## 高级数据结构

数据结构是算法的载体，而工程中的数据结构选择，本质上是在回答一个问题：你的负载长什么样？读多写少还是写多读少？数据放内存还是磁盘？要精确还是要快？四个答案排列组合，对应四类结构。没有最优，只有最匹配。

<Term def="在有序链表之上叠加多层索引，用随机化决定节点层数，以概率保证高度为 O(log n) 的平衡结构。">跳表</Term>是对平衡树的概率替代。平衡树靠旋转维持平衡，实现复杂、并发时锁粒度大；跳表让每个节点以固定概率「晋升」到上层索引，期望高度 O(log n)，查找从顶层一路向右向下，每层期望跳过一半。它用随机性换来了实现简单与并发友好——Redis 的有序集合正是看中这一点。代价是常数因子略大、内存多存几层指针，但在并发场景下其无锁实现远比红黑树现实。

## 核心概念

当数据大到放不进内存，磁盘 I/O 成为主要矛盾，结构必须为「块」服务。<Term def="把数据组织成页内有序、页间链表相连的多路平衡树，让一次磁盘 I/O 读回一大块有用数据，专为磁盘与范围查询优化。">B+ 树</Term>就是为此而生。它矮胖多路，一个节点装一个磁盘页，整页一次读入；所有数据只在叶子，叶子用链表串起，范围查询变成顺序扫描。数据库索引几乎清一色 B+ 树，因为它把随机 I/O 压到树高（通常 3–4 层），把范围扫描变成顺序 I/O。代价是写放大——一次插入可能触发页分裂与多层更新。

写多读少的场景则走向另一个极端。<Term def="把所有写入先追加到内存表，再批量合并刷盘的多层结构，用顺序写换写吞吐，代价是读需合并多层。">LSM 树</Term>把写变成顺序追加——先写内存 MemTable，满了刷成磁盘上不可变的 SSTable，后台再分层合并。写吞吐极高，因为磁盘顺序写远快于随机写，这正是 LevelDB、RocksDB、Cassandra 的根基。代价是读放大：一次读要查 MemTable 加多层 SSTable，所以 LSM 几乎总配布隆过滤器先过滤掉不存在的 key。

<Term def="用多个哈希函数映射到位数组，查询若对应位全为 1 则「可能存在」，若有 0 则「一定不存在」的概率成员查询结构。">布隆过滤器</Term>用极小内存回答「一定不存在」或「可能存在」。它不存元素本身，只存哈希后置位的标记。全 1 也可能是由别的元素凑巧置上的，故存在假阳性；但有 0 就说明这个 key 从没被置过，绝无假阴性。这个「单向确定」特性，恰好用来挡住 LSM 多层查找与缓存穿透中的无效查询。

<Callout type="tip">
<strong>建议 →</strong> 选结构先画负载画像：内存或磁盘、读写比、精确或概率、点查或范围查。画像定下后，跳表对应并发有序、B+ 树对应磁盘范围、LSM 对应写吞吐、布隆过滤器对应存在性预筛，四者常组合使用而非互斥。
</Callout>

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 写密集系统用了 B+ 树，写吞吐上不去、延迟抖动严重。<strong>原因 →</strong> B+ 树为读与范围查询优化，写要随机定位页并可能触发页分裂，写放大高。<strong>修法 →</strong> 写多读少改用 LSM 树换顺序写吞吐，并配布隆过滤器抑制读放大；若仍需范围查询，靠 LSM 的有序 SSTable 顺序扫描补足。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 用布隆过滤器判断「存在」后直接当作确定结果，偶尔返回错误数据。<strong>原因 →</strong> 误把假阳性当确定，布隆过滤器只能确定「不存在」，全 1 仍可能误判。<strong>修法 →</strong> 把布隆过滤器定位为「不存在的快速否定」前置筛网，命中「可能存在」后必须回真表核实，绝不能当唯一判据。
</Callout>

## 小结与练习

- 跳表用概率平衡替代旋转，期望高度 O(log n)，实现简单、并发友好，代价是常数与指针开销略大
- B+ 树矮胖多路、叶链相连，把随机 I/O 压到树高、范围查询变顺序扫描，是磁盘索引首选，代价是写放大
- LSM 树以顺序追加换写吞吐，读需合并多层故常配布隆过滤器；布隆过滤器单向确定「不存在」
- 取舍依据负载画像：内存/磁盘、读写比、精确/概率、点查/范围查，四结构常组合而非互斥

  <GlossaryItem term="跳表">在有序链表上叠加多层索引、用随机化决定节点层数的平衡结构，期望高度 O(log n)，实现简单、并发友好，代价是常数与指针开销略大。</GlossaryItem>
  <GlossaryItem term="B+ 树">页内有序、页间链表相连的多路平衡树，数据只在叶子层。把随机 I/O 压到树高、范围查询变顺序扫描，是数据库索引首选，代价是写放大。</GlossaryItem>
  <GlossaryItem term="布隆过滤器">用多个哈希映射到位数组、单向确定「不存在」的概率成员查询结构，无假阴性、有假阳性，常用于预筛无效查询。</GlossaryItem>
  <GlossaryItem term="LSM 树">把写入先追加到内存表再批量刷盘合并的多层结构，用顺序写换写吞吐，代价是读需合并多层，常配布隆过滤器抑制读放大。</GlossaryItem>
