## 从“可逆重排能否让普通编码器变聪明”开始

block-sorting compression（<Term def="把输入分块后按循环移位或后缀的全局次序重排，再用局部变换和统计编码压缩每块。">块排序压缩</Term>）先做一件反直觉的事：它不立即删除 redundancy，而是重排字符，让相似 context 的前驱聚到一起。后续简单的 Move-To-Front、Run-Length Encoding 与 entropy coder 才能吃到这些 runs 和偏斜分布。

先预测 `abracadabra` 的字符若只排序成 `aaaaabbcdrr` 是否够用。它压缩友好，却丢失所有次序，许多不同字符串会产生相同结果。目标必须同时满足两点：输出 locally homogeneous，又能无歧义恢复原串。

Burrows-Wheeler transform（<Term def="排序带唯一 sentinel 的所有循环移位，输出排序矩阵最后一列与 sentinel 行位置信息的可逆置换。">Burrows-Wheeler变换</Term>，BWT）正好完成这个桥接。它是 permutation，不改变字符数；真正的 compressed bits 由后面的 MTF、RLE 与 statistical coding 产生。

## Forward BWT：排序所有 cyclic rotations

给输入 s 追加唯一 sentinel `$`，规定它小于其他字符。概念算法：

1. 构造 s$ 的全部 n+1 个 cyclic left rotations。
2. 按从左到右的字典序排序这些 rows，得到矩阵 M'。
3. 读取最后一列 L，并保存 `$` 的位置 r；也可把 `$` 从 L 去掉，返回 L-hat 与 r。

<PaeBwtForwardTransformLab />

对 `abracadabra$`，最后一列是 `ard$rcaaaabb`，删除 sentinel 得 `ardrcaaaabb`，r=3。结尾的 `aaaabb` 体现 local homogeneity：排序后，拥有相似右侧 context 的 rows 相邻，它们在 L 中对应的 preceding symbols 也被放在一个连续区域。

不同于字典 compressor 直接用 old substring reference，BWT 利用全局 context order。自然语言与很多 Markovian data 的下一个/前一个符号受邻近 context 影响，因此这些连续区域往往只有少数 distinct symbols。

```text
ForwardBWT(s):
  t = s + sentinel
  rows = all cyclic rotations of t
  sort rows lexicographically
  L = last character of every sorted row
  return (L without sentinel, position of sentinel in L)
```

这个 pseudo-code 只用于定义。显式矩阵有 Θ(n²) 字符，16 MB block 会产生不可接受的概念空间。实现利用 sentinel 使“排序 rotations”等价于“排序 suffixes”：若 SA[i] 是第 i 小 suffix 的起点，则：

$$
L[i]
=
\begin{cases}
s[SA[i]-1], & SA[i]\ne 0\\
\$, & SA[i]=0
\end{cases}
$$

所以已有 Suffix Array 后只需线性扫描生成 L；总时间/IO 由 SA construction 决定，而不是构造旋转矩阵。

<Callout type="trap" title="在产品代码里真的构造 rotation matrix">
矩阵只是证明和教学工具。存 n 个长度 n 的 rows 会把空间与字符搬运放大到平方级；实现应构造 suffix array、suffix sorting order 或专用 BWT algorithm，再按 SA 前驱取 L。
</Callout>

## Backward BWT：first-last property 与 LF mapping

M' 的第一列 F 是 L 的 sorted permutation。只知道 F 不能还原次序；可逆性来自两个性质：

1. 同一 row 中，L[i] 是 F[i] 在原循环串中的 preceding symbol。
2. 相同字符在 L 与 F 中的 occurrences 保持相同相对次序。

LF mapping（<Term def="把 L 中某字符的第 k 次出现映射到 F 中同字符第 k 次出现的行号。">LF映射</Term>）定义为：若 L[i] 的第 k 个 occurrence 对应 F[j] 的第 k 个 occurrence，则 LF[i]=j。

设 C[c] 是小于 c 的字符总数，Rank(c,i) 计数 L[0,i) 中 c 的 occurrences，则：

$$
LF(i)
=
C[L[i]]+\operatorname{Rank}(L[i],i)
$$

<PaeLfMappingLab />

从 sentinel 对应 row 起，当前 L 字符是原串中当前位置的 predecessor；跳到 LF(row) 后再次读取 L，就向原串左移一个字符。重复 n 次可逆序填满 s，时间 O(n)。显式 LF array 占 O(n) words，也可用压缩 Rank structure 在线计算。

```text
BuildLF(L):
  C = cumulative counts: C[c] = count of symbols smaller than c
  seen = all zeros
  for i = 0 .. length(L)-1:
    LF[i] = C[L[i]] + seen[L[i]]
    seen[L[i]] = seen[L[i]] + 1

InvertBWT(L, sentinelRow):
  row = sentinelRow
  for output position from end to start:
    output[position] = L[row]
    row = LF[row]
```

实际格式可能返回去掉 `$` 的 L-hat 与 r，也可能保留 sentinel。inverse 的起始 row 和第一次输出字符随约定变化；算法正确性测试必须固定一种 convention，不应只凭例子调 off-by-one。

## MTF：把局部同质字符统一成小整数

Move-To-Front（<Term def="用动态 alphabet list 中的当前位置替换字符，并把该字符移到表首的可逆变换。">Move-To-Front</Term>，MTF）初始化为 alphabet 的固定顺序。处理字符 c 时，输出它当前 index p，再把 c 移到 front。inverse 用同一 initial list：取 index p 处字符输出，再移到 front，双方始终同步。

<PaeMoveToFrontLab />

若 L 中同字符连续出现，第一个可能输出较大 index，之后都输出0；若一个小集合频繁交替，输出通常也只在0、1、2附近。不同局部区域即使使用不同字符，也统一变成 small-integer alphabet。原章例 `bananacocco` 从列表 `a,b,c,n,o` 得到 `11311134101`。

MTF 自己通常不缩短序列。它利用 locality of reference 改变 distribution，随后可用 Elias integer code、RLE 或统计 coder。它不与 Huffman“静态前缀码最优”矛盾：同一 symbol 在不同时间可能对应不同 index/codeword，MTF pipeline 不属于静态逐符号 prefix-code 类别。

## RLE0：只压 MTF 产生的零游程

普通 RLE 把 maximal run c^ℓ 变成 ⟨ℓ,c⟩。run 长时收益大，run 短时 pair 反而膨胀。BWT+MTF 的结构明确告诉我们最值得压的是0-runs，因此 bzip 采用 restricted RLE0，而不是为所有 symbol 都付 run header。

非零 MTF indices 先加1，腾出0和1两个 alphabet symbols 专门表示 run code。Wheeler code 对长度 ℓ：

$$
\operatorname{RLE0}(\ell)
=
\operatorname{binary}(\ell+1)
\text{ 删除最高的 }1
$$

<PaeWheelerRleZeroLab />

例如五个0：ℓ+1=6，binary 为110，删除 leading 1 后写10。decoder 读 maximal 0/1 sequence，补回 leading 1、转整数再减1。输出 digit 数不超过原0-run长度；长 run 越省。

## bzip Compressor：每一层为下一层制造分布

bzip compressor（<Term def="按块串联 BWT、MTF、RLE0 与统计编码，并保存 inverse 所需元数据的压缩器。">bzip压缩器</Term>）的主链是：

<PaeBzipPipelineDiagram />

1. BWT 把相似 context 的 preceding symbols 聚成局部同质 L。
2. MTF 把重复/近邻字符变成0和 small integers。
3. RLE0 把0-runs 变成短 0/1 code。
4. Huffman-like statistical stage 对最终 alphabet 编码。

preamble 还要保存 block original size、CRC、sentinel/primary index、使用过的 alphabet 与统计表。单看 transforms 的 symbol count 不能代表文件大小。

bzip 按 block 工作，因为 forward BWT 与 inverse LF 的内存访问较分散，整文件全局排序昂贵。大 block 有更长 context 和更强 homogeneity，通常 compression ratio 更好；但 SA/BWT construction memory、compression latency 与 inverse cache misses 都增加。与 LZ window 不同，扩大 BWT block 也会明显拖慢 decompression。

<Callout type="trap" title="把 BWT 输出变短当成压缩成功">
BWT 只重排 n 个字符，长度仍是 n；MTF 也输出 n 个整数。必须把 RLE0、entropy coder 与所有 metadata 计入，才能讨论 bzip 压缩率。单独比较 L 的 runs 只是诊断信号。
</Callout>

## Compression Boosting：用多个0阶块模拟k阶模型

compression boosting（<Term def="借 BWT 将相同 k-context 的前驱形成连续 L blocks，再分别用0阶 coder 压缩，从而达到高阶经验熵界。">压缩提升</Term>）解释了 BWT 不只是“看起来 runs 多”。在 sorted rows 中，以同一 context w 开头的 rows 连续；其 L 区段 Lw 恰好收集原串中 w 的 preceding symbols。

<PaeCompressionBoostingDiagram />

若0阶 compressor C0 对任意 t 使用至多 |t|H0(t)+overhead(t) bits，把 L 按所有 k-context 分成 Lw 并逐块压缩，则主项：

$$
\sum_{w\in\Sigma^k}|L_w|H_0(L_w)
=
|s|H_k(s)
$$

因为 Lw 与原串中跟随/前驱同一 context 的 symbol multiset 对应。块 header 与 C0 redundancy 形成 additive term；Arithmetic 的 per-block overhead 很小，Huffman 每块最多不足1 bit/symbol 的简单界则更粗。

更强的 booster 不必事先固定 k。可在 LCP/ suffix-tree induced intervals 上动态规划选择 partition，使“各块 compressed cost + boundary cost”最小，并达到不差于任意固定 k partition 的结果。这里的提升不是训练一个 k阶概率表，而是用 BWT 的全局排列把高阶依赖物理地分组。

## Compressed Indexing：BWT 既能压，也能搜索

compressed indexing（<Term def="在接近压缩后文本空间内支持 Count、Locate 与 Extract，而无需先完整解压。">压缩索引</Term>）沿用 BWT、C 与 Rank。FM-index 可理解为 compressed suffix array，也可理解为 searchable bzip representation。

核心操作：

- Count(P) 返回以 P 为 prefix 的 sorted rows 区间 [first,last]，区间长度是 occurrence count。
- Locate(P) 把这些 rows 映射回原文 positions。
- Extract(i,j) 通过采样与 LF steps 恢复指定 substring。

backward search 从 P 的最后字符开始。若当前 [first,last] 是以 suffix P[i..] 开头的 rows，向左加字符 c=P[i-1]：

$$
\begin{aligned}
first' &= C[c]+\operatorname{Rank}(c,first),\\
last'  &= C[c]+\operatorname{Rank}(c,last+1)-1.
\end{aligned}
$$

<PaeFmBackwardSearchLab />

对 `abracadabra$` 的 pattern `ab`，先由 F 中 b 的范围得 [6,7]；再用 L 的 a-ranks 扩为 [2,3]，因此出现2次。每轮只做常数次 Rank，若 Rank O(1)，Count 时间 O(|P|)。

```text
BackwardSearch(P):
  first = 0
  last = n - 1
  for c in reverse(P):
    first = C[c] + Rank(c, first)
    last  = C[c] + Rank(c, last + 1) - 1
    if first > last:
      return empty
  return [first, last]
```

Locate 需要 SA position。FM-index 每隔 μ 个 text positions 采样 row→position；对未采样 row 反复 LF，至多 μ 步遇到 sample，再把步数加回。采样空间约 n log n / μ bits，定位每个 occurrence 最坏 O(μ) Rank calls。μ 小更快更大，μ 大更省更慢。

Extract 同理采样 text/SA 对应点，再沿 LF 向左生成字符。Rank structure 可用 wavelet tree、bitvectors 与 succinct dictionaries 在接近 nHk(s) 空间支持访问和计数；这让 index 接近 bzip 的空间，却保留全文搜索。

Rank 的定义有两种常见 convention：inclusive L[0..i] 或 half-open L[0..i)。公式必须成套使用。上文统一 half-open；测试应覆盖 first=0、last=n-1、字符不存在、单字符 pattern、sentinel 与重复字符，否则 off-by-one 会静默漏掉首尾 occurrence。

## 本章回顾

1. 块排序压缩先重排 context，再交给简单局部变换与统计编码。
2. Burrows-Wheeler变换排序带 sentinel 的 cyclic rotations，输出 L 与 primary index。
3. BWT 不缩短输入；它把相似右 context 的 preceding symbols 聚到 L 的连续区域。
4. 实现不构造平方矩阵，而由 Suffix Array 的前驱字符在线性时间导出 L。
5. LF 映射连接 L/F 中同字符同 occurrence，迭代 LF 可逆序恢复原串。
6. MTF 把 locality of reference 变成0和 small integer；RLE0 专门压零游程。
7. bzip 依次执行 BWT、MTF、RLE0、统计编码，并按 block 平衡空间与速度。
8. compression boosting 把 L 按 context 分块，用多个 H0 coder 达到 Hk 主项。
9. FM-index 的 backward search 用 C 与 Rank 在压缩 L 上维护 suffix-row interval。
10. Locate 与 Extract 通过 LF sampling 以辅助空间换查询步数。

<Exercises>

**问题 1：为什么第一列 F 很容易压缩，却不能代替 BWT 的 L？**

<Answer>F 只是输入字符 multiset 的全排序，所有具有相同字符计数的字符串都得到同一个 F，原次序已丢失。L 仍包含每个 sorted context 的 predecessor，并通过同字符 occurrence order 与 LF mapping 保留可逆关系。</Answer>

**问题 2：对 L=`ard$rcaaaabb`，L[6] 的 a 应映射到 F 哪一项？**

<Answer>L[0..6) 中已有一个a，所以 L[6] 是第二个a（以1计数）。F=`$aaaaabbcdrr` 中 a 从位置1开始，第二个a在位置2；half-open Rank(a,6)=1，LF(6)=C[a]+1=1+1=2。</Answer>

**问题 3：长度5的0-run 在 Wheeler RLE0 中写什么，如何还原？**

<Answer>先算5+1=6，binary是110，删掉 leading 1 得10。decoder 在10前补1得110=6，再减1恢复5；0和1已被保留给 run code，非零MTF index先加1避免歧义。</Answer>

**问题 4：FM-index 的 μ 从32增到256，会怎样影响 Locate？**

<Answer>采样行约减少8倍，辅助空间下降；但未采样 row 到最近 sample 的 LF/Rank 步数最坏从32增到256，每个 occurrence 的定位延迟约增8倍。Count 不依赖该 SA sampling，基本不变。</Answer>

</Exercises>
