本页不变量是：每增加一个模式都对应独立失败假设、指标收益和可撤销边界。任何“成功”结论都要保存以下证据：架构版本、逐层消融指标、阶段轨迹、错误归属、成本增量与回退结果，模型生成的计划或自信不能替代环境事实。

## 关键机制与可推翻实验

### 模式是积木不是处方

文章列出的模式不是成熟度阶梯，也不要求全部使用。

动手验证：从单次调用开始，只针对首个失败簇选一个构件。

### 一次只增加一个主要变量

同时加入路由、并行和评价会让收益不可归因。

动手验证：按版本逐层评测并保存差异。

### 组合边界需要显式合同

路由输出、链式中间物和工作者结果都应可独立校验。

动手验证：让某一层输出缺字段，确认错误在边界处停止。

### 回退比升级更重要

新模式在真实分布下退化时，系统要能恢复已知可用基线。

动手验证：关闭新增层，用相同输入验证回退结果与历史基线一致。

## 最小可运行实现

```ts
let system = singleCallBaseline;
for (const candidate of proposedLayers) {
  const next = compose(system, candidate);
  const delta = await evaluateDelta(system, next, frozenSuite);
  if (delta.quality > 0 && delta.cost <= budget) system = next;
  else recordRejectedLayer(candidate, delta);
}
return system;
```

这段切片只暴露“按可测需求组合检索、路由、链式、并行、评价和自治环节，并保留透明回退路径”的最小运行合同。交付版本还要补齐超时、密钥隔离、结构化日志、幂等和批量评测；缺少架构版本、逐层消融指标、阶段轨迹、错误归属、成本增量与回退结果时，代码能运行也不代表本章结论成立。

<Callout type="trap" title="不要把模型自评当作验收">

</Callout>

<Callout type="trap" title="版本变化必须重跑">

</Callout>

## 小结

- 模式是积木不是处方，按可测需求组合而非堆砌
- 一次只增加一个主要变量，用消融实验判断真实贡献
- 组合边界需要显式合同，每层输出可独立校验
- 回退比升级更重要，新层退化须能恢复已知基线
- 沿架构版本、消融指标、错误归属等证据定位首个分叉

**问题 1：最小证明。** 怎样用最少样本证明“每增加一个模式都对应独立失败假设、指标收益和可撤销边界”？

<Answer>
  冻结模型、指令、工具、权限和预算，写出正常、边界与单故障三类预期，再保存架构版本、逐层消融指标、阶段轨迹、错误归属、成本增量与回退结果。只要首个分叉未解释或失败样本产生副作用，就不能判定通过。
</Answer>

**问题 2：课程覆盖。** 组合与定制模式：把简单积木拼成合适系统、先打个比方、这些模式是积木，不是处方、加复杂度之前，先让指标说话、透明组合比复杂框架更可靠、组合可以大胆，回退必须保守、动手看：从简单工作流爬到组合系统、代码对照：mega-agent vs 透明组合 workflow如何进入可操作验证？

<Answer>
  把八个坐标分别标到架构决策图、状态轨迹和故障证据链中。每个坐标至少拥有一个可观察状态、一个明确判断或一个失败样本；只在目录中出现不算覆盖。
</Answer>

**问题 3：恢复闭环。** 怎样证明“把所有模式堆进 mega-agent，无法定位质量提升来自哪一层，也无法单独回退”已经修复？

<Answer>
  保存正常基线，注入故障并在架构版本、逐层消融指标、阶段轨迹、错误归属、成本增量与回退结果中标出首个差异；撤销后复位全部控件，以完全相同的输入、版本、预算和权限重放。环境结果与停止状态都回到基线才算修复。
</Answer>
