## 为什么只记结论不足以掌握工作流 vs 智能体：何时用哪个

学习“工作流 vs 智能体：何时用哪个”时，第一步不是记住结论，而是冻结输入、上下文、版本和成功标准。只有这些条件明确，工作流 vs 智能体：何时用哪个的含义才不会随着样例变化。正文已有的概念说明要与结构图、运行轨迹和失败样本互相印证，不能只凭最终输出看似正确就宣布完成。

结构分析从先打个比方开始：列出参与者、职责、连接方向、生命周期和所有权，再沿正常路径追踪数据或控制流。每一条边都要说明为什么存在、谁创建、谁消费、谁负责清理；如果边界被跨越，必须能在证据中找到第一处异常。

机制验证要把再辨析一次：差别不在步数，在「路是谁定的」写成可以执行的条件。正常样本证明主路径，恰好边界样本验证等号和空值，单故障样本只破坏一个假设。三类样本使用同一份观察指标，避免因为测试口径变化而把偶然结果误认成规律。

成本分析同时记录时间、空间、延迟、耦合、可维护性和不可逆操作。一个核心原则：先用最简单的，只在需要时加自主性不是一句“可能失败”，而是可复现输入、预期停点、实际轨迹、错误分类与清理步骤。任何自动重试都要有次数、预算和幂等边界。

方案比较不能只列优点。需要给出直接实现、当前方案和至少一个替代方案，逐项比较复杂度、扩展点、故障隔离和团队认知成本。当问题规模很小或变化轴稳定时，更简单的实现往往更好；模式与框架必须由真实变化压力证明。

实现阶段把大结论拆成可检查的中间产物：配置快照、结构清单、状态转移、输入输出样本、日志摘要和测试结果。每个产物带来源与生成命令，下一阶段只消费已通过门禁的版本，避免旧缓存或隐式默认值污染结论。

解释结果时必须区分相关性与因果性、接口承诺与实现细节、设计意图与运行事实。对“同一件事，多种自主性档位：智能体模式光谱”的判断要由独立证据支持，并明确适用范围；一旦输入分布、版本、硬件或组织边界改变，就重新运行最小实验。

复盘从首个分叉开始，而不是从最后一个报错倒推。先比较冻结输入，再比较第一份结构化中间产物，随后检查状态、约束和副作用。这样可以把复杂系统的排错范围收缩到一个阶段，避免在多个层次同时修改造成新的不确定性。

## 先打个比方

公司里办事，有两种路子。一种是**照流程走**：报销怎么填、走哪几个审批、谁盖章，写在制度里，每次都一样。这种事最省心——照着做就行，不会出岔子，也不用动脑子。

另一种是**请个人来办**：「帮我把这趟出差安排妥当。」具体怎么订、遇到没票了怎么改、临时改行程怎么应对，你说不全，只能交给一个能自己拿主意的人，让他见机行事。

关键在于：**流程固定的事照流程走最稳最省，情况多变、要随机应变的事才值得请个能自己拿主意的人。** 这一章就讲：做这类程序时，怎么判断一件事该「照流程走」还是该「请个人」——杀鸡别用牛刀，牛刀也别拿来杀鸡。选错了，要么白白浪费，要么根本办不成事。

## 一个核心原则：先用最简单的，只在需要时加自主性

知道了区别，下一个问题是「那我到底该用哪个」。这里有一条贯穿整个智能体工程的原则，也是本章的灵魂：**先用最简单的方案，只在确实需要时才加自主性。**

这里的 不是越多越好。给程序加自主性，等于把「决定下一步」的权力交给 LLM——这换来了灵活，但也同时换来了成本、延迟和不可预测性（下一节细看这笔账）。所以正确的姿势不是「先想怎么把它做成最酷的 agent」，而是**反过来**：先问「能不能用最笨最简单的办法（纯代码、写死的工作流）解决」，只有当简单办法确实顶不住时，才一点点往上加自主性。能省则省，这是工程上的稳妥，不是偷懒。

## 同一件事，多种自主性档位：智能体模式光谱

「加自主性」也不是从工作流一步跳到全自主 agent，中间还有一整排档位。把它们按自主性从低到高排开，就是一道 光谱，也正好是第四篇接下来要逐章展开的路线图：


从左到右：单次调用 → 链式 → 路由 → 并行 → 编排-工作者 → 评估-优化 → 自主 agent，越往右 LLM 自己拿主意越多。要点有两个：一是**多数实用系统落在中间这些工作流模式上**，自主 agent 只是最右端、最灵活也最贵的那一档，并非默认选项；二是中段那些模式（如-工作者）虽然用到 LLM，但整体控制流是人预先编排好的，路径不是 LLM 临场决定的——所以它们仍算工作流。链式 / 路由在 Ch12、并行 / 编排-工作者在 Ch13、评估-优化在 Ch14 展开，本章先把全景给你。

逐处对照两边的差异：左边是 `search → 取第一个 → pay` 三个函数**顺序直调**，路径写死，没有循环，也没有「LLM 决定下一步」——所以查到的车次没票时它无路可走，直接崩。右边核心是一个 `while` 循环，每一圈 `llm(ctx)` 让模型看当前情况、**自己决定**调哪个工具或收尾——没票它能自己改查别的车次。这份灵活不是白来的：右边每转一圈都要一次 LLM 调用，**更慢、更贵，而且同样输入下一步走哪不再固定**。这就是自主性的账：左边便宜可控但死板，右边灵活但贵且不定。

## 小结

- 工作流 vs 智能体的本质区别：路是人写死的，还是 LLM 边跑边自己选的——不看步数
- 核心原则：先用最简单的方案，只在确实需要时才加自主性，能简单别复杂
- 决策框架：先问「任务可预测、步数固定吗」——是 → 工作流（甚至纯代码）；否 → 才上 agent
- 自主性是把双刃剑：自主性↑ → 灵活↑，但成本 / 延迟 / 不可预测性也一起↑
- 第四篇是一道光谱：链式 / 路由 / 并行 / 编排-工作者 / 评估-优化，自主 agent 只是最右一档
