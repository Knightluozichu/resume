## 关键机制与可推翻实验

### 更长不等于更可靠

上下文增加会带来边际收益递减和注意分散，应优先提高信号密度。

动手验证：固定模型和任务，逐档增加无关材料，测量关键事实召回。

### 按需加载优于一次塞满

文件路径、查询和资源标识可作为轻量索引，真正内容在需要时获取。

动手验证：比较预加载全库与逐步检索的 token、延迟和答案证据。

### 压缩先追求召回

初版摘要应保留全部关键决定，再逐步去除冗余，不能一开始激进删减。

动手验证：对压缩前后的事实清单做确定性断言。

### 工具结果可以清理但要留结论

深层历史中的大段原始输出可移出窗口，同时保留来源、摘要和复取方式。

动手验证：清掉旧结果后让智能体重放，确认能按引用重新取得证据。

## 最小可运行实现

```ts
function compact(trace: Event[], budget: number) {
  const mustKeep = trace.filter(isGoalDecisionOrOpenIssue);
  const recent = trace.slice(-6);
  const summary = summarizeWithCitations(trace.slice(0, -6));
  const next = dedupe([...mustKeep, summary, ...recent]);
  assertFactsPreserved(trace, next);
  return fitTokenBudget(next, budget);
}
```

这段切片只暴露“把上下文视为有限注意预算，用按需检索、压缩和结构化笔记保留高信号信息”的最小运行合同。交付版本还要补齐超时、密钥隔离、结构化日志、幂等和批量评测；缺少token 预算、消息分类、保留清单、压缩前后事实断言、引用与任务结果时，代码能运行也不代表本章结论成立。

## 小结

- 把上下文视为有限注意预算，提高信号密度优先于堆量
- 按需检索优于一次塞满，用轻量索引按需加载
- 压缩先追求召回，保留目标、决定和未解决问题
- 禁止按最旧消息直接截断，避免删除未解决约束
- 沿 token 预算、保留清单、压缩前后事实断言定位分叉
