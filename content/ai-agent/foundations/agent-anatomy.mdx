## 为什么只记结论不足以掌握智能体解剖图

学习“智能体解剖图”时，第一步不是记住结论，而是冻结输入、上下文、版本和成功标准。只有这些条件明确，智能体解剖图的含义才不会随着样例变化。正文已有的概念说明要与结构图、运行轨迹和失败样本互相印证，不能只凭最终输出看似正确就宣布完成。

结构分析从给失忆天才配齐一套装备开始：列出参与者、职责、连接方向、生命周期和所有权，再沿正常路径追踪数据或控制流。每一条边都要说明为什么存在、谁创建、谁消费、谁负责清理；如果边界被跨越，必须能在证据中找到第一处异常。

机制验证要把一个智能体，拆开看是五大件写成可以执行的条件。正常样本证明主路径，恰好边界样本验证等号和空值，单故障样本只破坏一个假设。三类样本使用同一份观察指标，避免因为测试口径变化而把偶然结果误认成规律。

成本分析同时记录时间、空间、延迟、耦合、可维护性和不可逆操作。一个任务，怎样在五大件之间流转不是一句“可能失败”，而是可复现输入、预期停点、实际轨迹、错误分类与清理步骤。任何自动重试都要有次数、预算和幂等边界。

方案比较不能只列优点。需要给出直接实现、当前方案和至少一个替代方案，逐项比较复杂度、扩展点、故障隔离和团队认知成本。当问题规模很小或变化轴稳定时，更简单的实现往往更好；模式与框架必须由真实变化压力证明。

实现阶段把大结论拆成可检查的中间产物：配置快照、结构清单、状态转移、输入输出样本、日志摘要和测试结果。每个产物带来源与生成命令，下一阶段只消费已通过门禁的版本，避免旧缓存或隐式默认值污染结论。

解释结果时必须区分相关性与因果性、接口承诺与实现细节、设计意图与运行事实。对“动手：点一遍，拿到整本书的地图”的判断要由独立证据支持，并明确适用范围；一旦输入分布、版本、硬件或组织边界改变，就重新运行最小实验。

复盘从首个分叉开始，而不是从最后一个报错倒推。先比较冻结输入，再比较第一份结构化中间产物，随后检查状态、约束和副作用。这样可以把复杂系统的排错范围收缩到一个阶段，避免在多个层次同时修改造成新的不确定性。

迁移到真实项目时，先选择一个最小但有代表性的切片，保存改造前基线，再逐步引入“智能体解剖图”中的机制。每一步只改变一个变量并保留回滚点；性能、正确性、安全性和可理解性至少各有一项可量化指标。

最终验收要求读者能脱离页面重新画出结构、口述关键链路、实现最小版本、构造一个反例并解释失败位置。若只能复述名词而不能预测中间状态，说明知识仍停留在识记层，需要回到图示和实验重新验证。

## 可复现的最小实现

先把决策记录写成机器可读结构：

```json
{
  "unit": "智能体解剖图",
  "inputFrozen": true,
  "scenario": "normal | boundary | single-fault",
  "firstDivergence": null,
  "cleanupRequired": true
}
```

再用同一条执行链处理三类样本：

```ts
type Evidence = { stage: string; expected: string; actual: string };

function verify(sample: unknown, expected: readonly Evidence[]) {
  const trace = runFromCleanState(sample);
  return expected.find((item, index) => trace[index]?.actual !== item.expected);
}
```

最后保存回归门禁，禁止失败样本静默通过：

```text
normal      -> complete, invariant preserved
boundary    -> complete or explicit rejection
singleFault -> stop at first divergence, no stale output
```

用统一评分解释实验结果：

$$
Q = C_{correct} + C_{trace} + C_{recover} - R_{residual}
$$

$$
C_{coverage} = \frac{N_{verified}}{N_{official}}
$$

$$
R_{residual} = P(failure) \times I(impact)
$$

$$
Accept = (C_{coverage} \ge 0.90) \land (R_{residual} \le R_{budget})
$$

## 给失忆天才配齐一套装备

## 一个智能体，拆开看是五大件

先把整张「解剖图」摊在桌上。一个能干活的智能体，拆开看就是**五大件**：正中间一颗大脑，外加围着它的四样配件。我们一件件来对照那位失忆天才。

中心那颗大脑，就是前两章讲的大模型，这里叫它。它是失忆天才本人，负责决策、动脑，但也带着天生的三块短板（会幻觉、记不住、动不了手）。剩下四件，就是来给他补短板的。

第一件是：天才出不来、你进不去，唯一的沟通方式就是从门缝塞一张纸条进去。怎么把任务在纸条上说清楚、让他按你要的格式回话，就是这件配件管的事。

第二件是：失忆天才出不了屋，不能上网、算账、查实时数据。给屋子装一部「电话」，他就能在纸条上写「请帮我查一下票价」，由我们替他做完、把结果塞回去。

第三件是：天才转头就忘，还不懂你的私有资料。给他一个笔记本记下短期要点、再给一座可检索的资料库放长期知识，要用时取回塞回纸条，他就「记得住」、也能照资料说话。

第四件是：碰到要好几步的大任务，天才容易无从下手、还会犯错不自知。给他一张待办清单，把大任务拆成子任务、一步步推进，做完再回头自检。

## 一个任务，怎样在五大件之间流转

光知道有哪五件还不够，得看它们怎么**协作**。一个任务进了智能体，会在五大件之间流转一圈——这条「数据怎么一件件传过去」的路线，就叫。

走一遍这条路：任务进来 → **提示**把它组装成一张纸条 → **模型**读纸条、决策（比如「得先查票价」）→ 判断要不要调工具 →（要）**工具**出屋查到结果、塞回来 → **记忆**把关键信息存下/取回 → **规划**对照待办清单看「还有没有下一步」 → 没完就**回到模型**继续转下一轮、做完则**输出结果**。这个「没完就回头再转」的劲儿，正是上一章在五大件上的具体走法。

## 小结

- 一个智能体 = **五大件**：模型（大脑）+ 提示（纸条）+ 工具（电话）+ 记忆（笔记本+资料库）+ 规划（待办清单）
- 五件不是孤立零件，而是被一条**数据流**串成的整体：提示进 → 模型断 → 工具做 → 记忆记 → 规划盘，没完就回模型再转一轮，做完才输出
- 这个「没完就回头再转」的劲儿，就是上一章 **Agent Loop** 在五大件上的具体走法
- 全书地图：**提示 → 篇 2、工具 → 篇 3、记忆 → 篇 4、规划/反思 → 篇 5**（模型在篇 1）；篇 6 多智能体组队、篇 7 上生产
- 四件配件各补失忆天才一块短板：工具治「动不了手」、记忆治「记不住 + 会幻觉」、规划治「大任务抓瞎」、提示让你「把话说对」
