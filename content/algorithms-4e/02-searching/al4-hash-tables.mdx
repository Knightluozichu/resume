## 直觉引入

想象图书馆的书架。如果按编号顺序排（BST），找一本书要沿走道走 log n 步。但如果有个魔法函数把每本书的编号直接算出书架位置（散列函数），你一步到位就能找到（O(1)）。代价是两本书可能算出同一位置（冲突），且书架不能太满（负载因子）。

## 概念讲解

### 散列函数与冲突

<Al4HashTablesDiagram />

<Term def="散列表用散列函数将键映射到数组索引，期望 O(1) 查找，冲突用拉链法或开放地址法解决">
散列表
</Term>

散列函数 h(key) 将键映射到 [0, M) 的整数。理想：均匀分布、确定性、O(1) 计算。冲突不可避免（鸽巢原理），解决策略决定性能。

### 冲突解决

拉链法：每个桶存链表，冲突键挂同一链表。线性探测法：冲突时向后找下一个空位。缓存友好但删除复杂。

## 交互Demo

<Stepper>
<Step title="散列函数">hashCode() 计算哈希值，再 % M 映射到数组。好哈希函数均匀分布。</Step>
<Step title="拉链法">每个桶是链表。put/get 遍历链表。负载因子 n/M 控制链表长度。</Step>
<Step title="线性探测法">冲突时 h+1, h+2... 找空位。负载因子 < 0.5。删除需墓碑标记。</Step>
</Stepper>

## 代码对照

```java
// 1. 拉链法
public class SeparateChainingHashST<Key, Val> {
    private int M = 97;
    private SequentialSearchST<Key, Val>[] st;

    private int hash(Key key) {
        return (key.hashCode() & 0x7fffffff) % M;
    }

    public void put(Key key, Val val) {
        st[hash(key)].put(key, val);
    }
    public Val get(Key key) {
        return st[hash(key)].get(key);
    }
}

// 2. 线性探测法
public class LinearProbingHashST<Key, Val> {
    private int M = 30001;
    private Key[] keys;
    private Val[] vals;

    public void put(Key key, Val val) {
        int i;
        for (i = hash(key); keys[i] != null; i = (i+1) % M)
            if (keys[i].equals(key)) { vals[i] = val; return; }
        keys[i] = key; vals[i] = val;
    }

    public Val get(Key key) {
        for (int i = hash(key); keys[i] != null; i = (i+1) % M)
            if (keys[i].equals(key)) return vals[i];
        return null;
    }
}
```

## 常见误区

<Callout type="trap">
**误区：散列表查找一定是 O(1)。**
期望 O(1) 但最坏 O(n)（所有键哈希到同一桶）。实时系统需最坏保证时应用平衡树。
</Callout>

<Callout type="trap">
**误区：重写 equals 不重写 hashCode。**
Java 约定：equals 相等的对象 hashCode 必须相等。只重写 equals 不重写 hashCode 会导致散列表找不到值。
</Callout>

<Exercises>
**问题 1**：拉链法和线性探测法各有什么优劣？

<Answer>
拉链法：删除简单，负载因子可>1，有指针开销。线性探测：缓存友好，无指针，删除复杂，负载因子<0.5。
</Answer>

**问题 2**：什么时候用散列表而不是 BST？

<Answer>
不需有序操作且键可哈希用散列表（O(1)）。需有序遍历或最坏保证用 BST（O(log n)）。
</Answer>
</Exercises>
