## 直觉引入

想象你要在一本书里找algorithm。最笨的方法是从第一页逐个比对（暴力查找）。聪明的方法是先建目录索引（Trie），或利用已匹配信息跳过不可能的位置（KMP）。字符串算法就是让文本处理从O(n*m)降到O(n+m)甚至O(n)的艺术。

## 概念讲解

### 字符串查找

<Al4StringsDiagram />

<Term def="字符串查找是在文本中定位模式串，KMP利用已匹配前缀避免回溯达到O(n+m)">
字符串查找
</Term>

暴力查找：每个位置尝试匹配，失败回退一位。最坏O(n*m)。KMP：预处理模式串构建next数组，匹配失败时跳过不可能的位置，不回退文本指针。O(n+m)。Boyer-Moore：从右向左匹配，实际中最快。

### Trie树

Trie（前缀树）：每个节点代表一个字符，根到叶子的路径组成字符串。查找/插入O(L)（L为字符串长度，与集合大小无关）。适合前缀匹配、自动补全、拼写检查。

## 代码对照

```java
// KMP
class KMP {
    private int[][] dfa;
    public KMP(String pat) {
        int M = pat.length(), R = 256;
        dfa = new int[R][M];
        dfa[pat.charAt(0)][0] = 1;
        for (int X = 0, j = 1; j < M; j++) {
            for (int c = 0; c < R; c++) dfa[c][j] = dfa[c][X];
            dfa[pat.charAt(j)][j] = j + 1;
            X = dfa[pat.charAt(j)][X];
        }
    }
    public int search(String txt) {
        int i, j, N = txt.length(), M = dfa[0].length;
        for (i = 0, j = 0; i < N && j < M; i++)
            j = dfa[txt.charAt(i)][j];
        return j == M ? i - M : N;
    }
}

// Trie
class TrieST<Value> {
    private Node root = new Node();
    private static class Node {
        Object val; Node[] next = new Node[256];
    }
    public void put(String key, Value val) {
        root = put(root, key, val, 0);
    }
    private Node put(Node x, String key, Value val, int d) {
        if (x == null) x = new Node();
        if (d == key.length()) { x.val = val; return x; }
        x.next[key.charAt(d)] = put(x.next[key.charAt(d)], key, val, d+1);
        return x;
    }
}
```

## 常见误区

<Callout type="trap">
**误区：KMP一定比暴力查找快。**
KMP最坏O(n+m)优于暴力O(n*m)，但实际中暴力常更快——大部分匹配第一个字符就失败。
</Callout>

<Callout type="trap">
**误区：Trie空间不是问题。**
Trie每个字符一个节点，Unicode字符集大时空间爆炸。用HashMap替代数组或压缩Trie优化。
</Callout>

<Exercises>
**问题 1**：KMP的next数组（DFA）解决什么问题？

<Answer>
匹配失败时文本指针不回退。next[j]表示已匹配前缀=后缀的长度，跳到next[j]继续而非回退。
</Answer>

**问题 2**：Trie和散列表在字符串查找上各有什么优劣？

<Answer>
Trie：O(L)查找，支持前缀匹配，空间大。散列表：O(1)查找，空间紧凑，不支持前缀。
</Answer>
</Exercises>
