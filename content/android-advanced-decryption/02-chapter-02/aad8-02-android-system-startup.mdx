# 第2章 Android系统启动

本课程对应刘望舒《Android进阶解密》，电子工业出版社2018年10月初版，468页、702千字，ISBN 9787121348389。原书以Android 8.0系统源码为主；本页不会用Android 10后的ATMS、现代ART实现、Perfetto或新隐藏API政策替换原书链路。

## 从一条可证伪的调用链开始

先预测：把启动描述成线性函数列表会忽略init action/service触发、Zygote socket、SystemServer服务依赖与Launcher查询包信息的跨进程边界。把预测写成入口、对象身份、进程/线程、状态和完成回调五列，再去读源码。若结果与预测不同，先修正模型，不要选择性截取调用栈。

原书面向应用开发者学习系统源码，重点不是抄完整函数，而是抓住跨层调用的关键节点。每个节点都要回答：谁发起、在哪个进程和线程执行、哪份状态被修改、后续如何被唤醒、失败如何返回、什么现象代表真正完成。

验收不变量是：每个阶段都明确谁创建下一进程、使用何种配置或IPC、何时进入消息循环，以及何种日志证明阶段完成。只有源码版本、符号关系、运行轨迹与最终状态四类证据一致，结论才可以进入下一章。

## 可复现实验

```text
kernel -> init(PID 1) -> app_process -> Zygote -> system_server -> Launcher
```

```text
on boot -> class core -> service zygote -> socket zygote -> start
```

```bash
adb shell ps -A | grep -E 'zygote|system_server|launcher'
adb shell getprop sys.boot_completed
```

动手试：在同一镜像、同一构建和同一输入上重复正常、冷启动/首次加载、热路径、单变量失败与恢复五轮。记录PID/TID、调用入口、对象或token、状态前后值、耗时、异常/返回码和最终可见结果；性能章再记录P50/P95/P99，内存章保留GC Root路径。

<Callout type="trap" title="跨版本拼接调用链">
  类名相似不代表实现相同。Android
  8.0没有后来的ATMS体系，运行时、工具和隐藏API规则也不同；跨版本代码只能独立标注差异。
</Callout>

<Callout type="trap" title="把请求发出当成系统完成">
  Binder
  transact、fork返回、消息入队、补丁下载或View加入本地数组都只是中间状态。必须观察目标进程回调、系统状态、首帧或资源释放。
</Callout>
