## 四大核心心智模型

### 模型一：分层架构

```
// Android五层架构——从上到下依次调用
// System Apps（系统应用）
//   └── Launcher / Settings / Phone
// Java API Framework（应用框架）
//   └── ActivityManager / WindowManager / PackageManager
// Native Libraries & Android Runtime（原生库与运行时）
//   └── OpenGL ES / SQLite / ART虚拟机
// HAL（硬件抽象层）
//   └── Camera / Audio / Display HAL
// Linux Kernel（Linux内核）
//   └── Binder驱动 / 显示驱动 / 电源管理
```

<Callout type="info" title="核心认知">
Android是分层的系统：上层调用下层，下层为上层提供服务。理解分层才能定位问题属于哪一层——是应用层、框架层、运行时还是内核层。Binder IPC是跨进程通信的核心桥梁。
</Callout>

### 模型二：跨进程通信

```
// App进程 ←→ Binder ←→ system_server进程
// App进程1          App进程2          system_server
//   │                  │                  │
//   ├─ Binder ───────→ AMS（调度组件） ←──┤
//   ├─ Binder ───────→ PMS（包管理）   ←──┤
//   └─ Binder ───────→ WMS（窗口管理） ←──┤
//
// 四大组件运行在不同进程
// AMS/PMS/WMS在system_server中
// 所有跨进程通信都依赖Binder
```

### 模型三：消息驱动

```
// 主线程基于Looper/MessageQueue消息循环
// 所有UI操作、生命周期回调都在消息循环中执行
Looper.prepareMainLooper();
MessageQueue queue = Looper.myQueue();
// 循环处理消息
while (true) {
    Message msg = queue.next(); // 阻塞等待
    msg.target.dispatchMessage(msg); // 分发处理
}
// ANR = 主线程消息处理超时
```

### 模型四：组件化调度

```
// 四大组件由AMS统一调度
// Activity → AMS管理生命周期和栈
// Service → AMS管理启动和绑定
// BroadcastReceiver → AMS分发广播
// ContentProvider → AMS管理数据共享
// 组件间通过Intent通信
startActivity(new Intent(this, SecondActivity.class));
startService(new Intent(this, MyService.class));
sendBroadcast(new Intent("com.example.ACTION"));
```

按顺序学习每个章节，每章读完后做对应复习题。先从系统架构理解全局，再深入Binder理解进程间通信，然后研究AMS/PMS/WMS三大核心服务，接着ClassLoader和插件化理解底层加载机制，最后性能优化将前述知识综合应用。
</Callout>

<Glossary>

<GlossaryItem term="五层架构">
Android系统从上到下分为五层：系统应用层、应用框架层（Java API Framework）、原生库与运行时（Native C/C++ Libraries & ART）、硬件抽象层（HAL）、Linux内核层。每层有明确职责，上层调用下层。
</GlossaryItem>

<GlossaryItem term="Binder IPC">
Android跨进程通信的核心机制。通过mmap内存映射实现一次数据拷贝（传统IPC需两次），Binder驱动在内核层记录调用方UID/PID实现安全校验。Client通过Proxy发送请求，Server通过Stub处理请求，ServiceManager负责服务注册和查询。
</GlossaryItem>

<GlossaryItem term="AOT编译（Ahead-Of-Time）">
ART虚拟机的预编译策略，在应用安装时通过dex2oat将DEX字节码编译为机器码（OAT格式），运行时直接执行机器码，启动速度快。Android 7.0+采用AOT+JIT+Profile混合编译策略。
</GlossaryItem>

<GlossaryItem term="双亲委派（Parent Delegation）">
ClassLoader加载类时的委派机制：先检查是否已加载，再委托parent加载，parent失败才自己加载。保证核心类由BootClassLoader加载（安全性），同一类只加载一次（唯一性）。
</GlossaryItem>

<GlossaryItem term="OOM Adj">
Android进程优先级数值，决定进程在内存不足时被回收的顺序。前台进程adj≈0，可见进程≈100，服务进程≈500，缓存进程≈900。数值越大越容易被LowMemoryKiller杀掉。
</GlossaryItem>

</Glossary>

**问题 1**：全书的知识体系结构和递进逻辑是什么？

<Answer>
全书分为九个章节（含学习地图和全书复习），覆盖六大核心领域：①系统架构——五层分层架构（System Apps/Java API Framework/Native Libraries & ART/HAL/Linux Kernel）、系统启动流程（init→Zygote→system_server→Launcher）、Zygote的fork机制和COW优化；②虚拟机——Dalvik与ART对比（DEX/OAT格式、JIT/AOT编译、寄存器架构、GC机制）、dex2oat编译流程、VDEX/OAT/ART文件关系；③Binder IPC——Binder驱动mmap一次拷贝原理、ServiceManager服务注册查询、Proxy-Stub通信模型、AIDL自动生成代码机制；④核心服务——AMS（四大组件调度、Activity栈管理、进程优先级OOM Adj、内存回收）、PMS（APK包解析、权限管理、签名校验、安装流程）、WMS（Window类型层级、WindowState/Surface管理、绘制流程measure/layout/draw）；⑤底层技术——ClassLoader层级（BootClassLoader/PathClassLoader/DexClassLoader）、双亲委派机制、插件化原理（Hook AMS占坑、DexClassLoader加载插件）、热修复原理（操纵dexElements数组插入补丁dex）；⑥性能优化——启动优化（异步初始化、延迟加载、多阶段初始化）、内存优化（LeakCanary检测、内存泄漏场景、MAT分析）、渲染优化（过度绘制、布局层级、60fps）、ANR分析（traces.txt、StrictMode）、电量优化（WakeLock、JobScheduler）。递进逻辑：先从系统架构理解全局分层，再深入Binder理解进程间通信，然后研究AMS/PMS/WMS三大核心服务，接着ClassLoader理解类加载和插件化，最后性能优化综合应用前述知识。
</Answer>

**问题 2**：Android五层架构从上到下分别是什么？各层职责是什么？

<Answer>
五层从上到下：①System Apps（系统应用层）——Launcher、Settings、Phone等预装应用，开发者通过Intent调用系统应用；②Java API Framework（应用框架层）——Activity Manager、Window Manager、Package Manager、View System、Content Provider等API，是开发者直接使用的接口；③Native C/C++ Libraries & Android Runtime——OpenGL ES、SQLite、WebKit、Surface Flinger等原生库，以及Core Libraries和ART虚拟机（AOT+JIT编译）；④HAL（硬件抽象层）——Camera、Audio、Display、Sensor等硬件抽象接口，屏蔽厂商差异，允许闭源驱动在用户空间实现；⑤Linux Kernel（Linux内核层）——Binder驱动、Display驱动、WiFi驱动、Power Management、进程调度、内存管理。从上到下依次调用，下层为上层提供服务。用户空间（前三层+HAL）与内核空间（Linux Kernel）通过系统调用通信，Binder驱动是跨进程通信的核心桥梁。
</Answer>

**问题 3**：全书各章节之间存在哪些交叉关联？

<Answer>
交叉关联：①架构×Binder——五层架构中Framework层通过Binder驱动与Native/内核通信，理解架构才能理解Binder在系统中的定位；②Binder×AMS/PMS——AMS和PMS运行在system_server，App进程通过Binder与它们交互，Binder是组件调度的通信基础；③虚拟机×插件化——DexClassLoader加载插件dex依赖ART虚拟机的类加载机制，理解虚拟机才能理解插件化；④PMS×ClassLoader——PMS解析APK后通过PathClassLoader加载应用dex，包管理是类加载的前提；⑤AMS×WMS——Activity启动时AMS通过WMS添加窗口，两者协作完成Activity的显示；⑥AMS×性能——理解AMS的进程优先级和OOM Adj才能做内存优化，理解ANR机制（主线程5s无响应）才能做稳定性优化。一条主线：系统架构→通信机制（Binder）→核心服务（AMS/PMS/WMS）→底层技术（ClassLoader）→性能优化。
</Answer>

**问题 4**：Android进阶学习的核心心智模型是什么？

<Answer>
四大核心心智模型：①分层思维——Android从Linux内核到系统应用共五层，每层有明确职责，上层调用下层，理解分层才能定位问题层级；②跨进程思维——Android四大组件运行在不同进程，AMS/PMS/WMS在system_server，App在自己的进程，所有跨进程通信都依赖Binder IPC；③消息驱动思维——主线程基于Looper/MessageQueue消息循环，所有UI操作、生命周期回调都在消息循环中执行，主线程阻塞导致ANR；④组件化思维——Activity/Service/BroadcastReceiver/ContentProvider四大组件由AMS统一调度，组件间通过Intent通信。系统性认知建立路径：先从五层架构理解全局，再深入Binder理解进程间通信，然后研究AMS/PMS/WMS三大核心服务，接着ClassLoader和插件化理解底层加载机制，最后性能优化将前述知识综合应用。
</Answer>
