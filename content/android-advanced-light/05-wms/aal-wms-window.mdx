## WMS与窗口管理层级

<AalWmsWindowDiagram />

WMS（Window Manager Service）运行在system_server进程中，负责管理所有Window的添加、更新、移除，分配Surface，维护窗口层级和焦点。App通过WindowManager接口与WMS通信。

## 三种Window类型

| 类型 | 层级范围 | 特点 | 示例 |
|------|----------|------|------|
| Application Window | 1~99 | 与Activity一一对应 | PhoneWindow/DecorView |
| System Window | 1000~1999 | 需系统权限 | StatusBar/NavigationBar/Toast |
| Sub Window | 1000~1999 | 依附于父窗口 | PopupWindow/ContextMenu |

```
// Application Window — 最常见的窗口
// 每个Activity对应一个Window（PhoneWindow）
class Activity {
    Window mWindow; // PhoneWindow实例
    void attach() {
        mWindow = new PhoneWindow(this);
        mWindow.setContentView(R.layout.activity_main);
    }
}

// System Window — 需要权限
// Toast、状态栏、输入法窗口
WindowManager.LayoutParams params = new WindowManager.LayoutParams(
    LayoutParams.TYPE_APPLICATION_OVERLAY, // 系统窗口类型
    LayoutParams.FLAG_NOT_FOCUSABLE,
    PixelFormat.TRANSLUCENT
);
// 需要 SYSTEM_ALERT_WINDOW 权限
windowManager.addView(view, params);

// Sub Window — 依附于父窗口
// PopupWindow 坐标随父窗口变化
PopupWindow popup = new PopupWindow(view, width, height);
popup.showAsDropDown(anchorView); // 依附于anchorView
```

## Window、View、Surface关系

```
// 三者关系
Window（窗口容器）
  └─ DecorView（根View）
     └─ ContentView
        └─ 具体View（Button/TextView/...）

// 每个Window拥有一个Surface
Window → Surface（绘图表面/缓冲区）
         └─ 由SurfaceFlinger管理
         └─ View树通过Surface绘制内容

// ViewRootImpl = 桥梁 + 驱动器
ViewRootImpl
  ├─ 持有 WindowSession（与WMS通信的Binder）
  ├─ 持有 Surface（绘图表面）
  ├─ 驱动 performTraversals() → measure → layout → draw
  └─ 接收 InputManagerService 的输入事件
```

<Callout type="info" title="ViewRootImpl是核心桥梁">
ViewRootImpl是View树与WMS之间的桥梁。它每个Window只有一个实例，负责驱动View的measure/layout/draw三阶段绘制，管理Surface，并接收分发输入事件。performTraversals()是View绘制的总入口。
</Callout>

## View绘制流程

```
// ViewRootImpl.performTraversals() 是View绘制的总入口
// 分三个阶段，顺序固定：measure → layout → draw

performTraversals()
  ├─ performMeasure()  // 测量阶段
  │  └─ child.measure(widthSpec, heightSpec)
  │     └─ View.onMeasure() → setMeasuredDimension(w, h)
  │
  ├─ performLayout()   // 布局阶段
  │  └─ child.layout(l, t, r, b)
  │     └─ View.onLayout() → 确定子View位置
  │
  └─ performDraw()     // 绘制阶段
     └─ Surface.lockCanvas() → 获取Canvas
        └─ View.draw(canvas)
           ├─ drawBackground(canvas)  // 绘制背景
           ├─ onDraw(canvas)           // 绘制自身内容
           ├─ dispatchDraw(canvas)     // 绘制子View
           └─ onDrawForeground(canvas) // 绘制装饰（滚动条等）
        └─ Surface.unlockCanvasAndPost() // 提交给SurfaceFlinger
```

### measure（测量阶段）

```
// MeasureSpec：父View传递给子View的测量要求
// 三种模式：
// EXACTLY   — 精确值（match_parent 或具体dp）
// AT_MOST   — 最大值（wrap_content）
// UNSPECIFIED — 不限制（ScrollView内部使用）

// 父View根据自身MeasureSpec和子View的LayoutParams
// 计算子View的MeasureSpec
// 子View在onMeasure()中根据MeasureSpec确定最终宽高

// 子View → setMeasuredDimension(w, h) 保存测量结果
```

### layout（布局阶段）

```
// 确定每个View在父容器中的位置
// 父View在onLayout()中计算子View的left/top/right/bottom

// LinearLayout.onLayout() 示例：
void onLayout(boolean changed, int l, int t, int r, int b) {
    int childTop = 0;
    for (int i = 0; i < getChildCount(); i++) {
        View child = getChildAt(i);
        int childHeight = child.getMeasuredHeight();
        child.layout(0, childTop, child.getMeasuredWidth(), childTop + childHeight);
        childTop += childHeight;
    }
}
```

### draw（绘制阶段）

```
// 将View内容绘制到Surface上
// 软件绘制 vs 硬件加速

// 软件绘制（CPU）：
Canvas canvas = surface.lockCanvas();
view.draw(canvas);  // CPU逐像素绘制
surface.unlockCanvasAndPost();

// 硬件加速（GPU，默认开启）：
// 通过DisplayList批量提交GPU绘制命令
// 性能更好，支持复杂图形效果
```

## WMS核心职责

```
// WMS管理窗口的完整生命周期

// 1. 窗口添加
WindowManager.addView(view, params)
  └─ ViewRootImpl.setView()
     └─ WindowSession.addToDisplay() → WMS
        └─ WMS创建WindowState
        └─ 分配Surface

// 2. 窗口更新
ViewRootImpl.setLayoutParams()
  └─ WindowSession.relayout() → WMS
     └─ 更新WindowState（位置/大小）
     └─ 调整Surface大小

// 3. 窗口移除
WindowManager.removeView(view)
  └─ ViewRootImpl.die()
     └─ WindowSession.remove() → WMS
        └─ 销毁WindowState
        └─ 释放Surface

// 4. 焦点管理
// WMS维护当前焦点窗口
// InputManagerService将输入事件路由到焦点窗口
```

<Callout type="warning" title="AMS与WMS协作">
Activity启动时，AMS负责创建Activity实例和调用生命周期方法，然后通过WindowManager向WMS添加窗口。AMS负责「创建Activity」，WMS负责「显示窗口」，两者协作完成Activity从启动到显示的完整流程。
</Callout>

<Glossary>

<GlossaryItem term="WMS（Window Manager Service）">
Android窗口管理服务，运行在system_server。管理所有Window的添加、更新、移除，为每个Window分配Surface，维护窗口层级（z-order）和焦点窗口。App通过WindowManager接口与WMS通信。
</GlossaryItem>

<GlossaryItem term="WindowState">
WMS中每个窗口的抽象对象，记录窗口的位置、大小、动画、可见性等状态，持有Surface引用。WMS通过WindowState管理窗口的生命周期和层级排序。
</GlossaryItem>

<GlossaryItem term="Surface">
绘图表面，由SurfaceFlinger管理的图形缓冲区。每个Window拥有一个Surface。ViewRootImpl通过Surface.lockCanvas()获取Canvas，View树绘制到Canvas上，然后Surface.unlockCanvasAndPost()提交给SurfaceFlinger合成显示。
</GlossaryItem>

<GlossaryItem term="ViewRootImpl">
View树与WMS之间的桥梁。每个Window只有一个ViewRootImpl实例，负责驱动View的measure/layout/draw三阶段绘制，管理Surface生命周期，接收InputManagerService的输入事件并分发到View树。
</GlossaryItem>

<GlossaryItem term="MeasureSpec">
measure阶段父View传递给子View的测量要求。三种模式：EXACTLY（精确值，match_parent或具体dp）、AT_MOST（最大值，wrap_content）、UNSPECIFIED（不限制）。子View根据MeasureSpec在onMeasure()中确定最终宽高。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：Android中Window有哪几种类型？

<Answer>
Android Window分为三种类型：①Application Window（应用窗口）——层级1~99，对应Activity窗口（PhoneWindow/DecorView），与Activity一一对应，通过WindowManager添加，是最常见的窗口类型；②System Window（系统窗口）——层级1000~1999，包括StatusBar、NavigationBar、输入法窗口、Toast、系统对话框等，需要SYSTEM_ALERT_WINDOW等系统权限才能创建，z-order在应用窗口之上；③Sub Window（子窗口）——层级1000~1999，如PopupWindow、ContextMenu，必须依附于父窗口存在，坐标随父窗口变化，不能独立存在。窗口层级决定了z-order——层级数值越大显示在越上层。WMS通过WindowState管理每个窗口的层级，SurfaceFlinger按层级顺序合成窗口。
</Answer>

**问题 2**：Window、View、Surface三者关系是什么？ViewRootImpl扮演什么角色？

<Answer>
三者关系：①Window——窗口的抽象概念，每个Activity对应一个Window（PhoneWindow），是View树的容器；②View——UI组件，通过View树（DecorView → ContentView → 具体View）描述界面内容，Window持有DecorView作为根View；③Surface——绘图表面，是真正用于绘制的缓冲区，由SurfaceFlinger管理，每个Window拥有一个Surface。ViewRootImpl的角色：①桥梁——ViewRootImpl是View树与WMS之间的桥梁，持有WindowSession和Surface；②驱动绘制——performTraversals()是View绘制的入口，依次调用performMeasure()→performLayout()→performDraw()；③Surface管理——在draw阶段通过Surface.lockCanvas()获取Canvas，View树绘制到Canvas上，然后unlockCanvasAndPost()提交给SurfaceFlinger；④事件分发——接收InputManagerService的输入事件，分发到View树。
</Answer>

**问题 3**：WMS的核心职责是什么？

<Answer>
WMS核心职责：①窗口管理——管理所有Window的添加、更新、移除，每个Window对应一个WindowState对象，记录窗口的位置、大小、动画、可见性等状态；②Surface分配——为每个Window分配Surface，管理Surface的生命周期；③层级排序——维护窗口的z-order，按Window类型层级和添加顺序排序，确保正确的叠加显示；④焦点管理——维护当前焦点窗口（FocusedWindow），输入事件由InputManagerService路由到焦点窗口的ViewRootImpl；⑤窗口动画——管理窗口的进入/退出动画、旋转动画；⑥Token校验——通过WindowToken验证窗口创建权限，防止恶意应用伪造系统窗口。WMS运行在system_server，App通过WindowManager接口与WMS通信。
</Answer>

**问题 4**：View的完整绘制流程是怎样的？

<Answer>
View绘制流程由ViewRootImpl.performTraversals()触发，分三阶段：①measure（测量）——自顶向下递归测量每个View的宽高。父View根据自身的MeasureSpec和子View的LayoutParams计算子View的MeasureSpec，子View在onMeasure()中根据MeasureSpec确定最终宽高，调用setMeasuredDimension()保存结果。②layout（布局）——自顶向下递归确定每个View在父容器中的位置。父View在onLayout()中根据measure阶段测量的宽高和布局规则计算子View的left/top/right/bottom，调用child.layout()设置位置。③draw（绘制）——自顶向下递归绘制每个View的内容。ViewRootImpl通过Surface.lockCanvas()获取Canvas，View在onDraw()中将内容绘制到Canvas上（背景、内容、子View、装饰），最后Surface.unlockCanvasAndPost()提交给SurfaceFlinger合成。三阶段顺序固定：measure→layout→draw。
</Answer>
