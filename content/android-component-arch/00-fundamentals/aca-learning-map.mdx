## 知识体系全景

<AcaLearningMapDiagram />

《Android组件化架构》基于苍王的工程实践，系统讲解 Android 组件化开发的架构设计、路由导航、组件通信、依赖注入、生命周期管理和构建部署。全书分为六大核心主题，九个章节递进展开。

## 六大核心主题

### 主题一：架构设计

架构设计是组件化的地基，覆盖第 1-2 章：

```kotlin
// 组件化概述——为什么需要组件化
// 架构设计——五层分层、壳工程、公共库
// 壳工程只负责集成，不写业务逻辑
class App : Application() {
    override fun onCreate() {
        super.onCreate()
        // 初始化路由、DI、公共组件
        ARouter.init(this)
        DaggerAppComponent.create().inject(this)
    }
}
```

<Callout type="info" title="递进关系">
概述确立组件化动机 → 架构设计提供分层方案。没有清晰的分层，组件化就是空中楼阁。
</Callout>

### 主题二：路由与通信

路由与通信是组件化的经络，覆盖第 3-4 章：

```kotlin
// 路由——ARouter 编译期生成路由表，运行期查表跳转
@Route(path = "/order/detail")
class OrderDetailActivity : AppCompatActivity()

// 通信——接口下沉 + ARouter Provider
ARouter.getInstance().build("/order/detail")
    .withString("orderId", "123")
    .navigation()
```

<Callout type="warning" title="关键交叉点">
路由解决「页面跳转」，通信解决「数据交互」。两者共同消除组件间的直接依赖。
</Callout>

### 主题三：依赖注入与生命周期

依赖注入与生命周期是组件化的血液，覆盖第 5-6 章：

```kotlin
// DI——Dagger2 编译期生成注入代码
@Inject lateinit var repo: IOrderRepo

// 生命周期——Activity 计数判断前后台
// count == 0 → 后台，count > 0 → 前台
```

## 全书核心线索

```kotlin
// 一条主线贯穿全书：解耦——让组件可独立开发、编译、测试、部署

// 架构解耦——分层依赖，禁止反向
// app -> module-home -> common-biz -> common-core -> sdk

// 路由解耦——编译期注解，运行期跳转
@Route(path = "/user/profile")
class UserProfileActivity : AppCompatActivity()

// 通信解耦——接口定义在common，实现在组件
interface IUserService : IProvider {
    fun getUserName(): String
}

// DI解耦——依赖接口而非实现
@Inject lateinit var userService: IUserService
```

<Callout type="success" title="学习建议">
按顺序学习每个章节，每章读完后做对应复习题。重点是理解「为什么这样解耦」而非「怎么用框架」。组件化不是目的，可独立开发、可复用、可测试才是目的。
</Callout>

<Glossary>

<GlossaryItem term="组件化">
将单体 App 按业务边界拆分为多个独立模块（组件），每个组件可独立编译、测试、运行，最终通过壳工程集成为完整 App。
</GlossaryItem>

<GlossaryItem term="壳工程">
组件化架构中的顶层 Application 模块，不包含业务逻辑，只负责集成各业务组件、初始化全局框架（路由、DI等）。
</GlossaryItem>

<GlossaryItem term="路由表">
编译期通过 APT 注解处理器扫描 `@Route` 注解生成的映射表，记录 path 到 Activity/Provider 的对应关系，运行期用于路由跳转。
</GlossaryItem>

<GlossaryItem term="接口下沉">
将跨组件调用的接口定义放在 common 公共模块，各组件提供实现，调用方通过接口而非具体类来交互，实现解耦。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：全书的知识体系结构和递进逻辑是什么？

<Answer>
全书分为九个章节（含学习地图和全书复习），覆盖六大核心主题：架构设计（组件化概述、架构设计）、路由与通信（路由与导航、组件通信）、依赖注入与生命周期（依赖注入、生命周期管理）、构建与部署、实战案例。递进逻辑：从为什么要组件化到如何分层设计，再到路由通信解决解耦，然后是DI和生命周期管理运行期行为，最后是构建部署和实战落地，每个主题建立在前一个之上。
</Answer>

**问题 2**：单体架构的核心痛点是什么？组件化如何解决？

<Answer>
单体架构的核心痛点：编译慢（全量编译数分钟）、耦合高（模块互相直接依赖）、团队冲突（多人改同一模块）、无法独立测试和部署、复用困难。组件化通过五层分层架构（壳工程、业务组件、公共业务、基础架构、SDK）拆分模块，路由框架消除页面直接依赖，接口下沉消除数据直接依赖，多模块构建支持独立编译和调试，最终实现可独立开发、可复用、可测试。
</Answer>

**问题 3**：用一次完整的项目开发流程串联全书知识体系。

<Answer>
从架构设计开始：①壳工程作为空壳入口 ②拆分首页、登录、商品、订单等业务组件 ③common-core 提供网络/路由/DI基础设施 ④common-biz 提供支付/推送公共业务。路由阶段：用 ARouter 的 @Route 注解注册页面路径，编译期生成路由表。通信阶段：接口下沉到 common 层定义 IUserService，各组件实现后通过 ARouter Provider 发现。DI阶段：用 Dagger2 @Inject 注入接口实现。生命周期：通过 Activity 计数判断前后台，SPI 分发状态到各组件。构建：Gradle 多模块 + isRunAlone 切换集成/独立模式。
</Answer>

**问题 4**：六大核心主题之间有什么内在联系？

<Answer>
架构设计是地基——五层分层定义了组件的边界和依赖方向。路由与通信是经络——路由解决页面跳转解耦，通信解决数据交互解耦。DI与生命周期是血液——DI让组件依赖接口而非实现，生命周期管理组件的运行期行为。构建部署是骨架——多模块构建让组件可独立编译。实战案例是落地——电商App拆分验证全流程。交叉点：架构×路由=分层依赖+路由跳转；路由×通信=ARouter Provider；DI×通信=接口下沉+注入实现；生命周期×构建=isRunAlone 独立运行模式。
</Answer>
