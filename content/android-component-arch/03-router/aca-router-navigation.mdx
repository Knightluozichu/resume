## 编译期：注解处理器

ARouter 在编译期通过 APT（Annotation Processing Tool）扫描 `@Route` 注解，自动生成路由表代码：

```kotlin
// 1. 在 Activity/Fragment 上标注 @Route
@Route(path = "/order/detail")
class OrderDetailActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // 自动获取参数
        val orderId = intent.getStringExtra("orderId")
    }
}

// 2. APT 编译期自动生成路由表
// 生成的代码类似：
// ARouter$$Group$$order.java
//   routes.put("/order/detail", RouteMeta(
//     destination = OrderDetailActivity::class,
//     type = ACTIVITY
//   ))
//   routes.put("/order/list", RouteMeta(...))
```

<Callout type="info" title="APT 的价值">
APT 在编译期扫描注解生成 Java 文件，运行期无需反射。这意味着路由注册零性能损耗，且编译期就能发现路径冲突。
</Callout>

## 运行期：初始化与跳转

```kotlin
// 1. Application 中初始化
class App : Application() {
    override fun onCreate() {
        super.onCreate()
        ARouter.init(this)  // 加载编译期生成的路由表
    }
}

// 2. 页面跳转——基础用法
ARouter.getInstance()
    .build("/order/detail")
    .withString("orderId", "123456")
    .withInt("quantity", 2)
    .navigation()

// 3. 带回调的跳转
ARouter.getInstance()
    .build("/login/main")
    .navigation(this, object : NavigationCallback {
        override fun onFound(postcard: Postcard) {
            // 找到目标
        }
        override fun onLost(postcard: Postcard) {
            // 未找到目标，走降级策略
        }
        override fun onArrival(postcard: Postcard) {
            // 跳转完成
        }
    })

// 4. startActivityForResult
ARouter.getInstance()
    .build("/pay/result")
    .navigation(this, 1001)  // requestCode = 1001
```

## 参数传递

```kotlin
// 发送方——传递参数
ARouter.getInstance()
    .build("/order/detail")
    .withString("orderId", "123")
    .withInt("count", 5)
    .withBoolean("isVip", true)
    .withParcelable("orderInfo", orderInfo)  // 传递对象
    .navigation()

// 接收方——自动注入
@Route(path = "/order/detail")
class OrderDetailActivity : AppCompatActivity() {
    @Autowired @JvmField var orderId: String? = null
    @Autowired @JvmField var count: Int = 0
    @Autowired @JvmField var isVip: Boolean = false
    @Autowired @JvmField var orderInfo: OrderInfo? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        ARouter.getInstance().inject(this)  // 自动注入参数
    }
}
```

## 拦截器

```kotlin
// 全局拦截器——在跳转前执行
@Interceptor(priority = 1)
class LoginInterceptor : IInterceptor {
    override fun process(postcard: Postcard, callback: InterceptorCallback) {
        val path = postcard.path
        // 需要登录的页面
        if (path.startsWith("/order") || path.startsWith("/pay")) {
            if (!UserManager.isLoggedIn()) {
                // 跳转登录页
                ARouter.getInstance().build("/login/main").navigation()
                callback.onInterrupt(null)  // 中断跳转
                return
            }
        }
        callback.onContinue(postcard)  // 继续跳转
    }
}

// 多个拦截器按 priority 顺序执行
@Interceptor(priority = 2)
class AnalyticsInterceptor : IInterceptor {
    override fun process(postcard: Postcard, callback: InterceptorCallback) {
        // 埋点统计
        Analytics.track("page_view", mapOf("path" to postcard.path))
        callback.onContinue(postcard)
    }
}
```

## 降级策略

```kotlin
// 当目标页面不存在时的兜底
@Route(path = "/degrade/service")
class DegradeService : DegradeService {
    override fun onLost(context: Context, postcard: Postcard) {
        // 跳转到404页面或Toast提示
        Toast.makeText(context, "页面${postcard.path}不存在", Toast.LENGTH_SHORT).show()
        // 或跳转到Web页面
        ARouter.getInstance().build("/web/fallback")
            .withString("url", postcard.path)
            .navigation()
    }
}
```

<Glossary>

<GlossaryItem term="APT">
Annotation Processing Tool，编译期注解处理器。扫描源码中的注解，生成新的 Java 文件。ARouter 用它在编译期生成路由表，运行期零反射。
</GlossaryItem>

<GlossaryItem term="路由表">
编译期由 APT 生成的 path 到目标类（Activity/Provider）的映射表。按 group 分组，运行期 ARouter.init() 时加载到内存。
</GlossaryItem>

<GlossaryItem term="拦截器">
在路由跳转前执行的逻辑，按 priority 顺序链式执行。常用于登录校验、埋点统计、权限控制。
</GlossaryItem>

<GlossaryItem term="降级策略">
当路由目标不存在时的兜底处理。可实现 DegradeService 接口，跳转到404页面或Web降级页。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：ARouter 的编译期和运行期分别做了什么？

<Answer>
编译期：APT注解处理器扫描@Route注解，按group分组生成路由表Java文件（如ARouter$$Group$$order.java），记录path到Activity/Provider的映射。无需运行期反射，零性能损耗，编译期可发现路径冲突。运行期：ARouter.init()加载编译期生成的路由表到内存；调用build(path).navigation()时，从内存路由表匹配path，找到目标Activity的Class，最终调用startActivity跳转。
</Answer>

**问题 2**：如何在组件化项目中实现带登录校验的页面跳转？

<Answer>
用ARouter拦截器。创建@Interceptor(priority=1)标注的LoginInterceptor实现IInterceptor接口。在process()中判断postcard.path是否需要登录（如/order/、/pay/开头），如果需要且用户未登录，则callback.onInterrupt(null)中断跳转并路由到登录页；已登录则callback.onContinue(postcard)继续。多个拦截器按priority顺序链式执行。
</Answer>

**问题 3**：ARouter 的参数传递和降级策略如何使用？

<Answer>
参数传递：发送方用withString/withInt/withParcelable链式传参；接收方用@Autowired标注字段，在onCreate中调用ARouter.getInstance().inject(this)自动注入。降级策略：实现DegradeService接口，在onLost()中处理目标不存在的情况——可Toast提示、跳转404页或降级到Web页。降级服务也用@Route注解注册。
</Answer>

**问题 4**：为什么 ARouter 选择 APT 而不是运行期反射？

<Answer>
APT在编译期生成路由表代码，优势：①零性能损耗——运行期直接查内存Map，无反射开销 ②编译期安全——路径冲突在编译期报错而非运行期崩溃 ③类型安全——生成的代码有明确类型 ④R8/ProGuard友好——生成的Java文件不会被混淆破坏。反射方案运行期扫描注解慢、有性能损耗、混淆需额外配置。代价是APT增加了编译时间，但换来了运行期的高效和安全。
</Answer>

</Exercises>
