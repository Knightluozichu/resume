## 依赖注入的核心思想

```kotlin
// 硬编码——紧耦合，无法替换
class OrderActivity : AppCompatActivity() {
    // 直接 new，依赖具体实现
    private val repo = OrderRepository(ApiService())

    fun loadOrder() {
        repo.getOrder("123")
    }
}

// 依赖注入——解耦，可替换可测试
class OrderActivity : AppCompatActivity() {
    // 依赖接口，由 DI 容器注入实现
    @Inject lateinit var repo: IOrderRepository

    fun loadOrder() {
        repo.getOrder("123")
    }
}
```

<Callout type="info" title="依赖倒置原则">
高层模块（OrderActivity）不应依赖低层模块（OrderRepository），两者都应依赖抽象（IOrderRepository）。DI 容器负责在运行期把具体实现注入给高层。
</Callout>

## Dagger2 核心注解

### @Inject——标记注入点

```kotlin
// 1. 构造函数注入——告诉 Dagger 如何创建这个类
class OrderRepository @Inject constructor(
    private val api: OrderApi,
    private val cache: OrderCache
) : IOrderRepository {
    override fun getOrder(id: String): Order {
        return api.fetchOrder(id)
    }
}

// 2. 字段注入——告诉 Dagger 这个字段需要注入
class OrderActivity : AppCompatActivity() {
    @Inject lateinit var repo: IOrderRepository
    @Inject lateinit var userService: IUserService
}
```

### @Module——提供第三方依赖

```kotlin
// 当类不能修改构造函数（如第三方库），用 @Module 提供
@Module
class NetworkModule {
    @Provides
    fun provideOkHttp(): OkHttpClient {
        return OkHttpClient.Builder()
            .addInterceptor(LoggingInterceptor())
            .build()
    }

    @Provides
    fun provideRetrofit(client: OkHttpClient): Retrofit {
        return Retrofit.Builder()
            .client(client)
            .baseUrl("https://api.example.com")
            .build()
    }

    @Provides
    fun provideOrderApi(retrofit: Retrofit): OrderApi {
        return retrofit.create(OrderApi::class.java)
    }
}
```

### @Component——连接注入点和提供者

```kotlin
// Component 是注入器和被注入对象之间的桥梁
@Component(modules = [NetworkModule::class, RepositoryModule::class])
interface AppComponent {
    // 声明哪些类可以注入
    fun inject(activity: OrderActivity)
    fun inject(activity: HomeActivity)
    // 暴露依赖给子 Component
    fun orderRepository(): IOrderRepository
}

// 使用
class App : Application() {
    val appComponent = DaggerAppComponent.create()
}

class OrderActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        (application as App).appComponent.inject(this)
        // 现在 repo 已被注入
        repo.getOrder("123")
    }
}
```

## 组件化中的 DI

```kotlin
// 1. common-core 定义接口
interface IUserRepository {
    fun getUser(id: String): User
}

// 2. module-user 提供实现
class UserRepositoryImpl @Inject constructor(
    private val api: UserApi
) : IUserRepository {
    override fun getUser(id: String): User = api.fetchUser(id)
}

@Module
abstract class UserModule {
    @Binds
    abstract fun bindUserRepository(impl: UserRepositoryImpl): IUserRepository
}

// 3. module-home 注入使用
class HomeActivity : AppCompatActivity() {
    @Inject lateinit var userRepo: IUserRepository

    override fun onCreate(savedInstanceState: Bundle?) {
        (application as App).appComponent.inject(this)
        val user = userRepo.getUser("123")
    }
}
```

## 作用域（Scope）

```kotlin
// @Singleton——全App单例
@Singleton
class UserManager @Inject constructor(
    private val repo: IUserRepository
)

// @ActivityScoped——Activity 级别
@Scope
@Retention(AnnotationRetention.RUNTIME)
annotation class ActivityScoped

// 组件化中的作用域分层
@Singleton
@Component(modules = [AppModule::class])
interface AppComponent {
    fun userComponent(module: UserModule): UserComponent
}

@UserScope
@Scope
annotation class UserScope

@UserScope
@Subcomponent(modules = [UserModule::class])
interface UserComponent {
    fun inject(activity: ProfileActivity)
}
```

<Glossary>

<GlossaryItem term="依赖注入">
一种设计模式，对象不自己创建依赖，而是由外部容器（DI容器）注入。好处：解耦、可替换、可测试。Dagger2 在编译期生成注入代码。
</GlossaryItem>

<GlossaryItem term="@Inject">
Dagger2 注解，标记注入点。可标注构造函数（告诉Dagger如何创建）、字段（告诉Dagger需要注入）。构造函数注入优先于字段注入。
</GlossaryItem>

<GlossaryItem term="@Module">
Dagger2 注解，标记提供依赖的模块类。用 @Provides 方法提供第三方库实例（无法修改构造函数的类），用 @Binds 绑定接口到实现。
</GlossaryItem>

<GlossaryItem term="@Component">
Dagger2 注解，标记注入器接口。连接 @Module（提供者）和 @Inject（注入点）。编译期生成实现类（DaggerXxxComponent）。
</GlossaryItem>

<GlossaryItem term="作用域（Scope）">
Dagger2 中控制实例生命周期的机制。@Singleton 是全App单例，自定义 Scope（如 @ActivityScoped）可限定到特定层级。组件化中常按组件分作用域。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：依赖注入的核心原理是什么？解决了什么问题？

<Answer>
依赖注入的核心原理是依赖倒置——高层模块依赖接口而非具体实现，由DI容器在运行期创建并注入具体实现。解决的问题：①解耦——调用方不依赖实现类，可替换 ②可测试——测试时注入Mock实现 ③可复用——接口定义在common层，跨组件注入 ④生命周期管理——DI容器控制实例的创建和作用域。Dagger2在编译期生成注入代码，零运行期反射。
</Answer>

**问题 2**：Dagger2 的 @Inject、@Module、@Component 各自的作用和关系？

<Answer>
@Inject标记注入点——构造函数@Inject告诉Dagger如何创建该类，字段@Inject告诉Dagger需要注入。@Module标记提供者类——用@Provides方法提供第三方库实例（不可改构造函数的类），用@Binds绑定接口到实现。@Component标记注入器接口——连接@Module（提供者）和@Inject（注入点），编译期生成DaggerXxxComponent实现类。关系：Component引用Module获取依赖，把依赖注入到@Inject标记的字段。
</Answer>

**问题 3**：组件化项目中如何用 DI 实现跨组件接口注入？

<Answer>
①common-core定义接口IUserRepository ②module-user实现接口UserRepositoryImpl，用@Module+@Binds绑定接口到实现 ③app壳工程的AppComponent引用所有组件的Module ④module-home在Activity中@Inject lateinit var userRepo: IUserRepository，onCreate时调用appComponent.inject(this)完成注入。关键：接口在common层双方可编译，实现由module-user提供，module-home只依赖接口，Dagger在编译期生成注入代码。
</Answer>

**问题 4**：Dagger2 的作用域在组件化中如何分层？

<Answer>
作用域分层控制实例生命周期：①@Singleton——全App单例，绑定在AppComponent上，如UserManager、Retrofit等全局共享对象 ②自定义Scope如@UserScope——用户登录后创建，登出后销毁，用@Subcomponent实现 ③@ActivityScoped——Activity级别，Activity销毁时GC。组件化中：AppComponent（@Singleton）→ 各业务Component（自定义Scope）→ Activity。分层确保实例在正确的作用域内复用，避免内存泄漏。
</Answer>

</Exercises>
