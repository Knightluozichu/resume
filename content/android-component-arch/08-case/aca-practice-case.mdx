## 拆分步骤

### 第一步：建立公共层

```kotlin
// 1. common-core——基础架构
//    net/RetrofitClient.kt, router/RouterPaths.kt,
//    di/AppModule.kt, base/BaseActivity.kt

// 2. common-biz——公共业务
//    pay/PayManager.kt, push/PushManager.kt, share/ShareManager.kt

// 3. 定义跨组件接口（接口下沉）
// common-core/service/IUserService.kt
interface IUserService : IProvider {
    fun isLogin(): Boolean
    fun getUserId(): String?
    fun logout()
}

// common-core/service/IOrderService.kt
interface IOrderService : IProvider {
    fun createOrder(productId: String): String
    fun queryOrder(orderId: String): OrderInfo?
}
```

### 第二步：拆分业务组件

```kotlin
// module-home——首页组件
@Route(path = "/home/main")
class HomeActivity : BaseActivity() {
    @Inject lateinit var userService: IUserService

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        if (!userService.isLogin()) {
            ARouter.build("/login/main").navigation()
            finish()
            return
        }
        loadHomeData()
    }
}

// module-login——登录组件
@Route(path = "/login/main")
class LoginActivity : BaseActivity() {
    fun onLoginSuccess() {
        EventBus.getDefault().post(LoginEvent(userId))
        ARouter.build("/home/main").navigation()
        finish()
    }
}

// module-order——订单组件
@Route(path = "/order/service")
class OrderServiceImpl : IOrderService {
    @Inject lateinit var repo: OrderRepository

    override fun createOrder(productId: String): String {
        return repo.create(productId).id
    }
}
```

### 第三步：壳工程集成

```kotlin
// app/build.gradle.kts
dependencies {
    implementation(project(":module-home"))
    implementation(project(":module-login"))
    implementation(project(":module-product"))
    implementation(project(":module-cart"))
    implementation(project(":module-order"))
    implementation(project(":module-user"))
    implementation(project(":common-biz"))
    implementation(project(":common-core"))
}

// app/App.kt
class App : Application() {
    override fun onCreate() {
        super.onCreate()
        ARouter.init(this)
        DaggerAppComponent.create().inject(this)
        ComponentManager.init(this)
    }
}
```

## 跨组件交互示例

```kotlin
// 用户在首页点击商品 → 跳转商品详情 → 加购物车 → 下单 → 支付

// 1. 首页跳转商品详情（路由）
ARouter.build("/product/detail")
    .withString("productId", "p_001")
    .navigation()

// 2. 商品详情加购物车（接口下沉）
val cartService = ARouter.build("/cart/service")
    .navigation() as ICartService
cartService.addToCart("p_001", 1)

// 3. 购物车跳转订单（路由）
ARouter.build("/order/create")
    .withStringArrayList("productIds", productList)
    .navigation()

// 4. 订单创建后发起支付（接口下沉）
val payService = ARouter.build("/pay/service")
    .navigation() as IPayService
payService.pay(orderId, amount)

// 5. 支付成功通知（事件总线）
EventBus.getDefault().post(PaySuccessEvent(orderId))
```

<Callout type="success" title="实战经验">
组件化不是一步到位的。先拆公共层（common-core/common-biz），再按业务边界拆高内聚组件，最后处理跨组件通信。拆分过程中保持集成模式可编译，逐步迁移。
</Callout>

<Glossary>

<GlossaryItem term="业务边界">
组件拆分的依据——按业务领域划分组件，而非按技术层划分。如首页、登录、订单是业务边界，UI/逻辑/数据是技术层。
</GlossaryItem>

<GlossaryItem term="逐步迁移">
组件化改造策略：先建公共层，再拆分低风险组件，最后拆核心组件。每步保持可编译可运行，降低风险。
</GlossaryItem>

<GlossaryItem term="Stub（桩）">
独立运行模式下，为缺失的其他组件提供的占位实现。Stub 提供最小化逻辑，保证组件可独立编译运行。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：电商 App 组件化拆分的步骤是什么？

<Answer>
三步走：①建立公共层——创建common-core（网络/路由/DI/Base类）和common-biz（支付/推送/分享），定义跨组件接口（IUserService/IOrderService等） ②拆分业务组件——按业务边界拆分首页/登录/商品/购物车/订单/用户中心6个module，每个组件实现common层接口并@Route注册 ③壳工程集成——app依赖所有组件，Application中初始化ARouter/Dagger/ComponentManager。关键：先公共层后业务层，保持每步可编译。
</Answer>

**问题 2**：从首页到支付的完整跨组件交互流程如何实现？

<Answer>
组合使用路由+接口下沉+事件总线：①首页跳商品详情用路由——ARouter.build("/product/detail").withString("productId",...).navigation() ②商品详情加购物车用接口下沉——ICartService.addToCart() ③购物车跳订单用路由——ARouter.build("/order/create") ④订单创建后发起支付用接口下沉——IPayService.pay() ⑤支付成功用事件总线——EventBus.post(PaySuccessEvent)通知相关组件刷新。页面跳转用路由，同步调用用接口，状态广播用事件。
</Answer>

**问题 3**：组件化拆分带来了哪些可量化的收益？

<Answer>
①编译加速75%——单体8min降到单组件2min，因为只编译改动组件 ②Git冲突减少90%——6人各负责1-2个组件，改不同module ③组件复用——登录/支付组件作为aar复用到3个App ④可测试性——单组件独立单测覆盖率>80% ⑤可独立运行——debug模式单组件秒级启动调试。核心价值：开发效率提升、团队并行、质量可控。
</Answer>

**问题 4**：组件化拆分中遇到的最大挑战是什么？如何解决？

<Answer>
最大挑战是跨组件依赖的处理。拆分前OrderActivity直接import HomeActivity，拆分后不能直接依赖。解决：①页面跳转改用路由——所有startActivity替换为ARouter.build(path).navigation() ②数据获取改用接口下沉——直接调用改为通过common层接口+ARouter Provider ③状态通知改用事件总线——直接回调改为EventBus发布订阅 ④逐步迁移——先拆低风险组件（如登录），再拆核心组件（如订单），每步保持集成模式可编译。
</Answer>
