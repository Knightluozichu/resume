## 为什么这一单元不可压缩

本页依据Eric S. Raymond《UNIX编程艺术》，姜宏、何源、蔡晓骏译，电子工业出版社，2012年8月，ISBN 9787121176654，530页的中文完整目录和 Eric S. Raymond 的送印版在线目录，独立重构 **第6章 透明性：来点儿光**（6. Transparency）。通过可视状态、可编辑表示和诊断路径提升透明性、可显性与可维护性。课程不复制原书正文、插图、案例代码或练习答案，而把目录命题转写为新的模型、命令行切片、交互实验、失败样本和复核证据。

2012年中文版目录逐项列出序、4部分、20章、4个附录、Colophon和索引，共31个正式单元。作者官网 Revision 1.0 标记为2003年9月19日送往 Addison-Wesley 的版本，其目录含381个层级节点；中文版末尾另列Colophon和索引，因此课程的核心目录分母是383。旧内容把它压成8个主题页，遗漏了多道程序设计、微型语言、生成、配置、语言、工具、重用、可移植性、文档与开放源码等正式章，无法复刻全书路径。

时代边界同样不可省略。书中讨论的具体桌面、IPC、脚本语言、版本控制和文档工具反映2003年前后的生态；模块化、文本协议、透明诊断、进程组合、开放标准与社区协作仍是可迁移的判断框架。学习时要分别记录“历史机制”“稳定原则”和“当前替代”，不能把某个旧工具的流行度误当原则本身。

## 四个可手算模型

组合链的总成本由每段处理成本、接口转换与失败放大共同决定：

$$
C_p = \sum_i c_i + \sum_j x_j + f
$$

接口耦合用共享状态、隐式假设和接口宽度近似：

$$
K = s + a + w
$$

诊断能力取决于可见状态、确定性和故障定位粒度，并被隐藏状态削弱：

$$
D = v + r + g - h
$$

发布门禁采用乘法含义：目录覆盖、正常、边界、故障和独立复核任一缺失，整体都不能通过。

$$
G = c \times n \times e \times f \times r
$$

这些式子用于公开假设而非冒充精确预测。先给变量定义、单位和预期主导项，再运行实验。若缩短单段耗时却增加格式转换、共享状态或故障恢复，整体组合成本可能反而上升；这正是局部优化必须放回系统边界复核的原因。

## 从原则到可执行裁决

本单元的最小裁决链是“运行状态 → 可见表示 → 诊断入口 → 故障定位 → 恢复维护”。每个节点写五栏：正在解决的问题、成立语境、候选机制、可观察后果、撤回条件。1. 透明性至少绑定一个正常指标和一个拒绝阈值；2. 可显性至少绑定一个正常指标和一个拒绝阈值；3. 可编辑至少绑定一个正常指标和一个拒绝阈值；4. 故障诊断至少绑定一个正常指标和一个拒绝阈值；5. 维护成本至少绑定一个正常指标和一个拒绝阈值。这种记录把格言变成工程决策，也允许后来者发现原假设已经过期。

Unix风格不等于所有功能都拆成进程，也不等于所有表示都必须是人类可读文本。若数据量、延迟、安全或事务一致性让文本和进程边界付出不可接受代价，可以选择二进制格式、库调用或单体模块；但必须保留清晰接口、检查工具、版本策略和故障证据。原则指导比较，不替代测量。

## 最小可重放实现

第一段把数据和诊断分流，让成功输出保持可管道化：

```sh
set -eu
normalize_events < input.tsv \
  | select_events --status active \
  | sort -t "$(printf '\t')" -k2,2 > result.tsv
printf '%s\n' "records written" >&2
```

第二段用一个小过滤器固定输入模式、输出模式和失败状态：

```python
import json, sys

for number, line in enumerate(sys.stdin, 1):
    try:
        event = json.loads(line)
        if event.get("active") is True:
            print(json.dumps(event, sort_keys=True, separators=(",", ":")))
    except (ValueError, TypeError) as error:
        raise SystemExit(f"line {number}: {error}")
```

第三段把构建步骤声明为依赖关系，使干净检出可重复生成：

```make
.PHONY: verify clean
result.tsv: input.tsv normalize_events select_events
	./pipeline.sh
verify: result.tsv
	cmp --silent result.tsv fixtures/expected.tsv
clean:
	rm -f result.tsv
```

这三段不是唯一实现。真正需要保留的是单向数据流、稳定格式、独立诊断、非零失败状态和显式依赖。迁移到容器、云任务或流处理平台时，应逐项映射这些合同；若平台隐藏了退出状态或重试，必须用追踪与幂等证据补回可观察性。

| 组合   | 小工具、管道、重定向       | 高频内存内调用或原子事务     | 数据流、退出码、部分失败     |
| 表示   | 行文本、记录格式、开放协议 | 超大载荷、严格模式或安全边界 | 模式、版本、检查与转换工具   |
| 状态   | 文件、显式配置、独立进程   | 强一致共享状态               | 所有权、生命周期、恢复点     |
| 接口   | CLI、过滤器、源、汇        | 交互可视任务或无障碍需求     | 最小立异、脚本入口、错误语义 |
| 协作   | 开放标准、补丁、可重建发布 | 受监管或闭源依赖             | 许可证、来源、评审、退出计划 |

迁移顺序是观测、包裹、比较、切换、删除：先记录旧工具输入输出和故障；再用适配器固定合同；以影子运行比较语义；只切换一个调用方；最后删除旧路径。不要同时更换格式、进程边界和配置机制，否则无法定位第一个语义差异。

<Callout type="trap" title="陷阱：把小程序数量当成模块化">
  进程很多但共享同一数据库细节、环境变量或临时文件，仍然高度耦合。模块化要由职责、接口、状态所有权和独立测试证明，而不是由可执行文件计数证明。
</Callout>

<Callout type="trap" title="陷阱：把文本化当成拒绝模式与版本">
  人能打开文件不代表格式可安全演化。字段转义、编码、未知键、排序、原子写入和版本迁移都必须明确；否则“简单文本”只是把解析复杂度推给所有调用者。
</Callout>

## 可重放证据与独立复核

每次实验保存中文版版次、官方目录坐标、需求、代码哈希、工具与系统版本、locale、时区、输入、初始文件权限、单位和资源限制；随后保存预期管道、实际管道、标准输出、标准错误、退出码、耗时、首差和回退点。网络或外部服务要记录响应摘要和契约版本，不把敏感原文塞进证据。

独立复核者只接收合同、输入和干净检出。他先手算组合成本和耦合，再重建工具链，运行正常、边界与单故障；双方必须在相同节点接受或拒绝，并能解释差异来自Unix原则、时代假设、工具实现还是环境。无法从干净环境重建的演示不算完成。

## 本章回顾

第6章 透明性：来点儿光不是一个孤立格言，而是“运行状态 → 可见表示 → 诊断入口 → 故障定位 → 恢复维护”中的完整决策单元。掌握它意味着能比较候选、公开时代边界、写出接口与失败合同，并以组合、表示和证据三视图重放。课程最终要求读者既能说明Unix传统为何有效，也能在条件不成立时有证据地拒绝它。

1. 如何为第6章 透明性：来点儿光建立最小可重放基线？

<Answer>
  固定2012年中文版和作者送印版目录坐标、代码与工具版本、输入、locale、权限、初始状态和单位，先画“运行状态
  → 可见表示 → 诊断入口 → 故障定位 →
  恢复维护”预期，再保存正常、边界与单故障轨迹。
</Answer>

2. 怎样证明“能让陌生复核者在不读实现的情况下定位一次故障并恢复到已知状态。”不是一次偶然成功？

<Answer>
  先手算组合成本、接口耦合、诊断能力和移植余量，再让独立复核者从干净检出重建；双方必须在相同首差拒绝故障，并保留一致的退出码、诊断和回退状态。
</Answer>

3. 修复一个失败后怎样做相邻回归？

<Answer>
  先重放原失败，再运行相邻边界和正常基线；逐项检查透明性、可显性、可编辑、故障诊断、维护成本，确认输入输出、错误通道、版本与资源证据没有新首差后才进入下一页。
</Answer>
