## 核心概念

### AUTOSAR 的起源与目标

AUTOSAR（AUTomotive Open System ARchitecture，汽车开放系统架构）由全球主要汽车制造商和供应商于2003年联合发起，旨在建立开放的、标准化的汽车电子软件架构。其核心目标是实现应用软件与硬件的解耦，使软件组件可在不同ECU和硬件平台间复用，从而降低开发成本、提高软件质量和可维护性。

### 三层架构

AUTOSAR的核心是三层架构，自上而下分为：

1. **应用层（Application Layer）**：由若干软件组件（SWC）组成，实现车辆控制业务逻辑。SWC独立于硬件，通过端口（Port）和接口（Interface）与外部通信，不直接访问底层硬件。
2. **RTE运行时环境（Runtime Environment）**：位于应用层和BSW之间，是SWC与BSW的解耦桥梁。RTE屏蔽底层总线差异，提供通信抽象和调度管理，使SWC与BSW可以独立开发和演化。RTE从ARXML配置描述自动生成C代码。
3. **基础软件层（Basic Software Layer, BSW）**：提供操作系统、通信、诊断、存储等系统级服务，以及ECU硬件抽象和微控制器抽象。BSW内部又分为服务层、ECU抽象层和MCAL三层。

### 软硬件解耦的实现机制

AUTOSAR通过以下机制实现软硬件解耦：

- **虚拟功能总线（VFB）**：定义虚拟通信总线抽象，SWC在VFB上通信，不绑定具体物理总线
- **RTE自动生成**：根据ECU配置将VFB通信映射到物理总线（CAN/Ethernet/FlexRay）
- **标准化接口**：BSW和MCAL提供标准化API，不同芯片厂商实现相同接口
- **配置驱动**：系统配置以ARXML描述，工具自动生成代码，配置变更不修改源码

### BSW 三层子架构

BSW内部进一步分为三层：

- **服务层**：OS操作系统、内存服务（NvM）、通信服务（Com/PduR）、诊断服务（Dcm/Dem）、ECU状态管理（EcuM/BswM/WdgM）
- **ECU抽象层**：I/O抽象、存储抽象、通信抽象，屏蔽ECU硬件外设差异
- **MCAL微控制器抽象层**：直接访问微控制器寄存器，封装DIO/ADC/PWM/CAN等片上外设驱动

## 术语表

| 术语 | 含义 |
|------|------|
| AUTOSAR | 汽车开放系统架构，标准化汽车电子软件规范 |
| 应用层 | SWC集合，实现业务逻辑，独立于硬件 |
| RTE | 运行时环境，通信抽象与调度管理 |
| BSW | 基础软件层，系统服务与硬件抽象 |
| VFB | 虚拟功能总线，SWC间逻辑通信抽象 |
| 服务层 | BSW最上层，提供OS/通信/诊断等服务 |
| ECU抽象层 | BSW中层，屏蔽ECU外设差异 |
| MCAL | BSW最底层，微控制器寄存器抽象 |
| ARXML | AUTOSAR配置描述文件格式 |
| SWC | 软件组件，应用层基本单元 |
