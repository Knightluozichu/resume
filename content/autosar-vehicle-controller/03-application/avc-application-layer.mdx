## 核心概念

### SWC 三大核心要素

软件组件（SWC）是AUTOSAR应用层的基本单元，由三个核心要素构成：

1. **端口（Port）**：SWC与外部的通信接口，分为PPort（提供端口，Provider，数据/服务的提供方）和RPort（需求端口，Requirer，数据/服务的需求方）。一个SWC可以有多个PPort和RPort。

2. **内部行为（Internal Behavior）**：包含一个或多个Runnable（可运行实体），每个Runnable是一段可被RTE调度的C函数。Runnable通过RTE提供的API（如Rte_Read/Rte_Write/Rte_Call）访问端口数据。

3. **接口（Interface）**：定义端口的数据类型和通信方式，包括S/R接口（数据通信）、C/S接口（服务调用）、Mode Switch接口（模式切换）和NV Data接口（非易失数据）。

### 端口与接口类型

| 接口类型 | 说明 | 典型场景 |
|----------|------|----------|
| S/R（发送-接收） | 数据通信，发送方推送数据 | 传感器信号传输、状态广播 |
| C/S（客户端-服务端） | 服务调用，请求-响应模式 | 诊断服务调用、模式切换请求 |
| Mode Switch | 模式切换通知 | ECU模式状态变化通知 |
| NV Data | 非易失数据访问 | 标定参数读写、配置数据存储 |

PPort是数据/服务的提供方，RPort是数据/服务的需求方。一个S/R通信连接由一个PPort和一个RPort组成。

### Runnable 触发方式

Runnable由RTE根据配置的触发条件调度执行：

- **周期触发（Timing Event）**：RTE按固定周期（如10ms/100ms）调用，最常用
- **数据接收触发（DataReceived Event）**：RPort接收到新数据时触发
- **操作调用触发（OperationInvoked Event）**：C/S通信中客户端调用服务端操作时触发
- **模式切换触发（ModeSwitch Event）**：模式切换时触发
- **初始化触发（Init Event）**：ECU启动时触发一次

### SWC 类型分类

AUTOSAR定义了五种SWC类型：

1. **Application SWC（应用组件）**：纯应用逻辑，不直接访问硬件，通过RTE通信
2. **Sensor/Actuator SWC（传感器/执行器组件）**：连接应用层与ECU抽象层，通过RTE访问I/O
3. **Service SWC（服务组件）**：提供BSW服务接口（如诊断、模式管理）
4. **Parameter SWC（参数组件）**：提供标定参数访问
5. **ECU Abstraction SWC**：封装ECU硬件抽象层接口

### SWC 设计示例

以车速控制SWC为例，其设计包括：

- **RPort**：接收车速传感器信号（S/R接口，uint16 km/h）、接收目标车速设定（S/R接口，uint16）
- **PPort**：输出控制指令（S/R接口，sint8节气门开度百分比）、输出DTC状态（C/S接口）
- **Runnable**：Runnable_ReadSensor（周期10ms，读取并滤波）、Runnable_ControlLogic（周期10ms，PID计算）、Runnable_Init（初始化PID参数）

| SWC | 软件组件，应用层基本单元 |

| RPort | 需求端口，数据/服务的需求方 |
| Runnable | 可运行实体，SWC内可被调度的函数 |

| Sensor/Actuator SWC | 传感器/执行器组件 |
