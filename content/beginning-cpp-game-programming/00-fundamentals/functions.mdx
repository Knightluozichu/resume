## 函数是逻辑的积木

写游戏不可能把所有逻辑堆在 main 里。函数让你把一段逻辑命名、封装、复用：`update()`、`render()`、`takeDamage()` 各管一摊。C++ 函数机制里最关键的是参数怎么传、怎么省、怎么同名复用。

## 值传递与引用传递

值传递：实参的**副本**传给形参，函数内改形参不影响原变量。引用传递：形参成为实参的**别名**，函数内改形参就是改原变量。区分就看参数类型有没有 `&`。

```cpp
void addScore(int s);        // 值传：s 是副本，改 s 不影响外部
void damage(Player& p);      // 引用传：p 是别名，能直接扣 p 的血
```

那什么时候用引用？两种情况：一要函数修改原变量（`damage(p)` 直接改血量）；二实参是大对象（`string`、`Sprite`），值传要复制整份开销大，引用几乎零成本。

<Callout type="tip">
参数选择口诀：小类型（int/float/指针）值传；大对象只读用 `const&`（省复制又防误改），可写用 `&`。`void print(const Player& p)` 是只读大对象的标准写法。
</Callout>

## 默认参数

默认参数让某些参数有默认值，调用时可省略：

```cpp
void heal(Player& p, int amount = 10, bool showEffect = true);

heal(p);            // 等价 heal(p, 10, true)
heal(p, 50);        // 大回血，默认显示特效
heal(p, 50, false); // 静默回血（测试用）
```

一条签名覆盖多种调用，比写三个重载互相转发更简洁。规则：默认参数必须从右往左连续给，调用时也从右往左省略。

## 函数重载

同名函数但参数列表不同（个数/类型/顺序），编译器按实参自动匹配：

```cpp
void spawn(Enemy& e);                  // 默认位置
void spawn(Enemy& e, float x, float y);// 指定坐标
void spawn(Enemy& e, Vector2f pos);    // 向量坐标
```

调用 `spawn(e, 100, 200)` 匹配第二个，`spawn(e, pos)` 匹配第三个。重载适合参数类型/语义不同的情况；参数只是有常见默认值时用默认参数更简单。

<Callout type="trap">
重载只看参数列表，返回类型不参与区分。若两个重载对某调用都能匹配（二义性），编译报错，需显式转型消除。别滥用重载——参数语义差异大才用，否则用不同名字更清楚。
</Callout>

## 综合设计示例

「给玩家加血」，参数有玩家、加血量、是否触发特效。最佳设计：

```cpp
void heal(Player& p, int amount = 10, bool showEffect = true);
```

- `Player&`：必须改血量 + Player 大对象省复制
- `int amount` 值传：小类型只读输入
- 两个默认参数覆盖常见用法，特殊场景再传参

一条签名解决「默认小回血」「大回血」「静默回血」三种情况，简洁灵活。

## 小结

- 值传复制副本安全但改不了原件，引用传能改且省复制
- 大对象只读用 const&，可写用 &，小类型值传
- 默认参数覆盖常见用法，重载处理参数类型差异
- 签名设计要兼顾修改需求、性能与调用简洁性

<Glossary>
<GlossaryItem term="值传递">
将实参的副本传给形参的参数传递方式，函数内修改形参不影响原变量，适合小类型和只读输入。
</GlossaryItem>
<GlossaryItem term="引用传递">
用 `&` 声明形参使其成为实参别名，函数内修改形参即修改原变量，适合需要修改原件或避免大对象复制的场景。
</GlossaryItem>
<GlossaryItem term="const 引用">
`const T&` 形参，既避免复制又禁止函数内修改，是只读大对象参数的标准写法。
</GlossaryItem>
<GlossaryItem term="默认参数">
函数参数声明的默认值，调用时可省略该参数，规则是从右往左连续声明。
</GlossaryItem>
<GlossaryItem term="函数重载">
同名函数但参数列表不同，编译器按调用实参自动匹配最合适版本，返回类型不参与区分。
</GlossaryItem>
</Glossary>
