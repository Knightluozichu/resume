## 为什么需要一张地图

做游戏听起来很酷，但真正上手会卡在两个坎上：一是 C++ 本身语法不少，类型、流程、函数、类一层叠一层；二是游戏有自己的结构，游戏循环、窗口、渲染、碰撞，每个都是新概念。两件事一起学容易顾此失彼。

Michael Dawson 的《Beginning C++ Game Programming》给了一条清晰的路：先用 C++ 写控制台逻辑练语法，再引入 SFML 让画面动起来，最后把所有知识缝合成一个可玩游戏。这张地图就是帮你提前看清全貌，知道现在在哪、下一步去哪。

## 三大板块一览

全书 10 章分三大板块，对应三段递进：

- **C++ 基础（5 章）**：类型与变量、流程控制、函数与引用、类与面向对象。目标是建立「用 C++ 表达逻辑」的能力，全在控制台里跑，不被图形细节干扰。
- **游戏编程入门（3 章）**：游戏循环、图形与 SFML、碰撞检测。引入游戏专属结构和 SFML 工具链，让你的逻辑「动起来、看得见」。
- **游戏开发实战（2 章）**：综合游戏项目、总复习。用分层架构把前面的知识组装成完整可玩游戏，并串联复习。

<Callout type="tip">
前三段别跳。游戏循环里要用类组织 Game、Entity、State，没有类的基础就只能写成一坨过程式代码，难以扩展。语法地基越牢，后面组装游戏越顺。
</Callout>

## 工具链：SFML

本书选用 SFML（Simple and Fast Multimedia Layer）作为图形库。它面向对象、API 简洁，`RenderWindow`、`Sprite`、`Texture` 等类直观易用，且是 C++ 原生，与教学主线一致。相比直接啃底层 API，SFML 把窗口创建、事件循环、纹理加载等繁琐细节封装好，让你聚焦在「游戏逻辑与编程概念」上。

## 推荐学习路径

按依赖关系走，先打地基再盖楼：

```
第 1 站  学习地图        ← 先看清全貌（本章）
第 2 站  类型与变量      ← C++ 地基的第一块砖
第 3 站  流程控制        ← 让程序能判断、能循环
第 4 站  函数与引用      ← 把逻辑拆成可复用单元
第 5 站  类与面向对象    ← 用对象组织游戏世界
第 6 站  游戏循环        ← 一切游戏的心跳
第 7 站  图形与 SFML     ← 让画面动起来
第 8 站  碰撞检测        ← 让物体能相互作用
第 9 站  综合游戏项目    ← 把知识缝合成游戏
第 10 站 总复习          ← 串联全书
```

<Callout type="trap">
不要跳过前 5 章直接做游戏。看到第 6 章的游戏循环你会用到类、引用、函数重载，地基不牢会在组装阶段连环踩坑，反而更慢。
</Callout>

## 小结

- 全书分三大板块：C++ 基础、游戏编程入门、游戏开发实战
- 选 SFML 作图形库，封装底层细节、聚焦游戏逻辑
- 按依赖关系学习：先语法、再机制、最后组装
- 语法地基越牢，后续组装游戏越顺

<Glossary>
<GlossaryItem term="SFML">
Simple and Fast Multimedia Layer，面向对象的 C++ 多媒体库，封装窗口、图形、音频等模块，本书用它作为游戏图形与输入的工具链。
</GlossaryItem>
<GlossaryItem term="游戏循环">
游戏程序反复执行「处理输入 → 更新状态 → 渲染 → 检测退出」的核心结构，是实时游戏区别于顺序执行程序的根本。
</GlossaryItem>
<GlossaryItem term="三段递进">
本书的学习结构：先用 C++ 写逻辑，再让逻辑实时运行并可见，最后组装成工程化项目，每一段是下一段的地基。
</GlossaryItem>
</Glossary>
