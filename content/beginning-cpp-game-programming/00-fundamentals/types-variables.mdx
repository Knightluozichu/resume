## 类型是 C++ 的第一块砖

C++ 是静态类型语言，每个变量在声明时就要确定类型，编译器据此分配内存、检查运算合法性。游戏里所有数据——玩家的血量、角色的坐标、菜单的选项、是否通关——都要先想清楚用什么类型存。

## 四大类型族

C++ 基本类型分四族：

- **整型**：`short`、`int`、`long`、`long long`，存整数。游戏里的分数、生命值、关卡编号都用它。
- **浮点**：`float`、`double`、`long double`，存小数。角色坐标、速度、角度这类需要小数精度的量用浮点。
- **字符**：`char`、`wchar_t`、`char16_t`、`char32_t`，存单个字符。本质是小整数，可参与算术运算，常用于菜单选项（如按 `'1'` 开始）。
- **布尔**：`bool`，只有 `true`/`false`。游戏里的开关——是否暂停、是否碰撞、是否通关——都用它。

## 有符号 vs 无符号

整型可用 `signed`/`unsigned` 修饰。默认 `int` 是有符号，可正可负；`unsigned int` 只能非负，但正数上限翻倍。这听起来像「白捡范围」，但有陷阱。

```cpp
unsigned int hp = 0;
hp = hp - 1;  // 结果不是 -1，而是 4294967295！
```

无符号数减到负数会「回绕」成巨大正数。如果用 `unsigned` 存血量，玩家本该死亡却变成满血，bug 极难排查。

<Callout type="trap">
不要用 unsigned 存「会做减法」的量（如血量、倒计时）。回绕陷阱会让 0-1 变成天文数字。需要非负语义时，用 int 并在逻辑里约束范围更安全。
</Callout>

## 浮点的取舍

`float` 约 7 位有效数字、4 字节；`double` 约 15 位、8 字节。游戏坐标一般用 `float`：精度对屏幕像素足够，内存更省，GPU 单精度运算也更快。只有需要高精度累积（物理引擎长时间积分）才用 `double`。SFML 的 `Vector2f` 也用 `float`。

## 变量与初始化

```cpp
int score = 0;          // 传统初始化
float x{100.0f};        // 列表初始化，防窄化
auto name = getPlayerName(); // 类型推断
```

C++11 起推荐用 `{}` 列表初始化，它会阻止隐式窄化（如 `int x{3.5}` 编译报错），更安全。

## 类型推断 auto

`auto` 让编译器推导类型，少打字、改类型时连声明一起改。适合类型明显或冗长的场景：

```cpp
for (auto it = enemies.begin(); it != enemies.end(); ++it) { ... }
```

但类型不明显或涉及精度敏感运算时，显式声明更易读：

<Callout type="tip">
auto 的原则：类型从名字或上下文一目了然时用 auto；涉及精度（int/float 区别影响运算结果）或读者需要明确类型时显式声明。`auto hp = player.getHp();` 读者不知是 int 还是 float，此时写 `int hp` 更清楚。
</Callout>

## 小结

- C++ 基本类型分整型、浮点、字符、布尔四族
- 整型有符号/无符号之分，无符号回绕陷阱要警惕
- 游戏坐标用 float，计数用 int，开关用 bool
- auto 省事但类型不明显时显式声明更可读

<GlossaryItem term="静态类型">
变量类型在编译期确定的语言特性，编译器据此分配内存并检查运算合法性，C++ 是静态类型语言。
</GlossaryItem>
<GlossaryItem term="无符号回绕">
unsigned 整型减到负数时回绕成最大正值的现象，会导致「0-1 变成天文数字」的恶性 bug，故不宜存会做减法的量。
</GlossaryItem>
<GlossaryItem term="列表初始化">
用 `{}` 初始化变量的语法，会阻止隐式窄化转换（如把浮点赋给整型），比 `=` 更安全。
</GlossaryItem>
<GlossaryItem term="auto">
C++11 起的类型推断关键字，让编译器从初值推导变量类型，减少冗长类型名书写。
</GlossaryItem>
