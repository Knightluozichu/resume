## 串成一条路

学完前面九章，你已经从零走到了能做出一个可玩 2D 游戏的程度。这一章不教新东西，而是把散落的知识点串成一张网，看清它们怎么协作，以及下一步该往哪走。

## 三段递进

全书以「C++ 游戏编程」为中心，分三大分支：

- **C++ 基础**提供「表达逻辑的语言能力」：类型与变量、流程控制、函数与引用、类与面向对象。这是地基，没有它游戏逻辑无从写起。
- **游戏机制**提供「让逻辑实时运行并可见的机制」：游戏循环、SFML 图形、碰撞检测。这让你的逻辑动起来、看得见、能交互。
- **项目实战**用分层架构把两者组装成「可玩、可扩展的完整游戏」。

每一段都是下一段的地基：先学写逻辑 → 再学让逻辑动起来 → 最后把动起来的逻辑组织成工程。

## 类与实体的对应

C++ 的「类」与游戏的「实体」几乎是直译关系。Player 类定义玩家有什么数据（位置、血量）和行为（移动、受伤），游戏里的玩家角色就是一个 Player 对象。继承让「敌人均有公共属性又各有特殊行为」自然表达，多态让 `vector<Entity*>` 统一管理不同实体并各自调对 update/draw，封装把每个实体的状态保护起来。

<Callout type="tip">
面向对象是游戏开发的天然范式，因为游戏世界满是「有状态、有行为的对象」——这恰好对应类的「数据 + 方法」模型。从 C++ 类到游戏实体几乎是直译：一个类 = 一种游戏对象。
</Callout>

## 从控制台到图形游戏的思维转变

学完本书，你经历了几个关键转变：

1. **顺序执行 → 循环驱动**：从「跑完就结束」到「持续循环推进状态」。
2. **即时输出 → 双缓冲渲染**：从 cout 立即可见到 clear/draw/display 三件套。
3. **离散输入 → 实时输入 + 事件**：从 cin 阻塞到事件与实时状态并用。
4. **无时间概念 → 帧率无关**：从速度由 CPU 决定到用 delta time 统一。
5. **单一状态 → 状态机**：从线性执行到菜单/游玩/暂停反复切换。
6. **过程式 → 对象协作**：从一串函数到多对象在循环里协作。

核心转变：从「写一段跑完的逻辑」到「设计一个持续运行、状态不断演化的系统」。

## 基石与瓶颈

本书给了「从零到能做出可玩 2D 游戏」的完整闭环，这是最关键的信心与地基。但要继续做更复杂的游戏，需认清哪些是基石、哪些是瓶颈：

- **基石**（保留）：游戏循环结构、分层解耦思想、帧率无关、对象建模——这些进阶都长在上面。
- **瓶颈**（待升级）：纯继承实体模型在类型爆炸时会僵化（需转 ECS）；手写碰撞在大规模场景会慢（需空间分区引擎）；未涉及内存/性能优化；单文件组织撑不住大项目。

<Callout type="trap">
别把本书的具体实现当成唯一正解。继续前进时，把架构思想（分层、解耦、循环、帧率无关）保留，把具体实现（纯继承、手写碰撞、单类堆逻辑）逐步替换为更工程化的方案。思想是基石、部分实现是待升级的瓶颈。
</Callout>

## 继续前进的方向

- **C++ 进阶**：智能指针/RAII、移动语义、模板、STL、lambda。
- **设计模式与架构**：组件模式（ECS）、状态模式、观察者、工厂，用组合替代深继承。
- **游戏引擎概念**：场景图、材质系统、动画状态机、物理引擎集成。
- **性能与工具**：性能剖析、缓存友好设计、多线程、资源流式加载。
- **数学与物理**：线性代数（变换矩阵、四元数）、物理积分，支撑 3D 与真实物理。

## 小结

- 全书三段递进：C++ 基础 → 游戏机制 → 项目实战
- 类与实体直译对应，面向对象是游戏开发的天然范式
- 从控制台到图形游戏，思维从「跑完的逻辑」转向「持续运行的系统」
- 思想是基石、部分实现是待升级的瓶颈，继续前进保留前者替换后者
