## 你的 Activity 是「活的」——它有生命周期

用户切到别的 App、旋转屏幕、按 Back 键——这些操作都会触发 <Term def="系统按固定顺序调用的六个回调方法，通知 Activity 当前处于创建、可见、前台、暂停、停止或销毁状态。">Activity 生命周期</Term>。不懂生命周期，就容易内存泄漏、丢状态、莫名其妙崩溃。

用**相机**类比：onCreate 是开机，onResume 是进入拍摄，onPause 是接电话暂时放下，onStop 是盖上镜头盖，onDestroy 是关机。

## 六大生命周期回调

| 回调 | 调用时机 | 典型用途 |
|---|---|---|
| `onCreate()` | Activity 首次创建 | 加载布局、初始化变量 |
| `onStart()` | Activity 即将可见 | 注册可见时才需要的监听 |
| `onResume()` | 前台可交互 | 开启动画、恢复相机预览 |
| `onPause()` | 失去焦点 | 暂停动画、保存轻量状态 |
| `onStop()` | 完全不可见 | 释放重资源 |
| `onDestroy()` | Activity 被销毁 | 最终清理 |

<Stepper>
  <Step title="① A.onPause()">
    A 失去交互焦点，但仍可能部分可见（若 B 不是全屏）。此时应该暂停动画、保存轻量状态——onPause 是系统在低内存时最后保证执行的回调，持久化关键数据应在此完成。
  </Step>
  <Step title="② B.onCreate() → onStart() → onResume()">
    新 Activity B 经历完整的三回调序列进入前台，此时 B 可与用户交互。

    ```kotlin
    class BActivity : AppCompatActivity() {
        override fun onCreate(savedInstanceState: Bundle?) {
            super.onCreate(savedInstanceState)
            setContentView(R.layout.activity_b)
            // 此时 A 已经 onPause，B 的界面即将显示
        }
    }
    ```
  </Step>
  <Step title="③ A.onStop()">
    B 完全覆盖屏幕后，A 变为不可见，进入 Stopped 状态。此时应释放重资源（如传感器注册、网络监听）。按 Back 返回时顺序相反：B.onPause → A.onRestart/onStart/onResume → B.onStop/onDestroy。
  </Step>
</Stepper>

<Stepper>
  <Step title="① onPause → onStop → onDestroy">
    系统检测到屏幕方向变化，旧 Activity 实例依次经历暂停、停止、销毁三个回调。原有成员变量（如 EditText 输入、Activity 级状态）全部清空。

    ```
    // 旋转前用户输入了 "Hello"，onDestroy 后 mEditText 不复存在
    ```
  </Step>
  <Step title="② onCreate → onStart → onResume">
    系统以新的 Configuration（横屏/竖屏）重建 Activity 实例。新实例从零开始——如果没有 ViewModel 或 onSaveInstanceState，所有 UI 状态归零。
  </Step>
</Stepper>

实例被重建——成员变量默认清空，必须靠 ViewModel 或 `onSaveInstanceState` 保状态（下一章详讲）。

<Callout type="trap">
  **onPause 是最后保证执行的**——内存不足时系统可能在 onPause 后就杀进程，onStop/onDestroy 不一定跑到。持久化关键数据应在 onPause 完成。
</Callout>

<Callout type="trap">
  每个回调**第一行必须** `super.onCreate()` 等——父类负责 Fragment 恢复、主题初始化；跳过会 `SuperNotCalledException` 或界面异常。
</Callout>

<Callout type="trap">
  **现象**：onCreate 里做网络请求 → 启动黑屏数秒。**原因**：onCreate 在主线程。**修法**：协程/ViewModel 发起请求，onCreate 只做 UI 绑定。
</Callout>

## 小结

- 六回调：Create → Start → Resume ↔ Pause/Stop → Destroy
- 启动第二个 Activity：先 Pause 当前，再 Create 新的，最后 Stop 旧的
- 旋转 = 销毁 + 重建，需状态保持机制
- 耗时操作勿放主线程生命周期回调
