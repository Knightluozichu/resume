## 顶栏不只是标题——它是命令中枢

<Term def="Material Design 顶栏，可显示标题、导航图标和操作菜单，现代 App 多用 Toolbar 实现。">App Bar</Term>（Toolbar）承载标题、返回箭头和「更多」菜单。Fragment 时代默认 <Term def="旧版框架提供的顶栏，现推荐用 Toolbar + setSupportActionBar 替代。">ActionBar</Term> 不够灵活——把 Toolbar 放进布局，才能和 CoordinatorLayout、Drawer 配合。

## 启用 Toolbar

`res/layout/activity_main.xml`：

```xml
<com.google.android.material.appbar.MaterialToolbar
    android:id="@+id/toolbar"
    android:layout_width="match_parent"
    android:layout_height="?attr/actionBarSize"
    app:title="@string/app_name" />
```

```kotlin
setSupportActionBar(findViewById(R.id.toolbar))
supportActionBar?.setDisplayHomeAsUpEnabled(true)
```

主题使用 `NoActionBar` 变体，避免双顶栏。

## Options Menu

`res/menu/crime_list_menu.xml`：

```xml
<menu xmlns:android="http://schemas.android.com/apk/res/android">
    <item
        android:id="@+id/menu_add"
        android:icon="@drawable/ic_add"
        android:title="@string/add_crime"
        app:showAsAction="ifRoom" />
    <item
        android:id="@+id/menu_settings"
        android:title="@string/settings"
        app:showAsAction="never" />
</menu>
```

```kotlin
override fun onCreateOptionsMenu(menu: Menu): Boolean {
    menuInflater.inflate(R.menu.crime_list_menu, menu)
    return true
}

override fun onOptionsItemSelected(item: MenuItem): Boolean {
    return when (item.itemId) {
        R.id.menu_add -> { viewModel.addCrime(); true }
        R.id.menu_settings -> { startActivity(Intent(this, SettingsActivity::class.java)); true }
        android.R.id.home -> { onBackPressedDispatcher.onBackPressed(); true }
        else -> super.onOptionsItemSelected(item)
    }
}
```

`showAsAction="ifRoom"` 有空间时显示图标；`never` 进 Overflow（⋮）。

<Stepper>
  <Step title="① 列表页配置 Toolbar">
    在列表 Activity 的布局中放置 `MaterialToolbar`，主题使用 `NoActionBar` 变体避免双顶栏。通过 `setSupportActionBar(toolbar)` 将 Toolbar 设为 Activity 的 App Bar——列表页的 Toolbar 通常只显示标题和菜单项（如"添加"），不显示返回箭头（home 图标）。
  </Step>
  <Step title="② 详情页启用 Up 导航">
    在详情 Activity 中调用 `supportActionBar?.setDisplayHomeAsUpEnabled(true)`——Toolbar 左边出现一个向左的箭头（←），告诉用户"点这里可以返回上一级"。这是"向上导航"（Up）而非系统"返回"（Back）——Up 保证用户回到应用内的逻辑父页面。
  </Step>
  <Step title="③ 点击 ← 触发 onOptionsItemSelected">
    用户点击返回箭头时，系统回调 `onOptionsItemSelected(item)`，`item.itemId` 为 `android.R.id.home`。在回调中判断：如果用 Jetpack Navigation，调 `navController.navigateUp()` 或 `NavigationUI.navigateUp(navController, configuration)`；如果手动管理，调 `onBackPressedDispatcher.onBackPressed()` 或 `finish()`。必须 `return true` 表示事件已被消费。
  </Step>
  <Step title="④ 返回栈弹出，回到列表页">
    详情 Activity 从返回栈弹出（或 Fragment 详情页被 NavController 回退），列表页重新进入 `onResume` 状态。如果列表页之前被系统回收，此时自动重建并恢复滚动位置——用户感觉一切如初。
  </Step>
</Stepper>

<Callout type="tip">
  **Jetpack Navigation** 与 Toolbar 绑定：`setupWithNavController(toolbar, navController)` 自动处理标题与 Up，少写重复 home 处理。
</Callout>

<Callout type="trap">
  忘记 `return true` → 系统继续处理，可能触发默认行为或重复执行。已处理的 item 必须返回 true。
</Callout>

<Callout type="trap">
  Fragment 里要菜单：在 `onCreateView` 里 `setHasOptionsMenu(true)`（旧 API）或 MenuProvider（AndroidX Activity 1.4+），否则 `onCreateOptionsMenu` 不会调到 Fragment。
</Callout>

## 从生命周期、状态与证据开始

第4版不是API词典，而是六个逐步扩展的应用实验。每一章都要回答：用户从哪里进入，哪个Android组件拥有工作，回调在哪个线程发生，哪些事实必须跨旋转或进程死亡恢复，外部系统怎样失败，资源在何时释放。<Term def="负责创建、取消并最终释放组件、任务或资源的明确作用域">生命周期所有者</Term>把Activity、Fragment视图、ViewModel、Worker、线程与资源的寿命连接起来；没有所有者的异步任务就是潜在泄漏。

界面字段不是天然事实。<Term def="在配置变化或进程重建后，可从保存事实重新构造的最小用户状态">可恢复状态</Term>应根据数据大小与寿命放入saved instance state、ViewModel、数据库、文件或调度器，而不是全部塞进单例。Intent、文件、数据库、网络、系统服务和其他应用形成<Term def="跨边界交换数据时必须验证的action、类型、权限、大小、时序和失败约束">外部合同</Term>；正常响应只是合同中的一个样本。

本书以2019年第四版、Android 5.0至8.1及其后续兼容实践为语境。<Term def="Android版本、targetSdk、设备形态、权限与依赖共同限定的行为适用范围">版本边界</Term>要求先还原书中机制，再查询现代目标SDK的权限、后台、存储、通知和组件导出合同。<Term def="由环境指纹、输入、操作、日志、状态快照和断言组成的可重放结论">证据链</Term>则保证“在我的模拟器能跑”不会冒充可交付结论。

## 最小可执行切片

先把状态转换与Android副作用分开。下面的Kotlin骨架不替代本章代码，而是让旋转、进程恢复与失败输入可单测：

```kotlin
sealed interface ScreenState {
    data object Loading : ScreenState
    data class Ready(val key: String) : ScreenState
    data class Failed(val reason: String, val retryable: Boolean) : ScreenState
}

fun reduce(current: ScreenState, event: UiEvent): ScreenState = nextState(current, event)
```

固定JDK、SDK、Gradle、设备API、语言和输入，清理缓存后从命令行保存制品与日志：

```bash
./gradlew --no-daemon clean test assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am force-stop com.example.app
adb shell monkey -p com.example.app 1
adb logcat -d -v threadtime > run.log
```

先写行为断言，再执行用户操作和故障注入：

```gherkin
Given a pinned build, device API, locale, permission state, and input
When the owner is recreated after state saving or process death
Then durable facts reconstruct the same user-visible state
And cancelled work cannot update a destroyed owner
And denied permission, offline input, and malformed data remain recoverable
```

三段代码分别约束状态模型、环境重放和行为结果。真实项目还要加入静态检查、单元测试、仪器测试、无障碍检查和发布构建；日志只能支持断言，不能代替断言。

## 线程、状态与外部资源

主线程负责输入、生命周期分发和大部分UI工作，磁盘、网络、图片解码与长计算不能阻塞帧。后台结果返回前必须确认所有者仍有效；Fragment的生命周期与其View生命周期不是一回事。每个实现都应列出入口、线程、事实源、取消点、关闭责任和用户可见失败六项。

跨应用Intent、ContentProvider、WebView、网络响应、文件URI和深链都视为不可信输入。校验action、scheme、MIME、大小、授权与响应者；导出组件使用最小权限；日志、截图和测试数据库不得泄露令牌或个人数据。相机、音频、数据库、线程和回调注册必须在成功、异常与取消路径都释放。

性能以用户任务衡量：启动看可交互时刻，列表看掉帧与绑定分配，网络看超时和取消，后台工作看约束、电量与重复调度。每次比较固定设备温度、构建类型、数据规模和网络条件，先采基线再改变一个变量。

迁移现代目标SDK时，先在第4版语境中证明机制，再逐项处理组件导出、存储、通知、后台启动、权限、废弃API和依赖版本。每一步保存编译差异、行为差异、测试结果和回滚点；新API并不自动正确，旧API能编译也不代表仍符合平台政策。

<Answer>覆盖7个节点，从“14. The App Bar”到“Challenge: An Empty View for the RecyclerView”。主线是解释AppCompat应用栏、菜单资源、选择回调和Asset Studio在导航与动作层的边界，交付物是菜单状态表、图标资源、空列表视图与配置变化测试。</Answer>

**问题 2**：怎样建立本页最小可执行实验？
<Answer>固定JDK、SDK、Gradle、设备API、语言、权限和输入，完成一个从用户动作到可观察结果的垂直切片；保存干净构建、设备操作、原始日志、状态快照与断言。</Answer>

**问题 3**：为什么只在正常点击路径运行不能证明完成？
<Answer>它没有覆盖组件重建、进程死亡、异步取消、权限拒绝、外部输入失败、资源释放和版本变化。应逐项注入故障，并用菜单状态表、图标资源、空列表视图与配置变化测试核对。</Answer>

**问题 4**：怎样设计能推翻当前实现的反例？
<Answer>保持其他变量不变，分别注入旋转、后台回收、进程死亡、拒权、断网、无效输入与重复操作；任何状态丢失、越权、崩溃、泄漏或重复副作用都推翻完成结论。</Answer>

**问题 5**：从第4版语境迁移到现代目标SDK时如何控制变量？
<Answer>先按原书还原机制并锁定基线，再查询目标SDK合同；一次只迁移组件导出、存储、权限、后台、通知或依赖之一，保存构建、行为、测试和回滚差异。</Answer>

**问题 6**：本页达到独立交接标准需要什么？
<Answer>需要版本与设备指纹、源码提交、输入、构建命令、生命周期轨迹、原始日志、失败测试、安全边界与发布产物，让他人凭菜单状态表、图标资源、空列表视图与配置变化测试重放。</Answer>
