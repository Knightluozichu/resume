## 问题：为什么 Blender 操作经常在同一个快捷键下产生不同结果

先预测：鼠标停在 Outliner 上按同一个快捷键，是否必然和停在 3D Viewport 上结果相同？不会。Blender 的输入具有上下文，当前 Area 的 Editor、模式、选择和活动对象共同决定命令。本章不只教导航，而是建立界面状态模型，使后续建模和动画操作可以被准确复现。

## 窗口上下文、编辑器与模式

Window 包含 Screen，Screen 被 Areas 分割，每个 Area 承载一种 Editor；Workspace 保存面向任务的 Screen 布局。命令是否可用取决于鼠标所在 Editor、Object/Edit/Pose 等模式、选择集合和 Active Object。3D Cursor 是创建和变换枢轴，不是普通对象。Startup File 会影响每个新项目，必须把个人便利配置与项目依赖分开。

## 关键对象与数据流

建立一个四区布局，分别放 3D Viewport、Outliner、Properties 和 Timeline，记录鼠标上下文与模式。通过正交视图、Orbit、Pan、Zoom 和 Frame Selected 到达同一构图；再用框选、加选和 Active Object 颜色验证选择语义。最后保存偏好与 Startup File 前后对照，确认项目文件没有依赖隐藏的个人配置。

每次修改前先保存输入版本，修改后记录输出文件、统计和截图。最终画面正确但中间资产不符合预测，也不能立即签发，因为它可能依赖隐藏偏好、未保存图像、错误链接或偶然缓存。

## 从 Blender 2.83 LTS 到当前版本

第三版已经覆盖 Workspaces 与 2.8x 界面。当前版本的菜单和快捷键可能变化，但 Window、Area、Editor、Region、Mode、Selection 与 Active Object 的上下文模型稳定。Asset Browser 等新 Editor 可以加入布局，不改变本章基本结构。

## 小结

- Blender 输入依赖编辑器和模式上下文
- Area 承载 Editor，Workspace 组织任务布局
- 选择集合与 Active Object 语义不同
- Startup File 不能成为未记录的项目依赖
