## 问题：为什么看似相同的 Blender 操作会得到不同结果

先预测：鼠标停在 Outliner 上按同一个快捷键，是否必然和停在 3D Viewport 上结果相同？不会。Blender 的输入具有上下文，当前 Editor、Mode、Selection 和 Active Object 共同决定命令的作用对象。本章不只记按钮位置，而是建立一套能交接的界面状态模型，使后续建模、动画和渲染操作可以被准确复现。

本页依据 Pearson 第三版目录重写，不逐字复制原文。目录身份可在 [Pearson 书目页](https://www.pearson.com/en-gb/subject-catalog/p/learning-blender/P200000000666/9780136411758) 复核；当前软件行为与菜单位置应回到 [Blender 官方手册](https://docs.blender.org/manual/en/latest/) 和具体版本发布说明核对。

## Downloading and Installing Blender；Using Blender with Recommended Hardware

安装不是“下载完成”就结束。先写一份 **<Term>Window</Term> 基线**：Blender 版本与构建、操作系统、CPU、GPU、内存、显示器缩放、输入设备和启用的插件。硬件建议的意义是知道哪些功能会受显存、驱动或计算能力约束，而不是把一组推荐配置当成项目保证。

动手试：在目标机器安装一个固定版本，打开默认场景，保存到项目目录，再执行一次简单视口检查和低分辨率渲染。记录安装包来源、构建号、GPU 驱动和文件路径。若同一个 `.blend` 在另一台机器出现黑色纹理、视口卡顿或渲染差异，先比较环境基线与外部资产路径，不要把结果直接归因于“界面变了”。

## Using Blender's User Interface；Understanding Areas and Editors；Using Workspaces

Blender 的顶层 Window 可以包含工作屏幕；屏幕由多个 **<Term>Area</Term>** 组成，每个 Area 承载一个 **<Term>Editor</Term>**，而 **<Term>Workspace</Term>** 保存面向任务的布局。这个层级解释了为什么鼠标所在区域会改变快捷键的语义：输入先进入当前 Editor，再由 Mode、Selection 和 Active Object 决定可操作对象。

一个用于角色项目的起始布局可以同时放置 3D Viewport、Outliner、Properties 和 Timeline。不要只保存布局截图；还要记录每个 Area 的 Editor、鼠标焦点、当前 Mode 和当前活动对象。观察变化时，先切换 Workspace，再把同一条命令分别放到 Outliner 和 3D Viewport，比较提示、选择高亮和结果对象。

## Getting to Know Blender's Interface Elements；Understanding the 3D Viewport

3D Viewport 是观察、导航、选择和变换场景的主要 Editor。Header、工具栏、侧栏、视图导航控件和状态提示都是界面元素，但它们不等于场景数据。当前版本可能调整图标和入口，稳定的不变量仍是：Viewport 显示一个视图，Outliner 显示对象层级，Properties 修改上下文设置，文件保存项目状态。

把一个立方体、相机和灯光作为可核对的最小场景。先观察 Perspective，再切到 Front Orthographic 和 Camera View，检查对象是否只是改变了观察方式，而不是被修改了几何。若变换后看起来“消失”，先确认视图、隐藏状态、选择状态和 Frame Selected，再检查对象是否真的被移动。

## Navigating the 3D Scene；Selecting Objects；Understanding the 3D Cursor

导航改变观察者，不等于改变对象；Orbit、Pan、Zoom 和 Frame Selected 应留下可复现的视图记录。选择集合表示当前参与操作的对象，Active Object 则是其中承担主要上下文的对象；多选后若不记录 Active Object，后续父子关系、属性编辑和变换结果就无法交接。

**<Term>3D Cursor</Term>** 是创建新对象、对齐和设置变换枢轴的重要参考点，不是普通对象，也不会因为视图旋转而自动回到原点。先预测移动 Cursor 后添加对象的位置，再动手试；最后记录 Cursor 坐标、视图方向、Selection 和 Active Object。正常样本应在原点创建对象，边界样本应在非原点和正交视图下复核，故障样本则故意把 Cursor 放在远处，确认诊断步骤能找出偏差。

## Understanding Blender's User Preferences；Creating Your Own Startup File

**<Term>Preferences</Term>** 保存主题、输入设备、快捷键、插件和其他用户级偏好；**<Term>Startup File</Term>** 则定义新项目打开时的默认场景、布局和部分项目起点。个人偏好可以让作者操作更快，却不应该成为团队文件的隐藏依赖。保存 Startup File 前先清除测试对象、未打包外部资产和临时插件，再在 Factory Settings 下打开一个新项目做对照。

配置验收采用三份证据：偏好导出或截图、Startup File 的对象与布局清单、Factory Settings 的重放记录。若项目只有在个人 Startup File 下能运行，说明配置没有被显式记录；应把真正的项目依赖写进 `.blend`、版本账本或交接文档，而不是要求下一位读者复制作者的全部偏好。

<Callout type="trap" title="推荐硬件不是复现保证">
  现象：作者机器运行流畅，交接机器却出现视口卡顿或渲染差异。原因：只记录“推荐配置”，没有冻结 Blender 构建、驱动、GPU、插件和外部资产。修法：保留环境基线与低成本烟雾测试，先定位资源或版本差异，再讨论性能优化。
</Callout>

<Callout type="trap" title="Area、Editor 与 Workspace 不是同一个对象">
  现象：教程说“切换界面”时，读者找不到同一个按钮或快捷键作用错区域。原因：把布局容器、编辑器类型和任务工作区混为一谈。修法：记录 Window、Area、Editor、Workspace、Mode 和鼠标焦点，再描述操作入口。
</Callout>

<Callout type="trap" title="Preferences 不应偷偷变成项目依赖">
  现象：打开同一个文件，作者的快捷键和 Startup File 让结果看起来正确，其他人却无法重放。原因：个人偏好、外部插件或默认布局没有进入证据包。修法：用 Factory Settings 做对照，显式保存项目配置，并记录必须的插件、路径和版本。
</Callout>

## 从观察到可复现的界面记录

每次修改前先保存输入版本，修改后记录输出文件、视图、Selection、Active Object、Cursor 坐标、Mode 和配置来源。验收包至少包含：安装与硬件记录、Area/Editor 布局截图、三个标准视角、选择与 Active Object 对照、3D Cursor 坐标、偏好导出或截图，以及 Factory Settings 重放结果。

正常样本证明默认路径能工作；边界样本说明视图、硬件或非原点 Cursor 的适用范围；故障样本则故意改变一个上下文条件。若只看到最终画面正确，却无法说明鼠标焦点、模式或 Startup File 来源，不能立即签发，因为结果可能依赖隐藏状态。

## 小结

- 安装和硬件基线决定了 Blender 文件能否被稳定打开、保存和渲染。
- Window、Area、Editor、Workspace 与 Mode 共同构成输入上下文，不能混用名称。
- 3D Viewport 的导航改变观察方式；Selection、Active Object 和 3D Cursor 负责不同语义。
- Preferences 是用户级便利，Startup File 是默认起点；项目依赖必须显式记录并用 Factory Settings 对照。

## 练习与答案

<Exercises>

**问题 1：上下文诊断。** 同一个快捷键在 Outliner 和 3D Viewport 产生不同结果时，最小诊断记录应包含哪些字段？

<Answer>
  记录 Window、Area、Editor、鼠标焦点、Mode、Selection、Active Object、3D Cursor 坐标、Blender 版本与预期/实际结果。先保持文件和版本不变，只移动焦点做对照，才能判断差异来自输入上下文还是场景数据。
</Answer>

**问题 2：视图与对象。** 为什么从 Perspective 切到 Front Orthographic 不应被当成“修改了模型”？如何验证？

<Answer>
  视图切换改变观察投影，不直接修改几何。可保存对象变换、顶点或文件哈希作为输入证据，再比较视图设置；若模型看似消失，先用 Frame Selected、检查隐藏状态和 Selection，确认对象数据没有变化。
</Answer>

**问题 3：配置交接。** 一个文件只有在作者的 Startup File 下才能正确开始工作，你会如何修复？

<Answer>
  先在 Factory Settings 下重放并记录首个偏离信号，再区分个人 Preferences、Startup File、插件、外部路径和真正的 `.blend` 项目数据。把必要依赖显式写入文件或交接文档，保存配置快照并让另一位读者按同样步骤验证。
</Answer>

</Exercises>

<Glossary>
  <GlossaryItem term="Window">
    Blender 的顶层窗口容器；项目记录应包含窗口与显示环境，避免把系统显示差异误认为场景数据差异。
  </GlossaryItem>
  <GlossaryItem term="Area">
    Window 或 Screen 中承载一个 Editor 的布局区域；鼠标所在 Area 会影响输入上下文。
  </GlossaryItem>
  <GlossaryItem term="Editor">
    承担特定任务的界面类型，例如 3D Viewport、Outliner 或 Properties。
  </GlossaryItem>
  <GlossaryItem term="Workspace">
    面向任务保存 Screen 布局和编辑器组合的工作区；它不是单个 Editor。
  </GlossaryItem>
  <GlossaryItem term="3D Cursor">
    用于创建、对齐和设置变换枢轴的场景参考点；它不是普通对象，坐标应纳入验收记录。
  </GlossaryItem>
  <GlossaryItem term="Preferences">
    保存用户级主题、快捷键、输入设备和插件等偏好；必须和项目显式依赖区分。
  </GlossaryItem>
  <GlossaryItem term="Startup File">
    新项目打开时使用的默认场景与布局起点；发布前应在 Factory Settings 下对照重放。
  </GlossaryItem>
</Glossary>
