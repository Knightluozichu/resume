## 问题：为什么移动对象和移动网格顶点会产生不同的下游结果

先预测：在 Object Mode 把立方体缩放为两倍，与在 Edit Mode 把全部顶点缩放为两倍，视觉相同是否意味着数据相同？不相同。前者改变场景容器的变换，后者改变 Mesh Datablock 的局部数据。第三章用一个首个场景把对象、数据、变换、模式、修改器、材质、灯光、相机和渲染连接起来，并要求每次变化都有输入、预期、实际和恢复记录。

## Creating Objects；Moving, Rotating, and Scaling；Arranging Objects in Your Scene

创建一个立方体、一个平面、一盏灯和一台相机，先用明确前缀命名，再记录它们在 Outliner 中的层级。**<Term>Object</Term>** 是场景中的容器，保存位置、旋转、缩放、父子关系和可见性；它可以引用 Mesh、Camera 或 Light 等数据。移动、旋转和缩放 Object 会改变容器的变换，不等于把网格顶点永久改到相同位置。

动手试：先保存默认场景，再复制立方体，分别把副本放在左右两侧。记录每个对象的名称、位置、旋转、缩放和 Active Object。安排场景时让相机能看见主体、灯光有可比较的方向，最后再做一次 Frame Selected。正常样本应能从空场景复现；边界样本把对象移到相机外；故障样本则故意忘记保存变换记录，测试交接者能否找出第一个偏离信号。

## Naming Objects and Using Datablocks；Using Interaction Modes

**<Term>Datablock</Term>** 是 Blender 管理的可复用数据块，例如 Mesh、Material、Image、Camera 和 Light。两个 Object 可以引用同一个 Mesh；如果复制时保留链接，Edit Mode 中修改一个对象的网格可能让另一个对象同步变化。如果需要独立版本，必须显式创建独立数据副本，并在证据包中记录共享计数或复制方式。

**<Term>Interaction Mode</Term>** 决定当前输入落在哪里。Object Mode 更适合调整容器变换、层级和对象级属性；Edit Mode 进入 Mesh 的顶点、边和面；其他模式还可能把输入交给骨骼或姿态数据。不要用最终画面猜模式，应该在操作前记录 Mode、Selection、Active Object 和目标 Datablock，操作后比较变换字段与网格统计。

## Applying Flat or Smooth Surfaces；Working with Modifiers

Shade Flat 与 Shade Smooth 主要改变表面法线的显示方式，不应被解释为增加或减少真实面数。**<Term>Modifier Stack</Term>** 则把一组非破坏处理按顺序应用于求值几何；Bevel、Subdivision、Mirror 等修改器的顺序会改变边缘、面数和最终包围盒。保存一个原始网格和一个可重排的修改器栈，才能在出现形状差异时定位责任。

先预测，再只改变一个条件：同一个低面数立方体先 Bevel 后 Subdivision，与先 Subdivision 后 Bevel 是否给出相同边缘？通常不会。分别记录原始顶点数、修改器顺序、显示状态和求值后的截图。边界样本可以关闭某个 Modifier，故障样本则把顺序打乱，检查报告能否指出是输入数据、表面法线还是求值栈先发生变化。

## Using Workbench, EEVEE, and Cycles；Turning On the Lights

**<Term>Render Engine</Term>** 决定场景如何被转换为图像。Workbench 适合快速检查模型形状与布局，EEVEE 适合实时材质和灯光预览，Cycles 适合路径追踪质量对照；三者不是同一输出的简单速度档位。开启主光、补光和世界背景后，要同时记录引擎、采样或质量设置、分辨率、色彩管理和渲染时间。

创建一个可控的主光方向，先关闭主光观察场景是否失去层次，再恢复并固定灯光位置。不要把“视口看起来亮”当成渲染证据；视口显示、引擎设置和最终帧可能有不同的颜色与光照路径。使用同一个输入文件分别输出一帧 Workbench、EEVEE 和 Cycles，才能比较哪些差异属于引擎边界。

## Moving the Camera in Your Scene；Rendering

**<Term>Camera</Term>** 是最终帧的视点与裁切边界。移动相机时记录位置、旋转、焦距、分辨率和画幅比例；如果主体出了画面，先检查相机变换和裁切，不要先修改对象。渲染验收还要记录输出格式、颜色空间、文件路径和生成时间，避免只保留一张没有上下文的图片。

为同一场景建立 Hero Camera 和 Wide Camera 两份对照：前者突出主体，后者交代空间。先预测切换相机只会改变构图，再动手渲染并比较对象变换是否保持不变。正常样本保存一帧，边界样本把主体放到画面边缘，故障样本关闭主光或改用未记录的引擎；交接者应能凭日志判断差异来自 Camera、Light 还是 Render Engine。

<Callout type="trap" title="Object 变换不等于 Mesh 编辑">
  现象：两个看似相同大小的物体在后续修改器或导出中表现不同。原因：一个只改了 Object Transform，另一个改了 Mesh Datablock，或缩放没有应用。修法：记录 Mode、变换字段、顶点统计和 Datablock 共享关系，再决定是否应用变换或创建独立副本。
</Callout>

<Callout type="trap" title="修改器顺序不是视觉偏好">
  现象：Bevel 和 Subdivision 都打开，但边缘形状、面数或包围盒与预期不符。原因：Modifier Stack 的求值顺序改变了输入。修法：冻结原始网格，逐次交换一个修改器位置，分别保存顺序、统计和截图。
</Callout>

<Callout type="trap" title="视口亮不等于渲染可复现">
  现象：作者的视口画面正确，别人渲染却黑屏、构图不同或质量差异很大。原因：没有记录 Camera、Light、Render Engine、分辨率和颜色管理。修法：用同一输入文件输出固定的一帧，保存参数、路径、时间和预期/实际结果。
</Callout>

## 从空场景到可交接的一帧

建立最小证据包：对象与 Datablock 命名表、链接或独立副本记录、Object/Edit Mode 对照、Modifier Stack 顺序截图、三个引擎的固定分辨率输出、Camera 与 Light 参数、颜色管理、渲染时间和文件路径。每次修改前先保存输入版本，修改后记录输出文件、统计和截图。

验收分成正常、边界和故障三条路径。正常路径证明对象、灯光、相机和渲染能工作；边界路径说明相机裁切、引擎质量或共享数据的适用范围；故障路径故意关闭主光、交换修改器顺序或使用错误模式，证明诊断方法确实能找到首个偏离信号。最终画面正确但中间资产不符合预测，也不能立即签发，因为它可能依赖隐藏偏好、未保存数据或偶然缓存。

## 从 Blender 2.83 LTS 到当前版本

第三版使用 Workbench、EEVEE 与 Cycles，当前版本的名称、质量设置和界面入口可能演进。Object 与 Datablock 分离、模式语义、修改器顺序、相机和灯光的责任保持稳定；渲染引擎对照应按当前硬件重新测量。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。允许菜单、引擎选项和质量参数变化，不允许抹去原始问题、项目依赖或章节身份。

## 小结

- Object 保存场景容器状态，Datablock 保存可复用的网格、材质或灯光数据
- Interaction Mode 决定操作落在容器、网格或其他数据上
- Shade Flat/Smooth 与 Modifier Stack 分别提供表面显示和非破坏求值证据
- Camera、Light、Render Engine 与输出参数必须一起冻结，首帧才可复现

## 练习与答案

<Exercises>

**问题 1：复制关系。** 两个 Object 看起来相同，但 Edit Mode 修改一个后另一个也变化。请指出最可能的关系，并写出验证字段。

<Answer>
  最可能是两个 Object 共享同一个 Mesh Datablock。应检查对象名称、Mesh Datablock 名称或用户计数、当前 Interaction Mode、Selection 与 Active Object，再创建独立副本做对照。
</Answer>

**问题 2：修改器诊断。** Bevel 和 Subdivision 都存在，为什么仍不能只看最终图像判断配置正确？如何做最小对照？

<Answer>
  因为 Modifier Stack 顺序会改变求值几何，Shade Flat/Smooth 又可能只改变法线显示。保留同一个原始网格和表面设置，只交换一个修改器位置，记录顺序、面数、包围盒和截图，再恢复基线。
</Answer>

**问题 3：渲染交接。** 另一位读者说你的场景“打开正常但渲染全黑”，请列出优先检查顺序。

<Answer>
  先核对 Render Engine、活动 Camera、主光是否开启与可见、世界背景、分辨率和颜色管理，再比较对象材质与外部资源路径。使用同一个输入文件和固定参数重放，记录预期/实际结果、日志、输出路径与渲染时间。
</Answer>

</Exercises>

<Glossary>
  <GlossaryItem term="Object">
    场景中的容器，保存变换、层级和可见性，并引用一个或多个 Datablock。
  </GlossaryItem>
  <GlossaryItem term="Datablock">
    Blender 管理的可复用数据块，例如 Mesh、Material、Camera、Light 或 Image。
  </GlossaryItem>
  <GlossaryItem term="Interaction Mode">
    决定当前输入作用于对象容器、网格数据或其他特定数据的操作模式。
  </GlossaryItem>
  <GlossaryItem term="Modifier Stack">
    按顺序对输入几何进行非破坏求值的一组修改器；顺序会影响最终结果。
  </GlossaryItem>
  <GlossaryItem term="Render Engine">
    把场景、相机、灯光和材质转换为图像的计算路径，例如 Workbench、EEVEE 或 Cycles。
  </GlossaryItem>
  <GlossaryItem term="Camera">
    定义最终帧视点、裁切和构图的场景对象，位置、旋转、焦距和分辨率都应记录。
  </GlossaryItem>
</Glossary>
