## 问题：为什么移动对象和移动网格顶点会产生不同的下游结果

先预测：在 Object Mode 把立方体缩放为两倍，与在 Edit Mode 把全部顶点缩放为两倍，视觉相同是否意味着数据相同？不相同。前者改变 Object Transform，后者改变 Mesh Datablock。第三章用首个场景把对象、数据、变换、模式、修改器、材质、灯光、相机和渲染连接起来。

## Object 容器与 Datablock 数据

Object 保存场景变换、父子和可见性，并引用 Mesh、Camera、Light 或 Material Datablock。多个 Object 可共享同一个 Mesh，因此复制方式决定编辑是否联动。Object Mode 改容器变换，Edit Mode 改网格局部数据。Modifier 以可重排栈非破坏求值几何，Shade Smooth 改法线插值而非增加面。Workbench、EEVEE 和 Cycles 面向编辑、实时与路径追踪证据。

## 关键对象与数据流

创建三个对象并使用明确前缀命名，复制其中一个为共享 Mesh 实例，再分别在 Object/Edit Mode 修改以观察传播。添加 Bevel 与 Subdivision 并交换顺序，比较包围盒和面数。最后为相机、主光和材质建立最小场景，在 Workbench、EEVEE、Cycles 固定分辨率各输出一帧并记录时间。

每次修改前先保存输入版本，修改后记录输出文件、统计和截图。最终画面正确但中间资产不符合预测，也不能立即签发，因为它可能依赖隐藏偏好、未保存图像、错误链接或偶然缓存。

## 小结

- Object 与 Datablock 分离是 Blender 场景模型核心
- 模式决定操作落在容器还是数据
- 修改器顺序会改变最终几何
- 首次渲染必须固定相机、光照和输出参数

<Exercises>

**问题 1** 修改器为何有顺序？

<Answer>每个修改器读取前一项结果，同一参数在不同输入几何上结果不同。</Answer>

**问题 2** Workbench 最适合什么？

<Answer>快速编辑、检查形体和可视化，而非最终物理渲染。</Answer>

**问题 3** 渲染最少固定哪些参数？

<Answer>相机、引擎、分辨率、采样/质量、色彩管理、灯光和输出路径。</Answer>

</Exercises>
