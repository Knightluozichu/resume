## 问题：为什么漂亮概念图不一定是可建模参考图

先预测：一张透视夸张、姿势优美的单张概念图，能否直接约束眼睛、肩、髋和脚在三维中的位置？不能。第五章从角色描述和故事背景提取个性、风格和外表，用剪影与基型快速探索，再细化头部、服装和配色，最后制作正面与侧面比例一致的建模参考图。

## Character Description

角色描述回答“是谁、经历什么、怎样行动、为什么被观众记住”。先建立 **<Term>Character Brief</Term>**，把故事背景、年龄或体态、职业、性格、动作倾向、镜头距离和禁止事项写成可检查的输入。描述不应停留在“酷”或“可爱”，而要给出能影响形状、比例、服装、道具和姿势的证据。

例如“长期在狭窄空间维修设备、保持警觉”可以导出前倾重心、工具附件和清晰的观察方向；“保护同伴、承受冲击”可能导出宽肩、厚躯干和低重心。先保存三个关键词和一组反例，再进入画稿，避免之后的形状选择完全依赖个人偏好。

## Designing the Character

设计阶段把语义转成 **<Term>Shape Language</Term>**：用圆、方、三角、长短比例、重复节奏和不对称关系建立角色性格。先画许多黑色剪影，再用基型验证体块、重心和动作；**<Term>Silhouette</Term>** 是一种低成本的筛选证据，因为缩到最终镜头尺寸后，局部细节会消失，轮廓仍必须可读。

动手试：根据 Character Brief 画至少十二个小剪影，挑三案做简单基型。分别检查头、胸腔、髋、四肢和道具的主方向，记录每案的优点、风险和需要回到描述核对的地方。正常样本有一个可辨认方案；边界样本删去道具；故障样本把重心和动作方向故意冲突，验证选择标准能否拒绝它。

## Adding Color

配色不是给灰模涂一层漂亮颜色，而是建立远近、材质、情绪和视觉焦点。把颜色分成主色、辅色和强调色，使用 **<Term>Value Hierarchy</Term>** 检查明度关系：关闭颜色变成灰度后，角色的脸、躯干、服装和道具仍应有清晰的主次。颜色不能承担唯一识别线索，剪影和明度也要能工作。

先选择一个情绪方向，再限制调色板数量。Warm、Cool 或 Neutral 都可以成立，但必须说明它服务于什么故事和镜头。把方案缩到实际占屏尺寸，检查远景中的主色块和强调点；再用灰度、低对比背景和不同显示亮度复核，记录哪些颜色需要回退。

## Finalizing the Design

设计定稿不是“作者觉得满意”，而是能冻结输入并交给下游。建立 **<Term>Design Lock</Term>**：角色描述版本、入选剪影、基型比例、服装与道具清单、颜色层级、目标镜头、已知例外和下一个消费者都要有版本号。定稿后新的想法应进入变更记录，不能悄悄覆盖建模依据。

设计验收要同时问三个问题：缩略尺寸下是否仍能读出角色；灰度下主次是否成立；动作与重心是否支持故事。若一个方案只有正面站立图好看，侧面、行走或相机运动中却失去轮廓，就不是完成的设计。保存被淘汰的方案和淘汰理由，可以帮助团队在范围变化时快速恢复。

## Making Character Reference Images；Using Other Design Methods

**<Term>Orthographic Reference</Term>** 是给建模者使用的正交参考约束，不等同于透视概念插画。正面、侧面和必要的背面图应使用同一地面线、同一组水平辅助线和一致的身高单位；头顶、眼、肩、肘、髋、膝、踝和脚底要能够逐项对齐。记录图像版本、单位、裁切、透明度和导出路径，避免建模者猜比例。

其他设计方法可以包括纸笔、绘画软件、Grease Pencil、照片分析或生成式草图，但工具只负责探索和记录，不替代原创决策、版权来源、Character Brief 和 Design Lock。采用外部参考时记录来源、许可、修改范围和最终选择理由；采用生成式草图时保留人工重绘和形状语言判断，不能把不可追溯的图像直接当成生产蓝图。

正侧参考的验收应叠加同一组基准线，逐项记录像素偏差和遮挡关系。若胸腔深度、手掌朝向、服装厚度或头发与头部的关系仍需猜测，应回到设计阶段补充三视图或局部图，而不是把不确定性推给建模者。

<Callout type="trap" title="透视概念图不等于建模蓝图">
  现象：正面看起来漂亮，侧面建模却无法确定胸腔、髋部和脚的位置。原因：把透视、姿势和戏剧性构图误当成正交比例约束。修法：保留概念图用于叙事，再制作共享基准线的正面、侧面和必要背面参考。
</Callout>

<Callout type="trap" title="细节不能替代剪影">
  现象：角色画面塞满纹理、饰品和褶皱，缩小后却无法分辨身份。原因：没有先用 Silhouette 与 Shape Language 验证大形和重心。修法：先做黑色剪影和基型对照，缩到最终镜头尺寸后再决定哪些细节值得保留。
</Callout>

<Callout type="trap" title="颜色不能承担唯一识别责任">
  现象：彩色稿件能辨认，灰度、低亮度或远景中角色就失去层级。原因：没有验证 Value Hierarchy，把强调色当成轮廓和动作的替代物。修法：做缩略、灰度和低对比背景测试，补强形状、明度和动作方向。
</Callout>

## 从角色描述到建模交接

把设计资产整理成证据包：Character Brief、十二个剪影、三案比较、入选基型、颜色层级、缩略和灰度测试、Design Lock、正侧参考图、共用基准线、版本与来源记录。每次修改前保存输入版本，修改后记录输出图像、像素偏差、截图和验收结论。

验收分成正常、边界和故障三条路径。正常路径证明角色语义、形状、颜色和正侧比例互相支持；边界路径缩到远景、删掉道具或改变背景对比；故障路径故意制造参考错位、明度混乱或剪影不可读。另一位建模者应能只根据证据开始第 7 章，而不必猜身高单位、胸腔深度、道具朝向或颜色层级。

## 从 Blender 2.83 LTS 到当前版本

角色设计方法与 Blender 版本无关。Grease Pencil、外部绘画软件或生成式参考可以成为探索工具，但必须映射回角色描述、设计定稿和正侧参考，不应新增无法追踪来源的孤立资产。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。允许菜单、绘画工具和文件组织方式变化，不允许抹去角色 brief、形状语言、颜色层级、正交基线或版权责任。

## 小结

- Character Description 把故事和行为转成可检验的外形约束
- Designing the Character 先用 Shape Language、Silhouette 和基型筛选大形
- Adding Color 要通过 Value Hierarchy、缩略和灰度测试
- Finalizing the Design 与 Orthographic Reference 共同把创意变成可建模交付物

## 练习与答案

<Exercises>

**问题 1：剪影选择。** 三个角色方案都有精细服装，但缩小后只有一个仍能分辨。你会用哪些证据决定入选？

<Answer>
  先回到 Character Brief，比较每案的 Shape Language、Silhouette、重心、动作方向和最终镜头占屏；再用黑色剪影、缩略图和简单基型验证。细节数量不能抵消轮廓不可读或重心与故事冲突。
</Answer>

**问题 2：配色验收。** 彩色稿件辨识度很好，但灰度和低亮度背景下主次消失，如何修复？

<Answer>
  重新分配主色、辅色和强调色的明度，减少平均分布的高饱和颜色；用 Value Hierarchy 做灰度、缩略和低对比背景测试，并同步检查剪影和动作方向是否足以承担识别。
</Answer>

**问题 3：参考图交接。** 正面与侧面图的眼线和髋线不一致，建模者已经开始工作。你会如何处理？

<Answer>
  暂停建模交付，保存当前参考版本和已生成资产，回到 Orthographic Reference 校正共用地面线与关键水平线，记录头顶、眼、肩、髋、膝和脚底偏差。修正后重新发布 Design Lock，并让建模者按新版本重验收。
</Answer>

</Exercises>

<Glossary>
  <GlossaryItem term="Character Brief">
    记录角色故事、行为、外形约束、镜头和禁止事项的设计输入。
  </GlossaryItem>
  <GlossaryItem term="Shape Language">
    用几何形状、比例、节奏和不对称关系表达角色性格与功能的视觉系统。
  </GlossaryItem>
  <GlossaryItem term="Silhouette">
    去掉内部细节后仍可比较轮廓、重心和识别度的黑色剪影证据。
  </GlossaryItem>
  <GlossaryItem term="Value Hierarchy">
    在颜色被转成灰度时仍能保持角色主次和视觉焦点的明度层级。
  </GlossaryItem>
  <GlossaryItem term="Design Lock">
    冻结角色描述、形状、颜色、镜头、版本和下游消费者的可验收定稿记录。
  </GlossaryItem>
  <GlossaryItem term="Orthographic Reference">
    使用共同基准线和比例单位制作的正面、侧面或背面建模参考图。
  </GlossaryItem>
</Glossary>
