## 问题：为什么熟练建模不是记住快捷键，而是预测拓扑变化

先预测：对一圈边执行 Extrude、Inset、Bevel 或 Bridge，都会增加几何，但下游边流是否相同？完全不同。第六章建立选择和拓扑操作词汇，使第七章角色建模时每一步都能说明输入选择、生成元素、边流方向和可撤销边界。快捷键只是入口，真正需要交接的是网格状态和证据。

## Working with Vertices, Edges, and Faces

网格由 Vertex、Edge 和 Face 组成，三者不是同一层级的“点线面按钮”。Vertex 是位置锚点，Edge 连接两个顶点并携带边界与环流关系，Face 使用有序边界形成表面并依赖法线方向。Extrude、Inset、Bevel、Bridge 等工具读入不同元素后，生成的连接关系也不同。

每次操作前保存测试网格副本，记录顶点、边、面数量、边界数量和法线方向。一个视觉上相似的表面可能包含完全不同的边流；如果后续要 Loop Cut、Subdivision、UV 或变形，连接关系比当前截图更重要。先选择一个低多边形立方体做正常样本，再制造重复顶点、翻转法线和三角中断作为边界样本。

## Making Selections

**<Term>Selection Set</Term>** 是操作的显式输入，不能用“我大概选中了那一圈”替代。先区分 Vertex、Edge、Face 选择模式，再记录 Linked、Boundary、Loop、Ring、Similar、Random 等策略、Active Element、Mode 和视图方向。相同工具换一个选择集，可能从局部变换变成整片拓扑重连。

动手试：分别选择一圈 Edge、一个 Face 和一个 Boundary，截图高亮结果，再预测下一步 Extrude 或 Bevel 会影响哪些元素。若选择跨越不相连的区域，记录它们是否共享 Mesh、是否有隐藏元素，以及工具是否会跳过不兼容部分。选择证据应能让另一位读者在同一输入网格上重建，而不是只看到最终形状。

## Using Mesh Modeling Tools

用 **<Term>Topology Delta</Term>** 描述工具前后的变化：新增了哪些元素、删除了哪些元素、哪些边被重新连接、边界如何移动、法线是否改变。Extrude 复制并移动边界，Inset 在面内建立环，Loop Cut 沿四边面传播，Bridge 连接兼容的边环，Bevel 插入过渡段，Merge 或 Dissolve 改变元素身份。工具名称相近，不代表输出拓扑相同。

用 **<Term>Edge Flow</Term>** 检查面是否沿预期方向连续。角色模型需要围绕眼、嘴、肩和髋建立可变形环流；一个看似干净的局部补面，可能在下游产生极点、拉伸或无法环选的断点。每次只改变一个操作和一个参数，保存前后统计与截图，才能把差异归因给工具而不是隐藏上下文。

## Using Modeling Add-Ons

**<Term>Modeling Add-On</Term>** 可以把多步工具组合成一个入口，提供 LoopTools、F2 等额外菜单或操作，但它不会替你定义选择边界、拓扑目标和版本条件。启用插件时记录名称、版本、来源、依赖和偏好；在同一个测试网格上分别跑手工链和插件链，比较输出统计、法线、边界和故障行为。

插件输出必须能被下游使用。若插件让界面更快，却生成重叠点、非流形边或不可预测的面方向，速度优势不能抵消清理成本。把插件当成可替换实现：保留手工回退路径、输入副本和恢复步骤，避免项目文件依赖一台机器的隐藏配置。

## Using Other Useful Blender Options and Tools

网格工具还受法线显示、吸附、比例编辑、对称、X-Ray、隐藏状态、Transform Orientation 和撤销历史影响。启用这些选项前记录它们，因为同一个选择和同一个工具在不同上下文下会写入不同结果。**<Term>Non-Manifold</Term>** 几何、重复顶点、孤立元素、翻转法线和断裂面都应进入验收清单。

把拓扑检查做成固定步骤：检查重叠点和重复面，检查非流形边，检查法线方向，检查孤立或隐藏元素，再检查角色所需的环流和变形区域。先执行正常网格，再注入一项故障，观察检查工具是否能找到首个偏离信号。若只凭最终渲染判断，很多拓扑问题会被材质、灯光和视角掩盖。

<Callout type="trap" title="选择集不是操作后的附带信息">
  现象：同一个 Extrude 在不同文件中产生的面数和边界完全不同。原因：没有记录 Vertex、Edge、Face 模式、Linked/Boundary 策略、Active Element 和隐藏状态。修法：把 Selection Set 当成输入契约，执行前截图并写出预期影响范围。
</Callout>

<Callout type="trap" title="视觉相似不等于拓扑相同">
  现象：两个模型截图几乎一样，Loop Cut、Subdivision 或变形结果却明显不同。原因：忽略了 Topology Delta 和 Edge Flow，只比较了表面外观。修法：保存前后顶点、边、面、边界和法线统计，逐项核对新增、删除和重连关系。
</Callout>

<Callout type="trap" title="插件一步完成不等于免检">
  现象：插件生成的网格在作者电脑上看起来正确，交接后出现非流形边、法线翻转或版本错误。原因：把 Modeling Add-On 当成魔法，省略了版本、参数和故障样本。修法：保留手工回退路径，让插件输出通过相同的重叠点、法线、非流形和边流检查。
</Callout>

## 从选择到可交接拓扑

用同一个低多边形测试网格完成证据包：选择策略截图、至少十种操作前后拓扑统计、边流对照、法线与非流形检查、插件名称和版本、手工回退链、正常/边界/故障样本，以及每一步的预期和实际结果。每次修改前保存输入版本，修改后记录输出文件、参数、截图和恢复路径。

正常样本证明主路径可重放；边界样本测试多选、断开的边环、隐藏元素和高段数参数；故障样本注入重叠点、翻转法线、非流形边或三角中断。若工具输出无法说明哪一个信号先偏离，就不能把它交给第七章角色建模。

## 从 Blender 2.83 LTS 到当前版本

Blender 当前建模菜单、操作名称和插件内置状态可能变化。稳定不变量是选择集、拓扑变化、法线、边界、边流和验证步骤；迁移时记录操作搜索名、参数和版本，不把单一快捷键写成概念。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。允许菜单和工具变化，不允许抹去选择契约、拓扑审计、插件依赖或回退路径。

## 小结

- Vertex、Edge、Face 是不同层级的网格输入，Selection Set 必须显式记录
- Mesh Modeling Tools 的价值在于可解释的 Topology Delta 和 Edge Flow
- Modeling Add-On 只是可替换实现，不能替代版本记录与拓扑验收
- Non-Manifold、重复顶点、法线和隐藏状态都应进入交接证据

## 练习与答案

<Exercises>

**问题 1：选择诊断。** 对一圈边执行 Bevel 后影响范围超出预期，最先检查哪些输入？

<Answer>
  先检查当前 Mode、Edge 选择是否为预期的 Loop 或 Boundary、隐藏元素、Active Element、法线和段数参数，再保存选择截图与输入副本。不要先用撤销后的最终截图猜原因。
</Answer>

**问题 2：拓扑比较。** Extrude 和 Inset 都能让面看起来更复杂，如何证明它们不是同一种操作？

<Answer>
  对相同输入分别执行一次，记录顶点、边、面、边界、连接关系和法线的 Topology Delta。Extrude 复制并移动边界并产生侧面，Inset 在面内建立环；再检查 Edge Flow 是否满足后续 Loop 或变形需求。
</Answer>

**问题 3：插件交接。** 插件让一项建模工作只需一步，你仍要保留哪些证据？

<Answer>
  记录 Modeling Add-On 名称、版本、来源、参数、输入与输出文件、手工回退步骤，并让输出通过重叠点、法线、Non-Manifold、边界和 Edge Flow 检查。正常、边界和故障样本都通过后才能交接。
</Answer>

</Exercises>

<Glossary>
  <GlossaryItem term="Selection Set">
    当前明确选中的 Vertex、Edge 或 Face 集合，是网格操作的显式输入契约。
  </GlossaryItem>
  <GlossaryItem term="Topology Delta">
    一次工具操作前后新增、删除、重连元素以及边界和法线变化的记录。
  </GlossaryItem>
  <GlossaryItem term="Edge Flow">
    边沿着面和变形区域连续传播的方向与结构，影响环选、细分和角色变形。
  </GlossaryItem>
  <GlossaryItem term="Non-Manifold">
    不形成可预期实体表面的几何状态，例如边连接过多、边界异常或内部面。
  </GlossaryItem>
  <GlossaryItem term="Modeling Add-On">
    扩展 Blender 建模入口或组合操作的插件；它需要单独记录版本、依赖和回退路径。
  </GlossaryItem>
  <GlossaryItem term="Vertex">
    网格中的位置锚点；多个 Vertex 通过 Edge 连接并参与 Face 的边界。
  </GlossaryItem>
</Glossary>
