## 问题：为什么同一张 Base Color 不能让皮肤、布料和金属看起来相同又合理

先预测：三个区域的颜色接近，但 Roughness 和 Normal 都一样，灯光下能否稳定读出材质差异？很难。颜色只是输入的一部分；表面如何反射、散射和响应视角，还取决于材质参数、遮罩、通道解释以及测试时的灯光基线。

本章要解决的是“图像数据如何变成表面行为”。没有材质和 Shader 的责任边界，纹理绘制只能停留在颜色贴图；没有固定 Render Test，任何调整都可能被一盏更讨喜的灯光掩盖，无法证明改动本身有效。

## Understanding Materials

**<Term>Material</Term>** 是把表面目标、纹理输入和节点关系组织在一起的资产；**<Term>Shader</Term>** 则根据几何、视角、光照和这些参数计算最终的表面响应。图像只是数据来源，不会单独决定“像不像金属”；同一张颜色图接入不同的 Roughness、Normal 和遮罩，结果可能完全不同。

在 Blender 中，可以把角色材质拆成三层责任：纹理负责提供局部数据，节点负责转换与混合，Shader 负责在灯光下产生响应。**<Term>Principled BSDF</Term>** 把常见的 Base Color、Roughness、Metallic、Normal 等输入放在一个可观察的表面模型里，便于逐项改变并记录结果。先用中性灰背景、固定相机和三点参考灯建立基线，再判断某个参数是否真的解释了画面。

皮肤需要较柔和且有局部变化的高光，布料通常更分散、更受织物方向影响，金属则依赖清晰反射和边缘状态。这里的区别不是给三种材质贴三个标签，而是让每一项参数都能对应到一个可观察的光照现象。

## Masks and Layers

**<Term>Mask</Term>** 是一个控制“某层影响哪里、影响多少”的灰度输入，通常把 0 理解为不影响、1 理解为完全影响，中间值则形成过渡。Masks and Layers 的价值在于把边缘磨损、服装接缝、面部色差等局部变化限制在应该出现的位置，而不必复制整套材质。

先建立稳定的基础层，再用 Mask 混合第二层颜色、粗糙度或法线。检查 Mask 时不要只看最终渲染：单独显示灰度、反转一次、放大边界，确认它没有越过 UV 接缝或污染相邻部件。一个好的层结构能回答“哪个区域被修改、修改了哪个通道、为什么在这里修改”。

### 层混合的可追踪顺序

1. 为区域命名并保存未经修改的基础层。
2. 单独显示 Mask，确认灰度范围与边缘过渡。
3. 只把一层变化接入一个 Channel，记录预期的表面现象。
4. 在固定灯光下比较接入前后，保留输入、节点和渲染截图。

## Channels

**<Term>Channel</Term>** 是一张图像或一个节点输出所承载的具体信息通道。Base Color 的数值通常按颜色空间解释；Roughness、Metallic、Normal 和 Mask 更接近供节点计算的数值数据，应按 Non-Color 语义读取。若把数据图当成颜色显示，或把颜色图当成线性数据使用，数值会在进入 Shader 前就发生错误。

把每个通道视为一份有契约的输入：它有名称、用途、色彩空间、范围和下游节点。逐通道启停时，Base Color 应主要改变颜色，Roughness 应主要改变高光宽度，Normal 应主要改变微表面方向；若三个输入都同时改变，诊断就失去基准。对外部纹理使用与第九章一致的 Texture Set 命名，避免文件名和节点语义漂移。

## Shading Your Character

为 Jim 着色时，先建立皮肤、布料、金属、眼球和头发的材质清单，再为每种材质写下 Base Color、Roughness、Normal 和可选 Mask 的目标。先在中性光照下让材质分区成立，再加入细节和局部变化；不要用过强的美术灯光把错误的粗糙度或法线“照得好看”。

皮肤的颜色变化应该服从面部体积和镜头距离，布料要让褶皱、织物方向和接缝有可读的反射差异，金属则要用清晰高光和边缘磨损说明它的反射能力。每次只改一个输入，记录参数、预期现象和实际现象；如果整个角色同时变亮或变暗，先查颜色空间、曝光和灯光，而不是立刻重画纹理。

### 正常、边界与故障材质

正常样本是三种材质在同一灯光下有稳定差异；边界样本把 Roughness 推到极高或极低、降低贴图分辨率，观察适用范围；故障样本反转 Normal、把 Roughness 当 sRGB 或断开 Mask，确认 Render Test 能把错误指向具体输入。

## Running Render Tests

**<Term>Render Test</Term>** 是一组锁定相机、曝光、世界背景和参考灯的对照渲染，用来验证一个输入变化是否带来预期表面现象。至少保留近景、中景和轮廓角度：近景检查法线与高光宽度，中景检查材质分区，轮廓角度检查反射强弱和形体边界。EEVEE 与 Cycles 可以分别运行，但必须记录渲染器差异，不要把差异误判成贴图错误。

测试矩阵应包含输入版本、改动通道、预期、实际、截图和下一步。先渲染基线，再只关闭 Base Color、Roughness、Normal 或区域 Mask 中的一项，最后运行修改后的版本。若只有换灯后结果才成立，就说明结论依赖隐藏条件；若固定基线下仍能观察到对应变化，才算完成材质验收。

<Callout type="trap" title="颜色一样不代表材质一样">
  现象：皮肤、布料和金属都贴了正确颜色，画面却像同一种塑料。原因：Roughness、Normal 和反射响应没有按材质目标区分。修法：在固定灯光下逐通道修改，记录高光宽度、反射强度和表面尺度，再回到材质清单复核。
</Callout>

<Callout type="trap" title="Mask 看起来正确但层混合方向反了">
  现象：磨损或接缝出现在相反区域，或者边界突然变硬。原因：灰度方向、反转设置或 UV 边界没有被单独检查。修法：先显示 Mask 灰度，再测试反转和边界过渡，确认 Layer 只写入预期 Channel。
</Callout>

<Callout type="trap" title="渲染器换了就以为材质坏了">
  现象：EEVEE 与 Cycles 的高光宽度或阴影不同，作者直接重画纹理。原因：灯光、曝光、采样和渲染器语义没有分开记录。修法：保留同一节点语义的双渲染对照，先锁定基线，再区分输入错误与渲染器不可等价项。
</Callout>

## 验收证据：把外观变成可复现的判断

交付包至少包含：材质清单、节点图、每张图的色彩空间、Mask 灰度图、逐通道启停截图、Principled BSDF 参数、固定灯光与曝光、近景/中景/轮廓 Render Test、EEVEE/Cycles 对照以及故障样本的诊断结论。每一项证据都要带输入版本、预期现象和实际现象。

材质签收不能只看最终美术灯光。先用中性世界、固定相机和三盏参考灯确认皮肤、布料、金属和眼球在同一条件下的高光宽度、反射强度和表面细节；然后分别断开 Base Color、Roughness、Normal 与区域 Mask，保存逐通道结果。最后把 Base Color 误设为 Non-Color、把 Roughness 误设为 sRGB、反转法线 Y 通道并断开 Mask，确认故障图与修法一一对应。

## 从 Blender 2.83 LTS 到当前版本

第三版的 Material、Masks、Channels、Principled 思路和受控 Render Test 仍然稳定；当前版本可能改变 Principled BSDF 输入名称、颜色管理、EEVEE/Cycles 行为和节点界面布局。迁移时保留参数语义、通道色彩空间、Mask 边界、灯光基线和证据矩阵，不把节点插槽顺序或菜单位置当成知识本身。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。若项目引入额外层、UDIM 或外部烘焙工具，也要说明它如何回到材质节点、目标通道和固定 Render Test，而不是只记录工具名称。

## 小结

- Material 组织输入，Shader 在光照下产生表面响应
- Mask 决定区域，Channel 决定数据的具体语义
- 皮肤、布料和金属要用可解释的参数差异区分
- Render Test 必须锁定灯光、曝光、相机和改动通道

## 练习与答案

<Exercises>

**问题 1：材质诊断。** 皮肤和金属使用同一张 Base Color，渲染时高光也几乎一样。你会先检查哪些输入？请把预期的修复证据写出来。

<Answer>
  先在固定灯光下分别检查 Roughness、Metallic、Normal 和颜色空间，再逐个断开输入确认影响范围。修复证据应包含两种材质的参数表、近景与轮廓 Render Test，以及高光宽度、反射强度和表面细节的前后对照。
</Answer>

**问题 2：修改实验。** 在 `Bl3Ch10MaskChannelsLab` 中把“服装接缝”从 Roughness 切换到 Base Color，再反转 Mask。请描述两个变化分别改变了什么，以及如何确认没有写错区域。

<Answer>
  切换到 Base Color 会让接缝改变颜色分区，而不是只改变高光宽度；反转 Mask 会把层移到原先未选中的区域。先单独查看灰度 Mask，再在 UV 边界和最终角色上比较，最后记录输入通道与边界截图。
</Answer>

**问题 3：渲染测试设计。** 你发现 Cycles 中的布料比 EEVEE 更亮，如何判断是渲染器差异、灯光差异还是材质节点错误？

<Answer>
  先锁定同一相机、世界、三点灯、曝光、颜色管理和节点版本，分别输出两个渲染器的基线图；再只改变一个材质输入并比较同一视角。如果基线就有差异，记录为渲染器不可等价项；如果只有改动后异常，继续检查通道、颜色空间和节点连接。
</Answer>
