## 问题：为什么功能地图不是功能清单

先预测：学完角色主项目后，同时开启流体、布料、雕刻、视频剪辑和 Python 五条路线，是否最高效？通常不是。扩展功能的价值取决于它是否解决当前项目瓶颈、是否有可控输入、是否能保存中间状态、是否能进入既有资产谱系。知道按钮名称不等于拥有生产能力。

本章把末章当作能力地图，而不是第二个主项目。每条路线都沿着“问题 → 输入 → 工具 → 输出 → 证据”检查；先做一个固定资产的最小实验，再比较手工基线、质量、时间、缓存和失败恢复。实验结论可以是暂不采用，这同样是合格的工程判断。

## Simulations；2D Animation

**<Term>Simulation</Term>** 把时间、力、约束或碰撞转化为可缓存的状态序列。它适合布料、流体、刚体等真实时间演化，但输入场景、时间步、碰撞体、缓存路径和版本都必须固定；只保存最终帧，无法诊断中途爆炸、穿透或缓存失效。**<Term>2D Animation</Term>** 则把笔画、帧和二维图层组织成可编辑的动画资产，适合手绘标注、二维角色或三维镜头中的混合媒介。

两条路线的共同验收问题是：输入是否明确、时间轴是否可重放、缓存是否可清除重建、输出是否能交给合成或动画阶段。正常样本记录稳定运动或稳定笔画，边界样本减少碰撞体或改变帧率，失败样本删除缓存、改变尺度或加入自交，确认读者能从错误信号回到参数，而不是只看一张截图。

## VFX: Masking, Object Tracking, and Video Stabilization；Video Editing

VFX 路线把真实镜头变成可分析、可修改的时间序列。**<Term>Mask</Term>** 限定效果作用区域，边缘、羽化、跟踪和遮挡顺序要在多帧中保持稳定；**<Term>Object Tracking</Term>** 让二维特征或物体运动成为约束，轨迹的粘附、持续帧数和漂移比标记数量更重要。**<Term>Video Stabilization</Term>** 可以减少不需要的抖动，但会改变裁切、尺度和边界，不能把错误追踪伪装成正确镜头。

**<Term>Video Editing</Term>** 负责把镜头、音频、转场和输出时间线交给可审查的剪辑结构。正常样本保存原始素材、轨迹、遮罩和时间线，边界样本覆盖运动模糊、遮挡和极端裁切，失败样本故意让 Mask 滑动或稳定化过度。通过前先检查源帧率、代理媒体、时间线范围、色彩管理和导出格式，避免把播放流畅误判为镜头正确。

<Callout type="trap" title="把稳定化当成追踪修复">
  现象：画面看起来不抖了，但合成物体仍然漂移或边缘跳动。原因：Video Stabilization 改善相机观感，不会修复错误的 Object Tracking 或 Mask。修法：先查看轨迹粘附和遮罩边缘，再决定是否稳定化，并记录裁切、尺度和输出时间线。
</Callout>

## Sculpting；Retopology；Maps Baking

**<Term>Sculpting</Term>** 适合探索高模形体和局部细节，输出通常是高分辨率几何；**<Term>Retopology</Term>** 重新组织面流、密度和变形边界，让低模能被绑定、动画和实时渲染消费。高模漂亮但没有可用低模，不是完整资产。面流应围绕关节、轮廓、褶皱和 UV 接缝做决定，并保存参考高模与版本。

**<Term>Maps Baking</Term>** 把高模的法线、AO 或其他信息投射到低模的 UV 图像上。烘焙前固定高低模对应关系、法线方向、Cage、UV、贴图分辨率和色彩空间；烘焙后检查接缝、投射丢失、反向面和低模材质是否真的读取贴图。正常样本证明细节迁移，边界样本减少 Cage 或改变 UV，失败样本使用重叠岛或错误法线，让问题能被定位。

## Add-Ons；Python Scripting

**<Term>Add-on</Term>** 是可安装的功能集合，适合已有稳定工作流的扩展，但要记录 Blender 版本、插件版本、启用状态、许可证和卸载/回滚方式。**<Term>Python Scripting</Term>** 适合重复且规则明确的 Datablock、命名、导出或检查任务；它不应在规则含糊、输入选择不明或没有撤销路径时直接批量改写生产文件。

自动化的最小合同包括：输入范围、规则、预期输出、异常处理、日志、版本和回滚。正常样本执行少量对象并逐项比对，边界样本包含缺失属性、重复命名或空选择，失败样本中断执行并验证原文件仍可恢复。只有当收益可量化、输出能接入现有资产谱系，才把手工流程升级为 Add-on 或 Python Scripting。

<Bl3Ch15AutomationLab />

<Callout type="trap" title="把高模截图当成可交付资产">
  现象：Sculpting 结果很好看，但绑定、动画或实时材质接不住。原因：没有完成 Retopology、UV 和 Maps Baking 的接口验证。修法：保存高模、低模、面流、UV、Cage、贴图和法线设置，用下游材质或动画测试确认交接。
</Callout>

<Callout type="trap" title="没有规则和回滚就批量执行脚本">
  现象：一次批处理改坏了名称、链接或输出路径，无法恢复原状态。原因：输入选择、规则、API 版本和异常处理没有被固定，也没有手工基线和日志。修法：先用小样本运行，保存版本和日志，提供撤销/回滚，再扩大批次。
</Callout>

## 决策矩阵与验收证据

至少用一张决策矩阵比较候选路线的问题、输入、输出、学习成本、计算成本、缓存、失败恢复和进入现有管线的接口。服装次级运动可以候选布料 Simulation，但必须说明碰撞体、时间步和缓存；高模细节可以比较 Sculpting、Retopology 与 Maps Baking，但必须证明低模的 UV 和法线能接收结果；批量命名可以候选 Python Scripting，却要先确认命名规则稳定并提供撤销。

交付证据至少包含：输入文件路径、Datablock 名称、Blender 与插件/API 版本、参数、复现步骤、预期结果、实际结果、耗时、缓存位置、正常/边界/失败样本和恢复步骤。另一位读者应能重放最小实验并知道为什么采用、延后或拒绝某条路线。扩展功能越强，越不能省略中间资产和失败记录。

## 从 Blender 2.83 LTS 到当前版本

模拟后端、Grease Pencil、VFX、EEVEE、插件 API 和资产系统变化较快；迁移时保留问题分类、输入输出不变量、缓存与回滚证据，具体工具按当前官方文档复核。菜单和工具可以变化，但不能抹去原始问题、项目依赖或章节身份。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。若插件 API 或模拟后端变化，记录版本差异和重新验证的样本；若脚本依赖 Datablock 名称或属性，先做小批量回归，再允许它修改生产资产。

## 小结

- 用项目瓶颈选择扩展路线，而不是把功能名称当作学习计划
- Simulation、VFX、雕刻/烘焙和自动化都必须明确输入、输出、成本与恢复
- 高模、轨迹、缓存和脚本日志是可交付资产的一部分
- 最小实验可以得出“暂不采用”，但不能跳过证据和失败样本

## 练习与答案

<Exercises>

**问题 1：路线选择。** 服装在走路循环中发生穿透，但当前项目还没有稳定的缓存和碰撞体。你会如何决定是否立即使用 Simulation？

<Answer>
  先固定一件服装、一个角色动作和碰撞体，记录时间步、缓存路径、计算时间与穿透指标，再与手工修正基线比较。若输入尺度、碰撞和缓存都不可复现，应先修复资产接口；只有最小实验能稳定重放，Simulation 才值得进入生产管线。
</Answer>

**问题 2：资产交接。** Sculpting 后的高模细节无法在低模材质中出现，请列出排查顺序。

<Answer>
  先确认 Retopology 的高低模对应关系和面法线，再检查低模 UV、Cage、投射方向、贴图分辨率和色彩空间，随后查看 Maps Baking 是否产生接缝或丢失区域。最后确认材质节点读取了正确的法线/AO 贴图，并用同一低模做下游动画或渲染测试。
</Answer>

**问题 3：自动化验收。** 一个 Python Scripting 脚本能批量重命名对象，但项目中存在重复名和链接对象。你会批准它直接运行吗？

<Answer>
  不批准直接批量运行。先定义输入选择和命名规则，用副本和小批量覆盖重复名、链接对象、空选择等边界，保存手工基线、API 版本、日志和回滚路径。只有异常可报告、结果可复核且原资产可恢复时，才扩大批次。
</Answer>

</Exercises>
