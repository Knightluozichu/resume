## 问题：为什么末章列出大量功能却不等于每项都应立即深入

先预测：学完角色主项目后，同时开启流体、布料、雕刻、视频剪辑和 Python 五条路线，是否最高效？通常不是。第十五章是一张能力地图：Simulations、2D Animation、VFX、Video Editing、Sculpting、Retopology、Maps Baking、Add-ons 与 Python Scripting 各解决不同问题，应从真实项目瓶颈选择下一条路线。

## 问题类型到扩展模块

物理时间演化选择 Simulation，手绘和混合媒介选择 2D Animation，遮罩/物体追踪/稳像属于 VFX，镜头编排属于 Video Editing；高频形体探索用 Sculpting，生产拓扑重建用 Retopology，高模信息转低模用 Baking；重复且规则明确的操作再考虑 Add-on 或 Python。每条路线都应定义输入资产、计算成本、缓存和交付物。

## 关键对象与数据流

从 Jim 项目复盘中选一个真实瓶颈，例如服装次级运动、面部二维标注、高模细节、批量命名或渲染检查。为候选模块写最小实验，固定输入并比较手工基线、质量、时间、缓存和失败恢复。只有收益可量化且输出能进入既有资产谱系，才把新模块纳入生产管线。

每次修改前先保存输入版本，修改后记录输出文件、统计和截图。最终画面正确但中间资产不符合预测，也不能立即签发，因为它可能依赖隐藏偏好、未保存图像、错误链接或偶然缓存。

## 三步可重复实验

动手前先预测：只改变当前步骤的一项输入后，哪个对象、拓扑、像素、骨骼、轨迹或渲染结果应最先变化？实验期间固定 Blender 版本、插件、资产版本、相机和输出设置。

## 正常、边界与失败样本

本章至少保存一个正常样本、一个极端边界和一个故意破坏配置。正常样本证明主路径，边界样本说明适用范围，失败样本证明诊断方法确实能抓到错误。

<Callout type="trap">
  **因果陷阱**：把功能清单当学习计划会造成浅尝辄止，且无法判断新技能是否解决项目问题。
</Callout>

<Callout type="trap">
  **版本陷阱**：在流程仍频繁变化时过早自动化，会把错误假设固化到大量资产。
</Callout>

## 从 Blender 2.83 LTS 到当前版本

末章功能变化最快，特别是模拟后端、Grease Pencil、EEVEE、插件 API 和资产系统。只保留问题分类与输入输出不变量，具体工具按当前官方文档验证。Python 脚本必须记录 Blender API 版本和回滚方式。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。允许菜单和工具变化，不允许抹去原始问题、项目依赖或章节身份。

## 验收证据

验收为至少三条候选路线建立决策矩阵，并完成一项最小实验，包含输入、参数、耗时、质量、缓存、失败恢复和产物。能解释为什么其余路线暂不进入当前管线。

证据包同时记录文件路径、Datablock 名称、版本、参数、复现步骤、预期和实际结果。交给另一位读者后不需要猜隐藏状态即可重放，才算掌握而不只是看过。

决策矩阵至少比较问题、输入、输出、学习成本、计算成本、缓存、失败恢复和进入现有管线的接口。比如服装摆动可选择布料模拟，但必须说明碰撞体、时间步和缓存；高模细节可选择 Sculpt、Retopology 与 Baking，但必须证明低模法线和 UV 能接收结果；批量命名可选择 Python，却要先确认命名规则稳定并提供撤销。每项候选只做一个固定资产的小实验，保存手工基线和新流程的耗时、质量与故障记录。收益不能量化或输出无法进入 Jim 资产谱系时，结论应是暂不采用，而不是继续堆功能。

## 小结

- 末章是继续学习地图而非新主项目
- 扩展模块应由真实瓶颈驱动
- 最小实验先验证输入、成本和输出
- 自动化只适合稳定、重复且可验证的流程
