## 问题：怎样证明复刻的是完整角色生产流程，而不是十几个独立 Blender 教程

先预测：最终视频能播放，是否足以签发全书？不能。综合验收要从最终序列反查 Camera Solve、Lighting、Composite、Action、Rig、Material、Texture、UV、Mesh、Reference 和 Character Brief；每一项都需要版本、检查和失败样本。只有删除任一阶段会让后续证据链明确断裂，才算十五章真正连接。

本页不是第十六个制作功能，而是一扇发布闸门。它把全书交付物组织成“输入资产 → 阶段门 → 可消费输出 → 回归断言 → 证据包”的链路，要求另一位读者在干净环境中复现关键结果。最终像素可以漂亮，但如果中间图像未保存、链接对象被误改、Track 漂移或色彩管理未锁定，就不能签发。

## 原书边界与全书覆盖

本页只覆盖 Pearson 第三版目录对应的角色项目与延伸路径，不用现代功能清单替换作者的学习顺序：Chapters 1–3 负责 Blender 身份、界面和第一场景；Chapters 4–5 负责项目概览与角色设计；Chapters 6–7 负责建模工具和 Jim 网格；Chapters 8–10 负责 UV、纹理、材质和着色器；Chapters 11–12 负责 Rig 与角色动画；Chapters 13–14 负责 Camera Tracking、Lighting、Compositing 和 Rendering；Chapter 15 负责基于证据的下一条学习路线。

这些章节按原书边界唯一归属。本站重新组织解释、实验和证据，不逐字复制原文；导读、总复习和现代迁移不重复计算原章节覆盖。综合页的责任是检查连接、回归和签发，不替代任何一章的操作教学。

## 十五章交付物依赖图与失败回放

把每章抽象成输入、变换、输出和断言：环境身份保证文件可重放，界面上下文保证步骤无歧义，计划与设计约束模型，拓扑约束 UV 与 Rig，纹理和材质约束光照，Rig 约束 Action，Camera Solve 约束实景几何，Compositing 约束最终像素。**<Term>Asset Lineage</Term>** 记录这些对象从哪里来、由谁修改、被谁消费以及当前版本。

为每条链设置 **<Term>Checkpoint</Term>**：灰模、材质、Rig Pose、Walk Cycle、Tracking Proxy 和最终 Composite 都必须有输入版本、输出文件、检查断言和截图。失败回放分别破坏版本、参考比例、非流形、UV 密度、图像保存、权重、循环、Track 和灯光方向，验证系统能在最早阶段停下，而不是等到最后一帧才说“不像”。

## 正常、边界与失败样本

**<Term>Regression Scene</Term>** 是固定输入和断言的回归场景，用来比较当前实现是否仍满足过去的关键行为。正常样本证明主路径；边界样本说明适用范围，例如极端比例、低清纹理、高对比灯光、短轨迹或错误尺度；失败样本故意破坏配置，证明诊断方法能抓到错误。每种样本都记录预期与实际，不用“看起来差不多”替代断言。

**<Term>Failure Replay</Term>** 是可重放的故障记录：保存触发条件、最早异常信号、涉及文件和恢复步骤。它不能只是一张红色截图；需要知道是哪个 Datablock、图像、骨骼、Action、Track 或 Render Pass 先偏离。正常、边界和失败三类样本一起，才能说明发布包既能工作，也知道什么时候不该工作。

<Callout type="trap" title="把最终视频能播放当成全书通过">
  现象：序列能播放，但中间资产没有版本、图像未保存或某帧依赖偶然缓存。原因：只验收链末像素，没有逐阶段 Checkpoint 和 Asset Lineage。修法：从灰模、材质、Rig Pose、Walk Cycle、Tracking Proxy 到 Composite 逐项反查输入、输出和断言。
</Callout>

## 全书回归与发布闸门

全书回归先检查覆盖、题目、导航、链接和 MDX，再打开干净环境中的发布包，执行固定相机、灰模、材质、动作、Tracking Proxy 和最终 Composite 场景。记录 Blender 版本、外部资产、Datablock、插件/API、色彩管理、输出格式和执行时间。任何失败都应回到对应章节，而不是直接修改最终图像让门禁变绿。

**<Term>Release Package</Term>** 是可签发的源文件、外部资产、证据、回归场景和最终输出集合；**<Term>Migration Ledger</Term>** 则记录 Blender 2.83 LTS 历史基线、当前实现、稳定不变量、不可等价处和证据。发布前还要校验文件路径、序列完整性、图像格式、帧范围、颜色和校验值，保证另一位读者能重建同一判断。

签发闸门至少包括：15/15 原章覆盖、每个章节达到发布分数、题目与答案完整、导航准确、定向与全库 MDX 无错误、正常/边界/失败回放均有证据。门禁通过不等于所有像素跨版本相同，而是每个差异都有解释、版本和可接受范围。

<Callout type="trap" title="用迁移后的默认值掩盖不可复现差异">
  现象：当前 Blender 中最终图能看，但旧版项目无法按记录重建，或某个插件默认值改变后结果悄悄漂移。原因：没有 Migration Ledger，也没有锁定版本、色彩管理、节点和 API。修法：记录稳定不变量与不可等价处，用固定 Regression Scene 重跑并保留差异证据。
</Callout>

## 验收证据：一份可以交给审查人的发布包

发布包至少包含：环境身份、项目源文件、外部资产清单、Datablock 和链接关系、设计参考、Mesh/UV/Texture/Material、Rig/Action、Camera Solve、Lighting/Compositing、Render Pass、Preview/Final 对照、Regression Scene、Failure Replay、题目答案、导航检查、MDX 错误报告、Migration Ledger 和输出校验值。每项都标出版本、路径、预期、实际和责任阶段。

交给另一位读者后，不应需要猜隐藏状态才能重放。正常样本证明主路径稳定，边界样本说明适用范围，失败样本证明检测确实有效；如果只剩最终 PNG，没有源、证据和失败恢复，综合验收应拒绝签发。修复时先回到最早根因，再重新执行后续阶段，避免把错误烘焙进最终合成。

## 从 Blender 2.83 LTS 到当前版本

最终迁移账本以 Blender 2.83 LTS 第三版为历史基线，逐项记录当前界面、节点、库覆写、EEVEE、骨骼集合和 API 差异。稳定目标是可设计、可建模、可着色、可绑定、可动画、可跟踪和可合成，不要求像素级复制旧界面；要求差异能够被解释、复测和归档。

迁移账本采用五列：原书载体、稳定不变量、当前实现、不可等价处、证据。允许菜单和工具变化，不允许抹去原始问题、项目依赖或章节身份。每次升级先在固定回归场景中验证，再更新发布包的版本与校验记录。

## 小结

- 完整复刻由 Asset Lineage 和 Checkpoint 证明，而不是由页面数量证明
- 最终像素必须能反查到十五章源资产、参数和失败断言
- Regression Scene 与 Failure Replay 证明检查真正有效
- Release Package 同时包含源、证据、输出和 Migration Ledger

## 练习与答案

<Exercises>

**问题 1：依赖追溯。** 最终 Composite 画面在中段漂移，但单帧看起来正确。请写出从最终像素向前排查的顺序。

<Answer>
  先固定帧号和输出设置，检查 Camera Solve 的 Track 与 Ground/Scale，再检查相机是否消费了正确的 Asset Lineage；随后回看灯光、Render Pass、Compositing 节点和 Mask，最后核对材质、UV、Mesh、Rig/Action 是否来自正确版本。每一步都保存最早异常信号和复现帧，不能先调最终合成遮住漂移。
</Answer>

**问题 2：失败回放。** 如何设计一个能证明“未保存图像”会被发现的 Regression Scene？

<Answer>
  用固定材质和相机引用一张外部图像，保存正常源文件并记录预期颜色；复制源文件后故意删除或改名图像，再在干净环境打开并执行渲染。记录缺失链接、实际颜色、错误提示和恢复步骤，确认回归能在材质/图像阶段失败，而不是等最终视频才发现。
</Answer>

**问题 3：发布签发。** Candidate 已通过主要回归，但没有 Migration Ledger 和输出校验值。是否可以发布？

<Answer>
  不可以。Candidate 还需补齐 Blender/API/插件版本、稳定不变量、不可等价差异、输出帧范围、颜色、格式和校验值，并在同一发布包中保存源文件、外部资产、证据和 Failure Replay。完成后重新执行发布闸门，确认另一位读者能复现批准结论。
</Answer>

</Exercises>
