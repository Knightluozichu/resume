## 学习目标

- 理解区块链开发环境的四大工具分层
- 掌握 Hardhat 与 Foundry 两套主流框架的特点与选择
- 学会使用本地链与公共测试网进行分级验证
- 建立从编写合约到浏览器核查的完整开发数据流

## 核心概念

### 四大工具分层

区块链开发环境由四层工具栈组成，自底向上逐层支撑：

1. **语言与运行时**：Node.js 提供 JavaScript 运行时与 npm 包管理，Solidity 编译器 solc 负责把合约源码编译为字节码与 ABI，TypeScript 提供类型安全的部署与测试脚本。
2. **开发框架**：Hardhat 与 Foundry 是两大主流框架，承担编译、部署、测试网络管理与任务自动化。
3. **本地链与钱包**：Hardhat Node 与 Anvil 提供即时出块的本地链用于快速调试，MetaMask 作为浏览器钱包负责签名与注入 provider。
4. **测试网与浏览器**：Sepolia 等公共测试网提供接近真实的环境，Etherscan 用于部署后的源码验证与核查。

### Hardhat 与 Foundry

Hardhat 基于 JavaScript/TypeScript，插件生态丰富，部署脚本灵活，适合与前端工具链深度集成的团队。Foundry 基于 Solidity 编写测试，编译与模糊测试速度极快，更贴近合约本身思维。两者并非互斥：可以用 Foundry 做合约层快速测试，用 Hardhat 做部署脚本与前端联调。

### 本地链与测试网的分工

本地链（Hardhat Node / Anvil）的核心优势是快：即时出块、可重置状态、可分叉主网、免 Gas，适合单元测试与快速联调。公共测试网（Sepolia）的核心价值是真：真实共识、公开可见、外部用户与前端可接入，适合上线前的集成验证。原则是先本地后测试网，把低级错误挡在本地，把集成问题留到测试网。

### 开发数据流

完整的开发数据流为：编写合约 → 框架编译 → 本地链调试 → 测试网验证 → 浏览器核查。这一顺序体现了从快速反馈到真实环境的逐层收敛，跳级会让早期错误暴露在更昂贵的环境，增加排查成本。

## 术语表

| 术语 | 含义 |
|------|------|
| solc | Solidity 编译器，产出字节码与 ABI |
| Hardhat Node | Hardhat 内置的本地以太坊节点 |
| Anvil | Foundry 提供的本地测试链 |
| Sepolia | 以太坊公共测试网 |
| 水龙头 faucet | 领取测试网代币的服务 |
| provider | 前端与链通信的抽象接口 |
| 分叉 fork | 本地链复制主网状态运行 |
| Etherscan | 区块浏览器，支持源码验证 |

2. Hardhat 与 Foundry 的主要区别是什么？如何选择？
3. 本地链与公共测试网各自的作用是什么？为什么要先本地后测试网？
4. 描述开发数据流的五个环节，并解释为什么不能跳级。
5. Etherscan 的源码验证为什么对上线合约很重要？
