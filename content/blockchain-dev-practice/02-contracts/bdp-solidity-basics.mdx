## 学习目标

- 掌握 Solidity 合约的六大组成部分
- 理解 storage、memory、calldata 三种数据位置与 Gas 成本关系
- 区分函数可见性与状态变更性的语义
- 了解整数溢出保护与 require/revert/自定义 error 的 Gas 差异

## 核心概念

### 合约结构

一个 Solidity 合约由若干组成部分构成：pragma 版本声明锁定编译器兼容性；状态变量持久化上链，存储在 storage 中，Gas 成本最高；事件输出链上日志供前端低成本检索；修饰器复用校验逻辑；构造函数在部署时执行一次用于初始化；函数承载业务逻辑。

### 数据位置与 Gas

Solidity 有三种数据位置：storage 是持久化存储，写在链上，Gas 成本最高；memory 是函数内临时内存，函数结束即释放，成本中等；calldata 是只读的外部输入数据位置，不可修改，成本最低。核心原则是：只读入参用 calldata，临时计算用 memory，必须持久化才用 storage。合理选择数据位置是 Gas 优化的第一步。

### 函数可见性与状态变更性

可见性控制谁能调用：public 内外皆可、external 仅外部、internal 仅合约及子合约、private 仅本合约。状态变更性控制是否改链上状态：view 只读不改、pure 纯计算不读不写、payable 可接收以太币。前端调用时，call 用于只读查询不打包交易，transact 用于写状态需签名上链。

### 整数安全与错误处理

Solidity 0.8 起内建整数溢出检查，溢出自动 revert，因此不再需要 SafeMath 库。错误处理方面，require 携带字符串会消耗更多 Gas 存储字符串；revert 配合自定义 error（custom error）只在 revert 时编码选择器与参数，Gas 更省，尤其适合频繁触发的失败路径，因此推荐用自定义 error 替代 require 字符串。

## 术语表

| 术语 | 含义 |
|------|------|
| pragma | 声明 Solidity 编译器版本 |
| storage | 持久化上链的合约存储 |
| memory | 函数内临时内存 |
| calldata | 只读的外部调用入参位置 |
| modifier | 可复用的函数校验逻辑 |
| view | 只读不修改状态的函数 |
| pure | 不读不写状态的纯计算函数 |
| payable | 可接收以太币的函数 |
| custom error | Gas 友好的自定义错误类型 |
