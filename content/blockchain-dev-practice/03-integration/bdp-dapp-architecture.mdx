## 学习目标

- 掌握 DApp 三层架构的职责划分
- 理解 IPFS 元数据与 CID 内容寻址的一致性保证
- 学会用乐观更新与回滚改善用户体验
- 认识延迟、Gas 成本、可升级性三组关键权衡

## 核心概念

### 三层架构

DApp 采用三层架构：前端层负责用户交互（UI 组件、状态管理、钱包签名授权）；链下层负责索引与存储（The Graph 子图、IPFS/Arweave 元数据、预言机 Oracle）；链上层负责共识与状态（核心合约、代理合约、EVM 共识）。分层原则是链上只放必须去中心化的逻辑与资产，链下承担索引与存储，前端负责交互与乐观体验。

### 链下索引与存储

链上存储昂贵，因此历史数据聚合交给 The Graph 子图索引，用 GraphQL 查询；元数据（图片、JSON 属性）存到 IPFS 或 Arweave，链上只存 CID 哈希。CID 由内容哈希生成，内容一旦改变 CID 即变，因此链上记录的 CID 与链下内容一一对应，保证不可篡改与可验证一致性。预言机（如 Chainlink）负责把链外数据（价格、随机数）安全上链。

### 乐观更新与回滚

链上写入有区块确认延迟，若每次都等确认才更新 UI，体验极差。乐观更新指交易提交后立即在前端假定成功并更新界面，同时记录原状态；若交易最终失败或回滚，则用记录的原状态回滚 UI。这样在保持去中心化真实性的同时给出即时反馈。

### 关键权衡

DApp 架构面临三组关键权衡：延迟与去中心化（更多链下索引提升速度但弱化去中心化）；Gas 成本与链上数据量（链上数据越多越可信但越贵，需把非必要数据下链）；可升级性与不可篡改（可升级便于修漏洞但削弱信任，需用多签加时间锁约束）。决策原则是按场景取舍：资产与核心逻辑上链且谨慎升级，索引与展示下链优化体验。

## 术语表

| 术语 | 含义 |
|------|------|
| The Graph | 链上事件索引与 GraphQL 查询服务 |
| 子图 subgraph | The Graph 的索引单元 |
| IPFS | 去中心化内容存储 |
| CID | IPFS 内容标识符，由内容哈希生成 |
| 预言机 Oracle | 把链外数据送上链的服务 |
| 乐观更新 | 交易提交后立即更新 UI 的策略 |
| wagmi | React Web3 hooks 库 |
| EIP-712 | 结构化数据签名标准 |

4. DApp 架构面临的三组关键权衡是什么？如何决策？
