## 学习目标

- 理解 Web3 集成的四层数据通路
- 区分读操作 call 与写操作 transact
- 掌握事件监听实现链上状态实时同步
- 学会处理交易丢包、nonce 冲突与 revert 解码

## 核心概念

### 四层数据通路

Web3 集成由四层构成：前端层（React 组件、ethers.js/viem 库、MetaMask 钱包）、通信层（读操作 call 与写操作 transact）、网络层（RPC 节点与 JSON-RPC 协议）、链上层（智能合约与 EVM）。前端通过库按 ABI 编码调用数据，经 RPC 节点送达链上合约，返回结果或事件日志。

### 读 call 与写 transact

读操作 call 不打包交易、不上链、免 Gas、即时返回，适合查询状态；写操作 transact 需要钱包签名、打包上链、消耗 Gas、需等待区块确认，适合修改状态。前端应把只读查询用 call 获得即时响应，把状态变更用 transact 并妥善处理签名、确认与失败回退。

### 事件监听与状态同步

合约通过 event 输出日志，前端用 contract.on 按主题（indexed 参数）过滤订阅事件。链上事件一旦出块即推送到前端，实现状态实时同步。事件日志不参与合约状态但可低成本检索，是链上到链下通信的主通道。配合 The Graph 等索引服务可对历史事件做聚合查询。

### 错误处理与鲁棒性

写交易可能出现丢包或 nonce 冲突，多因前端并发提交或 nonce 未同步。正确做法是维护待确认 nonce 队列、串行化提交、对超时交易用相同 nonce 加更高 gas price 替换（speedup 或 cancel）。交易失败时，通过解析交易回执的 revert 数据，按 ABI 解码自定义 error 或 require 字符串，前端据此向用户展示可读错误。

## 术语表

| 术语 | 含义 |
|------|------|
| ethers.js | 主流 JavaScript 以太坊交互库 |
| viem | 类型友好的现代以太坊交互库 |
| ABI | 合约接口描述，编码调用数据 |
| provider | 与链通信的抽象接口 |
| JSON-RPC | 节点通信协议 |
| call | 只读查询，不上链不花 Gas |
| transact | 写状态交易，需签名上链 |
| nonce | 账户交易序号，防重放 |
| revert | 交易失败回滚并返回原因 |

## 练习题

1. Web3 集成的四层数据通路是什么？
2. 读操作 call 与写操作 transact 的区别是什么？
3. 前端如何实时感知链上状态变化？事件监听的机制是什么？
4. 写交易出现丢包或 nonce 冲突时如何处理？
5. revert reason 如何解码？为什么前端需要展示可读错误？
