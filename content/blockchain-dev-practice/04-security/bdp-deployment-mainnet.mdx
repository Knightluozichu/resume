## 学习目标

- 掌握主网上线的七阶段流水线
- 理解可升级合约的提案-时间锁-多签-执行治理流程
- 学会链上监控与应急响应手段
- 认识「合约不可回滚」对设计阶段的安全要求

## 核心概念

### 七阶段流水线

主网上线遵循七阶段流水线：1 编译（solc 产出 ABI 与字节码）、2 测试（单元、模糊、分叉覆盖回归）、3 测试网部署（Sepolia 联调真实交互）、4 验证（Etherscan 源码核验，使合约可读可审）、5 审计（第三方审计修复高危，赏金兜底）、6 多签（Gnosis Safe 分散权限防单点）、7 主网部署（正式不可撤销）。

### 可升级合约治理

可升级合约的治理需经四环节：提案公开升级内容供社区知情；时间锁设延迟执行窗口，让用户有时间在恶意升级前退出资金；多签批准要求 M-of-N 签名防止单点作恶；执行才真正切换 Logic 地址。四环节把升级权关进笼子，兼顾可迭代性与用户保护。透明代理与 UUPS 是两种常见实现。

### 运维监控与应急

上线后运维监控关注三方面：链上监控关注 TVL、交易量、Gas 与异常大额转账告警；事件追踪用 The Graph 索引与 Dune 仪表盘分析；应急响应包括 Pausable 暂停开关与资金抢救预案。监控与应急是上线后的生命线，能在漏洞被利用时快速止损。

### 不可回滚的铁律

主网合约部署后字节码不可更改，已发生的交易与状态转移无法撤销；代理虽能替换 Logic 代码，但已写入的 storage 状态难以安全回退，错误状态可能已被外部依赖。因此上线铁律是：主网部署不可撤销、永远先测试网、关键权限多签加时间锁、预留应急暂停开关。安全靠设计而非靠回滚，设计阶段就要把漏洞挡在门外。

## 术语表

| 术语 | 含义 |
|------|------|
| Etherscan 验证 | 提交源码与字节码匹配核验 |
| Gnosis Safe | 多签钱包标准实现 |
| 时间锁 Timelock | 延迟执行升级的治理机制 |
| 提案 Proposal | 公开的升级计划 |
| Pausable | 可暂停的应急开关 |
| TVL | 锁仓总价值 |
| Dune | 链上数据分析仪表盘 |
| speedup | 用更高 gas price 替换待确认交易 |

3. 上线后运维监控应关注哪些指标与应急手段？
4. 为什么说合约不可回滚？这对设计阶段意味着什么？
5. 透明代理与 UUPS 在升级治理上有何差异？
