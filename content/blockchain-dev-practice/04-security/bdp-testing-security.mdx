## 学习目标

- 掌握智能合约测试金字塔的层级与成本关系
- 理解 Slither、Mythril、Echidna 的检测技术差异
- 识别重入、溢出、访问控制、预言机操纵等高危漏洞
- 建立「测试覆盖加多轮审计加赏金兜底」的多层防御

## 核心概念

### 测试金字塔

智能合约测试从底到顶分为五层：单元测试 Unit（数量多成本低，验证单个函数）、集成与分叉测试（在真实主网状态上联调）、模糊测试 Fuzz（随机输入找边界与异常）、不变式测试 Invariant（断言系统在任意调用序列下的不变性质）、形式化验证（数学证明，成本最高数量最少）。层级越高越能发现深层逻辑漏洞但成本越高。

### 静态分析与审计工具

三类工具技术互补：Slither 用静态分析快速扫描重入、未初始化等模式问题；Mythril 用符号执行探索深层执行路径，发现复杂漏洞；Echidna 用基于属性的模糊测试，反复调用合约试图破坏开发者定义的不变式。Foundry 的 Forge 把 fuzz、invariant、fork 测试一体化集成。工具之上还需人工审计逐行复核，最后用赏金计划借助社区发现长尾问题。

### 高危漏洞清单

四类高危漏洞必须重点防御：重入攻击（外部调用回调改写未更新状态）、整数溢出（0.8 前无内建检查导致数值绕过）、访问控制缺失（关键函数无权限校验被任意调用）、预言机操纵（攻击者用闪电贷瞬时操纵价格影响报价）。每类都需对应防御模式：重入用检查-生效-交互加重入锁，溢出用 0.8 内建检查，权限用 Ownable/AccessControl，预言机用 TWAP 时间加权均价。

### 多层防御原则

合约部署后不可撤销，单一手段都有盲区：自动化测试覆盖已知模式但难发现逻辑漏洞；静态与符号工具误报漏报并存；人工审计能查逻辑但可能遗漏；赏金计划发现长尾问题。必须多层叠加：不信任外部合约、坚持检查-生效-交互、限制可升级权限、充分测试覆盖加多轮审计，才能把残余风险压到最低。

## 术语表

| 术语 | 含义 |
|------|------|
| 模糊测试 Fuzz | 用随机输入探测边界漏洞 |
| 不变式 Invariant | 系统应始终满足的性质 |
| 形式化验证 | 数学方法证明合约正确性 |
| Slither | 静态分析工具 |
| Mythril | 符号执行分析工具 |
| Echidna | 基于属性的模糊测试工具 |
| 重入 Reentrancy | 利用回调重复执行的攻击 |
| TWAP | 时间加权平均价格，防瞬时操纵 |
| 赏金计划 Bug Bounty | 社区悬赏找漏洞 |
