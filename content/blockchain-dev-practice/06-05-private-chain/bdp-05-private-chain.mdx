# 第5章 以太坊私有链的搭建与运行

私有链不是把主网名字换成“本地”就结束了。它的身份由创世配置、网络 ID、初始状态、节点集合、数据目录和客户端版本共同决定；节点能启动只证明进程存在，不能证明它加入了目标链。搭建时必须能从空目录重置，运行时必须能从账户、交易和区块三类对象解释状态变化。

本章以 2018 年工具语境讨论 Geth、JavaScript 控制台、CLI 和 TestRPC，同时把历史路径与现代替代隔离。TestRPC 适合快速生成内存测试链，但它不能替代多节点传播、持久化和真实共识实验；所有操作使用测试账户、可丢弃目录和无价值请求。

## 私有链合同与状态模型

一份私链合同至少包含：客户端和版本、创世配置摘要、chain ID、数据目录、节点密钥、P2P 与 RPC 端口、账户来源、初始余额、区块确认条件和清理方式。两个节点即使使用同一个客户端，也必须分别记录目录、端口和日志；共享目录会让状态来源无法解释。<Term>Disposable Data Directory</Term> 是隔离这些状态、保存证据后可安全清理的数据目录。

<Term>Genesis Identity</Term> 是由创世配置摘要、chain ID、初始状态和客户端规则共同组成的私链身份。它比网络名称更可靠；换一个创世文件或保留旧数据目录，都可能让节点进入另一条链。

状态变化仍然遵循：

$$
S_{t+1}=apply(S_t,T_t), \qquad valid(T_t,S_t)=1
$$

初始化是创建状态边界，连接是建立传播边界，交易是提出状态变化，区块是记录候选历史，查询是读取证据。任何失败都应保留原状态和错误对象；清空目录后重新运行必须能解释哪些输入发生了改变。

<Callout type="note" title="先保存创世证据，再启动节点">
  初始化前保存创世文件摘要、chain ID、初始账户和数据目录；启动后读取创世块、网络 ID、链头和同伴。这样能区分“初始化失败”“连接错误”和“误读旧数据”。
</Callout>

## 1. 创世配置与节点拓扑

私有链的创世配置决定初始状态、共识参数、预置账户和网络起点。初始化命令应只指向新的数据目录，完成后保存创世块哈希和配置摘要；如果复用旧目录，初始化命令可能拒绝，也可能留下难以解释的旧状态。

节点拓扑按单节点、双节点和内存测试链分别验收。双节点要有独立数据目录、不同 P2P 端口、明确同伴身份和相同创世摘要；节点看到的链头和状态摘要应能够相互对照。TestRPC 可以省略部分持久化与对等网络步骤，必须把这种省略写在实验结论中。

<Term>Peer Set</Term> 是参与私链传播的节点集合及其连接信息。它不是“进程列表”，还包含节点身份、P2P 端口、同伴关系、创世配置和最近链头；其中一项不一致，都可能产生孤立节点。

## 5.1 搭建一个私有链

搭建一个私有链时先生成或固定创世文件，再为每个节点创建独立目录并执行初始化。启动参数显式指定网络 ID、数据目录、P2P 端口、RPC 绑定和权限；初始化结果用创世块、账户列表和链头读取验证，而不是用命令退出码代替。

双节点实验还要交换节点身份并建立对等连接。连接后比较两个节点的区块哈希、交易池、链头和状态摘要；如果高度相同但历史不同，优先核对创世摘要、数据目录和客户端参数，而不是继续广播。

## 5.2 以太坊JavaScript控制台命令

JavaScript 控制台是 RPC 的交互外壳，不是独立的状态来源。每次命令都绑定具体节点、网络、账户和观察时刻；查询余额要记录账户地址和区块上下文，发送交易要记录 nonce、Gas、接收者、回执和确认。

<Term>Console Evidence</Term> 是控制台输入、RPC 端点、原始输出、网络身份和状态前后对照组成的证据包。复制一行格式化余额或交易哈希，不能让复核者知道它来自哪条链、哪个账户或哪个区块。

## 5.3 以太坊CLI控制台命令

CLI 适合把同一组查询写成可重复脚本。脚本应先读取网络 ID、创世块、链头和账户，再执行目标操作；原始 JSON 保存在受控目录，jq 或其他格式化工具只生成可分享摘要，不能覆盖原始响应。

CLI 参数中的数据目录、RPC 地址、账户和网络必须显式写出。省略参数依赖默认值时，命令可能读到另一份节点数据或连接到公共 RPC；脚本退出成功也不能替代对字段、状态和错误对象的检查。

## 5.3.1 账户管理

账户管理包括创建测试账户、读取地址和余额、核对 nonce、解锁边界以及签名交易。私链实验只使用新建测试账户，密钥存放在隔离目录；任何导入真实助记词或把密钥写入命令历史的步骤都不应执行。

账户地址不包含网络身份，余额和 nonce 属于特定私链状态。查询前先记录节点、chain ID、块高和账户来源；发送交易后比较前后余额、nonce、回执和区块位置，确保状态变化来自目标请求。

## 5.3.2 区块数据管理

区块数据管理用于读取 <Term>Chain Head</Term>、区块哈希、父块、时间戳、交易列表和确认深度。区块高度增加不一定表示节点连接了正确链；必须同时核对创世块、网络 ID、数据目录和同伴关系。

保存区块数据时保留原始响应和观察时刻，并将交易哈希映射回回执与状态变化。两个节点的同一高度若哈希不同，应停止继续测试，先定位创世、参数、同步和数据目录差异。

## 5.4 以太坊TestRPC测试链搭建

TestRPC 通过内存状态和预置账户快速提供开发接口，适合练习合约调用、事件和错误路径。它的即时挖矿、重置能力和预置余额降低了实验成本，但也隐藏了真实节点的磁盘持久化、对等传播、同步延迟和共识选择。<Term>TestRPC Boundary</Term> 用来标记这些与真实节点不同的实验边界。

使用 TestRPC 时要记录版本、启动参数、账户来源、网络 ID、快照或重置操作，并把结论限定为“接口路径可行”。迁移到私有 Geth 或其他客户端前，重新验证创世配置、账户、Gas、回执、区块和持久化，不能把内存测试结果直接当作生产证明。

<Callout type="trap" title="把 TestRPC 成功当成私链成功">
  现象：合约在内存测试链中立即返回成功，就认为双节点私链也会有同样结果。原因：TestRPC 可能即时出块、预置账户和简化网络，隐藏了持久化、传播、同步与确认边界。修法：在目标私链重新验证创世、账户、Gas、回执、区块和重启后的状态。
</Callout>

<Callout type="trap" title="把旧数据目录当成初始化结果">
  现象：节点高度、账户或链头与新创世文件不一致，团队继续用命令覆盖问题。原因：数据目录保留了另一条链的状态，初始化和启动输入已经不一致。修法：停止节点，保存目录树和日志，使用可丢弃新目录重新初始化，再比较创世摘要和链头。
</Callout>

## 5.5 本章小结

私有链搭建的核心不是启动一个本地进程，而是建立一条可重置、可连接、可核对的状态链：创世配置定义身份，独立数据目录保存状态，节点拓扑决定传播，控制台和 CLI 读取原始证据，TestRPC 则必须明确它的简化边界。

发布前至少要回答：创世块和 chain ID 是否匹配，节点是否使用独立目录并连接到正确同伴，账户和 nonce 是否属于测试链，交易是否进入区块并改变预期状态，重启后结果是否仍可解释。不能用窗口截图、余额摘要或即时成功提示补齐缺失证据。

## 练习与答案

<Exercises>

**问题 1：创世身份。** 两个节点使用同一客户端和同一 chain ID，但创世块哈希不同。它们能否视为同一条私链？

<Answer>
  不能。创世块是链的起点，创世配置、初始状态和 chain ID 共同定义身份；创世哈希不同意味着历史起点不同。应分别清理或隔离数据目录，固定同一创世文件并重新初始化，再比较链头和状态。
</Answer>

**问题 2：控制台证据。** CLI 返回账户余额增加，但没有保存区块号、交易回执和 RPC 网络。这个结果可以发布吗？

<Answer>
  不能。余额摘要无法证明来自目标私链，也无法说明是哪笔交易、哪个区块或什么确认深度产生变化。需要保存 RPC 端点、chain ID、账户、前后余额、nonce、交易哈希、回执、区块哈希和观察时刻。
</Answer>

**问题 3：TestRPC 边界。** TestRPC 中重启后状态仍然存在，是否证明真实私链具备同样的持久化能力？

<Answer>
  不能直接证明。先确认 TestRPC 的版本、快照或数据保存机制，再在目标客户端中使用独立数据目录重启，读取创世、链头、账户和交易状态。只有在目标拓扑下重复通过，才能把结论扩展到私链持久化。
</Answer>

</Exercises>
