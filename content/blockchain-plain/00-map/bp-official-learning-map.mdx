# 《白话区块链》2017版权威学习地图

## 为什么学习地图要从可验证对象开始

目录可以告诉你“先学什么、后学什么”，却不能单独证明你已经理解。学习地图把每个单元放进一条可执行路线：先找到对象，再写出规则，然后选择平台，最后通过实验观察状态变化。这样，读者不会把“看过章节”误认为“能解释一个拒绝结果”。

本页把目录节点登记在 <Term def="把原书单元、学习目标、证据和回放状态连接起来的结构化账本">Learning Ledger</Term> 中；每个节点都要绑定一个 <Term def="在验证通过后保持不变量并产生后状态的规则">State Invariant</Term>。区块、交易、账户和 UTXO 是对象，签名、链接、共识和权限是规则，平台与工具是运行边界，微链和风险案例是观察入口。

<Callout type="trap">**误区：目录覆盖率就是理解程度。** 现象是所有标题都被勾选，却说不出交易何时被拒绝；原因是目录只记录范围，没有记录对象、输入和后状态。修法是给每个节点绑定一个最小例子和一个失败路径，再标记完成。</Callout>

<Callout type="trap">**误区：现代命令可以直接替换历史命令。** 现象是新客户端能运行，读者就把它当成 2017 年原书行为；原因是版本、默认网络、钱包和共识环境已经变化。修法是建立历史行为、现代替代、差异和回退四列迁移表。</Callout>

<Callout type="trap">**误区：一张知识导图就是证据。** 现象是节点之间画了箭头，却没有可重放输入；原因是关系图展示结构，不展示验证和失败。修法是把每条关键箭头接到一个 <Term def="能由独立复核者从来源、输入、响应和状态重建的索引记录">Evidence Index</Term>，并保留原始对象。</Callout>

## 一张地图的四层结构

地图用四层回答“学什么、为什么、在哪运行、如何验收”：

1. **对象层**：区块、交易、账户、UTXO、合约状态和消息。先写字段与所有权，避免把“余额”当成所有模型的共同对象。
2. **规则层**：哈希链接、签名验证、价值守恒、共识排序、权限和回滚。每条规则都要有接受条件与拒绝条件。
3. **平台层**：比特币节点、以太坊、Fabric、钱包和客户端。平台提供执行边界，不能代替对规则的解释。
4. **实验层**：最小区块、交易构造、合约调用、微链、故障注入和风险回放。实验产出原始输入、响应、状态与恢复动作。

当一个节点进入 <Term def="代表规范链选择的历史序列，观察到的区块必须绑定到它才有确认意义">Canonical History</Term>，它才有“已确认”的含义；当一个风险被放入 <Term def="明确资产、攻击者能力、入口、影响和恢复边界的分析合同">Threat Model</Term>，它才从口号变成可以验证的假设。地图的目的正是让这些概念彼此有路可走，而不是把它们堆成标签。

## 从概念到最小实现

一个最小区块实验不需要模拟全部真实网络，但必须把关键边界说清楚：

```python
def append_block(chain, block, hash_block, valid_transaction):
    if not chain or block["previous"] != hash_block(chain[-1]):
        return {"accepted": False, "reason": "broken-link", "chain": chain}
    if not all(valid_transaction(tx) for tx in block["transactions"]):
        return {"accepted": False, "reason": "invalid-transaction", "chain": chain}
    return {"accepted": True, "reason": None, "chain": [*chain, block]}
```

这段代码只验证前块链接和交易集合，并明确失败时返回原链。真实系统还要处理签名、脚本、费用、锁定时间、网络传播、共识成员和持久化；教学地图的作用是指出这些问题属于哪一层，帮助读者选择下一页，而不是假装这个函数已经是完整节点。

另一个重要概念是 <Term def="把同一输入在固定版本和环境中再次运行，并比较原始输出与状态的过程">Replay</Term>。重放记录应包含来源摘要、软件版本、网络身份、数据目录、输入、原始响应、错误对象、前状态和后状态。缺少其中任一项，就要标记为无法重建，而不是用“结果看起来一样”补齐。

## 2017 年基线与现代迁移

原书讨论的是 2017 年前后的客户端、钱包、以太坊与 Fabric 生态。今天复习时保留其概念坐标和设计动机，同时把现代迁移单独列出：

| 迁移字段 | 要回答的问题 |
| --- | --- |
| 历史行为 | 原书命令或截图当时想证明什么？ |
| 当前替代 | 今天用什么工具重现同一概念？ |
| 行为差异 | 默认网络、账户、共识、接口或安全边界哪里改变？ |
| 验证方法 | 如何用日志、状态、回执或摘要证明替代仍对应原概念？ |
| 回退方案 | 当前工具不可用时，如何回到隔离的最小实验？ |

例如，现代以太坊的共识与节点架构已经变化，现代 Fabric 的组件和链码生命周期也可能不同；这些变化不能反写成 2017 年版本的事实。地图页只负责标记差异和指路，具体技术结论应回到相应官方文档或标准。

## 六类学习证据

| 证据类 | 最小内容 | 典型失败 |
| --- | --- | --- |
| 对象证据 | 字段、所有权、唯一标识、当前状态 | 把账户余额与 UTXO 数额混成同一模型 |
| 规则证据 | 输入、验证条件、接受与拒绝分支 | 只展示成功路径 |
| 平台证据 | 工具版本、网络、账户、数据目录 | 用默认配置掩盖上下文漂移 |
| 实现证据 | 代码、参数、日志、回执和事件 | 只保存格式化输出 |
| 故障证据 | 单一改变条件、原始错误、回退动作 | 失败后继续沿用旧状态 |
| 来源证据 | 原书节点、官方资料、标准或厂商链接 | 把现代博客当成历史版本依据 |

把这些字段组合成一份学习合同。合同不是额外作业，而是让学习成果能够被别人复核的最小接口。

## 练习与答案

<Exercises>

**问题 1：地图定位。** 你要学习“侧链技术”，但手里只有一张概念图。请按四层结构写出下一步要补的三个问题。

<Answer>
  先补对象：主链资产、侧链资产和锁定/退出凭证分别是什么；再补规则：锚定、证明和退出在什么条件下接受或拒绝；最后补实验：怎样在隔离环境记录跨链请求、证明、超时和恢复。这样才能从概念图走到可复核路线。
</Answer>

**问题 2：故障判断。** 微链收到一个前块摘要不匹配的区块。状态是否应该追加？请给出返回值中至少两个字段。

<Answer>
  不应追加。返回值至少包含 `accepted: false` 和 `reason: "broken-link"`，并保留原 `chain` 或其摘要。复核者还应记录输入区块、当前链头和哈希函数版本，证明拒绝来自链接规则而不是随机失败。
</Answer>

**问题 3：版本迁移。** 你用现代工具重做原书以太坊示例，命令能运行但默认网络不同。发布前应保存什么？

<Answer>
  保存历史命令的意图、现代工具版本、网络/chain ID、账户、数据目录、源码和编译产物摘要、部署回执、调用参数、前后状态及差异说明。若无法证明现代结果对应原概念，应把该节点标记为待复核，不把命令成功当作版本等价。
</Answer>

</Exercises>

## 学习地图发布检查

- 目录分母固定为 119 个正式层级，12 个单元的名称与原书一致。
- 每个节点至少能指向一个对象、规则、平台或实验，并说明下一步证据。
- 历史版本、现代替代和安全边界分开记录；现代工具不冒充原书事实。
- 正常、边界和故障路径共享观察字段，失败时保留原状态和原始错误。
- 复核者从来源和配置即可定位实验输入、输出、日志、回执和恢复动作。

## 小结

- 学习地图是从目录到证据的路线，不是标题截图。
- 四层结构把对象、规则、平台和实验连成连续路径。
- 119 个正式目录层级由 12 个单元覆盖，学习入口不计入原书分母。
- 2017 年基线与现代迁移必须分栏，差异要有验证和回退方案。
- 任何节点都应能被独立复核者从来源、输入和原始响应重新构建。

## 术语表

<Glossary>
  <GlossaryItem term="Learning Ledger">
    连接原书单元、学习目标、证据与回放状态的结构化账本。
  </GlossaryItem>
  <GlossaryItem term="State Invariant">
    状态转移前后必须保持的规则，例如前块链接正确、输入未重复消费或价值守恒。
  </GlossaryItem>
  <GlossaryItem term="Canonical History">

  </GlossaryItem>
  <GlossaryItem term="Evidence Index">
    指向来源、输入、响应、状态和失败对象的可重放索引。
  </GlossaryItem>
  <GlossaryItem term="Threat Model">
    明确资产、攻击者能力、入口、影响、可观测异常与恢复边界的分析合同。
  </GlossaryItem>
  <GlossaryItem term="Replay">
    在固定版本和环境中再次运行同一输入，并比较原始输出与状态的过程。
  </GlossaryItem>
