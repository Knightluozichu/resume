## 学习目标

- 掌握区块链交易的基本结构与 UTXO 模型
- 理解区块头的组成字段与 Merkle 树的作用
- 能够描述交易从创建到上链确认的完整生命周期
- 理解双花问题及其防范机制

## 核心概念

### 交易结构

一笔区块链交易由以下部分组成：

- **交易输入（Inputs）**：引用之前的 UTXO（未花费交易输出），说明资金的来源
- **交易输出（Outputs）**：指定接收地址和金额，创建新的 UTXO
- **数字签名**：用发送方的私钥签名，证明交易已被授权
- **手续费**：支付给矿工的激励，手续费越高越容易被优先打包

在 UTXO 模型中，交易的本质是「花费旧的 UTXO，创建新的 UTXO」。就像用一张 100 元钞票买东西，找回 30 元——旧的 100 元被消费掉，产生新的 30 元 UTXO。

### 区块结构

每个区块由区块头和区块体组成。区块头包含以下关键字段：

| 字段 | 作用 |
|------|------|
| 版本号 | 标识区块协议版本 |
| 前区块哈希 | 指向上一个区块，实现链式绑定 |
| Merkle 根 | 区块内所有交易的聚合哈希 |
| 时间戳 | 区块创建的大致时间 |
| 难度目标 | PoW 挖矿的哈希目标值 |
| Nonce | 矿工调整的随机数，用于满足挖矿条件 |

区块体则存储该区块打包的所有交易记录。

### Merkle 树

Merkle 树是一种将交易高效聚合的数据结构：

1. 对每笔交易计算哈希，得到叶子节点
2. 将相邻两个哈希拼接后再哈希，得到上一层节点
3. 逐层向上聚合，最终得到一个根哈希（Merkle Root）
4. 根哈希存入区块头

Merkle 树的价值在于**高效验证**：要验证某笔交易是否在区块中，只需提供从该交易到根的路径（Merkle Proof），无需下载全部交易。这就是 SPV（简化支付验证）的基础——轻节点只需区块头和 Merkle 路径即可验证交易。

### 交易生命周期

一笔交易从创建到最终确认，经历以下步骤：

1. **创建与签名**：发送方构建交易（输入、输出、手续费），用私钥签名
2. **广播**：将签名后的交易广播至 P2P 网络
3. **验证**：全网节点验证交易——签名是否有效、UTXO 是否未花费、金额是否非负、是否存在双花
4. **打包**：矿工将有效交易打包进候选区块
5. **上链确认**：新区块经共识机制确认后上链，交易完成最终确认

在 PoW 中，等待的确认数越多越安全。比特币通常建议等待 6 个区块确认（约 60 分钟）。

### 双花问题

双花问题是指同一笔数字资产被花费两次的攻击行为。这是数字货币面临的核心安全挑战。

区块链通过两个机制防止双花：

- **UTXO 模型**：每个 UTXO 只能被花费一次。一旦被某笔交易引用，就从未花费列表中移除
- **共识机制**：如果两笔交易试图花费同一个 UTXO，矿工只会确认先到达的那笔，后到的会被拒绝

对于更复杂的双花攻击（如 51% 攻击重组链），需要等待足够多的确认数来防范。

## 术语表

| 术语 | 含义 |
|------|------|
| 交易输入 | 引用之前 UTXO 的交易字段，说明资金来源 |
| 交易输出 | 指定接收地址和金额的交易字段，创建新 UTXO |
| UTXO | 未花费交易输出，比特币的交易模型 |
| Merkle 树 | 将交易两两哈希聚合的树形数据结构 |
| Merkle 根 | Merkle 树的顶层哈希，存入区块头 |
| Merkle Proof | 验证交易在区块中所需的哈希路径 |
| SPV | 简化支付验证，轻节点无需全量数据即可验证交易 |
| 双花问题 | 同一笔数字资产被花费两次的攻击 |
| 确认数 | 交易所在区块之后追加的区块数，越多越安全 |
| 手续费 | 交易发起者支付给矿工的费用 |
