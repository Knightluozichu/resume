# 前言

## 为什么前言要先约定如何学习

一本区块链书不只包含概念，还包含工具、网络、账户、协议假设和一连串会改变状态的实验。前言的职责不是提前讲完九章，而是告诉读者如何判断“我真的掌握了”：先说清对象，再验证规则；先在隔离环境运行，再解释失败；最后把历史版本与今天的替代分开。

本页把这份约定称为 <Term def="规定学习范围、状态观察、证据留存和版本迁移方式的可执行约定">Learning Contract</Term>。每个章节都要有一个 <Term def="描述对象、输入、验证条件、允许变化和后状态的最小模型">State Model</Term>；否则读者只能记住命令或类比，无法说明一个交易为什么被拒绝、一个合约为什么回滚或一个网络为什么没有达成一致。

<Callout type="trap">**误区：把九章当成九篇互不相干的文章。** 现象是跳过基础对象，直接复制平台命令；原因是没有理解后续章节依赖前面定义的状态和规则。修法是按“理解对象、解释可信、处理扩展、选择平台、动手搭建、识别风险”的顺序推进，并为每次跨章节引用保留前置证据。</Callout>

<Callout type="trap">**误区：把阅读完成当成实验完成。** 现象是能复述区块链概念，却不能给出前后状态或失败原因；原因是缺少 <Term def="把来源、输入、运行日志、原始响应和状态变化按时间串起来的记录">Evidence Trail</Term>。修法是每个关键概念都绑定一个最小运行样本、一个边界样本和一个可重建的失败记录。</Callout>

<Callout type="trap">**误区：遇到不一致仍继续推进。** 现象是版次不明、网络不明或异常只有“失败”二字，读者仍然往下安装和部署；原因是没有预先声明 <Term def="发现证据断裂时暂停实验、保留现场并返回上一可验证状态的规则">Stop Condition</Term>。修法是把停机、恢复和重新验证写成路线的一部分，而不是把异常藏在章节末尾。</Callout>

## 2017 年版的范围与来源

本书是《白话区块链》2017 年 10 月版：蒋勇、文延、嘉文著，机械工业出版社，236 页，ISBN 9787111582984。目录范围以[当当云阅读书页](https://e.dangdang.com/products/1901310198.html)为主，并用[得到书页](https://www.dedao.cn/ebook/detail?id=A1De6QkaNRMlK5yxrdmnEBXY97ZL23n2GD3o6zvGDekj1QgA84VbpqJOPLgxEJlY)和[天珑书店书页](https://www.tenlong.com.tw/products/9787111582984)交叉核对出版信息。本页是独立教学重构，不复制原书正文；今天的技术事实还需回到官方文档、标准或厂商资料。

前言只冻结学习范围和顺序，不把当年的命令承诺为今天仍可直接运行。历史实现、现代替代和安全边界必须分栏记录；当两者无法建立可验证对应关系时，学习合同应保留差异并触发 Stop Condition。

## 九章递进的学习合同

| 递进阶段 | 对应单元 | 学习结果 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| 理解对象 | 第1章 初识区块链 | 能描述交易、区块、节点和账本关系 | 一个可重放的交易与区块例子 |
| 看见用途 | 第2章 区块链应用发展 | 能画出链内状态与链外业务边界 | 应用角色、输入和后状态表 |
| 解释可信 | 第3章 密码算法、第4章 共识算法 | 能解释授权、排序、故障和最终性 | 签名验证与故障模型记录 |
| 理解扩展 | 第5章 扩容、侧链和闪电网络 | 能指出吞吐、结算和信任新增在哪里 | 扩展方案的安全假设表 |
| 选择平台 | 第6章 以太坊、第7章 超级账本 | 能按账户、权限、执行与网络约束选型 | 平台配置、调用回执与差异表 |
| 动手搭建 | 第8章 搭建微链 | 能从空目录构建并解释最小状态机 | 源码、测试、日志和失败回放 |
| 识别风险 | 第9章 潜在的问题 | 能为攻击、密钥、分叉和治理写恢复边界 | 风险假设、反例和恢复命令 |

九章不是并列目录。第 8 章的微链实验要用到第 1、3、4 章的对象、签名和共识边界；第 9 章的风险判断要回看第 5 至 7 章的扩展与平台假设。前置证据缺失时，不能用后续平台界面掩盖基础概念断裂。

## 从生活化账本到可运行状态

生活化账本的比喻可以帮助读者理解“谁记录、谁核对、谁能提出异议”，但它不能替代协议对象。实现审阅必须继续追问：交易有哪些字段，谁提供签名，节点依据什么规则接受，区块如何与前一个区块链接，失败时内存中的候选状态是否被丢弃。

```python
def learning_contract(run, expected_version):
    required = {"source", "version", "input", "before", "result", "failure"}
    missing = sorted(required.difference(run))
    version_ok = run.get("version") == expected_version
    return {
        "ok": not missing and version_ok,
        "missing": missing,
        "version_ok": version_ok,
    }
```

这个检查器不验证协议本身，却把前言的学习要求变成可以自动检查的形状：来源、版本、输入、前状态、结果和失败都必须出现。若版本不匹配，先停止并建立 <Term def="指出历史工具、现代替代、差异和回退方案的版本对照记录">Version Boundary</Term>；若状态无法解释，回到上一条可复核轨迹；若失败原因太宽泛，补齐原始错误后再继续。

## 2017 年基线与现代迁移

本书讨论的客户端、钱包、以太坊和 Fabric 都带有时代背景。现代重做时保留概念坐标，却不要直接复制已经失效的下载地址、网络参数、默认账户或命令。迁移表至少包括：

| 迁移字段 | 需要回答的问题 |
| --- | --- |
| 历史意图 | 原书示例希望证明哪个概念？ |
| 现代替代 | 今天用哪个工具或官方文档复现同一概念？ |
| 差异证据 | 网络、账户、接口、共识、权限或数据目录哪里改变？ |
| 回退路径 | 现代替代不可用时，如何回到隔离的最小实验？ |
| 阅读说明 | 哪些结论只是历史说明，哪些仍然适用于当前系统？ |

把迁移表当作 <Term def="说明历史意图、现代替代、差异证据和回退路径的审校说明">Migration Note</Term>，它就不会把“今天能跑”误写成“原书当时就是这样”。

## 前言规定的停机与恢复

以下情况必须停止继续叠加功能：

- 版次、工具版本、网络或账户无法定位；
- 交易、合约或账本的前后状态无法解释；
- 失败只留下一个笼统文本，没有原始响应或首个异常；
- 图示、代码和实验使用了不同的对象，但没有差异说明；
- 现代替代改变了安全假设，却没有单列迁移说明。

恢复流程是：保留现场和日志，缩小到最小输入，重现原失败，补齐缺失字段，再回到相邻的正常和边界样本。只有原失败、修复后正常和边界行为都能解释，才允许进入下一章或下一个平台。

## 前言练习与答案

<Exercises>

**问题 1：学习顺序。** 为什么第 8 章搭建微链不能脱离第 1、3、4 章直接开始？

<Answer>
  微链需要第 1 章的区块与交易对象、第 3 章的签名/摘要边界、第 4 章的排序与故障模型。缺少这些前置，代码即使能运行，也无法判断状态为什么被接受、为什么被拒绝或哪些安全保证根本没有实现。
</Answer>

**问题 2：停机条件。** 实验日志只有“交易失败”，但页面显示余额未变。请列出恢复顺序。

<Answer>
  先保留原始请求、网络、账户、响应和前状态；再缩小到最小输入，核对签名、输入是否已消费、余额和节点同步；随后把“失败”拆成可定位错误，重放相邻正常与边界样本。没有首个异常和后状态解释前，不应继续部署或扩展功能。
</Answer>

**问题 3：版本迁移。** 现代钱包能运行原书流程，但默认网络与账户不同。Migration Note 至少要写什么？

<Answer>
  至少写历史意图、现代替代、网络/账户差异、源码或配置摘要、验证方法和回退路径。还要说明哪些结论保留 2017 年语境，哪些结论可以迁移到今天；一次成功的界面操作不能代替这份差异证据。
</Answer>

</Exercises>

## 前言发布清单

- 九章顺序能解释对象、可信、扩展、平台、搭建和风险之间的依赖。
- 每个学习节点都有前状态、输入、观察结果、失败原因和恢复动作。
- 版次、工具、网络、账户和现代替代的差异进入 Version Boundary 或 Migration Note。
- 失败不会被笼统文本、截图或后续平台成功掩盖；原始现场可再次回放。
- 读者从隔离目录执行最小检查器，就能判断证据是否足够进入下一章。

## 小结

- 前言的产物是学习合同，不是额外的概念章节。
- 九章从对象理解逐步走到可信解释、扩展选择、平台实现、微链搭建和风险治理。
- Stop Condition 保护学习状态：证据断裂时先停、保留现场、缩小输入并恢复。
- 历史基线与现代迁移分开记录，成功运行不能掩盖版本差异。
- 只有前置证据、正常路径、边界路径和恢复动作都能重放，学习路线才真正闭合。
