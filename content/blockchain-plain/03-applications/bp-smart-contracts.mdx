- 理解智能合约的定义及其与传统合同的区别

## 核心概念

### 什么是智能合约

智能合约是部署在区块链上的程序，当预设条件满足时自动执行，无需第三方中介。

与传统合同相比：

| 维度 | 传统合同 | 智能合约 |
|------|----------|----------|
| 执行方式 | 依赖法律和人工执行 | 代码自动执行 |
| 违约风险 | 存在违约可能 | 不可阻止不可篡改 |
| 信任基础 | 法律体系 | 代码即法律 |
| 修改性 | 可协商修改 | 一旦部署不可修改 |
| 争议处理 | 法院仲裁 | 无争议空间，代码决定一切 |

智能合约的核心价值在于：将信任从「人和制度」转移到「代码和数学」。

### 合约部署流程

智能合约从编写到运行，经历以下步骤：

1. **编写合约**：使用 Solidity、Rust 等语言编写合约代码
2. **编译**：将高级语言编译为字节码（Bytecode）
3. **部署交易**：将字节码通过特殊交易广播到链上
4. **获得地址**：部署成功后，合约获得唯一的链上地址
5. **链上运行**：合约代码永久存储在区块链上，可被调用

### 合约执行流程

当智能合约被调用时，执行流程如下：

1. **触发条件**：用户发起交易调用合约，或另一合约调用
2. **EVM 执行**：以太坊虚拟机（EVM）读取合约状态，执行业务逻辑，消耗 Gas
3. **状态变更**：更新链上状态（如转账、修改存储变量）
4. **事件日志**：触发事件（Event），供链外应用监听
5. **共识确认**：执行结果经全网共识确认，不可逆上链

### Gas 机制

Gas 是衡量智能合约执行计算量的单位。每一步操作（存储读写、算术运算、跨合约调用）都消耗对应的 Gas。

Gas 机制的三重作用：

- **防止资源滥用**：防止恶意用户编写无限循环合约耗尽全网资源
- **激励验证者**：Gas 费支付给打包交易的矿工/验证者
- **促进代码优化**：复杂合约成本更高，激励开发者写出高效代码

如果交易执行过程中 Gas 不足，交易会回滚（Revert），已消耗的 Gas 不退还。因此发起交易时需要设置合理的 Gas Limit。

### 安全风险

智能合约一旦部署就不可修改，因此安全至关重要。主要风险包括：

- **代码漏洞不可撤回**：合约漏洞一旦被利用，损失无法追回（如 DAO 事件）
- **重入攻击**：合约在更新状态前向外部转账，攻击者利用回调重复提取资金
- **Gas 耗尽攻击**：故意让合约消耗过多 Gas 导致操作失败
- **预言机问题**：合约依赖链外数据，数据源不可信则合约行为异常

预防重入攻击的经典模式是 **Checks-Effects-Interactions**：先检查条件，再更新状态，最后才与外部合约交互。

### 典型应用

智能合约催生了丰富的区块链应用：

- **DeFi（去中心化金融）**：去中心化交易、借贷、稳定币
- **NFT（非同质化代币）**：艺术品、收藏品、游戏道具的唯一确权
- **DAO（去中心化自治组织）**：链上投票与提案治理
- **供应链溯源**：全链路追踪与防伪验证

## 术语表

| 术语 | 含义 |
|------|------|
| 智能合约 | 部署在区块链上的自动执行程序 |
| Solidity | 以太坊智能合约编程语言 |
| 字节码 | 合约编译后的低级代码，在 EVM 上运行 |
| EVM | 以太坊虚拟机，执行智能合约的运行环境 |
| Gas | 衡量智能合约执行计算量的单位 |
| Gas Limit | 交易发起者愿意支付的最大 Gas 量 |
| 重入攻击 | 利用回调在状态更新前重复提取资金的攻击 |
| 预言机 | 为智能合约提供链外数据的服务 |
| 事件 Event | 合约执行过程中发出的日志，供链外监听 |
| Checks-Effects-Interactions | 预防重入攻击的代码模式 |
