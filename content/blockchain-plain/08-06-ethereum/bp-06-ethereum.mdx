# 第6章 区块链开发平台：以太坊

以太坊把“转账”推广成对共享状态的确定性调用：交易携带调用者、目标、价值、数据和费用上限，节点用同一份字节码和前状态执行，再把后状态、日志和费用结果纳入区块。它的难点不是把函数写出来，而是让另一个节点能复核这次调用为什么被接受、拒绝或回滚。

本章把 2017 年书中介绍的钱包、客户端和合约平台作为历史坐标，重新组织成一条可测试的证据链。我们不把旧命令当作今天的部署指南，而是固定状态、网络标识、合约版本和失败边界，比较正常调用、边界预算和权限异常三种路径。

<Callout type="trap">**现象：**交易进入区块就被当作业务成功；**原因：**忽略执行状态、回执、事件和回滚原因；**修法：**同时检查 receipt status、Gas 消耗、日志、余额和后状态。</Callout>

<Callout type="trap">**现象：**Gas 耗尽后仍然读取到合约写入；**原因：**把临时写集误当作已提交状态；**修法：**在快照上执行，失败时恢复快照，只保留费用和失败证据。</Callout>

<Callout type="trap">**现象：**合约代码确定性被当作业务安全保证；**原因：**忽略权限、暂停开关、预言机和升级入口；**修法：**把调用者、角色检查、事件和异常路径加入权限审计。</Callout>

## 先把以太坊写成状态机

本章把一次调用的 `<Term def="由前状态、交易输入和合约代码共同计算后状态的可重放过程">State Transition</Term>` 作为最小对象。账户余额、nonce、合约存储、日志和费用都必须有前值或计算规则；只保存“交易哈希成功”不足以解释状态发生了什么。

交易的资源上限是 `<Term def="执行者为交易授权的计算资源单位上限，实际消耗会形成执行费用">Gas</Term>`。Gas Limit 限制一条调用路径最多执行多少计算，Gas Price 或现代费用字段决定费用计价；状态写入是否提交，仍取决于执行是否完成和协议是否接受交易。

执行环境是 `<Term def="按以太坊交易规则解释字节码、读取状态并产生后状态与日志的确定性虚拟机">EVM</Term>`。同一前状态、同一字节码和同一输入应得到相同的后状态，但确定性不保证权限配置、经济激励或外部数据正确。

账户的 `<Term def="用于阻止同一账户交易重放并维持交易顺序的单调序号">Nonce</Term>` 必须连续或符合客户端的待处理规则。若 nonce 跳过、重复或来自错误网络，节点可能拒绝、暂存或替换交易；不能只用签名有效来判断它可执行。

合约对外产生的 `<Term def="由执行路径写入、供索引器和复核者读取的结构化事件记录">Event Log</Term>` 是执行证据的一部分，不是状态变量的替代品。日志能帮助复核转账或铸币发生在哪条路径，但不能证明权限检查一定正确。

最后固定 `<Term def="标识交易应在哪个网络规则和状态历史中解释的网络编号">Chain ID</Term>`。Chain ID、创世配置、客户端版本和合约字节码共同决定重放环境；签名在一条链上有效，不代表可以安全复制到另一条链。

## 最小执行检查器

下面的代码用快照表达 EVM 的原子状态语义，用显式权限表表达代币入口的调用者边界。它不是完整客户端，却能让读者测试最关键的反例：执行失败后临时写集不能泄漏，权限失败不能静默改变余额。

<CodeTabs>
  <Tab label="Python / 状态与 Gas">

```python
from copy import deepcopy


def execute_call(state, caller, to, value, gas_limit, bytecode):
    before = deepcopy(state)
    if state["balances"].get(caller, 0) < value:
        return {"accepted": False, "reason": "insufficient-balance"}
    gas_remaining = gas_limit
    try:
        for instruction in bytecode:
            gas_remaining -= instruction["cost"]
            if gas_remaining < 0:
                raise RuntimeError("out-of-gas")
            instruction["apply"](state, caller, to, value)
    except RuntimeError as error:
        state.clear()
        state.update(before)
        return {"accepted": False, "reason": str(error), "gas_used": gas_limit - max(gas_remaining, 0)}
    return {"accepted": True, "state": state, "gas_used": gas_limit - gas_remaining}
```

  </Tab>
  <Tab label="Python / 权限与事件">

```python
def transfer_token(state, caller, recipient, amount):
    if state["paused"]:
        return {"accepted": False, "reason": "paused"}
    if amount <= 0 or state["balances"].get(caller, 0) < amount:
        return {"accepted": False, "reason": "invalid-amount"}
    state["balances"][caller] -= amount
    state["balances"][recipient] = state["balances"].get(recipient, 0) + amount
    return {"accepted": True, "event": {"name": "Transfer", "from": caller, "to": recipient, "amount": amount}}
```

  </Tab>
</CodeTabs>

正常样本用 Alice 向 Bob 转账 2；边界样本让 Gas 预算刚好覆盖最后一条指令；单变量失败样本只把 nonce、Gas Limit、暂停开关或调用者改掉一项。运行后逐项比较前状态、后状态、费用、日志和拒绝原因；如果只断言返回值为真，无法发现日志缺失或临时写集泄漏。

## 正式目录复核：从平台背景到合约证据

### 第6章 区块链开发平台：以太坊

本章总览的验收对象是“任何节点都能从同一前状态重放同一调用”。执行证据应串起签名、Chain ID、nonce、Gas、字节码、读写集、日志和后状态；只看交易哈希或钱包提示，会错过回滚、权限和网络错配。

### 6.1 项目介绍

项目介绍先回答平台解决什么问题：让可编程状态转移和原生价值转移共享一套共识历史。实验不从安装命令开始，而从一份可复制的链配置开始，避免把环境差异误认为合约逻辑差异。

### 6.1.1 项目背景

项目背景对应 2017 年以太坊生态的开发体验：客户端、钱包、测试链和智能合约工具正在快速演进。重读这段历史时，要把当年的产品界面和网络状态保留下来作为来源证据，同时明确它们不是今天的安全或兼容承诺。

### 6.1.2 以太坊组成

以太坊可以拆成账户状态、交易池、执行引擎、区块共识、日志索引和客户端接口。拆分后更容易定位故障：签名或 nonce 错误在交易入口，Gas 或字节码错误在执行层，确认或网络错误在区块与共识层。

### 6.1.3 关键概念

关键概念的连接顺序是：账户提供状态，交易携带调用，EVM 消耗 Gas 执行，日志暴露事件，区块把后状态纳入历史，Chain ID 限定解释边界。读者应能从一条回执反向找到每个字段的来源和验证条件。

### 6.1.4 官方钱包使用

钱包是签名和展示层，不是共识层。使用钱包时先检查网络、Chain ID、账户来源、目标地址、nonce、费用上限和合约数据，再用节点回执核对执行结果；界面显示“已发送”不能代替链上状态复核。

### 6.2 以太坊应用

应用开发把状态机暴露给用户和其他合约。设计时先画状态变量和权限转移，再确定事件、错误和暂停路径；对于可升级或依赖预言机的应用，还要把升级者和外部数据源纳入威胁模型。

### 6.2.1 测试链与私链

测试链和私链适合验证部署、回滚、事件和客户端连接，但它们的余额、验证者和网络条件不能代表公共网络。测试报告必须记录 Chain ID、创世配置、节点版本、区块时间、账户密钥来源和清理方式。

### 6.2.2 编写一个代币合约

代币合约至少需要检查余额守恒、授权入口、暂停行为、事件参数和重复调用。`transfer` 的成功不只意味着两个余额改变，还意味着调用者、接收者、金额、事件和总供应量都符合预期；铸币、销毁和管理员转移应使用不同的权限证据。

### 6.3 知识点导图

导图从“账户前状态”指向“签名与 nonce”，再指向“Gas 预算、EVM 执行、日志与后状态”，最后连接“区块确认、索引器和应用展示”。每条箭头都应落到一个字段或失败原因，避免用“智能合约很灵活”替代执行路径。

## 六类复核证据

### 状态与账户证据

保存账户余额、nonce、合约 storage、代码哈希和状态根的前后值。账户模型的余额变化要与价值、费用和合约写集分别核对，不能只看某个地址的最终余额。

### 交易与网络证据

保存 from、to、value、calldata、Chain ID、nonce、费用字段、签名和交易哈希。相同签名在错误网络上不应被当作目标链交易，替换或重放也必须留下原因。

### Gas 与执行证据

保存 Gas Limit、实际 Gas Used、失败位置、回滚标记和调用树。Gas 耗尽时状态写集应回到快照，已经执行的成本仍需能在回执或费用字段中解释。

### 权限与合约证据

保存调用者、角色集合、暂停状态、升级入口、预言机输入和权限拒绝原因。合约代码可复现不代表角色配置正确，管理员权限必须有独立审计记录。

### 日志与应用证据

保存事件名称、索引参数、非索引参数、日志顺序和对应状态变化。索引器展示的“转账成功”要能回到原始日志和执行回执，不能把前端缓存当作链上事实。

### 2017 年基线与现代迁移证据

本章以《白话区块链》2017 年版的平台、钱包和合约实践为历史坐标。现代迁移报告应重新核对客户端、共识、费用字段、网络标识、钱包和测试环境；旧命令可以解释概念，但不应直接成为生产操作手册。

## 容易踩的坑

<Callout type="trap">**现象：**调用合约时 Gas 耗尽，前端却显示“余额已经更新”；**原因：**前端先乐观更新或索引器读到了未确认的临时结果；**修法：**等待回执并核对后状态、日志和失败标记，失败时恢复本地缓存。</Callout>

<Callout type="trap">**现象：**同一笔签名交易在错误网络或旧 nonce 上被重放；**原因：**没有把 Chain ID 和 nonce 纳入签名前后的复核；**修法：**在发送前锁定网络标识和 nonce，接收端拒绝不匹配的交易。</Callout>

<Callout type="trap">**现象：**代币转账测试通过，未知地址却能调用铸币入口；**原因：**测试只覆盖正常角色，没有覆盖拒绝和暂停分支；**修法：**为每个外部入口建立角色矩阵，并断言余额、总供应量、事件和失败原因。</Callout>

## 小结

- 以太坊执行是由前状态、交易输入和 EVM 代码共同决定的状态转移。
- Gas 限制资源，失败时临时状态回滚，但已消耗的计算成本仍需解释。
- nonce 和 Chain ID 分别保护交易顺序与网络边界，签名有效不代表环境正确。
- 代币安全取决于余额守恒、权限、暂停路径、事件和升级入口的组合证据。
- 通过标准：能重放正常、边界和单变量失败样本，并标明 2017 年工具与现代配置的差异。

<Exercises>

**问题 1：**实现 `execute_call`，对调用前状态做快照；让一条字节码路径先修改余额再耗尽 Gas。验证返回 `out-of-gas`，余额、nonce 和 storage 恢复到调用前，而 `gas_used` 仍然大于零。

<Answer>

执行函数需要在第一次写入前复制状态，在每条指令扣除成本，并把 `gas_remaining` 作为失败判据。捕获 `out-of-gas` 后恢复快照，只返回失败原因和已用 Gas；不要把临时事件或写集当作后状态提交。

</Answer>

**问题 2：**给定 `transfer(from, to, amount)` 和 `mint(to, amount)` 两个入口，请为 Owner、普通持有者和未知地址写出权限矩阵，并列出成功与失败各自应该出现的事件和状态变化。

<Answer>

普通持有者只能在余额足够时调用 transfer，Owner 可以在权限检查通过后调用 mint，未知地址不能调用 mint。成功转账应改变双方余额并产生 Transfer 事件；失败调用不改变余额或总供应量，并保留 paused、unauthorized 或 insufficient-balance 原因。

</Answer>

**问题 3：**2017 年教程使用的旧钱包和客户端命令无法在现代环境运行。请列出仍可迁移的概念，以及必须重新验证的配置。

<Answer>

账户签名、nonce、Gas、EVM 状态转移、回执和事件等概念仍可迁移；客户端版本、共识机制、Chain ID、费用字段、钱包实现、测试链和创世配置必须重新验证。迁移报告要保留旧步骤作为历史来源，同时给出现代隔离环境和回滚方案。

</Answer>
