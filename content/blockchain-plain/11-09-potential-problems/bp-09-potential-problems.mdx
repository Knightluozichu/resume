区块链不是“广播后大家自然相信”，而是候选状态经过本地规则验证、网络传播、排序或共识，再提交为节点认可历史。任何结论都要回答五个问题：谁能发起，谁能验证，按什么顺序，失败时保留哪个状态，观察者凭什么复核。


## 区块、交易与证据不变量

$$
H_i = hash(H_{i-1} + merkle(T_i) + time_i + nonce_i)
$$

$$
valid(T) = signature(T, publicKey) and unspent(inputs) and valueIn >= valueOut
$$

$$
confirmed(T, k) = valid(T) and depth(T) >= k and canonical(block(T))
$$

$$
gate = source * replay * boundary * failureEvidence
$$

第一式把新区块绑定到前块摘要与交易集合；任一字段改变都会改变摘要，但只有独立验证和共识选择才能决定候选链是否被接受。第二式把签名授权、未花费约束和价值守恒分开，签名正确不代表输入尚未消费。第三式说明确认依赖规范链和深度，不能把“收到交易”写成“最终结算”。第四式要求来源、重放、边界与失败证据同时存在，任一为零都不能发布。

取三笔UTXO：A拥有7与4，拟向B支付8并找零3。合法交易必须引用两笔输入、由A签名并产生8与3两个输出；若仅引用7、重复引用同一输入或把找零写成4，节点应在进入候选区块前拒绝。把合法交易放入区块后修改金额，重算Merkle根和区块摘要虽可让单块内部一致，却会破坏后续链接和累计共识证据。

def verify_transaction(tx, utxos, verify_signature):
    inputs = [utxos.get(ref) for ref in tx["inputs"]]
    if None in inputs or len(set(tx["inputs"])) != len(tx["inputs"]):
        return False
    return verify_signature(tx) and sum(inputs) >= sum(tx["outputs"])

## 最小实例与重放顺序

先冻结创世状态、账户或UTXO集合、验证函数、网络成员、排序规则、确认条件和软件版本。按“构造交易 -> 本地签名 -> 邻居独立验证 -> 候选池 -> 打包或排序 -> 区块验证 -> 状态提交”记录每一步输入输出。只保存最后余额，会漏掉重复消费、错误签名被缓存、无效区块短暂传播或回滚未清理等问题。

正常样本使用两笔输入支付并找零；边界样本让输入恰好等于输出；单故障样本只破坏签名、前块摘要、背书数量或读版本中的一项。三组样本除该变量外保持相同，才能把拒绝原因归因到目标规则。随机网络实验保存种子、消息顺序和超时，不以一次收敛证明协议活性。

## 六类复核证据

### 状态与所有权合同

列出链上对象的唯一标识、所有者或解锁条件、当前版本和允许的状态转移。UTXO模型检查引用与未花费性，账户模型检查发送者、nonce与余额；两者不能共用一个含糊的“余额正确”断言。

### 密码与编码合同

记录哈希和签名算法、参数、密钥来源、随机数、序列化与地址校验。编码只解决传输表示，哈希只提供摘要，签名只证明相应私钥授权；真实性、保密性与业务合法性需要额外证据。

### 网络与共识合同

保存节点身份、连接、消息、传播顺序、故障模型、候选集合和规范历史选择。共识安全性与活性分别验证；暂时不出块和两个节点接受冲突最终状态是不同故障，不能只用平均TPS描述。

### 执行与平台合同

合约或链码记录前状态、调用者、输入、读写集、资源消耗、事件和后状态。失败执行必须原子回滚，外部服务和预言机响应进入证据，避免把链外副作用误当成虚拟机可回滚状态。

### 攻击与恢复合同

每个风险写出资产、攻击者能力、入口、首个可观测异常、影响和恢复边界。私钥丢失、多数重组、合约权限泄漏与数据增长的恢复手段不同；“不可篡改”不能替代备份、暂停、升级和治理。

### 发布与独立复核合同

独立复核者从空目录读取来源与配置，先手算最小状态，再运行正常、边界和单故障样本。哈希、签名、事件、余额、拒绝原因和最终状态逐项一致后才发布；任何缺失证据都进入隔离清单而非静默跳过。

## 容易踩的坑

**现象 →** SPV 轻钱包显示交易已确认 6 个区块，但全节点查不到这笔交易，余额凭空消失。
**原因 →** 轻钱包只验证 Merkle 证明包含性，不独立验证区块头工作量，恶意全节点可以伪造一条头链骗过轻钱包。
**修法 →** 轻钱包应从多个独立节点获取区块头并校验累计工作量；你可以用两个节点返回不同头链来亲眼看到轻钱包被骗的差异。

**现象 →** 交易广播后钱包显示"已发送"，几分钟后交易从内存池消失，余额恢复原值。
**原因 →** 交易只进入内存池尚未打包确认，可能因手续费过低被丢弃或被双花交易抢先确认。
**修法 →** 用确认深度而非广播成功判断结算，至少等待 k 个区块后才认为不可逆，并记录内存池状态变化。

**现象 →** 链遭 51% 攻击重组后，旧交易被"撤销"，但新链中的所有交易仍通过验证规则。
**原因 →** 共识攻击改变的是区块排序和历史选择，不改变本地验证规则；合法交易仍合法，只是被放入不同位置或被排除。
**修法 →** 区分"交易非法"和"交易被重组撤销"，高价值交易使用更多确认深度或等待最终性工具。

## 小结

- 分叉影响规则兼容，共识攻击影响历史排序而非交易合法性
- 轻钱包依赖诚实证明源，需多节点交叉校验区块头
- 私钥丢失可能不可逆，密钥生命周期必须审计
- 合约确定性不保证业务意图和权限配置正确
- 拥堵和数据增长需要容量治理和确认策略，非仅扩容

<Exercises>

**问题 1：** 软分叉和硬分叉在规则兼容性上有什么本质区别？各举一个例子说明对旧节点的影响。

<Answer>

软分叉是新规则比旧规则更严格，旧节点仍能接受新规则产出的区块（因为旧节点验证通过的范围更大），但旧节点可能接受被新规则拒绝的区块，导致临时分叉。例如比特币 SegWit 升级：旧节点不理解见证数据但仍接受区块。硬分叉是新规则与旧规则不兼容，旧节点会拒绝新规则产出的区块，导致永久分叉。例如以太坊 TheDAO 硬分叉：不支持回滚代码的节点继续在原链（ETC）上运行。

</Answer>

**问题 2：** 为什么 51% 攻击不能伪造任意交易？攻击者实际能做到什么？

<Answer>

51% 攻击控制的是出块权（排序），不是交易验证权。攻击者无法伪造他人签名，因此不能凭空创造交易或盗用他人 UTXO。攻击者实际能做到的是：（1）重组历史，把自己的交易从已确认区块中撤销（双花）；（2）审查交易，拒绝打包特定交易；（3）临时阻止其他矿工的区块被确认。但所有新区块中的交易仍必须通过每个节点的本地验证规则。

</Answer>

**问题 3（独立实现）：** 独立实现一个简化版 SPV 验证函数：给定交易哈希、Merkle 路径（兄弟节点哈希列表）、区块头 Merkle 根和方向标记列表（0=左兄弟，1=右兄弟），验证交易是否包含在该区块中。返回 True 或 False。

<Answer>

```python
import hashlib

def verify_merkle_proof(tx_hash, sibling_hashes, merkle_root, directions):
    current = tx_hash
    for sibling, direction in zip(sibling_hashes, directions):
        if direction == 0:
            current = hashlib.sha256(
                (sibling + current).encode("utf-8")
            ).hexdigest()
        else:
            current = hashlib.sha256(
                (current + sibling).encode("utf-8")
            ).hexdigest()
    return current == merkle_root
```

验证要点：改变 tx_hash、任一 sibling_hash 或 directions 中的任一方向标记，结果应从 True 变为 False。这正是 SPV 轻钱包验证交易包含性的核心逻辑——不需要下载全部交易，只需 O(log n) 大小的 Merkle 路径。

</Answer>
