# LLM应用生态全景

## 学习目标

完成本章学习后，你将能够：

1. 理解 LLM 应用生态的四层技术栈架构
2. 掌握模型层、编排层、工具层、应用层各自的角色与代表技术
3. 厘清闭源 API 与开源模型的选型维度
4. 明确从模型到应用的技术选型决策路径

## 核心概念

### 四层技术栈

LLM 应用生态由四层技术栈构成，自底向上层层叠加：

上图展示了 LLM 应用的四层技术栈：模型层提供核心能力，编排层负责组件组合，工具层提供存储与增强，应用层面向用户场景。

### 模型层

模型层是 LLM 应用的能力底座，分为四类：

- **闭源 API**：GPT-4、Claude、Gemini——能力最强、即开即用，但数据出域、成本随量
- **开源模型**：LLaMA、Mistral、Qwen、Falcon——可私有化部署、可微调，但需自备算力
- **嵌入模型**：text-embedding、BGE、E5——将文本转为向量，是 RAG 的基础
- **多模态模型**：GPT-4V、LLaVA、CLIP——处理图像、音频等非文本输入

### 编排层

编排层负责将模型能力组合为完整流程，核心框架包括：

- **LangChain**：生态最全，提供 Models、Prompts、Chains、Memory、Agents、Retrievers 六大组件
- **LlamaIndex**：RAG 专精，数据连接能力强，适合文档检索与知识库场景
- **Semantic Kernel**：微软生态，Plugin 编排模式，与 Azure 深度集成
- **Haystack**：Pipeline 设计，类型安全，适合生产级 RAG 系统

### 工具层

工具层提供存储、加载、评测和观察能力：

| 类别 | 代表工具 | 作用 |
|------|----------|------|
| 向量数据库 | Pinecone、Chroma、Weaviate、FAISS | 存储和检索嵌入向量 |
| 文档加载 | PDF/HTML/Markdown Loader | 将多格式文档转为文本 |
| 评测工具 | RAGAS、TruLens、LangSmith | 评估 RAG 质量与应用效果 |
| 观测平台 | Phoenix、Langfuse、WandB | 追踪调用链路、监控性能 |

### 应用层

应用层是面向用户的最终产品形态：

- **对话助手**：Chatbot、客服、FAQ 问答
- **RAG 系统**：知识问答、文档检索、企业搜索
- **Agent**：自主任务执行、工具调用、多步规划
- **Copilot**：代码助手、办公辅助、写作伴侣

### 核心选型维度

构建 LLM 应用时需在四个维度间权衡：

1. **能力与成本**：闭源 API 能力强但成本高，开源模型成本低但需运维
2. **数据隐私**：敏感数据需私有化部署，非敏感可用云 API
3. **延迟与吞吐**：实时场景需低延迟，批处理场景可牺牲延迟换吞吐
4. **可观测性**：生产系统需全链路追踪与成本监控

## 术语表

- **闭源 API**：由模型提供商托管的 LLM 接口，按调用量计费，数据需传输到提供商服务器
- **开源模型**：可下载部署的 LLM，支持私有化和微调，需自备 GPU 算力
- **编排框架**：将 LLM、提示、检索、记忆等组件组合为完整应用的开发框架
- **向量数据库**：专门存储和检索高维向量的数据库，是 RAG 的基础设施
- **可观测性**：对 LLM 应用的调用链路、性能指标、成本进行追踪和监控的能力
