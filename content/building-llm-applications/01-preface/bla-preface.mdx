# Preface：先建立可复现的学习合同

Preface 不是一段礼貌性的开场白，而是读者与实践环境之间的第一份合同。它要说明谁适合阅读、书覆盖什么、怎样取得配套资源、遇到问题向谁求助，以及哪些内容属于 2024 年出版时的模型和服务坐标。只有这些边界明确，后面的提示、检索、工具、代码和微调实验才有可比较的起点。

## 为什么先冻结应用合同

直觉上，读者只要复制一个 notebook 就能得到同样的回答；实际上，Python、依赖、模型端点、词元器、提示模板、数据快照、随机参数和工具权限都会改变结果。一次成功的请求只证明某个环境完成了一次计算，不证明换机器、换版本或换输入后仍然满足任务。

先预测：如果依赖升级后回答改变，应该先检查模型、提示还是环境？如果学习者只报告“报错了”，支持者能否复现？如果配套资源的链接仍然存在但提交版本已经变化，是否仍可称为同一个实验？本页用三个小实验把这些问题转换为输入、证据、责任主体和下一步动作。

<Callout type="trap">**现象：**样例可以运行，就把 Preface 的准备工作视为结束；**原因：**没有冻结环境、任务合同和预期结构；**修法：**在首次调用前保存版本、输入、输出约束和可重放记录。</Callout>

<Callout type="trap">**现象：**把书中模型、框架和云服务名称当成今天的稳定接口；**原因：**忽略出版时间、服务端默认值和依赖升级；**修法：**标注历史坐标、当前替代和重新测试项，禁止静默替换。</Callout>

<Callout type="trap">**现象：**遇到问题只发一张错误截图；**原因：**缺少最小输入、版本、日志和预期结果；**修法：**提交复现包，让另一位读者能从同一状态开始诊断。</Callout>

## 六个 Preface 术语

学习环境首先需要 `<Term def="描述读者任务、输入、输出、拒答条件和成功指标的可执行边界">Environment Contract</Term>`，它把“跟着做”转成可验收任务。读者定位依赖 `<Term def="说明目标读者已有知识、承担的任务和需要补齐的前置能力">Learning Audience</Term>`，否则同一个示例无法判断是难度适配问题还是实现问题。

书目与代码的时间边界用 `<Term def="区分出版时示例、本站独立重放、当前替代实现和未知项的来源标记">Source Boundary</Term>` 表达；环境可重复性则依赖 `<Term def="固定直接与传递依赖、运行时和模型工具版本的机器可读记录">Dependency Lock</Term>`。

遇到问题时，`<Term def="包含版本、最小输入、命令、日志、预期和实际结果的可复现问题材料">Reproduction Packet</Term>` 让求助从描述变成证据。长期学习还需要 `<Term def="由提问、复现、解释、修复和回归验证组成的支持交接流程">Support Loop</Term>`，它把一次答疑沉淀为下一位读者可使用的知识。

## 最小运行记录与门禁代码

Preface 阶段不要求立刻搭建完整 Agent，但要求每次运行都有可读的合同。下面的 Python 记录任务、版本、提示、数据和工具；TypeScript 版本用只读对象防止调用后悄悄改写输入。

<CodeTabs>
  <Tab label="Python / 运行记录">

```python
def freeze_request(task, runtime, prompt, data_hash, tools, seed):
    return {
        "task": task,
        "runtime": runtime,
        "prompt": prompt,
        "data_hash": data_hash,
        "tools": tuple(tools),
        "seed": seed,
    }
```

  </Tab>
  <Tab label="TypeScript / 资源门禁">

```typescript
type RunRecord = {
  input: unknown;
  config: unknown;
  output: unknown;
  judgment: unknown;
  limits: unknown;
};

function releaseGate(records: RunRecord[]) {
  const required: (keyof RunRecord)[] = [
    "input", "config", "output", "judgment", "limits",
  ];
  const missing = records
    .map((record, index) =>
      required.every((key) => key in record) ? -1 : index,
    )
    .filter((index) => index >= 0);
  return { pass: missing.length === 0, missing };
}
```

  </Tab>
</CodeTabs>

正常记录包含完整字段；边界记录让输入为空、输出超长或工具列表为空；单变量故障只移除一个字段或改变一个版本。拒绝时返回缺失字段和记录索引，不要用默认值补齐后继续发布。这样，错误会在可解释的门禁处停止，而不是在最后一句模型文本里才暴露。

## Preface 的阅读顺序

把 Preface 当作一次短的工程验收：先确认读者与任务，再确认书的范围和版本，然后拿到配套资源，最后建立求助与迁移路径。进入正文后，任何新的框架或模型都要回到这四个问题：它改变了哪个输入，增加了哪个责任，产生了哪些证据，失败后怎样恢复。

### Preface

Preface 的主任务是固定阅读合同。这里的输出不是一段口号，而是读者、范围、环境、资源、求助渠道和成功条件的清单；后续章节可以据此解释为什么一个实验算完成或需要暂停。

### Who this book is for

Who this book is for 让读者判断自己是否拥有 Python、API、数据和应用开发的前置能力。缺少某项能力时，应先选择补充路线并记录假设，不应把环境不匹配误判成模型或框架本身失效。

### What this book covers

What this book covers 划定模型基础、编排、提示、检索、会话、搜索、结构化数据、代码、多模态、微调和 Responsible AI 的范围。地图不会把每个章节承诺成生产配方，读者要区分概念演示、可运行样例和上线所需的额外控制。

### To get the most out of this book

To get the most out of this book 要求读者边读边运行、保存中间状态并提出可复现问题。最有效的学习记录不是“我看过了”，而是一次固定输入、一次正常结果、一个边界条件和一个能解释的失败原因。

### Get in touch

Get in touch 提供沟通入口，但沟通质量取决于上下文。提问时应带上章节、运行环境、依赖锁、最小输入、完整错误、预期结果和已经尝试过的变化，避免把诊断成本转移给回答者。

### Making the Most Out of This Book – Get to Know Your Free Benefits

Making the Most Out of This Book – Get to Know Your Free Benefits 的价值在于把附带材料视为可验证资源。下载包、代码、样例数据和说明都要记录来源、版本、许可和哈希；资源可获得不等于资源适合当前环境。

### Unlock Your Book’s Exclusive Benefits

Unlock Your Book’s Exclusive Benefits 强调资源领取和账户操作的边界。学习者只应提交必要信息，保存领取时间和版本，不要把第三方下载页、模型密钥或个人数据直接放进公开仓库。

### How to unlock these benefits in three easy steps

How to unlock these benefits in three easy steps 可以被复写成“确认身份、取得资源、验证内容”三个状态。每一步都要有成功条件和失败处理，例如链接失效时记录来源并请求替代，不以下载成功掩盖文件不完整。

### Need help?

Need help? 是支持闭环的终点入口。一个可行动的问题应让维护者能从固定环境开始复现；解释之后还要把修复步骤加入回归记录，让同一问题不必由每位读者重新摸索。

## 六类 Preface 证据

### 读者与任务证据

保存目标读者、前置知识、使用场景、成功指标、拒答条件和最小反例。不同读者可以选择不同路径，但每条路径都要说明进入条件与离开条件。

### 出版与来源证据

保存作者、出版社、版本、日期、页数、ISBN、官方产品页和目录映射。书中模型、框架与服务名称带有历史时间，本站重放和当前替代必须另外标记。

### 环境与依赖证据

保存 Python、操作系统、运行时、直接依赖、传递依赖、模型端点、词元器和配置哈希。锁文件解决可复现性的一部分，仍要记录外部服务的版本和响应差异。

### 配套资源证据

保存代码仓库提交、数据文件哈希、许可证、下载时间、校验命令和文件结构。资源发生变更时建立新快照，不覆盖旧证据，让读者知道差异来自哪里。

### 求助与隐私证据

保存最小复现、日志、错误对象和已尝试步骤，同时删除 API 密钥、个人数据、私有提示和生产样本。求助材料既要足够诊断，也要限制泄露范围。

### 迁移与回退证据

保存历史行为、当前替代、接口差异、重新测试结果、已知风险和回退版本。若新依赖改变输出，应把它视作一次需要复核的迁移，而不是在说明中悄悄改掉历史结论。

## 容易踩的坑

<Callout type="trap">**现象：**复制样例后只报告“模型回答不一样”；**原因：**没有记录版本、提示、数据快照和解码设置；**修法：**提交 Reproduction Packet，让差异可以沿输入、配置和输出逐项定位。</Callout>

<Callout type="trap">**现象：**下载链接还能打开，就认为配套代码可用；**原因：**没有校验提交、依赖、许可证和文件完整性；**修法：**保存资源哈希与校验命令，发现变更时建立新快照。</Callout>

<Callout type="trap">**现象：**把求助帖中的密钥、个人数据或生产样本一并上传；**原因：**把“可复现”误解为“公开所有原始材料”；**修法：**脱敏并缩小权限，只保留足以诊断的最小输入。</Callout>

## 小结与发布清单

- 用 Environment Contract 固定读者、任务、环境、资源、求助和成功条件。
- 用 Source Boundary 区分出版时语境、本站重放、当前替代和未知项。
- 用 Dependency Lock 与 Reproduction Packet 让样例和问题可以被另一人重跑。
- 资源领取、隐私保护、迁移复测和回退版本都是 Preface 的工程边界。
- 发布前确认来源、输入、配置、输出、判断、限制和复现路径完整。

## 练习与答案

<Exercises>

**问题 1：**一个读者报告“同一提示在今天返回不同答案”，请列出最先需要的五类复现信息。

<Answer>
  需要任务与最小输入、模型和端点版本、提示与解码配置、数据/检索快照、运行时与依赖锁；如果使用工具，还要保存工具白名单、参数和回执。随后比较两次输出与判断规则，不能只比较最终文本。
</Answer>

**问题 2：**为什么下载到配套代码还不能证明实验环境准备完成？

<Answer>
  文件可能来自不同提交，依赖可能已升级，数据可能缺少许可或哈希，模型端点也可能改变行为。准备完成需要来源、提交、依赖、配置、输入、校验命令和预期输出都能被记录，并用最小样例验证一次。
</Answer>

**问题 3（独立实现）：**实现一个 `release_gate`，拒绝缺少 `input`、`config`、`output`、`judgment` 或 `limits` 的记录，并返回缺失记录的索引。

<Answer>
  先定义必需字段集合，遍历记录并检查集合是否为当前记录的子集；不满足时保存索引，最后返回 `pass = missing.length == 0` 和 `missing`。函数只返回门禁结果，不修改任何运行记录，这样调用者可以补证据后重新提交。
</Answer>

</Exercises>
