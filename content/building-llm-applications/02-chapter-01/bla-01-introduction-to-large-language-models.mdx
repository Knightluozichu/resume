# Chapter 1：从语言表示到可审计的模型能力

大型语言模型不是一个把文字直接变成答案的单一函数，而是一条由数据、词元、表示、训练目标、评估协议和应用边界组成的证据链。本章把“模型很大”拆成可以检查的对象：输入怎样被切分，Transformer 怎样混合上下文，训练怎样获得基座能力，评估怎样避免自我证明，以及定制怎样改变成本和回滚责任。

先预测：如果只改变词元器、数据切分或模型定制方式，哪一个中间对象会先变化？把你的猜测写下来，再使用三个交互实验验证。实验中的分数和标签是教学用合成数据，重点是训练你在看到漂亮答案之前先找表示快照、数据边界、逐样本判断和回滚路径。

<Callout type="trap">**现象：**输出语气自信、结构完整，就把它当作事实；**原因：**把生成概率和外部真值混为一谈；**修法：**单独记录来源、验证规则和拒答条件，要求答案通过与任务相称的证据门。</Callout>

<Callout type="trap">**现象：**参数更多就默认架构更适合当前任务；**原因：**只看规模，忽略上下文长度、数据分布、延迟和部署约束；**修法：**在固定任务与预算下比较中间表示、逐样本质量和尾延迟。</Callout>

<Callout type="trap">**现象：**微调后一个样例变好就直接上线；**原因：**没有测量遗忘、数据泄漏、成本和回滚窗口；**修法：**保留基座对照、隔离评测集和可回退候选版本，再做发布判断。</Callout>

## 六个核心术语

`<Term def="在大量未针对单一任务的数据上学习、可被多个下游任务复用的模型">Foundation Model</Term>` 是能力的起点，不是某个具体应用的验收结论。LLM 说明以语言 token 为主要输入输出的模型类别，但不承诺事实性、推理能力或安全性；`<Term def="输入文本被切分为 token 时记录的字符区间和边界">Token Boundary</Term>` 则把这个输入过程变成可检查证据。

`<Term def="把 token 表示映射为上下文表示的注意力网络结构">Transformer</Term>` 是一种表示与计算结构；`<Term def="利用大规模数据学习下一 token 分布等通用能力的训练阶段">Pretraining</Term>` 是获得基座参数的过程。`<Term def="与训练数据隔离、用于估计模型在未知样本上表现的数据集合">Evaluation Set</Term>` 负责提供外部检查，`<Term def="通过提示、检索、适配器或更新参数改变模型行为的工程过程">Customization</Term>` 则改变应用所承担的验证与运营责任。

## 一个可运行的最小检查器

下面的代码把词元和字符区间一起保存，便于确认“同一句文本”是否真的经过了同一个输入表示。第二段代码将训练、评估和审计的必需字段列成门禁，缺证据时返回索引，而不是用默认值让流水线继续。

<CodeTabs>
  <Tab label="Python / 词元边界">

```python
def tokenize_with_boundaries(text, vocab):
    tokens = []
    cursor = 0
    for word in text.split():
        start = text.index(word, cursor)
        end = start + len(word)
        tokens.append({"text": word, "id": vocab.get(word, 0), "span": [start, end]})
        cursor = end
    return tokens
```

  </Tab>
  <Tab label="TypeScript / 评估门禁">

```typescript
type EvaluationRecord = {
  sampleId?: string;
  split?: "train" | "validation" | "test";
  output?: string;
  judgment?: string;
};

function evaluationGate(records: EvaluationRecord[]) {
  const missing = records
    .map((record, index) => {
      const complete = record.sampleId && record.split && record.output && record.judgment;
      return complete ? -1 : index;
    })
    .filter((index) => index >= 0);
  return { pass: missing.length === 0, missing };
}
```

  </Tab>
</CodeTabs>

词元边界让输入差异可定位，评估门禁让训练集和评测集不会被同一份记录悄悄混合。真实系统还应把模型版本、提示、随机参数、数据哈希、工具权限、延迟和成本放进运行记录；这一步的目标是建立最小证据结构，而不是假装一个小函数已经完成生产级评估。

## 从表示到训练目标

### Chapter 1: Introduction to Large Language Models

“Chapter 1: Introduction to Large Language Models”的主线是把模型能力放回数据和评估边界。阅读时同时标记输入表示、训练信号、外部验证和应用责任四个层次，避免把书中的概念说明误读为特定厂商的部署保证。

### What are large foundation models and LLMs?

“What are large foundation models and LLMs?”回答的是类别和用途边界：基础模型可以复用，LLM通常以 token 序列处理语言，但二者都需要任务数据、指标和拒答条件才能进入应用。先用同一组样本区分能力描述与验收结论。

### AI paradigm shift – an introduction to foundation models

“AI paradigm shift – an introduction to foundation models”强调从单任务模型到可迁移基础能力的工程转向。迁移带来更快的原型速度，也把数据许可、提示暴露、资源成本和人类审核责任推到应用团队面前。

### Under the hood of an LLM

“Under the hood of an LLM”需要沿着 token、向量表示、层间上下文混合和下一 token 分布追踪一次请求。内部状态不是可直接阅读的理由，因此应把可观察的表示快照、输出和外部判断分开保存。

### Most popular LLM transformers-based architectures

“Most popular LLM transformers-based architectures”不应被读成静态排行榜。比较架构时要固定任务、数据、上下文窗口、硬件、吞吐与评估脚本，再说明哪些差异来自编码器、解码器或混合结构，哪些只是服务配置差异。

### Early experiments

“Early experiments”提供低成本的直觉入口：先用很小的词表、短上下文和可控数据观察预测变化，再逐渐增加层数与数据规模。小实验的价值在于暴露假设，不在于用玩具结果预测生产模型的绝对性能。

### Introducing the transformer architecture

“Introducing the transformer architecture”把注意力理解为依据查询、键和值重新组合上下文的计算步骤。练习时记录序列长度、掩码方向和位置处理；同一个词在不同上下文中的表示变化，是比一句生成文本更早的证据。

### Training and evaluating LLMs

“Training and evaluating LLMs”要求把优化过程和外部检验拆开。训练损失、验证指标、测试集结果、人工判断、延迟、成本和安全失败各自回答不同问题，不能用一条漂亮曲线代替全部发布证据。

### Training an LLM

“Training an LLM”涉及数据清洗、token 化、批次、目标函数、检查点和资源预算。训练记录至少要能回溯数据快照、代码提交、硬件和随机种子；当检查点改变时，必须重新关联评估报告，不能覆盖旧版本。

### Model evaluation

“Model evaluation”是对未知样本和真实任务约束的受控检查。评估集要与训练数据隔离，样本要覆盖正常路径、边界输入和拒答情形，报告要保留逐样本结果，避免平均数遮住少量高影响失败。

### Base models versus customized models

“Base models versus customized models”比较的是责任边界，而不是简单的强弱排序。基座模型提供通用起点，提示与检索改变请求合同，微调还会改变权重或适配器；每种方式都需要独立的成本、风险和回滚证据。

### How to customize your model

“How to customize your model”应从最小改变开始：先固定基座，尝试提示，再评估检索或适配器，最后才考虑更重的参数更新。每一步都比较新增能力是否值得训练成本，并检查数据泄漏、灾难性遗忘和版本回退。

### Summary

“Summary”把本章收束为四个动作：检查表示，隔离训练与评估，选择合适的定制深度，保存发布所需证据。若不能说明差异发生在哪个中间节点，就不应只凭最终文本宣称模型能力已经改善。

### References

“References”用于标记本章的书目来源、官方产品页和独立重写边界。原书坐标保留历史语境；当前实现、接口和模型行为必须另行验证，引用存在不等于每个示例在今天仍可直接运行。

## 表示、训练与定制的六个判断

### 1. 表示层的判断

词元器决定字符如何进入模型，位置与注意力决定上下文如何被组合。做对照时先保存 token 文本、ID、区间和窗口，再比较表示或生成结果；这样才能知道差异是在输入阶段发生，还是在后续解码阶段发生。

### 2. 基础模型的判断

基础模型的“通用”意味着训练目标和数据覆盖较广，不意味着它知道你的私有事实，也不意味着它自动遵守业务权限。下游应用仍然需要来源、检索、结构校验、人工升级和拒答设计。

### 3. 训练目标的判断

下一 token 预测能训练语言连续性，却不能单独保证真值、因果理解或任务规范。目标函数、数据分布和奖励信号共同塑造行为；当应用指标变化时，要追问是哪一类训练证据支持这个结论。

### 4. 评估边界的判断

独立评测集的作用不是给模型颁奖，而是制造模型没有见过的检查。切分策略、时间范围、标签质量和失败成本都应写进报告；如果评估集被用于反复调参，它就不再是原先意义上的外部检验。

### 5. 定制方式的判断

提示定制通常改输入合同，检索定制补充外部知识，微调或适配器改变参数行为。越靠近参数，长期运营和回滚责任越重；越靠近请求，运行时成本与上下文管理越重要，三者都要用同一套任务指标比较。

### 6. 发布证据的判断

发布不是看到分数超过阈值就结束，而是确认输入、版本、数据、输出、判断、限制和回滚都能被重放。若任何一类证据缺失，应返回可行动的补证据任务，并保留当前候选版本以便审计。

## 容易踩的坑

<Callout type="trap">**现象：**只看训练损失下降就认为模型已经学会目标任务；**原因：**优化指标与外部任务指标并不相同；**修法：**冻结独立评估集，报告逐样本质量、成本、延迟和失败类别。</Callout>

<Callout type="trap">**现象：**把提示、检索和微调统称为“定制”，然后沿用同一套回滚办法；**原因：**没有区分改变请求还是改变参数；**修法：**为每种方式记录改变对象、版本、成本、数据许可和恢复路径。</Callout>

<Callout type="trap">**现象：**把评估集反复拿来调参后仍称为独立测试；**原因：**调参反馈已经泄漏进模型选择；**修法：**建立新的隔离测试集，并记录样本何时、由谁、为何被使用。</Callout>

## 小结与学习验收

- 先检查词元边界和上下文表示，再讨论一段文本是否流畅。
- 把预训练、评估和审计的产物分开，训练损失不能替代外部验证。
- 以任务、预算和风险比较基座、提示定制与微调，而不是默认参数越多越好。
- 每个模型结论都要带输入、版本、数据切分、逐样本判断、限制和回滚证据。
- 发布前回答：哪里发生变化、谁能复核、失败如何阻断、候选如何恢复。

## 练习与答案

<Exercises>

**问题 1：**同一段文本使用两个词元器后输出不同。请列出最先应保存的证据，并说明为什么不能只比较最终回答。

<Answer>
  保存词元文本与 ID、字符区间、上下文窗口、模型版本、解码设置和两次输出。词元边界已经改变输入表示，最终回答的差异可能在输入阶段就产生；没有中间快照，就无法判断是表示、注意力还是解码导致变化。
</Answer>

**问题 2：**训练损失持续下降，但独立评测集的事实性没有改善。请给出两个合理解释和一个验证动作。

<Answer>
  可能是训练数据分布与任务不同，也可能是目标函数奖励语言连续性而不是事实验证；还应检查评测标签和数据切分是否稳定。验证时保留旧检查点，在同一独立集合上做逐样本对照，并按错误类型和成本重新统计。
</Answer>

**问题 3（独立实现）：**实现一个 `customization_gate`，输入基座、提示和微调三种候选，只有当质量、成本、遗忘和泄漏字段都存在时才返回可发布。

<Answer>
  先为每个候选保存 `quality`、`cost`、`forgetting`、`leakage` 与 `rollback`，再检查字段是否齐全以及是否满足预设阈值。返回候选名、缺失字段和阻断原因；不要在字段缺失时使用零值，因为零值会把“没有测量”伪装成“没有风险”。
</Answer>

</Exercises>
