# 提示工程实践

## 学习目标

完成本章学习后，你将能够：

1. 掌握提示结构的四要素及其设计原则
2. 理解六种提示策略的原理、适用场景与优缺点
3. 运用提示工程最佳实践优化 LLM 输出质量
4. 针对不同任务选择合适的提示策略组合

### 提示策略矩阵

从简单到复杂，六种策略逐步增强 LLM 的推理能力：

**Zero-shot**：直接给指令，不给示例。适用于简单任务和能力强的模型。优点是零成本，缺点是输出格式不稳定。

**Few-shot**：给少量示例引导输出风格。适用于格式控制和风格模仿。通过 2-5 个示例锚定期望的输出模式。

**Chain-of-Thought (CoT)**：引导模型逐步推理。在提示中加入「让我们一步一步思考」或给出推理过程的示例。适用于数学推理、逻辑分析和多步任务。

**Self-Consistency**：对同一问题多次采样取多数票。通过温度调节生成多个推理路径，选择出现频率最高的答案。适用于需要高准确率的推理任务。

**ReAct**：推理与行动交替执行。模型先思考（Thought），再决定行动（Action），观察结果（Observation），循环往复。是 Agent 的基础范式。

**Structured Output**：用 JSON Schema 约束输出结构。通过 Function Calling 或输出解析器确保返回可程序化处理的结构化数据。适用于 API 对接和数据提取。

### 温度参数调控

温度（Temperature）控制输出的随机性：

- **温度 = 0**：确定性输出，每次结果相同——适合事实问答、数据提取
- **温度 = 0.3-0.5**：低随机性——适合总结、翻译
- **温度 = 0.7-1.0**：中等随机性——适合对话、创意写作
- **温度 > 1.0**：高随机性——适合头脑风暴、发散思考

### 提示工程最佳实践

1. **明确具体**：指令越清晰，输出越可控。避免模糊表述
2. **分步拆解**：复杂任务拆为子任务链，每步聚焦一个目标
3. **正面表述**：说「做什么」而非「不做什么」，模型对正面指令更敏感
4. **示例引导**：用 Few-shot 锚定输出格式，比纯描述更有效
5. **迭代调优**：A/B 测试加 bad case 回溯，持续优化提示
6. **温度调控**：创造性任务调高温度，事实任务调低温度

## 术语表

- **Zero-shot**：不给示例直接让模型完成任务，依赖模型预训练能力
- **Few-shot**：给少量输入输出示例引导模型按期望模式输出
- **Chain-of-Thought (CoT)**：引导模型展示推理过程而非直接给答案
- **ReAct**：Reasoning + Acting 范式，推理与行动交替循环
- **温度（Temperature）**：控制 LLM 输出随机性的参数，值越高输出越发散
