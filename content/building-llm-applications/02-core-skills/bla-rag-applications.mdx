# RAG应用开发

## 学习目标

完成本章学习后，你将能够：

1. 理解 RAG 的两阶段架构（离线索引 + 在线检索生成）
2. 掌握文档加载、分块、嵌入、存储、检索、重排、生成的完整流程
3. 区分 Naive RAG、Advanced RAG、Modular RAG 三种范式
4. 根据场景做出 RAG vs 微调的技术决策

## 核心概念

### RAG 核心思想

RAG（Retrieval Augmented Generation，检索增强生成）通过在生成前检索外部知识来增强 LLM 的回答能力。它解决了 LLM 的三个核心问题：知识截止日期、幻觉、无法引用溯源。

### 索引阶段（离线构建）

索引阶段将原始文档转化为可检索的向量索引：

1. **文档加载**：使用 Loader 将 PDF、HTML、Markdown、数据库等多种格式的文档转为纯文本
2. **分块（Chunking）**：将长文档切分为适当大小的块。常见策略有固定长度分块（如 512 token）和语义分块（按段落或主题）
3. **嵌入（Embedding）**：用嵌入模型将每个文本块转为高维向量
4. **存储**：将向量存入向量数据库（FAISS、Chroma、Pinecone），构建索引以支持快速检索

### 检索生成阶段（在线查询）

用户查询时，RAG 系统执行以下流程：

1. **查询嵌入**：将用户问题用同一嵌入模型转为向量
2. **向量检索**：在向量数据库中检索 Top-K 最相似的文档块
3. **重排序（Rerank）**：用 Cross-Encoder 对检索结果重新排序，提高精度
4. **上下文拼接**：将检索到的文档块拼入提示模板
5. **LLM 生成**：将拼好的提示发给 LLM，生成最终回答

### 三种 RAG 范式

| 范式 | 特点 | 优点 | 缺点 |
|------|------|------|------|
| Naive RAG | 检索-拼接-生成 | 简单易实现 | 检索质量不稳定 |
| Advanced RAG | 查询改写+重排序 | 质量更高 | 复杂度增加 |
| Modular RAG | 检索+记忆+路由 | 模块化可插拔 | 工程量大 |

**Naive RAG** 是最基础的形式，直接检索文档块拼入提示。**Advanced RAG** 在检索前做查询改写（如多查询生成、HyDE），在检索后做重排序，显著提升检索质量。**Modular RAG** 将 RAG 拆为可插拔模块（检索、记忆、路由、融合），支持更灵活的组合。

### RAG vs 微调

| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时更新，改数据库即可 | 需重新训练 |
| 引用溯源 | 可引用原文来源 | 无法溯源 |
| 适用场景 | 知识频繁变化、需引用 | 固定领域风格、特定格式 |
| 成本 | 检索+推理双重成本 | 训练成本高，推理成本低 |
| 延迟 | 检索增加延迟 | 无额外延迟 |

两者互补而非互斥：先微调模型风格与格式，再叠加 RAG 补充领域知识，是生产系统的常见做法。

## 术语表

- **RAG（Retrieval Augmented Generation）**：检索增强生成，通过检索外部知识增强 LLM 回答
- **嵌入（Embedding）**：将文本转为高维向量的过程，使语义相似的文本向量距离更近
- **向量数据库**：存储和检索高维向量的专用数据库，支持相似度搜索
- **分块（Chunking）**：将长文档切分为适当大小的块，是检索精度的关键
- **重排序（Rerank）**：用 Cross-Encoder 对初步检索结果重新排序，提高精度
