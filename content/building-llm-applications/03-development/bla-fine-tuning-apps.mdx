# 微调应用开发

## 学习目标

完成本章学习后，你将能够：

1. 理解微调的全流程：数据收集到评测部署
2. 掌握全参数微调、LoRA、QLoRA、Prefix Tuning 四种方法的原理与适用场景
3. 运用提示工程、RAG、微调的决策矩阵选择技术路线
4. 理解 LoRA 低秩分解的数学原理

## 核心概念

### 何时需要微调

微调不是 LLM 应用的第一步。正确的优先级是：先穷尽提示工程，再考虑 RAG 补充知识，最后才用微调定制能力。微调适用于提示和 RAG 都无法解决的场景：固定领域风格、特定输出格式、降低推理成本（蒸馏小模型）。

### 微调全流程

上图展示了微调的完整体系：五步全流程、四种方法对比和决策矩阵（提示工程 / RAG / 微调）。

微调全流程包含五个步骤：

1. **数据收集**：准备指令-回答对（SFT）或偏好对（DPO），通常需要 500-5000 条高质量数据
2. **数据清洗**：去重去噪、格式统一、质量过滤——数据质量决定微调效果上限
3. **训练配置**：设定学习率、Epoch、Batch Size，选择微调方法（LoRA / QLoRA）
4. **训练执行**：监控损失曲线，检测过拟合，适时早停
5. **评测部署**：在基准测试集上评估，A/B 对比原模型，通过后推理上线

### 四种微调方法对比

| 方法 | 原理 | 显存需求 | 效果 | 适用场景 |
|------|------|----------|------|----------|
| 全参数微调 | 更新所有参数 | 极大 | 最好 | 企业级、算力充足 |
| LoRA | 低秩适配器 | 中等 | 接近全量 | 最常用方案 |
| QLoRA | 4bit量化+LoRA | 极小 | 接近LoRA | 消费级GPU |
| Prefix Tuning | 前缀向量优化 | 极小 | 略逊LoRA | 多任务场景 |

### LoRA 数学原理

LoRA（Low-Rank Adaptation）的核心思想：预训练模型的权重更新是低秩的，可以用两个小矩阵的乘积近似。

给定原始权重矩阵 W（维度 d x k），LoRA 将权重更新表示为：

```
W' = W + delta_W = W + B * A
```

其中 A 是 r x k 维，B 是 d x r 维，r 远小于 d 和 k（如 r=8）。

训练时冻结原始权重 W，只训练 A 和 B。参数量从 d x k 降为 r x (d + k)，大幅减少显存需求。

QLoRA 在此基础上将基座模型量化为 4bit，进一步压缩显存，使 70B 模型可在单张 48GB GPU 上微调。

### 决策矩阵：提示 / RAG / 微调

| 场景 | 首选方案 | 理由 |
|------|----------|------|
| 通用问答 | 提示工程 | 零成本，改提示即可 |
| 格式调整 | 提示工程 | Few-shot 锚定格式 |
| 知识问答 | RAG | 知识可更新，可溯源 |
| 领域风格 | 微调 | 内化领域表达方式 |
| 特定格式输出 | 微调 | 稳定格式，降低延迟 |
| 降低推理成本 | 微调+蒸馏 | 小模型替代大模型 |

三者互补：先微调模型风格与格式，再叠加 RAG 补充实时知识，是生产系统的最佳实践。

## 术语表

- **微调（Fine-tuning）**：在预训练模型基础上用领域数据进一步训练，使模型适应特定任务
- **LoRA（Low-Rank Adaptation）**：低秩适配方法，用两个小矩阵近似权重更新，大幅减少训练参数
- **QLoRA**：在 LoRA 基础上将基座模型量化为 4bit，使大模型可在消费级 GPU 上微调
- **SFT（Supervised Fine-Tuning）**：监督微调，用指令-回答对训练模型学习指令遵循
- **早停（Early Stopping）**：当验证集损失不再下降时停止训练，防止过拟合
