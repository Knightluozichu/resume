# 编排框架与LangChain

## 学习目标

完成本章学习后，你将能够：

1. 理解 LangChain 六大核心组件的职责与协作关系
2. 掌握 LCEL 表达式语言的链式调用语法
3. 区分 Chains 与 Agents 两种编排模式
4. 根据场景选择合适的编排框架

## 核心概念

### 为什么需要编排框架

LLM 应用的核心挑战是把模型调用、提示管理、检索、记忆、工具调用等组件组合为完整流程。编排框架提供了统一的抽象层，让开发者像搭积木一样组装 LLM 应用。

| Retrievers | 检索器与RAG集成 | VectorStore、Multi-Query |

### LCEL 表达式语法

LangChain Expression Language (LCEL) 是 LangChain 的声明式语法，用管道符 `|` 串联组件：

```
chain = prompt | model | output_parser
result = chain.invoke("input")
```

LCEL 的核心优势：

- **流式输出**：支持 token 级流式返回，降低首字延迟
- **批量调用**：内置批量处理，提升吞吐量
- **异步支持**：原生 async/await，适合高并发场景
- **可组合**：任意 LCEL 链可作为更大链的子组件

### Chains vs Agents

**Chains（链）** 是预定义的执行路径：输入按固定顺序经过各组件。适合流程确定的任务。

**Agents（智能体）** 是动态决策路径：LLM 根据当前状态自主选择下一步操作。适合需要灵活决策的任务。

| 维度 | Chains | Agents |
|------|--------|--------|
| 执行路径 | 固定顺序 | 动态决策 |
| 可控性 | 高 | 低 |
| 灵活性 | 低 | 高 |
| 成本 | 可预测 | 不可预测 |
| 适用场景 | 流程确定的任务 | 需灵活决策的任务 |

### Memory 类型

| 类型 | 原理 | 适用场景 |
|------|------|----------|
| ConversationBufferMemory | 保留完整对话历史 | 短对话 |
| ConversationBufferWindowMemory | 只保留最近N轮 | 长对话控成本 |
| ConversationSummaryMemory | 用LLM总结历史 | 超长对话 |
| VectorStoreRetrieverMemory | 向量化存储历史 | 跨会话记忆 |

### 编排框架对比

| 框架 | 特点 | 适合场景 |
|------|------|----------|
| LangChain | 生态最全，组件丰富 | 快速原型与 Agent |
| LlamaIndex | RAG 专精，数据连接强 | 文档检索与知识库 |
| Haystack | Pipeline 设计，类型安全 | 生产级 RAG 系统 |

## 术语表

- **Chain（链）**：预定义执行路径的组件串联，输入按固定顺序经过各组件
- **Agent（智能体）**：由 LLM 自主决策执行路径的编排模式
- **LCEL**：LangChain Expression Language，用管道符串联组件的声明式语法
- **Memory**：管理对话历史和上下文信息的组件
- **Retriever**：从向量数据库等数据源检索相关文档的组件
