# Agent应用构建

## 学习目标

完成本章学习后，你将能够：

1. 理解 Agent 的核心推理循环（感知-推理-行动-观察）
2. 掌握 Agent 的四大组件：LLM大脑、记忆、工具集、规划
3. 区分 ReAct、Plan-and-Execute、Multi-Agent、Custom Agent 四种类型
4. 运用Agent设计要点构建可靠的 Agent 应用

## 核心概念

### 什么是 Agent

Agent 是能自主推理、规划和调用工具完成任务的智能体。与 Chains 的固定执行路径不同，Agent 由 LLM 自主决策下一步操作，能根据中间结果动态调整策略。

### 核心推理循环

上图展示了 Agent 的完整架构：中心是 LLM 大脑，上方是感知输入，左右是记忆和工具集，下方是行动输出和观察反馈回环，底部是四种 Agent 类型对比。

Agent 的核心是「感知-推理-行动-观察」循环：

1. **感知（Perception）**：接收用户任务或环境状态
2. **推理（Reasoning）**：LLM 分析当前状态，决定下一步行动
3. **行动（Action）**：调用工具执行操作（搜索、计算、API调用、代码执行）
4. **观察（Observation）**：获取行动结果，反馈给 LLM 进入下一轮循环

循环持续进行，直到任务完成或达到最大循环次数。

### 四大组件

| 组件 | 职责 | 实现方式 |
|------|------|----------|
| LLM 大脑 | 推理、决策、规划 | GPT-4 / Claude / 开源模型 |
| 记忆 | 上下文与经验积累 | 短期（对话历史）+ 长期（向量存储） |
| 工具集 | 执行具体操作 | 搜索、计算、API、代码执行、数据库 |
| 规划 | 分解复杂任务 | ReAct / Plan-and-Execute |

### 四种 Agent 类型

**ReAct Agent**：推理与行动交替执行，每轮先思考再行动。是最通用的 Agent 类型，适合大多数任务。

**Plan-and-Execute Agent**：先规划完整步骤，再逐步执行。适合复杂多步任务，规划阶段消耗较多 token 但执行阶段更高效。

**Multi-Agent**：多个 Agent 协作，各司其职。如一个 Agent 负责规划，一个负责执行，一个负责审核。适合角色分工的系统。

**Custom Agent**：自定义推理循环，针对特殊需求设计。如加入人工审核环节、自定义工具选择逻辑。

### Function Calling

Function Calling 是 Agent 调用工具的核心机制。LLM 接收工具的函数描述（名称、参数、返回值），自主决定调用哪个工具、传入什么参数，并解析返回结果。

工具描述的质量直接影响 Agent 的工具选择准确率。好的工具描述应包含：清晰的函数名、完整的参数说明、使用场景示例。

### Agent 设计要点

1. **工具描述清晰**：函数名和参数说明要明确，让 LLM 准确选择
2. **控制循环次数**：设置最大迭代数，防止无限循环消耗成本
3. **错误处理与重试**：工具调用可能失败，需要重试机制和降级策略
4. **结果验证**：对 Agent 输出做验证，防止错误结果传递
5. **成本与延迟可控**：Agent 多轮调用成本高，需要监控和限制
6. **人在回路兜底**：高风险操作需人工确认，避免 Agent 自主造成损失

## 术语表

- **Agent**：能自主推理、规划和调用工具完成任务的智能体
- **ReAct**：Reasoning + Acting 范式，推理与行动交替循环
- **Function Calling**：LLM 根据函数描述自主选择和调用工具的机制
- **Multi-Agent**：多个 Agent 协作完成任务的系统架构
- **人在回路（Human-in-the-loop）**：高风险操作需人工确认的安全机制
