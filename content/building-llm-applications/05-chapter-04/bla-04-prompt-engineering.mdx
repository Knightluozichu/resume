  pass: boolean;
  missing: number[];

  const required: (keyof RunRecord)[] = ["input", "config", "output", "judgment", "limits"];
  const missing = records
    .map((r, i) => (required.every((k) => k in r) ? -1 : i))
    .filter((i) => i >= 0);
  return { pass: missing.length === 0, missing };
}

## 从最小基线到应用

先实现没有记忆、检索和工具的最小模型调用，冻结五到十个正常样本及预期结构。然后每轮只加入一个能力：模板、少样本、检索、记忆、工具、代码执行或多模态输入。每一步都保留上一步基线，测量质量、延迟、成本和新引入的失败面。

输出验证分语法、语义、来源和权限四层。JSON可解析不代表事实正确；检索片段存在不代表回答受其支持；工具调用成功不代表参数获授权；前端显示顺畅也不代表多会话状态隔离。门禁失败应返回可解释状态，而不是让模型自由补写。

对话和Agent还需冻结会话ID、状态摘要、工具白名单、最大步数和终止条件。推荐与SQL应用按用户或时间分组切分，防止未来数据泄漏。代码执行放在无网络、限时限存沙箱。多模态链保存每种模态的原始输入及变换，避免只留最终文本。

## 对照、故障与回归

基线冻结任务、样本、模型、提示、知识快照、工具和判定，只改变一个因素。随机阶段至少多种子或多顺序运行，报告逐样本结果、均值、方差、尾延迟和成本。模型更大、框架更新或输出更长都不能替代受控比较。

故障轮次注入提示分隔符逃逸、空检索、过期资料、错误SQL模式、工具越权、会话串扰、代码死循环、图像OCR缺失和评测标签翻转。系统应在输入、提示、检索、权限、执行、输出或判定门禁报告首个分叉；最终答案错误只是末端症状。

修复后先重放原失败，再运行相邻边界与正常基线。上线反馈进入新的隔离数据版本，不直接污染测试集。质量、安全、延迟、成本和可复现性全部通过才晋级，发布单元冻结模型、提示、索引、工具适配器、服务镜像和评测清单。

## 容易踩的坑

**现象 →** 提示分隔符被用户输入逃逸，模型执行了注入指令。
**原因 →** 分隔符是普通文本，未做转义或结构化隔离。
**修法 →** 用结构化模板包裹用户输入，对分隔符做转义并校验边界。

**现象 →** 把思维链的"推理"直接当事实证据，结论出错无法追溯。
**原因 →** 隐藏推理不可验证，理由未由可见证据或外部校验支持。
**修法 →** 理由必须引用检索片段或外部验证，隐藏推理不作为事实来源。

**现象 →** 改提示一个词结果翻转。你可以亲自验证：冻结样本集，只改一个措辞跑全集，对比逐样本输出。
**原因 →** 提示对输出高度敏感，未建立回归集做版本对照。
**修法 →** 冻结提示回归集，每次改动只改一处并保留上版基线。

## 小结

- 清晰指令与任务拆分是提示基础
- 分隔符隔离输入防止注入逃逸
- 少样本引导稳定输出结构
- 思维链理由需可见证据支持
- 提示回归集冻结版本逐项对照

## 练习与答案

<Exercises>

**问题 1：概念理解。** 提示工程中为什么要使用分隔符？

<Answer>

分隔符把用户输入与指令、示例、检索片段明确隔开，降低提示注入风险，让模型清楚哪部分是指令、哪部分是待处理数据。但分隔符是普通文本，仍需配合结构化模板和转义校验，防止用户输入逃逸分隔符。

</Answer>

**问题 2：实践应用。** 思维链（Chain of Thought）的推理能直接当作事实证据吗？

<Answer>

不能。思维链是模型生成的隐藏推理，不可验证、可能幻觉。理由必须由可见的检索片段或外部校验支持。把隐藏推理当事实来源会导致错误无法追溯。正确做法是要求模型引用证据，并对引用做来源校验。

</Answer>

**问题 3（独立实现）：** 独立实现一个简化版少样本提示模板：输入指令、示例列表和待处理输入，用分隔符拼装成完整提示字符串。

<Answer>

```python
def build_few_shot(instruction, examples, user_input, sep="###"):
    parts = [instruction]
    for ex in examples:
        parts.append(f"{sep}\n输入: {ex['input']}\n输出: {ex['output']}")
    parts.append(f"{sep}\n输入: {user_input}\n输出:")
    return "\n".join(parts)
```

</Answer>

## 本章回顾

从清晰指令、任务拆分、理由与多候选选择进入分隔符、少样本、思维链和ReAct，并建立提示回归集。 掌握标准不是记住模型或框架名，而是能重建任务、版本、数据、调用图、权限、对照、指标、限制和失败证据。通过标准为：能在冻结样本上比较提示版本，验证结构化输出与注入边界，不把隐藏推理当作事实证据。
