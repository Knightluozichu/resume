# 生产部署与运维

## 学习目标

完成本章学习后，你将能够：

1. 理解 LLM 应用的生产架构总览与请求流转路径
2. 掌握云API、私有化、混合三种部署模式的优缺点与适用场景
3. 理解生产运维的六大支柱：监控、安全、成本、评测、扩缩容、灰度
4. 识别从原型到生产的关键跃迁

## 核心概念

### 从原型到生产

LLM 应用的原型和生产系统之间有巨大鸿沟。原型只关心「能不能跑通」，生产系统还要回答：够不够快、够不够稳、够不够安全、够不够便宜、能不能迭代。

生产架构的请求流转路径：

```
客户端 → API网关 → 负载均衡 → 推理服务 → LLM模型
```

- **API 网关**：鉴权、限流、请求路由、日志记录
- **负载均衡**：多副本路由、自动扩缩容、健康检查
- **推理服务**：vLLM / TGI 等推理引擎，管理 GPU 资源
- **LLM 模型**：运行在 GPU 集群上的模型实例

### 三种部署模式对比

| 维度 | 云 API 调用 | 私有化部署 | 混合部署 |
|------|-------------|------------|----------|
| 运维成本 | 零运维 | 高运维 | 中等运维 |
| 数据隐私 | 数据出域 | 数据不出域 | 按需选择 |
| 初始成本 | 低 | 高（GPU采购） | 中等 |
| 延迟 | 依赖网络 | 内网低延迟 | 按路由动态选择 |
| 适合场景 | 原型/非敏感 | 金融/医疗/政府 | 企业级生产 |

**云 API 调用**：最简单的方式，直接调用 OpenAI / Anthropic / Google 的 API。零运维、即开即用，但数据需传输到提供商服务器，成本随调用量线性增长。

**私有化部署**：用开源模型（LLaMA / Qwen）自建 GPU 集群部署。数据完全不出域，内网低延迟，但运维成本高、需采购 GPU。

**混合部署**：同时使用云 API 和私有模型，按请求敏感度和复杂度动态路由。简单请求用小模型，复杂请求路由大模型，兼顾成本与能力。

### 运维六大支柱

| 支柱 | 核心指标 | 工具 |
|------|----------|------|
| 监控与可观测 | 延迟、吞吐、错误率、Token用量 | Phoenix / Langfuse |
| 安全与合规 | 输入过滤、输出审核、PII脱敏 | Guardrails / Lakera |
| 成本优化 | 模型路由、缓存、量化 | 缓存层 / 路由器 |
| 评测与质量 | 回归测试、A/B测试、Bad case | RAGAS / LangSmith |
| 弹性扩缩容 | 自动扩容、峰值应对 | Kubernetes / Ray |
| 灰度发布 | 金丝雀、流量切分、回滚 | Feature Flag / 网关 |

### 成本优化策略

1. **模型路由**：简单请求用小模型（7B），复杂请求路由大模型（70B），降低 60% 成本
2. **语义缓存**：对相似查询缓存回答，FAQ 场景可命中 50% 以上
3. **量化部署**：INT8 / INT4 量化降低显存占用，单卡可部署更大模型
4. **批处理**：连续批处理提升 GPU 利用率
5. **上下文裁剪**：精简提示长度，减少 token 消耗

### 从原型到生产的关键跃迁

| 维度 | 原型 | 生产 |
|------|------|------|
| 可靠性 | 能跑通就行 | 99.9% 可用性 |
| 可观测 | 打印日志 | 全链路追踪 |
| 可扩展 | 单实例 | 弹性扩缩容 |
| 可控 | 不限成本 | 成本+安全双控 |
| 可迭代 | 手动测试 | 评测驱动迭代 |

## 术语表

- **vLLM**：高性能 LLM 推理引擎，支持 PagedAttention 和连续批处理
- **语义缓存**：对语义相似的查询缓存回答，避免重复调用 LLM
- **模型路由**：根据请求复杂度动态路由到不同大小的模型，优化成本
- **灰度发布**：逐步放量新版本，控制风险，支持快速回滚
- **可观测性**：对系统的调用链路、性能、成本进行全面追踪和监控
