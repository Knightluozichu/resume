# Chapter 5：把 LLM 嵌入应用而不是散落在代码里

嵌入 LLM 的第一步不是安装一个 SDK，而是决定模型、提示、数据、状态和工具如何通过稳定合同进入应用。LangChain、Hugging Face Hub 或自定义客户端都只能提供实现材料；任务、权限、日志、成本和回退仍然需要由应用团队负责。本章把一条嵌入管线拆成可替换适配器、可隔离状态和可撤销凭证三条证据链。

先预测：如果模型端点升级，哪个适配器最先应该变化？如果记忆跨租户泄露，应该继续生成还是立即阻断？如果 Hub 令牌出现在日志里，删除本地文件是否足够？三个实验会把这些问题转成输入、边界、证据和停止动作。

<Callout type="trap">**现象：**业务代码直接调用框架和模型 SDK，样例能跑就认为嵌入完成；**原因：**没有隔离版本、错误、成本和回退；**修法：**在业务层与外部服务之间建立适配器和请求合同，保留可替换实现。</Callout>

<Callout type="trap">**现象：**把对话历史或数据库结果都塞进共享记忆；**原因：**没有明确会话、租户、生命周期和可见范围；**修法：**为状态指定所有者、过期、清除和审计策略，跨界时停止请求。</Callout>

<Callout type="trap">**现象：**令牌写进 `.env` 后就认为秘密已经安全；**原因：**忽略提交、日志、客户端打包、权限 scope 和轮换；**修法：**最小权限注入、忽略文件、定期轮换，泄露后先撤销并记录影响范围。</Callout>

## 六个核心术语

`<Term def="隔离外部模型、框架或数据服务接口与业务逻辑的稳定薄层">Embedding Adapter</Term>` 让应用可以更换端点而不改写所有业务代码。一次调用还需要 `<Term def="固定任务、输入、模型、提示、数据、工具、输出和限制的可重放记录">Request Contract</Term>`，否则版本差异无法定位。

记忆和链必须遵守 `<Term def="定义状态的所有者、可见范围、生命周期、清理和跨步骤传递方式的规则">State Boundary</Term>`；工具动作必须符合 `<Term def="约束工具输入、输出、权限、超时、错误和副作用的接口">Tool Contract</Term>`。访问 Hub 或其他模型服务时，`<Term def="只授予必要资源和动作、可审计且能够撤销的访问凭证">Scoped Token</Term>` 比一串未分类的密钥更容易治理。

最后，`<Term def="说明开源权重来源、允许用途、限制、评估和已知风险的结构化文件">Model Card</Term>` 把“下载了模型”转成可以评审的来源与责任证据。

## 一个可运行的嵌入门禁

下面的 Python 函数先检查请求合同和工具权限，再允许适配器执行；TypeScript 版本把秘密配置从业务对象中分离。示例不连接真实服务，目的是先验证边界和缺证据时的停止行为。

<CodeTabs>
  <Tab label="Python / 请求合同">

```python
def embedding_gate(request, allowed_tools):
    required = {"task", "model", "prompt", "input_hash", "limits"}
    missing = sorted(required - request.keys())
    forbidden = sorted(set(request.get("tools", [])) - set(allowed_tools))
    if missing or forbidden:
        return {"pass": False, "missing": missing, "forbidden": forbidden}
    return {"pass": True, "missing": [], "forbidden": []}
```

  </Tab>
  <Tab label="TypeScript / 配置边界">

```typescript
type PublicConfig = {
  model: string;
  endpoint: string;
  promptVersion: string;
};

function publicConfig(env: Record<string, string | undefined>): PublicConfig {
  if (!env.MODEL_NAME || !env.MODEL_ENDPOINT || !env.PROMPT_VERSION) {
    throw new Error("model configuration is incomplete");
  }
  return {
    model: env.MODEL_NAME,
    endpoint: env.MODEL_ENDPOINT,
    promptVersion: env.PROMPT_VERSION,
  };
}
```

  </Tab>
</CodeTabs>

`embedding_gate` 不会因为工具名称看起来熟悉就放行越权动作；`publicConfig` 只返回非秘密运行配置，令牌由部署环境注入而不进入请求日志。生产实现还要增加租户、请求 ID、超时、成本、回执、数据来源和轮换记录，让一次失败能够被重放与撤销。

## 从管线到可维护应用

### Chapter 5: Embedding LLMs within Your Applications

“Chapter 5: Embedding LLMs within Your Applications”把模型能力放入应用责任链：适配器隔离外部变化，状态边界保护上下文，工具合同限制副作用，秘密治理保护访问入口。读者应在连接真实服务前用假端点完成这些合同的回归。

### Technical requirements

“Technical requirements”包括运行时、依赖锁、模型端点、数据连接、密钥注入、日志脱敏、超时、资源上限和回退版本。缺少其中任何一项，demo 的成功都不能说明应用可以在另一台机器或下一次升级后重放。

### A brief note about LangChain

“A brief note about LangChain”提醒我们把框架当作外部实现，而不是应用合同。组件、回调和模型适配器都可能随版本变化；业务层应只依赖自己的接口，并保存链路配置、版本和错误回执。

### Getting started with LangChain

“Getting started with LangChain”可以从假模型、假检索器和假工具开始，先验证输入输出和错误分支，再接真实端点。这样做能把框架安装问题、模型行为问题和业务合同问题分开，而不是让一个长 notebook 混在一起。

### Models and prompts

“Models and prompts”要求同时冻结模型、端点、词元器、提示版本、解码、上下文和输出 schema。提示改变可能影响缓存、成本和评估；模型别名改变可能影响质量和安全，两者都要通过同一回归集重新验证。

### Data connections

“Data connections”将数据库、文件、搜索和向量索引接入模型上下文。连接必须记录来源、权限、快照、有效期、查询参数和引用；空结果、过期结果或越权结果都应进入可解释的降级路径。

### Memory

“Memory”不是无限聊天历史，而是有所有者、范围、压缩方式、过期和删除动作的状态系统。保存摘要时要保留来源和版本；跨用户或租户的记忆必须被视为安全边界错误，而不是生成质量问题。

### Chains

“Chains”把多个确定步骤连接成可观察的流程。每个节点应有输入、输出、超时、重试、回退和负责人；链越长，越需要保存中间产物，否则最后一句文本无法告诉你哪个节点先失效。

### Agents

“Agents”让模型选择下一步动作，因而扩大了状态、权限、成本和停止风险。工具白名单、参数校验、最大步数、预算、取消和人工升级是最低边界；Agent 能完成任务不代表它可以自由访问所有系统。

### Working with LLMs via the Hugging Face Hub

“Working with LLMs via the Hugging Face Hub”把开源模型接入拆成账号、权限、权重、许可证、缓存、硬件和评估。Hub 页面可提供来源线索，但团队仍需核对模型卡、商业限制、版本、漏洞和本地运行资源。

### Create a Hugging Face user access token

“Create a Hugging Face user access token”应遵守最小 scope、专用账户、过期策略和可撤销性。令牌不是教程里的普通字符串；不要提交到仓库、写入前端、打印到日志或与不需要下载权重的服务共享。

### Storing your secrets in an .env file

“Storing your secrets in an .env file”适合本地开发的配置注入，但 `.env` 不是秘密保险箱。文件应被忽略、模板只保留变量名，CI 与生产使用独立注入和轮换；一旦泄露，要撤销旧凭证并检查历史与缓存。

### Start using open-source LLMs

“Start using open-source LLMs”应从模型卡、权重来源、许可证、硬件、量化、推理版本和任务评估开始。自托管增加控制力，也增加补丁、容量、监控、数据驻留与安全响应责任，下载权重只是嵌入的第一步。

### Summary

“Summary”把本章收束为三件事：用适配器和请求合同嵌入模型，用状态和工具边界保护多步调用，用 scoped token、`.env` 注入和模型卡治理开源资源。只有这些证据与质量、成本和回退一起通过，嵌入才接近发布。

### References

“References”标记 Packt 原书、LangChain、Hugging Face Hub 和安全配置资料的来源边界。框架 API、模型卡、许可证、令牌策略与服务价格会变化，当前实现必须在目标环境中重新核对，不由历史示例自动继承。

## 六类嵌入证据

### 1. 运行与适配器证据

保存运行时、依赖锁、模型端点、适配器版本、请求 ID、响应、延迟、成本和错误。业务层只看到稳定合同，外部 SDK 的变化在适配器层被隔离并可以单独回归。

### 2. 模型与提示证据

保存模型卡、权重或端点来源、提示版本、解码设置、上下文限制和输出 schema。更换模型时比较逐字段差异、失败类别和回退，而不只比较一段成功文本。

### 3. 数据连接证据

保存数据许可、连接身份、查询、快照、索引、引用、有效期和空结果处理。数据能够被模型读取不等于它应该被读取；权限、脱敏与租户边界先于生成质量。

### 4. 状态与编排证据

保存记忆所有者、摘要版本、生命周期、链路节点、Agent 步数、工具参数、回执和取消动作。跨界状态、无限循环或重复副作用都应在边界处停止，并保留影响范围。

### 5. 秘密与许可证证据

保存令牌 scope、创建者、过期、轮换、撤销、注入方式、`.gitignore`、模型卡和许可证审查。秘密不进入日志和客户端，开源权重不绕过商业、版权或安全评估。

### 6. 回归与回退证据

保存基准样本、旧版输出、新版差异、人工判断、资源预算、回退版本和演练时间。模型、框架、提示、数据、索引或凭证流程变化都应触发回归，不等用户先发现故障。

## 容易踩的坑

<Callout type="trap">**现象：**把框架对象直接传遍整个应用；**原因：**没有定义稳定的领域接口和适配器责任；**修法：**让业务层只依赖请求合同，框架升级先在适配器和回归环境中验证。</Callout>

<Callout type="trap">**现象：**为方便调试把完整请求、记忆和令牌写入日志；**原因：**没有区分诊断证据与秘密、个人数据和跨租户状态；**修法：**脱敏、哈希、最小化记录，并为高风险字段设置日志门禁。</Callout>

<Callout type="trap">**现象：**开源模型跑通一次就部署；**原因：**没有检查模型卡、许可证、容量、漏洞、质量和回退；**修法：**先完成来源与风险审查，再用独立样本和资源预算验证可维护性。</Callout>

## 小结与学习验收

- 用 Embedding Adapter 和 Request Contract 把外部服务与业务逻辑隔离。
- 用 State Boundary 和 Tool Contract 约束记忆、链、Agent 的可见范围和副作用。
- Hugging Face Hub 令牌采用最小 scope、注入、轮换与撤销；`.env` 只解决本地配置形态。
- 开源权重必须同时通过模型卡、许可证、硬件、质量、容量和安全评估。
- 发布前保留运行、数据、秘密、回归和回退证据，缺一项就暂停嵌入。

## 练习与答案

<Exercises>

**问题 1：**请设计一个最小模型适配器接口，使业务代码可以从托管 API 切换到本地模型而不修改任务逻辑。

<Answer>
  接口至少包含任务、提示、输入、模型标识、超时和限制，并统一返回文本或结构化输出、来源、延迟、成本、错误和请求 ID。托管与本地实现分别处理 SDK、凭证和硬件，业务层只消费这个合同；切换前使用同一回归集比较结果。
</Answer>

**问题 2：**发现一个 Hub 令牌出现在 CI 日志中，为什么只删除日志文件不够？

<Answer>
  日志可能已经被缓存、复制或下载，令牌还可能出现在历史构建、仓库、镜像和客户端中。应立即撤销并轮换令牌，确认 scope 与创建者，检查日志和历史暴露范围，清理副本，恢复后用新凭证和审计记录验证。
</Answer>

**问题 3（独立实现）：**实现一个 `embedding_gate`，拒绝缺少请求合同字段或调用未列入白名单的工具。

<Answer>
  定义任务、模型、提示、输入哈希和限制为必需字段，计算缺失列表；再把请求工具集合与允许集合做差集，返回未授权名称。任一缺口存在就返回 `pass=false`，不以空值补齐，也不把失败请求交给模型自由解释。
</Answer>

</Exercises>
