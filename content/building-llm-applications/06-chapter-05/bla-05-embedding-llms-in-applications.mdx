function releaseGate(
  records: GateRecord[],
): { pass: boolean; missing: number[] } {
  const required = ["input", "config", "output", "judgment", "limits"];
  const missing = records
    .map((r, i) => (required.every((k) => k in r) ? -1 : i))
    .filter((i) => i >= 0);
  return { pass: missing.length === 0, missing };
}

## 从最小基线到应用

先实现没有记忆、检索和工具的最小模型调用，冻结五到十个正常样本及预期结构。然后每轮只加入一个能力：模板、少样本、检索、记忆、工具、代码执行或多模态输入。每一步都保留上一步基线，测量质量、延迟、成本和新引入的失败面。

输出验证分语法、语义、来源和权限四层。JSON可解析不代表事实正确；检索片段存在不代表回答受其支持；工具调用成功不代表参数获授权；前端显示顺畅也不代表多会话状态隔离。门禁失败应返回可解释状态，而不是让模型自由补写。

对话和Agent还需冻结会话ID、状态摘要、工具白名单、最大步数和终止条件。推荐与SQL应用按用户或时间分组切分，防止未来数据泄漏。代码执行放在无网络、限时限存沙箱。多模态链保存每种模态的原始输入及变换，避免只留最终文本。

## 对照、故障与回归

基线冻结任务、样本、模型、提示、知识快照、工具和判定，只改变一个因素。随机阶段至少多种子或多顺序运行，报告逐样本结果、均值、方差、尾延迟和成本。模型更大、框架更新或输出更长都不能替代受控比较。

故障轮次注入提示分隔符逃逸、空检索、过期资料、错误SQL模式、工具越权、会话串扰、代码死循环、图像OCR缺失和评测标签翻转。系统应在输入、提示、检索、权限、执行、输出或判定门禁报告首个分叉；最终答案错误只是末端症状。

修复后先重放原失败，再运行相邻边界与正常基线。上线反馈进入新的隔离数据版本，不直接污染测试集。质量、安全、延迟、成本和可复现性全部通过才晋级，发布单元冻结模型、提示、索引、工具适配器、服务镜像和评测清单。

## 容易踩的坑

**现象 →** 把 Hugging Face token 写进 `.env` 后误提交到公开仓库，几小时内即被扫描器盗用。
**原因 →** `.env` 未加入 `.gitignore`，token 权限为 write 且无过期时间，密钥随源码外泄。
**修法 →** 立即吊销并重发只读 token，`.gitignore` 锁定 `.env`，密钥改用 secret manager 注入运行时。

**现象 →** 切换 `sentence-transformers` 默认模型后，新向量维度变成 384，旧索引仍存 768 维，余弦相似度全 NaN。
**原因 →** 模型别名指向新版本，嵌入维度未在合同中冻结，索引未随模型版本一起重建。
**修法 →** 记录模型版本与维度到请求清单，重建索引前比对维度，版本不一致直接拒绝写入。

**现象 →** 多用户共用一个 `ConversationBufferMemory`，A 的提问混入 B 的回答。
**原因 →** 记忆对象按进程单例持有，未按 session_id 隔离，上下文未设所有者与生命周期。
**修法 →** 用 session_id 作键的字典隔离每会话状态，设最大轮数与过期清理，越界降级为摘要。

冻结基线后只改变提示模板这一个因素，其余字段（模型、数据、工具、种子）保持不变。对正常、边界和注入样本各跑多种子，报告逐样本结果、均值、方差与尾延迟；通过 `compare_controlled` 断言 `changed` 集合长度为 1，确保差异可归因到提示。

</Answer>

**问题 3（独立实现）：** 独立实现一个简化版的 `release_gate`：输入记录列表，返回缺失必需字段的记录下标，缺字段即判不通过。

<Answer>

```python
def release_gate(records):
    required = {"input", "config", "output", "judgment", "limits"}
    missing = [i for i, r in enumerate(records)
               if not required.issubset(r)]
    return {"pass": not missing, "missing": missing}
```

</Answer>
