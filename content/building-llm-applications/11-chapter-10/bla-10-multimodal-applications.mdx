type GateRecord = {
  input?: unknown;
  config?: unknown;
  output?: unknown;
  judgment?: unknown;
  limits?: unknown;
};

function releaseGate(
  records: GateRecord[],
): { pass: boolean; missing: number[] } {
  const required = ["input", "config", "output", "judgment", "limits"];
  const missing = records
    .map((r, i) => (required.every((k) => k in r) ? -1 : i))
    .filter((i) => i >= 0);
  return { pass: missing.length === 0, missing };
}

## 从最小基线到应用

先实现没有记忆、检索和工具的最小模型调用，冻结五到十个正常样本及预期结构。然后每轮只加入一个能力：模板、少样本、检索、记忆、工具、代码执行或多模态输入。每一步都保留上一步基线，测量质量、延迟、成本和新引入的失败面。

输出验证分语法、语义、来源和权限四层。JSON可解析不代表事实正确；检索片段存在不代表回答受其支持；工具调用成功不代表参数获授权；前端显示顺畅也不代表多会话状态隔离。门禁失败应返回可解释状态，而不是让模型自由补写。

对话和Agent还需冻结会话ID、状态摘要、工具白名单、最大步数和终止条件。推荐与SQL应用按用户或时间分组切分，防止未来数据泄漏。代码执行放在无网络、限时限存沙箱。多模态链保存每种模态的原始输入及变换，避免只留最终文本。

## 对照、故障与回归

基线冻结任务、样本、模型、提示、知识快照、工具和判定，只改变一个因素。随机阶段至少多种子或多顺序运行，报告逐样本结果、均值、方差、尾延迟和成本。模型更大、框架更新或输出更长都不能替代受控比较。

故障轮次注入提示分隔符逃逸、空检索、过期资料、错误SQL模式、工具越权、会话串扰、代码死循环、图像OCR缺失和评测标签翻转。系统应在输入、提示、检索、权限、执行、输出或判定门禁报告首个分叉；最终答案错误只是末端症状。

修复后先重放原失败，再运行相邻边界与正常基线。上线反馈进入新的隔离数据版本，不直接污染测试集。质量、安全、延迟、成本和可复现性全部通过才晋级，发布单元冻结模型、提示、索引、工具适配器、服务镜像和评测清单。

评测可下钻到输入、输出、证据和理由，覆盖正常、边界、注入、越权、偏见、隐私与过度拒答。质量与成本在同一请求集合上报告，平均值之外保留尾部失败。

### 发布、监控与回退合同

发布前重放冻结回归集，线上监控模型错误、检索缺失、工具失败、延迟、成本和安全事件。模型、提示、索引和工具版本整体标记，可一键回到上一组已验证产物。

## 容易踩的坑

**现象 →** 发票 OCR 把金额 `1,200` 识别成 `1200` 或漏掉税额，汇总总额偏差巨大。
**原因 →** OCR 置信度未校验，关键字段无二次确认，图像质量差时模型静默出错。
**修法 →** 记录 OCR 原始框与置信度，关键字段交叉校验，低置信度触发人工复核而非直接入账。

**现象 →** Whisper 把英文视频转成中文幻觉字幕，下游摘要完全跑偏。
**原因 →** 未指定源语言，Whisper 自动检测在小语种片段上误判，生成内容未与音频比对。
**修法 →** 冻结源语言参数，保留音频指纹与逐段时间戳，转写后做语言一致性校验。

**现象 →** 三个月后无法复现某次图像生成结果，提示词与参数全部丢失。
**原因 →** 只保存了最终图片，未记录提示、种子、模型版本与变换链，多模态产物不可追溯。
**修法 →** 每种模态保存原始输入、变换、模型版本与中间产物，发布单元整体标记可回放。

## 小结

- 为每种模态分别保存原始输入、变换与中间产物。
- OCR 关键字段须交叉校验，低置信度触发人工复核。
- 音视频转写冻结语言参数，保留时间戳与指纹。
- 比较工具包、Agent 与顺序链的质量与可控性。
- 局部失败要有可解释的降级路径，而非整体崩溃。

## 练习与答案

<Exercises>

**问题 1：概念理解。** 为什么多模态链必须保存每种模态的中间产物？

<Answer>

多模态链中文本、图像、音频依次变换，只留最终文本会丢失原始图像质量、OCR 框、音频指纹等关键证据；一旦结果出错无法定位是 OCR、转写还是生成环节分叉，保存中间产物才能独立复核与回放。

</Answer>

**问题 2：实践应用。** 如何避免发票 OCR 关键字段静默出错？

<Answer>

记录 OCR 原始框与置信度，对金额、税号等关键字段做规则交叉校验（如金额等于小计加税额），低置信度或校验不一致时触发人工复核，而非直接入账；同时保留原图便于复检。

</Answer>

**问题 3（独立实现）：** 独立实现一个简化版多模态产物存档器：记录每一步的模态、输入哈希、模型与输出。

<Answer>

```python
def archive_step(modality, inp, model, out, meta=None):
    return {
        "modality": modality,
        "input_hash": hash(inp),
        "model": model,
        "output": out,
        "meta": meta or {},
    }


def archive_chain(steps):
    return {"steps": steps, "version": "1.0"}
```

</Answer>
