# Chapter 10：让多模态结果可检查、可回放、可降级

当应用接收图片、声音或视频时，模型看到的并不是一个普通字符串：文件可能损坏，语音可能被误识别，图像中的金额可能缺少小数点，生成的图片也可能无法说明来源。多模态应用的难点不是把更多接口接起来，而是让每一次转换都留下可核验的输入、约束和输出。

先猜一猜：一个模糊的发票图像应该直接交给模型，还是先停在输入检查？多个工具都能处理同一文件时，谁决定调用顺序？如果模型给出很流畅的字幕，但语言检测和音频不一致，前端应该显示什么？下面的实验会让这些选择变成可以切换和复盘的状态。

<Callout type="trap">**现象：**上传的发票识别出一个看似合理的总额，系统直接写入财务记录；**原因：**没有校验图像尺寸、字段置信度和小计与税额关系；**修法：**先保留原图与 OCR 框，关键字段交叉检查，低置信度进入人工复核。</Callout>

<Callout type="trap">**现象：**一个 Agent 在工具失败后悄悄换用另一个工具，用户无法知道答案来自哪里；**原因：**调用图、权限、重试和降级没有显式记录；**修法：**为每次调用保存请求 ID、参数、错误、重试次数和回退动作，禁止静默改路。</Callout>

<Callout type="trap">**现象：**最终图片或字幕可以展示，却无法重建三个月前的结果；**原因：**只存最终产物，丢掉原始模态、提示、模型版本和中间变换；**修法：**将每种模态的输入指纹、变换、模型和输出组成可回放链。</Callout>

## 六个核心术语

<Term def="记录输入模态、输出协议、质量阈值、权限和失败动作的可检查约定">Modality Contract</Term> 规定一张图片或一段音频何时可以进入模型；<Term def="把图片、音频或视频转换成下一阶段可用表示的处理步骤">Modality Transform</Term> 则记录裁剪、采样、转写或 OCR 等变化。

工具编排依靠 <Term def="描述模型、工具、状态和回退如何连接的有向调用计划">Orchestration Graph</Term>；每个结果还要带 <Term def="模型或规则对识别字段正确程度的数值或分级判断">Confidence Signal</Term>。最终用 <Term def="把原始输入、变换、版本和输出连成可复盘记录的链条">Artifact Lineage</Term> 找回来源，再用 <Term def="在失败、低置信度或越权风险时停止自动动作并选择下一步的规则">Fallback Gate</Term> 决定继续、人工确认或回退。

## 一个可运行的多模态产物记录器

下面的 Python 函数把每一步的模态、输入指纹、模型和输出放入同一条链；TypeScript 版本用联合类型约束模态。它不假装完成 OCR 或生成，只负责让后续验证拥有稳定的记录入口。

<CodeTabs>
  <Tab label="Python / 产物链">

~~~python
def record_artifact(modality, input_hash, model, output, previous=None):
    return {
        "modality": modality,
        "input_hash": input_hash,
        "model": model,
        "output": output,
        "previous": previous,
    }
~~~

  </Tab>
  <Tab label="TypeScript / 模态类型">

~~~typescript
type Modality = "text" | "image" | "audio" | "video";

type Artifact = {
  modality: Modality;
  inputHash: string;
  model: string;
  output: unknown;
  previous?: string;
};

function accepts(artifact: Artifact): boolean {
  return Boolean(artifact.inputHash && artifact.model && artifact.output);
}
~~~

  </Tab>
</CodeTabs>

record_artifact 让 OCR、Whisper、文本模型和图像生成拥有同一套追踪字段；accepts 只检查记录是否完整，不代表内容已经正确。生产实现还要保存文件类型、大小、许可、置信度、延迟、成本、用户授权和清理状态。

## 从输入检查到发布决定

### Chapter 10: Building Multimodal Applications with LLMs

这一章把文本、图像、音频和视频视作不同的证据来源，而不是可以互换的字符串。应用先验证模态，再选择模型和工具，最后以置信度、来源、人工复核和回退证据决定是否展示或写入下游系统。

### Technical requirements

技术要求应列出允许的文件类型、尺寸和时长、编码、语言、采样、保留周期、输出结构、延迟预算和人工确认条件。还要冻结模型端点、区域、凭据范围、日志字段和错误协议；否则同一张图在两次运行中可能走出不可比较的路径。

### Why multimodality?

多模态的价值在于不同输入携带不同证据：图片有空间位置，音频有时间顺序，视频同时包含画面和声音。选择多模态不是为了增加炫目的接口，而是为了回答单一模态无法回答的问题，同时承担同步、许可、质量和解释成本。

### Building a multimodal agent with LangChain

多模态 Agent 需要把模态输入、工具选择、状态摘要和最大步数写入调用图。先用假工具验证路由和错误处理，再接真实 LangChain 工具；每次调用保存参数、返回类型、延迟、成本、权限和下一步原因，不能只保留最终回答。

### Option 1: Using an out-of-the-box toolkit for Azure AI Services

现成 AI 工具包适合快速组合 OCR、语音、视觉或语言能力，但便利性不等于边界已经定义。封装层应明确区域、模型版本、凭据权限、输入留存、返回置信度和服务错误；把默认配置复制到自己的运行合同中再上线。

### Getting Started with AzureCognitiveServicesToolkit

开始使用该认知服务工具包时，先用一张已知答案的图片和一段短音频验证身份、区域、文件上传、响应结构和错误重试。将示例代码拆成输入适配、服务调用、字段校验和存档四层，避免把 SDK 返回对象直接传给用户界面。

### Setting up the toolkit

工具包配置至少要冻结端点、部署名、超时、重试、并发、区域、日志脱敏和临时文件清理。密钥不进入提示或产物正文；服务返回的原始响应只在受控存储中保留，并通过请求 ID 与用户看见的摘要连接。

### Leveraging a single tool

单工具路径适合先建立可解释基线，例如只用 OCR 读取发票字段或只用 Whisper 生成时间戳。先定义工具输入输出和失败状态，再测量它在正常、低质量和缺失输入上的表现；如果工具失败，应返回明确错误而不是让模型猜一个结果。

### Leveraging multiple tools

多个工具可以让图像、音频和视频互相补充，但每增加一个工具就增加权限、延迟、成本和失败组合。给每个工具设置最小输入、最大调用次数和可重试错误，调用图中标记来源；不同工具的结果冲突时，进入复核而不是随机选择。

### Building an end-to-end application for invoice analysis

发票应用可以先校验文件，再定位文字框、抽取字段、核对小计与税额，最后生成供人确认的结构化摘要。保留原图、裁剪框、OCR 文字、字段置信度和核算结果；金额或税号出现矛盾时，系统应暂停入账并显示需要确认的字段。

### Option 2: Combining single tools into one agent

把单个工具交给 Agent 调度时，模型可以决定先 OCR、再查账或再生成说明，但这种灵活性增加了不可预测路径。限制工具白名单、参数模式、最大步数和人工确认点，并在 UI 显示实际调用序列，用户才能知道答案是如何产生的。

### YouTube tools and Whisper

视频处理通常先取得允许使用的音频或字幕，再用 Whisper 转写并保留逐段时间戳。冻结源语言或可接受的语言集合，记录音频指纹、片段区间、转写置信度和修订；摘要只能引用已定位片段，不能把听不清的内容补成确定事实。

### DALL·E and text generation

图像生成要同时记录提示、参考输入、模型版本、种子或随机设置、内容安全结果和输出指纹。文本模型可负责构造说明或替代文本，但说明中的人物、地点和版权主张应有独立证据；不能把生成模型的流畅描述当成图像事实。

### Putting it all together

端到端流程可以是：接收并校验输入，按模态调用适配器，保存中间产物，合并结构化结果，运行质量与安全门禁，最后展示可回看的来源和回退动作。每条边都标明输入输出和失败语义，排查时才能定位是文件、模型、工具还是 UI 分叉。

### Option 3: Hard-coded approach with a sequential chain

顺序链把步骤写死，适合发票抽取、视频转写这类流程明确的任务。它牺牲部分灵活性，换来可预测的调用顺序、成本和回放；每一步都用结构化输入输出连接，并为跳过、重试、超时和人工确认定义显式分支。

### Comparing the three options

工具包的优势是接入快，Agent 的优势是能按上下文选择工具，顺序链的优势是审计和回放简单。用同一批样例比较质量、延迟、成本、失败率、权限复杂度和人工介入次数，再按风险和变化频率选方案，不能只凭代码行数判断优劣。

### Developing the front-end with Streamlit

Streamlit 前端应显示上传限制、处理中间状态、工具调用、来源、置信度、失败原因、重试和人工确认入口。不要只展示一个最终文本框；图像字段要能回到原图位置，字幕要能跳到时间戳，生成图像要能查看提示与版本。

### Summary

本章的 Summary 是一条可执行的多模态交付路线：先检查输入与许可，再记录模态变换，随后选择工具编排并保存每次调用，最后依据置信度、来源和人工确认决定展示、降级或回退。图像、音频、视频和文本可以共享存档接口，但不能共享未经验证的事实判断。

## 六类多模态证据

### 输入与许可证据

保存原始文件指纹、模态、类型、大小、来源、用户授权和保留期限。视频或图片里的第三方内容可能有额外许可边界，不能因为模型能读取就默认可以训练、存储或公开展示。

### 变换与同步证据

保存裁剪、压缩、采样、OCR 框、语言检测、音频切片和视频时间轴。每个中间产物引用上一步的 ID；如果音画不同步或图片被重新缩放，审核者可以从链上看到变化发生在哪里。

### 模型与工具证据

记录服务、部署、版本、区域、提示、参数、工具白名单、超时、重试和请求 ID。Azure AI Services、Whisper、DALL·E 或 LangChain 的接口会变化，历史代码只能说明结构，不能代替当前运行验证。

### 质量与置信度证据

记录字段置信度、语言检测、内容安全、OCR 框、字幕时间戳、人工修订和阈值。低置信度要触发可解释动作；把一个数字平均分当成全链路正确，会隐藏某个模态已经失真的事实。

### 产物与来源证据

最终文本、表格、图片和音频都要引用输入、变换、模型和判断 ID。下游用户点击来源时应能看到片段、框、时间或提示，而不是只看到一段没有出处的模型话术。

### 发布与回退证据

发布单冻结调用图、依赖、服务版本、回归集合、样例许可和上一版产物。线上出现识别漂移、工具超时、越权或高成本时，系统应能降级到缓存、人工或上一组已验证组件。

## 容易踩的坑

<Callout type="trap">**现象：**发票 OCR 把金额 1,200 读成 1200，系统仍然自动入账；**原因：**没有保存文字框和置信度，也没有检查小计、税额和总额关系；**修法：**关键字段做规则交叉校验，低置信度进入人工队列，并保留原图位置供复核。</Callout>

<Callout type="trap">**现象：**Whisper 把夹杂方言的英文视频生成了流畅但错误的字幕；**原因：**依赖自动语言检测，未核对片段时间戳、语言和音频质量；**修法：**冻结语言参数，按片段保存音频指纹与置信度，低质量片段显示待确认而不生成确定摘要。</Callout>

<Callout type="trap">**现象：**工具包升级后同一提示生成了不同图像，团队无法说明变化来源；**原因：**只保存最终图片，没有保存提示、参考图、模型、种子和变换链；**修法：**将多模态产物与版本坐标绑定，生成差异报告并保留上一版可回放结果。</Callout>

## 练习与答案

<Exercises>

**问题 1：概念理解。** 为什么多模态应用不能只保存最终文本或图片？

<Answer>

最终产物无法说明错误发生在文件、OCR、转写、模型、工具还是合并步骤，也无法恢复原始证据。保存每种模态的输入指纹、变换、模型、置信度和输出 ID，才能定位分叉、复核许可并回放结果。
</Answer>

**问题 2：实践应用。** 为发票分析设计三个自动停止条件，并说明停止后给用户什么信息。

<Answer>

文件类型或尺寸不允许时返回上传约束；金额、税号或总额校验不一致时返回字段位置和差异；关键字段置信度低时返回待确认字段和原图框。三种情况都不写入下游记录，并保留请求 ID 供重试或人工接管。
</Answer>

**问题 3（独立实现）：** 实现一个简化版 record_artifact，把模态、输入哈希、模型和输出连接到前一步。

<Answer>

~~~python
def record_artifact(modality, input_hash, model, output, previous=None):
    return {
        "modality": modality,
        "input_hash": input_hash,
        "model": model,
        "output": output,
        "previous": previous,
    }
~~~

实际实现还应加入时间戳、许可、置信度、请求 ID、错误状态和清理策略；函数返回的是证据记录，不是对多模态结果正确性的承诺。
</Answer>

</Exercises>
