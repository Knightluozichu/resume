# 第 13 章：趋势不是路线图，证据才是

生成式 AI 的新闻速度快于团队的评测速度。一个新模型可能展示惊人的演示，一个 Agent 可能在短视频中完成多步任务，一个小模型可能声称能降低成本；这些信号都值得记录，却不能直接变成生产承诺。本章用日期、版本、任务样例、资源预算和退出条件，把“正在发生”翻译成“我们可以验证”。

先做一个判断：如果一项能力只有演示，没有公开的输入边界和失败样例，团队应把它放进路线图、实验区，还是发布清单？如果企业案例只报告节省时间，却没有权限范围、人工复核和回退方式，它证明了技术价值，还是只证明了一个故事？下面的实验让这些判断变成可操作的记录。

<Callout type="trap">**现象：**团队把最新发布会中的演示当成稳定能力；**原因：**没有记录日期、版本、输入条件和失败样例，复查时无法重现；**修法：**先建立趋势卡片，再用固定测例和发布日期标记证据等级。</Callout>

<Callout type="trap">**现象：**一个企业案例显示产出变快，团队就扩大权限和用户范围；**原因：**价值指标与安全、成本、质量、人工接管没有同时记录；**修法：**把案例拆成小范围试点、监控门槛、责任人和退出路径，逐段扩大。</Callout>

## 六个核心术语

把趋势写进工程记录时，先使用 <Term def="记录能力主张、来源、日期、版本、测例和复查日期的卡片">Trend Radar</Term>，再用 <Term def="按来源、复现度、任务指标和限制条件标记结论可信度的等级">Evidence Grade</Term> 判断它能否支持下一步。能力不会永远稳定，<Term def="某项能力在特定模型、任务、资源与风险边界内仍然成立的时间和条件">Capability Window</Term> 需要与模型版本绑定。

当目标是低延迟、低成本或本地运行时，<Term def="参数与运行资源较小、针对明确任务优化并可在受限环境运行的语言模型">Small Model</Term> 可能比更大的模型合适；当组织把能力放进业务流程，<Term def="把问题、用户、收益、权限、监控和人工接管写成可验证假设的采用记录">Adoption Case</Term> 才能说明价值是否真实。最后，为每个试点写 <Term def="达到风险、成本或质量阈值时停止扩大并恢复旧路径的明确条件">Sunset Condition</Term>，让失败也有可执行的结论。

## 一个可复核的趋势记录

下面的 Python 记录一张最小趋势卡片，并在缺少来源、指标或退出条件时拒绝把状态写成“可采用”。TypeScript 版本用联合类型限制证据等级，避免把一段没有复现记录的宣传文字误当成生产结论。代码只管理记录结构，不能替代领域评测和人工审批。

<CodeTabs>
  <Tab label="Python / 趋势卡片">

~~~python
from dataclasses import dataclass

@dataclass
class TrendCard:
    name: str
    observed_on: str
    source: str
    task_metric: str
    sunset: str

def grade(card: TrendCard) -> str:
    fields = (card.observed_on, card.source, card.task_metric, card.sunset)
    return "review" if all(fields) else "hold"
~~~

  </Tab>
  <Tab label="TypeScript / 采用门槛">

~~~typescript
type Evidence = "signal" | "replicated" | "pilot";

type AdoptionRecord = {
  evidence: Evidence;
  owner: string;
  metric: string;
  rollback: string;
};

function canExpand(record: AdoptionRecord): boolean {
  return record.evidence !== "signal" && Boolean(record.owner && record.metric && record.rollback);
}
~~~

  </Tab>
</CodeTabs>

`grade` 把空字段变成 hold，提醒团队补证据；`canExpand` 只允许已有复现或试点证据、责任人、指标和回退路径的记录进入扩大评审。项目还需要把指标接到真实监控，并为高风险动作保留人工接管。

## 章节知识点与证据边界

### Chapter 13: Emerging Trends and Innovations

本章把趋势理解为待验证的工程假设，而不是按热度排序的新闻清单。每张记录至少包含来源、日期、版本、任务、指标、限制条件和复查触发器；缺少其中一项，就应降低证据等级并暂停扩大。

### The latest trends in language models and generative AI

观察趋势时可分为能力提升、交互方式、部署形态和组织采用四条线。对每条线都记录输入边界、输出质量、延迟、成本和失败样例，才能把“更强”改写成与具体任务相关的可检验说法。

### GPT-4V(ision)

多模态模型把图像、文字和问题放在同一任务中，但图片理解不等于事实核验。评测应覆盖小字、表格、遮挡、图像来源和敏感内容；对关键决定保留原图、模型版本、人工复核和不确定性说明。

### DALL-E 3

图像生成能力的评估不能只看一张好看的样例，还要检查提示遵循、人物与商标、风格相似、重复生成和拒绝边界。生产流程应标记生成来源、人工编辑、授权范围和下架动作，避免把视觉效果误当成可发布资产。

### AutoGen

多 Agent 协作把任务拆成角色、消息、工具和终止条件，优势是能组织长流程，风险是错误会沿着消息链放大。采用前要限制工具权限、设置最大轮次、保存轨迹并检查每个动作的批准人，不能只验最后一段文字。

### Small language models

小模型适合固定分类、抽取、路由、端侧辅助和高频低风险任务。比较时同时记录质量、延迟、内存、并发、更新成本和异常转交率；当任务开放度或风险上升，应保留更强模型或人工路径，不要为了单项成本牺牲可恢复性。

### Companies embracing generative AI

企业采用的共同信号不是“所有人都在用”，而是问题边界清楚、收益可计量、权限可控、人工责任明确。把案例拆成用户、任务、基线、收益、失败成本、监控和回退后，才能判断它是否能迁移到自己的流程。

### Coca-Cola

品牌内容案例适合观察创意速度、素材多样性与审核流程之间的关系。真正可复用的证据应说明哪些素材由模型提出、谁检查事实和商标、哪些资产需要授权、什么情况会停止投放，而不是只展示最终画面。

### Notion

知识工作案例适合观察摘要、检索、写作和团队协作的边界。评测应让用户判断引用是否支持结论、敏感页面是否被越权读取、错误摘要是否能被发现；没有访问控制、来源标记和人工修改记录时，效率提升不能直接代表质量提升。

### Malbek

合同与收入流程案例适合观察结构化抽取、条款核对和人工签批的结合。上线前需定义字段准确率、低置信度转交、版本比对和审计记录；模型可以减少查找工作，却不应替代对商业承诺和例外条款的授权判断。

### Microsoft

企业平台案例适合观察模型服务、权限、数据边界和治理工具如何一起落地。团队应把租户范围、日志访问、内容过滤、成本上限和事件回退写进试点合同与技术清单，并验证配置变化后旧的安全结论是否仍成立。

### Summary

总结趋势时，先区分信号、复现、试点和可扩大的证据等级，再为每项能力写资源预算、风险门槛、责任人和退出方案。这样做能让路线图保留好奇心，也能在证据不足时安全地说“现在还不能发布”。

### References

本章的章节主题与原书出版信息保持对应，趋势雷达、证据阶梯、采用闭环和代码示例为独立重写。模型能力、服务条款、企业案例与适用法规都会变化，项目应以最新官方资料、内部评测报告和审批记录作为发布依据。

## 从演示到发布的五类证据

### 来源与日期

保存原始公告、文档、模型版本、观察日期和复查日期。来源能说明“何时有人这样说”，却不能独自证明“在自己的任务上有效”；两者要在记录中分开。

### 任务与基线

用真实但脱敏的任务定义成功标准，并与现有流程或旧模型比较。基线包含质量、延迟、成本、人工时间和失败影响，单项指标变好不代表整体适合迁移。

### 资源与边界

记录硬件、并发、上下文长度、工具权限、数据地区和保留期限。能力窗口依赖这些边界；配置变化后应重跑关键测例，不把一次部署结果外推到所有场景。

### 人与运营

为每个高影响动作指定审核人、升级人和服务负责人。监控不只看平均质量，还要看异常率、低置信度转交、用户申诉、成本突增和人工接管是否及时。

### 退出与复查

预先写明什么情况下停止扩大、关闭功能、通知用户和恢复旧版。每次模型、工具、政策或数据变化都触发复查；一条清晰的退出条件比一段乐观预测更有生产价值。

## 容易踩的坑

<Callout type="trap">**现象：**排行榜上的分数很高，自己的任务却频繁失败；**原因：**基准任务、语言、输入边界和生产资源不同；**修法：**用自己的脱敏样例建立基线，报告失败类型、成本和人工接管。</Callout>

<Callout type="trap">**现象：**Agent 能完成演示流程，却在工具调用中扩大权限；**原因：**只检查最终答案，没有检查轨迹、参数和终止条件；**修法：**限制工具白名单与轮次，逐步记录审批、失败和回退。</Callout>

<Callout type="trap">**现象：**小模型单价低，团队就把所有任务迁移过去；**原因：**忽略质量尾部、资源峰值、更新成本和异常转交；**修法：**按任务风险分层，设置质量与成本双阈值，并保留更强模型或人工兜底。</Callout>

## 小结与学习验收

- 趋势卡片记录来源、日期、版本、测例、指标、限制条件和复查触发器。
- 证据等级把新闻信号、可复现结果、小范围试点和可扩大结论分开。
- 多模态、Agent 和小模型要在自己的任务、资源和权限边界内比较。
- 企业案例必须同时说明用户、收益、失败成本、监控、负责人和回退。
- 任何能力都要有失效条件；说“暂不采用”也是一项有证据的工程决定。

## 练习与答案

<Exercises>

**问题 1：概念理解。** 一张趋势卡片为什么要同时记录来源日期和任务指标？

<Answer>

来源日期告诉我们主张所处的版本与时间，任务指标则说明它是否在自己的输入和资源边界内成立。只有两者并列，团队才能在能力变化后复查，而不会把旧演示当成当前生产事实。
</Answer>

**问题 2：实践应用。** 为一个小模型试点设计三项必须记录的指标。

<Answer>

至少记录任务质量、端到端延迟和单位成本，并补充异常转交率或人工修正率作为安全信号。把这些指标与旧路径比较，预先写出质量下降、成本上升或异常率超阈值时的回退动作。
</Answer>

**问题 3：故障排查。** Agent 的最终答案正确，但中间调用了不应访问的工具，应该怎样处理？

<Answer>

把轨迹视为失败证据，先撤销扩大的权限并保留请求记录，再检查工具白名单、参数校验、轮次限制和人工批准点。修复后重放原任务与边界任务，只有轨迹和最终结果都满足门槛才恢复试点。
</Answer>

</Exercises>
