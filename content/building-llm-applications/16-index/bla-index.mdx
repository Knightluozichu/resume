# 索引是应用知识的双向地图

一本技术书的目录只告诉你内容在哪里，真正有用的索引还要告诉你从哪里开始、下一步做什么、如何验证和失败后往回走。本章把索引设计成一张双向地图：正向从术语或任务找到章节与代码，反向从错误症状找到首个分叉、负责人和回归测例。

没有这张地图，读者会在相似的模型名、框架名和章节标题之间反复跳转；更糟的是，旧版本的结论可能被新条目悄悄覆盖。三个实验会把索引项、故障追踪和验证日期变成可操作的记录，而不是章末的一串页码。

<Callout type="trap">**现象：**搜索结果命中了术语，却找不到能运行的示例；**原因：**索引只保存标题，没有保存章节路径、前置条件和验证产物；**修法：**每个条目连接定义、样例、练习或回归测试，并标记最后验证日期。</Callout>

<Callout type="trap">**现象：**故障排查从整本书重新开始；**原因：**索引只有正向目录，没有症状到首个异常对象的反向入口；**修法：**为无引用、工具越权、状态串扰和超时等症状建立反向记录，指向负责章节与重放步骤。</Callout>

## 六个核心术语

索引中的 <Term def="读者输入的术语、任务、症状或别名，用来启动一次定位">Query Key</Term> 需要连接到 <Term def="描述概念含义、前置条件和适用边界的短条目">Definition Node</Term>，再指向 <Term def="章节、代码、数据或实验在学习地图中的稳定地址">Learning Path</Term>。当查询来自线上失败时，使用 <Term def="从表面错误沿阶段记录回溯到第一个异常对象的排查路径">Reverse Trace</Term>，不要只记最终错误。

每个条目还应带 <Term def="说明条目来自目录、论文、官方文档、重放实验或个人推断的可信度标签">Evidence Tag</Term>；模型、框架或服务更新后，用 <Term def="记录条目最近一次在指定版本和样例上完成核验的日期">Verification Date</Term> 判断它仍可引用、需要复核，还是只能作为历史背景。

## 一个可运行的索引项校验器

下面的 Python 函数检查一条索引是否有查询键、路径、样例、证据标签和验证日期；TypeScript 版本把索引条目写成可检查的类型。代码不负责搜索全文，它只把“这个结果是否值得继续使用”变成明确的字段判断。

<CodeTabs>
  <Tab label="Python / 条目校验">

~~~python
def validate_entry(entry):
    required = {"key", "path", "sample", "evidence", "verified"}
    missing = sorted(required - set(entry))
    return {"usable": not missing, "missing": missing}
~~~

  </Tab>
  <Tab label="TypeScript / 反向记录">

~~~typescript
type IndexEntry = {
  key: string;
  aliases: string[];
  path: string;
  symptom?: string;
  sample: string;
  evidence: "catalog" | "paper" | "docs" | "replay";
  verified: string;
};

function canCite(entry: IndexEntry): boolean {
  return Boolean(entry.key && entry.path && entry.sample && entry.verified);
}
~~~

  </Tab>
</CodeTabs>

`validate_entry` 把缺字段变成显式列表，便于编辑器或构建任务阻止空索引；`canCite` 只判断最小引用条件，项目还要检查日期是否新鲜、版本是否匹配和样例是否能重放。不要用条目存在来代替证据成立。

## 设计正向与反向入口

### 正向入口：从词到行动

正向索引至少经过查询键、定义节点、学习路径和实践证据四层。术语条目写清定义与边界，章节路径写清前置知识，代码或数据写清运行条件，实验结果写清最后验证日期。这样读者点击一次后，知道为什么去那里以及怎样判断自己做对了。

### 反向入口：从失败到首分叉

故障项不应只写“见某章”。它要记录症状、请求或会话范围、阶段、首个异常对象、可能负责人和最小重放任务。答案无引用先查证据链，工具越权先查权限边界，会话串扰先查状态所有者；不同症状对应不同排查入口。

### 版本与别名

模型、框架、端点和术语常有别名。索引保存规范名称、用户常用称呼、版本和别名的关系，但不要把不同版本压进同一条路径。旧版本仍有学习价值时，标为历史条目，并指向当前替代实现。

### 证据等级

目录能够证明范围与出版位置，论文能够支持方法与实验条件，官方文档能够支持接口与服务约束，重放记录能够证明某个环境下的实际结果。用 Evidence Tag 标明来源，不让目录描述冒充运行证据。

### 维护责任

每条高影响索引项都要有维护人、最后验证日期和下次复查触发器。模型版本、依赖锁、接口、数据权限或章节代码变化时，重新验证受影响条目。没有维护人的条目只能作为线索，不能作为上线依据。

### 搜索排序

搜索结果先按查询匹配，再按证据等级、版本匹配和验证新鲜度排序。不要让标题热度压过失败症状的精确匹配；排在第一项的结果必须说明为什么适合当前任务，并给出下一步动作。

## 索引维护的五类记录

### 术语记录

术语记录包括规范名称、别名、定义、边界、首次出现的章节和一个小例子。若同一个词在模型、数据或治理语境中含义不同，建立上下文独立的节点，并在结果中显示差异。

### 章节记录

章节记录包括路径、前置知识、目标、代码入口、练习、相关故障和验证日期。章节移动时更新稳定地址；不要只存页面顺序，因为读者真正需要的是从问题到行动的跳转。

### 代码与数据记录

代码记录写明语言、依赖、输入、输出和运行限制，数据记录写明来源、许可、脱敏方式、版本和清理策略。代码能执行不代表数据适合使用，索引应把两者的边界分别呈现。

### 故障记录

故障记录写明症状、影响、首个分叉、日志字段、重放任务、修复章节和回归结果。修复后保留原症状，以便未来判断同类问题是否再次出现；只改最终答案会丢失诊断线索。

### 版本记录

版本记录把模型、提示模板、检索快照、工具适配器、服务镜像和索引条目放在同一组变更里。验证日期过期时，条目进入待复核队列；复核通过后更新日期和重放结果，不能静默延长有效期。

## 容易踩的坑

<Callout type="trap">**现象：**搜索到一个同名模型条目，照着路径运行却得到不同结果；**原因：**索引没有区分版本、端点和默认参数；**修法：**把版本窗口、运行条件和验证日期作为条目字段，并为不同版本建立独立记录。</Callout>

<Callout type="trap">**现象：**故障页列出了很多可能原因，排查仍然没有方向；**原因：**条目没有标记首个异常对象、负责人和最小重放任务；**修法：**按症状建立反向入口，先定位首分叉，再跳到章节与回归测例。</Callout>

<Callout type="trap">**现象：**索引越做越大，读者却找不到下一步；**原因：**只收集名称和页码，没有把查询连接到产物与验收；**修法：**每个条目至少指向一个定义、一个样例和一个验证动作，过期条目降级或合并别名。</Callout>

## 小结与学习验收

- 索引项把查询、定义、路径和实践证据连成一条线。
- 反向入口从症状回溯到首个分叉、负责人和重放任务。
- 版本、证据标签和验证日期决定条目能否继续引用。
- 术语、章节、代码、数据和故障各自保存不同的边界。
- 能从任一条目找到下一步，也能从一次失败找回相关章节。

## 练习与答案

<Exercises>

**问题 1：概念理解。** 为什么索引项不能只保存术语和页码？

<Answer>

术语和页码只能帮助定位文字，不能说明定义边界、版本、样例或验证状态。补上学习路径、证据标签和验证日期后，读者才知道这个结果能否支持当前任务。
</Answer>

**问题 2：实践应用。** 为“工具越权”建立一条反向索引记录，至少要包含哪些字段？

<Answer>

记录症状、请求范围、首个异常参数、权限校验位置、负责章节、最小重放任务、预期阻断动作和最近回归日期。这样排查可以从症状直接进入边界检查，而不是只看最终答案。
</Answer>

**问题 3：独立实现。** 实现一个函数：缺少路径、样例或验证日期时，索引项不能被引用。

<Answer>

~~~python
def can_cite(entry):
    required = ["path", "sample", "verified"]
    missing = [key for key in required if not entry.get(key)]
    return {"cite": not missing, "missing": missing}
~~~

再把 `missing` 写入编辑队列，让维护人补齐字段，而不是让搜索结果静默通过。
</Answer>

</Exercises>

## 正式目录逐项讲解

### Index

本节把索引定义为术语、章节、代码、数据、实验与故障的双向入口。一个可发布的条目必须能说明查询对应的定义或症状、下一步路径、证据来源、版本边界、实践样例和最后验证日期；当这些条件不再成立时，应重查、降级或停止引用。索引的价值不在于收集最多名称，而在于让读者从问题走到行动，再从失败回到首个分叉。

它同时保留历史坐标与当前验证结果：旧模型或旧接口可以帮助解释章节背景，但不能覆盖当前版本的实验。通过这样的边界，索引既是阅读入口，也是维护团队知识、回归测试和发布责任的工作台。
