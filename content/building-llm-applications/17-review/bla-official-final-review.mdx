# 全书总复习：把章节串成一条可发布的证据链

复习不是重新朗读章节标题，而是把一个真实任务从输入走到结果，再从失败结果走回首个分叉。模型选择决定能力与成本，提示决定任务边界，检索和结构化数据提供证据，编排与工具扩大行动，代码与多模态改变输入形态，微调与责任治理则改变长期维护方式。

本页提供一条统一的复盘路径：先冻结任务与基线，再逐项加入能力；每轮保存配置、样例、阶段输出、判定和资源开销；最后用质量、安全、延迟、成本和可复现性五道门决定是否发布。章节不是孤立知识点，而是同一条系统链上的不同检查位置。

<Callout type="trap">**现象：**复习时能说出模型和框架名称，却无法写出一个最小可运行应用；**原因：**知识停留在名词层，没有把任务、数据、调用阶段和预期结果连接起来；**修法：**从一条脱敏任务开始，先实现最小基线，再一次只加入一个能力。</Callout>

<Callout type="trap">**现象：**最终答案看起来正确，团队就跳过中间检查直接发布；**原因：**没有保存检索证据、工具轨迹、权限判断和逐样本结果；**修法：**让每个阶段都有输入、输出、失败条件和责任人，发布只接受可回放的证据链。</Callout>

## 六个核心术语

复习的起点是 <Term def="固定任务、输入样例、预期结果与资源边界的最小实验基准">Frozen Baseline</Term>；新增检索、工具或记忆前，先记录一次 <Term def="把问题经过模型、提示、数据、工具和输出检查的顺序画成的阶段链">Application Trace</Term>。每个失败要定位 <Term def="沿阶段链从表面症状回溯到第一个异常对象的位置">First Divergence</Term>，而不是只修最后一句话。

发布前使用 <Term def="质量、安全、延迟、成本与复现五类条件组成的放行检查集合">Release Gates</Term>；每个结果都要有 <Term def="能够由同一输入、配置、版本和环境再次得到的证据">Replay Evidence</Term>。当应用需要退出生产路径时，<Term def="在质量或风险阈值触发后恢复上一组已验证产物的动作">Rollback Path</Term> 让降级和回退成为计划，而不是临时猜测。

## 三步全书复盘实验

猜一猜：把一个最小调用链增加检索或工具后，最先需要新增的是能力、证据，还是权限检查？每一步先写预测，再只改变一个条件。实验使用合成任务；真实项目还要加入数据许可、用户同意、地区规则和维护责任人。

## 用代码复盘一条调用链

下面的 Python 记录一次跨阶段调用的最小轨迹，并检查五道发布门；TypeScript 版本把阶段和门禁结果固定成类型。它们不执行真实模型，只帮助复习者发现“只有最终文本、没有中间证据”的空洞报告。

<CodeTabs>
  <Tab label="Python / 轨迹与门禁">

~~~python
def review_run(stages, checks):
    gates = ["quality", "safety", "latency", "cost", "repro"]
    missing_trace = [name for name, value in stages.items() if not value]
    failed_gates = [name for name in gates if not checks.get(name, False)]
    return {
        "publish": not missing_trace and not failed_gates,
        "missing_trace": missing_trace,
        "failed_gates": failed_gates,
    }
~~~

  </Tab>
  <Tab label="TypeScript / 复盘记录">

~~~typescript
type Stage = "input" | "prompt" | "evidence" | "action" | "output";
type Gate = "quality" | "safety" | "latency" | "cost" | "repro";

type ReviewRecord = {
  trace: Partial<Record<Stage, string>>;
  gates: Record<Gate, boolean>;
  rollback: string;
};

function canRelease(record: ReviewRecord): boolean {
  return Object.values(record.trace).every(Boolean)
    && Object.values(record.gates).every(Boolean)
    && Boolean(record.rollback);
}
~~~

  </Tab>
</CodeTabs>

`review_run` 将缺失阶段和失败门禁分开列出，便于复盘者先补证据，再处理质量或安全缺口；`canRelease` 还要求有回退路径。真实系统应把同一记录连接到请求编号、版本、数据快照、工具轨迹和人工决定。

## 按章节重建系统能力

### 任务与模型选择

先写用户、输入、输出、拒答、成功标准和最小反例，再比较模型质量、延迟、成本、上下文、服务稳定性和数据边界。模型名不是决策，任务与资源窗口才是决策。冻结基线后，任何模型替换都通过同一组样例重放。

### 提示与结构化输出

提示负责角色、上下文、示例、边界和格式，但它不是唯一安全边界。把结构字段、枚举值、长度、引用和拒答条件交给确定性校验；解析成功不代表事实正确，结构正确也不代表来源充分。

### 编排与对话

编排把多个步骤连接起来，对话增加会话状态、记忆和用户期待。复习时画出状态所有者、生命周期、清理点和异常分支，测试新会话、并发会话、过期状态和重复请求，避免把串扰误判为模型能力。

### 搜索、推荐与结构化数据

检索系统要记录切块、嵌入、召回、重排、引用和有效期；推荐系统要记录候选、过滤、排序与反馈；SQL 或结构化数据应用要限制查询模式、字段和权限。结果命中不等于证据被使用，查询成功不等于动作获授权。

### 代码与多模态

代码执行需要沙箱、超时、资源上限、无网络或受控网络和审计日志。多模态应用保存原始输入、变换结果、文字抽取、图像位置和人工复核；最终文本不能替代中间产物，图片看起来清楚也不代表小字和表格被正确读取。

### 微调、趋势与责任治理

微调复习聚焦数据分割、版本、过拟合、回归和发布策略；趋势复习聚焦来源、日期、复现和能力窗口；责任治理复习聚焦分群评测、隐私、越权、人工复核和事件回退。三者共同提醒我们：能力提升必须与证据、边界和责任同步。

## 五道发布门禁的证据

### 质量

质量门回答任务是否完成，不能只看平均分。保留正常、边界、长输入、空证据、格式错误和高影响样例，并报告逐例结果、尾部失败和人工修正。

### 安全

安全门覆盖提示注入、越权工具、隐私泄露、有害请求、偏见和过度拒答。每条失败连接到阻断层、负责人、修复和重放，不用一句“模型已对齐”替代测试。

### 延迟

延迟门区分模型等待、检索、工具、队列、串行步骤和人工接管。报告中位数与尾延迟，说明缓存、并发、超时和降级策略，避免只用一次快照代表线上体验。

### 成本

成本门记录输入输出量、检索、工具、存储、人工和失败重试。给每个任务写预算与超限动作；低单价模型若产生更多重试、误判和人工处理，整体成本可能更高。

### 可复现

复现门冻结任务、数据快照、模型版本、提示、依赖、工具、随机参数和判定脚本。复现失败时标记差异来源，保留环境与输出，而不是覆盖旧结果以制造稳定假象。

## 第一版目录的复盘地图

全书正式目录被重新组织成四条复盘线，而不是只背章节顺序：

- **能力线：**模型选择、提示、结构化输出、微调和新能力，回答“它能做什么”。
- **链路线：**嵌入、对话、搜索、推荐、编排、工具和多模态，回答“它如何完成任务”。
- **证据线：**数据、引用、代码执行、评测、成本、延迟和回归，回答“凭什么相信结果”。
- **治理线：**权限、隐私、责任、公平、事件、回退和版本，回答“出了问题怎么办”。

学习地图、延伸阅读和索引页是本站的导航与复盘入口，不替代原书正式目录；复习时通过它们回到具体章节、代码和实验，而不是把导航文案当成技术事实。

## 容易踩的坑

<Callout type="trap">**现象：**全书复习结束仍无法写出最小应用；**原因：**把章节当作知识清单，没有冻结任务、输入、输出和基线；**修法：**先写一条可运行请求，再逐项加入检索、状态、工具或多模态，并保留每步差异。</Callout>

<Callout type="trap">**现象：**故障修复后平均分变高，却在边界输入上再次失效；**原因：**修复只重放正常样例，没有保留原失败、相邻边界和逐阶段轨迹；**修法：**先重放原失败，再跑边界与基线，把首个分叉和回归结果写入记录。</Callout>

<Callout type="trap">**现象：**所有质量指标都很好，线上仍无法安全发布；**原因：**缺少权限、隐私、成本、责任人或回退路径；**修法：**五道门都设阈值、负责人和动作，任一关键门缺证据就暂停扩大。</Callout>

## 小结与学习验收

- 从冻结任务和最小基线开始，而不是从模型名开始。
- 每次只加入一个能力，并保留输入、配置、阶段输出和判定。
- 从故障症状回放到首个分叉，再验证修复是否关闭原问题。
- 质量、安全、延迟、成本和复现五道门都要有证据。
- 发布记录必须包含责任人、回退路径和下一次复查条件。

## 练习与答案

<Exercises>

**问题 1：概念理解。** 为什么总复习需要一条 Application Trace，而不是只保留最终答案？

<Answer>

最终答案只能显示末端结果，无法区分提示偏离、检索缺失、工具越权、状态串扰或输出校验失败。阶段链保存每一步的输入、输出和判断，才能定位首个分叉并设计可复现修复。
</Answer>

**问题 2：实践应用。** 一个应用的质量、安全、延迟和成本都通过，但没有回退路径，应该如何决定？

<Answer>

暂不扩大或发布。可复现和回退是责任的一部分；先确定上一组已验证产物、触发阈值、负责人和恢复动作，再重跑关键样例并更新发布记录。
</Answer>

**问题 3：独立实现。** 实现一个函数：五道门中任意一项失败，返回失败名称而不是只返回 false。

<Answer>

~~~python
def release_review(checks):
    gates = ["quality", "safety", "latency", "cost", "repro"]
    failed = [gate for gate in gates if not checks.get(gate, False)]
    return {"release": not failed, "failed": failed}
~~~

把 `failed` 写入发布单，并为每一项指定修复人和下一次复查日期。
</Answer>

</Exercises>

## 本章回顾

全书总复习的验收不是记住模型、框架或章节名称，而是能从一个冻结任务重建最小调用链，保存跨阶段证据，从失败回放到首个分叉，并用质量、安全、延迟、成本和复现五道门做出放行、降级或回退决定。通过后仍要留下责任人、回退路径与复查条件，让结论可以独立复核。
