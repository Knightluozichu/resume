## 为什么 scanf 有时「不吃」你刚打的字？

想象快递柜取件：你输入取件码 `42` 然后按确认，柜门只认数字部分，**确认键的「咔嗒」还留在槽里没清走**。下一次有人来取件，柜门先把上次残留的「咔嗒」当输入处理了——你以为程序在等你打字，其实它早就读到了一个看不见的换行符。

程序和标准输入之间也有这样一个「快递槽」——<Term def="标准输入流 stdin 在程序和键盘之间暂存字符数据的区域。scanf 和 getchar 都从这里取数据。">输入缓冲区（input buffer）</Term>。上一章学了 scanf 和 switch 菜单；这一章降到**字符层**看清数据怎么一进一出，并学会**验证输入、清理残留**，写出不会「莫名其妙跳过等待」的交互程序。

## getchar 与 putchar：一次只搬一个字符

<Term def="从标准输入 stdin 读取下一个字符的标准库函数，返回该字符的 int 值或 EOF。声明在 stdio.h。">getchar()</Term> 和 <Term def="向标准输出 stdout 写一个字符的标准库函数，成功返回该字符，失败返回 EOF。声明在 stdio.h。">putchar()</Term> 是 C 里最「原始」的文本 I/O——不解析格式，一次处理一个字符：

```c
#include <stdio.h>
int main(void) {
    int ch;

    printf("输入字符（Ctrl+D 结束）:\n");
    while ((ch = getchar()) != EOF)
        putchar(ch);    /* 原样回显 */
    return 0;
}
```

注意 `ch` 的类型是 **int** 而不是 char。因为 getchar 要能返回 <Term def="End Of File 的负值整型宏，表示输入结束或读错误，不是普通字符。">EOF</Term>。标准只保证 EOF 是负值整型常量，不保证它恰好为 -1。若用 char 存储，EOF 可能与有效字节混淆，循环判断会出错。

putchar 把单个字符送到 stdout；getchar 从 stdin 取单个字符。它们底下仍走标准 I/O 的缓冲机制——不是每个字符都立刻跟键盘硬件打交道。

> 猜一猜：上面循环里用户按回车，putchar 会输出几个字符？换行符算不算「一个字符」？

<Term def="在程序和 I/O 设备之间暂存数据、批量读写的机制。分全缓冲、行缓冲、无缓冲三种。">缓冲 I/O（buffered I/O）</Term> 让实现不必为每个字符都执行底层读写。stdout 连接交互终端时常采用 <Term def="输出遇到换行、缓冲区满或显式刷新时送往目标的缓冲模式。交互流常采用该模式，但具体策略由实现和运行环境决定。">行缓冲（line buffered）</Term>；连接文件时常采用全缓冲。具体模式由 C 实现和运行环境决定，不能仅凭流名称断言。写交互程序时，提示后调用 `fflush(stdout)` 能明确要求已写数据送往目标。

<Stepper>
  <Step title="第一步：行缓冲——终端上的 stdout">
    stdout 连接交互终端时通常采用行缓冲。换行、缓冲区满或显式 fflush 会触发刷新；没有换行的提示可能暂时不可见。
  </Step>
  <Step title="第二步：全缓冲——文件与重定向">
    stdout 重定向到文件，或 fopen 打开的文件流，通常采用**全缓冲**。正常关闭流会刷新待写数据；异常终止时尚未刷新的数据可能丢失，关键边界应检查 fflush 或 fclose 的结果。
  </Step>
  <Step title="第三步：无缓冲——stderr 立刻到达">
    stderr 启动时不是全缓冲，常见实现把它设为无缓冲，但仍不应把“立刻显示”当成跨平台时序保证。它与 stdout 是不同流，适合错误诊断，也便于分别重定向。
  </Step>
</Stepper>

## 文件流和键盘输入：标准流与重定向

C 程序面对的是 <Term def="标准库用 FILE 对象表示的有序字节通道；同一套字符和格式化 I/O 可连接终端、普通文件或管道。">流（stream）</Term>，不是直接面对键盘或磁盘。程序启动时已有 `stdin`、`stdout`、`stderr` 三个标准文本流；`fopen` 则返回指向其他 `FILE` 对象的指针。`getchar()` 等价于从 `stdin` 调用 `getc`，`putchar(ch)` 等价于向 `stdout` 调用 `putc`。

```c
#include <stdio.h>

int main(void) {
    int ch;
    while ((ch = getchar()) != EOF)
        putchar(ch);

    if (ferror(stdin) || ferror(stdout)) {
        fputs("I/O error\n", stderr);
        return 1;
    }
    return 0;
}
```

同一程序无需修改，就能由命令环境改变流的连接：

```bash
./copy < input.txt > output.txt
producer | ./copy
```

第一条把文件连接到 stdin，并把 stdout 连接到另一个文件；第二条把前一个进程的输出连接到本程序输入。重定向通常由 shell 或宿主环境在程序启动前完成，不是 `<` 或 `|` 被 C 程序解析。`getchar()` 返回 EOF 后，用 `feof(stdin)` 可判断正常到达输入末尾，用 `ferror(stdin)` 判断读取失败；EOF 这个返回值本身不区分两者。

## 缓冲输入与混合数字字符输入：stdin 残留

上一章讲过 scanf 从缓冲区按格式「解码」数据。关键细节：**它只消费匹配成功的部分**，其余字符原封不动留在 stdin 缓冲区。

<StdinBufferDiagram />

用户输入 `42` 然后按回车，缓冲区里是 `'4' '2' '\n'`。`scanf("%d", &n)` 吃掉 `42`，**换行符 `\n` 还在**。紧接着 `getchar()` 读到的就是 `\n`（ASCII 10），不是你以为的「下一个按键」。

<Term def="检查用户输入是否合法、在非法时提示并重试，同时清理输入缓冲区残留字符的编程模式。">输入验证（input validation）</Term> 要保证：读入失败时不仅打印错误，还要**把缓冲区吃到干净**，否则重试时读到的是垃圾。

> 猜一猜：用户输入 `abc` 而程序期望整数，如果不清理缓冲区就 while 重试，会发生什么？

<Stepper>
  <Step title="第一步：整行进缓冲区">
    <StdinBufferDiagram step={1} />
    键盘驱动把用户敲的一行（含回车）送入 stdin 缓冲区。getchar 和 scanf 都从这里取数据，不是直接问键盘。
  </Step>
  <Step title="第二步：scanf 只取匹配部分">
    <StdinBufferDiagram step={2} />
    scanf("%d") 解析出整数后停止，**不匹配的字节留在缓冲区**。换行符、空格、字母都可能是残留。
  </Step>
  <Step title="第三步：下一次读取吃到残留">
    <StdinBufferDiagram step={3} />
    后续 getchar 或 scanf 优先消费残留。表现为「程序没等我输入就继续了」或「读到的总是换行」。恢复时必须读到换行或 EOF；只等换行会在输入已结束时死循环。
  </Step>
</Stepper>

## 输入验证：读入、检验、清理、重试

健壮的数字输入不是「scanf 一次就信」，而是区分成功、匹配失败和 EOF，再决定接受、清理或结束。先写一个不会在 EOF 卡住的记录清理函数：

<InputValidationFlowDiagram />

```c
static int discard_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF)
        ;
    return ch;
}

int main(void) {
    int n, status;

    for (;;) {
        printf("请输入 1-10 的整数: ");
        fflush(stdout);
        status = scanf("%d", &n);

        if (status == EOF)
            return 0;
        if (status == 1 && n >= 1 && n <= 10) {
            discard_line();
            break;
        }

        if (status == 0)
            puts("需要整数。");
        else
            printf("%d 不在 1-10 范围内。\n", n);
        if (discard_line() == EOF)
            return 0;
    }

    printf("你输入了 %d\n", n);
    return 0;
}
```

`scanf` 返回成功赋值的项数；期望 1 个整数却在首个非空白字符遇到字母时返回 0，到达输入末尾或读取失败且尚未赋值时返回 EOF。格式成功后还要做 1-10 的范围验证。`discard_line` 同时检查换行和 EOF，因此无论一行多长、文件是否以换行结尾，都能终止。

> 猜一猜：匹配失败后不调用 `discard_line()`，用户输入 `hello` 时下一次 scanf 会读取什么？

## 菜单驱动程序：把分支语句变成交互骨架

上一章的 switch 菜单在本章加上**输入验证**和**字符层选项**，就是完整的 <Term def="通过循环显示选项、读入用户选择、用 switch 分发功能、直到用户选择退出的程序结构。">菜单驱动程序（menu-driven program）</Term>：

<MenuDriverDiagram />

```c
#include <stdio.h>

static int discard_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF)
        ;
    return ch;
}

int main(void) {
    int choice, status;

    do {
        printf("\n=== 计算器 ===\n");
        printf("1. 加法  2. 减法  0. 退出\n");
        printf("请选择: ");
        fflush(stdout);

        status = scanf("%d", &choice);
        if (status == EOF)
            break;
        if (status != 1) {
            printf("请输入数字选项\n");
            if (discard_line() == EOF)
                break;
            continue;
        }
        discard_line();

        switch (choice) {
            case 1:
                printf("执行加法\n");
                break;
            case 2:
                printf("执行减法\n");
                break;
            case 0:
                printf("再见！\n");
                break;
            default:
                printf("无效选项 %d\n", choice);
        }
    } while (choice != 0);

    return 0;
}
```

单字符菜单可以用 getchar 读 `'y'/'n'`，但记得前面若有 scanf 残留，应按记录边界处理。不要直接写 `toupper(getchar())`：先用 int 保存返回值，排除 EOF，再把非 EOF 值转换为 `unsigned char` 后传给 `toupper`。

<Stepper>
  <Step title="第一步：显示菜单">
    <MenuDriverDiagram step={1} />
    每次循环开头用 printf 列出选项。do-while 保证至少显示一次；末尾加空行 `\n` 提升可读性。
  </Step>
  <Step title="第二步：读入并验证 choice">
    <MenuDriverDiagram step={2} />
    scanf 读整数选项，检查返回值。失败则清缓冲区并 continue 回菜单，不进入 switch。
  </Step>
  <Step title="第三步：switch 分发功能">
    <MenuDriverDiagram step={3} />
    各 case 执行对应功能，末尾 break 防 fall-through。default 捕获非法数字。case 0 打印告别信息。
  </Step>
  <Step title="第四步：循环或退出">
    <MenuDriverDiagram step={4} />
    while (choice != 0) 控制是否回到菜单。choice 为 0 时跳出 do-while，程序结束。break 只跳出 switch，退出靠循环条件。
  </Step>
</Stepper>

## 代码详解：字符过滤与行读取

### 场景一：统计一行中的字母个数

```c
#include <stdio.h>
#include <ctype.h>
int main(void) {
    int ch, count = 0;

    printf("输入一行文字:\n");
    while ((ch = getchar()) != '\n' && ch != EOF) {
        if (isalpha(ch))
            count++;
    }
    printf("字母个数: %d\n", count);
    return 0;
}
```

循环读到换行或 EOF 为止；`isalpha` 判断字母。ch 用 int，EOF 安全。

### 场景二：吃掉空白后读字符选项

```c
#include <stdio.h>
int main(void) {
    int ch;

    printf("确认？(y/n): ");
    fflush(stdout);
    while ((ch = getchar()) == ' ' || ch == '\t' || ch == '\n')
        ;   /* 跳过前导空白 */
    if (ch == 'y' || ch == 'Y')
        printf("已确认\n");
    else
        printf("已取消\n");
    return 0;
}
```

混合 scanf 后常需类似循环清掉 `\n` 再读 y/n。

### 场景三：用 getchar 实现「读一行」

```c
#define MAX 80
char line[MAX];
int i = 0, ch;

while (i < MAX - 1 && (ch = getchar()) != '\n' && ch != EOF)
    line[i++] = (char)ch;
line[i] = '\0';
```

留一位给 `\0`；但若输入超过 79 个字符，当前片段会把余下字符留给下一次读取。实际代码应在数组填满后丢弃到换行或 EOF，并检查读取错误。生产环境通常直接使用 `fgets`，再判断是否读到换行来识别截断；`gets` 无法限制长度，C11 已将它从标准库移除。

### 场景四：验证后的菜单（完整骨架）

```c
#include <stdio.h>

static int discard_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF)
        ;
    return ch;
}

int main(void) {
    int op, a, b, status;

    do {
        printf("1.加 2.减 0.退出\n选: ");
        fflush(stdout);
        status = scanf("%d", &op);
        if (status == EOF)
            break;
        if (status != 1) {
            puts("需要整数");
            if (discard_line() == EOF)
                break;
            continue;
        }
        discard_line();
        if (op == 0)
            break;
        if (op < 1 || op > 2) {
            puts("选项 1 或 2");
            continue;
        }
        printf("两整数: ");
        status = scanf("%d %d", &a, &b);
        if (status == EOF)
            break;
        if (status != 2) {
            puts("需要两个整数");
            if (discard_line() == EOF)
                break;
            continue;
        }
        discard_line();
        printf("结果: %d\n", op == 1 ? a + b : a - b);
    } while (1);
    return 0;
}
```

每次 scanf 后检查返回值；匹配失败清到记录边界，EOF 则结束交互。内层 continue 回到菜单，不嵌套过深。

## 容易踩的坑

<Callout type="trap">
  **现象**：`scanf("%d", &n); ch = getchar();` 后 ch 总是 `'\n'`，确认菜单像「自动按了回车」。
  **原因**：scanf 读整数后不消费行尾换行符，getchar 读到缓冲区残留。
  **修法**：按行交互时，用 `while ((ch = getchar()) != '\n' && ch != EOF) {}` 清到记录边界；只想读取下一个非空白字符时，可用 `scanf(" %c", &c)`，但仍要检查返回值，且前导空格会跨过任意数量的空白。
</Callout>

<Callout type="trap">
  **现象**：`char ch; while ((ch = getchar()) != EOF)` 文件未到尾就结束，或死循环。
  **原因**：char 可能是有符号类型，0xFF 字节被当成 -1 与 EOF 相等；或 unsigned char 与 EOF 比较隐式转换出错。
  **修法**：**永远用 int 接 getchar 返回值**，再 `(char)ch` 存入字符串。
</Callout>

<Callout type="trap">
  **现象**：提示「请输入:」不显示，程序像卡在 scanf。
  **原因**：当前 stdout 的缓冲策略尚未把无换行提示送到目标；交互终端上常见于行缓冲，重定向时也可能发生。
  **修法**：提示后 `fflush(stdout);` 或 `printf("请输入:\n");`。
</Callout>

<Callout type="trap">
  **现象**：输入 `abc` 期望数字，屏幕疯狂刷「无效输入」停不下来。
  **原因**：scanf 失败返回 0 但不消费 `abc\n`，下次循环立即再次失败，没给用户重新输入的机会。
  **修法**：失败分支读到换行或 EOF；换行后再提示，EOF 时结束。若只等待换行，文件末尾没有换行时会形成另一个死循环。
</Callout>

## 小结

- getchar/putchar 逐字符读写；返回值用 int 以正确区分 EOF 与普通字节
- 标准 I/O 面向流；重定向可把同一 stdin/stdout 程序连接到终端、文件或管道
- 缓冲策略取决于实现与连接目标；交互提示后 fflush(stdout) 明确要求刷新
- scanf 只消费匹配部分，换行等残留留 stdin；混合 I/O 必须清缓冲区
- 健壮输入 = 区分赋值数和 EOF + 范围验证 + 清到换行或 EOF 后再决定重试
- 菜单驱动 = do-while + 验证读入 + switch 分发 + default 兜底

问题：① `c` 应为 int；② getchar 读到 scanf 残留的 `\n` 而非 y。

修正：

```c
int n, c, tail;
if (scanf("%d", &n) != 1)
    return 1;
while ((tail = getchar()) != '\n' && tail != EOF)
    ;
printf("确认 %d? (y/n): ", n);
fflush(stdout);
c = getchar();
if (c == 'y' || c == 'Y')
    printf("已确认\n");
```

</Answer>

**问题 2（问答型）** `scanf("%d", &x)` 用户输入 `3.14` 时，scanf 返回值是多少？x 的值是多少？缓冲区里还剩什么？

<Answer>

返回值 **1**（成功读入整数 3）。x = 3。缓冲区残留 `.14\n`（或从 `.` 开始的未匹配部分）。若接着 `scanf("%d", &y)` 会失败，因为 `.` 不是数字开头。应清缓冲区再重读。

</Answer>

**问题 3（综合实现型）** 写程序：循环提示输入 1-5 的评分，用 scanf 读入并验证；非法输入提示并清缓冲区；合法输入打印「谢谢」后结束；若输入结束则正常退出。

<Answer>

```c
#include <stdio.h>

static int discard_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF)
        ;
    return ch;
}

int main(void) {
    int score, st;

    while (1) {
        printf("评分 1-5: ");
        fflush(stdout);
        st = scanf("%d", &score);
        if (st == EOF)
            return 0;
        if (st == 1 && score >= 1 && score <= 5) {
            discard_line();
            break;
        }
        if (st == 0)
            printf("请输入整数\n");
        else
            printf("%d 超出范围\n", score);
        if (discard_line() == EOF)
            return 0;
    }
    printf("谢谢，你打了 %d 分\n", score);
    return 0;
}
```

</Answer>

## 名词解释

<Glossary>

<GlossaryItem term="getchar()">
  从标准输入读取下一个字符的标准库函数。返回 int（字符值或 EOF）。声明在 stdio.h。与 putchar 配对实现字符级 I/O。
</GlossaryItem>

<GlossaryItem term="putchar()">
  向标准输出写一个字符。成功返回该字符，失败返回 EOF。声明在 stdio.h。常用于循环回显或配合 getchar 过滤字符。
</GlossaryItem>

<GlossaryItem term="EOF">
  End Of File 的负值整型宏，表示输入结束或读错误，不是普通字符。标准不保证它等于 -1；getchar 返回值须存 int，并用 feof 或 ferror 区分结束原因。
</GlossaryItem>

<GlossaryItem term="输入缓冲区（input buffer）">
  stdin 在程序和键盘之间的暂存区。用户按回车后整行先进缓冲区，scanf/getchar 再从中取。不匹配 scanf 格式的字符会残留。详见 StdinBufferDiagram。
</GlossaryItem>

<GlossaryItem term="缓冲 I/O（buffered I/O）">
  程序与设备之间用内存块批量读写，减少系统调用。分全缓冲、行缓冲、无缓冲。详见 BufferedIODiagram。
</GlossaryItem>

<GlossaryItem term="行缓冲（line buffered）">
  遇到换行符或缓冲区满才刷新到设备。终端 stdout 常用此模式。无换行的 printf 可能延迟显示。
</GlossaryItem>

<GlossaryItem term="输入验证（input validation）">
  读入后先检查转换结果，再检查业务范围；匹配失败时清理到换行或 EOF，只有仍有输入时才重试。详见 InputValidationFlowDiagram。
</GlossaryItem>

<GlossaryItem term="流（stream）">
  标准库用 FILE 对象表示的有序字节通道。stdin、stdout、stderr 是启动时已有的标准流，可由运行环境连接到终端、文件或管道。
</GlossaryItem>

<GlossaryItem term="菜单驱动程序（menu-driven program）">
  循环显示选项、读入选择、switch 分发、直到退出。结合 do-while、输入验证与 default。详见 MenuDriverDiagram。
</GlossaryItem>

</Glossary>
