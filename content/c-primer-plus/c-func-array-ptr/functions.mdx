## 为什么要把代码装进「函数」？

想象一家工厂把「切菜」「炒菜」「装盘」拆成三个工位：每个工位只做一件事，原料从上一个工位递过来，成品交给下一个。主程序如果把所有步骤写进 main，就像一个人包办全流程——代码越长越难改，改一处可能牵全身。

**如果没有函数呢？** 重复逻辑只能复制粘贴，变量名容易冲突，团队协作也无法分工。函数把「一段可复用的加工步骤」打包命名：需要时调用，不需要时不用管内部细节。这一章教你 C 语言里函数怎么定义、怎么声明、怎么传参、怎么返回值，以及怎样用多个函数拼出模块化程序。

## 创建和使用函数：定义、原型与调用

<Term def="由返回类型、函数名、形参列表和函数体组成的完整实现。告诉编译器函数做什么，并提供可执行的代码。">函数定义</Term> 是函数的「完整档案」：

```c
int sum(int a, int b)   /* 函数头 */
{
    return a + b;       /* 函数体 */
}
```

`int` 是返回类型，`sum` 是名字，`(int a, int b)` 是形参列表，花括号里是函数体。`return` 把结果交回给调用方。

若函数定义写在 `main` **之后**，调用点之前的编译器还不知道 `sum` 长什么样——需要 <Term def="在调用之前向编译器说明函数名、返回类型和形参类型的语句。也称函数声明。不含函数体。">函数原型（声明）</Term>：

```c
int sum(int a, int b);  /* 原型：分号结尾，无函数体 */

int main(void) {
    int x = sum(3, 5);  /* 调用 */
    return 0;
}

int sum(int a, int b) { /* 定义 */
    return a + b;
}
```

原型是「名片」，定义是「车间」，调用是「下单」。编译器用原型检查 `sum(3, 5)` 类型是否匹配；链接器把调用绑到真正的定义上。

`void` 作返回类型表示「无返回值」——函数体里用 `return;` 提前结束，或不写 return 落到函数末尾。

## 形参、实参与值传递

调用 `sum(3, 5)` 时，`3` 和 `5` 是 <Term def="调用函数时括号里提供的表达式或变量。其值按规则传给形参。">实参（actual argument）</Term>；定义里的 `a`、`b` 是 <Term def="函数定义或原型中列出的占位参数。调用时接收实参传来的值。">形参（formal parameter）</Term>。

C 对 `int`、`double`、`char` 以及结构体等，默认采用 <Term def="把实参的值拷贝一份给形参。形参与实参占用不同内存，修改形参不影响实参。">值传递（pass by value）</Term>：

```c
void try_change(int n) {
    n = 99;
}

int main(void) {
    int num = 5;
    try_change(num);
    printf("%d\n", num);  /* 仍是 5 */
    return 0;
}
```

<ParameterPassingDiagram />

函数内改 `n` 只改形参副本，main 里的 `num` 不动。要让函数改调用方的变量，需传指针（下一章）或把新值 `return` 回去。

<Term def="函数执行完毕或通过 return 交还给调用方的结果。类型须与函数声明的返回类型兼容。">返回值</Term> 常用赋值或表达式接收：`int r = sum(3, 5);` 或 `printf("%d", sum(3, 5));`。

## 调用记录：一次函数调用发生了什么

从 C 抽象机看，每次函数调用都有独立的参数与自动对象实例，并在返回后结束本次执行。常见 ABI 用 <Term def="常见机器实现中用于保存一次函数调用状态的区域，可含返回地址、被保存寄存器与部分自动对象；具体布局不是 C 语言保证。">栈帧（stack frame）</Term> 表示这份调用记录，但优化器可以把参数和局部对象放入寄存器、消除对象，甚至内联整个调用。因此下图是理解调用关系的典型实现模型，不是可移植程序可以依赖的内存布局。

## 局部变量、块作用域与自动存储期

<Term def="在函数体或复合语句块内声明的对象；其名字通常具有块作用域，未带 static 时通常具有自动存储期。">局部变量</Term> 的名字属于 <Term def="从声明点开始，到包含该声明的最小复合语句或函数定义末尾为止的可见区域。">块作用域</Term>。形参的作用域覆盖整个函数定义；函数体内普通局部对象通常具有自动存储期，每次进入相应块都会产生新的对象实例：

```c
int twice(int n);

int main(void) {
    int x = 10;        /* main 的局部变量 */
    printf("%d\n", twice(x));
    return 0;
}

int twice(int n) {     /* n 是 twice 的局部变量 */
    int tmp = n * 2;   /* tmp 也是 twice 的局部 */
    return tmp;
}
```

`main` 看不到 `tmp`，`twice` 也看不到 `x`，因为它们的块作用域不重叠。同名局部标识符在不同函数里互不影响；内层块还可以隐藏外层同名标识符。C 标准术语中的**函数作用域只属于 label 标签**，普通局部变量不是“函数作用域”。

函数内的 static 局部对象（`static int count`）具有静态存储期，生命周期贯穿整个程序，但名字仍只有块作用域；后续章节会展开。

## 递归：函数调用自身

<Term def="函数直接或间接调用自身的编程技巧。必须有基准情形终止递归，否则无限压栈导致栈溢出。">递归（recursion）</Term> 把大问题拆成「同样结构的小一号问题」：

```c
long fact(int n) {
    if (n <= 1)
        return 1;           /* 基准情形 */
    return n * fact(n - 1); /* 递归情形 */
}
```

`fact(4)` = 4 × `fact(3)` = 4 × 3 × `fact(2)` = … 直到 `fact(1)` 直接返回 1，再逐层乘回。

<Stepper>
  <Step title="第一步：fact(4) 入栈">
    第一次调用 n=4，尚未算完，需要 `fact(3)` 的结果。
  </Step>
  <Step title="第二步：递归加深">
    fact(3)、fact(2) 依次压栈——每层都「挂起」等待内层。
  </Step>
  <Step title="第三步：到达基准">
    n=1 时 return 1，不再继续递归。
  </Step>
  <Step title="第四步：逐层返回">
    1 → fact(2)=2 → fact(3)=6 → fact(4)=24。栈从深到浅依次弹出。
  </Step>
</Stepper>

### 尾递归不是“自动省栈”承诺

当递归调用是返回前最后一个动作时，称为 <Term def="递归调用的结果被当前函数直接返回，调用后不再执行乘法、加法等待完成操作的递归形式。">尾递归（tail recursion）</Term>。把中间结果放进累加器，就能把阶乘写成尾递归：

```c
static unsigned long fact_tail(unsigned n, unsigned long acc) {
    if (n <= 1)
        return acc;
    return fact_tail(n - 1, acc * n);
}

unsigned long fact(unsigned n) {
    return fact_tail(n, 1UL);
}
```

实现**可以**把尾调用复用为当前调用记录，但 C11 不保证尾调用优化；可移植程序不能因为“这是尾递归”就假定常量栈空间。若深度由不可信输入决定，循环通常更稳妥。无论递归还是循环，`unsigned long` 的阶乘都会很快溢出，生产代码还要在乘法前检查 `acc > ULONG_MAX / n`。

## 多源文件与头文件：从翻译单元到链接

较大的程序会把声明放进头文件，把定义分散到多个源文件。预处理后，每个 `.c` 文件连同它包含的头文件形成一个 <Term def="一个源文件经过预处理、展开 include 后交给编译器处理的完整单位；各翻译单元分别生成目标文件。">翻译单元</Term>，再由链接器把目标文件组成程序。

```c
/* math_utils.h */
#ifndef MATH_UTILS_H
#define MATH_UTILS_H
int square(int value);
#endif
```

```c
/* math_utils.c */
#include "math_utils.h"

int square(int value) {
    return value * value;
}
```

```c
/* main.c */
#include <stdio.h>
#include "math_utils.h"

int main(void) {
    printf("%d\n", square(7));
    return 0;
}
```

```bash
cc -std=c11 -Wall -Wextra -Wpedantic -c math_utils.c
cc -std=c11 -Wall -Wextra -Wpedantic -c main.c
cc main.o math_utils.o -o app
```

头文件保护宏允许同一声明被间接包含多次；函数定义留在一个 `.c` 文件中。声明告诉每个调用所在的翻译单元函数类型，定义提供最终可链接实体。具有外部链接的普通函数在整个程序中通常只能有一个定义：没有定义会产生未解析符号，重复定义会产生多重定义错误。

## 地址和指针：仍然是值传递

一元 `&` 运算符取得对象的地址，`*` 对指针做 <Term def="通过指针保存的地址访问它所指向对象的运算，也称解引用；只可用于有效、对齐且指向对象生存期内的指针。">间接访问</Term>。把地址作为实参，函数收到的仍然是**指针值的副本**，但副本和调用方指针指向同一对象，所以能修改该对象：

```c
#include <stdio.h>

void swap(int *left, int *right) {
    int temp = *left;
    *left = *right;
    *right = temp;
}

int main(void) {
    int a = 3, b = 8;
    swap(&a, &b);
    printf("a=%d b=%d\n", a, b);
    return 0;
}
```

调用方用 `&a`、`&b` 提供有效地址，`swap` 用 `*left`、`*right` 间接访问对象。若接口允许空指针，函数必须在解引用前明确处理；本例的契约要求两个参数都指向有效 `int`。传指针没有改变 C 的值传递规则，只是被复制的值恰好是地址。

## 代码详解：模块化小工具

### 场景一：函数原型 + 定义 + 调用

```c
#include <stdio.h>

double cube(double x);   /* 原型 */

int main(void) {
    printf("2^3 = %.0f\n", cube(2.0));
    return 0;
}

double cube(double x) {   /* 定义 */
    return x * x * x;
}
```

`main` 在前、定义在后时，原型不可省略。

### 场景二：多函数分工

```c
#include <stdio.h>

int get_int(int *value);
int square(int n);
void greet(void);

int main(void) {
    int x;
    greet();
    if (!get_int(&x))
        return 1;
    printf("平方 = %d\n", square(x));
    return 0;
}

void greet(void) {
    printf("输入一个整数：");
}

int get_int(int *value) {
    return scanf("%d", value) == 1;
}

int square(int n) {
    return n * n;
}
```

每个函数一块职责：问候、读入、计算——main 只做调度。

### 场景三：值传递与返回值

```c
#include <stdio.h>

int max_of_two(int a, int b) {
    if (a > b)
        return a;
    return b;
}

int main(void) {
    int m = max_of_two(12, 7);
    printf("较大者 %d\n", m);
    return 0;
}
```

形参 `a`、`b` 是实参的副本；`return` 把结果传回调用方，不修改 main 里原有变量。

### 场景四：递归求阶乘

```c
#include <stdio.h>

unsigned long fact(unsigned n) {
    if (n <= 1)
        return 1UL;
    return n * fact(n - 1);
}

int main(void) {
    printf("4! = %ld\n", fact(4));
    return 0;
}
```

本例聚焦递归结构，并假设 `4!` 可由 `unsigned long` 表示。若 n 来自输入，调用前还要限制范围或在每次乘法前做溢出检查。

## 容易踩的坑

<Callout type="trap">
  **现象**：`void foo()` 无参调用能编译，但 `foo(42)` 在某些旧编译器下也不报错，运行却错乱。
  **原因**：在本书使用的 C11 中，声明 `void foo()` 的空参数列表表示参数信息未指定，不是“函数不接收参数”的完整原型；`void foo(void)` 才明确无参数。
  **修法**：无参函数写 `void foo(void)`。不要依赖调用点缺少参数检查的旧式声明。
</Callout>

<Callout type="trap">
  **现象**：函数里改了形参，main 里的变量却没变，初学者以为「传进去了就应该联动」。
  **原因**：C 对基本类型是值传递——形参是副本。`void bump(int n) { n++; }` 不会让实参 +1。
  **修法**：需要改调用方变量时传地址 `void bump(int *p) { (*p)++; }` 并调用 `bump(&x)`，或 return 新值由调用方赋值。
</Callout>

<Callout type="trap">
  **现象**：调用函数前没有任何声明，现代编译失败或给出必须处理的诊断；强行继续可能生成不匹配的调用。
  **原因**：C99 起已经删除隐式函数声明与隐式 int。链接器只按符号连接，不能补做源语言层面的参数和返回类型检查。
  **修法**：让完整原型在调用前可见：把声明放进头文件并 include，或把定义放在调用之前。不要忽略该诊断。
</Callout>

<Callout type="trap">
  **现象**：`fact(n)` 没有 `if (n<=1) return 1`，程序崩溃或「栈溢出」。
  **原因**：递归无基准终止，每次调用再压一帧，栈空间有限，最终 stack overflow。
  **修法**：每个递归函数必须有「不再递归」的基准路径；递归深度极大时考虑改写成循环。
</Callout>

## 小结

- 函数 = 返回类型 + 名字 + 形参列表 + 体；原型供编译器检查，定义提供实现，链接器绑定调用
- 实参是调用时的值，形参是定义里的占位；C 默认值传递，改形参不改实参
- 每次调用有独立执行状态；栈帧是常见实现模型，不是所有局部对象的标准布局保证
- 普通局部变量具有块作用域；只有 label 标签具有 C 术语中的函数作用域
- 递归需基准情形与进展；尾调用优化不是 C11 保证
- 多源文件用头文件共享声明、源文件提供定义、链接器组合目标文件
- 传地址仍是值传递；被复制的指针可用于间接访问调用方对象

```c
int rect_area(int w, int h);   /* 原型 */

int main(void) {
    printf("面积 = %d\n", rect_area(5, 10));
    return 0;
}

int rect_area(int w, int h) {
    return w * h;
}
```

</Answer>

**问题 2（问答型）** 调用 `try_change(num)` 后 `num` 仍是 5，用文字说明值传递下内存里发生了什么。

<Answer>

调用时把 `num` 的值 5 **拷贝**到形参 `n` 的独立内存。函数内 `n = 99` 只修改副本。返回后形参帧销毁，main 中 `num` 所在内存从未被写入 99，故仍为 5。

</Answer>

**问题 3（综合实现型）** 写程序：用函数 `int is_prime(int n)` 判断素数，`void print_primes(int limit)` 打印 2 到 limit 之间所有素数。main 只负责读 `limit` 并调用。

<Answer>

```c
#include <stdio.h>

int is_prime(int n);
void print_primes(int limit);

int main(void) {
    int limit;
    printf("上限 = ");
    if (scanf("%d", &limit) != 1)
        return 1;
    print_primes(limit);
    return 0;
}

int is_prime(int n) {
    int i;
    if (n < 2)
        return 0;
    for (i = 2; i <= n / i; i++)
        if (n % i == 0)
            return 0;
    return 1;
}

void print_primes(int limit) {
    int i;
    for (i = 2; i <= limit; i++)
        if (is_prime(i))
            printf("%d ", i);
    printf("\n");
}
```

</Answer>

## 名词解释

<Glossary>

<GlossaryItem term="函数定义">
  由返回类型、函数名、形参列表和函数体构成的完整实现。既声明接口又提供可执行代码。具有外部链接且被使用的普通函数在整个程序中应有一个外部定义。
</GlossaryItem>

<GlossaryItem term="函数原型（声明）">
  在调用前向编译器说明函数名、返回类型和形参类型的语句，以分号结尾、无函数体。让编译器能检查调用是否类型匹配。详见 FunctionPrototypeDiagram。
</GlossaryItem>

<GlossaryItem term="形参（formal parameter）">
  函数定义或原型括号里列出的参数名，是实参值的接收占位。在函数栈帧中有自己的存储，值传递时是实参的副本。
</GlossaryItem>

<GlossaryItem term="实参（actual argument）">
  调用函数时写在括号里的表达式或变量。其值按传递规则交给形参。如 `sum(3, 5)` 中 3 和 5 是实参。
</GlossaryItem>

<GlossaryItem term="值传递（pass by value）">
  把实参的值拷贝给形参，形参与实参占用不同内存。修改形参不影响实参。C 对 int、double、结构体等默认采用值传递。详见 ParameterPassingDiagram。
</GlossaryItem>

<GlossaryItem term="返回值">
  函数通过 return 表达式交还给调用方的结果，类型须与函数声明的返回类型兼容。无返回值函数用 void，return 不带表达式。
</GlossaryItem>

<GlossaryItem term="栈帧（stack frame）">
  常见 ABI 用来保存一次函数调用状态的区域，可含返回地址、被保存寄存器和部分自动对象。具体布局以及对象是否实际入栈不由 C 标准保证。详见 FunctionCallStackDiagram。
</GlossaryItem>

<GlossaryItem term="局部变量">
  在函数体或复合语句块内声明的对象。名字通常具有块作用域；未带 static 时具有自动存储期，其生存期在相应块执行期间。
</GlossaryItem>

<GlossaryItem term="块作用域">
  从声明点到包含声明的最小复合语句或函数定义末尾的名字可见区域。普通局部变量和形参使用块作用域；C 的函数作用域只适用于 label 标签。
</GlossaryItem>

<GlossaryItem term="递归（recursion）">
  函数调用自身解决问题。须有基准情形停止递归，否则栈溢出。fact(n) 是经典示例。详见 RecursionStackDiagram。
</GlossaryItem>

<GlossaryItem term="尾递归（tail recursion）">
  递归调用结果被当前函数直接返回，调用之后没有待完成操作的递归形式。实现可以优化尾调用，但 C11 不保证常量栈空间。
</GlossaryItem>

<GlossaryItem term="翻译单元">
  一个源文件经过预处理并展开 include 后交给编译器的完整单位。多个翻译单元分别生成目标文件，再由链接器组成程序。
</GlossaryItem>

<GlossaryItem term="间接访问">
  对有效指针使用一元星号访问其所指对象的操作，也称解引用。指针必须满足对象生存期、类型和对齐等要求。
</GlossaryItem>

</Glossary>
