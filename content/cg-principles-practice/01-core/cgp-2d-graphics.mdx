## Ch2 Introduction to 2D Graphics Using WPF

WPF 是本书 2013 第三版使用的教学平台，不是现代项目必须采用的 API。可迁移原理是：

- **retained mode**：应用提交 scene objects/properties，系统保存并决定何时 layout、render、composite；
- **declarative scene**：XAML 之类描述结构与绑定，imperative code 处理状态变化；
- **hierarchy**：parent transform/opacity/clip 影响 descendants；
- **layout vs render transform**：前者参与测量与排列，后者通常只改变绘制；
- **device-independent unit**：逻辑单位与 device pixels 通过 DPI/display scale 映射。

<Term def="应用保留场景对象与属性，由图形框架跟踪变化并在需要时重新布局、绘制和合成的模式">保留模式场景</Term>与 immediate mode 各有边界。retained mode 易于 binding/animation/hit test，却需要 dirty propagation、lifetime 和 cache 策略；immediate mode 控制直接，但应用负责每帧重建命令与状态。

一个基本链路是 `input/binding → scene property → layout → world/render transform → clip → raster/composite → display`。debug 时必须知道问题发生在 layout 还是 rendering，而不是只改最终 matrix。

## Ch4 A 2D Graphics Test Bed

<Term def="以固定坐标、输入场景、可视化开关、参考输出和自动断言快速验证二维算法的最小实验环境">二维图形测试平台</Term>应允许：显示 control points/frames/bounds、逐步执行、保存输入、导出 reference、扫参数和比较算法版本。

corner cutting 以 polyline 相邻点生成新点。Chaikin-like 一步可写为：

$$
Q_i=(1-\alpha)P_i+\alpha P_{i+1},\qquad
R_i=\alpha P_i+(1-\alpha)P_{i+1},\quad 0<\alpha<1/2.
$$

迭代产生平滑极限趋势，但 open/closed endpoint rule、self-intersection、duplicate points 与 iteration growth 必须显式。test bed 要同时画原 polyline、新点与 segment correspondence，而不是只显示“更圆”的最终线。

```cpp
std::vector<Vec2> cornerCut(std::span<const Vec2> p, float alpha, bool closed) {
    require(alpha > 0.0f && alpha < 0.5f);
    std::vector<Vec2> out;
    forEachEdge(p, closed, [&](Vec2 a, Vec2 b) {
        out.push_back((1.0f - alpha) * a + alpha * b);
        out.push_back(alpha * a + (1.0f - alpha) * b);
    });
    return applyEndpointPolicy(out, p, closed);
}
```

测试不只比截图：验证 affine equivariance `cut(MP)=M cut(P)`、点数增长、convex-hull containment、closed continuity，以及 NaN/duplicate/empty input policy。

## Ch10 Transformations in Two Dimensions

<Cgp2dTransformDiagram />

<Term def="保持 affine combination 的变换，因此保留直线、平行性和同一直线上的比例；可由线性部分加平移表示">仿射变换</Term>对列向量约定：

$$
\tilde p'=M\tilde p,qquad
M=\begin{bmatrix}a&c&t_x\\b&d&t_y\\0&0&1\end{bmatrix},
\quad \tilde p=(x,y,1)^T.
$$

point 的 $w=1$ 会受 translation，vector 的 $w=0$ 不受 translation。rotation、scale、shear、reflection 都在 $2\times2$ 线性部分；determinant 表示有向面积缩放，`det(M)=0` 时变换不可逆。

若先执行 $A$ 再执行 $B$，列向量约定下：

$$
p'=B(Ap)=(BA)p.
$$

所以“先做的在右侧”只在已声明的列向量约定下成立；row-vector 项目顺序相反。内存 row-major/column-major 又是独立问题。

### Pivot、frame 与换基

绕 pivot $c$ 旋转：$M=T(c)R(\theta)T(-c)$。把坐标从 frame A 转到 B，应组合 `worldFromA` 与 `BFromWorld = inverse(worldFromB)`：

$$
p_B=M_{B\leftarrow W}M_{W\leftarrow A}p_A.
$$

命名矩阵的 source/target 比只写 `modelMatrix` 更能阻止顺序错误。inverse 还用于 hit testing：可把 pointer 从 screen 映回 local，再用简单 local geometry query。

<Term def="用额外坐标把 affine translation 与 linear transform 统一为矩阵乘法，并可表示无穷远方向的坐标系统">齐次坐标</Term>不只是“为了平移”。一般 projective transform 的最后一行可不是 `[0,0,1]`，结果需除以 $w$；$w\approx0$ 与符号变化必须有策略。

## Ch12 A 2D and 3D Transformation Library for Graphics

<CgpTransformLibraryDiagram />

变换库首先是 semantic contract：

- `Point2 - Point2 -> Vector2`，`Point2 + Vector2 -> Point2`，禁止 `Point + Point` 的无意义默认；
- `FrameFromLocal` / `LocalFromFrame` 或 `Transform<From,To>` 编码方向；
- 固定 handedness、vector side、angle unit、clip/depth convention 与 storage；
- separate construction（translate/rotate/scale/look-at）和 application（point/vector/normal/bounds）；
- inverse 返回 failure/optional，不能对 singular matrix 静默生成 Inf/NaN。

<Term def="对大量随机输入验证应始终成立的代数关系，而不是只核对少数手写样例的测试方法">性质测试</Term>适合变换库：

```cpp
property("inverse round trip", [](Affine2 m, Point2 p) {
    assume(abs(determinant(m.linear)) > 1e-5f);
    CHECK(near(inverse(m).applyPoint(m.applyPoint(p)), p));
});

property("composition", [](Affine2 a, Affine2 b, Point2 p) {
    CHECK(near((b * a).applyPoint(p), b.applyPoint(a.applyPoint(p))));
});
```

数值 tolerance 应按 magnitude、operation count 与 precision 设计，不能全库固定一个 epsilon。还要测试 NaN/Inf policy、negative scale/winding、huge translation、near singular、serialization 与 CPU/shader 一致性。

## 从逻辑单位到设备像素

二维 UI/绘图常跨 local、layout、window logical、framebuffer pixel 与 physical display。映射可近似：

$$
p_{pixel}=S_{DPI}\,M_{window\leftarrow local}p_{local}.
$$

pixel snapping 可让细线清晰，却会破坏连续动画；high-DPI 下 half-pixel 口诀依 API sampling convention，不能通用复制。reference 应覆盖 scale 100%/125%/200%、subpixel motion、clip edge 与文本/几何混排。

## 常见误区

<Callout type="trap">
**现象 →** 同时说 `M*v` 和“点左乘/右乘”，代码顺序靠猜。**原因 →** 混淆 vector convention 与 memory layout。**修法 →** API 命名 source/target，写 composition property test，并在 CPU/shader 两端用已知点验收。
</Callout>

<Callout type="trap">
**现象 →** 在 WPF/retained UI 中只改 render transform，却期待 layout 和 hit bounds 一起变化。**原因 →** 混淆 layout transform 与 visual transform。**修法 →** 显示 layout slot、render bounds 和 input inverse path，按任务选择层级。
</Callout>

<Callout type="trap">
**现象 →** test bed 只展示正常三角形和一次旋转。**原因 →** 把 demo 当验证。**修法 →** 加 open/closed、duplicate、empty、near-singular、negative scale、DPI 和随机性质测试。
</Callout>

## 练习

<Exercises>

**问题 1：retained mode 与 immediate mode 的核心差别是什么？**

<Answer>
retained mode 由框架保存 scene/state、跟踪 dirty 并调度 layout/render；immediate mode 由应用在绘制时提交命令，通常自己维护状态。差别影响更新粒度、hit testing、lifetime、可观测性和性能，不是单纯 API 语法。
</Answer>

**问题 2：如何构造绕任意点旋转并验证顺序？**

<Answer>
列向量下 `T(c) R T(-c)`：先把 pivot 移到原点，再旋转，再移回。验证 pivot 自身不动，距 pivot 长度保持，并以 property test 比较组合矩阵与逐步应用。
</Answer>

**问题 3：corner cutting 为什么适合验证 affine equivariance？**

<Answer>
新点由原点的 affine combination 生成，所以先做 affine transform 再切角，应等于先切角再变换。若不等，通常是坐标、权重、endpoint 或 composition 实现有错。
</Answer>

**问题 4：变换库为什么要区分 Point 和 Vector？**

<Answer>
point 表示位置并受 translation，vector 表示差/方向不受 translation；二者允许的代数操作也不同。类型区分能在编译/API 层阻止把方向当位置、把两个位置相加等语义错误。
</Answer>

</Exercises>
