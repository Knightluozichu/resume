## Ch3 An Ancient Renderer Made Modern

Dürer 装置把 eye $e$、画面平面与三维点 $p$ 连成一条 ray，交点是图像位置。若 eye 在原点、image plane 为 $z=-n$，相机空间点 $(x,y,z)$ 的平面坐标为：

$$
x_p=-n\frac{x}{z},\qquad y_p=-n\frac{y}{z}.
$$

这是相似三角形，不是“模拟人眼”这一句话。平行于 view direction 的线会趋向 vanishing point；平行于 image plane 的线仍可保持平行。

可直接解决 visibility；若只投影 mesh vertices 再连 wireframe，会遇到：视点后方点、跨 near plane 边、隐藏面、透视插值与遮挡顺序。

完整最小 renderer 需要 model/camera transform、clip、coverage/ray intersection、nearest visibility 和 shading。中间量应显示 camera-space geometry、clip decision、projected coordinates 与 selected hit。

## Ch7 Essential Mathematics and the Geometry of 2-Space and 3-Space

point 属于 affine space，vector 表示点之差。dot product 给长度/投影/夹角；cross product 给与两个向量垂直的有向面积向量：

$$
a\cdot b=\|a\|\|b\|\cos\theta,
\qquad \|a\times b\|=\|a\|\|b\|\sin\theta.
$$

把抽象 point/vector 变成数值。basis 非正交时不能用转置代替 inverse；handedness 决定 cross、winding 和 rotation 正方向。

平面可写为 $n\cdot x+d=0$。三角形中的 point 用 barycentric coordinates：

$$
p=\lambda_0p_0+\lambda_1p_1+\lambda_2p_2,
\quad \lambda_0+\lambda_1+\lambda_2=1.
$$

全部 $\lambda_i\ge0$ 表示在闭三角形内，但 edge inclusion 要统一，否则相邻 triangle 会产生 double hit 或 crack。退化 triangle 的面积接近零时必须有明确 policy。

在投影后插值 texture/depth 时还要区分 screen-linear 与 perspective-correct。

## Ch6 Fixed-Function 3D Graphics and Hierarchical Modeling


fixed-function pipeline 通过 transform、lighting、texture、blend 等预定义状态完成常见渲染。它的历史价值是暴露 stage/state；现代 programmable pipeline 把部分 stage 交给 shader，但 depth/raster/blend 等固定功能仍存在，不能把“fixed-function”误解成整个 GPU 不可编程。

中：

$$
M_{world(child)}=M_{world(parent)}M_{local(child)}.
$$

robot arm 的 shoulder、elbow、hand 各在局部 frame 建模。matrix stack 的 push/multiply/draw/pop 是 legacy API 的一种遍历实现；现代 ECS/scene graph 仍需同样的 parent-before-child update、dirty propagation、cycle prevention 与 bounds refresh。

```cpp
void updateWorld(Node& node, const Mat4& parentFromLocal) {
    node.worldFromLocal = parentFromLocal * node.parentFromLocal;
    node.worldBounds = transformBounds(node.worldFromLocal, node.localBounds);
    for (Node* child : node.children) updateWorld(*child, node.worldFromLocal);
}
```

非均匀 parent scale 会改变 child basis，旋转后可能产生 shear；如果设计要求 rigid joint，应分离 scale 或对 transform components 设约束。

## Ch11 Transformations in Three Dimensions

三维 affine transform 用 $4\times4$ 齐次矩阵。translation、scale、shear 与 reflection 直接推广；rotation 更复杂：可用 axis-angle、matrix 或 unit quaternion。

Rodrigues 公式围绕单位轴 $u$ 旋转 vector $v$：

$$
R_u(\theta)v=v\cos\theta+(u\times v)\sin\theta+u(u\cdot v)(1-\cos\theta).
$$

避免欧拉角参数化的 gimbal lock，不表示“任何插值都自动正确”。两个姿态需处理 antipodal equivalence、shortest path、normalization 和 coordinate convention。

normal 不是普通 direction。若 model 线性部分为 $A$，切平面向量变为 $At$，保持垂直要求：

$$
n'=(A^{-1})^Tn.
$$

纯 rotation 时等于 $An$；nonuniform scale/shear 时直接乘 $A$ 会错。singular transform 没有 normal inverse，资产和 runtime 必须拒绝或降级。

## Ch13 Camera Specifications and Transformations

先定义 camera world pose，再取 inverse 得到 view-from-world。`lookAt(eye,target,upHint)` 必须处理 eye≈target、up 与 forward 平行，以及 handedness。

**Perspective camera（透视相机）**以 eye/center of projection 和 frustum 表达近大远小；**orthographic camera（正交相机）**以平行投射方向和 box 表达与深度无关的图像尺度。二者都需要 view transform、clipping 和 depth，只是 projection 几何不同。

透视投影将 view frustum 映到 clip volume。projection 输出 homogeneous clip coordinates，先按 clip inequalities 裁剪，再除以 $w$ 得 NDC，最后 viewport 映射到 pixels/depth。正交投影通常 $w$ 保持常数，但仍执行通用 homogeneous divide；不是“完全不做除法”。

矩阵具体符号依 handedness、forward axis、NDC z range、reversed-Z 和 storage。不能把 `w=-z` 当所有 API 的定义。应以已知 near/far/corner points 做端到端测试。

perspective depth 对 view distance 非线性，传统映射近处精度高；near plane 过小会浪费精度。reversed-Z 配合 floating depth 和合适 projection 可改善远距离精度，但 compare/clear/linearization 全链要一致。

## Ch16 Survey of Real-Time 3D Graphics Platforms


可分层比较：

- thin graphics API：显式 resource/pipeline/command/sync，控制强，应用责任大；
- programmable rendering framework：封装 shader/material/pass/asset，保留较多渲染控制；
- scene graph/CAD/visualization toolkit：提供 hierarchy、camera、selection、data model；
- game engine：再加入 editor、animation、physics、streaming、platform build；
- browser/mobile/UI platform：受 sandbox、power、form factor 与 integration 约束。

平台不是按“越厚越高级”排序。选择要根据 performance predictability、content scale、tooling、portability、debuggability、team 与 product lifecycle，用代表性 vertical slice 测试。
