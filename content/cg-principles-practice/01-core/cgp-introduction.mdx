## 直觉：图像只有被观察和操纵时才完成任务

先预测：两个像素的物理 radiance 相同，观察者一定觉得一样亮吗？鼠标向右拖动，三维物体就一定绕世界 Y 轴旋转吗？都不一定。背景、适应、显示编码和交互映射会改变结果。

Ch1 定义问题与抽象，Ch5 定义观察者，Ch21 定义从用户动作到图形状态的闭环。三章共同要求：不能只证明“渲染器输出了像素”，还要证明这些像素可感知、可解释、可操纵。


## Ch1 Introduction：图形学的输入输出不止模型和图像

包括：

- modeling：选择 shape、material、light、camera、motion 的表示；
- rendering：求 visibility 与 radiance/image samples；
- animation/simulation：生成随时间变化的状态；
- interaction：把用户意图映射为 scene/view/action；
- display：把编码信号通过设备转成观察者看到的光。

其中 **Graphics Pipeline（图形管线）** 把 application、geometry/visibility、sampling/shading 与 display-oriented output 组织为可并行的阶段；它是一种重要抽象，不是图形学的全部定义。

图像处理、视觉与图形学会共享 sampling、optimization、learning 和 geometry，不能只用“模型→图像 / 图像→模型”完全切开。例如 inverse rendering 同时估计 geometry/material/light，neural rendering 也跨越表示与生成。

### 抽象是带损失的合同

可以是 immediate 2D canvas、retained scene graph、raster pipeline、ray query、material graph 或 game engine。抽象越厚，常见任务越快；但控制、可观测性与性能预测可能更弱。

选择抽象要列出：目标任务、数据规模、更新时间、质量/延迟预算、平台和 debug needs。不能因为某 API 流行就断言它代表图形学原理。

一个帧系统可写成 producer-consumer：

$$
S_{t+1}=Update(S_t, input_t),\qquad I_t=Render(S_{t+1}, camera_t),
$$

但 input sampling、simulation、render 和 display 可能跨帧重叠；交互延迟必须沿时间线测量，而非只看 renderer GPU time。

## Ch5 An Introduction to Human Visual Perception


眼睛把光学图像投到 retina；rods 对低照度与周边运动敏感，cones 支持明视觉与颜色。之后的神经处理强调对比、边缘、结构和变化。我们感知的不是逐像素 radiance 副本。

说明误差阈值依 spatial frequency、luminance、eccentricity、motion 与 adaptation。简化 Weber contrast：

$$
C_W=\frac{L_{target}-L_{background}}{L_{background}}.
$$

它只适合一定条件，不能代替 HDR、暗视觉或复杂图案的完整模型。

### 深度、颜色与运动线索

- depth：occlusion、relative size、perspective、texture gradient、shading、stereo disparity、motion parallax；
- color：由 spectrum、cone response、adaptation 与 context 共同形成，metamer 说明不同光谱可产生相同颜色感知；
- motion：temporal sampling、persistence、追踪与 optic flow 共同影响平滑和延迟；
- attention：显著性可引导观察，但任务与先验会改变注视位置。

视觉角决定屏幕特征在视网膜上的尺度：

$$
\theta=2\arctan\left(\frac{s}{2d}\right),
$$

其中 $s$ 是物理尺寸，$d$ 是观察距离。因此“1 像素误差”在手机、投影和头显上的可见程度不同。

提醒我们 RGB 是观察/设备相关表示，不是完整 spectrum。感知实验必须固定 display calibration、ambient light、view distance 与 adaptation time。

## Ch21 Interaction Techniques：把设备动作映射到任务自由度


至少说明 input space、controlled degrees of freedom、gain/constraint、selection、feedback 和 clutch/recovery。

### Multitouch 2D manipulation

两个触点从 $p_1,p_2$ 移到 $q_1,q_2$，可估计 translation、rotation 与 uniform scale：

$$
s=\frac{\|q_2-q_1\|}{\|p_2-p_1\|},\qquad
\phi=angle(q_2-q_1)-angle(p_2-p_1).
$$

变换围绕手势 centroid 组合；触点接近时方向不稳定，需要最小距离、filter 与 gesture-state transition。不能每帧重新选择触点而让对象跳变。

### Arcball、trackball 与 Unicam

arcball 将二维 cursor 投到虚拟球/双曲延拓，起止向量 $u,v$ 产生旋转轴 $u\times v$ 与角度 $\arccos(u\cdot v)$。它提供路径相关的三维旋转感；必须明确 object-space 还是 camera-space composition，并保证 quaternion normalization。

trackball 是一类“像滚动球”的映射，具体投影/增益实现不同，不能把名称当统一算法。Unicam 通过单鼠标在 rotate、pan、dolly 等 mode 间切换，降低同时控制 6-DOF 的困难，但 mode inference、focus point 与 transition feedback 决定可用性。

错误会表现为物体突然绕远处旋转、camera roll、drag 方向反直觉。debug view 应显示 pivot、basis、ray/pick point 与 active mode。

## 从感知目标到交互评价

交互技术不是只看“拖得动”。一个可复现实验要固定 task、target、device、display、latency 与 participant protocol，记录：

- completion time、success/error、path length、overshoot 与 mode error；
- end-to-end input-to-photon latency 与 dropped samples；
- subjective workload/comfort 和可学习性；
- 不同视距、尺寸、对比、色觉和运动能力下的 accessibility。

Fitts' law 可作为 pointing task 的描述模型：

$$
MT=a+b\log_2\left(1+\frac{D}{W}\right),
$$

但参数来自设备与用户实验，不是 UI 自动通过的公式。三维 selection、occlusion、depth 与 clutch 还会违反简单一维假设。
