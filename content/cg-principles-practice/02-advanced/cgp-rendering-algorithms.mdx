## Ch29 Light Transport

<Term def="描述场景中 emission 经 geometry visibility 和 material scattering 在位置与方向间传播的过程">光传输</Term>由 rendering equation 表达：

$$
L_o(x,\omega_o)=L_e(x,\omega_o)+
\int_{\Omega}f_s(x,\omega_i,\omega_o)L_i(x,\omega_i)
V(x,\omega_i)|n\cdot\omega_i|d\omega_i.
$$

$V$ 是 visibility，$L_i$ 又来自其他 surface 的 $L_o$，形成递归 integral equation。direct/indirect 是路径长度/光源连接的分类，diffuse/specular 是 scattering event 分类，不能混为同一个维度。

<Term def="按 camera、light 与 diffuse/specular/volume 等散射事件序列描述一条光路贡献的符号和结构">光路分类</Term>可用 eye/light endpoints 与 event sequence 分析算法覆盖：普通 path tracing 难采某些 specular-diffuse-specular path，photon/BDPT/MLT 各改善不同路径族。

## Ch30 Probability and Monte Carlo Integration

随机变量 $X\sim p$ 的期望可重写积分：

$$
I=\int_D f(x)dx=\mathbb E\left[\frac{f(X)}{p(X)}\right],
\qquad
\hat I_N=\frac1N\sum_{i=1}^{N}\frac{f(X_i)}{p(X_i)}.
$$

<Term def="用随机样本的加权平均估计积分，并以概率密度修正非均匀采样的数值方法">Monte Carlo 积分</Term>要求在 $f\ne0$ 处 $p>0$，PDF 的 measure/normalization 与 sample 一致。标准差约按 $1/\sqrt N$ 下降，所以只把 samples 加倍不会把噪声减半。

<Term def="让采样概率密度接近被积函数贡献分布，以降低 estimator 方差而保持正确权重的方法">重要性采样</Term>不是“多采亮处”口号，必须除以实际 PDF。stratification、low-discrepancy、multiple importance sampling 和 control variate 从不同角度减方差。

bias 是期望与真值差，variance 是随机波动；consistent 表示样本增加时收敛。biased denoiser/photon density estimator 仍可有用，但必须报告 bias 随参数是否消失，不能用“看起来平滑”替代。

## Ch31 Computing Solutions to the Rendering Equation: Theoretical Approaches

把 transport 写为 $L=L_e+KL$，Neumann series：

$$
L=\sum_{k=0}^{\infty}K^kL_e
$$

对应 0、1、2… 次 scattering contributions。不同算法对 function space、basis、paths 和 estimator 做不同近似。

<CgpTransportMethodsDiagram />

- radiosity：通常假设 diffuse，按 patches/basis 做 finite-element energy exchange；form factor visibility 与 matrix solve 是核心；
- path tracing：从 camera 随机 walk，估计方向积分，渐进无偏但高方差路径困难；
- bidirectional/Metropolis：连接 eye/light subpaths 或在 path space 变异，提高特定复杂路径效率；
- photon mapping：从 light 存 photon，再做 density estimation；有限 radius 有 bias，radius/sample schedule 决定 consistency；
- direct-light-plus-ambient/raster approximation：限制路径族换取实时成本，ambient 不等于真实 indirect。

算法没有“绝对最真实”排序。scene light/material/path distribution 决定 variance，representation 和 budget 决定 bias/memory。

## Ch32 Rendering in Practice

生产 renderer 要统一 camera、geometry/intersection、light sampling、BSDF evaluate/sample/pdf、spectrum/color、random sampler、film/filter 和 acceleration structure。

```cpp
Spectrum tracePath(Ray ray, Sampler& rng) {
    Spectrum L = 0, beta = 1;
    for (int bounce = 0; bounce < maxDepth; ++bounce) {
        Hit hit = scene.intersect(ray);
        if (!hit) { L += beta * environment(ray); break; }
        L += beta * emitted(hit, -ray.direction);
        L += beta * estimateDirectMIS(hit, rng);

        BsdfSample s = hit.bsdf.sample(-ray.direction, rng.next2D());
        if (!s.valid || s.pdf == 0) break;
        beta *= s.f * absDot(hit.normal, s.wi) / s.pdf;
        ray = spawnRobustRay(hit, s.wi);

        if (bounce > rrStart && russianRoulette(beta, rng)) break;
    }
    return L;
}
```

Russian roulette 的 survive probability 需除权，才能不因随机终止引入额外 bias。ray offset 要避免 self-hit 又不穿薄面；delta BSDF、environment PDF、light selection PDF 和 MIS measure 必须匹配。

<Term def="把来自光源的 photon hit 存入空间结构，再以局部邻域密度估计 radiance 的双阶段有偏渲染方法">光子映射</Term>实现需 separate photon tracing、storage/kd query、kernel/radius 和 final gather。caustic/global maps 可分离；debug 要显示 photons、power、search radius 与 neighbor count。

renderer debugging 不应只看 beauty：显示 normal/albedo/emission、path length、PDF、throughput、direct/indirect、hit IDs、BVH visits、variance 和 NaN/firefly source。

## Ch36 Visibility Determination

<Term def="保守或精确地判断哪些 surface samples、primitives 或 scene regions 能影响相机/光源/查询结果的过程">可见性判定</Term>包含：

- ray casting：对每 ray 取最近 valid intersection；
- depth buffer：对 rasterized fragments/samples 做 depth compare，成本按 generated fragments，不是笼统“每像素 O(1)”；
- list-priority/Painter：建立绘制先后，循环遮挡需 split 或其他方法；
- frustum clipping/culling、backface culling：便宜 conservative reduction；
- hierarchical occlusion/sector/portal：以 bounds/depth/region 降低不可见工作；
- partial coverage：处理 sample/filter footprint，不只二值 visible。

depth buffer 可参与透明渲染：opaque depth rejection、sorted blend、depth peeling、weighted/OIT、stochastic 等都有不同近似。“Z-buffer 不能处理透明”过于绝对；真正问题是多层 order-dependent composition，单 nearest depth 不足。

visibility culling 必须保守：false positive 增成本，false negative 丢图。上一帧 HZB/occlusion query 有 latency，camera jump 和 dynamic bounds 需 fallback。

## Ch37 Spatial Data Structures

<CgpVisibilityStructureDiagram />

<Term def="组织嵌入度量空间的对象和包围体，以加速 intersection、range、nearest 与 set query 的数据结构">空间数据结构</Term>应从 interface 开始：build/update、insert/remove、ray/overlap/nearest query、iterator、memory 和 concurrency。

- list：无 build、query 线性，适合极小或高度动态集合；
- BVH：对象分层，可重叠，适合 rays/collision；build quality/refit degradation 重要；
- kd/BSP tree：空间平面分割，traversal 有序，动态更新和 duplication 代价可能高；
- uniform/hierarchical grid：regular access 并行友好，密度/尺度差异大时效率下降；
- octree：层次空间 subdivision，适合多尺度 region query，但 pointer/layout 与 loose bounds 需设计。

结构评价要记录 build/refit/update、memory、node visits、primitive tests、cache/locality、query distribution 和 worst cases。ray tracing 不是对 N objects 必然 O(N)；好的 structure 平均减少候选，但也不能保证所有 scene/ray 都严格 O(log N)。

SAH 用 surface area 近似 traversal/intersection expected cost：

$$
C=C_T+\frac{A_L}{A_P}N_LC_I+\frac{A_R}{A_P}N_RC_I.
$$

它是针对 ray distribution 的 heuristic；动态、packet/coherent rays 或 collision query 可能需要不同 cost model。

## 常见误区

<Callout type="trap">
**现象 →** 采样 bright light 更多却没除 PDF，结果越采越亮。**原因 →** 把 importance sampling 当 heuristic weight。**修法 →** 统一 sample/evaluate/pdf measure，用 constant-function 与 normalization test 验证 estimator。
</Callout>

<Callout type="trap">
**现象 →** 用“Z-buffer 每像素 O(1)，ray O(N)”宣布算法优劣。**原因 →** 忽略 fragments/overdraw、acceleration build/traversal、scene/query distribution。**修法 →** 报告实际 generated fragments、node/primitive tests、memory 与时间。
</Callout>

<Callout type="trap">
**现象 →** denoise 后无噪就声称 path tracer 正确。**原因 →** filter 隐藏了 PDF、visibility、BSDF 或 energy bias。**修法 →** 保留 raw samples，运行 expectation/convergence、white furnace 与高样本 reference。
</Callout>

## 练习

<Exercises>

**问题 1：importance sampling 为什么不改变积分真值？**

<Answer>
从 p 采样后每项除以 p，期望为积分：E[f(X)/p(X)]=∫f(x)dx。p 只改变样本分布与 variance；若遗漏 PDF、support 不覆盖贡献或 measure 不一致就会 bias。
</Answer>

**问题 2：path tracing 与 photon mapping 的误差有何差异？**

<Answer>
标准 path tracing 样本均值通常无偏且方差随 N 降低；photon density estimate 用有限 radius/kernel 产生 smoothing bias，但若 photons 增加同时 radius 合理缩小可 consistent。具体实现的截断/denoise 会再引入 bias。
</Answer>

**问题 3：透明为什么不是简单关闭 depth write？**

<Answer>
多层透明需要按顺序或近似累积 transmittance/color；只关闭 write 仍需 opaque depth rejection、layer order、self-overlap 和 intersection handling。sorted blend、peeling、OIT 各有不同成本和误差。
</Answer>

**问题 4：何时 BVH refit 应改为 rebuild？**

<Answer>
大形变使固定 topology 的 sibling bounds 重叠，node visits/primitive tests 上升。跟踪 SAH proxy、query cost 与 update/build time，当累计 traversal 损失超过 rebuild 摊销成本时重建。
</Answer>

</Exercises>
