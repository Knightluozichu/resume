## 先区分“光到了”与“看见了”

想象两张内容完全相同的纸：一张放在暗色墙前，另一张放在亮色墙前。纸上的小方块没有换位置，但你对它的明暗判断可能不同。再想象小方块快速闪过：眼睛接收到了它，却不一定能把它报告成一个稳定事件。

本章解决的是“物理刺激如何成为知觉”的问题。没有这个区分，渲染器只追求显示器上的数值，却无法解释为什么边缘、背景、闪烁和运动会改变人对同一信号的判断。

先预测：保持中心亮度不变，只把周围背景调亮，中心的主观突出程度会保持不变吗？把变化速度调快又会怎样？

## Visual system：从光学输入到整合

<Callout type="trap" title="把视觉系统当成从像素到颜色的直通管">
  现象 → 只要提高输入亮度，就预期报告的亮度按同样比例提高。\ 原因 →
  处理链会编码局部关系、时间变化和上下文，知觉不是输入数组的逐点复制。\ 修法 →
  把输入、视网膜编码、神经通路和皮层整合分开记录，再比较最后报告。
</Callout>

<Term def="把光学刺激转换为可被神经系统处理、比较并报告的主观经验过程。">
  human visual perception
</Term>
不是一个单独的“视觉芯片”，而是多阶段处理的结果。输入先经过眼睛的光学结构，
<Term def="负责接收光、提取局部和时间变化，并把结果送入后续神经通路的处理系统。">
  visual system
</Term>
再把信号编码、汇聚和重组，最后才形成“这是一个边缘”“那里在运动”或“这个区域更亮”的报告。

<Cgp05VisualSystemDiagram />

把链路拆开有两个工程收益。第一，渲染或显示测试可以明确自己模拟的是光学输入、视网膜响应还是更高层的解释；第二，出现差异时可以问“哪一阶段改变了证据”，而不是把所有现象都归因于屏幕颜色。

## Retina：先编码变化，再传递细节

<Term def="眼球后部接收光并进行初步空间、亮度与时间编码的组织；它不是被动的像素存储器。">
  retina
</Term>
会把连续光强转换成神经信号。它关注的不只是某一点有多亮，还会比较附近区域和相邻时刻：变化明显的地方更值得后续通路保留，完全均匀的区域则可能被压缩。

这也是图形学测试中“边缘比平面更醒目”的生理直觉来源。一个小亮点放在暗背景上，和同样亮度的小亮点放在亮背景上，进入后续处理的局部差异不同。不要把这一事实误读成“系统不准确”；这是系统用有限资源优先编码变化的方式。

<Cgp05ReceptiveFieldDiagram />

<Term def="描述一个神经元会响应的空间区域与刺激组合；中心和周围的相对变化通常比绝对亮度更关键。">
  receptive field
</Term>
可以用中心—周围窗口来直觉化：中心信号推动响应，周围信号可能抑制或改变它。这个模型不是完整的生理仿真，却足以帮助我们设计可复现的显示和渲染测试。

```ts
type LocalSignal = { center: number; surround: number };

function localResponse(signal: LocalSignal) {
  return Math.max(0, signal.center - 0.55 * signal.surround);
}
```

代码中的系数只是教学用的可调参数，不是对真实神经元的精确测量。它的价值在于把“局部对比”变成可重复的输入输出：固定中心，改变周围，再记录响应如何变化。

## Contrast：知觉读取关系而非孤立数值

<Callout type="trap" title="用 RGB 数值直接预测主观明暗">
  现象 → 两个像素的 RGB 完全相同，就断言它们在画面中一定同样突出。\ 原因 →
  周围背景、边缘结构和显示上下文会改变局部比较，单个数值没有携带完整知觉条件。\
  修法 → 同时保存中心、周围、空间尺度和视口背景，比较整组刺激而不是单点颜色。
</Callout>

<Term def="描述刺激与周围或基线之间差异的关系；视觉系统常对差异比对绝对值更敏感。">
  contrast
</Term>
是设计视觉测试时必须写清的条件。增加中心亮度和降低周围亮度都可能提高局部差异，但它们对整体适应、边缘和后续颜色解释的影响并不相同。

因此测试台至少要保留一组对照：相同中心、不同周围；相同周围、不同中心；以及把刺激移到不同空间位置。只有这样，才能区分是局部关系变化，还是坐标、采样或颜色管理出了问题。

## Time：短暂信号也需要时间窗口

<Term def="在一段有限时间内汇总刺激变化，使短脉冲、闪烁和运动成为可比较事件的处理过程。">
  temporal integration
</Term>
解释了为什么“显示过一帧”不等于“人一定稳定地看见了它”。时间窗口过长，短暂变化可能被平均；窗口或刺激节奏改变，连续事件的可分辨程度也会改变。

<Cgp05TemporalIntegrationDiagram />

在交互实验中，调高变化速度并不只是让动画更快；它改变了刺激落在时间窗口中的重叠方式。评估一个视觉效果时，应同时记录帧率、刺激持续时间、重复频率和观察距离，而不是只保存一张静态截图。

## 本章回顾：四个知觉验收问题

1. 当前实验模拟的是光学输入，还是已经包含了更高层解释？
2. visual system 的哪一阶段引入了局部对比或时间上下文？
3. 中心与周围改变时，是否保存了完整刺激条件，而不是只看中心 RGB？
4. 变化速度、帧率和持续时间是否足以说明观察者实际经历的时间窗口？

<Exercises>

**问题 1：为什么同一中心亮度在两个背景上可能显得不同？**

<Answer>
  因为 human visual perception 会经过 visual system 的局部比较；receptive field
  中心和周围共同影响响应，单个中心 RGB 不能代表完整刺激条件。
</Answer>

**问题 2：修改 `localResponse`，让测试台同时输出中心增强和周围抑制两种记录，并说明如何避免把教学系数当成生理常数。**

<Answer>可以返回 `{ centerDrive: center, surroundInhibition: 0.55 * surround, response: Math.max(0, centerDrive - surroundInhibition) }`，并在测试报告中标注系数是教学模型参数；真实生理结论需要独立实验或权威资料，不能由这个简化函数单独证明。</Answer>

**问题 3：一个闪烁目标单帧可见、连续播放却不稳定，应该保存哪些证据？**

<Answer>
  保存帧率、刺激持续时间、重复频率、变化速度、观察距离和背景条件，再把事件放进
  temporal integration
  的时间窗口比较。这样才能区分显示链路丢帧、刺激节奏变化和知觉整合差异。
</Answer>

</Exercises>
