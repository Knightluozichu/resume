## 先把“可见性”拆成两种可检查的询问

屏幕上的一个颜色不是凭空出现的。渲染器必须先回答：这个像素对应哪一部分几何？一种做法是从像素发出射线，寻找最近交点；另一种做法是把三角形投影到屏幕，判断它覆盖了哪些样本，再为样本插值属性。

本章对照这两条路径，重点不是记住名词，而是保留中间证据。先猜一猜：提高屏幕采样规模后，ray casting 和 rasterization 的工作量会以同一种方式增长吗？如果一个像素颜色错误，应该先查交点、覆盖测试，还是深度顺序？

## ray casting：从像素追问最近交点

<Callout type="trap" title="只检查射线有没有命中，不检查最近交点">
  现象 → 物体轮廓看似正确，但前景被后景覆盖，反射或阴影出现穿透。 原因 →
  求交函数返回了任意 hit，没有在可接受的参数范围内选择最小正距离。 修法 →
  记录每个候选交点的 t，剔除相机背后的结果，再选择最近可见交点并保存法线与材质。
</Callout>

<Term def="从相机或像素位置沿一条方向发出射线，求它与场景几何的交点并选择可见结果的渲染方法。">
  ray casting
</Term>

**ray casting** 把可见性写成一次几何查询。给定射线原点 `o` 和方向 `d`，射线上的点可以写成：

$$
p(t) = o + t d
$$

人话翻译：`t` 从相机向前推进，任何满足几何约束的 `t` 都是候选交点；只保留视线前方且距离最小的候选，才得到当前像素看到的表面。

对于球、平面和三角形，可以分别实现交点测试；但调用方应该统一接收 `hit distance`、交点位置、法线和材质索引。若没有交点，就返回背景；若有交点，就把交点信息交给着色阶段。这样调试时可以明确问题来自射线生成、求交、最近点选择还是着色。

<Cgp15RayCastingDiagram />

ray casting 的优势是交点语义直接，反射、折射、软阴影或复杂可见性可以沿着命中的位置继续查询；代价是每条射线可能测试许多几何，并且递归或多次采样会快速增加工作量。空间加速结构可以减少候选几何，但不会改变“射线寻找交点”的核心证据。

## rasterization：从图元覆盖生成片段

<Term def="把投影后的点、线或三角形转换成覆盖屏幕样本的片段，并对深度与顶点属性进行插值的过程。">
  rasterization
</Term>

**rasterization** 采用相反的组织方式：先处理图元，再找它覆盖的屏幕样本。三角形顶点经过变换和裁剪后到达屏幕坐标，边函数或等价的覆盖规则判断一个样本中心在三角形内部还是外部；内部样本成为片段候选，随后插值深度、颜色、法线和纹理坐标。

<Cgp15RasterizationDiagram />

覆盖测试不是最终可见性。多个三角形可能覆盖同一个样本，还需要 **depth test** 比较深度并保留更靠近相机的片段。透视投影下，属性通常要进行透视正确插值，否则纹理或颜色会在深度变化明显的三角形上产生偏差。

<Term def="在同一个屏幕样本有多个片段候选时，根据深度缓冲判断哪个片段可以更新颜色的测试。">
  depth test
</Term>

光栅化的优势是图元和屏幕样本都容易批量并行，硬件可以高效完成覆盖、插值和深度测试；代价是它主要沿三角形图元推进，精确的多次反射或任意几何查询需要额外阶段。看到一个三角形没有颜色时，应区分它没有覆盖样本、被裁剪、被背面剔除，还是通过覆盖后又输给了 depth test。

## ray casting 与 rasterization 的证据链

<Cgp15PipelineComparisonDiagram />

两条路径都最终写入像素，但中间证据不同。ray casting 先有射线和最近交点，再进行法线、材质和光照计算；rasterization 先有图元覆盖，再进行属性插值、深度比较和片段着色。选择哪条路径，不是看哪一个名词更先进，而是看场景几何、可见性效果、并行方式和时间预算。

一个最小的光线查询接口可以把证据保留下来：

```ts
const ray = makePrimaryRay(pixel, camera);
const hit = scene.intersect(ray);
if (!hit || hit.t <= 0) return background;
return shade({ point: hit.point, normal: hit.normal, material: hit.material });
```

对应的光栅化路径可以把覆盖与深度分开检查：

```ts
const screenTriangle = projectAndClip(triangle, camera);
for (const sample of coveredSamples(screenTriangle)) {
  const fragment = interpolate(screenTriangle, sample);
  if (fragment.depth < depthBuffer[sample.id]) write(fragment);
}
```

代码中的 `hit.t`、`coveredSamples` 和 `fragment.depth` 都是比最终颜色更有价值的诊断输出。先确认中间证据，再判断着色是否正确，可以避免把几何错误误修成材质颜色。

## 常见误区

<Callout type="trap" title="把覆盖成功当成最终可见">
  现象 →
  三角形边界正确，但被遮挡的片段仍然写入颜色，或深度关系在不同角度下反转。 原因
  → 只实现了 rasterization 的覆盖测试，没有正确初始化、比较或更新 depth buffer。
  修法 → 分别记录覆盖结果和 depth test
  结果，确认深度空间、比较方向与清屏值一致。
</Callout>

<Callout type="trap" title="把 ray casting 的方向和距离混在一起">
  现象 → 物体位置稍微改变，命中点跳到相机背后，反射方向或阴影方向异常。 原因 →
  射线方向未归一化，或把交点的世界坐标当成参数 t 使用，导致最近点排序失真。 修法
  → 明确 `p(t) = o + t d` 的空间和单位，规定 d 的归一化约定，并对 t
  的正值范围写测试。
</Callout>

<Callout type="trap" title="只比较最终颜色，不保留中间证据">
  现象 →
  画面有黑块或闪烁，却无法判断是射线未命中、图元未覆盖、深度被拒绝还是着色错误。
  原因 → 管线把交点、覆盖样本、深度值和材质输入都隐藏在最终像素之后。 修法 →
  为调试模式输出 hit、coverage、depth 和 fragment
  状态，再按阶段定位，不要直接调颜色常数。
</Callout>

## 本章小结

- ray casting 从相机或像素发射射线，以最近几何交点作为可见性证据。
- rasterization 从投影图元出发，通过覆盖测试生成片段，再用插值和 depth test 决定写入。
- 覆盖成功不等于最终可见，交点、片段和深度都应保留为可检查的中间状态。
- 选择路径时要同时考虑效果、几何查询、并行方式和工作量，而不是只比较最终颜色。

<Exercises>

**问题 1：检查一个 ray casting 命中结果。** 给定射线 `p(t) = o + t d` 有三个候选交点，其中一个的 `t` 为负，另外两个都为正。你会保留哪些结果，最终选择哪一个？

<Answer>
  先剔除 `t` 为负的相机背后交点，再在剩余候选中选择最小正
  `t`，并返回交点位置、法线和材质。若没有正距离候选，就把当前样本标记为背景。
</Answer>

**问题 2：修改 RayCastViz。** 依次切换 ray casting 与 rasterization，提高屏幕采样规模，并把查询深度从 1 调到 8。记录 ray casting 的命中数、rasterization 的覆盖片段数，以及两条路径的估计工作量；说明为什么两者不会只由最终像素颜色区分。

<Answer>
  ray casting 的中间证据是每条射线的 origin、direction 和最近 hit；rasterization
  的中间证据是图元覆盖的样本、插值后的 fragment 和 depth test
  结果。提高采样规模会增加两者的样本工作，但查询深度主要增加 ray casting
  的后续求交或反射成本。
</Answer>

**问题 3：诊断一个黑色三角形。** 三角形顶点已经投影到屏幕，但最终颜色为空。请按阶段列出检查顺序。

<Answer>
  先检查裁剪和背面状态，再检查 rasterization 是否产生
  coverage；若有片段，检查插值后的深度、depth test
  比较和深度缓冲初始化；最后才检查材质、法线和光照。这样能区分“没有片段”和“片段被拒绝”两类问题。
</Answer>

</Exercises>
