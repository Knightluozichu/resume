## 先把一张图想成一张逐层盖章的通行证

想象一个点要通过几扇门：第一扇确认它相对观察者的位置，第二扇确认它还在可见范围，第三扇把它压到一块画布，最后才允许它留下颜色。每扇门都可能拒绝它，但拒绝的理由不同。

本章解决“点明明存在，为什么画面看不见”的问题：把每次盖章的输入、输出和边界写下来，让空白、变暗和变慢不再混成同一个故障。

没有这些阶段证据，调试只能反复改相机、颜色或线程数量。读完后，你应该能从第一处数量变为零、范围越界或等待增加的位置开始修复。

## 计算机图形学导论：观察管线是一份逐段契约

<Term def="以观察者为参照描述位置和方向的空间；世界中的点需要先转换到这里，才知道它位于视野前方还是后方。">
  观察空间
</Term>
让计算机图形学导论中的“看见”有了可检查的顺序：世界点先变成相对观察者的点，再进入裁剪和视口步骤。每个阶段都应留下一个小摘要，例如坐标范围、深度范围、保留数量和输出索引。

本章把 Graphics Pipeline（图形管线）看成一条逐段交接的契约：顶点进入观察空间后，经过投影与裁剪，再经过视口变换，最后才交给片段和像素阶段。Graphics Pipeline（图形管线）不会替前一站猜测单位或范围，也不会用最终颜色证明点曾经通过裁剪；要定位问题，必须找到第一个不满足契约的阶段。

### 观察空间：让深度有方向

在观察空间里，前方和后方不再依赖世界坐标的某个固定轴，而依赖观察者自己的前向。一个点的深度应该与投影约定一致；如果深度符号反了，后面的裁剪边界会把本来可见的点全部拒绝。

先固定相机，再记录三个字段：观察坐标中的位置、前向上的深度和进入下一阶段的点数。点数没有变化但深度符号异常，优先检查变换方向；点数突然变为零，才进入裁剪规则。

### 裁剪空间：边界决定是否继续

<Term def="投影矩阵输出的中间空间；点要满足各坐标与齐次分量的范围关系，才会被保留到后续阶段。">
  裁剪空间
</Term>
保留的是“可能出现在视口中的点”，不是已经完成屏幕定位的像素。它把可见性检查放在光栅化之前，因此一个点被裁掉后，继续修改颜色或光照都不会让它回来。

### 齐次除法：把 w 还原成可比较的坐标

<Term def="用齐次分量 w 同时除以 x、y、z，把投影后的点带回可比较范围的步骤；它体现了透视带来的深度缩放。">
  齐次除法
</Term>
是观察管线中的关键分界。投影结果通常写成 `(x, y, z,
w)`，除法后才适合与标准化设备坐标的边界比较；w 的符号和大小必须与投影约定一致。

$$
-1 \leq \frac{x}{w},\;\frac{y}{w},\;\frac{z}{w} \leq 1
$$

这个式子在说：除以 w 后的三个坐标要落在约定范围，点才有机会进入视口；边界判断发生在颜色写入之前。

在代码中，把每一步命名并返回，便于观察第一个偏离点：

```ts
const viewPoint = viewMatrix * worldPoint;
const clipPoint = projectionMatrix * viewPoint;
const ndc = clipPoint.xyz / clipPoint.w;
const visible = insideUnitCube(ndc);
return { viewPoint, clipPoint, ndc, visible };
```

若 `clipPoint.w` 为零或符号异常，先修投影；若 `ndc` 超出范围，先查裁剪约定；只有 `visible` 为真且片段数量正常时，才检查颜色。

### 视口变换：把标准范围铺到画布

视口变换把标准化设备坐标映射到实际画布像素范围，并把深度映射到深度缓冲的范围；它改变屏幕位置，不负责决定点是否可见。改变画布尺寸会改变像素坐标，但不应该改变世界空间中的物体，也不应该凭空创造片段。

## Light（光）：保留的片段才有能量

Light（光）在观察管线中位于可见性之后：只有通过观察和裁剪、产生片段的部分，才会接收方向、能量和材质输入。Light（光）可以解释为什么已有片段变暗，却不能解释为什么裁剪空间里根本没有片段。

### Radiometry（辐射度量）与 reflectance（反射率）

Radiometry（<Term def="描述光能量如何按功率、面积、方向或立体角分布的一组量；它是片段的能量输入描述。">辐射度量</Term>）描述到达表面的能量如何分布；reflectance（<Term def="表示表面保留或反射入射能量的比例；它是材质属性，不是可见性边界。">反射率</Term>）描述表面保留多少。两者只对已经存在的片段有意义，因此空白画面应先查观察和裁剪，而不是先把光源调亮。

固定可见几何后，分别记录入射能量、反射率和输出范围。若能量正常而输出暗，检查材质或颜色映射；若能量输入从未产生，检查片段是否在前一站被裁掉。

## Modern Graphics Hardware：观察阶段也有执行代价

Modern Graphics Hardware（现代图形硬件）把观察变换、裁剪测试、片段生成和采样任务分给许多执行单元。阶段之间虽然看起来是一条顺序链，阶段内部却可以同时处理大量相似数据；因此，任务数、分支差异和访问位置会共同影响吞吐。

### Parallelism（并行性）与 memory latency（内存延迟）

Parallelism（<Term def="让彼此独立的观察、裁剪或采样任务同时推进的能力；它提高吞吐，却不能绕过阶段依赖。">并行性</Term>）表示可以同时推进的独立任务数；memory latency（内存延迟）表示任务发出数据请求后等待结果的时间。并行性高并不等于没有等待：若所有任务都读取远处数据或等待同一阶段输出，更多执行单元只会一起停住。

观察管线的性能记录至少包含阶段计数、批次大小、缓存命中和等待比例。先确认任务是否独立，再判断是否扩大并行批次；不要用线程数量掩盖内存延迟或裁剪导致的空工作。

## 常见误区

<Callout type="trap" title="误区一：看到空白就先调光照">
  现象 → 画面完全没有像素，光源强度不断增加却没有任何变化。

原因 → 点可能在观察或裁剪阶段已经被拒绝，光照阶段根本没有片段输入。

修法 → 按观察点数、裁剪保留数、视口片段数的顺序记录证据，找到第一个变为零的阶段。

</Callout>

<Callout type="trap" title="误区二：把齐次除法当成普通缩放">
  现象 → 近处物体大小不对，或物体在深度边界附近突然跳动。

原因 → 忽略了 w 的符号和大小，或者在除法前后混用了裁剪空间与标准化坐标。

修法 → 同时保存 clipPoint 和 ndc，检查除法顺序、w 范围以及裁剪约定，再改投影参数。

</Callout>

<Callout type="trap" title="误区三：用更多执行单元解决空工作">
  现象 → 批次扩大了，等待任务变多，帧时间却没有下降。

原因 → 裁剪已经让许多任务没有有效片段，或所有任务都在等待远处内存，增加并行度不能创造工作。

修法 → 先核对可见片段计数和缓存局部性，再决定是否扩大批次；用吞吐与等待比例共同验收。

</Callout>

## 本章小结

- 观察空间让世界点获得相对观察者的深度与方向。
- 裁剪空间和齐次除法决定点是否有资格继续前进。
- 视口变换改变像素位置，但不负责创造可见片段。
- 辐射度量与反射率只对已经存在的片段提供光照解释。
- 并行性提高阶段内吞吐，但内存延迟和空工作仍要单独测量。

<Exercises>

**问题 1：追踪一个点。** 给出一个投影后的点 `(0.5, 0.25, 0.8, 2)`。先做齐次除法，再判断它是否落在标准范围内，并写出你会记录的三个阶段字段。

<Answer>
  除法后得到 `(0.25, 0.125,
  0.4)`，三个分量都在标准范围内，因此可以继续进入视口。可记录观察坐标、裁剪坐标与除法后的
  ndc，并额外保存 visible 标志。
</Answer>

**问题 2：修改裁剪实验。** 把 PipelineViz 的深度滑块拖到边界外，写出为什么调高光源强度没有效果，以及下一步该检查什么。

<Answer>
  点已在裁剪阶段被拒绝，没有片段可以接收
  Light（光）的能量；下一步应检查投影矩阵、w
  的符号和裁剪范围，而不是继续改辐射度量或颜色。
</Answer>

**问题 3：判断执行瓶颈。** 视口任务从 6 增加到 12 后，活跃任务增加但等待比例也增加。你会先扩大并行批次还是调整数据访问？

<Answer>
  先检查数据局部性、缓存命中和 memory
  latency，因为等待比例上升说明访存或依赖正在暴露；只有等待下降且仍有空闲执行单元时，扩大并行批次才有价值。
</Answer>

</Exercises>
