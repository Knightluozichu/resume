## 先把一个对象想成一棵带标签的树

想象一棵树：树干决定整体位置，枝条决定局部形状，叶片可以共享同一种颜色规则，但每片叶子仍有自己的位置。若把所有信息揉成一团，移动一片叶子就可能拖走整棵树。

本章解决“对象如何既能复用又能独立移动”的问题：把几何、材质和变换拆开，让每个更新动作只影响它真正拥有的部分。

没有清晰的对象层次，重复物体会复制太多数据，或者共享错误状态导致一批对象一起漂移、变暗。读完后，你应该能从一条拥有关系或一次批次等待开始定位问题。

## 计算机图形学导论：对象是图形管线的可追踪单位

对象层次让计算机图形学导论里的“物体”不再只是顶点数组，而是一组带有拥有关系的资源。一个对象可以引用共享的几何和材质，同时保存自己的模型变换；这样，更新位置不会复制整个网格，更新材质也不会意外改变邻居。

本章把 Graphics Pipeline（图形管线）看成对象状态逐段交付的路径：对象先提供局部顶点和模型变换，再进入世界、观察、裁剪和片段阶段。Graphics Pipeline（图形管线）只接收已经组织好的输入，不会替应用判断哪份状态应该共享；对象层次越明确，越容易在首个异常阶段找到责任。

### 对象层次：谁拥有哪份状态

<Term def="用父子关系组织对象、几何、材质和变换的结构；父节点提供范围或共同变换，子节点保留局部差异。">
  对象层次
</Term>
回答的是“改变一个字段会影响谁”。几何描述形状，材质描述表面输入，变换描述实例位置；三者可以由不同对象拥有，也可以在资源管理层共享。

先画出一条最小关系：Object 引用 Mesh 和 Material，同时持有 Transform。若两个实例引用同一 Mesh，修改顶点会影响两者；若它们只共享 Mesh 而各自持有 Transform，移动其中一个不应改变另一个。

### 局部坐标到世界坐标：实例只改变变换

<Term def="以对象自身原点和轴描述顶点的位置；同一份局部几何可以通过不同变换生成多个世界实例。">
  局部坐标
</Term>
适合保存可复用的网格数据，世界坐标适合表达对象在场景中的关系。对象变换通常先作用于局部点，再把结果交给后续观察与投影步骤。

$$
\mathbf{p}_{world} = M_{model}\,\mathbf{p}_{local}
$$

这个式子在说：每个实例只需要一份局部点和一份模型矩阵，就能把同一几何放到不同的世界位置。

### 资源图与生命周期

资源图不仅描述“谁引用谁”，还要描述“什么时候可以释放”。如果一个材质仍被多个对象引用，就不能在销毁其中一个对象时释放材质；如果网格已被批次使用，也不能提前回收网格缓冲。

把引用数量、最后使用的帧和释放条件作为可检查字段。对象层次解决的是语义拥有关系，资源图解决的是运行时生命周期；两者都比“所有资源一起销毁”更能解释间歇性崩溃。

### 实例化：复制变换，不复制几何

<Term def="让许多对象共享同一份几何和材质，只为每个实例保存独立变换或少量属性的绘制方式。">
  实例化
</Term>
把重复对象压缩成一份资源加一组实例数据。实例数量增加时，应该主要增长变换和绘制任务，而不是重复上传相同网格；这也是批量绘制和对象管线连接的地方。

```ts
const worldPoint = modelMatrix(instance.transform) * localPoint;
const draw = { mesh: sharedMesh, material: sharedMaterial, worldPoint };
return draw;
```

这段代码把共享引用和实例变换分开；若每个实例都重新创建 `sharedMesh`，复用的收益就会被资源复制抵消。

## Light（光）：对象材质只解释已有表面

Light（光）进入对象管线时，需要对象提供表面方向、材质和世界位置。Light（光）可以解释同一几何因材质或朝向不同而变暗，却不能修复模型矩阵错误造成的重叠，也不能让裁掉的对象重新产生片段。

### Radiometry（辐射度量）与 reflectance（反射率）

Radiometry（<Term def="描述光能量如何按功率、面积、方向或立体角分布的一组量；它是对象表面的能量输入。">辐射度量</Term>）描述到达对象表面的能量；reflectance（<Term def="表示材质表面保留或反射入射能量的比例；它属于材质，而不是实例变换。">反射率</Term>）描述材质保留多少。多个实例可以共享反射率，同时因为世界位置和朝向不同接收不同能量；调试时要分别记录实例变换与材质输入。

固定 Mesh 与相机后，只改变一个实例的材质或朝向。若所有实例一起变暗，查共享材质或光照坐标；若只有一个实例异常，查它自己的变换、法线和资源引用。

## Modern Graphics Hardware：对象批次要尊重执行边界

Modern Graphics Hardware（现代图形硬件）适合同时处理大量相似的对象实例，但共享几何、材质切换和不同分支会改变批次效率。对象管线的目标不是把所有对象强行合成一批，而是让可以共享状态的对象一起推进，让真正不同的状态在正确的位置分组。

### Parallelism（并行性）与 memory latency（内存延迟）

Parallelism（<Term def="让彼此独立的对象实例同时推进的能力；它提高吞吐，却不能绕过共享资源的依赖。">并行性</Term>）表示多个实例能否同时执行；memory latency（内存延迟）表示实例读取几何、材质或变换数据时等待返回的时间。实例越多不一定越快：若对象随机访问远处资源，更多执行单元会一起暴露等待。

在批次检查中同时记录实例数、材质切换数、共享几何命中率和等待比例。只有状态相似、资源局部性良好且执行单元仍有空闲时，扩大批次才会带来吞吐收益。

## 三步实验：从拥有关系走到批次吞吐

每一步先预测“哪些东西应该一起变化”，再只调整一个滑块。这样才能把对象层次、光照输入和硬件等待分开。

## 常见误区

<Callout type="trap" title="误区一：复制整个网格来移动实例">
  现象 → 实例数量增加后，内存和上传时间一起增长，移动每个对象却没有更简单。

原因 → 没有把共享几何与独立变换分开，把本来只需复制的矩阵变成了整份顶点数据。

修法 → 保留一份 Mesh，为每个实例保存 Transform；用实例数量、几何字节数和更新字节数验收复用是否生效。

</Callout>

<Callout type="trap" title="误区二：共享材质却期待实例独立变暗">
  现象 → 修改一个对象的反射率后，同一批其他对象也一起变暗或变亮。

原因 → 材质属于共享资源，实例没有覆盖属性，所有对象读取的是同一份反射率和纹理。

修法 → 明确材质的共享边界；需要独立变化时复制材质或提供实例属性，并分别记录辐射度量与反射率。

</Callout>

<Callout type="trap" title="误区三：只增加实例数来追求吞吐">
  现象 → 批次扩大后执行单元更多，但等待任务和帧时间也增加。

原因 → 材质切换、随机访存或共享资源依赖让 memory latency 暴露，并行性没有转化为有效工作。

修法 → 先按材质和资源局部性重排批次，再比较活跃任务、缓存命中和等待比例，最后才增加并行度。

</Callout>

## 本章小结

- 对象层次把几何、材质和变换的拥有关系拆清楚。
- 局部坐标经过模型矩阵生成世界实例，几何可以被复用。
- 资源图同时约束共享引用和释放生命周期。
- 辐射度量与反射率解释对象表面已有的光照输入。
- 并行性提高实例吞吐，但内存延迟和状态切换必须测量。

## 练习与答案

<Exercises>

**问题 1：设计对象层次。** 三个相同网格需要放在不同位置，其中一个使用不同反射率。请写出哪些资源共享，哪些字段独立，并说明理由。

<Answer>
  三个实例共享 Mesh；若两个对象材质一致，可共享
  Material，第三个需要独立反射率则使用材质覆盖或独立材质；三个对象都要有独立
  Transform。这样移动或改变单个实例不会复制或污染不相关资源。
</Answer>

**问题 2：修改实例实验。** 在 ObjectViz 中增加实例数量但保持共享几何，记录几何字节数、变换字节数和片段数。哪一个量应该保持不变？

<Answer>
  共享几何的字节数应该保持不变，变换数据和绘制任务数量会增加，片段数取决于实例是否可见。若几何字节数也线性增长，说明实现复制了
  Mesh 而不是只复制实例状态。
</Answer>

**问题 3：定位批次变慢。** 实例数增加后活跃任务增加，但等待比例也增加。你会先扩大并行批次还是重排资源？

<Answer>
  先按材质、纹理和共享几何重排资源访问，检查缓存命中与 memory
  latency；等待下降且仍有空闲执行单元后，再扩大并行批次。单看实例数不能证明吞吐提升。
</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="对象层次">
  用父子关系组织对象、几何、材质和变换的结构，帮助确定一次更新会影响谁。
</GlossaryItem>

<GlossaryItem term="局部坐标">
  以对象自身原点和轴描述顶点的位置，同一份局部几何可以生成多个世界实例。
</GlossaryItem>

<GlossaryItem term="实例化">
  共享几何和材质，只为每个对象保存独立变换或少量属性的绘制方式。
</GlossaryItem>

<GlossaryItem term="辐射度量">
  描述光能量如何按功率、面积和方向分布的一组量，不直接等于屏幕颜色。
</GlossaryItem>

<GlossaryItem term="反射率">
  表面保留或反射入射能量的比例，是材质属性而不是实例位置。
</GlossaryItem>

<GlossaryItem term="并行性">
  同时推进互不依赖实例工作的能力；它能提高吞吐，却不能绕过资源依赖和访存等待。
</GlossaryItem>

</Glossary>
