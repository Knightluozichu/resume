## 先把一帧画面想成一组等待交接的收件箱

屏幕上的一个像素并不只对应一份数据。渲染时，颜色、深度、模板和多重采样样本可能分别存放在不同的附件里；这些附件共同组成一个可以被管线写入、解析和呈现的目标。

本章解决“片段写到哪里、多个样本如何合成、结果怎样到达屏幕”三个相连的问题。帧缓冲负责组织存储，解析负责把样本汇聚成可显示的像素，交换链则负责把已完成的图像交给显示系统。

先预测再实验：如果只增加样本数，边缘证据应更细而不是凭空多出几何；如果只提高曝光，颜色信号应变化而不是深度附件改变；如果呈现等待变长，图像内容可以不变，但可用的交换图像会变少。把内容、存储和交接分开，调试才有方向。

## 计算机图形学导论：帧缓冲是 Graphics Pipeline 的落点

在计算机图形学导论中，Graphics Pipeline（图形管线）把顶点、图元和片段逐步转换成可写入的结果。片段经过覆盖、深度和混合等阶段后，不是直接“画到屏幕”，而是先写入颜色、深度或模板附件，再由后续步骤决定怎样解析与呈现。

Graphics Pipeline（图形管线）的每次写入都依赖一个明确的目标布局：附件的格式、尺寸、样本数和加载方式必须相容。若附件配置不完整，片段着色可能已经执行，最终画面却仍为空白；因此要从帧缓冲的写入证据开始，而不是只看着色器。

### 帧缓冲与附件

<Term def="为一次渲染组织颜色、深度、模板或采样图像等存储目标的组合；它是片段输出的落点而不是显示器本身。">
  帧缓冲
</Term>

帧缓冲可以理解成一个带有多格收件箱的目标：颜色附件接收可显示的颜色，深度附件记录可见性，模板附件记录遮罩或分类信息。附件必须拥有匹配的尺寸和样本配置，否则管线无法把同一个片段结果解释成一致的像素。

<Term def="帧缓冲中承载一种像素结果的具体图像存储，例如颜色、深度或模板；不同附件有不同格式和生命周期。">
  附件
</Term>

颜色附件不等于最终显示颜色。颜色可能仍处在线性空间，深度可能只服务于可见性，解析目标可能需要另一种格式；记录“写入哪个附件、何时转换、何时呈现”比只记住一个图像句柄更可靠。

### 多重采样与解析

<Term def="在一个像素覆盖范围内保留多个采样位置，以更细地表示边缘覆盖和颜色差异的技术。">
  多重采样
</Term>

多重采样让一个像素拥有多个样本。边缘处有的样本被三角形覆盖，有的样本未被覆盖，因此解析时可以得到比单点采样更平滑的覆盖证据；它增加存储和处理量，却不会创造新的几何片段。

<Term def="把一个像素的多个样本按规则汇聚成单个输出颜色或深度的过程；它是样本到显示像素的转换。">
  解析
</Term>

设宽度为 $W$、高度为 $H$ 的颜色附件使用 $S$ 个样本，线性存储中的样本索引可以写成：

$$
i = ((yW + x)S) + s
$$

这个索引先定位像素，再定位其中的样本；解析时要把同一组 $S$ 个样本聚合，而不是把相邻像素的样本混在一起。

对样本颜色 $C_s$ 使用平均解析时，输出可以写成：

$$
C_{\text{resolve}} = \frac{1}{S}\sum_{s=1}^{S} C_s
$$

这个平均只描述一种简单的解析规则，实际实现还可能结合覆盖率、格式和颜色空间；关键是解析输入应来自同一个像素的样本集合。

下面的伪代码把帧缓冲的责任顺序固定下来：先创建有匹配附件的目标，再绘制，最后解析并呈现。真实 API 名称可以不同，但数据交接关系不变。

```cpp
Framebuffer target = makeFramebuffer(color, depth, sampleCount);
beginRender(target);
drawScene();
resolveSamples(target.color, displayImage);
present(displayImage);
```

## Light（光）：帧缓冲保存能量经过转换后的证据

Light（光）在片段阶段贡献颜色和能量，帧缓冲则保存这些结果经过格式和颜色变换后的状态。若颜色附件被清空、格式不匹配或解析目标没有接收，光照计算即使正确，也不一定能在屏幕上出现。

### Radiometry（辐射度量）与 Reflectance（反射率）

Radiometry（<Term def="描述光能量如何按功率、面积、方向或立体角分布的一组量；它是颜色附件中能量变化的物理输入。">辐射度量</Term>）描述到达表面的能量，Reflectance（<Term def="表示表面保留或反射入射能量的比例；它影响写入颜色附件的材质响应。">反射率</Term>）描述材质保留多少能量。帧缓冲不会重新计算二者，只负责保存和传递它们经过着色、混合与格式化后的结果。

固定附件格式和解析规则后，只改变光源能量，再只改变反射率。若颜色附件中的线性值变化而深度附件不变，问题属于光照或材质；若颜色值正确但屏幕亮度不对，应继续检查曝光、颜色变换和呈现路径。

## Modern Graphics Hardware：附件访问是并行写入与带宽的折中

Modern Graphics Hardware（现代图形硬件）通常能并行处理很多片段和样本，但多重采样会扩大颜色与深度附件的写入量。更大的附件、更高的样本数和更复杂的解析都可能增加带宽压力；吞吐不能只看着色器算了多少次。

### Parallelism（并行性）与 memory latency（内存延迟）

Parallelism（并行性）让多个片段、样本或附件块同时推进，memory latency（内存延迟）则表示读取或写入数据后等待完成的时间。并行执行单元很多时，如果附件访问不连续、解析依赖前一批样本，更多任务也可能只是排队等待。

观察帧缓冲性能时至少记录样本数、颜色和深度写入量、解析耗时、交换图像可用数与等待比例。若内容正确但帧时间上升，先比较样本和附件带宽；若图像撕裂或重复，优先检查呈现同步，而不是继续增加并行度。

## 常见误区

<Callout type="trap" title="误区一：附件能创建就一定能写入">
  现象 → 片段着色没有报错，但颜色附件保持清空色，画面像是没有执行绘制。

原因 → 帧缓冲的尺寸、格式或样本数与渲染管线契约不匹配，写入目标没有形成完整组合。

修法 → 逐项核对颜色、深度和模板附件的尺寸、格式、样本数及加载方式，再检查绘制命令。

</Callout>

<Callout type="trap" title="误区二：样本数增加就等于重新绘制">
  现象 → 把多重采样从 1 调高后，边缘更平滑，但有人误以为场景几何被绘制了更多次。

原因 → 多重采样增加像素内的覆盖样本和附件存储，解析只是汇聚样本，不会生成新的三角形。

修法 → 分别记录片段数量、样本数量和解析输出，确认边缘变化来自覆盖证据而非额外几何。

</Callout>

<Callout type="trap" title="误区三：屏幕等待是光照错误">
  现象 → 颜色附件中的数值稳定，但屏幕偶尔显示上一帧、撕裂或停顿。

原因 → 呈现交换仍在等待显示设备使用图像，memory latency（内存延迟）和同步没有被正确处理。

修法 → 先检查交换图像的获取、提交和呈现顺序，再分别调试 Light（光）、曝光和反射率。

</Callout>

## 本章小结

- 帧缓冲把颜色、深度、模板和样本组织成一次渲染可写入的附件集合。
- 多重采样在像素内保存多个覆盖证据，解析再把同一像素的样本汇聚成输出。
- 辐射度量和反射率影响颜色附件中的能量结果，但不会替代附件配置与呈现同步。
- 现代图形硬件可以并行处理片段和样本，附件带宽与内存延迟仍会限制吞吐。
- 调试顺序应是“附件相容 → 样本解析 → 颜色转换 → 交换呈现 → 性能等待”。

## 练习与答案

<Exercises>

**问题 1：定位样本索引。** 颜色附件宽度为 `800`，像素坐标为 `(10, 4)`，样本数为 `4`。按本章索引式计算样本 `s=2` 的线性位置，并说明为什么不能直接把 `s` 加到像素索引上。

<Answer>
  线性位置为 `((4 × 800 + 10) × 4) + 2 =
  12842`。样本属于像素内部的第二层存储，必须先定位像素再定位样本；直接把 `2`
  加到像素索引会破坏像素与样本的分组。
</Answer>

**问题 2：修改采样解析实验。** 在 FramebufferViz 中比较样本数为 `1` 和 `4` 时的解析输出，写出边缘变平滑的原因，并指出它没有改变什么。

<Answer>
  四个样本可以分别记录像素边缘的覆盖和颜色，解析后得到更细的覆盖平均，所以边缘更平滑；它没有改变场景几何，也没有自动增加片段着色的语义数量。
</Answer>

**问题 3：判断呈现瓶颈。** 颜色附件数值稳定，但交换等待从 `0.35` 上升到 `0.80`。你会先调整曝光、反射率还是检查交换同步？

<Answer>
  先检查交换同步和可用图像获取，因为颜色内容没有变化，异常出现在渲染目标交给显示设备的交接阶段；曝光和反射率只应在颜色数值本身错误时调整。
</Answer>

</Exercises>
