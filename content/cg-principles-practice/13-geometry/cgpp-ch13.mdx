## 先把几何想成一批要通过检查站的顶点

一个模型中的顶点先描述对象自身的形状，随后要经过模型、观察和投影变换，才能与摄像机和视口建立关系。顶点越过检查站之后，仍可能被裁剪；只有可见部分才值得进入光栅化和片段处理。

本章解决“顶点怎样换坐标、哪些几何应被保留、为什么几何会变慢”三个相连的问题。坐标变换改变位置语义，裁剪减少无效工作，顶点批处理则决定硬件如何并行推进这些独立任务。

先预测再实验：只改变旋转，三角形的拓扑和顶点数量不应改变；收紧裁剪边界，可见区域应减少而不是改变光照强度；增加顶点批次但提高访问等待，完成数量可能不再同步增长。把几何语义、可见性和执行代价分开记录。

## 计算机图形学导论：几何是 Graphics Pipeline 的形状输入

在计算机图形学导论中，Graphics Pipeline（图形管线）从顶点和图元开始，把它们逐步变成屏幕上的片段。Geometry Pipeline（几何管线）负责把对象空间的顶点转换到裁剪空间、执行可见性裁剪并准备后续图元；它还没有决定最终像素颜色。

Graphics Pipeline（图形管线）的每个几何阶段都需要坐标约定一致。模型坐标、世界坐标、观察坐标和裁剪坐标若混用，顶点可能看似数值合理却落在错误的视锥中；调试时应保存每一阶段的顶点位置，而不是只观察最后一帧。

### 顶点与模型坐标

<Term def="几何图元的离散位置记录，通常还携带法线、颜色、纹理坐标等供后续阶段使用的属性。">
  顶点
</Term>

<Term def="以对象自身原点、轴向和尺度描述形状的坐标系；同一个模型可以通过模型变换放到不同世界位置。">
  模型坐标
</Term>

顶点在模型坐标中只回答“它相对这个对象在哪里”。模型矩阵把它放进世界，观察矩阵把世界转换到摄像机，投影矩阵则把可见范围编码进裁剪空间。法线不能简单当作位置乘同一个变换，非均匀缩放时尤其要注意它的方向语义。

对齐次位置 $p$，模型和观察变换可以合并写为：

$$
p_{\text{view}} = M_{\text{view}}M_{\text{model}}p
$$

这个乘法顺序表示先把对象放进世界，再从摄像机观察；矩阵顺序反过来会得到完全不同的位置，即使每个矩阵单独看都合法。

### 裁剪与透视除法

<Term def="把位于可见体积外的点或图元切掉，或在边界处生成新的交点，使后续光栅化只处理有效区域。">
  裁剪
</Term>

裁剪发生在投影之后、屏幕映射之前。三角形完全在视锥外时可以丢弃，跨过边界时则需要求交并生成新的边界顶点；裁剪不是把整个三角形粗暴地保留或删除。

<Term def="用齐次裁剪坐标的 w 分量除以 x、y、z，把顶点送入规范化设备坐标的步骤；它产生透视远近关系。">
  透视除法
</Term>

若顶点的裁剪坐标为 $(x_c,y_c,z_c,w_c)$，规范化设备坐标中的横坐标为：

$$
x_{\text{ndc}} = \frac{x_c}{w_c}
$$

这个除法让远处物体在屏幕上变小，也要求后续插值和深度测试正确处理 $w_c$；在除法前后混用坐标，会造成近大远小关系和裁剪边界同时错误。

下面的伪代码保留几何阶段的契约：先变换，检查裁剪，再做透视除法和视口映射。真实渲染 API 会把这些操作拆到固定或可编程阶段，但顺序不能随意交换。

```cpp
ClipVertex q = project(modelMatrix, viewMatrix, vertex);
if (outsideClipVolume(q)) return discard;
Vec3 ndc = q.xyz / q.w;
return viewportMap(ndc, viewport);
```

## Light（光）：几何属性为能量计算提供位置和方向

Light（光）需要知道表面位置、法线和观察方向，几何管线因此要保证顶点属性在变换后仍有一致的空间语义。几何裁剪决定哪些表面有机会被看到，但它不负责直接计算最终亮度。

### Radiometry（辐射度量）与 Reflectance（反射率）

Radiometry（辐射度量）描述光能量按功率、面积、方向或立体角的分布，Reflectance（反射率）描述材质保留多少入射能量。几何阶段提供位置、法线和可见性边界，光照阶段再利用这些信息计算颜色；把反射率误当成几何尺度会让材质和形状问题互相污染。

固定模型矩阵和裁剪边界后，只改变光源能量，再只改变反射率。若顶点位置、可见三角形和深度都不变而颜色变化，问题在光照或材质；若轮廓变化，先检查变换、裁剪和透视除法。

## Modern Graphics Hardware：顶点批次是并行工作但不是免费工作

Modern Graphics Hardware（现代图形硬件）通常可以同时变换许多相互独立的顶点。批次越大，执行单元越容易保持忙碌；但顶点属性越多、索引访问越分散、裁剪分支越不一致，带宽和调度成本也会变高。

### Parallelism（并行性）与 memory latency（内存延迟）

Parallelism（并行性）让独立顶点同时经过变换和属性准备，memory latency（内存延迟）表示读取顶点、索引或材质数据后等待可用的时间。增加并行任务只有在数据访问连续且依赖较少时才会提高吞吐；更多顶点可能只是让等待队列更长。

观察几何性能时至少记录输入顶点数、索引复用率、裁剪后顶点数、缓存命中和等待比例。顶点数量过多时先检查细节层次与重复数据，访问等待明显时先改善布局和局部性，再考虑扩大并行批次。

## 常见误区

<Callout type="trap" title="误区一：矩阵顺序不影响结果">
  现象 → 模型看似仍在画面中，但旋转、平移或摄像机方向与预期完全不同。

原因 → 模型、观察和投影矩阵作用在不同坐标空间，乘法顺序改变了顶点经过的变换路径。

修法 → 为每个中间空间记录一个顶点，明确列向量或行向量约定，再核对矩阵顺序。

</Callout>

<Callout type="trap" title="误区二：裁剪就是丢掉整个三角形">
  现象 → 三角形只越过视锥一条边，却整块消失或出现不自然的长边。

原因 → 跨边界图元需要求交生成新顶点，粗暴的全有或全无判断会破坏可见轮廓。

修法 → 先在裁剪空间判断每条边，再对跨界边插值位置和属性，最后进行透视除法。

</Callout>

<Callout type="trap" title="误区三：顶点批次越大就一定越快">
  现象 → 输入顶点数量增加，但完成率下降、等待任务变多，帧时间反而上升。

原因 → 顶点属性和索引访问不连续，memory latency（内存延迟）抵消了 Parallelism（并行性）的收益。

修法 → 先检查索引复用、缓存局部性和裁剪后数量，再决定是否扩大批次或降低细节层次。

</Callout>

## 本章小结

- 顶点从模型坐标经过模型、观察和投影变换，才获得可比较的裁剪空间位置。
- 裁剪保留视锥内的图元，透视除法把齐次坐标转换为规范化设备坐标。
- 几何阶段为光照提供位置、法线和可见性边界，辐射度量与反射率属于后续能量解释。
- 现代图形硬件能并行处理顶点，但属性访问、裁剪分支和内存延迟会限制吞吐。
- 调试顺序应是“空间正确 → 裁剪正确 → 属性一致 → 批次高效”。

<Exercises>

**问题 1：判断矩阵顺序。** 一个顶点先要被放到世界位置，再转换到摄像机空间。应如何排列模型矩阵和观察矩阵？如果顺序反过来会发生什么？

<Answer>
  按本章列向量约定，应先应用模型矩阵，再应用观察矩阵，写成 `p_view = M_view ×
  M_model × p`。顺序反过来会把平移或旋转解释在错误坐标系中，产生不同的世界位置。
</Answer>

**问题 2：修改裁剪实验。** 把 GeometryViz 的裁剪边界逐渐推入三角形，描述为什么轮廓会产生新交点，而不是只保留原始三个顶点。

<Answer>
  三角形跨过裁剪边界时，需要对边与边界求交并生成新的顶点，才能保留视锥内的多边形轮廓；这也是后续透视除法和属性插值的输入。
</Answer>

**问题 3：定位几何瓶颈。** 顶点批次从 8 增加到 12，但等待顶点也增加。你会先增加并行任务还是改善顶点访问？

<Answer>
  先改善顶点和索引访问的局部性，检查缓存命中和属性带宽；只有等待下降且执行单元仍有空闲时，扩大并行批次才可能提高有效吞吐。
</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="几何管线">
  把对象空间顶点变换、裁剪并准备为后续图元处理的一组阶段。
</GlossaryItem>

<GlossaryItem term="顶点">
  几何图元的离散位置记录，通常还携带法线、颜色和纹理坐标等属性。
</GlossaryItem>

<GlossaryItem term="模型坐标">
  以对象自身原点、轴向和尺度描述形状的坐标系。
</GlossaryItem>

<GlossaryItem term="裁剪">
  把可见体积外的几何切掉，并在边界处生成新的交点。
</GlossaryItem>

<GlossaryItem term="透视除法">
  用齐次裁剪坐标的 w 分量除以 x、y、z，得到规范化设备坐标的步骤。
</GlossaryItem>

<GlossaryItem term="法线">
  描述表面朝向的方向属性，为光照和可见性相关计算提供方向信息。
</GlossaryItem>
