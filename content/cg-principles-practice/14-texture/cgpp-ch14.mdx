## 先把纹理想成一张带坐标的材质地图

纹理不是贴纸被动地盖在模型上，而是一个由坐标、过滤规则和存储层级共同决定的采样系统。几何顶点携带纹理坐标，片段阶段对坐标插值，再从图像中取出与当前表面位置对应的颜色或材质参数。

本章解决“纹理坐标如何对应图像、远近变化时读哪一层、为什么高质量采样会变慢”三个相连的问题。UV 映射建立几何和图像的对应，MipMap 提供不同细节层级，各向异性过滤则在斜视表面上扩大采样覆盖。

先预测再实验：只移动 UV，纹理图案应沿表面移动而几何不变；只提高 LOD，读取的图像层级应变小而材质语义不变；只增加访问等待，颜色数值不应改变，只是完成时间变长。把坐标、层级和硬件代价分开观察。

## 计算机图形学导论：纹理是 Graphics Pipeline 的材质输入

在计算机图形学导论中，Graphics Pipeline（图形管线）把顶点属性插值到片段，再由纹理阶段用插值后的坐标读取材质图像。Texture Pipeline（纹理管线）因此连接几何属性、图像存储和片段颜色，而不是一个独立于图形管线的文件加载步骤。

Graphics Pipeline（图形管线）决定片段坐标在哪里产生，纹理采样决定该坐标访问哪些图像邻居。坐标范围、边界模式、过滤核和颜色空间若不一致，问题可能表现为接缝、闪烁、重复纹理或亮度异常；调试要保留 UV、LOD 和实际采样位置。

### 纹理与纹理坐标

<Term def="可被几何表面采样的一组二维或三维图像数据，通常保存颜色、法线、粗糙度等材质参数。">
  纹理
</Term>

<Term def="附着在顶点或片段上的图像坐标，通常用 u、v 表示并在图元内部插值。">
  纹理坐标
</Term>

纹理坐标通常在一个规范化区间内描述图像位置。顶点的坐标会随三角形插值到片段，如果三角形的三个顶点坐标顺序错误，纹理就会翻转、拉伸或出现跨边界接缝。地址模式还决定超出区间后是重复、夹紧还是镜像。

对一条边上坐标为 $u_0$ 和 $u_1$ 的两个顶点，位置参数为 $s$ 的片段坐标可写成：

$$
u(s) = (1-s)u_0 + su_1
$$

这个式子说明纹理坐标是几何属性的一部分；改变模型位置不会自动改变 UV 拓扑，改变 UV 才会改变纹理图案如何落在表面上。

### 纹理映射与细节层级

<Term def="把几何表面上的纹理坐标对应到图像位置，并根据采样规则取得材质值的过程。">
  纹理映射
</Term>

纹理映射的难点在于屏幕像素与纹理像素的覆盖比例会随距离、视角和投影变化。近处表面可能一个片段对应多个纹理像素，远处表面则可能许多纹理像素挤进一个片段；固定读取原始大图会产生闪烁、摩尔纹和不稳定的高频细节。

<Term def="为同一纹理预先生成的一组逐级缩小图像，采样时根据纹理在屏幕上的投影大小选择合适层级。">
  MipMap
</Term>

可用纹理坐标在相邻片段中的变化率估计层级。若局部投影尺度为 $\rho$，一个简化的层级选择式为：

$$
L = \log_2 \rho
$$

这个式子表达“投影越大，所需层级越粗”的趋势；实际系统会在相邻方向分别估计导数，并在层级之间做三线性或各向异性组合。

### 各向异性过滤与纹理缓存

<Term def="针对斜视或拉长的纹理投影，沿覆盖区域的多个方向采样并加权汇聚，以减少锯齿和闪烁的过滤策略。">
  各向异性过滤
</Term>

<Term def="保存近期纹理块或采样数据的高速存储区域，利用相邻片段的访问局部性降低重复读取的等待。">
  纹理缓存
</Term>

各向异性过滤可以改善斜视地面的清晰度，但通常要访问更多纹理样本。若这些样本沿连续方向排列，纹理缓存能复用数据；若 UV 跳跃很大或纹理布局不利于局部访问，过滤质量的提高会直接暴露带宽和延迟成本。

下面的伪代码把坐标、层级和过滤器分开。每一步都可以单独记录，避免把“UV 错位”和“缓存未命中”混成同一种问题。

```cpp
Vec2 uv = interpolate(vertexUv, fragmentBarycentrics);
float lod = estimateMipLevel(uvDerivatives);
TextureSample sample = textureSample(texture, uv, lod, filterMode);
return shadeWithMaterial(sample);
```

## Light（光）：纹理保存能量响应或材质参数

Light（光）在纹理阶段之后或片段着色阶段使用纹理中的颜色、法线和材质参数。纹理本身并不自动等于光照结果：同一张颜色纹理放在不同光源和反射率下，会得到不同的最终能量。

### Radiometry（辐射度量）与 Reflectance（反射率）

Radiometry（辐射度量）描述光能量按功率、面积、方向或立体角分布，Reflectance（反射率）描述表面保留或反射入射能量的比例。纹理可以存储反射率、法线或其他材质响应，纹理映射负责准确取值，光照阶段再解释这些值的物理意义。

固定 UV、LOD 和过滤规则后，只改变光源能量，再只改变纹理中的反射率。如果纹理图案位置变化，先查坐标和地址模式；如果图案位置正确但亮度变化，才检查辐射度量、反射率和颜色空间。

## Modern Graphics Hardware：纹理质量与访问吞吐互相牵制

Modern Graphics Hardware（现代图形硬件）通常能并行执行大量纹理请求，并依靠纹理缓存复用相邻片段的访问。更高的各向异性级别、更大的纹理和更复杂的过滤核会扩大每个片段的访问范围，缓存失配时尤其容易出现尾部等待。

### Parallelism（并行性）与 memory latency（内存延迟）

Parallelism（并行性）让许多片段同时发起纹理采样，memory latency（内存延迟）则表示采样请求等待纹理块返回的时间。并行任务很多并不意味着每个请求都更快：如果 UV 访问分散，执行单元会一起等待缓存或显存。

观察纹理性能时至少记录 UV 局部性、MipMap 命中层级、过滤样本数、缓存命中和等待比例。先确定画面质量是否需要提高过滤级别，再用访问证据判断是否应该调整纹理布局或采样批次。

## 常见误区

<Callout type="trap" title="误区一：纹理接缝一定是图像文件坏了">
  现象 → 模型边界出现突然跳变或纹理重复位置不对，但图像文件单独查看正常。

原因 → 顶点 UV 顺序、地址模式或跨接缝的坐标范围不一致，采样位置已经落到了错误邻域。

修法 → 先显示 UV、检查插值方向和 repeat 或 clamp 设置，再检查纹理文件内容。

</Callout>

<Callout type="trap" title="误区二：读取最高分辨率就最清晰">
  现象 → 远处地面闪烁、摩尔纹明显，继续固定读取原始大图却没有改善稳定性。

原因 → 屏幕一个像素覆盖了过多纹理细节，未预过滤的高频信息发生混叠。

修法 → 先根据导数选择 MipMap 层级，再比较三线性和各向异性过滤的质量与代价。

</Callout>

<Callout type="trap" title="误区三：提高各向异性不会影响性能">
  现象 → 斜视表面更清楚了，但纹理带宽、等待比例和帧时间一起上升。

原因 → 更多方向样本扩大了纹理请求，访问局部性不足时 memory latency（内存延迟）会抵消 Parallelism（并行性）。

修法 → 先测量缓存命中、样本数和 UV 局部性，再选择满足画质目标的最低过滤级别。

</Callout>

## 本章小结

- 纹理坐标把几何表面和材质图像对应起来，地址模式决定边界之外如何取值。
- MipMap 通过预过滤层级减少缩小时的高频混叠，各向异性过滤改善斜视表面但增加样本访问。
- 辐射度量和反射率解释纹理材质值的能量语义，纹理映射本身不等于最终光照。
- 现代图形硬件能并行处理纹理请求，纹理缓存和内存延迟决定实际吞吐。
- 调试顺序应是“UV 正确 → LOD 合适 → 过滤稳定 → 缓存可控”。

## 练习与答案

<Exercises>

**问题 1：判断 UV 插值。** 一条边的两个顶点纹理坐标为 `u₀=0.20` 和 `u₁=0.80`，片段位置参数为 `s=0.25`。求片段的 `u`，并说明改变 UV 不会改变什么。

<Answer>
  `u = (1 - 0.25) × 0.20 + 0.25 × 0.80 = 0.35`。改变 UV
  会改变纹理图案在表面上的对应位置，但不会改变模型的几何轮廓或顶点数量。
</Answer>

**问题 2：修改 MipMap 实验。** 把 TextureViz 的 LOD 从 `0` 调到 `3`，解释为什么远处纹理通常更稳定，并指出它牺牲了什么。

<Answer>
  更粗的预过滤层减少了屏幕像素覆盖的大量高频细节，因此闪烁和混叠更少；代价是远处图案的细节和锐度降低，且层级选择仍要匹配投影尺度。
</Answer>

**问题 3：定位采样瓶颈。** 各向异性级别提高后画面更清楚，但纹理缓存命中下降。你会先继续提高过滤还是改善访问局部性？

<Answer>
  先改善 UV
  访问局部性和纹理布局，并比较样本数、缓存命中和等待比例；只有质量仍不足且带宽预算允许时，才继续提高各向异性级别。
</Answer>

</Exercises>
