## 先把光照想成一笔需要方向和能量的账

表面变亮不是因为“有一个灯”这么简单。光源提供方向、颜色和能量，表面法线决定接收方向，材质反射率决定保留多少能量，观察方向还会影响高光等方向性响应。

本章解决“光从哪里来、表面能接收多少、为什么有时算得很慢”三个相连的问题。直接光照计算入射贡献，阴影判断光线是否可达，多光源执行则把同一片段的照明任务扩展成一批可并行工作。

先预测再实验：只旋转光源方向，几何轮廓和法线不应改变；只移动遮挡物，阴影区域应变化而材质参数不变；只提高访问等待，最终颜色数值不应改变，只是完成时间变长。把几何、能量和执行时间分开取证。

## 计算机图形学导论：光照是 Graphics Pipeline 的能量解释阶段

在计算机图形学导论中，Graphics Pipeline（图形管线）把顶点和片段属性送到可编程着色阶段。Lighting Pipeline（光照管线）接收片段位置、法线、纹理材质和光源数据，计算入射能量与反射响应，再把结果交给混合和帧缓冲输出。

Graphics Pipeline（图形管线）负责几何和可见性契约，光照阶段负责把“表面朝向”和“光从哪里来”解释成颜色。几何错误会让法线和位置错位，能量错误会让所有表面过亮或过暗；调试时应先确认坐标空间和光源单位。

### 光源、法线与直接光照

<Term def="描述发出或贡献照明能量的对象，至少包含方向、位置、强度和颜色等属性。">
  光源
</Term>

<Term def="描述表面朝向的单位方向，用于与入射光和观察方向比较；它不是顶点位置。">
  法线
</Term>

<Term def="根据光源方向、表面法线、距离和材质响应估计一个片段直接获得的照明贡献。">
  光照
</Term>

最简单的漫反射模型只保留光源方向与法线的夹角。设单位法线为 $n$、指向光源的单位方向为 $l$、入射能量为 $E$、反射率为 $\rho$，则可以写成：

$$
I_{\text{diffuse}} = \max(0,n\cdot l)E\rho
$$

这个式子把三个责任分开：点积决定方向匹配，$E$ 决定光源能量，$\rho$ 决定材质保留比例。法线背向光源时，点积为负，直接漫反射贡献应被截断。

点光源还会随着距离衰减。若光源功率为 $P$、距离为 $r$，理想化的球面扩散可表示为：

$$
E(r) = \frac{P}{4\pi r^2}
$$

这个平方反比提醒我们，移动光源会同时改变方向和能量；如果只想研究法线，应固定距离和光源强度。

### 阴影与间接光

<Term def="表示表面因光线被几何体阻挡而无法直接接收某个光源贡献的区域或状态。">
  阴影
</Term>

阴影判断的是从表面到光源的可达性。若路径被遮挡，直接光项被移除；表面仍可能从环境光、反射或间接光得到能量，因此阴影不等于材质反射率为零。

阴影贴图、光线查询和屏幕空间近似各有误差与成本。无论实现方式如何，调试都应把“光线是否可达”和“可达后反射多少”分开记录，否则会用反射率去掩盖遮挡错误。

## Radiometry（辐射度量）与 Reflectance（反射率）

<Term def="描述光能量如何按功率、面积、方向或立体角分布的一组物理量；它为光照计算提供可比较的能量语义。">
  辐射度量
</Term>

<Term def="表示表面保留或反射入射能量的比例；它是材质属性，不是光源强度或阴影可见性。">
  反射率
</Term>

Radiometry（辐射度量）负责描述光有多少，Reflectance（反射率）负责描述表面留下多少。两者都需要统一单位、方向和颜色空间；把显示编码值直接当作线性能量，会让光照叠加和距离衰减失去可解释性。

固定几何、法线和阴影状态后，只改变光源能量，再只改变反射率。若所有表面一起变化，优先查光源单位或颜色变换；若只有某种材质变化，检查反射率、法线方向和纹理采样。

## Modern Graphics Hardware：光照任务可以并行但会共享数据

Modern Graphics Hardware（现代图形硬件）能够同时计算大量片段的光照。每个片段可能读取相同的光源、阴影和材质数据，因此缓存复用能提高吞吐；当光源很多或阴影访问分散时，带宽和依赖会变成瓶颈。

### Parallelism（并行性）与 memory latency（内存延迟）

Parallelism（并行性）让彼此独立的光源或片段任务同时推进，memory latency（内存延迟）表示读取光源列表、阴影图或材质数据后等待结果的时间。提高光源数量不一定线性提高质量或速度：如果所有任务都等待同一份远端数据，执行单元会一起暴露尾部延迟。

观察光照性能时至少记录片段数、光源数、阴影查询数、缓存命中、活跃任务和等待比例。先判断某个光源是否真正贡献可见区域，再决定是否扩大批次或降低阴影采样。

下面的伪代码把光照的输入和遮挡判定分开。先计算可达性，再把通过的光源贡献累加，最后交给材质响应；这样每一项都能被单独测量。

```cpp
Color shade(Fragment fragment, Lights lights) {
  Color result = ambient(fragment.material);
  for (Light light : lights) {
    if (visibleToLight(fragment.position, light)) {
      result += directLight(fragment, light);
    }
  }
  return result;
}
```

## 常见误区

<Callout type="trap" title="误区一：表面变暗就是反射率太低">
  现象 → 整个区域突然变黑，直接调高材质反射率仍然无法恢复局部光照。

原因 → 法线可能背向光源，或阴影测试阻断了光线；反射率只改变已经到达的能量比例。

修法 → 先记录法线与光线点积、光线可达性和距离衰减，再检查反射率。

</Callout>

<Callout type="trap" title="误区二：阴影可以用环境光补回来">
  现象 → 阴影边界错误，增加环境光后画面不黑了，但遮挡轮廓仍然不对。

原因 → 环境光改变整体基线，不能修复光源可达性或阴影查询的几何错误。

修法 → 先验证光源到表面的遮挡路径，再分别调整环境项、直接光和材质反射率。

</Callout>

<Callout type="trap" title="误区三：光源越多就越逼真也越快">
  现象 → 增加光源后高光更丰富，但帧时间和等待任务一起上升。

原因 → 每个片段要处理更多光照和阴影任务，memory latency（内存延迟）会抵消 Parallelism（并行性）。

修法 → 先测量可见贡献、缓存命中和阴影采样，再选择重要光源或分层近似。

</Callout>

## 本章小结

- 光照由光源方向、法线、距离和材质反射率共同决定，单独调一个参数不能解释所有亮度变化。
- 漫反射点积和距离衰减把方向与能量分开，阴影则判断直接光是否可达。
- 辐射度量描述光有多少，反射率描述表面保留多少，二者需要统一物理和颜色语义。
- 现代图形硬件能并行处理多光源任务，但共享数据和内存延迟会限制吞吐。
- 调试顺序应是“法线方向 → 光线可达 → 能量单位 → 材质响应 → 执行代价”。

## 练习与答案

<Exercises>

**问题 1：计算漫反射项。** 当 `n·l=0.8`、入射能量 `E=2`、反射率 `ρ=0.5` 时，按本章简化模型计算漫反射强度；如果法线背向光源会怎样？

<Answer>
  漫反射强度为 `0.8 × 2 × 0.5 = 0.8`。如果法线背向光源，点积为负，经过 `max(0,
  n·l)` 截断后直接漫反射项为零。
</Answer>

**问题 2：修改阴影实验。** 把 LightingViz 的遮挡物移开，说明发生变化的是哪一项，并指出反射率是否应该自动改变。

<Answer>
  变化的是光源到表面的可达性，阴影测试通过后直接光项恢复；反射率是材质属性，不应因遮挡物移动而自动改变。
</Answer>

**问题 3：定位多光源瓶颈。** 光源数从 8 增到 12，同时等待任务从 2 增到 7。你会先减少光源、增加并行还是改善共享数据访问？

<Answer>
  先检查共享光源、阴影和材质数据的缓存局部性，并筛掉对当前片段没有贡献的光源；等待下降后再评估并行批次，而不是只增加执行任务。
</Answer>

</Exercises>
