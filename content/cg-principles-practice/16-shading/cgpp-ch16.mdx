## 先把着色想成一条把证据变成颜色的流水线

一个片段颜色不是某个函数凭空算出来的结果。它先从顶点携带的位置、法线、纹理坐标等属性开始，在图元内部经过插值，再进入片段着色器；着色器读取光源与材质数据，最后把响应写入帧缓冲。每一步都留下可以检查的输入和输出。

本章围绕三个问题展开：片段属性从哪里来、光照和材质怎样组合、为什么相同的着色逻辑在不同硬件负载下会出现等待。先做预测：只改变属性权重，几何轮廓不应移动；只改变访问等待，颜色语义不应改变；只增加分支分歧，结果可以相近，但通道完成时间会拉长。把数据正确性、光学含义和执行代价分开记录。

## 计算机图形学导论：着色器是 Graphics Pipeline 的解释阶段

在计算机图形学导论中，Graphics Pipeline（图形管线）把几何输入逐阶段变成可显示的片段。着色管线通常接收已经投影或插值后的属性，再用程序定义的规则计算颜色；它不是重新生成模型，也不负责替代可见性阶段。

### 从顶点属性到片段属性

<Term def="描述一组顶点属性按照片段在图元中的位置进行加权汇合的过程。">
  插值
</Term>

三角形三个顶点的属性可以用重心权重表示。设三个权重为 $\alpha$、$\beta$、$\gamma$，则它们的和为 1，片段属性可以写成：

$$
a_f = \alpha a_0 + \beta a_1 + \gamma a_2
$$

如果法线、颜色或纹理坐标在顶点阶段正确，但片段阶段出现渐变方向错误，先检查顶点顺序、坐标空间和权重，而不是立刻修改光照常数。插值给出的是局部输入；它不会自动把法线重新归一化，也不会替你修复错误的切线空间。

### 着色器的责任边界

<Term def="在图形管线的可编程阶段执行的函数，读取片段属性和资源，并输出颜色或其他阶段结果。">
  着色器
</Term>

着色器应当把输入契约、光照模型和输出编码分成三层。输入契约确认位置、法线和材质参数属于同一个坐标空间；光照模型说明光从哪里来、表面保留多少能量；输出层再处理混合、色调映射或帧缓冲格式。这样一旦画面异常，就能判断是数据未到达、公式不对，还是显示编码改变了观感。

下面的伪代码保持这种边界：先读取插值后的片段，再评估光照，最后应用材质响应。它没有把“没有光”与“反射率很低”混成同一个分支。

```cpp
Color shadeFragment(Fragment fragment, Material material, Light light) {
  Normal n = normalize(fragment.normal);
  Vec3 incoming = evaluateLight(light, fragment.position, n);
  return incoming * material.reflectance;
}
```

## Light（光）：着色器要解释能量和表面响应

<Term def="描述从光源到表面并参与可见颜色形成的照明贡献；它包含方向、位置、强度和颜色等信息。">
  光照
</Term>

Light（光）提供可被表面接收的方向与能量。着色器通常先计算法线与入射方向的关系，再把距离、遮挡和光源强度合并到一个入射项中。即使两个片段使用同一个材质，只要法线方向或光源距离不同，最终结果也可能不同。

### Radiometry（辐射度量）与 Reflectance（反射率）

Radiometry（辐射度量）描述能量如何按功率、面积、方向或立体角分布；Reflectance（反射率）描述表面保留或反射入射能量的比例。为了让调试有意义，二者要使用一致的单位和线性能量语义，不能把显示器的编码值直接当成光源功率。

用一个简化模型表达这种分工：

$$
C_{out} = L_{in} \rho + C_{ambient}
$$

其中 $L_{in}$ 是经过可达性与距离处理后的入射能量，$\rho$ 是反射率。若整个物体都变暗，先查光源单位、法线方向和坐标空间；若只有一种材质变暗，再查反射率或材质纹理。把环境项调大只能改变基线，不能修复错误的入射方向。

## Modern Graphics Hardware：同一着色器会同时处理许多片段

Modern Graphics Hardware（现代图形硬件）会把大量相似的片段组织成批次，交给执行单元并行处理。相邻片段共享着色器指令和只读资源时，吞吐通常较好；如果它们访问分散资源、走不同分支，批次就会暴露等待和闲置。

### Parallelism（并行性）与 memory latency（内存延迟）

<Term def="让多个独立的片段或光照任务同时推进的执行能力；它提高吞吐，但不能消除数据依赖。">
  并行性
</Term>

Parallelism（并行性）适合处理多个片段和多个光源任务，但分支分歧会让同一批通道依次走不同路径。memory latency（内存延迟）则是读取光源列表、纹理或材质数据后等待结果返回的时间。增加并行任务只有在数据能及时供给时才有收益；如果通道都在等同一份资源，执行宽度越大，暴露的尾部也可能越明显。

观察性能时记录光源任务数、活跃通道、分支分歧、缓存命中和等待比例。先确认着色结果是否值得这些资源访问，再决定是否减少光源、重排数据或改变批次大小。

## 常见误区

<Callout type="trap" title="误区一：渐变方向错了就改光照公式">
  现象 → 光照公式在单个片段上看起来合理，但三角形内部的颜色或法线沿错误方向渐变。

原因 → 顶点顺序、插值权重或坐标空间不一致，着色器收到的输入已经偏离预期；公式只是放大了错误。

修法 → 先显示三个顶点属性和片段重心权重，核对插值结果与法线归一化，再检查光照公式。

</Callout>

<Callout type="trap" title="误区二：画面变暗就是把反射率调高">
  现象 → 整个模型变暗，调高材质反射率后局部仍不对，甚至出现不自然的高亮。

原因 → Light（光）的方向、能量或遮挡可能错误；Reflectance（反射率）只描述到达表面的能量保留比例。

修法 → 分开记录入射能量、法线点积、遮挡状态和反射率，先修复 Radiometry（辐射度量）与光线可达性。

</Callout>

<Callout type="trap" title="误区三：并行通道越多，着色一定越快">
  现象 → 增加光源或执行批次后，吞吐没有提高，等待通道和帧时间反而上升。

原因 → 分支分歧让通道走不同路径，或共享资源读取暴露了 memory latency（内存延迟）；Parallelism（并行性）无法绕过依赖。

修法 → 先测量分支一致性、缓存命中和尾部等待，再重排数据、减少无贡献光源或调整批次大小。

</Callout>

## 本章小结

- 图形管线把顶点属性送到片段阶段，插值把图元内的局部位置转换成着色器输入。
- 着色器负责把输入契约、光照模型和输出编码连接起来，不能用一个常数掩盖坐标或数据错误。
- Light（光）提供入射能量，Radiometry（辐射度量）描述能量语义，Reflectance（反射率）描述表面保留比例。
- 现代图形硬件可以利用 Parallelism（并行性）处理许多片段，但 memory latency（内存延迟）与分支分歧会限制吞吐。
- 调试顺序应是“输入属性 → 插值权重 → 光照能量 → 材质响应 → 通道占用”。

<Exercises>

**问题 1：计算属性插值。** 三个顶点的标量属性分别为 `a₀=0.20`、`a₁=0.80`、`a₂=0.50`，片段重心权重为 `α=0.25`、`β=0.50`、`γ=0.25`。求片段属性，并说明权重和不为 1 时会发生什么。

<Answer>
  `a_f = 0.25 × 0.20 + 0.50 × 0.80 + 0.25 × 0.50 = 0.575`。权重和不为 1
  时，属性会产生整体缩放或偏移，通常说明重心坐标计算、透视校正或输入数据出了问题。
</Answer>

**问题 2：拆分光照与反射率。** 某片段的入射能量 `L_in=1.6`，反射率 `ρ=0.5`，环境项为 `0.1`。按本章简化模型计算输出，并说明只移动遮挡物时哪一项应该变化。

<Answer>
  `C_out = 1.6 × 0.5 + 0.1 =
  0.9`。只移动遮挡物时，光源到表面的可达性会改变，因而 `L_in` 可能变为 0
  或恢复；反射率和环境项不应自动改变。
</Answer>

**问题 3：定位硬件等待。** 光源任务从 6 增到 10 后，画面颜色基本稳定，但等待通道明显增加。你会先提高 Parallelism（并行性），还是先检查 memory latency（内存延迟）与分支分歧？

<Answer>
  先检查 memory
  latency（内存延迟）、缓存命中和分支分歧，确认等待来自共享资源还是路径不一致；只有数据供给稳定后，再评估提高
  Parallelism（并行性）是否能增加有效吞吐。
</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="图形管线">
  把几何输入逐阶段转换为可显示片段的处理流程，包含属性传递、可见性和着色等契约。
</GlossaryItem>

<GlossaryItem term="插值">
  按片段在图元中的位置，对顶点属性进行加权汇合的过程。
</GlossaryItem>

<GlossaryItem term="着色器">
  在图形管线可编程阶段执行的函数，读取片段属性和资源并输出阶段结果。
</GlossaryItem>

<GlossaryItem term="光照">
  根据光源、表面方向、距离和遮挡等因素估计片段照明贡献的过程。
</GlossaryItem>

<GlossaryItem term="反射率">
  表示表面保留或反射入射能量比例的材质属性。
</GlossaryItem>

<GlossaryItem term="并行性">
  让多个独立片段或光照任务同时推进的执行能力。
</GlossaryItem>
