## 先把动画想成一张由时间驱动的状态账本

一段动画不是把很多静态图片随意播放，而是用时间参数选择对象状态，再由插值规则生成中间姿态。关键帧说明“在哪个时刻必须是什么样”，姿态插值说明“两个已知姿态之间怎样走”，渲染管线则把当前姿态变成这一帧可见的几何、光照和颜色。

本章把动画拆成三个可检查的问题：时间如何选择状态，姿态如何连续变化，许多对象如何同时更新。先记下预测：只移动时间参数，关键帧本身不应改变；只改变插值曲线，运动路径或速度会改变但时间轴仍在；只提高访问等待，姿态数值应保持一致而完成时间变长。

## 计算机图形学导论：动画改变 Graphics Pipeline 的输入

Graphics Pipeline（图形管线）通常处理某一时刻的顶点、法线、纹理坐标和材质参数。Animation（动画）在管线之前更新对象变换或骨骼姿态，再把新的几何状态交给变换、可见性、着色和合成阶段。动画系统不应把时间逻辑藏在光照函数里，否则很难判断是姿态错了还是颜色错了。

### 关键帧与时间参数

<Term def="明确记录对象在某个时间点的姿态、位置或其他动画属性的样本。">
  关键帧
</Term>

<Term def="把动画时钟归一化到相邻关键帧之间，用来选择当前样本位置的数值。">
  时间参数
</Term>

若关键帧 A 位于时刻 $t_0$，关键帧 B 位于时刻 $t_1$，当前时刻为 $t$，可以先计算归一化时间参数：

$$
u = \frac{t-t_0}{t_1-t_0}
$$

通常会把 $u$ 限制在 0 到 1 的区间内。关键帧存储的是约束，不是每一帧的最终答案；播放速度、循环方式和时间重映射都会改变采样到的 $u$，但不会修改关键帧数据。

## Motion（运动）：姿态插值产生连续状态

<Term def="根据时间参数在已知姿态之间生成中间状态的过程，使位置、方向或骨骼属性随时间连续变化。">
  姿态插值
</Term>

Pose Interpolation（姿态插值）可以直接插值位置，也可以使用专门的旋转表示处理方向。对标量或位置向量，一个线性模型是：

$$
x(u) = (1-u)x_A + ux_B
$$

线性插值容易解释，但不一定带来平滑速度。为避免开始和结束处突然改变速度，可以先用缓入缓出曲线重映射 $u$，再把结果代入位置或旋转插值。无论选哪种曲线，都应保留原始时间参数和重映射后的参数，便于定位“时间错”还是“路径错”。

<Term def="在关键帧之间按指定曲线生成中间采样的过程，强调速度或数值随时间的变化方式。">
  补间
</Term>

补间负责填充关键帧之间的状态，不负责让对象自动符合碰撞、遮挡或光照规律。姿态更新后，法线和位置也随之变化；Graphics Pipeline（图形管线）需要重新执行受影响的阶段，不能只把上一帧颜色平移到新位置。

## Light（光）与 Radiometry（辐射度量）：每个新姿态都要重新解释能量

<Term def="描述光源方向、能量与当前动画姿态共同形成的片段照明贡献。">光照</Term>

Light（光）不会因为对象在动就自动跟随正确的坐标空间。若光源固定在世界空间，物体移动后入射方向会改变；若光源附着在对象上，则光源变换也要随对象姿态更新。Radiometry（辐射度量）描述功率、面积、方向和立体角，Reflectance（反射率）描述材质保留能量的比例。

动画调试时应把姿态、光源空间和材质数据分层记录：先确认当前位置和法线，再确认入射能量，最后确认反射率和颜色编码。否则运动造成的明暗变化很容易被误判成曝光或材质错误。

下面的伪代码明确了每帧更新顺序：时间先产生姿态，姿态再进入几何和光照计算。

```cpp
float u = normalizeTime(clock, keyframeA.time, keyframeB.time);
Pose pose = interpolatePose(keyframeA.pose, keyframeB.pose, easeInOut(u));
Geometry geometry = applyPose(characterMesh, pose);
Color color = shade(geometry, light, material);
present(color);
```

## Modern Graphics Hardware：动画采样会共享状态和资源

Modern Graphics Hardware（现代图形硬件）可以并行更新许多对象、骨骼或顶点，但动画数据通常共享关键帧缓冲、骨骼矩阵和纹理资源。对象数量增加时，计算本身未必是唯一瓶颈；随机读取关键帧、频繁上传矩阵或在不同路径上采样，都会暴露带宽和等待。

### Parallelism（并行性）与 memory latency（内存延迟）

<Term def="让多个对象、骨骼或采样任务同时推进的执行能力；它提高吞吐，但仍受共享状态和数据依赖限制。">
  并行性
</Term>

Parallelism（并行性）适合同时更新互不依赖的角色或骨骼分支，memory latency（内存延迟）则表示读取关键帧、矩阵或纹理后等待数据返回的时间。采样越密并不一定越流畅：如果所有任务都等待同一份关键帧数据，增加执行宽度只会让共享访问更拥堵。

性能排查至少记录对象数、骨骼数、每帧采样数、缓存命中、上传字节和等待比例。先判断动画误差来自时间和插值，还是来自资源未及时到达，再选择降低采样、压缩关键帧或重排数据布局。

## 常见误区

<Callout type="trap" title="误区一：关键帧越多，运动就越平滑">
  现象 → 关键帧数量增加后，动作仍然卡顿，某些区间甚至出现速度突变。

原因 → 平滑性取决于时间间隔、姿态插值和速度连续性，不只是样本数量；相邻关键帧的切线或旋转路径可能不连续。

修法 → 先画出时间参数和速度曲线，再检查关键帧间隔、插值曲线和旋转表示。

</Callout>

<Callout type="trap" title="误区二：动画变暗就是光源强度变了">
  现象 → 对象移动后亮度变化，调高 Light（光）强度仍然无法修复局部明暗跳变。

原因 → 对象姿态改变了法线、位置或光源坐标空间，Radiometry（辐射度量）输入随姿态变化；光照和运动的责任被混在一起。

修法 → 先记录每帧姿态、法线、入射方向和能量，再检查 Reflectance（反射率）与材质响应。

</Callout>

<Callout type="trap" title="误区三：提高采样密度一定能解决卡顿">
  现象 → 每帧采样数增加后动作更细，但等待任务和帧时间同时上升。

原因 → 共享关键帧、骨骼矩阵或纹理访问暴露了 memory latency（内存延迟），Parallelism（并行性）无法消除数据依赖。

修法 → 先测量采样误差、缓存命中和上传等待，再选择压缩关键帧、重排数据或降低无贡献采样。

</Callout>

## 本章小结

- Motion（运动）由时间参数选择状态，关键帧提供约束，Pose Interpolation（姿态插值）和补间生成中间姿态。
- 动画更新姿态后，Graphics Pipeline（图形管线）需要用新位置和法线重新执行受影响阶段。
- Light（光）、Radiometry（辐射度量）和 Reflectance（反射率）要在当前姿态和正确坐标空间中重新解释。
- 现代图形硬件能利用 Parallelism（并行性）处理多个动画任务，但 memory latency（内存延迟）会限制采样吞吐。
- 调试顺序应是“时间参数 → 姿态路径 → 光照空间 → 采样误差 → 资源等待”。

## 练习与答案

<Exercises>

**问题 1：计算姿态插值。** 姿态位置 `x_A=2`、`x_B=10`，归一化时间参数 `u=0.25`。按线性模型求当前位置，并说明改变关键帧间隔会不会直接改变这两个姿态值。

<Answer>
  `x(u) = (1 - 0.25) × 2 + 0.25 × 10 =
  4`。改变关键帧间隔会改变同一时钟时刻对应的时间参数和运动速度，但不会直接修改关键帧保存的姿态值。
</Answer>

**问题 2：区分运动与光照。** 对象旋转后局部变暗，但 Light（光）位置和 Reflectance（反射率）没有改变。你会先查什么，并如何用 Radiometry（辐射度量）证据验证？

<Answer>
  先检查旋转后的法线、对象到光源的方向和坐标空间，再记录
  Radiometry（辐射度量）对应的入射能量。姿态改变法线和入射角是合理原因，不应先把反射率或光源强度改掉。
</Answer>

**问题 3：定位动画采样瓶颈。** 角色数量不变但每帧采样从 4 增到 10，等待比例上升。你会先增加 Parallelism（并行性）还是检查 memory latency（内存延迟）？

<Answer>
  先检查 memory
  latency（内存延迟）、关键帧和骨骼矩阵的缓存命中，以及上传带宽；数据供给稳定后，再评估
  Parallelism（并行性）是否能隐藏部分采样等待。
</Answer>

</Exercises>
