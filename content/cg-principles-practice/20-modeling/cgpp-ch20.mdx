## 先把建模想成一份可执行的空间契约

模型不是屏幕上的轮廓，而是对形状、连接关系和属性的结构化描述。顶点提供位置与附加属性，边记录连接，面定义可被光栅化的区域；之后的变换把局部描述放入世界和相机空间，图形管线才有机会把它变成片段。

本章把建模问题拆成三个可检查部分：网格如何描述形状，空间变换如何改变位置和方向，顶点数据如何被硬件批量处理。先做预测：只提高细分级别，拓扑和细节会变化但光源不应移动；只缩放模型，位置和法线的空间表达会更新而材质属性不应凭空改变；只增加访问等待，模型几何不应变化，完成时间才会变长。

## 计算机图形学导论：模型是 Graphics Pipeline 的几何输入

Graphics Pipeline（图形管线）需要一个明确的几何输入契约。建模阶段提供顶点位置、法线、纹理坐标、索引和拓扑；变换阶段把局部坐标送到世界、视图和裁剪空间；后续阶段再进行可见性、插值、着色与输出。若输入拓扑或坐标空间含义不清，后面每一步都可能看起来像“渲染错误”。

### 模型、顶点与网格拓扑

<Term def="用顶点属性、连接关系和面来描述一个可被图形管线处理的形状数据集合。">
  模型
</Term>

<Term def="由顶点、边和面组成的离散表面表示，拓扑关系决定哪些顶点彼此相连。">
  网格
</Term>

网格的几何位置和拓扑连接是两种不同证据。移动一个顶点会改变形状，但不会自动改变连接；交换索引顺序可能改变面朝向、法线方向和可见性。提高细分级别通常同时增加顶点、边和面，因此画面细节与存储、变换和光栅化成本会一起变化。

对一个三角形，三个顶点位置可以写成 $p_0$、$p_1$、$p_2$，片段内部的位置由重心权重组合：

$$
p = \alpha p_0 + \beta p_1 + \gamma p_2
$$

权重的和应保持为 1。这个关系说明网格拓扑、顶点顺序和后续插值是相连的；如果面出现翻转，先检查索引和绕序，不要用光照强度掩盖法线问题。

## 局部空间与空间变换

<Term def="模型自身定义顶点时使用的坐标系，便于复用同一模型并独立表达其形状。">
  局部空间
</Term>

<Term def="把点、向量或法线从一个坐标系映射到另一个坐标系的矩阵或运算。">
  变换
</Term>

局部空间只描述模型自身，世界空间描述模型在场景中的位置，视图空间再把场景放到相机的观察关系中。点通常使用模型矩阵变换：

$$
p_{world} = M_{model}p_{local}
$$

平移、旋转和缩放可以组合在同一矩阵，但法线不是普通位置。非均匀缩放会改变法线与表面的垂直关系，因此应使用适合的逆转置变换并重新归一化。空间变换的问题通常表现为模型位置、朝向或光照一起异常，调试时要同时显示局部向量和世界向量。

### 法线、Light（光）与材质属性

<Term def="描述表面朝向的方向属性，用于与入射光和观察方向计算夹角；它不是一个位置点。">
  法线
</Term>

Light（光）在世界空间或对象空间中都有明确含义。模型移动或旋转后，光源方向、法线方向和材质纹理坐标必须转换到可比较的同一空间。Radiometry（辐射度量）描述光能量如何按功率、面积和方向分布，Reflectance（反射率）描述材质保留入射能量的比例；建模阶段应保存这些属性的来源和坐标契约，而不是把它们烘焙成不可解释的颜色。

如果模型缩放后明暗反转，先检查法线变换和归一化，再检查 Light（光）的坐标空间。若几何正确但材质亮度不对，再检查 Reflectance（反射率）和 Radiometry（辐射度量）的单位语义。

下面的伪代码保持几何和着色责任分开：

```cpp
ModelSpace local = loadMesh(vertices, indices);
WorldSpace world = transformModel(local, modelMatrix);
Normal worldNormal = transformNormal(local.normal, modelMatrix);
Color shaded = evaluateLight(world, worldNormal, light, material);
draw(world, shaded);
```

## Modern Graphics Hardware：模型细节会转化为顶点工作

Modern Graphics Hardware（现代图形硬件）会批量执行顶点变换、索引读取和属性访问。共享顶点、顺序索引和紧凑布局可以提高缓存复用；拓扑跳跃、重复顶点或材质访问分散时，带宽与等待会限制有效吞吐。

### Parallelism（并行性）与 memory latency（内存延迟）

<Term def="让多个顶点、面或模型实例同时推进的执行能力；它提高吞吐，但仍受共享数据依赖限制。">
  并行性
</Term>

Parallelism（并行性）适合处理互不依赖的顶点和实例，memory latency（内存延迟）表示读取索引、顶点属性或材质数据后等待结果返回的时间。细分越高并不一定让模型更好：如果新增细节不可见，却增加了随机读取和变换任务，画面收益会被带宽成本抵消。

性能排查应记录顶点数、索引复用、面剔除比例、缓存命中和等待比例。先确认新增顶点真的贡献了可见细节，再决定是否调整拓扑、实例化或数据布局。

## 常见误区

<Callout type="trap" title="误区一：增加顶点就能修复轮廓错误">
  现象 → 细分级别提高后，模型仍然出现裂缝、翻面或不连续的阴影。

原因 → 问题可能来自索引连接、绕序或法线，而不是几何采样不足；新增顶点只增加了错误数据的数量。

修法 → 先显示拓扑、面朝向和法线，验证连接关系正确后，再决定是否需要更多细节。

</Callout>

<Callout type="trap" title="误区二：法线可以像位置一样变换">
  现象 → 模型位置和轮廓正确，但非均匀缩放后光照出现断裂或明暗翻转。

原因 → 法线需要保持垂直关系，不能直接使用点的模型矩阵；缩放会改变法线方向和长度。

修法 → 使用适合的逆转置变换并重新归一化，再检查 Light（光）所在坐标空间。

</Callout>

<Callout type="trap" title="误区三：模型越密，画面一定越好">
  现象 → 顶点数和内存带宽上升，但目标尺寸下几乎看不出细节提升，帧时间却变长。

原因 → 新增顶点可能不可见，或索引和材质访问破坏缓存局部性，memory latency（内存延迟）抵消了 Parallelism（并行性）。

修法 → 先测量屏幕覆盖、缓存命中和顶点贡献，再选择细节层级、实例化或更紧凑的布局。

</Callout>

## 本章小结

- 模型由顶点、边、面和网格拓扑描述，细分会同时影响形状细节与后续顶点工作量。
- 局部空间、世界空间和视图空间有不同责任，变换必须保持点、向量和法线的语义。
- Graphics Pipeline（图形管线）接收建模阶段的几何契约，Light（光）、Radiometry（辐射度量）和 Reflectance（反射率）在统一空间中解释表面响应。
- 现代图形硬件能利用 Parallelism（并行性）处理顶点和实例，但 memory latency（内存延迟）会限制拓扑访问吞吐。
- 调试顺序应是“拓扑连接 → 法线方向 → 空间变换 → 可见细节 → 顶点访问代价”。

<Exercises>

**问题 1：判断三角形位置。** 三个顶点位置分别为 `p₀=0`、`p₁=4`、`p₂=8`，重心权重为 `α=0.25`、`β=0.50`、`γ=0.25`。按本章公式求插值位置，并说明权重总和的作用。

<Answer>
  `p = 0.25 × 0 + 0.50 × 4 + 0.25 × 8 = 4`。权重总和为 1
  时，结果保持在三个顶点描述的三角形内部；总和异常通常说明重心坐标或输入数据不完整。
</Answer>

**问题 2：区分空间与光照。** 模型沿一个轴非均匀缩放后，轮廓仍正确但局部变暗。你会先查模型位置还是法线？如何用 Light（光）和 Reflectance（反射率）证据排查？

<Answer>
  先查法线变换和归一化，再确认 Light（光）方向与模型处于同一坐标空间；固定
  Reflectance（反射率）后比较法线点积和入射能量，可以区分空间错误与材质响应错误。
</Answer>

**问题 3：定位顶点瓶颈。** 细分后顶点数量增加，但目标视口中新增面几乎不可见，等待比例上升。你会先增加 Parallelism（并行性）还是检查 memory latency（内存延迟）？

<Answer>
  先检查 memory
  latency（内存延迟）、索引复用和缓存命中，并确认新增顶点是否有可见贡献；数据布局和细节层级合理后，再评估增加
  Parallelism（并行性）是否有收益。
</Answer>

</Exercises>
