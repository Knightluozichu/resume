## 先把渲染想成一条有证据的生产线

屏幕上的一个像素不是场景数据的直接拷贝。它先获得几何输入，再经过可见性筛选，随后用光照模型解释留下的片段，最后被写入目标缓冲区。每一步都有自己的输入、输出和可观测指标；画面异常时，应该沿着这条链回放，而不是直接把所有参数一起调亮。

本章把 The Rendering Pipeline 组织成三个可检查问题：哪些几何最终可见，光能量如何被表面保留，以及现代图形硬件怎样并行处理这些工作。先预测：只增加采样数量，物体轮廓会变宽还是有效样本会变多？只改变 Reflectance（反射率），几何位置会移动还是输出响应会变化？只增加 memory latency（内存延迟），颜色会改变还是完成任务会减少？

## 计算机图形学导论：Graphics Pipeline 是输入到输出的契约

计算机图形学导论中最重要的工程习惯之一，是把 Graphics Pipeline（图形管线）视为一份阶段契约：前一阶段交付的数据必须说明坐标空间、覆盖范围和生命周期，后一阶段才可以据此工作。一个常见的抽象顺序是几何处理、可见性判断、片段着色和输出合成。

### 几何输入与坐标空间

<Term def="把顶点、法线、材质引用和拓扑数据交给后续渲染阶段的结构化输入。">
  几何输入
</Term>

几何输入包含位置、法线、纹理坐标和索引。模型空间中的顶点经过变换后进入世界空间，再由相机变换进入观察关系；如果法线仍停留在另一个空间，后续光照即使公式正确也会产生错误方向。渲染阶段首先要确认的不是颜色，而是每一份数据的空间语义。

### 可见性与片段预算

<Term def="决定哪些几何覆盖当前像素并值得继续计算的过程，包含深度、遮挡和采样覆盖等证据。">
  可见性
</Term>

可见性把大量潜在几何收缩成一组有效片段。深度测试可以拒绝被遮挡的片段，背面剔除可以减少不需要处理的面，采样覆盖则决定边缘像素的证据是否充分。可见性并不负责解释材质颜色；它的职责是给光照阶段一份有边界的工作清单。

若一个物体轮廓缺口只出现在边缘，先记录覆盖样本和深度顺序，再决定是否修改几何。若整个物体位置都偏移，应回到变换和相机输入检查，而不是提高采样密度掩盖坐标错误。

## Light（光）：把入射能量带到当前片段

Light（光）可以在世界空间、视图空间或局部空间中定义，但参与计算的方向和位置必须与片段数据处于同一坐标语义。光源方向决定能量从哪里来，距离和方向衰减决定能量到达多少，表面法线则决定这份能量以什么角度到达。

<Term def="在渲染阶段中把几何、光源和材质状态组合为片段颜色的计算过程。">
  光照
</Term>

光照不是一个“把颜色调亮”的按钮。Radiometry（辐射度量）负责描述功率、面积、方向和立体角等能量量纲，Reflectance（反射率）负责描述表面保留入射能量的比例。固定几何与采样后，改变光能量应主要改变亮度；固定光能量后，改变反射率应主要改变表面响应，这两个预测可以在实验中分别验证。

### Radiometry（辐射度量）与 Reflectance（反射率）

辐射度量的价值是让“更亮”变成可追踪的能量变化，而不是凭视觉猜测。对于一个简化的片段，可把输出响应写成：

$$
L_{out}=V\cdot E_{light}\cdot R_{surface}
$$

其中 $V$ 表示可见且有效的样本比例，$E_{light}$ 表示到达片段的光能量，$R_{surface}$ 表示表面反射率。这个模型不是完整的材质方程，却足以帮助定位：轮廓不动而亮度变化，优先查能量或反射率；有效样本减少而平均响应稳定，优先查可见性和采样覆盖。

下面的伪代码保留了阶段边界，让每种证据可以单独记录：

```cpp
Geometry geometry = fetchGeometry(scene, camera);
VisibleSet visible = resolveVisibility(geometry, depthBuffer, samples);
Radiance radiance = evaluateLight(visible, light, radiometry);
Color frame = applyReflectance(radiance, material.reflectance);
present(frame);
```

## Modern Graphics Hardware：渲染工作被拆成许多任务

Modern Graphics Hardware（现代图形硬件）擅长批量执行顶点、片段和纹理访问。一个阶段如果有许多相互独立的片段，就可以把它们分配给多个执行单元；但任务之间共享的纹理、深度缓冲和材质表仍会形成等待。硬件吞吐因此不是“核心越多越快”的单变量答案，而是工作量、局部性和同步边界的共同结果。

### Parallelism（并行性）与 memory latency（内存延迟）

<Term def="让多个相互独立的渲染任务同时推进的执行能力；它提高吞吐，但不能取消数据依赖。">
  并行性
</Term>

Parallelism（并行性）适合同时处理不同像素、实例或片段。memory latency（内存延迟）表示任务发出纹理、深度或材质访问后，等待数据返回的时间。若所有任务都读取同一份远端数据，继续扩大并行宽度可能只会增加排队；若数据局部性良好，更多并行任务才可能转化为有效吞吐。

性能诊断应同时记录片段数量、批次大小、缓存命中、带宽和等待比例。先确认光照与可见性没有产生无效工作，再调整任务布局；否则“优化”可能只是把错误更快地算完。

## 常见误区

<Callout type="trap" title="误区一：采样越多，轮廓错误就会消失">
  现象 → 采样数量上升后，边缘仍然出现断裂，帧时间却增加。

原因 → 采样只能增加覆盖证据，不能修复错误的顶点位置、深度顺序或坐标空间；可见性阶段收到的几何若已错误，更多样本只会重复观察错误。

修法 → 先冻结材质与光能量，检查几何变换、深度和有效样本位置，再判断是否需要提高采样密度。

</Callout>

<Callout type="trap" title="误区二：画面变暗就只调高 Light（光）">
  现象 → 调高光源能量后，局部仍然反常地暗，或不同视角的亮度变化方向不一致。

原因 → 法线和光源可能不在同一空间，或者 Reflectance（反射率）和 Radiometry（辐射度量）的单位语义被混在一起；能量增益无法修正方向错误。

修法 → 记录片段法线、入射方向、到达能量和表面反射率，逐项固定后再比较输出响应。

</Callout>

<Callout type="trap" title="误区三：扩大 Parallelism（并行性）必然降低帧时间">
  现象 → 执行单元增加后，完成任务数没有按比例上升，等待任务和带宽压力反而变大。

原因 → 任务共享纹理、深度或材质数据，memory latency（内存延迟）成为关键路径；更多并行工作不能取消数据依赖与访问排队。

修法 → 先测缓存局部性、访问批次和等待比例，再通过数据布局、可见性裁剪或任务分块减少无效访问。

</Callout>

## 本章小结

- Graphics Pipeline（图形管线）是一份阶段契约：几何输入先被处理，再经过可见性、光照和输出阶段。
- 可见性决定哪些片段值得继续计算，采样覆盖和深度顺序是可复核的证据。
- Light（光）带来能量，Radiometry（辐射度量）描述能量语义，Reflectance（反射率）描述表面保留能量的比例。
- Modern Graphics Hardware（现代图形硬件）可以利用 Parallelism（并行性）批量处理任务，但 memory latency（内存延迟）会限制有效吞吐。
- 调试顺序应是“几何与空间 → 可见性覆盖 → 能量与反射 → 任务局部性 → 帧输出”，每次只改变一个条件。

## 练习与答案

<Exercises>

**问题 1：定位阶段责任。** 一个片段的顶点位置正确，但被遮挡的区域仍然执行了大量光照计算。你会先检查哪个阶段？请写出两个可观测证据。

<Answer>
  先检查可见性阶段。可以记录深度测试前后的片段数量、遮挡剔除比例或有效采样覆盖；如果无效片段仍大量进入光照阶段，问题在阶段边界或裁剪策略，而不是先调高
  Light（光）。
</Answer>

**问题 2：拆分能量因素。** 固定有效样本比例后，光能量从 0.6 提高到 0.9，表面反射率保持 0.5。用本章的简化模型说明输出响应如何变化；如果几何轮廓也移动，说明还混入了什么问题？

<Answer>
  在 $L_{out}=V\cdot E_{light}\cdot R_{surface}$ 中，$V$ 与 $R_{surface}$
  不变时，能量项按 0.9 除以 0.6
  的比例提高，输出应随之变亮。若轮廓也移动，说明几何、相机或可见性输入被同时改变，不能把结果归因于光照。
</Answer>

**问题 3：判断吞吐瓶颈。** 片段任务从 12 增加到 18，Parallelism（并行性）保持不变，memory latency（内存延迟）明显升高，而有效吞吐下降。请给出一个优先修复动作和一个不应先做的动作。

<Answer>
  优先检查纹理与深度访问的局部性，减少不可见片段或重排批次，让任务少等待共享数据。不应先盲目扩大并行宽度，因为更多任务可能继续争用同一访问路径，反而放大排队。
</Answer>

</Exercises>
