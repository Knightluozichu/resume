## 先把光线追踪想成一次可回放的询问

光线追踪不是“从相机直接得到颜色”，而是对每个像素提出一串可回放的问题：从哪里发出一条样本光线，它先命中了哪一个表面，交点如何解释入射光，反射或折射后的贡献怎样回到像素。每个问题都有独立证据，因此噪声、黑斑和帧时间都可以沿路径定位。

本章把 The Ray Tracing Pipeline 拆成三条观察线：光线怎样穿过阶段，空间结构怎样减少无关求交，以及 Modern Graphics Hardware（现代图形硬件）怎样并行完成许多射线任务。先预测：只增加反射次数，单条射线的命中位置会自动改变吗？只增加采样数量，Light（光）的能量会变强吗？只增加 memory latency（内存延迟），像素颜色会改变还是完成任务会减少？

## 计算机图形学导论：Graphics Pipeline 接收一条带语义的光线

计算机图形学导论把 Graphics Pipeline（图形管线）描述为一组有边界的转换：几何输入经过变换和可见性处理，光照阶段解释表面响应，最后才形成输出。光线追踪把“从像素找表面”的顺序反过来，却仍然需要同样的契约：起点、方向、坐标空间、命中距离和材质引用都必须能被下一阶段理解。

### 光线与采样位置

<Term def="从相机或交点出发、带有起点和方向的有序射线，用来询问场景中第一个有效表面。">
  光线
</Term>

一条相机光线可以写成：

$$
r(t)=o+td
$$

其中 $o$ 是起点，$d$ 是归一化方向，$t$ 是沿方向前进的距离。像素采样点决定 $d$ 的初始值；透视相机、镜头采样或景深效果会改变采样分布，但不会改变这份基本契约。调试时应先画出 $o$ 和 $d$，确认光线确实穿过目标像素，再检查求交结果。

### 交点与几何证据

<Term def="光线与场景表面满足几何约束的位置，包含命中距离、法线和材质引用等后续着色所需信息。">
  交点
</Term>

对三角形而言，求交不仅要返回命中距离，还应携带重心坐标、法线和材质索引。最小的有效命中距离通常优先于更远的候选面，因为它代表从当前起点看到的第一个表面。若命中距离异常，先检查相机空间、三角形绕序和数值容差，不要用更强的光源掩盖错误的几何证据。

## 可见性：求交阶段是在筛选“看得见的表面”

<Term def="由最近有效交点决定当前光线看到哪个表面的状态；它连接空间遍历、深度关系和遮挡结果。">
  可见性
</Term>

可见性在光线追踪中不是一个独立的颜色效果，而是“哪一个交点可以继续参与着色”的判断。主光线寻找相机看到的表面，阴影光线询问光源方向是否被遮挡，反射光线则从当前交点寻找下一次可见表面。不同类型的光线共享求交机制，却有不同的终止条件和证据窗口。

### 空间结构如何缩小候选范围

没有加速结构时，一条光线可能需要测试场景中的许多三角形。包围盒层次、规则网格或其他空间索引把几何组织成可拒绝的候选区域：如果光线与一个节点的包围范围不相交，就可以跳过该节点的全部子几何。结构的价值是减少测试数量，不是改变真实交点。

先预测：把结构深度调高后，候选节点一定单调减少吗？如果更新代价、节点重叠或访问局部性变差，深层结构也可能增加遍历成本。实验时同时记录候选节点、真实三角形测试和更新时间，才能判断结构是否真的有效。

## Light（光）与 Radiometry（辐射度量）：交点要解释能量

Light（光）从光源沿路径传播，光线追踪在每个交点询问这份能量如何到达表面、被遮挡以及继续反射。法线决定方向关系，材质决定表面如何响应，路径长度和光源分布则影响到达能量。把这些因素混成一个亮度常数，会让路径错误和材质错误难以区分。

Radiometry（辐射度量）为功率、面积、方向和立体角提供能量语义；Reflectance（反射率）描述表面保留入射能量的比例。对于一个教学用的单次反射模型，可以把像素贡献写成：

$$
C_{pixel}=V\cdot E_{light}\cdot R_{surface}
$$

其中 $V$ 是可见性与采样覆盖的组合项，$E_{light}$ 是到达交点的能量，$R_{surface}$ 是表面反射率。真实的渲染方程还会包含方向积分和多次反射，但这个简化式足以支持一个重要预测：固定光线路径后，只改反射率，几何命中不应移动；固定材质后，只改采样覆盖，噪声应改变而光源本身不应变强。

下面的伪代码保留了从相机到像素的责任边界：

```cpp
Ray primary = makeCameraRay(pixel, sample);
Hit hit = traceClosest(primary, sceneStructure);
Radiance direct = evaluateLight(hit, light, radiometry);
Color contribution = applyReflectance(direct, hit.material);
accumulate(pixel, contribution);
```

## Modern Graphics Hardware：许多光线可以同时求交

Modern Graphics Hardware（现代图形硬件）适合把像素、样本和路径分成大量任务。相同阶段的射线可以共享执行资源，分支相近的路径容易形成稳定的批次；但不同反射深度、不同材质和不同空间节点会造成分歧。硬件吞吐因此取决于任务是否可并行、访问是否局部，以及等待是否被其他工作隐藏。

### Parallelism（并行性）与 memory latency（内存延迟）

<Term def="让许多独立光线或求交任务同时推进的执行能力；它受路径分歧和共享数据依赖限制。">
  并行性
</Term>

Parallelism（并行性）可以同时推进同一批主光线或阴影光线。memory latency（内存延迟）则来自读取空间节点、三角形、纹理和材质表后的等待。如果射线访问路径相近，缓存可以复用数据；如果每条射线跳到不同节点，更多并行任务可能只是制造更多未命中和排队。

因此，性能记录应包括每像素样本数、平均反射深度、候选节点、缓存命中、求交测试和等待比例。先降低不可见路径和无贡献样本，再考虑扩大批次或改变任务布局；否则加宽并行度只会更快地触发 memory latency（内存延迟）。

## 常见误区

<Callout type="trap" title="误区一：反射次数增加就会修复黑斑">
  现象 → 反射次数提高后，画面仍有黑斑，计算量和噪声却一起上升。

原因 → 黑斑可能来自错误法线、射线起点自相交或可见性判定；额外路径只会重复传播错误的交点。

修法 → 先记录首个命中距离、法线和遮挡结果，给次级光线加可解释的偏移，再判断是否需要更多反射。

</Callout>

<Callout type="trap" title="误区二：空间结构只要更深就一定更快">
  现象 → 结构深度增加后，候选节点减少，但遍历时间和更新时间反而上升。

原因 → 节点可能重叠、访问跳跃变多，或动态场景的结构更新成本超过了节省的求交测试；结构没有改变真实交点，只改变了筛选路径。

修法 → 同时测量候选节点、真实几何测试、缓存命中和更新时间，再选择深度、分割方式或重建策略。

</Callout>

<Callout type="trap" title="误区三：扩大 Parallelism（并行性）就能消除等待">
  现象 → 射线批次变大后，完成任务比例没有提高，memory latency（内存延迟）却更明显。

原因 → 不同路径访问不同空间节点和材质，分支分歧与缓存未命中让执行单元等待共享数据；并行宽度不能消除数据依赖。

修法 → 先按路径阶段重排任务、减少不可见样本并改善访问局部性，再评估增加并行批次是否有收益。

</Callout>

## 本章小结

- 光线追踪把像素询问拆成发射、求交、着色和累积，Graphics Pipeline（图形管线）的阶段契约仍然成立。
- 光线携带起点和方向，交点携带命中距离、法线和材质引用；可见性决定哪一个交点进入后续解释。
- Light（光）带来能量，Radiometry（辐射度量）说明能量语义，Reflectance（反射率）说明表面保留能量的比例。
- Modern Graphics Hardware（现代图形硬件）可以利用 Parallelism（并行性）同时处理许多射线，但 memory latency（内存延迟）会限制有效吞吐。
- 调试顺序应是“光线输入 → 首个交点 → 可见性与法线 → 能量与反射 → 路径批次与访问”，每次只改变一个条件。

<Exercises>

**问题 1：判断首个交点。** 相机光线写成 $r(t)=o+td$，沿同一方向得到两个候选命中距离 $t=2.0$ 和 $t=4.5$。在没有透明材质的简化场景中，应选择哪个交点？还要记录什么几何证据？

<Answer>
  应选择 $t=2.0$
  的最近有效交点，因为它代表从当前起点首先看到的表面。还要记录交点法线、材质引用和坐标空间；这些证据会影响后续
  Light（光）与 Reflectance（反射率）的解释。
</Answer>

**问题 2：拆分像素响应。** 固定可见性项 $V=0.8$、光能量 $E_{light}=0.75$ 和反射率 $R_{surface}=0.5$，用简化模型计算像素贡献。如果只增加采样而使 $V$ 从 0.8 变成 0.9，哪一项发生了变化？

<Answer>
  初始贡献为 $0.8\times0.75\times0.5=0.30$；调整后为
  $0.9\times0.75\times0.5=0.3375$。变化来自有效可见样本比例，不表示
  Light（光）能量或材质反射率被改变。
</Answer>

**问题 3：定位射线吞吐。** 样本数和射线数量增加后，命中结果保持稳定，但等待任务变多、缓存命中下降。你会先调低反射次数，还是先检查空间节点与材质访问的局部性？说明理由。

<Answer>
  先检查空间节点与材质访问的局部性，因为命中结果稳定说明几何和光照语义大致正确，等待增加更像
  memory
  latency（内存延迟）问题。确认访问路径后，再根据无贡献路径决定是否降低反射次数或样本数。
</Answer>

</Exercises>
