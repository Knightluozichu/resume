## 先把全局光照想成一张会回流的能量地图

只计算光源到表面的直达关系，通常无法解释墙面被邻近物体染色、角落变暗或遮挡边缘的柔和过渡。全局光照把表面接收到的能量再次作为后续路径的输入，让场景中的表面彼此影响。代价是路径更多、可见性更复杂、估计噪声和缓存陈旧度也更难隐藏。

本章把 Global Illumination Pipeline 拆成三个可检查问题：直接光和间接光怎样分工，有限采样或缓存怎样近似大量路径，以及 Modern Graphics Hardware（现代图形硬件）怎样并行处理这些路径。先预测：只增加反弹次数，所有间接路径都会带来可见亮度吗？只增加样本，遮挡错误会消失吗？只增加 memory latency（内存延迟），光照目标会改变还是完成任务会变慢？

## 计算机图形学导论：Graphics Pipeline 接收全局能量输入

计算机图形学导论中，Graphics Pipeline（图形管线）把几何、可见性、材质和光源组织成阶段契约。全局光照不是另一个孤立的颜色滤镜，而是对光照阶段输入的扩展：当前表面既接收 Light（光）的直接贡献，也接收其他表面反射回来的间接贡献。

### 直接光和间接光

<Term def="从光源直接到达当前表面的能量贡献，通常需要经过一次光源可见性判断。">
  直接光
</Term>

直接光的路径较短，通常可以用一条到光源的可见性查询来估计。若遮挡关系、法线和坐标空间正确，固定材质后改变光源能量应主要改变直接亮度，而不应改变物体轮廓。

<Term def="先到达一个表面、再由该表面反射或散射到当前表面的能量贡献，可能包含多次路径反弹。">
  间接光
</Term>

间接光让相邻表面互相影响。墙面颜色可能回流到地面，遮挡区域可能仍保留少量环境亮度，镜面路径则可能把远处高亮物体带入当前视野。间接光的难点不是“把直接光再加一次”，而是估计哪些路径真实存在、贡献有多大、何时可以停止。

## Light（光）与 Radiometry（辐射度量）：能量传播必须有单位

Light（光）是能量输入，Radiometry（辐射度量）提供功率、面积、方向和立体角的计量语义。全局光照需要在每次路径反弹时保留这些语义：路径长度会影响到达能量，法线决定方向投影，表面 Reflectance（反射率）决定能量有多少被保留或继续发出。

<Term def="把光源输入、路径方向、面积和可见性组合成当前表面能量响应的计算过程。">
  能量传输
</Term>

对一个简化的两次路径，可以把像素贡献写成：

$$
C=V_0E_0R_0+V_1E_1R_0R_1
$$

其中第一项代表直接光，第二项代表经过一次中间表面的间接光；$V$ 表示路径可见性，$E$ 表示到达路径节点的能量，$R$ 表示表面反射率。真实系统还要处理方向分布、纹理、折射和更多反弹，但这个简化式可以支持可验证预测：固定 $V$ 和几何后改变 $R$，贡献会变；固定 $R$ 后改变采样，主要应改变估计稳定性。

### 反射率不是曝光旋钮

Reflectance（反射率）描述表面响应，不是把整张图一起调亮的曝光值。提高反射率可能让间接光在多个表面之间回流更久，导致局部亮度上升；但如果颜色突然突破能量预算，应先查单位、色彩空间和重复计入，而不是继续提高反射率。

## 可见性、探针与缓存：用有限证据近似无限路径

全局光照的每个像素都可能依赖许多路径，实际系统通常用光线样本、辐照度探针、屏幕空间缓存或体素/辐射缓存压缩这些信息。缓存的价值是复用附近位置的间接光估计，风险是空间不连续、遮挡变化和场景更新让旧数据失效。

先预测：增加探针数量会自动修复墙角漏光吗？不会。探针数量提高空间覆盖，却不能修复错误的法线、错误的可见性或过度平滑的插值。应同时记录探针覆盖、遮挡比例、缓存更新时间和样本方差。

### 质量证据的三层账本

第一层是路径账本：每条样本记录起点、方向、命中和反弹次数。第二层是空间账本：每个缓存条目记录位置、法线、有效半径和更新时间。第三层是输出账本：记录直接贡献、间接贡献、噪声和帧时间。把三层混在一起，会让“缓存陈旧”看起来像“光源变弱”。

下面的伪代码把直接和间接责任分开：

```cpp
Direct direct = traceToLight(surface, light, visibility);
Indirect indirect = sampleBounce(surface, scene, samples, cache);
Color result = combineTransport(direct, indirect, material.reflectance);
present(result);
```

## Modern Graphics Hardware：路径并行也会遇到分歧

Modern Graphics Hardware（现代图形硬件）可以并行处理不同像素、光线和缓存更新。相同反弹深度、相近材质和相似访问路径容易组成稳定批次；路径深度不同或命中不同材质时，分支会分歧，执行单元不能始终保持同样的工作量。

### Parallelism（并行性）与 memory latency（内存延迟）

<Term def="让许多像素、光线或缓存更新任务同时推进的执行能力；它受路径分歧和共享数据依赖限制。">
  并行性
</Term>

Parallelism（并行性）能把独立路径同时送入求交、着色或缓存更新阶段。memory latency（内存延迟）则来自读取纹理、空间结构、缓存条目和材质表后的等待。如果路径随机访问远处数据，扩大批次可能只会增加缓存未命中；如果访问局部性良好，并行才更可能转化成有效吞吐。

性能排查应记录每像素样本、平均反弹、路径分歧、缓存命中、等待比例和间接光误差。先减少没有贡献的路径和陈旧缓存，再考虑增加并行宽度；否则硬件会更快地处理错误或无效工作。

## 常见误区

<Callout type="trap" title="误区一：增加反弹次数就能消除漏光">
  现象 → 反弹次数提高后，墙角仍然漏光，路径任务和帧时间却增加。

原因 → 漏光可能来自错误法线、遮挡查询或缓存插值半径；额外反弹只会让错误的可见性继续传播。

修法 → 先记录首个命中、遮挡结果和缓存有效半径，固定直接光后再判断是否需要更多反弹。

</Callout>

<Callout type="trap" title="误区二：缓存探针越多，间接光就越准确">
  现象 → 探针数量上升后，某些区域更平滑，但动态遮挡附近出现拖影或亮斑。

原因 → 覆盖数量增加不等于缓存内容新鲜；空间插值可能跨过遮挡边界，旧探针还会把历史能量带入当前帧。

修法 → 同时检查探针位置、法线相似度、遮挡比例和更新时间，必要时缩小插值半径或主动失效缓存。

</Callout>

<Callout type="trap" title="误区三：扩大 Parallelism（并行性）就能消除路径等待">
  现象 → 执行单元增加后，路径分歧、缓存未命中和 memory latency（内存延迟）一起上升。

原因 → 不同反弹深度和材质访问不同数据，任务批次变宽反而放大了分支和共享缓存争用；并行宽度不能取消数据依赖。

修法 → 先按路径阶段或反弹深度重排任务，裁剪无贡献样本并改善访问局部性，再评估增加并行度。

</Callout>

## 本章小结

- Graphics Pipeline（图形管线）接收几何、可见性、材质和光源输入，全局光照把表面间的能量回流纳入光照阶段。
- 直接光从光源到达表面，间接光经过一次或多次表面反射；两者必须用独立证据记录。
- Light（光）提供能量，Radiometry（辐射度量）提供单位语义，Reflectance（反射率）决定表面保留和继续传播的能量。
- 探针和缓存压缩了大量路径证据，但遮挡变化、空间插值和缓存陈旧度会影响间接光质量。
- Modern Graphics Hardware（现代图形硬件）能利用 Parallelism（并行性）处理许多路径，但 memory latency（内存延迟）与路径分歧会限制吞吐。

## 练习与答案

<Exercises>

**问题 1：拆分直接与间接贡献。** 固定直接贡献为 0.40，间接路径到达能量为 0.30，两个表面反射率均为 0.5，路径可见性均为 1。按 $C=V_0E_0R_0+V_1E_1R_0R_1$ 计算像素贡献，并说明反弹项为什么多乘一次反射率。

<Answer>
  像素贡献为
  $1\times0.40\times0.5+1\times0.30\times0.5\times0.5=0.275$。间接项经过当前表面和中间表面两次反射，因此要保留两个
  Reflectance（反射率）因素；它不是把直接光简单复制一份。
</Answer>

**问题 2：判断缓存问题。** 动态遮挡改变后，直接光立刻正确，但间接光在旧位置留下亮斑。你会先增加样本，还是检查缓存更新时间和插值半径？为什么？

<Answer>
  先检查缓存更新时间、探针位置和插值半径。直接光正确说明当前
  Light（光）和基本可见性路径可用，亮斑更像陈旧缓存跨过了新的遮挡边界；增加样本不能自动让旧缓存失效。
</Answer>

**问题 3：定位硬件瓶颈。** 光照质量保持稳定，但样本和反弹增加后缓存命中下降、等待任务上升。请给出一个优先修复动作，并说明为何不应先盲目扩大 Parallelism（并行性）。

<Answer>
  优先按路径阶段或反弹深度重排任务，并检查缓存和纹理访问的局部性，减少无贡献路径。盲目扩大
  Parallelism（并行性）会让更多分歧路径争用共享数据，放大 memory
  latency（内存延迟），未必提高有效吞吐。
</Answer>

</Exercises>
