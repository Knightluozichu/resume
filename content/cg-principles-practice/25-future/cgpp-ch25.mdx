## 先把“未来”变成可验收的设计空间

“未来”不是对某个产品发布日期的猜测，而是一个压力测试：如果渲染系统多出一种能力，它要接收什么输入、改变哪个阶段、提供哪些证据，又会把成本转移到哪里？这个问题把想象力拉回工程边界。我们不需要假装知道具体硬件或接口的名字，也能比较一条路线是否可解释、可测量、可回放。

本章用四个问题贯穿一条未来路线：输入契约是否稳定？新能力是否落在明确的可编程阶段？视觉质量是否能拆成光照、采样和误差证据？规模扩大后，Parallelism（并行性）是否被 memory latency（内存延迟）抵消？先预测：如果只把“未来能力”接到输出端，系统会更容易验收，还是更难定位责任？

## 计算机图形学导论：Graphics Pipeline 的边界仍然重要

计算机图形学导论给出的第一种稳定视角，是把图像看成一串有输入和输出的变换，而不是某个神奇的最终颜色。Graphics Pipeline（图形管线）可以把几何、可见性、材质、光源、采样和合成组织成阶段。未来能力只有在这些阶段之间有清楚的责任边界，才可能被替换、比较和回退。

例如，未来的光照估计可以替换一个光照阶段，但不应该默默改写相机坐标、材质单位或显示编码。未来的几何压缩可以改变输入表示，但必须说明它是否影响法线、纹理坐标和可见性。这样的拆分让“更先进”变成可验证的接口变化，而不是只看一张更亮或更锐的截图。

### 输入、阶段和输出的能力契约

<Term def="描述某阶段允许的输入单位、坐标、范围、随机性和输出承诺的最小接口；未来能力必须先遵守它，才能被替换和比较。">
  能力契约
</Term>

一份能力契约至少写清几何坐标空间、材质和光照的单位、随机样本的种子、允许的误差范围，以及输出属于线性空间还是显示空间。契约越具体，越容易用同一组输入重放两个实现；契约越含糊，性能或质量的变化就可能来自输入漂移。

<Term def="在管线中承担清楚输入与输出责任、可以由不同算法实现并接受相同验收的处理阶段。">
  可编程阶段
</Term>

可编程阶段不是把所有逻辑塞进一个黑盒，而是让阶段的输入、状态和验收保持可见。替换阶段时，应先固定场景、随机种子和显示变换，再比较能量、误差、帧时间及回退结果。这样才能知道提升来自算法，还是来自偷偷改变了输入。

## Light、Radiometry 与 Reflectance：未来光照不能丢掉单位

Light（光）是能量传播的对象，Radiometry（辐射度量）为功率、面积、方向和立体角提供计量语义，Reflectance（反射率）则描述表面保留和重新分配能量的方式。未来的光照模型即使更擅长估计复杂路径，也不能把这些概念合并成一个没有单位的亮度滑块。

可以用一个小模型约束预测。对一次直接贡献和一次单反弹贡献，令路径可见性为 $V$，到达能量为 $E$，表面反射率为 $R$，则

$$
C=V_0E_0R_0+V_1E_1R_0R_1
$$

第二项多经过一个表面，因此多一个反射率因素。它不是完整的渲染方程，却足以检查三件事：增加光能量是否改变能量账本，改变反射率是否只影响表面响应，增加样本是否主要降低估计噪声。若结果突破了单位或能量预算，应先查坐标、色彩空间、可见性和重复计入，而不是把“未来”当作错误的免责理由。

## 质量验收：把视觉收益拆成误差预算

<Term def="把允许的几何、可见性、能量、采样噪声和时间误差分配到可观察证据中的计划；它说明系统何时算作足够好。">
  误差预算
</Term>

误差预算让质量讨论有了可操作的边界。几何误差可以用轮廓或深度差异观察，光照误差可以对比能量和可见性，采样误差可以记录方差，性能误差则要看帧时间和等待比例。它们不能被一张总分遮盖：一张低噪声但漏光的图，并不比一张有噪声但遮挡正确的图更可靠。

先猜一猜：把样本数量从 4 提高到 20，会自动修复法线方向错误吗？不会。更多样本可以让同一个估计更稳定，却不能把错误的输入变成正确的输入。实践时固定相机、场景、种子和曝光，只改一个旋钮，并为每次比较保存质量指标和成本指标。

### 质量、延迟与回退

一个可交付的未来功能至少需要三条路径：目标质量路径、资源不足时的回退路径，以及问题出现后的诊断路径。目标质量路径说明新增细节或更稳定的光照；回退路径说明降低样本、关闭某个阶段或使用旧实现时仍然保持什么契约；诊断路径说明如何重放同一输入并定位责任阶段。

<Term def="用固定输入、固定随机种子和记录的参数重新执行一次实验，使质量或性能差异可以被复核。">
  复核回放
</Term>

复核回放不是录屏，而是保存足以再现决策的输入、参数、随机种子和输出证据。它让“看起来更好”变成“在同一条件下，误差下降了多少，成本增加了多少”。未来路线越复杂，回放越是验收的一部分，而不是发布后的补救工具。

## Modern Graphics Hardware：并行扩展仍受内存等待约束

Modern Graphics Hardware（现代图形硬件）可以并行推进像素、光线、材质和缓存更新，但并行执行并不会删除数据依赖。Parallelism（并行性）擅长扩大独立工作，memory latency（内存延迟）则来自纹理、几何、加速结构和缓存条目的等待。访问局部性差、路径分歧大或批次之间依赖强时，更多工作单元可能只是同时等待。

先预测：任务数量翻倍时，有效吞吐一定翻倍吗？只有在占用、访问和路径形态仍然适合并行时，答案才可能接近“是”。因此应同时记录完成任务、等待任务、缓存命中、路径分歧和每任务时间。若质量已经稳定但吞吐变差，优先检查数据布局、批次重排、无贡献样本和阶段间依赖，而不是盲目增大并行宽度。

### 从能力路线到规模化交付

一个未来能力的路线可以压缩成四个门：输入契约、可编程阶段、质量验收、规模化交付。每一扇门都要有一个失败时仍可解释的结果：契约不满足就拒绝输入，阶段不稳定就回退，质量超预算就标记，吞吐不足就保留等待证据。这样的路线并不承诺未来一定成功，却让失败可以被复盘。

## 常见误区

<Callout type="trap" title="误区一：未来能力越靠近输出，越容易验收">
  现象 → 新算法让最终图像更锐，但几何、材质、光照和显示变换的责任混在一起，问题无法定位。

原因 → 输出端只有结果，没有明确的输入契约和阶段证据；任何输入漂移都可能被误认为算法收益。

修法 → 把能力放入可编程阶段，固定坐标、单位、随机种子和回退实现，再分别记录质量、误差和成本。

</Callout>

<Callout type="trap" title="误区二：提高样本就能修复所有质量问题">
  现象 → 样本增加后噪声下降，但漏光、能量超预算或轮廓错误仍然存在，渲染时间继续上升。

原因 → 采样主要改善估计稳定性，不能修复错误法线、错误可见性、重复计入或显示空间混用。

修法 → 先固定场景和种子，分开检查 Light（光）的能量、Radiometry（辐射度量）的单位、Reflectance（反射率）的范围和遮挡证据，再决定样本预算。

</Callout>

<Callout type="trap" title="误区三：并行度扩大就代表硬件吞吐扩大">
  现象 → 任务数量和执行单元增加后，等待任务、缓存未命中和路径分歧同步增长。

原因 → Parallelism（并行性）只能同时推进可独立的工作，memory latency（内存延迟）和数据依赖仍会让批次停顿。

修法 → 先按阶段或路径形态重排任务，改善访问局部性，裁剪无贡献工作，再用复核回放比较有效吞吐和总成本。

</Callout>

## 本章小结

- 计算机图形学导论提供了“阶段有契约”的稳定视角；Graphics Pipeline（图形管线）让未来能力可以被放置、替换和回退。
- 能力契约、可编程阶段、误差预算和复核回放把“更先进”拆成可检查的输入、阶段、质量和重放证据。
- Light（光）是能量对象，Radiometry（辐射度量）保留单位语义，Reflectance（反射率）决定表面如何保留和分配能量；增加样本不能修复单位或可见性错误。
- Modern Graphics Hardware（现代图形硬件）可以利用 Parallelism（并行性）扩大独立工作，但 memory latency（内存延迟）、路径分歧和数据依赖决定规模化收益。
- 未来路线的发布标准不是“预测准确”，而是在同一输入下能解释质量收益、成本变化、回退结果和失败责任。

## 练习与答案

<Exercises>

**问题 1：设计能力契约。** 你要把一个新的光照估计阶段接入 Graphics Pipeline（图形管线）。请列出至少四项必须固定的输入或输出约束，并说明它们如何帮助两个实现做复核回放。

<Answer>
  可以固定坐标空间、Light（光）的能量单位、Reflectance（反射率）的范围、随机种子、输出色彩空间和误差预算中的阈值。两个实现使用同一场景、种子和单位时，差异就能归因到阶段算法，而不是输入漂移；保存参数与输出指标后，还可以重新执行复核回放。
</Answer>

**问题 2：拆分质量收益。** 某次实验把样本从 4 提高到 16 后，估计噪声下降，但墙角仍漏光，能量账本还增加了 30%。你会如何安排排查顺序？

<Answer>
  先固定场景、种子和曝光，检查遮挡、法线、坐标空间和重复计入，再核对
  Radiometry（辐射度量）的单位与
  Reflectance（反射率）的范围；确认路径责任后，才讨论样本预算。样本减少噪声，却不能修复可见性或能量语义错误。
</Answer>

**问题 3：定位吞吐瓶颈。** 任务数量翻倍后，完成任务只增加 20%，等待任务和缓存未命中明显增加。请给出一个优先动作，并解释为什么不应先盲目增加 Parallelism（并行性）。

<Answer>
  优先按阶段或路径形态重排任务，检查数据布局和访问局部性，并裁剪没有可见贡献的工作。Parallelism（并行性）只能同时推进独立任务；如果
  memory
  latency（内存延迟）和数据依赖已经主导时间，更宽的批次会让更多任务一起等待。
</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="能力契约">
  描述某阶段输入单位、坐标、范围、随机性和输出承诺的最小接口。
</GlossaryItem>

<GlossaryItem term="可编程阶段">
  在管线中承担清楚输入与输出责任、可以由不同算法实现并接受相同验收的处理阶段。
</GlossaryItem>

<GlossaryItem term="误差预算">
  把几何、可见性、能量、采样噪声和时间误差分配到可观察证据中的计划。
</GlossaryItem>

<GlossaryItem term="复核回放">
  用固定输入、随机种子和记录的参数重新执行实验，使质量或性能差异可以被复核。
</GlossaryItem>

</Glossary>
