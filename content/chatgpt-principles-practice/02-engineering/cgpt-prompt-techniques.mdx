## 核心概念

### 提示工程进阶阶梯

提示技巧由易到难、能力递进：Zero-shot 直接提问，Few-shot 给示范，CoT 引导推理，ToT/ReAct/自洽做多路径探索与工具协作。

<CgptPromptTechniquesDiagram />

### 三大高阶技巧

| 技巧 | 核心思想 | 适用场景 |
|------|----------|----------|
| CoT 思维链 | 引导一步步推理 | 数学/逻辑/多步推理 |
| ReAct | 推理与行动交替 | 需外部工具/知识的任务 |
| 自洽 | 多次采样投票 | 对准确率要求高的推理 |

### 提示工程四原则

- **明确具体**：角色 + 任务 + 约束 + 输出格式
- **结构清晰**：分隔符划分输入、分点列举、模板化
- **引导推理**：复杂任务先拆解再 CoT 逐步推理
- **迭代优化**：改提示 → 测试 → 对比 → 沉淀最佳实践

<Callout type="info">

提示工程是经验学科，没有银弹。系统优化流程：从最简提示开始 → 加角色和格式约束 → 用 Few-shot 示范 → 复杂任务加 CoT → 多组对比测准确率 → 边界 case 测鲁棒性 → 沉淀为模板。复杂任务常组合使用：Few-shot + CoT 既给示范又引导推理。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="Zero-shot">

零样本提示，直接提问不给示例，依赖模型自身能力，适合简单任务和强模型，优点是省 token。

</GlossaryItem>

<GlossaryItem term="Few-shot">

少样本提示，给几个输入输出示例让模型照着格式和模式回答，适合需要特定输出格式的任务。

</GlossaryItem>

<GlossaryItem term="CoT 思维链">

Chain-of-Thought，引导模型「一步步思考」展开中间推理过程，对数学逻辑多步推理效果显著提升。Zero-shot-CoT 用一句魔法提示即可触发。

</GlossaryItem>

<GlossaryItem term="ReAct">

Reasoning + Acting，模型交替进行 Thought 推理、Action 调用工具、Observation 观察结果，循环直至得出答案，是现代 Agent 的基础范式。

</GlossaryItem>

<GlossaryItem term="自洽 Self-Consistency">

同一问题多次采样生成多条推理路径，投票选最常见答案，以算力换准确率，用多样性消除单次采样误差。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

Zero-shot、Few-shot、CoT 三种提示技巧有什么区别？分别适合什么场景？

<Answer>

Zero-shot 直接提问不给示例靠模型能力适合简单任务；Few-shot 给几个示例照着格式模式回答适合需特定输出格式的任务如分类抽取；CoT 引导一步步思考展开中间推理适合数学逻辑多步推理。区别本质：Zero-shot 靠能力，Few-shot 靠示范，CoT 靠推理展开。复杂任务常组合 Few-shot + CoT 既给示范又引导推理。

</Answer>

### 问题 2

ReAct 模式是如何工作的？它解决了什么问题？

<Answer>

ReAct 让模型交替推理和行动：Thought 思考下一步、Action 调用外部工具、Observation 把工具返回结果加入上下文，循环直至得出答案。解决的问题是纯推理模型知识有截止日期不能实时计算不能操作外部系统，ReAct 把外部工具作为模型手眼，能用搜索查最新信息、用计算器精确计算、用 API 操作系统。是现代 Agent 的基础范式。

</Answer>

### 问题 3

自洽（Self-Consistency）的原理是什么？它以什么换什么？

<Answer>

自洽原理：对同一问题用较高温度多次采样生成多条不同推理路径和答案，然后投票选出现次数最多的答案。基于洞察正确答案往往多条路径都能达到而错误答案路径较单一。它以算力换准确率——多采样多推理消耗更多 token 和时间但消除单次采样随机误差，在数学推理上稳定提分。代价是成本和延迟上升，适合对准确率要求高对延迟不敏感的场景。

</Answer>

### 问题 4

提示工程的四原则是什么？如何系统性地优化一个提示？

<Answer>

四原则：明确具体（角色+任务+约束+输出格式）、结构清晰（分隔符分点模板化）、引导推理（复杂任务先拆解再 CoT）、迭代优化（改提示测试对比沉淀）。系统优化流程：从最简提示开始 → 加角色和格式约束 → 用 Few-shot 示范 → 复杂任务加 CoT → 多组对比测准确率 → 边界 case 测鲁棒性 → 沉淀为模板。提示工程是经验学科没有银弹靠迭代逼近最优。

</Answer>

</Exercises>
