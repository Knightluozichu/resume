## 核心概念

### 工具调用让模型长出手脚

大模型本身只能生成文本，无法实时搜索、精确计算、操作外部系统。工具调用通过 Function Calling 让模型能决策「调什么工具、传什么参数」，由应用执行真实操作，把结果回传模型继续推理。

<CgptPluginToolsDiagram />

### Function Calling 流程

| 步骤 | 角色 | 动作 |
|------|------|------|
| 1 | 应用 | 声明可用工具（name/description/parameters） |
| 2 | 模型 | 推理判断调用哪个工具、填充结构化参数 |
| 3 | 应用 | 拿到参数调用真实函数 |
| 4 | 应用 | 把返回值回传模型 |
| 5 | 模型 | 基于结果继续推理或给出最终答案 |

### 工具设计原则

模型选工具完全依赖 description 和 parameters 描述（看不到实现代码）：description 用动词开头说清做什么和适用场景；parameters 用 JSON Schema 写清类型、含义、是否必填、取值范围。工具设计质量直接决定调用成功率。

<Callout type="info">

工具调用循环必须设兜底防止无限循环：设 max_iterations 强制停止、设超时限制单次调用、handle_parsing_errors 处理格式错误、观察结果后给模型明确信号「信息已足够请直接回答」。工程上不能信任模型一定自行终止。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="Function Calling">

模型输出结构化的工具名和参数（而非自由文本），应用据此调用真实函数，再把结果回传模型。结构化输出可靠不翻车，是工具调用的工业标准。

</GlossaryItem>

<GlossaryItem term="工具调用循环">

Thought 推理 → Action 调用工具 → Observation 观察结果 → 继续推理或回答，循环直至信息充足或达上限。

</GlossaryItem>

<GlossaryItem term="JSON Schema">

声明工具参数结构的规范，包含参数名、类型、是否必填、取值范围等，模型据此填充结构化参数。

</GlossaryItem>

<GlossaryItem term="并行工具调用">

一次请求中模型可同时请求多个工具，应用并行执行后一起回传，降低往返延迟。

</GlossaryItem>

<GlossaryItem term="工具沙箱">

工具执行在隔离环境运行，限制权限和资源访问，防止模型被诱导执行危险操作。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

Function Calling 的工作流程是怎样的？它比让模型自己输出文本有什么优势？

<Answer>

流程：应用声明工具（name/description/parameters）→ 用户提问传入模型 → 模型推理输出结构化工具名和参数 → 应用调用真实函数 → 返回值回传模型 → 模型基于结果继续或给最终答案。优势：结构化输出无需正则解析可靠不翻车；模型只决策调什么传什么应用执行职责清晰；参数由 Schema 约束类型安全；支持并行调用降延迟。

</Answer>

### 问题 2

工具调用循环是如何终止的？如何防止无限循环？

<Answer>

终止条件：模型判断信息已充足输出最终答案、达最大迭代次数限制、工具执行出错无重试价值。防止无限循环：设 max_iterations 到上限强制停止、设超时限制单次调用、工具描述清晰减少无意义调用、handle_parsing_errors 处理格式错误、观察结果回传后给模型明确信号信息已足够。工程上必须设兜底不能信任模型一定自行终止。

</Answer>

### 问题 3

设计工具时，工具的 description 和 parameters 为什么至关重要？

<Answer>

模型选工具完全依赖 description 和 parameters 描述因为它看不到实现代码。description 决定模型何时调用必须清晰说明用途适用场景不适用场景，模糊导致误调漏调；parameters 决定模型怎么调用每个参数类型含义是否必填取值范围都要在 JSON Schema 写清。设计原则：description 动词开头说清做什么、参数命名自解释、加 enum 限制取值、必填项标注清楚。工具设计质量直接决定调用成功率。

</Answer>

### 问题 4

构建一个能查天气、订机票、发邮件的助手，工具调用系统如何设计？安全如何保障？

<Answer>

工具：get_weather(location,date)、search_flights(from,to,date)、book_flight(flight_id,passenger)、send_email(to,subject,body)。Agent 用 Function Calling 循环系统提示设助手角色。流程：用户问明天北京天气适合出行帮我订去上海机票 → 模型先调 get_weather → 观察天气好 → 调 search_flights → 选航班 → book_flight 前需用户确认 → 订票后可选 send_email 发凭证。安全：高风险工具加确认环节模型不能擅自执行、参数校验防注入、权限校验只允许操作本人资源、工具执行沙箱隔离、全程日志可审计、敏感操作限频。

</Answer>

</Exercises>
