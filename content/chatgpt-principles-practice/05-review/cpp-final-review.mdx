## 练习题

<Exercises>

### 问题 1

用一句话概括 ChatGPT 从原理到落地的全流程，然后展开解释四个层次。

<Answer>

一句话：ChatGPT 是从 GPT 架构出发，经预训练获得语言能力，用 RLHF 对齐人类偏好，再经推理优化、提示与工具、微调工程化，最终成为可靠线上智能服务的过程。四层：原理层理解 GPT 解码器架构、自回归预训练、缩放律涌现、RLHF 三阶段对齐；工程层掌握 KV 缓存/量化/批处理推理优化和 CoT/ReAct 提示工程；应用层通过 Function Calling 工具调用和 LoRA/QLoRA 微调构建应用；未来层把握多模态、Agent、开源、安全趋势。核心脉络：原理理解定义本质，工程掌握定义效率，应用构建定义场景，未来把握定义方向。

</Answer>

### 问题 2

预训练、对齐、提示、工具、微调五种手段各自解决什么问题？如何组合使用？

<Answer>

预训练解决能力来源问题海量语料自回归学习获通用语言能力产出基座模型；对齐解决行为规范问题 SFT+RM+PPO 让模型听话安全有用；提示解决行为引导问题零成本调行为 CoT 提升推理；工具解决能力边界问题 Function Calling 让模型用外部工具补知识盲区和操作能力；微调解决领域适配问题 LoRA 等把通用模型变领域专家。组合：预训练是地基对齐是必经提示+工具+微调是应用层三件套常组合——提示调即时行为、微调固化风格、工具扩展能力、RAG 补事实。先用提示试不够加 RAG/工具还不够微调。

</Answer>

### 问题 3

从选模型到上生产，ChatGPT 类应用开发的核心决策链是怎样的？

<Answer>

决策链：架构理解选基座（闭源 API vs 开源自部署按能力/成本/隐私权衡）；对齐用现成对齐模型或自己做 SFT/DPO；推理优化 KV 缓存量化连续批处理降本提速选 vLLM/llama.cpp 框架；提示与工具先提示工程调行为需外部能力加 Function Calling 复杂任务用 Agent 循环；微调提示不够再微调 LoRA 起步数据精标优先；评估指标+人工+LLM-Judge；部署服务化限流监控容错；迭代上线后持续收集反馈优化。核心：按需递进能用轻的不上重的。

</Answer>

### 问题 4

设计一个企业智能客服系统的完整方案，涵盖推理优化、RAG、工具调用和微调。

<Answer>

方案：需求 7x24 客服准确回答产品问题支持查订单提工单多轮对话。模型选型开源 Qwen-14B 自部署保隐私或调 GPT-4o-mini 降本。推理优化 vLLM 部署 PagedAttention+连续批处理提吞吐 INT8 量化降显存 SSE 流式输出降延迟。RAG 知识库离线加载产品手册/FAQ 分块向量化存 Chroma 在线检索 Top-10 重排 Top-5 注入提示。工具调用 knowledge_search（RAG 检索）、query_order（查订单 API）、create_ticket（建工单）、transfer_human（转人工）用 Function Calling 高风险操作加确认。微调用 5000 条客服对话精标数据做 LoRA 微调固化客服风格术语。多轮记忆滑动窗口+摘要 Redis 持久化按 session 隔离。安全越狱防御敏感词过滤权限校验审计日志。评估 100 测试题人工标注+LLM-Judge+A/B 测试。迭代上线后持续收集 bad case 补微调数据。

</Answer>
