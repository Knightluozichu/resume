## 直觉引入

想象你是一个工厂老板，需要给不同部门的员工制定工作规范。你可以写一份"岗位说明书"——定义这个岗位需要做什么，但不关心谁来做。这就是**接口**：定义契约，不关心实现。

你也可以设立一个"基础岗位"——它有默认的工作流程，新岗位可以继承它并修改部分步骤。这就是**抽象类**：提供默认实现，子类可以复用或覆盖。

接口像合同——谁都可以签，但一个人可以签多份合同（多实现）。抽象类像血脉——你只能有一个父亲（单继承），但父亲教你的东西可以直接用。

没有接口，C# 的单继承模型将无法表达"一个对象同时具备多种能力"的场景——比如一个类既是可比较的（`IComparable`）又是可处置的（`IDisposable`）。

## 概念讲解

### 接口：纯契约

<Term def="接口（Interface）是 CLR 中的纯契约类型，定义方法签名但不提供实现（C# 8.0 前无默认实现）。一个类可以实现多个接口，但只能继承一个基类。">

接口定义了一组方法、属性、事件的签名。类实现接口时，必须提供所有方法的实现。CLR 允许一个类实现多个接口——这是 C# 单继承模型下实现多态复用的关键机制。接口本身不能实例化，不能有实例字段，不能有构造函数。

</Term>

### 接口 vs 抽象类

<Term def="抽象类（Abstract Class）是可以包含部分实现的基类，不能被实例化。子类继承抽象类时必须实现所有抽象成员。C# 只允许单继承——一个类只能有一个基类。">

核心区别：接口是"能做什么"（has-a 能力），抽象类是"是什么"（is-a 关系）。一个 `FileStream` 既是 `Stream`（是什么，继承），又实现了 `IDisposable`（能做什么，接口）。抽象类可以提供字段、构造函数、默认实现；接口不能（C# 8.0 前完全不能，8.0 后有默认接口方法但语义不同）。

</Term>

### 显式接口实现

当类实现了多个接口且这些接口有同名方法时，可以用**显式接口实现**消除歧义。`void IDisposable.Dispose()` 只能通过接口引用调用，不能通过类引用调用。这隐藏了不需要暴露的接口方法，使公共 API 更干净。

<Stepper>

<Step title="接口定义契约">

`interface IComparable<T>` 定义了 `CompareTo(T other)` 方法签名。任何类型实现此接口都必须提供比较逻辑。接口不关心你怎么比较——它只要求你能比较。CLR 在类型对象中维护接口映射表，将接口方法映射到实际实现。

</Step>

<Step title="接口 vs 抽象类：单继承下的取舍">

C# 只允许单继承（一个基类），但允许多接口实现。如果用抽象类定义"可比较"能力，一个类就不能同时继承其他抽象类了。接口解决了这个问题——`class Student : Person, IComparable<Student>, IDisposable` 同时继承一个基类和实现两个接口。代价是接口不提供字段和构造函数。

</Step>

<Step title="显式接口实现：隐藏不需要的成员">

`class FileManager : IDisposable` 中，`Dispose()` 是清理方法，用户不应主动调用。用显式实现 `void IDisposable.Dispose()` 后，`fm.Dispose()` 编译报错，只能通过 `((IDisposable)fm).Dispose()` 调用。这使公共 API 更干净——用户不会误调用清理方法。多个接口有同名方法时，显式实现也能分别提供不同逻辑。

</Step>

<Step title="默认接口方法（C# 8.0+）">

C# 8.0 允许接口提供默认实现。`interface ILogger { void Log(string msg); void LogError(string msg) => Log($"ERROR: {msg}"); }`。实现类只需提供 `Log`，`LogError` 用默认实现。主要用途是向已有接口添加方法而不破坏现有实现——类似 Java 的 default method。但默认方法只能通过接口引用调用，不能通过类引用调用。

</Step>

</Stepper>

## 代码对照

```csharp
// 接口设计的核心模式

// === 接口定义：纯契约 ===
public interface IComparable<T>
{
    int CompareTo(T other);
}

public interface IDisposable : IDisposable
{
    void Dispose();
}

// === 抽象类：提供部分实现 ===
public abstract class Shape
{
    public abstract double Area();  // 子类必须实现
    public void Print() => Console.WriteLine($"Area: {Area()}");
}

// === 类：继承一个基类 + 实现多个接口 ===
public class Circle : Shape, IComparable<Circle>, IDisposable
{
    public double Radius { get; init; }

    public override double Area() => Math.PI * Radius * Radius;

    // 隐式接口实现
    public int CompareTo(Circle other) => Radius.CompareTo(other.Radius);

    // 显式接口实现：隐藏 Dispose，防止用户误调用
    void IDisposable.Dispose() => Console.WriteLine("Circle disposed");
}

// 使用
var c1 = new Circle { Radius = 3 };
var c2 = new Circle { Radius = 5 };

c1.CompareTo(c2);                       // 隐式：通过类引用调用
((IDisposable)c1).Dispose();            // 显式：必须通过接口引用调用
// c1.Dispose();                        // 编译错误：显式实现不可见

// 接口多态
IComparable<Circle> comp = c1;
comp.CompareTo(c2);                     // 通过接口引用调用
```

显式接口实现 `void IDisposable.Dispose()` 只能通过 `((IDisposable)c1).Dispose()` 调用——这防止了用户在不确定对象是否实现 `IDisposable` 的情况下误调用清理方法。

## 常见误区

<Callout type="trap">

**误区：接口和抽象类可以互相替代**

接口是"能做什么"（能力），抽象类是"是什么"（身份）。用抽象类定义能力会浪费唯一的继承名额——如果你的类需要"可比较"和"可处置"两种能力，用两个抽象类就无法同时实现。接口解决了多能力的问题。反过来，如果需要共享字段、构造函数或大量默认代码，接口做不到——必须用抽象类。两者是互补关系，不是替代关系。

</Callout>

<Callout type="trap">

**误区：显式接口实现是为了「封装」**

显式接口实现的主要目的是**消歧**和**API 清洁**，不是封装。当两个接口有同名方法时，显式实现可以分别提供不同逻辑。当接口方法不属于公共 API 的一部分时（如 `IDisposable.Dispose`），显式实现将其从 IntelliSense 中隐藏。但用户仍然可以通过接口引用调用——这不是真正的封装，只是调用方式的约束。

</Callout>

<Callout type="trap">

**误区：默认接口方法等于抽象类的默认实现**

C# 8.0 的默认接口方法与抽象类的虚方法语义不同。抽象类的虚方法可以被 `override` 覆盖，子类调用 `base.Method()` 可以访问父类实现。默认接口方法不能被 `override`——实现类可以提供新的同名方法"遮蔽"它，但不能用 `base` 调用接口的默认实现。默认方法只能通过接口引用调用，不通过类引用。它的主要目的是向后兼容——给已有接口加方法不破坏旧实现。

</Callout>

<Exercises>

**问题 1**：什么时候应该用接口，什么时候应该用抽象类？

<Answer>

用接口的场景：1. 定义"能力"而非"身份"（如 `IComparable`、`IDisposable`、`IEnumerable`）。2. 类型需要多种能力，但 C# 只允许单继承。3. 需要让不相关的类型共享行为契约（如 `string` 和 `int` 都实现 `IComparable`）。4. 需要支持跨继承树的 多态。

用抽象类的场景：1. 定义"是什么"的 is-a 关系（如 `Stream` → `FileStream`）。2. 需要共享字段、构造函数或大量默认代码。3. 需要提供 `protected` 成员供子类使用。4. 需要控制构造过程（抽象类可以有构造函数）。5. 需要虚方法链（子类调用 `base.Method()`）。

黄金法则：优先用接口定义契约，用抽象类提供默认实现。如果一个能力可以被多种不相关的类型共享，用接口；如果需要共享状态和代码，用抽象类。两者可以结合——抽象类实现接口提供默认实现，子类继承抽象类。

</Answer>

**问题 2**：显式接口实现 `void IDisposable.Dispose()` 和隐式实现 `public void Dispose()` 有什么区别？

<Answer>

区别在于可见性和调用方式：\n\n- 隐式实现 `public void Dispose()`：方法是类的公共成员，可以通过类引用直接调用 `obj.Dispose()`，也会出现在 IntelliSense 中。\n- 显式实现 `void IDisposable.Dispose()`：方法不是类的公共成员，不能通过类引用调用 `obj.Dispose()` 编译报错。只能通过接口引用调用 `((IDisposable)obj).Dispose()`。\n\n显式实现的使用场景：1. 接口方法不属于公共 API（如 `Dispose` 不应被用户主动调用）。2. 多个接口有同名方法，需要分别提供不同逻辑。3. 隐藏不常用的接口方法，保持公共 API 干净。\n\nCLR 实现：显式实现的 方法在类型对象的方法表中有独立的槽位，只能通过接口映射表访问，不在类的公共方法槽中。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="接口（Interface）">

CLR 中的纯契约类型。定义方法、属性、事件的签名但不提供实例字段或构造函数。一个类可以实现多个接口（多接口实现），但只能继承一个基类（单继承）。接口定义"能做什么"的能力契约。

</GlossaryItem>

<GlossaryItem term="抽象类（Abstract Class）">

可以包含抽象成员（无实现）和具体成员（有实现）的基类。不能被实例化。子类必须实现所有抽象成员。C# 只允许单继承——一个类只能有一个基类。抽象类定义"是什么"的身份关系，可以提供字段、构造函数和 protected 成员。

</GlossaryItem>

<GlossaryItem term="显式接口实现">

以 `ReturnType InterfaceName.MethodName()` 形式实现的接口方法。该方法不是类的公共成员，只能通过接口引用调用。用于消歧（多接口同名方法）和 API 清洁（隐藏不属于公共 API 的方法）。

</GlossaryItem>

<GlossaryItem term="默认接口方法（Default Interface Method）">

C# 8.0 引入的特性，允许接口提供方法的默认实现。实现类可以不提供该方法，使用接口的默认实现。主要用途是向后兼容——向已有接口添加新方法不破坏现有实现。默认方法只能通过接口引用调用。

</GlossaryItem>

<GlossaryItem term="接口映射（Interface Mapping）">

类型对象中维护的数据结构，将接口方法映射到类中的实际实现。CLR 通过接口映射表确定接口方法调用的目标地址。显式接口实现的方法在映射表中有独立槽位，不在公共方法槽中。

</GlossaryItem>

</Glossary>
