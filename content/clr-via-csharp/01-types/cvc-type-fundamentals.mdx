## 直觉引入

想象一个巨大的族谱。在这个族谱的最顶端，有一个共同的祖先——`System.Object`。CLR 中的每一个类型，无论是你自己写的 `class Dog` 还是内置的 `int`、`string`，都是这个祖先的后代。这意味着所有类型都共享一组基本能力：比较相等、转为字符串、获取哈希码、获取类型信息。

但族谱不只记录"谁是谁的后代"。每个类型在 CLR 内部都有一个"身份证"——类型对象，里面记载了它的方法清单、字段布局、祖先是谁。你用 `typeof(Dog)` 或 `obj.GetType()` 就是去翻这个身份证。

没有这套类型系统，CLR 无法做方法分派、类型检查、GC 遍历——一切都失去了秩序。

## 概念讲解

### 万物归一：System.Object

<Term def="System.Object 是 CLR 类型系统的根类型，所有类型（包括值类型）最终都派生自它。它定义了 Equals、GetHashCode、ToString、GetType 四个虚方法。">

CLR 规定所有类型都派生自 `System.Object`。这意味着任何对象都能调用 `ToString()`、`Equals()`、`GetHashCode()`、`GetType()`。这四个方法是 `Object` 定义的虚方法，子类可以重写。`GetType()` 是非虚的——你不能欺骗它返回错误的类型，这是类型安全的基石。

</Term>

### 类型对象与方法表

<Term def="类型对象（Type Object）是 CLR 为每个加载的类型创建的内存数据结构，包含方法表（Method Table）、字段布局、基类指针和接口映射。">

每个类型在 CLR 中有一个唯一的类型对象。类型对象存储了：方法表（每个方法的入口地址指针）、字段布局（字段在内存中的偏移量）、基类指针（指向父类型的类型对象）、接口映射（接口方法到实际实现的映射）。所有该类型的实例共享同一个类型对象——实例中有一个指针指向它，这叫"类型指针"（Type Handle）。

</Term>

### 运行时类型识别

`typeof(T)` 在编译期返回类型对象引用（静态已知类型）。`obj.GetType()` 在运行时返回对象的实际类型对象（动态类型）。`obj is T` 检查对象是否兼容类型 T（遍历继承链）。`obj as T` 尝试转型，失败返回 `null`（不抛异常）。这些操作都依赖类型对象中的继承链信息。

## 交互Demo

<CvcTypeFundamentalsDiagram />

<Stepper>

<Step title="继承层次：万物派生自 Object">

`class Dog : Animal`，`class Animal : Object`。CLR 的继承链从 Dog 开始，沿着基类指针一路向上：Dog → Animal → Object。`GetType()` 返回 Dog 的类型对象，`is Animal` 返回 `true`，因为遍历继承链能找到 Animal。所有类型最终都到达 Object——这是 CLR 类型安全的统一根基。

</Step>

<Step title="类型对象：方法的「通讯录」">

每个类型对象有一张方法表——类似通讯录，记录了每个方法的入口地址。调用 `dog.Bark()` 时，CLR 先通过 dog 的类型指针找到 Dog 的类型对象，再在方法表中查找 `Bark` 的地址，然后跳转执行。虚方法的多态分派就是查方法表——如果 Dog 重写了 Animal 的 `Speak()`，方法表中 `Speak` 指向 Dog 的实现。

</Step>

<Step title="GetType vs typeof：动态 vs 静态">

`typeof(Dog)` 在编译期确定，直接返回 Dog 的类型对象。`obj.GetType()` 在运行时通过对象的类型指针获取——即使 `Animal a = new Dog()`，`a.GetType()` 返回 Dog 而非 Animal。GetType 是非虚方法，无法被重写，保证返回的永远是对象的实际类型。

</Step>

<Step title="is 与 as：安全转型的两种方式">

`obj is T` 遍历继承链检查兼容性，返回 bool。`obj as T` 做同样的检查，成功返回转型后的引用，失败返回 `null`。`(T)obj` 直接转型，失败抛 `InvalidCastException`。`is` 用于条件判断，`as` 用于安全转型（但只能用于引用类型和可空值类型），强制转型 `(T)` 用于确定一定能成功或有异常处理的情况。

</Step>

</Stepper>

## 代码对照

```csharp
// CLR 类型系统基础

// 所有类型派生自 System.Object
public class Animal
{
    public string Name { get; init; }
    public virtual void Speak() => Console.WriteLine($"{Name} makes a sound");
}

public class Dog : Animal
{
    public override void Speak() => Console.WriteLine($"{Name} says Woof");
}

// typeof：编译期获取类型对象
Type dogType = typeof(Dog);        // Dog 的类型对象
Type animalType = typeof(Animal);  // Animal 的类型对象
Type objectType = typeof(object);  // Object 的类型对象

// GetType：运行时获取实际类型
Animal a = new Dog { Name = "Rex" };
Type actualType = a.GetType();     // Dog（不是 Animal！）
Console.WriteLine(actualType == dogType);  // True

// is：检查兼容性（遍历继承链）
bool isAnimal = a is Animal;       // True
bool isObject = a is object;       // True（万物皆是 object）
bool isCat = a is Cat;             // False

// as：安全转型
Dog d = a as Dog;                  // 成功，d 不为 null
Cat c = a as Cat;                  // 失败，c 为 null（不抛异常）

// 强制转型：失败抛异常
Dog d2 = (Dog)a;                   // 成功
// Cat c2 = (Cat)a;               // 抛 InvalidCastException
```

`GetType()` 返回 `Dog` 而非 `Animal`——它读取的是对象头部的类型指针，指向实际创建时的类型对象。这是多态的基础：对象知道自己是什么类型，不受声明类型的限制。

## 常见误区

<Callout type="trap">

**误区：`typeof(T)` 和 `obj.GetType()` 总是返回相同结果**

`typeof(T)` 返回编译期声明的类型，`obj.GetType()` 返回运行时实际类型。当声明类型是父类、实际对象是子类时（`Animal a = new Dog()`），`typeof(Animal)` 返回 Animal，`a.GetType()` 返回 Dog。在泛型中 `typeof(T)` 返回泛型参数绑定的类型——如果 T 是 Animal，返回 Animal。

</Callout>

<Callout type="trap">

**误区：`as` 可以用于所有类型转换**

`as` 只能用于引用类型和可空值类型（`int?`）。对于不可空值类型（如 `int`、`struct`），`as` 无法使用——因为转型失败时需要返回 `null`，而值类型不能为 `null`。值类型转换必须用 `is` 检查后再强制转型：`if (obj is int val) { ... }`（C# 7+ 模式匹配语法）。

</Callout>

<Callout type="trap">

**误区：值类型不继承自 Object**

值类型（`int`、`struct`）确实继承自 `System.ValueType`，而 `ValueType` 继承自 `Object`。所以值类型也最终派生自 Object，也可以调用 `ToString()`、`Equals()` 等。但值类型在内存布局上与引用类型不同——不需要类型指针（因为编译期类型已知），装箱后才获得引用类型的完整头部。

</Callout>

<Exercises>

**问题 1**：`Animal a = new Dog();` 后，`a.GetType()` 返回什么？为什么不是 `Animal`？

<Answer>

返回 `Dog`。`GetType()` 是非虚方法，它直接读取对象内存头部的类型指针（Type Handle）。对象在创建时（`new Dog()`），类型指针就被设为 Dog 的类型对象。声明类型 `Animal` 只是编译期的静态类型，不影响运行时的类型指针。这就是为什么 `GetType()` 总是返回对象的实际创建类型——它是 CLR 类型安全的基石，无法被欺骗。

</Answer>

**问题 2**：`is`、`as`、强制转型 `(T)` 三者有什么区别？分别在什么场景下使用？

<Answer>

三者的区别在于检查方式和失败行为：\n\n- `obj is T`：遍历继承链检查兼容性，返回 `bool`。不修改 `obj`。用于条件判断——只需要知道是否兼容，不需要转型后的引用。\n- `obj as T`：遍历继承链检查兼容性，成功返回转型后的引用，失败返回 `null`。不抛异常。用于引用类型的"尝试转型"——后续需要检查 `null`。只能用于引用类型和可空值类型。\n- `(T)obj`：直接强制转型，CLR 检查类型兼容性，失败抛 `InvalidCastException`。用于确定一定能成功（或有异常处理）的场景。值类型必须用这种方式。\n\nC# 7+ 推荐用模式匹配：`if (obj is Dog d) { d.Bark(); }`——一步完成检查和转型，代码更简洁。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="System.Object">

CLR 类型系统的根类型。所有类型（包括值类型通过 `System.ValueType`）最终都派生自它。定义了四个核心方法：`Equals`（相等比较）、`GetHashCode`（哈希码）、`ToString`（字符串表示）、`GetType`（运行时类型）。`GetType` 是非虚方法，无法被重写。

</GlossaryItem>

<GlossaryItem term="类型对象（Type Object）">

CLR 为每个加载的类型创建的内存数据结构。包含方法表（方法入口地址）、字段布局、基类指针、接口映射。所有同类型的实例共享同一个类型对象。`typeof(T)` 和 `GetType()` 返回的就是类型对象的引用。

</GlossaryItem>

<GlossaryItem term="方法表（Method Table）">

类型对象中的核心数据结构，记录了该类型所有方法的入口地址。方法调用时，CLR 通过类型指针找到类型对象，在方法表中查找方法地址。虚方法分派就是查方法表——子类重写的方法在方法表中指向子类实现。

</GlossaryItem>

<GlossaryItem term="类型指针（Type Handle）">

每个引用类型实例的内存头部都有一个类型指针，指向其类型对象。`GetType()` 就是通过读取这个指针获取实际类型的。这是 CLR 运行时类型识别的基础——对象永远知道自己是什么类型。

</GlossaryItem>

<GlossaryItem term="转型（Casting）">

将一个类型的引用当作另一个类型使用。向上转型（子类→父类）总是安全的，不需要检查。向下转型（父类→子类）需要运行时检查——CLR 遍历继承链确认兼容性。`is` 返回检查结果，`as` 返回转型引用或 null，强制转型 `(T)` 失败时抛异常。

</GlossaryItem>

</Glossary>
