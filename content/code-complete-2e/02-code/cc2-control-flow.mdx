## 学习目标

- 掌握布尔表达式的简化方法和最佳实践
- 理解不同控制结构的适用场景和选择指南
- 学会用卫语句重构深层嵌套的控制结构
- 理解控制流复杂度的度量和管理方法

## 核心概念

### 布尔表达式简化原则

复杂的布尔表达式是代码可读性的杀手。简化方法：

- **拆分复杂条件**：将复杂布尔表达式拆为命名布尔函数或中间布尔变量
- **利用德摩根律**：not(A and B) = not A or not B，转换为更易读的形式
- **括号明确优先级**：不依赖运算符优先级记忆，用括号显式分组消除歧义
- **肯定式表达**：用 isFound 而非 isNotFound，正向更易理解

### 控制结构选择指南

- **if-else**：正常情况放 if 分支，异常放 else，最常见情况在前，先处理后返回
- **case/switch**：按频率排序（高频放前面），必须有 default 分支
- **循环**：计数循环用 for，条件循环用 while，至少一次用 do-while
- **表驱动法**：用查表替代复杂条件分支，数据驱动逻辑，是最优雅的选择

核心原则：选择语义最匹配场景的结构，让代码意图自然表达。

### 嵌套控制结构简化

深层嵌套的问题：认知负担高、圈复杂度高、修改风险大。

**卫语句重构**：将深层嵌套的 if-if-if 结构改为先检查异常条件并提前返回：

```
// 深层嵌套（避免）
if (A) {
    if (B) {
        if (C) {
            doSomething()
        }
    }
}

// 卫语句（推荐）
if (!A) return
if (!B) return
if (!C) return
doSomething()
```

重构策略：用 if-then-else 替代嵌套、用 break/return 提前退出、用多态替代类型判断。

### 控制流复杂度管理

- **圈复杂度**：衡量独立路径数，每函数建议不超过 10
- **嵌套深度**：建议不超过 3-4 层
- **路径覆盖**：测试需覆盖所有分支
- **避免 goto**：用结构化控制替代跳转

控制流复杂度直接决定可维护性和可测试性，保持低复杂度是代码质量的基石。

## 术语表

- **德摩根律（De Morgan's Law）**：布尔表达式转换规则，not(A and B) = not A or not B
- **卫语句（Guard Clause）**：先检查异常条件并提前返回，使正常逻辑扁平化
- **表驱动法（Table-Driven Method）**：用查表替代复杂条件分支的编程技术
- **圈复杂度（Cyclomatic Complexity）**：衡量函数独立路径数的度量指标
- **嵌套深度（Nesting Depth）**：控制结构的嵌套层数
