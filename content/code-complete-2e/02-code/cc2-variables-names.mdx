## 核心概念

### 变量初始化原则

未初始化变量是常见的缺陷来源。三个初始化原则：

- **就近初始化**：在声明处或首次使用前立即初始化，避免使用未定义值
- **使用前确认**：使用变量前检查是否已正确初始化，做防御式检查
- **重置注意**：在循环或函数重入时需重新初始化，避免残留状态影响

### 变量作用域与持续性

**作用域**指变量的可见范围，**持续性**指变量存活的时间跨度。

作用域原则：
- 缩小变量作用域到最小可见范围
- 缩短变量存活时间（span），赋值与最后使用间越近越好
- 变量声明与使用越近越好
- 循环变量在循环内初始化
- 避免全局变量

持续性原则：
- 持续性越短越好，减少状态依赖
- 跨函数变量需明确生命周期
- 绑定时间越晚越灵活

核心规律：**作用域越小 → 错误越少；持续性越短 → 可维护性越高**。

### 命名规范与最佳实践

**变量命名**：完全准确描述变量代表什么；作用域越大名字越长越详细；计算限定词放末尾（如 totalRevenue 而非 revenueTotal）。

**循环变量**：简单循环用 i/j/k；嵌套循环用更有意义的名字；避免用 i 做非循环计数用途。

**布尔命名**：用 done/error/found/success 等肯定式命名；避免否定式（如 notFound 不佳）。

**命名约定**：统一团队约定；驼峰/下划线一致；不与语言冲突；**一致性最重要**。

### 常见命名问题

- **误导性名字**：data 处理不只数据
- **无意义名字**：x1/temp/foo 无信息量
- **近似名字**：user/users/userInfo 混淆
- **魔法数字**：用命名常量 MAX_RETRIES 替代硬编码 3

## 术语表

- **作用域（Scope）**：变量的可见范围
- **持续性（Persistence/Lifetime）**：变量存活的时间跨度
- **绑定时间（Binding Time）**：变量与值关联的时刻，越晚越灵活
- **命名约定（Naming Convention）**：团队统一的变量命名规则
- **魔法数字（Magic Number）**：代码中硬编码的数值，应用命名常量替代
