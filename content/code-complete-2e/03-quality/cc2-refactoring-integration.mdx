## 学习目标

- 理解代码重构的原因和时机
- 掌握重构的五个层次及各层次策略
- 理解分阶段集成与增量式集成的区别和优劣
- 掌握持续集成的核心实践及其与重构的配合

## 核心概念

### 重构的原因与时机

重构是改善代码内部结构而不改变外部行为的过程。常见原因：

- **代码重复**：相同逻辑多处出现，应提取公共方法
- **函数过长**：超百行难理解，职责不单一，应拆分
- **深层嵌套**：圈复杂度过高，应用卫语句扁平化
- **类设计差**：高耦合低内聚，应重新设计接口

### 重构策略与方法

重构分五个层次，从低到高：

- **数据级重构**：用常量替代魔法数、重命名变量、简化表达式
- **语句级重构**：分解布尔表达式、用卫语句替代嵌套、简化控制流
- **函数级重构**：提取/内联函数、移动函数到合适类、参数对象化
- **类级重构**：提取/内联类、隐藏委托、用多态替代条件分支
- **系统级重构**：引入设计模式、重新划分子系统、大规模重组

原则：从低层开始，小步重构，每步验证，保持代码始终可运行。

### 集成方式对比

**分阶段集成（传统）**：先开发所有模块再在项目后期一次性集成。问题集中爆发难定位，风险推迟到最后。

**增量式集成（推荐）**：小块开发小块集成，每次集成少量代码。优势：
- 问题早期暴露易定位
- 持续验证系统可运行
- 风险分散到多次小集成
- 反馈快速

增量式集成将大风险分解为小风险，符合「越早发现缺陷成本越低」原则。

### 持续集成核心实践

- **频繁集成**：每天至少一次，小步提交
- **自动化构建**：一键编译打包，消除手动错误
- **自动化测试**：每次构建运行测试套件，确保不回归
- **构建管线**：编译+测试+部署流水线化
- **快速反馈**：分钟级回归结果

**与重构的配合**：持续集成的自动化测试为重构提供安全网，频繁集成鼓励小步重构，快速反馈让重构更大胆。三者形成良性循环：重构改善设计 + 增量集成降低风险 + 持续集成保证质量 = 可演进的代码库。

## 术语表

- **重构（Refactoring）**：改善代码内部结构而不改变外部行为
- **增量式集成（Incremental Integration）**：小块开发小块集成的策略
- **持续集成（Continuous Integration, CI）**：频繁集成并通过自动化构建和测试验证
- **构建管线（Build Pipeline）**：编译+测试+部署的自动化流水线
- **提取函数（Extract Function）**：将代码段提取为独立函数的重构手法
