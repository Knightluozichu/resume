## 核心概念

### 科学调试流程

调试不是随意的试错，而是系统性的科学方法。五步流程：

1. **稳定重现**：找到可靠复现错误的方法
2. **定位根源**：通过假设/实验/观察找到真正根因
3. **修复缺陷**：修正错误代码，解决根源问题
4. **验证修复**：确认问题已解决且未引入新问题
5. **查找类似错误**：同根源问题一并修复

核心原则：**理解优于速度**——先完全理解缺陷原因再修复。

### 调试方法与心态

- **科学方法**：假设 → 实验 → 观察，系统性排除可能原因
- **二分查找**：逐步缩小范围，注释/禁用代码段，二分定位问题
- **工具辅助**：调试器断点、日志/跟踪、性能分析器，用工具不猜
- **正确心态**：接受缺陷是正常的，不急于修复，先理解再修正

科学方法优于试错：每个实验都排除一组假设，逐步逼近根因，效率高且可靠。

### 性能调优策略

**调优原则**：
- 先测量再优化（用数据说话）
- 优化热点（80/20 法则）
- 先正确再快速（不要过早优化）
- 先设计再调优（好设计自然高效）
- 保留可读性（不牺牲维护性换性能）

**调优层次**（从高到低）：
1. 程序结构：算法/数据结构选择（影响最大）
2. 模块设计：减少不必要的工作
3. 函数内：逻辑简化/短路求值
4. 语句级：循环展开/缓存
5. 机器级：编译器优化/内联

### 代码调优具体技术

- **算法优化**：换更高效算法（如 O(n) → O(log n)）
- **数据结构**：选择合适结构（哈希表/树）
- **缓存记忆**：存储重复计算结果
- **循环优化**：减少循环内工作
- **逻辑优化**：短路求值/提前退出

## 术语表

- **科学调试（Scientific Debugging）**：用假设-实验-观察方法系统性定位缺陷
- **二分查找调试（Bisection Debugging）**：逐步缩小问题范围的调试方法
- **性能分析器（Profiler）**：测量程序性能瓶颈的工具
- **80/20 法则（Pareto Principle）**：80% 的执行时间花在 20% 的代码上
- **过早优化（Premature Optimization）**：在未测量基础上过早进行性能优化
- **缓存记忆（Memoization）**：存储计算结果避免重复计算的技术
