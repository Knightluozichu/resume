<Objectives>

- 能从表目录定位表号、变量定义、单位、样本、版本与比较口径。
- 能判断两个数值是否真的可比，并在分母、年份或项目规模不同的时候拒绝结论。
- 能用正常、边界、故障和复位四条轨迹重建一项定量判断，保留计算和证据。

</Objectives>

## 为什么需要这一机制

表目录不是数字的索引，而是比较合同的入口。一个表格中的百分比、平均值或趋势只有在变量定义、单位、分母、样本、时间和版本一致时才支持比较。先找到表号，再核对口径，最后才允许把差异写成工程判断。

## 先避开三个表格误区

<Callout type="trap" title="误区一：数值差异就是因果差异">
  现象 → 看到更大的数字就下结论。原因 → 分母、样本或观察窗口不同。修法 → 在比较前写清变量、单位和分母。
</Callout>

<Callout type="trap" title="误区二：表号能替代表头">
  现象 → 只记录“见表 3-2”，不记录定义和版本。原因 → 读者无法重建数据口径。修法 → 把表号、标题、变量、样本和来源一起保存。
</Callout>

<Callout type="trap" title="误区三：重新计算就能修复不一致">
  现象 → 用公式掩盖不同年份或规模。原因 → 输入已经不可比。修法 → 先拒绝比较，补齐口径后再计算。
</Callout>

## 核心合同与操作术语

可比性要求：变量定义相同、单位相同、分母相同、样本和观察窗口可解释。<Term def="让读者定位原始表格及其上下文的编号、标题和来源">表号</Term>是入口，不是结论；<Term def="说明每一列或每一行代表什么、怎样采集和计算">变量定义</Term>决定数字表示的对象。

<Term def="数值的计量单位、分母、样本和观察窗口">单位与样本</Term>决定能否比较；<Term def="数据产生时的软件版本、年份、配置和筛选口径">版本口径</Term>防止把不同条件拼在一起；<Term def="在口径一致后由数据、计算和边界共同支持的工程决定">定量判断</Term>才是最终产物。

## 目录节点逐项深读

### 表目录

表目录的工程任务是把表格定位接到可复查比较。先记录表号和来源，再复制变量定义、单位、分母、样本、年份和版本；只有这些条件一致，才允许计算差异或趋势。若条件不一致，正确产物是拒绝理由和补数计划，而不是一个看似精确的百分比。

## 最小可重放实现

~~~text
left = read_table(table_id, definition, unit, sample, version)
right = read_table(other_id, definition, unit, sample, version)
assert comparable(left, right)
result = compare(left, right)
record(result, inputs, formula, boundary)
reset()
assert replay(inputs) == result
~~~

正常轨迹确认两个表可比；边界轨迹改变分母或观察窗口；故障轨迹注入不同年份或项目规模；复位轨迹恢复原始输入并重新计算。不能比较时，拒绝本身就是有效的工程结论。

## 先预测，再操作证据实验

先预测表号、口径或样本改变后哪一个节点会先变化，再只切换一个场景。组件中的数值链是教学模型，不代表任何真实项目的统计结果。

## 练习与答案

<Exercises>

**问题 1：判断可比性。** 两张表都报告“缺陷率”，但一张用每千行代码，另一张用每个功能点。你会怎么处理？

<Answer>
  先拒绝直接比较，记录变量定义和分母不同；只有取得共同口径或给出可靠转换依据后才计算。若不能转换，产物应是不可比说明，而不是平均两个百分比。
</Answer>

**问题 2：补齐表格证据。** 一位同事只给出“表 4-1 显示新版本更快”。请列出至少四个需要追问的字段。

<Answer>
  追问表号上下文、速度变量和单位、样本与分母、软件版本与配置、观察窗口和计算方法。补齐后再判断差异是否足以支持“更快”。
</Answer>

**问题 3：设计复位。** 重新计算后发现结果变好，但输入版本也被改了。如何诊断？

<Answer>
  从原版本和原输入恢复基线，只改变计算方法或一个指定条件；记录首个偏离，分别比较正常、边界和故障结果。若仍需改版本，应把它作为另一项实验，而不是覆盖原结论。
</Answer>

</Exercises>

## 本页小结

表目录的正确顺序是定位表号、核对定义、统一单位与样本、固定版本口径，最后才做定量判断。数据无法比较时，清楚记录拒绝理由比制造一个精确数字更可靠。
