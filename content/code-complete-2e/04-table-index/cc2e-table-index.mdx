## 为什么需要这一机制

表目录 解决的不是一个可背诵口号，而是从 **表格数值即结论** 到 **口径一致后再做定量判断** 的可观察变化。它的核心机制是：表目录用于核对表号、变量定义、单位、样本、版本和比较口径，再决定表中差异是否支持结论。

学习 表目录 时先预测 问题、表格定位、口径核对、数据比较、决策引用 的输入与输出，再改变一个直接条件。最终结果即使看似正确，只要中间状态违反合同、故障不能隔离或重置不能回到同一基线，本页结论就不通过。

### 表目录

在 **表目录** 中，目录节点 **表目录** 落在“问题”检查点。这里的技术含义是：把“表目录”放回 表目录用于核对表号、变量定义、单位、样本、版本和比较口径，再决定表中差异是否支持结论；它影响“表号”时，必须同时声明对象、输入、状态、输出和适用边界，不能用标题出现代替解释。

## 故障诊断与误区

<Callout type="trap" title="误区：直接比较不同分母、年份或项目规模的数据">
  这个错误会让 表目录
  无法从“表格数值即结论”稳定推进到“口径一致后再做定量判断”。诊断沿 问题 →
  表格定位 → 口径核对 → 数据比较 → 决策引用
  前进，只在第一次出现预期与实际不一致的节点停下，不用最终症状倒猜原因。
</Callout>

<Callout type="trap" title="误区：一个指标可以代替全部证据">
  表目录
  的单一数值可能被样本、缓存、默认值、测量窗口或偶然次序掩盖。至少同时保存机制轨迹、边界结果、故障拒绝和复位重放，任何一项缺失都不能用平均分补偿。
</Callout>

<Callout type="tip" title="恢复顺序">
  表目录 的恢复顺序是：还原输入和环境，清理派生状态，重建 表格定位，重跑
  口径核对，核对 决策引用，再注入同一故障确认拒绝可重复。
</Callout>
