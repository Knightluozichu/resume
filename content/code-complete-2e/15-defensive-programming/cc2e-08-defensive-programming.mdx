## 为什么需要这一机制

第8章：防御式编程 解决的不是一个可背诵口号，而是从 **相信所有调用者和输入** 到 **错误在最近边界被拒绝或隔离** 的可观察变化。它的核心机制是：防御式编程在信任边界验证外部数据，在内部用断言暴露不可能状态，并为错误、异常和恢复定义一致策略。

学习 第8章：防御式编程 时先预测 外部输入、边界校验、内部断言、错误隔离、安全结果 的输入与输出，再改变一个直接条件。最终结果即使看似正确，只要中间状态违反合同、故障不能隔离或重置不能回到同一基线，本页结论就不通过。


## 核心合同

$$
safe\ result=validate(input)\land preserve(invariant)\land contain(failure)
$$

第8章：防御式编程 的合同变量必须绑定到同一版本、同一输入、同一单位和同一观察窗口。先由合同推出预期，再观察 内部断言 与 安全结果；如果只是修改阈值来迎合结果，实验失去裁决能力。
