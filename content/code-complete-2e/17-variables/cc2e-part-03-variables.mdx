## 为什么需要这一部分

变量是程序中最小但最常见的状态边界。一个名字暗示对象，一个初值决定起点，一个作用域决定谁能改变它，一个生命周期决定旧状态何时失效；任何一个条件含糊，读者都要靠记忆猜测。把变量当成可观察合同，能减少隐藏状态和误用。

## 先避开三个变量误区

<Callout type="trap" title="误区一：声明了就代表有有效值">
  现象 → 变量能编译就使用。原因 → 初始化时机和无效状态没有定义。修法 → 写出初值、可为空条件和读取前置条件。
</Callout>

<Callout type="trap" title="误区二：短名字总是更清晰">
  现象 → 用 i、tmp 或 data 表示多个不同概念。原因 → 语义被上下文之外的记忆承担。修法 → 名称表达稳定意图，必要时用类型和注释补边界。
</Callout>

<Callout type="trap" title="误区三：大作用域方便复用">
  现象 → 状态跨越许多函数和时间。原因 → 读者无法追踪写入者与生命周期。修法 → 缩小可见范围，保留明确的输入输出。
</Callout>

## 目录节点逐项深读

### 第3部分 变量

本部分的阅读合同是：每个变量都能说明表示什么、什么时候有值、谁可以修改、何时失效。若一个变量承担多个含义，应拆分或显式建模；若作用域过大，应先记录写入路径再收缩。

## 最小可重放实现

~~~text
intent = state_variable_contract(object, unit, invariant)
value = initialize_before_read(intent)
name = choose_unambiguous_name(intent)
scope = restrict_visibility(name)
trace = replay_lifecycle(scope, normal, boundary, fault)
record(trace, firstDeviation, resetResult)
~~~

正常轨迹确认读写合同；边界轨迹使用空值、最大值或最后一次状态；故障轨迹读取未初始化值或复用含义；复位轨迹从新实例确认生命周期回到同一基线。

## 先预测，再操作证据实验

先预测修改初始化、命名或作用域后哪一个节点会先变化，再只切换一个场景。组件是变量合同的教学模型，不是某种语言的完整静态分析器。

## 练习与答案

<Exercises>

**问题 1：改写变量。** “data”在函数中先表示请求体、后来表示缓存结果，如何修订？

<Answer>
  把两个意图拆成不同变量，并用名称、类型或结构表达请求体与缓存结果；分别规定初始化、写入者和生命周期，再对两条路径重放。
</Answer>

**问题 2：缩小作用域。** 一个计数器被多个函数共享，如何判断它能否局部化？

<Answer>
  先追踪所有读取和写入，写出不变量和生命周期；如果只有一条调用链需要它，就把状态放入最小作用域并用参数或返回值传递，最后补边界回归。
</Answer>

**问题 3：诊断初始化。** 代码在正常输入通过，但空输入时使用了旧值。首个偏离在哪里？

<Answer>
  首个偏离在初始化或生命周期合同：空输入没有明确清理或拒绝，旧状态越过了观察窗口。恢复干净实例，固定空输入，记录预期拒绝或默认值，再重放。
</Answer>

</Exercises>

## 本页小结

变量质量来自可预测状态：明确意图，保证初始化，选择低歧义名称，限制作用域，并管理生命周期。正常路径不能掩盖旧值和越界状态；只有从干净基线重放，变量合同才可信。
