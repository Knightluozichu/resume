<Objectives>

- 能从语句目标写出顺序、分支、循环、异常和状态结果。
- 能为每条控制流说明输入、覆盖条件、终止条件和失败路径。
- 能通过边界与故障重放发现隐藏分支，并让另一位实践者解释同一控制流。

</Objectives>

## 为什么需要这一部分

语句把意图变成执行顺序。真正难的不是记住语法，而是让读者知道条件何时成立、循环何时终止、异常如何传播，以及状态在每一步怎样变化。只测正常路径会把未覆盖的分支伪装成稳定。

## 先避开三个控制流误区

<Callout type="trap" title="误区一：能运行就说明分支正确">
  现象 → 只用一个正常输入。原因 → 条件空间和异常路径没有写出。修法 → 为每个分支记录触发条件和证据。
</Callout>

<Callout type="trap" title="误区二：循环有递增就一定会终止">
  现象 → 忽略空集合、上限和不变量。原因 → 终止条件没有成为合同。修法 → 写出最小、最大和不收敛输入。
</Callout>

<Callout type="trap" title="误区三：异常是调用者的问题">
  现象 → 只抛出错误，不说明状态和恢复。原因 → 失败路径未被建模。修法 → 记录异常输入、首个偏离和复位动作。
</Callout>

## 核心合同与操作术语

<Term def="语句要改变的对象、状态或可观察结果">语句目标</Term>决定动作；<Term def="语句按什么先后读取、修改和返回状态">顺序</Term>决定因果。<Term def="输入满足何种条件时选择哪条路径">条件</Term>定义分支；<Term def="重复执行的前置条件、不变量和终止条件">循环</Term>约束重复；<Term def="失败输入如何改变状态、传播信息并恢复">异常状态</Term>把拒绝路径接到验收。

## 目录节点逐项深读

### 第4部分 语句

本部分的阅读合同是：先声明语句目标，再画出顺序、条件和循环，最后说明异常与状态。控制流的每一条边都应能由输入触发，也应能被测试或复查。

## 最小可重放实现

~~~text
baseline = freeze(input, version, expectedState)
trace = execute_sequence_condition_loop(baseline)
trace += execute_boundary_and_fault(baseline)
record(firstDeviation, terminalState, recovery)
reset()
assert replay(baseline) == baseline.trace
~~~

正常轨迹验证目标；边界轨迹使用空集、恰好值和最大值；故障轨迹触发异常或不满足前置条件；复位轨迹确认状态不会从上一条路径泄漏。

## 先预测，再操作证据实验

先预测顺序、条件、循环或异常状态改变后哪个节点会先变化，再只切换一个场景。专属面板是控制流证据链，不是编译器的完整分析。

## 练习与答案

<Exercises>

**问题 1：补齐分支。** 一段代码只测试成功响应，如何设计最小边界集？

<Answer>
  保留一个正常响应，再加入空结果、恰好阈值、超过阈值和失败响应；为每条路径写预期状态、返回值和恢复动作，并记录首个偏离。
</Answer>

**问题 2：检查循环。** 如何证明一个循环不会在空输入时访问无效元素？

<Answer>
  写出循环不变量、空集合前置条件和终止条件，使用空集合、一个元素和上限输入重放；若不变量无法成立，就先修正控制流。
</Answer>

**问题 3：处理异常。** 异常抛出后共享状态仍被修改，如何复位？

<Answer>
  固定故障输入，记录异常前最后一个有效状态和首个非法写入；让操作具备回滚或隔离，重置实例后再次执行并验证状态一致。
</Answer>

</Exercises>

## 本页小结

可靠语句把目标、顺序、条件、循环和异常状态连成可重放控制流。正常路径只是起点；边界、故障和复位证据才能说明分支和终止条件真的成立。
