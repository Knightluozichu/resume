## 为什么需要这一机制

第16章：控制循环 解决的不是一个可背诵口号，而是从 **重复执行某段代码** 到 **边界与终止都能推导** 的可观察变化。它的核心机制是：循环用初始化、继续条件、不变量、进展量和退出后置条件建立证明，并对零次、一次、末端和越界邻域测试。

学习 第16章：控制循环 时先预测 循环前状态、进入条件、单次不变量、退出条件、循环后状态 的输入与输出，再改变一个直接条件。最终结果即使看似正确，只要中间状态违反合同、故障不能隔离或重置不能回到同一基线，本页结论就不通过。

## 故障诊断与误区

<Callout type="trap" title="误区一：只测循环体内部的正常值">
  现象 → 正常列表通过，空列表或恰好末端时结果不稳定。 原因 → 测试没有覆盖零次、一次和越界一步。 修法 → 先写边界表，再逐项记录进入条件、访问索引和退出后状态。
</Callout>

<Callout type="trap" title="误区二：把进展量留给读者猜">
  现象 → 循环体看似执行了工作，却可能永远不退出。 原因 → 继续条件和状态更新分散，没人能指出每次迭代如何靠近出口。 修法 → 明确命名进展量，并断言它每次迭代都向退出条件移动。
</Callout>

<Callout type="trap" title="误区三：用改阈值掩盖错误边界">
  现象 → 把比较符改到样例通过，却无法解释最后一个元素和空集合。 原因 → 修复迎合了结果，没有先重建循环合同。 修法 → 固定输入与版本，分别验证初始化、守卫、不变量、进展量和后置条件。
</Callout>

第16章：控制循环 的六个操作术语是 <Term def="进入循环前，输入、索引和资源已经被明确记录的基线状态">循环前状态</Term>、<Term def="每次循环体开始和结束时都必须保持的可检查条件">循环不变量</Term>、<Term def="决定本轮是否继续执行的布尔或边界判断">继续条件</Term>、<Term def="每次迭代都应向退出条件移动的状态变化">进展量</Term>、<Term def="循环停止后必须成立的结果条件">循环后状态</Term> 和 <Term def="最小值、最大值、空集合与越界一步等容易暴露错误的输入位置">端点</Term>。每个术语都能指向实验控件、节点或状态文本；若只能指向目录标题，说明解释和验证仍未完成。


## 本页小结

第16章：控制循环 的完成标准是能解释“循环用初始化、继续条件、不变量、进展量和退出后置条件建立证明，并对零次、一次、末端和越界邻域测试”，用核心合同推出预期，沿五个专属节点观察实际，诊断“索引与集合长度错一位，或循环体不保证向退出条件推进”，并证明复位后同一输入重建基线轨迹。

<Glossary>

<GlossaryItem term="循环前状态">
  进入第一次判断前已经确定的输入集合、索引起点、资源和版本；它是重放实验的基线。
</GlossaryItem>

<GlossaryItem term="循环不变量">
  每次迭代前后都必须成立的条件，例如索引始终落在已处理前缀之后且不超过集合长度。
</GlossaryItem>

<GlossaryItem term="继续条件">
  决定循环体是否再次执行的判断；它必须说明零次执行和边界停止的结果。
</GlossaryItem>

<GlossaryItem term="进展量">
  每次迭代都会改变、并且朝退出条件移动的量，如索引递增或剩余任务减少。
</GlossaryItem>

<GlossaryItem term="循环后状态">
  退出时可检查的结果，包括最终索引、已处理数据和后置条件，而不是一句“循环结束了”。
</GlossaryItem>

<GlossaryItem term="端点">
  空集合、单元素、最后一个合法值和越界一步等最容易揭示边界错误的输入位置。
</GlossaryItem>

</Glossary>

<Exercises>

1. 对空集合、单元素集合和三元素集合，分别写出 `for (i = 0; i < items.length; i += 1)` 的迭代次数、最后一次合法索引和退出时的 `i`。说明这组样本怎样验证循环不变量。

<Answer>
  三种输入分别执行 0、1、3 次；非空集合最后一次合法索引是 0 或 2，退出时 `i` 都等于 `items.length`。因此循环体访问的索引始终小于长度，退出时后置条件可以独立检查。
</Answer>

2. 找出 `while (i < items.length) { use(items[i]); }` 的最小故障，并给出只改变必要状态的修法。需要保存什么证据才能证明不是靠改阈值蒙对？

<Answer>
  最小故障是 `i` 从未改变，导致继续条件永远成立。修法是在成功处理 `items[i]` 后执行 `i += 1`，并保存固定输入、每次索引、首个不变量偏离、退出时 `i` 以及重置后的重复轨迹。
</Answer>

3. 为“选择循环的种类、循环控制、由内而外、循环和数组的关系”建立四级证据清单：每项各写一个解释、一个实验节点和一个可重放练习。

<Answer>

</Answer>
