## 为什么需要这一机制

第22章：开发者测试 解决的不是一个可背诵口号，而是从 **运行过就是测试** 到 **测试能稳定暴露指定故障** 的可观察变化。它的核心机制是：开发者测试从需求和代码结构导出正常、边界、错误与独立路径用例，脚手架保证隔离、可重复和失败可诊断。

学习 第22章：开发者测试 时先预测 测试目标、用例设计、脚手架执行、覆盖观察、回归记录 的输入与输出，再改变一个直接条件。最终结果即使看似正确，只要中间状态违反合同、故障不能隔离或重置不能回到同一基线，本页结论就不通过。


## 核心合同

tests=equivalence\ classes+boundaries+error\ paths+independent\ paths
