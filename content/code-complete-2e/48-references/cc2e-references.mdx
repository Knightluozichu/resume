<Objectives>

- 能为一个具体主张选择相关、权威、版本明确且可复核的参考来源。
- 能给参考文献添加注释，说明它支持什么、不支持什么以及何时需要重新核对。
- 能让第二位读者从书目条目回到原始页面或实验，重建同一证据链。

</Objectives>

## 为什么需要这一机制

参考文献不是链接收藏夹，而是主张与证据之间的导航。作者、书名和 URL 只能帮助定位；读者还需要知道来源支持哪条判断、使用了哪个版本、上下文是否相同、哪些内容只是背景。注释把“我看过”改写成“你可以复核”。

## 先避开三个来源误区

<Callout type="trap" title="误区一：链接越多越可信">
  现象 → 参考列表很长，却无法回答当前问题。原因 → 来源没有绑定主张和选择理由。修法 → 每项写支持的具体判断。
</Callout>

<Callout type="trap" title="误区二：权威来源无需核对版本">
  现象 → 把旧规范或旧实现直接用于当前环境。原因 → 时间、版本和上下文被省略。修法 → 记录发布日期、版本和需要重测的边界。
</Callout>

<Callout type="trap" title="误区三：书目条目就是证据">
  现象 → 只引用作者名，不指出页、段、实验或数据。原因 → 读者无法定位主张。修法 → 增加注释和独立复核路径。
</Callout>

## 核心合同与操作术语

<Term def="需要外部资料、规范或实验支持的明确判断">参考需要</Term>先说明要证什么；<Term def="来源与当前主张、对象和上下文的匹配程度">来源相关性</Term>说明为何选它。<Term def="写明来源能支持和不能支持的主张边界">注释范围</Term>防止过度推断；<Term def="来源发布、实现或数据产生时的时间与版本条件">版本状态</Term>决定是否需要重测；<Term def="读者可再次定位来源、输入和结果的步骤">复核路径</Term>让书目进入工程证据。

## 目录节点逐项深读

### 参考文献

参考文献的工程任务是提供可追踪来源。每一条记录至少要有主张、作者或机构、标题、版本或日期、URL/出版信息、选择理由、支持范围和复核方式；如果来源只提供背景，就明确标为背景，不把它升级为当前事实。

## 最小可重放实现

~~~text
need = state_one_claim_to_support()
source = choose_relevant_authoritative_version(need)
annotation = record_supported_and_unsupported_scope(source)
replay = independent_reader_follows(annotation)
record(replay, boundary, reviewDate)
~~~

正常轨迹能定位并理解来源；边界轨迹改变版本或上下文；故障轨迹删去注释或引用不相关条目；复位轨迹从主张重新选择来源并重查。

## 先预测，再操作证据实验

先预测来源相关性、注释范围或版本状态改变后哪个节点会变化，再只切换一个场景。专属面板展示书目追踪模型，不替代真实来源核对。

## 练习与答案

<Exercises>

**问题 1：补齐条目。** 一条参考文献只有作者、书名和链接，请列出至少四项缺失信息。

<Answer>
  补充版本或日期、支持的具体主张、选择理由、页码或段落、适用范围和复核步骤；若是在线资源，还要记录访问时间和稳定标识。
</Answer>

**问题 2：判断相关性。** 一篇讲旧语言版本的文章能否直接支持当前 API 行为？

<Answer>
  不能直接支持。先说明它只能提供历史背景，再核对当前规范或实现版本，并用固定输入做最小复现；差异要记录为边界。
</Answer>

**问题 3：设计复核路径。** 如何让读者从书目条目回到一条性能判断？

<Answer>
  在注释中写出主张、数据或实验位置、版本、输入、指标和观察窗口；复核者从同一条件运行，记录结果和首个偏离。
</Answer>

</Exercises>

## 本页小结

参考文献的价值在于可追踪：从主张出发选择相关来源，写出支持范围，固定版本状态，提供复核路径。数量不能替代定位和重放。
