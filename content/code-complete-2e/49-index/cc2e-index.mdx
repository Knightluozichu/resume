<Objectives>

- 能从问题术语定位章节、页面和相关上下文，而不是只依赖关键词命中。
- 能利用交叉引用区分同名概念、连接前置条件和找到反例。
- 能让另一位读者沿索引导航回原始证据，并复述结论的适用边界。

</Objectives>

## 为什么需要这一机制

索引的职责是降低寻找证据的成本，不是替读者理解正文。一个词条需要指向位置和上下文，交叉引用需要说明概念之间的关系，最后仍要回到章节中的合同、例子和边界。只凭关键词拼出一句结论，容易把同名术语和不同条件混在一起。

## 先避开三个索引误区

<Callout type="trap" title="误区一：命中关键词就是理解">
  现象 → 搜到一个页面就直接引用。原因 → 上下文、版本和术语义项没有核对。修法 → 回到段落和章节合同。
</Callout>

<Callout type="trap" title="误区二：同一个词只有一个意思">
  现象 → 把不同章节的同名词条合并。原因 → 领域、输入和边界不同。修法 → 记录上下文和交叉引用关系。
</Callout>

<Callout type="trap" title="误区三：索引可以替代正文">
  现象 → 只看索引页下结论。原因 → 定义、例外和反例被跳过。修法 → 沿位置、上下文和引用回到可验证证据。
</Callout>

## 核心合同与操作术语

<Term def="读者用来描述当前问题并启动检索的稳定词语">术语</Term>要对应领域语义；<Term def="章节、标题、段落或组件中可定位的证据坐标">位置</Term>让结果可回到原文。<Term def="术语在当前章节中的定义、输入、例子和适用边界">上下文</Term>防止断章取义；<Term def="把同义词、前置概念、反例和相关章节连起来的关系">交叉引用</Term>扩大检索路径；<Term def="沿导航回到正文并在固定条件下重建判断">可重放结论</Term>才是检索的终点。

## 目录节点逐项深读

### 索引

索引的工程任务是把读者问题映射到证据。先写想回答的主张和术语，再定位章节与上下文，检查交叉引用，最后记录结论及边界。若多个位置命中，不能只选最短的一条，而要比较其定义和前置条件。

## 最小可重放实现

~~~text
term = normalize_question(userInput)
locations = locate(term, index)
context = inspect_surrounding_sections(locations)
links = follow_cross_references(context)
claim = replay_evidence(links, same_conditions)
record(claim, boundary, rejectedInterpretations)
~~~

正常轨迹从词条到正文；边界轨迹使用同名词或不同版本；故障轨迹跳过上下文直接拼接结论；复位轨迹从同一问题重新导航并验证。

## 先预测，再操作证据实验

先预测术语、上下文或交叉引用改变后哪个节点会变化，再只切换一个场景。专属面板展示导航证据链，不替代真实章节阅读。

## 练习与答案

<Exercises>

**问题 1：处理多义词。** 搜索“接口”命中设计、API 和用户界面三个位置，如何选择？

<Answer>
  先把问题改写成主张和对象，比较三个位置的定义、输入和边界；沿相关交叉引用查看前置条件，记录为何排除其他义项。
</Answer>

**问题 2：回到上下文。** 为什么索引页显示“异常处理”不能直接证明某个 API 会重试？

<Answer>
  索引只定位主题，没有提供 API 版本、触发条件、重试次数或失败边界。必须回到章节和规范，用固定输入重放。
</Answer>

**问题 3：设计交叉引用。** 如何验证一个词条与另一个词条确实相关？

<Answer>
  写出两者共享的主张或前置条件，沿引用找到正文证据，再用一个正常和一个边界输入验证关系；如果只有相似词形，应标为无证据关联。
</Answer>

</Exercises>

## 本页小结

索引的完成标准是术语能定位位置，位置提供上下文，交叉引用连接相关证据，读者最终能重放结论并说出边界。命中不是理解，导航必须回到可复查内容。
