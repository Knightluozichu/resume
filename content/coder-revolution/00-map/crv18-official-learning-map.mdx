## 《码农翻身》权威学习地图

本页依据刘欣《码农翻身》（2018 年第 1 版）及出版社公开书目信息，独立重构 **《码农翻身》权威学习地图**。正文、代码、图示、实验和练习都是本课程重新设计的教学材料，不复制原书正文、插图、练习答案或代码。

地图不是把全书当成 60 个互不相关的故事，而是声明每个单元需要什么前置、产出什么机制模型、由什么证据复核。故事可以帮助记忆矛盾，状态、协议、类型、构建和反馈证据才决定一条学习路线是否真的可用。

## 三个会让学习地图失效的陷阱

<Callout type="trap" title="按标题随机跳读">

- **现象**：读者从 Web 或框架故事开始，却无法解释线程、协议、运行时和数据边界，遇到故障只能回到搜索结果。
- **原因**：地图只列了目录，没有声明前置和产出，标题顺序被误当成机制依赖。
- **修法**：为每个单元写前置、最小产出和复核证据；缺前置时回退到最近的机制节点，而不是继续堆故事。

</Callout>

<Callout type="trap" title="把故事记忆当成机制掌握">

- **现象**：读者能复述人物和比喻，却不能预测状态变化、接口边界或失败后的接管动作。
- **原因**：学习检查只问“讲了什么”，没有要求用一个输入运行模型并解释反例。
- **修法**：每个单元至少留下一个状态图、一个边界样本和一个可重放结论；故事与机制分开验收。

</Callout>

<Callout type="trap" title="把完成进度当成学习证据">

- **现象**：路线打满勾，但换版本、换环境或遇到单一故障时无法从现象定位到前置机制。
- **原因**：进度是计数器，不是理解证据；地图没有记录复核者、环境和失败轨迹。
- **修法**：保存每个节点的输入、产出、复核结果和回退动作；证据不足时把节点标为待验证，不提前解锁下游。

</Callout>

## 五个词把地图变成依赖系统

`<Term def="学习某个单元前必须已经能解释、运行或复核的机制、协议、工具或边界。">前置机制</Term>`决定路线是否可以解锁。前置不是“看过上一章”，而是能完成明确的小任务。

`<Term def="完成单元后能够展示的状态模型、最小实现、故障解释或可审查记录。">学习产出</Term>`让完成标准可观察。没有产出的阅读只能算接触，不算掌握。

`<Term def="把一个故事或主题连接到线程、协议、运行时、代码变更和职业实践的有向关系。">机制依赖</Term>`解释为什么某个单元应该先学，以及缺失它会让下游哪一步失去依据。

`<Term def="用正常、边界或单一故障输入检查学习产出是否仍能解释状态、行为和恢复。">复核证据</Term>`把地图从目录升级为验收系统。证据要包含输入、预期、实际、首差和回退。

`<Term def="在当前前置尚未成立、证据冲突或环境改变时，回到最近可知状态并重建路线的动作。">路线回退</Term>`不是失败惩罚，而是避免把不稳定的前置传给更多下游单元。

五个词形成地图闭环：前置机制解锁学习产出，机制依赖说明方向，复核证据决定是否通过，路线回退处理缺口。地图中的箭头表示责任和状态变化，不只是阅读顺序。

## 60 个正式单元的路线分区

公开目录将本书范围组织成 60 个正式单元、253 个目录节点。本地图把它们分成五个机制区域：**系统基础**负责计算机、线程、进程、内存和文件；**Java 运行时**负责对象、异常、集合、并发和虚拟机；**Web 协议**负责请求、连接、状态、缓存和安全；**工程变更**负责 Git、构建、测试、发布和回退；**语言与成长**负责抽象、设计、沟通、学习和职业反馈。

分区不是把章节重新命名，而是为跨单元的前置和产出建立共同坐标。读者可以从目录节点进入，但必须在离开时写出“我改变了哪个模型、用什么样本验证、下游能接收什么”。

### 系统基础

先建立机器、线程、进程、内存、文件和网络的资源边界。产出是能从一个现象指出状态、所有者和生命周期，并用最小实验区分“没有资源”“没有权限”和“协议不匹配”。

### Java 运行时

再把语言结构连接到运行时：对象如何创建和回收，线程如何调度，异常如何传播，集合和锁如何改变状态。产出是一个能说明栈、堆、线程和共享状态关系的可复核模型。

### Web 协议

随后把运行时放进请求、连接、缓存、序列化和安全边界。产出是能沿一次请求追踪输入、协议状态、响应和失败恢复，而不是只背框架 API 名称。

### 工程变更

把代码、配置、构建、测试、发布和回退纳入历史。产出是能说明一次变更从工作区到线上结果的证据链，并在构建或部署失败时回到可知状态。

### 语言与成长

最后把机制理解转成抽象、表达、协作、学习和职业选择。产出不是一句励志总结，而是能解释自己的假设、反馈来源、练习计划和下一次复核。

## 地图合同

```ts
type LearningNode = {
  id: string;
  prerequisites: string[];
  output: string;
  evidence: string[];
  status: "locked" | "ready" | "verified" | "revisit";
};

function canUnlock(node: LearningNode, verified: Set<string>) {
  return (
    node.prerequisites.every((id) => verified.has(id)) &&
    node.evidence.length > 0
  );
}
```

这个合同不把学习简化成进度百分比。只有前置已验证、产出可观察、证据可重放，节点才从 `ready` 进入 `verified`；遇到边界或反例时回到 `revisit`，并记录路线回退而不是伪造完成。

## 四步使用学习地图

<Stepper>

<Step title="1. 选择最小目标和前置">

从一个可判定的问题开始，写出目标单元、需要的前置机制、环境版本和不在范围内的内容。不要用“学会 Web”替代可观察任务。

<Crv18OfficialLearningMapLoopDiagram />

</Step>

<Step title="2. 运行机制样本">

为目标机制准备正常样本和一个边界样本，先预测状态变化，再运行最小实现。保存输入、输出、错误信息和首个差异。

<Crv18OfficialLearningMapEvidenceDiagram />

</Step>

<Step title="3. 连接下游产出">

把通过的机制交给下一个区域，写明它能提供什么状态、协议或工程证据。如果下游无法接收，说明前置产出尚未闭合，应暂停解锁。

<Crv18OfficialLearningMapLoopDiagram />

</Step>

<Step title="4. 独立复核并决定回退">

让另一名读者只拿到地图、输入和验收命题，重放正常、边界和单一故障样本。根据结果标记 verified、revisit 或 locked，保留复核者与恢复动作。

<Crv18OfficialLearningMapEvidenceDiagram />

</Step>

## 正常、边界与单一故障证据

<Crv18OfficialLearningMapEvidenceDiagram />

| 样本     | 只改变的变量                     | 预期判定                           | 必存证据                   |
| -------- | -------------------------------- | ---------------------------------- | -------------------------- |
| 正常     | 前置、环境、产出和复核者完整     | 节点可解锁，下游能接收产出         | 目标、状态、输出、复核记录 |
| 边界     | 版本、权限或前置能力恰好越过阈值 | 暂停或回退，不把不稳定节点传给下游 | 阈值、首差、替代路径       |
| 单一故障 | 一个前置、样本或复核角色失效     | 在最早缺口暴露并回到可知状态       | 错误上下文、回退、重新验证 |

## 最小地图证据包与反例

证据包包含目标单元、前置列表、目录坐标、环境版本、最小输入、预测、实际状态、产出、复核者、首差、路线回退和下游接收结果。完成数量、阅读时长或最终截图只能辅助定位，不能单独证明路线有效。

反例不是“这章不重要”。它必须指出同一前提下下游产生不同状态，或证明前置在目标环境并不成立。发现反例后，保留失败轨迹，回到最近可知节点，修正前置或产出并重新复核；不要删除失败记录来保持地图连续解锁。

## 练习

<Exercises>

**问题 1：** 你想直接学习 Web 框架，但无法解释一次请求中的线程、连接和状态。地图应如何处理？

<Answer>

把“Web 框架能写出页面”改成可判定目标，回退到线程、协议和运行时的最近缺口；为每个前置写一个最小样本和复核证据。前置未验证时保持目标锁定，不用框架的成功页面伪造机制掌握。

</Answer>

**问题 2：** 一个单元的故事你能复述，但边界样本让下游构建失败。你会修改哪一项？

<Answer>

先保存输入、环境、预测、构建日志和首个差异，判断失败来自前置、学习产出还是下游假设。把节点标为 revisit，回到最近可知状态，只修改一个条件后重放；不要因为故事记得熟就解锁下游。

</Answer>

**问题 3：** 另一名读者用同一地图得出不同路线，怎样区分合理分支和地图缺陷？

<Answer>

比较两条路线的前置、产出、边界和复核证据；如果都能满足同一验收命题，这是可接受的分支。如果某一条依赖未声明的环境或无法提供下游需要的状态，就记录首个缺口，补前置或明确路线限制。

</Answer>

</Exercises>

## 本页小结

《码农翻身》权威学习地图的价值不是把 60 个单元排成一条漂亮目录，而是让前置机制、学习产出、机制依赖、复核证据和路线回退都可见。读者可以从故事进入，但必须用状态、协议、运行时、工程变更和反馈样本证明自己能接住下一个节点；证据不足时，回退是路线的一部分。
