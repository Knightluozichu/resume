## 学习目标

- 理解计算机从硬件到应用的分层架构
- 掌握源代码到执行结果的全链路流程
- 理解进程与线程的区别及内存模型
- 建立「代码如何跑起来」的系统认知

## 核心概念

### 编程世界的本质

编程不是写文字，而是**指挥计算机干活**。要真正理解编程，需要搞清楚一行代码从写下到执行经历了什么。《码农翻身》用故事化方式揭示了这层认知：你写的每一行代码，最终都要穿越语言层、操作系统层，到达硬件层被执行。

- **代码到执行**：源代码 → 编译/解释 → 加载 → 执行 → 结果输出

### 代码到执行流程

一行代码从写下到执行，经历以下步骤：

1. **源代码**：程序员用高级语言（Java/Python/C）编写代码文件
2. **编译/解释**：编译器将源码转为字节码或机器码；解释器逐行执行
3. **加载**：类加载器或操作系统将代码加载到内存
4. **执行**：CPU 从内存取指令、译码、执行
5. **输出**：结果写回内存或输出到外设

### 进程与内存

操作系统通过进程和线程管理程序的执行：

| 概念 | 说明 |
|------|------|
| 进程 | 独立的地址空间，包含代码段、数据段、堆、栈 |
| 线程 | 进程内的执行单位，共享堆内存，拥有独立栈 |
| CPU 调度 | 时间片轮转，上下文切换实现并发 |
| 堆 | 动态分配内存，对象实例存放处 |
| 栈 | 方法调用栈，局部变量与返回地址 |

### 编译型与解释型

| 类型 | 代表语言 | 特点 |
|------|----------|------|
| 编译型 | C / C++ | 源码直接编译为机器码，执行快 |
| 解释型 | Python / Ruby | 逐行解释执行，灵活但慢 |
| 混合型 | Java / JavaScript | 先编译为字节码，再由虚拟机解释或 JIT 编译 |

## 术语表

| 术语 | 释义 |
|------|------|
| 进程 | 操作系统资源分配的基本单位 |
| 线程 | CPU 调度的基本单位，进程内执行 |
| 上下文切换 | CPU 从一个线程切换到另一个线程的过程 |
| 编译器 | 将源代码翻译为目标代码的程序 |
| 解释器 | 逐行读取并执行源代码的程序 |
| 字节码 | 中间代码，由虚拟机解释执行 |
| 类加载器 | JVM 中将类文件加载到内存的组件 |
| 时间片 | CPU 分配给每个线程的执行时间 |

## 练习题

1. 描述源代码从编写到执行结果输出的完整流程。
2. 进程和线程有什么区别？它们在内存模型上有何不同？
3. 编译型语言和解释型语言各有什么优缺点？
4. 为什么说理解计算机分层架构对程序员很重要？
