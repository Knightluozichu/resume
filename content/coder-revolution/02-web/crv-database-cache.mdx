## 核心概念

### 数据存取的核心矛盾

数据库可靠但慢，缓存快但易失。《码农翻身》把这个矛盾比作「图书馆与书桌」：数据库是图书馆的书架，缓存是你桌上的书。你要看的书先从书架拿到桌上，看完了放回去。关键问题是什么时候拿、什么时候放、桌上的书过时了怎么办。

### ACID 事务特性

上图展示了数据库与缓存的两大维度：

- **ACID 四大特性**：原子性、一致性、隔离性、持久性
- **缓存读写策略**：Cache Aside / Read-Write Through / Write Behind

#### 原子性（Atomicity）

事务是最小的执行单位，要么全部成功，要么全部回滚。例如转账：扣款和加款必须同时成功或同时失败。

#### 一致性（Consistency）

事务执行前后，数据必须满足所有约束条件。例如转账前后总金额不变。

#### 隔离性（Isolation）

并发事务之间互不干扰，通过锁机制和隔离级别控制。

#### 持久性（Durability）

事务一旦提交，数据永久保存，即使系统故障也不丢失（通过日志保障）。

### 缓存读写策略

| 策略 | 读流程 | 写流程 | 特点 |
|------|--------|--------|------|
| Cache Aside | 先查缓存，未命中查 DB | 更新 DB，再删缓存 | 最常用，应用层控制 |
| Read/Write Through | 缓存同步读 DB | 缓存同步写 DB | 缓存层代理，一致性较好 |
| Write Behind | 先查缓存 | 只写缓存，异步刷 DB | 写入快，可能丢数据 |

### 缓存三大经典问题

| 问题 | 描述 | 对策 |
|------|------|------|
| 缓存穿透 | 查询不存在的数据，绕过缓存直击 DB | 布隆过滤器 / 空值缓存 |
| 缓存雪崩 | 大量缓存同时失效，DB 压力暴增 | 随机过期时间 / 限流降级 |
| 缓存击穿 | 热点 key 过期，并发直查 DB | 互斥锁 / 永不过期 |

### 数据访问链路

应用 → 缓存（内存级速度）→ 数据库（持久化存储）→ 磁盘（物理持久化）

缓存命中率越高，系统整体性能越好。但缓存引入了一致性问题，需要根据业务场景选择合适的策略。

## 术语表

| 术语 | 释义 |
|------|------|
| 事务 | 数据库操作的最小逻辑单元 |
| ACID | 原子性、一致性、隔离性、持久性 |
| 回滚 | 事务失败时撤销已执行的操作 |
| 缓存穿透 | 查询不存在的数据绕过缓存 |
| 缓存雪崩 | 大量缓存同时失效 |
| 缓存击穿 | 热点 key 过期时并发直查 DB |
| 布隆过滤器 | 判断元素是否存在的概率型数据结构 |
| Cache Aside | 应用层控制缓存的读写策略 |
