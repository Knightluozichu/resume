## 学习目标

- 理解 JVM 的运行时架构和三大子系统
- 掌握 JVM 内存区域划分及各自特点
- 理解垃圾回收的分代机制和流程
- 了解不同编程语言范式的特点和适用场景

## 核心概念

### JVM 的意义

Java 虚拟机（JVM）是「一次编写，到处运行」的基石。《码农翻身》把 JVM 比作一个「翻译官」：你用 Java 写的代码编译成字节码后，JVM 负责把它翻译成不同平台能理解的机器码。JVM 还帮你管理内存、回收垃圾，让程序员专注于业务逻辑。

- **内存区域**：堆 / 方法区 / 虚拟机栈 / 程序计数器

### JVM 三大子系统

1. **类加载子系统**：加载 → 链接（验证/准备/解析）→ 初始化
2. **运行时数据区**：方法区、堆、虚拟机栈、程序计数器
3. **执行引擎**：解释器 + JIT 编译器 + 垃圾回收器

### JVM 内存区域

| 区域 | 存储内容 | 线程共享 |
|------|----------|----------|
| 堆 | 对象实例 | 共享 |
| 方法区 | 类信息、常量、静态变量 | 共享 |
| 虚拟机栈 | 栈帧、局部变量、操作数栈 | 私有 |
| 程序计数器 | 当前执行指令地址 | 私有 |

### 垃圾回收机制

JVM 采用分代垃圾回收：

1. **新生代**（Eden + Survivor）：对象刚创建时存放处，Minor GC 频繁
2. **晋升**：存活过多次 Minor GC 的对象进入老年代
3. **老年代**：长期存活对象，Full GC 较少但耗时
4. **回收释放**：标记存活对象，清除垃圾，整理内存

### 编程语言范式

| 范式 | 代表语言 | 核心特点 |
|------|----------|----------|
| 面向对象 | Java / C++ / C# | 封装、继承、多态 |
| 函数式 | Haskell / Scala | 纯函数、不可变 |
| 动态类型 | Python / JS / Ruby | 运行时类型推断 |
| 系统级 | C / Rust / Go | 内存安全、高性能 |

不同范式各有优势，现代语言趋向多范式融合（如 Scala、Rust）。

## 术语表

| 术语 | 释义 |
|------|------|
| JVM | Java 虚拟机，执行字节码的运行时 |
| 字节码 | Java 源码编译后的中间代码 |
| 类加载器 | 将类文件加载到 JVM 内存的组件 |
| 堆 | JVM 中存储对象实例的内存区域 |
| 方法区 | 存储类信息、常量的内存区域 |
| GC | 垃圾回收，自动回收不再使用的内存 |
| 新生代 | JVM 堆中存放新对象的区域 |
| JIT | 即时编译，运行时将字节码编译为机器码 |

## 练习题

1. JVM 的三大子系统是什么？各自的职责是什么？
2. JVM 内存区域中哪些是线程共享的，哪些是线程私有的？
3. 描述垃圾回收的分代机制和 Minor GC / Full GC 的区别。
4. 面向对象范式和函数式范式各有什么优势？
