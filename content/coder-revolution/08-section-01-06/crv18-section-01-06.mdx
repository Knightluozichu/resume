## 1.6 我是一块硬盘

本页依据刘欣《码农翻身》（2018 年第 1 版）及出版社公开书目信息，独立重构 **1.6 我是一块硬盘**。正文、代码、图示、实验和练习都是本课程重新设计的教学材料，不复制原书正文、插图、练习答案或代码。

硬盘不是“文件躺在连续位置上”的透明盒子。文件系统把名称解析为元数据和数据块，用空闲空间结构分配块，再把读写请求交给块设备；设备只负责持久化块，不能替文件系统决定名称、权限、目录一致性或断电恢复。

## 三个会让文件系统模型失真的陷阱

<Callout type="trap" title="把文件名当成数据位置">

- **现象**：根据文件名或连续字节的直觉直接计算磁盘位置，忽略目录、元数据和间接块。
- **原因**：混淆名称解析、文件元数据、逻辑偏移和物理块，导致碎片、扩展和权限边界无法解释。
- **修法**：分别记录路径解析、元数据、逻辑块、物理块和设备请求；用小文件、扩展文件和稀疏文件样本验证。

</Callout>

<Callout type="trap" title="只写目录项就宣布保存成功">

- **现象**：断电后目录里出现文件名，但文件内容为空、旧、悬空或指向已经复用的块。
- **原因**：没有记录数据块、元数据和日志或同步操作的持久化顺序。
- **修法**：定义写入合同和恢复顺序，分别验证数据、元数据、空闲块结构与目录项，断电样本必须可恢复或明确拒绝。

</Callout>

<Callout type="trap" title="忽略空闲块和资源边界">

- **现象**：磁盘看似还有空间，但分配失败、碎片扩大或两个文件出现同一块归属。
- **原因**：把容量计数当作空闲块账本，没有验证分配、释放、崩溃和重放的一致性。
- **修法**：保存空闲结构、分配决策、所有者和回收记录；在恰好耗尽和单一元数据故障下停止扩大。

</Callout>

## 五个词组成文件读写合同

`<Term def="把路径中的目录项、名称和权限逐级解析为一个文件对象身份的过程。">名称解析</Term>`决定请求指向哪个对象。路径解析失败时不能继续读取旧缓存冒充成功。

`<Term def="描述文件类型、大小、权限、所有者、时间、块映射和一致性状态的记录。">元数据</Term>`不是文件内容的附属装饰，它决定如何解释和保护数据块。

`<Term def="保存文件内容的固定大小设备区域，逻辑块到物理块的映射由文件系统维护。">数据块</Term>`可能不连续，也可能需要间接映射。设备只看到块请求，不知道文件名。

`<Term def="记录哪些块可分配、已分配给谁以及释放是否完成的结构和不变量。">空闲块账本</Term>`保证分配不重叠、释放可重用、崩溃后能恢复。容量数字不能替代账本。

`<Term def="数据、元数据、目录项和空闲结构按约定被设备稳定保存，并能在断电后恢复到可解释状态。">持久化顺序</Term>`决定恢复看到的是旧版本、新版本还是拒绝状态。

五个词组成磁盘链：名称解析找到对象，元数据找到逻辑范围，数据块承载内容，空闲块账本管理空间，持久化顺序让这些记录在断电后仍然一致。

## 目录节点到机制证据

### 内部结构

内部结构包括目录项、元数据、数据块映射、空闲块结构和恢复日志。读写一个文件时，必须说明这些结构如何交接，而不是把文件系统当作一个无状态函数。

### 文件

文件是名称、元数据和内容块的组合对象。大小变化、权限变化和删除都会改变不同结构；“内容读到了”不能证明文件对象的所有状态都一致。

### 文件的存放

文件的存放可能跨越多个逻辑块和物理块。复核要区分逻辑偏移、块大小、寻址映射和设备队列，尤其要检查扩展与碎片边界。

### 管理空闲块

管理空闲块需要维护分配、释放、崩溃恢复和所有权不变量。空间不足不是只有“没有容量”一种失败，也可能是账本损坏、碎片或元数据无法安全更新。

### 文件系统

文件系统把名称、权限、元数据、数据块和空闲结构组织成可访问对象，并向块设备发出读写请求。它还要决定缓存、日志、同步和恢复策略。

## 文件读写合同

```ts
type FileWrite = {
  path: string;
  metadataBefore: string;
  dataBlocks: string[];
  freeBlockJournal: string[];
  persistenceOrder: string[];
  firstDeviation: string;
  recovery: string;
  decision: "commit" | "replay" | "reject";
};

function canCommit(write: FileWrite) {
  return (
    write.path.length > 0 &&
    write.metadataBefore.length > 0 &&
    write.dataBlocks.length > 0 &&
    write.freeBlockJournal.length > 0 &&
    write.persistenceOrder.length >= 2 &&
    write.firstDeviation.length > 0
  );
}
```

合同要求写入者能解释路径、元数据、数据块、空闲账本和持久化顺序。不能证明某一步稳定保存时选择 replay 或 reject，而不是用目录项存在掩盖内容和空间状态的不一致。

## 四步复核一次文件写入

<Stepper>

<Step title="1. 解析名称并读取元数据">

冻结路径、权限、文件版本和目录状态，记录每一级名称解析、元数据和逻辑范围。路径不存在、权限不足或对象类型不符时应在这里停止。

<Crv18Section0106LoopDiagram />

</Step>

<Step title="2. 定位数据块并检查空间">

把逻辑偏移转换为逻辑块和物理块，读取空闲块账本与所有权。加入文件扩展、碎片、恰好耗尽和块冲突样本。

<Crv18Section0106EvidenceDiagram />

</Step>

<Step title="3. 执行设备传输并记录顺序">

保存队列、寻址、传输结果、缓存状态和同步点。数据块、元数据、目录项和空闲结构的更新顺序必须可解释，不用返回成功替代稳定保存。

<Crv18Section0106LoopDiagram />

</Step>

<Step title="4. 注入断电并独立恢复">

让另一名复核者在正常、边界和单一故障样本下重放，比较恢复后的路径、内容、大小、权限和空闲账本。根据首差 replay、修复或拒绝写入。

<Crv18Section0106EvidenceDiagram />

</Step>

</Stepper>

## 正常、边界与单一故障证据

<Crv18Section0106EvidenceDiagram />

| 样本     | 只改变的变量                               | 预期判定                         | 必存证据               |
| -------- | ------------------------------------------ | -------------------------------- | ---------------------- |
| 正常     | 路径、元数据、数据块、空闲账本和同步完整   | 读取与恢复结果可解释             | 映射、顺序、内容、账本 |
| 边界     | 空间、文件大小、权限或断电时点越过阈值     | 停止或恢复到已知版本，不假装成功 | 阈值、旧状态、恢复决策 |
| 单一故障 | 一个目录项、数据块、空闲记录或设备传输失效 | 首个不一致暴露并修复或拒绝       | 首差、所有者、回放日志 |

## 最小磁盘证据包与反例

证据包包含路径和目录快照、文件元数据、逻辑到物理块映射、空闲块账本、设备请求、缓存和同步点、断电时点、恢复结果、版本和独立复核记录。最终读到内容或目录项存在，只能辅助定位，不能单独证明持久化一致。

反例可以是文件名存在但数据块未写完，也可以是两个文件在恢复后共享了不应共享的块。发现反例后，保留断电前后结构，修复日志或更新顺序，重建空闲账本并重放；不要删除旧块记录来制造干净结果。

## 练习

<Exercises>

**问题 1：** 断电后目录里有新文件名，但读取内容得到旧数据。你先比较哪些证据？

<Answer>

比较目录项、元数据版本、逻辑到物理块映射、数据块写入和同步顺序，找出第一处“新名称指向旧或未稳定数据”的变化。保留旧状态，修正日志或写入顺序后重放，不用目录项存在宣布完成。

</Answer>

**问题 2：** 磁盘容量还有余量，但创建大文件失败。如何区分容量、碎片和空闲账本问题？

<Answer>

记录块大小、连续或分散的空闲块、元数据预留和空闲账本一致性；用小文件、恰好容量和碎片样本比较首差。若账本损坏，先停止分配并恢复账本，不能把剩余容量数字当作可用空间证明。

</Answer>

**问题 3：** 两个文件恢复后内容互相污染，你会如何回退？

<Answer>

冻结断电前后的目录、元数据、块所有权和日志，确认首个重复归属或释放顺序错误。隔离受影响块，回退到最近一致快照，重建空闲账本并用只读恢复样本验证，最后再开放写入。

</Answer>

</Exercises>
