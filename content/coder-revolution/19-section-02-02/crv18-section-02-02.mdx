## 2.2 我是一个Java Class

本页依据刘欣《码农翻身》（2018 年第 1 版）及出版社公开书目信息，独立重构 **2.2 我是一个Java Class**。正文、代码、图示、实验和练习都是本课程重新设计的教学材料，不复制原书正文、插图、练习答案或代码。

Java Class 不是一张源代码截图。磁盘上有 class 文件，包含常量池、字段、方法和属性；JVM 加载并链接它，形成运行时类元数据；`new` 创建的实例对象只保存自己的字段状态，并通过运行时类找到方法和类型信息。把三者混成一个“类”，就无法解释静态初始化、符号解析、类加载器和对象生命周期。

## 三个会让类生命周期失真的陷阱

<Callout type="trap" title="把 class 文件当成运行时类本身">

- **现象**：文件存在就假定类已经加载、字段已准备、方法可以调用。
- **原因**：忽略加载器、验证、链接、初始化时机和多个运行时副本。
- **修法**：分别记录文件、类元数据和实例的身份；每次跨层都保留状态与加载器证据。

</Callout>

<Callout type="trap" title="把静态字段的默认值当成初始化结果">

- **现象**：类初始化方法还没完成，另一个路径就读取或依赖静态字段的最终业务值。
- **原因**：准备阶段会建立默认存储，初始化阶段才执行显式赋值和静态代码块。
- **修法**：区分准备值与初始化值，注入失败或循环依赖，检查是否出现半成品状态。

</Callout>

<Callout type="trap" title="把同名类当成同一个类型">

- **现象**：两个插件都加载同名类，强制转换却失败，或修改一个类文件没有影响正在运行的实例。
- **原因**：类型身份包含类加载器和运行时定义，不只由二进制名称决定。
- **修法**：记录类加载器、代码源、版本和实例的实际类；不要只打印简单类名。

</Callout>

## 六个目录节点到类生命周期证据

### 陌生警察

<Term def="在类进入运行时前检查 class 文件结构、版本、类型约束和字节码安全性的验证边界。">
  陌生警察
</Term>
代表验证阶段。它不会执行所有业务逻辑，而是先拒绝魔数、版本、栈图或类型关系不成立的类文件。正常样本要记录验证通过；边界样本改变版本或结构，记录拒绝位置和错误类别。

### 刺探信息

<Term def="读取常量池、字段和方法等符号信息，并建立运行时可用的静态存储与元数据准备状态。">
  刺探信息
</Term>
对应准备和符号信息观察。准备阶段给静态字段建立默认值，解析可以提前或按需完成；不要把“看见了符号”误当成“业务初始化已经执行”。

### 初识虚拟机

<Term def="JVM 将 class 文件转换为可管理的类元数据、方法信息和对象分配规则的运行时边界。">
  初识虚拟机
</Term>
要求同时看类加载器、方法区/元数据、堆对象和执行栈。它不是一个黑盒“运行
Java”的按钮；每个阶段都有可观察的状态、失败和资源成本。

### 快乐假期

<Term def="类已完成必要的加载与链接，首次主动使用触发初始化并让静态代码获得业务可见效果的阶段。">
  快乐假期
</Term>
表示初始化完成后的正常使用路径。若静态初始化抛出异常，后续主动使用可能被拒绝；实验要把首次使用、重复使用和初始化失败分开记录。

### 真相大白

<Term def="通过对照 class 文件、运行时类元数据和实例对象，确认类型身份、字段状态与方法分派来源。">
  真相大白
</Term>
不是打印一个类名就结束。检查对象的实际类、类加载器、代码源、静态字段和实例字段，才能解释“文件已更新但旧实例仍然运行”或“同名类型无法转换”。

### 2.2 我是一个Java Class

**2.2 我是一个Java Class**的核心是三层分离和一条状态机：加载文件，验证结构，准备默认状态，解析符号，初始化静态逻辑，最后在实例上执行方法。类文件是交付物，运行时类是 JVM 的定义，实例是某次 `new` 得到的状态；它们共享名称，却不共享生命周期。

## 最小类生命周期合同

```java
record ClassObservation(
    String binaryName,
    String loaderId,
    String codeSource,
    String phase,
    int staticValue,
    int instanceValue
) {}

static boolean canUse(ClassObservation observation) {
  return observation.phase().equals("initialized")
      && !observation.loaderId().isBlank()
      && !observation.codeSource().isBlank();
}
```

合同要求每一条观测绑定二进制名、类加载器、代码源、生命周期阶段和字段状态。`staticValue` 在准备阶段可能仍是默认值；`instanceValue` 必须属于某个实例。若阶段或身份不清楚，先停止调用并补证据。

## 四步复核一个 Java Class

<Stepper>

<Step title="1. 读取 class 文件并确认身份">

保存 class 文件来源、版本、二进制名、常量池摘要和加载器。正常样本从干净类路径加载；边界样本替换一个文件或版本，观察验证与加载错误。

<Crv18Section0202LifecycleDiagram />

</Step>

<Step title="2. 观察验证、准备与解析">

记录验证是否通过、静态字段的默认值、常量池符号和解析时机。不要在准备阶段读出业务最终值，也不要把按需解析误判为文件损坏。

<Crv18Section0202EvidenceDiagram />

</Step>

<Step title="3. 触发初始化并创建实例">

区分首次主动使用、静态初始化、构造器和实例方法。记录初始化线程、静态字段变化、实例字段和实际类加载器，注入一次初始化异常。

<Crv18Section0202ClassLab />

</Step>

<Step title="4. 对照类身份与恢复结果">

让两个加载器加载同名类，检查类型转换、静态状态和代码源；修复类路径或初始化顺序后，从干净 JVM 重新加载并重放，确认没有旧元数据残留。

</Step>

## 正常、边界与单一故障证据

<Crv18Section0202EvidenceDiagram />

| 样本     | 只改变的变量                       | 预期判定                           | 必存证据                       |
| -------- | ---------------------------------- | ---------------------------------- | ------------------------------ |
| 正常     | 文件、加载器、版本和初始化路径匹配 | 类初始化完成，实例身份可解释       | 文件摘要、阶段、加载器、字段值 |
| 边界     | 延迟解析、重复加载器或默认静态值   | 明确区分默认值、初始化值和类型身份 | 触发点、类加载器、代码源、线程 |
| 单一故障 | 一个版本、符号或静态初始化动作失败 | 在对应阶段拒绝，重启后可重放       | 异常、首个阶段差异、恢复日志   |

## 故障诊断：先定位阶段，再定位对象

1. **文件/验证层**：看魔数、版本、常量池和字节码结构；验证失败时不要继续讨论实例字段。
2. **链接层**：看准备值、符号解析、依赖类和加载器；区分找不到符号、类型不兼容和初始化失败。
3. **初始化层**：看首次主动使用、静态代码块、线程和异常；检查是否出现循环依赖或“错误后继续使用”。
4. **实例层**：看实际类、加载器、代码源、静态字段与实例字段；同名不等于同一类型。

如果日志只有“加载成功”，仍不足以证明初始化完成；如果实例方法能调用，也不能反推出所有静态依赖都已正确初始化。诊断要绑定阶段、身份和状态三件事。

## 最小类证据包与反例

证据包包含 class 文件哈希、编译目标、二进制名、类加载器、代码源、验证/解析记录、静态默认值与最终值、初始化线程、实例身份、异常和干净重放结果。涉及插件时，还要保存加载器层级与依赖版本。

反例一是准备阶段读取静态字段得到默认值，业务把它当成初始化后的配置；反例二是两个加载器各自定义同名类，实例强制转换失败。修复后不要只清空应用缓存，要重启或隔离类加载器并重新保存生命周期轨迹。

## 练习

<Exercises>

**问题 1：** 类已经被加载，但静态字段仍是默认值。你如何区分准备阶段和初始化阶段？

<Answer>

记录首次主动使用、初始化线程、静态代码块日志和字段变化；准备阶段只建立默认存储，初始化阶段才执行显式赋值和静态逻辑。不要用“类文件存在”或“能拿到 Class 对象”证明初始化完成。

</Answer>

**问题 2：** 两个插件都定义同名类，为什么实例不能互相转换？

<Answer>

运行时类型身份包含定义它的类加载器和代码源。同名二进制由不同加载器定义后是两个类型；保存实际类、加载器、代码源和依赖树，再统一加载器或明确隔离边界。

</Answer>

**问题 3：** 静态初始化抛出异常后，下一次主动使用仍然失败。诊断时先查什么？

<Answer>

先确认初始化异常、触发线程和类的失败状态，再检查依赖、配置和初始化循环。修复后用干净 JVM 重新加载，不能期待同一个失败的运行时类自动恢复到未初始化状态。

</Answer>

</Exercises>

## 本页小结

2.2 我是一个Java Class 的关键不是把 class 文件、运行时类和实例对象叫成同一个“类”，而是沿加载、验证、准备、解析、初始化和首次使用分别取证。完成标准是能解释默认值与初始化值、同名类与类加载器的关系，并从干净 JVM 重放版本、符号和初始化故障。
