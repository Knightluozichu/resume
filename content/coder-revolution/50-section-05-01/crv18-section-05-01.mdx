## 5.1 JavaScript ：一个草根的逆袭

本页依据刘欣《码农翻身》（2018 年第 1 版）及出版社公开书目信息，独立重构 **5.1 JavaScript ：一个草根的逆袭**。正文、图示、实验和练习是本课程重新设计的教学材料，不复制原书正文、插图、练习答案或代码。

JavaScript 的成长不只是“脚本变强了”。ECMAScript 规定语法、值、对象、函数和执行语义；浏览器、Node.js 等宿主提供文档、网络、文件或定时器能力；事件循环与任务队列决定异步回调何时获得执行机会；JSON 则是独立的数据交换格式。把这四层混成一层，代码能跑也不代表解释正确。

## 三个会让 JavaScript 解释失真的陷阱

<Callout type="trap" title="把宿主 API 当作 ECMAScript 内建能力">

- **现象**：把 `document`、`fetch` 或文件 API 说成语言本身到处都有，换宿主后程序立刻失效。
- **原因**：语言规范与宿主环境是不同合同；同一语法可以在多个宿主运行，但能力集合不相同。
- **修法**：分别记录语言版本、宿主名称与 API 能力；跨宿主复用时先验证依赖的环境边界。

</Callout>

<Callout type="trap" title="用执行代码的方式解析 JSON">

- **现象**：用 `eval` 把外部字符串当脚本执行，或认为 JSON 可以携带函数、原型和任意表达式。
- **原因**：JSON 只定义有限的数据值与结构，不是完整 JavaScript 程序；执行代码还会引入副作用和安全边界。
- **修法**：使用 JSON 专用解析器并校验结构，把数据和代码分开；失败时保存输入和解析错误而不是执行回退。

</Callout>

<Callout type="trap" title="把排队回调当成当前同步语句立即执行">

- **现象**：看到定时器或网络回调注册成功，就断言它会在下一行之前完成；页面状态因顺序误判而出错。
- **原因**：任务要等待当前执行片段结束并满足宿主调度条件，排队不等于执行，延迟也不等于精确时间承诺。
- **修法**：记录同步日志、任务入队点、回调执行点和结果写入点；用实际轨迹验证顺序，不靠直觉推断。

</Callout>

## 六个目录节点到执行证据

### 5.1 JavaScript ：一个草根的逆袭

总合同是：脚本先按 ECMAScript 语义解析和执行，再调用宿主 API；异步动作把任务交给宿主调度，回调执行后才产生可观察结果；JSON 只承担数据序列化，不承担代码执行。语言、宿主、任务与数据的边界必须分别记录。

### 出世

**出世** 对应脚本进入解析器的阶段。语法和静态结构决定程序能否形成执行单元；解析通过不代表宿主 API 存在，也不代表异步结果已经产生。

<Term def="JavaScript 源码被解析为可执行结构并接受语言语法与语义检查的阶段；它不负责提供宿主 API 或完成异步任务。">
  出世
</Term>

### 成长

**成长** 对应执行上下文与对象模型逐渐承担更复杂的程序状态。函数、词法环境、对象原型和闭包让代码能组织行为，但这些语言机制仍不等于浏览器文档或服务器文件能力。

<Term def="从脚本语句扩展到函数、对象、词法环境与原型等语言机制的能力增长；语言能力与宿主能力仍需分开验收。">
  成长
</Term>

### 第一桶金

**第一桶金** 对应脚本第一次有效调用宿主 API 并改变外部可观察状态。浏览器页面、网络请求或文件系统都是宿主提供的边界，调用成功要同时记录环境和权限。

<Term def="脚本通过宿主 API 产生第一次外部可观察效果的阶段；效果依赖宿主、权限和 API 合同，不是语言规范单独保证的。">
  第一桶金
</Term>

### 发明JSON

**发明JSON** 对应数据格式从代码中独立出来：对象、数组、字符串、数字、布尔值和空值组成可交换数据。解析 JSON 得到数据值，不会得到函数定义或原型行为。

<Term def="把有限的数据结构标准化为可交换文本格式的阶段；JSON 是数据，不是可以携带任意函数和语句的 JavaScript 程序。">
  发明JSON
</Term>

### 人生巅峰

**人生巅峰** 对应语言标准、丰富宿主和数据协议共同形成生态。程序可以在浏览器、服务器和工具链之间迁移，但每次迁移仍要重验 API、权限、事件调度和数据边界。

<Term def="语言语义、宿主生态和数据协议共同成熟并广泛协作的阶段；可移植性来自清晰边界，不来自假设所有环境相同。">
  人生巅峰
</Term>

## 五步重放一次 JavaScript 行为

<Stepper>

<Step title="1. 解析脚本并固定输入">

记录源码、语言版本和预期语法结构。正常样本使用纯语言表达式，边界样本加入宿主名称，故障样本把 JSON 文本放进代码执行路径。

<Crv18Section0501JavaScriptDiagram />

</Step>

<Step title="2. 创建执行上下文">

记录函数、变量、对象和闭包状态，区分语言创建的值与宿主注入的全局对象。相同源码换宿主时，先比较环境合同再比较结果。

<Crv18Section0501EvidenceDiagram />

</Step>

<Step title="3. 访问宿主 API">

固定 API、参数、权限和返回方式；浏览器与服务器样本只改变宿主边界。记录调用是否发出、错误来自语言还是宿主，以及是否产生异步任务。

<Crv18Section0501JavaScriptLab />

</Step>

<Step title="4. 排入任务并观察顺序">

把同步日志、任务入队和回调执行分开记录。边界样本让回调修改共享状态，验证当前脚本结束后才读取异步结果。

<Crv18Section0501EvidenceDiagram />

</Step>

<Step title="5. 产生结果并复位验证">

检查页面状态、返回值或序列化数据，确认 JSON 仍是数据。点击实验的“重置实验”，确认脚本、宿主、任务轨迹和结果回到同一基线。

</Step>

## 正常、边界与故障证据矩阵

<Crv18Section0501EvidenceDiagram />

| 样本 | 只改变的变量                | 预期判定                        | 必存证据                   |
| ---- | --------------------------- | ------------------------------- | -------------------------- |
| 正常 | 纯语言表达式与结构化数据    | 解析、执行、序列化结果可解释    | 源码、语言版本、数据值     |
| 边界 | 宿主 API 或异步任务         | 环境和调度边界明确，顺序可重放  | 宿主、权限、入队与执行日志 |
| 故障 | 把 JSON 当代码或 API 不存在 | 拒绝并指出首个语言/宿主边界错误 | 输入、错误、复位轨迹       |

## 故障诊断：先分语言、宿主和数据

1. **解析与语义**：查语法、值、函数和执行上下文；解析失败不能归咎于浏览器 API，数据解析也不能走代码执行回退。
2. **宿主边界**：查运行环境、权限、全局对象、API 版本和网络/文件限制；同一语言代码在不同宿主的能力不必相同。
3. **任务顺序**：查同步日志、入队时间、回调执行和共享状态写入；注册成功不等于回调已经执行。
4. **结果与数据**：查页面状态、返回值和 JSON 结构；数据结果正确也不能证明中间调用顺序或安全边界正确。

如果浏览器代码搬到服务器失败，先比较宿主 API；如果 JSON 解析触发副作用，移除代码执行路径并保存原始输入；如果页面先读到旧状态，重放同步与任务日志。每次只改变一个语言、宿主或数据边界。

## 术语与边界

本页五个术语都绑定到实验中的执行节点或状态文本：

- **出世**：脚本解析为可执行结构。
- **成长**：语言执行上下文、函数和对象模型扩展能力。
- **第一桶金**：首次调用宿主 API 产生外部效果。
- **发明JSON**：数据格式独立于代码执行。
- **人生巅峰**：语言、宿主和协议形成可协作生态。

## 练习

<Exercises>

**问题 1：** 为什么同一段 JavaScript 在浏览器能访问 `document`，换到服务器却失败？

<Answer>

因为 ECMAScript 规定语言语义，`document` 属于浏览器宿主提供的 API。迁移到服务器时应先核对宿主能力、权限和替代接口，不能把缺少宿主对象当成语言解析错误。

</Answer>

**问题 2：** 为什么 JSON 解析不应该通过执行字符串完成？

<Answer>

JSON 是有限数据格式，不包含任意函数和语句。执行字符串会把外部数据升级为代码并引入副作用；应使用 JSON 专用解析器，校验结构和错误，再把得到的值交给业务处理。

</Answer>

**问题 3：** 修改实验，让一个异步回调更新状态；写出需要保存的三类顺序证据。

<Answer>

应保存同步脚本的日志顺序、任务入队与回调执行的时间线、以及状态从旧值到新值的写入结果。重置后还要证明宿主、任务队列、共享状态和输出回到基线。

</Answer>

</Exercises>

## 本页小结

- JavaScript 语言语义由 ECMAScript 规定，宿主提供环境能力，任务调度决定异步顺序，JSON 只承载数据。
- 解析通过、API 可调用、回调已执行和页面结果可见是不同证据，不能互相替代。
- 诊断先分语言、宿主、任务和数据边界，再用同一输入重放修复。

读完后的自测问题是：面对“浏览器能跑、服务器不能跑”“JSON 触发副作用”或“异步状态顺序错乱”，你能否指出首个边界错误并保存可重放证据？
