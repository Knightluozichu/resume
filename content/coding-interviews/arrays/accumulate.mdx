## 直觉引入

把“子数组和”反复计算时，你常常会把同一段区间重复加很多次。  
前缀和的思想是把所有从起点到当前位置的累计结果先算好，每次询问只做两次取值和一次减法。  
这是一种典型的“把重复计算外包给预处理”的优化。

## 概念讲解

设数组为 `nums`，定义：

$$
\text{prefix}[i] = nums[0] + nums[1] + \cdots + nums[i]
$$

递推关系：

$$
\text{prefix}[0] = nums[0], \quad \text{prefix}[i] = \text{prefix}[i-1] + nums[i]
$$

有了 `prefix` 后，区间和可直接计算为：

$$
sum(l, r)=prefix[r]-prefix[l-1]\ (l>0),\quad sum(0,r)=prefix[r]
$$

工程上常见的坑是：只返回总和，没把每个前缀都保留下来，后续查询就失去优势；或者在大数据范围上直接用 `int` 溢出。

## 思考引导

### 1) 先问问题，不先写公式
这个题不是在问“前缀和怎么写”，而是问“我是否面对的是重复区间查询”。如果每次都要回头加一段区间，那么最合理的动作是先做索引化压缩。

### 2) 识别不变式
定义好前缀含义后，关键不变式是：prefix[i] 只表示从 0 到 i 的累计和，且任何区间和都可由两个边界差值恢复。只要不变式成立，后续查询都在 O(1)。

### 3) 为什么它一定成立
区间和的定义天然是加法可加性。你在一条轴上保存“到达每点的累计”，则两端点的差就是中间段，这种可消元关系在数学上完全稳定，不受元素顺序变化影响。

### 4) 常见误区
最典型错误不是公式写错，而是把“输入为空”“索引边界”“数值溢出”忽略。前缀和能降复杂度，但前提是你把边界和类型选对。

### 5) 你能找到一个反例吗
如果把数组设成 [1, -1, 1] 并随机查询 [1,2] 之类区间，边界算错一个索引就会整段结果翻倍错误。用小反例快速检验公式和边界处理是否一致。

### 6) 迁移到下一题
任何有“多次区间查询 + 不频繁更新”的题都先考虑前缀化。把“要不要先预处理”这件事提到解题前，而不是把时间都花在重复扫描。

## 代码对照

### C++ 实现

```cpp
#include <vector>

class Solution {
public:
    std::vector<long long> buildPrefixSums(const std::vector<int>& nums) {
        if (nums.empty()) {
            return {};
        }

        std::vector<long long> prefix;
        prefix.reserve(nums.size());

        long long current = 0;
        for (int value : nums) {
            current += value;
            prefix.push_back(current);
        }

        return prefix;
    }
};
```

### TypeScript 实现

```typescript
function buildPrefixSums(nums: number[]): number[] {
  if (!nums || nums.length === 0) {
    return [];
  }

  const prefix: number[] = [];
  let current = 0;

  for (const value of nums) {
    current += value;
    prefix.push(current);
  }

  return prefix;
}
```

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 区间和查询比对很慢，时间超阈值。  
  <strong>原因 →</strong> 仍然对每次查询做嵌套求和，重复扫描导致 $O(n)$。  
  <strong>修复 →</strong> 先构建一次前缀和，查询阶段直接做两次下标读取与一次减法。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 数据和较大时结果出现负值。  
  <strong>原因 →</strong> 用了 `int`，累计时发生溢出。  
  <strong>修复 →</strong> 用 `long long` / 更高精度数值类型保存累计结果。
</Callout>

<Callout type="tip">
  <strong>验收提醒：</strong> 对同一组样例同时验证前缀和与区间和，能一口气打掉大部分边界遗漏。
</Callout>
