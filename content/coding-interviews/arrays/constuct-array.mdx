<Objectives>

- 能理解为什么不能直接用“全积除以自身”解决。
- 能在 $O(n)$ 时间内给出左右乘积预处理方案。
- 能处理包含 0 的边界，并在代码中避免越界。

</Objectives>

## 直觉引入

若题目允许除法，`total / A[i]` 很快，但存在两个坑：`A[i]=0` 的场景会让结果不可逆，且题目常常明确“不能用除法”。  
更稳定的办法是把每个位置的贡献拆成“左侧累计积”和“右侧累计积”。

## 概念讲解

定义：

$$left[i]=A[0]\times\cdots\times A[i-1],\quad right[i]=A[i+1]\times\cdots\times A[n-1]$$

那么答案是 `B[i]=left[i]*right[i]`。  
`left` 可以从左到右一次算完，`right` 可在从右到左算，或者直接在结果数组上复用第二次遍历。

## 思考引导

### 1) 先问问题，不先写除法
这题问的是“每个位置排除自己后的乘积”，不是问“能不能除掉一个总积”。如果数组包含 0，或题目禁止除法，直接算总积是故障点。

### 2) 识别不变式
每个 B[i] 实际是左边积与右边积的乘积。左右积各自只与边界方向有关，能独立预处理，这就是你能降到线性时间的核心结构不变式。

### 3) 为什么它一定成立
乘积运算对序列有“区间可拆分”属性。把 A 切成 [0..i-1] 与 [i+1..n-1] 两段后，结果重组不依赖于中间项。

### 4) 常见误区
把“非零前提”默认为真或者把前后缀混用在一次乘法里，都会在含零数据上失真；另一个坑是下标循环方向没对齐导致重复乘。

### 5) 你能找到一个反例吗
数组 [1,0,3,4] 下，任何一次“总积除法”都失效。若左/右不对称就会让某些位置永远 0 或错乘。

### 6) 迁移到下一题
遇到“排除自身”或“共享同一前后缀信息”的场景，先问是否能拆成两个独立累积方向。不要一上来就触及除法和重复遍历。

## 实现代码

### C++ 实现

```cpp
#include <vector>

class Solution {
public:
    std::vector<int> constructArr(const std::vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return {};

        std::vector<long long> ans(n, 1);
        long long left = 1;
        for (int i = 0; i < n; ++i) {
            ans[i] = left;
            left *= nums[i];
        }

        long long right = 1;
        for (int i = n - 1; i >= 0; --i) {
            ans[i] *= right;
            right *= nums[i];
        }

        return std::vector<int>(ans.begin(), ans.end());
    }
};
```

### TypeScript 实现

```typescript
function constructArray(nums: number[]): number[] {
  const n = nums.length;
  if (n === 0) return [];

  const ans = new Array<number>(n).fill(1);
  let left = 1;
  for (let i = 0; i < n; i++) {
    ans[i] = left;
    left *= nums[i];
  }

  let right = 1;
  for (let i = n - 1; i >= 0; i--) {
    ans[i] *= right;
    right *= nums[i];
  }

  return ans;
}
```

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 遇到 0 时答案全错。  
  <strong>原因 →</strong> “全积/除法”会把 0 覆盖成异常情况。  
  <strong>修复 →</strong> 使用左右乘积拆解，即便有 0 也可正确计算（多个 0 时更是如此）。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 写出 `int` 版本后大规模测试随机溢出。  
  <strong>原因 →</strong> 乘积规模可快速超过 32 位。  
  <strong>修复 →</strong> 按题目约束选 `long long` 或大整数表示，若需要则返回溢出版本说明。
</Callout>
