<Objectives>

- 能解释 0（大小王）如何作为“可补齐资源”工作。
- 能给出排序后只靠首尾缺口判断的 $O(n\log n)$ 方案。
- 能处理重复非零牌导致失败的边界。

</Objectives>

## 直觉引入

把牌从小到大排好后，非零牌若有重复则必定不能构成顺子。  
其余缺口由 0 来补齐即可：`max-min` 不能超过 4，并且总缺口数不超过 0 的数量。

## 概念讲解

对排序后的数组：

1. 统计所有 `0`（空牌），记为 `jokers`。
2. 从第一个非零开始，相邻牌 `nums[i]` 与 `nums[i+1]`：
   - 若相同，直接失败（除 0 外）。
   - 若有间隙，累加 `gap += nums[i+1]-nums[i]-1`。
3. 成立条件：`gap <= jokers` 且最大最小值差值在 `[0,4]`。

## 思考引导

### 1) 先问问题，不先比大小
这题的真实问题是“是否可重排为连续区间”，不是“最长是什么”。顺子成立与否取决于间距覆盖，不取决于原始先后顺序。

### 2) 识别不变式
在去重后，连续性可由“最小值到最大值之间长度”和“有效元素数量是否一致”判断。重复牌会制造零间距，需要优先剥离。

### 3) 为什么它一定成立
若一组数是连续的，除了去掉重复后，其值域长度与元素数量必须一致，且每个相邻步长差应满足可接续关系。这个条件来自整数集合的闭包性质。

### 4) 常见误区
把重复数直接参与 gap 统计会把间隙压缩，让错误结果看起来“更小”。另外排序本身只负责规范化，不是最终判断。

### 5) 你能找到一个反例吗
输入 [1,2,2,3] 会被错误地判作可连续，如果不先去重。用这一组会检验你是否把去重写进了核心判断。

### 6) 迁移到下一题
任何要判定“按区间覆盖是否无缺失”的题，优先先标准化元素集合，再用值域长度、最小/最大值做可行域约束。

## 实现代码

```cpp
#include <algorithm>
#include <vector>

class Solution {
public:
    bool isContinuous(const std::vector<int>& nums) {
        if (nums.size() != 5) {
            return false;
        }

        std::vector<int> arr = nums;
        std::sort(arr.begin(), arr.end());

        int jokers = 0;
        int i = 0;
        while (i < 5 && arr[i] == 0) {
            ++jokers;
            ++i;
        }

        int gap = 0;
        for (; i < 4; ++i) {
            if (arr[i] == arr[i + 1]) {
                return false; // 非零重复
            }
            gap += arr[i + 1] - arr[i] - 1;
        }

        return gap <= jokers && (arr[4] - arr[jokers] <= 4);
    }
};
```

```typescript
function isStraight(cards: number[]): boolean {
  if (cards.length !== 5) return false;
  const arr = [...cards].sort((a, b) => a - b);

  let jokers = 0;
  let i = 0;
  while (i < arr.length && arr[i] === 0) {
    jokers++;
    i++;
  }

  let gap = 0;
  for (; i < arr.length - 1; i++) {
    if (arr[i] === arr[i + 1]) return false;
    gap += arr[i + 1] - arr[i] - 1;
  }

  return gap <= jokers && arr[arr.length - 1] - arr[jokers] <= 4;
}
```

<Callout type="trap">
  <strong>现象 →</strong> 明明能组成顺子却返回 false。  
  <strong>原因 →</strong> 把 “重复判断” 也当作可用 0 补齐了。  
  <strong>修复 →</strong> 非零重复应直接判定失败，0 不能替代重复牌。
</Callout>
