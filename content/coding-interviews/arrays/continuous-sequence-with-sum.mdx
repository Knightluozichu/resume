<Objectives>

- 能说明窗口和在右移/左移时为何只需加减一次。
- 能用双指针在 $O(n)$ 找到所有连续正数序列。
- 能分析窗口为空、sum 无解、边界值下的正确性。

</Objectives>

## 直觉引入

所有数都是正数时，窗口和随右端增加必定增大；随左端收缩必定减小。这种单调性让“连续区间和”非常适合双指针。

## 概念讲解

定义 `l=1, r=1, sum=0`（若用值域内数字），不断扩展 `r` 累加，`sum>target` 则移动 `l`。  
当 `sum==target` 时记录窗口 `[l, r-1]` 并继续右移尝试其他解。  
复杂度是每个元素进/出窗口一次，故为 $O(n)$。

## 思考引导

### 1) 先问问题，不先枚举
你不是在问“有几个子序列”，而是在问“给定正数，如何让区间和定位到 S”。只要元素都为正，窗口天然具备单调收缩性。

### 2) 识别不变式
滑动窗口维护 [l,r] 和当前和。左边界只会右移，和只会在扩张/收缩下有单调变化。这个单调行为是你每次决策正确性的基础。

### 3) 为什么它一定成立
在正数组中，添加正数和移除左端都只会改变和的方向性，没机会出现“移除后又更小于目标但又增加其他复杂状态”。

### 4) 常见误区
把它当作两重循环会退化到 O(n^2)。另一个常见错是没在和大于 S 时持续收缩，导致卡在某段区间上。

### 5) 你能找到一个反例吗
数组 [1,2,3,4] S=3。若只在单次循环里收缩一次，你可能错过窗口 [1,2]。边界条件要用 while 而非 if。

### 6) 迁移到下一题
这类“连续 + 约束可单调”的问题，优先考虑窗口而不是枚举。把“移动次数”当核心指标，会自然把复杂度压下去。

## 实现代码

```cpp
#include <vector>

class Solution {
public:
    std::vector<std::vector<int>> findContinuousSequences(int target) {
        std::vector<std::vector<int>> result;
        if (target < 3) return result;

        int left = 1, right = 1, sum = 0;
        while (left <= target / 2) {
            if (sum < target) {
                sum += right;
                ++right;
            } else if (sum > target) {
                sum -= left;
                ++left;
            } else {
                std::vector<int> seq;
                for (int v = left; v < right; ++v) seq.push_back(v);
                result.push_back(seq);

                sum -= left;
                ++left;
            }
        }
        return result;
    }
};
```

```typescript
function findContinuousSequences(target: number): number[][] {
  const result: number[][] = [];
  if (target < 3) return result;

  let left = 1;
  let right = 1;
  let sum = 0;

  while (left <= target / 2) {
    if (sum < target) {
      sum += right;
      right++;
    } else if (sum > target) {
      sum -= left;
      left++;
    } else {
      const seq: number[] = [];
      for (let v = left; v < right; v++) seq.push(v);
      result.push(seq);
      sum -= left;
      left++;
    }
  }

  return result;
}
```

<Callout type="trap">
  <strong>现象 →</strong> `sum==target` 后直接 `right++`，漏掉下一组解。  
  <strong>原因 →</strong> 需要先记录当前解，再缩小窗口继续搜索。  
  <strong>修复 →</strong> 记录后执行 `sum -= left; left++`。
</Callout>
