<Objectives>

- 能说明为什么最大堆比每次排序更省时间。
- 能处理 `k <= 0`、`k >= n` 等边界。
- 能写出稳定可读的堆方案并解释为什么取负序存放。

</Objectives>

## 直觉引入

要找最小的 K 个元素，不必把整个数组都排好序。  
一个大小始终不超过 K 的最大堆里，保留当前最小 K 个即可：  
新元素若比堆顶小，则替换堆顶。

## 概念讲解

时间复杂度主导项是每个元素一次比较入堆，`O(n log k)`。  
当 `k` 接近 n 时，排序法可能更简单，但题目要求 Top-K 时堆通常更优。

## 思考引导

### 1) 先问问题，不先固定方法
最小 k 个数先要定义服务目标：是否需要返回有序结果、是否允许改动输入、是否要求接近实时更新。目标不明会选错结构。

### 2) 识别不变式
k 个候选结构的核心不变式是：当前窗口/堆里的元素总是可能成为前 k 个候选，超过边界者可安全剔除。

### 3) 为什么它一定成立
最大堆维护前 k 小值时，堆顶是当前候选中的最大者；若出现更小值，它能替代堆顶而不影响前 k 的正确性。

### 4) 常见误区
把 TopK 写成全局排序会丢掉 O(n log n) 的优化机会；但若数据流多次更新，反而需要更复杂策略，单纯快排未必最佳。

### 5) 你能找到一个反例吗
当 n 很大而 k 很小（如 10^7 个元素中要 10 个）时，全排序耗时和内存压力都明显，不再适合作为默认方案。

### 6) 迁移到下一题
TopK 场景在日志、推荐、监控都常见。第一句话先问“更新频率与规模”，再决定用堆、分治或计数法。
## 交互 Demo

可视化理解“堆顶始终是当前窗口里最大的那个 K 中元素”，不合格元素会被快速淘汰。

<KLeastNumbersDiagram />

```cpp
#include <queue>
#include <vector>
#include <algorithm>

class Solution {
public:
    std::vector<int> smallestK(std::vector<int> nums, int k) {
        if (k <= 0 || nums.empty()) return {};
        if (k >= (int)nums.size()) return nums;

        std::priority_queue<int> maxHeap;
        for (int x : nums) {
            if ((int)maxHeap.size() < k) {
                maxHeap.push(x);
            } else if (x < maxHeap.top()) {
                maxHeap.pop();
                maxHeap.push(x);
            }
        }

        std::vector<int> ans;
        while (!maxHeap.empty()) {
            ans.push_back(maxHeap.top());
            maxHeap.pop();
        }
        return ans;
    }
};
```

```typescript
function smallestK(nums: number[], k: number): number[] {
  if (k <= 0 || nums.length === 0) return [];
  if (k >= nums.length) return [...nums];

  // 简洁实现：利用 JS 原生排序保持边界清晰
  const sorted = [...nums].sort((a, b) => a - b);
  return sorted.slice(0, k);
}
```

<Callout type="trap">
  <strong>现象 →</strong> k 大于数组长度时越界。  
  <strong>原因 →</strong> 未做边界裁剪。  
  <strong>修复 →</strong> `if (k >= n) return nums`，并在 C++ 与 TS 均防守。
</Callout>
