<Objectives>

- 能写出 `dp[i][j] = grid[i][j] + max(dp[i-1][j], dp[i][j-1])`。
- 能解释为什么只能从上方或左方转移。
- 能给出空间优化版本。

</Objectives>

## 直觉引入

走到某格 `(i,j)` 只有两种来源：上 `(i-1,j)` 与左 `(i,j-1)`。  
因此最优路径到达该格完全由这两个前驱的最优值决定，这是标准的局部最优转移。

## 概念讲解

边界处理：
- 第一行只能从左边来；
- 第一列只能从上边来。  
其余位置取二者最大值。

## 思考引导

### 1) 先问问题，不先走路径穷举
你不是在找一条手工可行路径，而是在问“每个格点的最优值依赖谁”。这就是 DP 定义问题，不是 DFS 写法优先。

### 2) 识别不变式
到达某格 (i,j) 的最优收益只与上方和左方最优值相关。这个不变式让每个格点可由一个公式闭环计算。

### 3) 为什么它一定成立
网格约束保证移动只能向右或向下。任一到达路径都必须经过这两个来源之一，因此全局最优可由局部最优递推出。

### 4) 常见误区
把网格边界和起点状态写反会导致连锁错误。另一个坑是没明确行列越界的初始行列处理。

### 5) 你能找到一个反例吗
2x2 小网格已足以检验边界递推是否统一（第一行、第一列的初始化规则）是否一致。

### 6) 迁移到下一题
任何二维路径累计、最短路径、最大价值问题都可复用“局部状态依赖 + 边界初始化”这套骨架。

```cpp
#include <vector>
#include <algorithm>

class Solution {
public:
    int maxValue(std::vector<std::vector<int>>& grid) {
        if (grid.empty() || grid[0].empty()) return 0;
        int m = grid.size(), n = grid[0].size();

        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                if (i == 0 && j == 0) continue;
                int top = (i > 0) ? grid[i - 1][j] : -1;
                int left = (j > 0) ? grid[i][j - 1] : -1;

                if (i == 0) grid[i][j] += left;
                else if (j == 0) grid[i][j] += top;
                else grid[i][j] += std::max(top, left);
            }
        }
        return grid[m - 1][n - 1];
    }
};
```

```typescript
function maxValue(grid: number[][]): number {
  if (!grid.length || !grid[0].length) return 0;
  const m = grid.length;
  const n = grid[0].length;

  for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {
      if (i === 0 && j === 0) continue;
      const fromTop = i > 0 ? grid[i - 1][j] : -Infinity;
      const fromLeft = j > 0 ? grid[i][j - 1] : -Infinity;
      if (i === 0) grid[i][j] += fromLeft;
      else if (j === 0) grid[i][j] += fromTop;
      else grid[i][j] += Math.max(fromTop, fromLeft);
    }
  }
  return grid[m - 1][n - 1];
}
```

<Callout type="trap">
  <strong>现象 →</strong> 第一行/列值算错。  
  <strong>原因 →</strong> 误把 `-INF` 当 0，导致路径可以“从不存在的方向转入”。  
  <strong>修复 →</strong> 明确边界条件分支。
</Callout>
