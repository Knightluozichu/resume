## 直觉引入

在常规的直线单链表中，指针随着 `next` 的延伸最终一定会指向 `null`。但如果链表在某处发生弯折，指向了前面已经出现过的某个节点，链表便会形成一个**环（Cycle）**。此时一旦在此链表上进行普通遍历，程序就会陷入**死循环**。

我们要解决两个核心问题：
1. **如何判断链表中是否存在环？**
2. **如果存在环，如何精确找出环的入口节点？**

这里我们可以引入生活中的**『闭合操场跑道』**概念来建立直觉：

> **跑道追击模型**：想象两个人在跑道上跑步，甲的速度是乙的 2 倍（甲每次跑 2 米，乙每次跑 1 米）。
> 
> - **情况 A（直线路跑）**：如果他们是在一条笔直且无限长的公路上奔跑，由于速度差异，甲会把乙越拉越远，两人**永远不会再次相遇**。
> - **情况 B（环形跑道）**：如果他们是在一个封闭的环形操场跑道上奔跑，即使起点相同或不同，只要跑道是个闭环，跑得快的甲就必定会**“套圈”**乙，两人必然会在跑道上的某处**再次相遇**。
> 
> 因此，如果我们在链表上模拟这两名跑者，若他们能够相遇，就足以铁证如山地证明：**此链表中必有环！**

## 概念讲解

### 1. 寻找环入口的数学证明

很多候选人在面试中能够背出“快慢指针在相遇后，重置一个指针到头部，同步 1 步/次前进，再次相遇即是入口”的口诀，但当面试官要求给出**严密的数学推导**时，往往因逻辑混乱而铩羽而归。

下面我们通过严谨的公式来证明这个算法的正确性：

设：
- 链表头节点到环入口节点的距离为 $a$。
- 环的周长（即环内包含的节点数）为 $L$。
- 慢指针 `slow` 和快指针 `fast` 首次相遇点距离环入口节点的顺时针距离为 $b$。（由此可知，相遇点顺时针走到环入口节点的剩余距离为 $L - b$）。

```
           a (头到入口)            b (入口到相遇点)
头 [1] ───────────────> 入口 [4] ───────────> 相遇点 [5]
                        ▲                        │
                        │                        │ L - b
                        └────────────────────────▼
                               环 (周长 L)
```

当 `slow` 和 `fast` 首次相遇在相遇点时：
1. **慢指针 `slow` 走的步数**：
   
   $$S_{slow} = a + b$$
   
   *注意：慢指针进入环后，在走完第一圈之前（即在环内走的步数必定小于 $L$），必定会被快指针追上。因此慢指针在环内走的距离就是 $b$。*

2. **快指针 `fast` 走的步数**：
   
   $$S_{fast} = a + k \cdot L + b \quad (k \ge 1)$$
   
   *其中 $k$ 为快指针在相遇前已经在环内转过的圈数。因为快指针先进环且速度快，所以在相遇前它至少已经在环内转了 1 圈（$k \ge 1$）。*

3. **速度关系**：
   快指针的速度是慢指针的 2 倍，所以在相同时间内快指针走的步数是慢指针的 2 倍：
   
   $$S_{fast} = 2 \cdot S_{slow}$$
   
   将上述 1、2 式代入，可得：
   
   $$a + k \cdot L + b = 2(a + b)$$
   
   化简得到：
   
   $$a = k \cdot L - b$$
   
   为了显式得出相遇点距离入口的剩余距离 $L - b$，我们将上式进行拆分重组：
   
   $$a = (k - 1)L + (L - b)$$

#### 数学物理含义分析：
- **左边 $a$**：代表一个指针从**链表头节点**出发，走到**环入口**所需的步数。
- **右边 $(k-1)L + (L-b)$**：代表另一个指针从**相遇点**出发，向前走 $L-b$ 步（到达入口），然后再在环内绕 $k-1$ 圈所需的步数。

由于这两者在数值上完全相等，因此：如果在相遇后，我们**将慢指针（或快指针）重置回链表头节点 `head`，而让另一个指针留在原地（相遇点），然后两者以相同的速度（每次 1 步）同步向前滑动**。当重置回头部的指针走了 $a$ 步到达入口时，留在原地的指针也刚好走了 $(k-1)L + (L-b)$ 步。因为绕环整圈不改变最终所处的位置，留在原地的指针走完这些步数后**也必然停留在环的入口节点上**。

此时，两指针在此相遇，相遇节点即为所求的环入口！

---

### 2. 计算环的周长（大小）

在环检测成功后，如果面试官追加提问：“如何求这个环的大小（包含多少个节点）？”

这非常简单，同样只需要常数级别的辅助变量：
- 当快慢指针相遇时，让其中一个指针（例如 `slow`）留在相遇点原地不动。
- 让另一个指针（例如 `fast`）继续一步一步向前移动，每次移动时计数器加 1。
- 当 `fast` 指针再次回到 `slow` 所处的相遇点时，计数器的数值就是环的周长 $L$。
- 该过程的时间复杂度为 $O(L)$（远小于 $O(N)$），空间复杂度为 $O(1)$。

## 代码对照

### 核心实现：寻找链表环入口

以下是 C++ 和 TypeScript 的核心实现对照。注意在代码中利用卫语句先将空链表或单节点无环链表予以安全拦截。

<CodeTabs>
  <Tab label="C++ 实现">
```cpp
struct ListNode {
    int m_nValue;
    ListNode* m_pNext;
    ListNode(int val) : m_nValue(val), m_pNext(nullptr) {}
};

class Solution {
public:
    ListNode* EntryNodeOfLoop(ListNode* pHead) {
        // 1. 防御性检查：链表为空或仅有一个节点，不可能成环
        if (pHead == nullptr || pHead->m_pNext == nullptr) {
            return nullptr;
        }

        ListNode* pSlow = pHead;
        ListNode* pFast = pHead;
        bool hasCycle = false;

        // 2. 第一阶段：判断是否有环并寻找相遇点
        while (pFast != nullptr && pFast->m_pNext != nullptr) {
            pSlow = pSlow->m_pNext;
            pFast = pFast->m_pNext->m_pNext; // 快指针每次移动 2 步

            if (pSlow == pFast) {
                hasCycle = true;
                break; // 相遇，说明有环
            }
        }

        // 如果没有环，直接返回 nullptr
        if (!hasCycle) {
            return nullptr;
        }

        // 3. 第二阶段：重置其中一个指针到头节点，两指针同步以 1 步/次等速前进
        pSlow = pHead;
        while (pSlow != pFast) {
            pSlow = pSlow->m_pNext;
            pFast = pFast->m_pNext; // 此时快指针也每次移动 1 步
        }

        // 再次相遇点即为环入口节点
        return pSlow;
    }
};
```
  </Tab>
  <Tab label="TypeScript 实现">
```typescript
class ListNode {
    val: number;
    next: ListNode | null = null;
    constructor(val: number) {
        this.val = val;
    }
}

function detectCycle(head: ListNode | null): ListNode | null {
    // 1. 防御性检查：链表为空或仅有一个节点，不可能成环
    if (head === null || head.next === null) {
        return null;
    }

    let slow: ListNode | null = head;
    let fast: ListNode | null = head;
    let hasCycle = false;

    // 2. 第一阶段：检测是否有环并寻找相遇点
    while (fast !== null && fast.next !== null) {
        slow = slow!.next;
        fast = fast.next.next;

        if (slow === fast) {
            hasCycle = true;
            break; // 首次相遇
        }
    }

    // 无环链表直接退出
    if (!hasCycle) {
        return null;
    }

    // 3. 第二阶段：重置 slow 到头节点，两指针等速前进寻找入口
    slow = head;
    while (slow !== fast) {
        slow = slow!.next;
        fast = fast!.next;
    }

    return slow; // 返回再次相遇的入口节点
}
```
  </Tab>
</CodeTabs>

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 试图省去防御性检查，直接执行 <code>fast = fast.next.next</code> 导致运行时发生段错误（Segmentation Fault）或空指针解引用异常。
  <strong>原因 →</strong> 当链表无环且节点数为奇数时，快指针 <code>fast</code> 会走到最后一个节点（此时 <code>fast.next</code> 为 null）。若不做校验，下一步执行 <code>fast.next.next</code> 相当于访问 <code>null.next</code>，从而导致崩溃。
  <strong>修复 →</strong> 循环控制条件必须严格写作 <code>while (fast !== null && fast.next !== null)</code>。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 误认为快慢指针在第一阶段相遇的节点（即相遇点）就是环的入口节点，直接返回了相遇节点。
  <strong>原因 →</strong> 从数学证明中可以看出，相遇点距离入口的顺时针距离为 $b$，只有在极特殊的情况下（例如环长度 $L$ 为 0，实际上不存在；或者 $a = L - b$ 恰好成立）相遇点才会等于入口。在绝大多数情况下，两者并不重合，必须执行第二阶段的重置与等速运动才能确定入口。
  <strong>修复 →</strong> 必须在检测到相遇后，重置一个指针到 <code>head</code>，再同步移动直至二次相遇，不可直接返回首次相遇节点。
</Callout>

## 小结与练习

- **Floyd 判圈算法** 巧妙地利用了封闭环内的相对速度差（相对速度为 1）使得快慢指针在 $O(N)$ 步内必然相遇，从而实现了常数级空间的高效检测。
- 环入口的定位依据了 $a = (k-1)L + (L-b)$ 的数学等价关系，重置其一指针后以等速同步移动即可寻获入口。

<Exercises>
  <Answer question="除了快慢指针法，如果面试官允许使用额外的 $O(N)$ 空间，有什么更直观的方法定位环入口？各有什么优缺点？">
    可以使用**哈希表（Hash Set）**法：
    - **基本思路**：定义一个哈希集合，从头节点开始遍历链表，每访问一个节点，先检查该节点是否已存在于集合中。如果存在，说明我们重新回到了之前访问过的节点，该节点就是环的入口；如果不存在，则将该节点存入集合中，继续访问下一个节点。如果遍历遇到 `null`，说明无环。
    - **对比评估**：
      - **优点**：逻辑极其简单直白，不需要任何数理推导和两阶段处理。
      - **缺点**：空间复杂度为 $O(N)$，对于极长链表会消耗大量额外的内存。而双指针追击法空间复杂度为 $O(1)$，是面试官更期望的最优解。
  </Answer>
  <Answer question="如果链表是一个完全闭合的环（即头节点本身就是环入口，没有直线部分），Floyd 算法能正确工作吗？请推导说明。">
    **完全可以正确工作。**
    - **理论推导**：若链表是完全闭合环，则头节点到环入口的距离 $a = 0$。根据推导公式：
      $$a = (k - 1)L + (L - b) \implies 0 = (k-1)L + (L - b)$$
      因为 $L - b \ge 0$，要使等式成立，必须有 $k = 1$ 且 $L - b = 0 \implies b = L$。
    - **执行轨迹**：两指针第一次在起点 `head` 出发。第一轮追击后，快指针在环内追上慢指针并相遇。由于慢指针没走完一圈（走了 $b = L$ 步，其实刚好绕了一整圈又回到了头节点），因此它们相遇在 `head`。重置慢指针到 `head`（其实原地不动），此时快指针也在 `head`（原地不动），`slow === fast` 条件立即成立，直接返回 `slow`（即 `head`）。逻辑完美闭环。
  </Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="Floyd 判圈算法">
    由罗伯特·弗洛伊德（Robert W. Floyd）设计的一种用于在有限状态机、有向图或链表中寻找环的算法。利用以不同速度在环内行进的两个指针最终必会相遇的物理特性来检测环的存在与入口。
  </GlossaryItem>
  <GlossaryItem term="相遇点 (Meeting Point)">
    在 Floyd 算法的第一阶段，以 2 倍速度行进的快指针与以 1 倍速度行进的慢指针在环内首次相碰撞重合的节点。
  </GlossaryItem>
  <GlossaryItem term="入口节点 (Entry Node of Loop)">
    链表的直线性前驱部分与环形闭合部分的衔接节点，是链表走向闭环状态的物理起点。
  </GlossaryItem>
</Glossary>
