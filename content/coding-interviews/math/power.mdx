## 直觉引入

想象一下，你手中有一张平整的超大白纸。如果要把这张白纸折叠成具有 $1024$ 层厚度的纸折叠物，你需要折叠多少次？

直觉上，你肯定不会去买 $1024$ 张纸一张张粘起来（这相当于 $O(n)$ 的朴素累乘）。你只需要把这张纸**对折**即可。
- 对折 1 次：$2$ 层厚度
- 对折 2 次：$4$ 层厚度
- 对折 3 次：$8$ 层厚度
- ...
- 对折 10 次：$1024$ 层厚度！

每次对折，厚度都会翻倍。原本需要堆叠 $1024$ 次的操作，通过连续对折，只需要 $10$ 次就能搞定。

这种「对折翻倍」的降维打击，就是本章我们要研究的 <Term def="一种通过折半减小乘法次数的高效计算 $x^n$ 的算法，其核心思想是二进制分解或分治，将时间复杂度从 $O(n)$ 降至 $O(\log n)$。">快速幂</Term> 算法。我们要解决的核心问题是：如何在计算机内存中高效计算 $x^n$，同时应对浮点数精度丧失、负指数以及整型边界溢出等一系列真实的工程地雷。

## 概念讲解

计算 $x^n$（$x$ 为双精度浮点数，$n$ 为整数）最朴素的想法是循环累乘 $n$ 次，时间复杂度为 $O(n)$。但当 $n$ 达到上亿级别时，这种方法在时限内几乎注定超时。

### 分治递推公式：快速幂的数学核心

利用分治法，我们可以把 $x^n$ 的计算折半拆解：
- 当指数 $n$ 为偶数时：
  $$x^n = x^{n/2} \cdot x^{n/2} = (x^{n/2})^2$$
- 当指数 $n$ 为奇数时：
  $$x^n = x \cdot x^{(n-1)/2} \cdot x^{(n-1)/2} = x \cdot (x^{(n-1)/2})^2$$

通过这种拆分，计算 $x^n$ 转化为计算 $x^{n/2}$，计算规模每次减半，总共只需要进行 $\log n$ 次乘法。

例如，要计算 $x^{32}$：
$$x^{32} = (x^{16})^2 \rightarrow x^{16} = (x^8)^2 \rightarrow x^8 = (x^4)^2 \rightarrow x^4 = (x^2)^2 \rightarrow x^2 = (x)^2$$
原本需要 $31$ 次乘法，现在只需 $5$ 次。

### 三大工程地雷与边界防护

看似简单的算法在实际面试和工程实现中却布满陷阱，主要包含以下三个核心考点：

#### 1. 浮点数精度陷阱

在计算机中，浮点数采用 IEEE 754 规范以二进制分数近似表示。因为很多十进制小数（如 `0.1`）无法用二进制精确表达，计算过程中会产生微小的舍入误差。
- **错误写法**：`if (base == 0.0)`
- **后果**：可能因为精度丢失导致 `base` 极度接近 0（如 `1e-18`）但并不完全等于 0.0，从而绕过判断，导致后续出现除以 0 的崩溃。
- **防御策略**：利用 <Term def="由于计算机采用 IEEE 754 浮点数规范表示实数，无法精确表示所有十进制小数，因此直接做等号比较是不安全的，必须使用误差限判断。">浮点数精度限制</Term>，判断其差值的绝对值是否小于一个极小的阈值（如 `1e-9`）：
  ```cpp
  if (std::abs(base - 0.0) < 1e-9)
  ```

#### 2. 负指数与除零危机

当指数 $n$ 为负数时，根据数学公式 $x^{-n} = \frac{1}{x^n}$，我们需要先求出 $x$ 的正次方，然后再取倒数。
但这里必须防范底数 $x=0$。
- 如果 $x = 0$ 且 $n < 0$，求倒数相当于计算 $1/0$，在计算机中会引发 division by zero 崩溃或产生非法的 `Infinity` 结果。
- **防御策略**：在计算前判断，若底数为 0 且指数小于等于 0，必须视为非法输入（报错、抛异常或返回 0）。

#### 3. INT_MIN 有符号整型溢出陷阱

在 C++ 等底层语言中，32 位有符号整型 `int` 的范围是 `[-2147483648, 2147483647]`。
- **致命陷阱**：当 $n = \text{INT\_MIN} = -2147483648$ 时，如果直接将其转为正数 `absN = -n`，所得的 `2147483648` 超出了 `int` 的最大上限 `2147483647`。
- **后果**：在 C++ 中，这会导致 <Term def="计算机整型变量超出其最大表示范围时发生的现象。在 32 位有符号数中，-INT_MIN 无法用同等类型表示，会引发越界或未定义行为。">整型溢出</Term>，产生未定义行为，`-n` 结果仍会变回 `-2147483648`，使程序陷入死循环或算出荒谬的 0 值。
- **防御策略**：在转换符号前，先将 $n$ 强转为 64 位有符号整型 `long long` 或者无符号整型 `unsigned int`，再取绝对值：
  ```cpp
  long long absN = std::abs(static_cast<long long>(n));
  ```

## 代码对照

为了实现高效率，我们通常采用**非递归（迭代）快速幂**。它不需要消耗额外的调用栈空间。

以下是 C++（带完整的浮点数比对及 64 位整型溢出防护）与 TypeScript（带安全数值取整防御）的实现对照：

<CodeTabs>
  <Tab label="C++">
```cpp
#include <cmath>
#include <stdexcept>

class Solution {
public:
    double myPow(double x, int n) {
        // 边界防护 1：底数为 0 且指数为负，抛出非法数学输入异常
        if (std::abs(x - 0.0) < 1e-9 && n < 0) {
            throw std::invalid_argument("Division by zero: 0 raised to a negative power is invalid.");
        }

        // 边界防护 2：0 的 0 次方或正次方
        if (std::abs(x - 0.0) < 1e-9) {
            return 0.0;
        }
        if (n == 0) {
            return 1.0;
        }

        // 防御性转换：用 64 位 long long 承接 n 的绝对值，避免 INT_MIN 取反后发生有符号整数溢出
        long long absN = n;
        if (n < 0) {
            absN = -absN; // 安全转为正数 2147483648
        }

        double result = 1.0;
        double currentProduct = x;

        // 迭代快速幂主循环：O(log n)
        while (absN > 0) {
            // 通过位运算判断当前指数最低位是否为 1（奇数）
            if ((absN & 1) == 1) {
                result *= currentProduct;
            }
            currentProduct *= currentProduct; // 底数自乘翻倍
            absN >>= 1;                       // 指数减半（右移 1 位）
        }

        // 若原指数为负数，返回结果的倒数
        return n < 0 ? 1.0 / result : result;
    }
};
```
  </Tab>
  <Tab label="TypeScript">
```typescript
function myPow(x: number, n: number): number {
  // 边界防护 1：在 JavaScript/TypeScript 中底数为 0 且指数为负数时，数学上是非法的
  if (x === 0 && n < 0) {
    throw new Error("Division by zero: 0 raised to a negative power is invalid.");
  }

  // 边界防护 2：底数为 0 的正数次方
  if (x === 0) {
    return 0;
  }
  if (n === 0) {
    return 1;
  }

  // TS/JS 的 number 是双精度浮点数，直接取绝对值没有 32 位整型溢出问题
  let absN = Math.abs(n);
  let result = 1.0;
  let currentProduct = x;

  // 迭代快速幂
  while (absN > 0) {
    // 避开 JS 32位位操作溢出限制，使用算术模运算判断奇偶性
    if (absN % 2 === 1) {
      result *= currentProduct;
    }
    currentProduct *= currentProduct;
    // 使用 Math.floor 除以 2 代替位移，防止超大指数在位运算时发生 32 位截断
    absN = Math.floor(absN / 2);
  }

  return n < 0 ? 1.0 / result : result;
}
```
  </Tab>
</CodeTabs>

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 在 C++ 中输入底数 2.0，指数为 -2147483648 (INT_MIN)，程序卡死，出现超时（Time Limit Exceeded）或发生运行时内存越界。
  <strong>原因 →</strong> 使用 `int absN = -n;` 企图转换负指数，由于 `-INT_MIN` 在 32 位有符号整数中发生溢出，运算结果依然是 `-2147483648`，这导致循环条件 `absN > 0` 永远成立或导致位移溢出，使得程序陷入无限死循环。
  <strong>修法 →</strong> 在求绝对值前，必须将指数升级为 64 位的 `long long` 类型的临时变量，再进行绝对值转换：`long long absN = std::abs((long long)n);`。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 输入底数 0.0，指数为负数时，程序成功执行但返回了 `Infinity`（无无穷大值）或者返回 1.0，没有检测出输入异常。
  <strong>原因 →</strong> 缺少了对底数为 0 且指数小于 0 的独立条件拦截。直接执行除倒数会导致 `1.0 / 0.0`，在部分编译器/解释器中这会产生 `Infinity`，掩盖了严重的除零逻辑漏洞。
  <strong>修法 →</strong> 前置边界拦截，判断 `std::abs(x - 0.0) < 1e-9 && n < 0` 并将其作为异常处理或返回特殊定义的标记。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 在 JS/TS 代码中，输入大指数（如 `n = 2147483648`），发现快速幂运算返回了错误值 `1`。
  <strong>原因 →</strong> 在 JS/TS 中使用了位操作符 `absN >>= 1` 和 `absN & 1`。JS 中的位操作会自动将 64 位浮点数强转为 32 位有符号整型。`2147483648` 的二进制第 31 位是 1，强转为 32 位有符号整型会变成负数 `-2147483648`，导致循环直接跳出或逻辑失控。
  <strong>修法 →</strong> 在 JS/TS 中处理大指数，应使用算术运算 `absN % 2 === 1` 和 `absN = Math.floor(absN / 2)`，避免使用按位右移和按位与操作符。
</Callout>

## 小结与练习

- 朴素 $x^n$ 的乘法复杂度为 $O(n)$，**快速幂算法**利用折半分治思想将其优化为 $O(\log n)$。
- 在底数判断中，由于浮点误差，**切忌直接使用 `== 0.0`**，应该使用 `abs(x - 0.0) < 1e-9` 进行误差限容差判断。
- 有符号 32 位整型 `INT_MIN` 无法直接取反，必须先**拓宽为 64 位 `long long`**，防止整型溢出导致的死循环。
- 迭代快速幂相比于递归，能将空间复杂度从 $O(\log n)$ 降低为 $O(1)$，消除了系统栈溢出风险。

<Exercises>
  <Answer question="既然快速幂有递归和迭代两种实现，它们在执行效率和调用栈上有何本质区别？">
    递归实现自顶向下分治，在每次折半时都会发生函数压栈，因此需要 $O(\log n)$ 的系统栈空间，如果递归层数过深，可能会导致栈溢出。
    迭代实现从底向上利用循环和位移，只需要定义几个辅助变量，空间复杂度为 $O(1)$。它完全没有函数调用的额外开销，因此在运行效率和空间安全性上都优于递归实现。
  </Answer>
  <Answer question="为什么在 $x^n$ 中 $0^0$ 在数学上常常是未定义的，而在各种编程语言的数学库中（如 C++ 的 pow(0, 0)）通常返回 1.0？">
    在极限分析中，$0^y \rightarrow 0$（当 $y > 0$ 时），而 $x^0 \rightarrow 1$（当 $x > 0$ 时），因此当底数和指数同时趋近于 0 时极限不唯一，在纯数学中是未定义的。
    但在代数与工程计算中，为了保证多项式公式 $P(x) = \sum a_k x^k$ 在 $x=0$ 且 $k=0$ 时第一项能正确输出常数 $a_0$，且为了避免大多数幂运算中频繁产生未定义错，工程实现统一约定 $0^0 = 1$。
  </Answer>

<Glossary>
  <GlossaryItem term="快速幂">
    一种利用二进制拆分或折半分治，大幅减少连续相乘次数的高效幂运算算法。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="浮点数精度限制">
    计算机使用有限二进制位数（IEEE 754 规范）来存储实数，导致无法无误差地存储无限循环二进制小数，在等值比对时需要容差阀值。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="整型溢出">
    当计算结果或数据转换超出了计算机硬件数据类型所能表示的最大/最小范围时，数据发生回绕、截断或引发未定义行为的现象。详见「常见误区」节。
