<Objectives>

- 能用辅助栈完整模拟压入与弹出过程。
- 掌握“只要栈顶等于下一个待弹出值，就持续弹出”的贪心规则。
- 能判断非法序列产生的原因，而不是只背结论。
- 能处理长度不一致、空序列、重复值等输入边界。

</Objectives>

## 核心思路

给定压栈序列 `pushed = [1, 2, 3, 4, 5]`，判断 `popped = [4, 5, 3, 2, 1]` 是否可能。

我们不需要猜所有操作组合，只要按 `pushed` 顺序模拟：

1. 依次把 `pushed` 的元素压入辅助栈。
2. 每压入一个元素后，检查辅助栈栈顶是否等于 `popped` 中下一个待弹出的元素。
3. 如果相等，就持续弹出，并移动 `popped` 指针。
4. 所有压入结束后，如果辅助栈为空，说明弹出序列合法。

## 为什么这个模拟是正确的？

栈的弹出只有一个合法来源：当前栈顶。给定压入顺序后，每一步可选择的动作只有：

- 继续压入下一个元素。
- 如果栈顶正好等于下一个目标弹出值，就弹出它。

一旦栈顶等于目标弹出值，立刻弹出不会损失任何可能性；如果不弹，它仍然挡在栈顶，后续元素压上来只会让它更晚弹出。因此这个贪心模拟足以覆盖所有合法情况。

## 代码对照

<CodeTabs>
  <Tab label="C++">
```cpp
#include <vector>
#include <stack>

bool validateStackSequences(
    const std::vector<int>& pushed,
    const std::vector<int>& popped
) {
    if (pushed.size() != popped.size()) return false;

    std::stack<int> helper;
    int popIndex = 0;

    for (int value : pushed) {
        helper.push(value);

        while (!helper.empty() &&
               popIndex < static_cast<int>(popped.size()) &&
               helper.top() == popped[popIndex]) {
            helper.pop();
            ++popIndex;
        }
    }

    return helper.empty() && popIndex == static_cast<int>(popped.size());
}
```

```typescript
function validateStackSequences(pushed: number[], popped: number[]): boolean {
  if (pushed.length !== popped.length) return false;

  const stack: number[] = [];
  let popIndex = 0;

  for (const value of pushed) {
    stack.push(value);

    while (
      stack.length > 0 &&
      popIndex < popped.length &&
      stack[stack.length - 1] === popped[popIndex]
    ) {
      stack.pop();
      popIndex++;
    }
  }

  return stack.length === 0 && popIndex === popped.length;
}
```

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 只比较两个序列的集合或排序结果，认为元素相同就合法。
  <strong>原因 →</strong> 栈有严格的后进先出约束，元素集合相同只是必要条件，不是充分条件。
  <strong>修法 →</strong> 必须模拟栈顶是否能按目标顺序弹出。
</Callout>
