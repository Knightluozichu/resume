## 直觉引入

在开始严谨的算法递推之前，我们先通过一把“钥匙与锁”的比喻来建立感性认识：

*   **字符串与模式的配对**：将源字符串 `s` 视作一扇**门**，而模式串 `p` 是我们需要拼接出的一把**钥匙**。钥匙的齿槽需要跟门上的弹子一一吻合，门才能打开。
*   **普通字符与点号通配符 `.`**：普通字符是一块形状固定的“金属齿瓣”，必须碰到相同的弹子才能吻合；而点号 `.` 是一块**“橡胶万能齿瓣”**，只要弹子存在（即当前字符不为空），它就能挤压变形契合任意字符。
*   **星号通配符 `*`**：星号不能独立存在，它必须依附于前一个字符（如 `a*` 或 `.*`）。它是一枚**“伸缩弹簧扣”**，它可以收缩到极致从而彻底消失（代表匹配 0 次，相当于删除前驱字符），也可以无限拉伸复制出多个相同的金属齿瓣（代表匹配 1 次、2 次甚至多次）。
    
    正是因为这枚弹簧扣可以“变长”或“缩短”，我们在拼接这部分钥匙时就面临了**多重决策**：到底是用它匹配当前的门弹子，还是索性把它缩回 0 尺寸直接跳过去？这种多决策、有重叠子问题的选择，便是**动态规划（DP）**或**深度优先回溯**登场的绝佳舞台。

## 概念讲解

### 1. 状态定义

我们使用动态规划来求解此问题。设源字符串为 `s`（长度为 $M$），模式串为 `p`（长度为 $N$）。

定义二维布尔数组 `dp[i][j]`：
*   **物理意义**：**源串 `s` 的前 `i` 个字符（`s[0..i-1]`）与模式串 `p` 的前 `j` 个字符（`p[0..j-1]`）是否能够完全匹配**。
*   **矩阵大小**：维度为 `(M + 1) * (N + 1)`，因为我们要额外分配一行一列来表示空串（长度为 0）的初始状态。

### 2. 状态转移方程

在递推计算 `dp[i][j]` 时，我们主要关注模式串的当前字符 `p[j-1]`：

#### 情况 A：`p[j-1] != '*'`（当前模式字符是普通字符或 `.`）
此时必须进行单字符的硬性匹配。只有在当前字符匹配成功，且各自前缀也匹配成功时，当前状态才为真：
$$dp[i][j] = dp[i-1][j-1] \quad \text{if } matches(s[i-1], p[j-1])$$

其中，字符匹配辅助函数 $matches(c_s, c_p)$ 定义为：
$$matches(c_s, c_p) = (c_s == c_p) \lor (c_p == '.')$$

#### 情况 B：`p[j-1] == '*'`（当前模式字符是星号）
星号通配符表示其前驱字符 `p[j-2]` 可以出现 0 次或多次。这促使我们拆分成以下两种互斥的决策逻辑：

1.  **匹配 0 次**（直接将该星号及其前驱字符丢弃不用）：
    我们把 `p` 的最后两个字符 `p[j-2]` 和 `*` 直接忽略，去看 `s` 的前 `i` 个字符是否能与 `p` 的前 `j-2` 个字符匹配：
    $$dp[i][j] = dp[i][j-2]$$

2.  **匹配 1 次或多次**（保留星号组合，并消去源串当前字符）：
    只有当**当前源字符 `s[i-1]` 与星号前驱 `p[j-2]` 匹配**时，该决策才有效。此时，我们可以消去源串的当前字符，且保持模式串不变（因为星号可以继续代表更多次匹配）：
    $$dp[i][j] = dp[i-1][j] \quad \text{if } matches(s[i-1], p[j-2])$$

将这两种决策合并，当 `p[j-1] == '*'` 时的完整转移方程为：
$$dp[i][j] = dp[i][j-2] \lor \Big(matches(s[i-1], p[j-2]) \land dp[i-1][j]\Big)$$

---

### 3. 边界与初始化

1.  **双空匹配**：`dp[0][0] = true`，表示空源串与空模式串天然匹配。
2.  **源串为空，模式串非空**：即 `dp[0][j]`（$j \ge 1$）。如果模式串中包含 `*`（例如 `a*b*c*`），它们都可以匹配 0 次而完全隐去。初始化转移方程为：
    $$dp[0][j] = dp[0][j-2] \quad \text{if } p[j-1] == '*'$$
    其余 `dp[0][j]` 均为 `false`。
3.  **源串非空，模式串为空**：即 `dp[i][0]`（$i \ge 1$）。空模式串无法匹配任何非空源串，因此 `dp[i][0]` 一律为 `false`。

## 代码对照

### 核心实现：指针回溯与 DP 矩阵

在 C++ 实现中，我们保留了《剑指Offer》原书经典的**字符指针递归回溯**写法，它逻辑直观，占用常数辅助空间（不计递归栈）；而在 TypeScript 中，我们使用**二维 DP 矩阵**的迭代写法，这能有效避免大量重复子问题带来的指数级时间消耗。

<CodeTabs>
  <Tab label="C++ (递归回溯指针法)">
```cpp
class Solution {
public:
    bool isMatch(const char* str, const char* pattern) {
        if (str == nullptr || pattern == nullptr)
            return false;

        return matchCore(str, pattern);
    }

private:
    bool matchCore(const char* str, const char* pattern) {
        // 1. 同时到达末尾，匹配成功
        if (*str == '\0' && *pattern == '\0')
            return true;

        // 2. 模式串已结束但源串未结束，匹配失败
        if (*str != '\0' && *pattern == '\0')
            return false;

        // 3. 当模式串的下一个字符是 '*' 时
        if (*(pattern + 1) == '*') {
            // 当前字符匹配成功（相同或模式为 '.' 且源字符不为空）
            if (*pattern == *str || (*pattern == '.' && *str != '\0')) {
                return matchCore(str + 1, pattern)      // 匹配 1 次或多次：源串后移，模式串不变
                    || matchCore(str, pattern + 2);     // 匹配 0 次：忽略此星号组合，模式串后移 2 位
            } else {
                // 当前字符不匹配，只能选择匹配 0 次
                return matchCore(str, pattern + 2);
            }
        }

        // 4. 普通单字符匹配
        if (*str == *pattern || (*pattern == '.' && *str != '\0'))
            return matchCore(str + 1, pattern + 1);

        return false;
    }
};
```

```typescript
function isMatch(s: string, p: string): boolean {
    const m = s.length;
    const n = p.length;

    // dp[i][j] 表示 s[0..i-1] 与 p[0..j-1] 是否匹配
    const dp: boolean[][] = Array.from({ length: m + 1 }, () =>
        Array(n + 1).fill(false)
    );

    // 1. Base cases
    dp[0][0] = true; // 空串与空模式匹配

    // 2. 初始化 dp[0][j]：处理源串为空但模式串有 * 的匹配情况
    for (let j = 2; j <= n; j++) {
        if (p[j - 1] === '*') {
            dp[0][j] = dp[0][j - 2];
        }
    }

    // 3. 状态转移
    for (let i = 1; i <= m; i++) {
        for (let j = 1; j <= n; j++) {
            if (p[j - 1] === '*') {
                // 决策 1：星号匹配 0 次
                const matchZero = dp[i][j - 2];
                // 决策 2：星号匹配 1 次及以上（前驱相同，且缩短后的源串亦匹配当前模式）
                const matchChar = p[j - 2] === '.' || s[i - 1] === p[j - 2];
                const matchMore = matchChar && dp[i - 1][j];

                dp[i][j] = matchZero || matchMore;
            } else {
                // 普通单字符匹配（相同或模式为 '.'）
                const matchChar = p[j - 1] === '.' || s[i - 1] === p[j - 1];
                dp[i][j] = matchChar && dp[i - 1][j - 1];
            }
        }
    }

    return dp[m][n];
}
```

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 动态规划状态转移时，数组下标越界（Index Out Of Bounds）。
  <strong>原因 →</strong> DP 矩阵的大小是 `(M+1)*(N+1)`，采用的是以 1 为基准的长度索引。而在访问原始字符串 `s[i-1]` 和 `p[j-1]` 时，使用的是以 0 为基准的字符索引。直接在字符访问中使用 `s[i]` 或 `p[j]` 会引起错位，导致检测到错误的字符，并且在末尾时发生越界崩溃。
  <strong>修复 →</strong> 始终牢记：状态 `dp[i][j]` 中的 `i` 和 `j` 代表长度，它们对应的源串和模式串字符分别位于索引 `i-1` 和 `j-1`。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 输入不合法的模式串（如以星号开头 `*a` 或连续星号 `a**`）时，程序崩溃或抛出 NullPointer 异常。
  <strong>原因 →</strong> 算法在遇到 `p[j-1] == '*'` 时，会无条件查询其前驱字符 `p[j-2]`。如果模式串首位就是 `*`，`j-2` 的值将为 `-1`，引发数组越界。
  <strong>修复 →</strong> 在算法入口或初始化前执行模式串合法性校验。对于首字符是星号（`p[0] == '*'`）的情形，应当直接抛出参数异常或返回不匹配。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 在递归回溯写法中，当输入包含大量星号通配符的长字符串时，运行时间暴增，甚至引发调用栈溢出（Stack Overflow）。
  <strong>原因 →</strong> 纯递归方法在处理诸如 `s = "aaaaaaaaaaaaab"`, `p = "a*a*a*a*a*a*a*b"` 等情况时，会产生极大量的重叠子问题。每次遇到 `*` 就会裂变出两条搜索路径，使最坏时间复杂度退化至指数级别 $O(2^{M+N})$，并由于调用栈过深引起栈溢出。
  <strong>修复 →</strong> 在实际生产或严苛测试中，优先采用二维动态规划迭代写法；如果必须使用递归，则应引入哈希表或二维备忘录数组（Memoization）进行剪枝优化。

</Callout>

## 小结与练习

- **动态规划的核心**：在于用二维矩阵记录所有的历史匹配状态。在面临星号 `*` 的伸缩性选择时，通过“丢弃它（0 次）”或“推进行（1 次以上）”的多路分支合并决策进行递推。
- **边界初始化的重要性**：由于空串可以被星号表达式过滤消除，所以 `dp[0][j]` 的初始化（必须偶数项全是 `*`）是保证大跨度匹配正常的前提。
- **复杂度表现**：动态规划法具有稳定的 $O(M \times N)$ 时间和空间复杂度。由于 `dp[i][j]` 的计算只依赖上一行（`i-1`）与当前行，可以通过滚动数组将空间优化到 $O(N)$。

<Exercises>
  <Answer question="模式串中连续出现 '.*'（例如 '.*.*'）时，状态转移会不会发生无限死循环？">
    不会。在动态规划的迭代写法中，我们是通过外层 `i` 从 1 到 `M`、内层 `j` 从 1 到 `N` 的严格单向双重循环进行计算的。在求 `dp[i][j]` 时，它所依赖的状态如 `dp[i][j-2]` 和 `dp[i-1][j]` 在此之前已经完成了计算（它们属于当前行的左侧或上一行），不存在循环依赖关系，因此绝对不会死循环。而在递归写法中，每次匹配 0 次都会使模式串向后移 2 位（`pattern + 2`），匹配多字则会让源串向后移 1 位（`str + 1`），字符串长度都是严格递减趋向终止条件的，故也不会发生死循环。
  </Answer>
  <Answer question="如何将动态规划空间复杂度从 $O(M \times N)$ 优化到 $O(N)$？请简述思路。">
    因为 `dp[i][j]` 的更新只依赖于当前行的左侧状态（如 `dp[i][j-2]`）以及上一行对应的状态（如 `dp[i-1][j]`、`dp[i-1][j-1]`）。这意味着，我们在进行状态转移时，并不需要保留所有历史行的矩阵。我们可以使用一维数组 `dp[j]`（大小为 $N+1$）作为滚动数组。在计算新的一行时，为了避免当前行计算出的新值覆盖掉上一行的旧值，我们可以采用临时变量保存或者在特定顺序下更新，从而让空间开销压缩至仅与模式串长度相关的 $O(N)$。
  </Answer>
</Exercises>

<Glossary>
  <GlossaryItem term="点号通配符 .">
    正则表达式中的元字符，在未开启特殊单行模式时，它可以匹配源字符串中除换行符之外的任意单个字符。详见「直觉引入」节。
  </GlossaryItem>
  <GlossaryItem term="星号通配符 *">
    正则表达式中的量词元字符，它不能单独存在，必须跟在某个前导字符或通配符后面，表示该前导项可以出现 0 次或任意多次。详见「概念讲解 2」节。
  </GlossaryItem>
  <GlossaryItem term="状态转移方程">
    动态规划算法中，用于描述当前未知状态与一个或多个已知前驱状态之间确定性推导关系的数学公式。详见「概念讲解 2」节。
  </GlossaryItem>
  <GlossaryItem term="滚动数组 (Space Optimization)">
    动态规划中常用的一种空间压缩技巧。当发现下一阶段的状态仅依赖上一阶段的状态时，可以用大小与阶段相同的常数个一维数组代替多维矩阵循环更新，从而成倍缩减内存开销。详见「小结与练习」节。
  </GlossaryItem>
