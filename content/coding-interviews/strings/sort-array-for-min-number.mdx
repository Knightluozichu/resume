<Objectives>

- 能解释为什么不是按数值大小比较，而是按 `a+b` 与 `b+a` 比较。
- 能证明排序比较关系定义能得到全局最小拼接结果。
- 能实现 C++ 与 TypeScript 版本并处理 `0` 情况。

</Objectives>

## 直觉引入

如果单看单个数字大小会犯错：比如 `3` 与 `30`。
要让局部最优满足全局，需要比较拼接字符串：`30+3`（303）和 `3+30`（330），谁小谁该在前。

## 算法思路

1. 把每个整数转成字符串。
2. 排序比较器返回 `(a+b) < (b+a)`。
3. 按排序结果拼接。
4. 去掉空字符串或全 `0` 的情况。

## 思考引导

### 1) 先问问题，不先默认数值排序
拼出最小数字要回答的是“比较两个元素拼接后的先后关系”，不是它们原始大小。

### 2) 识别不变式
排序器必须满足比较规则：x 在 y 前当且仅当 xy < yx。该规则定义了全局的可比关系。

### 3) 为什么它一定成立
若排序依据改成拼接序列最小化，局部顺序交换原则可延展到全局（可通过排序稳定性与传递性实现）。

### 4) 常见误区
错误地先转数值排序会引入前导零和大数比较误差。边界（全零）也要单独处理。

### 5) 你能找到一个反例吗
[3,30,34,5,9] 排序后是 30334...，若按数值排序会错。这个经典组合可反证比较器。

### 6) 迁移到下一题
版本号、路径码、标签串排序都可复用“比较器定义业务关系”思想，排序规则先于实现。

```cpp
#include <string>
#include <vector>
#include <algorithm>

class Solution {
public:
    std::string minNumber(std::vector<int> nums) {
        std::vector<std::string> arr;
        for (int x : nums) arr.push_back(std::to_string(x));

        std::sort(arr.begin(), arr.end(), [](const std::string& a, const std::string& b) {
            return a + b < b + a;
        });

        std::string ans;
        for (auto& s : arr) ans += s;
        if (!ans.empty() && ans[0] == '0') {
            return "0";
        }
        return ans;
    }
};
```

  <Tab label="TypeScript">
```typescript
function minNumber(nums: number[]): string {
    const arr = nums.map((x) => String(x));

    arr.sort((a, b) => (a + b).localeCompare(b + a));

    const ans = arr.join('');
    return ans[0] === '0' ? '0' : ans;
}
```
