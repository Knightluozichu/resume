## 直觉引入

想象你正站在一面镜子前。当你举起右手时，镜中的你举起了左手；当你举起左手时，镜中的你举起了右手。镜中的影像在水平方向上发生了翻转，但这并不影响你身体各个器官（节点）的相对连接关系：头依然长在脖子上，手依然连接在手臂上。

在计算机科学中，**二叉树的镜像**就是这样一种翻转行为。对于一棵二叉树，如果我们将它所有的非叶子节点的左、右孩子指针进行互换，整棵树在几何结构上就发生了一次完美的水平翻转：

```
     原二叉树：                  镜像二叉树：
        8                          8
      /   \                      /   \
     6     10                   10    6
    / \   /  \                 /  \  / \
   5   7 9   11               11  9 7   5
```

实现这一操作，本质上就像是一个**“自顶向下”地翻转小风扇**的过程：

1. 我们从最上层的根节点（`8`）开始，抓起它的左、右两个叶片（子树），把它们整体对调；
2. 接着，我们沿着两个叶片分别向下走，对遇到的每一个非空子节点（如 `6` 和 `10`），都重复这种对调操作；
3. 直到所有的分支都到达终点（叶子节点），翻转宣告结束，整棵树就呈现了镜像状态。

## 概念讲解

要在树结构中实现原地镜像（即不产生新节点，仅通过修改指针结构来完成翻转），可以采用**递归**或**迭代**两种实现路径。

### 1. 递归法：前序遍历与自顶向下交换

递归是解决树结构问题最自然的方式。在访问当前节点时，先执行左右指针的交换，再分别递归处理左右子树，这符合前序遍历的模式：

1. **递归基（终止条件）**：如果当前节点 `root` 为空，无须处理，直接返回 `nullptr` 或 `null`；
2. **原地交换**：暂存左孩子，将右孩子赋给左边，再将暂存的左孩子赋给右边；
3. **递归深搜**：分别对交换后的左子树 `root->left` 和右子树 `root->right` 调用镜像函数。

_注：也可以使用后序遍历（先递归子树再交换孩子），它们在效果上完全等价，均能完整遍历并正确翻转每一个节点的左右链接。_

### 2. 中序遍历逻辑陷阱：为什么不能直接使用中序？

如果直接套用中序遍历的传统逻辑（左 → 根 → 右）写递归，会发生严重的漏判与重复翻转：

```typescript
// 错误的中序遍历镜像伪代码
function mirrorTreeWrong(root) {
  if (!root) return;
  mirrorTreeWrong(root.left); // 1. 先递归处理左子树
  swap(root.left, root.right); // 2. 交换当前根节点的左右孩子
  mirrorTreeWrong(root.right); // 3. 递归处理右子树 (陷阱！)
}
```

- **为什么是陷阱**？  
  当我们在第 2 步完成了当前节点的 `root.left` 与 `root.right` 交换后，**原来的右子树已经被挪到了左边，原来的左子树挪到了右边**。  
  在第 3 步执行 `mirrorTreeWrong(root.right)` 时，传入的实际上是**刚刚已经被镜像处理过的原左子树**！而原本的右子树（现在在左侧）则在整个递归过程中被彻底跳过，从未被镜像过。
- **修复方法**：如果非要用中序，交换完毕后，第 3 步应该再次递归处理左子树 `mirrorTreeWrong(root.left)`。

### 3. 迭代法：BFS 队列与安全层序翻转

虽然递归法简洁，但在极度偏斜的树中（例如退化为只有左孩子的 $N$ 层单链表），递归深度可达 $O(N)$。在一些执行栈内存受限的环境中，这可能会引发**栈溢出 (Stack Overflow)**。

迭代法通过辅助数据结构（队列）进行层序遍历（BFS）来逐个交换节点。具体步骤如下：

1. 初始化一个空队列，并将根节点 `root` 放入队列；
2. 当队列不为空时，循环执行以下操作：
   - 弹出一个节点 `node`；
   - 交换 `node` 的左、右孩子指针（即使其中一侧或两侧为空，也进行物理对换）；
   - 如果该节点的左孩子不为空，放入队列；如果右孩子不为空，也放入队列。
3. 重复直至队列为空。由于采用堆内分配的队列存储候选节点，能有效规避递归栈溢出风险。

## 代码对照

原地镜像在 C++ 和 TypeScript 中的具体实现如下：

<CodeTabs>
  <Tab label="C++ (递归与迭代双版本)">
```cpp
#include <queue>
#include <algorithm>

struct TreeNode {
int val;
TreeNode* left;
TreeNode* right;
TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

class Solution {
public:
// 递归版本 (前序遍历 DFS)
TreeNode* mirrorTree(TreeNode* root) {
// 防御性检查
if (root == nullptr) {
return nullptr;
}

        // 交换当前节点的左右子节点
        std::swap(root->left, root->right);

        // 递归翻转子树
        mirrorTree(root->left);
        mirrorTree(root->right);

        return root;
    }

    // 迭代版本 (层序遍历 BFS)
    TreeNode* mirrorTreeIterative(TreeNode* root) {
        if (root == nullptr) {
            return nullptr;
        }

        std::queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            TreeNode* node = q.front();
            q.pop();

            // 原地交换左右指针
            std::swap(node->left, node->right);

            // 将子节点加入队列继续处理
            if (node->left != nullptr) {
                q.push(node->left);
            }
            if (node->right != nullptr) {
                q.push(node->right);
            }
        }

        return root;
    }

};

````

```typescript
class TreeNode {
  val: number;
  left: TreeNode | null = null;
  right: TreeNode | null = null;
  constructor(val: number) { this.val = val; }
}

/**
 * 1. 原地修改版本 (In-place Mirror)
 * 直接修改原输入树的指针结构，无额外节点内存开销
 */
function mirrorTree(root: TreeNode | null): TreeNode | null {
  if (root === null) {
    return null;
  }

  // 原地交换
  const temp = root.left;
  root.left = root.right;
  root.right = temp;

  // 递归处理子树
  mirrorTree(root.left);
  mirrorTree(root.right);

  return root;
}

/**
 * 2. 拷贝镜像版本 (Copy and Mirror)
 * 不破坏原二叉树的物理结构，而是动态分配生成一棵全新的镜像拷贝树
 */
function mirrorTreeCopy(root: TreeNode | null): TreeNode | null {
  if (root === null) {
    return null;
  }

  // 动态创建新节点
  const newRoot = new TreeNode(root.val);

  // 核心：新节点的左孩子关联到原右孩子的镜像拷贝，新节点的右孩子关联到原左孩子的镜像拷贝
  newRoot.left = mirrorTreeCopy(root.right);
  newRoot.right = mirrorTreeCopy(root.left);

  return newRoot;
}
````

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong>{" "}
  在递归执行时，只交换了节点的值，而没有互换节点的左右指针（即左右引用链接本身）。
  <strong>原因 →</strong>{" "}
  误以为镜像只是数值的变动。二叉树的鏡像本质上是改变物理链接指向，仅交换数值虽然对于简单二叉树可行，但在节点带有其他关联业务属性（如多属性对象、父指针引用等）或大型二叉树下极易引发逻辑错误，且不合算法考查规范。
  <strong>修法 →</strong> 坚决使用第三变量或标准库的 `std::swap`，对 `node.left`
  和 `node.right` 的指针引用进行整体对换。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 使用中序遍历实现原地镜像时，有些节点的左右孩子正确翻转，而另一些节点在多次运行中保持原样。
  <strong>原因 →</strong> 陷入了常规中序递归的逻辑盲区。在执行 `mirror(left) -> swap -> mirror(right)` 时，中间的 `swap` 将原右树转到了左侧，导致 `mirror(right)` 实际上又重入进了刚刚处理过的左子树，使得该子树被翻转了两次变回原样，而原右子树则被完全遗忘。
  <strong>修法 →</strong> 若使用中序，需在交换完指针后，将后续步骤修改为：`mirrorTree(root.left)` 两次。更简便的方案是改用前序或后序遍历。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 遇到空树或单节点树时，代码抛出 null 引用异常。
  <strong>原因 →</strong> 缺乏防御性编程意识，没有在算法入口或递归边界处对空树进行判断，直接读取了 `root.left` 或 `root.right`。
  <strong>修法 →</strong> 在方法体的第一行坚决写入 `if (root === null) return null;` 作为防线。

</Callout>

## 小结与练习

- 原地镜像二叉树的时间复杂度为 **$O(N)$**，因为树中每一个节点都会且仅会被访问一次并执行常数次的指针互换。
- 空间复杂度在最坏情况下为 **$O(H)$**（$H$ 为二叉树高度），在倾斜树下为 **$O(N)$**（由于递归调用栈深度或辅助队列/栈的开销），在完全二叉树下为 **$O(\log N)$**。
- 迭代版本采用队列（BFS）或栈（DFS）进行遍历，能有效防范深度树导致的调用栈溢出风险。

  <Answer question="如果原二叉树根节点为 8，左孩子为 6，右孩子为 10，其中 6 的左孩子为 5，右孩子为 7。镜像翻转后，节点 7 在树中的位置在哪里？它的双亲节点是什么？">
    镜像翻转后，根节点 8 的左右子树整体调换，因此节点 6 被挂到了根节点 8
    的右侧；而在节点 6 内部，其左右孩子 5 和 7 也会发生对调，使得 7 变成了 6
    的左孩子。 因此，节点 7 现在的物理位置是：**根节点 8 的右孩子的左孩子**。
    它的双亲节点是 **6**。
  </Answer>
  <Answer question="如何将基于 BFS 队列的迭代版本修改为基于 DFS 的迭代版本？需要引入什么数据结构？">
    只需将辅助队列（Queue，先进先出）替换为辅助栈（Stack，后进先出）即可。
    在循环中，每次从栈顶弹出一个节点，将其左右子节点进行交换，然后将交换后的非空左右孩子压入栈中。这样遍历的展开顺序就从层序变成了深度优先搜索（DFS）顺序，空间复杂度依旧由当前最大深度所决定。
  </Answer>
  <Answer question="在非原地拷贝镜像生成树副本时，为什么『新节点的左孩子』必须指向『原节点右孩子』的镜像，而不是左孩子的镜像？">
    因为拷贝镜像的目的是要生成一棵全新的、颠倒了左右结构的镜像树。
    对于原树中的任何一个节点，其镜像树中对应节点的左孩子在物理内容上必须等于原树中对应节点右侧的分支。因此，在克隆分配新节点后，我们需要将它的左指针（`newRoot.left`）挂接到对原右子节点调用镜像拷贝的结果（`mirrorTreeCopy(root.right)`）上，右指针同理，否则克隆出来的就只是普通的原树副本，而没有发生翻转。
  </Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="前序遍历">
    指先访问当前节点，再递归地遍历其左子树和右子树的树遍历策略。在镜像翻转中，前序遍历常用于递归版本的原地翻转。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="原地修改 (In-place)">
    指在算法运行过程中，仅利用常数个辅助变量，通过直接改变输入参数所指向的现有内存区域中的指针/引用指向来完成操作，不申请分配额外的节点内存空间。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="拷贝镜像 (Copy-and-Mirror)">
    指在不改动原数据源的前提下，通过对每个遇到的元素动态分配新内存（新建对象/节点），拷贝其数值并重新连接，生成一棵在物理上完全独立、逻辑上为原树水平翻转结果的新树。详见「代码对照」节。
  </GlossaryItem>
  <GlossaryItem term="层序遍历 (BFS)">
    指借助队列按照树的层级，自顶向下、自左向右逐层访问每个节点的树遍历策略。在镜像翻转中，层序遍历可用于迭代地执行指针交换。详见「概念讲解」节。
  </GlossaryItem>
</Glossary>
