## 直觉引入

想象一下，你有一套非常漂亮、复杂的悬挂木质风铃玩具，它以一根主线从天花板挂下，下方分支出许多大大小小的横杆，横杆的左右端各挂着小配件或其他横杆。由于这套风铃非常精致，你决定编写两份拼装说明书：

1. **从上到下说明书（顺序手册）**：记录了从顶部的第一根横杆开始，依次往下一个个挂上去的配件顺序。
2. **从左到右说明书（位置手册）**：记录了如果把挂好的风铃平铺在桌面上，从最左端的配件到最右端的配件，它们水平排列的相对次序。

现在，风铃散落成了一地零件，但你手中还有这两本手册。你会怎么把玩具完整地复原呢？

首先，你翻看“从上到下说明书”，它的第一个配件一定是最顶端、挂在天花板上的主横杆。找到这个主根后，你打开“从左到右说明书”，在长长的一行中定位到这个主横杆。这时候，你会惊喜地发现：在它的左边的所有零件，一定都挂在它的左边分支上；而在它右边的所有零件，一定都属于它的右边分支！

对于左边的一堆零件，你再次翻看“从上到下说明书”，找到在其中最先出现的那个零件，这就是左分支的子根；然后在“从左到右说明书”中定位它，再次切分成更小的左、右部分…… 这种通过“定位根节点，切分左右半”一步步还原玩具的物理过程，就是计算机科学中利用前序遍历和中序遍历序列**重建二叉树**的精妙过程。

## 概念讲解

在树的遍历中：

- <Term def="遍历二叉树时，按照『根节点 -> 左子树 -> 右子树』的顺序访问节点。">
    前序遍历
  </Term>
  （Preorder Traversal）的遍历规则是：**[ 根节点 | 左子树的前序遍历 |
  右子树的前序遍历
  ]**。这决定了前序遍历序列的**第一个元素必定是整棵二叉树的根节点**。
- <Term def="遍历二叉树时，按照『左子树 -> 根节点 -> 右子树』的顺序访问节点。">
    中序遍历
  </Term>
  （Inorder Traversal）的遍历规则是：**[ 左子树的中序遍历 | 根节点 |
  右子树的中序遍历
  ]**。这决定了如果我们在中序遍历中定位到根节点，**根节点左侧的所有元素必定属于左子树，右侧的所有元素必定属于右子树**。

因此，重建二叉树的算法本质是一个典型的**分治与递归**过程：

```
前序遍历：[ 1 | 2, 4, 7 | 3, 5, 6, 8 ]
         ↑ 根节点
中序遍历：[ 4, 7, 2 | 1 | 5, 3, 8, 6 ]
         └─左子树─┘  ↑  └─右子树──┘
                  定位根节点 1
```

### 1. 递归分治重建步骤

假设我们已知前序遍历区间为 `[preStart, preEnd]`，中序遍历区间为 `[inStart, inEnd]`：

1. **基准条件**：如果 `preStart > preEnd` 或 `inStart > inEnd`，说明当前子树为空，直接返回 `nullptr`（TypeScript 中返回 `null`）。
2. **确定根节点**：当前前序序列的第一个元素 `preorder[preStart]` 即为根节点。我们创建一个新的树节点 `root = new TreeNode(rootVal)`。
3. **划分区间**：在中序序列中找到根节点值对应的索引 `inIndex`。
   - 左子树的节点个数为 $leftSize = inIndex - inStart$。
   - 左子树的中序区间为 `[inStart, inIndex - 1]`，前序区间为 `[preStart + 1, preStart + leftSize]`。
   - 右子树的中序区间为 `[inIndex + 1, inEnd]`，前序区间为 `[preStart + leftSize + 1, preEnd]`。
4. **递归建立子树**：
   - 递归调用重建左子节点：`root->left = buildHelper(..., preStart + 1, preStart + leftSize, ..., inStart, inIndex - 1)`。
   - 递归调用重建右子节点：`root->right = buildHelper(..., preStart + leftSize + 1, preEnd, ..., inIndex + 1, inEnd)`。

### 2. 索引查找优化：引入哈希表

在递归的每一步中，我们都需要在中序序列中定位根节点的位置 `inIndex`。如果每次都通过 `for` 循环在线性时间 $O(n)$ 内搜索，在最坏情况下（树退化为单链表时），重建算法的总时间复杂度将退化至 $O(n^2)$。

为了将查找开销降低到常数级别，我们可以**在重建前进行预处理**：
使用一个辅助哈希表（在 C++ 中为 `std::unordered_map`，在 TS 中为 `Map`），将中序遍历中的每个元素值与其对应索引存储为键值对。这样，我们在递归重建时，只需通过根节点的值直接在哈希表中检索其索引，单次定位的时间复杂度将降低为 **$O(1)$**，整体算法的运行效率将显著提升至 **$O(n)$**。

- **时间复杂度**：$O(n)$，其中预处理哈希表耗时 $O(n)$，递归重建中每个节点只被创建并访问一次，查找耗时为常数级别。
- **空间复杂度**：$O(n)$，哈希表需要 $O(n)$ 的辅助空间，此外递归调用栈的深度在最坏情况下为 $O(n)$（单支树），在最好情况下（平衡二叉树）为 $O(\log n)$。

## 代码对照

在具体编写代码时，有两点需要额外警惕：

1. **边界控制**：左右边界索引在加减操作时容易发生越界，需特别注意前序子区间长度要与中序子区间长度完全一致（即 $leftSize$ 的计算与应用）。
2. **严禁值传递拷贝**：在向子函数传递数组时，必须传递**引用**或**只读指针**，切勿把数组直接按值拷贝，否则会导致时空复杂度严重恶化。

以下是 C++（哈希优化与递归）和 TypeScript（辅助函数与 Map 映射）的具体实现对照：

<CodeTabs>
  <Tab label="C++ (哈希映射优化)">
```cpp
#include <vector>
#include <unordered_map>

struct TreeNode {
int val;
TreeNode* left;
TreeNode* right;
TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

class Solution {
private:
// 使用哈希表缓存中序遍历的『值 -> 索引』映射，提升查找效率
std::unordered_map<int, int> inorder_map;

    TreeNode* buildHelper(const std::vector<int>& preorder, int preStart, int preEnd,
                         const std::vector<int>& inorder, int inStart, int inEnd) {
        // 基准情况：若区间无效，说明子树为空
        if (preStart > preEnd || inStart > inEnd) {
            return nullptr;
        }

        // 1. 前序遍历的第一个节点即为当前子树的根节点
        int rootVal = preorder[preStart];
        TreeNode* root = new TreeNode(rootVal);

        // 2. 利用哈希表在 O(1) 时间内定位根节点在中序序列中的位置
        int inIndex = inorder_map[rootVal];

        // 3. 计算左子树节点的数量
        int leftSize = inIndex - inStart;

        // 4. 递归重建左子树与右子树
        // 左子树前序范围：紧跟根节点后的 leftSize 个元素；中序范围：根节点左侧
        root->left = buildHelper(preorder, preStart + 1, preStart + leftSize,
                                 inorder, inStart, inIndex - 1);

        // 右子树前序范围：左子树之后的剩余元素；中序范围：根节点右侧
        root->right = buildHelper(preorder, preStart + leftSize + 1, preEnd,
                                  inorder, inIndex + 1, inEnd);

        return root;
    }

public:
TreeNode\* buildTree(std::vector<int>& preorder, std::vector<int>& inorder) {
if (preorder.empty() || inorder.empty() || preorder.size() != inorder.size()) {
return nullptr;
}

        inorder_map.clear();
        // 预处理中序遍历的所有元素索引
        for (int i = 0; i < inorder.size(); ++i) {
            inorder_map[inorder[i]] = i;
        }

        return buildHelper(preorder, 0, preorder.size() - 1,
                           inorder, 0, inorder.size() - 1);
    }

};

````

```typescript
class TreeNode {
    val: number;
    left: TreeNode | null;
    right: TreeNode | null;
    constructor(val?: number, left?: TreeNode | null, right?: TreeNode | null) {
        this.val = (val === undefined ? 0 : val);
        this.left = (left === undefined ? null : left);
        this.right = (right === undefined ? null : right);
    }
}

function buildTree(preorder: number[], inorder: number[]): TreeNode | null {
    if (preorder.length === 0 || inorder.length === 0 || preorder.length !== inorder.length) {
        return null;
    }

    // 建立中序遍历的值到索引的 Map 映射
    const inorderMap = new Map<number, number>();
    for (let i = 0; i < inorder.length; i++) {
        inorderMap.set(inorder[i], i);
    }

    // 递归辅助函数，避免数组切片产生 $O(n)$ 拷贝消耗
    function buildHelper(
        preStart: number,
        preEnd: number,
        inStart: number,
        inEnd: number
    ): TreeNode | null {
        if (preStart > preEnd || inStart > inEnd) {
            return null;
        }

        // 前序遍历的首元素即为当前根节点
        const rootVal = preorder[preStart];
        const root = new TreeNode(rootVal);

        // 获取中序遍历中的索引
        const inIndex = inorderMap.get(rootVal)!;
        const leftSize = inIndex - inStart; // 左子树大小

        // 递归构建左右子树并绑定到父节点
        root.left = buildHelper(preStart + 1, preStart + leftSize, inStart, inIndex - 1);
        root.right = buildHelper(preStart + leftSize + 1, preEnd, inIndex + 1, inEnd);

        return root;
    }

    return buildHelper(0, preorder.length - 1, 0, inorder.length - 1);
}
````

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 程序在处理较大树结构时，频繁发生内存溢出（Out of
  Memory）或耗时极长。
  <strong>原因 →</strong> 在设计递归函数时，错误地采用了值传递（Pass by
  Value）或者在 TS 中频繁调用
  `Array.prototype.slice()`。每一层递归都在拷贝子树数组，导致了产生大量冗余数组的物理复制，使空间复杂度从
  $O(n)$ 恶化到了 $O(n^2)$。
  <strong>修法 →</strong>{" "}
  严禁对原始数组进行拷贝或截取。应当只传递数组的引用（或只读指针），并使用边界索引（如
  `preStart`, `preEnd` 等）来指代当前子树的覆盖范围。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong>{" "}
  在计算右子树前序起点时，索引公式写错，导致重建出的树父子关系错乱或直接发生索引越界错误。
  <strong>原因 →</strong>{" "}
  混淆了前序遍历和中序遍历的偏移计算。前序序列中，左子树的长度是由中序序列划分出的
  $leftSize = inIndex - inStart$ 决定的，而非单纯依靠前序边界。
  <strong>修法 →</strong> 牢记公式：右子树前序起点 = `preStart + leftSize +
  1`；左子树前序终点 = `preStart + leftSize`。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong>{" "}
  在实际面试中，当输入前序和中序遍历数组长度不一致，或者数组中包含重复数据/两数组元素不匹配时，程序抛出空指针或键缺失异常。
  <strong>原因 →</strong>{" "}
  缺乏健壮的防御性编程。哈希映射只针对无重复节点值的情况有效，且如果前中序序列由于传输错误导致元素冲突，哈希查找会失败。
  <strong>修法 →</strong> 在函数入口无条件增加防御性判定 `if (preorder.size() !=
  inorder.size()) return
  nullptr;`。同时在哈希查找中加入容错，找不到对应键时及时中断并排错。
</Callout>

## 小结与练习

- 重建二叉树的基石是利用前序确定 **根节点**，利用中序 **划分左右子树区间**。
- 重建过程是一个典型的 **递归分治 (Divide and Conquer)** 模型。
- 引入 **哈希映射** 可以将中序查找时间优化至 $O(1)$，使算法总时间复杂度达到最优的 **$O(n)$**。
- 为规避冗余开销，在递归中必须 **只传递边界索引**，严禁使用值传递或数组切片。

  <Answer question="为什么在存在重复值节点的二叉树中，我们单凭前序遍历和中序遍历序列无法唯一重建这棵二叉树？">
    因为哈希映射和中序切分都是基于“节点值唯一”的假设。如果节点值存在重复，我们在中序遍历中定位根节点时，就可能找到多个相同值的索引，从而无法确定究竟哪一个是真正的根节点，这会导致左、右子树划分产生多义性，因此无法唯一重建。
  </Answer>
  <Answer question="如果我们将条件改为：通过中序遍历序列和后序遍历序列来重建二叉树，该如何调整算法？">
    后序遍历（左 -> 右 -> 根）的最后一个元素一定是根节点。因此，我们只需先从后序序列的末尾定位根节点，再在中序序列中找到该根节点，将其切分为左、右子树。在递归向下时，由于后序的根节点从后往前遍历，我们需要先重建右子树，再重建左子树。
  </Answer>
</Exercises>
