## 直觉引入

想象一下，你是一位建筑设计师，手里有一份庞大且复杂的别墅设计蓝图（树 $A$）。某天，客户递给你一张小巧的卫浴套间设计图纸（树 $B$），问你：**这栋别墅的某个局部区域，是不是完全按照这个卫浴套间的图纸设计的？**

为了验证这件事，你会怎么做？

你可能会拿着这张套间图纸作为“印章”或“漏字板”，在别墅的蓝图上四处比对：
1. 首先，你在别墅蓝图上寻找任何一个标记为“卫浴入口”的房间（主树 $A$ 的先序遍历，寻找与树 $B$ 根节点值相同的节点）。
2. 一旦在别墅蓝图的某个位置找到了对应的入口，你就把套间图纸重叠铺上去，逐个检查里面的洗手盆、马桶、浴缸的摆放和墙体结构是否完全一致（递归检验子结构匹配 `doesTree1HaveTree2`）。
3. 只要套间图纸上的所有设施与别墅蓝图对应位置完全重合，你就可以确信，这里确实包含该卫浴子结构。至于别墅在套间门外是否还延伸出了花园、卧室或厨房（树 $A$ 在匹配区域下方还有子孙节点），你完全不用在意——因为套间图纸并没有对门外的空间提出要求。

这就是计算机科学中判定**树的子结构**的物理直觉：通过“在主树中寻找匹配的根”加上“以该点为根的局部重叠形状比对”，在二叉树中寻找是否包含另一棵小树的结构。

## 概念讲解

判定树的子结构在实现上面临两个核心难点：**双重递归逻辑的设计**与**递归终止边界的判定**。

### 1. 双重递归设计模式

我们需要编写两个相互配合的递归函数：

1. **主函数 `isSubStructure(A, B)`**：负责在树 $A$ 中做遍历。如果当前节点 $A$ 匹配了 $B$ 的根节点，尝试调用辅助函数判定；若不匹配，则递归去 $A$ 的左子树和右子树中继续寻找可能匹配的子结构起点。
   $$\text{isSubStructure}(A, B) = \text{doesTree1HaveTree2}(A, B) \cup \text{isSubStructure}(A.\text{left}, B) \cup \text{isSubStructure}(A.\text{right}, B)$$
2. **辅助函数 `doesTree1HaveTree2(R, B)`**：负责在起点确定后，同步向下遍历两棵树，判定 $R$ 是否**完全包含** $B$ 的所有结构。

```
树 A：                  树 B：
      8 (A0)                 8 (B0)
    /   \                   / \
   8     7                 9   2
  / \
 9   2
```

### 2. 核心递归边界的精细设计

在辅助匹配函数 `doesTree1HaveTree2(R, B)` 中，递归终止条件的判定至关重要：
- **$B$ 为空时**：说明树 $B$ 上的所有节点都已经顺利比对完毕，并且在之前的比对中都相匹配。应当直接返回 **`true`**。
- **$R$ 为空但 $B$ 不为空时**：说明树 $A$ 的对应分支已经遍历结束，而树 $B$ 还有未匹配的节点，结构不一致。返回 **`false`**。
- **两者值不相等时**：节点值冲突，结构不匹配，返回 **`false`**。

#### 『子结构』与『子树』的终止条件差异

| 概念 | 定义 | $B$ 遍历到 null 时，$R$ 仍有子节点 | 边界判定公式 |
| :--- | :--- | :--- | :--- |
| **子结构 (Subtree Structure)** | 局部形状完全契合即可，不要求延伸到叶节点 | 判定为 **匹配成功** (`return true`) | `if (B == null) return true;` |
| **子树 (Subtree)** | 必须完全一致，直到双方都延伸到叶节点为止 | 判定为 **匹配失败** (`return false`) | `if (B == null) return R == null;` |

### 3. 浮点数等值判定：防范精度陷阱

如果二叉树的节点值是浮点数（如 `double` 或 `float`），直接在代码中使用 `A.val == B.val` 会带来严重的精度陷阱。由于计算机在二进制表示浮点数时存在舍入误差，两个本应相等的数字在比较时可能会因为末尾的微小差异被误判为不相等。

因此，我们需要实现一个带精度容差的比较函数：
$$\text{equal}(a, b) = |a - b| < 10^{-8}$$

## 代码对照

在编写实现时，需要额外防范**主函数中的空节点过滤**。如果直接传入的 $A$ 或 $B$ 本身就是空树，根据题目常规约定（如剑指 Offer 或 LeetCode），空树不能是任何树的子结构，直接返回 `false`。

以下是 C++（带 double 类型与精度比较）和 TypeScript（带防御性空检查）的具体实现对照：

<CodeTabs>
  <Tab label="C++ (浮点数精度兼容)">
```cpp
#include <cmath>

struct TreeNode {
    double val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(double x) : val(x), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    bool isSubStructure(TreeNode* A, TreeNode* B) {
        if (A == nullptr || B == nullptr) {
            return false;
        }
        
        bool result = false;
        // 1. 如果当前节点的值与 B 的根节点相等，尝试判断是否包含该子结构
        if (equal(A->val, B->val)) {
            result = doesTree1HaveTree2(A, B);
        }
        
        // 2. 若当前位置不匹配或匹配失败，递归遍历 A 的左子树与右子树继续寻找起点
        return result || isSubStructure(A->left, B) || isSubStructure(A->right, B);
    }

private:
    // 判定从 R 开始的子树是否包含以 B 为根的子结构
    bool doesTree1HaveTree2(TreeNode* R, TreeNode* B) {
        // B 遍历完毕，说明结构已经完全被包含，匹配成功
        if (B == nullptr) {
            return true;
        }
        // B 未遍历完但 R 为空，说明 A 树该分支不够深，匹配失败
        if (R == nullptr) {
            return false;
        }
        // 节点值不相等，匹配失败
        if (!equal(R->val, B->val)) {
            return false;
        }
        
        // 递归检查左右子树是否对应匹配
        return doesTree1HaveTree2(R->left, B->left) && 
               doesTree1HaveTree2(R->right, B->right);
    }
    
    // 浮点数安全等值比较，容忍 1e-8 精度误差
    bool equal(double num1, double num2) {
        return std::fabs(num1 - num2) < 1e-8;
    }
};
```

  <Tab label="TypeScript (防御性空检查)">
```typescript
class TreeNode {
  val: number;
  left: TreeNode | null = null;
  right: TreeNode | null = null;
  constructor(val: number) { this.val = val; }
}

// 浮点数等值判断，防止精度丢失
function isEquals(num1: number, num2: number): boolean {
  return Math.abs(num1 - num2) < 1e-8;
}

// 主函数：遍历树 A 寻找与 B 匹配的起点
function isSubStructure(A: TreeNode | null, B: TreeNode | null): boolean {
  // 防御性检查：根据常规约定，空树不能是任何树的子结构
  if (A === null || B === null) {
    return false;
  }
  
  let result = false;
  
  // 若根节点值相等，触发递归子结构匹配
  if (isEquals(A.val, B.val)) {
    result = doesTree1HaveTree2(A, B);
  }
  
  // 前序遍历 A 树，只要在当前节点、左子树或右子树中有一处匹配即可
  return result || isSubStructure(A.left, B) || isSubStructure(A.right, B);
}

// 辅助判定函数：校验以 R 为起点的树是否包含树 B
function doesTree1HaveTree2(R: TreeNode | null, B: TreeNode | null): boolean {
  // 树 B 遍历结束，说明全部节点匹配成功
  if (B === null) return true;
  // B 未结束但 A 分支已断，匹配失败
  if (R === null) return false;
  // 节点值不同，匹配失败
  if (!isEquals(R.val, B.val)) return false;
  
  // 递归检查左右子节点是否同时匹配
  return doesTree1HaveTree2(R.left, B.left) && doesTree1HaveTree2(R.right, B.right);
}
```

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 辅助匹配函数 `doesTree1HaveTree2` 在遇到 $B$ 为空和 $R$ 为空时，返回逻辑写反，或者将 `B == null` 时也判定为失败。
  <strong>原因 →</strong> 混淆了『匹配完毕』和『树已中断』的逻辑定义。在子结构校验中，树 $B$ 是我们的“模板模板”，当模板中的所有节点都成功比对到末尾（即 $B$ 变为 `null`）时，说明前面的比对畅通无阻，这正是**成功匹配**的终点信号。
  <strong>修法 →</strong> 确保 `if (B == null) return true;` 优先于 `if (R == null) return false;` 触发。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 输入为包含极小浮点数节点值的二叉树时，算法时而运行正确，时而漏判或错判。
  <strong>原因 →</strong> 直接使用了 `R->val == B->val` 进行节点值判断，忽略了浮点数表示时的截断和舍入误差。
  <strong>修法 →</strong> 坚决使用 `std::fabs(a - b) < 1e-8` 或等效的精度容差比较函数进行数值等值判断。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 算法在运行中抛出空指针解引用错误（如 C++ 中的 Segfault 或 TS 中的 Cannot read properties of null）。
  <strong>原因 →</strong> 在主函数中递归调用时，如直接写 `isSubStructure(A->left, B)` 却忘记在函数入口或调用前检查主树指针是否为空。
  <strong>修法 →</strong> 在主函数的第一行坚决写入 `if (A == nullptr || B == nullptr) return false;` 作为无可动摇的防御防线。
</Callout>

## 小结与练习

- 判定『树的子结构』依赖**主遍历函数**（寻找候选根节点）与**辅助匹配函数**（做重合校验）的双重递归配合。
- 关键递归终止逻辑：`B == null` 返回 `true`，而 `R == null` 返回 `false`。
- 对于浮点数类型（如 `double` / `float`）的节点值比对，应使用 **精度容差法** 规避计算机浮点数舍入误差带来的错误。
- 算法的 worst-case 时间复杂度为 **$O(N \times M)$**（当大部分节点值均与 B 的根匹配时），平均时间复杂度为 **$O(N)$**。

<Exercises>
  <Answer question="给定树 A 的根节点为 8，其左孩子为 8，右孩子为 7，左孩子的左孩子为 9；树 B 根节点为 8，其左孩子为 9。B 是否是 A 的子结构？如果是，第一匹配点是在 A 的哪个节点？">
    是。树 B 是树 A 的子结构。
    虽然以 A 根节点 8 开始的比对会因为左侧子树不匹配（A 根的左孩子是 8，而 B 根的左孩子是 9，二者不等）而失败，但主函数接着前序遍历 A，在 A 的左孩子（节点 8）处再次尝试匹配。此时以 A 的左孩子为起点的子树中包含左孩子 9，这与树 B 完全吻合。
    因此，匹配成功，第一匹配起点是树 A 的**左子节点 8**。
  </Answer>
  <Answer question="如果本题的逻辑由『树的子结构』变为『树的子树（Subtree）』判定（即树 B 必须与树 A 的某棵完整子树完全相同，一直延伸到叶节点），该如何修改辅助匹配函数？">
    需要修改辅助匹配函数的终止判定逻辑。当树 B 的节点遍历完毕变为 `null` 时，树 A 的对应节点 $R$ 也必须同时变为 `null`，不能再有其他子孙节点。
    修改方式为：将辅助匹配函数中的 `if (B == null) return true;` 改为 `if (B == null) return R == null;`。
  </Answer>
  <Answer question="在最坏情况下，『树的子结构』算法时间复杂度为 O(N * M)，这在什么树结构与数值特征下会触发？">
    在树 A 与树 B 退化为单链表偏斜树，且两棵树的所有节点值都完全相同的情况下触发。
    例如：树 A 是由 $N$ 个值为 1 的节点组成的右斜树，树 B 是由 $M$ 个值为 1 的节点组成的右斜树。此时，对于树 A 中的前 $N-M+1$ 个节点，主函数都会调用辅助匹配函数对其进行深度为 $M$ 的完全比对，从而每次比对都需要耗费 $O(M)$ 的时间，总时间复杂度退化至 $O(N \times M)$。
  </Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="子结构">
    指树 B 的结构和节点值与树 A 的某一部分局部契合。即使树 B 的叶节点在树 A 中对应位置还有下属的子孙节点，也视作包含匹配成功。详见「直觉引入」与「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="精度容差">
    指在比对浮点数（float 或 double）时，由于计算机存储精度受限存在截断误差，不直接使用等号比较，而是通过判断两数差值绝对值小于极小常数（如 1e-8）来判定数值相等。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="双重递归">
    指在树的匹配问题中，外层使用递归前序遍历树 A 寻找待匹配子结构的候选根节点，内层对找到的每个候选节点触发另一重递归（用于做两棵子树各分支的同步重叠比对）的设计方法。详见「概念讲解」节。
  </GlossaryItem>
</Glossary>
