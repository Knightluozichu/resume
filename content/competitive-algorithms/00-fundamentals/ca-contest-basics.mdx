## 直觉引入

如果你参加一场编程竞赛，拿到题目后第一件事不是想算法，而是看数据范围。数据范围告诉你能用什么复杂度的算法——10^5 意味着 O(n log n) 可以，10^8 意味着只能 O(n)。这就像出发前先看地图比例尺，决定你是走路还是开车。

竞赛和平时写代码最大的区别：不是写出来就行，要在规定时间和内存内跑完所有数据。I/O 优化、复杂度估算、对拍调试，这三项基本功决定了你能不能把正确的思路变成 AC 的代码。

## 概念讲解

### 复杂度与数据规模的对应关系

<CaContestBasicsDiagram />

<Term def="1 秒内大约能执行 10^8 次基本运算的经验法则">
1秒准则
</Term>

竞赛中根据数据规模倒推算法复杂度：n ≤ 20 可 O(2^n)，n ≤ 100 可 O(n^3)，n ≤ 10^5 需 O(n log n)，n ≤ 10^7 需 O(n)。这是"看数据范围猜算法"的核心依据。

### 对拍调试

<Term def="生成随机数据分别运行正确但慢的程序和待测程序，比较输出以定位错误的方法">
对拍
</Term>

写一个暴力解法（保证正确但慢），一个待测解法（可能错但快），再写一个数据生成器，循环比较两者输出。发现不一致时，就找到了一组反例数据。

## 交互Demo

<Stepper>
<Step title="第一步：读题估复杂度">看数据范围，用 1 秒准则倒推。n=10^5 → O(n log n)，n=10^3 → O(n^2)。</Step>

<Step title="第三步：对拍验证">写暴力解+数据生成器，循环对拍找到反例，修复后继续直到无反例。</Step>
</Stepper>

## 代码对照

```cpp
// 对拍脚本核心逻辑（bash）
// gen 生成随机数据，brute 是暴力解，main 是待测解
while true; do
    ./gen > test.in
    ./brute < test.in > ans.out
    ./main < test.in > my.out
    if ! diff ans.out my.out > /dev/null; then
        echo "Found counterexample!"
        break
    fi
done

// 数据生成器（C++）
#include <bits/stdc++.h>
using namespace std;
int main() {
    srand(time(0));
    int n = rand() % 20 + 1;  // 小规模，暴力可处理
    printf("%d\n", n);
    for (int i = 0; i < n; i++)
        printf("%d ", rand() % 100);
    return 0;
}
```

## 常见误区

<Callout type="trap">
**现象：算法正确但 TLE。**
原因 → I/O 太慢或常数过大。cin 默认与 stdio 同步，大量数据时慢 5-10 倍。
修法 → 加 `ios::sync_with_stdio(false); cin.tie(0);` 或直接用快速读入。
</Callout>

<Callout type="trap">
**现象：本地通过但提交 WA。**
原因 → 边界条件未处理（n=0、n=1、全相同、负数等），或整数溢出。
修法 → 用对拍找反例，检查 long long 是否需要，手动测试边界数据。
</Callout>

<Exercises>
**问题 1**：n=10^5，时限 1 秒，可接受的最高复杂度是多少？

<Answer>
O(n log n) 约执行 1.7×10^6 次运算，远在 10^8 以内，安全。O(n^2) 约执行 10^10 次，远超 10^8，会 TLE。因此最高可接受 O(n log n) 或 O(n√n)。
</Answer>

**问题 2**：对拍时为什么要用小规模随机数据？

<Answer>
暴力解法复杂度高，大数据跑不完。小规模数据暴力解能快速给出正确答案，且边界情况（n=0、n=1）更容易被随机覆盖。重点是找到反例，不是测性能。
</Answer>
</Exercises>
