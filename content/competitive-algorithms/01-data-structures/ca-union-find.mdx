## 直觉引入

想象一个社交网络，不断有人互相加好友。你需要随时回答"A 和 B 是否在同一个朋友圈里"。用数组标记每个人的朋友圈编号？不行，合并两个朋友圈时要改一堆人。

并查集就像家族族谱：每个人记住自己的"父亲"，找到族长（根节点）就知道自己属于哪个家族。合并两个家族只需让一个族长认另一个族长当父亲。找族长时顺便把路径上的人直接挂到族长名下，下次查找就是 O(1)——这就是路径压缩。

## 概念讲解

### 树形集合表示

<CaUnionFindDiagram />

<Term def="用森林表示互不相交的集合，每棵树代表一个集合，根节点是集合代表的动态连通性数据结构">
并查集
</Term>

并查集维护若干不相交集合。find(x) 找 x 所在集合的根（代表元素），union(x,y) 合并两个元素所在集合。两种操作都通过"顺着父指针走到根"实现。

### 两种优化

<Term def="查找时把路径上所有节点直接挂到根下，压扁树的高度的优化">
路径压缩
</Term>

<Term def="合并时把矮树挂到高树下，保证树高增长缓慢的优化">
按秩合并
</Term>

路径压缩在 find 过程中把路径上的节点直接指向根，按秩合并在 union 时把小树挂到大树下。两者结合后，单次操作均摊复杂度为 O(α(n))，其中 α 是反阿克曼函数，对任何实际 n 都小于 5。

## 代码对照

```cpp
// 并查集：路径压缩 + 按秩合并
int fa[N], rnk[N];

void init(int n) {
    for (int i = 1; i <= n; i++) {
        fa[i] = i; rnk[i] = 0;
    }
}

// 路径压缩：递归找到根，同时把路径上所有节点直接指向根
int find(int x) {
    return fa[x] == x ? x : fa[x] = find(fa[x]);
}

// 按秩合并：矮树挂高树
void unite(int x, int y) {
    x = find(x); y = find(y);
    if (x == y) return;
    if (rnk[x] < rnk[y]) fa[x] = y;
    else if (rnk[x] > rnk[y]) fa[y] = x;
    else { fa[y] = x; rnk[x]++; }
}
// 单次操作均摊 O(α(n)) ≈ O(1)
```

## 常见误区

<Callout type="trap">
**现象：只写路径压缩不写按秩合并，结果正确但慢。**
原因 → 路径压缩只在 find 时触发，第一次合并可能建成链。
修法 → 两个优化都写，虽然只用路径压缩实际也很快，但两者结合才有理论保证。
</Callout>

<Callout type="trap">
**现象：判断连通后忘记合并。**
原因 → 逻辑错误，只 find 不 union。
修法 → 明确"查询用 find，合并用 unite"，合并前不需要手动 find。
</Callout>

<Exercises>
**问题 1**：路径压缩和按秩合并各解决什么问题？

<Answer>
路径压缩解决"树变高导致 find 慢"的问题——在查找时压扁路径。按秩合并解决"合并时树高增长过快"的问题——矮树挂高树。两者结合使单次操作均摊 O(α(n))。
</Answer>

**问题 2**：n 个元素最多需要多少次 union 操作才能让所有元素连通？

<Answer>
n-1 次。每次 union 至少减少一个集合，初始 n 个集合，最终 1 个，所以最多 n-1 次合并。这就是最小生成树 Kruskal 算法的理论基础。
</Answer>
</Exercises>
