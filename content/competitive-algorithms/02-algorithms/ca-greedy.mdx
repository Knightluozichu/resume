## 直觉引入

你在超市排队结账，有 n 件商品要扫描。怎么排顺序最快？当然是先扫快的后扫慢的——每步选当前最优。这就是贪心：每一步做当下最好的选择，不回头。

但贪心不总是对的。比如找零钱，面额 1、5、11，找 15 元。贪心选最大的 11，剩 4 个 1 元共 5 枚；但选 5+5+5 只要 3 枚。贪心能用需要满足"局部最优能推导出全局最优"的性质，这个性质需要证明。

## 概念讲解

### 贪心策略

<CaGreedyDiagram />

<Term def="每一步都做当前看来最优的选择，且不回退的算法策略">
贪心算法
</Term>

贪心的关键不是"选最大的"，而是"选什么属性排序"。活动选择问题按结束时间排序选最早结束的；Huffman 编码按频率选最小的合并；最小生成树按边权排序选最小的。排序依据不同，但本质都是"贪心选择性质"。

### 正确性证明

<Term def="证明任何最优解都可以通过交换变成贪心解而不变差的证明方法">
交换法
</Term>

证明贪心解不劣于任何解：假设存在更优解，找出它与贪心解的第一个不同选择，交换后证明不更差，矛盾。或用数学归纳法证明每步贪心选择都在某个最优解中。

## 代码对照

```cpp
// 活动选择问题：n 个活动各有起止时间，选最多不冲突的活动
// 贪心策略：按结束时间排序，选最早结束的
struct Activity { int start, end; };

int selectMax(Activity a[], int n) {
    sort(a, a + n, [](const Activity& x, const Activity& y) {
        return x.end < y.end;           // 按结束时间排序
    });
    int count = 1, lastEnd = a[0].end;
    for (int i = 1; i < n; i++) {
        if (a[i].start >= lastEnd) {     // 不冲突
            count++;
            lastEnd = a[i].end;
        }
    }
    return count;
}
// 时间复杂度 O(n log n)，正确性可用交换法证明
```

## 常见误区

<Callout type="trap">
**现象：想出贪心策略直接交，WA。**
原因 → 贪心策略不满足贪心选择性质，局部最优无法推导全局最优。
修法 → 先用交换法尝试证明，证不出就构造反例。有反例就换 DP。
</Callout>

<Callout type="trap">
**现象：排序依据选错。**
原因 → 按直觉排序（如按开始时间），而非按贪心性质要求的依据（如结束时间）。
修法 → 分析"选哪个不会影响后续"——活动选择中选最早结束的留下最多时间给后续。
</Callout>

<Exercises>
**问题 1**：贪心和动态规划的根本区别是什么？

<Answer>
贪心每步做不可撤回的局部最优选择，不回头；DP 考虑所有子问题取最优。贪心适用范围窄但高效（通常 O(n log n)），DP 适用范围广但慢（通常 O(n^2)）。贪心是 DP 的特例：当子问题有"最优子结构+贪心选择性质"时可用贪心。
</Answer>

**问题 2**：活动选择问题为什么按结束时间排序而不是开始时间？

<Answer>
按结束时间排序选最早结束的，能给后续活动留出最多时间。按开始时间排序可能选了一个很长的活动，占用了大量时间段，导致后续可选活动变少。交换法可证明：任何最优解都能调整为选最早结束活动的解。
</Answer>
</Exercises>
