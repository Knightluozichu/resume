## 直觉引入

你要在一篇长文中查找一个词。最直觉的做法是逐个位置尝试匹配，失败就后移一位重来——这是暴力匹配，最坏 O(nm)。但失败时你已经匹配了一段前缀，能不能利用这个信息多跳几步？

KMP 的思路就是"失败时别白费功夫"。它预先计算一个 next 数组，告诉你匹配失败时模式串该跳到哪，而不是从头开始。就像你走迷宫走到死路，不是回到起点，而是回到上一个岔路口。

## 概念讲解

### KMP 字符串匹配

<CaStringAlgosDiagram />

<Term def="利用已匹配前缀的信息，通过 next 数组在失配时跳过不可能匹配的位置，实现 O(n+m) 的字符串匹配算法">
KMP
</Term>

next[i] 表示模式串 [0,i] 的最长相等前后缀长度。失配时模式串指针跳到 next[当前位-1]+1，主串指针不动。预处理 next 数组 O(m)，匹配 O(n)，总 O(n+m)。

### 字典树与 AC 自动机

<Term def="将多个字符串的公共前缀合并存储的树形结构，支持 O(L) 插入和查找">
字典树（Trie）
</Term>

<Term def="在字典树上构建类似 KMP 的失配指针，实现多模式串同时匹配的算法">
AC 自动机
</Term>

字典树把公共前缀共享存储，插入和查找都是 O(字符串长度)。AC 自动机在字典树上加失配指针，把 KMP 从单模式扩展到多模式：一次扫描文本即可匹配所有模式串。

## 代码对照

```cpp
// KMP 字符串匹配
void computeNext(char p[], int m, int next[]) {
    next[0] = -1;
    int i = 0, j = -1;
    while (i < m) {
        if (j == -1 || p[i] == p[j]) {
            next[++i] = ++j;     // 匹配成功，next[i] = j+1
        } else {
            j = next[j];         // 失配，j 回跳
        }
    }
}

int kmpSearch(char s[], int n, char p[], int m) {
    int next[N]; computeNext(p, m, next);
    int i = 0, j = 0;
    while (i < n && j < m) {
        if (j == -1 || s[i] == p[j]) { i++; j++; }
        else j = next[j];       // 失配，模式串跳转，主串不动
        if (j == m) return i - m; // 找到匹配
    }
    return -1;
}
// 时间 O(n+m)，空间 O(m)
```

## 常见误区

<Callout type="trap">
**现象：next 数组计算错误导致死循环。**
原因 → next[0] 未初始化为 -1，或失配回跳逻辑有误。
修法 → next[0] = -1 是哨兵，表示"主串指针前进，模式串回到开头"。
</Callout>

<Callout type="trap">
**现象：AC 自动机匹配结果重复或遗漏。**
原因 → 失配指针构建时 BFS 顺序不对，或 fail 指针未沿链传递。
修法 → BFS 保证按层序构建，查询时沿 fail 链收集所有匹配。
</Callout>

<Exercises>
**问题 1**：KMP 相比暴力匹配为什么快？

<Answer>
暴力匹配失配时主串回退到上次起点+1，模式串回到开头，最坏 O(nm)。KMP 利用 next 数组在失配时知道"已匹配前缀中最长相等前后缀"，模式串跳到该位置继续，主串不回退。总比较次数 O(n+m)。
</Answer>

**问题 2**：AC 自动机和 KMP 的关系是什么？

<Answer>
KMP 是单模式串匹配，用 next 数组处理失配。AC 自动机是多模式串匹配，在字典树上为每个节点构建 fail 指针（类似 next 数组），本质是把 KMP 的失配机制从"一条链"扩展到"一棵树"。一次扫描文本即可匹配所有模式串。
</Answer>
</Exercises>
