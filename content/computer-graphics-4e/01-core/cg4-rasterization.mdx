## 光栅化回答“哪些样本属于图元”

连续三角形没有“天然像素”。<Term def="在离散采样位置上判断点、线或多边形覆盖，并生成供后续着色和逐样本操作处理的片段数据">扫描转换</Term>需要先规定 sample positions、边界包含规则、数值精度和 viewport 映射。若相邻三角形对共享边采用不同临时判断，就会出现裂缝或重复覆盖。

光栅化也不负责所有前后工作：图元必须先在齐次 clip space 裁剪，之后 perspective divide 和 viewport 进入屏幕坐标；覆盖后才有插值、fragment shader、depth/stencil、blend 与 resolve。

## 齐次裁剪必须早于除以 w

Clip-space 顶点 $p_c=(x_c,y_c,z_c,w_c)$要相对观察体平面裁剪。以常见对称 x/y 约束为例：

$$
-w_c\le x_c\le w_c,\qquad -w_c\le y_c\le w_c.
$$

不同 API 的 z clip/depth range 约定可能不同，应由目标 API 明确。跨裁剪面的边需要在齐次坐标中插值生成新顶点及属性，然后才计算 NDC：

$$
(x_n,y_n,z_n)=\left(\frac{x_c}{w_c},\frac{y_c}{w_c},\frac{z_c}{w_c}\right).
$$

提前除以 w 会破坏跨相机平面图元的线性裁剪关系，尤其当 w 接近 0 或变号时产生爆裂。CPU reference 应保存 clip positions 和裁剪后顶点，不能从屏幕坐标开始假设图元天然合法。

Viewport 把 NDC 映射到窗口范围。若 NDC 为 $[-1,1]$，一个常见 x 映射是：

$$
x_s=x_0+\frac{x_n+1}{2}W.
$$

像素中心、原点方向和 depth mapping 必须与目标 API/测试约定一致。

## 边函数同时给出面积、覆盖和重心

对有向边 $v_i=(x_i,y_i)$ 到 $v_j=(x_j,y_j)$，定义：

$$
E_{ij}(p)=(p_x-x_i)(y_j-y_i)-(p_y-y_i)(x_j-x_i).
$$

符号由坐标系和顶点绕序决定；关键是三条边使用同一约定。$E_{01}(v_2)$的绝对值是三角形二倍面积。若面积为 0，则三点共线，不能归一化重心。

对一致绕序的内部点，可由对边函数得到：

$$
\lambda_0=\frac{E_{12}(p)}{E_{12}(v_0)},\quad
\lambda_1=\frac{E_{20}(p)}{E_{20}(v_1)},\quad
\lambda_2=1-\lambda_0-\lambda_1.
$$

<Term def="以三角形三个顶点为仿射基的权重，满足 lambda0+lambda1+lambda2=1，可表示位置和线性属性">重心坐标</Term>在内部通常非负；它既是覆盖判据的归一化形式，也是插值权重。

## Top-left 规则固定共享边归属

若覆盖条件只是三条边均 `>= 0`，两个相邻三角形都会包含共享边；若都用 `> 0`，两边都排除，出现裂缝。<Term def="对边界样本只包含 top 或 left 类型边、排除其互补边，使共享边精确归属一个图元的覆盖约定">Top-left 规则</Term>用半开集合固定归属。

具体 top/left 判定依屏幕 y 方向和绕序约定。实现应先统一坐标系与正面积方向，再把“边值为零时是否包含”封装为单一函数；不能从另一 API 示例复制判断符号。

```cpp
struct Edge {
  double a, b, c;
  bool inclusive;

  double evaluate(Vec2 p) const { return a * p.x + b * p.y + c; }
};

bool covered(double value, bool inclusive, double epsilon = 0.0) {
  return value > epsilon || (std::abs(value) <= epsilon && inclusive);
}

for (Pixel pixel : integerBoundingBox(v0, v1, v2, targetExtent)) {
  Vec2 p = pixel.center();
  double e0 = edge12.evaluate(p);
  double e1 = edge20.evaluate(p);
  double e2 = edge01.evaluate(p);
  if (covered(e0, edge12.inclusive) &&
      covered(e1, edge20.inclusive) &&
      covered(e2, edge01.inclusive)) {
    shadeSample(pixel, {e0 / area, e1 / area, e2 / area});
  }
}
```

硬件通常用固定点和增量求值保证共享边一致；教学实现用 double/epsilon 时要防止两个三角形因独立浮点误差同时包含/排除边。更可靠的 CPU 对照可量化到统一 subpixel fixed-point 网格。

## Bounding box 与增量遍历

Triangle setup 先求屏幕 bounding box，并裁剪到 framebuffer/scissor。边方程是线性的：x 增 1 时 $E$ 墼 a，y 增 1 时增 b，因此内层循环无需每个样本重新做完整叉积。

```cpp
for (int y = minY; y <= maxY; ++y) {
  Vec3 e = evaluateEdgesAt({minX + 0.5, y + 0.5});
  for (int x = minX; x <= maxX; ++x) {
    if (insideTopLeft(e)) emit(x, y, e / doubleArea);
    e += edgeStepX;
  }
}
```

Tile-based rasterization 还会先对小块做粗覆盖判定，再细分到 samples。小三角形、退化三角形和极大屏幕外 bounding box 都需单独测试。

## 仿射属性与透视正确插值

屏幕空间线性属性可直接：

$$
a_{linear}(p)=\sum_{i=0}^{2}\lambda_i a_i.
$$

但 UV、world position 等在透视投影后不能直接以屏幕重心线性插值。正确形式同时插值 $a_i/w_i$ 与 $1/w_i$：

$$
a(p)=
\frac{\sum_i\lambda_i\,a_i/w_i}
{\sum_i\lambda_i/w_i}.
$$

<Term def="在屏幕重心权重下分别插值属性除以 clip w 与 1/w，再相除恢复投影前线性关系的方法">透视正确插值</Term>不是“插完再随便乘回 w”，分母是每个样本插值得到的 reciprocal-w。

```cpp
template <typename T>
T perspectiveInterpolate(
    Vec3 lambda, std::array<T, 3> attribute, std::array<double, 3> clipW) {
  double reciprocalW = 0.0;
  T numerator{};
  for (int i = 0; i < 3; ++i) {
    double weightOverW = lambda[i] / clipW[i];
    numerator += attribute[i] * weightOverW;
    reciprocalW += weightOverW;
  }
  return numerator / reciprocalW;
}
```

GLSL 默认 smooth varying 使用透视正确插值；`noperspective`选择屏幕线性，`flat`不插值。Centroid/sample qualifier 影响多样本时求值位置，应根据导数、边缘和 coverage 需求选择。

## Pixel、Sample、Fragment 不是同义词

<Cg4SamplingFrequencyDiagram />

一个 pixel 是存储/显示格；coverage sample 是图元覆盖和 depth/stencil 的测试位置；fragment invocation 是 shader 执行；resolve 后才得到最终 pixel color。它们的数量不固定相等：

- overdraw 让同一 pixel 有多个图元 fragments；
- early tests 可在 shader 前拒绝，late tests 则在后；
- derivatives 可能创建 helper invocations；
- 4×MSAA 常有四个 coverage/depth samples，但 fragment shader可每 pixel 执行一次并把结果用于多个 covered samples；
- 开启 sample shading 或读取 sample-specific 状态可提高 invocation 频率。

Fragment shader 也不总在像素中心求值；插值位置必须在 covered region 中时可使用 centroid 等规则，避免边缘外推属性导致非法纹理坐标。

## 走样是采样与重建问题

<Term def="连续信号中超过采样系统可表示频率的内容折叠成错误低频模式，形成锯齿、摩尔纹或闪烁">走样</Term>不仅是轮廓锯齿。几何边界、细纹理、高光、程序噪声和动画时间变化都可能超出采样能力。

采样理论的理想带限条件为采样频率至少是最高信号频率两倍，但几何阶跃边界并非带限。工程方法是在采样前滤波或增加样本并重建：

- **MSAA**增加几何 coverage/depth samples，主要改善边缘，不自动过滤 shader/纹理高频；
- **SSAA**在更高分辨率执行完整着色后滤波下采样，覆盖更多走样来源但成本高；
- **Mipmapping/anisotropic filtering**预滤纹理 footprint，处理 minification；
- **Temporal AA**跨帧抖动和积累，需要 motion/reprojection 与历史有效性；
- **Analytic coverage**对特定图元直接估计像素覆盖。

“抗锯齿就是模糊”错误，因为低通滤波的目标是在离散采样前移除不可表示频率，重建滤波又要尽量保留可表示细节。评价应包含静态边缘、远处纹理、细高光和运动稳定性。

## 常见误区

<Callout type="trap">
**现象 →** 两个三角形拼成矩形时对角线偶发裂缝或颜色加深。
**原因 →** 边值等于 0 时两个图元都包含或都排除，没有统一 top-left 半开规则，或独立浮点误差破坏共享边一致性。
**修法 →** 统一绕序和 subpixel 表示，对互补有向边使用一致 inclusive 判定，并测试共享边每个 sample 恰好归属一次。
</Callout>

<Callout type="trap">
**现象 →** 纹理在倾斜平面上像橡皮布一样游动。
**原因 →** 用屏幕重心直接线性插值 UV，忽略每顶点 clip w。
**修法 →** 插值 UV/w 和 1/w 后相除；CPU 与 shader 使用同一顶点 clip values 做数值对照。
</Callout>

<Callout type="trap">
**现象 →** 开启 4×MSAA 后远处棋盘纹和高光仍闪烁。
**原因 →** MSAA 主要增加几何 coverage samples，并未预滤纹理或 shader 高频。
**修法 →** 纹理使用 mip/anisotropic footprint filtering，高光限制频率或采用时域/超采样策略；按走样来源选择滤波。
</Callout>

## 练习

<Exercises>

1. **共享边：** 两个相邻 CCW 三角形共享一条边，样本恰在边上。为什么单纯 `E>=0` 和 `E>0` 都不正确？

<Answer>
若两边都用 `E>=0`，共享边样本会被两个三角形覆盖，blend/计数可能重复；若都用 `E>0`，两者都排除，形成裂缝。Top-left 半开规则根据有向边类型让一个三角形包含、另一侧排除，因此并集无缝且不重复。判定符号需与坐标 y 方向和绕序配套。
</Answer>

2. **透视插值：** 屏幕重心为 (0.5,0.25,0.25)，三个顶点 $w=(1,2,4)$，标量属性 $a=(0,1,1)$。求透视正确值。

<Answer>
分子为 $0.5·0/1+0.25·1/2+0.25·1/4=0.1875$；分母为 $0.5/1+0.25/2+0.25/4=0.6875$；结果 $a=0.1875/0.6875\approx0.2727$。直接屏幕线性插值会得到 0.5，明显不同。
</Answer>

3. **采样频率：** 一个 pixel 的 4 个 MSAA samples 有 3 个被三角形覆盖。是否必然执行 3 次 fragment shader？Resolve 结果是什么？

<Answer>
不必然。默认情况下实现可按 fragment/pixel 频率执行一次着色并把颜色用于三个 covered samples；开启 sample shading 或 sample-specific 行为才可能增加 invocation。Resolve 将各 samples 的最终颜色按规则合成：三个 covered samples 使用三角形结果，一个 uncovered sample保留背景，因此简单平均示例为 $0.75C_{tri}+0.25C_{bg}$，还需考虑实际 format/resolve 规则。
</Answer>

</Exercises>

## 本章回顾

- 齐次裁剪早于 perspective divide，viewport/sample 约定决定屏幕覆盖合同；
- 边函数同时提供面积、覆盖和重心，top-left 规则保证共享边唯一归属；
- 透视正确插值对 attribute/w 和 1/w 分别插值再相除；
- pixel、sample、fragment invocation 与 resolve color 不同，抗锯齿必须按走样来源选择。
