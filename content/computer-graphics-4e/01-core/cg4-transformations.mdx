## 变换是在两个坐标系之间陈述同一对象

**Two-Dimensional Geometric Transformations / 二维几何变换**与 **Three-Dimensional Geometric Transformations / 三维几何变换**的共同核心不是记矩阵，而是明确源空间、目标空间、对象类型和组合顺序。同一个空间位置在局部、世界和相机坐标中有不同数值，但代表同一几何点。

让平移成为矩阵乘法：

$$
\begin{bmatrix}x'\\y'\\z'\\1\end{bmatrix}=
\begin{bmatrix}
R_{3\times3}&\mathbf t\\
\mathbf0^T&1
\end{bmatrix}
\begin{bmatrix}x\\y\\z\\1\end{bmatrix}.
$$

方向使用 w=0，因此平移列不生效。齐次向量还具有尺度等价：$p_h$与 $kp_h$（$k\ne0$）表示同一投影点，最终通过除 w 归一化。


## 向量约定、乘法顺序与内存布局是三件事

本章采用**列向量**：$p'=Mp$。因此组合 $p'=TRSp$表示先 scale、再 rotate、再 translate。若使用行向量 $p'=pM$，书写顺序相反，但几何可以完全等价。

Row-major/column-major 主要描述矩阵元素在内存中的排列；它不自动决定向量在左还是右、矩阵语义或函数组合顺序。OpenGL 接口的数组解释、GLSL 列向量习惯、GLM 默认存储/运算约定需要分别核对，不能用一句“OpenGL 是列主序”推导所有行为。

矩阵通常不可交换：

$$
TR\ne RT.
$$

“绕自身中心旋转”若模型 pivot 不在原点，需要把 pivot 移到原点、旋转、再移回：

$$
M=T(\mathbf p)R\,T(-\mathbf p).
$$

```cpp
Mat4 rotateAround(Vec3 pivot, Quat rotation) {
  return translate(pivot) * mat4(rotation) * translate(-pivot);
}

Vec4 pointWorld = model * Vec4(pointLocal, 1.0f);
Vec4 directionWorld = model * Vec4(directionLocal, 0.0f);
```

若 model 含缩放，方向长度会改变；若只需要方向，应取线性部分并按用途归一化。

## 二维观察：Window、Viewport 与裁剪

**Two-Dimensional Viewing / 二维观察**把世界或用户定义 window 映射到屏幕 viewport。对 window $[x_{w0},x_{w1}]$ 和 viewport $[x_{v0},x_{v1}]$：

$$
x_v=x_{v0}+(x_w-x_{w0})\frac{x_{v1}-x_{v0}}{x_{w1}-x_{w0}}.
$$

y 同理。若两个矩形 aspect ratio 不同，图形会被非均匀拉伸；可选择 letterbox/pillarbox、裁剪或改变观察范围。Window clipping 应在映射前定义保留区，viewport/scissor 则限制最终屏幕区域，二者语义不同。

```cpp
Vec2 windowToViewport(Vec2 p, Rect window, Rect viewport) {
  Vec2 normalized = {
    (p.x - window.min.x) / window.width(),
    (p.y - window.min.y) / window.height(),
  };
  return viewport.min + normalized * viewport.size();
}
```

当 window width/height 为 0 时映射未定义，必须拒绝；屏幕 y 轴向下的 UI 与数学 y 轴向上的场景还需明确翻转位置。

## 三维旋转与刚体变换

绕单位轴 $\hat u$旋转角 $\theta$可用 Rodrigues 公式：

$$
R\mathbf v=\mathbf v\cos\theta+
(\hat u\times\mathbf v)\sin\theta+
\hat u(\hat u\cdot\mathbf v)(1-\cos\theta).
$$

Rotation matrix 应近似正交且 determinant 为 +1。Euler angles 依赖旋转轴顺序并可能出现 gimbal lock；quaternion 适合组合和插值，但仍需归一化，并注意 $q$与 $-q$代表同一旋转。

刚体变换保持长度和角度；一般 affine transform 可含非均匀 scale/shear，不能再用转置代替逆矩阵。

## View Matrix 是相机姿态的逆

**Three-Dimensional Viewing / 三维观察**先建立相机 frame，再把世界坐标表达成相机坐标。若 camera-to-world 为：

$$
C=\begin{bmatrix}R&\mathbf e\\0&1\end{bmatrix},
$$

其中 R 为正交相机基、e 为世界位置，则 world-to-view：

$$
V=C^{-1}=\begin{bmatrix}R^T&-R^T\mathbf e\\0&1\end{bmatrix}.
$$

不是“把相机对象本身移到原点”的副作用，而是坐标基变换。

```cpp
Mat4 makeView(Vec3 eye, Vec3 target, Vec3 upHint) {
  Vec3 forward = normalize(target - eye);
  if (length2(cross(forward, upHint)) < 1e-10f) {
    throw InvalidCamera("up is parallel to view direction");
  }
  Vec3 right = normalize(cross(forward, upHint));
  Vec3 up = cross(right, forward);
  return inverseRigidFrame(right, up, -forward, eye); // 右手、相机看 -Z 的约定
}
```

Cross product 顺序、forward 是 +Z 还是 -Z 取决于 handedness 和 API convention。不要只背 `cross(f, up)`；用测试验证 eye 映射到原点、target 映射到相机前方、基向量正交。

## Projection 产出 Clip Coordinates

输出 clip coordinates，不直接输出屏幕像素。

Orthographic projection 是 affine map；perspective projection通过 $w_c$使除 w 后出现近大远小。在右手、相机朝 -Z 的常见约定中：

$$
x_{ndc}=\frac{x_v}{-z_v\tan(fov_y/2)\,aspect},\qquad
y_{ndc}=\frac{y_v}{-z_v\tan(fov_y/2)}.
$$

Near/far 必须满足目标矩阵约定；near 不能为 0。Depth clip/NDC range 在 OpenGL 与其他 API、GLM 编译配置中可能不同。错误混用会导致裁剪和深度重建失配。

标准透视 depth 精度随距离非线性分布，near plane 过小会严重浪费远处精度。Reverse-Z 和 floating-point depth 可改善精度，但需要配套 projection、clear、compare 和 depth range，不能只翻转 compare op。

```cpp
struct CameraMatrices {
  Mat4 view;
  Mat4 projection;
  Mat4 viewProjection;
};

CameraMatrices buildCamera(const Camera& c, const ClipConvention& convention) {
  Mat4 view = makeView(c.eye, c.target, c.up);
  Mat4 projection = perspective(
      c.verticalFov, c.aspect, c.nearPlane, c.farPlane, convention);
  return {view, projection, projection * view};
}
```

## 法线不是普通方向

在 model 线性部分 A 下为：

$$
\mathbf n'=(A^{-1})^T\mathbf n.
$$

推导来自切向量 $\mathbf n^T\mathbf t=0$：要求 $\mathbf n'^T(A\mathbf t)=0$，所以取 inverse-transpose。只有纯旋转或统一缩放后归一化等特殊情况，直接乘 A 才等价。


```cpp
Mat3 normalMatrix = transpose(inverse(mat3(model)));
Vec3 worldNormal = normalize(normalMatrix * localNormal);
```

若 A singular（某轴 scale=0），逆不存在；引擎应拒绝用于表面着色的退化变换或定义专门处理。

## 层次建模是坐标 frame 的树

**Hierarchical Modeling / 层次建模**把每个节点保存为相对父节点的 local transform。对于列向量约定：

$$
W_{child}=W_{parent}L_{child}.
$$

机械臂肩、肘、腕各在自己的 pivot frame 中旋转，父节点变化自动传递给后代。Mesh geometry 通常绑定在节点 local frame；动画更新 local parameters，遍历再生成 world matrices。

```cpp
void updateWorld(Node& node, const Mat4& parentWorld) {
  node.world = parentWorld * node.local;
  for (Node* child : node.children) updateWorld(*child, node.world);
}
```

需防止 scene graph cycle；reparent 时若要保持 world pose，应计算新 local：$L'=(W'_{parent})^{-1}W_{old}$。缓存 world transform 需要 dirty propagation 或版本号，否则父变更后子节点会使用旧矩阵。

## 本章回顾

- 二维/三维 transform 与 viewing 都先声明源/目标 frame、对象类型和约定；
- View 是 camera world frame 的逆，projection 输出 clip coordinates，除 w 后才是 NDC；
- 内存布局不等于向量乘法约定，矩阵组合顺序必须用已知数值测试；
- Normal 使用 inverse-transpose，层次节点使用 parentWorld×local 并管理 dirty/cycle/reparent。
