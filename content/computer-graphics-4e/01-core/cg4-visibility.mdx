## 可见性不是一个 Z 比较

**Visible-Surface Detection Methods / 可见面检测**解决“哪些表面对观察者有贡献”。现代渲染器通常分层减少候选：观察体外对象、背向图元、被粗层次完全遮挡的对象，最后才是每 sample 深度/模板。

必须保守：优化层可以漏剔除并交给后级处理，不能错误剔除真正可见对象。


## Clipping、Culling 与 Occlusion 分工

- **Frustum/view-volume clipping**：对象或图元位于观察体外；它与是否被其他物体遮挡无关。
- **Back-face culling**：对绕序一致的闭合表面，背向图元通常不贡献 opaque 外表；双面材质、镜像变换和开放表面需另行处理。
- **Occlusion culling**：对象在观察体内但被其他表面完全挡住；必须使用保守 bounds 和上一帧/当前帧深度证据。
- **Depth test**：光栅后对同一 sample 的候选深度比较，决定当前片段是否通过。

把四者统称“看不见就剔除”会导致错误：透明背面可能需要，投影屏幕很小的对象仍可能高亮，上一帧被遮挡的快速移动对象本帧可能出现。

## Z-buffer 的顺序无关边界

对 opaque、比较关系一致的片段近似顺序无关。

软件参考的 conventional depth 可以写为：

```cpp
void testAndWrite(Fragment f, Buffers& b) {
  if (f.depth < b.depth[f.sample]) {
    b.depth[f.sample] = f.depth;
    b.color[f.sample] = shade(f);
  }
}
```

但“clear=1、LESS”不是普遍规则。Reverse-Z 常使用 clear=0、GREATER；自定义 depth range 或等值 pass 也不同。正确配置必须是一组合同：projection mapping、clip/depth range、clear value、compare op、depth write 和重建公式。

Depth buffer 不保存完整排序，只保存当前最优深度。它不能直接给出第二层表面，也不能单独正确混合多个透明层。

## 透视深度为何远处难区分

标准 perspective mapping 可抽象为 view depth $d>0$ 到：

$$
z_{buffer}=A+\frac{B}{d},
$$

其中 A、B 由 near/far 和 API range 决定。导数大小：

$$
\left|\frac{dz_{buffer}}{dd}\right|=\frac{|B|}{d^2}.
$$

固定深度量化步长 $\Delta z$ 对应的世界深度间隔近似：

$$
\Delta d\approx\frac{d^2}{|B|}\Delta z.
$$

距离越远，同一个 depth code 覆盖越大的世界空间区间，因此共面或近共面表面更易量化到相同/相邻值。是整个几何、投影和量化链的结果，不只是“缓冲位数低”。

提高 near（不要无意义接近 0）、合理缩短 far、避免重复共面几何、为 decal 使用经过推导的 offset，都是针对性修复。盲加 polygon offset 会在不同斜率/分辨率产生新错误。

## Reverse-Z 与浮点深度

配合 floating-point depth，可利用浮点在 0 附近更密集的表示抵消 perspective $1/d$分布，显著改善远处精度，尤其 infinite far projection。

```cpp
struct DepthConvention {
  float clearValue;
  CompareOp compare;
  Mat4 projection;
};

DepthConvention reverseZ(const Camera& c) {
  return {
    .clearValue = 0.0f,
    .compare = CompareOp::Greater,
    .projection = makeReverseInfinitePerspective(c.fovY, c.aspect, c.nearPlane),
  };
}
```

迁移必须同步修改：projection、clip control/depth range、clear、compare、depth pyramid reduction、depth reconstruction、shadow/SSAO/post effects。只把 LESS 改 GREATER 会让整个场景错误。

## Early Tests、Hi-Z 与 Shader 行为

是实现优化，不改变 API 正确性语义。硬件可进行 early test、late test，或先保守判定再延后写入。

写 fragment depth、discard、side effects、sample masks 等行为会限制某些 early test/update，但不能简单断言“使用 discard 就完全没有 Early-Z”。具体优化由 API 语义、shader 声明和实现决定，应看 profiler/counters。

Hierarchical Z（Hi-Z）把 depth 聚合为 tile/mip 层次，用保守 min/max 快速拒绝整块。Reduction 方向取决于 LESS/GREATER convention。Depth pyramid 做对象 occlusion 时，投影 bounds、mip 选择、屏幕边界、上一帧延迟和相机运动都要保守处理。

## Depth Prepass 是成本交换

增加一次几何变换、raster、depth bandwidth 和 command cost，可能在高 overdraw、昂贵 pixel shader 场景收益，低 overdraw 或几何受限时反而更慢。

```cpp
// Pass 1: depth only
setColorWrites(false);
setDepthWrite(true);
setDepthCompare(convention.nearWins); // LESS or GREATER
drawOpaque(depthOnlyPipeline);

// Pass 2: shade the same opaque geometry
setColorWrites(true);
setDepthWrite(false);
setDepthCompare(CompareOp::Equal); // 数值路径一致时；否则选择经过验证的策略
drawOpaque(materialPipelines);
```

Prepass 与正式 pass 的 vertex deformation、alpha-tested geometry、LOD 和 depth calculation 必须一致，否则 EQUAL 会漏像素。Alpha cutout 常需要两次 texture/discard，收益需单独测量。

Front-to-back opaque sorting 可在无需完整 prepass 的情况下提高 early rejection；但排序增加 CPU/state 成本，应与材质 batching 权衡。

## Painter、BSP 与透明表面

直观但遇到循环遮挡或相交 polygon 时无法靠全局排序解决，可能需要 split 或 BSP。

标准 alpha blending 非交换，透明表面通常先画 opaque（depth write on），再将透明对象近似 back-to-front 排序、depth test on、depth write off。对象中心排序无法解决相交透明几何和单对象内部顺序。

Order-independent transparency（OIT）方法以更多内存/近似换取顺序鲁棒：depth peeling 保存多层，per-pixel linked list 精确收集后排序，weighted blended OIT 更便宜但近似。没有一种方法对所有透明、折射和体积情况都精确且低成本。

## 本章回顾

- Frustum、back-face、occlusion 与 depth test 是不同粒度的保守拒绝层；
- Depth mapping、clear、compare、reconstruction 必须形成完整 conventional/Reverse-Z 合同；
- Z-fighting 来自 perspective mapping 与量化，修复要针对 near/far、几何和格式；
- Z-prepass/Hi-Z 是实测优化，透明可见性需要排序或 OIT，不能只靠最近深度。
