## 从一个会失败的图像实验开始

Computer Graphics Systems and Applications要回答的不是“这个名词是什么”，而是：在固定输入下，如何验证“从应用需求反推图形系统的数据流与交互闭环”，并让一个反例可重复地推翻错误实现？先写下预期像素、几何或估计量，再运行基线；只要应用输入、管线阶段、误差预算和最终交互响应无法指出差异来自哪一步，图像看起来正确也不能通过。

本页的不变量是：Computer Graphics Systems and Applications的输入、公式中间量、输出与恢复结果可用同一基线复算。反例“先选API再定义应用误差预算，导致指标与用户任务脱节”只改变一个条件，因而正常、故障与恢复三次运行应能用同一输入直接比较。

## 原书单元与独立机制解释

### Computer Graphics Systems and Applications

computer graphics system 把建模、变换、可见性、着色与显示连接起来，graphics application 则决定精度、交互与性能目标。相同管线用于CAD、可视化或娱乐时，接受条件并不相同。

本单元的正式坐标是computer graphics system、graphics application。验证Computer Graphics Systems and Applications时，先制造“先选API再定义应用误差预算，导致指标与用户任务脱节”，再检查应用输入、管线阶段、误差预算和最终交互响应能否把错误定位到从应用需求反推图形系统的数据流与交互闭环的首个分叉。

$$
y=D(S(V(T(x))))
$$

## 最小可重现实验

```cpp
FrameResult render(const Scene& scene, const Camera& camera) {
  auto clip = transform(scene, camera);
  auto visible = clip_and_cull(clip);
  auto fragments = rasterize(visible);
  return shade_and_present(fragments);
}
```

运行Computer Graphics Systems and Applications时固定随机种子、输入几何、坐标约定和数值精度；记录编译命令或算法版本、输出摘要与失败条件。实验输出若依赖隐藏全局状态，必须先消除该依赖再比较。

<Callout type="trap" title="本页核心误区">
  先选API再定义应用误差预算，导致指标与用户任务脱节。这个错误会破坏“Computer Graphics Systems and Applications的输入、公式中间量、输出与恢复结果可用同一基线复算”，应先由应用输入、管线阶段、误差预算和最终交互响应定位，再讨论性能或视觉风格。
</Callout>

<Callout type="trap" title="不要把别的图形API模板套进来">
  Computer Graphics Systems and Applications只解释从应用需求反推图形系统的数据流与交互闭环。若原始资料讨论纯C++路径追踪、OpenGL时代图形学或光传输积分，就不能用VkBuffer、Fence与Semaphore替代相应的几何、光栅化或蒙特卡洛机制。
</Callout>

<Exercises>

**问题 1：公式与边界。** 怎样用一个数值样本证明 $y=D(S(V(T(x))))$ 中的量没有混用空间、单位或概率密度？

<Answer>
  先写出每个量的定义域与单位，选择能手算的输入，分别计算中间量和最终结果；再只扰动一个量。若应用输入、管线阶段、误差预算和最终交互响应的变化方向与公式不一致，应拒绝实现而不是调整截图。
</Answer>

**问题 2：正式坐标。** computer graphics system、graphics application如何进入可操作验证？

<Answer>
  1. **computer graphics system**：在专属实验中选中该节点，保存输入与应用输入、管线阶段、误差预算和最终交互响应，注入“先选API再定义应用误差预算，导致指标与用户任务脱节”后恢复并重放。
  2. **graphics application**：在专属实验中选中该节点，保存输入与应用输入、管线阶段、误差预算和最终交互响应，注入“先选API再定义应用误差预算，导致指标与用户任务脱节”后恢复并重放。
</Answer>

**问题 3：故障恢复。** 如何证明“先选API再定义应用误差预算，导致指标与用户任务脱节”已经真正修复？

<Answer>

</Answer>
