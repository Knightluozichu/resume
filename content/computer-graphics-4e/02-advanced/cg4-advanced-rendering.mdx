## Computer Animation：状态是时间函数

动画把状态写成 $x(t)$。位置线性插值：

$$
\mathbf p(t)=(1-u)\mathbf p_0+u\mathbf p_1,
\qquad u=\frac{t-t_0}{t_1-t_0}.
$$

Rotation 不宜直接逐分量插值 Euler angles；quaternion slerp 选择单位球上的弧，并处理 $q$与 $-q$等价和 shortest path。Scale、morph weights、camera parameters 也应按语义插值，而不是所有属性统一 lerp。

物理/程序动画应将 simulation timestep 与 display frame 分开。Fixed timestep accumulator：

```cpp
accumulator += clamp(realDeltaTime, 0.0, maxFrameDelta);
while (accumulator >= fixedDt) {
  previousState = currentState;
  simulate(currentState, fixedDt);
  accumulator -= fixedDt;
}
double alpha = accumulator / fixedDt;
render(interpolate(previousState, currentState, alpha));
```

它提高不同帧率下的可复现性，但网络、碰撞和随机数还需 deterministic policy。Motion blur/TAA 需要保存 previous transforms；teleport/animation reset 时必须使历史失效。

## Interaction 与 GUI：屏幕输入要回到场景

有两条常见路径：

1. **ID buffer picking**：绘制 object/primitive ID 到整数 attachment，点击时读取对应 pixel；需处理 DPI、viewport origin、MSAA resolve 和异步 readback。
2. **Ray picking**：把 screen point unproject 成 world ray，与 BVH/geometry 求交；需使用与渲染一致的 view/projection/depth conventions。

```cpp
Ray screenRay(Vec2 cursorLogical, const Viewport& vp, const Camera& camera) {
  Vec2 framebufferPixel = logicalToFramebuffer(cursorLogical, vp.dpiScale);
  Vec2 ndc = framebufferToNdc(framebufferPixel, vp);
  Vec4 nearH = inverse(camera.viewProjection) * clipPoint(ndc, camera.nearNdc);
  Vec4 farH  = inverse(camera.viewProjection) * clipPoint(ndc, camera.farNdc);
  Vec3 nearP = nearH.xyz / nearH.w;
  Vec3 farP = farH.xyz / farH.w;
  return {nearP, normalize(farP - nearP)};
}
```

GUI 还要管理 focus、capture、keyboard navigation、accessibility 和 event ordering。Picking hit 只是输入，不应在 render callback 中随意改 scene graph；使用 command/state update 边界能保持动画、undo 和多线程一致。

## Shadow Map 是 Direct Visibility 近似

估计的是光源到表面的 visibility，不是 global illumination。

```glsl
float hardShadow(vec4 lightClip, sampler2D shadowDepth, float receiverBias) {
  vec3 p = lightClip.xyz / lightClip.w;
  vec2 uv = p.xy * 0.5 + 0.5;
  float receiver = p.z * 0.5 + 0.5;
  if (any(lessThan(uv, vec2(0))) || any(greaterThan(uv, vec2(1)))) return 0.0;
  float blocker = texture(shadowDepth, uv).r;
  return receiver - receiverBias > blocker ? 1.0 : 0.0;
}
```

Bias 取决于 depth convention、slope、normal、resolution 和 projection，固定 0.005 不是通用答案。过小产生 self-shadow acne，过大产生 Peter Panning。PCF 是对离散 comparisons 过滤，产生软边近似；真实 area-light penumbra 随 blocker/receiver geometry 变化。

## Forward/Deferred 是数据调度选择

可避免对被遮挡表面执行昂贵多光源着色，并方便 light volumes/tiles，但成本是 G-buffer memory bandwidth、格式精度、MSAA 和 material variation。

“前向 $O(geometry\times lights)$、延迟 $O(geometry+pixels\times lights)$”只是粗略口号。Forward+/clustered 也会筛 light lists；deferred 每 pixel 仍可能遍历很多 lights。真实工作取决于 visible samples、light overlap、material cost、overdraw 和 bandwidth。

G-buffer通常保存最近 opaque layer，不代表 deferred “无法支持透明”。透明层可在 opaque deferred 后用 forward/clustered pass，或采用 OIT/multi-layer structures；只是单层 G-buffer不能直接表示多个透明 surfaces。

## Global Illumination 与渲染方程

目标由 rendering equation 表达：

$$
L_o(x,\omega_o)=L_e(x,\omega_o)+
\int_{\Omega^+}f_r(x,\omega_i,\omega_o)L_i(x,\omega_i)
(\mathbf n\cdot\omega_i)d\omega_i.
$$

Ray tracing 只是沿 ray 求最近交点/可见性，不自动物理精确。Whitted ray tracing 递归镜面反射/折射；path tracing 用 Monte Carlo 随机路径估计更一般积分。对半球积分采样 $\omega_i\sim p$：

$$
\hat L_o= L_e+\frac1N\sum_{k=1}^{N}
\frac{f_r(\omega_k,\omega_o)L_i(\omega_k)
(\mathbf n\cdot\omega_k)}{p(\omega_k)}.
$$

Estimator 是否 unbiased/consistent、variance 大小、PDF 是否覆盖非零 integrand、Russian roulette 和 MIS 权重都影响正确性。更多 samples 降低随机噪声约 $1/\sqrt N$，不修复 bias 或错误 BRDF。

## Radiosity：Diffuse Patch 之间的能量

方程：

$$
B_i=E_i+\rho_i\sum_jF_{ij}B_j,
$$

其中 $F_{ij}$是 patch i 到 j 的 form factor，包含几何、距离、朝向和 visibility。封闭系统应近似满足 $\sum_jF_{ij}=1$，互易关系 $A_iF_{ij}=A_jF_{ji}$是数值检查。

Radiosity 适合 diffuse、相对静态场景，可预计算 view-independent patch radiosity；离散误差、form-factor 成本和动态更新是边界。它与 path tracing 不是“旧/新同一算法”，而是不同表示和求解策略。

## Algorithmic Modeling：生成结构也要可验证

Fractal/L-system、particle system、procedural field 和 subdivision 从规则生成内容。验收不只看复杂：

- random seed 与参数可复现；
- topology/bounds/level of detail 不爆炸；
- 粒子 timestep、spawn/death 和 conservation 按模型定义；
- procedural frequency 与采样率匹配，避免空间/时间 aliasing；
- 输出 mesh/field 与后续 visibility/lighting 的数据合同一致。

算法建模可驱动动画和可视化，例如 L-system 生长、streamline particles、implicit field isosurface。

## Visualization of Data Sets：颜色必须表达数据

的 transfer function 不只是美术渐变。Color map 应匹配 ordered/diverging/categorical data，标出单位和范围，避免 rainbow 产生假边界；缺失/越界值需显式编码。

Scalar field 可用 contour/isosurface；vector field 可用 glyph、streamline/particle；volume data 可用 slice、isosurface 或 direct volume rendering。

Emission-absorption ray marching 的离散 front-to-back 合成：

$$
\mathbf C\leftarrow\mathbf C+(1-A)\alpha_i\mathbf c_i,
\qquad
A\leftarrow A+(1-A)\alpha_i.
$$

当 A 接近 1 可 early terminate；空空间可跳跃。但 opacity 依 step length，改变采样步长时要做 opacity correction，否则同一体数据会变浓/变淡。

```glsl
vec4 integrateVolume(Ray ray) {
  vec3 color = vec3(0.0);
  float opacity = 0.0;
  for (float t = ray.tMin; t < ray.tMax && opacity < 0.995; t += stepSize) {
    float scalar = sampleVolume(ray.origin + t * ray.direction);
    vec4 sampleValue = transferFunction(scalar);
    float alpha = correctOpacity(sampleValue.a, stepSize, referenceStep);
    color += (1.0 - opacity) * alpha * sampleValue.rgb;
    opacity += (1.0 - opacity) * alpha;
  }
  return vec4(color, opacity);
}
```

Volume interpolation、gradient normal、transfer function、sampling rate 和 compositing order 都应在合成数据上验证。好看的云状图不证明数值位置和单位正确。

## 本章回顾

- Animation/interaction 把时间和输入映射为可复现状态，再进入 rendering 与反馈；
- Shadow map估 direct visibility，deferred 重排 surface/light 数据，不等于 GI 或“不能透明”；
- Ray tracing 是求交框架，path tracing/radiosity 以不同 estimator/表示求全局光传输；
- Data visualization 必须保留单位、范围和 transfer semantics，volume integration需对 step size 收敛。
