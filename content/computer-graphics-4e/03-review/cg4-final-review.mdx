## Capstone A：交互动画机械臂场景

<Term def="以层次机械臂、样条相机、纹理材质、阴影/GI reference 和交互拾取组成的综合渲染验收场景">交互动画场景</Term>包含：

- Hardware/system：记录 GPU/display/framebuffer/color 配置、输入 DPI 和帧时间；
- Primitives/attributes/algorithms：CPU line/triangle reference 与 GPU 输出比较；
- 2D：UI timeline 的 transform、window/viewport 和 clipping；
- 3D：机械臂 local→world 层次、camera view/projection；
- Animation：fixed-step keyframes 驱动关节，Bezier/B-spline camera path；
- Object representations：mesh arm、parametric curve、implicit marker；
- Visibility：frustum/back-face/depth/Hi-Z，transparent overlay 单独处理；
- Appearance：linear color、Lambert/BRDF、texture/normal map、shadow visibility；
- GI reference：少样本 path tracing 或 radiosity 静态 reference；
- Interaction/GUI：ID/ray picking、drag pivot、undo 和 keyboard focus；
- Shader：显式 vertex/fragment interfaces 和 debug views。

层次核心：

$$
W_{joint_i}=W_{parent(i)}L_{joint_i}(t),
\qquad
p_{clip}=PVW_{joint_i}p_{local}.
$$

Spline camera 按 arc-length 近似重参数化可减少速度不均；orientation 使用 stable frame/quaternion，避免 Frenet frame 在低曲率处翻转。

```cpp
FrameEvidence renderMechanicalArm(const AppState& state) {
  updateHierarchy(state.fixedTime);
  Camera camera = evaluateSplineCamera(state.cameraParameter);
  PickResult pick = resolvePendingInput(camera, state.viewport);

  drawDepthAndOpaque(camera);
  drawDirectLightingAndShadows(camera);
  drawTransparentAndGui(camera, pick);

  return captureEvidence({
    "joint-world-matrices", "clip-positions", "depth",
    "linear-hdr", "display-output", "pipeline-stats"
  });
}
```

“画面能动”不够：30/60/144 Hz 下 fixed state 应一致，拾取同一 framebuffer pixel 命中一致对象，shared raster edges 无裂缝，normal map seam 和颜色出口有 reference。

## Capstone B：解析 Scalar Volume

<Term def="由已知解析函数生成、可精确预测等值面、梯度和积分趋势的体数据可视化验收任务">解析体数据任务</Term>使用：

$$
f(x,y,z)=\exp[-k(x^2+y^2+z^2)].
$$

其 iso-surface $f=c$是半径：

$$
r=\sqrt{-\ln c/k},
$$

梯度：

$$
\nabla f=-2k(x,y,z)f.
$$

这给出已知 geometry、normal direction 和 scalar range，可验收 volume texture interpolation、transfer function、isosurface extraction、ray-box intersection、front-to-back compositing 和 step-size convergence。

```cpp
Volume makeAnalyticVolume(int resolution, double k) {
  Volume v(resolution);
  for (Voxel p : v.voxels()) {
    Vec3 x = voxelCenterToDomain(p, {-1, 1});
    v[p] = std::exp(-k * dot(x, x));
  }
  return v;
}

void validateIsoSurface(const Mesh& iso, double c, double k) {
  double expectedRadius = std::sqrt(-std::log(c) / k);
  for (Vec3 p : sampleVertices(iso)) {
    assertNear(length(p), expectedRadius, spatialTolerance);
  }
}
```

UI transfer function 要显示 scalar units/range，color map 选择需符合 ordered data；volume ray marching 将 step 减半时图像应在容差内收敛，而不是透明度翻倍。

## 统一的 Sampling 与 Appearance 检查

两个 capstone 共用四条不变量：

1. **Coordinate**：所有点可追踪 local/world/view/clip/NDC/screen 或 data/texture domain；
2. **Sampling**：edge/texture/volume footprint 和 temporal rate 与信号频率匹配；
3. **Visibility/transport**：producer、occluder、BRDF/transfer 和 integration order 明确；
4. **Color/data semantics**：线性 radiance 与显示编码分离，visualization color 不伪造数据边界。

Raster coverage 使用边函数：

$$
E_{ij}(p)=(p_x-x_i)(y_j-y_i)-(p_y-y_i)(x_j-x_i),
$$

Surface light 使用 rendering equation；volume 使用 emission-absorption composite。三者都在离散 samples 上近似连续积分，但积分域和语义不同，不能用“都是 shader”混为一类。

## Global Illumination Reference

交互 raster 场景用 direct light + shadow map 作为实时路径，用 path tracing/radiosity 作为受控 reference。Path estimator：

$$
\hat I_N=\frac1N\sum_{i=1}^{N}\frac{g(X_i)}{p(X_i)}.
$$

比较时固定 scene/material/light/camera/color management。Reference samples 增加应收敛；若均值有偏，不能把差异全部归因实时近似。

## Visualization 不是“漂亮的后处理”

Volume/field visualization 的正确性来自数据任务：找峰值、比较区间、定位 iso-surface、追踪 vector flow。Transfer function、interpolation 和 opacity可改变判断，必须保存参数和 legend。

## 常见误区

<Callout type="trap">
**现象 →** 总复习只画实时 raster pipeline，动画、GUI、算法建模和可视化完全没有验收。
**原因 →** 把一本完整 graphics textbook 缩成渲染 API 教程。
**修法 →** 逐项核对官方 22 章，以交互动画场景和解析 volume 两个 capstone 覆盖非管线单元。
</Callout>

<Callout type="trap">
**现象 →** Reference image 接近就判定通过，但 144 Hz 动画、HiDPI picking 或 volume step 改变后失败。
**原因 →** 只验空间单帧，缺少时域、交互和数值收敛证据。
**修法 →** 使用多维证据矩阵，每个风险有对应参数 sweep 和断言。
</Callout>

<Callout type="trap">
**现象 →** 为达到帧率先减少样本/精度，导致 aliasing 或数据结论改变。
**原因 →** 性能指标覆盖正确性目标，没有先定义允许误差。
**修法 →** 先冻结图像/数据误差和交互任务，再在质量约束内比较 LOD、过滤、culling、transport approximations。
</Callout>

## 综合练习

<Exercises>

1. **覆盖审计：** 机械臂场景为何不能单独覆盖 Visualization of Data Sets？

<Answer>
它主要可验收图形系统、图元、变换、层次、动画、对象/样条、可见性、光照纹理、颜色、交互、shader和GI，但没有保证 scalar/vector/volume data 的 transfer semantics、单位、isosurface和积分。解析 volume task 提供已知 field/gradient/radius与 step convergence，才对数据可视化形成直接证据。
</Answer>

2. **跨域错误：** 机械臂拾取总偏半个窗口，渲染图像本身正确。应检查哪些合同？

<Answer>
检查 logical cursor→framebuffer DPI scale、window client origin、viewport offset/size、屏幕 y 方向、NDC/clip depth convention、inverse viewProjection 和 asynchronous ID readback frame。图像正确只证明 forward rendering path，不证明 inverse interaction mapping。
</Answer>

3. **质量预算：** Volume step 加倍使 GPU 快 40%，但 iso 边界位置偏 3 voxels。能否直接采用？

<Answer>
先看任务允许的 spatial error；若阈值小于 3 voxels则不能。可尝试 empty-space skipping、adaptive sampling、preintegration或更好 transfer filtering，在误差约束内优化。报告必须同时给 GPU 时间、解析半径误差、step size 和 transfer parameters，不能只报加速比。
</Answer>

</Exercises>

## 本章回顾

- 官方 22 章全部进入两个 capstone 或解析测试，不把全书缩成 raster pipeline；
- 交互动画场景验收系统、几何、采样、外观、动画和输入闭环；
- 解析 volume 以已知 field/gradient/isosurface 验收数据语义、采样和积分收敛；
- 数学、图像、时域、交互和性能证据各自证明不同结论，必须共同闭环。
