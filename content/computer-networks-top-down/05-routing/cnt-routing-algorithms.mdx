## 路由算法概述

<CntRoutingAlgorithmsDiagram />

路由算法决定分组从源到目的的 **最佳路径**。根据算法工作方式分为两大类：

| 算法 | 信息 | 全局/分布式 | 代表协议 |
|------|------|------------|----------|
| 链路状态（LS） | 全网络拓扑 | 全局 | OSPF, IS-IS |
| 距离向量（DV） | 仅邻居信息 | 分布式 | RIP, BGP(路径向量) |

## 链路状态算法（LS）

链路状态算法要求每个节点获得 **完整网络拓扑**，然后独立计算最短路径。

### 工作流程

```text
1. 每个节点向所有节点广播自己的链路状态（链路开销）
   → 通过LSA（链路状态通告）洪泛
2. 每个节点收集所有LSA，构建完整拓扑图
3. 每个节点独立运行Dijkstra算法计算最短路径
```

### Dijkstra算法

```text
初始化：
  N' = {u}              ← 已确定最短路径的节点集
  D(v) = c(u,v)         ← u到v的直接链路开销
  p(v) = u              ← v的前驱节点

循环（直到N'包含所有节点）：
  找不在N'中且D(w)最小的节点w
  将w加入N'
  对w的每个邻居v（不在N'中）：
    D(v) = min(D(v), D(w) + c(w,v))
    如果更新了D(v)，则p(v) = w

结果：每个节点的最短路径树
```

<Callout type="info" title="LS算法的复杂度">

Dijkstra算法时间复杂度为 O(n^2)，n为节点数。每次链路状态变化时需要重新计算。LS算法的优点是每个节点有完整拓扑、收敛快、无计数到无穷问题。缺点是广播LSA的开销大、存储需求高（需存全拓扑）。OSPF协议使用LS算法。

</Callout>

## 距离向量算法（DV）

距离向量算法基于 **Bellman-Ford方程**，每个节点仅与邻居交换距离向量。

### Bellman-Ford方程

$$D_x(y) = \min_v \{ c(x,v) + D_v(y) \}$$

其中 `D_x(y)` 是x到y的最短路径开销，`c(x,v)` 是x到邻居v的直接链路开销。

### 工作流程

```text
初始化：
  每个节点x维护距离向量 Dx = [Dx(y1), Dx(y2), ...]
  Dx(y) = c(x,y)（直接相连），否则 = ∞

迭代更新：
  每个节点将自己的距离向量发送给所有邻居
  收到邻居的距离向量后，用Bellman-Ford方程更新：
    Dx(y) = min { c(x,v) + Dv(y) }  对所有邻居v
  如果Dx有变化，将新Dx发送给邻居

收敛：当没有距离向量变化时，算法终止
```

### 计数到无穷问题

```text
问题场景：A ← 1 → B ← 1 → C，C到A的开销从2变为50

时刻    A的D(A)    B的D(A)    C的D(A)
t0       0          1          2
t1       0          2          3      ← C告诉B：A可达(经B)开销3
t2       0          4          5      ← B更新为3+1=4，C更新为4+1=5
...      ...        ...        ...
需要很多轮才能收敛到正确值（B=50, C=51）

解决：毒性逆转——B告诉C「我到A的距离=∞」（因为B到A经过C）
```

<Callout type="warning" title="DV算法的优缺点">

优点：消息开销小（仅与邻居交换）、存储需求低（只存距离向量）。缺点：收敛慢（计数到无穷问题）、路由环路风险。毒性逆转只能解决两节点环路，多节点环路仍需水平分割等机制。RIP协议使用DV算法。

</Callout>

## OSPF（开放最短路径优先）

OSPF是互联网中广泛使用的 **内部网关协议（IGP）**，基于链路状态算法。

### OSPF特性

| 特性 | 说明 |
|------|------|
| 算法 | 链路状态（Dijkstra） |
| 指标 | 可配置（带宽、延迟、负载等） |
| 更新 | 链路状态变化时触发更新 + 定期刷新 |
| 区域 | 支持分层（区域0为骨干） |
| 安全 | 支持MD5认证 |

```text
OSPF分层区域结构：
        ┌─────────────────────┐
        │     区域0（骨干）     │
        │  ┌───┐   ┌───┐      │
        │  │R1 │───│R2 │      │
        │  └─┬─┘   └─┬─┘      │
        └────│────────│────────┘
             │        │
        ┌────│───┐ ┌──│────┐
        │区域1   │ │区域2  │
        │ R3 R4  │ │ R5 R6│
        └────────┘ └──────┘

区域边界路由器（ABR）：连接区域和骨干
区域间路由：先到骨干，再到目的区域
```

## BGP（边界网关协议）

BGP是互联网的 **外部网关协议（EGP）**，连接不同自治系统（AS）。

### 自治系统（AS）

```text
互联网 = 多个AS互联

  AS100（ISP-A）──── BGP ──── AS200（ISP-B）
     │                           │
  AS300（企业）              AS400（企业）
     │                           │
  内部OSPF                    内部OSPF
```

### BGP路由通告

```text
BGP路由 = 前缀 + 属性

关键属性：
  AS-PATH：经过的AS序列（防环路）
  NEXT-HOP：下一跳路由器IP
  LOCAL-PREF：本地优先级（策略选择）

通告示例：
  AS100通告：138.16.0.0/16, AS-PATH=[AS100]
  AS200收到后通告：138.16.0.0/16, AS-PATH=[AS200, AS100]
  AS300收到后看到AS-PATH不含自己 → 接受
```

### BGP路由选择

```text
BGP选择策略（按优先级）：
1. LOCAL-PREF值最高的路由
2. AS-PATH最短的路由
3. 最近的NEXT-HOP（Hot Potato路由）
4. 其他tiebreaker（路由器ID、MED等）
```

<Callout type="info" title="BGP为什么用策略而非最短路径">

BGP连接不同AS（不同ISP/企业），路由选择不仅看路径长度，还要考虑商业策略（如：优先走客户链路而非提供商链路、不经过竞争对手网络）。BGP是路径向量协议——不仅记录距离，还记录完整AS路径，用于策略控制和环路检测。BGP是互联网能扩展到全球规模的关键。

</Callout>

## SDN控制平面

SDN将路由计算从路由器中抽离，由 **集中式控制器** 统一完成。

```text
传统控制平面：                  SDN控制平面：
每路由器独立运行路由算法        集中式控制器计算路由
  → 转发表分布存储                → 下发流表到交换机
  → 分布式一致性                  → 全局视角，集中决策

SDN架构：
  应用层（路由应用、负载均衡、防火墙）
    ↕ Northbound API
  控制层（SDN控制器，集中式）
    ↕ Southbound API（OpenFlow）
  数据层（SDN交换机，仅转发）
```

<Glossary>

<GlossaryItem term="链路状态算法（Link State）">
链路状态算法是全局路由算法，每个节点通过洪泛链路状态通告（LSA）向全网广播自己的链路开销，收集后构建完整网络拓扑，独立运行Dijkstra算法计算最短路径。时间复杂度O(n^2)。优点：收敛快、无计数到无穷问题、每个节点有全局视角。缺点：LSA洪泛开销大、需存储全拓扑。OSPF和IS-IS协议使用LS算法。
</GlossaryItem>

<GlossaryItem term="距离向量算法（Distance Vector）">
距离向量算法是分布式路由算法，基于Bellman-Ford方程 D_x(y)=min&#123;c(x,v)+D_v(y)&#125;。每个节点仅维护到所有目的的距离向量，并与邻居交换。收到邻居向量后用方程更新自己的向量，变化则通知邻居。优点：消息开销小、存储低。缺点：收敛慢、计数到无穷问题、路由环路。毒性逆转可缓解两节点环路。RIP协议使用DV算法。
</GlossaryItem>

<GlossaryItem term="BGP（边界网关协议）">
BGP是互联网的外部网关协议，连接不同自治系统（AS）。BGP是路径向量协议——通告路由时携带AS-PATH（经过的AS序列），用于环路检测和策略控制。路由选择不仅看路径长度，还看商业策略（LOCAL-PREF优先级、客户/提供商关系）。BGP使互联网能扩展到全球规模，是不同ISP/企业网络互联的基础。
</GlossaryItem>

<GlossaryItem term="SDN（软件定义网络）">
SDN将网络的数据平面（转发）和控制平面（路由计算）物理分离。数据层SDN交换机仅根据流表转发，控制层集中式控制器通过OpenFlow等南向接口下发流表。优势：全局视角优化路由、灵活编程网络行为、快速部署新功能（无需升级交换机）。SDN将网络从「分布式硬件设备」转变为「集中式软件控制」的范式。
</GlossaryItem>

</Glossary>

**问题 1：** 链路状态算法和距离向量算法的核心区别是什么？各自有什么优缺点？

<Answer>

核心区别：链路状态（LS）是全局算法——每个节点通过洪泛LSA获得完整网络拓扑，独立运行Dijkstra算法计算最短路径；距离向量（DV）是分布式算法——每个节点仅维护到各目的的距离向量，通过Bellman-Ford方程与邻居交换信息迭代更新。LS优点：收敛快、无计数到无穷问题、每个节点有全局视角；缺点：LSA洪泛开销大、需存储全拓扑（O(n^2)复杂度）。DV优点：消息开销小（仅与邻居交换）、存储需求低；缺点：收敛慢、计数到无穷问题（毒性逆转只能解两节点环路）、路由环路风险。OSPF用LS，RIP用DV。
</Answer>

**问题 2：** BGP为什么使用策略路由而非最短路径？AS-PATH有什么作用？

<Answer>

BGP连接不同自治系统（不同ISP/企业），路由选择必须考虑商业策略：优先走客户链路（有收入）而非提供商链路（有成本）、不经过竞争对手网络、遵守合同协议等。最短路径无法表达这些策略需求。BGP是路径向量协议，路由选择按LOCAL-PREF > AS-PATH长度 > 最近NEXT-HOP等优先级决定。AS-PATH记录路由经过的AS序列，有两个关键作用：①环路检测——如果AS-PATH中包含自己的AS号，说明路由环路，拒绝该路由 ②策略控制——可根据AS-PATH中的AS关系（客户/提供商/对等）决定是否接受路由和设置LOCAL-PREF。BGP是互联网能扩展到全球规模的关键。
</Answer>

</Exercises>
