## 网络安全概述

<CntNetworkSecurityDiagram />

网络安全的目标是保障 **机密性、完整性、认证、可用性**（CIA + 可用性）。网络分层架构决定了安全措施需在每层部署。

### 安全威胁与防御

| 威胁 | 含义 | 防御手段 |
|------|------|----------|
| 窃听 | 窃听网络流量 | 加密（TLS/IPsec） |
| 篡改 | 修改传输数据 | 消息完整性校验（MAC/HMAC） |
| 伪造 | 冒充他人发送 | 数字签名/认证 |
| 拒绝服务 | 使服务不可用 | 防火墙/限流/CDN |
| 重放 | 重发旧消息 | 序号/时间戳/Nonce |

## 密码学基础

### 对称加密（Symmetric Encryption）

```text
加密：明文 + 密钥K → 加密算法 → 密文
解密：密文 + 密钥K → 解密算法 → 明文

发送方和接收方共享同一密钥K

常见算法：
  AES（高级加密标准）：128/192/256位密钥，当前主流
  DES：56位密钥，已不安全
  ChaCha20：流密码，移动端常用

分组密码模式：
  ECB（电子密码本）：相同明文→相同密文（不安全）
  CBC（密码块链接）：每块与前一块密文异或（推荐）
  GCM（伽罗瓦计数器）：加密+认证一体（TLS推荐）
```

### 公钥加密（Public Key Encryption）

```text
密钥对：公钥Pu（公开）+ 私钥Pr（保密）
加密：明文 + 公钥Pu → 密文
解密：密文 + 私钥Pr → 明文

或反过来：
签名：消息 + 私钥Pr → 数字签名
验签：签名 + 公钥Pu → 验证

常见算法：
  RSA：基于大数分解，2048+位
  ECC（椭圆曲线）：同等安全下密钥更短
  Diffie-Hellman：密钥交换（不用于加密）

公钥加密慢（比对称慢100-1000倍），实际用法：
  用公钥加密协商对称密钥 → 用对称密钥加密大量数据
```

### 散列函数与消息认证码

```text
散列函数 H()：
  任意长度输入 → 固定长度输出（如256位）
  单向性：无法从哈希反推原文
  抗碰撞：找不到两个不同输入产生相同哈希

  常见：SHA-256, SHA-3, MD5（已不安全）

消息认证码（MAC/HMAC）：
  HMAC = H(密钥K + H(密钥K + 消息M))
  
  验证消息完整性 + 消息来源（需共享密钥）

数字签名：
  签名 = 私钥Pr(哈希(消息))
  验证 = 公钥Pu(签名) == 哈希(消息)
  
  验证完整性 + 不可否认性（私钥唯一）
```

<Callout type="info" title="为什么实际中用混合加密而非纯公钥加密">

公钥加密计算量是对称加密的100-1000倍。加密1MB数据用AES只需毫秒，用RSA需数秒。因此实际安全协议（TLS/IPsec）采用混合加密：先用公钥加密（或Diffie-Hellman交换）协商一个对称会话密钥（通常128-256位），然后用对称加密保护大量数据。这样兼顾了公钥的密钥分发安全性和对称加密的高效性。

</Callout>

## TLS/SSL

TLS（传输层安全）是Web安全通信的标准，位于应用层和传输层之间，为TCP连接提供加密和认证。

### TLS握手过程

```text
TLS握手（以TLS 1.2为例）：

1. ClientHello
   客户端 → 服务器
   支持的密码套件列表 + 客户端随机数

2. ServerHello + 证书 + ServerKeyExchange
   服务器 → 客户端
   选定的密码套件 + 服务器随机数 + 服务器证书(含公钥)

3. 客户端验证证书
   检查证书链 → 信任CA签名 → 提取服务器公钥
   检查域名匹配、有效期、吊销状态

4. ClientKeyExchange
   客户端生成预主密钥 → 用服务器公钥加密 → 发送
   或使用Diffie-Hellman交换协商预主密钥

5. 双方计算会话密钥
   主密钥 = PRF(预主密钥, 客户端随机数, 服务器随机数)
   会话密钥 = 从主密钥派生（加密密钥、MAC密钥、IV）

6. ChangeCipherSpec + Finished
   双方切换到加密模式，发送加密的Finished消息验证握手完整性
```

### TLS安全服务

| 服务 | 机制 |
|------|------|
| 机密性 | 对称加密（AES-GCM/ChaCha20） |
| 完整性 | HMAC/AEAD（加密+认证一体） |
| 认证 | 服务器证书（CA签名） + 可选客户端证书 |
| 前向安全 | 临时Diffie-Hellman（DHE/ECDHE） |

<Callout type="warning" title="前向安全（Forward Secrecy）为什么重要">

如果攻击者录制了所有加密流量，日后获取了服务器私钥，可以解密所有历史流量——除非使用了前向安全。前向安全使用 **临时Diffie-Hellman密钥交换（DHE/ECDHE）**：每次连接生成临时DH密钥对，会话密钥通过DH交换派生，连接结束后临时密钥销毁。即使日后私钥泄露，也无法恢复临时DH密钥，历史流量仍然安全。TLS 1.3强制要求前向安全。

</Callout>

## IPsec

IPsec是网络层安全协议，为IP数据报提供加密和认证，常用于 **VPN**（虚拟专用网）。

### IPsec两种模式

```text
传输模式（主机到主机）：
  [新IP头|ESP头|原始IP载荷（加密）|ESP尾|认证]
  保护IP载荷，IP头不变

隧道模式（网络到网络，VPN）：
  [新IP头|ESP头|原始IP头+原始IP载荷（加密）|ESP尾|认证]
  保护整个原始IP包，添加新IP头

  VPN网关A ──── 隧道（加密） ──── VPN网关B
  内网A                               内网B
  10.0.0.x                            172.16.0.x
```

### IPsec核心协议

| 协议 | 功能 |
|------|------|
| AH（认证头） | 完整性+认证（不加密） |
| ESP（封装安全载荷） | 加密+完整性+认证 |
| IKE（密钥交换） | 协商安全关联(SA)、交换密钥 |

## 防火墙与IDS

### 防火墙

防火墙隔离信任网络与不信任网络，根据 **规则** 允许或拒绝流量。

```text
防火墙类型：

无状态包过滤（传统）：
  检查每个IP包的头部：源/目的IP、端口、协议
  规则表逐条匹配 → 允许/拒绝
  简单快速但不理解连接状态

状态检测（现代）：
  维护连接状态表
  允许已建立连接的返回流量
  拒绝未经请求的入站连接

应用层网关（WAF/ALG）：
  检查应用层内容（HTTP请求、SQL注入等）
  深度包检测（DPI）
```

```text
防火墙规则示例（ACL）：
  规则   源IP          目的IP        端口   动作
  1     10.0.0.0/24   0.0.0.0/0     443   允许  ← 内网访问HTTPS
  2     10.0.0.0/24   0.0.0.0/0     80    允许  ← 内网访问HTTP
  3     0.0.0.0/0     10.0.0.10     80    允许  ← 外部访问Web服务器
  4     0.0.0.0/0     10.0.0.0/24   *     拒绝  ← 拒绝其他入站
  5     *             *             *     拒绝  ← 默认拒绝
```

### 入侵检测系统（IDS）

```text
IDS vs IPS：
  IDS（入侵检测）：旁路部署，检测攻击 → 告警
  IPS（入侵防御）：串联部署，检测攻击 → 阻断

检测方法：
  基于签名：匹配已知攻击特征（类似杀毒软件）
    优点：准确率高；缺点：无法检测未知攻击（零日）
  
  基于异常：建立正常行为基线，偏离则告警
    优点：可检测未知攻击；缺点：误报率高
```

<Glossary>

<GlossaryItem term="对称加密与公钥加密">
对称加密：发送方和接收方共享同一密钥，加密解密用同一密钥（如AES）。速度快，适合大量数据加密，但密钥分发困难。公钥加密：密钥对（公钥公开+私钥保密），公钥加密只能私钥解密，私钥签名可用公钥验证（如RSA）。解决了密钥分发问题，支持数字签名，但计算慢。实际中用混合加密：公钥协商对称会话密钥，对称密钥加密大量数据。
</GlossaryItem>

<GlossaryItem term="TLS（传输层安全）">
TLS位于应用层和传输层之间，为TCP连接提供机密性、完整性和认证。握手过程：①ClientHello（密码套件+随机数）②ServerHello+证书（服务器公钥）③客户端验证证书（CA签名链）④密钥交换（RSA或DHE/ECDHE协商预主密钥）⑤双方派生会话密钥⑥切换加密模式。TLS 1.3简化握手为1-RTT并强制前向安全（ECDHE）。HTTPS = HTTP over TLS。
</GlossaryItem>

<GlossaryItem term="IPsec VPN">
IPsec是网络层安全协议，常用于VPN。隧道模式：VPN网关将原始IP包加密后封装在新IP包中传输，保护整个原始IP包（含IP头），适合网络到网络VPN。传输模式只保护IP载荷，IP头不变，适合主机到主机。核心协议：ESP（加密+完整性）、AH（仅完整性）、IKE（密钥交换和安全关联协商）。IPsec在IP层工作，对上层透明——任何TCP/UDP流量都自动加密。
</GlossaryItem>

<GlossaryItem term="防火墙（Firewall）">
防火墙是隔离信任网络与不信任网络的设备，根据规则允许或拒绝流量。类型：①无状态包过滤——逐包检查IP/端口头部，简单但不理解连接状态 ②状态检测——维护连接状态表，允许已建立连接的返回流量 ③应用层网关——检查应用层内容（HTTP/SQL），深度包检测。安全原则是默认拒绝——只允许明确放行的流量，其余全部拒绝。现代防火墙通常集成IDS/IPS功能。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 对称加密和公钥加密各自的特点是什么？实际安全协议为什么使用混合加密？

<Answer>

对称加密特点：发送方和接收方共享同一密钥，加密解密用同一密钥（如AES）。速度快（适合大量数据），但密钥分发困难——双方需预先安全共享密钥。公钥加密特点：密钥对（公钥公开+私钥保密），公钥加密只能私钥解密，私钥签名可用公钥验证（如RSA）。解决密钥分发问题，支持数字签名，但计算速度慢（比对称慢100-1000倍）。实际安全协议使用混合加密的原因：公钥加密太慢不适合大量数据，对称加密密钥分发困难。混合加密先用公钥加密（或Diffie-Hellman交换）协商一个对称会话密钥（128-256位），然后用对称密钥加密大量数据。兼顾了公钥的密钥分发安全性和对称加密的高效性。
</Answer>

**问题 2：** TLS握手的主要步骤是什么？前向安全为什么重要？

<Answer>

TLS握手主要步骤（TLS 1.2）：①ClientHello——客户端发送支持的密码套件列表和客户端随机数 ②ServerHello+证书——服务器选定密码套件，返回服务器随机数和证书（含服务器公钥） ③客户端验证证书——检查CA签名链、域名匹配、有效期、吊销状态 ④密钥交换——客户端生成预主密钥用服务器公钥加密发送，或用Diffie-Hellman交换协商预主密钥 ⑤双方用预主密钥+两个随机数派生会话密钥 ⑥ChangeCipherSpec+Finished——切换加密模式，发送加密的Finished消息验证握手完整性。前向安全重要的原因：如果攻击者录制了所有加密流量，日后获取服务器私钥可解密所有历史流量。前向安全使用临时Diffie-Hellman（DHE/ECDHE），每次连接生成临时DH密钥对，会话密钥通过DH交换派生，连接结束后临时密钥销毁。即使私钥日后泄露也无法恢复临时密钥，历史流量仍安全。TLS 1.3强制前向安全。
</Answer>

</Exercises>
