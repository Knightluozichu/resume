## 算法层级：一个数量级胜过百倍微调

性能优化里有一个朴素的优先级：先把算法层级选对，再谈常量优化。原因看数字就明白。

<ChpAlgorithmComplexityDiagram />

n=10000 时，O(n log n) 约 1.3×10⁵ 次操作，O(n²) 是 10⁸ 次，差 770 倍。若每次操作 1ns，前者 0.13ms，后者 100ms。把冒泡（O(n²)）换成快排/归并（O(n log n)）能拿几百倍提升；而缓存对齐、循环展开这类常量优化通常只有 10–30%。量纲不同。

更重要的是可扩展性：算法层级决定增长曲线斜率。O(n²) 的代码 n 翻倍慢四倍，迟早撑不住；O(n log n) n 翻倍只慢两倍多。常量优化只是把「撑不住」的临界点往后挪一点，n 涨上去照样崩。所以优化的第一动作永远是确认算法层级对不对，而不是纠结常数。

## 摊还复杂度：允许偶尔慢，只要平均快

<Term def="对一系列操作求平均后的每操作复杂度，允许个别操作较慢，只要整体平均代价低">摊还复杂度</Term>（amortized complexity）解释了一个反直觉的现象：`std::vector::push_back` 是「均摊 O(1)」而非严格 O(1)。

vector 容量不够时会扩容（通常翻倍），把旧元素拷贝到新内存，这次扩容是 O(n)。但扩容后能再容纳 n 次 push_back 才需再次扩容。把一次 O(n) 扩容摊到 n 次插入上，每次均摊 O(1)。几何级数证明：n 次插入的总拷贝次数 1+2+4+…+n < 2n，总成本 O(n)。

但均摊 O(1) 不等于每次都快。单次扩容时会有一次 O(n) 抖动，对延迟敏感的实时系统需用 `reserve()` 预分配消除扩容，或用 `std::deque`（分段连续、扩容不拷贝）。

## 换算法 vs 常量优化：何时该做哪个

「换算法」通常比「在原算法上做常量优化」收益更大，但并非总是如此。

换算法收益大的原因：算法层级决定增长曲线，O(n²) 与 O(n log n) 在大 n 下差几百上千倍；常量优化封顶在几倍到十几倍。而且换算法往往换了思路（暴力→分治、递归→迭代加备忘录），从源头消除冗余工作；常量优化是在冗余工作上榨硬件，冗余仍在。

但常量优化反而更重要的情况：

- 算法已是该问题的最优层级（排序已达 O(n log n) 理论下界），唯一提升空间在常量（缓存、SIMD、分支消除）。
- n 固定且小（几十到几百），O(n²) 可能比 O(n log n) 还快——常数小、缓存好。STL 的 introsort 末段就是插入排序，正因小数组上插入排序跑赢快排。
- 热点已极致，算法无法再换，常量优化（对齐、预取、SIMD）是唯一出路。
- 实时约束下要消除尾部抖动（如扩容抖动）。

<Callout type="tip">
先确保算法层级正确（拿数量级），再在剖析定位的热点上做常量优化（拿倍数）。两者是优化的两个阶段，不是对立选项。脱离算法谈常量是雕花，脱离常量谈算法是空谈。
</Callout>

## 选择算法的决策框架

遇到一段热点，先问几个问题：数据是否有序？查找频率 vs 变更频率？key 分布？元素大小？是否需范围查询？n 的量级？

- 有序数据查找 → 二分（O(log n)），连续数组缓存好。
- 频繁查不变更 → 哈希（均摊 O(1)）或排序 vector。
- 小 n → 线性扫描，缓存红利碾压树/哈希常数。
- 重复查询多 → memoization 缓存结果。

每个候选都用 benchmark 在真实数据上验证，别只看大 O。

<Callout type="trap">
不要在小数组上执着于「更优复杂度」。n=16 时，插入排序的 O(n²) 因常数小、缓存好，常跑赢快排的 O(n log n)。STL 排序末段切到插入排序正是这个原因。最优算法随 n 变化，没有「全量程最优」。
</Callout>

## 小结

- 算法层级决定数量级，换算法（O(n²)→O(n log n)）收益远超常量优化
- 摊还复杂度允许偶尔慢只要平均快，`push_back` 均摊 O(1) 但有扩容抖动
- 算法到顶、n 小、热点极致时，常量优化（缓存/SIMD）反而更重要
- 选算法看 n、有序性、访问比例，每个候选都 benchmark 验证

<Glossary>
<GlossaryItem term="摊还复杂度">
对一系列操作求平均后的每操作复杂度，允许个别操作较慢（如 vector 扩容 O(n)），只要整体平均代价低（n 次插入总成本 O(n)，均摊 O(1)）。
</GlossaryItem>
<GlossaryItem term="大 O 表示法">
算法耗时随 n 增长的渐近上界，忽略常数与低阶项。它定方向但不反映真实耗时，需结合缓存与常量看。
</GlossaryItem>
<GlossaryItem term="introsort">
STL `std::sort` 用的混合排序：快排为主，递归深度超阈值切堆排（保 O(n log n) 最坏），末段小数组切插入排序（利用小 n 上 O(n²) 常数小的优势）。
</GlossaryItem>
<GlossaryItem term="memoization">
缓存重复子问题的计算结果，把指数级递归压成多项式。是动态规划的核心，适合重复查询多的场景。
</GlossaryItem>
</Glossary>
