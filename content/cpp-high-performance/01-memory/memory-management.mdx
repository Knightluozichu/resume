## 内存布局：栈几乎免费，堆很贵

要榨取 C++ 的性能，得先看清数据住在哪里。进程的虚拟地址空间分为五段：text（只读代码）、data（已初始化全局）、bss（零初始化全局）、heap（堆）、stack（栈）。其中跟性能关系最大的是栈和堆。

<ChpMemoryLayoutDiagram />

栈分配几乎免费：它只是移动栈指针（`sub rsp`），一条指令搞定，而且内存连续、缓存友好，函数返回时自动回收。堆分配却很贵：要走分配器查找空闲块、维护元数据，可能触发系统调用（`brk`/`mmap`），开销在几十到几百纳秒；分配出的内存散落在堆各处，缓存差；还容易产生碎片。

这条差异意味着一个朴素的原则：**能上栈不上堆，能复用不新分配**。把临时对象用返回值优化（RVO）放栈上，把循环内的 `new` 提到循环外复用，用 `std::string_view`/`std::span` 避免容器拷贝——这些都能省下可观的分配开销。

## 内存对齐：让一次访问只花一条指令

<Term def="数据地址是其大小的整数倍，使 CPU 能用一条指令完成访问而不跨缓存行或页边界">内存对齐</Term> 是常被忽略的提速点。CPU 访问对齐数据通常一条指令完成；未对齐的访问可能跨缓存行甚至跨页，要多次访问甚至触发异常。某些架构（ARM、旧 x86 SIMD）直接拒绝未对齐访问，硬件异常代价极高。

`alignas` 让你显式指定对齐。三个典型场景：SIMD 数据 `alignas(32)` 让 AVX 用对齐加载指令更快；多线程写的变量 `alignas(64)` 隔到不同缓存行，避免 false sharing；自定义对象池按缓存行对齐，减少跨行访问。原则是热点数据按自然对齐或缓存行对齐，能省下可观的访存开销。

<Callout type="tip">
优先把临时对象挪到栈上、把循环内的分配提到循环外复用。这两步成本最低、收益最稳，是内存优化的第一步。只有生命周期改不动时，再考虑换分配器或改布局。
</Callout>

## 内存池：把多次小分配合并成一次大分配

当热点确实在「大量同尺寸小对象的频繁分配/释放」时，<Term def="预分配一大块内存并按固定大小切出块供申请归还，把多次小分配合并为指针挪动的技术">内存池</Term> 能把每次几十纳秒的 `malloc` 降到几纳秒。

内存池的优势在于：分配退化为指针递增、时间是常数可预测、对象连续缓存友好、无碎片。它特别适合游戏里的粒子、解析器的节点、网络包缓冲这类「同尺寸、高频」的对象。

但内存池不是银弹。对象大小差异大时固定块池会浪费空间；分配释放稀疏时预占大块利用率低；多线程下要自己管空闲链表加锁或 thread-local，复杂度上来后未必比智能指针加通用分配器好；而且手动管理易出 use-after-free、double-free。判断标准：先测量确认「小对象频繁分配」是热点，再上池，别为池而池。

<Callout type="trap">
不要在还没测量时就上内存池。池要手动管理、易出内存安全 bug，维护成本高。只有剖析证实「小对象频繁分配」是热点，且通用分配器（或 `jemalloc`/`tcmalloc`）已不够用，才值得自定义池。
</Callout>

## 三层递进的优化思路

把一个高频创建/销毁临时对象的热点函数系统优化，可以按三层递进：

1. **改生命周期**（最易）：栈上对象、复用、`string_view`/`span`、延迟构造。
2. **换分配器**（生命周期改不动时）：`std::pmr::monotonic_buffer_resource`、对象池、`jemalloc`。
3. **改数据布局**（重构成本最高）：把「创建销毁」改成「标记有效位」（ECS 思路）、SoA 替代 AoS、值语义加连续存储。

每层都用 benchmark 验证收益再进下一层，避免过度设计。

## 小结

- 栈分配移动指针几乎免费、缓存友好；堆分配走分配器、易碎片、缓存差——能上栈不上堆
- 内存对齐让一次访问一条指令完成，热点数据按缓存行对齐用 `alignas`
- 内存池把多次小分配合并成一次大分配，仅适合「同尺寸高频」热点，别滥用
- 优化按生命周期 → 分配器 → 数据布局三层递进，每步测量验证

<Glossary>
<GlossaryItem term="内存对齐">
数据地址是其大小的整数倍，使 CPU 能用一条指令完成访问而不跨缓存行或页边界。未对齐访问会跨行、跨页甚至触发异常，变慢。
</GlossaryItem>
<GlossaryItem term="内存池">
预分配一大块内存并按固定大小切出块供申请归还，把多次小分配合并为指针挪动。适合同尺寸高频对象，分配 O(1) 且无碎片，但需手动管理、易出内存安全 bug。
</GlossaryItem>
<GlossaryItem term="栈分配">
通过移动栈指针为局部变量分配内存，一条指令完成、连续缓存友好、函数返回自动回收。比堆分配快一到两个数量级。
</GlossaryItem>
<GlossaryItem term="返回值优化（RVO）">
编译器消除函数返回临时对象的拷贝，直接在调用者的栈帧构造，使按值返回大对象几乎免费，避免堆分配。
</GlossaryItem>
</Glossary>

  <Answer question="栈分配和堆分配在性能上的根本差异是什么？为什么能上栈不上堆？">栈分配只需移动栈指针（一条指令），内存连续缓存友好，函数返回自动回收；堆分配要走分配器查找空闲块、维护元数据、可能触发系统调用，开销几十到几百纳秒，内存散落缓存差还易碎片。栈比堆快一到两个数量级，所以能上栈不上堆——用 RVO 按值返回、循环外复用、`string_view`/`span` 避免拷贝都能省下堆分配。</Answer>
  <Answer question="内存池在什么场景下有优势？什么场景下反而更差？">优势场景：大量同尺寸小对象的频繁分配/释放（如粒子、节点、网络包），分配退化为指针挪动、常数时间无碎片、连续缓存友好。反而更差的场景：对象大小差异大（固定块浪费）、分配释放稀疏（预占大块利用率低）、多线程（要加锁或 thread-local）、生命周期复杂（易 use-after-free）。判断：先测量确认热点是「同尺寸高频小分配」再上池。</Answer>
</Exercises>
