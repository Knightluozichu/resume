## 为什么学习地图必须服从官方 18 章

《C++ Primer Plus》第六版官方目录从 Chapter 1 Getting Started with C++ 推进到 Chapter 18 Visiting with the New C++ Standard。它不是“基础、OOP、STL”三个宽泛标签：数据类型、复合类型、循环、分支、函数基础、函数增强、内存模型、运算符、动态成员、继承、代码复用、异常、标准库、文件和 C++11 都有独立责任。

<Term def="由 InformIT/Pearson 第六版目录确认，并作为正文、题库、学习地图和总复习共同基线的 18 章顺序。">官方章序</Term>

旧地图只映射 8 个合并主题，会让读者从控制语句直接跳到类，漏掉分离编译、复制控制、异常与 I/O 等关键契约。新地图以 18 个精确 slug 为主键，章节内容和 36 道官方章节题逐一对应。


## 第一阶段：Chapter 1–6 证明程序、值与路径

Chapter 1 建立编辑、编译、链接、运行的工具链；Chapter 2 解剖 `main`、C++ statements、cout/cin、variables and functions；Chapter 3 处理 integer/floating point、const、arithmetic operators 与 conversions；Chapter 4 扩展到 array/string/struct/pointer/free store；Chapter 5–6 再证明循环、关系表达式、分支、逻辑和文件输入路径。

<Term def="从当前源代码开始，经干净构建、固定输入、运行与预期对照，能够排除旧产物并定位失败阶段的过程。">程序证据循环</Term>

这一段的最小作品是一份输入统计程序：保存完整命令、编译警告、输入类别表和实际输出。不能只保留一张成功截图；还要故意输入文本、边界值、空文件和缺失文件，区分格式失败、EOF 与打开失败。

```bash
c++ -std=c++17 -Wall -Wextra -Wconversion main.cpp -o app
printf '0\n59\n60\n100\n' | ./app
```

```cpp
int value{};
while (std::cin >> value) {
    classify(value);
}
if (!std::cin.eof()) reportInvalidInput();
```

<Callout type="trap" title="陷阱：有 C 基础就可以跳过 Chapter 1–6">
  C++ 的 iostream 状态、reference 初步、列表窄化、string/vector、range-for 和 free-store owner 都会影响后续类与 STL。可以加速熟悉语法，但必须通过边界与失败实验，而不是按语言相似度跳章。
</Callout>

## 第二阶段：Chapter 7–9 从函数进入程序模块

Chapter 7 以 prototype、按值传递、数组/字符串/结构体参数、递归和函数 pointer 建立函数契约；Chapter 8 加入 inline、reference、default argument、overload 与 function template；Chapter 9 再把声明/定义、翻译单元、storage duration、scope/linkage 和 namespace 串成多文件程序。

<Term def="由头文件声明、源文件定义、翻译单元、目标文件和最终链接输入组成，可定位符号生产者与消费者的结构。">模块构建链</Term>

```text
counter.hpp declaration
   -> main.cpp / counter.cpp translation units
   -> main.o / counter.o
   -> linker resolves next_count
```

阶段作品应包含至少两个 `.cpp` 和一个 `.hpp`，并分别复现 missing definition、multiple definition 与 namespace ambiguity。能说出“编译失败还是链接失败、哪个目标文件缺/多了哪个 symbol”，才算通过。

## 第三阶段：Chapter 10–15 建立有效对象与复用边界

Chapter 10 从 abstraction/classes、public/private、constructor/destructor 与 ADT 建立对象不变量；Chapter 11 设计 operator、friend 与 conversion；Chapter 12 处理 dynamic member、copy constructor、assignment 与 Queue；Chapter 13–14 分别证明 public is-a、多态和 containment/template/MI；Chapter 15 再覆盖 friend member、nested class、exception、RTTI 与 cast。

<Term def="对象从构造成功、复制或移动、每次公有操作、异常传播到析构结束都保持 owner 与不变量一致的证据。">对象生命周期证据</Term>

```cpp
class Record {
public:
    Record(std::string name, int score);
    virtual ~Record() = default;
    virtual std::string label() const = 0;
private:
    std::string name_;
    int score_;
};
```

阶段项目可实现一个有容量的记录 Queue：对象构造拒绝非法字段；队列明确 owner 和 copy/move policy；基类引用保留动态分派；异常展开不泄漏节点；需要向下转换时先质疑基类 virtual protocol 是否缺少能力。


<Callout type="trap" title="陷阱：学会 class 语法就能直接进入 STL">
  STL 的值语义依赖构造、复制、赋值、移动和析构；异质 owner 依赖虚析构；算法 callable 还依赖 reference 与 lifetime。先通过浅复制、切片、自赋值和异常展开实验，再进入容器。
</Callout>

## 第四阶段：Chapter 16–18 把库、文件和新标准闭合

Chapter 16 以 string、smart pointer、container、iterator、algorithm、functor 和 valarray 建立泛型范围；Chapter 17 用 stream state、file mode、binary/random access 和 stringstream 把值送入外部世界；Chapter 18 以 brace/auto/scoped enum、move、lambda、wrapper 和 variadic template 收束 C++11。

<Term def="由容器范围、迭代器能力、算法前置条件和 callable 语义共同组成的泛型处理边界。">范围算法契约</Term>

```cpp
std::vector<std::unique_ptr<Record>> records;
std::sort(records.begin(), records.end(),
          [](const auto& a, const auto& b) {
              return a->label() < b->label();
          });
```

最终作品要把对象保存到临时文件、关闭后重新打开、解析为新对象并逐字段比较。文本/二进制格式、覆盖/追加模式、EOF/format failure、move 后状态和 lambda capture lifetime 都要有独立测试。

## 四个阶段以可复查闸门放行


先预测每个阶段的通过证据，再切换面板比较未通过信号。阅读完章节只是输入；可运行作品、边界表、失败现象和根因解释才是学习产出。

<Term def="进入下一阶段前必须完成的作品、边界用例、故障注入和解释标准。">阶段闸门</Term>

## 小结

- 第六版官方结构是 18 章，不是旧地图的 8 个主题页
- Ch 1–6 证明工具链、值、数据形状和路径；Ch 7–9 建立函数与模块构建链
- Ch 10–15 维护对象不变量、复制/继承/复用/异常边界
- Ch 16–18 组合 STL 范围、文件状态和 C++11 所有权/callable
- 每阶段以作品、边界、故障和解释放行，不以阅读页数或单次成功输出放行

<Exercises>
  1. **问题 1：还原路线。** 将 18 章分成四个阶段，并为每段写一个可验收作品。

  <Answer question="官方 18 章如何形成四阶段能力链？">Ch1–6 是程序/值/路径，作品是可干净构建的输入分类器；Ch7–9 是函数/模块，作品是可复现符号故障的多文件程序；Ch10–15 是对象/复用，作品是通过复制、多态和异常测试的 owner 类型；Ch16–18 是库/系统，作品是 STL 管线与文件往返。</Answer>

  2. **问题 2：选择回补章节。** 程序能编译但 undefined reference，应回哪一阶段、收集什么？

  <Answer question="链接失败如何沿地图定位？">回 Chapter 9 所在模块阶段。收集声明和定义的完整签名/namespace、每个 .cpp 的编译命令与 .o、最终链接输入和符号表；确认 producer 定义唯一且 consumer 的目标文件/库确实参与链接。</Answer>

  3. **问题 3：设计最终项目。** 一个多态记录文件往返会复用哪些章节证据？

  <Answer question="端到端项目怎样串联四阶段？">Ch1–6 提供构建、类型、分支和循环；Ch7–9 提供函数/模块边界；Ch10–15 提供不变量、复制、virtual owner、异常；Ch16–18 提供 container/algorithm、stream state、文件 schema、smart pointer/move/lambda。每层都要有失败用例。</Answer>
</Exercises>
