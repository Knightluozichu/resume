## 分支与循环

控制语句决定程序的执行路径，分两类：分支做选择，循环做重复。这两类语句组合起来，就能表达任意复杂的程序逻辑。

<EppControlStatementsDiagram />

**分支结构**根据条件选择执行路径。`if/else` 用布尔条件二选一，可链式 `else if` 表达多路分支。`switch` 用整型或枚举值多路匹配，适合「一个值对应多种情况」的场景。switch 的 case 是标签而非块，匹配后一直往下执行直到 `break`——这叫穿透（fall-through），漏写 break 是经典 bug。

**循环结构**重复执行一段代码直到条件不满足。`for` 适合已知次数的计数循环。`while` 先判断后执行，条件不满足时一次都不跑。`do-while` 先执行后判断，至少跑一次。`range-for`（C++11）是遍历容器的语法糖，简洁安全。

## range-for 的安全优势

<Term def="C++11 引入的范围循环，用迭代器遍历容器元素，比手写下标循环更简洁安全">range-for</Term>

range-for 与传统下标循环相比有三大优势：简洁（不用写下标边界）、安全（不会越界）、通用（适用于所有提供 `begin()`/`end()` 的容器，包括 `list`/`map` 等无下标访问的容器）。

遍历只读元素用 `for (const auto& x : vec)` 避免拷贝，要修改元素用 `for (auto& x : vec)`。关键约束：range-for 内部持迭代器，遍历中不能增删容器元素（会使迭代器失效），需要边遍历边删要用迭代器循环配合 `erase` 返回值。

## switch 的穿透陷阱

switch 的 case 穿透机制是把双刃剑。匹配到某个 case 后，若没遇 break 会继续执行后续 case 的代码。这有时是有意的（多个 case 共享同一段代码），但绝大多数情况每个 case 末尾都要 break。漏写 break 会导致匹配 case A 却执行了 case B、case C 的代码，行为错误且难排查。

C++17 的 `[[fallthrough]]` 属性可显式标注「故意穿透」以消除编译器警告，让意图可见。

## 常见误区

<Callout type="trap"><strong>现象 →</strong> switch 明明 case 值匹配了，却执行了下一个 case 的代码。<strong>原因 →</strong> 漏写 break，case 穿透（fall-through）导致匹配后继续往下执行。<strong>修法 →</strong> 每个 case 末尾补 break；若故意穿透加 `[[fallthrough]]` 标注意图；开启 `-Wimplicit-fallthrough` 编译警告提前发现。</Callout>

## 小结与练习

C++ 控制语句分两类：分支（`if`/`else`、`switch`）根据条件选择路径，循环（`for`、`while`、`range-for`）重复执行代码块。switch 需用 break 防止 case 穿透，range-for 是遍历容器的安全语法糖，比手写下标循环更不易越界。
