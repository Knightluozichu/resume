## 类的解剖

类是 C++ 面向对象编程的核心，它把数据与行为封装在一起，用访问控制保护内部状态。一个类的完整生命周期由构造函数初始化、成员函数操作、this 指针指代自身、友元开后门协作。

<EppClassesObjectsDiagram />

**访问控制**分三级：`public` 放成员函数构成对象接口，外部可访问；`private` 放数据成员藏起来防篡改，只有类自己和友元能访问；`protected` 让派生类可访问基类的实现细节，用于继承体系。封装的本质就是用 private 藏数据、public 暴接口，保证对象状态只能通过受控接口改变。

**构造函数**与类同名、无返回类型，在对象诞生时自动调用，把对象从「未初始化内存」变成「可用状态」。可重载（默认构造、带参构造、拷贝构造）。初始化列表 `Stock(int n) : shares(n) {}` 比函数体赋值更高效——直接初始化而非先默认构造再赋值，且对 const 成员、引用成员、无默认构造的成员是必须的。

**this 指针**指向调用成员函数的那个对象自身。编译器把 `obj.f()` 改写成 `f(&obj)`，this 就是 `&obj`。this 用于区分同名参数与成员、返回 `*this` 支持链式调用。const 成员函数里 this 是 `const T*`，不能修改对象。

**友元** `friend` 授权外部函数或类访问私有成员。常用于运算符重载（如 `operator<<` 需访问私有数据输出）、紧密协作的类、需要访问私有构造的工厂。

## 封装与初始化

<Term def="用 private 藏数据、public 暴接口，保证对象状态只能通过受控接口改变的机制">封装</Term>

封装的价值在于保护不变量。若数据成员公开，外部可任意篡改，无法保证「shares 永远非负」这类约束；把数据藏进 private，只通过 public 的 `buy()`/`sell()` 接口操作，接口内部检查不变量，状态就始终合法。

初始化列表是构造函数的最佳实践。它直接用参数构造成员，少一次默认构造+赋值，对类类型成员效率更高。且 const 成员、引用成员、无默认构造的成员只能用初始化列表——这三者在函数体里赋值是非法的。养成「能用初始化列表就用」的习惯。

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 在类里写 `void setX(int x) { x = x; }` 想给成员 x 赋值，但对象状态没变。<strong>原因 →</strong> 参数名 x 遮蔽了成员 x，`x = x` 是参数自赋值，没碰成员。<strong>修法 →</strong> 用 `this->x = x;` 显式指明成员，或改参数名避免遮蔽；构造函数用初始化列表 `Foo(int x) : x(x) {}`；开 `-Wshadow` 警告提前发现。</Callout>

## 小结与练习

C++ 类用 private 藏数据成员、public 暴露成员函数接口，实现封装。构造函数在对象诞生时初始化成员，初始化列表比函数体赋值更高效且对某些成员是必须的。this 指针指向调用对象自身支持链式调用，友元授权外部访问私有成员。三者共同支撑类的完整生命周期。
