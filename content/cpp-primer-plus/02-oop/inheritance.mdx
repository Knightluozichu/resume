## 继承与多态三机制

继承让派生类复用基类的接口与实现，虚函数实现运行期多态，纯虚函数定义抽象类。三者递进构成面向对象的类型扩展能力。

<EppInheritanceDiagram />

**继承**语法 `class Derived : public Base { ... };`，派生类获得基类的成员，并可新增或覆盖。`public` 继承表达「is-a」关系——派生类是一种基类，基类指针可指向派生对象。这是多态的基础。

**虚函数** `virtual void f();` 声明可被派生类覆盖的函数。通过基类指针/引用调用时，实际执行的是「指针所指对象的实际类型」的版本，而非指针声明类型的版本——这是运行期多态，靠 vtable（虚函数表）动态绑定。派生类覆盖虚函数应写 `override` 关键字，让编译器检查确实在覆盖。

**纯虚函数** `virtual void f() = 0;` 只声明接口不提供实现。含纯虚函数的类是抽象类，不可实例化，只能作基类。抽象类定义接口契约，强制派生类必须实现纯虚函数才能实例化。

## 多态与 vtable

<Term def="通过基类指针/引用调用虚函数时，按对象实际类型而非指针声明类型分派的运行期多态机制">动态绑定</Term>

多态的底层是 vtable。每个含虚函数的类有一张虚函数表（每个虚函数一个指针条目），每个该类对象有一个 vptr 指向其所属类的 vtable。调用虚函数时，通过对象的 vptr 找到 vtable，再按偏移找到函数指针跳转。这多一次间接跳转，是多态的运行期开销。

多态的典型用法：`Shape* p = new Circle; p->draw();`。p 声明类型是 Shape*，但实际指向 Circle 对象，`p->draw()` 查 Circle 的 vtable 走 Circle 的 draw 版本。这就是「同一调用按对象类型分派」。

## override 与虚析构

覆盖虚函数必须写 `override`（C++11）。它让编译器检查「这个函数确实覆盖了基类虚函数」，签名不匹配时编译报错。若基类改了签名，派生类写 override 会立刻编译失败，逼你同步更新，避免「该走派生却走了基类」的隐蔽 bug。

基类析构函数通常要声明 `virtual`。若非虚，`Base* p = new Derived; delete p;` 只调 Base 析构，派生资源泄漏且行为未定义。声明虚后，delete 走 vtable 调派生析构（释放派生资源），再自动调基类析构，顺序正确。只要类可能被继承，析构就应虚。

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 基类有 `virtual void f()`，派生类也定义了 `void f()` 但忘写 override，基类把 f 改成 `f(int)` 后代码能编译但多态失效。<strong>原因 →</strong> 没写 override 编译器不检查覆盖，基类改签名后派生类的 f 不再是覆盖而是隐藏，通过基类指针调用走基类版本。<strong>修法 →</strong> 所有覆盖虚函数都加 override，让编译器替你把关；基类改签名后派生类会编译报错，逼你同步更新。</Callout>

## 小结与练习

C++ 继承让派生类复用基类接口，虚函数 virtual 实现运行期多态（基类指针按实际对象类型调用），纯虚函数 `= 0` 定义抽象类不可实例化。多态底层是 vtable 动态绑定。覆盖虚函数必须写 override 防止签名不匹配的隐蔽 bug，基类析构通常要虚以支持正确释放派生资源。
