## 基础语法测试

C++ 面试的第一道关卡不是高深的模板或并发，而是基础语法里那些「能说不能写」的陷阱。本章聚焦三大雷区：**未定义行为**、**const 正确性**、**类型转换**。它们之所以高频，是因为面试官能用一行代码就测出你是「背过概念」还是「真正理解」。

## 核心概念

### 未定义行为（UB）

<Term def="程序的行为没有被 C++ 标准规定，编译器无需诊断、运行时任何结果都「合法」的情况；一旦程序含 UB，整个程序的行为不再可信。">未定义行为（UB）</Term>

UB 最危险的地方在于它不是「报错」，而是「标准放弃描述」。它常常表现为「在你机器上正常，上线崩溃」。最常见的高频 UB 有：

- **有符号整数溢出**：`int` 运算结果超出表示范围是 UB，不是回绕。编译器可基于「程序无 UB」假设有符号数不溢出来做激进优化。
- **读取未初始化变量**：自动存储期的标量初值不确定，读取不确定值是 UB。
- **解引用空指针/悬空指针**：如 `*p` 当 `p` 为 nullptr。
- **数据竞争**：同一标量上无 sequenced-before 关系的冲突读写。
- **修改真正的 const 对象**：用 `const_cast` 去掉 const 后改写原本确实是 const 的对象。

```cpp
// UB：有符号溢出
int big = INT_MAX;
int next = big + 1;   // 不是 INT_MIN，而是 UB

// UB：未初始化读取
int* p;
if (p) { *p = 1; }    // 读 p 本身已 UB，比较结果不可信

// UB：修改真正的 const
const char* s = "abc";
const_cast<char*>(s)[0] = 'A';  // 字面量在只读区，写入是 UB
```

### const 正确性

const 正确性指在类型系统中一致地用 `const` 标注「不应被修改」的对象、参数、成员函数，让编译器在编译期拦截误修改。核心原则：**如果一个东西逻辑上不该变，就给它加 const**，把错误从运行时提前到编译时。

const 成员函数不能修改对象状态：在 const 成员函数内，`this` 的类型是 `const T*`，所有非 mutable 成员都变成 const。const 还参与重载——成员函数可按 const 与非 const 重载，常量对象只能调 const 版本，非常量对象优先调非 const 版本。典型用法是 `operator[]` 提供两个版本。

```cpp
class Vec {
  int* data_;
public:
  int& operator[](size_t i) { return data_[i]; }              // 非 const：可写
  const int& operator[](size_t i) const { return data_[i]; }  // const：只读
};
```

`mutable` 是 const 正确性的「逃生口」：const 成员函数仍可修改 `mutable` 成员（如缓存、互斥量）。但滥用会破坏契约，应只用于**逻辑 const**（对象可观察状态不变）而物理可变的情况。

### 四种类型转换

C++ 提供四种新式类型转换，各有明确用途：

- `static_cast`：用于有明确定义的隐式转换的反向或显式形式，如基本类型间转换、已知安全的向下转型。编译期检查，不做多态运行时检查。
- `const_cast`：只用于增删 const/volatile，不改变底层类型。唯一能「去掉 const」的转换，但去掉后改写原本真正是 const 的对象是 UB。
- `reinterpret_cast`：在位层面重新解释，如不相关指针类型互转。最危险，依赖实现。
- `dynamic_cast`：用于多态类型（含虚函数）的运行时向下转型，失败返回空指针或抛 `std::bad_cast`，依赖 RTTI。

<Term def="成员函数可按 const 与非 const 重载，编译器据调用对象的 const 性选择版本；常量对象只能调 const 版本。">const 重载</Term>

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 用 `const_cast` 去掉 const 后修改字符串字面量，本地能跑上线崩。 <strong>原因 →</strong> 字符串字面量存放在只读存储区，类型本是 `const char[]`。`const_cast` 只能用于「原本非 const 但被 API 错误标了 const」的情况；对真正 const 的对象去 const 是 UB，可能段错误也可能不报错。 <strong>修法 →</strong> 要可改字符串就别用字面量，用可写缓冲 `char buf[] = "abc";`，`buf` 是副本可自由修改。</Callout>

<Callout type="trap"><strong>现象 →</strong> 以为 `const` 成员函数一定线程安全，多线程调它却出现数据竞争。 <strong>原因 →</strong> const 只保证「不修改对象可观察状态」，不保证并发安全。若 const 成员函数内部读写 `mutable` 成员（如缓存）而无锁，多线程并发就是数据竞争。 <strong>修法 →</strong> 线程安全需显式加锁或用原子操作；const 是「逻辑不变」契约，不是「并发安全」契约。</Callout>

<Callout type="trap"><strong>现象 →</strong> 混用 `new[]` 与 `delete`（如 `delete` 配 `new[]`），偶尔崩溃偶尔泄漏。 <strong>原因 →</strong> `new T[n]` 分配数组并逐个构造，`delete[]` 逐个析构再释放；混用只析构首元素甚至解析错数组长度，是 UB。 <strong>修法 →</strong> 单个用 `new`/`delete`，数组用 `new[]`/`delete[]`，配对必须一致；现代 C++ 直接用 `vector` 或 `unique_ptr<T[]>` 避免手写数组管理。</Callout>
