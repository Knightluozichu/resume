## 模板测试

模板是 C++ 最强大的特性之一，也是面试中最能拉开档次的考点。一道「写个通用的 max 函数」或「解释这段 SFINAE」就能区分出你是「用过模板」还是「理解模板」。本章聚焦四个核心：**模板实例化**、**类型推导**、**SFINAE**、**模板元编程**。

## 核心概念

### 函数模板、类模板与实例化

- **函数模板**：用一个模板参数生成一族函数，如 `template<typename T> T add(T a, T b)`。调用可显式指定 `add<int>(1,2)` 或由实参推导 `add(1,2)`。函数模板支持重载。
- **类模板**：用模板参数生成一族类，如 `template<typename T> class Stack`。使用须指定参数 `Stack<int>`（C++17 起类模板参数可由构造函数推导）。
- **模板实例化**：编译器根据实际使用的模板参数把模板「具现」出具体代码。隐式实例化（用到时自动生成）或显式实例化（`template class Stack<int>;`）。模板是编译期机制，零运行时开销，但以编译时间与代码体积（模板膨胀）为代价。

### 类型推导三情形

模板类型推导针对 `template<typename T> void f(ParamType x)`，根据 ParamType 的形式分三种情形：

1. **ParamType 是普通引用（T&）**：实参是引用先剥离引用性，const 性由 ParamType 决定。传 `int&` 时 T 推导为 `int`。
2. **ParamType 是万能引用（T&&）**：左值实参推导 T 为左值引用，右值实参推导 T 为非引用。传 `int&` 时 T 推导为 `int&`（引用折叠）。
3. **ParamType 按值（T）**：实参的引用性和顶层 const/volatile 都被忽略。传 `const int&` 时 T 推导为 `int`。

关键区别：普通引用形参不保留实参的左右值性，万能引用形参保留——这是 **perfect forwarding** 的基础。万能引用靠引用折叠实现：`int& &&` 折叠成 `int&`。

<Term def="T&& 中 T 是模板参数时为万能引用，左值实参推导 T 为引用、右值为非引用，经引用折叠实现完美转发。">万能引用</Term>

### SFINAE 与 concepts

<Term def="Substitution Failure Is Not An Error，模板参数推导时若某候选替换失败，不报错而是把它从重载集剔除，从而按条件启用/禁用模板。">SFINAE</Term>

SFINAE 让我们「按条件启用/禁用模板」。用 `enable_if` 实现仅整数类型启用：

```cpp
template<typename T,
         typename = std::enable_if_t<std::is_integral_v<T>>>
void only_int(T x) { /* 整数版 */ }
```

T 是整数时模板有效；非整数时替换失败被剔除。SFINAE 的痛点：错误信息晦涩、写法绕、组合条件繁琐。C++20 的 concepts 简化了它：

```cpp
template<typename T>
  requires std::integral<T>
void only_int(T x) { /* 整数版 */ }
// 或：void only_int(std::integral auto x)
```

concept 直接表达约束，错误信息友好，组合用 `&&`/`||`。**新代码应优先 concept**。

### 模板元编程（TMP）

模板元编程利用模板的实例化机制在编译期执行计算，把模板当成「编译期函数」——参数是输入，特化/递归是计算，内嵌常量是输出。编译期阶乘：

```cpp
template<unsigned N>
struct Factorial {
  static constexpr unsigned value = N * Factorial<N - 1>::value;  // 递归
};
template<>
struct Factorial<0> {
  static constexpr unsigned value = 1;  // 终止特化
};
// Factorial<5>::value == 120，编译期算出
```

TMP 把类型当数据、特化当分支，在类型层面计算。现代替代方案：`constexpr`/`consteval` 函数用普通写法做编译期计算，`if constexpr` 做编译期分支，concepts 替代基于 SFINAE 的类型计算。**新代码应优先现代方案**，TMP 仅作为理解标准库实现与旧代码的背景知识。

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 以为 `T&&` 就是「右值引用」，对左值调用模板却编译通过。 <strong>原因 →</strong> 当 T 是模板参数时，`T&&` 是万能引用而非纯右值引用，左值实参经引用折叠推导 T 为左值引用。 <strong>修法 →</strong> 区分：`T&&`（T 是模板参数）是万能引用可接左右值；`int&&`（具体类型）才是纯右值引用只接右值。</Callout>

<Callout type="trap"><strong>现象 →</strong> 用 SFINAE 约束模板，调用错误类型时报出一大堆模板展开信息，无法定位。 <strong>原因 →</strong> SFINAE 替换失败被静默剔除，最终错误是「无匹配函数」加一堆候选展开，信息晦涩。 <strong>修法 →</strong> 改用 C++20 concepts，错误直接说「T 不满足 integral 约束」，可读性远胜 SFINAE。</Callout>

<Callout type="trap"><strong>现象 →</strong> 用 TMP 写编译期计算，编译极慢且代码难读。 <strong>原因 →</strong> TMP 用模板递归实例化做计算，每一层都生成代码，编译时间与代码体积膨胀。 <strong>修法 →</strong> 改用 constexpr/consteval 函数，用普通循环/递归写编译期计算，可读且编译更快。</Callout>

<GlossaryItem term="模板实例化">编译器根据使用的模板参数把模板具现出具体代码的过程，分隐式（自动）与显式（强制）。</GlossaryItem>
<GlossaryItem term="万能引用">T&& 中 T 为模板参数时的引用，左值推导 T 为引用、右值为非引用，经引用折叠实现完美转发。</GlossaryItem>
<GlossaryItem term="SFINAE">替换失败不是错误，某候选模板替换失败时静默剔除而非报错，用于按条件启用/禁用模板。</GlossaryItem>
