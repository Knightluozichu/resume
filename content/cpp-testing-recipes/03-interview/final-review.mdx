## 总复习

走到这里，你已经走完《C++ 编程测试秘籍》的全部十章。这一章不再讲新知识，而是用一张思维导图把全书收束，把零散的章节串成一张网，并给出一套可执行的面试复习方法论。复习的目标不是「再读一遍」，而是「把知识从能认变成能写、能调、能讲」。

## 全书收束：四大分支

思维导图的中心是「C++ 编程测试秘籍」，四条分支辐射到全书的知识体系：

- **基础测试**（accent 紫）：语法陷阱（UB、const、类型转换）、智能指针、循环引用。这是地基，覆盖面试最常考的语法与内存题。
- **进阶测试**（success 绿）：STL 迭代器失效、SFINAE/concepts、死锁与内存序。这是中坚，覆盖现代 C++ 工程能力核心。
- **面试实战**（warning 暖）：单例工厂、BFS/DFS、ASan 调试。这是冲刺，把前两板块放到面试场景检验。
- **测试方法论**（accent 紫）：陷阱清单法、测试驱动复盘、先测后优。这是贯穿全书的方法主线。

记忆线索：**基础筑底，进阶强骨，面试冲刺，测试方法论贯穿**。

## 贯穿全书的两条主线

复习时要把握两条贯穿全书的主线，它们在每章以不同面目出现：

**主线一：未定义行为（UB）。** UB 是「标准放弃描述」的陷阱——基础章直接考（有符号溢出、未初始化、空指针）；STL 章是使用失效迭代器、`new[]` 配 `delete`、范围 for 里 push_back；模板章是违反严格别名；并发章是数据竞争、DCLP 旧 bug；调试章里 Release 偶发崩溃的根因大半是「被优化放大的 UB」，ASan/UBSan 就是抓 UB 的工具。

**主线二：内存管理。** 内存管理贯穿 STL/模板/并发——STL 容器本身管理动态内存（vector 扩容、容器存智能指针）；模板常用于实现通用容器与智能指针（unique_ptr 是模板）；并发的 shared_ptr 引用计数是原子的，理解原子操作能看懂 shared_ptr 为何「引用计数安全却不保证对象读写安全」。

把这两条主线串成网而非孤立记忆，是总复习的核心。

<Term def="以典型陷阱为线索组织知识，与面试题库高度同构，保证不踩雷的复习策略；可转化为单测用例与 code review 检查项。">陷阱清单法</Term>

## 面试复习方法论

### 陷阱清单法

1. **建清单**：每章复习时把「典型陷阱」单独抄进一份清单，每条配一句话根因。
2. **自测**：盖住答案，看着清单条目默写「根因 + 修正」，写不出的回头补，每周过一遍。
3. **迁移**：面试前把清单浓缩成一页「高频陷阱速查」，临场编码时心里默念清单逐条避雷。
4. **转检查项**：把清单转成 code review checklist，面试写完代码主动按清单自检。

### 测试驱动复盘

1. **题后复盘**：每刷一题不只看对错，问「踩了哪个陷阱」「哪个知识点没掌握」，归类进清单。
2. **手写验证**：关键算法/模式在本地手写完整可编译版，用 ASan/Valgrind 跑，确认无内存错误才算真会。
3. **限时复现**：面试题限定时间训练反应速度，复盘记录「哪步卡了、为什么」。
4. **变式拓展**：把一题变式（如单例 → 线程安全单例 → 析构依赖单例），逼自己覆盖陷阱清单相邻条目。

### 把调试/优化包装成加分项

1. **主动展示工具意识**：写完代码主动说「我会用 ASan 跑一遍抓越界和 use-after-free，用 TSan 验证并发安全」。
2. **讲优化有据**：被问优化时先说「先 profiling 定位热点再优化」，举 Amdahl 定律，强调「先测后优」。
3. **讲调试有法**：被问「偶发崩溃怎么查」时，按 ASan/UBSan/TSan 在保留优化配置下复现、GDB backtrace 定位、git bisect 二分的步骤答。
4. **工程视角收尾**：总结时说「我把面试当 TDD——先想测试用例和陷阱，再写实现，最后用 sanitizer 验证」。

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 复习时把全书重读一遍，感觉都懂了，面试时却答不全。 <strong>原因 →</strong> 重读只触发「识别」而非「回忆」，知识没经过检索留不住，且没串成主线网。 <strong>修法 →</strong> 改用陷阱清单法默写根因+修正，用思维导图串两条主线，能默出来才算掌握。</Callout>

<Callout type="trap"><strong>现象 →</strong> 面试写完代码就交，被指出 bug 才发现踩了已知陷阱。 <strong>原因 →</strong> 没有主动自检习惯，写完即停。 <strong>修法 →</strong> 把陷阱清单转成 code review checklist，写完主动按清单自检（erase 后更新迭代器了吗、锁顺序一致吗），展现工程素养。</Callout>

<Callout type="trap"><strong>现象 →</strong> 被问优化时凭感觉说「这里用位运算更快」，实际没提升。 <strong>原因 →</strong> 没先测就优化，违反先测后优，且优化了非热点。 <strong>修法 →</strong> 先说「先 profiling 定位热点」，按算法复杂度 > 数据布局 > 微优化的顺序，优化后重新测验证。</Callout>
