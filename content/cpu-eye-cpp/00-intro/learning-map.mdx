## 为什么从 CPU 视角看 C++

C++ 的高级语法——类、虚函数、异常、模板——都是对底层硬件操作的抽象。停留在语法层面，你只知道「写了什么」，却不知道「CPU 实际怎么执行」。从 CPU 视角看，能看清三件语法层看不见的事：**成本**、**布局**与**优化的边界**。

一次虚函数调用要查虚表、间接跳转，比普通调用多一次访存；一次异常抛出要栈展开，代价远超 `if` 判断——这是成本。对象在内存里到底长什么样，成员顺序、对齐填充、虚指针位置，这些决定缓存命中与访存效率——这是布局。编译器能优化什么、不能优化什么，取决于它能否证明等价，不懂底层就无法预判优化是否生效——这是优化的边界。

所以「CPU 视角」不是炫技，而是把抽象映射回真实成本，让你写出既正确又高效的代码。

## 全书三段结构

<CpcBookMap />

全书分三大板块，呈「代码怎么来 → 怎么跑 → 怎么变快」的因果递进：

1. **编译与链接**（2 章）：讲清 C++ 源码如何经过预处理、编译、汇编、链接变成可执行文件。这是「代码的诞生」。
2. **CPU 运行时机制**（4 章）：从 CPU 视角看对象布局、函数调用栈帧、虚函数虚表、异常栈展开。这是「代码的运行」。
3. **CPU 性能优化**（4 章）：把对底层的理解转化为内联、缓存友好、编译器优化等性能红利。这是「代码的提速」。

三段之间是严格的依赖关系：不懂编译期如何展开抽象，就看不懂运行期的布局；不懂运行期布局，就看不懂优化为何生效或失效。跳层学习容易陷入「背了语法却写不出快代码」的困境。

## 学习路径与前置依赖

建议严格按章节顺序学习。运行时机制章（内存模型、函数调用、虚函数、异常）是全书的枢纽——它把编译期产生的机器码与运行期的硬件行为对接起来。性能优化章的每一项手段（内联、缓存、编译器优化）都建立在对运行时机制的理解之上。

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 觉得 C++ 语法都会了，写出来的程序却比同事慢，却找不到原因。<strong>原因 →</strong> 只学了「怎么写」，没学「CPU 怎么执行」，看不见虚函数的间接跳转、链表的缓存缺失、异常的栈展开成本。<strong>修法 →</strong> 按本书三段结构补齐底层认知：先懂编译产出什么，再看运行时 CPU 眼里代码长什么样，最后用这些知识指导优化。
</Callout>

## 小结与练习

全书主线一句话：懂 CPU，才能把 C++ 的抽象映射回真实成本。三段结构不是随意编排，而是「诞生 → 运行 → 提速」的因果链。
