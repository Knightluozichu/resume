## 虚拟地址空间布局

程序运行时，操作系统给它分配一段虚拟地址空间，从低地址到高地址分为几个段。

<CpcMemoryModelDiagram />

**代码段**存放编译后的机器指令，通常只读可执行。**只读数据段**存放 `const` 常量与字符串字面量。**数据段**存放已初始化的全局与静态变量，可读写。**BSS 段**存放未初始化（或初始化为 0）的全局与静态变量。**堆**是 `new`/`malloc` 分配的动态内存，向上增长，由程序员管理。**栈**存放局部变量、函数参数与返回地址，向下增长，自动管理。

## BSS 与 Data 的区别

<Term def="存放未初始化或初始化为 0 的全局/静态变量，不在可执行文件存数据，加载时由 OS 清零">BSS 段</Term>

BSS 段不占用可执行文件的磁盘空间，因为它存的全是 0，没必要在文件里存一堆 0——只需在程序加载时由操作系统按段大小分配内存并清零。可执行文件里 BSS 只记录「起始地址 + 大小」。

Data 段则不同，它存的是非 0 初值的全局/静态变量，这些初值必须保存在文件里，加载时原样拷贝到内存，否则程序恢复不了初始状态。工程含义：把一个大数组声明为全局并初始化为 0（进 BSS）比初始化为非 0（进 Data）可执行文件更小。

## 对象布局与 sizeof

从 CPU 视角看一个对象，语法上一个 `int` 加一个虚函数，内存里却是另一回事。以 `struct A { int x; virtual void f(); };` 为例，64 位系统下 `sizeof(A)` 通常是 16 字节：起始 8 字节是虚指针（vptr），指向类的虚表；接着 4 字节是 `int x`；末尾补 4 字节对齐填充，使对象大小是最大成员（vptr，8 字节）对齐的整数倍。

对齐填充是为 CPU 访存效率——未对齐的 8 字节访问可能跨缓存行甚至页边界，触发性能惩罚。成员声明顺序会影响填充量，合理排列成员能减少对象体积。

## 栈与堆的差异

栈是硬件原生支持的线性区：分配只需移动栈指针一条指令，O(1) 且极快；连续紧凑，栈顶常驻 L1 缓存，命中率极高；作用域结束自动回收，无泄漏风险。堆是软件模拟的自由区：`new` 要走内存分配器查找空闲块、可能的系统调用、维护元数据，慢几十到几百倍；碎片化导致对象散布在不连续地址，cache miss 频繁；生命周期需手动或靠智能指针管理。

性能设计含义：优先栈分配，能用局部变量就别 `new`；必须用堆时用对象池把碎片化转连续，恢复局部性。

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 以为 `sizeof` 一个含虚函数的小类就是成员大小之和，结果容器占用远超预期。<strong>原因 →</strong> 忘了 vptr（8 字节）与对齐填充，这两个隐藏开销语法层看不见。<strong>修法 →</strong> 用 `sizeof` 实测，理解 vptr 与对齐规则；热路径避免不必要的虚函数以省 vptr 开销。
</Callout>

## 小结与练习

程序地址空间分代码段、只读数据、数据段、BSS、堆、栈。BSS 不占可执行文件空间。含虚函数的对象有 vptr 与对齐填充，sizeof 反映真实占用。栈快且缓存友好，堆慢且碎片化。

<Exercises>

  <Answer question="`struct A { int x; virtual void f(); };` 在 64 位下 sizeof 是多少？为什么？">16 字节：vptr 8 + int 4 + 对齐填充 4，凑成 8 的整数倍。</Answer>
</Exercises>
