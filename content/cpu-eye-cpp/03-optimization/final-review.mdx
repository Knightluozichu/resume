## 全书主线回顾

全书三段结构是一条「诞生 → 运行 → 提速」的因果链：编译与链接决定代码长什么样（怎么来的），运行时机制决定 CPU 怎么执行它（怎么跑的），性能优化决定执行得有多快（怎么变快）。不懂前两段，优化就是盲猜。

一句话串联：编译决定代码长什么样，运行时机制决定 CPU 怎么执行它，优化决定执行得有多快。

## 零成本抽象的真相

<Term def="不为未使用的特性付费，抽象在编译期展开、运行期不留痕迹">零成本抽象</Term>

「零成本抽象」是 C++ 的设计哲学，但从 CPU 视角看，虚函数和异常都不是完全零成本。虚函数有每对象一个 vptr、调用多两次访存、间接跳转阻碍内联；异常有 unwind 表增大二进制、抛出极慢。

让它们接近零成本的关键是给编译器足够信息做编译期决议：虚函数靠去虚化（final 标注、CRTP 编译期多态、热路径避免虚调用）；异常靠表驱动的正常路径零开销加 noexcept 释放优化空间。零成本抽象的准确含义是「不为未使用的特性付费」——你用了就付费，不用时几乎不付。

## 系统化性能排查路径

给定一个性能不达标的程序，按「测量驱动、逐层下钻」排查：先用 profiler 定位热点，确认瓶颈是 CPU bound 还是 memory bound；再看算法与数据结构（复杂度、缓存友好的 vector 而非 list、热数据集中）；接着看内存布局（对齐填充、vptr 必要性、栈 vs 堆、false sharing）；然后看控制流（去虚化、分支提示、异常误用）；最后看编译器优化（`-O2`/`-O3`/`-march=native`、向量化阻碍、LTO、内联）。每改一处重新测量确认提升。

关键原则：先测量再优化、先算法后常量、先单线程后多核、先正确后快速。

## 懂 CPU 才能写好 C++

只懂语法不懂底层的程序员会系统性踩坑：滥用虚函数不知间接跳转切断优化链；异常当控制流不知栈展开代价；用链表代替数组不知缓存缺失；多线程共享计数器不知 false sharing；写出阻碍向量化的代码却以为编译器会优化；在多线程里依赖「编译器不会重排」的错觉写出 UB。

C++ 把硬件暴露给程序员，懂底层的人能把硬件红利榨干，不懂的人则被底层细节反噬。本书的价值正在于把语法层与 CPU 层打通，让每一行 C++ 都映射回真实的指令、访存与缓存行为。

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 凭直觉优化了半天，性能没提升。<strong>原因 →</strong> 不先测量就优化，在非热点上白费功夫，或跳层（算法没对就抠缓存）。<strong>修法 →</strong> 先用 profiler 定位热点，按算法 → 数据结构 → 内存布局 → 控制流 → 编译器优化逐层下钻，每改一处重新测量。
</Callout>

## 小结与练习

全书三段递进：编译与链接（代码怎么来）、运行时机制（怎么跑）、性能优化（怎么变快）。懂 CPU 才能把 C++ 语义映射回真实成本，写出既正确又高效的代码。
