## 这本书讲什么

《自制编译器》带你从零开始，完整实现一个将源代码翻译为目标机器可执行代码的编译器。与解释器不同，编译器不直接执行代码，而是将其翻译为等价的目标程序。

编译器覆盖的核心能力：

- 词法分析：源码文本 → Token 序列
- 语法分析：Token → 抽象语法树（AST）
- 语义分析：类型检查 + 符号表
- 中间代码生成：AST → 三地址码（IR）
- 代码优化：常量折叠 / 死代码消除 / 数据流分析
- 目标代码生成：IR → 机器指令 + 寄存器分配
- 链接与加载：目标文件 → 可执行文件 → 运行

## 编译器三段式架构

编译器采用**三段式架构**，每段职责分明，通过中间表示（IR）解耦：

| 阶段 | 模块 | 输入 → 输出 | 章节 |
|------|------|------------|------|
| 前端 | 词法 + 语法分析 | 源码 → Token → AST | ch2, ch3 |
| 中端 | 语义 + IR + 优化 | AST → IR → 优化 IR | ch4, ch5, ch6 |
| 后端 | 代码生成 | IR → 目标指令 | ch7 |
| 链接 | 链接 + 加载 | 目标文件 → 可执行文件 | ch8 |

<Callout type="info">

**关键洞察**：中间表示（IR）是三段之间的桥梁。前端不必关心目标机器，后端不必关心源语言，两者通过 IR 解耦独立开发。

</Callout>

## 为什么选三段式架构

| 对比维度 | 三段式编译器 | 单遍编译器 |
|---------|------------|-----------|
| 优化能力 | 强（IR 层多次遍历） | 弱（单次扫描） |
| 多语言支持 | M 个前端共享中后端 | 每语言独立实现 |
| 多平台支持 | N 个后端共享前中端 | 每平台独立实现 |
| 实现复杂度 | 中（需设计 IR） | 低（直接生成代码） |
| 适合场景 | 生产级编译器 | 入门教学/快速编译 |

<Callout type="tip">

本书目标是**理解完整编译链路**。三段式让源语言和目标机器解耦，是现代编译器（GCC/LLVM）的工业标准架构。

</Callout>

## 四个核心概念预览

| 概念 | 一句话解释 | 详细章节 |
|------|-----------|---------|
| Token | 源码分割后的最小语义单元 | ch2 |
| AST | 反映语法结构的树形数据 | ch3 |
| IR | 机器无关的中间指令表示 | ch5 |
| 数据流分析 | 在控制流图上推导程序性质 | ch6 |

<Glossary>

<GlossaryItem term="三段式架构">
编译器分为前端（词法+语法）、中端（语义+IR+优化）、后端（代码生成）三段，通过中间表示（IR）解耦，支持多语言×多平台复用。
</GlossaryItem>

<GlossaryItem term="中间表示（IR）">
介于 AST 和目标代码之间的机器无关指令表示（如三地址码、SSA），是前端与后端的接口，也是优化的操作对象。
</GlossaryItem>

<GlossaryItem term="编译 Pass（遍）">
对中间表示做一次完整处理的过程，每个 Pass 读入 IR 做一种变换后输出新 IR，多个 Pass 串成流水线。
</GlossaryItem>

<GlossaryItem term="数据流分析">
在控制流图上传播信息（到达定值、活跃变量等）来推导程序运行时性质的技术，是全局优化的理论基础。
</GlossaryItem>

</Glossary>

### 问题 1

《自制编译器》的整体目标是什么？编译器的三段式架构是什么？

<Answer>

整体目标是从零构建一个完整的编译器，将源代码翻译为目标机器的可执行代码。三段式架构：前端（词法分析+语法分析，源码→AST）中端（语义分析+IR生成+优化，AST→优化IR）后端（指令选择+寄存器分配，IR→目标代码）。三段通过中间表示（IR）解耦，前端与后端独立开发。

</Answer>

### 问题 2

编译器的完整流水线是什么？数据在各个阶段如何变换形态？

<Answer>

完整流水线：源码文本→词法分析→Token序列→语法分析→AST→语义分析→带类型注解的AST→IR生成→三地址码→优化→优化后IR→代码生成→目标指令序列→目标文件（.o）→链接→可执行文件→加载→运行。数据形态经历了从文本到结构化树再到线性指令序列的变换，每个阶段输出是下一阶段的输入。

</Answer>

### 问题 3

全书 10 章的学习路径是什么？各章之间的依赖关系是什么？

<Answer>

路径：ch0学习地图→ch1编译器架构→ch2词法分析生成器→ch3语法分析生成器→ch4语义分析与类型检查→ch5中间代码生成→ch6代码优化→ch7目标代码生成→ch8链接与加载→ch9全书复习。依赖：ch1是架构总览，ch2-ch3构成前端，ch4-ch6构成中端，ch7构成后端，ch8是链接加载，前端→中端→后端→链接层层递进，后端依赖中端的IR。

</Answer>

### 问题 4

为什么编译器采用三段式架构？中间表示（IR）在其中起什么作用？

<Answer>

三段式架构的核心优势是解耦与复用：多语言支持（M种语言只需M个前端，共享中后端）多平台支持（统一IR只需N个后端）优化复用（IR层优化只写一次，对所有语言和平台生效）。中间表示（IR）是三段之间的桥梁：前端输出AST，中端在IR层做分析和优化，后端从IR生成目标代码。IR让前端不必关心目标机器，后端不必关心源语言。

</Answer>
