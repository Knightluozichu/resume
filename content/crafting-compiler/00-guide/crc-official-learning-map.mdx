## 《自制编译器》权威学习地图

这张地图不是把章节标题排成一条只能从头走到尾的队列，而是把“源代码如何逐层变成可执行文件”拆成可选择、可验证的学习站点。每个站点都回答三个问题：输入是什么，产物是什么，下一阶段依赖哪一份证据。

学习者可以从语言前端开始，也可以从手头的汇编或链接问题反向进入；关键是标出缺失的前置能力，再安排一个小练习补回。先预测：如果一个人直接研究 ELF，却没有理解 AST 和 IR，他最可能把哪种高层错误误认为链接错误？地图的价值就在于让这条回补路径可见。

<Callout type="trap" title="误区一：把学习地图当成打卡清单">
  现象 → 章节标题全部读过，学习者却不能说出 token、AST、IR 和目标文件之间的交接证据。

原因 → 用阅读进度替代了输入、产物和失败边界的实际练习。

修法 → 每个阶段只选择一个最小探针，保存命令、产物和验收结果；完成证据后再标记站点。

</Callout>

<Callout type="trap" title="误区二：跳过前端直接修链接错误">
  现象 → 看到最终程序退出异常就反复调整链接参数，没有检查源位置、类型和生成的重定位。

原因 → 把最后观察到的故障层当成最早发生差异的层，忽略编译管线的交接关系。

修法 → 从源文件和 token 开始逐层核对；每层只改变一个观察点，找到最早差异后再进入下游修复。

</Callout>

<Callout type="trap" title="误区三：只保存最终可执行文件">
  现象 → 程序偶尔能运行，但没有源码版本、编译命令、目标 ABI 和中间产物，无法复现结果。

原因 → 把“能启动”当成工具链合同，遗漏版本、选项、符号和加载状态对结果的影响。

修法 → 保存输入、工具版本、命令、退出码、适用中间产物和清理重建记录，让下一次运行可以比较同一证据包。

</Callout>

## 全书概览

《自制编译器》的主线可以看成四个阶段。第一阶段建立 C♭ 与 `cbc` 的工作入口，认识编译器要解决的输入、语法和目标平台问题；第二阶段处理词法、语法、抽象语法树和语义约束；第三阶段把带有类型和绑定信息的结构降低为 IR 与 IA-32 指令；第四阶段生成目标文件、处理链接与加载，最终观察进程行为。

四个阶段不是互相隔离的专题。词法 token 的源位置会影响语法错误，AST 的绑定会影响类型检查，IR 的调用约定会影响栈帧和汇编，目标文件的符号与重定位又会影响链接器和加载器。地图把这些依赖画出来，学习者就能知道某个失败应该回到哪一层。

<Term def="把编译器的输入、结构化产物、错误合同和下游依赖组织成可观察步骤的路线；每个阶段都能独立运行最小探针。">
  编译管线
</Term>

## 课程地图：从源文件到进程

把一条最小程序想象成沿管线流动的证据：

```text
C♭ 源文件
  -> token 流
  -> AST 与绑定
  -> 类型与 IR
  -> IA-32 汇编
  -> ELF 目标文件
  -> 链接与加载
  -> 进程行为
```

每个箭头都意味着一次合同交接。词法层交出 token 类型和源位置，语法层交出树，语义层交出绑定和类型，IR 层交出可降低的控制流与数据流，汇编和目标文件层交出符号、重定位和权限信息。任何一层的证据不完整，下一层的“修复”都可能只是把错误往后推。

<Term def="某一编译阶段交给下一阶段的可观察数据、约束和错误语义；交接失败时应停在当前阶段，而不是生成伪产物。">
  阶段交接
</Term>

最小探针不必覆盖整门语言。一个整数表达式可以验证 token、树、类型、IR 和汇编；一个函数调用可以补充参数、栈和符号；一个外部库调用可以把重定位与加载引入观察范围。学习地图帮助你按目标增加复杂度，而不是一开始就构建所有能力。

## 四个阶段

### 阶段一：入口与目标

先把 `cbc` 的输入、命令、输出目录和目标 ABI 固定下来。这个阶段的产物是可以重复运行的最小源文件、编译命令和工具版本记录。遇到环境问题时，先区分 JavaCC、JDK、GNU 工具和目标平台的责任，不要把所有红字都归给编译器前端。

### 阶段二：前端结构

词法分析关注 token、最长匹配、非法字符和源位置；语法分析把 token 组织为树；JavaCC action 和 AST 生成让结构可以被后续阶段消费；引用消解和静态类型检查再为节点补充绑定、类型和求值约束。这个阶段的关键证据是“错误停在正确的源位置，且失败时不产生伪 IR”。

### 阶段三：中间表示与机器

IR 把高层语义变成更接近控制流、寄存器和内存的结构。IA-32 相关章节继续处理寄存器宽度、调用约定、表达式与语句、栈帧和优化边界。学习时不要只看生成的汇编是否“像人写的”，还要用哨兵输入、反汇编和运行结果检查栈效应与调用合同。

### 阶段四：目标文件与运行

生成目标文件后，`readelf`、`objdump`、`nm` 和链接器输出让节、段、符号、重定位、权限和地址解析变得可观察。链接和加载阶段适合使用一个外部符号或地址无关代码探针，记录链接命令、目标格式和运行时加载结果，避免只凭最终退出码判断成功。

## 推荐学习路径

默认路线从入口、词法与语法、AST 与语义、IR 与机器、目标文件到加载运行逐层推进。每走完一个阶段，至少完成一个“输入—产物—失败边界”的练习，再进入下一阶段：

1. **建立入口**：运行最小 `cbc` 示例，记录 JDK、JavaCC、GNU 工具、目标 ABI 和命令。
2. **理解前端**：从 token 和源位置开始，再看语法树、绑定、类型与错误合同。
3. **观察降低**：用一个表达式或函数调用追踪 AST、IR、IA-32 汇编和栈变化。
4. **检查目标文件**：用工具查看节、符号、重定位和权限，并把结果与汇编输入对应。
5. **完成运行验收**：清理构建目录后重建，比较进程输出、退出码和必要的加载轨迹。

如果你正在排查链接或加载问题，可以从第四阶段进入，但要先完成一个小型前端回放，确认源文件、符号声明和目标 ABI 没有更早的差异。跳读不是问题，无法说明回补证据才是问题。

## 怎么使用这张地图

<Term def="把一个学习目标压缩成一次有限范围的编译、观察或修复动作，并为输入、产物、失败边界和下一步留下记录。">
  编译探针
</Term>

每次学习只选一个探针。例如，“解释整数表达式如何进入汇编”可以固定一个源文件，保存 token、AST、IR、汇编和运行结果；“排查未定义符号”可以固定一个外部调用，保存目标文件符号表、重定位和链接器输出。探针越小，越容易在失败时指出最早差异。

建议把实验档案写成以下结构：

```text
source: samples/add.cb
toolchain: JDK + JavaCC + GNU binutils
target: IA-32 / chosen ABI
command: cbc --target ...
artifacts: tokens, ast, ir, assembly, object, executable
result: exit code and observed output
recovery: clean build and replay command
```

先猜一猜：同一份源码在清理前后得到不同的目标文件时，应该先比较编译命令、工具版本还是最终输出？先比较能影响所有下游产物的输入与工具坐标，再逐层查看差异，不要用最终输出掩盖中间层变化。

## 验收检查点

<Term def="用问题检查学习者能否解释一个阶段、运行一个最小探针、定位一处故障并说明清理重建后的结果。">
  验收检查点
</Term>

每个阶段的验收都分成三层：

- **解释**：能说出当前阶段接收什么、生成什么、把什么约束交给下一阶段。
- **操作**：能运行一个最小命令，保存产物、退出码、错误位置或工具输出。
- **迁移**：面对未见过的输入或目标 ABI，能构造边界或故障样本，判断应该回到哪一层。

如果解释通过但操作失败，缩小探针并检查环境；如果操作通过但迁移失败，改变输入或目标边界，保留同一观察指标；如果无法回退，重新记录阶段交接和清理重建命令。验收检查点的作用不是制造分数，而是决定下一次学习动作。

## 常见误区

常见误区都把课程路线和证据链割裂：有的人只完成目录阅读，有的人只盯最终可执行文件，还有的人在工具环境变化后继续比较旧产物。下面按现象、原因和修法拆开，方便把学习地图转成真实探针。

### 误区 1：只记住阶段名称

**现象**：能背出词法、语法、IR 和链接，却不能说明各层交给下一层什么。**原因**：只记名词，没有运行最小输入并保存阶段产物。**修法**：为一个简单表达式画交接表，再用同一源码逐层核对 token、AST、IR、汇编和目标文件。

### 误区 2：看到最后错误就改最后一层

**现象**：程序退出异常就反复修改链接参数，没有检查符号、重定位或更早的源位置。**原因**：把最后可见症状当成最早差异。**修法**：沿管线从输入开始比较，找到最早变化后只修改当前层，并在清理目录后重建。

### 误区 3：忽略工具链与目标坐标

**现象**：昨天生成的汇编、今天生成的目标文件和另一个 ABI 的结果被放在一起比较。**原因**：实验档案没有保存 JDK、JavaCC、GNU 工具、目标格式和命令选项。**修法**：把工具版本、目标 ABI、命令和退出码作为证据包的一部分，再比较中间产物。

## 小结

- 学习地图按“输入—产物—交接—验收”组织路线，允许跳读，但每次跳过都要安排回补探针。
- 四个阶段从入口与目标、前端结构、IR 与机器，到目标文件与运行，构成 C♭ 到进程的可观察管线。
- 编译探针应小到能保存源码、工具坐标、命令、阶段产物、失败边界和清理重建结果。
- 验收检查点覆盖解释、操作和迁移；遇到差异时回到最早变化层，而不是只修最后出现的错误。
- 学完地图的标志不是读完目录，而是能选择站点、运行探针、解释交接并复现一次结果。

<Exercises>

**问题 1：选择阶段。** 你写了一个整数表达式，最终程序输出错误。请列出从源文件到进程的关键产物，并说明第一轮应该保存哪三份证据。

<Answer>
  关键产物包括 token、AST、绑定或类型信息、IR、IA-32
  汇编、目标文件、链接结果和进程输出。第一轮至少保存固定源码与工具版本、编译命令与退出码，以及能覆盖当前怀疑阶段的中间产物；例如怀疑前端时保存
  token、AST 和错误位置，怀疑装载时再加符号与重定位。
</Answer>

**问题 2：设计编译探针。** 请为“未定义外部函数”设计一个最小探针，要求能区分源代码问题、目标文件问题和链接器问题。

<Answer>
  保留一个只调用外部函数的最小 C♭
  文件和明确声明，分别运行到汇编、目标文件和链接阶段。比较源位置、汇编符号引用、目标文件符号表与重定位、链接器诊断及退出码；每次只改变声明、目标
  ABI 或链接对象中的一个条件，避免把多个原因混在一起。
</Answer>

**问题 3：改 Demo 代码。** 实验中故障注入使 AST 与 IR 的节点数量不一致。请说明你会先检查什么、如何清理重建，以及何时可以进入下一阶段。

<Answer>
  先固定源码、工具版本和命令，比较 AST 的节点类型、源位置与 IR
  的输入映射，找到最早不一致的交接，而不是直接改汇编。修复后删除旧生成目录，重新运行同一命令，比较
  token、AST、IR
  和退出结果；只有正常、边界和一处故障输入都能解释，才进入汇编或目标文件阶段。
</Answer>

</Exercises>
