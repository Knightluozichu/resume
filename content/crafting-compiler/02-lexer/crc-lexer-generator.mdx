## 词法分析生成器的作用

词法分析生成器（如 Lex/Flex）接收**正则表达式**描述的 Token 规则，自动生成可执行的词法分析器代码：

```text
正则表达式 ──Thompson──→ NFA ──子集构造──→ DFA ──最小化──→ 状态转移表
```

## 从正则到 NFA：Thompson 构造

Thompson 构造法将每个正则表达式转为等价的 **NFA**（非确定有限自动机）：

| 正则构件 | NFA 构造 |
|---------|---------|
| 单字符 `a` | 起点 →(a)→ 终点 |
| 连接 `ab` | 串联两个 NFA |
| 选择 `a|b` | 新起点 ε 分支到两个 NFA |
| 重复 `a*` | ε 回环 + 旁路 |

<Callout type="info">

NFA 允许同一状态对同一输入有多条转移边，且有 ε（空转移）边。ε 转移实现分支选择，无需消费输入即可跳转。

</Callout>

## 从 NFA 到 DFA：子集构造

**DFA**（确定有限自动机）每个状态对每个输入只有一条转移，运行效率更高。子集构造法将 NFA 转为 DFA：

```text
NFA 状态集合 → 视为 DFA 的一个状态
对每个输入符号，计算转移后做 ε 闭包 → 得到新的 DFA 状态
```

| 对比 | NFA | DFA |
|------|-----|-----|
| 转移确定性 | 非确定（多条边 + ε） | 确定（每输入最多一条边） |
| 运行方式 | 维护状态集合/回溯 | 单步确定下一状态 |
| 状态数 | 少 | 多（最坏 2^n） |
| 运行效率 | 低 | 高 |

最后用 **Hopcroft 算法**最小化 DFA 状态数——合并等价状态。

## Token 类型与正则模式

```text
KEYWORD   if|else|while|return          → if, while
IDENT     [a-zA-Z_][a-zA-Z0-9_]*        → x, count
NUMBER    [0-9]+                         → 42, 0
OP        +|-|*|/|=|==                   → +, ==
```

## 最长匹配与优先级

<Callout type="warning">

**最长匹配（Maximal Munch）**：总是消费尽可能多的字符。输入 `==` 时匹配为 `==` 一个 Token，而非两个 `=`。

</Callout>

<Callout type="warning">

**优先级规则**：当一个输入能匹配多条规则时，按规则定义顺序选择靠前的。`if` 既能匹配 KEYWORD 也能匹配 IDENT，KEYWORD 在前所以匹配为关键字。

</Callout>

## 实战：用 Flex 定义词法规则

```text
%%
if|else|while|return   { return KEYWORD; }
[a-zA-Z_][a-zA-Z0-9_]* { return IDENT; }
[0-9]+                 { return NUMBER; }
"=="|"="|"+"|"-"|"*"|"/" { return OP; }
[ \t\n]+               { /* 跳过空白 */ }
%%
```

Flex 自动将上述正则规则转为 NFA → DFA → 状态转移表，生成 C 语言的 `yylex()` 函数。

<Glossary>

<GlossaryItem term="NFA（非确定有限自动机）">
允许同一状态对同一输入有多条转移边和 ε（空转移）边的有限自动机，需维护状态集合来模拟运行。
</GlossaryItem>

<GlossaryItem term="DFA（确定有限自动机）">
每个状态对每个输入符号最多有一条转移边、无 ε 边的有限自动机，单步即可确定下一状态，运行效率高。
</GlossaryItem>

<GlossaryItem term="Thompson 构造法">
将正则表达式转为 NFA 的算法：单字符转转移边，连接串联，选择用 ε 分支，重复用 ε 回环。
</GlossaryItem>

<GlossaryItem term="子集构造法">
将 NFA 转为 DFA 的算法：将 NFA 中能通过 ε 闭包到达的状态集合视为 DFA 的一个状态。
</GlossaryItem>

<GlossaryItem term="最长匹配（Maximal Munch）">
词法分析器总是消费尽可能多的字符来形成一个 Token 的规则，确保多字符运算符（如 ==）被正确识别。
</GlossaryItem>

</Glossary>

### 问题 1

词法分析生成器的核心流程是什么？正则表达式如何变成可执行的词法分析器？

<Answer>

核心流程：正则表达式→NFA（Thompson构造）→DFA（子集构造）→最小化DFA→词法分析器代码。正则表达式描述Token的词法模式，通过Thompson构造法转为非确定有限自动机（NFA），再用子集构造法转为确定有限自动机（DFA），最后通过Hopcroft算法最小化DFA状态数。最终的DFA可直接编码为状态转移表，驱动词法分析器逐字符消费输入并输出Token。工具如Lex/Flex自动完成这一流程。

</Answer>

### 问题 2

NFA 和 DFA 的区别是什么？子集构造法如何将 NFA 转为 DFA？

<Answer>

NFA（非确定有限自动机）允许同一状态对同一输入有多条转移边，且可有ε（空转移）边，需要维护状态集合并做回溯或并行模拟。DFA（确定有限自动机）每个状态对每个输入最多一条转移边，无ε边，单步即可确定下一状态，运行效率更高。子集构造法：将NFA中能通过ε闭包到达的状态集合视为DFA的一个状态，对每个输入符号计算该集合的转移后再做ε闭包，得到新的状态集合作为DFA的下一状态。最终每个DFA状态对应一个NFA状态子集。

</Answer>

### 问题 3

词法分析器的最长匹配（Maximal Munch）和优先级规则是什么？为什么需要它们？

<Answer>

最长匹配规则：词法分析器总是消费尽可能多的字符来形成一个Token。例如输入==时，应匹配为一个== Token而非两个= Token。优先级规则：当一个输入能匹配多条规则时（如if既能匹配关键字规则也能匹配标识符规则），按规则定义顺序选择靠前的。需要这两条规则是因为正则表达式本身没有优先级和贪婪语义——多个模式可能同时匹配同一段输入，必须有确定的消歧策略保证词法分析结果的唯一性和正确性。

</Answer>

### 问题 4

常见的 Token 类型有哪些？各自用什么样的正则模式匹配？

<Answer>

常见Token类型：KEYWORD（关键字）——用枚举模式匹配，如if|else|while|return。IDENT（标识符）——[a-zA-Z_][a-zA-Z0-9_]*，字母/下划线开头后跟字母数字下划线。NUMBER（数字字面量）——[0-9]+匹配整数，扩展可匹配浮点数。OP（运算符）——+|-|*|/|=|==，需注意多字符运算符优先于单字符。STRING（字符串）——用引号包裹的模式匹配。COMMENT（注释）——通常被丢弃不输出Token。每类Token携带类型标签和原始文本值。

</Answer>
