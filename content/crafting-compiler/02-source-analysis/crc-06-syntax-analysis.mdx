## 从 token 层级到可验证的语法树

语法分析的任务不是把 token 全部消费后返回一个“成功”标记，而是把 token 放入有边界的结构。定义说明程序里有哪些名字和初值，语句说明一次可执行动作，表达式说明值与运算关系，项则把乘法层或更高优先级的局部结构固定下来。

先预测 `a + b * c` 的树形，再观察解析器进入哪一层、消费了哪些 token、返回了哪一个节点。只要每层保存入口、出口、源跨度和子节点，优先级错误就不会被后续类型检查或代码生成掩盖。

<Callout type="trap" title="误区一：把语句和表达式混成一条规则">
  现象 → 赋值、调用和返回都能暂时解析，但分号、括号或嵌套块的错误位置不断漂移。

原因 → 语句的控制边界与表达式的值边界没有分开，解析器不知道谁负责消费结束 token。

修法 → 为语句和表达式分别保存入口、出口和返回节点，用最短语句与最短表达式分别验收。

</Callout>

<Callout type="trap" title="误区二：用从左到右的读取代替优先级">
  现象 → `a + b * c` 被构造为先加后乘，树的节点顺序却看起来仍然完整。

原因 → 项没有成为表达式的子层，乘法和加法共享了同一个平面规则。

修法 → 让 expression 调用 term，再由 expression 处理加法层；比较无括号和带括号样本的树形。

</Callout>

<Callout type="trap" title="误区三：截断输入也返回部分成功树">
  现象 → 缺少右括号或分号时，解析器交付一个看似完整的 AST，下游才报告无关错误。

原因 → 没有把必需的结束 token 和当前 production 的源跨度纳入错误合同。

修法 → 在缺口处抛出带位置和期望 token 的诊断，不交付越过错误边界的节点；清理后重复回放。

</Callout>

## 语法分析的工作合同

第6章 语法分析固定一条证据链：token 序列进入 production，production 根据上下文进入定义、语句、表达式或项，最后交付 AST 或诊断。每一层都要说明消费范围、子节点、返回值和失败位置，避免把结构责任推给后续阶段。

<Term def="保存语法结构、子节点和源码起止位置的树形产物；它把解析阶段的边界交给类型检查和代码生成继续使用。">
  AST
</Term>

AST 不只是打印出来的缩进文本。节点类型、子节点顺序和 `[start, end)` 源跨度共同构成合同；当 `a + b * c` 的乘法层挂错位置时，后续阶段应该能直接从树形断言发现问题。

<Term def="描述名字、类型、初值或函数入口等程序绑定如何出现的语法结构；它通常在定义边界处交付声明节点。">
  定义
</Term>

定义分析要先确认名字和边界，再处理可选初值或参数。`int count = 1;` 中的类型、名称、等号、初值和分号应分别有可观察的消费位置；缺少名称时不能把等号误当作表达式入口。

<Term def="表达一次可执行动作及其结束条件的语法结构，例如赋值、调用、返回或复合语句；它负责把表达式放入控制边界。">
  语句
</Term>

语句分析负责分号、块和控制结构的边界。它可以调用表达式分析取得值，但不应把表达式内部的优先级逻辑复制一遍。这样的分层让一个表达式修复能同时改善赋值、返回和调用。

<Term def="产生一个值的语法结构；它通过运算符、调用、名字和括号组合出带优先级与结合性的 AST。">
  表达式
</Term>

表达式层处理加法、赋值或条件等较低优先级构造，并把更紧的运算交给项。判断表达式是否正确时，要看根节点、子节点顺序和括号留下的源跨度，而不只是看 token 是否耗尽。

<Term def="表达式中优先级更高、可连续组合的局部结构，通常承载乘法、除法、名字、调用和括号等紧密绑定的构造。">
  项
</Term>

项是优先级分层的关键。若 expression 先解析一个 term，再消费加号和下一个 term，`b * c` 就会先在项层完成；若项规则过宽，表达式的结合性会在最小样本上暴露。

## 第1部分 代码分析

词法分析交付 token，语法分析交付 AST，语义检查再解释名字和类型。三者的交接可以用一个最小快照表达：输入 token、当前 production、已消费跨度、返回节点和错误位置。只有这些字段都能回放，才知道问题发生在扫描、分层还是语义阶段。

```text
tokens: identifier plus identifier star identifier eof
tree:   add(name(a), multiply(name(b), name(c)))
span:   [0, 9)
```

每次只改变一个因素：括号、运算符、结束 token 或嵌套深度。固定 JavaCC 版本、生成命令和样本编号，才能把树形变化归因给语法规则，而不是构建残留。

## 第6章 语法分析

第6章 语法分析把五个正式节点放在同一条可回放路径上：总入口决定当前语法合同，定义和语句建立外层边界，表达式与项决定值的分组，最后交付 AST 或诊断。专属实验显示每一层的入口 token、源跨度和当前结果。

## 6.1 定义的分析

定义分析从类型、名字和可选初始化开始。先消费必须存在的名字，再判断等号是否开启初值；分号或块结束是定义的边界。空定义、缺失名字和重复名字可以分别交给语法层与后续语义层，不要用一个模糊错误覆盖所有情况。

## 6.2 语句的分析

语句分析把表达式放进动作边界。赋值语句需要确认左侧可赋值、等号和右侧表达式，调用语句需要确认参数列表和结束括号，复合语句需要让块内语句共享明确的结束条件。语句层只负责控制边界，表达式层负责值的结构。

## 6.3 表达式的分析

表达式分析处理较低优先级的组合。递归下降实现通常让 expression 先取得一个 term，再在看到加号或减号时继续取得 term；这样左结合的 `a - b - c` 可以形成 `(a - b) - c`，而括号则通过新的嵌套入口改变范围。

## 6.4 项的分析

项分析处理比加法更紧的结构，例如乘法、除法、名字、调用和括号。对 `a + b * c`，项层先构造 `b * c`，表达式层再把结果与 `a` 组合。项的结束条件必须清楚，否则表达式层无法知道何时接管下一个运算符。

## 小结

- AST 同时保存节点结构、子节点顺序和源跨度，不能用 token 耗尽替代树形验收。
- 定义和语句负责外层边界，表达式与项负责值的分组、优先级和结合性。
- 项层先完成更紧的运算，表达式层再处理较低优先级；括号通过嵌套入口改变范围。
- 截断输入应在当前 production 的缺口处停止，并稳定报告期望 token、位置和退出码。

**问题 2：验证优先级。** 对 `a + b * c`、`(a + b) * c` 和 `a - b - c` 写出预期 AST，并说明应该由表达式层还是项层首先构造每个节点。

<Answer>
  第一棵树是 `add(a, multiply(b, c))`，乘法先由项层构造；第二棵树是
  `multiply(add(a, b), c)`，括号让表达式子树先完成；第三棵树是
  `subtract(subtract(a, b),
  c)`，表达式层按左结合逐次组合。比较根节点和每个节点的源跨度即可确认层级。
</Answer>

**问题 3：修复边界诊断。** 将一个合法调用改成缺少右括号的输入，再改成缺少语句分号的输入；要求清理生成目录后重复回放，比较停止位置、期望 token 和 AST 是否被错误输入污染。

<Answer>
  缺少右括号时应停在调用 production 的结束位置，期待
  RPAREN；缺少分号时应停在语句边界，期待
  SEMICOLON。两种输入都不交付越过缺口的完整节点。删除生成目录后用固定命令重建并运行两次，比较错误阶段、位置、消息摘要、树摘要和退出码。
