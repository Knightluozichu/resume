## 从匹配符号到一次稳定的节点构造

JavaCC production 匹配 token 后，可以在规则内部执行 action。action 适合把已经确认的语法片段组装成节点或返回值，但它不应偷偷修改全局符号表、依赖上一次解析的缓存，或替语义阶段决定类型。稳定的边界是：匹配符号进入 action，action 读取局部数据，节点携带结构和跨度，后续阶段再解释它。

先预测 `1 + 2` 会生成哪些节点，再在专属实验中逐步显示匹配符号、action、AST 节点、源码跨度和重放结果。每次只注入一个故障，才能判断是 action 执行、节点构造还是状态清理发生了问题。

<Callout type="trap" title="误区一：让 action 直接修改全局语义状态">
  现象 → 第一次解析成功，第二次解析同样输入却受到上一次名称、计数器或缓存的影响。

原因 → 把解析阶段的局部结构构造和语义阶段的环境更新混在 action 中，失败路径也没有回滚。

修法 → action 只返回局部节点或值；需要的环境变化交给后续阶段，并在重放时比较状态快照。

</Callout>

<Callout type="trap" title="误区二：用可变节点节省一次构造">
  现象 → 一个节点被多个父节点共享后，修改其中一处导致另一棵树的子节点和跨度一起变化。

原因 → AST 节点暴露可写字段，action 或调试代码可以在构造完成后改变既有结构。

修法 → 节点字段和子节点集合在构造后不可变；需要变化时创建新节点，并保留新的源跨度。

</Callout>

<Callout type="trap" title="误区三：把跨度当成调试附属信息">
  现象 → 树形看起来正确，但诊断高亮了错误文本，后续类型错误无法指回源码。

原因 → action 只传递值和节点类型，没有把 token 的起止位置合并到父节点。

修法 → 每个节点保存半开区间 `[start, end)`；组合节点取子树覆盖范围，并用嵌套样本检查边界。

</Callout>

## Action 与 AST 的工作合同

第2部分 抽象语法树和中间代码从语法结构继续向语义与 IR 传递信息。第7章 JavaCC的action和抽象语法树只负责把已匹配的符号变成结构化节点；它的输出要能被后续阶段读取，也要能在相同输入与相同 grammar 下重复得到相同结果。

<Term def="在 JavaCC production 内、匹配到指定 token 或子规则后执行的代码片段；它可以组装局部节点或返回值，但不应隐藏跨解析状态。">
  action
</Term>

action 的输入应来自当前 production 的局部变量和已匹配符号。一个清晰的 action 能回答“已经确认了什么、正在构造什么、交付给谁”；如果它还要更新全局环境，就需要把责任移动到语义阶段并留下显式接口。

<Term def="表示语法类别、子节点、字面值和源码范围的数据对象；它把解析结果交给类型检查、解释或代码生成。">
  AST 节点
</Term>

AST 节点要有稳定的种类和字段。例如二元加法节点可以保存左子节点、右子节点、运算符位置和整体跨度。字段越明确，后续阶段越不需要重新猜 token 的含义。

<Term def="创建后字段和子节点引用不再被原地修改的结构性质；它让树可以安全共享、缓存和跨阶段传递。">
  不可变
</Term>

不可变不是为了让代码更漂亮，而是为了让回放可比较。若 action 失败或下游需要另一种表示，创建新节点比修改旧节点更容易记录原因、保留旧快照和复现差异。

<Term def="对应源码中的半开区间 `[start, end)`；它由 token 和子节点范围合并得到，用于诊断、跳转和错误高亮。">
  源码跨度
</Term>

源码跨度是节点结构的一部分。叶节点直接取 token 范围，组合节点覆盖最左子节点到最右子节点；空结构和缺失 token 不应伪造一个越过错误位置的跨度。

<Term def="在相同输入、grammar、工具版本和清理条件下再次执行 action 与节点构造，并比较结构、跨度、状态和退出码的过程。">
  回放
</Term>

回放记录不仅包含最终树，还要包含 action 顺序、节点标识、跨度、错误消息和状态快照。这样才能区分生成器变化、输入变化和 action 残留。

## 第2部分 抽象语法树和中间代码

语法分析交付 AST 后，语义分析和 IR 转换才有稳定的输入。节点应保留语法阶段真正知道的事实：节点类型、子节点、字面值和源码跨度；类型、绑定和机器表示属于后续阶段，不要在 action 里提前写死。

## 第7章 JavaCC的action和抽象语法树

本章的主线是 `matched symbols → JavaCC action → immutable AST node`。在 action 之前，解析器只确认局部符号；在 action 之后，节点可以被检查、打印和转换；在重放验收中，等价输入应产生等价结构，失败输入不应污染下一次解析。

## 7.1 JavaCC的action

action 的执行时机跟 production 的消费顺序绑定。若 action 在右括号或分号确认之前就发布了完整节点，后续失败会留下半成品；更稳妥的做法是把局部值保存在 action 内，等必需符号匹配完成后一次构造节点。

action 也不应承担类型检查和名称解析。它可以把字面值、操作符和子节点组合起来，但“这个名字是否已声明”“两个类型能否相加”应在下一阶段通过明确的节点接口处理。

## 7.2 抽象语法树和节点

AST 节点把语法事实组织成后续阶段可以消费的接口。节点类型应足够区分字面值、名字、二元运算和调用；子节点顺序应表达结合性；源码跨度应覆盖用户真正输入的片段。构造后保持不可变，调试打印和类型检查就能共享同一份树。

## 小结

- action 只应基于当前 production 的已匹配符号构造局部结构，不应暗中改变跨解析状态。
- AST 节点要明确类型、子节点、值和源码跨度，构造后保持不可变。
- 源码跨度应随叶节点和组合节点一起保存，诊断才能指回用户输入。
- 回放要比较 action 顺序、节点结构、跨度、状态快照和退出码，而不只是最终打印文本。
