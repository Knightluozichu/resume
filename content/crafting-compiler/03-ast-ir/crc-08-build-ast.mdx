## 从源码片段到节点族

抽象语法树的生成把前一章的节点合同落实为一组可使用的节点族。表达式需要表达值与运算关系，语句需要表达动作和结束边界，声明需要表达名字、类型和初始化；这些结构都不能只靠打印文本来区分。

先预测 `count + 1`、`return count;` 和 `int count = 1;` 会生成哪些根节点，再通过 cbc 的解析器入口回放实际结果。固定输入、grammar、JavaCC 和构建目录，只改变一个样本，结构差分才有归因价值。

<Callout type="trap" title="误区一：让所有构造都返回通用节点">
  现象 → 表达式、语句和声明都能打印出来，但后续阶段需要通过字符串猜节点语义。

原因 → 节点工厂没有按语法责任划分类型，根节点、子节点和字段合同都变得模糊。

修法 → 为每个节点族定义明确 kind、字段和子节点顺序，用最短输入断言根节点与源码跨度。

</Callout>

<Callout type="trap" title="误区二：只比较 AST 文本而不比较结构">
  现象 → 两棵树打印结果相似，但加法左右子树或声明初始化边界已经被交换。

原因 → 快照没有比较节点类型、子节点位置、字面值和半开跨度。

修法 → 使用结构化 JSON 或字段表做差分，并把根节点、子节点顺序和跨度列为验收字段。

</Callout>

<Callout type="trap" title="误区三：cbc 启动时复用旧生成目录">
  现象 → 修改 grammar 后 AST 结果没有变化，或者命令在本机成功、清理后却失败。

原因 → cbc 入口没有明确生成、编译、运行和清理边界，旧 parser 或旧快照遮蔽了当前输入。

修法 → 记录入口参数、生成命令、工具版本、清理动作和退出码；清理后从同一输入重新生成并比较结果。

</Callout>

## AST 生成的工作合同

第8章 抽象语法树的生成关心“如何稳定地产生结构”，而不是提前完成类型检查或 IR 优化。输入是 token 和源位置，节点工厂负责选择结构，cbc 解析器负责把 grammar 接到运行命令，验收则比较 AST 字段、跨度、错误和构建状态。

<Term def="根据节点种类、子节点和值创建 AST 对象的集中接口；它把字段默认值、跨度合并和不可变约束放在同一处。">
  节点工厂
</Term>

节点工厂应让构造路径可见。表达式、语句和声明可以有不同入口，但每个入口都应交付明确的 kind、字段和 span；不符合合同的组合在工厂边界尽早失败。

<Term def="表示产生值的语法构造及其运算、调用、名字和字面量子树的 AST 族。">
  表达式 AST
</Term>

表达式 AST 需要保留运算符和子节点顺序。`count + 1` 的根节点应知道左右子树和加号范围，括号输入则应通过嵌套节点或跨度体现，而不是被压成同一个字符串。

<Term def="表示赋值、返回、调用、条件或复合块等可执行动作及其结束边界的 AST 族。">
  语句 AST
</Term>

语句 AST 连接控制边界和表达式子树。返回语句要知道返回值是否存在，复合块要保持语句顺序，分号或右括号等结束 token 不应被错误地吞进下一条语句。

<Term def="表示类型、名字、参数、初始值和声明范围等绑定结构的 AST 族。">
  声明 AST
</Term>

声明 AST 把名字和类型放在结构字段中，把可选初始化作为明确子节点。这样语义阶段可以检查定义，而不必重新扫描源代码寻找等号和分号。

<Term def="把 C♭源文件、JavaCC 生成解析器和 AST 输出命令连接起来的入口流程；它固定参数、构建目录和退出码。">
  cbc 解析器启动
</Term>

cbc 解析器启动不是一个黑盒按钮。它至少应记录输入文件、grammar 或生成版本、生成/编译/运行命令、清理动作、AST 输出和退出码；任何一项缺失，构建结果就难以复现。

## 第2部分 AST、语义与IR

AST 是语义分析和 IR 转换的共享输入。生成阶段要保存语法事实和源码位置，把符号解析、类型判断、临时变量和机器约束留给后续阶段；这样结构差分才能准确指出问题属于解析器还是语义过程。

## 第8章 抽象语法树的生成

本章将生成流程拆成五个可复查节点：第8章 抽象语法树的生成规定总合同，表达式/语句/声明 AST 规定节点族，cbc 的解析器的启动规定可执行入口。实验同时显示根节点、子节点、跨度、命令和退出码。

## 8.1 表达式的抽象语法树

表达式 AST 的核心是结构而非字符串。对于 `a + b * c`，根节点应表达加法，右子树应表达乘法；对于 `(a + b) * c`，括号改变了根节点与跨度。最小样本足以检验优先级和子节点顺序。

## 8.2 语句的抽象语法树

语句 AST 要保留动作边界与内部表达式。`return count;` 需要明确返回值，`count = count + 1;` 需要把左侧名字、赋值操作和右侧表达式放在稳定字段中；多条语句还必须保持源顺序。

## 8.3 声明的抽象语法树

声明 AST 把类型、名字、可选初值与跨度绑定在一起。`int count = 1;` 的初始化不应被丢进注释文本或通用 token 列表；缺少名字或分号时，构建应停在声明入口并给出期望 token。

## 8.4 cbc的解析器的启动

cbc 的解析器启动先准备生成目录，再用固定命令构建和运行解析器，最后序列化 AST。清理后重建是必要的控制实验：若同一输入产生不同根节点、节点字段或退出码，应先检查入口参数、生成产物和版本，而不是直接修改节点工厂。

## 小结

- 节点工厂集中表达 kind、字段、子节点和跨度合同，避免所有构造退化为通用节点。
- 表达式、语句和声明 AST 分别保留值结构、动作边界和绑定字段，并保持源顺序。
- cbc 解析器启动必须固定输入、生成/编译/运行命令、清理动作和退出码。
- AST 验收要做字段级结构差分，不能只比较打印文本或“命令成功”。
