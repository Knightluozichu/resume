## 从 AST 名称到唯一绑定

抽象语法树只告诉我们某个位置出现了名字；语义分析还要回答这个名字指向哪一份声明。引用消解把声明、嵌套作用域、变量或类型名使用串成一条可复查路径：先进入作用域，再登记声明，最后从当前作用域向外查找并留下声明 ID。

本章的主实验是“作用域与引用消解台”。它固定 C♭ 源码、`cbc` 提交、JDK 与 JavaCC、目标 ABI 和命令参数，只切换作用域形态、样本和故障模式。交互中的每个状态都对应声明 ID、作用域栈、查找结果或诊断，不把语义判断伪装成分数。

<Callout type="trap" title="误区一：把同名当成同一实体">
  现象 → 外层和内层都声明 `count` 时，所有引用都被绑定到同一个字符串键。

原因 → 符号表没有记录作用域和声明 ID，查找过程也没有明确从内层向外层的顺序。

修法 → 每次声明分配稳定 ID，把作用域栈和可见性写入绑定表；命中内层声明时记录遮蔽关系，而不是覆盖历史记录。

</Callout>

<Callout type="trap" title="误区二：忽略声明时点">
  现象 → 使用出现在声明之前，却因为后续存在同名声明而被错误接受。

原因 → 实现先扫描完整文本再做字符串搜索，丢失了声明出现的源位置和语言规定的可见时点。

修法 → 按 AST 源序处理声明与使用，把“可见范围”和“可见时点”分开断言；未满足条件时保留位置精确的未定义诊断。

</Callout>

<Callout type="trap" title="误区三：把类型名和变量名混进一张无规则的表">
  现象 → 类型名称的解析误用变量声明，或者重复定义被静默覆盖，后续节点带着伪绑定进入 IR。

原因 → 命名空间、重复策略和错误合同没有在引用消解阶段固定下来。

修法 → 为变量与类型名保留可解释的命名空间和声明类别；重复定义、未定义引用在生成 IR 前汇总并拒绝继续。

</Callout>

## 引用消解的工作合同

语义分析的概要不是“把名字替换成字符串”。它要把 AST 中的声明和使用转换为可追踪边：声明节点提供类别、源跨度和声明 ID，作用域栈提供可见集合，查找器提供命中或失败原因，诊断集合保留文件位置。通过不变量是：每个成功引用绑定唯一可见声明；遮蔽有明确的内外层关系；重复定义与未定义引用不会生成伪 IR。

<Term def="在 AST 上根据作用域、声明类别和源位置，为名字使用找到唯一可见声明的语义过程。">
  引用消解
</Term>

引用消解应输出结构化绑定，而不是只把 `count` 替换为文本。一个绑定至少包含使用节点 ID、声明 ID、名称空间、声明类别和源跨度；失败项则包含错误码、位置和查找过的作用域层级。

<Term def="由当前作用域到外层作用域组成的有序查找链；进入块时压入，离开块时弹出。">
  作用域栈
</Term>

作用域栈把嵌套块的可见性变成可观察状态。查找从栈顶开始，命中后停止；同名的外层声明仍保留在表中，用于解释遮蔽和离开内层后的恢复。

<Term def="声明在绑定表中的稳定身份，用于把一个名字使用连接到确切的声明节点，而不是连接到易变的文本。">
  声明 ID
</Term>

声明 ID 应跨越诊断、绑定表和后续类型检查保持稳定。调试输出可以使用 `D3`、`D7` 这样的短标识，但不能因为排序或重新生成而改变同一输入的含义。

<Term def="一个作用域中的声明隐藏外层同名声明的可见性关系；它不是重复定义，因为两个声明位于不同的作用域。">
  遮蔽
</Term>

遮蔽需要同时记录“使用命中了哪一个声明”和“哪一个外层声明被隐藏”。如果把它简化为覆盖键，调试器就无法解释离开内层后为什么绑定恢复。

<Term def="对重复定义、未定义引用或错误命名空间等失败进行统一收集的结果；它在生成 IR 前决定是否拒绝输入。">
  汇总诊断
</Term>

汇总诊断要有稳定排序规则，例如按源位置再按错误码排序。这样正常样本和错误样本都能清理后重放，并且不会用后一条错误覆盖更早的语义事实。

## 第2部分 AST、语义与IR

AST 提供语法事实，引用消解把名字使用连接到声明，静态类型检查再利用这些绑定判断表达式。这个阶段不应提前生成机器地址或优化 IR；它的边界是留下准确的声明边、命名空间和诊断，使后续阶段能复用同一份语义事实。

## 官方目录逐项深读

### 第9章 语义分析（1）引用的消解

本章的总合同把“每个名称绑定到唯一可见声明”落成绑定表和诊断。实验先展示从声明到使用的完整路径，再注入遮蔽、重复和未定义条件，观察错误如何在 IR 之前停止。

### 9.1 语义分析的概要

语义分析的概要规定 AST 之后的边界：遍历节点时维护作用域栈，为声明登记类别与源跨度，为使用请求查找，最后输出绑定表和汇总诊断。成功路径进入下一阶段，失败路径只保留可解释的语义产物。

### 9.2 变量引用的消解

变量引用从当前作用域向外查找。外层 `limit` 被内层 `limit` 遮蔽时，内层使用应绑定内层声明 ID；离开内层后，新的使用才恢复到外层 ID。未定义引用不能因为存在相似拼写或未来声明而被接受。

### 9.3 类型名称的消解

类型名称的消解要区分命名空间和声明类别。`Node` 作为类型名的可见性不应被变量 `Node` 的文本键覆盖；若语言只允许一个命名空间，也要把冲突规则写入诊断合同，而不是在表中静默选择一项。

## 小结

- 引用消解把名称使用连接到唯一声明 ID，不能退化为全局字符串替换。
- 作用域栈表达嵌套可见性，遮蔽保留内外层关系，声明时点决定使用能否命中。
- 变量与类型名称要遵守明确的命名空间和重复策略，失败项在生成 IR 前形成汇总诊断。
- `ResolveDump` 应保存输入、作用域栈、绑定表、错误位置、命令和清理记录，保证正常与错误样本都能重放。

**问题 2：分析遮蔽。** 外层声明 `limit` 的 ID 为 `D1`，函数内层声明同名变量的 ID 为 `D2`。函数体使用一次 `limit`，函数外再使用一次；请写出两条绑定和一条可见性解释。

<Answer>
  函数体使用绑定 `use_in → D2`，因为查找从函数作用域开始；函数外使用绑定
  `use_out → D1`，因为离开函数后内层作用域已弹出。记录“D2 遮蔽 D1”而不是删除
  D1，这样两个结果都能解释。
</Answer>

<Answer>

<GlossaryItem term="引用消解">
  根据作用域、声明类别和源位置，为名字使用找到唯一可见声明的语义过程。
</GlossaryItem>

<GlossaryItem term="作用域栈">
  由当前作用域到外层作用域组成的有序查找链，进入块时压入，离开块时弹出。
</GlossaryItem>

<GlossaryItem term="声明 ID">
  声明在绑定表中的稳定身份，用来连接名字使用与确切声明节点。
</GlossaryItem>

<GlossaryItem term="遮蔽">
  内层声明隐藏外层同名声明的可见性关系，离开内层后外层绑定可以恢复。
</GlossaryItem>

<GlossaryItem term="汇总诊断">
  对重复定义、未定义引用或命名空间错误进行统一收集并决定是否拒绝生成 IR 的结果。
