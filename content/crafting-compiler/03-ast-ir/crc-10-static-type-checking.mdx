## 为什么从“类型规则与转换台”开始

第10章 语义分析（2）静态类型检查沿“resolved AST → type rules → conversions → diagnostics”转换信息。最终进程返回正确值只能证明一条执行路径；类型规则与转换台保存token、AST、绑定、类型、IR、汇编、符号、重定位或加载轨迹中的适用层，让错误停在第一处分叉。

第10章 语义分析（2）静态类型检查固定C♭源码、cbc提交、JDK与JavaCC、GNU as/ld/binutils、IA-32目标、链接参数和运行环境，只改变表达式类别或检查结果。本页交互只移动resolved AST → type rules → conversions → diagnostics中的真实对象和状态，不生成置信、风险或证据分数。

## 来源、版本与独立重写边界

第10章 语义分析（2）静态类型检查以青木峰郎维护的[日文原版完整详细目录](https://i.loveruby.net/ja/stdcompiler/toc.html)限定4部分、22章、86个编号小节、附录和116个正式层级；本站未取得原书正文授权，中文解释、代码、图示、实验和答案均为独立教学重写。

第10章 语义分析（2）静态类型检查用[JavaCC完整语法文档](https://javacc.github.io/javacc/documentation/grammar.html)、[ELF规范](https://refspecs.linuxfoundation.org/elf/elf.pdf)、GNU [readelf](https://sourceware.org/binutils/docs/binutils/readelf.html)、[as](https://sourceware.org/binutils/docs/as/)与[ld](https://sourceware.org/binutils/docs/ld/)文档核对技术事实。原书主线是JavaCC、Linux/IA-32、GNU工具与ELF；现代JDK、x86-64、PIE和新版binutils默认值必须单独记录，不能改写原书时代坐标。
