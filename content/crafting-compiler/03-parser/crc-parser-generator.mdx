## 语法分析生成器的作用

语法分析生成器（如 Yacc/Bison）接收**文法规则**（BNF），自动生成语法分析器代码，将 Token 序列组织成 AST：

```text
文法（BNF） ──生成器──→ 分析表 ──驱动──→ AST
```

## 两种分析策略

| 策略 | 方向 | 代表 | 特点 |
|------|------|------|------|
| LL 分析 | 自顶向下 | 递归下降 / ANTLR | 从根预测产生式向下展开 |
| LR 分析 | 自底向上 | Yacc / Bison | 从叶移进归约向上构建 |

## LL 自顶向下分析

LL 分析从文法起始符号开始，根据**前看符号**预测应使用哪条产生式：

```text
expr → term { ("+"|"-") term }     ← 看 + 选这条
term → factor { ("*"|"/") factor }
factor → NUMBER | "(" expr ")"
```

<Callout type="warning">

LL 分析需**消除左递归**。`E → E + T` 是左递归，LL 无法处理（无限循环），需改写为 `E → T E'`、`E' → + T E' | ε`。

</Callout>

## LR 自底向上分析

LR 分析从输入终结符开始，用**移进-归约**机制向上构建：

```text
动作：
  移进（Shift）：将输入终结符压入栈
  归约（Reduce）：栈顶匹配产生式右部 → 弹出 → 压入左部非终结符
```

### 移进-归约示例

以文法 `T → T * F | F`，`F → id` 解析 `id * id`：

| 步骤 | 动作 | 栈 | 剩余输入 |
|------|------|----|---------|
| 1 | 移进 | `id` | `* id` |
| 2 | 归约 F→id | `F` | `* id` |
| 3 | 归约 T→F | `T` | `* id` |
| 4 | 移进 | `T *` | `id` |
| 5 | 移进 | `T * id` | (空) |
| 6 | 归约 T→T*F | `T` | 接受 |

## 移进-归约冲突

<Callout type="warning">

**移进-归约冲突**：分析器既可移进也可归约，无法确定。常见于运算符优先级未明确的文法。消解方法：声明运算符优先级和结合性——高优先级选移进，同优先级左结合选归约。

</Callout>

## LALR(1)：实用分析器

| 分析器 | 状态数 | 分析能力 | 实用性 |
|--------|--------|---------|--------|
| SLR(1) | 少 | 弱（用全局 Follow 集） | 一般 |
| LALR(1) | 少（= SLR） | 中（精确前看符号） | 强 |
| 规范 LR(1) | 多（最坏指数级） | 强 | 弮 |

<Callout type="tip">

Yacc/Bison 选择 LALR(1) 是因为它在状态数（实用性）和分析能力（表达能力）之间取得最佳平衡——状态表紧凑，能处理大多数实用文法。

</Callout>

## 实战：用 Bison 定义文法

```text
%%
expr : expr '+' term  { $$ = $1 + $3; }
     | term           { $$ = $1; }
     ;
term : term '*' factor { $$ = $1 * $3; }
     | factor          { $$ = $1; }
     ;
factor : NUMBER        { $$ = $1; }
       | '(' expr ')'  { $$ = $2; }
       ;
%%
```

Bison 自动构造 LALR(1) 分析表，生成 C 语言的 `yyparse()` 函数。

<Glossary>

<GlossaryItem term="LL 分析">
自顶向下的语法分析方法，从文法起始符号开始，根据前看符号预测产生式向下推导构建 AST，需消除左递归。
</GlossaryItem>

<GlossaryItem term="LR 分析">
自底向上的语法分析方法，从输入终结符开始，通过移进和归约操作向上构建 AST，能处理左递归，表达能力强。
</GlossaryItem>

<GlossaryItem term="移进-归约（Shift-Reduce）">
LR 分析的核心机制：移进将终结符压入栈，归约将栈顶匹配产生式右部的符号序列替换为左部非终结符。
</GlossaryItem>

<GlossaryItem term="移进-归约冲突">
分析器在某状态既可移进又可归约的歧义情况，通过声明运算符优先级和结合性消解。
</GlossaryItem>

<GlossaryItem term="LALR(1)">
Look-Ahead LR 分析，将规范 LR(1) 中同核心状态合并共享前看符号集，状态数与 SLR 相同但分析更精确，是 Yacc/Bison 使用的分析方法。
</GlossaryItem>

</Glossary>

### 问题 1

LL 分析和 LR 分析的核心区别是什么？各自的特点是什么？

<Answer>

LL分析是自顶向下的分析方法：从文法起始符号开始，根据前看符号预测应使用哪条产生式，向下展开构建AST。特点是需消除左递归，表达能力有限（LL(1)只能看一个前看符号），但实现简单（递归下降）。LR分析是自底向上的分析方法：从输入的终结符开始，逐步移进到栈中，当栈顶匹配某条产生式右部时归约为非终结符，直到归约到起始符号。特点是可以处理左递归，表达能力强（LALR(1)足够实用），但实现复杂。Yacc/Bison是经典的LALR(1)生成器。

</Answer>

### 问题 2

LR 分析的移进-归约机制是什么？以 `id * id` 为例说明完整过程。

<Answer>

移进-归约机制：移进（Shift）将输入终结符压入栈；归约（Reduce）当栈顶符号序列匹配某产生式右部时，弹出这些符号并压入左部非终结符。以文法E→E+T|T, T→T*F|F, F→id解析id*id为例：①移进id ②归约F→id（栈:F）③归约T→F（栈:T）④移进*（栈:T*）⑤移进id（栈:T*id）⑥归约F→id（栈:T*F）⑦归约T→T*F（栈:T）⑧归约E→T（栈:E），接受。整个过程从叶节点向上构建语法树。

</Answer>

### 问题 3

什么是移进-归约冲突？如何消解？

<Answer>

移进-归约冲突：在某状态下，分析器既可以选择移进下一个输入符号，也可以选择按某条产生式归约栈顶，两者都合法，分析器无法确定。常见于含if-then-else（悬空else）或运算符优先级未明确的文法。消解方法：优先级声明——为运算符声明优先级和结合性，当冲突涉及运算符时，高优先级选择移进（如*高于+），同优先级按结合性决定（左结合选归约，右结合选移进）。默认规则——Yacc/Bison默认在冲突时选择移进。归约-归约冲突则按定义顺序选择靠前的，通常说明文法有歧义需修改。

</Answer>

### 问题 4

什么是 LALR(1) 分析？为什么 Yacc/Bison 选择 LALR(1) 而非 SLR(1) 或规范 LR(1)？

<Answer>

LALR(1)（Look-Ahead LR）是一种介于SLR(1)和规范LR(1)之间的分析方法。SLR(1)用文法全局的Follow集做归约判断，过于宽松易产生假冲突。规范LR(1)为每个状态维护精确的前看符号集，状态数庞大不实用。LALR(1)将规范LR(1)中同核心（相同状态转移）的状态合并，共享前看符号集，状态数与SLR(1)相同但归约判断更精确。Yacc/Bison选择LALR(1)是因为它在状态数（实用性）和分析能力（表达能力）之间取得最佳平衡——状态表紧凑，能处理大多数实用文法，且冲突远少于SLR(1)。

</Answer>
