## 语义分析的作用

语法分析只检查代码**结构**是否合法（能不能解析），语义分析检查代码**含义**是否正确（对不对）：

```text
AST（语法正确）  →  语义分析  →  带类型注解的 AST（语义正确）
```

## 符号表

符号表记录程序中所有标识符的声明信息：

| 名字 | 类型 | 作用域 | 内存位置 |
|------|------|--------|---------|
| `x` | int | global | offset 0 |
| `sum` | int | block | offset 16 |
| `add` | int(int,int) | global | code addr |

<Callout type="info">

符号表在语义分析阶段构建，后续代码生成时用于确定变量的地址分配。

</Callout>

## 作用域链

作用域链模拟**词法作用域**的嵌套关系：

```text
全局作用域：x, add
  └── 函数作用域：参数 a, b
        └── 块作用域：局部变量 sum
```

查找变量时从**最内层**作用域开始，逐层向外搜索。内层作用域的变量**遮蔽**外层同名变量。进入作用域时创建新表节点压入链头，退出时弹出。

## 类型检查规则

### 赋值类型匹配

```text
int x = "abc";  ← 类型错误（int ≠ string）
int x = 42;     ← 正确
```

左右类型必须兼容。

### 函数调用签名

```text
add(1, 2)    ← 参数数量和类型匹配
add(1)       ← 参数不足，错误
```

实参数量、类型必须与形参匹配，返回类型参与推导。

<Callout type="warning">

类型检查沿 AST **自底向上**传播类型信息：叶子节点的类型已知（如 NUMBER → int），内部节点根据子节点类型和运算规则推导自身类型。

</Callout>

## 类型推导

类型推导从子表达式或上下文自动推导未知类型，无需全部显式标注：

```text
x = 1 + 2    →  推导 x 为 int（无需显式声明）
```

推导从已知类型出发，沿着 AST 自底向上传播，减少冗余的类型标注。

## 常见语义错误

| 错误类型 | 示例 | 说明 |
|---------|------|------|
| 未声明变量 | `y = 42;`（y 未定义） | 符号表中找不到名字 |
| 重复定义 | `int x; int x;` | 同一作用域内多次声明 |
| 类型不匹配 | `int x = "abc";` | 赋值左右类型不兼容 |
| 参数不匹配 | `add(1)`（需 2 参数） | 实参与形参不符 |
| 作用域错误 | 块外引用局部变量 | 变量在作用域外不可见 |

<Callout type="info">

语法正确的程序仍可能有语义错误。语义分析是编译器发现程序逻辑错误的第一道防线。

</Callout>

<GlossaryItem term="符号表（Symbol Table）">
记录程序中所有标识符声明信息的数据结构，包含名字、类型、作用域、内存位置等，在语义分析阶段构建。
</GlossaryItem>

<GlossaryItem term="作用域链">
模拟词法作用域嵌套关系的数据结构，查找变量时从最内层向外搜索，实现内层变量遮蔽外层同名变量。
</GlossaryItem>

<GlossaryItem term="类型检查（Type Checking）">
验证程序中每个操作的类型兼容性的过程，包括赋值匹配、函数签名匹配、运算符类型约束等。
</GlossaryItem>

<GlossaryItem term="类型推导（Type Inference）">
从子表达式或上下文自动推导未知类型的技术，减少冗余的类型标注，沿 AST 自底向上传播类型信息。
</GlossaryItem>

<GlossaryItem term="语义错误">
程序结构合法（语法正确）但含义不合法的错误，如未声明变量、重复定义、类型不匹配等，在语义分析阶段检测。
</GlossaryItem>

</Glossary>

### 问题 1

语义分析的作用是什么？它与语法分析有什么区别？

<Answer>

语义分析检查程序的语义正确性——语法分析只检查代码结构是否符合文法规则（能不能解析），语义分析检查代码含义是否合法（对不对）。语义分析主要做：构建符号表（记录变量/函数的声明信息）类型检查（确保赋值、运算、函数调用的类型兼容）作用域解析（确定每个名字引用对应哪个声明）语义错误检测（未声明变量、重复定义、类型不匹配等）。语法正确的程序可能语义错误。输出是带类型注解的AST，供IR生成使用。

</Answer>

### 问题 2

符号表是什么？作用域链如何工作？

<Answer>

符号表是记录程序中所有标识符声明信息的数据结构，每条记录包含名字、类型、作用域、内存位置等。作用域链模拟词法作用域的嵌套关系：全局作用域在最外层，函数作用域嵌套其中，块作用域再嵌套一层。查找变量时从最内层作用域开始，逐层向外搜索直到找到匹配的声明。这保证了内层作用域的变量遮蔽外层同名变量。进入一个作用域时创建新表节点压入链头，退出时弹出。符号表在语义分析阶段构建，后续代码生成时用于确定变量的地址分配。

</Answer>

### 问题 3

类型检查的核心规则有哪些？类型推导（Type Inference）解决什么问题？

<Answer>

核心规则：赋值类型匹配——赋值左右类型必须兼容。函数调用签名——实参数量、类型必须与形参匹配，返回类型参与推导。运算符类型——算术运算符要求操作数为数值，比较运算符返回布尔类型。条件表达式——if/while条件必须为布尔类型。类型推导解决需要显式标注所有类型的问题：从子表达式或上下文自动推导未知类型。如x = 1 + 2可推导x为int。推导从已知类型出发，沿着AST自底向上传播类型信息，减少冗余的类型标注。

</Answer>

### 问题 4

常见的语义错误有哪些？它们与语法错误有什么区别？

<Answer>

常见语义错误：未声明变量——使用了符号表中不存在的名字。重复定义——同一作用域内多次声明同名标识符。类型不匹配——如int变量赋值为string。函数参数不匹配——实参数量或类型与声明不符。返回类型错误——函数返回值类型与声明不符。作用域错误——在作用域外引用局部变量。与语法错误的区别：语法错误在语法分析阶段发现，是结构不合法（缺少分号、括号不匹配等）；语义错误在语义分析阶段发现，是结构合法但含义不合法。语法正确的程序仍可能有语义错误。

</Answer>
