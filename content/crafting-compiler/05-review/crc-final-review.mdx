## 端到端流程总览

从源码到可执行文件，编译器经过 9 个阶段，数据形态逐步变换：

```text
源码 → 词法 → 语法 → 语义 → IR生成 → 优化 → 代码生成 → 链接 → 运行
 ch2    ch2    ch3    ch4     ch5     ch6      ch7      ch8
```

## 数据形态变换链

| 阶段 | 输入 → 输出 | 数据形态 |
|------|------------|---------|
| 词法分析 | 源码文本 → Token 序列 | 文本 → 词法单元 |
| 语法分析 | Token → AST | 线性 → 树形结构 |
| 语义分析 | AST → 带注解 AST | 树 + 类型信息 |
| IR 生成 | 带注解 AST → 三地址码 | 树形 → 线性指令 |
| 优化 | 三地址码 → 优化后 IR | 冗余指令 → 精简指令 |
| 代码生成 | IR → 目标指令 | 抽象操作 → 机器指令 |
| 链接 | 目标文件 → 可执行文件 | 可重定位 → 最终地址 |
| 加载 | 可执行文件 → 运行进程 | 磁盘文件 → 内存映像 |

<Callout type="info">

数据形态从人类可读文本逐步变换为机器可执行指令：文本 → Token → AST → IR → 机器码。每次变换都更接近机器、更远离源语言。

</Callout>

## 核心概念串联

| 理论基础 | 支撑阶段 | 核心应用 |
|---------|---------|---------|
| 自动机理论 | 词法分析 | 正则 → NFA → DFA |
| 形式语言理论 | 语法分析 | 文法 → LR 分析 |
| 数据流分析 | 代码优化 | 到达定值 / 活跃变量 |
| 图论 | 寄存器分配 | 干涉图着色 |

## 前端 vs 后端

| 维度 | 前端 | 后端 |
|------|------|------|
| 关注点 | 代码说了什么 | 代码如何高效执行 |
| 阶段 | 词法 + 语法 + 语义 | IR生成 + 优化 + 代码生成 |
| 理论 | 自动机 + 形式语言 | 数据流分析 + 图论 |
| 与源语言 | 紧密相关 | 无关 |
| 与目标机器 | 无关 | 紧密相关 |
| 输出 | 带注解 AST | 目标指令序列 |

<Callout type="tip">

中间表示（IR）是前端与后端的分界线——与源语言和目标机器都无关，使两端独立演进。

</Callout>

## 理论基础一览

```text
词法分析 ← 自动机理论（正则 / DFA）
语法分析 ← 形式语言理论（文法 / LR）
代码优化 ← 数据流分析（格 / 不动点）
寄存器分配 ← 图论（图着色 / NP 完全）
```

### 问题 1

从源码到可执行文件，数据形态经历了哪些变换？每个阶段的输出是什么？

<Answer>

数据形态变换链：源码文本→词法分析→Token序列（源码被分割为带类型的词法单元）Token序列→语法分析→AST（Token按文法规则组织成树形结构）AST→语义分析→带类型注解的AST（每个节点标注类型信息）带注解AST→IR生成→三地址码（树形结构展平为线性指令）三地址码→优化→优化后IR（删除冗余、提升效率）优化后IR→代码生成→目标指令序列（抽象操作映射为机器指令）目标指令序列→目标文件（.o，带重定位信息）目标文件→链接→可执行文件（地址确定、符号绑定）可执行文件→加载→运行中的进程。整个过程从人类可读文本逐步变换为机器可执行指令。

</Answer>

### 问题 2

编译器各阶段依赖哪些理论基础？正则/DFA、文法/LR、数据流分析、图着色分别支撑哪个阶段？

<Answer>

词法分析依赖自动机理论——正则表达式描述Token模式，通过Thompson构造转为NFA，子集构造转为DFA，最终编码为状态转移表驱动词法分析器。语法分析依赖形式语言理论——上下文无关文法（BNF）描述语法结构，LR分析（LALR(1)）基于移进-归约机制和状态转移表解析Token流，生成器（Yacc/Bison）自动构造分析表。代码优化依赖数据流分析——在控制流图（CFG）上传播gen/kill、use/def等信息集合，通过不动点迭代求解到达定值、活跃变量等方程，支撑死代码消除、公共子表达式消除等优化。寄存器分配依赖图论——干涉图的着色问题（NP完全）建模寄存器分配，启发式算法（Chaitin）近似求解。

</Answer>

### 问题 3

编译器的前端和后端各自关注什么？中间表示（IR）为什么是两者的分界线？

<Answer>

前端关注「代码说了什么」——理解源代码的结构和语义。词法分析切分Token，语法分析构建AST，语义分析检查类型和作用域，输出带注解的AST。前端与源语言紧密相关，与目标机器无关。后端关注「代码如何高效执行」——生成和优化目标代码。IR生成将AST展平为线性指令，优化删除冗余提升效率，代码生成分配寄存器选择指令，链接合并目标文件。后端与目标机器紧密相关，与源语言无关。IR是分界线因为它与两者都无关——IR是机器无关的抽象指令表示，前端只需将源码翻译到IR，后端只需从IR生成目标代码，两端通过IR解耦独立演进。

</Answer>

### 问题 4

如果让你设计一门新语言并实现编译器，你会如何组织编译器的 Pass 流水线？各 Pass 的输入输出是什么？

<Answer>

Pass流水线设计：Pass 1（词法）——输入源码文本，输出Token流。Pass 2（语法）——输入Token流，输出AST。Pass 3（语义）——输入AST，输出带类型注解的AST+符号表。Pass 4（IR生成）——输入带注解AST，输出三地址码IR。Pass 5（IR规范化）——输入TAC，输出SSA形式IR。Pass 6-N（优化Pass序列）——每个Pass输入输出均为SSA IR，包括常量传播、死代码消除、公共子表达式消除、循环不变量外提、强度削弱等，迭代到不动点。Pass N+1（代码生成）——输入优化后SSA IR，输出目标指令序列（指令选择+寄存器分配+指令调度）。链接——输入目标文件+库，输出可执行文件。每个Pass职责单一、可独立测试和替换，通过IR串联。

</Answer>
