## 为什么从“ELF可重定位对象台”开始

第18章 生成目标文件沿“sections → symbols → relocations → object file”转换信息。最终进程返回正确值只能证明一条执行路径；ELF可重定位对象台保存token、AST、绑定、类型、IR、汇编、符号、重定位或加载轨迹中的适用层，让错误停在第一处分叉。

第18章 生成目标文件固定C♭源码、cbc提交、JDK与JavaCC、GNU as/ld/binutils、IA-32目标、链接参数和运行环境，只改变ELF视图或全局对象。本页交互只移动sections → symbols → relocations → object file中的真实对象和状态，不生成置信、风险或证据分数。

## 来源、版本与独立重写边界

第18章 生成目标文件以青木峰郎维护的[日文原版完整详细目录](https://i.loveruby.net/ja/stdcompiler/toc.html)限定4部分、22章、86个编号小节、附录和116个正式层级；本站未取得原书正文授权，中文解释、代码、图示、实验和答案均为独立教学重写。

第18章 生成目标文件用[JavaCC完整语法文档](https://javacc.github.io/javacc/documentation/grammar.html)、[ELF规范](https://refspecs.linuxfoundation.org/elf/elf.pdf)、GNU [readelf](https://sourceware.org/binutils/docs/binutils/readelf.html)、[as](https://sourceware.org/binutils/docs/as/)与[ld](https://sourceware.org/binutils/docs/ld/)文档核对技术事实。原书主线是JavaCC、Linux/IA-32、GNU工具与ELF；现代JDK、x86-64、PIE和新版binutils默认值必须单独记录，不能改写原书时代坐标。

第18章 生成目标文件的通过不变量是“节、符号绑定、大小和重定位引用相互一致并可由工具交叉解析”。实验档案保存源码与期望、cbc提交、工具版本、目标ABI、命令与退出码、所有适用中间产物、标准错误、第一处分叉、清理记录和回归结果。

```bash
readelf -h -S -s -r sample.o
objdump -drwC sample.o
nm -n sample.o
```

<Callout type="warning" title="历史IA-32工具链必须隔离">
  第18章
  生成目标文件涉及旧JDK、旧JavaCC、32位链接器、任意目标文件或加载器变量时，在容器或离线虚拟机中运行；固定资源与超时，禁止执行不可信二进制，先检查ELF架构、入口和依赖。
</Callout>

## 三个必须主动触发的误区

<Callout type="trap" title="中间产物不能省略">
  第18章
  生成目标文件不允许用最终返回值平均掉token、AST、绑定、类型、IR、汇编或ELF层失败；缺少适用中间证据即退回。
</Callout>

<Callout type="trap" title="章专属失败样本">
  第18章
  生成目标文件主动触发“目标文件节与可执行文件段不是同一概念”，再注入“把节文件偏移当成运行地址或提前写死未解析地址”。若节/符号/重定位交叉引用没有变化，先验证阳性对照和采集链，不能复用旧构建。
</Callout>

<Callout type="trap" title="机制与现代默认值分开">
  第18章
  生成目标文件的IA-32、非PIE或旧工具行为必须显式冻结；x86-64、PIE、不同JavaCC/JDK和binutils版本的结果只能作为带版本的对照。
</Callout>
