## 为什么从“GOT/PLT与PIC台”开始

第21章 生成地址无关代码沿“PIC reference → GOT/PLT → relocation → runtime address”转换信息。最终进程返回正确值只能证明一条执行路径；GOT/PLT与PIC台保存token、AST、绑定、类型、IR、汇编、符号、重定位或加载轨迹中的适用层，让错误停在第一处分叉。

第21章 生成地址无关代码固定C♭源码、cbc提交、JDK与JavaCC、GNU as/ld/binutils、IA-32目标、链接参数和运行环境，只改变引用对象或装载地址。本页交互只移动PIC reference → GOT/PLT → relocation → runtime address中的真实对象和状态，不生成置信、风险或证据分数。

## 来源、版本与独立重写边界

第21章 生成地址无关代码以青木峰郎维护的[日文原版完整详细目录](https://i.loveruby.net/ja/stdcompiler/toc.html)限定4部分、22章、86个编号小节、附录和116个正式层级；本站未取得原书正文授权，中文解释、代码、图示、实验和答案均为独立教学重写。

第21章 生成地址无关代码用[JavaCC完整语法文档](https://javacc.github.io/javacc/documentation/grammar.html)、[ELF规范](https://refspecs.linuxfoundation.org/elf/elf.pdf)、GNU [readelf](https://sourceware.org/binutils/docs/binutils/readelf.html)、[as](https://sourceware.org/binutils/docs/as/)与[ld](https://sourceware.org/binutils/docs/ld/)文档核对技术事实。原书主线是JavaCC、Linux/IA-32、GNU工具与ELF；现代JDK、x86-64、PIE和新版binutils默认值必须单独记录，不能改写原书时代坐标。

## 三个必须主动触发的误区

<Callout type="trap" title="中间产物不能省略">
  第21章
  生成地址无关代码不允许用最终返回值平均掉token、AST、绑定、类型、IR、汇编或ELF层失败；缺少适用中间证据即退回。
</Callout>

<Callout type="trap" title="章专属失败样本">
  第21章
  生成地址无关代码主动触发“PIE、PIC和共享库不是同一发布形态”，再注入“在代码段写绝对地址或把某次装载地址固化进结果”。若重定位类型、GOT/PLT项与绑定轨迹没有变化，先验证阳性对照和采集链，不能复用旧构建。
</Callout>

<Callout type="trap" title="机制与现代默认值分开">
  第21章
  生成地址无关代码的IA-32、非PIE或旧工具行为必须显式冻结；x86-64、PIE、不同JavaCC/JDK和binutils版本的结果只能作为带版本的对照。
</Callout>
