## 链接与加载的作用

编译器生成的目标文件（.o）是**可重定位**的——各段地址从 0 开始，符号引用尚未绑定。链接器将其合并为可执行文件，加载器将其装入内存运行：

```text
目标文件（.o）  →  链接器  →  可执行文件  →  加载器  →  运行
```

## 目标文件结构（ELF）

ELF（Executable and Linkable Format）目标文件包含：

| 段 | 内容 | 说明 |
|---|------|------|
| ELF Header | 文件类型、架构等元信息 | 文件头 |
| .text | 编译后的机器代码 | 代码段 |
| .data | 已初始化的全局/静态变量 | 数据段 |
| .bss | 未初始化的全局/静态变量 | 仅记录大小，不占文件空间 |
| .symtab | 符号表 | 记录定义和引用的符号 |
| .rel.text | 重定位表 | 代码段中待修正的地址 |

<Callout type="info">

符号表记录导出/引用的名字，重定位表记录待修正地址。编译器生成目标文件时各段地址从 0 开始（可重定位），链接器赋最终地址。

</Callout>

## 链接器两步工作

### 步骤 1：符号解析

合并所有目标文件的符号表，将每个符号**引用**绑定到其**定义**：

```text
main.o:  定义 main, 引用 printf
lib.o:   定义 printf
→ 链接后: main 引用的 printf 绑定到 lib.o 中的定义
```

<Callout type="warning">

若有**未定义符号**（引用了但没有任何文件定义），则报链接错误。

</Callout>

### 步骤 2：重定位

合并各目标文件的代码段和数据段到统一地址空间，按重定位表**修正地址**：

```text
main.o 中 call printf 的地址字段 = 0（待修正）
→ 链接器合并后 printf 在 0x401000
→ 修正为 call 0x401000
```

## 静态链接 vs 动态链接

| 对比 | 静态链接 | 动态链接 |
|------|---------|---------|
| 时机 | 编译链接时拷贝库代码 | 运行时加载共享库 |
| 文件体积 | 大（含库代码） | 小（只记录依赖） |
| 内存占用 | 每程序各存一份 | 多进程共享一份 |
| 启动速度 | 快（无运行时绑定） | 稍慢（需加载绑定） |
| 库更新 | 需重新链接 | 替换 .so 即可 |
| 运行依赖 | 无 | 需正确的库版本 |

<Callout type="tip">

现代系统默认动态链接。静态链接用于需要自包含部署的场景（如嵌入式、容器镜像）。

</Callout>

## 加载器工作流程

```text
1. 读取可执行文件头 → 获取各段信息
2. 分配虚拟地址空间
3. 映射 .text/.data 段到虚拟内存（.bss 零填充）
4. 加载动态链接依赖（如有）
5. 分配并初始化栈（参数、环境变量）
6. 跳转入口地址（_start → main）
```

<Callout type="info">

现代操作系统用 **mmap 按需分页**——段先建立虚拟映射，实际访问时才按页从磁盘加载，加速启动。

</Callout>

<Glossary>

<GlossaryItem term="链接器（Linker）">
将多个目标文件和库文件合并为可执行文件的程序，核心工作为符号解析（绑定引用到定义）和重定位（修正最终地址）。
</GlossaryItem>

<GlossaryItem term="符号解析（Symbol Resolution）">
链接器合并各目标文件的符号表，将每个符号引用绑定到其定义的过程，未定义符号会导致链接错误。
</GlossaryItem>

<GlossaryItem term="重定位（Relocation）">
链接器合并代码/数据段后，根据重定位表修正每条符号引用的地址为最终运行地址的过程。
</GlossaryItem>

<GlossaryItem term="静态链接">
在编译链接时将库代码完整拷贝到可执行文件中的链接方式，自包含但体积大、更新不便。
</GlossaryItem>

<GlossaryItem term="动态链接">
链接时只记录对共享库的依赖，运行时才加载共享库并绑定符号的链接方式，多进程共享、体积小。
</GlossaryItem>

<GlossaryItem term="加载器（Loader）">
将可执行文件装入内存并启动运行的系统程序，负责映射段、分配栈、跳转入口地址。
</GlossaryItem>

</Glossary>

### 问题 1

链接器的作用是什么？它的两步核心工作是什么？

<Answer>

链接器将多个目标文件（.o）和库文件合并为一个可执行文件。两步核心工作：符号解析——合并所有目标文件的符号表，将每个符号引用绑定到其定义。目标文件中的符号分定义（在本文件中有实现）和引用（在其他文件中定义），链接器跨文件匹配同名符号。若有未定义符号（引用了但没有任何文件定义）则报链接错误。重定位——合并各目标文件的代码段和数据段到统一的地址空间，根据重定位表修正每条引用符号的地址为最终运行地址。编译器生成目标文件时各段地址从0开始（可重定位），链接器赋最终地址。

</Answer>

### 问题 2

目标文件（ELF）的结构是什么？符号表和重定位表各自的作用是什么？

<Answer>

ELF目标文件结构：ELF Header——文件类型、目标架构等元信息。.text——编译后的机器代码段。.data——已初始化的全局/静态变量。.bss——未初始化的全局/静态变量（仅记录大小，不占文件空间）。.symtab（符号表）——记录本文件定义和引用的所有符号（函数、全局变量），标注每个符号是定义还是未定义、所在段和偏移。.rel.text/.rel.data（重定位表）——记录代码段/数据段中哪些位置有需要修正的符号引用，以及修正方式。符号表让链接器知道每个名字的定义在哪，重定位表让链接器知道哪些指令的地址字段需要修正。

</Answer>

### 问题 3

静态链接和动态链接的区别是什么？各有什么优缺点？

<Answer>

静态链接：在编译链接时将库的代码完整拷贝到可执行文件中。优点是可执行文件自包含、运行时无依赖、启动快。缺点是文件体积大、多个程序各自拷贝同一份库浪费内存、库更新需重新链接所有程序。动态链接：链接时只记录对共享库（.so/.dll）的依赖，运行时加载器才将共享库加载到内存并绑定符号。优点是可执行文件体积小、多进程共享同一份库代码节省内存、库更新无需重新链接程序。缺点是运行时有加载和符号绑定开销、依赖运行环境有正确的库版本。现代系统默认动态链接，静态链接用于需要自包含部署的场景。

</Answer>

### 问题 4

加载器（Loader）的工作流程是什么？程序从可执行文件到运行需要经过哪些步骤？

<Answer>

加载器在用户执行程序时将可执行文件装入内存并启动运行。工作流程：读取可执行文件头，获取各段信息（大小、虚拟地址、文件偏移）为新进程分配虚拟地址空间将.text、.data等段从文件映射到虚拟内存（.bss分配零填充内存，不读文件）加载动态链接依赖（如有），解析动态符号分配并初始化栈（压入命令行参数、环境变量）设置程序计数器（PC）为入口地址（_start→main），跳转执行。此后CPU从main开始执行指令，程序正式运行。现代操作系统用mmap做按需分页——段先建立虚拟映射，实际访问时才按页从磁盘加载。

</Answer>
