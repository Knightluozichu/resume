## 直觉引入

Android系统像一座「四层蛋糕」。最底层是Linux内核（地基，管硬件驱动和进程），往上是C/C++库和Android运行时（水电煤基础设施），再往上是Application Framework（框架层，提供ActivityManager/WindowManager等系统服务API），最顶层是Applications（应用层，你写的App和系统自带App）。开发者大部分时间在顶层用Java写App，通过调用框架层API间接使用底层能力。

## 四层架构详解

```text
层级                         核心内容                          开发者关系
──────────────────────────────────────────────────────────────────────────
Applications（应用层）        用户App / 系统App                  ← 直接在这里写代码
Application Framework         ActivityManager / WindowManager    ← 调用这些API
（框架层）                    ContentProvider / View System
                              NotificationManager / PackageManager
Libraries + Runtime           SQLite / OpenGL ES / WebKit        ← 间接使用
                              Dalvik/ART虚拟机 / 核心Java库
Linux Kernel（内核层）        驱动 / 进程管理 / 电源 / Binder IPC   ← 通常不直接操作
```

## 项目结构

```text
MyApp/
  app/
    src/main/
      java/com/pkg/          ← Java源码（Activity/Service等）
        MainActivity.java
      res/                   ← 资源目录
        layout/              ← XML布局（activity_main.xml）
        values/              ← strings.xml / colors.xml / styles.xml
        drawable/            ← 图片和矢量图
        mipmap/              ← 应用图标
      AndroidManifest.xml    ← 清单文件（全局配置）
      assets/                ← 原始资源（原样打包）
    build.gradle             ← Gradle构建配置（依赖/编译/签名）
  settings.gradle            ← 模块声明
```

<Callout type="insight">
**AndroidManifest是应用的全局配置中心**：四大组件（Activity/Service/Receiver/Provider）必须在此注册，未注册的组件运行时找不到（ActivityNotFoundException）。权限声明（`uses-permission`）、最低SDK版本、应用图标主题都在这里配置。
</Callout>

## AndroidManifest核心结构

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.example.myapp">

    <uses-permission android:name="android.permission.INTERNET" />

    <application
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/AppTheme">

        <activity android:name=".MainActivity">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
    </application>
</manifest>
```

## LogCat日志系统

```java
// 五个日志级别（从低到高）
Log.v("TAG", "详细信息");    // VERBOSE — 最详细，开发排查
Log.d("TAG", "调试信息");    // DEBUG   — 开发期最常用
Log.i("TAG", "状态信息");    // INFO    — 重要状态变化
Log.w("TAG", "警告信息");    // WARN    — 潜在问题
Log.e("TAG", "错误信息");    // ERROR   — 严重错误
```

<Callout type="trap">
**常见坑**：Activity忘记在AndroidManifest注册 → 运行时报ActivityNotFoundException。日志tag用类名而非随意字符串，便于LogCat过滤定位。
</Callout>

## 开发流程

```text
1.建项目（AS向导/Gradle）→ 2.写界面（XML布局+控件）→ 3.写逻辑（Activity/事件）
→ 4.注册（清单文件声明）→ 5.运行（模拟器/真机）
```

<Exercises>
**问题 1**：Android项目结构中各核心目录和文件的作用是什么？

<Answer>
核心结构：①src/main/java/——Java源码目录，存放Activity/Service等组件类。②src/main/res/——资源目录：layout/存XML布局、values/存字符串颜色尺寸样式、drawable/存图片、mipmap/存图标。③AndroidManifest.xml——清单文件，声明包名、四大组件、权限、SDK版本，是应用全局配置中心。④assets/——原始资源，通过AssetManager访问。⑤build.gradle——Gradle构建配置，声明依赖库和编译版本。每个组件必须在AndroidManifest注册，否则运行时找不到。
</Answer>

**问题 2**：AndroidManifest.xml清单文件的核心作用和必须声明的内容有哪些？

<Answer>
核心作用：①声明包名——应用唯一标识。②注册四大组件——每个Activity/Service/Receiver/Provider必须在此声明（`<activity>`/`<service>`/`<receiver>`/`<provider>`标签），未注册无法启动。③声明权限——`<uses-permission>`声明所需权限（INTERNET/CAMERA等）。④声明SDK版本——`<uses-sdk minSdkVersion>`。⑤声明应用图标主题——`<application>`的icon/label/theme。⑥声明Intent Filter——组件的`<intent-filter>`定义能响应的隐式Intent（MAIN+LAUNCHER标记启动Activity）。清单在打包时编译进APK，系统安装和运行时都依赖它。
</Answer>

**问题 3**：Android的LogCat日志系统有哪几个级别？各自的使用场景是什么？

<Answer>
5个级别（从低到高）：①Log.v——VERBOSE详细，开发排查用。②Log.d——DEBUG调试，开发期最常用，记录运行状态。③Log.i——INFO信息，重要状态变化（登录成功、网络连接），一般保留到发布版。④Log.w——WARN警告，有潜在问题但不影响运行（网络重试、缓存失效）。⑤Log.e——ERROR错误，严重错误（异常捕获、API失败），通常伴随功能不可用。tag参数用于过滤标识，通常用类名。DDMS提供线程/堆/文件浏览等更丰富的调试视图。
</Answer>

**问题 4**：从零创建一个Android应用，从建项目到运行需要经过哪些步骤？每步的关键点是什么？

<Answer>
①创建项目——AS向导选Empty Activity模板，填应用名/包名/最低SDK。关键：包名是唯一标识不可改，minSdkVersion决定兼容范围。②编写界面——在res/layout/下创建XML布局，用布局管理器组织控件。关键：控件需设layout_width/layout_height，用@string引用strings.xml。③编写逻辑——创建Activity继承AppCompatActivity，onCreate中setContentView载入布局，findViewById获取控件。④注册组件——在AndroidManifest的`<activity>`声明，启动Activity需MAIN+LAUNCHER的intent-filter。关键：未注册无法启动。⑤运行——选模拟器或真机（USB调试），Gradle编译打包APK安装。关键：真机调试更快。
</Answer>

<Glossary>
<GlossaryItem term="四层架构">Applications（应用层）/ Application Framework（框架层）/ Libraries + Android Runtime（库与运行时）/ Linux Kernel（内核层）。开发者主要在应用层写代码，调用框架层API。</GlossaryItem>
<GlossaryItem term="AndroidManifest">清单文件，应用全局配置中心。声明包名、注册四大组件、声明权限、配置SDK版本和应用图标主题。未注册的组件无法启动。</GlossaryItem>
<GlossaryItem term="LogCat">Android日志系统，5个级别（v/d/i/w/e）。通过ADB或Android Studio实时查看。tag用于过滤标识。</GlossaryItem>
<GlossaryItem term="DDMS">Dalvik Debug Monitor Service，提供线程/堆/文件浏览等调试视图。</GlossaryItem>
<GlossaryItem term="Gradle">Android项目构建工具，build.gradle声明依赖库、编译版本、签名配置。</GlossaryItem>
</Glossary>
