## 直觉引入

事件处理像「前台接待」。基于监听是「前台安了一个门铃按钮，有人按就响」（View注册监听器，事件触发时回调）。基于回调是「前台自己盯着门口，有人来就处理」（View子类重写回调方法，事件在自身方法内处理）。Handler是「对讲机」——子线程在后台干活，干完了用对讲机通知前台（主线程）更新界面。

## 两种事件处理模型

```text
基于监听（最常用）：
  EventSource（Button）→ 触发Event → 传递给EventListener → 回调onClick()
  特点：外部注册观察者，不继承View即可处理事件

基于回调（自定义View常用）：
  继承View子类 → 重写onKeyDown/onTouchEvent → 事件在View自身处理
  特点：事件处理与View定义内聚，返回true消费事件
```

## 基于监听的代码示例

```java
// 方式1：匿名内部类
button.setOnClickListener(new View.OnClickListener() {
    @Override
    public void onClick(View v) {
        // 处理点击
    }
});

// 方式2：Activity实现接口
public class MainActivity extends AppCompatActivity
        implements View.OnClickListener {
    @Override
    public void onClick(View v) {
        if (v.getId() == R.id.button) { /* 处理 */ }
    }
}
button.setOnClickListener(this);
```

## 触摸事件与手势检测

```java
// 触摸事件三阶段
@Override
public boolean onTouchEvent(MotionEvent event) {
    switch (event.getAction()) {
        case MotionEvent.ACTION_DOWN:  // 按下
            break;
        case MotionEvent.ACTION_MOVE:  // 移动
            break;
        case MotionEvent.ACTION_UP:    // 抬起
            break;
    }
    return true;  // true消费事件
}

// GestureDetector检测手势
GestureDetector detector = new GestureDetector(this,
    new GestureDetector.SimpleOnGestureListener() {
        @Override public boolean onSingleTapUp(MotionEvent e) { /* 单击 */ return true; }
        @Override public boolean onDoubleTap(MotionEvent e) { /* 双击 */ return true; }
        @Override public void onLongPress(MotionEvent e) { /* 长按 */ }
        @Override public boolean onFling(MotionEvent e1, MotionEvent e2,
                float velocityX, float velocityY) { /* 快速滑动 */ return true; }
        @Override public boolean onScroll(MotionEvent e1, MotionEvent e2,
                float distanceX, float distanceY) { /* 拖动 */ return true; }
    });
// 在onTouchEvent中委托给GestureDetector
detector.onTouchEvent(event);
```

## Handler异步消息机制

```text
子线程                          主线程
  │                               │
  │ sendMessage(msg)              │
  │──────────────────────────────→│ MessageQueue入队
  │                               │ Looper.loop()轮询取出
  │                               │ 分发给Handler
  │                               │ handleMessage(msg)回调
  │                               │ 更新UI ←───────┘
```

```java
// 子线程发送消息，主线程处理
Handler handler = new Handler(Looper.getMainLooper()) {
    @Override
    public void handleMessage(Message msg) {
        // 在主线程更新UI
        textView.setText((String) msg.obj);
    }
};

new Thread(() -> {
    // 子线程执行耗时操作
    String result = doNetworkRequest();
    // 发送消息到主线程
    Message msg = handler.obtainMessage();
    msg.obj = result;
    handler.sendMessage(msg);
}).start();
```

<Callout type="trap">
**ANR成因**：主线程做了耗时操作（网络请求/数据库/大文件IO/大量计算）→ 阻塞UI线程 → 界面卡顿无响应 → 超过5秒触发ANR弹窗 → 应用被强制关闭。Android 4.0+主线程网络请求直接抛NetworkOnMainThreadException。解决方案：耗时操作放子线程，完成后用Handler/post/runOnUiThread切回主线程更新UI。
</Callout>

<Exercises>
**问题 1**：Android基于监听的事件处理模型包含哪几个核心角色？工作流程是什么？

<Answer>
四个核心角色：①EventSource（事件源）——产生事件的GUI组件（Button/EditText）。②Event（事件对象）——封装事件信息（MotionEvent含坐标和动作、KeyEvent含键码）。③EventListener（事件监听器）——接口，定义回调方法（OnClickListener.onClick、OnTouchListener.onTouch）。④工作流程：事件源触发后创建Event对象，传递给已注册的EventListener，回调方法中编写业务逻辑。注册方式：button.setOnClickListener。也可Activity实现接口然后setOnClickListener(this)。基于监听是最常用的事件处理方式。
</Answer>

**问题 2**：基于监听和基于回调两种事件处理模型有什么区别？各自适合什么场景？

<Answer>
基于监听：在Activity或外部类创建监听器，通过setOnClickListener注册到事件源。事件触发时由监听器回调处理。优点：不继承View即可处理事件，灵活通用。适合Button点击、EditText文本变化等标准控件交互。基于回调：继承View子类，重写onKeyDown/onTouchEvent等方法。事件触发时先调用View自身回调，返回true消费事件。优点：事件处理与View定义内聚。适合自定义View内部处理触摸/按键。区别：监听是「外部注册观察者」，回调是「内部重写方法」。实践中常结合使用——自定义View用回调处理底层触摸绘制，Activity用监听处理业务点击。
</Answer>

**问题 3**：Handler异步消息处理机制的工作原理是什么？为什么Android规定主线程不能做耗时操作？

<Answer>
Handler机制：①子线程创建Message，通过Handler.sendMessage发送。②消息放入Handler关联的MessageQueue（按时间排序）。③Looper不断循环调用MessageQueue.next()取出消息。④Looper将Message分发给创建它的Handler的handleMessage方法。⑤handleMessage在Handler所在线程（通常主线程）执行，更新UI。主线程默认已有Looper和MessageQueue，子线程需Looper.prepare()+loop()。Android规定主线程不能做耗时操作：①主线程负责UI渲染和事件分发，被阻塞导致卡顿。②超5秒无响应触发ANR，应用被强制关闭。③网络请求在主线程直接抛NetworkOnMainThreadException。解决：耗时操作放子线程，完成后用Handler/post或AsyncTask切回主线程更新UI。
</Answer>

**问题 4**：如何实现Android手势检测？GestureDetector和VelocityTracker各自的作用是什么？

<Answer>
组合使用GestureDetector和VelocityTracker：①GestureDetector——检测常见手势。创建new GestureDetector(context, new SimpleOnGestureListener())，重写onSingleTapUp（单击）、onDoubleTap（双击）、onLongPress（长按）、onScroll（拖动）、onFling（快速滑动，含起点终点和速度）。在onTouchEvent中调用gestureDetector.onTouchEvent(event)将触摸事件交给它分析。②VelocityTracker——追踪滑动速度。ACTION_DOWN时obtain()获取，ACTION_MOVE时addMovement(event)记录轨迹，computeCurrentVelocity(units)后用getXVelocity()/getYVelocity()获取速度。用于判断快速滑动方向和力度。③onTouchEvent中通过event.getAction()判断ACTION_DOWN/MOVE/UP三阶段。典型应用：图片浏览器翻页、列表快速滑动。
</Answer>

<Glossary>
<GlossaryItem term="基于监听">外部注册监听器到事件源View，事件触发时由监听器回调处理。最常用的事件处理方式，适合标准控件交互。</GlossaryItem>
<GlossaryItem term="基于回调">继承View子类重写onKeyDown/onTouchEvent等方法，事件在View自身方法内处理，返回true消费。适合自定义View。</GlossaryItem>
<GlossaryItem term="Handler">异步消息处理机制。子线程sendMessage → MessageQueue入队 → Looper轮询取出 → handleMessage在主线程回调。用于子线程到主线程通信和UI更新。</GlossaryItem>
<GlossaryItem term="ANR">Application Not Responding，主线程阻塞超5秒触发，应用被强制关闭。避免方法：耗时操作放子线程。</GlossaryItem>
<GlossaryItem term="GestureDetector">手势检测器，识别单击/双击/长按/滑动/快速滑动等手势。在onTouchEvent中委托给它分析。</GlossaryItem>
</Glossary>
