## 直觉引入

数据持久化像「不同容量的收纳工具」。SharedPreferences是「小储物柜」——放钥匙扣、钱包等少量常用物品（用户设置、登录状态）。文件IO是「纸箱」——放各种杂七杂八的东西（缓存文件、日志、图片）。SQLite是「档案库」——有条理地存放大量结构化资料，可按条件检索（用户记录、聊天消息）。ContentProvider是「公共资料室」——不同部门（不同App）可以共享访问同一批资料（通讯录、媒体库）。

## 五大方案对比

```text
方案                  存储方式          适用场景              底层实现
────────────────────────────────────────────────────────────────────
SharedPreferences     键值对            少量配置/设置          XML文件
文件IO                原始文件          缓存/图片/日志          内部/外部存储
SQLite                结构化数据        大量数据/查询/事务      .db文件
ContentProvider       跨应用共享        通讯录/媒体库           封装SQLite
CursorAdapter         数据+列表         SQLite数据绑定ListView  Cursor→Adapter
```

## SharedPreferences

```java
// 写入
SharedPreferences sp = getSharedPreferences("config", MODE_PRIVATE);
SharedPreferences.Editor editor = sp.edit();
editor.putString("username", "admin");
editor.putBoolean("loggedIn", true);
editor.putInt("age", 25);
editor.commit();    // 同步提交（阻塞）
// editor.apply();  // 异步提交（推荐）

// 读取
String username = sp.getString("username", "默认值");
boolean loggedIn = sp.getBoolean("loggedIn", false);
```

## 文件IO存储

```java
// 内部存储（私有，卸载自动删除）
FileOutputStream fos = openFileOutput("data.txt", MODE_PRIVATE);
fos.write("content".getBytes());
fos.close();

FileInputStream fis = openFileInput("data.txt");
BufferedReader reader = new BufferedReader(new InputStreamReader(fis));
String line = reader.readLine();

// 外部存储（需权限 + 检查可用性）
if (Environment.getExternalStorageState().equals(Environment.MEDIA_MOUNTED)) {
    File file = new File(Environment.getExternalStorageDirectory(), "file.txt");
    FileOutputStream fos = new FileOutputStream(file);
    fos.write("content".getBytes());
}
```

## SQLite数据库操作

```java
// 1. 继承SQLiteOpenHelper
public class MyDBHelper extends SQLiteOpenHelper {
    public MyDBHelper(Context context) {
        super(context, "my.db", null, 1);  // 版本号
    }

    @Override
    public void onCreate(SQLiteDatabase db) {
        // 首次创建时建表
        db.execSQL("CREATE TABLE user (" +
            "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
            "name TEXT, age INTEGER)");
    }

    @Override
    public void onUpgrade(SQLiteDatabase db, int oldVersion, int newVersion) {
        // 版本升级时迁移
        db.execSQL("ALTER TABLE user ADD COLUMN email TEXT");
    }
}

// 2. 增删改查
SQLiteDatabase db = helper.getWritableDatabase();

// 增（用?占位符防注入）
db.execSQL("INSERT INTO user(name, age) VALUES(?, ?)",
    new Object[]{"张三", 25});

// 查
Cursor cursor = db.rawQuery("SELECT * FROM user WHERE age > ?",
    new String[]{"20"});
while (cursor.moveToNext()) {
    String name = cursor.getString(cursor.getColumnIndex("name"));
    int age = cursor.getInt(cursor.getColumnIndex("age"));
}
cursor.close();

// 3. 事务（批量操作原子性）
db.beginTransaction();
try {
    db.execSQL("INSERT INTO user(name) VALUES(?)", new Object[]{"A"});
    db.execSQL("INSERT INTO user(name) VALUES(?)", new Object[]{"B"});
    db.setTransactionSuccessful();  // 标记成功
} finally {
    db.endTransaction();  // 结束事务（成功才提交）
}
```

<Callout type="trap">
**SQL注入风险**：拼接SQL字符串（`"WHERE name='" + input + "'"`）可被注入。始终用`?`占位符 + 参数数组，让SQLite自动转义。绝不拼接SQL。
</Callout>

## ContentProvider跨应用共享

```text
数据提供方App                          数据访问方App
  ContentProvider                        ContentResolver
    query/insert/update/delete            ↓
    getType/call                        content://authority/path/id
         ↑                                    │
    UriMatcher匹配Uri                       │
    ContentObserver通知变化  ←─────────────────┘
```

<Callout type="insight">
**Uri结构**：`content://authority/path/id`。scheme固定content://，authority是注册的唯一标识，path标识数据表（如/user），id可选标识具体记录（如/user/1）。UriMatcher匹配不同Uri路径返回不同code区分操作类型。
</Callout>

## 选型决策

```text
少量键值对 → SharedPreferences
文件/图片 → 文件IO
大量结构化 → SQLite
跨App共享 → ContentProvider
数据+列表展示 → SQLite + CursorAdapter
```

<Exercises>
**问题 1**：Android数据持久化有哪些方案？各自的适用场景是什么？

<Answer>
五大方案：①SharedPreferences——键值对XML存储，适合少量配置（设置/登录状态）。②文件IO——openFileInput/Output内部存储或getExternalStorage外部存储，适合缓存/图片/日志。③SQLite——SQLiteOpenHelper管理创建升级，execSQL/rawQuery操作，适合大量结构化数据（用户记录/聊天消息），支持事务和查询。④ContentProvider——跨应用共享，query/insert/update/delete统一接口+Uri标识，适合通讯录/媒体库。⑤CursorAdapter——SQLite查询Cursor直接绑定ListView。选型：少量用SP，文件用IO，结构化用SQLite，跨App用ContentProvider。
</Answer>

**问题 2**：SQLiteOpenHelper的工作原理是什么？onCreate和onUpgrade分别在什么时候调用？

<Answer>
SQLiteOpenHelper管理数据库创建和版本升级。①构造函数传入context/数据库名/version。②首次getReadableDatabase/getWritableDatabase时检测数据库文件——不存在则调onCreate(db)执行建表SQL。③数据库已存在但version增大则调onUpgrade(db, old, new)执行ALTER TABLE迁移。④version不变则直接返回db实例。⑤getReadableDatabase只读（磁盘满降级），getWritableDatabase可读写（满抛异常）。onCreate只首次创建调一次，onUpgrade版本增大时调。升级应增量迁移（ALTER加列），不DROP重建（丢数据）。
</Answer>

**问题 3**：如何使用SQLite进行增删改查操作？如何防止SQL注入？事务的作用是什么？

<Answer>
增删改查：①增——execSQL("INSERT INTO t(c) VALUES(?)", new Object[]&#123;v&#125;)或insert(table, null, contentValues)。②删——execSQL("DELETE FROM t WHERE id=?", new Object[]&#123;id&#125;)或delete(table, "id=?", new String[]&#123;id&#125;)。③改——execSQL("UPDATE t SET c=? WHERE id=?", ...)或update。④查——rawQuery("SELECT * FROM t WHERE c=?", new String[]&#123;v&#125;)返回Cursor，moveToNext遍历，getString/getInt取值。防注入：始终用?占位符+参数数组，绝不拼接SQL。事务：beginTransaction→操作→setTransactionSuccessful→endTransaction（try-finally）。保证原子性——全部成功才提交，任一失败回滚。批量操作用事务大幅提升性能（减少磁盘IO）。
</Answer>

**问题 4**：ContentProvider如何实现跨应用数据共享？Uri的结构是什么？

<Answer>
实现：①数据提供方创建ContentProvider子类，重写query/insert/update/delete/getType/call六个方法。②AndroidManifest用`<provider authorities>`注册。③数据访问方通过ContentResolver（getContentResolver()）调用CRUD，传入Uri指定数据。Uri结构：content://authority/path/id——scheme固定content://，authority对应注册值，path标识表（/user），id可选标识记录（/user/1）。UriMatcher匹配不同路径返回code区分集合Uri和单条Uri。ContentObserver监听数据变化（registerContentObserver+notifyChange）。清单注册可设exported控制访问、permission设权限。
</Answer>

<Glossary>
<GlossaryItem term="SharedPreferences">轻量键值对存储，底层XML文件。getSharedPreferences.edit().putXxx.commit/apply写入，getXxx读取。适合少量配置。</GlossaryItem>
<GlossaryItem term="SQLiteOpenHelper">SQLite数据库管理辅助类。onCreate首次建表，onUpgrade版本迁移。getReadableDatabase/getWritableDatabase获取数据库实例。</GlossaryItem>
<GlossaryItem term="事务">beginTransaction/setTransactionSuccessful/endTransaction。保证一组操作原子性——全部成功才提交，任一失败回滚。批量操作大幅提升性能。</GlossaryItem>
<GlossaryItem term="ContentProvider">跨应用/跨进程数据共享组件。提供query/insert/update/delete统一接口，通过Uri标识数据，ContentResolver客户端访问。清单注册+权限控制。</GlossaryItem>
<GlossaryItem term="Uri">content://authority/path/id。scheme固定content://，authority唯一标识，path标识表，id可选标识记录。UriMatcher匹配不同路径。</GlossaryItem>
</Glossary>
