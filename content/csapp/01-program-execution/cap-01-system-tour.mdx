## 核心机制深挖

以 hello 程序为探针，把源代码、编译系统、处理器、存储层次、操作系统与网络串成一条可观察的端到端执行链。 本页不把系统描述成若干孤立名词，而把每个概念放回“读取源码 → 形成目标文件 → 装入地址空间 → 解释机器指令 → 访问层次存储 → 跨网络输出”的状态机。输入包括源码、位模式、目标制品、地址、文件或网络字节；状态包括程序计数器、寄存器、缓存与页表、内核对象和同步关系；输出必须同时说明正常值、资源所有权和下一阶段可以依赖的承诺。

本页签发的不变量是：**任一可见结果都能回溯到确定的位模式、翻译制品、机器状态和操作系统资源；抽象隐藏细节，但不删除责任边界。**。不变量必须在转换前后都成立。只展示一次成功运行最多证明样本可用，不能证明边界安全；因此每项机制都配正常、边界、失败和恢复四条轨迹，并把“谁检测、谁清理、谁重试、谁向上报告”写进证据账本。

保存 hello.c 的预处理文件、汇编、可重定位目标和可执行文件，再把系统调用、缺页、缓存与网络输出按时间对齐。 运行前先把预期写成状态快照，运行后逐字段比较。计时实验需要预热、重复和稳定输入；地址实验要记录位宽与权限；并发实验要记录同步边而非依赖偶然调度。这样才能把现象还原成可复查的因果链。

改变一个库、权限、缓存容量或网络端点，首个偏离必须定位到翻译、装载、执行、存储或通信中的唯一阶段。 故障移除后必须用完全相同的输入重放，确认制品、机器状态、外部输出和清理结果一起恢复。若只修正最终输出，却留下描述符、子进程、堆块、锁或错误映射，验收仍然失败。

中文第三版采用 x86-64、Linux 和 Y86-64 教学处理器。现代 CPU、内核和工具链会改变微结构、默认安全机制与性能数值，但固定宽度表示、指令语义、缓存局部性、符号重定位、进程地址空间、字节流接口和同步不变量仍然成立。现代对照必须标明差异，不能覆盖原书问题身份。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：源码与最终输出正确就代表系统正确。**
  中间仍可能存在未定义行为、错误重定位、缓存退化、资源泄漏或竞争；必须检查首个状态变化与清理结果。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据               | 通过条件     |
| ---- | -------------------------- | ---------------------- | ------------ |
| 正常 | 固定源码、工具链和输入     | 全阶段状态与输出       | 与预测一致   |
| 边界 | 极值、空输入、低容量       | 范围、终止与资源状态   | 不越界不泄漏 |
| 失败 | 错地址、缺依赖、断连或竞争 | 首个错误与责任层       | 失败被隔离   |
| 恢复 | 删除故障后重放             | 制品、状态、输出和清理 | 回到受控结果 |
