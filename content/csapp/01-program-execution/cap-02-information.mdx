## 同一组比特为什么会有不同答案

信息表示的关键不是背下某个十进制结果，而是先问三个问题：有多少位，采用什么编码，当前操作如何解释这些位。`0x80` 在八位无符号解释中是 128，在八位补码中是 -128；同一段内存还可能被当作字符、指令或地址的一部分。答案来自上下文，不来自比特串自己携带的标签。

本章的专属实验是“比特解释与边界回放台”。它固定一个十六进制样本和 C 语言的宽度，只切换解释方式、端序和故障样本。画面会同时显示比特格、字段边界、十六进制字节和解释结果；当注入溢出或舍入边界时，学习者必须先预测变化，再用打印出的原始字节确认哪一步改变了语义。

## 来源边界与实验坐标

本页依据 [CS:APP 第三版官方页面](https://csapp.cs.cmu.edu/3e/) 与[第三版前言](https://csapp.cs.cmu.edu/3e/pieces/preface3e.pdf)重组“信息的表示和处理”的目录范围，未复制教材正文；中文说明、代码、图示、实验和答案均为独立教学重写。C 语言转换行为、编译器输出和 IEEE 754 的实现细节，以当前编译器、目标架构和运行平台记录为准。

实验记录至少写明位宽、字节序、编译器版本、优化选项、输入字节和输出格式。原书的 x86-64/Linux 坐标与今天的平台可能在默认类型宽度、浮点指令或打印精度上不同；对照实验应标出差异，而不是把某个机器结果当成编码规则本身。

<Callout type="trap" title="误区一：看到十进制结果就忘了位宽">
  现象 → 计算机输出一个数，手算也得到同样的十进制值，但换成较窄类型后结果突然变负或回到小数。

原因 → 手算使用了无穷宽度，程序却在固定宽度、补码或无符号模运算中工作。

修法 → 先写出位宽和原始比特，再做扩展、截断和运算；同时打印十六进制与十进制，确认变化发生在哪个边界。

</Callout>

<Callout type="trap" title="误区二：字节顺序只影响网络，不影响本机分析">
  现象 → 同一十六进制字符串在文件、内存转储和另一台机器上的数值解释不同，却被当作算法错误。

原因 → 把字节序与数值编码混为一谈，没有记录多字节对象的存储顺序和读取方式。

修法 → 逐字节保存输入，分别用小端和大端重建数值；把地址、长度和打印格式写进探针契约。

</Callout>

<Callout type="trap" title="误区三：浮点打印的小数位就是精确值">
  现象 → 两个看起来相同的浮点结果在比较或累加后出现差异，调试器和日志中的小数位也不一致。

原因 → 忽略有效位、规格化、舍入模式和中间精度，拿十进制显示文本代替二进制表示。

修法 → 保存符号位、指数和尾数字段，使用相邻可表示值构造边界样本，并把比较容差和舍入模式写清楚。

</Callout>

## 六个术语：把比特解释写成可核对字段

<Term def="在特定位宽、编码和上下文下对一组比特的当前解释，例如无符号值、补码值、字符或浮点字段。">
  位模式
</Term>

位模式是实验的原始证据。先保存它，再讨论数值，可以避免打印格式或语言类型把真正的输入隐藏起来。

<Term def="一个对象、寄存器或运算参与者拥有的比特数量，决定可表示范围、扩展方式和截断位置。">
  位宽
</Term>

位宽决定边界。八位补码和三十二位补码拥有不同的最小值与最大值，扩展和截断也不能交换顺序。

<Term def="多字节对象在连续地址中排列高位字节与低位字节的规则。">字节序</Term>

字节序只描述排列，不改变字节本身。读取文件、内存转储或网络数据时，必须把排列规则与字段宽度一起记录。

<Term def="使用最高位作为符号权重、其余位参与数值计算的固定宽度整数编码。">
  补码
</Term>

补码让加法器可以复用同一套位级运算，但它的溢出范围仍受位宽限制；最小负数的相反数是常见边界。

<Term def="运算结果超出当前位宽可表达范围时发生的表示边界，可能表现为模回绕、符号改变或被语言规则拒绝。">
  溢出
</Term>

溢出是编码与运算共同造成的现象。应分别检查无符号回绕、补码结果和 C 语言中的未定义或实现相关行为。

<Term def="把无限精度或更高精度结果映射到当前浮点格式可表示值的规则。">
  舍入
</Term>

舍入不等于简单截断。符号、指数、尾数和舍入模式共同决定相邻可表示值，验证时应保存字段而不只保存显示小数。

## 官方目录逐项深读

### 第2章 信息的表示和处理

本章用同一比特串贯通存储、整数运算和浮点运算。每个结论都先说明位宽与编码，再用 C 或十六进制探针验证。

### 2.1 信息存储

从地址、字节和对象大小开始，建立“内存中是什么”与“程序如何解释它”的区别。

### 2.1.1 十六进制表示法

十六进制是压缩比特的可读写法。每一位十六进制数字对应四个比特，输出格式必须带宽度，前导零不能随意丢掉。

### 2.1.2 字数据大小

`char`、短整型、整型、长整型和指针的大小由平台与 ABI 约束。用 `sizeof` 和 `_Static_assert` 记录假设，不从类型名称猜宽度。

### 2.1.3 寻址和字节顺序

地址标识字节位置，端序决定多字节对象如何铺开。逐字节打印结构体和整数，能把对齐、填充与读取规则分开。

### 2.1.4 表示字符串

字符串是字节序列加终止约定；长度、编码和终止字节都可能成为边界。比较字符串时，不能把显示字符数当成内存字节数。

### 2.1.5 表示代码

指令也是字节，但需要目标架构和解码规则才能解释。随机数据与可执行代码可能共享字节形态，权限和程序段提供额外上下文。

### 2.1.6 布尔代数简介

与、或、非和异或提供位级组合的代数基础。用真值表或小宽度枚举检查表达式，比只看 C 运算符优先级可靠。

### 2.1.7 C语言中的位级运算

位级与、或、异或和取反直接作用在表示上。先把操作数写成固定宽度二进制，再检查掩码是否保留了想要的字段。

### 2.1.8 C语言中的逻辑运算

逻辑运算把非零解释成真，并可能短路；它与逐位运算的返回值、求值顺序和副作用不同。边界探针要覆盖零和非零的高位模式。

### 2.1.9 C语言中的移位运算

左移、逻辑右移和算术右移受操作数类型和宽度影响。对有符号负数、移位量等于宽度和高位丢失分别建立测试。

### 2.2 整数表示

整数表示要把无符号编码、补码编码、转换、扩展和截断分开。每一步都能用位模式和范围判据独立验收。

### 2.2.1 整型数据类型

整型类型提供语言层接口，实际宽度和范围仍取决于实现。把 `sizeof`、最小值宏和最大值宏放入同一基线，避免隐含平台假设。

### 2.2.2 无符号数的编码

无符号编码把每一位按二的幂加权，超出最大值时按模回绕。最大值、加一和减一是最小边界集合。

### 2.2.3 补码编码

补码用最高位承担负权重，零只有一种编码。最小负数、负一和相反数是区分补码与无符号解释的有效样本。

### 2.2.4 有符号数和无符号数之间的转换

转换通常保留位模式而改变解释；若目标宽度不同，还会发生扩展或截断。先比较原始字节，再比较数值，能看出哪一步改变了含义。

### 2.2.5 C语言中的有符号数与无符号数

混合表达式会触发整数提升和转换。把操作数类型、提升结果和比较结果逐项打印，才能解释看似反直觉的条件判断。

### 2.2.6 扩展一个数字的位表示

无符号扩展补零，补码扩展复制符号位；目标类型和源类型共同决定结果。用正数、负数和最小负数检查扩展。

### 2.2.7 截断数字

截断保留低位并丢弃高位，数值可能回绕或改变符号。把高位丢失的位置标在比特格上，比只看十进制更清楚。

### 2.2.8 关于有符号数与无符号数的建议

接口中应明确范围、转换方向和错误处理。需要位级模运算时使用无符号类型，需要数值比较时避免隐式混合。

### 2.3 整数运算

整数运算在固定宽度中进行，数学结果与机器结果可能不同。预测时同时写出无限精度结果、保留位和语言层行为。

### 2.3.1 无符号加法

无符号加法在模空间回绕，进位被丢弃。最大值附近的加法既能验证公式，也能验证 C 代码是否按预期使用了无符号类型。

### 2.3.2 补码加法

补码加法保留低位，但同号相加可能产生不可表示结果。通过符号变化和边界范围判断补码溢出。

### 2.3.3 补码的非

取反加一可以得到相反数，但最小负数没有对称的正数。这个特殊值应单独出现在回归矩阵中。

### 2.3.4 无符号乘法

乘法保留结果低位，宽度越窄越容易丢失高位。对最大值、幂和随机小数分别记录完整结果与截断结果。

### 2.3.5 补码乘法

补码乘法也可能保留低位而超出范围。正负组合、最小负数和零能帮助区分符号解释与位级乘法。

### 2.3.6 乘以常数

编译器常把乘以常数改写成移位与加法。检查优化前后汇编时，先证明位宽和溢出行为没有被错误改变。

### 2.3.7 除以2的幂

无符号除法向零下取整，补码负数的移位和除法还涉及舍入方向。负数边界是不可省略的样本。

### 2.3.8 关于整数运算的最后思考

整数运算的可靠结论必须同时说明范围、类型、宽度和语言语义。一个漂亮的代数等式不自动适用于溢出后的机器结果。

### 2.4 浮点数

浮点表示把有限比特分给符号、指数和尾数，能覆盖很大范围但不能精确表示所有实数。比较和累加应围绕可表示值设计。

### 2.4.1 二进制小数

二进制小数使用二的负幂，某些十进制小数会成为无限展开。把小数转换为字段，可以提前预测误差来源。

### 2.4.2 IEEE浮点表示

IEEE 格式定义符号、偏置指数、尾数以及零、无穷、NaN 和非规格化数。字段拆解比十进制打印更适合边界诊断。

### 2.4.3 数字示例

用小型字段手算一个值，再和程序打印的位模式对照。示例的价值在于揭示字段如何共同形成数值，而不是记住某个常数。

### 2.4.4 舍入

舍入把无限精度结果映射到相邻可表示值。构造正好位于中点附近的输入，才能观察舍入模式和尾数变化。

### 2.4.5 浮点运算

浮点加法和乘法可能非结合，溢出、下溢和 NaN 也有专门传播规则。回归应比较允许误差、字段和异常值，而不是只用字符串相等。

### 2.4.6 C语言中的浮点数

C 的 `float`、`double` 和 `long double` 由实现提供精度与求值策略。记录类型、编译器选项和打印格式，才能解释跨平台差异。

### 2.5 小结

本章的验收标准是：给定一组比特，能说清宽度、排列、编码、运算和舍入；给定一个异常结果，能用原始字段与边界样本复现，而不是用十进制直觉补解释。

## 三步实验：从比特到数值边界

先预测：同一组八位比特在无符号、补码和字节序切换后，哪一项会改变数值，哪一项只改变读取顺序？再选择溢出或舍入样本，观察实验台的字段变化。

## 小结：先保留比特，再解释答案

- 位宽、字节序和编码决定同一比特串的解释范围；十六进制是观察工具，不是额外类型。
- 无符号、补码和浮点运算必须分别处理回绕、溢出、扩展、截断和舍入。
- 最小 C 探针应同时打印原始字节和解释结果，并覆盖正常、边界、失败与恢复重放。
- 当字段、类型和运算语义都能解释实际输出时，表示结论才可以交给第3章的机器级表示。

  运算结果超出当前位宽可表达范围时发生的表示边界，可能表现为模回绕、符号改变或被语言规则拒绝。
</GlossaryItem>

<GlossaryItem term="舍入">
  把无限精度或更高精度结果映射到当前浮点格式可表示值的规则。
</GlossaryItem>

</Glossary>
