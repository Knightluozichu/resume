## 核心机制深挖

把 C 的数据、控制、过程、数组、结构和浮点运算还原为 x86-64 指令、寄存器、条件码、栈帧与地址计算。 本页不把系统描述成若干孤立名词，而把每个概念放回“编译 C 语句 → 解码操作数 → 更新寄存器 → 选择控制流 → 维护栈帧 → 检查内存边界”的状态机。输入包括源码、位模式、目标制品、地址、文件或网络字节；状态包括程序计数器、寄存器、缓存与页表、内核对象和同步关系；输出必须同时说明正常值、资源所有权和下一阶段可以依赖的承诺。

本页签发的不变量是：**每条机器指令都明确读取和写入哪些寄存器或内存；过程调用前后满足 ABI，返回地址、栈指针和被调用者保存寄存器保持约定。**。不变量必须在转换前后都成立。只展示一次成功运行最多证明样本可用，不能证明边界安全；因此每项机制都配正常、边界、失败和恢复四条轨迹，并把“谁检测、谁清理、谁重试、谁向上报告”写进证据账本。

用反汇编和 GDB 单步对齐源码、指令地址、寄存器、条件码与栈帧，比较条件跳转、条件传送、循环和 switch 的控制形态。 运行前先把预期写成状态快照，运行后逐字段比较。计时实验需要预热、重复和稳定输入；地址实验要记录位宽与权限；并发实验要记录同步边而非依赖偶然调度。这样才能把现象还原成可复查的因果链。

构造越界写、错误指针、错位结构和破坏返回地址的样本，在第一条污染状态的指令处停止，而不是等崩溃后猜测。 故障移除后必须用完全相同的输入重放，确认制品、机器状态、外部输出和清理结果一起恢复。若只修正最终输出，却留下描述符、子进程、堆块、锁或错误映射，验收仍然失败。

中文第三版采用 x86-64、Linux 和 Y86-64 教学处理器。现代 CPU、内核和工具链会改变微结构、默认安全机制与性能数值，但固定宽度表示、指令语义、缓存局部性、符号重定位、进程地址空间、字节流接口和同步不变量仍然成立。现代对照必须标明差异，不能覆盖原书问题身份。
