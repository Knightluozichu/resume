## 从哪一条机器状态开始

机器级表示的学习入口不是背汇编助记符，而是追问一条 C 语义如何变成可观察状态：输入与类型决定数据宽度，编译器选择指令，指令更新寄存器和条件码，控制边改变下一条地址，过程调用维护栈帧，最后由内存和浮点规则给出结果。每次实验都保留源码、汇编、寄存器、栈和地址证据。

本章的专属实验是“指令状态回放台”。选择观察模式和输入样本后，沿五个关键帧单步：固定源码、拆解操作数、更新状态、沿控制边前进、核对地址与结果。动画默认暂停，重置会回到相同的模式、样本和第一帧；边界样本则把焦点标成待核对状态。

## 来源边界与验证坐标

本章以 [CS:APP 第三版官方站点](https://csapp.cs.cmu.edu/3e/) 和[第三版前言](https://csapp.cs.cmu.edu/3e/pieces/preface3e.pdf)界定机器级表示的目录范围，并参考 [x86-64 System V ABI](https://refspecs.linuxbase.org/elf/x86_64-abi-0.99.pdf) 与 [GDB 官方手册](https://sourceware.org/gdb/documentation/)核对术语和工具行为。正文、代码、图示、实验和答案均为独立教学重写，不复现教材段落。

实验记录应写明编译器版本、目标架构、优化选项、调用约定、输入字节、寄存器快照和反汇编来源。x86-64、Linux 与现代编译器之间可能存在布局或默认安全机制差异；这里把差异作为可观测前提，不把某次运行的地址或性能数值当成普遍定律。

<Callout type="trap" title="误区一：汇编长得像就代表语义相同">
  现象 → 两个优化级别生成的指令序列外观不同，于是把其中一份直接当成唯一正确答案。

原因 → 没有先写出输入、输出、寄存器读写和异常边界，混淆了实现选择与语言语义。

修法 → 先用 C 层断言固定可观察结果，再比较指令、条件码和内存副作用；差异只有在破坏契约时才算错误。

</Callout>

<Callout type="trap" title="误区二：看到崩溃位置才开始找错">
  现象 → 程序在返回或解引用时崩溃，排查从最后一行反汇编开始，忽略更早的地址污染。

原因 → 没有在每个关键帧保存读集合、写集合和输入字节，导致错误已经传播后才观察。

修法 → 先在正常样本建立快照，再用边界样本逐帧对照；一旦发现第一条错误写入就停止继续扩大副作用。

</Callout>

<Callout type="trap" title="误区三：把浮点显示文本当成寄存器真值">
  现象 → 日志里的小数看起来相同，却在比较、转换或累加后走了不同分支。

原因 → 忽略浮点格式、舍入模式、寄存器传递和 NaN 比较规则，拿十进制打印文本替代位级证据。

修法 → 同时记录原始字段、转换指令、比较条件和舍入设置；用相邻可表示值重放边界，而不是只增加打印小数位。

</Callout>

## 六个术语：读懂一条指令的状态变化

<Term def="一条机器指令依据操作数和当前机器状态产生的寄存器、内存、条件码与程序计数器变化。">
  指令语义
</Term>

指令语义是回放台的最小契约。它回答“读了什么、写了什么、下一步去哪里”，因此可把汇编文本与状态快照对齐。

<Term def="某个时刻寄存器集合的可检查快照，包含程序计数器、栈指针、参数寄存器和需要保存的临时值。">
  寄存器状态
</Term>

寄存器状态让“值错了”变成可定位证据。调试时要区分调用者保存和被调用者保存寄存器，避免把 ABI 要求误判为编译器偶然行为。

<Term def="算术或逻辑指令写入、条件测试读取的零、符号、进位和溢出等标志位。">
  条件码
</Term>

条件码把数据运算连接到控制流。比较失败时，不只看跳转结果，还要回看是哪条指令写入标志以及分支读取了哪些标志。

<Term def="过程调用期间由栈指针、返回地址、保存寄存器、参数和局部对象共同形成的活动记录。">
  栈帧
</Term>

栈帧是过程边界的空间证据。进入和退出函数时记录栈指针变化、对齐要求与保存槽位，递归和变长局部对象才有可重放依据。

<Term def="由基址、索引、缩放因子和位移组合得到的内存位置计算式，常用于数组、结构和指针访问。">
  地址表达式
</Term>

地址表达式把数组下标和字节布局接起来。先算出有效地址，再检查对象大小、对齐、权限和边界，能避免把错误值误认为错误地址。

<Term def="用于复查一次执行的输入、指令、状态、资源和结果的最小可定位记录集合。">
  边界证据
</Term>

边界证据不是一张截图，而是能重放的记录：样本、版本、关键帧、最早错误读写、清理动作和再次执行的结果都要在同一账本中。

## 一次可复查的机器状态记录

用反汇编和 GDB 建立一份最小记录，重点不是复制所有输出，而是保存能解释分叉的字段：

```text
input: index=2, type=long, abi=sysv-x86-64
before: pc=..., rsp=..., rdi=..., rax=..., flags=...
instruction: movq (%rdi,%rax,8), %rcx
after:  pc=..., rsp=..., rcx=..., flags=..., address=...
decision: normal | boundary | bug
cleanup: restore stack, release probe, replay same input
```

若样本涉及浮点，额外记录格式字段、舍入模式、XMM 寄存器和比较条件。若样本涉及缓冲区或变长栈帧，额外记录对象边界、权限、对齐和返回地址保护状态。
