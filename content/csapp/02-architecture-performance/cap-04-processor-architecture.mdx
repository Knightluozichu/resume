## 为什么要同时看 SEQ 和 PIPE

处理器体系结构的核心问题不是“流水线有几级”，而是同一条 Y86-64 指令怎样从编码变成可提交状态。先读出 icode、ifun、寄存器编号和立即数，再把控制信号送过取指、译码、执行、访存、写回和 PC 更新；顺序实现提供基线，流水线实现通过重叠阶段换取吞吐，但两者必须保持相同的体系结构结果。

本章的专属实验是“流水线状态回放台”。选择 SEQ、PIPE、冒险处理或异常优先级，再选择正常序列、load/use 或分支改道样本。动画默认暂停，五个关键帧逐步展示编码、逻辑、顺序执行、阶段重叠和恢复提交；重置会恢复相同的模式、样本和第一帧。

## 来源边界与验证坐标

本章以 [CS:APP 第三版官方站点](https://csapp.cs.cmu.edu/3e/) 和[第三版前言](https://csapp.cs.cmu.edu/3e/pieces/preface3e.pdf)界定 Y86-64、HCL、SEQ 与 PIPE 的目录范围，并参考 [x86-64 System V ABI](https://refspecs.linuxbase.org/elf/x86_64-abi-0.99.pdf) 核对寄存器与调用边界。正文、控制逻辑、图示、实验和答案均为独立教学重写，不复现教材段落。

实验记录应注明模拟器版本、指令字节、初始 PC、寄存器文件、内存镜像、周期号、控制信号、流水线寄存器和最终状态。现代 CPU 的微结构可能不同，但这里的 Y86-64 是教学 ISA；现代对照只能解释差异，不能替换本章的可验证问题。

<Callout type="trap" title="误区一：PIPE 只要更快就一定正确">
  现象 → 流水线周期数下降，最终输出也看似相同，于是跳过阶段状态和异常检查。

原因 → 把性能指标当成体系结构等价性，没有检查暂停、转发、气泡和错误路径写回。

修法 → 先逐项比较 SEQ 与 PIPE 的 PC、寄存器、内存和状态码，再单独报告吞吐、停顿和提交周期。

</Callout>

<Callout type="trap" title="误区二：发现依赖就一律暂停整个流水线">
  现象 → 任意相邻读写都插入气泡，结果正确但吞吐下降，无法说明真正的冒险来源。

原因 → 没有区分可转发的数据依赖、load/use 延迟、控制依赖和结构限制。

修法 → 画出生产者与消费者所在阶段，只在值尚未可用时暂停；其余情况用转发或保持流水线前进。

</Callout>

<Callout type="trap" title="误区三：异常指令已经进入流水线就必须提交">
  现象 → 指令后面的访存或写回仍然发生，异常状态虽然被记录，但机器状态已经被错误路径污染。

原因 → 没有定义异常优先级和取消边界，把“检测到异常”误当成“已经完成隔离”。

修法 → 给异常携带状态码和指令位置，在提交前清空错误路径；重放时同时核对寄存器、内存和状态码。

</Callout>

## 六个术语：把周期图读成状态契约

<Term def="指令执行后对程序员可见的 PC、寄存器、内存和状态码所作的最终更新。">
  体系结构提交
</Term>

体系结构提交是 SEQ 与 PIPE 必须对齐的验收点。内部阶段如何重叠并不重要，重要的是错误路径不能提前改变外部可见状态。

<Term def="由指令字节、当前状态和控制逻辑共同决定的下一阶段输入与输出选择。">
  控制信号
</Term>

控制信号把 HCL 布尔表达式连接到硬件行为。记录它们的来源和去向，才能解释某个阶段为何读寄存器、写内存或选择下一条 PC。

<Term def="流水线中前一条指令产生的数据还未写入寄存器，后一条指令却已经需要读取它的时间关系。">
  数据冒险
</Term>

数据冒险不等于一定暂停。先判断值在哪个阶段产生、在哪个阶段被需要，再选择转发、保持或插入气泡。

<Term def="控制流指令改变下一条 PC 后，已经进入流水线的预测路径指令需要被取消的处理动作。">
  控制冒险
</Term>

控制冒险的验收是错误路径没有提交。预测命中时追求吞吐，预测失败时优先保证 PC、状态码和副作用的隔离。

<Term def="在相邻流水线阶段之间保存指令字段、控制信号、数据和状态码的时序边界。">
  流水线寄存器
</Term>

流水线寄存器让每个周期拥有稳定输入，也让暂停和气泡有了明确的保持与清空位置。

<Term def="用指令字节、周期快照、控制信号和提交状态重现一次 Y86-64 执行的记录集合。">
  周期证据
</Term>

周期证据比最终输出更能定位问题。它应包含样本、版本、周期、阶段寄存器、异常原因和恢复后的再次执行结果。

将 4.6.1 Y86-64模拟器 与相邻阶段的边界一起检查，尤其关注流水线寄存器传递、反馈路径、时钟边沿和错误指令的取消。记录周期号比只记录最终输出更能解释吞吐和延迟。

## 周期级验证记录

用模拟器或手写 trace 保存最小证据，重点是能解释某个控制动作和提交结果：

```text
instruction: mrmovq / rrmovq / jXX
cycle: 7
stage: fetch | decode | execute | memory | write | pc
control: stall=false, bubble=true, forward=none, status=SAOK
commit: pc=..., registers=..., memory=...
replay: same bytes, same initial state, same commit
```

若样本涉及异常，额外记录异常指令位置、状态码、取消范围和优先级；若样本涉及性能，额外记录总周期、填充/排空周期、停顿周期与有效提交数。

<Glossary>

<GlossaryItem term="体系结构提交">
  一次指令完成后对 PC、寄存器、内存和状态码产生的外部可见更新。
</GlossaryItem>
<GlossaryItem term="控制信号">
  由指令字段和当前状态计算出的阶段选择、写使能、暂停或气泡控制。
</GlossaryItem>
<GlossaryItem term="数据冒险">
  生产者结果尚未在寄存器可读时，消费者提前需要该结果的时序冲突。
</GlossaryItem>
<GlossaryItem term="控制冒险">
  分支或返回改变下一条 PC 后，预测路径与真实路径之间的冲突。
</GlossaryItem>
<GlossaryItem term="流水线寄存器">
  阶段之间保存指令数据、控制信号和状态码的时序存储边界。
</GlossaryItem>
<GlossaryItem term="周期证据">
  可按相同输入重放的指令、周期、阶段状态、控制动作和提交记录。
</GlossaryItem>

</Glossary>
