## 核心机制深挖

从 SRAM、DRAM、磁盘与 SSD 的速度和容量差异出发，用时间与空间局部性解释多级缓存如何接近快存储的性能。 本页不把系统描述成若干孤立名词，而把每个概念放回“生成地址 → 选择集合 → 匹配标记 → 读取缓存行 → 执行替换 → 写回下层”的状态机。输入包括源码、位模式、目标制品、地址、文件或网络字节；状态包括程序计数器、寄存器、缓存与页表、内核对象和同步关系；输出必须同时说明正常值、资源所有权和下一阶段可以依赖的承诺。

本页签发的不变量是：**地址按标记、集合索引和块偏移唯一拆分；命中、未命中、替换与写策略都可从缓存参数和访问序列重放。**。不变量必须在转换前后都成立。只展示一次成功运行最多证明样本可用，不能证明边界安全；因此每项机制都配正常、边界、失败和恢复四条轨迹，并把“谁检测、谁清理、谁重试、谁向上报告”写进证据账本。

构造步长、工作集和循环顺序不同的访问轨迹，计算直接映射与组相联缓存命中，并测出容量与步长形成的存储器山。 运行前先把预期写成状态快照，运行后逐字段比较。计时实验需要预热、重复和稳定输入；地址实验要记录位宽与权限；并发实验要记录同步边而非依赖偶然调度。这样才能把现象还原成可复查的因果链。

注入冲突抖动、跨行访问、错误循环顺序和工作集越界，区分强制、容量和冲突未命中的首要原因。 故障移除后必须用完全相同的输入重放，确认制品、机器状态、外部输出和清理结果一起恢复。若只修正最终输出，却留下描述符、子进程、堆块、锁或错误映射，验收仍然失败。

中文第三版采用 x86-64、Linux 和 Y86-64 教学处理器。现代 CPU、内核和工具链会改变微结构、默认安全机制与性能数值，但固定宽度表示、指令语义、缓存局部性、符号重定位、进程地址空间、字节流接口和同步不变量仍然成立。现代对照必须标明差异，不能覆盖原书问题身份。

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据               | 通过条件     |
| ---- | -------------------------- | ---------------------- | ------------ |
