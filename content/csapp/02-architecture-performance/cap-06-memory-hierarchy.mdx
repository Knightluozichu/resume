## 为什么同一个地址会走不同层

存储器层次结构的关键不是把所有存储技术排成速度榜，而是用小而快的层缓存大而慢的层。一次访问先由地址位段选择集合并匹配标记，再决定命中、从下一层填充、驱逐哪一行以及是否写回。访问模式改变时，时间局部性、空间局部性、工作集和步长共同改变命中率与性能。

本章的专属实验是“缓存命中回放台”。选择地址分解、局部性、命中策略或存储器山，再选择顺序访问、冲突访问或工作集超限。动画默认暂停，五个关键帧逐步展示地址、局部性、匹配、替换/写策略和访问重放；重置会恢复相同的模式、样本和第一帧。

<Callout type="trap" title="误区一：缓存越大就一定更快">
  现象 → 只比较容量，认为更大缓存必然降低所有访问的延迟。

原因 → 忽略相联度、行大小、层级延迟、带宽、功耗和访问模式，混淆容量收益与硬件代价。

修法 → 固定访问序列，分别记录命中率、命中延迟、未命中代价、带宽和 CPE；用参数而不是容量一个数字解释结果。

</Callout>

<Callout type="trap" title="误区二：顺序访问就是所有局部性都好">
  现象 → 循环按地址递增，却因工作集过大或同集合冲突出现大量未命中。

原因 → 把空间相邻和时间重用混为一谈，没有测量工作集、步长、集合映射和重复间隔。

修法 → 画出实际访问序列，逐项检查块偏移、集合和标记；用顺序、跨行、冲突和超容量样本对照。

</Callout>

<Callout type="trap" title="误区三：写命中只看最终内存值">
  现象 → 输出正确，但性能、带宽或下层副本与预期不一致。

原因 → 忽略直写/写回、写分配/非写分配、脏位和驱逐时机。

修法 → 记录写命中、写未命中、脏行、下层流量和驱逐动作；重放时同时验收数据和写策略证据。

</Callout>

## 六个术语：把地址和访问轨迹写成证据

<Term def="把一个地址拆成标记、集合索引和缓存行内偏移的位段。">地址分解</Term>

地址分解决定访问会检查哪个集合、比较哪个标记以及落在缓存行的哪个字节。行大小和集合数改变时，位段也会改变。

<Term def="最近访问过的数据在近期再次被访问的倾向，缓存可利用它保留已经取入的行。">
  时间局部性
</Term>

时间局部性解释重复访问为什么可能命中。重复间隔超过缓存容量或被其他行驱逐后，原先的重用就不再成立。

<Term def="访问一个缓存行后，附近地址很快也被访问的倾向，缓存行一次带入多个相邻字节。">
  空间局部性
</Term>

空间局部性解释行大小的收益。步长过大或访问跨行时，带入的相邻字节没有被使用，带宽和容量就会浪费。

<Term def="一次访问未在当前缓存层找到所需数据的事件，以及把数据从更低层取回的代价。">
  缓存未命中
</Term>

未命中要继续分类：第一次访问是强制未命中，工作集过大是容量未命中，同集合行互相驱逐是冲突未命中。

<Term def="缓存把地址映射到集合后，在该集合内允许同时保存的缓存行数量。">
  相联度
</Term>

相联度影响冲突概率、比较工作量和硬件成本。直接映射是一行，全相联把所有行放在同一组，组相联处于两者之间。

<Term def="按步长、工作集、循环顺序和重复间隔组织的一段真实地址访问序列。">
  访问轨迹
</Term>

访问轨迹是实验的原始证据。只看平均命中率不够，必须保留每次访问的集合、标记、命中/未命中、替换和下一层动作。

用一份可重放记录保存参数和访问结果，重点是让每个未命中都能回到地址与序列：

```text
cache: line=64B, sets=64, ways=8, policy=LRU
address: 0x..., tag=..., set=..., offset=...
access: load | store, hit=false, cause=conflict
action: fill | evict | writeback | next-level
measure: cpe=..., bandwidth=..., output_hash=...
replay: same parameters, same trace, same conclusion
```

若讨论磁盘、SSD 或 DRAM，额外记录容量、延迟、带宽、持久性和队列条件；若讨论写策略，额外记录脏位、下一层流量和驱逐时机。

用矩阵或数组循环构造存储器山样本，覆盖 6.5 编写高速缓存友好的代码、6.6 综合：高速缓存对程序性能的影响、6.6.1 存储器山、6.6.2 重新排列循环以提高空间局部性、6.6.3 在程序中利用局部性 与 6.7 小结。报告步长、工作集、循环顺序、命中率、带宽和 CPE。

<Answer>

先固定元素大小、缓存参数和输入矩阵，再改变循环顺序与步长。小工作集和连续访问应表现出较好的局部性；工作集超过某层容量或步长跨行时，记录性能拐点。优化后必须用同一输入检查输出、边界元素和访问轨迹。

</Answer>

## 章末回顾

本章的验收条件是：地址能被唯一拆成标记、集合和块偏移，局部性来自访问序列而不是口号，未命中能区分强制/容量/冲突，缓存组织和写策略能解释驱逐与下一层流量，缓存友好代码能用存储器山、CPE 和重放样本验证。最后用正常、边界、故障、恢复四类样本复查。

<Glossary>

<GlossaryItem term="地址分解">
  把地址位段解释为标记、集合索引和缓存行内偏移的过程。
</GlossaryItem>
<GlossaryItem term="时间局部性">
  近期访问过的数据在较短间隔内再次被访问的倾向。
</GlossaryItem>
<GlossaryItem term="空间局部性">
  访问一个位置后附近位置也被访问的倾向。
</GlossaryItem>
<GlossaryItem term="缓存未命中">
  当前层找不到所需缓存行并需要访问更低层的事件。
</GlossaryItem>
<GlossaryItem term="相联度">一个集合可同时容纳的缓存行数量。</GlossaryItem>
<GlossaryItem term="访问轨迹">
  按时间排列的地址、映射、命中、替换和写回记录。
</GlossaryItem>
