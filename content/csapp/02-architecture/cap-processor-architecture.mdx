## 直觉引入

如果 CPU 每次只完整执行一条指令再取下一条，那大部分硬件在每个周期都闲着——取指时执行单元空转，执行时取指单元空转。流水线的洞察是：像工厂流水线一样，把指令切成五道工序，五条指令同时在五道工序上推进，硬件利用率拉满。理想情况下吞吐率提升 5 倍。但流水线会遇到「冒险」——下一条指令依赖前一条的结果、或还不知道下一条该取哪条。处理冒险的转发、停顿、预测技术，是现代 CPU 设计的核心艺术。

## 指令周期与五阶段

<Term def="指令周期是一条指令从取出到完成的全过程，经典 RISC 分五阶段：取指(IF)→译码(ID)→执行(EX)→访存(MEM)→写回(WB)。">指令周期</Term>刻画一条指令的完整生命周期。**IF** 从内存/指令缓存取指令到指令寄存器；**ID** 解码指令、读寄存器；**EX** 算术逻辑单元运算（ALU）；**MEM** 访问数据内存（仅 load/store 需要）；**WB** 把结果写回寄存器堆。单周期实现每条指令一个时钟周期，但时钟周期由最慢指令决定，浪费严重。流水线让五阶段并行处理五条指令，CPI（cycles per instruction）逼近 1。

## 流水线与吞吐率

**流水线**的关键指标是吞吐率与加速比。理想 $k$ 级流水线加速比接近 $k$，但受限于最慢阶段（木桶效应）。实际吞吐率 $= \frac{1}{\text{最慢阶段延迟}}$。流水线寄存器在每个阶段间插入，锁存本阶段结果供下阶段使用。CPI 公式：$\text{CPI} = \text{理想 CPI} + \text{停顿周期}$。无停顿时 CPI=1（单发射）。现代超标量 CPU 每个 周 期 发射多条指令，CPI 可低于 1。

## 冒险与处理

三类冒险是流水线的敌人：①**结构冒险**——硬件资源冲突（同周期两条指令都要访存），靠资源重复（独立指令/数据缓存）解决；②**数据冒险**——后续指令需要前一条的结果，靠**转发（forwarding）**把 EX 结果直接旁路给下一条 ID，或**停顿（bubble）**插入空周期；③**控制冒险**——分支结果未定，下一条取哪条未知，靠**分支预测**猜测方向、**推测执行**提前跑、预测失败则**冲刷（flush）**流水线。

load-use 数据冒险无法完全转发（load 数据在 MEM 才就绪，下一条 ID 已开始），需插入一个 bubble。

## 分支预测与推测执行

**分支预测**是现代 CPU 性能命脉。静态预测（如「向后跳转预测为 taken」）简单但准确率有限；动态预测用分支历史表（BHT）和分支目标缓冲（BTB）记录历史，准确率超 95%。预测成功流水线不停顿；预测失败需冲刷已推测执行的指令，代价是 $k$ 周期（流水线深度）。深流水线（如 20 级）预测失败代价巨大，所以预测器越做越复杂。Spectre/Meltdown 漏洞正是利用推测执行读取了本不该访问的数据。

## 常见误区

<Callout type="trap">
**误区：流水线级数越多越快。** 流水线加深能提升主频（每级更简单跑得更快），但有两个反作用力：①分支预测失败代价随级数线性增长——20 级流水线预测失败要冲刷 20 周期；②流水线寄存器本身有开销，级数过多开销占比上升。Pentium 4 的 31 级超长流水线就是反例——主频上去了但 IPC 掉下来了，最终被 Core 架构的较短流水线取代。最优级数是主频与 IPC 的平衡点，不是越深越好。
</Callout>

<Exercises>
**问题 1**：流水线的三类冒险是什么？分别如何处理？

<Answer>
①结构冒险——同一周期多条指令争用同一硬件资源（如都访存）。处理：资源重复，分离指令缓存与数据缓存（哈佛结构），重复 ALU。②数据冒险——后续指令依赖前一条指令尚未写回的结果。处理：转发（forwarding/bypassing）把 EX/MEM 结果直接旁路给下一条 ID 阶段；无法转发时（如 load-use）插入 bubble 停顿一周期；编译器调度重排指令拉开依赖距离。③控制冒险——分支指令结果未决，下一条取指地址未知。处理：分支预测猜方向，推测执行提前跑，预测失败冲刷流水线；或简单停顿等分支结果。
</Answer>

**问题 2**：为什么分支预测对现代 CPU 性能如此关键？预测失败的代价是什么？

<Answer>
现代 CPU 流水线很深（10-20 级），每周期取多条指令。遇到分支时若等分支结果出来再取下一条，流水线要空等多个周期（等于流水线深度），IPC 暴跌。分支预测让 CPU 猜测分支方向并提前取指执行，预测成功流水线不停顿、吞吐率接近峰值。预测失败时必须冲刷流水线中所有错误推测执行的指令，代价约等于流水线深度 $k$ 个周期——20 级 CPU 一次预测失败浪费 20 周期。典型程序每 5-10 条指令一个分支，预测准确率每提升 1% 性能提升显著，所以预测器是 CPU 设计的重头戏。Spectre 漏洞正是滥用推测执行读取越权数据。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="指令周期">一条指令从取出到完成的全过程，RISC 经典五阶段：IF 取指 → ID 译码 → EX 执行 → MEM 访存 → WB 写回。单周期每指令一周期但时钟慢，流水线让五阶段并行 CPI 逼近 1。</GlossaryItem>
<GlossaryItem term="数据冒险">后续指令依赖前一条尚未写回的结果。靠转发（EX 结果旁路到下一条 ID）、停顿（插 bubble）、编译器调度处理。load-use 冒险无法完全转发需一周期停顿。</GlossaryItem>
<GlossaryItem term="分支预测">猜测分支方向提前取指执行，避免控制冒险停顿。动态预测用 BHT/BTB 历史记录准确率超 95%。预测失败冲刷流水线代价 = 流水线深度。深流水线预测准确率对性能影响巨大。</GlossaryItem>
</Glossary>
