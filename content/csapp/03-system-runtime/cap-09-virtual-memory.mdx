## 核心机制深挖

把虚拟内存同时视为 DRAM 缓存、地址空间管理和保护工具，并贯通地址翻译、内存映射、动态分配与垃圾收集。 本页不把系统描述成若干孤立名词，而把每个概念放回“拆分虚拟地址 → 查询 TLB → 遍历页表 → 访问物理缓存 → 管理堆块 → 回收或解除映射”的状态机。输入包括源码、位模式、目标制品、地址、文件或网络字节；状态包括程序计数器、寄存器、缓存与页表、内核对象和同步关系；输出必须同时说明正常值、资源所有权和下一阶段可以依赖的承诺。

本页签发的不变量是：**每个有效虚拟地址经权限检查映射到确定物理页或触发受控缺页；分配器维护块边界、对齐、空闲结构和不可重叠性。**。不变量必须在转换前后都成立。只展示一次成功运行最多证明样本可用，不能证明边界安全；因此每项机制都配正常、边界、失败和恢复四条轨迹，并把“谁检测、谁清理、谁重试、谁向上报告”写进证据账本。

逐位执行 TLB 与多级页表翻译，再用 mmap、fork 和自制分配器观察共享、写时复制、分割、合并与碎片。 运行前先把预期写成状态快照，运行后逐字段比较。计时实验需要预热、重复和稳定输入；地址实验要记录位宽与权限；并发实验要记录同步边而非依赖偶然调度。这样才能把现象还原成可复查的因果链。

注入坏指针、未初始化读取、越界、悬空引用、错位和泄漏，在地址翻译或对象生命周期的第一处违规处保留证据。 故障移除后必须用完全相同的输入重放，确认制品、机器状态、外部输出和清理结果一起恢复。若只修正最终输出，却留下描述符、子进程、堆块、锁或错误映射，验收仍然失败。

中文第三版采用 x86-64、Linux 和 Y86-64 教学处理器。现代 CPU、内核和工具链会改变微结构、默认安全机制与性能数值，但固定宽度表示、指令语义、缓存局部性、符号重定位、进程地址空间、字节流接口和同步不变量仍然成立。现代对照必须标明差异，不能覆盖原书问题身份。
