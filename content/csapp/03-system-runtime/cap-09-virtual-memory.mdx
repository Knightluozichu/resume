## 先看一条地址如何进入真实内存

虚拟内存不是一个单独的“更大的内存”。它同时充当 DRAM 的缓存、每个进程的地址空间边界，以及读写执行权限的保护层。一次访问先携带虚拟页号和页内偏移，处理器尝试从 TLB 取得映射；若未命中，再依据页表项找到物理页，必要时触发缺页。访问完成后，堆分配器和映射接口还会继续管理对象的生命周期。

本章的专属实验是“翻译与堆布局台”。选择拆分地址、查询 TLB、遍历页表、处理页命中、管理堆块或执行保护，再选择页命中、缺页或碎片样本。动画默认暂停，六个阶段逐帧展示；重置会回到同一阶段、同一样本和第一帧。

<Callout type="trap" title="误区一：虚拟地址就是物理地址加一个偏移">
  现象 → 直接把指针的数值当成 DRAM 地址，忽略进程隔离、页表和权限。

原因 → 混淆地址空间中的名称与硬件最终使用的物理页，忘记 TLB 和多级页表会参与翻译。

修法 → 先写出虚拟页号、页内偏移、PTE、物理页号和权限，再判断访问是命中、缺页还是保护错误。

</Callout>

<Callout type="trap" title="误区二：缺页就是程序越界，应该立即终止">
  现象 → 看到 page fault 就把所有缺页都当成非法访问。

原因 → 没有区分按需分配、写时复制、文件映射等可恢复缺页与权限违规、未映射地址。

修法 → 检查页表存在位、访问类型、映射来源和修复动作；只有无法满足契约的缺页才进入错误路径。

</Callout>

<Callout type="trap" title="误区三：free 之后内存内容仍然属于原对象">
  现象 → 释放块后继续读取旧指针，测试偶尔通过，于是认为生命周期没有问题。

原因 → 把地址仍可计算误当成对象仍然有效，忽略分配器可立即复用、合并或返回页面给内核。

修法 → 以分配状态和所有权为准，释放后让指针失效；用边界、复用、泄漏和双重释放样本检查堆结构。

</Callout>

## 六个术语：把翻译和生命周期说清楚

<Term def="由虚拟页号和页内偏移组成、供进程使用的地址表示。">虚拟地址</Term>

虚拟地址只在某个进程的地址空间中有意义。翻译时页内偏移通常保持不变，虚拟页号则通过 TLB 或页表找到物理页号。

<Term def="把虚拟页号快速映射到物理页号并缓存权限的硬件转换后备缓冲区。">
  TLB
</Term>

TLB 是地址翻译的缓存。命中时可以减少页表访问；未命中不代表访问非法，而是要继续检查页表层级和存在位。

<Term def="记录虚拟页到物理页映射、存在位、权限和其他状态的结构。">页表</Term>

页表把地址空间抽象落到页面映射。多级结构用更少的实际条目表示稀疏地址空间，但翻译时必须沿有效层级逐项检查。

<Term def="访问尚未驻留或权限不允许的页面时由内核处理的受控异常。">缺页</Term>

缺页可能通过装入页面、建立写时复制副本或补齐映射而恢复，也可能因为权限和地址无效而失败。区分来源比记住名称更重要。

<Term def="向进程地址空间申请、分割、合并和释放可变大小对象的运行时机制。">
  动态内存分配
</Term>

动态分配器管理的是对象边界和空闲结构，不只是返回一串字节。分配、释放、分割、合并与扩展堆都必须保持对齐和不可重叠。

<Term def="扫描可达对象并回收不再可达内存的自动生命周期管理方法。">
  垃圾收集
</Term>

垃圾收集需要根集合、可达性判断和回收策略。保守扫描可能保留伪指针指向的块，因此“未回收”并不自动说明扫描器错误。

## 正式目录逐项深读

### 第9章 虚拟内存

第9章 虚拟内存把一条虚拟地址路径连接到三类职责：缓存较慢的 DRAM，隔离进程的地址空间，以及阻止不允许的访问。后半章再把同样的边界思想延伸到 mmap、分配器、垃圾收集和错误诊断。

### 9.1 物理和虚拟寻址

物理地址标识内存系统中的实际位置，虚拟地址则由当前进程使用。页内偏移在翻译中保持，页号由映射结构转换；因此相同虚拟地址在不同进程中可以落到不同物理页。

### 9.2 地址空间

地址空间把代码、只读数据、堆、共享对象和栈组织成进程可见的范围。未映射的空洞不是“可随便使用的空白”，它帮助系统维持稀疏布局、保护页和按需分配。

### 9.3 虚拟内存作为缓存的工具

把 DRAM 看成页面级缓存时，页命中对应页面已在内存，缺页对应从更低层装入。页面较大、缺页代价较高，因此访问局部性会显著影响性能与带宽。

### 9.3.1 DRAM缓存的组织结构

DRAM 缓存由页面、页表项和驻留状态共同组织。系统通过页表项记录物理页、有效性、脏状态和权限，访问路径还可能经过 TLB 与处理器缓存。

### 9.3.2 页表

页表项至少需要把虚拟页映射到物理页，并标记是否存在以及允许的访问类型。多级页表只为实际使用的地址范围分配下级结构，从而避免为整个宽地址空间预留平面表。

### 9.3.3 页命中

页命中表示目标页面已驻留且访问权限满足。命中仍可能经历 TLB 未命中和页表遍历，所以实验要分别记录 TLB 命中、页表命中和处理器缓存结果。

### 9.3.4 缺页

缺页异常把控制权交给内核，内核判断是按需分配、文件装入、写时复制还是非法访问。可恢复路径更新页表后重试原指令，失败路径则向进程报告错误或终止。

### 9.3.5 分配页面

分配页面需要选择物理页或交换位置，建立映射并设置初始权限。分配结果不仅是一个地址，还包括页面是否清零、谁拥有它以及失败时如何释放已经取得的资源。

### 9.3.6 又是局部性救了我们

页面替换的成本使局部性再次成为性能关键。连续访问和短重用距离减少缺页与页表压力；随机触碰大工作集会让页面在刚被装入后就失去重用机会。

### 9.4 虚拟内存作为内存管理的工具

虚拟内存让系统可以把进程的地址空间与物理页分离，从而支持按需分配、共享、写时复制和交换。管理接口只承诺映射与权限，不承诺物理页永远固定。

### 9.5 虚拟内存作为内存保护的工具

页表权限把读、写、执行和用户/内核访问限制编码到映射中。保护失败不是分配失败的同义词；要根据访问类型和 PTE 标志判断责任边界。

### 9.6 地址翻译

地址翻译沿虚拟页号、TLB、页表层级和物理页号展开。复算时固定位宽、页大小和层级索引，输出虚拟地址、每级索引、PTE、物理地址与权限。

### 9.6.1 结合高速缓存和虚拟内存

处理器缓存和虚拟内存的索引、标记与权限检查相互影响。一个可重放样本应分别指出地址翻译是否命中、缓存是否命中，以及别名或权限变化在哪一层被发现。

### 9.6.2 利用TLB加速地址翻译

TLB 以空间换时间缓存近期页映射。改变工作集、页大小或地址交错时，记录 TLB 命中率、页表遍历次数和实际访问延迟，避免把 TLB 未命中误判成缺页。

### 9.6.3 多级页表

多级页表把虚拟页号拆成多个索引，沿有效指针逐级找到最终 PTE。稀疏地址空间只需要创建被访问分支；缺少中间结构时，访问会进入按需建立或失败路径。

### 9.6.4 综合：端到端的地址翻译

端到端翻译记录从虚拟地址到物理地址的每一项中间值，并附上 TLB、PTE 和权限证据。这样可以区分位段计算错、PTE 不存在、权限不符和物理页数据错误。

### 9.7 案例研究：Intel Core i7/Linux内存系统

案例研究把抽象地址翻译落到 Core i7 与 Linux 的页表、TLB、缓存和权限实践。硬件型号与内核配置会影响数量和性能，因此报告必须同时写明平台和稳定的翻译机制。

### 9.7.1 Core i7地址翻译

Core i7 地址翻译涉及多级页表、TLB 和缓存层次。教学复算可使用固定的虚拟地址与页大小，重点检查各级索引、PTE 权限和物理页号，而不是套用未注明型号的容量数字。

### 9.7.2 Linux虚拟内存系统

Linux 为进程维护映射区间、文件映射、堆和栈等区域，并在缺页时协调页分配与权限。`/proc` 的映射输出是观察证据，不能代替对页表和生命周期的解释。

### 9.8 内存映射

内存映射把文件、匿名页或设备区域接入进程地址空间。映射区间有长度、偏移、权限和共享方式；取消映射后，旧指针不再代表可访问对象。

### 9.8.1 再看共享对象

共享对象可被多个进程映射，代码页通常可共享而可写数据需要更谨慎的权限与复制语义。观察时比较映射地址、权限、文件偏移和写入后的可见性。

### 9.8.2 再看fork函数

`fork` 复制进程的地址空间视图并采用写时复制减少立即拷贝。父子进程最初看似共享内容，但任一方写入后会获得自己的物理页；用映射和页面变化验证这一边界。

### 9.8.3 再看execve函数

`execve` 用新程序映像替换当前进程的用户空间，成功时不会回到原调用点。PID 通常保持不变，但代码、数据、堆、栈和映射集合都应按新程序重新观察。

### 9.8.4 使用mmap函数的用户级内存映射

`mmap` 可创建匿名或文件支持的区域，并指定保护和共享标志。实验必须处理长度对齐、失败返回、取消映射和访问超出区域等边界，不能只验证首地址非空。

### 9.9 动态内存分配

动态内存分配把可变大小对象放到堆上，分配器负责向内核取得页面并在用户空间维护空闲结构。性能与正确性同时取决于放置、分割、合并、对齐和碎片。

### 9.9.1 malloc和free函数

`malloc` 返回满足对齐要求的已分配块，`free` 释放块并让分配器重新利用空间。重复释放、释放非起始地址和释放后访问都违反生命周期契约，应在实验中单独记录。

### 9.9.2 为什么要使用动态内存分配

动态分配让对象数量和大小在运行时决定，适合输入驱动的数据结构和长生命周期服务。它把管理责任从编译期移到程序逻辑，因此需要明确所有权和释放路径。

### 9.9.3 分配器的要求和目标

分配器既要保证有效块不重叠、对齐和可访问，也要追求吞吐量与空间利用率。报告中把正确性不变量和性能指标分开，避免快但损坏堆结构的实现被误判为优化。

### 9.9.4 碎片

内部碎片来自块大小与请求大小的差距，外部碎片来自空闲空间被切成无法满足请求的小块。统计总空闲量、最大连续块、请求序列和对齐开销，才能定位碎片来源。

### 9.9.5 实现问题

实现分配器需要约定块头、边界标记、空闲链表、扩展堆的系统接口和错误处理。每个字段的布局都要服务于遍历、分割、合并和调试，不能只为某个样本硬编码。

### 9.9.6 隐式空闲链表

隐式空闲链表把所有块按地址串在一起，用头部的大小和分配位判断下一个块。遍历简单但每次查找可能扫描很多已分配块，性能会随堆布局退化。

### 9.9.7 放置已分配的块

放置策略在找到足够大的空闲块后决定从头部、尾部还是某个位置放入请求。首次适配、下一次适配和最佳适配会产生不同的碎片与扫描成本，应以同一请求轨迹比较。

### 9.9.8 分割空闲块

空闲块明显大于请求时可以分割，前提是剩余部分足以成为合法块。分割后同步更新大小、分配位和链表关系，并检查尾部对齐与最小块大小。

### 9.9.9 获取额外的堆内存

当现有空闲结构无法满足请求，分配器向内核扩展堆或建立新映射。扩展失败时要沿错误路径释放临时元数据，并让原有堆保持可遍历。

### 9.9.10 合并空闲块

释放相邻块后合并可以降低外部碎片。合并前后都要确认前后块的状态、大小、链表链接和边界，避免把已分配对象吞入空闲区。

### 9.9.11 带边界标记的合并

边界标记把前一个块的大小放在可快速访问的位置，使释放时无需从堆首扫描寻找前块。代价是额外元数据和更严格的写入一致性要求。

### 9.9.12 综合：实现一个简单的分配器

一个最小分配器应能初始化堆、查找空闲块、分割、扩展、释放和合并，并提供一致的对齐保证。测试覆盖空堆、精确匹配、分割后再合并、扩展失败和重复释放。

### 9.9.13 显式空闲链表

显式空闲链表只链接空闲块，减少搜索已分配块的成本。插入、删除和合并时必须维护前后指针，调试器应验证链表没有环、没有悬挂节点且每个节点确实空闲。

### 9.9.14 分离的空闲链表

分离的空闲链表按大小类别组织空闲块，使常见请求能快速找到候选。类别边界、跨类合并和大块拆分是实现复杂点，空间利用率与吞吐量需要一起测量。

### 9.10 垃圾收集

垃圾收集器从根集合追踪可达对象，回收不可达空间。它将生命周期判断自动化，但仍受指针表示、保守误判、暂停时间和碎片整理策略限制。

### 9.10.1 垃圾收集器的基本知识

基本垃圾收集包含识别根、遍历引用图、标记对象和回收未标记块。实验要说明栈、全局区、寄存器和显式根的来源，并区分可达性与“最近是否访问”。

### 9.10.2 Mark&Sweep垃圾收集器

Mark&Sweep 先从根集合标记可达对象，再线性扫描堆回收未标记块。它不要求移动对象，因而适合保留指针稳定性的场景，但可能留下外部碎片。

### 9.10.3 C程序的保守Mark&Sweep

C 程序的保守收集器把看起来像堆地址的字作为潜在指针，因此可能保留实际上不可达的对象。对齐、地址范围和元数据边界会影响误保留率，测试应包含整数伪指针。

### 9.11 C程序中常见的与内存有关的错误

内存错误常表现为翻译失败、权限错误、堆结构损坏或延迟的数据异常。诊断时保留分配轨迹、地址范围、对象生命周期和工具报告，而不是只追逐最后一次崩溃。

### 9.11.1 间接引用坏指针

坏指针可能来自未初始化、释放后复用、越界或错误的类型转换。先确认指针来源和生命周期，再判断故障发生在地址未映射、权限不符还是对象内容已损坏。

### 9.11.2 读未初始化的内存

未初始化读取把不确定字节带入控制流或输出。分配器返回的内存不等于自动初始化；显式设置所有字段，并用工具检查第一次读取位置。

### 9.11.3 允许栈缓冲区溢出

栈缓冲区溢出会覆盖相邻数据、保存的控制信息或保护区域。边界检查、长度契约、编译器保护与权限策略需要分层验证，不能把一次未崩溃当作安全证明。

### 9.11.4 假设指针和它们指向的对象是相同大小的

指针自身的大小与它指向的对象大小没有必然关系。分配数组、复制结构体和计算步长时，应使用目标类型的大小，避免截断或越界。

### 9.11.5 造成错位错误

错位访问违反类型或硬件对齐要求，可能造成性能下降、未定义行为或硬件异常。检查字段偏移、分配器对齐保证和序列化格式，不能只依赖某个平台碰巧接受。

### 9.11.6 引用指针，而不是它所指向的对象

对指针变量本身取值与对其指向对象取值是两种操作。代码审查时标出每一层解引用和目标类型，再用最小数组或结构体样本验证写入的实际位置。

### 9.11.7 误解指针运算

指针加一按目标类型大小移动，不是固定增加一个字节。把基址、元素索引、元素大小和终止条件写在同一张表中，能快速发现跨数组和跨对象的错误。

### 9.11.8 引用不存在的变量

返回局部变量地址、保存已退出作用域的引用或拼错对象生命周期，都会产生悬空引用。检查作用域退出点和所有权转移，必要时改为复制、延长生命周期或显式分配。

### 9.11.9 引用空闲堆块中的数据

释放后读取的结果可能暂时保持旧值，也可能已被新对象覆盖；两种现象都不能证明访问合法。将释放时刻和后续复用轨迹纳入测试，确保工具能在第一次非法读取处报警。

### 9.11.10 引起内存泄漏

内存泄漏是对象仍被分配但已经失去所有释放路径。长时间运行和重复请求才能暴露它；记录分配调用栈、所有权图和回收计数，区分缓存保留与真正泄漏。

### 9.12 小结

本章闭环是：虚拟地址经 TLB 和多级页表映射到物理页，缺页与权限由内核受控处理，mmap 和进程接口塑造地址空间，分配器和垃圾收集器维护对象生命周期。用页命中、缺页、碎片和错误样本复查映射、保护、边界、对齐与清理，才能证明虚拟内存模型真的可重放。
