## 先看一串字节如何安全抵达目的地

系统级 I/O 的核心不是“调用一次 read 就得到请求长度”。应用先取得一个文件描述符，内核通过打开文件表项保存偏移、标志和对象关系；read 或 write 只报告本次实际完成的字节数，短计数、信号中断、EOF 和错误都要由调用者解释。RIO 把这些边界封装成可重放的循环，dup2、fork 和标准 I/O 又会改变描述符与缓冲的观察方式。

本章的专属实验是“描述符流转台”。选择打开对象、读取元数据、传输字节、处理短计数、共享与重定向或关闭清理，再选择完整传输、短读中断或重定向共享。动画默认暂停，六个阶段逐帧展示；重置会恢复同一阶段、同一样本和第一帧。

<Callout type="trap" title="误区一：read 返回值应该总等于请求长度">
  现象 → 只调用一次 read，得到短计数就把剩余数据当成丢失。

原因 → 把字节流接口的“本次可用数据”误当成“请求已满足”，忽略管道、终端、网络和信号中断都可能提前返回。

修法 → 用已完成字节数推进缓冲区，区分零字节 EOF、EINTR 和其他错误；只有达到目标长度才结束固定长度读取。

</Callout>

<Callout type="trap" title="误区二：两个描述符各自拥有独立文件偏移">
  现象 → fork 或 dup2 后两个执行流交错读写，结果出现跳过、覆盖或偏移意外移动。

原因 → 只看描述符整数，忽略它们可能指向同一个打开文件表项，共享偏移和状态标志。

修法 → 画出描述符到表项再到对象的图，记录每次系统调用前后的偏移，并用独立打开与共享打开样本对照。

</Callout>

<Callout type="trap" title="误区三：关闭描述符就会刷新所有缓冲数据">
  现象 → 底层文件已经关闭，但标准 I/O 缓冲中仍有数据，输出顺序或内容不完整。

原因 → 混用 stdio 与系统级 I/O，未按缓冲层的契约执行 flush、EOF 和所有权转移。

修法 → 为每个流选择一种缓冲策略，明确 flush 与 close 的责任；不要让两个抽象层无协调地操作同一个打开表项。

</Callout>

## 六个术语：把描述符和字节计数说清楚

<Term def="进程用来引用内核打开对象的非负整数索引。">文件描述符</Term>

文件描述符只是进程表中的入口，真正的偏移和打开标志在内核表项中。复制描述符可能共享表项，独立 open 则通常获得独立偏移。

<Term def="表示一次 read 或 write 实际完成了多少字节的返回结果。">短计数</Term>

短计数不是自动错误。它要求调用者推进缓冲区并决定继续、等待、结束或报告错误；正确循环必须避免重复消费已经处理的字节。

<Term def="保存打开标志、当前偏移、引用关系和底层对象的内核记录。">
  打开文件表项
</Term>

打开文件表项解释了 dup、fork 后的共享偏移，也解释了两个描述符为何会看到相同的状态。分析 I/O 时要把它与进程描述符表区分开。

<Term def="保存尚未交给调用者的输入字节以及对应描述符状态的用户空间缓冲。">
  RIO 缓冲
</Term>

RIO 缓冲把一次系统调用取回的多余字节保留下来，让上层按行或按固定长度读取。缓冲状态属于一个 RIO 实例，不能被另一个实例无条件复用。

<Term def="描述文件类型、大小、权限、时间和设备等属性的元数据集合。">
  文件元数据
</Term>

文件元数据回答“对象是什么以及有多大”，不等于文件内容。目录、普通文件和设备的类型字段会改变后续可用操作和错误边界。

<Term def="把一个文件描述符的输入或输出边改接到另一个描述符的操作。">
  I/O 重定向
</Term>

I/O 重定向改变的是描述符到打开表项的边，常用于把标准输入输出接到文件或管道。重定向前后的所有权、关闭顺序和共享偏移都应记录。

## 正式目录逐项深读

### 第10章 系统级I/O

第 10 章系统级 I/O 用文件描述符把文件、目录、终端和管道放进同一套观察框架。可靠程序要同时守住三条线：请求与实际字节相符、偏移与共享关系可解释、每个打开对象都有清理责任。

### 10.1 Unix I/O

Unix I/O 通过 open、read、write、close 等系统调用操作字节流。系统调用返回值和 errno 是协议的一部分，应用应把短计数、EOF、EINTR 与持久错误分成不同分支。

### 10.2 文件

文件是由内核管理的字节序列与元数据集合，目录、终端、管道也能以描述符形式参与 I/O，但它们的可寻址性、EOF 和短读行为不同。先确认对象类型，再选择循环策略。

### 10.3 打开和关闭文件

打开把路径和标志解析成描述符及打开文件表项，关闭则减少引用并释放不再需要的内核状态。错误路径也必须关闭已经成功打开的对象，不能只清理“全成功”的路径。

### 10.4 读和写文件

read 和 write 的返回值是实际完成量，零读通常表示 EOF，负值表示错误。固定长度传输要用剩余长度驱动循环，写入也要处理短写，不能假设磁盘或管道一次接收全部数据。

### 10.5 用RIO包健壮地读写

RIO 通过无缓冲循环和带缓冲输入隐藏部分系统调用边界，同时保留明确的错误和 EOF 语义。它适合把“可继续读取的字节”和“本次系统调用已完成的字节”分开管理。

### 10.5.1 RIO的无缓冲的输入输出函数

无缓冲 RIO 直接围绕描述符循环调用底层 read 或 write，适合固定长度字节传输。每次循环都推进指针和剩余长度，并决定 EINTR 是否重试，避免覆盖已复制的内容。

### 10.5.2 RIO的带缓冲的输入函数

带缓冲 RIO 一次取回一批字节，再从用户空间缓冲提供按行或按长度读取。EOF 和缓冲内剩余字节必须分开表示，重新初始化 RIO 实例时也要确认描述符关系没有变化。

### 10.6 读取文件元数据

stat 类接口报告大小、类型、权限、时间和设备信息。元数据可帮助程序预分配缓冲或选择目录遍历策略，但它与随后读写之间存在竞态，不能把一次 stat 当成永久保证。

### 10.7 读取目录内容

目录是由名称到目录项的结构化对象，读取目录内容应使用目录接口而不是把它当作普通字节文件。遍历时处理结束、权限失败、名称编码和条目变化，并关闭目录流。

### 10.8 共享文件

描述符可以共享一个打开文件表项，从而共享当前偏移和打开标志；独立打开同一路径通常拥有不同表项。用 fork、dup 和两次独立 open 对照，才能解释读写交错。

### 10.9 I/O重定向

dup2 把目标描述符的输入或输出边改接到源描述符对应的表项，常用于 shell 管道和标准流设置。重定向前先关闭会被替换的目标，随后明确谁关闭源和目标，避免引用计数泄漏。

### 10.10 标准I/O

标准 I/O 在系统级描述符之上提供 FILE 流、格式化和缓冲。它便利但增加了用户空间状态；若与 read/write 混用同一表项，必须协调缓冲刷新和偏移，否则观察到的顺序不再直观。

### 10.11 综合：我该使用哪些I/O函数？

固定长度二进制传输需要处理短计数，按行文本读取可使用带缓冲 RIO，格式化交互适合标准 I/O，目录则使用目录专用接口。选择依据是对象类型、边界、缓冲责任和故障语义，不是函数名称的偏好。

### 10.12 小结

本章闭环是：打开对象获得描述符，元数据定义观察坐标，读写传输实际字节，RIO 处理边界，共享与重定向改变表项关系，最后沿所有权路径关闭清理。用完整、短读、中断和共享样本复查字节、偏移、缓冲和资源，才能证明 I/O 真的可靠。

**问题 2**

实现一个 RIO 风格固定长度读取器，注入 EINTR、短读和提前 EOF，覆盖 10.5 用RIO包健壮地读写、10.5.1 RIO的无缓冲的输入输出函数、10.5.2 RIO的带缓冲的输入函数、10.12 小结。报告缓冲区指针、剩余长度、实际字节和每次重试原因。

<Answer>

</Answer>
