## 核心机制深挖

从 IP 地址、域名和连接端点进入套接字接口，再以 echo 与 TINY Web 服务器贯通客户端服务器模型、HTTP 静态与动态内容。 本页不把系统描述成若干孤立名词，而把每个概念放回“解析主机服务 → 创建套接字 → 建立连接 → 收发可靠字节流 → 解析 HTTP → 关闭连接”的状态机。输入包括源码、位模式、目标制品、地址、文件或网络字节；状态包括程序计数器、寄存器、缓存与页表、内核对象和同步关系；输出必须同时说明正常值、资源所有权和下一阶段可以依赖的承诺。

本页签发的不变量是：**网络字节序、地址长度、监听与已连接套接字角色明确；应用协议能处理分段到达、错误输入、半关闭和资源释放。**。不变量必须在转换前后都成立。只展示一次成功运行最多证明样本可用，不能证明边界安全；因此每项机制都配正常、边界、失败和恢复四条轨迹，并把“谁检测、谁清理、谁重试、谁向上报告”写进证据账本。

运行 echo 与 TINY，抓取 DNS、connect、accept、RIO 和 HTTP 事务的时序，再比较静态文件和 CGI 动态内容路径。 运行前先把预期写成状态快照，运行后逐字段比较。计时实验需要预热、重复和稳定输入；地址实验要记录位宽与权限；并发实验要记录同步边而非依赖偶然调度。这样才能把现象还原成可复查的因果链。

注入解析失败、端口占用、客户端提前断开、畸形请求和慢发送，验证服务器返回受控错误并关闭所有连接资源。 故障移除后必须用完全相同的输入重放，确认制品、机器状态、外部输出和清理结果一起恢复。若只修正最终输出，却留下描述符、子进程、堆块、锁或错误映射，验收仍然失败。

中文第三版采用 x86-64、Linux 和 Y86-64 教学处理器。现代 CPU、内核和工具链会改变微结构、默认安全机制与性能数值，但固定宽度表示、指令语义、缓存局部性、符号重定位、进程地址空间、字节流接口和同步不变量仍然成立。现代对照必须标明差异，不能覆盖原书问题身份。

## 常见误区与故障注入

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据               | 通过条件     |
| ---- | -------------------------- | ---------------------- | ------------ |
| 正常 | 固定源码、工具链和输入     | 全阶段状态与输出       | 与预测一致   |
| 边界 | 极值、空输入、低容量       | 范围、终止与资源状态   | 不越界不泄漏 |
| 失败 | 错地址、缺依赖、断连或竞争 | 首个错误与责任层       | 失败被隔离   |
| 恢复 | 删除故障后重放             | 制品、状态、输出和清理 | 回到受控结果 |
