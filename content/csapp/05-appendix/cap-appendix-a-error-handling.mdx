## 核心机制深挖

把 Unix 接口的返回值与 errno 变成不可省略的控制流，并用包装函数统一诊断、清理和教学示例中的失败处理。 本页不把系统描述成若干孤立名词，而把每个概念放回“调用系统接口 → 检查返回值 → 保存错误码 → 补充调用上下文 → 清理已获资源 → 传播或终止”的状态机。输入包括源码、位模式、目标制品、地址、文件或网络字节；状态包括程序计数器、寄存器、缓存与页表、内核对象和同步关系；输出必须同时说明正常值、资源所有权和下一阶段可以依赖的承诺。

本页签发的不变量是：**错误码只在失败返回后读取；诊断保留原始原因和调用上下文，任何部分成功获得的资源都沿唯一逆序路径清理。**。不变量必须在转换前后都成立。只展示一次成功运行最多证明样本可用，不能证明边界安全；因此每项机制都配正常、边界、失败和恢复四条轨迹，并把“谁检测、谁清理、谁重试、谁向上报告”写进证据账本。

分别触发 open、read、fork、execve 和网络接口失败，对比手写检查与包装函数的控制流、消息和资源状态。 运行前先把预期写成状态快照，运行后逐字段比较。计时实验需要预热、重复和稳定输入；地址实验要记录位宽与权限；并发实验要记录同步边而非依赖偶然调度。这样才能把现象还原成可复查的因果链。

注入不存在路径、权限拒绝、描述符耗尽和子进程创建失败，确认包装层不会覆盖 errno、重复清理或把失败当成功继续。 故障移除后必须用完全相同的输入重放，确认制品、机器状态、外部输出和清理结果一起恢复。若只修正最终输出，却留下描述符、子进程、堆块、锁或错误映射，验收仍然失败。

中文第三版采用 x86-64、Linux 和 Y86-64 教学处理器。现代 CPU、内核和工具链会改变微结构、默认安全机制与性能数值，但固定宽度表示、指令语义、缓存局部性、符号重定位、进程地址空间、字节流接口和同步不变量仍然成立。现代对照必须标明差异，不能覆盖原书问题身份。

## 状态与失败矩阵

| 观察层     | 正常轨迹             | 边界样本             | 失败证据             | 恢复条件               |
| ---------- | -------------------- | -------------------- | -------------------- | ---------------------- |
| 表示与制品 | 位宽、格式、符号明确 | 溢出、截断、缺失定义 | 字节、节与重定位位置 | 使用同一可追溯制品重放 |
| 机器与存储 | 指令和地址映射有效   | 冒险、未命中、缺页   | 首个寄存器或地址分叉 | 重置到已知机器状态     |
| 进程与资源 | 所有权和生命周期闭合 | 短计数、信号、容量   | 系统调用和资源快照   | 逆序清理后重试         |
| 通信与并发 | 协议和同步边完整     | 断连、交错、竞争     | 字节流、锁与进度图   | 相同输入可重复通过     |

## 常见误区与故障注入

<Callout type="trap">
  **误区一：源码与最终输出正确就代表系统正确。**
  中间仍可能存在未定义行为、错误重定位、缓存退化、资源泄漏或竞争；必须检查首个状态变化与清理结果。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据               | 通过条件     |
| ---- | -------------------------- | ---------------------- | ------------ |
| 正常 | 固定源码、工具链和输入     | 全阶段状态与输出       | 与预测一致   |
| 边界 | 极值、空输入、低容量       | 范围、终止与资源状态   | 不越界不泄漏 |
| 失败 | 错地址、缺依赖、断连或竞争 | 首个错误与责任层       | 失败被隔离   |
| 恢复 | 删除故障后重放             | 制品、状态、输出和清理 | 回到受控结果 |

## 练习

<Exercises>

**问题 1** 为什么不能只看最终输出验收附录 A 错误处理？

<Answer>
  最终输出会隐藏中间位模式、目标制品、地址翻译、资源所有权和并发次序。必须先预测，保存首个偏离点，删除故障后再以同一输入重放。
</Answer>

**问题 2** 如何把“附录A 错误处理”变成可执行证据？

<Answer>
  依次沿“调用系统接口、检查返回值、保存错误码、补充调用上下文、清理已获资源、传播或终止”登记输入、状态、责任接口、边界、失败出口和恢复条件，并让正常、边界、失败、恢复四类样本都留下可比较快照。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  错误码只在失败返回后读取；诊断保留原始原因和调用上下文，任何部分成功获得的资源都沿唯一逆序路径清理。
  同时，异常路径不会污染下一次运行，所有已获得资源都有唯一清理路径，恢复轨迹重新达到正常样本的状态与输出。
</Answer>

</Exercises>

## 小结

- errno：连接“调用系统接口”的输入与状态。
- 返回值：连接“检查返回值”的责任接口。
- 错误路径：连接“保存错误码”的边界条件。
- 包装函数：连接“补充调用上下文”的失败传播。
- 失败原子性：连接“清理已获资源”的恢复证据。
