## 为什么学习地图必须服从原书目录

本书不是十个“热门特性”的选读集，而是从C#语言规则一路推进到.NET数据、资源与I/O、metadata/dynamic、并发低层和text engine的25章系统参考。跳过中段会产生假理解：会写async却不懂Dispose和Stream owner，会用reflection却不懂assembly identity，会用Span却忽略native lifetime。

先预测：只学第1-4章能设计可靠网络服务吗；掌握Task就等于掌握thread safety吗；会写P/Invoke签名就不必学GC/pinning吗；Regex validation不需要资源上限吗；读完25章就自动具备迁移能力吗。答案都是否。

<Term def="以官方25章为唯一骨架，所有页面、复习题和验收证据都能映射回对应章节。">official-outline spine</Term>

## 路径一：Language（Chapters 1-4）

1. **Introducing C# and .NET**：对象、类型安全、内存、平台、CLR/BCL/runtime与C# 10变化。
2. **C# Language Basics**：编译、语法、类型、数值、字符串、数组、变量、表达式、语句与namespace。
3. **Creating Types in C#**：class/inheritance/object/struct/interface/enum/nested type/generic。
4. **Advanced C#**：delegate/event/lambda/exception/iterator/nullability/record/pattern/attribute/dynamic/operator/unsafe。

这四章建立编译器与类型系统模型。验收不是背语法，而是能预测overload、conversion、allocation、dispatch、exception和nullable flow。

```csharp
public abstract record Outcome;
public sealed record Accepted(Guid Id) : Outcome;
public sealed record Rejected(string Code) : Outcome;

static string Describe(Outcome outcome) => outcome switch
{
    Accepted { Id: var id } => $"accepted:{id:N}",
    Rejected { Code: var code } => $"rejected:{code}",
    _ => throw new UnreachableException()
};
```

这段代码同时要求type hierarchy、record value model、property pattern与exhaustiveness reasoning。

## 路径二：.NET and Data（Chapters 5-11）

5. **.NET Overview**：runtime、BCL、system types、兼容与application layers。
6. **.NET Fundamentals**：text、date/time、format/parse、globalization、number、Guid、equality/order。
7. **Collections**：enumeration、list/array/set/dictionary、immutable collection与comparer。
8. **LINQ Queries**：query expression、deferred execution、composition、provider expression tree与EF Core。
9. **LINQ Operators**：filter/project/join/order/group/set/aggregate/quantifier等operator semantics。
10. **LINQ to XML**：X-DOM、functional construction、query/update、namespace与streaming projection。
11. **Other XML and JSON Technologies**：XmlReader/Writer与System.Text.Json streaming/DOM lifetime。

这一段的共同门禁是semantic identity：字符串比较用什么culture，DateTime表示什么时间线，Dictionary/GroupBy如何判等，LINQ在内存还是provider执行，JSON missing/null/unknown如何映射。

<Stepper>
  <Step title="切换language、.NET/data、runtime与advanced路线"></Step>
  <Step title="标出前置边">把每个目标能力连接到前置章节，例如网络依赖URI、stream、async与disposal。</Step>
  <Step title="选择最小闭环">每次选一条从语言语义到边界验收的完整路径，不按页面数量冲进度。</Step>
</Stepper>

<Callout type="trap" title="把LINQ、XML和JSON当成互不相干的API章节">
它们共享deferred execution、enumeration、schema、identity、buffer和owner问题。只记方法名会在provider translation、disposed DOM和unknown字段上失败。
</Callout>

<Term def="把value、equality/order、deferred execution、schema与lifetime写成可测试输入输出的读取方式。">semantic reading lens</Term>

## 路径三：Runtime Services（Chapters 12-17）

12. **Disposal and Garbage Collection**：IDisposable、roots、generations、finalizers、pool、leak与weak reference。
13. **Diagnostics**：Debug/Trace、process/thread/stack、counter、Stopwatch与跨平台toolchain。
14. **Concurrency and Asynchrony**：thread/pool/context/Task/async stream/cancel/combinator/async lock。
15. **Streams and I/O**：partial I/O、adapter、compression、atomic file、OS security与memory map。
16. **Networking**：address/URI、HttpClient/server、DNS、SMTP与TCP framing。
17. **Assemblies**：manifest/metadata/IL、signing/resources、load context与plugin lifecycle。

Runtime路线的核心是owner timeline：谁创建、谁等待、谁取消、谁释放、失败时半成品是否可见。GC只管理不可达managed memory，不替你关闭stream、停止task或卸载plugin。

```csharp
static async Task<Result> FetchAsync(HttpClient client, Uri uri, CancellationToken ct)
{
    using HttpResponseMessage response = await client.SendAsync(
        new HttpRequestMessage(HttpMethod.Get, uri),
        HttpCompletionOption.ResponseHeadersRead, ct);
    response.EnsureSuccessStatusCode();
    await using Stream body = await response.Content.ReadAsStreamAsync(ct);
    return await ParseBoundedAsync(body, maxBytes: 1_000_000, ct);
}
```

一段看似普通的HTTP代码同时穿过URI identity、handler/response/stream ownership、async cancellation、partial I/O、JSON limits和diagnostics。

## 路径四：Metadata and Dynamic（Chapters 18-20）

18. **Reflection and Metadata**：Type/member binding、attribute、dynamic code、emit与IL parse。
19. **Dynamic Programming**：DLR、runtime overload、visitor、DynamicObject/Expando与language bridge。
20. **Cryptography**：DPAPI、hash/HMAC、password KDF、AEAD、key management与public-key signing。

三章都在处理“晚绑定边界”：reflection延迟成员选择，dynamic延迟类型检查，cryptographic envelope延迟按key/version解释bytes。晚绑定必须用identity、allowlist、version和fail-closed补回静态保障。

<Stepper>
  <Step title="切换type、owner、boundary与evidence"></Step>
  <Step title="为当前机制填四格">例如reflection写type identity、cache owner、execution boundary和trimmed-product test。</Step>
  <Step title="寻找缺失格">任何没有owner、limit、version或evidence的格子都是后续实现风险。</Step>
</Stepper>

<Term def="当成员、shape、key或格式在运行时决定时，用identity、version、allowlist与失败策略补回保障。">late-binding safety envelope</Term>

## 路径五：Concurrency and Low-level（Chapters 21-24）

21. **Advanced Threading**：exclusive/nonexclusive locks、signals、Barrier、Lazy、thread local与timer。
22. **Parallel Programming**：PFX、PLINQ、Parallel、Task scheduler、aggregate fault、concurrent queue。
23. **Span&lt;T&gt; and Memory&lt;T&gt;**：slice/copy/text、async memory、enumerator、stack/native storage。
24. **Native and COM Interoperability**：P/Invoke、marshaling、callback、shared memory与COM双向边界。

这一路线风险最高，因为错误可能跨thread、heap、process和ABI延迟爆发。所有优化先有sequential/safe baseline，再证明throughput、allocation或interop需求值得增加复杂度。

```csharp
static async Task ConsumeAsync(ChannelReader<IMemoryOwner<byte>> reader, CancellationToken ct)
{
    await foreach (IMemoryOwner<byte> owner in reader.ReadAllAsync(ct))
    {
        using (owner)
            Process(owner.Memory.Span);
    }
}
```

这里必须同时守住bounded queue、async completion、pooled memory owner与Span同步lifetime。

## 路径六：Text（Chapter 25）

25. **Regular Expressions**：engine/compile/options、escape/set/quantifier、greedy/lazy、assertion/lookaround/anchor/group、replace/split与recipes。

Regex是受预算约束的小程序。Pattern正确只是起点，还要限制input/output、显式timeout，并用near-miss证明不会因回溯阻塞服务。

<Callout type="trap" title="先学高级章节，遇到问题再补基础最快">
低层章节会同时依赖类型、resource、async、stream和assembly identity。缺少前置模型时只能复制API，无法解释lifetime和failure，返工成本更高。
</Callout>

<Term def="每章用预测、状态/owner追踪、故障注入和陌生案例迁移形成的四步验收。">predict-trace-break-transfer loop</Term>

## 本章回顾：从目录走向工程判断

1. 25章是连续体系，不是十个主题采样。
2. Language定义合法程序，Data定义语义，Runtime定义owner和completion。
3. Metadata/dynamic需要晚绑定安全壳，low-level需要精确lifetime。
4. 每章必须有预测、追踪、负测和迁移证据。
5. 最终目标是能为新问题选择正确chapter、contract和gate。

<Exercises>

**问题 1：设计HTTP插件服务的最小学习路径。**

<Answer>先完成1-4的type/delegate/exception，6-11的URI/collection/JSON schema，12-16的Dispose/diagnostics/async/stream/network，再学17-19的ALC/reflection/dynamic；若插件含native再补23-24。每段都以owner、version、fault test交付。</Answer>

**问题 2：怎样证明不是“读完”而是“掌握”第14章？**

<Answer>能预测Task/thread/context差异，画await state与cancellation owner，复现sync-over-async deadlock、starvation和WhenAny loser leak，并把同一contract迁移到一个新的bounded async pipeline。</Answer>

**问题 3：为什么第25章仍依赖前面章节？**

<Answer>Regex input是text/globalization问题，compiled/cache有runtime/deployment成本，timeout/cancel进入服务completion contract，replace输出有memory/stream上限，untrusted pattern属于security boundary；它不是孤立语法表。</Answer>
