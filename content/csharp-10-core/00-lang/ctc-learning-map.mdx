## 直觉引入

如果你要建造一栋大楼，你不会先装窗户再打地基。C# 10 的知识体系也是如此——类型系统是地基，异步并发是框架结构，现代特性是精装修。

C# 10 不是一个孤立的版本，它是 C# 二十年演进的集大成者。类型系统总览让你看清值类型与引用类型的分界；泛型深入让你理解 `List<T>` 背后的类型安全机制；异步深入让你掌握 `async/await` 的状态机本质；模式匹配和 record 让你用函数式思维写命令式代码。

本书以「核心特性深度」为全书主线——不追求覆盖 C# 的每个角落，而是把最关键的十个技术点钻透，让你从「会用 C#」升级到「理解 C#」。

## 概念讲解

### 四大板块

全书按技术领域分为四个板块，每个板块对应 C# 核心能力的一个维度：

1. **语言核心**（第 1-2 章）：学习地图与类型系统总览。建立全景认知，理解 C# 10 的值类型、引用类型、装箱与可空类型。
2. **类型系统**（第 3-4 章）：泛型深入与委托事件。从 `List<T>` 的类型参数到委托的类型安全回调，覆盖类型系统最核心的两个机制。
3. **异步并发**（第 5-6 章）：异步深入与并行 TPL。从 `async/await` 的状态机到 `Parallel.For` 的数据并行，覆盖 C# 最有价值的并发能力。
4. **现代特性**（第 7-10 章）：模式匹配、Record 与结构体、源生成器、总复习。覆盖 C# 7.0-10.0 引入的函数式风格与编译时编程能力。

### 为什么按这个顺序学

<Term def="类型系统是 C# 的地基：值类型与引用类型的内存模型决定了装箱、赋值、参数传递的一切行为。泛型和委托都建立在类型系统之上——泛型是类型参数化，委托是类型安全的函数引用。">

类型系统是全书的地基。不理解值类型与引用类型的内存差异，就无法理解装箱的性能开销和 `record struct` 的设计动机。泛型深入建立在类型系统之上——泛型本质是类型参数化，理解类型系统才能理解泛型约束的边界。委托与事件同样建立在类型系统之上——委托是类型安全的函数引用，它的「类型安全」来自类型系统的签名检查。

异步并发是类型系统之上的能力层。`async/await` 的状态机大量使用泛型（`Task<T>`）和委托（continuation）。并行 TPL 的 `Parallel.For` 和 PLINQ 依赖泛型委托 `Action<T>`。

现代特性是类型系统与异步能力的组合应用。模式匹配需要类型系统支持（类型模式、属性模式）；Record 是引用类型的值语义封装，`record struct` 是值类型的值语义封装；源生成器在编译时生成代码，需要理解类型系统的元数据。

</Term>

### 学习路径建议

**推荐路径**：语言核心（学习地图→类型系统总览）→ 类型系统（泛型→委托事件）→ 异步并发（异步→并行TPL）→ 现代特性（模式匹配→Record→源生成器→总复习）。

类型系统两章必须按顺序学：类型系统总览是泛型的基础。异步并发两章建议按顺序学：异步深入是并行 TPL 的基础——`Task` 是两者的共同抽象。现代特性中模式匹配应先学，Record 依赖模式匹配做解构，源生成器需要理解类型元数据。

## 代码对照

```csharp
// C# 10 核心特性速览：同一段「处理用户列表」逻辑在不同特性下的写法

// 基础写法（C# 1.0 风格）
List<User> activeUsers = new List<User>();
foreach (User u in users)
{
    if (u.IsActive && u.Age >= 18)
        activeUsers.Add(u);
}

// 泛型 + Lambda + LINQ（C# 3.0+）
var activeUsers = users.Where(u => u.IsActive && u.Age >= 18).ToList();

// 模式匹配（C# 8.0+）
var activeAdults = users
    .Where(u => u is { IsActive: true, Age: >= 18 })
    .ToList();

// Record + 模式匹配 + 顶层语句（C# 10）
record User(string Name, int Age, bool IsActive);

var activeAdults = users
    .Where(u => u is { IsActive: true, Age: >= 18 })
    .Select(u => u with { Name = u.Name.ToUpper() })
    .ToList();
```

从基础循环到 LINQ 到模式匹配再到 Record 的 `with` 表达式——每一步简化都建立在更底层特性的基础上。

## 常见误区

<Callout type="trap">

**误区：跳过类型系统直接学异步**

async/await 的 `Task<T>` 是泛型类型，continuation 使用委托，状态机字段涉及值类型与引用类型的内存布局。不理解类型系统就读不懂编译器生成的状态机代码，更无法理解为什么 `ValueTask` 比 `Task` 省分配。类型系统是地基，跳过地基建楼会塌。

</Callout>

<Callout type="trap">

**误区：把 C# 10 当 C# 7 学**

C# 8.0 的可空引用类型、C# 9.0 的 record 和顶层语句、C# 10 的 record struct 和 global using——这些不是「语法糖」，它们改变了写代码的方式。如果只用 C# 7 的思维写 C# 10，会错过类型安全保证、数据建模简洁性和编译时编程能力。C# 10 是多范式语言，要用现代特性发挥它的全部威力。

</Callout>

<Exercises>

**问题 1**：本书为什么把「类型系统」放在第一章而不是「异步编程」？

<Answer>

类型系统是 C# 的地基。值类型与引用类型的内存模型决定了装箱、赋值、参数传递的一切行为。泛型是类型参数化，委托是类型安全的函数引用——两者都建立在类型系统之上。async/await 的 `Task<T>` 是泛型类型，continuation 使用委托。不理解类型系统，就无法理解泛型约束、委托的签名检查、`ValueTask` 的省分配原理。先打地基再建楼，这是知识结构的必然顺序。

</Answer>

**问题 2**：C# 10 的 record struct 和 C# 9 的 record 有什么本质区别？为什么需要区分？

<Answer>

`record`（C# 9）是引用类型——分配在堆上，赋值是引用复制，两个变量指向同一个对象。`record struct`（C# 10）是值类型——分配在栈上（或内联在对象中），赋值是值复制，两个变量是独立副本。区别的本质是值语义与引用语义的选择：小型不可变数据（如坐标点、颜色）用 `record struct` 避免堆分配；需要共享身份的大型数据用 `record`。C# 10 让值类型也拥有 record 的值相等、解构和 `with` 表达式能力。

</Answer>
