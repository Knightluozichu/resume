## 直觉引入

你给物业公司留了一个电话号码，说「有快递到了就打这个电话通知我」。这个电话号码就是一个**委托**——你把「通知我」这个行为委托给了物业，物业不需要知道你是谁、住哪里，只需要在特定事件发生时拨这个号码。

委托定义了「打电话的规则」（签名：传什么参数、返回什么），任何符合规则的人（方法）都可以被登记。你可以留多个电话号码（多播），快递到了所有号码都会被拨打。

`event` 关键字则像是物业的公告板——外部人只能在上面贴自己的电话号码（`+=` 订阅）或撕掉自己的号码（`-=` 取消），但不能替别人贴/撕，也不能自己假装快递到了去打电话（只有物业能触发）。

## 概念讲解

### 委托：类型安全的函数引用

<Term def="委托（delegate）是 C# 中类型安全的函数引用。它定义了方法的签名（参数类型和返回类型），任何匹配该签名的方法都可以赋给委托实例。委托继承自 System.MulticastDelegate，支持多播（一个委托实例包含多个方法）。">

委托的核心是**签名契约**。声明 `delegate void Handler(string msg)` 后，任何接受 `string` 参数、返回 `void` 的方法都能赋给它。编译器在赋值时检查签名匹配——不匹配会编译报错。

委托继承自 `System.MulticastDelegate`，是面向对象的——可以携带目标对象（实例方法的 `this`），可以链式调用（多播）。

</Term>

### 内置委托类型

C# 内置了一组通用委托，避免每次都自定义 `delegate`：

- `Action` / `Action<T>` / `Action<T1,T2>` — 无返回值，最多 16 个参数
- `Func<TResult>` / `Func<T,TResult>` — 有返回值
- `Predicate<T>` — 返回 `bool`，用于条件判断

### event：对委托的封装

<Term def="事件（event）是对委托字段的封装，提供发布-订阅模式的访问控制。外部只能 += 订阅和 -= 取消，不能 = 覆盖或直接 Invoke。只有声明类内部才能触发事件。">

`public event EventHandler Click;` 和 `public EventHandler Click;` 的区别：

- **委托字段**：外部可以 `=` 覆盖（清除所有订阅者）、可以 `()` 直接调用（伪造事件触发）。
- **event**：外部只能 `+=` 和 `-=`，不能覆盖、不能直接调用。只有声明类内部能 `Click?.Invoke()` 触发。

event 本质是「对委托字段的封装」，类似 property 对字段的封装。

</Term>

### 多播委托

一个委托实例可以包含多个方法（`+=` 添加）。调用时按顺序全部执行。如果某个方法抛异常，后面的方法不会被执行——异常直接传播给调用者。

<Step title="委托定义与方法绑定">

委托定义签名契约：`delegate void Handler(string msg)`。任何匹配签名的方法都可以赋给委托实例。委托携带目标对象的 `this`，可以调用实例方法。与 C++ 函数指针不同，委托有编译时类型检查。

</Step>

<Step title="内置委托：Action 与 Func">

`Action<string>` 等价于 `delegate void Handler(string)`。`Func<int,int,string>` 等价于 `delegate string Handler(int,int)`。C# 3.0 后几乎不再需要自定义委托——用 `Action` 和 `Func` 即可，Lambda 直接赋值。

</Step>

<Step title="event 封装：发布-订阅控制">

`event Handler Click` 限制外部只能 `+=`/`-=`，防止外部覆盖订阅者或伪造触发。只有声明类内部能 `Click?.Invoke(args)`。编译后生成 private 委托字段 + public `add_Click`/`remove_Click` 方法。

</Step>

<Step title="多播调用链与异常隔离">

`Click += HandlerA; Click += HandlerB;` 后，触发 Click 时按 A→B 顺序调用。如果 A 抛异常，B 不会被调用。关键场景需要用 `GetInvocationList()` 逐个调用并 try-catch 隔离异常。

</Step>

</Stepper>

## 代码对照

```csharp
// 委托与事件：从自定义到内置到 event 封装

// === 自定义委托（C# 1.0 风格）===
public delegate void ClickHandler(object sender, EventArgs e);

class Button
{
    public event ClickHandler? Click;  // event 封装

    public void SimulateClick() => Click?.Invoke(this, EventArgs.Empty);
}

// === 内置委托（C# 3.0+ 推荐）===
class ModernButton
{
    // 用 Action/Func 代替自定义 delegate
    public event Action<object, EventArgs>? Click;

    public void SimulateClick() => Click?.Invoke(this, EventArgs.Empty);
}

// 使用
var btn = new ModernButton();
btn.Click += (sender, e) => Console.WriteLine("Clicked!");  // Lambda 订阅

// === 多播异常隔离 ===
var button = new ModernButton();
button.Click += (s, e) => Console.WriteLine("Handler A");
button.Click += (s, e) => throw new InvalidOperationException("Boom!");
button.Click += (s, e) => Console.WriteLine("Handler C");

// 不安全：B 抛异常后 C 不执行
// button.SimulateClick();

// 安全：逐个调用并隔离异常
var clickField = typeof(ModernButton)
    .GetField("Click", System.Reflection.BindingFlags.NonPublic | System.Reflection.BindingFlags.Instance)
    ?.GetValue(button) as ClickHandler;

// 更实际的做法：在自己的类中暴露 GetInvocationList
public class SafeEvent
{
    public event Action<string>? OnMessage;

    public void RaiseAll(string msg)
    {
        if (OnMessage is null) return;
        foreach (var handler in OnMessage.GetInvocationList())
        {
            try { ((Action<string>)handler)(msg); }
            catch (Exception ex) { Console.WriteLine($"Handler failed: {ex.Message}"); }
        }
    }
}
```

## 常见误区

<Callout type="trap">

**误区：event 和 public 委托字段效果一样**

`public event Handler Click` 和 `public Handler Click` 有本质区别。委托字段可以被外部 `=` 覆盖（清除所有订阅者）或直接 `()` 调用（伪造事件触发）。event 强制外部只能 `+=`/`-=`，保护了发布-订阅语义。就像你不会把变量设为 public 而是用属性封装一样，回调也应该用 event 封装。

</Callout>

<Callout type="trap">

**误区：总是需要自定义委托类型**

C# 3.0 以后，`Action`、`Func`、`Predicate` 覆盖了绝大多数场景。自定义 `delegate` 只在需要特殊语义名称（如 `ClickHandler` 比 `Action<object,EventArgs>` 更有表达力）或需要 `out`/`ref` 参数时才有必要。过度自定义委托类型会增加代码冗余，降低可读性。

</Callout>

<Exercises>

**问题 1**：为什么有了委托还需要 event 关键字？

<Answer>

event 对委托字段提供访问控制：外部只能 `+=`/`-=` 订阅和取消，不能 `=` 覆盖（防止清除其他订阅者）或直接 `Invoke`（防止伪造事件触发）。只有声明类内部能触发事件。event 本质是对委托字段的封装，类似 property 对字段的封装。

</Answer>

**问题 2**：`Action<T>` 和 `Func<T,TResult>` 的区别是什么？`Predicate<T>` 等价于哪个？

<Answer>

`Action<T>` 表示无返回值的方法（`void`），接受一个 `T` 参数。`Func<T,TResult>` 表示有返回值的方法，接受一个 `T` 参数并返回 `TResult`。`Predicate<T>` 表示返回 `bool` 的方法，接受一个 `T` 参数——等价于 `Func<T,bool>`。`Predicate<T>` 语义更明确（专用于条件判断），但功能上与 `Func<T,bool>` 完全相同。LINQ 的 `Where` 接受 `Func<T,bool>` 而非 `Predicate<T>`。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="委托（delegate）">

类型安全的函数引用。定义方法签名，匹配签名的方法可赋给委托实例。继承自 `System.MulticastDelegate`，支持多播和目标对象携带。是回调体系的基石。

</GlossaryItem>

<GlossaryItem term="事件（event）">

对委托字段的封装。外部只能 `+=`/`-=` 订阅，不能覆盖或直接调用。编译后生成 private 委托字段 + public add/remove 方法。

</GlossaryItem>

<GlossaryItem term="Action / Func / Predicate">

内置通用委托。`Action` 无返回值，`Func` 有返回值，`Predicate<T>` 返回 `bool`。C# 3.0 后基本取代自定义委托。

</GlossaryItem>

<GlossaryItem term="多播委托">

一个委托实例包含多个方法（`+=` 添加）。调用时按顺序全部执行。某个方法抛异常则后续方法不执行。可用 `GetInvocationList()` 逐个调用隔离异常。

</GlossaryItem>

</Glossary>
