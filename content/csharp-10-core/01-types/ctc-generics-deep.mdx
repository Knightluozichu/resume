## 直觉引入

想象一个快递柜。老式快递柜（`ArrayList`）每个格子都一样大，什么都能放，但取的时候你得自己确认「这到底是不是我的包裹」（类型不安全，还要拆箱）。新型快递柜（`List<T>`）在建造时就标明了「这一排只放书」，放错东西会被拒绝，取出来一定是书。

泛型就是「建造时标明类型」的机制。`List<T>` 中的 `T` 是类型参数——你在使用时指定 `T` 是 `int` 还是 `string`，编译器据此生成类型安全的代码。这比 `ArrayList` 的 `object` 方案多了编译时类型检查、消除了装箱开销。

## 概念讲解

### 泛型的类型参数化

<Term def="泛型（generic）是将类型作为参数的机制。类、接口、方法、委托都可以泛型化。泛型类型在编译时为所有引用类型参数共享同一份本机代码，为值类型参数生成各自的副本（避免装箱）。">

`List<T>` 是泛型类型，`T` 是类型参数。使用时用具体类型替换 `T`：`List<int>`、`List<string>`。编译器保证类型安全——`List<int>.Add("hello")` 编译报错。

C# 泛型与 Java 泛型有本质区别：Java 泛型是「类型擦除」（编译后 `List<T>` 变成 `List<Object>`，运行时无类型参数信息）；C# 泛型在运行时保留类型参数信息（reified generics），`typeof(List<int>)` 和 `typeof(List<string>)` 是不同的 Type 对象。

</Term>

### 泛型约束

约束（`where`）限制类型参数的范围，让编译器知道 `T` 有哪些能力：

- `where T : class` — T 必须是引用类型
- `where T : struct` — T 必须是值类型（不可空）
- `where T : new()` — T 必须有公共无参构造函数
- `where T : IComparable<T>` — T 必须实现指定接口
- `where T : BaseClass` — T 必须继承指定基类
- `where T : notnull` — T 不可为 null（可空上下文）

### 协变与逆变

<Term def="协变（covariance，out）允许将派生程度更大的泛型类型赋给派生程度更小的泛型类型。逆变（contravariance，in）允许相反方向的赋值。C# 在接口和委托上支持协变逆变，类不支持。">

协变和逆变解决的问题是：`IEnumerable<Derived>` 能否赋给 `IEnumerable<Base>`？

- **协变（out）**：`IEnumerable<out T>`。如果你只从泛型类型中**读取** T（输出），那么 `IEnumerable<Dog>` 可以赋给 `IEnumerable<Animal>`。安全，因为读取的一定是 Dog，也是 Animal。
- **逆变（in）**：`Action<in T>`。如果你只向泛型类型中**写入** T（输入），那么 `Action<Animal>` 可以赋给 `Action<Dog>`。安全，因为接受 Animal 的函数也能接受 Dog。
- **不变（invariant）**：`List<T>`。既读又写，不能协变也不能逆变。否则 `List<Dog>` 赋给 `List<Animal>` 后 `Add(new Cat())` 就能编译通过——类型安全被破坏。

</Term>

<Step title="类型参数化：编译时确定类型">

`List<T>` 中的 `T` 是占位符。使用 `List<int>` 时编译器用 `int` 替换 `T`，生成类型安全的代码。值类型参数（如 `int`）会生成专用的本机代码副本，避免装箱。引用类型参数（如 `string`、`Person`）共享同一份代码。

</Step>

<Step title="约束：限制 T 的能力">

`where T : IComparable<T>` 告诉编译器 T 实现了 `IComparable<T>`，于是可以调用 `T.CompareTo(T)`。`where T : new()` 允许 `new T()`。约束是编译器与开发者的契约——你承诺 T 有某些能力，编译器据此放宽限制。

</Step>

<Step title="协变（out）：安全读取">

`IEnumerable<out T>` 标记 T 是输出位置。`IEnumerable<Dog>` 可以赋给 `IEnumerable<Animal>`——因为从里面读出的 Dog 一定是 Animal。协变只适用于「只读」接口，T 只出现在返回值位置。

</Step>

<Step title="逆变（in）：安全写入">

`Action<in T>` 标记 T 是输入位置。`Action<Animal>` 可以赋给 `Action<Dog>`——因为接受 Animal 参数的函数，传入 Dog 也没问题。逆变只适用于「只写」接口，T 只出现在参数位置。

</Step>

</Stepper>

## 代码对照

```csharp
// 泛型深入：参数化、约束、协变逆变

// === 类型参数化 ===
public class Repository<T> where T : class
{
    private readonly List<T> _items = new();

    public void Add(T item) => _items.Add(item);  // 类型安全
    public T Get(int index) => _items[index];      // 无装箱
}

// === 泛型方法 + 多约束 ===
public static T CreateAndCompare<T>(T a, T b)
    where T : IComparable<T>, new()
{
    T default_ = new T();           // 约束允许 new T()
    return a.CompareTo(b) > 0 ? a : b;  // 约束允许 CompareTo
}

// === 协变（out）===
public interface IProducer<out T>
{
    T Produce();  // T 只在返回位置 → 协变安全
}

IProducer<Dog> dogProducer = new DogFactory();
IProducer<Animal> animalProducer = dogProducer;  // 协变：合法
Animal a = animalProducer.Produce();              // 读出 Dog，是 Animal

// === 逆变（in）===
public interface IConsumer<in T>
{
    void Consume(T item);  // T 只在参数位置 → 逆变安全
}

IConsumer<Animal> animalConsumer = new AnimalFeeder();
IConsumer<Dog> dogConsumer = animalConsumer;  // 逆变：合法
dogConsumer.Consume(new Dog());  // 传 Dog 给接受 Animal 的函数

// === 不变（List<T>）===
// List<Dog> dogs = new List<Dog>();
// List<Animal> animals = dogs;  // 编译错误！List<T> 不变
// 原因：如果合法，animals.Add(new Cat()) 就破坏了 dogs 的类型安全

// 基类与接口
class Animal { }
class Dog : Animal { }
class DogFactory : IProducer<Dog> { public Dog Produce() => new(); }
class AnimalFeeder : IConsumer<Animal> { public void Consume(Animal a) { } }
```

## 常见误区

<Callout type="trap">

**误区：C# 泛型和 Java 泛型一样有类型擦除**

Java 泛型在编译后擦除类型参数——`List<String>` 变成 `List<Object>`，运行时无法知道 `T` 是什么。C# 泛型在运行时保留类型参数（reified）——`typeof(List<int>)` 是一个独立的 Type 对象。这意味着 C# 泛型可以做 Java 做不到的事：值类型泛型不装箱、运行时反射获取类型参数、`typeof(T)` 在方法内可用、方法重载可以按泛型参数的运行时类型区分。

</Callout>

<Callout type="trap">

**误区：List\<Dog> 可以赋给 List\<Animal> 因为 Dog 是 Animal 的子类**

`List<T>` 是不变（invariant）的——既可读又可写。如果允许 `List<Dog>` 赋给 `List<Animal>`，你就能 `animals.Add(new Cat())`，而 animals 实际指向的是 `List<Dog>`——类型安全被破坏。协变只适用于「只读」接口（`IEnumerable<out T>`），逆变只适用于「只写」接口（`Action<in T>`）。`List<T>` 两个方向都不安全，所以不变。

</Callout>

<Exercises>

**问题 1**：为什么 `where T : new()` 约束不能与 `where T : struct` 同时使用？

<Answer>

`struct` 始终有隐式的公共无参构造函数（初始化为零值），所以 `new T()` 总是可用的，不需要 `new()` 约束。编译器将 `struct` 和 `new()` 视为互斥——如果 T 已经是值类型，`new T()` 一定合法，加 `new()` 约束是冗余的。同理，`where T : class` 和 `where T : struct` 互斥——T 不可能既是引用类型又是值类型。

</Answer>

**问题 2**：为什么 `IEnumerable<out T>` 可以协变而 `IList<T>` 不能？请从类型安全角度分析。

<Answer>

`IEnumerable<out T>` 只暴露读取方法（`GetEnumerator`），T 只出现在返回值位置。协变是安全的：`IEnumerable<Dog>` 赋给 `IEnumerable<Animal>` 后，从中读出的每个元素都是 Dog，一定是 Animal，不会出错。

`IList<T>` 同时暴露读（`this[int]` getter）和写（`Add(T)`、`this[int]` setter）。如果允许 `IList<Dog>` 赋给 `IList<Animal>`，你就能调用 `animals.Add(new Cat())`——但实际存储是 `List<Dog>`，存入 Cat 破坏了类型安全。所以既可读又写的泛型接口必须不变（invariant），不能协变也不能逆变。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="类型参数化">

将类型作为参数的机制。`List<T>` 中 `T` 是占位符，使用时用具体类型替换。编译器保证类型安全，值类型泛型不装箱。

</GlossaryItem>

<GlossaryItem term="泛型约束（where）">

限制类型参数的范围。`where T : class` 引用类型、`struct` 值类型、`new()` 有无参构造、接口/基类约束。让编译器知道 T 的能力。

</GlossaryItem>

<GlossaryItem term="协变（out）">

允许 `IEnumerable<Derived>` 赋给 `IEnumerable<Base>`。T 只出现在输出（返回值）位置。只读接口可协变。

</GlossaryItem>

<GlossaryItem term="逆变（in）">

允许 `Action<Base>` 赋给 `Action<Derived>`。T 只出现在输入（参数）位置。只写接口可逆变。

</GlossaryItem>

</Glossary>
