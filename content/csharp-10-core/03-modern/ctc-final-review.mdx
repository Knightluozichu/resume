## 直觉引入

你已经走完了 C# 10 核心技术指南的全部十章。现在是退后一步、看清全景的时候。

C# 10 的十大特性不是孤立的——它们构成一条因果链：类型系统是地基，泛型和委托筑墙，异步并发拓边界，模式匹配与 Record 装修，源生成器在建造时自动化。每个特性都建立在前一个的基础上，理解这条链比记住每个语法更重要。

总复习的目标不是重复每章的内容，而是把散落的拼图拼成完整画面——理解 C# 10 为什么这样设计，以及在实际项目中如何组合这些特性。

## 概念讲解

### 十大特性因果链

<Term def="C# 10 的十大特性构成一条因果链：类型系统（值/引用类型）是地基 → 泛型（类型参数化）和委托（类型安全回调）筑墙 → async/await（状态机）和 TPL（多核并行）拓边界 → 模式匹配（声明式条件）、Record（值语义数据）、源生成器（编译时代码生成）装修。每个特性都建立在前一个的基础上。">

1. **类型系统总览**：值类型 vs 引用类型、装箱、可空引用类型。是所有后续特性的地基——泛型、委托、异步、Record 都建立在类型系统之上。
2. **泛型深入**：类型参数化、约束、协变逆变。建立在类型系统之上——`Task<T>` 是泛型，`List<T>` 消除装箱。
3. **委托与事件**：类型安全回调、event 封装、多播。建立在类型系统之上——委托的「类型安全」来自类型系统的签名检查。异步的 continuation 是委托。
4. **异步深入**：async/await 状态机、Task/ValueTask、同步上下文。建立在泛型（`Task<T>`）和委托（continuation）之上。
5. **并行与 TPL**：Parallel.For、PLINQ、Task.Run。建立在泛型委托（`Action<T>`）和 Task 之上。
6. **模式匹配**：类型模式、属性模式、switch 表达式、列表模式。建立在类型系统之上——类型模式和属性模式依赖类型系统。
7. **Record 与结构体**：record（引用+值语义）、record struct（值+值语义）、with 表达式。建立在类型系统之上——record 和 record struct 是类型系统的两个维度。
8. **源生成器**：编译时代码生成、增量管线。建立在类型系统的元数据之上——生成器分析类型信息生成代码。

</Term>

### C# 10 的设计理念

C# 10 体现了三个设计理念：

1. **类型安全优先**：泛型消除装箱、可空引用类型防 null、委托检查签名。C# 在编译时尽可能捕获错误。
2. **多范式融合**：OOP（class）、函数式（record、模式匹配、不可变）、命令式（循环、可变）、声明式（LINQ、模式匹配）。C# 10 不强制单一范式。
3. **性能不妥协**：`ValueTask` 省分配、`Span<T>` 零拷贝、源生成器消除反射、`record struct` 避免堆分配。安全与性能兼得。

### 组合应用

实际项目中，这些特性经常组合使用：

- **API 控制器**：record（请求/响应 DTO）+ async/await（数据库查询）+ 模式匹配（结果处理）+ 源生成器（JSON 序列化）。
- **事件驱动系统**：委托与事件（发布订阅）+ async/await（异步处理器）+ record（事件数据）+ 模式匹配（事件路由）。
- **数据管道**：泛型（通用处理器）+ PLINQ（并行处理）+ record struct（数据载体）+ 源生成器（序列化）。

<Stepper>

<Step title="地基层：类型系统">

值类型与引用类型的内存模型决定了装箱、赋值、参数传递的一切行为。可空引用类型在编译时防 null。这是全书的地基——泛型是类型参数化，委托是类型安全回调，Record 是值语义数据，都建立在类型系统之上。

</Step>

<Step title="架构层：泛型与委托">

泛型让类型安全（`List<T>` 消除装箱），委托让回调安全（签名检查）。两者是 C# 类型系统的两个核心机制——异步的 `Task<T>` 是泛型，continuation 是委托；并行的 `Action<T>` 是泛型委托；LINQ 的 `Func<T,bool>` 是泛型委托。

</Step>

<Step title="能力层：异步与并行">

async/await 的状态机让线程不阻塞（I/O 场景），TPL 的 Parallel.For 让多核并行（CPU 场景）。`Task` 是两者的共同抽象。理解异步状态机才能写出不阻塞、不死锁的高性能代码；理解并行才能利用多核加速 CPU 密集计算。

</Step>

<Step title="表现层：现代特性">

模式匹配让条件分支更表达力，Record 让数据建模更简洁，源生成器让编译时编程成为可能。这三者建立在前面所有层级之上——模式匹配依赖类型系统，Record 是类型系统的值语义封装，源生成器分析类型元数据。组合使用它们，C# 10 代码比传统 C# 更安全、更简洁、更快。

</Step>

</Stepper>

## 代码对照

```csharp
// 综合应用：API 控制器全链路

// record：值语义 DTO（不可变、值相等、with 表达式）
public record CreateUserRequest(string Name, int Age, string Email);
public record UserDto(int Id, string Name, int Age, string Email);

// async/await：异步数据库查询（不阻塞线程）
// 泛型：Task<T> 是泛型异步结果
public async Task<Result<UserDto>> CreateUserAsync(CreateUserRequest request)
{
    // 模式匹配：验证逻辑
    if (request is { Age: < 0 or > 150 })
        return Result<UserDto>.Failure("Invalid age");

    if (request is { Name.Length: 0 })
        return Result<UserDto>.Failure("Name required");

    // record with：创建领域模型
    var user = new User(0, request.Name, request.Age, request.Email);

    // async：异步写入数据库
    var saved = await _repo.SaveAsync(user);

    // 模式匹配 + record：结果处理
    return saved switch
    {
        { Id: > 0 } => Result<UserDto>.Success(saved with { }),
        _ => Result<UserDto>.Failure("Save failed")
    };
}

// 源生成器：JSON 序列化（零反射）
[JsonSerializable(typeof(CreateUserRequest))]
[JsonSerializable(typeof(UserDto))]
public partial class ApiJsonContext : JsonSerializerContext { }

// 委托与事件：用户创建后发布事件
public event Func<User, Task>? UserCreated;

async Task OnUserCreated(User user)
{
    if (UserCreated is null) return;
    // 多播安全调用
    foreach (var handler in UserCreated.GetInvocationList())
    {
        try { await ((Func<User, Task>)handler)(user); }
        catch (Exception ex) { _logger.LogError(ex, "Handler failed"); }
    }
}

// 泛型：Result 类型
public abstract record Result<T>
{
    public static Result<T> Success(T value) => new SuccessResult(value);
    public static Result<T> Failure(string error) => new ErrorResult(error);

    public record SuccessResult(T Value) : Result<T>;
    public record ErrorResult(string Error) : Result<T>;
}

// 领域模型
public record User(int Id, string Name, int Age, string Email);

// 并行：批量处理用户
public async Task ProcessAllUsersAsync(IReadOnlyList<User> users)
{
    // PLINQ + async：并行异步处理
    var tasks = users
        .AsParallel()
        .Select(async user => await ProcessUserAsync(user))
        .ToArray();
    await Task.WhenAll(tasks);
}

async Task<User> ProcessUserAsync(User user) => user;
```

## 常见误区

<Callout type="trap">

**误区：学完语法就等于掌握 C# 10**

C# 10 的十大特性不只是语法——它们代表了 C# 语言设计的哲学。类型安全优先意味着编译时捕获错误；多范式融合意味着不拘泥于 OOP；性能不妥协意味着安全与速度兼得。真正的掌握是在实际项目中知道**何时用哪个特性**、**如何组合它们**、**它们的底层机制是什么**。语法可以查文档，设计判断力只能通过理解因果链来建立。

</Callout>

<Callout type="trap">

**误区：新特性总是比旧特性好**

`record struct` 不总是比 `struct` 好——大结构体的复制开销可能超过堆分配。`ValueTask` 不总是比 `Task` 好——异步完成时仍需分配且只能 await 一次。源生成器不总是比反射好——简单的一次性反射可能比维护生成器更简单。模式匹配不总是比 if-else 好——简单条件用 if-else 更清晰。选择特性时要理解其适用场景和限制，而不是盲目追求「现代」。

</Callout>

<Exercises>

**问题 1**：请描述 C# 10 十大特性的因果链，说明为什么这个学习顺序不可打乱。

<Answer>

因果链：类型系统（地基）→ 泛型与委托（架构）→ 异步与并行（能力）→ 模式匹配、Record、源生成器（表现）。

顺序不可打乱的原因：类型系统是所有特性的基础——泛型是类型参数化，委托的类型安全来自类型系统，Record 的值语义是类型系统的设计选择，模式匹配的类型模式依赖类型系统。泛型和委托是异步的基础——`Task<T>` 是泛型，continuation 是委托。异步和并行是现代特性的组合场景——API 控制器用 async/await + record + 源生成器。模式匹配应先于 Record 学习——Record 依赖模式匹配做解构和条件判断。源生成器需要理解类型系统的元数据。每个特性建立在前一个的基础上，跳级会丢失因果关系。

</Answer>

**问题 2**：设计一个「用户注册 API」的完整链路，说明在每一步用到哪些 C# 10 特性及其原因。

<Answer>

1. **请求 DTO**：用 `record`（`record RegisterRequest(string Name, string Email, string Password)`）。原因：不可变、值相等、`with` 表达式、自动 `ToString` 用于日志。

2. **请求验证**：用模式匹配（`request is { Name.Length: 0 }`、`request is { Age: < 0 or > 150 }`）。原因：声明式条件，比 if-else 嵌套更清晰。

3. **密码哈希**：用 `async/await`（`await _hasher.HashAsync(request.Password)`）。原因：CPU 密集计算用 `Task.Run` 卸载或使用异步 API 避免阻塞。

4. **数据库写入**：用 `async/await`（`await _repo.SaveAsync(user)`）。原因：I/O 操作不阻塞线程，`Task<T>` 是泛型异步结果。

5. **事件发布**：用委托与事件（`event Func<User, Task> UserRegistered`）。原因：发布-订阅模式，event 封装保护订阅者。多播用 `GetInvocationList` 隔离异常。

6. **JSON 序列化**：用源生成器（`[JsonSerializable(typeof(RegisterRequest))]`）。原因：编译时生成序列化代码，零运行时反射，比反射快 5-10 倍。

7. **响应 DTO**：用 `record`（`record UserDto(int Id, string Name)`）。原因：不可变数据传输对象，值相等便于测试。

8. **结果类型**：用泛型 record（`Result<T>` 的 `SuccessResult` 和 `ErrorResult`）。原因：类型安全的结果封装，避免异常控制流。

9. **批量处理**：用 PLINQ + async（`users.AsParallel().Select(async u => await ProcessAsync(u))`）。原因：并行异步处理，利用多核。

每一步的选择都基于该特性的设计优势：record 的不可变和值语义、模式匹配的声明式表达、async/await 的非阻塞、事件的安全封装、源生成器的编译时优化、泛型的类型安全。

</Answer>

</Exercises>
