## 直觉引入

你是一名快递分拣员。传统方式（if-else）是：「先看是不是书，如果是再看重量超不超 2kg，如果超了看目的地是不是国内……」。每一步都是命令式的「先做什么再做什么」。

模式匹配是声明式的：「给我一个匹配规则，符合规则就执行对应操作」。`box is Book { Weight: > 2, Destination: "domestic" }` 一次声明了所有条件——是 Book 类型、Weight 大于 2、Destination 是 domestic。不符合就跳到下一个规则。

这像正则表达式之于字符串匹配——你描述「什么样」而不是「怎么找」。模式匹配让复杂的条件分支变得简洁且表达力强。

## 概念讲解

### 类型模式与 is 表达式

<Term def="模式匹配（pattern matching）是 C# 7.0 引入的声明式条件判断机制。通过 is 和 switch，在判断类型的同时提取数据。C# 7-10 逐步引入了类型模式、属性模式、元组模式、位置模式、关系模式、逻辑模式和列表模式。">

类型模式在判断类型的同时声明变量：

```csharp
if (shape is Circle c)
    return Math.PI * c.Radius * c.Radius;
```

一行完成了「类型检查 + 类型转换 + 变量绑定」。比传统写法（`if (shape is Circle) { var c = (Circle)shape; ... }`）简洁得多。

### 属性模式

属性模式匹配对象的属性值：

```csharp
if (person is { Age: >= 18, IsActive: true })
    // person.Age >= 18 且 person.IsActive == true
```

C# 8.0 引入，可以嵌套：`person is { Address.City: "Beijing" }`。

### switch 表达式

<Term def="switch 表达式（switch expression）是 C# 8.0 引入的表达式形式的 switch。用 => 映射模式到结果，_ 是弃元模式（匹配任意值）。switch 表达式是表达式而非语句，有返回值。">

```csharp
var discount = customer.Type switch
{
    "vip" => 0.3m,
    "member" => 0.1m,
    _ => 0m
};
```

switch 表达式比 switch 语句更简洁，且编译器检查穷尽性（枚举必须覆盖所有值或加 `_`）。

### 关系模式与逻辑模式

C# 9.0 引入：

- **关系模式**：`> 0`、`<= 100`、`>= 18`
- **逻辑模式**：`and`、`or`、`not`

```csharp
var category = age switch
{
    < 13 => "child",
    >= 13 and < 20 => "teenager",
    >= 20 and < 65 => "adult",
    >= 65 => "senior"
};
```

### 列表模式

C# 10 引入列表模式，匹配数组或列表的结构：

```csharp
int[] arr = { 1, 2, 3 };
if (arr is [1, 2, 3]) // 精确匹配
if (arr is [1, .., 3]) // 首尾匹配，中间用 .. 忽略
if (arr is [var first, .. var rest]) // 提取首元素和剩余
```

## 代码对照

```csharp
// 模式匹配：类型、属性、关系、逻辑、列表

// 抽象基类与子类
abstract class Shape { }
class Circle(double radius) : Shape { public double Radius => radius; }
class Rectangle(double w, double h) : Shape { public double Width => w; public double Height => h; }
class Triangle(double a, double b, double c) : Shape { }

// === 传统写法 vs 模式匹配 ===
// 传统：冗长
double AreaTraditional(Shape shape)
{
    if (shape is Circle)
    {
        var c = (Circle)shape;
        return Math.PI * c.Radius * c.Radius;
    }
    else if (shape is Rectangle)
    {
        var r = (Rectangle)shape;
        return r.Width * r.Height;
    }
    return 0;
}

// 模式匹配：简洁
double AreaModern(Shape shape) => shape switch
{
    Circle c => Math.PI * c.Radius * c.Radius,
    Rectangle r => r.Width * r.Height,
    _ => 0
};

// === 属性模式 ===
record Person(string Name, int Age, bool IsActive, Address Address);
record Address(string City);

string Classify(Person p) => p switch
{
    { Age: < 18 } => "minor",
    { Age: >= 65, IsActive: true } => "active senior",
    { Age: >= 65 } => "senior",
    { IsActive: false } => "inactive",
    { Address.City: "Beijing" } => "beijing resident",
    _ => "other"
};

// === 关系模式 + 逻辑模式 ===
string Grade(int score) => score switch
{
    >= 90 and <= 100 => "A",
    >= 80 and < 90 => "B",
    >= 70 and < 80 => "C",
    >= 60 and < 70 => "D",
    >= 0 and < 60 => "F",
    < 0 or > 100 => "invalid"
};

// === 列表模式（C# 10）===
string ClassifyArray(int[] arr) => arr switch
{
    [] => "empty",
    [single] => $"single: {single}",
    [var a, var b] => $"pair: {a}, {b}",
    [var first, .. var middle, var last] => $"first={first}, last={last}, middle={middle.Length}",
    _ => "long array"
};

// === 元组模式 ===
string RockPaperScissors(string a, string b) => (a, b) switch
{
    ("rock", "scissors") or ("scissors", "paper") or ("paper", "rock") => "A wins",
    ("rock", "rock") or ("scissors", "scissors") or ("paper", "paper") => "draw",
    _ => "B wins"
};

// === not 模式 ===
if (shape is not null and not Circle)
    Console.WriteLine("Non-null, non-circle shape");
```

## 常见误区

<Callout type="trap">

**误区：模式匹配只是 if-else 的语法糖**

模式匹配的核心不是「更短的 if-else」，而是**声明式数据提取**。`shape is Circle c` 同时做了类型检查、类型转换和变量绑定——这三步在传统写法中是分开的。`person is { Age: >= 18 }` 用声明式语法描述「什么样的数据匹配」，而不是「怎么检查数据」。模式可以组合和嵌套（`is Circle { Radius: > 5 }`），可以穷尽性检查（switch 表达式对枚举强制覆盖）。这是编程范式的转变——从命令式条件到声明式模式。

</Callout>

<Callout type="trap">

**误区：switch 表达式必须用 `_` 兜底**

对枚举类型，switch 表达式要求穷尽所有可能值。如果你覆盖了所有枚举成员，不需要 `_`——编译器知道已穷尽。加 `_` 反而会掩盖未来新增枚举成员时的遗漏（编译器不再警告未覆盖）。只有对非枚举类型（如 string、int）或不确定穷尽的场景才需要 `_` 兜底。

</Callout>

<Exercises>

**问题 1**：`shape is Circle c` 比传统写法 `(Circle)c` 有什么优势？编译器做了什么？

<Answer>

`shape is Circle c` 一行完成三件事：类型检查（`shape is Circle`）、类型转换（`(Circle)shape`）和变量绑定（`c = (Circle)shape`）。传统写法需要两步：先 `if (shape is Circle)` 检查，再 `var c = (Circle)shape` 转换。如果用 `as` 操作符（`var c = shape as Circle; if (c != null)`），转换和检查分离，容易遗漏 null 检查。

模式匹配还支持流分析：编译器知道 `if (shape is Circle c)` 为 true 时 c 已赋值且非 null，在 if 体内可直接使用 c。在 C# 8+ 中，`is Circle c` 的 c 是可空感知的——如果 shape 是 `Circle?`，c 的类型是 `Circle`（非空），编译器保证安全。

</Answer>

**问题 2**：C# 10 的列表模式 `[var first, .. var rest]` 匹配什么？`..` 是什么？

<Answer>

`[var first, .. var rest]` 匹配至少 1 个元素的数组或列表：`first` 绑定第一个元素，`rest` 绑定剩余元素（一个 `Span<T>` 或数组切片）。`..` 是切片模式（slice pattern），匹配零个或多个元素。

例如 `[1, 2, 3]` 匹配后 `first = 1`，`rest = [2, 3]`。`[42]` 匹配后 `first = 42`，`rest = []`（空）。`[]` 不匹配（至少需要 1 个元素）。

列表模式适合解析固定格式的数据序列、处理命令行参数、解构数组。`..` 可以出现在不同位置：`[1, ..]` 匹配以 1 开头的数组，`[.., 9]` 匹配以 9 结尾的数组，`[1, .., 9]` 匹配首尾分别 1 和 9 的数组。

</Answer>
