## 直觉引入

你在工厂里生产产品。传统方式（反射）是：产品出厂后，用户拆开产品看说明书才知道它有什么零件——每次使用都要拆开看一遍，很慢。源生成器是：在产品出厂前（编译时），工厂自动生成一份零件清单附在产品里——用户直接看清单，不用拆产品。

反射在运行时检查类型信息（`GetType()`、`GetProperties()`），每次调用都有性能开销。源生成器在编译时读取类型信息，直接生成调用代码——运行时零反射开销。

源生成器是 C# 编译器的一个插件——编译器在编译过程中调用你的生成器代码，生成器分析用户的代码（通过 Roslyn API），输出新的 C# 代码，这些代码被一起编译进最终程序集。

## 概念讲解

### 源生成器原理

<Term def="源生成器（Source Generator）是 C# 9.0 引入的编译时代码生成机制。它是一个实现了 ISourceGenerator 接口的程序集，在编译过程中被编译器加载，分析用户代码的语法树和语义模型，生成新的 C# 源代码加入编译。生成的代码与用户代码一起编译，无运行时反射开销。">

源生成器的工作流程：

1. 编译器开始编译用户代码。
2. 加载引用的源生成器程序集。
3. 调用生成器的 `Initialize` 和 `Execute` 方法。
4. 生成器通过 `GeneratorInitializationContext` 注册语法接收器，收集感兴趣的语法节点。
5. 生成器通过 `GeneratorExecutionContext` 访问语义模型，分析类型信息。
6. 生成器通过 `context.AddSource()` 输出生成的 C# 代码。
7. 编译器将生成的代码与用户代码一起编译。

关键：生成器只能**添加**代码，不能**修改**已有代码。生成器在编译时运行，所以不能用运行时信息（如环境变量、文件系统状态）。

</Term>

### 增量源生成器

<Term def="增量源生成器（Incremental Source Generator）是 C# 10/.NET 6 引入的改进版源生成器，实现 IIncrementalGenerator 接口。它采用管线模型，通过 Where/Select 等操作过滤和转换数据，只在输入变化时重新执行，避免全量重算。">

传统 `ISourceGenerator` 的问题：每次编译都全量执行——即使只改了一个字符，所有生成器代码都重新运行。增量生成器（`IIncrementalGenerator`）采用管线模型：

1. `ForAttributeWithMetadataName` — 只在匹配特定特性的语法节点变化时触发。
2. `SyntaxProvider.CreateSyntaxProvider` — 按语法谓词过滤。
3. `Where` / `Select` / `Collect` — 管线操作，缓存中间结果。

增量生成器的核心优势：**增量计算**——只在输入变化时重新执行对应管线阶段，未变化的阶段复用缓存。对于大型项目，编译速度提升显著。

### 典型应用场景

- **JSON 序列化**：`System.Text.Json` 的源生成器在编译时生成序列化代码，避免运行时反射。
- **依赖注入**：`Microsoft.Extensions.DependencyInjection` 的源生成器生成注册代码。
- **日志**：`LoggerMessage` 源生成器生成高性能日志方法。
- **MVVM**：`CommunityToolkit.Mvvm` 的 `[ObservableProperty]` 生成属性。
- **正则表达式**：`RegexGenerator` 生成编译的正则代码。

<Stepper>

<Step title="传统反射：运行时开销">

`type.GetProperties()` 在运行时通过反射读取类型元数据。每次调用都要遍历元数据表、检查可见性、构建 PropertyInfo 数组。序列化 1000 个对象就是 1000 次反射调用——在高性能场景下是不可接受的开销。

</Step>

<Step title="源生成器：编译时生成">

源生成器在编译时分析类型，直接生成强类型代码。如 `[JsonSerializable(typeof(Person))]` 让生成器在编译时生成 `PersonJsonContext`，包含直接访问 `Person.Name`、`Person.Age` 的序列化代码。运行时零反射——直接字段访问，与手写代码一样快。

</Step>

<Step title="增量管线：只算变化">

C# 10 的 `IIncrementalGenerator` 用管线模型：`ForAttributeWithMetadataName` 只在匹配特性的代码变化时触发，`Select` 转换数据，`Collect` 缓存结果。未变化的管线阶段复用缓存——改一个文件不会全量重跑所有生成器。大型项目编译提速数倍。

</Step>

<Step title="限制与约束">

源生成器只能**添加**代码，不能修改已有代码。生成器在编译时运行，不能使用运行时信息（文件系统、环境变量、网络）。生成的代码对用户可见（可通过 IDE 查看），需要保证可读性。生成器不能引用用户项目的运行时依赖——只能用 Roslyn API 分析编译中的代码。

</Step>

</Stepper>

## 代码对照

```csharp
// 源生成器：从反射到增量生成

// === 传统反射：运行时开销 ===
public class ReflectionSerializer
{
    public string Serialize(object obj)
    {
        var type = obj.GetType();
        var props = type.GetProperties();  // 运行时反射
        var sb = new StringBuilder("{");
        foreach (var prop in props)
        {
            var name = prop.Name;
            var value = prop.GetValue(obj);  // 反射调用
            sb.Append($"\"{name}\":\"{value}\"");
        }
        return sb.Append("}").ToString();
    }
}

// === System.Text.Json 源生成器 ===
using System.Text.Json.Serialization;

// 标记需要生成序列化代码的类型
[JsonSerializable(typeof(Person))]
[JsonSerializable(typeof(List<Person>))]
[JsonSourceGenerationOptions(
    PropertyNamingPolicy = JsonKnownNamingPolicy.CamelCase,
    WriteIndented = true)]
public partial class PersonJsonContext : JsonSerializerContext
{
    // 生成器在编译时生成 GetPerson()、GetListPerson() 等方法
    // 直接访问 Person.Name、Person.Age，零反射
}

// 使用：运行时零反射
var json = JsonSerializer.Serialize(person, PersonJsonContext.Default.Person);
var person = JsonSerializer.Deserialize(json, PersonContext.Default.Person);

// === 自定义增量源生成器（简化示意）===
using Microsoft.CodeAnalysis;

[Generator]
public class ViewModelGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // 管线第一步：找到所有标记 [GenerateViewModel] 的类
        var provider = context.SyntaxProvider
            .ForAttributeWithMetadataName(
                "MyApp.GenerateViewModelAttribute",
                predicate: (node, _) => node is ClassDeclarationSyntax,
                transform: (ctx, _) => (ClassDeclarationSyntax)ctx.TargetNode)
            .Where(c => c is not null);

        // 管线第二步：为每个类生成代码
        context.RegisterSourceOutput(provider.Collect(), (spc, classes) =>
        {
            foreach (var cls in classes)
            {
                var source = GenerateViewModel(cls);
                spc.AddSource($"{cls.Identifier.Text}ViewModel.g.cs", source);
            }
        });
    }

    static string GenerateViewModel(ClassDeclarationSyntax cls)
    {
        var name = cls.Identifier.Text;
        // 生成 ViewModel 代码...
        return $@"
// <auto-generated/>
public partial class {name}ViewModel
{{
    // 生成的属性和命令...
}}
";
    }
}

// === LoggerMessage 源生成器 ===
public partial class MyLogger
{
    [LoggerMessage(
        EventId = 1,
        Level = LogLevel.Information,
        Message = "User {UserId} logged in at {Time}")]
    public static partial void LogUserLogin(
        ILogger logger, int userId, DateTime time);
    // 生成器生成高效的日志方法，避免字符串插值开销
}

// 数据类型定义
public class Person
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}
```

## 常见误区

<Callout type="trap">

**误区：源生成器可以修改已有代码**

源生成器只能**添加**新代码（`context.AddSource`），不能修改、删除或替换已有代码。如果你想给现有类添加方法，只能在同一个 `partial class` 中生成——源生成器生成的代码和用户代码是同一个类的不同 partial 声明。如果类不是 partial 的，生成器无法为其添加成员。这是源生成器与 AOP 织入工具（如 PostSharp、Fody）的根本区别——后者可以修改已编译的 IL。

</Callout>

<Callout type="trap">

**误区：源生成器在运行时执行**

源生成器在**编译时**执行，不是运行时。生成器程序集被编译器加载并执行，生成 C# 源代码，这些代码被加入编译。最终程序集里没有生成器代码——只有生成的代码。因此生成器不能使用运行时信息（文件系统、环境变量、数据库连接），只能分析编译中的代码。如果需要运行时行为变化，仍需配置文件或反射。

</Callout>

<Exercises>

**问题 1**：源生成器比反射快在哪里？为什么？

<Answer>

反射在运行时通过 `Type.GetProperties()`、`MethodInfo.Invoke()` 等方法读取类型元数据——每次调用都要遍历元数据表、检查可见性、构建反射对象、做安全检查。这些开销在每次调用时都存在。

源生成器在编译时分析类型，直接生成强类型代码——如直接 `person.Name` 访问属性而非 `prop.GetValue(person)`。生成的代码与手写代码一样快：直接字段/属性访问，无元数据遍历，无装箱，无安全检查。

性能差异可达 10-100 倍：`System.Text.Json` 的反射序列化比源生成器版本慢约 5-10 倍，且反射版本有 GC 分配（`PropertyInfo[]` 等）。

</Answer>

**问题 2**：增量源生成器（`IIncrementalGenerator`）比传统源生成器（`ISourceGenerator`）好在哪里？

<Answer>

传统 `ISourceGenerator` 每次编译都全量执行——即使只改了一个字符，所有生成器的 `Execute` 方法都重新运行，重新分析所有语法树。对于大型项目（数千文件），这导致编译变慢。

增量源生成器（`IIncrementalGenerator`）采用管线模型：
1. `ForAttributeWithMetadataName` 只在标记了特定特性的语法节点变化时触发。
2. `SyntaxProvider.CreateSyntaxProvider` 按语法谓词过滤，只处理感兴趣的节点。
3. `Where`/`Select`/`Collect` 等管线操作缓存中间结果——未变化的阶段复用缓存。

核心优势：**增量计算**。如果只改了一个文件，只有受影响的管线阶段重新执行，其他阶段复用缓存。大型项目编译速度提升数倍。此外，增量生成器的 API 更安全——`ForAttributeWithMetadataName` 避免了手动语法过滤的常见错误。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="源生成器（Source Generator）">

C# 9 引入的编译时代码生成机制。实现 `ISourceGenerator`，在编译时分析代码并生成新的 C# 源文件。只能添加代码，不能修改已有代码。

</GlossaryItem>

<GlossaryItem term="增量源生成器（Incremental Source Generator）">

C# 10 引入的改进版，实现 `IIncrementalGenerator`。管线模型，只在输入变化时重新执行对应阶段，避免全量重算。

</GlossaryItem>

<GlossaryItem term="JsonSerializerContext">

`System.Text.Json` 的源生成器入口。`[JsonSerializable(typeof(T))]` 标记后，编译时生成强类型序列化代码，零运行时反射。

</GlossaryItem>

<GlossaryItem term="partial class">

源生成器只能为 `partial class` 添加成员。生成的代码和用户代码是同一个类的不同 partial 声明。非 partial 类无法被生成器扩展。

</GlossaryItem>

</Glossary>
