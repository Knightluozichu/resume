## 直觉引入

想象你在工厂流水线上工作。命令式编程像你亲自走到每个工位，拿起零件、检查、加工、放到下一个工位——每一步都要你操心。函数式编程像你写了一张「加工说明书」贴在流水线上，流水线自己按说明书运转——你只描述「做什么」，不关心「怎么做」。

这张「加工说明书」就是函数。函数式编程的核心前提是：**函数本身也是一种数据**，就像数字和字符串一样，可以装在变量里、传来传去、组合在一起。这就是「函数是一等公民」。

C# 从 3.0 开始就把函数当作一等公民——`Func<T>` 委托类型让函数有了明确的类型，Lambda 表达式让你内联创建函数值，LINQ 让你用管道把函数串起来。

## 概念讲解

### Func 与 Action：函数的类型

<Term def="Func<T, TResult> 是 C# 的泛型委托类型，表示「接受 T 类型参数、返回 TResult 类型结果」的函数。Action<T> 是无返回值的版本。它们让函数有了明确类型，可以声明变量、作为参数传递。">

在 C# 中，每个函数都有一个类型。`Func<int, int>` 表示「接受 int 返回 int 的函数」，`Func<string, bool>` 表示「接受 string 返回 bool 的函数」。`Action<int>` 表示「接受 int 无返回值的函数」。

```csharp
Func<int, int> square = x => x * x;
Func<int, int, int> add = (a, b) => a + b;
Action<string> log = msg => Console.WriteLine(msg);
```

函数类型让函数与 int、string 一样有明确类型，可以声明变量、存储在集合中、作为参数传递。

</Term>

### Lambda：内联创建函数值

<Term def="Lambda 表达式是 C# 3.0 引入的匿名函数语法，如 `x => x * 2`。它是委托的语法糖，让你在需要函数值的地方内联创建，不需要单独定义命名方法。">

Lambda 是创建函数值最简洁的方式。`x => x * 2` 读作「x 映射到 x 乘以 2」。参数类型可以从委托签名推断——`Func<int, int> f = x => x * 2` 中 `x` 自动推断为 `int`。

Lambda 的本质是委托实例，编译器为它生成一个方法，委托指向该方法。表达式 Lambda `x => x * 2` 直接返回值；语句 Lambda `x => { return x * 2; }` 用花括号和 return。

</Term>

### 纯函数

<Term def="纯函数是给定相同输入永远返回相同输出、且不产生任何副作用的函数。它不修改外部状态、不依赖可变全局状态、不做 IO。纯函数是函数式编程的理想模型，因为它可预测、可测试、可缓存、可并行。">

纯函数有两个特征：**引用透明**（相同输入永远相同输出）和**无副作用**（不修改任何外部状态）。`x => x * 2` 是纯函数；`x => Console.WriteLine(x)` 不是（有 IO 副作用）；`x => _counter + x` 不是（依赖可变状态 `_counter`）。

纯函数的好处：可测试（不需要 mock 外部状态）、可缓存（相同输入缓存结果）、可并行（无共享状态，天然线程安全）、可推演（用代入法就能推导结果）。C# 不强制纯函数，但函数式编程鼓励尽量写纯函数。

</Term>

### 函数组合

函数组合是把两个函数拼成一个新函数：`Compose(f, g)(x) = f(g(x))`。先执行 g，再把结果传给 f。组合是函数式编程的核心能力——用小函数拼出复杂逻辑。

<Stepper>

<Step title="函数即值：赋值与传递">

`Func<int, int> f = x => x * 2` 把一个函数赋值给变量 `f`。`f` 的类型是 `Func<int, int>`，就像 `int x = 5` 把数字赋值给变量。函数可以像数据一样传来传去——`nums.Select(f)` 把 `f` 作为参数传给 `Select`。

</Step>

<Step title="纯函数：可预测与可测试">

纯函数 `x => x * 2` 给定输入 5 永远返回 10，不依赖任何外部状态。测试只需断言 `f(5) == 10`，不需要 mock。对比 `x => DateTime.Now + x`——每次调用结果不同，不可测试、不可缓存、不可并行。

</Step>

<Step title="函数组合：小函数拼大逻辑">

`Compose(doubleIt, addOne)(3)` = `doubleIt(addOne(3))` = `doubleIt(4)` = 8。组合让你把「加一」和「翻倍」两个简单函数拼成「先加一后翻倍」的复合函数，而不需要写一个 `x => (x + 1) * 2` 的大函数。组合是可逆的——拆开就是原来的小函数。

</Step>

<Step title="声明式管道：描述做什么">

`nums.Where(x => x > 5).Select(x => x * 2).ToList()` 描述「过滤大于 5 的、映射为两倍」。Where 和 Select 是高阶函数，接受函数参数。管道把数据流过一系列函数变换，每一步声明一个转换，不关心循环细节。

</Step>

</Stepper>

## 代码对照

```csharp
// 函数是一等公民：赋值、传参、返回

// 1. 赋值给变量
Func<int, int> square = x => x * x;
Func<int, int> doubleIt = x => x * 2;

// 2. 作为参数传递（高阶函数）
int[] nums = { 1, 2, 3, 4, 5 };
var doubled = nums.Select(doubleIt).ToArray();      // { 2, 4, 6, 8, 10 }
var squared = nums.Select(square).ToArray();         // { 1, 4, 9, 16, 25 }

// 3. 作为返回值（函数工厂）
Func<int, int> Adder(int n) => x => x + n;
var add10 = Adder(10);
Console.WriteLine(add10(5));  // 15

// 4. 函数组合
Func<T, V> Compose<T, U, V>(Func<U, V> f, Func<T, U> g) => x => f(g(x));
var addThenDouble = Compose(doubleIt, square);  // 先平方再翻倍
Console.WriteLine(addThenDouble(3));  // 18：square(3)=9, doubleIt(9)=18

// 5. 纯函数 vs 非纯函数
int counter = 0;
Func<int, int> impure = x => ++counter + x;  // 非纯：依赖并修改外部状态
Func<int, int> pure = x => x + 1;             // 纯：只依赖输入
```

## 常见误区

<Callout type="trap">

**误区：Lambda 就是匿名方法的简写，没有本质区别**

语法上 Lambda 是匿名方法的简写，但语义上 Lambda 是「函数即值」的体现。匿名方法（`delegate(int x) { return x * 2; }`）仍然是命令式思维——「写一个方法但不取名」。Lambda（`x => x * 2`）是函数式思维——「创建一个函数值」。Lambda 可以赋值给 `Func` 变量、作为参数传递、作为返回值，这是函数式编程的基础。此外，Lambda 可以编译为表达式树（`Expression<Func<T>>`），匿名方法不能。

</Callout>

<Callout type="trap">

**误区：所有函数都应该是纯函数**

C# 不是 Haskell，不强制纯函数。IO（读写文件、网络请求、控制台输出）必须通过副作用完成。函数式编程的策略是：**把纯逻辑和副作用分离**——核心业务逻辑用纯函数实现，副作用集中在系统边界（IO 层）。不要为了纯函数而把所有 IO 塞进一个函数——那样反而更难维护。目标是最大化纯函数的比例，而不是追求 100% 纯。

</Callout>

<Callout type="trap">

**误区：函数组合就是方法链**

方法链（`a.Foo().Bar().Baz()`）是面向对象的链式调用，每个方法接收者是对象自身。函数组合（`Compose(f, g)`）是函数式拼接，输入输出类型匹配就能组合，不需要对象。方法链受限于对象 API，函数组合可以跨类型自由拼接。LINQ 的管道是两者的结合——`IEnumerable` 提供链式接口，但每一步接受的是独立函数参数。

</Callout>

<Exercises>

**问题 1**：以下哪些是纯函数？为什么？

```csharp
int counter = 0;
Func<int, int> f1 = x => x * 2;
Func<int, int> f2 = x => { counter++; return x + counter; };
Func<string, int> f3 = s => s.Length;
Func<int, int> f4 = x => x + DateTime.Now.Second;
```

<Answer>

- `f1` 是纯函数——只依赖输入 x，相同输入永远相同输出，无副作用。
- `f2` 不是纯函数——修改了外部状态 `counter`（副作用），且依赖 `counter` 的当前值（相同输入不同输出）。
- `f3` 是纯函数——`s.Length` 只依赖输入 s，字符串是不可变的，相同输入永远相同输出。
- `f4` 不是纯函数——依赖 `DateTime.Now.Second`（可变外部状态），同一输入在不同时刻返回不同结果。

纯函数判定标准：1) 相同输入是否永远相同输出（引用透明）；2) 是否修改或依赖外部状态（无副作用）。

</Answer>

**问题 2**：请编写 `Compose` 函数并用它组合「取平方根」和「加 100」两个函数，使得组合后 `h(x) = sqrt(x + 100)`。

<Answer>

```csharp
Func<T, V> Compose<T, U, V>(Func<U, V> f, Func<T, U> g) => x => f(g(x));

Func<int, double> sqrt = x => Math.Sqrt(x);
Func<int, int> add100 = x => x + 100;

// 组合：先 add100，再 sqrt
// 注意类型匹配：add100: int -> int, sqrt: int -> double
// 但 sqrt 接受 int（隐式转换不适用 Func 泛型），需要调整
Func<double, double> sqrtD = x => Math.Sqrt(x);
Func<int, double> add100ThenSqrt = Compose(sqrtD, (Func<int, double>)(x => x + 100.0));

Console.WriteLine(add100ThenSqrt(25));  // sqrt(125) ≈ 11.18
```

关键点：组合时类型必须匹配——g 的输出类型必须是 f 的输入类型。`Compose(f, g)` 中 g 先执行，f 后执行，与数学上的 `f(g(x))` 一致。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="Func<T, TResult>">

C# 的泛型委托类型，表示「接受 T 类型参数、返回 TResult 类型结果」的函数。让函数有了明确类型，可以声明变量、作为参数传递。`Action<T>` 是无返回值版本。

</GlossaryItem>

<GlossaryItem term="Lambda 表达式">

C# 3.0 引入的匿名函数语法 `x => x * 2`，是委托的语法糖。让你内联创建函数值，不需要单独定义命名方法。参数类型可从委托签名推断。

</GlossaryItem>

<GlossaryItem term="纯函数（Pure Function）">

给定相同输入永远返回相同输出、且不产生任何副作用的函数。不修改外部状态、不依赖可变全局状态。纯函数可预测、可测试、可缓存、可并行，是函数式编程的理想模型。

</GlossaryItem>

<GlossaryItem term="函数组合（Compose）">

把两个函数拼成一个新函数：`Compose(f, g)(x) = f(g(x))`。先执行 g，结果传给 f。组合是函数式编程的核心能力——用小函数拼出复杂逻辑。类型必须匹配：g 的输出类型 = f 的输入类型。

</GlossaryItem>

<GlossaryItem term="引用透明">

纯函数的特性：函数调用可以用其返回值替换而不改变程序行为。`f(5)` 永远等于 10，所以代码中 `f(5)` 和 `10` 可以互换。这使得纯函数可推演、可缓存。

</GlossaryItem>

</Glossary>
