## 直觉引入

如果你要组装一台机器，最好的方式不是直接开始拧螺丝，而是先看装配图——知道每个零件在什么位置、它们之间怎么配合。本书的「学习地图」就是这张装配图。

函数式编程的核心思想可以浓缩为一句话：**用函数描述「做什么」，而不是用指令描述「怎么做」**。这听起来简单，但它衍生出了一套完整的思维方式：函数是一等公民、数据不可变、声明式组合。这些理念在 C# 中通过 LINQ、record、模式匹配等特性落地。

本书不追求把 C# 变成 Haskell，而是教你把函数式思维作为工具箱中的利器，在合适的场景用合适的方式写出更安全、更可组合的代码。

## 概念讲解

### 四大板块

全书按知识递进分为四个板块：

1. **函数式基础**（第 1-2 章）：学习地图与函数优先。建立「函数是一等公民」的核心心智模型。
2. **高阶函数**（第 3-4 章）：高阶函数、柯里化与偏应用。掌握函数组合与抽象的工具。
3. **不可变性**（第 5-6 章）：不可变数据、函数式模式匹配。理解数据建模与控制流的函数式方式。
4. **函数式实践**（第 7-10 章）：延迟求值、Monad 与链式、函数式错误处理、总复习。将理论落地为工程模式。

### 三大核心原则

<Term def="函数是一等公民意味着函数与 int、string 等数据类型享有同等权利：可以赋值给变量、作为参数传递、作为返回值返回。这是函数式编程的基石，所有高阶抽象（高阶函数、柯里化、Monad）都建立在这个前提上。">

函数式编程的三大核心原则：**函数是一等公民**（可赋值、可传参、可返回）、**不可变性**（数据创建后不可修改，变更通过创建新副本实现）、**声明式组合**（用管道把小函数组合成复杂逻辑，而非写大函数）。

</Term>

### 学习路径建议

**推荐路径**：函数式基础 → 高阶函数 → 不可变性 → 函数式实践。

高阶函数依赖「函数优先」的一等公民概念；不可变性需要高阶函数来处理数据转换；函数式实践（Monad、错误处理）综合运用前三板块的知识。总复习应放在最后，串联全书因果链。

<Step title="第一步：函数式基础打底">

先学「函数优先」，建立函数是一等公民的心智模型。理解 `Func<T, TResult>` 类型、Lambda 表达式、函数作为参数和返回值。这是全书的地基——不理解函数即值，后续的高阶函数和 Monad 无从谈起。

</Step>

<Step title="第二步：高阶函数建组合引擎">

高阶函数（接受函数或返回函数的函数）是函数式编程的组合引擎。Where、Select、Aggregate 是 C# 中最常用的高阶函数。柯里化与偏应用让你能把多参数函数拆成单参数链，实现更灵活的组合。

</Step>

<Step title="第三步：不可变性筑安全基石">

不可变数据（record + with 表达式）消除了共享状态导致的并发 bug。函数式模式匹配（switch 表达式）把控制流变成值表达式。这两个特性组合出函数式数据建模能力。

</Step>

<Step title="第四步：函数式实践落地工具箱">

延迟求值（yield + IEnumerable）让管道按需计算。Monad（Result/Option）把副作用和错误变成可组合的数据流。函数式错误处理用 Result 类型替代 try-catch。总复习串联全书。

</Step>

</Stepper>

## 代码对照

```csharp
// 同一段「过滤并转换列表」逻辑：命令式 vs 函数式

// 命令式：描述怎么做（循环 + 条件 + 累加）
var result = new List<int>();
foreach (var x in nums)
    if (x > 5)
        result.Add(x * 2);

// 函数式：描述做什么（过滤 + 映射）
var result = nums
    .Where(x => x > 5)     // 高阶函数：接受谓词函数
    .Select(x => x * 2)    // 高阶函数：接受映射函数
    .ToList();
```

命令式关注「怎么做」——手动循环、判断、累加。函数式关注「做什么」——过滤大于 5 的、映射为两倍。`Where` 和 `Select` 是高阶函数，它们接受函数参数，这是「函数是一等公民」的直接体现。

## 常见误区

<Callout type="trap">

**误区：C# 是 OOP 语言，不适合函数式编程**

C# 是多范式语言。C# 3.0 引入 LINQ（函数式数据管道），C# 7.0 引入模式匹配，C# 9.0 引入 record（不可变数据）。这些特性使 C# 具备了强大的函数式编程能力。函数式不是替代 OOP，而是补充——数据处理用函数式，行为建模用 OOP，按场景选择。

</Callout>

<Callout type="trap">

**误区：函数式编程就是用 LINQ**

LINQ 是 C# 函数式编程的入口，但不是全部。函数式还包括：不可变数据建模（record）、函数式错误处理（Result/Option 类型）、延迟求值（yield/IEnumerable）、Monad 链式组合。只学 LINQ 会错过函数式思维的核心——用类型表达意图、用组合替代嵌套、用不可变性替代锁。

</Callout>

<Exercises>

**问题 1**：本书四大板块的推荐学习顺序是什么？为什么不可变性放在高阶函数之后？

<Answer>

推荐顺序：函数式基础 → 高阶函数 → 不可变性 → 函数式实践。不可变性放在高阶函数之后，因为不可变数据的变更操作（with 表达式、数据转换）依赖高阶函数来描述「如何从旧数据生成新数据」。不理解高阶函数，就无法理解 `Select`、`Aggregate` 等数据转换工具，不可变数据的「创建新副本而非修改」就变成了笨重的全量拷贝。

</Answer>

**问题 2**：函数式编程的三大核心原则是什么？它们之间有什么因果关系？

<Answer>

三大核心原则：函数是一等公民、不可变性、声明式组合。因果关系：函数是一等公民是基石（没有它，函数不能作为参数传递）；声明式组合建立在一等公民之上（管道就是函数的链式组合）；不可变性是组合的安全保障（不可变数据无副作用，组合时不用担心互相干扰）。三者缺一不可：没有一等公民就没有组合，没有不可变性组合就不安全，没有组合函数式就只是语法糖。

</Answer>

</Exercises>
