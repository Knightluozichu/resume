## 直觉引入

想象一条工厂流水线：原材料进来，经过切割工位、打磨工位、质检工位，最后产出成品。每个工位只做一件事，但串起来就能完成复杂加工。

高阶函数就是流水线上的工位。**高阶函数**是接受函数作为参数、或返回函数作为结果的函数。`Where` 接受一个「判断函数」做质检，`Select` 接受一个「转换函数」做加工，`Aggregate` 接受一个「合并函数」做汇总。你把数据送进这条管道，每个高阶函数用你传入的函数处理数据，最终产出结果。

没有高阶函数，你每次过滤数据都要手写循环；有了高阶函数，你只需说「用这个函数过滤」「用那个函数转换」，流水线自己运转。

## 概念讲解

### 高阶函数的定义

<Term def="高阶函数是接受一个或多个函数作为参数，或返回一个函数作为结果的函数。它把函数当作数据来操作，是函数式编程组合能力的核心。Map（映射）、Filter（过滤）、Reduce（聚合）是三大经典高阶函数。">

高阶函数的关键在于：**函数本身是被操作的数据**。`Where(predicate, source)` 中 `predicate` 是一个函数，被当作参数传入。`Adder(n)` 返回一个函数 `x => x + n`，函数被当作返回值传出。

C# 中 LINQ 的方法几乎都是高阶函数：`Select` 接受映射函数，`Where` 接受谓词函数，`OrderBy` 接受键选择函数，`Aggregate` 接受累加函数。

</Term>

### Map（映射）

`Map` 在 C# 中叫 `Select`，它对集合中每个元素应用一个函数，生成新集合。类型签名：`IEnumerable<T> Select<T, U>(IEnumerable<T> source, Func<T, U> mapper)`。输入 `T` 集合，输出 `U` 集合，转换逻辑由 `mapper` 函数决定。

### Filter（过滤）

`Filter` 在 C# 中叫 `Where`，它用谓词函数筛选元素，只保留满足条件的。类型签名：`IEnumerable<T> Where<T>(IEnumerable<T> source, Func<T, bool> predicate)`。谓词返回 `true` 保留，`false` 丢弃。

### Reduce（聚合）

`Reduce` 在 C# 中叫 `Aggregate`，它把集合归约为单个值。类型签名：`TAccumulate Aggregate<T, TAccumulate>(IEnumerable<T> source, TAccumulate seed, Func<TAccumulate, T, TAccumulate> func)`。从种子值开始，逐个用 `func` 累加元素。

### 函数组合管道

高阶函数的真正威力在于**管道组合**：`source.Where(p1).Select(f1).Where(p2).Select(f2).Aggregate(seed, agg)`。每一步返回新集合，下一步在此基础继续处理。数据像水流过管道，每一步声明一个转换。

<Stepper>

<Step title="Filter：用谓词函数筛选">

`nums.Where(x => x > 2)` 中，`Where` 是高阶函数，`x => x > 2` 是谓词函数。Where 对每个元素调用谓词，返回 true 的保留：`[1,2,3,4,5]` 过滤后得 `[3,4,5]`。原集合不变，返回新序列。

</Step>

<Step title="Map：用映射函数转换">

`[3,4,5].Select(x => x * 2)` 中，`Select` 是高阶函数，`x => x * 2` 是映射函数。Select 对每个元素调用映射函数，收集结果：`[6,8,10]`。类型可以从 `int` 变为 `string`——`Select(x => x.ToString())` 返回 `IEnumerable<string>`。

</Step>

<Step title="Reduce：用聚合函数归约">

`[6,8,10].Aggregate(0, (acc, x) => acc + x)` 中，`Aggregate` 是高阶函数，`(acc, x) => acc + x` 是聚合函数。从种子 0 开始：`0+6=6, 6+8=14, 14+10=24`。最终归约为单个值 24。

</Step>

<Step title="管道组合：流水线加工">

`nums.Where(x => x > 2).Select(x => x * 2).Aggregate(0, (a, b) => a + b)` = 24。数据流过三步：过滤→映射→聚合。每步是高阶函数，接受函数参数。这就是声明式管道——描述「做什么」（过滤、映射、汇总），不描述「怎么做」（循环、条件、累加）。

</Step>

</Stepper>

## 代码对照

```csharp
// 三大高阶函数：Map / Filter / Reduce

int[] nums = { 1, 2, 3, 4, 5 };

// Filter（Where）：用谓词函数筛选
var evens = nums.Where(x => x % 2 == 0).ToList();     // { 2, 4 }
var big = nums.Where(x => x > 3).ToList();             // { 4, 5 }

// Map（Select）：用映射函数转换
var doubled = nums.Select(x => x * 2).ToList();         // { 2, 4, 6, 8, 10 }
var strings = nums.Select(x => $"#{x}").ToList();      // { "#1", "#2", ... }

// Reduce（Aggregate）：用聚合函数归约
var sum = nums.Aggregate(0, (acc, x) => acc + x);      // 15
var product = nums.Aggregate(1, (acc, x) => acc * x);  // 120
var max = nums.Aggregate((a, b) => a > b ? a : b);     // 5（无种子版）

// 管道组合
var result = nums
    .Where(x => x > 2)           // { 3, 4, 5 }
    .Select(x => x * x)          // { 9, 16, 25 }
    .Where(x => x < 20)          // { 9, 16 }
    .Aggregate(0, (a, b) => a + b);  // 25

// 自定义高阶函数
IEnumerable<T> MyFilter<T>(IEnumerable<T> src, Func<T, bool> pred)
{
    foreach (var item in src)
        if (pred(item))
            yield return item;
}

Func<int, int> MyMultiplier(int factor) => x => x * factor;  // 返回函数
var triple = MyMultiplier(3);
Console.WriteLine(triple(5));  // 15
```

## 常见误区

<Callout type="trap">

**误区：Select 和 Where 可以互换使用**

`Select` 是映射（Map），对每个元素转换，改变元素类型和值，但**不改变数量**——5 个元素映射后还是 5 个。`Where` 是过滤（Filter），用谓词筛选，**改变数量但不改变元素本身**——每个元素原样保留或丢弃。混用会导致类型错误：`Where` 的谓词返回 `bool`，`Select` 的映射返回任意类型。

</Callout>

<Callout type="trap">

**误区：Aggregate 总是需要种子值**

`Aggregate` 有两个重载：带种子的 `Aggregate(seed, func)` 和不带种子的 `Aggregate(func)`。不带种子时，第一个元素作为种子，从第二个元素开始累加。`nums.Aggregate((a, b) => a + b)` 等价于 `nums.Skip(1).Aggregate(nums.First(), (a, b) => a + b)`。空集合调用无种子版会抛异常——因为没有第一个元素当种子。

</Callout>

<Callout type="trap">

**误区：高阶函数一定比循环慢**

LINQ 的延迟执行有迭代器开销，在极热路径上确实比手写 foreach 慢。但绝大多数场景下：1) 可读性提升远大于微小的性能差异；2) 编译器和 JIT 会优化简单的 LINQ 管道；3) `Span<T>` 和 `MemoryExtensions` 提供了零分配的函数式 API。不要为了假想的性能放弃可读性——先写对，再在 profiling 指导下优化热点。

</Callout>

<Exercises>

**问题 1**：请用 LINQ 管道实现：给定字符串列表，找出所有长度大于 3 的字符串，转大写，按字母排序，用逗号连接成一个字符串。

<Answer>

```csharp
var words = new[] { "cat", "dog", "bird", "fish", "ant" };
var result = words
    .Where(w => w.Length > 3)          // { "bird", "fish" }
    .Select(w => w.ToUpper())           // { "BIRD", "FISH" }
    .OrderBy(w => w)                    // { "BIRD", "FISH" }
    .Aggregate((a, b) => $"{a},{b}");  // "BIRD,FISH"
// 或更简洁：
var result2 = string.Join(",", words
    .Where(w => w.Length > 3)
    .Select(w => w.ToUpper())
    .OrderBy(w => w));
```

管道四步：Where（过滤）→ Select（映射）→ OrderBy（排序）→ Aggregate（归约）。每步是高阶函数，接受函数参数。

</Answer>

**问题 2**：请推导 `Where` 和 `Select` 的类型签名，并解释为什么它们是高阶函数。

<Answer>

`Where` 签名：`IEnumerable<T> Where<T>(this IEnumerable<T> source, Func<T, bool> predicate)`

- 参数 `predicate` 的类型是 `Func<T, bool>`——一个接受 T 返回 bool 的函数
- `Where` 接受函数作为参数，所以是高阶函数
- 语义：对每个元素调用 `predicate`，返回 true 的保留

`Select` 签名：`IEnumerable<U> Select<T, U>(this IEnumerable<T> source, Func<T, U> selector)`

- 参数 `selector` 的类型是 `Func<T, U>`——一个接受 T 返回 U 的函数
- `Select` 接受函数作为参数，所以是高阶函数
- 语义：对每个元素调用 `selector`，收集返回值组成新集合
- 关键：`Select` 可以改变类型（T→U），`Where` 不能（输入输出都是 T）

两者都是高阶函数，因为它们都接受函数（`Func<T, bool>` / `Func<T, U>`）作为参数。这是「函数是一等公民」的直接体现——函数被当作数据传递。

</Answer>

<Glossary>

<GlossaryItem term="高阶函数（Higher-Order Function）">

接受一个或多个函数作为参数，或返回一个函数作为结果的函数。它把函数当作数据来操作。Map、Filter、Reduce 是三大经典高阶函数。C# 的 LINQ 方法（Select、Where、Aggregate 等）几乎都是高阶函数。

</GlossaryItem>

<GlossaryItem term="Map（映射）/ Select">

高阶函数，对集合中每个元素应用一个函数，生成新集合。不改变元素数量，但可以改变元素类型和值。C# 中对应 `Select`。类型签名：`Func<T, U>` 决定 T 到 U 的转换。

</GlossaryItem>

<GlossaryItem term="Filter（过滤）/ Where">

高阶函数，用谓词函数筛选元素，只保留满足条件的。改变元素数量，但不改变元素本身。C# 中对应 `Where`。谓词类型：`Func<T, bool>`。

</GlossaryItem>

<GlossaryItem term="Reduce（聚合）/ Aggregate">

高阶函数，把集合归约为单个值。从种子值开始，逐个用聚合函数累加。C# 中对应 `Aggregate`。聚合函数类型：`Func<TAccumulate, T, TAccumulate>`。

</GlossaryItem>

<GlossaryItem term="管道组合（Pipeline）">

把多个高阶函数串联调用，数据像水流过管道。每一步返回新集合，下一步继续处理。如 `source.Where(p1).Select(f1).Aggregate(seed, agg)`。管道是声明式的——描述做什么，不描述怎么做。

</GlossaryItem>

</Glossary>
