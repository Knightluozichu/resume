## 直觉引入

学完全书九章，我们走过了这样一条路：从「函数是一等公民」出发，经过高阶函数的组合引擎，不可变数据的安全基石，最终到达 Monad 和错误处理的实践工具箱。这条路不是孤立的章节堆砌，而是一条因果链——每个概念都是下一个概念的前提。

总复习的目标不是重述每章内容，而是**串联因果链**：为什么高阶函数需要一等公民？为什么不可变性需要高阶函数？为什么 Monad 需要高阶函数和不可变性？理解了这条链，你就不只是记住了 API，而是掌握了函数式思维的设计逻辑。

## 概念讲解

### 全书因果链

<Term def="全书四大板块构成递进因果链：函数是一等公民（基石）→ 高阶函数（组合引擎）→ 不可变数据（安全基石）→ Monad/错误处理（实践工具箱）。每个板块以前一个为前提——没有一等公民就没有高阶函数，没有高阶函数就没有 Monad 的 Bind，没有不可变性 Monad 链式就不安全。">

1. **函数是一等公民**（第 2 章）：函数可以赋值、传参、返回。这是所有后续概念的前提——高阶函数接受函数参数，Monad 的 Bind 返回函数，没有一等公民这些都不可能。
2. **高阶函数**（第 3-4 章）：Map/Filter/Reduce 接受函数参数，柯里化返回函数。高阶函数是一等公民的直接应用——函数作为数据被操作。
3. **不可变数据**（第 5-6 章）：record + with 创建副本而非修改。不可变性依赖高阶函数——数据转换（Select/Where）用高阶函数描述「如何从旧数据生成新数据」。
4. **函数式实践**（第 7-10 章）：延迟求值用 yield 迭代器，Monad 用 Bind 链式，错误处理用 Result 类型。这些综合运用前三个板块：Monad 的 Bind 是高阶函数，Result 的不可变性保证安全传播，延迟执行是 IEnumerable Monad 的体现。

</Term>

### 三大核心原则的落地

<Term def="函数式编程三大核心原则在 C# 中的落地：1）函数是一等公民——Func<T> 委托 + Lambda + LINQ；2）不可变性——record + init + with 表达式；3）声明式组合——LINQ 管道 + switch 表达式 + Monad 链式。">

| 原则 | C# 落地 | 核心机制 |
|---|---|---|
| 函数是一等公民 | `Func<T, U>` + Lambda | 函数有类型，可赋值传参返回 |
| 不可变性 | `record` + `with` + `init` | 数据创建后不可修改，变更创建副本 |
| 声明式组合 | LINQ 管道 + switch 表达式 | 描述「做什么」而非「怎么做」 |

</Term>

### 命令式 vs 函数式的选择

函数式不是银弹，C# 是多范式语言。选择原则：**数据处理用函数式，行为建模用 OOP，系统边界用 try-catch，内核逻辑用 Result**。

<Stepper>

<Step title="第一环：函数是一等公民（基石）">

全书起点。`Func<int, int> f = x => x * 2` 把函数赋值给变量。`nums.Select(f)` 把函数作为参数传递。`Adder(n)` 返回函数。没有一等公民，后续的高阶函数、柯里化、Monad 都无从谈起。C# 通过 `Func<T>` 委托类型和 Lambda 实现一等公民——函数有了明确类型，与 int、string 同等地位。

</Step>

<Step title="第二环：高阶函数（组合引擎）">

一等公民的直接应用。`Where` 接受谓词函数，`Select` 接受映射函数，`Aggregate` 接受聚合函数——都是高阶函数。柯里化把多参数函数拆成单参数链，偏应用固定部分参数生成新函数。管道组合 `Where(...).Select(...).Aggregate(...)` 让数据流过一系列函数变换。高阶函数是函数式编程的组合引擎——用小函数拼出复杂逻辑。

</Step>

<Step title="第三环：不可变数据（安全基石）">

`record` 提供不可变性——属性 init-only，`with` 创建副本而非修改。不可变数据消除共享状态导致的并发 bug，引用透明使代码可推演、可缓存、可测试。不可变性依赖高阶函数——数据转换用 Select/Where 描述「如何从旧数据生成新数据」。模式匹配（switch 表达式）把控制流变成值表达式，用类型/属性/关系模式替代 if-else 链。

</Step>

<Step title="第四环：实践工具箱（落地）">

综合运用前三板块。延迟求值（yield + IEnumerable）让管道按需计算，处理无限序列。Monad（Option/Result）用 Bind 链式消除嵌套 if-null 和 try-catch——None/Error 自动短路。错误处理用 Result 类型把错误变成数据，签名体现可失败性。LINQ 的 SelectMany 就是 Monad 的 Bind，C# 把 Monad 模式融入了语言。

</Step>

</Stepper>

## 代码对照

```csharp
// 综合实战：从命令式到函数式的完整重构

// === 需求：读取用户列表，过滤成年人，获取邮箱，发送通知 ===

// 命令式实现
class NotificationService
{
    public void NotifyAdults(string filePath)
    {
        List<User> users;
        try
        {
            var lines = File.ReadAllLines(filePath);
            users = new List<User>();
            foreach (var line in lines)
            {
                var parts = line.Split(',');
                if (parts.Length < 3) continue;
                if (!int.TryParse(parts[1], out var age)) continue;
                users.Add(new User(parts[0], age, parts[2]));
            }
        }
        catch (Exception ex)
        {
            Console.WriteLine($"Error: {ex.Message}");
            return;
        }

        foreach (var user in users)
        {
            if (user.Age >= 18)
            {
                if (!string.IsNullOrEmpty(user.Email))
                {
                    try
                    {
                        SendEmail(user.Email, $"Hello {user.Name}");
                        Console.WriteLine($"Sent to {user.Name}");
                    }
                    catch
                    {
                        Console.WriteLine($"Failed for {user.Name}");
                    }
                }
            }
        }
    }

    void SendEmail(string to, string body) { /* ... */ }
}

// 函数式重构
record User(string Name, int Age, string Email);

// 边界：IO 用 try-catch 转 Result
Result<string[], string> ReadLinesSafe(string path)
{
    try { return new Ok<string[], string>(File.ReadAllLines(path)); }
    catch (Exception ex) { return new Err<string[], string>(ex.Message); }
}

// 纯函数：解析行
Result<User, string> ParseUser(string line)
{
    var parts = line.Split(',');
    return parts.Length < 3
        ? new Err<User, string>($"Invalid line: {line}")
        : int.TryParse(parts[1], out var age)
            ? new Ok<User, string>(new User(parts[0], age, parts[2]))
            : new Err<User, string>($"Invalid age: {parts[1]}");
}

// 纯函数：发送通知
Result<string, string> Notify(User user)
    => string.IsNullOrEmpty(user.Email)
        ? new Err<string, string>($"No email for {user.Name}")
        : SendEmailSafe(user.Email, $"Hello {user.Name}");

Result<string, string> SendEmailSafe(string to, string body)
{
    try { /* SendEmail(to, body); */ return new Ok<string, string>($"Sent to {to}"); }
    catch (Exception ex) { return new Err<string, string>(ex.Message); }
}

// 函数式管道
void NotifyAdultsFunctional(string filePath)
{
    var results = ReadLinesSafe(filePath)              // Result<string[], string>
        .Map(lines => lines.Select(ParseUser))         // Result<IEnumerable<Result<User, string>>, string>
        .Match(
            ok: userResults => userResults
                .Where(r => r is Ok<User, string>)     // 只保留解析成功的
                .Select(r => (r as Ok<User, string>)!.Value)
                .Where(u => u.Age >= 18)                // 过滤成年人
                .Select(Notify)                         // 发送通知
                .Select(r => r.Match(
                    ok: msg => msg,
                    err: e => $"FAIL: {e}"
                ))
                .ToList(),
            err: e => new List<string> { $"READ FAIL: {e}" }
        );

    foreach (var r in results)
        Console.WriteLine(r);
}
```

## 常见误区

<Callout type="trap">

**误区：学完全书就应该所有代码都用函数式**

C# 是多范式语言，函数式是工具箱中的工具，不是唯一选择。数据处理（过滤、映射、聚合）用 LINQ 管道最自然；数据建模用 record + 模式匹配最安全；错误处理用 Result 类型最显式。但 GUI 事件处理、状态机、性能关键路径可能用 OOP 或命令式更合适。原则：**数据处理用函数式，行为建模用 OOP，边界 IO 用 try-catch，内核逻辑用 Result**。不要为了函数式而函数式——按场景选择最合适的范式。

</Callout>

<Callout type="trap">

**误区：函数式编程只在学术中有用，实际工程用不上**

本书每一章都展示了 C# 中的实际应用：LINQ 是函数式管道（高阶函数）、record 是不可变数据（C# 9）、switch 表达式是模式匹配（C# 8）、`?.` 是 Maybe Monad、`await` 是 Task Monad。这些不是学术理论，而是 C# 语言的核心特性。掌握函数式思维让你能更好地利用这些特性，写出更安全、更可组合、更可测试的代码。C# 3.0 引入 LINQ 就是函数式思维在工业语言中的成功实践。

</Callout>

<Exercises>

**问题 1**：请说出全书四大板块的因果链，并解释为什么不可变性放在高阶函数之后。

<Answer>

因果链：函数是一等公民（基石）→ 高阶函数（组合引擎）→ 不可变数据（安全基石）→ Monad/错误处理（实践工具箱）。

不可变性放在高阶函数之后的原因：不可变数据的「变更」操作（with 表达式创建副本）需要高阶函数描述「如何从旧数据生成新数据」。`Select`、`Where`、`Aggregate` 等高阶函数是数据转换的工具——不可变数据不能原地修改，只能用高阶函数生成新数据。不理解高阶函数，就无法理解 `nums.Select(x => x * 2)` 如何在不修改原数组的情况下生成新数组。此外，延迟执行（IEnumerable）本身是高阶函数的延迟应用，不可变数据流依赖延迟执行来避免中间集合。所以高阶函数是不可变性的前置依赖。

</Answer>

**问题 2**：请综合运用全书知识，重构以下命令式代码为函数式风格。要求使用 record、LINQ、switch 表达式和 Result 类型。

```csharp
// 命令式：计算订单折扣
string GetDiscount(Customer c, Order o)
{
    if (c == null) return "Customer required";
    if (o == null) return "Order required";
    decimal discount = 0;
    if (c.IsVip)
        discount = 0.2m;
    else if (c.Years > 5)
        discount = 0.1m;
    else
        discount = 0;
    if (o.Total > 1000)
        discount += 0.05m;
    var finalPrice = o.Total * (1 - discount);
    return $"{c.Name}: {finalPrice:F2} (discount: {discount:P0})";
}
```

<Answer>

```csharp
// 不可变数据模型
public record Customer(string Name, bool IsVip, int Years);
public record Order(decimal Total);
public record DiscountResult(string Summary, decimal FinalPrice, decimal DiscountRate);

// 函数式重构
Result<DiscountResult, string> GetDiscountFunctional(Customer? c, Order? o)
    => (c, o) switch
    {
        (null, _)    => new Err<DiscountResult, string>("Customer required"),
        (_, null)    => new Err<DiscountResult, string>("Order required"),
        (var cust, var ord) => new Ok<DiscountResult, string>(
            new DiscountResult(
                $"{cust.Name}: {ord.Total * (1 - CalcDiscount(cust, ord)):F2} " +
                $"(discount: {CalcDiscount(cust, ord):P0})",
                ord.Total * (1 - CalcDiscount(cust, ord)),
                CalcDiscount(cust, ord)
            )
        )
    };

// 纯函数：计算折扣率（switch 表达式）
decimal CalcDiscount(Customer c, Order o)
    => (BaseDiscount(c), o.Total > 1000) switch
    {
        (var base_, true)  => base_ + 0.05m,  // 基础折扣 + 大额折扣
        (var base_, false) => base_            // 仅基础折扣
    };

// 纯函数：基础折扣（switch 表达式 + 属性模式）
decimal BaseDiscount(Customer c) => c switch
{
    { IsVip: true }     => 0.2m,
    { Years: > 5 }      => 0.1m,
    _                   => 0m
};

// 使用
var r1 = GetDiscountFunctional(
    new Customer("Alice", true, 3),
    new Order(2000m));
// Ok: "Alice: 1500.00 (discount: 25%)"

var r2 = GetDiscountFunctional(null, new Order(100m));
// Err: "Customer required"

var r3 = GetDiscountFunctional(
    new Customer("Bob", false, 3),
    new Order(500m));
// Ok: "Bob: 500.00 (discount: 0%)"
```

重构要点：
1. **record**——不可变数据模型，值语义相等
2. **switch 表达式**——元组模式替代 if-else 链，属性模式替代条件判断
3. **Result 类型**——错误变成数据，签名体现可失败性
4. **纯函数**——CalcDiscount 和 BaseDiscount 无副作用，可测试、可缓存
5. **声明式**——描述「匹配什么返回什么」，不描述「怎么跳转」

</Answer>

<GlossaryItem term="因果链">

全书四大板块的递进依赖：函数是一等公民（基石）→ 高阶函数（组合引擎）→ 不可变数据（安全基石）→ Monad/错误处理（实践工具箱）。每个板块以前一个为前提。

</GlossaryItem>

<GlossaryItem term="三大核心原则落地">

函数是一等公民（Func + Lambda + LINQ）、不可变性（record + with + init）、声明式组合（LINQ 管道 + switch 表达式 + Monad 链式）。三大原则在 C# 中通过具体语法特性落地。

</GlossaryItem>

<GlossaryItem term="范式选择">

C# 是多范式语言，按场景选择：数据处理用函数式（LINQ），行为建模用 OOP（class + 虚方法），边界 IO 用 try-catch，内核逻辑用 Result。不要为了函数式而函数式。

</GlossaryItem>

<GlossaryItem term="边界 try-catch，内核 Result">

函数式架构模式：在系统边界（IO、外部 API）用 try-catch 捕获异常转为 Result，内核逻辑用 Result 链式传播。副作用集中在边界，纯逻辑在内核。

</GlossaryItem>
