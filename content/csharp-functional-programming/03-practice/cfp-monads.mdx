## 直觉引入

想象你在快递站取包裹。你需要：取包裹 → 拆开 → 检查商品 → 签收。每一步都可能失败——包裹不在、包装破损、商品有误。传统方式（命令式）是每步都检查：如果包裹不在就返回，如果拆不开就返回，如果商品有误就返回...层层嵌套的 if。

Monad 的方式像一条传送带：你把「取包裹」的结果放上传送带，传送带自动把结果传给「拆开」工位，再传给「检查」工位。如果任何一步失败（包裹不在），传送带自动跳过后续所有步骤，直接把「失败」送到终点。你不需要手动检查每步——传送带（Monad）帮你处理了。

Monad 的核心是 `Bind` 操作：接受一个包装值和一个「接受值并返回新包装值」的函数。如果包装值是「有值」，就把值传给函数继续；如果是「无值」，就跳过函数直接传播「无值」。这就是自动短路。

## 概念讲解

### Monad 的直觉

<Term def="Monad 是一种设计模式，把值包装在上下文中，提供 Bind 操作链式处理包装值。Maybe/Option Monad 的上下文是「有值或无值」，Bind 在无值时自动短路。Monad 的三个要素：1）包装类型 M<T>；2）包装函数 Return/Take（T → M<T>）；3）Bind 操作（M<T> × (T → M<U>) → M<U>）。">

Monad 不是一个具体类型，而是一种模式。C# 中最常见的 Monad 是 `Nullable<T>`（包装「有值或null」）、`Task<T>`（包装「未来的值」）、`IEnumerable<T>`（包装「零或多个值」）。它们都有 Bind 操作：`Nullable<int>` 的 `?.`、`Task<T>` 的 `await`/`ContinueWith`、`IEnumerable<T>` 的 `SelectMany`。

</Term>

### Maybe/Option Monad

<Term def="Maybe Monad（也叫 Option）是包装「有值或无值」的类型。Some(T) 表示有值，None 表示无值。Bind 操作：如果当前是 Some，把值传给函数继续；如果是 None，跳过函数直接返回 None。这消除了嵌套 if-null 检查。">

```csharp
public abstract record Option<T>;
public record Some<T>(T Value) : Option<T>;
public record None<T>() : Option<T>;

// Bind：链式操作的核心
Option<U> Bind<T, U>(Option<T> opt, Func<T, Option<U>> f) => opt switch
{
    Some<T> s => f(s.Value),
    None<T>  => new None<U>()  // 短路：None 直接传播
};
```

</Term>

### Bind 操作

<Term def="Bind（也叫 SelectMany、flatMap、>>=）是 Monad 的核心操作。类型签名：`M<U> Bind<T, U>(M<T>, Func<T, M<U>>)`。它接受一个包装值 M<T> 和一个「接受 T 返回 M<U>」的函数，返回 M<U>。如果 M<T> 是「有值」，提取值传给函数；如果是「无值」，短路返回无值。">

```csharp
// 链式 Bind：每步可能返回 None，None 自动短路
var result = Bind(
    Bind(
        Bind(
            Option.From(user),           // Option<User>
            u => Option.From(u.Profile)   // Option<Profile>
        ),
        p => Option.From(p.Address)       // Option<Address>
    ),
    a => Option.From(a.City)              // Option<string>
);
```

Bind 的类型签名 `Func<T, Option<U>>` 是高阶函数——接受值返回 Monad。这是 Monad 依赖高阶函数的原因。

</Term>

### LINQ SelectMany 就是 Bind

C# 的 LINQ `SelectMany` 就是 Monad 的 Bind。`IEnumerable<T>.SelectMany(T => IEnumerable<U>)` 把每个元素映射为子序列，然后拍平。`Option<T>` 如果实现了 `SelectMany`，就可以用 LINQ 查询语法：

```csharp
var result = from u in Option.From(user)
             from p in Option.From(u.Profile)
             from a in Option.From(p.Address)
             select a.City;
```

<Stepper>

<Step title="Some 链：全链执行">

`Some(5).Bind(x => Some(x * 2)).Bind(x => Some(x + 1)).Bind(x => Some(x.ToString()))` 全链执行：Some(5) → Bind 翻倍 → Some(10) → Bind 加一 → Some(11) → Bind 转字符串 → Some("11")。每步是 Some，值传递到下一步，最终返回 Some("11")。

</Step>

<Step title="None 短路：跳过后续">

`None.Bind(x => Some(x * 2)).Bind(x => Some(x + 1))...` 任何一步返回 None，后续所有 Bind 被跳过，直接传播 None。`None → None → None → None`。不需要手动检查每步是否为 None——Bind 自动处理。这是 Monad 消除嵌套 if-null 的核心机制。

</Step>

<Step title="命令式 vs Monad">

命令式：`if (a != null) { if (a.B != null) { return a.B.C; } } return null;`——3 层嵌套 if-null，可读性差。Monad：`Option.From(a).Bind(x => x.B).Bind(x => x.C)`——扁平链式，None 自动短路。逻辑相同但更简洁、更可组合。

</Step>

<Step title="LINQ 查询语法">

Option 实现了 SelectMany 后，可以用 LINQ 查询语法：`from a in Option.From(user) from b in Option.From(a.Profile) select b.Name`。这和 `Option.From(user).Bind(a => Option.From(a.Profile).Bind(p => Option.From(p.Name)))` 等价。LINQ 查询语法天然支持 Monad 链——这是 C# 把 Monad 模式融入语言的方式。

</Step>

</Stepper>

## 代码对照

```csharp
// Maybe/Option Monad 实现

// === Option 类型定义 ===
public abstract record Option<T>
{
    public static Option<T> Some(T value) => new SomeOption<T>(value);
    public static Option<T> None() => new NoneOption<T>();
}

public sealed record SomeOption<T>(T Value) : Option<T>;
public sealed record NoneOption<T>() : Option<T>;

// === Bind 扩展方法 ===
public static class OptionExtensions
{
    // Bind：核心 Monad 操作
    public static Option<U> Bind<T, U>(this Option<T> opt, Func<T, Option<U>> f)
        => opt switch
        {
            SomeOption<T> s => f(s.Value),
            NoneOption<T>  => Option<U>.None(),
            _              => Option<U>.None()
        };

    // Map：对 Some 中的值应用函数（不改变包装）
    public static Option<U> Map<T, U>(this Option<T> opt, Func<T, U> f)
        => opt.Bind(v => Option<U>.Some(f(v)));

    // Match：模式匹配处理两种情况
    public static R Match<T, R>(this Option<T> opt, Func<T, R> some, Func<R> none)
        => opt switch
        {
            SomeOption<T> s => some(s.Value),
            _               => none()
        };

    // GetOrElse：提供默认值
    public static T GetOrElse<T>(this Option<T> opt, T defaultValue)
        => opt.Match(v => v, () => defaultValue);

    // SelectMany：让 LINQ 查询语法可用
    public static Option<U> SelectMany<T, U>(this Option<T> opt, Func<T, Option<U>> f)
        => opt.Bind(f);

    public static Option<V> SelectMany<T, U, V>(
        this Option<T> opt,
        Func<T, Option<U>> f,
        Func<T, U, V> project)
        => opt.Bind(t => f(t).Bind(u => Option<V>.Some(project(t, u))));
}

// === 使用：命令式 vs Monad ===
class User { public Profile? Profile { get; set; } }
class Profile { public Address? Address { get; set; } }
class Address { public string? City { get; set; } }

// 命令式：嵌套 if-null
string? GetCityImperative(User? user)
{
    if (user is not null)
        if (user.Profile is not null)
            if (user.Profile.Address is not null)
                if (user.Profile.Address.City is not null)
                    return user.Profile.Address.City;
    return null;
}

// Monad：链式 Bind
Option<string> GetCityMonad(Option<User> userOpt)
    => userOpt
        .Bind(u => Option<Profile>.Some(u.Profile) ?? Option<Profile>.None())
        .Bind(p => Option<Address>.Some(p.Address) ?? Option<Address>.None())
        .Bind(a => a.City is not null ? Option<string>.Some(a.City) : Option<string>.None());

// LINQ 查询语法（等价于链式 Bind）
Option<string> GetCityLinq(Option<User> userOpt)
    => from u in userOpt
       from p in Option<Profile>.Some(u.Profile ?? new Profile())
       from a in Option<Address>.Some(p.Address ?? new Address())
       from c in (a.City is not null ? Option<string>.Some(a.City) : Option<string>.None())
       select c;

// === 更多 Monad 示例 ===
// 解析字符串为 int，再除法
Option<int> ParseInt(string s) =>
    int.TryParse(s, out var n) ? Option<int>.Some(n) : Option<int>.None();

Option<int> SafeDivide(int a, int b) =>
    b == 0 ? Option<int>.None() : Option<int>.Some(a / b);

var result = ParseInt("42")
    .Bind(x => SafeDivide(100, x))  // 100 / 42
    .Map(x => x * 2)                 // (100/42) * 2
    .GetOrElse(0);                   // 默认 0

var failResult = ParseInt("abc")
    .Bind(x => SafeDivide(100, x))  // None（ParseInt 失败）
    .Map(x => x * 2)                 // None（短路）
    .GetOrElse(0);                   // 0
```

## 常见误区

<Callout type="trap">

**误区：Monad 就是链式调用**

链式调用（`a.Foo().Bar().Baz()`）是方法链——每个方法返回对象自身或新对象，但不涉及「包装」和「短路」。Monad 的链式是 `Bind`——每步接受一个「返回包装值的函数」，包装类型负责短路传播。`List<T>.Add().Add()` 是方法链但不是 Monad。`IEnumerable<T>.SelectMany()` 是 Monad 的 Bind——它接受返回 IEnumerable 的函数，并拍平嵌套。Monad 的关键是 Bind 操作的语义，不是语法上的链式。

</Callout>

<Callout type="trap">

**误区：C# 的 ?. 运算符就是 Maybe Monad**

`?.` 是 null 条件运算符——`a?.B?.C?.D` 在任一环节为 null 时返回 null。它确实实现了 Maybe Monad 的短路语义，但它是语言内置的语法糖，只处理 null，不能自定义「无值」逻辑。真正的 Maybe Monad 是 `Option<T>` 类型——Some/None 是显式的，不只是 null。Option 区分「有值 None」和「null 值 Some(null)」——这在语义上更精确。此外，`?.` 不能与 LINQ 查询语法组合，Option 可以。

</Callout>

<Callout type="trap">

**误区：Monad 太抽象，实际用不上**

Monad 不是理论玩具——C# 中到处都是。`Nullable<T>` 的 `?.`、`Task<T>` 的 `await`、`IEnumerable<T>` 的 `SelectMany` 都是 Monad 操作。理解 Monad 模式让你能：1）统一理解这些看似不同的特性；2）自定义 Monad（如 Result、Option、State）解决特定问题；3）用 LINQ 查询语法组合 Monad 链。实际项目中，Option Monad 替代 null 检查，Result Monad 替代 try-catch，State Monad 管理可变状态——都是实用的工程模式。

</Callout>

<Exercises>

**问题 1**：请实现 `Option<T>.Map` 方法，它接受一个普通函数 `Func<T, U>`（不返回 Option），对 Some 中的值应用函数，None 保持不变。用 Bind 实现。

<Answer>

```csharp
// Map：对 Some 中的值应用普通函数
public static Option<U> Map<T, U>(this Option<T> opt, Func<T, U> f)
    => opt.Bind(v => Option<U>.Some(f(v)));
    // 如果 opt 是 Some(v)，Bind 调用 f(v) 并包装为 Some
    // 如果 opt 是 None，Bind 短路返回 None

// 等价展开：
public static Option<U> Map2<T, U>(this Option<T> opt, Func<T, U> f)
    => opt switch
    {
        SomeOption<T> s => Option<U>.Some(f(s.Value)),
        _               => Option<U>.None()
    };
```

关键点：
1. `Map` 和 `Bind` 的区别：`Bind` 的函数返回 `Option<U>`（已经包装），`Map` 的函数返回 `U`（需要包装）
2. `Map` 用 `Bind` 实现：把 f 的结果用 `Option<U>.Some` 包装
3. `Map` 不改变包装结构——Some 映射为 Some，None 保持 None
4. `Map` 就是 LINQ 的 `Select`——`opt.Select(f)` 和 `opt.Map(f)` 等价

</Answer>

**问题 2**：请用 Option Monad 实现一个链式操作：从字典中查找用户 → 获取用户邮箱 → 发送通知。每步可能失败（用户不存在、无邮箱），用 Monad 自动短路。

<Answer>

```csharp
// 数据类型
record User(string Name, Option<string> Email);

// 从字典查找用户
Option<User> FindUser(Dictionary<string, User> db, string id)
    => db.TryGetValue(id, out var user) ? Option<User>.Some(user) : Option<User>.None();

// 发送通知（模拟）
Option<string> SendNotification(string email)
{
    Console.WriteLine($"Sending to {email}");
    return Option<string>.Some($"Sent to {email}");
}

// 链式操作：查找 → 获取邮箱 → 发送
Option<string> NotifyUser(Dictionary<string, User> db, string userId)
    => FindUser(db, userId)                          // Option<User>
        .Bind(u => u.Email)                           // Option<string>（邮箱可能 None）
        .Bind(email => SendNotification(email));      // Option<string>（发送结果）

// 使用
var db = new Dictionary<string, User>
{
    ["1"] = new User("Alice", Option<string>.Some("alice@test.com")),
    ["2"] = new User("Bob", Option<string>.None()),  // 无邮箱
    // "3" 不存在
};

var r1 = NotifyUser(db, "1");  // Some("Sent to alice@test.com")——全链成功
var r2 = NotifyUser(db, "2");  // None——用户存在但无邮箱，Bind 短路
var r3 = NotifyUser(db, "3");  // None——用户不存在，第一个 Bind 就短路

// 处理结果
r1.Match(
    some: msg => Console.WriteLine($"Success: {msg}"),
    none: () => Console.WriteLine("Failed to notify")
);
```

关键点：
1. `FindUser` 返回 Option<User>——用户可能不存在
2. `u.Email` 是 Option<string>——邮箱可能 None
3. `Bind` 链式：每步失败自动短路，不需要手动 if 检查
4. `Match` 处理最终结果——Some 是成功，None 是失败
5. 对比命令式：需要 3 层 if-null 嵌套，Monad 用扁平链式替代

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="Monad">

一种设计模式，把值包装在上下文中，提供 Bind 操作链式处理。三要素：包装类型 M<T>、包装函数 Return（T→M<T>）、Bind 操作（M<T>×(T→M<U>)→M<U>）。C# 中的 Nullable<T>、Task<T>、IEnumerable<T> 都是 Monad。

</GlossaryItem>

<GlossaryItem term="Option/Maybe Monad">

包装「有值或无值」的 Monad。Some(T) 表示有值，None 表示无值。Bind 在 None 时自动短路。消除嵌套 if-null 检查。C# 中可用 record 实现。

</GlossaryItem>

<GlossaryItem term="Bind（SelectMany/flatMap）">

Monad 的核心操作。类型签名：`M<U> Bind<T, U>(M<T>, Func<T, M<U>>)`。接受包装值和「返回包装值的函数」。如果当前是「有值」，提取值传给函数；如果是「无值」，短路返回无值。C# 的 `SelectMany` 就是 Bind。

</GlossaryItem>

<GlossaryItem term="Map（Select/fmap）">

对 Monad 中的值应用普通函数（不返回 Monad）。`Map(opt, f) = Bind(opt, v => Some(f(v)))`。Some 映射为 Some，None 保持 None。C# 的 `Select` 就是 Map。

</GlossaryItem>

<GlossaryItem term="短路传播">

Monad Bind 的核心机制。当包装值是「无值」（None/Error）时，Bind 跳过函数调用，直接传播「无值」。后续所有 Bind 都被跳过，直到终端操作。消除了手动检查每步是否失败的嵌套。

</GlossaryItem>

</Glossary>
