## 为什么导学必须先固定版本、目录和验收证据

本书是《编写高质量代码：改善C#程序的157个建议》第一版，作者陆敏技，机械工业出版社，ISBN 9787111356493；本学习体系以作者发布的12章157条目录为唯一outline anchor。旧学习页曾把内容重排成10个泛化主题，导致原书建议不可追溯；本版恢复每条原题，再明确哪些2011结论要在现代.NET中收窄或改写。

先预测：第8条“避免显式enum值”对wire enum是否仍成立；第47条是否要求所有IDisposable类型写finalizer；第118条SecureString是否仍是新.NET默认。正确学习不是答“是/否”，而是给出适用domain、runtime、security和migration evidence。

<Term def="每个学习页面明确保留原建议标题和编号，使现代解释、反例与验证仍可反查到权威目录。">original-title anchor</Term>

## 五条跨章节主线

### Value chain：从Default到Public Type

Ch1定义default/equality/hash，Ch2把它用于Dictionary/HashSet key，Ch3通过generic/variance传播type relation，Ch7-8决定public type是否保持invariant。任何mutable key、default sentinel或narrowed subtype都会在后续边界放大。

### Lifetime chain：从Closure到Host Shutdown

Ch3 closure/event保存target，Ch4明确resource ownership，Ch6让Task/thread可取消并由host等待，Ch8检查singleton/global state。泄漏不只来自Dispose遗漏，也来自subscription、fire-and-forget和global cache。

### Failure chain：从Cleanup到Caller Action

Ch4 cleanup保证fault下release，Ch5区分Try/exception/cancellation并保留cause，Ch6观察task/parallel faults，Ch11把stable exceptions写入public docs。只在最终decision boundary记录主日志。

### Boundary chain：从Query到Permission

Ch2确定IEnumerable/IQueryable execution location，Ch7-8公开最小member/type capability，Ch9进一步区分artifact identity、publisher trust和runtime permission，Ch10给这些边界稳定可搜索的名字。

### Delivery chain：从Clean Change到Observable Version

Ch10让symbols可发现，Ch11让change局部、knowledge不重复，Ch12让tests/version selectors/release gates随production一起演进；Ch9补artifact provenance与least privilege。

<Term def="同一个contract在多个章节经历input、state、execution、public API到release的连续producer-to-consumer关系。">cross-chapter chain</Term>

## 每章统一学习法

每章不以“阅读完成”验收，而使用五步gate：

```text
READ       保留原题与时代背景
PREDICT    写出normal/boundary/fault/lifecycle结果
IMPLEMENT  用最小API表达contract
VERIFY     用可重复evidence证明结果
TRANSFER   在真实review/refactor解释tradeoff
```

<Term def="在进入下一章前必须产出的test、trace、profile、analyzer、security或compatibility结果，而非主观理解。">evidence gate</Term>

```text
chapter evidence = normal path
                 + boundary/counterexample
                 + fault/cancellation
                 + ownership/lifetime
                 + current target/runtime context
```

  <Step title="切换read、predict、implement、verify与transfer">

  <Step title="为建议建立反例而非只写正例">
    比较Parse/TryParse、array/List、throw/wrap、Task/Parallel、enum/class等两侧，说明错误选择会在哪个consumer处暴露。
  </Step>
  <Step title="用transfer task结束章节">
    选真实diff，引用建议编号，写出domain/target/evidence和migration，不以“书上说”作为唯一理由。

<Callout type="trap" title="能复述标题和示例就算掌握">
标题只提供问题入口。没有counterexample、failure/lifetime case和repeatable evidence，知识无法迁移到不同runtime、provider或security boundary。
</Callout>

## 推荐节奏与产物

1. 第1-3章：建立`value-query-type` contract notebook，完成equality、enumeration、closure/variance tests。
2. 第4-6章：绘制ownership/failure/execution flow，完成handle、fault injection、cancellation与benchmark。
3. 第7-9章：做public API/threat review，完成substitution、tamper、TLS、deny tests。
4. 第10-12章：完成rename/refactor/version演练，建立layered CI和deployed smoke。

<Term def="把一条建议用于真实代码，记录原行为、decision boundary、修改、证据和兼容/回滚方案的章节结束任务。">transfer task</Term>

## 本章回顾：从目录锚点走到迁移证据

官方12章与157条原题提供可追溯anchor，四段路径提供依赖顺序，五条cross-chapter chains连接真实故障，read-predict-implement-verify-transfer把理解转成evidence。进入第一章前，应能指出学习目标属于哪条链、最终由哪个consumer和gate验收。

<Exercises>

**问题 1：为什么官方目录顺序要从语言/集合/泛型走到资源、异常和并发？**

<Answer>并发和async放大已有contract：value equality不稳会破坏shared collection，deferred query会重复I/O，closure/event会延长lifetime；没有resource/failure ownership，Task fault与cancellation无法正确cleanup。因此先证明value/query/type，再进入resource/failure/execution，最后设计public/security/delivery边界。</Answer>

**问题 2：一个ConcurrentDictionary缓存偶发找不到已插入key，应沿哪条跨章节链审查？**

<Answer>先沿value chain回Ch1检查Equals/GetHashCode一致和key state immutable，再看Ch2 comparer/collection operation与compound atomicity；若generic key约束不明确回Ch3；public API若泄露mutable key回Ch7-8。用property tests、mutation-after-insert和concurrent operation trace验证，而不是只换另一个concurrent collection。</Answer>

**问题 3：怎样证明已经掌握一条旧结论在现代.NET中的适用边界？**

<Answer>保留original title，写出target/runtime/threat/domain，预测正反cases，完成最小implementation，并以current docs和tests/trace/profile/security evidence验证；最后在真实refactor记录migration。比如SecureString要引用现代平台指导并比较secret manager/lifetime，而非简单背“使用”或“不使用”。</Answer>

</Exercises>
