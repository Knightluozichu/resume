## 为什么需要一张地图

写 C# 的人常有两个执念：一是觉得「能跑就行，空引用异常运行时再说」，二是觉得「LINQ 一把梭，性能问题以后优化」。这两个念头都会把人带偏。一个未经空引用检查的属性访问可能让生产环境崩溃，一个在循环里多次枚举的延迟查询可能让 CPU 飙升十倍。真正决定 C# 代码质量的，不是某个 API 的奇技，而是从「语法是否正确」到「设计是否合理」到「性能是否高效」到「工程是否可靠」的完整心智模型。

本书给了一条清晰的路：先保证语法正确与空安全，再合理设计异常与异步，然后优化集合选择与内存分配，最后落到线程安全与 API 设计。这张地图帮你提前看清全貌。

## 四大质量维度一览

全书 10 章分四大维度，对应四段递进：

- **语法质量（2 章）**：学习地图、可空引用。建立空安全与类型正确的心智模型，回答「代码是否正确」。
- **设计质量（2 章）**：异常实践、异步模式。用合理的异常层次和 async/await 模式健壮化代码，回答「设计是否合理」。
- **性能质量（3 章）**：集合选择、LINQ 性能、内存分配。选对集合、写好 LINQ、控制内存分配，回答「性能是否高效」。
- **工程质量（3 章）**：线程安全、API 设计、总复习。保证多线程正确、设计可演进的 API、串联全书，回答「工程是否可靠」。

<Callout type="tip">
记住主线：从语法正确到工程可靠。每个维度解决前一维度遗留的问题，缺一环就写不出高质量的 C# 代码。
</Callout>

## 一条贯穿全书的主线

四个维度不是孤立的技巧堆叠，而是一条层层递进的主线：

1. **语法质量层**：理解可空引用类型与编译器的 null 流向分析。这是地基——不搞清空安全，运行时到处是 NullReferenceException。
2. **设计质量层**：用 <Term def="在合适层级捕获能处理的异常，抛具体类型，绝不吞异常">异常实践</Term> 和 <Term def="用 async/await 编译器状态机实现非阻塞异步">异步模式</Term> 健壮化代码，让失败可恢复、IO 不阻塞。
3. **性能质量层**：集合选对类型、LINQ 避免多次遍历、内存控制分配——这些都是高并发与大数据量下的硬骨头。
4. **工程质量层**：线程安全保证多线程正确，API 设计保证可演进，最后串联全书形成完整质量体系。

跳层是常见错误：不理解空安全就写异步代码，往往写出「看起来异步但到处 NullReferenceException」的代码。

## 推荐学习路径

按依赖关系走，先打地基再盖楼：

```
第 1 站  学习地图       ← 先看清全貌（本章）
第 2 站  可空引用       ← 让编译器帮你找空引用
第 3 站  异常实践       ← 抛具体异常、捕获有意义异常
第 4 站  异步模式       ← async/await 状态机与陷阱
第 5 站  集合选择       ← 按操作选对集合类型
第 6 站  LINQ 性能      ← 延迟执行与多次遍历陷阱
第 7 站  内存分配       ← 栈堆与装箱、Span 零拷贝
第 8 站  线程安全       ← 竞态条件与并发集合
第 9 站  API 设计       ← 命名、参数与演进兼容
第 10 站 总复习         ← 串联全书
```

<Callout type="trap">
不要跳过「可空引用」直接学异步模式。不理解 null 流向分析，async 方法返回 null 时调用方 await 就会崩溃——编译器能帮你拦住的问题，不要留到运行时。
</Callout>

## 小结

- 全书分四大维度：语法质量、设计质量、性能质量、工程质量
- 主线是「从语法正确到工程可靠」，可维护性优先于性能
- 按依赖学习：语法 → 设计 → 性能 → 工程
- 跳层（不学空安全就写异步）是 C# 开发最常见误区

<Glossary>
<GlossaryItem term="可空引用类型">
C# 8.0 引入的特性：开启 Nullable 后，引用类型默认不可为 null，用 `string?` 显式标注可空。编译器在编译期追踪 null 流向，未检查就解引用发出警告。详见第 2 章。
</GlossaryItem>
<GlossaryItem term="延迟执行">
LINQ 的 Where、Select 等方法只构建查询树不遍历数据，直到 ToList 等立即执行方法触发一次遍历。多次枚举会多次执行，需注意物化。详见第 6 章。
</GlossaryItem>
<GlossaryItem term="装箱">
值类型（如 `int`）转换为 `object` 时在堆上分配新对象并拷贝值。循环中装箱会产生大量垃圾增加 GC 压力，用泛型集合消除。详见第 7 章。
</GlossaryItem>
<GlossaryItem term="竞态条件">
多线程同时读写共享数据且读-改-写非原子时，结果不可预测。用 lock、Interlocked 或并发集合修复。详见第 8 章。
</GlossaryItem>
</Glossary>

  <Answer question="为什么说「能跑就行，空引用异常运行时再说」是危险的执念？">空引用异常在生产环境的修复成本远高于编译期。开启 Nullable 后编译器能在编译期追踪 null 流向，未检查就解引用发出 CS8602 警告，把问题拦在编译阶段。留到运行时则可能导致服务崩溃、用户体验受损、排查困难。高质量 C# 代码应该让编译器帮你找问题，而不是等用户帮你找。</Answer>
