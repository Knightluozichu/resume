## 直觉引入

想象你要存一堆东西。如果只是按顺序摆成一排，用数组或 `List&lt;T&gt;` 就行。如果你需要按名字快速找人，用 `Dictionary` 就像电话簿——O(1) 查找。如果你要排队取号，用 `Queue` 就像银行排队。如果你要后进先出像叠盘子，用 `Stack`。

选错集合就像用电话簿来排队——能做但极慢。在电话簿里找第 5 个人要 O(n)，在队列里找叫「张三」的人要 O(n)。每种集合为特定操作做了优化，选对集合是性能优化的第一步。

## 概念讲解

### 按操作类型选集合

<Term def="通过键快速查找值的集合，基于哈希表实现，查找 O(1)">Dictionary</Term> 适合键值查找：

```csharp
// 键值查找：Dictionary O(1)
var users = new Dictionary<int, User>();
users[42] = new User("Alice");
var user = users[42];  // O(1)

// 用 List 查找：O(n)
var list = new List<User>();
var found = list.FirstOrDefault(u => u.Id == 42);  // O(n)，慢
```

### List vs LinkedList

<Term def="基于动态数组的顺序集合，索引访问 O(1)，尾部增删 O(1)">List&lt;T&gt;</Term> 和 <Term def="基于双向链表的集合，任意位置增删 O(1)，索引访问 O(n)">LinkedList&lt;T&gt;</Term> 的取舍：

```csharp
// List：数组实现，索引访问 O(1)，中间插入 O(n)
var list = new List<int>();
list[0];           // O(1) 快
list.Add(42);      // O(1) 尾部追加
list.Insert(0, 1); // O(n) 要移动所有元素

// LinkedList：链表实现，任意位置增删 O(1)，索引访问 O(n)
var linked = new LinkedList<int>();
linked.AddFirst(1);  // O(1) 头部插入
linked.AddLast(2);   // O(1) 尾部追加
// linked[0];  // 不支持索引访问，查找 O(n)
```

### 有序集合

```csharp
// SortedDictionary：红黑树，按键有序，查找 O(log n)
var sorted = new SortedDictionary<string, int>();
sorted["banana"] = 1;
sorted["apple"] = 2;
// 遍历时按 key 排序：apple, banana

// SortedSet：有序唯一集合
var set = new SortedSet<int> { 3, 1, 2 };
// 遍历：1, 2, 3
```

### 并发集合

<Term def="线程安全的集合，用细粒度锁或无锁 CAS 实现并发读写">并发集合</Term> 在多线程场景下替代普通集合：

```csharp
// 坏代码：Dictionary 多线程写会损坏
var dict = new Dictionary<int, string>();
// 线程A: dict[1] = "a";
// 线程B: dict[2] = "b";  // 可能崩溃或数据损坏

// 好代码：ConcurrentDictionary 线程安全
var concurrent = new ConcurrentDictionary<int, string>();
concurrent.TryAdd(1, "a");  // 线程安全
concurrent.GetOrAdd(2, k => CreateValue(k));  // 原子的「查或加」
```

## 代码对照

```csharp
// ========== 坏代码：用 List 做键值查找 ==========
public User? FindUser(List<User> users, int id)
{
    return users.FirstOrDefault(u => u.Id == id);  // O(n)
}

// ========== 好代码：用 Dictionary ==========
private readonly Dictionary<int, User> _userById;
public User? FindUser(int id)
{
    _userById.TryGetValue(id, out var user);  // O(1)
    return user;
}

// ========== 坏代码：Dictionary 多线程写 ==========
private readonly Dictionary<string, int> _cache = new();
public void Increment(string key)
{
    // 多线程下会损坏或崩溃
    _cache[key] = _cache.GetValueOrDefault(key) + 1;
}

// ========== 好代码：ConcurrentDictionary ==========
private readonly ConcurrentDictionary<string, int> _cache = new();
public void Increment(string key)
{
    _cache.AddOrUpdate(key, 1, (_, old) => old + 1);  // 线程安全
}

// ========== 坏代码：ArrayList 装箱 ==========
var list = new ArrayList();
list.Add(1);    // int 装箱为 object，堆分配
list.Add("a");  // 非类型安全

// ========== 好代码：泛型 List<int> ==========
var list = new List<int>();
list.Add(1);    // 无装箱，栈上值直接存入数组
```

## 常见误区

<Callout type="trap">
**现象：** 用 `List&lt;T&gt;` 做频繁的键值查找，数据量大时明显变慢。
**原因：** `List&lt;T&gt;` 的 `Contains` 和 `Find` 是 O(n) 线性扫描，1 万条数据平均找 5000 次。
**修法：** 键值查找用 `Dictionary` O(1) 或 `HashSet` O(1)。只在需要顺序访问或索引访问时用 `List&lt;T&gt;`。
</Callout>

<Callout type="trap">
**现象：** 多线程下 `Dictionary` 偶发崩溃或数据丢失。
**原因：** `Dictionary` 不是线程安全的，多线程同时写会导致哈希桶链表损坏，可能死循环或丢数据。
**修法：** 多线程读写用 `ConcurrentDictionary`。如果只读（初始化后不再修改），普通 `Dictionary` 也可以（但 `GetOrAdd` 之类的复合操作不行）。
</Callout>

<Callout type="trap">
**现象：** 在循环中频繁 `Insert(0, item)` 头部插入 `List&lt;T&gt;`，性能极差。
**原因：** `List&lt;T&gt;` 是数组实现，头部插入要把所有元素后移一位，O(n) 操作。循环 n 次总复杂度 O(n^2)。
**修法：** 频繁头部插入用 `LinkedList&lt;T&gt;`。或者先 `Add` 到尾部最后 `Reverse`，O(n) 一次性完成。
</Callout>

## 小结

- 键值查找用 `Dictionary` O(1)，顺序访问用 `List&lt;T&gt;` O(1) 索引
- 频繁任意位置增删用 `LinkedList&lt;T&gt;` O(1)，队列用 `Queue`，栈用 `Stack`
- 多线程用 `ConcurrentDictionary` / `ConcurrentQueue`，不用普通集合
- 不可变场景用 `ImmutableList`，对外只读用 `ReadOnlyCollection` 包装
- 用泛型集合代替 `ArrayList` / `Hashtable`，消除装箱、保证类型安全

<Glossary>
<GlossaryItem term="Dictionary">
基于哈希表的键值集合。查找、插入、删除均为 O(1)。键需要正确实现 GetHashCode 和 Equals。不保证顺序。多线程不安全。
</GlossaryItem>
<GlossaryItem term="ConcurrentDictionary">
线程安全的 Dictionary。读操作无锁，写操作用细粒度锁（分桶锁）。适合多线程高频读写场景。AddOrUpdate 等复合操作原子执行。
</GlossaryItem>
<GlossaryItem term="List&lt;T&gt;">
基于动态数组的顺序集合。索引访问 O(1)，尾部追加均摊 O(1)，中间插入删除 O(n)。最常用的集合，适合顺序访问和索引访问。
</GlossaryItem>
<GlossaryItem term="ImmutableList">
不可变列表。修改操作返回新副本，通过结构共享避免完整拷贝。适合需要不可变快照或函数式编程场景。线程安全（因为不可变）。
</GlossaryItem>
</Glossary>

<Exercises>
  <Answer question="多线程场景下为什么不能用 `Dictionary` 而要用 `ConcurrentDictionary`？">`Dictionary` 不是线程安全的：1) 多线程同时写会导致哈希桶链表损坏，可能出现死循环、数据丢失或 NullReferenceException。2) 一个线程写一个线程读也不安全，因为写操作可能触发 rehash（扩容），此时读线程可能访问到正在移动的桶。3) `dict[key] = dict.GetValueOrDefault(key) + 1` 这种读-改-写复合操作即使加了锁也不够，因为其他线程可能在两步之间插入。`ConcurrentDictionary` 用分桶细粒度锁保证写安全，读无锁保证读安全，`AddOrUpdate` 等方法保证复合操作原子性。</Answer>
  <Answer question="什么场景该用 `LinkedList&lt;T&gt;` 而不是 `List&lt;T&gt;`？">用 `LinkedList&lt;T&gt;` 的场景：需要频繁在头部或中间插入删除，且不需要索引访问。因为 `LinkedList` 任意位置增删 O(1)（持有节点引用时），而 `List&lt;T&gt;` 中间增删 O(n)。用 `List&lt;T&gt;` 的场景：需要索引访问（如 `list[i]`）、需要随机访问、或主要在尾部追加。`LinkedList` 不支持索引访问（`linked[0]` 不存在），查找特定位置 O(n)。大多数场景 `List&lt;T&gt;` 更优，因为数组缓存友好、常数因子小。`LinkedList` 每个节点有额外指针开销，内存占用更大。</Answer>
</Exercises>
