## 直觉引入

想象两个仓库。栈是小仓库，就在手边，东西放进去拿出来极快，但空间小、先进后出。堆是大仓库，空间大但远了点，放东西要登记（分配）、不用了要通知管理员来清理（GC 回收）。

值类型（`int`、`struct`）放在小仓库（栈），函数结束自动清理。引用类型（`class`）放在大仓库（堆），GC 负责清理。如果你把值类型当引用类型用（装箱），就要把它从小仓库搬到大仓库——搬运本身有开销，还增加了大仓库的垃圾量，GC 要更频繁地清理。

## 概念讲解

### 值类型 vs 引用类型

<Term def="直接存储值的类型，分配在栈上，赋值时拷贝整个值">值类型</Term> 和 <Term def="存储引用的类型，分配在堆上，赋值时拷贝引用">引用类型</Term>：

```csharp
// 值类型：栈上分配，赋值拷贝整个值
struct Point { public int X, Y; }

var p1 = new Point { X = 1, Y = 2 };
var p2 = p1;    // 拷贝整个 struct
p2.X = 10;
// p1.X 仍是 1，p2.X 是 10

// 引用类型：堆上分配，赋值拷贝引用
class Person { public string Name; }

var p3 = new Person { Name = "Alice" };
var p4 = p3;    // 拷贝引用，指向同一对象
p4.Name = "Bob";
// p3.Name 也是 "Bob"，因为是同一个对象
```

### 装箱拆箱

<Term def="值类型转换为 object 或接口时在堆上分配对象并拷贝值">装箱</Term> 和 <Term def="从 object 中取出值类型并拷贝回栈">拆箱</Term>：

```csharp
int value = 42;

// 装箱：值类型 → 堆对象
object boxed = value;  // 在堆上分配一个 int 对象，拷贝 42

// 拆箱：堆对象 → 值类型
int unboxed = (int)boxed;  // 从堆对象拷贝值到栈

// 装箱的开销：
// 1. 堆分配新对象（GC 要回收）
// 2. 值拷贝到堆
// 3. 拆箱时类型检查 + 值拷贝回栈
```

### 装箱的常见场景

```csharp
// 1. 非泛型集合：ArrayList 装箱
var list = new ArrayList();
list.Add(1);    // int 装箱为 object
list.Add(2);    // 又装箱

// 用泛型集合消除装箱
var list = new List<int>();  // 无装箱
list.Add(1);

// 2. 非泛型接口：IComparable 装箱
int a = 1, b = 2;
IComparable ca = a;  // 装箱

// 用泛型接口避免
IComparable<int> ga = a;  // 无装箱（int 实现了 IComparable<int>）

// 3. string.Format 装箱
string s = string.Format("count={0}", 42);  // 42 装箱

// 用插值字符串避免（编译器优化）
string s = $"count={42}";  // 无装箱
```

### 减少分配的策略

<Term def="在不拷贝数据的情况下对连续内存区域进行切片操作的结构体">Span&lt;T&gt;</Term> 零拷贝：

```csharp
// Span<T>：栈上切片，零拷贝
string text = "Hello, World";
ReadOnlySpan<char> span = text.AsSpan();
ReadOnlySpan<char> hello = span.Slice(0, 5);  // 不拷贝，指向原内存

// 传统方式：Substring 拷贝
string hello = text.Substring(0, 5);  // 分配新字符串

// Span 操作数组
int[] array = { 1, 2, 3, 4, 5 };
Span<int> slice = array.AsSpan(1, 3);  // [2, 3, 4]，不拷贝
slice[0] = 20;  // 修改原数组 array[1] = 20
```

    ```csharp
    public byte[] Process(byte[] input)
    {
        var buffer = new byte[1024];  // 每次分配
        // ... 处理 ...
        return buffer;
    }

    // 好代码：用 ObjectPool 复用
    private static readonly ObjectPool<byte[]> _pool =
        new DefaultObjectPool<byte[]>(() => new byte[1024]);

    public byte[] Process(byte[] input)
    {
        var buffer = _pool.Get();    // 从池中取
        try
        {
            // ... 处理 ...
            return (byte[])buffer.Clone();
        }
        finally
        {
            _pool.Return(buffer);    // 归还池中
        }
    }
    ```

## 代码对照

```csharp
// ========== 坏代码：循环中装箱 ==========
var list = new ArrayList();
for (int i = 0; i < 10000; i++)
    list.Add(i);  // 每次装箱，10000 个堆对象

// ========== 好代码：泛型集合 ==========
var list = new List<int>(10000);  // 预分配容量
for (int i = 0; i < 10000; i++)
    list.Add(i);  // 无装箱

// ========== 坏代码：循环中字符串拼接 ==========
string log = "";
foreach (var item in items)
    log += item.ToString() + ", ";  // 每次分配新字符串

// ========== 好代码：StringBuilder ==========
var sb = new StringBuilder();
foreach (var item in items)
    sb.Append(item).Append(", ");
string log = sb.ToString();

// ========== 坏代码：不必要的 LINQ 分配 ==========
public int Sum(int[] numbers)
{
    return numbers.Where(n => n > 0).Sum();  // 分配迭代器+委托
}

// ========== 好代码：手写循环无分配 ==========
public int Sum(int[] numbers)
{
    int sum = 0;
    foreach (var n in numbers)
        if (n > 0) sum += n;
    return sum;
}
```

## 常见误区

<Callout type="trap">
**现象：** 用 `ArrayList` 存值类型，GC 压力大、性能差。
**原因：** `ArrayList` 的元素类型是 `object`，每次 `Add` 值类型都装箱，在堆上分配新对象。读取时还要拆箱。
**修法：** 一律用泛型集合 `List<int>`、`List<double>` 等，值类型直接存入数组，无装箱无拆箱。
</Callout>

<Callout type="trap">
**现象：** 循环中用 `+` 拼接字符串，数据量大时极慢。
**原因：** 字符串不可变，`a += b` 每次都分配新字符串并拷贝旧内容。循环 n 次总分配 O(n^2)。
**修法：** 用 `StringBuilder` 内部维护可变缓冲区，追加 O(1)，最后 `ToString()` 一次性分配。少量拼接用 `+` 无妨，循环拼接必须用 `StringBuilder`。
</Callout>

<Callout type="trap">
**现象：** `List<T>` 频繁扩容导致额外分配和拷贝。
**原因：** `List<T>` 内部是数组，容量不够时翻倍扩容并拷贝旧数据。循环中逐步 Add 会触发多次扩容。
**修法：** 如果知道大致数量，构造时传入初始容量 `new List<int>(10000)`，一次分配到位避免扩容。
</Callout>

## 小结

- 值类型在栈上分配、函数结束自动清理，引用类型在堆上分配、GC 回收
- 装箱把值类型包成堆对象产生 GC 压力，用泛型集合和泛型接口消除装箱
- 减少分配的策略：Span 零拷贝切片、StringBuilder 拼接、List 预分配容量、对象池复用
- 热路径手写循环避免 LINQ 分配，非热路径用 LINQ 保可读性

<Glossary>
<GlossaryItem term="装箱">
值类型（如 int）转换为 object 或接口时，在堆上分配新对象并拷贝值。开销包括堆分配、值拷贝和后续 GC 回收。循环中装箱会大量增加 GC 压力。
</GlossaryItem>
<GlossaryItem term="Span&lt;T&gt;">
C# 7.2 引入的内存切片结构体，可以对数组、字符串、原生内存进行零拷贝切片操作。本身是 ref struct 只能在栈上，不进堆。用于高性能场景避免不必要的内存拷贝。
</GlossaryItem>
<GlossaryItem term="StringBuilder">
可变字符串构建器，内部维护 char 缓冲区。追加操作 O(1)（缓冲区够大时），避免了字符串不可变导致的反复分配。循环拼接字符串时必须用。
</GlossaryItem>
<GlossaryItem term="对象池">
复用对象避免频繁分配回收的模式。从池中取对象用，用完归还。适合频繁创建销毁的大对象（如 byte 数组、StringBuilder）。用 ObjectPool 实现。
</GlossaryItem>
</Glossary>

<Exercises>
  <Answer question="以下代码哪里发生了装箱？如何消除？">```csharp
var list = new ArrayList();
list.Add(1);
list.Add("hello");
list.Add(3.14);
var sum = 0;
foreach (int i in list) sum += i;
```装箱发生在：1) `list.Add(1)` 把 int 装箱为 object。2) `list.Add(3.14)` 把 double 装箱为 object。3) `foreach (int i in list)` 从 object 拆箱为 int（还会对 "hello" 拆箱失败抛异常）。消除方法：用泛型集合。如果类型混合，用 `List<object>` 仍会装箱值类型。最佳方案是按类型分别存储：`var ints = new List<int>(); var doubles = new List<double>();`。如果确实需要异构集合，用 `List<object>` 但接受值类型装箱的开销，或用自定义记录类型。</Answer>
  <Answer question="为什么 `Span<T>` 能做到零拷贝？它有什么限制？">`Span<T>` 是一个 ref struct，内部存储一个引用（指向数据的起始地址）和一个长度。它不拥有数据，只是对现有内存（数组、字符串、原生内存）的一个「窗口」。切片操作只是创建新的 Span（新的引用+长度），不拷贝底层数据，所以零拷贝。限制：1) 只能在栈上——不能作为字段存储在 class 中，不能跨 await 边界（因为 await 可能切换线程，Span 指向的内存可能已被释放）。2) 不能装箱——不能转为 object 或实现非接口的装箱操作。3) 不能作为泛型参数传入不支持 ref struct 的方法。这些限制保证了 Span 指向的内存始终有效，不会出现悬垂引用。</Answer>
</Exercises>
