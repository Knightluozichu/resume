## 六阶段解题链

### 1. 核验版本目录

先写视觉与交互契约，不写具体属性。固定 DOM、文本、视口、字体和输入方式，预测无增强样式时应保留的内容、尺寸、焦点和阅读顺序。

### 2. 建立编码原则

查明目标效果属于盒生成、背景绘制、边框、滤镜、字体、布局还是合成阶段。只选能直接解释目标的机制，并注明规范能力与实现边界。

### 3. 推演绘制技巧

构造最小代码，删除重复数值、镜像状态和额外 DOM。先预测计算值与绘制区域，再运行正常样本，记录首个产生目标效果的声明。

### 4. 保护文本交互

只改变一个变量，例如容器宽度、文本长度、背景、字体、输入方式或动态偏好。停止在首个偏离点，不用更多覆盖把失败截图修平。

### 5. 验证布局动效

关闭关键能力，检查自然回退是否仍可读、可操作、可布局。增强方案不能反向破坏基线，也不能以颜色、动画或装饰替代语义。

### 6. 签发回退证据

清除故障后重放同一 DOM，确认没有旧内联样式、重复常量、隐藏焦点或层叠残留。把通过条件写成以后可以自动或人工复查的证据。

## 核心机制深挖

按 8 章与 47 个攻略建立问题、机制、回退和验收四联表，掌握可迁移的 CSS 求解方法。 解题时先区分**结构事实、计算样式、绘制结果和交互状态**：结构决定语义与可访问名称，级联和布局产生计算值与使用值，背景、边框、阴影、滤镜再参与绘制，动画与输入只改变状态。把这些阶段混在一起，往往会用多余 DOM 修背景、用固定尺寸修布局、用不可见原生控件修状态，最终难以维护。

本页签发不变量是：**每个攻略都能回答解决什么问题、依赖哪条机制、怎样回退，以及如何用边界样本证明它可维护。** 对每个方案都要问四个问题：不支持高级能力时剩下什么；内容变长时谁负责尺寸；键盘与触摸是否仍能完成任务；删除故障声明后是否回到同一基线。只有四问都有可复现答案，技巧才从演示升级为工程方案。

## 出版社目录逐项讲解

### 第1章 引言

本章先建立全书的求解方法：从真实问题出发，查询规范与兼容边界，保留简单基线，再把属性的既有副作用组合成更轻、更稳的方案。重点不是收集技巧，而是学会解释为什么一个方案满足 DRY、可维护、可扩展和标准兼容。

证据记录从“核验版本目录”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第2章 背景与边框

本章把背景和边框看成可叠放的绘制层。一个元素可以拥有多层背景图像、不同的定位与裁剪区域，再用阴影或 outline 增加边界；关键是明确每层相对 border box、padding box 还是 content box 计算。

证据记录从“建立编码原则”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第3章 形状

本章从矩形盒出发，用圆角、渐变、变换和伪元素构造非矩形外观。内容层尽量不变换，装饰层负责倾斜或旋转；这样文本、焦点和布局仍处在正常坐标系，视觉形状也能随内容伸缩。

证据记录从“推演绘制技巧”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第4章 视觉效果

本章区分盒轮廓、真实透明像素和背景采样。box-shadow 围绕矩形盒绘制，drop-shadow 跟随 alpha 轮廓，filter 与 backdrop-filter 位于不同采样阶段；选错阶段会得到错误边缘或不可读文字。

证据记录从“保护文本交互”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第5章 字体排印

本章把文本内容、语言元数据、字体字形、行框和装饰层连成证据链。CSS 可以增强断词、连字和下划线，但不可把关键文字只放在伪元素或路径效果里；复制、朗读和缩放始终是验收条件。

证据记录从“验证布局动效”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第6章 用户体验

本章要求视觉技巧服从输入语义。光标只提示可做什么，命中区决定能否操作，原生控件保存状态与键盘模型，遮罩和模糊只改变注意层级；每个方案都要同时验证鼠标、键盘和触摸。

证据记录从“签发回退证据”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第7章 结构与布局

本章从内在尺寸和剩余空间分配出发，解决自适应元素、表格、全幅背景、居中和页脚。判断方案时先问谁拥有宽高，再选择布局算法；不要用 transform 或固定像素掩盖错误的尺寸责任。

证据记录从“核验版本目录”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

### 第8章 过渡与动画

本章把运动分为连续插值与离散帧，时间函数决定变化速度，变换原点与嵌套坐标决定路径。动画必须从清楚的静态端点出发，并在 prefers-reduced-motion 下保留状态而非信息消失。

证据记录从“建立编码原则”开始：先写出未增强时的可用结果，再只加入一个 CSS 能力，比较计算样式、绘制边界、内容语义、输入状态和失败回退。若方案需要复制尺寸、隐藏真实控件、依赖固定内容或无法解释的层叠补丁，就回到最小样本重做。

## 方案比较矩阵

| 方案       | 依赖                       | 优点             | 主要风险             | 验收重点                |

## 常见误区与故障注入

<Callout type="trap">
  **误区一：看到效果相同就认定方案等价。** 固定尺寸、额外
  DOM、隐藏溢出和无法解释的高层级可能暂时生成同一截图，却会在内容、字体、输入或能力缺失时分叉。必须比较机制与恢复轨迹。
</Callout>

<Callout type="trap">
  **误区二：把 2026 年的便利属性直接冒充 2015 年原书攻略。**
  现代替代方案可以放入比较矩阵，但必须先解释原书使用的渐变、阴影、伪元素、变换或选择器机制，并明确两者的回退与兼容边界。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                             | 必查证据                 | 通过条件               |
| ---- | ------------------------------------ | ------------------------ | ---------------------- |
| 基线 | 关闭高级绘制或动画能力               | 内容、原生语义、正常流   | 信息与操作完整         |
| 增强 | 只开启目标机制                       | 计算值、绘制区、声明数量 | 目标效果由最少机制产生 |
| 失败 | 窄宽、长内容、键盘、换背景或快速反转 | 首个偏离点               | 能解释并移除根因       |
| 恢复 | 删除故障后重放同一 DOM               | 状态、尺寸、焦点、层叠   | 无残留覆盖且基线一致   |
