## 直觉引入

动效不是花哨的装饰——它是引导注意力的工具。页面滚动时背景慢慢移动产生深度感、加载时旋转的圆环告诉用户「正在工作」、hover 时元素微微上浮暗示「可点击」。这些动效的关键不是「动多少」而是「怎么动」——用对属性（transform/opacity）让动画只走合成层、用对缓动（cubic-bezier）让运动有节奏。

## 动画性能模型

<Term def="CSS 动画性能的关键是只动画「合成属性」（transform/opacity）——它们只触发合成阶段（GPU 移动位图），不触发重排（reflow）和重绘（repaint）。动画 width/margin/top/left 等布局属性会触发重排，代价大。">动画性能模型</Term>是做流畅动效的第一课。

```css
/* 好：只动画 transform（合成层） */
.good {
  transition: transform 0.3s ease;
}
.good:hover {
  transform: translateY(-4px);
}

/* 差：动画 top（触发重排） */
.bad {
  position: relative;
  transition: top 0.3s ease;
}
.bad:hover {
  top: -4px;
}
```

## 视差滚动

视差效果的核心是背景以不同速度滚动——用 background-attachment: fixed 或 background-position 动画实现。

```css
/* 简单视差：背景固定不动 */
.parallax-bg {
  background-image: url('hero.jpg');
  background-attachment: fixed;
  background-size: cover;
  height: 100vh;
}

/* 多层视差：用 perspective + translateZ */
.parallax-scene {
  perspective: 1px;
  overflow-x: hidden;
  overflow-y: auto;
  height: 100vh;
}
.parallax-layer {
  transform: translateZ(-1px) scale(2); /* 远景 */
  z-index: -1;
}
```

## CSS Loading 动画

```css
/* 旋转圆环 spinner */
.spinner {
  width: 40px;
  height: 40px;
  border: 4px solid rgba(0,0,0,0.1);
  border-top-color: #58a;
  border-radius: 50%;
  animation: spin 0.8s linear infinite;
}
@keyframes spin {
  to { transform: rotate(360deg); }
}

/* 骨架屏闪烁 */
.skeleton {
  background: linear-gradient(90deg, #f0f0f0 25%, #e0e0e0 50%, #f0f0f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
}
@keyframes shimmer {
  to { background-position: -200% 0; }
}
```

## 常见误区

<Callout type="trap">
**误区：加 will-change: transform 就能提升动画性能。** will-change 是「提前告知浏览器这个属性将要变化」的提示——浏览器据此预创建合成层。但滥用 will-change 反而有害：每个 will-change 都会创建独立的合成层，内存占用增加；过多合成层导致 GPU 合成开销增大。正确做法是只在即将开始动画时加 will-change、动画结束后移除（或用 JS 动态切换）。对于持续运行的动画（如 spinner），加 will-change 合理；对于偶尔触发的 hover 动画，不加通常也没问题。
</Callout>

<Exercises>
**问题 1**：为什么动画 `transform: translateY(-4px)` 比动画 `top: -4px` 性能更好？

<Answer>
top 是定位属性，修改它触发重排（reflow）——浏览器要重新计算该元素及所有受影响兄弟元素的几何位置，再重新重绘（repaint），代价大。transform 是合成属性——浏览器把元素提升到独立合成层，直接在 GPU 上移动已绘制好的位图，不触发重排也不重绘，只做合成（composite），性能最优。此外 transform 不影响文档流，不会导致其他元素重新布局。因此动画优先用 transform 和 opacity（两者都只合成），避免动画 width/margin/top/left/background-color 等触发重排或重绘的属性。
</Answer>

**问题 2**：骨架屏的 shimmer 动画为什么用 `background-position` 而不用 `transform`？

<Answer>
骨架屏的闪烁效果是让渐变条纹横向移动——需要移动的是背景图案位置而非整个元素。transform 移动的是整个元素（连同内容一起），不能只移动背景。background-position 只改变背景图案的起始位置，不移动元素本身，适合做背景流动效果。但 background-position 动画会触发重绘（repaint）——虽然不像重排那么昂贵，但仍不如 transform 只合成。性能优化方案是把渐变背景放在伪元素上、对伪元素做 transform 动画，这样只合成不重绘。但代码复杂度增加，需权衡。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="合成属性">只触发合成（composite）阶段而不触发重排（reflow）和重绘（repaint）的 CSS 属性，主要是 transform 和 opacity。动画应优先使用合成属性以保证流畅。</GlossaryItem>
<GlossaryItem term="视差滚动">背景与前景以不同速度滚动产生深度感的技术。简单方案用 background-attachment: fixed，多层方案用 perspective + translateZ 创建 Z 轴深度。</GlossaryItem>
<GlossaryItem term="will-change">提示浏览器某属性即将变化的 CSS 属性。浏览器据此预创建合成层以优化动画性能。但滥用会增加内存和合成开销，应按需使用、用完移除。</GlossaryItem>
</Glossary>
