## 直觉引入

把 CSS 想象成盖房子。你先要搭骨架——元素怎么排、盒子怎么算（流与盒模型）；然后刷墙面——文字怎么断行、行高怎么定（文本与排版）；接着分房间——弹性盒怎么分空间、网格怎么定位（布局体系）；最后做装饰——元素怎么翻转、动画怎么播放（视觉与动效）。本书回答的就是这些「从排版到动效」的 CSS 工程问题。

## 四阶段递进

<Term def="CSS 渲染机制是以正常流为基底、通过盒模型计算尺寸、用流式/弹性/网格布局组织位置、靠文本属性控制断行、经变换与动画驱动视觉表现的分层体系。">CSS 渲染系统</Term>的学习可以拆成四个递进阶段。**流与盒模型**包括正常流、浮动与 BFC、盒模型尺寸计算——它们解决「元素怎么排」和「盒子多大」，是所有上层布局的基底。**文本与排版**包括文本装饰、换行控制、行高与垂直对齐——它们决定「文字怎么断」和「行怎么排」。**布局体系**包括 Flex 一维弹性布局和 Grid 二维网格布局——它们精确控制「元素放哪」。**视觉与动效**包括 transform 变换与 animation/transition 动画——它们让页面「能动起来」。

```css
/* 一个「卡片从布局到动效」的完整 CSS 渲染旅程 */
.card {
  /* 1. 流与盒模型：border-box 所见即所得（第 2-3 章） */
  box-sizing: border-box;
  width: 300px;
  padding: 16px;
  border: 1px solid #ddd;

  /* 3. 布局体系：flex 居中内部内容（第 6 章） */
  display: flex;
  flex-direction: column;
  gap: 12px;

  /* 9. 视觉与动效：hover 时平滑上浮（第 9 章） */
  transition: transform 0.3s ease;
}
.card:hover {
  transform: translateY(-4px); /* 只合成不重排（第 8 章） */
}

/* 2. 文本排版：标题行高与换行（第 4-5 章） */
.card h3 {
  line-height: 1.5;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

## 常见误区

<Callout type="trap">
**误区：会写 CSS 属性就等于懂 CSS。** 属性只是表层——`display:flex` 怎么写、`margin` 怎么加，这些照文档抄就会。真正的难点在渲染机制：为什么浮动会导致父容器塌陷、BFC 为什么能隔离 margin、border-box 和 content-box 的实际尺寸差多少、line-height 无单位值和带单位值的继承差异、flex-grow 到底按什么分配、transform 为什么不触发重排。这些是「浏览器渲染时」才显现的机制，也是中高级面试与工程实战的真正考点。把属性当终点的人，写出的页面能看但脆弱；把渲染机制当核心的人，才能写出可控、可维护、高性能的 CSS。
</Callout>

<Exercises>
**问题 1**：全书四阶段是什么？为什么是这个顺序？

<Answer>
流与盒模型（正常流/浮动/BFC/盒模型）→ 文本与排版（装饰/换行/行高）→ 布局体系（Flex/Grid）→ 视觉与动效（transform/animation）→ 总复习。顺序由依赖关系决定：上层依赖下层。没有流与盒模型就没有元素排列；没有文本排版就无法控制文字；没有布局体系就精确不了位置；没有视觉动效就驱动不了交互。先有「能排」，再有「能断」，然后「能放」，最后「能动」。
</Answer>

**问题 2**：为什么 `transform: translateY(-4px)` 比修改 `top: -4px` 更适合做 hover 上浮动画？

<Answer>
top 是定位属性，修改它会触发重排（reflow）——浏览器要重新计算所有受影响元素的几何位置，再重绘，代价大。transform 是合成属性，浏览器直接在合成层上移动已绘制好的位图，不触发重排也不重绘，只做 GPU 合成，性能最优。此外 transform 不影响文档流，不会导致兄弟元素重新布局。因此动画优先用 transform 和 opacity，避免动画 width/margin/top/left 等触发重排的属性。
</Answer>
</Exercises>
