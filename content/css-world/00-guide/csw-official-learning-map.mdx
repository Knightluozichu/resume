# 《CSS 世界》权威学习地图

本页是张鑫旭著《CSS 世界》的独立教学重构。身份基线是人民邮电出版社 2017 年 12 月出版的版本；公开目录被拆成 12 个可核对节点，技术解释以 CSS 2.1 规范、作者官网与浏览器标准文档交叉验证。本页不复制原书段落，也不把现代 CSS 的新增模块倒填为原书内容。

<Objectives>

- 能沿着正常流、盒生成、包含块、使用值、行框和绘制层，解释 12 个目录节点之间的依赖关系。
- 能运行正常、窄视口和脱流覆盖三种样本，只改变一个变量，记录首个偏离点并恢复后重放。
- 能把 CSS 2.1 语境与现代 CSS 迁移分开，说明 Flex、Grid、transform 与 animation 不属于本书章节边界。

</Objectives>

## 从一个盒子的生成开始：CSS 世界如何连成一条链

遇到“为什么这个元素变宽、下移或盖住了另一个元素”，先不要从截图倒推属性。固定 DOM、样式表、视口、字体和内容，先预测它会生成什么盒，再问它读取谁作为<Term def="为盒的尺寸与位置提供参考的祖先盒或初始包含块">包含块</Term>，最后解释浏览器得到的<Term def="经过计算、约束和布局后真正用于排版的最终数值">使用值</Term>。本页的交互图把这条因果链展开；播放前先预测，切换样本后再找首个改变的节点。

## 学习地图的主轴

### 1. 身份与范围

《CSS 世界》围绕 CSS 2.1 的“流”组织材料。<Term def="块级盒与内联盒按照文档顺序参与布局的默认排版方式">正常流</Term>先建立术语、元素、尺寸和盒模型，再进入内联元素、浮动、定位、层叠、文本、装饰、显隐、界面和流向。这个顺序不是目录装饰：每个后续问题都要复用前面已经确认的盒、空间或绘制规则。

### 2. 从流到盒

<Term def="块级盒、内联盒、行框等由元素和格式化规则产生的排版对象">生成盒</Term>
是第一个可观测结果。元素本身不是布局答案；display、内容、匿名盒规则和父级格式化上下文共同决定排版对象。先画盒树，再讨论宽高，能避免把
DOM 树误当作布局树。

### 3. 从盒到尺寸

宽度与高度要经过指定值、计算值和使用值。百分比需要参考尺寸，auto 需要布局上下文，内在尺寸又会受内容、替换元素和约束影响。尺寸实验至少保存容器宽度、内容长度、字体和边界条件，不能只记录一次屏幕上的像素。

### 4. 从尺寸到行框

内联格式化上下文把文字、行内盒与替换元素放进行框；字体度量、基线、line-height 和空白处理会改变垂直位置。若一个图标“看起来偏下”，先查基线和行框，再决定是否需要调整 vertical-align；不要用随机 margin 把症状盖住。

### 5. 从流到绘制层

浮动、定位和清除会改变盒参与正常流的方式；<Term def="规定一组盒如何生成、排列、参与尺寸计算和相互作用的布局环境">格式化上下文</Term>与绘制顺序再决定谁覆盖谁。这里要区分“盒仍存在”“盒不占正常流空间”“盒不可见”和“盒在另一个绘制层”。这四个现象不能用一个 `display: none` 或一张截图互相替代。

### 6. 从文本到方向

文本处理、装饰、显隐、用户界面与书写方向是后半段的验证面。长单词、字体回退、焦点、滚动条、双向文字和方向切换都可能暴露隐藏约束。恢复实验应删除故障声明后重放同一 DOM，并确认流体尺寸契约仍在；覆盖关系要回到<Term def="把一组绘制对象隔离并按层级决定绘制顺序的上下文树节点">层叠上下文</Term>检查。

## 出版社目录逐项映射

下列 12 个节点是本页的公开目录路线。每一项都要回到“生成什么盒、读取哪个包含块、如何得到使用值、在哪个绘制层”的共同问题，再进入章节专属实验。列出的现代扩展只作为边界说明，不冒充原书章节。

### 第 1 章 概述

用“流”建立全书坐标系：先把正常流作为基线，再把尺寸、内联、浮动、定位、层叠和文本视作可观察的规则组合。验收证据是同一 DOM 在宽窄视口下都能解释。

### 第 2 章 需提前了解的术语和概念

把指定值、计算值、使用值、实际值、替换元素、包含块和格式化上下文写进同一张词汇表。术语必须能指导一个预测，而不是只给出名词翻译。

### 第 3 章 流、元素与基本尺寸

从元素类型、内容和父级上下文推导盒与基本尺寸，重点记录 auto、百分比、内在尺寸和可用空间的关系。边界样本使用窄容器和长内容。

### 第 4 章 盒尺寸四大家族

分别观察 content、padding、border 和 margin 如何参与尺寸与间距。每次只改变一个盒模型变量，并把指定值与最终使用值分栏记录。

### 第 5 章 内联元素与流

把文本、行内盒、行框与基线放在同一张图上。用不同字体、line-height 和替换元素验证垂直对齐，不把视觉补偿误认为排版规则。

### 第 6 章 流的破坏与保护

比较 float、position 与清除对正常流占位的影响，再记录恢复方法。问题不是“脱流是否更快”，而是哪个盒不再参加哪一个布局阶段。

### 第 7 章 CSS 世界的层叠规则

先画层叠上下文树，再比较来源、重要性、层叠层级和绘制顺序。一个更大的 z-index 不能跨越所有上下文，因此需要一个能推翻直觉的兄弟盒样本。

### 第 8 章 强大的文本处理能力

记录换行、空白、长词、字体回退、文本方向和溢出。结论要说明内容改变的是行框、盒尺寸还是绘制结果，以及变化发生在哪一步。

### 第 9 章 元素的装饰与美化

把背景、边框、圆角、阴影和渐变放回盒的绘制阶段。装饰不能反过来证明盒已经参与正常流，必须保留盒树与使用值证据。

### 第 10 章 元素的显示与隐藏

区分不生成盒、生成盒但不可见、脱离视口和仍可获得焦点等状态。用可访问交互和布局占位共同验收，而不是只看元素是否出现在截图中。

### 第 11 章 用户界面样式

把表单控件、光标、滚动条和焦点视为平台相关边界。基线结果要锁定浏览器与操作系统，再将可迁移的 CSS 规则与平台差异分栏。

### 第 12 章 流向的改变

观察方向、双向文字和书写模式改变后的阅读顺序、内联轴与块轴。恢复实验必须回到相同内容和字体，确认没有用固定像素掩盖方向问题。

## 三个高频误区

<Callout type="trap" title="把 DOM 树当成盒树">
  **现象：** 看到一个元素就假定它对应一个可见矩形。**原因：**
  忽略匿名盒、内联盒、替换元素和格式化上下文。**修法：**
  先画生成盒，再从包含块与使用值解释尺寸和位置。
</Callout>

<Callout type="trap" title="把指定值当成使用值">
  **现象：** 写了 `width: auto` 或百分比就直接断言像素宽度。**原因：**
  没有记录可用空间、内容约束和父级上下文。**修法：**
  固定输入，逐步写出计算值、约束和最终使用值。
</Callout>

<Callout type="trap" title="用层叠覆盖掩盖脱流">
  **现象：** 叠加一个更大的 z-index 或 margin 后截图“看起来对了”。**原因：**
  正常流占位、包含块和层叠上下文没有分开验证。**修法：**
  保存首个偏离点，删除覆盖声明，再从盒树和绘制顺序重新推导。
</Callout>

## 可重放验收记录

每个实验写六列：**DOM 与内容、生成盒与格式化上下文、包含块、计算值与使用值、首个偏离点、恢复结果**。尺寸实验增加视口和固有尺寸，内联实验增加字体度量与基线，定位实验增加脱流占位与四向偏移，层叠实验增加上下文树，文本实验增加字体回退，界面实验增加焦点与平台信息。

fixed  = DOM + stylesheet + viewport + fonts + content

  display: inline;

## 练习

<Exercises>

**问题 1：** 给一个块级元素设置 `width: auto`，先预测它的包含块、可用空间和使用值；再把容器改窄，记录哪个阶段首先改变。

<Answer>
  先固定内容、字体和外边距，确认 auto
  使用父级可用宽度；容器变窄时，尺寸阶段首先改变，随后长内容可能让行框和溢出状态变化。答案必须包含两个视口的证据，而不是一个截图。
</Answer>

**问题 2：** 一个浮动盒盖住了普通流中的说明文字，怎样判断是脱流还是层叠问题？

<Answer>
  先删除 z-index
  和装饰，只看盒树、占位与包含块；若兄弟盒不再占据原位置，是流参与方式先变了，再检查绘制顺序。恢复同一
  DOM 后，正常流和脱流样本的首个偏离点应一致。
</Answer>

**问题 3：** 长单词、字体回退和书写方向都改变时，如何保持实验可解释？

<Answer>
  不要一次改变三项；按内容、字体、方向分别重放，记录行框、基线、使用值和字体回退。最后组合变化，只把已知的单变量结果叠加，不用固定宽高掩盖差异。
</Answer>

</Exercises>

  <GlossaryItem term="包含块">
    为盒的尺寸与位置提供参考的祖先盒或初始包含块。
  </GlossaryItem>
  <GlossaryItem term="使用值">
    经过计算、约束和布局后真正用于排版的最终数值。
  </GlossaryItem>

  </GlossaryItem>
