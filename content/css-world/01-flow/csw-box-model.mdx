## 直觉引入

每个 HTML 元素都是一个盒子。盒子从内到外有四层：内容（content）、内边距（padding）、边框（border）、外边距（margin）。关键问题是：你设置的 `width` 到底指的是哪一层？content-box 说 width 只是内容区，padding 和 border 额外撑大盒子；border-box 说 width 包含内容+padding+border，设多少就是多少。这就是「盒子算多大」的核心分歧。

## 两种盒模型

<Term def="box-sizing 决定 width/height 计算范围：content-box（默认）只算内容区，border-box 算内容+padding+border。">box-sizing</Term> 的选择直接影响布局稳定性。默认 content-box 下，给 `width: 200px` 的元素加 `padding: 15px; border: 5px` 后，实际宽度变成 240px，容易撑破父容器。border-box 下，实际宽度始终是设置的 200px，padding 和 border 向内挤压内容区。

```css
/* 全局重置：现代项目标配 */
* {
  box-sizing: border-box;
}

/* content-box（默认）：width = 200，实际占 240px */
.box-a {
  box-sizing: content-box;
  width: 200px;
  padding: 15px;   /* +30px */
  border: 5px solid #333; /* +10px */
  /* 实际宽度 240px，可能撑破布局 */
}

/* border-box：width = 200，实际就是 200px */
.box-b {
  box-sizing: border-box;
  width: 200px;
  padding: 15px;
  border: 5px solid #333;
  /* content 自动收缩为 160px，所见即所得 */
}
```

## margin 合并

<Term def="margin 合并是相邻块级元素的垂直外边距在正常流中会合并为一个的机制，取两者中的较大值而非相加。">margin 合并</Term> 只发生在三个场景：相邻兄弟元素之间、父元素与第一个/最后一个子元素之间、空块级元素的自身上下 margin。合并后间距取 `max(margin-a, margin-b)` 而非 `margin-a + margin-b`。

```css
/* 合并场景：间距 = max(30, 20) = 30px，不是 50px */
.a { margin-bottom: 30px; }
.b { margin-top: 20px; }

/* 阻止合并：给父元素触发 BFC 或加 padding/border */
.parent {
  overflow: hidden;  /* 触发 BFC，隔离子元素 margin */
  /* 或 padding-top: 1px; border-top: 1px solid transparent; */
}
```

## 常见误区

<Callout type="trap">
**误区：margin 合并是 bug 需要修复。** margin 合并是 CSS 规范的有意设计——它让段落间距在视觉上保持一致（两个段落之间的间距不应该是一段的下边距加另一段的上边距，那样太大了）。合并只在「相邻块级正常流」中发生，flex/grid 容器的子元素不会合并，浮动和绝对定位元素也不会合并。所以用 flex 布局时你会发现 margin 不合并——这不是 bug，是因为 flex 容器建立了新的格式化上下文。理解了这个机制，就能解释很多「为什么间距不对」的诡异问题。
</Callout>

<Exercises>
**问题 1**：一个 `width: 200px; padding: 15px; border: 5px` 的元素，在 content-box 和 border-box 下实际宽度和内容区宽度各是多少？

<Answer>
content-box（默认）：实际宽度 = 200 + 15×2 + 5×2 = 240px，内容区 = 200px（width 就是内容区）。border-box：实际宽度 = 200px（width 含 border+padding），内容区 = 200 - 15×2 - 5×2 = 160px。关键区别：content-box 的 width 只管内容区，padding/border 向外撑大；border-box 的 width 管整个盒子，padding/border 向内挤压内容区。
</Answer>

**问题 2**：margin 合并在哪些场景不发生？为什么 flex 子元素的 margin 不合并？

<Answer>
不合并的场景：① flex/grid 容器的直接子元素；② 浮动元素；③ 绝对/固定定位元素；④ 行内块元素；⑤ 触发了 BFC 的元素之间。flex 子元素不合并的原因：flex 容器会为其子元素建立「flex 格式化上下文」，这是一种独立于正常流的渲染上下文，正常流的 margin 合并规则不适用于它。同理，grid 容器建立 grid 格式化上下文，BFC 容器建立块级格式化上下文，都不遵循正常流的 margin 合并规则。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="box-sizing">决定 width/height 计算范围的属性。content-box（默认）只算内容区，padding/border 额外撑大；border-box 算内容+padding+border，所见即所得。现代项目全局设 border-box。</GlossaryItem>
<GlossaryItem term="margin 合并">相邻块级元素垂直外边距合并为取大值的机制。只在正常流相邻块级间发生，flex/grid/浮动/定位元素不合并。是有意设计，非 bug。</GlossaryItem>
<GlossaryItem term="盒模型四层">从内到外：content（内容区，文字图片所在）、padding（内边距，背景延伸到此）、border（边框）、margin（外边距，透明，不参与背景）。margin 是元素间的间隔，不算入元素自身的可见尺寸。</GlossaryItem>
</Glossary>
