# 第 1 章 概述

本章是张鑫旭著《CSS 世界》的世界观入口，依据人民邮电出版社 2017 年 12 月版的公开目录独立重构，不复制原书段落。技术解释以 CSS 2.1 规范、作者公开资料和浏览器标准文档交叉核验；IE8、table 与 CSS3 都保留为历史或边界语境，不被混写成同一套现代布局模型。

<Objectives>

- 能从视口、包含块和文档顺序推导生成盒、块级盒、内联盒与行框的参与方式。
- 能运行正常、窄视口和浮动分叉样本，先预测再只改变一个变量，记录首个偏离点并完成恢复重放。

</Objectives>

## 从“为什么会这样排”开始

当一个标题下移、文字环绕或容器变窄时，先不要把截图当答案。固定 DOM、stylesheet、视口、字体和内容，先预测浏览器要创造什么排版对象，再确认对象读取哪个<Term def="为盒的尺寸和位置提供参考的祖先盒或初始坐标系">包含块</Term>，最后解释使用值如何影响行框和绘制。图中的时间线允许播放、单步和拖进度；每次切换样本，都要先说出你预计改变的阶段。

## 三个必须先建立的判断

<Callout type="trap" title="把 DOM 节点直接当成可见矩形">
  **现象：**
  每个元素都被画成一个独立盒，遇到文字换行或匿名盒就无法解释。**原因：**
  忽略元素、内容和格式化规则共同产生排版对象。**修法：**
  先画盒树，再区分块级盒、内联盒、行框和匿名盒，最后讨论尺寸。
</Callout>

<Callout type="trap" title="把 width 写法当成最终像素答案">
  **现象：** 看到 `auto` 或百分比就直接断言宽度。**原因：**
  没有固定包含块、可用空间、内容和约束，也没有区分指定值与使用值。**修法：**
  先记录参考盒和可用空间，再写出计算值、约束与使用值。
</Callout>

<Callout type="trap" title="用现代属性覆盖 CSS 2.1 规则">
  **现象：** 用 Flex、Grid 或 transform
  调整截图，却声称验证了本章的正常流。**原因：**
  新布局模型已经改变了盒生成或参与方式。**修法：** 先完成 CSS 2.1
  基线；现代扩展另建迁移样本，并明确它改变了哪个阶段。
</Callout>

## 正常流的核心机制

### 1. 先固定实验世界

每次实验先写清 DOM、样式表、视口、字体、内容和浏览器版本。<Term def="块级盒与内联盒按照文档顺序参与布局的默认排版方式">正常流</Term>不是一个开关，而是一组默认的生成、安放和尺寸规则。没有固定输入，就无法判断变化来自内容、字体、容器，还是来自声明本身。

### 2. 再观察浏览器创造什么

<Term def="块级盒、内联盒、行框等由元素与格式化规则共同产生的排版对象">
  生成盒
</Term>
是比 DOM
更接近布局事实的中间层。块级元素通常生成块盒，文字会参与内联格式化并进入行框，某些结构还会产生匿名盒。实验记录应先保存盒树，再解释宽高和位置。

### 3. 最后追踪空间如何流动

块级盒会在所属上下文中依次安放，内容会推动后续位置，内联内容会按行框换行。<Term def="在容器变化时仍由内容和可用空间共同决定尺寸与位置的布局性质">流体布局</Term>不是“所有尺寸都百分比”，而是删除不必要的固定坐标后，布局仍能对内容和容器变化作出可解释响应。

## 出版社目录与本章概念

### 第1章 概述

本章先给出 CSS 世界的观察坐标：正常流、盒生成、可用空间和浏览器支持边界。验收不是复述“CSS 很灵活”，而是能从输入推导盒树，并在宽度、内容和方向变化后解释首个不同。

### 1.1 CSS世界的“世界观”

CSS 世界的底层直觉是流：盒在可用空间中按规则安放，尺寸尽量由容器和内容共同决定。这个直觉帮助我们先解释默认行为，再解释覆盖、脱流和层叠；它也要求把指定值、计算值和使用值分开记录。

### 1.2 世界都是创造出来的

浏览器不会把 DOM 原样画成矩形，而是依据元素类型、内容和格式化上下文创造盒。<Term def="参与块格式化上下文、通常沿块方向排列并形成矩形占位的盒">块级盒</Term>与<Term def="参与内联格式化上下文、进入行框并受字体与基线影响的盒">内联盒</Term>并不拥有同一套尺寸与换行规则。`display`、匿名盒、文本和替换元素共同决定“画什么”；因此开发者工具中的盒模型是观测窗口，不是脱离规则的答案。

### 1.3 CSS完胜SVG的武器——流

本节的重点不是比较两个技术的优劣，而是观察 CSS 如何利用文档顺序、可用空间和内容自然排布。一个小的流体样本应能在宽窄容器中保持结构，再用证据解释为何换行和位置发生变化。

### 1.3.1 何为“流”

流是排版对象参与布局的默认秩序：块盒沿块方向排列，内联内容进入行框，前面的内容会影响后面的可用位置。只有先确定对象和上下文，才能讨论浮动、定位或层叠如何改变它。

### 1.3.2 流是如何影响整个CSS世界的

尺寸、内联、文本、装饰和界面问题都继承了流的前提。内容变长可能先改变行框，再改变盒高度；容器变窄可能先改变可用内联空间，再改变换行。每一次观察都要写出变化经过了哪些阶段。

### 1.3.3 什么是流体布局

流体布局要求删除非必要的固定坐标，保留容器、内容和约束之间的可解释关系。它不保证所有元素永远一样宽，也不等于忽略 min/max、字体或替换元素；它保证输入变化时能找到规则链，而不是寻找补丁。

### 1.4 CSS世界的开启从IE8开始

IE8 是本书历史叙事中的浏览器边界，不能直接当作今天的兼容性承诺。记录历史支持时要锁定浏览器版本和实现差异；现代浏览器的表现要另以当前规范与测试验证，不能把两种证据混为一谈。

### 1.5 table自己的世界

table 布局有自己的行、列、单元格和尺寸协调规则。它仍然与 CSS 世界相连，但不能被普通块流的直觉完全替代。比较实验应保持内容与容器一致，只切换布局模型，并分别记录盒树、可用空间和最终使用值。

### 1.6 CSS新世界——CSS3

CSS3 代表扩展能力与新的标准阶段。学习本章时先完成 CSS 2.1 正常流基线，再把新属性放进迁移账本：它是新增规则、改变了哪个布局阶段、在哪些浏览器成立、是否改变了原书问题的边界。

## 证据记录与边界

每个样本写六列：**DOM 与内容、生成盒与格式化上下文、包含块、计算值与使用值、首个偏离点、恢复结果**。尺寸变化增加视口和内容长度，内联变化增加字体与基线，浮动变化增加占位与环绕，历史变化增加浏览器版本。截图只能作为最后一列的辅助证据，不能替代前五列。

```text
branch = change_exactly_one_variable + first_divergence
replay = remove_fault + same_inputs + fluid_contract_preserved
```

```css
.page {
  max-width: 48rem;
  margin-inline: auto;
  padding-inline: 1rem;
}

.note {
  display: flow-root;
}
```

上面的代码只提供一个可观察基线：容器有最大宽度，外边距把它放回可用空间，内容仍按正常流排布。若要研究浮动，另加一个声明并保存分叉前后的盒树；不要同时改动宽度、定位和层叠。

## 练习

<Exercises>

**问题 1：** 一个块级盒在宽容器中占据整行，容器变窄后文字换行。请先预测哪一个阶段改变，再用图中的正常与窄视口样本核对。

<Answer>
  先保持
  DOM、字体和样式不变，包含块的可用空间先改变，随后内联内容的行框换行，最后盒高度可能改变。若记录显示先改了固定高度或
  margin，说明实验同时改变了多个变量。
</Answer>

**问题 2：** 给说明卡片加入一个浮动缩略图后，文字绕到图片旁边。如何判断它改变的是正常流还是层叠顺序？

<Answer>
  先检查浮动盒是否还占普通流中的位置，再看文字是否绕过它；这是参与方式和可用空间的变化。只有盒树与占位解释完成后，才检查绘制覆盖，不能用更大的
  z-index 代替流分析。
</Answer>

**问题 3：** 怎样验证“流体布局”不是“所有尺寸写成百分比”？

<Answer>
  删除非必要固定坐标，锁定内容和字体，分别改变容器宽度与内容长度；如果能从包含块、生成盒、行框和使用值解释结果，即使存在
  max-width 或内在尺寸，也仍然是可解释的流体布局。
</Answer>

</Exercises>

## 术语表

<Glossary>
  <GlossaryItem term="正常流">
    块级盒与内联盒按照文档顺序参与布局的默认排版方式。
  </GlossaryItem>
  <GlossaryItem term="生成盒">
    块级盒、内联盒、行框等由元素与格式化规则共同产生的排版对象。
  </GlossaryItem>
  <GlossaryItem term="包含块">
    为盒的尺寸和位置提供参考的祖先盒或初始坐标系。
  </GlossaryItem>
  <GlossaryItem term="流体布局">

  </GlossaryItem>

## 小结

- 先固定输入，再从包含块推导可用空间。
- 先解释生成盒和格式化上下文，再讨论尺寸、行框和绘制。
- 正常流是默认秩序；浮动、定位、table 与 CSS3 都必须作为明确分叉或边界记录。
- 流体布局的验收标准是规则链可解释、内容可变、容器可变、故障可恢复。
