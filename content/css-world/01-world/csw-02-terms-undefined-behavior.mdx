## 从一条声明为何失效开始

看到“颜色没有生效”或“两个浏览器结果不同”时，先不要马上修改选择器。固定 DOM、stylesheet、视口、字体和浏览器，先问输入属于哪个术语，再沿指定、解析、层叠、计算、使用和实际呈现阶段追踪。图中的样本可以切换有效声明、无效语法和未定义边界；动手前先预测它会在哪一格停止或分叉。

## 先分清三种失败

<Callout type="trap" title="把无效声明当成未定义行为">
  **现象：** 写错值后看到浏览器保留了旧样式，就说“规范允许任意结果”。**原因：**
  无效声明通常在解析阶段被丢弃，旧值来自层叠或继承，不是未定义语义。**修法：**
  先验证语法和属性值语法，再检查层叠来源与继承链。
</Callout>

<Callout type="trap" title="把继承得到的值当成作者直接指定">
  **现象：** 子元素看起来有颜色或字体，就认为它拥有同一条声明。**原因：**
  没有区分指定值、初始值与继承值。**修法：**
  沿父子关系记录指定值、计算值和使用值，给出缺失声明时的对照。
</Callout>

<Callout type="trap" title="用多个浏览器恰好相同证明存在契约">
  **现象：** 两个浏览器当前输出一致，就把结果写进组件合同。**原因：**
  一致的实现结果不等于规范承诺，未定义边界仍可能随内容、视口或版本分叉。**修法：**
  圈定规范边界，改写为明确结构，并保存跨环境与恢复证据。
</Callout>

## 术语如何进入值阶段

### 属性、值与声明

<Term def="规定元素可接受哪类样式输入及其语义的命名槽位">属性</Term>
是输入的名字，
<Term def="被属性接受并参与解析、层叠或布局的具体记号或数据">值</Term>
是它接受的内容，二者组成一条声明。关键字、长度、百分比、颜色、字符串、函数和变量替换都只是值的不同形态；只有匹配属性值语法，声明才有机会进入后续阶段。

### 关键字、单位与功能符

<Term def="由规范预先定义、以名字表达特殊语义的值记号">关键字</Term>
可能表示初始、继承、自动或某个属性专属状态；长度单位把数值与参考尺度连接起来；功能符则可能在解析时展开为颜色、计算或资源。替换变量时仍要重新检查结果是否满足目标属性的值语法，不能因为字符串来自变量就绕过解析。

### 从解析到使用

有效声明先参与层叠，随后结合初始值、继承、相对单位和布局上下文得到<Term def="当属性没有有效指定或继承输入时由规范提供的起始值">初始值</Term>、计算值和使用值。<Term def="把可继承属性的计算结果沿父子关系传给后代的规则">继承</Term>不是复制文本，而是值阶段中的一条明确关系；实际呈现还可能受平台字体、设备和绘制实现影响。

### 未定义行为的边界

<Term def="规范没有规定唯一结果、因此作者不能把实现偶然性写成可移植保证的状态">
  未定义行为
</Term>
与无效语法不同：前者表示边界内没有唯一承诺，后者通常在解析阶段退出。实验要先指出哪一条规则停止提供保证，再确认边界外的属性、继承、盒生成和使用值仍按定义工作。

## 出版社目录逐项映射

### 第2章 需提前了解的术语和概念

本章把术语变成实验入口：先拆分输入，再问它是否有效，接着追踪层叠、继承、计算值与使用值，最后检查规范是否提供唯一契约。若只背名词而不写出阶段和证据，仍然无法解释跨浏览器差异。

### 2.1 务必了解的CSS世界的专业术语

属性、值、关键字、变量、长度单位、功能符和声明是互相嵌套但不等价的概念。属性规定槽位，值提供数据，关键字提供规范语义，单位提供尺度，功能符提供计算或资源入口，声明把属性和值组成可参与样式处理的输入。

### 2.2 了解CSS世界中的“未定义行为”

未定义行为要求谨慎声明结论。先标出规范没有承诺唯一结果的边界，再把边界外仍然定义的部分单独验证。两个浏览器短暂给出相同结果只能成为观察记录，不能替代规范来源、反例、版本边界和恢复测试。

## 值阶段证据表

每个样本写六列：**原始声明、解析结论、层叠与继承来源、计算值、使用值、跨环境结果**。无效语法的恢复是删除或修正输入；未定义行为的恢复是改写结构或声明；继承问题的恢复是明确指定或明确初始值。三种恢复不能混用。

```text
input     = property + value + keyword + unit + function + declaration
pipeline  = specified -> parsed -> cascaded -> computed -> used -> actual
boundary  = defined_rule | invalid_input | undefined_result
evidence  = spec_link + browser_A + browser_B + viewport_pair + replay
```

```css
.card {
  color: inherit;
  width: auto;
  padding-inline: 1rem;
}

.card__label {
  color: var(--label-color, currentColor);
}
```

这个样本把继承、关键字和变量回退分开观察。变量替换后的结果仍需满足 `color` 的值语法；`auto` 也要等待布局上下文才能得到使用值。若测试要研究未定义行为，应另写一个明确的边界样本，不把正常声明污染成“浏览器试试看”。

## 练习

<Exercises>

**问题 1：** `color: 12px` 为什么不能作为“浏览器自由选择颜色”的证据？

<Answer>
  因为 `12px` 不符合 color
  属性的值语法，声明应在解析阶段被丢弃；页面仍显示颜色时，要继续查找层叠来源、继承或初始值，不能把无效输入称为未定义行为。
</Answer>

**问题 2：** 一个子元素显示父元素的颜色，如何证明这是继承而不是重复指定？

<Answer>
  保存子元素没有 color
  声明的样本，再记录父元素的指定值、子元素的计算值与使用值；随后移除父声明或设置明确初始值，比较链条是否断开。只有沿父子关系的对照能证明继承。
</Answer>

**问题 3：** 两个浏览器结果一致时，什么时候仍不能把结果写入组件合同？

<Answer>
  当规范没有规定唯一结果、测试只覆盖一个内容和视口，或结果依赖实现细节时不能承诺。应先引用规范边界，再改写为明确
  DOM 和声明，并在两个浏览器、两个视口和恢复样本中重放。
</Answer>

</Exercises>

## 小结

- 属性、值、关键字、单位、功能符和声明位于不同层次，先拆分再验证。
- 无效语法、继承得到的值和未定义结果必须分别记录，不能用一个“浏览器表现”概括。
- 值阶段从指定和解析开始，经过层叠、继承、计算与使用，实际呈现还受环境影响。
- 可移植 CSS 契约来自规范边界、明确结构、跨环境样本和恢复重放，而不是一次正常截图。
