## 从一个 `width:auto` 到底问什么开始

看到“这个盒子为什么这么宽”，先不要把 `auto` 翻译成一个固定数字。固定 DOM、stylesheet、视口、字体与内容，先辨认元素生成的盒，再确认它读取的<Term def="为盒的尺寸与位置提供参考的祖先盒或初始坐标系">包含块</Term>，最后写出内容约束、最小最大约束和使用值。图中的样本可切换块级基线、窄容器和内联空白；动手前先预测哪一阶段会改变。

## 三个需要先拆开的误区

<Callout type="trap" title="把 width:auto 当成 100%">
  **现象：** 任意元素写上 auto 就被解释为父盒宽度的百分比。**原因：**
  忽略元素类型、格式化上下文、浮动/定位状态、内容约束和外边距。**修法：**
  先列出包含块与可用空间，再从指定值推导实际使用值。
</Callout>

<Callout type="trap" title="把声明宽度当成内容宽度">
  **现象：** 写了 width 后直接量内容区域，padding、border 或 box-sizing
  变化却无法解释。**原因：** 没有区分外在盒、内在盒和盒尺寸计算入口。**修法：**
  把外部占位和内部承载分开记录，逐项加入 padding、border 与约束。
</Callout>

<Callout type="trap" title="把内联空白当成随机浏览器间距">
  **现象：** 图片或 inline-block 之间出现空隙，就用负 margin
  盲目抵消。**原因：** 忽略文本节点、字体空白、行框和基线。**修法：**
  保留/移除行尾空白做对照，记录行框与字体度量，再决定结构修复。
</Callout>

## 基本尺寸的求解链

### 外在盒、内在盒和包含块

<Term def="元素在父级格式化上下文中形成的占位与排列边界">块级元素</Term>
通常产生参与块格式化的外在盒，内容则由内在容器盒承载。外在盒回答“在流中占什么位置”，内在盒回答“内容如何放进去”；两者都要引用包含块，不能从
DOM 标签名直接猜像素。

### width:auto 的第一性问题

<Term def="让宽度由当前格式化上下文、包含块和内容约束共同求解的宽度状态">
  width:auto
</Term>
需要上下文。普通块级非替换元素常尽量利用可用内联空间，浮动或绝对定位可能收缩包裹，内容最小尺寸又可能抬高下限。实验必须记录元素状态、外边距和可用空间。

### 宽度分离

<Term def="让外层尺寸服从流与容器、内层通过间距承载内容的布局策略">
  宽度分离
</Term>
把“占多少空间”和“内容离边缘多远”拆成两个问题。外层保持流体，内层承载
padding、margin 或装饰；这样内容变化时不需要用固定宽度反复修补。

### 约束和尺寸入口

min-width、max-width、min-height、max-height、box-sizing、替换元素固有尺寸和内容最小尺寸都可能参与最终结果。先写基础使用值，再按规范顺序应用约束，才能知道是哪个边界把尺寸推高或压低。

## 出版社目录逐项映射

### 第3章 流、元素与基本尺寸

本章把“元素如何进入流”和“尺寸如何落地”放在一条链上：先辨认盒，再找到包含块，接着求解 auto 和约束，最后检查内联行框。21 个目录节点都要回到这条链，不能只记属性名称。

### 3.1 块级元素

块级元素的外在盒通常沿块方向排列并占据自己的布局位置；内容盒还要承载文字、替换元素或后代。宽度实验应同时记录外部占位、内容区域、外边距和父级可用空间。

### 3.1.1 为什么list-item元素会出现项目符号

list-item 的可见项目符号不是普通文本节点的偶然装饰，而是列表布局语义创造的额外排版对象。验证时比较 list-item 与普通 block 的盒结构、marker 位置和可用空间，避免把项目符号当成 margin。

### 3.1.2 display:inline-table的盒子是怎样组成的

inline-table 同时具有参与内联排列的外部表现和表格内部的布局结构。外部盒进入行框，内部表格盒协调行列；改变 display 时要分别记录外部行框、内部尺寸和基线，而不是只量最外层矩形。

### 3.1.3 width/height作用在哪个盒子上

这个问题要先放回当前格式化上下文，观察外部占位、内容区域、内边距和边框如何分别参与尺寸，再比较不同盒模型。width 与 height 的语义入口取决于盒类型和 box-sizing 等条件。应把 content、padding、border 和 margin 分栏，验证声明影响的是内容尺寸、边界尺寸还是外部占位，不能从 DevTools 的单一数值倒推。

### 3.2 width/height作用的具体细节

这一组节点把 width、height 从概念推进到约束求解。height 常受内容和流影响，百分比需要明确的参考高度；width 则在块、浮动、绝对定位和内联语境有不同的使用值路径。

### 3.2.1 深藏不露的width:auto

width:auto 的重点是“谁提供可用空间”。普通块盒往往充分利用包含块，浮动盒可能收缩包裹，外边距还能改变可分配空间。每次只改变元素的参与方式，才能分辨 auto 自身与流状态的影响。

### 3.2.2 width值作用的细节

声明 width 后仍要检查百分比参考、内在尺寸、最小内容宽度和盒尺寸模型。一个 20rem 的声明不自动等于内容区域 20rem；padding、border 和 box-sizing 可能改变外部边界与溢出结果。

### 3.2.3 CSS流体布局下的宽度分离原则

宽度分离让外部容器服从流，内部内容用间距与约束获得可读性。它适合响应式容器，因为父级变窄时外盒可收缩，内部 padding 不需要通过重新计算固定 width 才能保持结构。

### 3.2.4 改变width/height作用细节的box-sizing

这个节点要先固定内容、padding 和 border，把内容盒与边界盒的测量分开；只有尺寸入口明确，才知道溢出来自哪里。box-sizing 改变 width 和 height 的尺寸入口。实验应保持内容、padding 和 border 不变，只切换 box-sizing，分别记录 content-box 与 border-box 的使用尺寸，再验证是否出现滚动或溢出。

### 3.2.5 相对简单而单纯的height:auto

height:auto 通常让内容、内边距、边框和后代排版共同决定块盒高度。若给父级一个固定高度或隐藏溢出，表面高度可能暂时稳定，但内容变化时会暴露真实约束；恢复测试要删除固定高度再重放。

### 3.2.6 关于height:100%

height:100% 需要一个可解析的参考高度，父级高度为 auto 时往往没有可直接继承的百分比基准。测试应同时保留父级明确高度、父级 auto 和内容增长三个样本，区分百分比无效、使用值受约束与内容溢出。

### 3.3 CSS min-width/max-width和min-height/max-height二三事

min/max 是对基础求解结果施加的边界。它们可以保护可读性，也可能让流体容器在窄视口中溢出；验收要记录哪个约束获胜、内容最小尺寸是否介入，以及外部占位是否还能解释。

### 3.3.1 为流体而生的min-width/max-width

min-width 与 max-width 让容器在可变空间中拥有上下限。常见的流体合同是宽度随包含块缩放、最大宽度限制阅读行长、最小宽度保护内容；窄容器样本要检查三者的优先顺序。

### 3.3.2 与众不同的初始值

不同属性的初始值不应凭经验互换。实验要从规范或浏览器计算样式确认初始值，再比较未指定、显式 initial、继承和实际使用值；“没有写”不是所有属性的同一种状态。

### 3.3.3 超越!important，超越最大

`!important` 只改变层叠优先级，不会把 max-width 变成无限大，也不会跳过尺寸约束。若结果被最大尺寸挡住，应检查约束与包含块，而不是继续堆叠重要声明。

### 3.3.4 任意高度元素的展开收起动画技术

展开收起需要先知道内容的实际高度，再决定动画或状态切换的边界。不要把 auto 当作可直接插值的数字；记录测量时的盒、内容变化和最终恢复状态，避免把动画技巧误认为基本尺寸规则。

### 3.4 内联元素

内联元素参与行框而非独立的块级占位。它的宽度由内容和字体度量组成，高度与 line-height、基线、替换元素和上下文有关；尺寸实验应转向行框证据，而不是只读取元素外接矩形。

### 3.4.1 哪些元素是内联元素

文本、span、链接、图片和 inline-block 等在行内语境中的外部表现不同。先比较 display 和生成盒，再观察换行、基线与空白；不要把“标签常见用法”当作永久布局合同。

### 3.4.2 内联世界深入的基础——内联盒模型

<Term def="描述内容区域、行内盒、行框、字体度量和基线如何共同形成内联排版的模型">
  内联盒模型
</Term>
要同时看内容区域、行内盒、行框、基线和字体度量。line-height
为行框提供高度线索，vertical-align
改变对齐关系；多字体和替换元素样本能揭示隐藏的垂直空间。

### 3.4.3 幽灵空白节点

HTML 源码换行或缩进可能形成<Term def="由源码换行或空格形成、会参与内联排版并影响可见间距的文本节点">幽灵空白节点</Term>，它会参与内联排版并在 inline-block 或图片之间留下间距。恢复实验应只删除空白节点或改变结构，再比较行框、基线和可见间隔，避免用负 margin 掩盖原因。

## 尺寸证据记录

每个样本写六列：**元素类型与内容、外在盒与内在盒、包含块、计算值与使用值、行框/基线、恢复结果**。块级样本增加外边距和 min/max，auto 样本增加浮动或定位状态，内联样本增加字体和空白节点。截图只作为最后一列的辅助，不替代前五列。

```text
fixed    = DOM + stylesheet + viewport + fonts + content
boxes    = outer_box + inner_box + containing_block + line_boxes
solve    = specified -> computed -> constraints -> used_value
branch   = one_change + first_divergence + replay
contract = fluid_outer_size && explainable_inner_content
```

```css
.panel {
  width: auto;
  min-width: 0;
  max-width: 40rem;
  margin-inline: auto;
}

.panel__content {
  margin-inline: 1rem;
}
```

这段代码把外层尺寸与内部内容分开：外层响应包含块，内层通过间距承载内容。要验证 `box-sizing`、高度百分比或幽灵空白，应另建单变量样本，保存原始输入和恢复路径。

## 练习

<Exercises>

**问题 1：** 一个普通块级元素写 `width: auto`，容器从 640px 变为 320px。请先预测外在盒、内容宽度和行框的变化。

<Answer>
  先确认包含块和外边距，再预计 auto
  会重新利用较窄的可用空间；内容区域随之变窄，长文本可能增加行框数量并推高
  height。若出现超出 320px 的结果，还要检查 padding、border、min-width 和
  box-sizing。
</Answer>

**问题 2：** 为什么推荐把外层宽度和内层间距分离，而不是同时固定 width 与 padding？

<Answer>
  外层宽度服从流和容器变化，内层间距只表达内容与边界的关系；这样窄视口和长内容不会因为总尺寸重复计算而产生补丁。实验中分别切换外层
  width、内层 padding，并记录外在盒和内容盒。
</Answer>

**问题 3：** 图片或 inline-block 之间出现空隙时，如何证明它来自幽灵空白节点？

<Answer>
  保持字体、line-height、尺寸和样式不变，只删除源代码中的换行或空格文本节点；若间隙和行框基线同步改变，且恢复空白后重新出现，才可以把它归因于内联空白，而不是
  margin 或图片自身。
</Answer>

</Exercises>

## 小结

- 先辨认元素类型、生成盒和包含块，再解释 width、height 与内容尺寸。
- width:auto 是上下文中的求解状态；min/max、固有尺寸、box-sizing 和内容约束会继续改变结果。
- 宽度分离让外部占位与内部承载各自承担清晰责任，适合流体布局。
- 内联盒、行框、字体基线和幽灵空白节点必须用排版证据解释，不能靠负 margin 猜修。
