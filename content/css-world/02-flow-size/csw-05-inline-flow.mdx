# 第 5 章 内联元素与流

本章以张鑫旭著《CSS 世界》人民邮电出版社版的第 5 章公开目录为身份基线，采用独立教学改写。核心问题不是把一张截图调到相同像素，而是说明字符、替换元素、行内盒、行框盒和基线怎样在同一行里相遇；再用 `line-height` 与 `vertical-align` 找到首个变化。

<Objectives>

- 能从字体度量、基线和 x-height 预测一个内联行的行内盒、行框盒与对齐关系。
- 能用单变量实验解释 line-height 的 leading 分配、vertical-align 的基线位移、图片底部空隙和“大值”现象。
- 能在宽度、字体、内容长度和替换元素改变时，记录计算值、使用值、首个偏离点与恢复结果。

</Objectives>

## 先从一条基线开始

内联格式化的直觉入口是一条基线：字符的笔画围绕它展开，字体还提供 x-height、上伸部和下伸部等度量；替换元素则带着自己的盒子进入同一行。先固定 DOM、字体、视口和内容，再预测哪些盒会生成。图中的行框、字符和图片可以逐步播放；动手前先写下“哪一个盒最高、基线在哪里、行框会多高”。

## 三个必须先拆开的误区

<Callout type="trap" title="把 line-height 当成元素 height">
  **现象：** 给一段文字设置较大的
  line-height，就断言文字元素本身拥有同样高的内容盒。**原因：** line-height
  参与行框形成，行框由一行中的行内盒共同撑起，并不等于某个字符的外部盒。**修法：**
  分别记录字体度量、行内盒、行框盒和元素的计算值与使用值。
</Callout>

<Callout type="trap" title="把图片底部空隙当成图片多出来的 margin">
  **现象：** 图片底部出现一小段空白，直接给图片负 margin。**原因：**
  图片默认作为替换元素按基线参与行内排版，基线下方要保留字体下行空间。**修法：**
  先画出基线和行框，再用 vertical-align、display 或行高实验验证首个偏离点。
</Callout>

<Callout type="trap" title="把 vertical-align 当成任何盒子的 top 偏移">
  **现象：** 对块级盒设置 vertical-align，位置没有变化，于是继续堆叠 top 和负
  margin。**原因：** vertical-align
  的作用前提是内联或表格单元格上下文，且它改变的是对齐关系。**修法：**
  先确认格式化上下文，再比较基线、行内盒和行框盒的变化。
</Callout>

## 六阶段机制链

### 1. 读取字体度量

固定字体、字号、字形和内容，先读取<Term def="字体中小写字母主体高度的度量，影响字符相对基线的视觉位置">x-height</Term>，再标出上伸部、下伸部和基线。字体回退会改变这些度量，所以边界实验必须记录真实字体和回退路径。

### 2. 建立行内盒

文本、图片和其他内联内容进入同一个格式化上下文后，各自形成<Term def="参与内联格式化、承载文本或替换内容的局部盒子">行内盒</Term>。行内盒不是字符轮廓本身，也不等同于父元素的 content box；它要和内容、字体度量及对齐方式一起观察。

### 3. 计算行框

一行中的行内盒按照基线和对齐规则排列，最高的参与者决定<Term def="包住一行内联内容、由行内盒和 leading 共同撑起的盒子">行框盒</Term>的范围。先画出顶部、底部和基线，才能解释为什么一个很高的替换元素会拉高整行。

### 4. 形成 line-height

<Term def="参与行框形成并在行内盒上下分配 leading 的行高属性">line-height</Term>
不只是一条装饰属性；它把额外的 leading
分到行内盒上下，影响行框的可用高度。使用无单位数值时，继承的是比例；使用长度或百分比时，要记录计算值和继承时机，避免把声明值直接当最终结果。

### 5. 应用 vertical-align

<Term def="在适用上下文中改变行内参与者相对参考线位置的属性">
  vertical-align
</Term>
在适用的内联或表格单元格上下文中改变相对对齐位置。它可以将替换元素、文本和行内块相对
<Term def="文字基准线，行内内容默认围绕它进行垂直对齐">基线</Term>
移动，但不会抹掉行框、字体下行空间或内容固有尺寸。

### 6. 按基线恢复重放

删除故障声明后，重放同一 DOM、字体和视口；比较首个偏离点是否消失。恢复通过的证据不是“看起来差不多”，而是行内盒、行框盒、基线、使用值和窄宽内容下的流体契约同时回到可解释状态。

## 出版社目录逐项映射

### 第5章 内联元素与流

本章的主线是“字体度量—行内盒—行框—基线”。它把看似零散的字母 x、line-height 和 vertical-align 放进同一条证据链，解释内联内容为什么会改变高度和垂直位置。

### 5.1 字母x——CSS世界中隐匿的举足轻重的角色

字母 x 是观察字体度量的低成本探针。它不是一个独立 CSS 盒子，却能帮助我们识别 x-height、基线和字体回退带来的视觉变化；实验应锁定字号和实际字体，不能只凭字形截图猜测。

### 5.1.1 字母x与CSS世界的基线

字符的基线是行内对齐的参照线，字母 x 的主体通常围绕 x-height 展开。把基线画出来，再观察同一行的图片和文本，才能区分“图片下方有空间”与“图片自身有 margin”。

### 5.1.2 字母x与CSS中的x-height

x-height 影响字母主体相对字体 em 方框的位置，也会影响视觉上的垂直居中感。替换字体或字体回退后，x-height 可能改变；因此要把字体来源、字号、line-height 和最终使用值作为一组证据。

### 5.1.3 字母x与CSS中的ex

`ex` 是以当前字体 x-height 为参考的相对长度单位。它不是固定等于某个字号比例，字体切换会使相同的 `1ex` 得到不同的实际长度；在实验中应比较字体确定前后的计算值与使用值。

### 5.2 内联元素的基石line-height

`line-height` 是内联排版的高度入口之一。它参与行框形成，却不等价于字符墨水高度；只有把 leading、行内盒、行框盒和基线分开，才能解释一段文本为何撑开父容器。

### 5.2.1 内联元素的高度之本——line-height

对内联元素而言，行高是排版空间而不是某个字的轮廓高度。无单位数值会随着元素字号计算，长度值和百分比则在继承链上有不同的计算时机；测试时应同时看父子元素的计算值与使用值。

### 5.2.2 为什么line-height可以让内联元素“垂直居中”

单行文本在高度合适的 line-height 中会呈现近似垂直居中，是因为 leading 在行内盒上下分配，而不是因为字符盒突然变成了容器高度。换字体、加上下行部字符或改成多行后，这个近似需要重新验证。

### 5.2.3 深入line-height的各类属性值

`normal`、无单位数值、长度和百分比各自有计算与继承差异。先保存声明值，再读取计算值和使用值；不要把 DevTools 的一个数字倒推成所有后代都使用同一长度。

### 5.2.4 内联元素line-height的“大值特性”

当多个内联参与者的 line-height 或固有高度差异很大时，行框会被较高的参与者影响。大值可能来自文字、图片、行内块或对齐位移；定位时要逐个隐藏或恢复一个参与者，而不是用固定高度遮盖结果。

### 5.3 line-height的好朋友vertical-align

line-height 负责行框的高度条件，vertical-align 负责参与者在基线关系中的位置。两者必须放在同一条实验轨迹里观察，否则会把对齐变化错归因于 margin、top 或 transform。

### 5.3.1 vertical-align家族基本认识

vertical-align 包含基线、middle、文本顶部/底部、上标下标和数值或百分比等类别。每一类都要说明参考线和作用上下文，不能把它们概括成一个通用的“向上偏移”。

### 5.3.2 vertical-align作用的前提

先确认元素处于内联格式化上下文，或是表格单元格。块级盒不因为写了 vertical-align 就自动获得同一行的基线；若作用前提不成立，应该回到盒生成和格式化上下文检查。

### 5.3.3 vertical-align和line-height之间的关系

vertical-align 的参考线来自行内排版，而 line-height 决定行框和 leading 的空间。改变 line-height 可能改变 middle 的视觉位置；改变 vertical-align 也可能改变行框需要容纳的最高参与者，二者必须做单变量对照。

### 5.3.4 深入理解vertical-align线性类属性值

数值和百分比类值相对元素自身 line-height 计算位移。它们不是固定像素 top 偏移，字号、继承的 line-height 和字体变化都会影响结果；恢复实验应重新计算而不是复用旧数字。

### 5.3.5 深入理解vertical-align文本类属性值

text-top、text-bottom、top 和 bottom 以行或文本相关边界参与对齐。若行中同时出现图片、文字和行内块，最终位置还受最高行内盒和行框边界影响，所以要画出参考线再判断。

### 5.3.6 简单了解vertical-align上标下标类属性值

sub 与 super 体现了基于字体排版的上标下标对齐，不应简单替换成负 margin。它们会与字体度量、行高和可读性共同作用；实验应检查长内容、多行和字体回退后的行框变化。

### 5.3.7 无处不在的vertical-align

vertical-align 还会出现在图片、图标、inline-block、表格单元格和表单控件的对齐问题中。每次遇到“底部多一条空白”或“图标不在文字中线”，先检查是否进入了基线对齐路径。

### 5.3.8 基于vertical-align属性的水平垂直居中弹框

利用行内格式化和 vertical-align 可以构造传统的水平垂直居中方案，但方案依赖行框、占位元素、字体和内容高度。要在窄视口、长内容、键盘焦点和滚动状态下验收，不能只看一个固定尺寸的弹框截图。

## 盒与基线的证据记录

每个样本写六列：**DOM 与内容、字体与 x-height、行内盒与格式化上下文、行框与基线、计算值与使用值、恢复结果**。替换元素增加固有尺寸和资源状态，字体边界增加回退路径，line-height 增加继承时机，vertical-align 增加参考线和作用前提。

```text
freeze = DOM + stylesheet + viewport + fonts + content
predict = generated inline boxes + baseline + line box
change = exactly one line-height | vertical-align | font | width variable
stop = first divergent computed or used value
replay = remove fault + same inputs + fluid contract restored
```

```css
.inline-row {
  font-size: 16px;
  line-height: 1.5;
}

.inline-row > img {
  width: 1em;
  height: 1em;
  vertical-align: -0.15em;
}
```

第一个样本用于验证默认基线与图片底部空间，第二个样本用于验证 line-height 的大值特性，第三个样本用于验证 vertical-align 的相对位移。字体回退、长内容和窄视口都要沿同一条记录表重放。

## 练习

<Exercises>

**问题 1：** 为什么图片默认按基线排版时，底部可能出现一小段空隙？

<Answer>
  因为图片作为替换元素参与行内格式化，默认基线对齐；基线下方仍为字体保留下行空间。先画出基线和行框，再选择
  vertical-align、display 或行高策略，而不是先加负 margin。
</Answer>

**问题 2：** `line-height: 2` 为什么不等于“文字的 content box 高度是字号的两倍”？

<Answer>
  无单位 line-height 是相对字号的比例，会参与 leading
  和行框形成；字符墨水、行内盒、行框盒和父元素高度是不同证据。应分别读取计算值、使用值并在多行和大值参与者下重放。
</Answer>

**问题 3：** 设置 vertical-align 没有变化时，应该先检查什么？

<Answer>
  先检查元素是否处于内联或表格单元格上下文，再确认参考线、继承的
  line-height、计算值和使用值。若作用前提不成立，继续调整 top 或负 margin
  只是在遮盖盒生成问题。
</Answer>

</Exercises>

## 小结

- 字体度量提供 x-height、上伸部、下伸部和基线等观察入口；字体回退会改变这些输入。
- 行内盒是参与者，行框盒是整行容纳参与者后的结果；不能用一个元素的 height 代替整条排版链。
- line-height 形成高度条件，vertical-align 改变基线关系；图片底部空隙、垂直居中和大值特性都可以按这条链定位。
- 任何修复都要在窄视口、长内容、替换元素和字体回退下重放，并记录首个偏离点与恢复结果。
