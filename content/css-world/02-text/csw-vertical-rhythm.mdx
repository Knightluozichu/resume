## 直觉引入

行高决定文字行与行之间的距离。你设 `line-height: 1.5`，意思是行高是字号的 1.5 倍——字号 16px 时行高 24px，多出的 8px（行距）上下各分 4px（半行距）。关键陷阱在于继承：无单位值 `1.5` 会被子元素继承后重新计算（子元素字号 20px → 行高 30px），带单位值 `24px` 直接继承固定值（子元素字号 20px → 行高还是 24px，可能太小）。

## 行盒模型

<Term def="行盒（Line Box）是一行文字所在的矩形区域，高度由 line-height 决定，内部包含内容区（font-size）和上下半行距。">行盒</Term>的高度 = `line-height × font-size`。内容区高度 = `font-size`，行距 = `(line-height - 1) × font-size`，上下各分一半为半行距。

```css
.text {
  font-size: 16px;
  line-height: 1.5;
  /* 行盒高度 = 16 × 1.5 = 24px */
  /* 内容区 = 16px，行距 = 8px，上下各 4px 半行距 */
}
```

## line-height 四种取值

```css
/* 无单位：子元素继承后重新计算（推荐） */
.parent { font-size: 16px; line-height: 1.5; }  /* 24px */
.child  { font-size: 20px; }                     /* 继承 1.5 → 30px ✓ */

/* 带单位：子元素继承固定值（隐患） */
.parent { font-size: 16px; line-height: 24px; }  /* 24px */
.child  { font-size: 20px; }                     /* 继承 24px → 可能太小 ✗ */

/* 百分比：计算后继承固定值（同带单位隐患） */
.parent { font-size: 16px; line-height: 150%; }  /* 24px */
.child  { font-size: 20px; }                     /* 继承 24px ✗ */

/* normal：浏览器默认（约 1.2，随字体变化） */
.auto { line-height: normal; }
```

## vertical-align 基线对齐

<Term def="vertical-align 设置 inline/inline-block 元素在行盒内的垂直对齐方式，基于基线（baseline）定位。">vertical-align</Term> 只对 `inline` 和 `inline-block`（及 `table-cell`）元素生效，对块级元素无效。常用值：`baseline`（基线对齐，默认）、`top`（行盒顶）、`middle`（行盒中点）、`bottom`（行盒底）。

```css
/* 经典问题：图片底部有间隙 */
img { vertical-align: middle; }  /* 改为 middle/top 消除底部间隙 */
/* 原因：img 默认 baseline 对齐，基线下方有半行距留空 */

/* 行内块与文字居中对齐 */
.icon { vertical-align: middle; }
```

## 垂直韵律

垂直韵律是让所有间距成为基线的整数倍，形成视觉节奏感。

```css
:root { --baseline: 8px; }
h1 { font-size: 24px; line-height: 1.33; margin-bottom: calc(var(--baseline) * 4); } /* 32px */
p  { font-size: 16px; line-height: 1.5;  margin-bottom: calc(var(--baseline) * 2); } /* 16px */
```

## 常见误区

<Callout type="trap">
**误区：`line-height: 1.5` 和 `line-height: 150%` 效果一样。** 在设置元素自身上确实都是 24px，但继承行为完全不同。`1.5` 是无单位数，子元素继承的是「1.5 这个比例因子」，会在子元素自己的 font-size 上重新计算；`150%` 是百分比，在父元素上就计算成了 24px 这个固定值，子元素继承的是 24px 而非 150%。当子元素字号比父元素大时，`150%` 继承的固定值会导致行高不足、文字挤在一起。这就是为什么推荐用无单位值——它让行高随字号自适应。
</Callout>

<Exercises>
**问题 1**：line-height 无单位值和带单位值在继承时有什么本质区别？

<Answer>
无单位值（如 1.5）：子元素继承的是比例因子 1.5，会在子元素自身的 font-size 上重新计算。父元素 16px → 行高 24px；子元素 20px → 行高 30px（1.5×20）。带单位值（如 24px）和百分比（如 150%）：在设置元素上就计算成固定值 24px，子元素继承的是 24px 这个固定值而非比例。子元素 20px → 行高还是 24px，可能小于字号导致文字重叠。本质区别：无单位值传递的是「比例」（动态重算），带单位/百分比传递的是「计算结果」（固定继承）。
</Answer>

**问题 2**：为什么图片下方会有几像素的间隙？如何消除？

<Answer>
原因：img 是 inline 元素，默认 vertical-align: baseline，即图片底部与文字基线对齐。而基线下方还有「下沉」空间（字母 g/y 等下半部分占的区域），这部分是半行距的下半部分，所以图片底边到容器底边之间留出了这段空隙。解决方案：① `vertical-align: middle/top/bottom`（改变对齐方式，不再贴基线）；② `display: block`（变成块级，脱离行盒，无基线问题）；③ `line-height: 0`（父容器行高设为 0，消除半行距）。最推荐 vertical-align: middle 或 display: block。
</Answer>
</Exercises>
