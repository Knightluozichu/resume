# 第 6 章 流的破坏与保护

本章以张鑫旭著《CSS 世界》人民邮电出版社版的第 6 章公开目录为身份基线，采用独立教学改写。这里的“破坏”不是错误，而是元素不再按普通流的原路径参与尺寸和位置计算；真正需要解释的是：哪一部分空间离开了普通流、谁继续受到它影响、哪个边界负责保护，以及如何在窄视口和长内容下恢复流体契约。

<Objectives>

- 能画出 float、absolute、relative 和 fixed 对普通流占位、环绕范围与包含块的不同影响。
- 能用单变量实验解释 clear、BFC、overflow、clip 和定位偏移各自解决的边界问题。
- 能在故障注入后记录首个偏离点、计算值、使用值、包含块、层叠关系和恢复结果。

</Objectives>

## 三个必须先拆开的误区

<Callout type="trap" title="把 float 当成完全脱离流的 absolute">
  **现象：** 浮动盒旁边的文字仍会环绕，却被当作已经完全脱离普通流。**原因：**
  float 改变块级排列方式，但行盒仍会避让浮动区域。**修法：**
  分别记录块的占位、行盒的环绕边界和父容器的高度，再决定是否需要 clear 或 BFC。
</Callout>

<Callout type="trap" title="用 overflow:hidden 一键修复所有塌陷和溢出">
  **现象：** 加上 overflow:hidden
  后高度看似恢复，却发现阴影、滚动条或锚点行为改变。**原因：** overflow
  可能建立新的边界或滚动容器，同时剪裁超出 border box 的内容。**修法：**
  把包裹浮动、剪裁绘制、产生滚动和锚点定位拆成独立实验。
</Callout>

<Callout type="trap" title="把 absolute 的位置当成相对视口坐标">
  **现象：** absolute 元素在祖先加上 position 后突然换了位置，继续调整
  left/top。**原因：** absolute
  读取最近的定位祖先作为包含块，固定定位还可能受特殊包含块影响。**修法：**
  先标注包含块和 padding edge，再解释四向偏移、尺寸约束及恢复路径。
</Callout>

## 六阶段机制链

### 1. 观察正常流基线

固定 DOM、样式表、视口、字体和内容，先列出块级盒的顺序、占位高度、行盒边界和父容器高度。后续每个样本都从这份基线出发，避免把浏览器默认流与修复声明混成一个结果。

### 2. 注入环绕或脱流

只加入一个 float、position 或 overflow 声明，记录哪个盒仍占位、哪个盒开始环绕、哪个盒转而读取包含块。首个变化点比最终像素更有价值，因为它能说明破坏范围是局部的还是跨越整个容器。

### 3. 建立保护上下文

用 clear、BFC 或明确的 overflow 边界隔离影响，观察父子边界、兄弟间距、浮动包裹和滚动容器是否改变。保护的目标不是让所有内容回到原位置，而是让责任边界可预测。

### 4. 定义剪裁与滚动边界

如果内容超出容器，先判断需要可见、剪裁还是滚动；再分别测试 overflow-x 与 overflow-y。保留 border box、滚动宽高、焦点和锚点证据，避免只凭一张没有滚动条的截图签发。

### 5. 求解定位包含块

absolute、relative 和 fixed 的空间来源不同。先确定最近定位祖先、视口或特殊包含块，再读取 left/top/right/bottom、auto 尺寸和 margin:auto 的共同约束；不要把定位元素的视觉坐标直接当作普通流坐标。

### 6. 恢复并重放流体边界

删除故障声明，重放同一 DOM 和输入；再换窄视口、长内容、滚动状态和书写方向。只有占位、剪裁、包含块、层叠和可访问焦点都能回到预期，恢复才算完成。

## 出版社目录逐项映射

### 第6章 流的破坏与保护

本章把“脱离普通流”拆成四个问题：空间是否继续占位、行盒是否环绕、边界是否被保护、位置由哪个包含块决定。float、clear、BFC、overflow 与 position 不是同一类修复开关，必须沿不同证据链验收。

### 6.1 魔鬼属性float

<Term def="让盒子偏向一侧并让后续行盒避让其浮动区域的布局属性">float</Term>
改变盒的排列和环绕关系，但不等于 absolute
那样把所有关联都切断。先区分块级占位和行盒避让，再观察父容器是否能包住浮动。

### 6.1.1 float的本质与特性

float 会让盒子向左或向右移动，后续内容在可用行宽中绕开它；它依然属于当前布局问题的一部分。内容变长或容器变窄时，环绕高度和可用宽度都会变，不能把浮动看成固定坐标图标。

### 6.1.2 float的作用机制

浮动先改变自己的盒生成和位置，再影响同一格式化上下文中的行盒。测试时固定浮动宽度，逐步改变文字长度，记录文本行的起始 x、父高度和浮动边界，才能说明“环绕”发生在哪里。

### 6.1.3 float更深入的作用机制

多个浮动会相互避让，清除和父子边界还会叠加影响。把第二个浮动、长文本或 padding 作为单变量加入，比较它们是否改变了可用行宽、浮动堆叠顺序和父容器的包裹范围。

### 6.1.4 float与流体布局

float 可以构成旧式流体多栏，但宽度、间隙和内容长度必须留出可折返空间。实验应至少覆盖宽视口、窄视口和长单词，并记录浮动列宽、剩余行宽、溢出状态与恢复方案。

### 6.2 float的天然克星clear

<Term def="让盒子避开指定方向浮动影响、从浮动边界之后开始排列的属性">
  clear
</Term>
把后续盒推到浮动影响边界之外。它解决的是某个盒的排列起点，不自动让父元素拥有浮动子元素的高度，也不负责剪裁或滚动。

### 6.2.1 什么是clear属性

clear 的 left、right、both 值对应不同方向的浮动边界。记录 clear 盒的上边缘、浮动盒的下边缘和父容器高度，能区分“清除生效”与“父容器被包裹”这两个问题。

### 6.2.2 成事不足败事有余的clear

clear 只能影响后续盒的排列，不能替代 clearfix、BFC 或 overflow 的包裹职责。若 clear 元素本身被隐藏、处在不同格式化上下文或被定位脱流，视觉上可能没有变化，应先确认它是否仍参与正常流。

### 6.3 CSS世界的结界——BFC

<Term def="把一组盒放入独立块级格式化上下文、隔离部分外部流影响的布局上下文">
  BFC
</Term>
是边界责任的重新划分：浮动可以被容器包裹，外部浮动也不会随意穿透。建立 BFC
可能改变 margin 合并、宽度计算和溢出行为，所以每次都要说明它解决的具体边界。

### 6.3.1 BFC的定义

BFC 是独立的块级格式化上下文，内部块按自己的规则排列，浮动和边界计算不会简单地与外部合并。验证时记录触发条件、父高度、兄弟间距和内部宽度，而不是把某一个 CSS 声明背成万能口诀。

### 6.3.2 BFC与流体布局

BFC 常用于让文字列避开浮动、让父容器包裹浮动或隔离两列布局。流体实验要改变容器宽度和内容长度，确认可用宽度来自当前 BFC 的边界，而不是固定 width 恰好掩盖了问题。

### 6.4 最佳结界overflow

<Term def="控制内容超出盒子时可见、剪裁或滚动方式的属性">overflow</Term>
同时可能成为包裹浮动、剪裁绘制和建立滚动容器的边界。它很强，但副作用也多；要先写出目标是保护高度、剪裁视觉还是提供滚动。

### 6.4.1 overflow剪裁界线border box

overflow 的剪裁通常围绕盒的边界展开，border、padding 和背景的位置会影响“可见区域”与“内容区域”的区分。用阴影、绝对定位子元素和 border box 做对照，才能确认被截断的是绘制还是布局占位。

### 6.4.2 了解overflow-x和overflow-y

水平与垂直溢出可以分别控制，但两轴的组合还会影响是否形成滚动容器。窄视口实验要同时记录 scrollWidth、scrollHeight、可见宽高和焦点移动，不能只观察一条滚动条。

### 6.4.3 overflow与滚动条

滚动条会占用或影响可用空间，也会改变锚点、焦点和视觉稳定性。测试时固定内容长度，再切换 visible、hidden、auto 和 scroll，保存滚动位置和键盘路径，区分滚动容器建立与简单剪裁。

### 6.4.4 依赖overflow的样式表现

依赖 overflow 的技巧常用于清除浮动、隐藏超出内容和创建滚动区域，但同一声明可能同时改变父高度、剪裁阴影和定位参照。每个技巧都要拆成“布局结果”和“绘制结果”两列验收。

### 6.4.5 overflow与锚点定位

锚点滚动会寻找能够滚动的祖先；overflow 改变滚动容器后，目标元素可能滚到另一个边界里。用长内容、固定标题和键盘焦点复现，记录滚动祖先与目标矩形，不能仅凭 URL 片段判断成功。

### 6.5 float的兄弟position:absolute

absolute 与 float 都会改变普通流关系，但 absolute 不让后续行盒围绕自身排版。它把位置交给包含块和偏移约束，适合叠放和局部定位，必须同步检查原流占位是否仍由其他盒承担。

### 6.5.1 absolute的包含块

absolute 会寻找最近的定位祖先作为<Term def="为绝对定位或固定定位元素提供尺寸和偏移参考的祖先矩形">包含块</Term>；若找不到，则回到初始包含块或视口相关边界。先画出祖先 padding edge，再解释 left、top、right、bottom 和 auto 尺寸。

### 6.5.2 具有相对特性的无依赖absolute绝对定位

当 absolute 没有明确定位祖先时，它可能表现出相对视口或初始包含块的稳定位置，但这不是“没有依赖”。窗口尺寸、滚动、方向和祖先 transform 都可能改变参考边界，应把依赖链写出来。

### 6.5.3 absolute与text-align

text-align 主要影响内联内容的水平分布，不能把一个 absolute 盒当成普通文本直接居中。要比较 text-align、margin:auto 和 left/right 约束，需先确认绝对盒的包含块、宽度和是否存在可分配的剩余空间。

### 6.6 absolute与overflow

absolute 子元素可以超出普通流父盒，但父级 overflow 仍可能对其绘制区域剪裁。实验要同时改变定位祖先和 overflow 边界，记录子元素的几何位置、可见区域和滚动宽高，避免把“看不见”误判为“没有布局”。

### 6.7 absolute与clip

clip 是对定位元素可见区域的进一步限制，和 overflow 的滚动容器职责不同。先拆开定位、剪裁矩形与滚动边界，再观察焦点和命中区域是否仍然存在。

### 6.7.1 重新认识的clip属性

传统 clip 依赖定位上下文和矩形范围，常用于隐藏绝对定位元素的部分绘制。记录 top、right、bottom、left 的矩形关系与元素本身尺寸，才能说明 clip 改的是绘制可见性，而不是盒生成。

### 6.7.2 深入了解clip的渲染

clip 的渲染边界不会自动改变文档流占位，也不等价于删除节点。用背景、阴影、文本选择和键盘焦点样本检查裁剪后的可见性，才能分辨绘制层与交互层的差异。

### 6.8 absolute的流体特性

absolute 也可以在没有固定 width 的情况下利用左右约束形成流体宽度。这个特性依赖包含块、偏移对和内容最小尺寸，不能简单归类为“脱流就必须固定尺寸”。

### 6.8.1 当absolute遇到left/top/right/bottom属性

同时提供相反方向的偏移会参与尺寸求解，auto width 或 height 也会进入约束。逐项加入 left、right、top、bottom，记录可用宽度、边缘距离和内容溢出，才能看出哪个变量使布局从固定变成流体。

### 6.8.2 absolute的流体特性

绝对定位盒的流体宽度可以适应包含块变化，但长内容、min-width、padding 和 border 仍可能造成溢出。窄视口复测时，应保存包含块宽度、实际 border box、滚动宽度和恢复后的边界。

### 6.8.3 absolute的margin:auto居中

在尺寸和相反方向偏移已明确时，margin:auto 可以参与绝对定位盒的剩余空间分配。它不是所有定位上下文的无条件居中开关；先建立可计算的包含块和盒尺寸，再比较 margin:auto 与 transform 的职责。

### 6.9 position:relative才是大哥

relative 通常保留原来的普通流占位，再对视觉位置施加局部偏移；它常被用来建立 absolute 的包含块。由于占位仍在，必须分别验收文档流位置、绘制位置和后代定位参考。

### 6.9.1 relative对absolute的限制

relative 祖先为后代 absolute 提供局部参照，限制了后代偏移不会随页面其他区域任意漂移。移动祖先、改变 padding 和切换方向，能验证包含块是否真的绑定到了预期边界。

### 6.9.2 relative与定位

relative 的 top、right、bottom、left 改变绘制位置，通常不重新安排其他普通流兄弟。实验应记录原占位、视觉矩形和重叠命中区域，尤其要检查键盘焦点是否被视觉位移遮住。

### 6.9.3 relative的最小化影响原则

relative 只应包住需要建立局部参考或微调位置的最小区域。把它提升到整页根节点会改变后代 absolute 的包含块和维护边界；修复时优先缩小作用域，再验证窄视口和滚动结果。

### 6.10 强悍的position:fixed固定定位

<Term def="让元素相对视口或固定定位包含块保持固定位置、通常不随普通文档流滚动的定位模式">
  position:fixed
</Term>
适合工具栏、浮层和固定操作入口，但会改变占位、滚动、焦点和遮挡关系。使用它之前要明确固定的是哪个矩形、滚动谁以及如何为普通内容预留空间。

### 6.10.1 position:fixed不一样的“包含块”

fixed 通常以视口为参考，但某些祖先的变换等条件可能建立特殊包含块。对比无变换祖先和有变换祖先，记录滚动时的矩形、偏移来源和层叠上下文，不能只用“固定等于视口”概括。

### 6.10.2 position:fixed的absolute模拟

在支持条件有限或需要局部滚动时，可以用 absolute 加定位祖先模拟固定效果；两者在滚动、包含块、焦点和剪裁方面并不完全相同。实验应明确模拟的目标是视觉固定、局部固定还是交互固定。

### 6.10.3 position:fixed与背景锁定

弹层打开时锁定背景滚动，需要同时处理滚动条变化、焦点转移、内容高度和恢复位置。只把 body 设置为 overflow:hidden 可能引起布局跳动或丢失原滚动点；应记录锁定前后滚动容器和解除锁定后的恢复结果。

## 流断裂证据记录

每个样本写六列：**DOM 与内容、普通流占位、格式化上下文、包含块与偏移、剪裁/滚动/层叠结果、恢复重放**。float 增加环绕宽度，clear 增加浮动边界，BFC 增加隔离责任，overflow 增加 border box 和滚动指标，定位增加参考矩形，fixed 增加滚动与焦点路径。

```text
freeze = DOM + stylesheet + viewport + content + scroll position
baseline = normal-flow order + occupied space + containing block
change = exactly one float | clear | BFC | overflow | position variable
stop = first divergent box, boundary, used value, or scroll ancestor
replay = remove fault + same inputs + fluid boundary restored
```

```css
.flow-shell {
  display: flow-root;
}

.flow-shell__overlay {
  position: absolute;
  inset: 0 auto auto 0;
}

.flow-shell__bar {
  position: fixed;
  inset: auto 1rem 1rem auto;
}
```

第一个样本用于验证浮动包裹与 BFC 保护，第二个样本用于验证 overflow 的剪裁和滚动边界，第三个样本用于验证 absolute、relative 和 fixed 的包含块差异。每次只改一个条件，并保留滚动位置和焦点路径。

**问题 1：** 为什么父容器的背景没有包住 float 子元素？应该先比较哪些证据？

<Answer>
  浮动子元素改变了普通块的排列关系，父容器的正常高度可能没有被它撑开。先比较父高度、浮动边界、clear
  盒和 BFC 或 flow-root 触发前后的结果，再决定用保护上下文，而不是先写固定
  height。
</Answer>

**问题 2：** `overflow:hidden` 看似修复了高度，为什么还要检查滚动和绘制？

<Answer>
  overflow
  可能同时建立新的边界、剪裁超出内容并改变滚动容器；阴影、绝对定位子元素、锚点和键盘焦点都可能受影响。应分别检查
  border box、可见区域、scrollWidth、滚动祖先和恢复位置。
</Answer>

**问题 3：** absolute 元素在祖先加上 relative 后移动，如何定位根因？

<Answer>
  先确认最近定位祖先是否改变，再画出它的 padding edge、absolute
  的包含块和四向偏移。比较加入 relative
  前后的计算值、使用值和滚动行为，才能证明变化来自包含块切换，而不是 left/top
  随意调出来的。
</Answer>

</Exercises>

## 术语表

<Glossary>
  <GlossaryItem term="float">
    让盒子偏向一侧并让后续行盒避让其浮动区域的布局属性。
  </GlossaryItem>
  <GlossaryItem term="clear">
    让盒子避开指定方向浮动影响、从浮动边界之后开始排列的属性。
  </GlossaryItem>
  <GlossaryItem term="BFC">
    把一组盒放入独立块级格式化上下文、隔离部分外部流影响的布局上下文。
  </GlossaryItem>
  <GlossaryItem term="overflow">
    控制内容超出盒子时可见、剪裁或滚动方式的属性。
  </GlossaryItem>
  <GlossaryItem term="包含块">
    为绝对定位或固定定位元素提供尺寸和偏移参考的祖先矩形。
  </GlossaryItem>
  <GlossaryItem term="position:fixed">
    让元素相对视口或固定定位包含块保持固定位置的定位模式。
  </GlossaryItem>
</Glossary>

## 小结

- float 改变环绕，clear 改变后续排列起点；二者都不等同于 absolute 的完全脱流。
- BFC 和 overflow 可以承担包裹、隔离、剪裁或滚动中的某一项职责，不能把它们当作无副作用的万能修复。
- absolute 读取包含块与偏移，relative 通常保留占位并限制局部位移，fixed 还要同时处理滚动、焦点和背景锁定。
- 每个修复都要记录普通流占位、首个偏离点、边界责任、滚动/层叠结果与恢复重放，最终截图不能替代过程证据。
