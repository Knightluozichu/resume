# 第 7 章 CSS世界的层叠规则

本章以张鑫旭著《CSS 世界》人民邮电出版社版的第 7 章公开目录为身份基线，采用独立教学改写。层叠问题不是“谁的 z-index 数字更大”，而是先确定元素所在的层叠上下文，再在同一父上下文内比较层叠水平，最后按照规定的绘制顺序合成可见结果。排查遮挡时，先画树，再读数。

<Objectives>

- 能从 DOM、定位方式和触发条件画出层叠上下文树，并区分上下文与普通盒。
- 能按背景、负层级、块级盒、浮动、内联和定位内容解释绘制顺序，而不是凭截图猜测覆盖关系。
- 能用同级、负值和嵌套上下文实验定位首个偏离点，并在保留焦点顺序的前提下恢复有限语义层级。

</Objectives>

## 先画树，再比较数字

当一个弹层被卡在卡片后面、极大的 z-index 仍然没有覆盖按钮，先不要继续增加数字。固定 DOM、定位方式、视口和内容，画出每个可能创建上下文的祖先；再只改变一个 z-index 或触发条件，记录父级层级、同级关系、绘制阶段和最终命中区域。图中的上下文树、负值绘制阶段和同级比较可以逐步播放；先猜“比较发生在哪个父节点”。

## 三个必须先拆开的误区

<Callout type="trap" title="把 z-index 当作全局排行榜">
  **现象：** 给子元素设置极大的 z-index，仍然盖不过另一个组件。**原因：**
  z-index
  只在相同父层叠上下文的比较范围内直接生效，子上下文会作为整体参与父级排序。**修法：**
  先画上下文树，再调整同级父节点的有限语义层级。
</Callout>

<Callout type="trap" title="把负 z-index 当成无条件的页面底层">
  **现象：** 负值元素消失或被父背景覆盖，继续把数字改得更小。**原因：**
  负层级进入当前上下文的特定绘制阶段，仍受父背景、边界和上下文约束。**修法：**
  记录它所在的上下文、绘制阶段和命中区域，不用负值替代结构化背景层。
</Callout>

<Callout type="trap" title="用 transform 或 opacity 解决层叠却没记录副作用">
  **现象：** 为了让动画工作而加入
  transform，后代定位和覆盖关系却突然变化。**原因：**
  某些属性会创建新的层叠上下文，改变子树的比较边界。**修法：**
  把触发条件、上下文树、绘制顺序和键盘焦点作为同一份证据验收。
</Callout>

## 六阶段机制链

### 1. 固定背景与边界

固定 DOM、样式、视口、字体和内容，先标出背景、border、普通内容、浮动和定位盒的边界。背景不是“透明的底层”，它也属于绘制顺序的一部分；所有后续比较都应从这个稳定画布开始。

### 2. 识别层叠上下文

列出根上下文和由定位、z-index、opacity、transform 等条件创建的子上下文。不要只搜索 z-index；没有 z-index 的祖先也可能因为其他属性成为新的比较边界。

### 3. 列出层叠水平

在同一个父上下文里，为背景、负层级、普通块、浮动、内联和定位内容建立相对的层叠水平。数字只是某些定位内容的输入，不能跨越父上下文树直接比较。

### 4. 按顺序绘制

按照规范阶段把背景、边框、负值、块级盒、浮动、内联内容和定位内容依次绘制。出现遮挡时记录“最后绘制者”和“它属于哪个上下文”，而不是把视觉结果归因给最后写入的 CSS 规则。

### 5. 封装子上下文

子上下文内部先完成排序，再以整体身份参与父上下文。即使子节点拥有极大的 z-index，也不能越过父上下文在同级中的位置；这正是组件边界比数字更重要的地方。

### 6. 恢复有限层级

删除临时的极大数字和无必要的上下文触发条件，重放同一 DOM；再用窄视口、长内容、焦点和动画状态复查。恢复结果必须同时保留可读的层级命名、正确的命中区域和稳定的键盘顺序。

## 出版社目录逐项映射

### 第7章 CSS世界的层叠规则

层叠规则把“谁盖住谁”拆成上下文树、层叠水平和绘制顺序三个问题。只有比较对象处在同一父上下文中，z-index 的数字才具有直接的相对意义。

### 7.1 z-index只是CSS层叠规则中的一叶小舟

<Term def="在适用的定位或层叠上下文中提供层叠水平输入的属性">z-index</Term>
是层叠系统的一个输入，不是全局覆盖开关。本节“z-index 只是 CSS
层叠规则中的一叶小舟”的判断，强调它不能替代上下文树，也不能让后代跳出父节点的同级顺序。

### 7.2 理解CSS世界的层叠上下文和层叠水平

<Term def="把一组盒封装成独立层叠排序范围的上下文单元">层叠上下文</Term>
定义比较边界；同一父上下文中的参与者才会直接比较层叠水平。把这两个概念分开，才能解释为什么两个看似相邻的数字没有直接关系。

<Term def="元素在其父层叠上下文内参与排序时所处的相对级别">层叠水平</Term>
描述同级排序位置。它不是像素坐标，也不是跨上下文的绝对高度；父上下文的层叠水平先决定子树整体的相对位置。

### 7.2.1 什么是层叠上下文

层叠上下文是一个自洽的绘制分组：内部元素先按自己的规则合成，完成后整体进入父上下文。根元素通常提供根上下文，定位与特定绘制属性还会创建嵌套上下文。

### 7.2.2 什么是层叠水平

层叠水平可以理解为同一上下文中的排序标签。背景、负层级、普通内容和定位内容处在不同阶段；即使两个元素都没有显式 z-index，也可能因为所属阶段不同而产生覆盖差异。

### 7.3 理解元素的层叠顺序

<Term def="同一层叠上下文中从背景到前景逐阶段合成内容的绘制次序">层叠顺序</Term>
把背景、边框、负层级、块级盒、浮动、内联和定位内容串成一条绘制路径。排查遮挡时应记录顺序中的最后一个覆盖者，而不是只看
DOM 的先后。

### 7.4 务必牢记的层叠准则

第一条准则是先找上下文，第二条是只比较同级，第三条是把子上下文当整体，第四条是限制语义层级数量。若解决一个遮挡要把 z-index 加到几万，通常说明上下文边界或组件责任没有被画清楚。

### 7.5 深入了解层叠上下文

深入排查时要把创建条件、内部排序、父级位置和绘制结果放在同一张树上。opacity、transform、定位与 z-index 的组合可能改变层叠边界，修复后还要检查固定定位、动画和焦点是否仍然可用。

### 7.5.1 层叠上下文的特性

层叠上下文具有原子性：内部先排序，外部只看到这个分组在父上下文中的一个整体位置。它还形成隔离边界，因此子节点的数字不能直接拿去和外部兄弟竞争。

### 7.5.2 层叠上下文的创建

定位元素配合 z-index、透明度、变换和其他绘制条件都可能创建新的上下文。本节“层叠上下文的创建”要逐一对照触发条件；实验中一次只加入一个条件，并记录上下文树、计算值、使用值、合成边界和恢复前后的命中区域。

### 7.5.3 层叠上下文与层叠顺序

上下文决定比较范围，层叠顺序决定范围内各阶段的先后。本节“层叠上下文与层叠顺序”要求同时保留这两张图：即使同一个元素同时拥有定位和 z-index，也要先判断它属于哪个上下文，再把它放入适当的绘制阶段。

### 7.6 z-index负值深入理解

<Term def="位于当前层叠上下文较低绘制阶段、但仍受父背景和上下文约束的层级状态">
  负层级
</Term>
会进入当前上下文的负值绘制阶段。它不是穿透父背景的地下室，也不保证元素仍然可见或可点击；背景、剪裁和命中测试都要单独验收。

### 7.7 z-index“不犯二”准则

<Term def="记录并限制组件层级语义的有限命名与比较约束">绘制阶段</Term>
是比“更大数字”更稳定的调试单位。把组件分成背景、内容、浮层和模态等少数语义层，先在同级解决问题，再验证嵌套上下文不会产生越级期待。

## 层叠证据记录

每个样本写六列：**DOM 与内容、上下文树、层叠水平、绘制阶段、首个偏离点、恢复与焦点结果**。负值增加父背景和命中区域，定位增加包含块和偏移，动画增加上下文创建时机，组件浮层增加焦点陷阱和关闭路径。

```text
freeze = DOM + stylesheet + viewport + content + focus target
tree = root context + nested contexts + same-parent siblings
change = exactly one z-index | trigger | paint-order variable
stop = first divergent context, stacking level, paint phase, or hit target
replay = remove fault + same inputs + semantic layer contract restored
```

```css
.shell {
  position: relative;
  z-index: 0;
}

.content {
  position: relative;
  z-index: 1;
}

.dialog {
  position: fixed;
  z-index: 30;
}
```

第一个样本用于验证父上下文约束，第二个样本用于验证负值进入绘制阶段，第三个样本用于验证同级 z-index 的直接比较。动画和弹层实验还要检查焦点路径与关闭后的层级恢复。

## 练习

<Exercises>

**问题 1：** 子元素的 z-index 已经是 9999，为什么仍然可能盖不过外部兄弟？

<Answer>
  因为子元素先在父层叠上下文内排序，整个父上下文再以一个整体参与外部兄弟的比较。应先比较两个父上下文的同级层叠水平，再决定调整父级语义层，而不是继续增大子数字。
</Answer>

**问题 2：** 负 z-index 元素消失时，如何区分绘制顺序问题和命中区域问题？

<Answer>
  先画它所属的上下文和负值绘制阶段，再分别检查父背景、剪裁矩形、opacity 和
  pointer-events。可见性、命中测试和文档占位是三类证据，不能用其中一类替代另外两类。
</Answer>

**问题 3：** 为何给动画元素加 transform 后，后代浮层的层级关系会改变？

<Answer>
  某些绘制属性会创建新的层叠上下文，使后代只能在新上下文内部排序。应记录加入
  transform
  前后的上下文树、同级父节点和焦点顺序，再决定是否把动画边界移到正确的组件层。
</Answer>

</Exercises>

## 小结

- z-index 是排序输入，不是全局排行榜；必须先定位层叠上下文和同级父节点。
- 层叠上下文是原子分组，内部先排序，子节点不能越过父上下文的同级层级。
- 层叠水平与层叠顺序共同决定覆盖关系，负层级仍受背景、剪裁和命中测试约束。
- 修复层叠问题要限制语义层级数量，并同时验收动画、焦点、命中区域和关闭后的恢复结果。
