# 第 8 章 强大的文本处理能力

本章以张鑫旭著《CSS 世界》人民邮电出版社版的第 8 章公开目录为身份基线，采用独立教学改写。文本不是一组孤立的视觉属性：字号先决定度量，字体族再逐字符匹配，字重和字形决定可用轮廓，间距和断行最后把内容放进可读的几何边界。排查排版差异时，先找首个不同的计算值或字形来源。

<Objectives>

- 能从字号单位、字体族、字重字形和字体资源加载状态解释文本的计算值、使用值与实际宽度。
- 能用单变量实验区分 letter-spacing、word-spacing、white-space、word-break 和 overflow-wrap 对断行的不同职责。
- 能在中英文混排、长 URL、缺字形、字体回退、放大字号和首字首行场景下记录首个偏离点并恢复可读布局。

</Objectives>

## 先追踪一个字符的来源

当同一段文字在不同机器上宽度不同、中文突然换字体、长 URL 撑破容器，先不要直接改 `width` 或缩小字号。固定 DOM、视口、内容和样式，先写出字号单位和根字号；再沿字体族、字重、字形、网络字体和回退链追踪每个字符。最后才加入间距、空白和断行规则。动手前先猜：首个变化来自单位、字形，还是文本边界。

## 三个必须先拆开的误区

<Callout type="trap" title="把 em、rem 和 ex 当成固定像素换算">
  **现象：** 子元素继承后尺寸和预期不同，继续把 em 当成根字号比例。**原因：** em
  依赖当前元素字号，rem 依赖根字号，ex 还依赖当前字体的 x-height。**修法：**
  同时记录声明值、继承链、计算值、实际字体和使用值。
</Callout>

<Callout type="trap" title="把 font-weight 数字当成一定存在的字重文件">
  **现象：** 设置 600 后截图没有变粗，或不同平台粗细不同。**原因：**
  字体可能没有对应字重，浏览器会选择相邻字重或合成字形。**修法：**
  核对字体资源、可用字重和合成状态，不用截图推断资源是否加载。
</Callout>

<Callout type="trap" title="用 overflow:hidden 解决所有文本溢出">
  **现象：** 长 URL 不再撑破容器，却被截断、无法选择或焦点不可见。**原因：**
  溢出处理改变了可见边界，不等于解决了断词和可读性。**修法：** 先判断
  white-space、word-break、overflow-wrap 和滚动需求，再决定是否剪裁。
</Callout>

## 六阶段机制链

### 1. 确定字号与单位

先读取<Term def="决定文本 em 方框、行内度量和相对单位计算入口的属性">font-size</Term>的声明值、继承来源和计算值。em 依赖当前字号，rem 读取根字号，ex 关联当前字体的 x-height；同一个 `1em` 在不同节点不一定是同一长度。

### 2. 选择字体回退链

对每个字符匹配<Term def="按优先级提供字体族候选列表并允许逐字符回退的属性">font-family</Term>。字体族只是候选顺序，最终轮廓取决于字符是否存在、资源是否加载以及平台字体；中英文混排必须分别记录实际字形来源。

### 3. 匹配字重与字形

字重、斜体和小型大写等请求会进入字体匹配算法。浏览器可能找到真实文件，也可能选择相邻资源或合成字形；因此要把请求值、可用资源、实际使用字重和文本宽度放在同一张证据表里。

### 4. 装载 @font-face

`@font-face` 声明字体名称、资源、格式、unicode-range 和字重范围。实验需区分资源尚未加载、资源加载失败、字形缺失和 CSS 规则未命中的状态；网络字体完成后重新测量，不能把首次回退截图当作最终结果。

### 5. 控制间距与断行

letter-spacing、word-spacing 和 text-indent 改变文字几何；white-space、word-break 和 overflow-wrap 决定内容能否在边界处换行。先固定字体和字号，再一次只改一个间距或断行规则，记录首个换行位置。

### 6. 应用首字与首行

`:first-letter` 与 `:first-line` 伪元素把样式作用到文本片段，而不是普通 DOM 子节点。恢复实验要检查伪元素是否命中、首字是否改变行框、首行规则是否受容器宽度和语言影响，并同时保留可访问文本。

## 出版社目录逐项映射

### 第8章 强大的文本处理能力

本章把文本结果拆成字号、字体、字形、资源、间距和断行六层。每层都记录输入和首个偏离点，最终宽度或换行只是证据链的末端，不是唯一答案。

### 8.1 line-height的另外一个朋友font-size

本节“line-height 的另外一个朋友 font-size”说明字号如何决定 em 方框和相对长度的入口，也会影响 line-height、vertical-align 和行框。先固定字体，再改变字号，比较字符宽度、行框高度与相对单位的使用值。

### 8.1.1 font-size和vertical-align的隐秘故事

字号改变后，行内盒和字体度量会改变，vertical-align 的相对位移也可能随之变化。把字号、line-height、基线和替换元素固定成四列，才能分辨视觉位置变化来自字号还是对齐属性。

### 8.1.2 理解font-size与ex、em和rem的关系

em 以当前元素字号为参考，rem 以根元素字号为参考，ex 依赖当前字体的 x-height。父节点改变字号或字体后，三者的实际长度会不同；测试必须保存参考节点和实际字形。

### 8.1.3 理解font-size的关键字属性值

xx-small 到 xx-large、smaller 和 larger 等关键字由用户代理和继承关系参与计算。它们适合表达相对层级，不适合当作跨平台固定像素；要记录计算后的实际字号和可读性边界。

### 8.1.4 font-size:0与文本的隐藏

本节“font-size:0 与文本的隐藏”说明它可以消除部分内联空白的几何影响，但也可能隐藏文字、改变可访问体验和伪元素度量。恢复实验要检查文本是否仍可读、焦点是否可见、后代是否显式恢复字号。

### 8.2 字体属性家族的大家长font-family

font-family 提供按顺序尝试的字体族列表，不保证每个字符都来自第一候选。测试中应分别选择拉丁字符、中文、数字和符号，记录每类字符的实际匹配与宽度。

### 8.2.1 了解衬线字体和无衬线字体

衬线与无衬线是字体形态分类，不是固定的跨平台字体文件。它们可能具有不同 x-height、字宽和可读性；比较时要固定字号、line-height、字体加载状态和文本内容。

### 8.2.2 等宽字体的实践价值

等宽字体让代码、表格和字符网格更易对齐，但不同字体仍可能在字形、标点宽度和回退字符上不同。长行和中文混排实验要验证等宽契约是否被回退字体破坏。

### 8.2.3 中文字体和英文名称

同一字体可能拥有中文名称、英文名称和平台别名；名称写法不同不代表实际字体不同，也不代表一定能加载。用字体检测、网络面板和实际字形对照确认命中，而不是只看 CSS 文本。

### 8.2.4 一些补充说明

字体族选择还受用户代理、操作系统、语言和可用资源影响。声明顺序应从具体到通用，最后提供可接受的通用族；验收需要允许合理回退，不把某一台机器的字体视为硬依赖。

### 8.3 字体家族其他成员

font-weight、font-style 和 font-variant 共同描述字体家族的其他维度。它们可能命中真实字体文件，也可能由浏览器合成或退回普通样式；必须把请求值和实际字形分开记录。

### 8.3.1 貌似粗犷、实则精细无比的font-weight

<Term def="请求字体粗细级别、可能命中真实文件或合成字形的属性">
  font-weight
</Term>
的数字是请求的粗细级别，不保证字体目录里存在同名文件。浏览器会在可用字重中匹配，必要时合成；用字体资源和实际宽度验证，而不要用“数字越大越宽”概括。

### 8.3.2 具有近似姐妹花属性值的font-style

normal、italic 和 oblique 的区别涉及真实斜体字形与倾斜变换。字体缺少 italic 时可能合成斜体；测试要保存字形来源、字宽、行框和无障碍阅读结果。

### 8.3.3 不适合国情的font-variant

font-variant 的小型大写、数字和东亚文字相关特性依赖字体能力和语言。中文场景不能照搬拉丁排版预期；要先确认字体支持，再比较字形、宽度和回退结果。

### 8.4 font属性

<Term def="按语法组合字号、字体族、字重、字形和行高的缩写属性">font</Term>
是多个字体属性的缩写入口，组合语法和默认值会重置未写出的成员。使用它时先列出完整展开结果，再检查继承、line-height
和字体族是否被意外覆盖。

### 8.4.1 作为缩写的font属性

缩写 font 通常要求字号与字体族，其他成员按语法顺序出现。把旧规则展开成 font 后，必须逐项比较 font-size、font-family、font-weight、font-style 和 line-height，防止无意重置。

### 8.4.2 使用关键字值的font属性

font 的关键字值可能映射到用户代理的系统字体，不同平台的实际字体、字号和行高可能不同。验收应记录关键字、计算值、实际字体和文本宽度，不能把关键字当作固定设计 token。

### 8.4.3 font关键字属性值的应用价值

关键字适合表达系统界面、菜单和标题等语义层级，能跟随平台偏好；但内容区需要稳定度量时，应明确字体回退和最小可读字号。迁移时要把语义目标和像素目标分开。

### 8.5 真正了解@font face规则

@font-face 不是“上传一个字体就结束”，而是一组资源、范围和匹配条件。资源状态、格式、unicode-range、字重和字体显示策略都会决定浏览器是否采用它，必须在加载前后分别测量。

### 8.5.1 @font face的本质是变量

<Term def="声明可加载字体资源、匹配轴和字符覆盖范围的规则">@font-face</Term>
为字体资源建立 CSS 可用名称和匹配轴，字重、风格和 stretch
可以成为选择变量。改变其中一项后要确认命中的文件、字符覆盖范围和布局宽度，而不是只观察网络请求。

### 8.5.2 @font face与字体图标技术

字体图标依赖特定码点、字体加载和 fallback 行为；缺少字体时可能显示空方框或错误字符。应同时提供可访问文本、加载失败替代方案和不依赖单一字体的焦点路径。

### 8.6 文本的控制

文本控制属性改变缩进、字符间距、单词间距、空白、断词、对齐、装饰和大小写。每项只改变一个几何或断行变量，保持字体和内容不变，才能解释换行是否真正由该属性造成。

### 8.6.1 text-indent与内联元素缩进

text-indent 主要作用于块容器的首行，而不是任意内联子元素的独立位移。测试要比较块的首行、后续行、伪元素和多语言方向，避免用 padding 代替文本缩进语义。

### 8.6.2 letter-spacing与字符间距

<Term def="在字符之间调整额外空间、影响文字宽度和断行的属性">
  letter-spacing
</Term>
在字符之间增加或减少空间，会影响整行宽度、对齐和断行。极端负值可能让字形重叠，极端正值可能破坏按钮和标题；应在放大字号和窄视口下检查可读性。

### 8.6.3 word-spacing与单词间距

word-spacing 主要调整单词或空格分隔的间距，对中文连续字符的效果不同于英文。混排实验要分别使用英文单词、中文短语和数字，记录它与 letter-spacing 的叠加结果。

### 8.6.4 了解word-break和word-wrap的区别

word-break 决定允许在哪些字符边界断开，overflow-wrap 或 word-wrap 主要处理过长连续片段。长 URL、英文长词和中文句子要分开测试，才能知道是断词策略还是容器溢出。

### 8.6.5 white-space与换行和空格的控制

white-space 同时影响空格折叠和换行。`nowrap` 可以保持单行但可能制造横向溢出，`pre-wrap` 保留空格又允许换行；需要同时检查复制文本、滚动和窄视口行为。

### 8.6.6 text-align与元素对齐

text-align 对齐的是行内内容和行盒中的文本，不是让任意块级元素自动居中。比较 text-align、margin:auto、flex 对齐和内联格式化上下文，记录真正被对齐的对象。

### 8.6.7 如何解决text-decoration下划线和文本重叠的问题

下划线属于文本装饰绘制层，字体、line-height、字重和装饰偏移会影响是否与字形重叠。优先使用可调的 text-decoration-thickness、offset 或合适的 line-height，避免用伪元素覆盖可选择文本。

### 8.6.8 一本万利的text-transform字符大小写

text-transform 改变显示大小写，不一定改变 DOM 文本或复制结果；语言规则还会影响大小写转换。实验要比较视觉文本、可访问名称、复制内容和不同语言的特殊字符。

### 8.7 了解:first-letter/:first-line伪元素

`:first-letter` 与 `:first-line` 只作用于文本流中的特定片段，命中范围受盒生成、语言、换行和元素类型影响。它们不是普通子节点，不能用 DOM 查询或固定高度替代其排版规则。

### 8.7.1 深入:first-letter伪元素及其实例

首字放大、浮动和颜色效果会改变首行高度与后续文字环绕。长标题、中文首字、标点开头和窄容器都要复测，确保首字样式不会遮挡焦点或破坏阅读顺序。

### 8.7.2 故事相对较少的:first-line伪元素

首行伪元素的范围随容器宽度和字体变化，换行后命中的文字可能改变。实验应切换宽度、字号和方向，比较首行范围、计算样式和恢复后的普通文本，避免把一次截图当成固定选择器结果。

## 文本处理证据记录

每个样本写六列：**DOM 与内容、字号与单位、字体和字形来源、计算值与使用值、首个断行/宽度偏离点、恢复结果**。字体实验增加资源加载和 unicode-range，断行实验增加语言和连续字符，伪元素实验增加首行范围和可访问文本。

```text
freeze = DOM + stylesheet + viewport + content + root font size
match = font-size + family + weight/style + loaded glyph source
change = exactly one unit | font | spacing | whitespace | break variable
stop = first divergent glyph width, computed value, or line break
replay = remove fault + same inputs + readable boundary restored
```

```css
.copy {
  font-size: 1rem;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
  overflow-wrap: anywhere;
}

.copy::first-letter {
  font-weight: 700;
}
```

第一个样本验证相对单位和字体来源，第二个样本验证缺字形回退，第三个样本验证长 URL 与中文混排的断行。所有样本都要复核复制、焦点、缩放和字体加载失败后的可读性。

## 练习

<Exercises>

**问题 1：** 为什么同样写 `1em`，嵌套元素得到的实际长度可能不同？

<Answer>
  em 以当前元素字号为参考，当前字号又可能由父元素继承或被本地规则改变；rem
  才以根字号为参考，ex 还依赖当前字体的
  x-height。应沿继承链记录计算值和实际字体。
</Answer>

**问题 2：** 缺少某个中文字符的 Web Font 时，为什么不能只看字体文件是否加载成功？

<Answer>
  字体资源加载成功不等于包含每个字符的字形；浏览器仍会逐字符回退到其他字体。应检查字符覆盖范围、实际字形、宽度和换行，并提供合理的回退族。
</Answer>

**问题 3：** 长 URL 溢出时，word-break、overflow-wrap 和 overflow:hidden 应如何选择？

<Answer>
  先判断内容是否允许在任意点断开，再用 word-break 或 overflow-wrap
  保持可读换行；overflow:hidden
  只改变可见边界，可能截断文本和焦点。选择前要记录复制、滚动和无障碍结果。
</Answer>

</Exercises>

  </GlossaryItem>
  <GlossaryItem term="@font-face">
    声明可加载字体资源、匹配轴和字符覆盖范围的规则。
  </GlossaryItem>
  <GlossaryItem term="letter-spacing">
    在字符之间调整额外空间、影响文字宽度和断行的属性。
  </GlossaryItem>
</Glossary>

## 小结

- font-size 先提供度量入口，em、rem、ex 的参考对象不同；font-family 再按字符选择可用字形。
- 字重、字形和 @font-face 可能命中真实资源，也可能回退或合成，必须记录实际来源而非只看声明值。
- 间距、空白、断词、对齐、装饰和大小写各自改变不同的文本阶段，overflow:hidden 不能代替可读断行。
- 首字首行伪元素依赖文本流和换行范围；验收要覆盖字体失败、混排、缩放、焦点、复制和窄视口。
