# 第 9 章 元素的装饰与美化

本章以张鑫旭著《CSS 世界》人民邮电出版社版的第 9 章公开目录为身份基线，采用独立教学改写。装饰不是给元素贴一张背景图：先有可继承的前景色，再有 currentColor 的联动，然后按照背景绘制层、图像尺寸、位置、重复和附着规则合成结果。排查颜色或背景差异时，先找第一个不同的计算值、包含块或资源状态。

<Objectives>

- 能从继承链、currentColor 和背景绘制顺序解释一个元素的前景色、边框色与背景层。
- 能用剩余空间公式区分 background-position 百分比、repeat 模式和 fixed 附着对图像几何的影响。
- 能在隐藏元素、资源失败、透明色、系统主题、旧语法和多背景回退场景下记录首个偏离点并恢复可读装饰。

</Objectives>

## 先追踪一块颜色如何到达屏幕

遇到“边框颜色没有跟着文字变”“背景图看起来偏移”“滚动后 fixed 背景失效”时，不要先叠加更多渐变或改成固定像素。固定 DOM、盒尺寸、视口、内容和资源，先记录声明值、继承后的计算值、背景层顺序和图像的包含块，再观察绘制结果。动手前先猜：第一个变化来自继承、绘制层，还是资源与浏览器兼容？

## 三个必须先拆开的误区

<Callout type="trap" title="把 currentColor 当成不会变化的常量">
  **现象：** 文字换色了，边框或图标却仍是旧颜色。**原因：** currentColor
  读取当前元素的 color
  计算值；继承被切断、声明覆盖或组件内部建立新上下文时，读取点可能不同。**修法：**
  沿父子链同时记录 color、currentColor 和最终绘制色。
</Callout>

<Callout type="trap" title="把 background-position: 50% 当成图像在容器一半处">
  **现象：** 图像没有落在预想的几何中心，换尺寸后偏移更明显。**原因：**
  百分比作用于容器尺寸减图像尺寸的剩余空间，图像大小变化会改变可移动距离。**修法：**
  保存容器、图像、剩余空间和百分比四个值，再判断位置。
</Callout>

<Callout type="trap" title="用透明或隐藏直接推断背景资源没有加载">
  **现象：** 看不到背景图，就断言网络请求没有发生或兼容处理成功。**原因：**
  display:none、visibility、透明度、图层遮挡和资源失败可能产生相似外观。**修法：**
  分开观察网络、解码、绘制、回退色与可读边界，不用截图代替资源证据。
</Callout>

## 六阶段机制链

### 1. 解析前景色与继承

先读取<Term def="可继承并为文本、边框及其他绘制提供前景色的属性">color</Term>的声明值和继承来源，再判断当前元素的计算值。颜色关键字、透明值、rgba/hsla 和系统颜色都要落到实际使用值；对比时还要保留浏览器、主题和高对比模式。

### 2. 传播 currentColor

<Term def="读取当前元素 color 计算值、可复用于边框和图形的颜色变量">
  currentColor
</Term>
不是一个写死的色票，而是读取当前元素 color 的动态引用。边框、SVG
或组件图标使用它时，必须确认引用发生在哪个元素以及 color 是否在中间被覆盖。

### 3. 叠加背景绘制层

<Term def="在元素背景绘制区域中分层安排颜色和图像的属性集合">background</Term>
可以同时承载颜色、图像、位置、重复和附着等成员。背景色先提供底色，多个图像层按声明顺序参与绘制，内容文字仍应位于可读的上层；先写一条纯色回退，再添加高级图像是更稳的实验顺序。

### 4. 计算图像位置与剩余空间

位置百分比不是直接乘容器宽度。水平位置的移动距离是容器宽度减图像宽度，垂直方向同理；固定尺寸、固有尺寸、背景裁剪区域和盒模型都会改变这个剩余空间。先记录图像最终尺寸和背景定位区域，再解释偏移。

### 5. 应用重复与附着

<Term def="控制背景图在定位区域中如何平铺或停止平铺的属性">
  background-repeat
</Term>
决定图像是否沿一个或两个方向重复；
<Term def="决定背景图相对元素、滚动内容或视口附着方式的属性">
  background-attachment
</Term>
则改变滚动时的采样参考。两者不能互相替代，尤其不能用 repeat 的截图推断 fixed
的滚动行为。

### 6. 验证资源、隐藏和兼容边界

最后区分资源请求、解码、绘制和回退四个状态。display:none、透明背景、旧浏览器不支持的颜色语法和移动端对 fixed 的限制，都可能让外观相似但原因不同。恢复时删除故障声明，重放同一 DOM，并确认文字、焦点和纯色回退仍然可见。

## 出版社目录逐项映射

### 第9章 元素的装饰与美化

本章把元素装饰拆成颜色继承、背景绘制、图像定位、重复附着和资源回退五层。最终截图只是证据链末端，必须同时解释当前元素的计算值、背景定位区域、图像尺寸和绘制顺序。

### 9.1 CSS世界的color很单调

本节讨论颜色值的表达范围和继承行为。颜色关键字数量有限，透明、currentColor、rgba/hsla 与系统颜色还受到历史浏览器、主题和字体渲染环境影响；比较时要把声明语法与实际绘制色分开。

### 9.1.1 少得可怜的颜色关键字

具名颜色适合快速表达常见色，但名称集合有限，近似色会依赖数值或设计 token。实验时先写一个具名颜色，再用明确的 rgb 或现代颜色值替换，比较计算值和对比度，不要用名称数量代替色彩系统。

### 9.1.2 不支持的transparent关键字

这个目录标题保留了早期浏览器兼容语境；现代浏览器普遍识别 transparent，但旧环境、特定属性或降级链仍可能需要明确回退。测试要先绘制纯色，再切换透明，观察下方背景、边框和文字是否仍能辨认。

### 9.1.3 不支持的currentColor变量

这个标题同样记录了历史兼容问题；现代 CSS 已广泛支持 currentColor。实际排查应确认引用元素的 color 计算值、继承是否被覆盖，以及组件或 SVG 是否把颜色读取点放在了另一个元素上。

### 9.1.4 不支持的rgba颜色和hsla颜色

rgba 与 hsla 让透明度和色相表达更直接，但历史浏览器或旧属性可能需要纯色回退。先让回退色独立可读，再叠加半透明层；资源失败、主题变化和高对比模式下不能只留下透明背景。

### 9.1.5 支持却鸡肋的系统颜色

系统颜色可以跟随平台控件或主题，但名称、语义和可用范围受用户代理影响。它适合表达系统语义，不适合替代整个品牌色板；验收要在亮色、暗色和高对比模式下复核前景与背景对比。

### 9.2 CSS世界的background很单调

background 是多个背景成员的入口，单调感来自它最终仍受固定盒、图像尺寸、位置和绘制顺序约束。先拆 shorthand，再逐项检查 background-color、image、position、repeat、attachment 和 clip，避免一条缩写同时重置未写出的成员。

### 9.2.1 隐藏元素的background-image到底加不加载

不要把“不可见”与“不请求”混为一谈。display:none、visibility:hidden、透明度、预加载、缓存和网络失败可能产生不同请求与绘制结果；应该用网络面板、解码状态和回退色分别验证，而不是只观察元素截图。

### 9.2.2 与众不同的background-position百分比计算方式

百分比位置作用于“背景定位区域减图像尺寸”的剩余空间，因此 50% 只有在剩余空间上取中点。容器或图像尺寸变化会同时改变起点和移动距离；记录两者的 used value，才能解释为什么同一百分比在不同卡片上看起来不同。

### 9.2.3 background-repeat与渲染性能

repeat、repeat-x、repeat-y、no-repeat 和 round/space 等策略改变需要采样的区域与边缘处理。图像很大或重复频繁时还会增加解码、栅格化和绘制成本；先裁剪资源、限定层数，再在目标设备观察滚动和重绘，而不是用“能显示”判断性能。

### 9.2.4 外强中干的background-attachment:fixed

fixed 背景尝试把背景采样与视口或滚动参考绑定，但滚动容器、移动端合成层、性能限制和背景定位区域会改变实际行为。比较时必须滚动真实容器，并记录附着参考、重绘和降级结果；固定视觉不能取代可读内容。

### 9.2.5 background-color背景色永远是最低的

背景色位于背景图像之下，是最可靠的底层回退；它不会因为图像声明在后面就自动盖住图像。把纯色放在最底层可以保证资源失败时仍有边界，但文字和对比度仍要按最终图层检查。

### 9.2.6 利用多背景的属性hack小技巧

多背景可以把旧环境可识别的纯色或图像放在回退层，再把现代渐变和装饰层放在上面。先写回退声明，再写增强声明，并检查不支持后续语法的浏览器是否保留前一条规则；每一层都要有明确的职责。

### 9.2.7 渐变背景和rgba背景色的兼容处理

渐变与半透明色可以形成丰富层次，但兼容处理应从不透明纯色开始，再按能力逐层增强。测试要覆盖资源失败、主题切换、打印和高对比模式，确保增强层消失时仍留下可辨认的底色和文字。

## 装饰证据记录

每个样本写六列：**DOM 与内容、继承链、背景定位区域、图像尺寸与使用值、首个绘制偏离点、恢复结果**。颜色实验增加主题和对比度，背景实验增加图像加载与层叠顺序，fixed 实验增加真实滚动容器和移动端行为。

```text
freeze = DOM + box size + viewport + image resource + color scheme
trace = inherited color + currentColor + background layers + containing area
change = exactly one color | position | repeat | attachment | fallback variable
stop = first divergent used value, image request, paint layer, or scroll reference
replay = remove fault + same inputs + readable fallback and focus restored
```

```css
.notice {
  color: var(--accent);
  border: 1px solid currentColor;
  background-color: var(--bg);
  background-image: linear-gradient(
    90deg,
    currentColor 0 0.25rem,
    transparent 0.25rem
  );
  background-repeat: no-repeat;
  background-position: 1rem 50%;
}
```

## 练习

<Exercises>

**问题 1：** 为什么把 `color` 改成新值后，使用 currentColor 的边框有时仍然没有变化？

<Answer>
  currentColor 读取的是当前元素的 color
  计算值；继承链中途被覆盖、边框实际属于另一个元素，或
  SVG/组件把读取点放在别处，都可能导致结果不同。应沿元素链记录声明值、计算值和最终绘制色。
</Answer>

**问题 2：** 为什么 `background-position: 50% 50%` 不等于把图像左上角放在容器中心？

<Answer>
  百分比作用于容器尺寸减背景图尺寸的剩余空间。图像宽度与容器宽度相等时剩余空间为零，图像更小时才有可移动距离；应同时记录定位区域、图像
  used size 和剩余空间。
</Answer>

**问题 3：** 背景图不可见时，怎样区分资源未加载、元素隐藏和透明回退？

<Answer>
  分别检查网络请求与解码状态、display/visibility/透明度、绘制层和纯色回退。恢复实验删除一个故障声明后重放同一
  DOM，并确认文字、焦点、边界和主题对比度仍然可用。
</Answer>

</Exercises>

## 小结

- color 先经过继承形成当前元素的前景色，currentColor 再把这个结果复用于边框和图形。
- background-color 是可靠底层，图像、渐变和多背景按层绘制；先写纯色回退，再逐层增强。
- background-position 百分比作用于剩余空间；repeat 与 attachment 分别控制平铺和滚动参考，不能互相替代。
- 隐藏、透明、资源失败和旧语法可能产生相似外观，验收必须保留网络、绘制、文字、焦点和主题对比度证据。
