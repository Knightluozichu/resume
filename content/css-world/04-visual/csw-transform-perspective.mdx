## 直觉引入

transform 像是给元素贴一张「贴纸」——你移动、缩放、旋转这张贴纸，但元素在文档流中的原始位置不变。这就是它性能高的原因：不触发重排，浏览器直接在合成层操作位图。透视（perspective）则是给 3D 空间加一个「视点」——离视点近的看起来大，远的看起来小，和现实世界的透视一样。

## 二维变换函数

<Term def="transform 对元素施加变换而不影响文档流，包括 translate（平移）、scale（缩放）、rotate（旋转）、skew（倾斜），以 transform-origin 为原点。">transform</Term> 的变换不影响文档流——其他元素不会因为某个元素 transform 了而重新布局。

```css
/* translate：平移（最常用于动画） */
.move { transform: translate(50px, 20px); }  /* 右移 50px，下移 20px */
.moveX { transform: translateX(100px); }

/* scale：缩放 */
.zoom { transform: scale(1.5); }      /* 整体放大 1.5 倍 */
.zoomX { transform: scaleX(2); }      /* 水平拉伸 2 倍 */

/* rotate：旋转 */
.spin { transform: rotate(45deg); }   /* 顺时针 45 度 */

/* 变换原点（默认中心 50% 50%） */
.from-corner { transform-origin: 0 0; }  /* 从左上角旋转 */
```

## 合成顺序

<Term def="transform 多个变换函数从右往左执行，顺序不可交换——先旋转再平移与先平移再旋转结果不同。">合成顺序</Term>是 transform 最容易踩的坑。`translate(100px) rotate(45deg)` 先执行 rotate（绕原点旋转 45 度），再执行 translate（沿旋转后的坐标系平移 100px）。

```css
/* 顺序不同，结果不同 */
.a { transform: translate(100px) rotate(45deg); }  /* 先转再移 */
.b { transform: rotate(45deg) translate(100px); }  /* 先移再转（沿旋转后方向移） */
/* a 和 b 最终位置不同！ */
```

## perspective 三维透视

<Term def="perspective 定义 3D 空间的视点到屏幕的距离，值越小透视越强（近大远小越明显）。">perspective</Term> 需设在父元素上，子元素的 3D 变换才会产生透视效果。

```css
.scene { perspective: 800px; }  /* 视点距屏幕 800px */
.card {
  transform: rotateY(45deg);    /* 绕 Y 轴旋转，有近大远小效果 */
  transform-style: preserve-3d; /* 子元素保留 3D 空间 */
}

/* translateZ：Z 轴平移（正值靠近视点变大） */
.pop { transform: translateZ(100px); }  /* 向观察者方向移 100px，变大 */
```

## 常见误区

<Callout type="trap">
**误区：修改 `top` 和 `transform: translateY` 效果一样。** 视觉上可能一样，但性能天差地别。top 是定位属性，修改它触发重排（reflow）——浏览器重新计算所有受影响元素的几何位置，再重绘，主线程负担重。transform 是合成属性，浏览器把元素提升到独立合成层，直接在 GPU 上移动已绘制好的位图，不触发重排也不重绘。因此动画永远优先用 transform 和 opacity（两者都只合成），避免动画 width/margin/top/left 等触发重排的属性。配合 `will-change: transform` 可提前提升合成层。
</Callout>

<Exercises>
**问题 1**：transform 的合成顺序是怎样的？`translate(100px) rotate(45deg)` 和 `rotate(45deg) translate(100px)` 结果为什么不同？

<Answer>
transform 多个函数从右往左执行（类似函数嵌套 f(g(x)) 先算 g）。`translate(100px) rotate(45deg)`：先 rotate（元素绕原点旋转 45 度），再 translate（此时坐标系也已旋转，平移沿旋转后的方向）。`rotate(45deg) translate(100px)`：先 translate（沿原始坐标系水平移 100px），再 rotate（绕原点旋转 45 度）。两者旋转和平移的参照系不同，最终位置不同。矩阵乘法不可交换（A×B ≠ B×A），所以 transform 顺序不可交换。
</Answer>

**问题 2**：perspective 的值大小如何影响 3D 效果？为什么需要设在父元素上？

<Answer>
perspective 值代表视点到屏幕的距离（z=0 平面）。值越小，视点越近，透视效果越强（近大远小更夸张，类似广角镜头）；值越大，视点越远，透视越弱（接近正交投影，类似长焦镜头）。设在父元素上是因为 perspective 定义的是「观察这个 3D 空间的视点」，子元素在这个空间内做 3D 变换时才需要统一的视点参照。如果设在元素自身（用 transform: perspective(800px) rotateY(45deg)），则只对该元素自身生效，不会影响兄弟元素的相对 3D 关系。
</Answer>
</Exercises>
