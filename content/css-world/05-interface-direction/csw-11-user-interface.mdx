# 第 11 章 用户界面样式

本章以张鑫旭著《CSS 世界》人民邮电出版社版的第 11 章公开目录为身份基线，采用独立教学改写。用户界面样式不是给控件加一个“像按钮”的外观：先保留可达的焦点路径，再用 outline 在盒外提供反馈，最后用 cursor 表达指针意图。排查“控件看起来可用却无法操作”时，先找输入路径、焦点状态或语义上的第一个偏离点。

<Objectives>

- 能解释 outline 与 border 在盒模型、布局尺寸和焦点反馈上的差异，并为键盘焦点设计可见替代。
- 能用 outline-offset、圆角、焦点状态和 cursor 回退建立不改变布局的界面反馈。
- 能在键盘、鼠标、触摸、资源失败、窄视口和高对比模式下核对真实语义、焦点顺序与可操作性。

</Objectives>

## 先追踪一次焦点如何变得可见

遇到“鼠标能点但键盘找不到”“去掉 outline 后布局更整齐”或“自定义光标加载失败”，不要先用颜色或伪元素掩盖问题。固定真实控件、焦点顺序、盒尺寸、视口和状态，先记录输入方式与 focus-visible，再观察 outline 是否在盒外绘制、cursor 是否有关键字回退。动手前先猜：第一个变化来自焦点路径、轮廓几何，还是指针资源？

## 三个必须先拆开的误区

<Callout type="trap" title="全局 outline:0 none 只是移除了问题的反馈">
  **现象：** 页面视觉更干净，但 Tab 用户不知道当前焦点在哪。**原因：** outline
  被移除后，没有等价的 focus-visible 反馈，鼠标测试也不会暴露缺陷。**修法：**
  只在有明确替代方案时调整 outline，并用键盘、对比度和高对比模式复测。
</Callout>

<Callout type="trap" title="把 outline 当成会撑大布局的 border">
  **现象：** 为了避免跳动而不敢使用 outline，或把所有焦点环都改成
  border。**原因：** outline 在边框外绘制，不参与盒模型；border
  会改变尺寸或可用内容空间。**修法：** 用 outline、outline-offset
  和圆角表达焦点，记录边框盒尺寸是否保持不变。
</Callout>

<Callout type="trap" title="cursor:pointer 能把普通元素变成按钮">
  **现象：** 鼠标显示手形，但键盘、读屏或触摸没有同等操作路径。**原因：** cursor
  只表达指针意图，不创建语义、事件、焦点或状态。**修法：** 优先使用真实
  button/link，补齐焦点和状态，再为必要的自定义资源提供关键字回退。
</Callout>

## 六阶段机制链

### 1. 保留原生焦点

先读取<Term def="在元素外绘制焦点或状态轮廓、通常不参与盒模型的属性">outline</Term>之前的原生焦点路径：元素是否是 button、link 或具有明确键盘顺序，Tab 是否能到达，焦点状态是否能被辅助技术感知。样式应该增强路径，而不是把路径藏起来。

### 2. 绘制 outline

outline 在边框外绘制，通常不占布局空间，适合表达焦点、错误或拖拽状态。它可以跨越部分盒片段，几何上不等同于 border；测试要保存边框盒尺寸、焦点环覆盖范围与背景对比度。

### 3. 处理偏移与圆角

<Term def="控制 outline 与元素边界之间额外距离的属性">outline-offset</Term>
可以把焦点环从内容、阴影和圆角边缘移开。偏移过小会重叠文字，过大可能撞到相邻控件；圆角、窄宽、缩放和高对比模式都要复测。

### 4. 选择系统 cursor

<Term def="控制指针在元素上方呈现何种意图图形的属性">cursor</Term>
只改变指针反馈，不改变元素的语义、事件、焦点或可操作状态。pointer、text、not-allowed、progress
等关键字应与真实状态一致，不能用手形掩盖 disabled 或异步状态没有表达。

### 5. 提供自定义回退

<Term def="只在自定义光标资源成功时使用并在失败后回到关键字的 cursor 资源写法">
  cursor: url()
</Term>
必须配合可用的关键字回退、尺寸限制和资源失败测试。自定义图形不应替代焦点环、状态文本或触摸反馈，跨平台热点位置也要验证。

### 6. 核对键盘与指针

<Term def="只在键盘或其他非指针路径需要时显示焦点反馈的伪类">
  :focus-visible
</Term>
让焦点样式可以更贴近输入方式，但不能借此让键盘焦点消失。最终验收要用
Tab、Shift+Tab、Enter、Space、鼠标和触摸分别操作，并核对焦点顺序、状态名称与错误提示。

## 出版社目录逐项映射

### 第11章 用户界面样式

本章把界面反馈拆成焦点路径、轮廓绘制、几何偏移、指针意图、资源回退和多输入一致性六层。最终截图只能证明某一时刻的外观，不能证明键盘顺序、语义元素、触摸反馈或资源失败后的可用性。

### 11.1 和border形似的outline属性

outline 与 border 都能形成边缘，但 outline 在盒外绘制且通常不改变布局尺寸，最适合焦点反馈。比较时固定元素尺寸、边框、圆角和相邻内容，分别测量 border box 与轮廓覆盖区域。

### 11.1.1 万万不可在全局设置outline:0 none

全局去掉 outline 会把键盘焦点反馈一起删除，除非每个可聚焦控件都有清晰、足够对比的替代样式。验收必须使用真实 Tab 路径，并覆盖 :focus-visible、对比度、缩放和高对比模式。

### 11.1.2 真正的不占据空间的outline及其应用

outline 不参与盒模型，因此可以在不让布局跳动的情况下表达焦点、错误、拖拽或选中状态。outline-offset 和圆角用来解决重叠与几何边界，但仍要确保轮廓不被 overflow、邻接元素或背景色吞掉。

### 11.2 光标属性cursor

cursor 只改变指针图形和意图提示，不能替代 button、a、禁用状态、焦点顺序或可访问名称。使用前先确认真实控件和状态，再让指针与可操作性保持一致。

### 11.2.1 琳琅满目的cursor属性值

关键字光标覆盖 pointer、text、move、wait、progress、not-allowed 等常见状态，但平台和设备可能不完全一致。选择时应让光标与状态文案、键盘路径和触摸反馈一致，避免把“看起来能点”误当成“真的能操作”。

### 11.2.2 自定义光标

自定义光标适合品牌化或工具型界面，但必须提供关键字回退、尺寸与热点约束，并测试资源加载失败、触摸设备和高对比模式。它是增强反馈，不应承担焦点、语义或操作确认。

## 用户界面证据记录

每个样本写六列：**真实语义元素、输入方式与焦点顺序、边框盒与 outline 几何、计算值与资源回退、首个反馈偏离点、恢复结果**。键盘样本增加 focus-visible，光标样本增加平台与触摸，状态样本增加 disabled、busy 和错误文案。

```text
freeze = semantic element + focus order + box size + viewport + state text
trace = input modality + focus-visible + outline geometry + cursor fallback
change = exactly one outline | offset | radius | cursor | resource variable
stop = first divergent focus path, layout size, pointer intent, or accessible name
replay = remove fault + same inputs + keyboard, pointer, touch feedback restored
```

```css
.action:focus-visible {
  outline: 3px solid var(--accent);
  outline-offset: 3px;
}

.action[aria-busy="true"] {
  cursor: progress;
}

.action[aria-disabled="true"] {
  cursor: not-allowed;
}

.tool {
  cursor:
    url("/cursors/tool.svg") 8 8,
    pointer;
}
```

## 练习

<Exercises>

**问题 1：** 为什么 outline 通常比 border 更适合做键盘焦点环？

<Answer>
  outline
  在边框外绘制且通常不参与盒模型，不会因为焦点出现而让尺寸、文字换行或邻接布局跳动。仍需检查轮廓是否被裁剪、对比度是否足够以及窄宽和高对比模式下是否可见。
</Answer>

**问题 2：** 全局设置 outline:0 none 后，怎样判断替代焦点样式是否真的合格？

<Answer>
  用 Tab 和 Shift+Tab
  走完整路径，确认每个可聚焦控件都有稳定、足够对比且不被内容遮挡的 focus-visible
  反馈，再复测缩放、高对比、窄视口和错误状态。鼠标点击通过不能证明键盘通过。
</Answer>

**问题 3：** 为什么 cursor:pointer 不能替代 button 或 link？

<Answer>
  cursor
  只改变指针图形，不创建语义、键盘焦点、默认事件、状态或辅助技术名称。应优先使用真实
  button/link，补齐
  disabled、busy、错误和焦点反馈，再在需要时添加带关键字回退的自定义 cursor。
</Answer>

</Exercises>

## 小结

- outline 在盒外绘制且通常不改变布局尺寸，是键盘焦点和状态反馈的合适起点；outline-offset 与圆角负责几何间距。
- 全局移除 outline 必须有等价的 focus-visible 替代，并用真实 Tab 路径验证，而不是只看鼠标截图。
- cursor 表达指针意图，不创建语义、事件、焦点或可访问名称；自定义 cursor 必须带关键字回退。
- 键盘、鼠标和触摸应得到一致的状态反馈，焦点、状态文案、资源失败和高对比模式都属于发布证据。
