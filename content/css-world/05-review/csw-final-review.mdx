## 直觉引入

全书可以浓缩成一条主线：流与盒决定「怎么排」→ 文本决定「怎么断」→ 布局决定「怎么放」→ 动效决定「怎么动」。每一层解决上一层的遗留问题，每一层都建立在 CSS 渲染机制之上。理解这条主线，你就能解释任何 CSS 现象：为什么浮动会塌陷（流）、为什么行高继承出问题（文本）、为什么 flex 不合并 margin（布局）、为什么 transform 动画最流畅（动效）。

## 四层知识串联

<Term def="CSS 渲染机制是以正常流为基底、通过盒模型计算尺寸、用流式/弹性/网格布局组织位置、靠文本属性控制断行、经变换与动画驱动视觉表现的分层体系。">CSS 渲染机制</Term>的四个层次环环相扣。

```css
/* 一个完整的页面，四层知识全部参与 */
:root { box-sizing: border-box; }  /* 第 1 层：盒模型全局重置 */

.page {
  /* 第 3 层：Grid 二维骨架 */
  display: grid;
  grid-template-columns: 1fr 3fr;
  grid-template-areas: "nav main";
  min-height: 100vh;
  gap: 24px;  /* Grid gap 不参与 fr 分配 */
}

.card {
  /* 第 1 层：BFC 隔离 + border-box */
  display: flow-root;  /* 清除内部浮动，无副作用 */
  padding: 16px;
  /* 第 3 层：内部 Flex 排列 */
  display: flex;
  flex-direction: column;
  gap: 12px;  /* flex 子元素 margin 不合并 */
  /* 第 4 层：transform 动画（只合成不重排） */
  transition: transform 0.3s ease-out;
}
.card:hover { transform: translateY(-4px); }

.card h3 {
  /* 第 2 层：文本排版 */
  line-height: 1.5;        /* 无单位值，子元素动态重算 */
  white-space: nowrap;     /* 不换行 */
  overflow: hidden;
  text-overflow: ellipsis; /* 单行省略三件套 */
}
```

## 常见误区

<Callout type="trap">
**误区：CSS 只是「写样式」，没有深层机制。** CSS 的每一行属性背后都有渲染机制在支撑。`overflow:hidden` 不是「裁剪溢出」那么简单——它触发 BFC 改变了高度计算规则；`line-height: 1.5` 不是随便设的——无单位值和带单位值的继承行为完全不同；`flex:1` 不是「占一份」——它展开为 `1 1 0%`，basis 为 0 意味着所有空间都是剩余空间按比例分；`transform` 不触发重排不是巧合——它操作的是合成层位图而非布局树。区分「会写 CSS」和「懂 CSS」的标志：能否解释一段样式「为什么这样渲染」而非只是「能看」。
</Callout>

<Exercises>
**问题 1**：用全书四层知识解释「一个卡片 hover 上浮动画」的完整渲染过程。

<Answer>
①流与盒模型：卡片用 box-sizing:border-box 确保尺寸所见即所得，padding/border 向内挤压不撑破布局；②布局体系：卡片内部用 flex 排列（gap 替代 margin 避免合并问题），外层用 grid 定位；③文本排版：标题用 line-height:1.5（无单位值让子元素行高自适应）+ white-space:nowrap+overflow:hidden+text-overflow:ellipsis 实现单行省略；④视觉动效：hover 时 transform:translateY(-4px)，配合 transition:transform 0.3s ease-out 平滑过渡。transform 不触发重排（只合成），transition 用 ease-out（快→慢，出场首选）。will-change:transform 提前提升合成层优化。
</Answer>

**问题 2**：为什么说「把属性当终点的人写出的页面脆弱，把渲染机制当核心的人才能写出可控的 CSS」？

<Answer>
属性是表层的——照文档抄 display:flex、margin:20px 谁都会。但遇到「浮动塌陷」「margin 合并导致间距不对」「line-height 继承后行高异常」「flex:1 分配结果和预期不同」「动画卡顿」这些问题时，只懂属性的人无从下手。懂渲染机制的人知道：塌陷是浮动脱离流导致高度计算不含浮动子，合并是正常流相邻块级的取大值规则，行高异常是无单位值动态重算 vs 带单位值固定继承，flex 分配是 basis 先占剩余再按 grow 分，卡顿是动画了触发重排的属性。机制是「为什么」，属性是「是什么」，工程判断力来自前者。
</Answer>
