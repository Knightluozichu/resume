# 《CSS 世界》全书总复习

本页是《CSS 世界》十二章目录的最终复核，不是把每章的结论重新抄一遍。身份基线采用张鑫旭著《CSS 世界》人民邮电出版社电子版目录；正文为独立教学重构，不复制原书段落。复核对象是同一个问题：给定 DOM、声明、视口、字体和内容，能否从盒生成一路解释到绘制结果，并在改变一个条件后定位第一个分叉、删除故障再重放？

<Objectives>

- 能从 DOM 与声明出发，依次说明盒生成、格式化上下文、包含块、计算值、使用值、行框、层叠和绘制之间的因果关系。
- 能在正常、窄视口、长内容、混合语言、显隐和书写方向样本中只改变一个变量，记录首个偏离点与受影响的流体契约。
- 能用一个可重放实验串联《CSS 世界》的十二个目录节点，并为每个结论保存输入、观测、反例、修复和恢复证据。
- 能审查一页 CSS 方案是否只是截图看起来正确，还是确实能解释盒树、使用尺寸、内联基线、层叠顺序与方向变化。

</Objectives>

## 从一次可推翻的外观开始

先预测，而不是先修补。冻结 DOM 结构、样式表、视口、字体、内容和书写方向，写下“应该生成什么盒、谁是包含块、哪个值会改变”。然后只改一条声明或一个环境变量，把浏览器开发者工具当作观测仪器：它可以展示计算样式，却不能替我们解释为什么该值出现。

## 三个必须先拆开的误区

<Callout type="trap" title="把截图相同当成机制相同">
  **现象：** 两个方案在宽视口下像素相同，于是直接合并声明。**原因：**
  固定宽高、隐藏溢出或偶然的层叠顺序可能遮住不同的盒树和使用值。**修法：**
  固定同一输入，比较生成盒、包含块、使用尺寸、行框与绘制顺序，再用窄宽和长内容复核。
</Callout>

<Callout type="trap" title="把所有错位都归因于 margin">
  **现象：** 内联文字、图片或按钮错位，就不断调整 margin-top。**原因：**
  首个分叉可能来自字体度量、基线、行框、替换元素尺寸或正常流中的格式化上下文。**修法：**
  先记录行框和基线，再检查使用值与固有尺寸，最后才决定是否需要间距声明。
</Callout>

<Callout type="trap" title="把方向与显隐当作最后的视觉开关">
  **现象：** RTL、竖排或隐藏状态出现溢出、焦点消失和滚动起点异常。**原因：**
  书写模式会重映射逻辑轴，display、visibility、opacity
  和溢出对盒树与可访问结果的影响也不同。**修法：**
  保存逻辑顺序、盒是否生成、焦点路径、滚动边界和恢复后的同输入结果。
</Callout>

## 六层证据链

### 1. 读取输入与声明

先把元素、伪元素、文本内容、级联来源和继承链列出来。记录用户代理默认值与作者声明的差别，不把声明值直接写成“最终尺寸”。若两个选择器都能解释现象，保留优先级、来源顺序和继承路径，直到能指出当前使用的是哪一条规则。

### 2. 追踪盒树与格式化上下文

<Term def="由元素、文本或伪元素在布局中实际生成的一个或多个布局盒">生成盒</Term>
决定后续布局是否存在；display、匿名盒、替换元素和脱离正常流的元素会让 DOM
树与布局树不再一一对应。接着识别
<Term def="用于计算尺寸和定位的参照矩形，其来源取决于格式化上下文与定位规则">
  包含块
</Term>
，因为百分比、auto
和绝对定位的参照一旦选错，后面每个像素都可能看似合理却没有因果依据。

### 3. 求解使用尺寸与行框

浏览器会把级联结果、继承、固有尺寸、最小最大约束、可用空间和内容度量合成为 <Term def="布局完成后实际用于排版和绘制的尺寸或位置结果">使用值</Term>。尺寸复核要区分外在尺寸与内在尺寸；内联复核要把字体回退、字形度量、基线、行高和换行位置一并保存。只有把首个改变的使用值记下来，才能判断错位是尺寸问题还是绘制问题。

### 4. 解释层叠、装饰与绘制

先画出 <Term def="决定不同后代在局部绘制顺序中如何分组和比较的独立层叠空间">层叠上下文</Term>树，再比较层叠顺序、绘制阶段、背景、边框、文本装饰和定位元素。z-index 不是全局的“谁大谁在上”；一个新的上下文可能把看似更大的值关在自己的局部空间里。背景或阴影盖住焦点时，要同时检查绘制顺序和可访问焦点，而不是只提高数值。

### 5. 检查显隐、流向与逻辑轴

显隐实验要分别观察盒是否生成、是否占据布局空间、是否能被聚焦、是否仍参与辅助技术树。书写方向实验要保存 `direction`、`unicode-bidi`、`writing-mode`、滚动起点和内容顺序；<Term def="随 writing-mode 变化、描述内容沿其方向排列的稳定坐标轴">逻辑轴</Term>不能被简单等同为永远水平或永远垂直。优先使用 inline/block 逻辑属性，再检验替换元素、最小尺寸和窄视口。

### 6. 删除故障并重放

故障样本只引入一个脱流声明、尺寸约束、层叠条件、显隐状态或方向变量。证据记录应包含 DOM 与内容、生成盒、格式化上下文、包含块、计算值、使用值、行框、首个偏离点、绘制顺序和恢复结果。删除故障后，用完全相同的输入重放；如果结果只在某个宽度、字体或内容长度下恢复，说明修复仍是偶然覆盖。

## 总复习实验的交接协议

交接包至少包含四份材料：输入快照、机制轨迹、故障对照和恢复记录。输入快照锁定视口、字体加载结果、DOM、样式来源、方向和内容；机制轨迹按六层证据链排序；故障对照只改变一个变量并标注第一个不同的值；恢复记录说明删除哪条声明、是否重新计算了布局和绘制，以及窄宽、长内容、混排和焦点是否仍成立。

不要把“在我的浏览器里看起来对”当成通过条件。真正可交接的结果应能回答：谁生成了这个盒？哪个包含块提供参照？哪个使用值首先变化？行框和层叠上下文如何把变化传到绘制？显隐与书写方向是否改变了布局和交互？同一输入重放后，原来的流体契约是否回来了？

## 出版社目录的十二节点回放

把正式目录压缩成一条回放路径：第 1 章先建立阅读 CSS 现象的因果视角；第 2 章固定术语与未定义行为边界；第 3、4 章处理流、元素类型和盒尺寸；第 5 章解释内联盒、行框与基线；第 6 章检查脱离正常流及其保护方式；第 7 章建立层叠上下文和绘制顺序；第 8、9 章进入文本处理、背景、边框与装饰；第 10 章区分显示、隐藏、占位和可访问结果；第 11 章复核用户界面状态；第 12 章用 direction、unicode-bidi、writing-mode 与逻辑轴处理多语言和流向。

这条路径不是用一个大而全的组件代替十二章，而是让每个节点在同一组输入与观测字段里留下证据。总复习只宣布“已覆盖”还不够；必须能从任意节点向前追溯输入，向后追溯使用值和绘制，向旁边追溯边界与恢复。

## 练习

<Exercises>

**问题 1：** 一张截图与预期一致，为什么仍不能宣布 CSS 方案通过？

<Answer>
  截图只描述某个输入下的末端像素，不能证明生成盒、包含块、使用值、行框、层叠上下文、焦点和书写方向都正确。应固定输入并保存机制轨迹，再用窄视口、长内容和混合语言样本验证同一契约。
</Answer>

**问题 2：** 一个按钮在宽屏正常、窄屏错位，复核顺序应该怎样安排？

<Answer>
  先保持
  DOM、字体和声明不变，确认容器可用空间与生成盒；再检查包含块、使用宽度、内联行框和换行；之后才检查层叠、装饰、显隐和方向。每次只改变一个条件，并把第一个不同的使用值记录为故障入口。
</Answer>

**问题 3：** 如何证明删除一个方向或溢出补丁后，布局真的恢复了？

<Answer>
  保存故障前的
  DOM、内容、视口、字体、样式和观测结果，删除单条补丁后用完全相同输入重放。比较盒树、逻辑轴、使用尺寸、滚动边界、焦点和绘制顺序；若只在单一宽度或单一内容下正常，就不能称为恢复。
</Answer>

</Exercises>

## 术语表

<Glossary>
  <GlossaryItem term="生成盒">
    元素、文本或伪元素在布局中实际生成的布局盒；它决定后续尺寸和绘制是否有对象可追踪。
  </GlossaryItem>
  <GlossaryItem term="包含块">
    计算尺寸和定位时使用的参照矩形；百分比、auto 与定位的结果依赖它的来源。
  </GlossaryItem>
  <GlossaryItem term="使用值">
    布局完成后真正参与排版和绘制的尺寸或位置结果，不能直接等同于声明值。
  </GlossaryItem>
  <GlossaryItem term="层叠上下文">
    决定后代如何在局部绘制顺序中分组和比较的独立层叠空间。
  </GlossaryItem>
  <GlossaryItem term="逻辑轴">
    随书写模式变化、用于表达 inline 与 block
    流向的稳定坐标，而不是固定的物理水平或垂直。
  </GlossaryItem>
</Glossary>

## 小结

全书最终验收的最小闭环是：冻结输入，预测生成盒和包含块，沿使用值与行框找到第一个分叉，解释层叠与绘制，再删除单一故障并用同一输入重放。若宽度、内容长度、字体、显隐、焦点或书写方向变化就只能靠额外覆盖维持外观，说明机制尚未被解释，发布证据也尚未闭环。
