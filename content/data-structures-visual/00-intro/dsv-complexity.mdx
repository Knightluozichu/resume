## 直觉引入

假设你要在一本 1000 页的字典里找一个词。如果从头逐页翻，平均要翻 500 页；如果用二分法（从中间翻开，看字母大小决定往左还是往右），最多只需翻约 10 次。这就是复杂度的直觉——同样的问题，不同方法效率天差地别。

大 O 表示法就是用来量化这种效率差异的工具。它不关心具体几秒几毫秒，只关心**当数据量变大时，操作次数的增长趋势**。

## 概念讲解

### 大 O 表示法

<DsvComplexityDiagram />

<Term def="大 O 表示法描述算法在最坏情况下运行时间随输入规模增长的上界趋势">
大 O 表示法
</Term>

大 O 的核心是「抓大头、忽略常数」。$O(2n+3)$ 简写成 $O(n)$，因为当 $n$ 足够大时，常数 2 和 3 的影响可忽略不计。同理 $O(n^2+n)$ 简写为 $O(n^2)$。

### 常见复杂度等级

| 复杂度 | 名称 | 典型场景 | $n=10$ | $n=1000$ |
|---|---|---|---|---|
| $O(1)$ | 常数 | 数组下标访问 | 1 | 1 |
| $O(\log n)$ | 对数 | 二分查找 | 4 | 10 |
| $O(n)$ | 线性 | 遍历数组 | 10 | 1000 |
| $O(n \log n)$ | 线性对数 | 归并排序 | 33 | 9966 |
| $O(n^2)$ | 平方 | 冒泡排序 | 100 | 1000000 |
| $O(2^n)$ | 指数 | 暴力求子集 | 1024 | 天文数字 |

从表中能直观看出：$O(n^2)$ 在 $n=1000$ 时已经百万级操作，而 $O(\log n)$ 仅需 10 次。这就是为什么排序算法要从冒泡（$O(n^2)$）优化到快排（$O(n \log n)$）。

### 如何从代码推断复杂度

<Stepper>
<Step title="单层循环 = O(n)">
```python
for i in range(n):    # 循环 n 次
    print(i)          # 每次操作 O(1)
# 总共 n 次操作 → O(n)
```
</Step>
<Step title="嵌套循环 = O(n²)">
```python
for i in range(n):        # 外层 n 次
    for j in range(n):    # 内层 n 次
        print(i, j)       # 每次操作 O(1)
# 总共 n × n 次 → O(n²)
```
</Step>
<Step title="对半递减 = O(log n)">
```python
i = n
while i > 1:         # 每次把 i 减半
    i = i // 2       # n → n/2 → n/4 → ... → 1
# 递减次数 = log₂(n) → O(log n)
```
</Step>
<Step title="分治递归 = O(n log n)">
```python
def merge_sort(arr):
    if len(arr) <= 1: return arr
    mid = len(arr) // 2           # 对半分
    left = merge_sort(arr[:mid])  # 递归排序左半
    right = merge_sort(arr[mid:]) # 递归排序右半
    return merge(left, right)     # 合并 O(n)
# T(n) = 2T(n/2) + O(n) → O(n log n)
```
</Step>
</Stepper>

### 空间复杂度

<Term def="算法在运行过程中额外占用的内存空间随输入规模增长的趋势">空间复杂度</Term>

空间复杂度衡量算法「除了输入本身，还要额外花多少内存」。例如递归调用每层压栈，深度为 $n$ 的递归空间复杂度是 $O(n)$。归并排序需要额外 $O(n)$ 的辅助数组，而快排原地排序只需 $O(\log n)$ 的递归栈空间。

## 代码对照

```python
# 同一个问题「在数组中找目标值」，不同复杂度

# 顺序查找：O(n) —— 逐个比较
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

# 二分查找：O(log n) —— 每次排除一半（前提：数组已排序）
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

# n=100万时：顺序查找平均 50万次，二分查找仅 20次
```

## 常见误区

<Callout type="trap">
**误区：认为 O(n) 的算法一定比 O(n²) 快。**
大 O 描述的是增长趋势，不是绝对速度。当 n 很小时（比如 n=5），O(n²) 可能比 O(n) 还快，因为 O(n) 算法可能有更大的常数项。大 O 的价值在于：当 n 足够大时，低阶复杂度一定胜出。
</Callout>

<Callout type="trap">
**误区：只看时间复杂度，忽略空间复杂度。**
有些场景内存比时间更宝贵。例如递归写法简洁但栈空间 O(n)，迭代写法稍长但空间 O(1)。在嵌入式系统或大数据处理中，空间往往是瓶颈，需要做时间-空间权衡。
</Callout>

<Exercises>
**问题 1**：以下代码的时间复杂度是多少？
```python
for i in range(n):
    j = 1
    while j < n:
        j = j * 2
```

<Answer>
$O(n \log n)$。外层循环执行 $n$ 次，内层 while 循环每次把 $j$ 翻倍，执行 $\log_2 n$ 次。总共 $n \times \log_2 n$ 次操作，即 $O(n \log n)$。
</Answer>

**问题 2**：大 O 表示法为什么要「忽略常数」？

<Answer>
因为大 O 描述的是增长趋势（当 $n \to \infty$ 时），常数项不改变趋势的方向。$O(3n)$ 和 $O(100n)$ 都是线性增长，趋势相同，都记为 $O(n)$。只在同阶算法比较具体实现时才考虑常数因子的差异。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="大 O 表示法">
描述算法在最坏情况下运行时间（或空间）随输入规模增长的上界趋势，忽略常数项和低阶项，只保留最高阶项。
</GlossaryItem>
<GlossaryItem term="时间复杂度">
算法执行所需的基本操作次数随输入规模 $n$ 增长的趋势，用大 O 表示，如 $O(n)$、$O(n \log n)$。
</GlossaryItem>
<GlossaryItem term="空间复杂度">
算法在运行过程中额外占用的内存空间随输入规模增长的趋势，用大 O 表示。
</GlossaryItem>
<GlossaryItem term="最坏情况复杂度">
算法在所有可能的输入中，运行时间最长的那个情况对应的复杂度。大 O 通常描述最坏情况。
</GlossaryItem>
</Glossary>
