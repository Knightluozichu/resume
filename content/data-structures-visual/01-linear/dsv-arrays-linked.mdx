## 直觉引入

想象一排连号座位和一群手拉手的人。连号座位就像数组——你知道几号座位就能直接走过去，但如果中间要插一个人，后面所有人都得往后挪。手拉手的人就像链表——每个人记住下一个是谁，要插入新人只需断开两只手重新拉上，但找第 100 个人得从第 1 个开始顺着数过去。

这就是数组与链表的根本区别：**连续存储 vs 分散存储**，各有优劣。

## 概念讲解

### 数组：顺序存储

<DsvArraysLinkedDiagram />

<Term def="数组是在连续内存中存储相同类型元素的线性结构，通过下标实现 O(1) 随机访问">
数组
</Term>

数组的核心优势是**随机访问**：由于内存连续，`arr[i]` 的地址可以直接用 `基地址 + i × 元素大小` 算出，一步到位。代价是插入和删除——在中间插入一个元素，后面的全部要往后挪，最坏 $O(n)$。

| 操作 | 数组复杂度 | 说明 |
|---|---|---|
| 按下标访问 | $O(1)$ | 直接算地址 |
| 按值查找 | $O(n)$ | 需遍历（无序时） |
| 尾部插入 | $O(1)$ 均摊 | 动态数组扩容时 $O(n)$ |
| 中间插入 | $O(n)$ | 后续元素全部后移 |
| 中间删除 | $O(n)$ | 后续元素全部前移 |

### 链表：链式存储

<Term def="链表是用指针将分散的内存节点串联起来的线性结构，插入删除 O(1) 但不支持随机访问">
链表
</Term>

链表的每个节点包含「数据」和「指向下一节点的指针」。内存不连续，所以无法用下标直接访问——找第 $i$ 个节点必须从头节点开始顺着指针走 $i$ 步。但插入和删除只需修改指针，不需要移动其他元素。

<Stepper>
<Step title="链表插入节点">
要在节点 A 和 B 之间插入新节点 X：只需让 A 的 next 指向 X，X 的 next 指向 B。两步完成，不移动任何其他节点。时间 $O(1)$（已知位置时）。
</Step>
<Step title="链表删除节点">
要删除节点 B（前驱为 A）：让 A 的 next 直接指向 B 的 next（即 C），B 就被跳过了。一步完成。时间 $O(1)$（已知前驱时）。
</Step>
<Step title="链表查找第 i 个节点">
必须从头节点出发，顺着 next 指针走 $i$ 步。无法像数组那样一步到位。时间 $O(n)$。
</Step>
</Stepper>

### 单链表 vs 双链表 vs 循环链表

**单链表**：每个节点只有 next 指针，只能正向遍历。**双链表**：每个节点有 prev 和 next 两个指针，可以双向遍历，删除给定节点 $O(1)$（单链表需先找前驱 $O(n)$）。**循环链表**：尾节点指向头节点，形成环，适合环形缓冲区场景。

## 代码对照

```python
# 数组操作
arr = [10, 20, 30, 40, 50]

# O(1) 随机访问
print(arr[2])  # 30，直接算地址

# O(n) 中间插入：在索引 2 处插入 25
arr.insert(2, 25)  # [10, 20, 25, 30, 40, 50]，30/40/50 全部后移

# 链表操作
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    # O(n) 查找第 i 个节点
    def get(self, index):
        cur = self.head
        for _ in range(index):
            cur = cur.next
        return cur.data

    # O(1) 在已知节点后插入（无需移动其他元素）
    def insert_after(self, node, new_data):
        new_node = Node(new_data)
        new_node.next = node.next
        node.next = new_node
```

## 常见误区

<Callout type="trap">
**误区：认为链表插入删除一定是 O(1)。**
链表的插入删除本身（改指针）是 $O(1)$，但前提是已经拿到了要操作的节点位置。如果还要先从头遍历找到位置，查找那一步是 $O(n)$。所以链表中间插入的总体复杂度是 $O(n)$（查找）+$O(1)$（插入）=$O(n)$。
</Callout>

<Callout type="trap">
**误区：动态数组扩容时是 O(n)，所以数组不如链表。**
动态数组扩容确实偶尔 $O(n)$，但采用倍增策略后，均摊到每次插入是 $O(1)$。而且数组的连续内存对 CPU 缓存友好（空间局部性），实际运行中数组往往比链表快得多，即使理论复杂度相同。
</Callout>

<Exercises>
**问题 1**：频繁在头部插入元素，用数组还是链表？

<Answer>
用链表。链表头部插入只需新建节点并指向原头节点，$O(1)$。数组头部插入需要所有元素后移，$O(n)$。如果频繁头部插入，链表（或双端队列）远优于数组。
</Answer>

**问题 2**：为什么数组的随机访问是 $O(1)$ 而链表是 $O(n)$？

<Answer>
数组内存连续，`arr[i]` 的地址 = 基地址 + i × 元素大小，一步算出。链表内存分散，节点之间靠指针连接，找第 $i$ 个节点必须从头开始顺着 next 走 $i$ 步，所以是 $O(n)$。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="数组">
在连续内存中存储相同类型元素的线性结构，通过下标实现 O(1) 随机访问，但中间插入删除需 O(n)。
</GlossaryItem>
<GlossaryItem term="链表">
用指针将分散的内存节点串联的线性结构，插入删除 O(1)（已知位置时），但不支持随机访问，查找 O(n)。
</GlossaryItem>
<GlossaryItem term="顺序存储">
数据元素存放在地址连续的内存单元中，逻辑上相邻的元素物理上也相邻。数组的存储方式。
</GlossaryItem>
<GlossaryItem term="链式存储">
数据元素存放在任意内存位置，通过指针维护逻辑上的先后关系。链表的存储方式。
</GlossaryItem>
</Glossary>
