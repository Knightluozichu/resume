## 从“字符串不是字符数组的同义词”开始

串是零个或多个字符组成的有限序列，逻辑上是特殊线性表；但字符单位、编码和终止方式必须声明。C字符串习惯以NUL结尾，串ADT也可用`pointer + length`表示含NUL字节的序列。模式匹配若只调用`strlen`，会把表示限制悄悄变成算法前置条件。

先预测：空模式在任意文本中是否匹配；文本长度小于模式是否需要逐字符尝试；UTF-8的一个汉字应算一个字符还是三个字节。本文算法按byte sequence演示，空模式匹配起点0；Unicode字符/用户可见字素需要更高层解码与索引。

<Term def="由零个或多个字符组成的有限序列，具有明确长度与次序。">串</Term>可为空串，空串与只含空格或NUL的串不同。

## 串的定义与比较

两个串相等要求长度相同且每个位置单位相等。字典序比较从左到右找首个不同单位，较小单位对应较小串；若一个是另一个前缀，较短者更小。比较器必须与排序、查找和Hash相等语义一致。

<Term def="在固定字符单位和排序规则下，从左到右比较首个不同位置，或以前缀长度决定次序。">串比较</Term>若使用本地化collation，其等价、大小写和normalization规则必须显式，不再是简单byte compare。

```c
#include <stddef.h>
#include <stdint.h>

typedef struct {
    const uint8_t *data;
    size_t length;
} StringView;

int string_compare(StringView left, StringView right) {
    size_t common = left.length < right.length ? left.length : right.length;
    for (size_t i = 0; i < common; ++i) {
        if (left.data[i] < right.data[i]) return -1;
        if (left.data[i] > right.data[i]) return 1;
    }
    return (left.length > right.length) - (left.length < right.length);
}
```

指针为NULL且长度0是否允许要固定；本文允许空view但任何正长度必须有非NULL data。比较无符号byte避免char signedness改变128以上值的顺序。

## 串的抽象数据类型

串的抽象数据类型通常提供assign/copy、empty、length、compare、clear、concat、substring、index/match与replace。<Term def="用有限字符序列和操作契约定义、隐藏连续或块链表示的抽象类型。">串ADT</Term>必须声明操作返回新串还是原地修改，失败时owner和原值如何处理。

`substring(position,length)`要防`position + length`溢出，宜检查`position <= source.length`且`length <= source.length - position`。连接需要先检查总长度、分配成功后再写，才能在失败时保持原串。借用view切片不复制，但生命周期不得超过owner。

<Term def="把全部字符放在连续存储中，并以长度或终止符界定有效序列。">串的顺序存储</Term>按位读取和批量比较局部性好，连接/插入可能扩容和移动。定长表示必须区分拒绝与截断；静默截断会让相等、匹配和协议解析都失真。

<Term def="把串拆成多个固定或可变大小块，由链接保持先后次序。">串的链式存储</Term>能分散分配和较便宜拼接，但按位访问、比较和模式匹配要跨块维护cursor。每结点只存一个字符会导致链接开销过大，实际常用块链或rope类结构。

<Callout type="trap" title="C里字符串就是以NUL结尾的char数组">
那只是常见表示。网络frame、文件切片和二进制字段可能含NUL或不带终止符；算法若接受显式length，就能把表示前置条件放在边界而非隐藏在strlen中。
</Callout>

## 朴素模式匹配

给文本`T`长度`n`和模式`P`长度`m`，朴素算法依次尝试起点`0..n-m`，每次从`P[0]`开始比较，直到失配或完整匹配。<Term def="对每个可能起点从模式首位重新比较，失配后整体右移一位的搜索。">朴素模式匹配</Term>简单、对短模式常够用，但重复前缀会产生大量重复比较。

  <Step title="记录每次比较">对`AAAAAAAAAB`查`AAAAB`列出每个起点匹配长度，观察重复工作。</Step>
  <Step title="覆盖边界">空模式、空文本、模式更长、相等、首/尾匹配、无匹配、含NUL与重复字符。</Step>
</Stepper>

```c
#include <stdbool.h>
#include <stddef.h>

bool naive_find(StringView text, StringView pattern, size_t *position) {
    if (pattern.length == 0) {
        if (position != NULL) *position = 0;
        return true;
    }
    if (pattern.length > text.length) return false;
    for (size_t start = 0; start <= text.length - pattern.length; ++start) {
        size_t j = 0;
        while (j < pattern.length && text.data[start + j] == pattern.data[j]) {
            ++j;
        }
        if (j == pattern.length) {
            if (position != NULL) *position = start;
            return true;
        }
    }
    return false;
}
```

先检查`pattern.length > text.length`，再写减法，避免无符号下溢。最坏比较次数为`Theta((n-m+1)m)`，当模式有长重复前缀而每个起点在末尾失配时接近`Theta(nm)`。

## KMP模式匹配的原理

KMP观察到：在某起点已匹配`P[0..j)`后失配，这段文本已经等于模式前缀；下一次可能匹配不必让文本回退，只需找到该已匹配前缀的最长“既是前缀又是后缀”的真边界，把模式索引`j`回退到其长度。

<Term def="一个串中既是前缀又是后缀、但不等于整个串的子串。">真前后缀</Term>为失配提供可复用信息。<Term def="为模式各前缀记录失配后应回退位置或可保留边界长度的表。">next数组</Term>只依赖模式，可预处理复用。

不同资料有三种常见表示：1-based `next[1]=0`；0-based带`-1`哨兵；0-based LPS/prefix-function记录最长边界长度。它们可转换，但表项语义不同。本文代码采用0-based prefix length `lps[i]`，即`pattern[0..i]`的最长真前后缀长度。

### next数组值的推导

构建到位置`i`时，令`j`为前一前缀的最长边界长度。若`pattern[i] == pattern[j]`，边界扩展，`lps[i] = ++j`；否则把`j`回退为`lps[j-1]`继续比较，直到匹配或0。每次回退沿更短边界链，不重新扫描已知前缀。

```c
void build_lps(StringView pattern, size_t *lps) {
    if (pattern.length == 0) return;
    lps[0] = 0;
    size_t j = 0;
    for (size_t i = 1; i < pattern.length; ++i) {
        while (j > 0 && pattern.data[i] != pattern.data[j]) {
            j = lps[j - 1];
        }
        if (pattern.data[i] == pattern.data[j]) ++j;
        lps[i] = j;
    }
}

bool kmp_find(StringView text, StringView pattern, const size_t *lps,
              size_t *position) {
    if (pattern.length == 0) {
        if (position != NULL) *position = 0;
        return true;
    }
    size_t j = 0;
    for (size_t i = 0; i < text.length; ++i) {
        while (j > 0 && text.data[i] != pattern.data[j]) j = lps[j - 1];
        if (text.data[i] == pattern.data[j]) ++j;
        if (j == pattern.length) {
            if (position != NULL) *position = i + 1 - pattern.length;
            return true;
        }
    }
    return false;
}
```

构建`Theta(m)`，搜索`Theta(n)`：虽然while可在一次迭代多次回退，但`j`每次回退严格下降，增长总次数受文本推进限制。`lps`必须有`m`项并属于同一pattern；缓存时应绑定模式内容/hash与长度，不能错用旧表。

### nextval数组与KMP改进

若失配后回退到位置`k`，但`pattern[j] == pattern[k]`，同一个文本字符会立刻再次失配，可继续沿failure链跳过。<Term def="当回退位置字符与当前模式字符相同时继续压缩failure链的改进表。">nextval数组</Term>减少某些重复比较，不改变最坏线性阶。

nextval实现高度依赖`next`约定。不要把1-based教材公式直接抄进0-based LPS代码；先写每个表项的语义和哨兵，再对全相同、周期模式和无重复模式逐项对照。现代实现常直接使用LPS，是否加入nextval由实际比较成本决定。

<Callout type="trap" title="KMP永远比朴素匹配快，所以所有场景都应使用">
KMP有预处理、额外表和更复杂分支；短模式、小文本或一次性搜索中朴素/经过优化的库函数可能更快。KMP保证线性最坏比较，选择仍需工作负载与profile。
</Callout>

## 完整验证：结果、表与复杂度

先用reference朴素算法作为小规模oracle，枚举小字母表下所有短text/pattern，对KMP比较found与首位置。单独断言已知模式的LPS/next表；扰动表一项，确认测试能捕获。再用长重复前缀构造worst case，计数比较证明文本索引不回退且总比较线性。

Unicode搜索若按code point，应先严格解码并维护byte offset映射；若按用户字符，还要grapheme segmentation与normalization。算法的“字符”单位是输入模型的一部分，不能在结果offset交付时才决定。

### 分块输入中的匹配状态

大文件或网络流不能假设文本一次进入连续内存。朴素实现若逐块独立搜索，会漏掉“模式前半在上一块、后半在下一块”的跨边界匹配；保留最后`m-1`个单位与新块拼接可修复，但要处理重复报告和额外复制。KMP更自然：把当前`j`作为流状态跨块保存，下一块继续消费，不需要保存整个历史。

流式matcher至少保存pattern、failure table、当前边界长度`j`和已消费总offset。每处理一个byte，先按failure链回退/推进；匹配完成时报告`total + local_index + 1 - m`，若允许重叠匹配，再把`j`设为`lps[m-1]`继续，而不是重置0。首个匹配API可以终止，find-all API则要声明overlap policy。

Chunk大小不应改变结果。验证时对同一text用每个可能切分点、随机多块和1-byte chunks运行，断言匹配位置序列与连续reference一致；覆盖空块、模式长于块、匹配跨多个块和结束时只匹配部分前缀。状态序列化若用于断点续传，还需绑定pattern/hash与offset，不能拿旧状态配新模式。

### 偏移坐标必须随表示一起交付

Byte matcher报告byte offset；解码后code-point matcher报告code-point index；UI高亮常需要grapheme或原始byte range。若先normalization再匹配，normalized offset未必能直接切原文。管线应维护mapping或明确结果属于哪个coordinate space，避免“算法找到正确位置、展示却切错字符”。

比较与匹配也要共享等价规则。若搜索前做大小写折叠或Unicode normalization，pattern和text必须使用同一版本/locale的转换，并保留original用于展示；转换可能改变长度，一个输入单位不一定映射一个输出单位。此时KMP仍在线性处理normalized sequence，但端到端空间和offset契约包含转换层。

### 从表项到性质的测试

除了固定LPS向量，可验证每个`lps[i]`都小于等于`i`，对应前缀与后缀内容相等，且没有更长真边界；failure链严格下降并最终到0。搜索每一步保持`pattern[0..j)`等于已处理text的后缀。把这些性质放进debug validator，能快速定位表构建错还是搜索回退错。

Fuzz时限制长度并用朴素算法作oracle，记录seed、text、pattern、LPS和首个分歧状态。加入全相同字符、周期串、长公共前缀、含NUL与每个byte值；对nextval实现还要比较结果不变且比较次数不增加。性能结论最后再用长输入验证，正确性oracle永远先于“看起来更快”。

## 本章回顾：失配信息也可以复用

1. 串是有限有序字符序列，长度、单位、编码和owner必须明确。
2. 顺序存储局部性和索引好，块链便于分散增长但跨块操作复杂。
3. 朴素匹配逐起点重试，正确简单但最坏会重复比较前缀。
4. KMP用真前后缀构建next/failure table，文本索引不回退，构建加搜索为线性。
5. nextval压缩会立即重复失配的跳转，但必须与next下标约定一致。

<Exercises>

**问题 1：为什么StringView必须同时保存pointer和length？**

<Answer>Length界定序列，可表示含NUL或非NUL结尾切片，避免strlen越界/截断；pointer只给地址。还要规定length为0时NULL是否允许，以及view借用owner的生命周期。</Answer>

**问题 2：怎样手算模式ABABAC的LPS数组？**

<Answer>逐前缀求最长真前后缀长度：A=0，AB=0，ABA=1，ABAB=2，ABABA=3，ABABAC失配并沿3->1->0回退仍不匹配C，得0，所以数组为0,0,1,2,3,0。</Answer>

**问题 3：怎样证明KMP没有漏掉朴素算法会找到的首个匹配？**

<Answer>不变量是已处理文本后缀等于pattern[0..j)；失配只沿所有可能真边界回退，任何更早不满足边界的起点已被已知字符排除。再枚举小输入与朴素oracle比较首位置，覆盖空、重复和无匹配。</Answer>

</Exercises>
