## 直觉引入

地图上的城市和公路构成一张图：城市是顶点，公路是边，距离是权值。从北京到上海可以走很多条路，怎么找最短的？这就是图论要回答的问题。

图是数据结构中最通用的形态——树是图的特例（无环连通图），链表是树的特例（每个节点最多一个子）。掌握图就掌握了最一般的关系表示。

## 概念讲解

### 图的基本概念

<DsvGraphsDiagram />

<Term def="图是由顶点集合和边集合组成的数据结构，表示多对多的关系">
图
</Term>

- **有向图**：边有方向（A→B 不等于 B→A），如微博关注关系。
- **无向图**：边无方向（A-B 等价 B-A），如微信好友关系。
- **带权图**：边上有权值（距离、成本等），如地图导航。
- **度**：与顶点相连的边数。有向图分入度和出度。

### 图的存储

**邻接矩阵**：用 $n \times n$ 二维数组，`matrix[i][j] = 1`（或权值）表示顶点 $i$ 到 $j$ 有边。查边 $O(1)$，但空间 $O(n^2)$，适合稠密图。

**邻接表**：每个顶点维护一个链表（或动态数组），存储它的所有邻居。空间 $O(V+E)$，适合稀疏图（大多数实际场景）。遍历邻居高效。

### 图的遍历

<Stepper>
<Step title="BFS 广度优先搜索">
从起点出发，先访问所有直接邻居（第一层），再访问邻居的邻居（第二层），逐层扩展。用队列实现：出队一个节点，把未访问的邻居入队。BFS 天然能找无权图的最短路径。
</Step>
<Step title="DFS 深度优先搜索">
从起点出发，沿一条路走到底（无路可走或已访问），再回溯换路。用递归或栈实现。DFS 适合连通性判断、拓扑排序、环检测。DFS 的访问顺序像走迷宫——一条路走到黑再回头。
</Step>
<Step title="BFS vs DFS 对比">
BFS 用队列（FIFO），逐层扩展，空间 $O(V)$，适合找最短路径。DFS 用栈/递归（LIFO），深入到底再回溯，空间 $O(\text{深度})$，适合连通性与拓扑。两者时间都是 $O(V+E)$。
</Step>
</Stepper>

## 代码对照

```python
from collections import deque

# 邻接表表示图
graph = {
    'A': ['B', 'C'],
    'B': ['A', 'D', 'E'],
    'C': ['A', 'F'],
    'D': ['B'],
    'E': ['B', 'F'],
    'F': ['C', 'E'],
}

# BFS 广度优先搜索（用队列）
def bfs(graph, start):
    visited = set()
    queue = deque([start])
    visited.add(start)
    result = []
    while queue:
        node = queue.popleft()      # 出队
        result.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)  # 未访问邻居入队
    return result
# bfs(graph, 'A') → ['A', 'B', 'C', 'D', 'E', 'F']

# DFS 深度优先搜索（用递归）
def dfs(graph, node, visited=None, result=None):
    if visited is None:
        visited = set()
    if result is None:
        result = []
    visited.add(node)
    result.append(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited, result)  # 递归深入
    return result
# dfs(graph, 'A') → ['A', 'B', 'D', 'E', 'F', 'C']
```

## 常见误区

<Callout type="trap">
**误区：BFS 和 DFS 都能找最短路径。**
只有 BFS 能找**无权图**的最短路径（因为逐层扩展，第一次到达目标就是最短）。DFS 不保证最短——它一条路走到黑，可能绕远路。带权图的最短路径需要 Dijkstra 或 Bellman-Ford 算法。
</Callout>

<Callout type="trap">
**误区：邻接矩阵一定比邻接表差。**
邻接矩阵空间 $O(n^2)$ 但查边 $O(1)$，适合**稠密图**（边数接近 $n^2$）。邻接表空间 $O(V+E)$ 但查边需遍历邻居链表。如果图很稠密且需要频繁判断两点是否相邻（如社交网络的好友检测），邻接矩阵可能更合适。
</Callout>

<Exercises>
**问题 1**：BFS 和 DFS 分别用什么数据结构实现？时间复杂度各是多少？

<Answer>
BFS 用队列（FIFO）实现：出队一个节点，未访问邻居入队。DFS 用栈或递归（LIFO）实现：深入到底再回溯。两者时间复杂度都是 $O(V+E)$（每个顶点和每条边各访问一次），BFS 空间 $O(V)$，DFS 空间 $O(\text{树高})$。
</Answer>

**问题 2**：什么场景用邻接矩阵，什么场景用邻接表？

<Answer>
邻接矩阵适合稠密图（边数接近 $n^2$）和需要频繁判断两点是否相邻的场景，查边 $O(1)$ 但空间 $O(n^2)$。邻接表适合稀疏图（边数远小于 $n^2$，即大多数实际场景），空间 $O(V+E)$ 更省，遍历邻居高效。大多数图算法用邻接表。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="图">
由顶点集合和边集合组成的数据结构，表示多对多关系。是有向图或无向图，可带权值。
</GlossaryItem>
<GlossaryItem term="邻接矩阵">
用 n×n 二维数组存储图的边关系，matrix[i][j] 表示顶点 i 到 j 是否有边。查边 O(1)，空间 O(n²)，适合稠密图。
</GlossaryItem>
<GlossaryItem term="邻接表">
每个顶点维护一个链表存储其所有邻居。空间 O(V+E)，适合稀密图。是图最常用的存储方式。
</GlossaryItem>
<GlossaryItem term="BFS">
广度优先搜索，用队列实现，逐层扩展。适合无权图最短路径、层序遍历。时间 O(V+E)。
</GlossaryItem>
</Glossary>
