## 为什么总复习从失效契约开始

学完第9章后，最有价值的能力不是背出“快排平均`O(n log n)`”，而是看到现象就知道哪一层契约失效：链表节点丢失先查表示不变量；循环队列误判空满先查状态转移；Dijkstra在负边图上给出错误答案先查算法前提；散列查找突然变慢先查key分布和成本模型。官方目录保证知识覆盖，失效契约把九章转化为诊断索引。

先预测四个综合问题：删除任务时怎样同时维护记录、ID索引、优先队列和依赖图；拓扑排序为何能报告环却不能告诉你任意图的最短路；标题搜索用KMP后为什么整体请求仍可能被线性扫描拖慢；稳定排序怎样保持同优先级任务的创建顺序。答案都需要跨章，不存在一个“万能结构”。

要求先收集最小证据，再决定回到哪一章，而不是凭算法名称猜测。

## 九章收敛为四组能力


### 第1-2章：把问题变成可验收契约

第1章要求区分逻辑关系、物理表示和ADT；第2章要求算法有明确输入输出、终止、正确性和成本。复习时把每个操作写成四项：前置条件、状态转移、后置条件、失败保证。例如`list_insert(list, index, value)`必须定义`index == size`是否合法、分配失败时原表是否不变、成功后size和可达节点数如何变化。

```c
typedef enum {
    DS_OK,
    DS_NOT_FOUND,
    DS_INVALID,
    DS_NO_MEMORY
} DsStatus;

typedef struct {
    size_t comparisons;
    size_t moves;
    size_t allocations;
} CostCounters;
```

公开状态不能用一个模糊的`false`同时表达未找到、输入非法和内存不足；成本计数器也应与结果分离。是后面结构和算法共享的验收格式。

### 第3-5章：线性状态、访问纪律与模式复用

线性表复盘重点是顺序/链式表示如何改变访问、插删、cache与owner。栈和队列复盘重点是受限操作端以及空满边界；递归问题要能展开为显式栈帧。串复盘重点是长度、容量、终止符，以及朴素匹配与KMP如何处理重叠前后缀。三章共同训练“位置”语义：数组索引、链表前驱、栈顶、队头和模式下标不能混用。

统一测试可使用状态机：模型端用简单动态数组保存逻辑序列，被测端使用目标结构；随机生成插入、删除、push/pop、enqueue/dequeue或匹配操作，每步比较状态和结果。模型慢没有关系，因为它是小规模oracle。出现差异时保存最短操作序列，能比最终内存崩溃更早定位不变量破坏。

### 第6-7章：层次、网络和遍历状态

树把一对多关系组织为根、子树和路径；图允许多对多、方向和权。二叉树遍历、线索化、树/森林转换和赫夫曼编码依赖节点/链接不变量；图的DFS/BFS、MST、最短路径、拓扑和关键路径还依赖连通性、权值与有环性。复习时不要只画最终序列，要画frontier、visited、parent、distance或indegree如何变化。

```c
bool relax(int distance[], size_t from, size_t to, int weight) {
    if (distance[from] == INT_MAX) return false;
    if (weight < 0) return false;
    if (distance[from] <= INT_MAX - weight
        && distance[from] + weight < distance[to]) {
        distance[to] = distance[from] + weight;
        return true;
    }
    return false;
}
```

这段松弛操作显式拒绝负边并防整数溢出，只适合作为非负权最短路的一部分。若业务允许负边，应更换算法并检测负环，不能删掉检查继续运行。决定了“代码能运行”和“结果有意义”的边界。

### 第8-9章：组织信息与重排记录

查找章从静态表走到动态树和散列；排序章从平方级简单方法走到希尔、堆、归并、快速和外排序。两章共同回答“是否预先组织数据”：维护有序、树或散列会增加构建/更新成本，却加速后续查询；排序也可能是为二分、归并连接或稳定报告建立前提。整体成本必须包含数据生命周期，不能只计一次查询。

测试查找要区分found/not found、重复key策略和结构退化；测试排序要验证sorted、permutation和承诺的stable。BST高度、AVL平衡因子、B树节点容量、散列表负载/探测长度、排序比较/移动/空间都应成为可观察指标。结果正确但指标超界，仍说明结构选择或实现存在问题。


## 从需求反推结构，而不是从结构寻找用途


比“数据很多”更有用。例如读写比1000:1且需要范围查询，维护有序树可能合理；写多且只做精确查找，散列更直接；频繁取最值但无需范围，堆比完整有序结构便宜。

多个结构组合时要避免把一次更新变成不可恢复的半状态。可选择单一主记录存储，其余索引只保存稳定ID；更新先验证候选变更，按确定顺序修改，并在失败时回滚或重建派生索引。每个查询还要处理陈旧ID和删除标记。结构组合提升某些操作，却引入一致性成本，这一成本必须写入选择记录。

### 四类故障模型

**表示失配**包括数组容量与逻辑长度混淆、链断裂、树出现共享子节点、无向边只存一侧。最小证据是节点/索引/边与owner图，对应第1、3、6、7章。

**状态转移失配**包括栈顶或队头更新顺序错误、KMP下标回退错误、遍历重复入队、删除后索引未同步。最小证据是操作前后快照和局部不变量，对应第3-7章。

**算法前提失配**包括无序数据做二分、负边使用Dijkstra、有环图要求拓扑序、比较器不传递。最小证据是输入性质与算法声明的对照，对应第2、5、7-9章。

**成本模型失配**包括链表随机访问、倾斜BST、散列聚簇、快排坏pivot和超内存内排序。最小证据是规模曲线、结构指标、比较/移动/探测和I/O计数，对应第2、3、6、8、9章。


## Capstone：依赖感知任务索引

综合项目管理任务`{id,title,priority,duration,created_order}`及依赖边。动态数组或链表保存主记录；散列或平衡树按ID定位；堆提供最高优先级候选；邻接表保存依赖；拓扑排序验证可执行性，关键路径估算总工期；KMP搜索标题；报告按优先级、工期或创建顺序稳定排序。当数据超过内存时，报告改用有序run和多路归并。

```c
typedef struct {
    unsigned id;
    char title[96];
    int priority;
    int duration;
    size_t created_order;
} Task;

bool same_task(const Task *left, const Task *right) {
    return left->id == right->id
        && strcmp(left->title, right->title) == 0
        && left->priority == right->priority
        && left->duration == right->duration
        && left->created_order == right->created_order;
}
```

主记录是事实来源，索引、堆和图只引用ID。导入先在candidate结构中验证唯一ID、标题终止、非负工期、合法端点和无环要求；全部结构通过后才替换live版本。更新失败时live不变，派生结构可从主记录与边集确定性重建。把分配失败和部分更新纳入设计。


### Capstone正确性与性能证据

正确性先于性能。每次构建验证主记录数、ID唯一、索引可达、堆序、所有边端点存在、拓扑处理数、查询结果ID集合和排序稳定性。小规模使用朴素线性扫描、全路径枚举或标准库排序作oracle；随机操作后逐项比较。发现差异时缩减到最短记录/边/操作序列。

性能实验使用几何规模，分别改变读写比、图稀疏度、key分布、标题长度、重复率与初始有序度。记录比较、探测、移动、分配、队列峰值、图访问边数、排序buffer和块I/O，再结合wall time。若散列p99探测暴涨，可改hash/扩容或换树；若报告排序超内存，改外排序；若拓扑扫描重复遍历全部边，回查邻接表示。

故障恢复覆盖candidate任意分配点失败、更新中途取消、磁盘run损坏和验证失败。通过标准是错误分类明确、live查询结果不变、临时资源释放、重试不产生重复记录，并能从主事实重建派生索引。一次成功演示无法证明这些性质。

## 终局验收清单

1. 能为任意结构写出逻辑关系、物理表示、ADT操作与表示不变量。
2. 能证明算法终止和正确，推导最好/最坏时间、额外空间及真实成本指标。
3. 能实现并验证线性表、栈/队列、串匹配、树遍历与图遍历的核心操作。
4. 能说明MST、最短路、拓扑、关键路径、动态查找和七类排序的适用前提。
5. 能按工作负载选择单一或组合结构，并处理owner、一致性、失败和重建。
6. 能让查找与排序通过结果oracle、结构不变量、退化输入和规模曲线。
7. 能完成任务索引的candidate构建、查询、综合报告、故障恢复与决策记录。

## 本章回顾：九章最终收敛为可证明选择

1. 数据结构绪论与算法章给出表示语言、正确性和成本工具。
2. 线性表、栈队列与串训练位置、访问纪律、状态转移和模式复用。
3. 树与图训练层次、网络、遍历frontier以及算法前提。
4. 查找与排序训练通过预组织、索引与重排换取查询性能。
5. 表示失配、状态转移失配、算法前提失配和成本模型失配构成统一故障索引。
6. Capstone以建模、构建、查询、退化、失败、恢复和规模增长完成整书验收。
