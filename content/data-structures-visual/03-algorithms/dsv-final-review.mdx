## 直觉引入

学完整本书，我们走过了从数组到图、从顺序查找到哈希查找的完整旅程。现在把所有知识串成一张网：数据结构是「数据的书架」，算法是「操作数据的步骤」，两者共同决定了程序的效率。

全书的核心线索只有一句话：**没有最好的数据结构，只有最适合场景的数据结构**。复习的关键不是背定义，而是理解每种结构「擅长什么、不擅长什么」，在什么场景下选择它。

## 全书知识网络

<DsvFinalReviewDiagram />

全书知识点通过三条主线串联：

### 主线一：存储方式的演进

<Stepper>
<Step title="线性存储（数组 vs 链表）">
数组的连续存储带来 $O(1)$ 随机访问但 $O(n)$ 插入删除；链表的链式存储带来 $O(1)$ 插入删除但 $O(n)$ 访问。这是所有数据结构的根基——后续的栈、队列、树、图都基于这两种存储方式或其变体。
</Step>
<Step title="树形结构（BST → 堆）">
BST 用「左小右大」规则把线性查找 $O(n)$ 降到 $O(\log n)$，但可能退化为链。堆用「完全二叉树+堆序性」实现 $O(1)$ 取最值 + $O(\log n)$ 插入删除，是优先队列的最优实现。
</Step>
<Step title="图结构（BFS/DFS）">
图是最通用的结构，多对多关系。BFS 用队列逐层扩展找最短路径，DFS 用栈/递归深入回溯做连通性判断。两者时间都是 $O(V+E)$。
</Step>
</Stepper>

### 主线二：查找效率的跃迁

$O(n)$ 顺序查找 → $O(\log n)$ 二分查找/BST → $O(1)$ 哈希查找。每次跃迁都伴随前提条件的增加：二分要有序，哈希要额外空间。效率与灵活性不可兼得。

### 主线三：排序与结构的关系

排序算法本身依赖数据结构：快排依赖数组的随机访问做原地划分，归并依赖额外空间合并有序序列，堆排依赖堆的完全二叉树性质。选对结构，排序算法才能高效运行。

## 代码对照

```python
# 综合案例：设计一个学生成绩管理系统
# 需求：频繁按学号查找、偶尔按成绩排序、频繁取最高分

import heapq

class GradeSystem:
    def __init__(self):
        # 按学号查找 → 哈希表 O(1)
        self.by_id = {}
        # 取最高分 → 最大堆 O(1) peek
        self.max_heap = []  # 存 (-score, id) 模拟大顶堆

    def add(self, student_id, score):
        """添加学生：哈希表 O(1) + 堆 O(log n)"""
        self.by_id[student_id] = score
        heapq.heappush(self.max_heap, (-score, student_id))

    def find(self, student_id):
        """按学号查找：哈希表 O(1)"""
        return self.by_id.get(student_id, -1)

    def top_score(self):
        """取最高分：堆顶 O(1)"""
        if not self.max_heap:
            return None
        return (-self.max_heap[0][0], self.max_heap[0][1])

    def rank_by_score(self):
        """按成绩排序：O(n log n)"""
        return sorted(self.by_id.items(), key=lambda x: -x[1])

# 数据结构选择的决策过程：
# 1. 按学号查找高频 → 哈希表（O(1) 查找）
# 2. 取最高分高频 → 最大堆（O(1) peek）
# 3. 排序偶尔 → 不维护有序，需要时再排（O(n log n)）
# 这就是「根据操作频率选结构」的实战
```

## 常见误区

<Callout type="trap">
**误区：学了一堆结构，遇到问题还是只会用数组。**
这是因为只背了定义，没建立「操作频率 → 结构选择」的决策框架。面对问题时，先分析：哪些操作是高频的？查找、插入、删除、取最值？然后选最擅长该操作的结构。高频查找用哈希，高频取最值用堆，需要有序用 BST。
</Callout>

<Callout type="trap">
**误区：忽视数据结构的退化问题。**
BST 退化为链、哈希表冲突退化为 $O(n)$、快排最坏 $O(n^2)$。选择结构时不仅看平均复杂度，还要看最坏情况和触发条件。需要保证时选平衡树、开放寻址哈希、introsort。
</Callout>

<Exercises>
**问题 1**：设计一个系统，需要频繁插入数据、频繁查找最大值、偶尔按值范围查询。应该用哪些数据结构？

<Answer>
组合使用：①最大堆支持频繁插入 $O(\log n)$ + 查找最大值 $O(1)$；②对于范围查询，可以定期把堆数据导出排序后二分查找，或维护一个平衡 BST（如红黑树）支持 $O(\log n)$ 范围查询。如果范围查询频率不高，用堆+按需排序更简单；如果范围查询也频繁，用平衡 BST 统一处理插入、最值和范围查询。
</Answer>

**问题 2**：全书查找效率从 $O(n)$ 到 $O(1)$ 的三次跃迁分别是什么？各需要什么前提？

<Answer>
①顺序查找 $O(n)$ → 二分查找 $O(\log n)$：前提是数据有序且支持随机访问。②二分查找 $O(\log n)$ → BST $O(\log n)$：BST 的优势不在查找效率（与二分同级），而在于动态维护有序（插入删除 $O(\log n)$ vs 数组插入 $O(n)$）。③$O(\log n)$ → 哈希表 $O(1)$：前提是额外空间建哈希表，且不需要范围查询和有序遍历。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="数据结构选择决策">
根据操作频率与场景选择数据结构：高频查找用哈希表，高频取最值用堆，需要有序用 BST，需要先进先出用队列，需要后进先出用栈。
</GlossaryItem>
<GlossaryItem term="时间-空间权衡">
用额外空间换时间效率的通用原则。如哈希表用 O(n) 空间换 O(1) 查找，归并排序用 O(n) 空间换稳定 O(n log n)。
</GlossaryItem>
<GlossaryItem term="结构退化">
数据结构在特定操作序列下失去效率保证的现象。BST 退化为链、哈希表冲突严重、快排最坏情况都是退化。需通过平衡机制或合理设计避免。
</GlossaryItem>
<GlossaryItem term="操作频率分析">
选择数据结构的核心方法：统计各操作（查找、插入、删除、最值等）的频率，选择最擅长高频操作的结构。
</GlossaryItem>
</Glossary>
