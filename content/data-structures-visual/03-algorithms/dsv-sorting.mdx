## 直觉引入

给一副扑克牌排序，你会怎么做？最直觉的方法是：每次找最小的放最前面，再在剩下的里找最小的——这就是选择排序。或者把每张牌插入到已排序部分的正确位置——这就是插入排序。

但如果有 10000 张牌，$O(n^2)$ 的方法要做上亿次比较。更聪明的办法是：把牌分成两半分别排好，再合并两个有序序列——这就是归并排序，只需约 13 万次比较。排序算法的进化，就是把 $O(n^2)$ 压到 $O(n \log n)$。

### 简单排序：$O(n^2)$

<Term def="排序稳定性指相等元素排序后保持原有相对顺序，不影响排序结果但影响多关键字排序">
排序稳定性
</Term>

- **冒泡排序**：相邻元素两两比较，大的往后冒。每轮把最大的冒到最后。稳定，但效率最低。
- **选择排序**：每轮找最小值放到前面。不稳定（交换可能改变相等元素的顺序），但交换次数最少。
- **插入排序**：把每个元素插入到已排序部分的正确位置。稳定，小数据量或近乎有序时实际最快。

### 高效排序：$O(n \log n)$

<Stepper>
<Step title="快速排序（分治）">
选一个基准（pivot），把小于基准的放左边、大于的放右边，然后递归排序左右两部分。平均 $O(n \log n)$，最坏 $O(n^2)$（基准选不好时）。原地排序，缓存友好，实际最快。不稳定。
</Step>
<Step title="归并排序（分治+合并）">
把数组对半分，递归排序两半，然后合并两个有序数组。合并是 $O(n)$，递归深度 $O(\log n)$，总计 $O(n \log n)$。稳定排序，但需 $O(n)$ 额外空间。
</Step>
<Step title="堆排序">
先 $O(n)$ 建大顶堆，然后反复取堆顶（最大值）放末尾。原地排序，最坏也是 $O(n \log n)$，但常数比快排大。不稳定。
</Step>
</Stepper>

### 算法选择

| 场景 | 推荐算法 | 原因 |
|---|---|---|
| 小数据（n&lt;50） | 插入排序 | 常数小，近乎有序时接近 $O(n)$ |
| 通用大数据 | 快速排序 | 平均最快，原地排序 |
| 需要稳定性 | 归并排序 | 稳定且 $O(n \log n)$ |
| 最坏保证 | 堆排序 | 最坏 $O(n \log n)$，原地 |

## 代码对照

```python
# 快速排序：分治 + 原地划分
def quick_sort(arr, lo=0, hi=None):
    if hi is None:
        hi = len(arr) - 1
    if lo >= hi:
        return arr
    # 划分：选 arr[hi] 为基准，小的左大的右
    pivot = arr[hi]
    i = lo  # i 左边都是 < pivot 的
    for j in range(lo, hi):
        if arr[j] < pivot:
            arr[i], arr[j] = arr[j], arr[i]
            i += 1
    arr[i], arr[hi] = arr[hi], arr[i]  # pivot 放到正确位置
    quick_sort(arr, lo, i - 1)   # 递归左半
    quick_sort(arr, i + 1, hi)   # 递归右半
    return arr

# 归并排序：分治 + 合并
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # 递归排序左半
    right = merge_sort(arr[mid:])   # 递归排序右半
    return merge(left, right)       # 合并两个有序数组

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:     # <= 保证稳定性
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# 插入排序：小数据最优
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]  # 后移
            j -= 1
        arr[j + 1] = key  # 插入正确位置
    return arr
```

## 常见误区

<Callout type="trap">
**误区：认为快速排序一定比归并排序快。**
快排平均更快（常数小、缓存友好），但最坏 $O(n^2)$。归并排序始终 $O(n \log n)$ 且稳定。在需要稳定性（如多关键字排序）或最坏情况保证时，归并排序更可靠。
</Callout>

<Callout type="trap">
**误区：认为 $O(n^2)$ 排序没用。**
插入排序在小数据量（$n &lt; 50$）或近乎有序的数据上，实际比快排还快——因为常数极小且无递归开销。很多标准库的 sort 在递归到小子数组时切换为插入排序（如 introsort）。
</Callout>

<Exercises>
**问题 1**：快速排序最坏情况的时间复杂度是多少？什么情况下触发？

<Answer>
最坏 $O(n^2)$。当每次选的 pivot 都是最大或最小值时触发（如数组已排序且总是选最后一个元素做 pivot），划分极度不均，递归深度变成 $n$。解决方法：随机选 pivot、三数取中、或切换到堆排序（introsort）。
</Answer>

**问题 2**：什么是排序的稳定性？为什么重要？

<Answer>
稳定性指相等元素排序后保持原有相对顺序。例如按成绩排序，同分的学生保持原来学号顺序。稳定性在多关键字排序中很重要——先按次要关键字排，再按主要关键字稳定排序，就能得到正确结果。冒泡、插入、归并是稳定的；选择、快排、堆排不稳定。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="快速排序">
分治排序：选基准划分左右两部分，递归排序。平均 O(n log n)，最坏 O(n²)，原地排序，实际最快。不稳定。
</GlossaryItem>
<GlossaryItem term="归并排序">
分治排序：对半分递归排序，再合并两个有序数组。始终 O(n log n)，稳定，但需 O(n) 额外空间。
</GlossaryItem>
<GlossaryItem term="排序稳定性">
相等元素排序后保持原有相对顺序。稳定的排序适合多关键字排序。冒泡、插入、归并稳定；选择、快排、堆排不稳定。
</GlossaryItem>
<GlossaryItem term="分治法">
把问题分解为规模更小的同类子问题，递归求解后合并结果。快排和归并排都基于分治思想。
</GlossaryItem>
</Glossary>
