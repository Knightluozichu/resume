## 两条核心主线

### 主线一：数据建模与查询能力

```
// 从数据怎么组织到数据怎么查的递进路径
// 数据建模
//   └── 关系模型：关系/元组/属性/域
//   └── 键：超码 → 候选码 → 主码 → 外码
//   └── 完整性：实体/参照/用户定义
// 查询语言
//   └── SQL：DDL/DML/DCL
//   └── 关系代数：σ/π/⋈/×/∪/−/ρ
// 数据库设计
//   └── ER模型：实体/属性/联系
//   └── 规范化：1NF → 2NF → 3NF → BCNF
// 查询处理
//   └── 解析 → 翻译 → 优化 → 执行
//
// 核心：怎么组织 → 怎么描述 → 怎么设计 → 怎么取
```

### 主线二：系统可靠性与实现能力

```
// 从数据怎么存到数据怎么不出错的递进路径
// 存储层
//   └── 文件 → 页 → 记录
//   └── 索引：B+树/哈希/位图/聚簇
// 事务层
//   └── ACID 四特性
//   └── 隔离级别：读未提交 → 可串行化
// 并发层
//   └── 封锁 2PL / MVCC / 乐观 OCC
//   └── 死锁：预防/检测/回滚
// 恢复层
//   └── 日志 WAL / 检查点
//   └── ARIES：分析 → REDO → UNDO
//
// 核心：怎么存 → 怎么并发 → 怎么恢复
```

<Callout type="info" title="核心认知">
全书两条主线在「查询处理+事务」与「存储+并发恢复」处交汇——查询优化要考虑存储代价，事务的隔离性依赖并发控制，恢复系统要保证事务的原子性和持久性。理解这些交汇点，才能从"会用数据库"升级到"理解数据库系统"。
</Callout>

</GlossaryItem>

**问题 1**：全书分为哪几个篇章？各自的核心内容和递进逻辑是什么？

<Answer>
全书分四个篇章：基础篇——学习地图（知识体系）、关系模型（关系/元组/属性/域/键/完整性约束）；SQL与设计篇——SQL与关系代数（DDL/DML/DCL/关系代数运算）、数据库设计与ER模型（ER模型/函数依赖/范式）；系统实现篇——存储与索引（文件/页/B+树/哈希）、查询处理与优化（解析/优化/执行计划）；事务与恢复篇——事务管理（ACID/状态机/隔离级别）、并发控制（2PL/MVCC/OCC/死锁）、恢复系统（日志/检查点/ARIES）。递进逻辑：从会建模到会查询到会实现到会保障。
</Answer>

**问题 2**：贯穿全书的两条核心主线是什么？它们在哪些章节交汇？

<Answer>
主线一数据建模与查询能力：关系模型 → SQL → 关系代数 → ER设计 → 规范化 → 查询处理优化，解决"数据怎么组织、怎么查"。主线二系统可靠性与实现能力：存储索引 → 事务 → 并发控制 → 恢复系统，解决"数据怎么存、怎么不出错"。两条主线在"查询处理+事务"（查询优化考虑存储代价，事务隔离依赖并发控制）与"存储+并发恢复"（并发控制基于存储的锁表，恢复系统操作存储的日志）处交汇。
</Answer>

**问题 3**：为什么学习数据库要遵循"会建模→会查询→会实现→会保障"的顺序？

<Answer>
顺序依据：会建模——理解关系模型和完整性约束，建立数据组织认知；会查询——掌握SQL和关系代数，理解数据如何描述和操作；会实现——理解存储索引和查询处理，知道数据库如何高效工作；会保障——掌握事务并发恢复，保证数据正确与可靠。跳过基础的风险：①不理解关系模型，无法正确设计表结构；②不掌握SQL，无法操作数据；③不理解存储，无法优化性能；④不理解事务，无法保证数据一致性。每一步都是下一步的前提。
</Answer>

**问题 4**：数据库系统的四个要素是什么？它们如何构成一个完整系统？

<Answer>
四要素：①数据模型——定义数据结构（关系模型：关系/元组/属性/域），回答"数据长什么样"；②查询语言——定义数据操作（SQL和关系代数），回答"怎么操作数据"；③系统实现——决定性能（存储结构/索引/查询处理优化），回答"怎么高效执行"；④可靠性保障——保证正确与持久（事务ACID/并发控制/恢复系统），回答"怎么不出错"。四要素层层支撑：模型定义结构，语言操作结构，实现加速操作，保障维护正确性。
</Answer>
