## 关系模型核心概念

<DscRelationalModelDiagram />

关系模型由 E.F.Codd 提出，用单一的"关系"（二维表）来组织数据。它是 SQL 和整个关系数据库的理论基础——理解关系模型，才能理解 SQL 为什么这样设计。

## 关系的结构

```
// 关系 student = 表
// ┌──────────┬──────────┬───────────┐
// │ ID (主码)│ name     │ dept_id   │  ← 属性 Attribute（列）
// ├──────────┼──────────┼───────────┤
// │ 001      │ 张三     │ D01       │  ← 元组 Tuple（行）
// │ 002      │ 李四     │ D02       │
// └──────────┴──────────┴───────────┘
//   ↑ 域 Domain：每列的合法取值集合（原子值）
```

| 术语 | 通俗说法 | 含义 |
|------|----------|------|
| 关系 Relation | 表 | 元组的集合 |
| 元组 Tuple | 行 | 一条记录 |
| 属性 Attribute | 列 | 数据的一个特征 |
| 域 Domain | 取值范围 | 属性所有合法值的集合 |
| 关系模式 Schema | 表头 | 关系名+属性集合，如 `student(ID, name, dept_id)` |
| 关系实例 Instance | 数据 | 某一时刻关系中的实际元组 |

<Callout type="warning" title="关系是集合">
关系（表）在数学上是元组的集合，因此有两条重要性质：①元组无顺序（行的先后不影响语义）；②元组不重复（集合无重复元素）。此外属性取值必须是原子的（不可再分），这即第一范式 1NF。
</Callout>

## 键的层级

```
// 键层层缩小：从「能唯一标识」到「最精简」
// 超码 Superkey
//   └── {ID, name} 能唯一标识元组，但 name 多余
// 候选码 Candidate Key
//   └── {ID} 最小超码，去掉任何列就不唯一
// 主码 Primary Key
//   └── 从候选码中选定一个作为主标识
// 外码 Foreign Key
//   └── student.dept_id 引用 department.id
//       建立表与表之间的联系
```

- **超码**：能唯一标识元组的属性集合（可含多余列）
- **候选码**：最小的超码（去掉任何一列就不再唯一）
- **主码**：选定的一个候选码，作为元组的主标识
- **外码**：一个关系中的属性，引用另一个关系的主码，建立表间联系

<Callout type="info" title="主码选择原则">
当一个关系有多个候选码时，选值最稳定、最简短、最不可能为空的作为主码。例如学生表中 `{学号}` 和 `{身份证号}` 都能唯一标识，通常选学号作主码。
</Callout>

## 三类完整性约束

完整性约束保证数据的正确性和一致性：

| 约束类型 | 规则 | 目的 | SQL 实现 |
|----------|------|------|----------|
| 实体完整性 | 主码不能取空值，且唯一 | 保证每个元组可被唯一标识 | `PRIMARY KEY` |
| 参照完整性 | 外码值必须匹配被引用表的主码，或为 NULL | 保证表间引用不悬空 | `FOREIGN KEY ... REFERENCES` |
| 用户定义完整性 | 满足具体业务规则（域约束） | 保证列值符合业务语义 | `NOT NULL / UNIQUE / CHECK / DEFAULT` |

```
-- 实体完整性：主码非空且唯一
CREATE TABLE student (
  ID          VARCHAR(10) PRIMARY KEY,   -- 主码
  name        VARCHAR(50) NOT NULL,       -- 用户定义：非空
  age         INT CHECK (age > 0),         -- 用户定义：域约束
  dept_id     VARCHAR(10),
  FOREIGN KEY (dept_id) REFERENCES department(id)  -- 参照完整性
);
```

<Callout type="warning" title="外码的 NULL 语义">
参照完整性允许外码为 NULL——表示"尚未关联"。例如新员工还没分配部门，`dept_id` 可为 NULL，这不违反参照完整性。但主码绝不能为 NULL（实体完整性）。
</Callout>

## 关系模型三要素

```
// 关系模型 = 数据结构 + 数据操作 + 完整性约束
// 数据结构：关系（二维表）
// 数据操作：关系代数 / SQL（增删改查）
// 完整性约束：实体 / 参照 / 用户定义
```

关系模型的强大在于：用单一的"关系"结构表达所有数据，用关系代数提供完备的操作能力，用完整性约束保证正确性。SQL 正是关系模型的具体实现。

<Glossary>

<GlossaryItem term="关系与关系模式">
关系模式（Schema）是关系的"类型"——描述关系名、属性、域、键和约束，是静态稳定的结构定义，如 `student(ID, name, dept_id)`。关系实例（Instance）是关系在某一时刻的"值"——实际存储的元组集合，随增删改动态变化。类比：模式是类，实例是对象。
</GlossaryItem>

<GlossaryItem term="超码→候选码→主码">
超码是能唯一标识元组的属性集合（可含多余列）；候选码是最小的超码（去掉任何列就不唯一）；主码是从候选码中选定一个作为主标识。层级关系是包含关系：所有主码都是候选码，所有候选码都是超码。外码则跨关系，引用另一关系的主码建立联系。
</GlossaryItem>

<GlossaryItem term="三类完整性约束">
实体完整性：主码不能取空值且唯一，保证每个元组可唯一标识。参照完整性：外码值必须匹配被引用关系的主码或为 NULL，保证表间引用关系不悬空。用户定义完整性（域完整性）：属性值满足业务规则（NOT NULL/UNIQUE/CHECK/DEFAULT），保证数据符合语义。
</GlossaryItem>

<GlossaryItem term="第一范式 1NF">
关系模型要求每个属性的取值必须是原子的（不可再分），这即第一范式。例如"电话"列不能存一个集合 `{138xxx, 139xxx}`，而应拆成多行或单独表。1NF 是关系模型的基本要求，也是后续规范化的起点。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：解释关系、元组、属性、域四个概念及其对应关系。

<Answer>
关系（Relation）是元组的集合，通俗说就是一张表。元组（Tuple）是关系中的一行，即一条记录。属性（Attribute）是关系中的一列，描述数据的一个特征。域（Domain）是某属性所有合法取值的集合，即该列的取值范围。对应关系：关系=表，元组=行，属性=列，域=列的取值范围。例如关系 `student(ID, name, age)`，`{001, 张三, 20}` 是一个元组，ID/name/age 是属性，age 的域可以是正整数集合。
</Answer>

**问题 2**：超码、候选码、主码、外码有什么区别和联系？

<Answer>
超码（Superkey）是能唯一标识元组的属性集合，可包含多余列，如 `{ID, name}`。候选码（Candidate Key）是最小的超码，去掉任何一列就不再唯一，如 `{ID}`。主码（Primary Key）是从多个候选码中选定一个作为主标识。外码（Foreign Key）是一个关系中的属性，引用另一关系的主码，建立表间联系。联系：所有主码都是候选码，所有候选码都是超码；主码用于表内标识，外码用于表间关联。例如 student.dept_id 是外码，引用 department.id（主码）。
</Answer>

**问题 3**：三类完整性约束分别是什么？各举一个 SQL 实现的例子。

<Answer>
①实体完整性：主码不能取空值且唯一，保证每个元组可唯一标识。SQL：`ID VARCHAR(10) PRIMARY KEY`。②参照完整性：外码值必须匹配被引用关系的主码或为 NULL，保证表间引用不悬空。SQL：`FOREIGN KEY (dept_id) REFERENCES department(id)`。③用户定义完整性（域完整性）：属性值满足业务规则。SQL：`age INT CHECK (age > 0)` 或 `name VARCHAR(50) NOT NULL`。三者共同保证数据的正确性和一致性。
</Answer>

**问题 4**：为什么主码不能为空，而外码可以为空？这体现了什么完整性约束？

<Answer>
主码不能为空是实体完整性的要求——主码用于唯一标识每个元组，若为空就无法区分和标识元组，违反"每个元组可被唯一标识"的原则。外码可以为空是参照完整性的允许——外码为 NULL 表示"尚未关联"，例如新员工还没分配部门时 `dept_id` 为 NULL，这不违反参照完整性（参照完整性只要求外码非空时必须匹配被引用主码）。这体现了：实体完整性针对表内主标识的严格性，参照完整性针对表间引用的灵活性。
</Answer>

</Exercises>
