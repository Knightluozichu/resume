## 存储与索引结构

<DscStorageIndexingDiagram />

数据库的存储层决定了数据"怎么存"，索引层决定了数据"怎么找"。理解存储层次和索引结构，才能理解查询为什么快或慢，才能做出正确的索引设计。

## 存储层次

```
// 物理存储的三级结构
// 文件 File（逻辑单元）
//   └── 页 Page / Block（磁盘 IO 的最小单位）
//        └── 记录 Record / Tuple（一行数据）
```

| 层级 | 含义 | 说明 |
|------|------|------|
| 文件 | 逻辑存储单元 | 一个表对应一个或多个文件 |
| 页/块 | 磁盘 IO 单位 | 典型 4KB-16KB，读写以页为单位 |
| 记录 | 一行数据 | 定长或变长，存在页内 |

<Callout type="info" title="为什么以页为单位">
磁盘 IO 的代价远高于内存访问（约 10 万倍）。以页为单位批量读写，可以摊薄寻道开销。缓冲区管理器把"热页"缓存在内存，命中则免 IO。因此数据库性能优化的核心是"减少页 IO 次数"。
</Callout>

### 文件组织方式

```
// 四种文件组织
// 堆文件 Heap：记录无序，新行追加到末尾
// 顺序文件 Sequential：按搜索码物理排序
// 散列文件 Hash：按散列函数分布到桶
// 聚簇文件 Clustered：相关记录聚簇存储（按主码或聚簇键）
```

## B+ 树索引

B+ 树是数据库最常用的索引结构：

```
// B+ 树结构
//         [根节点]          ← 内部节点：只存键 + 指针（导航）
//        /    |    \
//   [内部] [内部] [内部]
//    /|\    /|\    /|\
// [叶]→[叶]→[叶]→[叶]     ← 叶子节点：存数据/指针，链表相连
//
// 特点：
//   1. 矮胖平衡：树高通常 3-4 层即可存上亿记录
//   2. 所有数据在叶子：内部节点只做导航
//   3. 叶子链表相连：支持高效范围查询
//   4. 查找代价 O(log n)：每次定位一层
```

| 特性 | B+ 树 | 说明 |
|------|-------|------|
| 查找复杂度 | `O(log n)` | 树高很低，3-4 层即可存亿级数据 |
| 范围查询 | 高效 | 叶子链表顺序扫描 |
| 点查询 | 高效 | 从根到叶定位 |
| 有序性 | 保持 | 键有序存储 |
| 适用 | 最通用 | 点查询+范围查询都支持 |

<Callout type="warning" title="B+树 vs B树">
B 树内部节点也存数据，B+ 树只有叶子存数据。B+ 树的优势：①内部节点不存数据→能存更多键→树更矮→IO 更少；②叶子链表相连→范围查询高效。所以数据库索引几乎都用 B+ 树。
</Callout>

## 索引类型对比

| 索引类型 | 支持查询 | 有序 | 适用场景 |
|----------|----------|------|----------|
| B+ 树 | 点查询+范围查询 | 是 | 最通用，高选择性列 |
| 哈希索引 | 仅点查询 `O(1)` | 否 | 等值查询，不支持范围 |
| 位图索引 | 点查询+聚合 | 否 | 低基数列（性别/状态） |
| 聚簇索引 | 点查询+范围查询 | 是 | 数据按索引键物理排序 |

```
// 聚簇索引 vs 非聚簇索引
// 聚簇索引：数据行按索引键物理排序存储，一表只能一个
//   └── 叶子节点直接存整行数据
// 非聚簇索引（二级索引）：数据行不按此键排序
//   └── 叶子节点存主码，需"回表"取整行
//
// 覆盖索引：索引包含查询所需所有列，免回表
//   └── SELECT 的列都在索引里 → 直接返回
```

<Callout type="info" title="索引选择原则">
①高选择性列（不同值多）适合建 B+ 树索引；②低基数列（如性别只有两值）适合位图索引；③等值查询为主可考虑哈希索引；④频繁范围查询用 B+ 树或聚簇索引；⑤一表只有一个聚簇索引（通常主码），其余是非聚簇。
</Callout>

## 稠密索引与稀疏索引

```
// 稠密索引 Dense：每条记录都有索引项
//   └── 查找快，但索引大
// 稀疏索引 Sparse：只有每页的第一条记录有索引项
//   └── 索引小，但需求数据有序，查找时先定位页再页内扫描
//
// 稀疏索引要求记录按搜索码有序（顺序文件）
```

## 缓冲区管理

```
// 缓冲区管理器 Buffer Manager
//   磁盘页按需读入内存缓冲区
//   命中 → 直接用，免 IO
//   未命中 → 读盘，可能淘汰脏页（写回磁盘）
//
// 替换策略：
//   LRU（最近最少使用）→ 通用默认
//   MRU（最近最常使用）→ 顺序扫描场景
//   Clock → LRU 的近似，开销低
```

<Glossary>

<GlossaryItem term="存储层次">
数据库物理存储分三级：文件（逻辑存储单元，一表对应一或多个文件）、页/块（磁盘 IO 最小单位，典型 4-16KB）、记录（一行数据，定长或变长）。读写以页为单位以摊薄寻道开销，缓冲区管理器把热页缓存内存，命中免 IO。性能优化核心是减少页 IO 次数。
</GlossaryItem>

<GlossaryItem term="B+树索引">
B+ 树是数据库最常用的索引结构。特点：矮胖平衡（3-4 层存亿级数据）；所有数据在叶子节点，内部节点只存键+指针做导航；叶子节点链表相连支持高效范围查询；查找代价 O(log n)。相比 B 树，B+ 树内部节点不存数据能容纳更多键、树更矮、IO 更少，且叶子链表支持范围扫描，故数据库索引几乎都用 B+ 树。
</GlossaryItem>

<GlossaryItem term="聚簇索引与非聚簇索引">
聚簇索引：数据行按索引键物理排序存储，叶子节点直接存整行数据，一表只能有一个（通常主码）。非聚簇索引（二级索引）：数据行不按此键排序，叶子节点存主码，查询需"回表"取整行。覆盖索引是特殊的非聚簇索引——索引包含查询所需所有列，免回表直接返回。
</GlossaryItem>

<GlossaryItem term="索引类型选择">
B+ 树：最通用，支持点查询+范围查询，有序，适合高选择性列。哈希索引：仅点查询 O(1)，无序，不支持范围。位图索引：适合低基数列（性别/状态），压缩存储。聚簇索引：数据按键物理排序，一表一个。选择原则：高选择性列建 B+ 树；低基数列用位图；等值查询用哈希；范围查询用 B+ 树或聚簇。
</GlossaryItem>

<GlossaryItem term="稠密索引与稀疏索引">
稠密索引：每条记录都有索引项，查找快但索引大。稀疏索引：只有每页第一条记录有索引项，索引小但要求记录按搜索码有序，查找时先定位页再页内扫描。稀疏索引因索引小、IO 少，常与顺序文件配合用于主码索引。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：为什么数据库以页（块）为单位进行 IO？缓冲区管理器起什么作用？

<Answer>
以页为单位 IO 是因为磁盘 IO 代价远高于内存访问（约 10 万倍），以页（典型 4-16KB）批量读写可摊薄寻道开销——一次寻道读一大块数据比多次读小数据高效得多。缓冲区管理器的作用：把磁盘页按需读入内存缓冲区，查询时若页已在缓冲区（命中）则直接用免 IO，若未命中则读盘并按替换策略（LRU/MRU/Clock）可能淘汰脏页（写回磁盘）。缓冲区命中率直接决定数据库性能。
</Answer>

**问题 2**：B+ 树为什么比 B 树更适合做数据库索引？说明三个原因。

<Answer>
①内部节点不存数据→能存更多键→每个节点能索引更多子节点→树更矮→查找 IO 更少。B 树内部节点也存数据，键容量小，树更高。②叶子节点链表相连→支持高效范围查询。范围查询只需定位起点后沿叶子链表顺序扫描即可，B 树做范围查询需中序遍历回溯，效率低。③所有数据在叶子层→查询路径长度一致→性能稳定。B 树数据分散在各级节点，查询路径长度不一。这三点使 B+ 树在 IO 代价和范围查询上全面优于 B 树。
</Answer>

**问题 3**：聚簇索引和非聚簇索引有什么区别？什么是覆盖索引？

<Answer>
聚簇索引：数据行按索引键物理排序存储，叶子节点直接存整行数据，一表只能有一个（通常主码）。非聚簇索引（二级索引）：数据行不按此键排序，叶子节点存主码值，查询非索引列时需"回表"——先用非聚簇索引找到主码，再用主码在聚簇索引中取整行。覆盖索引是特殊的非聚簇索引——索引包含了查询所需的所有列，因此无需回表，直接从索引返回结果，减少一次 IO，提升性能。
</Answer>

**问题 4**：给定一个"性别"列（只有男/女两个值）和一个"用户ID"列（每值唯一），分别该用什么索引？为什么？

<Answer>
"性别"列（低基数，只有两值）适合位图索引——位图索引为每个值建一个位图，压缩存储，适合低基数列的等值查询和聚合统计；若用 B+ 树则选择性太低（每个值对应一半数据），索引几乎无效。"用户ID"列（高基数，每值唯一）适合 B+ 树索引——选择性高，B+ 树能快速定位单条记录，O(log n) 查找；点查询和范围查询都高效。选择原则：高选择性列建 B+ 树，低基数列用位图索引。
</Answer>

</Exercises>
