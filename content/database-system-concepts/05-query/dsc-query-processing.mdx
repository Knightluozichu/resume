## 查询处理与优化

<DscQueryProcessingDiagram />

查询处理是把 SQL 语句转换为高效执行方案的过程。用户写的是声明式 SQL（要什么），数据库负责翻译成过程化执行计划（怎么取），并在等价方案中选代价最低的——这就是查询优化器，数据库最复杂的组件之一。

## 查询处理流水线

```
// 四步流水线
// ① 解析 Parse
//    └── 语法检查 → 生成语法树
// ② 翻译 Translate
//    └── 语法树 → 关系代数表达式树
// ③ 优化 Optimize
//    └── 代数优化 + 物理优化 → 选最优执行计划
// ④ 执行 Execute
//    └── 调用算子（扫描/连接/聚合）→ 返回结果
```

| 阶段 | 输入 | 输出 | 作用 |
|------|------|------|------|
| 解析 | SQL 文本 | 语法树 | 检查语法、生成解析树 |
| 翻译 | 语法树 | 关系代数表达式 | 转为关系代数，检查语义 |
| 优化 | 关系代数表达式 | 执行计划 | 选最低代价方案 |
| 执行 | 执行计划 | 结果集 | 调用算子产出结果 |

## 代数优化（逻辑层）

代数优化用等价规则变换关系代数表达式，不涉及具体实现：

```
// 核心策略：尽早减少数据量
// 1. 选择下推 σ
//    σ_c(R ⋈ S) ≡ σ_c(R) ⋈ S
//    先过滤再连接 → 中间结果更小
//
// 2. 投影下推 π
//    π_L(R ⋈ S) ≡ π_L1(R) ⋈ π_L2(S)
//    先裁列再连接 → 中间结果更窄
//
// 3. 选择级联
//    σ_c1(σ_c2(R)) ≡ σ_c1∧c2(R)
//    合并条件便于下推
//
// 4. 连接顺序重排
//    R ⋈ (S ⋈ T) ≡ (R ⋈ S) ⋈ T
//    选中间结果最小的连接顺序
//
// 5. 笛卡尔积消除
//    把笛卡尔积+选择转为等值连接
```

<Callout type="info" title="下推的核心思想">
选择和投影下推的目的是"尽早减少数据量"——先过滤掉不需要的行和列，再做昂贵的连接操作，这样中间结果更小、IO 更少。这是代数优化最重要的一条经验法则。
</Callout>

## 物理优化（实现层）

物理优化为每个关系代数运算选择具体的实现算法，基于代价估算：

```
// 为运算选算法
// 选择 σ：
//   └── 线性扫描（无索引，全表扫）
//   └── 索引扫描（有索引且选择性好）
//
// 连接 ⋈：
//   └── 嵌套循环 Nested Loop
//   └── 排序归并 Sort-Merge
//   └── 哈希连接 Hash Join
//
// 代价 = IO 开销 + CPU 开销
//   └── 基于统计信息（直方图/基数估计）估算
```

## 三种连接算法

| 算法 | 复杂度 | 适用场景 | 特点 |
|------|--------|----------|------|
| 嵌套循环 | `O(n·m)` | 小表/无索引/不等值 | 对每外层行扫全内层 |
| 排序归并 | `O(n log n + m log m)` | 已有序/大表等值 | 排序后归并 |
| 哈希连接 | `O(n+m)` | 等值连接/大表 | 内表建哈希表，外表探测 |

```
// 嵌套循环 Nested Loop
// for each r in R:           // 外层
//   for each s in S:         // 内层
//     if r.key == s.key: output
// 适合：小表、无索引、不等值连接
// 块嵌套循环：按块读外层，减少内层扫描次数

// 排序归并 Sort-Merge
// 1. R 和 S 按连接键排序
// 2. 双指针归并匹配
// 适合：已有序、大表等值连接

// 哈希连接 Hash Join
// 1. Build：用内表 S 建哈希表
// 2. Probe：用外表 R 每行探测哈希表
// 适合：等值连接、大表（最快）
// 限制：需内存建表，不支持不等值
```

<Callout type="warning" title="连接算法选择">
等值连接优先哈希连接（O(n+m) 最快）；已有序的数据用排序归并；小表或无索引用嵌套循环；不等值连接只能用嵌套循环。优化器根据数据量和索引情况自动选择。
</Callout>

## 优化器策略

```
// 两类优化策略
// 启发式（规则）优化
//   └── 按经验规则做代数变换（如选择下推）
//   └── 不依赖数据统计，速度快
//
// 代价优化
//   └── 枚举等价执行计划
//   └── 估算各方案代价选最优
//   └── 依赖直方图/基数估计
//
// 实际：先启发式剪枝，再代价优化精选
```

<Callout type="info" title="计划空间的挑战">
连接顺序的可能数随表数指数增长（n 个表有 n! 种顺序）。优化器用动态规划（自底向上）或概率搜索（如遗传算法）在可行时间内找到近优计划，而非穷举所有可能。
</Callout>

<Glossary>

<GlossaryItem term="查询处理流水线">
查询处理分四步：①解析——语法检查生成语法树；②翻译——语法树转关系代数表达式树；③优化——代数优化+物理优化选最优执行计划；④执行——调用算子产出结果。用户写声明式 SQL（要什么），数据库翻译成过程化执行计划（怎么取）并在等价方案中选代价最低的。
</GlossaryItem>

<GlossaryItem term="代数优化">
代数优化在逻辑层用等价规则变换关系代数表达式，不涉及具体实现。核心策略是"尽早减少数据量"：选择下推（先过滤再连接）、投影下推（先裁列再连接）、选择级联（合并条件下推）、连接顺序重排（选中间结果最小的顺序）、笛卡尔积消除。这些规则基于关系代数等价性，保证变换后语义不变。
</GlossaryItem>

<GlossaryItem term="物理优化">
物理优化在实现层为每个关系代数运算选择具体算法，基于代价估算。选择运算：线性扫描或索引扫描；连接运算：嵌套循环/排序归并/哈希连接。代价 = IO 开销 + CPU 开销，依赖统计信息（直方图、基数估计）估算。与代数优化互补：代数优化改结构，物理优化选算法。
</GlossaryItem>

<GlossaryItem term="三种连接算法">
嵌套循环 O(n·m)：对每外层行扫全内层，适合小表/无索引/不等值。排序归并 O(n log n+m log m)：两表按连接键排序后归并，适合已有序/大表等值。哈希连接 O(n+m)：内表建哈希表、外表探测，等值连接最快，需内存建表不支持不等值。优化器据数据量和索引自动选择。
</GlossaryItem>

<GlossaryItem term="启发式与代价优化">
启发式优化按经验规则做代数变换（如选择下推），不依赖数据统计，速度快。代价优化枚举等价执行计划，估算各方案代价选最优，依赖直方图/基数估计。实际先用启发式剪枝缩小空间，再用代价优化精选。计划空间随表数指数增长，用动态规划或概率搜索在可行时间找近优解。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：查询处理的四个阶段是什么？每阶段的输入和输出是什么？

<Answer>
①解析 Parse：输入 SQL 文本，输出语法树。检查语法合法性，生成解析树。②翻译 Translate：输入语法树，输出关系代数表达式树。转为关系代数，检查语义（如表/列是否存在）。③优化 Optimize：输入关系代数表达式，输出执行计划。做代数优化（等价变换）和物理优化（选算法），选代价最低方案。④执行 Execute：输入执行计划，输出结果集。调用算子（扫描/连接/聚合）产出结果。用户写声明式 SQL，数据库翻译成过程化执行计划并优化。
</Answer>

**问题 2**：什么是选择下推？为什么它能提升查询性能？用关系代数等价规则说明。

<Answer>
选择下推是把选择运算 σ 尽量移到表达式树的底部（靠近叶子/基本关系）的等价变换。等价规则：`σ_c(R ⋈ S) ≡ σ_c(R) ⋈ S`（当 c 只涉及 R 的属性时）。性能提升原因：先对 R 做选择过滤掉不满足条件的行，再做连接，中间结果更小——连接的代价与输入规模正相关，输入越小 IO 和计算越少。例如 `σ_dept='CS'(student ⋈ takes)` 下推为 `σ_dept='CS'(student) ⋈ takes`，先过滤出计算机系学生（少量），再连接选课表，远比先连接全部学生再过滤高效。
</Answer>

**问题 3**：对比三种连接算法的复杂度和适用场景。

<Answer>
①嵌套循环 O(n·m)：对每外层行扫全内层，适合小表、无索引、不等值连接。块嵌套循环按块读外层减少内层扫描次数。②排序归并 O(n log n+m log m)：两表按连接键排序后双指针归并，适合已有序数据、大表等值连接。③哈希连接 O(n+m)：内表建哈希表、外表探测，等值连接最快，适合大表等值连接，但需内存建表且不支持不等值。选择规则：等值连接优先哈希；已有序用排序归并；小表/无索引/不等值用嵌套循环。
</Answer>

**问题 4**：启发式优化和代价优化有什么区别？为什么实际中要结合使用？

<Answer>
启发式优化按经验规则做代数变换（如选择下推、投影下推、连接顺序重排），不依赖数据统计，速度快但可能非最优。代价优化枚举等价执行计划，估算每方案代价（IO+CPU）选最优，依赖直方图/基数估计，更精确但开销大。结合使用的原因：①计划空间随表数指数增长（n 表有 n! 种连接顺序），纯代价优化穷举不可行；②先用启发式剪枝缩小搜索空间（如强制选择下推），再对剩余候选做代价优化精选；③这样在优化时间和计划质量间取得平衡。
</Answer>

</Exercises>
