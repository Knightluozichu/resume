## 全书知识图谱

<DscFinalReviewDiagram />

《数据库系统概念》以四层结构组织全书：数据建模层（怎么组织数据）、查询处理层（怎么取数据）、系统实现层（怎么存怎么跑）、可靠性层（怎么不出错）。四层层层支撑，共同构成完整的数据库系统。

## 四层知识体系

| 层次 | 核心问题 | 关键概念 | 章节 |
|------|----------|----------|------|
| 第一层：建模 | 数据怎么组织？ | 关系模型/键/完整性/ER/范式 | 关系模型、数据库设计 |
| 第二层：查询 | 数据怎么取？ | SQL/关系代数/查询优化/连接算法 | SQL与关系代数、查询处理 |
| 第三层：实现 | 怎么存怎么跑？ | 文件/页/B+树/哈希/缓冲区 | 存储与索引、查询处理 |
| 第四层：可靠性 | 怎么不出错？ | ACID/隔离级别/2PL/MVCC/ARIES | 事务、并发、恢复 |

## 第一层：数据建模

```
// 数据怎么组织
// 关系模型
//   └── 关系/元组/属性/域
//   └── 键：超码 → 候选码 → 主码 → 外码
//   └── 完整性：实体/参照/用户定义
// ER设计
//   └── 实体/属性/联系（1:1/1:N/M:N）
//   └── 转关系模式（强实体/外码/新建关系）
// 规范化
//   └── 函数依赖 X→Y
//   └── 1NF（原子）→2NF（无部分依赖）→3NF（无传递）→BCNF
//   └── 消除冗余与异常（插入/更新/删除）
```

## 第二层：查询处理

```
// 数据怎么取
// SQL ↔ 关系代数
//   └── DDL/DML/DCL
//   └── σ选择/π投影/⋈连接/×笛卡尔/∪并/−差/ρ重命名
// 查询处理流水线
//   └── 解析 → 翻译 → 优化 → 执行
// 优化
//   └── 代数优化：选择下推/投影下推/连接重排
//   └── 物理优化：选算法（嵌套循环/排序归并/哈希连接）
//   └── 代价 = IO + CPU
```

## 第三层：系统实现

```
// 怎么存怎么跑
// 存储层次
//   └── 文件 → 页 → 记录
//   └── 文件组织：堆/顺序/散列/聚簇
// 索引
//   └── B+树（点+范围，O(log n)，最通用）
//   └── 哈希（点查询 O(1)）/ 位图（低基数）/ 聚簇（物理排序）
//   └── 聚簇 vs 非聚簇（回表）/ 覆盖索引（免回表）
// 缓冲区
//   └── LRU/MRU/Clock 替换，命中免 IO
```

## 第四层：可靠性

```
// 怎么不出错
// 事务 ACID
//   └── A原子性(UNDO)/C一致性/I隔离性(并发)/D持久性(REDO)
//   └── 隔离级别：读未提交→读已提交→可重复读→可串行化
// 并发控制
//   └── 封锁 2PL（严格2PL 避免级联中止）
//   └── MVCC（读写不互斥，快照隔离）
//   └── 乐观 OCC（无锁读，提交校验）
//   └── 死锁：预防/检测/超时
// 恢复
//   └── 日志 WAL + 检查点
//   └── ARIES：分析 → REDO → UNDO
//   └── 故障：事务/系统/介质
```

## 跨层交汇

<Callout type="info" title="四层如何协同">
第一层建模定义数据结构，第二层查询基于结构操作数据，第三层实现决定操作的性能，第四层可靠性保证操作的正确与持久。具体交汇：①查询优化（第二层）要考虑存储代价（第三层）——选索引扫描还是全表扫取决于 B+ 树；②事务隔离（第四层）依赖并发控制，而并发控制的锁表存于存储层（第三层）；③恢复系统（第四层）操作日志，日志记录的是关系模型（第一层）的数据修改。
</Callout>

## 全书核心脉络

```
// 数据库系统 = 数据模型 + 查询语言 + 系统实现 + 可靠性保障
//
// 数据模型（关系模型）
//   └── 定义"数据长什么样"（关系/元组/属性/域/键/约束）
// 查询语言（SQL/关系代数）
//   └── 定义"怎么操作数据"（DDL/DML/σπ⋈∪−）
// 系统实现（存储/索引/查询处理）
//   └── 决定"怎么高效执行"（B+树/缓冲区/优化器/连接算法）
// 可靠性保障（事务/并发/恢复）
//   └── 保证"怎么不出错"（ACID/2PL/MVCC/ARIES）
//
// 从理论到实现到保障：建模 → 查询 → 实现 → 可靠
```

## 综合分析框架

面对任何数据库问题，可按四层框架分析：

| 问题类型 | 分析层次 | 关键问题 |
|----------|----------|----------|
| 表设计不合理 | 建模层 | 是否满足范式？有无异常？ |
| 查询太慢 | 查询+实现层 | 执行计划如何？索引是否命中？ |
| 并发数据不一致 | 可靠性层 | 隔离级别够不够？有无并发异常？ |
| 崩溃后丢数据 | 可靠性层 | 日志/恢复机制是否健全？ |

<Glossary>

<GlossaryItem term="四层知识体系">
第一层建模：关系模型/键/完整性/ER设计/规范化，解决"数据怎么组织"。第二层查询：SQL/关系代数/查询优化/连接算法，解决"数据怎么取"。第三层实现：文件/页/索引(B+树/哈希)/缓冲区，解决"怎么存怎么跑"。第四层可靠性：ACID/隔离级别/2PL/MVCC/ARIES，解决"怎么不出错"。四层层层支撑。
</GlossaryItem>

<GlossaryItem term="数据库系统四要素">
数据库 = 数据模型（定义结构）+ 查询语言（定义操作）+ 系统实现（决定性能）+ 可靠性保障（保证正确）。数据模型回答"数据长什么样"，查询语言回答"怎么操作"，系统实现回答"怎么高效执行"，可靠性保障回答"怎么不出错"。
</GlossaryItem>

<GlossaryItem term="跨层交汇">
四层相互支撑：查询优化（第二层）要考虑存储代价（第三层）——选索引扫描还是全表扫取决于 B+ 树；事务隔离（第四层）依赖并发控制，锁表存于存储层（第三层）；恢复系统（第四层）操作日志，日志记录的是关系模型（第一层）的数据修改。理解交汇点才能从"会用数据库"升级到"理解数据库系统"。
</GlossaryItem>

<GlossaryItem term="综合分析框架">
面对数据库问题按四层分析：表设计不合理→建模层（是否满足范式/有无异常）；查询太慢→查询+实现层（执行计划/索引命中）；并发数据不一致→可靠性层（隔离级别/并发异常）；崩溃丢数据→可靠性层（日志/恢复机制）。
</GlossaryItem>

<Exercises>

**问题 1**：全书四层知识体系是什么？每层解决什么核心问题？

<Answer>
第一层建模：关系模型/键/完整性/ER设计/规范化，解决"数据怎么组织"——定义关系/元组/属性/域、键层级（超码→候选码→主码→外码）、三类完整性约束、ER转关系模式、函数依赖与1NF→BCNF规范化。第二层查询：SQL/关系代数/查询优化/连接算法，解决"数据怎么取"——SQL三类语言(DDL/DML/DCL)、关系代数运算(σπ⋈×∪−ρ)、查询处理流水线(解析→翻译→优化→执行)、代数优化(下推)+物理优化(选算法)。第三层实现：文件/页/索引/缓冲区，解决"怎么存怎么跑"——存储层次(文件→页→记录)、B+树/哈希/位图/聚簇索引、缓冲区管理(LRU)。第四层可靠性：ACID/隔离级别/2PL/MVCC/ARIES，解决"怎么不出错"。
</Answer>

**问题 2**：关系模型的三要素是什么？它们如何对应到 SQL 和系统实现？

<Answer>
三要素：①数据结构——关系（二维表），对应 SQL 的表定义（CREATE TABLE），对应系统实现的存储结构（文件/页/记录）。②数据操作——关系代数/SQL，对应 SQL 的 DML（SELECT/INSERT/UPDATE/DELETE）和关系代数运算（σπ⋈），对应系统实现的查询处理（解析→翻译→优化→执行）。③完整性约束——实体/参照/用户定义，对应 SQL 的 PRIMARY KEY/FOREIGN KEY/CHECK 约束，对应系统实现的约束检查机制。三要素贯穿从模型到语言到实现。
</Answer>

**问题 3**：ACID 四特性分别由什么机制保证？这些机制分别属于哪一章？

<Answer>
A 原子性——由 UNDO（撤销未提交事务）保证，属于"恢复系统"章。C 一致性——由 A+I+D 共同保证，是事务的最终目标，跨"事务管理/并发控制/恢复系统"三章。I 隔离性——由并发控制机制（封锁 2PL/MVCC/OCC）保证，属于"并发控制"章。D 持久性——由 REDO（重做已提交事务）保证，属于"恢复系统"章。其中 A 和 D 都依赖日志和恢复系统，I 依赖并发控制，三者共同保证 C。
</Answer>

**问题 4**：用四层分析框架分析"某查询很慢且偶发并发数据不一致"的问题。

<Answer>
查询慢（查询+实现层）：①看执行计划——是否用了索引扫描还是全表扫；②看索引是否命中——高选择性列是否建了 B+ 树索引，是否有覆盖索引免回表；③看连接算法——是否用了哈希连接而非嵌套循环；④看代数优化——选择是否下推减少中间结果；⑤看缓冲区命中率——热页是否在内存。并发数据不一致（可靠性层）：①看隔离级别——是否用了读已提交（可能有不可重复读），是否需提升到可重复读或可串行化；②看是否有并发异常——脏读/不可重复读/幻读/写偏斜；③看并发控制协议——MVCC 的快照隔离下可能有写偏斜，需 SSI；④看是否需调整隔离级别或加显式锁。两层结合：先解决正确性（提升隔离级别），再解决性能（优化查询和索引）。
</Answer>
