## 事务管理与 ACID

<DscTransactionsDiagram />

事务是数据库操作的基本单位，是一组"要么全做、要么全不做"的操作序列。ACID 是事务正确性的四个保证。理解事务，才能理解数据库如何在并发和故障下保持数据正确。

## ACID 四特性

```
// ACID = 原子性 + 一致性 + 隔离性 + 持久性
// A Atomicity 原子性
//   └── 事务是不可分割的单位：全做或全不做
//   └── 失败则回滚（UNDO），保证不留半成品
// C Consistency 一致性
//   └── 事务执行前后，数据库满足所有完整性约束
//   └── 由 A/I/D 共同保证
// I Isolation 隔离性
//   └── 并发事务互不干扰，像串行执行一样
//   └── 由并发控制机制保证
// D Durability 持久性
//   └── 事务提交后，修改永久保存，即使崩溃也不丢
//   └── 由恢复系统保证（REDO）
```

| 特性 | 含义 | 保证机制 | 解决的问题 |
|------|------|----------|------------|
| A 原子性 | 全做或全不做 | 回滚 UNDO | 事务中途失败留半成品 |
| C 一致性 | 约束不变 | A+I+D 共同保证 | 数据违反约束 |
| I 隔离性 | 并发互不干扰 | 并发控制 | 并发互相干扰 |
| D 持久性 | 提交即永久 | 恢复 REDO | 提交后崩溃丢数据 |

<Callout type="warning" title="一致性是目标，AID是手段">
一致性（C）是事务的最终目标——执行前后数据库都满足完整性约束。原子性（A）、隔离性（I）、持久性（D）是保证一致性的手段：A 保证不出现部分更新，I 保证并发不互相破坏，D 保证提交不丢失。三者共同确保一致性。
</Callout>

## 事务状态机

```
// 事务的五个状态
//   活动 Active
//     ↓ 最后一条语句执行完
//   部分提交 Partially Committed
//     ↓ 提交成功            ↓ 失败
//   提交 Committed         失败 Failed
//   （终态，可见）            ↓ 回滚完成
//                           终止 Aborted（终态，回滚）
//
// 活跃事务执行完所有语句 → 部分提交
// 部分提交后提交成功 → 提交（终态，修改持久化）
// 任何阶段失败 → 失败 → 回滚 → 终止（终态，撤销修改）
```

| 状态 | 含义 | 后继 |
|------|------|------|
| 活动 | 正在执行语句 | → 部分提交 / 失败 |
| 部分提交 | 最后语句执行完，未提交 | → 提交 / 失败 |
| 提交 | 提交成功，修改持久 | 终态 |
| 失败 | 发生错误，无法继续 | → 终止 |
| 终止 | 回滚完成，修改撤销 | 终态 |

<Callout type="info" title="部分提交 vs 提交">
部分提交（Partially Committed）表示事务的所有语句已执行完，但修改尚未持久化（可能还在缓冲区）。提交（Committed）表示修改已持久化到磁盘（日志已落盘），即使崩溃也不丢。两者之间的过渡由恢复系统保证。
</Callout>

## 隔离级别与并发异常

```
// 四种隔离级别（隔离性由弱到强）
// 读未提交 Read Uncommitted
//   └── 可能脏读（读到未提交的数据）
// 读已提交 Read Committed
//   └── 可能不可重复读（同一事务两次读结果不同）
// 可重复读 Repeatable Read
//   └── 可能幻读（范围查询多出行）
// 可串行化 Serializable
//   └── 无异常（隔离最强，并发最低）
```

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 并发性 |
|----------|------|------------|------|--------|
| 读未提交 | 有 | 有 | 有 | 最高 |
| 读已提交 | 无 | 有 | 有 | 高 |
| 可重复读 | 无 | 无 | 有 | 中 |
| 可串行化 | 无 | 无 | 无 | 最低 |

### 三种并发异常

```
// 脏读 Dirty Read
//   T1 修改数据未提交，T2 读到了
//   若 T1 回滚，T2 读到的是"不存在"的数据
//
// 不可重复读 Non-repeatable Read
//   T1 两次读同一行，T2 在中间修改并提交
//   T1 两次读结果不同
//
// 幻读 Phantom Read
//   T1 两次范围查询，T2 在中间插入/删除并提交
//   T1 第二次查询多出或少行（"幻影"行）
```

<Callout type="warning" title="隔离与性能的权衡">
隔离级别越高，一致性越强但并发性越低（锁更多、等待更长）。读未提交并发最高但可能读到脏数据；可串行化最安全但性能最差。实际需根据业务权衡——多数数据库默认用"读已提交"。
</Callout>

## 可串行化

```
// 可串行化 Serializability
//   并发执行的结果 = 某个串行执行的结果
//   → 并发事务的效果等价于一次一个地执行
//
// 冲突可串行化 Conflict Serializability
//   └── 通过交换非冲突操作得到等价串行顺序
//   └── 判定：优先图无环
//
// 视图可串行化 View Serializability
//   └── 更宽松的等价条件
//   └── 难以高效检测，实际少用
//
// 并发控制的目标 = 实现可串行化
```

<Glossary>

<GlossaryItem term="ACID">
事务四特性：A 原子性——事务不可分割，全做或全不做，失败则回滚（UNDO）；C 一致性——事务执行前后数据库满足所有完整性约束，是目标；I 隔离性——并发事务互不干扰像串行执行，由并发控制保证；D 持久性——提交后修改永久保存即使崩溃不丢，由恢复系统保证（REDO）。一致性是目标，AID 是保证一致性的手段。
</GlossaryItem>

<GlossaryItem term="事务状态机">
事务五个状态：活动（执行中）→部分提交（语句执行完未持久化）→提交（持久化，终态）；任何阶段失败→失败→终止（回滚，终态）。部分提交与提交的区别：部分提交表示语句执行完但修改未落盘，提交表示修改已持久化（日志落盘），崩溃也不丢。
</GlossaryItem>

<GlossaryItem term="四种隔离级别">
读未提交（可能脏读）、读已提交（无脏读，可能不可重复读）、可重复读（无不可重复读，可能幻读）、可串行化（无异常，隔离最强并发最低）。隔离越强一致性越高但并发越低。多数数据库默认用读已提交，需根据业务权衡。
</GlossaryItem>

<GlossaryItem term="三种并发异常">
脏读：T1 修改未提交，T2 读到，若 T1 回滚则 T2 读到"不存在"的数据。不可重复读：T1 两次读同一行，T2 中间修改并提交，T1 两次结果不同。幻读：T1 两次范围查询，T2 中间插入/删除并提交，T1 第二次多出或少行（幻影行）。隔离级别逐级消除这三种异常。
</GlossaryItem>

<GlossaryItem term="可串行化">
可串行化指并发执行结果等价于某个串行执行结果，是并发控制的目标。冲突可串行化：通过交换非冲突操作能得到等价串行顺序，判定方法是构造优先图——若无环则冲突可串行化。视图可串行化条件更宽松但难检测。并发控制协议（封锁/MVCC/乐观）的目标就是保证可串行化。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：解释 ACID 四特性，并说明一致性与其他三特性的关系。

<Answer>
A 原子性：事务不可分割，全做或全不做，失败则回滚（UNDO），保证不留半成品。C 一致性：事务执行前后数据库满足所有完整性约束。I 隔离性：并发事务互不干扰，像串行执行，由并发控制保证。D 持久性：提交后修改永久保存，即使崩溃也不丢，由恢复系统保证（REDO）。关系：一致性（C）是事务的最终目标，原子性（A）、隔离性（I）、持久性（D）是保证一致性的手段——A 保证不出现部分更新，I 保证并发不互相破坏，D 保证提交不丢失，三者共同确保一致性。
</Answer>

**问题 2**：描述事务状态机的状态转换。部分提交和提交有什么区别？

<Answer>
状态转换：活动（执行中）→最后语句执行完→部分提交→提交成功→提交（终态，修改持久化）；任何阶段失败→失败→回滚完成→终止（终态，修改撤销）。部分提交（Partially Committed）表示事务所有语句已执行完，但修改尚未持久化（可能还在缓冲区，未落盘）。提交（Committed）表示修改已持久化到磁盘（日志已落盘），即使崩溃也不丢失。区别在于持久化是否完成——部分提交后若崩溃需 REDO 恢复，提交后则保证持久。
</Answer>

**问题 3**：什么是脏读、不可重复读、幻读？分别由哪个隔离级别消除？

<Answer>
脏读：T1 修改数据未提交，T2 读到了，若 T1 回滚则 T2 读到"不存在"的数据——由读已提交消除。不可重复读：T1 两次读同一行，T2 在中间修改并提交，T1 两次结果不同——由可重复读消除。幻读：T1 两次范围查询，T2 在中间插入/删除并提交，T1 第二次多出或少行（幻影行）——由可串行化消除。隔离级别逐级消除：读未提交有全部三种异常，读已提交消除脏读，可重复读再消除不可重复读，可串行化消除全部。
</Answer>

**问题 4**：什么是可串行化？如何判定冲突可串行化？为什么它是并发控制的目标？

<Answer>
可串行化指并发执行的结果等价于某个串行执行结果——并发事务的效果像一次一个地执行一样。冲突可串行化的判定：构造优先图（节点是事务，若 T1 的操作与 T2 冲突且 T1 先执行，则画 T1→T2 的边），若优先图无环则冲突可串行化。它是并发控制的目标，因为可串行化保证了并发执行的正确性——结果等价于串行，因此并发不会破坏数据一致性。并发控制协议（封锁 2PL、MVCC、乐观 OCC）的设计都是为了在保证可串行化的前提下尽可能提高并发度。
</Answer>

</Exercises>
