# 第15章 查询处理

本课程对应Abraham Silberschatz、Henry F. Korth、S. 在“第15章 查询处理”的证据链中，Sudarshan著，杨冬青、李红燕、张金波等译《数据库系统概念（原书第7版）》，机械工业出版社2021年6月出版，820页，ISBN 9787111681816。原版第7版由McGraw-Hill于2019年发布。课程按原书11部分、32章与附录A逐项重构，不复制原文。

中文版第7版纸书正文收录第1-23章；第24-26章由中文版提供中文在线内容；第27-32章是原版官网英文在线章节；附录A在纸书中。本页媒介为“纸书正文”。
全课程另设学习地图与总复习，共35页；正式知识分母仍是32章与附录A。本页属于“第六部分 查询处理与优化”，依据正式目录覆盖9个节点。

“第15章 查询处理”没有使用未获授权的中文纸书正文；以 [作者官网第 7 版完整目录](https://www.db-book.com/toc-dir/toc.pdf) 界定 32 章与附录 A，以 [作者公开在线章节](https://www.db-book.com/online-chapters-dir/index.html)、[大学模式实验](https://www.db-book.com/university-lab-dir/exercises-dir/) 和 [McGraw-Hill 第 7 版变更说明](https://www.mheducation.com/unitas/highered/changes/silberschatz-database-system-concepts-7e.pdf) 核对可公开内容。中文解释、SQL、图示、实验与练习均为独立教学重写；实现行为再以 [PostgreSQL 官方文档](https://www.postgresql.org/docs/current/) 等一手规范复核。

## 从一次可观察状态变化开始

先预测：给定一份固定的大学数据库、一个操作和一个故障时刻，哪些逻辑行、物理页、锁、版本或日志记录应该变化，哪些绝不能变化？不要先运行再解释。把预测写成状态表，然后用独立查询、执行统计、页或日志轨迹核对。若预测与观察不一致，先检查模型和实验边界，而不是立即改配置。

本页主问题是“把关系运算映射为扫描、排序、哈希和连接算法并核算I/O与内存”。交付不以读完为准，而以另一位学习者能从算子流水线图、三种连接算法实验和I/O成本对账复现同一结论为准。最小正确性合同是：**每个物理算子保持逻辑语义，代价估算注明页数、内存页和输入有序性**。

## 机制推演：从语义到物理证据

选择可以顺序扫描或借助索引，外部排序分初始段与多路归并，连接可采用嵌套循环、归并或分区哈希。物化保存中间结果，流水线减少落盘；算法选择取决于页数、内存和数据顺序。

推演时始终区分五层。在“第15章 查询处理”的证据链中，第一层是业务不变量，说明哪些数据库状态合法；第二层是逻辑模型与查询语义，说明结果应该是什么；第三层是物理计划和数据结构，说明系统怎样得到结果；第四层是并发、日志与复制协议，说明交错和故障后仍保留哪些承诺；第五层是观测证据，说明我们怎样知道前四层真的成立。性能优化只能改变第三层和部分第四层的实现，不能悄悄改变前两层。

对每个节点建立因果链：输入版本与配置 → 操作或调度 → 中间状态 → 可观察输出 → 独立对账。在“第15章 查询处理”的证据链中，若结论涉及性能，报告中位数、尾延迟、吞吐、I/O和等待，而不是只截一条最快记录；若涉及正确性，至少准备一个应成功样本和一个应失败样本，并记录错误类别或恢复终点。

<Callout type="trap">
  **建模陷阱。**
  只比较渐进复杂度不计页面I/O，或在内存不足时仍假设一次哈希表装载完成。先恢复业务不变量、输入版本和最小反例，再选择结构或协议；不要让偶然成功的样例替代证明。
</Callout>

<Callout type="trap">
  **证据陷阱。**
  只保存最终截图无法区分逻辑错误、计划变化、缓存命中、并发交错和恢复副作用。必须同时保存预期、完整输入、操作顺序、关键中间状态和独立对账。
</Callout>

<Callout type="warning">
  写入、并发、崩溃、恢复与分布式实验只在隔离样例库进行。先保存重置脚本，规定影响行数、等待时间、磁盘空间和停止条件。
</Callout>

## 证据解释与交接

语义证据证明结果定义没有漂移。保存关系模式、约束、查询文本、参数、隔离级别和预期行集；涉及NULL、重复、顺序或聚集时，单独列出处理规则。任何实现比较都必须共享同一语义合同。

执行证据证明机制判断可以复核。保存计划、实际行数、缓冲命中、I/O、锁或版本、日志位置和错误状态中与本章相关的部分。计划估计与实际偏差本身就是结果，不应通过只截取计划名称隐藏。

失败证据证明边界真实存在。每次只注入一个变量：空输入、重复键、倾斜、并发冲突、进程崩溃、存储丢失或网络分区。明确失败前最后一个持久状态、恢复后第一个可用状态，以及是否需要人工介入。

交接证据让另一位学习者无需口头补充就能复现。最少包括版本卡、大学模式加载与重置脚本、预测表、算子流水线图、三种连接算法实验和I/O成本对账、正常与失败轨迹、独立对账、已知限制和回退条件。若更换DBMS或版本，先重跑基线再比较。

<Exercises>
**问题 1**：为什么“第15章 查询处理”必须覆盖9个目录节点？

<Answer>这些节点共同组成“把关系运算映射为扫描、排序、哈希和连接算法并核算I/O与内存”的语义、结构、执行、故障和证据链；缺项会让算子流水线图、三种连接算法实验和I/O成本对账无法独立复现。</Answer>

**问题 2**：本页最小正确性合同是什么？

<Answer>
  每个物理算子保持逻辑语义，代价估算注明页数、内存页和输入有序性。它必须由固定输入、正常轨迹、失败反例和独立对账共同证明。
</Answer>

**问题 3**：怎样构造能推翻常见错误的最小反例？

<Answer>
  把“只比较渐进复杂度不计页面I/O，或在内存不足时仍假设一次哈希表装载完成”写成待证假设，只改变一个数据、并发或故障变量，比较前后状态与独立对账结果。
</Answer>

**问题 4**：为什么执行成功不能证明数据库设计正确？

<Answer>
  执行成功只说明当前输入没有触发可见错误，不能证明所有合法调度、NULL、重复、故障和恢复边界都保持不变量；还需反例与机制证据。
</Answer>

**问题 5**：性能结论至少需要哪些数据？

<Answer>
  需要固定工作负载与数据规模、预热策略、重复次数、延迟分布、吞吐、I/O或等待、执行计划和正确性对账，不能只报告一次最快值。
</Answer>

**问题 6**：独立交接至少包含什么？

<Answer>需要版本与配置、大学模式基线、预测表、算子流水线图、三种连接算法实验和I/O成本对账、正常与失败轨迹、独立对账、已知限制和回退条件。</Answer>
</Exercises>
