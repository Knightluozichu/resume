## 从一次可观察状态变化开始

先预测：给定一份固定的大学数据库、一个操作和一个故障时刻，哪些逻辑行、物理页、锁、版本或日志记录应该变化，哪些绝不能变化？不要先运行再解释。把预测写成状态表，然后用独立查询、执行统计、页或日志轨迹核对。若预测与观察不一致，先检查模型和实验边界，而不是立即改配置。

本页主问题是“比较锁、时间戳、验证和多版本协议如何排序冲突并处理幻读”。交付不以读完为准，而以另一位学习者能从锁表轨迹、死锁等待图、MVCC可见性时间线和写偏差反例复现同一结论为准。最小正确性合同是：**并发历史不破坏声明的不变量，等待图、版本可见性和冲突检测均可审计**。

## 机制推演：从语义到物理证据

严格两阶段锁通过持锁到提交避免级联回滚，等待图检测死锁；时间戳按全局次序拒绝冲突，验证协议在提交前检查，多版本并发控制让读者选择可见版本。快照隔离并不自动保证可串行化。

推演时始终区分五层。第一层是业务不变量，说明哪些数据库状态合法；第二层是逻辑模型与查询语义，说明结果应该是什么；第三层是物理计划和数据结构，说明系统怎样得到结果；第四层是并发、日志与复制协议，说明交错和故障后仍保留哪些承诺；第五层是观测证据，说明我们怎样知道前四层真的成立。性能优化只能改变第三层和部分第四层的实现，不能悄悄改变前两层。

对每个节点建立因果链：输入版本与配置 → 操作或调度 → 中间状态 → 可观察输出 → 独立对账。若结论涉及性能，报告中位数、尾延迟、吞吐、I/O和等待，而不是只截一条最快记录；若涉及正确性，至少准备一个应成功样本和一个应失败样本，并记录错误类别或恢复终点。

## 最小可重放实验

```sql
-- 固定大学模式版本，并用独立计数建立输入基线
SELECT 'department' AS relation_name, COUNT(*) AS rows_n FROM department
UNION ALL
SELECT 'student', COUNT(*) FROM student
UNION ALL
SELECT 'takes', COUNT(*) FROM takes;
```

先在纸面写出预计关系数、目标键、异常类型和恢复终点。再执行本章实验，并把每一步与“并发历史不破坏声明的不变量，等待图、版本可见性和冲突检测均可审计”对照。查询正确不等于机制解释正确，执行成功也不等于故障后仍正确。

</Callout>

<Callout type="warning">
  写入、并发、崩溃、恢复与分布式实验只在隔离样例库进行。先保存重置脚本，规定影响行数、等待时间、磁盘空间和停止条件。
</Callout>

## 证据解释与交接

语义证据证明结果定义没有漂移。保存关系模式、约束、查询文本、参数、隔离级别和预期行集；涉及NULL、重复、顺序或聚集时，单独列出处理规则。任何实现比较都必须共享同一语义合同。

执行证据证明机制判断可以复核。保存计划、实际行数、缓冲命中、I/O、锁或版本、日志位置和错误状态中与本章相关的部分。计划估计与实际偏差本身就是结果，不应通过只截取计划名称隐藏。

失败证据证明边界真实存在。每次只注入一个变量：空输入、重复键、倾斜、并发冲突、进程崩溃、存储丢失或网络分区。明确失败前最后一个持久状态、恢复后第一个可用状态，以及是否需要人工介入。

交接证据让另一位学习者无需口头补充就能复现。最少包括版本卡、大学模式加载与重置脚本、预测表、锁表轨迹、死锁等待图、MVCC可见性时间线和写偏差反例、正常与失败轨迹、独立对账、已知限制和回退条件。若更换DBMS或版本，先重跑基线再比较。

## 本章回顾

重新完成“比较锁、时间戳、验证和多版本协议如何排序冲突并处理幻读”：先声明不变量和输入版本，按11个目录节点建立模型，手算正常路径，注入一个边界或故障，收集语义与执行证据，最后由独立查询对账。最终交付锁表轨迹、死锁等待图、MVCC可见性时间线和写偏差反例，并能证明“并发历史不破坏声明的不变量，等待图、版本可见性和冲突检测均可审计”。

## 复习与独立验收

<Exercises>
**问题 1**：为什么“第18章 并发控制”必须覆盖11个目录节点？
<Answer>这些节点共同组成“比较锁、时间戳、验证和多版本协议如何排序冲突并处理幻读”的语义、结构、执行、故障和证据链；缺项会让锁表轨迹、死锁等待图、MVCC可见性时间线和写偏差反例无法独立复现。</Answer>

**问题 2**：本页最小正确性合同是什么？

<Answer>
  并发历史不破坏声明的不变量，等待图、版本可见性和冲突检测均可审计。它必须由固定输入、正常轨迹、失败反例和独立对账共同证明。
</Answer>

**问题 3**：怎样构造能推翻常见错误的最小反例？

<Answer>
  把“只测试丢失更新，忽略谓词冲突、幻读和快照隔离下的写偏差”写成待证假设，只改变一个数据、并发或故障变量，比较前后状态与独立对账结果。
</Answer>

**问题 4**：为什么执行成功不能证明数据库设计正确？

<Answer>
  执行成功只说明当前输入没有触发可见错误，不能证明所有合法调度、NULL、重复、故障和恢复边界都保持不变量；还需反例与机制证据。
</Answer>

**问题 5**：性能结论至少需要哪些数据？

<Answer>
  需要固定工作负载与数据规模、预热策略、重复次数、延迟分布、吞吐、I/O或等待、执行计划和正确性对账，不能只报告一次最快值。
</Answer>

**问题 6**：独立交接至少包含什么？

<Answer>需要版本与配置、大学模式基线、预测表、锁表轨迹、死锁等待图、MVCC可见性时间线和写偏差反例、正常与失败轨迹、独立对账、已知限制和回退条件。</Answer>
</Exercises>
