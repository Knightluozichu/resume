## 知识体系全景

<DdiLearningMapDiagram />

《数据密集型应用系统设计》以"让数据系统可靠、可扩展、可维护"为主线，系统讲解从单机数据系统基础到分布式一致性再到大规模衍生数据处理的完整链路。全书分数据系统基础、分布式数据、衍生数据三个部分，覆盖从存储引擎原理到复制分区、从事务隔离到共识算法、从批处理到流处理的完整体系。

## 三条核心主线

### 主线一：数据系统设计

```
// 从数据系统怎么设计的递进路径
// 设计目标
//   └── 可靠性：硬件/软件/人为失误的容错
//   └── 可扩展性：负载描述 + 性能量化（吞吐/延迟百分位）
//   └── 可维护性：可运维/简洁/可演化
// 数据模型
//   └── 关系模型 → 文档模型 → 图模型
//   └── Schema 演化：读时模式 vs 写时模式
// 存储与检索
//   └── LSM-Tree（写优化） vs B-Tree（读优化）
//   └── 列式存储 / 内存数据库
// 编码与演化
//   └── 向前兼容 + 向后兼容
//   └── JSON/Protobuf/Avro
//
// 核心：懂目标 → 会建模 → 懂存储 → 会演化
```

### 主线二：分布式一致性

```
// 从分布式怎么不出错的递进路径
// 复制
//   └── 主从/多主/无主 → Quorum（w+r>n）
//   └── 复制滞后：读己之写/单调读/一致前缀读
// 分区
//   └── 范围分区 vs 哈希分区
//   └── 再平衡 + 二级索引分区
// 事务
//   └── ACID → 隔离级别阶梯（读未提交→可序列化）
//   └── 写倾斜/幻读 → SSI 可序列化快照隔离
// 一致性与共识
//   └── 线性一致性 / 因果一致性
//   └── CAP → 2PC → Raft/Paxos 共识
//
// 核心：能复制 → 能分区 → 能事务 → 能共识
```

### 主线三：衍生数据管道

```
// 从大规模数据怎么算的递进路径
// 衍生数据
//   └── 系统记录 vs 衍生数据
//   └── CDC / 事件溯源
// 批处理
//   └── MapReduce：Map → Shuffle → Reduce
//   └── 高吞吐/全量/容错简单
// 流处理
//   └── 事件时间 vs 处理时间 / 水位线
//   └── 窗口/exactly-once/状态管理
// 数据集成
//   └── Lambda（批+流） vs Kappa（纯流）
//   └── 拆解数据库 → 分布式基础设施
//
// 核心：懂衍生 → 会批处理 → 会流处理 → 能集成
```

<Callout type="info" title="核心认知">
全书三条主线在「存储+复制」（存储引擎决定复制策略）与「事务+共识」（事务需要共识保证跨副本一致）与「批流+集成」（批流处理是数据集成的实现手段）处交汇。理解这些交汇点，才能从"会用数据库"升级到"设计数据密集型应用系统"。
</Callout>

<Exercises>

**问题 1**：全书分为哪三个部分？各自的核心内容和递进逻辑是什么？

<Answer>
全书分三个部分：第一部分「数据系统基础」——学习地图（知识体系）、可靠性/可扩展性/可维护性三大目标、数据模型（关系/文档/图）、存储与检索（LSM-Tree/B-Tree）、编码与演化；第二部分「分布式数据」——复制（主从/多主/无主/Quorum/复制滞后）、分区（范围/哈希/再平衡/二级索引）、事务（ACID/隔离级别/SSI/写倾斜）、一致性与共识（线性一致性/CAP/2PC/Raft）；第三部分「衍生数据」——衍生数据（系统记录/CDC/事件溯源）、批处理与流处理（MapReduce/Flink/exactly-once）、未来方向（数据集成/拆解DB/伦理）。递进逻辑：从基础设计到分布式一致到衍生数据管道。
</Answer>

**问题 2**：贯穿全书的三条核心主线是什么？它们在哪些章节交汇？

<Answer>
主线一数据系统设计：可靠性 → 可扩展性 → 可维护性 → 数据模型/存储/编码，解决"数据系统怎么设计"。主线二分布式一致性：复制 → 分区 → 事务 → 共识，解决"分布式怎么不出错"。主线三衍生数据管道：批处理 → 流处理 → 数据集成，解决"大规模数据怎么算"。三条主线在"存储+复制"（存储引擎决定复制策略）与"事务+共识"（事务需要共识保证跨副本一致）与"批流+集成"（批流处理是数据集成的实现手段）处交汇。
</Answer>

**问题 3**：为什么学习DDIA要遵循"基础认知 → 分布式核心 → 衍生数据 → 全书整合"的顺序？

<Answer>
顺序依据：基础认知——理解可靠性、数据模型、存储引擎和编码演化，建立数据系统基本认知；分布式核心——复制、分区、事务、一致性共识是分布式系统的核心难点，需要先理解单机存储才能理解跨节点问题；衍生数据——批处理和流处理建立在分布式存储和复制的基础上，是大规模数据处理的应用层；全书整合——把三部分串起来理解数据系统的整体架构。跳过基础的风险：①不懂存储引擎无法理解复制日志；②不懂复制无法理解分区和事务；③不懂分布式一致性无法理解衍生数据管道的容错。每一步都是下一步的前提。
</Answer>

**问题 4**：DDIA的三个核心维度是什么？它们如何构成完整能力？

<Answer>
三维度：①基础设计——可靠性/可扩展性/可维护性 + 数据模型/存储检索/编码演化，回答"数据系统怎么设计"；②分布式一致性——复制/分区/事务/共识，回答"分布式怎么不出错"；③衍生数据管道——批处理/流处理/数据集成，回答"大规模数据怎么算"。三维度层层支撑：基础设计是地基（理解单机数据系统），分布式一致性是核心（解决跨节点协作难题），衍生数据管道是应用（用分布式基础设施处理大规模数据）。
</Answer>
