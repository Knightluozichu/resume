## 系统记录与数据集成

<DdiDerivedDataDiagram />

第三部分"衍生数据"将视角从"单一系统"提升到"数据基础设施"——数据不再只存于一处，而是通过系统记录+衍生系统的组合，让多种数据系统协作。

## 系统记录 vs 衍生数据

```
// 系统记录（System of Record）
//   数据的权威来源（True Source）
//   写入路径的终点
//   要求：一致、可恢复、权威
//   丢失 = 数据真正丢失
//   代表：OLTP 数据库主库
//
// 衍生数据（Derived Data）
//   从系统记录计算/转换得到
//   读路径的优化
//   可丢弃可重建 → 丢失后从系统记录重算
//   代表：索引、物化视图、缓存、搜索索引
//
// 核心认知
//   衍生数据不需要自己的写入API
//   → 通过消费系统记录的变更（CDC）来更新
//   → 衍生数据可以多种形式，各自优化不同查询
```

## 衍生数据的三种形式

| 形式 | 机制 | 同步方式 | 适用场景 |
|------|------|----------|----------|
| 物化视图与索引 | 同库内衍生 | 触发器/CDC/双写 | 加速特定查询 |
| 批处理衍生 | MapReduce/Spark | 定期全量计算 | 离线报表/ML训练 |
| 流处理衍生 | Kafka/Flink | 实时增量计算 | 低延迟物化视图 |

## 数据集成：让衍生数据保持同步

### 变更数据捕获（CDC）

```
// CDC 核心思想
//   捕获系统记录的变更日志（如 binlog）
//   → 转为事件流 → 衍生系统消费
//
// 特点
//   系统记录仍然是数据库（以状态为真相源）
//   CDC 只是「观测」变更的副产品
//   不改变现有架构
//
// 适用
//   OLTP → 搜索索引（ES）
//   OLTP → 缓存（Redis）
//   OLTP → 数据仓库
```

### 事件溯源（Event Sourcing）

```
// 事件溯源核心思想
//   以事件本身作为系统记录
//   当前状态由回放事件得到
//   数据库只存事件日志
//
// 特点
//   真相源是「事件」（不是状态）
//   状态是派生的（可回放重建）
//   完整审计、可回放、可重建任意时刻状态
//
// 适用
//   金融交易、领域事件丰富的系统
```

<Callout type="info" title="CDC vs 事件溯源">
CDC的真相源是"当前状态"（事件是观测副产品），事件溯源的真相源是"事件"（状态是派生）。CDC更实用（不改架构），事件溯源更纯粹（但架构改动大）。两者都通过日志实现衍生数据同步。
</Callout>

## Lambda架构 vs Kappa架构

```
// Lambda 架构
//   批层（Batch Layer）→ 全量计算，准确
//   速度层（Speed Layer）→ 增量计算，快速
//   合并层（Serving Layer）→ 合并两层结果
//
//   优点：批层保证准确性，速度层保证低延迟
//   缺点：维护两套代码（批+流逻辑需一致），复杂
//
// Kappa 架构
//   只用流处理
//   用日志保存全量数据
//   需要重算时从头重放日志
//
//   优点：一套代码、一套引擎，简洁
//   缺点：要求流处理引擎足够强大
//
// 趋势：批流融合（Flink）
//   批是流的特例（有界流）
//   一套引擎统一批和流
//   → Kappa 架构成为可能
```

## 拆解数据库（Unbundling the Database）

```
// 核心思想
//   把数据库内部机制 → 变成独立的分布式组件
//
// 映射关系
//   WAL 预写日志       → Kafka（分布式日志）
//   物化视图            → 批/流计算输出
//   CDC                 → 触发器 + 复制
//   索引                → Elasticsearch 等搜索引擎
//   事务                → 分布式事务（2PC + 共识）
//
// 意义
//   ① 不依赖单一数据库解决所有问题
//   ② 系统记录 + 一组衍生系统组合
//   ③ 每个组件独立扩展和演化
//   ④ 衍生数据通过日志自动同步
//
// 本质
//   把数据库内部的设计原则
//   提升到分布式基础设施层面
```

<Glossary>

<GlossaryItem term="系统记录与衍生数据">
系统记录是数据的权威来源（True Source），丢失=数据真正丢失。衍生数据从系统记录计算得到，可丢弃可重建。核心意义：衍生数据系统不需要自己的写入API，通过消费系统记录的变更（CDC）来更新，可以多种形式各自优化不同查询。
</GlossaryItem>

<GlossaryItem term="CDC vs 事件溯源">
CDC（变更数据捕获）：从现有数据库的变更日志中捕获事件转为流，系统记录是数据库（状态为真相源），CDC是观测副产品。事件溯源：以事件为系统记录，状态由回放事件得到。CDC更实用（不改架构），事件溯源更纯粹（架构改动大）。
</GlossaryItem>

<GlossaryItem term="Lambda vs Kappa">
Lambda：批层（全量准确）+速度层（增量快速）+合并层。两套代码，复杂但容错。Kappa：只用流处理，用日志重放替代批层。一套代码，简洁但流引擎需够强。趋势：批流融合（Flink），批是流的特例。
</GlossaryItem>

<GlossaryItem term="拆解数据库">
把数据库内部机制（WAL→Kafka、物化视图→批/流输出、CDC→触发器+复制、索引→ES）变成独立分布式组件。不再依赖单一数据库，而是"系统记录+衍生系统"组合。本质是把数据库设计原则提升到分布式基础设施层面。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：系统记录和衍生数据的区别是什么？

<Answer>
系统记录：数据的权威来源（True Source），是写入路径的终点。要求一致、可恢复、权威——如果衍生数据丢失，可以从系统记录重建；如果系统记录丢失则数据真正丢失。如OLTP数据库主库。衍生数据：从系统记录计算/转换得到的数据，是读路径的优化。可丢弃可重建——丢失后从系统记录重新计算即可恢复。如索引、物化视图、缓存、搜索索引。区别本质：系统记录是"真相源"，衍生数据是"从真相派生的便利"。实践意义：①衍生数据系统不需要自己的写入API，通过消费系统记录的变更（CDC）来更新；②衍生数据可以多种形式，各自优化不同查询模式。
</Answer>

**问题 2**：变更数据捕获（CDC）和事件溯源有什么区别？

<Answer>
CDC：从现有数据库的变更日志（如binlog）中捕获数据变更事件，转为事件流供衍生系统消费。系统记录仍然是数据库（以状态为真相源），CDC只是"观测"变更的副产品。优势——不改变现有架构，增量同步。适用——把OLTP数据库的变更同步到搜索索引、缓存、数据仓库。事件溯源：以事件本身作为系统记录，当前状态由回放事件得到。数据库只存事件日志，不存当前状态。优势——完整审计、可回放、可重建任意时刻状态。适用——金融交易、领域事件丰富的系统。核心区别：CDC的真相源是"当前状态"（事件是观测），事件溯源的真相源是"事件"（状态是派生）。
</Answer>

**问题 3**：Lambda架构和Kappa架构各自的核心思想是什么？有什么优缺点？

<Answer>
Lambda架构：批层+速度层+合并层。批层用批处理全量计算准确结果，速度层用流处理实时增量计算近似结果，查询时合并两层结果。优点——批层保证准确性（重跑可修正），速度层保证低延迟。缺点——维护两套代码（批和流逻辑需一致）、复杂度高。Kappa架构：只用流处理，用日志保存全量数据，需要重算时从头重放日志。优点——一套代码、一套引擎，简洁。缺点——要求流处理引擎足够强大（能处理回放、状态管理），且日志保留需足够长。趋势：批流融合（如Flink）——批是流的特例（有界流），一套引擎同时处理批和流，逐渐让Kappa架构成为可能。
</Answer>

**问题 4**：「拆解数据库」的核心思想是什么？它如何改变数据基础设施？

<Answer>
核心思想：把数据库内部的机制（WAL、物化视图、索引、触发器、复制）变成独立的分布式系统组件，用这些组件组合构建数据基础设施。映射关系：WAL→Kafka（日志）、物化视图→批/流计算输出、CDC→触发器+复制、索引→Elasticsearch。意义：①不再依赖单一数据库解决所有问题，而是用"系统记录+一组衍生系统"组合；②每个组件可以独立扩展和演化；③衍生数据从系统记录通过日志自动同步，保持最终一致；④本质是把数据库内部的设计原则提升到分布式基础设施层面。挑战：端到端一致性、运维复杂度、多系统协调。
</Answer>
