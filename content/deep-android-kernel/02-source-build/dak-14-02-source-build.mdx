# 第2章 Android源码下载及编译

本页依据林学森《深入理解Android内核设计思想》独立重构，不复制原文。版本锁定人民邮电出版社2014年5月首版、687页、ISBN 9787115348418，面向Android 4.3以上；全书为4篇22章、323个章/节/小节节点。

课程先复现首版Make构建、Binder、SurfaceFlinger、WMS、View、AudioFlinger、Ant与旧工具链，再用现代AOSP/Soong、Treble、ART和新调试工具建立迁移账本，绝不把第2版新增的虚拟机、安全与Gradle章节倒填进首版。

## 证据解释

第一份证据是版本证据：AOSP标签、repo manifest、主机工具链、产品目标和产物哈希必须同时保存。Android源码长期重构，同名类和服务在不同分支可能承担不同职责；跨版本拼接得到的“完整流程”实际上无法编译，也无法在单一设备上运行。

第二份证据是调用证据。针对“贯通Repo/Git下载、原生与定制产品编译、内核、烧录、系统映像、OTA和反编译”，从真实公开入口前向追踪，每次跨线程、跨进程、跨Java/Native、跨HAL/驱动边界都记录双方、数据形态、事务或函数编号和错误返回。manifest与标签、构建环境、产物哈希、boot/ramdisk/system解包、升级签名与烧录日志要能让另一位读者在相同标签上停在相同断点。

第三份证据是所有权证据。成功路径之外，主动让调用方退出、服务重启、缓冲区耗尽、输入损坏或超时发生，观察对象、引用计数、文件描述符、线程和映射是否释放。只画“谁调用谁”而不回答“谁负责释放”，无法解释系统泄漏、死锁和迟到回调。

第四份证据是迁移对照。现代AOSP可能以Soong、Treble、AIDL稳定接口、新渲染链或新调试工具替代首版机制。迁移时保持功能结果和故障样本不变，一次只替换一层；若线程、错误、性能或资源语义变化，先记录差异和回退，再更新结论。

```text
历史节点: 第2章 Android源码下载及编译
首版基线: Android 4.3 / 2014年第1版
现代候选: 待当前AOSP标签验证
不变量: 功能、线程进程、错误、资源释放
证据: manifest与标签、构建环境、产物哈希、boot/ramdisk/system解包、升级签名与烧录日志
回退: 任一不变量失败即恢复首版路径
```

## 本章回顾

从一次真实输入开始，依次回答源码属于哪个标签、入口在哪里、跨过哪些边界、每层保存什么状态、错误如何返回、资源由谁释放。再用manifest与标签、构建环境、产物哈希、boot/ramdisk/system解包、升级签名与烧录日志重放；无法在单一版本复现的结论退回研究阶段。

<Exercises>
**问题 1**：为什么必须保留20个正式节点？
<Answer>这些节点共同组成“贯通Repo/Git下载、原生与定制产品编译、内核、烧录、系统映像、OTA和反编译”的完整入口、机制、边界与证据链，删去节点会造成调用或所有权断裂。</Answer>

**问题 2**：最小正确性合同是什么？
<Answer>同一源码标签、构建目标和输入下，功能结果、线程进程、错误与资源释放必须确定且可重放。</Answer>

**问题 3**：怎样构造有效反例？
<Answer>主动让“跨分支下载源码和预编译件后仍宣称构建可复现，或烧录前不保存设备与回退映像”成立，再注入超时、服务退出、数据损坏或版本错配；出现死锁、泄漏、错位或不可复现即失败。</Answer>

**问题 4**：为什么类名和静态流程图不够？
<Answer>它们不能证明标签、运行入口、线程进程、对象身份、错误路径和释放结果，必须结合构建产物与运行日志。</Answer>

**问题 5**：怎样迁移而不改写首版？
<Answer>先保存Android 4.3首版行为基线，再一次替换一层，用相同输入和故障测试比较并记录差异与回退。</Answer>

**问题 6**：独立交接需要什么？
<Answer>需要源码版本卡、完整目录映射、构建命令与产物、manifest与标签、构建环境、产物哈希、boot/ramdisk/system解包、升级签名与烧录日志、失败实验、迁移账本和回退条件。</Answer>
</Exercises>
