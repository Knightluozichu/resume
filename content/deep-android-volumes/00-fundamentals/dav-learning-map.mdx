## 知识体系全景

<DavLearningMapDiagram />

《深入理解Android》（邓凡平著）是Android源码分析的标杆之作，分三卷系统讲解Android系统。卷I聚焦Java Framework层（Zygote、ClassLoader、插件化、JNI、Binder Java层），卷II深入Native层（init、Zygote native、属性系统、Binder native、ServiceManager、mediaserver），卷III对AMS/WMS/PMS等核心服务做深度源码剖析。全书以"源码驱动、逐层深入"为核心方法。

## 三卷递进路径

| 卷 | 章节 | 核心内容 | 依赖前序 |
|----|------|----------|----------|
| 卷I | Java Framework层 | Zygote/ClassLoader/插件化/JNI/Binder Java | 无 |
| 卷I | Native层与JNI | JNI注册/NDK/Java与C++交互 | Java Framework |
| 卷II | Init与Zygote | init.rc/属性系统/Zygote fork/启动流程 | Native层 |
| 卷II | Binder深度解析 | Binder驱动/native Binder/ServiceManager | Init与Zygote |
| 卷III | AMS深度解析 | Activity栈/组件调度/进程管理 | Binder |
| 卷III | WMS深度解析 | 窗口管理/Surface/输入系统 | AMS |
| 卷III | PMS深度解析 | APK解析/安装流程/权限管理 | AMS |
| 卷II | 媒体与音频框架 | MediaPlayer/AudioFlinger/Stagefright | Native层 |
| 全书 | 全书复习 | 知识图谱/选型矩阵/综合分析 | 全部 |

## 四大核心心智模型

### 模型一：分层架构

```
// Android系统分层——卷I/II/III贯穿的架构主线
// System Apps（系统应用）
//   └── Launcher / Settings / Phone
// Java API Framework（应用框架，卷I重点）
//   └── ActivityManager / WindowManager / PackageManager
//   └── ClassLoader / 插件化 / Context
// Native Libraries & Runtime（原生库与运行时，卷II重点）
//   └── ART虚拟机 / Binder原生库 / SurfaceFlinger
//   └── init / Zygote / 属性系统
// HAL（硬件抽象层）
//   └── Camera / Audio / Display HAL
// Linux Kernel（Linux内核）
//   └── Binder驱动 / ALSA / V4L2 / 电源管理
//
// 卷I看上层Java，卷II看中层Native，卷III看核心服务实现
```

<Callout type="info" title="核心认知">
全书三卷对应Android分层架构的不同切面：卷I从Java Framework层向下看（ClassLoader、插件化、Binder Java层），卷II从Native层向上看（init、Zygote、Binder native、属性系统），卷III从核心服务切入做源码级深度剖析（AMS、WMS、PMS）。三卷合起来覆盖从应用框架到内核驱动的完整链路。
</Callout>

### 模型三：跨进程通信主线

```
// Binder贯穿三卷的核心线索
// 卷I：Binder Java层——IBinder/Binder/ServiceManager(Java)
//   └── Proxy-Stub模型，AIDL生成代码
// 卷II：Binder Native层——binder.h/binder.c/ServiceManager(C++)
//   └── binder驱动交互，ioctl/BC_/BR_协议
// 卷III：核心服务都基于Binder
//   └── AMS/WMS/PMS注册到ServiceManager供App调用
//
// 理解Binder才能理解Android组件调度和服务化架构
```

### 模型四：启动流程主线

```
// 系统启动贯穿卷II的进程创建过程
// BootROM → Bootloader → Linux Kernel
//   → init（PID=1，卷II解析init.rc）
//     → ServiceManager（Binder服务管理）
//     → Zygote（孵化器，预加载资源）
//       → system_server（启动AMS/WMS/PMS）
//         → Launcher（桌面应用）
//
// Zygote fork + COW = 应用进程快速启动的秘密
```

<Callout type="success" title="学习建议">
按三卷顺序学习：先读卷I建立Java Framework层认知（ClassLoader、插件化、JNI），再读卷II理解Native层机制（init、Zygote、Binder native），最后读卷III深入核心服务源码（AMS、WMS、PMS）。每章读完后做对应复习题，三卷的知识在"Binder通信"和"启动流程"两条主线上交汇。
</Callout>

<Glossary>

<GlossaryItem term="三卷递进">
《深入理解Android》分三卷组织：卷I聚焦Java Framework层（Zygote、ClassLoader、插件化、JNI、Binder Java层），卷II深入Native层（init、Zygote native、属性系统、Binder native、ServiceManager），卷III对AMS/WMS/PMS等核心服务做源码级深度剖析。三卷从上到下、从框架到服务，构成完整知识体系。
</GlossaryItem>

<GlossaryItem term="源码驱动">
全书核心方法论。不空谈概念，而是从AOSP源码出发，逐行分析类定义、方法调用、数据结构，配合时序图理解控制流。每个知识点都追溯到具体源码文件和行号，建立"源码即文档"的认知。
</GlossaryItem>

<GlossaryItem term="Zygote">
Android进程孵化器，卷I和卷II均涉及。卷I从Java层看ZygoteInit如何预加载类和资源、fork system_server；卷II从Native层看app_main.cpp如何启动Zygote进程、fork机制实现。Zygote利用COW（写时复制）技术，所有应用进程由Zygote fork创建，共享预加载资源，显著提升启动速度。
</GlossaryItem>

<GlossaryItem term="Binder双层架构">
Binder通信在卷I和卷II分别从Java层和Native层剖析。卷I讲IBinder/Binder/ServiceManager的Java封装和AIDL Proxy-Stub；卷II讲binder驱动的ioctl协议、binder_proc/binder_node/binder_ref数据结构、ServiceManager的C++实现。两层通过JNI桥接，共同构成完整的跨进程通信体系。
</GlossaryItem>

**问题 1**：全书三卷的知识体系结构和递进逻辑是什么？

<Answer>
全书分三卷，覆盖Android系统从Java框架到Native底层到核心服务的完整链路：卷I——Java Framework层，包括Android架构总览、Zygote（Java层ZygoteInit预加载与fork）、ClassLoader与插件化原理（DexClassLoader/PathClassLoader/双亲委派/Activity插件化生命周期）、JNI原理（MediaScanner案例、JNI注册与签名）、Binder Java层（IBinder/Binder/ServiceManager Java封装/AIDL Proxy-Stub）；卷II——Native层，包括init进程（init.rc解析/属性系统/守护进程）、Zygote Native层（app_main.cpp/fork+COW/system_server启动）、Binder Native层（binder驱动/mmap一次拷贝/binder_proc/binder_node/binder_ref/BC_/BR_协议）、ServiceManager（C++实现/服务注册查询/ handle=0）、mediaserver进程；卷III——核心服务深度，包括AMS（Activity栈管理/组件调度/OOM Adj/进程管理）、WMS（Window/Surface管理/输入系统/VSync）、PMS（APK解析/安装流程/权限管理/签名校验）、音频框架（AudioFlinger/AudioTrack/Stagefright）。递进逻辑：先从卷I理解Java框架层，再从卷II深入Native底层机制，最后从卷III做核心服务源码级剖析。两条主线交汇：Binder通信（卷I Java层+卷II Native层）和启动流程（卷I+卷II的Zygote/init）。
</Answer>

**问题 2**：全书各章节之间存在哪些交叉关联？

<Answer>
交叉关联：①Java Framework×Native JNI——卷I的JNI原理是Java层调用Native层的桥梁，ClassLoader加载的dex通过JNI调用Native C++代码；②JNI×Binder——卷I的Binder Java层通过JNI调用卷II的Binder Native层，Java的transact()最终调用Native的binder_transaction；③Init×Zygote——卷II的init进程解析init.rc启动Zygote，Zygote由init创建并注册为服务；④Zygote×AMS——system_server由Zygote fork创建，system_server承载AMS/WMS/PMS（卷III），应用进程也由Zygote fork；⑤Binder×AMS——AMS运行在system_server，App通过Binder（卷I Java层+卷II Native层）与AMS交互，Binder是组件调度通信基础；⑥AMS×WMS——Activity启动时AMS通过WMS添加窗口；⑦AMS×PMS——AMS启动组件时通过PMS查询组件信息；⑧Native×Media——mediaserver进程（卷II）承载AudioFlinger（卷III音频），遵循同样的Binder C/S架构。
</Answer>

**问题 3**：贯穿全书的两条核心主线是什么？

<Answer>
两条核心主线：①Binder通信主线——贯穿卷I和卷II。卷I从Java层看Binder：IBinder接口、Binder类、ServiceManager(Java)封装、AIDL编译器自动生成Proxy和Stub，transact()方法将调用打包为Parcel通过ioctl发送。卷II从Native层看Binder：binder驱动的mmap一次拷贝原理、binder_proc/binder_node/binder_ref核心数据结构、BC_TRANSACTION/BR_TRANSACTION协议命令、ServiceManager的C++实现（handle=0硬编码）。两层通过JNI桥接，Java的transact()调用Native的binder_transaction()。卷III的核心服务（AMS/WMS/PMS）都基于这条主线向App提供跨进程服务。②启动流程主线——贯穿卷I和卷II。init进程（PID=1）解析init.rc启动关键服务，包括ServiceManager和Zygote。Zygote预加载系统类和资源，启动ART虚拟机。system_server由Zygote fork创建，启动AMS/WMS/PMS等核心服务。应用进程也由Zygote通过fork+COW快速创建。
</Answer>

**问题 4**：全书的核心方法论是什么？如何运用它分析实际系统问题？

<Answer>
核心方法论是"源码驱动、逐层深入"：①提出问题——明确要分析的功能或现象；②定位源码——在AOSP中找到对应的类、方法、数据结构；③逐行分析——用类图、时序图、数据结构图配合，理清控制流和数据流；④关联机制——理解该功能依赖的底层机制（Binder、Zygote、ClassLoader等）；⑤归纳总结——提炼设计模式和心智模型。运用举例——分析"App启动慢"：先从卷I的Java层定位ActivityThread.main和Application.onCreate源码，检查初始化耗时；再从卷II的Zygote层面检查fork+COW是否正常、预加载资源是否充足；再从卷III的AMS层面检查ProcessRecord调度和Activity栈管理；最后从Binder层面检查跨进程通信是否有性能瓶颈。综合运用三卷知识，从源码层面定位问题根因。
</Answer>
