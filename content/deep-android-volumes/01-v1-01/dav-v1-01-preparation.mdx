## 从一个可失败的问题开始

卷I 第1章 阅读前的准备工作不是类名清单，而是在android-2.2_r1中回答：建立Android 2.2四层架构、源码构建与阅读工具的统一坐标。先预测请求经过的线程、进程与对象所有者，再运行正常样本；如果android-2.2_r1标签、构建产物、进程清单、源码索引与Busybox命令结果不能指出首个变化，本页结论仍不可交接。

本章不变量是在android-2.2_r1固定输入下，建立Android 2.2四层架构、源码构建与阅读工具的统一坐标的入口身份、状态拥有者、成功结果、错误返回和资源释放均可重复观察。将“把现代Android Studio、Soong与ART行为倒填到Froyo源码”作为反例，必须在同一版本、同一输入下看到确定的错误或状态分叉，并能恢复到基线。

```bash
mkdir -p aosp-android-2.2_r1
cd aosp-android-2.2_r1
repo init -u https://android.googlesource.com/platform/manifest -b android-2.2_r1
repo sync -c

# 只在可恢复的同版本模拟器或测试机采集
adb shell ps
adb shell getprop ro.build.fingerprint
```

运行前保存主机工具链、manifest与产品目标；这些历史分支通常需要隔离的旧工具链环境。诊断命令只在可恢复模拟器或测试机执行，账号、媒体与设备标识使用隔离样本；现代设备输出不得冒充android-2.2_r1结果。
