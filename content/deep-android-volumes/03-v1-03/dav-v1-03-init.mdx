## 从一个可失败的问题开始

卷I 第3章 深入理解init不是类名清单，而是在android-2.2_r1中回答：从PID 1解析init.rc、启动service并建立属性服务。先预测请求经过的线程、进程与对象所有者，再运行正常样本；如果action/service解析表、进程父子关系、property socket请求、重启策略与失败日志不能指出首个变化，本页结论仍不可交接。

本章不变量是在android-2.2_r1固定输入下，从PID 1解析init.rc、启动service并建立属性服务的入口身份、状态拥有者、成功结果、错误返回和资源释放均可重复观察。将“把init.rc当静态脚本，忽略事件队列、服务状态和属性权限”作为反例，必须在同一版本、同一输入下看到确定的错误或状态分叉，并能恢复到基线。

## 章专属复现实验

```bash
mkdir -p aosp-android-2.2_r1
cd aosp-android-2.2_r1
repo init -u https://android.googlesource.com/platform/manifest -b android-2.2_r1
repo sync -c

# 只在可恢复的同版本模拟器或测试机采集
adb shell getprop init.svc.zygote
adb shell ps
```

复现卷I 第3章 深入理解init前先保存主机工具链、manifest与产品目标；android-2.2_r1历史分支通常需要隔离的旧工具链环境。与从PID 1解析init.rc、启动service并建立属性服务有关的诊断命令只在可恢复模拟器或测试机执行，账号、媒体与设备标识使用隔离样本；现代设备输出不得冒充android-2.2_r1结果。
