## PMS全景

<DavPmsDeepDiagram />

卷III对PMS（PackageManagerService）做源码级深度剖析。PMS运行在system_server进程，负责APK的解析、安装、权限管理、签名校验和组件查询。AMS启动Activity/Service时通过PMS查询组件信息。PMS是包管理的核心，也是应用安装和运行的入口。

## APK文件结构

```
// APK文件结构（卷III分析基础）
//
// app.apk（本质是ZIP文件）
// ├── AndroidManifest.xml    // 编译后的二进制XML
// ├── classes.dex            // Dalvik字节码（可能有多个dex）
// ├── classes2.dex
// ├── resources.arsc         // 编译后的资源索引
// ├── res/                   // 资源文件（layout/drawable/values）
// ├── assets/                // 原始资源
// ├── lib/                   // SO库（按ABI分目录）
// │   ├── arm64-v8a/
// │   │   └── libnative.so
// │   └── armeabi-v7a/
// │       └── libnative.so
// ├── META-INF/              // 签名信息
// │   ├── MANIFEST.MF        // 文件清单+SHA-1摘要
// │   ├── CERT.SF            // 签名文件
// │   └── CERT.RSA           // 签名证书（RSA公钥）
// └──META-INF/               // 签名块（V2/V3签名）
//
// AndroidManifest.xml关键内容:
//   &lt;manifest package="com.example.app"&gt;
//     &lt;uses-permission android:name="android.permission.INTERNET"/&gt;
//     &lt;application android:name=".App"&gt;
//       &lt;activity android:name=".MainActivity"&gt;
//         &lt;intent-filter&gt;
//           &lt;action android:name="android.intent.action.MAIN"/&gt;
//           &lt;category android:name="android.intent.category.LAUNCHER"/&gt;
//         </intent-filter>
//       </activity>
//       &lt;service android:name=".MyService"/&gt;
//       &lt;receiver android:name=".MyReceiver"/&gt;
//       &lt;provider android:name=".MyProvider"
//         android:authorities="com.example.provider"/>
//     </application>
//   </manifest>
```

## PackageParser解析

```
// PackageParser解析APK（卷III核心源码）
// frameworks/base/core/java/android/content/pm/PackageParser.java
//
// 解析流程:
//   PackageParser parser = new PackageParser();
//   // 1. 解析AndroidManifest.xml
//   Package pkg = parser.parsePackage(apkFile, flags);
//
// parsePackage()内部:
//   1. 解压APK，读取AndroidManifest.xml（二进制XML）
//   2. 用AssetManager + Resources解析二进制XML
//   3. 解析&lt;manifest&gt;标签:
//      → package名、versionCode、versionName
//   4. 解析&lt;uses-permission&gt;:
//      → 收集请求的权限列表
//   5. 解析&lt;application&gt;:
//      → Application信息（name/theme/icon）
//   6. 解析&lt;activity&gt;/&lt;service&gt;/&lt;receiver&gt;/&lt;provider&gt;:
//      → 创建Activity/Service/Receiver/Provider对象
//      → 解析&lt;intent-filter&gt;收集Action/Category/Data
//   7. 返回Package对象
//
// Package核心字段:
//   public final static class Package {
//       public String packageName;        // 包名
//       public String applicationName;    // Application类名
//       public ArrayList<Activity> activities;
//       public ArrayList<Service> services;
//       public ArrayList<Activity> receivers;
//       public ArrayList<Provider> providers;
//       public ArrayList<Permission> permissions;
//       public ArrayList<String> requestedPermissions;
//       public Signatures signatures;     // 签名
//       public String mAppId;             // 应用UID
//   }
//
// // 每个组件（Activity/Service/Receiver/Provider）:
// //   包含 name（类名）、exported（是否可被其他App调用）、
// //   intentFilters（Intent过滤器列表）
```

## APK安装六步流程

```
// APK安装流程（卷III核心分析）
// frameworks/base/services/core/java/com/android/server/pm/PackageManagerService.java
//
// ┌──────────┐     ┌──────────────┐     ┌──────────┐
// │ App/系统  │     │ system_server│     │ installd │
// │          │     │    (PMS)     │     │ (守护进程)│
// │ ① 安装请求│────→│              │     │          │
// │   (Intent)│     │ ② 拷贝APK    │     │          │
// │          │     │   到/data/app│     │          │
// │          │     │ ③ PackageParser│   │          │
// │          │     │   解析APK    │     │          │
// │          │     │ ④ 签名校验   │     │          │
// │          │     │   verifySignatures│ │        │
// │          │     │ ⑤ 权限检查   │     │          │
// │          │     │   grantPermissions│ │        │
// │          │     │ ⑥ dex2oat编译 │     │          │
// │          │     │ ──Socket──→  │     │ 编译dex   │
// │          │     │              │     │ →OAT文件  │
// │          │     │ ⑦ 注册组件   │     │          │
// │          │     │   写packages.xml │ │          │
// │ ←─────── │ 安装完成回调  │     │          │
// └──────────┘     └──────────────┘     └──────────┘
//
// 关键源码方法:
//   PMS.installPackage()
//     → installPackageWithVerification()
//       → InstallParams  // 安装参数封装
//       → handler.post(() -> {
//           // 1. 拷贝APK到 /data/app/&lt;包名&gt;/
//           // 2. 解析APK: PackageParser.parsePackage()
//           // 3. 签名校验: verifySignatures()
//           // 4. 权限授予: grantRuntimePermissions()
//           // 5. dex2oat: mInstaller.dexopt()
//           //    → installd守护进程执行 dex2oat 编译
//           // 6. 写入 packages.xml（持久化组件信息）
//           // 7. 通知AMS组件变更
//         })
```

<Callout type="info" title="dex2oat编译">
dex2oat是ART的编译器，将DEX字节码编译为机器码（OAT文件）。安装时PMS通过installd守护进程调用dex2oat，将classes.dex编译为app.odex（OAT文件）。运行时ART虚拟机直接加载OAT中的机器码，无需运行时解释执行。Android 7.0后采用AOT+JIT混合编译：安装时只做部分编译（速度优先），运行时JIT热点编译，空闲时后台全量AOT编译。
</Callout>

## 权限管理

```
// 权限管理——PMS核心职责（卷III分析）
//
// 权限分类:
//   1. 普通权限（Normal）: INSTALL后自动授予
//      如 INTERNET, VIBRATE
//   2. 危险权限（Dangerous）: 需运行时请求
//      如 CAMERA, READ_CONTACTS, ACCESS_FINE_LOCATION
//   3. 签名权限（Signature）: 需相同签名才授予
//      如 BIND_DEVICE_ADMIN
//   4. 特权权限（Privileged）: 需特权应用（/system/priv-app）
//
// 权限授予流程（Android 6.0+运行时权限）:
//   // 安装时（PMS）:
//   //   - 普通权限: 自动授予
//   //   - 危险权限: 记录但不授予，等待运行时请求
//   //   - 签名权限: 检查签名匹配
//
//   // 运行时（App请求）:
//   //   Activity.requestPermissions(READ_CONTACTS)
//   //     → 系统弹出权限对话框
//   //     → 用户授权 → PMS.grantRuntimePermission()
//   //     → 写入 /data/system/runtime-permissions.xml
//
// PMS权限校验源码:
//   boolean checkUidPermission(String permName, int uid) {
//       // 1. 检查UID是否被授予该权限
//       HashSet<String> perms = mSystemPermissions.get(uid);
//       if (perms != null && perms.contains(permName)) {
//           return PackageManager.PERMISSION_GRANTED;
//       }
//       // 2. 检查权限组
//       // 3. 返回 PERMISSION_DENIED
//       return PackageManager.PERMISSION_DENIED;
//   }
//
//   // AMS调用方权限校验:
//   //   int callingUid = Binder.getCallingUid();  // Binder内核层获取
//   //   int result = mPMS.checkUidPermission(perm, callingUid);
//   //   if (result != GRANTED) throw new SecurityException();
```

## 签名校验

```
// 签名校验——PMS安全核心（卷III分析）
//
// APK签名方案:
//   V1签名（JAR签名）: 基于MANIFEST.MF + CERT.SF + CERT.RSA
//   V2签名（APK签名V2）: 基于整个APK文件的签名块（Android 7.0+）
//   V3签名（APK签名V3）: 支持密钥轮换（Android 9.0+）
//
// V1签名校验流程:
//   1. 读取MANIFEST.MF: 每个文件的SHA-1摘要
//   2. 读取CERT.SF: MANIFEST.MF的签名
//   3. 读取CERT.RSA: 签名证书（X.509）
//   4. 用证书公钥验证CERT.SF的签名
//   5. 重新计算每个文件SHA-1，与MANIFEST.MF对比
//   // 确保APK内容未被篡改
//
// PMS签名校验源码:
//   boolean verifySignatures(Package pkg) {
//       // 1. 提取APK中的签名证书
//       Signature[] signatures = collectCertificates(pkg);
//       // 2. 如果是更新安装，与已有签名对比
//       if (mSettings.isExistingPackage(pkg.packageName)) {
//           Signature[] existing = mSettings.getSignatures(pkg.packageName);
//           if (!Signature.compareExactly(signatures, existing)) {
//               // 签名不一致 → 拒绝安装
//               return false;
//           }
//       }
//       // 3. 签名权限检查: 签名权限需匹配
//       // 4. 共享UID检查: sharedUser需相同签名
//       return true;
//   }
//
// 签名的作用:
//   - 完整性校验: APK内容未被篡改
//   - 身份认证: 确认APK来自同一开发者
//   - 权限控制: 签名权限只授予同签名应用
//   - 更新安装: 只有同签名才能更新已安装应用
```

<Glossary>

<GlossaryItem term="PackageManagerService(PMS)">
运行在system_server进程的核心服务，负责包管理。解析APK（PackageParser）、安装APK（六步流程）、管理权限（运行时权限校验）、校验签名（V1/V2/V3）、查询组件信息（供AMS调度使用）。持久化组件信息到packages.xml，通过installd守护进程执行dex2oat编译。
</GlossaryItem>

<GlossaryItem term="PackageParser">
PMS解析APK的核心类。parsePackage()解压APK读取AndroidManifest.xml（二进制XML），解析manifest/application/activity/service/receiver/provider标签，创建Package对象（包含包名/组件列表/权限列表/签名）。每个组件含name（类名）、exported、intentFilters。
</GlossaryItem>

<GlossaryItem term="APK安装六步">
①拷贝APK到/data/app/；②PackageParser解析APK获取Package对象；③签名校验（verifySignatures，确保完整性和身份认证）；④权限检查与授予（普通权限自动授予，危险权限记录待运行时请求）；⑤dex2oat编译（通过installd将DEX编译为OAT机器码）；⑥注册组件写入packages.xml并通知AMS。
</GlossaryItem>

<GlossaryItem term="dex2oat">
ART编译器，将DEX字节码编译为机器码（OAT文件）。安装时PMS通过installd调用dex2oat编译。Android 7.0+采用AOT+JIT混合：安装时部分编译（速度优先），运行时JIT热点编译，空闲时后台全量AOT。运行时ART直接加载OAT机器码，无需解释执行。
</GlossaryItem>

<GlossaryItem term="运行时权限">
Android 6.0+的权限模型。危险权限（CAMERA/LOCATION等）安装时不授予，需运行时通过requestPermissions()请求。PMS.grantRuntimePermission()授权后写入runtime-permissions.xml。PMS.checkUidPermission()供系统服务校验调用方权限，配合Binder的内核层UID记录实现安全控制。
</GlossaryItem>

<GlossaryItem term="APK签名校验">
PMS安全核心。V1签名基于MANIFEST.MF（文件SHA-1摘要）+CERT.SF+CERT.RSA（X.509证书）。V2/V3签名基于APK文件签名块。校验流程：提取证书→用公钥验签→重算文件摘要对比→更新安装时与已有签名比对（必须一致才能更新）。签名保证APK完整性、身份认证和权限控制。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：APK的文件结构是什么？PackageParser如何解析APK？

<Answer>
APK文件结构（本质是ZIP）：①AndroidManifest.xml——编译后的二进制XML，声明包名、组件、权限、应用配置；②classes.dex/classes2.dex——Dalvik字节码（应用代码）；③resources.arsc——编译后的资源索引；④res/——资源文件（layout/drawable/values）；⑤assets/——原始资源；⑥lib/——SO库（按ABI分目录arm64-v8a/armeabi-v7a等）；⑦META-INF/——签名信息（MANIFEST.MF文件清单+SHA-1摘要、CERT.SF签名文件、CERT.RSA签名证书）；⑧V2/V3签名块（APK文件中的签名块）。PackageParser解析流程：①parsePackage(apkFile, flags)解压APK读取AndroidManifest.xml；②用AssetManager和Resources解析二进制XML；③解析&lt;manifest&gt;标签获取包名/packageName/versionCode/versionName；④解析&lt;uses-permission&gt;收集请求的权限列表（requestedPermissions）；⑤解析&lt;application&gt;获取Application信息（applicationName/theme/icon）；⑥解析&lt;activity&gt;/&lt;service&gt;/&lt;receiver&gt;/&lt;provider&gt;创建对应组件对象，每个组件含name（类名）、exported（是否可被其他App调用）、intentFilters（Action/Category/Data列表）；⑦返回Package对象。Package核心字段：packageName、activities/services/receivers/providers组件列表、requestedPermissions、signatures签名、mAppId应用UID。
</Answer>

**问题 2**：详细描述APK安装的六步流程。

<Answer>
APK安装六步流程（PMS.installPackage()→installPackageWithVerification()）：①拷贝APK——将APK文件拷贝到/data/app/&lt;包名&gt;/目录下，重命名APK文件。②PackageParser解析APK——调用PackageParser.parsePackage(apkFile, flags)解析AndroidManifest.xml，创建Package对象（包含组件列表/权限列表/包名等）。③签名校验——调用verifySignatures(pkg)提取APK签名证书，验证签名完整性（重算文件SHA-1摘要与MANIFEST.MF对比），如果是更新安装则与已有签名对比（必须完全一致才能更新）。④权限检查与授予——grantRuntimePermissions()：普通权限（INTERNET/VIBRATE等）安装时自动授予，危险权限（CAMERA/LOCATION等）记录但不授予（等待运行时请求），签名权限检查签名匹配，特权权限检查是否在/system/priv-app。⑤dex2oat编译——通过installd守护进程（Socket通信）调用dex2oat，将classes.dex编译为OAT文件（机器码），存放在/data/app/&lt;包名&gt;/oat/目录。Android 7.0+采用AOT+JIT混合编译：安装时只做部分编译（速度优先），运行时JIT热点编译，空闲时后台全量AOT。⑥注册组件并持久化——将Package信息写入/data/system/packages.xml（持久化包名/组件/权限/签名映射），通知AMS组件变更（AMS可查询到新安装的组件）。安装完成后通过Intent回调通知调用方。
</Answer>

**问题 3**：Android的权限管理模型是什么？运行时权限如何工作？

<Answer>
Android权限管理模型分四类：①普通权限（Normal protectionLevel）——如INTERNET/VIBRATE，安装时自动授予，无需用户确认；②危险权限（Dangerous）——如CAMERA/READ_CONTACTS/ACCESS_FINE_LOCATION，涉及用户隐私，安装时不授予，需运行时请求用户授权；③签名权限（Signature）——如BIND_DEVICE_ADMIN，需与声明该权限的应用具有相同签名才授予；④特权权限（Privileged）——需应用预装在/system/priv-app目录。运行时权限工作流程（Android 6.0+）：①安装时——PMS.installPackage()中，普通权限自动授予写入packages.xml，危险权限记录在requestedPermissions但不授予，写入/data/system/runtime-permissions.xml标记为未授予。②运行时请求——App调用Activity.requestPermissions(READ_CONTACTS)→系统弹出权限对话框→用户选择授权或拒绝。③授权处理——用户授权后PMS.grantRuntimePermission(permName, packageName)将权限状态改为GRANTED写入runtime-permissions.xml。④权限校验——系统服务（如AMS/PMS）通过Binder.getCallingUid()获取调用方UID（内核层记录不可伪造），调用PMS.checkUidPermission(permName, uid)检查该UID是否被授予该权限，未授权则抛出SecurityException。⑤权限组——危险权限按组分类（如CONTACTS组含READ/WRITE_CONTACTS），授权组中一个权限时同组其他权限也自动授予。
</Answer>

**问题 4**：APK签名校验的流程是什么？签名有什么作用？V1和V2签名的区别？

<Answer>
APK签名校验流程：①提取证书——PMS.verifySignatures()调用collectCertificates(pkg)从META-INF/目录读取CERT.RSA中的X.509证书，提取签名公钥。②验证签名完整性——V1签名：读取MANIFEST.MF（记录每个文件的SHA-1摘要），读取CERT.SF（MANIFEST.MF内容的签名），用证书公钥验证CERT.SF的RSA签名，确认MANIFEST.MF未被篡改；重新计算APK中每个文件的SHA-1摘要，与MANIFEST.MF中记录的摘要对比，确认文件内容未被篡改。③更新安装校验——如果是更新已安装应用，与已有签名对比（Signature.compareExactly），签名必须完全一致才能更新（防止恶意应用冒充更新）。签名的四大作用：①完整性校验——确保APK内容未被篡改（任何文件修改都会导致摘要不匹配）；②身份认证——确认APK来自同一开发者（同一证书=同一开发者）；③权限控制——签名权限只授予同签名应用（如系统应用间的特权通信）；④更新安装——只有同签名的应用才能更新已安装应用（防止恶意应用冒充更新覆盖）。V1签名（JAR签名）基于文件：对APK内每个文件单独计算SHA-1摘要存入MANIFEST.MF，CERT.SF签名MANIFEST.MF，CERT.RSA包含证书。缺点是只签名文件内容不签名ZIP结构，且需解析全部文件。V2签名（APK签名V2，Android 7.0+）基于整个APK：在APK文件中插入签名块（APK Signing Block），对APK的所有内容（除签名块本身）按区域分段签名。优点是覆盖整个APK文件（包括ZIP结构），校验更快（无需解压全部文件），安全性更高。V3签名（Android 9.0+）支持密钥轮换——可声明新旧密钥的继承关系，支持密钥更新而不丢失应用身份。
</Answer>
