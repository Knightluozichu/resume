## 从一个可失败的问题开始

卷III 第1章 开发环境部署不是类名清单，而是在android-4.2.2_r1中回答：建立Android 4.2.2源码获取、编译、双IDE阅读与Java/Native调试环境。先预测请求经过的线程、进程与对象所有者，再运行正常样本；如果android-4.2.2_r1标签、out产物、Eclipse/SourceInsight索引、JDWP与gdb断点不能指出首个变化，本页结论仍不可交接。

本章不变量是在android-4.2.2_r1固定输入下，建立Android 4.2.2源码获取、编译、双IDE阅读与Java/Native调试环境的入口身份、状态拥有者、成功结果、错误返回和资源释放均可重复观察。将“用Android 5以上迁移后的目录解释4.2.2源码位置”作为反例，必须在同一版本、同一输入下看到确定的错误或状态分叉，并能恢复到基线。

## 章专属复现实验

```bash
mkdir -p aosp-android-4.2.2_r1
cd aosp-android-4.2.2_r1
repo init -u https://android.googlesource.com/platform/manifest -b android-4.2.2_r1
repo sync -c

# 只在可恢复的同版本模拟器或测试机采集
adb shell getprop ro.build.fingerprint
adb shell ps
```

运行前保存主机工具链、manifest与产品目标；这些历史分支通常需要隔离的旧工具链环境。诊断命令只在可恢复模拟器或测试机执行，账号、媒体与设备标识使用隔离样本；现代设备输出不得冒充android-4.2.2_r1结果。
