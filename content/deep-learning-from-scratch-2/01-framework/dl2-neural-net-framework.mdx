## 为什么要设计框架

在第一部中，我们用 NumPy 写死了一切：前向传播是手动的矩阵乘法，反向传播是手写的梯度公式。这种方式适合学习原理，但当网络变复杂时，手写梯度既繁琐又容易出错。

框架要解决的核心问题是：**让用户只定义前向计算，梯度由框架自动算出**。

## DeZero 的设计目标

<Callout type="info">

**设计哲学**：DeZero 追求「最小实现，最大理解」。它不追求性能和功能完备，而是用最少的代码实现一个「麻雀虽小五脏俱全」的框架，让每个设计决策都清晰可见。

</Callout>

DeZero 的三个核心目标：

| 目标 | 说明 |
|------|------|
| 自动微分 | 用户只写前向计算，框架自动构建计算图并反向求导 |
| 可组合 | 运算可像积木一样组合，构建任意复杂的计算流程 |
| 可扩展 | 新增运算只需继承 Function 并实现 forward/backward |

## 框架分层架构

DeZero 采用四层架构，自底向上逐层封装：

```python
# 第 4 层：工程层（Layer / Model / Optimizer）
#    将运算和参数封装为可复用模块
#
# 第 3 层：引擎层（自动微分 / 反向传播）
#    沿计算图反向传递梯度，实现自动求导
#
# 第 2 层：运算层（Function 子类）
#    定义具体运算（加、乘、sigmoid 等），连接计算图
#
# 第 1 层：数据层（Variable）
#    包装 NumPy 数组，记录计算图连接关系
```

### 各层职责

| 层次 | 核心类 | 职责 |
|------|--------|------|
| 数据层 | Variable | 包装数据、记录 creator、持有 grad |
| 运算层 | Function | 定义 forward/backward、连接计算图 |
| 引擎层 | backward 方法 | 拓扑排序、梯度反向传播 |
| 工程层 | Layer/Model/Optimizer | 参数管理、网络组合、训练循环 |

## 核心抽象：Variable 与 Function

DeZero 的世界只有两种东西：**数据（Variable）** 和 **运算（Function）**。

```python
class Variable:
    def __init__(self, data):
        self.data = data        # 前向值（NumPy 数组）
        self.grad = None        # 梯度（反向传播后填入）
        self.creator = None     # 产生它的 Function（计算图链接）

class Function:
    def __call__(self, input):
        x = input.data
        y = self.forward(x)          # 前向计算
        output = Variable(y)
        output.creator = self        # 记录计算图链接
        self.input = input           # 保存输入（反向传播用）
        return output

    def forward(self, x):
        raise NotImplementedError()

    def backward(self, gy):
        raise NotImplementedError()
```

<Callout type="warning">

**关键设计**：`output.creator = self` 这一行是计算图的灵魂——它把输出和产生它的运算连接起来。通过 creator 链，DeZero 能从任意输出回溯到所有输入，这是反向传播的基础。

</Callout>

## 定义即计算图

DeZero 的核心哲学是「定义即计算图」：用户写的每一行前向计算代码，都在同时构建计算图。

```python
# 用户代码：只写前向计算
x = Variable(np.array(2.0))
a = square(x)      # a = x^2
b = exp(a)          # b = e^a
y = add(b, x)       # y = b + x

# 框架自动构建了计算图：
# x ──→ square ──→ a ──→ exp ──→ b ──┐
# │                                   ├──→ add ──→ y
# └───────────────────────────────────┘

# 反向传播：框架自动算出 y 对 x 的导数
y.backward()
print(x.grad)  # 自动计算，无需手写梯度公式
```

## DeZero 与 PyTorch 的对应

| DeZero | PyTorch | 说明 |
|--------|---------|------|
| Variable | Tensor (requires_grad) | 数据容器 |
| Function | autograd.Function | 运算单元 |
| backward() | backward() | 反向传播 |
| Layer | nn.Module | 模块化层 |
| Model | nn.Module (嵌套) | 网络容器 |
| Optimizer | optim.SGD 等 | 优化器 |

<Glossary>

<GlossaryItem term="DeZero 框架">
本书从零打造的深度学习框架。采用四层架构：数据层（Variable）、运算层（Function）、引擎层（自动微分）、工程层（Layer/Model/Optimizer）。设计目标是自动微分、可组合、可扩展，用最小实现让读者理解框架内部机制。
</GlossaryItem>

<GlossaryItem term="定义即计算图">
DeZero 的核心设计哲学：用户写的每一行前向计算代码都在同时构建计算图。无需像第一部那样手动维护计算图结构，框架在 `Function.__call__` 中自动通过 creator 链接记录运算关系。
</GlossaryItem>

<GlossaryItem term="creator 链">
Variable 通过 creator 属性指向产生它的 Function，Function 通过 input 属性指向它的输入 Variable。这条 creator 链构成计算图的边，是反向传播回溯的路径。
</GlossaryItem>

<GlossaryItem term="forward/backward">
Function 的两个核心方法。forward 定义前向运算（输入→输出），backward 定义反向传播（输出梯度→输入梯度）。二者必须满足导数对应关系：backward 的输出 = forward 的导数 × 输入梯度。
</GlossaryItem>

<GlossaryItem term="四层架构">
DeZero 的分层设计：①数据层——Variable 包装数据并记录计算图；②运算层——Function 子类定义具体运算；③引擎层——backward 方法沿计算图反向传递梯度；④工程层——Layer/Model/Optimizer 封装参数与训练流程。自底向上逐层抽象。
</GlossaryItem>

<GlossaryItem term="可扩展性">
DeZero 新增运算只需继承 Function 并实现 forward/backward 两个方法，无需修改框架其他代码。这种开闭原则（对扩展开放，对修改关闭）是框架设计的核心目标。
</GlossaryItem>

</Glossary>

### 问题 1

DeZero 框架的核心设计目标是什么？它要解决什么问题？

<Answer>

DeZero 框架的核心设计目标是「自动微分」——用户只写前向计算，框架自动构建计算图并反向求导。它要解决的问题是：在第一部中用 NumPy 手写神经网络时，前向传播是手动的矩阵乘法，反向传播是手写的梯度公式。当网络变复杂时，手写梯度既繁琐又容易出错。DeZero 通过 Variable 包装数据、Function 抽象运算、creator 链记录计算图，让框架自动完成梯度计算。此外还有两个目标：①可组合——运算可像积木一样组合，构建任意复杂的计算流程；②可扩展——新增运算只需继承 Function 并实现 forward/backward，无需修改框架其他代码。DeZero 追求「最小实现，最大理解」，不追求性能而是让每个设计决策清晰可见。
</Answer>

### 问题 2

DeZero 的四层架构是什么？各层的核心类和职责是什么？

<Answer>

DeZero 采用四层架构，自底向上：①数据层——核心类 Variable，职责是包装 NumPy 数组（data 属性）、记录计算图链接（creator 属性）、持有梯度（grad 属性）。②运算层——核心类 Function 及其子类，职责是定义具体运算的 forward（前向计算）和 backward（反向梯度），在 `__call__` 中通过 `output.creator = self` 连接计算图。③引擎层——核心是 Variable.backward 方法，职责是对计算图做拓扑排序，沿图反向传递梯度，实现自动求导。④工程层——核心类 Layer/Model/Optimizer，职责是封装参数管理（权重收集与梯度清零）、网络组合（多层嵌套）、训练循环（参数更新）。这种分层设计使每层职责单一，自底向上逐层抽象。
</Answer>

### 问题 3

解释「定义即计算图」的设计哲学，并用代码说明。

<Answer>

「定义即计算图」是 DeZero 的核心设计哲学：用户写的每一行前向计算代码都在同时构建计算图，无需手动维护图结构。框架在 `Function.__call__` 中自动通过 creator 链记录运算关系。代码示例：`x = Variable(np.array(2.0)); a = square(x); b = exp(a); y = add(b, x)`。用户只写了前向计算，但框架已自动构建了计算图：x 经过 square 得到 a，a 经过 exp 得到 b，b 和 x 经过 add 得到 y。每一步 `__call__` 都执行 `output.creator = self`，把输出和运算连接起来。之后调用 `y.backward()` 时，框架沿 creator 链从 y 回溯到 x，自动用链式法则算出 y 对 x 的导数并存入 x.grad。用户完全不需要手写梯度公式。
</Answer>

### 问题 4

DeZero 与 PyTorch 有何对应关系？理解 DeZero 对使用 PyTorch 有何帮助？

<Answer>

DeZero 与 PyTorch 的对应关系：①Variable ↔ Tensor（requires_grad=True）——都是数据容器，都记录计算图。②Function ↔ autograd.Function——都定义 forward/backward，都是计算图节点。③backward() ↔ backward()——都沿计算图反向传递梯度。④Layer ↔ nn.Module——都封装参数与运算，都可嵌套组合。⑤Model ↔ nn.Module（嵌套）——都组合多个层构成网络。⑥Optimizer ↔ optim.SGD 等——都根据梯度更新参数。理解 DeZero 对使用 PyTorch 的帮助：①理解 autograd——知道 `loss.backward()` 内部是在沿计算图反向传递梯度，不再视为黑箱。②理解 nn.Module——知道 Module 的参数收集、梯度清零、状态管理机制。③调试能力——当梯度异常（NaN、梯度消失）时，能定位是哪个 Function 的 backward 实现有问题。④扩展能力——能自定义 autograd.Function 实现框架未提供的运算。
</Answer>
