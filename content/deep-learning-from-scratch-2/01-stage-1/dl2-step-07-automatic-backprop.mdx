## 为什么这一步不能跳过

步骤7 反向传播的自动化 的增量不是 API 名称，而是把 **调用者手工展开每个反向节点** 变为 **Variable 自己驱动完整反向链**。它的核心机制是：Variable.backward 从自身 creator 出发自动取函数、读取输出梯度并写回输入梯度。

这一步验收时固定输入数组、随机种子、DeZero 前一步版本与运行设备。先写出预期的 forward、shape、creator 或状态变化，再执行实现；backward 后清空派生梯度并从相同输入重放。这样才能区分本步能力与缓存、旧图或随机性的偶然结果。

<Callout type="info" title="本步硬合同">
  前向证据、反向证据和重置后重放必须同时一致。backward 只处理一个 creator
  或忘记继续回溯，会让长组合图只传播一层 时，即使最终 loss 或输出合理，也应判定
  步骤7 反向传播的自动化 失败。
</Callout>

## 数学与状态合同

$$
x.grad=F.backward(y.grad)
$$

对 步骤7 反向传播的自动化，公式中的每个量都要绑定到实际数组或对象：记录 dtype、shape、设备、creator/generation 或训练模式。若发生广播、归约、转置、时间递推或设备迁移，反向结果必须回到每个输入原有的语义边界。

## 最小实现草图

```python
# 反向传播的自动化：解析梯度必须由独立数值差分核对
x = Variable(np.array(0.5))
y = target(x)
y.backward(create_graph=False)
assert relative_error(x.grad, central_diff(target, x)) < 1e-4
```

这段草图不复制原书实现；它只保留 步骤7 反向传播的自动化 的可验证接口。实际练习要补齐输入构造、断言和失败样本，并用作者官方仓的对应 step 文件核对行为边界，而不是照抄代码行。
