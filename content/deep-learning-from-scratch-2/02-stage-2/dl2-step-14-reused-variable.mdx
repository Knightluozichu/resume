## 为什么这一步不能跳过

步骤14 重复使用同一个变量 的增量不是 API 名称，而是把 **每个变量假定只有一条路径** 变为 **分支梯度累加且可显式清零**。它的核心机制是：同一 Variable 经多条路径复用时必须累加梯度，cleargrad 则在新一轮反传前清空历史贡献。

这一步验收时固定输入数组、随机种子、DeZero 前一步版本与运行设备。先写出预期的 forward、shape、creator 或状态变化，再执行实现；backward 后清空派生梯度并从相同输入重放。这样才能区分本步能力与缓存、旧图或随机性的偶然结果。

<Callout type="info" title="本步硬合同">
  前向证据、反向证据和重置后重放必须同时一致。覆盖而非累加会漏掉分支贡献，不清空又会把两次训练的梯度混在一起
  时，即使最终 loss 或输出合理，也应判定 步骤14 重复使用同一个变量 失败。
</Callout>
