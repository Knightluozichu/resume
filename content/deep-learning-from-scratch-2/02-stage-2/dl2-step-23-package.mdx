## 为什么这一步不能跳过

步骤23 打包 的增量不是 API 名称，而是把 **所有实现堆在单个 step 文件** 变为 **可安装包维持单一公共类型**。它的核心机制是：core、functions 与 **init** 明确公共 API 边界，导入包时再安装运算符重载。

这一步验收时固定输入数组、随机种子、DeZero 前一步版本与运行设备。先写出预期的 forward、shape、creator 或状态变化，再执行实现；backward 后清空派生梯度并从相同输入重放。这样才能区分本步能力与缓存、旧图或随机性的偶然结果。

<Callout type="info" title="本步硬合同">
  前向证据、反向证据和重置后重放必须同时一致。循环导入或在多个模块重复定义
  Variable 会造成类型身份不一致 时，即使最终 loss 或输出合理，也应判定 步骤23
  打包 失败。
</Callout>
