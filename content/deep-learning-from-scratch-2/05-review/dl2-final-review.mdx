## 知识串联：一次完整的训练

把全书知识串成一次完整的训练流程：

```python
# ===== ch3: Variable + Function（基础引擎）=====
x = Variable(np.random.randn(30, 784))    # 数据包装
t = Variable(np.random.randint(0, 10, 30))

# ===== ch6-ch7: Layer + Model（工程封装）=====
model = MLP((100, 50, 10))                # 网络定义

# ===== ch5: Optimizer（参数更新）=====
optimizer = Adam().setup(model)            # 优化器绑定

# ===== ch8: 训练循环 =====
for epoch in range(100):
    # ch3: 前向传播（自动构建计算图）
    y = model(x)
    # ch8: 损失计算
    loss = softmax_cross_entropy(y, t)
    # ch4: 反向传播（自动微分）
    model.cleargrads()
    loss.backward()
    # ch5: 参数更新
    optimizer.update()
    # ch8: 评估
    acc = accuracy(model, test_set)
```

## DeZero 架构全景回顾

### 第一层：数据抽象（Variable）

<Callout type="info">

Variable 解决的问题：裸 NumPy 数组无法记录运算历史。Variable 包装 data 并通过 creator 链记录「谁产生了它」，使运算可追溯、可反向。

</Callout>

### 第二层：运算抽象（Function）

Function 解决的问题：运算需要同时定义前向和反向，且需要自动连接计算图。Function 基类在 `__call__` 中自动完成连接，子类只实现 forward/backward。

### 第三层：自动微分引擎（backward）

backward 解决的问题：复杂计算图的梯度计算。通过 generation 拓扑排序 + 链式法则，从输出端自动反向传递梯度到所有输入。

### 第四层：工程封装（Layer/Model/Optimizer）

Layer/Model 解决的问题：参数管理和网络组合。Optimizer 解决的问题：根据梯度更新参数。

## DeZero vs PyTorch 对应表

| DeZero 概念 | PyTorch 对应 | 关键差异 |
|-------------|-------------|---------|
| Variable | Tensor(requires_grad=True) | DeZero 用独立类，PyTorch 用标志位 |
| Function | autograd.Function | 接口几乎一致 |
| backward() | backward() | 均沿计算图反向传播 |
| Layer | nn.Module | 均支持嵌套和参数收集 |
| Model | nn.Module(顶层) | DeZero 区分 Layer/Model，PyTorch 统一 |
| Optimizer | optim.SGD/Adam | 接口一致(update↔step) |
| cleargrads() | zero_grad() | 均需手动调用 |
| using_config | no_grad() | 均用于禁用计算图 |

## 四个核心设计决策

### 决策一：计算图是隐式构建的

```python
# 用户代码：只写前向计算
y = model(x)
loss = softmax_cross_entropy(y, t)
# 计算图在 __call__ 中自动构建，用户无感
```

<Callout type="tip">

**设计哲学**：DeZero 和 PyTorch 都选择「隐式构建」计算图（动态图），而非 TensorFlow 1.x 的「显式定义后运行」。隐式构建更直观、更灵活，支持 Python 原生控制流（if/while）。

</Callout>

### 决策二：反向传播用 generation 拓扑排序

```python
# 按 generation 降序处理，保证拓扑顺序
funcs.sort(key=lambda x: x.generation)
f = funcs.pop()    # 取最大的（离输出最近的）
```

### 决策三：参数自动收集

```python
# __setattr__ 自动检测 Parameter 类型
self.W = Parameter(...)    # 自动加入 _params
# params() 递归收集子层参数
```

### 决策四：梯度累加而非覆盖

```python
# 多路径梯度累加
if x.grad is None:
    x.grad = gx
else:
    x.grad = x.grad + gx    # 累加，不覆盖
```

## 从 DeZero 到 PyTorch 的迁移路径

```text
理解 DeZero                迁移到 PyTorch
──────────                ──────────────
Variable.data        →    tensor.data
Variable.grad        →    tensor.grad
Variable.backward()  →    loss.backward()
Function.forward     →    autograd.Function.forward
Function.backward    →    autograd.Function.backward
Layer                →    nn.Module
Model                →    nn.Module
Optimizer.update()   →    optimizer.step()
model.cleargrads()   →    optimizer.zero_grad()
```

<Callout type="warning">

**迁移要点**：理解 DeZero 后迁移到 PyTorch 几乎零障碍——核心概念一一对应。主要差异在 API 命名（update/step、cleargrads/zero_grad）和语法糖（PyTorch 更丰富）。真正重要的是理解「计算图→反向传播→参数更新」的机制，这在不同框架中是通用的。

</Callout>

<Glossary>

<GlossaryItem term="DeZero 架构全景">
DeZero 的四层架构：①数据层（Variable）——包装数据+记录计算图。②运算层（Function）——定义运算+连接计算图。③引擎层（backward）——拓扑排序+反向传递梯度。④工程层（Layer/Model/Optimizer）——参数管理+网络组合+训练循环。四层自底向上逐层封装，形成完整的深度学习框架。
</GlossaryItem>

<GlossaryItem term="隐式计算图">
DeZero 和 PyTorch 共同采用的设计——计算图在前向传播时自动构建（动态图），用户无需显式定义。对比 TensorFlow 1.x 的静态图（先定义后运行），隐式构建更直观、支持 Python 原生控制流（if/while），是当前主流框架的共识。
</GlossaryItem>

<GlossaryItem term="动态图 vs 静态图">
动态图（DeZero/PyTorch）每次前向传播即时构建计算图，灵活、易调试、支持控制流。静态图（TF 1.x）先定义完整计算图再运行，可做全局优化但不够灵活。当前趋势是动态图为主（PyTorch/TF 2.x 默认动态）。
</GlossaryItem>

<GlossaryItem term="框架迁移">
从 DeZero 迁移到 PyTorch 的路径。核心概念一一对应：Variable↔Tensor、Function↔autograd.Function、Layer↔nn.Module、Optimizer.update↔optimizer.step。理解「计算图→反向传播→参数更新」机制后，迁移几乎零障碍。真正重要的是框架通用的原理，而非具体 API。
</GlossaryItem>

<GlossaryItem term="训练流程闭环">
全书知识的最终整合：数据(Variable)→模型(Layer/Model)→前向(Function)→损失(softmax交叉熵)→反向(backward)→更新(Optimizer)→评估(accuracy)。这个闭环是所有深度学习框架的核心工作流，理解 DeZero 的实现即理解了框架的本质。
</GlossaryItem>

<GlossaryItem term="数值梯度检验">
验证反向传播正确性的方法。用数值微分 `(f(x+h)-f(x-h))/(2h)` 独立计算梯度，与自动微分结果对比。是调试 Function.backward 实现的标准手段，DeZero 全书反复使用。体现了「先保证正确，再追求效率」的工程原则。
</GlossaryItem>

</Glossary>

### 问题 2

DeZero 的四层架构分别解决什么问题？层与层之间如何协作？

<Answer>

DeZero 四层架构各解决的问题：①数据层（Variable）——解决「数据不可追溯」问题。裸 NumPy 数组无法记录运算历史，Variable 包装 data 并通过 creator 链记录产生它的 Function，使运算可追溯、可反向。②运算层（Function）——解决「运算需同时定义前向反向且自动连接计算图」问题。Function 基类在 `__call__` 中自动完成 creator 设置和 inputs/outputs 保存，子类只实现 forward/backward。③引擎层（backward）——解决「复杂计算图梯度计算」问题。通过 generation 拓扑排序 + 链式法则，从输出端自动反向传递梯度到所有输入。④工程层（Layer/Model/Optimizer）——解决「参数管理和网络组合」问题。Layer 封装参数+运算，Model 组合多层网络，Optimizer 根据梯度更新参数。层间协作：Layer 内部用 Function 实现前向计算，Function 产出 Variable 形成计算图，backward 沿计算图反向传递梯度填入 Variable.grad，Optimizer 读取 grad 更新 Layer 的 Parameter.data。
</Answer>

### 问题 3

DeZero 与 PyTorch 的核心概念如何对应？理解 DeZero 对使用 PyTorch 有何帮助？

<Answer>

DeZero 与 PyTorch 核心概念对应：Variable↔Tensor(requires_grad=True)——数据容器，均记录计算图。Function↔autograd.Function——运算单元，均有 forward/backward。backward()↔backward()——反向传播，均沿计算图反向传递梯度。Layer↔nn.Module——模块化层，均支持嵌套和参数收集。Model↔nn.Module(顶层)——网络容器。Optimizer↔optim.SGD/Adam——优化器，接口一致(update↔step)。cleargrads()↔zero_grad()——梯度清零。using_config↔no_grad()——禁用计算图。理解 DeZero 对使用 PyTorch 的帮助：①理解 autograd——知道 `loss.backward()` 内部是沿计算图反向传递梯度，不再视为黑箱。②理解 nn.Module——知道参数收集、梯度清零的机制。③调试能力——梯度异常时能定位问题。④扩展能力——能自定义 autograd.Function。⑤迁移零障碍——核心概念一一对应，只需学 API 命名差异。真正重要的是「计算图→反向传播→参数更新」机制，这在所有框架中通用。
</Answer>

### 问题 4

全书有哪四个核心设计决策？每个决策解决了什么问题？

<Answer>

全书四个核心设计决策：①计算图隐式构建——在前向传播时（Function.__call__）自动通过 creator 链构建计算图，用户无需显式定义。解决了「如何让用户只写前向计算，框架自动记录运算关系」的问题。对比静态图（TF 1.x），隐式构建更灵活、支持控制流。②反向传播用 generation 拓扑排序——每个 Variable/Function 持有 generation（计算图深度），反向传播时按 generation 降序处理。解决了「复杂计算图（有分支和汇合）如何保证节点处理顺序正确」的问题——高代数（离输出近）先处理，保证下游梯度先算完。③参数自动收集——Layer 的 `__setattr__` 在赋值时检测 Parameter 类型自动加入 _params，params() 递归收集子层参数。解决了「如何让框架自动发现和管理所有可学习参数」的问题，用户无需手动维护参数列表。④梯度累加而非覆盖——当 Variable 被多条路径使用时，反向传播用 `x.grad = x.grad + gx` 累加。解决了「多路径梯度如何正确汇总」的问题，符合链式法则在分叉汇合场景的要求。这四个决策共同支撑了「用户只写前向，框架自动求导」的核心能力。
</Answer>
