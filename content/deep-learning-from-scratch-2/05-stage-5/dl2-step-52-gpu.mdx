## 为什么这一步不能跳过

步骤52 支持GPU 的增量不是 API 名称，而是把 **运算后端固定为 CPU NumPy** 变为 **同一图按设备一致性运行**。它的核心机制是：cuda 模块抽象 NumPy/CuPy，Variable、Layer 与 DataLoader 迁移数组且同一次运算必须处于同一设备。

这一步验收时固定输入数组、随机种子、DeZero 前一步版本与运行设备。先写出预期的 forward、shape、creator 或状态变化，再执行实现；backward 后清空派生梯度并从相同输入重放。这样才能区分本步能力与缓存、旧图或随机性的偶然结果。

<Callout type="info" title="本步硬合同">
  前向证据、反向证据和重置后重放必须同时一致。CPU ndarray 与 GPU CuPy
  数组混算会报错或触发昂贵隐式传输 时，即使最终 loss 或输出合理，也应判定 步骤52
  支持GPU 失败。
</Callout>
