## 直觉引入

把 HTTP 通信想象成打电话。<Term def="Keep-Alive 是 HTTP/1.1 默认开启的连接复用机制，允许在一条 TCP 连接上发送多个请求/响应，避免每次请求都进行 TCP 三次握手和四次挥手。">Keep-Alive</Term>就是「不挂电话继续说」——HTTP/1.0 每次说完一件事就挂断重拨（TCP 握手+挥手），HTTP/1.1 默认保持通话，连续说多件事不用重新拨号。**Agent 连接池**是「电话总机」——维护多条线路（maxSockets），线路忙时排队等（等待队列），线路闲时放回总机待命（空闲池），超时没人用就挂断（keepAliveTimeout）。**net.Socket** 是「电话线本身」——双向传输（Duplex Stream），能听能说。**libuv** 是「电信运营商」——底层用 epoll/kqueue/IOCP 监听线路有没有信号到达。

## Keep-Alive 与连接复用

HTTP/1.0 默认每次请求都建立新 TCP 连接——三次握手（~1 RTT）建连、传数据、四次挥手断连。下一个请求重新握手，延迟和带宽浪费严重。HTTP/1.1 默认开启 Keep-Alive，在同一条 TCP 连接上发送多个请求/响应：

```javascript
const http = require("http");

// HTTP/1.1 默认 Keep-Alive，Node.js 的 http.Agent 管理
const agent = new http.Agent({
  keepAlive: true,        // 开启连接复用
  maxSockets: 100,        // 每个 origin 最大并发连接
  maxFreeSockets: 10,     // 空闲连接池上限
  keepAliveTimeout: 4000, // 空闲超时（ms），超时关闭
});

// 复用连接：第二个请求不需重新握手
const req1 = http.request({ host: "example.com", agent }, (res) => {
  res.on("data", () => {});
  res.on("end", () => {
    // 连接放回空闲池，不关闭
    const req2 = http.request({ host: "example.com", agent }, (res2) => {
      // req2 复用 req1 的 TCP 连接，零握手延迟
    });
    req2.end();
  });
});
req1.end();
```

收益：①减少握手延迟（首次 1 RTT，后续 0 RTT）；②减少带宽（TCP/IP 头部分摊）；③减轻服务端（减少连接建立/断开的系统调用）。

## Agent 连接池

http.Agent 按 origin（host:port）分组管理 TCP 连接，每个 origin 有活跃连接和空闲连接两个池：

```javascript
// Agent 连接池工作流程
// 请求到来时：
//   1. 优先从空闲池取连接复用
//   2. 无空闲且活跃数 < maxSockets → 新建连接
//   3. 活跃数达 maxSockets → 请求排队等待

// 调优示例
const agent = new http.Agent({
  maxSockets: 50,         // 太小：排队等待，QPS 受限
                          // 太大：过多连接消耗 fd 和内存
  maxFreeSockets: 10,     // 空闲池上限，防止过多空闲连接占资源
  keepAliveTimeout: 4000, // 空闲 4s 后关闭
  scheduling: "lifo",     // 后进先出（优先用最近活跃的连接）
});

// Node.js 全局 Agent（http.globalAgent）
// Node 19+ 默认 keepAlive: true
// 可通过 http.globalAgent.keepAlive = true 启用
```

<Callout type="trap">
**误区：maxSockets 越大越好。** maxSockets 设太大（如 1000）会导致：①过多 TCP 连接消耗文件描述符（fd 限制）；②服务端连接数暴增可能触发限流/拒绝；③上下文切换开销增大。设太小（如 1）会导致请求串行排队。生产环境通常设 50-100，并配合监控观察连接池利用率。关键指标：等待队列长度、平均连接复用率。
</Callout>

## HTTP 模块分层

Node.js 的 HTTP 模块从上到下分三层：

```javascript
// 第一层：HTTP 协议层（http 模块）
const server = http.createServer((req, res) => {
  // req: http.IncomingMessage（Readable Stream）
  // res: http.ServerResponse（Writable Stream）
  // http 模块解析了 HTTP 报文：请求行、头部、body
  req.on("data", chunk => {
    // body 以 chunk（Buffer）流式到达
  });
  res.writeHead(200, { "Content-Type": "text/plain" });
  res.end("Hello");
});

// 第二层：TCP 层（net 模块）
// net.Socket 是 Duplex Stream，封装底层 TCP 连接
// http.Server 内部用 net.Server 监听端口
//   socket.on('data') → http 解析器 → req.emit('data')
//   res.write() → socket.write() → TCP 发送

// 第三层：libuv（跨平台 I/O）
// Linux: epoll（事件多路复用）
// macOS: kqueue
// Windows: IOCP
// libuv 把 socket fd 注册到事件多路复用器
//   有数据可读 → 通知事件循环 poll 阶段 → 触发 socket 'data' 事件
```

**net.Socket** 是桥梁：向上对 HTTP 模块暴露 Duplex Stream 接口（可读可写 chunk），向下通过 libuv 异步收发 TCP 数据。http 模块监听 socket 的 `data` 事件，按 HTTP 协议解析报文，解析出的 body 通过 `req`（IncomingMessage，Readable Stream）传递给用户。

## HTTP body 为什么是流

HTTP 请求 body 通过 TCP 分段传输到达，不会一次性到齐。Node.js 将 body 设计为 Readable Stream：

```javascript
// body 流式到达的演示
const server = http.createServer((req, res) => {
  // req 此时只有请求行和头部，body 还在传输中
  console.log(req.method, req.url); // 立即可用
  console.log(req.headers);         // 立即可用

  // body 以 chunk 流式到达
  let bodySize = 0;
  req.on("data", (chunk) => {
    bodySize += chunk.length;
    // chunk 是 Buffer，每次可能是 16KB / 64KB
  });
  req.on("end", () => {
    console.log("body 总大小:", bodySize);
    res.end("OK");
  });
});

// 不直接给完整 body 的原因：
// 1. 内存效率：1GB 上传若一次性读入内存会 OOM
//    流式处理每次只有一个 chunk（如 64KB），内存恒定
// 2. 时间效率：body 还在传输时就可以开始处理
//    如边接收边写磁盘、边解析边返回
// 3. 背压控制：消费慢时暂停 TCP 读取，防止内存堆积
// 4. 统一接口：req 是 Readable Stream，可以 pipe 到任何 Writable
```

<Exercises>
**问题 1**：http.Agent 的连接池是如何工作的？maxSockets 超出时会发生什么？

<Answer>
Agent 按 origin（host:port）分组管理 TCP 连接。请求到来时：①优先从空闲池取连接复用；②无空闲且活跃数 < maxSockets 则新建；③活跃数达 maxSockets 则请求排队等待。连接完成响应后放回空闲池，超 keepAliveTimeout 才关闭。maxSockets 超出时请求排队不报错但增加延迟。生产通常设 50-100，配合 maxFreeSockets 限制空闲连接数。
</Answer>

**问题 2**：Node.js 的 HTTP 模块是如何分层构建的？net.Socket 扮演什么角色？

<Answer>
三层：①http.Server/ClientRequest（HTTP 协议层，解析报文生成 req/res）；②net.Socket（TCP 层，Duplex Stream，封装 TCP 连接读写和事件）；③libuv（跨平台 I/O，Linux epoll/macOS kqueue/Windows IOCP）。net.Socket 是桥梁：向上暴露 Duplex Stream 接口，向下通过 libuv 异步收发 TCP 数据。http 模块监听 socket data 事件，按 HTTP 协议解析，body 通过 req（Readable Stream）传递。
</Answer>
</Exercises>
