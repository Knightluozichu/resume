## 直觉引入

把测试和部署想象成开餐厅的质检和开店流程。<Term def="测试金字塔是分层测试策略：底层单元测试最多（快、隔离、精准定位）、中层集成测试适中（多模块协作）、顶层 E2E 测试最少（慢、易 flaky、端到端验证）。">测试金字塔</Term>是「质检流程」——每道菜出厂前先快速自检（单元测试，量大快），再抽检搭配效果（集成测试，适中），最后整套试吃（E2E，少而全）。**Mocha/Jest** 是「质检工具箱」——Mocha 只提供框架（自己配断言/mock），Jest 开箱即用（断言+mock+覆盖率全内置）。**PM2** 是「连锁店管理」——一个厨房忙不过来就开多家分店（cluster 多进程），一家装修时其他继续营业（零停机 reload），分店着火自动重开（自动重启）。**Docker** 是「标准化餐车」——把厨房环境和菜品打包成一个箱子，推到哪里都能原样开张。

## 测试金字塔

```javascript
// 单元测试（底层，最多）：测单个函数，不依赖外部
// 快（毫秒）、隔离、失败能精准定位
function add(a, b) { return a + b; }

// Jest 单元测试
test("add 函数正确相加", () => {
  expect(add(1, 2)).toBe(3);
  expect(add(-1, 1)).toBe(0);
});

// 集成测试（中层，适中）：测多模块协作
const request = require("supertest");
const app = require("../app");

test("GET /api/users 返回用户列表", async () => {
  const res = await request(app).get("/api/users");
  expect(res.status).toBe(200);
  expect(Array.isArray(res.body)).toBe(true);
});

// E2E 测试（顶层，最少）：模拟真实用户操作
// 慢（分钟级）、依赖多、易 flaky
const { chromium } = require("playwright");

test("用户登录流程", async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  await page.goto("http://localhost:3000/login");
  await page.fill("#username", "admin");
  await page.fill("#password", "123456");
  await page.click("#submit");
  await page.waitForURL("**/dashboard");
  expect(page.url()).toContain("/dashboard");
  await browser.close();
});
```

原则：能用单元测试覆盖的不用集成，能用集成覆盖的不用 E2E。

## Mocha vs Jest

```javascript
// Mocha：只提供 describe/it 结构，断言和 mock 需另装
const { expect } = require("chai");      // 断言库
const sinon = require("sinon");          // mock 库

describe("UserService", () => {
  it("should find user by id", async () => {
    const stub = sinon.stub(User, "findById").resolves({ id: 1 });
    const user = await UserService.findById(1);
    expect(user.id).to.equal(1);
    stub.restore();
  });
});

// Jest：零配置，断言/mock/覆盖率全内置
describe("UserService", () => {
  it("should find user by id", async () => {
    const mockFn = jest.fn().mockResolvedValue({ id: 1 });
    User.findById = mockFn;
    const user = await UserService.findById(1);
    expect(user.id).toBe(1);
    expect(mockFn).toHaveBeenCalledWith(1);
  });
});

// Jest 覆盖率：jest --coverage
// 也可以用 c8（V8 原生覆盖率，比 istanbul 更准确）
```

Jest 优势：零配置（自动发现 *.test.js）、内置 expect/sinon/coverage、并行执行（每文件独立 worker）。新项目推荐 Jest，已有 Mocha 不必强迁。

## PM2 集群管理

```javascript
// ecosystem.config.js — PM2 配置
module.exports = {
  apps: [{
    name: "my-api",
    script: "./dist/server.js",
    instances: "max",           // 利用全部 CPU 核
    exec_mode: "cluster",       // cluster 模式
    max_memory_restart: "1G",   // 内存超限自动重启
    env: {
      NODE_ENV: "production",
      PORT: 3000,
    },
  }],
};

// PM2 命令
// pm2 start ecosystem.config.js   启动
// pm2 reload my-api               零停机重载（逐个重启 Worker）
// pm2 restart my-api              全部重启（有停机窗口，不推荐生产）
// pm2 logs my-api                 查看日志
// pm2 monit                       监控仪表盘
```

**零停机 reload 原理**：PM2 逐个重启 Worker——向 Worker 1 发 SIGTERM，Worker 1 停止接受新请求但完成存量请求（优雅关闭），退出后启动新 Worker 1 加载新代码，然后对 Worker 2 重复。任何时刻都有 N-1 个 Worker 在服务，用户无感知。

## Docker 部署

```dockerfile
# 多阶段构建 Dockerfile
# 阶段1：builder（装全部依赖、编译 TypeScript）
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci                    # 基于 lock 精确安装
COPY . .
RUN npm run build             # tsc 编译到 dist/

# 阶段2：runtime（只装生产依赖，不含 devDependencies）
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev         # 只装生产依赖
COPY --from=builder /app/dist ./dist
USER node                     # 非 root 用户运行
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s CMD wget -qO- http://localhost:3000/health || exit 1
CMD ["node", "dist/server.js"]
```

```javascript
// 优雅关闭：配合 Docker stop / PM2 reload
process.on("SIGTERM", async () => {
  console.log("收到 SIGTERM，开始优雅关闭");
  server.close();               // 停止接受新连接
  // 等待正在处理的请求完成
  // 关闭数据库连接、Redis 连接
  // 清理定时器
  await db.close();
  process.exit(0);
});
```

<Callout type="trap">
**误区：Docker 中用 PM2 管理进程。** Docker 容器本身就是进程管理器，再套一层 PM2 是反模式。Docker 的重启策略（--restart=always）已覆盖 PM2 的自动重启功能，Docker 的健康检查（HEALTHCHECK）已覆盖 PM2 的监控。在 Docker 中直接用 `node dist/server.js` 启动，让 Docker 管理生命周期。PM2 适合「裸机部署」场景（不用 Docker 的服务器）。如果一定要在 Docker 中用 PM2，需加 `--no-daemon` 前台运行，否则容器会因 PM2 daemon 后台运行而立即退出。
</Callout>

<Exercises>
**问题 1**：测试金字塔的三层是什么？为什么底层多顶层少？

<Answer>
三层：单元测试（最多，测单个函数，快毫秒级、隔离、精准定位）、集成测试（适中，测多模块协作，较慢秒级）、E2E 测试（最少，端到端模拟用户，慢分钟级、易 flaky）。底层多顶层少的原因：①速度——单元快大量运行不拖慢 CI，顶层慢多了跑数小时；②稳定性——单元隔离不因环境波动失败，E2E 依赖多易 flaky；③定位——单元失败精确定位函数，E2E 失败需排查。
</Answer>

**问题 2**：PM2 的零停机 reload 原理是什么？和 restart 有什么区别？

<Answer>
reload 逐个重启 Worker：向 Worker 1 发 SIGTERM，Worker 1 停止接受新连接但完成存量请求（优雅关闭），退出后启动新 Worker 1 加载新代码，然后对 Worker 2 重复。任何时刻有 N-1 个 Worker 在服务，用户无感知。restart 全部同时重启，有停机窗口。生产部署必用 reload。reload 配合应用的 SIGTERM 优雅关闭处理（server.close + 等请求完成 + 关连接），实现真正的零停机。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="测试金字塔">底层单元测试（多，快毫秒级隔离精准）、中层集成测试（适中，多模块协作）、顶层 E2E 测试（少，慢分钟级端到端）。底层多顶层少因速度、稳定性、定位精度。原则：能用单元覆盖不用集成，能用集成不用 E2E。</GlossaryItem>
<GlossaryItem term="PM2 cluster 模式">基于 Node cluster fork N 个 Worker 进程，主进程 round-robin 分发请求。Worker 崩溃自动重启。零停机 reload 逐个重启 Worker（SIGTERM 优雅关闭→启动新 Worker），任何时刻 N-1 在服务。max_memory_restart 防内存泄漏。restart 全部同时重启有停机窗口。</GlossaryItem>
<GlossaryItem term="Docker 最佳实践">alpine 瘦身镜像、多阶段构建（builder 编译→runtime 只装生产依赖）、npm ci 精确安装、非 root 用户运行、HEALTHCHECK 健康检查、SIGTERM 优雅关闭。Docker 中不套 PM2（容器本身是进程管理器），直接 node 启动。</GlossaryItem>
</Glossary>
