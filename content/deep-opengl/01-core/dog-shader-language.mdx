## 直觉引入

着色器不是一段被“丢给 GPU”就自动理解的数据处理函数。它同时处在三份契约里：源码必须满足某个 GLSL ES 版本；顶点输出与片元输入必须能链接成阶段接口；应用还要把 VAO 属性、uniform、纹理单元和输出附件接到正确位置。只看源码语法，会漏掉后两层最常见的故障。

可以把顶点着色器和片元着色器看成流水线两端的独立程序。顶点阶段为每个顶点输出裁剪空间位置和待插值数据；光栅化根据图元覆盖生成片元并插值；片元阶段读取插值结果、uniform 与纹理，输出一个或多个颜色值。程序链接器负责验证两端接口，应用负责提供真正的数据来源。

## 版本先于语法

WebGL 1 使用 GLSL ES 1.00，WebGL 2 使用 GLSL ES 3.00。OpenGL ES 3.2 还可使用 GLSL ES 3.20 的更多阶段与特性；桌面 OpenGL 使用桌面 GLSL，版本号、扩展和部分关键字并不能与 GLSL ES 逐行互换。

| 目的 | GLSL ES 1.00 | GLSL ES 3.00 |
| --- | --- | --- |
| 顶点输入 | attribute | in |
| 顶点到片元 | varying / varying | out / in |
| 片元颜色 | gl_FragColor | 用户声明 out vec4 |
| 纹理采样 | texture2D | texture |
| 版本声明 | 通常省略或 100 | #version 300 es，必须在最前 |

同一项目维护 ES 100 和 ES 300 两套源码时，应由明确的预处理或模板层生成版本差异，不能只替换 attribute 为 in：片元输出、纹理函数、整数类型、布局限定与扩展声明都可能不同。

## 类型与运算边界

GLSL ES 提供标量、向量、矩阵、结构、数组与不透明类型。vec3 不只是三个 float 的容器，它支持逐分量算术、swizzle 和向量内建函数；mat4 与 vec4 的乘法表示线性变换。几个容易被类 C 外观掩盖的规则是：

- 类型转换比 JavaScript/C 更严格，int 与 float 混算不能依赖隐式转换；
- 向量的乘号通常是逐分量乘法，矩阵乘法则由操作数类型决定；
- 矩阵按列向量语义构造，mvp * position 与 position * mvp 不是同一运算；
- WebGL 的 uniformMatrix*fv 要求 transpose 参数为 false，应用应按约定准备矩阵数据；
- 数组大小、循环和动态索引能力受语言版本与目标实现约束，不能从桌面 GLSL 直接推断。

## 精度是数值契约

<Term def="为浮点或整数表达式声明最小范围与精度等级的 highp、mediump、lowp">精度限定符</Term>描述最低数值能力，不是跨 GPU 固定的 IEEE 位数，也不保证 highp 一定更慢。顶点语言有默认浮点精度；片元语言没有默认 float 精度，必须声明默认 precision 或给相关声明逐一指定精度。

在 WebGL1 的片元阶段，highp float 可能不可用；WebGL2 对应 GLSL ES 3.00，片元 highp 是核心能力，但实际范围与精度仍应通过 getShaderPrecisionFormat 记录。颜色与普通 UV 常可使用 mediump，世界空间大坐标、深度重建、阴影比较和高动态范围计算更容易暴露 mediump 的范围或量化误差。

```js
function reportFragmentPrecision(gl) {
  for (const level of [gl.LOW_FLOAT, gl.MEDIUM_FLOAT, gl.HIGH_FLOAT]) {
    const info = gl.getShaderPrecisionFormat(gl.FRAGMENT_SHADER, level);
    console.log({
      level,
      rangeMin: info?.rangeMin,
      rangeMax: info?.rangeMax,
      precisionBits: info?.precision,
    });
  }
}
```

精度选择应由可重复场景验证：放大远距离坐标、观察渐变 banding、比较深度边缘和法线高光，再决定哪些中间量必须提升，而不是整份着色器盲目 highp 或 mediump。

## 阶段接口与插值

<Term def="相邻着色器阶段之间必须在名称、类型、数组、精度和限定规则上兼容的输入输出集合">阶段接口</Term>把顶点 out 接到片元 in。GLSL ES 3.00 默认按名称匹配，链接器还检查类型、数组和相关限定是否兼容。声明存在不代表变量一定活跃：若编译器证明某输入或 uniform 不影响输出，它可以被优化掉，应用查询位置会得到 -1 或 null。

<Term def="控制顶点输出如何为图元内部片元生成值的 smooth、flat、centroid 等规则">插值限定符</Term>决定光栅化如何传值：

- smooth 是默认的透视正确插值，适合颜色、UV、法线等连续量；
- flat 不插值，整个图元使用 provoking vertex 的值；整数片元输入必须使用 flat；
- centroid 要求插值位置位于图元与像素采样区域的交集附近，多重采样边缘更稳定。

顶点着色器写出的 v_uv 只存在于顶点上。片元读到的是由三个顶点值按屏幕覆盖和透视关系生成的结果，而不是“离这个片元最近的顶点值”。

## 应用、程序与资源接口

<Term def="由应用设置、在一次绘制期间对各着色器调用保持常量的程序变量">uniform</Term>适合变换、材质参数和纹理单元索引。普通 uniform 属于 program；切换 program 后，相同名字也不是同一个存储位置。WebGL2 的 uniform block 可把一组数据通过缓冲绑定复用，但 block 布局与绑定点仍要显式匹配。

<Term def="在着色器中代表纹理访问类型，其 uniform 值选择纹理单元而非保存纹理对象">采样器</Term>连接两层状态：uniform1i 把 sampler 设为纹理单元编号，activeTexture + bindTexture 把纹理对象接到该单元和目标。把 sampler uniform 设为 0 不等于纹理已绑定，漏掉任一层都会采到错误资源或不完整纹理。

## 一对完整的 GLSL ES 3.00 阶段

顶点阶段显式固定属性位置，输出 UV、颜色和一个不插值的材质编号。矩阵按“投影 × 视图 × 模型 × 位置”的列向量顺序使用。

```glsl
#version 300 es
precision highp float;
precision highp int;

layout(location = 0) in vec3 a_position;
layout(location = 1) in vec2 a_uv;
layout(location = 2) in vec3 a_color;

uniform mat4 u_model;
uniform mat4 u_viewProjection;

out highp vec2 v_uv;
out mediump vec3 v_color;
flat out highp int v_materialId;

void main() {
  gl_Position = u_viewProjection * u_model * vec4(a_position, 1.0);
  v_uv = a_uv;
  v_color = a_color;
  v_materialId = 0;
}
```

片元阶段必须以兼容声明接收接口。这里用纹理 alpha 混合顶点颜色，并写入 location 0 的颜色附件。

```glsl
#version 300 es
precision highp float;
precision highp int;

in highp vec2 v_uv;
in mediump vec3 v_color;
flat in highp int v_materialId;

uniform sampler2D u_baseColor;
layout(location = 0) out vec4 outColor;

void main() {
  vec4 texel = texture(u_baseColor, v_uv);
  outColor = vec4(texel.rgb * v_color, texel.a);
}
```

若把片元 v_color 改成 vec4，阶段源码各自仍可能合法，但链接器会报告接口类型不匹配。若完全不使用 v_materialId，它可能被优化掉；应用不应把“查询不到未使用变量”误判成链接器故障。

## 编译、链接与资源绑定

下面的 JavaScript 保留每个阶段日志，并验证矩阵和采样器位置。createShader/createProgram 返回失败也有明确路径。

```js
function compile(gl, type, source) {
  const shader = gl.createShader(type);
  if (!shader) throw new Error("createShader failed");
  gl.shaderSource(shader, source);
  gl.compileShader(shader);
  const log = gl.getShaderInfoLog(shader);
  if (!gl.getShaderParameter(shader, gl.COMPILE_STATUS)) {
    gl.deleteShader(shader);
    throw new Error(log || "shader compile failed");
  }
  if (log) console.info(log);
  return shader;
}

function link(gl, vertexSource, fragmentSource) {
  const vertex = compile(gl, gl.VERTEX_SHADER, vertexSource);
  const fragment = compile(gl, gl.FRAGMENT_SHADER, fragmentSource);
  const program = gl.createProgram();
  if (!program) throw new Error("createProgram failed");
  gl.attachShader(program, vertex);
  gl.attachShader(program, fragment);
  gl.linkProgram(program);
  gl.deleteShader(vertex);
  gl.deleteShader(fragment);
  const log = gl.getProgramInfoLog(program);
  if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
    gl.deleteProgram(program);
    throw new Error(log || "program link failed");
  }
  if (log) console.info(log);
  return program;
}

function bindMaterial(gl, program, mvpModel, viewProjection, texture) {
  gl.useProgram(program);
  const model = gl.getUniformLocation(program, "u_model");
  const vp = gl.getUniformLocation(program, "u_viewProjection");
  const baseColor = gl.getUniformLocation(program, "u_baseColor");
  if (model === null || vp === null || baseColor === null) {
    throw new Error("required uniform was not active");
  }
  gl.uniformMatrix4fv(model, false, mvpModel);
  gl.uniformMatrix4fv(vp, false, viewProjection);
  gl.activeTexture(gl.TEXTURE0);
  gl.bindTexture(gl.TEXTURE_2D, texture);
  gl.uniform1i(baseColor, 0);
}
```

可复现实验应依次制造三类错误：删掉分号观察编译日志；把 v_color 类型改错观察链接日志；把纹理绑定到 TEXTURE1 但 sampler 保持 0，观察程序已链接却采样错误。这三步分别验证源码、阶段接口和应用绑定。

## 常见误区

<Callout type="trap">
**现象 →** 在所有移动设备上把片元计算统一改成 mediump，远处模型抖动、深度重建断层或高光突然消失。
**原因 →** mediump 只承诺最低范围和精度，具体实现不同；世界坐标和非线性计算可能超出预算。
**修法 →** 查询精度格式并用极端坐标、渐变和深度边缘做对照，只对已验证的中间量降精度。
</Callout>

<Callout type="trap">
**现象 →** 顶点与片元 shader 都编译成功，却无法链接 program。
**原因 →** 单阶段语法合法不代表阶段接口兼容，out/in 的名称、类型、数组、精度或插值限定可能不一致。
**修法 →** 分别保存编译日志，再读取 program link log；把接口声明并排比较，不要继续修改 VAO。
</Callout>

<Callout type="trap">
**现象 →** sampler uniform 已设为 0，纹理仍然全黑或采到了别的材质。
**原因 →** sampler 只选择纹理单元；TEXTURE0 上还必须绑定目标正确且完整的纹理对象。
**修法 →** 同时检查 useProgram、uniform1i、activeTexture、bindTexture、纹理完整性和 mipmap 过滤条件。
</Callout>

## 练习

<Exercises>
**问题 1**：为什么 highp 不能简单理解为“更精确但一定更慢”？WebGL1 与 WebGL2 的片元阶段还要分别检查什么？

<Answer>
精度限定符规定最低范围和精度，硬件可能用同一执行宽度实现多个等级，因此性能差异不能脱离实现和基准断言。WebGL1 的片元 highp float 可能不可用，应查询 getShaderPrecisionFormat 并准备降级；WebGL2 的 GLSL ES 3.00 把片元 highp 纳入核心能力，但仍应记录实际范围和精度，并用目标场景验证数值误差。
</Answer>

**问题 2**：v_color 在顶点阶段是 vec3、片元阶段是 vec4 时，为什么编译可能都成功而链接失败？

<Answer>
每个 shader 单独编译时，vec3 输出和 vec4 输入在各自阶段内都是合法声明；只有链接 program 时，链接器才把相邻阶段组成接口并比较变量。名称相同但类型不一致违反阶段接口契约，因此链接失败。这类错误应读 program info log，而不是检查 VAO 或纹理。
</Answer>

**问题 3**：sampler2D、纹理单元和纹理对象三者如何连接？请给出把纹理接到单元 3 的命令顺序。

<Answer>
sampler2D uniform 保存纹理单元编号；activeTexture 选择应用随后操作的纹理单元；bindTexture 把具体纹理对象绑定到该单元的 TEXTURE_2D 目标。顺序可写为 useProgram(program)，activeTexture(TEXTURE0 + 3)，bindTexture(TEXTURE_2D, texture)，uniform1i(samplerLocation, 3)。还要保证纹理尺寸、格式和过滤所需 mipmap 完整。
</Answer>
</Exercises>

## 小结

- GLSL ES 版本决定可用语法；ES 100、ES 300 和桌面 GLSL 不能只靠关键字替换互转。
- 精度限定符定义最低数值能力，选择必须结合阶段支持查询和极端输入验证。
- 阶段接口在链接时检查，应用接口则由 VAO、uniform、纹理单元和输出附件在绘制时完成。
- smooth、flat 与 centroid 决定顶点输出如何生成片元输入，整数片元输入必须使用 flat。
- 编译、链接、资源绑定应分别制造故障并保存日志，才能把“黑屏”定位到正确边界。
