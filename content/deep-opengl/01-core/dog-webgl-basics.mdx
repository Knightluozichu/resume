## 直觉引入

canvas 同时活在两个坐标系统里：CSS 决定它在页面上显示多大，width/height 属性决定 WebGL 实际拥有多少像素。如果只把 CSS 设成 800×450，而绘图缓冲仍是默认 300×150，浏览器会把低分辨率图像拉伸到大区域；画面能出现，却会模糊并改变宽高比。

WebGL 上下文也不只是“浏览器里的 OpenGL”。它是浏览器为某个 canvas 建立的受安全约束执行环境。版本选择、上下文属性、初始化、跨域资源、能力限制和丢失恢复都属于契约。页面切到后台可能暂停 requestAnimationFrame，但不等于一定丢失上下文；真正丢失必须由 webglcontextlost 事件确认。

## 明确选择版本路径

由 canvas.getContext 创建。应用应先定义能力需求，再选择版本：

- 只支持 WebGL2：请求 webgl2，失败时显示明确的不支持信息；
- 同时支持 WebGL1：为 GLSL ES 1.00、VAO/实例化扩展、纹理格式和功能降级维护独立适配层；
- 不要把 getContext("webgl2") || getContext("webgl") 当作完整回退，因为返回类型变了，后续同一套 WebGL2 命令仍会失败。

WebGL2 以 OpenGL ES 3.0 为基线，核心包含 VAO、实例化、3D/数组纹理、uniform buffer、transform feedback、多 draw buffer 与整数能力。WebGL1 以 ES 2.0 为基线，VAO、实例化、MRT、浮点纹理可渲染性等能力往往需要不同扩展，而且扩展名称与调用入口也可能不同。

```js
function createRendererContext(canvas, mode = "webgl2") {
  const requested = {
    alpha: false,
    depth: true,
    stencil: false,
    antialias: true,
    premultipliedAlpha: false,
    preserveDrawingBuffer: false,
    powerPreference: "high-performance",
  };

  const gl = canvas.getContext(mode, requested);
  if (!gl) throw new Error(`${mode} context creation failed`);

  const actual = gl.getContextAttributes();
  if (!actual) throw new Error("context is already lost");

  return {
    gl,
    actual,
    version: gl.getParameter(gl.VERSION),
    shadingLanguage: gl.getParameter(gl.SHADING_LANGUAGE_VERSION),
    extensions: gl.getSupportedExtensions() ?? [],
  };
}

const canvas = document.querySelector("#viewport");
if (!(canvas instanceof HTMLCanvasElement)) throw new Error("missing canvas");
const context = createRendererContext(canvas, "webgl2");
console.log(context);
```

是请求而非全部强制保证。应用应读取 getContextAttributes 的实际结果。preserveDrawingBuffer=false 通常更利于浏览器复用交换资源，也意味着合成后不能依赖默认帧缓冲旧内容长期保留；需要截图或跨帧积累时，应渲染到自己的 FBO 或在正确时机读取。

## CSS 像素、设备像素与 viewport

尺寸不等于 CSS 尺寸。高 DPI 屏幕上，一个 CSS 像素可能对应多个设备像素。稳定流程是：

1. 读取 canvas.clientWidth/clientHeight；
2. 乘以受控的 devicePixelRatio，并按性能预算限制最大倍率；
3. 只有尺寸变化时更新 canvas.width/height；
4. 使用 gl.drawingBufferWidth/Height 设置 viewport；
5. 把实际宽高比传给投影矩阵和后处理。

```js
function resizeDrawingBuffer(gl, canvas, maxPixelRatio = 2) {
  const ratio = Math.min(window.devicePixelRatio || 1, maxPixelRatio);
  const width = Math.max(1, Math.round(canvas.clientWidth * ratio));
  const height = Math.max(1, Math.round(canvas.clientHeight * ratio));

  if (canvas.width !== width || canvas.height !== height) {
    canvas.width = width;
    canvas.height = height;
  }

  gl.viewport(0, 0, gl.drawingBufferWidth, gl.drawingBufferHeight);
  return gl.drawingBufferWidth / gl.drawingBufferHeight;
}

function renderFrame() {
  const aspect = resizeDrawingBuffer(gl, canvas);
  updateProjection(aspect);
  drawScene();
  requestAnimationFrame(renderFrame);
}
```

盲目使用完整 devicePixelRatio 可能把 4K 手机上的像素数量放大四倍以上，填充率和后处理带宽随面积增长。限制倍率、动态分辨率或离屏低分辨率路径都应建立在实际 drawing buffer 尺寸上。

## 能力探测而非版本猜测

至少回答：

- 最大纹理尺寸、数组层数、顶点属性数和 uniform block 限制是多少；
- 有多少颜色附件和 draw buffer；
- 所需浮点/半浮点格式能否采样、过滤并作为颜色附件；
- timer query、压缩纹理、各向异性过滤等扩展是否存在；
- shader 精度、program 链接和 framebuffer 完整性是否通过真实测试。

getSupportedExtensions 只说明可请求的扩展名称；必须再调用 getExtension 获得对象并检查返回值。核心 API 中“有某个格式枚举”也不自动证明该格式可渲染，应创建最小纹理/FBO 并检查 FRAMEBUFFER_COMPLETE。

| 能力 | WebGL1 | WebGL2 |
| --- | --- | --- |
| VAO | OES_vertex_array_object | 核心 |
| 实例化 | ANGLE_instanced_arrays | 核心 |
| MRT | WEBGL_draw_buffers | 核心 drawBuffers |
| UBO | 无核心能力 | 核心 |
| GLSL ES | 1.00 | 3.00 |
| 3D/数组纹理 | 无核心能力 | 核心 |

这张表只说明规范入口，不能替代限制值、扩展和格式可用性的实际检查。

## 上下文丢失不是页面隐藏

可能由 GPU 重置、驱动问题、浏览器资源策略或测试扩展触发。document.visibilityState 变化只表示页面可见性变化；它适合暂停动画和节能，但不能作为资源失效证据。

发生 webglcontextlost 后：

- 立即停止提交 GL 命令和 requestAnimationFrame 循环；
- 在事件中 preventDefault，表示应用希望浏览器在可能时恢复；这不是恢复时间或成功的保证；
- 丢弃 program、shader、buffer、texture、VAO、FBO、query 及所有 location 缓存；
- 保留 CPU 侧 shader 源码、网格、图片来源、材质和资源描述；
- 等 webglcontextrestored 到来后，按依赖顺序重建全部资源与非默认状态。

## 可测试的丢失恢复实现

```js
let frameId = 0;
let generation = 0;
let resources = createResources(gl, descriptors);

function schedule() {
  frameId = requestAnimationFrame(frame);
}

function frame() {
  draw(gl, resources);
  schedule();
}

canvas.addEventListener("webglcontextlost", (event) => {
  event.preventDefault();
  cancelAnimationFrame(frameId);
  resources = null;
});

canvas.addEventListener("webglcontextrestored", () => {
  try {
    generation += 1;
    const next = createResources(gl, descriptors);
    next.generation = generation;
    resources = next;
    schedule();
  } catch (error) {
    showFatalError("WebGL 资源恢复失败", error);
  }
});

// 仅用于自动化测试，不作为生产恢复机制。
const lose = gl.getExtension("WEBGL_lose_context");
lose?.loseContext();
setTimeout(() => lose?.restoreContext(), 1000);
```

program 重新链接后，attribute/uniform 位置和 WebGLUniformLocation 都属于新 program，旧缓存必须丢弃并重查。恢复测试应验证三件事：lost 期间绘制计数停止；restored 后资源 generation 增加；固定基准场景重新出现且无错误。

## 浏览器安全边界

WebGL 规范要求实现避免把其他进程或旧资源数据泄露给页面，因此未初始化资源、越界访问和着色器行为受到比原生 API 更严格的约束。上传跨域图片到纹理还需要服务器允许 CORS；仅仅能在 img 标签显示，并不表示能安全读取到 WebGL 纹理。

开发服务器与生产 CDN 应共同验证 Access-Control-Allow-Origin、图片解码失败、纹理尺寸和颜色空间。安全约束导致的 INVALID_VALUE 或纹理上传异常，不能靠禁用浏览器策略解决。

## 小结

- WebGL1 回退是独立后端适配，不是 getContext 调用后的自动兼容。
- 上下文属性是请求，实际缓冲配置要通过 getContextAttributes 和能力查询确认。
- CSS 尺寸、受控像素倍率、绘图缓冲、viewport 与投影宽高比必须同步。
- 页面隐藏不等于上下文丢失；只有 lost/restored 事件决定 GPU 资源代生命周期。
- CPU 资源描述与集中创建函数使初始化和恢复复用同一链路，自动化丢失测试才能证明它有效。
