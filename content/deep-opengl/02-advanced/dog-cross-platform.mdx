## 直觉引入

跨平台失败通常不是“完全不支持 OpenGL”，而是某个组合不成立：设备能采样浮点纹理，却不能把该格式作为颜色附件；能写浮点附件，却不支持该目标上的混合；支持四个 draw buffer，但项目 G-buffer 需要五个；shader 能编译，却因精度或扩展差异在另一阶段链接失败。

因此，版本号只能确定核心能力下限，不能直接等价为某条渲染路径。稳定实现要把需求写成数据，收集核心版本、限制、扩展和最小资源实验，再选择一条满足全部必需条件的路径。这套运行时验证也称为**特性检测**；选择结果还要携带“为什么关闭了 HDR/SSAO/实例化”的原因，而不是只返回 high/medium/low。

## 能力契约而不是 if 链

可分三层：

1. **必需能力**：缺少就不能运行该路径，例如 WebGL2、至少四个颜色附件、某种深度纹理格式；
2. **可选质量**：缺少时仍可运行，但关闭浮点混合 bloom、各向异性过滤或 timer query；
3. **资源预算**：最大纹理尺寸、uniform block、采样数、附件数量和内存预算。

仍需结合限制值。例如 WebGL2 核心有 drawBuffers，但 MAX_DRAW_BUFFERS 可能低于高质量 G-buffer 的需求；有 3D texture，也要检查 MAX_3D_TEXTURE_SIZE。

## 后端版本必须一次选定

WebGL2 与 WebGL1 不是同一对象的两个模式。初始化应先尝试目标后端，成功后把 API 包装、shader 版本和资源格式绑定成同一 RendererBackend。若项目真的支持 WebGL1，则维护独立适配层；不能创建 WebGL1 后仍调用 WebGL2 核心方法。

```js
function createBackend(canvas, allowWebGL1) {
  const webgl2 = canvas.getContext("webgl2", { alpha: false });
  if (webgl2) {
    return {
      kind: "webgl2",
      gl: webgl2,
      shaderLanguage: "glsl-es-300",
      vao: {
        create: () => webgl2.createVertexArray(),
        bind: (vao) => webgl2.bindVertexArray(vao),
      },
    };
  }

  if (!allowWebGL1) throw new Error("WebGL2 is required");
  const webgl1 = canvas.getContext("webgl", { alpha: false });
  if (!webgl1) throw new Error("WebGL is unavailable");
  const vao = webgl1.getExtension("OES_vertex_array_object");
  return {
    kind: "webgl1",
    gl: webgl1,
    shaderLanguage: "glsl-es-100",
    vao: vao
      ? {
          create: () => vao.createVertexArrayOES(),
          bind: (object) => vao.bindVertexArrayOES(object),
        }
      : null,
  };
}
```

同一个 canvas 一旦成功建立一种上下文，之后再请求另一种类型通常不能当作安全切换机制。后端选择应发生一次，页面要切换后端则重新创建 canvas 与完整资源图。

## 扩展是独立能力，不是等级徽章

通过 getExtension 返回扩展对象或启用对应语义。getSupportedExtensions 适合遥测和 UI，不应替代逐项 getExtension。

以 HDR 后处理为例，至少要拆开：

- 浮点/半浮点纹理能否创建和采样；
- 该 internal format 能否作为颜色附件；
- 过滤模式是否支持算法需要的线性过滤；
- 目标上是否需要且支持浮点混合；
- 多附件数量和位宽是否落在预算；
- shader 精度是否满足色调映射与亮区提取。

EXT_color_buffer_float 与 EXT_float_blend 解决的不是同一个问题。前者不能被“有 float blend”替代，后者也不应成为所有 HDR 算法的前置条件：若 bloom 用独立 additive 合成到 LDR 目标或不在浮点目标混合，需求会不同。

## 格式探针验证具体组合

比“枚举存在”更强。下面的函数创建 1×1 纹理并挂到 FBO，验证该 internalFormat/format/type 组合是否可作为颜色目标。

```js
function probeColorRenderable(gl, internalFormat, format, type) {
  const texture = gl.createTexture();
  const framebuffer = gl.createFramebuffer();
  if (!texture || !framebuffer) return false;

  let complete = false;
  try {
    gl.bindTexture(gl.TEXTURE_2D, texture);
    gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.NEAREST);
    gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.NEAREST);
    gl.texImage2D(
      gl.TEXTURE_2D,
      0,
      internalFormat,
      1,
      1,
      0,
      format,
      type,
      null,
    );

    gl.bindFramebuffer(gl.FRAMEBUFFER, framebuffer);
    gl.framebufferTexture2D(
      gl.FRAMEBUFFER,
      gl.COLOR_ATTACHMENT0,
      gl.TEXTURE_2D,
      texture,
      0,
    );
    gl.drawBuffers([gl.COLOR_ATTACHMENT0]);
    complete =
      gl.checkFramebufferStatus(gl.FRAMEBUFFER) ===
      gl.FRAMEBUFFER_COMPLETE;
  } finally {
    gl.bindFramebuffer(gl.FRAMEBUFFER, null);
    gl.deleteFramebuffer(framebuffer);
    gl.deleteTexture(texture);
  }
  return complete;
}
```

更强的探针会绘制已知颜色并 readPixels 比较容差，以捕获“FBO 完整但 shader/混合/读取组合不满足算法”的情况。探针应在初始化阶段运行并缓存结果，不能每帧创建资源。

## 声明式路径选择与解释

不是 catch 住异常后随便关闭效果。每条路径要声明必需条件、关闭项和替代算法。

```js
const paths = [
  {
    id: "deferred-hdr",
    requires: (c) =>
      c.webgl2 &&
      c.maxDrawBuffers >= 4 &&
      c.rgba16fRenderable &&
      c.maxTextureSize >= 4096,
    disabled: [],
  },
  {
    id: "forward-hdr",
    requires: (c) => c.webgl2 && c.rgba16fRenderable,
    disabled: ["deferred", "ssao"],
  },
  {
    id: "forward-ldr",
    requires: (c) => c.rgba8Renderable,
    disabled: ["hdr", "bloom", "ssao"],
  },
];

function selectPath(capabilities) {
  for (const path of paths) {
    if (path.requires(capabilities)) {
      return { ...path, reason: "all required capabilities satisfied" };
    }
  }
  throw new Error("no render path satisfies mandatory RGBA8 output");
}
```

生产代码最好把 requires 拆成命名断言，返回每项 pass/fail。这样遥测可记录“deferred-hdr 缺 MAX_DRAW_BUFFERS>=4”而非模糊的“low device”。

## Shader 变体与 API 适配

GLSL ES 100、GLSL ES 300、GLSL ES 320 和桌面 GLSL 的版本声明、阶段、限定符、纹理函数、输出方式与扩展语法不同。可靠方案有三种：

- 维护少量人工审查的独立源码；
- 从统一 shader IR/模板生成后端版本，并保存生成产物做编译测试；
- 使用成熟跨平台着色器工具链，反射出 attribute、uniform block 和资源绑定。

不要用无边界正则把 attribute 替换为 in，就宣称完成移植。ES100 的 varying/gl_FragColor、ES300 的用户输出、桌面 profile、精度语句和扩展声明都需要语法级转换与目标编译验证。

## 设备矩阵与回归证据

兼容测试至少按后端、GPU 家族、操作系统/浏览器和驱动版本分层。每个样本保存：

- VERSION、SHADING_LANGUAGE_VERSION、renderer（注意隐私与浏览器脱敏）；
- 核心限制值、启用扩展和格式探针结果；
- 被选路径、禁用效果和逐条原因；
- 固定场景截图/像素哈希、shader 编译日志和 FBO 状态；
- CPU/GPU 帧时间、内存与上下文丢失恢复结果。

设备数量有限时，可优先覆盖能力边界而非只覆盖品牌：WebGL1 无 VAO、WebGL2 最低 draw buffers、无 float blend、低 MAX_TEXTURE_SIZE、片元精度边界和高 DPI 内存压力。

## 小结

- 版本给核心下限，具体路径还取决于限制值、扩展和可执行资源探针。
- 可渲染、可过滤、可混合是独立能力；HDR 不能用单个扩展布尔值概括。
- WebGL1 回退必须同步切换 API、GLSL 和资源格式，半回退比明确失败更难诊断。
- 降级路径应保证正确性并返回关闭项和原因，而不是把设备贴成高/中/低标签。
- 结构化设备矩阵把能力选择变成可复现、可回归、可删除旧黑名单的工程证据。
