## 直觉引入

图形程序的“黑屏”不是一个错误类型，而是许多不同断点的共同外观：默认帧缓冲没显示、viewport 为零、三角形在裁剪空间外、VAO 读错缓冲、program 未链接、颜色写掩码关闭、深度测试拒绝全部片元，或后处理采样了错误纹理。随机切开关只能偶然命中，不能形成可复现诊断。

正确方法是建立证据层级：先确认输出目标能显示已知清屏色，再用固定裁剪空间三角形和常量色 shader 隔离几何与着色，随后逐层恢复真实状态。在第一处从正确变错误的位置抓帧，检查那次 draw 的完整输入。

## WebGL 错误队列的边界

不会像 JavaScript 异常一样自动指出调用栈。gl.getError 一次返回一个错误；若之前已有未读取错误，当前调用后的 getError 也不能自动证明错误由当前调用产生。

开发期可在隔离区间前先排空旧错误，执行一小段命令，再排空并报告新错误。不要给生产热路径每个 GL 调用都包 getError：频繁查询会增加开销，也不能提供比正确性实验更强的上下文。

```js
const ERROR_NAMES = new Map([
  [WebGL2RenderingContext.INVALID_ENUM, "INVALID_ENUM"],
  [WebGL2RenderingContext.INVALID_VALUE, "INVALID_VALUE"],
  [WebGL2RenderingContext.INVALID_OPERATION, "INVALID_OPERATION"],
  [WebGL2RenderingContext.INVALID_FRAMEBUFFER_OPERATION,
    "INVALID_FRAMEBUFFER_OPERATION"],
  [WebGL2RenderingContext.OUT_OF_MEMORY, "OUT_OF_MEMORY"],
  [WebGL2RenderingContext.CONTEXT_LOST_WEBGL, "CONTEXT_LOST_WEBGL"],
]);

function drainErrors(gl) {
  const errors = [];
  for (;;) {
    const error = gl.getError();
    if (error === gl.NO_ERROR) return errors;
    errors.push(ERROR_NAMES.get(error) ?? `0x${error.toString(16)}`);
  }
}

function checked(gl, label, operation) {
  const stale = drainErrors(gl);
  if (stale.length) console.warn("stale GL errors", stale);
  const result = operation();
  const current = drainErrors(gl);
  if (current.length) {
    throw new Error(`${label}: ${current.join(", ")}`);
  }
  return result;
}
```

getError 只报告规范错误，不保证捕获算法错误。draw 成功但矩阵错误、纹理内容错误或颜色正确却写到错误附件，都可能返回 NO_ERROR。

## KHR_debug 属于原生调试路径

WebGL2 不暴露，也没有 gl.debugMessageCallback。原生 OpenGL 与支持该扩展/核心能力的 OpenGL ES 可创建调试上下文，注册 glDebugMessageCallback，并用 glObjectLabel 给 program、buffer、texture、FBO 命名。

```cpp
void APIENTRY onGlDebug(
    GLenum source,
    GLenum type,
    GLuint id,
    GLenum severity,
    GLsizei,
    const GLchar* message,
    const void*) {
  if (severity == GL_DEBUG_SEVERITY_NOTIFICATION) return;
  logError("GL", source, type, id, severity, message);
}

void enableNativeDebug() {
  glEnable(GL_DEBUG_OUTPUT);
  glEnable(GL_DEBUG_OUTPUT_SYNCHRONOUS); // 仅开发期，便于保留调用栈
  glDebugMessageCallback(onGlDebug, nullptr);
  glObjectLabel(GL_PROGRAM, lightingProgram, -1, "lighting/program");
  glObjectLabel(GL_FRAMEBUFFER, gbuffer, -1, "deferred/gbuffer");
}
```

同步回调便于在触发调用栈停住，但会改变性能，性能测量时应关闭。WebGL 端要依赖 getError、shader/program 日志、浏览器扩展工具和帧抓取，不要复制原生 KHR_debug JavaScript 伪代码。

## 着色器日志必须保留源码行号

分两层：COMPILE_STATUS 对单个 shader，LINK_STATUS 对组合后的 program。info log 可能包含警告，也可能在失败时为空，因此状态位是判断依据，日志是诊断证据。

```js
function numbered(source) {
  return source
    .split("\n")
    .map((line, index) => `${String(index + 1).padStart(4)} | ${line}`)
    .join("\n");
}

function compile(gl, type, source, label) {
  const shader = gl.createShader(type);
  if (!shader) throw new Error(`${label}: createShader failed`);
  gl.shaderSource(shader, source);
  gl.compileShader(shader);
  const ok = gl.getShaderParameter(shader, gl.COMPILE_STATUS);
  const log = gl.getShaderInfoLog(shader) ?? "";
  if (!ok) {
    gl.deleteShader(shader);
    throw new Error(`${label} compile failed\n${log}\n${numbered(source)}`);
  }
  if (log.trim()) console.warn(`${label} compile log\n${log}`);
  return shader;
}

function link(gl, vertex, fragment, label) {
  const program = gl.createProgram();
  if (!program) throw new Error(`${label}: createProgram failed`);
  gl.attachShader(program, vertex);
  gl.attachShader(program, fragment);
  gl.linkProgram(program);
  const ok = gl.getProgramParameter(program, gl.LINK_STATUS);
  const log = gl.getProgramInfoLog(program) ?? "";
  if (!ok) {
    gl.deleteProgram(program);
    throw new Error(`${label} link failed\n${log}`);
  }
  return program;
}
```

链接成功后还要检查活跃 attribute、uniform、uniform block 和输出映射。位置为 -1/null 可能是变量被优化掉，也可能是名字或 program 用错；结合活跃接口枚举才能区分。

## 黑屏用已知输出二分


一个实用顺序是：

1. 默认 framebuffer 清洋红并立即呈现，证明 canvas/surface、viewport 和交换链；
2. 绑定目标 FBO 后也清不同颜色，检查附件、drawBuffers 和合成链；
3. 使用 gl_VertexID 生成固定裁剪空间三角形，排除 VBO/VAO/相机；
4. 片元输出常量白色，排除纹理、光照、颜色空间；
5. 逐项恢复 VAO、矩阵、纹理、深度/混合和后处理，记录第一处变化。

“洋红都看不到”时不应继续调法线贴图；“常量三角形正确，恢复 VAO 后消失”时也不应继续改 FBO。每一步都把搜索空间切小。

## 帧抓取查看 draw 的完整输入

应按平台选工具：

- Spector.js 面向 WebGL，可在浏览器捕获一帧并查看 command、program、uniform、texture、framebuffer 和状态；
- RenderDoc 适合原生 OpenGL/OpenGL ES、Vulkan、D3D 等受支持应用，能查看事件、管线、资源、mesh 和像素历史；
- 浏览器 WebGL 不应默认按原生桌面进程方式交给 RenderDoc，优先使用 Spector.js 和浏览器自己的 GPU 工具。

抓帧先找最后一个仍正确的 pass，再找第一个错误输出的 draw。检查：

- 当前 framebuffer 和颜色/深度附件是否是预期对象；
- viewport/scissor 与目标尺寸是否一致；
- program 源码、链接接口、uniform 和 sampler 单元；
- VAO 属性格式、缓冲内容、索引范围和实例 divisor；
- 深度、模板、混合、剔除、写掩码；
- 输入纹理 mip/层级/格式及该 draw 前是否已被正确写入。

帧抓取会增加开销，适合正确性和工作量分析，不应把抓取时的绝对帧时间当最终性能结论。


## GPU 计时要保持异步

在 WebGL2 中由 EXT_disjoint_timer_query_webgl2 提供。结果可用前读取会阻塞或无结果；GPU_DISJOINT_EXT 为真时，频率变化或重置使样本无效，必须丢弃。

```js
function beginGpuTimer(gl, ext, label) {
  const query = gl.createQuery();
  if (!query) return null;
  gl.beginQuery(ext.TIME_ELAPSED_EXT, query);
  return { label, query };
}

function endGpuTimer(gl, ext, pending, sample) {
  if (!sample) return;
  gl.endQuery(ext.TIME_ELAPSED_EXT);
  pending.push(sample);
}

function pollGpuTimers(gl, ext, pending) {
  const disjoint = gl.getParameter(ext.GPU_DISJOINT_EXT);
  const results = [];
  const waiting = [];
  for (const sample of pending) {
    const available = gl.getQueryParameter(
      sample.query,
      gl.QUERY_RESULT_AVAILABLE,
    );
    if (!available) {
      waiting.push(sample);
      continue;
    }
    if (!disjoint) {
      const ns = gl.getQueryParameter(sample.query, gl.QUERY_RESULT);
      results.push({ label: sample.label, milliseconds: ns / 1e6 });
    }
    gl.deleteQuery(sample.query);
  }
  return { waiting, results };
}
```

CPU 侧用 performance.mark/measure 或引擎 profiler 标记更新、剔除、排序、上传和提交。CPU 与 GPU 时间结合工作量计数，才能区分：

- CPU 提交：CPU 高、GPU 空洞，少 draw/状态缓存有效；
- 顶点：降低模型细分或实例数显著改善；
- 片元：降低分辨率或改常量 shader 显著改善；
- 带宽：降低附件/纹理位宽、采样数或 load/store 改善；
- 同步：移除 readPixels/finish/立即 query 后 CPU/GPU 空洞消失。

## 小结

- WebGL getError 与原生 KHR_debug 是两条不同调试路径，WebGL2 没有 debugMessageCallback。
- 编译、链接、活跃接口和应用绑定必须分别留证，状态位比 info log 是否为空更权威。
- 黑屏先用清屏色、固定三角形和常量 shader 找第一处断点，再抓取该 draw 的完整状态。
- Spector.js 面向 WebGL，RenderDoc 面向受支持原生图形应用；抓帧适合正确性而非绝对性能。
- GPU query 必须异步、检查 disjoint，并与 CPU marker 和工作量计数共同解释瓶颈。
