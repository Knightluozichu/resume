## 直觉引入

帧缓冲对象不是一张图片，而是一张“输出接线表”。它把片元着色器的颜色输出接到纹理或 renderbuffer，把深度/模板测试接到对应附件。真正保存像素的是附件；FBO 只描述本次绘制要写到哪里。

后处理之所以需要 FBO，不是因为默认帧缓冲绝对不能被读取，而是应用需要可控格式、尺寸、生命周期和采样方式的中间图像。场景先写入离屏颜色纹理，后续 pass 把它作为输入，再写到另一张纹理或默认帧缓冲。这个“读 A、写 B”的方向必须明确，不能一边采样 A 一边又把 A 作为当前输出。

## FBO 与附件所有权

本身不拥有附件存储。删除 FBO 不会自动删除独立创建并挂接的 texture/renderbuffer；资源管理器应分别跟踪并销毁。

有两类常见载体：

- texture 可在后续 shader 中采样，适合颜色、深度采样、后处理和 shadow map；
- renderbuffer 面向渲染目标存储，不能直接被 shader 采样，适合只在 pass 内用于深度/模板或多采样附件。

深度附件不是 FBO 完整的必需条件。纯颜色后处理 FBO 可以只有颜色附件；若 3D pass 需要近处遮挡远处，才要提供深度存储。没有深度附件时，即使代码启用 DEPTH_TEST，也没有可保留的深度缓冲来产生预期遮挡结果，但这不等同于 framebuffer 不完整。

## 完整性只验证目标组合

由 checkFramebufferStatus 检查。FRAMEBUFFER_COMPLETE 证明附件组合可用，不证明：

- viewport 与目标尺寸一致；
- shader 输出 location 与 drawBuffers 映射正确；
- pass 已清除或加载了期望内容；
- 采样器没有读取正在写入的附件；
- 颜色空间、混合、深度和写掩码符合算法。

常见不完整来源包括附件对象或层级无效、尺寸为零、格式不可渲染、相关附件 sample 数不一致，以及 drawBuffers 指向未挂接颜色位置。浮点纹理“可以采样”不代表“可以作为颜色附件”，WebGL2 中仍需按格式与 EXT_color_buffer_float 等能力验证。

## 创建可采样颜色目标

使用 texStorage2D 建立不可变 RGBA8 颜色存储，配一个 DEPTH_COMPONENT24 renderbuffer。不可变纹理不能原地改尺寸，resize 时应创建一套新资源，成功后再替换旧套件。

```js
function createSceneTarget(gl, width, height) {
  const framebuffer = gl.createFramebuffer();
  const color = gl.createTexture();
  const depth = gl.createRenderbuffer();
  if (!framebuffer || !color || !depth) {
    throw new Error("create framebuffer resources failed");
  }

  gl.bindTexture(gl.TEXTURE_2D, color);
  gl.texStorage2D(gl.TEXTURE_2D, 1, gl.RGBA8, width, height);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.LINEAR);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE);
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE);

  gl.bindRenderbuffer(gl.RENDERBUFFER, depth);
  gl.renderbufferStorage(
    gl.RENDERBUFFER,
    gl.DEPTH_COMPONENT24,
    width,
    height,
  );

  gl.bindFramebuffer(gl.FRAMEBUFFER, framebuffer);
  gl.framebufferTexture2D(
    gl.FRAMEBUFFER,
    gl.COLOR_ATTACHMENT0,
    gl.TEXTURE_2D,
    color,
    0,
  );
  gl.framebufferRenderbuffer(
    gl.FRAMEBUFFER,
    gl.DEPTH_ATTACHMENT,
    gl.RENDERBUFFER,
    depth,
  );
  gl.drawBuffers([gl.COLOR_ATTACHMENT0]);

  const status = gl.checkFramebufferStatus(gl.FRAMEBUFFER);
  gl.bindFramebuffer(gl.FRAMEBUFFER, null);
  if (status !== gl.FRAMEBUFFER_COMPLETE) {
    gl.deleteFramebuffer(framebuffer);
    gl.deleteTexture(color);
    gl.deleteRenderbuffer(depth);
    throw new Error(`incomplete framebuffer: 0x${status.toString(16)}`);
  }
  return { framebuffer, color, depth, width, height };
}
```

如果有多个颜色输出，依次挂 COLOR_ATTACHMENT0+n，并调用 drawBuffers 指定映射。片元 shader 的 layout(location=n) 输出最终写入 drawBuffers 列表中对应的附件；只挂纹理但不配置输出映射，不能构成完整 MRT pass。

## 每个 pass 都有状态契约

FBO 切换不仅是 bindFramebuffer。每个 pass 至少声明 framebuffer、viewport/scissor、drawBuffers、clear/load 语义、深度/模板/混合、颜色掩码、program、VAO 和输入纹理。

场景 pass 写离屏目标，合成 pass 再把颜色纹理画到默认帧缓冲。全屏三角形只需三个顶点，可由 gl_VertexID 在顶点 shader 中生成，避免四边形中间对角线和额外顶点。

```js
function renderScenePass(gl, target) {
  gl.bindFramebuffer(gl.FRAMEBUFFER, target.framebuffer);
  gl.viewport(0, 0, target.width, target.height);
  gl.enable(gl.DEPTH_TEST);
  gl.depthMask(true);
  gl.disable(gl.BLEND);
  gl.clearColor(0, 0, 0, 1);
  gl.clearDepth(1);
  gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT);
  drawScene(gl);
}

function renderCompositePass(gl, sourceTexture, canvas) {
  gl.bindFramebuffer(gl.FRAMEBUFFER, null);
  gl.viewport(0, 0, gl.drawingBufferWidth, gl.drawingBufferHeight);
  gl.disable(gl.DEPTH_TEST);
  gl.depthMask(false);
  gl.disable(gl.BLEND);
  gl.useProgram(compositeProgram);
  gl.activeTexture(gl.TEXTURE0);
  gl.bindTexture(gl.TEXTURE_2D, sourceTexture);
  gl.uniform1i(sourceLocation, 0);
  gl.bindVertexArray(fullscreenVao);
  gl.drawArrays(gl.TRIANGLES, 0, 3);
}
```

默认帧缓冲尺寸应取 drawingBufferWidth/Height，而不是只读 CSS clientWidth。离屏目标可按渲染比例使用不同尺寸，但投影、采样 texel size 和 viewport 必须使用各自实际尺寸。

## 反馈环路与 ping-pong

在 WebGL/OpenGL 渲染中不可作为普通后处理手段。读取与写入同一图像会产生禁止或未定义的反馈，不能假设 GPU 按像素顺序“原地更新”。

让第 n 遍读 source、写 destination，完成后交换引用。可分离高斯模糊常用一遍水平、一遍垂直；每遍只采一维邻域。

```js
function blurPingPong(gl, input, targets, passCount) {
  let source = input;
  for (let pass = 0; pass < passCount; pass += 1) {
    const destination = targets[pass % 2];
    if (destination.color === source) {
      throw new Error("read/write framebuffer feedback loop");
    }

    gl.bindFramebuffer(gl.FRAMEBUFFER, destination.framebuffer);
    gl.viewport(0, 0, destination.width, destination.height);
    gl.disable(gl.DEPTH_TEST);
    gl.disable(gl.BLEND);
    gl.useProgram(blurProgram);
    gl.activeTexture(gl.TEXTURE0);
    gl.bindTexture(gl.TEXTURE_2D, source);
    gl.uniform1i(blurSourceLocation, 0);
    gl.uniform2f(
      texelSizeLocation,
      1 / destination.width,
      1 / destination.height,
    );
    gl.uniform1i(horizontalLocation, pass % 2 === 0 ? 1 : 0);
    gl.bindVertexArray(fullscreenVao);
    gl.drawArrays(gl.TRIANGLES, 0, 3);
    source = destination.color;
  }
  return source;
}
```

两个目标必须尺寸和格式符合算法，且 input 不应与第一遍 destination 相同。更复杂的 render graph 可以根据资源生存期自动分配临时纹理，但底层仍遵守“同一 pass 读写资源不冲突”。

## 多采样与 resolve

WebGL2 的多采样 renderbuffer 可用 renderbufferStorageMultisample 创建，但普通 sampler2D 不能直接采样它。常见链路是：

1. 场景写入多采样颜色/深度 renderbuffer FBO；
2. 把它绑定为 READ_FRAMEBUFFER，把单采样纹理 FBO 绑定为 DRAW_FRAMEBUFFER；
3. 用 blitFramebuffer resolve 颜色；
4. 后处理采样单采样颜色纹理。

resolve 的源/目标尺寸、格式、过滤和 mask 受规范约束。若只为后处理而不需要 MSAA，应先测量其额外存储与 resolve 成本；移动设备上也可评估更便宜的抗锯齿路径。

## Resize 与资源重建

窗口尺寸或渲染比例变化时，所有依赖尺寸的纹理、renderbuffer、MSAA resolve 目标和 texel-size uniform 都要更新。使用 texStorage2D 的不可变纹理应重建，而不是对旧对象再次分配。

稳妥做法是先创建 nextTarget，检查完整后原子替换 currentTarget，再删除旧资源。若新尺寸超过设备限制或分配失败，保留旧目标并降低渲染比例，避免半套附件导致后续 pass 崩溃。

## 小结

- FBO 是附件接线状态，不保存像素；texture/renderbuffer 生命周期必须独立管理。
- 缺深度附件不等于不完整，是否需要深度由 pass 的遮挡、采样和后续使用决定。
- FRAMEBUFFER_COMPLETE 只证明目标组合可绘制，viewport、drawBuffers、反馈和状态仍需检查。
- 多采样目标通常先 resolve 到单采样纹理，再进入普通后处理。
- ping-pong、pass 状态契约和原子 resize 重建共同保证多遍链路可移植、可诊断。
