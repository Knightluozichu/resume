## 直觉引入

想象你在装修一栋房子。最初（C# 1.0）你打好地基、砌好墙——委托、事件、属性。然后（C# 2.0）你加了泛型这个「通用模板」，让橱柜可以装任何东西。接着（C# 3.0）你引入了 LINQ 这个「中央吸尘系统」，彻底改变了清洁方式。后来（C# 5.0）你装了 async/await 这个「智能家居系统」，让一切自动化。最近（C# 9.0）你用 record 重新装修了客厅，让它更简洁、更现代。

关键在于：你从未推倒重建。每次装修都在原有结构上叠加，旧家具（C# 1.0 代码）依然能用。这就是 C# 的进化哲学——持续进化但不破坏向后兼容。

## 概念讲解

### 三大阶段

<Term def="奠基期（C# 1.0-3.0）是 C# 建立核心语言能力的阶段：委托、泛型、LINQ 三大基石在此期间奠定。C# 3.0 的 LINQ 被称为分水岭，因为它把查询从外部 DSL 变成了语言一等公民。">

**奠基期（C# 1.0-3.0，2002-2007）**：建立核心语言能力。

- C# 1.0：委托、事件、属性、垃圾回收。类型安全的面向对象基础。
- C# 2.0：泛型、匿名方法、迭代器（`yield`）、可空类型（`Nullable<T>`）。泛型是类型安全的参数化，迭代器引入了状态机技术。
- C# 3.0：Lambda、扩展方法、LINQ、隐式类型（`var`）、表达式树。LINQ 依赖 Lambda + 扩展方法 + 表达式树的协同，是 C# 的分水岭。

</Term>

<Term def="进化期（C# 4.0-6.0）是 C# 拓展语言边界的阶段：dynamic 打通动态世界，async/await 解决异步回调地狱，语法糖大幅减少样板代码。">

**进化期（C# 4.0-6.0，2010-2015）**：拓展语言边界。

- C# 4.0：`dynamic`、命名参数、可选参数、协变/逆变泛型接口。`dynamic` 打通了与 COM 和动态语言的互操作。
- C# 5.0：`async/await`、调用方信息特性。async/await 复用迭代器状态机技术，把异步回调写成同步样式。
- C# 6.0：字符串插值、null 条件运算符（`?.`）、表达式主体成员。语法糖阶段，减少样板代码。

</Term>

<Term def="现代化期（C# 7.0-9.0）是 C# 引入函数式编程能力的阶段：模式匹配、可空引用类型、record 使 C# 从纯命令式走向多范式。">

**现代化期（C# 7.0-9.0，2017-2020）**：引入函数式能力。

- C# 7.0-7.3：模式匹配、元组、本地函数、`out` 变量声明、弃元（`_`）。
- C# 8.0：可空引用类型（NRT）、异步流（`IAsyncEnumerable`）、`switch` 表达式。
- C# 9.0：`record`、顶级语句、`init`-only 属性、目标类型 `new`、模式匹配增强。

</Term>

### C# 3.0 为什么是分水岭

C# 3.0 的 LINQ 把「查询」从外部 DSL（SQL 字符串）变成了语言一等公民——查询表达式直接编译成 C# 代码，有类型检查和智能提示。但 LINQ 不是单一特性，它依赖 C# 3.0 的五个新特性协同：

1. **Lambda**：`Where(x => x > 5)` 的谓词载体
2. **扩展方法**：让 `IEnumerable<T>` 看起来有 `Where/Select` 方法
3. **隐式类型（`var`）**：避免手写复杂返回类型
4. **匿名类型**：投影 `select new { Name = x.Name }` 的基石
5. **表达式树**：`IQueryable<T>` 把 Lambda 编译成数据结构供翻译成 SQL

</Step>

## 代码对照

```csharp
// 同一段「打招呼」逻辑在 C# 各版本中的写法演变

// C# 1.0：显式委托 + 命名方法
delegate string Greeter(string name);
string SayHi(string name) { return "Hello, " + name; }
Greeter g = new Greeter(SayHi);
Console.WriteLine(g("World"));

// C# 6.0：字符串插值
string SayHi6(string name) => $"Hello, {name}";

// C# 9.0：顶级语句 + record + 模式匹配
record Person(string Name, int Age);
var person = new Person("World", 30);
var greeting = person switch
{
    { Age: < 18 } => $"Hi, {person.Name}!",
    { Age: >= 18 } => $"Hello, {person.Name}.",
    _ => "Unknown"
};
Console.WriteLine(greeting);
```

## 常见误区

<Callout type="trap">

**误区：把 C# 3.0 的 LINQ 当成单一特性**

LINQ 不是单一特性，而是 Lambda + 扩展方法 + `var` + 匿名类型 + 表达式树五个特性的协同。没有 Lambda 就没有谓词载体，没有扩展方法 `IEnumerable<T>` 就没有 `Where/Select`，没有表达式树 `IQueryable` 就无法翻译成 SQL。理解这一点才能理解为什么 C# 3.0 是最重大的版本。

</Callout>

<Callout type="trap">

**误区：可空引用类型（NRT）是运行时检查**

C# 8.0 的可空引用类型是**编译时分析**，不是运行时检查。编译器做流分析，在可能为 null 的地方发出警告。运行时不做额外检查，零运行时开销。这与 TypeScript 的类型检查类似——类型标注帮助你在编译期发现问题。旧代码升级时 NRT 默认关闭，可以逐步开启。

</Callout>

<Exercises>

**问题 1**：C# 3.0 的 LINQ 依赖了哪些 C# 3.0 新特性？为什么说它是「分水岭」？

<Answer>

LINQ 依赖 Lambda（谓词载体）、扩展方法（让 `IEnumerable<T>` 有 `Where/Select`）、`var`（避免手写复杂类型）、匿名类型（投影基石）和表达式树（`IQueryable` 翻译成 SQL）。它是分水岭因为把查询从外部 DSL 变成了语言一等公民，有类型检查和智能提示，彻底改变了数据处理方式。

</Answer>

**问题 2**：从 C# 1.0 到 9.0，C# 在「减少样板代码」方面经历了哪些关键进化？

<Answer>

多条进化线：委托创建从 `new Delegate(Method)` 简化到 `x => x + 1`（C# 1.0→3.0）；属性从字段+属性体简化到 `public int X { get; set; }` 再到 `init`（C# 2.0→9.0）；类型声明引入 `var` 和目标类型 `new()`；程序入口从 `class Program { static void Main() }` 简化到顶级语句；`record Point(int X, int Y)` 一行替代整个不可变值类。核心方向是让编译器生成更多样板代码。

</Answer>

</Exercises>
