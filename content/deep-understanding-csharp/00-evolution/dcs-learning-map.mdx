## 直觉引入

如果你要了解一个人，最好的方式不是看他今天的照片，而是看他从小到大的成长相册——每张照片记录了他应对当时挑战的方式，串起来就是他的性格轨迹。

C# 也是如此。它不是一个静态的语言规范，而是一个持续进化了二十年的生命体。C# 1.0 引入委托是为了解决函数指针的类型安全问题；C# 3.0 引入 Lambda 是因为委托语法太冗长；C# 5.0 引入 async/await 是因为回调地狱太痛苦。每个特性都不是凭空出现的——它是 C# 对前一版本痛点的回应。

本书以「演进史」为全书主线，因为这样你能看到每个特性的「为什么」，而不只是「怎么用」。

## 概念讲解

### 四大板块

全书按 C# 的演进脉络分为四个板块，每个板块对应语言发展的一个阶段：

1. **C# 演进**（第 1-2 章）：学习地图与 C# 演进史。先建立全景认知，知道 C# 从 1.0 到 9.0 每个版本引入了什么。
2. **语言核心**（第 3-5 章）：委托与事件、迭代器与 yield、Lambda 与闭包。这是 C# 2.0-3.0 引入的核心语言机制，是后续所有特性的地基。
3. **动态并发**（第 6-7 章）：动态语言特性与异步内部机制。覆盖 C# 4.0 的 `dynamic` 和 C# 5.0 的 `async/await`。
4. **现代特性**（第 8-10 章）：模式匹配、Record 与元组、总复习。覆盖 C# 7.0-9.0 引入的函数式风格特性。

### 为什么按演进顺序学

<Term def="委托是 C# 1.0 引入的类型安全函数引用，是整个回调体系的基石。Lambda、事件、async/await 底层都依赖委托。">

按演进顺序学的核心价值在于建立**因果链**。委托（C# 1.0）是 Lambda（C# 3.0）的基础——Lambda 本质上是委托的语法糖。迭代器（C# 2.0）的 `yield return` 状态机技术是 async/await（C# 5.0）状态机的技术前身。Record（C# 9.0）+ 模式匹配（C# 7.0-9.0）组合出函数式数据建模能力。

如果你跳过委托直接学 Lambda，你只知道「Lambda 是匿名函数」，但不知道它编译后是委托实例。如果你跳过迭代器直接学 async/await，你不知道编译器复用了迭代器的状态机基础设施。

</Term>

### 学习路径建议

**推荐路径**：C# 演进史 → 语言核心（委托→迭代器→Lambda）→ 动态并发 → 现代特性 → 总复习。

语言核心三章必须按顺序学：委托是 Lambda 的基础，Lambda 是闭包的基础。动态并发和现代特性可以在这三条地基上灵活学习，但总复习应放在最后。

</Step>

<Step title="第四步：现代特性收全貌">

</Step>

## 代码对照

```csharp
// C# 演进链：同一段「过滤列表」逻辑在不同版本中的写法

// C# 1.0：命名方法 + 显式委托实例
delegate bool Filter(int x);
List<int> FilterList(List<int> list, Filter filter)
{
    var result = new List<int>();
    foreach (int x in list)
        if (filter(x)) result.Add(x);
    return result;
}
// 使用：FilterList(nums, new Filter(IsGreaterThan5));

// C# 2.0：匿名方法 + 方法组转换
FilterList(nums, delegate(int x) { return x > 5; });

// C# 3.0：Lambda + LINQ
nums.Where(x => x > 5).ToList();

// C# 9.0：record + 模式匹配
record Number(int Value);
var bigNumbers = numbers
    .Where(n => n is Number { Value: > 5 })
    .ToList();
```

从 C# 1.0 的 5 行命名方法到 C# 3.0 的 1 行 Lambda，再到 C# 9.0 的模式匹配——每一步简化都建立在前一步的基础上。

## 常见误区

<Callout type="trap">

**误区：跳过语言核心直接学异步**

async/await 的编译器转换生成状态机，状态机大量使用 Lambda 和闭包。不理解闭包就读不懂生成的代码。`Task` 的 continuation 机制与委托直接相关，迭代器的状态机模式是异步状态机的前身。跳过语言核心学异步，只能学语法，学不到原理。

</Callout>

<Callout type="trap">

**误区：把 C# 当 Java 学**

C# 3.0 之后的 LINQ、C# 5.0 的 async/await、C# 9.0 的 record 使 C# 与 Java 走向了完全不同的方向。如果只学 C# 的 OOP 部分（类、接口、继承），会错过 C# 最有价值的函数式和异步能力。C# 是多范式语言，不能只用 OOP 视角看它。

</Callout>

<Exercises>

**问题 1**：本书为什么以「C# 演进史」作为全书主线而不是按主题分类？

<Answer>

按演进史为主线，能看到每个特性的「为什么」——它在解决前一个版本的什么痛点。委托解决函数指针类型安全问题，Lambda 解决委托语法冗长，async 解决回调地狱。按主题分类虽然查阅方便，但会丢失特性之间的因果关系，变成孤立的知识点。

</Answer>

**问题 2**：如果跳过「语言核心」直接学「异步内部机制」会有什么问题？

<Answer>

async/await 的编译器转换生成状态机，状态机大量使用 Lambda 和闭包。不理解闭包就读不懂生成的代码。Task 的 continuation 机制与委托直接相关，迭代器的状态机模式是异步状态机的前身——C# 编译器先实现了迭代器状态机（C# 2.0），再在其基础上实现异步状态机（C# 5.0）。

</Answer>
