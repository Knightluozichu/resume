## 直觉引入

你给物业公司留了一个电话号码，说「有快递到了就打这个电话通知我」。这个电话号码就是一个**委托**——你把「通知我」这个行为委托给了物业，物业不需要知道你是谁、住哪里，只需要在特定事件发生时拨这个号码。

委托定义了「打电话的规则」（签名：传什么参数、返回什么），任何符合规则的人（方法）都可以被登记。你可以留多个电话号码（多播），快递到了所有号码都会被拨打。

`event` 关键字则像是物业的公告板——外部人只能在上面贴自己的电话号码（`+=` 订阅）或撕掉自己的号码（`-=` 取消），但不能替别人贴/撕，也不能自己假装快递到了去打电话（只有物业能触发）。

## 概念讲解

### 委托：类型安全的函数引用

<Term def="委托（delegate）是 C# 中类型安全的函数引用。它定义了方法的签名（参数类型和返回类型），任何匹配该签名的方法都可以赋给委托实例。委托继承自 System.MulticastDelegate，支持多播（一个委托实例包含多个方法）。">

委托的核心是**签名契约**。声明 `delegate void Handler(string msg)` 后，任何接受 `string` 参数、返回 `void` 的方法都能赋给它。编译器在赋值时检查签名匹配——不匹配会编译报错。这是委托与 C/C++ 函数指针的根本区别：函数指针只是裸地址，不检查签名；委托是类型安全的。

委托还是面向对象的——它继承自 `System.MulticastDelegate`，可以携带目标对象（实例方法的 `this`），可以链式调用（多播）。

</Term>

### event：对委托的封装

<Term def="事件（event）是对委托字段的封装，提供发布-订阅模式的访问控制。外部只能 += 订阅和 -= 取消，不能 = 覆盖或直接 Invoke。只有声明类内部才能触发事件。">

`public event EventHandler Click;` 和 `public EventHandler Click;` 的区别：

- **委托字段**：外部可以 `=` 覆盖（清除所有订阅者）、可以 `()` 直接调用（伪造事件触发）。
- **event**：外部只能 `+=` 和 `-=`，不能覆盖、不能直接调用。只有声明类内部能 `Click?.Invoke()` 触发。

event 本质是「对委托字段的封装」，类似 property 对字段的封装。编译后生成一个 private 委托字段 + public `add_Click`/`remove_Click` 方法。

</Term>

### 多播委托

一个委托实例可以包含多个方法（`+=` 添加）。调用时按顺序全部执行。如果某个方法抛异常，后面的方法不会被执行——异常直接传播给调用者。

<Step title="委托定义与方法绑定">

委托定义签名契约：`delegate void Handler(string msg)`。任何匹配签名的方法（如 `void OnClick(string msg)`）都可以赋给委托实例。委托携带目标对象的 `this`，可以调用实例方法。与 C++ 函数指针不同，委托有编译时类型检查。

</Step>

<Step title="event 封装：发布-订阅控制">

`event Handler Click` 限制外部只能 `+=`/`-=`，防止外部覆盖订阅者或伪造触发。只有声明类内部能 `Click?.Invoke(args)`。这就像物业的公告板——租户只能贴/撕自己的号码，不能动别人的，也不能假装快递到了。

</Step>

<Step title="多播调用链">

`Click += HandlerA; Click += HandlerB; Click += HandlerC;` 后，触发 Click 时按 A→B→C 顺序调用。如果 B 抛异常，C 不会被调用。关键场景需要用 `GetInvocationList()` 逐个调用并 try-catch 隔离异常。

</Step>

<Step title="委托实例化语法演进">

C# 1.0：`new Handler(Method)`（显式实例化 + 命名方法）。C# 2.0：`delegate(string x) { ... }`（匿名方法 + 方法组转换）。C# 3.0：`x => ...`（Lambda，最简形式）。从 3 行降到 1 行，催生了 LINQ 的声明式查询。

</Step>

## 代码对照

```csharp
// 委托与事件的完整演进

// === C# 1.0：显式委托 + 命名方法 ===
public delegate void ClickHandler(object sender, EventArgs e);

class Button
{
    // event 封装：外部只能 += / -=
    public event ClickHandler? Click;

    public void SimulateClick()
    {
        // 只有内部能触发
        Click?.Invoke(this, EventArgs.Empty);
    }
}

// 使用
var btn = new Button();
btn.Click += new ClickHandler(OnButtonClick);  // C# 1.0 写法

static void OnButtonClick(object sender, EventArgs e)
{
    Console.WriteLine("Clicked!");
}

// === C# 2.0：匿名方法 ===
btn.Click += delegate(object sender, EventArgs e) {
    Console.WriteLine("Anonymous handler");
};

// === C# 3.0：Lambda ===
btn.Click += (sender, e) => Console.WriteLine("Lambda handler");

// === 多播异常隔离 ===
btn.Click += (s, e) => throw new InvalidOperationException("Boom!");

// 不安全的直接触发（会停在前面的异常）
// btn.SimulateClick();  // HandlerA 执行 -> 异常 -> 后续 Handler 不执行

// 安全的多播调用
foreach (var handler in btn.Click?.GetInvocationList() ?? Array.Empty<Delegate>())
{
    try { handler.DynamicInvoke(btn, EventArgs.Empty); }
    catch (Exception ex) { Console.WriteLine($"Handler failed: {ex.Message}"); }
}
```

## 常见误区

<Callout type="trap">

**误区：event 和 public 委托字段效果一样**

`public event Handler Click` 和 `public Handler Click` 有本质区别。委托字段可以被外部 `=` 覆盖（清除所有订阅者）或直接 `()` 调用（伪造事件）。event 强制外部只能 `+=`/`-=`，保护了发布-订阅语义。就像你不会把变量设为 public 而是用属性封装一样，回调也应该用 event 封装。

</Callout>

<Callout type="trap">

**误区：多播委托中一个方法异常不影响其他方法**

默认的 `event?.Invoke()` 是一把梭调用——一个方法抛异常，后面的方法全部被跳过。在事件系统中这通常是不可接受的：一个订阅者的 bug 不应该影响其他订阅者。关键场景需要用 `GetInvocationList()` 逐个 `DynamicInvoke` 并 try-catch 隔离。

</Callout>

<Exercises>

**问题 1**：为什么有了委托还需要 event 关键字？

<Answer>

event 对委托字段提供访问控制：外部只能 `+=`/`-=` 订阅和取消，不能 `=` 覆盖（防止清除其他订阅者）或直接 `Invoke`（防止伪造事件触发）。只有声明类内部能触发事件。event 本质是对委托字段的封装，类似 property 对字段的封装。

</Answer>

**问题 2**：多播委托的调用列表中某个方法抛出异常会怎样？如何安全调用？

<Answer>

默认 `Invoke()` 按顺序调用，某个方法抛异常后后面的方法不会被执行——异常直接传播给调用者。安全调用的方法是用 `GetInvocationList()` 获取 `Delegate[]`，逐个 `DynamicInvoke` 并用 try-catch 包裹每个方法，确保一个失败不影响其他订阅者。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="委托（delegate）">

C# 中类型安全的函数引用。定义方法签名（参数和返回类型），匹配签名的方法可赋给委托实例。继承自 `System.MulticastDelegate`，支持多播、携带目标对象。是回调体系的基石。

</GlossaryItem>

<GlossaryItem term="事件（event）">

对委托字段的封装。外部只能 `+=`/`-=` 订阅，不能覆盖或直接调用。编译后生成 private 委托字段 + public add/remove 方法。提供发布-订阅模式的访问控制。

</GlossaryItem>

<GlossaryItem term="多播委托">

一个委托实例包含多个方法（`+=` 添加）。调用时按顺序全部执行。某个方法抛异常则后续方法不执行。可用 `GetInvocationList()` 逐个调用隔离异常。

</GlossaryItem>

<GlossaryItem term="方法组转换">

C# 2.0 引入的特性：可以直接把方法名赋给委托，不需要 `new DelegateType(Method)`。编译器自动推断并创建委托实例。

</GlossaryItem>

</Glossary>
