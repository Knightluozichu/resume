## 直觉引入

回顾全书的旅程：我们从 C# 1.0 的委托出发，经过迭代器的 `yield return` 状态机、Lambda 的闭包捕获、`dynamic` 的运行时绑定、`async/await` 的异步状态机，最终到达模式匹配和 record 的函数式数据建模。

这条路径不是随意的——每一步都是对前一步的改进和叠加。委托是 Lambda 的前身（Lambda 是委托的语法糖）。迭代器状态机是 async/await 状态机的技术基础（编译器复用同一套基础设施）。Lambda + 模式匹配 + record 组合出函数式编程范式。

C# 的演进可以概括为一句话：**从命令式到多范式**。数据建模从可变 class 走向不可变 record，控制流从 if-else 走向 switch 表达式，异步从回调地狱走向 async/await。但底层机制从未被推翻——C# 1.0 的委托在 C# 10+ 中仍是整个回调体系的基石。

## 概念讲解

### 六大特性因果链

<Term def="C# 六大特性的因果链：委托（C# 1.0）是类型安全回调的基石；迭代器 yield（C# 2.0）引入状态机技术；Lambda 闭包（C# 3.0）简化委托创建，是 LINQ 基石；async/await（C# 5.0）复用迭代器状态机 + 委托回调；模式匹配（C# 7-9）引入声明式分支；record（C# 9.0）提供值语义不可变数据。">

1. **委托**（C# 1.0）：类型安全的函数引用，回调体系的基石。
2. **迭代器 yield**（C# 2.0）：编译器生成状态机，首次引入「方法体拆分」技术。
3. **Lambda + 闭包**（C# 3.0）：简化委托创建，引入变量捕获和表达式树。LINQ 的基石。
4. **async/await**（C# 5.0）：复用迭代器状态机技术，用委托注册 continuation，把异步写成同步样式。
5. **模式匹配**（C# 7.0-9.0）：类型检查从 if-else 变成声明式 switch 表达式。
6. **record**（C# 9.0）：值语义的不可变数据类型，with 表达式 + 模式匹配 = 函数式数据建模。

因果关联：委托→Lambda（语法简化），迭代器→async（状态机复用），Lambda→LINQ→模式匹配（函数式思维），record+模式匹配（函数式数据建模）。

</Term>

### 状态机技术复用

迭代器状态机与 async/await 状态机的核心相同点：方法体拆成 switch-case、局部变量提升为字段、`MoveNext` 驱动暂停-恢复。核心不同点：迭代器是同步暂停（调用方主动 MoveNext），async 是异步暂停（Task 完成 + SynchronizationContext 恢复，可能跨线程）。

### 范式迁移的三个维度

<Term def="C# 从命令式到函数式的范式迁移体现在三个维度：数据建模（class 可变→record 不可变 + with）、控制流（if-else→switch 表达式 + 模式匹配）、异步处理（回调嵌套→async/await monadic 组合）。但 C# 不是纯函数式语言——可变性仍是默认，函数式特性是工具箱中的工具。">

1. **数据建模**：class + 可变属性 → record + init-only + with 表达式。数据从「有状态对象」变成「不可变值」。
2. **控制流**：if-else 链 + 类型转换 → switch 表达式 + 模式匹配。控制流从命令式分支变成值表达式。
3. **异步处理**：回调嵌套 → async/await。异步从手动管理回调变成编译器生成状态机。

## 代码对照

```csharp
// 综合应用：异步生产者-消费者管道

// 1. record 定义不可变数据（第 9 章）
record DataItem(int Id, string Content);

// 2. async IAsyncEnumerable 异步生产（第 4、7 章）
async IAsyncEnumerable<DataItem> ProduceAsync(
    [EnumeratorCancellation] CancellationToken ct)
{
    for (int i = 0; !ct.IsCancellationRequested; i++)
    {
        var content = await FetchFromApiAsync(i, ct);
        yield return new DataItem(i, content);
        await Task.Delay(1000, ct);
    }
}

// 3. Channel 异步缓冲
var channel = Channel.CreateBounded<DataItem>(100);

// 4. 生产者：await foreach 消费 IAsyncEnumerable
async Task ProduceToChannelAsync(CancellationToken ct)
{
    await foreach (var item in ProduceAsync(ct))
    {
        await channel.Writer.WriteAsync(item, ct);
    }
    channel.Writer.Complete();
}

// 5. 消费者：模式匹配处理
async Task ConsumeFromChannelAsync(CancellationToken ct)
{
    await foreach (var item in channel.Reader.ReadAllAsync(ct))
    {
        // switch 表达式 + 属性模式 + 关系模式 + when 子句
        var result = item switch
        {
            { Id: 0 }                    => "first item",
            { Content.Length: > 100 }    => "long content",
            DataItem { Id: var id } when id % 10 == 0 => "milestone",
            _                            => "normal"
        };
        Console.WriteLine($"{item.Id}: {result}");
    }
}

// 6. 全栈异步：Task.WhenAll 并行运行
var cts = new CancellationTokenSource(TimeSpan.FromMinutes(5));
await Task.WhenAll(
    ProduceToChannelAsync(cts.Token),
    ConsumeFromChannelAsync(cts.Token)
);

// === 六大特性在此管道中的角色 ===
// record（第 9 章）：DataItem 不可变数据载体
// yield return（第 4 章）：ProduceAsync 逐个产出，延迟执行
// async/await（第 7 章）：异步 IO 不阻塞线程
// IAsyncEnumerable（第 7 章）：异步迭代器，await foreach
// 模式匹配（第 8 章）：switch 表达式声明式处理
// 委托/Lambda（第 3、5 章）：Task continuation 的底层载体
```

## 常见误区

<Callout type="trap">

**误区：六大特性是独立的，可以单独学**

六大特性有强因果链：委托是 Lambda 的基础（Lambda 编译为委托），迭代器状态机是 async/await 的技术基础（编译器复用），Lambda + 模式匹配 + record 组合出函数式范式。跳过委托学 Lambda 只知道语法不知道原理，跳过迭代器学 async/await 不理解状态机转换。必须按因果链顺序学。

</Callout>

<Callout type="trap">

**误区：C# 已经完全变成了函数式语言**

C# 引入了函数式特性（record、模式匹配、不可变数据），但不是纯函数式语言。可变性仍是默认（class 可变、局部变量可变），record 是引用类型有拷贝开销，模式匹配不如 F# 的完整匹配强制，没有 IO monad 隔离副作用。C# 的定位是「多范式」——函数式特性是工具箱中的工具，不是强制范式。开发者可以按场景选择命令式或函数式风格。

</Callout>

<Callout type="trap">

**误区：迭代器状态机和 async 状态机是不同的技术**

两者是同一套编译器基础设施。核心相同：方法体拆成 switch-case、局部变量提升为字段、MoveNext 驱动暂停-恢复。C# 编译器团队先实现了迭代器状态机（C# 2.0），再在其基础上实现异步状态机（C# 5.0）。不同点仅在恢复机制：迭代器是调用方主动 MoveNext（同步），async 是 Task 完成 + SynchronizationContext 恢复（异步，可能跨线程）。

</Callout>

<GlossaryItem term="状态机技术复用">

编译器把含 yield/await 的方法体拆成 switch-case 状态机。迭代器（C# 2.0）和 async/await（C# 5.0）共用同一套编译器基础设施。核心相同：局部变量提升为字段、MoveNext 驱动暂停-恢复。不同点：迭代器同步暂停，async 异步暂停（可能跨线程）。

</GlossaryItem>

<GlossaryItem term="范式迁移">

C# 从命令式到多范式的迁移体现在三个维度：数据建模（class→record）、控制流（if-else→switch 表达式）、异步处理（回调→async/await）。但 C# 不是纯函数式——函数式特性是工具箱中的工具，可变性仍是默认。

</GlossaryItem>

<GlossaryItem term="叠加进化哲学">

C# 的设计哲学：每个新特性在旧特性基础上叠加，不推翻重来。委托→Lambda→表达式树，迭代器状态机→async 状态机，class→record。C# 1.0 代码在 C# 10+ 中仍能编译运行。这是 C# 与「推倒重来」的语言最大的不同。

</GlossaryItem>
