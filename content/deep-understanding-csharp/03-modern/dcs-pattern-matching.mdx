## 直觉引入

传统的类型检查像是在机场安检：你拿出证件（`is Type`），安检员看一眼，通过了你再走（强制转换）。如果你想检查多种类型，就要排好几次队（多层 if-else + is + 强制转换）。

模式匹配则是「一站式安检」——你把行李放上去，机器自动识别行李类型并执行对应操作。`shape switch { Circle c => ..., Rectangle r => ..., _ => ... }` 一行搞定：类型检查、变量绑定、分支分发全在一起。

更重要的是，模式匹配不只是类型检查。它可以检查属性（`{ Age: >= 18 }`）、比较大小（`> 5`）、组合条件（`and`/`or`/`not`），甚至递归解构（嵌套位置模式）。这让 C# 的分支逻辑从命令式的 if-else 链走向函数式的声明式匹配。

## 概念讲解

### 六种模式匹配类型

<Term def="模式匹配是 C# 7.0-9.0 逐步引入的声明式分支机制。六种类型：类型模式（is Type var）、常量模式（is null）、属性模式（is { Prop: pattern }）、位置模式（is Type(p1, p2)）、关系模式（is > 5）、逻辑模式（and/or/not）。模式可组合使用。">

1. **类型模式**（C# 7.0）：`o is string s` —— 检查类型并绑定变量。
2. **常量模式**（C# 7.0）：`x is null`、`count is 0` —— 检查是否等于常量。
3. **属性模式**（C# 8.0）：`p is { Age: >= 18 }` —— 检查对象属性。
4. **位置模式**（C# 8.0）：`p is Point(0, 0)` —— 通过 Deconstruct 解构匹配。
5. **关系模式**（C# 9.0）：`x is > 5`、`x is <= 10` —— 大小比较。
6. **逻辑模式**（C# 9.0）：`and`、`or`、`not` —— 组合模式。

模式可组合：`person is { Age: >= 18 and <= 65, Name: not null }`。

</Term>

### switch 表达式

<Term def="switch 表达式是 C# 8.0 引入的声明式分支语法。`shape switch { Circle c => ..., _ => ... }` 返回一个值，用箭头语法替代 case/break。支持模式匹配、穷尽性检查、无 fall-through。是 C# 走向函数式编程的重要一步。">

switch 表达式 vs switch 语句：
1. **表达式 vs 语句**：switch 表达式返回值，可直接赋值/返回；switch 语句是控制流。
2. **箭头语法**：`pattern => result` 取代 `case ... : ... break;`。
3. **模式匹配**：switch 表达式天然支持类型/属性/关系等模式。
4. **穷尽性检查**：switch 表达式要求穷尽所有可能（或加 `_`），否则编译器警告。
5. **无 fall-through**：每个分支独立返回，不需要 break。

</Term>

### 位置模式与 Deconstruct

<Term def="位置模式通过类型的 Deconstruct 方法解构对象，然后对各部分进行模式匹配。`p is Point(0, 0)` 编译器查找 Point 的 Deconstruct(out int, out int) 方法。record 类型自动生成 Deconstruct。也支持扩展方法提供 Deconstruct。">

位置模式要求类型有 `Deconstruct` 方法。`Point(0, 0)` 编译器查找 `Point.Deconstruct(out int x, out int y)`。支持嵌套：`Line(Point(0, 0), _)` 匹配起点在原点的线段。record 自动生成 Deconstruct。

</Term>

## 代码对照

```csharp
// 模式匹配的完整应用

// === 类型模式 + switch 表达式 ===
abstract record Shape;
record Circle(double Radius) : Shape;
record Rectangle(double Width, double Height) : Shape;
record Triangle(double A, double B, double C) : Shape;

double GetArea(Shape shape) => shape switch
{
    Circle c         => Math.PI * c.Radius * c.Radius,
    Rectangle r      => r.Width * r.Height,
    Triangle t       => HeronFormula(t.A, t.B, t.C),
    _                => 0
};

// === 属性模式 + 关系模式 + 逻辑模式 ===
string GetCategory(Person p) => p switch
{
    { Age: < 13 }              => "Child",
    { Age: >= 13 and < 20 }    => "Teenager",
    { Age: >= 20 and < 65 }    => "Adult",
    { Age: >= 65 }             => "Senior",
    _                          => "Unknown"
};

// === 位置模式 + 嵌套 ===
record Point(int X, int Y);
record Line(Point Start, Point End)
{
    public void Deconstruct(out Point start, out Point end)
    {
        start = Start;
        end = End;
    }
}

string DescribePoint(Point p) => p switch
{
    Point(0, 0)     => "origin",
    Point(0, _)     => "on Y axis",
    Point(_, 0)     => "on X axis",
    Point(var x, var y) when x == y => "on diagonal",
    _               => $"({p.X}, {p.Y})"
};

bool IsFromOrigin(Line l) => l switch
{
    Line(Point(0, 0), _) => true,   // 嵌套位置模式
    _                     => false
};

// === not 模式简化 null 检查 ===
if (shape is not null) { /* ... */ }

// === 元组模式 ===
string Classify(int x, int y) => (x, y) switch
{
    (0, 0) => "origin",
    (0, _) => "y-axis",
    (_, 0) => "x-axis",
    (var a, var b) when a > 0 && b > 0 => "Q1",
    (var a, var b) when a < 0 && b > 0 => "Q2",
    (var a, var b) when a < 0 && b < 0 => "Q3",
    _ => "Q4"
};
```

## 常见误区

<Callout type="trap">

**误区：模式匹配只是 if-else 的语法糖**

模式匹配不只是语法糖。它提供了声明式的分支语义——你描述「匹配什么」而不是「怎么检查」。它支持穷尽性检查（编译器警告未处理的分支）、嵌套递归匹配（位置模式嵌套）、模式组合（and/or/not）。更重要的是，switch 表达式返回值，使分支从控制流变成值表达式，这是函数式编程的核心特征。

</Callout>

<Callout type="trap">

**误区：模式匹配取代了 OOP 多态**

模式匹配和多态是互补的，不是替代关系。行为多变、数据固定时用 OOP 多态（策略模式——新增策略不修改现有代码）。数据多变、行为固定时用模式匹配（状态机——所有转换在一个 switch 表达式中）。需要跨类型匹配多个维度时用模式匹配（OOP 需要访问者模式才能做到）。

</Callout>

**问题 2**：switch 表达式和 switch 语句有什么区别？

<Answer>

switch 表达式返回值（可直接赋值/返回），用箭头语法 `pattern => result` 取代 `case/break`。天然支持模式匹配，有穷尽性检查（要求覆盖所有分支或加 `_`），无 fall-through（每个分支独立返回）。switch 语句是控制流，需要手动赋值和 break，支持 fall-through。switch 表达式是 C# 走向函数式的重要一步——把控制流变成值表达式。

</Answer>
