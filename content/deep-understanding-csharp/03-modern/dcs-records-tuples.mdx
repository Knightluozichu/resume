## 直觉引入

`class` 和 `record` 的区别可以用「身份证」和「名片」来比喻。

`class` 像身份证——两张身份证即使信息完全相同（同名、同号），它们也是两张不同的物理卡片（引用不同）。`p1.Equals(p2)` 比较的是「这是不是同一张卡」，不是「信息是否相同」。

`record` 像名片——两张名片如果印的信息完全相同，它们就是「等价」的。`p1.Equals(p2)` 比较的是「信息是否相同」，不是「是不是同一张纸」。这就是**值相等性**。

`record` 还有一个超能力：`with` 表达式。你可以「复印一张名片然后改掉一个字」——`p2 = p1 with { X = 10 }`。原名片不变，新名片是副本只改了 X。这是修改不可变对象的标准方式。

元组则像便签纸——临时写几个值凑一起用，不需要印刷名片（定义类型名）。`(1, "hello")` 就是便签，用完即弃。如果需要正式的名片（类型名、公共 API），用 record；如果只是临时打包，用元组。

## 概念讲解

### record：值语义的引用类型

<Term def="record 是 C# 9.0 引入的基于值相等性的引用类型。`record Point(int X, int Y)` 一行声明自动生成：构造函数、基于值的 Equals/GetHashCode/ToString、== 和 != 运算符、Deconstruct、with 表达式支持。所有属性是 init-only（不可变）。">

record 自动生成的成员：
1. **构造函数**：主构造函数参数成为 init-only 属性。
2. **基于值的 Equals**：所有属性相等则 Equals 返回 true（class 默认比较引用）。
3. **GetHashCode**：基于所有属性值计算。
4. **ToString**：`Point { X = 1, Y = 2 }` 可读格式。
5. **== 和 !=**：重载为值相等比较。
6. **Deconstruct**：`var (x, y) = point` 解构。
7. **with 表达式支持**：编译器生成拷贝构造函数。

</Term>

### with 表达式

<Term def="with 表达式是 C# 9.0 引入的不可变对象修改语法。`p2 = p1 with { X = 10 }` 创建 p1 的副本并修改 X。编译器调用拷贝构造函数创建完整副本，再修改指定属性。原对象不变。这是修改不可变 record 的标准方式。">

with 表达式做了三件事：
1. 调用 record 的受保护拷贝构造函数，创建完整副本。
2. 对副本应用指定的属性修改（通过 init-only setter）。
3. 返回修改后的副本。

class 不能用 with 表达式——没有拷贝构造函数、没有自动 init-only 属性、没有编译器生成的 with 支持。

</Term>

### record vs class vs 元组

| 特性 | record | class | 元组 |
|---|---|---|---|
| 相等性 | 值相等 | 引用相等 | 值相等 |
| 可变性 | 不可变 (init) | 可变 (set) | 不可变 |
| with 表达式 | 支持 | 不支持 | 支持 |
| 类型名 | 有 | 有 | 无 |
| 适用场景 | DTO/值对象 | 有状态对象 | 临时组合 |

`record Point(int X, int Y)` 的两个实例 `new Point(1, 2)` 和 `new Point(1, 2)` 的 `Equals` 返回 true（值相等）。class 的两个实例即使属性相同 `Equals` 返回 false（引用不同）。record 自动生成 Equals/GetHashCode/ToString/== /!=。

</Step>

<Step title="with 表达式：修改不可变对象">

`var p2 = p1 with { X = 10 }` 创建 p1 的副本并修改 X。编译器调用拷贝构造函数创建完整副本，再修改指定属性。原 p1 不变。class 不能用 with——没有拷贝构造函数和 init-only 属性。

</Step>

<Step title="元组：临时组合">

`(int Id, string Name)` 是匿名元组，编译期有命名别名但运行时仍是 `Item1/Item2`。适合方法返回多值、内部临时组合。不需要定义类型名。`var (id, name) = GetTuple()` 解构。

</Step>

<Step title="选择原则">

record：公共 API、领域模型（DTO/值对象/领域事件），需要类型名。元组：内部实现、临时返回值、用完即弃。class：有可变状态和行为的对象。如果组合值需要类型名表达业务语义，用 record；如果只是临时打包，用元组。

</Step>

</Stepper>

## 代码对照

```csharp
// record、class 与元组对比

// === record：值相等 + with + 自动生成 ===
record Point(int X, int Y);

var p1 = new Point(1, 2);
var p2 = new Point(1, 2);
Console.WriteLine(p1.Equals(p2));  // True（值相等）
Console.WriteLine(p1 == p2);       // True
Console.WriteLine(p1);             // Point { X = 1, Y = 2 }

// with 表达式
var p3 = p1 with { X = 10 };
Console.WriteLine(p3);             // Point { X = 10, Y = 2 }
Console.WriteLine(p1);             // Point { X = 1, Y = 2 }（不变）

// Deconstruct
var (x, y) = p1;
Console.WriteLine($"{x}, {y}");    // 1, 2

// === class：引用相等 ===
class PointClass
{
    public int X { get; set; }
    public int Y { get; set; }
    public PointClass(int x, int y) { X = x; Y = y; }
}

var c1 = new PointClass(1, 2);
var c2 = new PointClass(1, 2);
Console.WriteLine(c1.Equals(c2));  // False（引用不同）
// c1 with { X = 10 };  // 编译错误：class 不支持 with

// === 元组：临时组合 ===
(int Id, string Name) GetItem() => (1, "Alice");
var item = GetItem();
Console.WriteLine(item.Id);        // 1
Console.WriteLine(item.Name);      // Alice
Console.WriteLine(item.Item1);     // 1（仍可用 Item1）

// 元组值相等
var t1 = (1, "hello");
var t2 = (1, "hello");
Console.WriteLine(t1.Equals(t2));  // True

// === record 继承 ===
record Shape(string Color);
record Circle(string Color, double Radius) : Shape(Color);

var circle = new Circle("red", 5);
var sameCircle = new Circle("red", 5);
Console.WriteLine(circle.Equals(sameCircle));  // True（类型+值相同）

Shape shape = circle;
var copy = shape with { Color = "blue" };
// copy 是 Circle("blue", 5)，不是 Shape("blue")
// with 保留运行时类型，但只能修改编译时类型(Shape)的属性

// === record struct (C# 10.0) ===
record struct Rect(int W, int H);
var r1 = new Rect(3, 4);
var r2 = r1 with { H = 5 };
```

## 常见误区

<Callout type="trap">

**误区：record 就是 class 的语法糖**

record 不只是语法糖。它的核心语义是**值相等性**——两个 record 实例属性全等则 Equals 返回 true。class 默认是引用相等（除非手动重写 Equals）。record 还自动生成 with 表达式支持、Deconstruct、ToString 等。更重要的是，record 的属性是 init-only（不可变），class 默认可变。record 适合不可变数据载体，class 适合有状态对象。

</Callout>

<Callout type="trap">

**误区：with 表达式修改了原对象**

with 表达式不修改原对象——它创建一个完整副本并修改副本的指定属性。原对象完全不变。这是修改不可变 record 的标准方式：不修改，而是创建修改了部分属性的新副本。`var p2 = p1 with { X = 10 }` 后 p1 仍然是原值。大对象的 with 有性能开销（完整拷贝），不如 F# 的 structural sharing。

</Callout>

<Callout type="trap">

**误区：基类引用上用 with 可以修改子类属性**

`Shape s = new Circle("red", 5); var s2 = s with { Radius = 10 };` 编译错误——s 的编译时类型是 Shape，Shape 没有 Radius 属性。with 表达式只能修改编译时类型的属性。需要先 cast 或模式匹配获取具体类型。但 with 保留运行时类型——s2 是 Circle("blue", 5) 而非 Shape("blue")。

</Callout>

<Exercises>

**问题 1**：record 和 class 的核心区别是什么？record 自动生成了哪些成员？

<Answer>

核心区别是相等性：record 是值相等（属性全等则 Equals 返回 true），class 是引用相等（不同实例 Equals 返回 false）。record 自动生成：构造函数、基于值的 Equals/GetHashCode、ToString、== / != 运算符、Deconstruct、with 表达式支持（拷贝构造函数）。record 属性是 init-only（不可变），class 默认可变。

</Answer>

**问题 2**：什么时候用 record，什么时候用元组？

<Answer>

record 适合公共 API、领域模型（DTO/值对象/领域事件）——需要类型名表达业务语义、长生命周期、需要继承或自定义行为。元组适合内部实现、方法返回多值、临时组合——用完即弃、不需要类型名。规则：如果组合值需要类型名表达业务含义，用 record；如果只是临时打包传一下，用元组。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="record">

C# 9.0 引入的基于值相等性的引用类型。一行声明自动生成 Equals/GetHashCode/ToString/==/Deconstruct/with 支持。属性是 init-only（不可变）。适合 DTO、值对象、领域事件。

</GlossaryItem>

<GlossaryItem term="with 表达式">

C# 9.0 引入的不可变对象修改语法。`p with { X = 10 }` 创建副本并修改指定属性，原对象不变。编译器调用拷贝构造函数创建完整副本。class 不支持 with。

</GlossaryItem>

<GlossaryItem term="值相等性">

两个对象所有属性相等则 Equals 返回 true。record 和元组是值相等，class 默认是引用相等（比较是否同一实例）。record 通过 EqualityContract 保证继承体系中类型也必须相同。

</GlossaryItem>

<GlossaryItem term="元组（Tuple）">

C# 7.0 引入的 ValueTuple 语法。`(int Id, string Name)` 是匿名值类型，值相等、不可变、无类型名。命名元组的名字是编译期别名，运行时仍是 Item1/Item2。适合临时组合，不适合公共 API。

</GlossaryItem>

<GlossaryItem term="EqualityContract">

record 编译器生成的属性，记录实际运行时类型。比较时不仅比较属性值，还比较 EqualityContract——运行时类型必须相同才相等。保证 Circle 和 Rectangle 即使 Color 相同也不相等。

</GlossaryItem>

</Glossary>
