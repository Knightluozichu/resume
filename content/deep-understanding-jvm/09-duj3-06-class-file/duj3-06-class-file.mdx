# 第6章 类文件结构

Java 源码编译后不是一团无法阅读的二进制，而是一份有严格布局的 Class 文件合同。它先用固定头部说明自己是谁、属于哪个版本，再用常量池保存符号，随后列出访问标志、类与父类索引、字段、方法和属性。方法真正执行时，Code 属性又把局部变量、操作数栈、异常表和字节码组织起来。

本章的目标不是背下每个字节的偏移，而是能在“源码构造—Class 字节—`javap` 输出—虚拟机接受结果”之间往返。结构字段属于 JVMS 规范，`javap` 属于 JDK 工具，HotSpot 对指令的解释和编译属于实现观察；这三层必须在实验档案中分开写。

<Objectives>

- 能从魔数、版本、常量池、成员表、属性表和 Code 属性解释一份 Class 文件的主要结构。
- 能只改变一个源码构造或编译选项，使用 `javap`、字节哈希、异常和新 JVM 重放定位首个结构差异。
- 能区分 JVMS 合同、JDK 工具输出与 HotSpot 实现，在版本不兼容或证据冲突时回滚并保留未知项。

</Objectives>

## 三个必须主动触发的误区

<Callout type="trap" title="把主版本号当成唯一兼容性判断">
  **现象 →** Class 文件主版本号在目标 JDK 范围内，就直接断定应用兼容。 **原因
  →** 常量池引用、模块边界、依赖签名、属性和运行时行为也可能不兼容。 **修法 →**
  固定完整类路径和运行时，保存版本、依赖、`javap` 输出、启动异常和新 JVM
  重放结果。
</Callout>

<Callout type="trap" title="把常量池编号当成稳定 API">
  **现象 →** 一次编译看到 `#7` 指向某个方法，便在脚本中永久写死这个编号。 **原因
  →** 增删字符串、字段或编译器生成的合成成员都可能重排常量池。 **修法 →**
  记录“编号 → 标签 →
  描述符”的当前映射，并按语义和字节哈希比较，不把索引当稳定接口。
</Callout>

<Callout type="trap" title="只看字节码，不看属性和边界">
  **现象 →** `javap -c` 的指令看起来一致，就认为两份 Class 完全相同。 **原因 →**
  调试信息、签名、注解、异常表、栈映射和模块属性可能改变工具、验证或框架行为。
  **修法 →** 用 `-v -l -s` 保存完整输出，并把源码、编译参数、Class
  哈希和实际加载来源一起交接。
</Callout>

## 一张从字节偏移到语义的结构地图

先把输入固定为一份 Class 文件和一组编译命令，再从左到右观察结构：头部决定版本，常量池提供符号，成员和属性描述类的内容，Code 属性承载方法实现。任何差异都要回答两个问题：它位于哪种结构，改变后会影响解析、验证、调试还是运行时语义？

### 第6章 类文件结构

正式范围是“第6章 类文件结构”。本章的通过不变量是：字节偏移、JVMS 结构、`javap` 输出和源码构造四者能够相互指向。实验只改变一个源码构造或编译选项；若只剩一张反编译截图而没有 Class 哈希与原始输出，结论保持 `unknown`。

### 6.1 概述

Class 文件是一种有序的二进制数据结构，不是把 Java 源码逐字保存下来。读取它时先建立“字段名—长度—偏移—解释”的表格，再用工具输出校对；工具展示顺序可能与物理布局不同，所以不要把 `javap` 的视觉顺序直接当成字节排列。

### 6.2 无关性的基石

Class 文件把编译器与虚拟机之间的合同固定下来：源码语言可以演进，编译器可以改变实现细节，但运行时只接受符合规范布局和版本约束的字节。所谓“无关性”不是所有行为完全相同，而是不同实现都能按共同结构解释同一份合法输入。

### 6.3 Class类文件的结构

顶层结构可以按 `magic`、版本、常量池、访问标志、类索引、接口集合、字段表、方法表和属性表阅读。每一段都有计数或长度边界，定位错误时先检查前一段是否读多或读少，因为后续所有偏移都可能被连锁推歪。

### 6.3.1 魔数与Class文件的版本

文件开头的魔数用于快速识别输入，次后的次版本和主版本表达 Class 文件版本。`javap -verbose` 会把版本译成工具可读信息，但兼容判断仍应以目标 JDK 实际加载结果为准；只改主版本并在新 JVM 重放，可以观察版本门禁出现在哪个阶段。

### 6.3.2 常量池

常量池是从 1 开始编号的共享符号表，可能包含 UTF-8 字符串、类、字段、方法、名称与类型等不同标签。索引的意义依赖标签和交叉引用，不能只看数字；增删一个字符串就可能改变大量编号，所以对比时应还原标签链与描述符。

### 6.3.3 访问标志

访问标志说明这是类、接口、枚举还是模块，也描述 `public`、`final`、抽象、合成等属性。它是结构层的声明，不等于运行时一定允许某次访问；把标志与实际调用异常、模块边界和编译器输出对齐，才能解释“看起来公开但调用失败”的情况。

### 6.3.4 类索引、父类索引与接口索引集合

类索引、父类索引和接口索引都指向常量池中的类符号，构成继承与接口实现关系。检查时从索引追到 UTF-8 类名，再与源码声明、类路径和实际加载来源核对；父类或接口缺失时，错误可能在加载或链接阶段才出现。

### 6.3.5 字段表集合

字段表记录字段的访问标志、名称索引、描述符索引和属性。静态字段的常量值、泛型签名或运行时可见性可能通过属性表达；因此只列出字段名不能证明布局和初始化行为，必须保存字段描述符及相关属性。

### 6.3.6 方法表集合

方法表连接方法名、参数与返回值描述符、访问标志和 Code 等属性。重载方法靠描述符区分，不能只用方法名做唯一键；二进制兼容排查要比较调用方期望的名称与描述符是否仍能在被调用方找到。

### 6.3.7 属性表集合

属性表是给 Class、字段、方法或 Code 附加信息的容器。`LineNumberTable`、`LocalVariableTable`、`Signature`、注解和模块信息可能影响调试、框架反射或工具输出；属性不一定都参与核心执行，但不能因为运行结果暂时相同就把它们删掉。

### 6.4 字节码指令简介

字节码指令围绕局部变量、操作数栈、常量池、控制流、对象和方法调用组织。阅读一段指令时先标出每条指令的栈前置和后置形状，再追踪分支汇合点；这样能把“反编译看起来合理”转成可检查的执行合同。

### 6.4.1 字节码与数据类型

指令集用不同后缀表达整数、浮点、引用和宽值的操作，具体指令名与 Java 源码类型并非一一对应。验证和执行更关心栈上的类型类别与槽位宽度；比较源码改动时，要看它是否改变了装载、转换或返回指令，而不只看源代码行数。

### 6.4.2 加载和存储指令

加载指令把局部变量或常量送入操作数栈，存储指令把栈顶值写回局部变量。`javap -c` 中的局部变量槽位受编译器分配影响，不能拿槽位编号当源码变量的稳定身份；结合 `-l` 的行号和局部变量表才能建立近似映射。

### 6.4.3 运算指令

运算指令消费栈上的操作数并压回结果，整数溢出、浮点特殊值和宽值槽位都需要按 JVMS 语义解释。若要比较优化前后 Class，先固定源码输入和编译器，再记录指令序列与结果；不要从字节码长度直接推断运行时间。

### 6.4.4 类型转换指令

类型转换指令明确地把数值或引用从一种栈类型变成另一种类型。窄化转换可能丢失精度，引用转换则可能在运行时失败；调试时要把转换指令、异常类型、输入边界和测试结果一起保存，而不是只记录转换前后的打印值。

### 6.4.5 对象创建与访问指令

对象创建、字段访问和数组访问通过常量池符号与运行时对象协作。`new`、字段读写和数组边界检查属于不同语义点；看到一条创建指令不等于构造方法已经完成，更不等于所有字段都已按业务预期初始化。

### 6.4.6 操作数栈管理指令

栈管理指令复制、交换或丢弃栈上的值，影响后续指令的输入形状。验证器依赖每个基本块入口的栈状态在分支汇合时一致；检查异常或手工生成字节码时，应把每条指令的栈变化列成表，避免凭直觉修改一个偏移。

### 6.4.7 控制转移指令

条件跳转、无条件跳转和表跳转把指令序列组织成控制流图。分支目标是字节偏移，不是源码行号；插入或删除一条指令会改变后续目标，因此字节码变换必须同步更新分支、异常表和栈映射属性。

### 6.4.8 方法调用和返回指令

调用指令依据引用的名称与类型描述符建立方法契约，返回指令则把结果或空值交回调用者。`invokevirtual`、`invokeinterface`、`invokestatic` 等指令有不同的解析与分派语义；遇到 `NoSuchMethodError` 时要先比对调用方与被调用方的描述符。

### 6.4.9 异常处理指令

异常处理依赖异常表中的起止偏移、处理器入口和捕获类型，指令本身不会像普通跳转那样把所有控制流写在一条直线上。排查异常路径时要保存 `javap -v` 的异常表、实际堆栈和输入条件，否则很容易把“没有走到 catch”误判为指令丢失。

### 6.4.10 同步指令

同步指令维护对象监视器的进入和退出边界，异常路径必须保证结构化释放。字节码中的 `monitorenter` 与 `monitorexit` 只能说明同步合同，线程调度、锁竞争和偏向策略仍属于运行时观察；需要用线程转储和 JFR 对齐真实等待。

### 6.5 公有设计，私有实现

Class 文件格式是公有合同，但编译器如何布局局部变量、HotSpot 如何解释或编译指令、工具如何打印属性，都可能随版本变化。稳定脚本应依赖 JVMS 允许的结构和语义，不应依赖某次 `javap` 的空格、编号或实现专属字段顺序。

### 6.6 Class文件结构的发展

版本演进通常通过新增属性、常量池标签或新的语言特性承载，旧工具可能无法完整展示新结构。升级 JDK 时要用目标版本重新编译和解析，比较主版本、属性集合、依赖描述符及运行结果，并明确哪些差异是向后兼容、哪些必须切换工具或运行时。

### 6.7 本章小结

Class 文件阅读的稳定方法是：先核对头部与版本，再追常量池引用，随后检查成员、属性和 Code；字节码执行要回到操作数栈、控制流、调用描述符与异常表。任何结论都要带 Class 哈希、编译命令、JDK 版本和原始工具输出；当规范、工具和实现信号不一致时，保留未知并重新重放。

## 工具入口与实验档案

下面的命令把“源码构造”和“Class 观察”分开保存。`javap` 是索引工具，完整 stdout/stderr、编译命令和哈希才是可交接的原始证据。

```bash
set -eu
run_id="class-file-$(date +%Y%m%d-%H%M%S)"
mkdir -p "class-evidence/$run_id"
java -version 2> "class-evidence/$run_id/java-version.txt"
javac -g -parameters --release 12 Sample.java
sha256sum Sample.class > "class-evidence/$run_id/class.sha256"
javap -v -c -l -s -sysinfo Sample.class \
  > "class-evidence/$run_id/javap.txt" \
  2> "class-evidence/$run_id/javap.stderr.txt"
java -cp . Sample > "class-evidence/$run_id/run.stdout.txt" \
  2> "class-evidence/$run_id/run.stderr.txt"
```

## 代码对照：用最小样例制造结构差异

这个样例同时提供字段、方法、分支、异常和同步入口，方便观察成员表、描述符、Code、异常表与同步指令。它不模拟生产性能，也不自动判断 Class 是否“更好”。

```java
public final class ClassFileProbe {
  private final int seed;

  public ClassFileProbe(int seed) {
    this.seed = seed;
  }

  public int compute(String text) {
    if (text == null) throw new IllegalArgumentException("text");
    int value = seed + text.length();
    return value > 8 ? value * 2 : value - 1;
  }

  public synchronized int guarded(int value) {
    return compute(String.valueOf(value));
  }

  public static void main(String[] args) {
    System.out.println(new ClassFileProbe(3).compute("class"));
  }
}
```

先用固定 `--release` 编译两次确认哈希稳定，再只修改一个分支常量或方法签名。比较时优先追踪结构语义：新增字段是否改变字段表，参数变化是否改变描述符，异常分支是否改变异常表；不要用 Class 文件总字节数替代逐段解释。

  保持 JDK、`--release`、源码之外的内容和调试开关不变，只增加该方法；保存两份
  `javap -v -s` 与 Class 哈希，检查方法表中的参数描述符和常量池引用，同时对比
  `LineNumberTable` 等属性。用全新目录编译并重放，避免旧 Class 混入。
</Answer>

**问题 3：栈与异常。** 手工修改一条跳转目标后，虚拟机报告验证错误。请说明如何定位，而不是只把目标偏移改回去。

<Answer>
  先保留原始 Class、修改脚本和失败
  stderr，再把基本块入口、局部变量类型、操作数栈深度、分支目标、异常表和栈映射属性列成表。用
  `javap -v -c` 和目标 JDK 的新 JVM
  重放确认首个不一致；若变换工具不能同步更新所有偏移，就回滚变换并标记生成器不支持该结构。
</Answer>

## 本章小结

- Class 文件要按头部、常量池、成员、属性和 Code 分段阅读。
- 常量池索引、局部槽位和工具排版都不是稳定 API。
- 字节码指令必须结合操作数栈、控制流、描述符和异常表解释。
- 版本兼容、工具输出和 HotSpot 实现属于不同证据层。
- 每次差异都要可重放、可回滚并留下原始哈希与未知项。

## 术语表

<Glossary>
  <GlossaryItem term="魔数">
    Class 文件开头的固定标识，用来判断输入是否像 Java 虚拟机定义的类文件。
  </GlossaryItem>
  <GlossaryItem term="主版本号">
    表示 Class 文件目标版本的字段；它是格式兼容门槛，不是完整运行兼容证明。
  </GlossaryItem>
  <GlossaryItem term="常量池">
    保存类名、方法名、字段名和类型描述等符号的共享表，其他结构通过编号引用它。
  </GlossaryItem>
  <GlossaryItem term="描述符">
    用短字符串表达字段类型、方法参数和返回值的格式，帮助调用方与被调用方对齐契约。
  </GlossaryItem>
  <GlossaryItem term="属性表">
    附着在类、字段、方法或 Code
    上的扩展信息容器，调试、注解、签名和字节码都可能放在其中。
  </GlossaryItem>
  <GlossaryItem term="操作数栈">
    字节码执行时暂存指令输入和输出的结构；验证器会检查每个分支位置的栈形状。
  </GlossaryItem>
</Glossary>
