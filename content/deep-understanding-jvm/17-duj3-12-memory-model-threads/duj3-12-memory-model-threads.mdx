# 第12章 Java内存模型与线程

并发程序里最容易被忽略的不是线程创建，而是“一个线程写入后，另一个线程凭什么能看见”。Java 内存模型把这个问题变成动作、同步关系和可观察结果之间的合同；线程实现则把合同放进调度、状态和载体的运行时现场。

本章解决的问题是：普通字段、volatile、锁、线程启动与 join 分别建立什么关系？为什么一次没有复现错误的运行不能证明没有数据竞争？当平台线程换成虚拟线程时，哪些结论仍属于语言规则，哪些只是 JDK 与操作系统的实现观察？

先固定 JDK、供应商、VM 参数、源码和 Class 哈希、输入序列、线程载体与采集窗口，再只改变一个发布或保护条件。证据图会把动作、缓存、同步边、观察、线程状态和重放接成一条可播放路径；它展示如何诊断，不制造线程安全分数。

<Objectives>

- 能区分 Java 内存模型中的可见性、有序性与原子性，并为共享读写写出可核对的不变量。
- 能只改变一个同步或线程载体条件，采集同步边、线程状态、锁关系、原始日志和退出码。
- 能用全新进程与同输入重放解释一次并发反例，并标明结论属于语言规范、JVMS、HotSpot 还是目标 JDK 的边界。

</Objectives>

## 为什么从“动作—同步边—观察”开始

把共享变量想成一块公告板：一个线程写字不代表另一个线程已经读到最新内容；真正重要的是公告板旁边有没有一条可核对的交接规则。锁释放与获取、线程启动、线程结束后的 join，以及特定变量访问规则，都可能成为关系链的一部分，但它们的作用不能靠墙上时间猜测。

正确性和性能也要分开。先证明“不变量不会被破坏、读写具备所需可见性”；再测量锁竞争、调度、吞吐和尾延迟。平均值高不能抵消错误结果，线程转储也不能替代内存模型证明。

通过不变量是“每个共享读写都能回到明确同步边或安全发布；只改变一个条件时，第一处变化可定位；正确性与性能分别验收”。实验档案至少保存 JDK 与供应商、OS 或容器限制、VM 参数、源码与 Class 哈希、线程载体、工作量、采集窗口、线程转储、锁事件、退出码和清理记录。

## 三个必须主动触发的误区

<Callout type="trap" title="把 volatile 当成复合操作的原子性保证">
  **现象 →** 计数器加上 volatile 后仍然少于预期。 **原因 →**
  读、改、写是多个动作，可见性不等于复合操作不可分割。 **修法 →**
  写出不变量，改用锁或原子工具，并保存反例次数、输入规模和线程档案。
</Callout>

<Callout type="trap" title="把墙上时间当成同步边">
  **现象 →** 一个线程先调用 start，就断言另一个线程必然按预期看到全部状态。
  **原因 →** 需要分析具体动作与同步关系，普通字段写入不能靠直觉补全合同。 **修法
  →** 标出发布动作、读取动作和关系链，再用重复运行验证。
</Callout>

<Callout type="trap" title="把一次成功运行当成没有数据竞争">
  **现象 →** 运行一百次没有错误，就宣布程序线程安全。 **原因 →**
  调度窗口可能没有命中，错误结果也可能被断言或日志遗漏。 **修法 →**
  提高重复次数，保存第一次反例、线程转储、退出码，并在全新进程中重放。
</Callout>

## 官方目录逐项深读

下面 19 个小节严格对应 manifest 的正式节点。每节只回答一个问题：它在合同中的位置是什么、为什么需要它、怎样留下可重放证据。

### 12.1 概述

先把“内存模型合同”和“线程实现现场”分开：前者规定哪些关系能支撑可见性与顺序，后者记录当前 JDK 如何调度、阻塞和唤醒。实验先写问题和不变量，再选择能观察到第一处变化的工具。

### 12.2 硬件的效率与一致性

缓存、写缓冲和多核一致性解释了为什么本地观察不能直接等同于全局观察，但它们不能替代 Java 规范的同步规则。报告硬件或 VM 观察时，必须同时给出 JDK、CPU、参数与输入边界。

### 12.3 Java内存模型

Java 内存模型关心线程动作之间的可见性、顺序和同步关系，而不是提供一个可以直接窥视的硬件缓存图。把每次读写写成动作，再用关系链说明哪些结果允许、哪些结果被排除。

### 12.3.1 主内存与工作内存

主内存与工作内存是帮助理解共享与本地观察的模型语言，不应被当成某个 HotSpot 数据结构的逐字地图。实验记录共享变量、线程、写入动作和读取动作，避免把模型名直接当成测量结果。

### 12.3.2 内存间交互操作

读、写、锁定、解锁、启动和结束等动作组成了可分析的交互序列。将动作按线程编号和时间窗记录，再标出同步关系；只保存最终值会丢失决定可见性的关键过程。

### 12.3.3 对于volatile型变量的特殊规则

volatile 适合表达某些发布标志和可见状态，但它不能保护“读取旧值、计算新值、写回”这样的复合动作。用一个可重复的标志实验分别记录写入、读取、循环次数和退出码，再说明结论只覆盖已测量条件。

### 12.3.4 针对long和double型变量的特殊规则

long 与 double 的访问规则必须按目标 Java 版本和具体变量声明分析，不能把旧语境的实现观察扩展为所有平台保证。实验应记录是否使用 volatile 或锁、编译器版本和读写结果，保留异常或不一致的原始输出。

### 12.3.5 原子性、可见性与有序性

三者是不同问题：原子性关注动作是否可拆分，可见性关注写入能否被观察，有序性关注动作排列能否满足合同。一个 volatile 字段可能帮助后两者，却不能让多步库存扣减自动变成原子操作。

### 12.3.6 先行发生原则

先行发生关系是把“应当可见”变成可推理链条的核心。不要只说“线程 A 先跑”；要逐边写出锁、volatile、start、join 或其他规则如何连接写入与读取，并保留无法连接的路径作为风险。

### 12.4 Java与线程

Java 线程同时具有语言层动作和运行时状态。一个线程安全结论要先在共享状态合同中成立，再用线程现场解释等待、阻塞或调度成本；两类证据不能互相冒充。

### 12.4.1 线程的实现

平台线程、虚拟线程和底层 OS 载体的对应关系取决于 JDK 与实现。报告线程实现时固定版本和启动参数，保存线程名、载体、栈、状态与退出记录，不把一种实现的映射写成 Java 语言规则。

### 12.4.2 Java线程调度

调度决定何时运行、让出或等待，但通常不提供“谁先完成”的业务合同。改变调度相关条件时，保持输入和同步边不变，同时采集等待时间、状态转移和尾延迟，避免用平均吞吐掩盖少数长等待。

### 12.4.3 状态转换

NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING 和 TERMINATED 是可观测状态标签。它们描述快照，不保证下一刻仍然相同；用带时间戳的多份转储关联锁拥有者与等待者，才能解释状态变化。

### 12.5 Java与协程

协程或轻量任务把“任务”与“承载它的线程”分开，降低阻塞成本的可能性，却不会自动改变共享状态的同步合同。比较载体时保持动作序列、锁边界和输入不变，先验收正确性，再验收资源与尾延迟。

### 12.5.1 内核线程的局限

内核线程数量、栈空间、上下文切换和阻塞方式会限制并发规模，但具体阈值属于环境事实。实验必须记录 OS、容器配额、线程数、栈参数、失败退出码和采集成本，不能只引用一次机器的上限。

### 12.5.2 协程的复苏

协程复兴体现了任务调度与 OS 线程解绑的工程方向，而不是对 Java 内存模型的替换。观察轻量载体时，仍须按共享读写、同步边和安全发布分析；只改变载体才可以把资源差异归因给载体。

### 12.5.3 Java的解决方案

Java 的线程与协程方案在不同 JDK 版本有不同入口、状态和限制。使用目标 JDK 的文档与工具确认可用性，保存启动参数、线程转储、输入哈希和退出码；“能启动”不等于“所有阻塞和共享访问都安全”。

### 12.6 本章小结

读懂内存模型的稳定方法是先列动作和不变量，再标出同步边，最后用线程状态和全新进程重放解释实现现场。可见性、有序性、原子性、调度和载体各有边界；未经测量的默认值、时序与跨版本差异必须保留为 unknowns。

## 最小可见性探针：先保存动作再看结果

下面的程序用一个发布标志交接初始化结果。它不声称能证明所有硬件或 JDK 行为，只制造可复核的动作、重复次数和退出码；实验时可以复制一份去掉 volatile 的变体，比较反例与线程转储。

```java
public final class JmmProbe {
  static int payload;
  static volatile boolean published;

  public static void main(String[] args) throws Exception {
    int rounds = Integer.parseInt(args[0]);
    for (int i = 0; i < rounds; i++) {
      payload = i;
      published = true;
      Thread reader = new Thread(() -> {
        if (published && payload != i) {
          throw new AssertionError("visibility mismatch");
        }
      }, "reader-" + i);
      reader.start();
      reader.join();
      published = false;
    }
    System.out.println("rounds=" + rounds);
  }
}
```

先生成固定 Class，再分别运行带发布关系和故意移除关系的变体。`jcmd` 输出是实现现场，必须和 JDK 版本、PID、采集时间以及原始 stderr 一起归档。

```bash
set -eu
run_id="duj3-ch12-$(date +%Y%m%d-%H%M%S)"
mkdir -p "evidence/$run_id"
java -version 2> "evidence/$run_id/java-version.txt"

printf 'exit_code=%s\n' "$?" > "evidence/$run_id/exit-code.txt"
```
