## 为什么从“字节码速查与栈效应台”开始

附录C 虚拟机字节码指令表不能把语言、JVMS、HotSpot和某个JDK发行版混成一层。字节码速查与栈效应台沿“opcode bytes → operands → stack before/after → exception”保存输入和原始输出，让每个结论都能回到规范条款、实现状态和目标版本。

附录C 虚拟机字节码指令表固定JDK镜像、VM参数、工作量、采集窗口和资源限制，只改变指令族或验证条件；图中只呈现本章真实运行时对象、状态边与证据出口；高亮表示当前分析路径，不冒充真实吞吐、停顿、对象大小或线程安全证明。

## 三个必须主动触发的误区

<Callout type="trap" title="实现图不等于规范">附录C 虚拟机字节码指令表中的对象头、收集器默认值、JIT阈值、加载器结构和工具能力都可能随实现或版本变化；只有JVMS/JLS合同可以在对应Java SE版本内作为规范主张。</Callout>

<Callout type="trap" title="章专属失败样本">附录C 虚拟机字节码指令表主动触发“孤立背操作码、不验证栈高度和类型，或忽略指令版本与保留操作码”，并进一步注入“只背助记符，不计算操作数栈和异常边”；若opcode偏移、栈高与验证错误未出现，先验证采集链路和阳性对照，不得挑选一条符合预期的运行。</Callout>

<Callout type="trap" title="参数不能先于问题">附录C 虚拟机字节码指令表只有在SLO、基线、假设、单变量、资源代价和回滚阈值齐全时才允许改变VM参数；编译通过、进程存活或平均值改善都不能替代正确性和尾部证据。</Callout>
