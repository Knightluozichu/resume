# 附录D 对象查询语言（OQL）简介

内存问题通常不会把答案直接写在屏幕上：你先得到一份冻结的现场，再问一个问题，最后沿着对象之间的连接回到仍然存活的根。每一步都应留下输入和边界，不能只保留一张漂亮的结果截图。

如果没有分层记录，查询结果会把“现场里存在过”误写成“现在仍被保留”，也会把工具的默认过滤误写成 JVM 的普遍规律。本附录把一次查询拆成快照、条件、对象图和保留路径，并在复核台里注入过期快照故障。

<Objectives>

- 能把一次 OQL 复核拆成快照版本、查询条件、对象图和 GC Root 保留路径四类证据。
- 能区分“查询返回了对象”与“对象被某条根路径保留”，并记录工具、过滤条件和资源边界。
- 能修改复核台的查询目标并回答：快照版本不一致时，哪一层必须先停止下结论？

</Objectives>

## 先把“内存异常”变成一张可追溯地图

想象一座仓库：快照是某一时刻的盘点单，查询是筛选标签，对象图是货架之间的连接，根路径是说明“为什么这件货还不能搬走”的路线。只有四张单据能互相对上，盘点才值得复核。

这张地图解决两个问题：一个对象为什么出现在结果里，以及它为什么仍然占着空间。没有它，读者会把对象数量、对象大小和保留责任混在一起，最后只能凭经验猜测泄漏原因。

## 三个容易把 OQL 结果读错的坑

<Callout type="trap" title="把查询命中当成 GC Root 保留">
  **现象 →** 查询返回了一个对象，就宣布它一定阻止了回收。 **原因 →**
  命中只说明它满足筛选条件，不说明从根到它的路径仍然存在。 **修法 →**
  另存对象图和 GC Root 路径；找不到路径时把结论写成“命中但保留原因未知”。
</Callout>

<Callout type="trap" title="用不同时间的快照拼一条路径">
  **现象 →** 从上午快照拿对象数量，从下午快照拿字段值，再画成一条增长曲线。
  **原因 →** 对象身份、类加载器和现场状态可能已经变化。 **修法 →**
  每条结果绑定快照哈希、采集时间和工具版本；跨快照比较时显式标注它是近似对照。
</Callout>

<Callout type="trap" title="查询完成后立刻删除唯一证据">
  **现象 →** 为节省磁盘只保留查询导出，不保留原始堆文件。 **原因 →**
  导出结果无法重放过滤条件、工具默认值和保留路径。 **修法 →**
  先校验并归档原始快照、脚本和日志，再按保留策略销毁副本，销毁记录也要进入档案。
</Callout>

## 六个核心概念

### 堆快照：先冻结“看见了什么”

<Term def="某个时间点把 Java 堆中的对象、类型和引用关系保存下来的文件或数据集。">
  堆快照
</Term>
是查询的输入，不是实时堆本身。它必须带采集时间、进程标识、类文件版本、工具版本和校验和；缺少这些信息，两个同名快照就无法区分。

### OQL 查询：再说明“筛选什么”

<Term def="在堆分析工具中按类型、字段或关系筛选对象的查询表达；语法和可用函数由具体工具决定。">
  OQL 查询
</Term>
描述筛选条件和投影字段。查询结果只能回答“这份快照里哪些对象满足条件”，不能自动回答对象为何长期存活。

### 对象图：把“对象之间的连接”摊开

<Term def="以对象为节点、以字段或数组元素为边的引用关系图，用来说明查询结果如何连接到其他对象。">
  对象图
</Term>
把一行结果展开成可追踪的关系。它让读者区分共享引用、集合成员和偶然的局部变量，避免看到一个字段名就直接归责。

### GC Root：寻找“为什么还活着”

<Term def="垃圾收集器认可的存活起点，例如活动线程、静态字段或 JNI 引用；具体类别由运行时和工具报告决定。">
  GC Root
</Term>
是保留路径的起点。它不等于业务责任人；找到根只说明对象仍可达，还要结合字段和生命周期判断谁应该释放引用。

### 保留路径：记录“哪条连接阻止回收”

<Term def="从一个或多个 GC Root 沿引用边走到目标对象的路径，用来解释对象为什么仍然可达。">
  保留路径
</Term>
是对象图中的一条可解释路线。路径变化时，要记录快照版本和节点数量，不能把两次查询的路线拼成一条。

### 快照生命周期：管理“证据何时能被销毁”

<Term def="从采集、校验、分析、导出到按策略销毁堆快照的完整过程，包含权限、磁盘和敏感数据边界。">
  快照生命周期
</Term>
决定复核是否可重放。先保留原始文件和日志，再删除副本；如果堆里含有敏感数据，还要记录访问和销毁责任。

## 四层诊断合同

每次复核都写下面四层，避免查询结果越权：

| 层       | 必须记录                           | 能支持的结论         | 不能直接支持             |
| -------- | ---------------------------------- | -------------------- | ------------------------ |
| 快照     | 时间、进程、工具、哈希、类文件版本 | 这份现场里看到了什么 | 当前实时堆一定相同       |
| 查询     | 文本、参数、过滤、导出格式         | 哪些对象命中条件     | 对象一定被长期保留       |
| 对象图   | 节点、字段边、类加载器             | 对象怎样连接         | 业务代码一定有 bug       |
| 保留路径 | GC Root、路径长度、快照哈希        | 为什么对象仍可达     | 下一次快照仍会有同一路径 |

一个结果要同时保留四层证据。若只有查询导出，没有原始快照，就不能重放；若只有 GC Root，没有查询条件，就不能知道筛选范围；若快照时间不同，就把它们标成对照，不要伪装成同一现场。

## 快照与查询证据命令

下面的命令只负责生成可归档的现场和版本记录，不会自动证明泄漏原因。生产环境执行前要确认权限、磁盘空间、暂停时间和敏感数据处理策略；`jcmd` 或 OQL 客户端不可用时，保存完整错误原文。

```bash
set -o pipefail
PID="${PID:?set PID to the target Java process}"
OUT="evidence/oql/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$OUT"
java -version 2>&1 | tee "$OUT/java-version.txt"
jcmd "$PID" VM.command_line 2>&1 | tee "$OUT/command-line.txt"
jcmd "$PID" GC.heap_dump "$OUT/heap.hprof" 2>&1 | tee "$OUT/heap-dump.log"
sha256sum "$OUT/heap.hprof" | tee "$OUT/heap-sha256.txt"
```

查询卡片至少包含：快照哈希、查询原文、工具版本、过滤条件、返回数量、导出文件哈希、对象图范围、保留路径和销毁记录。堆快照可能包含口令、令牌或个人数据，分享前要按组织规则脱敏，不能把原始文件上传到公共位置。

## 练习、答案与单节点验收

<Exercises>

**问题 1：改 Demo 代码。** 在复核台增加一个“查询结果已导出但原始快照缺失”的故障。界面应该禁止哪种结论？重置后应恢复哪些证据层？

<Answer>
  界面应禁止“可重放”或“已确认保留路径”的结论，因为没有原始快照就无法核对对象图、过滤条件和工具默认值。重置后恢复完整的快照、查询、对象图、保留路径和生命周期层，并恢复默认快照哈希与时间。
</Answer>

**问题 2：区分命中与保留。** 查询返回一个 `Map` 实例，但没有找到从 GC Root 到它的完整路径。你会如何写当前结论？

<Answer>
  只能写“该实例在指定快照中命中查询条件，保留原因未知”。需要补采同一快照的对象图和
  GC Root
  路径，记录工具版本、类加载器、路径长度和失败输出；不能把命中数量直接写成泄漏数量。
</Answer>

**问题 3：设计跨快照对照。** 两份快照分别来自上午和下午，下午的某类实例数量更多。请列出比较前必须固定或标注的三类条件。

<Answer>
  至少标注采集时间与业务负载、进程和类文件版本、JDK
  与分析工具版本、快照哈希、查询文本和过滤条件；还要说明采集是否造成暂停以及对象图是否可比。结果只能说明这两份现场的差异，不能单独证明增长来自泄漏。
</Answer>

</Exercises>

## 本章小结与发布前回顾

- 快照冻结现场，查询定义筛选范围。
- 对象图解释引用关系，GC Root 解释可达起点。
- 保留路径支持“为什么仍然存活”的范围化结论。
- 跨快照比较必须记录时间、版本、哈希和负载。
- 原始快照、查询、日志和销毁记录共同构成可重放档案。

<Glossary>
  <GlossaryItem term="堆快照">
    某个时间点保存下来的 Java 堆对象和引用关系，像一张带时间戳的冻结盘点单。
  </GlossaryItem>
  <GlossaryItem term="OQL 查询">
    在堆分析工具中按类型、字段或关系筛选对象的查询文字，具体能力取决于工具。
  </GlossaryItem>
  <GlossaryItem term="对象图">
    用节点表示对象、用边表示字段或数组引用的关系图，帮助追踪对象如何连接。
  </GlossaryItem>
  <GlossaryItem term="GC Root">
    垃圾收集器认可的存活起点，例如活动线程、静态字段或 JNI 引用。
  </GlossaryItem>
  <GlossaryItem term="保留路径">
    从 GC Root 沿引用边走到目标对象的路线，用来解释对象为什么仍然可达。
  </GlossaryItem>
  <GlossaryItem term="快照生命周期">
    从采集、校验、分析、导出到按策略销毁快照的全过程，也包含权限和敏感数据边界。
  </GlossaryItem>
