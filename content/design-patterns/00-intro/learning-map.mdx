# 全书学习地图

设计模式全书不是一张把 23 个模式名称排成直线的海报。它更像一条可回放的路线：先描述问题，再按创建型、结构型和行为型定位入口，随后运行一个最小实验，最后留下接受或拒绝的证据。

这张地图解决的是“下一步学什么、为什么现在学它、学完留下什么”的导航问题。它不替读者完成模式章节，也不把目录标题计作理解证明；真正的完成信号必须来自正文解释、代码实验和复盘记录。

<Objectives>

- 能根据变化压力选择先修、创建型、结构型、行为型或综合复盘路径，并说明为什么不直接跳到模式名称。
- 能为每个学习节点留下一个可运行产物、一条边界样例和一条拒绝条件，而不是只收藏章节链接。
- 能操作路线图的故障开关和重置按钮，判断跳过先修会破坏什么，并把路线选择写成可复查的学习决定。

</Objectives>

## 直觉：路线是证据链，不是目录截图

假设你看到“新增导出格式”这个需求。直接打开某个模式章节当然很快，但你还不知道问题属于创建、结构还是行为，也不知道直接实现是否已经足够。更稳的顺序是先写变化压力，再选择模式家族，接着运行最小样例，最后记录成本和替代方案。

学习地图把这条顺序固定为：**问题合同 → 模式家族 → 章节实验 → 复盘证据**。每次只改变一个压力，并保存正常样例、边界样例和故障样例，学习者才能区分“我浏览过页面”和“我能解释一个设计决定”。

## 三个必须主动触发的路线误区

<Callout type="trap" title="把目录标题当成学习完成">
  **现象 →** 路线图列出 23 个模式名称，学习者就把每一项标成已掌握。 **原因 →**
  标题只有定位作用，没有提供参与者、协作时序和后果证据。 **修法 →**
  每进入一个节点，至少留下一个运行结果、一个反例和一句自己的选择理由。
</Callout>

<Callout type="trap" title="跳过先修直接挑模式">
  **现象 →** 还没有写清变化轴，就从“工厂”或“观察者”开始画类图。 **原因 →**
  模式名称先占据注意力，真正的问题边界反而消失。 **修法 →**
  先回到上下文和替代方案；如果直接实现更小，就把拒绝模式写进复盘。
</Callout>

<Callout type="trap" title="把路线顺序误写成原书原文">
  **现象 →** 把本站按练习安排的路线说成原书唯一的阅读顺序。 **原因 →**
  导航编排和出版目录是两个不同层次的证据。 **修法 →**
  目录事实链接回官方书目，学习顺序明确标为本站独立重写，并公开调整理由。
</Callout>

## 路线合同：六个词先于一个链接

一条学习路线先要固定<Term def="进入某个章节前已经具备的概念、代码能力和问题描述能力">先修</Term>，否则“跳读”无法解释遗漏了什么。接着识别<Term def="推动结构变化的具体需求，例如创建规则改变、接口组合改变或协作算法改变">变化压力</Term>，再选择最贴近问题的<Term def="按主要变化来源组织模式的入口，常用三类是创建型、结构型和行为型">模式家族</Term>。

每个节点都必须留下<Term def="学习者可以运行、检查或提交的具体结果，例如代码片段、调用轨迹或边界测试">学习产物</Term>和<Term def="能够支持继续学习、拒绝某个选择或回到基线的可观察结果">验收证据</Term>。最后做<Term def="把选择、代价、反例和下一次复查条件写回路线的过程">复盘</Term>，确认路线帮助你理解问题，而不是只增加收藏夹里的页面数。

| 路线字段 | 要回答的问题                 | 最小产物                 |
| -------- | ---------------------------- | ------------------------ |
| 先修     | 进入前我已经能解释什么       | 一句边界和一段最小代码   |
| 变化压力 | 哪个需求会迫使结构一起变化   | 一个可复现的变更输入     |
| 模式家族 | 创建、结构还是行为更贴近问题 | 选择理由和一个替代方案   |
| 学习产物 | 学完后我能运行或检查什么     | 代码、图或调用轨迹       |
| 验收证据 | 怎样证明我没有只背标题       | 正常、边界和故障三种结果 |
| 复盘     | 下次遇到相似问题先查什么     | 接受、拒绝和复查触发条件 |

## 官方范围与本站路线的关系

### 官方书籍结构

官方书目提供事实范围和模式目录的阅读坐标。本站把“导论”放在路线入口，是为了先建立问题合同；它不把入口页宣称成原书额外章节，也不把本站的练习顺序伪装成出版目录。

### 创建型路径

创建型路径处理“对象如何被创建”这一类变化。学习者先比较直接构造、工厂方法、抽象工厂、建造者、原型和单例等入口的适用压力，再进入相应章节；模式名称只是检索点，创建者、产品和客户端之间的责任才是验收对象。

### 结构型路径

结构型路径处理“已有对象或类如何组合”。适配器、桥接、组合、装饰器、外观、享元和代理都需要回到接口、所有权、身份与转换成本；如果一个包装层只增加了转发，却没有隔离真实变化，路线应允许你回到直接实现。

### 行为型路径

行为型路径处理算法、状态与消息如何协作。策略、观察者、命令、状态以及其他行为型章节都应先画出触发者、协作者和失败传播，再决定是否值得拆分职责；同一个类图形状不能替代协作证据。

### 综合复盘

综合复盘把多个变化轴放在同一张评审卡上。它要求你比较收益、额外对象、间接调用、调试路径和替代方案，并允许最终结论是“当前不采用模式”；拒绝并不是没有学会，而是学会了边界。

## 章专属实验：沿路线留下证据

先预测：如果你从“变化压力”切到“接口需要组合”，路线焦点会进入哪个模式家族？如果打开“跳过先修的故障”，页面应该如何提醒你不能把浏览记录当作完成证明？操作下面四步，每一步都观察路线图、故障状态和重置后的基线。

  <Step title="1. 固定变化压力">

  </Step>

    依次点击创建型、结构型和行为型路径，比较每个节点的先修和检查线。若三类都不贴合当前问题，保留直接实现作为路线结果，而不是为了完成导航强行选一个模式。

## 把路线验收写进 TypeScript

下面的类型把“看过章节”和“完成学习证据”分开。它不替你判断模式是否正确，只检查路线是否留下了可以复查的字段。

```ts
type RouteEvidence = {
  prerequisite: string;
  pressure: string;
  family: "creation" | "structure" | "behavior";
  artifact: string;
  boundaryCase: string;
  rejectionReason: string;
  reviewTrigger: string;
};

function isLearnable(evidence: RouteEvidence) {
  return Object.values(evidence).every((value) => value.trim().length > 0);
}
```

`isLearnable` 只检查记录完整，不替代代码运行和边界测试。一个真正可复查的路线记录还应该链接到章节实验、正常结果和故障结果。

## 练习、答案与路线验收

<Exercises>

本组练习围绕同一条路线闭环：先修、变化压力、模式家族、学习产物、验收证据和复盘。

**问题 1：改 Demo 代码。** 在路线图中增加一个“直接实现”节点。它应该放在哪个位置？点击它时，仍然需要记录哪些证据？

<Answer>
  可以把它放在模式家族之前或作为每个家族的对照分支，但不能跳过先修和变化压力。至少保留直接实现的代码、正常和边界结果、预计变化范围，以及为什么暂时不采用模式的拒绝条件。
</Answer>

**问题 2：场景选型。** 一个系统只有一个稳定的构造分支，却预期未来会增加产品族。你会直接进入抽象工厂章节吗？请写出进入前需要补齐的最小证据。

<Answer>
  不会只凭“未来可能扩展”进入。先记录产品族变化的具体来源、客户端不应知道的边界、直接构造的修改范围，以及增加创建入口的代价；若这些证据尚不存在，先完成导论中的问题合同和小实验。
</Answer>

**问题 3：做一次拒绝决定。** 学习者已经看完结构型和行为型章节，但没有运行任何示例。怎样判断“已看完”还没有达到“可复查”？

<Answer>
  检查路线记录是否有一个可运行产物、一个边界样例、一个故障结果和一次重置后的基线。如果只有章节标题、笔记和模式名称，就仍然缺少验收证据；应回到最贴近当前变化压力的章节补实验。
</Answer>

</Exercises>

## 本章小结与发布前回顾

- 学习地图是证据链，不是 23 个模式名称的线性清单。
- 先写问题合同，再按变化压力进入创建、结构或行为路径。
- 每个节点都要留下产物、边界样例、故障结果和复盘条件。
- 跳过先修可以作为故障实验，但不能作为完成证明。
- 路线顺序是本站独立教学编排，官方目录只承担范围与事实核对。

## 名词解释

<Glossary>
  <GlossaryItem term="先修">
    进入一个学习节点前已经具备的知识和代码能力，就像做实验前要先会读仪表。
  </GlossaryItem>
  <GlossaryItem term="变化压力">
    会迫使当前结构修改的具体需求，例如创建规则、接口组合或协作算法改变。
  </GlossaryItem>
  <GlossaryItem term="模式家族">
    按主要变化来源划分的入口类别，帮助你先定位问题，再查具体模式。
  </GlossaryItem>
  <GlossaryItem term="学习产物">
    学习后可以运行、检查或提交的东西，例如代码片段、调用轨迹或边界测试。
  </GlossaryItem>
  <GlossaryItem term="验收证据">
    能证明路线没有停留在标题浏览的结果，通常包括正常、边界和故障三种状态。
  </GlossaryItem>
  <GlossaryItem term="复盘">
    把这次选择的代价、反例和下一次复查条件写回记录的过程。
  </GlossaryItem>
</Glossary>
