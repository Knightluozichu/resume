## 痛点场景：跨平台 UI

你的应用要支持 Windows 和 Mac 两种风格，每种风格都有 Button 和 Checkbox。

不用模式：

```typescript
function createUI(platform: string, component: string) {
  if (platform === "win") {
    if (component === "button") return new WinButton();
    if (component === "checkbox") return new WinCheckbox();
  } else if (platform === "mac") {
    if (component === "button") return new MacButton();
    if (component === "checkbox") return new MacCheckbox();
  }
  // 加一个 Linux 平台？改这里
  // 加一个 RadioButton？也改这里
}
```

两层 if-else 嵌套，**创建逻辑和平台耦合**。

## 解决方案：工厂族

```typescript
// 产品接口
interface Button { render(): void }
interface Checkbox { render(): void }

// Windows 产品族
class WinButton implements Button { render() { /* Windows 风格 */ } }
class WinCheckbox implements Checkbox { render() { /* Windows 风格 */ } }

// Mac 产品族
class MacButton implements Button { render() { /* Mac 风格 */ } }
class MacCheckbox implements Checkbox { render() { /* Mac 风格 */ } }

// 抽象工厂
interface UIFactory {
  createButton(): Button;
  createCheckbox(): Checkbox;
}

// 具体工厂
class WinFactory implements UIFactory {
  createButton() { return new WinButton() }
  createCheckbox() { return new WinCheckbox() }
}
class MacFactory implements UIFactory {
  createButton() { return new MacButton() }
  createCheckbox() { return new MacCheckbox() }
}
```

使用：

```typescript
const factory: UIFactory = isMac ? new MacFactory() : new WinFactory();
const button = factory.createButton();
const checkbox = factory.createCheckbox();
// button 和 checkbox 保证风格一致
```

## 抽象工厂 vs 工厂方法

| 维度 | 工厂方法 | 抽象工厂 |
|------|----------|----------|
| 创建对象 | 单个产品 | 产品族（多个相关产品） |
| 扩展方式 | 加新工厂子类 | 加新工厂实现 |
| 加新产品类型 | 加新工厂子类即可 | **要改接口和所有工厂**（困难） |
| 加新平台/风格 | 不适用 | 加新工厂实现即可 |

<Callout type="warning">
抽象工厂的「开闭」是不对称的：**加新平台容易**（加新工厂），**加新产品类型困难**（改接口 = 改所有工厂）。这是抽象工厂的核心权衡。
</Callout>

## 常见误区

### 误区 1：产品类型多就用抽象工厂

抽象工厂适合产品类型**少且稳定**的场景（如 UI 组件：Button、Checkbox、TextField）。如果产品类型经常增加，抽象工厂的维护成本很高。

### 误区 2：混用抽象工厂和工厂方法

如果你只需要创建一种产品，用工厂方法。如果需要创建**一组相关产品**且保证它们风格一致，才用抽象工厂。

### 误区 3：工厂不保证产品族一致性

抽象工厂的核心价值是**保证产品族一致性**——WinFactory 不会返回 WinButton + MacCheckbox。如果你发现工厂方法可以返回任意组合，说明设计有问题。

## 小结

- 抽象工厂 = 创建产品族的工厂接口 + 多个具体工厂
- 核心价值：保证产品族一致性（Win 全 Win，Mac 全 Mac）
- 加新平台容易，加新产品类型困难——这是设计权衡
- 适合：跨平台 UI、数据库方言、主题系统

<Glossary>

<GlossaryItem term="抽象工厂模式">

提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们具体的类。

</GlossaryItem>

<GlossaryItem term="产品族">

一组相关联的产品，它们属于同一「家族」或「主题」。抽象工厂的核心职责是保证产品族的一致性。

</GlossaryItem>

<GlossaryItem term="开闭不对称性">

抽象工厂对「新增工厂（新平台）」开放扩展，但对「新增产品类型」需要修改接口——这是其固有的设计权衡。

</GlossaryItem>
