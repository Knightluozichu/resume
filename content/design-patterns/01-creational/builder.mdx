## 痛点场景：SQL 查询构建器

要构建一个 SQL 查询，有 SELECT、FROM、WHERE、ORDER BY、LIMIT 等多个可选部分。

构造函数方案：

```typescript
class Query {
  constructor(
    select: string[],
    from: string,
    where?: string,
    orderBy?: string,
    limit?: number,
    groupBy?: string,
    having?: string,
    // 参数越来越多...
  ) {}
}
new Query(["*"], "users", undefined, undefined, 10);
// undefined 太多，可读性差
```

## 解决方案：分步构建

```typescript
// 产品
class SQLQuery {
  select: string[] = [];
  from = "";
  where?: string;
  orderBy?: string;
  limit?: number;
}

// 建造者
class QueryBuilder {
  private query = new SQLQuery();

  select(...cols: string[]) { this.query.select = cols; return this }
  from(table: string) { this.query.from = table; return this }
  where(cond: string) { this.query.where = cond; return this }
  orderBy(col: string) { this.query.orderBy = col; return this }
  limit(n: number) { this.query.limit = n; return this }

  build(): SQLQuery { return this.query }
}
```

使用：

```typescript
const query = new QueryBuilder()
  .select("name", "age")
  .from("users")
  .where("age > 18")
  .orderBy("name")
  .limit(10)
  .build();
```

## 建造者 vs 工厂

| 维度 | 工厂模式 | 建造者模式 |
|------|----------|-----------|
| 创建方式 | 一步创建 | 分步创建 |
| 产品复杂度 | 简单对象 | 复杂对象（多参数） |
| 返回时机 | 立即返回 | 最后 build() 时返回 |
| 典型场景 | 根据类型创建 | 配置大量可选参数 |

<Callout type="tip">
工厂模式像「点套餐」——一步到位。建造者模式像「自定义披萨」——一步步选配料，最后烤好给你。
</Callout>

## Director 角色

经典建造者模式有 Director，它封装「标准构建流程」：

```typescript
class Director {
  constructor(private builder: QueryBuilder) {}

  // 预设：查所有成年用户
  buildAdultUsersQuery() {
    return this.builder
      .select("*")
      .from("users")
      .where("age >= 18")
      .orderBy("id")
      .build();
  }
}
```

Director 不是必须的。如果构建流程简单或每次都不同，客户端直接调用 Builder 方法即可。

## 常见误区

### 误区 1：简单对象用建造者

如果对象只有 2-3 个参数，用构造函数或工厂就够了。建造者适合参数多（≥5）、大多可选、需要分步配置的场景。

### 误区 2：Builder 不可复用

`build()` 后 Builder 内部状态已固定。如果要构建多个对象，要么每次 `new Builder()`，要么在 `build()` 中重置状态。

### 误区 3：忘了 return this

链式调用的关键：每个方法都 `return this`。漏掉一个，链就断了。TypeScript 可以用 `this` 返回类型保证安全。

## 小结

- 建造者 = 分步构建 + 最后组装，适合参数多且大多可选的复杂对象
- 核心价值：避免构造函数参数爆炸，提升可读性
- 链式调用（Fluent Builder）是最常见的实现形式
- Director 封装标准流程，可选不必须

<Glossary>

<GlossaryItem term="建造者模式">

将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。

</GlossaryItem>

<GlossaryItem term="Fluent Builder">

通过方法返回 `this` 实现链式调用的建造者风格。每个配置方法返回 Builder 自身，支持 `builder.a().b().c().build()` 写法。

</GlossaryItem>

<GlossaryItem term="Director">

封装标准构建流程的角色。它持有一个 Builder 引用，按固定顺序调用 Builder 方法构建产品。可选角色。

</GlossaryItem>
