## 痛点场景：怪物生成

游戏中要生成大量怪物。每只怪物有复杂的状态（血量、装备、AI 参数、技能列表）。用 `new` 创建要从头初始化所有字段，性能差且代码冗长。

```typescript
class Monster {
  constructor(
    hp: number, maxHp: number,
    equipment: Equipment[],
    skills: Skill[],
    aiParams: AIConfig,
    // ...几十个字段
  ) {}
}

// 每次都要传几十个参数
const goblin1 = new Monster(100, 100, [...], [...], {...});
const goblin2 = new Monster(100, 100, [...], [...], {...});
```

## 解决方案：克隆已有对象

```typescript
interface Prototype {
  clone(): Prototype;
}

class Monster implements Prototype {
  hp: number;
  maxHp: number;
  equipment: Equipment[];
  skills: Skill[];
  aiParams: AIConfig;

  clone(): Monster {
    // 深拷贝
    const copy = Object.create(this);
    copy.hp = this.hp;
    copy.maxHp = this.maxHp;
    copy.equipment = this.equipment.map(e => e.clone());
    copy.skills = this.skills.map(s => ({ ...s }));
    copy.aiParams = { ...this.aiParams };
    return copy;
  }
}

// 创建原型
const goblinPrototype = new Monster(100, 100, [sword], [slash], aggressiveAI);

// 快速克隆
const goblin1 = goblinPrototype.clone();
const goblin2 = goblinPrototype.clone();
goblin2.hp = 80; // 修改副本不影响原型
```

## 深拷贝 vs 浅拷贝

| 维度 | 浅拷贝 | 深拷贝 |
|------|--------|--------|
| 基本类型 | 复制值 | 复制值 |
| 引用类型 | 复制引用（共享对象） | 递归复制（独立对象） |
| 速度 | 快 | 慢 |
| 安全性 | 修改引用对象会影响原对象 | 完全独立 |

<Callout type="warning">
原型模式通常需要**深拷贝**——否则克隆出的对象与原型共享内部引用（如 equipment 数组），修改一个会影响另一个。这是原型模式最容易出 bug 的地方。
</Callout>

## 常见误区

### 误区 1：忘了深拷贝

最常见的 bug：浅拷贝后修改克隆体的数组/对象，原型也跟着变。所有引用类型字段都要递归拷贝。

### 误区 2：循环引用导致无限递归

如果对象 A 引用 B，B 又引用 A，深拷贝会无限递归。解决方案：用 `WeakMap` 记录已拷贝的对象。

### 误区 3：所有场景都用原型

原型模式适合：创建成本高（需要数据库查询、网络请求、复杂计算）、需要保留已有状态、大量相似对象的场景。如果 `new` 就够快，不必用原型。

## 小结

- 原型 = 通过克隆已有对象创建新对象
- 核心价值：避免昂贵的初始化，快速复制已有状态
- 关键注意点：深拷贝 vs 浅拷贝、循环引用
- 适合：游戏对象生成、配置复制、缓存快照

<Glossary>

<GlossaryItem term="原型模式">

用原型实例指定创建对象的种类，并且通过拷贝这些原型来创建新对象。

</GlossaryItem>

<GlossaryItem term="深拷贝">

递归复制对象的所有字段，包括引用类型字段指向的对象。克隆体与原对象完全独立。

</GlossaryItem>

<GlossaryItem term="浅拷贝">

只复制对象的基本类型字段，引用类型字段仍指向原对象。克隆体与原对象共享引用对象。

</GlossaryItem>

</Glossary>
