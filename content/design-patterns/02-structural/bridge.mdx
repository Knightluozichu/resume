## 痛点场景：形状渲染

你有形状（圆形、方形）和渲染器（OpenGL、DirectX）两个维度。用继承：

```
Shape
├── CircleOpenGL
├── CircleDirectX
├── SquareOpenGL
├── SquareDirectX
└── 加三角形？加 Vulkan？M × N 个类
```

**继承爆炸**：每加一个形状或一个渲染器，类数量乘法增长。

## 解决方案：拆成两个维度

```typescript
// 实现维度：渲染器
interface Renderer {
  renderCircle(x: number, y: number, r: number): void;
  renderSquare(x: number, y: number, w: number): void;
}

class OpenGLRenderer implements Renderer {
  renderCircle(x, y, r) { console.log(`OpenGL 画圆 (${x},${y},r=${r})`) }
  renderSquare(x, y, w) { console.log(`OpenGL 画方 (${x},${y},w=${w})`) }
}

class DirectXRenderer implements Renderer {
  renderCircle(x, y, r) { console.log(`DirectX 画圆 (${x},${y},r=${r})`) }
  renderSquare(x, y, w) { console.log(`DirectX 画方 (${x},${y},w=${w})`) }
}

// 抽象维度：形状
abstract class Shape {
  constructor(protected renderer: Renderer) {} // 桥
  abstract draw(): void;
}

class Circle extends Shape {
  constructor(renderer: Renderer, private x: number, private y: number, private r: number) {
    super(renderer);
  }
  draw() { this.renderer.renderCircle(this.x, this.y, this.r) }
}
```

使用：

```typescript
const circle = new Circle(new OpenGLRenderer(), 10, 20, 5);
circle.draw(); // OpenGL 画圆
```

新增形状？加一个 Shape 子类。新增渲染器？加一个 Renderer 实现。**M + N 个类，不是 M × N**。

## 常见误区

### 误区 1：桥接 vs 策略

两者结构相似（都持有接口引用），但桥接的目的是**分离两个独立变化的维度**，策略的目的是**替换算法**。

### 误区 2：只在一个维度变化时用桥接

如果只有一个维度变化，用策略或工厂就够了。桥接适合**两个或以上维度同时独立变化**的场景。

### 误区 3：桥接太抽象

桥接是 GoF 23 模式中最抽象的一个。关键是记住：**把继承换成组合**——让 Abstraction 持有 Implementor 引用，而不是继承 Implementor。

## 小结

- 桥接 = 分离抽象与实现，各自独立变化
- 核心价值：M × N 继承爆炸 → M + N 组合
- 适合：两个或以上维度独立变化的场景（形状×渲染器、消息×发送通道、设备×功能）
- 与策略的区别：桥接是「拆维度」，策略是「换算法」

<Glossary>

<GlossaryItem term="桥接模式">

将抽象部分与它的实现部分分离，使它们都可以独立地变化。

</GlossaryItem>

<GlossaryItem term="继承爆炸">

当两个以上维度通过继承组合时，子类数量呈乘法增长（M × N）。桥接模式通过组合将其降为加法（M + N）。

</GlossaryItem>

<GlossaryItem term="实现维度">

桥接模式中可独立变化的一个维度，通常对应「怎么做」（如渲染器）。与「抽象维度」（做什么，如形状）对应。

</GlossaryItem>
