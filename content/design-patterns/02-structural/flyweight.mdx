## 痛点场景：万棵树

游戏地图上有 10000 棵树。每棵树有纹理数据（2MB）和位置坐标。如果每棵树都是独立对象：

```
10000 棵树 × 2MB 纹理 = 20GB 内存 💥
```

但所有同种树的**纹理是相同的**，只有坐标不同。

## 解决方案：共享不变部分

```typescript
// 享元：内部状态（共享）
class TreeType {
  constructor(
    public name: string,
    public color: string,
    public texture: string, // 2MB 纹理，只存一份
  ) {}
  draw(x: number, y: number) {
    console.log(`画 ${this.name} 在 (${x}, ${y})，纹理: ${this.texture}`);
  }
}

// 享元工厂
class TreeFactory {
  private static types: Map<string, TreeType> = new Map();

  static getTreeType(name: string, color: string, texture: string): TreeType {
    const key = `${name}-${color}-${texture}`;
    if (!this.types.has(key)) {
      this.types.set(key, new TreeType(name, color, texture));
    }
    return this.types.get(key)!;
  }
}

// 上下文：外部状态（不共享）
class Tree {
  constructor(
    private x: number,
    private y: number,
    private type: TreeType, // 共享的享元
  ) {}
  draw() { this.type.draw(this.x, this.y) }
}
```

使用：

```typescript
// 10000 棵树，但只有 3 种 TreeType（3 × 2MB = 6MB）
const trees: Tree[] = [];
for (let i = 0; i < 10000; i++) {
  const type = TreeFactory.getTreeType("Oak", "green", "oak_texture_2mb");
  trees.push(new Tree(Math.random() * 1000, Math.random() * 1000, type));
}
// 内存：3 × 2MB（纹理） + 10000 × ~50B（坐标+引用） ≈ 6.5MB
```

## 内部状态 vs 外部状态

| 维度 | 内部状态 | 外部状态 |
|------|----------|----------|
| 是否共享 | 共享（所有享元对象共用） | 不共享（每个上下文独有） |
| 是否可变 | 不可变 | 可变 |
| 存储位置 | 享元对象内部 | 上下文对象内部 |
| 示例 | 树的纹理、颜色 | 树的坐标 |

<Callout type="warning">
享元模式的核心前提：内部状态必须**不可变**。如果享元对象的状态被修改，所有共享它的上下文都会受影响。
</Callout>

## 常见误区

### 误区 1：享元 = 单例

单例保证全局只有一个实例。享元允许多个实例，但每种内部状态只有一个实例（通过工厂管理）。享元是「按状态共享」，单例是「全局唯一」。

### 误区 2：所有对象都享元化

享元模式有管理成本（工厂、状态分离）。只有对象数量大（≥数千）且内部状态可复用时才值得用。

### 误区 3：线程安全

享元对象被多线程共享。如果内部状态不可变，天然线程安全。但如果误把可变状态放进享元，会有并发问题。

## 小结

- 享元 = 共享细粒度对象 + 分离内外状态
- 核心价值：大量相似对象场景下大幅减少内存
- 内部状态不可变且共享，外部状态可变且不共享
- 适合：游戏对象、文本字符、图标缓存
