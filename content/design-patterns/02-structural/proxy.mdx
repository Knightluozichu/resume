## 痛点场景：图片加载

APP 要显示一个图片列表，每张图片 5MB。如果一次性全部加载，首屏卡顿严重。

```typescript
// 不用代理：所有图片立即加载
const images = urls.map(url => new Image(url)); // 每张 5MB，卡死
```

## 解决方案：延迟加载

```typescript
// Subject 接口
interface Image {
  display(): void;
}

// RealSubject：真正加载图片
class RealImage implements Image {
  private data: Buffer | null = null;

  constructor(private url: string) {
    this.loadFromDisk(); // 构造时就加载
  }

  private loadFromDisk() {
    console.log(`从磁盘加载 ${this.url}...（5MB）`);
    this.data = Buffer.alloc(5 * 1024 * 1024);
  }

  display() { console.log(`显示 ${this.url}`) }
}

// Proxy：延迟加载
class ProxyImage implements Image {
  private realImage: RealImage | null = null;

  constructor(private url: string) {}

  display() {
    if (!this.realImage) {
      this.realImage = new RealImage(this.url); // 第一次 display 才加载
    }
    this.realImage.display();
  }
}
```

使用：

```typescript
// 创建代理列表——不加载任何图片
const images = urls.map(url => new ProxyImage(url));

// 只有滚动到可见的才 display，触发加载
images[0].display(); // 加载第一张
// images[1] 还没 display，不加载
```

## 三种代理

| 类型 | 用途 | 示例 |
|------|------|------|
| 虚代理 | 延迟创建昂贵的对象 | 图片懒加载、数据库连接延迟 |
| 远程代理 | 访问远程对象（像本地一样） | RPC stub、gRPC client |
| 保护代理 | 控制访问权限 | 权限校验后才允许调用 |

<Callout type="tip">
代理模式在 Web 开发中无处不在：HTTP 代理、CDN、Nginx 反向代理、JavaScript Proxy 对象——都是「在中间加一层控制」的思想。
</Callout>

## 代理 vs 装饰器

| 维度 | 代理模式 | 装饰器模式 |
|------|----------|-----------|
| 结构 | 几乎一样 | 几乎一样 |
| 意图 | 控制访问 | 增强功能 |
| 创建者 | 代理自己创建/获取 RealSubject | 客户端显式包装 |
| 生命周期 | RealSubject 可能永远不创建 | 装饰器一定包裹已有对象 |

<Callout type="warn">
面试高频：代理和装饰器结构几乎一样，区别在**意图**——代理是「控制访问」，装饰器是「增强功能」。
</Callout>

## 常见误区

### 误区 1：代理加功能

代理的核心是**控制访问**，不是加功能。如果代理在 display() 前加了缓存逻辑，它更像是装饰器。不过两者边界模糊，实践中混用常见。

### 误区 2：代理必须和 RealSubject 同接口

代理实现 Subject 接口是为了对客户端透明。但有时代理需要额外方法（如 `preload()`），这会破坏透明性。视场景权衡。

### 误区 3：虚代理忘记线程安全

多线程下虚代理的延迟创建可能有竞态条件（两个线程同时检查 null）。需要双重检查锁或同步机制。

## 小结

- 代理 = 控制对象访问，在客户端和 RealSubject 之间加一层
- 三种类型：虚代理（延迟）、远程代理（跨网络）、保护代理（权限）
- 与装饰器结构相似，但意图不同：代理控制访问，装饰器增强功能
- 适合：懒加载、权限控制、远程调用、缓存

<Glossary>

<GlossaryItem term="代理模式">

为其他对象提供一种代理以控制对这个对象的访问。

</GlossaryItem>

<GlossaryItem term="虚代理">

延迟创建昂贵对象的代理。只有真正需要使用对象时才创建，节省资源。

</GlossaryItem>

<GlossaryItem term="远程代理">

代表一个位于不同地址空间的对象，使客户端可以像访问本地对象一样访问远程对象。

</GlossaryItem>

<GlossaryItem term="保护代理">

控制对象访问权限的代理。在调用前检查调用者是否有权限。

</GlossaryItem>

</Glossary>
