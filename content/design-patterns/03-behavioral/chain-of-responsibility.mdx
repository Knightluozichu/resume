## 痛点场景：审批流程

报销审批：金额 < 1000 组长审批，< 10000 经理审批，≥ 10000 总监审批。

不用模式：

```typescript
function approve(amount: number) {
  if (amount < 1000) { teamLeader.approve(amount) }
  else if (amount < 10000) { manager.approve(amount) }
  else { director.approve(amount) }
}
```

每加一个审批级别或调整金额阈值，都要改这段代码——**违反 OCP**。

## 解决方案：链式传递

```typescript
abstract class Approver {
  protected next: Approver | null = null;

  setNext(approver: Approver): Approver {
    this.next = approver;
    return approver; // 支持链式设置
  }

  approve(amount: number): void {
    if (this.canApprove(amount)) {
      this.doApprove(amount);
    } else if (this.next) {
      this.next.approve(amount);
    } else {
      console.log(`无法审批 ${amount}：超出所有审批权限`);
    }
  }

  protected abstract canApprove(amount: number): boolean;
  protected abstract doApprove(amount: number): void;
}

class TeamLeader extends Approver {
  protected canApprove(amount: number) { return amount < 1000 }
  protected doApprove(amount: number) { console.log(`组长审批 ${amount}`) }
}
class Manager extends Approver {
  protected canApprove(amount: number) { return amount < 10000 }
  protected doApprove(amount: number) { console.log(`经理审批 ${amount}`) }
}
class Director extends Approver {
  protected canApprove(amount: number) { return true }
  protected doApprove(amount: number) { console.log(`总监审批 ${amount}`) }
}
```

使用：

```typescript
const chain = new TeamLeader();
chain.setNext(new Manager()).setNext(new Director());

chain.approve(500);    // 组长审批 500
chain.approve(5000);   // 经理审批 5000
chain.approve(50000);  // 总监审批 50000
```

## 常见误区

### 误区 1：请求一定被处理

责任链不保证请求一定被处理。如果链尾没有兜底处理器，请求可能被丢弃。设计时需考虑：是否需要默认处理？还是允许请求「落空」？

### 误区 2：链太长影响性能

请求可能遍历整条链。如果链很长且大部分处理器都「不处理」，性能会下降。可以在链头加快速判断，或用 Map 直接路由。

### 误区 3：纯责任链 vs 管道

纯责任链：只有一个处理器处理请求，其余跳过。管道（Pipeline/Filter）：每个处理器都处理一遍请求。两者结构相似但语义不同，不要混淆。

## 小结

- 责任链 = 请求沿链传递，直到被处理或到达链尾
- 核心价值：发送者与接收者解耦，发送者不知道谁会处理
- 适合：审批流程、中间件（Express/Koa）、事件冒泡、异常处理链
- 注意：请求可能不被处理、链过长影响性能

<Glossary>

<GlossaryItem term="责任链模式">

使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。将这些对象连成一条链，并沿着这条链传递请求，直到有一个对象处理它为止。

</GlossaryItem>

<GlossaryItem term="处理器">

责任链中的一个节点，决定是否处理请求或将请求传递给下一个处理器。

</GlossaryItem>

<GlossaryItem term="管道模式">

与责任链结构相似但语义不同：管道中每个处理器都处理请求（如中间件），责任链中只有一个处理器处理请求。

</GlossaryItem>

</Glossary>
