## 痛点场景：咖啡订单

咖啡店卖咖啡：基础咖啡（Espresso、HouseBlend），可以加料：牛奶、糖、摩卡、奶泡。

用继承会怎样？

```
Beverage
├── Espresso
├── EspressoWithMilk
├── EspressoWithSugar
├── EspressoWithMilkAndSugar
├── EspressoWithMilkAndMocha
├── HouseBlendWithMilk
└── ...（组合爆炸）
```

每种配料组合都要一个子类，**类爆炸**。

## 解决方案：洋葱式包装

把配料也变成 Beverage，它内部包着一个 Beverage：

```typescript
// 组件接口
interface Beverage {
  cost(): number;
  description(): string;
}

// 基础组件
class Espresso implements Beverage {
  cost() { return 15 }
  description() { return "浓缩咖啡" }
}

// 装饰器基类
abstract class CondimentDecorator implements Beverage {
  constructor(protected beverage: Beverage) {}
}

// 具体装饰器
class Milk extends CondimentDecorator {
  cost() { return this.beverage.cost() + 3 }
  description() { return this.beverage.description() + " + 牛奶" }
}

class Mocha extends CondimentDecorator {
  cost() { return this.beverage.cost() + 5 }
  description() { return this.beverage.description() + " + 摩卡" }
}
```

使用：

```typescript
// 一杯加了双份摩卡和牛奶的浓缩咖啡
const coffee = new Milk(new Mocha(new Mocha(new Espresso())));
console.log(coffee.description()); // 浓缩咖啡 + 摩卡 + 摩卡 + 牛奶
console.log(coffee.cost());        // 15 + 5 + 5 + 3 = 28
```

## 装饰器 vs 继承

| 维度 | 继承 | 装饰器 |
|------|------|--------|
| 扩展方式 | 编译时确定 | 运行时动态组合 |
| 灵活性 | 每种组合需一个子类 | 任意组合，类数量线性 |
| 透明性 | 调用方知道具体类型 | 调用方只看到接口 |
| 缺点 | 类爆炸 | 嵌套层数多时可读性差 |

<Callout type="tip">
装饰器和继承都遵循「is-a」关系——装饰器本身也实现了被装饰的接口。区别在于装饰器通过「持有引用 + 委托」实现扩展，而不是通过继承链。
</Callout>

## 常见误区

### 误区 1：装饰器需要知道具体组件类型

装饰器的目的是**透明扩展**——调用方不应该知道对象被装饰过。如果你的装饰器代码里出现了 `instanceof` 判断，说明设计有问题。

### 误区 2：装饰器链过长

```typescript
// 这样可读性很差
new A(new B(new C(new D(new E(new F())))))
```

装饰器适合 2-4 层包装。如果层数更多，考虑用建造者模式或直接组合。

### 误区 3：装饰器修改了原有行为

装饰器应该**增强**行为，不应**替换**或**取消**原有行为。如果 `Milk.cost()` 直接返回 3 而不调用 `this.beverage.cost()`，它就不是一个装饰器，而是一个新组件。

## 小结

- 装饰器 = 包装 + 委托，动态给对象添加职责
- 核心价值：用组合代替继承，避免类爆炸
- 适合配料/插件/中间件场景（Java I/O 流、TypeScript 装饰器、Express 中间件）
- 注意保持透明性——调用方不应感知装饰器的存在

<Glossary>

<GlossaryItem term="装饰器模式">

动态地给一个对象添加一些额外的职责。就增加功能来说，装饰器模式比生成子类更加灵活。

</GlossaryItem>

<GlossaryItem term="包装链">

装饰器嵌套形成的链式结构。最内层是基础组件，每层装饰器向外包装一层，像洋葱一样。

</GlossaryItem>

<GlossaryItem term="透明性">

装饰器的核心约束——装饰后的对象与原始对象具有相同的接口，调用方无法（也不需要）区分。

</GlossaryItem>
