# 迭代器模式

<Objectives>

- 能解释独立游标如何隐藏聚合的数组、树或堆表示，并区分 `hasNext`、`next` 和耗尽状态。
- 能修改本章实验，切换深度优先与优先级遍历，逐项读取任务，注入集合修改反例并重置游标。
- 能回答：当遍历期间集合会变化时，应该选择快照、fail-fast 还是弱一致策略，并说明理由。

</Objectives>

## 直觉：先把“怎么存”与“怎么读”拆开

任务集合一开始可能是数组，后来为了优先级改成堆，或者为了层级关系改成树。若业务代码直接使用索引、节点和排序细节，存储结构一变，所有调用方都要一起改。

把“下一个元素是谁”交给一个独立游标后，调用者只需要反复询问是否还有下一项，再取出当前项。换一种遍历方式时，可以创建另一个游标；但如果集合在遍历中变化，游标看到什么必须先写成清楚的规则。

## 三个必须主动触发的迭代器误区

<Callout type="trap" title="让调用者直接操作集合索引">
  **现象 →** 业务代码到处读取数组下标、树节点或堆内部字段。 **原因 →** 把当前存储方式误当成稳定的访问接口。 **修法 →** 让聚合创建 Iterator，调用者只依赖 `hasNext` 和 `next`。
</Callout>

<Callout type="trap" title="耗尽后继续返回最后一个元素">
  **现象 →** 循环忘记检查结束状态，`next` 重复返回元素或越过边界。 **原因 →** 没有定义游标耗尽后的合同。 **修法 →** 让 `hasNext` 可重复查询，并让越界读取明确失败或返回结束结果。
</Callout>

<Callout type="trap" title="遍历时修改集合却不声明一致性">
  **现象 →** 新元素有时漏读，有时重复，结果还依赖修改时机。 **原因 →** 把快照、fail-fast 和弱一致混成了一个模糊行为。 **修法 →** 明确迭代器与聚合的版本、快照或并发修改策略，并用实验验证。
</Callout>

## 问题合同与五个关键术语

## 官方目录节点的逐项解释

下面的 13 个节点对应 manifest 中 `designpatterns-19` 的正式目录。每一节都连接任务游标实验、TypeScript 切片或练习证据；只出现节点名称不算完成解释。

### 模式名称与分类

迭代器模式属于行为型模式，关注如何在不暴露聚合内部表示的情况下顺序访问元素。分类只是导航；采用证据是调用者只依赖统一游标，而聚合可以把数组、树、堆或分页数据藏在自己的实现里。

### 意图

意图是提供一种访问聚合元素的顺序方式，同时不暴露聚合的内部结构。任务实验用同一组任务展示两种游标：调用者只调用 `hasNext` 和 `next`，不需要分别写数组索引或优先级队列逻辑。

### 别名

本章使用“迭代器模式”这一正式名称；“游标”是解释性称呼，不追加未经来源核对的稳定别名。看到一个循环并不自动意味着迭代器，必须有独立的访问状态和可替换的遍历协议。

### 动机

当业务代码直接操作数组索引、树节点或堆顶元素，存储方式的变化会扩散到每个调用点。把当前访问位置封装到迭代器后，遍历策略可以局部替换，聚合也能继续隐藏内部表示。

### 适用性

当聚合需要多种遍历方式、并发遍历、惰性读取或隐藏内部表示时，迭代器适合。若调用者必须频繁执行随机访问和复杂查询，单纯逐项迭代可能不是最佳接口；若集合永远很小且只有一种读取方式，直接循环可能更简单。

### 结构

结构由 Aggregate、ConcreteAggregate、Iterator 和 ConcreteIterator 组成。Aggregate 创建迭代器；ConcreteIterator 保存聚合引用、当前位置和一致性信息；调用者通过统一协议逐项读取。实验把聚合内容、顺序和 cursor 分开显示。

### 参与者

Aggregate 保存任务并决定能创建哪些遍历策略；Iterator 声明 `hasNext`、`next` 或等价操作；ConcreteIterator 保存游标状态并实现具体顺序；客户端只消费协议。每个游标都有独立位置，因此两个遍历可以并行推进而不互相覆盖。

### 协作

客户端向聚合请求一个 Iterator，反复检查 `hasNext` 并调用 `next`。迭代器根据自己的策略定位下一项，返回元素后推进位置；到达末尾时报告耗尽。优先级游标和深度游标可以访问同一聚合，却拥有不同的顺序与状态。

### 后果

收益是表示隔离、遍历策略可替换、多个游标可独立存在，还可以按需惰性读取。成本是迭代器要处理失效、并发修改和资源释放，某些策略还需要额外快照或索引。抽象协议减少了调用者知识，却不会自动解决集合变化问题。

### 实现

实现时明确游标的初始位置、耗尽行为和重复查询语义，并选择快照、fail-fast 或弱一致策略。若聚合有版本号，迭代器可以在 `next` 前检查版本；若底层资源昂贵，应在结束或异常时释放资源。不要让 `next` 静默重复最后一项。

### 示例代码

下面的 TypeScript 切片展示一个最小的独立游标。调用者不需要知道数组索引，迭代器也能让结束状态可观察：

```ts
interface Iterator<T> {
  hasNext(): boolean;
  next(): T;
}

class TaskIterator implements Iterator<string> {
  private cursor = 0;

  constructor(private readonly tasks: string[]) {}

  hasNext() {
    return this.cursor < this.tasks.length;
  }

  next() {
    if (!this.hasNext()) throw new Error("iterator exhausted");
    return this.tasks[this.cursor++];
  }
}
```

### 已知应用

集合库、语法树遍历、分页结果、文件扫描和数据库游标都可能使用迭代器。识别真实应用时要检查是否有独立位置、统一读取协议和明确结束语义；“用了 `for` 循环”本身不足以证明采用了迭代器模式。

### 相关模式

组合模式提供可被遍历的树结构；访问者在元素结构稳定时增加操作；工厂方法可以负责创建具体迭代器。迭代器的区分点是隐藏聚合表示并封装访问位置，而不是构造树、执行操作或创建对象本身。

## 把游标合同写进 TypeScript

接口只说明如何读取，不会自动决定集合修改后的行为。下面的切片加入版本检查，让迭代器在聚合变化时快速失败，而不是返回含糊结果：

```ts
class VersionedIterator<T> implements Iterator<T> {
  private cursor = 0;

  constructor(
    private readonly snapshot: readonly T[],
    private readonly expectedVersion: number,
    private readonly readVersion: () => number,
  ) {}

  hasNext() {
    return this.cursor < this.snapshot.length;
  }

  next() {
    if (this.readVersion() !== this.expectedVersion) {
      throw new Error("collection modified during iteration");
    }
    return this.snapshot[this.cursor++];
  }
}
```

如果业务需要读到一致快照，可以在创建迭代器时复制元素；如果允许弱一致，则应记录可能漏读或重复的边界。关键是把选择写成合同，而不是让调用者猜测底层容器行为。

**问题 1：改 Demo 代码。** 为实验增加一个“只返回未完成任务”的过滤迭代器。它应复用已有的 `hasNext`/`next` 合同，还是把过滤逻辑交给调用者？请说明如何保持游标独立。

<Answer>
  可以实现一个包装或专用迭代器，内部持有基础迭代器并在 `hasNext` 中寻找下一个未完成任务；调用者仍只依赖同一合同。每个过滤迭代器需要自己的当前位置和待返回项缓存，不能共享另一个调用者的游标。
</Answer>

**问题 2：做一次拒绝决定。** 集合会在遍历期间被多个线程修改，而业务要求结果可重现。为什么不能默认使用弱一致迭代器？

<Answer>
  弱一致允许读到变化中的视图，可能漏读或重复，不能满足可重现要求。应选择快照或带版本的 fail-fast 策略，并在冲突时重试或明确返回错误。
</Answer>

**问题 3：比较相邻模式。** 一个需求是遍历一棵整体与部分组成的树，另一个需求是在树结构稳定后增加导出和审计操作。分别优先评估什么模式？

<Answer>
  树的整体与部分结构优先评估组合模式；在结构稳定但需要多种操作时优先评估访问者。迭代器负责隐藏遍历位置，不能替代树结构建模或操作扩展。
</Answer>

## 本章小结与发布前回顾

- 迭代器用独立游标隐藏聚合的内部表示。
- `hasNext`、`next` 和耗尽状态共同构成读取合同。
- 不同遍历策略可以拥有不同游标，而调用者保持不变。
- 集合修改必须明确快照、fail-fast 或弱一致策略。
- 通过实验能切换策略、逐项读取、触发耗尽并重置。
