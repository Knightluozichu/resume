## 什么是复合模式

单个模式解决单个问题。但真实系统往往有多个交织的问题——这时候需要**复合模式**：将多个模式组合使用，产生 1+1>2 的协同效应。

复合模式不是随意拼凑，而是模式间天然契合的组合。

## 经典案例：MVC

MVC 是最著名的复合模式。它组合了三个模式：

| 模式 | 在 MVC 中的角色 | 解决什么问题 |
|------|----------------|-------------|
| Observer | Model ↔ View | Model 状态变化时通知 View，二者松耦合 |
| Strategy | View ↔ Controller | View 将交互逻辑委托给 Controller，可替换策略 |
| Composite | View 内部 | View 由子 View 组成树形结构，统一渲染 |

```typescript
// Model：被观察者
class Model {
  private observers: View[] = [];
  private data: any;

  registerObserver(v: View) { this.observers.push(v) }
  notifyObservers() { this.observers.forEach(v => v.update(this.data)) }
  setData(data: any) { this.data = data; this.notifyObservers() }
}

// View：观察者 + Composite 节点 + Strategy 持有者
abstract class View {
  protected children: View[] = [];
  protected controller: Controller;

  abstract update(data: any): void;  // Observer 接口
  abstract render(): void;            // Composite 渲染

  setController(c: Controller) { this.controller = c } // Strategy 注入
  addChild(v: View) { this.children.push(v) }
}

// Controller：Strategy
interface Controller {
  handleInput(input: any): void;
}

class ButtonView extends View {
  update(data: any) { this.render() }
  render() {
    this.children.forEach(c => c.render()); // Composite
  }
}
```

## 模式如何协同

1. **Observer**：Model 变化 → 通知 View → View 刷新。Model 不知道 View 的具体类型，只通过 Observer 接口通信。
2. **Strategy**：用户输入 → View 交给 Controller 处理 → Controller 修改 Model。View 不含业务逻辑，Controller 可替换。
3. **Composite**：View 是树形结构（窗口包含面板，面板包含按钮），统一调用 `render()` 递归渲染。

三个模式各司其职，组合在一起形成了完整的 MVC 架构。

## 常见误区

### 误区 1：为组合而组合

不是所有系统都需要 MVC 级别的模式组合。简单 CRUD 用 MVC 是合理的，但一个配置面板也套 MVC 就过度设计了。**模式组合的复杂度应匹配问题复杂度**。

### 误区 2：模式越多越好

每个模式都有认知成本和维护成本。4 个模式组合的理解难度不是 4 倍，而是指数级增长。保持组合简洁——能用 2 个模式解决就不用 3 个。

### 误区 3：忽视模式间的冲突

某些模式组合可能冲突。例如：单例 + 享元都管理对象生命周期，混用容易混乱。组合前先确认模式间是否兼容。

## 小结

- 复合模式 = 多个模式协同工作，解决交织的复杂问题
- MVC 是经典案例：Observer（Model↔View）+ Strategy（View↔Controller）+ Composite（View 树）
- 模式组合的复杂度应匹配问题复杂度——过度组合是反模式
- 先理解单个模式，再理解组合——跳过基础直接学组合容易囫囵吞枣

<Glossary>

<GlossaryItem term="复合模式">

将两个或多个模式组合在一起形成的协同方案。复合模式不是模式的随意堆砌，而是模式间天然契合的组合。

</GlossaryItem>

<GlossaryItem term="MVC">

Model-View-Controller，最经典的复合模式案例。Model 管理数据（Observer 的 Subject），View 展示数据（Observer 的 Observer + Composite 节点），Controller 处理交互（Strategy）。

</GlossaryItem>

<GlossaryItem term="协同效应">

多个模式组合后产生的效果大于单个模式效果之和。例如 MVC 中 Observer 解耦了 Model 和 View，Strategy 解耦了 View 和 Controller，Composite 统一了 View 树——三者组合形成了完整的关注点分离架构。

</GlossaryItem>
