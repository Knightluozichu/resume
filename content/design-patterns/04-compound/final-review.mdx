## 直觉：终点相同，不代表走对了路

复制一份稿件给同事修改，自己的那份也跟着变了。最后把两份都改回原文，看起来没有损失，可是“互不影响”的约定早已被破坏。只检查最后一屏，会把这个问题漏掉。

本页要练的是评审：逐步检查谁改了什么、谁能恢复什么，决定是否真的需要增加一层设计。若只凭名称选方案，功能可能变复杂，原来的错误却依然存在。

## 本页身份与阅读合同

这是**本站原创综合复习页，不是 GoF 新增正式单元，也不是第 24 个模式**。下方 23 个名称是前文已学概念的回顾，不引入 23 个新概念；本页新增的综合视角只有下面四项。表格负责比较，实验只实现其中一个小切片，不伪装成“23 模式全集编辑器”。

- <Term def="运行前后都必须成立、且能用断言观察的行为或状态约束。">不变量</Term>
  ：A 和 B 的段落身份不同；编辑 B 不改变
  A。图中的引用线和纸面结果共同验证，不能只比最后文本。
- <Term def="同一对象被哪些持有者引用，以及谁有权修改或恢复它的约定。">
    所有权边界
  </Term>
  ：B 创建的快照只能由 B 恢复。实验最后一步把它交给 A，必须在写入前拒绝。
- <Term def="复制对象时，明确哪些可变部分必须分离、哪些不可变部分可以保持同一引用。">
    复制边界
  </Term>
  ：段落可变，样式只含一个冻结的字符串字段。图中 P1/P2
  分离，而两条样式引用会合到 F1。
- <Term def="足以证明额外抽象不值得引入的具体需求或代价条件。">拒绝条件</Term>
  ：若只是即时预览，不需要排队、审计或撤销，普通函数足够；不为了凑模式添加命令栈。

## 先预测，再追踪真实对象

先预测：只把“段落克隆边界”切成故障，保留值快照，走完两次编辑与两次撤销，最终文本能否正确？如果能，哪一步已经违反隔离？再预测：只保存活段落引用，为什么快照上的文字会随着编辑一起增长？

<DesignPatternsReviewContractLab />

操作顺序固定为：克隆 B → 保存 B 并追加 B → 保存 A 并追加 A → 撤销 A → 撤销 B → 尝试跨文档恢复。每次切换配置都回到第 0 步；“重置全部”还恢复两项正确配置。这个离散实验没有自动动画，静态显示同样支持减少动态效果的系统偏好。

| 配置              | 第 1 步 A / B | 第 2 步 A / B | 第 4 步 A / B | 必须看到的事实                     |
| ----------------- | ------------- | ------------- | ------------- | ---------------------------------- |
| 复制段落 + 文本值 | 稿 / 稿B      | 稿A / 稿B     | 稿 / 稿       | 可变对象分离、撤销恢复             |
| 共用段落 + 文本值 | 稿B / 稿B     | 稿BA / 稿BA   | 稿 / 稿       | 终点正确，但中途串改；身份始终错误 |
| 复制段落 + 活引用 | 稿 / 稿B      | 稿A / 稿B     | 稿A / 稿B     | 对象隔离正确，快照却随状态漂移     |
| 共用段落 + 活引用 | 稿B / 稿B     | 稿BA / 稿BA   | 稿BA / 稿BA   | 两个独立合同同时失败               |

四组配置的最后一步都必须拒绝跨文档快照。**共享了段落不等于共享了恢复权限**。页面中的“本步内容一致”只是局部观察；紧随其后的身份检查才揭示被终点掩盖的错误。

## 创建型比较

创建型的选择先看“创建时到底什么会变”。本例从现有稿件复制内容，是原型的局部用途；只有两份文档并不需要工厂层级。下面五行的验收动作分别检验产品选择、族一致性、构造次序、复制隔离和实例作用域，不用“都有一个 create 方法”代替判断。

| 模式                      | 真实变化压力与责任                                           | 与谁容易混淆；应怎样验证                                             | 拒绝条件与更小替代                                     |
| ------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------ |
| 工厂方法 Factory Method   | 导出任务基类固定保存流程，由子类决定创建 PDF 还是 SVG 编码器 | 抽象工厂管成套产品；这里只替换一个创建点，检查流程没有类型分支       | 没有可扩展创建点时，传入一个创建函数即可               |
| 抽象工厂 Abstract Factory | 打印版与屏幕版各需匹配的字体度量器和布局器，按族创建         | 工厂方法不自动保证族匹配；故意混搭两族应被配置校验拒绝               | 产品可任意组合、没有族约束时，用显式参数组装           |
| 生成器 Builder            | 同一份文档逐步加入标题、段落和资源，再产出不同表示           | 抽象工厂主要选产品族；生成器管理构造步骤，未完成资源解析不能交付结果 | 几个必填字段一次构造即可时，不增加逐步状态             |
| 原型 Prototype            | 根据现有稿件创建可独立编辑的副本，不重新解释全部初始化参数   | 不是无脑深拷贝；本页检查段落身份不同、冻结样式引用相同               | 普通构造器已经表达默认值且没有运行时模板时，直接构造   |
| 单例 Singleton            | 明确限定进程内只允许一个资源目录服务入口                     | 不等于全局变量，更不等于跨进程唯一；测作用域和测试隔离               | 只为“到处拿得到”时拒绝；按应用实例注入服务，别隐藏依赖 |

## 结构型比较

结构型关注对象连接后承担的语义。图中共享 F1 只是享元的缩小切片：重复样式可以复用，文本和文档位置不能塞进去。若扩展为大量样式，才需要按值归一化的池；本页不为一个样式再造缓存框架。

| 模式             | 真实变化压力与责任                                          | 与谁容易混淆；应怎样验证                                                   | 拒绝条件与更小替代                                   |
| ---------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------- |
| 适配器 Adapter   | 旧打印 API 接收毫米，新布局接口输出像素；转换接口并明确单位 | 桥接不是事后补兼容；用固定 DPI 的已知样本检查转换                          | 两端协议本来一致时，不包装空壳                       |
| 桥接 Bridge      | 文档抽象与渲染后端各自扩展，避免每种组合派生一个子类        | 与策略都可用委托；桥接强调两个独立变化维度，检查新增后端不用修改各文档子类 | 只有一个简单渲染函数时，直接注入函数                 |
| 组合 Composite   | 段落与章节容器需要统一排版入口，容器递归委派给孩子          | 不是所有列表都要做树；用嵌套章节检验统一调用，防环另立约束                 | 数据只有平面段落数组时，保留数组；本页不实现树遍历   |
| 装饰器 Decorator | 给某个输出流叠加压缩、统计等职责，保留原接口                | 代理主要控制访问；交换包装顺序，验证统计的是压缩前还是压缩后的字节         | 固定两步变换可直接函数组合时，不建装饰器继承体系     |
| 外观 Facade      | 为导出子系统提供常用入口，协调字体加载、布局、写文件        | 中介者管理同事间交互；外观简化客户入口，检查错误仍可传出                   | 调用端只有一次直调时，不再加转发服务                 |
| 享元 Flyweight   | 大量段落复用相同不可变字形/样式，把位置等变化信息留在外部   | 原型负责造副本，享元有意共享；本页测 F1 相同但 P1/P2 不同                  | 无显著重复对象或共享内容仍可变时，先用普通值，不建池 |
| 代理 Proxy       | 大图片延迟加载，或按权限拦截文档读取，同时保留访问接口      | 装饰器加职责，代理管可达性；未授权请求不应到达真实对象                     | 无加载、权限或远程边界时，直接使用真实对象           |

## 行为型比较

行为型先问“谁决定下一步、谁保存过去、谁对失败负责”。不要根据类图形状判断：策略和状态都可能有 Context；命令和备忘录都可能出现在撤销里。下面分两组回收全部 11 个模式，表中的观测条件可作为各自章节实验的复测入口。

### 分派、算法与传播

| 模式                           | 真实变化压力与责任                                         | 与谁容易混淆；应怎样验证                                         | 拒绝条件与更小替代                                     |
| ------------------------------ | ---------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------ |
| 责任链 Chain of Responsibility | 快捷键从选中控件逐级交给父容器，第一个能处理者结束请求     | 观察者通常通知多个订阅者；检查无人处理和提前停止路径             | 接收者固定时直接调用，别制造难以追踪的转发链           |
| 解释器 Interpreter             | 一个小型过滤语法用表达式节点解释标题、作者等条件           | 不是普通策略切换；同一语法树在两份文档环境中求值应遵守语义       | 语法复杂、有成熟解析工具时，不手写一套语言运行时       |
| 迭代器 Iterator                | 按文档顺序取段落而不泄露容器表示，遍历位置由迭代器持有     | 访问者承载跨类型操作；检查两次并行遍历的游标互不影响             | 原生数组迭代已足够时，不加自定义游标类                 |
| 策略 Strategy                  | 同一段文本可选贪心或高质量断行算法，调用方选择计算方式     | 状态按生命周期限制动作；相同输入下比较算法结果和成本             | 算法固定且短小时，普通函数更清楚                       |
| 状态 State                     | 草稿、审阅、锁定阶段允许的编辑动作不同，转换受当前阶段约束 | 策略通常不是生命周期；从锁定态编辑应拒绝且不预写内容             | 两个稳定分支足够时，用显式条件；别为每个布尔值建状态类 |
| 模板方法 Template Method       | 导出骨架固定“准备→编码→关闭”，子类定制编码步骤             | 策略用组合替换算法；模板方法靠继承固定顺序，测编码抛错仍关闭资源 | 没有继承扩展点时，普通函数加回调即可                   |

### 请求、快照与协作

| 模式            | 真实变化压力与责任                                         | 与谁容易混淆；应怎样验证                                             | 拒绝条件与更小替代                                             |
| --------------- | ---------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| 命令 Command    | 把一次“追加文字”绑定接收者，供延后执行或历史撤销使用       | 备忘录不描述请求；本页 CB 的撤销必须仍找 B，而非当前选中的文档       | 即时调用且不需要历史时，直接调用编辑函数                       |
| 备忘录 Memento  | 文档自己保存并解释恢复所需的内部状态，历史只保存不透明令牌 | 克隆不等于快照；本页复制可变段落、值快照、令牌所属文档分别验证       | 单一可逆操作且恢复不需隐藏状态时，可以只记录逆操作参数         |
| 观察者 Observer | 文档变化后通知字数栏、预览等多个独立订阅者                 | 中介者集中规定协调规则；检查取消订阅与订阅者失败策略                 | 只有一个已知调用者时，直接回调；通知本身不承诺事务一致性       |
| 中介者 Mediator | 编辑对话框中的纸张、边距、预览相互制约，由协调者管理交互   | 外观面向外部简化入口；测试改纸张引发边距校验与预览更新，而非同事互调 | 只有两个对象单向协作时直接连接，避免万能协调器                 |
| 访问者 Visitor  | 节点种类稳定，统计、检查等跨节点操作频繁新增               | 迭代器决定怎么走，访问者决定到节点做什么；新增节点种类会影响各操作   | 节点种类经常新增或一次简单遍历足够时，用方法或函数，不加双分派 |

## 混淆对照：组合不是越多越好

上面是候选清单，不是采购清单。本页实验证明四个职责可以合作，但没有声称用了模式就自动正确。对每一对混淆，都要追问失败发生在哪条边界。

| 看起来相似             | 真正分界                              | 在本页应如何裁决                                                 |
| ---------------------- | ------------------------------------- | ---------------------------------------------------------------- |
| 原型 / 享元            | 新对象的独立性 / 重复对象的有意共享   | 段落复制，样式保留同一引用；“全部深拷贝”和“全部共享”都不符合目标 |
| 命令 / 备忘录          | 请求及接收者 / 状态保存与恢复权限     | CB 记录 B 与撤销动作；文本值由 B 私有保存，命令不改令牌内容      |
| 策略 / 状态            | 可替换计算方法 / 当前阶段允许什么动作 | 两个实验故障开关只是测试配置，不因有选项就宣称实现策略或状态模式 |
| 适配器 / 装饰器 / 代理 | 改接口 / 增职责 / 控制访问            | 撤销所有权检查是文档自己的责任，不必再套一个“权限代理”才能检查   |
| 组合 / 访问者 / 迭代器 | 整体部分结构 / 跨类型操作 / 遍历协议  | 本页只有两个文档句柄，不需要任何一个；有文档一词不等于需要文档树 |

## 实现：同一个模型，三条独立断言

以下 TypeScript 片段**按出现顺序拼接为一个 `review.ts` 文件**，包括练习答案中的代码块；块间是在同一类或函数内部继续，不是独立运行文件。编译目标 ES2022、CommonJS，可用 TypeScript 编译后由 Node 运行。全页代码不依赖浏览器或新增库；图形组件用相同的模型实现。

**片段 1/5：声明与复制。** `ReviewDocument` 是接收编辑的文档对象。复制只展开段落一层：文本是字符串值，样式是明确冻结的共享对象。类型上的 `readonly` 不是深冻结；公开构造器不替调用方冻结样式，实验基线和练习会显式冻结。若外部传入可变样式，或以后样式含可变嵌套属性，当前共享合同就需要重新设计。

```ts
export type CopyMode = "copy" | "alias";
export type SnapshotMode = "value" | "live";
export type Paragraph = { text: string; style: Readonly<{ font: string }> };
export class ReviewDocument {
  #saved = new WeakMap<object, string | Paragraph>();
  constructor(public readonly paragraph: Paragraph) {}
  clone(mode: CopyMode): ReviewDocument {
    if (mode !== "copy" && mode !== "alias") throw new Error("copy mode");
    return new ReviewDocument(
      mode === "copy" ? { ...this.paragraph } : this.paragraph,
    );
  }
```

**片段 2/5：接着写在类内部，最后闭合类。** 令牌只是冻结的空对象，真正的数据在文档私有 `WeakMap` 内。对象身份就是查找键；另一个空对象不能冒充令牌。`snapshotText` 是图形的教学探针，生产的历史管理者无需也不应调用它。

```ts
  capture(mode: SnapshotMode): object {
    if (mode !== "value" && mode !== "live") throw new Error("snapshot mode");
    const token = Object.freeze({});
    this.#saved.set(token, mode === "value" ? this.paragraph.text : this.paragraph);
    return token;
  }
  snapshotText(token: object): string {
    if (!this.#saved.has(token)) throw new Error("foreign snapshot");
    const saved = this.#saved.get(token)!;
    return typeof saved === "string" ? saved : saved.text;
  }
  restore(token: object): void {
    this.paragraph.text = this.snapshotText(token);
  }
}
```

**片段 3/5：命令封装一次编辑。** 故障模式仍执行真实代码，不是给结果预填“失败”标签。`undo` 捕获原接收者与令牌；它既不找“当前活动文档”，也不简单删除末尾一个字符。

```ts
export function editReview(
  doc: ReviewDocument,
  suffix: string,
  mode: SnapshotMode,
) {
  const before = doc.capture(mode);
  doc.paragraph.text += suffix;
  return { receiver: doc, before, undo: () => doc.restore(before) };
}
```

**片段 4/5：固定场景的前半段。** `phase` 是演示步数，不是业务状态机。每帧从确定基线重放，确保重置不依赖上一次操作遗留状态。这里用冻结的单层对象来满足样式共享的前提。

```ts
export function runReview(copy: CopyMode, snapshot: SnapshotMode, phase: number) {
  if (!Number.isInteger(phase) || phase < 0 || phase > 5) throw new Error("phase");
  const style = Object.freeze({ font: "serif" });
  const a = new ReviewDocument({ text: "稿", style });
  const b = a.clone(copy);
  if (snapshot !== "value" && snapshot !== "live") throw new Error("snapshot mode");
  const commands: ReturnType<typeof editReview>[] = [];
  if (phase >= 1) commands.push(editReview(b, "B", snapshot));
  if (phase >= 2) commands.push(editReview(a, "A", snapshot));
  if (phase >= 3) commands[1].undo();
  if (phase >= 4) commands[0].undo();
```

**片段 5/5：接着写在函数内部，最后闭合函数。** 最后故意误用 B 的令牌，只有预期的所有权错误才被转换为可视结果，其他异常照常抛出。A 的 `restore` 会先读取并校验令牌，再写入，所以拒绝不能带来半次修改。

```ts
  let foreignRejected = false;
  if (phase >= 5) {
    try { a.restore(commands[0].before); }
    catch (error) {
      if (!(error instanceof Error) || error.message !== "foreign snapshot") throw error;
      foreignRejected = true;
    }
  }
  return { a, b, commands, foreignRejected };
}
```

保存文本值需要与历史文本总长度成比例的空间；每次追加还要创建新字符串。令牌检查避免权限混淆，不解决历史容量。这里没有样式池、通用事件总线或遍历框架，也没有外部 I/O：对发邮件、协作编辑等操作，恢复本地旧文本不能撤回外部事实。

## 常见误区

<Callout type="trap" title="最后恢复原文，就证明复制正确？">
  共用段落配合值快照会在第 4 步恢复原文，但第 1 步已经把 A
  改成“稿B”。修复的是复制边界，不能靠增加更多撤销步骤遮住问题。验收必须同时记录中间文本和对象身份。
</Callout>

<Callout type="trap" title="冻结了令牌，快照就不会变？">
  冻结空令牌只保护令牌自身。故障分支在 WeakMap
  里保存的是活段落，后续编辑会改变其
  text，撤销读回的还是当前值。修复应保存需要恢复的值；冻结和只读类型都不自动深复制引用图。
</Callout>

<Callout type="trap" title="有 undo 方法，就是通用撤销系统？">
  这里只有单线程、固定顺序的后进先出撤销。重复恢复同一值可以幂等，但任意乱序撤销可能抹掉更新；本例没有重做、分支历史、跨客户端冲突或外部副作用补偿。需求到了那些边界，应先重写合同，而不是给这个函数改一个更响亮的模式名。
</Callout>

## 拒绝模式的评审顺序

先写可观察需求，再尝试最小函数或数据结构；只有变化压力真实存在，才引入额外角色。给每个候选附上增加的对象、调用跳转和维护成本，然后用一个会失败的样本去挑战它。若删除模式层后所有业务断言仍通过且扩展需求没有损失，就优先保留更简单方案。

本页保留命令，是为了让请求记住接收者；保留快照，是为了把恢复权限留给文档；保留显式克隆，是为了讨论复制合同。没有大量对象就不实现享元池，没有树就不加组合，没有多个订阅者就不加观察者。代码里出现闭包、委托或选项，本身不是宣称某模式已经实现的证据。

<Exercises>

**问题 1：改代码，让副本真正独立。** 同事写了 `new ReviewDocument(doc.paragraph)` 作为复制。请修改实现，使编辑副本不影响原件，但冻结样式仍共享；不要使用 JSON 序列化把所有东西复制一遍。下列答案同时执行坏实现的反例和修复后的不变量。

<Answer>

新文档对象不同，并不代表内部段落不同。只复制可变段落层，保留样式引用；复制范围由数据合同决定，而非由“深”这个字决定。继续将本块拼在模型后。

```ts
export function check(ok: boolean, message: string): void {
  if (!ok) throw new Error(message);
}
const original = new ReviewDocument({
  text: "",
  style: Object.freeze({ font: "serif" }),
});
const badFork = (doc: ReviewDocument) => new ReviewDocument(doc.paragraph);
const bad = badFork(original);
const badCommand = editReview(bad, "错", "value");
check(original.paragraph.text === "错", "反例：原件被串改");
badCommand.undo();
const fork = (doc: ReviewDocument) => new ReviewDocument({ ...doc.paragraph });
const good = fork(original);
check(good.paragraph !== original.paragraph, "可变段落必须分离");
check(good.paragraph.style === original.paragraph.style, "样式不必复制");
check(Object.isFrozen(good.paragraph.style), "共享样式必须满足冻结前提");
const goodCommand = editReview(good, "新稿🙂", "value");
check(original.paragraph.text === "", "副本编辑不应影响原件");
goodCommand.undo();
check(good.paragraph.text === "", "空文本快照也必须可恢复");
```

若未来段落包含可变子对象，仅展开这一层就不够。先新增隔离断言，再决定对哪些子对象复制，不能把此处的安全结论推广到任意图。

</Answer>

**问题 2：定位失败的责任，而非给模式贴标签。** 预测共用段落配合值快照的第 2、3、4 步，再与正确复制配合活引用比较。为什么两个修复不能互相代替？写断言证明 A 不能拿 B 的令牌恢复，即使令牌被冻结。

<Answer>

前者 A/B 的文本依次都是“稿BA”“稿B”“稿”，但段落从未分离；后者的段落分离，却一直读回被编辑后的文本。一个是复制合同失败，一个是状态保存失败。令牌所属关系由各文档私有映射决定，不能由外观或最终内容推断。

```ts
const states = ["稿BA", "稿B", "稿"];
for (const [i, text] of states.entries()) {
  const r = runReview("alias", "value", i + 2);
  check(r.a.paragraph.text === text && r.b.paragraph.text === text, "别名轨迹");
  check(r.a.paragraph === r.b.paragraph, "终点正确也没修好身份");
}
const drift = runReview("copy", "live", 4);
check(drift.a.paragraph !== drift.b.paragraph, "复制边界已正确");
check(drift.a.paragraph.text === "稿A", "活引用撤销失败");
check(drift.b.paragraph.text === "稿B", "B 也没有恢复");
const safe = runReview("copy", "value", 5);
check(safe.foreignRejected, "必须拒绝跨文档令牌");
check(safe.a.paragraph.text === "稿", "拒绝时不可写入");
let rejected = false;
try {
  safe.a.restore(Object.freeze({}));
} catch {
  rejected = true;
}
check(rejected, "形状相同的伪造令牌不能恢复");
```

</Answer>

## 范围答卷：完成了什么，没有完成什么

根据 B6 独立范围复核，本站 **27 页 = 24 个正式映射单元 + 学习地图、复合练习、总复习**；24 个正式单元是导论加 23 模式，不是原书全部细分章节。**310 = 导论映射的 11 个宏观目录项 + 23 × 13 个模式描述字段**。13 字段是描述骨架，不是每个模式的 13 个独立知识点；本页也不会假造一套“总复习模式”的 13 字段来充数。

原书包含文档编辑器案例及附录 A 术语表、附录 B 记号指南、附录 C 基础类，还列有参考文献与索引。站内导论对这些项目的范围说明，不等于完整案例、符号体系、基础类实现及全部材料已经复现。本页的两个文档对象是原创教学切片，**不是原书文档编辑器的重建**；也没有逐项覆盖各模式的全部动机、实现变体和已知应用。

本页提交的是草稿：真实源文获取、原创解释、可执行反例及模型检查构成局部证据；整书范围核验、最终集成和真实双视口交互验收仍须单独完成。需要回访的路径是“业务断言→相应模式章→原书合法可访问材料”，不是从通过数量倒推教学充分性。

## 小结

创建型问对象怎样产生，结构型问对象怎样连接，行为型问责任怎样流动。选型要落在一次可观察的变化上：本页用段落身份检查复制，用共享冻结样式检查共享边界，用中间文本检查编辑隔离，用文档私有令牌检查恢复权限。三类错误不能互相抵销，最后看起来正确也不能免除中间步骤的验证。

当需求没有变化压力，拒绝模式也是正确的设计结论。学完 23 个名称，只获得了一组候选方案；能写出反例、留下断言并说清楚哪些内容还没验证，才是一份可复查的复习答卷。
