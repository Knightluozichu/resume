## 一句话记忆

### 创建型（5 个）——「对象怎么创建」

| 模式 | 一句话 |
|------|--------|
| 单例 | 全局唯一实例 |
| 工厂方法 | 子类决定创建哪个产品 |
| 抽象工厂 | 创建产品族，保证一致性 |
| 建造者 | 分步构建复杂对象 |
| 原型 | 克隆已有对象 |

### 结构型（7 个）——「类与对象怎么组合」

| 模式 | 一句话 |
|------|--------|
| 适配器 | 转换不兼容的接口 |
| 桥接 | 分离抽象与实现两个维度 |
| 组合 | 树形结构统一处理 |
| 装饰器 | 包装链动态扩展 |
| 外观 | 简化复杂子系统入口 |
| 享元 | 共享细粒度对象 |
| 代理 | 控制对象访问 |

### 行为型（11 个）——「对象间怎么通信」

| 模式 | 一句话 |
|------|--------|
| 责任链 | 请求沿链传递 |
| 命令 | 请求封装为对象 |
| 解释器 | 文法树解释语言 |
| 迭代器 | 统一遍历接口 |
| 中介者 | 多对多变星型 |
| 备忘录 | 状态快照与恢复 |
| 观察者 | 一对多依赖通知 |
| 状态 | 行为随状态改变 |
| 策略 | 算法族可互换 |
| 模板方法 | 骨架+钩子 |
| 访问者 | 双分派加操作 |

## 易混淆模式对比

### 策略 vs 状态

| 维度 | 策略 | 状态 |
|------|------|------|
| 意图 | 选择算法 | 改变行为 |
| 谁切换 | 客户端主动 | 状态自动切换 |
| 类比 | 选工具 | 变身份 |

### 代理 vs 装饰器

| 维度 | 代理 | 装饰器 |
|------|------|--------|
| 意图 | 控制访问 | 增强功能 |
| 创建者 | 代理自管理 | 客户端显式包装 |
| 类比 | 门卫 | 礼物包装 |

### 外观 vs 适配器

| 维度 | 外观 | 适配器 |
|------|------|--------|
| 意图 | 简化接口 | 转换接口 |
| 对象 | 多个子系统 | 一个不兼容类 |
| 类比 | 一键按钮 | 电源转换器 |

## 选型决策树

<DecisionTreeDiagram />

<Callout type="tip">
选型流程：**先定类型**（创建/结构/行为），**再问问题**（需要唯一实例？需要解耦请求？），最后落到具体模式。不要一上来就问「该用什么模式」，而是先明确问题类型。
</Callout>

## 三条设计直觉（再强调）

1. **封装变化**——把变化的部分单独拎出来
2. **针对接口编程**——依赖抽象，不依赖具体
3. **优先组合而非继承**——「有一个」比「是一个」更灵活

这三句话是 23 个模式背后最核心的共性。理解了它们，你已经掌握了设计模式的灵魂。

## 模式是药不是维生素

| 场景 | 该不该用模式 |
|------|-------------|
| 2 个分支的 if-else | 不用，直接写 |
| 5 个分支且会扩展 | 用策略模式 |
| 简单对象创建 | 不用，直接 new |
| 创建逻辑复杂且会变 | 用工厂方法 |
| 2 个类直接通信 | 不用中介者 |
| 5 个类网状耦合 | 用中介者 |

<Callout type="warn">
判断标准：**痛点是否存在 + 变化是否发生**。没病别吃药，但病了也别硬扛。
</Callout>

## 小结

- 23 模式分三类：创建型（怎么建）、结构型（怎么组合）、行为型（怎么通信）
- 易混淆模式对比：策略vs状态、代理vs装饰器、外观vs适配器
- 选型决策：先定类型，再问问题
- 终极原则：模式是药不是维生素——有痛点才用

<GlossaryItem term="选型决策树">

通过「问题类型 → 关键问题 → 具体模式」的层次化决策流程选择合适的设计模式。先定类型（创建/结构/行为），再问问题。

</GlossaryItem>

<GlossaryItem term="模式是药不是维生素">

设计模式应针对具体痛点使用，不是所有代码都需要模式。没有痛点时强行加模式是过度设计，有痛点时不用模式是欠设计。

</GlossaryItem>

<GlossaryItem term="三条设计直觉">

封装变化、针对接口编程、优先组合而非继承。这是 23 个模式背后最核心的共性原则。

</GlossaryItem>
