## 直觉引入

想象一个超市的货架整理。如果每次都检查所有货架（全堆扫描），效率极低。聪明的做法是分区管理：新上架的商品（Gen0）变动最频繁，先检查这层；存活一段时间的搬到中间层（Gen1）；长期商品放最上层（Gen2）。这就是 GC 分代回收的核心思想——新对象死得快，老对象活得久。

## 概念讲解

### 分代回收

<Term def="GC 将堆分为 Gen0/Gen1/Gen2 三代，新对象分配在 Gen0，存活后逐代晋升，优先回收最年轻的代。">
CLR 将托管堆分为三代：**Gen0**、**Gen1**、**Gen2**，加上**LOH**（大对象堆）。

新对象分配在 Gen0。Gen0 预算最小（通常几 MB），回收最快（只扫描少量新对象）。Gen0 回收时，存活对象晋升到 Gen1。Gen1 回收时，存活对象晋升到 Gen2。Gen2 回收（Full GC）扫描整个堆，代价最高。

分代假设：**新对象大概率很快变垃圾**（弱分代假设），**老对象大概率继续存活**（强分代假设）。基于此，GC 优先回收 Gen0，避免每次都扫描全堆，大幅降低回收成本。
</Term>

### 标记-清除-压缩

<Term def="GC 回收的三阶段：标记可达对象、清除不可达对象、压缩存活对象消除碎片。">
一次 GC 回收经历三个阶段：

1. **标记（Mark）**：从**根**（栈变量、静态字段、CPU 寄存器、GC 句柄）出发，遍历整个引用图，标记所有可达对象。可达 = 存活，不可达 = 垃圾。

2. **清除（Sweep）**：遍历堆中所有对象，未被标记的视为垃圾，释放其内存为空闲空间。

3. **压缩（Compact）**：将存活对象向堆的一端移动，消除碎片，更新所有引用地址。**Gen0/Gen1 总是压缩**，**Gen2 和 LOH 默认不压缩**（移动成本太高）。

压缩是 GC 最昂贵的操作——需要移动对象、更新所有引用指针、暂停所有线程（Stop-The-World）。
</Term>

## 代码对照

```csharp
// 减少分配：用 struct 避免堆分配
public struct Point  // 值类型，栈分配或内联
{
    public int X, Y;
}

// 池化复用：用 ArrayPool 避免 LOH 分配
var pool = ArrayPool<byte>.Shared;
byte[] buffer = pool.Rent(1024);  // 租用（可能 >1024）
try {
    // 使用 buffer...
}
finally {
    pool.Return(buffer);  // 归还复用，不进 GC
}

// Span 零拷贝切片，避免 Substring 分配
string text = "Hello, World";
ReadOnlySpan<char> slice = text.AsSpan(7, 5);  // "World"，零分配
```

## 常见误区

<Callout type="trap">
**误区：GC.Collect() 应该手动调用来释放内存**
手动 GC.Collect() 几乎总是反模式。它会触发 Full GC（代价最高），而且 GC 的自适应调度会被打乱。正确的做法是减少分配量，让 GC 按自己的节奏回收。只有在确认内存泄漏后作为诊断手段临时使用。
</Callout>

<Callout type="trap">
**误区：Gen2 对象不会影响性能**
Gen2 对象每次回收都要被扫描（Full GC），且可能不压缩导致碎片。大量 Gen2 对象意味着频繁 Full GC 和碎片化。应通过缩短对象生命周期避免晋升到 Gen2。
</Callout>

<Exercises>
**问题 1**：为什么 Gen0 回收比 Full GC 快得多？

<Answer>
Gen0 回收只扫描 Gen0 中的少量新对象（通常几 MB），而 Full GC 扫描整个堆（Gen0+Gen1+Gen2+LOH，可能数 GB）。扫描量差异巨大。此外 Gen0 总是压缩（对象少移动快），Gen2 可能不压缩但扫描量大。分代假设让 GC 大部分时候只做 Gen0 回收。
</Answer>

**问题 2**：什么情况下对象会从 Gen0 直接跳到 Gen2？

<Answer>
大对象（>=85000 字节）直接分配在 LOH，而 LOH 在 GC 视角下属 Gen2。所以 `new byte[100000]` 创建的对象一开始就在 Gen2/LOH，回收需要 Full GC。这就是为什么要用 ArrayPool 租用大数组而非反复 new。
</Answer>

</Exercises>

<Glossary>
<GlossaryItem term="分代假设">
新对象大概率很快变垃圾（弱分代），老对象大概率继续存活（强分代）。GC 据此优先回收 Gen0。
</GlossaryItem>
<GlossaryItem term="根（Root）">
GC 遍历的起点，包括栈变量、静态字段、CPU 寄存器、GC 句柄。从根可达的对象是存活的。
</GlossaryItem>
<GlossaryItem term="压缩（Compact）">
将存活对象向堆一端移动消除碎片，更新所有引用地址。Gen0/1 总是压缩，Gen2/LOH 默认不压缩。
</GlossaryItem>
<GlossaryItem term="Full GC">
扫描整个堆（含 Gen2 和 LOH）的回收，代价最高。触发条件包括 Gen2 预算用尽、LOH 预算用尽、显式 GC.Collect。
</GlossaryItem>
</Glossary>
