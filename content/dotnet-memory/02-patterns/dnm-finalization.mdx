## 直觉引入

想象仓库管理员（GC）发现一个货箱上贴着「销毁前需特殊处理」的标签（Finalizer）。管理员不能直接扔掉，而是先把它搬到「待处理区」（freachable 队列），等专门的清理工（终结器线程）来处理。处理完后，管理员下次巡查时才真正回收——这就需要两次巡查（两次 GC）。

## 概念讲解

### Finalizer 生命周期

<Term def="Finalizer 是 CLR 在 GC 回收对象前自动调用的清理方法。有 Finalizer 的对象需两次 GC：先移入 freachable 队列等待终结，再第二次 GC 回收。">
Finalizer（C# 语法 `~ClassName()`）与 C++ 析构函数有本质区别：
1. **不确定性**：C++ 析构在离开作用域时确定性调用；Finalizer 由 GC 在不确定时间调用
2. **异步**：C++ 析构在当前线程同步执行；Finalizer 在专用终结器线程异步执行
3. **角色**：C++ 析构是主要释放机制；Finalizer 只应作安全网

有 Finalizer 的对象需**两次 GC**：
1. 第一次 GC：发现不可达但有 Finalizer → 移入 freachable 队列（队列本身是根，使对象重新可达）
2. 终结器线程：从队列取出调用 Finalizer
3. 第二次 GC：对象真正不可达，回收内存

代价：内存延迟释放 + 两次 GC 开销 + 终结器线程是单线程（瓶颈）。
</Term>

### Dispose 模式

<Term def="标准 Dispose 模式通过 Dispose(bool disposing) 区分主动释放和 GC 终结，用 GC.SuppressFinalize 取消不必要的 Finalizer。">
标准 Dispose 模式：
```csharp
public class Resource : IDisposable {
  private bool _disposed;
  public void Dispose() { Dispose(true); GC.SuppressFinalize(this); }
  protected virtual void Dispose(bool disposing) {
    if (_disposed) return;
    if (disposing) { /* 释放托管资源 */ }
    /* 释放非托管资源 */
    _disposed = true;
  }
  ~Resource() { Dispose(false); }
}
```

`disposing` 参数含义：
- **true**：由 Dispose()/using 触发，其他托管对象可能还存活，可安全访问
- **false**：由 Finalizer 触发，其他托管对象可能已被回收，不能访问托管对象，只清非托管

`GC.SuppressFinalize(this)` 在手动 Dispose 后取消 Finalizer，避免不必要的两次 GC。
</Term>

## 代码对照

```csharp
// 标准 Dispose 模式：同时持有托管和非托管资源
public class MixedResource : IDisposable {
    private IntPtr _nativeHandle;  // 非托管资源
    private FileStream _stream;    // 托管资源
    private bool _disposed;

    // 公共 Dispose（开发者调用）
    public void Dispose() {
        Dispose(true);
        GC.SuppressFinalize(this); // 取消 Finalizer 避免两次 GC
    }

    // 受保护虚方法（子类可重写）
    protected virtual void Dispose(bool disposing) {
        if (_disposed) return;

        if (disposing) {
            // disposing=true: 主动调用，托管对象还活着
            _stream?.Dispose();
        }
        // 无论 disposing 值，都清非托管资源
        if (_nativeHandle != IntPtr.Zero) {
            NativeApi.CloseHandle(_nativeHandle);
            _nativeHandle = IntPtr.Zero;
        }
        _disposed = true;
    }

    // 安全网：如果开发者忘记 Dispose，GC 会调 Finalizer
    ~MixedResource() {
        Dispose(false); // false: 不碰 _stream（可能已回收）
    }
}
```

## 常见误区

<Callout type="trap">
**误区：Finalizer 可以替代 Dispose**
Finalizer 不确定性调用（可能几秒后也可能几分钟后），期间资源一直占用。且需两次 GC 回收。Finalizer 只应作安全网（开发者忘记 Dispose 时兜底），主要释放必须通过 Dispose。加 SuppressFinalize 确保 Dispose 后不再调 Finalizer。
</Callout>

<Callout type="trap">
**误区：Dispose(false) 中可以访问托管对象**
Dispose(false) 由 Finalizer 在终结器线程调用，此时 GC 正在回收，其他托管对象可能已被回收或正在被回收。访问它们可能导致未定义行为。Dispose(false) 中只能释放非托管资源（IntPtr 句柄等）。
</Callout>

<Exercises>
**问题 1**：为什么有 Finalizer 的对象需要两次 GC 才能回收？

<Answer>
第一次 GC 发现对象不可达但有 Finalizer，移入 freachable 队列。freachable 队列本身是根使对象重新可达。终结器线程从队列取出调用 Finalizer，完成后对象才真正不可达。第二次 GC 才回收内存。代价：延迟释放+两次 GC+单线程终结器瓶颈。
</Answer>

**问题 2**：Dispose(bool disposing) 的参数 true 和 false 分别在什么时候传入？各能做什么？

<Answer>
true：由 Dispose()/using 主动触发，其他托管对象可能还存活可安全访问释放。false：由 Finalizer(~ClassName) 触发，GC 正在回收其他托管对象可能已回收不能安全访问，只能释放非托管资源。SuppressFinalize 在 Dispose 后调用取消 Finalizer 避免两次 GC。
</Answer>

</Exercises>

<Glossary>
<GlossaryItem term="Finalizer">
CLR 在 GC 回收对象前自动调用的清理方法（~ClassName()），不确定性异步执行，需两次 GC。
</GlossaryItem>
<GlossaryItem term="freachable 队列">
终结化可达队列，存放待调用 Finalizer 的对象。队列本身是 GC 根，使对象重新可达。
</GlossaryItem>
<GlossaryItem term="Dispose 模式">
IDisposable + Finalizer 标准模式，Dispose(bool) 区分主动释放和 GC 终结，SuppressFinalize 取消 Finalizer。
</GlossaryItem>
<GlossaryItem term="GC.SuppressFinalize">
通知 GC 不再调用该对象的 Finalizer。在 Dispose() 后调用，避免不必要的两次 GC。
</GlossaryItem>
</Glossary>
