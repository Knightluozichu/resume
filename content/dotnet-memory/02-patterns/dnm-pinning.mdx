## 直觉引入

想象仓库管理员（GC）在整理货架（压缩），突然发现有些货箱上贴着「请勿移动」的标签（固定对象）。管理员只能绕过这些箱子，结果箱子之间的空隙无法合并。固定对象就像这些贴了标签的箱子——它们钉住了碎片，让整理变得困难。

## 概念讲解

### 固定场景与原理

<Term def="对象固定（Pinning）将托管堆对象标记为不可移动，防止 GC 压缩改变其地址。用于 P/Invoke 和 COM 互操作。">
需要固定的场景：将托管对象地址传给非托管代码（P/Invoke、COM 互操作）。非托管代码持有一个指针，如果 GC 移动了对象，指针就变成野指针。

固定方式：
1. **fixed 语句**：`fixed (byte* p = &arr[0]) { ... }`，作用域内对象不可移动
2. **GCHandleType.Pinned**：`GCHandle.Alloc(obj, GCHandleType.Pinned)`，长期固定
3. **fixed 字段**：`fixed byte[16] buffer` 嵌入 struct

原理：在对象头设置固定标记（或使用固定句柄表），GC 看到标记后跳过该对象不移动。作用域结束后清除标记。
</Term>

### 对 GC 压缩的影响

<Term def="固定对象不可移动，GC 压缩时必须跳过，导致碎片空洞无法合并。大量分散的固定对象严重降低压缩效率。">
GC 压缩时移动存活对象整理碎片。但固定对象不能移动，GC 必须跳过。如果固定对象分散在堆中，它们像钉子一样把碎片钉住——固定对象之间的空闲空间无法合并。

影响程度取决于固定模式：
- **短期固定**（fixed 语句几行代码）：影响小，对象很快解除固定
- **长期固定**（GCHandleType.Pinned 持续整个对象生命周期）：严重阻碍压缩
- **固定抖动**（循环中反复 fixed/unfixed 同一对象）：产生大量碎片

优化策略：1.缩短 fixed 作用域。2.用非托管内存（Marshal.AllocHGlobal）完全绕过托管堆。3.集中固定区域减少碎片分散。4..NET 5+ 用 [LibraryImport] 源生成器自动处理。
</Term>

## 代码对照

```csharp
// 场景：P/Invoke 传 byte[] 给 C 函数
[DllImport("nativelib")]
extern static unsafe void Process(byte* data, int length);

// 问题代码：长期固定
var handle = GCHandle.Alloc(buffer, GCHandleType.Pinned);
try {
    Process((byte*)handle.AddrOfPinnedObject(), buffer.Length);
} finally { handle.Free(); }

// 优化1：短期 fixed（作用域结束后自动解除）
unsafe {
    fixed (byte* p = buffer) {
        Process(p, buffer.Length); // 作用域内固定
    } // 离开作用域自动解除
}

// 优化2：非托管内存（完全绕过托管堆）
IntPtr nativeBuf = Marshal.AllocHGlobal(1024);
try {
    Process((byte*)nativeBuf, 1024);
} finally { Marshal.FreeHGlobal(nativeBuf); }

// 优化3：fixed buffer 嵌入 struct（固定在对象内）
struct Header { fixed byte signature[16]; }
```

## 常见误区

<Callout type="trap">
**误区：fixed 语句没有性能影响**
fixed 有隐性成本：1.设置/清除固定标记。2.固定期间该堆区域无法压缩。3.循环中反复 fixed 产生固定抖动。短期 fixed 影响小，但长期或高频固定会阻碍 GC 压缩导致碎片化。
</Callout>

<Callout type="trap">
**误区：所有 P/Invoke 都需要手动 fixed**
.NET 的 P/Invoke marshaler 会自动固定 blittable 类型（如 byte[]）。只有需要直接传指针（unsafe）时才需手动 fixed。.NET 5+ 的 [LibraryImport] 源生成器在编译期生成固定代码，比手动 fixed 更高效。
</Callout>

<Exercises>
**问题 1**：为什么固定对象会阻碍 GC 压缩？

<Answer>
GC 压缩通过移动存活对象整理碎片，但固定对象不可移动。如果固定对象分散在堆中，它们之间的空闲空间无法被合并——像钉子钉住碎片。即使 Gen0/Gen1 本应总是压缩，固定对象也会导致它们碎片化。
</Answer>

**问题 2**：设计高性能 P/Invoke 缓冲区方案避免频繁固定造成碎片。

<Answer>
方案：1.预分配大 byte[] 用 GCHandleType.Pinned 长期固定一次（避免反复 pin/unpin）。2.从池中租用传指针用完归还。3.集中固定在一块区域减少碎片分散。4.或直接用 Marshal.AllocHGlobal 分配非托管内存完全绕过托管堆用 Span 包装。5..NET 5+ 用 [LibraryImport] 源生成器自动处理固定。
</Answer>

</Exercises>

<Glossary>
<GlossaryItem term="Pinning（固定）">
将托管堆对象标记为不可移动，防止 GC 压缩改变地址。用于 P/Invoke 和 COM 互操作。
</GlossaryItem>
<GlossaryItem term="fixed 语句">
C# 语法，fixed (T* p = &amp;obj) &#123; ... &#125; 在作用域内固定对象，离开后自动解除。
</GlossaryItem>
<GlossaryItem term="GCHandleType.Pinned">
长期固定句柄，GCHandle.Alloc(obj, Pinned) 持续固定直到 Free。
</GlossaryItem>
<GlossaryItem term="pin thrashing（固定抖动）">
循环中反复 fixed/unfixed 同一对象产生大量碎片。应避免或用长期固定替代。
</GlossaryItem>
