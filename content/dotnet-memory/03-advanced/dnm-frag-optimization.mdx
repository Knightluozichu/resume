## 直觉引入

内存碎片就像一个被反复装卸的货架——货物大小不一，搬走后留下的空隙放不下新货。解决方法是：用标准尺寸的箱子（struct 统一大小）、用可伸缩的隔板（Span 零拷贝切片）、或者直接用仓库外的空间（非托管内存）完全绕过货架管理。

## 概念讲解

### 碎片类型与 struct 优化

<Term def="外部碎片=空闲块不连续，内部碎片=对齐填充浪费。struct 是值类型栈分配不进堆，减少 GC 压力。">
碎片分两种：
- **外部碎片**：堆中空闲块不连续，总空闲够但连续不够
- **内部碎片**：对象实际占用大于请求（对齐填充）

GC 压缩解决外部碎片（移动对象合并空闲块）。LOH 不压缩是外部碎片的主要来源。

**struct 优化**：struct 是值类型，局部变量在栈上分配（不进堆），作为字段内联在包含对象中。用 struct 替代高频创建的小 class 可避免 Gen0 堆分配。代价：大 struct 按值复制成本高（用 ref/in 传递），装箱会进堆（避免 object/接口转换）。
</Term>

### Span/Memory 零拷贝

<Term def="Span<T> 是连续内存的栈上视图（ref struct），零拷贝切片替代 Substring。Memory<T> 是堆安全版本可跨 await。">
**Span<T>** 是对连续内存的栈上视图，可以指向数组、字符串、栈内存（stackalloc）或非托管内存，零拷贝切片：
- `text.AsSpan(7, 5)` 替代 `text.Substring(7, 5)`（Substring 分配新字符串）
- `span.Slice()` 不分配新内存

Span<T> 是 **ref struct**，只能存在栈上——不能做字段、不能跨 await。

**Memory<T>** 是堆安全版本，可存入字段、跨 await，通过 `.Span` 属性获取 Span<T>。

选择原则：热路径用 Span<T>（零开销），异步场景用 Memory<T>。
</Term>

## 代码对照

```csharp
// 1. struct 替代 class 减少堆分配
public struct Point { public int X, Y; }  // 栈分配
// vs class Point（每次 new 进堆）

// 2. Span 零拷贝切片
string text = "Hello, World";
ReadOnlySpan<char> world = text.AsSpan(7, 5); // 零分配
// vs text.Substring(7, 5) 分配新 string

// 3. stackalloc 栈上分配小数组
Span<byte> buf = stackalloc byte[256]; // 不进堆

// 4. 零 GC 分配日志缓冲区（非托管内存 + Span + 池化）
class PooledLogBuffer {
  private static readonly ConcurrentQueue<IntPtr> Pool = new();
  
  public static (IntPtr ptr, Span<byte> span) Rent(int size) {
    if (!Pool.TryDequeue(out var ptr))
      ptr = Marshal.AllocHGlobal(size); // 非托管，不进堆
    return (ptr, new Span<byte>((void*)ptr, size));
  }
  
  public static void Return(IntPtr ptr) => Pool.Enqueue(ptr);
}
```

## 常见误区

<Callout type="trap">
**误区：struct 总是比 class 快**
大 struct 按值复制成本高（每次传参复制整个 struct）。需要用 ref/in 传递避免复制。struct 装箱（转为 object/接口）会进堆产生 GC——比 class 更差。struct 适合小的、不可变的值语义类型（如 Point、DateTime）。大的或需要多态的用 class。
</Callout>

<Callout type="trap">
**误区：Span<T> 可以在任何地方使用**
Span<T> 是 ref struct，有限制：不能做类的字段、不能跨 await、不能装箱、不能作为泛型参数。这些限制是为了保证 Span 指向的内存不会被 GC 移动。需要跨 await 或存字段时用 Memory<T>。
</Callout>

<Exercises>
**问题 1**：struct 替代 class 如何减少 GC 压力？有什么代价？

<Answer>
struct 是值类型栈分配或内联不进堆不产生 GC。class 每次 new 进堆产生 GC 负担。代价：大 struct 按值复制成本高需 ref/in 传递；装箱进堆要避免；不能继承；struct 数组连续内存缓存友好但 List<struct> 扩容复制整块。
</Answer>

**问题 2**：设计零 GC 分配且线程安全的日志缓冲区。

<Answer>
方案：1.预分配非托管缓冲区(Marshal.AllocHGlobal)用 ConcurrentQueue 池化。2.写日志时 TryDequeue 租用用 Span<byte> 写入失败时 AllocHGlobal 新分配不进托管堆。3.写满后 P/Invoke 写文件归还池。4.Span 指向非托管内存 ref unsafe 写入零托管分配。5.每线程租用独立缓冲区无共享。6.池上限超出直接 FreeHGlobal。核心：池化+非托管+Span=零 GC。
</Answer>

</Exercises>

<Glossary>
<GlossaryItem term="外部碎片">
堆中空闲块不连续导致无法分配。GC 压缩通过移动对象合并空闲块解决。LOH 不压缩是主要来源。
</GlossaryItem>
<GlossaryItem term="Span<T>">
连续内存的栈上视图（ref struct），零拷贝切片。不能做字段、不能跨 await。
</GlossaryItem>
<GlossaryItem term="Memory<T>">
Span<T> 的堆安全版本，可存入字段、跨 await。通过 .Span 属性获取 Span<T>。
</GlossaryItem>
<GlossaryItem term="stackalloc">
C# 关键字，在栈上分配小块内存，不进托管堆，方法返回时自动释放。
</GlossaryItem>
</Glossary>
