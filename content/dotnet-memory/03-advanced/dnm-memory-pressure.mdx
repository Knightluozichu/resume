## 直觉引入

GC 是仓库管理员，但它只能看到仓库（托管堆）里的货物。如果你偷偷在外面租了仓库（非托管内存 malloc），管理员根本不知道——它以为仓库很空不需要清理。AddMemoryPressure 就是告诉管理员「我还在外面占了地方」，让它在调度清理时考虑这部分开销。

## 概念讲解

### 非托管内存与 GC 感知

<Term def="GC 只感知托管堆大小。非托管内存（malloc/AllocHGlobal）对 GC 不可见，需用 AddMemoryPressure 告知。">
当代码通过 P/Invoke 调用 C 库的 `malloc` 分配大量非托管内存时，GC 感知不到——它只看到托管堆的大小。如果分配了 2GB 非托管内存但托管堆只有 100MB，GC 认为内存充足不触发回收。

后果：
1. 托管对象不及时回收（GC 没触发），内存泄漏表象
2. 非托管内存持续增长直到 OOM
3. GC 调度策略失准

解决方案：`GC.AddMemoryPressure(bytes)` 告诉 GC「额外占用 bytes 非托管内存」，让 GC 在调度回收时考虑。`GC.RemoveMemoryPressure(bytes)` 在释放后调用恢复基准。
</Term>

### SafeHandle 自动管理

<Term def="SafeHandle 是 .NET 提供的非托管句柄封装基类，自动管理 Finalizer、引用计数和内存压力。">
SafeHandle 优势：
1. **自动 Finalizer**：保证 `ReleaseHandle()` 在 GC 回收时调用释放非托管资源
2. **自动引用计数**：防止 P/Invoke 调用期间句柄被释放
3. **自动内存压力**：内部自动调用 AddMemoryPressure/RemoveMemoryPressure
4. **比 IntPtr 安全**：避免句柄被提前释放导致野指针

使用：继承 `SafeHandleZeroOrMinusOneIsInvalid`，重写 `ReleaseHandle()`：
```csharp
class MyHandle : SafeHandleZeroOrMinusOneIsInvalid {
  public MyHandle() : base(true) {}
  protected override bool ReleaseHandle() {
    return NativeApi.CloseHandle(handle);
  }
}
```
.NET 推荐用 SafeHandle 替代直接持有 IntPtr + 手动 Finalizer。
</Term>

## 代码对照

```csharp
// 问题：P/Invoke 分配大块非托管内存，GC 感知不到
class BadImageBuffer : IDisposable {
  private IntPtr _handle;
  
  public BadImageBuffer(int size) {
    _handle = NativeMalloc(size); // GC 看不到这 10MB
    // GC 以为只有几十字节的 IntPtr 在堆上
  }
  
  public void Dispose() {
    NativeFree(_handle);
    // GC 不知道非托管内存已释放
  }
}

// 正确：用 SafeHandle + AddMemoryPressure
class GoodImageBuffer : SafeHandleZeroOrMinusOneIsInvalid {
  private int _size;
  
  public GoodImageBuffer(int size) : base(true) {
    _size = size;
    SetHandle(NativeMalloc(size));
    GC.AddMemoryPressure(size); // 告知 GC 额外占用
  }
  
  protected override bool ReleaseHandle() {
    NativeFree(handle);
    GC.RemoveMemoryPressure(_size); // 恢复
    return true;
  }
}
```

## 常见误区

<Callout type="trap">
**误区：AddMemoryPressure 和 RemoveMemoryPressure 的字节数必须精确**
不需要精确到字节，给出近似值即可。GC 用这个值调整回收策略，不是精确记账。但 Add 和 Remove 的字节数应该匹配——Add 了 10MB 就要 Remove 10MB，否则 GC 的基准会偏移。
</Callout>

<Callout type="trap">
**误区：SafeHandle 会自动处理所有非托管资源**
SafeHandle 只自动管理句柄的生命周期（ReleaseHandle）和内存压力。具体的释放逻辑（调用哪个 free/close 函数）仍需你在 ReleaseHandle 中实现。SafeHandle 是框架不是魔法——它保证 ReleaseHandle 会被调用，但怎么释放由你决定。
</Callout>

<Exercises>
**问题 1**：为什么 GC 需要知道非托管内存使用量？不告知会怎样？

<Answer>
GC 回收触发基于托管堆预算和系统内存。若分配 2GB 非托管但托管堆 100MB，GC 认为内存充足不回收。后果：托管对象不及时回收内存泄漏表象，非托管增长到 OOM，GC 调度失准。告知后 GC 在压力增大时更积极回收触发 Dispose/Finalizer 释放非托管。
</Answer>

**问题 2**：SafeHandle 相比手动 IntPtr + AddMemoryPressure 有什么优势？

<Answer>
1.自动 Finalizer 保证 ReleaseHandle 在 GC 回收时调用。2.自动引用计数防止 P/Invoke 期间句柄被释放。3.自动管理 AddMemoryPressure/RemoveMemoryPressure。4.比 IntPtr+手动 Finalizer 更安全避免野指针。推荐用 SafeHandle 替代直接持有 IntPtr。
</Answer>

</Exercises>
