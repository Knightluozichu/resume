## 为什么最终输出正确仍然不够

<Term def="语言处理器连接“冻结源句”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">语言处理器</Term>、<Term def="编译器阶段连接“切分阶段”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">编译器阶段</Term>、<Term def="符号表连接“保存符号表”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">符号表</Term>、<Term def="趟连接“比较中间表示”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">趟</Term>、<Term def="环境与状态连接“执行目标代码”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">环境与状态</Term>
共同构成本页坐标。从语言处理器、编译器阶段和程序设计语言语义三个尺度建立全书坐标，并用同一条赋值语句追踪词法、语法、语义、IR、优化和目标代码。

编译器是一串互相依赖的转换。错误的扫描器可能恰好产生可分析的词法单元，错误的语法树可能被后续语义动作意外修补，错误的数据流事实可能只在冷路径暴露，违反机器约束的调度也可能在当前样本中碰巧执行。因此必须保存阶段输入、输出和不变量，定位第一处偏离，不能把单个样例跑通当作证明。

## 核心模型与实验账本

实验固定源程序、编译器提交、中间表示格式、目标机模型、优化级别和随机种子。前端保存词法单元、推导、语法树、属性值与类型环境；中端保存基本块、控制流图、支配关系、数据流集合和每次变换前后的IR；后端保存模式覆盖、依赖图、发射周期、寄存器映射、溢出代码与最终指令。每份产物都带生成方式、退出状态和摘要值。

样本分成四组。正常样本证明主路径，边界样本覆盖空输入、深嵌套、二义性、不可归约流图、寄存器压力、长延迟、别名和动态调用；失败样本只破坏一个语法、类型、数据流或机器约束；优化样本同时保存变换前后版本，并用解释执行或差分执行核对可观察行为。

诊断记录阶段、源位置或IR位置、实际状态、期望状态、相关前驱和首要根因。某阶段失败后不得继续消费旧缓存伪造下游结果；分析事实被变换失效时，必须显式重算或证明仍然有效。性能结论与正确性结论分开：前者记录静态成本、动态计数、代码大小和运行环境，后者要求语义与全部约束成立。

目录项进入追溯矩阵后，至少关联一个输入、一个算法前提、一份结构化产物、一个失败对照和一个回归断言。跨章接口同时记录生产者和消费者，这样既能发现“提到概念却没有验证”的空洞覆盖，也能在实现变化后只重放真正受影响的实验。

## 可运行的最小骨架

```text
position = initial + rate * 60
```

```text
id = id + id * num
<id, position> <=> <id, initial> + <id, rate> * <num, 60>
```

```text
source -> tokens -> syntax tree -> IR -> optimized IR -> target
```

## 常见误区

<Callout type="trap">
  **只看最终结果：**
  没有词法单元、语法树、属性依赖、CFG、数据流集合、调度表和寄存器映射，就无法把错误归因到具体阶段，也无法证明中间变换保持语义。
</Callout>

<Callout type="trap">
  **先变换再补条件：**
  优化、调度、并行化和过程间分析必须先证明前提；任何会令支配、活跃、别名、依赖或调用图失效的修改，都要触发明确重算。
</Callout>

## 四类样本与通过条件

| 样本 | 单一变量               | 必查证据         | 通过条件         |
| ---- | ---------------------- | ---------------- | ---------------- |
| 正常 | 一个最小语言或机器功能 | 全阶段快照       | 与预测一致       |
| 边界 | 深度、宽度、延迟或压力 | 临界分支和成本   | 边界可解释       |
| 失败 | 一个文法、事实或约束   | 首错与下游停止   | 不产出伪结果     |
| 优化 | 一个变换或策略         | 前后IR与差分执行 | 等价且收益可解释 |
