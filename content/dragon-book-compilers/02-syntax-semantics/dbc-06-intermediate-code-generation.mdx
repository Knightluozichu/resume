## 为什么最终输出正确仍然不够

<Term def="DAG连接“构造表达式DAG”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">DAG</Term>、<Term def="三地址代码连接“发射三地址码”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">三地址代码</Term>、<Term def="SSA连接“检查并转换类型”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">SSA</Term>、<Term def="类型检查连接“翻译布尔控制流”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">类型检查</Term>、<Term def="回填连接“回填跳转目标”阶段的输入、算法前提、结构化结果、成本和第一处失败证据。">回填</Term>
共同构成本页坐标。把类型、声明、表达式、布尔控制流、回填和过程调用统一翻译为可分析的语法树、DAG、三地址代码与SSA边界。

编译器是一串互相依赖的转换。错误的扫描器可能恰好产生可分析的词法单元，错误的语法树可能被后续语义动作意外修补，错误的数据流事实可能只在冷路径暴露，违反机器约束的调度也可能在当前样本中碰巧执行。因此必须保存阶段输入、输出和不变量，定位第一处偏离，不能把单个样例跑通当作证明。

## 常见误区

<Callout type="trap">
  **只看最终结果：**
  没有词法单元、语法树、属性依赖、CFG、数据流集合、调度表和寄存器映射，就无法把错误归因到具体阶段，也无法证明中间变换保持语义。
</Callout>

<Callout type="trap">
  **先变换再补条件：**
  优化、调度、并行化和过程间分析必须先证明前提；任何会令支配、活跃、别名、依赖或调用图失效的修改，都要触发明确重算。
</Callout>

## 四类样本与通过条件

| 样本 | 单一变量               | 必查证据         | 通过条件         |
| ---- | ---------------------- | ---------------- | ---------------- |
| 正常 | 一个最小语言或机器功能 | 全阶段快照       | 与预测一致       |
| 边界 | 深度、宽度、延迟或压力 | 临界分支和成本   | 边界可解释       |
| 失败 | 一个文法、事实或约束   | 首错与下游停止   | 不产出伪结果     |
| 优化 | 一个变换或策略         | 前后IR与差分执行 | 等价且收益可解释 |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终程序运行成功验收第6章 中间代码生成？

<Answer>
  最终行为可能隐藏错误词法单元、树结构、属性值、数据流事实、依赖边或机器约束。应保存每层结构化产物，定位第一处分叉，并从固定源程序清理重建。
</Answer>

**问题 2** 如何把“检查并转换类型”变成可回归实验？

<Answer>
  固定输入、实现版本、中间表示和目标模型，先预测DAG与三地址代码的中间状态，只改变一个条件，并保留正常、边界、失败和优化四类样本。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  每个临时值和跳转目标均有定义，类型转换显式可查，数组地址遵守布局公式，控制流边与回填列表最终完全闭合。
  修复后必须清理旧产物，完整重建全部下游结果，并让历史样本回到基线。
</Answer>

</Exercises>
