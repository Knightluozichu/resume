## 语法制导翻译

语法分析只检查程序的结构是否合法，不关心语义。**语法制导翻译**（Syntax-Directed Translation）在 CFG 的基础上附加属性和语义动作，将语法分析与语义分析统一在一个框架中——这是龙书的核心概念之一。

### SDD 与 SDT

| 概念 | 全称 | 特点 |
|------|------|------|
| SDD | 语法制导定义 | 声明式，给文法符号绑定属性，用语义规则定义求值方式，不规定求值顺序 |
| SDT | 语法制导翻译方案 | 过程化，在产生式中嵌入语义动作 `{ action }`，是 SDD 的实现 |

## 综合属性与继承属性

属性分为两类，求值方向不同：

- **综合属性**（Synthesized）：由子节点属性计算，**自底向上**求值。LR 分析归约时自然计算。例如 `E.val = E1.val + T.val`。
- **继承属性**（Inherited）：由父节点和兄弟节点属性计算，**自顶向下**求值。需在 LL 分析或特定遍历中求值。例如 `T.inh = E.inh`。

### L 属性定义

如果 SDD 的每个继承属性只依赖**左侧兄弟节点**和**父节点**的属性，则称为 L 属性定义。L 属性定义保证依赖图无环且可**单遍求值**，是实际编译器最常用的形式。

<Callout type="info">

**综合属性天然适合 LR 分析**：归约时所有子节点属性已计算完毕，可直接计算父节点综合属性。继承属性需要额外的遍历或 LL 分析配合，实现更复杂。

</Callout>

## 属性依赖图与求值

在语法分析树中，每个属性是一个节点，属性间的求值依赖关系是边。若属性 $b$ 的计算依赖属性 $a$，则有一条 $a \to b$ 的边。

- **拓扑排序**：属性必须按依赖顺序求值——先算无依赖的，再算依赖已求值的
- **无环 = 可求值**：如果依赖图无环（DAG），则存在拓扑序，属性可全部求值
- **有环 = 不可求值**：属性循环依赖，该 SDD 不合法

## 符号表

**符号表**（Symbol Table）记录源程序中所有标识符的声明信息，供语义分析阶段查询。

### 符号表条目

| 字段 | 说明 |
|------|------|
| name | 标识符名 |
| type | 数据类型（int / float / array / pointer） |
| kind | 种类（变量 / 函数 / 类 / 参数） |
| scope | 所在作用域 |
| offset | 在活动记录中的偏移 |

### 嵌套作用域管理

每个作用域对应一张符号表，用**栈式结构**管理：

- 进入作用域 → push 新表
- 退出作用域 → pop
- 查表：先查当前（栈顶）作用域，再向外层逐级查找
- 找到第一个匹配即返回（实现**遮蔽**——内层同名声明遮蔽外层）

<Callout type="tip">

对于嵌套过程语言（如 Pascal），符号表还保存**访问链**指向外层过程的符号表，支持非局部变量的访问。C 语言无嵌套函数，非局部变量即全局变量，直接放静态区。

</Callout>

## 语义分析的核心任务

语义分析检查语法分析无法发现的**上下文相关错误**：

1. **类型检查**：操作数类型是否匹配
2. **中间代码生成**：AST → 三地址码
3. **作用域解析**：名字 → 声明绑定，遮蔽 / 重名检测
4. **一致性检查**：未声明变量、重复声明、参数个数匹配

这些检查依赖符号表和类型系统，是语法分析（只看结构）做不到的。

<GlossaryItem term="语法制导定义（SDD）">
声明式地给每个文法符号绑定属性，用语义规则定义属性求值方式，不规定求值顺序。综合属性自底向上，继承属性自顶向下。
</GlossaryItem>

<GlossaryItem term="语法制导翻译方案（SDT）">
在产生式中嵌入语义动作 `{ action }`，是 SDD 的过程化实现。L 属性定义的 SDT 可单遍求值。
</GlossaryItem>

<GlossaryItem term="综合属性">
由子节点属性计算的属性，自底向上求值，LR 分析归约时自然计算。
</GlossaryItem>

<GlossaryItem term="继承属性">
由父节点和兄弟节点属性计算的属性，自顶向下求值，L 属性定义限制其只依赖左侧兄弟。
</GlossaryItem>

<GlossaryItem term="属性依赖图">
语法分析树中属性间的求值依赖关系图，无环（DAG）时可拓扑排序求值，有环则 SDD 不可求值。
</GlossaryItem>

<GlossaryItem term="符号表">
记录标识符声明信息（name/type/kind/scope/offset）的数据结构，供语义分析查询，用栈式结构管理嵌套作用域。
</GlossaryItem>

### 问题 1

语法制导翻译（SDT）和语法制导定义（SDD）的区别是什么？综合属性和继承属性有何不同？

<Answer>

SDD（语法制导定义）：声明式地给每个文法符号绑定属性，用语义规则定义属性求值方式，不规定求值顺序。综合属性（Synthesized）：由子节点属性计算，自底向上求值，LR 分析归约时自然计算。继承属性（Inherited）：由父节点和兄弟节点属性计算，自顶向下求值，需在 LL 分析或特定遍历中求值。SDT（语法制导翻译方案）：在产生式中嵌入语义动作 `{ action }`，是 SDD 的过程化实现。L 属性定义：继承属性只依赖左侧兄弟和父节点，可单遍求值，是实际编译器最常用的形式。

</Answer>

### 问题 2

符号表的作用是什么？如何管理嵌套作用域？

<Answer>

符号表记录源程序中所有标识符的声明信息（name、type、kind、scope、offset 等），供语义分析阶段查询（类型检查、作用域解析、一致性检查）。嵌套作用域管理：每个作用域对应一张符号表，用栈式结构管理。进入作用域时 push 新表，退出时 pop。查表时从当前（栈顶）作用域开始向外层逐级查找，找到第一个匹配即返回（遮蔽内层同名声明）。对于嵌套过程语言（如 Pascal），符号表还保存访问链指向外层过程的符号表，支持非局部变量的访问。

</Answer>

### 问题 3

什么是属性依赖图？为什么需要拓扑排序？

<Answer>

属性依赖图：在语法分析树中，每个属性是一个节点，属性间的求值依赖关系是边（若属性 b 的计算依赖属性 a，则有一条 a→b 的边）。拓扑排序：属性必须按依赖顺序求值——先算无依赖的，再算依赖已求值的。如果依赖图无环（DAG），则存在拓扑序，属性可全部求值；如果有环，则该 SDD 不可求值（属性循环依赖）。L 属性定义保证依赖图无环且可单遍求值，是实际编译器使用 SDT 的基础。

</Answer>

### 问题 4

语义分析阶段需要检查哪些错误？举例说明。

<Answer>

语义分析检查语法分析无法发现的上下文相关错误：①未声明变量使用——引用未在符号表中登记的名字 ②重复声明——同一作用域内同名标识符多次声明 ③类型不匹配——如 `int x = "hello"` 将字符串赋给整型 ④参数不匹配——函数调用实参个数或类型与形参不符 ⑤作用域错误——在作用域外引用局部变量 ⑥控制流错误——如 break 出现在循环外。这些检查依赖符号表和类型系统，是语法分析做不到的。

</Answer>
