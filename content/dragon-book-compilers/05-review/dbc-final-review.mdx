## 端到端编译流程

编译器是一个分阶段翻译管道，每个阶段有明确的输入输出和职责边界，通过中间表示（IR）解耦前后端：

<DbcFinalReviewDiagram />

### 完整流水线

| 阶段 | 输入 | 输出 | 章节 |
|------|------|------|------|
| 词法分析 | 源码字符流 | Token 序列 | ch1 |
| 语法分析 | Token 序列 | AST | ch2 |
| 语义分析 | AST + 符号表 | 带注解 AST | ch3 |
| 类型检查 | 带注解 AST | 类型验证后的 AST | ch4 |
| 中间代码生成 | 类型验证 AST | IR（三地址码） | ch3 |
| 机器无关优化 | IR | 优化后 IR | ch7 |
| 代码生成 | 优化 IR + 流图 | 目标机器代码 | ch6 |
| 机器相关优化 | 目标代码 | 优化后目标代码 | ch8 |

## 前端：源码 → IR

前端关注**源语言**，将源码翻译为机器无关的 IR：

| 阶段 | 核心技术 | 形式基础 |
|------|---------|---------|
| 词法分析 | 正则 → NFA → DFA → Token | Chomsky 3 型文法 / 有限自动机 |
| 语法分析 | CFG → LL/LR → AST | Chomsky 2 型文法 / 下推自动机 |
| 语义分析 | SDT/SDD + 符号表 | 属性文法 / 依赖图 |
| 类型检查 | 类型规则 / 类型等价 | 类型系统 |

<Callout type="info">

**形式语言理论是龙书的理论根基**：正则表达式 ↔ 有限自动机（词法）、上下文无关文法 ↔ 下推自动机（语法）。这些理论保证了分析算法的正确性和可判定性。

</Callout>

## 中端：IR 优化

中端在 IR 层做**机器无关优化**，核心是数据流分析：

- **数据流分析框架**（四要素）：方向 D、值域 V（有限格）、传递函数 F、交汇运算 ∧
- **不动点迭代**：反复应用传递函数和交汇运算直到值不再变化
- **保守性**：宁可漏报优化机会也不能误报（改变语义）
- **收敛性**：有限格 + 单调函数 → 迭代必收敛

### 核心优化技术

| 技术 | 分析基础 | 效果 |
|------|---------|------|
| CSE | 可用表达式（前向交集） | 消除重复计算 |
| 常量传播 | 前向数据流 | 编译期求值 |
| DCE | 活跃变量（后向并集） | 删除无用代码 |
| 代码外提 | 循环识别 + 不变量分析 | 减少循环内计算 |
| 强度削弱 | 归纳变量分析 | 加法替代乘法 |

## 后端：IR → 机器码

后端关注**目标机器**，将 IR 转换为高效的目标代码：

| 阶段 | 核心技术 | 章节 |
|------|---------|------|
| 基本块与流图 | 首指令划分 + 控制流边 | ch6 |
| 寄存器分配 | 活跃分析 → 干扰图 → k 着色 | ch6 |
| 指令调度 | 数据依赖分析 → 列表调度 | ch8 |
| 寄存器合并 | 消除 move 指令 | ch8 |
| 缓存优化 | 循环分块 / 数据局部性 | ch8 |
| 窥孔优化 | 局部指令替换 | ch6 |

## 龙书核心思想

编译器 = **分阶段翻译管道**。核心优势：

1. **每阶段职责单一** — 便于独立设计、测试、优化和替换
2. **前后端独立演进** — 前端关注源语言，后端关注目标机器
3. **多语言×多平台复用** — M 个前端 + N 个后端共享一套 IR 和优化器
4. **优化复用** — IR 层优化只写一次即覆盖所有组合
5. **渐进式正确性** — 每阶段验证本阶段正确性

<Callout type="tip">

优化的核心是数据流分析（保守近似 + 不动点迭代），在不改变语义的前提下产出更快更短的代码。这是 GCC、LLVM 等工业级编译器的标准架构。

</Callout>

### 问题 1

请完整描述从源代码到目标代码的端到端编译流程，每个阶段的输入输出是什么？

<Answer>

①词法分析：输入源码字符流，输出 Token 序列（`<type, lexeme, attr>`）②语法分析：输入 Token 序列，输出 AST（抽象语法树）③语义分析：输入 AST + 符号表，输出带注解的 AST（属性已求值，类型已检查）④中间代码生成：输入带注解 AST，输出 IR（三地址码）⑤机器无关优化：输入 IR，输出优化后 IR（CSE/常量传播/循环优化后）⑥代码生成：输入优化 IR + 流图，输出目标机器代码（含寄存器分配）⑦机器相关优化：输入目标代码，输出优化后目标代码（指令调度/窥孔后）。全程通过 IR 解耦前后端，符号表贯穿前端。

</Answer>

### 问题 2

前端（词法→语法→语义→类型）各阶段如何衔接？形式语言理论在其中起什么作用？

<Answer>

衔接：词法分析用正则描述词法规则，输出 Token；语法分析用 CFG 描述语法规则，在 Token 上构建 AST；语义分析用 SDT/SDD 在 AST 上绑定属性、查符号表；类型检查用类型系统验证语义合法性。形式语言理论是龙书的理论根基：①正则表达式 ↔ 有限自动机（NFA/DFA）——描述词法，Chomsky 3 型文法 ②上下文无关文法（CFG）↔ 下推自动机——描述语法，Chomsky 2 型文法 ③LL/LR 分析是 CFG 的高效解析算法 ④语法制导翻译是 CFG + 属性的形式化框架。形式语言理论保证了分析算法的正确性和可判定性——哪些语言可解析、如何高效解析。

</Answer>

### 问题 3

数据流分析是优化的理论基础。请说明数据流分析框架的四要素，并说明如何保证保守性和收敛性。

<Answer>

四要素：①方向 D——前向或后向 ②值域 V——通常是有限格（如表达式集合的幂集）③传递函数 F——`OUT[b]=F_b(IN[b])`，描述块内如何变换 ④交汇运算 ∧——多前驱/后继如何合并（交集或并集）。保守性：分析结果必须是安全近似——宁可漏报优化机会（少优化）也不能误报（改变语义）。例如可用表达式用交集（所有前驱都可用才可用），偏向保守。收敛性：①值域是有限格，值只能沿格单调变化（每步或不变或上升）②传递函数和交汇运算是单调函数 ③单调函数在有限格上迭代必到达不动点（移动次数有限）。因此迭代一定终止，结果是保守的不动点解。

</Answer>

### 问题 4

龙书的核心思想是什么？编译器设计为什么采用分阶段解耦架构？

<Answer>

核心思想：编译器 = 分阶段翻译管道，每个阶段有明确的输入输出和职责边界，通过中间表示（IR）解耦前后端。分阶段解耦的优势：①每阶段职责单一——便于独立设计、测试、优化和替换 ②前后端独立演进——前端关注源语言（词法/语法/语义/类型），后端关注目标机器（代码生成/寄存器/调度），中端在 IR 层做机器无关优化 ③多语言×多平台复用——M 个前端 + N 个后端共享一套 IR 和优化器，避免 M×N 组合爆炸 ④优化复用——IR 层优化只写一次即覆盖所有语言和平台组合 ⑤渐进式正确性——每阶段验证本阶段正确性，最终保证整体正确。这是 GCC、LLVM 等工业级编译器的标准架构。

</Answer>
