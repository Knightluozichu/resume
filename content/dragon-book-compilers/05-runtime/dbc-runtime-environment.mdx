## 运行时存储组织

程序运行时，内存分为四个区域，各有不同的用途和生命周期：

| 区域 | 内容 | 生命周期 | 增长方向 |
|------|------|---------|---------|
| 代码区（Code） | 目标代码 | 整个程序 | 固定 |
| 静态区（Static） | 全局变量、静态变量 | 整个程序 | 固定 |
| 堆区（Heap） | 动态分配对象 | 手动/GC 管理 | 向上 |
| 栈区（Stack） | 活动记录 | 函数调用/返回自动 | 向下 |

堆和栈相向增长，中间是自由空间。

## 活动记录

每次函数调用在栈上分配一个**活动记录**（Activation Record，又称栈帧），包含：

| 字段 | 说明 |
|------|------|
| 返回值 | 函数的返回结果 |
| 实参 | 调用者传入的参数 |
| 控制链 | 指向调用者的活动记录 |
| 访问链 | 指向外层过程的活动记录（非局部变量访问） |
| 机器状态 | 保存的寄存器、返回地址 PC |
| 局部变量 | 函数内声明的变量 |
| 临时变量 | 编译器生成的临时值 |

### 函数调用过程

1. 在栈顶分配新活动记录
2. 保存调用者机器状态和返回地址
3. 传入实参
4. 设置控制链和访问链
5. 初始化局部变量
6. 跳转到函数体执行

返回时：将返回值写入调用者活动记录 → 恢复机器状态 → 弹出活动记录 → 跳转回返回地址。

<Callout type="info">

栈式分配的分配/释放都是 O(1)（只需移动栈指针），且无需 GC，适合生命周期与函数调用一致的数据。堆式分配灵活但开销大，适合生命周期不确定的对象。

</Callout>

## 非局部变量的访问

对于嵌套过程语言（如 Pascal），内层函数可以访问外层函数的变量。龙书介绍了两种策略：

### 访问链（Access Link）

每个活动记录含一个访问链，指向**词法外层**过程的活动记录。访问非局部变量时，沿访问链逐层向上查找，最坏 O(n)（n 为嵌套深度）。

- 优点：空间开销小（每帧一个指针）
- 缺点：访问深嵌套变量时需多次跳转

### Display 表

维护一个全局数组，第 i 个元素指向第 i 层嵌套过程的活动记录。访问第 d 层的非局部变量时直接 `display[d]` 取到，O(1) 访问。

- 优点：访问快 O(1)
- 缺点：空间开销大，每次调用/返回需更新 Display 表

<Callout type="tip">

C 语言无嵌套函数，非局部变量即全局变量，直接放静态区即可，无需访问链或 Display 表。Pascal、Ada 等支持嵌套过程的语言才需要这些机制。

</Callout>

## 栈式分配 vs 堆式分配

| 维度 | 栈式分配 | 堆式分配 |
|------|---------|---------|
| 分配/释放 | O(1)，移动栈指针 | 开销大，需查找空闲块 |
| 生命周期 | 与函数调用一致 | 任意时刻 |
| 管理 | 自动（push/pop） | 手动（malloc/free）或 GC |
| 适合 | 局部变量、参数 | 动态对象、可变长结构 |
| 缺点 | 不能返回栈上数据指针 | 内存泄漏、碎片 |

实际程序混合使用：栈放局部变量，堆放动态对象，静态区放全局变量。

<Glossary>

<GlossaryItem term="活动记录（Activation Record）">
函数调用时在栈上分配的数据帧，包含返回值、实参、控制链、访问链、机器状态、局部变量和临时变量。调用时 push，返回时 pop。
</GlossaryItem>

<GlossaryItem term="栈式分配">
活动记录在栈上分配，函数返回自动释放，O(1) 分配/释放，适合生命周期与函数调用一致的数据。
</GlossaryItem>

<GlossaryItem term="堆式分配">
由程序员（malloc/free）或 GC 管理生命周期的动态分配，数据可在任意时刻分配和释放，适合生命周期不确定的对象。
</GlossaryItem>

<GlossaryItem term="访问链（Access Link）">
活动记录中指向词法外层过程活动记录的指针，沿访问链逐层向上查找可访问非局部变量，最坏 O(n)。
</GlossaryItem>

<GlossaryItem term="Display 表">
全局数组，第 i 个元素指向第 i 层嵌套过程的活动记录，O(1) 访问任意外层变量，空间换时间。
</GlossaryItem>

</Glossary>

### 问题 1

运行时内存分为哪些区域？各自存储什么内容？

<Answer>

运行时内存分四区：①代码区（Code）——存放编译后的目标代码，只读 ②静态区（Static/Data）——存放全局变量和静态变量，地址在编译期确定，生命周期为整个程序 ③堆区（Heap）——存放动态分配的对象（malloc/new），向上增长，由程序员或 GC 管理释放 ④栈区（Stack）——存放函数调用的活动记录，向下增长，调用时 push、返回时 pop，自动管理。堆和栈相向增长，中间是自由空间。

</Answer>

### 问题 2

活动记录（Activation Record）包含哪些字段？每次函数调用时发生了什么？

<Answer>

活动记录字段：①返回值 ②实参（actual parameters）③控制链（指向调用者的活动记录）④访问链（access link，指向外层过程活动记录，用于非局部变量访问）⑤机器状态（保存的寄存器、返回地址 PC）⑥局部变量 ⑦临时变量。函数调用时：①在栈顶分配新活动记录 ②保存调用者机器状态和返回地址 ③传入实参 ④设置控制链和访问链 ⑤初始化局部变量 ⑥跳转到函数体执行。函数返回时：①将返回值写入调用者活动记录 ②恢复调用者机器状态 ③弹出当前活动记录 ④跳转回返回地址。

</Answer>

### 问题 3

访问链和 Display 表如何实现非局部变量的访问？各有何优缺点？

<Answer>

访问链（Access Link）：每个活动记录含一个访问链，指向词法外层过程的活动记录。访问非局部变量时，沿访问链逐层向上查找，最坏 O(n)（n 为嵌套深度）。优点：空间开销小（每帧一个指针）。适合嵌套深度不大的语言（如 Pascal）。Display 表：维护一个全局数组，第 i 个元素指向第 i 层嵌套过程的活动记录。访问第 d 层的非局部变量时直接 display[d] 取到，O(1) 访问。但每次过程调用/返回需更新 Display 表。优点：访问快 O(1)；缺点：空间开销大，调用时维护成本高。两者都用于静态作用域语言（如 Pascal），C 语言无嵌套函数，非局部变量即全局变量，直接放静态区即可。

</Answer>

### 问题 4

栈式分配和堆式分配有什么区别？各自适用于什么场景？

<Answer>

栈式分配：活动记录在栈上分配，函数返回自动释放，分配/释放 O(1)，无需 GC。适合生命周期与函数调用一致的数据（局部变量、参数）。缺点：数据生命周期不能超过函数调用，不能返回指向栈上数据的指针。堆式分配：由程序员（malloc/free）或 GC 管理生命周期，数据可在任意时刻分配和释放。适合生命周期不确定的数据（动态对象、可变长结构）。缺点：分配/释放开销大，可能有内存泄漏和碎片，需 GC 或手动管理。实际程序混合使用：栈放局部变量，堆放动态对象，静态区放全局变量。

</Answer>
