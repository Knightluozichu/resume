## 直觉：先看一条生产线

工厂把工件按到达顺序存放。排在连续货架上，按位置取件方便；货架满了，可能得整体搬家。若每件各占一个独立位置，插队只需重新记录前后关系，但找第几个工件要一路追过去。

本章解决两件事：怎样保留顺序，怎样限制取件规则。没有明确规则，“先来的先处理”可能悄悄变成“最后来的先处理”；保存的旧位置也可能在搬家后指向错误对象。

## 3.1 Abstract Data Types：先约定行为

<Term def="只规定允许的对象、操作及其语义，不指定内部存储方式">
  抽象数据类型（ADT）
</Term>
把调用者和实现隔开。比如“添加一个元素后长度加一”是可观察结果；“元素存在连续内存还是独立节点中”是实现选择。接口相同，不意味着时间成本相同。

<Term def="调用操作之前必须满足的条件">前置条件</Term>
也是契约的一部分：读首元素需要非空。标准库的许多空容器操作并不承诺抛异常；本章教学类则显式抛异常或返回失败。下方实验把非法操作拒绝在状态改变之前，不能据此推断标准库自带相同守卫。练习2、3用断言检验这条
ADT 边界。

## 3.2 The List ADT：顺序不是链表专利

<Term def="保留元素相对次序、允许按位置插入删除的序列抽象">List ADT</Term>
可以装下
`[7,7,9]`。两个7值相同，却是两个位置上的元素；“删第一个7”与“删所有7”不是同一操作。连续表和链表都能表示这个序列，图中的格子位置与节点编号分别呈现两种表示。

<Term def="表示遍历位置的对象，可按容器支持的方式前进或后退">迭代器</Term>
把位置传给算法。范围 `[begin,end)` 包含开头，不包含结尾；空表的两者相等。`end()`
不指向元素，不能解引用，也不能作为单元素 `erase`
的对象。删除时保存返回的后继，而不是先删掉再递增旧位置。练习1会真正删除重复值并检查剩余顺序。

## 3.3 vector and list in the STL：接口相似，承诺不同

这里的 STL 指标准库的泛型容器与算法。现代示例统一使用 **C++17**，不是对历史版本接口的逐字复现。[N4659 的 vector](https://timsong-cpp.github.io/cppwp/n4659/vector) 与 [list](https://timsong-cpp.github.io/cppwp/n4659/list) 给出了以下契约（普通元素类型，不讨论 `vector<bool>` 特化）。

| 需求               | `std::vector<T>`           | `std::list<T>`                 |
| ------------------ | -------------------------- | ------------------------------ |
| 按下标访问第 i 项  | O(1)，连续存储             | 无 `operator[]`；遍历定位 O(i) |
| 尾部插入一项       | 均摊 O(1)，扩容时最坏 O(n) | O(1)，需分配一个节点           |
| 已知位置插入一项   | 最坏 O(n)，可能搬移后缀    | O(1)，仅改链接                 |
| 删除已知位置的一项 | O(n)，后缀向前移动         | O(1)，销毁该节点               |
| 迭代器能力         | 随机访问，可加减距离       | 双向，只能逐步前进后退         |

因此 `std::advance(listIterator,k)` 并未获得随机访问能力，仍需 O(k) 次前进。顺序读取日志通常先考虑 vector；只有反复在**已定位节点**附近编辑、又需要未删节点的身份稳定时，list 的代价才可能值得。

### 失效与对象生命周期

<Term def="对象从构造完成到被销毁的一段时间">生命周期</Term>决定对象是否仍存在；
<Term def="容器修改后，旧位置凭据不能再按原契约使用">迭代器失效</Term>
还可能发生在存储地址仍有对象时。不能通过“值看着没变”判断旧迭代器可用。图中代号是守卫模型的记录，不是
C++ 迭代器自带的检查。

| 修改                | 已保存位置的后果                                           |
| ------------------- | ---------------------------------------------------------- |
| vector 重新分配     | 所有元素迭代器、指针、引用以及旧 `end()` 失效              |
| vector 插入但不扩容 | 插入点之前仍有效；插入点及之后、旧 `end()` 失效            |
| vector 删除         | 删除点及之后的迭代器和引用失效，包括旧 `end()`             |
| list 插入           | 原有元素迭代器和引用仍有效                                 |
| list 删除           | 仅被删元素的迭代器和引用失效；容器销毁后所有元素都不可再用 |

## 3.4 Implementation of vector：拥有一个块

<Term def="容器无需重新分配即可容纳的元素数量上限">capacity</Term>与 `size`
分开：前者是可用空间，后者是逻辑元素数。标准 vector 的 `reserve(n)`
不创建新逻辑元素，不缩小容量；`resize(n)` 则创建或销毁元素。`reserve(8)` 后若
`size()==0`，访问 `v[0]` 仍不合法，`at(0)` 应抛出越界异常。

<Term def="负责释放资源的唯一或共享责任关系">所有权</Term>
决定谁释放块。扩容先分配新块，再复制或移动已有元素，成功后才替换旧块；通用类型还要处理构造失败与异常保证。本章只实现有界整数版本，使用
`unique_ptr`
自动释放，并禁止复制、移动，避免把一份资源误当两份独立资源。标准容器本身支持值语义复制；元素若是裸指针，复制的是指针值，不会替调用者深复制指向对象。

### 历史作者实现不是标准库契约

作者第三版配套 [Vector.h](https://users.cs.fiu.edu/~weiss/dsaa_c++3/code/Vector.h) 实际使用 `new Object[capacity]`：容量范围内的对象都已构造，不等同标准 vector 的未使用原始存储。该文件的 `reserve` 会按请求截断复制数，再加16个备用位置，甚至改变 `size`；因此不能把它当作 `std::vector::reserve` 的规格。图中倍增是本站选定的教学策略，**标准没有规定固定增长倍数**。

### 均摊不等于每次都快

<Term def="把一串操作的总成本分摊到每次操作，而非随机平均">均摊成本</Term>
来自几何增长：容量按1、2、4、8增长时，扩容复制量为 `1+2+4+…`。做 n
次尾插，复制总数小于 `2n`，另有 n 次写入，所以总成本 O(n)，每次均摊
O(1)。某一次满块追加仍要复制 n 个元素，最坏
O(n)。若每次只多留一格，则复制总数变成 `1+2+…+(n-1)`，退化为
O(n²)。下方第三次追加就能观察到一次昂贵事件。

## 3.5 Implementation of list：拥有节点和链接

<Term def="只维护边界链接、不代表业务元素的节点">哨兵</Term>
让空表也有稳定边界。作者
[List.h](https://users.cs.fiu.edu/~weiss/dsaa_c++3/code/List.h) 使用 head、tail
两个哨兵。空时 `head.next==tail`、`tail.prev==head`；实际节点各有
`prev/next`，图中左右两条线分别表示反向、正向链接，不代表连续地址。

在 p 前插入新节点 q：先令 `q.prev=p.prev`、`q.next=p`，再令 `p.prev.next=q`、`p.prev=q`。删除 p：先让前后邻居互相链接，记下后继，最后销毁 p。局部操作不搬移别的节点，但寻找 p 仍可能 O(n)。第六节代码把节点藏在类内，防止外部随便删哨兵。

析构必须释放所有数据节点；复制不能只复制头尾指针。作者代码为复制建立独立节点，本章小实现直接禁止复制与移动，留出明确边界。图里的“稳定”只适用于未删节点，不是永久有效；练习1也会检验标准容器复制后修改互不影响。

## 3.6 The Stack ADT：只在同一端进出

<Term def="最后进入的元素最先离开">LIFO</Term>是 Stack ADT 的取出规则。`push`
增加栈顶，`top` 只读不删，`pop` 删除栈顶；标准 `std::stack::pop()`
不返回值。应先检查非空，再读取并弹出；空栈的 `top/pop` 不保证给你一个异常。

栈适合括号匹配、表达式计算和撤销记录。计算后缀表达式 `8 3 -`，第一次取出的是右操作数3，再取左操作数8，结果为5；把顺序反过来会变成−5。实验的竖直槽从顶部取出；练习2为有界栈加入安全弹出，并用这个非交换操作验证取出顺序。

标准 stack 是<Term def="限制或改写已有容器的对外接口，而复用其存储">容器适配器</Term>，默认底层为<Term def="两端都能高效插入删除的标准序列容器，不保证整体连续">deque</Term>，也可用 vector 或 list；成本取决于底层。vector 尾插有均摊性质，不能把所有 stack 的 push 都说成最坏 O(1)。标准适配器没有固定 `full()`；图中容量3是额外教学契约。

## 3.7 The Queue ADT：两端各负其责

<Term def="最先进入的元素最先离开">FIFO</Term>是 Queue ADT
的取出规则：尾部入列，首部读取和出列。标准 `std::queue` 的 `front/back/pop`
同样需要非空，`pop` 不返回值；默认底层 deque，list 也可适配，但 vector
缺少所需的 `pop_front`，不能直接替换。

<Term def="用循环下标复用固定数组槽位的队列表示">环形缓冲区</Term>
避免出列时搬移全部后缀。容量 C 必须大于0；存 head 和 count，第 i 个逻辑元素在
`(head+i)%C`。入列写 `(head+count)%C`；出列令 `head=(head+1)%C`。满时
count=C、空时 count=0，**两者写槽都可能等于 head**，不能只比较两个下标。每步最坏
O(1)，不自动扩容。

实验容量为3，拒绝满写而非覆盖旧值；重复值仍按到达身份排序。若改成动态扩容，必须按逻辑次序复制到新块 `[0,count)`，再令 head=0，不能照物理槽顺序复制。练习3用一次回绕和重复值检查这一点。

## 交互实验：先预测，再执行

猜一猜：把连续块的元素数从2增加到3，保存的两个首元素句柄会怎样？执行一次“追加”，看到旧块被划掉、vector 句柄失效，而原链表节点保留。打开错误模式，选择“读取”：错误调用方跳过重新获取，vector 旧句柄被拒绝，list 节点#1仍可读。关闭错误模式再执行读取，正常调用方先获取**当前首元素的新句柄**，两边都成功，图中的代号更新。

这不是标准库替你修复旧迭代器，而是两种调用方流程的对照。现在打开错误模式，删除首元素后读取，两边都拒绝；关闭错误模式读取则取得新的首元素，它与已删除元素即使同值也不是同一身份。所有拒绝都发生在受保护模型里，不执行 C++ 悬空访问。

切换“栈 / 环形队列”，连续入列三次、出列一次，再入列一次：观察写槽回到0，head 留在1。空、满操作都应明确拒绝且不改数据。打开错误模式并出列，会把队尾误当队首；守卫按编号而非值比较，因此两个相同值也不能蒙混过关。最后按“完整重置”，包括视图和开关一起回到初始状态。

## C++17 实作：明确小实现的边界

下面和练习答案中的**所有 `cpp` 块按出现顺序拼接**，就是一个完整的 `lists_lab.cpp`；中间两处类定义有意跨块讲解。无需复制作者源码。保存后使用 `clang++ -std=c++17 -Wall -Wextra -Werror -pedantic -fsanitize=address,undefined lists_lab.cpp -o lists_lab && ./lists_lab`。全部断言通过时正常退出，无输出。不要定义 `NDEBUG`。

`IntBuffer` 的整数数组会构造整个容量范围；逻辑元素仍只在 `[0,n)`。最多16项，扩容先完成复制再交接所有权；参数按值传入，因此追加已有值也不会持有跨扩容引用。

```cpp
class IntBuffer {
    std::unique_ptr<int[]> data;
    std::size_t n = 0, cap = 0;
public:
    IntBuffer() = default;
    IntBuffer(const IntBuffer&) = delete;
    IntBuffer& operator=(const IntBuffer&) = delete;
    std::size_t size() const { return n; }
    std::size_t capacity() const { return cap; }
    int at(std::size_t i) const {
        if (i >= n) throw std::out_of_range("index");
        return data[i];
    }
    void reserve(std::size_t c) {
        if (c > 16) throw std::length_error("limit");
        if (c <= cap) return;
        auto fresh = std::make_unique<int[]>(c);
        for (std::size_t i = 0; i < n; ++i) fresh[i] = data[i];
        data.swap(fresh); cap = c;
    }
    void push(int x) {
        if (n == 16) throw std::length_error("full");
        if (n == cap) reserve(cap ? (cap > 8 ? 16 : 2 * cap) : 1);
        data[n++] = x;
    }
};
```

`IntList` 的两个哨兵是内嵌成员，不需要 `delete`；数据节点才由本对象拥有。删除函数是私有的，只由确认非空的接口调用。构造失败不会先破坏旧链接。

```cpp
class IntList {
    struct Node { int value; Node* prev; Node* next; };
    Node head{0, nullptr, nullptr}, tail{0, nullptr, nullptr};
    std::size_t n = 0;
    void erase(Node* p) {
        p->prev->next = p->next;
        p->next->prev = p->prev;
        delete p; --n;
    }
public:
    IntList() { head.next = &tail; tail.prev = &head; }
    IntList(const IntList&) = delete;
    IntList& operator=(const IntList&) = delete;
    ~IntList() { while (pop_front()) {} }
    std::size_t size() const { return n; }
    void push_back(int value) {
        Node* p = &tail;
        Node* q = new Node{value, p->prev, p};
        p->prev->next = q; p->prev = q; ++n;
    }
```

继续上一个类。安全空删除返回 false；按值删除这里只删第一个匹配项，寻找成本 O(n)。`values()` 返回独立快照，不泄露节点地址。

```cpp
    bool pop_front() {
        if (!n) return false;
        erase(head.next); return true;
    }
    bool erase_first(int value) {
        for (Node* p = head.next; p != &tail; p = p->next) {
            if (p->value == value) { erase(p); return true; }
        }
        return false;
    }
    std::vector<int> values() const {
        std::vector<int> result;
        for (const Node* p = head.next; p != &tail; p = p->next)
            result.push_back(p->value);
        return result;
    }
};
```

环形队列拥有三个整数槽。count 才是满空的判据；optional 的“无值”与队列里合法的0互不混淆。出列后旧整数比特可留在槽中，但已不属于逻辑序列；若改成通用对象，需决定何时销毁或释放被移除对象的资源。

```cpp
class Ring {
    std::array<int, 3> data{};
    std::size_t head = 0, count = 0;
public:
    std::size_t size() const { return count; }
    bool push(int value) {
        if (count == data.size()) return false;
        data[(head + count) % data.size()] = value;
        ++count; return true;
    }
    std::optional<int> pop() {
        if (!count) return std::nullopt;
        int value = data[head];
        head = (head + 1) % data.size(); --count;
        return value;
    }
```

继续该类，给出练习3要修改的接口：`values()` 必须返回逻辑次序而非物理顺序。下面是可运行的正确实现；做题时先遮住它，独立实现，再用答案的断言验证。

```cpp
    std::vector<int> values() const {
        std::vector<int> result;
        for (std::size_t i = 0; i < count; ++i)
            result.push_back(data[(head + i) % data.size()]);
        return result;
    }
};
```

## 常见误区

<Callout type="trap" title="值没变不代表迭代器有效">

**现象 →** 追加后旧迭代器“还打印出7”。  
**原因 →** 值重复或内存尚未重用不代表契约有效。  
**修法 →** 扩容后重新获取；用实验错误调用方观察守卫拒绝，不运行悬空解引用。

</Callout>

<Callout type="trap" title="链表插入成本不含定位">

**现象 →** 为按下标取数据选 list，因为“插入 O(1)”。  
**原因 →** 隐去了定位节点的 O(n) 成本与节点分配开销。  
**修法 →** 先列操作组合；大量下标访问、尾部追加优先评估 vector。

</Callout>

<Callout type="trap" title="下标相等不能区分满空">

**现象 →** 用 `head==写槽` 判空，满队列却允许覆盖。  
**原因 →** 回绕使空和满共享同一下标关系。  
**修法 →** 使用 count，先检查 count==容量；不要同时混用“浪费一槽”的另一种方案。

</Callout>

<Callout type="trap" title="浅复制会重复释放资源">

**现象 →** 手写容器复制后退出时重复释放。  
**原因 →** 浅复制把同一拥有指针交给两个析构函数。  
**修法 →** 禁止复制，或实现独立资源复制及异常安全；裸指针值复制不等于资源深复制。

</Callout>

## 小结

- 序列相同，不代表布局、身份和失效契约相同。
- 空满守卫、重复值和回绕必须进入断言。
- vector 扩容换块，list 插入保留原节点。

用 `it=erase(it)` 接住后继。vector 测试只验证容量变化，绝不读取旧指针；list 保存未删的9所在迭代器，删除两项7后仍有效。教学类禁止复制；标准容器可独立复制其整数元素。

```cpp
void test_storage() {
    IntBuffer b; b.reserve(2);
    assert(b.size() == 0 && b.capacity() == 2);
    bool threw = false;
    try { (void)b.at(0); } catch (const std::out_of_range&) {
        threw = true;
    }
    assert(threw);
    b.push(7); b.push(7); b.push(b.at(0));
    assert(b.size() == 3 && b.capacity() == 4 && b.at(2) == 7);
    b.reserve(1); assert(b.capacity() == 4 && b.size() == 3);
    while (b.size() < 16) b.push(9);
    threw = false;
    try { b.push(1); } catch (const std::length_error&) { threw = true; }
    assert(threw && b.size() == 16 && b.at(15) == 9);
    IntList l; assert(!l.pop_front());
    l.push_back(7); l.push_back(7); l.push_back(9);
    assert(l.erase_first(7));
    assert((l.values() == std::vector<int>{7, 9}));
    assert(!l.erase_first(4));
    assert(l.pop_front() && l.pop_front() && !l.pop_front());
    assert(l.size() == 0 && l.values().empty());
}
```

接着测标准契约。`reserve` 只保证至少所请求的容量，所以先填满实际 capacity，而不是假设实现恰好分配两格。reserve 后仍为空也单独测试。

```cpp
void test_standard() {
    std::vector<int> v; v.reserve(2);
    assert(v.empty());
    bool threw = false;
    try { (void)v.at(0); } catch (const std::out_of_range&) {
        threw = true;
    }
    assert(threw);
    v.resize(v.capacity(), 7);
    auto oldCapacity = v.capacity();
    v.push_back(9); assert(v.capacity() > oldCapacity);
    auto copy = v; copy[0] = 5; assert(v[0] == 7);
    std::list<int> l{7, 7, 9};
    auto stable = --l.end();
    l.insert(l.begin(), 7);
    for (auto it = l.begin(); it != l.end(); ) {
        if (*it == 7) it = l.erase(it); else ++it;
    }
    assert(l.size() == 1 && *stable == 9);
    auto other = l; other.front() = 5; assert(l.front() == 9);
}
```

</Answer>

**问题 2：把危险的弹栈改成有结果类型的接口。**

不要写“先减少数量再读数组”。实现容量3的 `FixedStack`：满写返回 false，空弹出返回 `nullopt`。用 `8 3 -` 和重复值验证 LIFO，解释它与标准 stack 接口的差别。

<Answer>

先检查，随后递减，再读取旧栈顶。整数版本不需要额外异常回滚。optional 使合法的0不再被误判为空；标准 stack 仍使用“先 top，后 pop”的两次调用。

```cpp
class FixedStack {
    std::array<int, 3> data{};
    std::size_t n = 0;
public:
    bool push(int x) {
        if (n == data.size()) return false;
        data[n++] = x; return true;
    }
    std::optional<int> pop() {
        if (!n) return std::nullopt;
        return data[--n];
    }
};
void test_stack() {
    FixedStack s; assert(!s.pop());
    assert(s.push(8) && s.push(3));
    int rhs = *s.pop(), lhs = *s.pop(); assert(lhs - rhs == 5);
    assert(s.push(7) && s.push(7) && s.push(0) && !s.push(9));
    assert(s.pop() == 0 && s.pop() == 7 && s.pop() == 7);
    assert(!s.pop());
    std::stack<int> standard; standard.push(8); standard.push(3);
    rhs = standard.top(); standard.pop();
    lhs = standard.top(); standard.pop();
    assert(lhs - rhs == 5 && standard.empty());
}
```

</Answer>

**问题 3：修改环形队列的快照，跨过数组末尾仍保持 FIFO。**

独立重写 `Ring::values()`，不能简单返回数组前三格。容量3，依次入7、7、9，出一次，再入5。此时物理数组与逻辑顺序各是什么？补满写拒绝、空读拒绝和长期回绕的测试。

<Answer>

物理数组是 `[5,7,9]`，head=1，逻辑快照为 `[7,9,5]`。必须从 head 开始取 count 项，对容量取余。禁止覆盖使失败后原序列不变；独立 `std::queue` 是后续循环的参考队列。

```cpp
void test_ring() {
    Ring r; assert(!r.pop());
    assert(r.push(7) && r.push(7) && r.push(9));
    assert(!r.push(4));
    assert((r.values() == std::vector<int>{7, 7, 9}));
    assert(r.pop() == 7 && r.push(5));
    assert((r.values() == std::vector<int>{7, 9, 5}));
    assert(r.pop() == 7 && r.pop() == 9 && r.pop() == 5);
    assert(!r.pop() && r.size() == 0);
    std::queue<int> oracle;
    for (int i = 0; i < 120; ++i) {
        if (i % 4 != 3) {
            bool room = oracle.size() < 3;
            assert(r.push(i % 3) == room);
            if (room) oracle.push(i % 3);
        } else {
            auto got = r.pop(); assert(got.has_value() == !oracle.empty());
            if (got) { assert(*got == oracle.front()); oracle.pop(); }
        }
        auto pending = oracle;
        for (int value : r.values()) {
            assert(!pending.empty() && value == pending.front()); pending.pop();
        }
        assert(pending.empty() && r.size() == oracle.size());
    }
}
```

最后连接所有测试。失败会在断言处终止；这不是用“看起来对”的打印结果代替自动检查。

```cpp
int main() {
    test_storage();
    test_standard();
    test_stack();
    test_ring();
}
```

</Answer>

<Glossary>
  <GlossaryItem term="抽象数据类型（ADT）">
    先约定能做什么和结果是什么，再选择内部表示。
  </GlossaryItem>
  <GlossaryItem term="前置条件">
    调用操作前必须成立的条件，例如读取栈顶前非空。
  </GlossaryItem>
  <GlossaryItem term="List ADT">
    保留相对次序的序列抽象，不专指链接节点。
  </GlossaryItem>
  <GlossaryItem term="迭代器">
    遍历位置凭据；随机访问能直接跳位置，双向只能逐步走。
  </GlossaryItem>
  <GlossaryItem term="生命周期">
    对象从构造到销毁的存活期间；存储还在不表示对象还在。
  </GlossaryItem>
  <GlossaryItem term="迭代器失效">
    修改后旧位置不再受容器契约保证，不能试读来验证。
  </GlossaryItem>
  <GlossaryItem term="capacity">
    无需重新分配可容纳的数量，不等于已存在的逻辑元素数。
  </GlossaryItem>
  <GlossaryItem term="所有权">
    谁负责释放资源；浅复制指针不会复制它指向的资源。
  </GlossaryItem>
  <GlossaryItem term="均摊成本">
    一串操作总成本除以操作数，不是每次最坏成本。
  </GlossaryItem>
  <GlossaryItem term="哨兵">
    没有业务元素的边界节点，减少首尾操作特判。
  </GlossaryItem>
  <GlossaryItem term="LIFO">
    后进先出，从同一端加入和取走，构成栈的规则。
  </GlossaryItem>
  <GlossaryItem term="FIFO">
    先进先出，尾部加入、首部取走，构成队列的规则。
  </GlossaryItem>
  <GlossaryItem term="容器适配器">
    包装已有容器，只对外暴露所需操作，例如 stack 隐藏中间位置访问。
  </GlossaryItem>
  <GlossaryItem term="deque">
    双端队列容器，可在两端插入删除，整体不保证连续存储。
  </GlossaryItem>
  <GlossaryItem term="环形缓冲区">
    下标到末尾后绕回开头，以固定槽位表示队列。
  </GlossaryItem>
