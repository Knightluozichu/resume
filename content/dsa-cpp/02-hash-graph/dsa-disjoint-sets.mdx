## 直觉引入

社交网络中，判断两个人是否在同一朋友圈（连通分量），最高效的方法是什么？并查集。

并查集维护一组互不相交的集合，支持两个操作：`find(x)`（找 x 所在集合的代表）和 `union(x,y)`（合并两个集合）。加上路径压缩和按秩合并，每次操作几乎 $O(1)$（准确说是 $O(\alpha(n))$，$\alpha$ 是反阿克曼函数，对任何实际 $n$ 都 $\leq 4$）。这是数据结构中最惊艳的复杂度之一。

## 概念讲解

### 并查集模型

<DsaDisjointSetsDiagram />

<Term def="并查集是一种维护互不相交集合的数据结构，支持 find（查找代表）和 union（合并集合）">
并查集
</Term>

并查集用**树**表示集合：每个集合一棵树，根节点是集合的「代表」。`find(x)` 沿父指针走到根，返回根。`union(x,y)` 把一棵树的根指向另一棵的根。

### 两种优化

<Stepper>
<Step title="路径压缩（Path Compression）">
`find(x)` 时，把路径上所有节点直接指向根。下次 `find` 一步到位。虽然单次 `find` 可能 $O(\log n)$，但路径压缩后树变扁平，后续操作接近 $O(1)$。
</Step>
<Step title="按秩合并（Union by Rank）">
合并时把矮树挂到高树下，保证树高 $O(\log n)$。`rank` 是树高的上界。不按秩合并可能退化为链表 $O(n)$。
</Step>
<Step title="两者结合的复杂度">
路径压缩 + 按秩合并：均摊 $O(\alpha(n))$，$\alpha$ 是反阿克曼函数。$\alpha(n) \leq 4$ 对所有 $n \leq 10^{80}$ 成立。实际中就是 $O(1)$。$n$ 次 `find`+`union` 的总代价 $O(n \cdot \alpha(n)) \approx O(n)$。
</Step>
</Stepper>

### 应用场景

- **连通分量**：图中加边时 `union`，判断连通性时 `find` 同根。
- **Kruskal 最小生成树**：按边权排序，用并查集判断是否形成环。
- **动态连通性**：在线处理「添加边 + 查询连通性」的混合操作。

## 代码对照

```cpp
#include <vector>

class UnionFind {
    std::vector<int> parent;
    std::vector<int> rank_;  // rank 是树高的上界
    int count;               // 连通分量数

public:
    UnionFind(int n) : parent(n), rank_(n, 0), count(n) {
        for (int i = 0; i < n; ++i)
            parent[i] = i;  // 初始每个元素自成一个集合
    }

    // find：带路径压缩
    int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]);  // 路径压缩：直接指向根
        return parent[x];
    }

    // union：带按秩合并
    bool unite(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;  // 已在同一集合

        // 按秩合并：矮树挂高树下
        if (rank_[px] < rank_[py]) {
            parent[px] = py;
        } else if (rank_[px] > rank_[py]) {
            parent[py] = px;
        } else {
            parent[py] = px;  // 等高：随便挂，但 rank+1
            ++rank_[px];
        }
        --count;  // 连通分量减 1
        return true;
    }

    bool connected(int x, int y) {
        return find(x) == find(y);
    }

    int components() const { return count; }
};

// Kruskal 最小生成树：并查集的经典应用
#include <algorithm>
struct Edge { int u, v, w; };

int kruskal(int n, std::vector<Edge>& edges) {
    std::sort(edges.begin(), edges.end(),
              [](const Edge& a, const Edge& b) { return a.w < b.w; });

    UnionFind uf(n);
    int mstWeight = 0;
    int edgeCount = 0;

    for (const auto& e : edges) {
        if (uf.unite(e.u, e.v)) {  // 不形成环就加入
            mstWeight += e.w;
            if (++edgeCount == n - 1) break;  // MST 有 n-1 条边
        }
    }
    return mstWeight;
}
```

## 常见误区

<Callout type="trap">
**误区：只用路径压缩，不用按秩合并（或反之）。**
单独使用路径压缩：均摊 $O(\log n)$（不是 $O(1)$）。单独使用按秩合并：$O(\log n)$。两者结合才能达到 $O(\alpha(n)) \approx O(1)$。漏掉任何一个优化，复杂度都会退化到 $O(\log n)$。
</Callout>

<Callout type="trap">
**误区：并查集的 find 是 $O(1)$ 所以不需要优化。**
不优化的并查集 `find` 最坏 $O(n)$（退化为链表）。只有路径压缩+按秩合并才能达到 $O(\alpha(n))$。而且路径压缩的收益是渐进的——第一次 `find` 可能 $O(\log n)$，但压缩后路径变短，后续接近 $O(1)$。
</Callout>

<Exercises>
**问题 1**：路径压缩和按秩合并分别解决什么问题？为什么要同时使用？

<Answer>
路径压缩解决「路径过长」问题：`find` 时把路径上所有节点直接指向根，使树扁平化。按秩合并解决「合并后树过高」问题：矮树挂高树下，保证树高 $O(\log n)$。单独使用任一个都是 $O(\log n)$，两者结合达到 $O(\alpha(n)) \approx O(1)$。缺一个都会退化。
</Answer>

**问题 2**：Kruskal 算法中并查集的作用是什么？为什么能保证正确性？

<Answer>
Kruskal 按边权从小到大排序，逐条考虑。并查集用于判断加入当前边是否形成环：如果边的两端点已在同一集合（`find(u) == find(v)`），加入会形成环，跳过；否则 `union(u,v)` 加入 MST。正确性来自：按权排序保证贪心选择最小边，并查集保证不形成环，两者结合得到最小生成树。复杂度 $O(E \log E + E \cdot \alpha(V)) \approx O(E \log E)$。
</Answer>
</Exercises>
