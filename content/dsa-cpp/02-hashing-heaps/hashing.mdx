## 从“碰撞是散列表的正常路径”开始

散列基本思想（<Term def="通过hash function把大key space映射到有限table，并由碰撞策略维护集合或映射语义。">散列基本思想</Term>）不是让不同 keys 永不相撞，而是让它们近似均匀地落入有限 buckets，并在相撞后仍能正确 `find`、`insert` 与 `remove`。若表长为 M，整数 key 的最小模型是：

$$
h(x)=x \bmod M
$$

先预测把 19、14、23、1、68、20 放进长度 7 的表。19 和68都映射到5，14映射到0；这不表示 hash function “坏了”，只说明 collision resolution 现在成为 correctness 的一部分。若只测试没有碰撞的数据，最危险的分支从未运行。

本书第3版第5章的官方七节依次是 **General Idea、Hash Function、Separate Chaining、Hash Tables Without Linked Lists、Rehashing、Hash Tables in the Standard Library、Extendible Hashing**。下面保持这个顺序：先确定地址质量，再比较链式与表内探查，最后处理增长、标准接口和外存目录。

## 5.1 General Idea

理想散列表把 key 映射到 array index，直接访问 bucket。只要 hash evaluation 是常数时间、分布均匀、load factor 受控，lookup 的 expected cost 可写成：

$$
\mathbb{E}[T_{\mathrm{find}}]=O(1)
$$

这个 O(1) 是 average/expected guarantee，不是“任何输入都一步完成”。攻击者控制字符串时，可构造大量 collisions；resize 时也会出现单次 O(N) 工作。接口设计必须把 average case、worst case 与 amortized resize cost 分开陈述。

散列表不维护 sorted order，因此不擅长 predecessor、range scan 或 ordered iteration。BST 用比较关系换取次序和 logarithmic bound；hash table 用额外 capacity 与分布假设换取平均常数 lookup。容器选择由所需 operations 决定，而不是笼统比较谁“更快”。

## 5.2 Hash Function

散列函数（<Term def="把key的全部相关信息稳定混合成整数，再映射到当前tableSize的函数。">散列函数</Term>）必须满足两个语义条件：相等 keys 产生相同 hash；对象留在容器期间，参与 hash/equality 的字段不能以破坏 bucket 定位的方式变化。均匀分布是性能目标，不是 equality contract 的替代品。

对字符串，只相加字符会忽略顺序，使 `abc` 与 `cba` 必然碰撞。第3版作者示例采用 multiplier 37 的 Horner recurrence：

$$
H_0=0,\qquad H_{i+1}=37H_i+\operatorname{code}(s_i)
$$

```cpp
std::size_t hashString(std::string_view key) {
    std::size_t value = 0;
    for (unsigned char ch : key)
        value = 37 * value + ch;
    return value;
}
```

这是对官方 `hash(const string&)` 的现代无符号改写。原示例使用 `int` 展示 recurrence；生产代码应避免依赖 signed overflow，并把混合后的 hash 对实际 bucket count 取模。table resize 会改变 bucket index，但不改变 key equality。

<DsaStringHashLab />

选择 prime table size 常用于降低 key pattern 与 modulus 的共同周期。它不能修复一个只读取 key 局部字段的差 hash function，也不能阻止 adversarial collision。正确评估应统计 bucket occupancy histogram、最长链、probe length 分位数，而不是只看平均时间。

## 5.3 Separate Chaining

分离链接法（<Term def="每个array bucket保存一条可变长度链，所有同地址keys留在该链中。">分离链接法</Term>）让 table array 存放 `list<HashedObj>`。`myhash(x)` 选择链，链内再做 equality search。若 N 个元素分到 M 个 buckets，负载因子（<Term def="active element count与bucket或slot count之比，用于预测链长、探查成本与扩容时机。">负载因子</Term>）为：

$$
\lambda=\frac{N}{M}
$$

均匀散列下，unsuccessful lookup 检查约 lambda 个元素；successful lookup 通常检查约 `1 + lambda/2` 个。Separate chaining 允许 lambda 超过1，但链越长，cache locality 和 tail latency 越差。

<DsaSeparateChainingLab />

第3版官方 `SeparateChaining.h` 的核心插入逻辑可以压缩为：

```cpp
bool insert(const Key& key) {
    auto& chain = buckets[myhash(key)];
    if (std::find(chain.begin(), chain.end(), key) != chain.end())
        return false;
    chain.push_back(key);
    if (++size > buckets.size())
        rehash();
    return true;
}
```

`remove` 必须同时从链中 erase 并减少 active size；`makeEmpty` 不只 clear 各链，也应让 size 回到0。官方示例的构造器参数名为 `size`，但正文代码固定把 `theLists` resize 到101；忠实阅读要区分教材要展示的算法与可直接复用的通用组件。

链式方案 deletion 简单，并且 table 不会因一个 bucket 满而插入失败；代价是每个 node allocation、pointer chasing 和较弱 locality。若 key/value 很小且访问密集，开放定址往往更紧凑。

## 5.4 Hash Tables Without Linked Lists

不用链表的散列表，也就是开放定址法（<Term def="所有entries直接存入table array，碰撞时沿确定probe sequence寻找slot。">开放定址法</Term>），把 collision resolution 留在同一个 array 内。第 i 次探查的一般形式是：

$$
h_i(x)=\bigl(h(x)+f(i)\bigr)\bmod M
$$

- linear probing 取 `f(i)=i`，连续 slots locality 好，但容易 primary clustering；
- quadratic probing 取 `f(i)=i^2`，打散连续团簇，但表长和 load 条件决定能否找到空位；
- double hashing 取 `f(i)=i h_2(x)`，第二 hash 必须与 M 合适，才能遍历足够多 slots。

<DsaOpenAddressingProbeLab />

第3版 `QuadraticProbing.h` 用奇数增量 1、3、5、7 递推平方差，避免每轮真的做 multiplication：

```cpp
std::size_t findPos(const Key& key) const {
    std::size_t offset = 1;
    std::size_t pos = myhash(key);
    while (slots[pos].state != EMPTY && slots[pos].key != key) {
        pos = (pos + offset) % slots.size();
        offset += 2;
    }
    return pos;
}
```

因为 `(i+1)^2-i^2=2i+1`，奇数 offset 依次得到 quadratic positions。prime table 且 load 不超过一半时，教材实现可以依赖探查找到空 slot；超过边界后，不能只把 loop 写成“总会结束”。

删除不能直接标成 EMPTY。假设 key A、B 发生碰撞，B 位于 A 后面的 probe slot；若删除 A 后写 EMPTY，查 B 会在 A 的旧位置提前停止，错误报告 absent。因此 slot 至少有 `ACTIVE`、`EMPTY`、`DELETED` 三态，DELETED 是 tombstone：lookup 继续越过它，insert 可复用它。

<Callout type="trap" title="删除后直接写 EMPTY">
开放定址 lookup 以 EMPTY 作为“该 probe chain 从未继续”的终止证据。把已占用 slot 删除成 EMPTY 会切断后继 key 的可达性；必须使用 tombstone，或执行能保持探查不变量的 cluster repair。
</Callout>

Tombstones 太多会延长 unsuccessful lookup，即使 active load 不高。因此监控不仅要看 active entries，还要看 occupied-or-deleted ratio；定期 rehash 可同时清理墓碑。

## 5.5 Rehashing

再散列（<Term def="分配更大table并用新tableSize重新计算所有active keys位置的整体迁移。">再散列</Term>）不是把旧 array 原样复制。因为 modulus 和 probe sequence 都依赖 table size，每个 active key 必须重新 insert；DELETED entries 不迁移。

<DsaRehashingLoadLab />

官方 quadratic probing 实现在 active size 超过 array size 一半时，把容量扩到约两倍后的下一个 prime。正确流程是保存旧表、创建全 EMPTY 新表、把 size 归零、逐个插入旧表中的 ACTIVE entries：

```cpp
void rehash() {
    auto old = std::move(slots);
    slots.assign(nextPrime(2 * old.size()), Entry{});
    size = 0;
    for (const Entry& entry : old)
        if (entry.state == ACTIVE)
            insert(entry.key);
}
```

若容量按固定比例增长，每个 key 在多次扩容中被搬移的总次数形成几何级数：

$$
N+\frac{N}{2}+\frac{N}{4}+\cdots \lt 2N
$$

所以 resize 单次 O(N)，但分摊到一串 insert 上仍可保持 amortized O(1)。如果每次只增加一个 slot，搬移总工作会退化为 quadratic。异常安全还要求新表构造或 key copy 失败时，不破坏旧表的可用状态。

## 5.6 Hash Tables in the Standard Library

标准库散列表（<Term def="以unordered_set或unordered_map暴露hash、equality、bucket与rehash策略的标准关联容器。">标准库散列表</Term>）在现代 C++ 中是 `std::unordered_set` 和 `std::unordered_map`。第3版成书时标准库 incorporation 是重要主题；今天使用时应抓住接口 contract，而不是假设实现一定等同于书中的 list buckets。

<DsaStdHashSemanticsLab />

`unordered_set<Key, Hash, KeyEqual>` 保持 unique keys；`unordered_map<Key, Value, Hash, KeyEqual>` 保存 key-value pairs。对于任何 `KeyEqual(a,b)` 为 true 的 a、b，必须有 `Hash(a)==Hash(b)`。反向不要求成立：相同 hash 可以是不同 key，容器会再用 equality 区分。

`reserve(n)` 按目标 element count 预留，`rehash(b)` 请求至少一定 bucket count；`max_load_factor` 影响何时增长。Rehash 会改变 bucket placement 并使 iterators 失效，references/pointers 的规则应以所用标准版本和具体 operation contract 为准。不要把 iterator 长期缓存跨越潜在 insertion。

<Callout type="trap" title="hash 与 equality 使用不同字段">
若 equality 只比较用户编号，而 hash 又混入可变昵称，相等对象可能落到不同 bucket，find 与 duplicate suppression 都会失真。先定义 key identity，再让 hash 覆盖同一身份字段。
</Callout>

需要 ordered traversal、range query 或稳定 worst-case logarithmic operation 时，选择 `set/map`；需要平均常数 exact lookup 且不依赖次序时，才选择 unordered family。基准应包含真实 key distribution、reserve policy 与 miss ratio。

## 5.7 Extendible Hashing

可扩散列（<Term def="以hash bits索引directory，bucket满时局部分裂，并按需增加global depth的动态外存散列。">可扩散列</Term>）解决 disk-based table 增长问题。普通 rehash 需要重写整个大文件；extendible hashing 用内存 directory 指向固定大小 disk buckets，只分裂溢出的 bucket。

<DsaExtendibleHashingLab />

global depth d 表示 directory 使用 d 个 hash bits，因此入口数为：

$$
|\mathrm{directory}|=2^d
$$

每个 bucket 另有 local depth。插入导致 bucket overflow 时：

1. 若 local depth 小于 global depth，只分裂该 bucket，并重定向一部分 directory entries；
2. 若两者相等，directory 先加倍，global depth 加1，再分裂 bucket；
3. 只有 hash suffix 属于该 bucket 的 records 需要重新分配，其他 disk buckets 不动。

这种结构让一次 lookup 通常是 directory memory access 加一次 bucket I/O。代价是 directory 可能增长、poor hash suffix distribution 会反复分裂，而且并发更新需要保护 directory 与 bucket metadata 的一致性。它不是通用 in-memory `unordered_map` 的复杂替代品，而是针对动态外存文件的局部增长方案。

## 本章回顾

1. Hashing 把 key comparison 转成 address computation，但 collision resolution 是正常且必要的路径。
2. Hash function 必须服从 equality contract，并尽量让真实 keys 均匀分布。
3. Separate chaining 允许 load factor 超过1，删除简单，但承担 allocation 与 pointer chasing。
4. Open addressing 把 entries 留在 array，linear、quadratic 与 double hashing 由 probe sequence 区分。
5. Tombstone 维持删除后的 probe reachability；直接写 EMPTY 会制造 false miss。
6. Rehash 必须按新容量重新插入 active keys，几何增长给出 amortized O(1) insert。
7. Standard unordered containers 承诺平均复杂度与语义，不承诺教材中的具体 bucket representation。
8. Extendible hashing 用 directory 和 local split 控制动态磁盘文件的 I/O 与增长范围。

<Exercises>

**问题 1：长度11的表中，key 25 用 quadratic probing，首地址已占用时前四个地址是什么？**

<Answer>首地址是25 mod 11=3。按 `h+i²`，i依次为0、1、2、3，地址为3、4、7、1（平方加首地址后再mod 11）。实现用offset 1、3、5递推会得到相同序列。</Answer>

**问题 2：为什么开放定址删除必须保留 DELETED，而 separate chaining 不需要？**

<Answer>开放定址中后继key的可达性依赖连续probe evidence，EMPTY表示从未继续，故删除成EMPTY会提前终止查找；DELETED允许继续。链式表的每个bucket有独立容器，erase一个node不会切断其他node的定位路径。</Answer>

**问题 3：容量11的 quadratic table 插入第6个active key后为何触发扩容？**

<Answer>第6个元素使load factor为6/11，超过教材实现的一半阈值。prime table与低于等于一半的load共同支持quadratic probing找到空位的假设，因此扩到约22后的下一prime 23并重插所有active keys。</Answer>

**问题 4：global depth为3、local depth为2的bucket溢出时，directory是否必须加倍？**

<Answer>不必。local depth小于global depth，已有directory bits足以区分两个新bucket；只把local depth加1、分裂该bucket并重定向相关entries。只有local depth等于global depth时才先把directory加倍。</Answer>
