## 先给物品找位置，再处理位置被占用

工厂里按零件编号找物品，若每次都从头翻完整排货架，库存越多就越慢。我们希望先计算一个位置，直接去那里找。

两个编号可能算出同一个位置。此时需要明确的续找规则；拿走中间一件物品后，也不能让后面的物品突然“失踪”。本章把放入、取出和扩建货架看作同一套规则来检验。

## 1. 散列基本思想：地址只是候选位置

<Term def="先由键计算位置，再在候选位置检查是否相等的检索方法">散列</Term>
不承诺一次命中。键经过
<Term def="把键确定性地映射为整数摘要的函数">散列函数</Term>，再由容量映射到
<Term def="散列表中由索引定位的存储单元或一组记录">桶</Term>
。不同键得到同一候选地址，称为
<Term def="不同键竞争同一候选位置的现象">碰撞</Term>
。碰撞后必须比较键本身；“摘要相等”不能当作“键相等”。

例如容量 7，整数 5、12、19 都先访问 5。主实验实际把它们依次放到 5、6、0，并非用动画预写结果。若键比较和函数计算都是常数成本，分布均匀且负载受控，查询期望为常数；最坏情况下仍可能检查全部键。字符串函数还要读字符，长度成本不能凭空消失。

散列表适合成员判断和编号查找，不提供有序遍历、前驱或范围查询。需要“编号 100 到 200”时，平衡树往往比散列表合适。后面的标准容器程序用集合充当语义参照，但不依赖它的具体桶实现。

### 函数契约：先正确，再谈均匀

相等键必须得到相同摘要；反方向不成立。若自定义相等比较忽略大小写，函数也必须按同一种大小写规则处理。容器内键的相等关系与摘要必须稳定；不能通过外部可变对象间接修改它们。现代标准库的相关契约见 [C++17 草案的无序容器要求](https://timsong-cpp.github.io/cppwp/n4659/unord.req)。

整数教学模型使用规范化余数。C++ 中 `-1 % 7` 为 `-1`，所以先取余，再在负数时加 7，得到索引 6。不能直接拿负余数访问数组。下方 `home` 实现这一规则，支持 `INT_MIN`，不通过取绝对值溢出来“修复”。

[作者伴随代码](https://users.cs.fiu.edu/~weiss/dsaa_c++3/code/SeparateChaining.cpp)展示按字符反复乘 37 再相加。字符简单相加会把 `ab` 和 `ba` 混在一起；乘法递推区分位置。本文用 `std::size_t` 进行定义明确的无符号回绕，不照搬历史示例的有符号溢出风险。它是教学函数，不是抗攻击哈希。

## 2. 分离链接法：冲突记录放在同一条链

<Term def="每个桶保存一条记录链，碰撞后在该链中比较键">分离链接法</Term>让
5、12、19 都留在第 5
桶的链中。插入前沿链检查重复键；删除时仅移除目标节点，不会截断其他记录的查询。下方
`Chain`
是完整可编译的最小集合实现，对应[作者的桶链结构](https://users.cs.fiu.edu/~weiss/dsaa_c++3/code/SeparateChaining.h)，但不是原文件的翻译。

<Term def="活跃元素数除以桶数或槽数，用于衡量容量利用程度">负载因子</Term>记为
α。链式方案允许 α 大于
1；这表示平均每条链超过一个元素，不表示桶数组越界。代价是节点分配与沿链访问，不能只看数组的空间。练习
1 对同一输入比较链与连续槽。

### 从负载推到工作量

本节符号：N 是活键数；M 是桶数或槽数；D 是删除标记数；α 是活负载；β 是包含删除标记的占用比例。

$$
\alpha=N/M,\qquad \beta=(N+D)/M
$$

这表示主图删除 12 后，N=2、D=1、M=7，活负载降为 2/7，但仍有 3/7 的槽不能作为查找的空槽终点。

均匀分配到 M 个链桶时，一次失败查询平均需检查 N/M 个链节点，因为每个键落到目标桶的概率是 1/M；再加桶定位的固定成本，就是期望 O(1+α)。分布偏斜时单链可长达 N。不能把这个链长估计直接套给连续探查。

## 3. 不用链表的散列表：沿槽探查

<Term def="发生碰撞后继续探查同一个数组中的其他槽">开放定址法</Term>
省掉外部链。第 i 次探查位置写成 `(h(x)+f(i)) mod M`，i 从 0
开始。主实验使用线性探查 `f(i)=i`，因此恰好访问一圈就覆盖 M
个槽；所有循环最多执行 M 次。

删除不能简单清空槽。<Term def="记录此槽曾被占用，查找应继续但插入可以复用的删除标记">墓碑</Term>保留探查链的连续性。查询见空槽可宣布不存在，见墓碑必须继续。插入可以记住第一块墓碑，却必须继续排除后方已有相等键，才能复用它。否则删除 12 后再插入 19，会产生两份 19。

### 探查策略不能只替换一个公式

线性探查会形成连续占用段，使后来从这一段出发的键也被推到尾部，称为<Term def="碰撞让连续占用段增长，进而吸引更多探查的现象">聚集</Term>。<Term def="用平方偏移而非连续偏移寻找后续槽">二次探查</Term>使用 `f(i)=i²`，但不保证走遍全表：M=8、起点 0 时只出现 0、1、4。即使 5 个槽空着，也可能无法插入。

对奇素数 M，i 取 0 到 `(M-1)/2` 时平方余数互异：若 i²≡j²，则 M 整除 `(i-j)(i+j)`，在该范围只能 i=j。所以至少有 `(M+1)/2` 个候选槽；不足一半的槽被占用时可找到空槽。删除后要区分活键与墓碑，不能用很低的 α 推断很快遇空。作者探查文件明确写有“素数、半空”的前提；本章线性模型不依赖该前提。

<Term def="用第二个函数决定探查步长的开放定址方法">双重散列</Term>使用
`h1(x)+i·h2(x)`；步长须与 M 互素。M=8、步长 2 只访问四槽，步长 3
才覆盖八槽。无论哪一种策略，仍应有探查次数上界，而不是 `while(true)`
等待永远不会遇到的空槽。

## 4. 先预测，再让墓碑故障发生

猜一猜：保留槽 6 的墓碑，查找 19 要访问哪些槽？把故障打开后，19 是否真的被删除了？

<DsaHashingProbeLab />

按“故障”会立即查询输入键，正确轨迹 `5 → 6 → 0` 会被截成 `5 → 6`；存储中的 19 没消失，只是错误算法提前宣布失败。输入 `-1` 再插入，应从 6 开始探查。把操作切到插入，尝试已有的 19，应报告重复而不是把墓碑当成新键位置。

输入 0、1、2、3、4 等键逐次插入可以逼近满表。表满时不存在的键最多探查 M 次，然后明确失败；若只剩墓碑，则绕完一圈后可以复用墓碑。重置同时恢复初始表、输入 19、查找操作、故障关闭和原始图形。

## 5. 再散列：不能原位把模数换掉

<Term def="建立新容量的空表并按新地址规则重新插入活键">再散列</Term>
改变容量后要重新定位每个活键。初始图选择“再散列到 11 槽”：键 19 从物理槽 0 移到
8，键 5 仍在
5；墓碑不搬家。这不是把数组尾部补空槽就结束。扩容分配、扫描和重新插入都要计入成本。

均匀散列与受控负载下，常见再散列的期望工作量为 O(N+M新)；若每次容量按比例增长，增长成本可分摊到多次插入。劣质函数让重插入产生长探查，单次重建仍可能退化。这里不声称无条件线性。相同容量重建也有意义：它清理墓碑，却不增加可容纳的活键数。

主图固定重建到 11，模型与 C++ 允许指定 1–31；目标比活键数还小时返回失败、保留原表。此处不做自动增长，目的是让满表和删除条件可以被直接观察。生产容器通常在更低负载就扩容，以免查询接近整圈扫描。

## 6. C++17 可运行对照：先实现，再用容器核查

下面依次拼接所有标为 `hash_lab.cpp` 的 **8 段**，保存为一个文件。每段不超过 30 行；跨段的类定义故意保持开放。这是独立编写的整数集合教学程序，不是完整通用容器。运行 `clang++ -std=c++17 -Wall -Wextra -Werror hash_lab.cpp -o hash_lab && ./hash_lab`，应输出 `hash lab ok`。练习中的 `exercise.cpp` 是第二个文件，不要拼入第一个。

### A1：头文件、函数与槽状态

`home` 先缩小余数再相加，避免负数越界；`wordHash` 使用无符号运算。槽不拿某个整数充当“空”，所以负数也能成为有效键。

```cpp file=hash_lab.cpp
#include <algorithm>
#include <cassert>
#include <climits>
#include <cstddef>
#include <iostream>
#include <list>
#include <stdexcept>
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>
int home(int key, int m) {
    if (m < 1 || m > 31) throw std::invalid_argument("capacity");
    int r = key % m;
    return r < 0 ? r + m : r;
}
std::size_t wordHash(const std::string& text) {
    std::size_t h = 0;
    for (unsigned char c : text) h = 37 * h + c;
    return h;
}
enum State { Empty, Live, Deleted };
struct Slot { State state = Empty; int key = 0; };
struct Search { int found = -1, vacant = -1, visits = 0; };
```

### A2：有限探查

查找记录首个可用位置，却继续检查重复键。只有空槽或完整一圈能证实不存在；参数 `wrong` 专门复现错误的墓碑终止，默认关闭。

```cpp file=hash_lab.cpp
struct Table {
    std::vector<Slot> slots;
    explicit Table(int m = 7) {
        home(0, m);
        slots.resize(m);
    }
    Search scan(int key, bool wrong = false) const {
        Search r;
        int m = static_cast<int>(slots.size());
        for (int i = 0; i < m; ++i) {
            int p = (home(key, m) + i) % m;
            const auto& s = slots[p];
            ++r.visits;
            if (s.state == Live && s.key == key) {
                r.found = p; return r;
            }
            if (s.state == Deleted && wrong) return r;
            if (s.state != Live && r.vacant < 0) r.vacant = p;
            if (s.state == Empty) return r;
        }
        return r;
    }
```

### A3：插入与删除

满表返回 `false`，没有越界写；重复键也返回 `false`。删除将状态改成墓碑。旧键字段即使还在，也不能被当作活键命中。

```cpp file=hash_lab.cpp
    bool insert(int key) {
        auto r = scan(key);
        if (r.found >= 0 || r.vacant < 0) return false;
        slots[r.vacant] = {Live, key};
        return true;
    }
    bool contains(int key) const { return scan(key).found >= 0; }
    bool erase(int key) {
        auto r = scan(key);
        if (r.found < 0) return false;
        slots[r.found].state = Deleted;
        return true;
    }
```

### A4：事务式重建

先构造临时表，成功搬完所有活键后才交换。容量不足不会破坏原表，且删除标记自然被丢弃。至此关闭 `Table` 类。

```cpp file=hash_lab.cpp
    bool rebuild(int capacity) {
        Table next(capacity);
        for (const auto& s : slots)
            if (s.state == Live && !next.insert(s.key)) return false;
        slots.swap(next.slots);
        return true;
    }
    std::size_t size() const {
        return std::count_if(slots.begin(), slots.end(),
            [](const Slot& s) { return s.state == Live; });
    }
};
```

### A5：对照桶链

这里固定七桶，便于与七槽表使用同一输入；链可以继续增长。`remove` 删除后不需要墓碑。虽然 `list.remove` 会移除所有相等项，但插入已保证唯一键。

```cpp file=hash_lab.cpp
struct Chain {
    std::vector<std::list<int>> buckets{7};
    bool contains(int key) const {
        const auto& b = buckets[home(key, 7)];
        return std::find(b.begin(), b.end(), key) != b.end();
    }
    bool insert(int key) {
        if (contains(key)) return false;
        buckets[home(key, 7)].push_back(key);
        return true;
    }
    bool erase(int key) {
        if (!contains(key)) return false;
        buckets[home(key, 7)].remove(key);
        return true;
    }
};
```

### 标准库散列表：历史目录不等于现代 API

原书冻结为第三版目录，其 5.6 是“Hash Tables in the Standard Library”。这不意味着历史正文已经使用今天的 C++17 API。本文的<Term def="按散列与相等关系组织元素、不保证排序的现代标准容器">无序容器</Term>示例是现代补充：`unordered_set` 存唯一键，`unordered_map` 存唯一键及值；多重版本才允许等价键重复。C++17 用 `find` 判断存在，不能偷用 C++20 的 `contains`。

`max_load_factor` 是负载策略；`reserve(n)` 按元素数量请求容量，`rehash(b)` 按桶数请求。实际桶数由实现选择，不可断言必为某个素数。重排会使迭代器失效，但不会使保留元素的指针或引用失效；删除目标元素另当别论。标准也没有要求内部必须采用本章的线性探查。

### A6：用键相等区分真正的碰撞

以下常量函数故意让全部键碰撞，却仍应保存两个不同键。`operator[]` 可能插入不存在的键；只想查找请用 `find`。程序在 `rehash` 后重新取得迭代器，而非访问失效的旧迭代器。

```cpp file=hash_lab.cpp
struct ConstantHash {
    std::size_t operator()(int) const { return 0; }
};
void standardCheck() {
    std::unordered_map<int, int, ConstantHash> counts;
    counts.max_load_factor(0.7f);
    counts.reserve(10);
    ++counts[5]; ++counts[12]; ++counts[5];
    assert(counts.size() == 2 && counts.at(5) == 2);
    counts.rehash(23);
    assert(counts.find(12) != counts.end());
    assert(counts.load_factor() <= counts.max_load_factor());
    counts.erase(5);
    assert(counts.find(5) == counts.end());
}
```

### A7：独立集合参照

参照只知道键集合，不复写我们的探查逻辑。每次操作后比较一个查询区间，并检查两边元素数。固定容量的表允许“满”失败，所以插入成功时才将键加入参照；边界测试还必须单独检验是否错误地提前报告满。

```cpp file=hash_lab.cpp
void compare(const Table& table, const std::unordered_set<int>& oracle) {
    assert(table.size() == oracle.size());
    for (int key = -30; key <= 30; ++key)
        assert(table.contains(key) == (oracle.count(key) != 0));
    for (int key : oracle) assert(table.contains(key));
}
void regression() {
    Table table;
    std::unordered_set<int> oracle;
    for (int key : {5, 12, 19, -1}) {
        assert(table.insert(key) == oracle.insert(key).second);
        compare(table, oracle);
    }
    assert(table.erase(12) == (oracle.erase(12) != 0));
    compare(table, oracle);
    assert(table.contains(19) && table.scan(19, true).found < 0);
    assert(!table.insert(19));
    assert(table.rebuild(11));
    compare(table, oracle);
    assert(table.scan(19).found == 8);
    assert(!table.rebuild(1));
    compare(table, oracle);
}
```

## 7. 可扩展散列：只分裂装不下的桶

<Term def="用可增长的位目录指向固定容量桶，溢出时只分裂相关桶的散列结构">
  可扩展散列
</Term>
面向动态增长的文件：目录项指向数据桶，多个目录项可以共用一个桶。与整张开放定址表重建不同，它尽量只重新分配溢出桶中的记录。这也是
[Fagin
等人的原始论文摘要](https://research.ibm.com/publications/extendible-hashinga-fast-access-method-for-dynamic-files)所述动态文件目标；这里不把摘要当作论文全文。

<Term def="整个目录当前用于索引的散列位数">全局深度</Term> g 决定目录有 `2^g`
项；<Term def="某个桶区分记录所使用的散列位数">局部深度</Term> ℓ 不超过
g。局部深度为 ℓ 的桶恰被 `2^(g-ℓ)`
个目录项引用。图使用低位，某些教材使用高位；只要分裂和寻址一致，两种约定都可以。

### 分裂与翻倍是不同动作

一个容量 2 的桶溢出时，按下一位将原桶记录分成两组，两个桶的 ℓ 都加一。若原先 ℓ 小于 g，已有目录位够用，只改指向这两个桶的相关引用；若原先 ℓ 等于 g，先将目录复制成两半、令 g 加一，再分裂桶。没有溢出的桶不会凭空多存一份记录。

本例 `index = ((key mod 2^g)+2^g) mod 2^g`，等价于取规范化整数的低 g 位。初始奇数桶装 1、3；插入 5 后 g=2，低位 01 桶装 1、5，11 桶装 3，而目录 00、10 仍共用偶数桶。这是实际位结构，不是“扩容”标题卡。目录接口与位不变量可对照 [CMU BusTub 的目录定义](https://raw.githubusercontent.com/cmu-db/bustub/master/src/include/storage/page/extendible_htable_directory_page.h)。

## 常见误区

<Callout type="trap" title="删除就清空">

**现象 →** 删除 12 后找不到仍存着的 19。**原因 →** 错把墓碑视为空槽。**修法 →** 查找越过墓碑，插入先排除重复键；用主图故障按钮比较实际路径。

</Callout>

<Callout type="trap" title="有空位就一定能插入">

**现象 →** 二次探查在 8 槽表里反复撞同三槽。**原因 →** 探查序列不覆盖全表，素数与负载前提被省略。**修法 →** 保留有界扫描并验证策略条件；线性探查的一圈保证不能借给其他策略。

</Callout>

<Callout type="trap" title="扩容只要 resize">

**现象 →** 新数组里键还在，却按新模数找不到。**原因 →** 地址规则变化，记录仍停在旧槽。**修法 →** 重插活键，丢弃墓碑；不要修改容器中参与散列的键。

</Callout>

<Callout type="trap" title="目录翻倍就是复制全部数据">

**现象 →** 目录增长后把每个桶的数据也复制一份。**原因 →** 把目录引用误认为记录。**修法 →** 图中跟随共享连线，只重分配溢出桶，并检查局部深度对应的引用数。

</Callout>

## 小结

- 地址碰撞不等于键相等，负载也不等于最坏探查次数。
- 删除留标记，再散列重插活键，用独立集合检查实现。
- 查找越过墓碑；局部深度小于全局深度时无需翻倍。

<Exercises>

**问题 1：同样的键，三种寻址规则会发生什么？**

容量 7，依次插入 5、12、19、-1，再删除 12。写出链式结构和线性表的状态、N/M 与 `(N+D)/M`，并预测查找 19 的正确与故障路径。若改用容量 8 的平方探查，从 0 出发为什么仍可能失败？

<Answer>

链式第 5 桶为 `[5,19]`，第 6 桶为 `[-1]`，其他链空；无需墓碑。线性表依次把四键放在 5、6、0、1，删除后槽 6 为墓碑。N=3、M=7、D=1，因此活负载 3/7、含墓碑占用比例 4/7；两个比例不是同一性能指标。

查找 19 正确访问 5、6、0，故障只访问 5、6。5 与 19 地址相同却不是同一键；`-1` 的规范化余数是 6，而非负数组下标。容量 8 的平方余数只取 0、1、4，若这三处已占用，其他五槽空着也无济于事。链式可以继续增长，开放定址必须处理容量上限。

</Answer>

**问题 2：改出“清理墓碑但不扩容”，并让参照程序揭穿错误修改。**

为 A1–A8 增加函数 `compact(Table&)`：容量不变，活键集合不变，所有墓碑清零。保存下列答案为 `exercise.cpp`，与 `hash_lab.cpp` 同目录，编译运行。随后把删除改成 `Empty`，或把 `rebuild` 改成仅 `resize`，原回归断言应失败；不要通过取消断言修测试。

<Answer>

直接复用事务式 `rebuild`，不需要另一套迁移算法。删除后槽 6 不能作为查询终点；清理后可以，因为 19 已按新表状态重插。测试同时检查集合、容量和墓碑数，而不是仅输出一句“成功”。

```cpp file=exercise.cpp
#define HASH_LAB_NO_MAIN
#include "hash_lab.cpp"
bool compact(Table& table) {
    return table.rebuild(static_cast<int>(table.slots.size()));
}
int main() {
    regression(); standardCheck();
    Table table;
    std::unordered_set<int> oracle{5, 19};
    for (int k : {5, 12, 19}) table.insert(k);
    table.erase(12);
    assert(compact(table));
    assert(table.slots.size() == 7);
    compare(table, oracle);
    for (const auto& s : table.slots) assert(s.state != Deleted);
    Table full(3);
    for (int k : {0, 3, 6}) assert(full.insert(k));
    assert(!full.insert(9) && full.scan(9).visits == 3);
    assert(full.erase(3) && full.insert(9));
    assert(!full.insert(6));
    std::cout << "compact ok\n";
}
```

运行 `clang++ -std=c++17 -Wall -Wextra -Werror exercise.cpp -o exercise && ./exercise`，应输出 `compact ok`。可进一步修改实验组件的再散列容量为当前表长，观察墓碑消失但容量不变。UI 模型保持键范围 -999–999；C++ 示例则允许全部 `int` 值。

</Answer>

**问题 3：目录为何只在部分分裂时翻倍，什么时候该选标准容器？**

目录实验初始已有 1、3；依次插入 5、9、7、11。写出最终 g、各桶的记录和局部深度，检查每个桶被多少目录项引用。再判断：内存里的用户编号计数与固定页容量的增长文件，哪个优先用 `unordered_map`，哪个适合研究可扩展散列？

<Answer>

5 使 g 从 1 到 2，9 又使 g 从 2 到 3。最终 B0 为空、ℓ=1，被 000、010、100、110 四项引用；B1 为 `[1,9]`、ℓ=3，对应 001；B3 为 `[5]`、ℓ=3，对应 101。另一个奇数分支先装 `[3,7]`，插入 11 后按位 2 分裂成 B2 `[3,11]` 对应 011、B4 `[7]` 对应 111，两者 ℓ=3。最后一次原局部深度为 2，小于 g=3，所以目录不翻倍。桶编号是本实验的分配顺序，不是算法通用常量。

内存计数优先选 C++17 `unordered_map`，并根据预计数量设置 `reserve`；不要为此维护磁盘目录。固定页容量且希望局部分裂的文件适合研究可扩展散列，但还需持久化和并发机制。不能从现代标准库名称推断它使用本实验的目录，也不能宣称第三版历史正文就采用了 C++17 接口。

</Answer>

## 名词解释

<Glossary>
  <GlossaryItem term="散列">
    先算候选位置，再核对键是否相等的查找方法。
  </GlossaryItem>
  <GlossaryItem term="散列函数">
    给同一键稳定地产生整数摘要；不同键允许摘要相同。
  </GlossaryItem>
  <GlossaryItem term="桶">根据索引找到的一个存储位置或一组记录。</GlossaryItem>
  <GlossaryItem term="碰撞">
    不同键要从同一个候选位置开始找，不代表键相等。
  </GlossaryItem>
  <GlossaryItem term="分离链接法">
    让一个桶中的冲突记录排成链，逐个比较。
  </GlossaryItem>
  <GlossaryItem term="负载因子">
    活键数除以桶或槽数，不包含已经删除的标记。
  </GlossaryItem>
  <GlossaryItem term="开放定址法">
    冲突记录继续在同一数组里寻找位置。
  </GlossaryItem>
  <GlossaryItem term="墓碑">
    删除留下的路标：此处可复用，但查找还得往后走。
  </GlossaryItem>
  <GlossaryItem term="聚集">
    连续占用段越长，后续键越容易被挤到同一段尾部。
  </GlossaryItem>
  <GlossaryItem term="二次探查">
    用平方偏移寻找后续槽；不保证遍历全部槽。
  </GlossaryItem>
  <GlossaryItem term="双重散列">
    第二个函数给出步长，步长与容量互素才能走遍槽。
  </GlossaryItem>
  <GlossaryItem term="再散列">
    更换地址规则后把活键重新插入，顺便清掉墓碑。
  </GlossaryItem>
  <GlossaryItem term="无序容器">
    现代 C++ 标准中按散列查找、不保证排序的一组容器。
  </GlossaryItem>
  <GlossaryItem term="可扩展散列">
    用增长的位目录管理固定容量桶，满桶局部分裂。
  </GlossaryItem>
  <GlossaryItem term="全局深度">
    整个目录使用多少位，g 位对应 2 的 g 次方个引用。
  </GlossaryItem>
  <GlossaryItem term="局部深度">
    一个桶已经用多少位区分记录，可小于目录使用的位数。
  </GlossaryItem>
</Glossary>
