## 从“代码外形不是设计技巧”开始

先预测：对硬币 4、3、1 凑出 6 时，每次取当前最大的硬币是否一定最优？这个贪心选择得到 4+1+1，共 3 枚；而 3+3 只要 2 枚。反例告诉我们，局部选择必须有额外证明，不能因为代码短就把它叫作正确。

本章的共同问题是“下一步如何减少不确定性”。选择题要留下 safe-choice 或反例，递归题要留下 recurrence 与边界，搜索题要留下 seed、约束和剪枝理由。这样才可以把一次运行变成可复核的工程证据。

<Callout type="trap" title="把一个成功样例当成全局正确性">
**现象 →** interval scheduling 的贪心样例成功，就直接把同一选择策略套到 coin change 或其他目标函数。

**原因 →** 不同问题需要不同的 greedy-choice property；局部最优只有在 exchange argument、cut property 或 stays-ahead 证明成立时，才可能推出全局最优。

**修法 →** 先写一个最小反例，再明确安全选择引理和剩余问题的最优子结构；没有证明时，把结论标成启发式并补充测试边界。

</Callout>

<Callout type="trap" title="用平均运行时间掩盖随机性和搜索失败">
**现象 →** 报告 randomized algorithms 的平均耗时，或报告 backtracking algorithms 找到一个解，就宣称算法一定正确且最优。

**原因 →** Las Vegas 与 Monte Carlo 的保证不同；回溯找到第一个解也不等于枚举完成或证明目标最优，错误的 pruning 还可能删掉唯一解。

**修法 →** 记录 seed、试验次数、error bound、搜索分支和剪枝不变量；把“找到一个”“数出全部”和“证明最优”分成不同验收合同。

</Callout>

<Term def="把问题拆成选择、子问题、随机性或搜索状态，并为每一步配上正确性与复杂度证据的一组方法。">
  算法设计技巧
</Term>
算法设计技巧不是递归、循环或某种数据结构的别名，而是对“如何缩小待证明的空间”做出的决定。先找反例，再选择证明对象，最后才决定代码形状，能避免把实现习惯误当作算法保证。

<Term def="在每一步选择当前看起来最安全的动作，并用交换、割或领先关系证明它不会损失全局最优。">
  贪心算法
</Term>
贪心算法 只在具有 greedy-choice property 和 optimal substructure
的问题上承诺最优。选择动作以后不回看并不是优点本身，关键是能把某个最优解交换成包含该动作的解。

<Term def="把一个问题拆成较小的子问题，分别求解，再用 combine 步骤合成原问题答案的结构。">
  分治
</Term>
分治 把 divide、conquer、combine 的成本写进
recurrence。子问题真的独立时，拆分能带来清晰的证明；如果子问题大量重叠，重复计算会提示我们改用动态规划。

<Term def="为重复出现的子问题定义状态和转移，保存已算结果，并按依赖顺序求出最终答案的方法。">
  动态规划
</Term>
动态规划 的首要工作不是选择 top-down 或 bottom-up，而是说清楚 state
的含义、transition 的来源、base case 和 evaluation
order。若还要恢复方案，就必须额外保存 choice 或 predecessor。

<Term def="使用随机选择改变运行路径，并显式报告结果保证、运行时间、随机种子和错误概率的算法。">
  随机化算法
</Term>
随机化算法 要区分 Las Vegas 与 Monte
Carlo：前者结果总正确但耗时随机，后者可能以小概率出错但通常能给出运行上界。没有
seed、trial 次数和概率假设的平均数字不可复现。

<Term def="沿着候选选择构造搜索树，遇到不满足约束的部分状态就回退，并只剪掉确定无法扩展的分支。">
  回溯算法
</Term>
回溯算法 的正确性依赖搜索树的完整性和剪枝安全性。apply 与 undo
必须对称；找到第一个解、枚举所有解、计数和求最优的返回控制也必须分开说明。

## algorithm design techniques

面对一个新问题，先写一张“证据责任表”：需要证明局部选择，还是需要处理重复状态；随机路径的保证是什么，还是必须完整探索约束空间。这个表比先套用某个熟悉的代码模板更能暴露未知前提。

统一流程是：构造最小反例，标出 state 或 choice，写出不变量和停止条件，最后用确定输入记录成本与结果。若任一环节说不清，就先把方案降级为启发式，而不是把不确定性藏进函数名。

## greedy algorithms

贪心算法 的最小证明通常有三步。第一，说明 greedy choice 在当前边界上是什么；第二，把任意最优解的第一项替换成该选择且不变差；第三，说明剩下的实例仍是同类问题。interval scheduling 选择最早结束的活动，就是为了给后续活动留下最长可用时间。

```cpp
std::sort(intervals.begin(), intervals.end(), byFinish);
Time end = minusInfinity;
for (const Interval& interval : intervals) {
    if (interval.start < end) continue;
    answer.push_back(interval);
    end = interval.finish;
}
```

这段循环只有在“最早结束者可以被交换进某个最优安排”的引理成立时才有全局保证。coin change 的反例则提醒我们：同样的“拿最大面值”动作，换一组 denomination 就可能失败。Dijkstra 还需要 nonnegative weights，Kruskal 需要 cut property，算法名字本身不是证明。

## divide and conquer

分治 的成本来自三个量：子问题数量、每个子问题的规模和拆分/合并工作。用 $T(n)=aT(n/b)+f(n)$ 表达时，a、b 和 f(n) 都必须对应真实代码，而不能只写一个熟悉的 Big-O。

这个式子在说：每一层产生 a 个规模缩小为 n/b 的工作，另外还要支付 f(n) 的边界成本。Mergesort 的 combine 是线性合并；bad quicksort 可能变成一边规模 n-1、另一边为空，因此平均表现不能替代最坏输入分析。

正确性可以用归纳法：假设每个 recursive call 得到正确子答案，再证明 combine 把它们合成为原问题答案。若子问题共享可变状态，所谓“独立”还要用 aliasing 测试验证；若大量重复，继续拆分只会浪费计算。

## dynamic programming

动态规划 先定义状态再写代码。以矩阵链为例，$m[i,j]$ 表示从矩阵 $A_i$ 到 $A_j$ 的最小标量乘法数，转移为

$$
m[i,j]=\min_{i\le k<j}\{m[i,k]+m[k+1,j]+c_{i-1}c_kc_j\}.
$$

这个式子在说：最后一次合并的位置 k 会把区间切成左右两个已经求好的子问题，再加上这次合并的代价。

```cpp
for (int length = 2; length <= n; ++length) {
    for (int left = 1; left + length - 1 <= n; ++left) {
        int right = left + length - 1;
        cost[left][right] = infinity;
        for (int split = left; split < right; ++split) {
            relaxSplit(left, split, right, cost, lastChange);
        }
    }
}
```

cost 记录最优值，lastChange 记录最优 split；只保存 cost 会让最终数值正确，却无法重建括号化方案。Top-down memoization 只访问 reachable states，bottom-up 则更容易检查 evaluation order 和 rolling memory。两种写法共享的是 state/transition 证明，不是表格外形。

## randomized algorithms

随机化算法 至少要报告四项：随机选择来自哪里、使用哪一个 seed、重复多少 trials，以及结果属于哪种保证。Las Vegas 算法可以随机选择 pivot 但返回结果必须正确；Monte Carlo 算法可以固定时间预算，但要给出错误概率和独立性假设。

若某个 witness 对 composite 的 false-pass probability 不超过 $1/4$，独立试验 t 次时，

$$
\Pr[\text{all false passes}]\le 4^{-t}.
$$

这个式子在说：只有每一次试验都误放行，整体才会失败，因此独立重复会指数降低 one-sided error；它不允许我们忽略坏的随机源或整数溢出。

```cpp
bool probablyPrime(Integer n, int trials, Random& random) {
    for (int i = 0; i < trials; ++i) {
        Integer base = random.uniform(2, n - 2);
        if (!passesWitness(base, n)) return false;
    }
    return true;
}
```

教学用 PRNG 适合展示路径，不等于 cryptographic entropy。测试记录 seed 和 sampled choices，生产实现还要检查 modular multiplication 的溢出边界。Expected $O(n\log n)$ 也不等于 deterministic worst-case，报告必须把平均、期望、最坏和错误概率分开。

## backtracking algorithms

回溯算法 把候选解组织成一棵搜索树。每次 apply(choice) 都要改变状态，每次失败或返回都要执行完全对称的 undo(choice)；constraint propagation、variable ordering 和 symmetry breaking 可以减少节点，但不能偷偷改变解集。

```cpp
bool search(State& state) {
    if (state.complete()) return state.accepts();
    for (Choice choice : state.candidates()) {
        if (!state.feasible(choice)) continue;
        state.apply(choice);
        if (search(state)) return true;
        state.undo(choice);
    }
    return false;
}
```

正确性来自搜索完整性：每个合法解都对应一条没有被错误剪掉的分支。若目标是求最优，还需要 branch-and-bound 的上/下界；若目标是枚举全部解，就不能在第一个 true 时提前停止。最坏成本常写成 $O(b^d)$，但实际节点数取决于约束传播和变量顺序，不能把剪枝后的观测值写成普遍保证。

## 代码实验：同一个问题的三种证据

把实验拆成三个确定的输入：一个让 greedy algorithms 失败的 coin change 例子，一个含重复状态的 Fibonacci 例子，以及一个会触发回溯 undo 的 N-Queens 前缀。每次运行都保存输入、选择、访问次数和返回合同，不要只保存最终答案。

```cpp
struct Evidence {
    std::string technique;
    std::string input;
    std::string invariant;
    std::size_t visits{};
};

Evidence greedyCounterexample() {
    return {"greedy algorithms", "coins={4,3,1}, amount=6",
            "largest coin is not a safe choice", 3};
}

Evidence dynamicState() {
    return {"dynamic programming", "fib(8)",
            "fib(n) is computed once", 9};
}

Evidence backtrackingPrefix() {
    return {"backtracking algorithms", "nqueens prefix=(0,2)",
            "apply and undo are symmetric", 4};
}
```

divide and conquer 的额外检查是把 recurrence 的每个参数和代码循环对应起来；randomized algorithms 的额外检查是重复同一 seed 并比较 sampled choices。若结果变化但 seed 没变，先查并发、未初始化内存或隐藏的时间输入，再讨论概率保证。

## 失败分诊与验收矩阵

1. **局部选择失败。** 先找最小反例；若不能给出 exchange argument、cut property 或 stays-ahead 关系，就把方案标成启发式。
2. **递推答案正确但无法恢复。** 检查 state 是否只保存 cost；需要路径时同步保存 split、choice 或 predecessor。
3. **随机或搜索结果不可复现。** 核对 seed、trial 次数、候选顺序、约束传播以及 apply/undo 是否对称。

| 验收层                  | 正常样本            | 边界样本               | 失败样本                 | 通过条件                       |
| ----------------------- | ------------------- | ---------------------- | ------------------------ | ------------------------------ |
| greedy algorithms       | interval scheduling | 相同结束时间、空输入   | coin change 选最大面值   | 安全选择与交换证明一致         |
| divide and conquer      | mergesort           | 不平衡 partition       | combine 漏元素           | recurrence 与代码成本对应      |
| dynamic programming     | matrix chain        | 不可达 state、重建路径 | 只存 cost                | state、transition、choice 完整 |
| randomized algorithms   | 固定 seed 的 trials | seed 改变、溢出边界    | 平均值冒充确定保证       | 记录保证类型与 error bound     |
| backtracking algorithms | N-Queens 合法分支   | 无解、全解枚举         | 剪掉唯一解或 undo 不对称 | 搜索完整且剪枝安全             |

## 本章回顾

- algorithm design techniques 先确定证明责任，再决定代码结构。
- greedy algorithms 需要安全选择证明，反例能快速揭露错误直觉。
- divide and conquer 要把 recurrence 的拆分、合并和边界成本对齐。
- dynamic programming 用 state、transition 和 choice 消除重复并恢复方案。
- randomized algorithms 与 backtracking algorithms 都必须保存失败路径，才能复核保证。

**问题 1：为什么 greedy algorithms 不能从一个成功样例推出全局最优？请用 coin change 反例，并比较 divide and conquer 的证明责任。**

<Answer>
  coin change 的 4、3、1 凑 6 时，先取 4 得到 4+1+1，而 3+3 更少；因此没有
  safe-choice proof 就不能承诺最优。divide and conquer
  则要说明子问题假设成立后，combine 如何保持原问题目标，并把 recurrence
  参数和代码成本对应起来。
</Answer>

**问题 2：把一个递归算法改成 dynamic programming 时，哪些信息必须保留？randomized algorithms 的 seed 又解决什么问题？**

<Answer>
  先定义 state 的含义和 transition，再保存重复 state
  的结果；若要恢复具体方案，还要保存 split、choice 或 predecessor。seed 让
  randomized algorithms 的 sampled choices 可以重放，但它不会把 Monte Carlo
  保证变成 Las Vegas 保证。
</Answer>

**问题 3：请修改下面的搜索实验，让 backtracking algorithms 枚举全部解，并为一次 divide and conquer 或 algorithm design techniques 选择写出验收证据。**

<Answer>
  把找到第一个解就返回的控制改成收集当前解后继续遍历其余候选，并确保每个分支返回前执行
  undo。验收记录应包含输入、约束、递推或安全选择不变量、访问节点数和一个失败分支；不能只记录最终解。
</Answer>
