## 从“代码外形不是设计技巧”开始

算法设计技巧（）不能只按“有没有递归”分类。Quicksort 和 mergesort 都递归，却因 partition/combine 不同而有不同风险；memoized recursion 与 bottom-up table 外形不同，却实现同一 dynamic-programming recurrence。

先预测 coin denominations 4、3、1 凑6。每次取最大 coin 的 greedy 得到4+1+1共3枚，而最优是3+3共2枚。局部选择“看起来最好”不构成证明；必须说明为什么某个 optimal solution 可 exchange 成包含该选择。

官方结构是总题 **Algorithm Design Techniques**，随后五节 **Greedy Algorithms、Divide and Conquer、Dynamic Programming、Randomized Algorithms、Backtracking Algorithms**。下面用同一套问题核查它们：state 是什么、做什么 choice、是否回看、如何证明、最坏输入是什么。

## 10.1 Greedy Algorithms

贪心算法（）适合拥有 greedy-choice property 和 optimal substructure 的问题。常见 proof patterns：

- exchange argument：把任意 optimal solution 的第一选择替换成 greedy choice，不变差；
- cut property：跨某个 cut 的 minimum edge 是 safe；
- stays ahead：证明 greedy prefix 在每一步不落后于任何 competitor。


以 interval scheduling 为例，每次选最早结束且与已选 intervals compatible 的活动：

```cpp
std::sort(intervals.begin(), intervals.end(), byFinish);
Time end = minusInfinity;
for (const Interval& interval : intervals) {
    if (interval.start < end) continue;
    answer.push_back(interval);
    end = interval.finish;
}
```

Exchange proof 把 optimal schedule 的首活动换成最早结束者，它不会减少余下可用时间。相反，coin change 只在特定 denomination systems 成立，不能从几个示例归纳 universal correctness。

Greedy 在 Huffman coding、Kruskal/Prim、Dijkstra 中也出现，但 safe-choice lemma 各不相同。Dijkstra 还需要 nonnegative weights；算法名字不是免检前提。


## 10.2 Divide and Conquer

分治（）包含 divide、conquer、combine。成本由 recurrence 决定：

$$
T(N)=aT(N/b)+f(N)
$$

其中 a 是 subproblem 数，N/b 是规模，f(N) 是 split/combine work。Mergesort 是 `2T(N/2)+Theta(N)`；balanced binary search 是 `T(N/2)+Theta(1)`；bad quicksort 是 `T(N-1)+Theta(N)`。


正确性通常用 induction：假设 recursive calls 正确，再证明 combine 保持目标。Subproblems 若严重 overlap，纯 recursion 会重复计算；这提示转向 DP。Subproblems 若共享可变 state，所谓“独立”也可能被 aliasing 破坏。

第3版示例包含 matrix multiplication、Fibonacci 等，用来区分算法结构和 asymptotic improvement。Matrix divide 只有在 block arithmetic 与 cutoff 合理时才兑现理论收益；小 sizes 的 constants 与 cache layout 仍重要。

## 10.3 Dynamic Programming

动态规划（）先写 state meaning，再写 transition、base cases 与 evaluation order。第3版 `Fig10_43` 的递归 `eval(n)` 反复计算所有更小 `eval(i)`；`Fig10_45` 用 table 保存结果，消除 exponential duplication。

Matrix-chain multiplication 给 dimensions `c0...cn`，state `m[i,j]` 是矩阵 Ai 到 Aj 的 minimum scalar multiplications：

$$
m[i,j]=\min_{i\le k<j}
\left(m[i,k]+m[k+1,j]+c_{i-1}c_kc_j\right)
$$


第3版 `Fig10_46.cpp` 按 chain length k 增长填 upper triangle，并把最优 split 存入 `lastChange`。只存 cost 不能重建 parenthesization：

```cpp
for (int length = 2; length <= n; ++length)
    for (int left = 1; left + length - 1 <= n; ++left) {
        int right = left + length - 1;
        cost[left][right] = infinity;
        for (int split = left; split < right; ++split)
            relaxSplit(left, split, right, cost, lastChange);
    }
```

State 必须包含影响 future choices 的全部信息，又不能把 history 原样塞入导致 state explosion。Top-down memoization 容易从 recurrence 写出且只访问 reachable states；bottom-up 便于控制 order、memory rolling 和 cache locality。


## 10.4 Randomized Algorithms

随机化算法（）分两类：

- Las Vegas：结果总正确，runtime 随机，如 randomized pivot quicksort；
- Monte Carlo：runtime受控，允许小概率错误，如 repeated primality witnesses。

第3版 `Fig10_62.cpp` 的 witness test 若发现 nontrivial square root of 1，就确定 composite；若若干随机 bases 都通过，只能说 probably prime。若每次对 composite 的 false-pass probability 至多1/4，独立 t 次：

$$
\Pr[\text{all false passes}]\le 4^{-t}
$$


```cpp
bool probablyPrime(Integer n, int trials, Random& random) {
    for (int i = 0; i < trials; ++i) {
        Integer base = random.uniform(2, n - 2);
        if (!passesWitness(base, n)) return false;
    }
    return true;
}
```

Seed 决定 reproducibility；测试应记录 seed 和 sampled choices。Cryptographic use 需要 cryptographically secure entropy 与 overflow-safe modular multiplication，不能直接复用教学 PRNG 和窄 integer arithmetic。

Expected O(N log N) 不等于 deterministic worst-case；error bound 也依赖 trials independence 和 witness theorem。报告必须说清 guarantee 类型。

## 10.5 Backtracking Algorithms

回溯算法（）适合 constraint satisfaction、排列、N-Queens、turnpike reconstruction 等。基本 skeleton：

```cpp
bool search(State& state) {
    if (state.complete()) return state.accepts();
    for (Choice choice : state.candidates()) {
        if (!state.feasible(choice)) continue;
        state.apply(choice);
        if (search(state)) return true;
        state.undo(choice);
    }
    return false;
}
```


Correctness 来自搜索树 completeness：每个 solution 对应某条 branch；safe pruning 只删除无法扩展成 solution 的 partial states。`apply/undo` 必须完全对称，特别是多个 indexes、counts 和 sets 同时变化时。

Worst-case 通常 exponential：

$$
T(d)=O(b^d)
$$

但 variable ordering、constraint propagation、symmetry breaking 和 lower bounds 可大幅减少实际 nodes。Branch-and-bound 在 feasibility pruning 外，再用 objective bound 删除不可能优于 incumbent 的分支。

找到第一个 solution、枚举全部 solutions、计数和求最优需要不同返回控制。误把“找到一个”当“证明最优”是常见 contract error。

## 本章回顾

1. Design technique由choice、subproblem和proof structure定义，不由代码外形定义。
2. Greedy需要safe-choice证明；局部最优样例不能替代exchange/cut argument。
3. Divide-and-conquer成本由recurrence中a、b和combine work共同决定。
4. DP以state/transition消除overlap，并另存choice才能重建solution。
5. Randomized algorithm必须区分Las Vegas、Monte Carlo、expected runtime与error bound。
6. Repeated independent trials可指数降低one-sided error，但seed和arithmetic仍要验证。
7. Backtracking以complete search保证正确，以safe pruning减少nodes，worst-case仍可exponential。
