## 从“昂贵的一次不代表昂贵的一串”开始

先预测：容量从 1 开始、满时翻倍，连续插入 8 个元素时，扩容搬移了多少旧元素？扩容到 2、4、8 时分别搬 1、2、4 个，总搬移 7；第 5 次插入虽然单次搬 4 个，但前 8 次的总成本仍与操作数量同阶。

这就是均摊分析的视角：允许一次 operation 很贵，但要证明这种尖峰不会在同一个 sequence 中无限频繁地出现。证明对象不是“随机抽一个操作的平均耗时”，而是从初始状态到最终状态的总 actual cost。

<Callout type="trap" title="把均摊分析写成 average-case probability">
**现象 →** 看到动态数组扩容的总成本是线性，就说每次 push 都是概率意义上的 O(1)，或把一次 resize 的 4 个搬移忽略掉。

**原因 →** amortized analysis 不依赖输入分布；它用 aggregate、credit 或 potential 约束一整段操作序列，单次操作仍可能很贵。

**修法 →** 明确 sequence、初始势能和最终势能，逐项列出 actual cost 与 amortized cost；若需要概率假设，再单独标成 average-case 分析。

</Callout>

<Callout type="trap" title="只背势能公式，不检查结构不变量">
**现象 →** 直接把 Phi 写成 root 数或 marked 数，却没有验证 link、cut、rotation 后势能的变化方向。

**原因 →** 势能必须足够非负且能支付未来工作；错误的函数可能让某次操作的 amortized cost 变成负数，或漏掉结构维护成本。

**修法 →** 先定义状态，再逐种操作计算 actual cost 和 ΔPhi；用一个最小序列重放 root、mark、child 和 parent 指针的变化。

</Callout>

<Term def="为一串操作而不是单次操作建立总成本上界的方法；它不要求每一次操作都便宜。">
  均摊分析
</Term>
均摊分析
把昂贵操作看成对整个序列的负债。只要初始势能为零、势能始终非负，并且每次的
amortized cost 能覆盖 actual cost，整串上界就成立，不需要假设输入均匀随机。

<Term def="用间接的相遇时间代替逐段追踪轨迹，从而把无限往返过程化成一个简单方程的小谜题。">
  无关谜题
</Term>
无关谜题
看似与数据结构无关，却展示了“引入一个合适状态变量”的思想。先求两只猫相遇的时间，再求母猫飞行距离，比逐段加越来越短的距离更容易核对。

<Term def="把不同秩的二项树组织成森林，插入时像二进制加一一样合并相同秩树的优先队列结构。">
  二项队列
</Term>
二项队列 的长插入会连续 link，像 binary counter 的 carry 一样形成一次尖峰。用
forest 中 root 的数量作为状态，就能说明每次 link 消除的 root
为未来操作积累了支付空间。

<Term def="合并时沿右路径访问并无条件交换孩子的堆；单次路径可能很长，但重排会让后续路径变短。">
  斜堆
</Term>
斜堆 不保存 leftist heap 那样的显式 rank。它用 heavy/light
的路径论证或势能变化解释 merge 的均摊界，不能把一次观察到的短 right path
当成不变量。

<Term def="延迟整理根链表并用 marked 节点和 cascading cut 管理 decrease-key 的堆。">
  斐波那契堆
</Term>
斐波那契堆 把合并和插入的整理工作延迟到 delete-min，再用 roots 数和 marked
nonroots 数构成势能。degree 与子树大小的关系保证整理时的 degree table
不会无限增长。

<Term def="访问节点后把它旋到根附近的自调整搜索树；它不承诺每次访问便宜，而是对访问序列给出均摊界。">
  伸展树
</Term>
伸展树 用 zig、zig-zig 和 zig-zag 旋转把访问历史反馈到形状中。subtree size 的
rank potential 支付长旋转，正确性还要求旋转保持 inorder 顺序和 parent 指针。

## amortized analysis

均摊分析有三种等价的证明习惯。aggregate method 直接界定一段 sequence 的 total actual cost；accounting method 给便宜操作预收 credit；potential method 为状态 D 定义 Phi(D)，并使用
$\widehat c_i=c_i+\Phi(D_i)-\Phi(D_{i-1})$。

这个式子在说：本次 actual cost 加上状态储能的变化，就是本次可以向整串预算收取的 amortized cost。若 Phi(D0)=0 且 Phi(D) 始终非负，则所有 actual costs 之和不超过所有 amortized costs 之和。势能不是漂亮的标签，必须对每一种状态迁移都算得清楚。

## unrelated puzzle

无关谜题描述两个小猫在 100 yards 球场两端以每分钟 10 yards 相向而行，母猫以每分钟 100 yards 在两者之间往返，直到两只小猫相遇。逐段追踪母猫会得到一个无限几何级数；引入相遇时间 t 则只需解

$$
t=\frac{100}{10+10}=5\ \text{minutes},\qquad d=100t=500\ \text{yards}.
$$

这个式子在说：先求终止状态的时间，再把重复轨迹投影成一次乘法。无关谜题本身不是数据结构证明，但它训练我们为一串复杂变化寻找足够而不冗余的状态变量。

## binomial queues

二项队列把 B0 singleton 组织成不同秩的 forest。插入新 singleton 时，低秩位置若已被占用就 link 两棵相同秩的树，直到找到空位；这正如 binary counter 加一。一次插入可能做很多次 link，但 root-count potential 会同步下降。

```cpp
void insert(Key key) {
    Tree* carry = singleton(key);
    for (std::size_t rank = 0; carry != nullptr; ++rank) {
        if (roots[rank] == nullptr)
            std::swap(roots[rank], carry);
        else {
            carry = link(roots[rank], carry);
            roots[rank] = nullptr;
        }
    }
}
```

如果插入前低 k 个秩都已有树，实际工作约为 k+1，而 root 数从 k+1 变成 1，势能变化约为 1-k；两者相加是常数级。merge 还要考虑两棵 forest 的 bit pattern，delete-min 则要找到最小 root、拆出 children 并重新合并，证明边界不同于 insert。

## skew heaps

斜堆的 merge 沿两个 right paths 递归，单次访问可以是 linear。分析把访问到的节点按子树大小分为 heavy 与 light：沿一条 root-to-leaf 路径，light edge 的数量受子树规模翻倍约束，因此至多 logarithmic。

合并后无条件交换左右孩子，许多旧的 right-heavy 节点会离开下一次 right path。势能可以记录 heavy nodes 数，actual cost 中的 heavy visits 由势能下降支付，剩下的 light visits 与势能增长共同形成均摊 logarithmic 边界。

这里不能声称每次 right spine 都短；那是 leftist heap 的结构性质。skew heaps 的承诺是 sequence bound，必须用多个交替 merge 的输入重放，而不是只测一个随机顺序。

## Fibonacci heaps

斐波那契堆通过 lazy consolidation 推迟整理：insert 和 meld 只拼接 root lists，delete-min 才把最小节点的 children 提升到 root list 并按 degree 合并。decrease-key 若破坏 heap order，就执行 cut；parent 首次丢 child 时 mark，继续丢失才触发 cascading cut。

常用势能是

$$
\Phi(H)=t(H)+2m(H),
$$

其中 t 是 root 数，m 是 marked nonroot 数。这个式子在说：root 增长和 marked 节点都代表未来要支付的结构工作，cascading cut 把 marked 变成 root 时会释放已经积累的势能。

```cpp
void decreaseKey(Node* x, Key key) {
    x->key = key;
    Node* parent = x->parent;
    if (parent && x->key < parent->key) {
        cutToRoot(x, parent);
        cascadingCut(parent);
    }
    if (x->key < minimum->key) minimum = x;
}
```

degree d 的节点必须拥有足够大的子树，才能保证 degree bound 为 logarithmic；这一步是 delete-min consolidation 的前提。Fibonacci heaps 的指针和常数成本较高，只有 decrease-key、meld 比例和规模都合适时，渐近优势才可能在基准中出现。

## splay trees

伸展树不保存 height 或 color，而是在访问后执行 zig、zig-zig、zig-zag。一次 access 可能沿长路径旋转很多次，但经常访问的节点会靠近根，访问序列的总成本可以被 rank potential 约束。

令 s(x) 为节点子树大小，rank 为 $r(x)=\log_2 s(x)$，整棵树的势能为

$$
\Phi(T)=\sum_{x\in T}\log_2 s(x).
$$

这个式子在说：大子树携带更多结构信息；旋转改变节点的子树规模，也就释放或积累了可用于支付未来旋转的势能。access lemma 给出一次伸展的均摊界，而不是每次旋转的最坏界。

```cpp
while (x->parent != nullptr) {
    Node* parent = x->parent;
    Node* grand = parent->parent;
    if (!grand) rotate(x);
    else if (sameDirection(x, parent, grand)) {
        rotate(parent);
        rotate(x);
    } else {
        rotate(x);
        rotate(x);
    }
}
```

每次旋转都必须保持 BST inorder sequence 和 parent pointers。一次 access 的实际路径很长时，不能说实现错误；要检查的是 rank 变化是否支付了序列中的总 rotation cost，以及 benchmark 是否包含重复访问、扫描访问和最坏构造。

## 代码实验：把一次尖峰放回 sequence

用固定操作序列测试动态数组或 root forest：先执行若干便宜操作，再刻意触发一次 resize、link、consolidate 或 rotation。日志至少包含 operation、actual cost、state summary、Phi before、Phi after 和 amortized cost；不要只输出一个总数。

```cpp
struct AmortizedEvent {
    std::string operation;
    std::size_t actual{};
    std::size_t phiBefore{};
    std::size_t phiAfter{};
};

AmortizedEvent resizeEvent() {
    return {"resize", "4", "3", "1"};
}

long long amortized(const AmortizedEvent& event) {
    return static_cast<long long>(event.actual)
         + static_cast<long long>(event.phiAfter)
         - static_cast<long long>(event.phiBefore);
}
```

对 binomial queues，检查每个 link 是否减少 root count；对 skew heaps，记录 right-path 上的 heavy/light 分类；对 Fibonacci heaps，记录 roots 和 marks；对 splay trees，记录访问前后每个相关子树的 size。这样才能把图示变成可复核的证据包。

## 失败分诊与验收矩阵

1. **势能为负或尖峰未被支付。** 检查初始势能、非负条件和每个状态迁移的 ΔPhi；错误函数应立即被最小序列暴露。
2. **堆的实现通过单次测试却失去序列边界。** 用重复 merge、decrease-key、delete-min 和交替访问构造结构债务，而不是只测均匀随机输入。
3. **均摊保证被误读成单次保证。** 把 actual cost、amortized cost、总 sequence bound 和 benchmark 结果分成四列报告。

| 验收层             | 正常样本                   | 边界样本                    | 失败样本                 | 通过条件                               |
| ------------------ | -------------------------- | --------------------------- | ------------------------ | -------------------------------------- |
| amortized analysis | 动态数组扩容               | 初始容量、空序列            | 把平均概率当均摊         | sequence、初始势能和总式完整           |
| unrelated puzzle   | 直接求相遇时间             | 无限分段、单位换算          | 逐段求和漏项             | 状态变量与终止条件清楚                 |
| binomial queues    | 连续插入与 link            | 长 binary carry             | root count 变化不符      | potential 下降支付 link                |
| skew heaps         | 交替 merge                 | 长 right path               | 误写成每次 logarithmic   | heavy/light 与序列重排一致             |
| Fibonacci heaps    | decrease-key 后 delete-min | cascading cut、空 root list | mark 未清理、degree 越界 | roots、marks、degree bound 可复核      |
| splay trees        | 重复访问热点               | 扫描序列、单次长路径        | 旋转破坏 inorder         | rank potential 与 access sequence 对齐 |

## 本章回顾

- amortized analysis 约束的是一串 actual cost，不是一次操作的平均概率。
- aggregate、accounting、potential 是三种互相校验的证明视角。
- unrelated puzzle 展示了用间接状态变量替代无限逐段追踪。
- binomial queues、skew heaps、Fibonacci heaps 把结构债务放在不同状态里。
- splay trees 用 rank potential 支付访问序列中的旋转尖峰。

<Answer>
  aggregate method 直接求整个 push sequence 的搬移总量；accounting method

  resize

**问题 2：binomial queues、skew heaps 和 Fibonacci heaps 的结构债务分别放在哪里？**

<Answer>
  binomial queues 把 binary carry 体现为 root 数和 link；skew heaps 用

  nonroots 和 lazy consolidation
  放进势能。三者都必须验证状态变化和未来操作的支付关系，不能把单次尖峰删掉。

  记录访问前后的 subtree size、每次 zig、zig-zig、zig-zag rotation、Phi(T)
  变化和后续重复访问成本。一次 access 的 actual cost 可以很高；只有把它放回完整
  sequence，使用 rank potential 和 access lemma 计算总 amortized
