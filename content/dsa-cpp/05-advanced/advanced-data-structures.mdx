## 从“复杂结构必须能逐项验不变量”开始

高级数据结构与实现（<Term def="通过更精细invariants、sentinels、randomization或multiway links优化特定operations，并承担更高验证成本。">高级数据结构与实现</Term>）不是“比基础结构更高级所以更快”。Red-black tree 给 worst-case ordered-map bound；treap 给 expected balance；k-d tree服务空间查询；pairing heap服务meld/decrease-key。需求不匹配时，复杂度只会增加故障面。

先预测一个实现只通过 inorder sorted 测试，能否证明 red-black tree 正确。不能：连续 red nodes 或 black-height 不等仍可保持 BST order，却让 height bound失效。Advanced structure至少要同时验证semantic order与structure-specific invariants。

官方七节是 **Top-Down Splay Trees、Red-Black Trees、Deterministic Skip Lists、AA-Trees、Treaps、k-d Trees、Pairing Heaps**，总题为 **Advanced Data Structures and Implementation**。作者公开代码也明确说明是2005年的教学实现，部分 remove、copy 或 reclaim routines 留作练习。

## 12.1 Top-Down Splay Trees

自顶向下伸展树（<Term def="在search下降途中完成rotations并把smaller/larger fragments暂挂到header两侧，最后assemble的splay实现。">自顶向下伸展树</Term>）避免先保存整条 parent path。临时 header 的 left/right 分别构建大于与小于 target 的 fragments，current 保留尚未分类 subtree。

<DsaTopDownSplayLab />

每轮可能先做 zig-zig rotation，再把 current 链接到对应 fragment。结束时把 current.left/right 与 fragments 余部拼回：

```cpp
leftTreeMax->right = current->left;
rightTreeMin->left = current->right;
current->left = header.right;
current->right = header.left;
root = current;
```

无论 target found 与否，最后访问 node 被 splay 到 root。Assembly 必须保持所有 left keys smaller、right keys larger；header 只是临时哨兵，不能泄漏进真实 tree。

Top-down implementation仍继承第11章 amortized bound，不给每次 logarithmic height。连续 locality-heavy accesses是其优势，strict worst-case latency不是。

## 12.2 Red-Black Trees

红黑树（<Term def="以node color、禁止red-red和equal black-height约束BST高度的worst-case logarithmic search tree。">红黑树</Term>）通常要求：

1. 每个 node 是 red 或 black，root black；
2. null leaves black；
3. red node 的 children 都 black；
4. 从任意 node 到 descendant null leaves 的 black count 相同。

<DsaRedBlackInvariantLab />

若 tree black height 为 bh，至少有 `2^bh-1` internal nodes；任何 path red/black 交替，最长最多是最短的两倍，因此：

$$
n(0)=0,\qquad n(bh)\ge 2n(bh-1)+1=2^{bh}-1
$$

再由最长 root-to-leaf path至多包含每个black node旁的一个red node，可得：

$$
h\le 2\log_2(N+1)
$$

第3版 `RedBlackTree.h` 的 top-down insertion 在下降时发现 current 有两个 red children就 color flip；若 parent也 red，再按 LL/LR/RL/RR rotation 修复。`header` 保存 negative-infinity sentinel，`nullNode` 作为所有 leaves，并把 search key 临时写入 sentinel element 终止 loop。

```cpp
current->color = RED;
current->left->color = BLACK;
current->right->color = BLACK;
if (parent->color == RED)
    rotateAndRecolor(item, great, grand, parent, current);
header->right->color = BLACK;
```

忠实边界：官方第3版文件的 `remove` 明确只打印 unimplemented，不能把本章对 deletion cases 的概念说明伪装成该文件已经提供完整删除实现。Sentinel key还要求构造时给出不大于所有真实 keys 的 `negInf`。

<Callout type="trap" title="只验证BST inorder">
Color flip或rotation遗漏可能仍输出sorted keys，却破坏red-red或black-height。每次mutation后应递归返回black height，发现左右不等立即失败，并单独检查root black与parent pointers。
</Callout>

## 12.3 Deterministic Skip Lists

确定性跳表（<Term def="以bounded gap invariant决定promotion层级，用right/down links提供worst-case logarithmic ordered search的skip structure。">确定性跳表</Term>）用层级 linked lists 模拟 balanced search。与 randomized skip list按概率晋升不同，它在 gap size 达到3时提升 middle element，使每层相邻 promoted nodes间底层gap受控。

<DsaDeterministicSkipListLab />

Search 从 top header 开始：key较小就 down，key较大就 right，equal则 found。Bounded gaps让每下降一层只需常数 right moves，levels O(log N)，所以 search/insert logarithmic。

第3版 `DSL.h` 使用 `header`、`tail(INFINITY)` 与可写 `bottom` sentinel消除 null checks；公开实现把 copy constructor、assignment、remove 和 reclaimMemory 留作未实现练习。直接析构该示例会打印泄漏提示，因此只能作为算法骨架，不能当 resource-safe container。

## 12.4 AA-Trees

AA树（<Term def="把red-black tree限制为只有right horizontal links，并用level、skew与split统一平衡cases的BST。">AA树</Term>）把 red nodes解释为与 parent 同 level 的 horizontal link，但只允许向右，且不能连续两个 right horizontal links。

<DsaAATreeSkewSplitLab />

`skew` 在 left child level 等于 node level 时右旋，消除 left horizontal link；`split` 在 right-right grandchild同 level 时左旋并提升新 root level：

```cpp
void rebalance(Node*& node) {
    skew(node);
    split(node);
}
```

Insert recursion返回时依次 skew/split。Delete 更复杂：下降并替换目标后降低不合法 levels，再对 node、right、right-right执行 skew，最后 split node和right。

官方 `AATree.h` deletion使用 function-local static `lastNode/deletedNode`，这会影响 reentrancy、thread safety和exception reasoning。教学上展示算法状态，production实现应把状态放入operation context。

## 12.5 Treaps

树堆（<Term def="同时按key保持BST order、按独立random priority保持heap order，以randomization获得expected logarithmic height。">树堆</Term>）给每个 inserted key 一个随机 priority。Keys唯一时，key+priority集合基本唯一决定shape；priority ordering使shape像random BST。

<DsaTreapDualOrderLab />

Insert先按 key递归，到达 leaf后若 child priority小于 parent，就 rotation把它上提。Expected height：

$$
\mathbb E[h]=O(\log N)
$$

Delete可把目标不断与较小-priority child rotation，直到 leaf后删除。Random priorities碰撞需要tie policy；untrusted可预测PRNG也可能被对抗。复现测试应记录seed/priorities，而不是只记录keys。

Treap比red-black实现短，但保证是expected，不是deterministic worst-case。Official `Treap.h` 的注释摘要与实际remove body存在不一致，更说明验收应读真实实现而非只信header comment。

## 12.6 k-d Trees

k-d树（<Term def="在k维points上按depth轮换split dimension，并用axis-aligned regions剪枝range或nearest queries的空间tree。">k-d树</Term>）把 multidimensional ordering分散到各 levels。第3版 `KdTree.cpp` 是二维教学实现：level 0比较 x，level 1比较 y，然后交替。

<DsaKdRangeLab />

Orthogonal range query若 node point在每个dimension都落入 low/high就输出；只有 query low不大于当前split value才访问 left，query high不小于split value才访问 right：

```cpp
if (low[axis] <= node->point[axis])
    range(node->left, 1 - axis, low, high);
if (high[axis] >= node->point[axis])
    range(node->right, 1 - axis, low, high);
```

Balanced且低维时剪枝有效；sorted insertion可退化，维度升高时curse of dimensionality让大量regions与query相交，接近linear scan。Nearest-neighbor还需按bounding-box distance决定远侧subtree是否可能改进best。

对近似balanced的二维tree，典型axis-aligned range reporting可写成输出敏感界，其中K是实际返回的points数：

$$
T(N,K)=O(\sqrt N+K)
$$

这个界不是任意shape与任意dimension的保证；若插入顺序让tree退化，或dimension升高导致regions大量相交，查询仍可能访问线性数量的nodes。

## 12.7 Pairing Heaps

配对堆（<Term def="以heap-ordered multiway tree、constant-time link和two-pass sibling combining实现简洁meldable priority queue。">配对堆</Term>）的 basic `compareAndLink` 比较两个 roots，把较大 root作为较小 root的leftmost child。Insert把singleton与root link，并返回 Position handle。

<DsaPairingHeapMergeLab />

DeleteMin移除root后，对children做 two-pass merge：left-to-right两两link，再right-to-left fold结果。单向连续link可能产生不理想shape，两遍策略是实现核心。

Decrease-key通过 Position 找到 node，若key降低后不是root，就从sibling list cut并与root link。Handle必须仍属于该 heap且未删除；official code不做完整ownership validation，错误或stale Position会损坏prev/next links。

```cpp
for (std::size_t i = 0; i + 1 < trees.size(); i += 2)
    trees[i] = link(trees[i], trees[i + 1]);
for (std::ptrdiff_t i = static_cast<std::ptrdiff_t>(lastPair); i >= 2; i -= 2)
    trees[i - 2] = link(trees[i - 2], trees[i]);
```

理论上 pairing heap许多operations有优秀amortized bounds，且常数通常比 Fibonacci heap小；但具体 decrease-key bound和variant需精确陈述，不能笼统照搬另一种 heap的复杂度表。

<Callout type="trap" title="忽略Position生命周期">
Pairing heap的decreaseKey接收insert返回的node handle。Node被deleteMin、heap析构或转移后handle失效；跨heap传入也非法。Public API应记录ownership/generation或把precondition明确限制在受控调用层。
</Callout>

## 本章回顾

1. Advanced structure必须由具体operation mix和可验证invariants支撑。
2. Top-down splay在下降时拆smaller/larger fragments并最后assemble。
3. Red-black通过color与equal black-height给worst-case logarithmic height。
4. Deterministic skip list用bounded gaps取代random promotion。
5. AA-tree把平衡规范成skew与split，但deletion/reentrancy仍需谨慎。
6. Treap同时保持BST key order和random-priority heap order，给expected balance。
7. k-d tree轮换dimensions并按region intersection剪枝，可能因shape或高维退化。
8. Pairing heap用constant-time link与two-pass deleteMin，Position带来lifetime contract。
9. 第3版官方代码包含明确未实现练习，不能直接标为production complete。

<Exercises>

**问题 1：red-black tree有N个internal nodes，为什么height至多约2log2(N+1)？**

<Answer>Black height为bh的subtree至少含2^bh-1个internal nodes；red node不能连续，所以任一路径长度最多2bh。由N至少2^bh-1得bh不超过log2(N+1)，故h不超过2log2(N+1)。</Answer>

**问题 2：AA-tree中skew与split分别修复什么？**

<Answer>Skew在left child与node同level时右旋，消除非法left horizontal link；split在连续两个right links同level时左旋并提升新root level，消除double-right horizontal chain。</Answer>

**问题 3：treap为何需要同时检查两种ordering？**

<Answer>Key BST order保证search语义，priority min-heap order保证randomized shape。Rotation必须保持inorder keys同时恢复priority；只查其中一个可能得到能遍历却高度退化或根本不可正确search的tree。</Answer>

**问题 4：pairing heap删除有7个children的minimum时two-pass如何进行？**

<Answer>第一遍left-to-right把前6棵两两link成3棵，第7棵保留，共4个结果；第二遍从right向left依次link，直到得到一个root。具体实现会处理odd tail再反向fold。</Answer>

</Exercises>
