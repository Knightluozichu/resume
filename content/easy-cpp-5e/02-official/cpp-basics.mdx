## 从一份能运行的骨架开始

上一课已经打通构建和运行路径，现在要开始读懂源代码。C++ 程序由声明、定义和语句等结构组成；操作系统从程序入口开始执行，而入口由名为 `main` 的函数提供。最小骨架不是必须死背的模板，而是一组责任清楚的部件。

```cpp
#include <iostream>

int main() {
    std::cout << "Welcome to C++\n";
    return 0;
}
```

`#include <iostream>` 让当前翻译单元看到标准流设施的声明。`int main()` 定义入口，花括号限定函数体。输出语句把字符送到标准输出，`return 0` 把成功状态交还运行环境。缩进不会改变 C++ 语义，却能让层级一眼可见。

<Term def="程序开始执行的约定入口函数；它返回整数退出状态给运行环境。">main 函数</Term>


## 语句、分号与执行顺序

函数体中的多数简单语句以分号结束。分号不是装饰，而是语法边界；漏掉后，编译器常在下一行才发现结构无法继续解析。因此诊断指向某行开头时，也要检查上一行是否缺少终止符。

<Term def="表达一个完整操作并按语言规则参与执行顺序的程序单位；简单语句通常以分号结束。">语句</Term>

在没有分支、循环或函数调用改变流程时，语句按书写顺序执行。下面先输出提示，再等待输入，最后输出结果。顺序改变会改变用户看到和程序等待的时机。

```cpp
#include <iostream>

int main() {
    int age = 0;
    std::cout << "Age: ";
    std::cin >> age;
    std::cout << "Next year: " << age + 1 << '\n';
    return 0;
}
```

先预测：若把第一条输出移到输入之后，程序启动时会安静地等待，用户可能以为它卡住；计算仍可正确，但交互顺序变差。代码的正确性不只包含最终数字，也包含可观察的提示时机。

## 标准输出是一条插入链

`std::cout` 是标准输出流对象，`<<` 把右侧值插入流。多个 `<<` 从左向右形成链，所以字符串、数字和换行可以写在同一条语句中。它们不是一次“拼接成新字符串”才输出，而是连续向流提交表示。

<Term def="程序默认写出文本和数值的标准输出流对象，通常连接终端。">标准输出</Term>

字符 `\n` 表示换行，不要求强制刷新缓冲区；`std::endl` 同时换行并刷新，只有确实需要立刻提交时才使用。初学代码若每行都用 `endl` 通常不会出错，但会掩盖“换行”和“刷新”是两个动作。

## 标准输入把字符解释为值

`std::cin` 是标准输入流对象，`>>` 从字符序列中提取符合目标类型的表示。输入 `42` 到 `int age` 时，流先读取字符 `'4'`、`'2'`，再按整数规则转换并写入变量。若输入 `abc`，转换失败，变量不会得到预期新值，流也会进入失败状态。

<Term def="程序默认读取用户输入的标准输入流对象；提取运算会按目标类型解释字符。">标准输入</Term>


`std::cin >> age` 默认跳过前导空白，并在不属于整数的字符处停止。它适合读取一个词或数值；需要读取含空格的整行文本时，应使用 `std::getline`，并理解前一次格式化提取可能留下换行符。此处先掌握最小模型：输入流包含字符、提取操作有目标类型、转换可能失败。

<Callout type="trap" title="陷阱：用户输入的任何内容都会自动变成 int">
  `>>` 会尝试转换，但不能保证成功。把变量先初始化，并在使用前检查 `if (std::cin)`；否则程序可能基于旧值继续计算，让输入错误伪装成业务结果。
</Callout>

## 命名空间不是复制名字

标准库设施放在 `std` 命名空间中，`std::cout` 的 `::` 表示在该命名空间查找名字。教材示例有时写 `using namespace std;` 以减少字符，但它会把大量名字引入当前查找范围。入门练习直接写 `std::` 更清楚：每个名字来自哪里一目了然，也不会在代码变大后制造冲突。

<Term def="为名字建立作用域、避免不同库或模块使用相同标识符时冲突的语言机制。">命名空间</Term>

局部 `using std::cout;` 只引入一个名字，影响范围更窄；头文件中尤其不应写全局 `using namespace std;`，因为每个包含者都会被迫接受这项查找规则。这里的原则不是“using 永远错误”，而是让名字可见范围与实际需要一致。

## 注释解释意图，不替代代码

`//` 注释延续到当前行结束，`/* ... */` 可跨多行。编译器在处理程序时忽略注释，因此注释无法修复错误，也不会执行。好的注释说明“为什么这样做、边界是什么”，而不是把 `age + 1` 重述成“年龄加一”。

```cpp
// 先初始化，确保输入失败时仍有已知状态。
int age = 0;

/* 练习阶段固定上限，
   后续再学习条件判断。 */
```

块注释不应随意嵌套，用注释临时屏蔽大段代码也容易留下结构混乱。更稳妥的学习实验是保留小样例、一次改一个语句，并由版本记录保存旧状态。

## 用首条证据定位错误

常见错误可分三层：缺分号、拼错名字等让编译器无法接受源代码；输入字符不能转换为目标类型使流进入失败状态；程序可正常执行但输出与预期不同则属于逻辑或需求错误。分类决定下一步看编译诊断、流状态还是输出对照。


<Callout type="trap" title="陷阱：编译器箭头指哪，根因就一定在哪">
  解析器经常在下一项开始时才发现上一项未闭合。先读第一条诊断，再检查当前位置之前的分号、引号、括号和名字；不要从最后一条级联错误倒着修改。
</Callout>

## 小结

- `main` 是约定入口，函数体中的语句按控制流执行，退出状态交还运行环境
- `#include` 提供标准流声明；`std::` 明确名字来源，适合建立清楚的初学模型
- `std::cout << value` 向标准输出插入表示，`std::cin >> target` 按目标类型提取并转换字符
- 输入转换可能失败，构建成功也不保证结果正确；语法、流状态和逻辑必须分别验证
- 注释用于解释意图和边界，不能替代结构清晰的代码或可执行测试

  1. **问题 1：拆解骨架。** 说明 `#include <iostream>`、`int main()`、花括号、输出语句和 `return 0` 各自责任。

  <Answer question="最小 C++ 程序的五个部件分别负责什么？">include 让翻译单元看到流设施声明；main 定义入口及整数返回类型；花括号界定函数体；输出语句把值送到标准输出；return 0 把正常退出状态交给运行环境。它们分别属于声明可见性、入口、作用域、行为和进程契约。</Answer>

  2. **问题 2：追踪输入。** 用户输入 `41` 后，程序如何得到并显示 `42`？输入 `abc` 又会怎样？

  <Answer question="std::cin 如何把 41 变成整数，abc 为什么失败？">标准输入先提供字符，提取运算根据目标是 int 尝试解析；41 能转换并写入 age，表达式 age + 1 得 42，再由输出流格式化。abc 不符合整数表示，提取失败并设置流状态，因此必须检查流后再使用值。</Answer>

  3. **问题 3：诊断边界。** 漏分号、输入失败和加法写错分别应看什么证据？

  <Answer question="三类错误应从哪些证据开始？">漏分号从首条编译诊断和上一语句边界开始；输入失败检查 std::cin 状态及原始输入；加法写错通常能构建运行，应比较实际输出与明确预期并检查表达式。不要用同一种排错方式处理所有失败。</Answer>
