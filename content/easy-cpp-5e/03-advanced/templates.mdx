## 函数模板：一份蓝图多种类型

函数模板是「函数的蓝图」——用占位类型（类型参数）写一份代码，编译器根据实际传入的类型自动生成对应版本。`template <typename T>` 声明类型参数 `T`：

```cpp
template <typename T>
T maxOf(T a, T b) {
    return (a > b) ? a : b;
}
```

使用时 `maxOf(3, 5)` 推断 `T=int` 生成 `int maxOf(int, int)`，`maxOf(2.5, 1.5)` 推断 `T=double` 生成 `double maxOf(double, double)`。不用为每种类型手写一遍，消除重复代码。

函数模板和函数重载的区别：重载需要每种类型手写一个函数，逻辑相同也要重复；模板写一次编译器自动生成。模板对所有类型用同一逻辑，重载可以给不同类型写不同逻辑。当多个类型逻辑完全相同时，模板是更好的选择。

## 类模板：泛型容器

类模板用类型参数定义类蓝图，实例化时用 `类名<类型>` 指定具体类型。STL 的 `vector`、`stack` 都是类模板：

```cpp
template <typename T>
class Box {
private:
    T value;
public:
    void set(T v) { value = v; }
    T get() { return value; }
};

Box<int> intBox;     intBox.set(42);
Box<string> strBox;  strBox.set("hello");
```

`Box<int>` 和 `Box<string>` 是两个独立的类，编译器分别为它们生成代码，`T` 被替换为 `int` 或 `string`，互不影响。

<Term def="用类型参数写一份代码蓝图，编译器根据实际类型在编译期自动生成对应版本，实现一份代码多种类型">模板</Term>

## 编译期实例化与零开销

模板本身不是代码，是蓝图。编译器在实例化时（遇到 `maxOf(3, 5)` 或 `Box<int>`）才生成具体代码，这叫隐式实例化，发生在编译期。因此模板定义通常放在头文件中——源文件看不到模板定义就无法实例化。

模板的「零开销」体现在三方面：编译期完成，运行时没有类型擦除或虚函数分派等开销，和手写的具体类型代码性能一样；类型安全，每个实例化是强类型的，编译器做完整检查；内联友好，编译器可见完整定义容易优化。

<Callout type="trap">
<strong>现象 →</strong> 模板代码编译慢、二进制体积大、错误信息冗长难读。<strong>原因 →</strong> 每种类型实例化生成一份代码导致代码膨胀；模板错误信息展开后很长；模板对类型参数有隐含要求（如必须支持 `>` 运算）。<strong>修法 →</strong> 控制实例化类型数量减少膨胀；模板定义放头文件（或显式实例化）；用 C++20 concepts 显式约束类型参数，让错误信息更清晰。
</Callout>

## 小结与练习

模板是编译期蓝图，编译器根据实际类型自动实例化。函数模板消除重复代码，类模板实现泛型容器。零运行时开销但可能增加编译时间和代码体积。
