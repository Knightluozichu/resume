## 为什么变量不是贴着名字的空盒子

程序要保存年龄、价格、字符和判断结果，就需要一块可被后续语句引用的状态。C++ 的变量同时包含四项信息：名字供源代码引用，类型规定可表示的值与操作，存储保存位模式，当前值是按类型解释该位模式所得的结果。只说“变量是盒子”不够，因为同一组位按 `int`、`char` 或浮点规则解释会得到不同意义。

例如十进制数值 `65` 与字符 `'A'` 在常见字符编码下可能关联到相同整数码，但一个变量表达数量，另一个表达字符。编译器依据声明类型选择输出、比较和转换规则；业务意义仍要由清楚的名字与约束补足。由此可见，存储空间只回答“放在哪里”，类型才回答“如何读写”，名字则回答“这份状态在问题域中代表什么”。

<Term def="程序中具有名字、类型、存储位置和生命周期的对象，可在允许范围内保存并更新一个值。">变量</Term>

<Term def="规定值的表示范围、可用操作和位模式解释规则的分类。">数据类型</Term>


## 声明同时建立名字和约束

```cpp
int age = 18;
double price = 12.5;
char grade = 'A';
bool available = true;
```

`int` 适合整数，`double` 适合带小数的近似实数，`char` 保存一个字符代码单元，`bool` 表示真假。类型不是根据未来输入自动改变的标签；一旦变量声明为 `int`，后续赋值会先尝试转换成 `int` 可表示的值。

选择类型要从领域约束出发：人数不能是 3.7，价格是否能接受二进制浮点近似要由业务决定，字符与完整文本也不是同一层。不要只按“现在看起来能放下”选择，而要考虑范围、精度、合法操作和与外部接口的契约。

## 初始化与赋值发生在不同时间

**初始化**发生在对象生命周期开始时，建立第一个状态；**赋值**发生在对象已经存在之后，用新值替换旧值。内置局部变量若只写 `int score;`，在被赋值前读取会产生未定义行为。最简单的防线是声明即初始化。

<Term def="在对象生命周期开始时建立其首个有效状态，而不是先创建再补写。">初始化</Term>

```cpp
int score = 0;      // 初始化
score = 95;         // 赋值

int level{3};       // 列表初始化
double ratio{0.75};
```

花括号列表初始化能拒绝明显窄化，例如 `int count{3.8};` 无法通过编译；`int count = 3.8;` 则可能静默丢掉小数。入门阶段优先使用明确初值和花括号，可以让“数据是否丢失”更早暴露。


<Callout type="trap" title="陷阱：未初始化的 int 会自动是 0">
  静态存储期对象会零初始化，但普通局部内置变量不保证有零值。读取未初始化局部变量不是“随机数技巧”，而是未定义行为；不要依赖调试器里偶然出现的 0。
</Callout>

## 赋值会执行类型转换

当右侧类型与左侧不同，C++ 会按规则转换。转换可能扩大表示范围，也可能丢失信息。`double` 到 `int` 会截去小数部分；超出目标整型可表示范围时结果不能当作可靠业务值；较小整数参与表达式时还会发生提升。

```cpp
double measured = 19.75;
int whole = measured;       // whole 为 19，小数信息丢失
double restored = whole;    // 19.0，丢失的信息不会回来
```

先预测：`restored` 是 19.75 还是 19.0？第二次转换只能把整数 19 表示成 `double`，无法恢复第一次已经丢掉的 `.75`。这说明“最终类型够大”不能修复早先的窄化。


## const 把不应修改写进类型

若一个值在初始化后不应改变，可用 `const` 表达约束。编译器会拒绝后续写入，让设计意图变成可检查规则，而不是只靠注释提醒。

<Term def="限定对象在初始化后不能通过该名字被修改的类型修饰符。">const</Term>

```cpp
const int daysPerWeek = 7;
const double taxRate = 0.13;
```

`const` 对象通常必须初始化，因为之后不能再赋值。它不等于“编译期常量”的全部含义，也不自动让引用到的外部对象永远不变；当前阶段先掌握最直接契约：通过这个变量名不能修改其值。

## 作用域决定名字在哪里可见

花括号形成块作用域，变量从声明点开始可见，离开块后名字不再可用，对象通常也结束生命周期。内层可以声明同名变量并遮蔽外层，但这样会让读者难以判断实际读写的是哪一个对象。

<Term def="名字可被查找和使用的源代码范围；块内声明通常只在该块及其后续嵌套范围可见。">作用域</Term>

变量应放在最小但足够的作用域，并靠近第一次使用处初始化。这样有效状态更容易证明，名称冲突更少，也不会让与任务无关的代码意外修改它。

<Callout type="trap" title="陷阱：内外层同名只是少打几个字符">
  遮蔽会让日志、调试器和代码审查同时出现两个同名对象。若它们语义不同，应使用不同名字；若语义相同，通常只需一个恰当作用域的变量。
</Callout>

## 从输入建立有效状态

声明变量只是准备接收值，输入是否成功仍要验证。把对象初始化为已知值，再检查 `std::cin`，可以让失败路径明确。

```cpp
int count = 0;
if (!(std::cin >> count)) {
    std::cerr << "count must be an integer\n";
    return 1;
}
```

这里变量始终有状态，但只有输入成功后的 `count` 才代表用户提供的数量。初始化不能替代验证；它的作用是避免失败路径读取不确定状态，并为错误处理提供稳定起点。

## 小结

- 变量由名字、类型、存储、值和生命周期共同定义；类型决定表示范围与允许操作
- 初始化建立首个状态，赋值替换已有状态；局部内置变量应在首次读取前明确初始化
- 不同类型之间的赋值会转换，窄化丢失的信息无法靠后续扩大类型恢复
- `const` 把“初始化后不应修改”变成编译器可检查的约束
- 作用域控制名字可见性与对象生命周期，变量应靠近使用点并避免无意义遮蔽

<Exercises>
  1. **问题 1：拆解变量模型。** `int age{18};` 中名字、类型、首值和存储各自是什么？

  <Answer question="int age{18} 的四个组成部分如何理解？">age 是源代码查找的名字，int 规定整数表示与操作，声明为对象提供适当存储，18 在生命周期开始时初始化该存储并按 int 解释。以后赋值改变值，但不改变变量的 int 类型与身份。</Answer>

  2. **问题 2：判断窄化。** `double x=7.9; int n=x; double y=n;` 中 n 与 y 分别是什么，为什么？

  <Answer question="double 到 int 再回 double 会发生什么？">n 得到 7，因为转换到 int 丢弃小数部分；y 得到 7.0，因为它只能把当前整数 7 转为 double。第一次转换丢掉的 .9 已不存在，目标类型变宽不会恢复历史信息。</Answer>

  3. **问题 3：设计输入状态。** 为什么 `int count=0;` 之后仍要检查 `std::cin >> count`？

  <Answer question="初始化 count 后为什么还必须检查输入流？">初始化只保证失败路径没有不确定位模式，不证明 0 是用户输入。流检查区分“成功读取的业务值”和“转换失败后保留的初值”，程序才能拒绝非法字符并给出明确退出状态。</Answer>
</Exercises>
