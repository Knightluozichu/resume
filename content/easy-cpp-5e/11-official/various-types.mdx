## 为什么一种内置类型不够表达一条记录

一个学生同时有编号、姓名和分数，三个值必须作为一个整体传递和返回。把它们保存在互不相关的变量中，会让调用者依赖位置和命名约定；结构体把共同描述一个实体的字段放入同一类型。

<Term def="把若干可具有不同类型的成员组合为一个记录对象的用户定义类型。">结构体</Term>

```cpp
#include <string>

struct Student {
    int id;
    std::string name;
    double score;
};

Student learner{1001, "Mina", 92.5};
```

数组表达“多个同类元素”，结构体表达“一个实体的多个异类属性”。建模时先问数据是重复序列还是命名记录，不要为了方便下标把编号、分数等强塞进同类型数组。

## 成员访问保留对象边界

对象使用 `.` 访问成员，指向结构体的指针使用 `->`。每个成员有独立类型和值，但生命周期通常随整个结构体对象开始与结束。

<Term def="属于结构体、类或联合体定义内部的命名子对象或函数。">成员</Term>

```cpp
learner.score = 95.0;

Student* selected = &learner;
selected->name = "Mana";
```

聚合初始化按成员声明顺序对应，顺序改变会影响调用代码。随着字段增多，应提供清楚的构造接口或使用指定初始化能力，避免调用点出现一串难以辨认的同类型值。

<Callout type="trap" title="陷阱：结构体只要能编译，就一定是合法业务对象">
  编译器只检查类型，不知道分数必须在 0 到 100、编号必须为正。初始化后仍要验证跨成员不变量；若规则复杂，应让后续类接口集中维护。
</Callout>

## 复制结构体会复制各成员状态

```cpp
Student copy = learner;
copy.score = 60.0;
```

对这份结构体，`copy` 是独立对象，修改分数不会改变 learner。成员若包含指针，复制地址并不复制目标对象，两个记录可能成为别名；因此“结构体复制”具体语义由成员类型共同决定。

传递较大结构体时可用 `const Student&` 只读借用，返回普通值通常仍清楚安全。不要为了避免复制返回局部结构体引用，它会在函数结束后悬空。

## 枚举把有限状态命名

许多状态只能从固定集合中选择，例如连接为 disconnected、connecting、connected。枚举把集合成员变成类型内的命名值，比散落的 0、1、2 更可读。

<Term def="定义一组有限命名常量来表达状态或分类的用户定义类型。">枚举</Term>

```cpp
enum class ConnectionState {
    disconnected,
    connecting,
    connected,
};

ConnectionState state = ConnectionState::disconnected;
```

`enum class` 的枚举名位于自身作用域，不会隐式当作普通整数使用，能减少名字冲突和意外运算。若需要持久化或协议传输，应显式映射到稳定编码，不依赖编译器内部表示。

## switch 应覆盖每个枚举状态

```cpp
const char* label(ConnectionState state) {
    switch (state) {
    case ConnectionState::disconnected: return "offline";
    case ConnectionState::connecting:   return "connecting";
    case ConnectionState::connected:    return "online";
    }
    return "invalid";
}
```

开启警告后，不写 default 有时能让编译器提醒新增枚举项未覆盖；边界输入来自反序列化时，又需要显式拒绝非法底层值。覆盖策略取决于值是否只在受控程序内部产生。

## 联合体让成员共享同一段存储

联合体声明多个可选成员，但同一时刻只有一个活动成员。它适合底层布局或带标签的变体实现，不适合把几个独立字段压缩进一个对象。

<Term def="多个成员共享同一存储、任一时刻只有一个活动成员的用户定义类型。">联合体</Term>

```cpp
union Number {
    int integer;
    double real;
};

Number number{};
number.integer = 42; // integer 成为活动成员
```

写入 `real` 后再读取 `integer` 通常不是“查看同一值的另一种类型”，而是违反活动成员规则或依赖不可移植细节。若必须知道当前有效项，需要额外标签与联合体同步维护；现代 C++ 的 `std::variant` 能封装这份标签和访问检查。

<Callout type="trap" title="陷阱：union 能同时保存 int 和 double">
  成员覆盖同一存储，不是两份独立槽位。最后激活哪个成员，就只能按该活动成员的规则访问；要同时保存两个值应使用 struct。
</Callout>

## 类型别名改善领域语言

`using` 或传统 `typedef` 可为已有类型提供另一个名字。别名能缩短复杂声明、强调单位或角色，但不会创建与原类型不兼容的新类型。

<Term def="为已有类型提供另一个名字的声明；改善表达但不产生独立类型身份。">类型别名</Term>

```cpp
using StudentId = int;
using Score = double;

StudentId id = 1001;
Score score = 92.5;
```

`StudentId` 与 `int` 仍可互换，编译器不会阻止把普通计数误传为学生编号。若需要强类型隔离，应定义包装结构体或类，而不是只用别名。

## 带标签联合体必须同步两个状态

```cpp
enum class ValueKind { integer, real };

struct Value {
    ValueKind kind;
    Number payload;
};
```

写 payload 时必须同步 kind，读取前先按 kind 选择活动成员。若标签写着 integer、实际最后激活 real，代码即使布局没变也失去语义安全。这类“两个字段必须一起变化”的约束正是更高层类或 variant 应封装的责任。

## 小结

- struct 组合同时存在的异类成员，数组组织同类序列，两者表达不同数据形状
- 聚合初始化按成员顺序，结构体复制语义由每个成员类型共同决定
- enum 为有限状态集合命名，enum class 提供作用域与更强类型边界
- union 成员共享存储，同一时刻只有一个活动成员；标签必须与实际成员同步
- using/typedef 只创建别名，不建立新的类型身份；强隔离需要包装类型

<Exercises>
  1. **问题 1：选择形状。** 学生的编号、姓名、分数为何用 struct，而五次成绩为何适合数组？

  <Answer question="记录与序列为什么使用不同类型设施？">学生属性类型和语义不同但共同描述一个实体，struct 用成员名组合；五次成绩是同类型重复元素，数组用长度和下标表达序列。数据形状决定设施，不按语法熟悉度选择。</Answer>

  2. **问题 2：审计 union。** 写 `number.integer=42` 后再写 `number.real=3.5`，此时哪个成员有效？

  <Answer question="联合体连续写两个成员后应读取哪个？">最后写入 real 后，real 是活动成员，integer 不再是当前有效表示。若程序需要运行时选择，必须用标签同步记录并按标签读取，或使用 std::variant 封装检查。</Answer>

  3. **问题 3：判断别名。** `using StudentId=int` 能否阻止把普通 int 计数传给学生编号参数？

  <Answer question="类型别名能否形成强类型隔离？">不能，StudentId 仍是 int 的另一个名字，普通 int 与它兼容。别名改善可读性；若必须防误传，应定义拥有显式构造和比较规则的包装结构体或类。</Answer>
</Exercises>
