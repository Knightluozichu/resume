## 从“const 把错误提前到编译期”开始

<Term def="由类型系统表达某个名称、对象视图或成员函数不应执行特定修改的约束。">const 契约</Term>

让编译器替你拒绝意外写入。它可以修饰全局/局部对象、参数、返回引用、指针本身、所指对象和成员函数。

<Term def="通过类型限制调用方可执行操作集合，而不是依赖注释和约定保持只读。">编译期只读能力</Term>

越靠近接口声明，越能减少实现与调用方需要共同记忆的隐含条件。

## 指针 const：读星号两侧

<Term def="指针所指对象不能经该指针修改，但指针可改指向的类型。">pointer-to-const</Term>

与

<Term def="指针自身地址不可改变，但所指对象是否可写由 pointee 类型决定的类型。">const pointer</Term>

是不同约束。

```cpp
char greeting[] = "Hello";
char* p1 = greeting;              // pointer 与 pointee 都可变
const char* p2 = greeting;        // pointee const
char* const p3 = greeting;        // pointer const
const char* const p4 = greeting;  // 两者 const
```

<Term def="指针、引用或迭代器最终访问的目标对象。">pointee</Term>

可用“const 在星号左边约束 pointee，星号右边约束 pointer”快速阅读；`T const*` 与 `const T*` 等价。


<Callout type="trap">
  **现象**：看到 `const` 就认定“整个指针不可变”。**原因**：没有区分 pointer 与
  pointee。**修法**：分别写出能否重新赋地址、能否经指针写对象两条编译测试，不靠口头猜测。
</Callout>

<Callout type="trap" title="陷阱：mutable cache 只要是 const 就天然线程安全">
  mutable 只放宽 const 成员函数修改位级状态，不提供同步。logical constness 与 data
  race 是两个维度；缓存初始化、失效和读取必须共享明确的同步协议。
</Callout>

## iterator 也有两层 const

<Term def="可移动位置并解引用元素的泛化指针，由容器定义有效和失效规则。">iterator</Term>

`const_iterator` 类似 `const T*`：可递增迭代器，但不能经它修改元素。`const std::vector<T>::iterator` 则类似 `T* const`：迭代器对象本身不能递增，元素仍可能可写。

```cpp
std::vector<int> values{1, 2, 3};
std::vector<int>::const_iterator read = values.begin();
++read;          // 正确
// *read = 4;    // 编译失败

const std::vector<int>::iterator fixed = values.begin();
*fixed = 4;      // 正确
// ++fixed;      // 编译失败
```

<Term def="可移动但只能读取元素的容器迭代器类型。">const_iterator</Term>

接口若只读取范围，优先接收 const range 或 const_iterator，避免算法意外修改元素。

## const 参数与返回引用限制能力

<Term def="函数承诺不通过该引用修改调用者对象的参数类型。">const reference parameter</Term>

允许绑定 const 对象和临时量，也避免昂贵复制。

```cpp
double distance(const Point& left, const Point& right);
const Widget& selected_widget(const Registry& registry, Id id);
```

<Term def="调用方通过函数结果取得只读别名，不能经该别名修改原对象的返回类型。">const reference return</Term>

可保护内部对象，但仍要保证生命周期。不要返回局部对象引用，也不要用 const 掩盖悬空设计。

原书还讨论给值返回加 const 以阻止 `(a * b) = c` 等怪异操作。现代 C++ 中 `const T` 值返回常阻碍移动或影响重载，通常让类接口和 ref-qualified 操作符处理误用，而不是给临时值普遍加 const。

<Term def="函数按值返回的临时结果，调用方拥有独立对象，现代接口通常不添加顶层 const。">value return</Term>

条款精神是尽量表达不可修改，不是无差别堆叠 const。
Use const whenever possible（尽可能使用 const）中的 possible 由真实语义决定：只读能力应明确，值返回和移动路径则不应被多余顶层 const 阻塞。

## const 成员函数参与重载

<Term def="承诺不修改对象抽象值，并可由 const 对象调用的成员函数。">const member function</Term>

末尾 const 属于函数类型，因此可以与非 const 版本重载。

```cpp
class TextBlock {
public:
    const char& operator[](std::size_t position) const
    {
        return text_.at(position);
    }

    char& operator[](std::size_t position)
    {
        return text_.at(position);
    }

private:
    std::string text_;
};
```

<Term def="由对象 const 属性决定选择只读或可写成员版本的重载机制。">const overload</Term>

const TextBlock 得到 `const char&`，普通对象得到 `char&`。同一查询接口准确传播写权限。


## bitwise constness 的局限

<Term def="const 成员函数不修改对象任何非 mutable 数据位的编译器层面规则。">bitwise constness</Term>

也称 physical constness。编译器主要执行这一规则，但它不保证抽象值真的不变。

```cpp
class CTextBlock {
public:
    char& operator[](std::size_t position) const
    {
        return pText_[position];
    }
private:
    char* pText_;
};
```

函数没有修改指针 `pText_` 的 bits，却返回可写引用，调用方能通过 const 对象改字符。类型检查通过，逻辑契约被破坏。

<Term def="const 成员函数不改变调用方可观察的对象抽象值，即使内部缓存位可能变化。">logical constness</Term>

更接近接口设计意图。const 不是“成员一位不动”，而是“从该只读视图不能观察到抽象值变化”。

<Callout type="trap">
  **现象**：const
  成员函数通过裸指针返回可写引用，因此代码编译就被认为安全。**原因**：只满足
  bitwise constness，没有检查别名泄露后的 logical constness。**修法**：const
  overload 返回 const reference，并审计所有 pointer/reference/iterator 出口。
</Callout>

## mutable 用于不改变抽象值的缓存

<Term def="允许数据成员在 const 成员函数中修改的说明符，适合不改变抽象值的内部状态。">mutable</Term>

例如缓存字符串长度：

```cpp
class TextBlock {
public:
    std::size_t length() const
    {
        if (!lengthValid_) {
            cachedLength_ = text_.size();
            lengthValid_ = true;
        }
        return cachedLength_;
    }

private:
    std::string text_;
    mutable bool lengthValid_{};
    mutable std::size_t cachedLength_{};
};
```

<Term def="为避免重复计算而保存的派生结果，其变化不应改变对象对外抽象值。">logical cache</Term>

任何修改 text\_ 的操作都必须使缓存失效，否则 const 查询返回错误结果。

## const 不等于线程安全

<Term def="多个线程无同步访问同一内存位置，且至少一个访问为写入的未定义行为。">data race</Term>

两个线程首次调用上面的 `length()` 会同时写 mutable 成员。logical constness 允许缓存变化，但 C++ memory model 不允许数据竞争。

```cpp
class ThreadSafeTextBlock {
public:
    std::size_t length() const
    {
        std::scoped_lock lock{mutex_};
        if (!cachedLength_)
            cachedLength_ = text_.size();
        return *cachedLength_;
    }
private:
    std::string text_;
    mutable std::mutex mutex_;
    mutable std::optional<std::size_t> cachedLength_;
};
```

<Term def="规定缓存读写、初始化、失效和并发访问如何同步的完整约定。">缓存同步协议</Term>

可能使用 mutex、atomic 或 `std::once_flag`，选择取决于失效需求。mutex 本身通常也需 mutable，因加锁不改变业务抽象值。

## 避免 const 与非 const 实现重复

两个 operator[] 若都包含复杂边界检查、日志和懒加载，复制实现会漂移。原书建议让非 const 版本调用 const 正本，再安全移除结果 const。

<Term def="以 const overload 作为读取逻辑唯一实现，非 const overload 委托后恢复写权限的模式。">const implementation reuse</Term>

```cpp
class TextBlock {
public:
    const char& operator[](std::size_t position) const
    {
        return checked_character(position);
    }

    char& operator[](std::size_t position)
    {
        return const_cast<char&>(
            std::as_const(*this)[position]);
    }
};
```

<Term def="显式移除类型 const 限定的转型；若原对象实际为 const 且随后写入，行为未定义。">const_cast</Term>

这里安全的前提是非 const overload 的 `*this` 原本确实非 const。反过来让 const 版本调用非 const 版本并 cast away const，可能让真正 const 对象被修改，不可接受。


现代代码也可把公共读取逻辑抽到私有模板或显式 object parameter，减少 cast；关键是保留一个正本，并证明 const 路径绝不获得写权限。

## const 接口审计

<Term def="逐个检查参数、返回别名、成员函数、缓存和全局副作用是否符合只读承诺的过程。">const audit</Term>

先从 public API 开始：只读参数是否为 const reference/span；查询是否标记 const；返回 pointer/reference/iterator 是否传播只读；值返回是否不必要地加顶层 const。再检查实现是否通过别名、全局注册表、日志计数或 mutable 改变可观察行为。

先预测：对 `const TextBlock block` 调用 `block[0]`、`length()` 和两个线程并发 `length()`，分别写出编译权限、抽象值和 memory model 预期。仅“调用能编译”不是验收。

- 静态断言 const 对象查询结果不可赋值。
- 非 const 对象查询结果可写且保持不变量。
- 修改 text 后缓存失效，下一次读取重新计算。
- ThreadSanitizer 下并发首次读取无 data race。
- const 与非 const 重载对非法索引产生一致诊断。

## 小结

- const 可约束对象、pointee、pointer、iterator、参数、返回别名与成员函数
- pointer-to-const 和 const pointer 是两层独立能力，const_iterator 也有对应差异
- const member overload 让同一接口向 const/非 const 对象传播只读或可写权限
- 编译器主要执行 bitwise constness，接口设计应满足 logical constness
- mutable 适合派生缓存，但必须有失效和线程同步协议
- 非 const 重载可复用 const 正本，但 const_cast 只在原对象非 const 时安全

  1. **问题 1：读懂四种指针（use const whenever possible、pointer-to-const、const pointer）。** 对 `T*`、`const T*`、`T* const`、`const T* const` 分别写出重指向和修改对象是否允许。

<Answer question="四种 pointer/pointee const 组合分别允许什么？">
  T* 两者都允许；const T* 可以重指向但不能经它改 T；T* const 不能重指向但可改
  T；const T* const 两者都禁止。const 在星号左约束 pointee，在右约束
  pointer。还要注意原对象是否本来 const，不能通过转型绕开真实 const。
</Answer>

2. **问题 2：修复缓存 const（const member function、logical constness、mutable）。** 一个 const `checksum()` 懒缓存结果，在多线程和对象修改后偶尔错误，设计完整协议。

<Answer question="logical const cache 需要哪些正确性条件？">
  缓存值与有效标记可
  mutable，因为不改变对象抽象值；每个改变源数据的操作必须在同一同步协议下使缓存失效；首次计算和读取需
  mutex、atomic 状态机或 once 机制避免 data race；如果数据可再次修改，once_flag
  不适用。测试修改后重算、并发首次读取和异常计算后的状态。
</Answer>
