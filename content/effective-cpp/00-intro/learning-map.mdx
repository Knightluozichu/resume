## 全书地图

当你打开 Effective C++，面对 55 条条款，第一件事不是逐条背诵，而是理解它们背后的组织逻辑。Scott Meyers 把 C++ 高效编程的经验整理成一条从语言习惯到模板元编程的递进链——先学会正确使用语言，再管理资源，再设计类与继承，最后驾驭模板与底层机制。

<EfcBookMap />

全书分为四大板块。第一板块「习惯 C++ 与构造析构」（条款 1-12）解决「怎么正确用 C++」——把 C++ 视为语言联邦，用 const 和 inline 替代 #define，保证对象初始化，正确处理构造、析构与赋值。这是地基，后续所有条款都建立在这套习惯上。

第二板块「<Term def="Resource Acquisition Is Initialization，把资源生命周期绑定到对象生命周期，构造获取析构释放。">资源管理</Term>」（条款 13-17）解决「资源怎么不泄漏」——核心是 RAII 模式，用对象管理资源，配合智能指针实现自动释放。这一板块把手动管理的负担交给类型系统。

第三板块「设计与继承」（条款 18-40）解决「类和类型层次怎么设计」——从接口设计的防误用原则，到成员封装、const 正确性，再到 public 继承的 is-a 关系和 NVI 模式。这一板块是面向对象 C++ 的设计核心。

第四板块「模板与杂项」（条款 41-55）解决「如何泛化和掌控底层」——从模板的隐式接口和 typename 双重含义，到模板元编程（TMP）、type traits、定制 new/delete，最后到 Boost 与标准库。

<Callout type="tip">
<strong>建议 →</strong> 每学完一个板块，挑一条条款动手写代码验证。比如学完资源管理，用 RAII 封装一个文件句柄类；学完继承，设计一个 NVI 模式的多态基类。条款是经验，只有动手才能内化。
</Callout>

## 核心概念

推荐学习路径是一条递进链：先读习惯 C++ 与构造析构，掌握语言的基本准则；再读资源管理，学会用对象管理资源；接着读设计与继承，掌握面向对象的设计原则；然后读模板与泛型，理解编译期多态；最后以杂项收口，涵盖 inline、转型、异常安全和标准库。

这条顺序背后的逻辑是——语言习惯是地基，资源管理是安全网，类设计是骨架，继承是骨架之间的关节，模板是骨架的泛化，杂项是工程实践的补丁。跳过任何一块都会断层：没有 RAII 就写不出异常安全的代码，没有封装就没有正确的继承，没有继承理解就无法设计模板化的类型层次。

<Callout type="trap">
<strong>现象 →</strong> 跳过资源管理直接学模板，结果模板代码充满内存泄漏。<strong>原因 →</strong> 模板大量使用动态资源，没有 RAII 基础就无法保证异常安全。<strong>修法 →</strong> 按板块顺序学习，先把 RAII 和智能指针吃透，再进入模板世界。
</Callout>

## 小结与练习

- 全书 55 条条款分四大板块：习惯奠基、资源管控、设计封装、模板延伸
- 推荐路径：习惯→资源→设计→继承→模板→杂项，顺序由依赖关系决定
- 每个板块的核心：习惯=正确使用语言，资源=RAII 自动释放，设计=封装与接口，模板=编译期泛化
- C++ 是语言联邦：C、OO、Template、STL 四种子语言各有高效准则

<Exercises>
  <Answer question="为什么 Scott Meyers 说「视 C++ 为一个语言联邦」？">C++ 不是单一范式语言，而是 C（过程式）、Object-Oriented C++（面向对象）、Template C++（泛型）、STL（标准库）四个子语言的联邦。不同子语言的高效编程准则不同——C 中 pass-by-value 常更高效，OO C++ 中 pass-by-reference-to-const 更好，STL 中迭代器按值传递更合适。把 C++ 当联邦而非单一语言，才能在不同语境下选对准则。</Answer>
  <Answer question="全书四大板块各自解决什么问题？为什么是递进而非并列？">习惯 C++ 与构造析构解决「怎么正确用语言」，资源管理解决「资源怎么不泄漏」，设计与继承解决「类和类型层次怎么设计」，模板与杂项解决「如何泛化和掌控底层」。它们递进：语言习惯是地基、资源管理是安全网、类设计是骨架、继承是关节、模板是泛化——后一块都以前一块为前提，跳级会断层。</Answer>
</Exercises>

  <GlossaryItem term="资源管理">通过 RAII 模式把资源的获取和释放绑定到对象的生命周期，利用析构函数和栈展开保证资源不泄漏。</GlossaryItem>
