## 从“55 条不是零散技巧”开始

Effective C++ 第三版把 55 个具体建议组织为九章。它们共同回答一个问题：怎样让 C++ 程序的正确性由对象生命周期、类型系统和明确 contract 承担，而不是依赖开发者每次都足够谨慎。

<Term def="以第三版九章和 55 个官方 Items 为唯一顺序来源的学习结构。">第三版九章路线</Term>

旧学习地图把全书压成四块，会让实现细节、new/delete 与杂项失去准确位置。当前路线逐 Item 保留原书边界。

<Term def="一条只解决一个核心设计问题，并给出可验证行为准则的原书单元。">Item 学习单元</Term>

## 第一章 Items 1-4：适应 C++

先理解 C++ 是 C、Object-Oriented C++、Template C++ 与 STL 组成的

<Term def="不同子语言拥有不同抽象、传参和性能准则的复合语言模型。">语言联邦</Term>。

Items 2-4 用 const、enum、inline 和完整初始化替代脆弱预处理/未初始化状态。

```cpp
class Session {
public:
    explicit Session(Id id) : id_(id), active_(false) {}
private:
    const Id id_;
    bool active_;
};
```

<Term def="对象在 constructor body 执行前就建立所有成员有效值的状态。">完整初始化</Term>

验收点：宏是否泄漏作用域；const 是否贯穿接口；成员、base、static objects 是否在首次使用前确定初始化。

## 第二章 Items 5-12：构造、析构与赋值

compiler 会生成 default/copy/destructor/assignment，但生成不等于语义正确。需要明确禁止 copy、让 polymorphic base destructor virtual、避免 destructor 抛异常、理解 constructor/destructor 期间 virtual dispatch，并让 assignment 返回 `*this`、处理 self-assignment、复制所有 members/bases。

<Term def="compiler 在满足条件时隐式声明或定义的构造、复制、赋值和析构函数。">编译器生成函数</Term>

<Term def="对象复制后所有 base 与成员状态都符合原对象 contract。">完整复制语义</Term>

```cpp
class UniqueHandle {
public:
    UniqueHandle(const UniqueHandle&) = delete;
    UniqueHandle& operator=(const UniqueHandle&) = delete;
};
```

<Callout type="trap" title="陷阱：没有写 copy 就表示对象不可复制">
  compiler 可能生成 copy operations。先定义 ownership/value semantics，再显式
  default、delete 或实现，不把默认行为当设计结论。
</Callout>

## 第三章 Items 13-17：资源管理

资源取得后立即交给对象，destructor 覆盖 normal return、early return 和 exception。unique/shared/weak ownership 必须与业务生命周期一致；new/delete family 配对；独立语句建立 smart pointer，避免求值顺序中的泄漏窗口。

<Term def="资源获取与管理对象初始化绑定，作用域结束自动执行配对释放。">RAII</Term>

<Term def="谁延长资源生命、谁负责最终释放、谁只是短期观察的明确协议。">ownership contract</Term>

```cpp
auto file = std::unique_ptr<FILE, FileCloser>(
    std::fopen(path.c_str(), "rb"));
if (!file) throw FileError{};
```

## 第四章 Items 18-25：设计与声明

接口应让正确使用自然、错误使用困难；class 设计就是 type 设计；默认 pass-by-reference-to-const；不返回 local/temporary handle；data private；能用 non-member non-friend 就减小访问面；对称转换放 non-member；为 user type 提供 non-throwing swap。

<Term def="通过类型、构造和函数边界让非法状态或调用无法表达的接口。">易正确接口</Term>

<Term def="只有最少必要代码能访问 representation，从而减少不变量破坏面。">封装访问面</Term>

## 第五章 Items 26-31：实现

延迟变量定义到真正需要且能初始化的位置；减少 casts；不要泄漏 internal handles；异常安全用 RAII、copy-and-swap 或 transaction；审慎 inline；通过 Pimpl、interface 和依赖反转降低 compilation dependency。

<Term def="操作失败后保证不泄漏，并按 basic/strong/no-throw 层级约束状态。">异常安全保证</Term>

<Term def="header 变化造成的 recompilation fan-out 和 binary coupling。">编译依赖</Term>

## 第六章 Items 32-40：继承与面向对象设计

public inheritance 必须满足 is-a 与 substitutability。区分 interface inheritance 和 implementation inheritance；virtual alternatives 包括 NVI、strategy 与 function wrapper；不要重定义 inherited nonvirtual 或 default parameter；composition 表达 has-a/implemented-in-terms-of；private/multiple inheritance 只有语义和成本证据充分才用。

<Term def="derived 可在所有 base client 中替换 base，并保持其行为 contract。">is-a substitutability</Term>

<Term def="public nonvirtual wrapper 统一检查和流程，private virtual hook 提供变化点。">NVI</Term>

<EcppPrincipleDependencyMap />

<Callout type="trap" title="陷阱：为了复用代码先建立继承">
  代码复用不证明 is-a。先做 substitutability
  test；若只是拥有部件或复用机制，composition 往往更准确。
</Callout>

## 第七章 Items 41-48：模板与泛型编程

templates 的 implicit interface 由 valid expressions 构成，compile-time polymorphism 在实例化/重载阶段发生。掌握 typename、dependent base lookup、parameter-independent factoring、member templates、hidden friends、traits/tag dispatch 与 TMP。

<Term def="由泛型代码必须成立的完整 expressions 组成、无需共同 base 的契约。">隐式接口</Term>

<Term def="通过 traits 抽取类型事实，再用 tags/overloads 在编译期选择实现。">traits 分派</Term>

先预测 template error 位于 deduction、lookup、substitution 还是 conversion，再读诊断，不把“模板报错很长”当成无法定位。

## 第八章 Items 49-52：定制 new 和 delete

理解 new-handler 失败循环；只在 usage errors、statistics、performance、clustering 或 alignment 有证据时替换；自定义函数遵守 zero request、handler、alignment、derived size 和 null delete；placement new 必须有 matching placement delete 处理 constructor failure。

<Term def="allocation 失败后调用当前处理器并重试，直至成功、抛异常或终止的控制流。">new-handler 循环</Term>

<Term def="placement allocation 与构造失败释放函数按额外参数类型对应。">placement 配对</Term>

## 第九章 Items 53-55：杂项

warnings 是潜在语义/portability 信号；标准库提供 ownership、containers、algorithms 和 vocabulary；TR1/Boost 展示库设施从 peer review 到 standardization 的演进。

<Term def="不同 compilers 与 libraries 共同构建，覆盖诊断和标准扩展差异。">可移植性矩阵</Term>

<Term def="通过社区同行评审和多平台实践磨炼库设计，再为标准化提供证据。">库标准化路径</Term>

## 两条推荐路线

**系统学习路线**：1-12 对象语义 → 13-17 ownership → 18-31 接口/实现 → 32-40 多态 → 41-48 generic → 49-55 底层与工程。

**问题驱动路线**：泄漏先读 13-17/29；继承 bug 读 32-40；模板诊断读 41-48；allocator bug 读 49-52。问题解决后回到系统路线补前置。

<Term def="以原书依赖顺序逐章建立完整模型的学习方式。">系统学习路线</Term>

<Term def="从当前故障进入相关 Items，再回补其前置 contract 的学习方式。">问题驱动路线</Term>

## 小结

- 第三版按九章组织 55 Items，不能压缩成丢失边界的四块目录
- 学习依赖从对象语义、ownership、接口、实现、多态走向 generic 与 allocation
- 每条 Item 用预测、最小复现、语言机制修复、正反测试和真实迁移验收
- 系统路线建立完整模型，问题路线解决故障后必须回补前置
