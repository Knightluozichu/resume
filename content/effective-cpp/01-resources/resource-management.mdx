## 为什么需要 RAII

C++ 最容易出错的环节不是语法，而是资源管理。每次 `new` 之后必须记得 `delete`，每次 `fopen` 之后必须记得 `fclose`，每次 `lock` 之后必须记得 `unlock`。问题在于，人的记忆是不可靠的——异常抛出、提前 return、逻辑分支变多，任何一个都可能导致释放被跳过。一旦跳过，资源就泄漏了。

## RAII 核心原则

<Term def="Resource Acquisition Is Initialization，把资源生命周期绑定到对象生命周期，构造获取析构释放。">RAII</Term> 的核心思想是把资源的生命周期绑定到对象的生命周期上。构造函数获取资源，析构函数释放资源。由于 C++ 保证对象销毁时析构函数一定被调用（无论是正常 return 还是异常抛出导致的栈展开），资源就一定能被释放。

条款 13 说「以对象管理资源」——这是全书最实用的准则。直接做法是用智能指针接管 `new` 的结果：

```cpp
// 手动管理——异常时泄漏
void f() {
  Widget* p = new Widget;
  ... // 如果这里抛异常，delete 永远不会执行
  delete p;
}

// RAII——异常安全
void f() {
  auto p = std::make_unique<Widget>();
  ... // 异常时 p 的析构自动释放
}
```

## 智能指针的三种所有权

<Term def="独占所有权的智能指针，不可拷贝可移动，零开销抽象。">unique_ptr</Term> 表达独占所有权：同一时刻只有一个指针持有资源，不可拷贝但可以 `std::move` 转移。它几乎和裸指针一样高效，是默认选择。

<Term def="共享所有权的智能指针，通过引用计数管理，计数归零时释放资源。">shared_ptr</Term> 表达共享所有权：多个指针可以指向同一资源，通过引用计数管理。计数归零时释放资源。代价是原子计数开销和可能的循环引用。

<Term def="不控制生命周期的观察者指针，配合 shared_ptr 打破循环引用。">weak_ptr</Term> 是「观察者」：它指向 `shared_ptr` 管理的资源但不增加引用计数。通过 `lock()` 提升为 `shared_ptr` 来安全访问。它的核心用途是打破循环引用——两个对象互相用 `shared_ptr` 指向对方，引用计数永远不归零，资源永不释放。

## 资源管理类的拷贝行为

条款 14 提醒：RAII 对象被拷贝时需要同时处理资源和所有权的语义。拷贝策略由资源的性质决定：资源能共享吗（`shared_ptr`）？能复制吗（深拷贝）？能转移吗（`unique_ptr` 的 move）？如果都不行，就禁止拷贝（`= delete`）。

条款 16 补充：成对使用 `new` 和 `delete` 时要采取相同形式——`new` 配 `delete`，`new[]` 配 `delete[]`，混用是未定义行为。条款 17 进一步要求：以独立语句将 `newed` 对象置入智能指针，避免编译器在参数求值顺序中插入异常导致泄漏。

<Callout type="tip">
<strong>建议 →</strong> 默认用 `unique_ptr`，只有在需要共享所有权时才用 `shared_ptr`。`unique_ptr` 可以隐式转换为 `shared_ptr`，反之不行——从独占到共享是安全的降级。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 两个对象互相用 `shared_ptr` 指向对方，内存永不释放。<strong>原因 →</strong> 循环引用导致引用计数永远不归零。<strong>修法 →</strong> 其中一方改用 `weak_ptr`，打破循环；访问时用 `lock()` 提升为 `shared_ptr`。
</Callout>

## 小结与练习

- RAII 把资源生命周期绑定到对象生命周期，利用栈展开保证释放
- unique_ptr 独占（默认选择），shared_ptr 共享（引用计数），weak_ptr 观察（打破循环）
- RAII 对象的拷贝策略由资源性质决定：共享、深拷贝、转移或禁止
- new/delete 必须形式匹配，独立语句置入智能指针防异常泄漏

<Exercises>
  <Answer question="RAII 为什么能保证资源不泄漏？异常时也能保证吗？">RAII 把资源释放放在析构函数中。C++ 保证对象销毁时析构函数一定被调用——无论是正常离开作用域还是异常导致的栈展开。因此即使异常抛出，已构造的 RAII 对象的析构函数仍会执行，资源仍会被释放。这是 RAII 异常安全的根本保证。</Answer>
  <Answer question="什么时候用 unique_ptr，什么时候用 shared_ptr？默认应该选哪个？">默认选 unique_ptr——它零开销、语义清晰、不可误用。只有需要多个所有者共享同一资源时才用 shared_ptr。unique_ptr 可以隐式转换为 shared_ptr（共享化是安全的降级），但 shared_ptr 不能转回 unique_ptr。因此从独占开始，需要时再升级为共享。</Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="RAII">Resource Acquisition Is Initialization，资源获取即初始化。构造函数获取资源，析构函数释放资源，利用栈展开保证异常安全。是 C++ 资源管理的核心范式。</GlossaryItem>
  <GlossaryItem term="unique_ptr">独占所有权的智能指针。同一时刻只有一个指针持有资源，不可拷贝但可以 move 转移。零开销抽象，是管理动态资源的默认选择。</GlossaryItem>
  <GlossaryItem term="shared_ptr">共享所有权的智能指针。多个指针可以指向同一资源，通过引用计数管理。计数归零时释放资源。有原子计数开销和循环引用风险。</GlossaryItem>
  <GlossaryItem term="weak_ptr">不控制生命周期的观察者智能指针。不增加引用计数，配合 shared_ptr 使用以打破循环引用。通过 lock() 安全提升为 shared_ptr。</GlossaryItem>
  <GlossaryItem term="循环引用">两个或多个对象互相用 shared_ptr 指向对方，导致引用计数永远不归零，资源永不释放。解法是其中一方改用 weak_ptr。</GlossaryItem>
</Glossary>
