## 设计 class 犹如设计 type

在 C++ 中，每定义一个类就是在创造一种新类型。条款 19 提醒：设计类时要像设计 type 一样思考——这个类型的对象如何创建和销毁？初始化和赋值该怎样？按值传递会发生什么？哪些操作是合法的？它会参与继承体系吗？每个问题都是一道设计关卡。

## 封装与数据隐藏

条款 22 的核心建议：将成员变量声明为 <Term def="只有类自身和友元可以访问的访问级别，外部和派生类都不能直接访问。">private</Term>。三个理由：

第一，语法一致性。如果成员变量是 public，用户用 `obj.x` 访问；改成函数后所有调用点都要改。private 加访问函数让接口统一为函数调用，后续可以自由改变实现（加缓存、加验证）而不破坏调用代码。

第二，访问控制。private 允许你分别控制读权限和写权限——只提供 getter 不提供 setter（只读），或加验证逻辑（写时检查合法值）。public 成员做不到这些。

第三，封装不变式。类的核心价值是维护约束（如「年龄必须 ≥ 0」）。如果成员变量是 public 或 protected，用户或派生类可以绕过约束直接赋值。protected 不比 public 更安全——派生类仍然可以直接修改，破坏不变式。

## 接口防误用

条款 18 说「让接口容易被正确使用，不易被误用」。核心方法是用类型系统编码约束——不要用 `int month` 让用户传 13，用 <Term def="带作用域的枚举类型，不会隐式转换为整数，防止误用。">enum class</Term> 限制合法值。不要返回裸指针让用户忘记释放，返回 `unique_ptr` 让释放自动化。

保持接口行为一致：如果 `add` 返回新对象，`subtract` 也应如此，不要一个返回新对象一个修改自身。消除资源管理责任：不要让用户手动 lock/unlock，提供 RAII 守卫类。

## pass-by-reference-to-const

条款 20 推荐用 <Term def="按常量引用传递参数，避免拷贝开销且不修改实参，是 C++ 中传递对象参数的推荐方式。">pass-by-reference-to-const</Term> 替代 pass-by-value。三个优势：避免拷贝开销（大对象如 string/vector 拷贝代价高昂）、避免对象切片（基类按值传递会切掉派生类部分）、const 保证不被修改。

例外：内置类型（int、double、指针）和 STL 迭代器/函数对象按值传递更好——拷贝代价和引用一样小甚至更小。

## non-member 优于 member

条款 23 提出一个违反直觉的建议：宁以 non-member、non-friend 替换 member 函数。逻辑是——封装 = 减少能访问类内部的代码量。member 函数能访问所有 private 成员，non-member non-friend 只能通过 public 接口操作。因此 non-member non-friend 的封装性更强。

例如 `WebBrowser` 有 `clearCache()`、`clearHistory()`、`clearCookies()` 三个成员函数。`clearEverything()` 作为 member 能访问所有 private，封装性低；作为 non-member 只通过 public 接口调用三个函数，封装性高。额外优势：non-member 函数可以分布在多个头文件中，降低编译依赖。

<Callout type="tip">
<strong>建议 →</strong> 把一组便利函数放在与类同名的命名空间中，分布在不同头文件里。用户按需 include，既保持封装又方便扩展。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 成员变量声明为 protected，认为比 public 更安全，结果派生类直接修改破坏了不变式。<strong>原因 →</strong> protected 成员变量对派生类完全开放，和 public 一样不安全。<strong>修法 →</strong> 成员变量一律 private，派生类通过 protected 访问函数获取，访问函数中可以加验证逻辑。
</Callout>

## 小结与练习

- 成员变量一律 private——封装不变式，统一接口，控制读写权限
- 接口防误用——用类型限制参数（enum class），返回智能指针而非裸指针
- pass-by-reference-to-const 替代 pass-by-value——省拷贝、防切片，内置类型除外
- non-member non-friend 比 member 封装性更强——减少能访问 private 的代码量

<Exercises>
  <Answer question="为什么 non-member non-friend 函数比 member 函数封装性更好？">封装的定义是「减少能访问类内部的代码量」。member 函数能访问所有 private 成员，non-member non-friend 只能通过 public 接口操作。因此 non-member non-friend 访问的内部更少，封装性更强。如果某个功能可以通过 public 接口实现，就应该做成 non-member。</Answer>
  <Answer question="pass-by-reference-to-const 在什么情况下不如 pass-by-value？">三种情况：①内置类型（int/double/指针），拷贝代价和引用一样小，甚至更小（引用需要间接寻址）；②STL 迭代器和函数对象，设计为按值传递，拷贝代价极小；③小型不可变类型（1-2个内置成员），按值可能更快。经验：类型 ≤ 一个指针大小时按值更优。</Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="private">只有类自身和友元可以访问的访问级别。外部和派生类都不能直接访问。保证成员变量不被绕过不变式直接修改。</GlossaryItem>
  <GlossaryItem term="enum class">带作用域的枚举类型（C++11），不会隐式转换为整数，防止误用。用于接口防误用——用类型限制参数合法值。</GlossaryItem>
  <GlossaryItem term="pass-by-reference-to-const">按常量引用传递参数，避免拷贝开销且不修改实参。是 C++ 中传递对象参数的推荐方式，能防止对象切片。</GlossaryItem>
  <GlossaryItem term="对象切片">按值传递派生类对象给基类参数时，派生类部分被「切掉」，只剩基类部分，虚函数不会多态。用引用传递可避免。</GlossaryItem>
  <GlossaryItem term="non-member non-friend">不是类的成员也不是友元的函数，只能通过 public 接口操作类对象。比 member 函数封装性更强，因为访问的内部更少。</GlossaryItem>
</Glossary>
