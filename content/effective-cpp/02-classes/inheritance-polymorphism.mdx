## is-a 关系

条款 32 确立了 public 继承的核心语义：<Term def="public 继承表达的语义——派生类是一种基类，基类能出现的地方派生类都能出现。">is-a</Term> 关系。每个派生类对象都是一个基类对象。基类能出现的地方，派生类对象都能出现（里氏替换原则）。

is-a 不是「是一种」的日常语义，而是严格的接口兼容：基类的所有 public 操作对派生类都必须有意义且行为一致。企鹅继承鸟如果鸟有 `fly()` 方法就不是 is-a——企鹅不能飞，接口不兼容。正方形继承长方形也不行——长方形可以独立改变长和宽，正方形不能。

## 三种函数的继承语义

条款 34 区分了三种函数，对应三种继承语义：

<Term def="只声明接口不含实现的虚函数，派生类必须实现。">纯虚函数</Term>（`virtual void f() = 0;`）：只继承接口，不继承实现。派生类必须实现它（否则也是抽象类）。用于强制派生类定义行为。

<Term def="声明接口并提供默认实现的虚函数，派生类可覆盖。">虚函数</Term>（`virtual void f() {}`）：继承接口加默认实现，派生类可覆盖也可不覆盖。用于基类有合理默认行为、派生类可能需要定制的场景。

<Term def="非虚函数，接口加强制实现，派生类不应重新定义。">非虚函数</Term>（`void f() {}`）：继承接口加强制实现，派生类不应重新定义。用于行为在所有派生类中必须一致的场景。

## NVI 模式

条款 35 介绍 <Term def="Non-Virtual Interface 模式，public 非虚函数调用 private 虚函数，统一前后置检查。">NVI</Term>（Non-Virtual Interface）模式——virtual 函数的优选替代方案。结构是：public 非虚函数做前后置检查（日志、锁、不变式验证），调用 private 虚函数做实际工作。派生类只覆盖 private 虚函数，不改 public 接口。

NVI 的优势：统一入口控制——所有调用都经过前后置检查；分离接口与实现——接口是 non-virtual 不可改，实现是 virtual 可覆盖；「before」和「after」代码保证不变式在调用前后成立。

## 绝不重定义 non-virtual 和缺省参数值

条款 36 和 37 有共同的本质——静态绑定与动态绑定的不一致导致行为分裂。

non-virtual 函数是静态绑定的（由指针/引用的静态类型决定调用版本）。如果派生类重定义了基类的 non-virtual 函数，通过基类指针调用走基类版本，通过派生类指针调用走派生类版本——同一个对象行为不一致，违反 is-a 关系。

缺省参数值也是静态绑定的。如果派生类覆盖了 virtual 函数但改了缺省参数值：函数体是派生类的（动态绑定），缺省参数是基类的（静态绑定）——调用派生类函数却用了基类的参数值。解法是 NVI 模式：在 public 非虚函数中定义缺省参数，private 虚函数不带缺省参数，从根上消除不一致。

<Callout type="tip">
<strong>建议 →</strong> 默认用 NVI 模式替代直接暴露 virtual 函数。public 接口非虚、private 实现虚——这是分离接口与实现的最佳实践，同时避免缺省参数值的绑定陷阱。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 派生类覆盖了 virtual 函数但改了缺省参数值，运行时调用了派生类函数却用了基类的参数。<strong>原因 →</strong> virtual 函数体动态绑定，缺省参数静态绑定——两者由不同机制决定。<strong>修法 →</strong> 用 NVI 模式：缺省参数只在 public 非虚函数中定义，派生类覆盖 private 虚函数（无缺省参数）。
</Callout>

## 小结与练习

- public 继承 = is-a：基类操作对派生类都必须有意义且行为一致
- 纯虚=只继承接口，虚=接口+默认实现，非虚=接口+强制实现
- NVI 模式：public 非虚函数包裹 private 虚函数，统一前后置检查
- 绝不重定义 non-virtual 函数和缺省参数值——静态/动态绑定不一致导致行为分裂

<Exercises>
  <Answer question="纯虚函数、虚函数、非虚函数分别适合什么场景？">纯虚函数适合「派生类必须实现，基类没有合理默认」——如抽象基类的接口声明。虚函数适合「基类有合理默认，派生类可能定制」——如 Shape::draw 有默认实现但 Circle 可以覆盖。非虚函数适合「行为在所有派生类中必须一致」——如对象的 ID 生成。不确定时默认用非虚，等需要多态时再改虚。</Answer>
  <Answer question="为什么缺省参数值是静态绑定的？这会导致什么问题？">C++ 规定缺省参数值由函数调用的静态类型决定（编译期），而非对象的实际类型（运行期）。如果派生类覆盖 virtual 函数时改了缺省参数，函数体走派生类（动态绑定），参数值走基类（静态绑定）——行为混乱。解法是 NVI 模式：缺省参数只在非虚函数中定义，虚函数不带缺省参数。</Answer>
</Exercises>
