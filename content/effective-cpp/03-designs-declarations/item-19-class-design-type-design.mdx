## 从 class 初稿的问题开始

声明一个 class，就是向语言加入一种新 type。调用者会创建、复制、移动、比较、转换、存储和销毁它；编译器会根据声明决定哪些表达式合法。因此 Item 19 的要求是 Treat class design as type design（设计 class 犹如设计 type）。

<Term def="从合法值、生命周期、操作、转换、错误和性能等完整可观察行为出发设计 class。">
  class design as type design
</Term>

下面这个初稿只有存储，没有类型设计：

```cpp
struct Money {
    long long amount;
    int currency;
    int scale;
};
```

它允许负 scale、未知 currency、不同币种直接相加，也没有说明 amount 是元、分还是最小货币单位。public fields 把所有责任推给每个调用者。

<Term def="用户只通过 public API 能观察到的值域、操作结果、失败、复杂度与生命周期保证。">
  observable type contract
</Term>

设计应先写出契约，再选择字段。字段只是实现契约的一种方式。

## 先定义合法值与不变量

类型首先要回答“什么对象是合法的”。Money 至少需要 currency、scale 与数值范围的一致规则。

<Term def="一个类型允许表示的全部合法状态集合。">value domain</Term>

```cpp
class Money {
public:
    static Result<Money, MoneyError> fromMinor(
        std::int64_t amount,
        Currency currency);

    std::int64_t minorUnits() const noexcept { return amount_; }
    Currency currency() const noexcept { return currency_; }

private:
    Money(std::int64_t amount, Currency currency) noexcept;

    std::int64_t amount_;
    Currency currency_;
};
```

<Term def="对象从构造成功到析构开始前始终必须满足的状态关系。">
  representation invariant
</Term>

private constructor 与 validating factory 确保公开世界只能看到合法 Money。每个 modifier 要么保持 invariant，要么失败且对象不变。

<Term def="一次 public operation 完成后，类型不变量仍成立的保证。">
  invariant preservation
</Term>

<Callout type="trap">
  **现象**：先 default construct，再依次 set
  amount、currency、scale。**原因**：设置期间对象可被观察为半有效状态，异常或早退会发布残缺对象。**修法**：一次初始化所有必需值，验证成功后才返回完整对象。
</Callout>

## 对象创建销毁是一份协议

object creation and destruction（对象创建销毁）不只是 constructor/destructor 语法。需要回答：允许 default construction 吗；创建会失败吗；失败怎样报告；对象拥有资源吗；谁能销毁；销毁是否可抛；是否允许 stack、heap 和跨模块创建。

<Term def="从输入验证、对象发布到最终销毁的一整套创建和释放规则。">
  lifecycle protocol
</Term>

对没有合理“空金额”的 Money，可以不提供 default constructor。对 identity object 如数据库连接，创建可能走 factory，析构归还连接，复制被删除，移动转移句柄。

```cpp
class Connection {
public:
    static Result<Connection, ConnectError> open(Endpoint);

    Connection(const Connection&) = delete;
    Connection& operator=(const Connection&) = delete;
    Connection(Connection&&) noexcept;
    Connection& operator=(Connection&&) noexcept;
    ~Connection() noexcept;
};
```

<Term def="对象代表可独立复制的值，复制后各对象语义相等但生命周期互不依赖。">
  value semantics
</Term>

<Term def="对象代表唯一外部实体或资源身份，复制会造成责任或身份冲突。">
  identity semantics
</Term>

先决定 value 还是 identity，再决定 special members；不能因为字段“刚好可复制”就默认允许复制。

## 初始化与赋值必须分开回答

initialization and assignment（初始化与赋值）看起来都把 rhs 内容放进 lhs，但前提完全不同：初始化面对尚不存在的值，赋值面对一个已有合法对象。

<Term def="在对象生命周期开始时一次建立表示和不变量的操作。">
  initialization contract
</Term>

<Term def="用新值替换一个已存在合法对象，同时规定失败保证和 self-assignment 行为的操作。">
  assignment contract
</Term>

```cpp
Money price = Money::fromMinor(1999, Currency::CNY).value(); // initialization
Money backup = price;                                        // copy initialization
backup = discount;                                           // assignment
```

assignment 要说明币种是否可改变、失败时 lhs 是否保持原值、self-assignment 是否安全。若类型持有多个资源，copy-and-swap 或先构造 candidate 再 commit 可提供强异常保证。

<Term def="操作失败时原对象保持调用前可观察状态的异常保证。">
  strong assignment guarantee
</Term>

<EcppLifecycleContractMap />

移动后的源对象不必保持原值，但必须可析构、可重新赋值，并满足文档声明的最小状态。

<Term def="move operation 后源对象仍满足类型允许的、可安全销毁和重新赋值的状态。">
  valid moved-from state
</Term>

## 按值传递暴露了什么成本

类型设计还要回答 pass-by-value 的含义与成本。Money 只有两个机器字且复制独立，按值可能合理；Connection 不可复制，只能 borrow 或 transfer。

<Term def="复制、移动、析构和间接访问给调用表达式带来的时间与空间代价。">
  value-transfer cost
</Term>

对于多态基类，按值传递还会 slicing；对于小型 value type，过度强制 const reference 可能增加间接访问。接口应从语义和测量决定，而不是套统一口号。

<Term def="参数形式直接表达借用、复制或 ownership transfer 的调用契约。">
  parameter ownership semantics
</Term>

## 操作集合要符合领域代数

能实现 operator 不等于应该提供。Money 的加法只对同币种闭合；不同币种需要 ExchangeRateContext，不能悄悄读取 global 汇率。

```cpp
Result<Money, CurrencyMismatch> operator+(Money lhs, Money rhs);

Money convert(
    Money source,
    Currency target,
    const ExchangeRateTable& rates,
    RoundingPolicy rounding);
```

<Term def="一种操作的输入、输出和组合规律与用户对该领域符号的稳定预期一致。">
  domain algebra
</Term>

比较也要决定 total ordering 是否存在。金额币种不同，直接 `operator<` 可能没有语义；显式转换后比较更诚实。

<Term def="一个操作对类型全部合法值都有明确、无歧义且保持不变量的结果。">
  operation closure
</Term>

<Callout type="trap">
  **现象**：因为底层 amount
  是整数，就自动生成所有算术和比较运算符。**原因**：存储表示的代数不等于领域代数，不同
  currency
  比较没有上下文。**修法**：只发布能写出领域规律和错误语义的最小操作集。
</Callout>

## 类型转换扩大了合法表达式集合

type conversions（类型转换）决定哪些其他类型能悄悄进入当前类型。隐式转换每增加一个，overload resolution 与调用者推理都会更复杂。

<Term def="无需调用者显式写出转换即可由编译器插入的类型变化。">
  implicit conversion
</Term>

`Money(long long)` 不应隐式，因为整数没有 currency；`operator long long()` 也会静默丢失币种。可改用命名 factory 和 accessor：

```cpp
auto price = Money::fromMinor(1999, Currency::CNY);
auto units = price.value().minorUnits();
```

<Term def="调用点明确写出语义变化、验证或信息损失的转换边界。">
  explicit conversion boundary
</Term>

无损且符合直觉的转换才可能隐式，例如 iterator 到 const_iterator；仍要测试 overload ambiguity。单参数 constructor 默认应先考虑 `explicit`。

## 继承必须回答 substitutability

inheritance（继承）不是代码复用按钮，而是在类型系统中声明关系。public inheritance 表示派生对象可在任何要求 base 的地方使用，并保持 base 的全部可观察契约。

<Term def="任何接受 base 的正确程序替换为 derived 后，仍保持原有可观察正确性。">
  substitutability
</Term>

若 FixedRateMoney 企图继承 Money，但禁止 currency 变化，而 base assignment 允许变化，substitutability 已破坏。只复用实现时应使用 composition 或 private implementation helper。

<Term def="一个类型以成员对象组合另一个实现能力，而不向用户声明 is-a 关系。">
  composition for reuse
</Term>

多态基类还要决定 virtual destructor、clone、copy policy、object slicing 与异常规格；这些都是 type contract，不是后补细节。

## 暴露与封装决定演进空间

public data、inline representation assumptions 和返回内部 handle 都会把实现变成用户依赖。类型应暴露语义操作，而不是存储步骤。

<Term def="在不破坏用户代码的前提下更换表示、缓存、验证或算法的设计余量。">
  representation freedom
</Term>

Money 可以今天使用 int64 minor units，未来换成 decimal；只要 observable contract 不变，调用者无需修改。若公开 amount/scale 字段，迁移会穿透整个代码库。

<Term def="用户源码或二进制已经依赖、后续版本必须维持或显式迁移的公开行为集合。">
  compatibility surface
</Term>

越多 public member、conversion 和 operator，compatibility surface 越大。最小接口不是少写代码，而是减少未来无法撤回的承诺。

## 泛型需求与性能保证也要提前决定

若类型要进入 unordered container，需要 equality 与 hash 一致；要排序需要 ordering；要做 compile-time value 需要 literal-type 条件；要跨 ABI 需要稳定 layout 或 opaque handle。

<Term def="为模板、容器或算法使用而必须满足的语法和语义要求集合。">
  generic contract
</Term>

性能也是 observable contract 的一部分。用户可能依赖 move 是 O(1)、lookup 是对数复杂度、destructor 不阻塞。若无法长期保证，不要在接口文档中随意承诺。

<Term def="类型操作对时间、空间、分配和阻塞行为给出的可依赖上界。">
  complexity guarantee
</Term>

## 用类型契约矩阵验收设计

先预测 Money 初稿会允许哪些非法表达式，再为每类决策建立证据：

- 构造：非法 currency、overflow、wire scale 不会发布对象。
- 复制移动：value type 独立；identity type 不可复制；moved-from 可析构和赋值。
- 赋值：self-assignment 与失败注入保持 invariant，资源不重复释放。
- 转换：整数不能隐式变 Money，信息损失必须命名且可见。
- 运算：不同币种相加返回明确错误，rounding policy 不依赖 global state。
- 继承：base contract tests 对每个 derived 重跑，验证 substitutability。
- 泛型：equality/hash、ordering 与 container requirements 保持一致。
- 性能：benchmark 验证承诺的复制、移动和 allocation 行为。

<Term def="把合法值、生命周期、操作、转换、继承与性能决策映射到测试证据的清单。">
  type contract matrix
</Term>

这张矩阵能区分“代码当前能跑”和“类型契约已经设计并可持续验证”。

## 小结

- 设计 class 就是在设计新 type，应先写 observable contract，再选字段与函数
- 合法值和 invariant 决定对象何时可以发布，创建与销毁共同形成生命周期协议
- initialization 建立对象，assignment 替换已有对象，两者的失败和 self-assignment 契约不同
- value/identity 语义决定 copy、move、destructor 和参数 ownership
- operator、type conversion 与 inheritance 都会扩大合法表达式集合，必须符合领域规律
- 用 type contract matrix 验证构造、转换、继承、泛型与性能承诺

<Exercises>
  1. **问题 1：审查 Money 初稿。** 针对 public amount/currency/scale，写出完整 type contract 与迁移后的最小接口。

<Answer question="Money 类型应先决定哪些契约？">
  定义合法 currency 与数值范围，由 validating factory 一次建立 invariant；确定
  value semantics、copy/move 成本和 assignment
  强保证；只允许同币种算术，不同币种转换显式接收汇率与 rounding
  policy；整数不能隐式转换。字段改 private，调用点迁往 named
  factory/accessor，并用构造负例与代数测试验收。
</Answer>

2. **问题 2：设计 Connection 生命周期。** 连接持有唯一 socket，open 会失败，业务需要借用和转移但不能复制。

  <Answer question="Connection 的创建复制移动和销毁应怎样设计？">使用返回 `Result<Connection, ConnectError>` 或 typed owner 的 factory；删除 copy constructor/assignment；提供 noexcept move，使源保持可析构和可重新赋值；destructor noexcept 关闭 socket。只读操作接收 reference borrow，取得连接的接口接收 rvalue/owner。失败注入验证每个成功 open 只 close 一次。</Answer>

3. **问题 3：判断继承与转换。** FixedRateMoney 想继承 Money 并隐式接受整数，同时禁止改变 currency，分析问题并重构。

  <Answer question="为什么该继承和隐式转换会破坏类型契约？">整数没有 currency，隐式构造会产生上下文依赖与 overload 歧义；改成显式 named factory。若 Money base 允许替换 currency，而 FixedRateMoney 禁止，derived 不能满足 base 全部操作，public inheritance 不具 substitutability；改用 composition，内部持有 Money 和固定汇率策略，只暴露符合自身 domain algebra 的接口。</Answer>
</Exercises>
