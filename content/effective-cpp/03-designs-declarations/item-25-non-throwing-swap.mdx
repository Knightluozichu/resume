## 从一个昂贵的通用交换开始

`std::swap(a, b)` 的通用实现概念上需要一个临时对象和若干 move/copy assignments：

```cpp
template<class T>
void genericSwap(T& a, T& b) {
    T temp(std::move(a));
    a = std::move(b);
    b = std::move(temp);
}
```

对普通 value type 可能足够；对拥有昂贵 invariant、custom allocation 或 pimpl 的类型，它可能做远多于“交换身份”所需的工作。

<Term def="使用类型的 move/copy construction 与 assignment 交换两个完整对象的标准后备策略。">
  generic swap fallback
</Term>

Item 25 的原则是 Consider support for a non-throwing swap（考虑写出一个不抛异常的 swap）。目标包含两部分：找到类型最便宜的表示交换，并把它接入泛型查找协议。

<Term def="在不分配、不复制业务资源且不会抛异常的情况下交换两个对象的可观察值。">
  non-throwing swap
</Term>

## pimpl 只需要交换 implementation owner

pimpl idiom（pimpl）把大部分表示放在独立 implementation object：

```cpp
class Widget {
public:
    Widget();
    Widget(const Widget& rhs);
    Widget& operator=(Widget rhs);
    ~Widget();

    void swap(Widget& other) noexcept;

private:
    std::unique_ptr<WidgetImpl> pImpl_;
};
```

<Term def="public class 只保存指向不完整 implementation type 的 owner，以隐藏表示和降低编译依赖。">
  pimpl idiom
</Term>

Widget 的全部状态由 `pImpl_` owner 表示。交换两个 Widget 无需复制 WidgetImpl，只交换两个 unique owners：

```cpp
void Widget::swap(Widget& other) noexcept {
    pImpl_.swap(other.pImpl_);
}
```

<Term def="由 class 提供、能够直接交换 private representation 的成员函数。">
  member swap
</Term>

unique_ptr swap 是常数时间且不分配，因此 Widget member swap 可正确声明 noexcept。

  已足够快。**原因**：类型的 move/assignment 可能维护额外状态、日志或 allocator
  规则，且泛型算法无法知道只换 owner 即可。**修法**：提供直接交换 representation
  的 member swap，并测量/声明真实 noexcept。
</Callout>

## 为什么 swap 应尽量不抛

swap 常被用作事务的 commit point：先在临时对象中完成可能失败的准备，再一次交换到目标。

<Term def="所有可能失败的工作成功后，以一个不可失败操作发布完整新状态的边界。">
  commit point
</Term>

```cpp
Widget& Widget::operator=(Widget rhs) {
    swap(rhs);
    return *this;
}
```

按值参数 rhs 在进入函数体前完成 copy/move；若失败，`*this` 未变。函数体 swap 若不抛，新状态一次提交，旧状态随 rhs 析构。

<Term def="操作失败时目标保持调用前状态，成功时发布完整结果的异常安全等级。">
  strong exception guarantee
</Term>

若 swap 在交换一半成员后抛异常，目标和候选都可能部分改变，commit 模型失效。

## noexcept 必须来自成员保证

不能为了满足建议而撒谎声明 noexcept。若 member swap 可能抛，noexcept 会在异常逃出时调用 `std::terminate`。

<Term def="异常离开被声明 noexcept 的函数时，程序终止而不是继续栈展开的语言规则。">
  noexcept termination rule
</Term>

成员组合类型应使用条件 noexcept：

```cpp
class Record {
public:
    void swap(Record& other)
        noexcept(noexcept(std::swap(id_, other.id_)) &&
                 noexcept(std::swap(payload_, other.payload_)));

private:
    Id id_;
    Payload payload_;
};
```

<Term def="函数 noexcept 状态由其组成操作是否不抛在编译期推导的声明。">
  conditional noexcept
</Term>

实现中使用成员的高效 swap；对于未知泛型成员，应采用 ADL-aware helper，而不是硬编码所有 `std::swap`。

## 同 namespace non-member swap 接入 ADL

member swap 高效但泛型算法通常调用 free `swap(a,b)`。因此在类型 namespace 提供 non-member overload：

```cpp
namespace ui {

void swap(Widget& lhs, Widget& rhs) noexcept {
    lhs.swap(rhs);
}

} // namespace ui
```

<Term def="与用户类型处于同 namespace、转调 member swap 并可由 ADL 找到的自由函数。">
  ADL-visible swap
</Term>

它不需要 friend，因为 member swap 已是 public；它只是连接查找协议与 private-aware implementation。

<Term def="public member 提供表示交换，non-member overload 提供泛型发现的双层定制结构。">
  two-layer swap customization
</Term>

## 泛型代码不要直接限定 std::swap

正确的泛型调用模式是：

```cpp
template<class T>
void exchangeValues(T& a, T& b)
    noexcept(noexcept(swap(a, b)))
{
    using std::swap;
    swap(a, b);
}
```

先 `using std::swap` 引入标准 fallback，再进行 unqualified call，让 ADL 同时寻找类型 namespace 的专用 overload。

<Term def="函数名不带 namespace 限定，使普通查找与 ADL 共同建立候选集合的调用。">
  unqualified swap call
</Term>

直接写 `std::swap(a,b)` 会绕过普通 ADL overload；只写 `swap(a,b)` 又可能在没有定制时找不到 fallback。

<Term def="在没有类型专用 swap 时可用的标准库通用实现。">
  std swap fallback
</Term>

<Callout type="trap">
  **现象**：generic algorithm 中始终写 `std::swap(a,b)`。**原因**：namespace
  限定阻止 ADL 选择用户类型的高效 overload。**修法**：函数作用域先 `using
  std::swap`，随后非限定调用 `swap(a,b)`。
</Callout>

## 非模板用户类型可选 std::swap 全特化

对具体 user-defined type，可以为 `std::swap` 提供符合规则的 explicit full specialization，转调 member swap：

```cpp
namespace std {

template<>
void swap(ui::Widget& lhs, ui::Widget& rhs) noexcept {
    lhs.swap(rhs);
}

} // namespace std
```

<Term def="为一个具体用户自定义类型提供的 std::swap 模板显式全特化。">
  std::swap specialization
</Term>

这使显式写 `std::swap(widgetA, widgetB)` 的代码也走高效路径。但首选仍是同 namespace non-member overload 加 ADL-aware 调用，因为覆盖面更自然。

<Term def="为所有模板参数都已确定的单一类型组合提供标准模板替代实现。">
  explicit full specialization
</Term>

不得向 `std` 随意添加普通 overload；只能在标准允许的 user-defined type specialization 边界内操作。

## class template 不要试图偏特化函数模板

若 Widget 本身是 class template：

```cpp
template<class T>
class Widget;
```

希望为所有 `Widget<T>` 偏特化 `std::swap` 会遇到问题：function templates 不能 partial specialization。

<Term def="只固定部分模板参数、其余仍保持泛化的特化形式；函数模板不支持这种机制。">
  function-template partial specialization
</Term>

正确做法是在 Widget 自己的 namespace 提供 function template overload：

```cpp
namespace ui {

template<class T>
void swap(Widget<T>& lhs, Widget<T>& rhs)
    noexcept(noexcept(lhs.swap(rhs)))
{
    lhs.swap(rhs);
}

} // namespace ui
```

<Term def="与 class template 同 namespace 的 swap function template，由 ADL 为每个实例发现。">
  template swap overload
</Term>

不要在 `std` namespace 添加该 overload。

## member swap 应逐项使用正确 swap

非 pimpl 类型可能有多个成员。member swap 要为每个成员选择最合适定制：

```cpp
void Document::swap(Document& other)
    noexcept(noexcept(swap(title_, other.title_)) &&
             noexcept(swap(body_, other.body_)))
{
    using std::swap;
    swap(title_, other.title_);
    swap(body_, other.body_);
}
```

<Term def="member swap 内对组成成员同样使用标准 fallback 加 ADL 定制的递归协议。">
  compositional swap
</Term>

实际代码中 noexcept expression 的 name lookup 要保证声明顺序和 helper 可见；可用 `std::is_nothrow_swappable_v` 等 traits 简化条件。

<Term def="在编译期判断某类型是否可交换且交换是否不抛的标准类型性质。">
  nothrow swappable trait
</Term>

若任一成员 swap 会抛，外层不能承诺无条件 noexcept。

## allocator-aware 类型要审查交换前提

标准容器和自定义 allocator-aware 类型的 swap 可能受 allocator equality 与 propagation traits 约束。交换内部 buffer owner 前，必须确保释放责任仍匹配 allocator。

<Term def="容器 swap 时 allocator 是否随对象一起交换的类型属性。">
  allocator propagation policy
</Term>

```text
propagate_on_container_swap == true
  -> allocator 与 storage 一起交换
false and allocators equal
  -> storage 可安全交换
false and allocators differ
  -> 不能盲目交换 owner
```

<Term def="内存必须最终由与其分配来源兼容的 allocator 释放的不变量。">
  allocator ownership invariant
</Term>

这类 swap 的 noexcept condition 必须与 allocator contract 一致，不能只看 pointer swap。

## swap 还影响容器和算法优化

标准算法、sort、rotate、optional/variant 和容器操作会依据 swappability/noexcept 选择路径或保证。正确 swap 不只是赋值实现细节。

<Term def="泛型算法通过 swap traits 和 ADL 使用用户类型高效交换能力的集成契约。">
  generic swappability contract
</Term>

若 move construction 抛但 swap 不抛，算法仍可能用 swap 维持更强保证。反之，错误 noexcept 会把可恢复异常变成 terminate。

<Term def="算法根据操作的 noexcept 属性选择能维持性能或异常保证的实现分支。">
  noexcept-driven algorithm selection
</Term>

## 用失败注入和查找轨迹验收

先预测每种调用形式最终选择哪个 function，再建立验证矩阵：

- member `a.swap(b)`、ADL `swap(a,b)`、显式 `std::swap(a,b)` 分别记录命中路径。
- pimpl swap 验证 implementation address 互换、无 allocation/copy/move。
- static assertions 验证 `is_nothrow_swappable` 与函数声明一致。
- copy-and-swap failure injection：candidate 构造失败时目标不变，commit 不抛。
- class template 实例验证同 namespace overload，不向 `std` 添加非法 overload。
- allocator 相等/不等与 propagation 组合验证 owner/deallocator 配对。
- self-swap 保持合法值，资源 ledger 不 double free 或泄漏。

<Term def="记录 swap 调用形式、候选选择、成员操作、异常和资源 owner 变化的事件序列。">
  swap resolution trace
</Term>

只有查找正确、成本正确、noexcept 真实三者同时成立，swap 定制才完成。

## 小结

- pimpl/resource type 应提供直接交换 representation 的 member swap，避免通用 move/copy 成本
- non-throwing swap 可作为 prepare-then-commit 的可靠提交点，支撑 strong exception guarantee
- 在类型 namespace 提供 non-member swap 转调 member，使 ADL 能发现定制
- generic code 使用 `using std::swap; swap(a,b)`，同时保留用户定制与标准 fallback
- 具体非模板 user type 可选 std::swap 全特化；class template 用自身 namespace function template overload
- noexcept 必须由 member、allocator 和递归 swap 的真实保证推导，不能虚假声明
