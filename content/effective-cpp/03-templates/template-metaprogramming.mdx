## 把计算搬到编译期

<Term def="Template Metaprogramming，利用 C++ 模板机制在编译期执行计算的编程技术。">模板元编程</Term>（TMP）是 C++ 最强大也最复杂的特性之一。它的核心思想是把计算从运行期搬到编译期——用模板实例化做编译期编程，让结果在编译完成时就已经算好，运行期零开销。

## TMP 的三要素

TMP 把编程范式映射到模板机制上：类型当值，实例化当循环，特化当分支。

类型当值：模板参数既可以是类型（`typename T`），也可以是值（`int N`），编译期可以对这些参数做计算。

实例化当循环：递归模板实例化实现编译期迭代。例如 `factorial<N> = N * factorial<N-1>`，编译器递归展开模板实例化，直到遇到终止条件。

特化当分支：主模板和偏特化/全特化构成编译期条件分支。`factorial<0>` 的全特化是递归终止条件——当 N 减到 0 时，编译器选择特化版本而非主模板，递归终止。

```cpp
template<int N>
struct factorial { static const int value = N * factorial<N-1>::value; };
template<>
struct factorial<0> { static const int value = 1; };  // 终止
// factorial<5>::value == 120，编译期已计算完毕
```

## SFINAE

<Term def="Substitution Failure Is Not An Error，模板参数替换失败时不报错而是排除该候选模板。">SFINAE</Term>（替换失败非错误）是模板重载解析的一条规则：在模板参数替换过程中，如果某个候选模板的替换导致无效类型或表达式，编译器不报错，而是静默排除该候选模板，继续尝试其他重载。

SFINAE 解决的问题是编译期条件选择——根据类型特征选择不同的函数重载。例如检测类型 T 是否有 `size()` 方法：有则调用版本 A，没有则调用版本 B。第一个模板替换成功就选择它，替换失败就静默排除，继续尝试第二个。

常见 SFINAE 工具包括 `enable_if`（条件为真时提供类型）、`void_t`（简化检测）和 `decltype` + 逗号表达式。现代 C++ 中 `if constexpr`（C++17）和 Concepts（C++20）部分替代了 SFINAE，但理解 SFINAE 对阅读旧代码和深入理解模板机制仍然必要。

## type traits

条款 47 介绍 <Term def="编译期查询和变换类型属性的模板工具，定义在 type_traits 中。">type traits</Term>（类型特征）——一组在编译期查询和变换类型属性的模板工具，定义在 `<type_traits>` 中。

类型查询：`is_integral<T>::value`（T 是否整数）、`is_pointer<T>::value`（T 是否指针）、`is_class<T>::value`（T 是否类类型）。

类型变换：`remove_const<T>::type`（去 const）、`add_pointer<T>::type`（加指针）、`decay<T>::type`（退化）。

编译期类型分派的典型模式：用 `is_integral<T>::type` 获取 `true_type` 或 `false_type` 标签，传给不同的重载函数实现编译期分派——零运行时开销。STL 的 `iterator_traits` 查询迭代器类别，算法根据类别选择最优实现。

<Callout type="tip">
<strong>建议 →</strong> 现代 C++ 中优先用 `if constexpr`（C++17）和 Concepts（C++20）替代 SFINAE——代码更易读、错误信息更清晰。只有在需要支持旧标准时才回退到 SFINAE。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> TMP 代码编译时间从秒级暴涨到分钟级，错误信息动辄数百行。<strong>原因 →</strong> 递归模板实例化呈指数增长，深层 TMP 会生成大量中间类型。<strong>修法 →</strong> 优先用 `constexpr` 函数替代模板递归做编译期计算；用 `if constexpr` 替代 SFINAE 做分派；只在必要时使用底层 TMP。
</Callout>

## 小结与练习

- TMP 把计算搬到编译期：类型当值、实例化当循环、特化当分支
- SFINAE 让编译器在替换失败时静默排除候选模板，实现编译期条件选择
- type traits 在编译期查询和变换类型属性，配合标签分派实现零开销类型分支
- 现代 C++ 用 constexpr/if constexpr/Concepts 降低 TMP 门槛

  <Answer question="SFINAE 解决了什么问题？它的工作原理是什么？">SFINAE 解决编译期条件选择——根据类型特征选择不同函数重载。工作原理：模板参数替换时如果导致无效类型或表达式，编译器不报错而是静默排除该候选模板，继续尝试其他重载。这样可以为不同类型特性提供不同的模板实现，编译器自动选择能替换成功的那个。</Answer>

## 名词解释

<Glossary>
  <GlossaryItem term="模板元编程（TMP）">Template Metaprogramming，利用 C++ 模板机制在编译期执行计算的编程技术。三要素：类型当值、实例化当循环、特化当分支。代价是编译时间长和错误信息难读，收益是零运行时开销和编译期类型安全。</GlossaryItem>
  <GlossaryItem term="SFINAE">Substitution Failure Is Not An Error，替换失败非错误。模板参数替换失败时编译器不报错而是排除该候选模板，用于编译期条件选择和类型特征检测。</GlossaryItem>
  <GlossaryItem term="type traits">编译期查询和变换类型属性的模板工具，定义在 type_traits 中。如 is_integral 查询是否整数、remove_const 去掉 const。配合标签分派实现零开销的类型分支。</GlossaryItem>
  <GlossaryItem term="编译期计算">在编译阶段完成的计算，通过模板递归实例化或 constexpr 函数实现。结果直接嵌入二进制，运行期零开销。</GlossaryItem>
</Glossary>
