## new 的两阶段操作

C++ 的 `new` 表达式不是一个原子操作，而是分两个阶段执行：先调用 `operator new` 分配原始内存，再在内存上调用构造函数构造对象。`delete` 表达式反向操作：先调用析构函数，再调用 `operator delete` 释放内存。

<EfcNewDeleteDiagram />

理解这两阶段的关键在于异常安全：如果第一阶段（分配内存）成功但第二阶段（构造函数）抛异常，编译器会自动调用 `operator delete` 释放第一阶段分配的内存——不会泄漏。这就是 `operator new` 和 `operator delete` 必须成对出现的原因。

## new-handler

条款 49 介绍 <Term def="当 operator new 无法满足内存分配请求时调用的回调函数，通过 set_new_handler 设置。">new-handler</Term>——当 `operator new` 无法满足内存分配请求时调用的函数，通过 `set_new_handler` 设置。

new-handler 可以做五件事：释放更多内存让 `operator new` 重试、安装不同的 new-handler（更激进的策略）、卸载 new-handler（直接抛 `bad_alloc`）、直接抛 `bad_alloc`、不返回（abort/exit）。

类可以有自己的专属 new-handler：用 RAII 类在构造时保存全局 handler 并安装类专属 handler，析构时恢复。这保证了异常安全——即使构造抛异常，handler 也会被恢复。

## placement new

<Term def="在已有内存上构造对象而不分配内存的 new 形式，如 new(ptr) T()。">placement new</Term> 在已有内存上构造对象，不分配内存。经典形式是 `new (ptr) T()`——在 `ptr` 指向的内存上构造 `T`。它常用于内存池、容器预分配、自定义内存管理。

placement new 的特殊之处在于它带额外参数（内存地址），因此匹配的是带额外参数的 `operator new` 重载。条款 52 警告：写了 placement new 就必须写对应的 placement delete。

原因在于异常路径：如果 `new (ptr) T()` 在构造函数时抛异常，编译器需要调用匹配的 `operator delete` 释放内存。编译器用 `operator new` 的签名去查找对应的 `operator delete`——如果找不到匹配的 placement delete，编译器不调用任何 delete，内存泄漏。

## 定制 new/delete 的常规

条款 51 列出自定义 `operator new` 需遵守的常规：正确返回内存、内存不足时调用 new-handler 并重试、处理零字节请求（当作 1 字节）、避免隐藏标准形式。

自定义 `operator delete` 需要：安全处理空指针（`delete nullptr` 合法）、不抛异常、匹配对应的 `operator new`。

一个隐蔽的陷阱：类内定义任何 `operator new` 都会隐藏所有全局版本（包括标准 placement new）。解决方法是在类内声明所有标准形式并转发到全局版本。

<Callout type="tip">
<strong>建议 →</strong> 大多数情况下不需要自定义 `operator new`/`delete`——标准库的默认实现已经足够好。只有在有明确性能需求（内存池、对齐要求）或调试需求（泄漏检测）时才考虑定制。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 自定义了带日志参数的 placement new 但没写对应的 placement delete，构造函数抛异常时内存泄漏。<strong>原因 →</strong> 编译器找不到匹配签名的 placement delete，不调用任何 delete。<strong>修法 →</strong> 每写一个自定义 operator new（带额外参数），就写一个签名匹配的 operator delete，同时声明标准形式避免名称隐藏。
</Callout>

## 小结与练习

- new = operator new（分配）+ 构造函数；delete = 析构函数 + operator delete（释放）
- new-handler 在内存不足时被调用，可释放内存、换策略或抛异常
- placement new 在已有内存上构造对象，不分配内存
- 写了 placement new 就必须写 placement delete——异常路径的清理需要它

## 名词解释

<Glossary>
  <GlossaryItem term="operator new">负责分配原始内存的全局或类内函数，new 表达式的第一阶段调用它。可以自定义以实现内存池、对齐控制等。内存不足时调用 new-handler。</GlossaryItem>
  <GlossaryItem term="new-handler">当 operator new 无法满足内存分配请求时调用的回调函数，通过 set_new_handler 设置。可释放内存、换策略、抛异常或终止程序。</GlossaryItem>
  <GlossaryItem term="placement new">在已有内存上构造对象而不分配内存的 new 形式，如 new(ptr) T()。常用于内存池和容器预分配。带额外参数，匹配带额外参数的 operator new 重载。</GlossaryItem>
  <GlossaryItem term="placement delete">与 placement new 配对的 operator delete 重载，仅在构造函数抛异常时被编译器调用以释放内存。不写 placement delete 会导致异常时内存泄漏。</GlossaryItem>
</Glossary>
