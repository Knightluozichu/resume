## 直觉引入

当你打开 Effective C#，面对 50 条建议，第一件事不是逐条背诵，而是看清它们背后的组织逻辑。Bill Wagner 把 C# 高效编程的经验整理成一条从语言习惯到并发设计的递进链——先学会正确使用语言，再管理资源，再驾驭泛型与 LINQ，最后处理并发与异常。

没有这条地图会怎样？你会今天学异常、明天学 LINQ，知识点散落一地，遇到问题想不起该用哪条建议。板块的意义在于建立「遇到哪类问题翻哪块」的索引。

### 四大板块

全书分为四大板块。第一板块「<Term def="C# 语言层面的基础习惯：用属性替代字段、用 readonly 替代 const、用 is/as 替代强转。">语言习惯</Term>」（条款 1-12）解决「怎么正确用 C#」——属性优先于字段、readonly 优于 const、is/as 优于强制转换。这是地基，后续所有建议都建立在这套习惯上。

第二板块「资源管理」（条款 13-25）解决「资源怎么不泄漏」——核心是 <Term def="标准释放模式：实现 IDisposable，提供 Dispose(bool) 同时清理托管与非托管资源，终结器兜底。">IDisposable 模式</Term>，配合 using 语句实现确定性释放。

第三板块「<Term def="用类型参数化与查询表达式提升抽象层次：泛型约束最小化、LINQ 延迟执行。">泛型与 LINQ</Term>」（条款 26-37）解决「如何泛化和查询」——泛型约束最小化、LINQ 的延迟执行与重复枚举陷阱。

第四板块「并发设计」（条款 38-50）解决「如何安全地并发」——异常过滤器、Task 并行、async/await、相等性与哈希一致性。

<Callout type="tip">
<strong>建议 →</strong> 每学完一个板块，挑一条建议动手写代码验证。比如学完资源管理，实现一个完整的 IDisposable 类型；学完并发设计，用 Task.WhenAll 重构一段串行 IO 代码。建议是经验，只有动手才能内化。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 跳过语言习惯直接学并发，结果 async 代码充满 async void 和死锁。<strong>原因 →</strong> 并发建立在对语言语义（类型、异常、相等性）的准确理解上，没有习惯地基就无法写出正确的异步代码。<strong>修法 →</strong> 按板块顺序学习，先把属性、readonly、异常基础吃透，再进入并发世界。
</Callout>

## 代码对照

```csharp
// 语言习惯：属性优先（条款 1）
public class Customer
{
    public string Name { get; set; }      // 属性：可校验、可虚拟、可数据绑定
    public int Age
    {
        get => _age;
        set => _age = value >= 0 ? value : throw new ArgumentException();
    }
    private int _age;
}

// 资源管理：IDisposable 模式（条款 12）
public class FileWrapper : IDisposable
{
    private readonly IntPtr _handle;
    private bool _disposed;

    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);
    }

    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;
        if (disposing) { /* 清理托管资源 */ }
        CloseHandle(_handle);              // 清理非托管资源
        _disposed = true;
    }

    ~FileWrapper() => Dispose(false);
}
```

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 把四大板块当成并列的「话题集」，随意挑选章节学习。<strong>原因 →</strong> 没有理解板块间的递进依赖：并发设计依赖对异常和类型的准确理解，泛型依赖对资源管理的掌握。<strong>修法 →</strong> 按板块顺序学习，语言习惯是地基、资源管理是安全网、泛型是骨架、并发是收口。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 学完一条建议就照搬到所有场景，比如到处用 readonly 或到处用 Task.WhenAll。<strong>原因 →</strong> 每条建议都有适用前提，脱离前提的「最佳实践」会变成反模式。<strong>修法 →</strong> 理解每条建议解决的问题和代价——readonly 版本安全但略慢、WhenAll 并行但有调度开销，按场景取舍。
</Callout>

## 小结与练习

<Exercises>
  <Answer question="为什么 Bill Wagner 把「属性优先」放在全书第一条？">属性是 C# 封装的基础单元。公共字段一旦发布就无法收回控制——无法加校验、无法虚拟化、无法数据绑定、无法参与接口契约。用属性替代字段，把存储细节藏在 get/set 后面，是后续所有面向对象建议（封装、接口、继承）的前提。把它放第一条，是在确立「先用属性，字段永远是 private」的地基习惯。</Answer>
  <Answer question="全书四大板块各自解决什么问题？为什么是递进而非并列？">语言习惯解决「怎么正确用语言」，资源管理解决「资源怎么不泄漏」，泛型与 LINQ 解决「如何泛化和查询」，并发设计解决「如何安全地并发」。它们递进：习惯是地基、资源是安全网、泛型是骨架、并发是收口——后一块都以前一块为前提，跳级会断层。</Answer>
</Exercises>

<Glossary>

  <GlossaryItem term="泛型与 LINQ">用类型参数化和查询表达式提升抽象层次的板块。泛型约束最小化保持复用性，LINQ 延迟执行让查询反映最新数据但需注意重复枚举。</GlossaryItem>
  <GlossaryItem term="推荐学习路径">由语言习惯→资源管理→泛型与 LINQ→并发设计递进而成的学习链，顺序由各板块之间的依赖关系决定，跳级会导致知识断层。</GlossaryItem>
