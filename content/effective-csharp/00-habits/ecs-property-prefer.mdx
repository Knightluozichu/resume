<Objectives>

- 能解释属性相比公共字段在封装、版本兼容与可扩展性上的优势
- 能把一个 public 字段改写为带校验的属性，并说明 ABI 不被破坏的原因
- 能回答：为什么接口里只能声明属性而不能声明字段？

</Objectives>

## 直觉引入

想象你开了一家快递柜。如果柜门没有锁（公共字段），任何人都能随意往里塞东西，甚至塞进损坏的包裹，你毫无办法。给柜门装上管理员（属性 get/set），管理员能检查包裹是否合规、能记录谁取了什么、还能换班时把权限交给别人——外部看到的还是同一个柜子，但控制权回到了你手里。

公共字段就是没锁的柜门：一旦发布，外部代码直接读写你的存储，你想加校验、改实现、做数据绑定，全都来不及。属性把「存什么」和「怎么访问」分开，让你永远保留修改访问逻辑的权力。

## 概念讲解

<EcsPropertyPreferDiagram />

### 属性是什么

<Term def="封装字段读写边界的成员，通过 get/set 访问器控制读取和赋值，可加校验、可虚拟、可参与接口。">属性</Term> 在 C# 中是一对 get/set 访问器，语法上像字段，语义上是方法调用。公共字段直接暴露存储，属性则把存储藏在访问器背后。

条款 1 的核心：对外暴露的数据成员一律用属性，字段永远是 private。这不是风格偏好，而是版本安全与可扩展性的硬要求。

### 属性带来的四项能力

第一，<Term def="在 set 访问器中校验赋值的合法性，拦截非法值。">封装校验</Term>。set 访问器可以拒绝非法值，字段做不到。第二，数据绑定。WPF、MAUI 等框架依赖属性通知机制（INotifyPropertyChanged），字段无法参与。第三，<Term def="接口只能包含属性、方法、事件、索引器，不能包含字段——属性是接口契约的合法成员。">接口契约</Term>。接口里只能声明属性，不能声明字段。第四，虚成员。属性可以声明为 virtual 供派生类 override，字段不能。

### 版本兼容

把字段改成属性会破坏二进制兼容——因为字段和属性编译出的 IL 元数据不同，调用方按字段访问的代码在属性版本上会抛 MissingMethodException。所以一旦用字段发布，就再也无法无痛改成属性。先用属性，永远留有余地。

<Callout type="trap">
<strong>现象 →</strong> 用 public 字段发布 API，后来想加校验改成属性，调用方全部报错。<strong>原因 →</strong> 字段和属性的 IL 访问指令不同（ldfld vs call get），二进制不兼容。<strong>修法 →</strong> 对外一律用属性发布，即使初版只是 `{ get; set; }` 自动属性，未来加校验也不破坏 ABI。
</Callout>

## 交互Demo

<Stepper>
  <Step title="第一步：公共字段——失控的存储">
    <EcsPropertyPreferDiagram />
    `public int Age;` 把存储直接暴露。外部可以写 `obj.Age = -5`，你无法拦截；改字段名会破坏二进制兼容；无法虚拟化、无法数据绑定、无法放入接口。一旦发布就收不回控制权。
  </Step>
  <Step title="第二步：自动属性——保留控制权">
    即使初版不需要校验，也用自动属性 `public int Age { get; set; }`。它编译成一对隐藏字段加访问器，对外是属性。未来想加校验时，只需把自动属性展开为带 backing field 的完整属性，调用方的二进制不受影响。
  </Step>
  <Step title="第三步：带校验的属性——拦截非法值">
    在 set 中加入 `value >= 0 ? value : throw`。外部赋值 `obj.Age = -5` 会抛异常，存储始终合法。这是字段永远做不到的——字段没有「赋值钩子」。
  </Step>
  <Step title="第四步：虚拟属性与接口契约">
    属性可声明 `virtual`，派生类用 override 改变行为；接口 `interface IAge { int Age { get; set; } }` 只能含属性。字段两者都做不到。当你需要多态或契约时，属性是唯一选择。
  </Step>
</Stepper>

## 代码对照

```csharp
// 反模式：公共字段
public class BadCustomer
{
    public string Name;     // 外部可随意写，无校验
    public int Age;         // 可被写成 -5
}

// 推荐：属性
public class Customer
{
    public string Name { get; set; }

    public int Age
    {
        get => _age;
        set => _age = value >= 0
            ? value
            : throw new ArgumentOutOfRangeException(nameof(Age));
    }
    private int _age;

    // 只读属性：构造后不可变
    public DateTime Created { get; } = DateTime.Now;

    // 计算属性：每次访问求值，无存储
    public bool IsMinor => Age < 18;
}

// 接口契约：只能用属性
public interface IProfile
{
    string Name { get; set; }   // 字段不被允许
    int Age { get; }
}
```

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 用 `public int X;` 发布，后来改成 `public int X { get; set; }`，调用方运行时抛 MissingFieldException。<strong>原因 →</strong> 字段（ldfld/stfld）和属性（call get_/set_）的 IL 指令不同，二进制不兼容。<strong>修法 →</strong> 一开始就用属性发布，即使不需要校验也用自动属性。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 在属性 get 里做昂贵的计算或 IO，调用方以为只是读字段，性能暴跌。<strong>原因 →</strong> 属性语法像字段，调用方会按字段预期频繁访问，但 get 实际是方法调用。<strong>修法 →</strong> get 应廉价且无副作用；昂贵的计算用方法（`ComputeX()`）命名以暗示代价。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 把 public 字段当成「公开常量」用，结果被外部修改导致状态错乱。<strong>原因 →</strong> 字段可写，没有只读保护。<strong>修法 →</strong> 只读数据用 `public T X { get; }`（只读属性）或 `public readonly T X`（运行期常量），不要用可写字段。
</Callout>

## 小结与练习

<Exercises>
  <Answer question="为什么接口里只能声明属性而不能声明字段？">接口定义的是行为契约（方法、属性、事件、索引器），不是实现细节。字段是存储实现，属于类的内部状态，放进接口会把实现细节泄漏到契约层。属性本质是一对 get/set 方法，符合「契约描述行为」的语义，所以接口允许属性而不允许字段。</Answer>
  <Answer question="把 public 字段改成属性为什么会破坏二进制兼容？">字段访问编译成 ldfld/stfld 指令直接读写内存偏移；属性访问编译成 call get_X/set_X 方法调用。两者的 IL 元数据和指令完全不同。调用方按字段编译的二进制，在属性版本里找不到对应的字段元数据，会抛 MissingFieldException。源码兼容但二进制不兼容。</Answer>
  <Answer question="属性 get 的设计约束是什么？为什么？">get 应廉价且无副作用。因为属性语法像字段，调用方会按字段预期频繁访问（如循环里读属性）。如果 get 做昂贵计算或有副作用（改状态、IO），调用方的性能预期和正确性都会被破坏。昂贵操作用方法命名暗示代价。</Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="属性">封装字段读写边界的成员，通过 get/set 访问器控制读取和赋值。语法上像字段，语义上是方法调用，可加校验、可虚拟、可参与接口与数据绑定。</GlossaryItem>
  <GlossaryItem term="自动属性">`{ get; set; }` 形式的属性，编译器自动生成隐藏的 backing field。对外是属性，未来可无痛展开为带校验的完整属性。</GlossaryItem>
  <GlossaryItem term="封装校验">在 set 访问器中校验赋值的合法性，拦截非法值。是属性相比字段的核心优势之一。</GlossaryItem>
  <GlossaryItem term="接口契约">接口只能包含属性、方法、事件、索引器，不能包含字段。属性是接口表达数据访问契约的唯一方式。</GlossaryItem>
  <GlossaryItem term="二进制兼容">改动能保持已编译程序集正常工作的兼容性。字段与属性的 IL 指令不同，互相替换会破坏二进制兼容。</GlossaryItem>
</Glossary>
