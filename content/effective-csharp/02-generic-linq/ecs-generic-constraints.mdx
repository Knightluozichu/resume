## 直觉引入

想象你招一个工人。如果你要求「会做饭、会编程、会开车、会画画」（约束多），能招到的人很少；如果你只要求「会编程」（约束少），能招到的人很多。但如果你什么要求都不提（无约束），你不知道这人会不会干活，只能让他搬砖（当 object 用）。

泛型约束就是给类型参数 T 设的「招聘要求」。不设约束，编译器不知道 T 能干什么，只能当 object；设了约束，编译器知道 T 有特定能力，能调用对应成员。Effective C# 的原则是「最小约束」——只要求你真正用到的能力，让尽可能多的类型能用你的泛型。

## 概念讲解

<EcsGenericConstraintsDiagram />

### 不加约束时 T 是什么

<Term def="用 where 子句限制类型参数必须满足的条件，使泛型代码能在 T 上调用特定成员。">泛型约束</Term> 的起点是理解「无约束的 T」。不加约束时，编译器只把 T 当 object——不能调用任何类型特定方法，不能用 `new T()`，不能赋 null（除非是引用类型）。这意味着泛型方法只能做 object 能做的事，丧失了类型优势。

### 五种约束及解锁的能力

`where T : class` 要求 T 是引用类型，解锁：可赋 null、可用 as/is。`where T : struct` 要求 T 是值类型（非 Nullable），解锁：无装箱存储。`where T : new()` 要求 T 有无参公共构造函数，解锁：`new T()`。`where T : IComparable<T>` 要求 T 实现接口，解锁：调用接口方法。`where T : Base` 要求 T 继承基类，解锁：访问基类成员。

### 最小约束原则

<Term def="Effective C# 原则：只约束泛型方法真正用到的能力，约束越少能传入的类型越多，泛型复用性越强。">最小约束原则</Term> 要求你只约束真正调用的成员。如果你的方法只调用 `CompareTo`，就只加 `IComparable<T>` 约束，不要顺便加 `new()` 或 `class`。约束越多，能传入的类型越少，泛型越不通用。

<Callout type="trap">
<strong>现象 →</strong> 泛型方法加了 `where T : class, new(), IComparable<T>` 三个约束，结果很多类型用不了。<strong>原因 →</strong> 多余的约束排除了不需要但满足核心能力的类型。<strong>修法 →</strong> 审视方法体真正用到的成员，只保留必需的约束。用约束替代运行时强制转换，让编译器在编译期保证类型安全。
</Callout>

## 交互Demo

<Stepper>
  <Step title="第一步：无约束——T 只能当 object">
    <EcsGenericConstraintsDiagram />
    `T Max<T>(T a, T b)` 不加约束时，编译器不知道 T 有什么方法，`a.CompareTo(b)` 编译报错。你只能用 `object` 的方法，泛型的类型优势丧失。这正是需要约束的原因。
  </Step>
  <Step title="第二步：加 IComparable<T> 约束">
    加 `where T : IComparable<T>` 后，编译器知道 T 有 CompareTo 方法，泛型方法可以调用它。int、string、自定义类型只要实现了 `IComparable<T>` 都能用。约束让泛型从「什么都能放但什么都干不了」变成「有特定能力的才能放且能干活」。
  </Step>
  <Step title="第三步：五种约束各解锁什么">
    class 解锁赋 null 与 as/is；struct 解锁无装箱值类型存储；new() 解锁 new T() 构造；接口约束解锁接口方法调用；基类约束解锁基类成员访问。每种约束都有代价——排除了不满足的类型。
  </Step>
  <Step title="第四步：最小约束——只约束用到的">
    Effective C# 强调最小约束：方法体只调用 CompareTo，就只加 `IComparable<T>`，别顺手加 new() 或 class。约束越少，能传入的类型越多，泛型越通用。每多一个约束都是在缩小适用范围，必须有充分理由。
  </Step>
</Stepper>

## 代码对照

```csharp
// 无约束：T 只能当 object，CompareTo 编译报错
public T MaxBad<T>(T a, T b)
{
    // return a.CompareTo(b) >= 0 ? a : b;  // 编译错误
    return a;  // 退化
}

// 最小约束：只约束真正用到的 IComparable<T>
public T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;

// new() 约束：解锁 new T()
public T Create<T>() where T : new()
    => new T();

// 多约束：每个都要有理由
public T FindOrCreate<T>(T[] items, T value)
    where T : IComparable<T>, new()      // 用到 CompareTo 和 new
{
    foreach (var item in items)
        if (item.CompareTo(value) == 0) return item;
    return new T();
}

// struct 约束：值类型，无 Nullable
public T Sum<T>(IEnumerable<T> source) where T : struct
{
    // T 不会是 null，可安全做值类型运算
    dynamic sum = default(T);
    foreach (var x in source) sum += x;
    return (T)sum;
}

// 使用：约束让编译器在编译期保证类型安全
Console.WriteLine(Max(3, 7));              // 7
Console.WriteLine(Max("apple", "banana")); // banana
```

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 不加约束就用 `((IComparable)a).CompareTo(b)` 强转，运行时类型不匹配抛异常。<strong>原因 →</strong> 用运行时强转绕过编译期检查，丧失了泛型的类型安全优势。<strong>修法 →</strong> 加 `where T : IComparable<T>` 约束，让编译器在编译期保证 T 有 CompareTo，类型不匹配在编译时就报错。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 加了 `where T : new()` 约束后，值类型也能用，但 `new T()` 比直接 new 慢。<strong>原因 →</strong> 泛型中的 `new T()` 通过反射调用构造器，有额外开销。<strong>修法 →</strong> 性能敏感场景用工厂函数 `Func<T>` 替代 new() 约束，把构造逻辑外部传入，避免反射开销。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 用 `where T : class` 约束后，值类型（如 int）无法用这个泛型方法。<strong>原因 →</strong> class 约束排除了所有值类型。<strong>修法 →</strong> 只有真正需要赋 null 或用 as/is 时才加 class 约束；如果方法对值类型也适用，去掉 class 约束以扩大适用范围。
</Callout>

## 小结与练习

<Exercises>
  <Answer question="为什么不加约束时 T 只能当 object 用？">编译器在编译泛型时不知道 T 的具体类型，只能假设它最弱的能力——object 的能力。object 没有类型特定的方法（如 CompareTo），所以不加约束时无法调用任何类型特定成员。约束的作用就是告诉编译器 T 至少有什么能力，从而解锁对应成员的调用。</Answer>
  <Answer question="五种泛型约束各解锁什么能力？">class 解锁赋 null 和 as/is 操作；struct 解锁无装箱值类型存储（排除 Nullable）；new() 解锁 new T() 构造；接口约束（如 `IComparable<T>`）解锁接口方法调用；基类约束（如 Base）解锁基类成员访问。每种约束都以缩小适用范围为代价换取能力。</Answer>
  <Answer question="为什么约束越多泛型复用性越差？最小约束原则是什么？">每个约束都排除了不满足该约束的类型，约束越多能传入的类型越少，泛型越不通用。最小约束原则：只约束泛型方法真正调用的成员，不加多余的约束。方法体只用到 CompareTo 就只加 `IComparable<T>`，不顺手加 new() 或 class。这样能传入的类型最多，复用性最强。</Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="泛型约束">用 where 子句限制类型参数 T 必须满足的条件（class/struct/new()/接口/基类），使编译器知道 T 的能力，从而在泛型代码中调用特定成员。</GlossaryItem>
  <GlossaryItem term="最小约束原则">Effective C# 原则：只约束泛型方法真正用到的能力，不加多余约束。约束越少能传入的类型越多，泛型复用性越强。</GlossaryItem>
  <GlossaryItem term="new() 约束">要求 T 有无参公共构造函数，解锁 `new T()`。代价是排除了没有无参构造的类型，且 new T() 有反射开销。</GlossaryItem>
  <GlossaryItem term="接口约束">要求 T 实现指定接口（如 `IComparable<T>`），解锁接口方法调用。是最常用的约束，让泛型方法能调用接口定义的成员。</GlossaryItem>
</Glossary>
