## 直觉引入

学完 50 条建议，最后一步不是再背一条，而是把它们串成一条线。Effective C# 的 50 条建议看似分散，实则有一条贯穿的主线：把人为容易犯的错误，交给编译器和运行时来兜底。

属性优先让封装成为默认；readonly 让版本安全成为默认；IDisposable 让资源释放成为默认；泛型约束让类型安全成为默认；LINQ 延迟执行让查询反映最新数据成为默认；异常过滤器让精确 catch 成为默认；Task.WhenAll 让并行成为默认；相等性协调让哈希查找正确成为默认。每一条都是在「让正确的做法成为默认」。

## 概念讲解

<EcsFinalReviewDiagram />

### 四大板块回顾

第一板块「语言习惯」奠定基础：用属性替代字段（封装校验与版本安全）、用 readonly 替代 const（跨程序集版本兼容）、用 is/as 替代强制转换（编译期类型安全）。这是地基——后续所有建议都建立在对语言语义的准确理解上。

第二板块「资源管理」管控资源：IDisposable 标准模式区分确定性释放与终结器兜底，using 让释放成为默认，区分托管与非托管资源。这一板块把资源生命周期的负担交给框架。

第三板块「泛型与 LINQ」提升抽象：泛型约束最小化保持复用性，LINQ 延迟执行让查询反映最新数据但需注意重复枚举。这一板块把集合操作的复杂度交给库。

第四板块「并发设计」收口正确性：异常过滤器精确 catch 不丢栈，Task.WhenAll 并行独立任务，async void 是炸弹，相等性三者协调。这一板块把并发安全交给模式与类型系统。

### 贯穿主线

<Term def="Effective C# 的核心哲学：把人为容易犯的错误交给编译器和运行时兜底，让正确的做法成为默认。">让类型系统兜底</Term> 是全书主线。属性让封装成为默认、readonly 让版本安全成为默认、IDisposable 让释放成为默认、泛型约束让类型安全成为默认、WhenAll 让并行成为默认、相等性协调让哈希正确成为默认。每条建议都是在「让正确成为默认，让错误编译不通过」。

<Callout type="tip">
<strong>建议 →</strong> 把 50 条建议按「它让什么成为默认」来归类记忆。比如「属性让封装成为默认」「readonly 让版本安全成为默认」「using 让释放成为默认」。这样 50 条就不零散，而是一条主线下的统一哲学。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 学完 50 条仍觉得零散，遇到问题想不起用哪条。<strong>原因 →</strong> 把建议当成孤立的规则背诵，没串成主线。<strong>修法 →</strong> 按「让什么成为默认」归类，再用四大板块定位——遇到封装问题翻语言习惯、遇到泄漏翻资源管理、遇到抽象翻泛型 LINQ、遇到并发翻并发设计。
</Callout>

## 代码对照

```csharp
// 语言习惯：属性 + readonly
public class Settings
{
    public string Name { get; set; }              // 属性优先
    public static readonly int Timeout = 5000;    // readonly 优于 const
}

// 资源管理：IDisposable 模式
public class DbConnection : IDisposable
{
    public void Dispose() { Dispose(true); GC.SuppressFinalize(this); }
    protected virtual void Dispose(bool disposing) { /* ... */ }
    ~DbConnection() => Dispose(false);
}
using var db = new DbConnection();                // using 确定性释放

// 泛型与 LINQ：最小约束 + 物化
public T Max<T>(T a, T b) where T : IComparable<T> // 只约束用到的
    => a.CompareTo(b) >= 0 ? a : b;

var results = source.Where(x => x.Active)          // 延迟执行
    .Select(x => x.Name)
    .ToList();                                     // 物化避免重复枚举

// 并发设计：WhenAll + 异常过滤器 + 相等性
await Task.WhenAll(DownloadAsync("a"), DownloadAsync("b"));  // 并行
try { /* ... */ }
catch (IOException e) when (e.HResult == 0x20) { /* 过滤器 */ } // 精确 catch
public override int GetHashCode() => HashCode.Combine(X, Y); // 相等性协调
```

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 学完 50 条仍零散，遇到问题想不起用哪条。<strong>原因 →</strong> 把建议当孤立规则背诵，没串成主线。<strong>修法 →</strong> 按「让什么成为默认」归类，用四大板块定位：封装问题翻语言习惯、泄漏翻资源管理、抽象翻泛型 LINQ、并发翻并发设计。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 照搬建议到所有场景，比如到处用 WhenAll 或到处用 readonly。<strong>原因 →</strong> 每条建议有适用前提，脱离前提的最佳实践变反模式。<strong>修法 →</strong> 理解每条建议解决的问题和代价——WhenAll 适合独立任务、readonly 适合跨程序集常量，按场景取舍而非照搬。
</Callout>

## 小结与练习

<Exercises>
  <Answer question="贯穿 Effective C# 全书的主线是什么？">让类型系统替你兜底——把人为容易犯的错误交给编译器和运行时。每条建议都在「让正确成为默认，让错误编译不通过」：属性让封装成为默认、readonly 让版本安全成为默认、IDisposable 让释放成为默认、泛型约束让类型安全成为默认、WhenAll 让并行成为默认、相等性协调让哈希正确成为默认。</Answer>
  <Answer question="四大板块如何递进？为什么是这个顺序？">语言习惯（封装、类型安全）是地基，资源管理（释放、不泄漏）是安全网，泛型与 LINQ（抽象、查询）是骨架，并发设计（并行、正确性）是收口。递进原因：并发依赖对异常和类型的准确理解（语言习惯），并发资源需正确释放（资源管理），并发集合需泛型抽象（泛型）。跳级会导致知识断层，比如没学异常基础就学 async 会写出 async void。</Answer>
  <Answer question="遇到一个具体问题，如何对应到正确的板块和条款？">先按问题类型定位板块：封装/版本/类型转换问题翻语言习惯；资源泄漏/释放问题翻资源管理；集合操作/查询/泛型问题翻泛型与 LINQ；多线程/异常/相等性问题翻并发设计。再在板块内按「让什么成为默认」找对应条款。比如「字典查不到相等键」属相等性问题→并发设计板块→GetHashCode 一致性条款。</Answer>
</Exercises>
