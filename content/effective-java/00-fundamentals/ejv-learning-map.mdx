## 直觉引入

把 Effective Java 想象成「建造一栋高质量的 Java 大厦」。你要先学会「用什么方式砌砖」（创建对象——静态工厂/Builder/try-with-resources），再确保「砖块之间能正确比对」（通用方法——equals/hashCode/compareTo）；有了正确的砖块需要「设计好房间结构」（类与接口——组合优于继承、最小可访问性），然后确保「不同类型的砖能安全组合」（泛型——PECS/类型安全）；需要固定常量时用「标准化的预制件」（枚举与注解——枚举单例/EnumSet/注解），需要批量操作时用「高效的施工机械」（Lambda与Stream——方法引用/无副作用管道）；每个施工步骤都要「安全规范」（方法设计——参数校验/防御性拷贝/Optional），最后整栋大厦在「多人施工」时要有「安全协议」（并发——同步/线程池/并发集合/安全发布）。

## 四阶段递进

<Term def="Effective Java 的核心理念是清晰、正确、可维护优先于聪明、快速、花哨——关注 API 设计质量、代码健壮性和并发安全性。">核心理念</Term>贯穿全书。全书可以拆成四个递进阶段。**对象创建与方法契约**解决「怎么创建对象」和「怎么比较对象」——静态工厂/Builder/try-with-resources、equals/hashCode/toString/compareTo。**类型系统设计**解决「怎么设计类」和「怎么类型安全」——组合优于继承/最小可访问性/接口优于抽象类、PECS/通配符/消除原生态类型。**语言特性运用**解决「怎么表达常量」和「怎么操作集合」——枚举单例/EnumSet/注解替代命名模式、Lambda/方法引用/Stream管道。**工程实践保障**解决「怎么设计方法签名」和「怎么并发安全」——参数校验/防御性拷贝/Optional、同步/线程池/并发集合/安全发布。

```text
// 「一个 API 设计与实现」——Effective Java 全书知识点全程参与的数据流

// 1. 创建对象（第1章）：选择正确的创建方式
//    public static Player create(String name) {  // 静态工厂
//        return new Player(name);
//    }
//    try (var reader = Files.newBufferedReader(path)) { ... }  // try-with-resources

// 2. 通用方法（第2章）：实现比较和展示契约
//    @Override public boolean equals(Object o) { ... }
//    @Override public int hashCode() { return Objects.hash(name, score); }
//    @Override public String toString() { return "Player{name=" + name + "}"; }

// 3. 类与接口（第3章）：用组合设计
//    public final class Game {  // final: 不可继承
//        private final List<Player> players;  // 组合而非继承
//    }

// 4. 泛型（第4章）：类型安全
//    public static <T extends Comparable<? super T>> T max(List<? extends T> list) { ... }

// 5. 枚举与注解（第5章）：用枚举表达状态
//    public enum Difficulty { EASY, NORMAL, HARD }

// 6. Lambda与Stream（第6章）：声明式操作
//    players.stream().filter(p -> p.getScore() > 100).sorted().collect(toList());

// 7. 方法设计（第7章）：安全签名
//    public void addPlayer(Player p) {
//        players.add(Objects.requireNonNull(p));  // fail-fast
//    }

// 8. 并发（第8章）：线程安全
//    private final ConcurrentHashMap<String, Player> cache = new ConcurrentHashMap<>();
```

## 常见误区

<Callout type="trap">
**误区：会用 Java API 就等于会写 Java。** 能写出 `new ArrayList`、`stream().filter().collect()` 只是「会用 API」——照着文档抄就能做。真正会写 Java 的人能解释：为什么重写 equals 必须重写 hashCode（HashMap 依赖两者配合才能正确查找）、为什么组合优于继承（继承破坏封装性，父类升级会破坏子类）、为什么 PECS 原则让泛型 API 更灵活（生产者 extends、消费者 super）、为什么 try-with-resources 比 try-finally 更安全（异常不会被 close 覆盖）、为什么不可变对象天生线程安全（状态不变不需要同步）。把 Java 当黑盒的人遇到 NullPointerException 只会加 if 判空；懂 Effective Java 的人知道用 Optional 或 fail-fast 校验。区分标志：能否解释「Java 为什么这样设计」而非只是「能编译它」。
</Callout>

<Exercises>
**问题 1**：全书四阶段递进是什么？为什么是这个顺序？

<Answer>
对象创建与方法契约 → 类型系统设计 → 语言特性运用 → 工程实践保障 → 全书复习。顺序由依赖关系决定：先掌握对象怎么创建和比较（创建对象和通用方法是所有代码的基础），再学习类怎么设计和类型怎么安全（类与接口和泛型是类型系统的核心）；然后运用语言特性（枚举注解和Lambda流是在类型系统基础上的高级表达）；最后保障工程实践（方法设计和并发是生产级代码的保障）。先「创建和比较对象」，再「设计类型」，然后「运用特性」，最后「保障工程」。
</Answer>

**问题 2**：用「一个 API 设计与实现」描述全书主线。

<Answer>
一个游戏 API 的设计与实现经过全书多个知识点：①创建对象（第1章）——用静态工厂方法创建 Player，try-with-resources 管理资源；②通用方法（第2章）——Player 重写 equals/hashCode/toString 满足契约，实现 Comparable 排序；③类与接口（第3章）——Game 用组合持有 List&lt;Player&gt;，final 类保证不可继承，最小可访问性降低耦合；④泛型（第4章）——max 方法用 PECS 通配符设计灵活的类型签名；⑤枚举与注解（第5章）——Difficulty 枚举替代 int 常量，@Test 注解标记测试方法；⑥Lambda与Stream（第6章）——用 Stream 管道过滤排序玩家，方法引用简化代码；⑦方法设计（第7章）——addPlayer 方法做参数校验，返回 Optional 表示可能缺失；⑧并发（第8章）——ConcurrentHashMap 线程安全缓存，线程池处理批量请求。一个 API，全书知识点全部参与。
</Answer>
</Exercises>

<GlossaryItem term="核心理念">Effective Java 的核心：清晰、正确、可维护优先于聪明、快速、花哨。关注 API 设计质量、代码健壮性和并发安全性，而非语言语法本身。</GlossaryItem>
<GlossaryItem term="四阶段递进">对象创建与方法契约 → 类型系统设计 → 语言特性运用 → 工程实践保障 → 全书复习。每层解决前一层的遗留问题：创建比较解决「怎么写基础代码」，类型系统解决「怎么设计安全」，语言特性解决「怎么表达高效」，工程保障解决「怎么生产级运行」。</GlossaryItem>
<GlossaryItem term="最佳实践">经过工程验证的、在大多数场景下最优的编程方式。Effective Java 的每条建议都是 Joshua Bloch 多年经验的总结，关注正确性、可维护性和安全性。</GlossaryItem>
<GlossaryItem term="API 设计">Application Programming Interface 的设计——决定类的公开接口（方法签名、参数类型、返回值、异常），直接影响代码的易用性和健壮性。好的 API 设计让错误难以发生。</GlossaryItem>
