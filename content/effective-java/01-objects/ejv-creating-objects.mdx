## 静态工厂 vs 构造器

<Term def="静态工厂方法是返回类实例的静态方法，相比构造器有命名、实例控制、返回子类型等优势。">静态工厂方法</Term>是 Effective Java 的第一条建议。

<EjvCreatingObjectsDiagram />

```java
// 静态工厂方法示例——优势：有名称、可复用实例、可返回子类型
public static Boolean valueOf(boolean b) {
    return b ? Boolean.TRUE : Boolean.FALSE;  // 复用单例，不创建新对象
}

public static List<Integer> of(Integer... elements) {
    // 根据元素数量返回不同的不可变 List 实现
    return List.of(elements);  // Java 9+ 静态工厂
}

// 命名约定：from / of / valueOf / getInstance / newInstance / getType / newType
public static Player from(String name) { return new Player(name); }
```

## Builder 模式

当构造器参数很多时，telescoping（重叠构造器）和 JavaBeans 模式都有问题。Builder 模式是最优解。

```java
// 不好：telescoping 构造器——参数多时无法区分含义
public Pizza(int size) { this(size, false); }
public Pizza(int size, boolean cheese) { this(size, cheese, false); }
public Pizza(int size, boolean cheese, boolean pepperoni) { ... }
// 调用：new Pizza(12, true, false, true)  // 每个 boolean 是什么含义？

// 好：Builder 模式——链式调用，保证不可变
public final class Pizza {
    private final int size;
    private final boolean cheese, pepperoni, mushroom;

    public static class Builder {
        private final int size;
        private boolean cheese = false, pepperoni = false, mushroom = false;

        public Builder(int size) { this.size = size; }
        public Builder cheese()    { cheese = true;    return this; }
        public Builder pepperoni() { pepperoni = true; return this; }
        public Builder mushroom()  { mushroom = true;  return this; }
        public Pizza build() { return new Pizza(this); }
    }
    private Pizza(Builder b) {
        size = b.size; cheese = b.cheese;
        pepperoni = b.pepperoni; mushroom = b.mushroom;
    }
}
// 调用：new Pizza.Builder(12).cheese().pepperoni().build();
```

## try-with-resources

```java
// 不好：try-finally——关闭异常会覆盖业务异常
static String firstLineOfFile(String path) throws IOException {
    BufferedReader br = new BufferedReader(new FileReader(path));
    try {
        return br.readLine();
    } finally {
        br.close();  // 如果 close 也抛异常，readLine 的异常被覆盖
    }
}

// 好：try-with-resources——自动关闭，异常不丢失
static String firstLineOfFile(String path) throws IOException {
    try (BufferedReader br = new BufferedReader(new FileReader(path))) {
        return br.readLine();  // br 自动关闭，close 的异常被 suppressed
    }
}

// 多资源——按声明逆序关闭
static void copy(String src, String dst) throws IOException {
    try (InputStream in = new FileInputStream(src);
         OutputStream out = new FileOutputStream(dst)) {
        byte[] buf = new byte[1024];
        int n;
        while ((n = in.read(buf)) >= 0) out.write(buf, 0, n);
    }
}
```

## 内存管理

<Callout type="trap">
**误区：Java 有 GC 就不需要关心内存。** 两个问题：①创建不必要的对象增加 GC 压力——`new String("hello")` 每次创建新对象，应该用 `"hello"` 复用常量池；`Long sum = 0L` 在循环中自动装箱创建大量临时对象，应该用 `long sum = 0L`。②过期引用导致内存泄漏——Stack 的 pop 方法如果不把数组元素置 null，弹出的对象无法被 GC 回收。GC 不是万能的，开发者仍有责任管理对象生命周期。
</Callout>

```java
// 避免创建不必要的对象
String s = "hello";                    // 好：复用字符串常量池
String s2 = new String("hello");       // 不好：每次创建新对象

long sum = 0L;                         // 好：基本类型
Long sum2 = 0L;                        // 不好：自动装箱，每次 += 创建新 Long

// 清除过期引用
public Object pop() {
    if (size == 0) throw new EmptyStackException();
    Object result = elements[--size];
    elements[size] = null;             // 清除过期引用，防止内存泄漏
    return result;
}
```

<Exercises>
**问题 1**：静态工厂方法相比构造器有哪些优势？

<Answer>
五大优势：①有名称——可描述返回对象特征，比构造器更易读；②不必每次创建新对象——可返回预先构造的实例（如 Boolean.valueOf）；③可返回原返回类型的子类型——API 更简洁；④返回对象可随调用变化——根据参数返回不同子类；⑤返回类在编写时可不存在——服务提供者框架基础。缺点：无 public 构造器的类不能被子类化；静态工厂方法在文档中不如构造器显眼（需用 from/of/valueOf 等命名约定）。
</Answer>

**问题 2**：try-with-resources 相比 try-finally 解决了什么问题？

<Answer>
解决了资源关闭异常覆盖业务异常的问题。try-finally 中，如果 try 块和 finally 的 close() 都抛异常，close 的异常会覆盖 try 块的异常，丢失真正的错误信息。try-with-resources 把 close 的异常作为 suppressed exception 附在 try 块异常上（通过 addSuppressed），保留了原始异常。此外代码更简洁，可同时关闭多个资源（按逆序），且每个资源的异常都不会丢失。凡使用 AutoCloseable 资源都应使用 try-with-resources。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="静态工厂方法">返回类实例的静态方法。优势：有名称、可复用实例、可返回子类型、返回对象可变化、返回类可延迟存在。命名约定：from/of/valueOf/getInstance/newInstance。</GlossaryItem>
<GlossaryItem term="Builder模式">用 Builder 对象链式设置参数后一次性 build() 创建不可变对象。解决 telescoping 构造器参数多时不可读和 JavaBeans 模式构造不原子的问题。</GlossaryItem>
<GlossaryItem term="try-with-resources">Java 7 语法糖，自动关闭 AutoCloseable 资源。相比 try-finally 更简洁，且正确处理关闭异常（suppressed exception），多资源按逆序关闭。</GlossaryItem>
<GlossaryItem term="过期引用">对象已经不再使用但仍被引用（如 Stack 弹出后未置 null），导致 GC 无法回收的内存泄漏。解决：不再需要的引用显式置 null。</GlossaryItem>
</Glossary>
