## 组合优于继承

<Term def="组合是在类中持有另一个类的实例，相比继承不依赖实现细节，不破坏封装性。">组合</Term>是 Effective Java 最重要的设计原则之一。

<EjvClassesInterfacesDiagram />

```java
// 不好：继承破坏封装——HashSet.addAll 内部调用 add
public class InstrumentedHashSet<E> extends HashSet<E> {
    private int addCount = 0;
    @Override public boolean add(E e) { addCount++; return super.add(e); }
    @Override public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c);  // 父类 addAll 内部调用 add → 计数翻倍！
    }
}

// 好：组合 + 转发——不依赖父类实现细节
public class InstrumentedSet<E> extends ForwardingSet<E> {
    private int addCount = 0;
    @Override public boolean add(E e) { addCount++; return super.add(e); }
    @Override public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c);  // ForwardingSet.addAll 转发给内部 Set
    }
}
public class ForwardingSet<E> implements Set<E> {
    private final Set<E> s;  // 组合：持有 Set 实例
    public ForwardingSet(Set<E> s) { this.s = s; }
    @Override public boolean add(E e) { return s.add(e); }
    @Override public boolean addAll(Collection<? extends E> c) { return s.addAll(c); }
    // ... 转发所有 Set 方法
}
```

## 接口优于抽象类

```java
// 接口 + 骨架实现 = 灵活 + 代码复用
public interface List<E> extends Collection<E> {
    E get(int index);
    E set(int index, E element);
    // ... 抽象方法
}

// 骨架实现：AbstractList 提供大部分默认实现
public abstract class AbstractList<E> implements List<E> {
    public boolean add(E e) { add(size(), e); return true; }
    // ... 默认实现，子类只需覆写少量方法
}

// 具体 ArrayList 继承骨架实现
public class ArrayList<E> extends AbstractList<E> { ... }
```

## 不可变类

```java
// 不可变类设计规则
public final class Complex {          // 1. final 类，不可继承
    private final double re;           // 2. final 字段
    private final double im;           // 3. private 字段

    public Complex(double re, double im) {
        this.re = re;
        this.im = im;
    }
    // 4. 无 setter，无修改方法
    public Complex plus(Complex c) {
        return new Complex(re + c.re, im + c.im);  // 返回新实例
    }
    public double realPart() { return re; }
    public double imaginaryPart() { return im; }
}
```

<Exercises>
**问题 1**：为什么组合优于继承？继承在什么情况下安全？

<Answer>
组合优于继承因为继承破坏封装性——子类依赖父类实现细节（方法调用顺序等），父类升级时子类可能崩溃（如 HashSet.addAll 调用 add 导致计数翻倍）。继承安全的情况：子类和父类在同一包内由同一作者控制；类明确设计为可继承（abstract 类，文档化自用模式）；接口继承（implements）而非实现继承（extends）。跨包继承具体类几乎总是危险的。
</Answer>

**问题 2**：如何设计一个不可变类？不可变类有哪些优势？

<Answer>
设计规则：①不提供修改对象状态的方法；②final 修饰类防止扩展；③所有字段 final；④所有字段 private；⑤对可变组件做防御性拷贝。优势：①天生线程安全不需同步；②可自由共享（单例/常量池）；③适合做 Map key 和 Set 元素；④原子性——要么完全创建要么失败。代价：每个不同值需独立对象，大量运算有性能开销（可用可变配套类如 StringBuilder 解决）。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="组合">在类中持有另一个类的实例（private final Set s），通过转发调用其方法。不依赖实现细节，不破坏封装，可运行时替换。优先于继承。</GlossaryItem>
<GlossaryItem term="最小可访问性">每个类和成员的可访问性尽可能低：private > package-private > protected > public。降低可访问性 = 降低耦合 = 提高封装性 = 更多重构自由。</GlossaryItem>
<GlossaryItem term="骨架实现">接口定义类型 + 抽象类提供默认实现的组合。如 List + AbstractList + ArrayList。命名约定 AbstractInterface。Java 8 default 方法增强了接口的默认实现能力。</GlossaryItem>
<GlossaryItem term="不可变类">状态创建后不可改变的类。规则：final 类、final 字段、private 字段、无 setter、可变组件防御性拷贝。天生线程安全，可自由共享。</GlossaryItem>
</Glossary>
