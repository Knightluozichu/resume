## PECS 原则

<Term def="PECS = Producer Extends, Consumer Super。从集合读取用 ? extends T（生产者），向集合写入用 ? super T（消费者）。">PECS</Term>是泛型通配符的核心原则。

<EjvGenericsDiagram />

```java
// PECS 经典案例：Collections.max
public static <T extends Comparable<? super T>> T max(
        List<? extends T> list,            // 生产者：读取元素
        Comparator<? super T> comp) {      // 消费者：接受元素
    T max = list.get(0);
    for (T t : list) {
        if (comp.compare(t, max) > 0) max = t;
    }
    return max;
}
// 这样 max(List<Integer>, Comparator<Number>) 也能工作
```

## 消除原生态类型

```java
// 不好：原生态类型——运行时才发现错误
List list = new ArrayList();
list.add("hello");
Integer n = (Integer) list.get(0);  // ClassCastException!

// 好：参数化类型——编译期发现错误
List<String> list2 = new ArrayList<>();
list2.add("hello");
// list2.add(42);  // 编译错误！

// 三种 Set 的区别
Set rawSet = new HashSet();         // 原生态类型：不安全，可放任何类型
Set<Object> objSet = new HashSet<>(); // 参数化：可放任何 Object，类型安全
Set<?> wildSet = new HashSet<>();    // 无界通配符：类型安全，但不能 add（null 除外）
```

## 类型擦除

Java 泛型在编译后擦除类型参数——`List&lt;String&gt;` 和 `List&lt;Integer&gt;` 运行时都是 `List`。

```java
// 类型擦除的限制
public class GenericLimitations<T> {
    // new T()           // 非法：不能实例化类型参数
    // new T[10]         // 非法：不能创建泛型数组
    // T.class           // 非法：没有泛型类字面量
    // if (x instanceof T)  // 非法：instanceof 不能用类型参数
    private T field;     // 合法：可以有类型参数字段

    // 绕过限制：传入 Class<T>
    public T newInstance(Class<T> clazz) throws Exception {
        return clazz.getDeclaredConstructor().newInstance();
    }
}
```

<Exercises>
**问题 1**：什么是 PECS 原则？Producer Extends 和 Consumer Super 分别用于什么场景？

<Answer>
PECS = Producer Extends, Consumer Super。如果参数化类型代表生产者（从中读取数据），用 ? extends T；如果代表消费者（向其写入数据），用 ? super T。如 Collections.max(List&lt;? extends T> list, Comparator&lt;? super T> comp)——list 是生产者（读取元素），Comparator 是消费者（接受元素比较）。PECS 让 API 更灵活——max(List&lt;Integer&gt;, Comparator&lt;Number&gt;) 也能工作，同时保证类型安全。
</Answer>

**问题 2**：什么是类型擦除？它对泛型有哪些限制？

<Answer>
类型擦除：Java 泛型编译时进行类型检查，但编译后擦除类型参数——List&lt;String&gt; 和 List&lt;Integer&gt; 运行时都是 List，类型参数不存在于字节码中。这是为兼容 Java 5 前代码。限制：不能 new T()（无法实例化类型参数）、不能 new T[n]（不能创建泛型数组）、不能 instanceof T、不能 T.class、静态方法不能用类的类型参数、泛型类不能继承 Throwable。绕过：传入 Class&lt;T&gt; 对象用反射创建实例。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="PECS">Producer Extends, Consumer Super。从集合读取（生产者）用 ? extends T，向集合写入（消费者）用 ? super T。让泛型 API 更灵活且类型安全。</GlossaryItem>
<GlossaryItem term="原生态类型">不带类型参数的泛型类型（如 List 而非 List&lt;String&gt;）。丢失类型安全，编译器只发警告。新代码不应使用，仅为向后兼容保留。</GlossaryItem>
<GlossaryItem term="类型擦除">Java 泛型编译后擦除类型参数的机制。List&lt;String&gt; 和 List&lt;Integer&gt; 运行时都是 List。为兼容 Java 5 前代码而设计，带来诸多限制。</GlossaryItem>
<GlossaryItem term="无界通配符">Set&lt;?&gt;，表示「类型未知」的安全通配符。类型安全但不能添加元素（null 除外），适合只读场景或不确定元素类型时使用。</GlossaryItem>
</Glossary>
