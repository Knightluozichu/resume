## 枚举单例

<Term def="枚举单例是用 enum 实现的单例模式，JVM 保证线程安全、防序列化和防反射攻击。">枚举单例</Term>是实现单例的最佳方式。

<EjvEnumsAnnotationsDiagram />

```java
// 枚举单例——最佳实现
public enum Singleton {
    INSTANCE;
    public void doWork() { System.out.println("working"); }
}
// 使用：Singleton.INSTANCE.doWork();

// 对比：双重检查锁（复杂且易错）
public class SingletonDC {
    private static volatile SingletonDC instance;
    public static SingletonDC getInstance() {
        if (instance == null) {
            synchronized (SingletonDC.class) {
                if (instance == null) instance = new SingletonDC();
            }
        }
        return instance;
    }
}
```

## 枚举策略模式

```java
// 枚举策略模式——行为与常量绑定，优于 switch
public enum Operation {
    PLUS  { public double apply(double a, double b) { return a + b; } },
    MINUS { public double apply(double a, double b) { return a - b; } },
    TIMES { public double apply(double a, double b) { return a * b; } },
    DIVIDE{ public double apply(double a, double b) { return a / b; } };

    public abstract double apply(double a, double b);
}
// 使用：Operation.PLUS.apply(1, 2) = 3.0
// 优势：新增常量时编译器强制实现 apply，不会遗漏

// 对比：switch 方式——新增常量可能遗漏 case
public static double apply(Operation op, double a, double b) {
    switch (op) {
        case PLUS: return a + b;
        case MINUS: return a - b;
        // 忘记 TIMES → 运行时崩溃
    }
    throw new AssertionError("Unknown op: " + op);
}
```

## EnumSet 和注解

```java
// EnumSet 替代位域
// 不好：位域——无类型安全，不可遍历
public static final int STYLE_BOLD = 1 << 0;
public static final int STYLE_ITALIC = 1 << 1;
int flags = STYLE_BOLD | STYLE_ITALIC;  // int 可以是任何值

// 好：EnumSet——类型安全，可遍历
public enum Style { BOLD, ITALIC, UNDERLINE }
EnumSet<Style> styles = EnumSet.of(Style.BOLD, Style.ITALIC);
for (Style s : styles) { ... }  // 可遍历

// 注解替代命名模式
// 不好：命名模式——拼写错无报错
public void tetSomething() { ... }  // testSomething 拼成 tetSomething → 静默跳过

// 好：注解——编译期检查
@Test
public void something() { ... }  // @Test 拼错编译失败

// @Override 防止覆写拼写错误
@Override
public boolean equels(Object o) { ... }  // equels 不是 equals → 编译报错！
```

<Exercises>
**问题 1**：为什么用枚举实现单例比双重检查锁更好？

<Answer>
枚举单例 `enum Singleton { INSTANCE; }` 优势：①线程安全——JVM 在类加载时保证枚举常量唯一初始化；②防序列化攻击——枚举序列化由 JVM 特殊处理，不会通过反序列化创建新实例；③防反射攻击——枚举 newInstance 会抛 IllegalArgumentException。双重检查锁需要 volatile + synchronized，代码复杂易错，还需额外处理序列化（readResolve）和反射防御（私有构造器抛异常）。
</Answer>

**问题 2**：EnumSet 相比位域有哪些优势？

<Answer>
EnumSet 优势：①类型安全——只能放枚举值，位域的 int 可以是任何值；②可遍历——实现 Iterable 可直接 for-each，位域需要手动位操作；③可读——toString 输出 [BOLD, ITALIC]，位域只输出数字；④高性能——内部用位向量实现（64 个枚举值以内用一个 long），操作都是位运算；⑤无容量限制——位域受 int/long 位数限制。永远不要用位域，用 EnumSet 替代。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="枚举单例">用 enum 实现的单例模式。JVM 保证线程安全、防序列化攻击、防反射攻击。是实现单例的最佳方式，无需 synchronized 或 volatile。</GlossaryItem>
<GlossaryItem term="枚举策略模式">在每个枚举常量中绑定不同行为（通过抽象方法或具体实现）。优势：新增常量时编译器强制实现方法，不会遗漏；行为与数据绑定，优于 switch-case。</GlossaryItem>
<GlossaryItem term="EnumSet">以枚举为元素的 Set 实现，内部用位向量。替代位域（int flags），提供类型安全、可遍历、高性能的集合操作。</GlossaryItem>
<GlossaryItem term="注解">编译期可检查的元数据标记，替代命名模式（如 test 前缀）。@Override 防止覆写拼写错误，@Test 标记测试方法，编译器检查拼写正确性。</GlossaryItem>
</Glossary>
