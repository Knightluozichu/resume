## 八大主题核心要点

```text
// 1. 创建与销毁对象（第1章）——怎么创建更好
//    静态工厂 > 构造器（有名称、可复用、可返回子类型）
//    Builder > telescoping（多参数时链式调用、保证不可变）
//    try-with-resources > try-finally（异常不丢失）
//    避免创建不必要对象 + 清除过期引用

// 2. 通用方法（第2章）——怎么比较正确
//    equals 五契约：自反/对称/传递/一致/非空
//    hashCode 必须与 equals 配合（31 * result + f.hashCode()）
//    compareTo 与 equals 保持一致

// 3. 类与接口（第3章）——怎么设计安全
//    组合 > 继承（不破坏封装）
//    接口 > 抽象类（可多实现、骨架实现）
//    最小可访问性（private > package-private > protected > public）
//    不可变类：final 类 + final 字段 + 无 setter

// 4. 泛型（第4章）——怎么类型安全
//    PECS: Producer extends, Consumer super
//    消除原生态类型（List → List<String>）
//    类型擦除的限制（不能 new T()、不能 T.class）

// 5. 枚举与注解（第5章）——怎么表达常量
//    枚举单例（线程安全、防序列化/反射攻击）
//    枚举策略模式（行为绑定常量，优于 switch）
//    EnumSet 替代位域、注解替代命名模式

// 6. Lambda与Stream（第6章）——怎么操作集合
//    Lambda 替代匿名类、方法引用优于 Lambda
//    Stream 管道：源 + 中间操作 + 终端操作
//    无副作用原则（collect 聚合，forEach 仅展示）

// 7. 方法设计（第7章）——怎么签名安全
//    参数校验 fail-fast（Objects.requireNonNull）
//    防御性拷贝（保护可变参数和返回值）
//    Optional 作为返回值（不用作参数/字段）

// 8. 并发（第8章）——怎么并发安全
//    同步三原则 + volatile 不保证原子性
//    ThreadPoolExecutor 替代 Executors 工厂方法
//    并发集合 > synchronizedXxx
//    安全发布 + 不可变对象天然线程安全
```

<Callout type="trap">
**全书最大的陷阱：会用 Java API 不等于会写 Java。** 能写 `new ArrayList`、`stream().filter().collect()` 只是「会用 API」。Effective Java 教你的是为什么重写 equals 必须重写 hashCode、为什么组合优于继承、为什么 PECS 让泛型更灵活、为什么 try-with-resources 比 try-finally 更安全、为什么不可变对象天生线程安全。核心理念：清晰、正确、可维护优先于聪明、快速、花哨。
</Callout>

<Exercises>
**问题 1**：Effective Java 全书围绕的三大核心主题是什么？它们之间有什么关系？

<Answer>
三大核心主题：①API 设计质量——如何设计清晰、正确、易用的 API（静态工厂、Builder、最小可访问性、参数设计）；②代码健壮性——如何避免常见陷阱和 bug（equals/hashCode 契约、防御性拷贝、参数校验）；③并发安全性——如何在多线程环境下保证正确性（同步、线程池、并发集合、安全发布）。关系：API 设计决定基础结构→代码健壮性确保运行时正确→并发安全性处理多线程。不可变对象（API 设计）天生线程安全（并发安全），三者层层递进。
</Answer>

**问题 2**：「组合优于继承」在全书哪些章节中出现？它解决什么根本问题？

<Answer>
出现在：第3章（类与接口——HashSet 继承计数翻倍）；第2章（equals 对称性——ColorPoint 持有 Point）；第4章（泛型——ForwardingSet 组合实现 InstrumentedSet）；第8章（并发——不可变类组合持有可变状态）。根本问题：继承是「实现耦合」——子类依赖父类实现细节，父类变化破坏子类。组合是「接口耦合」——只依赖公开接口，内部实现可自由变化，且允许运行时替换。
</Answer>

<GlossaryItem term="核心理念">清晰、正确、可维护优先于聪明、快速、花哨。全书 90 条建议都围绕这一理念展开，关注 API 设计质量、代码健壮性和并发安全性。</GlossaryItem>
<GlossaryItem term="三大主题">API 设计质量（怎么设计清晰易用的 API）、代码健壮性（怎么避免常见 bug）、并发安全性（怎么多线程不出错）。三者层层递进：设计→实现→并发。</GlossaryItem>
<GlossaryItem term="组合优于继承">贯穿全书的核心设计原则。继承是实现耦合（依赖父类实现细节），组合是接口耦合（只依赖公开接口）。出现在类与接口、equals、泛型、并发等多个章节。</GlossaryItem>
<GlossaryItem term="知识链条">创建对象→通用方法→类与接口→泛型→枚举注解→Lambda流→方法→并发。每一环解决前一环的遗留问题：创建比较→类型设计→类型安全→常量表达→集合操作→方法签名→并发安全。</GlossaryItem>
