## Lambda vs 匿名类

<Term def="Lambda 表达式是函数式接口（只有一个抽象方法的接口）的简洁实现，用于替代冗长的匿名内部类。">Lambda</Term>是 Java 8 引入的函数式编程特性。

<EjvLambdasStreamsDiagram />

```java
// 匿名类——冗长
Collections.sort(words, new Comparator<String>() {
    public int compare(String s1, String s2) {
        return Integer.compare(s1.length(), s2.length());
    }
});

// Lambda——简洁
words.sort((s1, s2) -> Integer.compare(s1.length(), s2.length()));

// 方法引用——更简洁
words.sort(Comparator.comparingInt(String::length));
```

## 方法引用

```java
// 四种方法引用
// 1. 静态方法引用：Integer::parseInt
Function<String, Integer> parser = Integer::parseInt;

// 2. 特定对象的实例方法引用：System.out::println
words.forEach(System.out::println);

// 3. 特定类型的任意对象实例方法引用：String::length
words.stream().map(String::length);

// 4. 构造器引用：TreeMap::new
Supplier<TreeMap<String, Integer>> factory = TreeMap::new;
```

## Stream 管道

```java
// Stream 管道 = 源 + 中间操作 + 终端操作
List<String> result = words.stream()                    // 源
    .filter(w -> w.length() > 3)                        // 中间操作：过滤
    .map(String::toUpperCase)                           // 中间操作：转换
    .sorted()                                           // 中间操作：排序
    .collect(Collectors.toList());                      // 终端操作：收集

// 无副作用原则——不要在 Stream 中修改状态
// 不好：有副作用
List<String> results = new ArrayList<>();
words.stream().filter(w -> w.length() > 3)
    .forEach(w -> results.add(w.toUpperCase()));  // 有副作用！并行流不安全

// 好：无副作用
List<String> results2 = words.stream()
    .filter(w -> w.length() > 3)
    .map(String::toUpperCase)
    .collect(Collectors.toList());  // collect 负责聚合
```

<Callout type="trap">
**陷阱：在 Stream 中使用 forEach 修改外部状态。** `list.stream().forEach(x -> results.add(x))` 在并行流中会导致竞态条件——results 不是线程安全的。forEach 应该只用于展示结果（如打印），不用于修改状态。用 collect 做聚合，用 reduce 做归约。
</Callout>

<Exercises>
**问题 1**：方法引用有哪四种类型？为什么方法引用优于 Lambda？

<Answer>
四种类型：①静态方法引用（Integer::parseInt）；②特定对象实例方法引用（System.out::println）；③特定类型任意对象实例方法引用（String::length）；④构造器引用（TreeMap::new）。方法引用优于 Lambda 因为更简洁可读——service::execute 比 () -> service.execute() 更短且更清晰。当 Lambda 体只是调用一个已存在的方法时就应用方法引用。但如果方法引用更长或更难读（如需指定泛型参数），就用 Lambda。
</Answer>

**问题 2**：Stream 管道的三部分是什么？中间操作和终端操作有什么区别？

<Answer>
三部分：①源（stream()）；②零或多个中间操作（filter/map/sorted/limit）；③一个终端操作（collect/forEach/count/reduce）。区别：中间操作是惰性的（lazy），终端操作触发前不执行；中间操作返回 Stream 可链式调用，终端操作返回非 Stream 类型；终端操作消费流，流只能消费一次。惰性的好处是 limit(n) 可以让无限流在找到 n 个元素后停止，不需要处理所有元素。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Lambda">函数式接口（只有一个抽象方法的接口）的简洁实现。优势：代码简洁、类型推导。限制：只能用于函数式接口，不能有实例字段，this 指向外部类。</GlossaryItem>
<GlossaryItem term="方法引用">Lambda 的简写形式，当 Lambda 体只是调用一个已存在的方法时使用。四种：静态方法、特定对象实例方法、类型实例方法、构造器引用。</GlossaryItem>
<GlossaryItem term="Stream管道">源 + 中间操作 + 终端操作的流水线。中间操作惰性执行，终端操作触发计算。支持顺序流和并行流。</GlossaryItem>
<GlossaryItem term="无副作用">Stream 操作不应修改可变状态。有副作用的代码在并行流中导致竞态条件，破坏惰性优化。用 collect 聚合，forEach 仅用于展示。</GlossaryItem>
</Glossary>
