## 参数校验

<Term def="fail-fast 原则要求在方法入口处立即校验参数有效性，发现错误立即抛出异常而非让错误传播。">fail-fast</Term>是方法设计的基本原则。

<EjvMethodsDiagram />

```java
// 参数校验——fail-fast
public SortedSet<K> subSet(K from, K to) {
    Objects.requireNonNull(from, "from must not be null");
    Objects.requireNonNull(to, "to must not be null");
    // 及早失败，而不是在深处产生 NPE
    return innerSubSet(from, to);
}

// 公共方法必须校验；私有方法可用 assert
private void helper(String s) {
    assert s != null : "s must not be null";  // 仅在 -ea 模式生效
}
```

## 防御性拷贝

```java
// 防御性拷贝——保护可变内部状态
public final class Period {
    private final Date start;
    private final Date end;

    public Period(Date start, Date end) {
        // 先拷贝再校验——防止 TOCTOU 漏洞
        this.start = new Date(start.getTime());  // 防御性拷贝
        this.end = new Date(end.getTime());
        if (this.start.after(this.end))
            throw new IllegalArgumentException();
    }
    // 返回时也要拷贝
    public Date getStart() { return new Date(start.getTime()); }
    public Date getEnd() { return new Date(end.getTime()); }
}
// 不这样做：调用方 period.getStart().setTime(...) 就修改了内部状态
```

## Optional 与重载

```java
// Optional 作为返回值——表示可能缺失
public static <E extends Comparable<E>> Optional<E> max(List<E> list) {
    if (list.isEmpty()) return Optional.empty();
    E result = list.get(0);
    for (E e : list) if (e.compareTo(result) > 0) result = e;
    return Optional.of(result);
}
// 调用方被强制处理缺失情况
max(list).orElse(defaultMax);

// 慎用重载——静态分派可能导致意外行为
public class CollectionClassifier {
    public static String classify(Set<?> s) { return "Set"; }
    public static String classify(List<?> l) { return "List"; }
    public static String classify(Collection<?> c) { return "Collection"; }

    public static void main(String[] args) {
        Collection<?>[] collections = { new HashSet<>(), new ArrayList<>() };
        for (Collection<?> c : collections)
            System.out.println(classify(c));  // 全部打印 "Collection"！
        // 重载看编译时类型（Collection<?>），不看运行时类型
    }
}
```

<Exercises>
**问题 1**：什么是防御性拷贝？为什么构造器和返回值都需要做？

<Answer>
防御性拷贝是在将可变对象传入或传出类边界时创建拷贝，防止外部修改破坏内部不变量。构造器需要：如果直接保存传入的可变对象引用（如 Date），调用方随后可修改该对象绕过封装。返回值需要：如果返回内部可变对象引用，调用方可修改它破坏不变量。正确做法是构造器和 accessor 都用 new Date(start.getTime()) 创建拷贝。拷贝必须在校验之前做（防止 TOCTOU 漏洞）。
</Answer>

**问题 2**：Optional 的正确和错误用法分别是什么？

<Answer>
正确用法：作为返回值表示可能缺失（Optional&lt;T&gt; max(List&lt;T&gt;)），链式处理（opt.map().orElse()），强制调用方处理缺失。错误用法：作为方法参数（不如直接参数或重载）、作为字段（不可序列化、浪费内存）、作为 Map 值（不如允许 null）、直接 get() 不检查（等于回到 NPE）。Optional 的设计意图是作为返回类型，不是 null 的通用替代品。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="fail-fast">在方法入口处立即校验参数有效性，发现错误立即抛异常。工具：Objects.requireNonNull()、Guava checkArgument()。防止错误传播到深处难以调试。</GlossaryItem>
<GlossaryItem term="防御性拷贝">在类边界对可变对象创建拷贝，防止外部修改破坏不变量。构造器先拷贝再校验（防 TOCTOU），返回值也要拷贝。不可变对象不需要。</GlossaryItem>
<GlossaryItem term="Optional">表示可能缺失的返回值容器。强制调用方处理缺失情况（isPresent/get 或 orElse/orElseGet）。仅用于返回值，不用作参数/字段/Map值。</GlossaryItem>
<GlossaryItem term="重载风险">重载是编译期静态分派，根据参数编译时类型决定调用版本。参数类型相近时（int/long、Object/String）易混淆。建议：类型完全不同时可安全重载，类型相近时避免重载改用不同方法名。</GlossaryItem>
</Glossary>
