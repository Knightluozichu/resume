## 从虚拟函数模板开始理解 auto

```cpp
auto value = expression;
```

概念上，compiler 把 `auto` 当成 template parameter T，把 declaration 的其余修饰当成 ParamType，再应用 Item 1 的规则。

<Term def="从 initializer expression 与 auto declaration pattern 得到变量完整类型的过程。">auto type deduction</Term>

<Term def="把 auto 视作 T、把 declarator 视作 ParamType，从而复用模板推导规则的模型。">template deduction correspondence</Term>

Item 2 的原则是 Understand auto type deduction（理解 auto 类型推导）。除一个 braced initializer 特例外，它与 template deduction 高度一致。

先预测每条 declaration 的 auto 部分和最终变量类型；不要把 `const auto&` 整体误称为“auto 推导出的类型”。

## plain auto 对应 by-value 推导

```cpp
int x = 0;
const int cx = x;
const int& rx = x;

auto a = x;  // int
auto b = cx; // int: top-level const removed
auto c = rx; // int: reference/top-level const removed
```

<Term def="auto 变量没有 reference/pointer 修饰时，像 T by-value parameter 一样推导。">plain-auto by-value rule</Term>

initializer 的 reference 与 top-level cv 被移除，因为变量是独立对象。若 initializer 是 pointer-to-const，pointee const 仍保留。

<Term def="直接约束 initializer 对象本身、在 plain auto 复制后不进入结果的 cv。">auto top-level cv removal</Term>

```cpp
const char* const source = "text";
auto pointer = source; // const char*: pointer mutable, pointee const
```

## declarator 修饰在推导后组成类型

```cpp
const auto constant = x; // const int
auto& ref = cx;           // const int&
const auto& cref = x;     // const int&
auto* ptr = &cx;          // const int*
```

<Term def="const、reference 与 pointer token 在 auto/T 推导结果外层形成最终 declaration type。">auto declarator composition</Term>

`const auto constant` 中 auto 部分是 int，最终变量加 const；`auto& ref` 的 reference 模式保留 cx 的 const。

## auto double ampersand 是 universal reference

```cpp
auto&& u1 = x;   // int&
auto&& u2 = cx;  // const int&
auto&& u3 = 27;  // int&&
```

<Term def="initializer 参与推导的 auto double ampersand declaration，可绑定 lvalue/rvalue 并触发引用折叠。">auto universal reference</Term>

lvalue initializer 使 auto/T 推导为 lvalue reference；rvalue 使 auto 为非引用类型，最终 `&&` 保留。range-for 中 `auto&&` 因此能适配 proxy/reference/value element expressions。

<Term def="auto reference 与 initializer value category 组合后按 reference collapsing 得到的最终引用。">auto value-category preservation</Term>

<Callout type="trap" title="陷阱：auto 总是产生值复制">
  plain auto 才采用 by-value 规则。`auto&`、`const auto&`、`auto&&`
  明确建立引用；它们的 lifetime 与悬空风险必须按 reference 审查。
</Callout>

## 唯一核心差异：braced initializer

在本书 C++11/14 语境中：

```cpp
auto x1 = 27;   // int
auto x2(27);    // int
auto x3 = {27}; // std::initializer_list<int>
auto x4{27};    // C++11/14: std::initializer_list<int>
```

<Term def="变量 auto 遇到 braced initializer 时，优先尝试推导 std initializer list 的特殊规则。">auto braced-initializer rule</Term>

`auto` 被想象成 `std::initializer_list<T>` 的 element T，所有 elements 必须推导为同一类型。

<EmcppAutoBracedInitializerMap />

<Term def="保存同类型只读元素序列、由花括号列表临时 backing array 支持的轻量对象。">initializer_list deduction</Term>

## 混合 element types 不会找公共类型

```cpp
// auto bad = {1, 2.0}; // error: int and double conflict
std::initializer_list<double> ok = {1, 2.0};
```

auto deduction 不计算 common type；它要求每个 element 对 T 给出相同推导。显式写目标 list type 后，普通 conversion 才可把 int 转 double。

<Term def="同一 braced list 的 elements 对 initializer list element T 给出不一致类型。">braced element deduction conflict</Term>

## 与 function template 的关键差异

```cpp
template<class T>
void consume(T value);

auto values = {1, 2, 3}; // deduces initializer_list<int>
// consume({1, 2, 3});   // T cannot be deduced
consume(values);         // now argument has a type
```

<Term def="花括号列表本身没有普通表达式类型，函数模板参数若未明确 initializer_list 模式就无法从中推导 T。">typeless braced initializer</Term>

若模板参数明确写 `std::initializer_list<T>`，compiler 才能从 elements 推导 T。

```cpp
template<class T>
void consumeList(std::initializer_list<T> values);

consumeList({1, 2, 3}); // T=int
```

## auto return 不采用变量 auto 的特例

```cpp
auto makeValues() {
    // return {1, 2, 3}; // error
    return std::initializer_list<int>{1, 2, 3};
}
```

<Term def="function return type 中 auto 通过 function template deduction rules 从 return expression 推导。">auto return deduction</Term>

return braced list 是 typeless，不能套变量 auto 的 initializer_list 特例。示例直接返回 initializer_list 还要警惕 backing array lifetime；工程上更适合返回 `std::array`/`std::vector`。

## generic lambda 参数也采用模板推导

```cpp
auto log = [](auto value) { record(value); };

log(42);
// log({1, 2, 3}); // cannot deduce lambda call operator template parameter

auto list = {1, 2, 3};
log(list);
```

<Term def="含 auto parameter、其 closure call operator 作为 function template 实例化的 lambda。">generic lambda deduction</Term>

参数 auto 不是变量 declaration 的 braced-list规则；它等价于 function template parameter。

  变量 auto 有 initializer_list 特例；auto return 和 generic lambda 参数使用

## C++17 对直接花括号的变化

本书面向 C++11/14，`auto x{27}` 推导 initializer_list。C++17 起，direct-list initialization 的单个 element 推导该 element type，而 `auto x = {27}` 仍推导 initializer_list。

<Term def="不同 language standard 对 direct-list auto 单元素推导规则的版本差异。">auto deduction version boundary</Term>

因此迁移旧示例必须标注 language mode；不要让 compiler 默认版本悄悄改变结论。

## auto 不等于忽略类型

auto 让 compiler 写出准确类型，但 API reviewer 仍要理解 cv/reference、proxy 和 lifetime。推导结果应由 initializer 和 declarator 清楚表达。

<Term def="由 initializer 直接表达具体类型来源，避免手写冗长或不准确类型名称。">initializer-driven type expression</Term>

当 initializer 返回 proxy、ownership wrapper 或 view 时，auto 可能保存短生命周期对象；Item 6 将处理“推导正确但语义不想要”的情况。

## 一套推导检查流程

1. 判断 auto 所在 variable、return 还是 generic lambda context。
2. variable 中把 auto 替换为虚拟 T，并识别 by-value/reference/universal case。
3. 分开记录 auto/T 与最终 declaration type。
4. 若 initializer 是 braces，检查当前 context 是否有 initializer_list 特例。
5. 检查 element types、backing array lifetime 和 language standard version。
6. 用 `std::is_same_v`/compiler diagnostic 验证，不依赖 IDE 简写。

<Term def="按上下文、虚拟 T、花括号特例和版本逐步验证 auto 类型的方法。">auto deduction worksheet</Term>

## 小结

- auto variable deduction 基本对应 template deduction，declarator 修饰与推导 T 组成最终类型
- plain auto 丢弃 reference/top-level cv，auto reference/pointer 保留相应 contract
- auto double ampersand 是 universal reference，按 initializer value category 折叠
- C++11/14 variable auto 对 braced initializer 有 initializer_list 特例
- function auto return 与 generic lambda parameter 使用模板推导，不采用变量花括号特例
- C++17 改变单元素 direct-list auto，结论必须绑定 language mode

<Exercises>
  1. **问题 1：推导 plain、reference 和 auto double ampersand。** initializer 是 const int lvalue。

<Answer question="三种最终类型分别是什么？">
  plain auto 采用 by-value，移除 top-level const，得到 int；auto reference 对应
  T reference，保留 const，得到 const int reference；auto double ampersand 接收
  lvalue，auto/T 推导为 const int lvalue reference，折叠后仍是 const int lvalue
  reference。
</Answer>

2. **问题 2：比较变量、function return 与 generic lambda 的花括号。** 解释失败阶段。

<Answer question="为什么只有变量 auto 能直接得到 initializer list？">
  C++11/14 variable auto 对 braced initializer 有专门 initializer_list
  推导；auto return 和 generic lambda parameter 使用 function template
  deduction，而 braced list 无普通类型，无法为普通 T 推导。可先物化 typed
  list，或把参数明确写为 initializer_list pattern。
</Answer>

3. **问题 3：同一源码在 C++14 与 C++17 中检查 direct-list auto。** 设计门禁。

  <Answer question="怎样防止版本升级静默改变类型？">分别用两个 language modes 编译；对 `auto x{27}` 写 version-conditional is_same assertions，C++14 期望 initializer_list，C++17 期望 int；`auto y = {27}` 两者都期望 initializer_list。公共代码若依赖特定类型应显式声明，避免版本隐式变化。</Answer>
