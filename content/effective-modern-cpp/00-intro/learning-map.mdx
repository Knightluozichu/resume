## 全书地图

当你打开 Effective Modern C++，面对 42 条条款，第一件事不是逐条背诵，而是理解它们背后的组织逻辑。Scott Meyers 把 C++11/14 带来的范式转变整理成一条从「读懂类型」到「写好并发」的递进链——先学会在类型推导无处不在的现代 C++ 里看清类型，再用智能指针把资源交给类型系统，再用移动语义让资源高效转移，最后用 Lambda 与并发 API 安全地写多线程。

<EmcBookMap />

全书分为四大板块。第一板块「类型推导与 auto」（条款 1-6）解决「现代 C++ 里类型怎么被推导」——模板推导、auto、decltype 三套机制，加上「优先用 auto」与「显式类型初始化惯用法」。这是地基：C++11/14 里 auto 和 decltype 遍地都是，看不清推导就写不对代码。

第二板块「<Term def="把资源生命周期绑定到对象生命周期，用智能指针实现确定性释放。">智能指针与资源管理</Term>」（条款 7-22）解决「资源怎么不泄漏、怎么更现代」——从花括号初始化、nullptr、作用域枚举等「迈向现代 C++」的语法迁移，到 unique_ptr、shared_ptr、weak_ptr、make 函数与 Pimpl 惯用法。这一板块把 C++98 的手动 new/delete 升级为确定性的对象管理。

第三板块「移动语义与转发」（条款 23-30）解决「资源怎么高效转移」——std::move、通用引用、引用折叠、std::forward，以及完美转发的失败案例。这一板块让「零拷贝传递」成为可能，是现代 C++ 的性能红利。

第四板块「并发与其他」（条款 31-42）解决「怎么安全写多线程与收尾优化」——Lambda 表达式、thread/atomic/future 并发 API、emplace 优化。

<Callout type="tip">
<strong>建议 →</strong> 每学完一个板块，挑一条条款动手写代码验证。比如学完类型推导，用编译器类型推导查看工具（如 `std::decay`、IDE 悬浮提示）对照 auto 推导结果；学完智能指针，把一个 C++98 的裸指针类改写成 unique_ptr 版本。
</Callout>

## 核心概念

推荐学习路径是一条递进链：先读类型推导与 auto，掌握「读代码」的能力；再读智能指针与资源管理，学会「管资源」；接着读移动语义与转发，掌握「搬资源」；然后读并发与其他，把前几层能力组合到多线程环境。

这条顺序背后的逻辑是——类型推导是读代码的钥匙，资源管理是安全网，移动语义是提速器，并发是综合考场。跳过任何一块都会断层：不懂类型推导就看不懂 auto 满天飞的现代代码，不懂资源管理就写不出线程安全的多线程代码，不懂移动语义就无法把对象高效移入 Lambda 闭包与跨线程任务。

<Callout type="trap">
<strong>现象 →</strong> 跳过移动语义直接学并发，结果跨线程传递大对象时全是深拷贝。<strong>原因 →</strong> 跨线程任务常需把对象移入闭包或 future，不懂 std::move 与 init 捕获就只能拷贝。<strong>修法 →</strong> 按板块顺序学习，先把移动语义吃透，再进入并发，用 init 捕获 `[up = std::move(p)]` 把资源移入闭包。
</Callout>

## 小结与练习

- 全书 42 条条款分四大板块：类型推导、资源管理、移动转发、并发其他
- 推荐路径：推导→资源→移动→并发，顺序由依赖关系决定
- 每个板块的核心：推导=读懂类型，资源=确定性释放，移动=高效转移，并发=安全协作
- Modern 版相比 Effective C++ 聚焦 C++11/14 新特性的范式与陷阱

<Exercises>
  <Answer question="为什么 Scott Meyers 要为 C++11/14 单独写一本 Modern 版本？">Effective C++ 面向 C++98，核心是正确用语言、RAII、类设计。C++11/14 引入了类型推导（auto/decltype）、智能指针、移动语义、Lambda 与并发 API 等全新范式，这些特性有大量新陷阱（推导看不清、循环引用、移动不发生、悬空捕获等），旧准则不够用。Modern 版专门针对这些新特性提供指导，所以独立成书。</Answer>
  <Answer question="全书四大板块各自解决什么问题？为什么是递进而非并列？">类型推导与 auto 解决「读懂类型」，智能指针解决「资源不泄漏」，移动语义解决「资源高效转移」，并发解决「安全多线程」。它们递进：读懂类型是前提，资源管理是安全网，移动是提速，并发是综合。后一块都以前一块为前提，跳级会断层——比如不懂移动就无法高效地把对象移入并发任务的闭包。</Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="类型推导">编译器根据初始化表达式或函数实参自动推断变量或模板参数的类型，C++11/14 中 auto、decltype、模板推导三套机制并存。</GlossaryItem>
  <GlossaryItem term="智能指针与资源管理">用 unique_ptr/shared_ptr/weak_ptr 等智能指针把资源的获取与释放绑定到对象生命周期，利用析构与栈展开保证确定性释放，取代手动 new/delete。</GlossaryItem>
  <GlossaryItem term="移动语义">通过右值引用与移动构造/赋值，把资源的所有权从一个对象「窃取」到另一个对象，避免深拷贝，实现近零开销的资源转移。</GlossaryItem>
  <GlossaryItem term="完美转发">用通用引用 + 引用折叠 + std::forward，把函数实参的值类别（左值/右值）原样传递给内部函数，使转发函数对左右值都正确高效。</GlossaryItem>
</Glossary>
