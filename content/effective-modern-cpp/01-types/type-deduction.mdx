## 为什么需要理解模板推导

C++11/14 里类型推导无处不在——auto、decltype、模板、Lambda。但推导规则并不直观：const 会不会丢？引用会不会保留？花括号初始化推成什么？不理解模板推导，就读不懂现代 C++ 代码里到处出现的 `T&&`、`const T&`。条款 1 是这一切的源头：auto 推导几乎与模板推导同源，先把模板推导吃透，后面就顺理成章。

## 三种 ParamType 情形

条款 1 把模板推导按 `template<typename T> void f(ParamType param)` 中 ParamType 的形式分三种情形。

情形一：ParamType 是引用或指针（非通用引用）。规则是「先忽略实参的引用性，再按模式匹配」。比如实参是 `const int x`，对 `T&` 形参，T 推为 `const int`，param 是 `const int&`——const 被保留进 T，因为不能让 param 修改一个 const 对象。

情形二：ParamType 是<Term def="形如 T&& 且 T 是待推导模板参数的引用，能同时绑定左值与右值。">通用引用</Term>（`T&&`）。此时实参的值类别参与推导：左值实参让 T 推为 `T&`，右值实参让 T 推为 `T`。这背后的机制是引用折叠，条款 28 详述。

情形三：ParamType 按值传递。规则是「忽略实参的引用性，并去掉顶层 const」。因为按值传的是副本，原对象的 const 与引用性对副本无意义。

```cpp
template<typename T> void f(T param);          // 情形三：按值
const int cx = 42;
f(cx);  // T 推为 int（顶层 const 被去掉）
```

## 数组与函数的退化

数组与函数实参在按值传递时会退化为指针：`const char name[]` 退化成 `const char*`，函数 `void g(int)` 退化成 `void(*)(int)`。但按引用传递时不退化，T 推导出真实的数组类型如 `const char[4]`。

这个差别有实用价值：利用按引用传递数组的模板，可以推导出数组大小，从而实现编译期数组大小推断工具：

```cpp
template<typename T, std::size_t N>
constexpr std::size_t arrSize(T (&)[N]) noexcept { return N; }
```

<Callout type="tip">
<strong>建议 →</strong> 想确认某处推导出的类型，用条款 4 的查看技巧：让推导结果导致编译错误，编译器报错信息里会打印类型；或用 IDE 的悬浮提示与 `decltype` 配合 `std::decay` 观察。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 以为 `f(cx)` 中 T 推为 `const int`（按值传递）。<strong>原因 →</strong> 按值传递会去掉顶层 const，副本本身可变。<strong>修法 →</strong> 牢记情形三「去引用 + 去顶层 const」；若要保留 const，把形参改成 `const T&` 或 `const T`。
</Callout>

## 与 auto 的关系

模板推导是 auto 推导的钥匙。auto 推导时，auto 扮演 T，变量类型扮演 ParamType，初始化表达式扮演实参，三种情形一一对应。唯一差别在花括号初始化——auto 会把它推成 `std::initializer_list`，而模板不会。这条岔路留到下一章详述。

## 小结与练习

- 模板推导三情形：引用/指针、通用引用、按值，各自处理 const 与引用的方式不同
- 按值传递去顶层 const 与引用性；引用传递保留 const
- 数组/函数按值退化为指针，按引用保留真实类型
- auto 推导与模板同源，唯一差别是花括号初始化

<Exercises>
  <Answer question="数组实参按值传递与按引用传递时，T 分别推导为什么？">按值传递时数组退化为指针，如 `const char name[]` 推导 T 为 `const char*`；按引用传递时不退化，T 推导为真实的数组类型如 `const char[4]`，param 是 `const char(&)[4]`。利用按引用保留数组类型，可实现编译期推断数组大小的工具函数。</Answer>
  <Answer question="对 `template<typename T> void f(T& param)` 与实参 `const int x`，T 和 param 各是什么？为什么 const 不丢？">T 推导为 `const int`，param 是 `const int&`。因为情形一中实参的引用性被忽略后，要让 `T&` 匹配 `const int` 实参，T 必须是 `const int`，否则 param 就能修改 const 对象，违反 const 正确性。所以引用传递下 const 会被保留进 T。</Answer>
</Exercises>

  <GlossaryItem term="通用引用">形如 `T&&` 且 T 是待推导模板参数的引用，能同时绑定左值与右值，是完美转发的入口，条款 24 详述。</GlossaryItem>
