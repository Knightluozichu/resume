## 从“先读名字还是先解 declarator”开始

Item 9 的原则是 Prefer alias declarations to typedefs（优先使用别名声明而非 typedef）。两者都为既有类型建立同义名称，不创建新类型；真正差异在声明可读性与是否能直接参数化。

<Term def="使用 using Name = Type 形式，为既有类型建立同义名称的现代声明。">
  alias declaration
</Term>

<Term def="使用 typedef Type Name 形式建立类型同义词的传统声明机制。">
  typedef
</Term>

```cpp
typedef std::unique_ptr<
    std::unordered_map<std::string, std::string>
> UPtrMapSS;

using UPtrMapSS = std::unique_ptr<
    std::unordered_map<std::string, std::string>
>;
```

先预测两者的 type identity：完全相同。using 的优势是固定成“新名称 = 目标类型”的阅读方向，尤其在 declarator 复杂时更明显。

## alias 不创建强类型

```cpp
using UserId = std::uint64_t;
using OrderId = std::uint64_t;

UserId user = 7;
OrderId order = user; // allowed: both are uint64_t aliases
```

<Term def="alias 与目标类型具有相同 type identity，不提供领域间的隐式转换隔离。">
  type synonym
</Term>

若需要阻止 UserId 与 OrderId 混用，应使用 wrapper class、enum class 或 strong-type library。alias 只改善 spelling 和维护点。

<Callout type="trap" title="陷阱：不同 using 名称会形成不同 overload">
  alias declaration 和 typedef 都只是 type synonym。两个 alias 指向同一
  underlying type 时，不能据此 定义两个独立 overload，也不能期待 compiler
  阻止它们互相赋值。
</Callout>

## 函数指针展示 using 的阅读优势

传统 typedef 把 alias name 嵌进 pointer declarator 中：

```cpp
typedef void (*Callback)(int, const std::string&);
```

using 保持左侧永远是名称：

```cpp
using Callback = void (*)(int, const std::string&);
```

<Term def="指向具有固定参数与返回类型函数的 pointer type。">
  function pointer alias
</Term>

两者都表示同一个 callback type，但 using 不要求读者先解析 `(*Callback)` 才找到名称。对 pointer-to-member、数组引用和 noexcept function type，这种顺序更稳定。

## const 修饰 alias 要看 alias 代表哪一层

```cpp
using WidgetPtr = Widget*;

const WidgetPtr pointer = nullptr; // Widget* const
```

<Term def="const 修饰 alias name 时作用于 alias 展开后的最外层类型，而非文字上最靠近的 token。">
  alias top-level const
</Term>

`WidgetPtr` 是完整 pointer type，前置 const 修饰 pointer object，不是 pointee。using 提升可读性，但不能替代逐层类型推导。

## alias template 是决定性能力

typedef declaration 本身不能成为 template；传统做法必须把 nested typedef 放进 class template：

```cpp
template<typename T>
struct MyAllocList {
    typedef std::list<T, MyAllocator<T>> type;
};

MyAllocList<Widget>::type widgets;
```

<Term def="把 nested typedef 包在 class template 中，以间接生成一族相关类型的传统模式。">
  typedef metafunction wrapper
</Term>

alias declaration 可以直接参数化：

```cpp
template<typename T>
using MyAllocList = std::list<T, MyAllocator<T>>;

MyAllocList<Widget> widgets;
```

<Term def="可接受 template parameters，并直接展开为目标类型表达式的 using 声明。">
  alias template
</Term>

没有额外 wrapper class，也不需要访问 nested `type`。调用处看到的是最终类型族，而不是“运行一个 metafunction 再取结果”。

## dependent name 为什么需要 typename

在 template definition 中，compiler 无法仅凭 `MyAllocList<T>::type` 的文本知道 `type` 一定是类型。某个 specialization 可能让同名成员成为 value，因此 dependent qualified name 默认不按 type 解析。

<Term def="含有未决 template parameter、必须等到实例化后才能确定含义的名称。">
  dependent name
</Term>

<Term def="告诉 parser 某个依赖限定名称应按类型解释的消歧关键字。">
  dependent type typename
</Term>

```cpp
template<typename T>
class WidgetStore {
private:
    typename MyAllocList<T>::type items;
};
```

这里 `typename` 不是装饰：它向 parser 承诺 nested member 是 type。

## alias template 消除 nested dependent type

直接 alias template 的名字已知是类型模板；实例化结果自然处于 type context：

```cpp
template<typename T>
using MyAllocListT = std::list<T, MyAllocator<T>>;

template<typename T>
class WidgetStore {
private:
    MyAllocListT<T> items;
};
```

<Term def="以 alias template 直接产生目标类型，避免访问 dependent nested type 的展开方式。">
  direct type-family expansion
</Term>

这减少 `typename` 和 `::type` 的机械噪声，也降低忘记 typename 导致 parser error 的概率。

<Callout
  type="trap"
  title="陷阱：using 能让所有 dependent names 都不再需要 typename"
>
  只有改写成直接 alias 后不再访问 nested dependent type 的位置才消失。若代码仍写
  dependent qualified member type，语言的 typename 消歧规则照常适用。
</Callout>

## C++ type traits 从 nested type 走向后缀 t

C++11 type traits 通常用 class template 暴露 nested `type`：

```cpp
typename std::remove_const<T>::type
typename std::remove_reference<T>::type
typename std::add_lvalue_reference<T>::type
```

<Term def="通过 class template 的 nested type 返回类型计算结果的标准元编程接口。">
  type trait metafunction
</Term>

C++14 为常见 traits 提供 `_t` aliases：

```cpp
std::remove_const_t<T>
std::remove_reference_t<T>
std::add_lvalue_reference_t<T>
```

<Term def="以后缀 _t 暴露 trait 结果类型的标准 alias template。">
  trait type alias
</Term>

其概念实现就是把旧接口包成 alias：

```cpp
template<typename T>
using remove_const_t = typename remove_const<T>::type;
```

## alias 让组合式 trait 更接近类型表达式

```cpp
template<typename T>
using Normalized = std::remove_cv_t<std::remove_reference_t<T>>;

static_assert(std::is_same_v<Normalized<const int&>, int>);
```

<Term def="按顺序组合多个 trait alias，将输入类型转换成目标规范形式。">
  type normalization pipeline
</Term>

旧写法需要在每层插入 `typename` 与 `::type`，括号/尖括号层次更难审查。alias 不改变 computation，却把重点从元函数机械结构移回类型变换本身。

## 保留 struct metafunction 的场景

alias template 只能产出 type；class-template metafunction 可以同时提供 values、多个 nested results、partial specialization 与诊断辅助。

<Term def="需要多个结果、value metadata 或特化入口时保留的 class-template 类型计算结构。">
  structured metafunction
</Term>

```cpp
template<typename T>
struct SerializationTraits {
    using wire_type = T;
    static constexpr bool fixed_size = true;
};
```

选择标准不是“using 永远取代 struct”，而是单一类型映射优先 alias；多结果协议使用具名 trait structure。

## 迁移 typedef 的可执行步骤

<Term def="在保持 type identity 与 ABI 不变的前提下，将传统 typedef 逐步改写为 using。">
  alias migration
</Term>

1. 用 static assertion 固定 alias 与旧类型等价。
2. 先迁移 function pointers 和复杂 declarators，提升 review 收益。
3. 把仅用于 nested `type` 的 wrapper 改成 alias template。
4. 更新 call sites，移除不再需要的 `typename` 与 `::type`。
5. 保留确有 values、多结果或 specialization contract 的 trait structs。
6. 重新运行所有 template instantiations，而非只编译未实例化的定义。

```cpp
using NewCallback = void (*)(int, const std::string&);
static_assert(std::is_same_v<Callback, NewCallback>);
```

<Term def="通过 is_same 固定旧 alias、新 alias 与 underlying target 类型完全一致。">
  alias equivalence assertion
</Term>

## API 命名应表达角色而不是缩写结构

`UPtrMapSS` 虽比完整模板短，却把实现缩写暴露给读者。更好的 public alias 往往表达角色：

```cpp
using HeaderTable =
    std::unordered_map<std::string, std::string>;

using OwnedHeaderTable = std::unique_ptr<HeaderTable>;
```

<Term def="以领域职责命名 alias，使调用方依赖语义角色而非容器与指针缩写。">
  role-oriented type alias
</Term>

若底层 map 换成 flat map，调用者更容易保持稳定；alias 成为隔离 spelling coupling 的维护点，而不是制造另一种难懂缩写。

## 小结

- alias declaration 与 typedef 都创建 type synonym，不产生强类型或新 ABI
- using 固定成 Name = Type 的阅读顺序，对 function pointer 和复杂 declarator 更清晰
- const 修饰 alias 时作用于展开后的最外层，仍需逐层分析 pointer/cv
- typedef 不能直接参数化，传统方案要 class-template wrapper、nested type 和调用端 `::type`
- alias template 直接表达参数化类型族，减少 wrapper 与 dependent type typename 噪声
- dependent qualified type 仍需要 typename；只有不再访问 nested dependent type 的代码才能移除
- C++14 `_t` traits 就是标准 alias templates，使类型变换组合更清晰
- 单一类型映射优先 alias，多结果/value/specialization 协议可保留 structured metafunction

  1. **问题 1：改写函数指针 typedef。** 保持 ABI 与 callable signature 不变。

<Answer question="如何改写并证明等价？">
  把嵌入 declarator 的 typedef 改成 using Callback = function pointer
  type，使名称固定在等号左侧。 用 is_same static assertion 比较旧 Callback、新
  alias 与完整目标类型；再编译真实注册与调用路径，证明 参数、返回值和 calling
  convention 没有改变。
</Answer>

2. **问题 2：把 MyAllocList wrapper 改成 alias template。** template class 内原来需要 typename 与 type。

<Answer question="调用处为何能删掉 typename？">
  定义 template using MyAllocListT 直接展开 list with custom allocator；调用处写
  MyAllocListT of T。 alias template 已知产生类型，不再访问 dependent wrapper 的
  nested member，因此不需要 typename 或 type。若仍访问其他 dependent nested
  type，typename 规则不变。
</Answer>

3. **问题 3：设计类型规范化 alias。** 输入 const volatile reference，输出无 cv 的 value type。

  <Answer question="怎样组合并测试？">先用 remove reference trait alias 去掉 reference，再用 remove cv trait alias 去掉底层 cv，封装成 Normalized alias template。用 is_same 覆盖 const int reference、volatile Widget double reference 和 plain type；若需保留数组或函数信息，另列 contract，不盲目 decay。</Answer>
