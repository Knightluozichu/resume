## 从“constexpr 不等于总在编译期执行”开始

Item 15 的原则是 Use constexpr whenever possible（尽可能使用 constexpr）。`constexpr` 对 object 和 function 的含义不同：object 必须具有编译期可用值；function 则获得“在条件满足时可参与 constant evaluation”的能力。

<Term def="声明一个必须由 constant expression 初始化、值可用于编译期语境的对象。">constexpr object</Term>

<Term def="允许在参数与执行路径均满足常量求值规则时于编译期计算，也可在运行期调用的函数。">constexpr function</Term>

```cpp
constexpr int square(int value) noexcept {
    return value * value;
}

constexpr auto compileTime = square(5); // constant evaluation
int input = readValue();
auto runTime = square(input);            // normal runtime call
```

先预测：函数 declaration 相同，调用语境与 arguments 决定求值阶段。

## constexpr object 同时是 const

```cpp
constexpr int maxConnections = 64;
// maxConnections = 128; // error
```

<Term def="constexpr object 隐含的不可修改属性；其值在初始化后固定。">implicit constness</Term>

所有 constexpr objects 都是 const，但并非所有 const objects 都是 compile-time constants：

```cpp
const int runtimeLimit = readLimit(); // const after runtime initialization
constexpr int fixedLimit = 64;        // compile-time value
```

<Term def="运行期初始化后保持不变，却不能用于要求 constant expression 的语境。">runtime const object</Term>

const 回答“对象之后能否修改”；constexpr 还回答“initializer 能否在编译期完成并供语言常量语境使用”。

<Callout type="trap" title="陷阱：const 变量一定可以作为所有编译期参数">
  const 只保证初始化后不可修改。若 initializer 依赖 I/O、clock
  或普通函数，值仍在运行期产生，不能作为 array extent、non-type template
  argument 等 constant expression。
</Callout>

## compile-time context 强制常量求值

某些语言位置必须得到 constant expression：

```cpp
constexpr int conditions = 5;

std::array<int, square(conditions)> results;
enum class BufferSize : int { value = square(8) };
alignas(square(4)) std::byte storage[64];
```

<Term def="语言要求表达式在 translation 阶段求值，否则程序 ill-formed 的位置。">compile-time context</Term>

<Term def="可由 compiler 完整求值且满足语言常量表达式限制的表达式。">constant expression</Term>

如果 `square` 不是 constexpr，或 argument 不是 constant expression，这些 declarations 直接编译失败。

## constexpr function 提供能力而非强制

```cpp
constexpr int power(int base, int exponent) noexcept {
    return exponent == 0
        ? 1
        : base * power(base, exponent - 1);
}
```

<Term def="constexpr function 在常量输入与合规执行路径下可由 compiler 求值的接口能力。">constant-evaluation capability</Term>

`power(3, 5)` 若用于 array size，必须编译期求值；若 base/exponent 来自 runtime input，同一函数生成普通运行代码。constexpr 因而能统一 compile-time/runtime algorithm，避免两套实现漂移。

## compile-time evaluation 也会暴露错误

在常量求值中执行到不允许操作会使表达式不再是 constant expression；若所在语境强制编译期，得到 diagnostic。

```cpp
constexpr int checkedDivide(int lhs, int rhs) {
    return lhs / rhs;
}

// constexpr auto invalid = checkedDivide(10, 0); // compile-time error
```

<Term def="常量求值期间发现非法路径，使错误在编译阶段而非运行阶段暴露。">constant-evaluation diagnostic</Term>

但普通 runtime call 仍需正常 input validation；constexpr 不自动把所有可能输入都穷举验证。

## constexpr function 的参数和返回值需满足 literal 规则

用于常量求值的类型必须能在编译期构造、销毁和表示。C++11/14 语境通常称为 literal type。

<Term def="可拥有 constexpr object、并满足常量求值所需构造与表示条件的类型。">literal type</Term>

```cpp
class Point {
public:
    constexpr Point(double xValue, double yValue) noexcept
        : xValue_(xValue), yValue_(yValue) {}

    constexpr double x() const noexcept { return xValue_; }
    constexpr double y() const noexcept { return yValue_; }

private:
    double xValue_;
    double yValue_;
};
```

<Term def="可在 constant evaluation 中初始化 literal object 的 constructor。">constexpr constructor</Term>

Point 的 members 都由 constant expressions 初始化，constructor 不执行不允许的运行期行为，因此可创建 constexpr Point。

## constexpr member functions 让对象链保持编译期可用

```cpp
constexpr Point midpoint(Point lhs, Point rhs) noexcept {
    return {
        (lhs.x() + rhs.x()) / 2.0,
        (lhs.y() + rhs.y()) / 2.0,
    };
}

constexpr Point origin{0.0, 0.0};
constexpr Point corner{10.0, 20.0};
constexpr auto center = midpoint(origin, corner);
static_assert(center.x() == 5.0);
```

<Term def="从 constexpr constructor、accessors 到算法返回值连续保持 constant evaluation 的调用链。">constexpr object pipeline</Term>

任何一环缺少 constexpr 都会中断 compile-time use，即使实现本身看似简单。

## C++11 对 function body 限制严格

C++11 constexpr non-constructor function 基本要求单一 return expression；循环、可变局部状态和多语句逻辑难以表达，常用 recursion 或 conditional expression。

<Term def="C++11 constexpr function 近似单 return expression 的严格函数体约束。">C++11 constexpr restriction</Term>

```cpp
constexpr int power11(int base, int exponent) noexcept {
    return exponent == 0 ? 1 : base * power11(base, exponent - 1);
}
```

这解释了早期 constexpr 代码偏函数式，而不是 recursion 必然更高效。

## C++14 允许更自然的局部状态和循环

```cpp
constexpr int power14(int base, int exponent) noexcept {
    int result = 1;
    for (int i = 0; i < exponent; ++i) {
        result *= base;
    }
    return result;
}
```

<Term def="C++14 放宽 constexpr body，允许局部变量、循环和多条语句的能力。">relaxed constexpr body</Term>

同一函数在 runtime input 下仍是普通 loop。工程应按最低语言标准编写，不把 C++14 语法放进 C++11 target。

## constexpr 不保证编译器预计算普通调用

```cpp
int exponent = readExponent();
auto value = power14(3, exponent);
```

<Term def="普通 runtime context 中 compiler 可自行 constant-fold，但语言不要求必须在编译期执行。">optional constant folding</Term>

即使 arguments 恰好可知，只要不是强制 compile-time context，是否预计算属于 optimization。需要语言保证时，将结果声明 constexpr 或放进 static_assert/template argument。

<Callout type="trap" title="陷阱：函数写 constexpr 就能保证零运行期开销">
  constexpr 只提供常量求值资格。runtime arguments 会产生 runtime call/inline
  code；普通语境中的预计算也取决于
  optimizer。性能结论必须看调用上下文和生成代码。
</Callout>

## constexpr 是接口承诺

caller 可能把函数结果用于 template argument、array extent 或 static_assert。后续移除 constexpr 会让这些调用点停止编译。

<Term def="公开函数允许 caller 在常量语境使用，因此限制未来实现只能采用 constant-evaluable 操作的契约。">constexpr interface commitment</Term>

和 noexcept 类似，不应因为当前实现简单就随意承诺；但对数学、geometry、unit conversion、bit layout 等自然纯函数，应尽早提供 constexpr 能力。

## 尽可能不等于到处添加

I/O、mutex、dynamic plugin、runtime allocation（取决于语言版本）或 virtual dispatch 往往不适合 C++11/14 constexpr。判断标准：

<Term def="基于语义稳定性、literal types 与常量求值规则决定是否公开 constexpr 的边界。">constexpr applicability boundary</Term>

1. 算法是否对相同输入产生确定结果。
2. 参数/返回类型是否 literal-compatible。
3. 合法路径是否只使用当前语言版本允许的操作。
4. caller 是否从 compile-time context 获益。
5. 未来实现是否能继续维持该承诺。

## constexpr 验收矩阵

<Term def="覆盖强制编译期、运行期调用、边界输入、语言版本和接口回归的测试集合。">constexpr contract matrix</Term>

1. static_assert 验证 representative results。
2. std::array/non-type template argument 证明真正可用于 compile-time context。
3. runtime inputs 调用同一 function 并与 reference implementation 对比。
4. invalid constant path 形成 compile-fail diagnostic。
5. C++11/C++14 target 分别验证允许的 body syntax。
6. constexpr class pipeline 覆盖 constructor、accessor 与 derived algorithm。

先预测“此处必须编译期”还是“允许运行期”，再选择证据；仅观察优化后的汇编不能证明语言层 constant-expression contract。

## 小结

- constexpr object 必须由 constant expression 初始化，并隐含 const；普通 const 可能运行期初始化
- constexpr function 可在编译期或运行期执行，取决于 arguments、执行路径与调用语境
- array extent、template argument、enum value、alignment 等 compile-time contexts 强制常量求值
- literal type、constexpr constructor/member 可形成完整 constexpr object pipeline
- C++11 constexpr body 限制严格；C++14 允许局部变量、循环和多语句
- 普通调用是否 constant-fold 是优化选择，不是 constexpr 的执行保证
- constexpr 是 public interface commitment，移除会破坏 caller 的编译期用法
- 验收必须同时覆盖 static_assert、强制语境与 runtime path

<Exercises>
  1. **问题 1：同一个 power function 接受 constexpr exponent 和 runtime exponent。** 各在哪个阶段执行？

<Answer question="什么决定求值阶段？">
  当 arguments 都是 constant expressions 且结果用于 array extent/static_assert
  等强制语境时，compiler 必须常量求值；runtime exponent
  使调用走运行期。普通语境即使输入常量，是否预计算也只是 optimization。 用 std
  array 与 runtime reference test 分别验证两条路径。
</Answer>

2. **问题 2：const limit 由 readLimit 初始化。** 能否作为 non-type template argument？

<Answer question="const 与 constexpr 的差异是什么？">
  不能。该对象虽然初始化后不可修改，值却来自 runtime function，不是 constant
  expression。若 limit 必须成为 template
  argument，就要让来源本身可常量求值并声明 constexpr；否则重构 API 接受运行期
  size，而不是用 cast 或宏伪装。
</Answer>

3. **问题 3：为 Point 增加 constexpr midpoint。** 同时支持编译期与运行期坐标。

  <Answer question="完整 pipeline 需要哪些条件？">Point 是 literal-compatible type，constructor 与 x/y accessors 声明 constexpr，midpoint 只调用这些合规操作并返回 Point。用 constexpr Points 和 static_assert 验证编译期结果，再用 runtime inputs 对比；若 target 是 C++11，保持单 return expression，C++14 才使用局部变量或循环。</Answer>
</Exercises>
