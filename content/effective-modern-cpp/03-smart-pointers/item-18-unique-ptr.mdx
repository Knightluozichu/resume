## 从“一个资源只有一条销毁责任链”开始

Item 18 的原则是 Use std::unique_ptr for exclusive-ownership resource management（用 unique_ptr 管理独占资源）。当任一时刻只有一个 owner 负责销毁 resource，unique_ptr 让这条责任进入类型系统。

<Term def="move-only smart pointer，在 scope 结束时调用 deleter 销毁其独占管理的 object。">unique_ptr</Term>

<Term def="任一时刻只有一个 owner 负责资源生命周期，ownership 只能显式转移而不能复制。">exclusive ownership</Term>

```cpp
auto widget = std::make_unique<Widget>(arguments);

// auto copy = widget;            // error
auto nextOwner = std::move(widget); // ownership transfer
```

先预测 move 后状态：nextOwner 拥有 Widget，widget 为空但仍可析构/赋值。

## move-only 语义消除双重销毁

copying 若复制 raw pointer，会产生两个“都认为自己负责 delete”的 owners。unique_ptr 删除 copy operations，只允许 move 将 pointer/deleter 状态转给新 owner。

<Term def="从 source unique_ptr 把 pointer 与 deleter state 转移到 destination，并把 source 置空。">ownership transfer</Term>

```cpp
std::unique_ptr<Widget> makeWidget() {
    auto result = std::make_unique<Widget>();
    configure(*result);
    return result;
}
```

返回局部 unique_ptr 通过 move/elision 安全交付，异常或早退时局部 owner 自动清理。

<Term def="resource acquisition 与 object lifetime 绑定，所有控制流出口自动执行释放。">deterministic RAII cleanup</Term>

## 默认成本接近 raw pointer

使用 `std::default_delete` 时，unique_ptr 通常与 raw pointer 大小相同，dereference/get 操作可内联，不需要 reference count 或单独 control block。

<Term def="无状态默认删除策略，普通 object specialization 最终执行 delete。">default deleter</Term>

```cpp
static_assert(sizeof(std::unique_ptr<Widget>) == sizeof(Widget*));
```

该 assertion 是常见实现性质而非标准强制；工程可以在目标 ABI 验证，但不应写可移植逻辑依赖相等。

<Callout type="trap" title="陷阱：unique_ptr 永远只有一个机器字">
  custom deleter 是 unique_ptr 类型与状态的一部分。stateless deleter
  常被压缩掉，stateful functor 或 function pointer
  通常增加对象尺寸；标准只保证语义，不保证固定 layout。
</Callout>

## factory 默认返回 unique_ptr

若 factory 创建 object 且不知道 caller 最终 ownership 模型，unique_ptr 是最小承诺：

```cpp
class Investment {
public:
    virtual ~Investment() = default;
};

template<typename... Arguments>
std::unique_ptr<Investment> makeInvestment(Arguments&&... arguments);
```

<Term def="创建资源并把唯一 ownership 作为返回值交付给 caller 的工厂接口。">factory return</Term>

caller 可直接持有 unique_ptr；若后来确实需要共享，可从 rvalue unique_ptr 构造 shared_ptr。反向从 shared_ptr 恢复 unique ownership 通常不安全。

<Term def="factory 先返回最严格的独占 owner，让 caller 按需要单向升级 ownership 的策略。">ownership-minimal factory</Term>

## polymorphic conversion 保留单一 owner

```cpp
std::unique_ptr<DerivedInvestment> derived =
    std::make_unique<DerivedInvestment>();

std::unique_ptr<Investment> base = std::move(derived);
```

<Term def="把 unique_ptr to Derived 移动转换成 unique_ptr to Base，同时保持唯一 ownership。">polymorphic unique conversion</Term>

Base 必须有 virtual destructor，否则通过 base pointer delete derived object 是未定义行为。conversion 不会自动修复 base destruction contract。

## custom deleter 把释放协议封装进 owner

资源可能来自 C API、pool、file mapping 或需要销毁日志，不应直接 delete：

```cpp
auto investmentDeleter = [](Investment* investment) noexcept {
    logInvestmentClose(investment);
    delete investment;
};

using InvestmentPtr = std::unique_ptr<
    Investment,
    decltype(investmentDeleter)
>;
```

<Term def="存储在 smart pointer 类型中的 callable，在 owner 销毁/reset 时执行资源特定释放。">custom deleter</Term>

deleter 应能安全处理 null（unique_ptr 通常只对 non-null 调用），并且不应抛异常，因为 destructor path 抛出会 terminate。

<Term def="deleter 在析构上下文执行，不允许异常逃逸的释放边界。">nonthrowing deletion boundary</Term>

## deleter 类型影响 unique_ptr 类型

```cpp
struct PoolReturn {
    Pool* pool;

    void operator()(Widget* pointer) const noexcept {
        pool->release(pointer);
    }
};

using PooledWidget = std::unique_ptr<Widget, PoolReturn>;
```

<Term def="deleter 捕获 pointer、allocator 或 policy 数据，使每个 owner 附带额外状态。">stateful deleter</Term>

不同 deleter types 产生不同 unique_ptr types，影响 public function signatures、containers 与 ABI。若 deleter 只是 stateless lambda/functor，empty-base optimization 常避免尺寸增长；function pointer deleter 通常额外占一个 pointer。

## function-pointer deleter 换取统一运行期策略

```cpp
using ErasedWidgetPtr = std::unique_ptr<
    Widget,
    void (*)(Widget*)
>;
```

<Term def="以 function pointer 固定 deleter type，可运行期切换函数，但增加存储与间接调用。">function-pointer deleter</Term>

是否 type erase 取决于边界：内部热路径优先具体 stateless type；稳定 ABI/plugin 边界可能接受 function pointer 成本。

## get、release 与 reset 表达不同责任

```cpp
Widget* observed = owner.get(); // borrow, no ownership transfer

owner.reset(new Widget());      // destroy old, own new
Widget* escaped = owner.release(); // relinquish ownership
```

<Term def="从 unique_ptr 取得 raw pointer 仅用于观察，owner 与 lifetime 不改变。">raw observing access</Term>

<Term def="返回 raw pointer 并让 unique_ptr 放弃销毁责任，caller 必须接管资源。">ownership release escape</Term>

`release()` 是高风险边界，通常应立即交给另一个 owner/C API；裸 pointer 留在 local flow 容易 leak。

<Callout
  type="trap"
  title="陷阱：get 与 release 都返回 raw pointer，因此效果相同"
>
  get 只借出地址，unique_ptr 仍负责销毁；release 取消 ownership，若 caller
  不立刻接管就泄漏。代码审查应 对 release 建立独立规则，不能按普通 getter 处理。
</Callout>

## unique_ptr 到 shared_ptr 是单向升级

```cpp
std::unique_ptr<Widget> exclusive = std::make_unique<Widget>();
std::shared_ptr<Widget> shared = std::move(exclusive);
```

<Term def="从唯一 owner 创建 shared control block 并转移资源，之后生命周期由引用计数管理。">shared-ownership upgrade</Term>

升级后不能可靠判断何时只剩一个 owner 并退回 unique_ptr。factory return unique_ptr 因而保留最大决策空间。

## array specialization 是边界工具

`std::unique_ptr<T[]>` 使用 delete[] 并提供 indexing，但不记录 size，也缺少 vector 的丰富 API。

```cpp
auto buffer = std::make_unique<std::byte[]>(size);
buffer[index] = std::byte{0};
```

<Term def="管理 dynamic array 并在析构时执行 delete[] 的 unique_ptr specialization。">unique array owner</Term>

对普通 sequence 优先 vector/array；只有 ABI buffer、C API 或自定义 memory block 确实需要 dynamic array ownership 时使用该 specialization。

## incomplete type 与 pimpl

unique_ptr 可作为 pimpl member 指向 forward-declared implementation，但 owning class destructor 通常需在 Impl complete 的 source file 中定义。

```cpp
class Widget {
public:
    Widget();
    ~Widget();

private:
    class Impl;
    std::unique_ptr<Impl> impl;
};
```

<Term def="public header 只保存 unique_ptr to incomplete Impl，将定义和销毁放到 source file 的模式。">unique_ptr pimpl</Term>

这减少 compile dependency，同时保留明确唯一 ownership。

## unique ownership 验收矩阵

<Term def="覆盖不可复制、可移动、factory 异常、custom deletion、polymorphism 与 release 的测试集合。">unique ownership contract matrix</Term>

1. static traits 证明 owner 不可 copy、可按设计 move。
2. move 后 source 为空，destination 只销毁一次。
3. factory 在 configure 抛异常时无 leak。
4. custom deleter 被精确调用一次且不抛。
5. Derived-to-Base deletion 调用 virtual destructor。
6. release path 立即转交明确 owner。
7. unique-to-shared upgrade 保留同一 resource 并清空 source。

先画 ownership graph，再选择 pointer type；若图中任一时刻只有一个销毁责任，unique_ptr 是默认答案。

## 小结

- unique_ptr 以 move-only type 表达 exclusive ownership，scope exit 确定性清理
- default deleter 下成本通常接近 raw pointer，但 layout 不是标准固定保证
- factory return unique_ptr 保留调用方继续独占或升级 shared ownership 的选择
- unique_ptr to Derived 可 move 成 unique_ptr to Base，base destructor 必须 virtual
- custom deleter 是 unique_ptr type/state 的一部分，影响 size、ABI 和 noexcept destruction
- get 是 borrow；release 放弃 ownership，必须立即接管
- unique_ptr 可单向升级 shared_ptr，反向恢复独占通常不可行
- array specialization 适合低层 buffer，普通 sequence 优先 container

<Exercises>
  1. **问题 1：设计 Investment polymorphic factory。** caller 可能独占，也可能共享。

<Answer question="为什么 factory 应先返回 unique_ptr？">
  factory 返回 unique pointer to base，并保证 base virtual destructor；内部用
  make unique derived 创建，再 move-convert。caller 可保持零 control-block
  的独占 owner，或以后 move 到 shared pointer。测试 factory exception 无
  leak、derived destructor 被调用和 unique-to-shared source 置空。
</Answer>

2. **问题 2：pool resource 需要归还 Pool。** 设计 custom deleter 并分析尺寸。

<Answer question="deleter 保存什么，如何验收？">
  stateful functor 保存 Pool pointer，call operator noexcept 地 release
  resource；unique_ptr type 包含该 deleter，因此 object 通常比 raw pointer
  大。用 sizeof 仅验证目标 ABI，用 counter 验证 move 后 deleter state 跟随
  owner且只释放一次，并注入异常确认 deleter 不传播。
</Answer>

3. **问题 3：代码调用 release 后把 raw pointer 存进全局列表。** 修复 ownership hole。

  <Answer question="get、release 或 owner transfer 该选哪个？">只观察时使用 get，并保证 borrow 不越过 owner lifetime；转交所有权时让接收 API 直接接受 unique_ptr，调用处 move owner；只有必须调用接管 raw pointer 的 C API 才 release，并在同一 expression/紧邻语句完成交付。用 leak sanitizer 和失败路径测试证明无 ownership gap。</Answer>
</Exercises>
