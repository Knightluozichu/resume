## 全书一图收束

学完全书 42 条条款，最后一步是把它们串成一条能力链。Effective Modern C++ 不是 42 条孤立建议，而是一条从「读懂类型」到「写好并发」的递进路径——每一层都以前一层为基础，跳级会断层。这一章用思维导图收束四大板块，并做跨章节串联。

## 四大板块的核心目标

第一板块「类型推导与 auto」（条款 1-6）：让推导为所用，但看得清类型、避开代理类型陷阱。核心是三套推导机制（模板/auto/decltype）加上「优先用 auto」与「显式类型初始化惯用法」。

第二板块「智能指针与资源管理」（条款 7-22）：用对象和智能指针把资源生命周期交给类型系统，确定性释放。核心是 unique/shared/weak 三种指针 + make 函数 + Pimpl。

第三板块「移动语义与转发」（条款 23-30）：用右值引用与完美转发让资源高效转移而非拷贝。核心是 std::move、通用引用、引用折叠、std::forward。

第四板块「并发与其他」（条款 31-42）：用 Lambda 与并发 API 安全地写多线程与收尾优化。核心是 Lambda 捕获、task/atomic/future、emplace。

## 跨章节串联：一条能力链

四个板块构成「读类型 → 管资源 → 搬资源 → 并发协作」的递进。读懂类型是读代码的前提；资源管理是安全网；移动是提速器；并发是综合考场。后一块都以前一块为基础：不懂类型推导就看不懂 auto 满天飞的现代代码；不懂资源管理就写不出线程安全的多线程代码；不懂移动语义就无法把对象高效移入 Lambda 闭包与跨线程任务。

## auto 三件套配合

auto（条款 5）、decltype(auto)（条款 3）、显式类型初始化（条款 6）三者按场景分层选用：默认用 auto 减冗余防截断；需要透传引用性（如转发返回类型）升级 decltype(auto)；遇到代理类型陷阱加 `static_cast<TargetType>` 强制推导目标类型。三者不是对立，而是同一思路（让推导为所用）的不同工具。

## move 与 forward 的分工

条款 25 口诀：右值引用用 std::move，通用引用用 std::forward。std::move 是无条件右值 cast（确定右值），std::forward 是有条件右值 cast（保持通用引用的值类别）。混用会出 bug——在通用引用上用 move 会把左值也强行移动，导致悬空。唯一例外：`return std::move(local)` 往往有害（阻止 RVO），应直接 `return local`。

## 小结与练习

- 四大板块一条链：读类型 → 管资源 → 搬资源 → 并发协作，后一块依赖前一块
- auto 三件套按场景配合：默认 auto，透传引用用 decltype(auto)，代理类型加显式 cast
- move 用于右值引用（无条件），forward 用于通用引用（有条件），不可混用
- 迁移最高优先级：智能指针、auto、移动+noexcept、task 优先+thread unjoinable、atomic 管并发
