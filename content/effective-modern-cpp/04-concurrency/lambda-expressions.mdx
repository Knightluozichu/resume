## 为什么需要 Lambda

C++11 之前，要把「一段逻辑」传给算法或异步任务，只能写一个具名函数或函数对象，再传函数指针——逻辑与调用点分离，可读性差。Lambda 让你「在调用处就地写一段可执行逻辑」，编译器生成一个闭包类型，闭包是它的实例。Lambda 是现代 C++ 写并发、回调、算法组合的基础工具。

## Lambda 的结构

Lambda 由五部分组成：捕获列表、参数列表、mutable、尾随返回类型、函数体。捕获列表决定如何「捕获」所在作用域的变量（值捕获拷贝一份，引用捕获持引用）；参数列表传给 Lambda；mutable 允许修改值捕获的副本；尾随返回类型可省略由 return 推导；函数体是实际逻辑。

Lambda 本质是编译器生成一个含 `operator()` 的类（闭包类型），闭包是它的实例。捕获的变量成为闭包的成员。

## 避免默认捕获（条款 31）

条款 31 建议避免默认捕获模式（`[=]` 和 `[&]`），因为隐式捕获让人忽视到底捕获了什么。

默认引用捕获 `[&]` 的主要风险是<Term def="Lambda 捕获的引用所指向的对象已析构，访问即未定义行为。">悬空引用</Term>：Lambda 捕获局部变量的引用，但 Lambda 寿命可能超过该变量。异步回调、容器存储的闭包、std::thread 任务都是高危场景——回调执行时局部变量早已析构。

默认值捕获 `[=]` 给人「安全」的错觉，但它不捕获 this 指向的对象本身（只捕获 this 指针值），成员变量通过 this 间接访问，对象析构后 this 悬空。

建议：显式列出捕获变量（如 `[&x]` 而非 `[&]`），让悬空风险一眼可见；能不捕获就不捕获，用参数传入更安全。

## init 捕获与移动捕获（条款 32）

条款 32 的 init 捕获（C++14）在捕获列表里给捕获变量指定初始化表达式，如 `[name = expr]`。它解决普通捕获做不到的两件事：移动捕获（`[up = std::move(p)]` 把只移动类型移入闭包）和给捕获成员重命名或用表达式初始化。

```cpp
auto p = std::make_unique<Widget>();
auto func = [up = std::move(p)] { up->doSomething(); };
```

C++11 无 init 捕获，要移动捕获需手写 functor 或用 std::bind 绕路；C++14 一行搞定，是异步任务把资源移入闭包的标准手段。

## 泛型 Lambda 与优先 Lambda（条款 33-34）

条款 33：泛型 Lambda 用 `auto&&` 参数 + `std::forward` 转发，C++14 起支持。条款 34：优先用 Lambda 而非 std::bind——Lambda 可读性好、报错清晰、重载决议自然、易内联，std::bind 的占位符晦涩、重载函数难传、表达力受限。C++14 引入 init 捕获后，std::bind 的最后优势也消失，新代码应一律用 Lambda。

<Callout type="tip">
<strong>建议 →</strong> 显式捕获而非默认捕获；要把对象移入闭包用 init 捕获 `[up = std::move(p)]`；新代码一律用 Lambda 取代 std::bind。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 异步回调里用 `[&]` 捕获局部变量，回调执行时读到垃圾值。<strong>原因 →</strong> 局部变量已析构，引用悬空。<strong>修法 →</strong> 改用值捕获或 init 移动捕获把所需数据复制/移入闭包，让闭包自持数据，不依赖外部生命周期。
</Callout>

## 小结与练习

- Lambda 五部分：捕获、参数、mutable、尾随返回、函数体；本质是编译器生成的闭包类型
- 默认捕获 `[=]`/`[&]` 有悬空风险，优先显式捕获
- init 捕获（C++14）解决移动捕获与表达式初始化，是异步任务移入资源的标准手段
- 优先 Lambda 而非 std::bind：可读、报错清晰、重载自然、易内联

  <GlossaryItem term="闭包">Lambda 表达式生成的类（闭包类型）的实例，含 operator()，捕获的变量成为其成员。</GlossaryItem>
  <GlossaryItem term="捕获">Lambda 在捕获列表中决定如何使用所在作用域的变量，值捕获拷贝一份，引用捕获持引用。</GlossaryItem>
  <GlossaryItem term="悬空引用">Lambda 捕获的引用所指向的对象已析构，访问即未定义行为，默认引用捕获的高频风险。</GlossaryItem>
