## 从“工具只转换表达式，资源由目标函数决定”开始

Item 23 的原则是 Understand std::move and std::forward（理解 std::move 与 std::forward）。两者本质都不搬运 bytes、不清空 source、不调用 allocator；它们产生带特定 value category 的表达式，后续 overload 才决定行为。

<Term def="把 expression 无条件转换成对应类型的 rvalue/xvalue expression 的标准工具。">std move</Term>

<Term def="根据显式 template argument 有条件恢复 original argument value category 的标准工具。">std forward</Term>

```cpp
std::string source = "payload";
std::string target = std::move(source);
```

先预测：`std::move(source)` 只让 move constructor 成为最佳候选；真正转移 string buffer 的是 target constructor。

## std::move 是无条件 cast

概念实现：

```cpp
template<typename T>
std::remove_reference_t<T>&& move(T&& parameter) noexcept {
    using ReturnType = std::remove_reference_t<T>&&;
    return static_cast<ReturnType>(parameter);
}
```

<Term def="std::move 不执行资源操作，只产生 xvalue 供 overload resolution 使用。">cast not move</Term>

remove_reference 保证返回类型是 rvalue reference；函数名 `move` 描述调用者意图，而不是函数内部执行。

## overload 决定 copy 还是 move

```cpp
class Buffer {
public:
    Buffer(const Buffer&); // copy
    Buffer(Buffer&&);      // move
};

Buffer first;
Buffer second(std::move(first));
```

<Term def="rvalue expression 进入 candidate set 后，由参数 cv/reference 匹配选出 copy 或 move overload。">move-overload selection</Term>

若 Buffer 没有 move constructor，const-reference copy 仍可绑定 rvalue，代码会 copy；若 move deleted，selected deleted candidate 会报错。看到 std::move 不能证明发生移动。

<Callout type="trap" title="陷阱：代码出现 std::move 就一定比 copy 快">
  target type 可能没有 move、move 可能退化成逐成员 copy、source 可能 const，或
  compiler 原本可做 elision。 必须检查 selected overload、生成的 special members
  和实际成本。
</Callout>

## named rvalue-reference parameter 是 lvalue expression

```cpp
void consume(Widget&& widget) {
    process(widget);            // widget expression is lvalue
    process(std::move(widget)); // explicit xvalue
}
```

<Term def="变量拥有名称后，其使用表达式具有 identity，因此无论 declared reference type 如何都为 lvalue。">named-reference lvalue rule</Term>

`Widget&&` 说明 parameter 能绑定 rvalue；进入 function body 后名字 `widget` 可反复使用，是 lvalue。要把资源交给下游，必须明确 std::move，并承认此后仅可依赖 moved-from contract。

## move 的正确时机是最后一次资源使用

<Term def="在 source 当前值不再需要、后续只析构或重新赋值的点显式转移资源。">last-use move point</Term>

```cpp
void submit(Widget widget) {
    validate(widget);
    queue.push_back(std::move(widget)); // last use of current value
}
```

过早 move 后再读取 source 容易产生逻辑 bug；过晚 move 则多一次 copy。review 应标出 source value 的最后使用边界。

## moved-from object 有效但状态通常未指定

标准库 moved-from objects 一般保证 valid but unspecified，可析构、赋值，并可调用没有额外前置条件的 operations。

<Term def="move 后对象 invariants 仍成立，但除特别说明外具体 value 不由 contract 保证。">valid but unspecified state</Term>

不要测试 `source.empty()` 作为通用 move 证明；某实现可留下原值。测试应验证 destination 资源正确、source 可安全析构/赋新值。

## const rvalue 常常不能移动

```cpp
class Annotation {
public:
    explicit Annotation(const std::string text)
        : value(std::move(text)) {}

private:
    std::string value;
};
```

<Term def="具有 rvalue value category 但类型仍带 const，不能绑定到普通 non-const rvalue-reference move parameter。">const rvalue</Term>

`text` 是 const object；std::move 得到 const string rvalue。string move constructor 接受 non-const string rvalue reference，不能移除 const；copy constructor 接受 const string reference，因此被选择。

<EmcppConstRvalueOverloadMap />

<Term def="std::move 保留 cv qualifiers，const source 转换后仍是 const rvalue。">cv-preserving move cast</Term>

修复通常是按值接收非 const parameter：

```cpp
explicit Annotation(std::string text)
    : value(std::move(text)) {}
```

caller lvalue 复制进 parameter，rvalue 可 move/elide 进入 parameter，随后统一 move 到 member。

<Callout
  type="trap"
  title="陷阱：std::move 会去掉 const，因为 move 需要修改 source"
>
  std::move 只移除 reference 并添加 rvalue-reference category，不移除
  const。强行 cast away const 并修改 真正 const object 会产生未定义行为；应修正
  API 参数类型。
</Callout>

## std::forward 是 conditional cast

forwarding wrapper 要保留 caller 传入的是 lvalue 还是 rvalue：

```cpp
template<typename T>
void relay(T&& argument) {
    consume(std::forward<T>(argument));
}
```

<Term def="当 T 推导为 lvalue reference 时返回 lvalue；推导为 non-reference 时返回 rvalue 的转换。">conditional cast</Term>

named argument 自身是 lvalue，`std::forward<T>` 使用 deduced T 恢复入口 value category。

<EmcppForwardConditionalMap />

## reference collapsing 保存 lvalue 信息

lvalue 传给 forwarding reference 时，T 推导为 lvalue reference；type formation 中 reference collapsing 让 parameter 仍为 lvalue reference。rvalue 传入时 T 为 non-reference，parameter 为 rvalue reference。

<Term def="引用组合按规则折叠，使任何含 lvalue reference 的组合结果为 lvalue reference。">reference collapsing</Term>

```cpp
Widget widget;
relay(widget);        // T = Widget&, forward yields lvalue
relay(Widget{});      // T = Widget, forward yields rvalue
```

Item 24 将完整区分 forwarding/universal references 与 ordinary rvalue references。

## std::forward 只用于 forwarding references

<Term def="type 由当前 call 推导、形如 T double ampersand 的 parameter，可绑定 lvalue 与 rvalue。">forwarding reference parameter</Term>

普通 `Widget&&` 不需要条件恢复，它只接受 rvalue，最后使用时 std::move 更清楚。对非 forwarding parameter 使用 forward 会让 intent 和 template argument 来源不透明。

## move 与 forward 的语义对照

- std::move：caller 无条件声明“可把此 expression 当 rvalue”。
- std::forward：wrapper 有条件声明“保持 original caller category”。
- 两者都只是 cast；target operation 决定资源行为。

<Term def="根据函数是在消费本地 value 还是透明传递 caller category 选择 move/forward。">value-category intent boundary</Term>

consumer/sink 用 move；generic relay/factory 用 forward。

## 不要在 return local 时机械 std::move

```cpp
Widget makeWidget() {
    Widget result;
    return result; // allows NRVO and implicit move fallback
}
```

<Term def="compiler 直接在 caller storage 构造 local return object，省略 copy/move。">named return value optimization</Term>

写 `return std::move(result)` 可能使 expression 不再满足 NRVO 条件，反而强制一次 move。Item 25 将系统讨论 RVO 与 forwarding failure。

## move/forward 验收矩阵

<Term def="覆盖 lvalue/rvalue/const inputs、selected overload、moved-from state 与 forwarding preservation 的测试集合。">move-forward contract matrix</Term>

1. overload probes 记录 lvalue、rvalue、const rvalue 选择。
2. copy/move counters 证明 std::move 后真实 operation。
3. forwarding wrapper 对 lvalue 不 move，对 rvalue 选择 move。
4. source move 后只执行 documented valid operations。
5. const parameter 路径不假装 move。
6. return local 保留 NRVO opportunity。

先预测 expression value category 与 cv，再看 candidate signatures；函数名和 `&&` token 都不能单独证明行为。

## 小结

- std::move 是无条件 rvalue cast，不执行资源移动；selected constructor/assignment 才移动或复制
- named rvalue-reference parameter 在函数体中是 lvalue expression，需要最后使用点显式 move
- moved-from object 通常 valid but unspecified，只保证可析构与满足前置条件的操作
- std::move 保留 const；const rvalue 不能绑定普通 move constructor，常静默选择 copy
- std::forward 根据 deduced T 条件恢复 caller 的 lvalue/rvalue category
- reference collapsing 让 forwarding reference 保存 lvalue 信息
- move 用于消费已不再需要的 value，forward 用于透明转发 parameter
- return local 机械 move 可能阻止 NRVO

<Exercises>
  1. **问题 1：代码调用 std::move 但 copy counter 增加。** 列出可能原因。

<Answer question="如何从证据定位？">
  检查 source 是否 const、target 是否真正声明 move、user destructor 是否抑制
  implicit move、move signature 是否 deleted/inaccessible，以及 operation
  是否本质逐成员 copy。打印/静态检查 selected signatures，用 counters 覆盖
  non-const/const rvalues；std::move token 本身不是移动证据。
</Answer>

2. **问题 2：relay 接收 T forwarding reference。** 为什么不能直接 consume(argument)？

<Answer question="lvalue/rvalue caller 各会发生什么？">
  named argument 在 body 中总是 lvalue，直接传会让 rvalue caller 也走 lvalue
  overload。使用 forward with deduced T：lvalue caller 使 T 为 lvalue
  reference并恢复 lvalue，rvalue caller 使 T 为 value type并恢复
  rvalue。overload probes 验证两条路径。
</Answer>

3. **问题 3：constructor 接受 const string by value 并 std::move 到 member。** 修复静默 copy。

  <Answer question="为什么 const 阻止 move，API 应怎样改？">move cast 保留 const，结果是 const string rvalue，不能绑定需要可修改 source 的 non-const move constructor，只能绑定 copy const-reference。把 by-value parameter 改成非 const string，验证 lvalue caller 一次 copy 后 move、rvalue caller move/elide 后再 move，并删除依赖 parameter const 的假安全。</Answer>
</Exercises>
