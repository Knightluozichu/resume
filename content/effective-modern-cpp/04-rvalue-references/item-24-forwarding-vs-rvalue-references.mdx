<Objectives>

- 能区分 universal references（通用引用/forwarding references）与 rvalue references（右值引用），判断 `&&` 的真实类别
- 能推导 lvalue/rvalue/const arguments 下的 T，并应用 reference collapsing 得到 parameter type
- 能分析 auto double ampersand（auto&&）、generic lambda 与 container members 中是否发生 type deduction（类型推导）

</Objectives>

## 从“两个 && 的含义由推导上下文决定”开始

Item 24 的原则是 Distinguish universal references from rvalue references（区分通用引用与右值引用）。源码中的 `&&` 只有在“被推导类型的精确形式”下才是 forwarding reference；否则就是 ordinary rvalue reference。

<Term def="形如 T double ampersand 且 T 在当前调用中被推导，可绑定 lvalue/rvalue 并保存 caller 值类别的引用。">forwarding reference</Term>

<Term def="只绑定可转换 rvalue/xvalue 的引用类型，不因 caller lvalue 推导而折叠。">rvalue reference</Term>

原书使用 universal reference 名称；现代标准术语是 forwarding reference。两者在本条指同一语言模式。

```cpp
template<typename T>
void relay(T&& value); // forwarding reference

void consume(Widget&& value); // rvalue reference
```

先预测：relay 可接 lvalue/rvalue；consume 不能直接接 Widget lvalue。

## forwarding reference 有两个同时成立的条件

1. parameter 形式是对被推导类型的精确 `T&&`。
2. T 的 type deduction 发生在这次调用中。

<Term def="当前函数调用根据 argument type/value category 求出模板参数或 auto type 的过程。">type deduction</Term>

```cpp
template<typename T>
void inspect(T&& value);
```

任何 cv 或其他 type wrapper 都会改变分类：

```cpp
template<typename T>
void inspect(const T&& value); // ordinary rvalue reference

template<typename T>
void inspect(std::vector<T>&& value); // rvalue reference to vector
```

<Term def="只有未加 const、未包裹在其他 type constructor 中的被推导 T double ampersand 才满足形式要求。">exact forwarding-reference form</Term>

<Callout type="trap" title="陷阱：任何 function template 中的双 ampersand 都是 forwarding reference">
  template context 不够。`const T&&`、`vector<T>&&` 都不是精确的 deduced T&& 形式，只能绑定 rvalue；
  必须同时检查 deduction target 与 parameter pattern。
</Callout>

## lvalue argument 让 T 推导成 reference

```cpp
Widget widget;
relay(widget);
```

<Term def="forwarding-reference deduction 的特殊规则：lvalue argument 使 T 本身推导为 lvalue reference。">lvalue-reference deduction</Term>

这里 T 是 `Widget&`；parameter 的概念形式成为 Widget lvalue-reference + rvalue-reference，再经 collapsing 得到 Widget lvalue reference。

## reference collapsing 决定最终类型

规则可记为：只要组合中有 lvalue reference，结果就是 lvalue reference；只有 rvalue-reference 与 rvalue-reference 才仍为 rvalue reference。

<Term def="reference-to-reference 在模板实例化/alias/auto 中按规定合并为单一 reference type。">reference collapsing</Term>

- lvalue reference + lvalue reference → lvalue reference
- lvalue reference + rvalue reference → lvalue reference
- rvalue reference + lvalue reference → lvalue reference
- rvalue reference + rvalue reference → rvalue reference

<EmcppForwardingDeductionCollapseMap />

这不是源码可直接声明的 reference-to-reference，而是 type substitution 中间形态的语言归一化。

## rvalue argument 让 T 推导成 value type

```cpp
relay(Widget{});
```

<Term def="rvalue argument 进入 forwarding-reference deduction 时，T 推导为 non-reference value type。">rvalue value-type deduction</Term>

T 是 Widget，parameter 成为 Widget rvalue reference。因此同一 declaration 能在实例化后成为两种不同 reference categories。

## const lvalue 的 cv 也被保存

```cpp
const Widget widget;
relay(widget);
```

T 推导为 const Widget lvalue reference，parameter collapse 后也是 const Widget lvalue reference。

<Term def="forwarding-reference deduction 同时保留 lvalue 的 const/volatile 与 reference 属性。">cv-category preservation</Term>

std::forward of T 因而恢复 const lvalue，不会错误制造可修改 rvalue。

## class template member 的 T 可能早已确定

```cpp
template<typename T>
class Vector {
public:
    void pushBack(T&& value); // rvalue reference
};
```

<Term def="class template 实例化时 T 已固定，member call 不再对 T 做 type deduction。">class-level type fixation</Term>

对 `Vector<Widget>`，signature 已是 `pushBack(Widget&&)`；lvalue Widget 不可调用。虽然文字包含 T&&，当前 call 没有推导，因此不是 forwarding reference。

## member 自己的 template parameter 可以 forwarding

```cpp
template<typename T>
class Vector {
public:
    template<typename Argument>
    void emplaceBack(Argument&& value); // forwarding reference
};
```

<Term def="member function 自己声明并在每次调用推导的 template parameter，可形成 forwarding reference。">member-level forwarding deduction</Term>

区分点不是“属于 class template”，而是具体 `Argument` 是否在当前 member call 被推导。

## auto&& 遵循同一规则

auto 本身需要从 initializer 推导，因此非 braced-list 例外下，`auto&&` 是 forwarding reference 形式。

```cpp
Widget widget;

auto&& first = widget;   // Widget&
auto&& second = Widget{}; // Widget&&
```

<Term def="auto 通过 initializer 推导并与 double ampersand/reference collapsing 组合的 forwarding reference。">auto double ampersand</Term>

first 不会把 lvalue 变 rvalue；auto 推导保存 lvalue reference。

## braced initializer 是 auto&& 的例外边界

```cpp
auto&& values = {1, 2, 3};
```

<Term def="auto 与 braced list 使用 initializer_list 特殊推导，而非普通 forwarding-reference deduction。">braced auto-reference exception</Term>

这里得到 initializer_list-related rvalue reference，不应拿来证明 generic forwarding behavior。裸 braced list 也常无法被 function template T&& 推导。

<Callout
  type="trap"
  title="陷阱：auto&& 永远透明保存任意 initializer 的精确类型"
>
  braced initializer 走 auto 的特殊 initializer_list 规则；proxy/lifetime
  也可能被精确保留。必须先识别 initializer category，再讨论 forwarding 与 owner
  lifetime。
</Callout>

## range-for 的 auto&& 适配 proxy 与 value category

```cpp
for (auto&& element : range) {
    process(element);
}
```

<Term def="range-for 中从 dereference result 推导 auto&&，兼容 lvalue references、proxies 与 temporary ranges。">forwarding range element</Term>

它比 `auto&` 更能接受 proxy/prvalue dereference result，也避免 plain auto 无意复制；但 named element 在 body 中仍是 lvalue expression，需要 forward only when downstream 应保持原 dereference category。

## generic lambda 的 auto&& 也是 forwarding reference

```cpp
auto relayLambda = [](auto&& argument) {
    consume(std::forward<decltype(argument)>(argument));
};
```

<Term def="generic lambda 为 auto parameter 生成模板化 call operator，并在每次调用推导 auto&&。">generic-lambda forwarding parameter</Term>

这里没有显式 T，可用 `decltype(argument)` 作为 std::forward 的 template argument，恢复 caller category。

## 普通 rvalue reference 表达消费 intent

```cpp
void setWidget(Widget&& widget) {
    stored = std::move(widget);
}
```

<Term def="API 只接受 caller 明确提供的 expendable rvalue，并通常消费其资源的契约。">rvalue-consuming parameter</Term>

它不是 generic relay，不应使用 std::forward；last use 处 std::move 更直接。是否采用 by-value + move 还取决于 overload 数量和成本。

## forwarding reference 本身不是 ownership contract

它可以绑定 lvalue borrow、const object 或 temporary。保存 parameter address/reference 到调用后可能悬空；无条件 move lvalue 又会意外消费 caller。

<Term def="forwarding parameter 只编码值类别，不说明 callee 是否借用、复制、消费或保存。">forwarding ownership ambiguity</Term>

public API 仍需通过名称、constraints、documentation 和 downstream behavior 明确 ownership。

## reference 分类验收矩阵

<Term def="覆盖 exact form、deduction、cv、auto、member template 与 braced-list 例外的编译期测试集合。">reference classification matrix</Term>

1. T&& function 对 mutable/const lvalue 与 rvalue 推导正确。
2. const T&& 拒绝 lvalue。
3. class-level T&& member 拒绝 lvalue，member-template Argument&& 接受。
4. auto&& initializer 的 decltype 与预期一致。
5. generic lambda forward 保持 overload selection。
6. braced-list cases 单独测试，不套普通推导结论。

先问“谁在当前表达式中被推导”，再看是否精确 T&&；只数 ampersands 会稳定地产生错误判断。

## 小结

- forwarding/universal reference 必须是被当前 call 推导类型的精确 T&& 形式
- ordinary Widget&&、const T&&、vector of T rvalue reference 都是 rvalue references
- lvalue argument 让 T 推导为 lvalue reference，经 collapsing 后 parameter 为 lvalue reference
- rvalue argument 让 T 为 value type，parameter 为 rvalue reference；cv 同样被保留
- class-template T 在 member call 前已固定时，T&& 不是 forwarding；member 自己推导的 Argument&& 才是
- auto&& 通常是 forwarding reference，range-for/generic lambda 可利用；braced list 是特殊推导边界
- forwarding reference 保存 value category，不自动定义 ownership 或 lifetime

<Exercises>
  1. **问题 1：分类四个 signatures。** T&&、const T&&、vector of T rvalue reference、member Argument&&。

<Answer question="哪些是 forwarding references？">
  function T double ampersand在调用中推导 T，是 forwarding reference；const T
  double ampersand不是精确形式； vector wrapper 也不是精确 T；class member 的
  Argument 若由该 member call 推导，则是 forwarding reference。 用 lvalue
  compile-pass/fail cases 验证，而非只看 template 关键字。
</Answer>

2. **问题 2：推导 mutable lvalue、const lvalue 和 rvalue。** parameter 是 T forwarding reference。

<Answer question="T 与最终 parameter 各是什么？">
  mutable lvalue 使 T 为 Widget lvalue reference并 collapse 成 Widget lvalue
  reference；const lvalue 使 T 为 const Widget lvalue reference并保持
  const；rvalue 使 T 为 Widget value type，parameter 为 Widget rvalue
  reference。用 is_same assertions 固定三条实例化。
</Answer>

3. **问题 3：generic lambda 要透明调用 consume overloads。** 直接传 argument 总走 lvalue。

  <Answer question="如何恢复 caller category？">auto double ampersand parameter 在 call operator 中被推导，但命名 argument expression 是 lvalue。使用 std forward with decltype(argument)，让 lvalue/const lvalue/rvalue 分别恢复原类别。overload counters 验证三条路径，并禁止 lambda 保存 forwarding reference 到调用结束后。</Answer>
</Exercises>
