## 从“源码不能写引用的引用”开始

普通 C++ 源码不能直接声明 reference to reference：

```cpp
int x = 0;
int& & bad = x;   // ill-formed source syntax
int&& & alsoBad = x;
```

但 template deduction、type alias 或 `decltype` 可以在类型替换过程中间接形成 `T& &&` 这样的组合。语言不能简单拒绝它，因为 forwarding reference 正需要用这种组合保存 argument 的 value category。解决办法就是 reference collapsing（引用折叠）：把中间组合规范成一个合法的 lvalue 或 rvalue reference。

<Term def="当类型替换或别名展开间接形成 reference to reference 时，按固定规则将其规范为单个引用类型。">reference collapsing</Term>

先预测四种 `&`/`&&` 组合的结果，再记一条压缩规则：只要组合中出现 lvalue reference，结果就是 lvalue reference；只有两个 rvalue references 相遇，结果仍为 rvalue reference。

## 四条规则与左值引用优先

以 `T` 表示非引用基础类型，四条规则是：

```cpp
T&  &  -> T&
T&  && -> T&
T&& &  -> T&
T&& && -> T&&
```

<Term def="四种引用组合中，只要任一层是 lvalue reference，折叠结果就是 lvalue reference。">lvalue reference wins</Term>

可以类比逻辑运算：`&` 像具有支配力的状态，只有两边都为 `&&` 才保留 rvalue reference。这个助记法不改变类型中的 `const`；例如 `const Widget& &&` 折叠为 `const Widget&`，cv qualification 属于被引用类型，会原样保留。

<Callout
  type="trap"
  title="陷阱：&& 出现在声明中，最终类型就一定是 rvalue reference"
>
  `&&` 只是外层写法。若替换进来的类型本身是 lvalue reference，`T&&` 会形成
  `Widget& &&` 并折叠为 `Widget&`；必须先展开 T，再判断最终类型。
</Callout>

## forwarding reference 有一条特殊推导规则

考虑典型入口：

```cpp
template<typename T>
void process(T&& param);
```

<Term def="形如 cv-unqualified deduced T&& 的参数；它能根据 argument category 最终成为 lvalue 或 rvalue reference。">forwarding reference</Term>

当 lvalue 传给 forwarding reference 时，T 被特殊推导成 lvalue reference type；当 rvalue 传入时，T 推导为 non-reference type。普通按值 template deduction 不会把 T 推导成 reference，这条例外正是 forwarding 的第一半机制。

## lvalue 输入经过推导再折叠

```cpp
Widget widget;
process(widget);
```

<Term def="lvalue 传入 forwarding reference 时，template parameter T 被推导为 argument type 的 lvalue reference。">lvalue-reference deduction</Term>

推导得到 `T = Widget&`。把 T 代回 parameter declaration `T&&`，中间类型为 `Widget& &&`；按第二条规则折叠为 `Widget&`。因此 `param` 可绑定 lvalue，不是因为 rvalue reference 参数突然允许 lvalue，而是实例化后的参数根本就是 lvalue reference。

const lvalue 同理：T 是 `const Widget&`，替换后形成 `const Widget& &&`，最终为 `const Widget&`。引用折叠不会剥掉 const。

## rvalue 输入不需要发生双引用折叠

```cpp
process(Widget{});
```

rvalue 输入使 T 推导为 plain `Widget`。代入 `T&&` 后得到 `Widget&&`，没有内层 reference，因此最终是 rvalue reference。

<Term def="rvalue 传入 forwarding reference 时 T 保持非引用，实例化参数直接成为 T&&。">rvalue nonreference deduction</Term>

这解释了 forwarding reference 如何编码两类信息：T 是否为 reference 记录原 argument 是 lvalue 还是 rvalue；T 指向的类型及 cv 则记录 mutable/const 属性。`std::forward<T>` 正是读取这份编码，决定恢复 lvalue 还是 rvalue expression。

## forwarding 的完整机制是两步而非一条魔法规则

<Term def="先对 lvalue 特殊推导出 reference T，再在 T&& 替换时执行 reference collapsing 的组合机制。">deduction-collapse pair</Term>

只有特殊 deduction 没有 collapsing，`Widget& &&` 将是不合法类型；只有 collapsing 没有特殊 deduction，lvalue 的 T 不会携带 `&`，parameter 仍是 `Widget&&` 而无法绑定 lvalue。两条语言规则配合，才产生所谓 universal/forwarding behavior。

这也说明并非所有 `T&&` 都是 forwarding reference：若 T 不参与 deduction，或 parameter 带 const，例如 `const T&&`，就没有这套 lvalue-reference deduction。

```cpp
template<typename T>
void exactVector(std::vector<T>&&); // rvalue reference, not forwarding

template<typename T>
void constRvalue(const T&&);        // rvalue reference, not forwarding
```

## 场景一：template instantiation

template instantiation（模板实例化）是最常见场景。compiler 将 deduced template arguments 代入 function/class template；若代入结果把 reference modifier 叠在 reference type 上，就应用 collapse rules。

<Term def="用 deduced 或显式 template arguments 替换模板参数并生成具体 declaration/function 的过程。">template instantiation</Term>

```cpp
template<typename T>
struct Holder {
    using Ref = T&&;
};

using LvalueHolder = Holder<Widget&>;
// Ref forms Widget& &&, then collapses to Widget&
```

规则并不限于 function parameters。只要合法模板替换间接形成 reference combination，都执行相同折叠。

## 场景二：auto&& 延续 forwarding 行为

`auto&&` 与 forwarding-reference template parameter 采用相同推导与折叠机制：

```cpp
Widget widget;
auto&& first = widget;    // auto = Widget&, final Widget&
auto&& second = Widget{}; // auto = Widget,  final Widget&&
```

<Term def="auto 与 && 组合时根据 initializer category 推导 reference 或 non-reference auto，再执行引用折叠。">auto forwarding deduction</Term>

range-for 中的 `auto&& element` 因而能绑定容器迭代器返回的不同 reference/proxy categories；generic lambda 的 `auto&&` parameter 也遵循同类机制。但变量名字 `first`、`second` 在 expression 中仍是 lvalue，这是 Item 23 的 named-rvalue-reference 规则，不要把 variable type 与 expression category 混为一谈。

## 场景三：typedef 与 using alias 展开

别名可以把 reference 隐藏在名字中，后续再加引用时触发折叠：

```cpp
using RvalueRefToWidget = Widget&&;

RvalueRefToWidget&& rr = Widget{}; // Widget&& && -> Widget&&
RvalueRefToWidget&  lr = rr;       // Widget&& &  -> Widget&
```

<Term def="typedef 或 using 名称代表 reference type，使用点附加新的 reference modifier 后再展开并折叠。">alias-reference expansion</Term>

不能仅凭 alias 名称含 “RvalueRef” 就断言使用点仍是 rvalue reference；真实类型由 alias 展开和外层 modifier 共同决定。代码审查时应先把 alias 替换成其 underlying type，再应用四条表。

## 场景四：decltype 结果继续参与组合

`decltype` 本身可能产出 reference type，外层模板或声明再附加 `&&` 时也会折叠：

```cpp
Widget widget;

using A = decltype(widget);   // Widget
using B = decltype((widget)); // Widget&
using C = B&&;                // Widget& && -> Widget&
```

<Term def="decltype 根据表达式形式与 value category 得到可能含 reference 的精确类型。">decltype reference result</Term>

未加括号的 id-expression `decltype(widget)` 按实体声明类型得到 Widget；额外括号使 `(widget)` 作为 lvalue expression 分析，得到 `Widget&`。当 B 再与 `&&` 组合时，引用折叠把它变成 Widget&。

## auto typedef decltype 使用同一张规则表

auto typedef decltype 并不是三套不同的折叠算法。它们的差异只在“内层类型如何产生”：auto 由 initializer deduction 得到，typedef/using 由 alias 展开得到，decltype 由 expression 规则得到；一旦形成 `&`/`&&` 组合，就统一应用四条 collapse rules。

<Term def="先确定内层 reference type 的来源，再统一套用 collapse table 的两阶段推导方法。">form-then-collapse method</Term>

因此排查复杂声明时按固定步骤执行：展开 alias；计算 template/auto/decltype 的内层类型；保留 cv；写出完整 reference combination；最后折叠。不要从变量名、`&&` 的表面字符或 initializer 的直觉直接跳到答案。

## 引用折叠不等于 value category 转换

<Term def="类型系统中合并 reference modifiers 的规则，不会自动把有名字的 expression 转换成 rvalue。">type-only collapse</Term>

折叠决定 declaration 的 reference type；expression category 仍由表达式规则决定。即便 `param` 的类型最终是 `Widget&&`，表达式 `param` 因为有名字仍是 lvalue。要把原 rvalue category 传下去，必须使用 `std::forward<T>(param)`；无条件 `std::move(param)` 会错误移动原 lvalue。

<Callout
  type="trap"
  title="陷阱：引用折叠后是 Widget&&，函数体里的 param 就是 rvalue"
>
  declaration type 与 expression value category 是两层问题。有名字的 param
  expression 总是 lvalue；reference collapsing 只计算类型，std::forward 才按 T
  的编码恢复调用者 category。
</Callout>

## 小结

- reference collapsing 把模板替换、推导或 alias 展开形成的 reference to reference 规范为合法引用
- 四条规则可压缩为 lvalue reference wins：只要出现 `&` 就得到 `&`，只有 `&& + &&` 保留 `&&`
- forwarding reference 对 lvalue 将 T 特殊推导为 lvalue reference，再由 `T&&` 替换触发折叠
- rvalue 输入使 T 保持 non-reference，实例化参数直接成为 rvalue reference
- forwarding 能力来自 lvalue-reference deduction 与 reference collapsing 的组合，不是所有 `T&&` 都具备
- 引用折叠发生在 template instantiation、auto deduction、typedef/using alias 与 decltype 结果组合中
- auto typedef decltype 只在内层类型来源上不同，形成双引用后都使用同一张四规则表
- 折叠只改变 declaration type；有名字的 parameter expression 仍是 lvalue，需由 `std::forward` 恢复 category

  `T& &`、`T& &&`、`T&& &` 都折叠为 T&，只有 `T&& &&` 折叠为 T&&。助记为组合中

2. **问题 2：分别向 process(T&&) 传 mutable lvalue、const lvalue 和 rvalue。** 推导 T、替换 parameter 并折叠。

<Answer question="三条 template instantiation path 是什么？">
  mutable lvalue 令 T=Widget&，代入形成 Widget& &&，折叠为 Widget&；const lvalue
  令 T=const Widget&，形成 const Widget& &&，折叠为 const Widget&；rvalue 令
  T=Widget，代入直接得到 Widget&&。前两条先执行特殊 lvalue
  deduction，三条最终都按同一类型替换过程确定 parameter。
</Answer>
