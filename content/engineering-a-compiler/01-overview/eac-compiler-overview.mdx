## 编译器是什么

编译器是一个**翻译程序**：它读入用源语言（如 C、Java）编写的源代码，输出等价的目标程序（通常是机器码）。与解释器不同，编译器在程序运行前完成翻译，生成的目标程序独立运行。

```text
源代码（.c / .java）  →  编译器  →  目标程序（.exe / 机器码）
```

## 三段式架构

现代编译器采用**三段式架构**，通过中间表示（IR）将前端与后端解耦：

| 阶段 | 职责 | 核心模块 | 章节 |
|------|------|---------|------|
| 前端 | 源码 → IR | 扫描器 / 语法分析器 / 上下文分析 | ch2, ch3, ch4 |
| 中端 | IR → 优化 IR | IR 生成器 / 数据流分析 / 优化 Pass | ch5, ch6 |
| 后端 | IR → 机器码 | 指令选择 / 寄存器分配 / 指令调度 | ch7, ch8 |

### 前端职责

前端负责理解源语言的语法和基本语义：

- **词法扫描**：将源码文本切分为 Token 序列
- **语法分析**：将 Token 组织成 AST（抽象语法树）
- **上下文相关分析**：类型检查、符号表管理、作用域规则

前端输出机器无关的 IR，不关心目标机器的任何细节。

### 中端职责

中端在 IR 层做分析和优化，是编译器的「性价比核心」：

- **IR 生成**：将带注解的 AST 翻译为线性 IR（三地址码 / SSA）
- **数据流分析**：在 CFG 上推导程序性质（活跃变量、可用表达式等）
- **优化 Pass**：冗余消除、循环优化、常量传播等

中端不涉及任何机器特定信息，优化只需实现一次即对所有平台生效。

### 后端职责

后端将机器无关的 IR 转换为目标机器码：

- **指令选择**：用树重写 + 动态规划选出最优目标指令
- **寄存器分配**：将虚拟寄存器映射到有限的物理寄存器
- **指令调度**：重排指令避免流水线停顿

后端只关心 IR → 机器码的映射，不关心源语言。

<Callout type="info">

**IR 是前后端之间的契约**：前端只管源语言 → IR，后端只管 IR → 机器码。两端通过 IR 接口独立演进，互不依赖。

</Callout>

## M+N 复用矩阵

三段式架构的工程价值在于**复用**：

```text
没有统一 IR：  M 种语言 × N 种机器 = M×N 套完整编译器
有统一 IR：    M 个前端 + 1 套中端 + N 个后端 = M+N 套模块
```

| | 前端 | 中端（IR + 优化） | 后端 |
|--|------|------------------|------|
| 数量 | M 个 | 1 套（复用） | N 个 |
| 关心 | 源语言 | 机器无关优化 | 目标机器 |

这是 GCC 支持 60+ 种语言和 30+ 种架构、LLVM 支持 Swift/Rust/C++ 等多种语言的根本原因——优化只需做一次。

## Pass 管道

编译器将整个翻译过程组织为**Pass 管道**——每个 Pass 只做一种变换，读入 IR 输出新 IR：

```text
源码 → [扫描 Pass] → [语法 Pass] → [语义 Pass] → [IR 生成 Pass]
     → [数据流分析 Pass] → [优化 Pass 1] → [优化 Pass 2] → ...
     → [指令选择 Pass] → [寄存器分配 Pass] → [调度 Pass] → 机器码
```

<Callout type="tip">

Pass 管道的好处：①每个 Pass 职责单一，便于实现和调试 ②可配置（`-O0` 跳过优化 Pass）③后一个 Pass 依赖前一个 Pass 的结果 ④多次遍历能发现单遍无法发现的优化机会。LLVM 的 `opt` 工具就是 Pass 管道管理器。

</Callout>

## 编译器 vs 解释器

| 对比维度 | 编译器 | 解释器 |
|---------|--------|--------|
| 翻译时机 | 运行前翻译 | 运行时逐条解释 |
| 输出 | 独立的目标程序 | 无独立目标程序 |
| 执行速度 | 快（目标码原生运行） | 慢（逐条解释开销） |
| 启动速度 | 慢（需先编译） | 快（直接执行） |
| 优化机会 | 多（可全局分析） | 少（逐条执行） |
| 典型代表 | GCC / Clang / javac | Python / Ruby / 早期 JVM |

现代 JVM 采用**混合模式**：先用解释器快速启动，热点代码再用 JIT 编译器编译为机器码，兼顾启动速度和运行性能。

<Glossary>

<GlossaryItem term="三段式架构">
编译器分为前端（源码→IR）、中端（IR优化）、后端（IR→机器码）三段，通过 IR 解耦，实现 M+N 复用而非 M×N 组合爆炸。
</GlossaryItem>

<GlossaryItem term="M+N 复用">
支持 M 种源语言只需 M 个前端，支持 N 种目标机只需 N 个后端，共享一套 IR 和优化器。优化在 IR 层做一次即对所有组合生效。
</GlossaryItem>

<GlossaryItem term="编译 Pass（遍）">
对 IR 做一次完整处理的编译阶段，每个 Pass 读入 IR 做一种变换后输出新 IR，多个 Pass 串成管道。LLVM opt / GCC GIMPLE passes 是典型实现。
</GlossaryItem>

<GlossaryItem term="JIT 编译器">
Just-In-Time 编译器，在程序运行时将热点代码编译为机器码，兼顾解释器的快速启动和编译器的高效执行。HotSpot / V8 是代表。
</GlossaryItem>

</Glossary>

### 问题 1

编译器三段式架构中前端、中端、后端各自的职责是什么？IR 在其中扮演什么角色？

<Answer>

前端职责：词法扫描（源码→Token）、语法分析（Token→AST）、上下文相关分析（类型检查+符号表），最终输出机器无关的中间表示（IR）。中端职责：在 IR 层做数据流分析与各种优化（冗余消除、循环优化等），输出优化后的 IR，不涉及任何机器细节。后端职责：指令选择（IR→目标指令）、寄存器分配（虚拟寄存器→物理寄存器）、指令调度（重排指令避免流水线停顿），输出目标机器码。IR 是三段之间的契约与桥梁：前端只管源语言→IR，后端只管 IR→机器码，两端通过 IR 解耦独立演进。

</Answer>

### 问题 2

编译器的 M×N 复用矩阵是什么？为什么三段式架构能实现 M+N 而非 M×N？

<Answer>

如果没有统一 IR，支持 M 种源语言和 N 种目标机需要 M×N 个独立编译器（每种语言×每种机器组合一套完整实现）。三段式架构通过引入机器无关的 IR 作为中间契约，将问题降为 M+N：只需 M 个前端（每种语言一个，输出统一 IR）+ 1 套中端优化器（复用）+ N 个后端（每种机器一个，从 IR 生成代码）。优化只需在 IR 层做一次，对所有语言和机器同时生效。这是 GCC、LLVM 等现代编译器能支持数十种语言和架构的根本原因。

</Answer>

### 问题 3

编译器设计与解释器有什么本质区别？为什么编译器需要多个 Pass（遍）？

<Answer>

本质区别：编译器将源代码翻译为等价的目标程序后退出，目标程序独立运行；解释器逐条执行源代码的语义，不生成独立的目标程序。编译器是「翻译器」，解释器是「执行器」。编译器需要多个 Pass 的原因：①每个 Pass 只做一种变换，职责单一便于实现和调试 ②后一个 Pass 依赖前一个 Pass 的结果（如优化依赖 IR 已建立的数据流信息）③多次遍历能发现单遍无法发现的优化机会（如全局优化需要完整的控制流图）④分离 Pass 使编译器可配置（如 -O0 跳过优化 Pass）。Pass 管道是现代编译器（LLVM opt、GCC GIMPLE passes）的核心架构。

</Answer>

### 问题 4

编译器各个阶段处理的数据形态如何变换？为什么需要多种中间表示？

<Answer>

数据形态变换链：源码文本（字符流）→词法扫描→Token序列（线性带类型标记）→语法分析→AST（树形，反映语法结构）→上下文分析→带注解AST（附加类型/符号信息）→IR生成→三地址码/SSA（线性机器无关指令）→优化→优化后IR→后端→目标指令序列（机器相关）→机器码（二进制）。需要多种中间表示的原因：每种表示服务于不同阶段的需求——AST 保留语法结构便于语义分析；线性 IR 便于数据流分析和优化；机器相关指令便于寄存器分配和调度。没有一种表示能同时高效地服务于所有阶段，故需在阶段间转换数据形态。

</Answer>
