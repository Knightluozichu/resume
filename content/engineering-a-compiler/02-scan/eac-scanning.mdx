## 扫描器的任务

词法扫描器（Scanner / Lexer）是编译器的第一个阶段，负责将源码文本切分为 **Token 序列**——每个 Token 是一个带类型标记的最小语义单元：

```text
源码: if (x >= 10) { return x; }
      ↓ 词法扫描
Token: <IF> <LPAREN> <ID:x> <GE> <INT:10> <RPAREN> <LBRACE> <RETURN> <ID:x> <SEMI> <RBRACE>
```

扫描器的核心是一个**有限状态机**：逐字符读入源码，根据当前状态和输入字符转移到下一状态，在接受状态产出 Token。

## 生成流水线

工业级扫描器通常由**扫描器生成器**（如 flex / lex）自动生成，流水线分四步：

| 步骤 | 输入 → 输出 | 算法 |
|------|------------|------|
| ① 正则表达式 | Token 模式描述 | 人工编写 |
| ② NFA 构造 | 正则 → NFA | Thompson 构造法 |
| ③ DFA 构造 | NFA → DFA | 子集构造法 |
| ④ DFA 最小化 | DFA → 最小 DFA | Hopcroft 算法 |

最终将最小 DFA 编码为**转移表**，运行时扫描器只需查表驱动。

### 第一步：正则表达式

用正则描述每种 Token 的词法模式：

```text
关键字 if : if
标识符   : [a-zA-Z_][a-zA-Z0-9_]*
整数常量 : [0-9]+
关系运算 : >= | <= | == | != | > | <
```

### 第二步：Thompson 构造法（正则 → NFA）

Thompson 构造法将正则转为 **NFA**（非确定有限自动机）：

- 每个字符匹配 → 一个转移
- `ab`（连接）→ 串联
- `a|b`（选择）→ ε 分支
- `a*`（闭包）→ ε 循环

NFA 的特点：允许 **ε 转移**（不消耗输入即可跳转），对同一输入可能有多个转移目标。

```text
正则: a(b|c)*

NFA（含 ε 转移）:
  →(a)→ • →ε→ ⇗ ⇘
              (b)  →ε→ • →ε→ ⇖ ⇙
              (c)
```

### 第三步：子集构造法（NFA → DFA）

NFA 运行时需维护状态集合（或回溯），效率低。**子集构造法**将 NFA 转为 **DFA**（确定有限自动机）：

核心思想：「NFA 的状态集合 ↔ DFA 的单状态」。

1. 计算 NFA 起始状态的 **ε-闭包**（通过 ε 能到达的所有状态）
2. 对每个状态集合和每个输入字符，计算转移后的新状态集合的 ε-闭包
3. 将每个唯一的状态集合映射为一个新的 DFA 状态
4. 包含 NFA 接受状态的集合对应 DFA 接受状态

```text
NFA 状态集 {s0,s1,s3}  →  DFA 状态 D0
DFA 转移: D0 --a--> D1, D0 --b--> D2 ...
```

DFA 每步转移都是确定的，运行时无需回溯，查表即可。

### 第四步：Hopcroft 最小化

子集构造法生成的 DFA 可能有冗余状态（等价但未合并）。**Hopcroft 算法**通过**划分等价类**最小化 DFA：

1. 初始划分：接受状态 vs 非接受状态
2. 反复细分：若同一类中的状态对某输入转移到不同类，则分裂
3. 直到划分不再变化

最小 DFA 状态数最少，转移表更紧凑，扫描器更快。

<Callout type="info">

**工程实践**：flex / lex 将上述四步自动化——你只需写正则规则，生成器自动产出 C 代码的表驱动扫描器。但理解原理对调试词法错误和优化扫描性能至关重要。

</Callout>

## 最长匹配与优先规则

扫描器运行时遵循两条核心规则：

### 最长匹配（Maximal Munch）

扫描器遇到接受状态后**不立即停止**，而是继续读入直到无法转移，然后回退到上一个接受状态，取最长可匹配的子串。

```text
输入: iffy
错误做法: 在 "if" 处停止 → 识别为关键字 IF
正确做法: 继续读入 → "iffy" 匹配标识符 → 识别为 ID
```

### 优先规则

当多个模式同时匹配同一输入时，按**声明顺序**选择（通常关键字声明在标识符之前）：

```text
输入: if
"if" 同时匹配关键字模式 if 和标识符模式 [a-z]+
→ 关键字模式声明在前 → 识别为 IF
```

<Callout type="warning">

最长匹配和优先规则共同保证：`iffy` 是 ID 不是 IF，`if` 是 IF 不是 ID。这两条规则是词法正确性的基石。

</Callout>

## 表驱动扫描器

最小 DFA 编码为两张表：**转移表**（状态×字符→下一状态）和**接受表**（状态→Token 类型）。运行时扫描器循环：

```text
state = START
while (char = next_char()) {
    state = transition[state][char]   // 查表转移
    if (state == ERROR) break
    if (is_accept[state]) {
        last_accept = state            // 记录接受点
        last_pos = current_pos
    }
}
rollback_to(last_pos)                  // 回退到最长匹配点
emit(token_type[last_accept])          // 产出 Token
```

表驱动的优势：扫描器代码固定不变，只换表即可支持不同词法规则——完全数据驱动。

<Glossary>

<GlossaryItem term="NFA（非确定有限自动机）">
对同一输入可能有多个转移目标，允许 ε 转移（不消耗输入即跳转）。Thompson 构造法将正则转为 NFA，结构直观但运行需维护状态集合。
</GlossaryItem>

<GlossaryItem term="DFA（确定有限自动机）">
对每个状态和输入字符只有唯一转移，无 ε 转移。运行时查表即可，无需回溯。子集构造法将 NFA 转为 DFA。
</GlossaryItem>

<GlossaryItem term="子集构造法（Subset Construction）">
将 NFA 转为 DFA 的算法：NFA 的状态集合映射为 DFA 的单状态，通过 ε-闭包和转移计算构建。
</GlossaryItem>

<GlossaryItem term="最长匹配原则（Maximal Munch）">
扫描器遇到接受状态后继续读入直到无法转移，取最长可匹配子串作为 Token，保证 `iffy` 识别为 ID 而非 IF。
</GlossaryItem>

<GlossaryItem term="表驱动扫描器">
将 DFA 编码为转移表和接受表，扫描器代码固定不变只换表即支持不同词法规则，是 flex/lex 的运行时模型。
</GlossaryItem>

</Glossary>

### 问题 1

词法扫描器的生成流水线是什么？从正则表达式到表驱动 DFA 经历了哪些步骤？

<Answer>

生成流水线四步：①正则表达式——用正则描述每种 Token 的词法模式 ②Thompson 构造法——将正则转为 NFA，引入 ε 转移和多路分支 ③子集构造法——将 NFA 转为 DFA，消除 ε 转移，合并状态集合 ④Hopcroft 算法——最小化 DFA，划分等价状态类。最终将最小 DFA 编码为转移表，运行时扫描器只需查表驱动。

</Answer>

### 问题 2

什么是最长匹配原则和优先规则？以输入 `iffy` 为例说明。

<Answer>

最长匹配原则：扫描器遇到接受状态后不立即停止，继续读入直到无法转移，回退到上一个接受状态，取最长可匹配子串。优先规则：多模式同时匹配时按声明顺序选择（关键字优先于标识符）。以 iffy 为例：扫描器不会在 "if" 处停止识别为关键字 IF，而是继续读入 fy，发现 "iffy" 完整匹配标识符模式，识别为 ID token。只有输入恰好是 "if" 后跟非标识符字符时才识别为 IF。

</Answer>

### 问题 3

NFA 和 DFA 有什么区别？子集构造法如何将 NFA 转为 DFA？

<Answer>

NFA：对一输入字符可能有多个转移目标，允许 ε 转移，需维护状态集合或回溯。DFA：对每个状态和输入字符只有唯一转移，无 ε 转移，查表即可无需回溯。子集构造法核心是「NFA 状态集合 ↔ DFA 单状态」：①计算每个 NFA 状态的 ε-闭包 ②对每个状态集合和输入字符，计算转移后的新状态集合的 ε-闭包 ③每个唯一状态集合映射为新的 DFA 状态 ④包含 NFA 接受状态的集合对应 DFA 接受状态。

</Answer>

### 问题 4

为什么编译器要将词法分析独立为扫描器阶段，而不是在语法分析中直接处理字符？

<Answer>

独立扫描器的理由：①分离关注点——词法规则（正则）与语法规则（上下文无关文法）属于不同层次 ②效率——DFA 扫描器是 O(n) 线性时间 ③可复用——扫描器生成器（flex/lex）可自动从正则生成高效 DFA ④预处理——扫描器同时处理注释剥离、空白跳过、行号跟踪等词法级任务 ⑤错误定位——词法错误（非法字符）在扫描阶段就能精确定位。语法分析器接收干净的 Token 序列，不必关心字符级细节。

</Answer>
