## 语法分析的任务

语法分析器（Parser）接收扫描器产出的 **Token 序列**，根据**上下文无关文法（CFG）**判断输入是否语法合法，并构建 **AST（抽象语法树）**：

```text
Token: <ID:x> <ASSIGN> <ID:y> <PLUS> <INT:2> <SEMI>
      ↓ 语法分析
AST:   Assign
       ├── x
       └── +
           ├── y
           └── 2
```

上下文无关文法用**产生式**描述语法结构，如 `Assign → ID = Expr ;`。

## 两大流派：LL 与 LR

语法分析分为两大流派，区别在于**推导方向**：

| 维度 | LL 分析（自顶向下） | LR 分析（自底向上） |
|------|-------------------|-------------------|
| 方向 | 从起始符号推导到输入串 | 从输入串归约到起始符号 |
| 策略 | 预测用哪条产生式展开 | 移进 Token，栈顶匹配时归约 |
| 典型实现 | 递归下降 / 预测分析表 | 移进-归约 + LR 分析表 |
| 左递归 | 不能处理 | 能处理 |
| 表达力 | 较弱（LL(1) 文法子集） | 较强（LALR(1) 覆盖大多数语言） |
| 工具 | ANTLR / 手写递归下降 | yacc / bison |

### 自顶向下：LL 分析

LL 分析从**起始符号 S** 出发，每次选择最左非终结符，**预测**用哪条产生式展开：

```text
S → id = E ;          // 展开最左非终结符 S
  id = E ;
    id = T + E ;      // 展开 E → T + E
      id = id + E ;   // 展开 T → id
        ...
```

预测的依据是 **FIRST 集**——每个非终结符能推导出的首个终结符集合。若 FIRST 集无交集，则 LL(1)（向前看 1 个 Token）即可无回溯决策。

**递归下降**是 LL 分析的最常见手写形式：每个非终结符对应一个函数，函数内根据当前 Token 决定调用哪个子函数。

<Callout type="warning">

**LL 的弱点**：不能处理左递归文法（`E → E + T` 会导致无限递归）。必须改写为右递归（`E → T E'`，`E' → + T E' | ε`）后才能用 LL 分析。

</Callout>

### 自底向上：LR 分析

LR 分析从**输入串**出发，通过两个操作逐步归约到起始符号：

- **移进（Shift）**：读入下一个 Token 压入栈
- **归约（Reduce）**：栈顶匹配某产生式右部时，将右部替换为左部非终结符

```text
步骤 1（移进）: 栈 [ id ]           输入 = expr ;
步骤 2（移进）: 栈 [ id = ]         输入 expr ;
步骤 3（移进）: 栈 [ id = id ]      输入 + ;
步骤 4（归约）: 栈 [ id = T ]       输入 + ;     // T → id
步骤 5（移进）: 栈 [ id = T + ]     输入 ;
步骤 6（归约）: 栈 [ id = E ]       输入 ;       // E → T + E
步骤 7（归约）: 栈 [ Assign ]       输入 ε       // Assign → id = E
```

## LR 分析的能力层次

LR 分析按 lookahead 能力递增分为四层：

| 层次 | lookahead | 特点 | 状态数 |
|------|-----------|------|--------|
| LR(0) | 0 | 不看 lookahead，冲突最多 | 少 |
| SLR(1) | 1 | 用 FOLLOW 集消除部分冲突 | 少 |
| LALR(1) | 1 | 每状态独立 lookahead，合并同核心状态 | 中（≈ SLR） |
| LR(1) | 1 | 完整 lookahead，能力最强 | 多（可能爆炸） |

<Callout type="tip">

**LALR(1) 是工程上的甜点**：状态数接近 SLR(1) 但分析能力接近 LR(1)，yacc/bison 默认生成 LALR(1) 分析器。大多数编程语言文法都能被 LALR(1) 处理。

</Callout>

## 冲突与消除

移进-归约分析中可能出现两类**冲突**：

### 移进-归约冲突

栈顶内容既可移进下一个 Token，也可按某产生式归约，分析器无法确定。

```text
栈 [ id = E ]  输入 + ;
  → 归约 Assign → id = E ？ 还是
  → 移进 + ？
```

### 归约-归约冲突

栈顶内容同时匹配两条不同产生式的右部，无法确定按哪条归约。

### 消除方法

1. **增加 lookahead**：LR(0) → SLR(1) → LALR(1) → LR(1)
2. **改写文法**：提取左因子、消除二义性
3. **优先级声明**：yacc 的 `%left`、`%right`、`%prec` 让分析器按优先级决策

<Glossary>

<GlossaryItem term="LL 分析（自顶向下）">
从起始符号出发，预测用哪条产生式展开最左非终结符，逐步推导出输入串。典型实现是递归下降和预测分析表，需 FIRST 集，不能处理左递归。
</GlossaryItem>

<GlossaryItem term="LR 分析（自底向上）">
从输入串出发，通过移进（Shift）和归约（Reduce）操作逐步归约到起始符号。能处理左递归，表达力强，是 yacc/bison 的基础。
</GlossaryItem>

<GlossaryItem term="LALR(1)">
Look-Ahead LR(1)，合并 LR(1) 中核心相同但 lookahead 不同的状态，状态数接近 SLR(1) 但分析能力接近 LR(1)。是工程上最常用的 LR 分析算法。
</GlossaryItem>

<GlossaryItem term="移进-归约冲突">
栈顶内容既可移进也可归约时产生的歧义。通过增加 lookahead、改写文法或设置优先级声明消除。
</GlossaryItem>

<GlossaryItem term="左递归">
产生式形如 `A → A α`，LL 分析会无限递归。需改写为右递归 `A → β A'`，`A' → α A' | ε` 消除。
</GlossaryItem>

</Glossary>

### 问题 1

LL 分析和 LR 分析的区别是什么？各自的自顶向下/自底向上是如何工作的？

<Answer>

LL 分析（自顶向下）：从起始符号 S 出发，预测使用哪条产生式展开最左非终结符，逐步推导出输入串。典型实现是递归下降和预测分析表，需 FIRST 集。不能处理左递归。LR 分析（自底向上）：从输入串出发，通过移进（读入 Token 压栈）和归约（栈顶匹配产生式右部时替换为左部）操作，逐步归约到起始符号。能处理左递归，表达力更强，能力递增 LR(0)→SLR(1)→LALR(1)→LR(1)。

</Answer>

### 问题 2

移进-归约分析中的「移进-归约冲突」和「归约-归约冲突」是什么？如何消除？

<Answer>

移进-归约冲突：栈顶既可移进也可归约，分析器无法确定。归约-归约冲突：栈顶同时匹配两条不同产生式右部，无法确定按哪条归约。消除方法：①增加向前看符号数（LR(0)→SLR(1)→LALR(1)→LR(1)）②改写文法消除歧义（提取左因子）③设置优先级和结合性声明（yacc 的 %prec、%left、%right）。LALR(1) 是工程上的实用折中。

</Answer>

### 问题 3

LR 分析器的能力层次 LR(0) → SLR(1) → LALR(1) → LR(1) 有什么区别？

<Answer>

LR(0) 不向前看符号，冲突最多。SLR(1) 归约时检查 lookahead 是否在 FOLLOW 集中，能消除部分冲突。LALR(1) 合并 LR(1) 项目集中核心相同但 lookahead 不同的状态，状态数与 SLR(1) 相当但归约决策更精确。LR(1) 最精确，每个状态有完整 lookahead，能力最强但状态数可能爆炸。四者能力递增、状态数递增：LR(0) < SLR(1) ≤ LALR(1) < LR(1)。

</Answer>

### 问题 4

什么是左递归文法？为什么 LL 分析不能处理左递归？如何消除？

<Answer>

左递归文法：产生式形如 `A → A α`（直接左递归）或经多步推导形成 `A ⇒+ A α`（间接左递归）。LL 分析不能处理的原因：LL 自顶向下展开最左非终结符时，遇到 `A → A α` 会再次展开 A，形成无限递归。消除直接左递归：将 `A → A α | β` 改写为 `A → β A'` 和 `A' → α A' | ε`，用新非终结符 A' 将左递归转为尾递归。间接左递归需先求推导闭包再统一消除。

</Answer>
