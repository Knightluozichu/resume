## 语法分析的局限

语法分析（上下文无关文法）能判断 `x = y + z` 结构合法，但管不住以下**上下文相关性质**：

- `x` 是否已声明？（需查符号表）
- `y` 和 `z` 类型是否兼容？（需类型检查）
- 函数实参个数和类型是否匹配签名？
- `return` 语句的返回值类型是否与函数声明一致？
- `break` 是否在循环内？

这些性质不是「结构合法性」而是「语义合法性」，依赖符号表、类型系统和作用域规则。**上下文相关分析**就是在语法分析之后、IR 生成之前，遍历 AST 检查这些语义规则并标注类型信息的过程。

## 属性文法

**属性文法**在文法的每个节点上挂载**属性**，通过属性求值规则表达语义：

### 综合属性（Synthesized）

由子节点的属性计算得到，**自底向上**传递：

```text
E.type = result_type(E1.type, E2.type, op)
// 子表达式先算好 type 传给父节点
```

表达式节点的类型由子表达式类型和运算符决定——子节点先算好，父节点综合。

### 继承属性（Inherited）

由父节点或兄弟节点传入，**自顶向下**传递：

```text
var_decl.type → inherited by variable.name
// 声明语句的类型限定符传给变量名
```

变量声明 `int x` 中，`x` 的类型由声明的类型限定符（`int`）继承而来。

### 语法制导翻译（SDT）

**语法制导翻译**在遍历 AST 时按属性依赖求值：综合属性在归约时计算，继承属性在推导时计算。求值顺序需满足**属性依赖图无环**（Adorned AST），使整个属性求值能顺利完成。

<Callout type="info">

SDT 把语义检查和 IR 生成的逻辑嵌入语法结构遍历中。综合属性用于表达式求值和类型推导，继承属性用于传递作用域、类型限定等上下文信息。

</Callout>

## 符号表

**符号表**记录「名字 → 信息」的映射，是声明与引用之间的桥梁：

| 信息字段 | 说明 |
|---------|------|
| 类型 | int / float / struct / function |
| 种类 | 变量 / 函数 / 类 / 类型别名 |
| 作用域层级 | 嵌套深度 |
| 存储位置 | 栈偏移 / 堆地址 / 寄存器 |
| 可见性 | public / private / protected |

### 嵌套作用域

支持嵌套作用域的常见方式是**作用域栈**：

```text
进入函数 foo()   → 压入新作用域表
  进入块 { }     → 压入新作用域表
    声明 int x   → 插入栈顶表
    引用 x       → 从栈顶向下搜索，找到最近的 x
  离开块         → 弹出栈顶表
离开函数         → 弹出栈顶表
```

查找时从栈顶向下搜索，实现「内层遮蔽外层」的可见性规则。

<Callout type="tip">

符号表是编译器的「记忆」——声明时插入，引用时查找。高效的符号表实现（哈希表 + 作用域链）对编译速度至关重要。

</Callout>

## 类型检查与推断

### 类型检查

程序员显式声明变量类型，编译器**验证**操作是否类型合法：

```text
int x = 1;
float y = 2.0;
x + y;  // int + float → 检查是否允许隐式转换 → 结果 float
```

类型规则表达为：`Γ ⊢ e1 : τ1, Γ ⊢ e2 : τ2 ⟹ Γ ⊢ e1 + e2 : result(τ1, τ2)`

### 类型推断

程序员不声明类型，编译器根据使用方式**推导**出变量类型：

```text
let x = 1 + 2;   // 推断 x : int（1+2 的结果类型）
let f = fun(y) → y + 1;  // 推断 y : int, f : int → int
```

**Hindley-Milner 算法**是经典的全局类型推断算法，基于**合一（Unification）**——将类型约束逐步求解出最一般类型。

### 问题 1

为什么语法分析（上下文无关文法）不足以完成编译器的全部前端工作？什么是上下文相关分析？

<Answer>

上下文无关文法只能描述语法结构（如 `x = y + z` 是合法赋值），但无法表达需上下文才能判断的性质：变量是否已声明、类型是否兼容、函数参数是否匹配、return 类型是否一致、break 是否在循环内。这些是上下文相关性质。上下文相关分析是在语法分析之后、IR 生成之前，遍历 AST 检查语义规则并标注类型信息的过程，是前端的第三个阶段。

</Answer>

### 问题 2

属性文法中的综合属性和继承属性是什么？语法制导翻译（SDT）如何利用它们？

<Answer>

综合属性：由子节点属性计算，自底向上传递。如表达式节点的 type 由子表达式 type 和运算符决定。继承属性：由父节点或兄弟节点传入，自顶向下传递。如变量声明的类型限定符传给变量名。SDT 在遍历 AST 时按属性依赖求值，综合属性在归约时计算，继承属性在推导时计算，求值顺序需满足属性依赖图无环。SDT 把语义检查和 IR 生成逻辑嵌入语法结构遍历。

</Answer>

### 问题 3

符号表的作用是什么？如何支持嵌套作用域？

<Answer>

符号表记录「名字→信息」（类型、种类、作用域层级、存储位置），是声明与引用的桥梁。支持嵌套作用域用作用域栈：进入新作用域压入新表，离开时弹出；查找时从栈顶向下搜索，实现「内层遮蔽外层」。也可用符号表树（子作用域指向父作用域）或哈希表+作用域链。函数调用、块语句、类定义都创建新的嵌套作用域。

</Answer>

### 问题 4

类型检查和类型推断有什么区别？类型规则如何表达？

<Answer>

类型检查：程序员显式声明类型，编译器验证操作是否类型合法——是验证过程，类型已给出。类型推断：程序员不声明类型，编译器根据使用方式自动推导——是求解过程，类型需算出。Hindley-Milner 算法基于合一是经典推断算法。类型规则用类型判断表达：`Γ ⊢ e1:τ1, Γ ⊢ e2:τ2 ⟹ Γ ⊢ e1+e2 : result(τ1,τ2)`，即在类型环境 Γ 下若 e1 类型 τ1、e2 类型 τ2，则 e1+e2 类型由 result 函数决定。类型规则组成类型系统。

</Answer>
