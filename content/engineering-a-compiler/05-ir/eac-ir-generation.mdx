## 中间表示的作用

中间表示（IR）是介于 AST 和目标代码之间的**机器无关**表示。前端输出 AST，中端翻译为 IR，后端从 IR 生成目标代码：

```text
带注解 AST  →  IR 生成  →  三地址码  →  SSA 化  →  优化  →  优化后 IR
```

<EacIrGenerationDiagram />

<Callout type="info">

不直接在 AST 上生成目标代码，是因为 AST 层次结构复杂、与源语言耦合紧密。IR 形式简单（线性指令），便于做机器无关优化，也便于后端复用。

</Callout>

## 三地址码（TAC）

三地址码每条指令最多包含**三个操作数**（两个源 + 一个目的）：

```text
t1 = c * 2        ← 两个源操作数 c 和 2，目的 t1
t2 = b + t1       ← 两个源操作数 b 和 t1，目的 t2
a = t2            ← 一个源操作数 t2，目的 a
```

### AST → TAC 翻译示例

以 `a = b + c * 2` 为例：

```text
AST:                          TAC:
Assign                        t1 = c * 2
├── a                         t2 = b + t1
└── BinOp(+)                  a = t2
    ├── b
    └── BinOp(*)
        ├── c
        └── 2
```

翻译过程**自底向上**：先翻译 `c * 2` 生成 `t1`，再翻译 `b + t1` 生成 `t2`，最后赋值 `a = t2`。临时变量将嵌套的树形表达式展平为线性指令序列。

## 语法制导翻译

语法制导翻译（SDT）在遍历 AST 时为每个节点计算**属性**并生成 IR 指令：

### 综合属性

子节点的属性值由其子树计算，**自底向上**传递：

```text
E.addr = new_temp()                        ← 分配临时变量
emit(E.addr = E1.addr + E2.addr)           ← 生成指令
```

表达式节点 E 的 `addr` 属性 = 临时变量名，子表达式先算好 `addr` 传给父节点。

### 继承属性

节点的属性值由父节点传入，**自顶向下**传递：

```text
S.next = inherited_label    ← 控制流标签从父节点传入
```

控制流翻译需用继承属性传递跳转标号、循环入口/出口等上下文信息。

## SSA 形式

SSA（静态单赋值）要求每个变量只被赋值一次，在控制流汇合点用 $\phi$ 函数合并：

```text
TAC:              SSA:
t1 = a + b        t1_1 = a + b
t1 = c * d        t1_2 = c * d
                  t1_3 = phi(t1_1, t1_2)   ← φ 函数合并两条路径
```

$\phi$ 函数的数学含义：$t_1^{(3)} = \phi(t_1^{(1)}, t_1^{(2)})$ 表示根据到达该点的控制流路径选择对应的值。

<Callout type="tip">

SSA 的核心优势：每个变量只有一个定义点，**def-use 链**直接且精确，使常量传播、死代码消除等优化实现更简单高效。LLVM IR、GCC GIMPLE 都是 SSA 形式。

</Callout>

## 控制流图与基本块

### 基本块（Basic Block）

一段连续的指令序列，只有**一个入口**（第一条指令）和**一个出口**（最后一条指令），块内没有分支也没有跳转目标。

### 控制流图（CFG）

将每个基本块作为节点、跳转关系作为有向边构成的图。若块 B1 末尾跳转到 B2，则有一条边 $B_1 \to B_2$。

CFG 显式表达程序的控制流结构（分支、循环），是数据流分析的基础数据结构。

## 三种 IR 形式对比

| IR 形式 | 特点 | 优势 | 用途 |
|---------|------|------|------|
| 三地址码（TAC） | 线性指令，每条最多 3 操作数 | 简单易生成 | 基础 IR |
| SSA 形式 | 每变量只赋值一次 | 优化友好，def-use 精确 | LLVM IR |
| 控制流图（CFG） | 基本块 + 跳转边 | 数据流分析基础 | 优化分析 |

三者可组合使用：SSA 形式的指令组织在 CFG 的基本块中，是现代编译器的标准 IR 形态。

</GlossaryItem>

SSA 中在控制流汇合点插入的合并函数，$t = \phi(t_1, t_2)$ 表示根据到达路径选择 $t_1$ 或 $t_2$ 的值。

</GlossaryItem>

<GlossaryItem term="基本块（Basic Block）">
只有一个入口和一个出口的连续指令序列，块内无分支无跳转目标，是 CFG 的节点单元。
</GlossaryItem>

<Exercises>

### 问题 1

中间表示（IR）的作用是什么？为什么不在 AST 上直接生成目标代码？

<Answer>

中间表示是介于 AST 和目标代码之间的机器无关表示。作用：①解耦前端与后端——前端输出 IR，后端从 IR 生成代码，两端独立 ②优化友好——IR 是线性指令序列，比树形 AST 更适合做数据流分析和优化 ③多平台复用——同一份 IR 可生成不同平台代码，优化只需做一次。不在 AST 上直接生成目标代码是因为 AST 层次结构复杂、与源语言耦合紧密，直接生成会混杂语法结构与机器细节，难以做机器无关优化。

</Answer>

### 问题 2

三地址码（TAC）的格式是什么？以 `a = b + c * 2` 为例说明 AST 如何翻译为三地址码。

<Answer>

三地址码每条指令最多三个操作数（两源+一目的），形式 `x = y op z`。以 `a = b + c * 2` 为例：翻译过程自底向上——先为 `c * 2` 生成临时变量 t1，emit `t1 = c * 2`；再为 `b + t1` 生成临时变量 t2，emit `t2 = b + t1`；最后生成赋值 `a = t2`。临时变量将嵌套树形表达式展平为线性指令序列。

</Answer>

### 问题 3

什么是 SSA（静态单赋值）形式？φ 函数的作用是什么？为什么 SSA 使优化更高效？

<Answer>

SSA 要求每个变量只被赋值一次，多次赋值创建新版本（x1,x2,x3）。控制流汇合点用 φ 函数合并：`x3 = phi(x1, x2)` 表示根据到达路径选择 x1 或 x2 的值。SSA 使优化更高效的原因：①每个变量只有一个定义点，def-use 链直接精确 ②常量传播、死代码消除等优化在 SSA 上实现更简单 ③避免「同一变量多次定值」的模糊性。LLVM IR、GCC GIMPLE 都采用 SSA。

</Answer>

### 问题 4

控制流图（CFG）和基本块是什么？它们在 IR 中的作用是什么？

<Answer>

基本块：只有一个入口和一个出口的连续指令序列，块内无分支无跳转目标。控制流图：将基本块作为节点、跳转关系作为有向边构成的图。CFG 的作用：①显式表达控制流结构（分支、循环），是数据流分析的基础 ②划分基本块使分析可块内局部做、块间全局做 ③循环检测（通过支配关系和回边）是循环优化前提 ④CFG + SSA 是现代编译器优化管道的标准 IR 形态。

</Answer>

</Exercises>
