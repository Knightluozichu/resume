## 端到端流水线

从源代码到目标机器码，编译器经过以下阶段，每个阶段有明确的输入输出：

| 阶段 | 章节 | 输入 → 输出 | 核心技术 |
|------|------|------------|---------|
| 词法扫描 | ch2 | 源码文本 → Token 序列 | 正则 / DFA / 表驱动 |
| 语法分析 | ch3 | Token → AST | LL / LR / 移进归约 |
| 上下文分析 | ch4 | AST → 带注解 AST | 属性文法 / 符号表 / 类型检查 |
| IR 生成 | ch5 | 带注解 AST → IR | 三地址码 / SSA / CFG |
| 代码优化 | ch6 | IR → 优化 IR | 数据流分析 / 冗余消除 / 循环优化 |
| 指令选择 | ch7 | 优化 IR → 目标指令 | 树重写 / 动态规划 |
| 寄存器分配 | ch8 | 虚拟寄存器 → 物理寄存器 | 干扰图 / 图着色 / 线性扫描 |

数据形态经历了：**文本 → 树（AST）→ 线性机器无关指令（IR）→ 线性机器相关指令 → 二进制机器码**的逐步变换。

## 三段架构与 IR 枢纽

### 前端：理解源语言

前端三章（ch2-ch4）负责将源码转为 IR：

- **ch2 词法扫描器**：正则 → NFA → DFA → 最小化 DFA → 表驱动扫描器。核心是有限状态机 + 最长匹配原则。
- **ch3 语法分析器**：LL（自顶向下）vs LR（自底向上）。核心是预测分析表 / 移进归约 + LALR(1)。
- **ch4 上下文相关分析**：属性文法（综合 / 继承属性）+ 符号表（作用域栈）+ 类型检查 / 推断。

### 中端：优化 IR

中端两章（ch5-ch6）在机器无关层做分析和优化：

- **ch5 中间表示生成**：AST → 三地址码 → SSA。核心是语法制导翻译 + φ 函数 + CFG。
- **ch6 代码优化原理**：数据流分析框架（方向 / 值域 / 传递函数 / 交汇运算）→ 冗余消除（LVN / 可用表达式 / DCE）→ 循环优化（LICM / 强度削弱 / 归纳变量）。

### 后端：生成机器码

后端两章（ch7-ch8）将 IR 转为目标机器码：

- **ch7 指令选择**：IR 树 → 瓦片覆盖 → 动态规划求最优覆盖。核心是树重写 + 成本模型。
- **ch8 寄存器分配**：活跃分析 → 干扰图 → 图着色 / 线性扫描。核心是溢出策略 + 活跃区间分裂。

<Callout type="info">

**IR 是全书的核心枢纽**：前端输出 IR，中端消费并优化 IR，后端从 IR 生成代码。IR 让前后端解耦，实现 M+N 复用，优化在 IR 层做一次即对所有组合生效。这是 GCC、LLVM 等工业级编译器的标准架构。

</Callout>

## 核心概念对比

### 前端三大分析层次

| 层次 | 分析对象 | 文法 / 规则 | 输出 |
|------|---------|------------|------|
| 词法 | 字符流 | 正则 | Token |
| 语法 | Token 流 | 上下文无关文法（CFG） | AST |
| 语义 | AST | 属性文法 + 类型规则 | 带注解 AST / IR |

### 中端优化分类

| 优化 | 作用域 | 方向 | 效果 |
|------|--------|------|------|
| 局部值编号（LVN） | 基本块内 | 局部 | 消除块内冗余计算 |
| 可用表达式 | 全局 | 前向 | 消除跨块冗余计算 |
| 死代码消除（DCE） | 全局 | 后向 | 删除无用计算 |
| 循环不变量外提 | 循环 | - | 减少循环内重复计算 |
| 强度削弱 | 循环 | - | 用便宜运算替代昂贵运算 |

### 后端两种寄存器分配

| 维度 | 图着色 | 线性扫描 |
|------|--------|---------|
| 建模 | 干扰图着色 | 活跃区间排序贪心 |
| 质量 | 最优 | 略低 |
| 速度 | O(n²) | O(n log n) |
| 适用 | AOT（GCC/LLVM） | JIT（HotSpot/V8） |

## 数据形态变换链

```text
源码文本（字符流）
  ↓ 词法扫描（ch2）
Token 序列（线性带类型标记）
  ↓ 语法分析（ch3）
AST（树形，反映语法结构）
  ↓ 上下文分析（ch4）
带注解 AST（附加类型 / 符号信息）
  ↓ IR 生成（ch5）
三地址码 / SSA（线性机器无关指令）
  ↓ 代码优化（ch6）
优化后 IR（冗余消除 / 循环优化）
  ↓ 指令选择（ch7）
目标指令序列（机器相关，虚拟寄存器）
  ↓ 寄存器分配（ch8）
分配寄存器的指令（物理寄存器 + spill）
  ↓ 指令调度
最终机器码（二进制）
```

## 自主实现策略

如果要自己实现一个简单编译器，建议**分阶段推进**：

| 阶段 | 实现 | 可简化 |
|------|------|--------|
| 1 | 扫描器（正则 → 手写 DFA） | 用 flex 自动生成 |
| 2 | 递归下降语法分析器 | 不用 LALR |
| 3 | 符号表 + 基本类型检查 | 只支持 int/float |
| 4 | AST → 三地址码翻译 | 跳过 SSA |
| 5 | 局部优化（常量折叠 + LVN） | 跳过全局数据流分析 |
| 6 | 简单指令选择（逐条翻译） | 不做树重写 DP |
| 7 | 简单寄存器分配（线性扫描） | 不做图着色 |

<Callout type="tip">

核心原则：**先正确再高效，先端到端打通再逐步优化**。先把扫描 → 语法 → IR → 后端全链路跑通（能编译出可运行程序），再逐步提升各阶段质量。迭代式开发是编译器实现的关键策略。

</Callout>

### 问题 1

从源代码到目标机器码，编译器的完整流水线是什么？每个阶段的核心输入输出是什么？

<Answer>

完整流水线：①词法扫描——输入源码文本，输出 Token 序列 ②语法分析——输入 Token，输出 AST ③上下文相关分析——输入 AST，输出带注解 AST ④IR 生成——输入带注解 AST，输出机器无关 IR（三地址码/SSA）⑤代码优化——输入 IR，输出优化后 IR ⑥指令选择——输入优化后 IR，输出目标指令（虚拟寄存器）⑦寄存器分配——输入虚拟寄存器指令，输出物理寄存器指令 ⑧指令调度——输入物理寄存器指令，输出重排后的指令 ⑨最终输出机器码。数据形态经历了文本→树→线性机器无关指令→线性机器相关指令→二进制机器码的变换。

</Answer>

### 问题 2

IR 在编译器架构中为什么如此关键？它如何实现 M+N 复用和优化复用？

<Answer>

IR 是编译器的核心枢纽：①前后端解耦——前端只管源语言→IR，后端只管 IR→机器码，两端独立演进 ②M+N 复用——M 种语言只需 M 个前端，N 种机器只需 N 个后端，共享一套 IR 和优化器，避免 M×N 组合爆炸 ③优化复用——所有优化 Pass 在机器无关 IR 层实现一次，对所有语言和机器同时生效 ④分阶段验证——IR 作为中间检查点 ⑤工具链生态——统一 IR 使不同语言代码可链接互操作（如 LLVM IR 让 C++、Rust、Swift 混合编译）。

</Answer>

### 问题 3

前端、中端、后端各自的核心技术是什么？它们如何衔接？

<Answer>

前端：词法扫描（正则→DFA→表驱动）、语法分析（LL/LR/移进归约）、上下文分析（属性文法/符号表/类型检查），输出 IR。中端：IR 生成（AST→三地址码/SSA/CFG）、数据流分析（前向后向/格/传递函数/不动点）、优化（LVN/可用表达式/DCE/循环优化），输出优化后 IR。后端：指令选择（树重写+动态规划）、寄存器分配（活跃分析→干扰图→图着色/线性扫描）、指令调度，输出机器码。衔接：前端输出 IR→中端消费并优化 IR→后端从 IR 生成代码，IR 是三段统一接口。

</Answer>

### 问题 4

如果要自己实现一个简单编译器，你会如何分阶段推进？哪些阶段可以简化或跳过？

<Answer>

分阶段：①扫描器（正则→手写 DFA）②递归下降语法分析器 ③符号表+基本类型检查 ④AST→三地址码翻译 ⑤局部优化（常量折叠+LVN）⑥简单指令选择（逐条翻译）⑦简单寄存器分配（线性扫描）。可简化/跳过：①SSA 化——用普通三地址码 ②复杂数据流分析——只做局部优化 ③树重写指令选择——逐条翻译+特判寻址 ④图着色——用线性扫描 ⑤指令调度。核心是先端到端打通（能编译出可运行程序），再逐步优化各阶段质量。迭代式开发：先正确再高效。

</Answer>
