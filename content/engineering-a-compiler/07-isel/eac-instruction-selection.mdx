## 指令选择的任务

指令选择（Instruction Selection）将机器无关的 IR 映射为**目标机器的指令序列**，目标是选出成本最低（最快 / 最短）的指令组合。

不能逐条翻译 IR 的原因：

- 目标机有**复合指令**——多条 IR 操作可合并为一条指令
- 不同指令组合实现同一效果但**成本不同**
- 寻址模式丰富（如 `LOAD [base+index*scale]` 一条指令完成地址计算 + 加载）
- 需考虑指令的**副作用和约束**

## 树重写：瓦片覆盖

### IR 树与瓦片

将 IR 表达为**树形结构**，每条目标指令描述为一个**瓦片（Tile）**——即一个树模式 + 成本：

```text
rule1: +(reg, reg)          → ADD  cost 1
rule2: *(reg, reg)          → MUL  cost 3
rule3: *(reg, const_pow2)   → SHL  cost 1   ← 用移位替代乘法
rule4: const                → LOAD cost 1
rule5: mem[reg]             → LOAD cost 2
```

指令选择 = 用瓦片**无重叠地覆盖**整棵 IR 树，使总成本最小。

### 示例

以 `a + (b * 4)` 的 IR 树为例：

```text
      +
     / \
    a   *
       / \
      b   4

方案 A（MUL）: LOAD a, LOAD b, LOAD 4, MUL, ADD  → cost 1+1+1+3+1 = 7
方案 B（SHL）: LOAD a, LOAD b, SHL 2, ADD        → cost 1+1+1+1 = 4  ← 最优
```

方案 B 利用 `*(x, 4) → SHL(x, 2)` 规则，用移位替代乘法，成本更低。

## 动态规划求最优覆盖

### 递推思路

对 IR 树每个子树，记录「用各规则覆盖该子树的最小成本」，**自底向上**递推：

$$Cost(node, rule) = rule.cost + \sum_{child} \min_{r} Cost(child, r)$$

即：用规则 `rule` 覆盖当前节点的成本 = `rule` 自身成本 + 各子树的最优覆盖成本之和。

### 求解步骤

1. **叶节点**：成本由寄存器 / 常量加载规则决定
2. **内部节点**：对每条可匹配的规则，计算 `rule.cost + 子树最优成本`
3. **根节点**：取所有可匹配规则中成本最小的，即全局最优指令序列

<Callout type="info">

树形 DP 天然适合递归 IR：时间复杂度 $O(\text{节点数} \times \text{规则数})$。burg、iburg 等工具自动从规则描述生成最优指令选择器。

</Callout>

## 成本模型

每条瓦片的成本通常用**时钟周期数**或**指令字节数**衡量：

| 指令 | 周期数 | 说明 |
|------|--------|------|
| ADD / SUB | 1 | 简单算术 |
| SHL / SHR | 1 | 位移 |
| MUL | 3-10 | 乘法较慢 |
| DIV | 20-40 | 除法很慢 |
| LOAD / STORE | 1-3 | 内存访问 |

准确的成本模型是指令选择质量的关键。但现代 CPU 乱序执行使精确成本难以建模，实践中常简化为静态周期估计。

<Callout type="warning">

成本模型是理想化的。实际 CPU 有流水线、缓存、乱序执行，静态成本估计与真实性能可能有偏差。编译器只能在模型精度和编译速度间权衡。

</Callout>

## 与后端其他阶段的关系

指令选择、寄存器分配和指令调度是后端的三大阶段，它们的**顺序影响代码质量**：

| 顺序 | 特点 |
|------|------|
| 先选指令 → 再分配寄存器 | 经典顺序（GCC/LLVM 默认），但 spill 可能破坏调度 |
| 先分配 → 再选指令 | 限制寻址模式，但避免 spill |
| 调度与分配交替 | LLVM 实践，质量最优但复杂 |

实践中常需多轮迭代或交替执行，没有完美顺序。

<Glossary>

<GlossaryItem term="指令选择">
将机器无关 IR 映射为目标机器指令序列的过程，目标是选出成本最低的指令组合。本质是组合优化问题。
</GlossaryItem>

<GlossaryItem term="瓦片（Tile）">
一条目标指令对应的 IR 树模式。整棵 IR 树被一组无重叠的瓦片完整覆盖，每个瓦片有成本。
</GlossaryItem>

<GlossaryItem term="树重写（Tree Pattern Matching）">
用瓦片覆盖 IR 树的指令选择方法。每条目标指令描述为一个树模式 + 成本，目标是找总成本最小的覆盖。
</GlossaryItem>

<GlossaryItem term="最优覆盖">
动态规划求出的成本最小的瓦片覆盖方案。对每个子树记录各规则的最小成本，自底向上递推。
</GlossaryItem>

<GlossaryItem term="成本模型">
每条指令的执行代价（周期数或字节数）。准确成本模型是指令选择质量的关键，但现代 CPU 乱序执行使精确建模困难。
</GlossaryItem>

### 问题 1

指令选择解决什么问题？为什么 IR 不能直接逐条翻译为目标指令？

<Answer>

指令选择将机器无关 IR 映射为目标机器指令序列，选出成本最低的指令组合。不能逐条翻译的原因：①目标机有复合指令，多条 IR 可合并为一条 ②不同指令组合实现同一效果但成本不同 ③寻址模式丰富（如 `LOAD [base+index*scale]` 一条完成地址计算+加载）④需考虑指令副作用和约束。指令选择本质是在目标指令集所有合法覆盖中选最优的组合优化问题。

</Answer>

### 问题 2

树重写如何做指令选择？动态规划如何求最优覆盖？

<Answer>

树重写：将 IR 表达为树，每条目标指令描述为树模式（瓦片）+成本，指令选择 = 用瓦片无重叠覆盖整棵 IR 树使总成本最小。动态规划求最优覆盖：对每个子树记录「用各规则覆盖的最小成本」，自底向上递推。`Cost(node, rule) = rule.cost + Σ 各子树最优覆盖成本`。叶节点成本由加载规则决定，根节点最优 rule 即全局最优指令序列。时间复杂度 O(节点数 × 规则数)。

</Answer>

### 问题 3

指令选择中的「瓦片」和「成本」是什么？为什么需要成本模型？

<Answer>

瓦片：一条目标指令对应的 IR 树模式，如 `+(reg,reg) → ADD`、`*(reg,4) → SHL 2`。成本：每条瓦片的执行代价（周期数或字节数），如 MUL cost 3、SHL cost 1。需要成本模型是因为同一 IR 子树可被多条不同瓦片覆盖（如 `a+1` 可用 ADD 或 INC 或 LEA），需成本模型决定选哪个最优。准确成本模型是质量关键，但现代 CPU 乱序执行使精确建模困难，常简化为静态周期估计。

</Answer>

### 问题 4

指令选择、指令调度和寄存器分配三者有什么关系？为什么它们的顺序影响代码质量？

<Answer>

三者是后端核心：指令选择把 IR 映射为目标指令（虚拟寄存器）；寄存器分配把虚拟寄存器映射到物理寄存器（不够则溢出）；指令调度重排指令避免流水线停顿。顺序影响质量：①先选指令再分配——经典顺序，但 spill 可能破坏调度 ②先分配再选指令——限制寻址模式但避免 spill ③调度与分配相互依赖——调度改变指令顺序影响活跃范围，分配插入 spill 影响调度。实践常需多轮迭代或交替，如 LLVM 的分配和调度交替进行。

</Answer>
