## 寄存器分配的问题

目标机的物理寄存器数量有限（如 x86-64 只有 16 个通用寄存器），但 IR 中使用的虚拟寄存器可能有几百个。**寄存器分配**将虚拟寄存器映射到有限的物理寄存器，不够时将部分变量溢出到内存。

## 图着色分配流程

图着色是质量最优的寄存器分配方法，分三步：

### 第一步：活跃变量分析

后向数据流分析，计算每个程序点的**活跃变量集合**（在该点之后还会被使用的变量）：

$$OUT[b] = \bigcup_{s \in succ(b)} IN[s]$$

$$IN[b] = (OUT[b] - DEF[b]) \cup USE[b]$$

变量在「定值点」到「最后使用点」之间是活跃的。

### 第二步：构建干扰图

将每个变量作为图的**节点**，若两个变量在某一程序点同时活跃（活跃区间重叠），则连一条**干扰边**——表示不能共用同一物理寄存器：

```text
b = a + 1   // {a, b} 同时活跃 → a-b 干扰
c = b * 2   // {b, c} 同时活跃 → b-c 干扰
d = a - c   // {a, c, d} 同时活跃 → a-c, a-d, c-d 干扰
```

### 第三步：图着色

用 $K$ 种颜色（$K$ = 可用物理寄存器数）对干扰图着色，使相邻节点颜色不同。每种颜色对应一个物理寄存器：

- 着色成功 → 所有变量分配到寄存器
- 色数 $> K$ → 需溢出部分变量到内存

<Callout type="info">

图着色是 NP 完全问题，编译器用**启发式算法**（如 Chaitin-Briggs）近似求解：反复删除度数小于 $K$ 的节点（一定能着色），无法删除时选溢出候选。

</Callout>

## 溢出（Spill）

当干扰图色数超过 $K$ 时，无法将所有变量分配到寄存器，需将部分变量存放到**栈帧内存**。

### 选择溢出候选

| 策略 | 理由 |
|------|------|
| 度数最高 | 干扰多，删除后降低着色难度最大 |
| 使用频率最低 | 溢出代价小（少插 LOAD/STORE） |
| 活跃区间最长 | 释放的寄存器压力大 |

### 溢出后处理

1. 在溢出变量的定值后插入 `STORE`（寄存器 → 内存），使用前插入 `LOAD`（内存 → 寄存器）
2. 重新计算活跃变量和干扰图（因为插入了新的临时变量）
3. 重新着色，可能需多轮迭代

<Callout type="warning">

溢出是寄存器压力下的最后手段，会显著降低性能。现代编译器用**活跃区间分裂**将长区间在关键边界拆分，使部分子区间分配寄存器而其余溢出，比整体溢出更精细。

</Callout>

## 线性扫描

图着色质量最优但 $O(n^2)$ 太慢。**线性扫描**按活跃区间排序贪心分配，复杂度 $O(n \log n)$：

```text
1. 将所有活跃区间按起始点排序
2. 维护当前占用寄存器的活跃区间集合
3. 遇到新区间时：
   - 若有空闲寄存器 → 分配
   - 否则选未来最远才使用的区间溢出
```

### 适用场景对比

| 维度 | 图着色 | 线性扫描 |
|------|--------|---------|
| 质量 | 最优 | 略低（5-10% 差距） |
| 速度 | $O(n^2)$ | $O(n \log n)$ |
| 适用 | AOT 编译器（GCC/LLVM） | JIT 编译器（HotSpot/V8/LuaJIT） |

JIT 编译器在运行时编译，编译时间直接影响响应速度，故倾向用线性扫描——「足够好且快」。

## 活跃区间

**活跃区间**是变量从第一次定值到最后一次使用之间的连续指令范围。线性扫描直接用活跃区间排序；图着色用逐点活跃信息构建更精确的干扰图。

现代编译器做**活跃区间分裂**——将一个长区间在关键边界拆分为多个子区间，使部分子区间可分配寄存器而其余溢出，减少 LOAD/STORE 次数。LLVM 的寄存器分配大量使用区间分裂。

<Glossary>

<GlossaryItem term="活跃变量分析">
后向数据流分析，计算每个程序点的活跃变量集合（之后还会被使用的变量）。是构建干扰图的基础。
</GlossaryItem>

<GlossaryItem term="干扰图">
将变量作为节点、同时活跃的变量对连边的图。相邻节点不能共用同一物理寄存器，寄存器分配建模为图着色问题。
</GlossaryItem>

<GlossaryItem term="图着色寄存器分配">
用 K 种颜色（K=物理寄存器数）对干扰图着色使相邻节点颜色不同。质量最优但 O(n²) 复杂度，是 AOT 编译器首选。
</GlossaryItem>

<GlossaryItem term="溢出（Spill）">
色数超过 K 时将部分变量存到栈帧内存，在定值后插 STORE、使用前插 LOAD，重新着色可能需多轮迭代。
</GlossaryItem>

<GlossaryItem term="线性扫描">
按活跃区间排序贪心分配寄存器的 O(n log n) 算法，质量略低于图着色但快一个数量级，是 JIT 编译器首选。
</GlossaryItem>

<GlossaryItem term="活跃区间">
变量从第一次定值到最后一次使用之间的连续指令范围。线性扫描直接用区间排序，图着色用逐点活跃信息构建干扰图。
</GlossaryItem>

</Glossary>

### 问题 1

图着色寄存器分配的完整流程是什么？活跃变量分析、干扰图和着色各起什么作用？

<Answer>

完整流程三步：①活跃变量分析——后向数据流分析计算每点活跃变量集合 ②构建干扰图——变量为节点，同时活跃的变量对连干扰边（不能共用寄存器）③图着色——用 K 种颜色（K=物理寄存器数）着色使相邻节点颜色不同，每色对应一寄存器。K 色成功则全部分配，色数>K 则溢出。活跃分析提供「谁干扰谁」信息，干扰图将分配建模为图论问题，着色算法求解最优分配。

</Answer>

### 问题 2

寄存器分配中溢出（Spill）是什么？如何选择溢出候选？溢出后需要做什么？

<Answer>

溢出：色数超过 K 时将部分变量存到栈帧内存。选择溢出候选：①度数最高（干扰多，删除降低难度大）②使用频率最低（溢出代价小）③活跃区间最长（释放压力大）。Chaitin-Briggs 算法反复删除度数<K 的节点，无法删除时选溢出候选。溢出后：①定值后插 STORE、使用前插 LOAD ②重新计算活跃变量和干扰图 ③重新着色，可能多轮迭代。

</Answer>

### 问题 3

图着色分配和线性扫描分配各有什么特点？为什么 JIT 编译器倾向用线性扫描？

<Answer>

图着色：质量最优但 O(n²) 复杂度，编译时间长，是 AOT 编译器（GCC/LLVM）首选。线性扫描：按活跃区间排序贪心分配，O(n log n)，质量略低（5-10% 差距）但快一个数量级。JIT 编译器（HotSpot/V8/LuaJIT）倾向线性扫描是因为 JIT 在运行时编译，编译时间直接影响程序响应速度，图着色的质量优势不值得其时间代价，线性扫描的「足够好且快」更符合 JIT 需求。

</Answer>

### 问题 4

什么是活跃区间（Live Interval）？它与活跃变量分析的关系是什么？

<Answer>

活跃区间：变量从第一次定值到最后一次使用之间的连续指令范围。与活跃变量分析的关系：活跃变量分析计算每点活跃集合，是构建活跃区间的基础——从逐点活跃集合推导出每个变量的活跃范围再合并为连续区间。线性扫描直接用活跃区间排序分配；图着色用逐点活跃信息构建更精确的干扰图。现代编译器还做活跃区间分裂——将长区间在关键边界拆为子区间，部分子区间分配寄存器其余溢出，比整体溢出更精细。LLVM 大量使用区间分裂。

</Answer>
