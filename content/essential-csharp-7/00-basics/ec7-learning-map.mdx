## 直觉引入

学一门语言就像盖一栋楼。你不能先装电梯再打地基，也不能先装修再砌墙——顺序错了，每一步都会塌。

C# 7.0 本质论把这门语言拆成四段：先学砖块和水泥（基础类型与控制流），再学怎么搭房间（类与对象），然后学怎么做可复用的预制构件（泛型与委托），最后学怎么让整栋楼智能化运转（LINQ 与异步）。每一段都建立在前一段之上，跳过任何一段都会在后面遇到「看得懂语法却不理解为什么」的困境。

## 概念讲解

### 四段递进结构

全书按一条主线展开：**类型安全的层层抽象**。这条主线把分散的语法点、面向对象、泛型、高级特性串成一个体系——每一层都在前一层的基础上提供更强的表达力。

**C# 基础（第 1-3 章）**是地基。它覆盖类型系统（值类型与引用类型的根本区别）、变量声明与 `var` 类型推断、运算符优先级与控制流（`if`/`switch`/循环）。不理解类型系统，就无法理解后续章节中的装箱拆箱、泛型约束、接口多态。

<Term def="一门语言同时支持过程式、面向对象、函数式等多种编程风格，且在整个类型系统中保持编译期类型安全。">强类型多范式语言</Term>

**面向对象（第 4-5 章）**是骨架。它把基础类型升级为自定义类型——用类封装数据与行为，用继承与接口实现复用与多态。C# 的面向对象比 C++ 更纯粹（单继承 + 接口多实现），比 Java 更丰富（属性、事件、委托）。

**泛型与委托（第 6-7 章）**是筋脉。泛型把类型参数化，一份代码适用于多种类型且无装箱开销；委托把方法当作一等公民，事件基于委托实现发布-订阅模型。这两者是 LINQ 与异步编程的语法基础。

**高级特性（第 8-10 章）**是皇冠。LINQ 把查询抽象为统一管道，async/await 把异步编程简化为看似同步的代码。它们是 C# 区别于其他静态类型语言的核心竞争力。

### 为什么不能跳段学习

<Callout type="trap"><strong>现象 →</strong> 学了基础语法直接跳去用 async/await，写出代码能跑但完全不理解背后的状态机机制，出了死锁不知怎么排查。<strong>原因 →</strong> 跳过了面向对象和泛型委托段。async/await 依赖 Task（泛型类）、委托（回调 continuation）、状态机（编译器生成的类）。没有这些基础，await 就只是个"魔法关键字"。<strong>修法 →</strong> 回到面向对象段补齐类与继承，再学泛型与委托，理解 Task 和回调机制后，async/await 才能学得透。</Callout>

  <Step title="第四步：高级特性——LINQ 与异步的皇冠">
    第四段覆盖第 8-10 章。LINQ 把集合查询抽象为 `Where`/`OrderBy`/`Select` 链式管道，延迟执行到枚举时才求值。async/await 让异步代码写得像同步代码，编译器生成状态机管理挂起与恢复。最后总复习用思维导图收束全书。
  </Step>

## 代码对照

```csharp
// 第 1-3 章：基础——类型与控制流
int x = 42;                    // 值类型，栈分配
string s = "hello";            // 引用类型，堆分配
var numbers = new List<int>(); // var 类型推断

if (x > 0) { Console.WriteLine(s); }

// 第 4-5 章：面向对象——封装与多态
public class Animal {
    public string Name { get; set; }      // 属性
    public virtual void Speak() { }       // 虚方法
}
public class Dog : Animal {
    public override void Speak() => Console.WriteLine("Woof");
}

// 第 6-7 章：泛型与委托
public class Stack<T> { /* ... */ }       // 泛型类
public delegate void Handler(string msg); // 委托

// 第 8-9 章：LINQ 与异步
var result = numbers.Where(n => n > 2).OrderBy(n => n);
var data = await httpClient.GetStringAsync(url);
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 把 C# 当 C++ 学，过度使用继承层次，忽视接口和委托的力量。<strong>原因 →</strong> C++ 是多继承，容易建深层继承树；C# 是单继承 + 接口多实现，设计哲学不同。在 C# 中，接口定义"能力"（can-do），继承表达"是什么"（is-a），两者分工明确。<strong>修法 →</strong> 在 C# 中优先用接口定义契约，用组合替代深层继承。委托和事件是 C# 独特的解耦手段，不要忽视。</Callout>

<Callout type="trap"><strong>现象 →</strong> 混淆值类型与引用类型，把 struct 当 class 用，性能反而下降。<strong>原因 →</strong> struct 赋值是拷贝，大 struct 频繁传递比 class 引用传递开销更大；且 struct 装箱后变引用类型，产生额外 GC 压力。<strong>修法 →</strong> 小而不可变的值用 struct（如 `Point`、`DateTime`），需要共享可变状态的大对象用 class。</Callout>

<Exercises>
<Answer question="全书分为哪四段？各包含哪些章节？">C# 基础（第 1-3 章：学习地图、类型与变量、运算符与控制流）；面向对象（第 4-5 章：类与对象、继承与接口）；泛型与委托（第 6-7 章：泛型、委托与事件）；高级特性（第 8-10 章：LINQ、异步编程、总复习）。</Answer>
<Answer question="为什么不能跳过面向对象直接学 async/await？">async/await 依赖 Task（泛型类）、委托（回调 continuation）、编译器生成的状态机（类）。没有面向对象、泛型、委托的基础，await 只是魔法关键字，出了死锁或异常无法排查。</Answer>
<Answer question="C# 的单继承 + 接口多实现与 C++ 的多继承有什么设计差异？">C# 单继承避免多继承的菱形问题，更安全；接口多实现提供 can-do 能力组合，比 C++ 的多继承更灵活。C# 的设计哲学是：用接口定义能力契约，用组合替代深层继承。</Answer>
<Answer question="struct 和 class 在什么场景下应该选哪个？">小而不可变的值（如 Point、DateTime）用 struct，值语义天然正确且可避免堆分配；需要共享可变状态的大对象用 class，引用传递比拷贝更高效。大 struct 频繁拷贝反而比 class 慢。</Answer>
</Exercises>
