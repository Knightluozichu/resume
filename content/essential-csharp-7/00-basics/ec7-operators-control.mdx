## 直觉引入

运算符就像交通规则——谁先走、谁后走有明确优先级。如果你不遵守规则，结果就会出错。比如 `2 + 3 * 4`，乘法优先级高于加法，所以先算 `3 * 4 = 12`，再算 `2 + 12 = 14`。如果你想要先加后乘，必须加括号 `(2 + 3) * 4 = 20`。

控制流则是路线规划——程序从哪里走、在哪里分岔、在哪里绕圈。`if-else` 是十字路口二选一，`switch` 是环岛多路分支，`for`/`while`/`foreach` 是绕圈循环，`break`/`continue` 是紧急出口和跳过通道。C# 7.0 的模式匹配让 `switch` 从简单的值匹配升级为类型与结构匹配，表达力大幅提升。

## 概念讲解

### 运算符优先级

C# 运算符从高到低大致为：一元（`++`/`--`/`!`/`~`/`(T)x`）→ 乘除取模（`*`/`/`/`%`）→ 加减（`+`/`-`）→ 关系（`<`/`>`/`<=`/`>=`/`is`/`as`）→ 相等（`==`/`!=`）→ 逻辑（`&`/`^`/`|`/`&&`/`||`）→ 赋值（`=`/`+=`/`-=`/`??=`）。

<Term def="逻辑与 && 和逻辑或 || 的求值策略：如果左侧已能确定结果，右侧不求值。如 false && X 中 X 不执行。">短路求值</Term>

`&&` 和 `||` 是短路运算符：`a && b` 中如果 `a` 为 false，`b` 不求值；`a || b` 中如果 `a` 为 true，`b` 不求值。这在防空指针时极其常用：`if (obj != null && obj.Count > 0)` 中，如果 `obj` 为 null，`obj.Count` 不会执行，避免了 NullReferenceException。

### 空合并与空条件运算符

C# 提供两个处理 null 的利器：

- **空合并运算符 `??`**：`x ?? y` 表示 x 不为 null 时返回 x，否则返回 y。常用于提供默认值：`string name = input ?? "anonymous";`
- **空条件运算符 `?.`**：`x?.Member` 表示 x 不为 null 时访问 Member，否则返回 null。`obj?.Count` 等价于 `obj != null ? obj.Count : null`。

两者常组合使用：`var len = text?.Length ?? 0;`——text 为 null 时 len 为 0，否则为 text.Length。

### 模式匹配 switch

C# 7.0 的 switch 表达式支持类型模式、when 守卫、属性模式：

```csharp
string Describe(object o) => o switch
{
    null => "null",
    int n when n < 0 => "negative",
    int n => $"positive {n}",
    string s => $"string: {s}",
    _ => "unknown"
};
```

<Term def="C# 7.0 引入的 switch 表达式，支持类型匹配、属性匹配、when 守卫和弃元模式 _，是比传统 switch 语句更强的分支工具。">模式匹配 switch</Term>

`_` 是弃元模式（discard），匹配任何值，相当于 default。switch 表达式是表达式而非语句，可以直接赋值，且编译器检查是否穷尽所有分支。

### 循环与跳转

C# 提供 `for`、`while`、`do-while`、`foreach` 四种循环。`foreach` 用于遍历实现了 `IEnumerable` 的集合，是最常用的循环。`break` 立即跳出循环，`continue` 跳过当前迭代进入下一次，`return` 直接退出方法。

    <Ec7OperatorsControlDiagram />

    运算符优先级决定求值顺序。`2 + 3 * 4 = 14`（先乘后加）。短路求值是 `&&`/`||` 的核心安全特性：`if (list != null && list.Count > 0)` 中，如果 `list` 为 null，`list.Count` 不会执行，避免 NullReferenceException。不用短路的话（用 `&` 代替 `&&`），两边都会求值，空指针就会炸。
  </Step>
  <Step title="第二步：空合并与空条件——优雅处理 null">
    `?.` 和 `??` 让 null 处理变得简洁。`text?.Length ?? 0` 一行搞定"text 为 null 返回 0，否则返回长度"。不用它们要写 `int len = text != null ? text.Length : 0;`，冗长且容易漏判。C# 7.0 还支持 `??=` 空合并赋值：`name ??= "default";` 等价于 `if (name == null) name = "default";`。
  </Step>
  <Step title="第三步：模式匹配 switch——类型安全的多路分支">
    C# 7.0 的 switch 表达式从值匹配升级为类型匹配。`o switch { int n => ..., string s => ..., _ => ... }` 一次匹配类型并绑定变量。配合 `when` 守卫可以做更细的分支：`int n when n < 0 => "negative"`。编译器检查穷尽性，漏掉分支会编译报错。
  </Step>
  <Step title="第四步：循环与跳转——控制迭代">
    `foreach` 遍历集合最常用，`for` 需要索引时用，`while` 条件循环。`break` 跳出整个循环（如找到目标就停），`continue` 跳过当前迭代（如跳过无效项）。`return` 直接退出方法。嵌套循环中 `break` 只跳出最内层——要跳出多层可用标志变量或提取方法后 return。
  </Step>
</Stepper>

## 代码对照

```csharp
// 短路求值：防止空指针
if (list != null && list.Count > 0) { /* 安全 */ }

// 空合并与空条件
string name = input ?? "anonymous";
int len = text?.Length ?? 0;
name ??= "default";  // C# 7.0 空合并赋值

// 模式匹配 switch 表达式
string Grade(int score) => score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 60 => "C",
    _ => "F"
};

// 类型模式 + when 守卫
string Describe(object o) => o switch
{
    null => "null",
    int n when n < 0 => "negative",
    int n => $"positive {n}",
    string s => $"string: {s}",
    _ => "unknown"
};

// foreach 与跳转
foreach (var item in items)
{
    if (item == null) continue;  // 跳过 null
    if (item.IsFinal) break;     // 找到终态就停
    Process(item);
}
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 用 `&` 代替 `&&`，导致空指针异常。<strong>原因 →</strong> `&` 是非短路逻辑与，两边都求值。`if (obj != null & obj.Count > 0)` 中，即使 obj 为 null，`obj.Count` 也会执行，抛 NullReferenceException。<strong>修法 →</strong> 逻辑判断用 `&&` 和 `||`（短路），`&` 和 `|` 仅用于位运算。</Callout>

<Callout type="trap"><strong>现象 →</strong> switch 表达式漏了分支，编译报错"switch 表达式未处理某些输入"。<strong>原因 →</strong> switch 表达式要求穷尽所有可能，必须有 `_`（弃元）或 default 分支兜底。<strong>修法 →</strong> 加 `_ => defaultValue` 作为最后分支，或确保所有已知情况都覆盖。</Callout>

<Callout type="trap"><strong>现象 →</strong> 在 foreach 中修改集合（如 Remove），抛 InvalidOperationException。<strong>原因 →</strong> foreach 使用迭代器遍历，迭代器检测到集合被修改会抛异常（快速失败机制）。<strong>修法 →</strong> 用 for 循环倒序遍历并 Remove，或先收集要删除的项再统一删除，或用 LINQ `Where` 过滤生成新集合。</Callout>
