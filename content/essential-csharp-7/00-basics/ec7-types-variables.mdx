## 直觉引入

想象你有一份文件。如果你把文件**复印**一份给同事，同事在副本上涂改不影响你的原件——这就是值类型：赋值就是拷贝。如果你把文件的**网盘链接**发给同事，你们看的是同一份文件，谁改了对方都能看到——这就是引用类型：赋值是共享。

C# 的类型系统就建立在这个根本区别上。`int`、`double`、`bool` 是值类型，存在栈上，赋值拷贝数据；`string`、数组、类实例是引用类型，存在堆上，赋值共享引用。理解这个区别，才能理解后续的装箱拆箱、泛型约束、参数传递行为。

## 概念讲解

### 值类型与引用类型

<Term def="变量直接存储数据本身，分配在栈上，赋值时产生独立副本。包括简单类型、struct、enum。">值类型</Term>

<Term def="变量存储指向堆数据的引用（地址），赋值时共享同一对象。包括 class、数组、接口、委托、string。">引用类型</Term>

值类型的变量直接包含数据。`int a = 10; int b = a;` 后修改 `b` 不影响 `a`，因为 `b` 是 `a` 的独立拷贝。引用类型的变量包含指向堆对象的引用。`Employee e1 = new Employee(); Employee e2 = e1;` 后 `e1` 和 `e2` 指向同一个堆对象，通过任何一个修改都会影响另一个。

`string` 是特殊的引用类型——它不可变（immutable）。虽然 `string` 在堆上分配，但每次修改都产生新对象，行为看起来像值类型。这是 C# 有意为之的设计：不可变性保证了字符串共享的安全性。

### var 类型推断

`var` 让编译器根据右侧表达式推断变量类型。`var x = 42;` 等价于 `int x = 42;`。`var` 是编译期特性，编译后类型完全确定，不是动态类型。

`var` 的适用场景：右侧类型明显时（如 `var names = new List<string>();`）、LINQ 查询结果类型复杂时。不适用场景：右侧类型不明显时（如 `var x = GetValue();` 看不出类型），此时显式类型更可读。

### 可空类型与装箱拆箱

<Term def="在值类型基础上包装一个 null 标记，允许值类型变量表示"未赋值"。如 int? 可以是 0 到 MaxValue 或 null。">可空类型</Term>

`int? x = null;` 在底层是 `Nullable<int>` 结构体，包含一个 `bool HasValue` 标记和 `int value`。可空类型常用于数据库映射（数据库字段可以为 NULL）和 JSON 反序列化。

<Term def="把值类型包装成 object（或接口）引用类型对象的过程，在堆上分配并拷贝数据。反向操作是拆箱。">装箱</Term>

```csharp
int x = 42;
object o = x;    // 装箱：在堆上创建 int 对象，拷贝 42
int y = (int)o;  // 拆箱：从堆对象中提取值拷贝到栈
```

装箱有性能开销（堆分配 + GC 压力）。泛型（如 `List<int>`）的核心价值之一就是消除装箱——值类型直接存在泛型容器的内部数组中，不需要装箱成 `object`。

## 交互Demo

<Stepper>
  <Step title="第一步：值类型赋值——拷贝数据">
    <Ec7TypesVariablesDiagram />

    `int a = 10; int b = a;` 执行后，`a` 和 `b` 是栈上两个独立的存储位置，各存各的 10。修改 `b = 20` 不影响 `a`——这就是值类型的拷贝语义。struct 也是值类型，`DateTime d1 = DateTime.Now; DateTime d2 = d1;` 同样产生独立拷贝。
  </Step>
  <Step title="第二步：引用类型赋值——共享对象">
    `var e1 = new Employee(); var e2 = e1;` 执行后，`e1` 和 `e2` 是栈上两个引用变量，但都指向堆上同一个 Employee 对象。`e2.Name = "Bob"` 后 `e1.Name` 也是 "Bob"——它们共享同一个对象。数组同理：`int[] a = {1,2}; int[] b = a; b[0] = 99;` 后 `a[0]` 也是 99。
  </Step>
  <Step title="第三步：装箱——值类型变引用类型">
    当值类型需要作为 `object` 或接口使用时（如 `ArrayList` 存 `int`，或调用 `object.Equals(object)`），编译器自动装箱：在堆上分配一个对象，拷贝值类型的值。装箱有性能开销，频繁装箱（如在循环中把 int 存进非泛型容器）会产生大量垃圾对象，增加 GC 压力。
  </Step>
  <Step title="第四步：泛型消除装箱">
    `List<int>` 的内部是 `int[]`，直接存值，不需要装箱。而 `ArrayList` 的内部是 `object[]`，存 int 时每次都装箱。这就是泛型的核心价值之一：类型安全且无装箱开销。
  </Step>
</Stepper>

## 代码对照

```csharp
// 值类型：赋值 = 拷贝
int a = 10;
int b = a;
b = 20;
Console.WriteLine(a);  // 10，不受影响

// 引用类型：赋值 = 共享
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;
list2.Add(4);
Console.WriteLine(list1.Count);  // 4，共享同一对象

// string 不可变
string s1 = "hello";
string s2 = s1;
s2 = "world";
Console.WriteLine(s1);  // hello，string 不可变

// 可空类型
int? age = null;
if (age.HasValue)
    Console.WriteLine(age.Value);
else
    Console.WriteLine("未提供");

// 装箱与拆箱
int x = 42;
object o = x;        // 装箱
int y = (int)o;      // 拆箱

// var 类型推断
var name = "Alice";              // string
var count = 42;                  // int
var items = new List<string>();  // List<string>
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 把大 struct 当 class 用，方法参数传 struct 时性能比 class 差。<strong>原因 →</strong> struct 是值类型，每次传参都拷贝整个结构体。大 struct（如含多个数组的坐标结构）拷贝开销远大于 class 的引用拷贝（4/8 字节指针）。<strong>修法 →</strong> 小而不可变的值用 struct（小于 16 字节），大对象用 class。传 struct 给方法时可加 `ref` 避免拷贝。</Callout>

<Callout type="trap"><strong>现象 →</strong> 在循环里把 int 存进 ArrayList，性能很差且 GC 频繁。<strong>原因 →</strong> ArrayList 内部是 `object[]`，存 int 时每次都装箱，在堆上创建临时对象，循环结束后这些对象变垃圾。<strong>修法 →</strong> 用泛型 `List<int>` 替代 ArrayList，内部是 `int[]`，直接存值不装箱。</Callout>

<Callout type="trap"><strong>现象 →</strong> `int? x = null; int y = x;` 编译报错。<strong>原因 →</strong> `int?` 可能是 null，直接赋给 `int` 不安全——null 不是有效的 int 值。<strong>修法 →</strong> 用 `int y = x ?? 0;`（null 合并，null 时用默认值 0）或 `int y = x.GetValueOrDefault();`。或先检查 `x.HasValue` 再取 `x.Value`。</Callout>

<Answer question="值类型和引用类型在赋值时的行为有什么根本区别？">值类型赋值拷贝数据（栈上独立副本），修改互不影响；引用类型赋值共享引用（指向同一堆对象），通过任何一个修改都影响另一个。string 是特殊引用类型，不可变所以看起来像值类型。</Answer>
<Answer question="var 是动态类型吗？什么场景适合用 var，什么场景不适合？">var 不是动态类型，是编译期类型推断，编译后类型完全确定。适合：右侧类型明显（如 `new List<string>()`）、LINQ 结果类型复杂。不适合：右侧类型不明显（如 `GetValue()`），此时显式类型更可读。</Answer>
<Answer question="什么是装箱？它有什么性能问题？泛型如何解决？">装箱是把值类型包装成 object 引用类型，在堆上分配并拷贝数据。性能问题：堆分配开销 + GC 压力，频繁装箱（如非泛型容器存 int）产生大量垃圾。泛型（如 `List<int>`）内部用 `int[]` 直接存值，消除装箱。</Answer>
<Answer question="分析以下代码的输出和原因：`int[] a = {1,2}; int[] b = a; b[0] = 99; Console.WriteLine(a[0]);`">输出 99。数组是引用类型，`int[] b = a` 让 b 和 a 指向同一个堆上的数组对象。通过 b 修改 `b[0] = 99` 直接改变了共享的数组，所以 `a[0]` 也是 99。要独立拷贝需用 `b = (int[])a.Clone()` 或 `b = a.ToArray()`。</Answer>
</Exercises>

## 名词解释

<Glossary>
<GlossaryItem term="值类型">变量直接存储数据本身，分配在栈上，赋值时产生独立副本。包括 int、double、bool、char、struct、enum。</GlossaryItem>
<GlossaryItem term="引用类型">变量存储指向堆数据的引用（地址），赋值时共享同一对象。包括 class、数组、接口、委托、string。</GlossaryItem>
<GlossaryItem term="可空类型（int?）">在值类型基础上包装 null 标记，底层是 Nullable&lt;T&gt; 结构体，含 HasValue 标记和 Value 字段。常用于数据库映射。</GlossaryItem>
<GlossaryItem term="装箱（Boxing）">把值类型隐式转换为 object 或接口的引用类型，在堆上分配并拷贝数据。反向操作是拆箱。频繁装箱有性能开销。</GlossaryItem>
<GlossaryItem term="var 类型推断">编译器根据右侧表达式推断变量类型，是编译期特性，编译后类型完全确定，不是动态类型。</GlossaryItem>
