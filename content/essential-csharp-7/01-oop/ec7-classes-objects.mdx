## 直觉引入

想象一个公司。员工有姓名、工号、薪资（数据），能工作、能加薪（行为）。如果这些数据公开挂着，任何人都能直接改薪资，那不乱套了？所以公司用规章制度把数据藏起来，只允许通过"人事部审批"这样的受控接口修改——这就是封装。

C# 的类就是这样一个"微型公司"。`private` 字段是内部账本，外人看不到；`public` 属性是办事窗口，有 get（查询）和 set（审批）两个口；`public` 方法是具体业务流程；构造函数是入职手续——员工对象诞生的那一刻就把初始信息填好。

## 概念讲解

### 字段与属性

<Term def="类内部的数据存储，通常 private，直接表示对象的状态。">字段（field）</Term>

<Term def="对字段的受控访问代理，提供 get 和 set 访问器，可在访问时加入验证逻辑。C# 支持自动属性省略后备字段。">属性（property）</Term>

字段是原始数据存储，应保持 private。属性是字段的"安全代理"——外部通过属性读写数据，属性内部可以做验证。C# 的自动属性 `{ get; set; }` 让编译器自动生成后备字段，省去手写字段：

```csharp
// 自动属性——编译器生成后备字段
public string Name { get; set; }

// 带验证的属性
private int _age;
public int Age
{
    get => _age;
    set => _age = value < 0 ? 0 : value;  // 不允许负数
}
```

C# 7.0 引入 `init` 访问器：只能在构造时赋值，之后不可变，兼顾不可变性与初始化灵活性。`public string Name { get; init; }` 允许对象初始化器赋值，但构造完成后只读。

### 构造函数

构造函数与类同名，在对象创建时自动调用，负责初始化字段。C# 支持构造函数重载和构造函数链（用 `: this(...)` 调用另一个构造函数）：

```csharp
public class Employee
{
    public string Name { get; }
    public decimal Salary { get; set; }

    public Employee(string name, decimal salary)
    {
        Name = name;
        Salary = salary;
    }
    public Employee(string name) : this(name, 3000) { }  // 链式调用
}
```

### 静态成员与实例成员

<Term def="属于类本身而非某个实例的成员，通过类名访问，不依赖对象。所有实例共享同一份静态数据。">静态成员（static）</Term>

静态字段属于类，所有实例共享。静态方法不依赖实例，直接通过类名调用。实例成员属于对象，每个对象有自己的一份。`Console.WriteLine()` 中 `WriteLine` 就是静态方法。

### this 指针

`this` 指向当前对象实例。用途：区分同名参数与字段（`this.name = name`）、链式调用（`return this`）、构造函数链（`: this(...)`）、扩展方法（`this` 参数）。

## 交互Demo

<Stepper>
  <Step title="第一步：字段 + 属性——封装的基本结构">
    <Ec7ClassesObjectsDiagram />

    类用 `private` 字段存储数据，`public` 属性提供受控访问。自动属性 `{ get; set; }` 最简洁；需要验证时手写 get/set 访问器；需要不可变时用 `{ get; init; }` 或 `{ get; }`（只读，只能在构造函数中赋值）。字段是"保险箱"，属性是"窗口"——外部通过窗口看和改，不能直接开保险箱。
  </Step>
  <Step title="第二步：构造函数——对象的出生证明">
    构造函数在 `new` 时自动调用，负责把字段初始化到合法状态。不带参的默认构造函数在没写任何构造函数时编译器自动生成；写了带参构造函数后默认构造函数不再自动生成。构造函数链 `: this(...)` 避免重复初始化逻辑——主构造函数做全部工作，其他构造函数委托给它。
  </Step>
  <Step title="第三步：静态成员——属于类而非对象">
    静态字段所有实例共享（如计数器 `static int Count`），静态方法不依赖实例（如 `Math.Max`）。静态构造函数在类首次使用时执行一次，用于初始化静态字段。注意：静态方法不能访问实例成员（没有 this），实例方法可以访问静态成员。
  </Step>
  <Step title="第四步：this 指针——指向当前实例">
    this 最常用于区分同名参数与字段：构造函数 `Employee(string name) { this.name = name; }` 中，`this.name` 是字段，`name` 是参数。this 也用于链式调用：`builder.SetX(1).SetY(2)` 中每个方法返回 `this`。扩展方法的第一个参数用 `this` 修饰，让静态方法看起来像实例方法。
  </Step>
</Stepper>

## 代码对照

```csharp
public class Employee
{
    // 自动属性
    public string Name { get; set; }

    // 带验证的属性
    private decimal _salary;
    public decimal Salary
    {
        get => _salary;
        set => _salary = value < 0 ? 0 : value;
    }

    // 只读属性 + init
    public int Id { get; }
    public string Dept { get; init; }

    // 静态字段——实例计数器
    private static int _count = 0;

    // 构造函数链
    public Employee(string name, decimal salary)
    {
        Name = name;
        Salary = salary;
        Id = ++_count;  // this.Id 由静态计数器分配
    }
    public Employee(string name) : this(name, 3000) { }

    // 实例方法
    public void Raise(decimal pct) => Salary *= (1 + pct);

    // 静态方法
    public static int TotalCount => _count;
}

// 使用
var emp = new Employee("Alice", 5000) { Dept = "Eng" };
emp.Raise(0.1m);
Console.WriteLine($"{emp.Name}: {emp.Salary}");
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 字段写成 public，外部直接修改跳过验证逻辑。<strong>原因 →</strong> 图方便把字段公开，绕过了属性的验证保护。比如 `public int Age;` 允许外部设为负数。<strong>修法 →</strong> 字段一律 private，通过 public 属性暴露。需要验证时手写 get/set 访问器；不需验证时用自动属性 `{ get; set; }`。</Callout>

<Callout type="trap"><strong>现象 →</strong> 在静态方法中访问实例成员，编译报错。<strong>原因 →</strong> 静态方法不关联任何对象实例，没有 this 指针，无法访问属于对象的实例字段/属性/方法。<strong>修法 →</strong> 静态方法只能访问静态成员。需要访问实例成员时，把方法改为实例方法，或把对象作为参数传入。</Callout>

<Callout type="trap"><strong>现象 →</strong> 写了带参构造函数后 `new Employee()` 报错"没有无参构造函数"。<strong>原因 →</strong> 一旦手写了任何构造函数，编译器不再自动生成默认无参构造函数。<strong>修法 →</strong> 如果需要无参构造，显式写一个 `public Employee() { }` 或 `public Employee() : this("default", 0) { }`。</Callout>

## 小结与练习

<Exercises>
<Answer question="字段和属性有什么区别？为什么字段应该 private 而属性 public？">字段是原始数据存储，属性是字段的受控访问代理。字段 private 防止外部绕过验证直接篡改数据；属性 public 提供受控的 get/set 接口，可在 set 中加验证逻辑。自动属性 `{ get; set; }` 让编译器自动生成 private 后备字段。</Answer>
<Answer question="C# 7.0 的 init 访问器与 set 有什么区别？与只读属性 `{ get; }` 有什么区别？">init 只能在对象构造阶段（构造函数或对象初始化器）赋值，之后只读；set 任何时候都可写。`{ get; }` 只读属性只能在构造函数中赋值，不能用对象初始化器赋值；init 允许初始化器赋值，更灵活。</Answer>
<Answer question="静态成员和实例成员有什么区别？静态方法为什么不能访问实例成员？">静态成员属于类本身，所有实例共享，通过类名访问；实例成员属于对象，每个对象独立一份，通过对象引用访问。静态方法没有 this 指针（不关联任何对象），无法确定要访问哪个对象的实例成员。</Answer>
<Answer question="this 指针有哪些用途？举三个场景。">(1) 区分同名参数与字段：`this.name = name`。(2) 构造函数链：`public Employee(string n) : this(n, 0) {}`。(3) 链式调用返回自身：`return this` 让 `obj.SetX(1).SetY(2)` 连续调用。</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="字段（field）">类内部的数据存储，通常 private，直接表示对象状态。</GlossaryItem>
<GlossaryItem term="属性（property）">对字段的受控访问代理，提供 get/set 访问器，可在访问时加验证。自动属性省略后备字段。</GlossaryItem>
<GlossaryItem term="init 访问器">C# 7.0 引入，只能在构造阶段赋值的属性设置器，兼顾不可变性与初始化灵活性。</GlossaryItem>
<GlossaryItem term="静态成员（static）">属于类本身而非实例的成员，通过类名访问，所有实例共享。静态方法无 this，不能访问实例成员。</GlossaryItem>
<GlossaryItem term="构造函数">与类同名、对象创建时自动调用的特殊方法，负责初始化字段到合法状态。支持重载和链式调用。</GlossaryItem>
</Glossary>
