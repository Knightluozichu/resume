## 直觉引入

想象动物王国。所有动物都能"叫"——但狗叫"Woof"、猫叫"Meow"。基类 Animal 定义了"能叫"这个能力（虚方法 Speak），但具体怎么叫留给子类自己决定（override）。这就是多态：相同的调用 `animal.Speak()`，根据实际类型（Dog 还是 Cat）产生不同行为。

接口则像"资格证"。一个 Dog 不仅是 Animal（is-a 继承），还可以有"可移动"（IMovable）和"可比较"（IComparable）资格证（can-do 接口）。C# 的单继承让你只能有一个"父亲"（Animal），但可以持有多个"资格证"（接口）。这避免了多继承的菱形问题，同时保持了灵活性。

## 概念讲解

### 继承与多态

<Term def="派生类获得基类的所有成员（除构造函数），并可以添加或覆写成员。C# 只允许单继承（一个基类）。">继承</Term>

<Term def="基类用 virtual 声明可覆写方法，派生类用 override 提供自己的实现。运行时根据对象的实际类型（而非声明类型）调用对应版本。">运行时多态</Term>

```csharp
public abstract class Animal
{
    public string Name { get; set; }
    public abstract void Speak();  // 抽象方法：子类必须实现
}

public class Dog : Animal
{
    public override void Speak() => Console.WriteLine("Woof");
}
```

`virtual` 标记可覆写的方法（有默认实现），`abstract` 标记必须覆写的方法（无实现，类必须 abstract），`override` 在子类中覆写。`new` 关键字隐藏基类方法（不推荐，破坏多态）。

多态的核心：`Animal a = new Dog(); a.Speak();` 调用 Dog 的 Speak，而不是 Animal 的——因为运行时看实际类型。

### 接口

<Term def="定义一组方法、属性、事件的契约，不含实现（C# 8.0 前）。类可以实现多个接口，接口之间可以多继承。">接口（interface）</Term>

接口定义"能力"而非"是什么"。`IComparable` 定义"可比较"，`IEnumerable` 定义"可遍历"，`IDisposable` 定义"可释放"。一个类可以实现多个接口：

```csharp
public class Dog : Animal, IMovable, IComparable
{
    public override void Speak() => Console.WriteLine("Woof");
    public void Move() { /* 移动逻辑 */ }
    public int CompareTo(object obj) { /* 比较逻辑 */ }
}
```

### 抽象类 vs 接口

| 维度 | 抽象类 | 接口 |
|---|---|---|
| 继承数 | 单继承 | 多实现 |
| 成员 | 字段、属性、方法、构造函数 | 方法、属性（无字段） |
| 实现 | 可有具体实现 | 纯契约（C# 7.0） |
| 适用 | is-a 关系，共享代码 | can-do 关系，定义能力 |

选择原则：如果多个类型有共同的"是什么"关系和共享代码，用抽象类；如果只是定义"能做什么"的能力契约，用接口。

## 交互Demo

<Stepper>
  <Step title="第一步：virtual/override——多态的基础">
    <Ec7InheritanceInterfacesDiagram />

    基类用 `virtual` 声明可覆写方法（可选覆写），用 `abstract` 声明必须覆写方法（子类必须实现）。子类用 `override` 提供自己的实现。运行时多态：`Animal a = new Dog(); a.Speak();` 调用 Dog 版本，因为 CLR 根据对象的实际类型分派。如果子类用 `new` 而非 `override`，多态失效——`a.Speak()` 调用 Animal 版本。
  </Step>
  <Step title="第二步：接口多实现——can-do 能力组合">
    C# 单继承但接口多实现。Dog 继承 Animal（is-a），同时实现 IMovable（can-do 移动）和 IComparable（can-do 比较）。接口定义能力契约，不包含实现（C# 7.0）。接口让你在不破坏继承层次的前提下给类添加能力。接口之间也可以继承：`interface IComparable<T> : IComparable`。
  </Step>
  <Step title="第三步：抽象类 vs 接口——什么时候用哪个">
    抽象类适合 is-a 关系 + 共享代码：Animal 提供通用的 Name 属性和 Eat 方法，Dog/Cat 继承后只覆写 Speak。接口适合 can-do 能力：IMovable 定义 Move 能力，Dog 和 Car（不是 Animal）都可以实现。优先用接口定义能力，用抽象类共享实现——两者常组合使用。
  </Step>
  <Step title="第四步：多态的实际应用——统一处理不同类型">
    多态的价值在于"用基类/接口类型统一处理不同子类"。`List<Animal> zoo = new() { new Dog(), new Cat() }; foreach (var a in zoo) a.Speak();`——不需要 if-else 判断类型，多态自动分派。这是开闭原则的基础：加新动物只需加新子类，不改现有代码。
  </Step>
</Stepper>

## 代码对照

```csharp
// 抽象基类
public abstract class Animal
{
    public string Name { get; set; }
    public abstract void Speak();           // 子类必须实现
    public virtual void Eat() { /* 默认实现 */ }
}

// 接口
public interface IMovable { void Move(); }

// 派生类：继承 + 接口实现
public class Dog : Animal, IMovable
{
    public override void Speak() => Console.WriteLine("Woof");
    public void Move() => Console.WriteLine("Running");
}

public class Cat : Animal
{
    public override void Speak() => Console.WriteLine("Meow");
}

// 多态：统一处理
var zoo = new List<Animal> { new Dog { Name = "Rex" }, new Cat { Name = "Tom" } };
foreach (var animal in zoo)
{
    Console.Write($"{animal.Name}: ");
    animal.Speak();  // 运行时分派：Dog->Woof, Cat->Meow
}

// 接口多态
var movers = new List<IMovable> { new Dog() /*, new Car() */ };
foreach (var m in movers) m.Move();
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 子类用 `new` 而非 `override` 覆写方法，多态失效。<strong>原因 →</strong> `new` 是方法隐藏（shadowing），不参与多态分派。`Animal a = new Dog(); a.Speak();` 调用 Animal 版本而非 Dog 版本，因为 `new` 告诉编译器"这是一个不相关的新方法，只是恰好同名"。<strong>修法 →</strong> 基类方法标记 `virtual`，子类用 `override` 覆写。只有需要故意隐藏时才用 `new`（罕见），且要清楚多态不生效。</Callout>

<Callout type="trap"><strong>现象 →</strong> 滥用继承建深层层次，改基类牵一发动全身。<strong>原因 →</strong> 继承是最强的耦合（子类依赖基类实现细节）。层次越深，修改基类影响面越大。<strong>修法 →</strong> 优先用接口和组合替代继承。继承只用于真正的 is-a 关系且层次不超过 2-3 层。"组合优于继承"是面向对象设计的核心原则。</Callout>

<Callout type="trap"><strong>现象 →</strong> 把什么都定义成抽象类，接口不用。<strong>原因 →</strong> 混淆抽象类和接口的定位。抽象类是 is-a + 共享实现，接口是 can-do 能力契约。<strong>修法 →</strong> 有共享代码和字段用抽象类；只定义能力契约用接口。C# 单继承意味着用了抽象类就不能再继承其他类，接口多实现更灵活。</Callout>

## 小结与练习

<Exercises>
<Answer question="virtual、abstract、override、new 四个关键字在继承中各自的作用？">virtual：基类声明可覆写方法（有默认实现）；abstract：基类声明必须覆写方法（无实现，类必须 abstract）；override：子类覆写 virtual/abstract 方法，参与多态分派；new：子类隐藏基类同名方法，不参与多态分派。</Answer>
<Answer question="抽象类和接口有什么区别？什么时候用抽象类，什么时候用接口？">抽象类：单继承，可含字段/构造函数/具体实现，适合 is-a + 共享代码。接口：多实现，只含方法/属性契约（C# 7.0），适合 can-do 能力。有共享实现用抽象类，只定义能力用接口，优先接口+组合。</Answer>
<Answer question="`Animal a = new Dog(); a.Speak();` 为什么调用 Dog 的 Speak 而不是 Animal 的？">运行时多态：CLR 根据对象的实际类型（Dog）而非声明类型（Animal）分派虚方法调用。Dog 用 override 覆写了 Speak，所以调用 Dog 版本。如果 Dog 用 new 而非 override，多态失效，调用 Animal 版本。</Answer>
<Answer question="如何用接口和组合替代深层继承？举例说明。">不建 Animal→Mammal→Dog→Puppy 层次，而是 Dog implements IMovable, IComparable, IBarkable。Dog 内部组合其他对象（如含一个 Legs 组件）。接口定义能力，组合复用实现，避免继承的强耦合。修改一个接口实现不影响其他能力。</Answer>
</Exercises>

## 名词解释

<Glossary>
<GlossaryItem term="运行时多态">基类用 virtual/abstract 声明可覆写方法，子类用 override 提供实现。CLR 运行时根据对象实际类型分派调用。</GlossaryItem>
<GlossaryItem term="接口（interface）">定义方法/属性/事件的契约（不含实现），类可实现多个接口。接口定义 can-do 能力，可多继承。</GlossaryItem>
<GlossaryItem term="抽象类（abstract class）">不能实例化的基类，可含抽象方法（无实现）和具体方法。用于 is-a 关系和共享代码。C# 单继承。</GlossaryItem>
<GlossaryItem term="is-a 与 can-do">继承表达 is-a（是什么）关系，接口表达 can-do（能做什么）能力。C# 用单继承管 is-a，用接口多实现管 can-do。</GlossaryItem>
<GlossaryItem term="方法隐藏（new）">子类用 new 声明与基类同名的方法，不参与多态分派。与 override 不同，new 不覆写而是隐藏。</GlossaryItem>
</Glossary>
