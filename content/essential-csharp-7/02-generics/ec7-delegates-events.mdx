## 直觉引入

想象一个微信群。群主（发布者）发了一条消息，所有群成员（订阅者）都收到通知。群成员可以自由加入（+=）和退出（-=），但群外人不能冒充群主发消息（只有发布者能触发事件）。

委托就是这个通知机制的"通信协议"——它定义了"收到消息后该做什么"的方法签名。事件是委托的"安全封装"——外部只能订阅/取消订阅（+=/-=），不能直接触发。Lambda 表达式是委托的"快捷写法"——不需要单独定义方法，直接写 `x => x * 2` 就能创建一个委托实例。

## 概念讲解

### 委托

<Term def="类型安全的函数指针，定义方法签名（参数类型 + 返回类型）。委托实例可以持有匹配签名的方法，并像调用普通方法一样调用它。">委托（delegate）</Term>

```csharp
// 定义委托类型
public delegate void Handler(string message);

// 匹配签名的方法
void LogToConsole(string msg) => Console.WriteLine(msg);
void LogToFile(string msg) => File.AppendAllText("log.txt", msg);

// 委托实例持有方法
Handler h = LogToConsole;
h("hello");  // 调用 LogToConsole
```

委托是类型安全的——方法签名必须完全匹配委托定义。C# 的委托本质上是一个继承自 `System.MulticastDelegate` 的类。

### 多播委托

<Term def="一个委托实例通过 += 持有多个方法引用，调用时按注册顺序依次执行所有方法。">多播委托</Term>

```csharp
Handler h = LogToConsole;
h += LogToFile;    // 添加第二个方法
h("hello");        // 先调用 LogToConsole，再调用 LogToFile
```

多播委托内部维护一个调用列表（invocation list），`+=` 添加方法，`-=` 移除方法。调用时按顺序执行所有方法。注意：如果某个方法抛异常，后续方法不执行。

### event 关键字

<Term def="用 event 修饰的委托字段，外部只能 += / -= 订阅和取消，不能直接赋值或触发。只有声明类内部可以触发。">事件（event）</Term>

```csharp
public class Publisher
{
    public event Handler OnMessage;  // 事件

    public void Send(string msg)
    {
        OnMessage?.Invoke(msg);  // 只有 Publisher 内部能触发
    }
}

// 外部
var pub = new Publisher();
pub.OnMessage += LogToConsole;  // 合法：订阅
// pub.OnMessage("hi");         // 编译错误：外部不能触发
// pub.OnMessage = null;        // 编译错误：外部不能赋值
```

`event` 封装了委托，只暴露 `+=` 和 `-=` 给外部。这实现了发布-订阅模式的核心安全约束：订阅者只能订阅/取消，不能干扰其他订阅者或冒充发布者触发。

### Func/Action 与 Lambda

C# 内置了两组泛型委托，省去自定义委托类型：

- `Action<T>` — 无返回值的方法（void）。`Action<string>` 等价于上面的 `Handler`。
- `Func<T, TResult>` — 有返回值的方法。`Func<int, int>` 表示 `int -> int` 的函数。

<Term def="简洁的匿名方法语法。`x => x * 2` 创建一个输入 x 返回 x*2 的委托实例。">Lambda 表达式</Term>

```csharp
// Lambda 创建委托实例
Func<int, int> double = x => x * 2;
Action<string> log = msg => Console.WriteLine(msg);

// 常用于 LINQ
var evens = numbers.Where(n => n % 2 == 0);
```

## 交互Demo

<Stepper>
  <Step title="第一步：委托——类型安全的函数指针">
    <Ec7DelegatesEventsDiagram />

    委托定义方法签名，委托实例持有匹配的方法。`Handler h = LogToConsole;` 让 h 指向 LogToConsole 方法，`h("msg")` 调用它。委托是类型安全的——签名不匹配编译报错。委托可以把方法当参数传递（回调模式），这是函数式编程的基础。
  </Step>
  <Step title="第二步：多播委托——一对多通知">
    `h += LogToFile` 让 h 持有两个方法。调用 `h("msg")` 时按注册顺序依次执行两个方法。多播委托是发布-订阅的基础——一个事件触发多个处理者。注意：如果中间方法抛异常，后续方法不执行。解决方案：用 `GetInvocationList()` 逐个调用并 try-catch。
  </Step>
  <Step title="第三步：event——安全封装委托">
    `event` 修饰的委托字段只允许外部 `+=` / `-=`，不允许赋值或触发。这防止了：订阅者覆盖其他订阅者（`pub.OnMessage = null` 会清空所有订阅）、订阅者冒充发布者触发。只有声明类内部能 `OnMessage?.Invoke()`。`?.` 空条件运算符防止无订阅者时 NullReferenceException。
  </Step>
  <Step title="第四步：Func/Action + Lambda——委托的现代写法">
    `Func<int, bool> isEven = x => x % 2 == 0;` 一行定义委托实例，无需自定义委托类型。Lambda 是 LINQ 的基石——`Where(n => n > 0)` 中的 `n => n > 0` 就是 `Func<int, bool>` 委托。Action 用于无返回值的回调（如事件处理器），Func 用于有返回值的变换（如 LINQ 投影）。
  </Step>
</Stepper>

## 代码对照

```csharp
// 自定义委托
public delegate void PriceChangedHandler(decimal oldPrice, decimal newPrice);

public class Stock
{
    public string Symbol { get; }
    private decimal _price;
    public event PriceChangedHandler PriceChanged;

    public decimal Price
    {
        get => _price;
        set
        {
            if (_price != value)
            {
                var old = _price;
                _price = value;
                PriceChanged?.Invoke(old, value);  // 触发事件
            }
        }
    }

    public Stock(string symbol, decimal price)
    {
        Symbol = symbol;
        _price = price;
    }
}

// 订阅
var stock = new Stock("AAPL", 150m);
stock.PriceChanged += (old, neu) =>
    Console.WriteLine($"{stock.Symbol}: {old} -> {neu}");
stock.Price = 155m;  // 输出: AAPL: 150 -> 155

// Func / Action
Func<int, int> square = x => x * x;
Action<string> log = msg => Console.WriteLine($"[LOG] {msg}");

var nums = new List<int> { 1, 2, 3, 4, 5 };
var squared = nums.Select(square);        // {1,4,9,16,25}
var evens = nums.Where(n => n % 2 == 0);  // {2,4}
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 多播委托中一个处理器抛异常，后续处理器不执行。<strong>原因 →</strong> 多播委托按顺序调用，一旦某个方法抛异常，调用链中断。<strong>修法 →</strong> 用 `GetInvocationList()` 获取调用列表，逐个 try-catch 调用，确保所有处理器都能执行。或使用事件时在每个处理器内部 try-catch。</Callout>

<Callout type="trap"><strong>现象 →</strong> 订阅者忘记取消订阅（-=），导致内存泄漏——发布者持有订阅者引用，订阅者无法被 GC 回收。<strong>原因 →</strong> 事件是多播委托，发布者通过事件持有订阅者方法的引用（而方法又关联着订阅者对象）。只要发布者活着，订阅者就不会被 GC。<strong>修法 →</strong> 订阅者在 Dispose 或反注册时 -= 取消订阅。或用弱引用事件模式。</Callout>

<Callout type="trap"><strong>现象 →</strong> 用普通委托字段（不加 event）暴露给外部，被外部覆盖了所有订阅者。<strong>原因 →</strong> 普通委托字段外部可以 `=` 赋值（覆盖），而 event 只允许 `+=` / `-=`。<strong>修法 →</strong> 发布-订阅模式一律用 event 修饰，防止外部覆盖订阅列表。普通委托字段用于回调（一对一），event 用于事件（一对多）。</Callout>

<Exercises>
<Answer question="委托的本质是什么？它与函数指针（C/C++）有什么区别？">委托是类型安全的函数指针，本质是继承自 MulticastDelegate 的类。与 C/C++ 函数指针的区别：(1) 类型安全——签名必须匹配，编译期检查；(2) 支持多播——一个委托实例持有多个方法；(3) 可持有实例方法+对象引用（不只是静态方法）。</Answer>
<Answer question="event 修饰的委托与普通委托字段有什么区别？为什么发布-订阅模式必须用 event？">普通委托字段：外部可赋值（= 覆盖）、可触发（Invoke）。event 修饰的委托：外部只能 += / -=（订阅/取消），不能赋值或触发，只有声明类内部能触发。必须用 event 因为：(1) 防止订阅者覆盖其他订阅者；(2) 防止外部冒充发布者触发；(3) 封装触发权限。</Answer>
<Answer question="Func 和 Action 各自的签名是什么？写出 `Func<int, string>` 和 `Action<int>` 的含义。">Func&lt;T, TResult&gt; 表示接受 T 返回 TResult 的方法。Action&lt;T&gt; 表示接受 T 无返回值（void）的方法。`Func&lt;int, string&gt;`：接受 int 返回 string 的函数。`Action&lt;int&gt;`：接受 int 无返回值的动作。</Answer>
<Answer question="多播委托中一个处理器抛异常会怎样？如何确保所有处理器都能执行？">多播委托按注册顺序依次调用，一旦某个处理器抛异常，调用链中断，后续处理器不执行。确保全部执行的方法：用 `GetInvocationList()` 获取调用列表，逐个 try-catch 调用每个处理器，记录异常但不中断循环。</Answer>
</Exercises>
