## 直觉引入

想象一个快递柜。如果没有泛型，你只能造一个"object 柜"——什么都能放，但取出时不知道里面是书还是食品，得拆开看（类型不安全），而且放进去的值类型（如苹果）还要先打包成 object（装箱，浪费空间和时间）。

有了泛型，你可以造 `Locker<苹果>` 和 `Locker<书>`——苹果柜只能放苹果，书柜只能放书，类型在编译期就确定了，放错东西编译器直接报错。而且苹果柜的内部就是苹果架，不需要打包（无装箱）。这就是泛型的两个核心价值：**类型安全**和**消除装箱**。

## 概念讲解

### 泛型类与方法

<Term def="用类型参数 T 占位，定义一份代码适用于多种类型。实例化时用具体类型替换 T，编译器生成类型安全的专用版本。">泛型</Term>

```csharp
public class Stack<T>
{
    private T[] _items = new T[0];
    public void Push(T item) { /* ... */ }
    public T Pop() { /* ... */ }
}

var intStack = new Stack<int>();      // T = int
var strStack = new Stack<string>();   // T = string
```

`Stack<int>` 和 `Stack<string>` 是两个完全不同的类型，编译器为每种类型参数生成专用代码（JIT 阶段）。值类型泛型（如 `Stack<int>`）内部直接用 `int[]` 存储，无装箱开销。

泛型方法类似：`T Find<T>(T[] array, Func<T, bool> predicate)` 可以在任意类型数组中查找。

### 泛型约束（where 子句）

<Term def="用 where 子句限制类型参数 T 必须满足的条件，使泛型代码能在 T 上调用特定成员。">泛型约束</Term>

不加约束时，编译器不知道 T 是什么类型，只能当 object 用——不能调用任何特定方法。约束让编译器知道 T 的能力：

```csharp
// T 必须实现 IComparable<T>，才能调用 CompareTo
public T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;

// T 必须有无参构造函数，才能 new T()
public T Create<T>() where T : new()
    => new T();
```

五种约束：
- `where T : class` — T 必须是引用类型
- `where T : struct` — T 必须是值类型（非 Nullable）
- `where T : new()` — T 必须有无参公共构造函数
- `where T : IComparable` — T 必须实现指定接口
- `where T : Animal` — T 必须是指定基类或其派生类

### 协变与逆变

<Term def="协变 out 允许把派生类型泛型赋给基类型泛型（如 IEnumerable<Derived> 赋给 IEnumerable<Base>）；逆变 in 允许反向赋值。">协变与逆变</Term>

```csharp
// 协变：out 参数——只能输出，不能输入
IEnumerable<Dog> dogs = new List<Dog>();
IEnumerable<Animal> animals = dogs;  // 合法，因为 IEnumerable<out T>

// 逆变：in 参数——只能输入，不能输出
Action<Animal> animalAction = a => a.Eat();
Action<Dog> dogAction = animalAction;  // 合法，因为 Action<in T>
```

协变 out：T 只出现在返回值位置（输出），所以 `IEnumerable<Dog>` 可以安全地当 `IEnumerable<Animal>` 用。逆变 in：T 只出现在参数位置（输入），所以 `Action<Animal>` 可以安全地当 `Action<Dog>` 用（能处理 Animal 的函数当然能处理 Dog）。

## 交互Demo

<Stepper>
  <Step title="第一步：类型参数化——一份代码多种类型">
    <Ec7GenericsDiagram />

    `Stack<T>` 用 T 做占位符定义一份代码。`new Stack<int>()` 时 T=int，`new Stack<string>()` 时 T=string。编译器为每种值类型生成专用代码（int 栈内部是 int[]，无装箱）；引用类型共享一份代码。对比非泛型 Stack（用 object 存储），泛型版本类型安全（不会存错类型）且无装箱开销。
  </Step>
  <Step title="第二步：where 约束——告诉编译器 T 的能力">
    不加约束，T 只能当 object 用——不能调用任何方法。`where T : IComparable<T>` 让编译器知道 T 有 CompareTo 方法，泛型代码可以调用它。`where T : new()` 让编译器知道 T 可以 new。`where T : class` 限制 T 为引用类型（不能用 int 实例化）。约束让泛型从"什么都能放"变成"有特定能力的才能放"。
  </Step>
  <Step title="第三步：协变 out——安全地 widening">
    协变让 `IEnumerable<Dog>` 赋给 `IEnumerable<Animal>`。安全的原因：IEnumerable 只输出 T（GetEnumerator 返回 T），不输入 T。把 Dog 当 Animal 输出是安全的（Dog is-a Animal）。但 `List<Dog>` 不能赋给 `List<Animal>`——因为 List 既有 Add(T) 输入又有 T 索引输出，双向不安全。
  </Step>
  <Step title="第四步：逆变 in——安全地 narrowing">
    逆变让 `Action<Animal>` 赋给 `Action<Dog>`。安全的原因：Action 只输入 T（调用时传参），不输出 T。能把 Animal 当参数处理的函数，当然能处理 Dog（Dog is-a Animal，传进去的 Dog 一定能被当 Animal 处理）。逆变常用于回调/事件处理器的类型兼容。
  </Step>
</Stepper>

## 代码对照

```csharp
// 泛型类
public class Stack<T>
{
    private T[] _items = new T[16];
    private int _count = 0;

    public void Push(T item) => _items[_count++] = item;
    public T Pop() => _items[--_count];
    public int Count => _count;
}

// 泛型方法 + 约束
public T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;

// 使用
var s1 = new Stack<int>();     // 无装箱
s1.Push(42);
int x = s1.Pop();              // 类型安全，无需强转

var s2 = new Stack<string>();
s2.Push("hello");

Console.WriteLine(Max(3, 7));           // 7
Console.WriteLine(Max("apple", "banana")); // banana

// 协变
IEnumerable<Animal> animals = new List<Dog>();

// 逆变
Action<Animal> feeder = a => a.Eat();
Action<Dog> dogFeeder = feeder;
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> `List<Dog> dogs = new List<Dog>(); List<Animal> animals = dogs;` 编译报错。<strong>原因 →</strong> List&lt;T&gt; 的 T 是不变（invariant）的——既有 Add(T) 输入又有 T 输出。如果允许这个赋值，`animals.Add(new Cat())` 就把 Cat 塞进了 Dog 列表，类型不安全。<strong>修法 →</strong> 用 `IEnumerable<Animal> animals = dogs;`（协变，只读安全），或用 `dogs.Cast<Animal>().ToList()` 创建新列表。</Callout>

<Callout type="trap"><strong>现象 →</strong> 泛型方法不加约束就调用 T 的方法，编译报错"T 不包含方法 X"。<strong>原因 →</strong> 不加约束时编译器只把 T 当 object，不知道 T 有哪些方法。<strong>修法 →</strong> 加 `where T : IComparable<T>` 等约束，让编译器知道 T 的能力。或用 dynamic（不推荐，丧失类型安全）。</Callout>

<Callout type="trap"><strong>现象 →</strong> `where T : new()` 约束下 `new T()` 比直接 new 慢。<strong>原因 →</strong> `new T()` 在泛型中通过反射调用构造函数，有额外开销（虽然编译器有一定优化）。<strong>修法 →</strong> 性能敏感场景可用工厂函数 `Func<T>` 代替 `new()` 约束，或用 `Activator.CreateInstance<T>()` 缓存优化。</Callout>

## 小结与练习

<Exercises>
<Answer question="泛型相比非泛型（用 object 存储）有什么两大核心优势？">(1) 类型安全：编译期检查类型，不会把 string 存进 int 栈，取值无需强转。(2) 消除装箱：值类型泛型（如 Stack&lt;int&gt;）内部直接用 int[] 存值，不需要装箱成 object，无堆分配和 GC 压力。</Answer>
<Answer question="泛型约束有哪五种？各限制 T 是什么？">(1) where T : class — 引用类型；(2) where T : struct — 值类型（非 Nullable）；(3) where T : new() — 有无参公共构造函数；(4) where T : IComparable — 实现指定接口；(5) where T : Animal — 是指定基类或派生类。</Answer>
<Answer question="为什么 `List<Dog>` 不能赋给 `List<Animal>`，但 `IEnumerable<Dog>` 可以赋给 `IEnumerable<Animal>`？">List&lt;T&gt; 的 T 是 invariant（双向：Add(T) 输入 + T 索引输出），允许赋值会导致 Add(Cat) 进 Dog 列表。IEnumerable&lt;out T&gt; 协变（只输出 T 不输入），把 Dog 当 Animal 输出安全。协变要求 T 只出现在输出位置。</Answer>
<Answer question="协变 out 和逆变 in 各自的安全逻辑是什么？">协变 out：T 只输出不输入，派生类型泛型可赋给基类型泛型（IEnumerable&lt;Dog&gt; → IEnumerable&lt;Animal&gt;），因为输出 Dog 当 Animal 用安全。逆变 in：T 只输入不输出，基类型泛型可赋给派生类型泛型（Action&lt;Animal&gt; → Action&lt;Dog&gt;），因为处理 Animal 的函数能处理 Dog。</Answer>
</Exercises>

## 名词解释

<Glossary>
<GlossaryItem term="泛型">用类型参数 T 占位定义一份代码，实例化时用具体类型替换，编译器生成类型安全且无装箱的专用版本。</GlossaryItem>
<GlossaryItem term="泛型约束（where）">限制类型参数 T 必须满足的条件（class/struct/new()/接口/基类），使泛型代码能在 T 上调用特定成员。</GlossaryItem>
<GlossaryItem term="协变（out）">T 只出现在输出位置，允许把派生类型泛型赋给基类型泛型。如 IEnumerable&lt;Dog&gt; → IEnumerable&lt;Animal&gt;。</GlossaryItem>
<GlossaryItem term="逆变（in）">T 只出现在输入位置，允许把基类型泛型赋给派生类型泛型。如 Action&lt;Animal&gt; → Action&lt;Dog&gt;。</GlossaryItem>
<GlossaryItem term="invariant（不变）">T 同时出现在输入和输出位置（如 List&lt;T&gt;），不允许协变也不允许逆变，类型参数严格匹配。</GlossaryItem>
</Glossary>
