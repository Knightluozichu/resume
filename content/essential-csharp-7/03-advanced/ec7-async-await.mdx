## 直觉引入

想象你去餐厅点餐。同步模式：你站在取餐口等，什么也不做，直到餐好了才离开——你的时间被完全浪费。异步模式：你拿到一个取餐号（Task），回座位看手机（线程释放去做别的事），餐好了服务员叫号（回调恢复），你再去取——你等餐的时间被利用了。

async/await 就是这个"取餐号"机制。`await httpClient.GetStringAsync(url)` 发出请求后，当前线程不傻等，而是被释放去做其他工作（处理其他请求）。等 HTTP 响应到了，一个可用线程捡起"取餐号"继续执行 await 后面的代码。整个流程看起来像同步代码（一行接一行），但底层不阻塞线程。

## 概念讲解

### async/await 与状态机

<Term def="async 标记方法为异步方法，await 挂起等待而不阻塞线程。编译器把 async 方法编译成状态机，每个 await 是一个挂起点。">async/await</Term>

```csharp
public async Task<string> GetDataAsync()
{
    var data = await httpClient.GetStringAsync(url);  // 挂起点 1
    var result = await ProcessAsync(data);            // 挂起点 2
    return result.ToUpper();
}
```

编译器把这段代码编译成一个状态机类。每个 `await` 把方法分成若干状态：状态 0 是 await 之前的代码，状态 1 是第一个 await 恢复后的代码，以此类推。当 `await` 的 Task 未完成时，状态机保存当前状态（局部变量、执行位置）并返回；Task 完成后，调度器恢复状态机，从保存的位置继续执行。

关键点：`await` 不是"等待"——它是"挂起并释放线程"。当前线程不阻塞，可以去处理其他工作。Task 完成后，一个线程池线程（或捕获的同步上下文）恢复执行。

### Task 生命周期

<Term def="表示一个异步操作的句柄，代表"未来的结果"。Task 有 Created/WaitingForActivation/Running/RanToCompletion/Faulted/Canceled 等状态。">Task</Term>

- `Task` — 无返回值的异步操作
- `Task<T>` — 有返回值的异步操作，`T` 是结果类型
- `Task.CompletedTask` — 已完成的空 Task

Task 的核心状态：
- **RanToCompletion** — 成功完成
- **Faulted** — 抛出异常（异常存在 Task.Exception 属性中）
- **Canceled** — 被取消（CancellationToken 触发）

### async 方法的返回类型

- `Task<T>` — 最常用，返回 `T` 类型结果
- `Task` — 无返回值
- `void` — 仅用于事件处理器（async void），其余场景避免

### 异常处理

async 方法中的异常被捕获到返回的 Task 中。`await` 会重新抛出 Task 中的异常，可以用 try-catch 捕获：

```csharp
try
{
    var data = await httpClient.GetStringAsync(url);
}
catch (HttpRequestException ex)
{
    // await 重新抛出异常，这里捕获
}
```

## 交互Demo

<Stepper>
  <Step title="第一步：同步阻塞——线程空转浪费">
    <Ec7AsyncAwaitDiagram />

    同步方法 `string GetData() { return httpClient.GetString(url); }` 中，调用线程在等待 HTTP 响应期间被阻塞（线程空转），什么也做不了。如果这是服务器场景，每个请求占一个线程，线程池很快耗尽，吞吐量急剧下降。
  </Step>
  <Step title="第二步：async/await——挂起释放线程">
    `async Task<string> GetDataAsync() { return await httpClient.GetStringAsync(url); }` 中，await 发出请求后挂起状态机，释放当前线程。线程回到线程池处理其他请求。HTTP 响应到了，线程池分配一个线程恢复状态机，继续执行 await 后的代码。整个过程中没有线程被浪费在"等待"上。
  </Step>
  <Step title="第三步：编译器生成状态机">
    编译器把 async 方法编译成状态机类：每个 await 是一个状态切换点。状态机保存局部变量和执行位置。await 时调用 `GetAwaiter()` 检查 Task：已完成则同步继续，未完成则注册回调并返回（释放线程）。Task 完成后回调恢复状态机，从保存的位置继续。这就是"看起来像同步，实际是回调"的魔法。
  </Step>
  <Step title="第四步：异常与取消">
    async 方法中的异常被存入 Task，await 重新抛出供 try-catch 捕获。取消通过 CancellationToken 实现：传入 async 方法，调用 Cancel() 后 Task 变为 Canceled 状态，await 抛 OperationCanceledException。最佳实践：所有 async 方法接受可选的 CancellationToken 参数，支持协作式取消。
  </Step>
</Stepper>

## 代码对照

```csharp
// 异步方法
public async Task<string> FetchDataAsync(string url, CancellationToken ct)
{
    try
    {
        var response = await httpClient.GetAsync(url, ct);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadAsStringAsync();
    }
    catch (OperationCanceledException)
    {
        // 被取消
        return "cancelled";
    }
    catch (HttpRequestException ex)
    {
        // 网络错误
        return $"error: {ex.Message}";
    }
}

// 并行执行多个异步操作
public async Task<int> FetchAllAsync()
{
    var task1 = FetchDataAsync("https://api1.com");
    var task2 = FetchDataAsync("https://api2.com");
    string[] results = await Task.WhenAll(task1, task2);
    return results.Length;
}

// 调用
using var cts = new CancellationTokenSource();
cts.CancelAfter(TimeSpan.FromSeconds(5));
var data = await FetchDataAsync("https://example.com", cts.Token);
Console.WriteLine(data);
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 在 async 方法中用 `.Result` 或 `.Wait()` 等待 Task，导致死锁。<strong>原因 →</strong> UI/ASP.NET 有同步上下文（SynchronizationContext）。`.Result` 阻塞当前线程等待 Task，但 Task 的 continuation 需要在同步上下文上执行——而当前线程正被阻塞，形成死锁。<strong>修法 →</strong> 一律用 `await` 而非 `.Result`/`.Wait()`。整个调用链从底到顶都是 async（"async all the way"）。</Callout>

<Callout type="trap"><strong>现象 →</strong> `async void` 方法抛异常，程序崩溃。<strong>原因 →</strong> async void 的异常无法被调用方 try-catch 捕获（没有 Task 可以存异常），直接抛到 SynchronizationContext 导致崩溃。<strong>修法 →</strong> async void 仅用于事件处理器（EventHandler 签名要求 void）。其余场景返回 Task 或 `Task<T>`。</Callout>

<Callout type="trap"><strong>现象 →</strong> `async Task Foo() { }` 返回的 Task 永远不完成。<strong>原因 →</strong> 方法体内没有 await，编译器警告但编译通过。Task 实际已完成但调用方可能不知道。<strong>修法 →</strong> 确保 async 方法至少有一个 await，或显式 `return Task.CompletedTask`。编译器警告 CS1998 不要忽略。</Callout>
