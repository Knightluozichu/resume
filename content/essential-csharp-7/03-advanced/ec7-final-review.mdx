## 直觉引入

盖了十层楼，最后要站在楼顶往下看一眼——看看地基（类型系统）怎么支撑骨架（面向对象），骨架怎么挂上筋脉（泛型委托），筋脉怎么驱动智能系统（LINQ 与异步）。每一层都不是孤立的，下面一层的知识在上面一层中以新的形式反复出现。

比如"类型安全"这条主线：第 2 章的值类型/引用类型是基础，第 6 章的泛型约束 `where T : struct` 直接依赖它，第 8 章的 LINQ 延迟执行基于泛型 `IEnumerable&lt;T&gt;`，第 9 章的 `Task&lt;T&gt;` 也是泛型。一条线串下来，你会发现 C# 的每个高级特性都有坚实的基础支撑。

## 概念讲解

### 四大板块核心收束

**C# 基础**是所有后续章节的地基。值类型与引用类型的区别（栈 vs 堆、拷贝 vs 共享）贯穿全书——泛型 `where T : struct` 约束直接引用它，`List&lt;int&gt;` 无装箱的性能优势源于它，`string` 的不可变性也是它。运算符优先级和模式匹配 switch 是日常代码的基础工具，`?.` 和 `??` 在异步和 LINQ 代码中频繁出现。

**面向对象**把基础类型升级为自定义类型。类的封装（字段+属性+方法+构造函数）是所有 C# 代码的组织单元。继承与接口的多态（virtual/override/abstract）是 LINQ 的基础——`IEnumerable&lt;T&gt;` 是接口，`Where` 等算子是扩展方法。设计原则"组合优于继承"在泛型容器和委托事件中被反复体现。

**泛型与委托**是高级特性的语法基石。泛型提供类型参数化和约束，LINQ 完全构建在泛型 `IEnumerable&lt;T&gt;` 和泛型委托 `Func<T, bool>` 上。委托（Func/Action）是 LINQ 的 Lambda 参数类型，也是 async/await 的 continuation 回调机制。事件是发布-订阅模型，在 UI 编程和架构解耦中无处不在。

**高级特性**是 C# 的核心竞争力。LINQ 把集合查询抽象为统一管道，延迟执行让链式组合高效。async/await 把异步编程简化为看似同步的代码，状态机管理挂起与恢复。

## 代码对照

```csharp
// 全书知识综合：一个异步 LINQ 查询，涉及泛型、委托、接口
public async Task<List&lt;string>> GetTopActiveUsersAsync(
    IEnumerable<User> users, CancellationToken ct)
{
    // LINQ（第 8 章）：Where/OrderBy/Select 链式 + 延迟执行
    // Func<User, bool> / Func<User, int>（第 7 章）：Lambda 委托
    // IEnumerable<User>（第 6 章）：泛型接口
    var query = users
        .Where(u => u.IsActive)              // Func<User, bool>
        .OrderByDescending(u => u.Score)     // Func<User, int>
        .Select(u => u.Name);                // Func<User, string>

    // async/await（第 9 章）：异步不阻塞线程
    // ToList（第 8 章）：立即执行，缓存结果
    var result = await Task.Run(() => query.ToList(), ct);
    return result;
}

// 类与继承（第 4-5 章）：封装 + 多态
public abstract class User                  // 抽象基类
{
    public string Name { get; init; }       // init 只读设置器（第 4 章）
    public abstract bool IsActive { get; }  // abstract 必须覆写（第 5 章）
    public int Score { get; set; }
}

public class Member : User                  // 继承
{
    public override bool IsActive => Score > 0;  // override 多态
}
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 学完全书后仍然把各章节当独立知识点，看不到关联。<strong>原因 →</strong> 缺乏"类型安全主线"的全局视角——每个高级特性都有基础支撑。<strong>修法 →</strong> 回顾跨章关联图谱：类型系统 → 泛型约束 → LINQ 泛型容器 → Task 泛型异步；封装 → 委托封装方法 → event 封装委托；接口 → 泛型接口 → IEnumerable 驱动 LINQ。</Callout>

<Callout type="trap"><strong>现象 →</strong> 知道语法但不会综合运用，遇到实际问题不知从何下手。<strong>原因 →</strong> 缺乏综合练习——每个知识点单独练过，但没串联。<strong>修法 →</strong> 做综合练习：写一个异步 LINQ 查询（涉及泛型 IEnumerable、Func 委托、async/await、Task），把四段知识串起来用。</Callout>

## 小结与练习

<Exercises>
<Answer question="用&quot;类型安全主线&quot;串联全书的四个关键环节。">第 2 章值类型/引用类型（栈 vs 堆、拷贝 vs 共享）→ 第 6 章泛型约束 where T : struct/class（直接引用值/引用类型区分）→ 第 8 章 LINQ 基于 IEnumerable&lt;T&gt; 泛型枚举（类型安全查询）→ 第 9 章 Task&lt;T&gt; 泛型异步（类型安全的未来结果）。</Answer>
<Answer question="委托、Func/Action、Lambda、LINQ 之间是什么关系？">委托是类型安全的函数指针。Func/Action 是 C# 内置的泛型委托（省去自定义）。Lambda 是创建委托实例的简洁语法。LINQ 的 Where/Select 等算子接受 Func/Action 参数——传入的 Lambda 就是委托实例。从委托到 LINQ 是一条能力递进线。</Answer>
<Answer question="为什么说&quot;组合优于继承&quot;在 C# 中尤为重要？">C# 单继承限制了一个类只能有一个基类，深层继承层次耦合强且不灵活。接口多实现+组合提供了更灵活的复用方式：定义接口能力契约，内部组合其他对象实现具体逻辑。泛型和委托进一步支持组合——泛型容器组合任意类型，委托组合任意方法。</Answer>
<Answer question="综合题：写一个异步方法，从用户列表中筛选活跃用户、按分数降序取前 10 名，返回姓名列表。要求支持取消。">
```csharp
public async Task<List&lt;string>> GetTopUsersAsync(
    IEnumerable<User> users, CancellationToken ct)
{
    return await Task.Run(() => users
        .Where(u => u.IsActive)
        .OrderByDescending(u => u.Score)
        .Take(10)
        .Select(u => u.Name)
        .ToList(), ct);
}
```
综合运用：LINQ（Where/OrderByDescending/Take/Select/ToList）、Func 委托（Lambda 参数）、泛型（IEnumerable&lt;User&gt;/List&lt;string&gt;）、async/await（Task.Run 异步不阻塞）、CancellationToken（协作式取消）。
</Answer>
</Exercises>
