## 直觉引入

想象工厂流水线。原材料（数据源）经过一道道工序（算子）：先筛选合格品（Where），再按尺寸排序（OrderBy），最后贴标签（Select）。每道工序只管自己的事，串在一起就是完整的加工流程。

LINQ 就是集合处理的"流水线"。你不需要写 for 循环+if 判断+临时变量来手动筛选排序，而是一行链式调用搞定：`items.Where(x => x > 0).OrderBy(x => x).Select(x => x * 2)`。更巧妙的是，这些工序是"按需启动"的——你声明了流水线但不立刻开工，只有最终取货（枚举或 ToList）时才真正执行。这就是延迟执行。

## 概念讲解

### 两种语法

<Term def="类似 SQL 的声明式查询语法，用 from-where-orderby-select 关键字。编译后等价于方法语法。">查询语法（Query Syntax）</Term>

<Term def="用扩展方法和 Lambda 链式调用的语法。功能是查询语法的超集——某些算子（如 Sum、Take）只有方法语法。">方法语法（Fluent Syntax）</Term>

```csharp
// 查询语法
var result = from x in numbers
             where x > 2
             orderby x
             select x * 10;

// 方法语法（等价）
var result = numbers
    .Where(x => x > 2)
    .OrderBy(x => x)
    .Select(x => x * 10);
```

两种语法编译后完全等价。查询语法在多 from（SelectMany）和 join 时更易读；方法语法功能更全且链式更灵活。实际开发中方法语法更常用，因为所有标准查询算子都支持。

### 标准查询算子

LINQ 提供几十个标准查询算子，分几类：

- **过滤**：`Where`（条件过滤）、`OfType<T>`（类型过滤）
- **投影**：`Select`（一对一变换）、`SelectMany`（一对多展开）
- **排序**：`OrderBy`/`OrderByDescending`/`ThenBy`
- **分组**：`GroupBy`（按键分组）
- **聚合**：`Count`/`Sum`/`Average`/`Max`/`Min`
- **元素**：`First`/`FirstOrDefault`/`Single`/`ElementAt`
- **集合**：`Distinct`/`Union`/`Intersect`/`Except`
- **连接**：`Join`/`GroupJoin`

### 延迟执行与立即执行

<Term def="查询在声明时不执行，只有枚举（foreach/ToList/ToArray）时才求值。Where/OrderBy/Select 等返回 IEnumerable 的算子是延迟的。">延迟执行</Term>

<Term def="查询在调用时立即求值并返回结果。ToList/Count/First/Sum 等返回具体值或集合的算子是立即的。">立即执行</Term>

```csharp
var query = numbers.Where(x => x > 2);  // 延迟：不执行
var list = query.ToList();              // 立即：执行查询
var count = query.Count();              // 立即：执行查询
```

延迟执行的核心是迭代器（yield return）。`Where` 返回的是一个迭代器对象，每次 `MoveNext()` 才计算下一个元素。延迟执行的好处：可以链式组合多个算子而不产生中间集合；可以多次枚举同一查询（数据源变化时结果不同）。陷阱：多次枚举会重复执行查询——如果数据源是数据库或昂贵计算，应 ToList 缓存结果。

## 交互Demo

<Stepper>
  <Step title="第一步：流水线构建——声明而不执行">
    <Ec7LinqDiagram />

    `var q = numbers.Where(x => x > 2).OrderBy(x => x).Select(x => x * 10);` 这行代码只是构建了查询管道，并不执行。Where 返回迭代器，OrderBy 包装迭代器，Select 再包装。整个管道像一个"待执行计划"，等待枚举触发。此时 numbers 还是原始数据 `[3,1,4,1,5,9,2,6]`。
  </Step>
  <Step title="第二步：枚举触发——按需计算">
    `foreach (var x in q)` 触发执行。迭代器逐个产出元素：Where 过滤出 3,4,5,9,6 → OrderBy 排序成 3,4,5,6,9 → Select 变换成 30,40,50,60,90。整个管道在单次遍历中完成，不产生中间集合。每个元素经过完整管道后才取下一个——这是流式处理。
  </Step>
  <Step title="第三步：立即执行算子——触发求值">
    `q.ToList()` 或 `q.Count()` 是立即执行——它们必须遍历整个管道才能收集结果或计数。ToList 产生一个 List 缓存结果，后续操作直接用缓存，不重复执行查询。这就是"缓存查询结果"的标准做法。
  </Step>
  <Step title="第四步：延迟执行的陷阱——多次枚举">
    延迟执行意味着每次 foreach 都重新执行查询。如果 numbers 变了，结果也变。如果数据源是 EF Core 的 DbSet，每次枚举都发一次 SQL 查询！解决方案：如果需要稳定结果或避免重复计算，用 `.ToList()` 缓存。如果要反映最新数据，保持延迟执行。
  </Step>
</Stepper>

## 代码对照

```csharp
var students = new List<Student>
{
    new("Alice", 85, "CS"),
    new("Bob", 72, "Math"),
    new("Carol", 90, "CS"),
    new("Dave", 65, "Math"),
};

// 过滤 + 排序 + 投影
var topCS = students
    .Where(s => s.Major == "CS")
    .OrderByDescending(s => s.Score)
    .Select(s => s.Name);

// 分组
var byMajor = students.GroupBy(s => s.Major);
foreach (var g in byMajor)
    Console.WriteLine($"{g.Key}: {g.Average(s => s.Score):F1}");

// 聚合
var avgScore = students.Average(s => s.Score);
var best = students.OrderByDescending(s => s.Score).First();

// 延迟执行陷阱
var query = students.Where(s => s.Score > 70);
students.Add(new("Eve", 95, "CS"));
// query 现在包含 Eve！因为延迟执行，枚举时才计算
var cached = query.ToList();  // 缓存，后续 students 变化不影响 cached

record Student(string Name, int Score, string Major);
```

## 常见误区

<Callout type="trap"><strong>现象 →</strong> 多次 foreach 同一个 query，每次都重新执行查询，性能差或数据库被多次查询。<strong>原因 →</strong> 延迟执行——每次枚举都从头执行管道。如果是 EF Core 查询，每次都发 SQL。<strong>修法 →</strong> 需要稳定结果或避免重复计算时，先 `.ToList()` 缓存。需要反映最新数据时保持延迟。</Callout>

<Callout type="trap"><strong>现象 →</strong> `query.First()` 在空集合上抛 InvalidOperationException。<strong>原因 →</strong> First 要求至少一个元素，空集合抛异常。<strong>修法 →</strong> 用 `FirstOrDefault()` 返回默认值（引用类型 null，值类型 default），然后用 `??` 或 `HasValue` 判断。Single 也有对应的 SingleOrDefault。</Callout>

<Callout type="trap"><strong>现象 →</strong> 在 foreach 中修改 query 的数据源，抛 InvalidOperationException。<strong>原因 →</strong> LINQ to Objects 在枚举时检测集合修改会抛异常（迭代器快速失败）。<strong>修法 →</strong> 先 `.ToList()` 创建快照再遍历修改，或用 for 循环倒序遍历。</Callout>

<Answer question="延迟执行有什么陷阱？如何避免？">陷阱：(1) 多次枚举重复执行查询（EF Core 每次发 SQL）；(2) 数据源变化导致结果变化；(3) 在 foreach 中修改数据源抛异常。避免：需要稳定结果时先 `.ToList()` 缓存；避免在枚举中修改数据源。</Answer>

var top3 = students

<Glossary>
<GlossaryItem term="查询语法（Query Syntax）">类似 SQL 的声明式 LINQ 语法，用 from-where-orderby-select 关键字。编译后等价于方法语法。</GlossaryItem>
<GlossaryItem term="方法语法（Fluent Syntax）">用扩展方法和 Lambda 链式调用的 LINQ 语法。功能是查询语法的超集。</GlossaryItem>
<GlossaryItem term="延迟执行">查询声明时不执行，枚举时才求值。基于迭代器（yield return）。好处：无中间集合、可多次枚举、流式处理。</GlossaryItem>
<GlossaryItem term="立即执行">查询调用时立即求值。ToList/Count/First/Sum 等返回具体值或集合的算子是立即执行。</GlossaryItem>
<GlossaryItem term="标准查询算子">LINQ 提供的几十个扩展方法，分过滤/投影/排序/分组/聚合/元素/集合/连接等类别。</GlossaryItem>
