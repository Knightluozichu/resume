## 为什么Late Binding必须集中在边界

普通C#调用由compiler验证member、arguments和return；reflection按metadata name查找，dynamic把lookup推迟到runtime。它们能支持serializer、DI container、plugin、COM/脚本互操作，却同时削弱rename safety、IDE navigation和compile-time proof。正确做法是把late binding放在小型adapter，尽快转换为typed contract。

先预测：`typeof(T)`与`obj.GetType()`分别得到什么；GetProperty找不到返回null还是throw；Activator缺少constructor怎样；MethodInfo.Invoke内层method抛异常如何呈现；nameof是否读取object；attribute是否主动执行；dynamic调用不存在member何时失败。随后逐层验证。

<Term def="从runtime type identity查找metadata member、验证目标/参数并执行create/read/write/invoke的晚绑定流程。">reflection pipeline</Term>

## Reflection: Obtaining Type Metadata

`typeof(KnownType)`在compile time引用type，`instance.GetType()`返回object exact runtime type，`Type.GetType(string)`按name解析且受assembly qualification/load context影响。generic/open/closed types仍保留第12章所述metadata identity。

```csharp
Type declared = typeof(Dictionary<,>);
object value = new Dictionary<string, int>();
Type runtime = value.GetType();

Console.WriteLine(runtime.GetGenericTypeDefinition() == declared); // True
```

string-based type name脆弱且可能加载不可信code；plugin系统应有assembly allowlist、signature/version和interface validation，不直接接受外部任意type name。

## MemberInfo and BindingFlags

Type可枚举/查找constructors、methods、properties、fields、events等MemberInfo。默认lookup的public/instance/static范围并不总符合需求；`BindingFlags`明确Public/NonPublic、Instance/Static、DeclaredOnly、IgnoreCase等。name、overloads和parameter types需一起消除ambiguity。

<Term def="按name、member kind、visibility、static/instance、inheritance与signature选择唯一metadata member的规则。">metadata lookup contract</Term>

```csharp
PropertyInfo property = typeof(Report).GetProperty(
    "Title",
    BindingFlags.Public | BindingFlags.Instance);

if (property == null || !property.CanRead)
    throw new InvalidOperationException("Report.Title is required");

object title = property.GetValue(report, null);
```

reflection APIs常返回null、empty array或抛AmbiguousMatchException；调用前验证member存在、read/write权限、target type和index parameters。频繁serialization/mapping应缓存已验证metadata或compiled accessors，而不是每item重复GetProperty。

## Activator and Reflective Invocation

`Activator.CreateInstance`按runtime Type创建object，常要求accessible matching constructor；generic overload可保留type。`MethodInfo.Invoke`接收target与object arguments，value types可能boxing，ref/out更新反映到arguments array。target method exception通常包在`TargetInvocationException.InnerException`中。

```csharp
Type type = ResolvePluginType();
if (!typeof(IPlugin).IsAssignableFrom(type) || type.IsAbstract)
    throw new InvalidOperationException("plugin must implement IPlugin");

var plugin = (IPlugin)Activator.CreateInstance(type);
plugin.Run(); // typed calls after one reflective boundary
```

不要让每个业务call都Invoke。一次discovery/create后cast到interface，恢复compile-time contract。private member reflection会耦合implementation并可能受platform/trimming限制，除诊断/tooling外应避免。

<Callout type="trap" title="reflection只是写法更长，语义和普通调用一样安全">
member可能不存在/歧义，arguments在runtime才验证，target exception被包装，name-based code也不随rename自动更新。必须建立显式validation与failure contract。
</Callout>

## nameof Is a Compile-Time Symbol Name

`nameof(expression-or-symbol)`产生compile-time string，适合argument exception、property notification、logging field name。它不执行expression、不会dereference null，并随symbol rename更新；结果通常是最后一个简单name而非完整qualified path。

<Term def="由compiler从symbol解析生成、无需执行表达式且可随rename更新的名称字符串。">symbol-name contract</Term>

```csharp
public void Load(string path)
{
    if (path == null)
        throw new ArgumentNullException(nameof(path));
}

string member = nameof(Report.Title); // "Title"
```

nameof不是runtime reflection，不能读取display name或attribute；对外protocol/database field name若需要稳定跨rename，不应直接依赖nameof，需显式schema constant。

## Attributes Annotate Metadata

custom attribute继承`Attribute`。positional arguments映射constructor parameters，named arguments设置public writable properties/fields；可用types受metadata constant表示限制。`AttributeUsage`声明有效targets、AllowMultiple和Inherited，compiler据此验证annotation。

<Term def="附着到assembly/type/member/parameter等target的声明式metadata，以及允许位置、重复和继承规则。">attribute metadata contract</Term>

```csharp
[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = true)]
public sealed class TableAttribute : Attribute
{
    public TableAttribute(string name) { Name = name; }
    public string Name { get; }
    public string Schema { get; set; }
}

[Table("orders", Schema = "sales")]
public sealed class Order { }
```

attribute不会自动创建table或执行validation；ORM/tool必须reflection读取并采取行为。读取attributes可能实例化attribute objects并执行constructor，纯metadata inspection可用相应metadata API降低side effects。不要把secret或高频mutable data放入attributes。

## Attribute Discovery and Versioning

attribute consumer应按known attribute type查询，验证required properties并定义missing/duplicate policy。改attribute constructor、remove property或rename type会影响compiled consumers/metadata；用于public tooling contract时需要versioning。

```csharp
TableAttribute table = typeof(Order)
    .GetCustomAttributes(typeof(TableAttribute), inherit: true)
    .Cast<TableAttribute>()
    .SingleOrDefault();

if (table == null) throw new InvalidOperationException("Table metadata required");
```

multiple attributes的order不应无文档依赖；inherit=true只按AttributeUsage和member/type rules工作，不表示metadata物理复制到derived declaration。

## dynamic Defers Binding

`dynamic` variable在metadata/CLR storage层常以object表示，但compiler把其operations标为runtime-bound。member access、operator、index、conversion和overload resolution在execution时根据runtime values由binder完成；成功result通常继续是dynamic，错误可向后传播多步。

<Term def="compiler接受operation并生成runtime binder site，由actual value types选择member/overload或抛binder exception的边界。">dynamic binding boundary</Term>

```csharp
dynamic value = GetValue();

try
{
    Console.WriteLine(value.ToUpper());
}
catch (Microsoft.CSharp.RuntimeBinder.RuntimeBinderException ex)
{
    Console.Error.WriteLine(ex.Message);
}
```

若value是string成功，int则runtime失败。dynamic不是reflection syntax sugar的完全同义词：binder应用C#-like overload/conversion规则并可与DynamicObject/COM交互，但两者都失去普通static proof。

## Choosing Static, Reflection, Attributes, or Dynamic

已知compile-time contract优先interface/generic/static calls；需要发现metadata或runtime-selected type用reflection；需要声明式annotation用attribute；与COM、dynamic language、shape-unstable payload边界可dynamic。四者不是风格互换，而是不同信息可用时机。

测试reflection要覆盖missing/ambiguous/nonpublic/constructor throw/target exception；attribute覆盖targets/multiple/inheritance/missing metadata；dynamic覆盖每个runtime shape、overload和binder failure。benchmark discovery cache与hot-path invocation，防止late binding进入inner loop。

## 本章回顾：发现、注解与绑定要有边界

1. reflection从Type到MemberInfo再create/invoke，lookup和target/argument failure必须显式验证。
2. BindingFlags与signature决定唯一member，hot path应缓存validated metadata/accessor。
3. nameof是compile-time rename-safe symbol string，不是reflection或stable external schema。
4. attribute只存declarative metadata，AttributeUsage控制target/multiple/inheritance，consumer执行行为。
5. dynamic把binding推迟到runtime，应集中在interop adapter并尽快恢复typed contract。

<Exercises>

**问题 1：如何安全加载配置指定的plugin type？**

<Answer>在允许assembly/load context中解析qualified type，验证非abstract且实现IPlugin、constructor可用，再Activator创建；捕获并区分resolution/constructor failure。创建后立即cast IPlugin，业务调用走typed interface。限制allowlist/signature并缓存validated descriptor，不接受任意外部type name。</Answer>

**问题 2：怎样设计可多次用于class的Tag attribute？**

<Answer>继承Attribute，以AttributeUsage(AttributeTargets.Class, AllowMultiple=true, Inherited按需求)声明policy；constructor参数保存required constant data，named writable properties保存optional metadata。consumer用GetCustomAttributes读取全部instances，不依赖返回顺序，并测试derived/missing/duplicate行为。</Answer>

**问题 3：何时可以使用dynamic，怎样防止错误扩散？**

<Answer>COM、dynamic language或shape不稳定外部payload边界可减少反射样板；每种runtime shape执行真实tests并处理RuntimeBinderException。adapter立即检查required members/conversions，转成typed DTO/interface后返回，内部不继续传播dynamic。已知contract仍用static/generic。</Answer>

</Exercises>
