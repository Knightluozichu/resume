## 直觉引入

Android系统像一个「分层蛋糕」。最底层的蛋糕胚是Linux内核（管理硬件驱动和进程），上面一层奶油是系统运行层（C/C++库和ART虚拟机，提供SQLite/OpenGL等能力），再上一层是应用框架层（ActivityManager/WindowManager等系统服务API），最顶层的草莓就是你的应用。开发者站在最顶层，通过框架层提供的API与系统交互，但理解底层结构有助于定位问题。

## Android四层架构

```text
┌──────────────────────────────────────┐
│  应用层（Applications）                 │  ← 你写的App
│  电话/短信/浏览器/你的App              │
├──────────────────────────────────────┤
│  应用框架层（Application Framework）   │  ← 开发者主要使用的API
│  ActivityManager / WindowManager      │
│  ContentProvider / View System        │
│  NotificationManager / PackageManager │
├──────────────────────────────────────┤
│  系统运行层                            │  ← 底层能力
│  Libraries: SQLite/OpenGL/Media       │
│  Android Runtime: ART虚拟机 + 核心库   │
├──────────────────────────────────────┤
│  Linux内核层                           │  ← 硬件抽象
│  驱动/电源管理/进程管理/内存管理        │
└──────────────────────────────────────┘
```

<Callout type="insight">
**开发者主要与框架层交互**：日常开发用的Activity、Service、View、Notification等都是框架层提供的API。但理解四层架构有助于定位问题——例如ANR是因为主线程阻塞（框架层的线程模型），内存泄漏是因为对象生命周期管理不当（运行层的GC机制），HAL问题是内核层的驱动异常。
</Callout>

## 项目目录结构

```text
MyApplication/
├── app/
│   ├── src/
│   │   └── main/
│   │       ├── java/com/example/app/     ← 源码目录
│   │       │   └── MainActivity.kt
│   │       ├── res/                      ← 资源目录
│   │       │   ├── layout/               ← 布局XML
│   │       │   │   └── activity_main.xml
│   │       │   ├── values/               ← 字符串/颜色/样式
│   │       │   │   ├── strings.xml
│   │       │   │   └── colors.xml
│   │       │   ├── drawable/             ← 图片/矢量图
│   │       │   └── mipmap/               ← 应用图标
│   │       └── AndroidManifest.xml       ← 清单文件
│   └── build.gradle                      ← 模块构建配置
├── build.gradle                          ← 项目构建配置
├── settings.gradle
└── gradlew                               ← Gradle Wrapper
```

## Gradle构建系统

```text
build.gradle (Module: app):
android {
    compileSdkVersion 34          // 编译用的SDK版本
    defaultConfig {
        applicationId "com.example.app"
        minSdkVersion 21          // 最低支持版本（Android 5.0）
        targetSdkVersion 34       // 目标版本（影响行为变更）
        versionCode 1
        versionName "1.0"
    }
}
dependencies {
    implementation "androidx.core:core-ktx:1.12.0"
    implementation "androidx.appcompat:appcompat:1.6.1"
    // 添加第三方依赖
}
```

<Callout type="trap">
**Gradle Wrapper的作用**：gradlew脚本和gradle-wrapper.properties锁定Gradle版本，确保团队所有人用相同版本构建。不要手动修改wrapper版本，用 `./gradlew wrapper --gradle-version=X.X` 命令升级。
</Callout>

## 日志工具与调试

```text
Log.v(tag, msg)  // Verbose  最详细
Log.d(tag, msg)  // Debug     调试信息（最常用）
Log.i(tag, msg)  // Info      重要信息
Log.w(tag, msg)  // Warning   警告
Log.e(tag, msg)  // Error     错误

// 最佳实践：类名作为tag
private static final String TAG = "MainActivity";
Log.d(TAG, "onCreate called")

// Logcat过滤
// tag:MainActivity     只看该tag的日志
// level:Debug          只看Debug及以上
```

## AndroidManifest清单文件

```text
<manifest package="com.example.app">
    <!-- 声明权限 -->
    <uses-permission android:name="android.permission.INTERNET" />

    <application
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.App">
        <!-- 注册Activity -->
        <activity android:name=".MainActivity">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
        <!-- 注册Service/Receiver/Provider... -->
    </application>
</manifest>
```

<Callout type="insight">
**AndroidManifest是系统了解应用的唯一入口**：四大组件必须在此注册（否则系统不识别，调用时崩溃），权限必须声明，应用级配置（图标/主题/Application类）在此设置。构建时打包进APK，安装时系统解析。
</Callout>

<Exercises>
**问题 1**：Android系统的四层架构是什么？每层各包含哪些核心组件？

<Answer>
Android四层架构从上到下：①应用层——所有用户安装的应用程序，由开发者用Java/Kotlin编写。②应用框架层——为应用层提供API，核心包括ActivityManager（管理Activity生命周期和任务栈）、WindowManager（管理窗口）、ContentProvider（数据共享）、View System（UI控件体系）、NotificationManager、PackageManager、ResourceManager。开发者主要与这层交互。③系统运行层——C/C++库（SQLite/OpenGL ES/Media Framework/WebKit）和Android运行时（Dalvik虚拟机→ART运行时，执行DEX字节码）。④Linux内核层——硬件驱动、电源管理、进程管理、内存管理、安全机制。
</Answer>

**问题 2**：Android项目的标准目录结构是什么？各目录的职责是什么？

<Answer>
app/src/main/是主源集。①java/com/example/app/——源码目录，存放Activity/Service/Fragment等类。②res/——资源目录：layout/布局XML、values/字符串颜色样式、drawable/图片、mipmap/图标。③AndroidManifest.xml——清单文件，注册四大组件、声明权限、配置应用元数据。④build.gradle——构建配置：compileSdkVersion/minSdkVersion/targetSdkVersion/dependencies。⑤gradlew——Gradle Wrapper锁定版本。资源通过R类引用：R.layout.activity_main、R.string.app_name。
</Answer>

**问题 3**：Android中的日志工具Log有哪几个级别？如何高效使用Logcat调试？

<Answer>
Log五个级别（从低到高）：Log.v()Verbose、Log.d()Debug（最常用）、Log.i()Info、Log.w()Warning、Log.e()Error。签名Log.d(String tag, String msg)，tag通常用类名便于过滤。Logcat调试：①tag:MainActivity过滤标签。②级别下拉框过滤。③关键字搜索。④进程过滤只看当前应用。最佳实践：①private static final String TAG = "ClassName"统一管理tag。②发布版本用BuildConfig.DEBUG判断是否输出日志。③日志包含上下文信息。④不要在循环中打大量日志。
</Answer>

**问题 4**：AndroidManifest.xml的作用是什么？必须注册哪些内容？

<Answer>
AndroidManifest.xml是应用清单文件，描述应用全局配置。必须注册：①包名——manifest的package属性。②四大组件——所有Activity/Service/BroadcastReceiver/ContentProvider必须声明，否则系统不识别调用时崩溃。③权限声明——<uses-permission>声明需要的系统权限。④应用配置——<application>标签配置icon/label/theme/name。⑤SDK版本——minSdkVersion/targetSdkVersion。⑥Intent过滤器——<intent-filter>声明组件能响应的隐式Intent。未注册的Activity调用startActivity会抛ActivityNotFoundException。
</Answer>

<Glossary>
<GlossaryItem term="四层架构">Android系统从上到下分为应用层、应用框架层、系统运行层（Libraries+Android Runtime）、Linux内核层。开发者主要与框架层API交互。</GlossaryItem>
<GlossaryItem term="AndroidManifest">应用清单文件，注册四大组件、声明权限、配置应用元数据。是系统了解应用的唯一入口，未注册的组件无法使用。</GlossaryItem>
<GlossaryItem term="Gradle">Android的构建系统，管理依赖、编译、打包。Gradle Wrapper锁定版本确保团队一致性。build.gradle配置SDK版本和依赖。</GlossaryItem>
<GlossaryItem term="R类">构建工具自动生成的资源引用类，通过R.layout.xxx/R.string.xxx/R.id.xxx在代码中引用资源。</GlossaryItem>
<GlossaryItem term="Logcat">Android日志查看工具，可按tag/级别/关键字/进程过滤日志。Log.d()是最常用的调试日志方法。</GlossaryItem>
</Glossary>
