## 直觉引入

UI布局像「房间装修」。LinearLayout是「沿墙一字排开」（水平或垂直排列）；RelativeLayout是「以某物为参照摆放」（A在B左边、C在D下方）；ConstraintLayout是「用弹簧连接两端」（约束关系，扁平不嵌套）；FrameLayout是「桌上叠盘子」（层叠堆放）。RecyclerView是「传送带工厂」——屏幕外的ViewHolder回收复用，只重新绑定数据，不重新创建视图，像流水线一样高效。

## 六大布局对比

```text
布局               布局方式              核心属性                    适用场景
──────────────────────────────────────────────────────────────────────────
LinearLayout      线性排列（水平/垂直）   orientation / weight       简单线性排列
RelativeLayout    相对定位              above/below/toLeftOf       灵活相对位置
ConstraintLayout  约束连接（推荐）        constraintXXX / Chain      扁平化减少嵌套
FrameLayout       层叠堆放              gravity / layout_gravity   Fragment容器
TableLayout       行列表格              TableRow / stretchColumns  规整表单
GridLayout        网格排列              rowCount / columnCount     网格布局
```

<Callout type="insight">
**为什么推荐ConstraintLayout**：ConstraintLayout通过约束关系实现扁平化布局，一个ConstraintLayout可替代多层嵌套的LinearLayout+RelativeLayout。减少View树层级 → 降低measure/layout遍历开销 → 提升渲染性能。Android Studio Layout Editor对ConstraintLayout有可视化拖拽支持。
</Callout>

## RecyclerView三件套

```text
RecyclerView = Adapter + LayoutManager + ViewHolder

工作流程：
  1. Adapter.onCreateViewHolder()  — 创建ViewHolder（inflate布局）
  2. Adapter.onBindViewHolder()    — 绑定数据到ViewHolder的控件
  3. LayoutManager                 — 决定item的排列方式和滚动方向
  4. ViewHolder复用                — 滑出屏幕的ViewHolder放入RecycledViewPool
                                     新item复用，只调onBind不重新inflate

三种LayoutManager：
  LinearLayoutManager       — 线性（水平/垂直）
  GridLayoutManager         — 网格
  StaggeredGridLayoutManager — 瀑布流

数据更新：
  adapter.notifyDataSetChanged()          — 全量刷新（粗暴）
  adapter.notifyItemInserted(position)    — 局部插入（推荐）
  adapter.notifyItemRemoved(position)     — 局部删除
  ListAdapter + DiffUtil                  — 自动计算差异，最优方案
```

<Callout type="trap">
**ListView vs RecyclerView**：ListView的convertView复用需手动实现ViewHolder（容易遗漏），性能差。RecyclerView将ViewHolder作为强制内置机制，且支持局部刷新（DiffUtil）和多种布局排列，是列表的标配方案。新项目一律用RecyclerView，不要用ListView。
</Callout>

## 自定义View流程

```text
1. 继承View，提供构造函数（Context + AttributeSet）
2. 自定义属性：res/values/attrs.xml → <declare-styleable>
3. 重写 onMeasure(widthMeasureSpec, heightMeasureSpec)
   — 解析MeasureSpec，计算View大小
   — 调用 setMeasuredDimension(w, h)
4. 重写 onDraw(Canvas canvas)
   — 用 Canvas + Paint 绘制内容
   — drawRect / drawCircle / drawText / drawPath
   — 注意：onDraw中不要创建对象（每次绘制都调用）
5. 重写 onTouchEvent(MotionEvent)
   — 处理 ACTION_DOWN / MOVE / UP
   — 返回true消费事件
6. （ViewGroup）重写 onLayout 定位子View
7. 性能优化：
   — invalidate()  触发重绘（主线程）
   — postInvalidate()  触发重绘（子线程安全）
   — 硬件加速默认开启
```

<Callout type="insight">
**onMeasure必须重写的原因**：如果不重写onMeasure，自定义View的wrap_content属性不生效（表现为match_parent效果）。因为默认实现只处理EXACTLY模式，wrap_content对应AT_MOST模式需手动计算内容大小并调setMeasuredDimension。
</Callout>

<Exercises>
**问题 1**：RecyclerView相比ListView有哪些核心优势？其三件套各自的作用是什么？

<Answer>
RecyclerView核心优势：①强制ViewHolder模式（ListView需手动实现容易遗漏）②布局灵活（LayoutManager切换排列方式）③细粒度刷新（notifyItemInserted等局部刷新+DiffUtil）④内置动画（ItemAnimator）⑤装饰器（ItemDecoration分隔线）。三件套作用：①Adapter——桥接数据与视图，创建ViewHolder和绑定数据。②LayoutManager——决定item布局排列和滚动方向。③ViewHolder——持有控件引用（findViewById只执行一次），避免滚动时重复查找。复用流程：滑出屏幕的ViewHolder放入RecycledViewPool，新item取复用只调onBindViewHolder。
</Answer>

**问题 2**：Android六大布局各自的特点和适用场景是什么？为什么推荐ConstraintLayout？

<Answer>
六大布局：①LinearLayout——线性排列，orientation指定方向，weight按比例分配。②RelativeLayout——相对定位，控件相对父容器或其他控件。③ConstraintLayout（推荐）——约束关系连接控件，支持链/比例/屏障，核心优势是扁平化减少嵌套层级降低measure/layout开销。④FrameLayout——层叠堆放，适合Fragment容器。⑤TableLayout——行列表格。⑥GridLayout——网格排列。选型：首选ConstraintLayout扁平化，简单线性用LinearLayout，Fragment容器用FrameLayout。
</Answer>

**问题 3**：如何实现一个自定义View？需要重写哪些方法？

<Answer>
自定义View步骤：①继承View提供构造函数。②自定义属性attrs.xml+TypedArray读取。③重写onMeasure解析MeasureSpec计算大小调setMeasuredDimension（不重写wrap_content不生效）。④重写onDraw用Canvas+Paint绘制内容（onDraw中不要创建对象）。⑤重写onTouchEvent处理触摸交互返回true消费事件。⑥ViewGroup需重写onLayout定位子View。⑦invalidate()触发重绘，postInvalidate()子线程安全。
</Answer>

**问题 4**：Android中常用的基本控件有哪些？各自的核心属性是什么？

<Answer>
常用控件：①TextView——text/textSize(sp)/textColor/maxLines/ellipsize。②EditText——hint/inputType(password/number/phone)/maxLength。③Button——text/onClick/background。④ImageView——src/scaleType(fitXY/centerCrop)/adjustViewBounds。⑤ProgressBar——max/progress/style。⑥AlertDialog——Builder构建setTitle/setMessage/setPositiveButton。⑦RecyclerView——列表展示。⑧ViewPager2——页面滑动。尺寸用dp、字体用sp、颜色在colors.xml定义。
</Answer>

<Glossary>
<GlossaryItem term="ConstraintLayout">约束布局（Android推荐），通过约束关系连接控件两端，支持链/比例/屏障。核心优势是扁平化——一个ConstraintLayout替代多层嵌套，减少View树层级提升性能。</GlossaryItem>
<GlossaryItem term="RecyclerView三件套">Adapter（数据↔视图桥接）、LayoutManager（排列方式和滚动方向）、ViewHolder（持有控件引用+复用）。滑出屏幕的ViewHolder放入池中复用，只调onBind不重新inflate。</GlossaryItem>
<GlossaryItem term="ViewHolder复用">RecyclerView核心性能优化。屏幕外的ViewHolder放入RecycledViewPool，新item进入时取复用，只调onBindViewHolder重新绑定数据，避免重复inflate布局XML的开销。</GlossaryItem>
<GlossaryItem term="自定义View">继承View重写onMeasure（测量大小）/onDraw（绘制内容）/onTouchEvent（触摸交互）。onMeasure不重写则wrap_content不生效，onDraw中不能创建对象（避免GC）。</GlossaryItem>
<GlossaryItem term="DiffUtil">RecyclerView的差异计算工具，自动对比新旧数据列表的差异，生成最优的局部更新操作（insert/remove/move/change），配合ListAdapter使用，替代手动notifyDataSetChanged。</GlossaryItem>
</Glossary>
