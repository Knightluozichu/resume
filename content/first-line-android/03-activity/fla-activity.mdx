## 直觉引入

Activity像「舞台上的演员」。登场前要化妆穿戏服（onCreate初始化），拉开幕布观众能看到但还不能互动（onStart可见），演员走到聚光灯下开始表演（onResume可交互）。突然有人递道具上来（onPause部分遮挡），幕布完全拉上观众看不到了（onStop不可见），演出结束卸妆离场（onDestroy销毁）。Fragment像「舞台上的场景道具」——它依附于舞台（Activity），有自己的生命周期（多了一层视图生命周期），可以通过导演（FragmentManager）切换场景（事务管理+回退栈）。

## Activity生命周期

```text
完整生命周期：

  onCreate()    ← Activity创建，初始化布局和控件（只调一次）
      ↓
  onStart()     ← 变为可见（但不可交互）
      ↓
  onResume()    ← 获得焦点，可交互（前台运行状态）
      ↓
    [运行中]
      ↓
  onPause()     ← 失去焦点（部分遮挡），释放CPU密集资源
      ↓
  onStop()      ← 完全不可见，释放较重资源
      ↓
  onDestroy()   ← 销毁，释放所有资源

从onStop回到前台：
  onRestart() → onStart() → onResume()

屏幕旋转（配置变更）：
  onPause → onStop → onDestroy → onCreate → onStart → onResume
  （整个Activity重建！数据需用ViewModel或onSaveInstanceState保存）
```

<Callout type="trap">
**屏幕旋转导致数据丢失**：旋转屏幕时Activity完整走销毁→重建流程，所有成员变量重置。解决方案：①ViewModel（推荐，跨配置变更存活）②onSaveInstanceState保存→onCreate/onRestoreInstanceState恢复（适合少量数据）③manifest锁定方向android:configChanges（不推荐，只是推迟问题）。
</Callout>

## 四大启动模式

```text
模式             行为                                  应用场景
──────────────────────────────────────────────────────────────────
standard         每次startActivity创建新实例入栈         普通页面（默认）
singleTop        栈顶有则复用（调onNewIntent），否则新建  推送详情页/新闻页
singleTask       栈内单例，清空上方Activity              应用首页/主界面
singleInstance   独占任务栈，全局唯一实例                系统级页面（来电界面）

配置方式：
  XML: <activity android:launchMode="singleTop" />
  代码: intent.addFlags(Intent.FLAG_ACTIVITY_SINGLE_TOP)
```

## Fragment生命周期与事务管理

```text
Fragment生命周期（比Activity多视图生命周期）：

  onAttach()        ← 绑定到Activity
      ↓
  onCreate()        ← 初始化（非视图）
      ↓
  onCreateView()    ← 创建视图（inflate布局）        ← Fragment独有
      ↓
  onViewCreated()   ← 视图创建完成                   ← Fragment独有
      ↓
  onActivityCreated() ← Activity的onCreate完成
      ↓
  onStart() → onResume() → [运行] → onPause() → onStop()
      ↓
  onDestroyView()   ← 视图销毁（Fragment实例仍在）   ← Fragment独有
      ↓
  onDestroy()       ← Fragment销毁
      ↓
  onDetach()        ← 与Activity解绑

Fragment事务管理：
  supportFragmentManager.beginTransaction()
      .replace(R.id.container, FragmentB())   // 替换
      .addToBackStack(null)                    // 加入回退栈
      .commit()                                // 提交（异步）

  // 回退栈：按back键弹出最近一次事务，恢复上一个Fragment
```

<Callout type="insight">
**Fragment视图生命周期**：Fragment多了onCreateView/onDestroyView，因为Fragment的视图可被销毁重建（如ViewPager预加载销毁）但Fragment实例仍存活。这意味着Fragment的字段数据在视图销毁后仍在，但控件引用需在onCreateView中重新获取。这也是ViewModel+ViewBinding在Fragment中需在onDestroyView清理控件引用的原因。
</Callout>

## Intent通信

```text
显式Intent（应用内跳转，指定类名）：
  val intent = Intent(this, TargetActivity::class.java)
  intent.putExtra("key", "value")
  startActivity(intent)

  // 目标Activity读取
  val value = intent.getStringExtra("key")

隐式Intent（跨应用，指定action）：
  val intent = Intent(Intent.ACTION_VIEW, Uri.parse("https://example.com"))
  startActivity(intent)  // 系统匹配能处理该action的App

等待返回结果：
  // 启动方
  startActivityForResult(intent, REQUEST_CODE)
  // 处理返回
  onActivityResult(requestCode, resultCode, data)

Fragment间通信：
  // 方式1：共享ViewModel（推荐）
  // 方式2：arguments Bundle
  val fragment = FragmentB()
  fragment.arguments = bundleOf("key" to "value")
```

<Exercises>
**问题 1**：Activity的完整生命周期是什么？每个回调方法的触发时机和典型操作是什么？

<Answer>
七个回调：①onCreate()——首次创建，初始化布局和控件（setContentView/findViewById），只调一次。②onStart()——变为可见但不可交互。③onResume()——获得焦点可交互，前台运行。④onPause()——失去焦点（部分遮挡），释放CPU密集资源（停止动画/音视频），不能做耗时操作。⑤onStop()——完全不可见，释放较重资源。⑥onDestroy()——销毁前释放所有资源。⑦onRestart()——从停止状态重新启动。典型流转：onCreate→onStart→onResume（运行）→onPause→onStop（后台）→onRestart→onStart→onResume（回前台）→onPause→onStop→onDestroy（销毁）。屏幕旋转走完整销毁→重建。
</Answer>

**问题 2**：Activity的四种启动模式是什么？各自的应用场景是什么？

<Answer>
四种模式：①standard（默认）——每次startActivity创建新实例。②singleTop——栈顶复用，已在栈顶则调onNewIntent不新建，适合推送详情页。③singleTask——栈内单例，已存在则清空上方Activity并调onNewIntent，适合应用首页。④singleInstance——独占任务栈，全局唯一，适合系统级页面。配置：XML的android:launchMode或Intent.addFlags。singleTask和singleInstance影响任务栈结构。
</Answer>

**问题 3**：Fragment的生命周期与Activity有何不同？Fragment事务管理如何工作？

<Answer>
Fragment比Activity多了视图生命周期：onCreateView（创建视图）/onDestroyView（视图销毁但实例存活）/onAttach/onDetach（与Activity绑定解绑）/onViewCreated/onActivityCreated。原因：Fragment视图可被销毁重建（ViewPager预加载）但实例存活。事务管理：FragmentManager.beginTransaction().replace(容器ID, Fragment).addToBackStack(name).commit()。addToBackStack将事务加入回退栈，back键弹出恢复上个Fragment。commit()异步提交，commitNow()同步。配置变更Fragment重建，数据用arguments或ViewModel保存。
</Answer>

**问题 4**：显式Intent和隐式Intent的区别是什么？如何在Activity间传递数据？

<Answer>
显式Intent——直接指定目标类名，用于应用内跳转。隐式Intent——指定action和category，系统匹配能响应的组件（通过intent-filter声明），用于跨应用通信（打开浏览器/拨打电话/分享）。数据传递：①Intent.putExtra(key, value)传基本类型和对象，目标用getStringExtra等读取。②Bundle打包多数据。③startActivityForResult启动并等返回结果，目标setResult+finish，源onActivityResult处理。④Fragment用arguments Bundle。⑤同Activity下Fragment共享ViewModel通信。
</Answer>

<Glossary>
<GlossaryItem term="Activity生命周期">七个回调：onCreate（创建初始化）→onStart（可见）→onResume（可交互）→onPause（失去焦点）→onStop（不可见）→onDestroy（销毁）。屏幕旋转触发完整销毁→重建流程。</GlossaryItem>
<GlossaryItem term="启动模式">四种launchMode：standard（每次新建）、singleTop（栈顶复用）、singleTask（栈内单例清上方）、singleInstance（独占任务栈）。决定Activity实例在任务栈中的创建和复用行为。</GlossaryItem>
<GlossaryItem term="Fragment事务">通过FragmentManager.beginTransaction()管理Fragment的添加/替换/移除。addToBackStack()加入回退栈使back键可恢复，commit()异步提交。</GlossaryItem>
<GlossaryItem term="Fragment视图生命周期">Fragment独有的onCreateView/onDestroyView，因为Fragment视图可被销毁重建但实例存活。字段数据在视图销毁后仍在，控件引用需重新获取。</GlossaryItem>
<GlossaryItem term="Intent">Android组件通信的信使。显式Intent指定类名用于应用内跳转，隐式Intent指定action用于跨应用通信。通过putExtra传递数据。</GlossaryItem>
</Glossary>
