## 直觉引入

数据存储像「不同容量的收纳方案」。SharedPreferences是「小储物柜」（几条键值对，放设置项）；文件存储是「大箱子」（放日志、图片、缓存，无结构）；SQLite是「档案库」（结构化关系数据，支持SQL查询，像一个微型Excel）；LitePal是「档案库管理员」（帮你把面向对象操作翻译成SQL，省去手写SQL）；Room是「智能档案库管理员」（编译期检查SQL对错+自动映射对象+响应式查询，Jetpack官方推荐）；ContentProvider是「公共资料室」（跨应用共享数据，别的App通过Uri来查询）。

## 五种存储方案对比

```text
方案                数据形式         适用场景              核心API
──────────────────────────────────────────────────────────────────────
SharedPreferences   键值对（XML）    设置项/记住密码       edit().putXxx().apply()
文件存储            任意格式         日志/缓存/大文件      openFileOutput/Input()
SQLite              关系型数据库     结构化关系数据        SQLiteOpenHelper
LitePal             ORM映射         面向对象操作数据库    save()/findAll()
Room（推荐）        ORM+编译检查     现代架构首选          @Entity/@Dao/@Database
ContentProvider     跨应用共享       跨进程数据访问        query/insert/update/delete
```

<Callout type="insight">
**选型决策**：几条键值对→SharedPreferences；大量关系数据→Room（编译期检查+响应式查询）；大文件→文件存储；跨App共享→ContentProvider。现代项目首选Room替代手写SQLite，LitePal因维护不活跃已不推荐。
</Callout>

## SharedPreferences

```text
// 获取SharedPreferences实例
val sp = getSharedPreferences("config", Context.MODE_PRIVATE)
// 或用PreferenceManager.getDefaultSharedPreferences(context)

// 写入（异步，推荐）
sp.edit()
  .putString("username", "admin")
  .putBoolean("remember", true)
  .apply()    // 异步写入磁盘，不阻塞主线程

// 写入（同步，需确认结果时）
sp.edit().putString("key", "value").commit()  // 返回boolean

// 读取
val username = sp.getString("username", "default")
val remember = sp.getBoolean("remember", false)
```

<Callout type="trap">
**apply() vs commit()**：apply()异步写入不阻塞主线程但无返回值（推荐常规使用）；commit()同步写入返回boolean但阻塞主线程（需确认写入成功时用，但应在子线程）。两者都先更新内存缓存（立即生效），区别在磁盘持久化时机。
</Callout>

## SQLite与SQLiteOpenHelper

```text
class MyDBHelper(context: Context) :
    SQLiteOpenHelper(context, "app.db", null, 1) {

    // 首次创建数据库时调用（只一次）
    override fun onCreate(db: SQLiteDatabase) {
        db.execSQL("""
            CREATE TABLE IF NOT EXISTS User (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                name TEXT,
                age INTEGER
            )
        """)
    }

    // 数据库版本号递增时调用
    override fun onUpgrade(db: SQLiteDatabase, oldVer: Int, newVer: Int) {
        if (oldVer < 2) {
            db.execSQL("ALTER TABLE User ADD COLUMN email TEXT")
        }
        // 逐步迁移：if(oldVer < 3) { ... }
    }
}

// 增删改查
val db = helper.writableDatabase
db.execSQL("INSERT INTO User(name, age) VALUES(?, ?)", arrayOf("Tom", 20))

// 事务（保证原子性）
db.beginTransaction()
try {
    // 多条SQL...
    db.setTransactionSuccessful()  // 标记成功
} finally {
    db.endTransaction()  // 成功则提交，否则回滚
}

// 查询
val cursor = db.rawQuery("SELECT * FROM User WHERE age > ?", arrayOf("18"))
while (cursor.moveToNext()) {
    val name = cursor.getString(cursor.getColumnIndex("name"))
}
cursor.close()  // 必须关闭！
```

## Room（Jetpack推荐ORM）

```text
// 1. @Entity 定义表
@Entity(tableName = "users")
data class User(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    @ColumnInfo(name = "user_name") val name: String,
    val age: Int
)

// 2. @Dao 定义操作接口
@Dao
interface UserDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(user: User): Long

    @Query("SELECT * FROM users WHERE age > :minAge")
    fun getUsersOlderThan(minAge: Int): LiveData<List<User>>

    @Delete
    suspend fun delete(user: User)

    @Update
    suspend fun update(user: User)
}

// 3. @Database 定义数据库
@Database(entities = [User::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun userDao(): UserDao
}

// 使用（单例）
val db = Room.databaseBuilder(context, AppDatabase::class.java, "app.db").build()
// 协程中调用
viewModelScope.launch {
    db.userDao().insert(User(name = "Tom", age = 20))
}
```

<Callout type="insight">
**Room的三大优势**：①编译期检查——SQL语法错误/表名不存在/字段拼写错误在编译时报错，而非运行时崩溃。②类型安全——查询结果自动映射为对象，不需手动从Cursor逐字段读取。③响应式查询——返回LiveData/Flow，数据库变化自动通知UI更新。现代项目用Room替代手写SQLite。
</Callout>

## ContentProvider跨应用共享

```text
// 定义ContentProvider
class UserProvider : ContentProvider() {
    override fun query(uri: Uri, ...): Cursor { ... }
    override fun insert(uri: Uri, ...): Uri { ... }
    override fun update(uri: Uri, ...): Int { ... }
    override fun delete(uri: Uri, ...): Int { ... }
}

// AndroidManifest注册
<provider android:name=".UserProvider"
    android:authorities="com.example.app.userprovider" />

// 客户端通过ContentResolver访问
val cursor = contentResolver.query(
    Uri.parse("content://com.example.app.userprovider/user"),
    null, null, null, null
)
```

<Exercises>
**问题 1**：Android五种数据存储方案各自的适用场景和优缺点是什么？

<Answer>
五种方案：①SharedPreferences——键值对XML存储，适合少量设置项。apply()异步写入。缺点：不适合大量数据、不支持查询。②文件存储——openFileOutput内部存储（私有），外部存储需权限。适合大文件/缓存。③SQLite——关系型数据库，SQLiteOpenHelper管理创建升级。适合结构化数据，但手写SQL易错。④LitePal——ORM简化SQL，但维护不活跃。⑤Room（推荐）——Jetpack官方ORM，@Entity/@Dao/@Database，编译期检查+类型安全+响应式查询。选型：键值对→SP，关系数据→Room，大文件→文件，跨App→ContentProvider。
</Answer>

**问题 2**：Room的三大核心注解如何使用？相比手写SQLite有什么优势？

<Answer>
三大注解：①@Entity(tableName)定义表，@PrimaryKey主键(autoGenerate自增)，@ColumnInfo列名。②@Dao接口声明操作：@Insert/@Delete/@Update/@Query(SQL编译期检查)，返回LiveData/Flow响应式。③@Database(entities, version)定义数据库持有者。优势：①编译期SQL检查（表名/字段名错误编译报错）。②类型安全（自动映射对象，不需手动Cursor读取）。③样板代码消除（不需写onCreate/onUpgrade/Cursor管理/事务）。④响应式查询（LiveData/Flow自动通知UI）。⑤结构化Migration。
</Answer>

**问题 3**：SQLiteOpenHelper的onCreate和onUpgrade分别在何时调用？如何管理版本迁移？

<Answer>
onCreate——数据库首次创建时调用（文件不存在），执行建表SQL，只调一次。onUpgrade——版本号递增时调用（已存在库版本 < 构造函数版本），执行ALTER/CREATE迁移SQL。迁移策略：①每次改表结构version+1，onUpgrade中加对应SQL。②逐步迁移——if(oldVersion < 2){升级到v2} if(oldVersion < 3){升级到v3}，确保从任何旧版本逐步升级。③ALTER ADD COLUMN保留数据，删列需建新表+复制+删旧+重命名。事务：beginTransaction→SQL→setTransactionSuccessful→endTransaction保证原子性。Room的Migration类是对onUpgrade的结构化封装。
</Answer>

**问题 4**：SharedPreferences的apply()和commit()有什么区别？内部存储和外部存储的区别是什么？

<Answer>
apply() vs commit()：apply()异步写入不阻塞主线程无返回值（推荐）；commit()同步写入返回boolean但阻塞主线程（需确认时用，应在子线程）。两者都先更新内存缓存立即生效。内部存储——应用私有（/data/data/包名/files/），不需权限，卸载删除，空间有限。外部存储——共享（/sdcard/），需权限，Android 10+ Scoped Storage限制（用MediaStore/SAF/getExternalFilesDir），空间大。应用私有文件用内部存储，共享媒体用MediaStore，用户选文件用SAF。
</Answer>
</Exercises>

<GlossaryItem term="SharedPreferences">轻量级键值对存储（底层XML文件），适合少量设置项。edit().putXxx().apply()异步写入。apply()异步不阻塞（推荐），commit()同步返回boolean。</GlossaryItem>
<GlossaryItem term="SQLiteOpenHelper">SQLite数据库管理类，onCreate首次建表，onUpgrade版本迁移。事务用beginTransaction/setTransactionSuccessful/endTransaction保证原子性。</GlossaryItem>
<GlossaryItem term="Room">Jetpack官方ORM。@Entity定义表/@Dao定义操作/@Database定义数据库。编译期SQL检查+类型安全+响应式查询（LiveData/Flow）。现代项目首选替代手写SQLite。</GlossaryItem>
<GlossaryItem term="ContentProvider">四大组件之一，跨应用/跨进程数据共享。提供query/insert/update/delete接口，通过Uri标识数据，客户端用ContentResolver访问。</GlossaryItem>
<GlossaryItem term="数据库版本迁移">SQLite版本号递增触发onUpgrade，需逐步迁移（if oldVersion < N）确保从任何旧版本升级。Room用Migration类结构化封装迁移逻辑。</GlossaryItem>
