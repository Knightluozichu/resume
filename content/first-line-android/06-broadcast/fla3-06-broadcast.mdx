## 从生命周期与状态开始

BroadcastReceiver的执行窗口短，onReceive应完成快速判定并把持久工作交给合适调度器。动态注册与宿主生命周期绑定，静态接收在新Android版本受到隐式广播与后台限制。外部广播是跨进程输入，必须验证action、extras、权限和导出状态。强制下线应由认证状态单一来源驱动，关闭旧页面并清理敏感数据，而不是依赖一个容易丢失的全局弹窗。

Android应用不是从main函数开始并一直驻留的桌面程序。系统可创建、暂停、停止和销毁组件，也可在后台终止整个进程；用户返回时，应用必须从保存状态和持久数据恢复。<Term def="由系统回调驱动、描述组件从创建到销毁及可见交互阶段的状态机">生命周期</Term>决定资源何时取得与释放，<Term def="跨配置变更或进程重建仍能恢复的最小业务事实">持久状态</Term>不能只存在View字段或单例中。

所有异步工作都要绑定所有者。<Term def="负责创建、取消并最终释放组件、任务或资源的明确作用域">所有者</Term>可能是Activity、Fragment的View、ViewModel、Service或应用进程；作用域不同，取消时刻也不同。<Term def="Android版本、targetSdk、设备形态、权限、网络与厂商实现共同形成的行为适用范围">版本边界</Term>防止把Android 10示例当成永久平台规则。<Term def="可由测试重放并以日志、状态快照、截图或产物校验支持的结论链">证据链</Term>则把代码与用户可观察行为连接起来。

主线程负责输入、生命周期分发与大部分UI工作；磁盘、网络、解析和长计算不能阻塞帧与组件回调。异步返回也不能盲目写入已销毁界面。数据流应以一个持久或可恢复的事实源为中心，UI状态从事实派生，用户动作转成明确意图。这样旋转、重建和多入口导航才不会产生多个互相冲突的真相。

跨应用Intent、Provider、网络响应、文件和深链都属于不可信输入。校验action、URI、大小、类型、授权与来源；按最小权限配置导出组件；日志和错误界面不得泄露令牌与个人数据。功能测试之外，还要验证拒绝权限、空数据、重复点击、超时、取消、磁盘满和进程恢复。

## 最小可执行切片

先把状态与副作用分离，示例只表达可恢复合同：

```kotlin
sealed interface UiState {
    data object Loading : UiState
    data class Ready(val itemId: String) : UiState
    data class Failed(val retryable: Boolean) : UiState
}

fun reduce(state: UiState, event: UserEvent): UiState = nextState(state, event)
```

固定环境并从命令行保留可复现证据：

```bash
./gradlew clean test assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am force-stop example.package
adb shell monkey -p example.package 1
adb logcat -d -v threadtime > run.log
```

验收在操作前写出故障条件：

```gherkin
Given a pinned JDK, SDK, Gradle build, device API, locale, and seed
When the component is recreated after state saving or process death
Then user-visible state is restored from durable facts
And cancelled work cannot update a destroyed owner
And denied permission, offline input, and malformed data remain recoverable
```

三段代码分别承担状态模型、环境重放和行为断言。真实工程还需静态检查、单元测试、仪器测试、截图或无障碍检查，以及发布构建验证；不要用日志输出代替断言，也不要让测试依赖本机IDE缓存。

## 线程、状态与资源边界

每个实现列出五张表：入口来自哪里，执行在哪个线程，状态保存在哪里，资源由谁关闭，失败怎样呈现与重试。网络重试必须有上限、退避和幂等；数据库升级必须覆盖所有受支持旧版本；文件和媒体句柄在取消与异常路径释放；组件回调不持有超过生命周期的View或Context。

性能以用户任务衡量。启动不仅看首帧，还要检查可交互时刻；列表不仅看平均帧率，还要检查滚动卡顿和绑定分配；后台工作不仅看是否完成，还要检查电量、约束与系统调度；网络不仅看成功耗时，还要检查超时、取消和错误恢复。每次比较固定设备温度、构建类型、数据规模与网络条件。

版本迁移分两步：先在Android 10/Kotlin语境下还原书中机制，再对目标compileSdk、targetSdk和设备API查询当前官方合同。一次只迁移一个变化，例如存储、权限、通知、后台启动、发布仓库或已弃用库；保存编译警告、运行差异和回滚。新API更现代不代表自动正确，旧API能编译也不代表仍符合平台政策。

<Callout type="trap">**核心陷阱。** 把广播当进程内事件总线，未限制导出、权限、输入来源和注册/注销生命周期。修复方法是回到组件所有者与状态源，注入旋转、进程重建、拒权、断网和无效输入，再对照目标SDK合同。</Callout>

<Callout type="trap">**历史示例不等于当前最佳实践。** 第3版准确反映Android 10时代；目标SDK变化可能改变后台、存储、权限、通知和发布政策。保留原书机制，再建立迁移层，禁止无说明地混写时代。</Callout>

<Callout type="warning">**数据与设备安全。** 真机日志、数据库、媒体、位置和网络响应可能含个人数据；测试使用专用账号与样本，最小授权、清理产物。签名密钥、API密钥和服务端凭据不得写入仓库或客户端日志。</Callout>
