## 直觉引入

网络请求像「寄信」。你不能在办公室门口一直等邮递员（主线程不能阻塞），得让助理去寄（子线程发请求），助理收到回信后再通过内部电话告诉你（Handler/协程切回主线程）。HttpURLConnection是「自己去邮局寄信」（原生API，步骤繁琐）；OkHttp是「快递公司」（连接池复用、拦截器、缓存，专业高效）；Retrofit是「快递代理平台」（你只声明寄什么，代理帮你搞定全部细节，还能自动翻译回信内容）。JSON解析像「翻译回信」——JSONObject是「逐字翻译」（手动逐字段读取），Gson是「机器翻译」（一行代码自动映射成对象）。

## 网络请求流程

```text
完整流程（必须在子线程）：

  子线程发起请求
      ↓
  HttpURLConnection / OkHttp / Retrofit
      ↓
  建立连接（openConnection / newCall）
      ↓
  设置请求方法（GET/POST）和参数
      ↓
  发送请求，等待响应
      ↓
  读取响应流（getInputStream / BufferedReader）
      ↓
  解析JSON（JSONObject / Gson / Moshi）
      ↓
  切回主线程更新UI（Handler / runOnUiThread / 协程）
```

<Callout type="trap">
**主线程不能做网络请求**：Android 3.0+禁止主线程执行网络操作，抛NetworkOnMainThreadException。原因：网络是耗时IO，阻塞主线程导致ANR（5秒无响应）。所有网络请求必须在子线程，结果通过Handler/协程切回主线程更新UI。
</Callout>

## 三种异步方案对比

```text
方案               核心机制                      特点
──────────────────────────────────────────────────────────────────
Thread+Handler     子线程请求 + Handler切主线程    最底层，代码量大
AsyncTask          doInBackground+onPostExecute   已废弃（内存泄漏/崩溃）
OkHttp enqueue     enqueue(callback)异步回调       连接池/拦截器/缓存
Retrofit+Coroutine suspend函数 + 协程             最现代，代码最简洁（推荐）

HttpURLConnection（原生，了解原理）：
  Thread {
      val url = URL("https://api.example.com/data")
      val conn = url.openConnection() as HttpURLConnection
      conn.requestMethod = "GET"
      conn.connectTimeout = 8000
      val reader = BufferedReader(InputStreamReader(conn.inputStream))
      val response = reader.readText()
      reader.close()
      conn.disconnect()

      runOnUiThread { textView.text = response }  // 切主线程
  }.start()

OkHttp（推荐）：
  val client = OkHttpClient()
  val request = Request.Builder().url("https://api.example.com/data").build()
  client.newCall(request).enqueue(object : Callback {
      override fun onResponse(call: Call, response: Response) {
          val body = response.body?.string()
          // 仍在子线程，需切主线程
      }
  })

Retrofit + Coroutine（最现代，推荐）：
  // 接口定义
  interface ApiService {
      @GET("data")
      suspend fun getData(): Response<MyData>
  }
  // ViewModel中调用（协程自动切线程）
  viewModelScope.launch {
      val response = apiService.getData()
      _data.value = response.body()  // 主线程更新LiveData
  }
```

<Callout type="insight">
**现代方案：Retrofit + OkHttp + Coroutines**：Retrofit接口化API声明（注解），底层OkHttp发请求（连接池/拦截器/缓存），suspend函数配合协程自动线程切换。代码最简洁，网络层与UI层完全解耦，生命周期安全（ViewModelScope自动取消）。
</Callout>

## OkHttp与Retrofit详解

```text
OkHttp核心特性：
  - 连接池：默认5个空闲连接复用（Keep-Alive），减少TCP握手
  - 拦截器：Interceptor链式处理请求/响应（加Header/日志/缓存/重试）
  - 超时配置：connectTimeout/readTimeout/writeTimeout
  - 自动重试：连接失败自动重试
  - 缓存：基于HTTP缓存头（Cache-Control/ETag）
  - HTTP/2支持：多路复用
  - Gzip透明压缩：自动解压

  // 添加日志拦截器
  val client = OkHttpClient.Builder()
      .addInterceptor(HttpLoggingInterceptor().apply {
          level = HttpLoggingInterceptor.Level.BODY
      })
      .connectTimeout(10, TimeUnit.SECONDS)
      .build()

Retrofit核心特性：
  - 接口化API：@GET/@POST/@PUT/@DELETE 注解声明
  - 类型安全：返回值直接定义为数据类型（Call<User>或suspend User）
  - Converter自动转换：GsonConverterFactory自动JSON↔对象
  - 与OkHttp无缝集成：共享连接池/拦截器/缓存

  // Retrofit配置
  val retrofit = Retrofit.Builder()
      .baseUrl("https://api.example.com/")
      .addConverterFactory(GsonConverterFactory.create())
      .client(okHttpClient)
      .build()

  // 接口定义
  interface ApiService {
      @GET("users/{id}")
      suspend fun getUser(@Path("id") id: Int): User

      @POST("users")
      suspend fun createUser(@Body user: User): User

      @GET("search")
      suspend fun search(@Query("q") query: String): List<User>
  }

  // 使用
  val api = retrofit.create(ApiService::class.java)
```

## JSON解析

```text
JSONObject（手动解析，内置无需依赖）：
  val json = JSONObject(responseString)
  val name = json.getString("name")
  val age = json.getInt("age")
  val items = json.getJSONArray("items")
  for (i in 0 until items.length()) {
      val item = items.getJSONObject(i)
      // ...
  }

  适合：简单结构，只需提取少量字段

Gson（自动映射，推荐）：
  // JSON → 对象
  val user = Gson().fromJson(jsonString, User::class.java)

  // 对象 → JSON
  val json = Gson().toJson(user)

  // 数据类定义
  data class User(
      @SerializedName("user_name") val userName: String,  // 字段别名
      val age: Int,
      val items: List<Item>
  )

  适合：复杂结构，自动映射，配合Retrofit Converter使用

Moshi（Kotlin友好，编译期生成）：
  - KSP/KAPT编译期生成适配器（避免反射）
  - 比Gson更快更安全
  - 支持Kotlin nullable
  - 现代Kotlin项目首选
```

## 权限与HTTP限制

```text
必须声明的权限：
  <uses-permission android:name="android.permission.INTERNET" />
  <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

Android 9.0 HTTP限制：
  - 默认禁止明文HTTP请求（只允许HTTPS）
  - HTTP请求抛CLEARTEXT communication not permitted异常

  解决方案：
  1. 改用HTTPS（推荐）
  2. 配置networkSecurityConfig允许特定域名HTTP：
     res/xml/network_security_config.xml:
     <network-security-config>
         <domain-config cleartextTrafficPermitted="true">
             <domain includeSubdomains="true">example.com</domain>
         </domain-config>
     </network-security-config>
     AndroidManifest:
     <application android:networkSecurityConfig="@xml/network_security_config">
  3. 全局允许明文（仅调试，不推荐）：
     android:usesCleartextTraffic="true"
```

<Exercises>
**问题 1**：为什么Android中网络请求必须在子线程执行？有哪些异步处理方案？

<Answer>
网络请求必须在子线程因为Android禁止主线程执行网络操作（NetworkOnMainThreadException，Android 3.0+），原因：网络是耗时IO阻塞主线程导致ANR（5秒无响应）。异步方案：①Thread+Handler——子线程请求+Handler切主线程，最底层代码量大。②AsyncTask——已废弃。③OkHttp enqueue——异步回调，底层封装连接池/超时/重试。④Retrofit+Coroutine——suspend函数+协程自动线程切换，最现代最简洁。最佳实践：Retrofit+OkHttp+Coroutines，ViewModelScope协程中调suspend API，返回LiveData/Flow给UI观察。
</Answer>

**问题 2**：OkHttp和Retrofit各自的核心特性是什么？为什么要组合使用？

<Answer>
OkHttp核心特性：连接池（5个空闲连接复用减少TCP握手）、拦截器链（统一加Header/日志/缓存/重试）、超时配置、自动重试、HTTP缓存、HTTP/2多路复用、Gzip透明压缩。Retrofit核心特性：接口化API（@GET/@POST注解声明）、类型安全（返回值直接定义为数据类型）、Converter自动JSON↔对象转换、适配器支持Coroutine/Flow/RxJava、与OkHttp无缝集成共享连接池。组合使用原因：OkHttp提供高性能HTTP底层，Retrofit在其上提供接口化高层抽象。Retrofit解决怎么方便定义调用API，OkHttp解决怎么高效发HTTP请求。
</Answer>

**问题 3**：Android中如何解析JSON数据？Gson和JSONObject各有什么优缺点？

<Answer>
JSONObject手动解析——内置无需依赖，逐字段读取getString/getInt/getJSONArray，代码冗长易出错，适合简单结构。Gson自动映射——Gson().fromJson(json, User::class.java)一行映射对象，支持嵌套对象和集合/泛型/@SerializedName字段别名，需添加依赖，适合复杂结构。Moshi——Kotlin友好编译期生成适配器避免反射，比Gson快安全支持nullable，现代Kotlin首选。最佳实践：用Gson/Moshi自动映射+Retrofit Converter自动在网络返回时解析，业务代码只面对对象不面对JSON字符串。
</Answer>

**问题 4**：Android网络编程需要哪些权限配置？Android 9.0对HTTP有什么限制？

<Answer>
权限：声明<uses-permission android:name="android.permission.INTERNET"/>（普通权限无需运行时申请），如需查网络状态声明ACCESS_NETWORK_STATE。Android 9.0 HTTP限制：①默认禁明文HTTP只允许HTTPS（CLEARTEXT communication not permitted异常）。②解决方案：改HTTPS（推荐）/配置networkSecurityConfig允许特定域名HTTP（res/xml/network_security_config.xml中domain-config cleartextTrafficPermitted=true）/全局usesCleartextTraffic=true（仅调试不推荐）。Android 7.0+默认只信任系统CA证书，自定义证书需在networkSecurityConfig配置。
</Answer>

<Glossary>
<GlossaryItem term="NetworkOnMainThreadException">Android 3.0+禁止主线程执行网络操作，违反时抛此异常。原因：网络IO耗时阻塞主线程导致ANR。解决方案：子线程请求+Handler/协程切主线程更新UI。</GlossaryItem>
<GlossaryItem term="OkHttp">Square开源HTTP客户端，核心特性：连接池复用、拦截器链、超时/重试配置、缓存、HTTP/2、Gzip压缩。与Retrofit组合使用提供高性能HTTP底层。</GlossaryItem>
<GlossaryItem term="Retrofit">Square开源接口化HTTP客户端，用注解声明API（@GET/@POST/@Path/@Query/@Body），类型安全返回值自动映射，Converter自动JSON解析，与OkHttp无缝集成。底层默认用OkHttp。</GlossaryItem>
<GlossaryItem term="Gson">Google开源JSON库，fromJson/toJson一行代码完成对象↔JSON映射，支持嵌套/集合/泛型/@SerializedName别名。配合Retrofit Converter自动解析网络响应。</GlossaryItem>
<GlossaryItem term="networkSecurityConfig">Android 7.0+网络安全配置，在res/xml/中定义信任的CA证书和允许明文HTTP的域名。Android 9.0+默认禁明文HTTP，需在此配置放行特定域名。</GlossaryItem>
</Glossary>
