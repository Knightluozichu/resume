## 直觉引入

想象你住进一栋智能公寓。你不必记住每件电器的型号，只要对着管家说"开灯""设闹钟"，管家自会去调用对应的开关。Python 就是这栋公寓：你说 `len(deck)`、`for card in deck`，解释器这个"管家"自会去找到对象上对应的特殊方法去执行。

你不需要知道 `deck` 是 list 还是自定义类，只要它"会回应"相应的特殊方法，Python 的语法就能对它生效。这种"语法 → 特殊方法"的约定，就是 Python 数据模型。

没有数据模型，每种容器都要发明自己的 `length()`、`at()`、`iterate()` 方法，标准库和第三方代码无法互通；有了它，一个实现了 `__getitem__` 的自定义牌堆，能直接被 `random.choice`、`sorted`、切片语法接受。

## 概念讲解

### 特殊方法是什么

<Term def="以双下划线包裹的方法，是 Python 数据模型的实现接口。内置函数和语法通过隐式调用它们与对象交互。">

**特殊方法（special methods）**，又称 dunder methods（double underscore），形如 `__len__`、`__getitem__`、`__repr__`。它们不是给你直接调用的，而是给 Python 解释器调用的——当你写 `len(obj)`，解释器去调 `obj.__len__()`；当你写 `obj[i]`，解释器去调 `obj.__getitem__(i)`。

</Term>

### 语法到特殊方法的分发

数据模型的核心思想是：**内置语法和函数只是糖衣，真正干活的是对象上的特殊方法**。这意味着只要你的类型实现了相应方法，它就能享受 Python 的全套语法支持。

| 语法 / 内置函数 | 特殊方法 | 用途 |
|---|---|---|
| `len(obj)` | `__len__` | 长度 |
| `obj[i]` / `obj[a:b]` | `__getitem__` | 索引与切片 |
| `for x in obj` | `__iter__` / `__next__` | 迭代 |
| `repr(obj)` | `__repr__` | 开发者表示 |
| `a + b` | `__add__` | 运算符重载 |
| `with obj as x:` | `__enter__` / `__exit__` | 上下文管理 |

### 为什么用内置函数而非直接调特殊方法

`len(obj)` 比 `obj.__len__()` 更好，因为：内置函数对内置类型走 CPython 快速路径（直接读内部字段，不经方法调用），且做了返回值类型校验。直接调 `__len__` 既绕过了数据模型抽象，对内置类型反而更慢。Pythonic 原则：**用内置函数/语法，让特殊方法待在幕后**。

## 代码对照

```python
# 一副扑克牌：靠特殊方法融入 Python
import collections
from random import choice

Card = collections.namedtuple('Card', ['rank', 'suit'])

class FrenchDeck:
    ranks = [str(n) for n in range(2, 11)] + list('JQKA')
    suits = 'spades diamonds clubs hearts'.split()

    def __init__(self):
        self._cards = [Card(r, s) for s in self.suits for r in self.ranks]

    def __len__(self):
        return len(self._cards)          # len(deck) → 52

    def __getitem__(self, position):
        return self._cards[position]     # deck[0]、deck[12::13] 切片都可用

deck = FrenchDeck()
print(len(deck))            # 52 —— 走 __len__
print(deck[0])              # Card(rank='2', suit='spades') —— 走 __getitem__
print(choice(deck))         # 随机一张 —— choice 内部用 __getitem__
print(deck[:3])             # 切片，前三张 —— 也走 __getitem__
# 没写 __iter__，但 for 能用：迭代回退到 __getitem__，从 0 起逐个取直到越界
for card in deck[:3]:
    print(card)
```

注意：`FrenchDeck` 没写 `__iter__`，但 `for` 能工作——这是数据模型的**迭代回退机制**：没有 `__iter__` 时，解释器退回到用 `__getitem__(0)`、`__getitem__(1)`… 直到抛 `IndexError`。这就是为什么"只实现 `__getitem__`"也能让对象可迭代。

## 常见误区

<Callout type="trap">

**误区：直接调用 `obj.__len__()` 而非 `len(obj)`**

有人以为"既然 `len()` 内部调 `__len__`，我直接调不就省一步？"恰恰相反：直接调绕过了内置函数的类型校验和快速路径，对 `list`、`str` 等内置类型更慢，也破坏了数据模型的抽象。永远用 `len()`，让 `__len__` 待在幕后。

</Callout>

<Callout type="trap">

**误区：运算符方法遇到不兼容类型直接抛 `TypeError`**

`__add__` 里若 `self` 与 `other` 维度不同，应返回 `NotImplemented` 而非 `raise TypeError`。返回 `NotImplemented` 后解释器会尝试 `other.__radd__(self)`，给对方一个机会；只有双方都返回 `NotImplemented` 才抛 `TypeError`。这是数据模型的双分派约定。

</Callout>

<Exercises>

**问题 1**：`FrenchDeck` 没有实现 `__iter__`，为什么 `for card in deck` 仍能工作？

<Answer>

因为 Python 的迭代协议有**回退机制**：当对象没有 `__iter__` 时，解释器退回到旧的序列迭代协议——从下标 0 开始反复调用 `__getitem__(i)`，直到抛 `IndexError` 停止。`FrenchDeck` 实现了 `__getitem__`，所以 `for` 能用它逐个取出元素。不过显式实现 `__iter__` 通常更高效、语义更清晰，回退机制主要是为了向后兼容旧式序列。

</Answer>

**问题 2**：为什么说 `len(obj)` 比 `obj.__len__()` 更 Pythonic？请从快速路径和抽象两个角度解释。

<Answer>

1. 快速路径：对 `list`、`str`、`dict` 等内置类型，`len()` 直接读取 C 结构体里的长度字段，不经过 Python 层的方法调用，比 `obj.__len__()` 更快；同时 `len()` 会校验返回值必须是 `int`，防止 `__len__` 实现错误。2. 抽象：`len()` 是数据模型的正面入口，调用者无需关心对象类型；直接调 `__len__` 把实现细节暴露到调用点，破坏了"语法是糖衣、特殊方法在幕后"的约定。Pythonic 的做法是永远用内置函数/语法访问对象。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="特殊方法">

以双下划线包裹的方法（如 `__len__`、`__getitem__`），是 Python 数据模型的实现接口。主要由解释器在执行内置语法/函数时隐式调用，不应在代码里直接调用。

</GlossaryItem>

<GlossaryItem term="数据模型">

Python 定义的一组特殊方法约定，规定了对象如何与语言交互。实现相应特殊方法，自定义类型即可被内置函数与语法（`len`、`[]`、`for`、`+`、`with` 等）接受。

</GlossaryItem>

<GlossaryItem term="迭代回退机制">

当对象没有 `__iter__` 时，解释器退回到用 `__getitem__(0)`、`__getitem__(1)`… 迭代，直到抛 `IndexError`。这让只实现 `__getitem__` 的序列也能被 `for` 遍历。

</GlossaryItem>

<GlossaryItem term="NotImplemented">

运算符特殊方法在遇到不支持的类型时返回的特殊单例（注意不是异常）。它通知解释器尝试右操作数的反向方法（如 `__radd__`），是运算符双分派机制的核心。

</GlossaryItem>

</Glossary>
