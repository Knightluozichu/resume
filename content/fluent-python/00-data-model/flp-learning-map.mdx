## 直觉引入

学 Python 进阶就像学开车。你不能只会踩油门（写能跑的脚本），还得懂发动机怎么转（数据模型）、变速箱有几档（数据结构）、方向盘怎么传力（函数与对象），最后学会越野漂移（高级特性）。只会踩油门的人永远开不快、开不稳。

本书以 Luciano Ramalho 的《流畅的 Python》为蓝本，带你从"会写 Python"跨越到"写得 Pythonic"。全书按"数据模型 → 数据结构 → 函数与对象 → 高级特性"四步推进，每一步都建立在前一步的基础上。

没有数据模型，你不知道 `len()` 为什么对任何对象都管用；没有数据结构，你不知道该用列表还是字典；没有函数与对象，你写不出可复用、可约束的抽象；没有高级特性，你读不懂主流框架里满地的装饰器和生成器。

## 概念讲解

### 四大板块

全书按学习递进分为四个板块：

1. **Python 数据模型**（第 1-2 章）：学习地图与数据模型。先建立全景认知，理解 Python 世界由一组特殊方法驱动——这是全书的地基。
2. **数据结构**（第 3-4 章）：序列类型与字典集合。掌握内置容器的高效用法与底层机制，这是日常编码最频繁接触的部分。
3. **函数与对象**（第 5-7 章）：一等函数、类型提示、协议与 ABC。把函数当对象传递，用类型与协议约束设计边界。
4. **高级特性**（第 8-10 章）：闭包与装饰器、生成器、总复习。理解作用域、延迟求值与惰性计算，读懂框架源码。

### 为什么按这个顺序学

<Term def="学习递进链是四大板块的依赖关系：数据模型是世界观，数据结构是其骨架，函数对象是脉络，高级特性是内功。">

按这个顺序学的核心价值在于建立**递进能力链**。数据模型是世界观——不懂特殊方法，就看不懂数据结构为何如此工作。数据结构是骨架——序列和字典是函数与对象操作的素材。函数与对象是脉络——协议和类型提示把零散知识组织成可维护的工程。高级特性是内功——闭包、装饰器、生成器把前三者升华成优雅的抽象。

</Term>

### 学习路径建议

**推荐路径**：学习地图 → 数据模型 → 序列类型 → 字典与集合 → 一等函数 → 类型提示 → 协议与 ABC → 闭包与装饰器 → 生成器 → 总复习。

前两个板块必须按顺序学，函数与对象三章可以在数据结构基础上灵活推进。高级特性放最后，因为装饰器和生成器需要先理解函数对象与序列协议。

<Step title="第一步：数据模型立心">

先理解 Python 数据模型——对象通过实现特殊方法（`__len__`、`__getitem__` 等）融入语言。`len(obj)` 实际调用 `obj.__len__()`，`for x in obj` 实际调用 `__iter__`。建立这个心智模型，后续所有知识都有了锚点。

</Step>

<Step title="第二步：数据结构筑基">

序列（列表、元组、字符串）和映射（字典、集合）是 Python 的骨架容器。理解切片、解包、推导式、字典的哈希机制，你才能写出既快又清晰的代码。这一步把"能跑"提升到"用得对"。

</Step>

<Step title="第三步：函数对象塑形">

函数在 Python 里是一等公民——可以赋值、传参、返回。高阶函数、类型提示、协议与 ABC 让你能定义清晰的接口契约，写出可复用、可维护的抽象层。

</Step>

<Step title="第四步：高级特性升华">

闭包捕获变量而非值，装饰器在不改原函数的前提下增强行为，生成器用惰性求值处理无限或大数据流。学完这一步，你就能读懂 Django、Flask 源码里满地的 `@login_required` 和 `yield`。

</Step>

</Stepper>

## 代码对照

```python
# Python 进阶递进：从特殊方法到生成器

# Layer 1: 数据模型——实现特殊方法，融入语言
class Deck:
    def __init__(self):
        self.cards = [f"{r}{s}" for r in "23456789TJQKA" for s in "♠♥♦♣"]
    def __len__(self):
        return len(self.cards)
    def __getitem__(self, i):
        return self.cards[i]

deck = Deck()
print(len(deck))          # 52 —— len() 走 __len__
print(deck[0])            # 2♠ —— [] 走 __getitem__
from random import choice
print(choice(deck))       # 随机一张 —— choice 依赖 __getitem__

# Layer 2: 数据结构——用对容器
words = "the quick brown fox".split()
freq = {w: len(w) for w in words}   # 字典推导式
print(sorted(freq, key=freq.get))   # 按词长排序

# Layer 3: 函数对象——高阶函数
def make_multiplier(n):
    return lambda x: x * n          # 函数作为返回值
double = make_multiplier(2)
print(double(21))                   # 42

# Layer 4: 高级特性——生成器惰性求值
def fibonacci():
    a, b = 0, 1
    while True:
        yield b                     # 不预先生成全部，按需产出
        a, b = b, a + b

fib = fibonacci()
print([next(fib) for _ in range(8)])  # [1, 1, 2, 3, 5, 8, 13, 21]
```

从实现 `__getitem__` 让自定义牌堆能被 `choice` 接受，到用生成器表达无限序列——每一步都建立在前一步的基础上。

## 常见误区

<Callout type="trap">

**误区：跳过数据模型直接学高级特性**

很多人急着学装饰器、元类，跳过数据模型。结果能背 `@decorator` 语法，却不知道装饰器返回的为什么是函数、`__call__` 在哪起作用——因为没建立"对象行为由特殊方法决定"的心智。数据模型不牢，高级特性就是空中楼阁。

</Callout>

<Callout type="trap">

**误区：把 Python 当带缩进的 C 写**

只会用 `for i in range(len(lst))` 而不会用切片和推导式，只会写 `if obj.__class__ == X` 而不会用 `isinstance` 与协议——这是没理解数据模型的典型症状。Pythonic 不是炫技，是顺应语言设计。

</Callout>

<Exercises>

**问题 1**：本书四大板块的顺序是什么？为什么按这个顺序学习？

<Answer>

四大板块的顺序是：Python 数据模型 → 数据结构 → 函数与对象 → 高级特性。

按这个顺序学习的原因是建立了递进能力链：1. 数据模型是世界观，特殊方法是后续所有知识的锚点；2. 数据结构是骨架，序列和字典是函数操作的对象；3. 函数与对象是脉络，协议和类型提示把零散知识组织成工程；4. 高级特性是内功，装饰器和生成器依赖前三者。跳过任何一层，上层知识就会悬空。

</Answer>

**问题 2**：为什么说"数据模型"是理解全书的钥匙，而不是"数据结构"？

<Answer>

数据模型定义了对象如何通过特殊方法与语言交互（`len()`→`__len__`、`for`→`__iter__`、`+`→`__add__`）。数据结构板块里 `list`、`dict` 的行为本质就是这些特殊方法的实现；函数对象板块的"协议"就是一组特殊方法的约定；高级特性的装饰器依赖 `__call__`、生成器依赖 `__iter__`/`__next__`。所以数据模型是底层世界观，数据结构只是它在容器领域的具体化——不先理解世界观，就看不懂数据结构为何如此工作。

</Answer>

<Glossary>

<GlossaryItem term="四大板块">

全书按学习递进分为四个板块：Python 数据模型（学习地图、数据模型）、数据结构（序列类型、字典与集合）、函数与对象（一等函数、类型提示、协议与 ABC）、高级特性（闭包与装饰器、生成器、总复习）。

</GlossaryItem>

<GlossaryItem term="递进能力链">

四大板块之间的依赖关系：数据模型是世界观，数据结构是其骨架，函数对象是脉络，高级特性是内功。每个板块都建立在前一个板块的基础上。

</GlossaryItem>

<GlossaryItem term="特殊方法">

以双下划线包裹的方法（如 `__len__`、`__getitem__`），也叫 dunder methods。Python 内置函数和语法通过调用它们与对象交互，是实现数据模型的基本手段。

</GlossaryItem>

<GlossaryItem term="Pythonic">

顺应 Python 数据模型、用语言提供的协议和语法糖而非自己造轮子的编码风格。例如用切片而非手写下标循环，用推导式而非 for-append。

</GlossaryItem>
