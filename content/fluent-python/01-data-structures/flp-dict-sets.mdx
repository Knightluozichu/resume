## 核心模型与责任

字典与集合都建立在哈希表上。可哈希对象必须在生命周期内保持哈希值不变，并让相等对象拥有相同哈希；通常由不可变成分构成，元组也只有在全部元素可哈希时才可作键。 <Term def="字典推导、双星号解包与合并运算符把转换、复制和覆盖规则写成表达式；映射模式匹配只要求目标含有指定键，多余键不会阻止匹配，并可用双星号捕获其余字段。">字典推导、解包、合并与模式匹配</Term>

这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

字典推导、双星号解包与合并运算符把转换、复制和覆盖规则写成表达式；映射模式匹配只要求目标含有指定键，多余键不会阻止匹配，并可用双星号捕获其余字段。 <Term def="缺失键应按语义选择get、setdefault、defaultdict或自定义missing。读取与创建不能混为一谈；defaultdict只在getitem路径触发工厂，get不会自动插入。">可哈希对象与缺失键</Term>

```python
dial_codes = [(880, 'Bangladesh'), (55, 'Brazil'), (86, 'China')]
country_dial = {country: code for code, country in dial_codes}
merged = country_dial | {'China': 999}
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

缺失键应按语义选择get、setdefault、defaultdict或自定义missing。读取与创建不能混为一谈；defaultdict只在getitem路径触发工厂，get不会自动插入。 <Term def="映射变体包括ChainMap、Counter、UserDict和只读MappingProxyType。字典视图是动态窗口而非快照，keys与items支持集合式操作，values视图则不定义集合语义。">映射变体与字典视图</Term>

<FlpDictSetsBoundaryLab />

```python
from collections import defaultdict
index = defaultdict(list)
for word, line in [('python', 1), ('python', 8), ('data', 3)]:
    index[word].append(line)
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

映射变体包括ChainMap、Counter、UserDict和只读MappingProxyType。字典视图是动态窗口而非快照，keys与items支持集合式操作，values视图则不定义集合语义。 <Term def="集合操作与字典视图操作适合表达去重、成员判断、交并差和键集合比较。哈希表用空间换近似常数时间，但不要依赖内部槽位或把顺序保证误解成排序。">集合操作与字典视图操作</Term>

集合操作与字典视图操作适合表达去重、成员判断、交并差和键集合比较。哈希表用空间换近似常数时间，但不要依赖内部槽位或把顺序保证误解成排序。 <Term def="用可复现实验判断字典与集合实现是否保持协议、不变量与失败语义。">字典与集合验证边界</Term>
