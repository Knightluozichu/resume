## 从一个错误直觉开始

先预测：只记住对象引用、可变性与回收的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

对象引用、可变性与回收的起点是变量不是盒子，而是绑定到对象的名字。赋值复制引用而不复制对象，函数参数也采用共享传参，因此可变参数可能被被调函数原地改变。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

身份、相等性与别名要分层判断：is比较是否同一对象，双等号委托值相等协议。None等单例用is，业务值用相等；两个名字指向同一可变对象时，任一修改都能被另一名字观察。
```python
a = {'items': []}
b = a
b['items'].append('shared')
assert a is b and a == b
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

浅复制只复制最外层容器，内部元素仍共享；深复制递归复制对象图并用memo处理循环。复制策略必须匹配聚合边界，不要默认deepcopy就能正确复制数据库连接或共享缓存。

```python
def append_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

可变参数默认值在函数定义时只创建一次，导致多次调用和多个实例共享状态。默认使用None哨兵，再在函数内部创建新容器，并在接收外部可变集合时决定是防御性复制还是明确共享。
del与垃圾回收针对引用而非对象；引用计数归零或循环垃圾被探测后对象才可能回收。weakref允许观察对象而不延长生命周期，但finalizer时机不能承担关键业务提交。
```python
from copy import copy, deepcopy
original = [['A'], ['B']]
shallow = copy(original)
deep = deepcopy(original)
original[0].append('shared only with shallow')
```
