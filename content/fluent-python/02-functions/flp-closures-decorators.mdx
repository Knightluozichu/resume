## 核心模型与责任

装饰器与闭包都建立在函数一等性上。装饰器在定义后立即接收目标并把名称重新绑定到返回对象；闭包则让内部函数保留定义环境中的自由变量。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

装饰器执行与注册要区分导入阶段和调用阶段。注册装饰器常在导入时把函数加入表并原样返回，包装装饰器则创建新调用链；模块导入副作用必须可预测。
```python
def register(func):
    registry.append(func)
    return func
registry = []
@register
def task(): return 'ok'
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

变量作用域、闭包与nonlocal解释了为什么读取自由变量可行，而重新绑定需要声明nonlocal。闭包保存的是绑定单元，不只是定义时值，因此可构建有状态平均器。

```python
def make_averager():
    total = count = 0
    def average(value):
        nonlocal total, count
        total += value; count += 1
        return total / count
    return average
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

cache、lru_cache与singledispatch分别处理无界记忆、有界淘汰和按第一个参数类型分派。缓存参数必须可哈希，返回值应视为共享；分派注册要避免隐藏业务规则。
参数化装饰器多一层函数来接收配置，类装饰器能保存状态。无论形式如何，都应使用wraps保留名称、文档和签名，并明确同步、异步及异常语义。
```python
from functools import lru_cache, wraps
@lru_cache(maxsize=128)
def fib(n): return n if n < 2 else fib(n - 1) + fib(n - 2)
```
