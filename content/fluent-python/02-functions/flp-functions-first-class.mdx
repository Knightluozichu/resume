## 从一个错误直觉开始

先预测：只记住函数作为一等对象的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

函数作为一等对象意味着可以赋给变量、放进集合、作为参数传入并作为结果返回。函数名只是引用，调用运算符才执行对象；这让行为可以像数据一样组合和选择。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

高阶函数接收函数或返回函数，sorted的key、map和reduce都是典型入口。简单映射过滤通常优先推导式，真正需要策略注入或惰性管道时再使用高阶抽象。
```python
factorial = lambda n: 1 if n < 2 else n * factorial(n - 1)
functions = [len, str.upper, factorial]
assert functions[0]([1, 2]) == 2
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

可调用对象不局限于函数：实现call的实例、类、绑定方法和生成器函数都可调用。带状态的调用对象适合累计器或配置化策略，但状态和并发可见性需要明确。

```python
class Averager:
    def __init__(self): self.total = 0; self.count = 0
    def __call__(self, value):
        self.total += value; self.count += 1
        return self.total / self.count
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

仅关键字参数与仅位置参数用星号和斜杠表达API调用约束。关键字参数提升可读性，位置专用允许未来修改内部参数名；签名应服务稳定契约，而不是炫技。
operator模块与functools.partial减少微小lambda，把itemgetter、attrgetter和methodcaller用于结构化提取，把partial用于冻结部分参数。包装后仍要保留清楚命名和类型信息。
```python
from operator import attrgetter
from functools import partial
normalize = partial(round, ndigits=2)
by_name = attrgetter('name')
```
