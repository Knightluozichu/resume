## 直觉引入

闭包就像一个实习生，你把任务交给他时只给了「找那个叫 n 的文件」（变量引用），没给他文件内容。等他真去找时，如果 n 文件被换过了，他拿到的是最新版本——不是你交代时的版本。

装饰器则是「函数的包装车间」：你把函数送进去，车间给它套一层外壳（wrapper），外壳在调用原函数前后做额外的事（计时、重试、日志），然后把套了壳的函数还给你。从此你调用这个名字，实际跑的是外壳。

这两个机制合在一起，是 Flask 路由、Django 权限、pytest fixture 的共同基础。不懂闭包，就读不懂装饰器为什么能「记住」原函数。

## 概念讲解

### 闭包

<Term def="闭包是延伸了作用域的函数——内部函数引用外层变量，外层返回后仍可访问。闭包捕获的是变量引用而非值，故延迟绑定。">

闭包指内部函数引用了外层函数的变量，即使外层函数已返回，内部函数仍能访问那些变量。关键：闭包捕获的是**变量本身（引用）**，而非捕获那一刻的值。若外层变量在闭包被调用前变化，闭包看到最新值（延迟绑定）。

</Term>

### 装饰器

装饰器是「接收函数、返回函数」的高阶函数。`@timer` 加在 `def greet():` 上，等价于定义后执行 `greet = timer(greet)`——把 greet 重新绑定到 wrapper。调用 `greet()` 实际执行 wrapper，wrapper 内部再调用原 greet。

### functools.wraps

wrapper 是新函数，默认 `__name__`、`__doc__` 是自己的，会抹掉原函数元信息，让调试、文档、反射（FastAPI 签名）失效。`@functools.wraps(func)` 把原函数元信息复制到 wrapper，是装饰器标配。

### 带参装饰器

带参装饰器需三层嵌套：第 1 层接收装饰器参数返回真正的装饰器，第 2 层接收被装饰函数返回 wrapper，第 3 层是实际包装。每一层对应一个参数传入时机。

## 代码对照

```python
import functools
import time

# 闭包：捕获变量而非值
def make_adder():
    n = 1
    def add(x):
        return x + n      # 捕获变量 n
    n = 100                # 改了 n
    return add
print(make_adder()(1))     # 101，不是 2 —— 延迟绑定

# 无参装饰器：计时
def timer(func):
    @functools.wraps(func)            # 保留原函数元信息
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)  # 闭包捕获 func
        print(f"{func.__name__}: {time.perf_counter()-start:.4f}s")
        return result
    return wrapper

@timer
def slow():
    time.sleep(0.1)
slow()                     # slow: 0.1xxxs
print(slow.__name__)       # slow —— wraps 保留，没有的话是 wrapper

# 带参装饰器：重试（三层嵌套）
def retry(times=3):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator

@retry(times=3)
def call_api():
    ...
# 等价于 call_api = retry(times=3)(call_api)

# 循环闭包陷阱
fns_bad = [lambda: i for i in range(3)]
print([f() for f in fns_bad])   # [2, 2, 2] —— 全取最终值
fns_good = [lambda i=i: i for i in range(3)]   # 默认参数固化
print([f() for f in fns_good])  # [0, 1, 2]
```

`fns_bad` 全输出 2，因为每个 lambda 捕获同一个变量 i，调用时 i 已是最终值 2。`lambda i=i` 用默认参数在定义时固化当前值，破解陷阱。

## 常见误区

<Callout type="trap">

**误区：以为闭包捕获的是定义时的值**

闭包捕获变量引用，调用时才求值。`make_adder` 里 n 改成 100 后闭包看到 100，循环里所有 lambda 看到同一个最终 i。要固化值用默认参数 `lambda i=i: i` 或 `functools.partial`。

</Callout>

<Callout type="trap">

**误区：写装饰器不加 functools.wraps**

不加 `@wraps(func)`，wrapper 的 `__name__` 变成 `'wrapper'`、`__doc__` 丢失，调试时看不出原函数是谁，FastAPI 等靠签名反射的框架会失效。这是写装饰器的强制标配。

</Callout>

<Exercises>

**问题 1**：`fns = [lambda: i for i in range(3)]; print([f() for f in fns])` 输出什么？为什么？如何修复？

<Answer>

输出 `[2, 2, 2]`（range(3) 时）。原因：每个 `lambda: i` 是闭包，捕获的是变量 i 的引用，不是迭代时 i 的值。推导式执行完后 i 的最终值是 2，等真正调用 `f()` 时所有闭包都读 i，得到 2。这是「延迟绑定」陷阱。修复用默认参数在定义时固化值：`fns = [lambda i=i: i for i in range(3)]`，输出 `[0, 1, 2]`；或用 `functools.partial(lambda x: x, i)`。本质都是把循环变量在定义时固化，避免闭包延迟读到最终值。

</Answer>

**问题 2**：实现带参装饰器 `@retry(times=3)`，并解释三层嵌套为何必要。

<Answer>

```python
import functools
def retry(times=3):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator
```
三层必要的原因：参数（times）和被装饰函数（func）是两个不同时刻传入——times 在 `@retry(times=3)` 求值时传入，func 在装饰阶段传入，调用的 *args 又是第三个时刻。每一层闭包对应一个参数传入时机：第 1 层接收装饰器参数返回 decorator，第 2 层接收 func 返回 wrapper，第 3 层是实际包装。缺一层就无法区分「装饰器参数」和「被装饰函数」。`@retry(times=3)` ≡ `call_api = retry(times=3)(call_api)`。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="闭包">

延伸了作用域的内部函数，引用外层变量，外层返回后仍可访问。捕获的是变量引用而非值，故延迟绑定。

</GlossaryItem>

<GlossaryItem term="装饰器">

接收函数、返回函数的高阶函数。`@timer` 等价于 `greet = timer(greet)`，把名字重新绑定到 wrapper，wrapper 用闭包捕获原函数。

</GlossaryItem>

<GlossaryItem term="functools.wraps">

装饰器标配，把原函数的 `__name__`、`__doc__`、`__module__` 等元信息复制到 wrapper，避免元信息丢失导致调试和反射失效。

</GlossaryItem>

<GlossaryItem term="循环闭包陷阱">

列表推导式里 `lambda: i` 捕获变量引用，调用时全取循环变量最终值。用默认参数 `lambda i=i: i` 在定义时固化值可修复。

</GlossaryItem>

</Glossary>
