## 直觉引入

想象一条传送带。list 是把所有产品先堆在仓库里再处理——仓库小了就爆。生成器是流水线——产品一个一个过来，处理完即走，任何时刻传送带上只有一件。所以仓库再小也能运转，甚至产品可以「无穷无尽」地来。

`yield` 就是流水线上的暂停按钮：产出一个产品后暂停，等下游喊「下一个」（`next()`）再恢复生产。这让函数能表达无限序列、处理大到放不进内存的数据流，是 Python 数据流处理的核心工具。

读不懂框架里的 `yield`，就读不懂它如何惰性加载、如何流式响应。生成器是把「函数」从「一次性返回」升级为「可暂停的生产线」。

## 概念讲解

### yield 的暂停与恢复

<Term def="yield 产出值后暂停执行并保留栈帧，next() 调用时恢复继续。生成器是可暂停、可恢复的惰性函数。">

生成器是用 `yield` 产出值的函数。调用它不立即执行函数体，而是返回一个生成器对象。`next(gen)` 驱动执行到下一个 `yield`，产出值后**暂停**并保留栈帧（局部变量、执行位置）；再次 `next()` 时**恢复**继续。函数自然结束或遇到 `return` 时抛 `StopIteration` 表示迭代完成。

</Term>

### 惰性与无限序列

生成器是惰性的——每次 `next()` 才计算并产出下一个值，不预生成全部。因此能表达无限序列（`while True: yield ...`），任何时刻内存 O(1)。而 list 必须立即求值所有元素，无限序列会让它无限分配内存。

### 代价

惰性的代价：生成器只能前向迭代一次，耗尽即终止；不支持随机索引（`gen[i]` 非法）、不能取长度（`len(gen)` 非法）、不可切片。需要多次遍历或随机访问时用 list，或用 `itertools.tee` 复制（有内存代价）。

### 生成器管道

多个生成器可串联成惰性管道：`(x for x in gen if cond)` 接在另一个生成器后，中间不产生完整 list。即使源序列有十亿个元素，只要最终只取 N 个，就只计算 N 次所需，内存恒定。

## 代码对照

```python
from itertools import islice

# 生成器：可暂停可恢复
def squares():
    n = 0
    while True:
        n += 1
        yield n * n          # 产出后暂停，next() 恢复

gen = squares()
print(next(gen))             # 1
print(next(gen))             # 4
print(next(gen))             # 9 —— 状态被保留

# 无限序列 + 截取
print(list(islice(squares(), 5)))   # [1, 4, 9, 16, 25]

# 斐波那契生成器
def fib():
    a, b = 0, 1
    while True:
        yield b
        a, b = b, a + b

print(list(islice(fib(), 8)))       # [1, 1, 2, 3, 5, 8, 13, 21]

# 生成器管道：O(1) 内存处理大流
nums = (x for x in range(10**9))            # 不占内存
squares_gen = (x*x for x in nums)           # 仍是生成器
evens = (x for x in squares_gen if x % 2 == 0)
print(list(islice(evens, 5)))               # [0, 4, 16, 36, 64]
# 只计算了取出 5 个偶数平方所需的次数，不生成十亿个

# 生成器表达式 vs 列表推导式
gen_exp = (x*x for x in range(5))   # 惰性，迭代器
list_comp = [x*x for x in range(5)] # 立即，可重复遍历
print(sum(gen_exp))                 # 30
# print(sum(gen_exp))              # 0 —— 已耗尽，只能迭代一次
```

`evens` 管道即使源有十亿元素，也只算了取出 5 个所需的次数。这就是惰性管道的威力——内存恒定，按需计算。

## 常见误区

<Callout type="trap">

**误区：把生成器当 list 反复遍历或下标访问**

生成器是迭代器，耗尽即终止，`gen[i]`、`len(gen)`、切片都非法。`sum(gen)` 第二次调用得 0，因为已耗尽。需要重复遍历或随机访问，先转 list，或用 `itertools.tee`（有内存代价）。

</Callout>

<Callout type="trap">

**误区：在生成器管道里混入 list 打断惰性**

`[x for x in src]` 会立即求值成 list，把十亿元素塞进内存，后续生成器再惰性也没用。管道每一环都要用生成器表达式或生成器函数，任何一环用了 list 就会「断流」、内存暴涨。

</Callout>

<Exercises>

**问题 1**：为什么生成器能处理无限序列而 list 不能？这种能力的代价是什么？

<Answer>

能处理无限序列的原因：生成器惰性——每次 `next()` 才计算产出下一个，不预生成全部。`while True: yield n` 永不结束但内存 O(1)，任何时刻只保留当前状态。list 必须立即求值所有元素，无限序列会无限分配内存，物理不可能。代价：1. 只能前向迭代一次，耗尽即终止，不能反复遍历；2. 不支持随机索引 `gen[i]`；3. 不能取长度 `len(gen)`；4. 不可切片。需要多次遍历或随机访问时用 list，或用 `itertools.tee` 复制（有内存代价）。生成器用「一次性、不可索引」换来「惰性、省内存、可无限」。

</Answer>

**问题 2**：写一个 `fib()` 生成器产出斐波那契数，并说明生成器在管道中的优势。

<Answer>

```python
def fib():
    a, b = 0, 1
    while True:
        yield b
        a, b = b, a + b
from itertools import islice
print(list(islice(fib(), 10)))  # 前 10 项
```
管道优势：生成器可作惰性管道一环，多个变换串联而中间不产生完整 list。`(x*x for x in range(10**9))` 再接 `(x for x in nums if x%2==0)` 再 `islice(..., 10)`，即使源有十亿元素，最终只计算取出 10 个所需的次数，内存恒定。若每步都用 list，中间会生成上亿元素撑爆内存。生成器管道是大数据流处理的核心模式。

</Answer>

<Glossary>

<GlossaryItem term="生成器">

用 `yield` 产出值的函数，返回生成器对象。`next()` 驱动执行到 yield 后暂停、保留栈帧，再次 next 恢复。实现惰性求值。

</GlossaryItem>

<GlossaryItem term="yield">

生成器的关键字，产出值后暂停执行并保留状态，等下次 `next()` 恢复。与 `return` 一次性终止不同，yield 可多次暂停恢复。

</GlossaryItem>

<GlossaryItem term="惰性求值">

不预先计算所有值，按需逐个计算产出。让生成器能处理无限序列、内存 O(1)。代价是不可索引、不可重复遍历。

</GlossaryItem>

<GlossaryItem term="生成器管道">

多个生成器串联成惰性数据流，中间不产生完整 list。即使源序列巨大，只要最终取 N 个就只算 N 次所需，内存恒定。

</GlossaryItem>

</Glossary>
