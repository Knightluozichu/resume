## 从一个错误直觉开始

先预测：只记住继承的利与弊的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

继承的利与弊取决于关系是否稳定。接口继承表达可替换能力，实现继承复用代码却耦合父类内部；当子类只想借一段逻辑时，组合通常让依赖和生命周期更清楚。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

super与内置类型子类化都要求理解协作式调用。super不是固定父类，而是沿当前MRO继续查找；覆盖方法应使用可协作签名。直接子类化dict时某些C级操作可能绕过覆盖方法，UserDict更可预测。
```python
class Root:
    def ping(self): print('root')
class A(Root):
    def ping(self): print('A'); super().ping()
class B(Root):
    def ping(self): print('B'); super().ping()
class Leaf(A, B): pass
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

多重继承与方法解析顺序采用C3线性化，保证局部顺序和单调性。每个协作方法调用super一次并接受兼容参数，才能让菱形结构中的每个实现恰好执行一次。

```python
from collections import UserDict
class DoppelDict(UserDict):
    def __setitem__(self, key, value): super().__setitem__(key, [value, value])
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

Mixin类应提供单一、可复用的行为，不独立实例化，也不拥有复杂状态。名称说明用途，依赖的宿主协议写进文档或类型协议，避免隐式要求某个具体父类。
组合优于继承并非绝对口号：框架要求回调基类、稳定is-a关系可用继承；策略、服务和存储等易变化协作者更适合组合。评审时应画出MRO和对象所有权。
```python
class JsonMixin:
    def as_json(self): return json.dumps(self.to_mapping())
class Report(JsonMixin):
    def to_mapping(self): return {'status': self.status}
```
