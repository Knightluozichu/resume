## 核心模型与责任

运算符重载让领域对象参与Python表达式，但应保持操作数语义和返回类型可预测。不能创建新运算符，也不能改变and、or等关键字；滥用会把简单方法调用变成隐蔽规则。 <Term def="一元运算符plus、minus和abs通常返回新对象，plus可用于触发数值上下文转换。不可变值对象最容易维护运算不变量，原对象不应在看似纯表达式中被修改。">一元运算符</Term>

这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

一元运算符plus、minus和abs通常返回新对象，plus可用于触发数值上下文转换。不可变值对象最容易维护运算不变量，原对象不应在看似纯表达式中被修改。 <Term def="加法、标量乘法与矩阵乘法要分别验证维度和操作数能力。zip_longest可支持不同长度向量，mul接受Real，matmul表达点积或矩阵语义，命名与文档必须一致。">加法、标量乘法与矩阵乘法</Term>

```python
def __neg__(self): return type(self)(-x for x in self)
def __pos__(self): return type(self)(self)
def __abs__(self): return math.hypot(*self)
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

加法、标量乘法与矩阵乘法要分别验证维度和操作数能力。zip_longest可支持不同长度向量，mul接受Real，matmul表达点积或矩阵语义，命名与文档必须一致。 <Term def="反向运算符与富比较形成双分派链：左方法返回NotImplemented后才尝试右方法。eq最终可退回身份比较，排序没有通用默认；异常应在双方都不支持后由解释器产生。">反向运算符与富比较</Term>

<FlpOperatorOverloadingBoundaryLab />

```python
import numbers
def __mul__(self, scalar):
    if isinstance(scalar, numbers.Real): return type(self)(x * scalar for x in self)
    return NotImplemented
def __rmul__(self, scalar): return self * scalar
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

反向运算符与富比较形成双分派链：左方法返回NotImplemented后才尝试右方法。eq最终可退回身份比较，排序没有通用默认；异常应在双方都不支持后由解释器产生。 <Term def="增量赋值运算符若未实现iadd会退回add再绑定；可变对象可实现原地更新。调用者需要知道别名是否观察到变化，因此返回新对象往往更适合值类型。">增量赋值运算符</Term>

增量赋值运算符若未实现iadd会退回add再绑定；可变对象可实现原地更新。调用者需要知道别名是否观察到变化，因此返回新对象往往更适合值类型。 <Term def="用可复现实验判断运算符重载实现是否保持协议、不变量与失败语义。">运算符重载验证边界</Term>

```python
def __matmul__(self, other):
    try: return sum(a * b for a, b in zip(self, other, strict=True))
    except TypeError: return NotImplemented
```

## 代码实验与诊断
