## 从一个错误直觉开始

先预测：只记住接口、协议与ABC的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

接口、协议与ABC覆盖从非正式行为约定到显式运行时抽象的连续谱。参数类型应依赖真正需要的最小能力，避免为了一个len和getitem要求调用者继承庞大基类。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

鸭子类型与猴子补丁强调先尝试行为，也提醒补丁作用域和版本风险。测试中临时替换接口可以，生产代码若依赖第三方私有实现，升级时会失去契约保障。
```python
from collections.abc import MutableSequence
class FrenchDeck2(MutableSequence):
    def __len__(self): return len(self._cards)
    def __getitem__(self, index): return self._cards[index]
    def __setitem__(self, index, value): self._cards[index] = value
    def __delitem__(self, index): del self._cards[index]
    def insert(self, index, value): self._cards.insert(index, value)
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

鹅类型与虚拟子类使用ABC的注册和subclasshook声明结构关系。虚拟子类不会继承实现，isinstance成功也不代表mixin存在，注册者必须承担协议真实满足的责任。

```python
from typing import Protocol, TypeVar
T = TypeVar('T')
class SupportsLessThan(Protocol):
    def __lt__(self, other: object) -> bool: ...
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

静态协议与运行时可检查协议由typing.Protocol表达结构子类型。runtime_checkable只检查属性存在，不验证完整签名；运行时业务校验仍应直接调用并处理失败。
协议设计与数值协议应保持精简、可组合并有明确语义。Complex、SupportsAbs等既展示数值能力，也说明类型层次越大越难实现；客户端协议往往比通用大ABC更稳定。
```python
from typing import runtime_checkable
@runtime_checkable
class Closable(Protocol):
    def close(self) -> None: ...
def shutdown(resource: Closable): resource.close()
```
