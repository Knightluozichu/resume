## 从一个错误直觉开始

先预测：只记住序列特殊方法的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

序列特殊方法应把自定义类型逐步带到协议要求，而不是一开始模仿list。len与getitem提供基础读取，切片返回同类型，动态分量属性和格式化建立领域便利。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

自定义序列与鸭子类型说明协议来自行为：没有继承Sequence也能被迭代和切片。若希望获得index、count等mixin，可继承适合的ABC，但仍要实现核心抽象方法。
```python
import numbers
def __getitem__(self, key):
    if isinstance(key, slice): return type(self)(self._components[key])
    if isinstance(key, numbers.Integral): return self._components[key]
    raise TypeError('indices must be integers or slices')
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

支持切片的getitem必须识别int和slice。slice.indices把负数和越界值规范化；返回切片时构造同类对象，单索引才返回标量，并对非法类型给出准确TypeError。

```python
shortcut_names = 'xyzt'
def __getattr__(self, name):
    pos = self.shortcut_names.find(name)
    if 0 <= pos < len(self._components): return self._components[pos]
    raise AttributeError(name)
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

动态属性访问可用getattr把x、y、z、t映射到分量，但setattr也要阻止只读快捷名被意外创建。属性回退只处理真正缺失的名称，不能吞掉内部错误。
哈希、相等与格式化要覆盖任意维度：用zip比较会截断，必须先比长度；hash可归约各分量；超球面格式应从模长和角度推导并保持数值稳定。
```python
from functools import reduce
from operator import xor
def __hash__(self): return reduce(xor, map(hash, self._components), 0)
def __eq__(self, other): return len(self) == len(other) and all(a == b for a, b in zip(self, other))
```
