## 核心模型与责任

异步编程用单线程事件循环管理大量等待中的I/O任务。async函数调用返回协程对象，只有await、create_task或运行器驱动后才执行；忘记await会留下未运行工作。 <Term def="可等待对象与原生协程包括coroutine、Task和Future。await暂停当前协程而不是线程，让事件循环运行其他就绪任务；长时间不await的CPU循环会阻塞全部任务。">可等待对象与原生协程</Term>

这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

可等待对象与原生协程包括coroutine、Task和Future。await暂停当前协程而不是线程，让事件循环运行其他就绪任务；长时间不await的CPU循环会阻塞全部任务。 <Term def="asyncio、HTTPX与信号量组合并发HTTP请求时，信号量限制在途数量，客户端应复用连接并设置超时。gather保留输入顺序，as_completed按完成顺序流式处理。">asyncio、HTTPX与信号量</Term>

```python
import asyncio
async def probe(url):
    await asyncio.sleep(0.01)
    return url
async def main():
    return await asyncio.gather(*(probe(url) for url in urls))
results = asyncio.run(main())
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

asyncio、HTTPX与信号量组合并发HTTP请求时，信号量限制在途数量，客户端应复用连接并设置超时。gather保留输入顺序，as_completed按完成顺序流式处理。 <Term def="异步上下文管理器、迭代器与生成器分别表达异步获取清理和逐步拉取。async with保证连接归还，async for在每轮允许等待，aclose用于提前终止生成器。">异步上下文管理器、迭代器与生成器</Term>

<FlpAsyncProgrammingBoundaryLab />

```python
semaphore = asyncio.Semaphore(10)
async def bounded_get(client, url):
    async with semaphore:
        response = await client.get(url, timeout=5)
        response.raise_for_status()
        return response.content
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

异步上下文管理器、迭代器与生成器分别表达异步获取清理和逐步拉取。async with保证连接归还，async for在每轮允许等待，aclose用于提前终止生成器。 <Term def="asyncio服务器与阻塞调用的边界最关键：文件、DNS、旧库或CPU工作可能阻塞循环，应使用原生异步API或to_thread，并通过取消、超时和背压关闭任务树。">asyncio服务器与阻塞调用</Term>

asyncio服务器与阻塞调用的边界最关键：文件、DNS、旧库或CPU工作可能阻塞循环，应使用原生异步API或to_thread，并通过取消、超时和背压关闭任务树。 <Term def="用可复现实验判断异步编程实现是否保持协议、不变量与失败语义。">异步编程验证边界</Term>

```python
async def lines(stream):
    async with stream:
        async for line in stream:
            yield line.rstrip()
value = await asyncio.to_thread(blocking_function)
```

## 代码实验与诊断

把三段代码保存为同一最小实验，先运行原始版本，再只改变一个维度。至少检查：公开结果是否稳定、失败是否在正确边界暴露、是否产生意外别名或资源泄漏、类型提示与运行时行为是否一致。观察变化后写出因果解释，而不是只记录输出。
