## 从一个错误直觉开始

先预测：只记住迭代器、生成器与经典协程的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

迭代器、生成器与经典协程都把执行拆成暂停和恢复，但协议用途不同。迭代器按拉取方式产出序列，生成器用yield简化状态机，经典协程还可通过send接收值。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

可迭代对象与迭代器不能混为一谈：iterable能返回新iterator，iterator自身实现next且通常只能消费一次。容器应返回独立迭代器，不要让对象本身在多次循环间共享游标。
```python
class Sentence:
    def __init__(self, text): self.words = text.split()
    def __iter__(self):
        for word in self.words: yield word
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

生成器函数与惰性求值让函数调用先返回生成器对象，直到next才执行函数体。惰性节省内存并支持无限流，但错误可能延迟到消费位置，资源边界也要随迭代关闭。

```python
from itertools import chain, islice
def naturals():
    n = 0
    while True:
        yield n
        n += 1
first_ten = list(islice(naturals(), 10))
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

itertools与yield from提供组合、筛选、分组和子生成器委托。groupby只分组相邻项，tee可能缓存巨大差距；yield from会转发next、send、throw和return值。
经典协程返回值藏在StopIteration.value中，yield from可接收它。现代并发优先原生async协程，但理解经典协议有助于掌握生成器委托和异常传播。
```python
def subgen():
    yield 1
    return 42
def delegating():
    result = yield from subgen()
    print('returned', result)
```
