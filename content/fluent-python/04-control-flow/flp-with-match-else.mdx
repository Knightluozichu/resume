## 从一个错误直觉开始

## 核心模型与责任

with、match与else块把建立清理、结构分派和成功路径写进控制流语法。它们都减少手工标志位，但前提是理解执行顺序、变量绑定和异常传播。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

上下文管理器与contextlib让enter获取资源、exit总能清理。contextmanager把yield前后代码变成进入退出阶段；是否抑制异常由exit返回值决定，默认应传播未知错误。
```python
from contextlib import contextmanager
@contextmanager
def managed(resource):
    try: yield resource
    finally: resource.close()
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

lis.py中的模式匹配展示如何把Scheme表达式按结构分解：原子、quote、if、lambda与函数调用可由不同case表达。模式顺序从具体到宽泛，最后保留明确非法语法分支。

```python
def evaluate(exp):
    match exp:
        case ['quote', value]: return value
        case ['if', test, consequence, alternative]: return evaluate(consequence if evaluate(test) else alternative)
        case [proc, *args]: return apply(evaluate(proc), [evaluate(arg) for arg in args])
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

OR模式要求每个分支绑定同一组变量，可合并共享处理逻辑；守卫只在结构匹配后求值。模式不是普通赋值，类模式还依赖match_args或关键字属性。
if之外的else块出现在for、while和try。循环else只在未break时执行，try else只在主体无异常时执行成功逻辑；把可能抛错的代码限制在try主体可避免捕获过宽。
```python
for item in items:
    if matches(item):
        result = item
        break
else:
    raise LookupError('no match')
```
