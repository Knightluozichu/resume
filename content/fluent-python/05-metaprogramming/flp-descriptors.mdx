## 核心模型与责任

属性描述符是实现get、set或delete协议并作为类属性保存的对象。property、方法、classmethod和许多ORM字段都建立在描述符上，实例点号访问由描述符优先级决定。 <Term def="基于描述符的验证把多个字段共有的正数、非空或类型规则抽出。描述符本身存于类，值应存入各实例；错误消息要包含公开字段名而不是内部存储细节。">基于描述符的验证</Term>

这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

基于描述符的验证把多个字段共有的正数、非空或类型规则抽出。描述符本身存于类，值应存入各实例；错误消息要包含公开字段名而不是内部存储细节。 <Term def="自动存储属性命名可由set_name在类创建时接收owner和name，生成不冲突的私有键。相比手工传字段名，它避免声明重复并支持多个验证描述符共存。">自动存储属性命名</Term>

```python
class Quantity:
    def __set_name__(self, owner, name): self.storage_name = '_' + name
    def __get__(self, instance, owner):
        if instance is None: return self
        return getattr(instance, self.storage_name)
    def __set__(self, instance, value):
        if value <= 0: raise ValueError('must be positive')
        setattr(instance, self.storage_name, value)
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

自动存储属性命名可由set_name在类创建时接收owner和name，生成不冲突的私有键。相比手工传字段名，它避免声明重复并支持多个验证描述符共存。 <Term def="覆盖型与非覆盖型描述符的差异取决于是否实现set或delete。数据描述符优先于实例字典，非数据描述符可能被同名实例属性遮蔽；类属性赋值则可能直接替换描述符。">覆盖型与非覆盖型描述符</Term>

```python
class LineItem:

    price = Quantity()
```

## 机制三：边界条件与成本

覆盖型与非覆盖型描述符的差异取决于是否实现set或delete。数据描述符优先于实例字典，非数据描述符可能被同名实例属性遮蔽；类属性赋值则可能直接替换描述符。 <Term def="方法是描述符：函数的get在通过实例访问时返回绑定方法，自动携带self；通过类访问则返回函数。这个绑定机制也解释了staticmethod和classmethod如何改变默认行为。">方法是描述符</Term>

方法是描述符：函数的get在通过实例访问时返回绑定方法，自动携带self；通过类访问则返回函数。这个绑定机制也解释了staticmethod和classmethod如何改变默认行为。 <Term def="用可复现实验判断属性描述符实现是否保持协议、不变量与失败语义。">属性描述符验证边界</Term>

```python
class Function:
    def __get__(self, instance, owner):
        if instance is None: return self
        return MethodType(self, instance)
```
