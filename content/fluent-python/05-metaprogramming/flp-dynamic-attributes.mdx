## 从一个错误直觉开始

先预测：只记住动态属性与特性的语法，是否足以写出可靠实现？不够。真正需要掌握的是对象、协议、状态和失败路径怎样协作。不是孤立技巧，而是把调用方意图映射到可测试行为的模型。


## 核心模型与责任

动态属性与特性把点号访问连接到计算逻辑，但公开接口应像普通属性一样稳定。属性适合无参数、低成本和可预测访问，昂贵I/O应保留显式方法。
这一章的阅读方法是先写出输入和不变量，再观察解释器或标准库采取哪条路径，最后用反例确认边界。这样学习得到的是可迁移的判断，而不是只能复述示例。

## 机制一：第一条执行链

使用动态属性处理JSON数据可把映射键包装成属性并递归转换嵌套结构。必须处理关键字、非法标识符和缺失字段，并保留原始数据入口，避免神奇访问掩盖输入错误。
```python
class FrozenJSON:
    def __init__(self, mapping): self.__data = dict(mapping)
    def __getattr__(self, name):
        try: value = self.__data[name]
        except KeyError as error: raise AttributeError(name) from error
        return FrozenJSON.build(value)
```

运行后记录对象身份、返回类型和异常位置；再改变一个输入，确认变化来自协议本身，而不是偶然的实现细节。

## 机制二：状态、类型与协作

使用new灵活创建对象发生在init之前，可根据原始数据返回不同类型或完成不可变基类构造。多数场景工厂类方法更直观，只有实例创建协议确实需要控制时才覆盖new。

```python
class LineItem:
    def __init__(self, weight): self.weight = weight
    @property
    def weight(self): return self._weight
    @weight.setter
    def weight(self, value):
        if value <= 0: raise ValueError('weight must be positive')
        self._weight = value
```

评审这段代码时，先问调用端依赖什么能力，再问实现是否扩大了共享状态或静默吞掉错误。接口越小，替换和测试通常越直接。

## 机制三：边界条件与成本

计算特性与缓存特性把派生值放在property或cached_property后。缓存只适合依赖不可变输入或有失效策略的数据；把缓存值写入实例字典会影响后续描述符查找。
属性验证与处理由getter、setter和deleter维护不变量。验证应在赋值边界失败并给出字段上下文，多个字段联合约束则适合显式命令或不可变构造。
```python
from functools import cached_property
class Record:
    @cached_property
    def total(self):
        return sum(load_expensive_values(self.id))
```
