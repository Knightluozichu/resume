## 直觉引入

把一个前端项目想象成一条流水线。你先要把原材料加工成成品——源码怎么编译打包成可部署的产物（构建）；然后质检——代码类型对不对、规范好不好、测试过不过（质量）；接着自动出货——推送代码就自动检查、构建、部署（CI/CD）；最后售后跟踪——线上快不快、有没有报错（监控）；发现问题再回到生产线改进。本书回答的就是这些「从能写代码到能交付上线并持续改进」的工程问题。

## 四阶段闭环

<Term def="以构建工具打包产物、质量保障防错、CI/CD 自动交付、线上监控驱动改进的分层闭环体系。所有前端工程化实践都在这四层之上运转。">前端工程化体系</Term>的学习可以拆成四个递进阶段。**构建体系**包括构建工具演进与模块联邦——它们解决「源码怎么变成可部署产物」和「大型应用怎么拆分独立交付」，是所有上层的基底。**质量保障**包括 TypeScript/ESLint 与测试策略——它们决定「编码期能拦住多少错误」和「逻辑能不能被验证」。**持续交付**包括 CI 流水线与部署策略——它们让代码「能自动检查与构建」和「能安全发布与回滚」。**线上监控**包括性能监控与错误追踪——它们让团队「能看见线上体验」和「能定位线上异常」。

```yaml
# 一次「代码提交 → 构建产物 → 质量检查 → 自动交付 → 线上监控 → 改进」的工程化旅程
# 1. 构建层：Vite 把 TSX 编译打包成产物（第 2 章）
#    大型应用用 Module Federation 拆分独立交付（第 3 章）
vite build  # 产出 dist/ + SourceMap

# 2. 质量层：类型检查 + 规范扫描 + 测试（第 4-5 章）
tsc --noEmit && eslint . && vitest run

# 3. 交付层：CI 自动化 + 部署策略（第 6-7 章）
#    git push → GitHub Actions → Lint/Test/Build → 灰度发布
git push origin main

# 4. 监控层：性能 + 错误追踪（第 8-9 章）
#    web-vitals 采集 LCP/INP/CLS → Sentry 捕获异常 → SourceMap 还原
#    发现问题 → 回到代码改进 → 重新走上述流程
```

## 常见误区

<Callout type="trap">
**误区：会用框架写页面就等于懂前端工程化。** 写组件、调 API、搭页面只是表层——照文档抄就会。真正的难点在工程化判断力：构建产物为什么体积大、分包策略对首屏的影响；类型安全边界怎么划才不致 any 满天飞；测试该覆盖哪些路径、覆盖率多少才有意义；CI 流水线怎么编排才能又快又可靠；部署出问题怎么秒级回滚；线上白屏怎么靠 SourceMap 还原定位。这些是「项目跑起来后」才显现的问题，也是中高级面试与生产实战的真正考点。把写页面当终点的人，做的应用能跑但难维护；把工程化当核心的人，才能做出可控、可交付、可观测的前端项目。
</Callout>

## 小结与练习

<Exercises>
**问题 1**：全书四阶段闭环是什么？为什么是这个顺序？

<Answer>
构建 → 质量 → CI/CD → 监控 → 回到代码改进。顺序由依赖关系决定：没有构建就没有可部署的产物（源码无法直接上线）；没有质量保障就敢上线只会制造故障（类型与测试拦在编码期）；没有 CI/CD 就无法可靠地反复交付（手动部署易错且慢）；没有监控就不知道线上发生了什么（性能退化与错误无人知晓）。先「能打包」，再「能防错」，然后「能自动交付」，接着「能观测」，最后「驱动改进」回到代码，形成闭环。
</Answer>

**问题 2（综合题）**：用「一次代码提交到线上改进」的旅程，说明全书十章各自扮演什么角色。

<Answer>
开发者提交代码：①构建工具——Vite/Webpack 把源码编译打包成产物（第 2 章）；②模块联邦——大型应用拆成独立微前端各自构建交付（第 3 章）；③TypeScript/ESLint——提交前类型检查与规范扫描拦截低级错误（第 4 章）；④测试策略——单元/集成/E2E 验证逻辑正确（第 5 章）；⑤CI 流水线——git push 触发自动 Lint/Test/Build（第 6 章）；⑥部署策略——蓝绿/灰度安全发布到线上（第 7 章）；⑦性能监控——Web Vitals 采集真实用户体验（第 8 章）；⑧错误追踪——Sentry 捕获线上异常、SourceMap 还原源码（第 9 章）。学习地图（第 1 章）给方向，总复习（第 10 章）串闭环。
</Answer>
</Exercises>

<GlossaryItem term="四阶段闭环">构建（打包产物）→ 质量（类型/规范/测试）→ CI/CD（自动化交付）→ 监控（性能/错误追踪）→ 改进（回到代码）。每层解决前一层的遗留问题：构建层有产物但可能有错，质量层补防错；质量层防了错但交付靠手动，CI/CD 补自动化；CI/CD 能交付但不知道线上好坏，监控补观测；监控发现问题再回到代码，形成闭环。</GlossaryItem>
