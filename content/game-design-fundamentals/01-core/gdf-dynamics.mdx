## 直觉引入

象棋的规则只有几页纸，但产生的棋局变化比宇宙原子还多。规则是机制，棋局变化是动态。设计师写规则，但不对每种棋局负责——棋局是规则「自己长出来的」，这就是涌现。

涌现是游戏设计的魔法：简单的规则产生复杂的行为。但魔法有时会失控——玩家可能发现你没想到的「最优策略」破坏游戏乐趣。设计师的任务是引导好的涌现，抑制坏的涌现。

## 概念讲解

### 动态的形成

<GdfDynamicsDiagram />

<Term def="机制在运行时通过玩家交互和系统运算产生的行为模式">动态</Term>是机制的「运行态」。跳跃力+重力+平台布局=玩家学会连续跳跃过平台。单个机制不产生动态，动态来自机制间的交互和玩家策略。

<Term def="简单规则组合后产生的、设计师未显式编程的复杂行为">涌现</Term>是动态的核心特征。涌现分为正向涌现（丰富游戏深度，如速通、卡位战术）和负向涌现（破坏游戏体验，如无限循环Bug、逃课打法）。

### 动态的层次

动态有三个层次：微观动态（单次操作行为，如跳劈）、中观动态（短期策略，如连招组合）、宏观动态（长期博弈，如经济运营、Meta 策略）。

## 代码对照

```csharp
// 涌现行为示例：跳跃+攻击+暴击的组合
public class CombatDynamics {
    public float jumpForce = 7f;
    public float attackDamage = 10f;
    public float critMultiplier = 2f;
    public float airAttackBonus = 1.5f; // 空中攻击加成
    
    // 设计师只写了这些机制，但玩家发现：
    // 跳起 → 空中攻击（1.5x）→ 触发暴击（2x）= 3x 伤害
    // 这是涌现行为——设计师没写「空中暴击连招」
    // 但三个机制组合自然产生了这个策略
}
```

## 常见误区

<Callout type="trap">
**现象：试图预测所有涌现行为，过度设计规则。**
原因：涌现的本质是不可完全预测，试图控制一切会扼杀创意。修法：接受涌现的不确定性，通过测试发现涌现行为，而非试图在设计中穷举。保留「好的意外」，修补「坏的意外」。
</Callout>

<Callout type="trap">
**现象：发现负向涌现就加规则禁止。**
原因：加禁止规则会让玩家感觉受限，且可能产生新的负向涌现。修法：优先调参数（降低收益）而非加禁令。让正道玩法更有吸引力，而非禁止偏门玩法。
</Callout>

<Exercises>
**问题 1**：什么是涌现行为？正向涌现和负向涌现的区别是什么？

<Answer>
涌现行为是简单规则组合后产生的、设计师未显式编程的复杂行为。正向涌现增加游戏深度和乐趣（如速通、连招、卡位战术），负向涌现破坏游戏体验（如逃课打法、无限循环Bug、经济崩溃）。区别在于：正向涌现让游戏更有趣，鼓励玩家探索；负向涌现让游戏失去挑战或平衡，让玩家觉得无聊或不公平。
</Answer>

**问题 2**：发现负向涌现时，为什么优先调参数而非加禁令？

<Answer>
加禁令直接禁止玩家行为，让玩家感觉受限，且可能在禁令的边缘产生新的负向涌现。调参数（如降低逃课收益、增加正道奖励）让玩家自然选择正道玩法，不感觉受限。设计原则是「引导而非禁止」——让正确的玩法成为最优选择，而非禁止错误玩法。这样既保留了玩家自由，又引导了期望的动态行为。
</Answer>
</Exercises>
