## 直觉引入

游戏机制就像物理定律——它们定义了游戏世界里什么能做、什么不能做。跳跃力决定了你能跳多高，重力决定了你会落下来。玩家在机制定义的「物理定律」下探索可能性，就像现实中的人在物理定律下发明飞机。

好的机制给玩家大行为空间但清晰的边界。坏的机制要么限制太多（玩家无事可做），要么限制太少（玩家不知道该做什么）。

## 概念讲解

### 机制分类

<GdfMechanicsDiagram />

<Term def="游戏的基础规则系统，定义玩家能做什么操作以及系统如何响应">游戏机制</Term>可分为：基础机制（移动/跳跃/攻击）、经济机制（资源获取/消耗/交易）、进度机制（经验/等级/解锁）、状态机制（生命/Buff/Debuff）。

<Term def="机制允许的所有合法操作的集合，即玩家在规则框架内能探索的可能性范围">行为空间</Term>是评价机制好坏的核心指标。行为空间太大=玩家迷茫；太小=玩家无聊。好的机制设计让行为空间「大而有界」——可能性丰富但边界清晰。

### 机制设计原则

机制设计的三原则：一致性（同样的输入产生同样的输出）、可读性（玩家能理解机制如何运作）、深度（简单机制能组合出复杂策略）。

## 代码对照

```csharp
// 机制设计：跳跃系统的参数定义
public class JumpMechanics {
    // 基础参数
    public float jumpForce = 7f;       // 跳跃力（决定能跳多高）
    public float gravity = -20f;        // 重力（决定下落速度）
    public int maxJumps = 2;            // 最大跳跃次数（二段跳）
    public float coyoteTime = 0.15f;    // 土狼时间（离开平台后仍可跳）
    
    // 这些参数定义了行为空间：
    // - jumpForce=7 → 能跳到 2.45 单位高
    // - maxJumps=2 → 二段跳扩展可达范围
    // - coyoteTime → 容错率，鼓励冒险
}
```

## 常见误区

<Callout type="trap">
**现象：机制太多太复杂，玩家学不会。**
原因：认知负荷过载，玩家无法理解所有规则。修法：核心机制控制在 3-5 个以内，新机制逐步引入。每个新机制必须有教学关卡，让玩家在实践中学会。
</Callout>

<Callout type="trap">
**现象：机制之间没有交互，各玩各的。**
原因：好的机制应该能组合产生涌现行为。相互独立的机制浪费了行为空间。修法：设计机制时思考组合可能性——跳跃+攻击=跳劈，重力+风力=滑翔。机制组合越丰富，行为空间越深。
</Callout>

<Exercises>
**问题 1**：什么是行为空间？如何评价机制的好坏？

<Answer>
行为空间是机制允许的所有合法操作的集合，即玩家在规则框架内能探索的可能性范围。评价机制好坏看行为空间的「大而有界」——可能性丰富但边界清晰。行为空间太大玩家迷茫（不知道该做什么），太小玩家无聊（没选择）。好机制让玩家在有限规则下发展出丰富的策略。
</Answer>

**问题 2**：机制设计的三原则是什么？

<Answer>
一致性：同样的输入产生同样的输出，玩家能建立可靠的心智模型。可读性：玩家能理解机制如何运作，能预测操作结果。深度：简单机制能组合出复杂策略，新手老手都能找到乐趣。三原则缺一不可——不一致的机制让玩家沮丧，不可读的机制让玩家迷茫，没深度的机制让玩家很快厌倦。
</Answer>
</Exercises>
