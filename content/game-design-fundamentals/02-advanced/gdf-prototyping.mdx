## 直觉引入

你有一个绝妙的游戏点子。与其花半年写代码再发现不好玩，不如花半天用纸和笔做个原型测一下。如果纸面版本都不好玩，做成电子游戏也不会好玩。原型设计的核心是「用最小成本验证最大风险」。

好的设计师不是一次做对的人，而是最快发现错误的人。迭代不是「改到完美」，而是「快速试错，保留有效部分，丢弃无效部分」。

## 概念讲解

### 原型分类

<GdfPrototypingDiagram />

<Term def="用纸和笔模拟游戏机制的最低成本原型，用于快速验证核心玩法">纸面原型</Term>是游戏设计的基础工具。用纸片当角色、画网格当地图、手写规则当机制。成本低、修改快、不需要编程。

<Term def="用代码实现的可交互原型，验证纸面原型无法测试的实时操作和视觉反馈">数字原型</Term>在纸面验证核心玩法后使用，用最简代码实现核心循环，不加美术和音效。

### 迭代设计流程

<Term def="「设计→原型→测试→分析→修改」的循环过程，每轮迭代减少不确定性">迭代设计</Term>是现代游戏开发的核心方法。每轮迭代回答一个关键问题：这个机制好玩吗？这个难度合适吗？这个引导有效吗？

## 代码对照

```csharp
// 数字原型：最简核心循环
public class PrototypeCore : MonoBehaviour
{
    // 只实现核心机制，不加美术/音效/菜单
    void Update()
    {
        // 移动
        if (Input.GetKey(KeyCode.Space)) 
            transform.position += Vector3.up * 5f * Time.deltaTime;
        // 重力
        transform.position += Vector3.down * 10f * Time.deltaTime;
        // 碰撞检测（用最简 AABB）
        if (CheckCollision(transform.position))
            Debug.Log("Hit!"); // 只打 Log，不加特效
    }
    // 目标：2 小时内跑通核心循环，验证好不好玩
}
```

## 常见误区

<Callout type="trap">
**现象：跳过原型直接做完整游戏。**
原因：原型看似浪费时间，实则是节省时间——在纸面发现不好玩只需改纸，在代码中发现需要重构。修法：任何新机制先用纸面原型验证，再写代码。纸面原型 1 小时能验证的，代码可能要 1 天。
</Callout>

<Callout type="trap">
**现象：原型做太精细，加美术和音效。**
原因：原型的目的是验证玩法，不是做成品。加美术音效浪费时间且干扰判断。修法：数字原型用灰盒（纯色方块），不加音效，不加菜单。只实现核心循环。确认好玩后再加生产价值。
</Callout>

<Exercises>
**问题 1**：为什么纸面原型在游戏设计中仍然重要？

<Answer>
纸面原型用纸和笔模拟游戏机制，成本低（纸和笔）、修改快（擦掉重画）、不需要编程（设计师独立完成）。它的价值在于：5-10 分钟就能测试一局，1 小时能验证多个设计变体。如果纸面版本都不好玩，做成电子游戏也不会好玩——因为核心玩法的问题不会因为加美术音效而解决。纸面原型让设计师用最小成本验证最大风险。
</Answer>

**问题 2**：什么是迭代设计？每轮迭代应该聚焦什么？

<Answer>
迭代设计是「设计→原型→测试→分析→修改」的循环过程，每轮迭代减少不确定性。每轮迭代应聚焦一个关键问题：这个机制好玩吗？这个难度合适吗？这个引导有效吗？不聚焦多个问题因为无法判断哪个改动导致了什么效果。通常 5-10 轮迭代才能从「可能有潜力」到「确认好玩」。迭代不是「改到完美」而是「快速试错，保留有效的，丢弃无效的」。
</Answer>
