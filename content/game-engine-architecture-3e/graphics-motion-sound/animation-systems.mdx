## 角色奔跑时突然停下——脚还在滑

你可以试试：在任何 3D 游戏里让角色按住前跑步，然后突然松开。如果动画和移动速度不匹配，你会发现角色的脚在地上"滑冰"——动画在播跑步但角色已经不移动了，或者反过来。

<Term def="动画逻辑的有限状态机。每个状态是一个动画 Clip（Idle/Run/Jump），状态之间的切换由参数（Speed/IsAirborne）触发。">动画状态机</Term>定义了"什么条件下播什么动画"——Speed > 0.5 → 从 Idle 切换到 Run，IsAirborne = true → 强制切换到 Jump。但状态机只能选一个动画，不能同时混合两个动画——这里就需要 <Term def="按参数（速度、转向角）混合多个动画的树形图。例如 Idle 和 Run 按速度线性混合：速度=0 全是 Idle，速度=1 全是 Run，速度=0.3 = 30% Run + 70% Idle。">Blend Tree</Term>。

<GameEngineAnatomyDiagram chapter="animation" />

<Stepper>
  <Step title="资源和状态机决定播放意图">状态机根据当前参数（Speed, IsAirborne）决定"应该播哪个 clip 或哪些 clip 混合"。</Step>
  <Step title="混合与采样生成骨骼姿态">Blend Tree 把多个 clip 的动画按权重混合。骨骼采样从每个 clip 里提取当前时间的那一帧姿态，加权平均后生成最终 local pose。</Step>
  <Step title="姿态输出并回写运动">Pose 被传给渲染做蒙皮（顶点跟着骨骼动）。Root Motion 把动画里的根骨骼位移提取出来回写到角色世界位置，让移动量和动画步幅一致——消灭滑步。</Step>
</Stepper>

**Root Motion 冲突**是动画和物理的经典战场：动画说"我这帧往前走了 0.5 米"，物理说"你撞墙了不能走"。两个系统都想写 Transform。解决方案是明确阶段——物理先跑 → 物理结果做墙壁约束 → 动画在约束后的位置上叠加 Root Motion → 最终 Transform。

## 容易踩的坑
- **现象 ->** 状态切换时有 0.1 秒的"闪一下"。**原因 ->** 状态切换没做过渡混合——直接从 Idle pose 跳到 Run pose。**修法 ->** 状态切换加 Crossfade（交叉淡入淡出 0.1-0.2 秒）。
- **现象 ->** 角色在斜坡上 Root Motion 导致脚陷进地里。**原因 ->** Root Motion 是水平位移，没有考虑地面高度变化。**修法 ->** Root Motion 之后再做一次"贴地"——沿重力方向投射到地面。

## 小结
- 动画状态机 = "播什么"的决策层
- Blend Tree = 按参数混合多个动画，产出平滑过渡
- 骨骼采样 = 从 clip 里取关键帧插值出当前姿态
- Root Motion = 让动画驱动角色位移，消灭滑步
- 动画和物理共享 Transform——前者先跑、后者修正、动画叠加

<Glossary>
<GlossaryItem term="动画状态机">根据输入参数选择当前播放动画的有限状态机。Idle/Run/Jump 之间的切换由 Speed/IsAirborne 等参数触发。</GlossaryItem>
<GlossaryItem term="Blend Tree">按参数（速度、方向角）混合多个动画的树形结构。让 Walk 和 Run 之间平滑过渡。</GlossaryItem>
<GlossaryItem term="Root Motion">从动画中提取根骨骼的位移，回写到角色世界位置。让移动速度和动画步幅匹配。</GlossaryItem>
<GlossaryItem term="蒙皮">根据骨骼姿态变换每个顶点的位置。GPU 顶点着色器用蒙皮矩阵把顶点从"绑定姿势"变换到"当前姿势"。</GlossaryItem>
</Glossary>
