## 场景太复杂，帧率从 60 掉到 20，物理开始乱飞

这是真实发生过的事。某开放世界项目在发售前一个月的性能测试中发现：在城镇密集区帧率掉到 25fps，而物理模拟的行为和稳定 60fps 时完全不同——角色有时穿墙，投掷物轨迹偏移，赛车物理手感飘忽。QA 复现都复现不了，因为每次掉帧的模式都不同。

原因：所有子系统都用**变步长**（每帧的实际 dt 不一样），物理模拟的稳定性严重依赖 dt 的恒定。dt 从 16.67ms 跳到 40ms 时，物理积分误差被放大，同一个输入产生不同结果。

解决方案：**混合循环**——物理和部分核心逻辑用固定步长，渲染和表现用变步长。

## 三种游戏循环策略

| 策略 | dt 来源 | 优点 | 致命缺陷 |
|------|---------|------|---------|
| 纯变步长 | 每帧实际 dt | 简单，CPU 空闲时不浪费 | dt 抖动 → 物理不稳定 |
| 纯固定步 | 固定 dt（如 1/60s） | 物理完全确定可复现 | 帧率低时出现慢动作 |
| 混合（业界标准） | 物理固定 dt，渲染变步 | 物理稳定 + 画面流畅 | 实现稍复杂，需要插值 |

混合循环的骨架：

<CodeTabs>
  <Tab label="C++ 混合游戏循环">

```cpp
// 业界标准：固定步模拟 + 变步渲染
const float FIXED_DT = 1.0f / 60.0f; // 16.67ms
float accumulator = 0.0f;

while (running) {
    float frameDt = clock.CalcDeltaTime();

    // 防止 spiral of death
    if (frameDt > 0.25f) frameDt = 0.25f;

    accumulator += frameDt;

    // 固定步长模拟：不够就多跑几次
    while (accumulator >= FIXED_DT) {
        physics.Step(FIXED_DT);
        gameplay.Update(FIXED_DT);
        accumulator -= FIXED_DT;
    }

    // 变步渲染：用插值因子让画面流畅
    float alpha = accumulator / FIXED_DT;
    renderer.Render(alpha);
    window.SwapBuffers();
}
```

## Spiral of Death：蝴蝶效应

所谓"死亡螺旋"，是这样的连锁反应：帧 A 复杂，超过 16.67ms → 帧 B 的 accumulator 更大 → 需要更多的物理 step 来追上 → 帧 B 也超预算 → accumulator 越来越大 → 越来越超预算 → 帧率跌到个位数。打破循环的核心就是 `frameDt > 0.25f ? 0.25f : frameDt`——强制截断，宁可丢一帧的真实时间也不能让 accumulator 无限涨。

## 容易踩的坑

- **现象 ->** 30fps 下物理"重量感"很足，60fps 下轻飘飘。**原因 ->** 物理 dt 被实际帧率拖动了，60fps 下 dt 更小 = 力作用的时间更短 = 冲量更小。**修法 ->** 物理永远用固定 dt，保证力的冲量恒定。

- **现象 ->** vsync 关了帧率飙到 300，代码里每帧加了粒子，CPU 100% 占用。**原因 ->** 游戏循环没有做帧率限制——"能跑多快跑多快"纯浪费电。**修法 ->** 加上帧率 cap > 游戏循环的最大迭代频率。

## 小结

- 混合循环 = 固定步模拟 + 变步渲染：业界标准
- 固定 dt 保证物理可复现——同样输入永远同样结果
- Spiral of Death：帧超预算 → 需要多步追 → 更超预算 → 死循环，用 dt 截断防
- 渲染用 alpha 插值因子——在两次物理 step 之间平滑画面
- 帧预算管理：预留 headroom 而非挤满 100%

## 名词解释

<Glossary>
  <GlossaryItem term="固定步长">物理模拟每步固定时间间隔（如 1/60s），不受帧率波动影响。保证模拟可复现。</GlossaryItem>
  <GlossaryItem term="Spiral of Death">一帧超预算 → 下一帧需要多步模拟来追 → 更超预算 → 恶性循环。用 dt 上限截断来打破。</GlossaryItem>
  <GlossaryItem term="插值因子（alpha）">累加器 / 固定dt 的比值。渲染用它在两次物理 step 之间插值位置和姿态，让低帧率画面也流畅。</GlossaryItem>
  <GlossaryItem term="变步长">每帧按实际时间间隔推进。简单但不稳定——物理行为随帧率变化。</GlossaryItem>
</Glossary>
