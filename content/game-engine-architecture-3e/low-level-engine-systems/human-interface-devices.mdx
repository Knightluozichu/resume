## 手柄摇杆在中心位置，角色还在自动走

这是一个经典手柄 Bug：玩家把手柄放桌上，摇杆在物理中立位置，但角色还在微微往前蹭。原因是摇杆的模拟量不是完美的 0——它在 0.002 到 0.008 之间微小漂移。如果输入系统不加<Term def="摇杆中心附近一定范围内的微小输入被视为零。防止摇杆物理漂移导致角色自动移动。">死区</Term>，这个噪音就会变成持续输入。

<Term def="把不同设备（键盘的 W、手柄的左摇杆 Y+、触屏的向上滑）映射到同一个抽象动作（MoveForward），玩法代码只关心动作不关心设备。">动作映射</Term>是输入系统最核心的一层抽象。它的逻辑很简单：玩法代码不应该知道玩家用的是键盘还是手柄。键盘 W = MoveForward、手柄左摇杆上 = MoveForward、触屏上滑 = MoveForward——玩法只调 `GetActionValue("MoveForward")`。

输入系统的四层流水线：

1. **设备驱动层**：从操作系统收原始事件（按键码、摇杆原始值、触摸坐标、鼠标位移）
2. **采样/去抖层**：把原始事件按帧时间戳收集，去抖动——同一帧内多次按键当成一次处理
3. **归一化层**：把不同设备的原始值归一化到统一范围（如 -1 到 1）。摇杆加死区，鼠标加灵敏度
4. **动作映射层**：把归一化后的设备值映射到"动作"——`MoveForward`、`Jump`、`Aim`、`Fire`

  </Step>
  <Step title="归一化——抹平设备差异">

  </Step>
  <Step title="动作驱动玩法并触发反馈">
    归一化后的值映射到动作 → 玩法逻辑消费动作改变世界状态 → 渲染、音效、震动把结果反馈给玩家。输入链路在这一步闭合。

**输入延迟**不只是"按钮到画面"的时间。从物理按下按键到屏幕上角色起跳，中间经过了：USB 轮询周期(1-8ms) → OS 输入栈(1-2ms) → 引擎采样(0-16ms，取决于在哪一帧采到) → 逻辑运算(0-3ms) → 渲染(0-16ms) → 显示扫描(0-16ms)。总和可以超过 50ms——在格斗游戏里这个延迟已经影响胜负。

## 容易踩的坑

- **现象 ->** PC 版支持手柄和键盘，但两个设备的按键配置各自一套，维护成本翻倍。**原因 ->** 没有统一的动作映射层。**修法 ->** 所有设备映射到同一套"动作"，改键 → 只改映射表。键盘的 Space 和手柄的 A 都映射到 Jump。

- **现象 ->** 触屏设备上虚拟摇杆比物理手柄延迟高很多。**原因 ->** 触控的"滑动"需要在 OS 层判断滑动手势（不是点击），这本身就比物理按键多一层滤波延迟。**修法 ->** 用低延迟触控 API（如 Apple Pencil 的预测触摸），或接受触控输入比物理按键多 20-40ms 延迟的现实。

## 小结

- 动作映射 = 把具体设备抽象为统一动作，玩法代码一劳永逸
- 死区 = 滤掉摇杆的物理漂移噪音
- 归一化 = 不同设备的量程映射到统一的 -1 到 1
- 输入延迟 = USB + OS + 采样 + 逻辑 + 渲染 + 显示 = 可达 50ms+
- 低延迟输入和物理准确性一样重要——在竞技游戏里延迟决定胜负
- 震动/音效反馈是"闭合输入回路"的最后一步

  <Answer question="你有一个赛车游戏，用键盘 WASD 开车。为什么键盘开车感觉是“0 或 1”而不能像手柄一样慢慢打方向？怎么改善？">
    键盘是数字输入——按或不按，没有中间值。手柄摇杆是模拟输入——从 0 到 1 平滑过渡。改善键盘手感：给键盘输入加"虚拟模拟"——例如检测到 A 键按住后，转向值从 0 在 0.3 秒内渐进达到 1（曲线加速），松开后渐进归零。这样键盘也能有类似摇杆的"轻打"和"重打"手感。

## 名词解释

<Glossary>
  <GlossaryItem term="动作映射">把不同物理设备（键盘/手柄/触屏）的输入事件映射到统一的抽象动作（Jump/Fire/Move）。玩法代码只关心动作名，不关心设备类型。</GlossaryItem>
  <GlossaryItem term="死区">摇杆中心附近一小区间内的模拟值被当做 0 处理。防止摇杆物理漂移（0.002 微偏）导致角色自动移动。</GlossaryItem>
  <GlossaryItem term="归一化">把不同设备的原始输入范围（手柄摇杆 -32768~32767、鼠标 0~DPI）映射到统一范围（-1~1），让动作映射层能统一处理。</GlossaryItem>
  <GlossaryItem term="去抖">一帧内有多次同一按键事件时只报告一次。防止操作系统或设备驱动的重复事件导致一帧内多次触发。</GlossaryItem>
  <GlossaryItem term="输入延迟">从物理按下到画面响应的时间。来源：USB 轮询 → OS 输入栈 → 引擎采样 → 逻辑 → 渲染 → 显示扫描。</GlossaryItem>
</Glossary>
