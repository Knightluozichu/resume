## 层级让变换可组合

游戏里一个角色拿一把枪，枪要跟着角色走、跟着手转。如果每帧手算枪的世界位置会很痛苦。变换系统用一棵<Term def="场景图是有向树，每个节点存局部变换（相对父节点），世界变换通过父链递归累积。">场景层级树</Term>解决：枪是手的子节点、手是角色的子节点、角色是世界的子节点。每个节点只存「相对父节点」的局部变换，世界变换由父链递归累积。

## 世界矩阵的累积

子节点的世界矩阵 = 父节点世界矩阵 × 子节点局部矩阵。用数学表达：

$$M_{world}^{child} = M_{world}^{parent} \times M_{local}^{child}$$

每个节点的局部变换用 <Term def="TRS 把变换分解为平移 T、旋转 R、缩放 S 三个独立分量，组合成 M = T × R × S，便于编辑器和动画分别控制。">TRS 分解</Term>：平移 T、旋转 R（四元数）、缩放 S，组合成 $M_{local} = T \times R \times S$。这个分解让编辑器可以独立调三个分量，也方便动画系统分别插值。

```cpp
// 自顶向下递归更新世界矩阵
void SceneNode::UpdateWorld(const Mat4& parentWorld, bool parentDirty) {
    bool dirty = parentDirty || localDirty_;
    if (dirty) {
        worldMatrix_ = parentWorld * localMatrix_;  // 累积
        worldDirty_ = true;  // 通知子节点重算
    }
    for (auto& child : children_) {
        child->UpdateWorld(worldMatrix_, dirty);
    }
}
```

## 坐标空间变换链

一个顶点从模型到屏幕，要经过四个空间：局部空间 × Model → 世界空间 × View → 观察空间 × Projection → 裁剪空间 → 透视除法 → 屏幕空间。其中 Model 矩阵就是变换系统算出的世界矩阵，View 是摄像机的逆世界矩阵。变换系统的工作就是把这些矩阵准备好交给渲染管线。

## 脏标记优化

如果每帧重算所有节点的世界矩阵，上千个节点是浪费。用脏标记：只有局部变换改变时标记 `localDirty`，父节点 dirty 才递归标记子节点 dirty。没标记的节点直接用缓存的世界矩阵。大部分静态物体（建筑、地形）永不变 dirty，零开销。

<Callout type="trap">
**坑：TRS 顺序写错。** $M = T \times R \times S$ 是「先缩放、再旋转、再平移」，如果写成 $S \times R \times T$ 会先平移再缩放，物体位置会被缩放拉偏。TRS 顺序是约定俗成的，必须统一。
</Callout>

<Exercises>
**问题 1**：父节点移动后，子节点的世界矩阵为什么必须重算？局部矩阵需要改吗？

<Answer>
世界矩阵 = 父世界 × 子局部。父节点移动改变了父世界矩阵，所以子世界矩阵必须重算。但子节点的局部矩阵（相对父节点的偏移）不需要改——子节点「跟着父节点走」正是层级的目的。这就是脏标记传播：父 dirty 则子 worldDirty，但子的 localDirty 不变。
</Answer>

**问题 2**：为什么 View 矩阵是摄像机世界矩阵的逆？

<Answer>
View 矩阵的作用是把世界空间变换到观察空间（摄像机视角）。摄像机的世界矩阵把摄像机从原点变换到它在场景中的位置和朝向。要把世界「看」成摄像机视角，就是做这个变换的逆——把摄像机移回原点，整个世界跟着反向移动。所以 $M_{view} = M_{cameraWorld}^{-1}$。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="局部变换">节点相对父节点的变换（TRS），是设计师在编辑器里直接设置的值。</GlossaryItem>
<GlossaryItem term="世界变换">节点相对世界原点的绝对变换，由父链递归累积得到，交给渲染管线使用。</GlossaryItem>
<GlossaryItem term="脏标记">记录数据是否过期需要重算的标志。变换系统用它跳过未改变节点的重算，把 O(n) 每帧重算降到 O(改变的节点数)。</GlossaryItem>
</Glossary>
