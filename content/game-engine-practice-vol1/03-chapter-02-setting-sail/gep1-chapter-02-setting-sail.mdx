## 为什么基础框架要从状态和证据开始

第2章 起航承担 **起航章建立编程、编辑器、数学、空间、图形API、汇编与生产工作流的全景入口。** 本课程不复制原书正文、插图或配套代码，而把目录中的示例引擎机制重构为状态合同、可运行实验、故障样本与验收工件。本页逐项覆盖13个目录坐标：第2章 起航、2.1 游戏编程、2.2 游戏引擎的组成、2.3 游戏引擎编辑器的组成、2.4 数学、2.5 空间变换、2.5.1 坐标系、2.5.2 不同空间的转换、2.6 3D流水线、2.7 OpenGL和DirectX、2.8 汇编指令、2.9 引擎工作流、练习。

引擎基础框架不是模块名称集合。内存分配器决定对象能否安全创建，反射决定对象如何进入工具与存储，资源代理决定异步内容能否稳定引用，场景结构决定每帧查询规模，LOD又把视觉误差换成时间和带宽。任何一层缺少身份、生命周期或失败语义，问题都会在更高层以随机崩溃、错误画面或帧抖动出现。

对象身份把反射、序列化、克隆与复制串在一起；资源代理让对象不直接依赖加载地址；场景节点把空间与生命周期组织起来；屏幕误差则给LOD一个可测目标。属性反射必须和版本迁移、权限、编辑事务一起设计，不能只做“根据字符串找字段”。

## 四个可复算指标

端到端帧时间保留CPU/GPU重叠与等待：

$$
T_{frame} = max(T_{update}, T_{render}) + T_{wait}
$$

按对齐要求申请内存后的实际尺寸为：

$$
A(n,a) = lceil n/a
ceil a
$$

资源缓存命中率必须按真实请求计算：

$$
H = N_{hit} / N_{request}
$$

LOD用投影误差连接世界误差、焦距、距离与屏幕高度：

$$
e_{screen} = e_{world} f / (z h)
$$

帧时间要报告P50、P95和P99；内存要报告峰值、碎片和生命周期；命中率要区分预热与冷启动；LOD还要观察切换抖动、轮廓破坏和纹理带宽。公式只建立可复算口径，不替代目标设备上的视觉与性能验收。

```cpp
struct EngineRecord {
    uint64_t objectId;
    uint64_t resourceId;
    uint32_t generation;
    enum class State { Loading, Ready, Failed, Retired } state;
    double updateMs;
    double renderMs;
};

bool valid(const EngineRecord& value, uint32_t expectedGeneration) {
    return value.generation == expectedGeneration &&
           value.state == EngineRecord::State::Ready;
}
```

实现迁移到其他引擎时可以更换类型名和API，但必须保留对象身份、代际、资源身份、状态、更新时间和渲染时间。只有这些字段稳定，序列化、热重载、场景查询和LOD决策才能在同一证据链上复核。

## 本单元的验收工件

第一件工件是边界图：把“建立程序循环、统一空间约定、追踪3D流水线、连接编辑器资产、验证目标机输出”画成有向图，逐边标出数据、所有者、状态、线程与失败返回。第二件是目标机轨迹：固定构建和输入，保存正常帧、尾延迟帧与故障帧中的对象、资源、分配和呈现事件。第三件是反例报告：主动破坏实时顺序或汇编证据，定位第一个不变量失效点，并证明修复后没有把成本转移到画质、编辑器或关闭阶段。

<Callout type="trap" title="把示例类型名当成架构原则">
  VSObject或某个历史引擎接口只是实现样本。迁移时应保留身份、反射、生命周期和证据合同，而不是复制类层级与宏。
</Callout>

<Callout type="trap" title="只验证热缓存正常路径">
  资源、对象和场景系统常在冷启动、切场景、热重载和关闭时失效。必须包含资源迟到、引用失效、部分初始化和预算超限。
</Callout>

<Callout type="trap" title="性能提升但视觉或工具回退">
  LOD、压缩、布局和异步化可能损伤轮廓、精度、撤销或调试能力。验收必须同时报告输出质量与生产体验。
</Callout>

## 先预测再运行

运行交互前先预测：对象规模翻倍时更新还是渲染先越界；缓存命中下降时等待如何传到帧尾；LOD阈值收紧时画质与三角形数量怎样变化。若观察与预测不一致，优先检查异步队列、跨帧流水、预热状态和统计窗口。

## 本章回顾

第2章 起航是“建立程序循环 → 统一空间约定 → 追踪3D流水线 → 连接编辑器资产 → 验证目标机输出”中的基础框架合同。掌握本页意味着能逐项定位13个权威目录节点，解释实时顺序、坐标合同、API差异、汇编证据、工作流反馈的适用边界，复算时间、内存、资源与LOD指标，并用正常、压力和故障轨迹让结论可迁移。

<Exercises>

**问题 1：目录与状态。** 重画第2章 起航的机制链，并标出身份、生命周期和线程边界。

<Answer>
  从建立程序循环到验证目标机输出逐项写输入、输出、所有者和失败回收，再用实时顺序与坐标合同检查隐式共享。任何无法说明代际、资源状态或关闭顺序的边都未完成。
</Answer>

**问题 2：预算实验。** 怎样验证API差异在冷启动与稳定运行中都成立？

</Answer>

**问题 3：迁移复核。** 怎样证明第2章 起航不是只会复述VSSystem示例？

<Answer>
  在另一引擎中重建同一输入、状态、生命周期、预算和证据字段，先预测汇编证据的失效点，再注入等价故障。独立复核者能从轨迹得到相同边界才算迁移成功。
</Answer>
