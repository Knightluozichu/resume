## 为什么基础框架要从状态和证据开始

第8章 对象系统承担 **对象系统用身份、反射、序列化、克隆、编辑绑定和复制建立数据驱动引擎的核心元模型。** 本课程不复制原书正文、插图或配套代码，而把目录中的示例引擎机制重构为状态合同、可运行实验、故障样本与验收工件。本页逐项覆盖22个目录坐标：第8章 对象系统、8.1 智能指针、8.2 RTTI、8.3 VSObject、8.4 属性反射、8.5 序列化存储、8.5.1 传统序列化方式、8.5.2 使用属性表进行序列化存储、8.6 克隆、8.7 属性与UI绑定*、8.7.1 基本控件、8.7.2 组合控件与属性、8.7.3 属性绑定、8.8 函数反射、8.9 复制属性与函数、8.9.1 对象复制、8.9.2 属性复制、8.9.3 函数复制、8.9.4 小结、8.10 番外篇——Unreal Engine 4中的反射*、练习、示例。

引擎基础框架不是模块名称集合。内存分配器决定对象能否安全创建，反射决定对象如何进入工具与存储，资源代理决定异步内容能否稳定引用，场景结构决定每帧查询规模，LOD又把视觉误差换成时间和带宽。任何一层缺少身份、生命周期或失败语义，问题都会在更高层以随机崩溃、错误画面或帧抖动出现。

## 四个可复算指标

端到端帧时间保留CPU/GPU重叠与等待：

$$
T_{frame} = max(T_{update}, T_{render}) + T_{wait}
$$

按对齐要求申请内存后的实际尺寸为：

$$
A(n,a) = lceil n/a
ceil a
$$

资源缓存命中率必须按真实请求计算：

$$
H = N_{hit} / N_{request}
$$

LOD用投影误差连接世界误差、焦距、距离与屏幕高度：

$$
e_{screen} = e_{world} f / (z h)
$$

帧时间要报告P50、P95和P99；内存要报告峰值、碎片和生命周期；命中率要区分预热与冷启动；LOD还要观察切换抖动、轮廓破坏和纹理带宽。公式只建立可复算口径，不替代目标设备上的视觉与性能验收。

```cpp
struct EngineRecord {
    uint64_t objectId;
    uint64_t resourceId;
    uint32_t generation;
    enum class State { Loading, Ready, Failed, Retired } state;
    double updateMs;
    double renderMs;
};

bool valid(const EngineRecord& value, uint32_t expectedGeneration) {
    return value.generation == expectedGeneration &&
           value.state == EngineRecord::State::Ready;
}
```

## 本单元的验收工件

第一件工件是边界图：把“注册类型元数据、创建稳定对象、编辑与序列化、克隆或复制、回收引用图”画成有向图，逐边标出数据、所有者、状态、线程与失败返回。第二件是目标机轨迹：固定构建和输入，保存正常帧、尾延迟帧与故障帧中的对象、资源、分配和呈现事件。第三件是反例报告：主动破坏引用所有权或UI事务，定位第一个不变量失效点，并证明修复后没有把成本转移到画质、编辑器或关闭阶段。

<Callout type="trap" title="把示例类型名当成架构原则">
  VSObject或某个历史引擎接口只是实现样本。迁移时应保留身份、反射、生命周期和证据合同，而不是复制类层级与宏。
</Callout>

<Callout type="trap" title="只验证热缓存正常路径">
  资源、对象和场景系统常在冷启动、切场景、热重载和关闭时失效。必须包含资源迟到、引用失效、部分初始化和预算超限。
</Callout>

<Callout type="trap" title="性能提升但视觉或工具回退">
  LOD、压缩、布局和异步化可能损伤轮廓、精度、撤销或调试能力。验收必须同时报告输出质量与生产体验。
</Callout>

## 先预测再运行

运行交互前先预测：对象规模翻倍时更新还是渲染先越界；缓存命中下降时等待如何传到帧尾；LOD阈值收紧时画质与三角形数量怎样变化。若观察与预测不一致，优先检查异步队列、跨帧流水、预热状态和统计窗口。

## 本章回顾

第8章 对象系统是“注册类型元数据 → 创建稳定对象 → 编辑与序列化 → 克隆或复制 → 回收引用图”中的基础框架合同。掌握本页意味着能逐项定位22个权威目录节点，解释引用所有权、反射版本、对象图存储、UI事务、复制权限的适用边界，复算时间、内存、资源与LOD指标，并用正常、压力和故障轨迹让结论可迁移。
