## 为什么基础框架要从状态和证据开始

第11章 场景管理承担 **场景管理用层级变换、空间索引、相机裁剪、对象动态性和光源影响控制世界查询成本。** 本课程不复制原书正文、插图或配套代码，而把目录中的示例引擎机制重构为状态合同、可运行实验、故障样本与验收工件。本页逐项覆盖19个目录坐标：第11章 场景管理、11.1 根节点与场景、11.2 空间位置的父子关系、11.2.1 变换、11.2.2 包围盒、11.2.3 空间管理结构与更新、11.3 相机与相机裁剪、11.3.1 相机的定义、11.3.2 根据相机裁剪物体、11.4 静态物体与动态物体、11.4.1 采用四叉树管理静态物体、11.4.2 入口算法简介和潜在的可见集合*、11.5 光源、11.5.1 间接光、11.5.2 局部光、11.6 相机和光源的更新管理、11.7 番外篇——浅谈Prez、软硬件遮挡剔除*、练习、示例。

引擎基础框架不是模块名称集合。内存分配器决定对象能否安全创建，反射决定对象如何进入工具与存储，资源代理决定异步内容能否稳定引用，场景结构决定每帧查询规模，LOD又把视觉误差换成时间和带宽。任何一层缺少身份、生命周期或失败语义，问题都会在更高层以随机崩溃、错误画面或帧抖动出现。

对象身份把反射、序列化、克隆与复制串在一起；资源代理让对象不直接依赖加载地址；场景节点把空间与生命周期组织起来；屏幕误差则给LOD一个可测目标。属性反射必须和版本迁移、权限、编辑事务一起设计，不能只做“根据字符串找字段”。

## 四个可复算指标

端到端帧时间保留CPU/GPU重叠与等待：

$$
T_{frame} = max(T_{update}, T_{render}) + T_{wait}
$$

按对齐要求申请内存后的实际尺寸为：

$$
A(n,a) = lceil n/a
ceil a
$$

资源缓存命中率必须按真实请求计算：

$$
H = N_{hit} / N_{request}
$$

LOD用投影误差连接世界误差、焦距、距离与屏幕高度：

$$
e_{screen} = e_{world} f / (z h)
$$

帧时间要报告P50、P95和P99；内存要报告峰值、碎片和生命周期；命中率要区分预热与冷启动；LOD还要观察切换抖动、轮廓破坏和纹理带宽。公式只建立可复算口径，不替代目标设备上的视觉与性能验收。

## 最小实现骨架

```cpp
struct EngineRecord {
    uint64_t objectId;
    uint64_t resourceId;
    uint32_t generation;
    enum class State { Loading, Ready, Failed, Retired } state;
    double updateMs;
    double renderMs;
};

bool valid(const EngineRecord& value, uint32_t expectedGeneration) {
    return value.generation == expectedGeneration &&
           value.state == EngineRecord::State::Ready;
}
```

## 本单元的验收工件

第一件工件是边界图：把“更新层级变换、维护空间索引、构建相机视锥、筛选对象与光源、提交可见集合”画成有向图，逐边标出数据、所有者、状态、线程与失败返回。第二件是目标机轨迹：固定构建和输入，保存正常帧、尾延迟帧与故障帧中的对象、资源、分配和呈现事件。第三件是反例报告：主动破坏层级正确或剔除延迟，定位第一个不变量失效点，并证明修复后没有把成本转移到画质、编辑器或关闭阶段。

<Callout type="trap" title="把示例类型名当成架构原则">
  VSObject或某个历史引擎接口只是实现样本。迁移时应保留身份、反射、生命周期和证据合同，而不是复制类层级与宏。
</Callout>

<Callout type="trap" title="只验证热缓存正常路径">
  资源、对象和场景系统常在冷启动、切场景、热重载和关闭时失效。必须包含资源迟到、引用失效、部分初始化和预算超限。
</Callout>

<Callout type="trap" title="性能提升但视觉或工具回退">
  LOD、压缩、布局和异步化可能损伤轮廓、精度、撤销或调试能力。验收必须同时报告输出质量与生产体验。
</Callout>

## 先预测再运行

运行交互前先预测：对象规模翻倍时更新还是渲染先越界；缓存命中下降时等待如何传到帧尾；LOD阈值收紧时画质与三角形数量怎样变化。若观察与预测不一致，优先检查异步队列、跨帧流水、预热状态和统计窗口。

第11章 场景管理是“更新层级变换 → 维护空间索引 → 构建相机视锥 → 筛选对象与光源 → 提交可见集合”中的基础框架合同。掌握本页意味着能逐项定位19个权威目录节点，解释层级正确、包围体保守、索引更新、剔除延迟、光源影响的适用边界，复算时间、内存、资源与LOD指标，并用正常、压力和故障轨迹让结论可迁移。
