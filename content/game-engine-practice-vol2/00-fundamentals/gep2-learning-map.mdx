## 直觉引入

如果说卷1 是在打地基——内存怎么分、数学怎么算、渲染怎么画，那么卷2 就是在地基上盖起一栋能住人的楼：东西会碰撞反弹、角色会跑会跳、声音会随距离衰减、多人能联机、美术能改了立刻看到。卷2《高级技术》回答的是这些「高级运行时能力」各子系统之间如何协同，而不只是各自怎么实现。

## 三阶段递进

<Term def="运行时核心是引擎每帧重复执行的游戏循环，卷2 各子系统都挂在这条循环上协作，卷1 的地基（内存/数学/变换/渲染/场景/事件）为其提供底层支撑。">
  运行时核心
</Term>
之上，卷2
的八大子系统可以拆成三个递进阶段。**模拟层**包括物理引擎和碰撞系统——它们让世界有物理真实感，物体能碰撞、堆叠、弹开。**表现层**包括骨骼动画、动画混合和音频系统——它们让角色会动、动作不跳变、声音有空间感。**联机与工具层**包括网络架构、编辑器框架和脚本系统——它们让多人能协作、资产能烘焙、逻辑能热重载。

```cpp
// 卷2 一帧的旅程：八大子系统串进游戏循环
void Engine::Frame(float renderDt) {
    input.Poll();                       // 输入采集（含网络收远端输入）
    script.Update(renderDt);            // 脚本：处理输入产生意图
    physics.Step(FIXED_DT);             // 物理引擎：固定步进（碰撞系统供流形）
    animation.Update(renderDt);         // 骨骼动画 + 动画混合：更新姿态
    audio.Update();                     // 音频：更新 3D 声源
    network.Sync();                     // 网络：同步状态/插值回滚
    renderPipeline.Render();            // 渲染（卷1）
}
```

## 常见误区

<Callout type="trap">
  **误区：把卷2 当成八个独立模块各学各的。**
  物理依赖碰撞提供接触、动画依赖物理状态、网络要同步物理与动画结果、脚本要调用全部
  API。脱离「协同」只学单点，遇到「角色穿地」「多人不同步」这类跨子系统问题就无从下手。卷2
  的主线正是「协同」二字。
</Callout>

<Exercises>
**问题 1**：卷2 三阶段是什么？为什么是这个顺序？

<Answer>
  模拟层（物理/碰撞）→ 表现层（骨骼动画/动画混合/音频）→
  联机与工具层（网络/编辑器/脚本）。顺序由运行时依赖决定：先有物理真实感，角色才有真实的状态可表现；表现层做好后才有东西可联机同步、可放进工具链迭代。模拟层不通则表现层基于错误状态，联机同步的也是错的。
</Answer>

**问题 2**：卷2 与卷1 的关系是什么？

<Answer>
卷1 是地基（内存/数学/变换/渲染/资源/场景/事件），卷2 是地基之上的高级运行时能力。卷2 每个子系统都依赖卷1：物理碰撞用数学库做变换、用内存系统做数据布局；骨骼动画的骨骼层级就是卷1 变换树的特例；网络同步的对象挂在卷1 的场景图上。地基不稳，卷2 子系统的性能与正确性都无从谈起。
</Answer>
</Exercises>
