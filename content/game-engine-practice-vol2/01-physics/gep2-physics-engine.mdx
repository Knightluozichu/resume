## 直觉引入

让一个球从高处落下，它要越落越快、撞地弹起、最终静止——这套「真实感」不是渲染画出来的，而是物理引擎一帧帧算出来的。物理引擎的本质是：每帧用一个小的时间步，对每个刚体施力、更新速度位置、再修正让它们不互相穿透。听起来简单，难在「稳定」——积分器选错了能量会爆炸，时间步不固定会抖动穿透。

## 单步四阶段

<Term def="积分器是把加速度、速度、位置随时间推进的数值方法，游戏里常用半隐式 Euler，用新速度更新位置以保证稳定性。">
  积分器
</Term>
是物理引擎的心脏。一个物理步进分四步：先**施力**，把重力、弹簧、外力累加成合力；再**积分**，用半隐式
Euler
更新速度和位置；接着**约束求解**，迭代修正穿透和距离约束（关节、接触）；最后**积分修正**，把解算后的位置写回变换。每帧按固定
dt 拆成多个子步循环执行。

```cpp
// 半隐式 Euler：用新速度更新位置，比显式 Euler 稳定
void Integrate(Body& b, float dt) {
    Vector3 a = b.force * b.invMass;       // a = F/m
    b.velocity += a * dt;                  // 先更新速度（新 v）
    b.position += b.velocity * dt;         // 再用新 v 更新位置
    b.force = Vector3::Zero;               // 清力，下帧重新累加
}

// 固定时间步 + 累加器：解耦帧率与物理
void PhysicsSystem::Step(float frameDt) {
    accumulator += frameDt;
    while (accumulator >= FIXED_DT) {
        IntegrateAllBodies(FIXED_DT);      // 固定步长积分
        SolveConstraints(FIXED_DT);        // 约束求解（迭代 N 次）
        accumulator -= FIXED_DT;
    }
}
```

## 稳定性权衡

显式 Euler 用旧速度更新位置（`x += v_old·dt`），能量会持续增加，弹簧系统几秒就「爆炸」。半隐式 Euler 调换顺序，用新速度更新位置，对线性系统是辛积分器，能量守恒更好。约束求解用 Sequential Impulse 法多次迭代收敛，迭代越多越稳但越耗 CPU——通常 4-10 次够用，穿透比抖动更刺眼，故宁可牺牲积分精度也要保证约束求解。

<Callout type="trap">
  **误区：物理直接用渲染帧率跑。** 掉帧时 dt
  变大，积分误差暴增，物体穿透甚至飞出。固定 dt
  让物理确定且稳定，掉帧只影响画面流畅度不影响物理正确性。
</Callout>

<Exercises>
**问题 1**：半隐式 Euler 和显式 Euler 的区别是什么？

<Answer>
  显式 Euler 用旧速度更新位置（x += v_old·dt），能量持续增加、易爆炸。半隐式
  Euler 先更新速度再用新速度更新位置（v += a·dt 后 x +=
  v_new·dt），对线性系统是辛积分器，能量守恒好、稳定。游戏多选半隐式，因为它简单、开销低且对常见场景足够稳定。
</Answer>

**问题 2**：为什么物理引擎要迭代求解约束，而不是一次算准？

<Answer>
多个约束耦合（如堆叠的箱子），独立求解一个约束会破坏另一个。迭代让约束逐步收敛到满足所有约束的近似解，但不是精确解。一次算准需要解大型线性方程组（O(n³)），对实时游戏太慢。迭代法用多次廉价修正换取「足够好」的稳定性，是实时性与精度的工程权衡。
</Answer>
</Exercises>

<Glossary>
  <GlossaryItem term="半隐式 Euler">
    先更新速度再用新速度更新位置的积分法，对线性系统稳定、能量守恒好，是游戏物理首选。
  </GlossaryItem>
  <GlossaryItem term="固定时间步">
    物理以恒定 dt 推进，与可变渲染帧率解耦；用累加器把帧时间拆成多个固定子步。
  </GlossaryItem>
  <GlossaryItem term="Sequential Impulse">
    约束求解的迭代冲量法：对每个约束独立求冲量，多次迭代收敛，兼顾速度与稳定性。
  </GlossaryItem>
</Glossary>
