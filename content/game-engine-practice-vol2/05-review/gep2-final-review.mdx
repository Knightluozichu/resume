## 直觉引入

学完十章，碎片知识堆在脑子里容易散。把它们串成「一帧里发生了什么」就能看清全局：玩家按下摇杆，脚本响应、物理推进、动画更新、音频发声、网络同步、渲染绘制——八大子系统按顺序协作，缺一不可。卷2 的主线不是某个子系统多精妙，而是它们如何「协同」成一个完整运行时。

## 八大子系统协同

<Term def="子系统协同指卷2 八大系统围绕运行时核心，以感知—响应、数据—消费链路互相配合，而非孤立存在，是卷2 的核心视角。">
  子系统协同
</Term>
是卷2
的灵魂。八大子系统按三阶段归类：**模拟层**（物理引擎、碰撞系统）让世界有物理真实感；**表现层**（骨骼动画、动画混合、音频系统）让角色会动会响；**联机与工具层**（网络架构、编辑器框架、脚本系统）让多人能协作、资产能迭代。它们围绕卷1
的运行时核心（游戏循环）协作。

## 一帧的旅程

```cpp
// 卷2 一帧内八大子系统的协作顺序
void Engine::Frame(float renderDt) {
    input.Poll();                  // 输入采集（含网络收远端输入）
    script.Update(renderDt);       // 脚本：处理输入产生意图
    physics.Step(FIXED_DT);        // 物理：碰撞系统供流形，约束求解
    animation.Update(renderDt);    // 骨骼动画 + 动画混合：更新姿态
    audio.Update();                // 音频：更新 3D 声源
    network.Sync();                // 网络：同步状态/插值回滚
    renderPipeline.Render();       // 渲染（卷1）
}
```

典型链路：碰撞系统感知相交→把流形交给物理引擎响应（施冲量）；骨骼动画产出姿态→渲染消费；动画混合融合多状态→骨骼动画驱动；脚本经绑定调全模块 API；网络把本地状态同步远端、把远端输入交本地模拟；编辑器资产管线离线烘焙→运行时加载。任一子系统掉链子都暴露跨系统问题：物理抖动→角色穿地；动画不混合→动作跳变；网络不同步→多人错位。

<Callout type="trap">
  **误区：把卷2 当八个独立模块各学各的。**
  物理依赖碰撞、动画依赖物理状态、网络同步物理与动画结果、脚本调用全部
  API。脱离「协同」只学单点，遇到跨子系统问题就无从下手。卷2
  的价值正是「协同」二字。
</Callout>

<Exercises>
**问题 1**：卷2 八大子系统按三阶段如何归类？

<Answer>
  模拟层：物理引擎、碰撞系统（让世界有物理真实感）。表现层：骨骼动画、动画混合、音频系统（让角色会动会响）。联机与工具层：网络架构、编辑器框架、脚本系统（联机协作开发）。八大子系统围绕运行时核心（游戏循环）协同，卷1
  的地基支撑其上。
</Answer>

**问题 2**：做一个支持多人联机的动作游戏，卷2 哪些子系统必须协同？描述一帧内协作流。

<Answer>
物理、碰撞、骨骼动画、动画混合、音频、网络、脚本全部协同。一帧内：输入采集（含网络收远端输入）→脚本处理输入产生意图→物理推进（碰撞系统供流形、约束求解消除穿透）→骨骼动画按物理/逻辑状态更新姿态、动画混合融合待机/移动→音频更新 3D 声源→网络把本地状态发服务器、收服务器快照插值/回滚修正远端角色→渲染绘制。任一子系统出问题都会暴露：物理抖动角色穿地、动画不混合动作跳变、网络不同步多人错位。
</Answer>
