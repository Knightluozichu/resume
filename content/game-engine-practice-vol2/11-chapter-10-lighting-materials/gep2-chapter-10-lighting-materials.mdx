## 为什么高级引擎技术必须以状态和证据开始

本章把材质场景渲染、间接光、材质通道、自定义光照和投射函数组装成可扩展光照流程。 本课程不复制原书正文、插图或配套代码，而把目录中的VSSystem机制重构为状态合同、可运行实验、故障样本与验收工件。本页逐项覆盖26个目录坐标：第10章 光照与材质、10.1 VSMaterialSceneRender、10.2 VSIndirectRenderPass、10.3 VSMaterialPass、10.4 自定义光照、10.5 光源投射函数、练习、示例、示例10.1、示例10.2、示例10.3、示例10.4、示例10.5、示例10.6、示例10.7、示例10.8、示例10.9、示例10.10、示例10.11、示例10.12、示例10.13、示例10.14、示例10.15、示例10.16、示例10.17、示例10.18。

卷2的技术不能拆成互不相干的技巧。骨骼姿态决定动态包围盒与渲染输入，材质图决定着色器变体与管线状态，阴影和后期决定目标资源生命周期，多线程又改变资源何时可见、何时可释放。一个局部模块若不声明身份、所有权、阶段和失败语义，就会在更高层表现为姿态跳变、错误画面、缓存爆炸、帧尾等待或偶发崩溃。

## 四个可复算模型

线性蒙皮把绑定空间顶点变换到当前姿态：

$$
p^{prime} = sum_{i=1}^{k} w_i M_i B_i^{-1} p, qquad sum_i w_i = 1
$$

两姿态混合的平移与旋转分别采用线性插值和球面插值：

$$
t = (1-alpha)t_0 + alpha t_1, qquad q = operatorname{slerp}(q_0,q_1,alpha)
$$

考虑CPU/GPU重叠与帧尾等待的预算是：

$$
T_{frame}=max(T_{update},T_{render})+T_{wait}
$$

并行优化受串行比例约束：

$$
S(N)=rac{1}{(1-P)+P/N+T_{sync}}
$$

蒙皮应报告末端位置、法线与轮廓误差；混合应检查权重和、旋转最短弧与事件连续性；帧时间应给出P50、P95、P99及异常帧；并行实验必须把同步、队列、缓存和取消成本算入，不能只报告平均任务时间。

## 可迁移实现骨架

先让每个阶段消费不可变输入、产生带版本输出，并把资源回收推迟到最后读者完成。下列结构不绑定某个图形API，字段却足以关联动画、渲染和并发轨迹。

```cpp
struct FrameEvidence {
  uint64_t frame_id;
  uint64_t asset_generation;
  uint64_t resource_fence;
  double cpu_ms;
  double gpu_ms;
  double pose_error;
  const char* final_state;
};
```

每帧流程先冻结输入，再并行计算，最后在明确边界提交。任何中途失败都返回带身份的状态，而不是留下半更新对象。

```text
freeze gameplay state
  -> sample and blend pose
  -> build immutable render snapshot
  -> compile or fetch material pipeline
  -> submit commands with resource fence
  -> collect CPU/GPU evidence and retire resources
```

证据包采用机器可读字段，便于同一输入跨版本比较并定位第一处偏差。

```json
{
  "scenario": "normal|stress|fault",
  "assetGeneration": 42,
  "frameRange": [1200, 1320],
  "budgets": { "cpuMs": 8.0, "gpuMs": 8.0, "memoryMiB": 512 },
  "result": { "state": "accepted", "firstViolation": null }
}
```

## 本单元的验收工件

第一件工件是依赖图：把“分类场景光源 → 选择材质通道 → 累积直接光 → 组合间接光 → 验证投射函数”画成有向图，逐边标出数据、所有者、线程、栅栏与失败返回。第二件工件是目标机轨迹：固定构建、资产和输入，保存正常帧、尾延迟帧与故障帧中的姿态、资源、命令和GPU事件。第三件工件是反例报告：主动破坏光源分类、材质通道、直接光、间接光、投射函数中的一个不变量，定位第一个失效点，并证明修复后没有把成本转移到画质、内存、编辑器或关闭阶段。

<Callout type="trap" title="把历史类型名当成架构原则">
  VSSystem类名和旧平台接口只是实现样本。迁移时保留数据合同、生命周期、预算与证据字段，不复制宏、继承树或后端调用顺序。
</Callout>

<Callout type="trap" title="只验证预热后的正常帧">
  动画、材质和资源系统常在冷启动、切换、热更新、取消或关闭时失效。测试必须包含资源迟到、变体缺失、设备重建和并发回收。
</Callout>

<Callout type="trap" title="帧率提升但质量或工具回退">
  压缩、近似、异步与缓存可能损伤姿态、阴影、颜色、撤销或调试能力。验收应同时报告输出质量、性能分位数和内容生产体验。
</Callout>

## 先预测再运行

运行交互前先预测：角色与材质数量翻倍时CPU、GPU还是内存先越界；工作线程增加后同步项为何可能反而扩大；故障注入后哪条资源引用最先失效。若观察与预测不一致，优先检查跨帧流水、缓存预热、统计窗口、栅栏归属和异步取消。
