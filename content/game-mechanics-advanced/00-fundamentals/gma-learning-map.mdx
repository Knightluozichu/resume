## 直觉引入

设计游戏机制像设计一台精密机器。你不能凭感觉拼零件——你需要图纸。Machinations 就是那张图纸：它把游戏内部的资源流和反馈结构画出来，让你在写代码前就能看见机器怎么运转。

全书核心线索是：先理解「机制是什么」（机制设计），再学「怎么画出来」（Machinations 框架），然后「让图跑起来」（模拟），最后「调到好玩」（调优）。

## 概念讲解

### 全书结构

<GmaLearningMapDiagram />

<Term def="一种可视化游戏内部经济和反馈结构的图表语言，由 Doris 和 Joris Dormans 提出">Machinations 框架</Term>是全书的核心工具。它用源、池、转换器、排水、闸门、触发器、注册器七种元素画出游戏的资源流图，让设计师能「看见」机制如何产生动态行为。

全书分六大板块：机制设计基础（行为空间/深度）→ Machinations 框架（反馈结构可视化）→ 模拟系统（离散/连续）→ 经济与概率（水龙头/水槽/随机）→ 谜题设计（渐进难度）→ 机制调优（迭代平衡）。

## 代码对照

```csharp
// 全书核心链路在代码中的映射
// 1. 机制设计 → 定义规则和数据结构
public class GameMechanics {
    public float damage = 10f;
    public float dropRate = 0.3f;
}

// 2. Machinations → 可视化反馈结构（伪代码）
// 源(怪物) → 池(掉落) → 转换器(卖店→金币) → 池(金币) → 排水(升级)

// 3. 模拟 → 让结构跑起来
for (int i = 0; i < 1000; i++) {
    SimulateOneGame(); // 跑 1000 局收集数据
}

// 4. 调优 → 根据数据改参数
// if (winRate > 0.55) damage *= 0.9f; // 削弱
```

## 常见误区

<Callout type="trap">
**现象：跳过 Machinations 直接写代码。**
原因：Machinations 让你在写代码前就能分析反馈结构、发现隐藏环路。跳过它直接写代码，等你发现平衡问题时已经写了上千行，改起来成本极高。修法：先用 Machinations 画图分析，确认反馈结构合理后再写代码。
</Callout>

<Glossary>
<GlossaryItem term="Machinations 框架">一种可视化游戏内部经济和反馈结构的图表语言，用七种元素（源/池/转换器/排水/闸门/触发器/注册器）画出资源流图。</GlossaryItem>
<GlossaryItem term="行为空间">机制允许的所有合法操作的集合，评价机制好坏的核心指标。</GlossaryItem>
<GlossaryItem term="反馈环路">机制运行时形成的正反馈（增强）或负反馈（平衡）循环，是涌现行为的来源。</GlossaryItem>
<GlossaryItem term="统治策略">明显优于所有其他选择的策略，是机制调优的头号敌人。</GlossaryItem>
</Glossary>
