## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第1—22页。机制是规则、流程和数据在运行时共同形成的状态转换；设计者必须先声明可行动作、状态边界和不确定性来源，再选择纸面、软件或实体原型。

## 核心模型

规则定义允许与禁止的动作，但机制还要说明动作怎样读取当前状态、产生结果并更新后续选择。把游戏看成状态机，可以把模糊的好玩假设改写为可复验的输入、转换和输出。

离散机制按明确事件改变状态，连续机制按时间和物理量演化。两者可以组合，但必须明确采样频率、碰撞或阈值事件以及玩家能否预测结果，否则策略空间会被噪声吞没。

机制设计应在概念阶段就开始，并在精化和调优阶段不断收敛。纸面原型适合离散规则，软件原型适合高频计算，实体原型适合空间与身体交互；原型只验证一个风险，不负责伪装成完整产品。

本页采用下式作为最小可核查模型：

$$
S_{t+1}=F(S_t,a_t,r_t)
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="直接决定挑战、玩家动作与结果反馈的规则集合">核心机制</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Stepper>

    <Gma01DesigningGameMechanicsExperimentLab />
  </Step>
  <Step title="2. 动作输入 → 结果计算">
    逐步运行并保存首个状态变化。边界样本只改变一个变量，失败样本必须能回放到首个偏离节点。
  </Step>
  <Step title="3. 原型观测 → 设计结论">
    将模型结论与真实玩家或真实关卡对照；只有结构正确、体验一致且失败被拒绝时才签发。

  </Step>
</Stepper>

## 可复现实验

用同一追逐玩法制作纸面离散版和固定步长连续版，锁定初始状态与随机种子，对比策略数量、可预测性和每次状态更新的可解释性。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["规则声明","状态建模","动作输入","结果计算","原型观测","设计结论"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-01-designing-game-mechanics,17,baseline,规则声明,fixed,0,1,1.0,,complete
gma-01-designing-game-mechanics,17,failure,动作输入,fixed,1,9,9.0,动作输入,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  把美术反馈当作机制变化，或在原型中同时改规则、界面和难度。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“相同初始状态、动作与随机种子能够重放出相同状态轨迹”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 1** 第1章覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Rules Define Games、Games Are Unpredictable、From Rules to Mechanics、Mechanics Are Media-Independent、Five Types of Game Mechanics、Discrete Mechanics vs. Continuous Mechanics、Mechanics and the Game Design Process、Prototyping Techniques。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“把美术反馈当作机制变化，或在原型中同时改规则、界面和难度”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“相同初始状态、动作与随机种子能够重放出相同状态轨迹”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
