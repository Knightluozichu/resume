## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第43—58页。复杂性不是元素数量，而是连接、反馈、迭代和尺度之间的相互作用；设计者要识别局部规则怎样跨尺度形成稳定、振荡或失控的宏观模式。

</Callout>

## 核心模型

玩法是系统运行后出现的性质，而不是规则清单本身。局部组件拥有有限状态和邻接关系，反复迭代后可能形成聚类、周期、传播前沿或崩溃，这些宏观形态必须通过轨迹观察。

复杂系统的关键结构包括非线性反馈、历史依赖、多个组织尺度和对初始条件的敏感性。单帧截图无法证明因果，需要保存输入、时间序列和首个分叉点。

驾驭突现并不等于完全预测每局结果，而是限定状态空间、建立阻尼与恢复机制，并用边界样本验证系统不会进入永久锁死、无限增长或无意义噪声。

本页采用下式作为最小可核查模型：

$$
x_{t+1}=G(x_t,A,\theta)
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="由相互连接、反馈和迭代产生跨尺度行为的系统">复杂系统</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="局部规则长期运行后形成的稳定、周期或传播结构">宏观模式</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

## 可复现实验

用相同网格规则运行三组初始密度和两个反馈增益，保存每步活跃单元、聚类数和首次分叉，判断复杂度来自拓扑还是随机扰动。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["局部规则","连接拓扑","迭代轨迹","反馈环","宏观模式","边界约束"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-03-complex-systems-emergence,17,baseline,局部规则,fixed,0,1,1.0,,complete
gma-03-complex-systems-emergence,17,failure,迭代轨迹,fixed,1,9,9.0,迭代轨迹,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  只增加单位和随机数制造表面混乱，却没有可解释的跨尺度结构。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“宏观结论必须能追溯到局部规则与首次分叉，而不是只看最终分数”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

## 练习

<Exercises>

**问题 1** 第3章覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Gameplay as an Emergent Property of Games、Structural Qualities of Complex Systems、Harnessing Emergence in Games、Feedback、Iteration、Multiple Scales of Organization。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“只增加单位和随机数制造表面混乱，却没有可解释的跨尺度结构”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“宏观结论必须能追溯到局部规则与首次分叉，而不是只看最终分数”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
