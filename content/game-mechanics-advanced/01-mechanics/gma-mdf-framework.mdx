## 直觉引入

想象你在看一张电路图。电池（源）供电，电线传输电流（资源流），开关控制通断（闸门），电表显示数值（注册器）。Machinations 就是游戏经济系统的「电路图」——把看不见的资源流动画成可视化的结构图。

## 概念讲解

### 七大核心元素

<GmaMdfFrameworkDiagram />

<Term def="自动产生资源的元素，代表游戏中的资源产出机制">源（Source）</Term>是资源的起点，如怪物刷新、任务奖励。<Term def="存储资源的元素，代表游戏中的资源容器">池（Pool）</Term>存储资源，如玩家金币、材料库存。

<Term def="将一种资源变为另一种的元素，代表资源转换机制">转换器（Converter）</Term>如材料→装备。<Term def="消耗/移除资源的元素，代表资源消耗机制">排水（Drain）</Term>如升级消耗、死亡掉落。

<Term def="根据条件分流资源的元素，代表决策点">闸门（Gate）</Term>如「金币&gt;100 时打折」。<Term def="在特定条件下激活事件的元素">触发器（Trigger）</Term>如「血量&lt;30% 时狂暴」。<Term def="存储状态变量供其他元素引用的元素">注册器（Register）</Term>如记录当前等级。

### 资源流与信息流

资源流（实线）传输实际资源，信息流（虚线）传输状态信息用于决策。区分关键：资源流改变资源量和位置，信息流只读取状态。

## 代码对照

```csharp
// Machinations 元素在代码中的映射
// 源 → 资源产出
void SpawnEnemy() { enemies.Add(new Enemy()); }

// 池 → 资源存储
int gold = 0;
List<Item> inventory = new();

// 转换器 → 资源转换
bool Craft(Item material, int count, Item result) {
    if (inventory.Count(material) >= count) {
        inventory.Remove(material, count);
        inventory.Add(result);
        return true;
    }
    return false;
}

// 排水 → 资源消耗
bool Upgrade(int cost) {
    if (gold >= cost) { gold -= cost; return true; }
    return false;
}

// 闸门 + 触发器 → 条件判定
if (health < maxHealth * 0.3f) { // 注册器读取 + 闸门判定
    ActivateBerserk(); // 触发器
}
```

## 常见误区

<Callout type="trap">
**现象：只画资源流不画信息流，遗漏隐藏反馈。**
原因：信息流连接的状态读取可能形成反馈环路。修法：画图时必须标注所有状态引用（信息流），检查是否形成环路。
</Callout>
