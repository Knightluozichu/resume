## 直觉引入

游戏机制像物理定律——它们定义了游戏世界里什么能做、什么不能做。跳跃力决定能跳多高，重力决定会落下来。玩家在机制定义的「物理定律」下探索可能性，就像现实中的人发明飞机。

好的机制给玩家大行为空间但清晰的边界。坏的机制要么限制太多（无事可做），要么限制太少（不知该做什么）。

## 概念讲解

### 机制分类与行为空间

<GmaMechanicsDesignDiagram />

<Term def="机制允许的所有合法操作的集合，即玩家在规则框架内能探索的可能性范围">行为空间</Term>是评价机制好坏的核心指标。行为空间太大=迷茫，太小=无聊。好机制让行为空间「大而有界」——可能性丰富但边界清晰。

<Term def="简单机制能组合出复杂策略的程度，等于行为空间中有效策略的丰富度">机制深度</Term>不同于行为空间大小。深度高的游戏让行为空间中有大量有意义的策略选择——新手用基础操作就能玩，老手能组合出高级策略。

### 机制四分类

机制可分为：基础机制（移动/攻击）、经济机制（资源/交易）、进度机制（经验/解锁）、状态机制（Buff/Debuff）。好的机制设计让四类机制能组合产生涌现行为。

## 代码对照

```csharp
// 机制设计：四类机制的定义
public class GameMechanics {
    // 基础机制
    public float moveSpeed = 5f;
    public float attackDamage = 10f;

    // 经济机制
    public int goldDropMin = 5;
    public int goldDropMax = 15;

    // 进度机制
    public int xpPerKill = 20;
    public int xpToLevelUp = 100;

    // 状态机制
    public float buffDuration = 10f;
    public float buffMultiplier = 1.5f;
}
```

## 常见误区

<Callout type="trap">
**现象：机制太多太复杂，玩家学不会。**
原因：认知负荷过载。修法：核心机制控制在 3-5 个以内，新机制逐步引入，每个新机制必须有教学关卡。
</Callout>

<Callout type="trap">
**现象：机制之间没有交互，各玩各的。**
原因：好的机制应该能组合产生涌现行为。修法：设计机制时思考组合可能性——跳跃+攻击=跳劈，重力+风力=滑翔。
</Callout>

<Exercises>
**问题 1**：什么是机制深度？它与行为空间有什么关系？

<Answer>
机制深度是指简单机制能组合出复杂策略的程度。深度 = 行为空间中有效策略的丰富度。行为空间是所有合法操作的集合，但不是所有操作都有意义。深度高的游戏让行为空间中有大量有意义的策略选择。
</Answer>
</Exercises>
