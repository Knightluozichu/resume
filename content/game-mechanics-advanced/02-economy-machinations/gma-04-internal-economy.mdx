## 核心模型

资源是可量化概念，实体携带行为和身份。源创造资源，排水口移除资源，转换器改变资源类型，交易器按比率交换资源。每条流都要声明速率、触发条件和容量。

经济结构不是资源列表，而是连接关系。正反馈会让优势加速，负反馈会产生稳定，瓶颈会形成阶段门。只有记录库存和流量时间序列，才能区分暂时短缺与结构性失衡。

内部经济可控制进度、频率、难度和策略选择。设计签发必须同时检查守恒、上限、无资源时的失败路径，以及玩家是否能理解行为与经济结果的关系。

本页采用下式作为最小可核查模型：

$$
\Delta R=I_{source}+I_{trade}-O_{drain}-O_{convert}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

### 深度诊断：存量、流量与阶段不能混为一谈

库存是某一时刻的存量，生产率和消耗率是时间区间内的流量。高库存可能来自早期积累，不代表当前生产健康；低库存也可能是高周转而不是短缺。诊断时要同时画库存曲线、每条边的流量和容量利用率，并标记玩法阶段切换。若只看终局总量，转换器饥饿、交易器卡死和排水突增都会被平均值掩盖。

## 可复现实验

建立金币、原料和成品三资源经济，分别注入无限源、转换瓶颈和高排水三种故障，比较库存轨迹并定位第一条破坏守恒或容量的边。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["资源定义","实体所有权","流入速率","转换交易","流出速率","库存轨迹"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

