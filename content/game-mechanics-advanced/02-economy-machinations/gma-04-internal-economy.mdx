## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第59—78页。内部经济不限于货币，它描述任何可量化资源如何被生产、储存、转换、交易和消耗；经济结构决定玩法阶段、稀缺性和玩家决策。

## 核心模型

资源是可量化概念，实体携带行为和身份。源创造资源，排水口移除资源，转换器改变资源类型，交易器按比率交换资源。每条流都要声明速率、触发条件和容量。

经济结构不是资源列表，而是连接关系。正反馈会让优势加速，负反馈会产生稳定，瓶颈会形成阶段门。只有记录库存和流量时间序列，才能区分暂时短缺与结构性失衡。

内部经济可控制进度、频率、难度和策略选择。设计签发必须同时检查守恒、上限、无资源时的失败路径，以及玩家是否能理解行为与经济结果的关系。

本页采用下式作为最小可核查模型：

$$
\Delta R=I_{source}+I_{trade}-O_{drain}-O_{convert}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

### 深度诊断：存量、流量与阶段不能混为一谈

库存是某一时刻的存量，生产率和消耗率是时间区间内的流量。高库存可能来自早期积累，不代表当前生产健康；低库存也可能是高周转而不是短缺。诊断时要同时画库存曲线、每条边的流量和容量利用率，并标记玩法阶段切换。若只看终局总量，转换器饥饿、交易器卡死和排水突增都会被平均值掩盖。

## 从结构到证据的六阶段链

<Stepper>
  <Step title="1. 资源定义 → 实体所有权">
    固定初始状态、规则版本和测试对象，写出两阶段的输入输出，不允许用“感觉更好”作为观测值。
    </Step>
  <Step title="2. 流入速率 → 转换交易">
    逐步运行并保存首个状态变化。边界样本只改变一个变量，失败样本必须能回放到首个偏离节点。
  </Step>
  <Step title="3. 流出速率 → 库存轨迹">
    将模型结论与真实玩家或真实关卡对照；只有结构正确、体验一致且失败被拒绝时才签发。
    </Step>
</Stepper>

## 可复现实验

建立金币、原料和成品三资源经济，分别注入无限源、转换瓶颈和高排水三种故障，比较库存轨迹并定位第一条破坏守恒或容量的边。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["资源定义","实体所有权","流入速率","转换交易","流出速率","库存轨迹"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-04-internal-economy,17,baseline,资源定义,fixed,0,1,1.0,,complete
gma-04-internal-economy,17,failure,流入速率,fixed,1,9,9.0,流入速率,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  资源凭空增加、负库存继续消费，或用总量掩盖局部瓶颈。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“每个资源变化都能归因于源、排水口、转换器或交易器中的一个明确事件”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 1** 第4章覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

  本页覆盖 Elements of Internal Economies、Resources、Entities、Sources、Drains、Converters、Traders、Economic Structure、Uses for Internal Economies in Games。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。

**问题 2** 怎样主动制造“资源凭空增加、负库存继续消费，或用总量掩盖局部瓶颈”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“每个资源变化都能归因于源、排水口、转换器或交易器中的一个明确事件”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
