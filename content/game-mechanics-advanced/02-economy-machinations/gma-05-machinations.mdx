## 核心模型

源、池、排水口和转换器构成基本资源流，闸门、交易器、延迟与终止器处理分配、交换和时间。节点不是装饰图标，每个都要声明激活模式、流率和容量。

资源连接搬运资源，状态连接不搬运资源而修改目标参数。混淆两者会让模型看似连通却无法解释守恒。自动、交互、起始和被动激活也必须与真实游戏事件对应。

Pac-Man 案例展示从地图事件、药丸、生命和敌人状态抽取模型。正确做法不是复制所有实现细节，而是保留决定游戏阶段、风险和得分的因果骨架。

本页采用下式作为最小可核查模型：

$$
P_{t+1}=P_t+\sum f_{in}-\sum f_{out}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="在节点之间搬运可量化资源的连接">资源连接</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="读取一个节点状态并修改另一个节点参数的连接">状态连接</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="节点由自动、交互、起始或被动条件触发的方式">激活模式</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

## 可复现实验

先用六个节点重建 Pac-Man 的药丸、分数和生命主线，再故意交换一条资源连接与状态连接，比较两次运行的守恒日志和首个错误节点。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["游戏事件","节点选择","连接语义","激活模式","运行轨迹","模型对照"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-05-machinations,17,baseline,游戏事件,fixed,0,1,1.0,,complete
gma-05-machinations,17,failure,连接语义,fixed,1,9,9.0,连接语义,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  把状态连接当资源流，或让自动节点在真实游戏没有对应触发条件。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“图中每条边只有一种语义，资源连接守恒，状态连接只修改已声明参数”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 2** 怎样主动制造“把状态连接当资源流，或让自动节点在真实游戏没有对应触发条件”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“图中每条边只有一种语义，资源连接守恒，状态连接只修改已声明参数”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
