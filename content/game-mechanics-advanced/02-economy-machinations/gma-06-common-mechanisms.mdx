## 核心模型

正反馈放大当前差异，适合成长与升级但可能滚雪球；负反馈抵消差异，适合稳定和追赶但可能抹平努力。反馈强度取决于环路增益和延迟，不由一句增强或削弱决定。

确定性、随机流率、玩家技能和多人动态是不同不确定性来源。固定随机种子只能控制随机性，不能消除策略分叉或其他玩家行为，因此证据要分层记录。

动作、策略与第一人称射击经济都可以还原成资源与反馈结构。抽象应保留真正影响决策的弹药、生命、位置或生产能力，删除只影响表现的细节。

本页采用下式作为最小可核查模型：

$$
g_{loop}=\prod_{i=1}^{n}g_i
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="当前优势经环路放大并进一步提高后续优势的结构">正反馈</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="偏离目标后产生反向作用并限制偏差的结构">负反馈</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

## 可复现实验

建立一个成长引擎和追赶机制，分别扫描反馈增益与延迟；保存领先差、翻盘率和振荡幅度，区分稳定、滚雪球和过度橡皮筋。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["机制样本","不确定性分类","反馈方向","环路增益","延迟观测","策略分布"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-06-common-mechanisms,17,baseline,机制样本,fixed,0,1,1.0,,complete
gma-06-common-mechanisms,17,failure,反馈方向,fixed,1,9,9.0,反馈方向,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  用更大的随机范围制造假突现，或用强负反馈让所有选择结果相同。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“随机种子固定后，剩余差异必须能由玩家策略或系统状态解释”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 2** 怎样主动制造“用更大的随机范围制造假突现，或用强负反馈让所有选择结果相同”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“随机种子固定后，剩余差异必须能由玩家策略或系统状态解释”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
