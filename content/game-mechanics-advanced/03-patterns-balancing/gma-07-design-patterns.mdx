## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第147—170页。设计模式不是可直接复制的数值配方，而是由意图、结构、参与者、后果和适用边界组成的机制词汇；模式必须在当前经济中重新实例化并验证。

<Callout type="note" title="先预测">
  在运行图或查看答案前，先预测“设计意图”经过“模式候选”后，哪个状态会最先改变；再写出支持预测的规则、资源或连接。预测必须带可证伪结果。
</Callout>

## 核心模型

引擎模式持续生成增长，摩擦模式限制或消耗增长，升级模式提高挑战或能力，稳定与周期模式控制长期形态。类别描述结构倾向，不保证玩家体验。

Machinations 模式语言把抽象名称落到节点和反馈环。一个模式记录意图、结构、参与者、协作、后果和相关模式，缺少任何一项都容易把名称当成答案。

利用模式进行创意时，应先声明设计问题，再选择候选结构，预测副作用并运行反例。组合多个模式时重点检查共享资源和反馈环，因为局部合理不等于组合稳定。

本页采用下式作为最小可核查模型：

$$
V_{pattern}=B_{intent}-C_{sideEffect}-R_{misuse}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="通过循环投入和产出持续提高生产能力的结构">引擎模式</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="通过消耗、损失或效率下降限制增长的结构">摩擦模式</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="模式在收益之外必然引入的成本、风险和行为倾向">模式后果</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

### 深度诊断：模式实例必须回答适用性

模式实例至少记录触发前提、资源所有者、环路方向、延迟、容量和退出条件。两个图都叫“引擎”并不意味着行为相同：静态产能、动态投资和转换链对早期策略、长尾增长及失败恢复的影响完全不同。评审时先用意图筛选，再对结构做消融，最后检查副作用；任何只能说出模式名却无法预测轨迹变化的方案都不能签发。

## 从结构到证据的六阶段链

<Stepper>
  <Step title="1. 设计意图 → 模式候选">
    固定初始状态、规则版本和测试对象，写出两阶段的输入输出，不允许用“感觉更好”作为观测值。
    </Step>
  <Step title="2. 结构实例 → 副作用预测">
    逐步运行并保存首个状态变化。边界样本只改变一个变量，失败样本必须能回放到首个偏离节点。
  </Step>
  <Step title="3. 反例运行 → 组合验收">
    将模型结论与真实玩家或真实关卡对照；只有结构正确、体验一致且失败被拒绝时才签发。
    </Step>
</Stepper>

## 可复现实验

把同一资源引擎分别接入静态摩擦、动态摩擦和停止机制，记录增长曲线、决策频率和失败模式，验证模式后果而非只比较最终产量。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["设计意图","模式候选","结构实例","副作用预测","反例运行","组合验收"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-07-design-patterns,17,baseline,设计意图,fixed,0,1,1.0,,complete
gma-07-design-patterns,17,failure,结构实例,fixed,1,9,9.0,结构实例,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  看到成长系统就套用引擎模式，却没有摩擦、停止条件或容量上限。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“模式名称必须映射到可见结构、适用条件和可测后果”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

<Exercises>

**问题 1** 第7章覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Introducing Design Patterns、Machinations Design Pattern Language、Engines、Friction、Escalation、Stability and Cycles、Leveraging Patterns for Design。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“看到成长系统就套用引擎模式，却没有摩擦、停止条件或容量上限”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“模式名称必须映射到可见结构、适用条件和可测后果”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>

</Exercises>
