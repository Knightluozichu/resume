## 核心模型

人工玩家可以按脚本、随机、启发式或搜索策略行动。每类代理代表不同假设，不能把单一最优代理的结果当作所有玩家。模拟必须保存策略、种子和每步命令。

Monopoly 案例揭示规则、交易和位置怎样改变长期财富分布；SimWar 案例展示如何逐步校准单位、生产与战斗。平衡结论应看分布、长尾和统治策略，而不仅是总体胜率。

从模型到游戏需要做语义对照：模型节点对应哪个运行时状态，省略了哪些表现和操作成本，真实玩家是否执行同样策略。模型预测与真人测试分离时应拒绝签发。

本页采用下式作为最小可核查模型：

$$
\hat{p}=\frac{wins}{runs},\quad CI\propto\sqrt{\frac{\hat{p}(1-\hat{p})}{runs}}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

### 深度诊断：均值平衡不等于策略平衡

批量模拟要报告样本量、置信区间、分位数和策略条件分布。总体胜率接近一半，仍可能由一种策略统治新手局、另一种策略统治高手局；平均对局长度稳定，也可能隐藏少量无法结束的长尾。应按代理类型、初始位置和随机种子分层，保存异常终局，再用真人测试验证代理是否覆盖了真实可执行动作和认知成本。

## 可复现实验

为同一对战规则实现随机、贪心和风险规避三类代理，每类固定参数运行1000次；比较胜率、对局长度、资源差和策略熵，再用真人局验证排序。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["代理策略","随机种子","批量运行","结果分布","统治策略","真人对照"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text

```

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |
