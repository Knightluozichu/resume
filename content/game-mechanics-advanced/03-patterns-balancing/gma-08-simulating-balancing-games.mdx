## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第171—196页。模拟平衡不是寻找一个平均值，而是让人工玩家、随机种子和策略分布覆盖真实决策空间，并把模型结论回接到可玩实现。

</Callout>

## 核心模型

人工玩家可以按脚本、随机、启发式或搜索策略行动。每类代理代表不同假设，不能把单一最优代理的结果当作所有玩家。模拟必须保存策略、种子和每步命令。

Monopoly 案例揭示规则、交易和位置怎样改变长期财富分布；SimWar 案例展示如何逐步校准单位、生产与战斗。平衡结论应看分布、长尾和统治策略，而不仅是总体胜率。

从模型到游戏需要做语义对照：模型节点对应哪个运行时状态，省略了哪些表现和操作成本，真实玩家是否执行同样策略。模型预测与真人测试分离时应拒绝签发。

本页采用下式作为最小可核查模型：

$$
\hat{p}=\frac{wins}{runs},\quad CI\propto\sqrt{\frac{\hat{p}(1-\hat{p})}{runs}}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="按明确策略在模型中选择动作的自动代理">人工玩家</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="在绝大多数状态下都不劣并经常更优的选择">统治策略</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="把模型状态和事件逐项映射到真实游戏实现与玩家操作的过程">模型对照</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

### 深度诊断：均值平衡不等于策略平衡

批量模拟要报告样本量、置信区间、分位数和策略条件分布。总体胜率接近一半，仍可能由一种策略统治新手局、另一种策略统治高手局；平均对局长度稳定，也可能隐藏少量无法结束的长尾。应按代理类型、初始位置和随机种子分层，保存异常终局，再用真人测试验证代理是否覆盖了真实可执行动作和认知成本。

## 从结构到证据的六阶段链

<Stepper>
  <Step title="1. 代理策略 → 随机种子">
    固定初始状态、规则版本和测试对象，写出两阶段的输入输出，不允许用“感觉更好”作为观测值。
    </Step>
  <Step title="2. 批量运行 → 结果分布">
    逐步运行并保存首个状态变化。边界样本只改变一个变量，失败样本必须能回放到首个偏离节点。
  </Step>
  <Step title="3. 统治策略 → 真人对照">
    将模型结论与真实玩家或真实关卡对照；只有结构正确、体验一致且失败被拒绝时才签发。
    </Step>
</Stepper>

## 可复现实验

为同一对战规则实现随机、贪心和风险规避三类代理，每类固定参数运行1000次；比较胜率、对局长度、资源差和策略熵，再用真人局验证排序。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["代理策略","随机种子","批量运行","结果分布","统治策略","真人对照"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-08-simulating-balancing-games,17,baseline,代理策略,fixed,0,1,1.0,,complete
gma-08-simulating-balancing-games,17,failure,批量运行,fixed,1,9,9.0,批量运行,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  只跑一个平均代理，或通过让所有选项同样弱来获得表面胜率平衡。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“每个模拟结果都携带代理版本、种子、参数和完整终局原因”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 2** 怎样主动制造“只跑一个平均代理，或通过让所有选项同样弱来获得表面胜率平衡”并证明修复有效？

<Answer>

<Answer>
