## 核心模型

Caesar III 的城市经济由建筑、道路、工人、原料和居民需求组成。分析时要把地图和连接成本纳入模型，因为同一生产比率在不同空间拓扑下会形成不同瓶颈。

主导经济结构决定玩家长期策略：引擎增长、摩擦、升级和多重反馈共同形成游戏阶段。若阶段只由数值膨胀而没有新决策，经济虽增长却没有进程质量。

Lunar Colony 的设计过程从资源与目标出发，逐步加入建筑、转换、运输和风险，再通过模拟删减无效环节。每次改动只针对一个可观察问题，并保留前后轨迹。

本页采用下式作为最小可核查模型：

$$
Q_{net}=\min(Q_{input},Q_{capacity},Q_{transport})-L
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

## 可复现实验

构建三段生产链并改变道路容量、仓库位置和需求波峰，记录每段利用率与库存等待；验证瓶颈转移后是否产生新的有效决策。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["生产链","空间连接","阶段目标","反馈结构","瓶颈样本","迭代对照"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-09-building-economies,17,baseline,生产链,fixed,0,1,1.0,,complete
gma-09-building-economies,17,failure,阶段目标,fixed,1,9,9.0,阶段目标,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  忽略运输与布局成本，导致纸面平衡的生产链在关卡中永久堵塞。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“所有产出都能追溯投入、容量、空间路径和时间成本”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 2** 怎样主动制造“忽略运输与布局成本，导致纸面平衡的生产链在关卡中永久堵塞”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“所有产出都能追溯投入、容量、空间路径和时间成本”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
