## 直觉引入

调优游戏像调吉他琴弦。你不能一次拧到完美——你先调到大概，弹一下听音准，再微调，再弹，再微调。机制调优也是这个循环：假设→测试→分析→调整，每次只动一个旋钮。

## 概念讲解

### 统治策略

<GmaMechanismTuningDiagram />

<Term def="某一种策略明显优于所有其他选择，导致玩家没有理由选别的">统治策略（Dominant Strategy）</Term>是调优头号敌人。它消灭策略多样性，浪费设计，降低深度。调优目标：消除统治策略，让多策略各有适用场景。

### 四步迭代循环

1. 设定假设——明确调什么、为什么调、期望效果。2. 模拟测试——跑大量对局收集数据。3. 分析数据——看胜率、策略分布、时长是否符合预期。4. 调整参数——微调后回到第 1 步。

### 平衡 ≠ 等价

绝对等价（所有策略数值相同）消灭了选择意义。好的平衡是「多策略各有场景」——每个策略在某情境下最优，但在其他情境下有劣势。平衡的本质是权衡而非等价。

## 代码对照

```csharp
// 机制调优：迭代平衡循环
public class MechanismTuner {
    // 当前参数
    public float weaponADamage = 10f;
    public float weaponBDamage = 8f;
    public float weaponBRange = 15f;  // B 射程远

    // 模拟 1000 局
    public TuningResult RunSimulation(int games = 1000) {
        int winsA = 0, winsB = 0;
        for (int i = 0; i < games; i++) {
            var result = SimulateGame();
            if (result.Winner == "A") winsA++;
            else winsB++;
        }
        return new TuningResult {
            WinRateA = (float)winsA / games,
            WinRateB = (float)winsB / games,
        };
    }

    // 调优：消除统治策略
    public void Tune() {
        var result = RunSimulation();
        if (result.WinRateA > 0.55f) {
            // A 太强，削弱
            weaponADamage *= 0.9f;
        } else if (result.WinRateB > 0.55f) {
            // B 太强，削弱
            weaponBDamage *= 0.9f;
        }
        // 重复直到胜率在 45-55% 区间
    }
}
```

## 常见误区

<Callout type="trap">
**现象：一次改多个参数，无法归因效果。**
原因：改了三个参数后胜率变了，但不知道是哪个参数起作用。修法：每次只改一个参数，模拟后归因，再改下一个。
</Callout>

<Callout type="trap">
**现象：追求绝对等价，所有策略数值相同。**
原因：等价消灭了选择意义——选什么都一样。修法：追求「各有场景」的权衡而非等价——高伤害慢速 vs 低伤害快速，各有优劣。
</Callout>

<Exercises>
**问题 1**：什么是「统治策略」？为什么它是机制调优的头号敌人？

<Answer>
统治策略是某一种策略明显优于所有其他选择，导致玩家没有理由选别的。它是头号敌人因为：消灭策略多样性（所有人都用同一策略），浪费设计（其他策略无人使用），降低深度（表面有选择但实质只有一个最优解）。调优目标：消除统治策略，让多策略各有场景。
</Answer>
</Exercises>
