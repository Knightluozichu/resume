## 核心模型

锁钥机制用能力、物品、信息或状态打开新的空间和任务。可靠设计要建立锁钥依赖图，检查钥匙是否可达、是否会被误耗，以及分支汇合时是否保留必要能力。

涌现进程不依赖固定关卡顺序，而让资源、能力和反馈结构改变玩家可做的事情。进度作为资源时也需要来源、消耗和上限，否则增长会变成单向滚雪球。

升级挑战提高压力，升级复杂度增加交互关系。两者应分开测量：同时提高会让失败原因不可解释。进程验收还要覆盖回退、重复游玩和错过内容后的恢复路径。

本页采用下式作为最小可核查模型：

$$
Reach(s)=\{n\mid prereq(n)\subseteq inventory(s)\}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="用能力、物品、信息或状态控制内容可达性的机制">锁钥机制</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

### 深度诊断：锁钥图需要状态搜索而非目测

同一把钥匙若可消费、可丢弃或被多个锁共享，静态依赖图就不足以证明可达。测试模型应把当前位置、已持有能力、已消耗资源和永久世界状态组成搜索节点，枚举合法动作并标记无后继但未完成的状态。对每个软锁样本，还要证明替代钥匙、回退路径或保护规则能在相同前缀下恢复，而不是只修一条演示路线。

## 可复现实验

枚举一个三分支锁钥图的物品获取和消耗顺序，用状态搜索找到无后继状态；再加入替代钥匙或安全退出，证明软锁集合归零。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["锁钥图","可达性","进度资源","阶段变化","软锁检测","恢复路径"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-11-progression-mechanisms,17,baseline,锁钥图,fixed,0,1,1.0,,complete
gma-11-progression-mechanisms,17,failure,进度资源,fixed,1,9,9.0,进度资源,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  关键钥匙可被消耗且没有替代来源，导致存档永久软锁。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“任何可进入状态都至少存在一条满足资源与能力条件的继续或安全退出路径”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

## 练习

<Exercises>

**问题 1** 第11章覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Lock-and-Key Mechanisms、Locks, Keys, and Access、Emergent Progression、Progress as a Resource、Escalating Challenge、Escalating Complexity。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“关键钥匙可被消耗且没有替代来源，导致存档永久软锁”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“任何可进入状态都至少存在一条满足资源与能力条件的继续或安全退出路径”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>

</Exercises>
