## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第301—302页。速查手册的价值不是记图标，而是把每个符号还原成运行语义、输入输出和边界条件，从而支持读图、复刻和模型审查。

<Callout type="note" title="先预测">
  在运行图或查看答案前，先预测“符号识别”经过“连接分类”后，哪个状态会最先改变；再写出支持预测的规则、资源或连接。预测必须带可证伪结果。
</Callout>

## 核心模型

节点符号表示源、池、排水口、转换器、交易器、闸门和延迟等行为。资源连接与状态连接必须用不同线型和箭头表达，颜色只辅助区分资源类型。

激活模式决定节点何时执行，流率和时间间隔决定每次搬运多少资源。速查时要同时读节点、连接、标签和触发，不可只按图标猜功能。

审查一个图时，从初始状态逐边追踪一次正常运行，再测试空池、满池、零流率和循环依赖。速查表应能直接给出每种边界的预期语义。

本页采用下式作为最小可核查模型：

$$
flow=rate\times activations
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="表示一种资源行为或控制行为的标准图形">节点符号</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="一次激活沿资源连接搬运的资源数量规则">流率</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

### 深度诊断：符号表必须支持执行推演

可靠速查表要让读者回答四件事：节点何时激活、每次读取什么状态、沿哪类连接传递多少资源、容量或条件不满足时怎样失败。符号颜色、位置和线条粗细只能辅助阅读，不能承担唯一语义。审查时用无文字图做五步手工推演，再与工具输出逐节点对照；出现分歧时修复标签或契约，而不是靠口头解释补洞。

## 可复现实验

隐藏一个模型的文字说明，只保留标准符号和标签，让另一位读者重写执行契约；用五步轨迹比较两份解释是否一致。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["符号识别","连接分类","激活读取","流率计算","边界执行","语义复述"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-appendix-a-machinations-reference,17,baseline,符号识别,fixed,0,1,1.0,,complete
gma-appendix-a-machinations-reference,17,failure,激活读取,fixed,1,9,9.0,激活读取,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  依赖颜色区分关键语义，或省略流率与激活模式导致图不可执行。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“观察者只使用图和速查表即可写出每个节点的确定输入输出契约”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

<Exercises>

**问题 1** 附录A覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Machinations Quick Reference、Node Symbols、Resource Connections、State Connections、Activation Modes、Flow Rates and Intervals、Color Coding and Resource Types。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“依赖颜色区分关键语义，或省略流率与激活模式导致图不可执行”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“观察者只使用图和速查表即可写出每个节点的确定输入输出契约”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
