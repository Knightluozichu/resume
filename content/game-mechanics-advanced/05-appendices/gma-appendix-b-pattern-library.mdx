## 官方位置与先预测

本页严格对应《Game Mechanics: Advanced Game Design》原书第303—336页及在线附录B。模式库覆盖增长、摩擦、停止、消耗、升级、竞赛、交易和周期；每个模式都要按意图、结构、后果和相关模式进行选择，而不是按名称拼装。

<Callout type="note" title="先预测">
  在运行图或查看答案前，先预测“问题陈述”经过“模式意图”后，哪个状态会最先改变；再写出支持预测的规则、资源或连接。预测必须带可证伪结果。
</Callout>

## 核心模型

静态、动态和转换引擎描述不同增长结构，引擎建造让玩家投资生产能力。静态与动态摩擦、停止机制和消耗模式负责限制增长并制造取舍。

升级挑战、升级复杂度、军备竞赛、玩法风格强化和多重反馈改变长期节奏。交易、工人放置和慢周期则组织玩家之间或时间维度上的资源竞争。

模式组合审查要画出共享资源和闭合环路，逐个关闭模式观察系统是否仍满足目标。若删除某模式没有可观测变化，它可能只是命名上的冗余。

本页采用下式作为最小可核查模型：

$$
E_{pattern}=distance(T_{with},T_{without})
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="暂时移除一个模式并比较系统轨迹以验证其真实作用">消融实验</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

## 从结构到证据的六阶段链

<Stepper>
  <Step title="1. 问题陈述 → 模式意图">
    固定初始状态、规则版本和测试对象，写出两阶段的输入输出，不允许用“感觉更好”作为观测值。
    </Step>
  <Step title="2. 结构实例 → 模式组合">
    逐步运行并保存首个状态变化。边界样本只改变一个变量，失败样本必须能回放到首个偏离节点。
  </Step>
  <Step title="3. 消融实验 → 后果签发">
    将模型结论与真实玩家或真实关卡对照；只有结构正确、体验一致且失败被拒绝时才签发。
    </Step>
</Stepper>

## 可复现实验

选一个引擎、一个摩擦和一个升级模式组成经济，分别做三次消融；比较库存、决策频率和终止时间，确认每个模式的独有后果。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["问题陈述","模式意图","结构实例","模式组合","消融实验","后果签发"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-appendix-b-pattern-library,17,baseline,问题陈述,fixed,0,1,1.0,,complete
gma-appendix-b-pattern-library,17,failure,结构实例,fixed,1,9,9.0,结构实例,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  同时叠加多个增长模式却没有摩擦和停止条件，导致无限加速。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“每个采用的模式都必须产生独有且可测的结构后果”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

## 练习

<Exercises>

**问题 1** 附录B覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Static Engine、Dynamic Engine、Converter Engine、Engine Building、Static Friction、Dynamic Friction、Stopping Mechanism、Attrition、Escalating Challenge、Escalating Complexity、Arms Race、Playing Style Reinforcement、Multiple Feedback、Trade、Worker Placement、Slow Cycle。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“同时叠加多个增长模式却没有摩擦和停止条件，导致无限加速”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“每个采用的模式都必须产生独有且可测的结构后果”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
