## 核心模型

先创建最小图并为节点命名，再配置初值、容量、流率和激活模式。连接资源流和状态流后，应单步执行并核对每个中间状态，而不是立即跑大量样本。

单次运行用于验证语义，批量运行用于观察分布。批量前固定模型版本、参数集合、随机种子策略和终止条件，否则统计无法比较。

导出证据至少包含图版本、参数、运行次数、原始序列、聚合指标和异常样本。分享截图而不分享可执行模型与上下文，无法支持复验。

本页采用下式作为最小可核查模型：

$$
N_{valid}=N_{runs}-N_{invalid}-N_{timeout}
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

<Term def="固定输入和种子后逐步核对通过的参考运行记录">基准轨迹</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

<Term def="在声明的参数与种子策略下重复执行模型以获得分布">批量运行</Term>必须在本页实验中留下可观察状态，不能只作为术语出现。

## 可复现实验

从一个源到池再到排水口建立三节点图，先逐步核对十步，再批量运行三组流率；导出原始轨迹与统计并让他人复验同一结论。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["创建图","配置节点","连接语义","单步校验","批量运行","导出证据"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-appendix-c-machinations-start,17,baseline,创建图,fixed,0,1,1.0,,complete
gma-appendix-c-machinations-start,17,failure,连接语义,fixed,1,9,9.0,连接语义,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  模型语义尚未校验就运行一千次，并用稳定的错误平均值宣称平衡。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“批量运行前必须有一条逐步核对通过的确定性基准轨迹”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

<Exercises>

**问题 1** 附录C覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

<Answer>
  本页覆盖 Getting Started with Machinations、Create a Diagram、Add and Configure Nodes、Connect Resource and State Flows、Run a Single Simulation、Run Multiple Simulations、Collect Statistical Data、Export and Share Evidence。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“模型语义尚未校验就运行一千次，并用稳定的错误平均值宣称平衡”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“批量运行前必须有一条逐步核对通过的确定性基准轨迹”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
