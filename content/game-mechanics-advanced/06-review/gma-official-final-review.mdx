## 核心模型

第一道门检查规则与状态契约：动作、随机性、离散和连续更新可重放；第二道门检查结构：涌现、反馈、经济守恒和模式组合有可定位的因果。

第三道门检查验证：Machinations 图可以单步和批量执行，人工玩家覆盖多种策略，模型预测与真人测试方向一致；第四道门检查体验：关卡教学、进程可达与意义表达不互相冲突。

最终证据包保存来源目录、模型版本、参数、种子、原始轨迹、失败注入、修复对照和签发理由。任何只靠最终均值或演示截图的结论都应退回。

本页采用下式作为最小可核查模型：

$$
PASS=R\land E\land S\land L\land M
$$

式子只定义要观察的关系，不能单独证明设计成立。必须保存输入上下文、逐步轨迹、边界样本和玩家行为对照。

## 可复现实验

选一条核心循环完成规则表、Machinations 图、三类代理模拟、三间教学关卡、锁钥搜索和玩家解释访谈，并注入一个反馈失控与一个软锁故障。

使用下面的实验契约记录每次运行。它故意把模型、种子和终止原因放进结果，避免只保留最终均值。

```ts
type RunEvidence = {
  modelVersion: string;
  seed: number;
  stages: readonly string[];
  observations: readonly number[];
  firstDeviation: string | null;
  termination: "complete" | "rejected" | "timeout";
};

const stages = ["规则契约","结构模型","模拟分布","关卡进程","意义对照","证据签发"] as const;

function validateRun(run: RunEvidence): boolean {
  return run.stages.length === stages.length &&
    run.observations.length === stages.length &&
    run.termination !== "timeout";
}
```

证据表至少包含以下列，且同一对照组只能修改一个计划变量。

```text
model,seed,variant,stage,input,state_before,state_after,metric,first_deviation,termination
gma-official-final-review,17,baseline,规则契约,fixed,0,1,1.0,,complete
gma-official-final-review,17,failure,模拟分布,fixed,1,9,9.0,模拟分布,rejected
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="结构或目录边界丢失">
  模拟胜率看似平衡，但真人测试暴露单一策略、软锁或主题表达相反。保存错误模型、首个偏离节点和原始轨迹，再恢复本页官方主题逐项复验。
</Callout>

<Callout type="trap" title="数字改善但设计目标恶化">
  故意让平均指标变好，同时减少有效选择、制造软锁、转移资源成本或破坏意义表达。若主指标改善但“性能、平衡、可达性与意义四类门必须同时通过，不能用一个好看的平均值替代”不成立，签发门必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 目录 | 官方主题逐项可定位 | 相邻主题交叉 | 故意漏一项 | 覆盖无空洞 |
| 状态 | 同输入可重放 | 容量或阈值附近 | 注入首个偏离 | 因果可定位 |
| 分布 | 多策略多种子 | 长尾与极端输入 | 统治策略或失控 | 结论不过拟合 |
| 体验 | 模型与玩家一致 | 新手或回退路径 | 误解、软锁或反表达 | 四门同时通过 |

**问题 1** 综合验收覆盖哪些官方主题？任选三个，写出它们之间的因果关系。

  本页覆盖 Rules-to-Mechanics Contract、Emergence and Progression Integration、Complex-System Boundary Tests、Internal-Economy Conservation、Executable Machinations Model、Feedback and Pattern Analysis、Simulated and Human Play Tests、Economy and Level Integration、Progression Reachability、Meaning Alignment、Reproducible Evidence Package。合格答案不是罗列名称，而要写出上游输入怎样改变中间状态，再怎样产生下游可观察结果。
</Answer>

**问题 2** 怎样主动制造“模拟胜率看似平衡，但真人测试暴露单一策略、软锁或主题表达相反”并证明修复有效？

<Answer>
  固定模型版本、参数和随机种子，只注入该故障；保存首个偏离节点与完整轨迹。修复后用相同输入复验，并确认指标、选择空间、可达性和体验没有发生新的转移性回归。
</Answer>

**问题 3** 为什么“性能、平衡、可达性与意义四类门必须同时通过，不能用一个好看的平均值替代”必须作为签发不变量？

<Answer>
  因为它连接了本页结构与最终设计目标。缺少该不变量时，局部数值可能改善，但系统可能通过隐藏成本、统治策略、软锁或错误表达把问题转移到其他位置。
</Answer>
