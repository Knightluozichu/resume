## 目录主线与因果关系

### 1. 先建立四层观察框架

同一功能必须同时回答机器怎样连接、状态怎样共享、服务怎样获利、团队怎样运营。只看套接字会遗漏支付与运维，只看商业又无法解释延迟和容量边界。

先预测：如果省略这一层，正常样本可能仍然成功，但边界或故障样本会在哪个状态首先偏离？

### 2. 两类案例承担验证责任

K Online用C/S MMO验证持久世界、空间分割和数据库；J Multiplayer用P2P MO验证共享状态、竞争控制与NAT问题。两者不是并列名词，而是架构取舍的对照实验。

先预测：如果省略这一层，正常样本可能仍然成功，但边界或故障样本会在哪个状态首先偏离？

### 3. 把上线当作系统的一部分

辅助系统、成本估算、监控、负荷测试和团队移交决定服务能否长期运行，因此学习终点不是客户端连通，而是故障后可恢复、可解释、可继续交付。

先预测：如果省略这一层，正常样本可能仍然成功，但边界或故障样本会在哪个状态首先偏离？

## 小结

- **四层观察框架**：从物理、概念、商业与组织四个层面描述同一网络游戏服务。
- **C/S MMO**：由长期运行的权威服务器维护大规模持久世界的客户机/服务器游戏。
- **P2P MO**：由少量玩家节点直接共享对局状态、通常没有专用游戏服务器的多人游戏。
- **辅助系统**：围绕匹配、聊天、排行、更新、支付和运营构成的非主循环能力集合。
- **可追踪目录**：把每个公开分节映射到页面、实验、题目与验收证据的覆盖方法。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
- 公开目录已逐项追踪，现代补充不会冒充原书分节。
