## 直觉引入

想象你在看一场远程直播的足球赛。状态同步就像解说员每 10 秒播报一次所有球员的位置：「1 号在左路 30 米，9 号在禁区，守门员在门线」。你收到的是**结果**——每个人此刻在哪。但 10 秒一次的播报太粗糙，球员看起来会瞬移。于是你在两次播报之间做**插值**——根据前后两次位置平滑过渡，让球员跑起来流畅。这就是状态同步+快照插值的核心：服务器定期下发世界快照，客户端在快照间插值渲染。

## 快照：世界的定时切片

<Term def="状态同步是服务器演算全部游戏逻辑后周期性下发世界状态快照、客户端负责插值渲染的同步策略，天然保证服务器权威但带宽消耗较大。">状态同步</Term>与帧同步相反——服务器是唯一的逻辑权威。服务器以固定频率（如 20Hz）把所有需要同步的对象状态打包成**快照**（Snapshot）下发。每个快照包含一组对象的状态：位置、朝向、速度、动画状态等。客户端收到快照后不直接渲染当前值，而是存入缓冲区，在两个快照之间做时间插值。

```cpp
struct Snapshot {
    uint32_t frameId;
    float    timestamp;
    std::vector<ObjectState> states; // 所有可见对象的状态
};

struct ObjectState {
    uint32_t id;
    Vector3  position;
    Quaternion rotation;
    Vector3  velocity;
    uint8_t  animState;
};

class StateSyncClient {
    std::deque<Snapshot> snapshotBuffer; // 快照缓冲区

    void OnSnapshot(const Snapshot& snap) {
        snapshotBuffer.push_back(snap);
        // 保持缓冲区有约 100ms 的历史数据用于插值
        while (snapshotBuffer.size() > 3) snapshotBuffer.pop_front();
    }

    void Render(float renderTime) {
        // renderTime = 服务器时间 - 插值延迟（如 100ms）
        // 在两个快照之间线性插值
        auto& s0 = snapshotBuffer[0];
        auto& s1 = snapshotBuffer[1];
        float alpha = (renderTime - s0.timestamp) / (s1.timestamp - s0.timestamp);
        alpha = clamp(alpha, 0, 1);

        for (auto& obj : visibleObjects) {
            auto* a = findState(s0, obj.id);
            auto* b = findState(s1, obj.id);
            obj.position = lerp(a->position, b->position, alpha);
            obj.rotation = slerp(a->rotation, b->rotation, alpha);
        }
    }
};
```

## 插值延迟：用延迟换平滑

客户端不是收到快照就立刻渲染，而是**故意延迟一小段**（通常 100ms）再渲染。这段延迟让客户端手里始终有「过去两个快照」的数据可以插值。如果没有这个延迟——收到快照就渲染——在快照到达抖动时会看到角色瞬移和抖动。插值延迟的本质是**用恒定的小延迟换取渲染平滑**：宁可所有人慢 100ms，也不要忽快忽慢地跳。

## 客户端预测与服务器校正

本地玩家的操作如果走纯状态同步，每次按键要等服务器返回才知道结果——100ms+ 的延迟让手感极差。**客户端预测**让本地客户端先本地模拟自己的操作结果（移动、碰撞），不等服务器。服务器返回的权威快照到了再**校正**：如果预测和权威一致，无缝继续；如果有偏差，把客户端状态修正到权威值。小偏差用插值平滑过渡（避免瞬移），大偏差直接跳变。

## 常见误区

<Callout type="trap">
**误区：插值延迟越小手感越好，应该尽量压低。** 插值延迟必须大于快照到达的抖动范围。如果服务器 20Hz 发快照（每 50ms 一个），但网络抖动让偶尔两个快照间隔变成 120ms，那么插值延迟至少要 100ms 才能保证插值时手里有前后两个快照。设成 50ms 的话，一旦抖动超过 50ms，客户端手里只有一个快照无法插值，角色就会瞬移。插值延迟是「平滑」与「实时」的权衡，不是越低越好。
</Callout>

<Exercises>
**问题 1**：状态同步中插值延迟的作用是什么？为什么不能设为零？

<Answer>
插值延迟让客户端手里始终保留「过去两个快照」用于线性插值渲染。如果设为零（收到即渲染），网络抖动会导致快照到达间隔不均匀——有时 30ms，有时 120ms——角色就会忽快忽慢甚至瞬移。设为约 100ms 后，即使快照延迟到达，客户端手里仍有足够的历史数据做平滑插值。本质是用恒定的小延迟换取渲染连续性：宁可所有人稳定慢 100ms，也不要不稳定地跳。
</Answer>

**问题 2**：客户端预测如何改善本地玩家的手感？校正时如何处理偏差？

<Answer>
纯状态同步中本地玩家每次按键要等服务器 RTT 后才看到结果，手感极差。客户端预测让本地客户端立即模拟自己的操作结果（不等服务器），操作响应零延迟。服务器权威快照到达后做校正：若预测与权威一致则无缝继续；若有偏差则修正。小偏差用插值平滑过渡到权威位置（避免可见瞬移），大偏差直接跳变（说明预测严重错误）。预测的正确率越高（物理规则与服务器一致），校正的可见偏差越少。
</Answer>
</Exercises>
