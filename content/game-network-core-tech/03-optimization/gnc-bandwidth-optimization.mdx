## 直觉引入

想象你在向朋友描述一幅不断变化的画。最笨的办法是每次都描述整幅画——天空是蓝的，草地是绿的，房子在中间……但画的大部分没变，只有一朵云在飘。聪明的做法是第一次描述全画，之后只说「那朵云向右移了 2 米」。这就是 **Delta 压缩**——只传变化量。进一步，你不需要说「向右移动了 2.374829 米」，精度到分米就够了——「向右 0.2 米」用更少的话表达同样的信息。这就是**量化**。把每个数字都用恰好够用的位数编码，就是**位打包**。

## Delta 压缩：只传变化

<Term def="Delta 压缩是状态同步中只下发与上一份快照差异部分的带宽优化技术，核心是维护一份双方共享的基准快照，仅传输变化字段。">Delta 压缩</Term>的前提是服务器和客户端都保留最近一份快照作为**基准**。新快照到来时，服务器逐字段对比：没变的字段不传，变了的字段只传新值。为了告诉客户端「哪些字段变了」，用一个**变更位掩码**（Changed Bitmask）——每个字段对应一位，1 表示变化，0 表示不变。客户端先读位掩码，再按位读取变化的字段。

```cpp
// 字段位掩码定义
enum ObjectFields : uint32_t {
    POSITION = 1 << 0,
    ROTATION = 1 << 1,
    VELOCITY = 1 << 2,
    HEALTH   = 1 << 3,
    ANIM     = 1 << 4,
};

struct DeltaHeader {
    uint32_t objectId;
    uint32_t changedMask; // 哪些字段变了
};

void writeDelta(BitWriter& w, const ObjectState& prev, const ObjectState& curr) {
    uint32_t mask = 0;
    if (prev.position != curr.position) mask |= POSITION;
    if (prev.rotation != curr.rotation) mask |= ROTATION;
    if (prev.health   != curr.health)   mask |= HEALTH;
    // ... 其他字段
    w.WriteBits(mask, 5); // 5 位掩码

    if (mask & POSITION) writeQuantizedVec3(w, curr.position);
    if (mask & ROTATION) writeQuantizedQuat(w, curr.rotation);
    if (mask & HEALTH)   w.WriteBits(curr.health, 7); // 0-127 足够
}
```

## 位打包：一个 bit 都不浪费

默认情况下，一个 `int` 占 32 位，但游戏中的很多数值根本不需要这么多。血量 0-100 只需要 7 位（128）。玩家 ID 在 64 人对局中只需要 6 位。朝向角度 0-360 度量化到 256 级只需要 8 位。**位打包器**（BitWriter/BitReader）打破字节边界，把多个字段紧密排列——7 位血量 + 6 位 ID + 8 位朝向 = 21 位，不到 3 字节，而不是默认的 12 字节。

## 量化：精度够用就行

浮点位置 `x=123.456789` 占 32 位，但游戏地图通常不需要毫米级精度。把坐标量化到厘米级：`quantized = (int)(x * 100)`，地图范围 ±3276 米用 16 位有符号整数即可表示，比 32 位浮点省一半。四元数旋转的四个分量中只有三个独立（模为 1），可以只传三个最小的分量加一个 2 位的索引标识最大的分量，用 3×9 + 2 = 29 位表示完整旋转，比 4×32 = 128 位省 75%。

## 常见误区

<Callout type="trap">
**误区：Delta 压缩必须保证基准快照可靠到达。** Delta 压缩依赖客户端有正确的基准快照——如果基准丢了，Delta 就无法还原。但 UDP 不保证可靠，基准快照可能丢。解决方案不是「保证基准可靠」（那就退化成 TCP 了），而是周期性穿插**全量快照**（每 N 帧发一次完整状态），让丢失基准的客户端能自我修复。同时，关键状态变更走可靠通道，常规 Delta 走不可靠通道——丢了就等下一个全量快照。
</Callout>

<Exercises>
**问题 1**：位打包如何压缩一个血量字段（0-100）和玩家 ID（最多 64 人）？

<Answer>
默认 int 各占 32 位，血量 + ID = 64 位 = 8 字节。位打包按实际范围分配位数：血量 0-100 需要 7 位（2^7=128 ≥ 101），玩家 ID 0-63 需要 6 位（2^6=64）。总计 7 + 6 = 13 位 ≈ 1.6 字节，比 8 字节省 80%。位打包器打破字节边界，把两个字段紧密排列在一个 16 位字中，不浪费任何一个 bit。
</Answer>

**问题 2**：Delta 压缩中如果基准快照丢了怎么办？

<Answer>
Delta 压缩依赖客户端持有正确的基准快照来还原差异，但 UDP 不保证可靠，基准可能丢。解决方案有二：①周期性穿插全量快照——每隔 N 帧（如每 10 帧）发一次完整状态而非 Delta，丢失基准的客户端最多等 N 帧就能自我修复；②关键状态变更走可靠通道保证到达，常规 Delta 走不可靠通道，丢了等下一个全量快照。不能为保证基准可靠而对所有包走可靠通道——那会引入队头阻塞，退化成 TCP 的问题。
</Answer>
</Exercises>
