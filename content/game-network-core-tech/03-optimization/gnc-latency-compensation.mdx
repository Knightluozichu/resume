## 直觉引入

想象你用一把狙击枪瞄准一个移动的靶子。光从靶子到你眼睛要时间，你的手指扣扳机到子弹飞出要时间，子弹飞到靶子要时间——你瞄准的永远是靶子「过去」的位置。现实里光速够快，这个延迟可以忽略。但在网络游戏中，靶子的位置从对方客户端 → 服务器 → 你的客户端，要经历 100ms+ 的网络延迟。你看到的靶子其实是它 100ms 前的位置。如果你直接瞄准你看到的位置开火，子弹到达时靶子早就移走了——这公平吗？延迟补偿就是解决这个「时间错位」的工程手段。

## 核心事实：收到的都是过去

网络游戏有一个不可违背的物理事实：**所有收到的状态都是过去的**。你看到的远程玩家位置是它 100ms 前的位置；你发出的开火指令到达服务器时也是 100ms 后了。如果不补偿，高延迟玩家永远打不中移动目标——不是技术差，是物理定律不公。延迟补偿的目标就是**让每个玩家在自己屏幕上看到什么，就按那个时刻判定**，消除延迟带来的不公平。

## 服务器端回退判定

<Term def="服务器端回退（Lag Compensation）是服务器保存近期历史快照、在处理玩家射击请求时把世界状态回退到该玩家开火时刻来判定命中的延迟补偿技术。">服务器端回退</Term>是 FPS 游戏的标准做法。服务器维护一个**历史快照环形缓冲区**，记录过去约 1 秒内所有玩家的位置。当玩家 A 的开火请求到达时（假设延迟 100ms），服务器不按当前状态判定，而是把时间回退到 A 开火那一刻——查缓冲区中 100ms 前所有玩家的位置——在 A 当时看到的世界状态下判定是否命中。

```cpp
class LagCompensator {
    // 环形缓冲区：保存最近 1 秒的所有玩家位置，按时间索引
    std::deque<TimedSnapshot> history; // 每个快照带时间戳

    bool ProcessFire(PlayerId shooter, Vector3 aimDir, float clientTime) {
        // clientTime = 玩家按下开火时的世界时间（嵌入客户端包）
        // 找到最接近 clientTime 的历史快照
        auto& snap = findSnapshotAt(history, clientTime);

        // 在该历史时刻的世界状态下做射线检测
        Ray ray{snap.GetPosition(shooter), aimDir};
        for (auto& [pid, pos] : snap.positions) {
            if (pid == shooter) continue;
            if (rayHitsHitbox(ray, pos, HITBOX_SIZE)) {
                dealDamage(pid, shooter->weaponDamage);
                return true; // 命中！按玩家看到的世界判定
            }
        }
        return false;
    }

    void OnTick(float dt) {
        history.push_back(captureCurrentSnapshot());
        // 丢弃超过 1 秒的历史
        while (history.front().time < now - 1.0f) history.pop_front();
    }
};
```

## 客户端前移插值

服务器端回退解决了「射击公平」，但渲染层面还有问题：远程玩家在你的屏幕上永远是 100ms 前的位置——他停下来了你还要等 100ms 才看到他停。**前移插值**（Extrapolation）在快照间隔超过预期时，根据最后已知的速度和方向**预测**实体的未来位置，让渲染更贴近「现在」。但预测有风险：如果实体突然转向或停止，预测位置会偏，下一个快照到来时需要校正（瞬移）。因此前移插值只做短时预测（几十毫秒），且优先用插值而非外推。

## 常见误区

<Callout type="trap">
**误区：回退判定让高延迟玩家占便宜，应该限制最大回退时间。** 回退判定不是「给高延迟玩家优待」，而是「还给每个玩家他当时看到的真相」。低延迟玩家看到的接近实时，回退量小；高延迟玩家看到的是更旧的过去，回退量大。如果不做回退，高延迟玩家永远打不中人——他瞄准的是 100ms 前的位置，但服务器按当前（已经移走了）的位置判定，这对高延迟玩家极不公平。回退判定的本质是「让每个玩家对自己屏幕上看到的世界负责」。当然，最大回退时间要限制（如 200ms），避免 500ms 延迟的玩家回退到荒谬的过去。
</Callout>

<Exercises>
**问题 1**：服务器端回退判定如何保证射击公平？

<Answer>
服务器维护近 1 秒的历史快照环形缓冲区。当玩家的开火请求到达时（含客户端时间戳），服务器不按当前世界状态判定，而是查缓冲区找到该玩家开火那一刻的世界快照，在那个历史状态下做射线检测。这意味着：玩家 A 看到目标在 X 位置时开火，服务器判定时也把目标回退到 X 位置——A 打中了他看到的目标。每个玩家不管延迟高低，都按「自己当时看到的世界」被判定，消除了延迟导致的不公平。
</Answer>

**问题 2**：客户端前移插值（外推）有什么风险？如何控制？

<Answer>
前移插值在快照延迟到达时根据最后已知速度和方向预测实体未来位置，让渲染更贴近「现在」。风险是预测可能出错——实体突然转向或停止时，预测位置与实际位置偏差大，下一个快照到来时需要校正，表现为角色瞬移。控制方法：①只做短时预测（几十毫秒），不长时间外推；②优先用插值（两个已知快照间）而非外推（超出已知快照）；③预测偏差大时用插值平滑过渡而非直接跳变，减少可见瞬移感。
</Answer>
