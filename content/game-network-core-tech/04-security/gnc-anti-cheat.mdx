## 直觉引入

想象一家银行的金库。最外层是银行大门的保安（客户端反篡改）——检查你是不是带武器进来。第二层是柜台职员（输入校验）——你递一张取款单说要取 100 万，职员要查你账上有没有这么多钱。第三层是金库审计（服务器权威）——不管你怎么填单子，最终钱从金库拿出来要审计员按账本核对。第四层是事后稽查（行为检测）——如果发现某个账户每天取款 100 次每次刚好卡限额，系统标记可疑。反作弊就是这种层层设防：每一层防不同的作弊手段，没有银弹，只有纵深防御。

## 第一层：服务器权威

<Term def="服务器权威是反作弊的基石——所有关键游戏逻辑（位置、伤害、经济）由服务器计算，客户端的输入只是「请求」而非「指令」，服务器永远不信任客户端发来的状态。">服务器权威</Term>是反作弊最重要的原则。核心思想：**客户端可以请求，但服务器决定**。客户端说「我往前走了 10 米」，服务器不是照单全收，而是自己模拟「按这个输入你应该走到哪」，再告诉客户端结果。客户端说「我打中了敌人 100 血」，服务器自己判定「按你的位置和朝向，这枪能不能打中、打中多少血」。所有关键状态（血量、位置、伤害、经济）都以服务器为准，客户端只是渲染服务器告诉它的世界。

```cpp
// 服务器权威：客户端发输入，服务器演算结果
class AuthoritativeServer {
    void OnPlayerMove(PlayerId pid, const MoveInput& input) {
        Player& p = players[pid];
        // 不信任客户端发来的位置！只用输入做服务器端模拟
        Vector3 newPos = simulateMove(p.position, input, FIXED_DT);

        // 合理性校验：移动速度是否超限
        float dist = distance(p.position, newPos);
        float maxDist = p.speed * FIXED_DT * 1.1f; // 允许 10% 误差
        if (dist > maxDist) {
            // 速度作弊！拒绝并回弹
            sendToClient(pid, TeleportMsg{p.position}); // 强制拉回
            flagSuspicious(pid, "speed_hack");
            return;
        }
        p.position = newPos;
        // 下发权威位置给所有客户端
        broadcastState(p);
    }

    void OnPlayerFire(PlayerId pid, const FireInput& input) {
        Player& p = players[pid];
        // 不信任客户端说的「我打中了谁」！服务器自己判定
        Ray ray{p.position, p.aimDir};
        HitResult hit = raycast(ray);
        if (hit.targetId != input.claimedTarget) {
            // 客户端谎报命中目标，可疑
            flagSuspicious(pid, "hit_mismatch");
            return;
        }
        dealDamage(hit.targetId, p.weaponDamage); // 服务器算伤害
    }
};
```

## 第二层：输入合理性校验

即使服务器权威，也要对客户端输入做合理性校验。**速度校验**——玩家每帧移动距离不能超过最大速度。**射线校验**——客户端声称的命中目标要和服务器射线检测结果一致。**范围校验**——数值（伤害、血量）要在合法范围内。**频率校验**——每秒开火次数不能超过武器射速。这些校验不是「防住所有作弊」，而是「让作弊的成本和风险急剧上升」——每次作弊都可能触发标记，积累到阈值就封号。

## 第三层：行为检测

有些作弊不违反物理规则但行为异常——自动瞄准（Aimbot）的每次准星移动都完美锁定头部，人类做不到。**行为检测**用统计分析找异常：命中率异常高、反应时间异常短、准星移动轨迹过于规则。这些不直接判定作弊（可能高手也准），而是累积可疑分数，结合其他信号（举报、多账号关联）综合判断。近年来机器学习被引入反作弊——用正常玩家和已知作弊者的行为数据训练分类模型，检测新型作弊模式。

## 第四层：客户端反篡改

客户端反篡改是最后一道防线，也是最弱的防线——因为客户端在玩家手里，理论上可以被逆向。**代码完整性校验**检测游戏可执行文件是否被修改。**内存反扫描**检测注入的作弊 DLL。**调试器检测**阻止逆向工程。但这些都只能提高门槛，无法根除—— determined 的作弊者总能绕过客户端保护。因此客户端反篡改只能作为辅助手段，核心防线必须在服务器端。

## 常见误区

<Callout type="trap">
**误区：客户端检测到作弊就立刻封号，最有效。** 客户端检测是最不可靠的——它在玩家手里，作弊者可以绕过检测、伪造「正常」信号。如果依赖客户端检测立刻封号，会出现两种灾难：①作弊者绕过检测继续作弊；②正常玩家被误判封号（某些驱动、录屏软件触发误报）。正确策略是：客户端检测只作为「信号」上报服务器，服务器结合多维度（行为统计、举报、关联账号）综合判断，确认后才封号，且封号要延迟执行（不告诉作弊者是哪个检测触发的），避免作弊者快速迭代绕过。
</Callout>

<Exercises>
**问题 1**：为什么服务器权威是反作弊的基石？如果客户端可以直接报告自己的位置会怎样？

<Answer>
如果客户端直接报告自己的位置，作弊者可以伪造任意位置——瞬移到任意坐标、穿墙、飞到空中。服务器权威要求客户端只发输入（按键），服务器自己模拟得出位置，作弊者最多能伪造按键，但物理规则（速度上限、碰撞）由服务器执行，无法突破。服务器权威把「游戏状态的正确性」从不可信的客户端转移到可信的服务器，是反作弊的第一道也是最重要的防线。没有服务器权威，后续所有校验都是空中楼阁。
</Answer>

**问题 2**：反作弊为什么要「分层纵深防御」而非单一银弹？

<Answer>
没有单一手段能防住所有作弊。服务器权威防状态伪造但防不了 Aimbot（输入合法但行为完美）；输入校验防超速但防不了透视（不修改状态只读内存）；行为检测防异常模式但需要积累数据、有延迟；客户端反篡改提高门槛但在玩家手里可被绕过。分层防御让每种作弊手段都有对应的检测层，作弊者要同时绕过所有层才能成功，成本急剧上升。且各层信号可以交叉验证降低误判——单一信号可能是误报，多信号同时触发则高度可疑。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="服务器权威">反作弊基石。所有关键游戏逻辑由服务器计算，客户端输入只是「请求」而非「指令」。把状态正确性从不可信客户端转移到可信服务器。</GlossaryItem>
<GlossaryItem term="输入合理性校验">服务器对客户端输入做速度、射线、范围、频率等合理性检查。不是防住所有作弊，而是让每次作弊都可能触发标记，累积到阈值封号。</GlossaryItem>
<GlossaryItem term="行为检测">用统计分析检测不违反物理规则但行为异常的作弊（如 Aimbot 命中率过高）。累积可疑分数结合多信号综合判断，机器学习日益重要。</GlossaryItem>
<GlossaryItem term="客户端反篡改">检测游戏文件修改、内存注入、调试器附加的客户端保护。在玩家手中可被绕过，只能提高门槛，作为辅助手段而非核心防线。</GlossaryItem>
<GlossaryItem term="纵深防御">反作弊方法论：服务器权威+输入校验+行为检测+客户端反篡改多层配合。没有银弹，每种作弊都有对应检测层，多信号交叉验证降低误判。</GlossaryItem>
</Glossary>
