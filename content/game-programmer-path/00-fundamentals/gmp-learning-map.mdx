## 直觉引入

成为游戏程序员像修炼武功。先练基本功（C++ 语言），再修内功（数据结构），然后学招式（算法），接着掌握兵器（引擎），最后实战演练（面试）。基本功不牢走不远，内功不足打不硬。

全书核心线索是：先打语言基础，再修数据结构和算法内功，然后学引擎和图形技术，最后准备面试进入行业。每一层都建立在前一层之上。

## 代码对照

```cpp
// 游戏程序员的技术栈全景
// 1. C++ 基础：内存管理、模板、RAII
// 2. 数据结构：数组、链表、树、哈希表
// 3. 算法：排序、搜索、动态规划
// 4. 引擎：游戏循环、组件系统、资源管理
// 5. 图形：渲染管线、着色器、空间裁剪
// 6. 玩法：状态机、行为树、事件系统

// 示例：一个游戏程序员每天都在写的代码
class GameObject {
    std::vector<Component*> components; // 数据结构
public:
    template<typename T>           // C++ 模板
    void AddComponent() {
        components.push_back(new T()); // 引擎组件系统
    }
    void Update(float dt) {
        for (auto* c : components)  // 算法遍历
            c->Update(dt);
    }
};
```

## 常见误区

<Callout type="trap">
**现象：跳过数据结构和算法直接学引擎。**
原因：引擎是上层应用，数据结构和算法是底层基础。没有基础学引擎只能「调 API」，不能理解原理。修法：先打牢 C++ 和数据结构算法基础，再学引擎时才能理解引擎为什么这样设计。
</Callout>

<Callout type="trap">
**现象：只学理论不做项目。**
原因：游戏编程是实践性极强的领域，理论不落地等于没学。修法：每学一个知识点就写一个小 demo——学链表写内存池，学渲染写软光栅化器，学引擎写迷你游戏引擎。
</Callout>

<Exercises>
**问题 1**：全书四大板块是什么？它们之间是什么关系？

<Answer>
基础入门（学习地图/职业路径）、核心技能（C++/数据结构/算法）、高级技术（引擎/图形/玩法/面试）、总复习。呈金字塔递进关系：基础入门提供方向认知，核心技能打底层内功，高级技术建上层能力，总复习串联全部。每一层都建立在前一层之上——C++ 不牢学不好引擎，数据结构不精算法面试过不了。
</Answer>

**问题 2**：游戏程序员的知识体系为什么是金字塔结构？

<Answer>
底层是 C++ 语言（工具），中层是数据结构与算法（内功），上层是引擎/图形/玩法（应用）。金字塔结构意味着：底层不稳上层会塌——不懂内存管不了引擎资源，不懂数据结构优化不了算法。越底层的知识越通用（C++ 到处用），越上层的知识越专用（引擎 API 各不同）。学习应从底向上，但实践可以从顶向下——先用引擎做项目再回头补基础。
</Answer>
</Exercises>
