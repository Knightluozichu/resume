## 直觉引入

算法是解决问题的步骤。同样的任务，好算法 1 秒完成，坏算法 1 小时。大 O 表示法告诉你算法「数据量变大时变慢的速度」——O(n) 翻倍数据翻倍时间，O(n^2) 翻倍数据变 4 倍时间。

游戏每帧只有 16 毫秒（60fps）。一个 O(n^2) 的碰撞检测，100 个对象只需 0.1ms，1000 个对象就要 10ms——吃掉一帧 60% 的时间。这就是为什么算法选择在游戏中至关重要。

## 概念讲解

### 大 O 表示法

<GmpAlgorithmsDiagram />

<Term def="描述算法运行时间随输入规模增长的上界的数学表示">大 O 表示法</Term>忽略常数和低阶项，只关注增长趋势。常见等级：O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n)。

<Term def="将问题分解为子问题递归求解再合并的算法策略，通常产生 O(n log n) 复杂度">分治法</Term>是排序（归并/快排）和搜索（二分）的基础思想。

### 游戏常用算法

<Term def="将空间划分为网格或树结构以减少碰撞检测的算法">空间划分</Term>是游戏最重要的算法之一。暴力碰撞检测 O(n^2)，用四叉树/八叉树划分空间后降到 O(n log n)。

## 代码对照

```cpp
// 碰撞检测：暴力 vs 空间划分
// 暴力 O(n^2) — 1000 个对象 = 100 万次检测
void BruteForceCollision(std::vector<Object>& objs) {
    for (int i = 0; i < objs.size(); ++i)
        for (int j = i+1; j < objs.size(); ++j)
            if (Intersect(objs[i], objs[j]))
                HandleCollision(objs[i], objs[j]);
}

// 空间划分 O(n log n) — 四叉树只检测邻近对象
void QuadTreeCollision(std::vector<Object>& objs) {
    QuadTree tree(bounds);
    for (auto& o : objs) tree.Insert(o);     // O(log n) per insert
    for (auto& o : objs) {
        auto nearby = tree.Query(o.bounds);   // O(log n) per query
        for (auto* n : nearby)
            if (Intersect(o, *n))
                HandleCollision(o, *n);
    }
}
```

## 常见误区

<Callout type="trap">
**现象：游戏循环中用 O(n^2) 算法处理大量对象。**
原因：n=100 时 O(n^2) 还好（10000 次），n=1000 时就爆炸（100 万次）。修法：用空间划分（四叉树/网格）将 O(n^2) 降为 O(n log n) 或 O(n)。碰撞检测、邻居查找、影响范围计算都应空间划分。
</Callout>

<Callout type="trap">
**现象：只看大 O 不看常数因子。**
原因：大 O 忽略常数，但实际中常数可能很大。O(n) 的算法如果每次迭代重 100 倍，可能比 O(n log n) 慢。修法：大 O 用于定性判断趋势，实际性能还需 Profiler 验证。但先保证大 O 不差（不在循环中嵌套 O(n)），再优化常数。
</Callout>

<Exercises>
**问题 1**：为什么游戏循环中的 O(n^2) 算法是危险的？

<Answer>
游戏每帧只有 16ms（60fps）。O(n^2) 算法在 n=100 时约 10000 次操作（0.1ms），n=1000 时约 100 万次操作（10ms），吃掉一帧 60% 的时间。n=10000 时约 1 亿次操作（100ms），直接卡到 10fps。游戏对象数量随场景复杂度增长，O(n^2) 算法在数据量增长时会突然「爆炸」。应将 O(n^2) 优化为 O(n log n) 或 O(n)。
</Answer>

**问题 2**：空间划分算法如何将碰撞检测从 O(n^2) 降为 O(n log n)？

<Answer>
暴力碰撞检测对每对对象检测碰撞，共 n*(n-1)/2 对，O(n^2)。空间划分（四叉树/网格）将空间分为区域，每个对象只与同区域和相邻区域的对象检测。构建树 O(n log n)，每个对象查询邻居 O(log n)，总共 O(n log n)。大部分远距离对象被空间分区过滤掉，不需要检测。实际中网格法在均匀分布场景更快（接近 O(n)），四叉树在不均匀分布场景更优。
</Answer>
</Exercises>
