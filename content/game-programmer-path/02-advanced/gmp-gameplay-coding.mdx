## 直觉引入

角色站在地上按跳跃键，进入跳跃状态。跳跃中按攻击键，进入空中攻击状态。落地回到待机状态。这些状态切换就是状态机——角色在任何时刻只能处于一个状态，状态间按条件切换。

复杂的 AI 需要更灵活的逻辑。敌人先判断能否看到玩家（条件），能看到就追击（行为），追不到就巡逻（行为）。这就是行为树——用树结构组织决策和行为，比状态机更灵活。

## 概念讲解

### 状态机

<GmpGameplayCodingDiagram />

<Term def="用有限状态描述对象行为模式的模式，对象在任一时刻只处于一个状态">有限状态机</Term>（FSM）是最简单的游戏逻辑模式。每个状态有进入、更新、退出三个回调，状态间通过条件触发切换。适合角色控制（Idle/Run/Jump/Attack）。

<Term def="用树结构组织 AI 决策和行为的模式，支持选择节点、序列节点和装饰节点">行为树</Term>比状态机更灵活。选择节点（找第一个可执行的子节点）、序列节点（依次执行所有子节点）、装饰节点（修饰子行为如重复/反转）。适合复杂 AI。

### 事件系统

<Term def="发布-订阅模式的消息系统，发送者不直接调用接收者而是通过事件解耦">事件系统</Term>是游戏逻辑解耦的核心。角色死亡触发 OnDeath 事件，UI 监听显示死亡画面，音效监听播放死亡音效。发送者不需要知道谁在监听。

## 代码对照

```cpp
// 有限状态机：角色控制
class PlayerStateMachine {
    enum State { Idle, Run, Jump, Attack };
    State current = Idle;
    
    void Update(float dt) {
        switch (current) {
            case Idle:
                if (input.IsMoving()) ChangeState(Run);
                if (input.JumpPressed()) ChangeState(Jump);
                break;
            case Jump:
                if (IsGrounded()) ChangeState(Idle);
                break;
        }
    }
};

// 事件系统：解耦
class EventBus {
    std::unordered_map<EventType, std::vector<std::function<void()>>> listeners;
public:
    void Subscribe(EventType type, std::function<void()> callback) {
        listeners[type].push_back(callback);
    }
    void Publish(EventType type) {
        for (auto& cb : listeners[type]) cb();
    }
};
// 用法：角色死亡 → Publish(OnDeath) → UI/音效/成就 各自响应
```

## 常见误区

<Callout type="trap">
**现象：用状态机做复杂 AI，状态数量爆炸。**
原因：状态机状态数随行为数指数增长，10 个行为可能有 100+ 个状态和切换。修法：复杂 AI 用行为树——行为独立定义，用选择/序列节点组合，不需要为每个行为组合定义状态。
</Callout>

<Callout type="trap">
**现象：游戏逻辑各系统直接互相调用。**
原因：直接调用导致强耦合，改一个系统要改所有依赖它的系统。修法：用事件系统解耦——系统间通过事件通信，发送者不依赖接收者。新增功能只需订阅新事件，不改现有代码。
</Callout>

<Exercises>
**问题 1**：状态机和行为树分别适合什么场景？

<Answer>
状态机适合简单逻辑和角色控制——状态数量少（如 Idle/Run/Jump/Attack）、切换条件清晰。每个状态有进入/更新/退出回调，状态间通过条件切换。行为树适合复杂 AI——需要分层决策（先判断条件再选行为）、并行行为、优先级。行为树用选择节点（找第一个可执行的）、序列节点（依次执行所有）、装饰节点（修饰子行为）组织逻辑，比状态机更灵活不会状态爆炸。
</Answer>

**问题 2**：为什么游戏逻辑要用事件系统而非直接调用？

<Answer>
直接调用导致强耦合——A 调 B 的方法，A 就依赖 B 的接口，改 B 要改 A。事件系统解耦：A 触发事件不关心谁响应，B 监听事件不关心谁触发。优势：1. 新增功能不改现有代码（订阅新事件即可）。2. 多系统响应同一事件（角色死亡→UI+音效+成就各自响应）。3. 可测试性强（模拟事件即可测试各系统独立工作）。
</Answer>
</Exercises>
