## 直觉引入

面试不是考你会多少，而是考你解决问题的能力。面试官给你一道没见过的题，看你如何分析、如何拆解、如何从暴力解法优化到最优解。这个过程比最终答案更重要。

游戏程序员面试通常有四轮：算法面（写代码）、系统设计面（设计架构）、项目面（聊经验）、HR 面（聊软技能）。每轮考察不同维度，全面发展才能通过。

## 概念讲解

### 面试考察维度

<GmpInterviewDiagram />

<Term def="考察数据结构、算法和编码能力的面试轮次，通常要求白板或在线写代码">算法面试</Term>是技术面的核心。考察点：正确性（能不能写对）、复杂度（能不能分析大 O）、优化（能不能从暴力优化到最优）、边界处理（空输入/极大输入/特殊输入）。

<Term def="考察架构设计能力的面试轮次，要求设计一个系统的整体结构">系统设计面试</Term>考察点：需求分析（问清楚要做什么）、模块划分（怎么拆分）、技术选型（选什么方案）、扩展性（能扛多少量级）、权衡取舍（方案优劣）。

### 备考策略

算法备考：刷题 200-300 道，覆盖数组/链表/树/图/DP/贪心/回溯。按类型刷，每类掌握 2-3 个经典模板。系统设计备考：理解常见系统架构（游戏服务器/匹配系统/排行榜），练习从需求到架构的完整推导。

## 代码对照

```cpp
// 算法面试示例：两数之和
// 暴力 O(n^2) → 哈希表 O(n)
vector<int> TwoSum(vector<int>& nums, int target) {
    unordered_map<int, int> map; // 值→索引
    for (int i = 0; i < nums.size(); ++i) {
        int complement = target - nums[i];
        if (map.count(complement))
            return {map[complement], i}; // 找到配对
        map[nums[i]] = i;
    }
    return {};
}
// 面试关键：先说暴力解（O(n^2)），再说优化（哈希表 O(n)），
// 分析复杂度，处理边界（空数组/无解），写完验证
```

## 常见误区

<Callout type="trap">
**现象：只刷题不理解模板，遇到变体不会做。**
原因：死记答案不理解原理，题目换个说法就不会了。修法：每类题掌握核心模板和原理（如双指针/滑动窗口/单调栈），理解为什么这样做而非背答案。能举一反三才是真懂。
</Callout>

<Callout type="trap">
**现象：面试时直接写最优解，不讲解思路。**
原因：面试官不只看结果更看过程——你如何分析问题、如何从暴力到优化。修法：先讲暴力解法，分析复杂度，再说优化思路，最后写代码。边写边讲，让面试官跟着你的思路走。
</Callout>

<Exercises>
**问题 1**：技术面试和系统设计面试的区别是什么？

<Answer>
技术（算法）面试考察编码能力——给一道具体题目写代码，看正确性、复杂度、优化能力、边界处理。通常 30-45 分钟写 1-2 道题。系统设计面试考察架构能力——设计一个系统的整体结构（如设计游戏匹配系统），看需求分析、模块划分、技术选型、扩展性、权衡取舍。通常 45 分钟一个开放性问题。前者考「能不能写出正确高效的代码」，后者考「能不能设计合理的系统架构」。
</Answer>

**问题 2**：算法面试时应该如何讲解思路？

<Answer>
正确流程：1. 确认题意——复述题目确认理解无误，问清输入输出和边界。2. 说暴力解法——先说最直观的 O(n^2) 解法，表明你能解决。3. 分析复杂度——说清楚时间和空间复杂度。4. 说优化思路——「我注意到可以用哈希表把查找从 O(n) 降到 O(1)」。5. 写代码——边写边讲，变量命名清晰。6. 验证——用示例走一遍确认正确，检查边界。让面试官全程跟着你的思路走。
</Answer>
</Exercises>
