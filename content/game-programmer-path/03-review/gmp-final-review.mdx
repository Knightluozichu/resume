## 直觉引入

回顾全书，我们像修炼武功一样走完了游戏程序员的成长路径。先打语言基础（C++），再修内功（数据结构与算法），然后学兵器（引擎与图形），最后实战演练（面试）。每一层都建立在前一层之上。

全书的灵魂是那句话：语言是工具，数据结构是内功，算法是招式。工具不称手走不远，内功不足打不硬，招式不精打不赢。

## 代码对照

```cpp
// 全书知识串联：一个游戏对象的完整实现
// 1. C++ 基础：RAII + 智能指针管理内存
class GameObject {
    std::vector<std::unique_ptr<Component>> components; // 智能指针
    
    // 2. 数据结构：用数组（缓存友好）存组件
    template<typename T> T* AddComponent() {
        components.push_back(std::make_unique<T>());
        return static_cast<T*>(components.back().get());
    }
    
    // 3. 算法：每帧遍历更新，O(n) 但缓存友好
    void Update(float dt) {
        for (auto& c : components) c->Update(dt);
    }
};

// 4. 引擎：组件系统，组合优于继承
// 5. 图形：渲染管线，DrawCall 合并
// 6. 玩法：状态机控制角色，事件系统解耦
// 7. 面试：能讲清楚每个设计决策的原因
```

## 常见误区

<Callout type="trap">
**现象：学了知识但不做项目，面试时讲不出实践经验。**
原因：游戏行业面试看重项目经验，纯知识不落地等于没有。修法：每学一个知识做一个小项目——学 C++ 做内存池，学数据结构做四叉树碰撞检测，学图形做软光栅化器，学引擎做迷你游戏引擎。项目是知识的最好证明。
</Callout>

<Callout type="trap">
**现象：只学上层 API 不学底层原理。**
原因：上层 API 变化快（Unity/Unreal 版本更新），底层原理不变（内存/算法/渲染管线）。修法：花 70% 时间学底层原理（C++/数据结构/算法/渲染原理），30% 时间学上层 API。面试考底层原理，工作用上层 API，两者结合才稳。
</Callout>

<Exercises>
**问题 1**：描述一个游戏程序员从入门到面试的完整学习路径。

<Answer>
1. C++ 基础：内存模型/RAII/智能指针/移动语义。2. 数据结构：数组/链表/树/哈希表，理解缓存友好性。3. 算法：排序/搜索/空间划分/动态规划，掌握大 O 分析。4. 引擎基础：游戏循环/组件系统/资源管理。5. 图形学：渲染管线/着色器/DrawCall 优化。6. 玩法编程：状态机/行为树/事件系统。7. 面试准备：刷题 200-300 道+系统设计练习。每步配合小项目实践。
</Answer>

**问题 2**：游戏程序员的核心能力三角是什么？三者如何协作？

<Answer>
编程基础（C++/内存管理）：决定能不能写出代码——RAII 管理资源、智能指针防泄漏、栈堆选择优化性能。算法思维（数据结构/复杂度分析）：决定能不能写出高效代码——选对数据结构（数组 vs 链表）、优化复杂度（O(n^2)→O(n log n)）、理解缓存友好性。工程实践（引擎/图形/玩法）：决定能不能做出游戏——游戏循环/组件系统/渲染管线/状态机。三者协作：基础保证代码能跑，算法保证跑得快，工程保证能做成产品。缺任何一角都是短板。
</Answer>
