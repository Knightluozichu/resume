## 痛点：没动也每帧重算

场景图里一个父节点动了，它的子节点、孙节点的世界变换都要重算。但如果这帧父节点根本没动，子节点也没动，重新算一遍世界矩阵纯属浪费。场景越大、层级越深，这种「没动也算」的浪费越严重。

## 解决方案：改了才标脏，要用才算

给每个对象挂一个 `dirty` 标记。修改了局部变换时把标记设为 `true`——意思是「我的世界变换过期了」。只有真正要用世界变换时，才检查标记：脏了就算一次并清标记，没脏就直接用上次的缓存结果。

<DirtyFlagDiagram />

```typescript
class SceneNode {
  private dirty = true;       // 世界变换是否过期
  private worldMatrix: Mat4;  // 缓存的世界变换

  setLocalTransform(m: Mat4) {
    this.local = m;
    this.dirty = true;        // 改了局部 → 标脏
    for (const child of this.children) child.markDirty(); // 子节点也过期
  }

  getWorldTransform(): Mat4 {
    if (this.dirty) {
      this.worldMatrix = this.parent.getWorldTransform().mul(this.local);
      this.dirty = false;     // 算完 → 清标
    }
    return this.worldMatrix;  // 没脏直接返回缓存
  }
}
```

父节点没动的帧，`getWorldTransform` 直接返回缓存——省掉了整棵子树的矩阵乘法。

<Callout type="tip">
脏标记的本质是「延迟计算」：把计算推迟到真正需要的那一刻，用标记记录「数据是否过期」。大部分帧数据没变，标记是干净的，计算就省了。
</Callout>

## 标脏的传播

一个节点的局部变换变了，它的所有子孙的世界变换也跟着过期——所以标脏要沿子树向下传播。但向上不影响：父节点变了子节点才过期，子节点变了父节点的世界变换不变。传播方向是单向向下的。

## 常见误区

### 误区 1：「每帧清掉脏标记最保险」

脏标记的价值在于「没脏就不算」。如果每帧不管脏不脏都清掉并重算，等于退化回全量计算，标记白挂了。只有「按需检查、脏了才算」才能省掉没动帧的计算。

### 误区 2：「标脏不标脏无所谓，反正最后都会算」

标脏是触发计算的开关。漏标会导致用了过期的缓存结果——对象明明动了，渲染却还用旧位置。标脏必须在所有可能修改数据的入口都做，漏一处就是 bug。

### 误区 3：「脏标记适合所有昂贵操作」

脏标记适合「修改少、查询多」的场景。如果每帧都改、每帧都要查，标记永远是脏的，反而多了维护标记的额外开销。只有「大部分帧数据不变」时，脏标记才有正收益。

## 小结

- 脏标记用布尔标记记录数据是否过期，修改时标脏，查询时按需重算并清标
- 场景图变换是典型场景：没动的帧直接用缓存，省掉整棵子树的矩阵乘法
- 标脏沿子树向下传播，父动子过期，子动父不变
- 只在「修改少、查询多」时有效，每帧都改都查的场景没收益

<Glossary>
<GlossaryItem term="脏标记">
一个布尔标志，记录某项派生数据是否因源数据修改而过期。为 true 时表示需要重新计算，计算后清除。
</GlossaryItem>
<GlossaryItem term="延迟计算">
把昂贵的计算推迟到结果真正被需要时才执行，而非每次修改后立即算。脏标记是实现延迟计算的常见手段。
</GlossaryItem>
<GlossaryItem term="场景图">
用树形结构组织场景中的对象，父节点的变换会传递影响子节点的世界变换。脏标记可避免没动的子树被重复计算。
</GlossaryItem>
