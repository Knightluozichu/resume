## 为什么“2. Command”从问题证据开始

物理按键直接调用角色方法，使重绑定、AI、回放和撤销互相缠绕。本页不把模式当成必选答案，而是先保存无模式基线，再验证候选机制是否真正改变可观察结果。通过条件是“相同命令流和初始状态产生相同角色状态”，而不是类或接口数量增加。

## 官方结构逐项深读

### 2. Command

命令把方法调用对象化，使输入映射、角色指令、撤销重做、录制与网络重放共享同一动作合同。

2. Command 的因果解释从“读取输入”开始：先标出输入、所有者和可见结果，再说明命令保存动作意图及必要参数，调用者延后把它交给明确目标执行。若没有模式的基线也能更简单地守住“相同命令流和初始状态产生相同角色状态”，这一节点应得出“不采用”的结论。

2. Command 的验证只改变一个条件，记录命令日志、目标ID、执行序号与撤销后状态；随后注入“撤销记录遗漏执行前位置或外部副作用”，定位首个分叉并执行重置。这样该节点同时具备出现、解释、专属实验和练习验证四级证据。

### Directions for Actors

### Undo and Redo

Classy and Dysfunctional? 是设计分叉题；回答必须说明选择怎样改变命令保存动作意图及必要参数，调用者延后把它交给明确目标执行，以及哪条反例会推翻选择。
