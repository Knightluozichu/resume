## 为什么“2. Command”从问题证据开始

物理按键直接调用角色方法，使重绑定、AI、回放和撤销互相缠绕。本页不把模式当成必选答案，而是先保存无模式基线，再验证候选机制是否真正改变可观察结果。通过条件是“相同命令流和初始状态产生相同角色状态”，而不是类或接口数量增加。

## 官方结构逐项深读

### 2. Command

命令把方法调用对象化，使输入映射、角色指令、撤销重做、录制与网络重放共享同一动作合同。

2. Command 的因果解释从“读取输入”开始：先标出输入、所有者和可见结果，再说明命令保存动作意图及必要参数，调用者延后把它交给明确目标执行。若没有模式的基线也能更简单地守住“相同命令流和初始状态产生相同角色状态”，这一节点应得出“不采用”的结论。

2. Command 的验证只改变一个条件，记录命令日志、目标ID、执行序号与撤销后状态；随后注入“撤销记录遗漏执行前位置或外部副作用”，定位首个分叉并执行重置。这样该节点同时具备出现、解释、专属实验和练习验证四级证据。

### Configuring Input

输入层把物理按键映射为命令对象，使重绑定、AI控制和回放不依赖具体设备。

Configuring Input 的因果解释从“生成命令”开始：先标出输入、所有者和可见结果，再说明命令保存动作意图及必要参数，调用者延后把它交给明确目标执行。若没有模式的基线也能更简单地守住“相同命令流和初始状态产生相同角色状态”，这一节点应得出“不采用”的结论。

Configuring Input 的验证只改变一个条件，记录命令日志、目标ID、执行序号与撤销后状态；随后注入“撤销记录遗漏执行前位置或外部副作用”，定位首个分叉并执行重置。这样该节点同时具备出现、解释、专属实验和练习验证四级证据。

### Directions for Actors

命令接收显式角色目标后可同时驱动玩家、AI或远端代理，消除对全局主角的隐式依赖。

Directions for Actors 的因果解释从“绑定目标”开始：先标出输入、所有者和可见结果，再说明命令保存动作意图及必要参数，调用者延后把它交给明确目标执行。若没有模式的基线也能更简单地守住“相同命令流和初始状态产生相同角色状态”，这一节点应得出“不采用”的结论。

Directions for Actors 的验证只改变一个条件，记录命令日志、目标ID、执行序号与撤销后状态；随后注入“撤销记录遗漏执行前位置或外部副作用”，定位首个分叉并执行重置。这样该节点同时具备出现、解释、专属实验和练习验证四级证据。

### Undo and Redo

可撤销命令保存执行前状态或逆操作，并把副作用、失败与合并边界写入日志。

Undo and Redo 的因果解释从“执行记录”开始：先标出输入、所有者和可见结果，再说明命令保存动作意图及必要参数，调用者延后把它交给明确目标执行。若没有模式的基线也能更简单地守住“相同命令流和初始状态产生相同角色状态”，这一节点应得出“不采用”的结论。

### Classy and Dysfunctional?

Classy and Dysfunctional? 是设计分叉题；回答必须说明选择怎样改变命令保存动作意图及必要参数，调用者延后把它交给明确目标执行，以及哪条反例会推翻选择。

Classy and Dysfunctional? 的因果解释从“撤销重放”开始：先标出输入、所有者和可见结果，再说明命令保存动作意图及必要参数，调用者延后把它交给明确目标执行。若没有模式的基线也能更简单地守住“相同命令流和初始状态产生相同角色状态”，这一节点应得出“不采用”的结论。

关联模式用于比较组合与替代，不应因为两个模式常一起出现就默认同时引入。

## 本章练习与节点验证矩阵

<Exercises>

**问题 1：基线与选择。** 怎样证明命令对象解决的是本页真实问题，而不是增加装饰性抽象？

<Answer>
  用同一构建、场景和输入分别运行直接调用与命令对象，比较命令日志、目标ID、执行序号与撤销后状态；候选方案只有在守住“相同命令流和初始状态产生相同角色状态”且主要代价下降时才保留。
</Answer>

**问题 2：逐节点验证。** 本页正式节点怎样从标题升级为可复查证据？

<Answer>
  - **2. Command**：执行“读取输入”，注入“撤销记录遗漏执行前位置或外部副作用”，以命令日志、目标ID、执行序号与撤销后状态判定是否守住不变量。
  - **Configuring Input**：执行“生成命令”，注入“撤销记录遗漏执行前位置或外部副作用”，以命令日志、目标ID、执行序号与撤销后状态判定是否守住不变量。
  - **Directions for Actors**：执行“绑定目标”，注入“撤销记录遗漏执行前位置或外部副作用”，以命令日志、目标ID、执行序号与撤销后状态判定是否守住不变量。
  - **Undo and Redo**：执行“执行记录”，注入“撤销记录遗漏执行前位置或外部副作用”，以命令日志、目标ID、执行序号与撤销后状态判定是否守住不变量。
  - **Classy and Dysfunctional?**：执行“撤销重放”，注入“撤销记录遗漏执行前位置或外部副作用”，以命令日志、目标ID、执行序号与撤销后状态判定是否守住不变量。
  - **See Also**：执行“读取输入”，注入“撤销记录遗漏执行前位置或外部副作用”，以命令日志、目标ID、执行序号与撤销后状态判定是否守住不变量。
</Answer>

**问题 3：反例与复位。** 注入“撤销记录遗漏执行前位置或外部副作用”后怎样关闭实验闭环？

<Answer>
  先定位第一个偏离“相同命令流和初始状态产生相同角色状态”的阶段，只修复该原因；随后重放正常、压力和故障路径，并点击重置确认状态、代际和计数全部回到同一初值。
</Answer>

</Exercises>
