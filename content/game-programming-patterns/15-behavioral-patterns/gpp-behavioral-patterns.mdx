{/* GPP_QUALITY_V2 */}

## 为什么“IV. Behavioral Patterns”从问题证据开始

大量角色与技能行为若都硬编码，迭代速度和安全性会同时下降。本页不把模式当成必选答案，而是先保存无模式基线，再验证候选机制是否真正改变可观察结果。通过条件是“内容作者的表达能力不越过运行时安全边界”，而不是类或接口数量增加。

## 官方结构逐项深读

### IV. Behavioral Patterns

行为模式让设计者组合、扩展和数据驱动游戏行为而不让类层次或硬编码分支失控。

IV. Behavioral Patterns 的因果解释从“统计行为”开始：先标出输入、所有者和可见结果，再说明从数据分类、受限原语到虚拟机逐级增加表达力和工具成本。若没有模式的基线也能更简单地守住“内容作者的表达能力不越过运行时安全边界”，这一节点应得出“不采用”的结论。

IV. Behavioral Patterns 的验证只改变一个条件，记录内容改动时间、可表达操作、沙箱边界与工具维护量；随后注入“为少量固定行为提前建设完整虚拟机”，定位首个分叉并执行重置。这样该节点同时具备出现、解释、专属实验和练习验证四级证据。

### The Patterns

分部导言建立模式之间的选择坐标，模式名称不是结论，问题、约束与反例才是选择依据。

The Patterns 的因果解释从“评估信任”开始：先标出输入、所有者和可见结果，再说明从数据分类、受限原语到虚拟机逐级增加表达力和工具成本。若没有模式的基线也能更简单地守住“内容作者的表达能力不越过运行时安全边界”，这一节点应得出“不采用”的结论。

The Patterns 的验证只改变一个条件，记录内容改动时间、可表达操作、沙箱边界与工具维护量；随后注入“为少量固定行为提前建设完整虚拟机”，定位首个分叉并执行重置。这样该节点同时具备出现、解释、专属实验和练习验证四级证据。

## 可迁移实现或计算骨架

```text
initial state -> 统计行为 -> 评估信任 -> 选择表达层 -> 限制能力 -> 测量迭代
fault injection -> 为少量固定行为提前建设完整虚拟机
pass condition -> 内容作者的表达能力不越过运行时安全边界
reset -> initial state
```

该骨架只保存实验合同；真实项目还要把平台、构建、场景、输入和统计窗口固定下来，并保留基线实现以便回退。
