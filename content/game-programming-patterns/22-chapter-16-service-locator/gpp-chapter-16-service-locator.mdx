# 16. Service Locator


{/* GPP_QUALITY_V2 */}

## 为什么“16. Service Locator”从问题证据开始

音频等服务从全局变量访问会隐藏依赖并让测试无法替换。本页不把模式当成必选答案，而是先保存无模式基线，再验证候选机制是否真正改变可观察结果。通过条件是“服务缺失和服务范围都有确定、可测试的行为”，而不是类或接口数量增加。

## 可迁移实现或计算骨架

```text
initial state -> 定义服务 -> 注册提供者 -> 定位实例 -> 调用能力 -> 替换释放
fault injection -> 服务尚未注册时调用返回悬空引用
pass condition -> 服务缺失和服务范围都有确定、可测试的行为
reset -> initial state
```

该骨架只保存实验合同；真实项目还要把平台、构建、场景、输入和统计窗口固定下来，并保留基线实现以便回退。
