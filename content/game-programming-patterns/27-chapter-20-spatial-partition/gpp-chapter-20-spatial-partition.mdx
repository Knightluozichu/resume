Are objects only stored in the partition? 的因果解释从“移动迁移”开始：先标出输入、所有者和可见结果，再说明对象进入网格或层级分区，移动时更新归属，查询只遍历相交单元。若没有模式的基线也能更简单地守住“分区查询不漏掉范围内对象，也不重复返回同一身份”，这一节点应得出“不采用”的结论。

## 可迁移实现或计算骨架

```text
initial state -> 计算单元 -> 插入分区 -> 范围查询 -> 移动迁移 -> 对照真值
fault injection -> 单位跨格移动后旧链表节点未移除
pass condition -> 分区查询不漏掉范围内对象，也不重复返回同一身份
reset -> initial state
```

该骨架只保存实验合同；真实项目还要把平台、构建、场景、输入和统计窗口固定下来，并保留基线实现以便回退。

<Callout type="trap" title="先选模式再找问题">
  20. Spatial Partition若没有“全体两两距离检查随单位数平方增长”的可重放样本，就不应引入候选模式。
</Callout>

<Callout type="trap" title="只看类图不看时序">
  20. Spatial Partition必须解释计算单元、插入分区、范围查询、移动迁移、对照真值之间谁先发生；最终结果相同不代表中间状态安全。
</Callout>

<Callout type="trap" title="只测顺利路径">
  故意触发“单位跨格移动后旧链表节点未移除”；若单元坐标、对象链、候选数、命中集合与全量真值无法定位首个分叉，实验和实现都不能通过。
</Callout>
