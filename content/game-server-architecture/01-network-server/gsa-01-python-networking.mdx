## 核心概念与所有权

<Term def="由地址、端口、协议和内核状态共同构成的通信端点。">Socket</Term>、<Term def="TCP提供的有序字节序列，不携带应用消息边界。">字节流</Term>、<Term def="UDP一次发送对应一个独立报文，但可能丢失、乱序或重复。">数据报</Term>、<Term def="调用立即返回，由就绪通知驱动后续收发。">非阻塞I/O</Term>、<Term def="把I/O就绪事件分派给注册处理器的事件循环模式。">Reactor</Term>。
这些概念必须同时回答四个问题：谁创建输入，谁拥有可变状态，哪个代际拒绝旧结果，失败后谁回滚或补偿。

## 目录主线与因果关系

### 1. Socket不是消息队列

bind、listen、connect只建立通信关系；recv可能少读，send也可能只写出一部分。应用必须维护独立缓冲区和消息长度。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 2. 阻塞模型决定容量上限

线程等待I/O时仍占栈和调度资源；非阻塞模型把等待转成事件，但要求连接状态只能由事件循环或明确的分片所有者修改。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 3. HTTP工具与Twisted的位置

SimpleHTTPServer、BaseHTTPServer和urllib用于理解请求边界；Twisted把Reactor、Transport、Protocol和Deferred组合成可恢复的异步控制流。

## 最小实现骨架

下面是用于复现实验的独立骨架，不是原书代码复制；生产实现还需补齐平台差异、权限、安全和资源清理。

```python
def on_readable(conn, state):
    chunk = conn.recv(4096)
    if not chunk:
        return close_generation(state.generation)
    state.buffer.extend(chunk)
    while frame := try_decode_frame(state.buffer):
        dispatch_once(frame.request_id, frame.payload)
```

## 常见误区与故障注入

<Callout type="trap" title="状态所有权被绕过">
  把一次recv当成一条完整消息，粘包和分片出现后解析器立刻错位。
  最终成功可能只是重试或覆盖掩盖了错误，必须保存每阶段状态摘要和拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  在Reactor回调中执行阻塞数据库调用，让一个慢请求拖住所有连接。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **Socket**：由地址、端口、协议和内核状态共同构成的通信端点。
- **字节流**：TCP提供的有序字节序列，不携带应用消息边界。
- **数据报**：UDP一次发送对应一个独立报文，但可能丢失、乱序或重复。
- **非阻塞I/O**：调用立即返回，由就绪通知驱动后续收发。
- **Reactor**：把I/O就绪事件分派给注册处理器的事件循环模式。
