## 目录主线与因果关系

### 1. SQL与NoSQL按约束选择

关系事务适合账户和经济账本；键值或文档模型适合明确访问路径。不能用NoSQL名称掩盖缺失的一致性语义。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 2. 内存快不代表安全

Redis持久化和主从复制减少丢失窗口，但复制延迟与故障切换仍可能暴露旧值，写路径必须记录版本。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 3. 备份只有恢复后才算证据

定义RPO、RTO、加密和保留期，定期在隔离环境恢复并核对行数、校验和和业务不变量；SQLite适合单机嵌入场景而非无界并发写。

## 常见误区与故障注入

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份、顺序和容量   | 六阶段顺序完成   | 状态摘要与所有权一致   |

## 小结

- **事实源**：发生冲突时拥有最终裁决权的持久数据副本。
- **SQL**：以关系、模式和事务约束组织数据的查询语言与模型。
- **NoSQL**：为特定访问模式放宽关系模型的一组非关系存储。
- **持久化**：把内存状态写入可在进程或机器故障后恢复的介质。
- **恢复点**：故障后允许回到的最新一致数据时刻。
