## 目录主线与因果关系

### 1. 无状态才能任意负载均衡

认证、查询等服务可外置状态后横向扩容；世界逻辑若保留进程内状态，就必须按玩家或场景稳定路由。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 2. 轮询和集群都要序号

客户端重试、代理重放和节点切换会制造重复。服务端用幂等键和单调版本把至少一次投递收敛为一次副作用。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 3. 定时任务也是分布式写

发奖、赛季结算和清理任务必须获得租约，记录批次与游标；接管节点从检查点继续而不是从头重复。

## 常见误区与故障注入

<Callout type="trap" title="状态所有权被绕过">
  把有状态房间随机分发到任意节点，同一玩家在两个进程形成两份会话。
  最终成功可能只是重试或覆盖掩盖了错误，必须保存每阶段状态摘要和拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  所有节点都执行同一个定时发奖任务，数据库最终出现多份奖励。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **无状态服务**：请求所需事实不依赖当前进程内私有会话的服务。
- **有状态服务**：进程持有跨请求持续且影响结果的会话或世界状态。
- **一致路由**：相同状态键在成员变化时仍尽量映射到稳定所有者。
- **幂等键**：标识同一逻辑请求并阻止重复副作用的唯一键。
- **定时租约**：证明某个节点在有限时间内有权执行计划任务的记录。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
