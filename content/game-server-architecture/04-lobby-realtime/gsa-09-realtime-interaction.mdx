## 目录主线与因果关系

### 1. TCP与UDP按消息语义混用

登录和资产操作需要可靠有序；位置与瞄准可容忍丢失但不能容忍旧包覆盖。协议层为不同消息选择可靠性。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 2. 包头是防线不是装饰

长度、版本、类型、序号和校验先验证再分配内存。压缩前限制解压后大小，混淆不能替代认证加密。

先预测：如果省略这一层，正常样本也许仍能成功，但边界或故障样本会在哪个状态首先偏离？

### 3. 重连是状态迁移

新连接提交票据、最后确认序号和会话代际，服务器只补发缺失的可恢复状态；旧连接随后到达的结果必须被拒绝。

下面是用于复现实验的独立骨架，不是原书代码复制；生产实现还需补齐平台差异、权限、安全和资源清理。

def accept_packet(session, header, body):
    validate_length_and_version(header)
    if header.epoch != session.epoch or header.seq <= session.last_seq:
        return DROP_STALE
    verify_mac(header, body)
    session.last_seq = header.seq
    return dispatch(header.kind, body)

## 常见误区与故障注入

<Callout type="trap" title="状态所有权被绕过">
  重连后旧连接仍能提交结果，新旧代际交错覆盖玩家位置和操作。
  最终成功可能只是重试或覆盖掩盖了错误，必须保存每阶段状态摘要和拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  按客户端包长直接分配或解压，畸形包用极小流量耗尽内存。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份、顺序和容量   | 六阶段顺序完成   | 状态摘要与所有权一致   |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧版本、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **长连接**：跨多个交互持续存在并维护会话上下文的通信通道。
- **序列号**：标识包或输入顺序并用于检测丢失、重复和乱序的单调编号。
- **协议包头**：声明版本、类型、长度、序号和完整性信息的固定边界。
- **重连代际**：每次新会话递增并使旧连接结果失效的版本号。
- **背压**：下游变慢时限制生产速率或队列容量的反馈机制。
