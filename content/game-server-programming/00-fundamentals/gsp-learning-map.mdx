## 直觉引入

把游戏服务器想象成一座城市交通系统。要让它高效运转，你得先修路（TCP Socket 怎么收发数据），再定交通规则（协议怎么设计封包），然后建市政厅（服务器架构怎么组织），接着配红绿灯和调度员（线程模型谁干什么），最后还得有仓库（数据怎么存）、快取柜（缓存怎么加速），以及应对高峰期的多车道分流（负载均衡）和安全监控（反作弊）。本书回答的就是这些「服务器端」的基础问题——不是教你写具体游戏玩法，而是讲清楚服务器各模块为什么这么设计。

## 四阶段递进

<Term def="游戏服务器是为客户端提供权威状态管理、逻辑计算与数据持久化的后端系统，把多玩家连接、战斗、经济、社交等通用能力封装成可复用的服务。">游戏服务器</Term>的基础框架可以拆成四个递进阶段。**网络基础层**包括 TCP Socket 编程和协议设计——它们解决「数据怎么从 A 到 B」和「怎么切分消息」，是所有上层模块的通信基石。**服务器核心层**包括服务器架构、线程模型和数据持久化——它们决定「服务器怎么组织」「谁干什么活」和「数据存哪」。**扩展运维层**包括缓存策略、负载均衡和安全反作弊——它们让服务器「跑得快」「扛得住」「不被黑」。

```cpp
// 游戏服务器的核心脉络：一条消息的旅程
void Server::OnMessage(Connection* conn, Message* msg) {
    // 1. 网络层：IO 线程已收完字节，解出完整包
    msg->Decode();                    // 协议层：反序列化
    // 2. 逻辑层：路由到对应处理函数
    Handler* h = router.Find(msg->id);
    h->Process(conn, msg);           // 业务逻辑：更新状态
    // 3. 数据层：持久化
    if (msg->dirty) db.MarkDirty();   // 标记脏数据，定时落库
    // 4. 回包：IO 线程发送
    conn->Send(msg->reply);
}
```

## 常见误区

<Callout type="trap">
**误区：先学架构再学网络。** 服务器架构建立在网络通信之上——不理解 TCP 的字节流特性，就理解不了为什么需要封包/解包；不理解 epoll 的事件驱动，就理解不了为什么 IO 线程要和逻辑线程分离。地基没打牢，学架构只会停留在「画框图」层面，遇到粘包、半包、连接风暴无从下手。
</Callout>

<Exercises>
**问题 1**：全书四阶段是什么？为什么是这个顺序？

<Answer>
网络基础层（Socket/协议）→ 服务器核心层（架构/线程/数据）→ 扩展运维层（缓存/负载/安全）→ 总复习。顺序由依赖关系决定：上层依赖下层。没有网络通信就没有服务器；没有服务器组织就没有线程分工；没有数据持久化就没有缓存需求；没有缓存和架构就没有负载均衡和安全。先有「能通信」，再有「能组织」，然后才能「扛得住」和「不被黑」。
</Answer>

**问题 2**：为什么说「TCP Socket 是服务器网络的地基」？

<Answer>
游戏服务器的所有通信——登录、战斗、聊天、交易——最终都通过 TCP 连接收发字节流。不理解 TCP 的三次握手就无法管理连接生命周期；不理解粘包就无法正确切分消息；不理解 epoll 就无法高效处理数千并发连接。Socket 编程是「数据怎么从客户端到服务器」的底层答案，跳过它学上层架构如同空中楼阁。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="游戏服务器">为客户端提供权威状态管理、逻辑计算与数据持久化的后端系统。所有玩家可见的游戏状态都由服务器计算和广播，客户端只负责输入和渲染。</GlossaryItem>
<GlossaryItem term="消息旅程">一条网络消息从客户端发出到服务器处理完毕再回包的完整路径：Socket 收发 → 协议解包 → 逻辑路由 → 数据持久化 → 回包下发。全书以这条主线串联各模块。</GlossaryItem>
<GlossaryItem term="服务端权威">所有关键游戏逻辑（位置、伤害、经济）由服务器计算，客户端的输入只是「请求」而非「指令」。这是反作弊的基石。</GlossaryItem>
</Glossary>
