## 从第1章的核心问题开始

网络程序的第一条纪律是区分传输事实与业务消息。TCP 只提供有序字节流，不提供消息边界；UDP 保留数据报边界，却不保证到达和顺序。服务器必须先定义权威职责、编码规则和连接生命周期，再选择传输并实现组帧。

### Socket 生命周期

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

### 表示必须统一

IP 文本与二进制地址、主机字节序与网络字节序、定长头与变长体都要有单一转换边界，不能把本机结构体直接发送到网络。

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

## 可复现实验

写一个最小回显服务器和测试客户端。先预测一次 send 是否必然对应一次 recv，再分别注入 1 字节分片、两个帧合并、客户端中途断开和 UDP 序号跳变；记录解析器缓冲区、期望长度和第一处拒绝原因。

### 最小实现

```cpp
struct FrameHeader { std::uint32_t bodyBytes; std::uint16_t type; };

bool decodeHeader(std::span<const std::byte> raw, FrameHeader& out) {
  if (raw.size() < 6) return false;
  out.bodyBytes = readNetworkU32(raw.subspan(0, 4));
  out.type = readNetworkU16(raw.subspan(4, 2));
  return out.bodyBytes <= 64 * 1024;
}
```

### 边界处理

```cpp
bool readFrame(Socket& socket, Buffer& pending, Message& out) {
  while (!pending.hasCompleteFrame()) {
    const auto n = socket.receive(pending.writeSpan());
    if (n == 0) return false;
    pending.commit(n);
  }
  return pending.popFrame(out);
}
```

### 证据契约

```cpp
struct Datagram { std::uint32_t session; std::uint32_t sequence; Bytes body; };

Decision accept(const Datagram& packet, ReplayWindow& window) {
  if (packet.body.size() > 1200) return Decision::RejectOversize;
  if (!window.markIfNew(packet.sequence)) return Decision::RejectReplay;
  return Decision::Dispatch;
}
```

实现代码只是实验的一部分。每次运行还要记录构建版本、配置摘要、样本类型、输入规模、首偏离节点、恢复动作和最终决策。若无法用相同输入重放，结论不能进入交付清单。

## 两个必须主动制造的失败

<Callout type="trap" title="机制边界被绕过">
  把 TCP 当作消息队列，假设一次发送等于一次接收；压力下出现半包和粘包后，解析器把下一条消息的字节当成本条正文。 保存故障运行的输入、首偏离节点和拒绝原因，再用同一输入验证修复。
</Callout>

<Callout type="trap" title="局部成功掩盖系统退化">
  直接发送含指针、填充和主机字节序的 C++ 结构体；同一程序跨编译器或跨平台后字段错位。 即使最终画面或平均吞吐看起来正常，只要关键不变量没有证据，阶段门仍必须拒绝。
</Callout>

## 练习

<Exercises>

**问题 1** 为什么 TCP 接收循环必须同时处理半包和多包？

<Answer>
因为 TCP 只保证字节顺序，不保留发送调用边界。一次接收可能不足一帧，也可能包含多帧；解析器必须保留未完成字节并循环弹出所有完整帧。
</Answer>

**问题 2** IP 地址转换和字节转换应放在哪个边界？

<Answer>
放在网络适配层。业务层只接触规范化的端点和值对象，避免地址文本、平台字节序和协议字段在各处理器中重复转换。
</Answer>

**问题 3** 怎样证明 UDP 路径不会把重放包执行两次？

<Answer>
固定会话和序号，发送正常、重复、乱序与超窗数据报；检查重放窗口只允许首次有效序号进入业务处理，并记录每次拒绝原因。
</Answer>

</Exercises>
