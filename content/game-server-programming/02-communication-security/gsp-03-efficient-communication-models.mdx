## 从第3章的核心问题开始

高效 I/O 的关键不是某个 API 名称，而是把等待从每连接一线程改为事件或完成通知，并明确每个操作的生命周期。IOCP 告诉程序某次异步操作已经完成；epoll 告诉程序某个文件描述符当前就绪。两者都要求应用正确处理部分读写、取消、关闭和陈旧事件。

## 核心概念与因果关系

### 阻塞与非阻塞

阻塞调用把等待交给当前线程；非阻塞调用立即返回状态，由事件循环决定何时重试。两者都可能写出正确服务器，但资源模型和调度成本不同。

### 异步与完成

```cpp
void onCompletion(const Completion& c) {
  auto connection = registry.find(c.connectionId);
  if (!connection || connection->generation() != c.generation) return;
  if (c.error) return connection->beginClose(c.error);
  c.kind == Read ? connection->onBytes(c.bytes)
                 : connection->onSent(c.bytes);
}
```

本页签发不变量是：**一个异步操作只完成一次；连接关闭后同代际事件全部排空；陈旧完成不能访问复用后的连接对象；发送队列超过预算时会暂停读取或拒绝请求。** 任何演示、截图或单次成功都不能替代它。
