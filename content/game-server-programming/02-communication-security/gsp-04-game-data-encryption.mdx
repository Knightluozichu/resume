## 从第4章的核心问题开始

加密不是把字节变得不可读，而是针对明确攻击者保护机密性、完整性与身份。算法可以公开，安全性必须依赖受控密钥；网络游戏还要处理重放、降级、密钥泄露和客户端不可信。2007 年常见算法的历史背景应保留，但新实现必须采用经过审查的认证协议。

## 核心概念与因果关系

<Term def="对资产、攻击者能力、攻击路径和后果的结构化描述。">威胁模型</Term>、<Term def="同时提供机密性和完整性校验的标准加密方式。">认证加密</Term>、<Term def="限定在一次会话或短周期内使用的临时密钥。">会话密钥</Term>、<Term def="在给定密钥和算法约束下不得错误复用的加密输入。">随机数</Term>、<Term def="记录已接受序号并拒绝重复或过旧消息的状态。">重放窗口</Term>。这些概念不能只停留在定义上：每个概念都要落到输入、内部状态、输出和失败证据。读者应能指出哪个模块拥有状态、哪个边界拒绝非法输入、哪个指标证明系统没有把成本推给下游。

### 先写威胁模型

发送者和接收者之间可能存在窃听、篡改、伪造和重放。每项资产、攻击者能力和失败后果都要写清，才能选择保护措施。

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

### 算法与密钥分离

算法不应靠保密实现；密钥要有生成、分发、存储、轮换和吊销流程。把固定密钥编译进客户端等于向攻击者交付密钥。

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

### 机密性不等于完整性

只加密不认证仍可能被篡改。认证加密同时输出密文和认证标签，接收端必须先验证标签再解析正文。

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

### 随机数和重放

同一密钥下随机数必须满足所选算法的唯一性要求；协议还要绑定会话、方向和序号，并用窗口拒绝重复消息。

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

### 历史算法要标注边界

DES、裸 RSA、自制异或和无密钥散列不能作为当前网络协议方案。现代页面解释迁移理由，不把今天的推荐倒写成原书原话。

## 可复现实验

固定一条登录消息，先预测加密后任意改动是否一定能被发现。分别翻转密文字节、标签字节、序号、会话标识和协议版本，再重放原包；保存验证顺序和拒绝原因，确认任何失败都不会进入业务解析。

### 最小实现

```ts
type SecureEnvelope = {
  version: number;
  sessionId: bigint;
  sequence: bigint;
  ciphertext: Uint8Array;
  tag: Uint8Array;
};
```

### 边界处理

```ts
function receive(envelope: SecureEnvelope, session: Session) {
  session.replayWindow.assertFresh(envelope.sequence);
  const plain = session.aead.open({
    nonce: makeNonce(envelope.sequence),
    aad: encodeHeader(envelope),
    ciphertext: envelope.ciphertext,
    tag: envelope.tag,
  });
  return parseMessage(plain);
}
```

### 证据契约

```ts
security_event,session,sequence,result,reason
packet_verify,42,100,accepted,-
packet_verify,42,100,rejected,replay
packet_verify,42,101,rejected,tag_mismatch
```

实现代码只是实验的一部分。每次运行还要记录构建版本、配置摘要、样本类型、输入规模、首偏离节点、恢复动作和最终决策。若无法用相同输入重放，结论不能进入交付清单。

## 两个必须主动制造的失败

<Callout type="trap" title="机制边界被绕过">
  自制异或或固定替换表，只让抓包内容看起来混乱，却没有完整性、密钥管理和抗分析能力。 保存故障运行的输入、首偏离节点和拒绝原因，再用同一输入验证修复。
</Callout>

<Callout type="trap" title="局部成功掩盖系统退化">
  先解析密文中的长度和类型再校验认证标签，攻击者可利用解析器差异消耗资源或触发漏洞。 即使最终画面或平均吞吐看起来正常，只要关键不变量没有证据，阶段门仍必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 输入 | 合法且固定 | 容量、顺序或时序临界值 | 畸形、重复或中断 | 分类清晰且可重放 |
| 状态 | 按六阶段推进 | 达到预算但不越界 | 在首偏离节点停止 | 无隐式跨层写入 |
| 输出 | 结果和证据一致 | 退化可解释 | 拒绝、补偿或回滚 | 不变量恢复 |
| 交接 | 他人按记录复验 | 干净环境复验 | 删除隐含依赖 | 结论仍成立 |

本页签发不变量是：**未经认证的数据永不进入反序列化和业务层；同一会话的序号不能被重复接受；密钥不会出现在日志、客户端常量或崩溃报告中。** 任何演示、截图或单次成功都不能替代它。

## 练习

<Exercises>

**问题 1** 为什么算法公开仍然可以安全？

<Answer>
现代密码学假设算法和协议公开，安全性依赖密钥和经过分析的数学困难。靠隐藏算法无法接受同行审查，一旦实现泄露便整体失效。
</Answer>

**问题 2** 只使用加密为何不能防篡改？

<Answer>
许多加密模式只隐藏内容，不证明内容未被改变。认证标签把密文和上下文绑定到密钥，验证失败时必须在解析前拒绝。
</Answer>

**问题 3** 客户端不可信对密钥设计有什么影响？

<Answer>
长期服务器秘密不能交给客户端。客户端持有的会话材料应短期、可撤销、权限受限，关键规则仍由服务器验证。
</Answer>

</Exercises>
