## 直觉引入

如果你开了一家餐厅，一开始客人少，一个厨师就够了（单服）。客人多了，一个厨房忙不过来，你开了分店——每家分店有自己的厨房和仓库，互不干扰（分服）。但有时候客人想跨店点菜（跨服副本），你就需要一个中央调度中心（跨服中心）。而所有客人进门时都先经过大堂经理（网关），由经理安排座位和核实会员身份。游戏服务器的架构演进和这个过程几乎一样。

## 分服模型

<Term def="分服（Sharding）是将玩家按区服分配到独立逻辑服务器的架构模式，每个区服拥有独立的数据和进程，实现负载分散和数据隔离。">分服</Term>是游戏服务器最基础的架构模式。每个区服是一个独立的逻辑进程，拥有自己的玩家数据、场景状态和数据库实例。玩家登录时选择区服，后续所有请求都路由到该区服的逻辑服务器。分服的核心优势是**隔离性**——一个区服的故障（崩溃、回档、卡顿）不会影响其他区服，且每个区服的数据互不干扰，无需分布式事务。

```cpp
// 简单的分服路由
Server* routeToServer(int playerId) {
    int serverId = playerServerMap[playerId];  // 玩家所属区服
    return servers[serverId];                   // 返回对应逻辑服
}
// 玩家一旦选择区服，所有操作都在该区服内完成
// 区服间不共享内存，通过跨服中心通信
```

## 网关层

当玩家数量增长，单台逻辑服承受不了所有连接的收发压力。**网关层**（Gateway）作为客户端与逻辑服之间的中间层，负责连接管理、鉴权、加密和路由转发。客户端不直连逻辑服，而是连到网关；网关验证身份后，将消息转发到对应的逻辑服。

网关层的价值在于：**连接收敛**——数千连接由多个网关分摊，逻辑服只处理网关转发的内部消息；**安全屏障**——逻辑服不暴露公网，所有外部请求先过网关的鉴权；**协议转换**——网关处理加密/压缩，逻辑服只处理明文消息；**无缝迁移**——逻辑服重启或扩容时，网关暂存消息，玩家无感知。

<Callout type="trap">
**误区：让逻辑服直接处理客户端连接。** 逻辑服同时处理网络 IO 和游戏逻辑会导致：连接管理消耗逻辑线程时间、安全风险暴露逻辑服地址、扩容时连接断开玩家掉线。网关层把网络 IO 从逻辑服中剥离出来，让逻辑服专注于业务计算，这是分布式游戏服务器的标准设计。
</Callout>

## 跨服架构

分服解决了隔离问题，但有些玩法天然需要跨服：跨服副本、全服排行榜、公会战、匹配系统。这些功能需要多个区服的玩家在同一个逻辑空间交互。

跨服的实现方案是引入**跨服中心**：各分服通过内部协议将跨服请求发送到跨服服务器，跨服服务器维护一个独立的逻辑空间（如跨服副本的场景状态），处理完毕后将结果回传给各分服。跨服中心不直接连客户端——所有玩家消息仍通过各自分服的网关转发。

```cpp
// 跨服副本的简化流程
void onEnterCrossDungeon(int playerId, int dungeonId) {
    // 1. 本服发送跨服请求到跨服中心
    CrossDungeonReq req;
    req.playerId = playerId;
    req.dungeonId = dungeonId;
    req.fromServer = myServerId;
    crossServer->Send(req);

    // 2. 跨服中心创建副本，返回副本地址
    // 3. 本服通知客户端切换到跨服网关
    // 4. 客户端连到跨服网关，进入跨服副本
}
```

跨服架构的挑战在于**数据同步**——玩家的装备、属性、状态需要在分服和跨服中心之间同步。通常的做法是：进入跨服时，分服将玩家快照发送给跨服中心；跨服结束时，跨服中心将变更结果回传给分服，分服更新数据库。

<Exercises>
**问题 1**：为什么要分服？分服的核心优势是什么？

<Answer>
分服的核心动机是负载分散和数据隔离。单台服务器的 CPU、内存、网络带宽有上限，无法承载无限玩家。分服将玩家分散到多个独立进程，每个进程承载一部分玩家，实现水平扩展。核心优势是隔离性：一个区服的崩溃、卡顿、回档不影响其他区服；区服间数据独立，无需分布式事务，大大简化了实现。代价是跨服交互需要额外的同步机制。
</Answer>

**问题 2**：网关层解决了什么问题？如果没有网关层会怎样？

<Answer>
网关层解决了连接收敛、安全屏障、协议转换和无缝迁移四个问题。没有网关层：逻辑服直接处理客户端连接，网络 IO 消耗逻辑线程时间；逻辑服暴露公网 IP，容易被 DDoS 攻击；扩容或重启逻辑服时所有客户端连接断开，玩家掉线；加密/压缩逻辑混在业务代码中，耦合严重。网关层把网络 IO 从逻辑服剥离，让逻辑服专注业务计算，是分布式游戏服务器的标准设计。
</Answer>
</Exercises>

<GlossaryItem term="跨服中心">协调多个区服间交互的独立服务器。处理跨服副本、全服排行榜、公会战等需要多区服玩家共同参与的玩法。</GlossaryItem>
<GlossaryItem term="连接收敛">多个网关分摊数千客户端连接的 IO 压力，逻辑服只处理网关转发的内部消息，降低逻辑服的网络负载。</GlossaryItem>
