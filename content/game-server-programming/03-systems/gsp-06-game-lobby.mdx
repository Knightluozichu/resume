## 从第6章的核心问题开始

大厅位于账号服务、游戏房间与客户端之间，它不是一个页面列表，而是玩家从认证到进入对局的状态协调器。可靠实现必须让会话身份、房间版本、席位预留和进入游戏形成可回放状态机，并在超时、重复点击和房间崩溃时收敛。

</Callout>

## 可复现实验

让同一玩家快速双击匹配，并在席位预留后断开网络。先预测大厅会产生几个席位，再延迟游戏服确认、重放旧令牌并模拟房间进程退出；检查玩家最终只能处于空闲、已预留或对局中一个状态。

### 最小实现

```ts
type LobbyState =
  | { kind: "idle"; generation: number }
  | { kind: "reserved"; generation: number; roomId: string; expiresAt: number }
  | { kind: "in_game"; generation: number; roomId: string };
```

### 边界处理

```ts
function disconnect(player: PlayerSession, generation: number) {
  if (player.generation !== generation) return;
  player.connection = null;
  player.reconnectDeadline = now() + 30_000;
}
```

### 证据契约

```ts
function consumeJoinToken(token: JoinToken, room: Room) {
  token.verifySignature();
  token.assertNotExpired();
  if (!room.consumeOnce(token.id, token.seat)) return "duplicate";
  return room.attach(token.playerId, token.seat);
}
```

实现代码只是实验的一部分。每次运行还要记录构建版本、配置摘要、样本类型、输入规模、首偏离节点、恢复动作和最终决策。若无法用相同输入重放，结论不能进入交付清单。

## 两个必须主动制造的失败

<Callout type="trap" title="机制边界被绕过">
  匹配成功后直接把房间地址返回客户端，没有预留和确认；两个并发请求占用两个席位并进入不同房间。 保存故障运行的输入、首偏离节点和拒绝原因，再用同一输入验证修复。
</Callout>

<Callout type="trap" title="局部成功掩盖系统退化">
  断线事件只按 playerId 清理在线状态；旧连接晚到的断开通知把刚重连的新会话踢下线。 即使最终画面或平均吞吐看起来正常，只要关键不变量没有证据，阶段门仍必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 输入 | 合法且固定 | 容量、顺序或时序临界值 | 畸形、重复或中断 | 分类清晰且可重放 |
| 状态 | 按六阶段推进 | 达到预算但不越界 | 在首偏离节点停止 | 无隐式跨层写入 |
| 输出 | 结果和证据一致 | 退化可解释 | 拒绝、补偿或回滚 | 不变量恢复 |
| 交接 | 他人按记录复验 | 干净环境复验 | 删除隐含依赖 | 结论仍成立 |

本页签发不变量是：**同一玩家同一时刻最多拥有一个有效大厅会话和一个对局归属；一次性令牌只被消费一次；超时席位必然释放；旧代际断开不会清除新会话。** 任何演示、截图或单次成功都不能替代它。

## 练习

<Exercises>

**问题 1** 为什么房间列表不能作为席位真相？

<Answer>
列表是延迟投影，显示有空位不代表提交时仍有空位。席位必须由房间或权威协调器以原子预留决定。
</Answer>

**问题 2** 会话代际解决什么竞态？

<Answer>
解决旧连接事件晚到的问题。任何心跳、断开和消息都带代际，只有当前代际可以修改玩家在线状态。
</Answer>

**问题 3** 怎样验证重复匹配不会创建两个对局归属？

<Answer>
用同一幂等键并发发送两次，延迟其中一次响应；检查协调存储只有一个预留，两个响应引用同一结果，超时后状态一致释放。
</Answer>

</Exercises>
