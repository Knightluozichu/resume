## 从总复习的核心问题开始

全书的最终产物不是八个孤立示例，而是一条可追踪的玩家旅程：客户端连接并组帧，线程和 I/O 模型调度消息，加密边界拒绝不可信输入，数据库保存权威结果，大厅协调入局，GM 控制运营变更，更新系统交付兼容客户端。任何局部成功都不能替代端到端不变量。

</Callout>

## 核心概念与因果关系

<Term def="用同一运行标识串联跨模块输入、状态和结果的记录。">端到端轨迹</Term>、<Term def="有控制地制造单一失败以验证检测和恢复路径。">故障注入</Term>、<Term def="同一业务请求重复执行时返回的稳定单一结果。">幂等结果</Term>、<Term def="证明拒绝、补偿、重连或回滚已经恢复不变量的记录。">恢复证据</Term>、<Term def="所有功能、故障和来源门禁同时通过后的正式结论。">交付签发</Term>。这些概念不能只停留在定义上：每个概念都要落到输入、内部状态、输出和失败证据。读者应能指出哪个模块拥有状态、哪个边界拒绝非法输入、哪个指标证明系统没有把成本推给下游。

### 连接链

检查地址和字节序、TCP 组帧、UDP 序号、连接代际与关闭路径，证明恶意长度和陈旧事件无法越界。

验证时固定软件版本、配置和输入规模，先保存正常轨迹，再只改变一个边界条件。最终结果相同并不代表过程正确；必须比较阶段状态、队列水位、错误分类和恢复动作。

### 调度链

### 信任链

## 六阶段证据链

<Stepper>
  <Step title="1. 锁定同一测试版本 → 回放连接与调度轨迹">
    固定版本、输入和职责边界，保存正常样本。任何隐式默认值都写入证据记录。
    </Step>
  <Step title="2. 注入篡改重放竞态 → 验证事务大厅幂等">
    加入容量、顺序、超时和并发边界，记录第一个偏离正常轨迹的状态，而不是只看最终页面。
    </Step>
  <Step title="3. 演练 GM 补偿与更新回滚 → 归档指标日志并签发">
    主动制造故障，确认门禁会拒绝；修复后用同一输入复测，并归档日志、状态快照和签发结论。
    </Step>
</Stepper>

## 可复现实验

运行一条从登录到入房再到补发和更新的脚本。先预测故障最早会在哪一层暴露，然后依次注入 TCP 半包、旧连接完成、认证标签错误、重复购买、重复匹配、GM 响应丢失和更新断电；每次只允许一个首偏离节点。

### 最小实现

```ts
type EndToEndTrace = {
  runId: string;
  connectionGeneration: number;
  sessionId: string;
  requestId: string;
  roomReservationId: string;
  releaseVersion: string;
};
```

### 边界处理

```ts
const gates = [
  verifyFrameBoundary, verifyIoGeneration, verifyAuthentication,
  verifyIdempotentCommit, verifyLobbyOwnership, verifyGmAudit,
  verifyReleaseRollback,
];

for (const gate of gates) await gate(trace);
```

### 证据契约

```ts
gate,sample,first_deviation,recovery,decision
network,boundary,frame_buffer,continue,pass
crypto,failure,tag_verify,reject,pass
database,failure,idempotency_lookup,replay_result,pass
update,failure,health_check,rollback,pass
```

实现代码只是实验的一部分。每次运行还要记录构建版本、配置摘要、样本类型、输入规模、首偏离节点、恢复动作和最终决策。若无法用相同输入重放，结论不能进入交付清单。

## 两个必须主动制造的失败

<Callout type="trap" title="机制边界被绕过">
  八章分别演示成功，但没有统一会话 ID、请求 ID 和运行编号；跨层故障发生时无法证明哪个状态先偏离。 保存故障运行的输入、首偏离节点和拒绝原因，再用同一输入验证修复。
</Callout>

<Callout type="trap" title="局部成功掩盖系统退化">
  只验证最终页面和平均吞吐，没有重放、冲突、关闭、恢复和回滚演练；系统在理想路径上通过却不能交付。 即使最终画面或平均吞吐看起来正常，只要关键不变量没有证据，阶段门仍必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本 | 边界样本 | 失败样本 | 通过条件 |
| --- | --- | --- | --- | --- |
| 输入 | 合法且固定 | 容量、顺序或时序临界值 | 畸形、重复或中断 | 分类清晰且可重放 |
| 状态 | 按六阶段推进 | 达到预算但不越界 | 在首偏离节点停止 | 无隐式跨层写入 |
| 输出 | 结果和证据一致 | 退化可解释 | 拒绝、补偿或回滚 | 不变量恢复 |
| 交接 | 他人按记录复验 | 干净环境复验 | 删除隐含依赖 | 结论仍成立 |

本页签发不变量是：**所有官方章节都有可回放正常、边界和失败样本；每个故障在越过所属边界前被拒绝或补偿；日志、指标、数据库和版本清单使用同一运行编号。** 任何演示、截图或单次成功都不能替代它。

## 练习

<Exercises>

**问题 1** 为什么全书测试要使用统一运行编号？

<Answer>
统一编号让网络、线程、加密、数据库、大厅、GM 和更新证据可以按时间和因果对齐，避免把不同运行的成功片段拼成错误结论。
</Answer>

**问题 2** 故障注入为什么一次只改变一个变量？

<Answer>
这样才能定位首偏离节点并把恢复结果归因于修复；同时改变多个故障会让证据链失去可解释性。
</Answer>

**问题 3** 何时可以签发这本书的重建？

<Answer>
10 页全部编译和审计通过，8 个正式章节与 57 个公开目录条目覆盖完整，60 道题唯一，侧栏顺序正确，所有正常边界失败实验和来源边界都可复核。
</Answer>

</Exercises>
