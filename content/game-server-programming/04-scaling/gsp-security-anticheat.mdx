## 直觉引入

游戏安全就像银行安保。第一层是运钞车（传输加密）——钱在路上不能被抢。第二层是柜台验身（权限鉴权）——确认你是你、你有权限操作。第三层是风控审计（逻辑校验）——你转了一笔异常金额，系统自动拦截。但最重要的是：客户说了不算，银行系统说了算（服务端权威）——你说你账上有 100 万没用，银行数据库里有多少才是多少。游戏服务器就是这个「银行」，客户端就是客户的嘴——永远不能信。

## 核心原则：服务端权威

<Term def="服务端权威（Server-Authoritative）是所有关键游戏逻辑由服务器计算和判定的架构原则，客户端的输入只是「请求」而非「指令」，服务器验证后才执行。">服务端权威</Term>是游戏安全的基石。客户端只负责输入（按键、触屏）和渲染（画画面），所有关键逻辑——位置、伤害、掉落、经济——都由服务器计算。客户端发给服务器的不是「我打了 1000 伤害」，而是「我对目标 B 使用了技能 A」；服务器根据自身状态计算伤害、扣血、掉落，再把结果广播给所有客户端。

为什么不能信任客户端？因为客户端运行在玩家的设备上，玩家可以修改客户端代码、篡改内存数据、拦截和伪造网络包。如果客户端说「我打了 1000 伤害」服务器就信，玩家可以改成「我打了 99999 伤害」。如果客户端说「我在 (100, 200)」服务器就信，玩家可以改成「我在 Boss 旁边」瞬间移动。服务端权威让这些篡改无效——客户端改的是自己的请求，服务器按自己的逻辑计算。

## 传输安全层

即使有了服务端权威，传输过程仍需加密——否则中间人可以窃听通信内容（获取其他玩家位置、副本信息）或篡改数据（修改请求参数）。

**协议加密**：用 AES 对称加密消息体，密钥在登录时通过 RSA 非对称加密交换。每次连接使用不同的会话密钥，防止密钥泄露后被批量解密。

**防重放攻击**：攻击者录下一条合法消息（如「使用药水」），稍后重放。防护方案：每条消息附带时间戳和递增序列号，服务器校验时间戳在合理窗口内且序列号大于上次——重复或过期的消息直接丢弃。

**数据完整性**：用 HMAC（哈希消息认证码）对整个包签名。服务器收到后重新计算 HMAC 并比对——任何字节被篡改都会导致签名不匹配，直接丢弃。

## 权限安全层

**登录鉴权**：客户端登录时用账号密码换取 Token，后续每次请求都带 Token。Token 有过期时间，过期后需重新登录。设备指纹绑定防止 Token 被盗后在其他设备使用。

**操作频率限制**：对高频操作（如聊天、交易、创建房间）设频率上限。超过频率的请求直接丢弃或延迟处理，防止恶意刷屏或自动化脚本。

**GM 指令白名单**：管理指令（封号、发奖励、刷怪）只能从内网管理后台发起，客户端永远不能发送 GM 指令的消息ID。

## 逻辑反作弊层

即使传输加密、权限正确，客户端仍可能发送「合法但异常」的请求——如移动速度超过上限、伤害数值不合理。逻辑反作弊在服务器业务逻辑中加入校验：

**移动校验**：服务器记录玩家上次位置和时间，收到移动请求时计算速度。如果速度超过角色上限（如 10 m/s），判定为加速外挂，拒绝移动并标记。

**战斗校验**：客户端发「使用技能A攻击目标B」，服务器根据自身数据计算伤害（技能基础伤害 + 属性加成 - 目标防御），而不是信任客户端发的伤害值。同时校验 CD 是否冷却完毕、蓝量是否足够、目标是否在攻击范围内。

**经济校验**：所有交易由服务器记录审计日志。异常金币波动（如短时间内金币暴增）触发风控告警，人工或自动核查。

```cpp
// 移动校验示例
bool validateMove(int playerId, Vec3 newPos, float timestamp) {
    Player* p = getPlayer(playerId);
    Vec3 oldPos = p->pos;
    float dt = timestamp - p->lastMoveTime;
    float dist = distance(oldPos, newPos);
    float speed = dist / dt;
    float maxSpeed = p->getMoveSpeed() * 1.5f;  // 允许 50% 误差

    if (speed > maxSpeed) {
        // 加速外挂检测
        p->cheatScore += 10;
        if (p->cheatScore > 100) banPlayer(playerId);
        return false;  // 拒绝移动
    }
    p->pos = newPos;
    p->lastMoveTime = timestamp;
    return true;
}
```

<Callout type="trap">
**误区：加密了就不用校验了。** 加密防止的是窃听和篡改——第三方无法读取或修改传输中的数据。但客户端自己发的数据是加密前的明文——玩家修改客户端代码后发出的「合法加密包」服务器能解密，但内容可能是作弊的（如速度 999）。加密是「防外人」，逻辑校验是「防玩家」，两者缺一不可。服务端权威把两者串联：加密保证传输安全，权威保证即使客户端作弊也无法影响游戏结果。
</Callout>

<Exercises>
**问题 1**：什么是服务端权威？为什么它是反作弊的基石？

<Answer>
服务端权威是所有关键游戏逻辑（位置、伤害、经济）由服务器计算和判定的架构原则。客户端发的是「请求」（如「我对B用了技能A」）而非「指令」（如「我打了B 1000伤害」），服务器根据自身状态计算结果。它是反作弊基石的原因：客户端运行在玩家设备上，玩家可以修改代码、篡改内存、伪造网络包。如果服务器信任客户端数据（如客户端说伤害999），作弊就无法防范。服务端权威让客户端的篡改无效——改的只是请求，结果由服务器算。
</Answer>

**问题 2**：加密和逻辑校验分别防什么？为什么都需要？

<Answer>
加密防的是第三方窃听和篡改——中间人无法读取或修改传输中的数据。逻辑校验防的是玩家通过修改客户端发送「合法但异常」的请求——如移动速度999、伤害999。加密解决不了玩家作弊：玩家修改客户端代码后发出的包是合法加密的，服务器能解密但内容是作弊值。逻辑校验在服务器业务逻辑中校验请求的合理性（速度上限、伤害公式）。加密是「防外人」，校验是「防玩家」，两者缺一不可。
</Answer>
