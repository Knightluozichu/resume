## 直觉引入

把垃圾回收想象成「一座城市的环卫系统」。城市每天产生大量垃圾（不可达对象），环卫车需要定期清理。最早的清扫方式是「逐门逐户检查谁家有没有垃圾」（标记-清除——遍历所有对象标记存活，再清除其余）；后来发现把还活着的货物搬到街的另一头更高效（复制式回收——From/To半区复制）；但搬家太费空间，于是改为「原地整理把存货挤到一边」（标记-压缩——滑动消除碎片）；再后来发现「新城区垃圾多、老城区垃圾少」（分代回收——弱分代假说，年轻代频繁回收）；为了不停城运作又发明了「边营业边清扫」（并发回收——与mutator同时运行）；对时间要求极苛刻的场景则用「定时定量清扫」（实时GC——Metronome调度保证截止时间）；最终演进出G1、ZGC、Shenandoah等现代实现。


## 递进逻辑：为什么是这个顺序

```text
算法维度（基础回收）         性能维度（分代与并发）
┌──────────────────────┐      ┌──────────────────────┐
│ 标记清除 → 复制 → 压缩  │ ───→ │ 分代 → 并发 → 实时     │
│   理解 GC 怎么找垃圾     │      │   理解 GC 怎么更快更稳  │
└──────────────────────┘      └──────────────────────┘
         工程维度（现代实现）
         ┌──────────────────────┐
         │ G1/ZGC/Shenandoah 对比 │
         │   理解算法怎么落地      │
         └──────────────────────┘
```

<Callout type="insight">
**核心理念**：《垃圾回收算法手册》从三个维度理解GC——算法维度（标记/复制/压缩怎么回收）、性能维度（分代/并发/实时怎么降低停顿和开销）、工程维度（G1/ZGC/Shenandoah怎么实现落地）。三者交叉构成完整的GC技术闭环：不懂基础算法就无法理解分代策略；不懂分代策略就无法理解并发回收的优化方向；不懂并发/实时就无法理解现代GC的设计动机。
</Callout>

## 一次 Full GC 频繁触发事故串联全书

用一次线上Full GC频繁触发、应用卡顿数秒的事故串联三大维度：

```text
① GC概述      理解STW与性能指标，判断是吞吐问题还是延迟问题
② 标记-清除   理解碎片如何导致分配失败→触发Full GC
③ 复制式回收  理解为什么年轻代用复制式（无碎片+快速）
④ 标记-压缩   理解老年代碎片压缩的代价（移动对象+更新引用）
⑤ 分代回收    检查分代比例是否不当导致对象过早晋升
⑥ 并发回收    分析是否CMS并发标记跟不上导致Concurrent Mode Failure
⑦ 实时GC      对比实时GC如何将停顿控制在预算内
⑧ 现代GC对比  评估是否应迁移到G1或ZGC解决长停顿问题
```

<Callout type="trap">
**误区**：遇到GC性能问题就加大堆或换收集器。调参大法能暂时缓解但不理解根因，问题会反复出现。真正懂GC的人能从算法选择、分代假说、并发安全三个维度解释根因，给出针对性修复方案。
</Callout>

<Exercises>
**问题 1**：《垃圾回收算法手册》全书的知识体系结构和递进逻辑是什么？

<Answer>
全书分为十个章节（含学习地图和全书复习），覆盖GC的三大知识维度：①基础算法——标记-清除（三色标记/自由链表/碎片问题/位图标记）、复制式回收（Cheney算法/From-To半区/无碎片但空间减半）、标记-压缩（滑动压缩/Two-Finger双指法/表格法/转发指针）；②分代策略——弱分代假说（绝大多数对象朝生夕死）、写屏障与卡表（解决跨代引用追踪）、remembered set（Minor GC只扫描年轻代+脏卡）；③并发与实时——并发回收（三色不变式/SATB快照/INC增量更新/漏标与浮动垃圾）、实时GC（工作量模型/Slack调度/Metronome时间片/截止时间保证）；④现代实现——G1（Region分代/SATB+卡表/Mixed GC）、ZGC（染色指针/读屏障/亚毫秒停顿）、Shenandoah（Brooks转发指针/并发疏散）、CMS（已废弃）。递进逻辑：从算法维度（怎么回收）到性能维度（怎么更快更稳）到工程维度（怎么落地），三个维度交叉构成完整闭环。
</Answer>

**问题 2**：标记-清除、复制式回收、标记-压缩三种基础算法各自的核心权衡是什么？

<Answer>
三种算法的核心权衡：①标记-清除——优点是原地回收不移动对象（适合不关心碎片的场景），缺点是产生外部碎片（空闲块不连续，大对象分配失败）和清除阶段需遍历整个堆；②复制式回收——优点是无碎片（存活对象紧凑复制到To区）且分配极快（指针碰撞），缺点是可用空间减半（需要From/To两个半区）且复制成本与存活对象数量成正比（适合死亡率高的年轻代）；③标记-压缩——优点是无碎片且不浪费空间（原地滑动），缺点是多趟遍历开销大（计算新地址→更新引用→移动对象）且不保留对象分配顺序（Two-Finger）或需额外空间存偏移表（表格法）。选择依据：年轻代死亡率高→复制式；老年代不能浪费空间→标记-压缩或标记-清除；嵌入式受限环境→标记-清除（低开销无移动）。
</Answer>

**问题 3**：用一次线上Full GC频繁触发的问题，串联全书的知识体系。

<Answer>
主线：一次线上Full GC频繁触发、应用卡顿数秒的诊断与修复。①基础算法——理解标记-清除的碎片问题如何导致大对象分配失败触发Full GC，复制式回收为何不适合老年代（存活率高→复制成本大）；②分代策略——检查Survivor区是否过小导致对象过早晋升老年代，老年代碎片是否因长期标记-清除积累，写屏障开销是否影响吞吐；③并发回收——分析是否CMS的Concurrent Mode Failure（并发标记跟不上分配速度）退化为Full GC，SATB/INC策略的开销与正确性权衡；④现代GC——评估迁移到G1（Region+Mixed GC减少碎片）或ZGC（并发疏散消除STW疏散阶段）能否根治问题。依赖关系：基础算法是根因分析的底层，分代策略决定GC频率，并发回收决定停顿长度，现代GC对比给出最终方案。
</Answer>

**问题 4**：为什么说理解GC算法原理对实际调优至关重要？「会换GC收集器」和「懂GC算法」的区别是什么？

<Answer>
会换GC收集器的人遇到问题就从CMS换G1或从G1换ZGC，能暂时缓解但不理解为什么有效、什么时候会失效。懂GC算法的人能解释：为什么G1的Region分代比CMS的物理分代更适合大堆（避免全堆扫描，Garbage First选择性回收）；为什么ZGC的染色指针比Shenandoah的Brooks指针更省空间（染色指针利用64位地址高位，不额外占用对象头）；为什么SATB会产生浮动垃圾但不会漏标（快照保证不漏但可能多标，本轮不回收的垃圾下轮再说）；为什么实时GC的Metronome调度需要精确的工作量模型（分配率×时间=必须完成的GC工作量，Slack为负就会溢出截止时间）。判断标志：能否从算法选择、分代假说、并发安全三个维度解释一个GC现象的根因，而非「遇到问题就换收集器」。
</Answer>

<GlossaryItem term="三大维度">算法维度（基础算法——标记清除/复制/压缩）、性能维度（分代与并发——弱分代假说/写屏障/三色不变式）、工程维度（现代实现——G1/ZGC/Shenandoah）。三者交叉构成GC技术闭环。</GlossaryItem>
<GlossaryItem term="递进链">标记清除 → 复制 → 标记压缩 → 分代 → 并发 → 实时 → 现代GC对比。算法维度到性能维度到工程维度的递进，每个维度建立在前一个之上。</GlossaryItem>
<GlossaryItem term="Full GC事故主线">用一次线上Full GC频繁触发的诊断串联全书：碎片分析 → 分代比例检查 → 并发标记评估 → 现代GC迁移方案。</GlossaryItem>
<GlossaryItem term="GC性能指标三角">吞吐量（throughput）、延迟（latency/STW停顿）、内存占用（footprint）。三者不可能同时最优，GC算法选择本质是在三者间做权衡。</GlossaryItem>
