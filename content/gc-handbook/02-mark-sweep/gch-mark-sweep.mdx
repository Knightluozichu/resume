## 直觉引入

标记-清除像「仓库盘点」。第一步盘点（标记）：从仓库入口（根集合）出发，沿着货架通道（引用链）走遍所有能走到的货物（可达对象），在这些货物上贴一个绿色标签（标记为存活）。走不到的货物就是废弃的（不可达=垃圾）。第二步清理（清除）：把没贴标签的货物从货架上取下来，腾出空间。但问题来了——取下来的位置留下了大小不一的空洞（碎片），新来的大货物可能找不到连续的空洞放不下。

## 三阶段流程

```text
阶段1：标记（Mark）
  从 GC Roots 出发，深度优先/广度优先遍历对象图
  所有可达对象标记为「存活」
  工作队列：灰色对象队列（待扫描子节点）

阶段2：清除（Sweep）
  线性遍历整个堆
  未标记的对象 → 加入自由链表
  已标记的对象 → 清除标记位（为下一轮准备）

阶段3：碎片（Fragmentation）
  存活对象原地不动
  空闲块不连续 → 外部碎片
  总空闲空间可能足够，但无法分配大对象
```

<Callout type="insight">
**标记-清除的核心矛盾**：标记阶段只遍历存活对象（开销与存活量成正比），但清除阶段必须遍历整个堆（开销与堆大小成正比）。对于大堆且存活率高的场景，清除阶段的开销不可忽视。位图标记可以将清除阶段优化为遍历位图而非整个堆。
</Callout>

## 三色标记法

```text
三色不变式（并发标记的安全保证）：

白色 White：尚未被GC访问 → 候选垃圾
灰色 Grey：已访问但子节点未全部扫描 → 工作队列中
黑色 Black：已访问且子节点全部扫描 → 确定存活

流转：白 →（被发现）→ 灰 →（子节点扫描完）→ 黑

强不变式：黑色对象不允许指向白色对象
  → 任何新增的黑→白引用都会被屏障拦截
  → 保证不会漏标

弱不变式：黑色对象可以指向白色对象
  → 但被指向的白色对象会被立即标记为灰色
  → SATB（Snapshot At The Beginning）快照策略
```

<Callout type="trap">
**并发标记的致命问题——漏标**：如果mutator在GC标记过程中修改了引用（黑色B新增指向白色D的引用，同时灰色A删除了指向D的引用），GC可能永远不会再访问到D，将存活的D误判为垃圾并回收，导致程序崩溃。这就是为什么并发GC必须使用读写屏障。
</Callout>

## 自由链表管理

```text
自由链表（Free List）= 空闲块的链表

结构：
  head → [size|next] → [size|next] → [size|next] → null
         空闲块1         空闲块2         空闲块3

分配策略：
  First-Fit：找到第一个足够大的空闲块
    优点：快    缺点：大块被切碎
  Best-Fit：找到最小的足够大的空闲块
    优点：减少碎片    缺点：遍历慢
  Next-Fit：从上次分配位置继续找
    优点：局部性好    缺点：可能跳过大块

问题：
  - 碎片导致分配失败（总空间够但无连续大块）
  - 链表遍历影响分配速度
  - 合并相邻空闲块的开销
```

## 位图标记优化

```text
传统标记：在对象头中设置标记位
  问题：每个对象都要写对象头 → 缓存不友好

位图标记：用一个独立的位图表记录标记状态
  1 bit 对应堆中一个对齐单位（如8字节）

  堆地址:  [obj A][   ][obj B][obj C][   ]
  位图:     1  0  0  0  1  0  0  1  0  0

优点：
  ① 标记时不写对象头 → 无写屏障开销
  ② 位图紧凑 → 缓存友好
  ③ 清除阶段遍历位图而非整个堆
  ④ 支持并行标记（不同位图区域无冲突）
```

<Exercises>
**问题 1**：标记-清除算法的三阶段是什么？每个阶段的开销与什么成正比？

<Answer>
三阶段：①标记（Mark）——从GC Roots出发遍历对象图，标记所有可达对象为存活。开销与存活对象数量成正比（只遍历可达对象）。②清除（Sweep）——线性遍历整个堆，将未标记的对象加入自由链表，清除已标记对象的标记位。开销与堆大小成正比（必须遍历整个堆，包括存活和已死的对象）。③碎片（Fragmentation）——标记-清除不移动对象，回收后的空闲块不连续，产生外部碎片。碎片本身不产生运行时开销，但会导致后续分配失败（总空闲空间足够但无连续大块）。核心矛盾：标记阶段高效（只看存活对象），但清除阶段低效（必须看整个堆）。位图标记可以将清除阶段优化为遍历位图而非整个堆，减少缓存失效。
</Answer>

**问题 2**：三色标记法中，强不变式和弱不变式的区别是什么？分别对应什么屏障策略？

<Answer>
强不变式：黑色对象不允许指向白色对象。任何时刻如果黑色对象要新增指向白色对象的引用，屏障必须拦截——要么把白色对象变灰（确保后续会被扫描），要么阻止黑色对象获得白色引用。强不变式通过写屏障在新增引用时拦截。INC（增量更新）策略维护强不变式：当黑→白的新引用出现时，将黑色对象重新变灰，使其在后续会被重新扫描。弱不变式：黑色对象可以指向白色对象，但被指向的白色对象会被立即标记为灰色。SATB（Snapshot At Beginning）策略维护弱不变式：在GC开始时快照所有引用关系，当mutator删除引用时（如灰色A删除指向白色D的引用），写屏障将D变灰，保证D不会被漏标。区别：强不变式更严格但可能重新扫描更多对象；弱不变式更宽松但可能产生浮动垃圾（快照时存活但GC运行期间已死的对象不会被回收）。
</Answer>

**问题 3**：标记-清除算法的碎片问题如何影响系统？有哪些缓解策略？

<Answer>
碎片问题的影响：①大对象分配失败——总空闲空间可能足够，但空闲块不连续，找不到一个足够大的连续块，导致分配失败触发Full GC或OOM；②分配速度下降——自由链表变长，First-Fit/Best-Fit查找需要遍历更多空闲块；③缓存局部性差——存活对象分散在堆各处，访问时缓存命中率低。缓解策略：①空闲块合并——清除阶段将相邻的空闲块合并为大块，减少碎片数量；②分代回收——年轻代用复制式（无碎片），老年代用标记-清除（减少移动开销），分而治之；③定期压缩——周期性运行标记-压缩消除碎片；④大对象区——为大对象单独分配连续区域，避免在常规堆中找不到大块；⑤位图标记+分区清除——按区清除减少遍历开销。根本解决：标记-压缩（移动消除碎片）或复制式（紧凑无碎片），但都有额外开销。
</Answer>

**问题 4**：位图标记相比传统对象头标记有什么优势？为什么位图标记更适合并行GC？

<Answer>
位图标记用一个独立的位图表记录对象的标记状态（1 bit对应堆中一个对齐单位），而非在对象头中设置标记位。优势：①无写屏障开销——标记时不修改对象头，只修改位图，不影响mutator对对象头的并发访问；②缓存友好——位图紧凑（1 bit/对象 vs 对象头1 byte/对象），遍历位图时缓存命中率高；③清除优化——清除阶段遍历位图而非整个堆，位图中连续的0表示连续的空闲区，可以快速跳过；④适合并行——不同GC线程负责不同的位图区域（按堆地址分区），标记时不会产生对同一缓存行的竞争（false sharing少）。适合并行GC的原因：传统标记中多个线程同时写不同对象的标记位，如果这些对象头恰好在同一缓存行，会产生false sharing（一个线程写导致其他线程的缓存行失效）。位图标记可以将不同线程分配到不同的位图区域，避免false sharing，提高并行效率。
</Answer>

<Glossary>
<GlossaryItem term="三色标记法">用白/灰/黑三色标记对象状态的算法。白色=未访问（候选垃圾），灰色=已访问但子节点未扫描完（工作队列），黑色=已访问且子节点全扫描完（确定存活）。是并发标记的理论基础。</GlossaryItem>
<GlossaryItem term="三色不变式">并发标记的安全约束。强不变式：黑色不指向白色（INC增量更新维护）；弱不变式：黑色可指向白色但白色会被变灰（SATB快照维护）。</GlossaryItem>
<GlossaryItem term="自由链表">标记-清除算法中管理空闲块的链表数据结构。每个节点记录空闲块大小和下一块地址。分配时从链表中查找足够大的块。</GlossaryItem>
<GlossaryItem term="外部碎片">标记-清除不移动对象导致空闲块不连续。总空闲空间可能足够但无法分配大对象。与复制式/压缩式的「无碎片」形成对比。</GlossaryItem>
<GlossaryItem term="位图标记">用独立位图表记录标记状态（1 bit/对齐单位），替代对象头标记位。缓存友好、适合并行、清除阶段可遍历位图而非整个堆。</GlossaryItem>
</Glossary>
