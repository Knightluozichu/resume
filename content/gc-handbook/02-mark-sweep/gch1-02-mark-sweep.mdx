# 第2章 标记-清扫垃圾回收

本页对应第一版正式结构中的 **第2章 标记-清扫垃圾回收**。课程不复制原文，而是按目录逐节点独立重构算法、证明与工程接口，目标是从根闭包、三色抽象、位图标记与惰性清扫推导不移动回收器的正确性、局部性和碎片代价。每项结论必须回到对象图、状态转换、伪代码和可重复测量，不能用某个JVM参数名称替代算法理解。

## 从对象图与不变式开始

标记阶段计算从根可达对象的传递闭包，清扫阶段回收未标记单元并重置下一轮元数据。白、灰、黑三色不是对象的业务状态，而是遍历进度：灰对象已发现但其出边尚未完全扫描，黑对象的出边已处理。位图将标记元数据从对象头移出，便于批量清零和并行原子更新，却要求地址到位的精确映射。惰性清扫把清扫成本移到分配路径，改善整轮暂停但可能制造分配尾延迟。

所有垃圾回收问题先抽象为<Term def="以对象为顶点、引用为有向边并显式标出根的运行时状态模型">对象图</Term>。<Term def="运行时承诺可由栈、寄存器、全局、句柄或原生接口直接访问的入口集合">根集合</Term>是遍历入口；从根可达只是保守的存活近似，并不等于对象未来必被使用。<Term def="执行应用逻辑、分配对象并持续改变对象图的线程">变异器</Term>与回收器共享同一堆状态。安全性要求不能回收仍可能被访问的对象，完整性描述是否能找出所有垃圾，及时性描述识别与回收之间的延迟。回收器、分配器、编译器和语言语义共同决定这些合同，任何一层缺失都可能让局部正确的算法在系统中失效。

停止世界、并行和并发是三个正交维度。停止世界描述变异器是否暂停，并行描述多个回收线程是否同时完成同一阶段，并发描述回收器是否与变异器重叠运行。并发降低某些暂停，却增加屏障、同步、浮动垃圾和CPU竞争；并行缩短阶段墙钟时间，却可能增加总CPU和内存带宽。必须报告阶段时间线，而不是把“并行并发”当成一个模糊标签。

对象移动决定运行时接口的复杂度。不移动方案保留地址稳定性但可能碎片化；复制与整理产生连续空间和快速分配，却必须更新根、堆内引用、句柄、内部指针和原生代码持有的地址。并发移动还需读屏障、间接层或多版本协议，保证变异器无论在搬移前、中、后读取都看到合法对象身份与字段值。<Term def="回收完成前用于吸收继续分配、对象复制和元数据增长的保留容量">空间余量</Term>必须按最坏工作量而不是平均值估算；并发结构还要指出<Term def="一个并发操作可被视为瞬间生效、并与其他操作形成合法顺序的时刻">线性化点</Term>。

## 最小算法切片

先把算法写成可检查的状态机，而不是产品参数清单：

```text
roots -> discover(object)
while worklist is not empty:
  object = remove(worklist)
  for each reference in object:
    if reference has not been discovered:
      mark or forward reference
      add reference to worklist
reclaim, sweep, compact, or publish the completed space
```

实现记录至少包含对象标识、地址或句柄、颜色/计数/年龄、所属分区、扫描状态和转发状态。每次状态变化注明唯一所有者和原子边界；若元数据会溢出、工作表会耗尽或目的空间会不足，失败路径必须在实验前定义。只给出正常路径的伪代码不能证明回收器可用。

实验输入与环境采用可重放合同：

```yaml
runtime: exact-build-and-commit
heap: fixed-min-max-and-region-layout
workload: seeded-object-graph-and-allocation-trace
controls: one-variable-per-run
evidence: raw-events-percentiles-space-cpu-errors
stop: timeout-or-explicit-safety-limit
```

验收把预期和可推翻条件写在运行前：

```gherkin
Given identical roots, object graph, heap limit, threads, and seed
When one collector policy or workload variable changes
Then safety and progress invariants still hold
And target gains do not hide CPU, space, latency, or failure regressions
```

对并发算法，枚举变异器可能执行的读、写、分配、发布、批量复制、原生调用和线程退出。屏障完整性要逐项核对，阶段切换前冲刷线程本地日志；终止检测不仅检查全局队列为空，还要证明没有本地或飞行中的工作。对实时算法，还要把每步最大成本和不可中断区间写进预算。

## 定量模型与边界

回收占比与有效吞吐必须共用同一墙钟窗口：

$$
R_{gc}=T_{gc}/T_{wall}, qquad Throughput=Work_{mutator}/T_{wall}
$$

追踪与复制工作至少受根、扫描边和存活字节控制：

$$
W_{trace} \approx N_{roots}+N_{edges scanned}, qquad W_{copy} \approx Bytes_{live}
$$

空间安全要求回收完成前仍有足够余量吸收分配和疏散：

$$
Reserve ge AllocationRate 	imes T_{cycle}+Bytes_{evacuated}+Metadata
$$

实时与低延迟比较还应明确一个观测窗内留给变异器的最低份额：

$$
U_{mutator}=T_{mutator}/T_{wall}=1-R_{gc}
$$

公式用于明确变量，不替代测量。每个数字注明单位、堆上限、对象分布、线程数、预热、重复次数、分位数和置信范围。平均暂停、最大暂停和服务端请求尾延迟回答不同问题；一次运行的最小值不能作为容量承诺。

<Callout type="trap">**核心陷阱。** 只画标记和清扫两个阶段，忽略工作表溢出、缓存访问、自由空间组织和是否移动的工程选择。修复方法是回到对象图和时间线，一次只改变一个算法或参数，并同时记录目标指标与CPU、驻留集、分配失败、回收频率和错误率。</Callout>

<Callout type="trap">**实现名称不等于算法证明。** 产品可能组合多个算法并在版本间改变屏障、阶段与默认值。先证明根、对象移动、并发交错和空间余量，再把证据映射到具体实现；只有参数名或日志截图不能通过验收。</Callout>

<Callout type="warning">**安全实验。** 堆耗尽、并发竞态、对象移动和原生引用实验应在受限进程或容器内执行，设置内存、CPU和超时，禁止对生产数据直接做破坏性重放。堆转储和日志可能包含业务数据，应最小授权并记录销毁。</Callout>

## 本章回顾

本页从“第2章 标记-清扫垃圾回收”覆盖到“移动还是不移动？”，共12个正式节点。闭环是先建立对象图与不变式，再执行“在相同对象图上切换对象头标记与侧位图、立即清扫与惰性清扫，测量缓存失效、分配延迟和碎片”，最后用三色状态机、标记栈上界、位图布局、惰性清扫与空闲链证据证明结论可重放、可推翻、可回滚。若仍出现“只画标记和清扫两个阶段，忽略工作表溢出、缓存访问、自由空间组织和是否移动的工程选择”，应补做失败交错和空间余量实验，而不是继续叠加参数。

<Exercises>

**问题 1**：第2章 标记-清扫垃圾回收覆盖哪些正式节点，核心证明主线是什么？

<Answer>本页覆盖12个正式节点，从“第2章 标记-清扫垃圾回收”到“移动还是不移动？”。核心主线是从根闭包、三色抽象、位图标记与惰性清扫推导不移动回收器的正确性、局部性和碎片代价，交付三色状态机、标记栈上界、位图布局、惰性清扫与空闲链证据。</Answer>

**问题 2**：怎样为第2章 标记-清扫垃圾回收建立最小可执行实验？

<Answer>固定对象图、根、分配序列、堆上限、线程和测量窗口，执行“在相同对象图上切换对象头标记与侧位图、立即清扫与惰性清扫，测量缓存失效、分配延迟和碎片”；保存基线、单变量对照、原始证据与停止条件。</Answer>

**问题 3**：为什么“只画标记和清扫两个阶段，忽略工作表溢出、缓存访问、自由空间组织和是否移动的工程选择”会破坏结论？

<Answer>它遗漏正确性合同、系统接口或负面成本。必须回到三色状态机、标记栈上界、位图布局、惰性清扫与空闲链证据，补齐对象移动、并发交错、空间余量、吞吐CPU内存与失败回滚。</Answer>

**问题 4**：如何为第2章 标记-清扫垃圾回收设计反证？

<Answer>保持输入与环境不变，只提高存活率、分配率、共享度或线程数中的一个；一旦安全性、尾延迟、空间、CPU或进展保证越界，即推翻原选择。</Answer>

**问题 5**：把该章算法迁移到另一语言或运行时时，哪些合同必须重建？

<Answer>重新核对根枚举、对象布局、引用精度、移动能力、屏障插入、弱引用与终结语义、原生接口、内存模型和日志口径，不能复制产品参数。</Answer>

**问题 6**：达到独立交接标准需要哪些证据？

<Answer>需要版本化源码或伪代码、对象图、输入生成器、完整配置、原始测量、失败反例、资源风险和回滚，让他人仅凭三色状态机、标记栈上界、位图布局、惰性清扫与空闲链证据重放并挑战结论。</Answer>
