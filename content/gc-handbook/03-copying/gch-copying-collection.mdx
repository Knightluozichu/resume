## 直觉引入

复制式回收像「搬家整理」。你有一间堆满杂物的房间（From区），旁边有一间空房间（To区）。搬家时你从门口（根集合）能拿到的东西开始，一件件搬到空房间，按顺序放好。搬完之后原房间整个清空（整体回收），所有东西在新房间紧凑排列（无碎片）。关键妙处是：搬的时候顺手在每个东西上贴一张「新地址便签」（转发指针），别人问你「东西在哪」你只需看便签就知道新位置。

## From/To 半区机制

```text
堆被等分为两个半区：

┌────────────────┬────────────────┐
│  From 半区      │   To 半区       │
│  （当前使用）    │  （空闲/目标）   │
│  对象分配在此    │  复制目标        │
└────────────────┴────────────────┘

回收流程：
  1. 从根集合出发，把存活对象复制到To区
  2. Cheney算法广度优先追踪所有可达对象
  3. 更新所有引用指向To区新地址
  4. 交换From/To角色（原From区整体可复用）

核心代价：可用空间减半（任何时刻只有From区可用）
核心收益：无碎片（To区紧凑排列）+ 分配极快（指针碰撞）
```

<Callout type="insight">
**空间减半的深层原因**：复制式回收需要保证To区有足够空间容纳From区的所有存活对象。最坏情况下所有对象都存活，To区需要与From区等大。因此堆利用率最高50%。实际中年轻代存活率低（弱分代假说），复制量少，这个代价是可接受的。但老年代存活率高，复制成本大，不适合用复制式。
</Callout>

## Cheney 算法

```text
Cheney算法 = 广度优先（BFS）复制 + 工作队列内联

核心：用两个指针 scan 和 free 管理To区

初始状态：
  To区：[          空闲          ]
  scan ─┘                  free ─┘

步骤1：从根集合复制
  对每个根引用指向的对象：
    复制到To区free位置
    在旧对象头设置转发指针 → To区新地址
    free 推进

  To区：[A'|C'|          空闲      ]
  scan ─┘        free ─┘
  （A'和C'已复制，旧A和C有转发指针）

步骤2：扫描队列
  while (scan &lt; free) {
    取scan处对象（如A'）
    遍历A'的每个引用字段：
      如果引用对象未被复制（无转发指针）：
        复制到free位置，设置转发指针
        free 推进
      更新A'的引用字段 → 转发后的新地址
    scan 推进
  }

步骤3：完成
  scan == free → 所有存活对象已复制且引用已更新
  交换From/To角色
```

<Callout type="trap">
**关键细节——转发指针的作用**：当对象A被复制到To区后，旧A的头中记录了新地址（转发指针）。后续如果另一个对象B也引用A，GC检查B的引用字段发现A已有转发指针，直接将B的引用更新为A的新地址，不会重复复制。这保证了每个存活对象只被复制一次。
</Callout>

## 指针碰撞分配

```text
复制式回收后To区紧凑无碎片 → 分配极快

分配机制（Bump-the-Pointer / 指针碰撞）：
  维护一个 free 指针指向To区空闲区起点

  分配对象O（大小s）：
    if (free + s &lt;= end) {
      addr = free
      free += s
      return addr
    } else {
      触发GC
    }

  时间复杂度：O(1)！
  对比标记-清除的自由链表分配：O(n)（遍历链表找合适块）

线程安全：
  单线程：直接bump
  多线程：TLAB（Thread-Local Allocation Buffer）
    每个线程预分配一小段To区，各自在自己的TLAB中bump
    避免每次分配都CAS竞争free指针
```

## 复制式 vs 标记-清除

```text
特性          标记-清除         复制式回收
─────────────────────────────────────────────
碎片          有（外部碎片）     无（紧凑排列）
空间利用率     ~100%            ~50%（减半）
分配速度       O(n)（链表查找）   O(1)（指针碰撞）
回收开销       遍历整个堆        只复制存活对象
适合场景       存活率高的老年代   存活率低的年轻代
引用更新       不需要（原地）     需要（转发指针）
对象移动       不移动            移动到To区
```

<Exercises>
**问题 1**：Cheney算法的scan和free指针各自的作用是什么？算法何时终止？

<Answer>
scan指针：指向To区中「已复制但尚未扫描其引用字段」的对象。scan的工作是取出该对象，遍历其引用字段，将引用的未复制对象复制到To区并更新引用。scan向后推进表示该对象已被处理。free指针：指向To区中下一个空闲位置，即新复制对象的落地位置。每复制一个对象，free向后推进。算法流程：①初始scan=free=To区起点；②从根集合复制存活对象到free处，free推进；③while(scan&lt;free)：取scan处对象，扫描其引用字段，未复制的复制到free处（free推进），更新引用为转发地址，scan推进；④scan==free时终止——所有存活对象已复制且引用已更新。终止条件的含义：scan追上free表示To区中所有已复制的对象都已扫描完毕，没有新的对象需要复制，回收完成。
</Answer>

**问题 2**：复制式回收为什么适合年轻代但不适合老年代？

<Answer>
复制式回收的代价与存活对象数量成正比（需要复制每个存活对象）。年轻代符合弱分代假说——绝大多数对象朝生夕死，存活率极低（通常只有2%~20%），因此复制量很小，回收极快。同时年轻代频繁GC需要快速完成，复制式的O(1)分配（指针碰撞）和紧凑无碎片特性非常有利。老年代不适合的原因：①存活率高——老年代存放长期存活的对象，存活率可能80%~95%，复制量巨大，回收极慢；②空间浪费不可接受——老年代通常占堆的大部分，减半意味着大量空间浪费，而年轻代本来就小（通常占堆1/3），减半的绝对量小；③对象大——老年代可能有大对象，复制大对象开销高。因此老年代通常用标记-清除（如CMS）或标记-压缩（如Serial Old、Parallel Old）。
</Answer>

**问题 3**：转发指针如何保证每个存活对象只被复制一次？

<Answer>
转发指针（Forwarding Pointer）在对象被复制到To区后，写入旧对象的对象头中，记录新地址。工作流程：①GC从根集合或某个已扫描对象的引用字段出发，遇到对象A；②检查A的对象头是否有转发指针——如果没有，说明A尚未被复制：将A复制到To区free位置，在旧A的对象头写入转发指针指向To区新地址，更新引用字段为新地址；③如果A已有转发指针，说明A已被复制过：直接将引用字段更新为转发指针指向的新地址，不再复制。关键点：第一个引用A的GC操作会复制A并设置转发指针，后续所有引用A的操作都通过转发指针找到新地址，不会重复复制。这保证了每个存活对象恰好被复制一次，时间复杂度为O(存活对象数量)。
</Answer>

**问题 4**：TLAB（Thread-Local Allocation Buffer）如何解决多线程下的指针碰撞竞争问题？

<Answer>
多线程环境下如果所有线程共享一个free指针做指针碰撞，每次分配都需要CAS（Compare-And-Swap）竞争free指针，在高并发分配时成为瓶颈。TLAB解决方案：将To区的空闲空间预先划分为多个小段，每个线程分配一段作为自己的TLAB。线程在自己的TLAB内做指针碰撞（单线程无竞争，O(1)），只有当TLAB用完时才需要向全局free指针申请新的TLAB（CAS竞争频率大幅降低）。优势：①分配无锁——99%以上的分配在TLAB内完成，无需CAS；②缓存友好——每个线程的TLAB是连续内存，分配的对象在同一缓存行附近；③可调——TLAB大小可动态调整（JVM的-XX:MinTLABSize/-XX:TLABSize），大TLAB减少申请频率但增加浪费。代价：TLAB未用完的部分在GC时浪费（通常很小），以及TLAB切换时的缓存失效。JVM默认开启TLAB（-XX:+UseTLAB）。
</Answer>

<Glossary>
<GlossaryItem term="From/To半区">复制式回收将堆等分为两个半区，任意时刻只用From区分配，To区空闲。GC时存活对象从From复制到To，然后交换角色。代价是空间减半。</GlossaryItem>
<GlossaryItem term="Cheney算法">复制式回收的经典算法，用scan和free双指针在To区内实现广度优先复制。scan扫描已复制对象的引用，free指向下一个复制位置。scan==free时终止。</GlossaryItem>
<GlossaryItem term="转发指针">对象被复制到To区后，旧对象头中记录的新地址。保证每个存活对象只被复制一次，后续引用通过转发指针直接更新为新地址。</GlossaryItem>
<GlossaryItem term="指针碰撞">复制式回收后To区紧凑无碎片，分配时只需将free指针前移对象大小即可，O(1)分配。多线程下用TLAB避免竞争。</GlossaryItem>
<GlossaryItem term="TLAB">Thread-Local Allocation Buffer，每个线程预分配一段To区空间，在自己的TLAB内无锁指针碰撞分配，减少多线程CAS竞争。JVM默认开启。</GlossaryItem>
</Glossary>
