## 直觉引入

标记-压缩像「书架整理」。书架上有些书被借走了（垃圾对象留下的空洞），剩下散落各处（碎片）。你想把它们挤到一头，腾出连续空间放新书。但不能直接推——每本书的位置变了，借书卡上记的旧位置（引用）就得改。所以你得先算好每本书该挪到哪（计算新地址），再把所有借书卡上的位置更新（更新引用），最后才真正搬书（移动对象）。这就是标记-压缩的三趟流程。

## 滑动压缩三趟流程

```text
前提：标记阶段已完成，存活对象已标记

趟1：计算新地址
  从堆起点线性扫描
  为每个存活对象计算压缩后的新地址
  将新地址写入对象头（转发指针）
  维护一个「旧地址→新地址」的映射

趟2：更新引用
  遍历所有根引用和所有存活对象的引用字段
  将每个引用更新为转发指针指向的新地址

趟3：移动对象
  从堆起点线性扫描
  将每个存活对象移动到其新地址
  移动后清除标记位和转发指针

结果：存活对象紧凑排列在堆一端，另一端连续空闲
```

<Callout type="insight">
**为什么需要三趟而不是一趟**：如果在一趟中既移动对象又更新引用，会面临「先移谁」的困境——移动A可能覆盖B的位置（B还没移走），或者B移走后A找不到B的新位置。三趟分离了「计算地址」「更新引用」「移动对象」三个关注点，每趟都是线性扫描，保证正确性。代价是多趟遍历的开销。
</Callout>

## Two-Finger 双指法

```text
两趟压缩，不保留对象分配顺序：

趟1：移动存活对象到空洞
  scan 指针从堆起点向右扫描找存活对象
  free 指针从堆末尾向左扫描找空洞
  当 scan 找到空洞且 free 找到存活对象时：
    将 free 处的对象移到 scan 处的空洞
    在旧位置设置转发指针

趟2：更新引用
  遍历所有引用，通过转发指针更新为新地址

特点：
  优点：只需两趟，比滑动三趟少一趟
  缺点：对象顺序被打乱 → 缓存局部性差
  适合：不关心对象顺序的场景
```

## 表格法

```text
用标记位图 + 偏移表实现压缩：

步骤1：标记位图
  用1 bit记录每个对齐单位是否存活
  位图比遍历堆更紧凑、更缓存友好

步骤2：偏移表
  将堆分成固定大小的块
  为每个块记录：该块之前所有块的存活对象总大小
  = 该块第一个存活对象的新地址

步骤3：更新引用
  通过位图+偏移表计算每个引用的新地址

步骤4：移动对象
  按位图指示移动存活对象

特点：
  优点：支持并行化（不同块可并行处理）
  优点：适合大堆（位图紧凑）
  缺点：额外空间存偏移表
  适合：大堆 + 并行GC
```

## 三种压缩策略对比

```text
策略          遍历趟数  保留顺序  额外空间  并行化  缓存友好
────────────────────────────────────────────────────────────
滑动压缩       3        是        转发指针   难      是
Two-Finger    2        否        转发指针   难      否
表格法         4        是        位图+偏移表 是      是
```

<Callout type="trap">
**误区**：认为标记-压缩比标记-清除「更好」。实际上标记-压缩的移动开销（多趟遍历+对象移动+引用更新）远大于标记-清除（一趟遍历+链表操作）。标记-压缩的价值在于消除碎片，但如果碎片不严重或可以容忍（如老年代分配频率低），标记-清除可能更高效。CMS就是用标记-清除而非标记-压缩，以换取更短的停顿。
</Callout>

## 转发指针的实现

```text
对象头中的转发指针：

  ┌─────────────────────────┐
  │ 对象头 (Object Header)    │
  │  ┌─────────────────────┐ │
  │  │ 标记位 / 锁信息       │ │
  │  ├─────────────────────┤ │
  │  │ 转发指针 (fwd ptr)   │ │ ← 压缩时写入新地址
  │  ├─────────────────────┤ │
  │  │ 类型指针 (klass)     │ │
  │  └─────────────────────┘ │
  ├─────────────────────────┤
  │ 实例数据                  │
  └─────────────────────────┘

转发指针的生命周期：
  1. 标记阶段：不存在
  2. 计算新地址：写入新地址
  3. 更新引用：被读取以更新所有引用
  4. 移动完成后：清除（恢复为正常状态）

注意：转发指针占用对象头空间
  → 增加了每个对象的内存开销
  → 某些GC（如Shenandoah的Brooks指针）永久保留转发指针
```

<Exercises>
**问题 1**：滑动压缩为什么需要三趟遍历？每趟分别做什么？

<Answer>
三趟遍历的原因是分离三个关注点，避免「先移谁」的困境（移动A可能覆盖未移走的B，或B移走后A找不到B的新位置）。①趟1计算新地址——从堆起点线性扫描，为每个存活对象计算压缩后的新地址（累计存活对象大小即为下一个对象的新地址偏移），将新地址写入对象头作为转发指针。这一趟不移动任何对象，只计算和记录。②趟2更新引用——遍历所有GC Roots和所有存活对象的引用字段，将每个引用通过转发指针更新为新地址。这一趟不移动对象，只修改引用值。③趟3移动对象——从堆起点线性扫描，将每个存活对象移动到其转发指针记录的新地址。因为新地址总是≤旧地址（向左滑动），且已按顺序计算好，移动时不会覆盖尚未移动的对象。三趟都是线性扫描，时间复杂度O(堆大小)。结果：存活对象紧凑排列在堆一端，无碎片。
</Answer>

**问题 2**：Two-Finger双指法和滑动压缩的核心区别是什么？各自的优缺点？

<Answer>
核心区别：滑动压缩保留对象的分配顺序（存活对象按原顺序向左滑动），Two-Finger不保留顺序（从堆两端向中间扫描，将末尾存活对象移到前端空洞）。滑动压缩三趟流程：计算新地址→更新引用→移动对象。Two-Finger两趟流程：①双指针对向扫描，scan从左找空洞，free从右找存活对象，将右端对象移到左端空洞并设转发指针；②更新所有引用。优点对比：Two-Finger只需两趟（少一趟遍历），滑动压缩保留顺序（缓存友好）。缺点对比：Two-Finger打乱对象顺序导致后续访问缓存局部性差，滑动压缩多一趟遍历开销更大。适用场景：Two-Finger适合不关心对象顺序且堆较小的场景；滑动压缩适合大堆和对缓存性能要求高的场景（现代GC普遍采用滑动压缩或其变体）。实际上大多数现代GC（如G1的Full GC、Parallel Old）使用保留顺序的压缩算法，因为缓存性能对整体吞吐影响很大。
</Answer>

**问题 3**：表格法如何支持并行压缩？相比滑动压缩有什么优势？

<Answer>
表格法用标记位图+偏移表实现压缩，支持并行化的关键在于分块处理。流程：①标记位图——用1 bit记录每个对齐单位的存活状态，位图紧凑且可按区域并行填充；②偏移表——将堆分成固定大小的块，为每个块预计算「该块之前所有存活对象的总大小」即该块第一个存活对象的新地址偏移。不同块的偏移可并行计算（前缀和算法）；③更新引用——每个引用通过查位图确认对象在哪个块，再查偏移表得到该块的基础偏移，加上块内偏移得到新地址。不同引用的更新可并行；④移动对象——不同块的对象可并行移动（各块的目标区域不重叠）。优势：①并行化——不同GC线程负责不同块，标记/更新/移动都可并行，适合多核大堆；②缓存友好——位图紧凑（1 bit/单位），遍历位图比遍历整个堆缓存命中率高；③可扩展——块大小可调，适应不同堆规模。代价：额外空间存位图和偏移表（通常~3%堆大小）。
</Answer>

**问题 4**：为什么CMS选择标记-清除而不是标记-压缩？这个选择的代价是什么？

<Answer>
CMS（Concurrent Mark Sweep）选择标记-清除而非标记-压缩的核心原因是降低停顿。标记-清除的清除阶段只需将未标记对象加入自由链表（不移动对象），可以并发执行（与mutator同时运行）。而标记-压缩需要移动对象和更新所有引用，这需要STW（移动对象时mutator不能访问被移动的对象，否则会读到错误地址）。CMS的设计目标是最低停顿，因此选择了可以并发的标记-清除。代价：①碎片——标记-清除不移动对象，长期运行后碎片严重，可能导致大对象分配失败触发Full GC（Serial Old的标记-压缩，全程STW，停顿极长）；②Concurrent Mode Failure——当碎片导致分配失败时退化为Full GC，反而停顿更长；③空间预占用——CMS需要预留空间给并发标记使用（避免分配失败），降低了堆利用率。CMS最终在JDK 9被废弃，JDK 14移除，核心原因就是碎片问题无法根治。G1通过Region化+Mixed GC在减少碎片的同时保持低停顿，替代了CMS。
</Answer>

<Glossary>
<GlossaryItem term="滑动压缩">标记-压缩的经典策略，三趟遍历（计算新地址→更新引用→移动对象），存活对象按原顺序向一端滑动。保留分配顺序→缓存友好，但三趟开销大。</GlossaryItem>
<GlossaryItem term="Two-Finger">双指法压缩，scan从左找空洞、free从右找存活对象，将末尾对象移到前端空洞。只需两趟但不保留顺序，缓存局部性差。</GlossaryItem>
<GlossaryItem term="表格法">用标记位图+偏移表实现的压缩策略。支持分块并行处理，适合大堆和多核。代价是额外空间存位图和偏移表。</GlossaryItem>
<GlossaryItem term="转发指针">压缩过程中写入对象头的「新地址」指针。用于在移动对象前先更新所有引用，保证引用的正确性。移动完成后清除。</GlossaryItem>
<GlossaryItem term="碎片消除">标记-压缩的核心价值。与标记-清除（有碎片）和复制式（无碎片但空间减半）形成三角权衡：压缩无碎片不浪费空间，但移动开销大。</GlossaryItem>
</Glossary>
