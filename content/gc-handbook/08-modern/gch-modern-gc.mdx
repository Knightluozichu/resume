## 直觉引入

四大GC像「四代环卫系统」。CMS是第一代「边营业边扫」（并发标记-清除），但碎片严重最终被淘汰。G1是第二代「分区精扫」（Region+Garbage First），平衡了停顿和碎片。Shenandoah和ZGC是第三代「全程并发」（并发疏散），连搬运货物（移动对象）都不停业。Shenandoah用「每件货物贴搬家标签」（Brooks转发指针），ZGC用「地址编码颜色」（染色指针），殊途同归但技术路线不同。

## 四大GC总览对比

```text
特性          CMS           G1            Shenandoah     ZGC
──────────────────────────────────────────────────────────────
内存模型       物理分代       Region分代     Region无分代    ZPage多粒度
停顿时间       ~100ms        ~200ms        <10ms          <1ms
并发标记       是            是             是              是
并发疏散       否            否             是              是
屏障技术       卡表写屏障     SATB+卡表      Brooks指针      染色指针+读屏障
堆上限         ~4GB          ~32GB          ~数百GB         16TB
JDK状态        JDK14废弃     JDK9+默认      JDK12+生产      JDK15+生产
```

<Callout type="insight">
**并发疏散是低延迟的关键**：CMS和G1的停顿主要来自「疏散阶段」（移动存活对象）必须STW，因为移动对象时mutator不能访问。Shenandoah和ZGC通过转发指针（Brooks/染色指针）实现了并发疏散——移动对象时mutator照常运行，读引用时自动转发到新地址。这就是它们能达到&lt;10ms甚至&lt;1ms停顿的根本原因。
</Callout>

## CMS——并发标记-清除先驱

```text
设计目标：低停顿（老年代并发回收）
内存模型：物理分代（连续Eden/Survivor/Old）
核心流程：
  1. 初始标记 STW（标记GC Roots直接引用）
  2. 并发标记（与mutator同时遍历对象图）
  3. 预清理（减少再标记工作量）
  4. 再标记 STW（修正并发标记期间的变更，INC策略）
  5. 并发清除（回收未标记对象）

屏障：卡表写屏障 + INC增量更新
算法：标记-清除（不压缩 → 碎片严重）

致命缺陷：
  ①碎片 → 大对象分配失败 → Full GC（Serial Old STW极长）
  ②Concurrent Mode Failure → 并发标记跟不上分配 → 退化为Full GC
  ③浮动垃圾 → 并发期间产生的垃圾本轮不回收

结局：JDK 9标记废弃，JDK 14移除
```

## G1——Region化分代回收

```text
设计目标：可预测停顿 + 减少碎片
内存模型：Region分代（1-32MB Region动态充当Eden/Survivor/Old/Humongous）
核心流程：
  1. 并发标记（SATB策略）
  2. Mixed GC（选择垃圾最多的Region回收 = Garbage First）
  3. 疏散（存活对象复制到空闲Region，STW但可控制Region数量）

屏障：SATB写屏障 + 卡表 + RSet
算法：复制式（Young/Mixed GC）+ 标记-压缩（Full GC降级）

优势：
  ①Region化 → 可选择回收垃圾最多的Region
  ②可预测停顿 → MaxGCPauseMillis目标，选择能在目标内完成的Region集合
  ③Mixed GC → 增量回收老年代，减少碎片
  ④Full GC频率低 → 正常运行时几乎不触发

局限：
  ①疏散仍需STW（虽然可控）
  ②RSet内存开销（1%~20%堆）
  ③大堆时停顿仍可能超标
```

## ZGC——染色指针亚毫秒停顿

```text
设计目标：亚毫秒级停顿，支持超大堆（16TB）
内存模型：ZPage（多粒度：2MB/32MB/N-page）
核心技术：染色指针（Colored Pointer）

染色指针原理：
  64位地址中用高位（如42-45位）编码GC状态：
  ┌──────┬──────────────────────────┬──────────────────┐
  │ 未使用 │ 染色位(M0/M1/Remapped)    │ 对象地址(42位)    │
  └──────┴──────────────────────────┴──────────────────┘

  Marked0/Marked1：标记中（两个标记位交替使用，区分GC轮次）
  Remapped：已就位（对象已在最终位置）

读屏障：
  每次读引用时检查指针颜色：
    - Marked0/Marked1 → 对象在标记中，可能需要转发
    - Remapped → 对象已就位，直接访问
  自愈：读屏障自动将旧指针修正为转发后的新地址

并发疏散：
  1. 并发标记（染色指针标记存活）
  2. 并发疏散（将存活对象复制到新ZPage）
  3. 并发重映射（更新引用为新地址，由读屏障自愈辅助）

优势：
  ①STW < 1ms（几乎全并发）
  ②支持16TB堆（染色指针用42位地址）
  ③读屏障自愈 → 无需单独重映射阶段
  ④停顿不随堆增大而增长

代价：
  ①读屏障开销（JIT可优化部分）
  ②染色指针需要OS支持多视图映射
  ③无分代（JDK 21开始实验性分代ZGC）
```

## Shenandoah——Brooks转发指针

```text
设计目标：低停顿 + 并发疏散
内存模型：Region（无分代，JDK 12+）
核心技术：Brooks转发指针

Brooks指针原理：
  每个对象头中增加一个转发指针：
  ┌────────────────┬────────────────┐
  │ Brooks fwd ptr  │ 对象数据        │
  └────────────────┴────────────────┘

  fwd == self → 对象未移动，直接访问
  fwd != self → 对象已移动，跳转到fwd指向的新位置

并发疏散流程：
  1. 并发标记（标记存活对象）
  2. 并发疏散（复制存活对象到新Region，更新Brooks指针）
  3. 并发更新引用（将所有引用更新为新地址）

优势：
  ①STW < 10ms（并发疏散+并发更新引用）
  ②实现相对直观（Brooks指针概念简单）
  ③不需要OS特殊支持（vs ZGC的多视图映射）

代价：
  ①每个对象额外1指针空间（~5%内存开销）
  ②每次访问对象需读Brooks指针（读屏障开销）
  ③无分代（所有对象同等对待，Young GC效率不如G1）

Shenandoah vs ZGC：
  共同点：都实现并发疏散，都达到<10ms停顿
  区别：Shenandoah用对象头空间（Brooks），ZGC用地址空间（染色）
        ZGC停顿更短（<1ms），Shenandoah实现更简单
```

<Callout type="trap">
**误区**：认为ZGC一定比G1好。实际上ZGC的读屏障开销在吞吐密集场景下可能使吞吐下降10%~15%，而G1的吞吐损失通常&lt;5%。对于批处理、大数据等吞吐优先的场景，G1可能更合适。ZGC的优势在延迟敏感的交互式场景。选择GC必须看场景，没有银弹。
</Callout>

## GC选型决策

```text
场景                    推荐GC        理由
────────────────────────────────────────────────────────
批处理/大数据           Parallel/G1   吞吐优先，停顿可容忍
Web服务/微服务          G1            平衡吞吐与延迟
低延迟交易              ZGC           <1ms停顿，交易不超时
超大堆（>32GB）          ZGC           停顿不随堆增长
中等堆+低延迟            Shenandoah    <10ms停顿，无需OS特殊支持
嵌入式/受限             Serial        低开销，单线程
```

<Exercises>
**问题 1**：为什么Shenandoah和ZGC能达到比G1更低的停顿？核心技术差异是什么？

<Answer>
根本原因：Shenandoah和ZGC实现了「并发疏散」（concurrent evacuation），而G1的疏散阶段仍然需要STW。G1的流程：并发标记（SATB）→ STW疏散（存活对象复制到空闲Region）。疏散必须STW因为移动对象时mutator不能访问被移动的对象（会读到错误地址），G1无法在移动时让mutator继续运行。Shenandoah和ZGC通过转发指针技术解决了这个问题：①Shenandoah的Brooks指针——每个对象头中有一个转发指针，初始指向自己。对象被移动后，转发指针指向新地址。mutator每次访问对象时先读转发指针，如果指向自己则直接访问，如果指向别处则跳转到新地址。GC移动对象时只需更新转发指针，mutator通过旧地址仍能找到新位置。②ZGC的染色指针——在64位地址的高位编码GC状态（Marked0/Marked1/Remapped），读屏障检查指针颜色判断对象是否正在被移动/转发，自动修正为新地址。两者都实现了「移动对象时mutator不停」，因此疏散阶段可以并发执行，STW仅限于极短的初始标记和再标记阶段。
</Answer>

**问题 2**：染色指针和Brooks转发指针各自的工作原理是什么？各有什么优缺点？

<Answer>
染色指针（ZGC）：在64位指针的高位（如第42-45位）编码GC状态。Marked0/Marked1表示标记中（两个位交替使用区分GC轮次），Remapped表示已就位。读屏障检查指针颜色：如果是Marked状态，对象可能正在被移动，需检查转发表获取新地址并修正指针（自愈）；如果是Remapped，对象已就位，直接访问。通过OS的多视图映射（multi-mapping），同一物理内存映射到不同虚拟地址，染色指针的地址转换由MMU完成。优点：①不额外占用对象头空间（利用地址高位）；②停顿更短（&lt;1ms）；③支持16TB超大堆。缺点：①需要OS支持多视图映射；②读屏障开销（每次读引用都检查颜色）；③实现复杂。Brooks转发指针（Shenandoah）：在每个对象的对象头中增加一个转发指针，初始指向自己。对象被移动后，转发指针更新为新地址。每次访问对象先读转发指针，fwd==self则未移动，fwd!=self则跳转。优点：①实现相对简单直观；②不需要OS特殊支持；③概念清晰。缺点：①每个对象额外1指针空间开销（约5%堆大小）；②每次对象访问都需额外读一次转发指针（缓存影响）；③停顿不如ZGC短（&lt;10ms vs &lt;1ms）。
</Answer>

**问题 3**：CMS为什么被废弃？G1如何解决CMS的问题？

<Answer>
CMS被废弃的核心原因是碎片问题无法根治：①CMS使用标记-清除算法（不压缩），长期运行后老年代碎片严重。当碎片导致大对象分配失败时，触发Full GC（Serial Old的标记-压缩，全程STW停顿极长），反而比不用CMS更差。②Concurrent Mode Failure——当分配速度超过并发标记速度时，老年代在标记完成前就满了，退化为Full GC。③浮动垃圾——并发期间产生的垃圾本轮不回收，需预留空间，降低堆利用率。G1的解决方案：①Region化——堆分为等大Region（1-32MB），每个Region动态充当Eden/Survivor/Old/Humongous，无物理分代边界。回收时以Region为单位选择垃圾最多的回收（Garbage First），而非回收整个老年代。②Mixed GC——在Young GC基础上增量回收部分Old Region，每次回收少量Old Region消除碎片，而非等到Full GC才压缩。③可预测停顿——通过MaxGCPauseMillis设定停顿目标，根据每个Region的回收成本模型选择能在目标时间内完成的最大Region集合。④复制式回收——存活对象复制到空闲Region，天然无碎片（vs CMS的标记-清除）。G1通过Region化+Mixed GC+复制式回收，在保持低停顿的同时解决了CMS的碎片问题，因此JDK 9起G1成为默认GC。
</Answer>

**问题 4**：在一个32GB堆、要求99线延迟&lt;10ms的在线交易系统中，应该选择G1还是ZGC？为什么？

<Answer>
应选择ZGC。分析：①延迟要求——99线&lt;10ms意味着99%的GC停顿必须在10ms以内。G1的典型停顿在~200ms级（虽然MaxGCPauseMillis可设，但在32GB堆上疏散阶段的实际停顿很难控制在10ms以内，因为G1疏散是STW的）。ZGC的停顿&lt;1ms，且不随堆大小增长，32GB堆下99线轻松&lt;10ms。②堆大小——32GB对G1来说偏大（G1推荐8GB~32GB，32GB是上限），疏散开销随堆增大。ZGC专为超大堆设计，32GB完全在舒适区。③吞吐权衡——在线交易系统是延迟敏感型而非吞吐敏感型，ZGC的读屏障开销（约10%~15%吞吐损失）是可接受的，而G1可能出现的200ms停顿会导致交易超时。④分代——ZGC目前无分代（JDK 21开始实验性分代ZGC），在年轻代回收效率上不如G1，但对于交易系统（对象生命周期相对均匀）影响不大。综上，ZGC的亚毫秒停顿+不随堆增长+32GB舒适区，使其比G1更适合此场景。如果堆较小（如4GB）或延迟要求宽松（如100ms），G1的吞吐优势更明显，则是更好的选择。
</Answer>

<Glossary>
<GlossaryItem term="并发疏散">GC移动存活对象时与mutator同时运行。是ZGC/Shenandoah达到&lt;10ms停顿的关键技术。CMS/G1的疏散阶段仍需STW。</GlossaryItem>
<GlossaryItem term="染色指针">ZGC的核心技术。在64位地址高位编码GC状态（Marked0/Marked1/Remapped），读屏障检查颜色实现并发转发。不占对象头空间，支持16TB堆。</GlossaryItem>
<GlossaryItem term="Brooks转发指针">Shenandoah的核心技术。每个对象头增加转发指针，移动后指向新地址。实现简单但每对象额外1指针空间开销。</GlossaryItem>
<GlossaryItem term="Garbage First">G1的核心策略。优先回收垃圾最多的Region，在停顿目标内选择最大回收量的Region集合。</GlossaryItem>
<GlossaryItem term="Concurrent Mode Failure">CMS的致命缺陷。并发标记速度跟不上分配速度时，老年代在标记完成前填满，退化为Full GC。</GlossaryItem>
</Glossary>
