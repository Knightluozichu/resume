## 直觉引入

几何体数据结构是计算机图形学的骨架——没有高效的空间组织，光线追踪、碰撞检测、地形渲染都退化为暴力 $O(n)$。本书从最基本的图元出发，逐步构建出四叉树、BVH、R-Tree 等空间加速结构。

全书的核心思想是「空间分割」：把 $n$ 个几何对象组织成树形结构，使得每次查询只需访问 $O(\log n)$ 个节点而非全部 $n$ 个。不同的分割策略（均匀网格 vs 自适应树 vs 层次包围盒）各有优劣，选择取决于数据分布和查询模式。

## 概念讲解

全书分四大板块：**基础**（图元与空间关系）、**数据结构**（四叉树与 BVH）、**算法**（三角剖分、Voronoi、空间索引）、**应用**（碰撞检测与光线追踪）。

<Term def="空间中的基本几何对象">图元</Term>是构建一切的基础。<Term def="递归地将空间分成子区域">空间分割</Term>是加速的核心手段。<Term def="用层次结构包裹几何体的包围盒">层次包围盒</Term>是光线追踪和碰撞检测的通用加速结构。

### 板块依赖
- 基础 → 结构：图元和 AABB 是四叉树/BVH 的基本单元。
- 结构 → 算法：空间索引为三角剖分和 Voronoi 提供查询基础。
- 算法 → 应用：碰撞检测和光线追踪是算法的直接消费者。

### 结构选择指南
- 数据均匀分布 → 均匀网格/空间哈希
- 数据稀疏/非均匀 → 四叉树/八叉树
- 射线查询为主 → BVH（SAH 构建）
- 范围查询为主 → R-Tree
- 动态更新频繁 → 动态 BVH 或空间哈希

## 代码对照

用 Python 展示全书结构索引与查询复杂度对比：

```python
structures = [
    ("暴力遍历", "O(n)", "无结构，逐个测试", "基准"),
    ("均匀网格", "O(1)+k", "等大格子", "均匀数据"),
    ("空间哈希", "O(1)+k", "稀疏网格", "游戏引擎"),
    ("四叉树", "O(log n)+k", "2D 自适应", "碰撞/LOD"),
    ("八叉树", "O(log n)+k", "3D 自适应", "体素/粒子"),
    ("BVH", "O(log n)", "层次包围盒", "光线追踪"),
    ("KD-Tree", "O(log n)", "空间中分面", "最近邻"),
    ("R-Tree", "O(log n)+k", "层次 MBR", "GIS/范围查询"),
]

print(f"{'结构':<12} {'查询复杂度':<16} {'特点':<14} {'典型应用'}")
print("-" * 60)
for name, complexity, desc, app in structures:
    print(f"{name:<12} {complexity:<16} {desc:<14} {app}")

def brute_force_query(objects, point):
    """暴力查询：O(n)"""
    return [obj for obj in objects if obj.contains(point)]

def grid_query(grid, point, cell_size):
    """网格查询：O(1) 定位 + O(k) 遍历"""
    cx, cy = int(point[0] // cell_size), int(point[1] // cell_size)
    return grid.get((cx, cy), [])

# 复杂度对比模拟
import time, random
for n in [100, 1000, 10000, 100000]:
    objs = [(random.random(), random.random()) for _ in range(n)]
    t0 = time.time()
    for _ in range(1000):
        brute_force_query(objs, (0.5, 0.5))
    t_brute = time.time() - t0
    print(f"n={n:>6}: 暴力 {t_brute*1000:.1f}ms")

```

暴力遍历 $O(n)$ 在 $n=100000$ 时显著变慢。空间结构通过分割/层次化把查询降为 $O(\log n)$。实际选择需权衡构建时间、查询频率和动态更新成本。

## 常见误区

<Callout type="trap">
**现象 →** 认为暴力遍历够用，忽略空间结构。
**原因 →** 小规模数据时 O(n) 确实够快。
**修法 →** 图形学场景常有 10 万+ 三角形，暴力遍历帧率崩溃。空间结构是生产环境的必需品，不是过早优化。
</Callout>

<Callout type="trap">
**现象 →** 盲目选择 BVH 而不考虑场景特点。
**原因 →** BVH 名气大，以为万能。
**修法 →** BVH 适合射线查询，但范围查询 R-Tree 更优。游戏场景动态更新频繁时空间哈希更实用。根据查询类型和数据分布选结构。
</Callout>

<Exercises>
**问题**：几何体数据结构的核心目标是什么？

<Answer>
把暴力 O(n) 的空间查询降为 O(log n) 或 O(1)+k。通过空间分割（网格/树）或层次包围（BVH/R-Tree）组织几何对象，使查询只需访问少量候选而非全部。
</Answer>

**问题**：给定一个有 10 万三角形的静态场景用于光线追踪，应该选哪种空间结构？

<Answer>
BVH（用 SAH 构建）。理由：光线追踪以射线查询为主，BVH 射线遍历 O(log n)；场景静态，构建一次反复使用，SAH 构建虽慢但查询最优；GPU 友好，适合并行化。
</Answer>
</Exercises>
