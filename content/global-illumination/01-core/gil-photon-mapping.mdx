## 直觉：光子不是物理世界中的单个光量子

先预测：若每次把发射 photon 数翻倍，却保持每个 photon 携带的 flux 不变，图像会怎样？会越来越亮。Rendering 中的 photon 是 Monte Carlo energy packet；其功率必须除以发射样本数和生成概率。Photon map 存的是传输样本，不是可直接相加的“亮点”。

Photon mapping 在原书第 7.6 节作为 hybrid algorithm：第一遍从 lights 追踪 photon paths，在非 specular interaction 存 position、incoming direction 和 flux；第二遍从 camera 追踪，在 query point 用局部 surface density estimate 重建 incoming illumination。它特别适合 light 端容易生成而 camera 端难命中的 caustic path。

## 第一遍：发射与 photon tracing

<Term def="从发光体按功率选择端点和发射方向，沿散射路径正向传播能量包，并在可重建事件存储状态的过程">光子追踪</Term>（photon tracing）先选择 light $j$，再采 position $x_0$ 与 direction $\omega_0$。若总共发射 $N$ 个 photons，初始 packet flux 可写为：

$$
\Phi_0=\frac{L_e(x_0,\omega_0)\,G_e(x_0,\omega_0)}
{N\,p_L(j)p_A(x_0|j)p_\omega(\omega_0|x_0,j)}.
$$

$G_e$ 表示由 emission 参数化带来的 cosine/area 等因子，具体形式取决于 light API measure。Point、area、environment light 的 endpoint measure 不同，不能套用同一面积 PDF。

每次 surface interaction 按 BSDF component 和 direction 采样，更新 flux/throughput；Russian roulette 以 reflectance 分配 reflection、transmission、absorption，并补偿 continuation probability。通常不在 pure specular vertex 做 surface density storage，因为其方向分布是 delta，邻域平均不能表达镜面出射；但 path history 必须保留，以便下一个 diffuse hit 分类为 caustic。

## Photon 记录与空间索引

<Term def="保存能量样本的位置、入射方向、flux 和路径分类，并支持局部邻域查询的空间数据集">光子贴图</Term>（photon map）中的最小记录是 `(position, incomingDirection, flux, flags)`。Surface normal 可存储或由 geometry 重新查询；material id、path depth 和 previous-specular flag 用于过滤跨面/跨路径类污染。

Kd-tree 常按 photon positions 构建，支持 fixed-radius search 或 k-nearest neighbors。Build cost 约 $O(N\log N)$，balanced tree query 期望为 $O(\log N+k)$，但分布极端和半径过大会退化。索引只解决“找到附近点”，不负责判断这些点是否属于同一 smooth surface chart。

Query 过滤至少检查 normal orientation、material/surface identity、距离和 path map。薄墙两侧在 Euclidean 空间很近，若只按 position 查询会漏光；曲面上的 geodesic/visibility discontinuity 也会破坏平面 kernel 假设。

## Global map 与 caustic map

<GilPhotonMapSplitDiagram />

<Term def="只存储经历一个或多个 specular 事件后首次到达 diffuse 表面的 photon，用于重建高频焦散路径的专用贴图">焦散光子图</Term>对应 `L-S+-D` path prefix。因为 caustic 集中，通常分配更多 photons、较小 query radius，并可直接在 camera-visible diffuse point 估计。

Global photon map 存更一般的 indirect diffuse hits，用于粗略预估 incoming field 或支持 final gathering。Direct photon 常可用于 diagnostic，但正式估计一般由 next-event estimation 更低方差；若 direct map 与 NEE 都加，会重复 `L-D-E`。

Specular reflection/refraction 从 camera 端继续精确追踪；photon map 在后续 diffuse endpoint 重建。按 path class 划分让 caustic、direct、global 与 specular responsibilities 互斥，而不是“每个 map 都加一点”。

## 第二遍：surface radiance density estimate

<Term def="在查询点的切平面邻域内，对 photon flux 与 BSDF 进行核加权并除以有效面积，重建出射 radiance 的估计器">辐亮度密度估计</Term>对 query point $x$、方向 $\omega_o$ 写为：

$$
\widehat L_o(x,\omega_o)=
\frac{1}{Nh^2}\sum_{k=1}^{N_h}
K\!\left(\frac{\|x-X_k\|}{h}\right)
f_r(x,\omega_k,\omega_o)\Phi_k.
$$

这里假设二维 surface kernel $K$ 已归一化；若采用 uniform disk，常见形式等价于邻域总 flux 除以 $\pi h^2$。Cone filter 可令权重随距离线性下降并重新归一化：

$$
K_h(r)=\frac{3}{\pi h^2}\left(1-\frac{r}{h}\right),
\qquad 0\le r\le h.
$$

估计 incoming irradiance 后再乘 BRDF，或在 sum 内按每个 incoming direction 评估 BRDF，适用范围不同。对 non-Lambertian diffuse/glossy component，必须保留 photon direction；只存 flux density 会丢失角分布。

## Radius、bias、variance 与一致性

<GilPhotonRadiusDiagram />

<Term def="核密度估计的空间支持尺度；它同时控制邻域 photon 数、平滑偏差和随机方差">查询半径</Term> $h$ 越大，neighbor count 高且图像平滑，但跨越 illumination/visibility gradient 产生 blur/leak；$h$ 越小，locality 好但可能一个 photon 都找不到。

固定半径 photon mapping 有 bias。对平滑二维表面，典型一致性条件是：

$$
h_N\to0,
\qquad Nh_N^2\to\infty
\quad (N\to\infty).
$$

第一项让 smoothing bias 消失，第二项让邻域有效样本数增长以压低 variance。固定 $k$ 的 nearest-neighbor 半径会随机收缩，但还需分析 $k$ 是否增长；只增加 photons、固定 radius 会收敛到被 kernel 模糊的解。

边界处 kernel support 被截断，直接除以完整圆盘面积会低估；跨几何边界又可能高估。可使用 boundary-aware area normalization、surface chart、normal/material filtering 或缩小 radius，但每种修复都要报告它对 bias/variance 的影响。

## Final gathering 与 photon map

<Term def="在相机可见点从半球采样若干次间接查询，用 photon map 作为 incoming field 或引导，从而改善局部可见性与重建质量">最终聚集</Term>（final gathering）常把 caustic map 直接估计与 global map 间接查询组合：

1. Emission 与 specular chain 由 camera tracing；
2. Direct illumination 由 NEE/MIS；
3. Caustic term 从 caustic map density estimate；
4. Diffuse indirect 通过 gather rays，在次级 hit 查询 global map 或 low-frequency estimate。

Final gather 能恢复当前点到次级表面的 visibility 与方向变化，减少直接 global density estimate 的 blotch；但它不会自动消除次级 photon estimate 的 kernel bias。若 gather ray 又继续完整 path tracing，与 global map 责任重叠，需要明确截断/控制变量设计。

## 书后延伸：PPM 的年代边界

Progressive photon mapping（PPM）发表于 2008 年，晚于本项目锁定的 2006 第二版，因此不计入原书第 7.6 节复刻。它可作为后续延伸理解：先固定 camera visible points，多轮发射 photon batch，更新累计 flux 与逐步收缩的 radius，从而让内存不随总 photon 数增长并获得一致估计。

必须区分“原书 photon mapping”与“后来 PPM/SPPM”。不能用 PPM 替代本节的 kd-tree photon map、two-pass radiance estimate 与 final gathering，也不能把后来的结论写成原书内容。

## 可审计的两遍实现

```cpp
// Pass 1: photons carry flux already divided by emission PDFs and count.
for (int i = 0; i < photonCount; ++i) {
    PhotonState p = emitPhoton(lightSampler, sampler);
    while (scene.scatter(p, sampler)) {
        if (p.event.isNonSpecular()) maps.store(classify(p.history), p.record());
        if (!russianRoulette(p, sampler)) break;
    }
}
maps.buildKdTrees();

// Pass 2: camera responsibilities are explicitly partitioned.
L = emission(ray) + estimateDirectNee(ray);
L += causticMap.densityEstimate(hit, causticRadius);
L += finalGatherUsingGlobalMap(hit, sampler);
```

Debug output应包含 emitted flux sum、stored photon count by depth/map、query neighbor count、effective radius、kernel weight sum 和 rejected cross-surface photons。

## 常见误区

<Callout type="trap">
**现象 →** photon 数翻倍后图像亮度也翻倍。**原因 →** packet flux 没除以总发射数或 endpoint PDF。**修法 →** 对 emitted flux sum 做与 $N$ 无关的守恒测试。
</Callout>

<Callout type="trap">
**现象 →** 薄墙另一侧出现漏光。**原因 →** kd-tree 只按 Euclidean distance 找邻居，kernel 跨越不同 surface chart。**修法 →** 用法线、材质/primitive、局部平面与边界过滤，并报告有效 kernel area。
</Callout>

<Callout type="trap">
**现象 →** 宣称固定 radius 下增加 photons 会得到精确点值。**原因 →** variance 降低但 smoothing bias 保留。**修法 →** 同时给出 $h_N\to0$ 与 $Nh_N^2\to\infty$ 的参数 schedule。
</Callout>

## 练习

<Exercises>

**问题 1：为什么 caustic photon map 只在第一次 non-specular hit 存储？**

<Answer>
它要表示 `L-S+-D` 的高频焦散路径：photon 先经历一个或多个 specular event，再首次落到可密度重建的 diffuse/non-specular surface。后续 diffuse bounce 属于更低频 global indirect，可进入 global map，避免路径责任混乱。
</Answer>

**问题 2：uniform disk density estimate 的主要 bias 来源是什么？**

<Answer>
它假设半径内 radiance/geometry/visibility 近似平滑，用邻域平均替代点值；在 gradient、shadow boundary、surface boundary 或薄几何处会 blur/leak。有限半径即使 photon 无限多也保留该 smoothing bias。
</Answer>

**问题 3：kd-tree 查询返回的近邻为什么仍需过滤？**

<Answer>
Kd-tree 只保证三维位置近，不保证同一表面侧、法线方向、材质、路径类别或可见区域。跨薄墙/折角 photon 会污染局部 surface density，需要 normal、primitive/material、tangent-plane 与 map-class 条件。
</Answer>

**问题 4：PPM 为什么不能写成 2006 第二版原书内容？**

<Answer>
PPM 在 2008 年发表，时间晚于本书第二版。它是 photon mapping 的重要后续扩展，可用于现代延伸，但本页的原书责任仍是 two-pass photon tracing、map、density estimate、caustic/global partition 与 final gathering。
</Answer>

</Exercises>

## 小结

光子映射把 difficult light paths 转成两遍估计：light pass 以正确 endpoint PDF 发射并追踪能量，按路径历史建立 caustic/global photon maps；camera pass 通过 kd-tree 邻域与归一 kernel 重建 radiance，并用 final gathering 改善可见端质量。半径、边界和 path overlap 决定 bias，样本数与 proposal 决定 variance；PPM 是 2008 年后的扩展，不能倒灌为 2006 原书主体。
