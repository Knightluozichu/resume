本页的不变量是：A Class Library for Global Illumination的输入、公式中间量、输出与恢复结果可用同一基线复算。反例“类层次隐藏路径概率，或对象生命周期使缓存引用失效”只改变一个条件，因而正常、故障与恢复三次运行应能用同一输入直接比较。

## 原书单元与独立机制解释

### A Class Library for Global Illumination

path node classes 保存路径顶点的几何与概率状态，light source sampling classes 封装光源生成策略，global illumination api 负责场景、积分器和输出的稳定边界。接口必须携带PDF与测度，不能只返回方向。

本单元的正式坐标是path node classes、light source sampling classes、global illumination api。验证A Class Library for Global Illumination时，先制造“类层次隐藏路径概率，或对象生命周期使缓存引用失效”，再检查类型合同、正反向PDF、所有权、序列化和最小场景测试能否把错误定位到用类型与接口把路径、采样器和传感器组合成可扩展渲染器的首个分叉。

$$
PathNode=(x,n,\omega,\beta,p_f,p_r,event)
$$

## 最小可重现实验

```cpp
struct PathNode {
  Point3 p; Normal3 n; Spectrum throughput;
  double pdfForward, pdfReverse;
  ScatteringEvent event;
};
PathNode extend(const PathNode&, const Sample&);
```

运行A Class Library for Global Illumination时固定随机种子、输入几何、坐标约定和数值精度；记录编译命令或算法版本、输出摘要与失败条件。实验输出若依赖隐藏全局状态，必须先消除该依赖再比较。

<Callout type="trap" title="本页核心误区">
  类层次隐藏路径概率，或对象生命周期使缓存引用失效。这个错误会破坏“A Class Library for Global Illumination的输入、公式中间量、输出与恢复结果可用同一基线复算”，应先由类型合同、正反向PDF、所有权、序列化和最小场景测试定位，再讨论性能或视觉风格。
</Callout>

<Callout type="trap" title="不要把别的图形API模板套进来">
  A Class Library for Global Illumination只解释用类型与接口把路径、采样器和传感器组合成可扩展渲染器。若原始资料讨论纯C++路径追踪、OpenGL时代图形学或光传输积分，就不能用VkBuffer、Fence与Semaphore替代相应的几何、光栅化或蒙特卡洛机制。
</Callout>

## 本章回顾

掌握A Class Library for Global Illumination意味着能将“用类型与接口把路径、采样器和传感器组合成可扩展渲染器”写成明确公式或算法，能操作正式坐标，能制造“类层次隐藏路径概率，或对象生命周期使缓存引用失效”，还能凭类型合同、正反向PDF、所有权、序列化和最小场景测试恢复同输入结果，而不是把一段Vulkan生命周期模板换上本章标题。
