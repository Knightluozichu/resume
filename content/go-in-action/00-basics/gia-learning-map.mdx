## 直觉引入

如果把学 Go 比作造一辆车，核心类型（切片、map、struct）是底盘和发动机——承载所有功能；并发模型（goroutine、channel）是变速箱和四驱系统——这是 Go 区别于其他语言的灵魂；工程实践（测试、打包、标准库）是流水线和质检——让车能大规模生产且可靠出厂。

Go 的设计者有一个执念：**语言应该服务于工程协作，而非炫技**。C++ 特性繁多但编译慢、协作难；Java 冗长且框架沉重；Go 选择了「少即是多」——25 个关键字、无继承、快速编译、内置并发原语。这种克制换来的是：新人一周上手、大团队协作顺畅、单二进制部署。

<Term def="Go 追求简洁与工程效率，核心原则：少即是多、快速编译、原生并发、工程务实。">

- **少即是多**：25 个关键字，无继承无泛型（1.18 前），显式优于隐式

<Stepper>
<Step title="第一板块：Go 入门">
理解 Go 为何这样设计：少即是多不是简陋，而是用最少的特性组合出最强大的能力。25 个关键字覆盖了流程控制、类型声明、并发原语。无继承意味着用组合+接口实现复用，避免继承链的脆弱。这一板块建立「Go 思维」——不要套用 Java/C++ 的面向对象范式。
</Step>
<Step title="第二板块：核心类型">
切片是 Go 最常用的类型——它是引用类型，ptr+len+cap 三元组指向底层数组。map 是哈希表引用，零值 nil 不能直接写。struct 是值类型，用指针避免复制或修改原值。掌握这三者 + interface，你就掌握了 Go 90% 的类型系统。
</Step>
<Step title="第三板块：并发模型">
goroutine 是轻量协程（2KB 栈），用 go 关键字启动。channel 实现 CSP——「不要通过共享内存通信，而要通过通信共享内存」。无缓冲 channel 同步握手，有缓冲 channel 异步解耦。三大模式：worker pool、pipeline、fan-out/fan-in。这是 Go 的灵魂板块。
</Step>
<Step title="第四板块：工程实践">
Go 把工程工具链内置：testing 包无需框架、go module 管理依赖、go build 交叉编译单二进制。标准库「电池齐全」——net/http 一个包就能写 Web 服务。context.Context 贯穿调用链管理超时与取消。这一板块让 Go 代码从「能跑」变成「能上线」。
</Step>
</Stepper>

## 代码对照

```go
// 切片：引用类型，append 返回新切片
nums := []int{1, 2, 3}
nums = append(nums, 4) // 超容时分配新底层数组

// map：引用类型，需 make 初始化
scores := make(map[string]int)
scores["Alice"] = 90
if v, ok := scores["Bob"]; !ok {
    fmt.Println("Bob 不存在") // ok 模式检查存在性
}

// struct：值类型
type User struct {
    Name string
    Age  int
}
u := User{Name: "Alice", Age: 30}
uPtr := &u // 指针避免复制

// goroutine + channel：CSP 并发
ch := make(chan int)
go func() {
    ch <- 42 // 发送
}()
fmt.Println(<-ch) // 接收：42

// interface 隐式实现
type Speaker interface{ Speak() string }
func (u User) Speak() string { return "Hi, " + u.Name }
// User 自动满足 Speaker，无需显式声明 implements
```

## 常见误区

<Callout type="trap">
**误区：把 Go 当「简化版 Java」学**
Go 没有继承、没有泛型（1.18 前）、没有异常、没有构造函数。套用 Java 的类继承思维会处处碰壁。Go 的面向对象是「struct + interface 组合」——用嵌入（embedding）替代继承，用隐式接口替代 implements。学 Go 要先接受「少」，再发现「少」带来的清晰与高效。
</Callout>

<Callout type="trap">
**误区：跳过并发直接写 CRUD**
并发是 Go 的灵魂，跳过它等于只学了 Go 的一半。很多 Go 库（net/http、database/sql）都基于 goroutine + channel 设计。不理解并发，就读不懂标准库的实现，也写不出高性能服务。即使你只写 CRUD，理解 context 的取消传播也至关重要——否则 goroutine 泄漏会成为线上事故。
</Callout>

<Exercises>
**问题 1**：Go 全书四大板块的顺序是什么？为什么要按这个顺序学习？

<Answer>
四大板块：Go 入门（环境与哲学）→ 核心类型（切片、map、struct）→ 并发模型（goroutine、channel、并发模式）→ 工程实践（测试、打包、标准库）。

按此顺序学习因为建立了递进能力链：核心类型是承载所有业务逻辑的底盘（不懂切片/map 无法写任何 Go 代码），并发模型是 Go 区别于其他语言的灵魂（不懂 goroutine/channel 就浪费了 Go 的核心价值），工程实践是从能跑到能上线的保障（测试、模块、标准库是生产级必需）。每一层都建立在前一层之上。
</Answer>

**问题 2**：Go 的「少即是多」哲学体现在哪些方面？这种克制带来了什么好处？

<Answer>
体现：25 个关键字（C 有 32，Java 有 50+）；无继承（用组合+嵌入替代）；1.18 前无泛型（用 interface 替代）；无异常（用 error 返回值）；无构造函数（用普通函数）；gofmt 强制统一格式（无格式争论）。

好处：1. 学习曲线平缓——新人一周上手；2. 大团队协作顺畅——代码风格统一，读别人的代码像读自己的；3. 编译极快——无头文件、依赖明确，秒级构建百万行项目；4. 工具链统一——go build/test/fmt/vet/mod 一套命令搞定。克制换来的是工程效率的最大化——这正是 Go 为大规模后端服务而生的设计目标。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="少即是多">
Go 的核心哲学：用最少的语言特性组合出最强大的工程能力。25 个关键字、无继承、无异常——克制换来学习曲线平缓、编译快、协作顺畅。
</GlossaryItem>
<GlossaryItem term="CSP 模型">
Communicating Sequential Processes，Go 并发的理论基础。「不要通过共享内存通信，而要通过通信共享内存」——goroutine 之间通过 channel 传递消息，而非共享变量加锁。
</GlossaryItem>
<GlossaryItem term="原生并发">
Go 把并发作为语言一等公民：go 关键字启动 goroutine，channel 是内置类型。无需第三方库或复杂 API，并发就像 if/for 一样自然。
</GlossaryItem>
<GlossaryItem term="单二进制部署">
Go 编译产出单一可执行文件，包含所有依赖（无动态链接）。CGO_ENABLED=0 可纯静态编译，交叉编译只需 GOOS/GOARCH。这让 Go 部署极简——一个文件扔上去就跑。
</GlossaryItem>
</Glossary>
