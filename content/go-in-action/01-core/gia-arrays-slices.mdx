## 直觉引入

数组像一排固定数量的储物柜——你定做时说好 5 个柜子，就不能变成 6 个，而且「复制」是把每个柜子的内容都抄一遍。切片像一个「窗口」——它指向一排柜子中的某几个，可以滑动（len）和扩大视野（cap），「复制」只是复制了窗口的位置信息而非柜子内容。

关键洞察：切片不存数据，它只是「指向」底层数组的 ptr+len+cap。两个切片可能共享同一底层数组——通过一个切片修改会影响另一个。这是切片高效的根源，也是最容易踩坑的地方。

## 概念讲解

### 数组：值类型

<Term def="数组 [N]T 是固定长度、值类型的序列。长度是类型的一部分，[5]int 和 [6]int 是不同类型。赋值和传参会复制全部元素。">

```go
var a [5]int          // 零值 [0,0,0,0,0]
b := [3]int{1, 2, 3}
c := b                // 复制全部元素，b 和 c 独立
c[0] = 99             // 不影响 b
```

数组在实际 Go 代码中很少直接使用——长度固定太不灵活。大多数场景用切片。数组主要用于：固定大小缓冲区、矩阵运算、作为切片的底层数组。

</Term>

### 切片：引用类型

<Term def="切片 []T 是动态长度引用类型，由 ptr（指向底层数组）+ len（当前长度）+ cap（容量）三部分组成。零值 nil 可安全读取长度。">

```go
s := make([]int, 3, 5) // len=3, cap=5
s2 := []int{1, 2, 3}
var s3 []int           // nil 切片，len=0
```

切片赋值或传参只复制三元组（ptr+len+cap），共享同一底层数组。修改切片元素会影响所有共享该底层数组的切片。

</Term>

### append 与扩容

<Term def="append 向切片追加元素。若 len < cap，直接写入底层数组；若 len == cap，分配新底层数组（扩容后复制），返回新切片。必须接收 append 的返回值。">

扩容规则：cap < 256 时翻倍，cap >= 256 时约 1.25 倍增长。扩容后新切片指向新底层数组，原切片不变——这是 `s = append(s, x)` 必须接收返回值的原因。

</Term>

切片 s := a[1:3] 创建一个指向 a 底层数组的新切片。修改 s[0] 会改变 a[1]——它们共享底层数组。这是切片高效的根源（零拷贝视图），也是陷阱来源。用 copy(s, src) 创建独立副本避免共享。
</Step>
<Step title="步骤2：掌握 append 的返回值">

</Step>
<Step title="步骤3：用 copy 切断共享">
当你需要独立副本时：dst := make([]int, len(src)); copy(dst, src)。或用 copy 切断子切片与原数组的共享。注意 copy 返回实际复制的元素数（取 src 和 dst len 的较小值）。
</Step>

## 代码对照

```go
// 数组：值类型，长度是类型一部分
a := [3]int{1, 2, 3}
b := a       // 复制全部
b[0] = 99    // a[0] 仍是 1

// 切片：引用类型
s1 := []int{1, 2, 3, 4, 5}
s2 := s1[1:3]   // s2 = [2, 3]，共享 s1 底层数组
s2[0] = 99      // s1[1] 变成 99！共享底层数组

// 独立副本
s3 := make([]int, len(s1))
copy(s3, s1)    // s3 独立于 s1

// append 扩容
s := make([]int, 0, 3)
s = append(s, 1, 2, 3) // len=3, cap=3，未扩容
s = append(s, 4)        // len=4, cap=6（翻倍），新底层数组

// 三索引切片（限制 cap，防止 append 污染共享数组）
s4 := s1[1:3:3] // len=2, cap=2，append 必扩容不影响 s1

// 遍历
for i, v := range s1 {
    fmt.Printf("%d: %d\n", i, v)
}
```

## 常见误区

<Callout type="trap">
**误区：忘记接收 append 的返回值**
`append(s, x)` 不修改原切片变量 s——它返回新切片。写 `append(s, x)` 不接收，s 不变，数据丢失。这是 Go 最常见的 bug 之一。规则：永远 `s = append(s, x)`。append 是「函数」不是「方法」，它没有副作用，必须用返回值。
</Callout>

<Callout type="trap">
**误区：子切片共享底层数组导致意外修改**
`s2 := s1[1:3]; s2[0] = 99` 会修改 s1[1]，因为共享底层数组。如果你不希望子切片影响原切片，用 copy 创建独立副本，或用三索引切片 `s1[1:3:3]` 限制 cap 防止 append 污染。在大切片上做子切片操作时尤其要注意——这个 bug 不会立即暴露，可能在后续读取时才出错。
</Callout>

<Exercises>
**问题 1**：以下代码输出什么？为什么？

```go
s := []int{1, 2, 3, 4, 5}
sub := s[1:3]
sub = append(sub, 99)
fmt.Println(s, sub)
```

<Answer>
输出：s = [1 2 3 99 5]，sub = [2 3 99]。

分析：sub := s[1:3] 创建子切片，sub 的底层数组就是 s 的底层数组，sub 的 ptr 指向 s[1]，len=2，cap=4（从 s[1] 到数组末尾）。append(sub, 99) 时 len(2) < cap(4)，无需扩容，直接写入底层数组的第 3 个位置（即 s[3]）。所以 s[3] 被改成 99，sub 变成 [2, 3, 99]。

这就是共享底层数组的陷阱——通过 sub 的 append 污染了 s 的数据。要避免：用三索引切片 sub := s[1:3:3]（cap=2），append 时 len==cap 必扩容，分配新数组不影响 s。
</Answer>

**问题 2**：为什么 `s = append(s, x)` 必须接收返回值？append 不修改原切片吗？

<Answer>
append 不修改原切片变量 s，因为切片是值类型（ptr+len+cap 三元组）。append 接收的是 s 的副本，它可能：1. len < cap 时，在底层数组写入并返回 len+1 的新三元组（ptr 不变）；2. len == cap 时，分配新底层数组、复制、写入，返回 ptr 指向新数组的新三元组。

两种情况都返回新切片值。如果你不接收 `s = append(s, x)`，s 仍是原来的三元组——情况 1 下你看不到新长度，情况 2 下数据写到了被丢弃的新数组。所以必须接收返回值。Go 没有「引用传递」，切片虽共享底层数组但三元组本身是值传递——append 无法修改调用方的 s 变量。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="切片（Slice）">
[]T 动态长度引用类型，由 ptr（指向底层数组）+ len（长度）+ cap（容量）组成。赋值/传参共享底层数组。零值 nil 可安全读取长度。Go 最常用的序列类型。
</GlossaryItem>
<GlossaryItem term="底层数组">
切片实际存储数据的连续内存。多个切片可共享同一底层数组（通过子切片）。修改共享底层数组的切片元素会影响其他切片——这是切片高效与陷阱的根源。
</GlossaryItem>
<GlossaryItem term="append 扩容">
append 在 len==cap 时分配新底层数组：cap<256 翻倍，cap>=256 约 1.25 倍。扩容后切片指向新数组，原切片不变。必须接收 append 返回值。
</GlossaryItem>
<GlossaryItem term="三索引切片">
s[low:high:max] 限制切片的 cap 为 max-low。用于防止 append 子切片时污染共享底层数组——cap 被限制后 append 必扩容，分配新数组不影响原切片。
</GlossaryItem>
</Glossary>
