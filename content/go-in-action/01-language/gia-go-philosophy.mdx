## 从大型软件的反馈速度开始
先预测：快速编译、goroutine和GC是否意味着程序自然正确且资源无泄漏？不是，它们只改变反馈、调度和内存回收方式。

Go语言介绍不是口号列表。它针对编译慢、依赖复杂、网络并发与内存管理成本，选择小语法、快速构建、goroutine、静态类型和GC。<Term def="从修改源码到得到格式、诊断、测试和二进制结果所需的反馈周期。">development feedback loop</Term>是Go工程生产力的第一证据。

## 开发速度与统一工具

编译器拒绝未使用import和变量，`gofmt`统一格式，`go test`与`go build`共享package模型。<Term def="语言发行版内置格式、文档、测试、构建与诊断命令的工程约定。">standard toolchain contract</Term>减少项目间配置差异，但依赖和生成工具仍需锁定。

```go
package main
import "fmt"
func main() { fmt.Println("Hello, Go") }
```

## 并发不是自动并行

Goroutine是由运行时调度的独立工作，channel提供通信与同步；是否并行还取决于可用逻辑处理器和工作性质。<Term def="运行时把goroutine映射到OS线程与逻辑处理器的调度责任。">runtime scheduling boundary</Term>不能成为正确性依赖。

```go
done := make(chan struct{})
go func() { close(done) }()
<-done
```

## 类型系统与组合

Go静态知道每个值的类型和表示，用方法与隐式接口满足实现多态，用嵌入与组合代替类继承。<Term def="具体类型只要拥有接口要求的方法集，就自动满足接口的关系。">implicit interface satisfaction</Term>使实现包不需依赖接口包，却要求接口保持小而聚焦。

## 内存管理与资源边界

逃逸分析决定值可否留栈，GC回收不可达堆对象。<Term def="由编译器决定分配位置、由运行时回收不可达内存的管理模型。">managed memory boundary</Term>不负责关闭文件、停止goroutine或提交业务事务，这些仍要显式生命周期。

```go
func label(id int) *string {
    value := fmt.Sprintf("id-%d", id)
    return &value
}
```

## Hello Go与Playground

本地执行记录`go version`、module、命令、stdout和status。Playground适合共享小例子，但时间、网络、文件和toolchain版本受限制。<Term def="示例所在toolchain、操作系统、网络、文件和时间能力的执行范围。">example environment envelope</Term>决定结果能否迁移生产。

<Callout type="trap" title="goroutine很轻所以数量无限">每个goroutine仍占栈、调度、引用对象和外部连接；没有取消和背压会耗尽资源。</Callout>

## 本章回顾

本章覆盖现代编程挑战、开发速度、并发、Go语言的类型系统、内存管理、Hello Go和Go Playground。每项便利都有边界，必须以toolchain、runtime和资源证据验证。

<Exercises>
**问题 1：GC不负责哪些资源？**<Answer>文件、socket、锁、goroutine、事务和业务句柄都需显式关闭或取消。</Answer>
**问题 2：如何证明goroutine真的并行？**<Answer>固定GOMAXPROCS和CPU工作负载，使用trace或profile观察多个处理器同时执行；仅启动goroutine只能证明并发结构。</Answer>
**问题 3：Playground结果为何不能直接代表本地？**<Answer>它限制网络、文件、时间和版本，必须在目标toolchain与OS复跑。</Answer>
</Exercises>
