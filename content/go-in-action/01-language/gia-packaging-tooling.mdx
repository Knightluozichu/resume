## 从目录何时成为包开始
先预测：把两个相互import的包放进同一仓库能否消除循环？不能；依赖图按package而不是仓库判断。

包与工具把源码组织成可复用语义单元。目录内普通Go文件通常声明同一package，导出标识符首字母大写，main包产生可执行入口。要求import graph无环。


## 包命名与Main包

包名应短、清楚、描述能力，调用时自然读成`http.Client`；不要重复路径或用`util`掩盖职责。Main只装配。在module替换和major版本中尤其重要。

```go
package clock
func Now() time.Time { return time.Now() }
```

## Import与Init

编译器按依赖图加载包，包级变量先初始化，再按文件规则运行init，最后进入main。不应承载隐藏网络调用和不可测试业务。

```go
import jsoniter "encoding/json"
var decode = jsoniter.NewDecoder
```

## Go命令与开发工具

`go fmt`统一格式，`go vet`发现可疑构造，`go doc`读取API，`go test`验证，`go build`产物。应在本地和CI一致。

```sh
go fmt ./...
go vet ./...
go test ./...
go build ./...
```


## 协作、仓库与依赖管理

原书介绍remote import、vendor和gb，反映2015年的依赖环境；现代代码以module path、go.mod与go.sum解析版本，可选择vendor冻结源码。必须区分原书历史工具与今天可复现实践。


## 把工具输出变成合并证据

工具命令只有进入可重复流程才形成门禁：固定Go版本，在干净检出上依次执行格式检查、`go vet`、`go test`和`go build`，并让任一步非零状态阻止合并。文档检查还要从包外读取导出API，确认命名和示例对调用者成立。这样本地通过、CI失败时，可以沿版本、命令、依赖和日志逐层定位差异，而不是把“我的机器能编译”当成包质量结论。
