## 从类型决定多少内存开始
先预测：把`(*Worker)(nil)`赋给接口后，接口是否等于nil？不等，因为动态类型已经是`*Worker`。
Go语言的类型系统告诉编译器值的大小、表示和可用操作。不会因底层类型相同就自动互赋。


## 用户定义类型
`type Duration int64`建立独立类型；别名则保持同一身份。决定API是否表达单位。

```go
type UserID int64
var id UserID = 7
```

## 方法与Receiver
值receiver收到副本，指针receiver可修改原值并避免大复制。影响接口满足；选择应在同一类型上一致。

```go
type Counter int
func (c *Counter) Inc() { (*c)++ }
```

编译器可在可寻址值上自动补取址，让`value.Inc()`写法成立，但这不会把指针receiver方法加入`Counter`的方法集。接口满足应按静态方法集判断；调用语法的便利不能替代类型关系证明。

## 指针与值
内置类型、引用类型和struct有不同本质。Slice、map、channel复制header后共享运行时数据；struct默认整值复制。不能只以性能决定。

## 接口与多态
接口由方法集合组成，具体类型隐式满足。解释typed nil陷阱。

```go
type Reader interface { Read([]byte) (int, error) }
```


## 类型嵌入与组合
嵌入提升字段和方法，但不是继承。支持组合变化。

## 标识符导出与未导出
首字母大写跨包导出，小写只在包内。要求公开API最小稳定。


## 验收实验：方法集与Nil矩阵
为一个struct分别定义值receiver查询和指针receiver修改，列出T与*T满足哪些接口，再把值、指针、nil指针和nil接口依次传入。随后嵌入该类型，制造同名方法冲突并观察显式选择。记录每种调用是否复制、能否修改、动态类型是什么、标识符是否跨包可见。
