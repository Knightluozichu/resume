## 从并发机制到可复用生命周期开始
先预测：worker阻塞在外部I/O时，仅关闭任务channel能否退出？不能，还需要取消、timeout或关闭底层资源。
并发模式不是更多channel语法，而是对停止和资源责任的封装。<Term def="把启动、超时、取消、资源归还、队列关闭与等待封装为可复用结构。">concurrency pattern contract</Term>。

## Runner：控制程序寿命
Runner顺序执行任务，同时select完成、timeout与interrupt。<Term def="完成、超时和系统中断三类事件竞争决定退出的协议。">runner termination protocol</Term>必须停止接收新工作并等待已启动任务。

```go
select { case <-done: case <-timeout: case <-interrupt: }
```

## Pooling：借出有限资源
Buffered channel保存可用资源，Acquire借出，Release归还。<Term def="成功获取后调用者恰好执行一次归还或销毁的责任。">resource return obligation</Term>防止池枯竭。

```go
resource := <-pool
defer func(){ pool <- resource }()
```

## 损坏资源与关闭
使用失败的连接不应归还；Pool关闭后拒绝新Acquire并关闭空闲资源。<Term def="区分健康归还、损坏销毁和池整体关闭的资源状态机。">pool health state</Term>要求并发close幂等。

<GiaPoolLab />

## Work：固定Goroutine工作池
固定worker从队列消费，限制并发度并Wait。<Term def="任务提交、worker消费、队列关闭、错误和完成等待组成的工作协议。">worker pool lifecycle</Term>要处理worker panic和生产者提前退出。

```go
for i := 0; i < workers; i++ { go run(jobs, &wg) }
close(jobs); wg.Wait()
```

## 验收实验：在每个边界注入停止
Runner分别注入完成、timeout和interrupt；Pool测试创建失败、使用损坏、重复Release、Close后Acquire；Work测试空队列、队列满、worker panic和生产者提前结束。每次记录谁拥有资源、谁发送停止、谁关闭channel、谁等待完成，确保没有goroutine或句柄遗留。

## 模式选择
<Term def="按程序寿命、资源稀缺或任务并发上限选择Runner、Pool或Work。">pattern selection rule</Term>。三者可组合，但关闭顺序必须从入口到worker再到资源池。

<Callout type="trap" title="把资源放回channel就完成Pool">还需损坏、double release、close与Acquire竞争规则。</Callout>
<Callout type="trap" title="关闭任务队列会自动停止所有worker">Worker还可能阻塞外部I/O，需要取消或timeout。</Callout>

## 本章回顾
本章覆盖并发模式、Runner、程序生命周期超时与中断、Pooling、可复用资源池、Work和goroutine工作池。三种模式最终都必须回答正常、失败和关闭路径由谁收束，不能只展示启动代码。
<Exercises>
**问题 1：Runner超时后还要做什么？**<Answer>停止新任务并等待或取消已启动任务。</Answer>
**问题 2：损坏资源如何处理？**<Answer>销毁而非归还，并按策略补充。</Answer>
**问题 3：如何停止worker？**<Answer>关闭任务源、发取消并Wait。</Answer>
</Exercises>
