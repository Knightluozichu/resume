## 从独立函数怎样推进开始
先预测：两个goroutine无同步递增共享计数器，最终值是否稳定？不稳定，并且属于data race。
并发允许函数独立推进，并行允许同时执行。阻止把goroutine数量当吞吐。


## Goroutine与Go调度器
G是goroutine，M是OS线程，P持有执行Go代码所需资源。调度次序不承诺。

```go
go func() { work() }()
```

## 竞态条件
无同步共享读写且至少一方写会形成data race。用`go test -race ./...`获取证据。

```sh
go test -race ./...
```

## 原子函数与互斥锁
Atomic适合单值计数或flag，复合状态在同一Mutex临界区维护。还需统一锁顺序。

同步不仅避免两个写操作撞在一起，还建立内存可见性的先后关系。若一个goroutine写入数据后只修改普通布尔值，另一个goroutine看到布尔值时仍不能据此推导数据已可见；锁、原子操作或channel收发才提供可依赖的同步边。


## Channel与CSP
Channel传值并同步goroutine。要求发送方关闭，接收方不关闭。

```go
values := make(chan int, 1)
values <- 7
close(values)
fmt.Println(<-values)
```

## 无缓冲与有缓冲
无缓冲发送接收握手，有缓冲在容量内解耦；容量改变阻塞点，不消除背压与关闭。必须显式。


## 验收实验：同一任务三种同步
先让两个goroutine无同步更新计数并保存race报告；再分别用atomic和Mutex修复，说明atomic只覆盖单值，而锁可保护复合状态。最后改成channel转移owner，分别设容量0、1和有界值，记录发送阻塞点、关闭者与退出路径。三种实现结果相同，证明方式和背压位置不同。
