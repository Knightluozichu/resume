## 从标准库为何值得依赖开始
先预测：Reader返回`n > 0`同时返回EOF时，是否丢弃这n字节？不能，应先处理数据再解释结束。
标准库随Go发布、遵守兼容承诺并持续测试。仍需核对当前版本。


## 文档与源代码
`go doc`看API，源码解释性能和错误细节，但未导出实现不是长期契约。。

```sh
go doc io.Reader
go env GOROOT
```

## 日志
日志记录事件、稳定字段和上下文；库返回error，main决定fatal退出。禁止泄露secret。

```go
log.Printf("feed=%q status=%d", name, status)
```

## JSON编码与解码
Decoder流式读取，struct tag映射字段。应在入口明确。

```go
dec := json.NewDecoder(r)
dec.DisallowUnknownFields()
if err := dec.Decode(&value); err != nil { return err }
```


## Input与Output
Reader和Writer小接口让包互操作。支持Copy、buffer、gzip、hash与network组合。

## EOF、短写与Close
Reader可同时返回n大于0和error；Writer可能partial write。。Close错误可能是flush失败，不能总忽略。


## 验收实验：故障Reader与Writer
实现一次只返回少量字节、最后同时返回数据和EOF的Reader，再实现partial write后报错的Writer；让io.Copy和自写循环处理并比较。JSON测试未知字段、两个顶层值、超大数字和空body；日志写入buffer并断言secret被遮蔽。由此证明包间互操作在短读写和错误时仍成立。
