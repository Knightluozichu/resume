## 从测试应在开发期间运行开始
先预测：一次benchmark快5%能否认定优化？不能，必须多次采样、统计比较并确认语义等价。
测试和性能不是结束阶段。随`go test`进入日常反馈。


## 单元与表驱动测试
Test函数接收`*testing.T`，表驱动case减少重复，subtest提供名字与隔离。要避免循环变量捕获和共享状态。

```go
func TestAdd(t *testing.T) {
    if got := Add(2, 3); got != 5 { t.Fatalf("got %d", got) }
}
```

## HTTP测试
Recorder直接测handler，Server提供真实本地HTTP给client。选择取决于要测试哪一侧。

```go
rr := httptest.NewRecorder()
handler.ServeHTTP(rr, httptest.NewRequest("GET", "/", nil))
```

## Example与包文档
Example可被go test执行，`Output:`注释比较stdout并进入文档。不应依赖随机顺序和时间。


## Benchmark
Benchmark循环`b.N`，setup移出计时区，结果必须被消费。不是跑一次的数字。

```go
func BenchmarkFormat(b *testing.B) {
    for i := 0; i < b.N; i++ { sink = strconv.Itoa(i) }
}
```

## 参数与统计比较
使用`-bench`、`-benchmem`、`-count`，再以benchstat比较分布。避免把setup和GC噪声误作改进。

报告中的ns/op描述单位操作耗时，B/op和allocs/op暴露分配成本；三者可能朝不同方向变化。比较前应保存CPU、Go版本、样本次数和输入规模，先确认功能测试等价，再判断差异是否超过噪声区间。


## 验收实验：从失败消息到统计结论
为解析函数建立正常、空值、坏格式和边界表格，故意制造失败以检查case名称和差异；对HTTP同时测试handler与client边界；让Example进入文档。基准运行多次，报告allocs/op并用benchstat比较。若新实现语义不同或setup进入计时，性能数字无效。
