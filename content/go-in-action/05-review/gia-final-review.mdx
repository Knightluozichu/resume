## 从故障应该回哪一章开始
先预测：服务测试通过但退出挂住，应先查第6章goroutine和channel，再查第7章模式关闭与第8章I/O资源。
总复习把9章变成诊断索引。：包构建查第3章，append别名查第4章，typed nil查第5章，race查第6章，泄漏查第7章。


## 构建层：第1至3章
语言目标、完整search程序、package和toolchain共同产生二进制。要求clean build。

```sh
go fmt ./... && go vet ./... && go test ./... && go build ./...
```

## 建模层：第4至5章
数组、slice、map决定复制共享，类型、方法、接口和嵌入决定行为。。

```go
type Matcher interface { Search(Feed, string) ([]Result, error) }
```

## 运行层：第6至8章
Goroutine、锁、channel与模式控制并发，Reader/Writer、JSON和log控制边界。必须覆盖timeout和interrupt。

```go
ctx, cancel := context.WithTimeout(context.Background(), time.Second)
defer cancel()
```

## 验证层：第9章
Unit、httptest、Example、benchmark与race提供不同证据。不能被覆盖率单独替代。


## 综合项目
RSS搜索服务用main装配、search包建模、matcher扩展、bounded worker控制并发、context取消、Reader解码、错误返回和稳定输出。。


## 验收实验：删除缓存后重建并关闭
从clean checkout执行fmt、vet、test、race和build；启动本地feed，让一条成功、一条超时、一条返回坏JSON，确认错误含feed坐标。随后取消context、关闭生产、等待worker并检查临时资源。最后对matcher和JSON路径做多次benchmark。只有构建、功能、失败、竞态、关闭和性能证据同时成立才通过。


## 本章回顾
9章统一为构建、建模、运行和验证。最终搜索服务必须能解释数据共享、接口、goroutine、资源、I/O、错误和性能证据。
