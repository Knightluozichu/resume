## 为什么学习地图必须以原书 13 章为骨架

《The Go Programming Language》并不是“语法、函数、接口、并发”几张概览卡。13章从可执行程序和数据表示开始，经过函数/方法/接口，再分开讨论通信式并发与共享变量同步，最后进入包工具、测试、反射和unsafe/cgo。省掉任何一层，后续问题都会失去前置解释。

<Term def="以作者官方 13 章为唯一章节骨架，每章对齐完整目录单元、专属图解、练习与复习题；地图/总复习只导航和综合，不替代正文。">official chapter path</Term>

先预测：interface containing nil pointer为什么必须先理解method set和dynamic pair，goroutine leak为什么不是“channel语法”问题，reflection decoder为何依赖composite types和pointer addressability，以及unsafe优化为何最后才学。

### 阶段一：第 1–4 章，程序与数据

1. **Tutorial** 用命令行、dup、GIF、HTTP fetch/server建立输入-转换-输出骨架。
2. **Program Structure** 定义names、declarations、variables、assignments、types、packages/files、scope。
3. **Basic Data Types** 给出integers、floats、complex、bool、UTF-8 strings、constants的值域与运算。
4. **Composite Types** 处理array copy、slice alias、map membership、struct shape、JSON/template boundary。

<Term def="第1–4章共同建立的value、type、scope、copy/alias、shape与encoding模型；所有receiver、interface、channel和reflection判断都依赖它。">value and ownership foundation</Term>

阶段验收不是“会写变量”，而是看到一个value能回答：它的static/dynamic type、zero value、copy后是否alias、谁能mutation、何时失效、跨JSON/template后shape如何变化。

### 阶段二：第 5–7 章，函数到行为契约

5. **Functions** 串联call frames、errors、closures、variadic、defer/panic/recover。
6. **Methods** 解释receiver copy/mutation、T/*T method sets、embedding、method values和encapsulation。
7. **Interfaces** 建立implicit satisfaction、dynamic type/value、typed nil、assertion/type switch与consumer contracts。

<Term def="function signature/error、receiver method set与consumer interface共同形成的调用边界；它规定可见行为、ownership、failure与dynamic dispatch。">abstraction boundary</Term>

只有先掌握第5章closure environment，才能判断goroutine捕获state；只有第6章method set清楚，才能正确解释第7章interface satisfaction和nil pointer。

### 阶段三：第 8–9 章，两种并发模型

8. **Goroutines and Channels** 覆盖clock/echo、pipeline、directional/buffered channels、parallel loop、crawler、select、traversal、cancellation、chat。
9. **Concurrency with Shared Variables** 覆盖race、Mutex/RWMutex、memory model、Once、race detector、memo cache、scheduler/threads。

<Term def="对goroutine completion/cancellation、channel close/backpressure、shared invariant与happens-before分别给出owner和verification的并发正确性证据。">concurrency proof</Term>

channel不是“更高级的锁”，Mutex也不是“违反Go哲学”。先看state ownership和interaction：message flow用channel/owner goroutine，短共享invariant可用Mutex；两者都必须有shutdown/error evidence。

### 阶段四：第 10–13 章，工程和运行时边界

10. **Packages and the Go Tool** 建立import/module/build graph、internal/docs/query。
11. **Testing** 区分test oracle、coverage、benchmark、profile、example。
12. **Reflection** 在runtime unknown shape上安全dispatch、codec、set、tags、methods。
13. **Low-Level Programming** 处理layout、unsafe.Pointer/uintptr、deep equality、cgo ownership。

<Term def="go list/build/test/race/profile/checkptr与boundary tests产生的可复现结果，用来证明package graph、behavior、performance、reflection/ABI assumptions。">engineering evidence</Term>

越靠后，runtime freedom越大，所需限制越多。reflection/unsafe不是“高级技巧”奖励，而是只有typed/interface/generic/generated方案不足时才进入的窄边界。

```go
// 一条贯穿全书的 producer-to-consumer skeleton
type Request struct { Key string `json:"key"` }       // Ch3-4
type Loader interface { Load(context.Context, string) ([]byte, error) } // Ch5-7

func Serve(loader Loader, jobs <-chan Request) <-chan Result { // Ch8-9
    // package/build/test/reflection/unsafe boundaries belong to Ch10-13.
    return runBounded(loader, jobs)
}
```

把每章的结论落成同一份可重复检查的证据目录，而不是只在笔记里打勾：

```bash
mkdir -p evidence/ch08
go test ./... -race -count=1 | tee evidence/ch08/race.txt
go test ./internal/pipeline -run TestCancel -count=100 \
  | tee evidence/ch08/cancel.txt
go test ./internal/pipeline -run TestBackpressure -count=1 \
  | tee evidence/ch08/backpressure.txt
```

第 8–9 章的最小练习要把完成、取消和关闭责任写进测试；只验证 happy path 不能证明 goroutine 会退出：

```go
func TestPipelineStopsAfterCancel(t *testing.T) {
    ctx, cancel := context.WithCancel(context.Background())
    done := make(chan struct{})
    go func() { defer close(done); runPipeline(ctx) }()

    cancel()
    select {
    case <-done:
    case <-time.After(time.Second):
        t.Fatal("pipeline leaked after cancellation")
    }
}
```

## 本章回顾：13 章是一条能力链

1. 第1–4章建立values、types、scope、ownership与shape。
2. 第5–7章把functions、receivers、interfaces组成abstraction boundary。
3. 第8–9章分别证明channel lifecycle与shared-state synchronization。
4. 第10–13章建立package/tool/test evidence，并限制reflection/unsafe/cgo。
5. 每章按官方目录、专属图、practice、review和verification闭环。

<Exercises>

**问题 1：为什么第 8 章不能拆成 goroutine/channel/select 三个互不相干的学习主题？**

<Answer>原书用clock/echo/pipeline/crawler/traversal/chat把三者组成lifecycle：goroutine需要completion，channel需要owner/close/backpressure，select同时等待work/timer/cancel。拆开只会语法，无法解释earlyreturn导致upstream阻塞、closedchannel永久ready或slowclient拖垮broadcaster。应按第8章完整flow学习，第9章再处理sharedstate memory model。</Answer>

**问题 2：遇到 interface 返回 non-nil error 但内部 pointer 是 nil，应沿哪条依赖链复查？**

<Answer>先回第6章检查Error method在T还是*T method set，再回第7章画interface dynamic type/value pair；typednil *MyError装入后pair不是(nil,nil)，所以err!=nil。修复成功path直接return nil，并在第11章增加constructor/return regression；若跨goroutine传播，再验证第8章result channel始终发送一次。</Answer>

**问题 3：何时允许进入第 13 章 unsafe/cgo，而不是继续用 typed Go？**

<Answer>先有第10–11章的real build/benchmark/profile证明typed方案无法满足ABI或measuredcost，再确认interface/generics/codegen不能解决。unsafe边界记录GOOS/GOARCH/layout/allocation/bounds/lifetime；cgo记录copy/pin/retain/free/error。保留safe reference或fallback，并用race/checkptr/cgo tests和clean builds验证，才能进入release gate。</Answer>

</Exercises>
