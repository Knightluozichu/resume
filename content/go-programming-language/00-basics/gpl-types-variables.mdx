## 直觉引入

Go 的类型系统就像一套标准化的收纳盒——每个类型有固定大小和形状。值类型是独立的盒子（复制即拷贝全部内容），引用类型是带标签的钥匙（复制只复制钥匙，指向同一个柜子）。理解这个区别是写出正确 Go 代码的前提——它决定了函数传参、赋值和并发行为的本质。

## 概念讲解

### 值类型与引用类型

<Term def="值类型（int/struct/array）赋值时复制全部数据；引用类型（slice/map/channel）赋值时复制引用，指向同一底层数据。">
Go 类型分两大类：

**值类型**：int、float64、bool、string、struct、array
- 赋值和传参时复制全部数据
- 修改副本不影响原始数据
- `a := 5; b := a; b = 10` 后 a 仍是 5

**引用类型**：slice、map、channel
- 赋值和传参时复制引用（指针+元数据）
- 修改副本会影响原始数据（共享底层数据）
- `a := []int{1}; b := a; b[0] = 99` 后 a[0] 也是 99

注意：Go 中所有赋值都是「值拷贝」——引用类型拷贝的是引用本身（指针），不是底层数据。所以「引用类型」更准确的说法是「内部包含指针的类型」。

这个区别是 Go 最重要的基础知识——不理解它就无法理解为什么函数修改 slice 会被调用者看到，也无法理解为什么 map 传参不需要传指针。
</Term>

### 变量声明与零值

<Term def="Go 所有类型都有零值（int=0, string="", pointer=nil）。var 用于包级声明，:= 用于函数内短声明。make 用于 slice/map/channel 初始化。">
变量声明方式：
```go
var x int           // 零值 0
var y = 42          // 类型推断
z := "hello"        // 短声明（仅函数内）
const Pi = 3.14159  // 常量
```

**零值机制**：Go 没有未初始化变量。所有类型都有零值：
- 数值类型：0
- string：""（空字符串）
- bool：false
- 指针/接口/slice/map/channel/function：nil

**make vs new**：
- `new(T)`：分配零值 T 的内存，返回 *T（指针）。少用
- `make(T, ...)`：仅用于 slice/map/channel，初始化内部结构，返回 T（不是指针）

```go
p := new(int)     // *int, *p = 0
s := make([]int, 0, 10) // []int, len=0 cap=10
m := make(map[string]int) // map[string]int
```
</Term>

## 代码对照

```go
package main

import "fmt"

// 值类型：修改副本不影响原始
type Point struct{ X, Y int }

func modifyValue(p Point) {
    p.X = 999 // 修改副本
}

// 引用类型：修改 slice 会被调用者看到
func modifySlice(s []int) {
    s[0] = 999 // 修改底层数组
}

// 指针传递：修改原始值
func modifyPointer(p *Point) {
    p.X = 999 // 通过指针修改原始
}

func main() {
    // 值类型
    p1 := Point{X: 1, Y: 2}
    modifyValue(p1)
    fmt.Println(p1.X) // 1（未改变）

    // 引用类型
    s1 := []int{1, 2, 3}
    modifySlice(s1)
    fmt.Println(s1[0]) // 999（改变了！）

    // 指针传递
    p2 := &Point{X: 1, Y: 2}
    modifyPointer(p2)
    fmt.Println(p2.X) // 999（改变了）

    // 零值
    var zeroInt int      // 0
    var zeroStr string   // ""
    var zeroPtr *int     // nil
    fmt.Println(zeroInt, zeroStr, zeroPtr)

    // make 初始化引用类型
    m := make(map[string]int)
    m["one"] = 1
    fmt.Println(m) // map[one:1]
}
```

## 常见误区

<Callout type="trap">
**误区：slice 和数组是一样的**
array 是值类型（固定长度，赋值复制全部元素），slice 是引用类型（变长，赋值复制引用）。`[3]int` 是数组，`[]int` 是 slice。函数参数写 `[]int` 传的是 slice（引用），写 `[3]int` 传的是数组（值拷贝）。实际开发中几乎只用 slice。
</Callout>

<Callout type="trap">
**误区：map 传参需要传指针才能修改**
map 本身就是引用类型——传参时复制的是 map 的内部指针，修改会被调用者看到。不需要传 *map。只有当你需要「重新初始化 map」（让调用者看到新 map）时才需要指针。slice 也类似，但 slice 的 append 可能创建新底层数组，所以修改 len/cap 需要返回或传指针。
</Callout>

<Exercises>
**问题 1**：为什么 Go 函数修改 map 参数会被调用者看到，而修改 struct 参数不会？

<Answer>
map 是引用类型——传参时复制的是 map 内部指针，函数内的 map 和调用者的 map 指向同一底层数据，修改会被看到。struct 是值类型——传参时复制全部字段数据，函数内修改的是副本，不影响调用者的原始数据。要让函数修改 struct，传 *struct 指针。
</Answer>

**问题 2**：make 和 new 的区别是什么？分别什么时候用？

<Answer>
new(T) 分配零值 T 的内存返回 *T 指针，用于任何类型。make(T,...) 初始化 slice/map/channel 的内部结构返回 T，仅用于这三种引用类型。实际开发中 make 更常用——因为 slice/map/channel 需要初始化内部结构才能使用，而 new 返回的指针指向的零值通常还需要进一步初始化。Go 中指针使用较少，大多数场景直接用值。
</Answer>

</Exercises>
