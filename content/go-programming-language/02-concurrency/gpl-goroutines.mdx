## 直觉引入

goroutine 就像一群协作的工人共享几个工作台（操作系统线程）。工人在工作台上干活，累了（阻塞等 IO）就让出工作台给其他工人。调度器（GMP）负责分配工作台。因为工人很轻（初始 2KB 栈），你可以轻松雇用十万个工人——这在传统线程模型中是不可想象的（每个线程 1-8MB 栈）。

## 概念讲解

### goroutine 与线程

<Term def="goroutine 是 Go runtime 管理的轻量级线程，初始栈 2KB 可增长。由 GMP 调度器映射到少量操作系统线程上。">
**goroutine vs OS 线程**：

| 特性 | goroutine | OS 线程 |
|------|-----------|---------|
| 栈大小 | 2KB 起步可增长 | 1-8MB 固定 |
| 创建开销 | 微秒级 | 毫秒级 |
| 调度 | Go runtime 用户态 | OS 内核态 |
| 数量 | 可达数十万 | 通常数百 |
| 切换 | ~100ns（用户态） | ~1us（内核态） |

创建 goroutine：
```go
go func() {
    fmt.Println("running in goroutine")
}()
```

goroutine 的栈是可增长的——初始 2KB，不够时 runtime 自动扩容（复制到更大的栈）。这使得 goroutine 既轻量又能处理深层递归。

关键区别：goroutine 是协作式调度的（在 IO/锁/channel 等阻塞点让出），但 Go 1.14+ 也支持抢占式调度（长时间运行的 goroutine 会被强制抢占）。
</Term>

### GMP 调度模型

<Term def="G(goroutine)-M(线程)-P(处理器) 模型：P 持有可运行 G 的本地队列，M 绑定 P 执行 G。P 数量 = GOMAXPROCS。">
**GMP 模型**：
- **G**（Goroutine）：用户代码的执行单元
- **M**（Machine）：操作系统线程，实际执行 G
- **P**（Processor）：逻辑处理器，持有本地 G 队列。数量 = GOMAXPROCS（默认=CPU 核数）

调度流程：
1. M 绑定一个 P，从 P 的本地队列取 G 执行
2. 本地队列空了，从全局队列偷（加锁）
3. 全局也空了，从其他 P 偷一半（work stealing）
4. G 阻塞（IO/锁/channel）时，M 让出 P 给其他 M，自己阻塞等待
5. G 恢复后放回某个 P 的队列

**GOMAXPROCS** 控制 P 的数量——即同时执行 Go 代码的线程数。IO 阻塞的 M 不占 P，所以 IO 密集型应用可以开很多 goroutine 而不需要调 GOMAXPROCS。

**goroutine 泄漏**：goroutine 阻塞在 channel 接收但无人发送，会永远阻塞。用 context.Context 或 select + timeout 避免泄漏。
</Term>

## 代码对照

```go
package main

import (
    "context"
    "fmt"
    "sync"
    "time"
)

// 基本 goroutine
func basicGoroutine() {
    go func() {
        fmt.Println("running in goroutine")
    }()
    time.Sleep(time.Second) // 等待 goroutine（简单但不推荐）
}

// WaitGroup 等待多个 goroutine
func waitGroupExample() {
    var wg sync.WaitGroup
    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            fmt.Printf("worker %d done\n", id)
        }(i)
    }
    wg.Wait() // 等待所有完成
}

// context 避免 goroutine 泄漏
func contextExample() {
    ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
    defer cancel()

    go func() {
        select {
        case <-ctx.Done():
            fmt.Println("goroutine cancelled:", ctx.Err())
            return
        case <-time.After(5 * time.Second):
            fmt.Println("work done")
        }
    }()

    <-ctx.Done() // 2秒后超时
    time.Sleep(100 * time.Millisecond) // 等 goroutine 打印
}

// 循环变量捕获问题
func loopCapture() {
    var wg sync.WaitGroup
    for i := 0; i < 3; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            // Go 1.22+ 每次 i 是新变量
            // Go 1.21- 需 i := i 创建副本
            fmt.Println(i)
        }()
    }
    wg.Wait()
}

func main() {
    basicGoroutine()
    waitGroupExample()
    contextExample()
    loopCapture()
}
```

## 常见误区

<Callout type="trap">
**误区：goroutine 就是协程（coroutine）**
goroutine 和协程有关但不完全相同。协程通常是协作式调度（需显式 yield），goroutine 在 Go 1.14+ 支持抢占式调度（runtime 强制暂停长时间运行的 goroutine）。goroutine 由 Go runtime 调度到 OS 线程上，开发者不感知调度细节。可以说 goroutine 是「Go runtime 管理的轻量级线程」，比传统协程更强大。
</Callout>

<Callout type="trap">
**误区：goroutine 之间共享变量是安全的**
goroutine 共享内存需要同步——和线程一样会数据竞争。`go func(){ x++ }()` 多个 goroutine 同时执行会导致 x 的值不确定。Go 的哲学是用 channel 通信替代共享内存：「不要通过共享内存通信，而要通过通信共享内存」。如果必须共享，用 sync.Mutex 或 sync/atomic。
</Callout>

<Exercises>
**问题 1**：goroutine 和操作系统线程有什么区别？为什么 Go 可以创建数十万个 goroutine？

<Answer>
区别：1.栈大小——goroutine 2KB 可增长，线程 1-8MB 固定。2.创建开销——goroutine 微秒级，线程毫秒级。3.调度——goroutine 由 Go runtime 用户态调度，线程由 OS 内核态调度。4.切换——goroutine ~100ns 用户态切换，线程 ~1us 内核态切换。可创建数十万因为：2KB×10万=200MB（可接受），而 8MB×10万=800GB（不可能）。且 goroutine 在少量线程上多路复用。
</Answer>

**问题 2**：GMP 模型中 P 的作用是什么？GOMAXPROCS 如何影响并发性能？

<Answer>
P(Processor) 是逻辑处理器，持有本地 G 队列。M(线程) 必须绑定 P 才能执行 G。P 数量=GOMAXPROCS=同时执行 Go 代码的线程数。GOMAXPROCS 默认=CPU 核数。CPU 密集型：GOMAXPROCS=核数最优。IO 密集型：可适当调大但不影响——IO 阻塞的 M 让出 P 给其他 M，P 始终保持忙碌。P 的本地队列减少锁竞争，work stealing 负载均衡。
</Answer>

</Exercises>
