## 直觉引入

select 就像火车站的多个检票口——你同时盯着多个检票口（channel 操作），哪个先开闸（有数据可读或可写）就去哪个。如果多个同时开闸，随机选一个。如果都没开闸但有 default 分支，就走 default 不等待。这让 goroutine 可以同时响应多个事件源——这是编写健壮并发程序的关键能力。

## 概念讲解

### select 多路复用

<Term def="select 同时等待多个 channel 操作。任意一个就绪就执行对应分支。多个就绪时随机选择。无就绪且无 default 则阻塞。">
**select 基本语法**：
```go
select {
case val := <-ch1:
    fmt.Println("from ch1:", val)
case ch2 <- 42:
    fmt.Println("sent to ch2")
case <-time.After(3 * time.Second):
    fmt.Println("timeout")
default:
    fmt.Println("no channel ready")
}
```

**关键行为**：
1. **同时就绪随机选**：多个 case 同时就绪时，随机选一个（避免饥饿）
2. **无就绪则阻塞**：没有 case 就绪且无 default → 阻塞等待
3. **有 default 不阻塞**：有 default 且无 case 就绪 → 执行 default
4. **nil channel 被跳过**：case 中的 nil channel 不会被选中（可用于动态启用/禁用 case）

select 让 goroutine 可以同时等待多个事件源，而不是顺序阻塞——这是编写响应式并发程序的核心。
</Term>

### 超时与 for-select 模式

<Term def="用 time.After 实现超时控制。for-select 循环持续处理事件。nil channel 动态禁用 case。">
**超时控制**：
```go
select {
case result := <-slowOp():
    fmt.Println(result)
case <-time.After(2 * time.Second):
    fmt.Println("timeout!") // 2 秒内无结果
}
```

**for-select 循环**（最常见的并发模式）：
```go
for {
    select {
    case msg := <-input:
        process(msg)
    case <-done:
        return // 收到退出信号
    case <-time.After(5 * time.Second):
        fmt.Println("idle timeout")
    }
}
```

**nil channel 动态控制**：
```go
var ch chan int = nil // nil channel
select {
case val := <-ch: // ch 为 nil 时此 case 永远不会被选中
    // ...
case <-done:
    return
}
// 动态启用：
ch = make(chan int) // 现在 ch 非 nil，case 可被选中
```

这个技巧用于：处理完一个 channel 后将其设为 nil，从 select 中「移除」它，继续处理其他 channel。
</Term>

## 代码对照

```go
package main

import (
    "context"
    "fmt"
    "time"
)

// 超时控制
func withTimeout() {
    ch := make(chan string)
    go func() {
        time.Sleep(2 * time.Second)
        ch <- "result"
    }()

    select {
    case result := <-ch:
        fmt.Println("got:", result)
    case <-time.After(1 * time.Second):
        fmt.Println("timeout!") // 1 秒超时
    }
}

// for-select 事件循环
func eventLoop(done <-chan struct{}) {
    tick := time.Tick(500 * time.Millisecond)
    for {
        select {
        case <-done:
            fmt.Println("shutting down")
            return
        case <-tick:
            fmt.Println("tick at", time.Now().Format("15:04:05"))
        }
    }
}

// 非阻塞操作（default）
func nonBlocking(ch chan int) {
    select {
    case val := <-ch:
        fmt.Println("received:", val)
    default:
        fmt.Println("no value available") // 不阻塞
    }
}

// 动态禁用 case（nil channel）
func dynamicSelect() {
    ch1 := make(chan int, 1)
    ch2 := make(chan int, 1)
    ch1 <- 1
    ch2 <- 2

    for i := 0; i < 2; i++ {
        select {
        case val := <-ch1:
            fmt.Println("ch1:", val)
            ch1 = nil // 禁用 ch1 的 case
        case val := <-ch2:
            fmt.Println("ch2:", val)
            ch2 = nil // 禁用 ch2 的 case
        }
    }
}

// context 配合 select
func contextSelect(ctx context.Context) {
    for {
        select {
        case <-ctx.Done():
            fmt.Println("cancelled:", ctx.Err())
            return
        case <-time.After(1 * time.Second):
            fmt.Println("working...")
        }
    }
}

func main() {
    withTimeout()

    done := make(chan struct{})
    go eventLoop(done)
    time.Sleep(1600 * time.Millisecond)
    close(done)
    time.Sleep(100 * time.Millisecond)

    ch := make(chan int, 1)
    nonBlocking(ch) // 有值
    nonBlocking(ch) // 无值

    dynamicSelect()

    ctx, cancel := context.WithTimeout(context.Background(), 2500*time.Millisecond)
    defer cancel()
    contextSelect(ctx)
}
```

## 常见误区

<Callout type="trap">
**误区：select 会按 case 顺序检查并选择第一个就绪的**
select 不按 case 顺序——多个 case 同时就绪时**随机**选择一个。这是刻意设计：避免某个 case 始终被优先导致其他 case 饥饿。如果需要优先级，需要嵌套 select：先非阻塞检查高优先级 case（default 分支不操作），再进入主 select。
</Callout>

<Callout type="trap">
**误区：time.After 在循环中使用没有开销**
time.After 创建的 timer 在超时前不会被 GC——它会留在 timer 堆中直到触发。在 for-select 循环中每次循环都 time.After 会累积大量未触发的 timer，造成内存泄漏。修法：用 time.NewTimer 手动管理，或用 time.Tick（只创建一次）。Go 1.23+ 对 time.After 有优化但仍建议避免在紧密循环中使用。
</Callout>

<Exercises>
**问题 1**：select 的多个 case 同时就绪时会怎样？为什么这样设计？

<Answer>
多个 case 同时就绪时随机选择一个执行。这样设计是为了避免饥饿——如果按固定顺序选择，排在后面的 case 可能始终被跳过。随机选择保证公平性。如果需要优先级，用嵌套 select：先非阻塞检查高优先级 case（select{case x:=<-high:...; default:}），再进入主 select 处理所有 case。
</Answer>

**问题 2**：如何在 for-select 循环中安全退出？列举两种方式。

<Answer>
方式1：done channel——close(done) 通知退出，select 中 case <-done: return。方式2：context.Context——ctx.Cancel() 触发 ctx.Done()，select 中 case <-ctx.Done(): return。context 更推荐——支持超时和值传递。注意：退出前确保 goroutine 不会泄漏——关闭所有它可能阻塞的 channel，或用 context 贯穿整个 goroutine 生命周期。
</Answer>

</Exercises>
