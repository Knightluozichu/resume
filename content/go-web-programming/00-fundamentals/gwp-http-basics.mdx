## 直觉引入

HTTP 就像寄信：你写一封信（请求），写上收件地址（URL）和寄送方式（GET/POST），放进邮筒；服务器收到信后处理后回信（响应），回信信封上标注状态（200 收到、404 查无此人、500 内部出错）。

Go 的 `net/http` 标准库让这个过程变得极其简单——你只需要写一个函数来"读信和回信"，剩下的 TCP 连接管理、HTTP 协议解析全部由标准库处理。

## 概念讲解

### HTTP 请求与响应结构

<Term def="HTTP 请求由请求行（方法+路径+版本）、请求头、请求体组成；响应由状态行（版本+状态码+原因）、响应头、响应体组成。Go 中对应 http.Request 和 http.ResponseWriter。">

一个 HTTP 请求包含三部分：

- **请求行**：`GET /api/users HTTP/1.1`——方法、路径、协议版本
- **请求头**：`Host`、`Content-Type`、`Authorization` 等键值对
- **请求体**：POST/PUT 携带的数据（JSON、表单等）

响应同样三部分：状态行（`HTTP/1.1 200 OK`）、响应头、响应体。Go 中 `http.Request` 封装了请求的全部信息，`http.ResponseWriter` 是写入响应的接口。

</Term>

### Handler 接口

<Term def="http.Handler 是 Go HTTP 处理的核心接口，只有一个方法 ServeHTTP(w http.ResponseWriter, r *http.Request)。任何实现该接口的类型都能处理 HTTP 请求。">

```go
type Handler interface {
    ServeHTTP(w ResponseWriter, r *Request)
}
```

`http.HandlerFunc(f)` 是一个适配器，将普通函数 `func(w, r)` 转为 `Handler`。`http.HandleFunc` 则直接注册函数到默认路由。`ResponseWriter` 是一个接口，你可以调用 `w.WriteHeader(200)` 写状态码、`w.Header().Set(...)` 设置响应头、`w.Write([]byte)` 写响应体。

</Term>

## 代码对照

```go
package main

import (
    "encoding/json"
    "fmt"
    "log"
    "net/http"
)

// User 结构体
type User struct {
    ID   int    `json:"id"`
    Name string `json:"name"`
}

func userHandler(w http.ResponseWriter, r *http.Request) {
    // 根据方法分发
    switch r.Method {
    case http.MethodGet:
        users := []User{{1, "Go"}, {2, "Web"}}
        w.Header().Set("Content-Type", "application/json")
        json.NewEncoder(w).Encode(users)

    case http.MethodPost:
        var u User
        if err := json.NewDecoder(r.Body).Decode(&u); err != nil {
            w.WriteHeader(http.StatusBadRequest)
            fmt.Fprint(w, "Invalid JSON")
            return
        }
        u.ID = 100 // 模拟数据库分配 ID
        w.Header().Set("Content-Type", "application/json")
        w.WriteHeader(http.StatusCreated) // 201
        json.NewEncoder(w).Encode(u)

    default:
        w.WriteHeader(http.StatusMethodNotAllowed) // 405
    }
}

func main() {
    http.HandleFunc("/users", userHandler)
    http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("OK"))
    })

    log.Println("Server starting on :8080")
    log.Fatal(http.ListenAndServe(":8080", nil))
}
```

## 常见误区

<Callout type="trap">
**误区：WriteHeader 顺序错误**
`w.WriteHeader(200)` 必须在 `w.Write()` 之前调用。一旦调用了 `Write`，Go 会自动发送 200 状态码，之后再调用 `WriteHeader` 会被忽略并打印警告。如果你需要自定义状态码（如 201/400/500），必须先 `WriteHeader` 再 `Write`。
</Callout>

<Callout type="trap">
**误区：用 GET 方法做修改操作**
HTTP 方法有语义约定：GET 应该是幂等且无副作用的（只读取数据），POST 用于创建，PUT/PATCH 用于更新，DELETE 用于删除。用 GET 来修改数据会导致缓存出错、爬虫误触发、CDN 缓存错误响应。遵循 RESTful 约定让 API 可预测。
</Callout>

<Exercises>
**问题 1**：在 Go 的 HTTP Handler 中，为什么 `w.Header().Set("Content-Type", "application/json")` 必须在 `w.WriteHeader()` 和 `w.Write()` 之前调用？

<Answer>
HTTP 响应的格式是：状态行 → 响应头 → 空行 → 响应体。Go 的 `ResponseWriter` 在第一次调用 `WriteHeader` 或 `Write` 时会将响应头发送给客户端。

一旦响应头已发送，之后再调用 `w.Header().Set()` 不会有任何效果——头已经走了。同样，`WriteHeader` 也只能调用一次。因此正确的顺序是：先设置所有 Header，再调用 `WriteHeader`（如果非 200），最后 `Write` 写响应体。
</Answer>

**问题 2**：`http.Handler` 接口和 `http.HandlerFunc` 类型有什么关系？为什么 Go 要这样设计？

<Answer>
`http.Handler` 是一个接口，定义了 `ServeHTTP(w ResponseWriter, r *Request)` 方法。`http.HandlerFunc` 是一个类型，定义为 `type HandlerFunc func(ResponseWriter, *Request)`，它为自身添加了 `ServeHTTP` 方法，使得任何签名为 `func(w, r)` 的普通函数都能自动满足 `http.Handler` 接口。

这个设计是 Go 的"适配器模式"经典案例：接口定义契约，`HandlerFunc` 让普通函数无需显式定义结构体和方法就能满足接口。`http.HandleFunc` 进一步简化——直接将函数注册到路由，内部用 `HandlerFunc` 包装。这让 Web 开发极其简洁：写一个函数就是写一个 Handler。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="HTTP 方法">
定义请求语义的动词：GET（读取，幂等无副作用）、POST（创建，非幂等）、PUT（整体更新，幂等）、PATCH（部分更新）、DELETE（删除，幂等）。遵循方法语义让 API 符合 RESTful 约定，利于缓存、重试和客户端理解。
</GlossaryItem>
<GlossaryItem term="状态码">
HTTP 响应状态码分五类：1xx 信息、2xx 成功（200 OK、201 Created、204 No Content）、3xx 重定向（301/302/304）、4xx 客户端错误（400 Bad Request、401 Unauthorized、404 Not Found）、5xx 服务器错误（500 Internal Error、503 Service Unavailable）。
</GlossaryItem>
<GlossaryItem term="http.ResponseWriter">
Go 标准库中写入 HTTP 响应的接口，提供三个核心方法：`Header()` 返回响应头 map、`WriteHeader(statusCode)` 发送状态码、`Write([]byte)` 写响应体。注意顺序约束：Header 必须在 WriteHeader 前设置，WriteHeader 在 Write 前调用。
</GlossaryItem>
<GlossaryItem term="ServeMux">
Go 标准库的 HTTP 请求多路复用器（路由器）。`http.HandleFunc(pattern, handler)` 将 URL 模式映射到处理器。模式 `/` 匹配所有未匹配的路径，`/users/` 以斜杠结尾匹配子路径。Go 1.22 起支持方法和路径参数（`GET /users/{id}`）。
</GlossaryItem>
</Glossary>
