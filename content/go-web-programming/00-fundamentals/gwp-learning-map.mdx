## 直觉引入

如果把构建一个 Web 应用比作开一家餐厅，那么 HTTP 协议就是"前门到后厨的传菜通道"——客人（请求）从前门进来，服务员（路由）带位，厨师（Handler）做菜，账单（响应）送回去。

Go 语言在 Web 开发中的独特优势在于：它的标准库自带了完整的 HTTP 服务器（`net/http`），你不需要安装任何框架就能跑起一个高性能的 Web 服务。这就像餐厅自带厨房设备——你不需要额外采购就能直接开业。

## 概念讲解

### 四大板块

<Term def="Go Web 编程全书分为四大板块：Web基础、路由与中间件、数据层、生产部署，按请求生命周期递进组织。">

全书十章分为四大板块，按照一个 HTTP 请求的生命周期递进：

1. **Web 基础**（第1-2章）：HTTP 协议与 Go 标准库——理解请求和响应的本质
2. **路由与中间件**（第3-4章）：路由分发与中间件链——组织请求处理流程
3. **数据层**（第5-7章）：数据库、模板与 JSON API——存取和呈现数据
4. **生产部署**（第8-10章）：认证、部署与总复习——安全上线与运维保障

</Term>

### Go Web 的核心哲学

<Term def="Go Web 开发的核心理念：标准库优先、组合优于继承、显式错误处理、单二进制部署。">

Go 构建 Web 应用有几个核心设计理念：

- **标准库优先**：`net/http` 提供完整的 HTTP 服务器和客户端，很多项目不需要第三方框架
- **组合优于继承**：通过嵌入 `http.Handler` 接口组合功能，而非继承基类
- **中间件模式**：`func(http.Handler) http.Handler` 是一切中间件的签名，简洁而强大
- **单二进制部署**：编译为一个可执行文件，无外部依赖，容器化极简

</Term>

<Step title="第一板块：Web 基础">
理解 HTTP 协议——请求方法（GET/POST/PUT/DELETE）、状态码（200/400/500）、请求头与响应头。掌握 Go 标准库 `net/http` 的 `ServeMux`、`Handler` 接口和 `HandlerFunc` 适配器。这是一切 Web 开发的地基：不理解 HTTP，就无法理解路由和中间件。
</Step>
<Step title="第二板块：路由与中间件">
学习路由匹配——`http.ServeMux` 的模式匹配、第三方路由库（gorilla/mux、chi）的参数路由。掌握中间件洋葱模型——日志、认证、限流等横切关注点的优雅实现方式。路由决定"谁处理请求"，中间件决定"处理前后做什么"。
</Step>
<Step title="第三板块：数据层">
掌握 `database/sql` 的连接池和预编译语句、`html/template` 的上下文感知转义、`encoding/json` 的结构体标签映射。这是 Web 应用的核心：从数据库取数据，渲染为 HTML 或 JSON 返回给客户端。
</Step>
<Step title="第四板块：生产部署">
学习 Session-Cookie 与 JWT 两种认证方案、密码安全存储（bcrypt）。掌握 Go 应用的部署：Docker 容器化、Nginx 反向代理、优雅关闭、结构化日志和监控。将开发环境的应用变为生产级服务。
</Step>

## 代码对照

```go
// 一个最小的 Go Web 服务器——只需标准库
package main

import (
    "fmt"
    "net/http"
)

func main() {
    // 注册路由
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintf(w, "Hello, %s!", r.URL.Path[1:])
    })

    http.HandleFunc("/api/json", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        w.Write([]byte(`{"message": "Hello, Go Web!"}`))
    })

    // 启动服务器
    fmt.Println("Server running on :8080")
    http.ListenAndServe(":8080", nil)
}
```

## 常见误区

<Callout type="trap">
**误区：一上来就用 Web 框架**
很多初学者直接从 Gin、Echo 等框架开始，跳过了标准库 `net/http` 的学习。这导致你理解不了框架在做什么——路由、中间件、上下文都是对标准库的封装。先掌握标准库，再用框架，才能理解框架的取舍和适用场景。
</Callout>

<Callout type="trap">
**误区：忽视 HTTP 协议基础**
HTTP 是一切 Web 开发的底层协议。不理解请求方法语义（GET 不应修改数据）、状态码约定（201 Created vs 200 OK）、缓存头（Cache-Control），写出的 API 就不符合规范，客户端难以正确消费。先学 HTTP，再学 Go 的 HTTP 实现。
</Callout>

<Exercises>
**问题 1**：Go Web 编程全书四大板块的顺序是什么？为什么要按这个顺序学习？

<Answer>
四大板块：Web 基础（HTTP 与标准库）→ 路由与中间件（请求分发与横切处理）→ 数据层（数据库/模板/JSON）→ 生产部署（认证/部署/运维）。

按这个顺序学习是因为它对应一个 HTTP 请求的完整生命周期：请求先到达服务器（Web 基础），被路由分发和中间件处理（路由与中间件），Handler 从数据层获取数据并渲染响应（数据层），最终整个应用需要安全上线和运维保障（生产部署）。每一层都建立在前一层之上——不理解 HTTP 就无法理解路由，不理解路由就无法理解中间件，不理解数据层就无法构建有意义的 Web 应用。
</Answer>

**问题 2**：Go 的 `net/http` 标准库与第三方 Web 框架（如 Gin）的核心区别是什么？

<Answer>
`net/http` 标准库提供了 HTTP 服务器和路由的基础设施：`ServeMux` 做简单的模式匹配路由，`Handler` 接口定义处理函数签名，`http.Client` 提供客户端能力。它没有参数路由（`/users/{id}`）、没有内置中间件链、没有 JSON 绑定/验证、没有分组路由。

第三方框架在这些基础上做了增强：Gin 用 httprouter 实现高效的前缀树路由，提供 `c.JSON()` 快速序列化，内置中间件链和参数绑定。但它们都基于 `net/http` 的接口——`http.Handler` 是统一的契约。先学标准库能理解框架的本质，在简单项目中标准库就足够了，框架是"用复杂度换便利性"的取舍。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="HTTP 生命周期">
一个 HTTP 请求从客户端发出，经过 DNS 解析、TCP 连接、HTTP 请求传输、服务器处理、HTTP 响应返回的完整过程。Go Web 开发的核心就是在这个生命周期的"服务器处理"环节做文章：路由、中间件、Handler、数据存取。
</GlossaryItem>
<GlossaryItem term="http.Handler">
Go 标准库定义的核心接口：`ServeHTTP(w http.ResponseWriter, r *http.Request)`。任何实现了该接口的类型都可以作为 HTTP 处理器。`http.HandlerFunc` 是将普通函数适配为 Handler 的类型。
</GlossaryItem>
<GlossaryItem term="中间件（Middleware）">
签名为 `func(http.Handler) http.Handler` 的函数，包装一个 Handler 返回新的 Handler。中间件可以在请求前后添加逻辑（日志、认证、限流），多个中间件组成洋葱模型嵌套调用。
</GlossaryItem>
<GlossaryItem term="单二进制部署">
Go 编译为单个静态链接的可执行文件，无外部依赖（CGO_ENABLED=0 时）。这意味着部署只需复制一个文件到服务器，Docker 镜像可以基于 `scratch`（空镜像），极大简化了部署和运维。
</GlossaryItem>
</Glossary>
