## 从浏览器为何能调用Go开始

先预测：浏览器访问一个URI时，是否直接调用Go函数？不是。客户端发送HTTP消息，服务器解析后选择handler，再把结果编码为响应。<Term def="客户端请求、服务端处理和响应返回组成的一次协议往返。">HTTP exchange contract</Term>把网络协议与函数调用分开。

## Go为何适合Web应用

编译产物、垃圾回收、静态类型、标准库和轻量并发共同降低交付成本。<Term def="组件职责清晰、依赖方向稳定且可独立测试的应用结构。">modular web architecture</Term>比“框架少”更重要；性能也必须由测量证明，不能从语言标签推导。

```go
func main() {
    http.HandleFunc("/", hello)
    log.Fatal(http.ListenAndServe(":8080", nil))
}
```

## Web应用如何工作

DNS、连接、HTTP请求、路由、handler、存储和模板按顺序协作。<Term def="把协议输入分派到应用行为并生成响应的处理入口。">handler boundary</Term>只拥有一次请求，不应启动无法取消的后台工作。

## HTTP请求

请求包含method、URI、版本、header和可选body。GET与HEAD应安全，PUT与DELETE按语义应幂等，但服务器实现仍要维护不变量。<Term def="重复执行同一请求产生与执行一次相同目标状态的语义。">idempotent method semantics</Term>不等于每次响应字节完全相同。

```http
POST /threads HTTP/1.1
Content-Type: application/x-www-form-urlencoded

title=Go
```

## HTTP响应、URI与HTTP/2

响应由状态行、header和body组成；URI标识资源位置与查询。HTTP/2改变连接上的帧和stream复用，不改变handler看到的高层请求语义。<Term def="状态码、响应头和实体共同表达处理结果的协议承诺。">response message contract</Term>要求写body前确定状态和header。

## Handler与Template Engine

Handler处理协议和业务，template engine把数据与展示程序组合。<Term def="在不改变领域数据的前提下把数据安全渲染为内容的组件。">template rendering boundary</Term>应默认使用html/template处理上下文转义。

```go
func hello(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "text/plain; charset=utf-8")
    w.WriteHeader(http.StatusOK)
    _, _ = io.WriteString(w, "hello")
}
```

## 验收实验：原始消息到Handler

用curl分别发送GET、POST和不支持的方法，保存请求行、header、状态和body；随后切换HTTP/1.1与HTTP/2客户端，确认业务handler行为一致。故意在Write后修改状态码，观察为何响应已提交。

<Callout type="trap" title="POST天然比GET安全">方法名不提供认证、授权或加密；敏感操作仍需TLS、身份和权限检查。</Callout>
<Callout type="trap" title="HTTP/2要求重写业务Handler">net/http在传输层处理协议差异，高层handler契约通常保持不变。</Callout>

<Exercises>
**问题 1：安全方法与幂等方法相同吗？**<Answer>不同；安全表示不请求状态改变，幂等表示重复请求的目标状态相同。</Answer>
**问题 2：何时状态码被提交？**<Answer>调用WriteHeader或第一次Write时。</Answer>
**问题 3：Handler与模板谁负责什么？**<Answer>Handler处理请求和业务，模板只负责根据数据生成展示内容。</Answer>
