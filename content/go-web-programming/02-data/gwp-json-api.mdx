## 直觉引入

JSON API 就像国际快递的标准箱：不管你寄什么（Go struct），都装进统一规格的箱子（JSON）里，贴上标准标签（Content-Type: application/json），收件人拆箱后还原成本地格式（另一个 Go struct）。

Go 的 `encoding/json` 用 struct tag 作为"装箱说明书"——告诉序列化器每个字段对应箱子上哪个标签、空值要不要装、哪些字段不装。`json.Marshal` 是装箱，`json.Unmarshal` 是拆箱。

## 概念讲解

### Marshal 与 Unmarshal

<Term def="json.Marshal 将 Go 值编码为 JSON 字节切片（[]byte），json.Unmarshal 将 JSON 字节切片解码到 Go 值。编码时字段名按 struct tag 映射，解码时按 tag 匹配 JSON 键。">

```go
type User struct {
    ID       int    `json:"id"`
    Name     string `json:"name"`
    Email    string `json:"email,omitempty"` // 空值省略
    Password string `json:"-"`               // 永不序列化
}

u := User{ID: 1, Name: "Go", Email: "", Password: "secret"}
data, _ := json.Marshal(u)
// {"id":1,"name":"Go"}  — email 因 omitempty 被省略，password 被 - 排除

var u2 User
json.Unmarshal(data, &u2) // 解码到 u2
```

</Term>

### struct tag 详解

<Term def="struct tag 是反引号包裹的元数据字符串，json tag 格式为 `json:"name,omitempty"`。name 控制字段名，omitempty 空值省略，- 完全忽略，- 但带逗号 ,omitempty 时字段名为 -。">

常用 tag 选项：

- `json:"field_name"` — 指定 JSON 中的键名（默认用 Go 字段名）
- `json:"field,omitempty"` — 零值（""、0、nil、false）时省略该字段
- `json:"-"` — 完全忽略该字段，不序列化也不反序列化
- `json:",string"` — 将数值/布尔包装为字符串（如 `"123"` 而非 `123`）
- 无 tag — 用 Go 字段名作为 JSON 键名

</Term>

### Encoder/Decoder 流式处理

<Term def="json.NewEncoder(w).Encode(v) 直接将 JSON 写入 io.Writer（如 ResponseWriter），json.NewDecoder(r).Decode(&v) 直接从 io.Reader 读取 JSON 解码。适合 HTTP 请求/响应场景，避免中间 []byte 分配。">

```go
// 响应：直接编码到 ResponseWriter
json.NewEncoder(w).Encode(users) // 等价于 Marshal + w.Write

// 请求：直接从 Body 解码
var u User
json.NewDecoder(r.Body).Decode(&u)
```

Encoder/Decoder 比先 Marshal 再 Write 更高效——减少一次内存分配，且支持流式处理大 JSON。

</Term>

<Step title="第一步：定义数据模型">
为 API 资源定义 struct，用 `json` tag 控制序列化行为。敏感字段（如密码）用 `json:"-"` 排除。可选字段用 `omitempty` 省略零值。字段名用 snake_case（`json:"user_id"`）或 camelCase 根据团队约定。
</Step>
<Step title="第二步：编写 API Handler">
读取请求：`json.NewDecoder(r.Body).Decode(&input)`。处理业务逻辑。写入响应：先设 `w.Header().Set("Content-Type", "application/json")`，再用 `json.NewEncoder(w).Encode(result)` 输出。错误时返回结构化错误 JSON。
</Step>
<Step title="第三步：设计错误响应">
错误响应应有统一格式：`{"error": {"code": "INVALID_REQUEST", "message": "..."}}`。HTTP 状态码反映错误类型：400 客户端请求格式错误、401 未认证、403 无权限、404 资源不存在、422 验证失败、500 服务器内部错误。错误信息对客户端有意义，但不暴露内部实现。
</Step>
</Stepper>

## 代码对照

```go
package main

import (
    "encoding/json"
    "net/http"
    "strconv"
)

type User struct {
    ID       int    `json:"id"`
    Name     string `json:"name"`
    Email    string `json:"email,omitempty"`
    Password string `json:"-"` // 永不暴露
}

type ErrorResponse struct {
    Error ErrorDetail `json:"error"`
}
type ErrorDetail struct {
    Code    string `json:"code"`
    Message string `json:"message"`
}

func writeJSON(w http.ResponseWriter, status int, v interface{}) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}

func writeError(w http.ResponseWriter, status int, code, msg string) {
    writeJSON(w, status, ErrorResponse{ErrorDetail{code, msg}})
}

// GET /users/{id}
func getUserHandler(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(r.PathValue("id"))
    if err != nil {
        writeError(w, 400, "INVALID_ID", "User ID must be a number")
        return
    }

    user := findUser(id) // 模拟查询
    if user == nil {
        writeError(w, 404, "NOT_FOUND", "User not found")
        return
    }

    writeJSON(w, 200, user)
}

// POST /users
func createUserHandler(w http.ResponseWriter, r *http.Request) {
    var input struct {
        Name  string `json:"name"`
        Email string `json:"email"`
    }
    if err := json.NewDecoder(r.Body).Decode(&input); err != nil {
        writeError(w, 400, "INVALID_JSON", "Request body is not valid JSON")
        return
    }

    if input.Name == "" {
        writeError(w, 422, "VALIDATION_ERROR", "Name is required")
        return
    }

    user := User{ID: 100, Name: input.Name, Email: input.Email}
    writeJSON(w, 201, user) // 201 Created
}

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /users/{id}", getUserHandler)
    mux.HandleFunc("POST /users", createUserHandler)
    http.ListenAndServe(":8080", mux)
}
```

## 常见误区

<Callout type="trap">
**误区：忘记设置 Content-Type**
返回 JSON 时不设置 `Content-Type: application/json`，浏览器和客户端可能按 `text/plain` 处理，导致编码问题或客户端 JSON 解析器报错。始终在 WriteHeader 之前设置 `w.Header().Set("Content-Type", "application/json")`。如果是 API，可以写一个 `writeJSON` 辅助函数统一处理。
</Callout>

<Callout type="trap">
**误区：暴露敏感字段**
struct 的 Password、Token 等字段如果忘记加 `json:"-"`，会被序列化到 JSON 响应中，泄露给客户端。这是严重的安全漏洞。在 API 响应中只暴露必要的字段——为输入和输出定义不同的 struct，或用 `json:"-"` 排除敏感字段。定期检查 API 响应结构，确保没有多余字段。
</Callout>

<Exercises>
**问题 1**：`json:"email,omitempty"` 和 `json:"-"` 的区别是什么？各自在什么场景下使用？

<Answer>
- `json:"email,omitempty"`：字段正常序列化为 JSON 键 `email`，但当值为零值（空字符串 `""`、0、nil、false）时省略该键。用于可选字段——有值时输出，无值时不出现，保持 JSON 简洁。
- `json:"-"`：字段完全被排除——既不序列化到 JSON 输出，也不从 JSON 输入反序列化。用于不应暴露给客户端的内部字段，如密码 `Password string \`json:"-"\``、内部 ID、临时计算字段。

场景区分：`omitempty` 用于"有时有值有时没有"的可选字段（如用户可能没填邮箱）；`-` 用于"永远不该出现在 JSON 中"的敏感或内部字段（如密码、内部状态）。注意 `json:"-,"`（带逗号）表示字段名真的叫 `-`，不是排除。
</Answer>

**问题 2**：设计一个博客 API 的错误响应格式，要求能区分验证错误（多个字段验证失败）和其他错误。请给出 JSON 结构和 Go 实现。

<Answer>
JSON 结构:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      {"field": "title", "message": "Title is required"},
      {"field": "body", "message": "Body must be at least 10 characters"}
    ]
  }
}
```

Go 实现:
```go
type FieldError struct {
    Field   string `json:"field"`
    Message string `json:"message"`
}

type APIError struct {
    Code    string       `json:"code"`
    Message string       `json:"message"`
    Details []FieldError `json:"details,omitempty"`
}

type ErrorResponse struct {
    Error APIError `json:"error"`
}

func writeValidationError(w http.ResponseWriter, errs []FieldError) {
    resp := ErrorResponse{
        Error: APIError{
            Code:    "VALIDATION_ERROR",
            Message: "Request validation failed",
            Details: errs,
        },
    }
    writeJSON(w, 422, resp) // 422 Unprocessable Entity
}

func writeSimpleError(w http.ResponseWriter, status int, code, msg string) {
    writeJSON(w, status, ErrorResponse{
        Error: APIError{Code: code, Message: msg},
    })
}
```
设计要点：统一 error 包装结构、details 用 omitempty（非验证错误时省略）、422 状态码表示语义错误（格式正确但内容不合法）、field 错误列表让客户端能逐字段显示错误。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="json.Marshal">
将 Go 值编码为 JSON `[]byte`。按 struct 的 `json` tag 映射字段名，零值字段默认输出（除非 omitempty），不可见字段（`json:"-"`）被排除。递归处理嵌套 struct、slice、map。返回 `([]byte, error)`。
</GlossaryItem>
<GlossaryItem term="json.Unmarshal">
将 JSON `[]byte` 解码到 Go 值。按 `json` tag 匹配 JSON 键名到 struct 字段，类型不匹配时返回 error。解码时 JSON 中多余的字段被忽略（不报错），缺失的字段保持零值。传指针：`json.Unmarshal(data, &v)`。
</GlossaryItem>
<GlossaryItem term="struct tag">
反引号包裹的元数据，附加在 struct 字段上。`json` tag 格式 `json:"name,options"`：name 控制 JSON 键名，`omitempty` 省略零值，`-` 排除字段。tag 是编译时检查不了的字符串，拼写错误（如 `json` 写成 `josn`）会静默失败——字段用默认名。
</GlossaryItem>
<GlossaryItem term="RESTful API">
用 HTTP 方法表达操作、URL 表达资源、JSON 表达数据的 API 设计风格。`GET /users` 列表、`POST /users` 创建、`GET /users/{id}` 详情、`PUT /users/{id}` 更新、`DELETE /users/{id}` 删除。无状态、统一接口、可缓存。状态码：200/201/204 成功，400/401/403/404/422 客户端错误，500 服务器错误。
</GlossaryItem>
</Glossary>
