## 直觉引入

模板渲染就像填表格：你有一张预印好的表格（模板），上面有空白栏位（`{{.Name}}`），你把数据填进去（Execute），得到完整的文件（HTML）。

Go 的 `html/template` 比普通"查找替换"聪明的地方在于：它知道每个栏位在什么上下文中（HTML 标签里、属性里、JavaScript 里、URL 里），会根据上下文自动做不同的转义。比如 `<` 在 HTML 文本中变成 `&lt;`，在 JavaScript 中变成 `\u003c`。这是防止 XSS 攻击的关键防线。

## 概念讲解

### 解析与执行

<Term def="html/template 的工作流程分两步：Parse 将模板字符串解析为语法树（AST），Execute 遍历 AST 注入数据并输出。Parse 只做一次，Execute 可多次复用不同数据。">

```go
// 解析阶段：模板字符串 → AST
tmpl, err := template.New("page").Parse(`
<h1>{{.Title}}</h1>
<ul>{{range .Items}}<li>{{.}}</li>{{end}}</ul>
`)

// 执行阶段：AST + 数据 → 输出
data := struct {
    Title string
    Items []string
}{"My List", []string{"Go", "Web", "Template"}}
tmpl.Execute(w, data) // w 是 http.ResponseWriter
```

Parse 阶段检查模板语法是否正确，Execute 阶段注入数据并转义。同一模板可以 Execute 多次，传入不同数据——适合预编译模板在应用启动时解析一次。

</Term>

### 上下文感知转义

<Term def="html/template 根据插值位置的上下文（HTML 文本、属性、JavaScript、CSS、URL）自动选择不同的转义策略，防止 XSS 攻击。这是它区别于 text/template 的核心安全特性。">

同一个 `{{.Content}}`，根据它出现的位置，转义方式不同：

- HTML 文本中：`{{.Content}}` → `<` 变 `&lt;`，`>` 变 `&gt;`
- HTML 属性中：`value="{{.Content}}"` → `"` 变 `&#34;`
- JavaScript 中：`&lt;script&gt;var x = "{{.Content}}";&lt;/script&gt;` → `"` 变 `\u0022`
- URL 中：`href="{{.Content}}"` → `&` 变 `%26`

这种上下文感知让开发者不需要手动转义——模板引擎自动处理。**永远用 `html/template` 渲染 HTML，不要用 `text/template`**——后者不转义，有 XSS 风险。

</Term>

<Step title="第一步：编写模板">
创建 `.html` 或 `.tmpl` 文件，用 `{{}}` 双花括号标记 Action。常用 Action：`{{.}}` 当前数据、`{{.Field}}` 字段、`{{range}}...{{end}}` 遍历、`{{if}}...{{end}}` 条件、`{{template "name" .}}` 组合子模板。
</Step>
<Step title="第二步：解析模板">
用 `template.ParseFiles("layout.html", "content.html")` 解析文件，或 `template.New("name").Parse(src)` 解析字符串。解析可合并多个模板，通过 `{{define "name"}}` 定义子模板，`{{template "name" .}}` 引用。
</Step>
<Step title="第三步：执行渲染">
`tmpl.Execute(w, data)` 将数据注入模板输出到 ResponseWriter。data 可以是 struct（推荐，有类型安全）或 map[string]any（灵活但无类型检查）。字段名需是导出的（首字母大写），模板中用首字母小写访问。
</Step>
</Stepper>

## 代码对照

```go
package main

import (
    "html/template"
    "net/http"
)

// 模板定义
const layoutHTML = `
<!DOCTYPE html>
<html>
<head><title>{{.Title}}</title></head>
<body>
  <header>{{template "header" .}}</header>
  <main>
    {{range .Users}}
      <div class="user">
        <h2>{{.Name}}</h2>
        <p>Email: {{.Email}}</p>
        {{if .Admin}}<span class="badge">Admin</span>{{end}}
      </div>
    {{end}}
  </main>
</body>
</html>
{{define "header"}}<h1>{{.Title}}</h1>{{end}}
`

type User struct {
    Name  string
    Email string
    Admin bool
}

type PageData struct {
    Title string
    Users []User
}

// 预编译模板（应用启动时执行一次）
var tmpl = template.Must(
    template.New("layout").Parse(layoutHTML),
)

func usersHandler(w http.ResponseWriter, r *http.Request) {
    data := PageData{
        Title: "User List",
        Users: []User{
            {"Alice", "alice@example.com", true},
            {"Bob", "bob@example.com", false},
            {"<script>alert('xss')</script>", "evil@test.com", false},
        },
    }
    // xss 会被自动转义为 &lt;script&gt;...
    tmpl.Execute(w, data)
}

func main() {
    http.HandleFunc("/users", usersHandler)
    http.ListenAndServe(":8080", nil)
}
```

## 常见误区

<Callout type="trap">
**误区：用 text/template 渲染 HTML**
`text/template` 和 `html/template` 语法相同，但 `text/template` 不做任何转义。如果你用它渲染 HTML，用户输入的 `&lt;script&gt;alert('xss')&lt;/script&gt;` 会被原样输出，导致 XSS 攻击。渲染 HTML 必须用 `html/template`，它会根据上下文自动转义。`text/template` 只用于生成代码、配置文件等非 HTML 场景。
</Callout>

<Callout type="trap">
**误区：每次请求都重新 Parse 模板**
`template.Parse` 是有开销的——词法分析、语法分析、构建 AST。如果在每个 Handler 中都调用 Parse，性能会很差。正确做法是在应用启动时（`init` 或 `main` 中）解析一次模板，用 `template.Must` 处理错误，之后每个请求只调用 `Execute` 复用已编译的 AST。
</Callout>

<Exercises>
**问题 1**：`html/template` 的"上下文感知转义"是什么意思？请举例说明同一个值在不同上下文中如何被不同地转义。

<Answer>
上下文感知转义指模板引擎根据插值 `{{.}}` 出现的位置（上下文），自动选择不同的转义策略。以 `{{.Content}}` 值为 `&lt;script&gt;alert(1)&lt;/script&gt;"&` 为例：

- HTML 文本中 `<div>{{.Content}}</div>`：`<` → `&lt;`，`>` → `&gt;`，输出 `&lt;script&gt;alert(1)&lt;/script&gt;"&amp;`
- HTML 属性中 `<input value="{{.Content}}">`：额外转义 `"` → `&#34;`，防止属性注入
- JavaScript 中 `&lt;script&gt;var x = "{{.Content}}";&lt;/script&gt;`：转义为 Unicode 编码 `\u003cscript...`，防止脚本注入
- URL 中 `<a href="{{.Content}}">`：转义为 URL 编码 `%3Cscript...`

这种机制让开发者无需手动判断转义，模板引擎自动防止 XSS。关键前提：必须使用 `html/template` 而非 `text/template`。
</Answer>

**问题 2**：设计一个博客文章页面，需要布局模板（layout.html）和内容模板（article.html）组合。布局包含 header/footer，内容区域引用文章模板。请写出两个模板的结构和 Go 渲染代码。

<Answer>
layout.html:
```
{{define "layout"}}
<!DOCTYPE html>
<html>
<head><title>{{.Title}}</title></head>
<body>
  <header>{{template "header" .}}</header>
  <main>{{template "content" .}}</main>
  <footer>&copy; 2024 Blog</footer>
</body>
</html>
{{end}}
```

article.html:
```
{{define "content"}}
<article>
  <h2>{{.Article.Title}}</h2>
  <time>{{.Article.Date}}</time>
  <div>{{.Article.Body}}</div>
</article>
{{end}}
```

Go 代码:
```go
var tmpl = template.Must(template.ParseFiles("layout.html", "article.html"))

func articleHandler(w http.ResponseWriter, r *http.Request) {
    data := struct {
        Title   string
        Article Article
    }{
        Title:   "My Blog",
        Article: Article{Title: "Go Templates", Date: "2024-01-01", Body: "Hello!"},
    }
    tmpl.ExecuteTemplate(w, "layout", data)
}
```
关键点：用 `{{define}}` 定义命名模板，`{{template "name" .}}` 引用，`ExecuteTemplate` 指定执行根模板。`template.Must` 在解析失败时 panic，适合初始化阶段。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="html/template">
Go 标准库的 HTML 模板引擎，提供上下文感知转义防止 XSS。工作流程：Parse（解析模板为 AST）→ Execute（注入数据并转义输出）。支持 `{{range}}`、`{{if}}`、`{{template}}` 等控制结构。与 `text/template` 语法兼容但增加安全转义。
</GlossaryItem>
<GlossaryItem term="上下文感知转义">
`html/template` 的核心安全特性——根据插值位置的上下文（HTML 文本、属性值、JavaScript、CSS、URL）自动选择合适的转义策略。同一值在 HTML 中转义 `<`，在 JS 中转义为 Unicode，在 URL 中百分号编码。开发者无需手动转义，引擎自动防止 XSS。
</GlossaryItem>
<GlossaryItem term="Action">
模板中 `{{}}` 包围的指令，如 `{{.Field}}` 输出字段、`{{range}}...{{end}}` 遍历、`{{if}}...{{end}}` 条件、`{{template "name" .}}` 引用子模板。Action 在 Execute 阶段被求值替换，非 Action 的文本原样输出。
</GlossaryItem>
<GlossaryItem term="template.Must">
辅助函数，包装 `template.Parse` 等返回 `(Template, error)` 的函数。如果 error 非 nil 则 panic。用于初始化阶段——模板解析错误意味着程序无法正常工作，应该在启动时就暴露而非运行时处理。`var tmpl = template.Must(template.ParseFiles(...))`。
</GlossaryItem>
</Glossary>
