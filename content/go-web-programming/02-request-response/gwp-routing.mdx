## 从谁接收TCP连接开始

先预测：调用ListenAndServe后，main是否继续执行下一行？正常运行时它阻塞并持续接收连接，只有服务停止或失败才返回。<Term def="监听地址、超时、handler和错误返回共同组成的服务器运行协议。">HTTP server lifecycle contract</Term>要求启动错误不能被忽略。

## Go net/http库

net/http把连接管理、消息解析与handler调用连接起来。<Term def="把传输层请求转换为Request与ResponseWriter调用的标准库边界。">nethttp serving boundary</Term>让应用通常不直接操作socket，但仍要配置header读取、空闲和关闭策略。

```go
server := &http.Server{
    Addr: ":8080",
    Handler: routes(),
    ReadHeaderTimeout: 5 * time.Second,
}
log.Fatal(server.ListenAndServe())
```

## Handler与HandlerFunc

Handler只要求`ServeHTTP(http.ResponseWriter, *http.Request)`；普通函数通过HandlerFunc适配。<Term def="接收结构化请求并向唯一ResponseWriter提交响应的接口协议。">handler interface contract</Term>支持对象持有依赖，也支持函数保持轻量。

```go
type healthHandler struct{}
func (healthHandler) ServeHTTP(w http.ResponseWriter, _ *http.Request) {
    w.WriteHeader(http.StatusNoContent)
}
```

## Multiplexer

Mux根据模式选择handler。<Term def="从请求host、method或path到单一handler的确定匹配规则。">multiplexer matching invariant</Term>需要覆盖具体路径、子树、根fallback和不支持方法；路由只分派，不替代认证与业务验证。

```go
mux := http.NewServeMux()
mux.Handle("GET /health", healthHandler{})
mux.HandleFunc("GET /threads/", showThread)
```

## 默认Mux与显式依赖

包级`http.HandleFunc`写入DefaultServeMux，测试和多个服务器会共享全局状态。<Term def="由调用方创建并传入mux，使路由集合具有明确所有者的设计。">explicit router ownership</Term>更容易隔离测试和审查暴露面。

## HTTP/2支持

HTTP/2在一条连接上复用stream并压缩header。<Term def="传输协议升级不改变应用Handler语义的兼容边界。">HTTP version abstraction</Term>要求代码不依赖连接对应单请求或响应写入时序巧合；TLS配置和客户端协商由服务器层处理。

## 验收实验：路由与失败矩阵

分别制造端口占用、未知路径、方法不匹配、handler panic和响应二次写入，保存启动错误、状态码和日志。再用两个独立mux运行测试，证明路由状态不会跨用例污染；切换HTTP版本确认handler断言保持一致。

<Callout type="trap" title="ListenAndServe返回nil表示成功退出">它通常以错误返回；正常关闭可能是ErrServerClosed，需要按关闭上下文区分。</Callout>
<Callout type="trap" title="路由命中就代表请求合法">路由只选择处理器，参数、身份、权限和领域不变量仍需后续验证。</Callout>
