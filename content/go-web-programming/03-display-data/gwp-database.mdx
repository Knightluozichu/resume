## 从数据需要活多久开始

先预测：把论坛主题保存在map中，进程重启后是否仍存在？不会。先决定寿命、容量、查询和并发，再选择介质。


## 内存存储

Struct、slice和map提供低延迟，但状态只存在于进程内。适合缓存、测试替身或临时状态；多goroutine读写必须同步，快照与恢复要另行设计。

```go
type MemoryStore struct {
    mu sync.RWMutex
    threads map[int]Thread
}
```

## CSV与Gob文件存储

CSV便于交换和检查，gob保留Go类型信息但与Go结构耦合。不能直接覆盖唯一好文件；部分写入、进程崩溃和schema变化都要测试。

```go
tmp, err := os.CreateTemp(dir, "threads-*.tmp")
if err != nil { return err }
defer tmp.Close()
// encode, sync, close, then rename
```

## Go与SQL

database/sql是连接池和查询抽象，`*sql.DB`不是单连接。要求使用占位参数、区分ErrNoRows、检查Rows.Err并关闭Rows。


## CRUD与事务

Create、retrieve、update、delete必须定义未找到、重复键和并发更新行为。由BeginTx、Commit和Rollback明确拥有，不能跨请求泄漏。

```go
tx, err := db.BeginTx(ctx, nil)
if err != nil { return err }
defer tx.Rollback()
if _, err := tx.ExecContext(ctx, query, args...); err != nil { return err }
return tx.Commit()
```

## SQL关系

用户、主题和回复通过主外键连接，一对多与多对多影响查询和删除规则。应由数据库约束与应用验证双层保护。

## Go关系映射器

Mapper可减少扫描和SQL样板，但可能隐藏N+1查询、事务和字段映射。要求日志或测试能观察执行SQL数量和参数。


## 验收实验：同一仓库三种实现

为Thread仓库定义同一接口，分别实现内存、文件和SQL版本；运行共享契约测试。注入并发写、部分文件写、ErrNoRows、扫描失败和Commit失败，确认每种实现返回一致领域结果且不泄漏资源。
