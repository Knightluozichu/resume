## 从模板为什么分解析和执行开始

先预测：每次请求都从磁盘读取并Parse模板是否正确？能运行但放大I/O、语法失败和并发复杂度。应在启动期发现语法错误。


## Template与Template Engine

Template是含占位动作的展示程序，engine负责解析、绑定函数和执行。要求模板命名稳定，执行时不访问隐藏全局状态。

```go
templates := template.Must(template.New("base").Funcs(funcs).ParseFS(files, "*.html"))
```

## text/template与html/template

两者共享语法，但html/template按HTML、属性、URL、CSS和JavaScript位置做上下文转义。是默认安全边界；不要把不可信字符串转成template.HTML绕过。


## Action、参数与变量

Action位于双花括号中，可访问dot、字段、方法和变量。要求空值和缺失字段有明确策略，复杂业务判断留在handler。

```html
{{range .Threads}}
  <a href="/thread/{{.ID}}">{{.Title}}</a>
{{else}}
  <p>No threads</p>
{{end}}
```

## Pipeline与Function

Pipeline把前一步结果作为后一步参数，函数可返回值或`(value, error)`。适合格式化，不适合数据库、网络和不可控副作用。

## 嵌套模板与Layout

define声明命名模板，template调用子模板，block提供可覆盖默认内容。避免复制header与footer，并要求数据契约一致。

```html
{{define "base"}}<main>{{block "content" .}}{{end}}</main>{{end}}
{{define "content"}}<h1>{{.Title}}</h1>{{end}}
```


## 验收实验：同一输入四种上下文

把包含引号、尖括号、URL分隔符和脚本片段的输入分别放到文本、属性、URL和JavaScript位置，保存html/template输出；再与text/template比较。故意使用未知模板、失败函数和错误数据形状，确认错误在响应提交前可诊断。
