## 直觉引入

把 Go Web 应用部署到生产就像开店营业：你的代码是"手艺"，部署架构是"店铺装修"。Go 的独特优势是——你的手艺可以打包成一个"自带厨房的餐车"（单二进制），推到哪里都能直接营业，不需要现场搭厨房（安装运行时依赖）。

但光有餐车不够，你还需要：门口保安（Nginx 反向代理 + TLS）、营业招牌（健康检查）、收摊流程（优雅关闭）、监控摄像头（结构化日志 + Prometheus）。这些是把"能跑"变成"能稳定服务"的关键。

## 概念讲解

### 单二进制与 Docker 容器化

<Term def="Go 编译为单个静态链接二进制文件（CGO_ENABLED=0），无外部依赖。Docker 多阶段构建第一阶段编译，第二阶段用 scratch 或 alpine 镜像运行，最终镜像极小（~10-20MB）。">

```dockerfile
# 构建阶段
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o server -ldflags="-s -w" .

# 运行阶段（scratch = 空镜像，最小化攻击面）
FROM scratch
COPY --from=builder /app/server /server
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
EXPOSE 8080
ENTRYPOINT ["/server"]
```

`-ldflags="-s -w"` 去除调试信息减小体积。`scratch` 镜像连 shell 都没有，攻击面最小。`ca-certificates` 是 HTTPS 客户端请求所需的根证书。

</Term>

### 反向代理与 TLS 终止

<Term def="Nginx 作为反向代理：接收 HTTPS 请求（443），终止 TLS 加密，将明文 HTTP 转发给后端 Go 服务（8080）。后端不需要处理 TLS，简化证书管理和性能开销。">

```
用户 --HTTPS--> Nginx (443, TLS终止) --HTTP--> Go服务 (8080)
```

Nginx 配置核心：

```nginx
server {
    listen 443 ssl;
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Nginx 还负责负载均衡（多 Go 实例）、静态文件服务、Gzip 压缩、限流。

</Term>

### 优雅关闭

<Term def="优雅关闭指服务器收到关闭信号后：1) 停止接收新连接 2) 等待处理中的请求完成 3) 关闭数据库连接池等资源 4) 退出进程。确保零停机部署——不丢失正在处理的请求。">

```go
func main() {
    server := &http.Server{Addr: ":8080", Handler: mux}

    go func() {
        if err := server.ListenAndServe(); err != http.ErrServerClosed {
            log.Fatal(err)
        }
    }()

    // 等待中断信号
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
    <-quit

    // 给正在处理的请求 30 秒完成
    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()
    server.Shutdown(ctx) // 优雅关闭

    db.Close() // 关闭数据库连接池
    log.Println("Server shutdown complete")
}
```

</Term>

<Step title="第一步：编译与容器化">
`CGO_ENABLED=0 go build -o server` 编译为静态二进制。写多阶段 Dockerfile：builder 阶段编译，scratch 阶段运行。`docker build -t myapp .` 构建镜像，`docker run -p 8080:8080 myapp` 运行。镜像应带版本标签而非 latest，便于回滚。
</Step>
<Step title="第二步：配置 Nginx 反代">
Nginx 监听 443 端口处理 HTTPS，proxy_pass 转发到 Go 服务的 8080。设置 X-Forwarded-For 等头让 Go 获取真实客户端 IP。用 Let's Encrypt + certbot 自动获取免费 TLS 证书。Nginx 配置定期 reload 更新证书。
</Step>
<Step title="第三步：实现优雅关闭">
用 `signal.Notify` 捕获 SIGTERM（Docker stop / Kubernetes 发送）。收到信号后调用 `server.Shutdown(ctx)` 停止接收新连接并等待处理中请求完成。设置超时（如 30s）防止卡死。关闭数据库连接池、刷新日志缓冲。部署时旧实例优雅退出，新实例就绪——零停机。
</Step>
</Stepper>

## 代码对照

```go
package main

import (
    "context"
    "database/sql"
    "log/slog"
    "net/http"
    "os"
    "os/signal"
    "syscall"
    "time"
)

func main() {
    // 结构化日志（Go 1.21+ slog）
    logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
    slog.SetDefault(logger)

    // 配置从环境变量读取（12-Factor App）
    port := os.Getenv("PORT")
    if port == "" {
        port = "8080"
    }
    dsn := os.Getenv("DATABASE_URL")

    db, err := sql.Open("postgres", dsn)
    if err != nil {
        slog.Error("DB connection failed", "error", err)
        os.Exit(1)
    }
    defer db.Close()
    db.SetMaxOpenConns(25)

    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        if err := db.Ping(); err != nil {
            w.WriteHeader(503)
            w.Write([]byte(`{"status":"unhealthy"}`))
            return
        }
        w.Write([]byte(`{"status":"ok"}`))
    })
    mux.HandleFunc("GET /", handler)

    server := &http.Server{
        Addr:         ":" + port,
        Handler:      mux,
        ReadTimeout:  10 * time.Second,
        WriteTimeout: 30 * time.Second,
        IdleTimeout:  120 * time.Second,
    }

    go func() {
        slog.Info("Server starting", "port", port)
        if err := server.ListenAndServe(); err != nil && err != http.ErrServerClosed {
            slog.Error("Server failed", "error", err)
            os.Exit(1)
        }
    }()

    // 优雅关闭
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
    sig := <-quit
    slog.Info("Shutting down", "signal", sig.String())

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    if err := server.Shutdown(ctx); err != nil {
        slog.Error("Forced shutdown", "error", err)
    }
    slog.Info("Server stopped")
}
```

## 常见误区

<Callout type="trap">
**误区：Docker 镜像用 latest 标签**
`docker build -t myapp:latest` 看似方便，但在生产环境中是灾难——你无法区分当前运行的是哪个版本，回滚时不知道回退到哪个镜像。始终用语义化版本标签：`myapp:v1.2.3` 或 Git commit SHA：`myapp:abc1234`。配合 CI/CD 自动打标签，确保每次部署都可追溯、可回滚。
</Callout>

<Callout type="trap">
**误区：不设 HTTP 超时**
`http.ListenAndServe(":8080", nil)` 默认无超时——慢速攻击者可以打开连接不发数据，耗尽服务器的文件描述符。生产环境必须设置 `ReadTimeout`（读请求超时）、`WriteTimeout`（写响应超时）、`IdleTimeout`（Keep-Alive 空闲超时）。合理的值：Read 10s、Write 30s、Idle 120s。对于 API 上传大文件场景可能需要单独调整。
</Callout>

<Exercises>
**问题 1**：Go 的优雅关闭（Graceful Shutdown）需要哪几个步骤？为什么 `server.Shutdown(ctx)` 比直接 `os.Exit(0)` 更好？

<Answer>
优雅关闭步骤：
1. 捕获信号：`signal.Notify(quit, SIGINT, SIGTERM)` 监听中断信号
2. 停止监听：`server.Shutdown(ctx)` 关闭监听端口，不再接受新连接
3. 等待处理：已接受的连接继续处理，直到完成或超时
4. 释放资源：关闭数据库连接池、刷新日志、关闭文件句柄
5. 退出进程

`server.Shutdown(ctx)` 比 `os.Exit(0)` 好的原因：
- `os.Exit(0)` 立即终止进程，正在处理的请求被中断——用户看到 502 错误，数据可能写入一半
- `Shutdown` 给正在处理的请求时间完成（ctx 超时控制），确保不丢数据
- `Shutdown` 允许执行 `defer`（如 `db.Close()`），`os.Exit` 不执行 defer
- 在 Kubernetes/Docker 滚动更新中，优雅关闭确保旧实例处理完请求再退出，新实例接管——零停机
</Answer>

**问题 2**：设计一个 Go Web 应用的 Docker 多阶段构建，要求最终镜像小于 20MB，并说明每个阶段的职责。

<Answer>
```dockerfile
# 阶段1：构建
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-s -w" -o app .

# 阶段2：运行
FROM scratch
COPY --from=builder /app/app /app
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
EXPOSE 8080
ENTRYPOINT ["/app"]
```

各阶段职责：
- **builder 阶段**：用完整 Go 工具链编译代码。先 `go mod download` 利用 Docker 层缓存——代码变更时只重新编译，不重新下载依赖。`CGO_ENABLED=0` 生成纯静态二进制（scratch 镜像无 libc）。`-ldflags="-s -w"` 去除符号表和调试信息，减小体积。
- **运行阶段**：`scratch` 是空镜像（0 字节），只包含我们 COPY 进去的二进制和 CA 证书。CA 证书用于 HTTPS 客户端请求（如调用第三方 API）。最终镜像约 10-15MB——只有二进制本身。无 shell、无包管理器，攻击面最小。

体积优化关键：多阶段构建丢弃 builder 阶段的 Go 工具链和源码，scratch 无任何基础层，`-s -w` 裁剪二进制。如果需要调试工具可以用 `alpine`（~5MB）代替 scratch。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Docker 多阶段构建">
用多个 FROM 阶段构建镜像：第一阶段用完整工具链编译代码，第二阶段只 COPY 编译产物到最小化镜像。最终镜像不含编译器和源码，体积小、攻击面小。Go 特别适合——静态编译二进制可放入 `scratch`（空镜像）中运行。
</GlossaryItem>
<GlossaryItem term="TLS 终止">
反向代理（如 Nginx）在入口处解密 HTTPS 流量，将明文 HTTP 转发给后端服务。后端不需要处理 TLS 加密/解密——简化证书管理（证书只在 Nginx 上配置）、减少后端 CPU 开销、便于集中管理 TLS 策略。
</GlossaryItem>
<GlossaryItem term="优雅关闭">
服务器收到关闭信号后，停止接受新连接，等待正在处理的请求完成（带超时），释放资源后退出。Go 中通过 `signal.Notify` 捕获 SIGTERM + `server.Shutdown(ctx)` 实现。确保部署时不丢失请求、不中断数据写入。
</GlossaryItem>
<GlossaryItem term="12-Factor App">
SaaS 应用方法论十二条原则，其中配置管理原则：配置（数据库连接串、API 密钥、端口）通过环境变量注入，不硬编码在代码中。Go 中用 `os.Getenv("KEY")` 读取，配合 `flag` 或 `envconfig` 库。使同一二进制能在开发/测试/生产环境运行。
</GlossaryItem>
</Glossary>
