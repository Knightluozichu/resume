## 从单二进制为何仍不够开始

先预测：`go build`成功后，复制一个文件到服务器就一定能运行完整Web应用吗？不一定，模板、静态文件、证书、配置和数据库schema都可能缺失。必须完整。


## 部署到独立服务器

独立主机提供最大控制权，也要求自行管理用户、目录、进程、日志、TLS、端口、防火墙和升级。要求非root运行、固定工作目录和可观察退出状态。

```sh
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o web ./cmd/web
sha256sum web templates/* public/*
```

## 部署到Heroku

原书展示Heroku的构建和dyno模型。应用监听平台提供的PORT，持久状态放外部服务，本地文件系统不可作为长期数据库。

## 部署到Google App Engine

App Engine提供托管实例、路由和伸缩，但有运行时与服务约束。需要在设计期验证超时、文件、网络和后台任务限制。


## 部署到Docker

Docker镜像封装文件系统与启动命令，不自动解决配置、数据和安全。要求多阶段构建、固定基础镜像、非root用户和外部秘密。

```dockerfile
FROM golang:1.24 AS build
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -o /out/web ./cmd/web
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/web /web
ENTRYPOINT ["/web"]
```


## 部署方式比较

部署方法比较的维度包括控制权、运维负担、伸缩、启动时间、持久存储、网络、成本与供应商约束。不能只按命令多少选择。

## 健康、切换与回滚

发布先验证进程、依赖和关键请求，再切换流量；失败按版本回滚。要求测试产物与上线产物摘要一致。

```text
commit -> test report -> artifact digest -> deployment id -> probe result -> rollback digest
```


## 验收实验：同一版本两种目标

用同一提交构建独立二进制和Docker镜像，记录Go版本、依赖、资产与摘要。在临时环境运行健康、静态文件、模板和数据库迁移检查；故意缺失模板、错误PORT和失败迁移，确认切流前阻断并能回滚上一摘要。


## 本章回顾

本章覆盖部署到服务器、Heroku、Google App Engine、Docker和方法比较。部署的核心不是复制命令，而是完整发布物、平台约束、不可变身份和切流回滚证据。
