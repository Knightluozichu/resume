## 直觉：图像处理不仅是“最终画面加滤镜”

这 24 章处理的是离散信号：有的在 HDR/颜色域，有的在纹理/覆盖域，有的把几何烘焙为图像，有的从视频图像提取对象。滤波核、采样足迹、编码和时间曝光决定结果，不能用 Bloom + tone mapping 概括。

先预测：在线性 RGB 上做模糊与在 sRGB 数值上做同一核，结果是否相同？不相同。卷积是线性运算，必须先把非线性编码解码到正确工作域。

### GPU Gems 1 Ch21-27：HDR、颜色、过滤与框架

- **Real-Time Glow**：提取/扩散高亮并合成，建立早期 HDR glow 数据流；
- **Color Controls**：曝光、对比、饱和度和颜色变换的顺序与工作域；
- **Depth of Field: A Survey of Techniques**：比较 accumulation、分层与 post-process 景深伪影；
- **High-Quality Filtering**：用 GPU 纹理取样组合更高阶重建/缩放核；
- **Fast Filter-Width Estimates with Texture Maps**：在缺少方便导数时估计映射足迹宽度；
- **The OpenEXR Image File Format**：half、HDR 通道、压缩、窗口/元数据和生产交换；
- **A Framework for Image Processing**：将 GPU filter 组织成资源、pass 和依赖图。

离散卷积：

$$
y[p]=\sum_{q\in K}k[q]x[p-q].
$$

<Term def="为每个输出样本定义源图像邻域和权重，用于重建、缩放、模糊、锐化或特征提取的离散函数">重建滤波核</Term>应说明是否归一化、是否有负 lobes、边界如何扩展及在哪个颜色域执行。

```glsl
vec3 convolveLinear(sampler2D src, vec2 uv, vec2 texel) {
  vec3 sum = vec3(0.0); float weight = 0.0;
  for (int i=0; i<tapCount; ++i) {
    vec3 c = decodeToLinear(texture(src, uv + offsets[i]*texel).rgb);
    sum += weights[i] * c; weight += weights[i];
  }
  return sum / weight;
}
```

Glow/Bloom 的阈值、软膝、降采样和合成位置由创作目标决定。若是模拟镜头散射，通常在 scene-linear/high-range 域工作；若是显示风格光晕，也可能在显示映射后设计。不存在无条件“必须在 tone mapping 前”。

### Footprint、DOF 与 OpenEXR

纹理足迹可由导数近似，LOD：

$$
\lambda\approx\log_2\max(\|\partial(u,v)/\partial x\|,\|\partial(u,v)/\partial y\|).
$$

Fast Filter-Width Estimates 与 Mipmap-Level Measurement 都要求把像素覆盖的纹理区域可视化，而非只看最终纹理是否模糊。

薄透镜景深的 circle of confusion（比例形式）随焦距差增大：

$$
c\propto A\left|\frac{z-z_f}{z}\right|,
$$

其中 $A$ 与光圈相关、$z_f$ 为焦平面。后处理 DOF 缺少被前景遮挡的背景信息，容易 foreground bleed；分层/散射 gather 与真实多样本各有边界。

<Term def="支持高动态范围像素、16 位 half、任意通道、data/display window、压缩和元数据的生产图像交换格式">OpenEXR</Term>不是“让画面自动 HDR”。读写必须保持 channel name/type、色度/颜色空间和 premultiplication 元数据约定。

### GPU Gems 2 Ch20-28：高质量采样与生产图像管线

- **Fast Third-Order Texture Filtering**：以有限硬件采样组合三阶核；
- **High-Quality Antialiased Rasterization**：提高 coverage/subpixel 采样质量；
- **Fast Prefiltered Lines**：用预积分线核稳定渲染亚像素线；
- **Hair Animation and Rendering in the Nalu Demo**：毛发模拟、深度/alpha 与各向异性外观形成图像层；
- **Using Lookup Tables to Accelerate Color Transformations**：1D/3D LUT 近似复杂颜色映射；
- **GPU Image Processing in Apple's Motion**：可组合效果、资源生命周期和实时创作工作流；
- **Implementing Improved Perlin Noise**：连续程序信号及其 GPU 实现；
- **Advanced High-Quality Filtering**：更广核、更高阶和 separable/优化实现；
- **Mipmap-Level Measurement**：测量实际 minification level 和 footprint 误差。

<Term def="把多维颜色变换预采样为网格，运行时通过一维或三维插值近似原函数的查找结构">颜色查找表</Term>必须固定输入/输出颜色空间、range、grid 分辨率和插值。LUT 误差要用色差/最大误差测量，不能只目测。

```cpp
ImageGraph graph;
graph.add("decode", input, linearWorkingImage);
graph.add("color-lut", linearWorkingImage, gradedImage);
graph.add("filter", gradedImage, filteredImage);
graph.add("encode", filteredImage, displayOutput);
graph.compileResourceLifetimes();
graph.executeWithGpuQueries();
```

Nalu hair 不只是粒子：图像侧要处理多层透明排序/近似、深度阴影和 alpha filtering。Improved Perlin Noise 在本书自然页已有算法复现，此处关注它作为可过滤图像信号进入 Motion/texture pipeline 的频谱与 aliasing。

### GPU Gems 3 Ch21-28：几何图像化与屏幕时空效果

- **True Impostors**：在 impostor 纹理中编码深度/表面并按视线重建，不是普通 billboard；
- **Baking Normal Maps on the GPU**：从高低模对应关系生成切线空间 normal map，并处理 cage/UV 接缝；
- **High-Speed, Off-Screen Particles**：把不可见/离屏粒子更新和存储从可见渲染路径解耦；
- **The Importance of Being Linear**：纹理解码、光照、过滤、混合与显示编码的颜色合同；
- **Rendering Vector Art on the GPU**：曲线/边界的解析或近似 coverage，而非先高分辨率截图；
- **Object Detection by Color: Using the GPU for Real-Time Video Image Processing**：颜色分类、形态处理/连通区域与视频流延迟；
- **Motion Blur as a Post-Processing Effect**：用深度/速度重建曝光期轨迹并处理遮挡；
- **Practical Post-Process Depth of Field**：可部署 DOF 的分层、scatter/gather 和伪影控制。

## 线性光与颜色出口

<Term def="与辐射/光子贡献近似成比例、可以进行加权平均和能量合成的颜色数值域">场景线性颜色</Term>是 lighting、filtering、resampling 和 alpha composite 的默认工作域。sRGB 是编码传输函数，不是“gamma 2.2 精确等价”。

直通 alpha 合成在线性域：

$$
C_o=\alpha_sC_s+(1-\alpha_s)C_d.
$$

若源为 premultiplied，存储 $C'_s=\alpha_sC_s$，则 $C'_o=C'_s+(1-\alpha_s)C'_d$。OpenEXR、粒子、hair 和后处理图之间必须统一 straight/premultiplied。

## Impostor、Normal Baking 与 Vector Coverage

True Impostors 用深度/层信息让平面表示产生视差和正确交点；验收旋转视角、silhouette、层穿插与深度写入。Normal baking 要比较高模几何法线经 tangent basis 编码后的结果，检查 mirrored UV handedness 和 cage miss。

矢量图形的核心是像素对曲线/填充区域的 coverage。预滤波线把距离到线的积分/lookup 映射为 alpha；High-Quality Antialiased Rasterization 和 Rendering Vector Art on the GPU 都要以 subpixel reference 检查边缘面积，而不是只看锯齿少。

## 时域：Motion Blur、DOF 与视频

曝光运动模糊近似积分：

$$
C=\frac1{\Delta t}\int_{t_0}^{t_0+\Delta t}L(x(t),t)dt.
$$

post-process velocity blur 只有当前可见层的速度/深度，disocclusion 无历史背景；需要 neighborhood clamp、前后景分离和相机/物体速度正确性。DOF 也有类似层缺失问题。

视频颜色检测要固定 camera transfer、white balance 和颜色空间；阈值后还需形态学/连通性，并记录端到端 latency。GPU 更快不代表分类在光照变化下稳健。

```glsl
vec3 accumulateMotion(sampler2D color, sampler2D depth, vec2 uv, vec2 velocity) {
  vec3 sum = vec3(0.0); float w = 0.0;
  for (int i=0; i<sampleCount; ++i) {
    float t = (i + 0.5) / sampleCount - 0.5;
    vec2 q = uv + t * velocity;
    float accept = depthCompatible(depth, uv, q);
    sum += accept * texture(color, q).rgb; w += accept;
  }
  return sum / max(w, 1e-5);
}
```

## 常见误区

<Callout type="trap">
**现象 →** 页面只讲 Bloom 和 tone mapping，却宣称覆盖 GPU Gems 图像章节。
**原因 →** 忽略过滤、格式、图像图、几何烘焙、矢量覆盖、视频和时域重建。
**修法 →** 按 24 章清单分别保留信号、工作域、边界和参考判据。
</Callout>

<Callout type="trap">
**现象 →** 直接在 sRGB 数值上模糊/缩放后出现暗边。
**原因 →** 在非线性编码域做线性加权。
**修法 →** 先解码到约定工作域，正确处理 premultiplied alpha，过滤后再编码输出。
</Callout>

<Callout type="trap">
**现象 →** post-process DOF/运动模糊在轮廓泄漏背景或前景颜色。
**原因 →** 单层 depth/velocity 无法表示被遮挡表面，且采样未做层兼容。
**修法 →** 分层/散射或 depth-aware 权重，明确 disocclusion 回退，并与多样本参考序列比较。
</Callout>

## 练习

<Exercises>

**问题 1：High-Quality Filtering 与 The Importance of Being Linear 如何相互约束？**

<Answer>
高质量核只有在正确信号域加权才有意义。若输入为 sRGB 编码或 straight-alpha 边缘，直接卷积会改变亮度/引入色边；应解码线性并通常预乘 alpha，再应用核和重新编码。
</Answer>

**问题 2：True Impostor 与普通 billboard 的差异怎么验证？**

<Answer>
从离轴视角和相互穿插场景检查内部视差、silhouette、深度测试与遮挡。普通 billboard 只是一张平面颜色；true impostor 利用深度/表面表示沿视线重建交点。
</Answer>

**问题 3：设计覆盖 24 章的图像回归包。**

<Answer>
包含 HDR/OpenEXR 色卡、impulse/edge/线条/矢量、缩放纹理、hair/particle alpha、impostor/normal bake 模型、视频颜色目标，以及焦点和运动轨迹；保存线性中间图、coverage、depth/velocity、LUT 坐标和参考误差。
</Answer>

</Exercises>
