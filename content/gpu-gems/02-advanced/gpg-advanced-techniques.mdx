## 直觉：高级工程不是换一种渲染路径

这些章节一半讨论如何测量管线、创作和集成 shader，另一半讨论怎样把稀疏体数据、GI、视觉算法和困难格式映射到 GPU。前向/延迟只是局部架构选择，不能代替工具接口、数据表示和 conservative coverage。

先预测：把 fragment shader 指令减半后 GPU 时间不变，是优化失败还是测量错误？两者都可能；先通过分辨率、纹理带宽、顶点量和 CPU 提交的受控缩放识别真正瓶颈。

<Term def="通过单独改变候选阶段工作量并观察帧时间响应，定位限制整条 GPU/CPU 流水的最慢资源或依赖">瓶颈实验</Term>是 Graphics Pipeline Performance 的核心方法。

### GPU Gems 1 Ch28-36：性能、创作与生产集成

- **Graphics Pipeline Performance**：用控制变量定位 transform、raster、fragment、texture、framebuffer 或 CPU bottleneck；
- **Efficient Occlusion Culling**：异步 query、层次代理和保守可见性；
- **The Design of FX Composer**：shader IDE、参数语义、预览场景和插件架构；
- **Using FX Composer**：效果创作、参数调整、pass/technique 和资产工作流；
- **An Introduction to Shader Interfaces**：用明确定义输入输出组合 shader fragments；
- **Converting Production RenderMan Shaders to Real-Time**：识别离线 shader 假设，降维/预计算/近似到实时路径；
- **Integrating Hardware Shading into Cinema 4D**：把 GPU preview 接入既有 CPU/内容工具并维持一致性；
- **Leveraging High-Quality Software Rendering Effects in Real-Time Applications**：预烘焙或混合复用高质量软件效果；
- **Integrating Shaders into Applications**：effect 语义、annotation、状态、资源和应用生命周期。

若流水阶段可重叠，稳定吞吐近似由最慢阶段决定：

$$
T_{frame}\gtrsim\max(T_{CPU},T_{vertex},T_{raster},T_{fragment},T_{memory}).
$$

<Term def="用屏幕分辨率、shader 指令、纹理访问、顶点数、blend 或提交量的定向缩放，观察时间斜率来判断受限阶段的方法">控制变量剖析</Term>比只看总 FPS 更能解释原因。

```cpp
for (Experiment e : bottleneckExperiments) {
  applyOneChange(e); // resolution, texture, vertex, fragment, submission
  warmUp();
  Samples s = measureCpuGpuQueries();
  reportSlopeAgainstWork(e, s);
  restoreBaseline();
}
```

Efficient Occlusion Culling 已在几何页解释 query latency；此处强调 pipeline：立即 readback 会把 GPU/CPU 串行，节省的 fragment 工作必须大于 proxy/query/等待成本。

### Shader interface 与工具资产合同

<Term def="用语义、类型、资源需求和状态声明描述 shader 单元如何被工具、其他单元和应用组合的显式边界">Shader interface</Term>让 FX Composer、RenderMan 转译和宿主 DCC/应用共享参数意义。

```ts
type ShaderParameter = {
  semantic: string;
  valueType: "float" | "color" | "texture" | "matrix";
  colorSpace?: "scene-linear" | "sRGB";
  defaultValue: unknown;
  range?: [number, number];
  binding: string;
};
```

工具预览必须明确坐标、灯光、颜色管理、纹理和状态。RenderMan shader 可能依赖任意循环、射线、导数、闭包和高质量过滤；实时转换要标出预计算、LUT、纹理烘焙和删减项，不能只做语法翻译。

FX Composer/Cinema 4D/应用集成的验收是同一资产在工具预览、离线参考和运行时的参数/图像一致性，以及 shader reload、错误日志、版本迁移和资源生命周期。

### GPU Gems 2 Ch37-42：稀疏数据、GI 与覆盖

- **Octree Textures on the GPU**：把稀疏三维/表面数据编码为可在 GPU 遍历的 octree texture；
- **High-Quality Global Illumination Rendering Using Rasterization**：用 rasterization 收集/传播高质量 GI 中间量；
- **Global Illumination Using Progressive Refinement Radiosity**：按未发射能量逐步更新 patch radiosity；
- **Computer Vision on the GPU**：把图像算子和特征/匹配流水映射到 GPU；
- **Deferred Filtering: Rendering from Difficult Data Formats**：先生成可过滤中间表示，再推迟重建/过滤；
- **Conservative Rasterization**：只要 primitive 与像素 cell 相交就生成覆盖，支持 voxelization/collision 等。

## Octree texture 与 deferred filtering

<Term def="递归八分空间，只为有数据的节点分配子节点，并把索引/叶值编码为 GPU 可随机访问纹理的稀疏表示">Octree texture</Term>需要验证节点地址、child mask、最大深度、边界采样和缓存局部性。内存近似取决于占用节点而不是完整 $8^d$ 网格，但 pointer/indirection 有成本。

Deferred Filtering 针对直接插值困难的数据：先 raster/decode 到规则 screen/image representation，再在有邻域意义的空间过滤。它不是 deferred shading；验收格式解码、coverage holes、filter domain 和 reconstruction bias。

## Radiosity 与 rasterized GI

patch radiosity 离散方程：

$$
B_i=E_i+\rho_i\sum_j F_{ij}B_j.
$$

<Term def="每轮选择未分配能量最大的 patch，把其贡献按 form factor 发射给其他 patch，逐步逼近 radiosity 解的算法">渐进细化辐射度</Term>需要 form-factor reciprocity/energy、visibility 和收敛残差证据。GPU rasterization 可用 hemicube/投影方式估计可见 form factors，但分辨率与 alias 会影响能量。

```cpp
while (unshotEnergy > epsilon && iteration++ < maxIterations) {
  Patch shooter = selectMaxUnshotPatch();
  FormFactors F = rasterizeHemicubeVisibility(shooter);
  distributeEnergy(shooter, F, radiosity, unshot);
  logEnergyResidual(iteration, unshot);
}
```

High-Quality GI Using Rasterization 还可能将光传输问题重写为一系列 GPU 图像 pass。现代 compute/ray tracing 可替代部分载体，但原章“用 raster 做通用可见性/积分工具”的不变量应保留。

## Conservative raster 与 vision

<Term def="只要 primitive 与像素/voxel cell 有任意交集就报告覆盖的光栅化规则，保证不漏但可能产生额外 false positives">保守光栅化</Term>区别于中心样本规则。CPU oracle 可做 triangle-box intersection，对每个 cell 比较 false negative 必须为零；额外覆盖再由窄阶段过滤。

Computer Vision on the GPU 映射卷积、金字塔、特征和归约时要保留数值阈值与边界。性能需包含上传/下载和 pipeline latency；GPU kernel 快不等于端到端快。

## 常见误区

<Callout type="trap">
**现象 →** 用“前向还是延迟”覆盖这 15 章。
**原因 →** 忽略原章的性能实验、创作工具、shader 集成、稀疏表示、GI 和保守覆盖。
**修法 →** 按原章分别保留系统边界、数据结构和可测输出。
</Callout>

<Callout type="trap">
**现象 →** fragment 指令减少便宣布优化成功。
**原因 →** 没证明原场景 fragment-bound，可能受 bandwidth、vertex 或 CPU 提交限制。
**修法 →** 用控制变量剖析和异步 query 比较时间斜率，并保持参考图一致。
</Callout>

<Callout type="trap">
**现象 →** conservative raster 输出更多 cell 被当成错误。
**原因 →** 混淆保守阶段“不得漏”与精确相交阶段。
**修法 →** 先保证 false negative 为零，再统计 false positive 并用窄阶段过滤。
</Callout>

## 练习

<Exercises>

**问题 1：如何定位 fragment-bound？**

<Answer>
固定输出，降低分辨率/片段指令/纹理采样并观察 GPU 时间近似按像素工作下降；改变顶点数或 CPU 提交影响较小。用 timer/pipeline statistics 交叉验证，不用 FPS 单点猜测。
</Answer>

**问题 2：RenderMan shader 实时转换应保留什么证据？**

<Answer>
记录原参数/空间/颜色/过滤和依赖能力，标注预计算、LUT、烘焙和删减；在标准资产上比较离线、工具预览、运行时中间项与图像误差，并测目标预算。
</Answer>

**问题 3：怎样验收 progressive radiosity？**

<Answer>
用小场景解析/CPU form factors 对照，检查能量不增、reciprocity 趋势、unshot residual 单调收敛和最终 patch radiosity；扫描 hemicube 分辨率、遮挡和停止阈值。
</Answer>

</Exercises>

## 小结

15 章的高级性来自生产系统：测量真正瓶颈、把 shader 作为有接口资产集成，并把稀疏空间、GI、视觉和覆盖重写为 GPU 可执行表示。任何现代迁移都必须同时证明接口一致、数值/图像正确和规模化收益。
