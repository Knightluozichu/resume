## 直觉：几何复杂度不仅是“三角形多少”

这 15 章分别解决数据生成、驻留/流送、重复实例、可见性、连续曲面、像素位移、角色变形、植被层次和隐式表面。LOD 只是资源分配的一部分；错误的流送、遮挡等待或共享边会让三角形更少但画面更差、更慢。

先预测：遮挡查询精确返回 0，但 CPU 同帧等待结果后帧率下降，算法是否正确？可见性结果正确，调度却错误；query 必须跨帧/层次使用，避免把异步 GPU 变成同步函数。

### GPU Gems 2 Ch1-8：从植物到像素位移

- **Toward Photorealism in Virtual Botany**：以植物层级、器官和 growth/appearance 数据组织可缩放植被；
- **Terrain Rendering Using GPU-Based Geometry Clipmaps**：以相机为中心的嵌套规则网格复用拓扑并流送高度；
- **Inside Geometry Instancing**：比较 API/vertex constant/stream 等实例数据路径与批次上限；
- **Segment Buffering**：把动态几何分段并行填充/消费，减少 CPU/GPU 等待；
- **Optimizing Resource Management with Multistreaming**：按更新频率拆分顶点 streams，避免重传静态属性；
- **Hardware Occlusion Queries Made Useful**：延迟读取、层次代理和保守策略隐藏 query latency；
- **Adaptive Tessellation of Subdivision Surfaces with Displacement Mapping**：在当时硬件约束下把 subdivision/位移细节按误差自适应生成；
- **Per-Pixel Displacement Mapping with Distance Functions**：以距离函数指导像素级 ray-height intersection。

<Term def="围绕观察者维护若干同心、分辨率按二次幂变化的规则网格环，并增量更新进入窗口的高度样本">Geometry clipmap</Term>把地形拓扑固定化。第 $l$ 层网格间距：

$$
s_l=s_0 2^l.
$$

相机移动不足一个 coarse texel 时不必重建所有层；新行/列环形更新。层间 transition 需 morph/skirt 或一致采样防裂缝，并用高度频谱验证远层是否 alias。

```cpp
for (ClipLevel& level : levels) {
  IVec2 origin = snap(cameraXZ, level.spacing);
  Rect delta = level.moveWindow(origin);
  streamHeightTexels(level, delta);
  drawFixedRingMesh(level, morphBand(level));
}
```

### Instancing、streams 与 segment ownership

<Term def="共享网格和渲染状态、用每实例变换或参数区分多个对象，以减少重复数据与提交的绘制组织方式">几何实例化</Term>的收益取决于批次兼容和实例数据带宽。多 stream 把位置/法线等静态属性与动画/实例属性分离；segment buffering 用 ring/多段避免 CPU 覆写 GPU 正在读取的区域。

若每实例数据 $b_i$、网格顶点 $V$、单顶点属性 $b_v$，重复上传与实例化近似数据量：

$$
B_{repeat}=N Vb_v,\qquad B_{instance}=Vb_v+Nb_i.
$$

但 draw 内 shader 分支、不可见实例与 material divergence 可能抵消收益。现代 indirect/mesh shader 是扩展，不应抹去原章的批次和 stream 权衡。

### Occlusion query：结果延迟是核心

query 返回通过深度测试的 sample 数。若 CPU 立即等待，损失并行。可先画近到远、用上一帧结果、对 BVH 节点发 query，并在结果未就绪时保守绘制。

```cpp
for (Node* node : frontToBackHierarchy) {
  if (node->lastVisible || queryAvailable(node)) {
    bool visible = node->lastVisible || readQuery(node) > 0;
    if (visible) drawOrDescend(node);
  } else {
    drawOrDescend(node); // conservative fallback, no CPU stall
  }
  issueProxyQueryForNextFrame(node);
}
```

验收不仅看 culled count，还看 CPU wait、query 数、proxy false positive 与被节省 GPU 工作。

### Subdivision 与 distance-function displacement

屏幕误差可由世界误差 $e_w$ 投影近似：

$$
e_{px}\approx\frac{f_{px}}{z}e_w.
$$

相邻 patch 共享边必须使用一致 refinement，否则裂缝。原章早于现代固定 tessellation stages；现代 TCS/TES 或 compute mesh generation 可以承载同一误差与边合同，但不能倒写成原章使用了 Hull/Domain Shader。

<Term def="在切线空间沿视线遍历高度场，并用预计算距离/安全步长跳过不可能相交区间的像素位移求交">距离函数位移</Term>与 relief/cone stepping 相关。应与 dense march 比较漏碰、掠射角、薄峰和 UV 越界。

## Terrain 与 refinement：生成和显示分开验收

程序 terrain 需区分基础噪声、地貌约束、侵蚀/沉积与显示 LOD。生成高度正确不代表 clipmap sampling 无裂缝；显示稳定也不证明地形统计合理。

Generic Adaptive Mesh Refinement 的共同合同是：计算误差 → 标记 split/merge → 维护邻接一致 → compact/emit 新 mesh。现代 compute 可做 prefix sum/compaction，但要限制输出容量和检测非收敛 refinement。

## Crowd、blend shapes 与植被层次

blend shape：

$$
\mathbf p'=\mathbf p_0+\sum_j w_j\Delta\mathbf p_j.
$$

<Term def="把大量角色的动画帧/骨骼或形变状态编码为可随机访问 GPU 数据，并按实例选择和插值的群体渲染方式">GPU 群体动画</Term>要验证相位多样性、帧插值、skin/blend 顺序和 LOD transition。DirectX 10 章的 stream-output 路径可翻译为 compute/vertex pulling，但应记录原始数据流。

SpeedTree 与 procedural wind 要沿树层级传播：树干低频弯曲、枝条局部响应、叶片高频抖动。根节点、刚度、相位与空间 wind field 决定相干性；随机逐叶抖动不是完整树风动画。

```glsl
vec3 bendTree(vec3 p, TreeNode node, WindField wind) {
  vec3 low = wind.lowFrequency * node.trunkWeight;
  vec3 gust = sampleWind(p, time + node.instancePhase) * node.branchWeight;
  return rotateAroundPivot(p, node.pivot, low + gust * node.flexibility);
}
```

## Metaball：隐式场到点表示

<Term def="若干局部核函数叠加形成的隐式标量场，其等值面表达平滑融合体">Metaball 场</Term>：

$$
F(\mathbf x)=\sum_i \phi_i(\|\mathbf x-\mathbf c_i\|),\qquad F(\mathbf x)=\tau.
$$

Point-Based Visualization 以 GPU points/sprites 近似可见 surface contribution。验收等值阈值、融合拓扑、深度排序/重建、法线 $\nabla F$ 和 point density；不能只显示一团 alpha blobs。

## 常见误区

<Callout type="trap">
**现象 →** 用现代 Hull/Domain Shader 代码宣称复刻 GPU Gems 2 Ch7。
**原因 →** 忽略原章硬件年代和算法数据流。
**修法 →** 先还原 subdivision/refinement/位移与共享边合同，再把现代 stage 标为迁移实现。
</Callout>

<Callout type="trap">
**现象 →** occlusion query 剔除准确却更慢。
**原因 →** CPU 同帧同步等待或 query 太细碎。
**修法 →** 延迟/层次/保守读取，统计 wait、query overhead 和节省工作，按阈值关闭无收益 query。
</Callout>

<Callout type="trap">
**现象 →** terrain/trees 单帧无裂缝，移动时出现 ring、LOD 或风场跳变。
**原因 →** 只验收静态几何，未检查跨层 morph、数据流送和时间相位。
**修法 →** 固定相机与风场轨迹，记录 level/LOD/phase 可视化和帧间差。
</Callout>

## 练习

<Exercises>

**问题 1：Geometry clipmap 为什么能减少地形重建？**

<Answer>
各层使用固定规则环网格，只随相机按 texel 对齐平移；移动时仅更新新进入窗口的行列高度，拓扑可复用。层间通过 morph/transition 连接，并保留远层低频表示。
</Answer>

**问题 2：实例化、multistreaming 和 segment buffering 分别解决什么？**

<Answer>
实例化减少重复网格与提交；multistreaming 按更新频率拆属性，避免重传静态数据；segment buffering 管理 CPU/GPU 并发访问动态区域。三者可组合，但合同不同。
</Answer>

**问题 3：设计覆盖 15 章的综合场景。**

<Answer>
程序地形由 geometry clipmap 显示，森林用 SpeedTree/instancing/multistreaming 和层次风，crowd 含 blend shapes，建筑做层次 occlusion，近景 patch 自适应 subdivision/位移，水边 metaball 可视化；记录流送、query、LOD、裂缝和吞吐。
</Answer>

</Exercises>

## 小结

15 个几何原章共同回答数据怎样生成、驻留、复用、剔除、细化、变形和转为可见表面。完整复现必须保留时代数据流与算法不变量，再明确现代 tessellation/compute/mesh 路径，不能把所有章节压成距离 LOD。
