## 直觉：GPU 计算不是从 Compute Shader 开始的

第一卷把数组编码成纹理，用 fragment shader 逐元素计算并 ping-pong render target；第二卷抽象 streaming processor、gather、reduction 和数据结构；第三卷 CUDA 提供线程块、共享存储和更一般 scatter。若把三卷都重写成现代 work group，会丢失算法为何适配/不适配当时 GPU 的关键。

先预测：一个现代 compute 版 reduction 比原 fragment-pass 快，是否说明原章算法已被“替代”？只说明载体性能变化；树形归约的工作量、跨度、结合律和数值顺序仍需复现。

<Term def="把同一个 kernel 应用于大量数据元素，并把存储访问和控制流组织为可并行流的计算模型">流式计算模型</Term>贯穿三代载体。

### GPU Gems 1 Ch37-42：借图形管线做计算

- **A Toolkit for Computation on GPUs**：把数组、迭代、reduction、sort/search 等计算原语映射到 texture + fragment pass；

- **Volume Rendering Techniques**：三维纹理采样、transfer function、front-to-back compositing 和 early termination；
- **Applying Real-Time Shading to 3D Ultrasound Visualization**：将医学体数据、切片/体绘制和 shading 结合；
- **Real-Time Stereograms**：按深度约束建立左右像素对应并生成自立体图；
- **Deformers**：把 lattice、twist、bend 等几何变形映射到 vertex program。

<Term def="把计算域编码为纹理，用全屏/几何光栅产生 invocation，fragment shader 从源纹理 gather 并写目标纹理，再交换读写目标的早期 GPGPU 方式">Fragment-pass GPGPU</Term>受到输出位置固定、scatter 困难和 pass 同步限制。

```cpp
Texture src = initialState, dst = scratch;
for (int iteration=0; iteration<K; ++iteration) {
  bindInputs(src);
  bindRenderTarget(dst);
  drawDomainQuad(fragmentKernel);
  swap(src, dst); // pass boundary establishes the next iteration source
}
```

### Stable fluids：算子分解与投影

不可压缩速度场满足 $\nabla\cdot\mathbf u=0$。一步常分为 advection、force、pressure solve、projection：

$$
\nabla^2p=\nabla\cdot\mathbf u^*,\qquad
\mathbf u=\mathbf u^*-\nabla p.
$$

半拉格朗日 advection 稳定但有数值耗散；Jacobi pressure 迭代次数影响 divergence 残差。验收边界条件、质量/涡量趋势、$\|\nabla\cdot u\|$ 和时间步，而非只看烟雾动画。

### Volume、ultrasound 与合成

front-to-back 预乘合成：

$$
C_{new}=C+(1-\alpha)\alpha_s C_s,\qquad
\alpha_{new}=\alpha+(1-\alpha)\alpha_s.
$$

<Term def="把标量体数据经 transfer function 映射为颜色/消光，沿视线采样并按透射率合成的图像生成过程">体绘制</Term>要说明采样步长、transfer function、梯度法线和 early termination。超声数据还需保留物理强度/动态范围和医学空间标定，不能把图像增强当诊断真实性。

Stereogram 与 deformers 分别代表约束传播和独立顶点映射；前者要处理冲突/遮挡，后者要验证坐标空间、Jacobian/法线和边界连续性。

### GPU Gems 2 Ch29-36：架构与并行原语

- **Streaming Architectures and Technology Trends**：流处理器、算术/带宽趋势和可编程性；
- **The GeForce 6 Series GPU Architecture**：当代 vertex/fragment 单元、纹理、分支和吞吐约束；

- **Taking the Plunge into GPU Computing**：从算法选择、数据表示、精度到传输评估 GPU 适用性；

<Term def="把一组元素按结合运算合并为较少元素直至单值或分块结果的并行原语">并行归约</Term>对 $N$ 项的总工作 $O(N)$、理想跨度 $O(\log N)$。浮点加法不满足严格结合律，树顺序与 CPU 串行结果可能不同，需误差容限/补偿策略。

<GpgParallelPrimitiveDiagram />

```glsl
shared float tile[BLOCK];
tile[lid] = gid < count ? input[gid] : 0.0;
barrier();
for (uint stride=BLOCK/2; stride>0; stride>>=1) {
  if (lid < stride) tile[lid] += tile[lid+stride];
  barrier();
}
if (lid==0) partial[groupId] = tile[0];
```

不要给 shared memory 固定“快多少倍”；bank conflict、occupancy、global cache 和复用次数决定收益。必须测 memory transaction、active groups 和实际 kernel time。

- **AES Encryption and Decryption on the GPU**：并行处理独立 block，管理 lookup/table、key schedule 和吞吐；
- **Efficient Random Number Generation and Application Using CUDA**：并行 RNG state、统计质量和应用采样；

- **Using the Geometry Shader for Compact and Variable-Length GPU Feedback**：用 geometry shader 输出变长结果并 compact feedback。

### Scan、RNG 与可变长输出

<Term def="输出每个位置之前或包含当前位置的前缀结合结果，是 compaction、排序、分配和稀疏构建的基础原语">并行前缀和</Term>。exclusive scan：

$$
y_i=\sum_{j=0}^{i-1}x_j.
$$

work-efficient scan 用 tree up-sweep 得总和，再 down-sweep 分发前缀；多 block 还需 scan block sums 并 uniform add。验收零项、非幂二长度、溢出和 in-place 边界。

RNG 不能只看速度：每线程 state seed/subsequence 不应重叠，要测均匀性、自相关和应用估计偏差。AES 要用标准测试向量验证加解密和 block mode；性能报告包含 host/device 传输与数据规模，不能只报 kernel bandwidth。

geometry shader feedback 是统一 shader 时代的变长输出技巧。现代 compute 可用 predicate + scan + scatter compact，但必须比较输出顺序、容量、计数和 overflow。

### Gaussian recurrence 与地震成像

Gaussian $g(x)=e^{-x^2/(2\sigma^2)}$ 的相邻值比可递推更新，避免每项 `exp`。实现必须定期/边界重归一化并比较累计误差。

Seismic imaging 通常具有高维 stencil/相关/累加和巨大带宽。验证小网格解析波、边界条件、时间步稳定性和浮点精度；tile 共享存储只有在 halo 复用抵消加载/同步时有效。

```cpp
Result validateKernel(Kernel gpu, Reference cpu, Inputs tests) {
  for (auto input : tests) {
    auto expected = cpu(input);
    auto actual = gpu(input);
    compareValuesAndInvariants(expected, actual);
  }
  return measureEndToEnd(gpu, tests.largeCases());
}
```

## 常见误区

<Callout type="trap">
**现象 →** 用一段现代 Compute Shader 卷积代表 20 个 GPGPU 原章。
**原因 →** 忽略 fragment-pass 限制、流式抽象、并行原语和 CUDA 应用各自核心。
**修法 →** 保留三代数据流，并逐章验证 fluid/volume、structures/reduction、AES/RNG/scan 等不同问题。
</Callout>

<Callout type="trap">
**现象 →** 用 `mix/step` 替换所有分支，认为必然更快。
**原因 →** 分支相干性、执行架构和两边工作量未测；predication 可能执行全部路径。
**修法 →** 构造不同分支分布，测 instruction/occupancy/time，并保持数值边界一致。
</Callout>

<Callout type="trap">
**现象 →** GPU kernel 快于 CPU 就宣布加速。
**原因 →** 忽略上传、下载、同步、预处理和小规模 launch 成本。
**修法 →** 同时报 kernel 与端到端时间，扫描问题规模并给出性能交叉点和驻留数据条件。
</Callout>

## 练习

<Exercises>

**问题 1：fragment-pass reduction 与 CUDA reduction 的不变量是什么？**

<Answer>
都以结合运算分层缩小元素数，工作近似 O(N)、跨度 O(log N)，每层输出成为下一层输入。不同的是写入/gather、同步和局部存储载体；浮点树顺序误差两者都要验收。
</Answer>

**问题 2：如何验证 Parallel Prefix Sum？**

<Answer>
对零长度、1、非幂二、跨 block、大值溢出和随机数组，与 CPU exclusive/inclusive scan 比较；检查总工作、block sums、uniform add 和容量，并用 scan 驱动 compaction 端到端测试。
</Answer>

**问题 3：设计覆盖 20 章的综合任务。**

<Answer>
读取超声/地震体数据，GPU deformer/流体更新场，volume render 输出；用 reduction 统计、scan compact、RNG 采样、Gaussian filter，AES 加密输出；保留 fragment-pass 教学对照与 CUDA/compute 现代路径，并记录数值、流量和时间。
</Answer>

</Exercises>

## 小结

20 章记录 GPU 从图形管线计算工具箱、流式并行机器到 CUDA 通用处理器的演进。完整复现既要保留每代限制，也要验证 reduction/scan/RNG 等基础原语和 fluid/volume/AES/seismic 等应用，不能用“GPU 适合数据并行”一句话代替。
