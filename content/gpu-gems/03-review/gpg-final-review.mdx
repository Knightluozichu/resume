## 直觉：三卷不是“一帧渲染流程”

一帧只能串起自然、几何、光影、材质和图像的一部分；它无法覆盖线性方程、期权、AES、病毒匹配、医学 FFT、FX Composer 或 shader 工具集成。全书完成必须使用多种实验和证据，而不是一张渲染架构图。

先预测：131 个标题都在页面中出现、评分覆盖 100%，是否已经证明内容完整？没有。标题只是库存证据，每个主题还要有公式/数据流、现代复现、失败边界和独立 oracle。

<Term def="把每个原章的身份、核心不变量、实现位置、失败注入、参考判据和性能条件连接起来的可审计记录">原章证据链</Term>是最终验收单位。

## 八主题最终证据

### 自然效果 8 章

水波/焦散、Dawn 皮肤/动画、Improved Perlin Noise、Vulcan 火、草与衍射分别保留波导数、折射聚焦、层次外观、blend weight、连续噪声、介质合成、LOD 风场和波长方向关系。

### 光照阴影 24 章

shadow map/volume/PCF/VSM/PSSM、deferred、irradiance/BTF、AO/GI、大气/折射均有深度、矩、stencil、G-buffer、可见性和透射中间附件；PCF 不再被误称物理软影，AO 不再被称完整 GI。

### 材质着色 12 章

SSS、Spatial BRDF、IBL、Texture Bombing、PUC、植被、multi-specular、relief、Tabula Rasa deferred 和 importance sampling 保留高维外观、几何求交与 PDF 证据；现代 PBR 只是对照。

### 图像处理 24 章

glow/color/DOF/filter/OpenEXR/Motion、AA/lines/LUT/noise/mip、impostor/normal bake/particles/linear/vector/video/motion blur 使用 impulse、edge、色卡、subpixel、depth/velocity 与时间参考。

### 几何处理 15 章

clipmap、instancing/streams、query、adaptive tessellation/displacement、procedural terrain、crowd/blend、SpeedTree/wind 与 metaball 检查驻留、邻接、时序、query latency 和吞吐。

### 高级工程 15 章

pipeline performance、FX Composer/interfaces、RenderMan/DCC/app integration、octree texture、raster GI/radiosity、vision/deferred filtering/conservative raster 使用工具一致性、残差、覆盖和受控性能斜率。

### GPU 计算 20 章

fragment-pass、streaming、CUDA 三代路径分别还原；fluid/volume/ultrasound/stereogram/deformer、reduction/scan、AES/RNG/seismic/Gaussian/feedback 均有原语与应用 oracle。

### 数值物理 13 章

protein/linear/options/sort/flow/FFT、rigid/fluid/N-body/collision/LCP/SDF/virus 用领域残差、置信区间、守恒、完备性和端到端性能验收，不再误写成粒子系统。

## 四个综合实验

<GpgCapstoneDiagram />

### A：动态自然世界

程序地形/clipmap、SpeedTree 风、草、水与焦散、皮肤角色、阴影/AO/大气、HDR 图像链组合。调试视图显示 LOD/morph、波导数、shadow moments、AO、linear color 和 temporal difference。

```cpp
WorldEvidence renderLivingWorld(Frame f) {
  updateTerrainTreesWaterCharacters(f);
  renderVisibilityLightingAndAppearance();
  processLinearHdrImageChain();
  return captureGeometryLightingImageEvidence();
}
```

### B：并行原语实验室

对 map、reduction、scan、sort、compact、stencil/FFT 运行小规模 CPU oracle 和大规模性能扫描。对浮点结果使用绝对/相对误差：

$$
e_{rel}=\frac{|x_{gpu}-x_{ref}|}{\max(|x_{ref}|,\epsilon)}.
$$

记录工作量、memory traffic、kernel 和端到端时间，并保留 fragment-pass 教学对照。

```cpp
for (Primitive p : primitives) {
  checkEdgeCases(p, cpuOracle);
  scanSizesAndDistributions(p);
  reportAccuracyTrafficAndCrossover(p);
}
```

### C：数值与物理工作台

同一程序运行 linear solver、期权、fluid、N-body、collision/LCP、SDF、FFT phantom 与 virus matching。每个模块必须提供领域 residual/invariant，不能共享“画面正常”判据。

### D：生产工具与性能闭环

标准资产从 shader authoring/FX 参数、离线参考、DCC preview 到运行时，检查 interface、颜色、状态和资源一致性；随后用 controlled experiments 定位瓶颈。

<Term def="固定设备、驱动、输入和输出质量，只改变一个候选工作量并同时测 CPU/GPU 时间与计数器的实验">受控性能回归</Term>避免优化结论依赖 FPS 单点。

```ts
type ChapterEvidence = {
  id: string;
  invariant: string;
  originalCarrier: string;
  modernCarrier: string;
  oracle: string;
  boundaryCases: string[];
  artifacts: string[];
  performanceConditions: string[];
};
```

## 三代迁移审计

<Term def="记录原始 GPU/API 能力、算法为何采用该数据流、现代替代路径及语义差异的迁移说明">代际翻译记录</Term>对每章必需。至少区分：

- Cg/fragment shader + texture ping-pong：固定输出、gather 强、pass 边界同步；
- unified shader/geometry stream-out：阶段更通用、可产生几何和 feedback；
- CUDA/modern compute：线程组、共享存储、scatter/atomic/barrier 更显式。

迁移不能把“现代 API 更方便”当成算法证明。比如 scan 的工作/跨度、fluid divergence、shadow leaking、filter domain 与 LCP residual 不因 API 更新而消失。

## 最终评分门槛

<Term def="同时要求目录身份、内容深度、专属图示、可执行/可推导实践、教学闭环和权威来源达到阈值的章节验收标准">多维质量门槛</Term>在此书为每页至少 90 分、整书至少 90、131 单元覆盖至少 90%，且无失败章节。

质量评分是结构化筛查，不直接证明算法输出，因此还需以下真实证据：

1. manifest 131 单元及官方来源；
2. 八主题页逐章核心和图示；
3. 数值/图像/统计/系统 oracle；
4. 边界与失败注入；
5. 现代迁移说明；
6. MDX、TypeScript、lint 与最终构建门槛。

## 常见误区

<Callout type="trap">
**现象 →** 用“一帧从几何到后处理”声称覆盖三卷。
**原因 →** 忽略工具链、科学、金融、医学、安全和并行原语章节。
**修法 →** 使用八主题与四综合实验；一帧只属于自然世界实验。
</Callout>

<Callout type="trap">
**现象 →** manifest 覆盖 100% 就宣布一比一复现。
**原因 →** 关键词匹配只证明标题进入内容语料，不证明核心和结果正确。
**修法 →** 每个 id 连接不变量、现代路径、oracle、边界、artifact 和性能条件。
</Callout>

<Callout type="trap">
**现象 →** 所有旧算法都换成 compute 后删除历史路径。
**原因 →** 丢失算法如何受 gather/scatter、同步和阶段能力影响的教学价值。
**修法 →** 保留代际翻译记录，明确等价、不等价和已淘汰假设。
</Callout>

## 练习

<Exercises>

**问题 1：为什么总复习需要四个综合实验？**

<Answer>
动态自然世界覆盖渲染主题；并行原语实验室覆盖计算骨架；数值物理工作台覆盖领域正确性；生产工具闭环覆盖接口和性能。任何一个都无法单独表达 131 章的不同证据类型。
</Answer>

**问题 2：怎样防止标题覆盖冒充内容覆盖？**

<Answer>
为每个 manifest id 建 ChapterEvidence，至少含不变量、原始/现代载体、oracle、边界、artifact 和性能条件；自动检查字段，人工/实验检查证据。标题只用于定位，不作为最终通过判据。
</Answer>

**问题 3：本书何时可以判定通过？**

<Answer>
131 章库存和唯一归属闭合；十页均达 90、整书与目录覆盖达门槛；八主题和四综合实验有正确性/边界/性能证据；MDX/type/lint 通过。全库部署仍要等 225 本全部完成。
</Answer>

## 小结

GPU Gems 的完整性来自 131 条原章证据链，而不是一帧、九主题或关键词。八主题保留每章核心，四个实验覆盖不同证据类型，代际翻译解释算法与载体变化；只有目录、内容、结果和工程门槛同时成立，整书才算完成。
