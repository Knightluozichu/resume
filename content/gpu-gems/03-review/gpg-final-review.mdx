## 直觉引入

一帧画面从空到满，经历了什么？先画几何（LOD/细分决定画多少三角形），再算光照（阴影/材质决定表面长什么样），然后加特效（粒子/自然效果增添动态），最后做后处理（Bloom/色调映射定调画面风格）。GPU Gems 的九大主题恰好覆盖了这一帧的每个环节——复习时用这条线把它们串成闭环。

全书九大主题按渲染顺序可分为三层：效果层（自然效果、光照阴影、材质着色器）负责「画面长什么样」；处理层（图像处理、几何细分、粒子物理）负责「怎么高效地画」；计算层（GPGPU、高级技术）负责「GPU 还能做什么」。

## 交互Demo

<Stepper>
<Step title="第一步：几何准备阶段">
帧开始时，先做 LOD 选择和曲面细分（几何章节），决定每个物体画多少三角形。同时 GPU 粒子系统在 Compute Shader 中并行更新位置（粒子章节）。这一阶段决定了场景的几何复杂度。
<GpgFinalReviewDiagram />
</Step>
<Step title="第二步：光照与材质阶段">
渲染不透明物体时，阴影映射（光照阴影章节）决定哪些区域暗，BRDF（材质章节）决定表面颜色，自然效果着色器（自然效果章节）给水面、毛发等特殊效果。延迟或前向渲染（高级技术章节）决定光照计算路径。
</Step>
<Step title="第三步：后处理与输出阶段">
几何和光照完成后进入后处理：Bloom 加光晕（图像处理章节），色调映射压缩 HDR，最后输出到屏幕。GPGPU 贯穿全程，粒子更新、阴影模糊、图像卷积都可能用 Compute Shader 加速。
</Step>
</Stepper>

## 代码对照

```glsl
// 一帧的着色器全景（伪代码）
// === 几何阶段 ===
// Vertex/Tessellation Shader: LOD + 曲面细分
// Geometry pass → G-Buffer（延迟渲染）

// === 光照阶段 ===
// Lighting pass: 逐光源从 G-Buffer 读取材质算 BRDF
// Shadow Map pass: 从光源渲染深度

// === 特效阶段 ===
// 自然效果: 水面法线扰动、火焰噪声、毛发壳渲染
// 粒子: Compute Shader 更新后直接渲染

// === 后处理阶段 ===
// Bloom: 降采样金字塔 → 高斯模糊 → 叠加
// Tone Mapping: ACES 压缩 HDR → LDR
// 最终输出到屏幕

// GPGPU 可用于上述任何阶段的加速
```

## 常见误区

<Callout type="trap">
**误区：把九大主题当独立模块学习。**
它们是一帧渲染的各个环节，互相依赖。比如自然效果（水面）依赖光照阴影（反射），粒子系统依赖 GPGPU（Compute Shader 更新），后处理依赖图像处理（降采样金字塔）。复习时必须串联理解。
</Callout>

<Callout type="trap">
**误区：只学技术不学取舍。**
GPU Gems 的价值不只是「怎么做」，更是「什么时候用」。前向还是延迟？CPU 粒子还是 GPU 粒子？程序化噪声还是预存纹理？每个选择都有适用场景，复习时要能说清取舍依据。
</Callout>

<Exercises>
**问题 1**：用一帧渲染顺序串联全书九大主题。

<Answer>
几何准备（LOD/曲面细分+粒子更新）→ 光照材质（阴影映射+BRDF+自然效果+前向/延迟渲染）→ 后处理输出（Bloom+色调映射）。GPGPU 贯穿全程加速各阶段。九大主题不是独立模块而是一帧的各个环节。
</Answer>

**问题 2**：GPU Gems 的核心方法论是什么？

<Answer>
效果驱动——从具体视觉目标（水要有波纹、火要发光、金属要有高光）出发，倒推技术方案（噪声扰动法线、加色混合、PBR 参数）。每个案例都先展示「要什么效果」再给「怎么实现」，并标注性能代价。这种方法论贴近实际开发流程，是实战手册而非理论教材。
</Answer>
</Exercises>
