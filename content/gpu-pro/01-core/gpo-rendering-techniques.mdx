## 直觉引入

想象三种画画方式。前向渲染是「逐个物体画完」（每画一个物体就把所有灯光涂上去）；延迟渲染是「先画线稿再上色」（先画几何信息，再统一打光）；可见性缓冲是「只记编号再查色」（先记每个像素属于哪个三角形，再按需查属性）。三种方式各有取舍。

## 概念讲解

### 三种渲染技术对比

<GpoRenderingTechniquesDiagram />

- <Term def="前向渲染（Forward Rendering）逐物体逐光源计算光照，每个物体在每个光源下渲染一次">前向渲染</Term>：光源数 O(N*M)，支持 MSAA 和透明物体
- <Term def="延迟渲染（Deferred Rendering）先将几何信息写入 G-Buffer，再在光照 Pass 中逐像素计算所有光源">延迟渲染</Term>：光源数 O(N+M)，不支持 MSAA，G-Buffer 带宽大
- <Term def="可见性缓冲（Visibility Buffer）只存储图元 ID 和属性索引，光照时按需从顶点/索引缓冲读取属性">可见性缓冲</Term>：带宽极低，材质复杂度无关，需现代 GPU 特性

## 代码对照

```hlsl
// 延迟渲染 G-Buffer Pass（简化）
struct GBuffer {
    float4 albedo   : SV_Target0; // rgb=颜色 a=AO
    float4 normal   : SV_Target1; // rgb=法线 a=roughness
    float4 material : SV_Target2; // r=metallic g=emission b=...
};

GBuffer GBufferPass(Varyings IN) {
    GBuffer g;
    g.albedo = tex2D(_MainTex, IN.uv) * _Color;
    g.normal = float4(IN.normalWS * 0.5 + 0.5, _Roughness);
    g.material = float4(_Metallic, _Emission, 0, 0);
    return g;
}

// 延迟渲染光照 Pass（简化）
float4 DeferredLighting(float2 uv, GBuffer g) {
    float3 normal = g.normal.rgb * 2 - 1;
    float3 posVS = ReconstructPosition(uv, depth);
    float3 color = 0;
    for (int i = 0; i < numLights; i++) {
        color += BRDF(g.albedo, normal, g.material, lights[i], posVS);
    }
    return float4(color, 1);
}

// 可见性缓冲（简化）
// G-Buffer 只存 32bit: drawID(8) + triangleID(24)
uint VisibilityBuffer(float2 uv) {
    return (drawID << 24) | triangleID;
}
// 光照时按需读取顶点属性
float3 ReadAttribute(uint visBuffer, uint2 pixel) {
    uint drawID = visBuffer >> 24;
    uint triID = visBuffer & 0xFFFFFF;
    // 从 Bindless Buffer 读取顶点属性
    return ReadVertexAttribute(drawID, triID, pixel);
}
```

## 常见误区

<Callout type="trap">
**误区：延迟渲染一定比前向渲染快。**
延迟渲染在多光源场景（4+光源）下优势明显，但 G-Buffer 带宽开销大（3-4 张 RT），移动端 TBR 架构下 G-Buffer 会增加 Tile 内存压力。少光源场景（1-2 个）前向渲染更快。应根据光源数量和平台选择。
</Callout>

<Callout type="trap">
**误区：可见性缓冲可以轻松替代延迟渲染。**
可见性缓冲需要 Bindless Resource（GPU 侧随机访问顶点缓冲）、间接绘制和现代光栅化器支持。旧 API（DX11/GL）无法实现，需 DX12/Vulkan/Metal。实现复杂度远高于延迟渲染，适合追求极致带宽效率的高端项目。
</Callout>

<Exercises>
**问题 1**：前向渲染和延迟渲染的光源复杂度分别是什么？为什么？

<Answer>
前向渲染光源复杂度 O(N*M)（N=物体数，M=光源数），每个物体在每个光源下渲染一次，光源数增加时光照计算线性增长。延迟渲染光源复杂度 O(N+M)，G-Buffer Pass 渲染 N 个物体（不含光照计算），光照 Pass 对每个像素遍历 M 个光源（与物体数无关）。延迟渲染将几何渲染和光照计算解耦，大量光源时光照 Pass 开销只取决于屏幕分辨率和光源数，与场景物体数无关。
</Answer>

**问题 2**：可见性缓冲相比延迟渲染的优势是什么？为什么需要现代 GPU 特性？

<Answer>
优势：1) G-Buffer 只存 32bit 图元 ID（vs 延迟渲染 96-128bit），带宽极低；2) 材质复杂度无关——延迟渲染需将所有材质参数编码进 G-Buffer（受限），可见性缓冲光照时按需读取原始顶点属性（无限制）；3) 支持任意复杂材质（多层 BRDF、SSS）。需要现代 GPU 特性因为：1) Bindless Resource 允许 Shader 随机访问任意顶点缓冲（旧 API 需预绑定）；2) 间接绘制支持 GPU 侧剔除和绘制调度；3) 需要高速的 Structured Buffer 随机访问。DX11/GL 不支持 Bindless，需 DX12/Vulkan/Metal。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="前向渲染">逐物体逐光源计算光照，支持 MSAA 和透明物体，光源数 O(N*M)。</GlossaryItem>
<GlossaryItem term="延迟渲染">先写 G-Buffer 再统一计算光照，光源数 O(N+M)，不支持 MSAA。</GlossaryItem>
<GlossaryItem term="G-Buffer">Geometry Buffer，延迟渲染中存储几何和材质信息的多张渲染目标。</GlossaryItem>
<GlossaryItem term="可见性缓冲">只存图元 ID 的极简 G-Buffer，光照时按需读取顶点属性，带宽极低。</GlossaryItem>
</Glossary>
