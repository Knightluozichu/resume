## 直觉引入

你有一副完全打乱的扑克牌，想要从小到大排好。你随手抽一张牌（比如方块 7）放在桌上，然后把剩下的牌一张张翻开：比 7 小的扔左边一堆，比 7 大的扔右边一堆。接下来，你对着左边那堆和右边那堆分别<strong>再做一遍同样的事</strong>——抽一张当基准，更小的放左，更大的放右。

等每一堆都只剩一张牌时，你把所有堆按「左堆 + 基准牌 + 右堆」的顺序拼起来——整副牌排好了。

这就是快速排序的灵魂——分治法：先选一个参照物把数据劈成两半，再对每一半递归地做同样的事。这章的核心问题是：怎样选参照物才能让「劈」的效率最高？

## 概念讲解

### 分治：先拆再合

<Term def="将大问题拆成若干个结构相同的小问题，分别解决后再合并结果。快速排序、归并排序都基于此思想。">分治</Term>是算法设计的核心策略之一。它遵循三步：

1. <strong>分解</strong>：把原问题拆成若干子问题，子问题与原问题结构相同、规模更小。
2. <strong>解决</strong>：递归地解决每个子问题。如果子问题足够小，直接求解。
3. <strong>合并</strong>：把子问题的解拼成原问题的解。

在快排里，分解就是选 pivot 做分区；解决就是对左右两区递归排序；合并——快排根本不需要显式合并，因为分区在分解时就已经把元素放到了正确的位置上。

### 枢轴与分区：快排的核心操作

<Term def="快速排序中选出的参照元素。所有比它小的放左边，比它大的放右边。pivot 的选择直接影响效率。">枢轴（pivot）</Term>是快排的「裁判」。它不参与左右区的排序——它站在中间，定好了位置就不再动。

<Term def="将数组按 pivot 分成左右两部分的过程：左边元素 ≤ pivot，右边元素 ≥ pivot。分区后 pivot 处于最终位置。">分区</Term>是快排唯一的重体力活。一次分区操作遍历整个数组一次（O(n)），把元素按小于 pivot 和大于 pivot 分到两边。

<QuickSortDiagram />

看图：绿色是被选中的 pivot，它最终落在正确位置上。左边橙色区都比它小，右边蓝色区都比它大。然后左右两区各自递归地做同样的事。

### 时间复杂度：为什么是 n log n？

快排的效率取决于分区是否「均匀」。假设每次 pivot 恰好把数组对半劈开：
- 第 1 层：1 次分区，遍历 n 个元素 → O(n)
- 第 2 层：2 次分区，各遍历约 n/2 个元素，共 O(n)
- 第 3 层：4 次分区 → O(n)
- …直到每块只剩 1 个元素。总层数 = log₂n 层。

每层 O(n)，共 log n 层，总 O(n log n)。这就是快排的平均情况。

但如果你每次都选到最小或最大的元素当 pivot（比如已经排好序的数组，还傻傻地选第一个当 pivot），分区会极不均匀：一层只分离出 1 个元素，总共 n 层。每层 O(n)，总 O(n²)。这是最坏情况。

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 在已排序数组上用快排，每次都选第一个元素当 pivot，退化成 O(n²) 甚至栈溢出。<strong>原因 →</strong> 已排序数组里，第一个元素就是最小元素——分区后左区为空，右区还是 n-1 个元素。递归树退化成一条链：n → n-1 → … → 1，共 n 层。<strong>修法 →</strong> 随机选 pivot，或取首尾中三者的中位数。随机化后，最坏的输入也被概率摊平。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 认为快排在任何场景下都比归并排序快。<strong>原因 →</strong> 虽然都是 O(n log n)，但快排在分区不均匀时会退化到 O(n²)，而归并排序<strong>始终</strong>是严格的 O(n log n)。而且归并排序是稳定排序，快排通常不是。<strong>修法 →</strong> 需要严格稳定排序（比如按多个键排序要求顺序不变）时选归并排序；对内存敏感时快排更优（原地排序，无需额外数组）。
</Callout>

## 小结与练习

- 快速排序 = 选 pivot + 分区 + 递归。分区是核心操作，每层 O(n)，理想总层数 log n，总 O(n log n)。
- pivot 选择决定效率：随机选 pivot 用概率消除最坏退化风险。
- 分治三步走：分解（分区）、解决（递归）、合并（快排无需显式合并，分区已完成定位）。
- 快排是不稳定排序，归并排序是稳定排序——根据需求选择。

<Exercises>
  <Answer question="手算：对数组 [3, 6, 8, 10, 1, 2, 1]，以第一个元素 3 为 pivot 做一次分区。写出分区后的数组。">
    以 3 为 pivot：比 3 小的有 1, 2, 1 → 左区；比 3 大的有 6, 8, 10 → 右区。分区后：[1, 2, 1, 3, 6, 8, 10]。注意 pivot (3) 落在第 4 个位置（下标 3），从此不再移动。
  </Answer>
  <Answer question="固定选最后一个元素当 pivot，构造一个让快排退化到 O(n²) 的输入。">
    让数组已经是升序排列（如 [1, 2, 3, 4, 5]），每次选最后一个（最大值）当 pivot：右区每次为空，左区只少一个元素。或者数组是降序的，每次选第一个也一样退化。
  </Answer>
  <Answer question="为什么随机选 pivot 几乎不会退化到 O(n²)？">
    随机选 pivot，每次选到极端值（最大或最小）的概率是 2/n。递归 n 层的概率大约是 (2/n)ⁿ——当 n 稍大时这个概率几乎为零。随机化不保证最优，但保证「几乎不可能最坏」。
  </Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="快速排序">
    选 pivot、分区、递归排序的快排算法。平均时间复杂度 O(n log n)，最坏 O(n²)。通过随机化 pivot 避免退化。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="枢轴（pivot）">
    快排选出的参照元素。分区后 pivot 落在最终排定位置。选得好 → 递归树平衡 → O(n log n)；选得差 → 递归树退化成链 → O(n²)。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="分区">
    一次遍历将数组按 pivot 分成左右两部分的过程。左区所有元素 ≤ pivot，右区所有元素 ≥ pivot。每次分区成本 O(n)。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="分治">
    将大问题拆成同结构的小问题分别解决再合并的策略。快排是分治的典范：分区（拆）、递归（治）、无需显式合并。详见「概念讲解」节。
  </GlossaryItem>
</Glossary>
