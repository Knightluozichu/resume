## 直觉引入

你见过俄罗斯套娃吗？打开一个木娃娃，里面还有一个更小的；再打开，还有更小的——直到最里面那个实心的、打不开的为止。每一个娃娃在尺寸上变小一点，但形状和「打开看看」这个动作一模一样。

递归就是程序世界的俄罗斯套娃。一个函数在解决一个问题时，把问题缩小一点、简化一点，然后让「另一个自己」去解决这个缩小版的问题。一层一层往里走，直到问题小到可以直接回答——那个「最里面的实心娃娃」就叫基线条件。

这章解决的核心问题：有些问题天然是「自相似」的——大问题由同类的小问题组成。没有递归，你只能手动模拟这个层层递进的过程，代码会又长又难读。

## 概念讲解

### 递归的解剖：基线条件 + 递归条件

<Term def="函数直接或间接调用自身来解决问题的编程技术。每次调用把问题缩小，直到碰到基线条件返回。">递归</Term>之所以难上手，是因为你要同时理解两件事：函数在做什么，以及「还没做完的自己」存在哪里。

每一个正确的递归函数都包含两个不可或缺的部分：

<Term def="递归停止的条件——问题已经小到可以直接回答，不需要再调用自己。">基线条件</Term>告诉函数「什么时候停下来」。没有它，递归就像没有底的套娃，会一直打开直到内存炸掉（栈溢出）。

<Term def="函数还没有满足基线条件时继续调用自身，每次让问题朝基线条件靠近一步。">递归条件</Term>告诉函数「怎样让问题变小」。它必须保证每一步都能离基线条件更近——如果问题规模不缩小，递归永远不会结束。

<Term def="程序在内存中记录函数调用顺序的数据结构。每次函数调用压入一帧，返回时弹出。递归深度 = 栈高度。">调用栈</Term>是递归的隐形代价。每次函数调用自己，计算机就在调用栈上压入一帧，记录「调用点在哪、局部变量是多少」。当递归深度很大时，栈可能爆满。

看图：每一层递归调用压入栈中变成一帧。注意基线条件触达后，栈开始一层层弹出——从最深层返回，逐级把结果传回给上一层。

### 阶乘：递归的最经典模板

阶乘的定义天然是递归的：

$$n! = \begin{cases} 1 & \text{当 } n = 0 \text{（基线条件）} \\ n \times (n-1)! & \text{当 } n > 0 \text{（递归条件）} \end{cases}$$

这个定义完美呼应递归的解剖结构。要算 5!，你得先算 4!；要算 4!，你得先算 3!……一直叠到 0! = 1，再逐层乘回去。

## 数学推导

### 符号表

| 符号 | 含义 |
|------|------|
| n | 输入规模 |
| n! | n 的阶乘 |
| T(n) | 计算 n! 所需的时间 |
| S(n) | 计算 n! 所需的栈空间 |

### 递归调用的栈展开

以 n = 4 为例，手动追踪调用栈的变化。括号里是「当前在等谁的返回值」：

```
factorial(4) → 在等 factorial(3) 返回，压栈（帧 1）
  factorial(3) → 在等 factorial(2) 返回，压栈（帧 2）
    factorial(2) → 在等 factorial(1) 返回，压栈（帧 3）
      factorial(1) → 在等 factorial(0) 返回，压栈（帧 4）
        factorial(0) → 命中基线！返回 1，弹出帧 4
      factorial(1) → 收到 1，算 1×1=1，返回 1，弹出帧 3
    factorial(2) → 收到 1，算 2×1=2，返回 2，弹出帧 2
  factorial(3) → 收到 2，算 3×2=6，返回 6，弹出帧 1
factorial(4) → 收到 6，算 4×6=24，返回 24
```

这个式子在说：每多一层递归，栈上就多压一帧。当 n = 4 时栈深度为 5（含基线帧）。推广到任意 n：
- 时间复杂度 T(n) = O(n)（做了 n 次乘法）
- 空间复杂度 S(n) = O(n)（调用栈深度为 n+1）

O(n) 的空间意味着：如果你递归算 10000!，调用栈会有 10001 帧——这在大多数语言里会触发栈溢出。这就是为什么有些递归需要改用循环或者<strong>尾递归优化</strong>。

### 斐波那契：递归的陷阱

斐波那契数列的递归定义：

$$F(n) = \begin{cases} 0 & \text{当 } n = 0 \\ 1 & \text{当 } n = 1 \\ F(n-1) + F(n-2) & \text{当 } n > 1 \end{cases}$$

这个定义简洁优美，但直接翻译成递归代码是灾难。为什么？因为 F(n-1) 和 F(n-2) 各自递归时，会<strong>重复计算</strong>大量子问题。计算 F(5) 时，F(3) 被算了 2 次，F(2) 被算了 3 次，F(1) 被算了 5 次。时间复杂度会爆炸到 O(2ⁿ)。

这个式子在说：递归本身不是坏的，但<strong>没有缓存子问题结果的朴素递归</strong>在重叠子问题上会指数级膨胀。后面的动态规划章节会回来修这个问题。

## 常见误区

<Callout type="trap">
  <strong>现象 →</strong> 递归函数无限循环，最终栈溢出崩溃。<strong>原因 →</strong> 缺少基线条件，或者递归条件没有让问题真正朝基线靠近（比如每次传一样的参数）。<strong>修法 →</strong> 写递归的第一件事永远是确认「什么情况下不用再调用自己」。然后验证递归参数每一步都在朝那个方向移动。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 用朴素递归算斐波那契 F(50)，程序跑一周都不出结果。<strong>原因 →</strong> 朴素斐波那契递归产生指数级重复计算——F(n) 重复计算 F(n-2)、F(n-3)……形成 O(2ⁿ) 的爆炸。<strong>修法 →</strong> 引入记忆化（memoization）缓存已算过的子问题结果，或改用自底向上的动态规划。这也是后面「动态规划」章节要讲的内容。
</Callout>

## 小结与练习

- 递归 = 基线条件（何时停）+ 递归条件（怎样让问题变小）。缺一不可。
- 调用栈记录每次函数调用的上下文。递归深度 = 栈高度，O(n) 空间是递归的隐藏成本。
- 递归适合「自相似」问题——大问题可以拆成同结构的小问题。
- 朴素递归在重叠子问题上可能指数爆炸（斐波那契是典型），用记忆化或动态规划应对。

  <Answer question="手算 factorial(5) 的完整调用栈（写明每一帧的参数和返回值）。">
    factorial(5) → 等 factorial(4) → 等 factorial(3) → 等 factorial(2) → 等 factorial(1) → 等 factorial(0) → 返回 1。然后逐级乘回：1×1=1, 2×1=2, 3×2=6, 4×6=24, 5×24=120。
  </Answer>
  <Answer question="推导：朴素递归算 F(n) 为什么是 O(2ⁿ)？">
    每个 F(k) 调用 F(k-1) 和 F(k-2)。画递归树发现：节点数大约是 2ⁿ。F(n-1) 和 F(n-2) 的子问题大量重叠，但朴素递归不记忆结果，每个子问题被重复计算多次，时间按指数增长。
  </Answer>
  <Answer question="递归一定比循环慢吗？什么情况下递归更好？">
    递归因为有函数调用开销和栈空间消耗，通常比等价的循环略慢。但递归在处理树遍历、分治算法、嵌套结构解析时，代码比循环清晰得多。现代编译器对尾递归做了优化（消除栈帧），可以把尾递归变成和循环一样快。
  </Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="递归">
    函数调用自身来解决问题的技术。每次调用缩小问题，直到基线条件停止。递归之美在于用简洁代码表达「自相似」结构。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="基线条件">
    递归停止的条件——问题已小到可以直接回答，不需要再调用自己。没有基线条件 = 无限递归 = 栈溢出。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="递归条件">
    函数还没满足基线条件时调用自身，并且每次让问题向基线靠近一步。阶乘的递归条件是 n > 0 时调用 factorial(n-1)。详见「概念讲解」节。
  </GlossaryItem>
  <GlossaryItem term="调用栈">
    计算机在内存中管理函数调用的数据结构。每次函数调用压入一帧（记录参数和返回地址），返回时弹出。递归深度决定栈高度，太深会溢出。详见「概念讲解」和「数学推导」节。
  </GlossaryItem>
</Glossary>
