## 核心概念

<Term def="一种思考框架：面对新问题时，先识别输入结构和约束条件，再按问题形状匹配对应的算法家族，最后用复杂度估算确认可行性。">算法决策框架</Term>
是你读完本书后最该带走的东西。它不是一个具体算法，而是一种思维习惯——遇到问题不是先写代码，而是先画数据、想结构、查前提、算复杂度。这个习惯的价值远大于背下任何一种算法的实现。

<Term def="描述算法的时间需求如何随输入规模增长的语言，用于预测在真实数据量下算法是否可行。">复杂度</Term>
在本书中充当的不是理论课的考点，而是工程决策的算盘。O(n²) 对 n=1000 是百万级操作——几毫秒；对 n=10⁶ 是万亿级——不可接受。下面这张速查表把本书所有算法的前提、时间和空间整理在一起，供你决策时查阅。

### 算法复杂度速查表

| 算法 | 前提条件 | 平均时间 | 最坏时间 | 空间 | 核心局限 |
|---|---|---|---|---|---|
| 二分查找 | 必须有序数组、随机访问 | O(log n) | O(log n) | O(1) | 不支持动态插入 |
| 选择排序 | 无 | O(n²) | O(n²) | O(1) | n 较大时太慢 |
| 快速排序 | 无 | O(n log n) | O(n²)（已有序时） | O(log n) | 最坏情况退化 |
| 散列表 | 好的哈希函数 + 低负载因子 | O(1) | O(n)（冲突严重时） | O(n) | 不保证有序遍历 |
| BFS | 无权图 / 无向或有向 | O(V+E) | O(V+E) | O(V) | 不支持带权边 |
| Dijkstra | 非负权图 | O((V+E) log V) | O((V+E) log V) | O(V) | 负权边失效 |
| BST（不平衡） | 键可比较 | O(log n) | O(n)（退化时） | O(n) | 插入顺序决定形状 |
| 平衡树 | 键可比较 | O(log n) | O(log n) | O(n) | 维护开销（旋转/变色） |
| 贪心（近似） | 无严格前提（只求近似） | O(n²)（集合覆盖） | O(n²) | O(n) | 不保证最优 |
| 贪心（精确） | 贪心选择性质 + 最优子结构 | 取决于问题 | 同左 | 取决于问题 | 只适用特定问题 |
| 动态规划 | 最优子结构 + 重叠子问题 | O(nW)（背包） | O(nW) | O(nW) 可优化到 O(W) | W 大时仍慢（伪多项式） |
| KNN（预测） | 特征需缩放、维度不宜过高 | O(n·d) 或 O(log n)（索引加速） | O(n·d) | O(n·d)（存训练集） | 预测慢 + 维数灾难 |

> 注：V=顶点数，E=边数，n=元素数，W=背包容量，d=特征维度。

## 后续学习方向

学完这 13 章，你有了算法思维的地基。往哪个方向盖楼，取决于你面对的问题类型。

**图算法方向**：你已经看了 BFS（无权最短）和 Dijkstra（非负权最短）。
下一步可以看 Bellman-Ford（处理负权边）、A*（启发式搜索，游戏寻路标配）、
最小生成树（Prim/Kruskal）、拓扑排序。图算法是地图、社交网络、路由协议的数学底座。

**字符串匹配方向**：散列表处理了「查是否存在」，但「查在哪里出现」需要字符串算法。
KMP（Knuth-Morris-Pratt）是入门，Boyer-Moore 是工业标准，
Trie 树处理前缀搜索（自动补全），后缀数组处理全文搜索。

**机器学习方向**：KNN 是门槛。下一步是线性回归（预测数值）、
逻辑回归（二分类）、决策树（可解释性强）、随机森林（集成学习）。
这些算法的数学核心——梯度下降、损失函数——会在你掌握基本概率和线性代数后变得清晰。

**数据结构方向**：你已经掌握了数组、链表、散列表、树、堆（Dijkstra 中暗含）。
进阶数据结构包括 B 树（数据库索引的底层）、跳表（替代平衡树的概率化方案）、
并查集（处理动态连通性）、Bloom Filter（概率性集合，内存极省）。

**理论根基**：如果你对«为什么贪心有时对有时不对»或«NP 完全到底意味着什么»有更深的好奇，
可以读算法导论（CLRS）的相关章节。NP 完全性的证明并非神秘——它只是在说：
如果这个问题有快速算法，那所有同类问题都有——而学界普遍认为没有。

## 常见误区

- **现象 →** 学完这本书觉得「算法都会了」，上手新题还是先写代码后分析。**原因 →** 知识是散的，没有形成决策框架。**修法 →** 下次拿到问题，强制自己先走完三步：画数据写约束 → 查前提匹配算法 → 算复杂度。走完三遍这个流程就是本能了。

- **现象 →** 背住复杂度表就以为能做决策，没考虑常数因子和工程细节。**原因 →** 复杂度省略了常数。同样是 O(n log n)，归并排序的常数可能比快排大 2-3 倍——小 n 时归并反而慢。**修法 →** n 较小时（几百以内）以实测为准，大数据量时复杂度决定一切。实用主义的折中：先按复杂度筛选，再小规模基准测试。

- **现象 →** 以为学更多算法就能解决所有问题。**原因 →** 算法的力量有边界——NP 完全问题在 n 较大时不是靠换算法能解决的。**修法 →** 学会识别 NP 完全问题的特征（所有组合都要试 / 问题规模 n 小时可能枚举），及时切换到近似算法或启发式方法，不要钻精确解的牛角尖。

  算法选型三问，按顺序：①前提满足吗？②复杂度在目标数据量下可行吗？③工程约束（内存上限、延迟要求）能接受吗？
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 看书时每个算法都懂，合上书面对现实问题不知道用哪个。<strong>原因 →</strong>{" "}
  现实问题不会贴标签说 «请用 DFS» ——它只会给你数据、约束、目标。<strong>修法 →</strong>{" "}
  练习将现实问题翻译成数据结构语言：这是找路径（图 BFS/Dijkstra）、还是多阶段决策（DP）、
  还是覆盖最大化（贪心近似）？翻译对了，算法自然就出来了。
</Callout>

## 小结与练习

- 算法决策框架：看数据结构 → 猜问题类型 → 按前提过滤候选算法 → 查复杂度估算可行性。
- 复杂度速查表是决策的算盘——每种算法都附有前提、时间和致命弱点。
- 12 种算法覆盖了搜索、排序、图、优化、机器学习五个领域的基础武器。
- 后续可选方向：更多图算法、字符串匹配、机器学习算子、高级数据结构、NP 完全理论。

<Exercises>
  <Answer question="你面对一个 500 万节点的地图，要为汽车导航找最快路线。走决策框架找合适算法。">
    地图是图结构（节点=路口、边=道路）。边权是行驶时间，全是正数。前提满足→ Dijkstra（或 A* 加启发式更快）。复杂度 O((V+E) log V) ≈ 500 万 × log 500 万 ≈ 亿级操作，现代 CPU 在几秒内完成。前提满足 + 复杂度可行 = Dijkstra 是正确答案。
  </Answer>
  <Answer question="你需要在 10 万篇文章中快速搜索某个关键词是否出现过，但不需要知道位置。选哪种算法或数据结构？">
    需求是 «存在性查询» 且 «不需要位置» → 散列表（关键词做键）或 Bloom Filter（极省内存 + 可接受微小误判）。散列表 O(1) 查询，10 万键绰绰有余。Bloom Filter 用更少内存但不支持删除且有小概率误报。
  </Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="算法决策框架">
    面对新问题时的思维流程：识别输入数据结构 → 判断问题类型（搜索/排序/路径/优化/分类）→ 按前提条件过滤候选算法 → 依据复杂度速查表确认可行性。
  </GlossaryItem>
  <GlossaryItem term="复杂度">
    描述算法的时间需求或空间需求如何随输入规模（n）增长的表示方式，用于在实际编码前估算并预测算法在目标数据量下的可行性。
  </GlossaryItem>
  <GlossaryItem term="复杂度速查表">
    汇总本书所有算法的前置条件、平均/最坏时间复杂度、空间复杂度和核心局限的表格，提供快速比对和选型参考。
  </GlossaryItem>
  <GlossaryItem term="NP 完全问题">
    一类不存在已知多项式时间精确算法的问题。面对此类问题，应转向近似算法（如贪心近似）或启发式搜索，放弃精确最优的追求。
  </GlossaryItem>
  <GlossaryItem term="图算法">
    在节点和边构成的图结构上运行的算法家族。BFS（无权最短路径）、Dijkstra（非负权最短路径）、Bellman-Ford（允许负权）、A*（启发式）均属此类。
  </GlossaryItem>
  <GlossaryItem term="机器学习">
    让计算机从数据中自动发现模式的方法论。KNN 是本书介绍的入门算法。后续方向包括线性回归、逻辑回归、决策树、随机森林、深度学习等。
  </GlossaryItem>
</Glossary>
