## 先玩一遍

动态规划不是玄学填表——它是把一件大东西拆成小东西，把每个小东西的答案存进表格，组装大东西时直接查表不再重算。像一个旅行者在打包行李箱：箱子容量有限，面对一堆物品，每次问自己「装这个，剩下的空间还能塞多少价值？」

    暴力枚举 2ⁿ 种组合——n=30 时已经是十亿级。DP 用 O(nW) 的表解决。

  <Step title="执行关键动作——逐格填表、二选一">
    dp[i][w] 的含义：考虑前 i 个物品，容量为 w 时的最大价值。
    填法：对每个物品 i 和容量 w，dp[i][w] = max(dp[i-1][w], dp[i-1][w-wᵢ] + vᵢ)。
    翻译成人话：要么不取 i（价值 = 上一行同列），要么取 i（价值 = 物品 i 的价值 + 上一行减去 i 重量的那一列）。选大的。

  </Step>

    填到 dp[i][w] 时，它依赖的两个格子 dp[i-1][w] 和 dp[i-1][w-wᵢ] 都已经算好放在表里了。
    不需要递归重新探索——O(1) 查表。整张表填完只需 n×W 步，而非指数级。
    这就是 DP 把「时间换空间」反过来用的精髓：用表空间换掉重复计算的时间。

    如果 dp[i][w] ≠ dp[i-1][w]，说明取了物品 i，跳到 dp[i-1][w-wᵢ]；
    否则没取，跳到 dp[i-1][w]。回溯到顶就是最优解包含的物品列表。

## 核心概念

<Term def="一种算法设计范式：将问题分解为重叠子问题，用表格缓存子问题解避免重复计算，从子问题解构建全局最优解。">动态规划（DP）</Term>
是算法设计中最强大的武器之一。它的核心洞察是：如果问题的子问题会重复出现（「重叠子问题」），那把每个子问题只算一遍存在表里，遇到相同子问题直接查表——指数时间变多项式时间。DP 需要用备忘录（自上而下递归+缓存）或 DP 表（自底向上迭代）实现。

<Term def="在递归求解过程中，完全相同的子问题被反复计算多次——这是 DP 可以优化的标志。">重叠子问题</Term>
是判断 «该用 DP 还是分治» 的判据。分治的子问题互不相交（如归并排序拆两半各管各），DP 的子问题大量重叠（如斐波那契 fib(5) 依赖 fib(4) 和 fib(3)，而 fib(4) 又依赖 fib(3) 和 fib(2)，fib(3) 算了两次）。重叠越严重，缓存收益越大。

<Term def="描述子问题解如何由更小子问题的解构建的数学关系式。">状态转移方程</Term>
是 DP 的心脏。它要回答一个精确的问题：已知所有比当前问题「小一号」的子问题答案，当前问题的答案怎么算出来？背包问题的转移式 dp[i][w] = max( dp[i-1][w], dp[i-1][w-wᵢ] + vᵢ ) 就是一个典型——两个子问题解之间取 max。

<Term def="给定一组物品各有重量和价值，在总重量不超过 W 的前提下最大化总价值。">背包问题</Term>
是 DP 的招牌例题。0-1 背包（每个物品要么取要么不取）是最经典的 DP 表格问题——二维表格，物品一行、容量一列。完全背包（物品可以取无限次）只需改一行：转移时算 dp[i][w-wᵢ] + vᵢ 而非 dp[i-1][w-wᵢ] + vᵢ（同一物品可继续用）。

## 小公式

本节把背包 DP 的数学核心拆开——每个符号、每步推理都要有「人话翻译」。

**符号表**：n = 物品数；W = 背包容量；wᵢ = 第 i 个物品重量；vᵢ = 第 i 个物品价值；dp[i][w] = 考虑前 i 个物品、容量为 w 时的最大价值。

**状态定义**：

$$
dp[i][w] = \text{前 } i \text{ 个物品放进容量 } w \text{ 的背包的最大价值}
$$

这个式子在说：dp[i][w] 回答的不是「所有物品」的最优，而是「只给你前 i 个，容量只给你 w」的最优。小一号的问题就是 i 和 w 各减一点。

**转移方程**：

$$
dp[i][w] =
\begin{cases}
dp[i-1][w], & \text{如果 } w_i > w \text{（装不下第 } i \text{ 个）} \\
\max\bigl(dp[i-1][w],\; dp[i-1][w-w_i] + v_i\bigr), & \text{装得下时二选一}
\end{cases}
$$

人话翻译：如果第 i 个物品太重装不下，答案就是前 i-1 个在容量 w 下的最优（和它无关）。装得下时，面临一个二选一的决定——要么不取它（答案 = 行上格），要么取它（答案 = 取它的价值 + 剩余容量在剩余物品中的最优解）。选大的。

**复杂度**：

$$
\text{Time} = O(nW),\quad \text{Space} = O(nW) \text{（可优化至 } O(W) \text{ 滚动数组）}
$$

n 个物品 × W 个容量格子 = 每格 O(1) 填表。W 可能很大——这就是 DP 的致命弱点：当 W 是 10⁹ 时 O(nW) 也不可行。这时需要换策略（如分支定界法或近似算法）。

## 常见误区

- **现象 →** 没定义清楚 dp[i][w] 的含义就开始写转移方程，导致维度混乱。**原因 →** DP 的第一步永远是«定义状态的含义»——一个能用人话说清楚的物理含义。**修法 →** 写出 dp[i][w] 的含义并用一个具体例子验证：i=2, w=3 时 dp[2][3] 的值能用人话解释吗？

- **现象 →** 混淆 0-1 背包和完全背包的转移。**原因 →** 0-1 背包看上一行 dp[i-1][w-wᵢ]，同一物品不可复用；完全背包看同行 dp[i][w-wᵢ]，同一物品可继续取。**修法 →** 背一个口诀：«0-1 向上看（i-1），完全向左看（同 i）».

- **现象 →** DP 解完只返回最优值，丢失了解路径。**原因 →** 填表过程只维护 dp 值，没有记录 dp[i][w] 是从哪个选择来的。**修法 →** 加一张 choice[i][w] 布尔表，记录«是否选了物品 i»。回溯时从 dp[n][W] 开始，根据 choice 表逆向跟踪路径。

<Callout type="trap">
  <strong>现象 →</strong> 觉得 DP 需要先找「最优子结构」+「重叠子问题」才能用，被术语劝退。<strong>原因 →</strong>{" "}
  术语把简单直觉包装了。最优子结构 = 大问题答案能由小问题答案拼出来（大多数问题都是）；
  重叠子问题 = 递归探索时小问题会重复访问（斐波那契/背包/编辑距离都会）。<strong>修法 →</strong>{" "}
  尝试先用朴素递归写一遍问题，画出调用树——如果同一参数出现了多次，DP 就该出马。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 在 W 非常大（如 10⁹）的问题上硬套 DP 表格，O(nW) 仍超时。<strong>原因 →</strong>{" "}
  DP 的复杂度是和 W 值大小有关的（伪多项式时间），而非常规的 O(n log n)。<strong>修法 →</strong>{" "}
  当 W 巨大时，转为贪心近似、分支定界、或按价值做 DP（dp[i][v] = 达到价值 v 的最小重量）。
</Callout>

## 小结与练习

- DP = 拆问题 + 存答案 + 复用：把指数次重复计算降为表格的一次填充。
- 状态定义回答«dp[i][w] 是什么»，转移方程回答«怎么从更小的 dp 算出当前 dp»。
- 0-1 背包看 i-1 行，完全背包看 i 行同列——一字之差决定复用性。
- DP 的代价是 O(nW) 空间时间——W 太大时需换策略。

## 名词解释

<Glossary>
  <GlossaryItem term="动态规划（DP）">
    一种算法范式：把大问题拆成子问题，用表格/缓存存下每个子问题的解，组装时不重复计算。核心条件是问题有最优子结构和重叠子问题。
  </GlossaryItem>
  <GlossaryItem term="重叠子问题">
    在递归求解过程中，完全相同的子问题被反复多次计算。这是 DP 可以发挥缓存优势的信号——没有重叠则分治更自然。
  </GlossaryItem>
  <GlossaryItem term="状态转移方程">
    描述当前问题的最优解如何从比它「小一号」的子问题最优解计算得到的数学公式。是 DP 的心脏。
  </GlossaryItem>
  <GlossaryItem term="背包问题">
    DP 的招牌例题。0-1 背包：每个物品取或不取；完全背包：物品可无限次取。用二维表格 dp[i][w] 记录「前 i 个物品在容量 w 下的最大价值」。
  </GlossaryItem>
  <GlossaryItem term="最优子结构">
    全局最优解可由子问题最优解组合而成。有最优子结构 = DP 和贪心都可能适用；没有 = 两者都不行。
  </GlossaryItem>
  <GlossaryItem term="DP 表">
    动态规划的核心数据结构——二维（或多维）表格，每个格子存一个子问题的最优解。不同问题的表格形状和填充顺序不同，但原则不变：填当前格前依赖于的格子必须已填好。
  </GlossaryItem>
</Glossary>
