## 从2的n次方个背包组合开始

先预测：4磅背包有吉他、音响、笔记本三件物品，每件只能整件拿或不拿。检查所有组合只需8次；若增加到30件，还能逐个组合尝试吗？

背包问题的简单穷举需要2^n。每增加一件物品，已有每个组合都分裂为“拿新物品”和“不拿新物品”两种，组合数翻倍。下面的位掩码实现能得到精确答案，但运行次数直接等于幂集大小：

```python
def brute_force_knapsack(
    items: list[tuple[str, int, int]], capacity: int
) -> tuple[int, list[str]]:
    best_value = 0
    best_items: list[str] = []
    for mask in range(1 << len(items)):
        total_weight = 0
        total_value = 0
        chosen: list[str] = []
        for index, (name, weight, value) in enumerate(items):
            if mask & (1 << index):
                total_weight += weight
                total_value += value
                chosen.append(name)
        if total_weight <= capacity and total_value > best_value:
            best_value = total_value
            best_items = chosen
    return best_value, best_items

items = [("吉他", 1, 1500), ("音响", 4, 3000), ("笔记本", 3, 2000)]
assert brute_force_knapsack(items, 4) == (3500, ["吉他", "笔记本"])
```

30件物品对应超过十亿个子集。上一章的贪心能快速给某个答案，却不保证0/1背包精确最优。<Term def="把问题拆成一组可枚举状态的子问题，保存每个子问题答案并由小到大组合的算法设计方法。">动态规划</Term>提供另一条路：不枚举完整选择序列，而是只求“前若干物品、给定容量”这些真正影响后续的子问题。

## 4磅背包网格

动态规划把问题拆成离散子问题。对原章的三件物品，动态规划表格每行对应物品，表格每列对应容量1、2、3、4磅。<Term def="以有限索引表示问题状态的子问题，例如前i件物品与容量w的组合。">离散子问题</Term>由两个坐标标识：

- 行 `i` 表示只允许使用前 `i` 件物品。
- 列 `w` 表示背包容量上限为 `w`。
- 单元格表示当前物品和容量下的最大价值，即 `cell[i][w]`。

<KnapsackGridDiagram />

第一行只有1磅、1500美元的吉他，容量1到4都能放入它，所以各格都是1500。第二行加入4磅、3000美元的音响：容量1到3仍只能选择吉他，容量4比较吉他1500与音响3000，写入3000。第三行加入3磅、2000美元的笔记本：容量4可以把笔记本与剩余1磅格中的吉他组合，得到3500，超过不选笔记本的3000。

<Stepper>
  <Step title="给每个格子一句完整定义"><KnapsackGridDiagram />`cell[i][w]` 表示只看前i件物品、容量不超过w时的最大价值，不是“当前物品价值”。</Step>
  <Step title="先写不选择候选">不选择当前物品时继承上一行：物品集合退回前i-1件，容量保持w。</Step>
  <Step title="再写选择候选"><KnapsackDecisionLab />选择当前物品时加上剩余容量最优值：当前价值加上一行的 `w-weight[i]` 列。</Step>
  <Step title="取两种方案最大值">取选择与不选择两种方案最大值写入当前格；若物品装不下，只能继承上一行。</Step>
</Stepper>

## 状态转移为何不能少定义

<Term def="存放所有离散子问题答案、并按依赖顺序填充的网格或数组。">DP表格</Term>不是算法本身，状态语义才决定格子如何解释。0/1背包转移可写成：

`cell[i][w] = cell[i-1][w]`，当当前物品重量大于容量；

否则比较 `cell[i-1][w]` 与 `value[i] + cell[i-1][w-weight[i]]`，取较大值。

两个候选都读上一行，因为第i件物品一旦选择，剩余容量只能继续使用前i-1件物品。若选择分支错误地读取当前行，就可能再次使用第i件，把0/1背包变成允许重复拿同类物品的完全背包。

<Term def="完整问题的最优解可由若干子问题的最优解组合得到的性质。">最优子结构</Term>解释了为何可以复用剩余容量的最优值：如果一个最优方案选择了笔记本，那么拿掉笔记本后，余下物品必须是“前两件、容量1磅”的最优方案；否则换成更好的余下方案就能改善原答案，和最优性矛盾。动态规划依赖最优子结构。

<Term def="不同决策路径会反复到达同一个状态，使缓存该状态答案可以避免重复求解的性质。">重叠子问题</Term>解释了为何表格比递归枚举快。许多选择序列会留下相同的“处理到第i件、剩余容量w”；动态规划复用重叠子问题，让每个 `(i,w)` 只求一次。

<Callout type="trap" title="只要写递归就一定适合动态规划">
递归只是控制流。DP需要状态可复用，并且转移能由已解子问题构成；若子问题互不重叠，缓存可能没有收益；若状态遗漏影响未来的信息，表格会合并本不等价的情况并给出错误答案。
</Callout>

## 实现填表并回溯选择

下面实现同时保存最大价值表与是否选择当前物品的布尔表。<Term def="从最终状态沿转移来源逆向移动，恢复构成最优值的具体决策。">回溯</Term>从右下角开始：若当前格选择了物品，就记录名称并减去重量；否则只移动到上一行。

```python
def knapsack_dp(
    items: list[tuple[str, int, int]], capacity: int
) -> tuple[int, list[str]]:
    rows = len(items) + 1
    cell = [[0] * (capacity + 1) for _ in range(rows)]
    take = [[False] * (capacity + 1) for _ in range(rows)]

    for i, (_, weight, value) in enumerate(items, start=1):
        for current_capacity in range(capacity + 1):
            without_item = cell[i - 1][current_capacity]
            cell[i][current_capacity] = without_item
            if weight <= current_capacity:
                with_item = value + cell[i - 1][current_capacity - weight]
                if with_item > without_item:
                    cell[i][current_capacity] = with_item
                    take[i][current_capacity] = True

    chosen: list[str] = []
    current_capacity = capacity
    for i in range(len(items), 0, -1):
        if take[i][current_capacity]:
            name, weight, _ = items[i - 1]
            chosen.append(name)
            current_capacity -= weight
    chosen.reverse()
    return cell[-1][-1], chosen

assert knapsack_dp(items, 4) == (3500, ["吉他", "笔记本"])
```

时间和表空间都是 `O(nW)`。这里的 `W` 是容量数值而不是输入位数；当容量以二进制编码时，`W` 可能相对输入长度指数大，因此0/1背包DP是<Term def="复杂度对数值大小呈多项式，但对表示该数值所需位数不一定是多项式。">伪多项式时间</Term>，不能简单说它解决了一般背包的多项式时间精确求解。

若只求最优值，可把表压成一行并让容量从大到小更新，空间降为 `O(W)`；若还要恢复选择，需要保留二维表、父指针或额外重算。工程上先决定输出只需数值还是还需方案，再选择存储结构。

## 背包FAQ：新增、顺序与粒度

<DpDesignMap />

新增物品只需新增一行，因为旧表已经包含“不使用新物品”的全部子问题。新行逐列比较旧答案与“新物品价值加剩余容量旧答案”，无需重新枚举原物品组合。

改变物品行顺序不改变最优值：中间行代表的“前i件物品”集合会变化，单元格可能不同，但最后一行仍考虑全部物品，最终可行组合相同。前提是每件物品恰好处理一次，转移与初始化保持一致。

列粒度决定可表示的重量。若列步长是1磅，就不能直接表示0.5磅物品；可以把所有重量乘2，以半磅为一单位，但列数也相应翻倍。若重量是高精度连续数，简单容量网格可能不可行，需要重新离散化、换状态维度或使用其他算法。

不可分割物品与分数背包不同。0/1背包的格子只比较整件拿或不拿；分数背包允许拿一部分，按价值密度贪心可精确填满容量。不能在0/1表中用“剩余半件”补空位。

<Stepper>
  <Step title="新增物品时追加一行"><DpDesignMap />上一行已经总结所有旧物品组合，新行只引入拿或不拿新物品的二选一。</Step>
  <Step title="重排行时检查最终不变量">逐行中间值会变，但每件物品处理一次后，最后一行仍覆盖同一可行方案集合。</Step>
  <Step title="由最小重量单位设计列">把0.5磅缩放为1个单位，把4磅容量缩放为8个单位；先估算表宽能否接受。</Step>
  <Step title="从右下角回溯恢复选择"><KnapsackDecisionLab />比较当前格的来源；选择物品则减少容量，不选择则只上移一行。</Step>
</Stepper>

<Callout type="trap" title="O(nW)就是关于输入长度的多项式时间">
W是容量数值。容量10亿只需约30个二进制位，却会产生10亿列；因此该算法是伪多项式时间。复杂度评估必须同时看数值范围和编码长度。
</Callout>

## 最长公共子串与最长公共子序列

背包按物品与容量建立网格，字符串也能按两个字符位置建立网格。相似的表形不代表同一转移：必须先决定“连续匹配”还是“允许跳过字符”。

<StringMatchGridDiagram />

<Term def="同时出现在两个字符串中且字符连续的最长片段。">最长公共子串</Term>要求连续。若当前字符相同，格子等于左上角加1；若不同，连续链被打断，格子归零。最大值可能出现在表内任意位置，记录最大值结束坐标即可恢复子串。HISH与FISH的最长公共子串是ISH，长度3。

<Term def="同时保持两个字符串字符相对顺序、但允许跳过字符的最长序列。">最长公共子序列</Term>不要求连续。字符相同时取左上角加1；字符不同时，取上方和左方较大值，表示跳过某一侧字符。答案在右下角；从表格回溯，相等时收集字符并斜向移动，不等时走向较大邻格。FOSH与FISH的最长公共子序列可为FSH，长度3。

```python
def longest_common_substring(a: str, b: str) -> str:
    cell = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    best_length = 0
    best_end = 0
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                cell[i][j] = cell[i - 1][j - 1] + 1
                if cell[i][j] > best_length:
                    best_length = cell[i][j]
                    best_end = i
    return a[best_end - best_length:best_end]

def longest_common_subsequence(a: str, b: str) -> str:
    cell = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                cell[i][j] = cell[i - 1][j - 1] + 1
            else:
                cell[i][j] = max(cell[i - 1][j], cell[i][j - 1])

    chars: list[str] = []
    i, j = len(a), len(b)
    while i > 0 and j > 0:
        if a[i - 1] == b[j - 1]:
            chars.append(a[i - 1])
            i -= 1
            j -= 1
        elif cell[i - 1][j] >= cell[i][j - 1]:
            i -= 1
        else:
            j -= 1
    return "".join(reversed(chars))

assert longest_common_substring("HISH", "FISH") == "ISH"
assert longest_common_subsequence("FOSH", "FISH") == "FSH"
```

<Stepper>
  <Step title="先定义匹配是否必须连续"><StringMatchGridDiagram />子串要求连续，子序列只保持顺序；这一句话决定不匹配时是归零还是继承邻格。</Step>
  <Step title="定义行列为字符前缀">`cell[i][j]` 只看两个字符串的前i与前j个字符，空前缀行列初始化为0。</Step>
  <Step title="按依赖方向填表">相等都读左上角；子串不等写0，子序列不等取上方与左方最大值。</Step>
  <Step title="按答案位置回溯">子串从全表最大格向前截取连续片段；子序列从右下角沿转移来源逆向收集字符。</Step>
</Stepper>

<Callout type="trap" title="公共子串和公共子序列只差名字">
两者状态转移与答案位置不同。把子序列的不匹配继承规则用于子串，会错误地把分散字符拼成不连续片段；把子串归零规则用于子序列，则会漏掉可跳过字符的更长答案。
</Callout>

## 原章概念回查

背包问题的简单穷举需要2^n，动态规划把问题拆成离散子问题。动态规划表格每行对应物品，表格每列对应容量，单元格表示当前物品和容量下的最大价值。

不选择当前物品时继承上一行；选择当前物品时加上剩余容量最优值；取选择与不选择两种方案最大值。

改变物品行顺序不改变最优值，新增物品只需新增一行，列粒度决定可表示的重量，不可分割物品与分数背包不同。

动态规划依赖最优子结构，动态规划复用重叠子问题。最长公共子串要求连续，最长公共子序列只保持顺序；从表格回溯恢复选择或匹配字符。

## 本章回顾

1. n个0/1选择形成2的n次方个组合。
2. DP只保留能影响未来的离散状态，不保留完整决策历史。
3. 背包格子定义为前i件物品在容量w下的最大价值。
4. 不选当前物品读取上一行同列。
5. 选择当前物品读取上一行剩余容量列并加当前价值。
6. 最优子结构保证可用子问题最优值组合大问题答案。
7. 重叠子问题让表格缓存避免重复求解。
8. 新物品追加一行，物品行顺序不改变最终最优值。
9. 容量粒度控制可表示重量，也控制表格宽度。
10. O(nW)背包DP是伪多项式时间。
11. 公共子串不匹配归零，公共子序列不匹配继承邻格最大值。
12. 最优数值与具体方案是两种输出，后者需要记录并回溯转移来源。

<Exercises>

**问题 1：4磅背包的吉他、音响、笔记本表中，右下角3500是怎样计算出来的？**

<Answer>不选笔记本时继承上一行容量4的3000。选择笔记本时得到其价值2000，加上上一行剩余容量1的最优值1500，也就是吉他，总计3500。取两者最大值，因此写3500并记录选择笔记本。</Answer>

**问题 2：把物品行顺序改成笔记本、吉他、音响，最终最优值会改变吗？**

<Answer>不会。中间行代表的物品集合不同，单元格会变化，但最后一行仍考虑同样三件物品，每件最多一次，可行组合集合相同，所以最终最优值仍是3500。若实现错误地读取当前行或重复物品，才可能改变结论。</Answer>

**问题 3：背包含0.5磅物品而表格列步长为1磅，应如何处理？**

<Answer>若所有重量都是0.5磅的整数倍，可统一乘2，把半磅作为一个容量单位：4磅容量变成8列单位。若重量精度更细或为任意实数，列数可能不可接受，需要重新离散化、改变状态或换算法。</Answer>

**问题 4：为什么HISH与FISH的公共子串可以是ISH，而FOSH与FISH的公共子序列可以是FSH？**

<Answer>ISH在两个字符串中都连续出现，所以是长度3的公共子串。FSH在FOSH和FISH中都按F、S、H顺序出现，但中间各跳过一个不同字符，因此是公共子序列而不是公共子串。</Answer>

</Exercises>
