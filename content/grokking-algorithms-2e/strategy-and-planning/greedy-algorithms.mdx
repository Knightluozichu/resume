## 先玩一遍

贪心算法是一种「只管眼前」的策略。每一步它选中看起来最有利的那个选项，然后永不回头。听起来像赌博——但有些问题天生就允许这样：每步的局部最优叠加起来恰好也是全局最优。

## 核心概念

<Term def="每一步做当前看起来最优的选择，不再回溯，最终得到一个可接受（甚至最优）的解。">贪心算法</Term>
是一种策略范式，不是具体算法。它回答「如果我只顾眼前利益、永不反悔，能走到哪里？」。
贪心不保证最优——除非问题本身经过数学证明满足两个条件（见下）。但当精确求解太慢时，贪心近似常常是工程中唯一可行的选择。

<Term def="问题的最优解包含子问题的最优解——这是动态规划和贪心都依赖的性质。">最优子结构</Term>
是贪心和动态规划共同的立身之本。如果一个问题的全局最优解可以由局部最优决策「拼起来」，那问题就有最优子结构。有最优子结构 ≠ 贪心一定对——还需要「贪心选择性质」。

<Term def="局部最优选择能通向全局最优，不需要回溯比较其他选择。">贪心选择性质</Term>
是区分「能用贪心」和「必须用 DP」的界限。集合覆盖问题没有贪心选择性质（选当前最多的电台可能堵死后续更好的组合），所以贪心只能给近似。Dijkstra 有贪心选择性质（每次锁定最近节点就是全局最优的一步），所以贪心给精确解。

<Term def="无法在多项式时间内精确求解的问题类别，但可以在多项式时间内验证一个猜测。">NP 完全</Term>
是理解「为什么有时候必须用近似算法」的关键背景。旅行商问题、集合覆盖都属此类——精确求解是指数级时间。面对 NP 完全问题，贪心策略不是「偷懒」，而是唯一现实的出路：在合理时间内拿到足够好的答案。

## 代码拆解：集合覆盖的贪心实现

贪心的代码结构非常清晰——三步走：扫描未覆盖元素、挑最佳候选、标记已覆盖。下面拆开讲每一步的逻辑重点。

**第一步——维护「未覆盖集」**。用一个集合存储还没被覆盖的元素。每选中一个电台，就把它覆盖的元素从未覆盖集中移除。当集合变空时算法结束。

```python
states_needed = set(["mt", "wa", "or", "id", "nv", "ut", "ca", "az"])
stations = {
    "kone":   {"id", "nv", "ut"},
    "ktwo":   {"wa", "id", "mt"},
    "kthree": {"or", "nv", "ca"},
    "kfour":  {"nv", "ut"},
    "kfive":  {"ca", "az"},
}
final_stations = set()
```

**第二步——每轮挑出覆盖最多未覆盖元素的候选**。这是贪心的核心「度量」：
每个候选站只算它和未覆盖集的交集。不关心它之前覆盖过什么，也不考虑「选了这个会不会堵住后面的组合」。
这是贪心最激进也最脆弱的地方——它在做一个不可逆的局部决策。

```python
while states_needed:
    best_station = None
    states_covered = set()
    for station, states_for_station in stations.items():
        covered = states_needed & states_for_station
        if len(covered) > len(states_covered):
            best_station = station
            states_covered = covered
    states_needed -= states_covered
    final_stations.add(best_station)
```

**第三步——时间复杂度分析**。while 循环最多跑 n 趟（每个电台最多被选一次），
每趟扫描 m 个剩余电台计算交集。总复杂度约 O(nm)。对比暴力穷举的 O(2^n)，
贪心把一个不可能完成的任务变成了秒出的答案——代价是「最优」可能差一点。

## 常见误区

- **现象 →** 以为贪心在所有问题上都给最优解。**原因 →** 教科书先讲贪心最优的例子（Dijkstra、MST），容易形成「贪心=最优」的错觉。**修法 →** 记住一条铁律：贪心给最优需要满足「贪心选择性质」，不是所有问题都有。集合覆盖就是反面教材——贪心只能近似。

- **现象 →** 在硬币找零问题上，以为贪心总能给最优。**原因 →** 人民币面额 {1,5,10,20,50,100} 恰好让贪心最优，但并非所有面额组合都如此。**修法 →** 试面额 {1,3,4}，找零 6。贪心 pick 4+1+1=3 枚，最优是 3+3=2 枚。

- **现象 →** 看到 NP 完全就放弃，不知道还有近似算法这条路。**原因 →** 把「NP 完全」理解成「无解」，其实是无「多项式时间精确解」。**修法 →** 贪心、局部搜索、遗传算法——近似解法才是处理 NP 完全问题的工程标准答案。不求最优，求满意。

<Callout type="trap">
  <strong>现象 →</strong> 对一个问题试了贪心发现有效，就直接宣布「贪心给最优」，没有做任何理论验证。<strong>原因 →</strong>{" "}
  把「通过测试用例」等同为「数学正确」。贪心失效的极端情况往往不在随手构造的例子里。<strong>修法 →</strong>{" "}
  真正的验证需要证明两件事：(1) 贪心选择性质成立，(2) 最优子结构成立。不能靠跑几个用例替代。
</Callout>

<Callout type="trap">
  <strong>现象 →</strong> 在需要精确最优的场景用贪心近似替代。<strong>原因 →</strong>{" "}
  贪心实现简单，忽略了一旦给近似解意味着可能和最优差几个数量级。<strong>修法 →</strong>{" "}
  对 NP 完全问题，先算贪心近似比（该问题已知的最差情况差距多大），再决定是否接受这个误差范围。
</Callout>

## 小结与练习

- 贪心 = 每一步选局部最优，不回头，最终得到一个也许最优、也许近似的答案。
- 贪心成立两条件：贪心选择性质（局部最优通向全局）+ 最优子结构（子问题最优可拼）。
- 集合覆盖是 NP 完全问题，贪心给近似解，近似比有理论保证。
- Dijkstra 和 MST 具备贪心选择性质，贪心给精确最优——这是幸运，不是贪心的本事。

  <Answer question="改代码：把贪心度量从「覆盖最多未覆盖元素」改成「覆盖最少未覆盖元素」，结果会怎样？">
    贪心会选择最没用的站来凑数，会先用完 kfour（仅覆盖 2 个州），再用 kfive（2 个），以此类推。最终选中的电台数可能远多于最优解——这证明了贪心度量必须精心设计，不能随便换。
  </Answer>
  <Answer question="为什么集合覆盖问题的贪心近似能被证明「接近最优可能的形式」？">
    因为已经证明：不存在多项式时间算法能给出比贪心更好近似比的保证，除非 P=NP。换句话说，贪心在对集合覆盖的近似这件事上已经是理论极限——不是为了省事，是没有更好的路。

## 名词解释

<Glossary>
  <GlossaryItem term="贪心算法">
    一种策略范式：每一步根据当前信息做出看似最优的选择，不做回溯。对某些问题给精确最优，对另一些给近似解。
  </GlossaryItem>
  <GlossaryItem term="最优子结构">
    一个问题的最优解可以由它的子问题的最优解「拼合」而成。这是动态规划和贪心共同的必要前提。
  </GlossaryItem>
  <GlossaryItem term="贪心选择性质">
    局部最优选择可以安全地固定下来，不需要考虑其他可能——因为这条选择一定出现在某个全局最优解中。拥有此性质的问题贪心即最优。
  </GlossaryItem>
  <GlossaryItem term="NP 完全">
    一类「猜容易、算难」的问题：验证一个候选解很快，但找到最优解在最坏情况下需要指数时间。集合覆盖、旅行商均在此列。
  </GlossaryItem>
  <GlossaryItem term="近似算法">
    不求最优、求足够好的算法。通常附有近似比——保证结果不会比最优差超过某个倍数的证明。
  </GlossaryItem>
</Glossary>
