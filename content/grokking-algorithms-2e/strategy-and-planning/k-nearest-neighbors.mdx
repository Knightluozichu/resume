## 从橙子与葡萄柚开始

先预测：一个水果比常见橙子更大、更红，但又没有典型葡萄柚那么明显。若只看“它最像谁”，怎样把直觉变成可重复算法？

<FruitFeatureDiagram />

原章用橙子与葡萄柚分类建立直觉：葡萄柚通常更大、更红，橙子通常更小、颜色不同。<Term def="预测时寻找新样本附近的k个已标注样本，并聚合它们标签或数值的算法。">K近邻</Term>根据最相似样本预测。对新水果选择最近的k个邻居，分类用邻居多数投票；若三位邻居中两位是橙子、一位是葡萄柚，就预测橙子。

这里没有自动出现的“相似”。必须先决定怎样描述水果、怎样缩放数值、用什么距离以及选择多少邻居。KNN简单，是因为规则短；并不意味着数据表示和验证可以省略。

## 特征提取与距离

<Term def="把原始对象转换成可供算法比较的数值属性的过程。">特征提取</Term>把对象表示为数值。水果可以用大小、重量、红度、表皮纹理等特征；用户可以用对不同电影类型的偏好评分。选择与任务相关的特征比盲目增加维度更重要：包装条形码可能唯一识别水果，却未必帮助判断品种。

<Term def="按固定顺序排列的一组数值，用于表示一个对象。">特征向量</Term>例如 `[大小=7.2, 红度=6.8]`。向量各维必须在训练样本与新样本中含义一致，缺失值、类别编码和单位也要使用同一规则。

<Term def="多维空间中两点各坐标差平方和的平方根。">欧氏距离</Term>衡量特征向量接近程度：

$$
d(x,y)=\sqrt{\sum_{j=1}^{p}(x_j-y_j)^2}.
$$

下面只用训练样本拟合均值和标准差，再用同一参数变换训练样本与查询。若先把验证集或测试集也纳入均值计算，就把未来数据分布泄漏给模型评估。

```python
from math import sqrt
from statistics import fmean

def fit_standardizer(rows: list[list[float]]) -> tuple[list[float], list[float]]:
    columns = list(zip(*rows))
    means = [fmean(column) for column in columns]
    scales = []
    for column, mean in zip(columns, means):
        variance = fmean([(value - mean) ** 2 for value in column])
        scales.append(sqrt(variance) or 1.0)
    return means, scales

def transform(
    row: list[float], means: list[float], scales: list[float]
) -> list[float]:
    return [
        (value - mean) / scale
        for value, mean, scale in zip(row, means, scales)
    ]

def euclidean(left: list[float], right: list[float]) -> float:
    if len(left) != len(right):
        raise ValueError("feature dimensions differ")
    return sqrt(sum((a - b) ** 2 for a, b in zip(left, right)))
```

<Term def="用训练集参数把各特征转换到可比较尺度的预处理，包括归一化或标准化。">特征缩放</Term>防止数值范围大的维度支配距离。例如重量100至300克、红度0至1时，未缩放欧氏距离几乎只看重量。特征归一化或标准化不能保证每个特征都同样有用，但能消除纯单位尺度造成的支配。

<Stepper>
  <Step title="定义与任务相关的特征"><FruitFeatureDiagram />水果品种可看大小与红度；先解释每一维为何可能帮助区分类别。</Step>
  <Step title="只用训练集拟合缩放参数">计算训练集各维均值与标准差，保存参数；验证、测试和线上查询只做transform。</Step>
  <Step title="计算到全部样本的距离"><KnnVoteLab />对每个已标注样本计算同一种距离，保证特征顺序、单位与缺失值处理一致。</Step>
  <Step title="选择最近的k个邻居">按距离从小到大选前k个，保留距离和标签，供投票、加权或回归聚合。</Step>
</Stepper>

<Callout type="trap" title="所有特征原值直接算距离">
量纲大的特征会支配欧氏距离。应在训练折内拟合缩放参数，并把同一变换应用到验证与查询；仍需通过验证判断特征是否相关，缩放不能修复无关特征。
</Callout>

## 分类：多数投票

<Term def="从有限类别中为新样本预测一个标签的任务。">分类</Term>用邻居标签聚合。最简单的<Term def="把k个邻居中出现次数最多的类别作为预测结果的规则。">多数投票</Term>只数票；也可以让更近邻居权重更大。二分类常选奇数k减少平票，但多分类或重复距离仍可能平票，所以实现需要确定的决胜规则。

```python
from collections import defaultdict

Sample = tuple[list[float], str]

def knn_classify(
    samples: list[Sample], query: list[float], k: int
) -> str:
    if not 1 <= k <= len(samples):
        raise ValueError("k must be within the sample count")

    nearest = sorted(
        (euclidean(features, query), label)
        for features, label in samples
    )[:k]

    votes: dict[str, list[float]] = defaultdict(list)
    for distance, label in nearest:
        votes[label].append(distance)

    return min(
        votes,
        key=lambda label: (
            -len(votes[label]),
            sum(votes[label]),
            label,
        ),
    )
```

决胜键依次比较票数更多、同票时邻居总距离更小、再同票时标签字典序，因此结果可复现。生产系统还应处理类别不平衡、重复样本、置信度阈值与拒绝预测；“多数类”可能只是训练数据数量更多，不一定代表局部证据更强。

<Stepper>
  <Step title="检查k与样本数量"><KnnVoteLab />k至少为1且不能超过可用训练样本；交叉验证的每个训练折都要满足该条件。</Step>
  <Step title="按距离截取最近邻">不要先按标签分组；邻居资格只由统一距离或相似度定义决定。</Step>
  <Step title="聚合标签并处理平票">多数投票给出类别；可用距离和作为平票规则，或使用预先声明的距离加权。</Step>
  <Step title="在验证集选择k与规则"><KSelectionLab />同时比较准确率、召回率、类别不平衡影响和预测延迟，不查看测试集调参。</Step>
</Stepper>

## k过小与k过大

k过小对噪声敏感。k等于1时，一个错标样本或离群点就能独自决定附近查询，模型方差高、决策边界容易出现孤岛。k过大可能抹平局部结构；当k接近训练集大小时，预测趋向全局多数类，小类区域会被淹没，偏差增大。

没有脱离数据的固定最佳k。应在训练数据内部交叉验证候选k，并把缩放、特征选择等步骤放进每个训练折，最后只在独立测试集做一次无偏评估。距离度量、投票权重和特征集合也都是模型选择的一部分，“k是唯一超参数”并不成立。

<KSelectionLab />

<Callout type="trap" title="在测试集上挑出表现最好的k">
反复查看测试结果会把测试集变成调参数据，使最终分数乐观。应使用训练/验证或交叉验证选择k，锁定方案后再评估一次测试集。
</Callout>

## 推荐系统：寻找相似用户

<Term def="根据用户历史与相似关系生成其可能感兴趣内容的系统。">推荐系统</Term>与水果分类共享同一结构。先把用户表示为喜剧、动作、剧情、恐怖、爱情等偏好特征向量；再寻找距离近的用户；相似用户提供推荐候选，即他们高评分而目标用户尚未看过的电影。

<RecommendationFeatureMap />

特征提取决定“口味相似”的含义。评分缺失不应简单当作0分，因为“没看过”和“不喜欢”不同；不同用户评分尺度也可能不同，有人总打5分，有人最高只打3分。实际协同过滤常使用共同评分项、中心化、余弦相似度或更专门的矩阵方法。原章KNN故事的重点是：推荐前必须先把对象转成可比较表示。

## 回归：对邻居目标值求平均

<Term def="预测连续数值而不是离散类别的任务。">回归</Term>对邻居目标值求平均。例如预测用户会给一部电影多少分，可以找最相似用户并平均他们对该电影的评分；也可按距离倒数加权，让更近用户贡献更大。

```python
NumericSample = tuple[list[float], float]

def knn_regress(
    samples: list[NumericSample], query: list[float], k: int
) -> float:
    if not 1 <= k <= len(samples):
        raise ValueError("k must be within the sample count")
    nearest = sorted(
        (euclidean(features, query), target)
        for features, target in samples
    )[:k]
    return fmean(target for _, target in nearest)

ratings = [
    ([5.0, 1.0, 4.0], 4.5),
    ([4.0, 1.0, 5.0], 4.0),
    ([1.0, 5.0, 1.0], 1.5),
]
prediction = knn_regress(ratings, [4.5, 1.0, 4.5], k=2)
assert prediction == 4.25
```

分类与回归的邻居搜索相同，输出聚合不同。分类数标签频率，回归平均或加权平均连续目标。回归还要关注异常目标值、评分范围与均方误差等指标；平均值可能被极端邻居拉动。

<Stepper>
  <Step title="把用户转成同构特征向量"><RecommendationFeatureMap />每一维表示相同电影类型或行为统计，缺失值与评分尺度使用统一语义。</Step>
  <Step title="寻找相似用户">在缩放或中心化后的表示上计算距离，选择最近的k位用户。</Step>
  <Step title="区分推荐候选与最终分数">邻居喜欢的未看内容形成候选；再用邻居评分聚合估计目标用户偏好。</Step>
  <Step title="回归时平均目标值">若预测连续评分，对邻居目标值求平均或预先验证的距离加权平均，而不是类别投票。</Step>
</Stepper>

## 成本、索引与局限

KNN训练成本低但预测需搜索样本。训练阶段至少要校验、缩放并存储 `n` 个 `d` 维样本，时间与内存通常是 `O(nd)`，只是没有昂贵的参数优化循环。暴力预测计算全部距离也是 `O(nd)`；全排序是 `O(n log n)`，维护大小k的堆可降为 `O(n log k)`。

低维、分布合适时，KD-tree或ball tree可能显著加速精确查询；但树索引没有对任意高维数据的统一 `O(log n)` 保证。维度升高后数据变稀疏，最近与较远距离的区分度可能下降，这就是常说的维数灾难。此时可减少无关维度、学习更合适表示，或在可接受召回损失时使用近似最近邻。

<Term def="训练阶段主要保存样本，把大部分计算推迟到查询阶段的学习方式。">惰性学习</Term>描述这种取舍，但“惰性”不等于训练零成本。数据更新简单、局部模式直观是优点；内存大、预测慢、对表示敏感是代价。

线上更新还会改变邻域本身。追加新样本虽不需要重新优化参数，却可能要求重新计算缩放统计、重建近邻索引并重新验证k；删除隐私数据也必须同步清理样本库和索引。评估时应按真实时间或用户边界切分数据，避免同一用户的近重复记录同时进入训练与测试，让最近邻“认出副本”而不是学到可泛化相似性。

监控也要覆盖数据漂移：若新水果尺寸分布或用户口味长期偏离训练样本，最近邻可能仍返回结果，却已经没有足够接近的可靠参照。可记录最近距离、邻居标签一致度和拒绝率，为低置信查询设置人工或后备策略。

<Callout type="trap" title="使用KD-tree后查询一定是O(log n)">
查询成本依赖维度、数据分布、距离和树平衡；高维时大量分支可能都需访问，最坏情况接近线性扫描。应在真实数据上测延迟与召回，再决定精确索引或近似近邻。
</Callout>

## 原章概念回查

K近邻根据最相似样本预测，橙子与葡萄柚分类展示了大小和红度的局部邻域。特征提取把对象表示为数值，欧氏距离衡量特征向量接近程度。

算法选择最近的k个邻居，分类用邻居多数投票。k过小对噪声敏感，k过大可能抹平局部结构。特征尺度不同会支配距离，因此要做特征归一化或标准化。

推荐系统把用户表示为特征向量，相似用户提供推荐候选。回归对邻居目标值求平均。选择与任务相关的特征，才能让距离表示真实相似。

KNN训练成本低但预测需搜索样本；具体成本还包括数据存储、缩放、邻居选择和索引维护。

## 本章回顾

1. KNN依据局部相似样本进行分类或回归。
2. 特征提取先决定对象如何进入数值空间。
3. 欧氏距离只是众多距离之一，必须匹配特征语义。
4. 缩放参数只从训练数据拟合并复用于未来查询。
5. 分类用多数投票或距离加权投票。
6. k过小易受噪声影响，k过大易忽略局部结构。
7. k、距离、权重、特征和缩放都需要验证。
8. 推荐系统可由相似用户产生候选与评分估计。
9. 回归平均邻居连续目标值，不做类别投票。
10. KNN存储训练样本，暴力查询需计算到全部样本的距离。
11. 树索引对低维可能有效，高维不能承诺对数查询。
12. 特征质量、维度和数据分布往往比算法代码更决定结果。

<Exercises>

**问题 1：重量范围100至300克、红度范围0至1，直接算欧氏距离会有什么问题？**

<Answer>重量差可达数百，红度差最多1，平方和几乎由重量决定，红度即使有分类价值也难以影响邻居。应只用训练集拟合标准化或归一化参数，再对验证、测试和查询使用同一变换。</Answer>

**问题 2：k等于1和k接近训练样本数时分别有什么风险？**

<Answer>k等于1时单个噪声、错标或离群样本就能决定预测，方差高；k很大时局部类别被全局多数稀释，偏差高，小类尤其容易被淹没。应通过训练集内部交叉验证选择。</Answer>

**问题 3：三位相似用户对电影评分4、5、2，未加权KNN回归预测是多少？**

<Answer>未加权平均为 `(4+5+2)/3 = 11/3`，约3.67。若采用距离加权，结果取决于三位邻居距离；权重规则必须预先定义并在验证数据上选择。</Answer>

**问题 4：“KNN没有训练，所以训练时间和存储都是O(1)”是否正确？**

<Answer>不正确。KNN通常没有参数优化循环，但仍需校验、变换和保存n个d维样本，时间与内存至少是O(nd)尺度。计算主要被推迟到预测，暴力查询也要O(nd)计算距离。</Answer>

</Exercises>
