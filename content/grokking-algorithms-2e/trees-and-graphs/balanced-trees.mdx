## 从查找与插入的矛盾开始

先预测：有序数组二分查找是 `O(log n)`，但中间插入要移动后缀；链表在已知位置时改链接很快，但按键查找是 `O(n)`。能否让查找和插入都只沿一条较短路径完成？

<Term def="对每个节点维持左子树键更小、右子树键更大的二叉树。">二叉搜索树</Term>简称BST。查找从根开始：目标小就走左边，大就走右边；插入沿同一比较路径走到空位。重复键必须由实现明确规定拒绝、计数或固定放一侧，本页示例选择忽略重复键。

```python
from dataclasses import dataclass

@dataclass
class BstNode:
    key: int
    left: "BstNode | None" = None
    right: "BstNode | None" = None

def bst_insert(node: BstNode | None, key: int) -> BstNode:
    if node is None:
        return BstNode(key)
    if key < node.key:
        node.left = bst_insert(node.left, key)
    elif key > node.key:
        node.right = bst_insert(node.right, key)
    return node

def bst_contains(node: BstNode | None, key: int) -> bool:
    current = node
    while current is not None:
        if key == current.key:
            return True
        current = current.left if key < current.key else current.right
    return False
```

每次操作访问一条根到空位或目标的路径，所以普通BST时间是 `O(h)`，其中<Term def="从根到最深叶路径所含边数或层数的尺度，决定根到叶操作上界。">树高</Term>为 `h`。若高度是对数级，查找和插入是 `O(log n)`；若高度接近节点数，操作退化为 `O(n)`。

## 插入顺序决定普通BST形状

同一组键1到7，按 `4,2,6,1,3,5,7` 插入能形成较矮树；按 `1,2,3,4,5,6,7` 插入时，每个新键都成为最右孩子，树变成链。插入顺序决定普通BST形状，键集合相同不代表性能相同。

较矮的树查找更快，因为每次比较只能推进一层。随机插入有时得到尚可形状，却不提供确定高度上界；“数据看起来随机”也不是结构不变量。若服务必须抵抗有序输入或敌意顺序，需要会主动维护高度的树。

这里要区分“平均输入下常见的形状”和“数据结构承诺的不变量”。前者依赖输入分布，后者由每次修改主动恢复。平衡搜索树的价值正是把性能保证写进更新算法：即使键按已排序顺序到达，也不能允许根到叶路径无限拉长。

  <Step title="建立BST顺序"><BstShapeDiagram />从根比较，较小键进入左子树，较大键进入右子树，重复键按契约处理。</Step>
  <Step title="计算两种插入形状">分别插入中位数优先序列和升序序列，画出节点路径并测量最大深度。</Step>
  <Step title="把成本写成O(h)">不要先写O(log n)；先由访问路径得到O(h)，再说明高度是否有对数保证。</Step>
  <Step title="决定是否需要平衡">输入顺序不可控且查找延迟有上界要求时，选能自动修复高度的结构。</Step>
</Stepper>

<Callout type="trap" title="BST查找天然是O(log n)">
顺序性质只决定往哪边走，不决定两边规模接近。升序插入可形成长度n的链；普通BST查找与插入的正确结论是O(h)。
</Callout>

## 平衡树把高度维持在对数级

<Term def="通过结构约束和局部重组，把搜索树高度控制在对数级的树。">平衡树</Term>把高度维持在O(log n)。维护不一定只花常数总时间：插入首先沿根到叶路径搜索，随后可能沿祖先路径更新高度或其他元数据；单次旋转是 `O(1)`，完整更新仍通常是 `O(log n)`。

第2版依次介绍三种不同思路：

- AVL树用严格高度差和旋转给出每次操作的对数上界。
- 伸展树不保存平衡因子，每次访问后调整，提供摊还性能并利用时间局部性。
- B树让一个节点容纳多个键与孩子，以很高分支因子减少外存层数。

没有一种结构在所有指标上都最好；要看是否需要单次最坏保证、访问是否偏向热点、节点位于内存还是磁盘页。

## AVL平衡因子与失衡阈值

<Term def="每个节点左右子树高度差至多为1的平衡二叉搜索树。">AVL树</Term>是平衡二叉搜索树。定义<Term def="节点左子树高度减右子树高度的值。">平衡因子</Term>：

$$
\operatorname{balance}(v)=h(v.left)-h(v.right).
$$

AVL平衡因子是左右子树高度差，合法值为 `-1、0、1`。插入后，沿搜索路径更新高度；首个祖先绝对平衡因子达到2时触发AVL失衡阈值，并根据高侧与新键方向选择旋转。

<AvlRotationLab />

四种插入失衡覆盖所有方向组合：

1. 左左：右旋修复左左失衡。
2. 右右：左旋修复右右失衡。
3. 左右：双旋修复左右或右左失衡中的LR，先左旋左孩子，再右旋失衡根。
4. 右左：先右旋右孩子，再左旋失衡根。

<Term def="在不改变中序键顺序的前提下，局部重排父子关系以降低高度的操作。">旋转</Term>只重连少量指针。下面的左右旋转先更新下降节点高度，再更新新根高度：

```python
from dataclasses import dataclass

@dataclass
class AvlNode:
    key: int
    left: "AvlNode | None" = None
    right: "AvlNode | None" = None
    height: int = 1

def height(node: AvlNode | None) -> int:
    return node.height if node is not None else 0

def update_height(node: AvlNode) -> None:
    node.height = 1 + max(height(node.left), height(node.right))

def rotate_right(root: AvlNode) -> AvlNode:
    new_root = root.left
    assert new_root is not None
    middle = new_root.right
    new_root.right = root
    root.left = middle
    update_height(root)
    update_height(new_root)
    return new_root

def rotate_left(root: AvlNode) -> AvlNode:
    new_root = root.right
    assert new_root is not None
    middle = new_root.left
    new_root.left = root
    root.right = middle
    update_height(root)
    update_height(new_root)
    return new_root
```

旋转保持二叉搜索树顺序。以右旋为例，设旧根为 `y`、左孩子为 `x`、`x` 的右子树为 `middle`。旋转前有 `x.key < middle.keys < y.key`；把 `middle` 改挂到 `y.left` 后关系仍成立，中序序列完全不变。

<Stepper>
  <Step title="沿插入路径更新高度"><AvlRotationLab />新叶高度为1，返回时逐层用左右孩子高度重算当前节点。</Step>
  <Step title="计算平衡因子">左高减右高；绝对值不超过1就保持结构并继续向上返回。</Step>
  <Step title="识别四种方向">先看失衡节点左重还是右重，再看新键落在高侧孩子的内侧还是外侧。</Step>
  <Step title="旋转并挂回新根">执行单旋或双旋，更新高度，并把旋转返回的新局部根重新接到父节点。</Step>
</Stepper>

```python
def avl_insert(node: AvlNode | None, key: int) -> AvlNode:
    if node is None:
        return AvlNode(key)
    if key < node.key:
        node.left = avl_insert(node.left, key)
    elif key > node.key:
        node.right = avl_insert(node.right, key)
    else:
        return node

    update_height(node)
    balance = height(node.left) - height(node.right)

    if balance > 1:
        assert node.left is not None
        if key > node.left.key:
            node.left = rotate_left(node.left)
        return rotate_right(node)

    if balance < -1:
        assert node.right is not None
        if key < node.right.key:
            node.right = rotate_right(node.right)
        return rotate_left(node)

    return node

root: AvlNode | None = None
for key in [10, 20, 30, 40, 50, 25]:
    root = avl_insert(root, key)
assert root is not None and root.height == 3
```

这个实现覆盖插入，不等于完整生产级AVL：删除后可能有多个祖先继续失衡，重复键、父指针、迭代器和并发也需单独设计。掌握重点是“维护顺序不变量”和“维护高度不变量”两条逻辑不能混在一起。

<Callout type="trap" title="旋转函数改完内部指针就不必返回新根">
旋转会改变局部子树根。调用者若不把返回值挂回父节点或全树根，旋转后的部分可能不可达；高度也必须按先旧根、后新根的顺序更新。
</Callout>

## 伸展树：把刚访问的节点旋到根

<Term def="每次查找、插入或删除后把相关节点通过旋转移动到根附近的BST。">伸展树</Term>不存平衡因子。伸展树把访问节点旋到根：根据节点、父节点和祖父节点方向，执行zig、zig-zig或zig-zag旋转。近期访问过的热点自然靠近根，后续重复访问更快。

<SplayAccessLab />

单次操作可能沿长链走 `Theta(n)`，因此伸展树不保证每次 `O(log n)`。<Term def="把一段操作序列总成本分摊到每次操作，而非要求每次成本相同的分析方法。">摊还分析</Term>说明伸展树提供摊还性能：典型字典操作摊还 `O(log n)`。这里不是假设随机输入，也不是把一次慢操作忽略，而是证明一段任意操作序列的总成本受控。

伸展树适合具有时间局部性的访问，例如少量键在一段时间内频繁使用；它实现元数据少，还能方便分裂与合并。但实时系统若要求每次操作都不超过确定对数上界，AVL等结构更直接。

## B树：用高分支因子减少磁盘访问

<Term def="每个节点可保存多个有序键和多个孩子，并保持所有叶子同层的平衡搜索树。">B树</Term>不是binary tree的缩写。B树一个节点保存多个键和孩子；节点中的键把值域分成多个区间，每个孩子负责一个区间。节点满时分裂并向父节点提升中间键，根分裂时树高才增加。

<BTreePageDiagram />

数据库和文件系统常让一个B树节点匹配磁盘页或存储块。一次昂贵I/O把页内多个键与孩子指针一起读入内存，<Term def="一个内部节点可指向的孩子数量。">分支因子</Term>远大于2。B树降低树高与磁盘访问次数；即使页内要做若干CPU比较，减少随机I/O通常更重要。

设每个节点最多有约 `B` 个孩子，树高尺度约为 `log_B n`。AVL以二叉分支控制内存中的比较路径，B树以宽节点控制页访问路径；两者都追求较矮结构，但成本模型不同。

<Stepper>
  <Step title="先写工作负载"><SplayAccessLab />判断需要单次最坏保证、摊还保证还是热点访问优化。</Step>
  <Step title="确认存储层级"><BTreePageDiagram />内存指针访问和磁盘页访问代价差异巨大，节点布局应匹配介质。</Step>
  <Step title="选择维护策略">AVL保存高度并旋转，伸展树每次访问后调整，B树通过多键页和分裂保持平衡。</Step>
  <Step title="用真实指标验证">同时测查找、修改、内存或页占用、最坏延迟与缓存命中，不只比较大O标签。</Step>
</Stepper>

<Callout type="trap" title="B树是每个节点有两个孩子的平衡BST">
B树的B不表示binary。它是多路搜索树，一个节点保存多个键和多个孩子；高分支因子正是降低磁盘层数的关键。
</Callout>

## AVL、伸展树与B树的使用场景

- AVL：需要内存有序映射，并重视每次查找、插入和删除的对数最坏上界。
- 伸展树：访问具有明显局部性，接受单次波动而重视操作序列的摊还效率。
- B树：索引位于磁盘、SSD页或数据库缓冲池，希望一次页读取携带大量分支信息。

标准库具体采用何种树应查实现文档，不能把“有序映射”自动等同于某一种平衡树。实际选择还要比较成熟实现、并发语义、范围扫描、内存布局与持久化需求。

## 原章概念回查

插入顺序决定普通BST形状，较矮的树查找更快。平衡树把高度维持在O(log n)，避免有序输入把搜索路径拉成长链。

AVL树是平衡二叉搜索树，AVL平衡因子是左右子树高度差；达到AVL失衡阈值时，右旋修复左左失衡，左旋修复右右失衡，双旋修复左右或右左失衡。旋转保持二叉搜索树顺序。

伸展树把访问节点旋到根，伸展树提供摊还性能，适合热点访问但不承诺每次操作的对数最坏时间。

B树一个节点保存多个键和孩子，B树降低树高与磁盘访问次数。AVL、伸展树与B树的使用场景分别对应严格内存平衡、访问局部性与外存页优化。

## 本章回顾

1. 普通BST查找和插入成本为 `O(h)`。
2. 插入顺序能让同一键集形成矮树或链。
3. 平衡树主动把高度维持在 `O(log n)`。
4. AVL要求每个节点左右高度差不超过1。
5. LL与RR用单旋，LR与RL用双旋。
6. 旋转改变父子形状但保持中序键顺序。
7. 完整AVL更新还需沿搜索路径维护高度。
8. 伸展树把访问节点移动到根并利用时间局部性。
9. 伸展树单次可线性，但操作摊还为对数级。
10. B树节点保存多个键和多个孩子。
11. 高分支因子降低树高和昂贵页访问次数。
12. 选型必须匹配最坏保证、访问分布和存储介质。

<Exercises>

**问题 1：把1到7升序插入普通BST与AVL，查找7的路径长度有什么不同？**

<Answer>普通BST形成全右链，查找7要沿1到7访问7个节点，成本线性。AVL在插入过程中旋转，树高保持对数级，7位于约3层结构中；具体根形状取决于旋转过程，但高度上界不退化。</Answer>

**问题 2：插入30、10、20为什么需要LR双旋？**

<Answer>30左重，但新键20落在左孩子10的右侧。直接右旋30会让10上升却仍不平衡；先左旋10把20提升为左子树根，再右旋30，最终20为局部根、10在左、30在右。</Answer>

**问题 3：伸展树某次查找花O(n)，为什么仍可说摊还O(log n)？**

<Answer>摊还界分析的是一整段操作总成本。昂贵伸展会重组长路径，把刚访问节点和沿途结构带到更有利位置，后续操作变便宜；总成本分摊后每次为对数级，不代表那次慢操作本身变快。</Answer>

**问题 4：为什么数据库索引更常使用B树族而不是AVL？**

<Answer>一次磁盘或SSD页访问远比页内比较昂贵。B树一个页节点保存多个键与大量孩子，分支因子高、层数少，因此显著减少随机页读取；AVL每节点键少，二叉高度会带来更多页跳转。</Answer>

</Exercises>
