## 从最少段到最低总成本开始

先预测：从Start到Finish，上方路线只有两段，下方路线有三段。若每段道路耗时不同，边数较少的路线一定更快吗？

<WeightedPathDiagram />

第6章的BFS回答“哪条路经过的边最少”。本章给每条边附上距离、时间、价格等数值，形成。上图上方两段共7分钟，下方三段共6分钟；BFS会选前者，Dijkstra会选后者。加权图的边带有成本，目标不再是数边，而是最小化边权总和。

要求从起点同时求到多个节点的最小成本。Dijkstra寻找非负权图最短路径：图可以有向或无向，也可以有环；真正的前提是从起点可达、参与计算的边权都不能为负。零权边允许存在。

## 使用Dijkstra算法

原章把流程压成四步：

1. 找出。
2. 检查该节点的所有邻居。
3. 若经过当前节点更便宜，就更新邻居成本和父节点。
4. 将当前节点标为已处理，回到第一步。

节点成本是从起点到该节点的当前最小已知代价。初始化时起点为0，直接邻居可写成对应边权，其他节点为无穷大；算法发现更短路线后，成本只会下降。父节点表用于恢复路径：每当邻居成本被改小，同时把当前节点记为这个邻居的新父节点。


## 松弛如何传播更便宜的路线

操作比较：

$$
\operatorname{candidate}=d[u]+w(u,v),\qquad
\text{若 }\operatorname{candidate}\lt d[v]\text{，则更新 }d[v].
$$

其中 `d[u]` 是起点到当前节点 `u` 的已知最小成本，`w(u,v)` 是边成本。松弛操作比较新路径与旧成本；更新邻居成本和父节点必须是同一个原子逻辑。只改成本会丢失路线，只改父节点则会让父链与成本不一致。

原书示例从Start出发：直达A成本6、直达B成本2。选择B后，`2+3=5` 改善A，`2+5=7` 首次到达Finish；再处理A，`5+1=6` 又改善Finish。最终父链是 `Finish ← A ← B ← Start`，反转后得到 `Start → B → A → Finish`，总成本6。


## 术语：方向、权重、成本与已处理

加权边常带方向：`A→B` 有价格不代表 `B→A` 也存在或价格相同。无向加权边通常在邻接表中写成两个方向。路径是边序列，路径成本是各边权之和；“最短”只是传统名称，优化量也可以是时间或费用。

“已处理”不是“已经看见”。节点可能多次进入成本表或最小堆，但处理完成后节点不再重复选择。扫描版显式维护集合；懒删除最小堆版允许旧条目留在堆中，弹出时若条目成本大于最新成本就跳过。

## 钢琴交换示例

原章的“Trading for a piano”把物品当节点，把完成一次交换还需补的钱当边权。Rama手中有一本书，可以补5美元换唱片，或0美元换海报；唱片可通向贝斯和架子鼓，海报也有不同价格的同类交换，最后由乐器换到钢琴。


钢琴交换示例说明，贪心选择的是“从起点累计成本最低的未处理节点”，不是“当前边最便宜”。如果只选眼前最小边，可能进入后续代价很高的分支；成本表始终比较完整前缀路径。

## 负权边

负权可以表示返利、汇率收益或能量回收，但它会破坏Dijkstra证明所需的单调性。负权边会破坏已处理节点最优性：一个当前看来更远的节点，可能通过负边回到已处理节点并给出更低成本。

<NegativeEdgeDiagram />

图中Start直达A成本2、到B成本5，B再以-10到A。Dijkstra先处理A并把2当成最终值；之后处理B才发现到A的候选成本是-5。这个反例没有环，更没有负权环，所以“只有负权环才有问题”是错误判断。Dijkstra不能处理负权边。

可处理负权边：它反复对全部边松弛，若不存在可达负权环，可得到有限最短距离；额外一轮仍能更新则说明存在可达负权环。若负权环位于通往目标的可达区域，沿环反复行走会让成本无限下降，此时没有有限最短路径。


## 实现：散列表记录图、成本和父节点

原书用散列表记录图、成本和父节点。下面先建立与原章一致的Start、A、B、Finish网络：

```python
graph = {
    "start": {"a": 6, "b": 2},
    "a": {"finish": 1},
    "b": {"a": 3, "finish": 5},
    "finish": {},
}

infinity = float("inf")
costs = {"a": 6, "b": 2, "finish": infinity}
parents = {"a": "start", "b": "start", "finish": None}
processed: set[str] = set()
```

扫描版每轮遍历成本表，选择成本最低的未处理节点。它直接对应原书四步，适合先验证状态变化：

```python
def find_lowest_cost_node(
    costs: dict[str, float], processed: set[str]
) -> str | None:
    best_node = None
    best_cost = float("inf")
    for node, cost in costs.items():
        if node not in processed and cost < best_cost:
            best_node = node
            best_cost = cost
    return best_node

node = find_lowest_cost_node(costs, processed)
while node is not None:
    cost = costs[node]
    for neighbor, weight in graph[node].items():
        candidate = cost + weight
        if candidate < costs[neighbor]:
            costs[neighbor] = candidate
            parents[neighbor] = node
    processed.add(node)
    node = find_lowest_cost_node(costs, processed)

assert costs["finish"] == 6
assert parents == {"a": "b", "b": "start", "finish": "a"}
```

若有 `V` 个节点和 `E` 条边，朴素扫描找最低成本共花 `O(V²)`，遍历邻边共花 `O(E)`，总计 `O(V²+E)`。对于稠密图，这个版本简单且可能足够；对于稀疏大图，优先队列可加速最低成本节点选择。

## 优先队列与路径恢复

通常由二叉堆实现。Python的 `heapq` 没有直接的decrease-key，常用做法是每次改善都压入新条目，弹出旧成本时跳过：

```python
from heapq import heappop, heappush

def dijkstra(
    graph: dict[str, dict[str, float]], start: str
) -> tuple[dict[str, float], dict[str, str | None]]:
    distances = {node: float("inf") for node in graph}
    parents: dict[str, str | None] = {node: None for node in graph}
    distances[start] = 0
    heap: list[tuple[float, str]] = [(0, start)]

    while heap:
        current_cost, node = heappop(heap)
        if current_cost != distances[node]:
            continue
        for neighbor, weight in graph[node].items():
            if weight < 0:
                raise ValueError("Dijkstra requires non-negative weights")
            candidate = current_cost + weight
            if candidate < distances[neighbor]:
                distances[neighbor] = candidate
                parents[neighbor] = node
                heappush(heap, (candidate, neighbor))
    return distances, parents

def restore_path(
    parents: dict[str, str | None], start: str, target: str
) -> list[str]:
    path: list[str] = []
    node: str | None = target
    while node is not None:
        path.append(node)
        if node == start:
            return list(reversed(path))
        node = parents[node]
    return []

distances, parent_table = dijkstra(graph, "start")
assert distances["finish"] == 6
assert restore_path(parent_table, "start", "finish") == [
    "start", "b", "a", "finish"
]
```


邻接表加二叉堆的常见复杂度是 `O((V+E) log V)`，连通图中常简写为 `O(E log V)`；空间是 `O(V+E)`，懒删除时堆里可能暂存多个同节点条目。若只关心一个目标，可在目标以最新最小成本弹出时结束，而不是在它第一次入堆时结束。


## 为什么非负权时选择安全

设Dijkstra将要处理的节点为 `u`，它在所有未处理节点中暂定成本最小。假设还存在一条更短路径到 `u`。沿该路径从起点前进，取第一个未处理节点 `x`，它的前驱 `y` 已处理，因此处理 `y` 时已经松弛了边 `y→x`。

由于后续边权都非负，到 `x` 的路径前缀成本不会大于整条假设路径成本；于是 `d[x]` 应小于 `d[u]`，与“`u` 是最低成本未处理节点”矛盾。因此选中时 `d[u]` 已是最短距离。负权边会让“路径继续延伸时成本不会下降”失效，这正是前述反例能推翻A的原因。

## 原章概念回查

加权图的边带有成本，Dijkstra寻找非负权图最短路径。节点成本是从起点到该节点的当前最小已知代价，父节点表用于恢复路径。

算法选择成本最低的未处理节点，检查该节点所有邻居；松弛操作比较新路径与旧成本，更新邻居成本和父节点，处理完成后节点不再重复选择。

钢琴交换示例把交换成本建成边权。负权边会破坏已处理节点最优性，Dijkstra不能处理负权边，Bellman-Ford可处理负权边。

实现中用散列表记录图、成本和父节点；在更大的稀疏图中，优先队列可加速最低成本节点选择。

## 本章回顾

1. BFS找最少边数，Dijkstra找非负权图的最低权重和。
2. 成本表保存当前最小已知代价，父节点表保存对应路径。
3. 每轮选择成本最低的未处理节点。
4. 松弛比较 `d[u]+w(u,v)` 与 `d[v]`。
5. 成本改善时必须同步更新父节点。
6. 非负权保证节点被处理时距离已经最终确定。
7. 钢琴交换的最低成本链是书、唱片、架子鼓、钢琴，共35美元。
8. 一条负权边就足以让Dijkstra失败，不需要负权环。
9. Bellman-Ford可处理负权边并检测可达负权环。
10. 扫描版直观但需 `O(V²+E)` 时间。
11. 邻接表加二叉堆通常需 `O((V+E) log V)` 时间。
12. 目标第一次入队不代表完成，只有以最新最低成本弹出时才能提前结束。
