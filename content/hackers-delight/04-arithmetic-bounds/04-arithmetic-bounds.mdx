## 从“结果在范围内”和“计算过程没越界”开始

先预测：若$x$属于closed interval $[-8,23]$，表达式`x - (-8)`应落在0到31之间。把这个difference解释为unsigned distance后，低于负8的值会在modulo word中变成large distance，高于23的值也超过span，于是一次unsigned comparison可同时拒绝两侧。

但这条技巧只回答single value membership。若已知$x$和$y$各自在某个interval内，要推导$x+y$、$x-y$或$x\mathbin{\&}y$的range，还必须分别处理monotonicity、overflow、fixed-width wraparound和变量correlation。Chapter 4 Arithmetic Bounds的核心不是“猜一个大概范围”，而是给每个bound标注soundness与tightness。

<Term def="包含lower和upper endpoints的整数集合，写作从lower到upper的闭区间。">闭区间</Term>用$[a,b]$表示。Sound bound要求所有possible outputs都在其中；tight interval hull还要求lower与upper分别是可达到的minimum和maximum。一个bound可以sound却很宽，也可以看似tight却漏掉真实value。

## 4.1 Checking bounds of integers

### Two comparisons and one translated distance

Direct membership predicate是

$$
a\le x
\quad\land\quad
x\le b,
\qquad a\le b.
$$

<HD4MembershipLab />

<Term def="把x与lower bound的modulo差解释为nonnegative distance，再与interval span做一次unsigned comparison。">无符号距离检查</Term>把interval平移到从zero开始：

$$
\operatorname{inRange}(x;a,b)
\iff
\operatorname{unsigned}(x-a)
\le
\operatorname{unsigned}(b-a).
$$

<HD4UnsignedDistanceLab />

关键不是source里少写一个operator，而是subtraction必须在unsigned word algebra中形成。若先做signed `x - a`，extreme inputs可能在cast之前已经signed overflow。C reference应先转换operands，再做modulo subtraction：

```c
#include <stdbool.h>
#include <stdint.h>

static bool in_closed_i32(int32_t x, int32_t low, int32_t high) {
    if (low > high) return false;
    uint32_t distance = (uint32_t)x - (uint32_t)low;
    uint32_t span = (uint32_t)high - (uint32_t)low;
    return distance <= span;
}
```

这个form适用于一个ordinary nonwrapping signed interval。若domain本身是cyclic sequence number，可能有意让interval穿过maximum到zero，此时membership是两个ranges的union，不能沿用ordinary low不大于high的contract。

### Point, half-open, and shifted checks

Bounds checking必须先确定endpoint convention。Closed $[a,b]$包含$b$；half-open $[a,b)$不包含$b$，适合array index，因为valid index condition是$0\le i\lt n$。对zero-based upper-only check，cast-to-unsigned idiom可把negative index变成large value，再与length比较。

Pointer bounds还涉及object provenance、one-past pointer与element size，不应只把addresses转为integers比较。Integer predicate是numeric evidence，不自动满足language object model。

## 4.2 Propagating bounds through adds and subtracts

### Monotonic endpoints over mathematical integers

<Term def="从operand ranges推导expression所有possible results所在range的过程。">界传播</Term>（propagating bounds through adds and subtracts）在independent intervals

$$
x\in[a,b],
\qquad
y\in[c,d]
$$

且使用mathematical integer semantics时，addition对两个operands都monotone increasing：

$$
x+y\in[a+c,\ b+d].
$$

<HD4AddIntervalLab />

Lower endpoint由$a+c$达到，upper endpoint由$b+d$达到，所以这是tight interval hull。Subtraction对left operand increasing、对right operand decreasing：

$$
x-y\in[a-d,\ b-c].
$$

<HD4SubtractIntervalLab />

Unary negation会reverse order：若$x\in[a,b]$，则$-x\in[-b,-a]$，但minimum signed value可能不可negate。Multiplication还需根据operand signs检查四个endpoint products；若只乘known constant，negative constant会交换lower与upper roles。

### Compute the bounds in a wider or checked domain

即使source operands都fit，endpoint expression也可能不fit。若用同样窄的signed type先算$b+d$，bound calculation itself可能undefined，无法再据此证明program安全。可靠实现使用wider integer、checked arithmetic或explicit precondition。

```c
typedef struct {
    int32_t low;
    int32_t high;
} i32_interval;

static bool add_interval_i32(i32_interval x, i32_interval y,
                             i32_interval *out) {
    int64_t low = (int64_t)x.low + (int64_t)y.low;
    int64_t high = (int64_t)x.high + (int64_t)y.high;
    if (low < INT32_MIN || high > INT32_MAX) return false;
    out->low = (int32_t)low;
    out->high = (int32_t)high;
    return true;
}
```

若failure policy是saturate，output interval可clamp到type range；若policy是trap或reject，则status必须沿call chain传播。把overflow silently当作wraparound会改变抽象domain。

### Wraparound is often a split set

在8-bit unsigned arithmetic中，$[240,250]+[10,20]$的mathematical hull为$[250,270]$。Stored results modulo 256为

$$
[250,255]\cup[0,14],
$$

不是一个ordinary unsigned interval。

<Term def="fixed-width modulo operation后跨越maximum与zero、通常需表示为两个ordinary intervals之并的result set。">回绕集合</Term>若强制用single hull，只能扩成$[0,255]$才sound，precision几乎全部丢失。

<HD4WraparoundBoundsLab />

系统可以选择四种representation：reject可能overflow的operation；在wider mathematical domain继续；用split intervals；或采用native cyclic interval abstraction。哪种都比让ordinary interval悄悄跨zero更明确。

### Correlation changes the attainable set

Endpoint formulas假设$x$与$y$可独立取range内任意组合。若两个symbols相关，independent interval arithmetic会过宽。最简单例子是$x-x$：把两次appearance当独立variables得到$[a-b,b-a]$，但同一个$x$相减exactly zero。

<Term def="同一变量多次出现或变量之间存在约束，而普通interval arithmetic把它们错误视为独立选择的问题。">依赖问题</Term>（dependency problem）不影响soundness，却会降低precision并触发false alarms。

<HD4DependencyLab />

解决方式包括代数化简、affine forms、symbolic constraints或relational domains。Bit trick proof中最实用的第一步仍是先化简identity，再传播剩余independent inputs。

## 4.3 Propagating bounds through logical operations

### Numeric order does not make AND, OR, XOR monotone

对fixed-width unsigned single values，总有$x\mathbin{\&}y\le x$、$x\le x\mathbin{|}y$。但当$x$从某个integer增加到更大integer时，binary carry会同时清零lower bits，所以bitwise result不必随numeric operand单调变化。

<HD4LogicalIntervalLab />

因此把logical operation只代入四组endpoint并取minimum/maximum并不可靠。Counterexamples在4-bit domain就出现：

- AND：$x\in[0,1]$、$y\in[0,2]$，四个endpoint pairs结果全为zero，但interior pair $1\mathbin{\&}1=1$。
- OR：$x,y\in[0,2]$，endpoint-only maximum为2，但interior pair $1\mathbin{|}2=3$。
- XOR：同一ranges中，$1\mathbin{\oplus}2=3$也超过endpoint-only maximum。

<HD4EndpointTrapLab />

<Term def="某logical expression在给定operand intervals上可达到的真实minimum与maximum。">逻辑极值</Term>必须通过bit structure求解，而非ordinary calculus monotonicity。

### Sound coarse bounds

在需要cheap proof而非maximum precision时，可先使用universal inequalities。对nonnegative unsigned operands：

$$
0\le x\mathbin{\&}y\le\min(x,y),
$$

且由$x\mathbin{|}y=x+y-(x\mathbin{\&}y)$与$x\mathbin{\oplus}y\le x\mathbin{|}y$可得

$$
0\le x\mathbin{\oplus}y
\le
x\mathbin{|}y
\le
\min(2^w-1,\ x+y).
$$

于是只知$x\le b$、$y\le d$时，AND upper bound可取$\min(b,d)$，OR/XOR upper bound可取$\min(2^w-1,b+d)$。这些bounds sound，却常不tight。

<HD4CoarseLogicalBoundsLab />

NOT在fixed width下反而有exact interval transform。令word mask $M=2^w-1$，则$\operatorname{NOT}x=M-x$严格order reversing：

$$
x\in[a,b]
\Longrightarrow
\operatorname{NOT}x\in[M-b,\ M-a].
$$

<HD4ComplementBoundsLab />

### Exact logical bounds by prefix search

<Term def="在某个significant bit可能从0变1的boundary处分割interval，使每个subrange共享更稳定的high-bit prefix。">前缀分裂</Term>是exact algorithms的核心。Integer interval跨越$2^k$ boundary时，bit $k$及lower suffix发生carry transition；把range在该boundary切开后，可以在fixed prefix下判断某output bit能否取0或1。

<HD4PrefixSplitLab />

求minimum时从most significant output bit向下，优先尝试0，并检查是否仍存在compatible operand prefixes；求maximum则优先尝试1。每一步同时收紧$x$与$y$的feasible subranges。AND、OR、XOR的区别只在当前bit允许的input pairs不同：

- AND output 1只允许input pair 11。
- OR output 0只允许input pair 00。
- XOR output 1允许01或10。

这可以写成branch-and-bound，也可使用书中针对各operation化简的word algorithms。Reference oracle应先保证正确，再比较optimized implementation。

```text
EXACT-LOGICAL-BOUND(a, b, c, d, operation, direction, width)
1  states = {(range x=[a,b], range y=[c,d], output prefix empty)}
2  for bit from width-1 down to 0
3      try desired output bit first: 0 for minimum, 1 for maximum
4      split each operand range at this bit's power-of-two boundaries
5      keep only prefix pairs whose input bits can produce the candidate bit
6      if no state survives, choose the other output bit
7  return the reachable output prefix
```

For small widths，exhaustive enumeration gives a complete oracle：

```c
static void exact_xor_bounds_u8(uint8_t a, uint8_t b,
                                uint8_t c, uint8_t d,
                                uint8_t *minimum, uint8_t *maximum) {
    uint8_t lo = UINT8_MAX;
    uint8_t hi = 0;
    for (unsigned x = a; x <= b; ++x) {
        for (unsigned y = c; y <= d; ++y) {
            uint8_t z = (uint8_t)(x ^ y);
            if (z < lo) lo = z;
            if (z > hi) hi = z;
            if (y == d) break;
        }
        if (x == b) break;
    }
    *minimum = lo;
    *maximum = hi;
}
```

Loop breaks avoid unsigned endpoint increment wrapping and running forever。对8-bit全部intervals仍很多，测试可枚举selected intervals或更小word widths，再用random 32-bit cases补充。Oracle用于验证optimized bound，不应用自己的同一推导重写一遍。

<Callout type="trap" title="单调算术的四端点法也适用于bitwise operations">
Binary increment会清lower bits，AND、OR、XOR对numeric order并不monotone，真实extremum可在interior。修法是使用sound coarse inequalities，或按high-bit prefixes做exact feasibility search。
</Callout>

<Callout type="trap" title="区间端点能表示就说明端点运算也安全">
两个representable endpoints相加、相减或negate仍可能超出type。修法是在wider或checked domain计算bounds，再决定reject、saturate、split还是采用cyclic representation。
</Callout>

## 小结

Chapter 4 Arithmetic Bounds从checking bounds of integers开始：ordinary closed interval可平移成unsigned distance与span的一次比较，但subtraction必须在unsigned algebra中完成。

Propagating bounds through adds and subtracts依赖monotonicity。Independent mathematical intervals的sum hull为$[a+c,b+d]$，difference hull为$[a-d,b-c]$；fixed-width overflow可能把结果变成split wraparound set，变量correlation则使independent hull过宽。

Propagating bounds through logical operations不能只求四个endpoint pairs。AND、OR、XOR对numeric order不monotone，exact extrema需要按significant-bit boundaries分裂并做prefix feasibility；如果precision要求较低，可使用明确标注为coarse的universal inequalities。每个bound都应携带domain、overflow、correlation与validation evidence。

<Exercises>

**问题 1**：为什么unsigned-distance membership要先cast operands再subtraction，而不是先算signed x减low再cast？

<Answer>
Extreme signed values之间的difference可能超出signed range，先做signed subtraction会在cast前产生undefined behavior。分别转为same-width unsigned后相减按modulo定义，below-low values形成large distance，再与span统一比较。
</Answer>

**问题 2**：若x属于负3到5、y属于4到11，independent mathematical sum和difference的tight hull分别是什么？

<Answer>
Sum lower为负3加4等于1，upper为5加11等于16，所以是1到16。Difference lower用最小x减最大y得到负14，upper用最大x减最小y得到1，所以是负14到1。
</Answer>

**问题 3**：为什么8-bit ranges 240到250与10到20的modulo sum不能精确写成一个ordinary unsigned interval？

<Answer>
Mathematical results 250到270在modulo 256后分成250到255与0到14，中间15到249不可达到。一个ordinary low-to-high interval无法跨maximum回到zero；要么用两个intervals，要么采用cyclic representation。
</Answer>

**问题 4**：给出endpoint-only方法漏掉OR maximum的最小示例之一，并说明修法。

<Answer>
x与y都属于0到2时，四个endpoint pairs只看到0 OR 0、0 OR 2、2 OR 0、2 OR 2，maximum为2；interior pair 1 OR 2等于3。修法是small-width exhaustive oracle或按highest changing bit分裂ranges做exact prefix search。
</Answer>

</Exercises>
