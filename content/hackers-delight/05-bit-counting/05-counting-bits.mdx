## 从“计数”与“定位”其实是同一件事开始

先预测：8-bit pattern `00101100`有3个1-bits、2个leading zeros、2个trailing zeros，parity为odd。Counting Bits看似包含四个不同functions，但它们共享两种结构：reduction把许多bits压成一个small integer，selection先定位某个distinguished 1-bit再把position编码成integer。

令word $x$的bits为$x_{w-1}\ldots x_0$。（population count）定义

$$
\operatorname{pop}(x)
=
\sum_{i=0}^{w-1}x_i.
$$

与则返回positions。Zero没有highest或rightmost one，所以CLZ和CTZ必须另外规定结果。

## 5.1 Counting 1-bits

### Direct scan and clear-the-rightmost-one

最直接算法逐bit累加`x & 1`再logical shift，执行$w$轮，成本与data无关。


利用Chapter 2的identity，$x\mathbin{\&}(x-1)$每次恰好clear一个rightmost 1。因此循环次数正好等于population count：

```c
#include <stdint.h>

static unsigned popcount_sparse_u32(uint32_t x) {
    unsigned count = 0;
    while (x != 0u) {
        x &= x - 1u;
        ++count;
    }
    return count;
}
```


Invariant是每轮开始时，`count + pop(x)`等于original population。Loop结束时$x=0$，于是count就是answer。Sparse data时iterations很少；dense all-ones word则执行$w$轮，还形成serial dependency chain。


### Lookup by chunks

把word拆为bytes，可预计算256-entry table，再对每个byte lookup并相加。4-bit table更小但lookups更多；16-bit table有65536 entries，可能增加cache pressure。


Lookup correctness来自additivity：disjoint bit fields的population counts可相加。Performance则依赖table residency、loads、extract instructions与memory subsystem，不能只数source operations。

### SWAR: a reduction tree inside a word

（SWAR）先在每2-bit lane内计数，再合并为4-bit、8-bit、16-bit partial sums。Masks阻止相邻lanes互相污染。


32-bit经典结构为：

```c
static unsigned popcount_swar_u32(uint32_t x) {
    x = x - ((x >> 1) & UINT32_C(0x55555555));
    x = (x & UINT32_C(0x33333333))
      + ((x >> 2) & UINT32_C(0x33333333));
    x = (x + (x >> 4)) & UINT32_C(0x0F0F0F0F);
    x = x + (x >> 8);
    x = x + (x >> 16);
    return x & 0x3Fu;
}
```

第一行不只是“magic constant”：每个2-bit lane用original two-bit value减去其high bit，结果正好是该lane的one count。后续每次把相邻partial sums相加。Final mask保留足以表示0到32的6 bits。

Width改变时，masks、stage count与final result width都要改。对于standard widths，优先使用standard library或compiler intrinsic，让target选择POPCNT、vector instruction或fallback；手写SWAR主要作为portable reference或受控平台实现。

## 5.2 Parity

（parity）满足

$$
\operatorname{parity}(x)
=
\operatorname{pop}(x)\bmod2
=
x_0\oplus x_1\oplus\cdots\oplus x_{w-1}.
$$


因为XOR associative且相同bit成对抵消，可把word halves不断fold：

$$
x\gets x\oplus(x\mathbin{\mathrm{shr}}w/2),
\quad
x\gets x\oplus(x\mathbin{\mathrm{shr}}w/4),
\quad\ldots
$$

最终low bit就是all input bits XOR。


```c
static unsigned parity_u32(uint32_t x) {
    x ^= x >> 16;
    x ^= x >> 8;
    x ^= x >> 4;
    x ^= x >> 2;
    x ^= x >> 1;
    return x & 1u;
}
```

Parity能检测odd number of bit flips，却不能检测所有even-number errors，也不能指出error position。Chapter 15会把它扩展到Hamming-style parity checks；这里的任务只是高效reduction。

若已有population-count primitive，`popcount(x) & 1`通常表达最清楚；若target有direct parity flag或instruction，compiler可能自行利用。Source-level XOR count不是最终performance evidence。

## 5.3 Counting leading zeros

### Highest one, bit length, and logarithm

对nonzero unsigned $x$，

$$
\left\lfloor\log_2x\right\rfloor
=
w-1-\operatorname{clz}(x),
\qquad
\operatorname{bitLength}(x)
=
w-\operatorname{clz}(x).
$$


CLZ同时服务normalization、integer logarithm、priority encoding、floating-point construction与next-power calculation。对$x=0$，bit length常定义为0，因此令$\operatorname{clz}(0)=w$很方便；但某些hardware primitives对zero保留undefined或special result，wrapper必须统一。

### Linear scan versus binary group search

Linear reference从most significant mask开始，遇到first one即停止。Binary search先测试upper half是否为zero，再选择half，随后测试quarter、eighth，经过$\log_2w$个group decisions定位。


```c
static unsigned clz_reference_u32(uint32_t x) {
    if (x == 0u) return 32u;
    unsigned count = 0;
    uint32_t bit = UINT32_C(0x80000000);
    while ((x & bit) == 0u) {
        ++count;
        bit >>= 1;
    }
    return count;
}

static unsigned ctz_reference_u32(uint32_t x) {
    if (x == 0u) return 32u;
    unsigned count = 0;
    while ((x & 1u) == 0u) {
        ++count;
        x >>= 1;
    }
    return count;
}
```

Reference loops容易审计，optimized binary-search/lookup/intrinsic versions应与它在all small-width patterns和selected 32-bit boundaries上比较。Signed negative input必须先转换到declared unsigned pattern，否则arithmetic shift与sign extension会改变meaning。

## 5.4 Counting trailing zeros

### Isolate the lowbit

对nonzero $x$，lowbit identity

$$
x\mathbin{\&}(-x)
=
2^{\operatorname{ctz}(x)}
$$

把position问题变成one-hot integer logarithm。


再减一会得到恰好$\operatorname{ctz}(x)$个low ones：

$$
\operatorname{ctz}(x)
=
\operatorname{pop}((x\mathbin{\&}(-x))-1),
\qquad x\ne0.
$$


这条identity可复用popcount primitive，却不是说它一定比direct CTZ instruction便宜。它的重要性是proof composition：isolate one-hot、convert exponent to low-ones count、reduce。

### De Bruijn indexing

可把32个possible one-hot positions映射到5-bit table index。对isolated lowbit乘一个chosen 32-bit constant，取product high 5 bits，再lookup original position。


Correctness依赖三个width-specific objects共同匹配：multiplication modulo $2^{32}$、constant与32-entry table。把constant复制到64-bit code，或让language用unbounded multiplication，都可能破坏mapping。Zero也不在one-hot domain，必须先guard。

### Zero policy is part of the API

不能由caller猜测。Returning $w$常使bit length与range loops方便；precondition nonzero可匹配某些intrinsics；optional/status则最明确。


跨target wrapper至少测试zero、one、highest bit、all ones和每个one-hot position。若underlying primitive在zero undefined，wrapper必须在调用之前branch，不能先调用再覆盖result。

## 小结

Chapter 5 Counting Bits把counting 1-bits视为reduction。Direct scan按width工作，clear-rightmost-one按population工作，lookup按chunks工作，SWAR在word内构造固定reduction tree；target primitive通常是production首选。

Parity是population modulo two，可用XOR folding计算。Counting leading zeros定位highest one，并给出floor logarithm和bit length；counting trailing zeros通过$x\mathbin{\&}(-x)$隔离rightmost one，再用log、popcount mask或De Bruijn lookup编码position。

所有算法都必须固定unsigned width，尤其要明确CLZ/CTZ的zero behavior。正确的交付顺序是identity、reference、boundary oracle、target mapping，而不是从magic constant直接跳到performance claim。
