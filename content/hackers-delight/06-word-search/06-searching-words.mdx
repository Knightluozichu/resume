## 从“一次检查四个bytes”开始

先预测：32-bit word的四个bytes若分别减一，会让原本为zero的byte从`00`回绕为`FF`，从而产生high bit；但普通word subtraction的borrow可以跨byte传播，所以“high bit出现”首先是一个existence syndrome，不必天然等于每个lane的exact predicate。

Searching Words把一个register视为多个并行lanes或一条bit string。前者用repeated byte constants寻找zero；后者用shift、AND、complement与Chapter 5的CTZ/popcount寻找runs。两类技巧都要求先固定<Term def="一个machine word中被视为独立8-bit element的字段，可用repeated constants并行测试。">字节通道</Term>、search order和word-edge behavior。

## 6.1 Find first zero-byte

### Lane-wise high-bit syndrome

对32-bit word $x$，令

$$
L=\mathtt{0x01010101},
\qquad
H=\mathtt{0x80808080}.
$$

若某byte为zero，减$L$后对应lane在borrow作用下变成all ones；original byte的complement也有high bit。于是

$$
z=(x-L)\mathbin{\&}(\operatorname{NOT}x)\mathbin{\&}H
$$

nonzero当且仅当至少存在一个zero byte。

<HD6ByteLaneLab />

<Term def="由lane-wise subtract、original complement和lane high-bit mask形成，用于判断是否存在零byte的word。">零字节症状</Term>可在一个expression中筛掉大多数nonzero lanes。

<HD6HasZeroByteLab />

```c
#include <stdbool.h>
#include <stdint.h>

static bool has_zero_byte_u32(uint32_t x) {
    const uint32_t low_bits = UINT32_C(0x01010101);
    const uint32_t high_bits = UINT32_C(0x80808080);
    return ((x - low_bits) & ~x & high_bits) != 0u;
}
```

Unsigned subtraction按modulo定义。这个predicate检测“至少一个”，不要求每个set high bit都对应original zero lane。若low-order zero引发borrow，紧随其后的value-one byte也可能成为candidate；但在low-byte-first顺序中，false candidate位于真实zero之后，所以least candidate仍能定位真实first zero。

### Exact per-byte zero mask

若要枚举所有zero bytes、从high side找first，或不想依赖borrow ordering，需要<Term def="每个original zero byte只在该lane high position置1、其他lanes为0的word mask。">精确零字节掩码</Term>。一种construction先屏蔽每个byte high bit，向low seven bits加`0x7F`，再OR original和low-bit mask；只有original zero lane的high bit最终保持clear，complement后被选中。

<HD6ExactZeroMaskLab />

```c
static uint32_t exact_zero_byte_mask_u32(uint32_t x) {
    const uint32_t low_sevens = UINT32_C(0x7F7F7F7F);
    const uint32_t high_bits = UINT32_C(0x80808080);
    uint32_t low = x & low_sevens;
    uint32_t nonzero = (low + low_sevens) | x | low_sevens;
    return ~nonzero & high_bits;
}
```

每个low-seven lane最大为127，加127最大254，不会向next byte产生carry，因此lanes保持独立。Mask中每个1位都位于byte high position。

### Locate means choosing an order

若numeric low byte先搜索，`ctz(mask) / 8`给first lane index；若numeric high byte先搜索，则用CLZ后换算。Memory中first byte由endianness和load arrangement决定，不一定等于numeric low-order lane。

<HD6FirstZeroByteLab />

<Term def="明确word lanes按numeric low-to-high、high-to-low或increasing-memory-address被检查的约定。">搜索顺序</Term>必须进入API contract。

<HD6SearchOrderLab />

Word-at-a-time string scanning还必须保证load合法。即使最终mask忽略object末尾之外的bytes，越界load本身仍可能违反language rules、跨unmapped page或触发sanitizer。Production implementation需使用safe unaligned load primitive、bounded tail copy或scalar tail。

## 6.2 Find first string of 1-bits of a given length

### Define maximal runs and edge sentinels

<Term def="由相邻1-bits组成、且在word内不能再向任一方向扩展的maximal contiguous segment。">一位串</Term>（1-bit run）由start position与length描述。Bit 0以下和bit $w-1$以上视为virtual zeros，才能统一识别touching edges的runs。

<HD6RunInventoryLab />

<HD6RunBoundaryLab />

Run starts是当前bit为1、lower neighbor为0的位置：

$$
\operatorname{starts}(x)
=
x\mathbin{\&}\operatorname{NOT}(x\mathbin{\mathrm{shl}}1).
$$

Run ends类似使用logical right shift：

$$
\operatorname{ends}(x)
=
x\mathbin{\&}\operatorname{NOT}(x\mathbin{\mathrm{shr}}1).
$$

<Term def="一位串中最低位置的1-bit，由当前bit为1且lower neighbor为0定义。">串起点</Term>与ends数量相同，可按position配对恢复每个maximal run。

<HD6RunPredicateLab />

### Shifted AND as a fixed-length predicate

要找至少$n$个consecutive ones，构造

$$
M_n
=
x
\mathbin{\&}(x\mathbin{\mathrm{shr}}1)
\mathbin{\&}\cdots\mathbin{\&}
(x\mathbin{\mathrm{shr}}(n-1)).
$$

$M_n$的bit $i$为1，当且仅当original positions $i$到$i+n-1$全为1。若$M_n$nonzero，CTZ给low-order first start。

<HD6FixedRunLab />

```c
static bool first_run_at_least_u32(uint32_t x, unsigned length,
                                   unsigned *start) {
    if (length == 0u || length > 32u) return false;
    uint32_t candidates = x;
    for (unsigned offset = 1; offset < length; ++offset)
        candidates &= x >> offset;
    if (candidates == 0u) return false;
    *start = ctz_reference_u32(candidates);
    return true;
}
```

这里search的是“至少length”，不是exactly length。若要exact maximal length，还需检查candidate两侧为zero。Length zero通常作为invalid request，而不是让empty string在每个position都match。

Large $n$可用doubling构造减少shifts：先算length 2、4、8的all-one blocks，再按$n$的binary decomposition组合。但复杂实现必须与linear shifted-AND oracle逐pattern比较。

## 6.3 Find longest string of 1-bits

### Erode every run in parallel

令

$$
y_{t+1}
=
y_t\mathbin{\&}(y_t\mathbin{\mathrm{shl}}1),
\qquad
y_0=x.
$$

每次iteration从每个run的low end移除一个bit，length $L$的run经过$L-1$次后剩一bit，第$L$次后消失。

<Term def="用word与其one-bit shifted copy做AND，使每个1-run每轮缩短一位的parallel transform。">串侵蚀</Term>（run erosion）把所有runs同时缩短。

<HD6RunErosionLab />

因此直到word为zero的iteration count正好等于longest run length：

```c
static unsigned longest_run_ones_u32(uint32_t x) {
    unsigned length = 0;
    while (x != 0u) {
        x &= x << 1;
        ++length;
    }
    return length;
}
```

<HD6LongestRunLab />

Invariant可表述为：iteration $t$之后，每个original run保留$\max(L-t,0)$ bits。Nonzero iff至少一个original length大于$t$。Worst case all ones执行$w$轮；也可对predicate“是否存在length $n$ run”做binary search，在$\log w$次queries内得到longest，但每次query自身有cost。

## 6.4 Find shortest string of 1-bits

Shortest必须限定为shortest maximal run；否则任何nonzero word都含length-one substring，问题失去意义。

一种reference先计算starts与ends，按low-to-high顺序配对，取最小`end - start + 1`。另一种观察erosion：当run count第一次下降时，刚消失的run具有minimum original length。

<HD6ShortestRunLab />

```text
SHORTEST-MAXIMAL-RUN(x, width)
1  if x is zero, return no-run
2  starts = positions where bit is 1 and lower neighbor is 0
3  ends   = positions where bit is 1 and higher neighbor is 0
4  pair starts and ends in increasing position order
5  return minimum(end - start + 1)
```

Zero input返回no-run而不是zero-length run；all-ones input只有一个length-$w$ run；edge runs依赖virtual zeros。若word表示cyclic ring而非linear string，bit $w-1$和bit 0可能相邻，此时edge runs要merge，算法与ordinary machine word不同。

<Callout type="trap" title="零字节subtract mask精确标出每个zero lane">
它可靠回答existence，也可在low-lane-first时定位least true zero；borrow可能让后续value-one lane成为candidate。修法是需要all-lane exactness或reverse search时使用exact zero-byte mask。
</Callout>

<Callout type="trap" title="只要mask掉多余bytes就可以越界读一个word">
Bit result正确不代表load合法；越界read可能跨object、page或触发undefined behavior。修法是bounded word loads加scalar/copy tail，并用sanitizer和page-boundary tests验证。
</Callout>

## 小结

Chapter 6 Searching Words首先用repeated constants在byte lanes中find first zero-byte。Subtract/complement/high-bit expression可靠检测存在性；精确枚举或reverse search要使用不跨lane carry的exact mask。定位还需指定numeric或memory order，并保证word load合法。

Find first string of 1-bits of a given length用shifted copies的AND生成candidate starts。Find longest string of 1-bits通过parallel run erosion计数直到zero。Find shortest string of 1-bits必须针对maximal runs，配对run starts/ends或观察first disappearance。

这些技巧的共同contract是geometry：lane width、search order、edge sentinels、linear/cyclic topology与safe memory range。Expression只在这些条件固定后才有确定meaning。

<Exercises>

**问题 1**：为什么zero-byte subtract expression能可靠判断existence，却不保证每个candidate high bit都是zero lane？

<Answer>
Original zero lane减一必产生all ones且通过NOT-x与high mask，所以没有false negative。Word subtraction的borrow可进入更高lane，使紧随zero的value-one lane也出现candidate high bit，因此all-lane mask可能有false positives。
</Answer>

**问题 2**：对bit string 0011100110111000，要求length 3时，shifted-AND mask中的set bits表示什么？

<Answer>
每个set bit i表示original positions i、i加1、i加2全为one，也就是一个at-least-three run的possible low start。Longer run会贡献多个overlapping candidates；CTZ取numeric low-order first。
</Answer>

**问题 3**：为什么repeated x AND x-left-shift-one的iteration count等于longest run length？

<Answer>
每轮把每个run缩短一位，length L的run在前L减1轮仍nonzero，第L轮消失。Whole word只有在所有runs都消失时为zero，因此最后消失的run就是longest，iteration count等于其length。
</Answer>

**问题 4**：Zero、all ones和cyclic word分别如何改变shortest maximal-run contract？

<Answer>
Zero没有one-run，应返回no-run；all ones在线性word中有一个length-w run；cyclic topology把high-edge与low-edge runs视为相邻，需要先merge，不能使用virtual-zero edge assumption。
</Answer>
