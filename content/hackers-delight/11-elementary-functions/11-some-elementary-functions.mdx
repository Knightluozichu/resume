## 从“整数函数必须返回哪个邻点”开始

先预测：对$n=35$求square root，整数程序应该返回5、6，还是报告没有exact result？这不是微小的implementation choice，而是API contract。Chapter 11讨论的some elementary functions都把continuous function投影回integer lattice；必须先固定domain、rounding与overflow，再谈bit tricks。

本章对nonnegative input采用floor convention。<Term def="对nonnegative n返回最大的integer r，使r的平方不超过n。">整数平方根</Term>返回$r=\lfloor\sqrt n\rfloor$，<Term def="用返回值与其相邻integer的幂界同时证明floor result正确的可检查条件。">相邻幂证书</Term>要求

$$
r^2\le n\lt(r+1)^2.
$$

整数立方根、整数对数也采用同一结构：找到monotone predicate最后为true的位置。结果不仅是一个number，还带着一个只需两次边界检查就能复核的certificate。

<HD11RoundingContractLab />

Signed input要另写policy。Square root通常拒绝negative values；cube root可扩展到negative values，但floor、toward-zero和odd symmetry给出的结果并不总相同。本章reference code先限定nonnegative domain，避免把signed rounding问题藏进optimization。

## 11.1 Integer square root

### Floor result与remainder

定义$r=\operatorname{isqrt}(n)$。除了相邻平方证书，还可返回remainder

$$
\rho=n-r^2,
\qquad
0\le\rho\lt2r+1.
$$

上界来自$(r+1)^2-r^2=2r+1$。Exact square恰好满足$\rho=0$；nonzero remainder告诉caller输入距离lower square有多远，但不应被误当作floating fractional part。

<HD11SqrtBoundsLab />

Production checker不能直接在原word width计算$r^2$。若multiplication wrap，过大的candidate可能伪装成很小的square。对positive $r$，安全lower-bound comparison可改写为

$$
r\le\left\lfloor\frac nr\right\rfloor.
$$

Upper bound同理比较$r+1$与$n/(r+1)$，或在wider type计算square。Zero需要单独处理，避免division by zero。

### Binary search as a monotone boundary problem

Predicate $P(x)$表示$x^2\le n$。在nonnegative integers上，$P$先true后false，因此integer square root就是last true。Binary search容易证明，运行时间为$O(\log n)$ candidate comparisons；若initial high由bit length给出，范围还能缩到root所需bits。

```c
static uint32_t isqrt_binary_u32(uint32_t n) {
    uint32_t low = 0;
    uint32_t high = UINT16_MAX + 1u; // exclusive
    while (low + 1u < high) {
        uint32_t mid = low + (high - low) / 2u;
        if (mid == 0u || mid <= n / mid) {
            low = mid;
        } else {
            high = mid;
        }
    }
    return low;
}
```

Loop invariant是low可行、high不可行且answer位于二者之间。对32-bit input，root至多65535，所以exclusive high 65536安全。Generic width实现应从numeric limits推导bound，不能硬搬这个constant。

<HD11MonotonePredicateLab />

### Integer Newton iteration

Real Newton method对$x^2-n=0$给出average of $x$ and $n/x$。Integer variant每步floor：

$$
x_{k+1}
=
\left\lfloor
\frac{x_k+\lfloor n/x_k\rfloor}{2}
\right\rfloor.
$$

若$x_0$在root上方，sequence快速下降。可用bit length $L=\lfloor\log_2n\rfloor+1$选择$x_0=2^{\lceil L/2\rceil}$。当next不再小于current时停止，current就是floor root；最后仍用相邻平方certificate验证。

<HD11SqrtNewtonLab />

<Term def="从root上方开始，反复把estimate与n除estimate的quotient取floor average，形成单调下降的integer Newton sequence。">牛顿下降</Term>的关键不是公式本身，而是initialization和stopping rule。Floor arithmetic在answer附近可能使next等于current，甚至从下方跳动；只测试“next恰好等于current”而不保留above-root invariant，证明并不完整。

```c
static uint32_t isqrt_newton_u32(uint32_t n) {
    if (n == 0u) return 0u;
    unsigned bits = 32u - stdc_leading_zeros(n);
    uint32_t x = UINT32_C(1) << ((bits + 1u) / 2u);

    for (;;) {
        uint32_t next = (x + n / x) / 2u;
        if (next >= x) return x;
        x = next;
    }
}
```

这里的addition在32-bit case安全，因为initial estimate和quotient都不超过65536附近；generic wider implementation仍需证明sum不会overflow，或改写为half sums。

### Digit-by-digit binary square root

Longhand square root每次消耗radix的two digits；binary version因此从most significant end按bit pairs处理。每轮把remainder左移two bits并引入next pair，再判断能否减去由partial root构造的trial divisor。它只用shift、subtract、compare，适合没有fast division的target，也自然产生fixed iteration count。

<HD11SqrtBitPairsLab />

这类算法的state invariant是：已消费prefix等于partial root的square加current remainder；remainder始终nonnegative且小于下一trial interval。相比Newton，digit-by-digit较慢但control structure稳定；相比generic binary search，它一次决定一个root bit。

## 11.2 Integer cube root

<Term def="对nonnegative n返回最大的integer r，使r的立方不超过n。">整数立方根</Term>定义

$$
r=\lfloor\sqrt[3]{n}\rfloor,
\qquad
r^3\le n\lt(r+1)^3.
$$

Adjacent gap为

$$
(r+1)^3-r^3=3r^2+3r+1,
$$

所以remainder $\rho=n-r^3$应小于该gap。与square root一样，certificate要用wider arithmetic或division-based guarded comparison，不能让$r^3$在原width wrap。

<HD11CubeBoundsLab />

Binary search可直接复用last-true framework，把predicate改为$x^3\le n$。Safe comparison可以逐级guard：先确认$x$不大于$n/x$，再检查$x$不大于$(n/x)/x$；wider type通常更清楚。Cube root的bit length约为input bit length的one third，这给出tight initial range。

### Cube-root Newton

对$f(x)=x^3-n$应用Newton，得到real update $(2x+n/x^2)/3$。Integer form是

$$
x_{k+1}
=
\left\lfloor
\frac{2x_k+\lfloor n/x_k^2\rfloor}{3}
\right\rfloor.
$$

选择cube大于等于$n$的power-of-two initial estimate，保持sequence从上方下降；当next不再减小时返回current，再检查相邻立方bounds。

<HD11CubeNewtonLab />

```c
static uint32_t icbrt_newton_u32(uint32_t n) {
    if (n == 0u) return 0u;
    unsigned bits = 32u - stdc_leading_zeros(n);
    uint32_t x = UINT32_C(1) << ((bits + 2u) / 3u);
    while ((uint64_t)x * x * x < n) x <<= 1u;

    for (;;) {
        uint64_t square = (uint64_t)x * x;
        uint32_t next = (uint32_t)((2u * (uint64_t)x + n / square) / 3u);
        if (next >= x) return x;
        x = next;
    }
}
```

Code明确使用64-bit intermediate，适用于32-bit input。若target没有double-width multiply，binary search with guarded divisions或digit algorithm会更可靠。Signed negative extension必须单独说明：若要求mathematical floor，negative noncube的result比toward-zero cube root小1；若要求odd symmetry，则返回negative of nonnegative root。

## 11.3 Integer exponentiation

Naive repeated multiplication计算$a^e$需要$e-1$次multiplications。<Term def="按exponent bits反复square factor，只在当前bit为one时乘入result的logarithmic exponentiation algorithm。">平方求幂</Term>（exponentiation by squaring）使用identity

$$
a^e=
\begin{cases}
(a^2)^{e/2}, & e\text{ even},\\
a(a^2)^{(e-1)/2}, & e\text{ odd}.
\end{cases}
$$

Runtime处理exponent的bits，因此iteration count为$O(\log e)$。Loop invariant是

$$
\text{result}\cdot\text{factor}^{\text{remaining}}=a^e.
$$

Odd bit把factor乘进result；随后remaining右移，factor平方。Remaining变为zero时，result就是original power。

<HD11ExponentiationLab />

```c
static bool pow_u32_checked(uint32_t base, uint32_t exponent,
                            uint32_t *out) {
    uint32_t result = 1u;
    uint32_t factor = base;
    uint32_t remaining = exponent;

    while (remaining != 0u) {
        if ((remaining & 1u) != 0u) {
            if (factor != 0u && result > UINT32_MAX / factor) return false;
            result *= factor;
        }
        remaining >>= 1u;
        if (remaining != 0u) {
            if (factor != 0u && factor > UINT32_MAX / factor) return false;
            factor *= factor;
        }
    }
    *out = result;
    return true;
}
```

Function把zero exponent返回multiplicative identity one。因此zero to zero也返回one；这是combinatorial和many language libraries常用的contract，但不是universal mathematical decree。若application不接受，入口应显式reject该pair。

<HD11PowerOverflowLab />

<Term def="Final mathematical result或temporary product超过machine type range，导致wrap、trap或undefined behavior的风险。">中间值溢出</Term>必须在每一次conditional multiply和square前检查。只检查final result太晚：temporary factor可能已经overflow，之后即使该factor不再被selected，程序状态也不可信。

Signed base还要处理minimum integer的absolute value不可表示，以及positive result、negative result的不同limits。Modular exponentiation则是另一contract：每步有意在modulus下reduce，wrap不能自动等同于arbitrary modulus。

## 11.4 Integer logarithm

对base $b\ge2$和positive $n$，<Term def="返回最大的integer k，使base的k次方不超过positive input n。">整数对数</Term>定义

$$
k=\lfloor\log_b n\rfloor,
\qquad
b^k\le n\lt b^{k+1}.
$$

这个相邻幂certificate与root完全同构。Zero没有finite logarithm，base one不会产生strictly growing powers，negative base也不满足本章monotone definition；API应拒绝这些inputs。

### Base two is the highest set bit

Positive binary integer的floor log2等于highest set bit position。对w-bit word，

$$
\lfloor\log_2 n\rfloor
=
w-1-\operatorname{clz}(n).
$$

`clz(0)`在部分instruction sets或languages中undefined，因此zero check必须位于builtin call之前。Bit length则是floor log2加one。

<HD11Log2Lab />

```c
static bool ilog2_u32(uint32_t n, unsigned *out) {
    if (n == 0u) return false;
    *out = 31u - stdc_leading_zeros(n);
    return true;
}
```

Compiler intrinsic通常映射到count-leading-zeros或bit-scan instruction。Portable fallback可先用binary search over word halves，或复用Chapter 5的population-related bit techniques；无论实现形式，结果都要满足power-of-two bounds。

### Arbitrary base without overflowing the next power

最直接的algorithm从power one开始，反复乘base直到next power会超过$n$。关键是不要先计算可能overflow的`power * base`；先比较power与integer quotient $n/base$。

<HD11LogBaseLab />

```c
static bool ilog_u32(uint32_t n, uint32_t base,
                     uint32_t *exponent, uint32_t *power) {
    if (n == 0u || base < 2u) return false;
    uint32_t e = 0u;
    uint32_t p = 1u;
    while (p <= n / base) {
        p *= base;
        ++e;
    }
    *exponent = e;
    *power = p;
    return true;
}
```

Returned power就是$b^k$；caller可用$p\le n$与$n/p\lt b$复核certificate。Large exponent或frequent queries可采用binary search over exponent、table of powers或floating estimate加integer correction，但floating `log`只能做estimate：near exact powers的rounding可能差one，最终必须回到integer bounds。

## Roots and logarithms are one boundary-search pattern

<Term def="对ordered integer candidates寻找predicate由true变false的最后位置，并用相邻候选验证结果。">单调边界</Term>统一本章三个floor functions：

- Square root搜索最大的$r$，使$r^2$不超过$n$。
- Cube root搜索最大的$r$，使$r^3$不超过$n$。
- Integer logarithm搜索最大的$k$，使$b^k$不超过$n$。

Algorithm可换成binary search、Newton、digit recurrence、bit scan或power table，但contract不变：domain明确、rounding明确、last-true invariant明确、adjacent certificate明确。优化后的fast path应和simple reference oracle在edge values、perfect powers以及power边界两侧交叉验证。

<Callout type="trap" title="Newton只要等到next等于current就一定正确">
Integer floor会让iteration在root附近停滞或从下方出现不同behavior。修法是从已证明在root上方的estimate开始，只接受descending steps，在next不再减小时返回current，并用相邻幂证书复核。
</Callout>

<Callout type="trap" title="先算candidate的幂再比较最直观">
在fixed-width word中，square、cube或next power可能先overflow并wrap，错误candidate反而通过。修法是使用wider intermediate，或把comparison改写成guarded division，且zero case单独处理。
</Callout>

## 小结

Chapter 11 Some Elementary Functions把integer square root、integer cube root、integer exponentiation和integer logarithm放在同一套machine-integer reasoning中。Square与cube roots返回floor result，并用相邻幂bounds作为certificate；Newton需要above-root initialization和descending stopping rule，binary digit method提供只用shift、subtract和compare的alternative。

Exponentiation by squaring按exponent bits把linear multiplications降到logarithmic count，但每次square和multiply都要提前检查overflow。Integer logarithm在base two时等于highest set bit position，在arbitrary base时可用guarded multiplication寻找largest fitting power。

真正可移植的bit-level implementation不是只给出fast formula，而是同时给出domain、rounding、invariant、overflow strategy、adjacent certificate与independent oracle。

<Exercises>

**问题 1**：对$n=173$，integer square root、remainder和相邻平方证书分别是什么？

<Answer>
Thirteen的平方是169，fourteen的平方是196，因此floor integer square root为13。Remainder是173减169等于4；169不超过173且173小于196，相邻平方证书成立。
</Answer>

**问题 2**：为什么square-root Newton iteration要从root上方开始，并在next不再小于current时停止？

<Answer>
Above-root initialization使integer sequence保持单调下降，避免从下方因floor造成难以证明的停滞或跳动。当next不再下降时，current已经到达floor root的fixed region；再检查current平方与next integer平方即可确认结果。
</Answer>

**问题 3**：计算$3^{13}$时，exponentiation by squaring依赖什么loop invariant？Overflow应在哪里检查？

<Answer>
Invariant是result乘factor的remaining次方始终等于original 3的13次方。Current exponent bit为one时先检查result乘factor；remaining右移后若仍需迭代，再检查factor平方。每个temporary multiplication前都检查，而不是只看final result。
</Answer>

**问题 4**：对$n=1000$和base 10，integer logarithm返回什么？为什么guarded loop不先计算next power？

<Answer>
Largest exponent是3，因为10的3次方等于1000，而10的4次方超过1000。Loop先比较current power是否不超过n除base，只有确认next multiplication仍在range内才执行，从而避免next power在fixed-width type中overflow。
</Answer>
