## 从“为什么7到8会同时翻四个bits”开始

先预测：ordinary 4-bit binary从0111递增到1000，四个tracks不会在physical world绝对同时切换。若sensor或receiver在transition中间采样，可能暂时看到0000、1111或other mixed pattern。能否重新排列all 16 patterns，使相邻numeric states每次只改变one bit？

（Gray code）回答yes。Chapter 13只聚焦binary reflected Gray code及其negabinary variant。对fixed width $w$，目标是：

- 覆盖all $2^w$ bit patterns exactly once。
- Consecutive codewords的为one。
- 若声称cyclic，last与first的distance也为one。


Gray code改变的是representation order，不是ordinary arithmetic value。Gray word作为unsigned integer解释通常不等于其encoded index；要加、比较numeric magnitude或计算arbitrary jump，必须使用matching Gray semantics或先decode。

## 13.1 Gray Code

### Reflected construction visits the hypercube one edge at a time

（reflected binary Gray code）递归构造：

1. One-bit list是zero、one。
2. 保留previous list顺序并prefix zero。
3. Reverse previous list并prefix one。
4. Concatenate both halves。


Within each half，adjacency由previous code继承。Middle pair的suffix相同，只prefix从zero变one；first和last也只在new top bit不同，所以construction保持cyclic。


Graphically，$w$-bit words是w-dimensional hypercube vertices；Gray sequence是一条访问each vertex once的Hamiltonian cycle。One-bit change就是沿one edge移动。

### Binary to reflected Gray is one shift and XOR

设ordinary binary index为$b$，reflected Gray word为$g$：

$$
g
=
b\oplus(b\mathbin{\mathrm{shr}}1).
$$

Bit relation是

$$
g_i=b_{i+1}\oplus b_i,
$$

其中top之外的$b$视为zero。Gray bit记录adjacent binary bits之间是否发生boundary，而不是independent place value。


```c
static uint32_t binary_to_gray(uint32_t value) {
    return value ^ (value >> 1);
}
```

为什么successors只差one bit？令$t$是$n+1$的rightmost set bit：

$$
t=(n+1)\mathbin{\&}(-(n+1)).
$$

Binary increment把$t$下方的trailing ones清zero，并把$t$设one。Shift-XOR把这段many-bit carry changes相互cancel，只在boundary留下one bit：

$$
G(n)\oplus G(n+1)=t.
$$

因此difference恰为power of two，Hamming distance为one。

### Gray to binary is a prefix XOR scan

从$g_i=b_{i+1}\oplus b_i$反解：

$$
b_i
=
g_i\oplus g_{i+1}\oplus\cdots\oplus g_{w-1}.
$$

每个binary bit是从most significant side到该position的Gray prefix parity。Serial decoder从top向low逐bit XOR；word-parallel decoder可用doubling shifts：

```c
static uint32_t gray_to_binary(uint32_t gray) {
    uint32_t value = gray;
    value ^= value >> 1;
    value ^= value >> 2;
    value ^= value >> 4;
    value ^= value >> 8;
    value ^= value >> 16;
    return value;
}
```

Each stage把known prefix length double，32-bit word需要five stages。Generic implementation按word width生成shifts，不能把32-bit sequence直接用于larger type。


Gray encode和decode必须满足two-way round-trip。Full-width exhaustive test可遍历all indices，确认uniqueness、adjacency、wrap与inverse；wide words则用algebraic identities加boundary/random testing。

## 13.2 Incrementing a Gray-Coded Integer

### Direct increment does not require full decoding

最直观方案是Gray decode、ordinary increment、re-encode。若只持有Gray word，还可利用直接找next flip。

Gray bits整体XOR会telescopically cancel：

$$
\operatorname{parity}(g)
=
b_0.
$$

所以：

- 若Gray popcount为even，original index是even，flip bit zero。
- 若Gray popcount为odd，找Gray word的rightmost one，flip其左侧bit。


令$y=g\mathbin{\&}(-g)$提取rightmost one mask。Non-wrapping direct increment为

$$
g'
=
\begin{cases}
g\oplus1, & \operatorname{parity}(g)=0,\\
g\oplus(2y), & \operatorname{parity}(g)=1.
\end{cases}
$$

```c
static uint32_t gray_increment_unbounded(uint32_t gray) {
    if ((stdc_count_ones(gray) & 1u) == 0u) {
        return gray ^ 1u;
    }
    uint32_t rightmost_one = gray & (0u - gray);
    return gray ^ (rightmost_one << 1);
}
```

Function需要one spare high bit。若current是fixed-width sequence最后word，rightmost-one left shift落到width之外。

### Fixed-width cyclic increment has a boundary contract

在$w$ bits中，final reflected Gray word是only top bit set；cyclic next应回zero并flip该top bit，而不是丢弃out-of-range mask后保持unchanged。


```c
static uint32_t gray_increment_cyclic(uint32_t gray, unsigned width) {
    uint32_t top = UINT32_C(1) << (width - 1u);
    uint32_t mask = (top << 1u) - 1u;
    gray &= mask;
    if (gray == top) return 0u;
    if ((stdc_count_ones(gray) & 1u) == 0u) return gray ^ 1u;
    uint32_t rightmost_one = gray & (0u - gray);
    return gray ^ (rightmost_one << 1u);
}
```

Production code要单独处理width equal word size，避免shift by full width。也必须说明increment是modulo $2^w$还是允许grow width。

Direct rule只对successor by one成立。Pointer一次jump several positions时，two Gray words可能diff many bits；不能因为两端都叫Gray就假设one-bit transition。

## 13.3 Negabinary Gray Code

Chapter 12给出base -2 canonical representation。（negabinary Gray code）把two ideas组合：

1. 按ordinary integer value遍历fixed-width negabinary range。
2. 把每个integer编码为w-bit base -2 word $b_{-2}$。
3. 应用same transform $g=b_{-2}\oplus(b_{-2}\mathbin{\mathrm{shr}}1)$。


Three-bit base -2 range是negative 2到positive 5；four-bit range是negative 10到positive 5。Sequence index therefore包含negative and positive integers，但output仍是all w-bit patterns。

对adjacent ordinary integer values $n$与$n+1$，their negabinary words可能改变many bits；same shift-XOR again cancels carry region，使result只flip one bit。Fixed-width range的last-to-first也distance one，因此sequence cyclic。


它不是standard reflected order。可以从zero/one开始，alternately在list top和bottom附近reflection扩展；numeric range每增加one position会向negative或positive side扩张，取决于new place weight sign。

Decode分两层：

```c
static int64_t negabinary_gray_to_integer(uint32_t gray,
                                          unsigned width) {
    uint32_t word = gray_to_binary(gray);
    int64_t value = 0;
    for (unsigned bit = width; bit-- > 0u;) {
        value = value * -2 + ((word >> bit) & 1u);
    }
    return value;
}
```

First inverse Gray transform得到base -2 digit word，then Horner evaluation bynegative two得到signed integer。反向encode必须固定width并检查value落在对应asymmetric range内。

不要把negabinary Gray与“把two's-complement negative integer直接做ordinary Gray transform”混为一谈。前者的source digits是canonical base -2 word；后者依赖fixed two's-complement bit pattern，numeric ordering和range semantics不同。

## 13.4 Brief History and Applications

### Reflected code predates its modern name

Brief History and Applications（历史与应用）先区分idea与name。One-change order在Frank Gray之前已有相关forms；Frank Gray在1947 filed、1953 granted的pulse-code communication patent中系统使用reflected binary code来降低adjacent quantization transitions的ambiguity，之后Gray code成为通用名称。

是最直观应用。Ordinary binary在carry boundary同时切换many tracks；manufacturing offset或sampling time使receiver可能读到far-away mixed code。Gray track transition只有one bit changing，sample至多在two adjacent codewords之间ambiguous。


这不是error-correcting code。One track fault仍可能把word变成another valid codeword；而Gray word的one-bit corruption经prefix XOR decode甚至会改变多个low binary bits。Application要根据fault model另加parity、redundancy或range checks。

### Clock-domain pointers need more than XOR

Asynchronous FIFO常把monotone binary pointer转换为Gray后跨clock domain，因为one-step increment只改变one source bit。但complete还需要：

- Pointer每次source update只前进one logical step，或证明sampled transitions仍安全。
- Each bit经过synchronizer，Gray coding本身不消除metastability。
- Inter-bit skew受constraint，使destination aperture不会看到不同source updates拼接。
- Full/empty comparison在synchronized Gray domain使用proved transform。


Combinationally从ripple-changing binary counter生成Gray可能产生glitches；registered source Gray word更容易满足physical one-bit assumption。

### Maps, state enumeration, and puzzles

Karnaugh map使用Gray labels排列rows/columns，使geometrically adjacent cells只改变one Boolean variable，edge wrap也adjacent。这让implicant grouping直接对应one-variable elimination。


Gray order还用于enumerating subsets、rotary controls、test patterns与Tower-of-Hanoi-like state walks。共同点不是“XOR很快”，而是consumer关心local transition distance。若consumer主要做numeric arithmetic，ordinary binary通常更自然。

## 小结

Chapter 13 Gray Code用reflected construction遍历all fixed-width patterns，每个successor只改变one bit。Ordinary binary index通过$b\oplus(b\mathbin{\mathrm{shr}}1)$编码，inverse是most-significant-side prefix XOR；successor difference等于$n+1$的rightmost set bit。

Incrementing a Gray-coded integer可直接利用Gray parity：even翻bit zero，odd翻rightmost one左侧bit；fixed-width cyclic final state需要special wrap。Negabinary Gray code把按integer value排序的base -2 words送入same shift-XOR，得到range跨negative和positive的cyclic one-bit sequence。

History and applications说明Gray code的价值来自local transition，不来自arithmetic convenience。Position encoders、Karnaugh maps与asynchronous pointers都受益，但physical timing、synchronization与fault detection仍需独立contract。
