## 从“同一串32位为什么有多种意义”开始

先预测：word `0x3F800000`若按unsigned integer读取是1065353216，按binary32读取却是1。Bit trick并未改变bits；它改变的是interpretation。可靠实现必须同时回答three questions：bits如何分区、每个区间怎样解释、哪些输入不属于算法domain。

不是“带小数点的整数”。它把significand与scale分别编码，使有限bit budget覆盖极大dynamic range，但spacing随magnitude变化。Chapter 17的主线正是：先掌握representation，再把integer tricks应用到conversion、comparison和approximation，最后用distribution与boundary table检查直觉。


## 17.1 IEEE Format（IEEE格式）

Binary32的fields为sign $s$、stored exponent $e$和fraction integer $f$。当$1\le e\le254$时，value是：

$$
x=(-1)^s\left(1+\frac{f}{2^{23}}\right)2^{e-127}.
$$

Bias 127让negative and positive exponents都可存在unsigned exponent field中。Leading one不必存储，所以23 fraction bits提供24 bits precision。Bit layout并不等于numeric order：negative region的fraction越大，numeric value反而越小，这是后续integer comparison必须修正的地方。

当$e=0$且$f\ne0$时，value是：

$$
x=(-1)^s\left(\frac{f}{2^{23}}\right)2^{-126}.
$$

当$e=0,f=0$时得到signed zero；当$e=255,f=0$时得到signed infinity；当$e=255,f\ne0$时得到NaN。NaN fraction还可携带payload。算法若只检查“exponent不是zero”便把infinity和NaN误当normal，因此分类必须同时看exponent与fraction。


### ULP and binades

固定normal exponent的区间称为binade。相邻binary32的为

$$
\operatorname{ulp}(x)=2^{E-23}
\quad\text{for}\quad 2^E\le |x|\lt2^{E+1}.
$$

所以absolute error随scale增长，而normal range内relative spacing约为$2^{-23}$。比较误差时只写一个全局absolute epsilon通常不成立；应根据问题选ULP distance、relative tolerance或domain-specific absolute floor。


## 17.2 Floating-Point To/From Integer Conversions（浮点数与整数转换）

Binary32有效precision为24 bits，因此all integers from $-2^{24}$ through $2^{24}$ are exact。超过这个后，adjacent representable integers先隔2，再隔4、8，依次增长。Consequently，integer 16777217 rounds back to 16777216 under round-to-nearest-even。


### Integer to binary32

Unsigned integer转binary32可按representation反推：

1. Use count-leading-zeros找到highest set bit $k$。
2. Set biased exponent to $k+127$。
3. 把remaining significant bits放入fraction，并收集guard、round、sticky bits。
4. Apply selected rounding mode；若carry使significand overflow，则increment exponent。

下面的reference version依赖platform conversion来执行current rounding policy，bit-pattern只是为了verification，而不是用strict-aliasing违规方式读取object：

```cpp
#include <bit>
#include <cstdint>
#include <limits>

struct FloatWord {
    float value;
    std::uint32_t bits;
    bool exact;
};

FloatWord to_binary32(std::uint32_t input) {
    const float value = static_cast<float>(input);
    const auto bits = std::bit_cast<std::uint32_t>(value);
    const bool exact = static_cast<double>(value) ==
                       static_cast<double>(input);
    return {value, bits, exact};
}
```

在pre-C++20 code中可用`memcpy`在same-size trivially copyable objects之间复制bits。用pointer cast把`float*`强行解释成`uint32_t*`会碰到aliasing和alignment问题，不应作为portable proof。

### Binary32 to integer

Float-to-integer不只是删掉fraction。Contract必须指定rounding direction，并在转换前处理NaN、infinity与out-of-range。C/C++ built-in cast向zero truncates finite fractional part，但当truncated value不能表示为destination integer时，不能假设它自动saturate。

```cpp
#include <cmath>
#include <cstdint>
#include <limits>
#include <optional>

std::optional<std::int32_t> checked_trunc_to_i32(float value) {
    if (!std::isfinite(value)) return std::nullopt;
    const double truncated = std::trunc(static_cast<double>(value));
    if (truncated < -2147483648.0 || truncated > 2147483647.0) {
        return std::nullopt;
    }
    return static_cast<std::int32_t>(truncated);
}
```

这里先提升到double再比较bound，避免把2147483647转换为binary32后round成2147483648，导致upper-bound test失真。Production API还应决定negative zero是否保留、subnormal是否flush、rounding-mode是否可配置。


## 17.3 Comparing Floating-Point Numbers Using Integer Operations（用整数运算比较浮点数）

Positive finite binary32的unsigned bit pattern随numeric value增加；negative finite region则方向相反。可以把each encoding映射为：

$$
K(u)=
\begin{cases}
\mathord{\sim}u, & \text{if sign bit is one},\\
u\mathbin{\oplus}\mathtt{0x80000000}, & \text{otherwise}.
\end{cases}
$$

Negative encodings are complemented；nonnegative encodings flip sign bit。Equivalent branch-free mask is `(-(u >> 31)) | 0x80000000`。

```cpp
#include <bit>
#include <cstdint>

std::uint32_t ordered_binary32_key(float value) {
    const std::uint32_t bits = std::bit_cast<std::uint32_t>(value);
    const std::uint32_t sign = bits >> 31;
    const std::uint32_t mask = (0u - sign) | 0x80000000u;
    return bits ^ mask;
}
```


This key naturally orders negative infinity beforefinite values and positive infinity afterthem，but signed zeros与NaNs需要contract。Numeric equality认为negative zero equals positive zero，key却把two encodings排成adjacent distinct values。NaN与itself unordered，而integer key必然给它一个位置。因此有three viable policies：

- Numeric compare：先reject NaN，并canonicalize both zeros to one encoding。
- Bitwise deterministic order：保留signed zero和NaN payload，但明确这不是ordinary numeric relation。
- IEEE totalOrder：实现standard规定的complete ordering，包括NaN sign、quiet/signaling与payload规则。


## 17.4 An Approximate Reciprocal Square Root Routine（近似平方根倒数）

目标是positive normal binary32上的$y\approx1/\sqrt{x}$。Taking logarithms gives

$$
\log_2 y=-\frac{1}{2}\log_2 x.
$$

Binary32 exponent field让bit pattern粗略呈现affine log scale。Right-shifting input word approximately halves exponent；从tuned constant `0x5F375A82`减去它，便得到。

```cpp
#include <bit>
#include <cstdint>

float reciprocal_sqrt_seed(float x) {
    std::uint32_t word = std::bit_cast<std::uint32_t>(x);
    word = 0x5F375A82u - (word >> 1);
    return std::bit_cast<float>(word);
}

float reciprocal_sqrt_refine(float x, float y) {
    return y * (1.5f - 0.5f * x * y * y);
}
```

The seed is only a coarse model。Apply
$$
y_{k+1}=y_k\left(1.5-0.5xy_k^2\right).
$$

在representative positive-normal sweep中，one refinement的maximum relative error约$1.75\times10^{-3}$，two refinements约$4.72\times10^{-6}$。Exact peak依赖constant、rounding sequence和whether intermediate operations fuse；这些数字应作为tested contract，不是无条件mathematical guarantee。

### Domain and modern use

This routine的core domain是positive normal finite inputs。Zero的mathematical result is infinity；negative input has no real result；subnormal、infinity和NaN都需要separate policy。Modern CPUs/GPUs可能提供hardware reciprocal-square-root estimate，再配合Newton refinement；standard library `sqrt`也可能更准确且足够快。Bit hack是否值得使用必须由target benchmark、error sweep与special-value test共同决定。


## 17.5 The Distribution of Leading Digits（首位数字分布）

许多跨越multiple decades、近似scale-invariant的数据并非first digits uniformly distributed。 predicts

$$
P(D=d)=\log_{10}\left(1+\frac{1}{d}\right),
\qquad d\in\{1,2,\ldots,9\}.
$$

Digit 1 probability约30.1%，digit 9约4.58%。Reason可从fractional part of $log_{10}x$理解：若它在$[0,1)$近似uniform，first digit $d$对应interval from $log_{10}d$ to $log_{10}(d+1)$，interval length正是formula。


这不是“所有真实数据都服从Benford”的law。Telephone numbers、fixed-price catalog、human-imposed bounds、single narrow interval或uniform random integers都可能不符合。Powers of two会显示另一种structured pattern。The sampling mechanism decides distribution。


## 17.6 Table of Miscellaneous Values（杂项数值表）

Chapter最后的table把representation landmarks集中起来。For binary32：

$$
\begin{aligned}
\epsilon_1 &= 2^{-23},\\
x_{\min,\mathrm{normal}} &= 2^{-126},\\
x_{\min,\mathrm{subnormal}} &= 2^{-149},\\
x_{\max} &= (2-2^{-23})2^{127}.
\end{aligned}
$$

These values分别锚定spacing at one、normal/subnormal boundary、smallest positive value和overflow boundary。再加exact integer threshold $2^{24}$，就构成conversion和comparison的minimum known-vector set。


`nextafter`-style tests还应覆盖：largest subnormal的next value是minimum normal；one的next value word为`0x3F800001`；negative one向positive direction的next word为`0xBF7FFFFF`；maximum finite向positive direction进入infinity。Every landmark同时assert bits、classification和numeric relation，避免只检查printed decimal。

## 17.7 Engineering contract and verification

Floating bit trick的proof不能止于three hand examples。Recommended verification matrix：

- Exact vectors：positive/negative zero、minimum/maximum subnormal、minimum normal、one、exact-integer boundary、maximum finite、infinities、several NaNs。
- Metamorphic properties：finite monotone key preserves order；decode/encode round-trip preservesbits；`nextUp(x)` strictly advances one encoding step。
- Error sweeps：按exponent分层并覆盖fraction endpoints，而不是只从small decimal range均匀抽样。
- Compiler/target checks：fast-math、flush-to-zero、fused multiply-add和rounding mode都记录在test environment中。


### One decision sequence

面对new floating trick，可依次问：

1. 输入是numeric values还是raw interchange bits？
2. 支持哪些classes，unsupported input怎样返回？
3. Equality、ordering和rounding采用哪个standard contract？
4. Error用absolute、relative还是ULP度量，maximum budget是多少？
5. Clear reference implementation和optimized implementation是否逐bit或逐contract等价？

这个sequence把clever constant变成reviewable engineering artifact。Representation知识给出candidate transform；domain contract与exhaustive boundary tests才给出可信度。

## 小结

IEEE binary32以sign、biased exponent和fraction编码normal、subnormal、zero、infinity与NaN；ULP随binade变化。Integer conversion必须显式处理rounding、range与special values。Finite non-NaN encodings经negative complement和positive sign flip可得到monotone integer key，但signed zero与NaN仍需policy。Approximate reciprocal square root由affine-log seed加Newton refinement构成，速度价值必须由target benchmark和full-range error sweep证明。Leading-digit distribution来自sampling process，miscellaneous-value table则提供boundary test anchors。
