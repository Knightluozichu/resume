## 从“7加1为什么显示8却要标错”开始

先预测：4-bit adder输入`0111`和`0001`，硬件自然输出`1000`。Bits没有错；若按unsigned解释，结果8完全合法；若按two’s-complement signed解释，两个positive operands却得到negative eight，mathematical result无法表示，所以发生signed overflow。

Arithmetic Tables for a 4-Bit Machine（4位机器算术表）把这种interpretation conflict摊开成完整small universe。附录用underlining标signed overflow；教学版用color和status fields表达same distinction。

<HDAppendixAWordDecodeLab />

<Term def="Word width固定为four bits，unsigned domain为zero through fifteen，two’s-complement signed domain为negative eight through seven的abstract machine。">4位机器</Term>只有16种bit patterns，正适合exhaustive reasoning。Let $u$ be a4-bit word interpreted unsigned；its signed value is

$$
S(u)=
\begin{cases}
u, & 0\le u\le7,\\
u-16, & 8\le u\le15.
\end{cases}
$$

Every stored arithmetic result isreduced modulo16：

$$
\operatorname{low}_4(z)=z\bmod16.
$$

Modulo result is alwayswell-defined；overflow is aclaim aboutwhetherexact result fits achosen interpretation。

## A.1 Reading the tables（读取算术表）

<Term def="Rows and columns enumerateall operand words，cells showfull or stored arithmetic result andmark status conditions such as signed overflow。">算术表</Term> simultaneously serveasexamples andtruth tables。Before readingacell，fixfive conventions：

1. Are row/column labelsbits、unsigned values orsigned values？
2. Is cell thefull mathematical result orthelow-word result？
3. Is operation row minus column orcolumn minus row？
4. Does carry meanunsigned carry，or onsubtraction not-borrow？
5. Does overflow refer tounsigned width orsigne d range？

In Appendix A，hex labels0 throughF denote words；signed labelsnegative8 throughnegative1 appearabove8 throughF toremindtheir second interpretation。Addition cells showfull hexadecimal sums up to`1E`；the machine’s stored result islow digit。Underlining marks signed overflow，not everycarry。

<Callout type="trap" title="常见误区：carry和signed overflow是同一个bit">

`F + 1` hasunsigned carry butsigned operandsnegative one andpositive one producezero withoutsigned overflow。`7 + 1` hasno unsigned carry，yetpositive signed result8 isout ofrange。The flags areindependent predicates。

</Callout>

## A.2 Table A-1 · Addition（加法表）

For words$x,y$，full unsigned sum is$x+y$，stored word is

$$
r=(x+y)\bmod16.
$$

Unsigned carry isone exactlywhen$x+y\ge16$。Signed overflow isone exactlywhen

$$
S(x)+S(y)\notin[-8,7].
$$

Equivalent sign-bit rule：operands havesame sign andwrapped result hasopposite sign。This rule avoidsperforming wider signed arithmetic inhardware。

<Stepper>
  <Step title="Step 1 · Decode both words">
    Read each nibble bothunsigned andsigned；do notchoosemeaning afterseeingthe result。
    <HDAppendixAWordDecodeLab />
  </Step>
  <Step title="Step 2 · Locate full sum">
    The selected grid cell showslowhex digit；inspectfull sum andcarry separately。
    <HDAppendixAAdditionTableLab />
  </Step>
  <Step title="Step 3 · Compare flag predicates">
    Switch amongcases whereonlycarry、onlyoverflow、both orneither occurs。
    <HDAppendixAAdditionFlagsLab />
  </Step>
</Stepper>

```c
#include <stdbool.h>
#include <stdint.h>

typedef struct {
    uint8_t low;
    bool carry;
    bool signed_overflow;
} add4_result;

add4_result add4(uint8_t x, uint8_t y) {
    x &= 0xFu;
    y &= 0xFu;
    uint8_t full = (uint8_t)(x + y);
    uint8_t low = full & 0xFu;
    bool carry = full > 0xFu;
    bool overflow = ((~(x ^ y) & (x ^ low)) & 0x8u) != 0;
    return (add4_result){low, carry, overflow};
}
```

The overflow expression looks only atsign bit position。`~(x ^ y)` selects same-sign operands；`x ^ low` selects sign change；mask`0x8` isolatesnibble sign。

## A.3 Table A-2 · Subtraction, row minus column（减法表）

Table A-2 operation is<Term def="Appendix A subtraction table convention：left row operand a minus top column operand b。">行减列</Term>。For unsigned words$x,y$，stored difference is

$$
r=(x-y)\bmod16.
$$

Unsigned borrow isone exactlywhen$x<y$。The table assumesadder-style implementation

$$
x-y=x+\mathord{\sim}y+1
\pmod{16},
$$

so final carry isone whenno borrow occurred。That is<Term def="Subtraction status convention in which carry one means the unsigned minuend was at least the subtrahend，so no borrow was needed。">carry等于非借位</Term>。

<Stepper>
  <Step title="Step 1 · Fix row and column">
    Row isminuend，column issubtrahend；reversingthem changesbothresult andborrow。
    <HDAppendixASubtractionTableLab />
  </Step>
  <Step title="Step 2 · Translate borrow to carry">
    Compare$x<y$ withfinal carry from$x+(~y)+1$；the bits arelogical complements。
    <HDAppendixANotBorrowLab />
  </Step>
  <Step title="Step 3 · Check signed range">
    Interpret bothinputs as$S(x),S(y)$ andmark overflow whenexact difference leavesnegative8 through7。
    <HDAppendixAOverflowPredicateLab />
  </Step>
</Stepper>

Signed subtraction overflow occurs whenoperand signs differ andresult sign differs fromminuend sign：

```c
add4_result sub4(uint8_t x, uint8_t y) {
    x &= 0xFu;
    y &= 0xFu;
    uint8_t low = (uint8_t)(x - y) & 0xFu;
    bool borrow = x < y;
    bool overflow = (((x ^ y) & (x ^ low)) & 0x8u) != 0;
    return (add4_result){low, !borrow, overflow};
}
```

Here result field named`carry` storesnot-borrow to matchAppendix convention。An API should nameit explicitly；a bareflag`C` invitescross-architecture mistakes becauseinstruction sets differin subtraction flag conventions。

<Callout type="trap" title="常见误区：负的table cell必然表示borrow或overflow">

Signed negativity isjustbit3 beingone。For examplenegative three minuspositive two equalsnegative five，representable withoutsigned overflow；unsigned words`D - 2` equal11 withoutborrow。One bit pattern canmeanbothfacts atonce。

</Callout>

## A.4 Tables A-3/A-4 · Multiplication（乘法表）

Two 4-bit operands producean exact8-bit product。Forunsigned inputs，range iszero through225；for signed inputs，range isnegative56 through64。The low4 bits are identical underboth interpretations because two’s-complement multiplication agrees modulo16：

$$
(xy)\bmod16=(S(x)S(y))\bmod16.
$$

High half differs。Unsigned full product useszero-extended operands；signed full product uses sign-extended operands。

<HDAppendixAUnsignedMultiplicationLab />

### Unsigned one-word overflow

Unsigned 4-bit multiplication overflowsone word whenexact product exceeds15，equivalentlywhenhigh nibble isnonzero。Full 8-bit result remainsvalid andcontains bothhigh/low halves。

<HDAppendixAFullProductLab />

### Signed one-word overflow

Signed product fitsone word only ifexact value isinnegative8 through7。Equivalent high-half test：all bits abovelow nibble must equalthe low nibble sign extension。A high nibble ofzero isnot enoughforpositive result iflow sign bit isone；for examplepositive9 cannot be represented though8-bit producthigh nibble iszero。

<HDAppendixASignedMultiplicationLab />

```c
typedef struct {
    uint8_t low;
    uint8_t high;
    bool overflow;
} mul4_result;

mul4_result mul4_unsigned(uint8_t x, uint8_t y) {
    uint16_t product = (uint16_t)(x & 0xFu) * (uint16_t)(y & 0xFu);
    return (mul4_result){
        (uint8_t)(product & 0xFu),
        (uint8_t)((product >> 4) & 0xFu),
        product > 0xFu
    };
}
```

For signed multiplication，decodeeach input intoa wider signed type beforemultiply；thencheckrange beforetruncation。Checkingafterlow-word truncation losesoverflow evidence。

## A.5 One invariant behind every underline

The Appendix markings canall begenerated froma single<Term def="Compute operation in a wider mathematical domain，then declare overflow exactly when exact result lies outside target signed interval。">精确结果范围契约</Term>：

$$
\mathrm{overflow}_{s4}(z)=[z<-8\;\lor\;z>7].
$$

Addition/subtraction sign formulas areoptimized ways tocompute samepredicate fromnarrow words。Multiplication high-half test isanother equivalent implementation。The wider reference is simplest oracle forsmall exhaustive tests。

<HDAppendixAOverflowPredicateLab />

### Generate, do not hand-copy

A 16-by-16 table has256 cells peroperation。Manual transcription ispoor source oftruth；generate cells andflags fromindependent reference arithmetic，thenassertoptimized predicates match。

```c
for (unsigned x = 0; x != 16; ++x) {
    for (unsigned y = 0; y != 16; ++y) {
        int sx = (x & 8u) ? (int)x - 16 : (int)x;
        int sy = (y & 8u) ? (int)y - 16 : (int)y;
        int exact = sx + sy;
        unsigned low = (x + y) & 15u;
        bool range_overflow = exact < -8 || exact > 7;
        bool bit_overflow = ((~(x ^ y) & (x ^ low)) & 8u) != 0;
        assert(range_overflow == bit_overflow);
    }
}
```

Repeat forsubtraction andboth multiplication interpretations。Known boundary cells include`7+1`、`F+1`、`8+8`、`8-1`、`7-F`、`F*F` and`8*8`。

## 小结

4-bit machine exposesall fixed-width arithmetic cases in16 words。Table A-1 separatesfull addition、stored low nibble、unsigned carry andsigned overflow。Table A-2 isrow minus column anddefinescarry asnot-borrow。Tables A-3/A-4 showthat signed andunsigned multiplication sharelow half butdifferin full-width interpretation andoverflow tests。Underlining meanssigned exact result cannot fitnegative8 through7，not merelythat a high bit exists。Generated exhaustive tables turnvisual reference intoan executable specification。
