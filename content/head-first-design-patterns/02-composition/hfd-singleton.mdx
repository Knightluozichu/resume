## 为什么需要单例模式

有些对象在系统中只需要一个实例：线程池、缓存、注册表、日志器、配置管理器。如果创建多个实例，会导致状态不一致或资源浪费——两个日志器写不同文件、两个缓存持有不同数据。

最直觉的方案是全局变量，但全局变量在面向对象中有问题：无法延迟创建（启动时就分配）、无法控制访问、无法保证唯一性。单例模式把「唯一实例」和「全局访问」封装到类自身——构造函数私有，通过静态方法获取唯一实例。

## 概念讲解

单例模式的实现要点是：**构造函数私有 + 静态唯一实例 + 全局访问方法**。难点在于多线程下保证唯一性。书中介绍了四种 Java 实现，逐步解决线程安全、延迟加载和性能的三角矛盾。

在类加载时直接 `new` 实例。简单且线程安全（JVM
类加载保证），但如果实例重且启动时不一定用到，浪费资源。

延迟加载，但 `synchronized`
加在整个方法上——即使实例已创建，每次调用都加锁，性能差。

只在实例未创建时加锁，创建后直接返回。兼顾线程安全和性能，但必须用 `volatile`
修饰实例——防止 `new` 操作的指令重排序导致「半初始化」对象。

是最推荐方案。内部类在首次使用时才加载，JVM 类加载机制保证线程安全，代码最简洁。

## 代码对照

```java
// 双检锁（DCL）——需 volatile
public class Singleton {
    private volatile static Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {                  // 第一次检查（无锁）
            synchronized (Singleton.class) {
                if (instance == null) {          // 第二次检查（有锁）
                    instance = new Singleton();  // volatile 防指令重排
                }
            }
        }
        return instance;
    }
}

// 静态内部类——最推荐
public class Singleton {
    private Singleton() {}

    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;  // 首次访问时 Holder 才加载
    }
}
```

静态内部类方案利用 JVM 类加载机制同时满足线程安全 + 延迟加载，且无同步开销。

## 小结与练习

- 单例模式确保唯一实例 + 全局访问点：构造私有 + 静态实例 + getInstance
- 四种实现：饿汉（安全不延迟）、懒汉同步（延迟但慢）、双检锁（快需 volatile）、静态内部类（推荐）
- 双检锁的 volatile 防止 new 的指令重排序导致半初始化对象
- 静态内部类利用 JVM 类加载机制天然满足线程安全 + 延迟加载
