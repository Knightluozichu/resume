## 为什么需要单例模式

有些对象在系统中只需要一个实例：线程池、缓存、注册表、日志器、配置管理器。如果创建多个实例，会导致状态不一致或资源浪费——两个日志器写不同文件、两个缓存持有不同数据。

最直觉的方案是全局变量，但全局变量在面向对象中有问题：无法延迟创建（启动时就分配）、无法控制访问、无法保证唯一性。单例模式把「唯一实例」和「全局访问」封装到类自身——构造函数私有，通过静态方法获取唯一实例。

## 概念讲解

单例模式的实现要点是：**构造函数私有 + 静态唯一实例 + 全局访问方法**。难点在于多线程下保证唯一性。书中介绍了四种 Java 实现，逐步解决线程安全、延迟加载和性能的三角矛盾。

<Term def="类加载时就创建实例，天然线程安全但不延迟加载">饿汉式</Term>
在类加载时直接 `new` 实例。简单且线程安全（JVM
类加载保证），但如果实例重且启动时不一定用到，浪费资源。

<Term def="首次调用时创建实例，方法加 synchronized 保证线程安全但每次调用都同步">懒汉式同步方法</Term>
延迟加载，但 `synchronized`
加在整个方法上——即使实例已创建，每次调用都加锁，性能差。

<Term def="先判空再加锁再判空，需 volatile 防止指令重排">双检锁（DCL）</Term>
只在实例未创建时加锁，创建后直接返回。兼顾线程安全和性能，但必须用 `volatile`
修饰实例——防止 `new` 操作的指令重排序导致「半初始化」对象。

<Term def="利用 JVM 类加载机制天然保证线程安全和延迟加载">静态内部类</Term>
是最推荐方案。内部类在首次使用时才加载，JVM 类加载机制保证线程安全，代码最简洁。

## 代码对照

```java
// 双检锁（DCL）——需 volatile
public class Singleton {
    private volatile static Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {                  // 第一次检查（无锁）
            synchronized (Singleton.class) {
                if (instance == null) {          // 第二次检查（有锁）
                    instance = new Singleton();  // volatile 防指令重排
                }
            }
        }
        return instance;
    }
}

// 静态内部类——最推荐
public class Singleton {
    private Singleton() {}

    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;  // 首次访问时 Holder 才加载
    }
}
```

静态内部类方案利用 JVM 类加载机制同时满足线程安全 + 延迟加载，且无同步开销。

## 小结与练习

- 单例模式确保唯一实例 + 全局访问点：构造私有 + 静态实例 + getInstance
- 四种实现：饿汉（安全不延迟）、懒汉同步（延迟但慢）、双检锁（快需 volatile）、静态内部类（推荐）
- 双检锁的 volatile 防止 new 的指令重排序导致半初始化对象
- 静态内部类利用 JVM 类加载机制天然满足线程安全 + 延迟加载

<Exercises>
  <Answer question="双检锁为什么要用 volatile？不加 volatile 会出什么问题？">
    `new Singleton()` 分三步：1.分配内存 2.调用构造函数初始化 3.把地址赋给
    instance。JVM 可能重排序为 1→3→2。线程 A 执行到步骤 3（instance
    非空但未初始化），线程 B 进入 getInstance() 第一次检查 instance
    非空直接返回——拿到半初始化对象，使用时崩溃。volatile
    禁止指令重排序（happens-before
    语义）并保证内存可见性，确保其他线程看到完整初始化的对象。
  </Answer>
  <Answer question="为什么静态内部类是最推荐的 Java 单例实现？">
    三个原因：1.线程安全——JVM 类加载机制保证类初始化线程安全，无需
    synchronized。2.延迟加载——Holder 内部类在首次访问 getInstance()
    时才加载，不会在 Singleton 类加载时就创建实例。3.代码简洁——无
    synchronized、无
    volatile、无双重检查，代码最清晰。唯一限制是不支持延迟传参（构造时无法传参数），但绝大多数单例场景不需要传参。
  </Answer>
</Exercises>

<Glossary>
  <GlossaryItem term="饿汉式">
    类加载时就创建实例的单例实现。JVM
    类加载保证线程安全，但不支持延迟加载——实例重时浪费资源。
  </GlossaryItem>
  <GlossaryItem term="双检锁（DCL）">
    先无锁检查再加锁再检查的单例实现。只在实例未创建时加锁，兼顾线程安全和性能。必须用
    volatile 防止 new 的指令重排序。
  </GlossaryItem>
  <GlossaryItem term="volatile">
    Java 关键字，禁止指令重排序并保证内存可见性。在双检锁中防止 new
    操作的重排序导致其他线程拿到半初始化对象。
  </GlossaryItem>
  <GlossaryItem term="静态内部类">
    利用 JVM
    类加载机制实现的单例方案。内部类在首次使用时才加载，天然保证线程安全和延迟加载，是最推荐的
    Java 单例实现。
  </GlossaryItem>
