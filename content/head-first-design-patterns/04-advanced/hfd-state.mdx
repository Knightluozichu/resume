## 为什么需要状态模式

你在开发一个口香糖机。它的工作流程是：没投币时只能投币；投了币可以转把手或退币；转了把手就发糖；糖卖光了就拒绝服务。最初你用一堆 `if-else` 或 `switch` 根据当前状态判断该做什么：

```java
public void insertQuarter() {
    if (state == HAS_QUARTER) {
        System.out.println("已经投过硬币了");
    } else if (state == NO_QUARTER) {
        state = HAS_QUARTER;
        System.out.println("投币成功");
    } else if (state == SOLD_OUT) { ... }
    else if (state == SOLD) { ... }
}
```

每个动作方法（投币、退币、转把手、发糖）都要写一遍四状态的判断。加一个新状态（比如「中奖状态」），要改所有方法里的分支——容易漏、容易错。

问题的根源是：**状态判断散落在各个方法里**。状态越多，条件分支越膨胀，行为越难维护。

## 概念讲解

状态模式的思路是：**把每种状态的行为封装到独立的状态对象里，Context 持有当前状态引用，把行为委托出去**。

是 GumballMachine。它不再用 if-else 判断状态，而是把 `insertQuarter()` 委托给
`state.insertQuarter()`。状态转移就是把 `state` 引用换成另一个状态对象。

声明 `insertQuarter()`、`ejectQuarter()`、`turnCrank()`、`dispense()`
等方法。每个具体状态只实现「自己这个状态下」该做什么——NoQuarterState 的
`insertQuarter()` 是接受投币，HasQuarterState 的 `insertQuarter()` 是拒绝重复投币。

不再散落在条件分支里，而是集中在状态对象内部：NoQuarterState 收到投币后，调
`context.setState(hasQuarterState)` 完成转移。转移逻辑和状态行为写在一起，清晰可控。

关键转变：从「Context 根据状态判断行为」到「状态对象自己决定行为」。Context 变简单了（只委托），每个状态对象内聚了「这个状态下该做什么 + 该转移到哪」。加新状态只需新增一个状态类，Context 和其他状态零改动。

## 代码对照

```java
// 1. State 接口
public interface State {
    void insertQuarter();
    void ejectQuarter();
    void turnCrank();
    void dispense();
}

// 2. Context——持有状态引用，委托行为
public class GumballMachine {
    State noQuarterState = new NoQuarterState(this);
    State hasQuarterState = new HasQuarterState(this);
    State soldState = new SoldState(this);
    State state = noQuarterState;  // 当前状态

    public void insertQuarter() { state.insertQuarter(); }  // 委托
    public void turnCrank() { state.turnCrank(); }
    public void setState(State s) { this.state = s; }       // 状态转移
}

// 3. 具体状态——行为 + 转移写在一起
public class NoQuarterState implements State {
    GumballMachine machine;
    public NoQuarterState(GumballMachine m) { machine = m; }

    public void insertQuarter() {
        System.out.println("投币成功");
        machine.setState(machine.getHasQuarterState());  // 转移
    }
    public void turnCrank() {
        System.out.println("还没投币呢");  // 此状态下不合法
    }
    // ...
}
```

Context 只负责委托和切换状态引用，每个状态对象内聚自己的行为——条件分支消失了。

## 小结与练习

- 状态模式把状态相关行为分散到独立状态对象，Context 持有当前状态引用并委托行为
- 状态转移 = 切换 Context 的 state 引用，显式且集中
- 加新状态只需新增状态类，Context 和其他状态零改动——替代膨胀的 if-else
- 适用场景：对象行为依赖内部状态，且状态多、转移复杂、会持续增加
