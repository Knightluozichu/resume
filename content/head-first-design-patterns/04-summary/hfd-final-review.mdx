## 回到起点

全书从策略模式开始——把行为抽成接口，用组合代替继承。然后一路走过观察者、装饰器、工厂、单例、命令、适配器、外观，最后用模板方法收尾。10 个模式看似各不相同，但它们都在做同一件事：**找出变化的部分，把它抽出来独立封装**。

现在把所有模式放到 GoF 的三大分类框架里，看看它们各自解决什么问题。

## GoF 三大分类

<HfdFinalReviewDiagram />

覆盖 3 个：

- **单例模式**：保证全局唯一实例，控制访问点。
- **工厂方法**：子类决定创建哪个对象，依赖倒置。
- **抽象工厂**：创建一族风格一致的相关产品。

覆盖 3
个：

- **装饰器模式**：层层包裹动态叠加功能，继承类型+持有引用。
- **适配器模式**：转换接口让不兼容的类协作。
- **外观模式**：提供简化入口屏蔽子系统复杂度。

覆盖
4 个：

- **策略模式**：把算法封装成可替换的接口。
- **观察者模式**：一对多通知，松耦合的数据广播。
- **命令模式**：请求封装成对象，支持撤销和宏操作。
- **模板方法**：父类定义骨架，子类填空——好莱坞原则。

## 三大原则贯穿全书

体现在：策略模式（Duck 面向 FlyBehavior）、观察者模式（Subject 面向
Observer）、装饰器模式（面向 Beverage）、命令模式（Invoker 面向 Command）。

体现在：策略模式（Duck 组合
FlyBehavior）、装饰器模式（装饰器组合被装饰对象）、观察者模式（Subject 组合
Observer 列表）、命令模式（ConcreteCommand 组合 Receiver）。

体现在：每个模式都把一个变化点隔离封装——策略封装行为变化，观察者封装状态变化，装饰器封装功能叠加，工厂封装创建过程。

## 复合模式：模式协同工作

实际项目中，模式很少单独使用。以智能家居系统为例：

```java
// 单例——全局控制器
public class SmartHomeController {
    private static SmartHomeController instance;
    // 全局唯一，管理所有设备和命令历史
}

// 命令模式——封装控制请求，支持撤销
public class LightOnCommand implements Command {
    Light light;
    public void execute() { light.on(); }
    public void undo() { light.off(); }
}

// 外观模式——简化客户端调用
public class SmartHomeFacade {
    public void goHome() {  // 一键回家
        lightOnCmd.execute();
        acOnCmd.execute();
        musicOnCmd.execute();
    }
}

// 工厂方法——创建命令对象
public abstract class CommandFactory {
    abstract Command createCommand(String device, String action);
}

// 观察者模式——设备状态同步到 UI
public class Device implements Subject {
    List<Observer> observers;
    public void stateChanged() { notifyObservers(); }
}
```

多个模式协同：Facade 调用 Command，Command 调用 Device；Device 状态变化通知 Observer；CommandFactory 创建 Command；Singleton 管理全局。每个模式解决一个问题域。

## 小结与练习

- 全书覆盖 8 个 GoF 模式：创建型 3 个、结构型 3 个、行为型 4 个
- 三大原则贯穿所有模式：针对接口编程、多用组合少用继承、对变化封装
- 核心心法：把变化的部分抽出来，封装成独立对象
- 模式是重构的目标不是设计的起点——先简单，变化来再重构
