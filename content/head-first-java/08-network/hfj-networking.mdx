## Socket 通信

<Term def="Socket是网络通信的端点,Java中客户端用Socket连接服务器,服务器用ServerSocket监听端口接受连接。">Socket 通信</Term>是 Java 网络编程的基础。

<HfjNetworkingDiagram />

```java
import java.io.*;
import java.net.*;

// ===== 服务器端 =====
// 1. 创建 ServerSocket, 绑定端口
ServerSocket serverSocket = new ServerSocket(5000);
System.out.println("服务器启动, 等待连接...");

// 2. accept() 阻塞等待客户端连接
Socket clientSocket = serverSocket.accept();
System.out.println("客户端连接: " + clientSocket.getInetAddress());

// 3. 获取输入输出流
InputStream in = clientSocket.getInputStream();
OutputStream out = clientSocket.getOutputStream();

// 4. 读取客户端数据
byte[] buf = new byte[1024];
int len = in.read(buf);
String request = new String(buf, 0, len);
System.out.println("收到: " + request);

// 5. 发送响应
out.write("Hello from server".getBytes());
out.flush();  // 刷新缓冲区!

// 6. 关闭
clientSocket.close();
serverSocket.close();
```

```java
// ===== 客户端 =====
// 1. 创建 Socket, 连接服务器 (IP + 端口)
Socket socket = new Socket("127.0.0.1", 5000);

// 2. 获取输入输出流
OutputStream out = socket.getOutputStream();
InputStream in = socket.getInputStream();

// 3. 发送数据
out.write("Hello from client".getBytes());
out.flush();

// 4. 读取响应
byte[] buf = new byte[1024];
int len = in.read(buf);
String response = new String(buf, 0, len);
System.out.println("服务器回复: " + response);

// 5. 关闭
socket.close();
```

## TCP vs UDP

```java
// TCP: 面向连接, 可靠传输
// Socket (客户端) + ServerSocket (服务器)
// 三次握手建立连接, 保证数据到达, 按序到达
// 适用: HTTP/FTP/聊天/文件传输

// UDP: 无连接, 不可靠传输
// DatagramSocket + DatagramPacket
// 直接发送, 不保证到达, 开销小
// 适用: DNS/视频流/在线游戏
import java.net.*;

// UDP 发送端
DatagramSocket udpSocket = new DatagramSocket();
String msg = "Hello UDP";
DatagramPacket packet = new DatagramPacket(
    msg.getBytes(), msg.length(),
    InetAddress.getByName("127.0.0.1"), 5000
);
udpSocket.send(packet);

// UDP 接收端
DatagramSocket recvSocket = new DatagramSocket(5000);
byte[] buf = new byte[1024];
DatagramPacket recvPacket = new DatagramPacket(buf, buf.length);
recvSocket.receive(recvPacket);  // 阻塞等待
String received = new String(recvPacket.getData(), 0, recvPacket.getLength());
```

## 多线程服务器

```java
// 单线程问题: 处理一个客户端时, 其他客户端被阻塞
// 多线程: 主线程循环 accept, 每个客户端交给独立线程

ServerSocket server = new ServerSocket(5000);
while (true) {
    Socket client = server.accept();  // 主线程等待连接
    // 每个客户端一个线程
    new Thread(() -> {
        try {
            handleClient(client);  // 处理客户端请求
        } catch (IOException e) {
            e.printStackTrace();
        }
    }).start();
    // 主线程立即回到 accept 等待下一个客户端
}

// 处理单个客户端
void handleClient(Socket client) throws IOException {
    try (InputStream in = client.getInputStream();
         OutputStream out = client.getOutputStream()) {

        byte[] buf = new byte[1024];
        int len = in.read(buf);
        String request = new String(buf, 0, len);

        out.write(("Echo: " + request).getBytes());
        out.flush();
    } finally {
        client.close();
    }
}
```

## 常见误区

<Callout type="trap">
**误区：Socket 通信不需要 flush。** OutputStream 通常有缓冲区（尤其是用 PrintWriter/BufferedWriter 包装的），写入的数据可能还在缓冲区没发到网络。如果不 flush()，对方可能收不到数据或收不全。PrintWriter 的构造函数可设 autoFlush=true，但 OutputStream 必须手动 flush。关闭流之前也必须先 flush。最佳实践用 try-with-resources 自动关闭，关闭顺序：先输出流（触发 flush）→ 输入流 → Socket。
</Callout>

<Exercises>
**问题 1**：TCP 和 UDP 的区别是什么？分别适用什么场景？

<Answer>
TCP：面向连接（三次握手），可靠传输（保证到达、不丢失、按序），流式传输，开销大，一对一。适用 HTTP/FTP/SMTP/聊天等需要可靠传输的场景。UDP：无连接（直接发送），不可靠（可能丢包/乱序），数据报传输，开销小，支持一对多/广播。适用 DNS/视频流/在线游戏/VoIP 等允许少量丢包但要求低延迟的场景。
</Answer>

**问题 2**：如何实现一个多线程服务器？为什么需要多线程？

<Answer>
需要多线程的原因：单线程服务器处理一个客户端时无法 accept 其他客户端，后续客户端被阻塞。实现：主线程 `while(true) { Socket client = server.accept(); new Thread(() -> handleClient(client)).start(); }`。主线程循环 accept，每个客户端连接创建新线程处理，主线程立即回到 accept 等待下一个。每个客户端互不阻塞。局限性：每个客户端一个线程，连接数多时线程开销大，生产环境用线程池（ExecutorService）替代。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Socket">网络通信端点。客户端用 new Socket("IP", port) 连接服务器，获取输入输出流收发数据。代表一个 TCP 连接的一端。</GlossaryItem>
<GlossaryItem term="ServerSocket">服务器端监听端点。new ServerSocket(port) 绑定端口开始监听，accept() 阻塞等待客户端连接，返回通信用的 Socket。不直接收发数据，只负责接受连接。</GlossaryItem>
<GlossaryItem term="TCP">传输控制协议。面向连接、可靠传输（保证到达、按序、不丢失）、流式传输。三次握手建立连接，有确认/重传机制。开销大但可靠。适用 HTTP/FTP/聊天。</GlossaryItem>
<GlossaryItem term="UDP">用户数据报协议。无连接、不可靠（可能丢包/乱序）、数据报传输。无确认/重传，开销小。支持一对多/广播。适用 DNS/视频流/游戏/VoIP 等低延迟场景。</GlossaryItem>
<GlossaryItem term="多线程服务器">主线程循环 accept，每个客户端连接交给独立工作线程处理，实现并发服务。避免单线程处理一个客户端时阻塞其他客户端。生产环境用线程池替代手动 new Thread。</GlossaryItem>
</Glossary>
