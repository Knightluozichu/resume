## 为什么“第13章 风险行为：异常处理”必须从可运行证据开始

把失败建模为异常对象，沿调用栈明确抛出、捕获、排序、清理和传播责任。本页属于正式单元，目标不是复制原书正文、插图或趣味题，而是依照 O'Reilly 官方第3版完整目录，把核心标题重构为预测、代码、对象图、失败注入和验收工件。正式节点共21个，最终产物是异常分类表、控制流轨迹与 JavaSound 失败注入测试。

Java 程序同时存在源代码、编译期类型、字节码、运行时对象、调用栈、线程和外部资源七种观察面。只看最终输出，可能把引用别名、异常传播、惰性求值或竞态隐藏起来；只背语言规则，又无法证明自己能在真实程序中定位状态。因此每个结论都要同时回答“编译器允许什么”“运行时发生什么”“证据怎样复现”。

## 四个可复算指标

目录覆盖率只说明核心标题是否有落点：

$$
C_{toc}=\frac{N_{covered}}{N_{official}}
$$

验证覆盖必须同时覆盖正常、边界与失败状态：

$$
C_{evidence}=\frac{N_{observed\ state\times\ path}}{N_{planned\ state\times\ path}}
$$

一次实验的总成本包含编译、执行、观察和解释：

$$
T_{experiment}=T_{compile}+T_{run}+T_{observe}+T_{explain}
$$

回归风险按受影响合同、未覆盖路径与共享状态修正：

$$
R_{regression}=I_{contract}\times(1-C_{evidence})\times(1+S_{shared})
$$

这些式子用于暴露遗漏，不是能力证明。覆盖率达到100%仍可能只有表面复述；时间更短也可能是跳过验证。必须保留分项、输入和失败样本，不能只报告一个总数。

本单元的最小实现围绕“把失败建模为异常对象，沿调用栈明确抛出、捕获、排序、清理和传播责任”：

```java
static int parsePort(String raw) {
  try {
    int port = Integer.parseInt(raw);
    if (port < 1 || port > 65535) throw new IllegalArgumentException("range");
    return port;
  } catch (NumberFormatException cause) {
    throw new IllegalArgumentException("not a number", cause);
  }
}
```

## 三类高频误区

<Callout type="trap">
  **把编译成功当成合同正确。** 编译器只能验证类型和语法的一部分，无法证明业务不变量、资源关闭、输出顺序或线程安全。必须执行边界和失败路径。
</Callout>

<Callout type="trap">
  **把单次输出当成语言规则。** 哈希迭代、线程调度、网络分片和垃圾回收都可能改变观察。结论必须说明哪些顺序有合同保证，哪些只是本次实现现象。
</Callout>

<Callout type="trap">
  **成功样本替代最小反例。** 捕获 Exception 后吞掉上下文，或用 finally/TWR 不当掩盖原始失败。至少加入空输入、极值、重复调用、失败恢复和并发/关闭条件中的适用项，明确结论边界。
</Callout>
