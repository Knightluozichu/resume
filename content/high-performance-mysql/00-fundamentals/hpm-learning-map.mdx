## 知识体系全景

<HpmLearningMapDiagram />

《高性能MySQL》以"让MySQL跑得快、撑得住、稳得住"为主线，系统讲解MySQL的性能优化、扩展与运维。全书分架构基础篇、性能优化篇、扩展高可用篇、运维保障篇四个篇章，覆盖从存储引擎原理到索引查询优化、从复制分片到监控诊断的完整链路。

## 两条核心主线

### 主线一：性能提升能力

```
// 从单机怎么跑得快的递进路径
// 架构理解
//   └── 连接层/SQL层/存储引擎层
//   └── InnoDB：事务/行锁/MVCC/聚簇索引
// 索引设计
//   └── B+树结构：矮胖平衡/叶子链表
//   └── 聚簇 vs 二级 → 覆盖索引/最左前缀
// 查询优化
//   └── EXPLAIN：type/key/rows/Extra
//   └── 访问类型：const → ref → range → ALL
// Schema设计
//   └── 数据类型：最小够用/整数主键
//   └── 范式 vs 反范式/缓存汇总表
//
// 核心：懂引擎 → 会建索引 → 会看执行计划 → 会设计表
```

### 主线二：可靠扩展能力

```
// 从系统怎么撑得住、稳得住的递进路径
// 复制
//   └── binlog 事件回放：主库写/从库回放
//   └── GTID/半同步/组复制
// 扩展高可用
//   └── 读写分离：读扩展
//   └── 分片：写扩展/故障切换/RPO/RTO
// OS与硬件调优
//   └── CPU/内存/磁盘/网络
//   └── 缓冲池/刷盘策略/IO调度
// 监控与诊断
//   └── 信息源：SHOW/Performance Schema/慢日志
//   └── 方法：自顶向下/等待事件分析
//
// 核心：能复制 → 能分片 → 能调系统 → 能诊断
```

<Callout type="info" title="核心认知">
全书两条主线在「Schema+复制」与「OS+监控」处交汇——Schema设计决定数据怎么分布（影响复制和分片策略），OS调优和监控决定了运行质量（性能瓶颈最终落在硬件资源与诊断能力上）。理解这些交汇点，才能从"会用MySQL"升级到"驾驭高性能MySQL"。
</Callout>

**问题 1**：全书分为哪几个篇章？各自的核心内容和递进逻辑是什么？

<Answer>
全书分四个篇章：架构基础篇——学习地图（知识体系）、MySQL架构（连接/SQL/存储引擎/InnoDB事务锁）；性能优化篇——索引设计（B+树/聚簇/覆盖/最左前缀）、查询优化（EXPLAIN/执行计划/访问类型）、Schema设计（数据类型/范式反范式/缓存汇总表）；扩展高可用篇——复制（binlog/主从/GTID/拓扑）、扩展与高可用（读写分离/分片/故障切换/RPO/RTO）；运维保障篇——OS与硬件调优（CPU/内存/磁盘/缓冲池/刷盘策略）、监控与诊断（Performance Schema/慢日志/自顶向下分析）。递进逻辑：从懂架构到会优化到能扩展到稳运维。
</Answer>

**问题 2**：贯穿全书的两条核心主线是什么？它们在哪些章节交汇？

<Answer>
主线一性能提升能力：架构 → 索引 → 查询 → Schema，解决"单机查询怎么跑得快"。主线二可靠扩展能力：复制 → 扩展高可用 → OS调优 → 监控诊断，解决"系统怎么撑得住、稳得住"。两条主线在"Schema+复制"（Schema设计决定数据分布，影响复制和分片策略）与"OS+监控"（OS调优和监控决定运行质量，性能瓶颈落在硬件资源与诊断能力）处交汇。
</Answer>

**问题 3**：为什么学习高性能MySQL要遵循"懂架构→会优化→能扩展→稳运维"的顺序？

<Answer>
顺序依据：懂架构——理解MySQL分层和InnoDB引擎，建立内部运行认知；会优化——掌握索引、查询执行计划、Schema设计，知道查询如何高效执行；能扩展——理解复制和分片，知道系统如何横向扩展与容灾；稳运维——掌握OS调优和监控诊断，保证系统稳定运行。跳过基础的风险：①不懂架构，无法理解索引和事务的实现；②不会优化，单机性能是扩展的天花板；③不懂复制，无法正确扩展和高可用；④不会监控，出问题无法定位。每一步都是下一步的前提。
</Answer>

**问题 4**：高性能MySQL的四个要素是什么？它们如何构成完整能力？

<Answer>
四要素：①架构理解——分层模型与存储引擎（连接/SQL/存储引擎层、InnoDB事务锁MVCC），回答"MySQL内部怎么运作"；②性能优化——索引/查询/Schema（B+树/EXPLAIN/数据类型/范式），回答"单机怎么跑得快"；③扩展高可用——复制/分片/切换（binlog/读写分离/故障切换），回答"怎么撑得住不宕机"；④运维保障——OS调优/监控诊断（缓冲池/Performance Schema/慢日志），回答"怎么稳得住、出问题怎么查"。四要素层层支撑：架构是基础，优化是核心，扩展是规模，运维是稳定。
</Answer>
