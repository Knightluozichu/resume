## 直觉引入

把 CPU 想象成一个厨房。运算器（ALU）是厨师——负责切菜炒菜（算术和逻辑运算）；控制器（CU）是服务员——负责看菜单（取指令）、理解菜单（译码）、指挥厨师做菜（产生控制信号）；寄存器是厨师手边的料理台——放着正在处理的食材（操作数），伸手就拿到；时钟是节拍器——滴答滴答控制每一步的节奏。一条指令就像一份订单：服务员取订单→理解订单→厨师做菜→把菜放回料理台，循环往复，一道道菜就做出来了。

## CPU 的四大组成

<Term def="CPU（中央处理器）是由运算器（ALU）、控制器（CU）、寄存器组和时钟组成的集成电路芯片，通过执行指令周期循环来运行程序。">CPU</Term>由四大部分组成。**运算器（ALU）** 执行算术运算（加减乘除）和逻辑运算（与或非/比较），是「做计算」的核心部件。**控制器（CU）** 从内存取指令、解码指令含义、产生控制信号协调 ALU/寄存器/总线，是「指挥官」。**寄存器组** 是 CPU 内部的超高速存储：程序计数器（PC）存下一条指令地址、指令寄存器（IR）存当前指令、通用寄存器（如 AX/BX/CX）存操作数。**时钟** 产生固定频率的节拍信号，驱动 CPU 一步步执行。四者协作完成指令执行——运算器管算、控制器管指挥、寄存器管暂存、时钟管节奏。

## 指令周期

CPU 执行一条指令经过四个阶段，称为**指令周期**（fetch-decode-execute）。①**取指（Fetch）**：控制器把 PC 中的地址送到地址总线，从内存读出指令存入指令寄存器 IR，PC 自动加 1 指向下一条。②**译码（Decode）**：控制器解析 IR 中的指令，确定操作码（做什么运算）和操作数（对什么数据），产生对应的控制信号。③**执行（Execute）**：根据译码结果，ALU 做运算或访存读写数据。④**写回（Write-back）**：把执行结果写回目标寄存器或内存。一条指令执行完回到取指阶段开始下一条，循环往复直到程序结束。这就是 CPU 「跑」程序的本质。

## 流水线

**流水线（Pipeline）** 把指令执行拆成多个阶段（如取指→译码→执行→访存→写回），让多条指令的不同阶段同时进行。如同工厂流水线：第 1 条指令在执行时，第 2 条在译码，第 3 条在取指。理想情况下 5 级流水线可达到 5 倍吞吐量。代价是**流水线冒险**：①数据冒险——后一条指令依赖前一条的结果；②控制冒险——分支跳转改变指令流；③结构冒险——多条指令争用同一硬件。需要用转发（forwarding）、分支预测等机制解决。

## 寄存器 vs 内存

寄存器是 CPU 内部存储，访问速度约 0-1 个时钟周期；内存（DRAM）在 CPU 外部，通过总线访问，速度约 100-300 个周期，慢 100 倍以上。CPU 不能直接用内存当寄存器，因为速度差距太大（每条指令都要等几百周期，流水线无法工作）且指令编码会膨胀（寄存器编号只需几位，内存地址需要 32/64 位）。所以 CPU 先把数据从内存加载到寄存器，在寄存器上运算，再写回内存。

## 常见误区

<Callout type="trap">
**误区：CPU 主频越高电脑越快。** 主频只是 CPU 的节拍频率，不是性能的全部。一个 4GHz 的 CPU 如果每 4 个周期才能完成一条指令（IPC=0.25），实际吞吐量只有 1GHz/s；一个 3GHz 的 CPU 如果每个周期完成一条指令（IPC=1），吞吐量是 3GHz/s，反而更快。影响 CPU 性能的因素还包括：流水线深度、缓存大小、分支预测准确率、内存带宽等。只看主频就像只看汽车发动机转速不看挡位和车重。
</Callout>

<Exercises>
**问题 1**：指令周期的四个阶段是什么？每个阶段做什么？

<Answer>
①取指（Fetch）——控制器把 PC 中的地址送到地址总线，从内存读出指令存入指令寄存器 IR，PC 自动加 1；②译码（Decode）——控制器解析 IR 中的指令，确定操作码和操作数，产生控制信号；③执行（Execute）——根据译码结果，ALU 做运算或访存读写数据；④写回（Write-back）——把执行结果写回目标寄存器或内存。一条指令执行完回到取指阶段开始下一条，循环往复直到程序结束。
</Answer>

**问题 2**：什么是流水线？它如何提升性能？有什么代价？

<Answer>
流水线把指令执行拆成多个阶段，让多条指令的不同阶段同时进行。理想情况下 5 级流水线可达 5 倍吞吐量。代价是流水线冒险：数据冒险（后一条指令依赖前一条结果）、控制冒险（分支跳转改变指令流）、结构冒险（多条指令争用同一硬件）。需要用转发、分支预测、双端口内存等机制解决。
</Answer>
</Exercises>
