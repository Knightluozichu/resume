## 直觉引入

计算机只认识 0 和 1，但你要表示的不仅仅是正整数——还有负数、小数、文字、颜色、声音。一切信息都必须编码成二进制。补码让负数和减法统一成加法；IEEE 754 用科学计数法表示小数但引入了精度问题；ASCII 只能表示英文，Unicode 覆盖全世界所有字符，UTF-8 让 Unicode 高效存储。理解这些编码方式，就理解了计算机如何「表达」世界。

## 补码

<Term def="补码是一种用二进制表示有符号整数的方法：正数直接表示，负数取反加 1。它统一了加减法（A-B = A+(-B)），消除了正负零问题，且表示范围比原码多一个负数。">补码</Term>是计算机表示有符号整数的方法。正数的补码就是其二进制表示，最高位为 0；负数的补码是其绝对值取反加 1，最高位为 1。如 8 位下 +5 = 00000101，-5 = 11111011。用补码的原因：①统一加减法——A-B = A+(-B)，CPU 不需要减法电路；②没有正负零问题；③表示范围多一个（8 位补码 -128~+127）。

## IEEE 754 浮点数

**浮点数**用二进制科学计数法表示：符号位 + 指数位（阶码）+ 尾数位。32 位单精度：1 位符号 + 8 位指数（偏移 127）+ 23 位尾数。精度问题的根源：①十进制小数不一定能精确表示为二进制——如 0.1 在二进制中是无限循环；②有限的尾数位数无法表示所有实数——23 位尾数约 7 位十进制精度。所以 0.1 + 0.2 ≠ 0.3。

## 字符编码

**ASCII** 用 7 位（128 个码位）表示英文字母和符号。**Unicode** 为每个字符分配唯一码点（如「中」= U+4E2D），覆盖 14 万+ 字符。**UTF-8** 是 Unicode 的变长编码实现：ASCII 字符用 1 字节（兼容 ASCII），中文用 3 字节。UTF-8 兼容 ASCII、无字节序问题、节省空间，已成为 Web 事实标准。

## 整数溢出

**整数溢出**是运算结果超出范围。无符号溢出时回绕（255+1=0）；有符号补码溢出时符号反转（127+1=-128）。防范方法：运算前检查、使用大整数库、开启溢出检查、使用饱和运算。溢出是缓冲区溢出等安全漏洞的常见根源。

## 常见误区

<Callout type="trap">
**误区：0.1 + 0.2 应该等于 0.3，这是 bug。** 这不是 bug 而是浮点数的固有特性。0.1 在二进制中是无限循环小数（0.000110011...），23 位尾数截断后产生误差。这个误差在金融计算中不可接受，应该用定点数或十进制库（如 Java 的 BigDecimal、Python 的 decimal 模块）。这不是某个编程语言的缺陷——所有使用 IEEE 754 的语言都有这个问题。
</Callout>

<Exercises>
**问题 1**：什么是补码？为什么计算机用补码而不是原码来表示负数？

<Answer>
补码是表示有符号整数的方法：正数直接表示，负数取反加 1。用补码的原因：①统一加减法——A-B = A+(-B)，CPU 不需要减法电路；②没有正负零问题——原码中 +0 和 -0 是两个表示；③表示范围多一个——8 位补码 -128~+127，原码 -127~+127。
</Answer>

**问题 2**：ASCII、Unicode 和 UTF-8 的关系是什么？

<Answer>
ASCII 用 7 位表示 128 个英文字符。Unicode 为全世界所有字符分配唯一码点，但不规定存储方式。UTF-8 是 Unicode 的变长编码实现：ASCII 字符用 1 字节且完全兼容 ASCII，中文用 3 字节。UTF-8 兼容 ASCII、无字节序问题、节省空间，是 Web 事实标准。
</Answer>
</Exercises>
