## 核心机制深挖

程序流由顺序、条件分支和循环组合而成；流程图把控制状态外显，结构化设计限制任意跳转，中断和事件驱动则在明确入口与返回条件下改变正常顺序。 本页统一登记六类证据：**输入与编码、当前状态、转换规则、接口所有者、首个失败、恢复结果**。硬件页观察引脚和寄存器，程序页观察控制流与数据结构，网络页观察逐层地址和消息，系统页观察阶段文档与运营状态；对象不同，证据方法一致。

本页签发不变量是：**任一执行路径都由明确条件选择，循环有可达终止条件；中断或事件处理保存并恢复必要上下文，不让异步入口破坏主流程状态。**。先预测再运行能迫使学习者明确因果；正常样本证明基本路径，边界样本暴露容量和时序，失败样本确定责任边界，恢复样本证明系统可以回到受控状态。

## 状态与失败矩阵

| 对象       | 正常状态       | 常见边界               | 失败证据           | 恢复条件       |
| ---------- | -------------- | ---------------------- | ------------------ | -------------- |
| 输入与编码 | 类型和范围明确 | 空值、最大值、非法字节 | 原始输入与解析位置 | 拒绝或规范化   |
| 运行与存储 | 状态转换可追踪 | 容量、时序、并发       | 首个错误状态       | 回到已知快照   |
| 接口与网络 | 地址和协议一致 | 丢包、乱序、超时       | 分层日志与消息     | 重试不破坏结果 |
| 系统与运营 | 文档和责任明确 | 依赖故障、节点失效     | 告警、切换与影响   | 业务结果恢复   |
