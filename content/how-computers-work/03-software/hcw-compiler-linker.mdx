## 直觉引入

你写了一段 C 代码 `printf("Hello")`，但 CPU 不认识 printf 这个词。从源代码到可执行文件要经过四个阶段：预处理把 `#include` 展开成几千行代码；编译把 C 代码翻译成汇编；汇编把汇编翻译成机器码（目标文件）；链接把多个目标文件和库拼在一起，修正地址。每一步都在做不同层次的翻译和拼装。

## 编译四阶段

C/C++ 从源代码到可执行文件分四步。①**预处理**——处理 # 开头的指令，展开宏（#define）、包含头文件（#include）、条件编译（#ifdef），输出仍是 C 代码。②**编译**——词法分析、语法分析、语义分析、中间代码生成和优化，输出汇编代码（.s）。③**汇编**——汇编代码翻译成机器码，生成目标文件（.o），此时函数地址尚未最终确定。④**链接**——多个目标文件和库合并，解析符号引用，修正地址，生成可执行文件。

## 编译器 vs 解释器

**编译器**把整个源代码提前翻译成机器码，运行时直接执行。优点：运行快、可全局优化。缺点：编译耗时、平台相关。代表：C/C++/Rust。**解释器**逐行读取源代码即时执行。优点：跨平台、调试方便。缺点：运行慢。代表：Python/Ruby。现代语言常混合：Java 先编译成字节码再由 JVM 解释/JIT；JavaScript 由 V8 先解释再 JIT 热点编译。

## 链接器

<Term def="链接器把多个目标文件（.o）和库文件合并成可执行文件，完成符号解析（引用与定义配对）和地址重定位（修正相对地址为绝对地址）。">链接器</Term>完成两件事：①**符号解析**——每个目标文件有导出符号表和未解析符号表，链接器把「引用」和「定义」配对。找不到定义报「undefined reference」，找到多个报「multiple definition」。②**地址重定位**——编译器生成目标文件时地址从 0 开始（相对地址），链接器确定最终位置后修正所有相对地址为绝对地址。

## 静态 vs 动态链接

**静态链接**——链接时把库代码复制到可执行文件中。优点：自包含、启动快。缺点：体积大、多程序各自嵌入浪费内存、库更新需重编译。**动态链接**——链接时只记录符号信息，运行时由动态链接器加载 .so/.dll。优点：体积小、共享内存、库更新只换文件。缺点：运行时依赖、启动略慢、版本兼容性需管理。

## 常见误区

<Callout type="trap">
**误区：「undefined reference to xxx」是编译错误。** 这其实是链接错误——编译阶段已经成功（语法没问题），但在链接阶段找不到某个函数的定义。常见原因：①忘了链接库（如用了 pthread 但没加 -lpthread）；②函数声明了但没实现；③C/C++ 混编时 extern "C" 没加导致名称修饰不匹配。区分编译错误和链接错误很重要——前者是语法问题，后者是符号找不到。
</Callout>

<Exercises>
**问题 1**：编译的四个阶段是什么？每个阶段做什么？

<Answer>
①预处理——处理 # 指令，展开宏/包含头文件/条件编译，输出 C 代码；②编译——词法/语法/语义分析+优化，输出汇编代码（.s）；③汇编——汇编代码翻译成机器码，生成目标文件（.o）；④链接——多目标文件和库合并，符号解析+地址重定位，生成可执行文件。
</Answer>

**问题 2**：静态链接和动态链接有什么区别？

<Answer>
静态链接——链接时把库代码复制到可执行文件。优点：自包含、启动快。缺点：体积大、浪费内存、库更新需重编译。动态链接——运行时加载 .so/.dll。优点：体积小、共享内存、库更新只换文件。缺点：运行时依赖、启动略慢、版本兼容需管理（DLL Hell）。
</Answer>
</Exercises>

<GlossaryItem term="链接器">把多个目标文件和库合并成可执行文件的工具。完成符号解析（引用与定义配对）和地址重定位（相对地址修正为绝对地址）。</GlossaryItem>
<GlossaryItem term="动态链接">运行时由动态链接器加载共享库（.so/.dll）并完成符号绑定。相比静态链接体积小、可共享内存，但运行时依赖库存在。</GlossaryItem>
