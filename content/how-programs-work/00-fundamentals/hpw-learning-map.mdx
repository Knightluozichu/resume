## 直觉引入

把一个程序想象成一支巡回演出的剧团。剧本是源代码，但剧本本身不会自己演——你得先把剧本翻成演员能懂的动作（编译成机器指令），给演员安排好舞台站位和道具（内存布局与指针），演出时要有导演调度谁先上场谁退场（进程调度），演员需要用剧场设备时要向后台申请（系统调用），不同剧目共用同一套布景省得反复搬运（动态链接），演出结束后还要有人打扫舞台回收道具（垃圾回收）。本书回答的就是这些「从源代码到运行中的程序」的运行时原理问题。

## 四阶段递进

<Term def="程序的运行时是以内存为舞台、以机器指令为动作、以操作系统为调度者、以运行时系统为后勤的动态执行体系。">程序运行时</Term>的学习可以拆成四个递进阶段。**内存与执行基础**包括内存基础、指针原理、机器指令和栈与堆——它们解决「数据存在哪里」「地址怎么寻址」「CPU 怎么执行」「内存怎么分配」，是所有运行时行为的物理基底。**操作系统交互**包括进程调度和系统调用——它们决定「程序怎么被调度执行」和「程序怎么请求内核服务」。**运行时高级机制**包括动态链接和垃圾回收——它们解决「代码怎么共享复用」和「内存怎么自动回收」。**总复习**串联全部知识点。

```text
// 一次「从源代码到运行中的进程」的完整程序运行时旅程
源代码 hello.c 经编译链接变成可执行文件:
  // 1. 内存层：程序加载进内存，建立代码段/数据段/栈/堆布局
  //    指针是地址，机器指令驱动 CPU 执行（第 2-5 章内存与执行基础）

  // 2. 执行层：函数调用在栈上压入栈帧，动态数据在堆上分配
  //    栈帧记录返回地址和局部变量（第 4-5 章机器指令与栈堆）

  // 3. 系统层：操作系统为程序创建进程，按调度算法分配 CPU 时间
  //    程序通过系统调用请求内核服务（第 6-7 章进程调度与系统调用）

  // 4. 运行时层：动态链接共享库代码，垃圾回收器自动回收堆内存
  //    程序运行期间按需加载库、回收无用对象（第 8-9 章动态链接与 GC）

  // 5. 输出：进程完成任务，操作系统回收资源，程序「跑完」
```

## 常见误区

<Callout type="trap">
**误区：会写代码就等于懂程序怎么跑。** 写代码只是描述「程序该做什么」——声明变量、写循环、调函数，这些照语法就能写。真正懂运行时的人能解释：为什么程序会段错误（指针越界/野指针）、为什么会内存泄漏（堆分配不释放）、为什么多线程会死锁（调度竞争）、为什么动态库能节省内存（共享映射）、为什么有 GC 还会 OOM（回收不及时/引用未断）。把运行时当黑盒的人遇到崩溃只能重启；懂底层的人能定位根因、写出安全高效的代码、做性能级优化。
</Callout>

<Exercises>
**问题 1**：全书四阶段是什么？为什么是这个顺序？

<Answer>
内存与执行基础（内存基础/指针原理/机器指令/栈与堆）→ 操作系统交互（进程调度/系统调用）→ 运行时高级机制（动态链接/垃圾回收）→ 总复习。顺序由依赖关系决定：上层依赖下层。没有内存布局就没有数据存放；没有指针就没有地址寻址；没有机器指令就没有执行动作；没有栈与堆就没有函数调用和动态分配。先有「能存」，再有「能寻址」，然后「能执行」，接着「能分配」，再「能调度管理」，最后「能共享回收」。
</Answer>

**问题 2**：用「从源代码到运行中的进程」的完整旅程描述全书主线。

<Answer>
源代码编译链接成可执行文件：①内存层——程序加载进内存，建立代码段/数据段/栈/堆布局，指针是地址，机器指令驱动 CPU 执行（第 2-5 章）；②执行层——函数调用在栈上压入栈帧，动态数据在堆上分配（第 4-5 章机器指令与栈堆）；③系统层——操作系统为程序创建进程，按调度算法分配 CPU 时间，程序通过系统调用请求内核服务（第 6-7 章进程调度与系统调用）；④运行时层——动态链接共享库代码，垃圾回收器自动回收堆内存（第 8-9 章动态链接与 GC）；⑤输出——进程完成任务，操作系统回收资源，程序「跑完」。一次运行，四层全部参与。
</Answer>
</Exercises>

<GlossaryItem term="四阶段递进">内存与执行基础（内存/指针/指令/栈堆）→ 操作系统交互（进程调度/系统调用）→ 运行时高级机制（动态链接/垃圾回收）→ 总复习。每层解决前一层的遗留问题：内存层提供存储能力，执行层补动作手段，系统层补调度框架，运行时层补共享与回收机制。</GlossaryItem>
