## 直觉引入

把 CPU 想象成一个只会听极简口令的执行者。你说「把 5 号柜子的东西搬到 3 号柜子」「把 3 号和 4 号柜子的数相加放回 3 号」，它就照做。这些口令就是**机器指令**——每条指令就是一个「操作码 + 操作数」的二进制编码。你写的 C 代码 `c = a + b`，编译器会翻成好几条这样的口令：从内存读 a 到寄存器、读 b 到寄存器、加法、把结果写回内存的 c。CPU 不懂 C，不懂循环，不懂函数——它只会一条一条地执行机器指令。

## 指令的组成

<Term def="机器指令是 CPU 能直接执行的最基本操作单位，由操作码（做什么）和操作数（对谁做）组成，以二进制编码存储在内存的代码段。">机器指令</Term>由两部分组成。**操作码（Opcode）** 告诉 CPU 做什么操作——加法、减法、读内存、写内存、跳转、比较。**操作数（Operand）** 指明操作的对象——可以是寄存器编号、内存地址或立即数（直接写在指令里的常数）。例如 `ADD EAX, 5` 的操作码是 ADD，操作数是寄存器 EAX 和立即数 5，意思是「把 EAX 的值加 5 存回 EAX」。不同指令长度不同（x86 是变长指令，1-15 字节；ARM 是定长 4 字节），但都遵循「操作码在前、操作数在后」的编码规则。

## 寄存器与运算

CPU 不能直接对内存里的两个数做运算——必须先把它们加载到**寄存器**，在寄存器上运算，再把结果写回内存。一条 `c = a + b` 大致编译成：`MOV EAX, [a]`（把 a 从内存读到 EAX）、`ADD EAX, [b]`（把 b 加到 EAX）、`MOV [c], EAX`（把 EAX 写回 c）。为什么不让 CPU 直接算内存里的数？因为内存访问比寄存器慢 100 倍以上，且 ALU 的输入端直接连寄存器。寄存器是 CPU 的「手」，要算什么先拿在手里。通用寄存器（如 EAX/EBX/ECX/EDX）存操作数，程序计数器（PC/EIP）存下一条指令地址，栈指针（ESP）存栈顶地址，基址指针（EBP）存当前栈帧基址。

## 寻址方式

**寻址方式**指指令如何找到操作数。常见有：①**立即寻址**——操作数直接在指令里，如 `MOV EAX, 5`；②**寄存器寻址**——操作数在寄存器里，如 `MOV EAX, EBX`；③**直接寻址**——操作数在内存，地址直接写在指令里，如 `MOV EAX, [0x1000]`；④**寄存器间接寻址**——地址存在寄存器里，如 `MOV EAX, [EBX]`（EBX 存的是地址），这是指针的底层实现；⑤**基址+偏移寻址**——如 `MOV EAX, [EBP+8]`，访问栈帧中距 EBP 偏移 8 的局部变量或参数。指针、数组、结构体成员访问，底层都映射到这些寻址方式。

## 跳转与控制流

CPU 默认按地址顺序逐条执行指令（PC 自动递增）。改变执行顺序靠**跳转指令**：①**无条件跳转（JMP）**——直接把 PC 设为目标地址，对应 C 的 `goto`；②**条件跳转（JE/JNE/JG 等）**——根据标志寄存器（上条指令运算结果设的零标志/符号标志等）决定是否跳转，对应 `if`/`while`/`for`。例如 `if (a > b) c = 1;` 编译成：比较 a 和 b（CMP，设标志位）、条件跳转（若不大于则跳过）、赋值 c=1。函数调用（CALL）本质也是跳转——把返回地址压栈再跳到函数入口，函数末尾的 RET 从栈弹出返回地址跳回去。循环、分支、函数调用，底层全是跳转指令的组合。

## 常见误区

<Callout type="trap">
**误区：高级语言的语句和机器指令是一一对应的。** 一条 C 语句通常对应多条机器指令。`c = a + b` 要三四条（读 a、读 b、加、写 c）；`arr[i] = x` 更多（算地址、读 x、写内存、可能还有边界检查）；一个函数调用涉及压参数、压返回地址、跳转、建栈帧、恢复栈帧、返回一堆指令。这就是为什么同样的逻辑，不同写法性能差很多——少一次内存访问就少 100 个周期。理解「高级语句 → 多条机器指令」的展开，才能写出对 CPU 友好的代码，也才能看懂性能剖析工具的输出。
</Callout>

<Exercises>
**问题 1**：机器指令由哪两部分组成？为什么 `c = a + b` 要编译成多条指令？

<Answer>
机器指令由操作码（做什么）和操作数（对谁做）组成。`c = a + b` 要编译成多条指令，因为 CPU 不能直接对内存里的两个数做运算——必须先把 a 从内存读到寄存器（MOV EAX,[a]）、把 b 加到寄存器（ADD EAX,[b]）、再把结果写回内存的 c（MOV [c],EAX）。内存访问比寄存器慢 100 倍以上，ALU 输入端直接连寄存器，所以数据要先入寄存器才能运算。
</Answer>

**问题 2**：常见的寻址方式有哪些？指针的底层实现对应哪一种？

<Answer>
常见寻址方式：①立即寻址——操作数直接在指令里（MOV EAX,5）；②寄存器寻址——操作数在寄存器（MOV EAX,EBX）；③直接寻址——操作数在内存，地址写在指令里（MOV EAX,[0x1000]）；④寄存器间接寻址——地址存在寄存器里（MOV EAX,[EBX]）；⑤基址+偏移寻址——如 MOV EAX,[EBP+8] 访问栈帧变量。指针的底层实现对应寄存器间接寻址——指针变量存的是地址，把这个地址放进寄存器，再用 [寄存器] 间接访问它指向的内存。数组下标和结构体成员访问则对应基址+偏移寻址。
</Answer>
