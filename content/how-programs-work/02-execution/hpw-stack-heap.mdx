## 直觉引入

把内存的中段想象成两支施工队从两头往中间盖楼。栈是「快速拼装队」——从高楼顶往下搭，每来一个函数调用就快速拼一层（栈帧），函数返回就拆掉这层，快进快出，但只能按顺序拆（后进先出）。堆是「自由施工队」——从低处往上盖，谁要一块地就划一块（malloc），用完要主动归还（free），不归还就一直占着。栈快但死板（大小固定、必须后进先出）；堆灵活但费心（要手动管理、容易碎片化）。程序运行时，函数调用靠栈，动态数据靠堆。

## 栈与函数调用

<Term def="栈是用于管理函数调用的内存区域，采用后进先出原则，每次函数调用压入一个栈帧，函数返回时弹出。">栈</Term>的核心机制是**栈帧（Stack Frame）**。函数被调用时，CPU 在栈顶压入一个栈帧，包含：①返回地址（函数执行完跳回哪里）；②调用方栈帧的基址指针（用于恢复）；③参数（部分架构用寄存器传参，溢出的入栈）；④局部变量。函数返回时弹出整个栈帧，栈指针恢复到调用前，程序靠返回地址跳回调用方。因为栈帧严格「后进先出」，函数返回时局部变量自动销毁——这就是为什么不能返回局部变量的地址（悬空指针）。递归太深会层层压栈直到栈耗尽，这就是**栈溢出**。

## 堆与动态分配

<Term def="堆是用于运行时动态分配的内存区域，由程序员通过 malloc/new 申请、free/delete 释放，生命周期不受函数调用约束。">堆</Term>解决的是「编译期不知道要多少内存」的问题。`int *arr = malloc(n * sizeof(int))` 在堆上申请 n 个 int 的连续空间，返回这块空间的起始地址；用完要 `free(arr)` 归还。堆的分配由内存分配器（如 glibc 的 ptmalloc）管理，它维护一个空闲块链表，申请时找一块够大的切出来，释放时合并相邻空闲块。堆的优点是灵活——大小运行时决定、生命周期跨函数；代价是①要手动管理（忘记 free = 内存泄漏，释放两次 = 崩溃）；②分配/释放有开销（要查空闲链表）；③容易产生**碎片**（频繁分配释放后，空闲内存被切成零散小块，虽有总量却无法满足大块申请）。

## 栈 vs 堆

| 维度 | 栈 | 堆 |
|------|----|----|
| 分配方式 | 编译器自动（压栈） | 程序员手动（malloc/new） |
| 释放方式 | 函数返回自动弹出 | 手动（free/delete）或 GC |
| 速度 | 极快（移动栈指针） | 较慢（查空闲链表） |
| 大小 | 有限（默认 1-8MB） | 大（受物理内存限制） |
| 生命周期 | 随函数调用结束 | 跨函数，由释放决定 |
| 碎片 | 无（连续压弹出） | 有（频繁分配释放产生） |

经验法则：能用栈就用栈（局部变量、固定大小数组），只有运行时才知道大小或需要跨函数传递的数据才用堆。

## 内存泄漏与栈溢出

两类典型运行时故障：①**内存泄漏**——堆上申请的内存不再使用却没释放，进程持有的内存只增不减，长时间运行后耗尽内存崩溃。常见于循环里 malloc 却在循环外才 free、异常路径漏 free、数据结构里存了指针却没遍历释放。排查靠 Valgrind/AddressSanitizer。②**栈溢出**——栈用超了限额（默认通常 8MB），典型是无限递归没有终止条件，或局部变量太大（如 `int arr[10000000]`）。栈溢出直接段错误。防范：递归要有终止条件和合理深度，大数组改用堆分配。

## 常见误区

<Callout type="trap">
**误区：栈上的数据比堆上的快，所以全用栈。** 栈的「快」指的是分配/释放快（只需移动栈指针，不查链表），不是「访问栈上的数据更快」。访问速度取决于数据是否在 CPU 缓存里，与在栈还是堆无关——栈数据因局部性好常在缓存，但堆上连续访问的数据同样能享受缓存。全用栈的问题：①栈大小有限（8MB），大数组直接溢出；②栈数据随函数返回销毁，跨函数传递的数据无法用栈；③栈大小编译期要确定，运行时才知道大小的数据（如读入的变长输入）必须用堆。「能用栈就用栈」是局部、定长数据的优化原则，不是全局法则。
</Callout>

<Exercises>
**问题 1**：函数调用时栈帧包含哪些内容？为什么不能返回局部变量的地址？

<Answer>
栈帧包含：①返回地址（函数执行完跳回哪里）；②调用方栈帧的基址指针（用于恢复）；③参数（寄存器传参溢出的部分）；④局部变量。函数返回时整个栈帧被弹出，栈指针恢复到调用前。不能返回局部变量地址，因为局部变量在栈帧里，函数返回栈帧弹出后那块内存就被回收了（可能被下一个函数调用覆盖），再访问就是悬空指针，读到的是垃圾数据或触发崩溃。要返回数据应通过返回值、传出参数（指针）或在堆上分配。
</Answer>

**问题 2**：栈和堆在分配方式、速度、大小、生命周期上有什么区别？什么时候该用堆？

<Answer>
①分配方式——栈编译器自动压栈，堆程序员手动 malloc/new；②速度——栈极快（移动栈指针），堆较慢（查空闲链表）；③大小——栈有限（1-8MB），堆大（受物理内存限制）；④生命周期——栈随函数返回自动销毁，堆跨函数由释放决定。该用堆的情况：运行时才知道大小的数据（变长输入）、需要跨函数传递且生命周期超出函数的数据、非常大的数据（超过栈限额）。能用栈就用栈是局部定长数据的优化原则。
</Answer>

<Glossary>
<GlossaryItem term="栈帧">函数调用时压入栈的数据块，含返回地址、调用方基址指针、参数和局部变量。函数返回时弹出，局部变量自动销毁，因此不能返回局部变量地址。</GlossaryItem>
<GlossaryItem term="堆">运行时动态分配的内存区域，由 malloc/new 申请、free/delete 释放。灵活（大小运行时定、生命周期跨函数）但需手动管理，忘记释放导致内存泄漏。</GlossaryItem>
<GlossaryItem term="内存泄漏">堆上申请的内存不再使用却未释放，进程内存只增不减，长期运行后耗尽内存崩溃。排查靠 Valgrind/AddressSanitizer，防范靠严格配对 malloc/free 或使用智能指针/GC。</GlossaryItem>
</Glossary>
