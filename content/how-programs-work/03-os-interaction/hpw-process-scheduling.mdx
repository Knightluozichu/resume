## 直觉引入

把 CPU 想象成只有一个窗口的银行。程序是排在柜台的顾客，但只有一个柜员（单核）。柜员不可能真同时办两个业务，但他每个顾客办一小会儿就切到下一个，切得飞快（每秒上百次），每个顾客都觉得自己在被服务——这就是**并发**。操作系统是排号系统：决定下一个叫谁（调度）、记住每个顾客办到哪了（上下文）、顾客在等材料时先挂起叫别人（阻塞）。进程就是「一个正在跑的程序实例」，线程是「进程里的子任务，共享同一套资源」。

## 进程与线程

<Term def="进程是程序的一次执行实例，拥有独立的地址空间和资源；线程是进程内的执行单元，同一进程的线程共享地址空间。">进程</Term>是资源分配的基本单位——每个进程有独立的虚拟地址空间、文件描述符表、内核栈。创建进程（fork）要复制父进程的地址空间（写时复制优化），开销大。**线程**是 CPU 调度的基本单位——同一进程的多个线程共享代码段、数据段、堆、文件描述符，但各自有独立的栈和寄存器上下文。创建线程比创建进程轻得多（不复制地址空间），线程切换也比进程切换快（不用切换页表）。所以高并发服务器常用多线程而非多进程。代价是共享地址空间带来数据竞争——多个线程同时读写同一变量需要同步（锁/原子操作），搞不好就死锁或数据错乱。

## 进程状态与上下文切换

进程在生命周期中处于三种核心状态：①**就绪（Ready）**——具备运行条件，等 CPU；②**运行（Running）**——正在 CPU 上执行；③**阻塞（Blocked/Waiting）**——在等 I/O 或事件，即使有 CPU 也跑不了。状态转换：就绪→运行（被调度选中）、运行→就绪（时间片用完）、运行→阻塞（等 I/O/锁）、阻塞→就绪（I/O 完成/拿到锁）。**上下文切换**是调度器把当前运行进程的寄存器/PC/栈指针保存到它的进程控制块（PCB），再加载下一个进程的上下文到 CPU 的过程。切换有开销（保存恢复寄存器、可能失效缓存、切换页表），所以并非「线程越多越快」——太多线程会让切换开销压过实际工作。

## 调度算法

调度器决定就绪队列里下一个跑谁。常见算法：①**先来先服务（FCFS）**——按到达顺序排队，简单但短任务会被长任务拖住（护送效应）；②**最短作业优先（SJF）**——优先跑预计时间最短的，平均等待时间最优但无法预知时长且饿死长任务；③**时间片轮转（Round Robin）**——每个进程跑一个时间片（如 10ms）就切到下一个，公平且响应快，是分时系统的基础；④**优先级调度**——按优先级高低调度，可能饿死低优先级进程（需老化机制补偿）；⑤**多级反馈队列（MLFQ）**——综合前三者，多个就绪队列不同优先级，进程根据行为在队列间升降（CPU 密集型降级、I/O 密集型保持高优先级），现代操作系统多采用其变体。时间片大小的权衡：太大退化成 FCFS（响应慢），太小上下文切换开销占比过高。

## 并发与并行

**并发（Concurrency）** 是「多个任务在交替推进」（单核切换），**并行（Parallelism）** 是「多个任务在同一时刻真正同时执行」（多核各跑一个）。单核 CPU 只能并发不能并行；多核既能并发也能并行。并发带来了**竞态条件**——多个线程交错执行时，对共享变量的读-改-写不是原子的，结果依赖执行顺序。例如 `count++` 看似一条语句，实际是「读 count、加 1、写回」三步，两个线程同时做可能丢失一次更新。解决靠**同步机制**（互斥锁保证同一时刻只有一个线程进入临界区、原子操作让读-改-写不可分割）。并发编程的难点正在于执行顺序的不确定性——bug 难复现、难调试。

## 常见误区

<Callout type="trap">
**误区：线程越多程序越快。** 线程多只在「CPU 密集型任务且核数够」时提速——4 核跑 4 线程可能 4 倍速，但跑 100 线程不会更快，反而因上下文切换开销（保存恢复寄存器、缓存失效、页表切换）变慢。对 I/O 密集型任务，线程数略多于核数有利（一些线程阻塞等 I/O 时其他线程能跑），但过多同样徒增切换成本和内存占用（每个线程有独立栈）。真正的提速来自：减少锁竞争、提高缓存命中率、让线程数匹配硬件并行度。盲目开线程池而不考虑任务性质和资源争用，常常适得其反。
</Callout>

<Exercises>
**问题 1**：进程和线程有什么区别？为什么高并发服务器常用多线程而非多进程？

<Answer>
进程是资源分配的基本单位，拥有独立地址空间和资源；线程是 CPU 调度的基本单位，同一进程的线程共享代码段/数据段/堆/文件描述符，但各有独立栈和寄存器上下文。高并发服务器常用多线程因为：①创建线程比创建进程轻（不复制地址空间）；②线程切换比进程切换快（不用切换页表）；③线程间通信更方便（共享内存直接读写，而进程间要管道/消息队列/共享内存等 IPC）。代价是共享地址空间带来数据竞争，需要锁/原子操作等同步机制。
</Answer>

**问题 2**：进程的三种核心状态是什么？什么是上下文切换，为什么不是线程越多越快？

<Answer>
三种核心状态：①就绪（Ready）——具备运行条件等 CPU；②运行（Running）——正在 CPU 执行；③阻塞（Blocked）——等 I/O 或事件，有 CPU 也跑不了。上下文切换是调度器把当前进程的寄存器/PC/栈指针保存到 PCB，再加载下一进程的上下文到 CPU。不是线程越多越快，因为：①上下文切换有开销（保存恢复寄存器、缓存失效、页表切换），线程过多切换开销压过实际工作；②线程数超过核数时并行度受限，多出的线程只能并发切换；③线程间锁竞争和缓存失效随线程数增加而恶化。提速要靠减少锁竞争、提高缓存命中率、让线程数匹配硬件并行度。
</Answer>
