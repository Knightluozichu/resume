## 直觉引入

把操作系统想象成一家公司的管理层，普通员工（用户程序）不能直接去仓库搬东西（碰硬件），得填申请单交给仓库管理员（内核）代办。这个「申请单」就是**系统调用**。你写 `printf("hello")`，标准库最终会调用 `write` 系统调用，让内核把数据写到屏幕对应的设备；你 `fopen` 读文件，底层是 `open`/`read` 系统调用让内核去磁盘读。为什么不让程序直接读写硬件？因为如果任何程序都能直接碰磁盘、网卡，一个恶意或写错的程序就能搞垮整个系统。所以 CPU 设了特权级，普通程序跑在低特权，碰硬件必须「升级」请内核代劳。

## 用户态与内核态

<Term def="CPU 运行特权分为用户态（低特权，不能直接访问硬件和内核内存）和内核态（高特权，可访问一切），系统调用是二者之间的受控通道。">用户态/内核态</Term>是 CPU 硬件提供的保护机制。现代 CPU 有多个特权级（x86 有 ring 0-3），操作系统内核跑在 ring 0（最高权限），普通程序跑在 ring 3（最低权限）。用户态程序不能直接执行特权指令（如读写 I/O 端口、修改页表、关中断），也不能访问内核占用的内存区域——硬件会拦截并触发异常。这种隔离保证了一个程序崩溃或作恶不会搞垮整个系统。程序需要做特权操作（读写文件、网络通信、创建进程）时，唯一的合法途径就是**系统调用**——一条受控的「升级到内核态、执行内核代码、再降回用户态」的通道。

## 系统调用的机制

系统调用的执行流程：①用户程序把系统调用号（如 read=0、write=1）和参数放进寄存器；②执行一条特殊指令触发「陷入内核」——老式做法是软中断（`int 0x80`），现代 x86 用专用 `syscall` 指令，ARM 用 `svc`；③CPU 硬件自动切换到内核态（ring 0），跳到内核预设的系统调用入口；④内核查系统调用号找到对应处理函数，检查参数合法性后执行（读磁盘、写网卡等）；⑤执行完把返回值放进寄存器，切换回用户态，程序继续。整个过程有上下文切换开销（用户栈↔内核栈切换、寄存器保存恢复），所以系统调用比普通函数调用慢得多——这是为什么频繁系统调用会成为性能瓶颈，也是 `printf` 要带缓冲的原因。

## 常见系统调用

| 类别 | 系统调用 | 用途 |
|------|---------|------|
| 文件 I/O | open/read/write/close | 打开/读/写/关闭文件 |
| 进程管理 | fork/exec/wait/exit | 创建/替换/等待/退出进程 |
| 内存管理 | mmap/brk/munmap | 映射文件/调整堆/取消映射 |
| 网络 | socket/connect/bind/recv | 建套接字/连接/收发数据 |
| 信号 | kill/sigaction | 发送/注册信号处理 |

`fork` 创建当前进程的副本；`exec` 把当前进程的代码段替换成新程序（fork+exec 是启动新程序的标准组合）；`mmap` 把文件或设备映射进内存，让读写文件像读写内存一样（比 read/write 少一次内核↔用户拷贝）；`brk` 调整堆顶指针，是 malloc 向 OS 申请内存的底层手段。日常用的 C 库函数（printf/fopen/malloc）多数是对系统调用的封装和缓冲。

## 缓冲与系统调用

标准库的 `printf` 不会每次调用都直接 `write` 系统调用——它先把数据攒在用户态缓冲区，攒满或遇到换行/fflush 时才一次 `write`。因为系统调用有固定开销（上下文切换），写 1 字节和写 4096 字节的系统调用成本差不多。带缓冲让「写 1000 个字符」从 1000 次系统调用降到 1 次，性能差几个数量级。这也是为什么程序崩溃时未 fflush 的 printf 输出会丢失——数据还在用户态缓冲里没进内核。理解「库函数 = 缓冲 + 系统调用封装」，才能解释这些诡异现象。

## 常见误区

<Callout type="trap">
**误区：库函数和系统调用是一回事。** 库函数（如 printf、malloc、fopen）多数是对系统调用的封装，但二者层次不同：库函数在用户态执行，可带缓冲/重试/格式化；系统调用是陷入内核的特权操作。有些库函数不对应系统调用（如 strcpy/strlen 纯内存操作）；有些系统调用没有直接对应的库函数（如 mmap 要直接调或通过薄封装）。关键区别：系统调用有上下文切换开销，库函数（纯用户态部分）没有。所以 `strlen` 极快（不陷入内核），而 `write` 慢得多。性能优化的一个要点就是减少系统调用次数——用缓冲、批量、mmap 替代频繁的小系统调用。
</Callout>

<Exercises>
**问题 1**：为什么要有用户态和内核态的划分？系统调用在其中起什么作用？

<Answer>
用户态和内核态是 CPU 硬件提供的保护机制：内核跑在 ring 0 高特权，普通程序跑在 ring 3 低特权，用户态不能直接执行特权指令（读写 I/O、改页表、关中断）也不能访问内核内存——硬件会拦截触发异常。这保证了一个程序崩溃或作恶不会搞垮整个系统。系统调用的作用是二者之间唯一的受控通道：程序需要做特权操作（读写文件、网络、创建进程）时，通过系统调用陷入内核态、由内核代为执行、再返回用户态。没有系统调用，用户程序就无法合法地碰任何硬件资源。
</Answer>

**问题 2**：系统调用的执行流程是什么？为什么 printf 要带缓冲？

<Answer>
系统调用执行流程：①用户程序把系统调用号和参数放进寄存器；②执行 syscall/int 0x80 指令陷入内核；③CPU 硬件切换到内核态，跳到内核系统调用入口；④内核查调用号找到处理函数，检查参数后执行特权操作；⑤把返回值放进寄存器，切换回用户态。printf 带缓冲是因为系统调用有固定的上下文切换开销，写 1 字节和写 4096 字节成本差不多。printf 先把数据攒在用户态缓冲区，攒满或遇换行/fflush 才一次 write 系统调用，把「写 1000 字符」从 1000 次系统调用降到 1 次，性能差几个数量级。代价是程序崩溃时未 fflush 的输出会丢失。
</Answer>
