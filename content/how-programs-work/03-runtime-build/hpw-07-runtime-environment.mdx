## 核心机制深挖

程序依赖操作系统 API、CPU 指令集和设备抽象；源码可通过移植层、虚拟机或语言运行时跨环境，BIOS/固件与引导程序则在应用之前建立操作系统运行条件。 每次实验统一登记六类证据：**源码与输入、制品字节、机器状态、接口所有者、首个失败、恢复结果**。CPU页看寄存器和程序计数器，存储页看地址与页面，构建页看符号和映射，硬件页看寄存器、中断与DMA；观察对象不同，因果账本一致。

本页签发不变量是：**程序声明所需 API、指令集与运行时版本；跨环境方案明确被抽象的差异，启动链每一级都验证下一阶段身份。**。正常样本证明主路径，边界样本暴露字长和容量，失败样本确认责任层，恢复样本证明同一输入能回到受控结果。任何无法定位到首个状态分叉的成功都不是完整证据。

## 2015版语境与现代对照

原书基于32位x86、Windows、FreeBSD Port、Java虚拟机、DLL、BIOS、IN/OUT、DMA和C语言讲解。重构保留12章、1个附录、5个专栏及共118个公开目录条目；64位ABI、现代UEFI、容器或当代编译器只作为对照，不能替换原书问题身份。

现代系统扩大了地址和并行规模，却仍要解析符号、建立地址空间、遵守调用约定、跨越系统调用并协调设备。对照时必须写明原书行为、现代变化和仍然成立的不变量，避免把版本差异误判为原理消失。
