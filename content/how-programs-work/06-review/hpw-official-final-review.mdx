## 核心机制深挖

总复习把源代码经编译与链接变成本地代码，加载器建立地址空间，CPU按寄存器和栈执行，系统调用进入内核，设备通过中断或DMA返回数据，最终结果再被程序解释。 每次实验统一登记六类证据：**源码与输入、制品字节、机器状态、接口所有者、首个失败、恢复结果**。CPU页看寄存器和程序计数器，存储页看地址与页面，构建页看符号和映射，硬件页看寄存器、中断与DMA；观察对象不同，因果账本一致。

本页签发不变量是：**同一源码、工具链与环境得到可追溯制品；正常、边界、失败和恢复样本都能关联到首个偏离的指令、内存、接口或设备状态。**。正常样本证明主路径，边界样本暴露字长和容量，失败样本确认责任层，恢复样本证明同一输入能回到受控结果。任何无法定位到首个状态分叉的成功都不是完整证据。

## 2015版语境与现代对照

原书基于32位x86、Windows、FreeBSD Port、Java虚拟机、DLL、BIOS、IN/OUT、DMA和C语言讲解。重构保留12章、1个附录、5个专栏及共118个公开目录条目；64位ABI、现代UEFI、容器或当代编译器只作为对照，不能替换原书问题身份。

现代系统扩大了地址和并行规模，却仍要解析符号、建立地址空间、遵守调用约定、跨越系统调用并协调设备。对照时必须写明原书行为、现代变化和仍然成立的不变量，避免把版本差异误判为原理消失。

```text
freeze source, toolchain, input, and environment
predict bytes, registers, memory, symbols, or device state
change exactly one condition
stop at the first divergent boundary
remove the fault and replay the same input
verify artifact, state, output, and cleanup
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：源码正确就代表程序运行正确。**
  编译、链接、装载、ABI、内存和设备任一层都可能失败，必须追踪完整执行链。
</Callout>

<Callout type="trap">
  **误区二：用今天的平台术语覆盖原书目录。**
  现代工具可以做对照，但二进制、浮点误差、压缩、运行环境、汇编和硬件控制主线不能被删掉。
</Callout>
