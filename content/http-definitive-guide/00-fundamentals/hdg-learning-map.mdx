## HTTP 请求生命周期

一个完整的 HTTP 请求从客户端发起到收到响应，经历以下阶段：

```text
URL 解析 → DNS 查询 → TCP/TLS 连接 → 代理转发 → 缓存查询
    → 认证鉴权 → 内容协商 → 服务器处理 → 响应返回 → 连接关闭
```

<Callout type="info" title="为什么从报文开始学">

HTTP 的所有功能都通过报文实现：请求方法是报文的一部分，状态码在响应报文中，首部控制缓存/认证/协商/连接行为。先理解报文格式，后续章节的首部字段才有立足点。这也是本书从「报文与连接」开始而非从「历史背景」开始的原因。

</Callout>

## 推荐学习路径

```text
基础(报文/URL) → 基础设施(代理/缓存) → 安全(认证/HTTPS) → 高级(协商/托管) → 复习整合
     ↓                ↓                    ↓                   ↓                ↓
  请求/响应        代理/缓存             Basic/TLS           虚拟主机          端到端流程
  状态码           Cache-Control         证书验证             负载均衡          知识网络
```

## HTTP 核心设计原则

1. **无状态** — 每个请求独立，服务器不记忆历史请求，状态通过 Cookie 补充
2. **请求-响应** — 客户端发起请求，服务器返回响应，一问一答
3. **文本协议** — HTTP/1.x 报文是纯文本，可读可调试
4. **分层扩展** — 代理、网关、缓存等中间层可透明插入，不改动端系统

<Glossary>

<GlossaryItem term="HTTP（超文本传输协议）">
HTTP 是 Web 的核心应用层协议，基于 TCP，采用请求-响应模型。客户端发送请求（方法+URL+首部+体），服务器返回响应（状态码+首部+体）。HTTP 是无状态协议——每个请求独立处理，服务器不记录历史，状态通过 Cookie 维持。HTTP/1.1 默认持久连接，HTTP/2 引入多路复用，HTTP/3 基于 QUIC/UDP。本书覆盖 HTTP/1.1 的完整体系，是理解现代 Web 的基础。
</GlossaryItem>

<GlossaryItem term="四大知识域">
HTTP 权威指南的内容按递进关系分为四大知识域：①HTTP 基础（报文格式、连接管理、URL 资源定位）②中间基础设施（代理网关、缓存体系、内容协商转码）③安全与认证（Basic/Digest 认证、HTTPS/TLS 加密）④部署与整合（虚拟主机、重定向、负载均衡、全书知识串联）。每个域解决一个核心问题，域内章节有依赖关系，域间也有交叉（如缓存依赖代理、认证依赖 HTTPS）。
</GlossaryItem>

<GlossaryItem term="请求生命周期（Request Lifecycle）">
一个 HTTP 请求从发起到收到响应的完整过程：①URL 解析（提取 scheme/host/path）②DNS 查询（域名转 IP）③建立连接（TCP 握手 + TLS 握手）④代理转发（经正向/反向代理）⑤缓存查询（命中直接返回，未命中转发源服务器）⑥认证鉴权（Basic/Digest 验证身份）⑦内容协商（Accept 头选最佳表示）⑧服务器处理（虚拟主机路由 + 负载均衡 + 生成响应）⑨响应返回（经缓存/代理回传）⑩连接关闭（持久连接保持或释放）。
</GlossaryItem>

<GlossaryItem term="无状态协议（Stateless Protocol）">
HTTP 是无状态协议——服务器处理每个请求时不参考之前的请求，每个请求独立处理。这样设计简化了服务器实现、提高了可扩展性（任何服务器都能处理任何请求）。代价是状态维持需要额外机制：Cookie 在客户端存储状态，Session 在服务器端记录，Token（JWT）在无状态服务间传递认证信息。无状态是 REST 架构的核心约束之一。
</GlossaryItem>

</Glossary>

**问题 1：** HTTP 权威指南的四大知识域分别解决什么问题？它们之间有什么依赖关系？

<Answer>

四大知识域：①HTTP 基础——解决「报文怎么构造、资源怎么定位」，是所有后续章节的地基 ②中间基础设施——解决「中间层怎么转发/缓存/转换」，依赖基础域的报文格式和首部 ③安全与认证——解决「身份怎么验证、通信怎么加密」，认证首部建立在报文格式上，HTTPS 在连接层加密 ④部署与整合——解决「怎么部署、知识怎么串联」。依赖关系：基础 → 基础设施（代理转发需要理解报文）→ 安全（认证首部在报文中，加密在连接上）→ 部署（虚拟主机靠 Host 首部，负载均衡靠代理）。同时存在交叉：缓存依赖代理作为载体，Basic 认证依赖 HTTPS 保证安全。
</Answer>

**问题 2：** 描述一个 HTTPS 请求从发起到收到响应的完整生命周期，涉及本书哪些章节的知识？

<Answer>

①URL 解析——提取 scheme(https)、host、path（第 3 章 URL 与资源定位）②DNS 查询——域名解析为 IP 地址 ③TCP 连接 + TLS 握手——三次握手建立 TCP，然后 TLS 握手协商加密套件、验证证书、交换密钥（第 7 章 HTTPS 与 SSL/TLS）④构造请求报文——方法+URL+首部+体（第 2 章 HTTP 报文与连接）⑤代理转发——请求经正向/反向代理转发（第 4 章代理与网关）⑥缓存查询——代理/CDN 检查缓存命中（第 5 章缓存体系）⑦认证鉴权——Basic/Digest 验证客户端身份（第 6 章认证与安全）⑧内容协商——根据 Accept 头选择最佳表示（第 8 章内容协商与转码）⑨服务器处理——虚拟主机路由 + 负载均衡选后端（第 9 章 Web 托管与部署）⑩响应返回——经缓存/代理回传，持久连接保持或关闭（第 2 章连接管理）。
</Answer>
