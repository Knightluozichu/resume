## HTTP 报文结构

<HdgHttpMessagesDiagram />

HTTP 报文是纯文本格式，由三部分组成，以 CRLF（`\r\n`）分隔。

### 请求报文

```text
GET /api/users?page=1 HTTP/1.1        ← 起始行（方法 URL 版本）
Host: www.example.com                  ← 首部行
User-Agent: Mozilla/5.0
Accept: application/json
Authorization: Bearer token123
                                       ← 空行（标志首部结束）
{"name":"test"}                        ← 请求体（GET 通常为空）
```

### 响应报文

```text
HTTP/1.1 200 OK                        ← 状态行（版本 状态码 短语）
Content-Type: application/json         ← 首部行
Content-Length: 127
Cache-Control: max-age=3600
                                       ← 空行
{"id":1,"name":"test"}                 ← 响应体
```

## HTTP 方法

| 方法 | 语义 | 幂等 | 安全 | 有请求体 |
|------|------|------|------|----------|
| GET | 获取资源 | 是 | 是 | 通常无 |
| POST | 创建资源/提交数据 | 否 | 否 | 有 |
| PUT | 完整替换资源 | 是 | 否 | 有 |
| DELETE | 删除资源 | 是 | 否 | 可有 |
| HEAD | 只取首部不含体 | 是 | 是 | 无 |
| OPTIONS | 查询服务器能力 | 是 | 是 | 无 |
| TRACE | 回显请求用于诊断 | 是 | 否 | 无 |

<Callout type="warning" title="幂等性和安全性的意义">

**幂等**（Idempotent）指同一请求执行多次与一次效果相同——GET/PUT/DELETE 幂等，POST 不幂等。**安全**（Safe）指不修改服务器状态——GET/HEAD/OPTIONS 安全。这两个属性影响缓存行为（只有安全方法可缓存）和重试策略（幂等方法可安全重试）。

</Callout>

## HTTP 状态码

| 分类 | 含义 | 典型状态码 |
|------|------|-----------|
| 1xx | 信息性 | 100 Continue |
| 2xx | 成功 | 200 OK, 201 Created, 204 No Content |
| 3xx | 重定向 | 301 Moved Permanently, 302 Found, 304 Not Modified |
| 4xx | 客户端错误 | 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found |
| 5xx | 服务器错误 | 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable |

```text
常用状态码速查：
200 OK           — 请求成功
301 Moved        — 永久重定向（缓存）
302 Found        — 临时重定向（不缓存）
304 Not Modified — 缓存副本仍有效（条件请求响应）
401 Unauthorized — 需要认证
403 Forbidden    — 认证但无权限
404 Not Found    — 资源不存在
500 Server Error — 服务器内部错误
503 Unavailable  — 服务不可用（过载/维护）
```

## TCP 连接管理

### 非持久连接 vs 持久连接

```text
非持久连接（HTTP/1.0 默认）：
  每个请求 = 独立 TCP 连接
  开销：每个对象 2 RTT（TCP 握手 + HTTP 请求响应）
  1 HTML + 10 图片 = 11 次 TCP 握手 = 22+ RTT

持久连接（HTTP/1.1 默认，Connection: keep-alive）：
  TCP 连接复用，多个请求串行或流水线传输
  开销：1 次 TCP 握手，后续请求只需 1 RTT
  1 HTML + 10 图片 = 1 次 TCP 握手
```

<Callout type="info" title="RTT 对延迟的影响">

RTT（Round-Trip Time）是往返时延。非持久连接下每个对象需要 2 个 RTT：一个 TCP 握手 + 一个 HTTP 请求响应。10 个对象 = 20+ RTT。持久连接降至 1-2 个 RTT。HTTP/2 的多路复用进一步消除队头阻塞，HTTP/3 基于 QUIC 甚至消除了 TCP 握手的 RTT。

</Callout>

## 常用 HTTP 首部

### 请求首部

| 首部 | 作用 |
|------|------|
| Host | 目标主机名（虚拟主机必需） |
| User-Agent | 客户端标识 |
| Accept | 期望的 MIME 类型 |
| Accept-Encoding | 期望的编码（gzip/br） |
| Authorization | 认证凭证 |
| Cookie | 携带 Cookie |
| If-Modified-Since | 条件请求（缓存验证） |

### 响应首部

| 首部 | 作用 |
|------|------|
| Content-Type | 响应体 MIME 类型 |
| Content-Length | 响应体长度 |
| Cache-Control | 缓存指令 |
| Set-Cookie | 设置 Cookie |
| WWW-Authenticate | 认证挑战 |
| Location | 重定向目标 URL |
| Server | 服务器标识 |

<Glossary>

<GlossaryItem term="HTTP 报文（HTTP Message）">
HTTP 报文是 HTTP 通信的基本单元，纯文本格式（HTTP/1.x），由三部分组成：①起始行——请求报文是请求行（方法 URL 版本），响应报文是状态行（版本 状态码 短语）②首部——零个或多个键值对，每行一个，以空行结束③主体——可选的数据部分（HTML/JSON/图片等）。起始行和首部合称「首部块」，以 CRLF 空行与主体分隔。HTTP/2 将报文压缩为二进制帧，但语义不变。
</GlossaryItem>

<GlossaryItem term="持久连接（Persistent Connection）">
持久连接是 HTTP/1.1 的默认连接模式（Connection: keep-alive）：TCP 连接在多个请求间保持打开，不必每个请求都重新握手。优势：①减少 TCP 握手延迟（省 N-1 次 RTT）②减少 TCP 慢启动影响③连接复用提高吞吐。流水线模式允许在收到前一个响应前发出下一个请求。HTTP/2 的多路复用进一步允许同一连接上多个请求并行传输，消除了队头阻塞。
</GlossaryItem>

<GlossaryItem term="幂等性（Idempotency）">
幂等性指同一请求执行一次与执行多次的效果相同。HTTP 方法中 GET/PUT/DELETE 是幂等的——重复 GET 不改变状态，重复 PUT 结果一样，重复 DELETE 后资源仍不存在。POST 不是幂等的——重复 POST 可能创建多个资源。幂等性影响：①重试策略——幂等方法可安全自动重试（网络超时后）②缓存——只有安全且幂等的方法可缓存。
</GlossaryItem>

<GlossaryItem term="HTTP 状态码（Status Code）">
HTTP 状态码是响应报文状态行中的三位数字，表示请求的处理结果。分类：1xx 信息性（继续通信）2xx 成功（200 OK/201 Created/204 No Content）3xx 重定向（301 永久/302 临时/304 缓存有效）4xx 客户端错误（400 请求格式错/401 需认证/403 无权限/404 不存在）5xx 服务器错误（500 内部错误/502 网关错误/503 不可用）。状态码配合短语提供人类可读的描述。
</GlossaryItem>

</Glossary>

**问题 1：** HTTP 请求报文和响应报文的结构分别是什么？空行的作用是什么？

<Answer>

HTTP 请求报文由三部分组成：①请求行（方法 URL HTTP版本，如 `GET /index.html HTTP/1.1`）②首部（Host/User-Agent/Accept 等键值对，每行一个）③请求体（GET 通常为空，POST 携带数据）。HTTP 响应报文由三部分组成：①状态行（HTTP版本 状态码 短语，如 `HTTP/1.1 200 OK`）②首部（Content-Type/Content-Length 等键值对）③响应体（HTML/JSON 等内容）。空行（CRLF）的作用是标志首部块的结束——服务器/客户端读到空行就知道首部已全部读完，后面的内容是主体。这是 HTTP 报文解析的关键分隔符。
</Answer>

**问题 2：** 持久连接和非持久连接有什么区别？为什么 HTTP/1.1 默认使用持久连接？

<Answer>

区别：①非持久连接每个请求建立独立 TCP 连接，用完即关；持久连接保持 TCP 连接，复用传输多个请求 ②非持久连接每个对象需 2 RTT（TCP 握手 + HTTP 请求响应），持久连接首个对象 2 RTT，后续对象只需 1 RTT ③非持久连接 1 HTML + 10 图片 = 11 次 TCP 握手；持久连接只需 1 次 ④非持久连接每次握手都经历 TCP 慢启动，持久连接的连接已处于拥塞窗口稳定状态。HTTP/1.1 默认持久连接的原因：①大幅减少延迟（省去重复 TCP 握手 RTT）②减少服务器连接开销（不必频繁创建/销毁连接）③TCP 拥塞窗口复用，吞吐更高 ④流水线模式进一步减少等待时间。HTTP/2 在持久连接基础上引入多路复用，彻底消除队头阻塞。
</Answer>
