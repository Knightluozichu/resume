## URL 语法

<HdgUrlResourceDiagram />

URL（统一资源定位符）是互联网资源的地址，语法格式为：

```text
scheme://user:password@host:port/path;params?query#fragment
       └─── 认证 ──┘ └──主机──┘ └─路径─┘ └查询┘ └片段┘
```

| 组件 | 说明 | 示例 |
|------|------|------|
| scheme | 协议方案 | http, https, ftp, mailto |
| user:password | 认证信息（少用） | admin:pass |
| host | 主机名或 IP | www.example.com, 192.168.1.1 |
| port | 端口号 | 80(http), 443(https), 8080 |
| path | 资源路径 | /api/v1/users |
| params | 路径参数（少用） | ;type=a |
| query | 查询字符串 | ?page=1&size=20 |
| fragment | 片段标识符 | #section2 |

## 绝对 URL 与相对 URL

### 绝对 URL

包含完整信息（scheme + host + path），可独立定位资源：

```text
https://www.example.com/docs/guide.html
ftp://ftp.example.com/files/data.zip
```

### 相对 URL

省略 scheme 和 host，需参照 **基础 URL**（Base URL）才能定位：

```text
基础 URL：https://www.example.com/docs/current/page.html

相对 URL          → 解析后的绝对 URL
guide.html        → https://www.example.com/docs/current/guide.html
../images/x.png   → https://www.example.com/docs/images/x.png
/about            → https://www.example.com/about
//cdn.example.com/lib.js → https://cdn.example.com/lib.js
```

<Callout type="info" title="相对 URL 解析规则">

相对 URL 以基础 URL 为参照：`./` 表示当前目录，`../` 表示上一级目录，`/` 表示根路径，`//` 表示只省略 scheme 但保留 host。浏览器通常用当前页面的 URL 作为基础 URL，也可通过 HTML `<base>` 标签显式指定。

</Callout>

## URL 编码

URL 只允许 ASCII 字符的子集安全传输，其他字符需用 **百分号编码**（Percent-Encoding）。

### 编码规则

```text
安全字符（不编码）：A-Z a-z 0-9 - _ . ~
保留字符（特殊语境编码）：: / ? # [ ] @ ! $ & ' ( ) * + , ; =
不安全字符（必须编码）：空格 双引号 < > { } | \ ^

编码方式：字符的 UTF-8 字节序列，每字节用 %XX 表示
空格 → %20（或 query 中的 +）
中"文" → %E4%B8%AD%E6%96%87
& → %26（query 中需编码避免与参数分隔符冲突）
```

### 常见编码场景

| 原始字符 | 编码结果 | 场景 |
|----------|----------|------|
| 空格 | `%20` 或 `+` | URL 路径或查询参数 |
| 中文 | `%E4%B8%AD` | 非 ASCII 字符 |
| `&` | `%26` | 查询参数值中 |
| `=` | `%3D` | 查询参数值中 |
| `/` | `%2F` | 路径段中需字面斜杠时 |

| 方案 | 用途 | 默认端口 |
|------|------|----------|
| http | Web 页面传输 | 80 |

## 资源解析流程

服务器收到请求路径后，将路径映射到实际资源：

```text
请求路径 /api/users/42
    → 文件系统：/var/www/api/users/42.json
    → 数据库查询：SELECT * FROM users WHERE id=42
    → 动态脚本：执行 /api/users.php?id=42
    → 重定向：301 → /v2/users/42
```

<Glossary>

<GlossaryItem term="URL（统一资源定位符）">
URL 是互联网资源的地址标识，语法为 scheme://user:password@host:port/path;params?query#fragment。核心组件：scheme（协议方案，如 http/https/ftp）、host（主机名或 IP 地址）、port（端口号，http 默认 80/https 默认 443）、path（资源路径）、query（查询字符串，键值对参数）、fragment（片段标识符，客户端锚点，不发送到服务器）。URL 是 URI 的子集——URI 还包括 URN（统一资源名称）。URL 定位资源的方式是「地址」，URN 定位的方式是「名称」。
</GlossaryItem>

<GlossaryItem term="相对 URL（Relative URL）">
相对 URL 是省略了 scheme 和 host 的不完整 URL，需参照基础 URL（Base URL）才能定位资源。解析规则：`./` 或无前缀表示当前目录，`../` 表示上一级目录，`/` 表示根路径，`//` 表示保留 host 但省略 scheme（继承基础 URL 的 scheme）。浏览器通常用当前页面 URL 作为基础 URL，也可通过 HTML `<base href="...">` 标签指定。相对 URL 的优势：①省空间（短）②便于站点迁移（不用改路径）③协议无关（`//` 自动适配 http/https）。
</GlossaryItem>

<GlossaryItem term="百分号编码（Percent-Encoding）">
百分号编码是 URL 中表示非 ASCII 字符和不安全字符的编码方式：字符的 UTF-8 字节序列中每个字节用 `%` 加两位十六进制数表示。安全字符（A-Z a-z 0-9 - _ . ~）不编码。保留字符（如 : / ? # & =）在特定语境下需编码——例如 `&` 在查询参数值中需编码为 `%26`，否则会被误认为参数分隔符。空格通常编码为 `%20`，在查询字符串中也可用 `+`。中文「中」的 UTF-8 编码为 E4 B8 AD，URL 编码为 `%E4%B8%AD`。
</GlossaryItem>

<GlossaryItem term="URL 方案（URL Scheme）">
URL 方案是 URL 的第一部分，指定访问资源使用的协议。常见方案：http（Web 页面，端口 80）、https（加密 Web，端口 443）、ftp（文件传输，端口 21）、mailto（电子邮件，无端口）、file（本地文件）、data（内联数据，如 data:text/html,xxx）。方案决定了 URL 其余部分的语法和解析方式——例如 mailto:user@example.com 的语法完全不同于 http://host/path。浏览器和服务器根据 scheme 选择对应的协议处理器。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** URL 的语法结构包含哪些组件？`fragment` 和 `query` 有什么区别？

<Answer>

URL 语法为 `scheme://user:password@host:port/path;params?query#fragment`，核心组件：①scheme 协议方案（http/https）②host 主机名或 IP ③port 端口号 ④path 资源路径 ⑤query 查询字符串 ⑥fragment 片段标识符。query 和 fragment 的区别：①query（查询字符串）是 `?` 后的键值对参数（如 `?page=1&size=20`），会被发送到服务器，服务器可读取参数值 ②fragment（片段标识符）是 `#` 后的锚点（如 `#section2`），只在客户端使用，不会被发送到服务器，用于页面内定位。因此 query 影响服务器返回的内容，fragment 只影响浏览器滚动到页面的哪个位置。
</Answer>

**问题 2：** 什么是百分号编码？为什么需要编码？给出两个编码示例。

<Answer>

百分号编码是 URL 中表示非 ASCII 字符和不安全字符的方式：将字符的 UTF-8 字节序列中每个字节用 `%` 加两位十六进制数表示。需要编码的原因：①URL 设计为只传输 ASCII 字符子集，非 ASCII 字符（如中文）无法直接表示 ②某些 ASCII 字符在 URL 中有特殊含义（如 `&` 是参数分隔符、`?` 是查询起始符、`#` 是片段起始符），当这些字符需要作为普通字符出现在参数值中时必须编码 ③不安全字符（如空格、双引号、`<`、`>`）可能被各种系统错误处理。示例：空格编码为 `%20`（query 中也可用 `+`），中文「中」的 UTF-8 字节为 E4 B8 AD，编码为 `%E4%B8%AD`。
</Answer>
