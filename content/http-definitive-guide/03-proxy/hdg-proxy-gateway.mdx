## 代理与网关概述

<HdgProxyGatewayDiagram />

HTTP 中间层是插入在客户端和服务器之间的组件，用于转发请求和响应。根据协议转换能力分为代理和网关。

### 直接连接 vs 中间层转发

```text
直接连接：客户端 ←→ 服务器
代理转发：客户端 → 代理 → 服务器
网关转发：客户端 → 网关(HTTP→FTP) → FTP服务器
```

## 代理（Proxy）

代理是两端使用 **相同协议** 的中间层（HTTP ↔ HTTP），代表客户端发起请求，对服务器透明。

### 正向代理 vs 反向代理

| 特性 | 正向代理 | 反向代理 |
|------|----------|----------|
| 代表方 | 代表客户端 | 代表服务器 |
| 部署位置 | 客户端侧 | 服务器侧 |
| 客户端感知 | 知道代理存在 | 不知道代理存在 |
| 典型用途 | 翻墙/过滤/匿名化 | 负载均衡/缓存/SSL终止 |
| 配置方式 | 客户端配置代理地址 | DNS 指向反向代理 |

### 代理的用途

```text
1. 缓存 — 存储响应副本，减少重复请求延迟
2. 过滤 — 拦截非法/敏感内容（企业防火墙）
3. 匿名化 — 隐藏客户端真实 IP
4. 负载均衡 — 将请求分发到多台后端服务器
5. SSL 终止 — 反向代理解密 HTTPS，后端用 HTTP
6. 请求改写 — 修改首部、URL 或内容
```

## 网关（Gateway）

网关是两端使用 **不同协议** 的中间层（HTTP ↔ FTP/SMTP），代表服务器接收请求，对客户端透明。

```text
客户端 → HTTP 网关 → FTP 服务器（HTTP/FTP 协议转换）
客户端 → HTTP 网关 → SMTP 服务器（HTTP/SMTP 邮件网关）
客户端 → HTTPS 网关 → HTTP 服务器（SSL 终止网关）
```

## 隧道与中继

### 隧道（Tunnel）

隧道根据 **CONNECT 方法** 建立盲转通路，不解析不修改 HTTP 数据：

```text
1. 客户端 → 代理：CONNECT www.example.com:443 HTTP/1.1
2. 代理 → 服务器：建立 TCP 连接
3. 代理 → 客户端：200 Connection Established
4. 客户端 ↔ 服务器：TLS 握手 + 加密数据（代理盲转发）
```

<Callout type="info" title="隧道为什么重要">

HTTPS 流量经 HTTP 代理时，代理无法读取加密内容。通过 CONNECT 建立隧道后，代理只在 TCP 层面盲转发数据，不接触 TLS 加密层。这样既支持了 HTTPS 经代理穿透，又保证了端到端加密安全。

</Callout>

### 中继（Relay）

中继是不完整的 HTTP 代理，只做简单转发：

- 不解析首部，不理解 HTTP 语义
- 不处理 CONNECT 方法
- 可能导致连接管理问题（如无法正确处理持久连接）
- 应避免使用，使用完整代理替代

## 代理链

请求可以经过多个代理串联转发，形成代理链：

```text
客户端 → 代理A(缓存) → 代理B(过滤) → 网关(协议转换) → 代理C(负载均衡) → 服务器
```

### Via 首部

每个代理在 `Via` 首部中追加自己的信息，形成转发链路记录：

```text
Via: 1.1 proxy-a.example.com, 1.1 proxy-b.example.com
```

<Glossary>

<GlossaryItem term="代理（Proxy）">
HTTP 代理是两端使用相同协议的中间层（HTTP ↔ HTTP），代表客户端向服务器发起请求。分为正向代理（客户端侧部署，客户端知道代理存在，用于过滤/匿名/翻墙）和反向代理（服务器侧部署，客户端不知道代理存在，用于负载均衡/缓存/SSL终止）。代理可修改请求和响应：添加/删除首部、缓存响应、过滤内容、改写 URL。代理通过 Via 首部记录转发链路。代理是缓存体系的基础载体——Web 缓存通常部署在代理层。
</GlossaryItem>

<GlossaryItem term="网关（Gateway）">
网关是两端使用不同协议的中间层，代表服务器接收请求并进行协议转换。与代理的区别：代理两端同协议（HTTP↔HTTP），网关两端异协议（HTTP↔FTP/SMTP）。网关对客户端透明——客户端以为自己在和 HTTP 服务器通信，实际网关将请求转换为 FTP/SMTP 等协议后转发给后端。典型用途：HTTP/POP3 网关（通过 Web 读取邮件）、HTTP/HTTPS 网关（SSL 终止）、HTTP/数据库网关（Web 查询数据库）。网关扩展了 HTTP 可访问的资源类型。
</GlossaryItem>

<GlossaryItem term="隧道（Tunnel）">
隧道是根据 CONNECT 方法建立的盲转发通路。工作流程：客户端向代理发送 CONNECT 请求指定目标 host:port，代理建立到目标的 TCP 连接后返回 200 Connection Established，之后代理在两端之间盲转发 TCP 数据，不解析不修改。隧道主要用于 HTTPS 经 HTTP 代理穿透——代理无法读取加密内容，只在 TCP 层面转发。隧道不是完整的 HTTP 代理，不理解 HTTP 语义，只做透明的数据管道。
</GlossaryItem>

<GlossaryItem term="代理链（Proxy Chaining）">
代理链是请求经过多个代理串联转发的拓扑。例如：客户端 → 缓存代理 → 过滤代理 → 负载均衡代理 → 服务器。每个代理在 Via 首部中追加自己的标识（协议版本+主机名），形成完整的转发路径记录。代理链中任一代理都可执行缓存、过滤、改写等操作。链路越长延迟越高（每跳增加 RTT），但功能组合更灵活。Trace 方法的 Max-Forwards 首部可限制转发跳数用于诊断。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 代理和网关的区别是什么？正向代理和反向代理的区别是什么？

<Answer>

代理和网关的区别：①代理两端使用相同协议（HTTP ↔ HTTP），网关两端使用不同协议（HTTP ↔ FTP/SMTP）②代理代表客户端发起请求，对服务器透明；网关代表服务器接收请求，对客户端透明③代理用于转发/缓存/过滤，网关用于协议转换/资源映射。正向代理和反向代理的区别：①正向代理部署在客户端侧，代表客户端；反向代理部署在服务器侧，代表服务器②客户端知道正向代理存在（需配置代理地址），不知道反向代理存在（DNS 直接指向反向代理）③正向代理用途：翻墙/过滤/匿名化；反向代理用途：负载均衡/缓存/SSL终止/安全防护。
</Answer>

**问题 2：** 隧道的作用是什么？为什么 HTTPS 需要 CONNECT 方法建立隧道？

<Answer>

隧道的作用是在 HTTP 代理和目标服务器之间建立盲转发通路，代理不解析不修改转发的数据。HTTPS 需要 CONNECT 方法建立隧道的原因：HTTPS 流量是加密的，HTTP 代理无法读取加密的 HTTP 请求/响应内容，因此无法像处理普通 HTTP 请求那样解析 URL 和首部来转发。通过 CONNECT 方法，客户端告诉代理「请帮我连接到目标服务器的 443 端口」，代理建立 TCP 连接后返回 200 Connection Established，之后代理在客户端和服务器之间盲转发 TCP 数据流——TLS 握手和加密数据都在隧道中端到端传输，代理完全不接触加密层。这样既支持了 HTTPS 经代理穿透，又保证了端到端加密安全。
</Answer>
