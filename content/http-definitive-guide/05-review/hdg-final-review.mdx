## 端到端请求流程

<HdgFinalReviewDiagram />

一个 HTTPS 请求从发起到收到响应，贯穿全书所有章节的知识：

```text
 1. URL 解析        — 第 3 章：scheme://host/path 分解
 2. DNS 解析        — 域名 → IP 地址
 3. TLS 握手        — 第 7 章：证书验证 + 密钥协商
 4. 构造请求报文     — 第 2 章：方法 + URL + 首部 + 体
 5. 代理转发        — 第 4 章：正向/反向代理转发
 6. 缓存查询        — 第 5 章：命中直接返回，未命中转发源
 7. 认证鉴权        — 第 6 章：Basic/Digest 验证身份
 8. 内容协商        — 第 8 章：Accept 头选最佳表示
 9. 服务器处理       — 第 9 章：虚拟主机路由 + 负载均衡
10. 响应返回        — 第 5 章：经缓存/代理回传客户端
11. 连接关闭        — 第 2 章：持久连接保持或释放
```

<Callout type="info" title="为什么端到端视角重要">

单章学习容易产生「知识孤岛」——知道报文格式但不知道首部在哪里被使用，知道缓存但不知道缓存部署在代理上。端到端视角把所有章节串联成一条完整的请求处理链路，每个知识点都在链路上找到自己的位置。这不仅是复习，更是理解 HTTP 协议作为系统工程的设计哲学。

</Callout>

## 跨章节知识关联

### 报文 ↔ URL

```text
URL 路径 → 出现在请求报文的请求行：GET /api/users HTTP/1.1
Host 首部 → URL 的 host:port 部分，用于虚拟主机路由
URL 编码 → 影响请求行和首部中的字符表示
相对 URL → 浏览器解析为绝对 URL 后构造请求
```

### 代理 ↔ 缓存

```text
缓存部署在代理层 — 代理是缓存的物理载体
缓存命中在代理层判断 — 代理检查是否有有效副本
条件请求经代理转发 — If-Modified-Since/If-None-Match 通过代理传递
代理链中的缓存 — 每个代理都可独立缓存
```

### 认证 ↔ HTTPS

```text
Basic 认证须配 HTTPS — Base64 明文凭证需 TLS 加密保护
TLS 证书验证 = 服务器认证 — HTTPS 本身是认证机制
认证首部在报文中 — Authorization/WWW-Authenticate 是 HTTP 首部
Cookie 安全属性依赖 HTTPS — Secure 标记要求 HTTPS 传输
```

### 协商 ↔ 托管

```text
虚拟主机 + 内容协商 — Host 首部选站点，Accept 首部选表示
负载均衡 + 内容转码 — LB 分发请求，代理可转码响应
重定向 + 协商 — 重定向到最适合的表示版本
```

## 核心概念对比总结

### 代理 vs 网关 vs 隧道

| 概念 | 协议 | 透明性 | 用途 |
|------|------|--------|------|
| 代理 | 同协议（HTTP↔HTTP） | 对服务器透明 | 转发/缓存/过滤 |
| 网关 | 异协议（HTTP↔FTP） | 对客户端透明 | 协议转换 |
| 隧道 | 盲转发（不解析） | 双方透明 | HTTPS穿透 |

### Basic vs Digest 认证

| 特性 | Basic | Digest |
|------|-------|--------|
| 凭证 | Base64 编码（可逆） | MD5 哈希（不可逆） |
| 密码传输 | 明文（须 HTTPS） | 不传输 |
| 防重放 | 无 | nonce |
| 安全性 | 低 | 中（MD5 已弱） |

### 持久 vs 非持久连接

| 特性 | 非持久 | 持久 |
|------|--------|------|
| TCP 连接 | 每请求一个 | 复用 |
| 每对象 RTT | 2 | 1（后续） |
| 默认版本 | HTTP/1.0 | HTTP/1.1 |
| 流水线 | 不支持 | 支持 |

### 服务器驱动 vs 客户端驱动协商

| 特性 | 服务器驱动 | 客户端驱动 |
|------|-----------|-----------|
| 决策方 | 服务器 | 客户端 |
| 请求数 | 1 次 | 2 次 |
| 实现 | 服务器需协商逻辑 | 服务器列选项 |
| 常用度 | 高（常用） | 低 |

## HTTP 协议设计哲学

```text
1. 无状态设计 — 每个请求独立，简化服务器实现，提高可扩展性
2. 文本协议 — 可读可调试，降低开发和排错成本
3. 分层架构 — 代理/网关/缓存可透明插入，不改动端系统
4. 首部驱动 — 功能通过首部字段协商，核心协议保持简单
5. REST 原则 — 资源 + 方法 + 表示，统一接口
```

<GlossaryItem term="端到端请求流程（End-to-End Request Flow）">
端到端请求流程是一个 HTTP 请求从客户端发起到收到响应的完整旅程，串联全书所有知识：①URL 解析（第 3 章）②DNS 查询③TLS 握手（第 7 章）④构造请求报文（第 2 章）⑤代理转发（第 4 章）⑥缓存查询（第 5 章）⑦认证鉴权（第 6 章）⑧内容协商（第 8 章）⑨服务器处理含虚拟主机路由和负载均衡（第 9 章）⑩响应返回⑪连接关闭（第 2 章）。端到端视角把各章节知识串联成完整链路，理解每个知识点在请求处理中的位置，是理解 HTTP 作为系统工程的关键。
</GlossaryItem>

<GlossaryItem term="跨章节知识关联">
HTTP 各章节知识不是孤立的，而是相互关联：①报文↔URL——URL 路径出现在请求行，Host 首部用于虚拟主机②代理↔缓存——缓存部署在代理层，条件请求经代理转发③认证↔HTTPS——Basic 认证须配 HTTPS，TLS 证书本身是服务器认证④协商↔托管——虚拟主机用 Host 首部选站点，内容协商用 Accept 首部选表示。理解这些关联才能建立完整的 HTTP 知识网络，而非零散的知识点。
</GlossaryItem>

<GlossaryItem term="HTTP 设计哲学">
HTTP 的核心设计原则：①无状态——每个请求独立处理，服务器不记忆历史，简化实现并提高可扩展性（状态通过 Cookie 补充）②文本协议——HTTP/1.x 报文是纯文本，可读可调试，降低开发成本③分层架构——代理/网关/缓存等中间层可透明插入，不改动端系统④首部驱动——功能通过首部字段协商（Cache-Control/Authorization/Accept），核心协议保持简单⑤REST 原则——资源（URL）+ 方法（GET/POST）+ 表示（Content-Type），统一接口。这些设计使 HTTP 成为 Web 的通用协议。
</GlossaryItem>

<GlossaryItem term="HTTP 协议演进">
HTTP 协议的演进路线：①HTTP/0.9——极简，只有 GET，响应纯 HTML②HTTP/1.0——引入首部、状态码、多种方法，但默认非持久连接③HTTP/1.1——默认持久连接、Host 首部（虚拟主机）、管道化、缓存控制（Cache-Control）④HTTP/2——二进制分帧、多路复用（消除队头阻塞）、首部压缩（HPACK）、服务器推送⑤HTTP/3——基于 QUIC（UDP），消除 TCP 队头阻塞、0-RTT 连接恢复。本书以 HTTP/1.1 为核心，是理解后续版本的基础——HTTP/2 和 HTTP/3 的语义层与 HTTP/1.1 完全一致，只是传输效率优化。
</GlossaryItem>

</Glossary>

**问题 1：** 描述一个 HTTPS 请求的端到端完整流程，标注每一步涉及本书哪个章节的知识。

<Answer>

①URL 解析——客户端解析 URL 提取 scheme(https)/host/path（第 3 章 URL 与资源定位）②DNS 查询——将域名解析为 IP 地址③TLS 握手——TCP 连接后进行 TLS 握手：ClientHello/ServerHello/证书验证/密钥协商（第 7 章 HTTPS 与 SSL/TLS）④构造请求报文——组装方法+URL+首部+请求体（第 2 章 HTTP 报文与连接）⑤代理转发——请求经正向/反向代理转发到目标服务器（第 4 章代理与网关）⑥缓存查询——代理/CDN 检查缓存是否命中，命中直接返回，未命中转发到源服务器（第 5 章缓存体系）⑦认证鉴权——服务器验证客户端身份（Basic/Digest 认证，401 挑战）（第 6 章认证与安全）⑧内容协商——服务器根据 Accept 系列首部选择最佳表示（第 8 章内容协商与转码）⑨服务器处理——虚拟主机用 Host 首部路由站点，负载均衡器分发到后端服务器（第 9 章 Web 托管与部署）⑩响应返回——响应经缓存/代理回传客户端，缓存层存储副本⑪连接关闭——持久连接保持或关闭（第 2 章连接管理）。一个请求贯穿了全书所有章节的知识。
</Answer>

**问题 2：** 代理、网关和隧道有什么区别？举例说明各自的使用场景。

<Answer>

区别：①代理——两端使用相同协议（HTTP↔HTTP），代表客户端发起请求，对服务器透明。场景：企业正向代理（过滤员工上网）、反向代理（负载均衡+缓存+SSL终止）②网关——两端使用不同协议，代表服务器接收请求，对客户端透明。场景：HTTP/POP3 网关（通过 Web 读取邮件）、HTTP/FTP 网关（通过 HTTP 下载 FTP 文件）、HTTPS→HTTP 网关（SSL 终止，LB 解密 HTTPS 后转发 HTTP 到后端）③隧道——根据 CONNECT 方法建立的盲转发通路，不解析不修改数据，对双方透明。场景：HTTPS 经 HTTP 代理穿透——客户端发送 CONNECT 请求让代理建立到目标 443 端口的 TCP 连接，之后代理盲转发 TLS 加密数据，不接触加密层。总结：代理是同协议转发（改报文），网关是异协议转换（改协议），隧道是盲转发（不改任何东西）。
</Answer>
