## 从一条可证伪的HTTP事务开始

先预测：把服务器视为静态文件读取器会遗漏虚拟目录、动态映射、访问控制和并发I/O架构。把预测写成“URL/资源、连接、请求报文、中间实体、响应报文、身份与编码”六行，再运行客户端、代理或服务器。结果不同先定位首个字节或状态偏差。

本页主问题是：沿接受连接、接收、处理、资源映射、构建响应、发送和日志还原Web服务器。每条消息要注明发送者、接收者、HTTP版本、连接复用、逐跳/端到端首部、主体边界与历史协议状态。

验收不变量是：请求从套接字到资源和响应的七个步骤都有明确输入、访问控制、MIME类型和日志证据。最终页面正常、状态码200或TLS通道建立都只是局部事实，不能单独证明资源身份、缓存变体、代理转发与证书身份全部正确。

### 5.3 实际的web 服务器会做些什么

“5.3 实际的web 服务器会做些什么”位于服务器处理流水线：接收连接后解析请求、映射资源、执行访问控制、构造响应并记录日志；每一步都应留下可归责的输入与输出。

### 5.4 第一步——接受客户端连接

诊断“5.4 第一步——接受客户端连接”先确定哪一端关闭、是否仍有未确认字节以及方法是否幂等；页面最终成功不能证明中间没有重复请求。

#### 5.4.1 处理新连接

诊断“5.4.1 处理新连接”先确定哪一端关闭、是否仍有未确认字节以及方法是否幂等；页面最终成功不能证明中间没有重复请求。

#### 5.4.2 客户端主机名识别

“5.4.2 客户端主机名识别”通常需要反向 DNS，既增加延迟也不构成可靠身份；服务器应把它当作可选日志信息，而非访问控制凭据。

#### 5.4.3 通过ident 确定客户端用户

“5.4.3 通过ident 确定客户端用户”尝试从客户端主机的 Ident 服务取得发起连接的用户名；穿越 NAT、代理或防火墙时可靠性很低，也带来隐私成本。

### 5.5 第二步——接收请求报文

分析“5.5 第二步——接收请求报文”要保留起始行、全部首部与实体边界；把解析对象重新打印，可能丢掉重复字段、空白和线路顺序证据。

#### 5.5.1 报文的内部表示法

验证“5.5.1 报文的内部表示法”构造一条合法报文和一条只改一个字节的反例，比较解析、状态码、连接复用与后续消息边界。

#### 5.5.2 连接的输入/ 输出处理结构

“5.5.2 连接的输入/ 输出处理结构”把 HTTP 等待拆成 DNS、建连、请求发送、服务器处理和响应传输；连接复用影响握手次数，但不能改变报文边界与应用语义。

### 5.6 第三步——处理请求

验证“5.6 第三步——处理请求”固定 URL 与身份，只改变一项映射或权限配置，比较服务器选择的资源、状态码和日志责任字段。

### 5.7 第四步——对资源的映射及访问

“5.7 第四步——对资源的映射及访问”位于 HTTP 基础模型：URI 标识资源，请求与响应组成事务，媒体类型解释表示，中间组件在不破坏端到端语义的前提下转发或处理消息。

#### 5.7.1 docroot

“5.7.1 docroot”把 URL 路径映射到服务器文件树根；规范化后必须仍位于允许根目录内，防止路径穿越访问任意文件。

#### 5.7.2 目录列表

“5.7.2 目录列表”位于服务器处理流水线：接收连接后解析请求、映射资源、执行访问控制、构造响应并记录日志；每一步都应留下可归责的输入与输出。

#### 5.7.3 动态内容资源的映射

“5.7.3 动态内容资源的映射”位于 HTTP 基础模型：URI 标识资源，请求与响应组成事务，媒体类型解释表示，中间组件在不破坏端到端语义的前提下转发或处理消息。

#### 5.7.4 服务器端包含项

“5.7.4 服务器端包含项”在发送前由服务器把动态片段嵌入静态表示；它改变最终实体、缓存键与执行权限，不能仅按源文件判断响应。

#### 5.7.5 访问控制

“5.7.5 访问控制”的失败应归到接收、解析、映射、授权、执行或发送中的首个异常阶段；后续 500 响应只是结果，不是根因。

### 5.8 第五步——构建响应

“5.8 第五步——构建响应”的失败应归到接收、解析、映射、授权、执行或发送中的首个异常阶段；后续 500 响应只是结果，不是根因。

#### 5.8.1 响应实体

“5.8.1 响应实体”描述表示字节及其封装：媒体类型说明格式，内容编码说明变换，长度或分块界定边界，验证器和范围支持局部传输。

#### 5.8.2 mime 类型

核对“5.8.2 mime 类型”要保存编码前后实体、Content-Type、Content-Encoding、线路长度与解码长度，避免把传输编码误当资源格式。

#### 5.8.3 重定向

“5.8.3 重定向”在本章用于回答“沿接受连接、接收、处理、资源映射、构建响应、发送和日志还原Web服务器”。学习时必须把这个名称落到具体报文、连接、中间状态或历史规范，并说明它改变了哪项可观察结果。
