# 附录A uri 方案

“附录A uri 方案”锁定David Gourley、Brian Totty、Marjorie Sayer、Sailu Reddy、Anshu Aggarwal著，陈涓、赵振平译《HTTP权威指南》，人民邮电出版社，2012年，ISBN 9787115281487；英文原版HTTP: The Definitive Guide，O'Reilly Media，2002年9月，656页，ISBN 1565925092。O'Reilly官方页面确认英文首版的5个正文部分、21章和8个附录；中文版完整印刷目录另含“第六部分 附录”和索引。忠实度分母共586个部分、章、编号节/小节、附录与索引节点。

“附录A uri 方案”未取得未获授权的完整中文正文；课程以 [O’Reilly 官方在线版](https://www.oreilly.com/library/view/http-the-definitive/1565925092/) 与 [章级导览](https://www.oreilly.com/library/view/http-the-definitive/1565925092/pr02s02.html) 界定首版范围，中文解释、报文、实验和练习均为独立教学重写。现代语义仅以 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)、[RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html) 和 [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html) 核对差异。

- 能写出含首版边界、原始报文、故障、恢复和复核人的证据包。

</Objectives>

## 从一条可证伪的HTTP事务开始

先预测：把2002年参考表当作现代协议注册表，会忽略后续废弃、更新和安全变化。把预测写成“URL/资源、连接、请求报文、中间实体、响应报文、身份与编码”六行，再运行客户端、代理或服务器。结果不同先定位首个字节或状态偏差。

本页主问题是：查证原书时代的URI方案及其组件与访问语义。每条消息要注明发送者、接收者、HTTP版本、连接复用、逐跳/端到端首部、主体边界与历史协议状态。

验收不变量是：每次查表都能记录“查证原书时代的URI方案及其组件与访问语义”所对应的字段、上下文、版本和规范限制。最终页面正常、状态码200或TLS通道建立都只是局部事实，不能单独证明资源身份、缓存变体、代理转发与证书身份全部正确。

## 核心机制深读

### 先从方案画出事务

查证原书时代的URI方案及其组件与访问语义。先固定资源身份和请求目标，再标出客户端、中间实体与源服务器，任何优化或安全结论都不能跳过原始报文。

动手试：先手写预期请求与响应，再抓取正常事务和一个单变量故障事务。标出首个不同字节或状态，不用最终页面猜根因。

### 区分方案与权限

方案和权限可能在同一事务中协作，但责任、状态位置和失败语义不同。对比正常请求、单个首部变化和单个连接故障，定位首个偏差。

动手试：先手写预期请求与响应，再抓取正常事务和一个单变量故障事务。标出首个不同字节或状态，不用最终页面猜根因。

### 让路径经过真实中间实体

代理、缓存、网关或隧道会读取、添加、删除或转发不同首部。逐跳记录Via、Connection列出的字段、缓存决策和认证边界。

动手试：先手写预期请求与响应，再抓取正常事务和一个单变量故障事务。标出首个不同字节或状态，不用最终页面猜根因。

### 验证查询的历史语境

原书写于2002年，以HTTP/1.0、HTTP/1.1、SSL/TLS早期版本和当时Web基础设施为背景。现代实现可做对照，但不能冒充原书节点。

动手试：先手写预期请求与响应，再抓取正常事务和一个单变量故障事务。标出首个不同字节或状态，不用最终页面猜根因。

### 用片段关闭证据门

每次查表都能记录“查证原书时代的URI方案及其组件与访问语义”所对应的字段、上下文、版本和规范限制。证据至少包含原始请求/响应、TCP时间线、中间状态、失败注入、恢复动作和第三方复核。

## 首版机制逐项深读

### 附录A uri 方案

验证“附录A uri 方案”只改变一个 URI 组成部分，同时观察 DNS 目标、Host 与请求路径；若三者一起变化，就无法归因。

### 教学支撑：查证原书时代的URI方案及其组件与访问语义

解释“教学支撑：查证原书时代的URI方案及其组件与访问语义”时先写原始 URI，再标出规范化与百分号编码的位置；客户端显示文本不能替代真正发送的请求目标字节。

### 报文实验：方案的请求输入

“报文实验：方案的请求输入”用基准 URI、目标 URI 与最终请求目标三列核对，尤其区分相对引用解析、默认端口和只在客户端使用的片段。

### 状态实验：权限的中间状态

验证“状态实验：权限的中间状态”使用两个用户与两个站点，比较域、路径、会话和持久状态的选择规则，确认不会跨边界串用。

### 边界实验：路径的失败语义

“边界实验：路径的失败语义”属于资源标识链：方案决定解释规则，权限部分给出主机与端口，路径、参数和查询参与请求目标，片段只在客户端定位表示内部位置。

### 互操作实验：查询的代理与缓存影响

“互操作实验：查询的代理与缓存影响”用基准 URI、目标 URI 与最终请求目标三列核对，尤其区分相对引用解析、默认端口和只在客户端使用的片段。

### 安全实验：片段的身份与隐私边界

解释“安全实验：片段的身份与隐私边界”时先写原始 URI，再标出规范化与百分号编码的位置；客户端显示文本不能替代真正发送的请求目标字节。

### 历史边界：2002年英文首版与2012年中译本

“历史边界：2002年英文首版与2012年中译本”用于区分 2002 年首版观察与后续 HTTP 演进：先复原原书当时的限制，再把现代 RFC 结论作为单独对照，二者不能互相冒充。

### 证据门：原始报文、时间线、配置、日志与复核人

验证“证据门：原始报文、时间线、配置、日志与复核人”构造一条合法报文和一条只改一个字节的反例，比较解析、状态码、连接复用与后续消息边界。

## 可复现实验记录

```text
GET /resource HTTP/1.1
Host: example.test
Connection: keep-alive
Accept: */*
```

```text
HTTP/1.1 200 OK
Date: Tue, 01 Jan 2002 00:00:00 GMT
Content-Type: text/plain
Content-Length: 5

hello
```

```text
evidence = request_bytes + response_bytes + tcp_timeline + intermediary_state + recovery
```

动手试：保存一次正常请求、一次缓存或连接边界和一次单变量故障。记录客户端、代理、缓存、网关与源服务器看到的原始报文，以及统一时间戳和恢复动作。

<Callout type="trap" title="把端到端首部当成逐跳首部">
  Connection及其列出的字段只能作用于当前连接，代理必须移除；误转发会破坏持久连接、缓存和下游解释。
</Callout>

<Callout type="trap" title="用现代HTTP覆盖原书">
  本书的HTTP-NG、Cookie版本1、Digest、FrontPage、WebDAV、WPAD等内容必须按历史状态讲解。现代替代技术不能改写原书目录。
</Callout>

**问题 1：为什么“附录A uri 方案”必须固定2002年首版？**

<Answer>
  固定版次才能让5个正文部分、21章、8附录、索引和586个节点与HTTP/1.0、HTTP/1.1时代协议语境一一对应；现代标准只能独立比较。

<Answer>
  固定资源、请求与其他中间状态，只改变一个连接、首部、缓存、认证、编码或重定向变量；比较原始字节、首个偏差和恢复结果。
</Answer>
