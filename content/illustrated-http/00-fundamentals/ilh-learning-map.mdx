## HTTP协议核心设计哲学

1. **无状态** — 服务器不保留客户端状态，每个请求独立处理（Cookie/Session用来弥补）
2. **请求-响应** — 客户端发起请求，服务器返回响应，一问一答
3. **文本协议** — HTTP报文是纯文本，可读性好，易于调试
4. **可扩展首部** — 通过首部字段扩展功能，不改变协议核心

<Glossary>

<GlossaryItem term="HTTP（超文本传输协议）">
HTTP是HyperText Transfer Protocol的缩写，是Web通信的基础协议。它位于TCP/IP协议栈的应用层，采用请求-响应模型，客户端发送请求、服务器返回响应。HTTP是无状态协议——服务器不保留客户端的任何状态信息，每次请求都是独立的。HTTP默认端口80，HTTPS默认端口443。
</GlossaryItem>

<GlossaryItem term="TCP/IP协议栈">
TCP/IP是互联网通信的基础协议族，分为四层：应用层（HTTP/FTP/DNS）、传输层（TCP/UDP）、网络层（IP）和数据链路层（以太网/Wi-Fi）。HTTP运行在应用层，依赖传输层的TCP提供可靠传输。数据在发送端从上到下逐层封装，在接收端从下到上逐层解封装。
</GlossaryItem>

<GlossaryItem term="无状态（Stateless）">
HTTP协议不保存客户端的状态信息——服务器处理完一个请求后就忘记该客户端的所有信息。这意味着每个HTTP请求都必须携带服务器处理该请求所需的全部信息。无状态简化了服务器设计、提高了可扩展性，但导致无法保持用户登录状态——需要通过Cookie和Session机制来弥补。
</GlossaryItem>

<GlossaryItem term="URI与URL">
URI（统一资源标识符）是标识互联网资源的字符串的统称。URL（统一资源定位符）是URI的子集，不仅标识资源还指明了如何访问该资源（协议+主机+路径）。例如 `https://www.example.com/index.html` 是一个URL，也是URI。URI还包含URN（统一资源名称）等不包含位置信息的标识符。
</GlossaryItem>

</Glossary>

**问题 1：** 全书分为哪八大知识域？各自的核心内容和递进逻辑是什么？

<Answer>

全书分八大知识域：HTTP基础（TCP/IP协议栈/URI/请求响应模型/无状态）、HTTP方法（GET/POST/PUT/DELETE/幂等性/安全方法）、状态码（2xx/3xx/4xx/5xx分类与含义）、HTTP首部（通用/请求/响应/实体首部/Cookie机制）、HTTPS与安全（加密原理/SSL-TLS握手/数字证书/公钥密码体系）、认证与授权（BASIC/Digest/Session+Cookie/Token/JWT）、缓存机制（强缓存/协商缓存/Cache-Control/ETag）、Web架构与未来（HTTP2/HTTP3/WebSocket/CDN/代理网关隧道）。递进逻辑：怎么通信 → 怎么操作 → 怎么带信息 → 怎么加密 → 你是谁 → 怎么加速 → 怎么演进 → 怎么整合。

</Answer>

**问题 2：** HTTP协议的四个核心设计哲学是什么？「无状态」为什么既是优点也是缺点？

<Answer>

四个核心设计哲学：①无状态——服务器不保留客户端状态，每个请求独立处理；②请求-响应——客户端发起请求，服务器返回响应，一问一答模型；③文本协议——HTTP报文是纯文本，可读性好易于调试；④可扩展首部——通过首部字段扩展功能，不改变协议核心。无状态的优点是简化了服务器设计、提高了可扩展性（任意服务器都能处理任意请求）。缺点是无法保持用户登录状态等会话信息——需要通过Cookie和Session机制来弥补，这引入了额外的状态管理复杂性。

</Answer>
