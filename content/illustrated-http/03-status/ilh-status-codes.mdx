## 状态码分类

<IlhStatusCodesDiagram />

状态码以三位数字表示，第一位数字代表响应类别。格式为 `HTTP/1.1 [状态码] [原因短语]`。

| 类别 | 含义 | 速记 |
|------|------|------|
| 1xx | 信息性状态码 | 请求已接收，继续处理（很少使用） |
| 2xx | 成功状态码 | 请求被正常处理 |
| 3xx | 重定向状态码 | 需要额外操作完成请求 |
| 4xx | 客户端错误状态码 | 请求有语法错误或无法完成 |
| 5xx | 服务器错误状态码 | 服务器处理出错 |

## 2xx：成功

| 状态码 | 原因短语 | 含义 |
|--------|----------|------|
| `200 OK` | 正常响应 | 请求成功，响应体包含请求的资源 |
| `204 No Content` | 无内容 | 请求成功但无响应体返回（如PUT/DELETE成功） |
| `206 Partial Content` | 部分内容 | 范围请求成功（配合Range首部，用于视频拖拽/断点续传） |

## 3xx：重定向

| 状态码 | 原因短语 | 含义 |
|--------|----------|------|
| `301 Moved Permanently` | 永久重定向 | 资源已永久移动到新URI，书签应更新 |
| `302 Found` | 临时重定向 | 资源临时移动到新URI，后续请求仍用原URI |
| `303 See Other` | 查看其他位置 | 用GET方法访问另一个URI（POST后重定向到结果页） |
| `304 Not Modified` | 未修改 | 协商缓存命中，客户端用本地缓存 |
| `307 Temporary Redirect` | 临时重定向 | 与302类似但不改变请求方法（302可能POST→GET） |
| `308 Permanent Redirect` | 永久重定向 | 与301类似但不改变请求方法 |

<Callout type="warning" title="301 vs 302 vs 303 vs 307">

重定向状态码的细微差别是面试常考点：

- **301 永久重定向**：搜索引擎会更新索引，书签应更新。GET请求会跟随重定向。
- **302 临时重定向**：搜索引擎不更新索引。理论上不改变方法，但浏览器实现中POST可能变GET。
- **303 See Other**：明确要求用GET访问新URI（POST提交后重定向到结果页的标准做法）。
- **307 临时重定向**：严格保持原请求方法（POST重定向后仍是POST）。
- **308 永久重定向**：严格保持原请求方法的永久重定向。

</Callout>

## 4xx：客户端错误

| 状态码 | 原因短语 | 含义 |
|--------|----------|------|
| `400 Bad Request` | 请求语法错误 | 请求格式/参数有误，服务器无法理解 |
| `401 Unauthorized` | 未认证 | 需要登录认证（配合WWW-Authenticate首部） |
| `403 Forbidden` | 拒绝访问 | 已认证但无权限访问该资源 |
| `404 Not Found` | 未找到 | 请求的资源不存在 |
| `405 Method Not Allowed` | 方法不允许 | 该资源不支持此HTTP方法（如对只读资源PUT） |
| `429 Too Many Requests` | 请求过多 | 触发限流（配合Retry-After首部） |

<Callout type="info" title="401 vs 403 的区别">

这是最常混淆的两个状态码：

- **401 Unauthorized** = 「你是谁？」 → 需要认证，你还没登录
- **403 Forbidden** = 「我知道你是谁，但你不能做这个」 → 已登录但无权限

例如：访问管理后台，未登录返回401；已登录但不是管理员返回403。

</Callout>

## 5xx：服务器错误

| 状态码 | 原因短语 | 含义 |
|--------|----------|------|
| `500 Internal Server Error` | 服务器内部错误 | 代码异常、数据库崩溃等 |
| `502 Bad Gateway` | 网关错误 | 代理/网关从上游服务器收到无效响应 |
| `503 Service Unavailable` | 服务不可用 | 服务器过载或维护中（配合Retry-After首部） |
| `504 Gateway Timeout` | 网关超时 | 代理/网关等待上游服务器响应超时 |

<Glossary>

<GlossaryItem term="状态码（Status Code）">
HTTP响应中三位数字的代码，表示服务器对请求的处理结果。状态码的第一位数字表示响应类别：1xx信息性、2xx成功、3xx重定向、4xx客户端错误、5xx服务器错误。状态码与原因短语（如OK/Not Found）配合使用，但程序中应判断数字而非原因短语（因为原因短语可自定义）。
</GlossaryItem>

<GlossaryItem term="301永久重定向">
表示请求的资源已永久移动到新URI。搜索引擎会更新索引、转移权重到新URL。浏览器会缓存这个重定向，后续请求直接跳转到新URI。典型场景：HTTP跳HTTPS、域名迁移、URL结构调整。配合Location首部指定新的URI。
</GlossaryItem>

<GlossaryItem term="304 Not Modified">
协商缓存命中时返回的状态码。客户端发送带条件首部（If-Modified-Since或If-None-Match）的请求，服务器检查资源未修改则返回304（不返回响应体），客户端使用本地缓存。304是3xx状态码但不表示重定向，而是「缓存仍然有效，不用重新下载」。
</GlossaryItem>

<GlossaryItem term="502 vs 503 vs 504">
三个5xx错误经常混淆：502 Bad Gateway——网关/代理从上游服务器收到无效响应（上游服务器崩了或返回了垃圾数据）；503 Service Unavailable——服务器暂时无法处理请求（过载或维护中，通常会恢复）；504 Gateway Timeout——网关/代理等待上游服务器响应超时（上游服务器太慢了）。简单记忆：502上游坏了、503自己太忙、504上游太慢。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** HTTP状态码分为哪五大类？401和403有什么区别？

<Answer>

HTTP状态码分为五大类：①1xx信息性状态码（请求已接收继续处理，很少使用）②2xx成功状态码（请求被正常处理，如200/204/206）③3xx重定向状态码（需额外操作完成请求，如301/302/304）④4xx客户端错误状态码（请求有语法错误或无法完成，如400/401/403/404）⑤5xx服务器错误状态码（服务器处理出错，如500/502/503/504）。401 Unauthorized和403 Forbidden的区别：401表示需要认证（「你是谁？」，用户未登录），配合WWW-Authenticate首部要求客户端提供凭证；403表示已认证但无权限访问（「我知道你是谁，但你不能做这个」，如普通用户访问管理后台）。简单记忆：未登录返回401，已登录无权限返回403。

</Answer>

**问题 2：** 301和302重定向有什么区别？304状态码的作用是什么？502和504怎么区分？

<Answer>

301 Moved Permanently（永久重定向）和302 Found（临时重定向）的区别：①语义不同——301表示资源永久移动到新URI，302表示临时移动；②搜索引擎行为不同——301会更新索引、转移权重到新URL，302不更新索引；③浏览器缓存行为不同——301会被浏览器缓存，后续请求直接跳转新URI，302每次都会请求原URI。304 Not Modified的作用是协商缓存命中——客户端发送带条件首部（If-Modified-Since/If-None-Match）的请求，服务器检查资源未修改则返回304（无响应体），客户端用本地缓存，节省带宽。502和504的区分：502 Bad Gateway是网关/代理从上游收到无效响应（上游服务器崩了或返回垃圾数据），504 Gateway Timeout是网关/代理等待上游响应超时（上游太慢）。

</Answer>

</Exercises>
