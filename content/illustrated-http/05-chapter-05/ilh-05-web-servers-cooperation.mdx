## 从一条可证伪的HTTP交换开始

先预测：把代理、网关、隧道和CDN统称为反向代理，会丢失协议转换、透明转发、加密通道与缓存责任边界。把预测写成“请求输入、线上消息、接收方状态、响应输出、最终副作用”五列，再运行实验。若结果与预测不同，先修正模型，不要只截取一个状态码证明自己。

本章的主问题是：解释虚拟主机、代理、网关、隧道和缓存如何处在客户端与源服务器之间并改变转发路径。原书以图解建立直觉，本课程把图解升级为可操作轨迹：每个箭头必须注明方向、协议对象和完成点；每个安全结论必须附一条攻击或误配置反例。

验收不变量是：给出一条含中介的请求链时，能说明每一跳代表谁、是否改写协议、缓存存在哪里以及响应新鲜度如何判断。浏览器页面“看起来正常”只能说明某个终点出现，不能单独证明DNS、连接、TLS、缓存、认证或授权中的哪一段正确。

## 核心机制深读

### Host让同一IP区分站点

TCP连接的目标IP不足以表示用户想访问哪个域名。HTTP/1.1要求Host首部，虚拟主机据此选择站点配置；Host错误可能访问到默认站点，也可能污染缓存键或路由。

动手试：先写下预期请求、响应与状态变化，再捕获一次正常交换和一次只改一个变量的失败交换。比较状态码、首部、主体、缓存或会话状态，确认结论来自证据而非浏览器表象。

### 三种转发器的工作层次

代理面向HTTP消息，可增加Via、执行访问控制或缓存；网关把HTTP接入数据库、应用服务器等非HTTP处理；隧道只建立透明通道，例如代理收到CONNECT后转发加密字节。

动手试：先写下预期请求、响应与状态变化，再捕获一次正常交换和一次只改一个变量的失败交换。比较状态码、首部、主体、缓存或会话状态，确认结论来自证据而非浏览器表象。

### 缓存命中不是永远正确

缓存副本必须判断新鲜度。未过期可直接返回；过期后用ETag或Last-Modified向源站验证，未修改时复用副本。共享缓存还必须遵守private、no-store、Authorization与Vary等约束。

动手试：先写下预期请求、响应与状态变化，再捕获一次正常交换和一次只改一个变量的失败交换。比较状态码、首部、主体、缓存或会话状态，确认结论来自证据而非浏览器表象。

### 客户端缓存也是协议参与者

浏览器缓存保存表示和验证器，下次请求可能不联网、做条件请求或完整下载。调试时要区分源站响应、代理缓存响应和浏览器本地副本，Age、Via、304和开发者工具线索需共同判断。

```text

HTTP/1.1 200 Connection Established
```

```text
fresh cache -> return copy
stale cache -> conditional request -> 304 reuse | 200 replace
```

<Callout type="trap" title="把现代规范倒灌进首版">

</Callout>

## 本章回顾
