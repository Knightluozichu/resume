## HTTPS = HTTP + 安全

<IlhHttpsSecurityDiagram />

HTTP有三个安全缺陷：**明文传输**（内容可被窃听）、**无法验证身份**（可能连到假冒服务器）、**无法验证完整性**（内容可被篡改）。HTTPS通过加密、认证、完整性保护解决这三个问题。

## 两种加密方式

### 共享密钥加密（对称加密）

加密和解密使用 **同一个密钥**。

```
加密：明文 + 密钥K → 密文
解密：密文 + 密钥K → 明文

优点：速度快，适合大量数据
缺点：如何安全地把密钥传递给对方？
```

常见算法：AES、DES（已不安全）、3DES

### 公开密钥加密（非对称加密）

使用 **一对密钥**：公钥（公开）和私钥（保密）。

```
加密：明文 + 公钥 → 密文
解密：密文 + 私钥 → 明文

（或反过来用于签名：私钥签名 → 公钥验证）

优点：无需传递私钥，安全性高
缺点：速度慢，不适合大量数据
```

常见算法：RSA、ECC

<Callout type="warning" title="对称加密的核心难题">

对称加密的密钥必须保密，但通信双方需要共享这个密钥——怎么安全地传递密钥？如果直接发送密钥，被截获就全完了。这就是「密钥分配问题」。HTTPS的解决方案是：用非对称加密安全传递对称密钥，然后用对称加密传输数据。

</Callout>

## HTTPS混合加密机制

HTTPS采用 **混合加密** ——结合两种加密方式的优势：

```
① 密钥交换阶段：用公开密钥加密（非对称）安全传递共享密钥
   → 解决密钥分配问题（慢但只传少量数据）

② 数据传输阶段：用共享密钥加密（对称）高效传输数据
   → 解决性能问题（快且数据量大）
```

## SSL/TLS握手流程

```
客户端                                    服务器
  |                                         |
  | --- ① Client Hello ----------------→   |  支持的TLS版本/加密套件/随机数A
  |                                         |
  | ←-- ② Server Hello + 证书 + 公钥 ---   |  选定套件/随机数B/服务器证书/公钥
  |                                         |
  |  验证证书 → 生成预主密钥                |
  |  用服务器公钥加密预主密钥               |
  |                                         |
  | --- ③ 加密的预主密钥 ---------------→   |
  |                                         |
  |  双方用随机数A+随机数B+预主密钥          |
  |  生成相同的会话密钥                      |
  |                                         |
  | ←--- ④ 切换到加密通信 ---------------   |
  |                                         |
  | ======  用会话密钥对称加密通信 ======== |
```

## 数字证书与CA

<Callout type="info" title="为什么需要数字证书">

非对称加密中，客户端需要获取服务器的公钥。但如果有人冒充服务器发送自己的公钥呢？客户端无法分辨——这就是中间人攻击。

**数字证书** 由权威的CA（证书颁发机构）签发，证明「这个公钥确实属于这个服务器」。客户端信任CA，CA担保服务器身份，形成信任链。

</Callout>

### 证书验证过程

```
1. 服务器发送证书（含公钥 + 服务器信息 + CA签名）
2. 客户端用CA的公钥验证证书签名 → 确认证书未被篡改
3. 客户端检查证书中的域名与访问的域名匹配
4. 客户端检查证书未过期、未吊销
5. 验证通过 → 信任证书中的公钥
```

<Glossary>

<GlossaryItem term="对称加密（共享密钥加密）">
加密和解密使用同一把密钥的加密方式。通信双方必须共享这把密钥，因此也叫共享密钥加密。优点是计算速度快，适合加密大量数据。缺点是密钥分配困难——如何安全地把密钥传给对方是个问题。HTTPS中，对称加密用于加密实际传输的数据（会话密钥加密），常见算法有AES、ChaCha20。
</GlossaryItem>

<GlossaryItem term="非对称加密（公开密钥加密）">
使用一对数学上关联的密钥——公钥和私钥——的加密方式。公钥可以公开，私钥必须保密。用公钥加密的数据只能用私钥解密，反之亦然。优点是解决了密钥分配问题（公钥可以公开传递）。缺点是计算速度慢，不适合加密大量数据。HTTPS中，非对称加密用于在握手阶段安全交换对称密钥，常见算法有RSA、ECC。
</GlossaryItem>

<GlossaryItem term="SSL/TLS">
为HTTP通信提供安全保障的协议。SSL（安全套接层）是早期版本，TLS（传输层安全）是SSL的继任者，现在说的HTTPS实际上使用的是TLS。TLS在TCP之上、HTTP之下，为应用层数据提供加密、认证和完整性保护。TLS握手过程协商加密套件、验证证书、交换密钥，然后建立加密通道。
</GlossaryItem>

<GlossaryItem term="数字证书与CA（证书颁发机构）">
数字证书是由权威机构（CA，Certificate Authority）签发的电子文档，用于证明公钥的所有者身份。证书包含：公钥、持有者信息、有效期、CA的数字签名。客户端通过验证CA签名来确认证书真实性。CA是PKI（公钥基础设施）的核心——客户端预装了可信CA的根证书，形成信任链：客户端信任CA → CA担保服务器身份 → 客户端信任服务器。常见CA有DigiCert、Let's Encrypt等。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** HTTP有什么安全缺陷？HTTPS如何解决？对称加密和非对称加密各有什么优缺点？

<Answer>

HTTP的三个安全缺陷：①明文传输——通信内容可被窃听 ②无法验证身份——可能连接到假冒服务器（中间人攻击）③无法验证完整性——内容可被篡改。HTTPS通过加密（解决窃听）、认证（解决身份伪造）、完整性保护（解决篡改）来解决。对称加密（共享密钥加密）的优点是速度快适合大量数据，缺点是密钥分配困难——如何安全传递密钥。非对称加密（公开密钥加密）的优点是无需传递私钥安全性高（公钥可公开），缺点是速度慢不适合大量数据。HTTPS采用混合加密：用非对称加密安全传递对称密钥，再用对称加密高效传输数据，兼顾安全与性能。

</Answer>

**问题 2：** 简述SSL/TLS握手流程。为什么需要数字证书？CA的作用是什么？

<Answer>

SSL/TLS握手流程：①客户端发送Client Hello（支持的TLS版本/加密套件/随机数A）→ ②服务器回复Server Hello（选定套件/随机数B）并发送服务器证书和公钥 → ③客户端验证证书，生成预主密钥，用服务器公钥加密后发送 → ④双方用随机数A+随机数B+预主密钥生成相同的会话密钥，切换到加密通信。需要数字证书是因为非对称加密中客户端需要获取服务器公钥，但可能被中间人冒充——客户端无法分辨公钥是否属于真正的服务器。数字证书由CA签发，证明公钥所有者身份。CA（证书颁发机构）的作用是作为可信第三方：客户端预装CA根证书信任CA，CA验证服务器身份后签发证书，形成信任链——客户端信任CA → CA担保服务器 → 客户端信任服务器。

</Answer>
