## HTTP缓存机制

<IlhCachingDiagram />

HTTP缓存的目标是 **减少不必要的网络传输** ——如果客户端已有有效副本，就不必重新下载。缓存分两层：强缓存（不问服务器）和协商缓存（问服务器能不能用）。

## 强缓存

强缓存命中时，客户端 **不发送请求**，直接使用本地缓存。这是最快的缓存方式。

### Cache-Control（HTTP/1.1 首选）

```
Cache-Control: max-age=3600      ← 缓存3600秒（从响应生成时刻起算）
Cache-Control: no-cache          ← 不直接用缓存，每次必须向服务器验证（走协商缓存）
Cache-Control: no-store          ← 完全不缓存（敏感数据）
Cache-Control: public            ← 可被CDN等中间代理缓存
Cache-Control: private           ← 仅浏览器可缓存（如用户个性化数据）
Cache-Control: must-revalidate   ← 过期后必须重新验证，不能用过期缓存
```

### Expires（HTTP/1.0 已过时）

```
Expires: Wed, 01 Jan 2025 00:00:00 GMT    ← 绝对过期时间
```

<Callout type="warning" title="Cache-Control 优先于 Expires">

当Cache-Control和Expires同时存在时，Cache-Control优先。Expires是HTTP/1.0的方案，用绝对时间，如果客户端时钟不准确会导致缓存失效判断错误。Cache-Control用max-age相对时间，更可靠。现代Web应优先使用Cache-Control。

</Callout>

强缓存命中时，浏览器返回状态码 **200**（Chrome DevTools中显示 `from disk cache` 或 `from memory cache`）。

## 协商缓存

强缓存过期后，客户端发送请求 **询问服务器** 缓存是否还能用。如果没变，服务器返回 **304 Not Modified**（无响应体），客户端继续用本地缓存。

### ETag / If-None-Match（优先级高）

```
① 首次请求 → 服务器响应带 ETag: "abc123"（资源的唯一哈希标识）

② 再次请求 → 客户端带 If-None-Match: "abc123"

③ 服务器对比ETag：
   - 相同 → 304 Not Modified（无响应体）
   - 不同 → 200 OK + 新资源 + 新ETag
```

### Last-Modified / If-Modified-Since（优先级低）

```
① 首次请求 → 服务器响应带 Last-Modified: Wed, 01 Jan 2025 00:00:00 GMT

② 再次请求 → 客户端带 If-Modified-Since: Wed, 01 Jan 2025 00:00:00 GMT

③ 服务器对比修改时间：
   - 未修改 → 304 Not Modified
   - 已修改 → 200 OK + 新资源 + 新Last-Modified
```

<Callout type="info" title="ETag vs Last-Modified">

ETag比Last-Modified更精确：
- Last-Modified精度为秒级，1秒内多次修改无法检测
- Last-Modified只看时间，文件内容没变但时间改了也会认为修改了
- ETag基于内容哈希，只要内容相同ETag就相同

当ETag和Last-Modified同时存在时，**ETag优先** ——服务器先比较ETag，ETag匹配才返回304。

</Callout>

## 缓存决策流程

```
客户端请求资源
    ↓
检查本地缓存 + Cache-Control未过期？
    ├── 是 → 强缓存命中 → 200 (from cache)      [不请求服务器，最快]
    └── 否 → 发送协商缓存请求
              ├── ETag匹配？
              │    ├── 是 → 304 Not Modified      [请求了但无响应体，省带宽]
              │    └── 否 → 200 + 新资源           [完整下载]
              └── Last-Modified匹配？
                   ├── 是 → 304 Not Modified
                   └── 否 → 200 + 新资源
```

## 缓存策略最佳实践

| 资源类型 | 策略 | 示例 |
|----------|------|------|
| 不变的静态资源 | 强缓存长max-age | `Cache-Control: max-age=31536000`（带hash的文件名） |
| 经常变的资源 | 协商缓存 | `Cache-Control: no-cache` + `ETag` |
| 敏感数据 | 不缓存 | `Cache-Control: no-store` |
| 用户个性化 | 私有缓存 | `Cache-Control: private, no-cache` |

<Callout type="warning" title="文件名hash + 长缓存 = 前端缓存最优解">

前端打包工具（Webpack/Vite）会给文件名加hash（如 `app.a1b2c3.js`）。文件内容变 → hash变 → 文件名变 → 浏览器视为新资源请求。文件不变 → hash不变 → 文件名不变 → 强缓存命中。这样静态资源可以设置极长的 `max-age`（如一年），内容更新时通过文件名变化自动失效缓存。

</Callout>

<Glossary>

<GlossaryItem term="强缓存">
HTTP缓存的第一层。在Cache-Control的max-age未过期或Expires未到期时，客户端直接使用本地缓存的副本，不向服务器发送任何请求。强缓存命中时浏览器返回200状态码（DevTools显示from cache），无网络请求、无网络延迟，是最快的缓存方式。通过Cache-Control: no-cache可以禁用强缓存（强制走协商缓存），Cache-Control: no-store可以完全禁用缓存。
</GlossaryItem>

<GlossaryItem term="协商缓存（条件请求）">
HTTP缓存的第二层。强缓存过期后，客户端发送带条件首部的请求询问服务器缓存是否可用。条件首部有两种：If-None-Match（携带上次ETag）和If-Modified-Since（携带上次Last-Modified）。服务器验证后如果资源未修改返回304 Not Modified（无响应体），客户端用本地缓存；如果已修改返回200+新资源。协商缓存有网络往返但省去了响应体传输，节省带宽。ETag优先于Last-Modified。
</GlossaryItem>

<GlossaryItem term="ETag（实体标签）">
资源的唯一标识，通常是资源内容的哈希值。服务器在响应中通过ETag首部返回。客户端下次请求时通过If-None-Match携带该ETag，服务器比较ETag是否变化来决定返回304还是200。ETag比Last-Modified更精确——基于内容而非时间，能检测1秒内的多次修改，也能避免「内容没变但修改时间变了」的误判。
</GlossaryItem>

<GlossaryItem term="Cache-Control指令">
HTTP/1.1缓存控制首部，提供细粒度的缓存策略控制。常用指令：max-age=N（相对过期秒数）、no-cache（不直接用缓存，每次验证）、no-store（完全不缓存）、public/private（是否允许中间代理缓存）、must-revalidate（过期后必须验证）。Cache-Control是现代Web缓存控制的首选方案，优先于HTTP/1.0的Expires。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 强缓存和协商缓存有什么区别？各自返回什么状态码？

<Answer>

强缓存和协商缓存的区别：①请求行为不同——强缓存命中时不向服务器发送请求，直接用本地缓存；协商缓存命中时会向服务器发送请求询问缓存是否可用。②状态码不同——强缓存命中返回200（DevTools显示from cache），协商缓存命中返回304 Not Modified。③速度不同——强缓存无网络请求无延迟最快，协商缓存有网络往返但无响应体传输省带宽。强缓存通过Cache-Control: max-age或Expires控制，过期后进入协商缓存。协商缓存通过ETag/If-None-Match或Last-Modified/If-Modified-Since验证，ETag优先于Last-Modified。

</Answer>

**问题 2：** Cache-Control有哪些常用指令？ETag和Last-Modified有什么区别？前端如何实现最优缓存策略？

<Answer>

Cache-Control常用指令：max-age=N（缓存N秒）、no-cache（不直接用缓存，每次走协商缓存验证）、no-store（完全不缓存，敏感数据用）、public（允许CDN等代理缓存）、private（仅浏览器缓存，个性化数据用）、must-revalidate（过期后必须验证不能用过期缓存）。ETag和Last-Modified的区别：ETag基于内容哈希精确度高（能检测1秒内多次修改，内容没变ETag不变），Last-Modified基于修改时间精度为秒级（1秒内多次修改检测不到，内容没变但时间改了会误判修改）。ETag优先于Last-Modified。前端最优缓存策略：打包工具给文件名加hash（如app.a1b2c3.js），对静态资源设置极长max-age（如31536000秒=1年），文件内容变化→hash变化→文件名变化→浏览器视为新资源请求新文件，文件不变→hash不变→强缓存命中。这样静态资源可长期缓存，内容更新时自动失效。

</Answer>
