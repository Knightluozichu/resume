## HTTP版本演进

### HTTP/1.0（1996年）

- 每次请求新建TCP连接，响应后断开
- 非持久连接，开销大
- 每个资源（HTML/CSS/JS/图片）都需要单独的TCP连接

### HTTP/1.1（1997年，当前主流）

- **持久连接（Keep-Alive）**：一个TCP连接可发送多个请求
- **管道化**：可连续发送请求不等响应（但浏览器普遍禁用，队头阻塞）
- **Host首部**：支持虚拟主机（一个IP多个域名）
- **范围请求**：Range首部支持断点续传
- **缓存控制**：Cache-Control/ETag等

### HTTP/2（2015年）

- **二进制分帧**：不再是文本协议，改为二进制帧
- **多路复用**：一个TCP连接上并行多个请求/响应，解决队头阻塞
- **头部压缩**：HPACK算法压缩首部
- **服务器推送**：服务器可主动推送资源

### HTTP/3（2022年）

- **基于QUIC/UDP**：不再依赖TCP，避免TCP层队头阻塞
- **0-RTT连接**：重连时可零往返时间
- **连接迁移**：网络切换（如Wi-Fi切4G）不断连接

<Callout type="info" title="队头阻塞（Head-of-Line Blocking）">

HTTP/1.1的管道化中，多个请求复用一个TCP连接，但必须按顺序响应——如果第一个请求处理慢，后面的请求即使已就绪也必须等待。这就是HTTP/1.1的队头阻塞。

HTTP/2用多路复用解决了应用层队头阻塞——多个请求并行响应。但TCP层仍有队头阻塞——TCP保证有序，一个包丢了后面所有包都要等。

HTTP/3改用UDP（QUIC），彻底消除队头阻塞。

</Callout>

## Web架构组件

### 代理（Proxy）

转发客户端请求和服务器响应的中间程序。

- **正向代理**：代理客户端（如VPN、公司代理），服务器不知道真实客户端
- **反向代理**：代理服务器（如Nginx），客户端不知道真实服务器

### 网关（Gateway）

工作在应用层的协议转换器，将HTTP请求转换为其他协议。

```
客户端 → [网关] → 数据库/邮件服务器
         HTTP → SQL/SMTP
```

### 隧道（Tunnel）

在通信双方之间建立加密通道，如SSL/TLS隧道。

### CDN（内容分发网络）

将静态资源缓存到全球各地的边缘节点，用户就近获取资源，加速访问。

```
用户 → 就近CDN节点 → （缓存命中？直接返回 : 回源服务器获取并缓存）
```

## WebSocket

<Callout type="info" title="WebSocket：全双工实时通信">

传统HTTP是 **请求-响应** 模型——只有客户端能发起请求，服务器不能主动推送。WebSocket解决了这个问题：

```
① 客户端发送HTTP Upgrade请求 → 服务器同意升级
② 连接从HTTP升级为WebSocket（一次握手）
③ 建立持久双向连接
   - 服务器可主动推送消息
   - 客户端也可随时发送消息
④ 直到一方主动关闭连接
```

适用场景：聊天室、实时通知、股票行情、协同编辑。

</Callout>

## Web安全威胁与防御

### XSS（跨站脚本攻击）

攻击者向页面注入恶意JavaScript代码，在其他用户浏览器中执行。

```
防御：
① 输出转义（HTML实体编码）
② CSP（Content Security Policy）
③ HttpOnly Cookie（防Cookie窃取）
```

### CSRF（跨站请求伪造）

诱导已登录用户在不知情下发送请求（利用Cookie自动携带特性）。

```
防御：
① CSRF Token（请求携带随机Token）
② Referer检查
③ SameSite Cookie属性
```

### DoS/DDoS攻击

大量请求耗尽服务器资源，使其无法正常服务。

```
防御：
① 限流（Rate Limiting）
② 验证码
③ WAF（Web应用防火墙）
④ CDN流量清洗
```

<Glossary>

<GlossaryItem term="HTTP/2多路复用">
HTTP/2的核心特性之一。在HTTP/1.1中，一个TCP连接上同一时刻只能处理一个请求（管道化虽然可以连续发送但必须按序响应）。HTTP/2将每个请求/响应拆分为二进制帧，多个请求的帧可以在同一个TCP连接上交错传输、并行处理，互不阻塞。这解决了HTTP/1.1的应用层队头阻塞问题，大幅提升了页面加载速度（尤其对需要加载大量小资源的页面）。
</GlossaryItem>

<GlossaryItem term="WebSocket">
一种在单个TCP连接上进行全双工通信的协议。与传统HTTP的请求-响应模型不同，WebSocket建立连接后，服务器可以主动向客户端推送消息，客户端也可以随时发送消息。WebSocket通过HTTP Upgrade握手建立连接，然后升级为WebSocket协议。适用场景包括聊天应用、实时通知、股票行情、在线协同编辑等需要服务器主动推送的场景。
</GlossaryItem>

<GlossaryItem term="CDN（内容分发网络）">
Content Delivery Network，通过在全球各地部署边缘节点，将静态资源（图片/CSS/JS/视频）缓存到离用户最近的节点。用户访问时CDN就近返回缓存内容，减少网络延迟和回源压力。CDN的缓存策略与HTTP缓存机制一致——边缘节点作为中间缓存，遵守Cache-Control/Expires等缓存指令。CDN还能提供DDoS防护、SSL卸载等附加功能。
</GlossaryItem>

<GlossaryItem term="XSS（跨站脚本攻击）">
Cross-Site Scripting，攻击者向Web页面注入恶意JavaScript代码，当其他用户浏览该页面时恶意脚本在用户浏览器中执行。危害：窃取Cookie/Session、重定向到钓鱼网站、篡改页面内容。防御手段：①输出时HTML实体转义（将<>&'"转义）②CSP（Content Security Policy，限制脚本来源）③设置Cookie的HttpOnly属性防止JavaScript窃取。XSS分为反射型（恶意代码在URL中）、存储型（恶意代码存入数据库）、DOM型（前端JS直接操作DOM引入）。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** HTTP/1.1、HTTP/2、HTTP/3各自的核心改进是什么？什么是队头阻塞？

<Answer>

HTTP/1.1的核心改进：持久连接（Keep-Alive，一个TCP连接可发送多个请求）、管道化（可连续发送请求）、Host首部（支持虚拟主机）、范围请求（断点续传）。HTTP/2的核心改进：二进制分帧（不再是文本协议）、多路复用（一个TCP连接并行处理多个请求解决应用层队头阻塞）、头部压缩（HPACK）、服务器推送。HTTP/3的核心改进：基于QUIC/UDP（不再依赖TCP，消除TCP层队头阻塞）、0-RTT重连（零往返时间）、连接迁移（网络切换不断连）。队头阻塞是指多个请求复用同一连接时，前面的请求处理慢会阻塞后面请求的现象。HTTP/1.1管道化存在应用层队头阻塞（必须按序响应），HTTP/2多路复用解决了应用层队头阻塞但TCP层仍有（TCP保证有序丢包重传），HTTP/3改用UDP彻底消除。

</Answer>

**问题 2：** WebSocket和传统HTTP有什么区别？XSS和CSRF是什么？如何防御？

<Answer>

WebSocket和传统HTTP的区别：传统HTTP是请求-响应模型，只有客户端能发起请求，服务器不能主动推送；WebSocket建立连接后是全双工通信，服务器可主动推送消息，客户端也可随时发送，适合实时通信场景。WebSocket通过HTTP Upgrade握手建立连接后升级协议。XSS（跨站脚本攻击）是攻击者向页面注入恶意JavaScript，在其他用户浏览器中执行，窃取Cookie或篡改页面。防御：输出HTML实体转义、CSP（限制脚本来源）、HttpOnly Cookie。CSRF（跨站请求伪造）是诱导已登录用户在不知情下发送请求（利用Cookie自动携带），如构造恶意页面让用户点击后自动转账。防御：CSRF Token（请求携带服务器下发的随机Token，攻击者无法获取）、Referer检查、SameSite Cookie属性。

</Answer>
