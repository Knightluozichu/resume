- 不懂协议栈 → 无法理解性能调优的TCP参数

</Callout>

## 服务端网络核心设计原则

1. **分层架构** — 接入层、逻辑层、数据层各司其职，流量逐层过滤
2. **流量分发** — 通过负载均衡将请求分散到多台服务器，避免单点过载
3. **冗余容灾** — 关键组件至少双份，故障自动转移，服务持续可用
4. **纵深防御** — 从网络边界到应用层逐层设防，安全不靠单点

<Glossary>

<GlossaryItem term="服务端网络架构">
服务端网络架构是指服务器节点通过网络协议（TCP/IP）互联、通过中间设施（负载均衡器、代理、网关）协作、对外提供高可用、高并发、安全服务的整体设计。它关注「流量怎么进来、怎么分发、怎么容灾、怎么防御、怎么演进」，是后端工程的基础骨架。
</GlossaryItem>

<GlossaryItem term="负载均衡（Load Balancing）">
负载均衡是将进入的网络流量分散到多台后端服务器的技术。它可以是四层（基于IP+端口）或七层（基于HTTP内容），通过轮询、最少连接等调度算法决定请求去向，并配合健康检查剔除故障节点。负载均衡器是服务端网络的第一道流量分发枢纽。
</GlossaryItem>

<GlossaryItem term="高可用（High Availability）">
高可用是指系统通过冗余设计和故障自动转移，在单点故障时仍能持续提供服务的能力。核心思路是「消除单点故障」——关键组件至少部署两份（主备或双活），通过心跳检测和VIP漂移实现故障切换。可用性通常用「几个9」衡量，如99.99% = 年停机约52.6分钟。
</GlossaryItem>

<GlossaryItem term="反向代理（Reverse Proxy）">
反向代理位于客户端和后端服务器之间，客户端只看到代理地址，后端服务器对客户端透明。反向代理负责请求转发、负载均衡、SSL终结、缓存、安全过滤等。Nginx是最常见的反向代理实现。与正向代理（代理客户端）不同，反向代理代理的是服务端。
</GlossaryItem>

</Glossary>

**问题 1：** 全书分为哪六大知识域？各自的核心内容和递进逻辑是什么？

<Answer>

全书分六大知识域：服务器网络基础（协议栈/TCP-UDP/端口套接字/服务器架构模型）、负载均衡机制（L4-L7负载均衡/调度算法/健康检查/会话保持）、高可用架构（冗余设计/主备双活/故障转移/VIP与VRRP）、DNS与CDN（域名解析/DNS负载均衡/CDN缓存回源/边缘节点）、防火墙与网络安全+反向代理网关（包过滤/状态检测/WAF/DDoS防御/ACL规则/Nginx反向代理/API网关/请求路由/限流）、微服务网络+性能调优（服务间通信/服务网格/Sidecar/Istio/TCP调优/零拷贝/连接池/监控链路追踪）。递进逻辑：怎么连接 → 怎么分发 → 怎么容灾 → 怎么加速 → 怎么防御 → 怎么演进 → 怎么整合。

</Answer>

**问题 2：** 服务端网络的四个核心设计原则是什么？「分层架构」为什么重要？

<Answer>

四个核心设计原则：①分层架构——接入层、逻辑层、数据层各司其职，流量逐层过滤 ②流量分发——通过负载均衡将请求分散到多台服务器，避免单点过载 ③冗余容灾——关键组件至少双份，故障自动转移，服务持续可用 ④纵深防御——从网络边界到应用层逐层设防，安全不靠单点。分层架构重要因为：每层职责清晰便于独立扩展和维护；流量逐层过滤使安全策略可分层部署；某一层故障不会波及全部；新功能可在某一层独立迭代而不影响其他层。

</Answer>

</Exercises>
