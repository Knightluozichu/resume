## 高可用的核心思想

<IsnHighAvailabilityDiagram />

高可用（HA）的核心是 **消除单点故障（SPOF）**——关键组件至少部署两份，一台挂了另一台顶上，用户无感知。

### 可用性等级

| 等级 | 可用率 | 年停机时间 | 场景 |
|------|--------|-----------|------|
| 2个9 | 99% | 3.65天 | 内部系统 |
| 3个9 | 99.9% | 8.76小时 | 一般业务 |
| 4个9 | 99.99% | 52.6分钟 | 核心业务 |
| 5个9 | 99.999% | 5.26分钟 | 金融/电信 |

<Callout type="info" title="可用性怎么算">

可用性 = 正常时间 / (正常时间 + 故障时间)。从2个9到5个9，每提升一个9，年停机时间缩小10倍。但成本指数级增长——5个9通常需要异地多活+自动容灾+24小时运维。大部分业务做到4个9（年停机1小时内）即可。

</Callout>

## 三种冗余模式

| 模式 | 原理 | 资源利用率 | 切换速度 | 复杂度 |
|------|------|-----------|----------|--------|
| 主备（Active-Standby） | 一台工作一台待命，故障时切换 | 50% | 秒级 | 低 |
| 双活（Active-Active） | 两台同时工作，互为备份 | 100% | 无需切换 | 中 |
| 多活（Multi-Active） | 多机房同时服务 | 100% | 无需切换 | 高 |

```text
主备模式:    [主节点 ✓ 活跃]  [备节点 ✗ 待命]  → 主挂 → 备接管
双活模式:    [节点A ✓ 活跃]  [节点B ✓ 活跃]  → A挂 → B继续（本来就在工作）
多活模式:    [北京机房 ✓] [上海机房 ✓] [广州机房 ✓] → 任一挂 → 其他继续
```

<Callout type="warning" title="双活比主备好？不一定">

双活资源利用率高（100% vs 50%），但要求两台服务器状态完全同步。如果是数据库双活，写冲突、一致性保证非常复杂。主备虽然浪费资源，但简单可靠——很多场景（如数据库主从）主备仍是首选。

</Callout>

## VIP漂移与VRRP

故障转移的核心机制是 **VIP漂移**——虚拟IP从故障节点浮动到健康节点。

### VRRP工作原理

```text
VRRP（虚拟路由冗余协议）：
                    VIP: 192.168.1.100
                    ┌─────────────┐
客户端 → VIP ──── → │  Master节点  │ (优先级200) ← 活跃
                    └─────────────┘
                    ┌─────────────┐
                    │  Backup节点  │ (优先级100) ← 待命
                    └─────────────┘

故障转移流程：
1. Master每1秒发VRRP广告包 → "我还活着"
2. Backup 3秒没收到 → 判定Master挂了
3. Backup提升自己为Master → 抢占VIP
4. ARP广播 → 告诉交换机"VIP现在在我这里"
5. 客户端流量自动切到新Master（VIP没变）
```

<Callout type="info" title="为什么用VIP而不是真实IP">

客户端连的是VIP（虚拟IP），不是某台服务器的真实IP。这样服务器切换时，客户端无感知——VIP还是那个VIP，只是底层从服务器A漂移到了服务器B。Keepalived是Linux下最常用的VRRP实现。

</Callout>

## 脑裂问题

脑裂（Split-Brain）是高可用最危险的故障——两台服务器都认为对方挂了，都抢占VIP，导致数据冲突。

### 脑裂成因与防御

```text
脑裂场景：
  Master ←──[网络断开]──→ Backup
  Master: "Backup挂了，我是唯一的主！"
  Backup: "Master挂了，我是唯一的主！"
  → 两台同时持有VIP → 流量打到两台 → 数据冲突！

防御策略：
  ① 仲裁节点（Quorum）—— 奇数节点投票，多数派才能成为Master
  ② 共享存储（Fencing）—— 抢占共享锁，抢不到的强制关机
  ③ 多条心跳线 —— 主网+备用网+串口线，全断才算真挂
```

<Glossary>

<GlossaryItem term="单点故障（SPOF）">
单点故障（Single Point of Failure）是指系统中某个组件一旦故障就会导致整个系统不可用的设计缺陷。高可用的核心目标就是消除单点故障——通过冗余部署，确保每个关键组件至少有两份。检查SPOF的方法：逐个假设每个组件故障，看系统是否还能服务。如果某个组件故障就全盘崩溃，说明它是SPOF，必须冗余。
</GlossaryItem>

<GlossaryItem term="VIP漂移">
VIP（Virtual IP）是不绑定特定网卡的虚拟IP地址。正常情况下VIP指向Master节点，当Master故障时，VIP自动漂移到Backup节点。客户端始终连接VIP而非真实IP，因此故障转移对客户端透明——VIP没变，只是底层物理节点换了。VIP漂移是VRRP/Keepalived实现故障转移的核心机制。
</GlossaryItem>

<GlossaryItem term="VRRP（虚拟路由冗余协议）">
VRRP是IETF标准协议（RFC 5798），用于实现路由器/服务器的冗余备份。一组服务器组成VRRP组，选举一个Master持有VIP，其余为Backup。Master定期发送VRRP广告包，Backup在超时后发起选举抢占VIP。Keepalived是Linux下最流行的VRRP实现，广泛用于Nginx/LVS的高可用。
</GlossaryItem>

<GlossaryItem term="脑裂（Split-Brain）">
脑裂是高可用系统中两台服务器因网络分区互相认为对方故障，同时抢占VIP成为Master的致命问题。后果是两台服务器同时写入导致数据不一致或损坏。防御策略：①仲裁节点——奇数节点投票，多数派才成为Master ②Fencing（ fencing）——抢占共享存储锁，抢不到的强制关机 ③多条心跳线——主网+备用网+串口线，全断才算真挂。
</GlossaryItem>

</Glossary>

**问题 1：** 高可用的核心思想是什么？主备、双活、多活三种冗余模式有什么区别？

<Answer>

高可用的核心思想是消除单点故障（SPOF）——关键组件至少部署两份，一台挂了另一台顶上，用户无感知。三种冗余模式区别：①主备——一台工作一台待命，故障时切换，资源利用率50%，切换秒级，复杂度低 ②双活——两台同时工作互为备份，资源利用率100%，无需切换，复杂度中 ③多活——多机房同时服务，资源利用率100%，无需切换，复杂度高。双活资源利用率高但要求状态完全同步（数据库双活写冲突复杂），主备浪费资源但简单可靠——很多场景主备仍是首选。

</Answer>

**问题 2：** VIP漂移的原理是什么？脑裂问题如何防御？

<Answer>

VIP漂移原理：VIP是不绑定特定网卡的虚拟IP。正常时VIP指向Master节点，Master定期发VRRP广告包。当Master故障，Backup超时未收到广告包后发起选举抢占VIP，通过ARP广播告诉交换机VIP现在在Backup这里。客户端始终连VIP而非真实IP，故障转移对客户端透明。脑裂是两台服务器因网络分区互相认为对方故障同时抢占VIP导致数据冲突。防御策略：①仲裁节点——奇数节点投票，多数派才成为Master ②Fencing——抢占共享存储锁，抢不到的强制关机 ③多条心跳线——主网+备用网+串口线，全断才算真挂。

</Answer>
