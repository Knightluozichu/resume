## 端到端请求流转

一个用户请求从输入域名到获得响应，经过服务端网络的每一层。

```text
用户请求 www.example.com 的完整流转：

① DNS解析
  → 本地DNS → 根DNS → 顶级域 → 权威DNS → 返回CDN边缘节点IP（GSLB）

② CDN边缘节点
  → 命中缓存 → 直接返回（静态资源）
  → 未命中 → 回源到负载均衡器

③ 负载均衡层
  → LVS(L4) 高速分发 → Nginx(L7) 基于HTTP路由

④ 安全过滤层
  → WAF 检测SQL注入/XSS → 防火墙 ACL规则过滤

⑤ 反向代理/网关层
  → SSL终结（解密HTTPS）→ 限流（令牌桶）→ 认证（JWT校验）

⑥ 微服务层
  → API网关路由到微服务 → Sidecar代理 → 服务间gRPC调用

⑦ 性能保障
  → 连接池复用 → 零拷贝传输 → 全链路追踪监控
```

<Callout type="info" title="每一层解决什么问题">

①DNS——怎么找到服务器 ②CDN——怎么就近获取内容 ③负载均衡——怎么分担流量 ④安全——怎么挡住攻击 ⑤代理/网关——怎么路由和过滤 ⑥微服务——怎么拆分通信 ⑦性能——怎么调到最优。每层解决一个核心问题，层与层之间通过标准协议衔接。

</Callout>

## 核心知识线索

### 线索一：流量入口演进

```text
单机服务器 → 负载均衡器(L4/L7) → CDN+GSLB(全球加速) → API网关(微服务入口)
```

### 线索二：可靠性演进

```text
单点 → 主备(冗余) → 双活(同时服务) → 多活(异地容灾) → 服务网格(故障自愈)
```

### 线索三：安全纵深

```text
ACL(网络层) → 状态检测(连接层) → WAF(应用层) → 零信任(全面认证)
```

### 线索四：性能优化

```text
短连接 → 长连接(Keep-Alive) → 连接池(复用) → 零拷贝(sendfile) → 多路复用(epoll)
```

## 架构选型对比

### 负载均衡选型

| 需求 | 推荐方案 | 理由 |
|------|---------|------|
| 高速L4转发 | LVS | 内核态性能最高 |
| HTTP内容路由 | Nginx | L7灵活路由+SSL终结 |
| 全球地域调度 | DNS+GSLB | 按地域返回最近机房 |
| 微服务内部 | Envoy/Sidecar | 与服务网格集成 |

### 高可用选型

| 需求 | 推荐方案 | 理由 |
|------|---------|------|
| Nginx高可用 | Keepalived+VIP | 主备秒级切换 |
| 数据库容灾 | 主从复制+故障转移 | 数据不丢+服务不断 |
| 异地容灾 | 双活/多活 | 机房级容灾 |
| 防脑裂 | 仲裁节点+Fencing | 避免双Master |

## 核心设计原则回顾

1. **分层架构** — 接入层/逻辑层/数据层各司其职，流量逐层过滤
2. **消除单点** — 关键组件至少双份，故障自动转移
3. **纵深防御** — 网络层+应用层逐层设防，不靠单点
4. **就近服务** — CDN边缘缓存+GSLB地域调度，降低延迟
5. **可观测性** — 指标监控+链路追踪+日志聚合，全链路可见

<Glossary>

<GlossaryItem term="端到端请求流转">
端到端请求流转是指一个用户请求从输入域名到获得响应，经过服务端网络每一层的完整路径。典型流程：DNS解析→CDN边缘缓存→LVS(L4)负载均衡→Nginx(L7)路由→WAF安全过滤→SSL终结→API网关认证限流→微服务Sidecar→服务间gRPC调用→连接池/零拷贝传输→全链路追踪监控。每一层解决一个核心问题，层与层之间通过标准协议（TCP/HTTP/gRPC）衔接。
</GlossaryItem>

<GlossaryItem term="架构选型决策">
架构选型决策是根据业务需求选择合适技术方案的过程。核心原则：①没有银弹——每个方案都有取舍 ②按需求选型——QPS/延迟/可用性/成本 ③组合使用——L4+L7、主备+多活 ④渐进演进——从简单到复杂。负载均衡选型：高速L4用LVS、HTTP路由用Nginx、全球调度用DNS+GSLB、微服务内部用Envoy。高可用选型：Nginx用Keepalived+VIP、数据库用主从+故障转移、异地容灾用多活。
</GlossaryItem>

<GlossaryItem term="纵深防御（Defense in Depth）">
纵深防御是安全架构的核心原则——不依赖单一安全措施，而是从网络边界到应用层逐层设防。服务端网络安全纵深：①ACL/防火墙（L3/L4网络层过滤）②状态检测（连接层跟踪）③WAF（L7应用层攻击拦截）④认证授权（身份验证）⑤加密传输（SSL/TLS）。任何一层被突破，还有后续层兜底。单点防御一旦被绕过就全盘崩溃，纵深防御大幅提升攻击成本。
</GlossaryItem>

<GlossaryItem term="可观测性（Observability）">
可观测性是指通过外部表现推断系统内部状态的能力。服务端网络可观测性三支柱：①指标监控（Metrics）——QPS/延迟/错误率/资源使用率，工具Prometheus+Grafana ②链路追踪（Tracing）——一个请求经过所有服务调用的完整链路和耗时，工具Jaeger/Zipkin ③日志聚合（Logging）——请求日志/错误日志/审计日志，工具ELK/Loki。三者互补：指标告诉你「有问题」，追踪告诉你「在哪」，日志告诉你「为什么」。
</GlossaryItem>

</Glossary>
