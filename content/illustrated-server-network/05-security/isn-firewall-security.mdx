## 防火墙演进

<IsnFirewallSecurityDiagram />

防火墙是服务端网络的边界守卫，控制进出网络的流量。从简单包过滤到智能WAF，防火墙不断演进。

### 防火墙四代演进

| 代次 | 类型 | 工作层 | 原理 | 局限 |
|------|------|--------|------|------|
| 第一代 | 包过滤 | L3/L4 | 按IP/端口/协议过滤 | 不感知连接状态 |
| 第二代 | 状态检测 | L3/L4 | 跟踪连接状态 | 不解析应用层 |
| 第三代 | 应用网关 | L7 | 代理+深度检测 | 性能开销大 |
| 第四代 | WAF | L7 | 专防Web攻击 | 只防HTTP层 |

<Callout type="info" title="包过滤 vs 状态检测">

包过滤防火墙逐个检查每个数据包的IP/端口，不管这个包属于哪个连接。状态检测防火墙维护连接状态表——知道「这个包属于已建立的连接」，只放行属于合法连接的包。状态检测比包过滤更安全（防止伪造包混入），且性能优于应用网关（不需要完整代理）。

</Callout>

## ACL访问控制

ACL（Access Control List）是防火墙的核心规则表，定义哪些流量允许、哪些拒绝。

### ACL规则匹配

```text
ACL规则示例：
  规则1: 允许 源10.0.0.0/8 → 目的端口80    (允许内网访问HTTP)
  规则2: 允许 源10.0.0.0/8 → 目的端口443   (允许内网访问HTTPS)
  规则3: 允许 源0.0.0.0/0  → 目的端口22    (允许外网SSH) ← 危险!
  规则4: 拒绝 源0.0.0.0/0  → 目的端口3306  (拒绝外网访问MySQL)
  规则5: 拒绝 所有                         (默认拒绝)

匹配原则：从上到下，首次匹配生效
  → 外网访问80 → 规则3? 不匹配 → 规则4? 不匹配 → 规则5 拒绝
  → 内网访问80 → 规则1 匹配 → 允许 ✓
```

<Callout type="warning" title="ACL安全原则：默认拒绝">

安全最佳实践是「默认拒绝（Default Deny）」——最后一条规则永远是「拒绝所有」，只明确放行需要的流量。这比「默认允许」安全得多——忘记拒绝的端口不会被暴露。iptables/安全组都遵循这个原则。

</Callout>

## WAF Web应用防火墙

WAF（Web Application Firewall）专门防护HTTP层的Web攻击，是传统防火墙无法覆盖的补充。

### WAF防护的常见攻击

| 攻击类型 | 原理 | WAF检测方式 |
|---------|------|------------|
| SQL注入 | 在输入中嵌入SQL语句 | 关键字/模式匹配 |
| XSS | 注入恶意JavaScript | 脚本标签检测 |
| CC攻击 | 大量合法请求压垮服务器 | 频率/行为分析 |
| 路径遍历 | 访问 ../../etc/passwd | 路径模式检测 |

```text
SQL注入示例：
  正常请求:  /login?user=admin&pass=123456
  注入攻击:  /login?user=admin'--&pass=anything
  WAF检测:   请求中包含 ' -- 等SQL关键字 → 拦截 ✗

XSS示例:
  正常请求:  /search?q=phone
  XSS攻击:  /search?q=<script>steal()</script>
  WAF检测:   请求中包含 <script> 标签 → 拦截 ✗
```

<Callout type="info" title="WAF vs 传统防火墙">

传统防火墙看IP/端口——「这个IP能访问80端口吗」，不关心HTTP内容。WAF看HTTP内容——「这个请求是不是SQL注入/XSS」。两者互补：传统防火墙挡网络层攻击，WAF挡应用层攻击。生产环境通常传统防火墙（安全组/iptables）+ WAF（Cloudflare/阿里WAF）组合使用。

</Callout>

## DDoS防御

DDoS（分布式拒绝服务）通过大量傀儡机发送海量请求，压垮服务器带宽或资源。

### DDoS攻击类型与防御

| 类型 | 攻击层 | 原理 | 防御 |
|------|--------|------|------|
| 流量型 | L3/L4 | 海量UDP/TCP包占满带宽 | 流量清洗/黑洞路由 |
| 协议型 | L3/L4 | SYN Flood耗尽连接 | SYN Cookie/连接限制 |
| 应用型 | L7 | 大量合法HTTP请求 | WAF频率限制/验证码 |

```text
SYN Flood攻击原理：
  攻击者发大量SYN → 服务器为每个SYN分配资源等待ACK
  → 攻击者永不发ACK → 服务器连接表耗尽 → 合法用户无法连接

防御 - SYN Cookie:
  服务器不分配资源，把状态编码进SYN-ACK的序列号返回
  → 客户端ACK带回序列号 → 验证通过才分配资源
  → 攻击者不回ACK → 服务器无资源消耗
```

<Glossary>

<GlossaryItem term="状态检测防火墙（Stateful Inspection）">
状态检测防火墙在包过滤基础上增加连接状态跟踪。它维护一张「连接状态表」，记录每个TCP连接的状态（SYN-SENT/ESTABLISHED/TIME-WAIT等）。只有属于已建立合法连接的数据包才被放行，伪造的非法包被丢弃。状态检测比简单包过滤更安全（防止伪造包注入已建立连接），性能优于应用层代理（不需要完整解析报文）。iptables的conntrack模块就是状态检测实现。
</GlossaryItem>

<GlossaryItem term="WAF（Web应用防火墙）">
WAF是专门防护HTTP/HTTPS应用层攻击的防火墙。它深度解析HTTP请求内容（URL/Header/Body/Cookie），检测SQL注入、XSS、CC攻击、路径遍历等Web攻击。传统防火墙只看IP/端口不关心HTTP内容，WAF填补了这个空白。常见WAF实现：Cloudflare、阿里云WAF、ModSecurity。生产环境通常传统防火墙+ WAF组合使用——前者挡网络层攻击，后者挡应用层攻击。
</GlossaryItem>

<GlossaryItem term="DDoS（分布式拒绝服务）">
DDoS是攻击者控制大量傀儡机（Botnet）同时向目标发送海量请求，耗尽带宽或服务器资源的攻击。分三类：①流量型——海量UDP/TCP包占满带宽（如UDP反射放大），防御靠流量清洗/黑洞路由 ②协议型——利用协议缺陷耗尽连接（如SYN Flood），防御靠SYN Cookie/连接限制 ③应用型——大量合法HTTP请求压垮应用，防御靠WAF频率限制/验证码。
</GlossaryItem>

<GlossaryItem term="ACL（访问控制列表）">
ACL是防火墙/路由器上的规则表，定义哪些网络流量允许通过、哪些被拒绝。每条规则包含源IP、目的IP、端口、协议、动作（允许/拒绝）。匹配原则是从上到下首次匹配生效。安全最佳实践是「默认拒绝」——最后一条规则永远是「拒绝所有」，只明确放行需要的流量。iptables、云安全组、AWS NACL都是ACL的实现。
</GlossaryItem>

</Glossary>

**问题 1：** 包过滤防火墙和状态检测防火墙的核心区别是什么？ACL的安全原则是什么？

<Answer>

包过滤防火墙逐个检查每个数据包的IP/端口/协议，不管这个包属于哪个连接，无法防止伪造包注入。状态检测防火墙维护连接状态表，知道每个包属于哪个TCP连接及其状态（SYN-SENT/ESTABLISHED等），只放行属于合法连接的包，能防止伪造包注入已建立连接。状态检测比包过滤更安全，性能优于应用层代理。ACL的安全原则是「默认拒绝」——最后一条规则永远是「拒绝所有」，只明确放行需要的流量。这比「默认允许」安全得多——忘记拒绝的端口不会被暴露。

</Answer>

**问题 2：** WAF防护哪些Web攻击？DDoS的三种攻击类型及防御方式是什么？

<Answer>

WAF专门防护HTTP应用层攻击：①SQL注入——在输入中嵌入SQL语句，WAF通过关键字/模式匹配检测拦截 ②XSS——注入恶意JavaScript脚本，WAF检测script标签拦截 ③CC攻击——大量合法请求压垮服务器，WAF通过频率/行为分析拦截 ④路径遍历——访问../../etc/passwd等，WAF检测路径模式拦截。DDoS三种攻击类型及防御：①流量型（L3/L4）——海量UDP/TCP包占满带宽，防御靠流量清洗/黑洞路由 ②协议型（L3/L4）——SYN Flood耗尽连接，防御靠SYN Cookie/连接限制 ③应用型（L7）——大量合法HTTP请求压垮应用，防御靠WAF频率限制/验证码。

</Answer>
