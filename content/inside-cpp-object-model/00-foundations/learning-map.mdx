## 从“语法背后留下什么”开始

《Inside the C++ Object Model》不是一本重讲 class syntax 的书。它追问 `class`、inheritance、virtual、constructor、template、exception 和 RTTI 被 compiler 接受后，object bytes、hidden parameters、tables、generated calls 与 lifetime protocol 怎样共同满足语言语义。

<Term def="C++ 对 object-oriented semantics 的语言支持，以及 compiler/ABI 为实现这些语义采用的底层 representation 与 transformation。">C++ object model</Term>

先预测一个 polymorphic derived object 至少包含哪些 subobjects/metadata，再用 layout dump 和 call output 验证。目标不是记住“vptr 在 offset 0”这种 target-specific 结论，而是能从 static/dynamic type、hierarchy 和 lifetime phase 推导合法行为，并知道哪些 bytes 需要实测。

## 官方第一版七章路线


<Term def="Addison-Wesley Professional 1996 年第一版按 Object Lessons 到 On the Cusp of the Object Model 排列的七章结构。">official seven-chapter route</Term>

### 第1章：Object Lessons

建立全书 vocabulary：simple、table-driven 与 prevailing C++ model；encapsulation 是否改变 layout；base subobject 如何加入；`struct/class` 的真实差异；pointer static type 与 object dynamic type 怎样产生 polymorphism。

```cpp
struct Base {
    int data = 1;
    virtual int value() const { return data; }
};

struct Derived : Base {
    int extra = 2;
    int value() const override { return data + extra; }
};
```

学习产物是第一张 object sketch：标出 Base subobject、Derived member、可能的 vptr、`Base*` view，以及 data/nonvirtual/virtual 三类访问的决议时机。

### 第2章：The Semantics of Constructors

判断 compiler 何时需要 synthesis：member/base default construction、virtual representation、virtual base；default memberwise copy 何时能 bitwise lower；explicit、argument、return value initialization 如何变换；member initializer list 的真实顺序。

学习产物是一份 constructor expansion：对每个 hidden/generated action 写明触发语义，不把“compiler 自动生成”误解为“所有 scalar 清零”或“必有一次 copy”。

### 第3章：The Semantics of Data

把 member name binding、data layout 与 address calculation 拆开；比较 static/nonstatic access；沿 ordinary、polymorphic、multiple、virtual inheritance 追踪 data；理解 pointer-to-data-member 是 class-relative locator。

学习产物是一张 target-scoped layout table：size/alignment、member/base offsets、fixed/runtime adjustment 与 ABI caveat 分栏记录。

### 第4章：The Semantics of Function

把 nonstatic call 改写为 hidden `this`；理解 name mangling 与 overload linkage；展开 virtual slot；在 multiple/virtual inheritance 中追踪 thunk 和 this/result adjustment；最后比较 member-function pointer 与 inline formal/local expansion。

```cpp
using Action = void (Controller::*)(int);

Action action = &Controller::start;
(controller.*action)(2);
```

学习产物是一条 call trace：static lookup -> symbol/slot -> incoming object view -> adjustment -> target body，并记录 optimizer 是否 devirtualize/inline。

### 第5章：Semantics of Construction, Destruction, and Copy

从 class declaration 契约进入完整 lifecycle：pure virtual destructor 仍需 definition；const virtual 必须匹配；most-derived object 从 virtual/direct bases 到 vptr/members/body 建立；copy 不 raw-copy dynamic identity；destruction 逆序退场。

学习产物是一张 phase state machine，能解释 constructor/destructor 中 virtual call 为什么只看到 active class，以及 exception 时为何只 unwind 已成功 subobjects。

### 第6章：Runtime Semantics

storage duration 决定 global/local-static/automatic/dynamic object 的触发边界；new-expression 组合 allocation 与 construction；array new 管理逐元素 rollback；placement new 在 external storage 开始 lifetime；temporary 按 materialization/full-expression/elision 推导。

```cpp
alignas(Node) std::byte storage[sizeof(Node)];
Node* node = new (storage) Node(args);
node->~Node();
```

学习产物是一份 ownership protocol：谁提供 storage、谁开始 lifetime、constructor throw 谁回滚、谁调用 destructor、谁最终 deallocate。

### 第7章：On the Cusp of the Object Model

template 把 dependent name/member body 推迟到 instantiation；exception runtime 创建 thrown object、搜索 try/catch 并 unwind；RTTI 通过 dynamic metadata 检查 cast/typeid；固定 layout/vtable 又形成 DSO/shared-memory ABI 边界。

学习产物是一份 late-decision matrix：definition/instantiation/runtime/link-load/process boundary 各自允许使用哪些 type/layout identity。

## 四层机制依赖


<Term def="base subobjects、nonstatic data、padding、vptr 与 virtual-base metadata 共同形成的对象字节/元数据结构。">object representation</Term>

第 1/3 章提供 representation，第 2/4 章把 source operations lower 到这份 representation，第 5/6 章规定 representation 在何时有效、复制和撤销，第 7 章才使用 compile/runtime metadata 做更晚决议。跳过 dependency 会出现典型误解：只画 vtable 不画 incoming base view；只说 new 分配内存不说 lifetime；只说 RTTI 查类型不说 DSO identity。

<Term def="compiler 为保持 object semantics 而插入 hidden this/result、base/member constructor、vptr setup、thunk、cleanup 等动作。">program transformation</Term>

<Term def="object/subobjects 从未构造、逐层有效、完整动态状态、逐层析构到 lifetime 结束的有序阶段。">lifetime state machine</Term>

<Term def="把 name/type/handler/target 的最终选择从 definition 推迟到 template instantiation、throw 或 runtime type query。">deferred decision</Term>

## 三栏证据法


<Term def="由 C++ language rules 保证、在 conforming implementations 间应保持相同 observable behavior 的结论。">language guarantee</Term>

<Term def="特定 compiler、target、calling convention 与 binary interface 为实现语言语义采用的布局和符号协议。">implementation ABI</Term>

<Term def="固定 toolchain/options/workload 后，通过 layout、symbols、assembly、counters 或 profiler 得到的可复现实测事实。">experimental evidence</Term>

每份笔记至少三栏：标准保证什么；当前 ABI 怎样做；本次实验观察到什么。比如“virtual call 选 final overrider”是 language guarantee，“对象首字段为 vptr”不是；“当前 Itanium ABI build 在 offset 0 放 vptr”可以是 experiment+ABI conclusion。

<Callout type="trap" title="陷阱：把书中主流实现模型当成标准规定">
  本书解释 prevalent implementation，帮助推导成本；C++ standard 不规定 vptr
  位置、vtable shape、member-pointer bytes 或 exception table。引用任何 layout
  数字时都附 compiler、target ABI、language mode 和 options。
</Callout>

## 七章学习循环

每章使用同一闭环：

1. 写出 source-level contract 与预测行为；
2. 画 object/subobject/call/lifetime representation；
3. 写最小 probe，记录 output、addresses、counts；
4. 查看 optimized assembly/symbol/layout 或 runtime metadata；
5. 把 observation 归类为 language、ABI 或 optimizer choice；
6. 用 exercise 迁移到 multiple/virtual inheritance、failure path 或 boundary case；
7. 将结论写成带适用范围的 engineering decision。

<Term def="先预测语义与实现路径，再用最小实验和优化后证据验证，最后限定结论适用边界的学习方式。">predict-observe-bound loop</Term>

<Callout type="trap" title="陷阱：只看一次sizeof或反汇编就宣称掌握对象模型">
  单一 observation 不能覆盖 construction phase、multiple
  inheritance、copy/elision、 exception path 或跨 module
  ABI。至少改变一个关键维度并重跑；若结论随 ABI/options 变化，就把它保留为
  implementation fact，不推广为 language rule。
</Callout>

## 完成标准

完成这条路线后，应能对一个陌生 hierarchy 输出四份工件：object layout sketch、member call lowering、construction/copy/destruction state machine、ABI boundary review。答案必须同时解释 correctness 与 cost，且每个 target-specific 结论都有可重复证据。

## 小结

- 官方第一版是 7 章，不是按 vtable/RTTI 等零散主题拼出的 8 页摘要
- 第 1/3 章建立 representation，第 2/4 章解释 compiler transformations
- 第 5/6 章把 representation 放入完整 object/storage lifetime
- 第 7 章处理 template、exception、RTTI 的 deferred decisions 与 ABI 边界
- language guarantee、implementation ABI、experimental evidence 必须分栏
- vptr/vtable 是常见实现，不是标准固定 bytes
- predict-observe-bound loop 让每个结论既可验证又不过度推广
- 最终产物是 layout、call、lifecycle、boundary 四份机制证据，而不是术语背诵

  storage/allocation/temporary ownership protocol；Ch7
  instantiation/exception/RTTI/ABI boundary matrix。每份工件都以上一层

2. **问题 2：拆分一条“virtual函数慢”的说法。** 分别写 language guarantee、ABI hypothesis、experiment 和 design decision。

<Answer question="怎样把模糊性能判断改成可验证结论？">
  guarantee 是 dynamic call 必须产生 final overrider 的 observable result；ABI
  hypothesis 是 vptr+slot+可能 thunk；experiment 固定 target
  distribution/body，记录 devirtualization、 indirect branch、this
  adjustment、branch miss 与 wall time。若热点 tiny body 且多 target
  导致明显回归，可考虑 variant/static dispatch；若 compiler 已 devirtualize 或
  body 主导，则保留 hierarchy。结论只适用于该 workload/toolchain。
</Answer>

3. **问题 3：设计一个跨章节 probe。** hierarchy 同时含 virtual base、virtual method、copy、array new 和 failed constructor；写出预期 trace 与证据分类。

  <Answer question="一个实验怎样覆盖representation、transformation和lifetime？">
    先画唯一 virtual base、direct bases、members 与 vptr views；记录 constructor calls 应从
    virtual base 到 direct bases/members，virtual dispatch 受 active phase 限制。copy
    建立 target vptr/virtual base，不 raw-copy identity。array 第 k 个 throw 时仅逆序销毁前
    k 个完整 elements，再释放 allocation。call order 属 language semantics，具体 vptr/
    offsets/cookie 属 ABI observation；计数与 addresses 是本次 experimental evidence。
  </Answer>
</Exercises>
