## 三种对象模型

要理解 C++ 对象在内存里长什么样，Lippman 先抛出三种假想模型作对照。第一种是「简单对象模型」：对象内存里不直接放成员，而是存一张指针表，每个槽位指向一个成员。所有成员存取都经一次间接，简单但慢，而且每个对象要多存一张表，空间开销大。

第二种是「表格驱动对象模型」：把数据成员和成员函数分成两张表，对象只存这两张表的指针。它进一步把数据和函数解耦，但同样逃不开间接开销。

## C++ 对象模型

真正落地的是第三种「C++ 对象模型」，它做了一个关键取舍：非虚数据成员直接内联在对象里，存取就是一次偏移，零间接、零额外空间；只有需要多态的虚函数才付一次间接代价——通过对象里的 vptr 指向虚表，虚表里存函数指针。

这个折中的哲学是：绝大多数成员访问走快路径，只有虚函数走慢路径。你为多态能力付的代价，被精确地限制在「需要它的那部分」。

## 对象里有什么

在 C++ 对象模型下，一个对象内存通常包含：非静数据成员（直接内联）、若类有虚函数则多一个 vptr。成员函数的代码不放在对象里——所有成员函数共享一份代码，存在代码段，调用时把对象地址作为 this 隐式传入。静态成员也独立于对象存在，存于全局数据段。

所以一个没有虚函数、只有普通成员函数和几个数据成员的类，它的 `sizeof` 只反映数据成员布局（含对齐 padding），与成员函数的多少无关。

## 模型选择的代价

把三种模型放在一起看，能更清楚 C++ 模型付了什么代价、又省下了什么。简单对象模型和表格驱动模型把所有成员都做成间接存取，结果是每个对象都背着一堆指针、每次访问都要解引用——抽象很纯粹，但运行太慢、空间太胖。C++ 模型的洞察在于：绝大多数成员访问根本不需要多态，没必要为它们付间接代价。

于是 C++ 把成员分成两类区别对待：非虚数据成员直接内联，存取是一次偏移，零间接、零额外空间，这是快路径；虚函数因为要在运行期决定调用哪个版本，才引入 vptr 与 vtable 做间接，这是慢路径。你为多态付的代价被精确限制在「需要它的那部分」。这也是为什么「加 virtual」不是免费午餐——一旦类有了虚函数，每个对象都恒定多出一个 vptr，哪怕你从不调用它。理解这套「按需付费」的哲学，是判断何时该用虚函数、何时该用非虚甚至模板多态的基础。

<Callout type="tip">
<strong>建议 →</strong> 用 `sizeof` 当探针：给一个类逐步加 virtual 函数、加静态成员、改成员顺序，观察 `sizeof` 的变化。你会亲眼看到 vptr 占了一个指针大小、静态成员不计入、padding 随顺序伸缩——这是理解对象模型最直观的方式。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 以为「加了 virtual 但不调虚函数就没开销」，结果对象数组内存翻倍。<strong>原因 →</strong> 只要类有虚函数，每个对象都恒定多出一个 vptr，与你是否调用无关；这是空间开销，不是「用时才付」。<strong>修法 →</strong> 把「加 virtual」当结构性决定：只在确需多态的类上用虚函数，大头对象数组尤其要避免无谓的 vptr。
</Callout>

## 小结与练习

- 三种模型：简单（全间接）、表格驱动（数据/函数分表）、C++（数据内联 + 虚函数间接）
- C++ 模型把间接代价限定在虚函数，非虚成员存取走快路径
- 对象内存 = 非静数据成员 + 可能的 vptr；成员函数代码全类共享、不计入对象
- 加 virtual 是结构性决定，vptr 开销恒定存在

<Exercises>
  <Answer question="为什么 C++ 选择「数据内联 + 虚函数间接」而不是简单对象模型的全间接？">权衡空间与速度。全间接每个成员都要一次指针解引用，存取慢，且对象要多存指针表，空间大。C++ 模型把非虚数据成员直接内联，存取是一次偏移、零间接零额外空间；只为需要多态的虚函数付一次间接（vptr + vtable）。绝大多数访问走快路径，只有虚函数走慢路径，是抽象与效率的折中。</Answer>
  <Answer question="一个只有普通非虚成员函数、无虚函数的类，它的 sizeof 包含成员函数指针吗？为什么？">不包含。C++ 对象模型里非虚成员函数代码全类共享、存在代码段，对象里只放数据成员（和可能的 vptr）。没有虚函数就没有 vptr，所以 sizeof 只反映数据成员布局含对齐 padding，与成员函数多少无关。成员函数调用在编译期绑定到具体函数，不需要对象里存指针。</Answer>
</Exercises>
