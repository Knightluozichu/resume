## 对齐与 padding

C++ 对象模型把非虚数据成员直接内联在对象里，但成员不是紧密排列的。为了让每个成员落在自身对齐要求的整数倍地址上（硬件访问对齐数据更快），编译器会在成员之间插入空白字节，这就是 padding。

看一个例子：`struct { char c; int i; double d; }`。char 占 1 字节，但要让 int 落在 4 字节边界，后面得插 3 字节 padding；double 要落在 8 字节边界。最终这个结构体可能占 16 字节，其中 3 字节是 padding。整个结构体还要对齐到最大成员（double）的 8 字节边界，末尾可能再补 padding。

## 成员顺序影响 sizeof

同样是这三个成员，把声明顺序调成 `double d; int i; char c;`，sizeof 可能从 16 缩到 16 或更小——关键是大对齐成员放前面、小的放后面，能减少中间的 padding。所以成员声明顺序不是无所谓的小事，它直接决定对象大小，在对象数组、缓存敏感场景下影响巨大。

## 空类与特殊成员

空类 `struct Empty {}` 没有任何成员，但 sizeof 通常是 1。原因是 C++ 要保证同一类型的两个不同对象地址不同，得给空对象一个字节的占位。

静态成员存于全局数据段，所有对象共享一份，不属于任何单个对象，所以不计入 sizeof。位域则把多个小字段压进尽量少的存储单元，比如 `int a:3; int b:3; int c:2;` 共 8 位，可压进 1 个字节。

## 对齐规则与边界

对齐的具体规则可以总结成两条：一是每个成员要落在自身大小（或编译器设定的对齐值，取较小者）的整数倍地址上；二是整个结构体的大小要是其最大成员对齐值的整数倍，不够就在末尾补 padding。成员的对齐值通常等于其大小——char 对齐 1、short 对齐 2、int 与 float 对齐 4、double 与指针对齐 8（64 位下）。理解这两条，就能徒手算出任意结构体的 sizeof。

这套规则在工程上的影响远超「省几个字节」。当对象被放进数组、或成为缓存敏感的热数据时，padding 直接决定了一个缓存行能装下几个有效对象——一个被 padding 撑大一半的结构体，会让缓存命中率显著下降。此外还要注意：含指针成员的类在 32 位与 64 位下 sizeof 不同（指针从 4 变 8），跨平台序列化时不能直接 memcpy 对象布局，否则对齐与字节序都会出问题。

需要时也可以显式干预对齐：`#pragma pack` 或 C++11 的 `alignas` 能压缩或放宽对齐值，`alignof` 能查询某类型的对齐要求。但干预对齐是把双刃剑——压缩对齐可能让某些架构上的未对齐访问变慢甚至崩溃，放宽对齐则白白浪费空间。除非有明确的对齐需求（比如匹配硬件寄存器、做 SIMD 向量化），否则让编译器按默认规则对齐最稳妥。

<Callout type="tip">
<strong>建议 →</strong> 性能敏感的结构体，按对齐值从大到小排列成员。把 double、指针放前面，int、short 依次，char 和位域垫底。这是不改逻辑、只靠重排换内存与缓存友好度的零成本优化。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 对象数组内存占用比预期大很多，缓存命中率差。<strong>原因 →</strong> 成员顺序不佳让 padding 撑大对象，一个本该 12 字节的对象变成 24 字节，数组里一半是空气。<strong>修法 →</strong> 重排成员压缩 padding；把冷数据（调试字段、罕见属性）拆到独立结构或用指针间接，避免冷字段污染缓存行。
</Callout>

## 小结与练习

- 对齐让成员落在自身边界上，padding 是为此插入的空白字节
- sizeof = 成员占用 + padding，整体对齐到最大成员的对齐值
- 成员声明顺序影响 sizeof：大对齐成员放前面可压缩 padding
- 空类占 1 字节、静态成员不计入、位域可压缩小字段

<Exercises>
  <Answer question="struct {char c; double d; int i;} 的 sizeof 为什么可能是 24，而调成 double d; int i; char c; 后可能缩到 16？">对齐导致 padding。原顺序 char(1B) 后要让 double 落在 8 字节边界，插 7B padding，再 double(8B)，再 int(4B)，末尾补 4B 对齐到 8，合计 24B。调序后 double(8B) 先放，int(4B) 紧跟，char(1B) 再跟，末尾补 3B 对齐到 8，合计 16B。大对齐成员放前面能压缩 padding。</Answer>
  <Answer question="空类 struct Empty {} 的 sizeof 是多少？为什么？静态成员算不算进对象大小？">空类 sizeof 通常是 1。虽然它没有成员，但 C++ 要保证同一类型的两个不同对象地址不同，所以给 1 字节占位。静态成员不算进对象大小——它存于全局数据段、所有对象共享一份，不属于任何单个对象，sizeof 只反映一个实例的非静成员布局。</Answer>
</Exercises>
