## 一张图串起全书

走到这里，我们已经把《深度探索 C++ 对象模型》的五大主题过了一遍：对象在内存里的布局、对象怎么被构造出来、成员函数怎么被调用、运行时多态怎么实现、继承与生命周期。这五块不是孤立的，它们由一个共同的枢纽串起来——vptr。

## 以 vptr 为枢纽

vptr 贯穿构造、使用、析构三阶段，是全书最重要的线索。构造期，vptr 先指向基类虚表、最后才改指向派生类虚表。使用期，虚调用经对象的 vptr 查 vtable 槽位、间接调到正确版本，多态生效；RTTI 也靠 vptr 找到挂在虚表上的 type_info。析构期，vptr 先改回基类虚表再析构派生部分，虚函数又退化为基类版本。

理解了 vptr 在这三个阶段的去向，就理解了为什么构造析构期虚函数会退化、为什么多态只在构造完成后到析构开始前生效、为什么多重继承的对象要有多个 vptr、为什么没有虚函数就没有 RTTI。vptr 是「布局—构造—多态—生命」四大主题的共同枢纽。

## 主线一句话

全书可以用一句话概括：对象在内存里长什么样 → 怎么被造出来 → 怎么调用与多态 → 怎么消亡。这个顺序由依赖关系决定，也是推荐的复习路径：不先懂对象布局，就看不懂构造时 vptr 为什么被两次设置；不懂构造语义，就看不懂多态生效的窗口；不懂运行时多态，多重继承的 this 调整与虚继承就成了无源之水。

## 三问诊断法

把全书压成一条可操作的诊断线索，可以总结为「三问」：遇到任何 C++ 对象行为的问题，先问——对象内存里有什么？构造析构时 vptr 怎么变？这次调用走没走虚表？这三问覆盖了布局、构造、多态三大主题，能解释绝大多数看似诡异的运行期行为。

比如「基类构造函数里调虚函数为什么没走派生覆写」，三问依次回答：对象内存里有 vptr；构造期 vptr 先指向基类虚表、还没改到派生类；这次调用走了虚表，但查到的是基类版本——答案自然浮现。再比如「delete 基类指针为何派生部分没析构」，三问回答：对象内存里有 vptr；析构链是否走虚表取决于析构是否虚函数；若析构非虚，这次 delete 没走虚表、编译期静态绑定基类析构——派生部分被跳过。养成用这三问拆解问题的习惯，对象模型就从一堆零散结论变成了一台可推演的机器。

<strong>建议 →</strong> 复习时别逐章背，而是用「vptr 此刻指向谁的虚表」这条线索把各章串起来。遇到任何对象模型的问题，先问三句：对象内存里有什么？构造析构时 vptr 怎么变？这次调用走没走虚表？这三问能解释绝大多数 C++ 对象行为。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 代码同时踩了三个坑：基类析构非虚却 delete 基类指针、构造函数里调虚函数期望走派生覆写、菱形继承未虚继承导致访问基类成员二义。<strong>原因 →</strong> 三者都是对象模型没吃透的典型表现——虚析构、构造期 vptr、虚继承。<strong>修法 →</strong> ① 基类析构声明 virtual，经 vptr 走派生析构完成反向析构链；② 别在构造里调虚函数做派生行为，改为构造后显式调 init；③ B1、B2 用 virtual 继承 Base，共享 Base 只存一份，经 vbptr 间接定位。
</Callout>

## 小结与练习

- 全书五大主题：对象布局、构造语义、函数模型、运行时多态、继承与生命周期
- vptr 是布局—构造—多态—生命的共同枢纽，贯穿构造使用析构三阶段
- 多态只在构造完成到析构开始之间生效，构造析构期虚函数退化
- 主线：对象长什么样 → 怎么造 → 怎么调用多态 → 怎么消亡

  <Answer question="用 vptr 这条线索，解释为什么「构造期调虚函数不走派生覆写」和「多态基类析构必须虚」是同一个机制的两面。">两者都源于 vptr 在构造析构期的行为。构造派生对象时 vptr 先指向基类虚表，基类构造函数运行期间虚调用经 vptr 查到的是基类版本，派生覆写没接上——这是「构造期不走派生覆写」。析构反向：若基类析构非虚，delete 基类指针时编译期按静态类型绑定基类析构、不查虚表，派生部分不析构；只有虚析构才经 vptr 走到派生析构。两者都是「vptr 此刻指向谁」决定的——构造期指基类、使用期指派生、析构期先改回基类。</Answer>
  <Answer question="设计一个高性能多态对象池，需要兼顾虚函数多态、紧凑内存布局、避免构造期陷阱、正确析构。给出设计要点。">① 多态：基类提供虚接口含虚析构，派生覆写，经基类指针走虚表多态。② 紧凑布局：成员按对齐值从大到小排列压 padding，热数据聚在前一个缓存行，冷数据拆出或用指针间接。③ 对象池：预分配连续内存，对象在其中 placement new 构造、显式析构，注意 vptr 仍由 placement new 正确设置。④ 避免构造期陷阱：构造函数里不调虚函数做派生行为，需初始化后置行为就构造完成后单独调 init。⑤ 析构：归还池时显式调析构（不 delete 内存），虚析构保证派生部分正确清理；析构期同样不调虚函数做派生行为。⑥ 池管分配释放（阶段①⑤），构造析构（阶段②④）按 C++ 规则走，多态窗口（阶段③）只在构造完成后到析构前。</Answer>
