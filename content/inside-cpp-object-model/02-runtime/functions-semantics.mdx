## 成员函数不是「属于对象」

一个常见误解是：每个对象里都存着自己的成员函数。其实不是。在 C++ 对象模型里，所有成员函数共享一份代码，存在代码段，对象里只放数据成员（和可能的 vptr）。调用 `obj.f(a)` 时，编译器把它改写成 `Foo::f(&obj, a)`——把对象地址作为隐式首参传入，这个参数就是 this 指针，始终指向调用该函数的对象实例。

所以成员函数的差别，不在「代码放哪」（都共享一份），而在「如何找到它」和「何时决定调哪个」。

## 四种调用模型

非虚成员函数在编译期就决议，调用点直接绑定到 `Foo::f`，经 this 直调，等同普通函数调用，开销最小。虚成员函数在运行期决议，调用点先取对象的 vptr、查 vtable 对应槽、再间接调用，多一次查表间接——这是多态的代价。静态成员函数没有 this 注入，与普通函数完全等价，不能访问非静成员。内联展开则把函数体替换到调用点，省去调用开销，但可能增大代码体积。

## 多态只认指针和引用

一个微妙点：虚函数的多态只在通过指针或引用调用时才生效。如果你用一个值类型的对象 `obj.h()` 调虚函数，编译器已经知道确切静态类型，会直接绑定甚至内联，不查虚表。只有 `ptr->h()` 才走虚表、运行期决议。

## 调用开销的真实差距

把四种模型的调用开销排个序，能看清虚函数到底贵在哪。非虚调用与静态调用等同普通函数，开销最小，且能被内联——内联后连调用栈帧都省了，是性能最优的路径。虚调用多了一次经 vptr 的间接寻址，更要命的是它基本无法内联：编译器在调用点不知道运行期会命中哪个版本，没法把函数体替换进来。对一个频繁调用的小虚函数，这点开销会被放大成可观的性能损失。

这也是为什么实践中常有「把多态从运行期挪到编译期」的优化思路：如果派生类型在编译期就能确定，用 CRTP（奇特的模板递归模式）或 `if constexpr` 把虚调用变成模板静态绑定，既保留了多态的表达力，又省掉了虚表间接、还能内联。当然这一切的前提是——你确实在热点路径上、且 profiler 证实虚调用是瓶颈。多数场景下虚调用的开销可以忽略，别为想象中的性能过早放弃多态的清晰设计。

最后要澄清一个常见混淆：成员函数无论非虚还是虚，其代码都不存在对象里，而是全类共享一份、放在代码段。对象里只有数据成员与可能的 vptr。所以「同一类型的所有对象调用同一个成员函数」其实是调用同一段代码，区别只在调用点如何找到它——非虚靠编译期绑定、虚靠运行期经 vptr 查表。理解这一点，就不会再误以为「每个对象都存着自己的函数」。

<Callout type="tip">
<strong>建议 →</strong> 热点路径里别用小虚函数。虚调用多一次间接、且基本无法内联，频繁调用会放大开销。能用非虚就别用虚；确需多态又在意性能时，考虑在循环外把虚调用结果缓存，或用 CRTP 把运行期多态转为编译期多态。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 以为「同一个虚函数用对象值调用和用指针调用行为一样」，结果值调用被内联优化、指针调用却走虚表，性能差异巨大。<strong>原因 →</strong> 值调用时编译器掌握确切类型，直接绑定甚至内联；指针调用才运行期经 vptr 查表，无法内联。<strong>修法 →</strong> 记住多态只认指针和引用；想优化虚调用，要么改成非虚、要么用值调用场景（如能确定类型）。
</Callout>

## 小结与练习

- 成员函数代码全类共享、存代码段，对象里不存函数指针
- obj.f(a) 被改写为 Foo::f(&obj, a)，&obj 即 this；静态函数无 this
- 非虚编译期直调、虚运行期经 vptr 间接、静态等同普通函数、内联零开销
- 多态只在指针/引用调用时生效，值调用会直接绑定甚至内联

## 名词解释

<Glossary>
  <GlossaryItem term="this 指针">成员函数调用时编译器隐式传入的对象地址首参，指向调用该函数的对象实例；静态函数无 this。</GlossaryItem>
  <GlossaryItem term="非虚成员函数">编译期决议、调用点直接绑定到具体函数、经 this 直调的成员函数，开销等同普通函数。</GlossaryItem>
  <GlossaryItem term="虚成员函数">运行期经对象的 vptr 查 vtable 槽位、间接调用的成员函数，支持多态但多一次间接。</GlossaryItem>
  <GlossaryItem term="静态成员函数">无 this 注入、与普通函数等价、不与具体对象绑定的成员函数，不能访问非静成员。</GlossaryItem>
</Glossary>
