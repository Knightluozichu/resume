## 常见误区与故障注入

<Callout type="trap" title="陷阱：前缀有序就已经证明排序正确">

现象：证明只写“每轮结束时前缀有序”，却没有说明元素没有被删除、复制或改值。

原因：有序性只说明关系，不说明输出仍是输入的排列；算法可以返回一个更短的有序序列而不违反这句弱命题。

修复：不变量同时声明前缀有序和多重集保持，终止时再推出整个数组满足输出合同。

</Callout>

<Callout type="trap" title="陷阱：把 key 放回去以后就不用检查边界">

现象：代码在索引为零时继续减一，或用 `>=` 跨过相等元素，却仍声称实现了稳定插入排序。

原因：循环条件既决定索引是否安全，也决定相等元素是否改变相对顺序；实现细节正是证明的边界。

修复：使用 `i > 0 && A[i - 1] > key`，先移动严格更大的元素，再把 key 写入空位，并测试空数组、单元素和重复值。

</Callout>

<Callout type="trap" title="陷阱：看见两层循环就直接报 Θ(n²)">

现象：任何输入都被贴上同一个二次复杂度标签，已排序和近乎有序数据的行为被忽略。

原因：内层执行次数由每个 key 前面的更大元素决定；输入形状和统计的操作种类会改变成本账本。

修复：记录比较、移动和写回次数，区分最好、最坏、平均及 `Θ(n+k)` 的参数化表达，并声明概率模型。

</Callout>

<Callout type="trap" title="陷阱：分治算法更快，所以总是更适合">

现象：看到 merge sort 的 `Θ(n log n)` 就忽略它的缓冲区、递归和小数组常数。

原因：渐近增长率描述规模趋势，却不自动决定缓存、移动语义、内存预算和短输入上的交叉点。

修复：把正确性与成本分开证明，在约束允许时使用混合策略，并用代表性输入基准选择阈值。

</Callout>

## 核心术语与证据所有权

<Term def="在循环每次迭代的特定时刻都成立、可用于连接初始状态和终止结论的命题。">循环不变量</Term> 不是“代码看起来合理”的描述，而是要能被初始化、保持和终止三段论证共同使用的命题。

<Term def="已经按非降序排列、并且包含原数组相应元素的前半段；插入排序每一轮都把它扩大一格。">有序前缀</Term> 是插入排序的状态摘要。只说它有序还不够，还要保留元素多重集。

<Term def="从左到右扫描序列，维护一个有序前缀，并把当前 key 插入到前缀正确位置的增量排序算法。">插入排序</Term> 用局部移动换取简单的状态和原地实现。

<Term def="描述输入随问题规模增长的量，例如元素个数 n、图的顶点与边或整数的 bit 数。">输入规模</Term> 让不同实例的时间、空间和 I/O 成本有共同坐标。

<Term def="序列中满足 i 小于 j 且 A[i] 大于 A[j] 的下标对；它衡量输入离有序还差多少。">逆序对</Term> 能把近乎有序输入的实际工作量写成参数，而不只报告最坏阶。

<Term def="把大问题拆成子问题，分别求解后用一个可证明的 combine 步骤合并答案的设计方式。">分治设计</Term> 将局部正确性和递推成本连接起来。

术语核对顺序是：状态命题负责正确性，输入规模负责成本坐标，逆序对负责输入依赖，分治设计负责另一条算法构造路线。后文不会用“复杂度”掩盖究竟统计了哪一种操作。

## getting started / 入门

入门不是先记住一个 API，而是先把问题写成可以反驳的合同。对排序而言，输入是有限的可比较序列；输出需要非降序，还必须是输入的排列。空序列、单元素、重复键和负数都属于应被合同覆盖的实例，而不是“以后再处理”的例外。

插入排序把这个合同拆成一个很小的状态：左侧是已经解决的部分，右侧是尚未处理的部分。外层循环每次取出一个 key，内层循环把前缀中严格更大的元素向右移动，最后把 key 写入留下的空位。这个动作既改变局部位置，也保留全体元素的多重集。

```text
INSERTION-SORT(A)
1  for j = 2 to A.length
2      key = A[j]
3      i = j - 1
4      while i > 0 and A[i] > key
5          A[i + 1] = A[i]
6          i = i - 1
7      A[i + 1] = key
```

### 用循环不变量证明

在第 `j` 轮开始时，命题是：“`A[1..j-1]` 已按非降序排列，并且包含原数组前 `j-1` 个元素的同一多重集。”

1. **Initialization**：第一轮开始时只有 `A[1]`，单元素序列有序，且没有丢失元素。
2. **Maintenance**：保存 key；每次只把严格大于 key 的前缀元素右移，移动不会改变多重集；key 写入第一个不大于它的空位后，新前缀仍然有序。
3. **Termination**：当 `j` 越过数组末端，前缀覆盖整个数组；不变量同时给出非降序和排列保持，于是得到完整排序合同。

若只写“前缀有序”，第二段不能推出排列保持。反过来，若只做频数检查，也不能推出输出有序。完整证明需要同时携带关系和所有权证据。

## insertion sort / 插入排序

### 一次插入的边界

对于 `key`，内层扫描从右向左进行。遇到 `A[i] > key` 才右移，遇到 `A[i] <= key` 就停止。于是相等的元素留在 key 左侧，稳定性来自这个严格不等式，而不是来自语言或容器名称。

```cpp
void insertion_sort(std::vector<int>& a) {
    for (std::size_t j = 1; j < a.size(); ++j) {
        int key = a[j];
        std::size_t i = j;
        while (i > 0 && a[i - 1] > key) {
            a[i] = a[i - 1];
            --i;
        }
        a[i] = key;
    }
}
```

实现审核要问三件事：key 是否在覆盖原位置前被保存；索引是否在零位置停止；重复值是否保留相对顺序。它们正好对应前面的证明义务，不是三个互不相关的风格偏好。

### 从插入动作到合并动作

插入排序每次把一个元素接入已有答案，是增量思路。另一个选择是先把数组分成两半，各自排序，再合并两个有序序列。合并时比较两个序列当前最小的 front，取较小者追加到输出；一侧耗尽后，另一侧剩余部分可以整体追加。

```text
MERGE(left, right)
1  output = empty sequence
2  while left and right are both nonempty
3      append the smaller front to output
4  append the nonempty remainder
5  return output
```

合并的循环不变量是：“`output` 已包含两个输入中最小的若干元素，并且保持非降序；两个 front 分别是各自尚未输出部分的最小元素。”初始化时输出为空；每次选择更小 front 保持命题；终止时所有元素恰好被输出一次。

## analyzing algorithms / 算法分析

### RAM 模型与输入规模

分析前要写出模型。常见 RAM 模型把索引、普通整数的比较和一次数组访问视为常数成本，但它不允许把任意长整数乘法、磁盘读取或网络调用偷偷算作一步。输入整数有 `b` 个 bit 时，加法成本可能依赖 `b`；输入在磁盘时，I/O 次数可能支配 CPU 指令。

排序通常以元素数 `n` 作为输入规模，但报告还要说明元素是否定长、比较是否昂贵、是否包含输出分配和 I/O。原地插入排序只保存 key 与索引，辅助空间是 `Θ(1)`；merge sort 的缓冲区通常需要 `Θ(n)`，递归栈另有 `Θ(log n)`，但会被线性缓冲区支配。

### 最好、最坏、平均与参数化成本

已排序输入中，每一轮 while 的第一次比较就失败，运行时间是 `Θ(n)`。逆序输入中，第 `j` 轮移动 `j` 个元素：

$$
\sum_{j=1}^{n-1}j=\frac{n(n-1)}2
$$

因此最坏时间为 `Θ(n²)`。若所有排列等概率，期望逆序对为 `n(n-1)/4`，插入排序平均时间仍为 `Θ(n²)`。但若输入只含 `k` 个逆序对，移动量跟 `k` 直接相关，可以报告 `Θ(n+k)` 的参数化成本，这更能解释它为何适合小数组和近乎有序数据。

“平均”不是“我随便测了几次”。它必须声明样本空间或概率分布；“最坏”则是对所有合法实例的上界。两者都要标明统计对象：比较次数、右移次数、写回次数还是总 RAM 操作。

### 可核查的成本账本

设第 `j` 轮 while 测试 `t_j` 次。外层边界、key 保存和最终写回提供固定项，内层比较和移动提供与输入相关的项，因此总成本是固定项加上若干个 `t_j` 的组合。已排序输入里 `t_j` 近似为常数；逆序输入里 `t_j` 随 `j` 增长；同一份代码因此产生两份不同账本。

比较次数与移动次数也不是同一指标。昂贵对象的移动可能远高于整数比较，连续内存移动也可能比指针结构的少量比较更快。渐近阶回答规模增长，操作分类与基准则解释相同阶数实现之间的工程差异。

## designing algorithms / 算法设计

### 增量与 divide-and-conquer

插入排序的设计问题是：“若前 `j-1` 项已经解决，怎样把第 `j` 项接进去？”这是增量设计。归并排序提出另一种问题分解：

1. **Divide**：把长度为 `n` 的数组分成两个近半区间；
2. **Conquer**：递归地排序两个区间；
3. **Combine**：用线性 merge 合并两个有序结果。

```text
MERGE-SORT(A, p, r)
1  if p >= r
2      return
3  q = floor((p + r) / 2)
4  MERGE-SORT(A, p, q)
5  MERGE-SORT(A, q + 1, r)
6  MERGE(A, p, q, r)
```

### 正确性与递推分开证明

正确性使用归纳：长度为一的区间已经有序；假设两次递归返回有序排列，merge 的不变量保证合并结果仍有序且保留多重集，因此当前区间正确。

成本使用递推：两次半规模递归各贡献 `T(n/2)`，merge 线性扫描两侧贡献 `Θ(n)`，得到

$$
T(n)=2T(n/2)+\Theta(n),\qquad T(1)=\Theta(1)
$$

递归树每一层总成本是 `Θ(n)`，高度是 `Θ(log n)`，所以 `T(n)=Θ(n log n)`。这个结论不来自“看起来更高级”，而来自平衡切分、线性 combine 和基例共同组成的证明。

### 混合策略的工程出口

merge sort 的增长率通常优于插入排序，却需要缓冲区和递归管理；小数组上，插入排序较低的固定开销和更好的局部性可能更有利。实际库可以在大区间使用分治，在小区间切换插入排序，前提是两个分支拥有同一个输出合同。

切换阈值不是复杂度定理。应在目标机器上使用随机、近乎有序、逆序和重复值样本测量，并记录元素大小、移动语义、缓存和分配方式。正确性证书保证“选哪条分支都返回排序排列”，成本证书再说明“每种分支在哪个范围有效”。

<Exercises>

1. 对序列 `[5, 2, 2, 4]` 写出插入排序每轮开始时的循环不变量，并分别指出它如何证明有序性与排列保持。为什么 `>=` 会破坏稳定边界？

   <Answer>

   每轮开始时，`A[0..j)` 按非降序排列，并包含原数组前 `j` 个元素的同一多重集。右移严格大于 key 的元素保持多重集，key 写入空位后得到新的有序前缀；终止时前缀覆盖整个数组。若条件改为 `>=`，相等元素也会跨过 key，带 payload 的记录可能交换相对顺序，因此不再保证稳定。

   </Answer>

2. 令 `n=6`，比较已排序、逆序和只有两个逆序对的输入。分别估计移动量，并说明为什么“平均时间”需要额外的输入分布假设。

   <Answer>

   已排序输入的移动量为 0；逆序输入的移动量为 `1+2+3+4+5=15`；只有两个逆序对时，移动量与 `k=2` 同阶，整体工作可写成 `Θ(n+k)` 的形式。平均时间必须先说明是在所有排列等概率、某个真实数据集分布，还是别的采样模型下取期望，否则“平均”没有可复现的含义。

   </Answer>

3. 解释 `T(n)=2T(n/2)+Θ(n)` 中三个部分分别来自哪里，并为 merge sort 的正确性和空间成本各写一条不能省略的假设。

   <Answer>

   两个 `T(n/2)` 来自两次近半递归，`Θ(n)` 来自一次线性 merge。正确性需要递归区间确实返回有序排列，且 merge 不丢元素并按序组合；空间分析需要说明是否分配长度为 `n` 的辅助缓冲区，以及递归栈是否计入。若切分不平衡或 merge 不是线性扫描，原递推和结论都要重写。

   </Answer>

## 本章证据清单

完成本章后，面对任何一个算法，可以按同一顺序留下证据：

1. 写合法输入、输出合同和要保持的所有权；
2. 找到状态摘要，并用初始化、保持、终止证明它；
3. 声明输入规模、RAM/I/O 模型和统计的操作；
4. 区分最好、最坏、平均和参数化输入，不把样例平均当成理论平均；
5. 选择增量或分治设计，分别给出正确性和成本证明；
6. 用边界测试和基准测量检查实现是否仍符合这些假设。

## 小结

- getting started / 入门从问题合同开始，而不是从某个 API 开始。
- insertion sort / 插入排序用有序前缀增量扩展答案；循环不变量必须同时保留顺序和多重集。
- analyzing algorithms / 算法分析要声明输入规模、计算模型、操作账本和输入分布；插入排序最好为 `Θ(n)`，最坏与随机排列平均为 `Θ(n²)`，近乎有序时可用逆序对参数化。
- designing algorithms / 算法设计既可以增量推进，也可以 divide-and-conquer；merge sort 由线性 merge 和两次半规模递归得到 `Θ(n log n)`，但需要额外空间。
- 正确性、复杂度和工程阈值是三张不同的证书：先证明合同，再解释成本，最后用目标环境测量选择实现。
