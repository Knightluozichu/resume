## 分治范式与递推式

一个分治算法由三个可分别证明的步骤组成：divide 把实例切成若干更小的同类实例；conquer 递归求解每个子问题（规模小到阈值以下时直接解）；combine 把子问题的答案合并成原问题的答案。归并排序是模板：divide 对半切数组，conquer 递归排序两半，combine 线性 merge 两个有序段。

把三步结构翻译成成本语言，就得到本章的中心对象——<Term def="用 T 在更小输入上的值定义 T 本身的等式或不等式；分治算法的运行时间总可以写成这种形式。">递推式</Term>：

$$
T(n) = a\,T(n/b) + f(n)
$$

这个式子在说：规模为 `n` 的问题，被切成 `a` 个规模为 `n/b` 的子问题（这就是 `aT(n/b)` 一项），再加上 divide 和 combine 的非递归开销 `f(n)`。只要说清楚 `a`、`b`、`f` 各自来自算法哪一步，成本分析就从一个模糊问题变成一道可以求解的数学题。

## 方阵分块乘法：8 个乘积的账本

矩阵乘法是本章的主线例子，因为它有一个“直接做”的基准算法可以做对照。两个 `n×n` 方阵相乘，输出有 `n²` 个元素，每个元素是长度为 `n` 的行乘列点积，所以直接算法的时间是 `Θ(n³)`。分治视角下，把 `A、B、C` 各自分成四个 `n/2` 阶方阵块，标量乘法公式对块照样成立：

$$
\begin{aligned}
C_{11}&=A_{11}B_{11}+A_{12}B_{21},&
C_{12}&=A_{11}B_{12}+A_{12}B_{22},\\
C_{21}&=A_{21}B_{11}+A_{22}B_{21},&
C_{22}&=A_{21}B_{12}+A_{22}B_{22}.
\end{aligned}
$$

每个输出块是两次块乘积之和，四个输出块共 8 次半规模乘法；块加法的元素量是 `Θ(n²)`，于是分治重写的成本递推为：

$$
T(n)=8T(n/2)+\Theta(n^2)=\Theta(n^3).
$$

这个式子在说：分支数 `a=8`、缩小因子 `b=2`、层内代价 `f(n)=Θ(n²)`，而结果仍然是 `Θ(n³)`——单纯地递归重写没有改变增长阶。它真正的价值是暴露了瓶颈：递归树每层有 8 个分支。后面会看到，把 8 个乘积降到 7 个，指数就会真的下降。

## 递归树：把递推式画成逐层账本

<Term def="把递推式的递归调用关系画成一棵树：根是规模为 n 的问题，每个节点长出 a 个规模为 n/b 的子节点，用来看每层有多少工作。">
  递归树
</Term>
法把抽象递推式变成一张可以逐行核对的账本。第 `i` 层有 `a^i`
个节点，每个节点的规模是 `n/b^i`，若层内代价是 `n^d`，则第 `i` 层总工作为：

$$
w_i = a^i \left(\frac{n}{b^i}\right)^{d}
$$

这个式子在说：层内代价随子问题规模下降（括号里的因子），但节点数在上升（`a^i` 因子），两者相乘才是这一层的真实账单。总成本是各层求和再加上叶子基准：

$$
T(n)=\sum_{i=0}^{L-1} w_i + a^{L}\cdot T(1),\qquad L=\lceil \log_b n\rceil
$$

这个式子在说：总账本是“每层的账加起来”，而不是“深度乘以某个常数”——深度只有 `Θ(log n)` 层，每层的工作量却可以相差悬殊。下面这个实验把这张账本画出来，你可以亲手改分支数、缩小因子和层内代价，看树形和数值轨迹一起变化。

## 主方法：一次比较定增长率

账本求和有一个常用的“闭卷结论”。对 `T(n)=aT(n/b)+Θ(n^d)`（`a≥1, b>1`），先算临界指数 `log_b a`，再把它和层内代价阶 `d` 比一次大小：

$$
T(n)=\begin{cases}
\Theta(n^d) & d>\log_b a,\\
\Theta(n^d \log n) & d=\log_b a,\\
\Theta(n^{\log_b a}) & d<\log_b a.
\end{cases}
$$

这三行在说同一件事：总账本由“最强的那个量级”主导。`d` 大，根层的 toll 就压过一切；两者相等，每层账差不多，层数 `Θ(log n)` 就变成多余的 log 因子；`d` 小，叶子层爆炸的节点数说了算。直觉上它就是在回答“这张账本是顶层贵、每层一样贵、还是底层贵”。

<Term def="对形如 T(n)=aT(n/b)+f(n) 的递推式，直接比较 f 的阶与 n^{log_b a} 就得出 Θ 结论的三情形判定法。">
  主方法
</Term>
的前提不能忘：它要求层内代价是干净的 `Θ(n^d)` 多项式阶。`f(n)=n log n`
这类“夹在两阶之间”的代价，或者子问题规模不是均匀除以 `b`
的递推式，都要回到递归树或更强的工具上。

## 代入法：先猜，再让归纳说话

<Term def="先猜测递推式解的形式（如 T(n)≤cn^k），再用数学归纳法验证猜测、必要时用低阶项强化假设的求解方法。">
  代入法
</Term>
是最通用也最容易翻车的路径：猜一个上界
`T(n)≤c·n^k`，把递推式右边代进去，看能不能证出目标。以 `T(n)=aT(n/2)+n`
为例，归纳一步长这样：

$$
T(n)\le a\cdot c\left(\frac{n}{2}\right)^{k}+n
= c\,n^{k}\cdot\frac{a}{2^{k}}+n
$$

这个式子在说：子问题那部分贡献 `c·n^k` 的 `a/2^k` 倍，剩下 `+n` 是必须在余量里吸收的 toll。把 `c·n^k` 提出来并按 `n` 归一，残差是 `r = c(1-a/2^k)n^{k-1}-1`：`r≥0` 假设才站得住，`r<0` 假设被反推。

代入法的两个经典翻车点正好对应残差的两个来源：临界情形 `a=2^k` 时因子 `(1-a/2^k)` 为零，任何 `c` 都救不了（真解往往带 log 因子，应改猜 `T(n)≤cn log n`）；而像 `T(n)=4T(n/2)+n` 猜 `cn²`，残差恒为 `-1`，修法是强化假设成 `T(n)≤cn²-dn`，用低阶项把 toll 在归纳步里抵掉。下面的实验让你亲手调 `a、k、c`，看残差条的符号裁决。

## Strassen：少一个乘积，降一个指数

回到方阵乘法。普通分块递归每层做 8 次半规模乘法；Strassen 的关键想法是用代数恒等式把 7 个乘积组合出全部四个输出块——多做一些块加减，换少一次递归乘法。乘法子问题数量的递推从 `8T(n/2)` 变成 `7T(n/2)`：

$$
\text{mult}(n)=7\,\text{mult}(n/2)\;\Rightarrow\;\text{mult}(n)=n^{\log_2 7}\approx n^{2.807}
$$

这个式子在说：减少子问题数量直接压低指数——`log2 7≈2.807` 对 `3`，这就是“减少子问题数量是边界案例”的含义。代价是每层多出 18 项块加减（构造 7 个乘积的输入 10 项、组合输出 8 项），加法递推为 `adds(n)=7·adds(n/2)+18·(n/2)²`，展开是 `6·(7^{log2 n}-n²)`。

渐近赢家在小规模不一定赢。按上面的计数模型，n=8 时普通分块总账本是 `512+448=960`，Strassen 是 `343+1674=2017`；要到 `n≈1024` 总操作数才反超（真实实现的切换阈值还受常数、缓存和内存布局影响）。下面的实验把两根账柱并排画出来，你可以注入“只数乘法”的故障，亲眼看交叉点结论怎么被藏掉。

## 代码对照：两个可运行的 oracle

纸面推导要能被程序复核。第一段代码把递归树账本和主方法判定写成纯函数：输入 `a、b、d、n`，输出逐层工作量、叶子数和总账本，以及三情形结论。

```python
from math import log

def level_works(a, b, d, n):
    works, size, i = [], float(n), 0
    while size > 1 and i < 8:
        works.append((a ** i) * (size ** d))
        size /= b
        i += 1
    return works, a ** len(works)

def master_case(a, b, d):
    crit = log(a, b)
    if d > crit:
        return "case1", f"O(n^{d})"
    if d == crit:
        return "case2", f"O(n^{d} log n)"
    return "case3", f"O(n^{log(a, b):.3f})"
```

第二段代码把两种块乘算法的乘法和加法分开记账，并在 2 的幂上扫描总账本交叉点——这正是 Strassen 实验里 `data-crossover-estimate` 读数的来源。

```python
def counts(n, products, add_blocks):
    mults, adds, size = 1, 0, 1
    while size < n:
        adds = products * adds + add_blocks * size * size
        mults *= products
        size *= 2
    return mults, adds

def crossover():
    size = 2
    while size <= 1 << 20:
        classic = counts(size, 8, 4)   # 普通分块：4 次块加法
        strassen = counts(size, 7, 18) # Strassen：18 次块加减
        if sum(strassen) < sum(classic):
            return size
        size *= 2
```

两个函数只用标准库，且与页面三个实验的读出口径完全一致：Lab 1 的 `data-total-work`、Lab 3 的 `data-total-classic` / `data-total-strassen` 都可以拿这里的输出逐位核对。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：看见递归深度 log n，就报 Θ(log n)">
  **现象**：T(n)=2T(n/2)+n 被说成 Θ(log n)。**原因**：深度只是层数，每层还有线性
  toll，逐层求和是 Θ(n log n)。**修法**：在 Lab 1 注入“只把 toll
  记在根层”的故障，看总账本如何塌缩，再恢复正常账本逐层相加。
</Callout>

<Callout type="trap" title="陷阱：代入时丢掉 toll 项，一切猜测都通过">
  **现象**：归纳展开写着写着 `+n`
  不见了，残差恒非负。**原因**：丢弃非递归代价等于删掉要证明的那部分不等式。**修法**：在
  Lab 2 打开“丢弃 +n”故障对比两行残差；正确展开必须完整保留 `f(n)`，临界情形改猜
  `cn log n` 或强化假设 `cn²-dn`。
</Callout>

<Callout type="trap" title="陷阱：只数乘法，断言 Strassen 在任何规模都该用">
  **现象**：n=8 时也切换到 Strassen。**原因**：18
  项块加减被排除在账本外，加法段被隐藏。**修法**：在 Lab 3
  对比乘加总账本；本计数模型的交叉点在
  n≈1024，真实阈值由测量决定，渐近结论不能替代工程阈值。
</Callout>

## 本章证据清单

完成本章后，面对任何一个分治算法，可以按同一顺序留下证据：

1. 写出 divide、conquer、combine 三步，并指明 `a、b、f(n)` 各来自哪一步；
2. 画出递归树，列出每层工作量 `a^i·(n/b^i)^d` 与叶子账；
3. 用主方法三情形核对渐近结论，不适用时回退到逐层求和；
4. 用代入法写出完整归纳一步，检查残差符号与临界情形；
5. 对“减少子问题数量”式优化，乘加分开记账并找交叉点，不把渐近结论当工程阈值。

## 小结

- 分治范式把算法拆成 divide、conquer、combine 三步，直接生成 `T(n)=aT(n/b)+f(n)`。
- 递归树法逐层记账：层数由 `b` 决定，层账由 `a` 与 `d` 决定，总量是求和而非深度乘常数。
- 主方法一次比较 `d` 与 `log_b a` 定三情形；代入法先猜后证，临界情形靠 log 因子或强化假设。
- Strassen 用 7 个乘积把指数压到 `log2 7≈2.807`，但加减账让交叉点推迟到 n≈1024（本计数模型）。
- 三种求解路径互为校验：树给直觉，主方法给结论，代入法给证明。

## 版本与原书边界

本章依据 CLRS 第四版第 4 章的目录定位与核心主题进行独立教学重写：以权威目录限定范围、以公开学术资料核对事实、不复现原书正文。分治三步、方阵分块、Strassen、代入法、递归树与主方法的主题归属第 4 章目录；交互实验、计数模型、Python oracle、练习答案和验收清单是本项目新增材料。

本章的 Strassen 计数采用“每层 18 项块加减、基准 1×1”的教学模型，得到的总账本交叉点（n≈1024）是该模型下的计算结果，不等于任何具体实现的实测切换阈值。主方法叙述限定在层内代价为 Θ(n^d) 的均匀递推式；非多项式 toll 与非均匀切分需要递归树或更强的定理。
