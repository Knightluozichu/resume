## 先问：为什么只会偶尔换掉当前最佳？

想象按随机顺序面试 `n` 名能力互异的候选人：看到迄今为止的最佳者就立即雇用。先预测：期望雇用人数会是 `n/2` 吗？不会。第 `i` 个位置成为前 `i` 人中最佳者的概率只有 `1/i`，所以期望总数是调和和而不是线性数量。

再预测一个区别：如果输入顺序不是随机的，而是算法先用自己的随机位洗牌，分析对象改变了吗？改变了。概率分析把不确定性放在输入分布；随机算法把随机性放进过程，对同一个固定输入分析内部随机位产生的运行分布。推进下面的实验，观察两种路线在哪里分叉。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：平均输入就是“随机看起来差不多”">

现象：直接说候选人顺序平均随机，却没有说明哪些排列属于样本空间、每个排列是否等概率。

原因：期望是概率空间上的量；推荐批次、退出和对手排序都会改变分布，不能把一次实验的直觉当成假设。

修复：先声明候选人排名互异、`n!` 个排列等概率，或明确写出真实数据的采样过程；结论要连同这个模型一起报告。

</Callout>

<Callout type="trap" title="陷阱：期望线性性要求所有事件独立">

现象：因为“早期出现优秀候选人会影响后续记录”，就认为不能把各位置的期望相加。

原因：独立性是计算乘积概率时常见的条件，不是期望线性性的前提；依赖事件仍可以逐项求期望再相加。

修复：把总量写成 `X = X₁ + ... + Xₙ`，分别求 `E[Xᵢ]`，再使用 `E[X] = Σ E[Xᵢ]`，并说明哪里确实需要独立性。

</Callout>

<Callout type="trap" title="陷阱：随机交换很多次就得到均匀排列">

现象：每个元素都独立地交换到一个随机位置，于是宣称所有排列概率相同。

原因：不同交换路径汇聚到不同最终排列的次数可能不同；“使用随机数”不等于“输出均匀”。

修复：每个位置 `i` 只从尚未固定的后缀均匀选择，或给出每个排列恰好获得 `1/n!` 概率的证明。

</Callout>

<Callout type="trap" title="陷阱：平均负载就等于最大负载，期望碰撞就等于碰撞概率">

现象：球入箱的平均负载为 `b/n`，便声称每个箱都接近平均；或者把期望碰撞对数直接当成至少一次碰撞的概率。

原因：期望计数与事件概率是不同随机量，最大值还需要尾界或额外结构；均值不能独立提供尾部保证。

修复：为目标事件单独定义指示器，区分期望、概率和高概率界，并写清是否需要 union bound、Markov 或独立窗口。

</Callout>

## 核心术语与证据所有权

<Term def="由可能结果及其概率组成的集合；概率分析的每个期望或概率都必须说明它在哪个样本空间上取值。">样本空间</Term> 是随机推理的地基。没有它，“平均”“随机顺序”和“成功概率”都缺少可复核的含义。

<Term def="取值为 0 或 1、用于表示某个事件是否发生的随机变量；把多个局部事件相加就能得到总量。">指示器随机变量</Term> 把“总共发生多少次”改写成一组更容易求期望的小事件。

<Term def="对任意一组可积随机变量，和的期望等于各项期望之和；它不要求这些变量彼此独立。">期望线性性</Term> 是雇用、碰撞和负载分析的关键捷径，但不能被误用来推出概率乘积。

<Term def="在算法运行过程中主动抽取随机位，使固定输入对应一组可能的执行路径或运行时间的算法。">随机算法</Term> 的保证要说明随机源、分布、期望成本或失败概率。

<Term def="每个长度相同的最终排列都拥有相同概率的排列分布；随机化原地排列必须证明这一点，而不能只展示几次输出。">均匀随机排列</Term> 是把任意固定输入变成可分析随机顺序的一种机制。

<Term def="输入只能按到达顺序处理、拒绝后不能召回时，在观察和立即选择之间安排阈值与预算的决策问题。">在线选择</Term> 让成功概率和决策合同依赖信息何时可见。

术语核对顺序是：先定样本空间，再用指示器拆总量，随后决定是否由算法主动随机化，最后检查碰撞与在线选择中的概率目标。这样可以避免把随机输入、随机算法、期望计数和事件概率混成一个“平均表现”。

## probabilistic analysis and randomized algorithms / 概率分析与随机算法

概率分析有两种常见不确定性来源。第一种是输入来自一个概率分布：算法本身是确定的，但不同输入带来不同成本。第二种是算法主动读取随机位：对同一个固定实例 `x`，运行时间是 `T(x, R)`，其中 `R` 是随机串。

因此要先写清分析对象：

| 路线 | 固定的对象 | 随机的对象 | 典型保证 |
| --- | --- | --- | --- |
| 概率分析 | 算法与输入规模 | 输入排列或样本 | `E[T(X)]`、事件概率 |
| 随机算法 | 问题实例 | 算法内部随机位 | `E_R[T(x,R)]`、失败概率 |
| 最坏分析 | 所有合法实例 | 无需概率 | 对每个实例的上界 |

概率不是“这次运行大概会这样”的口头描述。它需要样本空间、概率质量、随机源和统计目标；若对手能观察随机位，原本的独立性或不可预测性假设也可能失效。

## hiring problem / 雇用问题

设面试每人花费 `cᵢ`，雇用一次花费 `cₕ`，并且 `cₕ` 远大于 `cᵢ`。所有人都要面试，所以固定成本是 `cᵢ n`；变化部分是打破当前最佳记录的次数 `M`：

$$
C(n)=c_i n+c_h M.
$$

若候选人按能力递增到达，每个人都是新纪录，`M=n`，这是最坏排列。若最佳者第一人到达，`M=1`。这两个例子提供确定边界，却还没有回答随机顺序的期望。

假设能力排名互异，且 `n!` 个到达排列等概率。对固定位置 `i`，前 `i` 人中的最佳者等可能出现在这 `i` 个位置中的任一个，因此第 `i` 人打破记录的概率为 `1/i`。由期望线性性：

$$
\mathbb{E}[M]
=\sum_{i=1}^{n}\Pr\{\text{position }i\text{ is a record}\}
=\sum_{i=1}^{n}\frac{1}{i}
=H_n
=\ln n+O(1).
$$

期望总成本为 `O(cᵢ n + cₕ log n)`。这里的 `log n` 不是说每次输入都只雇用对数个人，而是说在随机排列模型下，雇用次数的期望随调和和增长。

这个模型也展示了概率分析的边界：真实招聘可能按批次到达，候选人可能退出，能力排序可能与推荐渠道相关。如果分布不再均匀，`1/i` 需要重算；如果输入可被对手安排，应考虑先随机化顺序。

## indicator random variables / 指示器随机变量

对第 `i` 个位置定义：

$$
X_i=
\begin{cases}
1,&\text{第 }i\text{ 人被雇用},\\
0,&\text{否则}.
\end{cases}
\qquad
M=\sum_{i=1}^{n}X_i.
$$

因为 `Xᵢ` 只有 0 和 1：

$$
\mathbb{E}[X_i]=1\cdot\Pr\{X_i=1\}+0\cdot\Pr\{X_i=0\}
=\Pr\{X_i=1\}.
$$

把总量先写成局部事件之和，再逐项求期望，是指示器方法的通用工作流。它可以分析雇用次数、碰撞对数、空箱数量、超过阈值的箱子数量或长度为 `k` 的窗口数量。

~~~ts
function recordCount(ranks: number[]) {
  let best = Number.NEGATIVE_INFINITY;
  let records = 0;
  for (const rank of ranks) {
    if (rank > best) {
      best = rank;
      records += 1;
    }
  }
  return records;
}
~~~

`recordCount` 对一个确定排列给出确定计数；若排列来自等概率随机顺序，则对这个计数再取期望。代码可以验证小规模样本，却不能替代对所有 `n` 的概率证明。

### 期望线性性不等于独立性

记录事件之间通常有依赖：如果第一位已经很高，后续位置成为新纪录的机会会降低。但：

$$
\mathbb{E}\left[\sum_i X_i\right]=\sum_i\mathbb{E}[X_i]
$$

对可积随机变量成立，不需要独立。独立性在计算“多个事件同时发生”的乘积概率时才是常见条件；不要把两个定理的前提互相搬运。

## randomized algorithms / 随机算法

若输入顺序可能被对手控制，可以让算法先打乱数组，再执行确定性的 HIRE-ASSISTANT。对固定能力集合 `x`，随机化带来的期望是：

$$
\mathbb{E}_{R}[M(x,R)]
=\sum_{i=1}^{n}\frac{1}{i}
=H_n,
$$

前提是随机位产生均匀排列且对手不能预知未来随机位。这里的结论对每个固定输入成立，和“输入本来随机”是不同承诺。

### 均匀随机排列的不变式

Fisher–Yates 风格的原地随机化在第 `i` 个位置从尚未固定的后缀中均匀选择一个位置：

~~~text
RANDOMIZE-IN-PLACE(A)
1  for i = 1 to A.length
2      j = RANDOM(i, A.length)
3      swap A[i] with A[j]
~~~

不变式可以写成：第 `i` 轮开始前，前 `i-1` 个位置是从全部元素中抽出的均匀有序样本；每个长度为 `i-1` 的前缀概率都是 `(n-i+1)!/n!`。第 `i` 轮从剩余 `n-i+1` 个元素中均匀选一个，于是每个长度为 `i` 的前缀概率变成 `(n-i)!/n!`。终止时，每个完整排列概率都是 `1/n!`。

实现还需要一个准确的随机整数接口：`RANDOM(i,n)` 必须在闭区间内无偏。用低质量的模运算把大范围随机字节压到区间，可能制造模偏差；种子可以帮助复现实验，但不是新的独立证据。密码学场景还要求随机源不可预测，性能随机化则通常关注统计质量和速度。

## further uses of indicator random variables / 指示器随机变量的进一步应用

### Birthday paradox / 生日碰撞

在 365 个等可能生日中抽取 `k` 人，先算没有碰撞的补事件：

$$
\Pr\{\text{no collision}\}
=\prod_{i=0}^{k-1}\frac{365-i}{365},
\qquad
\Pr\{\text{collision}\}=1-\Pr\{\text{no collision}\}.
$$

当 `k=23` 时，碰撞概率已经超过一半。另一条路线是为每一对人定义 `Xᵢⱼ=1` 表示同生日，则匹配对数的期望为：

$$
\mathbb{E}\left[\sum_{i<j}X_{ij}\right]
=\binom{k}{2}\frac{1}{365}.
$$

“期望匹配对数”与“至少一次碰撞的概率”不是同一个量，不能直接互换；它们分别适合不同的工程问题。

### Balls and bins / 球入箱

把 `b` 个球独立均匀投入 `n` 个箱。对箱 `j` 定义 `Eⱼ=1` 表示它为空：

$$
\Pr\{E_j=1\}=\left(1-\frac{1}{n}\right)^b,
\qquad
\mathbb{E}[\text{empty bins}]
=n\left(1-\frac{1}{n}\right)^b.
$$

也可以为球对是否落入同一箱定义指示器，分析碰撞对数；为负载是否超过阈值定义指示器，分析超载箱数量。平均负载 `b/n` 不能单独保证最大负载，尾部目标需要额外概率工具。

### Streaks / 连续正面

抛 `n` 次公平硬币，考虑每个起点开始的长度为 `k` 的窗口。某个固定窗口全为正面的概率是 `2^{-k}`，候选窗口数量不超过 `n`，因此窗口指示器之和的期望至多为：

$$
\mathbb{E}[\text{all-head windows}]\le \frac{n}{2^k}.
$$

相邻窗口重叠，不能为了计算乘积概率而假设它们独立；但期望线性性仍能直接相加。想构造独立事件时，可以选择互不重叠的窗口。`k` 略大于 `log₂ n` 时，出现长 streak 的期望候选数很小，之后再用 union bound 或 Markov 得到概率上界。

### Online hiring / 在线雇用

在线雇用改变了决策合同：候选人被拒绝后不能召回，目标从“维护当前最佳”变成“只选一次并尽量选到全局最佳”。经典阈值策略先观察前 `k` 人但不雇用，记录样本最佳；随后雇用第一个超过阈值的人。

观察过少，阈值噪声大且容易过早承诺；观察过多，真正最佳者可能已经在样本期被永久错过。分析要按全局最佳者的到达位置分解成功事件，再对 `k` 求和或优化。它强调同一个候选人模型在决策合同改变后，成功指标、随机变量和保证都必须重新定义。

1. 假设 `n` 个候选人的能力排名互异且到达排列等概率。定义第 `i` 个位置的指示器，并推导雇用次数的期望；解释为什么不需要事件独立。

   <Answer>

   令 `Xᵢ=1` 表示第 `i` 人是前 `i` 人中的最佳者，否则为 0。因为前 `i` 人中的最佳者等可能落在任一位置，`E[Xᵢ]=1/i`。雇用总数 `M=ΣXᵢ`，所以 `E[M]=Σ(1/i)=Hₙ=Θ(log n)`。记录事件之间存在依赖，但期望线性性只要求各项可积，不要求独立。

   </Answer>

2. 说明为什么“每个元素独立交换到随机位置”不能自动保证均匀排列，并给出原地随机化的正确选择范围。

   <Answer>

   不同交换序列到达同一个最终排列的路径数可能不同，所以最终排列概率不一定相同。正确做法是在位置 `i` 只从 `i` 到数组末端的尚未固定后缀中均匀选择 `j`，再交换 `A[i]` 和 `A[j]`；用前缀概率不变式可证明终止时每个排列概率为 `1/n!`。

   </Answer>

3. 比较生日碰撞、球入箱和在线选择中的随机目标。分别写出一个指示器或概率事件，并指出不能从平均值直接推出什么结论。

   <Answer>

   生日问题可以为每对人定义同生日指示器，并分别用补事件计算至少一次碰撞；球入箱可以为每个箱定义空箱指示器，但平均负载 `b/n` 不能推出最大负载；在线选择可以定义“选中全局最佳”的成功事件，但观察窗口 `k` 同时影响错过最佳者与过早选择。三者的随机量不同，不能把期望计数、事件概率和成功概率互相替代。

   </Answer>

</Exercises>

## 本章证据清单

遇到一个带不确定性的算法问题，可以依次留下：

1. 样本空间、概率分布、随机源和对手能看到的信息；
2. 输入随机还是算法随机，以及保证针对哪一个对象；
3. 总量如何分解为 0/1 指示器；
4. 每个指示器的概率或期望从哪条对称性、计数或独立性得到；
5. 结论是期望、至少一次事件概率、尾部界还是成功概率；
6. 实现如何避免模偏差、错误洗牌、不可复现种子或在线决策越界。

## 小结

- probabilistic analysis and randomized algorithms / 概率分析与随机算法必须先声明随机性来自输入还是算法。
- hiring problem / 雇用问题在等概率排列下由记录事件得到 `Hₙ=Θ(log n)` 的期望雇用次数；最坏排列仍可达到线性雇用。
- indicator random variables / 指示器随机变量把总量拆成局部 0/1 事件；期望线性性不要求这些事件独立。
- randomized algorithms / 随机算法把随机位纳入过程；均匀随机排列需要前缀概率不变式，而不是重复交换的直觉。
- further uses of indicator random variables / 指示器随机变量的进一步应用覆盖生日碰撞、球入箱、连续正面和在线雇用；期望计数、事件概率和成功概率必须分开报告。

<GlossaryItem term="期望线性性">和的期望等于各项期望之和的性质，不要求随机变量彼此独立。</GlossaryItem>
<GlossaryItem term="随机算法">在运行过程中抽取随机位、使固定输入对应多个可能执行路径的算法。</GlossaryItem>
<GlossaryItem term="均匀随机排列">每个最终排列具有相同概率的排列分布。</GlossaryItem>
<GlossaryItem term="在线选择">输入只能顺序到达且拒绝后不可召回时，在观察和立即决策之间安排预算的过程。</GlossaryItem>

</Glossary>

## 版本与原书边界

本章依据 CLRS 第四版第 5 章的目录定位与核心论证进行独立教学重写。雇用问题、指示器随机变量、均匀随机排列和进一步应用来自官方主题；交互实验、故障注入、工程化随机源检查、练习答案和证据清单是本项目新增材料。

生日、球入箱和 streak 的公式分别服务于碰撞、空箱和窗口事件；在线雇用则改变了可见信息与决策合同。任何概率结论都必须带上样本空间、独立性、随机源和失败定义，不能用一次模拟替代理论保证。
