## 从“数组为什么能像一棵树”开始

先预测：把数组`[16,14,10,8,7,9,3,2,4,1]`按层解释为二叉树，需要为每个节点保存左右指针吗？不需要。近乎完全二叉树的形状由元素数量唯一确定，层序位置可以直接算出父子索引。

<Term def="存储在连续数组中的近乎完全二叉树，并满足父节点与子节点之间的局部次序性质。">堆</Term>同时拥有树视角和数组视角。它不是完全排序数组；最大堆只保证沿任意根到叶路径非增。

## 6.1 Heaps

### 数组与完全二叉树映射

使用CLRS的一基索引，节点$i$的关系为：

$$
\operatorname{PARENT}(i)=\left\lfloor\frac i2\right\rfloor,\qquad
\operatorname{LEFT}(i)=2i,\qquad
\operatorname{RIGHT}(i)=2i+1.
$$

<CLRS4HeapIndexLab />

长度$n$堆的叶节点是$\lfloor n/2\rfloor+1$到$n$，因此最后一个内部节点为$\lfloor n/2\rfloor$。树高为$\lfloor\lg n\rfloor$，这就是沿单条父子路径操作成本为$O(\lg n)$的来源。

<Term def="每个非根节点的键不大于其父节点键，因此子树最大值位于子树根部的局部有序条件。">最大堆性质</Term>写成：

$$
A[\operatorname{PARENT}(i)]\ge A[i]
\qquad\text{for every nonroot }i.
$$

局部父子关系通过传递性保证根为全局最大值，却不保证兄弟、堂兄弟或数组相邻元素之间有序。因此在堆中搜索任意键仍可能需要$\Theta(n)$。

数组通常同时维护`length`和`heap-size`。前者是已分配元素数，后者是当前属于堆的前缀长度；堆排序会逐渐缩小`heap-size`，把尾部留给已排好序的元素。

## 6.2 Maintaining the heap property

### MAX-HEAPIFY的前置条件

<Term def="在左右子树已经是最大堆、但根可能过小时，沿较大子节点路径向下交换以恢复整棵子树堆性质的过程。">MAX-HEAPIFY</Term>只修复一个可能的根部违例。它比较根与两个孩子，若最大者不是根，就交换并递归修复被换入的子树。

<CLRS4MaxHeapifyTraceLab />

```cpp
void max_heapify(std::vector<int>& a, int i, int heap_size) {
    while (true) {
        int left = 2 * i + 1;
        int right = left + 1;
        int largest = i;
        if (left < heap_size && a[left] > a[largest]) largest = left;
        if (right < heap_size && a[right] > a[largest]) largest = right;
        if (largest == i) return;
        std::swap(a[i], a[largest]);
        i = largest;
    }
}
```

代码改为零基索引后，孩子公式变成`2*i+1`和`2*i+2`。公式体系必须整体切换，不能把一基的父节点公式与零基的孩子公式混用。

<CLRS4HeapifyInvariantLab />

正确性依赖不变式：每轮开始时，除当前位置$i$可能小于孩子外，其余节点满足最大堆性质；交换较大孩子后，原位置恢复，唯一可能违例移到更深一层。到达叶子或根已最大时终止。

每次迭代下降一层，最坏走过树高：

$$
T(h)\le T(h-1)+\Theta(1)=\Theta(h)=O(\lg n).
$$

递归版本把“违例向下移动”直接映射到调用栈，代码接近证明，但最坏需要$O(\lg n)$栈空间；上面的迭代版本只更新索引$i$，辅助空间为$O(1)$。两者比较次数同阶，工程选择取决于栈限制、调用开销和可读性。若节点键是大型对象，交换对象本身可能昂贵，可以在数组中存句柄或移动语义友好的记录，但比较器必须始终针对同一优先级字段。

分支选择也不能只比较左孩子。只有与左右孩子中的较大者交换，原位置才同时不小于两个孩子；若先看到左孩子较大就立即交换，右孩子可能更大，修复后的父节点仍违例。这个细节正是“最大孩子”而非“任意更大孩子”出现在伪代码中的原因。

<Callout type="trap" title="任意坏数组都能从根调用一次heapify修好">
MAX-HEAPIFY要求左右子树事先已经是堆。若子树内部也违例，一次根部下沉不会访问其他坏路径。修法是先自底向上建堆，或明确调用点维持的前置条件。
</Callout>

## 6.3 Building a heap

### 自底向上建堆

<Term def="把任意数组从最后一个内部节点到根依次执行MAX-HEAPIFY，从叶子已成堆的事实逐层构造完整堆。">建堆</Term>从$i=\lfloor n/2\rfloor$递减到1。处理$i$时，它的孩子索引更大，已经在前面的迭代中成为堆，所以MAX-HEAPIFY前置条件成立。

<CLRS4BuildHeapLab />

```cpp
void build_max_heap(std::vector<int>& a) {
    for (int i = static_cast<int>(a.size()) / 2 - 1; i >= 0; --i) {
        max_heapify(a, i, static_cast<int>(a.size()));
    }
}
```

### 为什么总成本是Θ(n)

把$n/2$个内部节点各乘一个$O(\lg n)$会得到有效但松的$O(n\lg n)$上界。更精确地，近乎完全二叉树中高度为$h$的节点至多$\lceil n/2^{h+1}\rceil$，而该节点heapify成本为$O(h)$。因此：

$$
\sum_{h=0}^{\lfloor\lg n\rfloor}
\left\lceil\frac{n}{2^{h+1}}\right\rceil O(h)
=O\!\left(n\sum_{h=0}^{\infty}\frac h{2^h}\right)
=O(n).
$$

<CLRS4BuildCostLab />

直觉是多数内部节点靠近叶子，只能下降零到一层；能下降很多层的节点极少。读取全部$n$个元素本身给出$\Omega(n)$下界，所以BUILD-MAX-HEAP为$\Theta(n)$。

## 6.4 The heapsort algorithm

堆排序算法先线性建最大堆，随后重复把根部最大值与堆末尾交换，缩小`heap-size`，再对新根调用MAX-HEAPIFY。尾部元素从右向左固定为当前剩余最大值，最终数组升序。

<CLRS4HeapsortTraceLab />

循环不变式可写为：

1. `A[0..heap_size)`是包含尚未输出元素的最大堆。
2. `A[heap_size..n)`按非降序排列。
3. 后缀中的每个元素不小于堆前缀中的每个元素，且整个数组保持原多重集。

<CLRS4HeapsortInvariantLab />

建堆为$\Theta(n)$，随后$n-1$次提取各花$O(\lg n)$：

$$
T(n)=\Theta(n)+(n-1)O(\lg n)=O(n\lg n).
$$

逆序、已排序和随机输入都不改变渐近最坏界；比较排序下界又给出$\Omega(n\lg n)$，所以堆排序最坏时间为$\Theta(n\lg n)$。数组内交换使辅助空间为$O(1)$，但它通常不稳定，因为根尾交换会跨越相等键的原始顺序。

与merge sort相比，heapsort省线性缓冲区却有较差的缓存局部性；与quicksort相比，它提供确定的$n\lg n$最坏界，但常数和访问模式往往更差。算法选择不能只看同一个Θ标签。

<Callout type="trap" title="heap-size缩小后仍对整个数组heapify">
已交换到尾部的元素属于有序后缀，不再是堆节点。若heapify仍使用`length`，它会把已输出最大值拉回堆。修法是所有孩子边界都检查当前`heap-size`。
</Callout>

## 6.5 Priority queues

<Term def="维护带优先级元素并支持查看或删除最高优先级、插入和修改键值的抽象数据类型。">优先队列</Term>把堆从排序内部结构提升为可复用ADT。最大堆提供：

- `MAXIMUM`读取根，$\Theta(1)$。
- `EXTRACT-MAX`用末元素覆盖根并heapify，$O(\lg n)$。
- `INCREASE-KEY`增大键后向父方向交换，$O(\lg n)$。
- `INSERT`追加负无穷哨兵再increase，$O(\lg n)$。

<CLRS4PriorityQueueLab />

`INCREASE-KEY`的前置条件是新键不小于旧键，因为只有祖先方向可能违例；若要降低键，应向下heapify。生产接口常返回handle或索引映射，否则外部对象移动后无法在$O(1)$定位其堆位置。

优先队列用于事件调度、Dijkstra候选顶点、top-k流式维护和任务抢占。最大堆或最小堆只是实现选择；ADT contract应描述优先级比较器、相等键行为、空队列错误和键更新所有权。

删除任意位置$i$时，可以把末元素移到$i$，然后比较它与原键：变大则沿父链上浮，变小则向孩子方向heapify。若调用者只持有业务对象而没有堆索引，寻找$i$会退化为线性扫描；因此支持高效更新/删除的实现通常维护对象到索引的反向映射，并在每次swap时同步更新。

二叉堆还可推广为$d$叉堆。树高降为$\Theta(\log_d n)$，上浮路径更短，但每次下沉要在最多$d$个孩子中找最大值。增大$d$有利于insert和increase-key，却提高extract时每层比较数；Dijkstra等工作负载应根据键更新与删除最小值的比例选择分支度，而不是默认二叉一定最优。

```text
MAX-HEAP-INSERT(A, key)
1  heap-size = heap-size + 1
2  A[heap-size] = -∞
3  MAX-HEAP-INCREASE-KEY(A, heap-size, key)
```

## 小结

Chapter 6 Heapsort用连续数组表示近乎完全二叉树。最大堆性质让根保持全局最大；MAX-HEAPIFY在子树已成堆的前提下沿一条路径恢复性质，花$O(\lg n)$。BUILD-MAX-HEAP自底向上处理内部节点，按节点高度加权后得到$\Theta(n)$，而不是松的$O(n\lg n)$。

堆排序维护“最大堆前缀加有序后缀”，以$O(1)$辅助空间获得$\Theta(n\lg n)$最坏时间。相同结构实现最大优先队列，为MAXIMUM、EXTRACT-MAX、INCREASE-KEY和INSERT提供常数或对数成本；正确实现的关键是索引体系、heap-size边界和每个操作的键值方向。

<Exercises>

**问题 1**：一基索引堆中，为什么$\lfloor n/2\rfloor+1$到$n$全是叶子？

<Answer>
若$i>\lfloor n/2\rfloor$，则左孩子索引$2i>n$，右孩子更大，所以没有孩子。反之$i\le\lfloor n/2\rfloor$时$2i\le n$，至少有左孩子，因此叶区间恰为后半段。
</Answer>

**问题 2**：解释BUILD-MAX-HEAP线性时间证明为何不能只说“有n/2次调用”。

<Answer>
调用次数只给数量，单次成本随节点高度不同。必须把高度$h$节点数$O(n/2^{h+1})$乘成本$O(h)$后求和；加权级数$\sum h/2^h$收敛，才得到$O(n)$，再结合读入下界为$\Theta(n)$。
</Answer>

**问题 3**：堆排序提取最大值后，为什么只需对根调用MAX-HEAPIFY？

<Answer>
交换前除根外所有堆边满足性质。末元素移到根后，两棵孩子子树内部未改变，仍是最大堆；唯一可能违例是新根小于孩子，正好满足MAX-HEAPIFY前置条件。
</Answer>

**问题 4**：`INCREASE-KEY`收到更小的新键时会破坏哪类假设，怎样修正API？

<Answer>
增大键只可能违反与父节点的关系，因此算法向上移动；更小键可能小于孩子，需要向下heapify。API应拒绝更小值，或提供独立`CHANGE-KEY`，根据比较结果选择向上或向下修复。
</Answer>

</Exercises>
