## 先问：一次扫描能让多少元素“各就各位”？

想象一摞未排序的文件，每次只允许挑一张当作“界桩”，把剩下的按大小分成两摞。最自然的贪心想法是：一次扫描只让界桩自己落到最终位置，两侧内部保持无序，然后对两侧重复同样的扫描。这种方式没有“合并”步骤，所有排序工作都在划分阶段完成。

先预测：如果每次界桩都恰好是最小或最大元素，递归会变成什么形状？如果界桩总落在中间，又会是什么形状？下面三个实验把这两种极端和中间情形都画出来，让你亲手验证预测。

## PARTITION 与四区循环不变式

### 主元、扫描指针与四个区域

<Term def="把数组一段区间按某个关键值分成左右两部分的子过程；划分后左侧元素不大于关键值，右侧元素大于关键值。">
  划分
</Term>
是快速排序的唯一核心操作。在
<Term def="以单个扫描指针从左向右维护不大于主元与大于主元两个区域，最后把主元换到中间的单向扫描划分方案。">
  Lomuto 划分
</Term>
版本中，我们选子数组最右端元素 $x=A[r]$ 作为
<Term def="划分过程中被选作比较基准的元素；一趟划分结束时它会停在自己的最终排序位置。">
  主元
</Term>
，然后用两个索引把区间切成四个区域：

1. $A[p..i]$：已知不大于 $x$；
2. $A[i+1..j-1]$：已知大于 $x$；
3. $A[j..r-1]$：尚未扫描；
4. $A[r]$：主元本身。

<Term def="算法执行过程中，在每次循环迭代开始或结束时都成立的条件；它保证循环结束时能得到期望的后置条件。">
  循环不变式
</Term>
就是上述四条在每一轮 $j$ 推进前后都成立。扫描开始时
$i=p-1$，左区为空，大于区也为空，不变式自然成立。

```cpp
int lomuto_partition(std::vector<int>& a, int p, int r) {
    int x = a[r];
    int i = p - 1;
    for (int j = p; j < r; ++j) {
        if (a[j] <= x) {
            ++i;
            std::swap(a[i], a[j]);
        }
    }
    std::swap(a[i + 1], a[r]);
    return i + 1;
}
```

每轮只做一次比较 `a[j] <= x`。若成立，就扩大左区并把元素换进去；否则只让“大于区”向右延伸。无论是否交换，四个区域合起来始终保存原多重集。扫描结束时未知区为空，把主元换到 $i+1$ 位置，$q=i+1$ 就是主元的最终秩。

### 为什么主元归位后两侧不必排序

一趟划分只保证：对所有 $k<q$ 有 $A[k]\le A[q]$，对所有 $k>q$ 有 $A[k]>A[q]$。左区和右区内部仍然无序，但它们各自的排序结果不会改变主元已经满足的全局位置。于是<Term def="以反复划分把区间拆成更小的子区间、再递归排序子区间的原地排序算法。">快速排序</Term>不需要合并步骤——划分已经跨区间地排好了主元。

```cpp
void quicksort(std::vector<int>& a, int p, int r) {
    if (p >= r) return;
    int q = lomuto_partition(a, p, r);
    quicksort(a, p, q - 1);
    quicksort(a, q + 1, r);
}
```

递归终止依赖区间严格缩小。$q$ 必须被排除在两次递归调用之外：若写成 `quicksort(a, p, q)`，当 $q=p$ 时左递归区间长度不变，可能无限递归。单元素或空区间天然有序，这是归纳基例。

### 比较、交换与稳定性

Lomuto 划分对长度为 $m$ 的子数组恰好做 $m-1$ 次比较，与输入形状无关。交换次数则等于主元秩加一（含最后的归位交换），因此极端主元会导致极不平衡。它通常不稳定：一个跨区域交换可能让相等键的原始相对顺序改变。若业务要求稳定，必须额外携带索引作为次级键、使用辅助缓冲区，或改用天然稳定的算法。

## Lomuto 与 Hoare：机制差异与返回契约

### 单向扫描 vs 双指针收敛

<Term def="用两个指针从数组两端向中间收敛、找到逆序对就交换，返回两段分界的双指针划分方案。">
  Hoare 划分
</Term>
采用另一种思路：选首元素 $x=A[p]$ 作主元值，左指针 $i$ 从 $p-1$ 向右找“大于等于
$x$”的元素，右指针 $j$ 从 $r+1$ 向左找“小于等于
$x$”的元素，两者相遇时停止。它通常交换次数更少，对重复键也更友好。

关键差异不在扫描方向，而在<Term def="划分过程返回的索引所代表的语义，以及调用方应如何据此构造递归区间。">返回契约</Term>：

| 方案   | 扫描方向             | 返回值语义         | 递归区间                 |
| ------ | -------------------- | ------------------ | ------------------------ |
| Lomuto | $j$ 从左向右         | $q$ 是主元最终位置 | $[p, q-1]$ 与 $[q+1, r]$ |
| Hoare  | $i$ 左、$j$ 右向中间 | $j$ 是两段的分界   | $[p, j]$ 与 $[j+1, r]$   |

Lomuto 保证主元已就位，所以主元不再参与递归；Hoare 只保证左段元素不大于右段元素，分界本身归入左段，主元未必停在自己的最终位置。两种方案都能正确实现快速排序，前提是调用方遵守各自契约。

<Clrs4Chapter07QuicksortHoareContractLab />

### 为什么不能混用契约

如果把 Lomuto 的递归界 `[p, q-1]`、`[q+1, r]` 直接套到 Hoare 返回的 $j$ 上，下标 $j$ 永远不会被任何递归区间接管。这个元素于是被遗漏，最终数组在该位置出错。实验二的“契约混用”故障开关把覆盖空洞可视化：覆盖计数会从 $n$ 降到 $n-1$，洞格红显。

## 性能分析：划分均衡决定一切

### 最坏、均衡与固定比例

快速排序的成本完全由递归树形状决定。若主元总是最小或最大元素，递推为：

$$
T(n)=T(n-1)+T(0)+\Theta(n)=\Theta(n^2).
$$

这个式子在说：每一层只减少一个元素，却要付线性的扫描费，一共付 $n$ 层。若主元每次恰好把区间对半分：

$$
T(n)=2T(n/2)+\Theta(n)=\Theta(n\lg n).
$$

更一般地，只要每次两边都是固定比例——例如 $9n/10$ 与 $n/10$——最长递归路径仍是 $\Theta(\lg n)$，每层总工作量仍被 $\Theta(n)$ 压住，总成本依然是 $\Theta(n\lg n)$。完美平衡不是必要条件，这是快速排序在实践中常数优秀的重要原因。

### 主元策略改变递归树

<Term def="通过随机选择主元下标来降低遇到持续坏划分概率的快速排序变体；期望成本在算法随机位上取，不依赖输入已随机。">
  随机化快速排序
</Term>
先随机选 $i\in[p,r]$，把 $A[i]$ 与 $A[r]$ 交换，再复用 Lomuto
划分。对任何固定输入，当前子数组每个元素成为主元的概率相同。随机化降低持续坏划分的概率，却没有删除最坏执行路径；仍可能连续选到极端主元，只是概率很低。

```cpp
int randomized_partition(std::vector<int>& a, int p, int r, Rng& rng) {
    std::uniform_int_distribution<int> pick(p, r);
    int i = pick(rng);
    std::swap(a[i], a[r]);
    return lomuto_partition(a, p, r);
}
```

工程上还常用 median-of-three 或小样本中位数改善常见输入常数，用 introsort 监控递归深度并在超标时切换堆排序。三者分别优化常见情况、对抗性输入与确定最坏界，不能用一个模糊的“主元更好”互相替代。

### 尾递归优化：只压栈不省时

递归深度过大不仅耗时，还可能占 $\Theta(n)$ 调用栈。<Term def="快速排序实现中只递归处理较小子区间、用循环继续处理较大子区间的技巧，可把调用栈深度限制在 O(lg n)。">尾递归优化</Term>的做法是：每次划分后，先递归排序较短的一侧，再用循环继续处理较长的一侧。由于较短一侧长度至多减半，调用栈深度被限制在 $O(\lg n)$。注意它改变的是栈深，不是总时间——时间仍由划分序列决定。

## 重复键与三路划分

上述 Lomuto 分析假设键互异。当大量键相等时，二路划分可能把所有等值元素塞进一侧，造成不必要递归。三路划分维护“小于、等于、大于”三个区间，划分后只递归两边，等值块已处于最终范围。

对全相等输入，二路 Lomuto 每趟只归位主元一个，递归树退化为链，深度 $n$、工作量 $n(n-1)/2$；三路划分一趟即可把全部等值元素归位，深度 $1$、工作量 $n-1$。实验三的“二路划分处理全等键”故障开关把这个倍数差异直接画成树形对比。

```text
THREE-WAY-PARTITION(A, p, r)
1  x = A[p]
2  lt = p, gt = r, i = p
3  while i <= gt
4      if A[i] < x    swap A[lt] and A[i]; lt++; i++
5      else if A[i] > x    swap A[i] and A[gt]; gt--
6      else    i++
7  return (lt, gt)
```

比较器必须满足严格弱序；若比较结果不传递，任何基于分区的排序都可能破坏不变式。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：把划分的局部有序当成全局有序">

现象：看到主元左边都不大于它、右边都大于它，就认为两侧已经排好序，从而漏掉递归。

原因：划分只固定主元一个元素的最终位置，两侧内部仍无序；快速排序的正确性依赖递归继续排序两侧。

修复：在 PARTITION 后必须对 `[p, q-1]` 和 `[q+1, r]` 递归；用实验一验证两侧元素并不按非降序排列。

</Callout>

<Callout type="trap" title="陷阱：把 Lomuto 的递归界套到 Hoare 返回值上">

现象：Hoare 划分返回 $j$ 后，写成 `quicksort(a, p, j-1)` 与 `quicksort(a, j+1, r)`。

原因：Hoare 返回的是两段分界，不是主元最终位置；分界本身应归入左段。

修复：Hoare 的递归界是 `[p, j]` 与 `[j+1, r]`。实验二的“契约混用”故障开关会暴露覆盖空洞。

</Callout>

<Callout type="trap" title="陷阱：认为已排序输入一定对快速排序友好">

现象：在已排序数组上运行“末元素主元”的快速排序，发现速度极慢，于是认为快速排序不适合有序数据。

原因：变慢的是特定主元策略，不是快速排序本身；已排序输入对 median-of-three 或随机主元并不构成最坏情形。

修复：性能结论必须绑定具体主元策略；实验三的递归树把 sorted+last 的链形退化与 sorted+median3 的近似满二叉树并排展示。

</Callout>

<Callout type="trap" title="陷阱：随机化等于删除最坏路径">

现象：引入随机主元后，就认为任何输入都不可能触发 $\Theta(n^2)$。

原因：随机化只降低坏路径的概率，不删除坏路径；连续抽到极端主元仍可能发生。

修复：需要确定性最坏界时，使用 introsort 等深度保护机制；随机化快速排序的期望分析见下节。

</Callout>

## 期望 $O(n\lg n)$：元素对视角

### 为什么不用递归式也能分析

把最终有序键记为 $z_1<z_2<\cdots<z_n$。定义指示器 $X_{ij}=1$ 当且仅当 $z_i$ 与 $z_j$ 在算法某一步被直接比较。任意一对元素最多直接比较一次：第一次从包含二者的同一子数组选出主元后，它们要么相互比较，要么被主元永久分开。

区间 $Z_{ij}=\{z_i,\ldots,z_j\}$ 中，只有 $z_i$ 或 $z_j$ 最先被选为主元时二者才会比较，因此：

$$
\Pr\{X_{ij}=1\}=\frac{2}{j-i+1}.
$$

总比较数 $X=\sum_{i<j}X_{ij}$。由期望线性性：

$$
\begin{aligned}
\mathbb E[X]
&=\sum_{i=1}^{n-1}\sum_{j=i+1}^{n}\frac{2}{j-i+1}\\
&\le2\sum_{i=1}^{n-1}\sum_{k=1}^{n}\frac1k\\
&=2(n-1)H_n=O(n\lg n).
\end{aligned}
$$

这个证明不要求各 $X_{ij}$ 独立。它绕开“左右子问题规模相关”的递推困难，直接计算所有可能比较的发生概率。加上每次交换与指针移动的常数工作，得到随机化快速排序的期望时间为 $O(n\lg n)$。

更精确地整理双重和可得期望比较次数约为 $2n\ln n$。期望只控制均值；若关心延迟尾部，还需分析坏划分连续出现的概率或设置递归深度保护。

## 本章证据清单

完成本章后，面对任意一段待排序区间，可以按同一顺序留下证据：

1. 写出划分方案的扫描方向、主元位置和返回契约；
2. 列出四区循环不变式，并验证主元归位后左区全 $\le x$、右区全 $>x$；
3. 根据返回值写出正确的递归区间，检查每个下标都被接管；
4. 画出或想象递归树形状：链形对应 $\Theta(n^2)$、近似满二叉对应 $\Theta(n\lg n)$；
5. 说明主元策略（随机、median-of-three、introsort）分别优化哪种风险；
6. 对重复键输入判断是否需要三路划分，并校验比较器满足严格弱序。

## 小结

对照学习目标逐条回收本章证据，应当能独立复述以下内容：

- 快速排序通过反复划分把主元放到最终位置，combine 步骤为空；
- Lomuto 划分维护四区循环不变式，比较次数恒为子数组长度减一；
- Hoare 划分返回分界而非最终主元位置，递归区间必须把分界归入左段；
- 划分均衡决定性能：极端主元 $\Theta(n^2)$、固定比例或对半分 $\Theta(n\lg n)$；
- 随机化主元降低持续坏划分概率但不删除最坏路径，尾递归优化独立压栈深；
- 重复键场景需三路划分，否则全等输入会退化为链；
- 元素对比较概率证明随机化快速排序期望比较次数为 $O(n\lg n)$。

## 术语表

<Glossary>

<GlossaryItem term="快速排序">
  以反复划分把区间拆成更小的子区间、再递归排序子区间的原地比较排序算法；没有独立的合并步骤。
</GlossaryItem>

<GlossaryItem term="划分">
  把数组一段区间按某个关键值分成左右两部分的子过程；划分后左侧元素不大于关键值，右侧元素大于关键值。
</GlossaryItem>

<GlossaryItem term="主元">
  划分过程中被选作比较基准的元素；一趟划分结束时它会停在自己的最终排序位置。
</GlossaryItem>

<GlossaryItem term="循环不变式">
  算法执行过程中，在每次循环迭代开始或结束时都成立的条件；它保证循环结束时能得到期望的后置条件。
</GlossaryItem>

<GlossaryItem term="Lomuto 划分">
  用单个扫描指针从左向右维护“不大于主元”与“大于主元”两个区域，最后把主元换到中间的单向扫描划分方案。
</GlossaryItem>

<GlossaryItem term="Hoare 划分">
  用两个指针从数组两端向中间收敛、找到逆序对就交换，返回两段分界的双指针划分方案。
</GlossaryItem>

<GlossaryItem term="返回契约">
  划分过程返回的索引所代表的语义，以及调用方应如何据此构造递归区间；Lomuto 与
  Hoare 的契约不同，不可混用。
</GlossaryItem>

<GlossaryItem term="随机化快速排序">
  通过随机选择主元下标来降低遇到持续坏划分概率的快速排序变体；期望成本在算法随机位上取，对固定输入也成立。
</GlossaryItem>

<GlossaryItem term="尾递归优化">
  快速排序实现中只递归处理较短子区间、用循环继续处理较长子区间的技巧，可把调用栈深度限制在
  O(lg n)。
</GlossaryItem>

</Glossary>
