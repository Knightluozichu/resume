## 8.1 比较排序的下界：决策树

比较排序的全部信息来源是一次比较返回的"是/否"。把某个算法在固定 n 上的所有行为画成<Term def="把算法在固定输入规模上的全部比较结果与控制流画成二叉树：内部节点是一次比较，叶子是算法承诺的输出，根到叶的路径对应一次具体运行。">决策树</Term>：每个内部节点是一次比较，两条边是两种结果，叶子是算法给出的有序输出。

### 为什么叶子数至少是 n!

n 个互异键有 n! 种输入排列，正确算法必须把每种排列送到写有正确有序结果的叶子——两个不同排列不能共用一片叶子，否则其中一个必然被排错。因此决策树至少有 n! 片叶子，而高度为 h 的二叉树最多有 2^h 片叶子：

$$
n!\le 2^h
\quad\Longrightarrow\quad
h\ge \lg(n!)=n\lg n-\Theta(n)=\Theta(n\lg n).
$$

这个式子在说：比较次数 h 必须大到能装下 n! 种区分，而 2^h 装得下 n! 的最小 h 大约是 n lg n。所以任何比较排序的最坏比较次数都是 Ω(n lg n)，merge sort 与 heap sort 的 Θ(n lg n) 在此模型中渐近最优。

同样的论证也压住平均情况：在均匀随机排列下，叶子足够多的二叉树平均深度仍是 Ω(n lg n)。随机化只改变"哪种输入碰上最坏路径"，不改变"存在很长路径"这个事实——只要算法对每个输入都必须正确。

### 为什么这个下界只管比较

下界只数比较，不数数据移动、缓存未命中或比较器成本；它也不禁止"读取键本身的值"。这正是三种线性时间排序的逃生门：当键是小范围整数时，可以把键直接当数组下标用；当键可切成位时，可以按位处理；当值落在一个已知区间时，可以按区间分桶。它们都获取了比较模型拿不到的信息，因此不再受 2^h 的分叉约束——但每种自由都附带一个前提条件，这就是后面三节的主角。

## 8.2 计数排序：把键当地址

<Term def="不比较元素，而是统计每个整数键出现多少次，再用前缀和直接算出每个键在输出中的落位区间，一次扫描放完的排序方法。">
  计数排序
</Term>
适用于键落在小区间 $0,\ldots,k$ 的记录。第一遍扫描统计每个键的频数
`C[key]`，成本 Θ(n+k)——注意初始化计数数组本身就要 Θ(k)，这不是可以忽略的小项。

第二遍把频数变成前缀和：

$$
C[i]\gets C[i]+C[i-1].
$$

这行递推在说：处理完下标 i 之后，`C[i]` 等于输入里所有键不超过 i 的记录总数，也就是键 i 在输出中占据区间的右端点。之后从输入末尾开始，把每条记录放进 `B[C[A[j]]]` 并递减对应计数。

```cpp
std::vector<Record> counting_sort(const std::vector<Record>& input, int k) {
    std::vector<int> count(k + 1, 0);
    std::vector<Record> output(input.size());
    for (const auto& item : input) ++count[item.key];
    for (int key = 1; key <= k; ++key) count[key] += count[key - 1];
    for (int j = static_cast<int>(input.size()) - 1; j >= 0; --j) {
        output[--count[input[j].key]] = input[j];
    }
    return output;
}
```

这段实现里最值得盯住的词是从右向左：相等键的记录中，靠后的先占住该键的最右空位，靠前的随后落到更左位置，两者的原始顺序被保留。这种"相等元素相对顺序不变"的性质叫<Term def="排序后，键相等的记录保持它们原来的相对先后顺序；对纯键序列不可见，但对带附带信息的记录是关键合同条款。">稳定排序</Term>。若只把频数展开成裸键序列，记录身份会消失，根本谈不上稳定性；一旦记录带 payload，放置方向就决定了相等键谁先谁后。

### 为什么从右向左而不是从左向右

直觉上两个方向"都能放对键"，差别只在相等键的内部顺序。从右向左扫描时，每条记录的落位恰好是该键剩余空位中最靠右的一个，于是输入中靠后的相等键天然排在靠后的槽位——稳定。换成正向扫描，靠后的相等键会先占掉靠左的空位，顺序被整个反转。排序结果照样"有序"，可若下游算法指望相等键的原始次序（下一节的基数排序正是如此），错误的放置方向就埋下了一颗延时引爆的雷。

时间和空间都要如实记账：

$$
T(n,k)=\Theta(n+k),
\qquad
S(n,k)=\Theta(n+k).
$$

这组等式在提醒：只有 $k=O(n)$ 时才能简写成"线性"。一百条记录若键散布在 32 位整数全集，分配四十亿个计数格比排序本身还慢——此时应压缩键域、改哈希频数，或者干脆退回比较排序。

## 8.3 基数排序：按位次序的归纳

<Term def="从最低位开始，依次用稳定的子排序按每一位排序，每处理一位就把有序前缀扩展一位的方法；高位相同的记录靠子排序的稳定性保持低位已排好的顺序。">
  低位优先
</Term>
（LSD）基数排序把键切成 d 位，每位取值
0..k。它先按最低位排，再按次低位排，直到最高位：

```text
RADIX-SORT(A, d)
1  for digit = 1 to d
2      use a stable sort to sort A on digit
```

这段伪代码只有一行实质内容：每遍子排序必须是稳定的。正确性靠对已处理位数归纳：假设第 i−1 遍后记录按低 i−1 位有序，第 i 遍按新位稳定排序时，新位较小的整体靠前，新位相等的记录保持低位次序，于是低 i 位全部有序。d 遍之后完整键有序。若把"稳定"二字偷换成任意快排，归纳论证在第一步就断裂——上一实验的故障开关演示的正是这个断裂点。

每位用计数排序时，总时间为：

$$
\Theta\bigl(d\,(n+k)\bigr).
$$

这个乘积在说明：轮数 d 和位域 k 都是真实的成本变量，不是常量。对 w 位机器字，每次取 r 位则 $d=\lceil w/r\rceil$、$k+1=2^r$：r 取大，轮数少但计数数组暴涨；r 取小则反之。最优 r 取决于缓存容量、内存带宽和 n，工程上要做基准，不能把"字宽是常数"悄悄当成免费午餐。

最高位优先（MSD）是另一份合同：先按最高位分桶再递归各桶，不要求跨桶稳定，但要处理空桶、递归深度和不等长键。LSD 与 MSD 的正确性前提不同，证明不能互相借用。

## 8.4 桶排序：均匀性是有价前提

<Term def="把区间 [0,1) 切成 n 个有序子区间，按 ⌊nx⌋ 把元素散入子区间（桶），桶内局部排序后按桶号直接连接的排序方法；期望线性依赖输入独立均匀分布。">
  桶排序
</Term>
对落在 $[0,1)$ 的 n 个实数工作：建立 n 个桶，把 x 放进第 $\lfloor nx\rfloor$
号桶。桶区间天然有序——小编号桶里的任何值都不超过大编号桶里的值——所以只要桶内排好序，按桶号连接即得全局有序。

设第 i 桶有 n_i 个元素，散入与连接是 Θ(n)，总成本由局部排序的 $\sum_i O(n_i^2)$ 控制。关键推导是二阶矩：把 $n_i^2$ 看成桶 i 中"有序元素对"的数量，自身对贡献期望 n，不同元素的有序对共 n(n−1) 个、每对落入同桶的概率是 1/n，于是

$$
\mathbb E\!\left[\sum_{i=0}^{n-1} n_i^2\right]=n+(n-1)=2n-1=O(n).
$$

这个等式每一步都有前提：期望的线性性、元素两两独立、每个桶等概率。任一前提失效，结论就跟着失效。所有元素挤进同一桶的极端输入下，桶内插入排序比较次数达到 $n(n-1)/2$——Θ(n²)，比任何比较排序都差。缓解办法包括按累积分布函数做等概率映射、用样本估计分位数边界，或监控最大桶负载并在超标时回退到 Θ(n lg n) 排序。

```text
BUCKET-SORT(A)
1  create ordered buckets B[0..n-1]
2  append x to B[floor(n*x)] for every x in A
3  sort each bucket locally
4  concatenate buckets in index order
```

这份伪代码还藏着两个边界地雷。输入若允许 1.0，$\lfloor nx\rfloor$ 算出 n，越出桶数组下标——合同应明确半开区间 [0,1)，或把 1.0 夹到末桶。NaN 没有普通全序，映射结果无意义，必须前置校验、单独成桶或显式拒绝。越界与夹紧的分歧要由接口合同说清，不能靠调用者运气。

## 常见误区与故障注入

<Callout type="trap" title="误区：线性时间排序推翻了 Ω(n lg n) 下界">

现象：看到计数排序 Θ(n) 的结论，认为比较排序下界被突破了，或认为下界证明有误。

原因：决策树下界只约束"信息全部来自两两比较"的算法；计数、基数、桶排序读取了键的数值、位或区间位置，这些信息不在二叉比较模型内。

修复：报告任何排序算法的成本时，把模型假设（比较-only / 整数键域 / 分布已知）写进合同，并说明下界是否适用于该模型。

</Callout>

<Callout type="trap" title="误区：键域成本可以当作常数忽略">

现象：写"计数排序是线性算法"，然后对 32 位整数键分配几十亿格的计数数组。

原因：Θ(n+k) 中的 k 是真实变量；只有 k=O(n) 时"线性"才成立，初始化计数数组的 Θ(k) 无法绕过。

修复：先量键域再选算法；键域大时压缩、哈希频数或改用比较排序，并在文档里写明 k 的量级。

</Callout>

<Callout type="trap" title="误区：LSD 基数排序可以套用任意快排">

现象：把"每遍按一位排序"实现成调用库里的不稳定排序，样例碰巧全对就上线。

原因：LSD 的正确性归纳要求子排序稳定；不稳定子排序会在高位同键组内洗乱低位已排好的次序，且只有特定键组合才触发，样例测试极易漏检。

修复：给子排序加稳定性断言，或在小键域上用计数排序这类天然稳定的子排序；测试集中加入高位相同、低位交错的对立键组。

</Callout>

## 练习

<Exercises>

1. 决策树下界手算：n=5 个互异键时，正确比较排序的决策树至少要有多少片叶子？最坏比较次数至少是多少？（提示：先算 ⌈lg(5!)⌉。）

   <Answer>

   叶子数至少是 5! = 120。由 n! ≤ 2^h 得 2^h ≥ 120；2^6 = 64 < 120 ≤ 128 = 2^7，因此 h ≥ 7。最坏比较次数至少是 7 次——尽管 5 个元素只有 10 对，下界仍然要求 7 次比较而不是直觉上的"够挑就行"。

   </Answer>

2. 带 payload 的计数排序：输入记录（按顺序）为 d:5、a:3、b:5、c:3、e:1，键域 1..5。写出前缀和完成后各键的计数端点，并给出稳定放置后输出槽位的记录顺序；再说明正向扫描会得到什么顺序。

   <Answer>

   频数为 C[1]=1、C[3]=2、C[5]=2，其余为 0；前缀和后各键的右端点（最右空位+1）为 C[1]=1、C[2]=1、C[3]=3、C[4]=3、C[5]=5。从右向左放置：e→槽0，c→槽2，b→槽4，a→槽1，d→槽3，稳定输出为 e、a、c、d、b（键序列 1、3、3、5、5，相等键保持输入顺序）。若改为正向扫描，输出为 e、c、a、b、d，键仍然有序，但 a 与 c、b 与 d 的原始顺序被反转。

   </Answer>

3. 桶排序推导：n 个元素独立均匀落入 n 个桶，推导 E[Σn_i²] = 2n−1；并回答：若所有元素落入同一个桶，桶内插入排序需要多少次比较？这告诉我们"期望 Θ(n)"和"最坏 Θ(n)"差在哪个前提上？

   <Answer>

   把 n_i² 展开为桶 i 内的有序元素对数：自身对（x=x）共 n 个，期望贡献 n；不同元素的有序对共 n(n−1) 个，独立均匀下每对落入同一桶的概率是 1/n，期望贡献 n(n−1)·(1/n)=n−1。相加得 2n−1。全部落入一桶时插入排序比较次数为 n(n−1)/2，即 Θ(n²)。差距的前提正是"元素独立且每个桶等概率"：它把最大桶负载压在 O(log n / log log n) 的高概率水平，一旦分布聚簇或元素相关，期望线性立刻失效。

   </Answer>

</Exercises>

## 小结

- 决策树把比较排序下界翻译成叶子计数：n! ≤ 2^h ⟹ h ≥ lg(n!) = Θ(n lg n)。
- 下界只属于比较模型；读取键值、位或区间位置即可逃出模型，但每个逃生门都有前提。
- 计数排序 Θ(n+k)：键域 k 必须 O(n)，从右向左放置换来稳定性。
- LSD 基数排序 Θ(d(n,k))：正确性靠"每遍子排序稳定"这条归纳支柱。
- 桶排序期望 Θ(n)：均匀独立假设负责压住 Σn_i²，聚簇时退化为 Θ(n²)。
