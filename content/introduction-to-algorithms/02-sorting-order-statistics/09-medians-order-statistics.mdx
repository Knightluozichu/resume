## 直觉：只找冠军，何必排完整张榜

流水线上有一千件包裹，主管只要最重的一件。先预测：为了找出它，需要先把一千件按重量全排好序吗？直觉上不必——大多数包裹只要在某次称重里"输过一次"，就可以离开候选区，根本不需要知道自己的完整名次。

这一章把这种"只领奖、不排名"的问题形式化。你会看到三件事：找出冠军最少要称几次；怎样随机挑裁判让平均称重次数稳定在正比于件数；以及怎样安排一场有保底机制的淘汰赛，让最坏情况也不退化。

没有它，所有"只要中位数/只要前 1%"的需求都会被拖进完整排序的 $\Theta(n\lg n)$ 成本里，而本章的全部目的就是说明这笔账可以压到线性。

## 最小值与最大值的比较次

先固定度量：本节只数"两个元素直接比大小"的次数，记为<Term def="算法为解决某个问题所必须执行的两个元素直接比较操作的总数；本节把它当作成本账本。">比较次</Term>。键的移动、下标运算都不算，因为比较次有一个漂亮的性质——它能同时给出上界（一种做法用了多少次）和下界（任何做法至少要多少次）。

### 单独找最小：$n-1$ 次，少一次都不行

扫描法再简单不过：先让第一个元素举牌，每个新元素挑战一次擂主，输了就淘汰。$n$ 个元素一共挑战 $n-1$ 次，这就是上界。

$$
\text{比较次}(\min) = n-1
$$

这个式子在说：只找最小值时，一次比较恰好淘汰一个"最小候选"，把候选从 $n$ 个削到 $1$ 个需要恰好 $n-1$ 刀。下界同样锋利：如果某个元素从头到尾没输过，它的值就还没被排除——它仍可能是最小值；要排除其余 $n-1$ 个候选，每次比较至多排除一个，所以任何算法都省不掉这 $n-1$ 次。

```cpp
int minimum(const std::vector<int>& a) {
    if (a.empty()) throw std::invalid_argument("empty");
    int champion = a[0];
    for (std::size_t i = 1; i < a.size(); ++i) {
        if (a[i] < champion) champion = a[i];
    }
    return champion;
}
```

注意挑战规则的严格不等号：相等不改变擂主，这决定了重复值出现时返回哪一个记录。空输入没有最小值，应该由类型系统或错误合同显式处理，而不是让它默默越界。

### 同时找最小与最大：配对的账是 $\lceil 3n/2\rceil-2$

朴素做法是独立跑两遍扫描，成本 $2n-2$。配对法把相邻两个元素先拉到一起比一场，胜者只可能挑战"最大"，败者只可能挑战"最小"：

1. 对内一场比较，分出这一对的胜者与败者；
2. 胜者挑战当前最大，败者挑战当前最小；
3. 一对花 3 次比较，淘汰两个候选名额。

偶数 $n$ 先用第一对做一次初始化，剩下 $(n-2)/2$ 对每对 3 次：

$$
1+3\cdot\frac{n-2}{2}=\frac{3n}{2}-2
$$

这个式子在说：初始化花 1 次，之后每对固定 3 次，账是精确的等式不是估计。奇数 $n$ 让第一个元素同时兼任两个擂主（0 次比较），剩余 $(n-1)/2$ 对仍各 3 次，总计 $3(n-1)/2$。两种情形合并为上界 $\lceil 3n/2\rceil-2$——比 $2n-2$ 省了约 $n/2$ 次，却仍然是线性。

先预测：把 $n$ 从 8 换成 9（奇数边界），配对公式 $\lceil 3n/2\rceil-2$ 还精确成立吗？再把策略换成顺序扫描，账本差多少？动手切换下面的实验，核对每一次比较真的发生在它该发生的位置。

## RANDOMIZED-SELECT：期望线性的选择

最小值只是"第 1 小"。一般地，<Term def="在一组可比较元素中，按其键值从小到大排名后恰好位于第 i 位的元素；i=1 是最小值，i=n 是最大值。">顺序统计量</Term> 提问的是：第 $i$ 小是谁？中位数对应 $i=\lceil n/2\rceil$（奇数 $n$ 时唯一定义；偶数 $n$ 需先声明取下中位还是上中位）。完整排序当然能回答问题，但它给出的远比问的多——内部次序我们根本不关心。

### partition 一次，只留目标那一侧

关键观察：围绕主元做一次划分，主元的秩就被永久确定了，而它左侧和右侧的内部仍然无序。设划分后主元在子数组中的局部秩为 $k$（1-based），目标是第 $i$ 小：

- $i=k$：主元就是答案，直接返回；
- $i<k$：答案在左侧，递归左侧且 $i$ 不变；
- $i>k$：答案在右侧，递归右侧，并且新的局部秩要减去已排除的 $k$ 个元素——这就是<Term def="向右递归时把目标秩 i 改写为 i−k，其中 k 是本轮主元的局部秩；漏掉它会让右侧用错误的秩去找答案。">秩平移</Term>。

```cpp
int randomized_select(std::vector<int>& a, int p, int r, int i) {
    if (p == r) return a[p];
    int q = randomized_partition(a, p, r); // 主元落到最终秩上
    int k = q - p + 1;                     // 主元的局部秩
    if (i == k) return a[q];               // 命中
    if (i < k) return randomized_select(a, p, q - 1, i);
    return randomized_select(a, q + 1, r, i - k); // 秩平移不可省略
}
```

单侧递归是成本飞跃的来源：每一轮只保留包含目标的那一半区间，另一侧整体丢弃，根本不需要排好。正确性则由划分的不变量兜住——主元左侧每个键不大于它、右侧每个键大于它，因此目标秩只可能落在所选的那一侧。

### 期望为什么是 $\Theta(n)$

最坏的路径仍然存在：每次都倒霉地选到最小元，区间每次只缩 1，总成本退回 $\Theta(n^2)$。期望分析不看单条路径，而看"进展"出现的频率。若主元的秩均匀分布，它落在中间一半（即两侧各自至少占 $n/4$）的概率至少是 $1/2$；一旦发生，较大侧的规模至多 $3n/4$。

$$
\mathbb E[T(n)]\le cn+c\frac{3n}{4}+c\Big(\frac{3}{4}\Big)^2 n+\cdots
=cn\sum_{j\ge 0}\Big(\frac34\Big)^j=4cn=O(n)
$$

这个式子在说：把"同一规模阶段的尝试"打包，好进展以至少 $1/2$ 的概率反复出现，期望等待次数是常数，于是每一层规模的总开销形成公比 $3/4$ 的几何级数，加起来仍是一个常数倍的 $n$。再补上读取输入的 $\Omega(n)$ 下界，期望时间恰为 $\Theta(n)$。注意期望是对算法内部的随机位取的，对每一个固定输入排列都成立；若随机源有偏或可被对手预测，这个账就作废。

## SELECT：中位数的中位数保证最坏线性

随机化给了期望，但给不了承诺：某一次运行仍可能滑进二次。确定性算法 SELECT 用额外线性工作换一个质量有保证的主元——<Term def="把元素分成每组至多 5 个的小组，取每组中位数，再递归地取这些中位数的中位数作为主元的构造方法。">中位数的中位数</Term>。构造分五步：

1. 把 $n$ 个元素分成 $\lceil n/5\rceil$ 组，每组至多 5 个；
2. 组内排序（至多 5 个元素，常数次比较），取出每组的中位数；
3. 递归地找出这些中位数的中位数，记为 $x$；
4. 围绕 $x$ 做一次三路划分（小于、等于、大于）；
5. 与 RANDOMIZED-SELECT 一样，只在包含目标秩的一侧递归。

### 淘汰保证：两侧各躺倒至少 $3n/10$

为什么 $x$ 靠谱？看那些中位数不小于 $x$ 的组：这样的组至少有一半（除去 $x$ 自己所在的组）。每个这样的组里，中位数带着组内比它大的两个元素一起"不小于 $x$"。把零头（$x$ 自身所在组、可能不满的组）减掉，仍能保证：

$$
\#\{a\ge x\}\ \ge\ 3\Big\lceil\frac{\lceil n/5\rceil}{2}\Big\rceil-6
\ge \frac{3n}{10}-O(1)
$$

这个式子在说：无论输入长什么样，$x$ 右侧至少躺着约三成的元素，左侧由对称论证同样成立。于是较大的一侧至多 $7n/10+6$ 个元素，递归规模被牢牢卡住。加上找组中位数的中位数那次递归（规模 $\lceil n/5\rceil$）和分组、划分的线性工作：

$$
T(n)\le T\Big(\Big\lceil\frac n5\Big\rceil\Big)+T\Big(\frac{7n}{10}+6\Big)+\Theta(n)
$$

这个式子在说：两项递归的渐近比例之和是 $1/5+7/10=9/10$，严格小于 1，留下一成的线性余量。代入法取足够大的常数 $c$，把 $0.9cn$ 与线性项对齐后，剩余的 $O(c)$ 小项可以由更大的 $c$ 吸收，基例直接排序——于是 $T(n)=O(n)$，读取下界给出 $\Theta(n)$。

### 为什么偏偏是五

组大小 $s$ 在两头记账：找组中位数的成本随 $s$ 涨，而每组中位数能"带走"的伴生元素是 $(s-1)/2$ 个，淘汰比例约为 $(s+1)/(4s)$。证明要求两项递归比例和 $1/s+(1-(s+1)/(4s))$ 严格小于 1：$s=3$ 时恰好等于 1，递推解不出线性；$s=5$ 得到 $9/10$；$s=7$ 是 $6/7$，同样小于 1 但常数更差、实现更繁。五是"证明刚好闭合"的最小选择。

## 常见误区

<Callout type="trap" title="误区：期望线性就是最坏线性">

现象：给 RANDOMIZED-SELECT 贴上"线性时间选择"标签，然后用在有实时约束的路径上。
原因：期望是对内部随机位取的平均；对抗输入或倒霉的随机序列仍可能每次只淘汰主元，滑回 $\(n^2)$。
修法：需要承诺时改用 SELECT（中位数的中位数），或像内省式选择那样监控递归深度、异常时切换到确定性主元。

</Callout>

<Callout type="trap" title="误区：中位数的中位数实践中总是更快">

现象：因为有最坏线性保证，就以为它平均也比随机选择快。
原因：分组、组内排序和递归找代表带来不小的常数，随机选择在典型输入上的常数往往更小。
修法：把"正确性保证"和"平均性能"分开验收；实践中常用 quickselect，深度异常时才回退到 SELECT。

</Callout>

<Callout type="trap" title="误区：partition 之后两侧内部已经有序">

现象：看到主元落位、左右分区，就以为左右两边也排好了，或把"秩平移"当成可有可无的整理步骤。
原因：划分只确定主元一个元素的最终秩，两侧内部次序完全未知；向右递归时目标秩若不减去已排除的 $k$ 个元素，就会用错误的秩在右侧找答案。
修法：用上面的实验二打开故障开关——忘记秩平移的那一栏会返回一个具体的错误元素，而不是抽象地说"错了"。

</Callout>

<Exercises>

1. 用配对法同时找 $n=9$ 个元素的最小值与最大值：初始化花几次比较、逐对花几次、总数是多少？说明为什么 $\lceil 3n/2\rceil-2$ 在奇数 $n$ 上仍然精确。

   <Answer>

   奇数 $n$ 时令首元素同时担任两个擂主，初始化 0 次比较；剩余 $(n-1)/2=4$ 对每对 3 次，总计 $3\times 4=12$ 次。公式给出 $\lceil 3\cdot 9/2\rceil-2=14-2=12$，与实验一中 $n=9$ 的账完全一致。关键点：奇数初始化免费，所以公式把两种情况合并后依然精确。

   </Answer>

2. 设"好主元"（秩落在中间一半）以概率至少 $1/2$ 出现，且出现时下一规模至多为 $3m/4$。写出期望工作的几何级数并求和，再说明为什么这不能排除 $\Theta(n^2)$ 的最坏情况。

   <Answer>

   把同一规模阶段的尝试打包，期望开销受 $cn+c\frac{3n}{4}+c(\frac34)^2n+\cdots=cn\sum_{j\ge0}(3/4)^j=4cn$ 控制，即 $O(n)$；读取输入给出匹配的 $\Omega(n)$。但期望界不排除低概率坏路径：若每次主元都是最小元，递推退化为 $T(n)=T(n-1)+\Theta(n)$，解为 $\Theta(n^2)$——这正是实验二中"对抗"主元策略画出的形状。

   </Answer>

3. 对 $n=30$ 的五分组 SELECT：组数 $g$ 是多少？用 $3\lceil g/2\rceil-6$ 计算每侧至少有多少元素不小于 $x$（也不大于 $x$），并由此写出较大递归侧的上界与两项递归的比例和，判断递推能否解出 $O(n)$。

   <Answer>

   $g=\lceil 30/5\rceil=6$；每侧至少有 $3\lceil 6/2\rceil-6=9-6=3$ 个元素被淘汰，较大侧至多 $30-3=27=7n/10+O(1)$。比例和为 $1/5+27/30$ 的渐近形式 $1/5+7/10=9/10<1$，留出一成线性余量，代入法可吸收小项，$T(n)=O(n)$ 成立。实验三默认参数下实测 $\ge x$ 侧 13 个、$\le x$ 侧 16 个，都满足这条保证线。

   </Answer>

</Exercises>

## 小结

- 第 $i$ 小把最小值、最大值、中位数统一成选择问题；只找最小要 $n-1$ 次比较，且下界不可再省。
- 配对法同时找最小/最大把账从 $2n-2$ 降到 $\lceil 3n/2\rceil-2$，靠"对内一场、胜者挑战最大、败者挑战最小"的淘汰结构。
- RANDOMIZED-SELECT 每次划分只留目标侧；秩平移 $i\leftarrow i-k$ 是正确性的一部分，不是优化。
- 好主元以常概率出现使期望工作成为公比 $3/4$ 的几何级数，期望 $\Theta(n)$、最坏 $\Theta(n^2)$。
- 五分组中位数的中位数给出每侧 $3n/10-O(1)$ 的淘汰保证，$9/10<1$ 的比例和把最坏情况也压成线性。

实验中的数组由确定性公式生成，主元策略由读者显式选择，用于代替随机位做可重复演示；均匀随机下的概率结论（好主元概率至少 $1/2$、期望几何级数）在正文中以论证形式给出，实验不负责伪造随机样本。偶数 $n$ 的中位数定义、重复键的三路划分等边界在正文与实验中均已显式声明。
