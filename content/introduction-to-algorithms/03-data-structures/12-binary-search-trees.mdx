## 先问：查一本全书为什么不用翻遍每一页？

想象一座档案馆：每张卡片只有一个编号，馆员把它们挂成一张层层分叉的地图——每张卡片左边挂的不大于它，右边挂的不小于它。查一个编号时，每到一张卡片只需比一次大小就能排除一个方向的整棵子树，像走迷宫时每个路口都立着“往左都更小”的路标。先预测：如果树形足够匀称、每一步都能排除约一半候选，查 n 张卡片要比多少次？

这张地图有个隐患：它只保证“每个路口的路标规则成立”，不保证地图长得匀称。如果编号恰好从小到大依次挂进地图，每一层都只剩一个分叉，地图就退化成一条走廊，路标规则依然成立，却一步也甩不掉。本章的两个实验分别盯住这两件事：验证规则是否全局成立，以及在摘掉一张卡片后怎样把地图的岔路重新接好。

没有这张地图，要么每次查找翻遍全部卡片，要么为维持全序不断挪动大量卡片。二叉搜索树每次比较都能排除一个方向的子树；只有树形足够匀称时，候选规模才会近似减半、查找才是对数级。普通 BST 必须自己管理形状——这正是下一章红黑树要接手的问题。

## 12.1 什么是二叉搜索树

<Term def="每个节点的左子树全部键不大于它、右子树全部键不小于它的二叉树，支持动态有序集合的查找、插入与删除。">
  二叉搜索树
</Term>
（BST）把“有序”从数组的物理相邻搬到树的分岔上：比较一次就能排除一个方向的子树；只有树形平衡时，候选数才会近似减半。形状由插入历史决定。

形式化地，对任意节点 x，其左子树中的每个键 y 与右子树中的每个键 z 满足：

$$
y\in x.left\text{ 子树}\Rightarrow y.key\le x.key,
\qquad
z\in x.right\text{ 子树}\Rightarrow z.key\ge x.key.
$$

这组式子在说：约束作用在**整棵子树**上，不是只约束直接相连的两个节点。每个节点实际被整条祖先链夹在一个开区间里——这就是 Lab 1 里验证器沿递归传递的 (low, high)。

<Term def="BST 正确性的全局判据：每个键都落在祖先节点链划定的 (low, high) 区间内，等价于中序序列非降序。">
  全子树范围约束
</Term>
有一个等价镜像：中序遍历输出的键序列非降序，当且仅当树的形状与键分布满足这里采用的非严格
BST 规则。Lab 1 的“埋雷树”上，节点 4 小于其父
8、父子对看起来完全正常，但它破坏了祖先 5
划定的下界——局部检查全部通过，范围检查与中序镜像却同时报警。

<Term def="按“左子树 → 根 → 右子树”顺序访问每个节点恰好一次的遍历，BST 上输出非降序键序列。">
  中序遍历
</Term>
的成本是
Θ(n)：每个节点进出递归各一次。递归深度等于树高，退化链上可能撑爆调用栈，工程实现常改用手显栈。

把空子树的高度记为 −1，节点高度满足递推：

$$
h(x)=1+\max\{h(x.left),\,h(x.right)\}.
$$

这个式子在说：树高由最深的那条根到叶路径决定，与节点总数无关。n 个节点的树高在最坏情况下是 n−1（每层一个节点的退化链），最矮的近完全树高度为 ⌊lg n⌋，一般平衡树高度为 Θ(lg n)——同一个 n，操作成本可以差一个指数级。

## 12.2 查询：沿一条根叶路径走到底

search 从根出发：目标更小走左、更大走右、相等即命中、撞空即不存在。minimum 沿 left 一路到底，maximum 沿 right 一路到底；对任意子树都成立，所以它们同时是 delete 与 successor 的组件。每个操作每层只访问一个节点：

$$
T_{\text{search}},T_{\text{min}},T_{\text{successor}}=O(h),\quad\text{最坏情形为 }\Theta(h).
$$

这些操作至多访问一条根到叶路径，最坏情形为 Θ(h)。匀称树 h = Θ(lg n)，最坏操作为对数级；按已排序输入逐个插入，h = Θ(n)，最坏操作为线性——BST 本身不保证任何平衡。

<Term def="键大于 x 的最小节点：x 有右子树时取右子树最小值，否则沿 parent 向上找第一个从左边上来的祖先。">
  后继节点
</Term>
（successor）有两种情形：x 有右子树，successor 就是右子树的 minimum；否则沿
parent 上升，直到第一次从某祖先的左边走上来——那个祖先就是
successor。上升路上跳过的祖先都把 x 放在右子树里，键都不大于
x，不可能是答案；一路升到根都没有，则 x 是全树最大，successor 为空。predecessor
完全对称。

单次 successor 是 O(h)。从 minimum 出发反复调用 successor 恰好按非降序枚举全部节点，总时间 O(n)：每条边在整个枚举中被向上向下各走常数次，不能简单相乘成 O(nh)。

## 12.3 插入与删除：边的缝合手术

INSERT 复用 search 的路径：保存最后一个非空节点 y，撞空后新节点作为 y 的左或右孩子接上；空树时新节点即根。插入只改路径末端的常数条边，成本 O(h)——但树高也从此被插入顺序塑形。

删除才是这台机器上唯一容易翻车的地方，先把“替换一棵子树根”的动作抽出来：

<Term def="用节点 v 替换节点 u 的原子操作：把 u 的父指向 v 的一侧改接到 v，并同步 v 的 parent 指针；不检查次序、不搬动 u 的孩子。">
  TRANSPLANT
</Term>
不检查 BST 次序，也不自动把 u 的左右孩子接到
v——调用者必须保证替换后整棵子树仍落在正确的键区间里。DELETE
分三种情形：零孩子直接用空替换 z；单孩子用其孩子替换 z；双孩子时取 successor y
顶替 z 的位置。Lab 2 手术台逐步展示这三种情形的边重接。

双孩子情形为什么安全？y 是 z 右子树的最小键，所以 z 左子树的每个键 a 与右子树剩余节点的每个键 b 满足：

$$
\forall a\in z.left:\ a.key\le z.key\le y.key,
\qquad
\forall b\in z.right\setminus\{y\}:\ y.key\le b.key.
$$

这组不等式在说：y 放进 z 的位置后，左边整棵子树仍不大于 y，右边整棵子树仍不小于 y，全子树范围约束原样保留。而 y 没有左孩子（否则它不是最小值），所以它能干净地接管 z 的两棵子树；y 深在右子树里时，要先把自己的右孩子移交给原父节点，再顶到 z 的位置。

## 代码对照：同一逻辑的两种实现

查询三件套在 C++ 与 TypeScript 里是逐行镜像：循环不变量、空指针分支、parent 回跳的条件完全一致。

<CodeTabs>

<Tab label="C++">

```cpp
Node* search(Node* x, int key) {
    while (x && x->key != key)
        x = key < x->key ? x->left : x->right;
    return x;
}
Node* minimum(Node* x) {
    while (x->left) x = x->left;
    return x;
}
Node* successor(Node* x) {
    if (x->right) return minimum(x->right);
    Node* y = x->parent;
    while (y && x == y->right) { x = y; y = y->parent; }
    return y;
}
```

</Tab>

<Tab label="TypeScript">

```ts
type Node = {
  key: number;
  left: Node | null;
  right: Node | null;
  parent: Node | null;
};
function search(root: Node | null, key: number): Node | null {
  let x = root;
  while (x && x.key !== key) x = key < x.key ? x.left : x.right;
  return x;
}
function minimum(x: Node): Node {
  while (x.left) x = x.left;
  return x;
}
function successor(x: Node): Node | null {
  if (x.right) return minimum(x.right);
  let y = x.parent;
  while (y && x === y.right) {
    x = y;
    y = y.parent;
  }
  return y;
}
```

</Tab>

</CodeTabs>

实现审核问三件事：循环终止时 x 是命中节点还是空、minimum 在空树上的行为是否被调用方排除、successor 回跳时 `x == y->right` 的比较方向有没有写反。任何一个答错，Lab 2 的搜索路径高亮都会和代码轨迹对不上。

INSERT 与 search 共用同一条比较路径，区别只在撞空后的缝合：

<CodeTabs>

<Tab label="C++">

```cpp
void insert(Tree& t, Node* z) {
    Node* y = nullptr;
    Node* x = t.root;
    while (x) {
        y = x;
        x = z->key < x->key ? x->left : x->right;
    }
    z->parent = y;
    if (!y) t.root = z;
    else if (z->key < y->key) y->left = z;
    else y->right = z;
}
```

</Tab>

<Tab label="TypeScript">

```ts
function insert(t: Tree, z: Node): void {
  let y: Node | null = null;
  let x = t.root;
  while (x) {
    y = x;
    x = z.key < x.key ? x.left : x.right;
  }
  z.parent = y;
  if (!y) t.root = z;
  else if (z.key < y.key) y.left = z;
  else y.right = z;
}
```

</Tab>

</CodeTabs>

以上实现假定键互异。若要保存重复键，不能仅把相等键一律向右、同时仍允许后续插入按普通比较向左分叉；应把唯一序号并入比较键（如 `(key, insertionId)`），或在一个节点中记录该键的计数，并让查询、删除和验证遵守同一表示。

DELETE 的全部风险都集中在指针缝合上，TRANSPLANT 把边界分支收拢到一处：

<CodeTabs>

<Tab label="C++">

```cpp
void transplant(Tree& t, Node* u, Node* v) {
    if (!u->parent) t.root = v;
    else if (u == u->parent->left) u->parent->left = v;
    else u->parent->right = v;
    if (v) v->parent = u->parent;
}
void remove(Tree& t, Node* z) {
    if (!z->left) transplant(t, z, z->right);
    else if (!z->right) transplant(t, z, z->left);
    else {
        Node* y = minimum(z->right);
        if (y->parent != z) {
            transplant(t, y, y->right);
            y->right = z->right;
            y->right->parent = y;
        }
        transplant(t, z, y);
        y->left = z->left;
        y->left->parent = y;
    }
}
```

</Tab>

<Tab label="TypeScript">

```ts
function transplant(t: Tree, u: Node, v: Node | null): void {
  if (!u.parent) t.root = v;
  else if (u === u.parent.left) u.parent.left = v;
  else u.parent.right = v;
  if (v) v.parent = u.parent;
}
function remove(t: Tree, z: Node): void {
  if (!z.left) transplant(t, z, z.right);
  else if (!z.right) transplant(t, z, z.left);
  else {
    const y = minimum(z.right);
    if (y.parent !== z) {
      transplant(t, y, y.right);
      y.right = z.right;
      y.right.parent = y;
    }
    transplant(t, z, y);
    y.left = z.left;
    y.left.parent = y;
  }
}
```

</Tab>

</CodeTabs>

`y->left = z->left` 与它前面的 parent 同步是深缝合分支最容易漏的一行——Lab 2 的故障开关专门演示漏掉它之后左子树失联的样子。删除共执行常数次 TRANSPLANT 加至多一次向下找 minimum，总时间 O(h)。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：用“只查父子对”验证 BST">

现象：写了个校验函数逐条边比较父子大小，埋雷树上报告 0 违例，自信地判定合法。

原因：BST 约束作用在整棵子树上，每个节点要满足的是整条祖先链划定的 (low, high) 区间；只看父亲一个数，等于把祖父以上的所有约束整段跳过。

修复：验证器递归传递区间——进左子树把 high 换成父键，进右子树把 low 换成父键，再检查节点是否越界。打开 Lab 1 的“只查父子对”故障开关，看完整验证与局部验证的结论怎样相反。

</Callout>

<Callout type="trap" title="陷阱：以为 BST 的高度天然是 lg n">

现象：算出操作成本 O(h) 后，直接把 h 写成 ⌊lg n⌋，宣称所有操作对数时间。

原因：⌊lg n⌋ 是匀称形状的高度；按已排序输入依次插入普通 BST 会得到一条 n 个节点的退化链，h = Θ(n)。随机插入的期望高度 O(lg n) 是输入分布的结论，不是结构保证。

修复：分析时保留 h，只在结构有平衡机制（下一章的红黑树）时才替换成 lg n。Lab 2 换不同的删除目标，观察树高随操作历史的变化。

</Callout>

<Callout type="trap" title="陷阱：双孩子删除漏接 successor 的左子树">

现象：删除根这类深 successor 情形后，z 的左子树从根不可达——遍历结果少了一截，或更糟，悬空的子树被后续操作重复接入。

原因：y.parent ≠ z 的缝合顺序是“先摘除 y、移交 y 的右孩子、再把 y 顶到 z 的位置”，其中 y 接管 z 左子树的 `y.left = z.left` 与 parent 同步是独立的一步，不是 TRANSPLANT 的副作用。

修复：对照 Lab 2 时间线第 4 步逐条边核对：y 的原位置由 y.right 接管，y 接管 z 的左右子树，三条 parent 指针同步更新。打开“忘记接左子树”故障开关，失联子树以红虚线现形。

</Callout>

3. 依次插入 8、3、10、1、6、14、13 到空 BST（相等放右）。画出最终树，给出树高 h 与 search(13) 的比较次数；再回答：若把插入顺序换成 1、3、6、8、10、13、14，h 与 search(13) 的比较次数各是多少？两次结果差多少，说明什么？

   <Answer>

   第一种顺序得到根 8，左子树 3（左 1、右 6），右子树 10（右 14，14 的左 13）；最长路径为 8 → 10 → 14 → 13，因此 h = 3（按边计），search(13) 比较 4 次。第二种顺序每个新键都更大，全部挂右：1 → 3 → 6 → 8 → 10 → 13 → 14 的退化链；h = 6（按边计），search(13) 比较 6 次。同一组键、同一操作集，只因为插入顺序不同，树高与操作成本就可从对数级退化到线性级——说明普通 BST 的 h 由输入历史塑形，没有任何结构保证，这正是需要平衡机制（下一章红黑树）的原因。

   </Answer>

</Exercises>

## 小结

对照学习目标逐条回收本章证据，应当能独立复述以下内容：

- BST 性质是全局约束：每个键落在祖先划定的 (low, high) 区间内，中序非降序是其等价镜像。
- search、minimum、successor、insert、delete 至多沿单条根叶路径工作，最坏成本 Θ(h)。
- h 由插入历史塑形：匀称 Θ(lg n)，退化为 Θ(n)；结构本身不保证平衡。
- 删除 = TRANSPLANT 缝合：零/单孩子一次替换，双孩子用 successor 顶替并移交。
- successor 无左孩子，顶到 z 位置后范围约束原样保留；每条边修改都要双向同步。

## 名词解释

<Glossary>

<GlossaryItem term="二叉搜索树">
  左子树全部键不大于它、右子树全部键不小于它的二叉树；比较一次排除一个方向的子树；只有平衡时查找才按对数级缩小，形状由插入历史决定。
</GlossaryItem>
<GlossaryItem term="全子树范围约束">
  BST 正确性的全局判据：每个键都落在祖先链划定的 (low, high)
  区间内；等价于中序序列非降序，只看父子对会漏检。
</GlossaryItem>
<GlossaryItem term="中序遍历">
  按“左子树 → 根 → 右子树”的顺序访问每个节点一次；在 BST
  上输出非降序键序列，本身也是一棵树的“排序视图”。
</GlossaryItem>
<GlossaryItem term="后继节点">
  键大于 x 的最小节点：有右子树就取右子树最小值，否则沿 parent
  向上找第一个从左边上来的祖先；全树最大者的后继为空。
</GlossaryItem>
<GlossaryItem term="TRANSPLANT">
  用 v 替换 u 的原子操作：把 u 父节点指向 u 的一侧改接到 v 并同步 v 的
  parent；不检查次序、不搬动 u 的孩子，边界分支全在这里。
</GlossaryItem>

</Glossary>
