## 先预测：不完全平衡为何仍能保证对数高度？

红黑树不要求左右子树高度相等。它约束每条从节点到后代空叶的路径具有相同的黑节点数，并禁止红节点相邻。因而任一路径上的红节点至多夹在黑节点之间；最长路径长度至多是最短全黑路径的两倍。下面把这个直觉变成可检查的不变量，再用插入和删除修复解释结构如何恢复。

这棵树仍是普通二叉搜索树：每个键的左子树键更小，右子树键更大。颜色只约束树形，不改变搜索顺序。

## 13.1 Properties of red-black trees

<Term def="满足五条颜色与黑高性质的二叉搜索树">红黑树</Term>
把每个缺失孩子视为黑色的 NIL 哨兵。常见实现让多个空孩子共享一个 `T.nil`
对象；它不是业务节点，也不计入内部节点数，但必须参与颜色和路径黑数的定义。CLRS
的五条性质是：

1. 每个节点为红或黑。
2. 根为黑。
3. 每个 NIL 叶为黑。
4. 红节点的两个孩子均为黑。
5. 对每个节点，从它到所有后代 NIL 叶的简单路径都包含相同数量的黑节点。

从节点 $x$ 出发到 NIL 的路径黑数称为其 <Term def="从节点到任一后代 NIL 叶路径上的黑节点数；不计起点节点，计入黑色 NIL">黑高</Term> $bh(x)$；按此处约定，$x$ 本身不计入 $bh(x)$，NIL 作为黑节点计入。若子树黑高为 $b$，其根的两个孩子子树黑高至少为 $b-1$。以 NIL 的黑高为 0 作归纳，内部节点数满足

$$
N(b)\ge 1+2N(b-1),\qquad N(0)=0,
$$

所以 $N(b)\ge 2^b-1$。性质 4 又保证任意路径上红节点不能连续出现，故从根到 NIL 的路径长度 $h$ 至多是黑节点数的两倍。代入根子树的节点下界：

$$
n\ge 2^{bh(root)}-1,\qquad bh(root)\ge h/2
\quad\Longrightarrow\quad h\le 2\lg(n+1).
$$

因此普通 BST 的 search、minimum、successor 等操作为 $O(h)=O(\lg n)$。插入与删除先沿一条搜索路径定位，再沿祖先路径修复，整体仍为 $O(\lg n)$。这不是“每次旋转都让树更矮”的结论，而是五条不变量共同限制了高度。

一个完整的合法性检查不能只看中序输出：中序有序仅证明键顺序，无法发现红红相邻或左右黑高不同；只检查颜色也无法发现键放错子树。验证器应同时携带 BST 上下界、父指针关系、颜色约束和递归返回的黑高，并在第一个违反条件处报告节点与路径。

## 13.2 Rotations

<Term def="改变局部父子指针、但保持中序次序的常数时间结构变换">旋转</Term>
是局部指针变换。设 $x$ 的右孩子为 $y$，$y$ 的左子树为 $\beta$，则左旋把 $\beta$
移到 $x.right$，把 $y$ 接到 $x$ 原来的父位置（必要时更新 root），再令 $x$ 成为
$y.left$。旋转前后的中序次序都是 $\alpha,x,\beta,y,\gamma$，所以 BST
排序关系保持。右旋完全镜像。

```cpp
void left_rotate(Tree& t, Node* x) {
    Node* y = x->right;              // 前置条件：y != T.nil
    x->right = y->left;              // beta 转接到 x 的右侧
    if (y->left != t.nil) y->left->parent = x;
    y->parent = x->parent;
    if (x->parent == t.nil) t.root = y;
    else if (x == x->parent->left) x->parent->left = y;
    else x->parent->right = y;
    y->left = x;
    x->parent = y;
}
```

旋转本身不重着色，时间为 $\Theta(1)$。插入和删除修复依据各自的证明，在旋转前后单独调整颜色。若节点另存 subtree size 或区间最大值等增强字段，旋转后还必须按依赖顺序重算受影响节点；普通 BST 次序正确并不自动保证增强信息正确。

## 13.3 Insertion：红叶、叔节点与局部修复

普通 BST 插入把新节点 $z$ 接为叶后先染红。若染黑，经过它的路径黑数会立即多一；染红则不改变这些路径的黑数，只可能产生两类问题：$z$ 成为红根，或其父节点也是红色。fixup 的循环条件是 `z.parent.color == RED`。循环中父节点不是根，因为根为黑，所以祖父存在且为黑。

假设父节点是祖父的左孩子，叔节点是祖父右孩子；另一侧完全镜像。根据叔节点颜色与 $z$ 相对父节点的位置，修复分三类：

1. **红叔（case 1）**：父与叔染黑，祖父染红，把 $z$ 上移到祖父。局部红红冲突可能向上移动，但经过该子树的路径黑数保持。
2. **黑叔、三角（case 2）**：若父是左孩子而 $z$ 是父的右孩子，先对父左旋，将三角变成直线。此步只改变结构。
3. **黑叔、直线（case 3）**：父染黑、祖父染红，再对祖父右旋，消除局部红红冲突。case 2 转换后也进入此修复。

每轮 case 1 都把可能冲突上移至少两层；旋转修复的最终总旋转次数至多 2。循环结束把根染黑，覆盖“新节点成为根”或冲突传播到根的情况。因此插入从搜索到修复总计 $O(\lg n)$，而旋转次数有更紧的常数界。

```text
RB-INSERT(T, z)
1  TREE-INSERT(T, z)       // 按 BST 次序插入
2  z.left = z.right = T.nil
3  z.color = RED           // 不增加任一路径的黑数
4  RB-INSERT-FIXUP(T, z)   // 消除可能的根红或 red-red 违例
```

## 13.4 Deletion：物理移除颜色与额外黑色

删除时要区分“逻辑上要求删除的节点”和“实际从原位置移走的节点” $y$。当待删节点有两个孩子时，通常用其后继替代；修复依据的是 $y$ 原位置被移走前的颜色，而不是简单查看待删节点 $z$ 的颜色。若 $y$ 原本为红，移除不改变黑高；若为黑，替换位置 $x$ 所在路径少一个黑节点，才需要 fixup。

把这份亏空记作 $x$ 携带的 <Term def="删除修复期间用于追踪路径黑数亏空的记账单位，不是节点的第三种颜色">额外黑色</Term>。它是分析路径黑数的记账方式，不是实际节点颜色枚举的新值：通过 $x$ 的路径在记账时多算一个黑单位，fixup 的工作就是把这一单位上移、转换位置或消除。若 $x=T.nil$，共享哨兵的 `parent` 仍须记录替换位置的父节点，以便找到兄弟。

假设 $x$ 是父节点的左孩子，兄弟 $w=x.parent.right$；右侧镜像。按兄弟及其孩子颜色处理；相对 $x$ 而言，<Term def="兄弟靠近 x 一侧的孩子">近侄子</Term>和<Term def="兄弟远离 x 一侧的孩子">远侄子</Term>决定 case 3 或 case 4：

1. **case 1：兄弟红。** 父必为黑。交换兄弟与父的颜色并对父左旋，将局面化为黑兄弟；额外黑色仍由 $x$ 携带。
2. **case 2：兄弟黑，两个孩子都黑。** 兄弟染红，将额外黑色上移到父。若父为红，下一轮可吸收它；否则继续向上。
3. **case 3：兄弟黑，近侄红、远侄黑。** 交换兄弟与近侄的颜色并对兄弟右旋，转成远侄为红的 case 4。
4. **case 4：兄弟黑，远侄红。** 兄弟取得父的颜色，父与远侄染黑，对父左旋，额外黑色在此消除。

case 2 可能沿树高重复；其他情况只做常数次转换，删除修复最多 3 次旋转。修复结束还要把 $x$（包括 NIL）染黑。结构删除的搜索与修复沿树高进行，故总时间为 $O(\lg n)$。

```text
RB-DELETE(T, z)
1  perform BST deletion; save y-original-color and replacement x
2  if y-original-color == BLACK
3      RB-DELETE-FIXUP(T, x)
```

## 常见误区与故障定位

<Callout type="trap" title="陷阱：中序有序就等于红黑树合法">

现象：验证器只比较中序序列，或只检查红黑颜色规则，却接受了一棵黑高不等或键顺序错误的树。

原因：BST 次序与红黑性质是两组独立约束。中序检查不能证明颜色和黑高；局部颜色检查也不能证明全局键范围正确。

修复：一次后序遍历同时传递 `(lower, upper, parent)`，返回左右黑高；发现左右黑高不等、红红相邻、父边不一致或键越界时立即返回带路径的错误。

</Callout>

<Callout type="trap" title="陷阱：删除 NIL 后丢掉 parent">

现象：删除黑叶后，fixup 无法区分兄弟、父节点或当前亏空位，某些样例通过但其他分支访问了错误节点。

原因：删除修复即使让 `x` 指向共享的 `T.nil`，仍需要通过 `x.parent` 定位兄弟和叔侄；把 NIL 当成无状态空指针会破坏修复所需上下文。

修复：`TRANSPLANT` 替换位置时也设置 `v.parent = u.parent`，包括 `v == T.nil` 的情况；操作后验证 root、parent 反向边与所有叶路径黑高。

</Callout>

## 练习与答案

<Exercises>

1. 黑高推导题：若根黑高为 4，给出其子树内部节点的最小数量下界，并说明高度界依赖的另一条性质。

   <Answer>

   递推为 `N(b) ≥ 1 + 2N(b−1)` 且 `N(0)=0`，因此最小内部节点数至少 `2⁴−1=15`。仅有这个节点下界还不够得到高度界；还需性质 4，保证红节点不相邻，使任一路径至少一半节点为黑。

   </Answer>

2. 插入追踪题：父是祖父的左孩子，叔节点黑，且新节点 `z` 是父的右孩子。说明两步修复的旋转对象和方向。

   <Answer>

   这是左-右三角。先对父节点左旋，让 `z` 成为直线局部的父位置；再按直线 case 对祖父右旋，并将原父染黑、祖父染红。第一步只把形状转换为 case 3，第二步与换色一起消除 red-red，局部中序顺序不变。

   </Answer>

3. 删除诊断题：删除一个黑叶后，替换位 `x=T.nil`，且 `x` 是父的左孩子。此时黑兄弟 `w` 的两个孩子都是黑色，应如何处理？为什么 NIL 仍需 parent？

   <Answer>

   这是 case 2：把 `w` 染红，将额外黑色从 `x` 上移到父节点；若父为红，下一轮吸收额外黑色，否则继续向上。`T.nil.parent` 提供父节点，从而能定位 `w` 并确定后续修复分支。

   </Answer>

</Exercises>

## 小结

五条红黑性质让黑高成为可归纳的规模证书，并给出 $h\le2\lg(n+1)$。旋转以 $\Theta(1)$ 指针改写保留中序顺序；插入红叶保住原黑高，按叔节点颜色先上移或把三角转直线；删除则根据物理移除节点的原色判断是否产生额外黑色，再按兄弟与近/远侄子完成转换、上移或消除。实现审计需同时覆盖 BST 次序、NIL、颜色、黑高和父指针，不能把一次成功的搜索演示当作结构正确性证明。
