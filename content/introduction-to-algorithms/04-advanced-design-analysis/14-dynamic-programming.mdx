## 从“递归树为何重复算同一格”开始

先预测：长度10的钢条，尝试第一刀后会递归求多个剩余长度；不同切法是否会反复请求“长度4的最优收益”？会。朴素递归把相同状态复制成许多树节点，动态规划把每个不同状态只计算一次。

<Term def="把具有最优子结构和重叠子问题的问题分解为状态，在依赖顺序中各求一次并保存结果的算法方法。">动态规划</Term>不是“填二维表”的同义词。核心是找到足以决定未来的state和无环dependency。

## 14.1 Rod cutting

### Recurrence

长度$n$钢条的价格表为$p_i$。选择第一段长度$i$后，剩余$n-i$必须取得自身最优收益，否则替换成更优切法就能改进原方案。定义$r_0=0$：

$$
r_n=\max_{1\le i\le n}\{p_i+r_{n-i}\}.
$$

<CLRS4RodCutLab />

朴素递归枚举所有第一刀，调用数指数增长。Top-down memoization在第一次请求$r_n$时递归计算并缓存；bottom-up按长度1到$n$填表，保证使用$r_j$时$j$更小且已知。

```cpp
for (int length = 1; length <= n; ++length) {
    revenue[length] = -INF;
    for (int first = 1; first <= length; ++first) {
        int candidate = price[first] + revenue[length - first];
        if (candidate > revenue[length]) {
            revenue[length] = candidate;
            first_cut[length] = first;
        }
    }
}
```

状态数$n+1$，每个长度尝试$O(n)$个first cut，总时间$\Theta(n^2)$、空间$\Theta(n)$。

<CLRS4RodTableLab />

只保存revenue能回答最优值，却不能输出切法。`first_cut[length]`记录达到最大值的第一段；从$n$反复减去该长度即可重构。并列最优时，tie policy决定输出更少段、更长首段或字典序方案，价值相同但witness不同。

若每次切割有固定成本$c$，transition应在确实产生切口时扣费；把$c$对每段都扣会多算或少算边界。state和transition必须与问题contract同步。

## 14.2 Matrix-chain multiplication

### Parenthesization changes cost

矩阵链$A_1A_2\cdots A_n$乘积顺序不改变结果，却改变标量乘法次数。若$A_i$形状为$p_{i-1}\times p_i$，区间$i..j$在$k$处分裂，最后合并成本$p_{i-1}p_kp_j$。

<CLRS4MatrixChainCostLab />

令$m[i,j]$为$A_i\cdots A_j$最少乘法数，base为$m[i,i]=0$：

$$
m[i,j]=
\min_{i\le k\lt j}
\{m[i,k]+m[k+1,j]+p_{i-1}p_kp_j\}.
$$

按链长$\ell=2,\ldots,n$计算，短区间先于长区间。共有$\Theta(n^2)$状态，每状态尝试$O(n)$分割，总时间$\Theta(n^3)$、空间$\Theta(n^2)$。

<CLRS4MatrixChainOrderLab />

`s[i,j]`保存最优split $k$。打印括号时递归输出`(i,k)`与`(k+1,j)`；不必实际乘矩阵就能规划顺序。维度数组必须首尾衔接，若$A_i$列数不等于$A_{i+1}$行数，问题实例本身非法。

```text
PRINT-OPTIMAL-PARENS(s, i, j)
1  if i == j, print Ai
2  else print "("
3       PRINT-OPTIMAL-PARENS(s, i, s[i,j])
4       PRINT-OPTIMAL-PARENS(s, s[i,j]+1, j)
5       print ")"
```

矩阵链展示了区间DP典型结构：state由两个端点定义，transition枚举最后一次合并位置，计算顺序按区间长度，choice表重建树形方案。

## 14.3 Elements of dynamic programming

### Optimal substructure

<Term def="一个问题的最优解可拆成若干子问题最优解；若某子解非最优，用更优子解替换会改进整体。">最优子结构</Term>需要证明，不是看到递归就自动成立。标准证明流程：

1. 假设已知最优解的某个结构选择。
2. 刻画该选择产生的子问题。
3. 用cut-and-paste证明最优解中的子解也必须最优。
4. 枚举所有合法选择取min或max。

<CLRS4DPElementsLab />

最短路拥有最优子结构，但带“必须访问不同颜色边”约束时，仅用当前顶点作为state可能不足；需要把最后颜色或已用资源加入state。状态充分性要求：两个历史若映射到同一state，它们未来可行选择和成本必须等价。

### Overlapping subproblems

<Term def="递归分解中许多调用落到同一个状态，若不缓存会重复计算，而不同状态总数远小于递归树节点数。">重叠子问题</Term>区分DP与普通分治。Merge sort子数组基本不重叠，缓存无收益；rod cutting、LCS和matrix chain反复请求相同长度或区间。

Memoization适合只访问部分state：用递归表达transition，第一次计算后缓存。Bottom-up省递归开销并容易压缩空间，但必须找到topological order。两者在相同state/transition下通常有相同渐近上界。

### Four-step workflow

动态规划原理可归纳为：

1. Characterize optimal solution structure.
2. Recursively define optimal value.
3. Compute value top-down or bottom-up.
4. Construct an optimal solution from stored choices.

省略第4步只能交付score，不能交付witness。若只需score，可以压缩掉不再使用的历史行；若需重构，要保存choice、重新计算路径，或采用Hirschberg等分治重构方法。

<Callout type="trap" title="状态越少越好">
过度压缩状态可能把未来行为不同的历史合并，transition便不再正确。修法是先证明state sufficient，再优化等价状态或滚动空间；内存小不能以丢失信息为代价。
</Callout>

## 14.4 Longest common subsequence

### Prefix states

<Term def="从两个序列各删除零个或多个元素但保持相对顺序后，能同时得到的最长序列。">最长公共子序列</Term>不同于substring，不要求元素连续。令$c[i,j]$为$X[1..i]$与$Y[1..j]$的LCS长度：

$$
c[i,j]=
\begin{cases}
0,&i=0\text{ or }j=0,\\
c[i-1,j-1]+1,&x_i=y_j,\\
\max\{c[i-1,j],c[i,j-1]\},&x_i\ne y_j.
\end{cases}
$$

<CLRS4LCSGridLab />

相等末字符存在某个最优LCS包含该字符，可转到双前缀；不等时最优解至少丢弃一个末字符，因此取上或左。表有$(m+1)(n+1)$格，时间和空间$O(mn)$。

```cpp
for (int i = 1; i <= m; ++i)
    for (int j = 1; j <= n; ++j)
        c[i][j] = x[i - 1] == y[j - 1]
            ? c[i - 1][j - 1] + 1
            : std::max(c[i - 1][j], c[i][j - 1]);
```

从`c[m][n]`回溯：字符相等就输出并走对角；否则走值更大的上或左。tie可能产生不同但同长LCS，应明确政策。

<CLRS4LCSReconstructLab />

只求长度时，每行只依赖上一行和当前行左格，可压到$O(\min(m,n))$空间；这会丢掉普通回溯路径。重构需求是空间优化contract的一部分。

## 14.5 Optimal binary search trees

### Successful and unsuccessful searches

<Term def="给定有序键成功概率p_i和键间失败概率q_i，选择BST形状以最小化期望比较成本的动态规划问题。">最优二叉搜索树</Term>不仅考虑搜索键$k_i$成功，还考虑落在键间dummy $d_i$的失败搜索。节点深度每增加1，该子树所有查询都多一次比较。

<CLRS4OptimalBSTLab />

令$e[i,j]$为包含$k_i,\ldots,k_j$子树的最小期望成本，$w[i,j]$为该区间所有$p$与$q$概率和。空区间base为$e[i,i-1]=q_{i-1}$：

$$
e[i,j]=
\min_{i\le r\le j}
\{e[i,r-1]+e[r+1,j]+w[i,j]\}.
$$

$w[i,j]$加一次是因为把左右最优子树挂到root $k_r$下面后，其中每项深度都增加1。漏掉失败概率$q_i$或这次权重，会优化错误目标。

按区间长度填$e,w,root$三表，朴素时间$O(n^3)$、空间$O(n^2)$。`root[i,j]`重建最优树。概率不必总和恰好1才能决定同一最优形状，但必须非负且尺度一致；归一化便于解释期望成本。

<Callout type="trap" title="最高概率键一定是根">
根选择会同时改变左右所有查询深度，不能只看单键概率。修法是对每个候选root计算左右最优成本加完整区间权重，由DP比较全局影响。
</Callout>

## 小结

Chapter 14 Dynamic Programming用钢条切割建立缓存与choice重构，用矩阵链乘法展示区间state和split，用动态规划原理抽象optimal substructure、overlapping subproblems、依赖顺序和witness。LCS用前缀二维表处理序列对齐，optimal BST把成功与失败概率按深度加权。

DP正确性来自state sufficient、base完整、transition覆盖和dependency acyclic；效率来自不同state数量乘每state转移数。值最优不等于方案已交付，choice与tie policy必须纳入contract。

<Exercises>

**问题 1**：钢条切割为何记录`first_cut[n]`就足以重构完整方案？

<Answer>
`first_cut[n]`给最优解第一段$i$，剩余部分按recurrence必须采用长度$n-i$的最优解；继续读取`first_cut[n-i]`，长度严格下降直到0，得到全部段且收益和为$r_n$。
</Answer>

**问题 2**：矩阵链DP为何按区间长度而不是按左端点单独递增？

<Answer>
状态$m[i,j]$依赖所有$m[i,k]$与$m[k+1,j]$，它们区间都比$j-i+1$短。按长度递增保证每个候选split的两个子状态已完成；只按左端点不自动满足右子区间依赖。
</Answer>

**问题 3**：LCS只保留两行能否直接重构序列？

<Answer>
不能用普通回溯，因为更早格的方向和值已丢失。若只求长度，两行足够；若需序列，应保存direction/full table、重新计算，或用Hirschberg分治在低空间中重构。
</Answer>

**问题 4**：optimal BST recurrence为何额外加$w[i,j]$？

<Answer>
选择root后，左右子树的每次成功或失败搜索相对其子问题都下沉一层，区间内每项查询成本统一加1。它们的总概率正是$w[i,j]$，所以要在左右最优成本之外加该权重。
</Answer>
