## 从“最早结束为何比最短活动更安全”开始

先预测：会议室只能容纳一个活动。面对`[1,4)`、`[3,5)`和`[0,6)`，先选持续时间最短的活动，是否一定给后续留下最多机会？不一定。持续时间忽略了结束边界；活动越早结束，可兼容的时间后缀越大。

<Term def="每一步选择当前看来最优且仍可行的局部选项，并且不回退；正确性必须证明该选择可嵌入某个全局最优解。">贪心算法</Term>不是“取最大或最小”的语法模板。它是一份proof contract：精确定义local choice，把任意optimum交换成包含该choice的optimum，再把剩余部分归约为同类子问题。

## 15.1 An activity-selection problem

### Compatible intervals

<Term def="给定共享资源上的开始与结束时间，从中选出数量最多且两两不重叠活动的优化问题。">活动选择问题</Term>要求最大化活动数量，而不是占用总时长或空闲时间。活动$a_i$占半开区间$[s_i,f_i)$；若$s_j\ge f_i$，则$a_j$可接在$a_i$之后。

设活动按结束时间非降序排列。选择最早结束的$a_1$后，剩余候选是：

$$
S_1=\{a_i\in S:s_i\ge f_1\}.
$$

问题的关键不是$a_1$“看起来不错”，而是存在一个最优解以$a_1$开始。设某最优解$A$的第一个活动为$a_k$。因为$a_1$结束最早，所以$f_1\le f_k$；用$a_1$替换$a_k$不会让$A$中任何后续活动冲突，活动数也不变。这是nonworsening exchange。

<CLRS4ActivityExchangeLab />

交换后，最优解余下部分必须是$S_1$上的最优解；否则用更大的兼容集合替换它，就能得到比原解更多活动，矛盾。因此一次choice后可永久丢弃所有开始早于$f_1$的活动，并在后缀上重复。

```cpp
vector<Activity> select_activities(vector<Activity> a) {
    sort(a.begin(), a.end(),
         [](auto x, auto y) { return x.finish < y.finish; });
    vector<Activity> selected;
    int boundary = numeric_limits<int>::min();
    for (const auto& item : a) {
        if (item.start >= boundary) {
            selected.push_back(item);
            boundary = item.finish;
        }
    }
    return selected;
}
```

排序耗时$O(n\log n)$，扫描$O(n)$；若输入已按finish排序，整体为$\Theta(n)$。相同结束时间可按start或标识稳定排序，正确性不变，但tie policy使witness可复现。

活动选择也可以写成区间DP：令$c[i,j]$为结束于$a_i$之后、开始于$a_j$之前的最大兼容活动数，则

$$
c[i,j]=
\max_{a_k\in S_{ij}}\{c[i,k]+c[k,j]+1\}.
$$

DP枚举第一个或中间活动；贪心证明进一步说明只需尝试最早结束的安全choice。贪心并非没有子问题，而是proof把transition候选从许多个压成一个。

## 15.2 Elements of the greedy strategy

### Greedy-choice property

<Term def="存在至少一个全局最优解包含算法当前选定的局部选择，因此该选择可在求解子问题之前永久提交。">贪心选择性质</Term>比optimal substructure更强。动态规划通常先求子问题，再比较choice；贪心先提交choice，只求由它产生的一个residual problem。

<CLRS4GreedyDecisionLab />

设计一个贪心算法时，应依次回答：

1. optimization objective究竟是数量、权重、成本还是延迟？
2. local choice的全序和tie policy是什么？
3. 任意optimal solution怎样交换成包含该choice且objective不变差？
4. 固定choice后，剩余候选是否真是原问题的较小实例？
5. feasibility和objective如何在induction中保持？

Exchange argument常用一个“最早分歧点”。比较greedy witness $G$与optimal witness $O$，找到两者第一处不同；把$O$该处选择替换成$G$的选择，证明前缀仍可行、剩余空间不缩小且成本不增。重复交换便把$O$变成$G$。

<CLRS4GreedyProofLab />

### When a plausible rule fails

局部最优必须与问题结构对齐。零钱系统$\{1,3,4\}$中，largest coin first对金额6给出$4+1+1$，而最优是$3+3$。这里不存在把最优首枚3无损交换成4的论证：交换后剩余金额2需要两枚硬币，总数增加。

<CLRS4GreedyCounterexampleLab />

<Callout type="trap" title="有optimal substructure就能贪心">
最短路、矩阵链和0-1背包都有最优子结构，但任意局部最优边或物品不一定安全。修法是单独证明greedy-choice property；若无法交换任意最优解，应保留多个choice并使用DP、搜索或其他方法。
</Callout>

反例测试应优先覆盖：一个局部choice阻塞两个稍差choice、相同key的tie产生不同未来、负权或容量约束破坏单调性，以及目标从cardinality改成weight。活动选择若改为最大总价值，earliest finish不再普遍正确，应转为weighted interval scheduling DP。

## 15.3 Huffman codes

### Prefix-free representation

<Term def="按字符频率反复合并两个最低频率节点所构造的最优前缀码，使消息的总编码位数最小。">Huffman编码</Term>把字符放在二叉树叶子，左边记0、右边记1。叶子到根路径决定codeword；因为字符只在叶子，没有codeword是另一个的prefix，串接后的bitstream可唯一解码。

若字符$c$频率为$c.freq$、在树$T$中深度为$d_T(c)$，总编码成本为：

$$
B(T)=\sum_{c\in C}c.freq\cdot d_T(c).
$$

固定长度码对6个字符每个至少3位；variable-length prefix code让高频字符靠近root、低频字符更深，从而降低weighted path length。

<CLRS4HuffmanForestLab />

Huffman算法维护一片forest。每轮从min-priority queue取出频率最小的$x,y$，建立频率$x.freq+y.freq$的parent并插回；最后剩下的root就是code tree。

```cpp
Node* huffman(vector<Node*> leaves) {
    MinPriorityQueue q(leaves);
    while (q.size() > 1) {
        Node* x = q.extract_min();
        Node* y = q.extract_min();
        Node* z = new Node(x->freq + y->freq, x, y);
        q.insert(z);
    }
    return q.extract_min();
}
```

有$n$个字符时进行$n-1$次merge；二叉heap实现为$O(n\log n)$，若频率已排序可用两个FIFO queue做到线性merge。编码左右位可以互换，等频tie也可能产生不同树，但最优成本相同；生产实现需固定排序次键以获得确定输出。

<CLRS4HuffmanPrefixLab />

### Why merging two minima is safe

任意最优full binary prefix tree中，取最深的一对sibling leaves。若它们不是最低频$x,y$，把更高频深叶与较低频浅叶交换不会增加成本，因为：

$$
\Delta=(f_{\mathrm{low}}-f_{\mathrm{high}})
(d_{\mathrm{deep}}-d_{\mathrm{shallow}})\le 0.
$$

更完整地说，成本差是频率差与深度差的乘积，低频放得更深不劣。因此存在一个最优树让$x,y$成为最深siblings。把它们收缩为频率$x.freq+y.freq$的伪字符$z$，原树成本满足

$$
B(T)=B(T')+x.freq+y.freq.
$$

附加项与其余结构无关，所以$T'$必须是收缩alphabet的最优树；否则替换为更优$T'$并展开$x,y$就会改进$T$。Sibling exchange给greedy choice，contraction给optimal substructure，induction完成证明。

<Callout type="trap" title="只按频率直接分配短码">
任意给高频字符短bit string可能违反prefix-free，例如同时使用`0`和`01`会导致解码边界不唯一。修法是构造完整二叉树，让所有字符位于叶子，并用根到叶路径生成codeword。
</Callout>

## 15.4 Offline caching

### Farthest in the future

<Term def="请求序列在决策前全部已知的缓存优化问题；满缓存miss时淘汰下一次访问最晚的resident page可最小化miss。">离线缓存</Term>给定容量$k$和完整page request sequence。命中不改变miss数；未命中且尚有空位时直接装入；只有“miss且已满”需要选择victim。

<CLRS4OfflineCacheTraceLab />

Belady策略也称farthest-in-future：对每个resident page查找其下一次请求位置，淘汰位置最远者；永不再请求可视为next use为$\infty$。它需要知道未来，因此是offline optimum，常用作在线LRU、FIFO等策略的benchmark，而不是普通运行时可直接实现的预言算法。

```text
OFFLINE-CACHE(requests, capacity)
1  for each request r at position i
2      if r is resident, continue
3      count one miss
4      if cache is full
5          evict page with farthest next request after i
6      load r
```

<CLRS4FarthestFutureLab />

正确性仍是exchange。设OPT在当前第一次与Belady不同的full-cache miss上淘汰$x$，Belady淘汰$y$，且$y$的next use不早于$x$。修改OPT，让它先淘汰$y$并暂时保留$x$。在原OPT下一次请求$y$之前，修改方案拥有$x$而缺$y$：任何请求若需要$x$，修改方案反而命中；其余page状态一致。到请求$y$时再对齐两方案，修改后的miss不会更多。

若cache初始为空，miss count可写为：

$$
M=\sum_{i=1}^{m}\mathbf{1}[r_i\notin C_{i-1}],
$$

其中$C_{i-1}$是处理请求$i$前的resident set。Proof必须核算强制load造成的状态变化，不能只比较victim的下次访问。相同next-use距离时任意victim都安全，但需稳定tie policy保证trace可重放。

Offline caching说明“最晚使用”有时才是正确局部choice；同一个词“greedy”并不规定方向。安全方向完全由exchange中的dominance关系决定。

## 小结

Chapter 15 Greedy Algorithms从activity-selection problem建立earliest-finish交换论证，再提炼elements of the greedy strategy：greedy-choice property、optimal substructure、feasibility invariant、exchange与residual instance。Huffman codes用最低频siblings交换和contraction最小化带权路径长度；offline caching用farthest-in-future交换最小化miss。

贪心的速度来自只保留一个choice，但这一删减必须由证明授权。每个可交付算法都应带有目标、确定choice、tie policy、交换映射、归约关系和复杂度；找不到nonworsening exchange时，应主动寻找反例并切换算法范式。

<Exercises>

**问题 1**：活动选择为何按最早结束安全，而按最早开始不安全？

<Answer>
最早结束活动的finish不晚于最优解首活动，替换后不会排除任何原本兼容的后续活动。最早开始可能持续很久并覆盖多个短活动，无法保证存在不减活动数的交换，所以缺少greedy-choice property。
</Answer>

**问题 2**：Huffman为何每次必须同时取两个最低频节点？

<Answer>
在某棵最优full binary tree中，可以通过交换让两个最低频字符成为最深sibling leaves。收缩这对siblings后得到更小alphabet的最优前缀码问题，因此合并二者是可归纳的安全choice；只取一个节点不能形成可收缩的二叉parent。
</Answer>

**问题 3**：相同频率的Huffman字符采用不同tie policy会破坏最优性吗？

<Answer>
不会。等频节点互换对带权路径长度贡献相同，可能生成不同codeword或树形但成本相同。实现仍应固定次排序键，以便编码器、解码器、测试和构建产物得到一致结果。
</Answer>

**问题 4**：为什么farthest-in-future不能直接作为普通在线缓存策略？

<Answer>
它在每次淘汰时需要知道每个resident page未来下一次请求位置，而在线算法只看到已发生请求。它是离线最优基准；实际在线策略可与其miss数比较竞争性能，但不能假装拥有未提供的未来信息。
</Answer>

</Exercises>
