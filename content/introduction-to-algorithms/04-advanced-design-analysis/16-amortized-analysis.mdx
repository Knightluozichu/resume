## 从“一次昂贵扩容是否意味着每次都很慢”开始

先预测：动态数组第9次插入可能复制8个旧元素再写入新元素，实际成本为9。能否据此断言每次INSERT都要$O(n)$？不能。前8次插入中只有容量边界触发复制；昂贵操作之间积累了足够多便宜操作。

研究sequence cost。它允许某次operation很贵，但要求所有长度$n$的合法序列总成本都受控。若总成本$T(n)=O(n)$，则每次amortized cost为$O(1)$，这不是说每次actual cost都为常数。


## 16.1 Aggregate analysis

### Stack operations

不区分各操作收费。考虑`PUSH`、`POP`和`MULTIPOP(k)`：单次`MULTIPOP`最坏可弹出$n$项，但每个item在被PUSH后最多POP一次。


若序列包含$n$次操作，PUSH数至多$n$，所有POP和MULTIPOP实际弹出的item总数也至多PUSH数。因此：

$$
T(n)\le n+n=2n,
\qquad
\frac{T(n)}{n}\le 2.
$$

该界对任何操作排列成立，包括最后一次清空全部元素。不能把每次MULTIPOP的参数$k$直接相加，因为空栈停止条件让许多requested pops没有实际成本。

### Incrementing a binary counter

二进制计数器`INCREMENT`把尾部连续1翻成0，再把首个0翻成1。值$2^j-1$之后的一次操作会翻$j+1$位，单次成本并非常数。


观察每一bit：最低位每次翻，bit $j$每$2^j$次increment至多翻一次。$n$次操作总flip数满足：

$$
\sum_{j=0}^{\lfloor\lg n\rfloor}
\left\lfloor\frac{n}{2^j}\right\rfloor
\lt
n\sum_{j=0}^{\infty}\frac{1}{2^j}
=2n.
$$

所以单次amortized cost小于2。这里没有假设counter value均匀分布；即使序列专门结束在昂贵carry上，总和仍受几何级数控制。

```cpp
int increment(vector<int>& bits) {
    int flips = 0;
    int i = 0;
    while (i < bits.size() && bits[i] == 1) {
        bits[i++] = 0;
        ++flips;
    }
    if (i == bits.size()) bits.push_back(0);
    bits[i] = 1;
    return flips + 1;
}
```

## 16.2 The accounting method

### Prepaying future work

像记账：amortized charge减actual cost形成credit。便宜操作预付，未来昂贵操作消费这些余额。

对stack可向每次PUSH收2：1支付实际push，1枚coin留在该item上。POP收费0并拿走item上的coin支付实际pop。因为item不存在就不能pop，任何sequence prefix都不会欠债。


对前$i$次操作，令$\hat c_j$为摊还收费、$c_j$为实际成本、$b_i$为余额：

$$
b_i=\sum_{j=1}^{i}(\hat c_j-c_j)\ge 0.
$$

于是$\sum c_j\le\sum\hat c_j$。非负条件必须对每个prefix成立，而不是仅检查最终余额；否则证明可能在中途借用尚未发生操作的钱，无法上界提前停止的序列。


核算法不要求所有operation采用相同charge。可以让push收费2、pop收费0；关键是明确credit属于哪个object或state，并证明其创建、转移和消费均保持不变量。信用不能被同一未来工作重复使用。

```cpp
struct AccountedStack {
    vector<int> data;
    int credits = 0;

    void push(int value) {
        data.push_back(value);
        ++credits;
    }
    void pop() {
        if (data.empty()) return;
        data.pop_back();
        --credits;
        assert(credits >= 0);
    }
};
```


## 16.3 The potential method

### State-level stored work

是全局化accounting。对第$i$次操作前后状态$D_{i-1},D_i$，定义：

$$
\hat c_i=c_i+\Phi(D_i)-\Phi(D_{i-1}).
$$

正势能变化表示预存未来工作，负变化表示释放能量支付昂贵操作。求和后中间项两两抵消：

$$
\sum_{i=1}^{n}\hat c_i
=
\sum_{i=1}^{n}c_i+\Phi(D_n)-\Phi(D_0).
$$

若$\Phi(D_n)\ge\Phi(D_0)$，则总摊还成本上界总实际成本。常令$\Phi(D_0)=0$且所有reachable state势能非负，便自动覆盖任意prefix。


### Binary counter potential

令$\Phi(D)$为counter中1的个数。一次increment若有$t$个trailing ones，实际翻$t+1$位；势能变化为$1-t$，所以：

$$
\hat c_i=(t+1)+(1-t)=2.
$$


carry越长，actual cost越高，但清除的1越多，释放势能恰好抵消。选择potential不是猜一个“看起来像能量”的量，而是识别昂贵操作消耗了哪些此前逐步积累的结构。

Potential可以整体加常数而不改变$\Delta\Phi$，但边界条件仍要保证最终potential不低于初始值。若允许任意大负势能，摊还总和可能低估actual total。

## 16.4 Dynamic tables

### Expansion by doubling

支持table insert和delete。容量`size`、元素数`num`，load factor为$\alpha=num/size$。

只考虑插入：未满时写一个slot成本1；满时申请两倍空间，复制`num`项，再插入。扩容复制规模依次为$1,2,4,\ldots$，到$n$次insert前总复制量小于$n$：

$$
T(n)
\lt
n+\sum_{j=0}^{\lfloor\lg n\rfloor}2^j
\lt 3n.
$$


```cpp
void table_insert(Table& t, Value value) {
    if (t.num == t.size) {
        auto larger = allocate(max(1, 2 * t.size));
        copy(t.data, t.data + t.num, larger);
        release(t.data);
        t.data = larger;
        t.size = max(1, 2 * t.size);
    }
    t.data[t.num++] = value;
}
```

势能$\Phi(T)=2\,num-size$适用于load至少一半的插入阶段。普通insert使势能增加2并支付写入；扩容后size翻倍，旧状态积累的势能下降，支付复制。严格推导需分别代入扩容前后`num`与`size`。

### Contraction without thrashing

若delete后load一到$1/2$就容量减半，边界附近一次insert扩容、一次delete缩容可反复复制$\Theta(n)$项，摊还界失效。CLRS使用hysteresis：满载时扩为两倍，仅在load降至$1/4$时缩为一半；缩容后load回到$1/2$，与下一次扩容之间隔着许多insert。


同时处理扩缩容时可用分段potential：

$$
\Phi(T)=
\begin{cases}
2\,num-size,&\alpha\ge 1/2,\\
size/2-num,&\alpha\lt 1/2.
\end{cases}
$$

它在$\alpha=1/2$处为0，在接近满载或四分之一缩容边界时积累credit。每次普通insert/delete的actual cost与potential change均为常数，resize释放的potential支付copy，因此任意$m$次操作总成本为$O(m)$。


## 小结

Chapter 16 Amortized Analysis用aggregate analysis直接界定栈与binary counter总成本，用accounting method把预付coin绑定到未来工作，用potential method把储存工作编码成状态函数。Dynamic tables展示扩容几何级数，以及四分之一缩容阈值如何避免thrashing。

摊还界是对任意操作序列的确定性上界，不是average-case概率。合格证明必须写清actual cost model、操作序列量词、credit或potential不变量、昂贵事件间隔与最终求和；单个示例trace只能辅助理解，不能替代全序列证明。
