## 从“为什么不为每次rank查询重新中序遍历”开始

先预测：一棵平衡搜索树有一百万个节点，要查询key 42是第几小。每次中序遍历需线性时间；若每个节点记录其subtree size，沿一条root-to-node路径就能累计被跳过的节点数。

不是随手加cache字段。必须给出字段的精确定义、base value、更新与旋转维护规则，并证明新查询依据该字段跳过数据时不会漏解。


## 17.1 Dynamic order statistics

### Subtree sizes

以red-black tree为base。每个节点$x$增加`size[x]`，表示以$x$为root的内部节点数；sentinel `NIL`的size为0：

$$
size[x]=size[x.left]+size[x.right]+1.
$$

只依赖两个children，因此沿insert/delete search path可自底向上更新；rotation只改变常数个节点的child关系。


### Selecting by rank

在节点$x$，其local rank为$r=size[x.left]+1$。若请求$i=r$返回$x$；若$i\lt r$去left；否则去right并把请求改为$i-r$。

```text
OS-SELECT(x, i)
1  r = x.left.size + 1
2  if i == r, return x
3  if i < r, return OS-SELECT(x.left, i)
4  return OS-SELECT(x.right, i - r)
```


每步下降一层，red-black tree高度$O(\log n)$，所以OS-SELECT为$O(\log n)$。调用前必须验证$1\le i\le size[x]$；否则递归可能进入NIL却没有合法答案。

### Computing a node's rank

OS-RANK从$x$开始，初值$r=size[x.left]+1$。向parent上升时，若当前node是right child，则parent及parent的left subtree都排在$x$之前，需加$size[parent.left]+1$：

$$
rank(x)=size[x.left]+1+
\sum_{\substack{y\text{ on path}\\y\text{ is a right child}}}
(size[y.parent.left]+1).
$$


```cpp
int os_rank(Node* tree, Node* x) {
    int rank = x->left->size + 1;
    for (Node* y = x; y != tree; y = y->parent) {
        if (y == y->parent->right)
            rank += y->parent->left->size + 1;
    }
    return rank;
}
```

循环同样只走tree height。若允许duplicate keys，必须定义节点全序，例如`(key, insertion_id)`，否则“某个key的rank”可能是区间而非单值。

## 17.2 How to augment a data structure

### Four design steps

扩张数据结构的方法可分四步：

1. 选择支持原始更新和基础查询的underlying structure。
2. 定义额外字段及NIL值，写出局部recurrence。
3. 证明insert、delete和rotation能维护字段且代价受控。
4. 设计新操作，并证明每次branch或pruning都由字段语义授权。


给出通用维护上界。普通BST search path有$O(\log n)$个节点，可在path上更新字段；red-black fixup执行$O(\log n)$次recolor和常数次rotation。每次rotation只需重算旋转涉及的两个node。

以left rotation为例，原$x$的右child $y$升为subtree root。先用新children重算$x$，再重算$y$：

$$
field[x]\leftarrow F(x,x.left,x.right),
\qquad
field[y]\leftarrow F(y,y.left,y.right).
$$


```cpp
void repair_after_left_rotate(Node* x, Node* y) {
    x->size = x->left->size + x->right->size + 1;
    y->size = y->left->size + y->right->size + 1;
    // The same child-first order works for any child-local field.
}
```

字段“node depth”不满足该定理：一个rotation可能改变整个moved subtree内许多节点的depth，且depth依赖ancestors而非children。定理不是说它无法维护，而是不能直接获得常数rotation repair的结论。


## 17.3 Interval trees

### Overlap contract

存closed intervals $i=[i.low,i.high]$。两个closed intervals $i,j$重叠当且仅当：

$$
i.low\le j.high
\quad\text{and}\quad
j.low\le i.high.
$$


若业务使用half-open intervals，端点相等不算overlap，应改用严格比较。Endpoint policy必须从存储到查询保持一致。

### The max field

每个node $x$保存以$x$为root的所有interval最大high：

$$
x.max=\max\{x.int.high,\ x.left.max,\ x.right.max\},
$$

并令`NIL.max`为负无穷。该字段是child-local，扩张定理保证red-black insert/delete仍为$O(\log n)$。


### Searching for one overlap

从root开始。若当前interval与query重叠就返回；否则，当left非空且`left.max >= query.low`时去left，因为left仍可能存在high足够大的interval；反之去right。

```text
INTERVAL-SEARCH(T, query)
1  x = T.root
2  while x != T.nil and x.int does not overlap query
3      if x.left != T.nil and x.left.max >= query.low
4          x = x.left
5      else
6          x = x.right
7  return x
```


为何去right不会漏掉left解？若`left.max < query.low`，left中每个interval的high都早于query.low，绝无重叠。为何选择left不会错过唯一right解？即使left最终无解，可以证明若right有重叠，则沿所选路径的结构关系保证left方向存在可返回的overlap，或算法之后在相关证明中以BST low-order排除不可能区域。这里目标是返回任意一个overlap，不是枚举全部。

查询每轮下降一层，时间$O(\log n)$。若要报告所有$k$个重叠区间，需要遍历所有仍可能命中的subtrees，典型输出敏感上界为$O(\log n+k)$，不能用“返回一个”的路径证明直接宣称完成枚举。


## 小结

Chapter 17 Augmenting Data Structures以dynamic order statistics展示`size`如何支持SELECT与RANK，再用how to augment a data structure中的四步法和augmentation theorem概括维护条件。Interval trees以low为BST key、以subtree max high为扩张字段，实现重叠搜索。

扩张的核心不是多一个字段，而是一个端到端证书：field semantics、sentinel base、path update、rotation repair、query pruning和complexity。任何一环缺失，metadata都可能在结构更新后悄悄失真，或让查询错误跳过含答案的subtree。
