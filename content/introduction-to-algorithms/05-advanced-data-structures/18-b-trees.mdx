## 先问：为什么外存里的树不照搬二叉搜索树？

把磁盘想成一排需要整箱搬运的货架：一次搬运可以带回很多相邻货物，但搬运本身比在箱内扫一遍更贵。如果每个节点只放一个 key，查找就会反复搬箱；如果一个节点正好填满页面，同一箱里的许多比较可以在内存中完成。

本章解决的问题是：如何让一棵搜索树把昂贵的“搬一页”次数压到很少，同时仍然能插入和删除。没有占用边界，页面可能太空；没有分裂和合并，更新会破坏有序范围。

先预测：当页面一次能装下数百个 key 时，应该优先减少树的层数，还是优先让每页只放一个 key？选择后推进下面的实验，观察搜索、分裂和删除的证据是否保持一致。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：只看比较次数，不看 page access">

现象：实现报告了页内二分查找的比较次数，却说算法一定很快。

原因：外存模型中读取一页的代价通常远高于在已读页面内比较；两种成本不是同一个计数器。

修复：同时报告 page access 和页内比较；先根据页面容量选择最小度数，再讨论 CPU 常数。

</Callout>

<Callout type="trap" title="陷阱：把 full child 直接交给插入递归">

现象：向一个已经有 `2t−1` 个 keys 的 child 继续下降，写入时才发现 parent 没有位置。

原因：parent 可能无法接收 promoted median，递归也无法保证下一步有空位。

修复：下降前先 split child；median 上移、两侧 child 分开后，再根据新 separator 选择路径。

</Callout>

<Callout type="trap" title="陷阱：删除后再处理 underflow">

现象：删除已经让 child 变空，随后才尝试从 sibling 借 key，结果忘记同步 parent separator 或 child pointer。

原因：递归已经经过不合法的 page，修复时机太晚，无法维持一遍向下遍历的前提。

修复：进入 child 前先 borrow 或 merge，让递归目标至少拥有 `t` 个 keys；每次搬运都同步 separator 和 pointer。

</Callout>

<Callout type="trap" title="陷阱：只验证 inorder keys 就宣布 B 树正确">

现象：所有 key 的中序序列正确，但某个 leaf 深度不同，或一个 internal node 的 child 数与 key 数不匹配。

原因：集合结果无法证明占用边界、范围分区和页面指针仍然成立。

修复：每次操作后递归检查 key 有序、child range、occupancy、children 数、等深叶子和 dirty page 写回。

</Callout>

## B-trees / B 树

### 页面模型与核心字段

<Term def="把搜索树节点按页面组织、让一页容纳多个有序 key 的外存搜索树">B 树</Term>把节点设计成页面，而不是把每个 key 分散到独立节点。一个 internal page 有 `n[x]` 个 keys，就有 `n[x]+1` 个 children；相邻 separator 划出的范围决定下一页是否值得读取。

<Term def="控制每个非根节点最少和最多 key 数的参数，通常记作 t">最小度数</Term> `t` 满足 `t ≥ 2`。除 root 外，每个节点至少有 `t−1` 个 keys，最多有 `2t−1` 个 keys；internal node 的 children 数总比 keys 多 1。root 可以更小，因为小树不应被迫浪费一个完整页面。

这些上下界就是 <Term def="节点在页面中允许保持的 key 数和 child 数范围">页面占用边界</Term>。它们让 split 有确定的上限，也让 delete 能够通过 borrow 或 merge 恢复合法占用。

### definition of B-trees / B 树定义

一棵 B-trees 必须同时满足以下结构不变量：

1. 每个节点内的 keys 有序；相邻 child range 被 separator 严格分开。
2. 除 root 外，节点的 key 数在 `t−1` 到 `2t−1` 之间。
3. internal node 有 `n[x]+1` 个 children；leaf 没有 children。
4. 所有 leaves 具有相同 depth。
5. root 非空时至少有一个 key；删除后可以收缩为唯一 child。

高度为 `h` 的最稀疏非空 B 树，root 有 1 个 key，下一层最多只提供两个 children，之后每个 internal node 至少有 `t` 个 children。因此：

$$
n \ge 1 + 2(t-1)\sum_{i=0}^{h-1}t^i = 2t^h - 1.
$$

这个式子在说：节点越宽，达到同样 key 数所需的页面层数越少。

于是高度满足：

$$
h \le \log_t\frac{n+1}{2}.
$$

这个式子在说：B 树把外存查找的 page access 压到 `O(log_t n)`；但 `t` 不能盲目增大，还要平衡页面大小、key 宽度、pointer 宽度和页内搜索。

## basic operations on B-trees / B 树基本操作

### 搜索：一次只读取一页

在当前 page 中找到首个不小于目标 key 的位置。相等就返回；当前节点是 leaf 就失败；否则根据 range 读取对应 child。

```text
B-TREE-SEARCH(x, k)
1  i = first index with k <= x.key[i]
2  if i <= x.n and k == x.key[i], return (x, i)
3  if x.leaf, return NIL
4  DISK-READ(x.child[i])
5  return B-TREE-SEARCH(x.child[i], k)
```

若树高为 `h`，page access 是 `O(h) = O(log_t n)`。页内线性扫描每层约需 `O(t)` 比较，二分查找约需 `O(log t)` 比较；因此应该把两个成本分开描述。缓存命中可能减少物理设备等待，但不会改变算法的 page reference 边界。

### 插入：先分裂，再下降

当 child 已经有 `2t−1` 个 keys 时，先把中间 key 提升到 parent：左 child 保留前 `t−1` 个，右 sibling 接收后 `t−1` 个；如果 child 不是 leaf，还要把对应的 children 一起分开。

<Term def="把 full child 的中间 key 提升到 parent，并把两侧 keys 与 pointers 分开">分裂提升</Term>要求 parent 本身 nonfull。若 root full，先创建一个空的新 root，把旧 root 接成 child，再执行 split；只有这一刻树高会增加。

```cpp
void splitChild(Node& parent, int i, int t) {
    Node& full = *parent.child[i];
    auto right = makeNode(full.leaf);
    Key median = full.keys[t - 1];
    right->keys.assign(full.keys.begin() + t, full.keys.end());
    full.keys.resize(t - 1);
    if (!full.leaf) {
        right->children.assign(full.children.begin() + t, full.children.end());
        full.children.resize(t);
    }
    parent.keys.insert(parent.keys.begin() + i, median);
    parent.children.insert(parent.children.begin() + i + 1, std::move(right));
}
```

插入 nonfull node 时，leaf 只需右移较大的 keys；internal node 则先判断目标 child 是否 full，必要时 split，再根据 promoted median 重新决定左或右。这个顺序保证递归永远不会进入 full child。

### 页面写回与复杂度

一次操作包含 `DISK-READ`、页内比较、节点修改和 `DISK-WRITE`。渐近地，搜索和插入都沿一条 root-to-leaf 路径工作，每层只做常数次页面读写：

$$
Q_{page}=O(h)=O(\log_t n).
$$

这个式子在说：page access 随树高增长，而页内比较应作为另一个成本维度报告。

## deleting a key from a B-tree / 从 B 树删除键

### 下行前的安全边界

删除比搜索和插入更容易破坏占用。我们使用 <Term def="递归下降前先保证目标 child 至少有 t 个 keys，使删除后仍不会低于 t−1">下行不变量</Term>：进入 child 前，它至少有 `t` 个 keys。

如果目标 child 只有 `t−1` 个 keys，就在下降前修复：相邻 sibling 至少有 `t` 个 keys 时借位；两侧都是 `t−1` 时，把一个 separator 和两个 child 合并为 `2t−1` 个 keys 的节点。这样递归进入的目标仍然有足够余量。

### key 在 leaf 或 internal node

- key 在 leaf：直接删除，剩余占用仍由下行不变量保护。
- key 在 internal node：若前 child 至少有 `t` 个 keys，用 predecessor 替换；否则若后 child 至少有 `t` 个 keys，用 successor 替换；两边都不足时 merge，再在合并节点中继续删除。
- key 不在当前 node：定位 child；若它只有 `t−1` 个 keys，先 borrow 或 merge，再递归。

<Term def="从富 sibling 向目标 child 借 key，或把两个贫 child 与 parent separator 合并">借位合并</Term>不是把 key 随便塞进 child。以 left sibling 借位为例：parent separator 先下移到目标 child，left sibling 的最大 key 再上移成为新的 separator；internal node 还必须同步移动对应 child pointer。

### root 收缩与完整验证

merge 可能让 root 的最后一个 key 被移走。此时把唯一合并 child 提升为新 root，树高减少 1。实现测试不能只比较所有 key 的集合，还要在每次操作后检查：

1. 每个 node 的 keys 有序，且 child range 没有交叠或空洞。
2. 非根节点满足 `t−1 ≤ keys ≤ 2t−1`；internal node 的 children 数等于 keys 数加 1。
3. 所有 leaves 深度相同，root 收缩后仍然满足 root 例外。
4. 发生 borrow、merge、split 时，separator、child pointer 与 dirty page 都同步写回。

## 小结

- B 树把多个有序 keys 与 child ranges 放入页面，减少 page access。
- definition of B-trees 固定占用边界、root 例外、child 数和等深叶子。
- basic operations on B-trees 通过 page search 与 split-before-descent 保持路径安全。
- deleting a key from a B-tree 在下降前 borrow 或 merge，并在 root 空时收缩高度。
- 正确性检查必须覆盖 ranges、occupancy、leaf depth 和页面写回，而非只看 key 集合。
