## 从“连通性查询为何不必每次重跑图搜索”开始

先预测：边不断加入无向图，只需回答两个顶点是否已连通。每次从头BFS会重复探索旧边；若每个connected component维护一个representative，查询只需比较两个FIND-SET结果，加入跨component边时再UNION。

也称union-find。它适合只合并、不拆分的动态等价关系；如果需要删除边后拆分component，接口与分析都不足。


## 19.1 Disjoint-set operations

### Partition contract

设universe为$S=\{x_1,\ldots,x_n\}$，当前sets构成partition：

$$
S_1\cup S_2\cup\cdots\cup S_k=S,
\qquad
S_i\cap S_j=\varnothing\quad(i\ne j).
$$

有三项：

1. `MAKE-SET(x)`要求$x$尚未存在，创建$\{x\}$。
2. `FIND-SET(x)`返回该set的representative；同set元素结果相同。
3. `UNION(x,y)`先找两root，不同才合并；相同则no-op。


Representative不必是最小元素，也不必在不同版本保持不变。客户端只能依赖“相同集合返回相同代表”，不能把具体root identity写成业务语义。Tie policy可固定root选择以便测试复现。

在connected components或Kruskal算法中，`FIND-SET(u) != FIND-SET(v)`既是“当前不连通”判断，也是加入edge不会成环的certificate；随后UNION两个representatives。

## 19.2 Linked-list representation of disjoint sets

### Direct representative pointers

让MAKE-SET和FIND-SET为$O(1)$。UNION把一条list接到另一条tail，但被追加list的每个node都要重写representative pointer。

若总把large list附到singleton后面，已有大量元素可能反复改pointer，$n-1$次union累计$\Theta(n^2)$。


Weighted-union heuristic总把shorter list附到longer list。某个element每次被重写时，其new set size至少翻倍：

$$
1,2,4,\ldots,2^r\le n
\quad\Longrightarrow\quad
r\le\lfloor\lg n\rfloor.
$$


因此$n$个elements的全部representative rewrites至多$O(n\log n)$。含$n$次MAKE-SET的$m$个操作总时间：

$$
T(m,n)=O(m+n\log n).
$$

```cpp
void list_union(Set* x, Set* y) {
    if (x == y) return;
    if (x->size < y->size) swap(x, y);
    x->tail->next = y->head;
    for (Node* node = y->head; node != nullptr; node = node->next)
        node->representative = x->head;
    x->tail = y->tail;
    x->size += y->size;
}
```

Head/tail empty-state、self-union和size update必须原子保持。实际并发环境还需锁或版本协议，本章分析假定顺序操作。


## 19.3 Disjoint-set forests

### Parent-pointer trees

避免给所有成员保存direct representative。MAKE-SET令`parent[x]=x`；FIND沿parent到root；UNION把一棵root挂到另一棵root。


若随意link，连续把root挂成child可形成长度$n-1$的chain，使FIND为$\Theta(n)$。Union by rank为root维护height upper bound `rank`，总把低rank root挂到高rank root；仅当ranks相等时任选一root为parent并把它rank加1。


```cpp
void link_roots(Node* x, Node* y) {
    if (x->rank > y->rank) swap(x, y);
    x->parent = y;
    if (x->rank == y->rank) ++y->rank;
}

void unite(Node* x, Node* y) {
    link_roots(find_set(x), find_set(y));
}
```

Rank为$r$的root至少代表$2^r$个elements，因此：

$$
rank[x]\le\lfloor\lg n\rfloor.
$$

单独使用union by rank使tree height为$O(\log n)$。Path compression会让rank不再等于实际height，但它仍是单调upper-bound标签，link规则继续有效；不要在compression后重新计算rank。

### Path compression

FIND-SET递归找到root后，在return path把每个visited node直接指向root。Partition不变，后续queries更短。


```cpp
Node* find_set(Node* x) {
    if (x->parent != x)
        x->parent = find_set(x->parent);
    return x->parent;
}
```


Compression只改parent，不改rank。Iterative版本需要先找到root，再第二次遍历path执行rewire；若只把起点指向grandparent，是path halving，仍是有效变体但证明与具体writes不同。

## 19.4 Analysis of union by rank with path compression

### Sequence bound

组合后，单次FIND仍可能遇到较长的尚未压缩path；正确结论是长度$m$操作序列的总时间。

对$n$次MAKE-SET及总计$m\ge n$次operations：

$$
T(m,n)=O(m\,\alpha(n)),
$$

其中$\alpha$是inverse Ackermann function，增长极慢但不是数学上的常数。


分析核心可分三层：

1. Rank只在相等rank roots合并时增加，故rank沿parent path严格增加。
2. Rank为$r$的node需要至少$2^r$规模，high-rank nodes数量迅速减少。
3. Path compression让一个node跨过大量中间rank；按rank区间为这些跳跃收费后，重复昂贵traversal极少。

完整证明使用快速增长函数对rank分层，并把FIND path成本分给nodes。不能用“第一次压平后全是常数”替代：不同union会把roots重新link，且一段序列中仍会创建新的未压缩paths。


## 小结

Chapter 19 Data Structures for Disjoint Sets先定义disjoint-set operations与partition contract；linked-list representation用weighted union和size doubling把pointer rewrites压到$O(n\log n)$。Disjoint-set forests用parent roots表示集合，union by rank控制height，path compression降低未来FIND成本。

Analysis of union by rank with path compression给出$O(m\alpha(n))$总序列界。正确实现必须保持forest acyclic、只link representatives、相等rank时才递增，并让compression只重写parents；正确说明则要区分amortized practical constant与worst-case per-call constant。
