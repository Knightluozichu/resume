## 先问：同一张图为什么会有不同的遍历形状？

把图想成一张城市地图：路口是地点，路是连接。你可以先把离起点一条路能到的地点全部看完，也可以沿一条路走到尽头再回头；两种路线都看同一张地图，却留下不同的证据。

本章解决的问题是：如何存储连接、如何系统地发现地点，以及如何从发现顺序推出最短距离、依赖顺序或互相可达的群组。没有明确的边合同，反向边、重复边和权重会让“访问一次”失去意义。

先预测：从起点出发，应该先展开同一距离的所有节点，还是先沿一条分支走到底？选择一个模式并推进下面的实验，观察它留下的是 frontier、时间区间、完成顺序还是转置证据。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：把 adjacency list 与 matrix 的成本混成一个 O(V+E)">

现象：不管图是稀疏还是稠密，都直接写遍历成本为 `O(V+E)`，却没有说明如何枚举邻居。

原因：list 枚举一个 vertex 的邻居与 degree 相关；matrix 扫描一整行则可能每次都花 `Θ(V)`。

修复：先声明表示，再分别报告空间、邻居枚举和 edge membership 的成本；不要把矩阵的逐行扫描省略掉。

</Callout>

<Callout type="trap" title="陷阱：BFS 发现节点后还反复改 parent">

现象：节点已入队却被后来的边再次改 parent，最后得到的路径不再对应首次达到它的最短层。

原因：BFS 的距离证书来自 FIFO frontier；首次发现时，所有更短层已经处理完。

修复：WHITE 节点第一次发现时立即设置 distance 和 parent，之后只扫描它，不重新选择父节点。

</Callout>

<Callout type="trap" title="陷阱：看到一条边就宣布图能拓扑排序">

现象：输出了一个看似合理的排列，却没有检查 directed cycle。

原因：拓扑序只对 DAG 存在；DFS 看到 GRAY ancestor 的 back edge 就已经给出环证据。

修复：在生成 reverse finish order 前先处理 back edge；验证器检查每条 directed edge 的起点位置严格早于终点。

</Callout>

<Callout type="trap" title="陷阱：在原图上跑第二遍 SCC DFS">

现象：第二遍 DFS 从一个 component 沿 outgoing edge 吞并了另一个本不互达的 component。

原因：Kosaraju 的第二遍需要在 transpose 上按第一遍 finish 时间递减顺序启动。

修复：构造 `Gᵀ`，按第一遍的 decreasing finish order 启动第二遍；每棵第二遍 DFS tree 才是一个 SCC。

</Callout>

## elementary graph algorithms / 基本图算法

### 图和边的合同

图算法前必须先声明：graph 是 directed 还是 undirected，edge 是否 weighted，是否允许 parallel edge 与 self-loop，以及遍历时是否按 logical edge 去重。相同的 vertex 集合在不同合同下可能代表不同问题。

<Term def="描述 vertex、edge、方向、权重与表示方式的完整约定">图的表示</Term>是算法的输入边界。它决定空间和访问方式，但不决定 BFS、DFS 或 SCC 的证明本身。

### representations of graphs / 图的表示

<Term def="为每个 vertex 保存相邻 vertex 列表的表示，适合枚举实际存在的边">邻接表</Term>对有向图的空间是 `Θ(V+E)`；无向边 `{u,v}` 通常在 `u` 和 `v` 的列表中各出现一次。枚举 `u` 的邻居需要 `Θ(deg(u))`，所有列表扫描一次就是 `Θ(V+E)`。

邻接矩阵空间是 `Θ(V²)`，判断某条边是否存在可在 `O(1)` 完成，但枚举一行的成本是 `Θ(V)`。稠密图或频繁 pair query 可以偏好矩阵；稀疏图的遍历通常偏好邻接表。

对无向图，如果要让每条 logical edge 只处理一次，需要 edge id 或固定的 vertex 顺序；否则同一条边的两个 adjacency incidences 会被误计为两条边。

$$
\text{adjacency-list space}=\Theta(V+E),\qquad
\text{adjacency-matrix space}=\Theta(V^2).
$$

这个式子在说：表示不是实现细节，而是决定遍历成本模型的第一项选择。

## breadth-first search / 广度优先搜索

<Term def="使用先进先出队列逐层发现 vertex 的遍历，适合无权边的最短距离">广度优先搜索</Term>（BFS）维护 WHITE、GRAY、BLACK 三种状态。起点 distance 为 0；发现邻居时立即设置 `distance = parent.distance + 1` 并入队；出队后扫描完全部邻居才变 BLACK。

```text
BFS(G, s)
1  initialize every vertex WHITE, distance infinity, parent NIL
2  color s GRAY, set s.distance = 0, enqueue s
3  while queue is not empty
4      u = dequeue
5      for each v in G.Adj[u]
6          if v is WHITE
7              color v GRAY; v.distance = u.distance + 1
8              v.parent = u; enqueue v
9      color u BLACK
```

FIFO 队列保证队首节点所在层不晚于队尾节点。若 edge `(u,v)` 连接两个可达节点，则真实最短距离满足：

$$
\delta(s,v)\le\delta(s,u)+1.
$$

这个式子在说：沿一条边最多只增加一层；BFS 首次发现 `v` 时，前面所有更短层都已经被处理，因此 `d[v] = δ(s,v)`。

parent 指针形成 breadth-first tree。打印路径时从目标沿 parent 回到 source，再反转；不可达 vertex 保持 infinity 和 NIL。邻接表实现总成本为 `O(V+E)`，因为每个 vertex 最多入队一次、每个 adjacency entry 扫描一次。

## depth-first search / 深度优先搜索

<Term def="沿一条分支递归深入、完成后回退，并记录发现与完成时间的遍历">深度优先搜索</Term>（DFS）在首次进入 vertex 时记录 discovery time 并置 GRAY；所有 outgoing adjacency 扫描完后置 BLACK 并记录 finish time。它得到的是 DFS forest，而不是按距离分层的树。

```cpp
void dfsVisit(Vertex u) {
    color[u] = GRAY;
    discover[u] = ++time;
    for (Vertex v : adjacency[u]) {
        if (color[v] == WHITE) {
            parent[v] = u;
            dfsVisit(v);
        }
    }
    color[u] = BLACK;
    finish[u] = ++time;
}
```

任意两个 vertex 的时间区间要么互不相交，要么一个完整包含另一个；完整包含关系恰好对应 DFS forest 中的 ancestor 关系：

$$
u\text{ is ancestor of }v
\iff d[u]\lt d[v]\lt f[v]\lt f[u].
$$

这个式子在说：一个分支从打开到关闭的时间窗会包住它递归发现的后代。

在 directed graph 中，遇到 GRAY ancestor 是 back edge，说明存在 directed cycle；遇到 WHITE 是 tree edge，遇到 BLACK 可能是 forward 或 cross edge。递归实现的 call stack 最坏为 `O(V)`，大图可改用显式 stack，但必须保存下一个 neighbor index 才能保持 finish 语义。

## topological sort / 拓扑排序

<Term def="对 DAG 的 vertex 排列，使每条 directed edge 都从较早位置指向较晚位置">拓扑序</Term>只对 DAG 存在。DFS 在 vertex finish 时把它放到列表前端，等价于按 finish time 递减排序。

对每条 edge `(u,v)`，合法结果必须满足 `position(u)` 小于 `position(v)`。如果 DFS 发现 `v` 是 GRAY ancestor，就存在 back edge，图有环，不能生成拓扑序。

拓扑序通常不唯一：neighbor iteration 顺序和 tie policy 会改变 witness。验证器不应只比较一个固定数组，而应检查每个 vertex 恰好出现一次，并逐条检查 edge 方向。

## strongly connected components / 强连通分量

<Term def="有向图中任意两个 vertex 互相可达的最大等价类">强连通分量</Term>（SCC）把 mutual reachability 压缩成 component。Kosaraju 的两遍 DFS 是：

1. 在 `G` 上运行 DFS，记录 finish times。
2. 构造 transpose `Gᵀ`，把每条 directed edge 反向。
3. 按第一遍 finish time 递减顺序，在 `Gᵀ` 上启动 DFS。
4. 第二遍的每棵 DFS tree 就是一个 SCC。

把每个 SCC 收缩成一个节点得到 condensation graph。它必是 DAG：如果 component 之间存在环，它们就能互相到达，原本应属于同一个 SCC。第一遍的 finish 顺序保证第二遍从 transpose condensation 的合适 source component 开始，DFS 不会越过仍未输出的 component。

transpose 不改变 SCC 内部的 mutual reachability，只反向 component 之间的 edge。因此两遍 DFS、构造 transpose 和扫描所有 adjacency entry 的总成本仍为 `O(V+E)`。

## 小结

- elementary graph algorithms 先由图与边的合同决定空间和邻居访问成本。
- representations of graphs 在 adjacency list 的稀疏遍历与 matrix 的常数边查询之间做取舍。
- breadth-first search 以 FIFO frontier 证明无权最短距离；depth-first search 以时间区间证明祖先和环。
- topological sort 用 reverse finish order 排列 DAG；back edge 表示不能排序的环。
- strongly connected components 在 `G` 与 `Gᵀ` 上运行两遍 DFS，得到 condensation DAG 的互达分组。
