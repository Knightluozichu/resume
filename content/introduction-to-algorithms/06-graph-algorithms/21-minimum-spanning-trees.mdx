## 先问：每次选最便宜的边为什么可能成环？

把图想成一组城市和候选道路。目标是让所有城市连通，同时总道路成本尽可能小；不需要让每个城市都沿着离某个起点最近的路线到达。选择一条很便宜的道路之前，要先问它是否会把两个已经连通的区域再次绕成环。

本章解决的问题是：怎样把“便宜”变成可证明的安全选择。没有 component 或 cut 的证据，三角形上的三条低价边会形成 cycle；图不连通时，算法得到的也只是 forest，不能悄悄称作 spanning tree。

先预测：当一条 edge 是当前 crossing edges 中最轻的，它是否一定能加入某棵 MST？选择一个模式推进下面的实验，观察割性质、Kruskal 和 Prim 如何给同一个 safe edge 不同的操作路径。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：全局最小 edge 就一定安全">

现象：把所有 edge 按 weight 排序，看到最小 edge 就无条件加入。

原因：它可能连接同一 component 的两个 vertex，形成 cycle；全局 weight 没有说明当前 forest 的 cut。

修复：Kruskal 先用 DSU 判断 endpoints 是否属于不同 component；更一般地，回到某个 respecting cut 的 light crossing edge 证书。

</Callout>

<Callout type="trap" title="陷阱：Prim 的 key 是从 root 累加的距离">

现象：把 `key[v]` 当作 root 到 `v` 的路径总 weight，按 shortest path 的方式更新。

原因：Prim 的 key 只表示一条连接当前 tree 与 `v` 的最轻 crossing edge，不是 source distance。

修复：只在 `v` 仍在 frontier 且 `w(u,v)` 小于当前 key 时更新 parent 和 key；不要累加 root path。

</Callout>

<Callout type="trap" title="陷阱：少于 V−1 条边也可以叫 MST">

现象：输入图 disconnected，算法返回了几棵 component 内的树，却把结果标成 spanning tree。

原因：spanning 要求覆盖全部 vertex 且连通；disconnected input 不存在 spanning tree。

修复：明确 API 返回 minimum spanning forest，或拒绝 disconnected input；同时检查 edge 数、连通性和 component 数。

</Callout>

<Callout type="trap" title="陷阱：weight 相等时只允许一个答案">

现象：测试把某一棵 MST 当作唯一正确数组，换了 tie order 就判错。

原因：equal weights 可能产生多棵总 weight 相同的 MST；唯一的是最优值，不一定是 edge witness。

修复：固定 deterministic tie policy 以便复现，或验证无环、连通、总 weight 与 safe-choice 证据，而不是比较单一排列。

</Callout>

## minimum spanning trees / 最小生成树

### 图的合同和目标

<Term def="覆盖同一无向连通图全部 vertex、边数为 V−1 且总 weight 最小的 spanning tree">最小生成树</Term>（MST）针对 undirected、connected、weighted graph。任意 spanning tree 都有 `|V|−1` 条 edges，目标函数是树中 edge weight 的总和，而不是从某个 source 出发的路径和。

$$
|T|=|V|-1,
\qquad
w(T)=\sum_{e\in T}w(e).
$$

这个式子在说：MST 同时受结构约束和权重目标约束；连通但含 cycle 的 edge set 不是 tree。

negative weights 没问题，因为安全性只依赖 weight 的相对顺序。equal weights 可以有多个 MST；实现需要明确 tie policy 和多重 edge 的 identity。

### growing a minimum spanning tree / 生成最小生成树

维护 edge set `A`，并保持 <Term def="存在某一棵 MST 包含当前已选 edge set 的不变量">可延展森林</Term> 不变量：存在一棵 MST `T` 使 `A` 是 `T` 的子集。初始 `A` 为空时显然成立；每次加入 safe edge 后，不变量继续成立。

```text
GENERIC-MST(G, w)
1  A = empty set
2  while A does not form a spanning tree
3      find an edge (u,v) that is safe for A
4      A = A union {(u,v)}
5  return A
```

### cut 与 crossing edge

把 vertex 集合分成 `(S, V−S)` 就得到一个 cut。若当前 `A` 没有 edge crossing 这个 cut，就说 cut respects `A`。所有从 `S` 到 `V−S` 的 edges 构成 crossing edges，其中 weight 最小者是 light edge。

<Term def="把 vertex 分成两侧且不切断当前 forest 的边界；它用于授权一条 crossing edge">割</Term>的关键性质是：如果 cut respects `A`，那么该 cut 的任意 light crossing edge 都是 safe，可以加入某一棵仍然包含 `A` 的 MST。

证明用 exchange argument：若 light edge `(u,v)` 不在某棵包含 `A` 的 MST `T` 中，把它加入 `T` 会产生唯一 cycle；cycle 中还有另一条 crossing edge `(x,y)`。由于 `(u,v)` 是 light edge，`w(u,v)` 不大于 `w(x,y)`；移除 `(x,y)` 得到 weight 不增的新 spanning tree `T'`，因此 `T'` 仍是 MST，并包含 `A` 加上这条 safe edge。

<Term def="在某个 respecting cut 的 crossing edges 中 weight 最小的边；cut property 证明它可以安全加入">安全边</Term>不是“全局最便宜”的同义词，而是拥有 cut 证书的 light edge。Kruskal 和 Prim 的差别在于它们每一步维护的 cut 不同。

## Kruskal 与 Prim

### Kruskal

<Term def="按 weight 扫描 edges，并用并查集跳过成环边的最小生成树算法">Kruskal</Term> 让 `A` 始终保持 forest。把 edges 按 weight 排序，依次检查当前 edge 的两个 endpoints 是否属于不同 component；不同就加入并 union，相同就跳过。

```cpp
vector<Edge> kruskal(Graph g) {
    DisjointSet sets(g.vertices);
    sort(g.edges.begin(), g.edges.end(), by_weight_then_id);
    vector<Edge> tree;
    for (const Edge& edge : g.edges) {
        if (sets.find(edge.u) != sets.find(edge.v)) {
            tree.push_back(edge);
            sets.unite(edge.u, edge.v);
        }
    }
    return tree;
}
```

每个 component 都可以看作一个正在被维护的区域；跨 component 的当前最轻 edge 对应某个 respecting cut，所以是 safe。排序成本为 `O(E log E)`，DSU 操作总成本近似为 `O(E α(V))`，整体通常由排序主导。

### Prim

Prim 从一个 root 开始维护一棵 tree。此时 cut 固定为当前 tree vertices `S` 与外部 `V−S`；对每个外部 vertex `v`，`key[v]` 是已知连接 `v` 与 `S` 的最轻 crossing edge weight，`parent[v]` 保存对应端点。

<Term def="Prim 用来表示某个外部 vertex 连接当前 tree 的最轻 crossing edge weight">frontier key</Term>每轮从优先队列取最小 key 的 vertex，并把对应 parent edge 加入 tree；扫描新 vertex 的邻接边后更新仍在 frontier 中的 keys。

```text
MST-PRIM(G, w, r)
1  for each vertex u: key[u] = infinity, parent[u] = NIL
2  key[r] = 0; put all vertices in min-priority queue Q
3  while Q is not empty
4      u = EXTRACT-MIN(Q)
5      for each v adjacent to u
6          if v is in Q and w(u,v) < key[v]
7              parent[v] = u
8              DECREASE-KEY(Q, v, w(u,v))
```

`key` 不是 root 到 vertex 的 shortest path distance；它只记录一条 crossing edge 的 weight。binary heap 加 adjacency list 的典型成本为 `O(E log V)`；dense graph 配 matrix 和简单数组可以达到 `O(V²)`。

### minimum spanning trees 的终态证书

当 `A` 有 `V−1` 条 edges、无 cycle 且覆盖全部 vertices 时，`A` 是 spanning tree；若每条加入的 edge 都有 safe-choice 证书，它就是 MST。生产验证还需要检查 edge identity、integer overflow、floating-point tie policy 与输入是否 disconnected。

$$
A\text{ acyclic and }|A|=|V|-1
\Longrightarrow A\text{ is a spanning tree}.
$$

这个式子在说：无环和边数给出 tree 结构，但 minimum 仍需要每次选择的 cut 或等价 exchange 证据。

## 小结

- minimum spanning trees 要求无向连通图上的 spanning tree 具有最小总 weight。
- growing a minimum spanning tree 维护可延展森林，并用 cut property 证明 safe edge。
- Kruskal 按全局 weight 顺序扫描，用 DSU 跳过同 component 的 cycle edge。
- Prim 维护当前 tree 与外部的 frontier key，选择该 cut 的 light edge。
- negative 或 equal weights 不会破坏理论；disconnected graph 只能返回 forest 或显式报错。

   <Answer>

   weight 为 2 的 edge 是该 cut 的 light crossing edge，cut property 保证它 safe：存在一棵包含 `A` 加上它的 MST。两条 weight 为 5 的 edge 都可能是 safe，结论不要求 witness 唯一；deterministic tie policy 只负责让实现可复现。
