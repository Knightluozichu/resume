## 先问：matching 都叫匹配，最优到底指什么？

给定同一张二分图，至少有三种不同任务：尽量多配对的 maximum cardinality matching；不允许一对双方都想离开的 stable marriage；以及在完美匹配中最大化总 weight 的 assignment。它们共享“不重复 endpoint”的结构，却不能共享同一份最优性证书。

先预测：如果当前匹配不够大，应寻找哪一条 alternating path？如果两个人都想离开当前 partner，稳定性如何被破坏？如果每条边都有 weight，为什么一组 locally tight 的边还不能直接称为最优？

## 常见误区与故障注入

<Callout type="trap" title="陷阱：找到一条 alternating path 就直接 flip，不检查它是否 augmenting">

现象：翻转路径上的 matched/unmatched edges 后，匹配边数没有增加，或两个边共享 endpoint。

原因：只有从 free left 到 free right、且 edges 严格交替的 path 才是 augmenting path；任意 alternating walk 不具备增长结论。

修复：验证路径两端均 free、内部 edge 顺序交替且 path vertex-disjoint；再用 symmetric difference 更新 matching。

</Callout>

<Callout type="trap" title="陷阱：把 stable matching 当作最大 total rank 的 matching">

现象：为了提高所有人的偏好分数，交换一对 pair，却没有检查是否产生一对共同更喜欢彼此的参与者。

原因：stable-marriage 的目标是没有 blocking pair，不是最大化 cardinality 或所有 rank 的总和。

修复：对每个不在 matching 中的 pair 检查双方是否都偏好对方胜过当前 partner；发现一对即可证明不稳定。

</Callout>

<Callout type="trap" title="陷阱：Hungarian 中 label 可行就等于已经得到最优 assignment">

现象：只打印满足 label inequality 的数字，就宣布 assignment optimal，却没有 perfect matching。

原因：feasible labels 只给 dual upper bound；只有 equality graph 中的 perfect matching 才能让 primal weight 与 label sum 同时 tight。

修复：先检查每条 label constraint，再检查 equality graph 的 perfect matching；两者缺一不可。

</Callout>

<Callout type="trap" title="陷阱：Hopcroft-Karp phase 中并行翻转共享 vertex 的路径">

现象：一轮 DFS 找到多条 shortest augmenting path，却同时修改了同一个 matched vertex 的两侧。

原因：同时 flip 只有在路径 vertex-disjoint 时才保持每个 endpoint 最多一条 matched edge。

修复：DFS 成功后立即占用 path vertices，标记本 phase 的 dead vertex，下一条路径跳过已占用节点。

</Callout>

## matchings in bipartite graphs / 二分图匹配

### Endpoint 合同与三个目标

<Term def="在二分图中选择一组互不共享 endpoint 的 edges 的结构">匹配</Term>是二分图 `G=(L∪R,E)` 的 edge 子集，其中每个 vertex 至多属于一条选中 edge。先声明目标：maximum cardinality 最大化 `|M|`；stable marriage 要求没有 blocking pair；assignment problem 则在通常的完美 matching 中最大化或最小化 total weight。

相同的 endpoint 合同不意味着相同的 API。maximum matching 可以返回任意一个最大 edge set；stable matching 必须返回 preference-aware pair set；assignment 必须返回 pair set 与 total weight。验证器不能把一组 stable pairs 当作 maximum 的证明，也不能把 maximum cardinality 当作 weighted optimum。

## maximum bipartite matching revisited / 重新审视最大二分匹配

### Symmetric difference 与增广

<Term def="沿 unmatched edge 与 matched edge 交替行走、并用来寻找增长匹配的路径结构">交替路</Term>在 `M` 的边与不在 `M` 的边之间交替。若它从一个 free vertex 开始并在另一个 free vertex 结束，就得到 <Term def="两端是 free vertex、flip 后使 matching cardinality 增加一的交替路">增广路</Term>。沿路径取 symmetric difference：

$$
M' = M \triangle E(P),
\qquad |M'|=|M|+1.
$$

Berge theorem 给出 maximum 证书：`M` 是 maximum matching，当且仅当不存在 `M`-augmenting path。向前方向显然，因为一条增广路可以让匹配多一条边；反向方向考虑 `M` 与更大匹配 `M*` 的 symmetric difference。其连通分量只能是 alternating cycles 或 alternating paths，其中必有一条 path 含有比 `M` 更多的 `M*` edges，正是 augmenting path。

朴素做法每次 DFS 找一条 path，最多增广 `O(V)` 次，每轮扫描 `O(E)`，得到 `O(VE)`。代码必须在发现路径后按边身份 flip，而不是重新构造一个可能重复 endpoint 的边集合。

### Hopcroft-Karp phases

Hopcroft-Karp 从所有 free left vertices 同时 BFS。沿 unmatched edge 从 left 走向 right，沿 matched edge 从 right 回到 left；首次到达 free right 的 layer 决定当前最短增广长度。随后 DFS 只在这张 layer graph 中寻找 vertex-disjoint shortest augmenting paths，并在一个 phase 内一起 flip：

```text
HOPCROFT-KARP(G)
1  M = empty matching
2  while BFS builds layers reaching a free right vertex
3      for each free left vertex u
4          DFS within layers for a vertex-disjoint shortest augmenting path
5      augment M along every path found in this phase
6  return M
```

每个 phase 的 BFS 与全部 DFS 总计 `O(E)`；shortest augmenting length 在 phase 之间严格增加。将短路径 phase 数和剩余长路径数量结合，可得 `O(E√V)` 时间。失败的 DFS 应把本 phase 无法继续的 vertex 标记为 dead，避免重复扫描。

## stable-marriage problem / 稳定婚姻问题

### Preferences 与 blocking pair

<Term def="在 preference matching 中，一对未配对参与者都严格偏好彼此胜过当前 partner 的不稳定证据">阻塞对</Term> `(m,w)` 满足：`m` 偏好 `w` 胜过当前 partner，且 `w` 偏好 `m` 胜过当前 partner。<Term def="不存在 blocking pair 的 preference matching 性质">稳定匹配</Term>的目标是没有这样的 pair，而不是最大化总 rank。输入的完整 strict preference lists、ties、incomplete lists 与 capacities 必须分别声明；ties 会改变 stability 定义。

### Deferred acceptance

Gale-Shapley 的 proposer-oriented 版本让 free proposer 向尚未 proposal 的最高偏好 receiver 申请。receiver 在当前 hold 与新 proposal 中暂存自己更喜欢的一个，拒绝另一个；hold 不是 final，直到所有 proposer 都完成。

```text
DEFERRED-ACCEPTANCE
1  while some proposer m is free and has an untried receiver
2      w = highest-ranked receiver not yet proposed to by m
3      if w is free, w tentatively holds m
4      else if w prefers m to current m'
5          w rejects m' and holds m
6      else w rejects m
7  return held pairs
```

每个 ordered pair 最多 proposal 一次，时间为 `O(n²)`。receiver 的 held partner 只会变好，proposer 被拒绝后只会向偏好更低的 receiver 申请，因此算法终止。稳定性证明采用反证：若最终存在 blocking pair `(m,w)`，则 `m` 在得到 final partner 前曾向更喜欢的 `w` proposal；`w` 当时拒绝了 `m` 或后来换成更喜欢的人，所以不可能最终更偏好 `m`。

proposer-oriented 结果对 proposer 最优、对 receiver 最差；交换 proposal side 会选择 stable matching lattice 的另一端。这再次说明 stable matching 的“最优”必须带上角色与 preference 合同。

## Hungarian algorithm / 匈牙利算法

### assignment problem / 指派问题

给定 `n×n` weight matrix，assignment problem 要求选一个 perfect matching `M`，最大化：

$$
\max_{M\text{ perfect}}\sum_{(x,y)\in M}w(x,y).
$$

### Feasible labels 与 equality graph

<Term def="满足每条 edge 上 label 总和不低于 weight、从而提供 assignment dual upper bound 的顶点标记">可行标记</Term> `l` 满足：

$$
l(x)+l(y)\ge w(x,y)\quad\text{for every }(x,y)\in E.
$$

由 label 约束得到 equality graph `E_l`，它只包含 tight edges：

$$
E_l=\{(x,y):l(x)+l(y)=w(x,y)\}.
$$

对任意 perfect matching `M`，都有 `w(M) ≤ Σ_v l(v)`。如果 equality graph 中存在 perfect matching，则每条 matched edge 都 tight，matching weight 恰等于 label sum 的 upper bound，因此同时达到 primal optimum 与 dual bound。

### Slack 更新

若 equality graph 中的当前 matching 不是 perfect，从 free left root 建立 alternating tree；设已到达的 left 集合为 `S`，right 集合为 `T`，计算：

$$
\delta=\min_{x\in S,y\notin T}\{l(x)+l(y)-w(x,y)\}.
$$

将 `S` 的 labels 减 `δ`、`T` 的 labels 加 `δ`，其余不变。已有 equality edges 保持 tight，所有 label constraints 仍可行，至少一条 `S` 到 `Y−T` 的 edge 变成 tight，equality graph 因而扩展。重复 augment 或 label update，直到获得 perfect tight matching。稠密矩阵实现为 `O(n³)`；min-cost 版本可以 negate weights 或使用 dual potentials，但 inequality direction 与 overflow 处理必须保持一致。

```text
HUNGARIAN-MAX-WEIGHT
1  initialize feasible labels and an equality-graph matching
2  while matching is not perfect
3      grow an alternating tree in the equality graph
4      if a free right vertex is reached, augment
5      else compute minimum slack delta
6          decrease labels on S; increase labels on T
7          continue with newly tight edges
8  return perfect equality matching and labels
```

## 小结

- matchings in bipartite graphs / 二分图匹配共享 endpoint 不重复结构，但目标必须先声明。
- maximum bipartite matching revisited / 重新审视最大二分匹配用 Berge theorem 和 Hopcroft-Karp 的无增广路证书。
- stable-marriage problem / 稳定婚姻问题用 deferred acceptance 产生无 blocking pair 的稳定匹配。
- Hungarian algorithm / 匈牙利算法维护 feasible labels、equality graph 和 slack，求解加权完美匹配。
- assignment problem / 指派问题的最优性需要 perfect tight matching 与 label upper bound 同时成立。
