## 从“最优值必须带证明”开始

先预测：一个solver返回profit 10，并不自动说明10最优。你至少要确认这个point满足所有resource constraints；更强的做法是再给一个任何可行方案都不可能超过10的upper bound。Primal solution负责“做得到”，dual solution负责“不会更好”，两者相遇才关闭证明。

<Term def="在线性equalities或inequalities及variable domains下优化linear objective的连续优化问题。">线性规划</Term>（linear programming，LP）把decision variables组成vector $x$，把constraints组成matrix $A$与vector $b$，把objective coefficients组成$c$。一种常用maximization form为

$$
\max\ c^Tx
\quad\text{subject to}\quad
Ax\le b,\qquad x\ge0.
$$

<CLRS4FeasibleRegionLab />

这里的“linear”同时约束objective和constraints：变量不能相乘，不能取平方，也不能由if语句改变coefficient。绝对值、min/max和piecewise cost有时可引入auxiliary variables线性化，但每次转换都要证明新formulation与原问题等价或明确它只是relaxation。

## 29.1 Linear programming formulations and algorithms

### Feasible region与status

<Term def="满足全部linear constraints与variable domains的points集合；它是convex polyhedron，可能为空或无界。">可行域</Term>是half-spaces、hyperplanes和domain bounds的交。Linear objective的level sets是parallel hyperplanes；沿objective direction平移，最后接触bounded feasible polyhedron的位置给optimum。

<CLRS4LPStatusLab />

LP有三类必须区分的outcomes：

- feasible且bounded：存在finite optimum，可能有一个point或整个optimal face；
- infeasible：没有point同时满足所有constraints；
- unbounded：存在feasible improving ray，使objective无限改善。

Solver的“失败”不能笼统处理。Infeasibility certificate、unbounded ray与numerical failure含义完全不同，调用方应保存status而不是只读objective field。

### Standard form与slack

<Term def="把线性规划用统一objective direction、constraint direction和variable sign conventions表示，便于算法与对偶推导。">标准形式</Term>不是唯一排版。Equality可拆成两条inequalities；greater-than可乘负一；free variable可写成两个nonnegative variables之差；upper-bound inequality可引入nonnegative slack：

$$
a_i^Tx\le b_i
\quad\Longleftrightarrow\quad
a_i^Tx+s_i=b_i,\qquad s_i\ge0.
$$

<CLRS4SlackFormLab />

Slack $s_i=0$说明constraint tight或active；positive slack说明resource尚未用尽。Tight不等于dual price必positive，但complementary slackness会说明positive price只能出现在tight constraint上。

```ts
type LinearProgram = {
  objective: number[];
  sense: "max" | "min";
  rows: Array<{ coefficients: number[]; relation: "<=" | "=" | ">="; rhs: number }>;
  lowerBounds: number[];
  upperBounds: Array<number | null>;
};
```

Structured representation比拼接solver text可靠：dimensions可检查，variables有stable ids，domain bounds不会因formatting遗漏，solution也能按ids映射回业务对象。

### Vertices, bases, and simplex

在nondegenerate geometric intuition中，足够多linearly independent constraints同时tight会确定一个vertex；algebraically，对standard-form equalities选择一组basic variables并令nonbasic variables为0，解得basic solution。若它满足nonnegativity，就是<Term def="由一组basis constraints或basic variables确定并同时满足全部constraints的vertex-like feasible solution。">基本可行解</Term>。

<CLRS4SimplexWalkLab />

Simplex从一个basic feasible solution出发，选择entering variable与leaving variable做pivot，移动到相邻basis并改善objective，直到reduced costs证明没有improving adjacent direction。Degeneracy可能让pivot后objective不变，bad pivot rules甚至cycle，因此实现需要deterministic anti-cycling policy与tolerances。

```text
SIMPLEX-SKELETON(slack_form)
1  construct an initial basic feasible solution or run a feasibility phase
2  choose an entering nonbasic variable with improving reduced cost
3  use the ratio test to choose a leaving basic variable
4  pivot the equations and update the basis
5  repeat until no improving reduced cost remains
```

Simplex在实践中极其重要，但存在exponential worst-case examples。Ellipsoid method首先给出LP polynomial-time solvability的理论里程碑；interior-point families沿feasible region内部路径推进，也拥有polynomial guarantees并适合large sparse systems。

<CLRS4LPAlgorithmLab />

“Polynomial time”还依赖input coefficients的bit length，不能只按variables和constraints数量计数。Floating-point solver还会使用presolve、scaling、sparse factorization和termination tolerance；理论exact optimum与reported approximate solution之间要用feasibility residual和duality gap连接。

<Callout type="trap" title="Simplex常常很快，所以它有polynomial worst-case">
Empirical performance与worst-case complexity是不同命题。Simplex有很强实践表现却存在指数级pivot paths；ellipsoid与interior-point提供polynomial理论路径。修法是分别报告algorithm family、theoretical guarantee和workload benchmark。
</Callout>

## 29.2 Formulating problems as linear programs

### 五步建模

<Term def="把domain decisions逐一映射成variables、linear constraints、objective与domains，并证明solver solution可映射回原问题。">线性规划建模</Term>从语义开始，不从matrix开始：

1. 每个variable代表哪个可控decision，单位是什么；
2. 每条constraint对应哪个law、resource或balance；
3. objective究竟max profit、min cost还是min worst violation；
4. variable是continuous、nonnegative、bounded还是本应integer；
5. solution如何round、deploy并验证原domain invariants。

<CLRS4ModelingPipelineLab />

### Resource allocation

生产问题令$x_j$表示product $j$的数量，$a_{ij}$表示一unit product消耗resource $i$，$b_i$为resource budget，$c_j$为unit contribution：

$$
\max\sum_j c_jx_j
\quad\text{subject to}\quad
\sum_j a_{ij}x_j\le b_i\ \text{for every resource }i,
\qquad x_j\ge0.
$$

<CLRS4ProductionLPModelLab />

若$x_j$必须是whole machines或yes/no choices，continuous LP会允许不可部署的fractional result。此时原问题是integer linear program；去掉integrality得到LP relaxation，可提供bound，但不是自动可行解。

### Network formulations

Flow LP为每条directed edge $(u,v)$建variable $f_{uv}$，加入capacity bounds与每个internal vertex的flow conservation，objective maximizes source outflow。它与Chapter 24 combinatorial max-flow算法描述同一optimization problem，却提供了统一建模语言和duality视角。

```text
variables: f[u,v] for every directed edge
constraints:
    0 <= f[u,v] <= capacity[u,v]
    sum incoming flow = sum outgoing flow for every internal vertex
objective:
    maximize total flow leaving source
```

<CLRS4FlowLPModelLab />

Shortest path也能写成unit-flow min-cost LP：从source发送一unit flow到target，objective求edge costs加权和。LP formulation有助于组合额外linear constraints，但specialized graph algorithm通常更直接、更快，并给出更强integral structure。能写成LP不等于必须调用general solver。

### Relaxation and rounding

<Term def="放宽integrality或其他hard constraints得到更大可行域的连续LP，用其optimum为原离散问题提供bound。">LP松弛</Term>对maximization给upper bound，对minimization给lower bound。它可用于branch-and-bound、approximation rounding和integrality-gap分析。

<CLRS4RelaxationLab />

Rounding必须重新检查原constraints。把每个fractional variable独立四舍五入，可能同时超出许多resources；正确算法需要问题特定的rounding、alteration或primal-dual construction。Relaxation quality用integrality gap衡量，不能只看solver返回得快。

<Callout type="trap" title="把fractional optimum直接当作业务方案">
LP relaxation的point只保证满足relaxed domains。若原变量必须binary或integer，它通常不可部署。修法是保留integrality语义，报告relaxation bound，并使用有可行性与approximation证明的rounding或整数求解。
</Callout>

## 29.3 Duality

### Constructing the dual

对primal

$$
\max\ c^Tx
\quad\text{subject to}\quad
Ax\le b,\qquad x\ge0,
$$

对应dual为

$$
\min\ b^Ty
\quad\text{subject to}\quad
A^Ty\ge c,\qquad y\ge0.
$$

每个primal constraint产生一个dual variable，可解释为resource shadow price；每个primal variable产生一个dual constraint，要求resources的priced cost覆盖该decision的unit contribution。

<CLRS4PrimalDualLab />

### Weak and strong duality

<Term def="把primal constraints按nonnegative dual variables加权，得到对所有primal-feasible solutions都成立的objective bound。">对偶性</Term>首先给weak duality。若$x,y$分别primal/dual feasible，则

$$
c^Tx\le x^TA^Ty=y^TAx\le y^Tb.
$$

所以任何dual-feasible $y$都是primal maximization的upper-bound certificate。

<CLRS4WeakDualityLab />

Strong duality说明，当primal与dual有finite optima时，optimal values相等：

$$
c^Tx^*=b^Ty^*.
$$

这把optimization转成verification：找到primal feasible $x$和dual feasible $y$且objective相等，就无需枚举所有primal points，也能证明二者optimal。Approximate solver使用duality gap $b^Ty-c^Tx$和scaled feasibility violations作为stopping evidence。

### Complementary slackness

Primal constraint slack为$b-Ax$，dual constraint slack为$A^Ty-c$。对feasible $x,y$，optimality等价于每对nonnegative terms不同时positive：

$$
y_i\bigl(b_i-(Ax)_i\bigr)=0,
\qquad
x_j\bigl((A^Ty)_j-c_j\bigr)=0.
$$

<CLRS4ComplementarySlacknessLab />

解释是：resource有positive price时必须fully used；decision variable为positive时，它的priced resource cost必须恰好等于unit contribution。Complementary slackness既是optimality test，也是从dual结构猜primal support、从primal active set猜dual support的算法设计线索。

Dual of dual回到primal。Equality constraints、free variables和不同inequality directions会改变dual variable signs或dual constraint types；最稳妥的方法是先转换到一个明确canonical form，或使用一张逐项对应表，而不是凭记忆翻符号。

## LP交付证书

一份可复查结果至少包含variable dictionary、objective sense、每条constraint与domain source、solver status、primal solution和violations。若声称optimal，再给dual solution、dual violations、objective gap与tolerance；若是relaxation，还要给原integral problem的feasible rounded solution和gap。

## 小结

Chapter 29 Linear Programming先建立linear programming formulations and algorithms：可行域是convex polyhedron，slack form暴露active constraints，basic feasible solutions连接vertices与simplex pivots，ellipsoid和interior-point补齐polynomial-time视角。Formulating problems as linear programs要求从domain语义到variables、constraints、objective和domains逐项可追踪，并区分exact LP与integer relaxation。

Duality为每个primal方案提供bound。Weak duality保证primal value不超过dual value，strong duality让optimal values相遇，complementary slackness解释哪些resources与decisions必须tight。最终交付物不是“solver说最优”，而是primal feasibility、dual feasibility、zero或small gap以及可部署domain interpretation组成的certificate。

<Exercises>

**问题 1**：对constraint $x_1+x_2\le4$，candidate $(1,2)$与$(2,2)$的slack分别是多少？

<Answer>
Slack定义为right-hand side减left-hand side。对(1,2)为4-3=1，constraint不tight；对(2,2)为4-4=0，constraint tight。
</Answer>

**问题 2**：为何任意dual-feasible $y$都给primal maximization一个upper bound？

<Answer>
Primal feasibility给Ax不超过b，乘nonnegative y得到yᵀAx不超过yᵀb；dual feasibility给Aᵀy至少为c，乘nonnegative x得到cᵀx不超过xᵀAᵀy。连接两式便有cᵀx不超过bᵀy。
</Answer>

**问题 3**：Primal feasible value为18，dual feasible value为20，能证明什么，不能证明什么？

<Answer>
可以证明primal optimum位于18到20之间，当前absolute duality gap为2。不能单独证明任一candidate optimal；只有gap为0，或在明确tolerance下足够小并满足两侧feasibility时，才构成相应最优或近似最优证书。
</Answer>

**问题 4**：为什么binary problem的LP relaxation optimum可能比所有integer solutions更好？

<Answer>
Relaxation把每个binary domain扩大为连续interval，原integer feasible points仍在其中，但新增了fractional points。Maximization在更大集合上的optimum不会更小，因此它是upper bound；新增point却可能不对应任何合法integer decision。
</Answer>

</Exercises>
