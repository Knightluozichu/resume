## 为什么匹配时要记住刚才比较过什么

在一段文本里找短词，最直接的做法是把词贴到每个可能的位置逐字符比较。问题出现在“前面一长段都对，最后才错”：下一次移动时，刚才确认过的字符并没有消失；如果全部重比，就白白丢掉信息。算法设计的关键不是神奇地跳过字符，而是证明哪些候选位置不可能，或把可复用的部分保存下来。

先预测：文本是 `ababcababac`，模式是 `ababac`。从位置 0 开始时，前五个字符相等，第六个失配。下一次可能的起点是每个位置吗？哪些已经比较过的前缀/后缀能帮助我们？先在下面的实验中看真实轨迹，再读各方法的保证。

## 问题合同：什么叫一次匹配

令文本为 $T[0..n)$，模式为 $P[0..m)$。合法起点只有 $0$ 到 $n-m$；若

$$
T[s..s+m)=P[0..m),
$$

则 $s$ 是一个出现位置。本文讨论报告**所有**出现位置，因此允许重叠：`aaaaaa` 中模式 `aaaa` 出现在 0、1、2。算法返回的是索引；实际 API 还必须说明索引按字节、Unicode 码点还是用户感知字符计数，并统一大小写折叠与规范化规则。若预处理和扫描采用不同的字符表示，即使算法推导正确，位置也可能错误。

空模式的结果取决于接口约定（例如每个边界都算一次或只算一次），实现应显式处理，不能把它交给下面要求 $m>0$ 的循环。模式长于文本时没有合法窗口，应立即返回空结果。

## 32.1 朴素法：逐个检查对齐

朴素算法依次枚举起点 $s$，从模式首字符开始比较；一旦失配，就尝试 $s+1$。它不需要预处理，容易实现，也是验证优化版本的小输入参照：

```text
NAIVE-MATCH(T, P)
  for s = 0 .. n-m:
    j = 0
    while j < m and T[s+j] = P[j]:
      j = j + 1
    if j = m: report s
```

最坏情况下，每个窗口都先匹配很长的前缀才失败。例如文本全是 `a`，模式是许多 `a` 后接 `b`。窗口数为 $n-m+1$，每个最多比较 $m$ 个字符，时间为 $O((n-m+1)m)$，空间（不计输出）为 $O(1)$。这不是“永远慢”：一次性查找、小模式或已有高度优化的库函数，可能更适合直接扫描而不是支付预处理成本。

**不要把报告命中当作可以跳过整个模式。**若下一起点增加 $m$，就会漏掉重叠结果；本章所有算法的报告语义都是继续寻找下一个允许重叠的出现。

## 32.2 Rabin–Karp：先比较指纹，再核对字符

<Term def="用多项式滚动指纹筛选文本窗口，并逐字符核验哈希相等候选的精确匹配算法。">
  Rabin–Karp
</Term>
将长度为 $m$ 的窗口当作以基数 $d$ 表示的数，并对大素数 $q$
取模。模式与当前窗口的哈希不等，就能确定二者不同；哈希相等则只说明“值得核验”，因为不同字符串可能发生碰撞（spurious
hit）。逐字符复核后，结果仍然精确。

记 $h=d^{m-1}\bmod q$。相邻窗口只差一个离开字符和一个进入字符，因此无需从头算哈希：

$$
t_{s+1}=\bigl(d(t_s-T[s]h)+T[s+m]\bigr)\bmod q.
$$

可以把这一步想成数字窗口左移一位：去掉最高位、整体乘基数，再加新末位。实现时需把负余数规范到 $0..q-1$，并让字符到数字的映射与哈希参数一致。

用一个故意很小的参数看清“指纹不等即可排除、相等仍要核验”：令字符映射为 $a\mapsto0,b\mapsto1,c\mapsto2$，基数 $d=3$、模数 $q=5$，在文本 `aabc` 中查找 `bc`。模式指纹为 $(1\cdot3+2)\bmod5=0$；第一个窗口 `aa` 的指纹也是 0，但字符不相等，所以它只是伪命中。窗口从 `aa` 滚到 `ab` 时，$h=3$，新指纹为 $[3(0-0\cdot3)+1]\bmod5=1$；再滚到 `bc` 得 $[3(1-0\cdot3)+2]\bmod5=0$，此时逐字符核验才确认起点 2。这个小模数专为展示碰撞，不能据此推断实际参数的碰撞率；精确性来自候选核验。

若出现 $r$ 次指纹相等，逐个核验最多额外花 $O(rm)$；滚动扫描本身为 $O(n)$。因此最坏情况仍可达 $O(nm)$，期望表现取决于基数/模数选择、输入分布与随机化假设，不能把“哈希相等”误当作证明。该方法在同时搜索多个等长模式时尤其有用：文本窗口的滚动指纹可以共享，再按模式指纹分组核验。

## 32.3 有限自动机：把已读前缀压成状态

对固定模式 $P$，<Term def="把模式匹配进度编码成状态，并按输入字符转移的预计算状态机。">有限自动机</Term> 的状态 $q\in\{0,\ldots,m\}$ 表示：到目前为止读过的文本中，**最长的、同时也是模式前缀的后缀**长度是 $q$。读入字符 $a$ 后，状态转移为

$$
\delta(q,a)=\max\{k: P[0..k)\text{ 是 }P[0..q)a\text{ 的后缀}
\}.
$$

状态的含义是不变量：它只保留继续匹配所需的信息。预先建好转移表后，每个文本字符只需一次查表，扫描耗时 $O(n)$；代价是转移表可能需要 $O(m|\Sigma|)$ 空间，且构造表本身并非免费。字母表很大或模式只用一次时，密集表可能不划算。

到达状态 $m$ 就报告以当前字符结尾的匹配。之后的转移仍须保留模式的边界（同时为前缀和后缀的部分），才能接住重叠命中；直接回到 0 并不总正确。

## 32.4 <Term def="Knuth–Morris–Pratt 的缩写；借助模式前缀函数在线性时间内完成精确匹配。">KMP</Term>：沿边界链回退，不让文本倒退

<Term def="一个串同时作为某个串的真前缀和后缀时，它就是这个串的边界。">
  边界
</Term>
给出失配后仍可能成立的候选。对模式前缀 $P[0..q]$，
<Term def="pi[q] 是 P[0..q] 的最长真前缀、同时也是后缀的长度。">
  前缀函数 $\pi[q]$
</Term>
记录最长边界长度。若已有 $q$ 个字符匹配、下一字符失配，原来的 $q$
个字符不必重读：最长边界之后的候选由 $\pi[q-1]$ 给出，再沿同一链继续回退。

以模式 `ababaca` 为例，前缀函数是 `[0, 0, 1, 2, 3, 0, 1]`。其中 `ababa` 的最长真前后缀是 `aba`，长度 3。若它之后失配，KMP 保留这 3 个字符代表的匹配状态，而不是把文本指针退回去重新比较。

```text
COMPUTE-PI(P)
  pi[0] = 0; k = 0
  for q = 1 .. m-1:
    while k > 0 and P[k] != P[q]: k = pi[k-1]
    if P[k] = P[q]: k = k + 1
    pi[q] = k

KMP(T, P, pi)
  q = 0
  for i = 0 .. n-1:
    while q > 0 and P[q] != T[i]: q = pi[q-1]
    if P[q] = T[i]: q = q + 1
    if q = m:
      report i-m+1
      q = pi[m-1]
```

前缀函数预处理耗时 $O(m)$，扫描耗时 $O(n)$，总时间 $O(n+m)$，额外空间 $O(m)$。内层 `while` 虽然嵌套，但每读入一个文本字符，状态至多增加一次；每次回退都让状态严格变小，因此整个过程中增加与回退的总次数都是线性的。

命中后令 $q=\pi[m-1]$，保留模式的最长边界。这既让文本指针继续前进，也让下一次扫描接续可能重叠的匹配。实验里的“命中后清零”是有意注入的错误：它可能看似正常，却会在 `aaaaaa` / `aaaa` 上漏报位置 1 和 2。

## 32.5 如何选择：复用的是模式，还是文本

| 使用情形                           | 合适的起点 | 需要记住的成本                               |
| ---------------------------------- | ---------- | -------------------------------------------- |
| 一次性、小输入                     | 朴素法     | 无预处理，最坏可能重复比较大量字符           |
| 一个模式扫描一个或多个文本         | KMP        | $O(m)$ 模式预处理，扫描 $O(n)$，确定性线性界 |
| 多个等长模式扫描同一文本           | Rabin–Karp | 共享窗口哈希；候选仍须验证，最坏可退化       |
| 模式固定、反复扫描文本且字母表可控 | 有限自动机 | 扫描快，但转移表空间/预处理可能大            |
| 文本固定、反复查询许多模式         | 后缀数组   | 预处理文本索引；单次查询需二分比较并报告结果 |

本章以朴素法、Rabin–Karp、有限自动机和 KMP 为核心的在线匹配器。后缀数组代表相反的复用方向：对固定文本，把所有后缀按字典序排列，形成<Term def="按文本各个后缀的字典序保存其起点的索引结构。">后缀数组</Term>。以模式为前缀的后缀在排序结果中形成连续区间，可通过二分搜索定位；若每次比较最多读 $m$ 个字符，基本查询代价为 $O(m\log n)$，输出 $k$ 个位置还需 $O(k)$。构建后缀数组与 LCP 等增强结构属于索引成本，适合多次查询摊销，不应和单次扫描混为一谈。

## 容易踩的坑

<Callout type="trap" title="把指纹相等当成匹配">

现象：Rabin–Karp 一发现哈希相等就返回位置。原因：哈希是压缩表示，不同窗口可能映到同一余数。修法：每个候选都逐字符核验；碰撞只能增加工作，不能改变精确答案。

</Callout>

<Callout type="trap" title="KMP 失配时移动了文本指针">

现象：失配后回退 `i`，甚至重新扫描刚读过的文本。原因：把朴素法的对齐循环照搬到 KMP。修法：文本指针只向前；按 `pi[q-1]` 缩短模式状态，直到可继续或回到 0。

</Callout>

<Callout type="trap" title="命中后清零，丢掉重叠结果">

现象：在 `aaaaaa` 中搜索 `aaaa` 只报出起点 0。原因：报告命中后丢弃了仍是模式前缀的已读后缀。修法：恢复到 `pi[m-1]`，并用周期性模式测试边界情况。

</Callout>

## 小结

- 匹配先定义索引、空模式和重叠语义，再讨论复杂度。
- 朴素法枚举全部对齐；重复长前缀比较会使最坏时间达到 $O(nm)$。
- Rabin–Karp 用滚动哈希排除窗口，但哈希相等后仍须核验。
- KMP 用前缀函数保留边界；预处理与扫描分别为 $O(m)$、$O(n)$。
- 固定模式与固定文本是不同的复用方向；后缀数组服务重复文本查询。

## 练习

<Exercises>

1. 文本 `aaaaaa`、模式 `aaaa`：列出全部起点。若 KMP 命中后把状态清零，会漏掉哪些结果？

<Answer>
  全部起点为 0、1、2。模式的最长边界长度为 3；命中后清零会漏掉 1、2，恢复到状态
  3 则可继续找到它们。
</Answer>

2. 模式 `ababaca` 的前缀函数为 `[0,0,1,2,3,0,1]`。扫描时已匹配 `ababa`，下一字符与模式中 `c` 不同。KMP 下一候选状态是多少？为什么不必回到 0？

<Answer>
  回到长度 3，因为 `ababa` 的最长真前后缀是
  `aba`。这段后缀已在文本中读过，仍与模式开头一致；文本指针无需后退。
</Answer>

3. 选择一种方法并说明理由：只查一次短模式；同一个模式反复扫描许多文本；同一文本上查询大量模式。

<Answer>
  一次短模式可从朴素扫描开始以免预处理；同一模式反复扫描可预处理
  KMP（若字母表小且模式固定，也可考虑自动机）；固定文本的许多查询可建立后缀索引。若是许多等长模式共享一次文本扫描，可考虑
  Rabin–Karp 指纹筛选并核验候选。
</Answer>

4. 动手题：在实验中选择 `P = aaaa`，先预测关闭故障时的命中数，再打开“命中后清零”。预设文本为 `aaaaaabaaaaaa`；分别写出正确命中起点、故障下命中起点和漏报位置，重置后解释 `pi[m-1]` 保住了什么。

<Answer>
  正确起点为 0、1、2、7、8、9。清零故障下只报告 0 和 7，漏掉
  1、2、8、9：两段连续的 `a` 各有三个长度为 4
  的重叠窗口，但第一次命中后清零会丢掉后缀 `aaa`。对
  `aaaa`，$\pi[m-1]=3$；恢复到 3
  表示末尾三个已读字符仍是模式前缀，下一字符可以继续验证下一个重叠窗口。
</Answer>
