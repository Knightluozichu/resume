## 直觉：查地图与验地图

先预测：给你一张地图，要求找出一条恰好经过每座城市一次、最后回到起点的路线——和你拿着别人画好的一条路线逐段核对，哪件事更费事？两者看似都在解决同一个问题，工作量却可能差出几百倍。

差别不在聪不聪明，而在任务本身：从零找路线，最坏情况下要把所有排法都试一遍；而核对一条路线，只需拿着图一段段问"这两城之间有路吗"。一个负责"找到答案"，一个负责"验证答案"，后者通常便宜得多。

本章研究的就是这条差别能不能被普遍消除：哪些问题的"验证"可以很快完成、它们的"求解"是否也同样快；以及如何证明一个新问题和某个已知难题"一样难"——靠的是一张方向绝对不能画反的箭头图。没有这套语言，面对一个死活做不快的问题，你既说不出它为什么难，也说不出该换什么策略。

## 决策问题：只回答是或否

<Term def="只要求对每个输入回答“是”或“否”的问题；优化问题可通过对目标值设一个阈值，改写成等价的决策版本。">
  决策问题
</Term>
（decision
problem）把讨论收窄到最简单的问答形态：每个输入要么属于这个问题、要么不属于。很多实际问题天然是优化形态——"最短路线多少钱？"——但可以改写："是否存在一条总费用不超过
B
的路线？"若可行解代价是整数、最优值的二进制位数有多项式上界，并且阈值版能在多项式时间判定，就可用二分搜索在多项式次查询内确定最优值；要恢复一份具体最优解，通常还需逐步固定选择并继续调用判定器（自归约）。因此复杂度理论常以决策语言定义
P、NP 与 NP-complete，但“判定最优值”和“输出最优解”仍须区分。

把输入编码成二进制串后，一个决策问题就是一个语言 L：所有"答案为是"的串构成的集合。求解算法读入串 x，输出 x 是否属于 L。这里有一个容易忽略的纪律：复杂度一律按**编码后的长度** n 计量，而不是按输入里某个整数的数值计量。整数 N 的二进制编码只有约 log₂N 位；一个跑 N 步的程序，相对于编码长度是指数级的。第五节实验里的验证器严格按"查表次数"计数，就是在守这条纪律。

## 多项式时间：稳定的可解边界

<Term def="运行步数不超过输入规模某个固定次幂（n^k，k 与输入无关）的算法；这里的输入规模指编码后的二进制长度。">
  多项式时间
</Term>
（polynomial time）是"高效可解"的理论边界。选它不是因为每个多项式算法都快——n¹⁰⁰
并不实用——而是因为它对组合运算稳健：两段多项式程序首尾相接仍是多项式；多项式次调用多项式子程序仍是多项式；常见计算模型互相模拟也只需多项式开销。这个边界在"复合"和"换机器"这两件事上都不容易失真，所以适合做分类的锚点。

与之相对的是 pseudo-polynomial（拟多项式）算法：它按输入中数值的大小跑多项式，却可能按编码长度跑指数。背包问题的经典动态规划以目标值为表宽，就是拟多项式——它不能作为"该问题已落入 P"的证据，除非输入改用一元编码。判断一个算法到底是不是多项式，永远先问"输入规模按位算有多大"。

## 证书与验证器：NP 的工作定义

<Term def="能被快速核验的“答案证据”：yes-实例存在长度不超过输入多项式的串 y，验证器可在多项式时间内确认它。">
  证书
</Term>
（certificate，也称
witness）就是那张"别人画好的路线"。现在形式化直觉引入里"验地图"的那一侧：验证器
V 是一个确定性的多项式时间程序，它同时拿到输入 x 和证书 y，输出 1（认可）或
0（不认可）。一个语言属于 NP，当且仅当存在一个多项式 p 和这样的 V，使得：x 属于
L 时，至少存在一个长度 ≤ p(|x|) 的证书让 V 输出 1；x 不属于 L 时，任何 y 都让 V
输出 0。

注意两个不对称。其一，NP 只要求 yes-实例存在证书，不要求有人能快速找到它——找到是求解者的负担，验证器只负责核验。其二，no-实例不需要这类证书；co-NP 讨论的是"no 也有短证书"的语言类，它与 NP 是否相等同样未解决。NP 里的 N 来自一种"先猜证书再验证"的抽象计算模型，它既不是"非多项式"，也不是"随机"。

若一个问题本身就在 P 里，验证器可以干脆忽略证书、直接运行那个多项式求解算法，所以 P 是 NP 的子集。反方向——每个能快速验证的问题是否也能快速求解——正是 P versus NP 问题，至今悬而未决。第五节实验把这一切落到了一张 6 顶点的图上：两张声称的证书、三项检查、一个判定读数。

## 数学：P、NP 与归约的精确定义

本节符号：x 为编码后的输入串，n = |x| 为其二进制长度；L 为语言（决策问题）；y 为证书；p 为多项式界；V 为验证器；f 为归约映射；A、B 为两个决策问题；TIME(nᵏ) 为 O(nᵏ) 步内可判定的语言类。

P 类的定义是所有多项式时间界的并集：

$$
P=\bigcup_{k\ge 1}\operatorname{TIME}(n^k).
$$

这个式子在说：只要存在一个固定的幂 k，让某台确定型机器在 nᵏ 步内判定 L，L 就属于 P——k 不能随输入变化，n 永远是编码长度而不是数值大小。

NP 类用证书存在量词定义：

$$
x\in L
\ \Longleftrightarrow\
\exists\,y\ \bigl(|y|\le p(|x|)\ \wedge\ V(x,y)=1\bigr).
$$

这个式子在说：x 是 yes-实例，等价于"存在一张个头不超过输入多项式的证书，能被验证器认可"；是 no-实例时，所有证书都过不了验证器。

归约是本章第二个核心定义。

<Term def="A≤ₚB：存在多项式时间可计算的函数 f，使 x∈A 当且仅当 f(x)∈B；含义是“若 B 能快速求解，则 A 也能”。">
  多项式时间归约
</Term>
（polynomial-time reduction，记作 A≤ₚB）写作：

$$
x\in A\ \Longleftrightarrow\ f(x)\in B.
$$

这个式子在说：把 A 的任意输入 x 用多项式时间翻译成 B 的一个输入 f(x)，使得答案完全保持——x 是 yes 当且仅当 f(x) 是 yes。于是 B 的任何高效求解器立刻成为 A 的高效求解器：先算 f(x)，再交给它。

由此得到 <Term def="同时满足“属于 NP”（有短证书可快速验证）和“NP 里所有语言都能多项式归约到它”（至少和任何 NP 问题一样难）的问题。">NP完全</Term> 的定义：

$$
B\text{ 是 NP-complete}
\ \Longleftrightarrow\
B\in NP\ \wedge\ \forall L\in NP,\ L\le_p B.
$$

这个式子在说：一个问题是 NP 完全的，要同时满足两条——它自己在 NP 里（有短证书可验），并且 NP 里所有语言都能归约到它（它至少和任何 NP 问题一样难）。只满足后者的问题叫 <Term def="所有 NP 问题都能多项式归约到它；它不必自身属于 NP。">NP-hard</Term>：优化版本、甚至不可判定问题都可能是 NP-hard，但它们不是决策语言，谈不上"属于 NP"。两条混淆是常见误区，见后面"常见误区"。

## 经典问题与归约工具箱

Cook–Levin 定理给出这条工具链的根：布尔可满足性问题 SAT 是 NP-complete。之后每一条箭头都必须是一个保持 yes/no 答案的多项式时间映射；归约的传递性允许把链首的 NP-hardness 逐段传到链尾。代表性链条是 SAT → 3-CNF-SAT → CLIQUE → VERTEX-COVER → HAMILTONIAN-CYCLE → TSP。这里不展开 gadget 的完整证明，但要知道每条箭头各自需要证明什么，不能仅凭“它们看起来相似”就跳过。

其中 CLIQUE 到 VERTEX-COVER 可写得精确些：CLIQUE(G,k) 等价于 COMPLEMENT-INDEPENDENT-SET(补图 Ḡ,k)，再等价于 VERTEX-COVER(Ḡ, |V|−k)；因为集合 S 是独立集，当且仅当 V\S 是顶点覆盖。Hamiltonian-cycle 到 TSP 决策版可给原图边成本 1、非边成本 |V|+1，并设界 B=|V|：成本不超过 |V| 的巡回恰好只能使用原图边。

选源问题的原则是结构贴近：源越贴近目标，构造零件（gadget）越少、双向等价越容易证明。实验第四步把“难度沿箭头传染”的方向画出来，并演示方向画反的错误。

这些经典问题为什么属于 NP，可以直接检查各自的 yes-证书：

| 决策问题                                              | yes-证书     | 多项式验证内容                                               |
| ----------------------------------------------------- | ------------ | ------------------------------------------------------------ |
| CLIQUE：图中是否有至少 k 个两两相邻的顶点？           | k 个顶点     | 检查顶点互异，并检查每一对之间都有边，至多检查 k(k−1)/2 对。 |
| VERTEX-COVER：是否存在大小至多 k 的顶点覆盖？         | 顶点集合 C   | 检查\|C\| ≤ k，并逐边确认至少一个端点在 C 中。               |
| HAMILTONIAN-CYCLE：是否有经过每个顶点恰好一次的回路？ | 顶点序列     | 检查长度、互异性、每段边及最后回到起点的边。                 |
| TSP（决策版）：是否有总成本至多 B 的巡回？            | 一个巡回顺序 | 检查每个城市恰好一次，累加巡回边成本并与 B 比较。            |

证书长度都被输入图/矩阵的规模多项式界定；验证器只做有限次查表、比较和加法。对于 TSP，成本采用二进制编码时，成本和的位数也至多比输入中的成本位数多 O(log n)，所以这些算术操作仍是输入长度的多项式时间。这个表说明的是这些决策问题在 NP 中；NP 完全还要另证 NP-hard，不能从“证书好验”直接推出。

也要说清 NP-complete 标签**不**意味着什么：它是针对最坏情形、渐进意义的分类，不表示每个具体实例都难，更不禁止特判、参数化算法、近似算法、随机化或启发式在实际规模上奏效。它要求的是：在 P versus NP 解决之前，不要指望存在一个对所有实例都已证明的一般多项式精确求解器。

## 代码对照：一个诚实的验证器

第五节实验背后的 oracle 可以写成二十行以内的结构化代码。注意第 10 行的绕回 `(i + 1) % n`：它就是被"漏查闭合边"故障删掉的那一行——删掉它，验证器对末位回到起点这一段不查表，假证书立刻漏网。

```ts
function verifyCycle(
  edges: Set<string>, // 无向边集，规范序 "u-v"（u < v）
  order: number[], // 声称的顶点序列（证书）
  n: number, // 顶点总数
): boolean {
  if (order.length !== n) return false; // 检查①长度
  if (new Set(order).size !== n) return false; // 检查①唯一
  for (let i = 0; i < n; i++) {
    // 检查②+③
    const u = order[i];
    const v = order[(i + 1) % n]; // 末位绕回起点
    if (!edges.has(u < v ? `${u}-${v}` : `${v}-${u}`)) return false;
  }
  return true;
}
```

这段代码还体现一个工程纪律：验证器返回布尔判定，不返回"confidence"。NP 的数学定义里，验证器对每个证书必须给出确定的 0/1；把概率或分数混进判定，就不再是同一个概念。

## 常见误区

<Callout type="trap">
  **现象**：声称"证明"了新问题 B 很难，给出的却是从 B 到 SAT
  的归约。原因：难度只沿归约箭头正向传染——B≤ₚSAT 说的是"B 不比 SAT
  难"，方向反了什么都证明不了。修法：从已知 NP-complete 的 A 构造
  A≤ₚB，并同时交付映射的多项式时间界与双向等价证明；第五节实验第四步的故障开关演示的就是这个错误。
</Callout>

<Callout type="trap">
  **现象**：把 NP 读成"非多项式"或"随机多项式"，进而以为"NP 完全 =
  绝对没有快算法"。原因：NP 的 N
  来自"先猜后验"的非确定型计算模型，与随机无关；NP-complete
  是条件性结论——若有一个 NP-complete 问题落入 P，则 P=NP，所有 NP
  问题全部有高效算法。修法：引用 NP-complete 结论时永远带上"除非 P=NP"的前提。
</Callout>

<Callout type="trap">
  **现象**：看到按数值跑得很快的动态规划，就宣称对应判定问题"已是多项式时间"。原因：复杂度按编码长度
  n 计量，数值 N 只占 log₂N 位；以 N 为表宽的算法相对 n
  是指数。修法：先声明编码（二进制还是一元），再核算运行时间是 n 的多项式还是 N
  的多项式——后者只能叫拟多项式。
</Callout>

<Callout type="trap">
  **现象**：归约证明只写"显然等价"，或只证了 x∈A ⇒ f(x)∈B 一个方向。原因：反向
  f(x)∈B ⇒ x∈A 负责排除 f 引入的伪解（目标 witness
  不对应任何源实例的情形），经常更难、却最容易漏。修法：按固定清单审计——映射算法、输出规模界、运行时间界、正向、反向，五项缺一即打回。
</Callout>

## 小结

- 决策问题只答是/否，优化版可借阈值改写。
- 复杂度按编码长度计，不按数值大小计。
- 证书短、验证快 = NP；P⊆NP，反向未决。
- A≤ₚB 表示 B 至少和 A 一样难，箭头别画反。
- NP-complete = 属于 NP + 承受所有 NP 归约。

2. 在第五节实验中选择证书 B 并推进到判定步：验证器输出什么、拒绝原因对应哪一项检查？然后注入"漏查闭合边"故障重放：读数变成什么、这个验证器违反了哪条健全性要求？

   <Answer>

   正常流程输出 REJECT：证书 B 的检查①（顶点唯一）与检查②（相邻边逐段，含弦 3-5 与边 5-4）全部通过，唯独检查③失败——闭合边 4-0 不在图上。注入故障后读数变成"接受"，但这是错误放行：x 是 no-实例却存在"能通过验证"的证书，违反"no-实例的所有证书都必须被验证器拒绝"这条健全性要求。修法不是给判定打个折扣，而是把跳过的检查补回来——三项检查缺一不可。

   </Answer>

3. 某同学为证明新问题 B 是 NP-hard，构造了一个从 B 到 3-CNF-SAT 的多项式归约，并指出"3-CNF-SAT 是 NP-complete，所以 B 很难"。这个论证错在哪？要写出一个合格的 hardness 证明，归约应该长什么样？

   <Answer>

   错在方向：B≤ₚ3-CNF-SAT 的含义是"若 3-CNF-SAT 能快速求解，则 B 也能"，即 B 不比 3-CNF-SAT 难——这正是要证明的结论的反面。合格的证明应选定一个已知 NP-complete 的 A（结构上越贴近 B 越好，如顶点覆盖或哈密顿回路），构造 A≤ₚB 的多项式映射 f，并交付五项证据：映射算法、输出规模多项式界、运行时间多项式界、x∈A⇒f(x)∈B、f(x)∈B⇒x∈A。若 B 本身还在 NP 里（给出证书与验证器），才能进一步称 B 是 NP-complete。

   </Answer>

## 名词解释

<Glossary>

<GlossaryItem term="决策问题">
  只回答"是"或"否"的问题。大白话：不许问"最好的方案值多少钱"，只能问"有没有不超过
  500 块的方案"——优化问题都能改成这种问法。详见"决策问题"节。
</GlossaryItem>
<GlossaryItem term="多项式时间">
  运行步数不超过输入规模的某个固定次幂；输入规模是编码后的位数。大白话：输入翻一倍，耗时最多按"倍的固定次方"涨，而不是翻倍再翻倍。详见"多项式时间"节。
</GlossaryItem>
<GlossaryItem term="证书">
  一张能被快速核验的"答案证据"，比如一条声称的回路。yes-实例必有一张证书能过验证，no-实例的所有证书都过不了。详见"证书与验证器"节与第五节实验。
</GlossaryItem>
<GlossaryItem term="多项式时间归约">
  把问题 A 的输入在多项式时间内翻译成问题 B 的输入，且两边答案始终一致，记作
  A≤ₚB。大白话：B 的任何解法都能借来解 A，所以 B 至少和 A
  一样难——箭头从已知难的指向目标。详见"数学"节与实验第四步。
</GlossaryItem>
<GlossaryItem term="NP-hard">
  至少和 NP 中每个问题一样难：所有 NP 问题都能多项式归约到它。它不要求自身属于
  NP，因此 NP-hard 不自动等于 NP-complete；还要证明它在 NP
  中才够完整。详见“数学”节。
</GlossaryItem>
<GlossaryItem term="NP完全">
  同时满足"自己在 NP 里"和"NP
  里所有问题都能归约到它"的问题。大白话：这类问题里只要有一个被找到高效解法，所有可快速验证的问题全会变成可快速求解的。详见"数学"节与"经典问题与归约工具箱"节。
</GlossaryItem>

</Glossary>
