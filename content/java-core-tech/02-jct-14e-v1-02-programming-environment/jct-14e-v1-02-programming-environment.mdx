## 为什么从“JDK 工具链复现台”开始

卷I 第2章 Java 编程环境要解决的不是 API 名称记忆，而是建立 JDK 25 安装、javac/java 命令、IDE 与 JShell 之间一致且可复现的源码—字节码—运行链。 直觉上，编译成功只排除了部分静态错误；运行一次成功也没有覆盖空值、极值、取消、并发、资源关闭、区域、协议与版本边界。

先预测：把执行入口从“命令行”切换为“IDE构建”，环境一致率与隐式配置风险会如何变化？随后只改这一项运行探针；结果不符时修改机制假设，不移动输入边界。

## 三个必须主动触发的误区

<Callout type="trap" title="编译成功不等于合同成立">
  卷I 第2章 Java 编程环境必须覆盖运行时输入、状态与资源边界；编译器没有承诺源码、JDK版本、编译选项和运行类路径四项均可重建会在所有外部条件下自动成立。
</Callout>

<Callout type="trap" title="本章核心故障">
  IDE 使用 JDK 25 而终端仍调用旧 javac，导致同一源码得到不同诊断。先定位识别JDK→编译源码→检查字节码→运行类→交互验证中的第一个分叉，再修改最小原因。
</Callout>

<Callout type="trap" title="修复后没有同输入重放">
  只展示新结果无法证明修复；必须恢复原始Java版本、输入与资源坐标，让原反例转成稳定回归，再执行重置。
</Callout>
