## 知识链路

```text
// 八步知识链路: 从代码到架构

// 1. 语法基础: 变量/类型/运算符/控制流/异常
int x = 10; String s = "hello";
try { ... } catch (IOException e) { ... }

// 2. OOP: 封装 → 继承 → 多态 → 抽象
class Employee { private double salary; }
class Manager extends Employee { @Override double getSalary() { ... } }

// 3. 接口: interface → default → Lambda → 函数式接口 → 方法引用
Comparator<Employee> bySalary = Comparator.comparingDouble(Employee::getSalary);

// 4. 集合: List/Set/Queue/Map → 泛型类型安全 → 迭代器 fail-fast
List<Employee> list = new ArrayList<>();
Map<String, List<Employee>> byDept = list.stream()
    .collect(Collectors.groupingBy(Employee::getDept));

// 5. IO: 字节流/字符流 → 缓冲/装饰器 → NIO Channel/Buffer → Stream API
try (var in = new BufferedReader(new FileReader("data.txt"))) { ... }
list.stream().filter(e -> e.getSalary() > 50000).toList();

// 6. 并发: Thread/Runnable → synchronized/Lock → volatile/CAS → 线程池
ExecutorService pool = new ThreadPoolExecutor(4, 8, 60, SECONDS, queue);
ConcurrentHashMap<Long, Employee> cache = new ConcurrentHashMap<>();

// 7. 高级: 注解@Retention → 反射invoke → 类加载双亲委派 → 动态代理
@Entity class User { @Column String name; }
Field f = User.class.getDeclaredField("name"); f.setAccessible(true);

// 8. 网络: DOM/SAX XML → JSON Jackson → Socket TCP → HttpClient
HttpClient client = HttpClient.newHttpClient();
String json = new ObjectMapper().writeValueAsString(user);
HttpResponse<String> res = client.send(req, BodyHandlers.ofString());
```

## 核心对比

| 对比项 | 区别 | 使用建议 |
|--------|------|----------|
| `==` vs `equals` | `==`比较地址/基本类型值，`equals`比较内容 | String/Integer 用 equals |
| String vs StringBuilder | 不可变 vs 可变 | 循环拼接用 StringBuilder |
| 接口 vs 抽象类 | 多实现无字段 vs 单继承有字段 | 行为规范用接口，共享代码用抽象类 |
| synchronized vs Lock | 自动释放 vs 手动unlock | 简单同步用synchronized |
| HashMap vs ConcurrentHashMap | 非线程安全 vs CAS+分段锁 | 多线程用ConcurrentHashMap |
| IO流 vs Stream API | 数据读写管道 vs 函数式数据管道 | 不同概念，不要混淆 |
| ArrayList vs LinkedList | 动态数组O(1)访问 vs 链表O(n)访问 | 默认ArrayList |

## 常见误区

<Callout type="trap">
**误区：学完 API 就等于掌握 Java。** API 只是工具，真正的 Java 功力在于理解机制：为什么 String 不可变（安全+常量池+线程安全）、为什么 HashMap 链表要转红黑树（防哈希碰撞攻击）、为什么 volatile 不保证原子性（只可见性，count++ 仍非原子）、为什么类加载要双亲委派（防核心类篡改）、为什么 IO 要用装饰器模式（灵活组合功能）。面试常考的不是「怎么用」，而是「为什么这样设计」。能解释设计原因，才算真正理解 Java。
</Callout>

<Exercises>
**问题 1**：从「Java源码」到「程序执行」的完整旅程是什么？

<Answer>
①编写 .java 源文件；②javac 编译为 .class 字节码（平台无关）；③类加载——ClassLoader 加载 .class 到 JVM（加载→验证→准备→解析→初始化），双亲委派保证安全；④运行——JVM 解释器逐条执行字节码，热点代码 JIT 编译为机器码缓存执行；⑤JVM 内存管理——堆（对象+数组，GC管理）、方法区/元空间（类信息+常量池）、栈（方法栈帧）、程序计数器；⑥GC 自动回收——新生代（Eden+S0+S1，复制算法）→老年代（标记-清除/整理）。整个旅程：源码→字节码→类加载→解释/JIT执行→GC回收。
</Answer>

**问题 2**：比较 Java 集合框架中 List、Set、Map 三大接口的核心特点和实现类。

<Answer>
List（有序可重复）：ArrayList（动态数组，get O(1)，最常用）、LinkedList（双向链表，首尾增删 O(1)）、CopyOnWriteArrayList（读多写少，线程安全）。Set（无序不重复）：HashSet（哈希表 O(1)）、LinkedHashSet（保持插入顺序）、TreeSet（红黑树 O(log n)，有序）。Map（键值映射）：HashMap（最常用，非线程安全）、LinkedHashMap（保持顺序）、TreeMap（有序）、ConcurrentHashMap（线程安全，高并发首选）。选择原则：默认 ArrayList+HashMap；需排序用 TreeSet/TreeMap；需线程安全用 CopyOnWriteArrayList/ConcurrentHashMap。
</Answer>

<Glossary>
<GlossaryItem term="四阶段递进">基础语法与面向对象 → 接口Lambda与集合泛型 → I/O流与并发编程 → 高级特性与XML网络。每层解决前一层的遗留问题：基础解决「怎么写代码」，接口集合解决「怎么抽象和操作」，IO并发解决「怎么读写和并发」，高级网络解决「怎么动态和通信」。</GlossaryItem>
<GlossaryItem term="JVM内存模型">堆（对象实例+数组，GC管理）、方法区/元空间（类信息+常量池+静态变量）、栈（方法栈帧：局部变量表+操作数栈）、程序计数器（当前指令地址）、本地方法栈（native方法）。JDK 8+ 用元空间替代永久代，使用本地内存。</GlossaryItem>
<GlossaryItem term="GC垃圾回收">自动回收堆中无用对象。分代回收：新生代（Eden+S0+S1，Minor GC，复制算法）→老年代（Full GC，标记-清除/标记-整理）。GC Roots：栈中引用、静态变量、常量、JNI引用。可达性分析判断对象是否存活。常用收集器：G1（Java 9+默认）、ZGC（低延迟）。</GlossaryItem>
<GlossaryItem term="JIT编译">即时编译（Just-In-Time）。JVM 运行时将热点代码（频繁调用的方法/循环）编译为本地机器码缓存执行。混合模式：解释器启动快，JIT 运行快。热点探测：方法调用计数器+回边计数器。C1编译器快速编译，C2编译器深度优化。</GlossaryItem>
</Glossary>
