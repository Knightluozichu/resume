## 注解

<Term def="注解是代码的元数据标记,编译器和运行时工具可通过反射读取注解信息。@Retention控制保留期:SOURCE/CLASS/RUNTIME。">注解</Term>是 Java 元编程的基础。

<JctAdvancedFeaturesDiagram />

```java
// 内置注解
@Override           // 检查方法重写
@Deprecated         // 标记过时
@SuppressWarnings   // 抑制警告
@FunctionalInterface // 函数式接口

// 元注解: 标注注解的注解
@Target(ElementType.TYPE)      // 可标注位置: TYPE/FIELD/METHOD...
@Retention(RetentionPolicy.RUNTIME)  // 保留期: SOURCE/CLASS/RUNTIME

// 自定义注解: @Retention(RUNTIME) 才能被反射读取
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface Entity {
    String table() default "";
}

@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Column {
    String name() default "";
    boolean nullable() default true;
}

// 使用注解
@Entity(table = "users")
public class User {
    @Column(name = "user_name")
    private String name;

    @Column(name = "age", nullable = false)
    private int age;
}
```

## 反射

```java
// 获取 Class 对象
Class<?> cls = Class.forName("com.example.User");
Class<?> cls2 = User.class;
Class<?> cls3 = new User().getClass();

// 获取类信息
Field[] fields = cls.getDeclaredFields();      // 所有字段(含private)
Method[] methods = cls.getDeclaredMethods();   // 所有方法
Constructor<?>[] constructors = cls.getConstructors();

// 动态创建对象
Object obj = cls.getDeclaredConstructor().newInstance();
// (替代已废弃的 cls.newInstance())

// 动态读写字段
Field nameField = cls.getDeclaredField("name");
nameField.setAccessible(true);   // 突破 private 限制
nameField.set(obj, "Alice");
String name = (String) nameField.get(obj);

// 动态调用方法
Method setName = cls.getDeclaredMethod("setName", String.class);
setName.invoke(obj, "Bob");

// 读取注解 (需要 @Retention(RUNTIME))
if (cls.isAnnotationPresent(Entity.class)) {
    Entity entity = cls.getAnnotation(Entity.class);
    String table = entity.table();  // "users"
}
for (Field f : cls.getDeclaredFields()) {
    if (f.isAnnotationPresent(Column.class)) {
        Column col = f.getAnnotation(Column.class);
        System.out.println(f.getName() + " -> " + col.name());
    }
}
```

## 类加载器

```java
// 类加载器层次: 双亲委派模型
// BootstrapClassLoader (C++ 实现, 加载 rt.jar 核心类)
//   -> ExtClassLoader/PlatformClassLoader (加载扩展类)
//     -> AppClassLoader (加载 classpath 应用类)
//       -> 自定义 ClassLoader

// 双亲委派: 收到加载请求先委派父加载器
// 设计原因: ①安全——防止核心类被篡改
//          ②唯一性——同一类只加载一次

// 类加载生命周期:
// 加载 -> 验证 -> 准备 -> 解析 -> 初始化 -> 使用 -> 卸载

// 获取类加载器
ClassLoader loader = String.class.getClassLoader();  // null (Bootstrap)
ClassLoader appLoader = MyApp.class.getClassLoader(); // AppClassLoader

// 动态加载类
Class<?> dynamicClass = Class.forName("com.example.Plugin", true, loader);
```

## 常见误区

<Callout type="trap">
**误区：反射性能不是问题，框架都在用。** 反射比直接调用慢 10~100 倍（JIT 优化后差距缩小但仍有开销）。性能瓶颈在获取 Method/Field 对象，而非调用本身。优化方案：①缓存反射结果（Method/Field 对象复用）；②setAccessible(true) 跳过访问检查；③框架级用 ASM/CGLIB 字节码增强生成代理类，比反射快得多。另一个常见误解：自定义 `java.lang.String` 会被加载——双亲委派模型保证 Bootstrap 的 String 优先加载，用户版本不会被加载，这是安全机制。
</Callout>

<Exercises>
**问题 1**：@Retention 有哪几种策略？分别什么时候可用？

<Answer>
三种策略：①SOURCE——注解只在源码中存在，编译后丢弃（如 @Override），仅编译器检查；②CLASS（默认）——保留到 class 文件但运行时 JVM 不加载，字节码工具（ASM/CGLIB）可读取；③RUNTIME——保留到运行时，可通过反射读取（如 Spring @Component、@Entity）。使用场景：编译检查用 SOURCE，字节码处理用 CLASS，运行时框架用 RUNTIME。自定义注解通常用 @Retention(RUNTIME) + @Target，通过反射 getAnnotation() 读取。
</Answer>

**问题 2**：双亲委派模型是什么？为什么要这么设计？

<Answer>
双亲委派：类加载请求先委派给父加载器，父加载器加载不到再自己加载。层次：BootstrapClassLoader→ExtClassLoader→AppClassLoader→自定义。设计原因：①安全——防止核心类被篡改（用户自定义 java.lang.String 会被 Bootstrap 的 String 覆盖）；②唯一性——同一类只被加载一次（同一加载器+同一类名=同一 Class 对象），避免重复加载。打破双亲委派：SPI 机制（线程上下文 ClassLoader）、Tomcat（每个 Web 应用独立 ClassLoader 隔离）、热部署（自定义 ClassLoader 重新加载类）。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="注解">代码的元数据标记。元注解 @Target 控制标注位置，@Retention 控制保留期（SOURCE/CLASS/RUNTIME）。RUNTIME 注解可通过反射读取。框架大量使用注解：Spring @Component/@Autowired、JPA @Entity/@Column、JUnit @Test。</GlossaryItem>
<GlossaryItem term="反射">运行时动态获取类信息并操作对象的能力。Class.forName() 获取类，getDeclaredFields() 获取字段，setAccessible(true) 突破 private，Method.invoke() 动态调用。用于框架（Spring IoC、ORM、JSON序列化）。性能优化：缓存反射结果、MethodHandle、字节码增强。</GlossaryItem>
<GlossaryItem term="类加载器">将 .class 文件加载到 JVM 内存的组件。双亲委派模型：请求先委派父加载器。层次：BootstrapClassLoader→ExtClassLoader→AppClassLoader→自定义。保证核心类安全和类唯一性。类加载生命周期：加载→验证→准备→解析→初始化→使用→卸载。</GlossaryItem>
<GlossaryItem term="动态代理">运行时生成代理对象的机制。JDK 动态代理基于接口（Proxy.newProxyInstance + InvocationHandler），CGLIB 基于继承（ASM 生成子类 + MethodInterceptor）。用于 AOP（事务/日志/权限）、RPC、懒加载。Spring AOP 有接口默认 JDK 代理，无接口用 CGLIB。</GlossaryItem>
</Glossary>
