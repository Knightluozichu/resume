## 为什么从“I/O 格式与资源边界台”开始

卷II 第2章 输入与输出要解决的不是 API 名称记忆，而是区分字节与字符、文件属性、映射内存、锁、序列化和正则边界，确保格式与资源生命周期可恢复。 直觉上，编译成功只排除了部分静态错误；运行一次成功也没有覆盖空值、极值、取消、并发、资源关闭、区域、协议与版本边界。

先预测：把数据表示从“显式UTF-8”切换为“对象图”，往返一致率与格式与泄漏风险会如何变化？随后只改这一项运行探针；结果不符时修改机制假设，不移动输入边界。

## 三个必须主动触发的误区

<Callout type="trap" title="编译成功不等于合同成立">
  卷II 第2章 输入与输出必须覆盖运行时输入、状态与资源边界；编译器没有承诺格式、编码、大小与关闭责任在读取前明确会在所有外部条件下自动成立。
