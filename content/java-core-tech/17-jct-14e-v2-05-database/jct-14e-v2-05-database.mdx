## 为什么从“JDBC 事务与资源轨迹台”开始

卷II 第5章 数据库编程要解决的不是 API 名称记忆，而是从 JDBC 驱动、SQL 参数、结果集、元数据、事务到连接池建立一致性、隔离与资源归还合同。 直觉上，编译成功只排除了部分静态错误；运行一次成功也没有覆盖空值、极值、取消、并发、资源关闭、区域、协议与版本边界。

先预测：把语句构造从“参数语句”切换为“批处理参数”，数据一致率与注入与半提交风险会如何变化？随后只改这一项运行探针；结果不符时修改机制假设，不移动输入边界。

```java
try (var ps = connection.prepareStatement("select name from users where id = ?")) {
  ps.setLong(1, id);
  try (var rs = ps.executeQuery()) { return rs.next() ? rs.getString(1) : null; }
}
```

## 三个必须主动触发的误区

<Callout type="trap" title="编译成功不等于合同成立">
  卷II 第5章 数据库编程必须覆盖运行时输入、状态与资源边界；编译器没有承诺事务要么完整提交，要么完整回滚并释放所有JDBC资源会在所有外部条件下自动成立。
</Callout>

<Callout type="trap" title="本章核心故障">
  拼接SQL或捕获异常后仍提交部分修改，并把脏连接放回池中。先定位取得连接→绑定参数→执行语句→提交事务→归还连接中的第一个分叉，再修改最小原因。
</Callout>

<Callout type="trap" title="修复后没有同输入重放">
  只展示新结果无法证明修复；必须恢复原始Java版本、输入与资源坐标，让原反例转成稳定回归，再执行重置。
</Callout>
