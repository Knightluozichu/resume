## 为什么从“动态编译诊断台”开始

卷II 第8章 编译与脚本要解决的不是 API 名称记忆，而是通过 Compiler API 的诊断、内存文件与产物身份管理动态编译，并把脚本执行放入明确的信任和资源边界。 直觉上，编译成功只排除了部分静态错误；运行一次成功也没有覆盖空值、极值、取消、并发、资源关闭、区域、协议与版本边界。

先预测：把代码来源从“已签名插件”切换为“用户文本”，诊断完备率与代码执行风险会如何变化？随后只改这一项运行探针；结果不符时修改机制假设，不移动输入边界。
