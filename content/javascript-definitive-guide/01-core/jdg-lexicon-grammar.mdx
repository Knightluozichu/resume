## 直觉引入

你有没有好奇过：为什么 JavaScript 允许省略分号，但有时省略又会出 bug？答案藏在词法结构里——JavaScript 引擎在解析源码时，会先把字符流切分成 token（标识符、字面量、运算符、标点），再用一套叫 ASI（自动分号插入）的规则决定语句边界。ASI 大多数时候能正确补分号，但在少数情况下会把两行错误地拼成一条语句。词法结构是程序的最底层：它定义了「字符如何组成程序」，是所有上层语法的地基。理解它，不是为了纠结分号风格，而是为了在遇到诡异解析错误时能精确解释「为什么这两行被拼在一起了」。

## 四个词法要素

<Term def="ASI（自动分号插入）是 JavaScript 引擎在解析阶段自动补充分号的机制：当遇到换行符且下一 token 无法与当前语句拼接时、遇到右大括号时、或输入流结束时，自动插入分号。它让省略分号在多数情况下可行，但少数情况会导致错误拼接。">ASI 自动分号插入</Term>是词法结构中最易踩坑的部分。JavaScript 程序由 **Unicode 文本** 构成，区分大小写（`let` 是关键字，`Let` 不是），字符串和标识符中可使用任意 Unicode 字符。**注释**有两种：`//` 单行和 `/* */` 多行（不可嵌套）。**标识符**以字母、`$` 或 `_` 开头，后续可含数字；**保留字**（关键字）不可作标识符。

```javascript
// 1. Unicode：标识符可用中文等 Unicode 字符
const 价格 = 100; // 合法但工程上不推荐

// 2. ASI 正常工作：换行后下一 token 无法拼接，自动补分号
const a = 1
const b = 2 // ASI 在两行间补分号，正常

// 3. ASI 陷阱：return 后换行，ASI 在 return 后补分号
function bad() {
  return        // ← ASI 在这里补分号！
    { ok: 1 };  // 这行变成独立语句，函数返回 undefined
}

// 4. ASI 陷阱：以 ( 开头的行被拼到上一行
let x = 1
(x + 2).toFixed()  // 被解析成 1(x + 2).toFixed() → TypeError

// 5. 修复：以 [ ( + - 开头的行前加分号
let x = 1
;(x + 2).toFixed() // 前置分号防拼接
```

## 保留字分类

JavaScript 的保留字分三类：**语言关键字**（`var`/`let`/`const`/`function`/`class`/`return`/`if`/`for`/`async`/`await` 等）在语法中有固定含义，不可作标识符；**保留待用字**（`enum`/`implements`/`interface`/`package` 等）当前未启用但严格模式下保留，以备未来扩展；**特殊字面量**（`true`/`false`/`null`/`undefined`）虽非关键字但同样不可作标识符。值得注意的是 `undefined` 不是关键字——它是一个全局只读属性，这意味着在非严格模式下可以被遮蔽（这也是为什么用 `void 0` 替代它的由来）。

## 常见误区

<Callout type="trap">
**误区：ASI 能自动补分号，所以可以一律不写分号。** ASI 确实让省略分号在多数情况下可行，但它有一套复杂规则，少数情况会出错。最典型的是以 `(`、`[`、`` ` ``、`+`、`-` 开头的行被拼到上一行：`a\n(b+c)` 被解析成 `a(b+c)`，`[1,2]\n.forEach(...)` 被解析成属性访问。还有 `return`/`throw`/`break`/`continue` 后换行会提前断句。工程上有两种稳健做法：要么每条语句末尾都写分号（主流风格），要么在以 `[`/`(`/`+`/`-`/`` ` `` 开头的行前加分号（无分号风格）。纯靠 ASI 不加任何防护，迟早踩坑。
</Callout>

<Exercises>
**问题 1**：ASI 自动分号插入的三条规则是什么？为什么 `return\nvalue` 会返回 `undefined`？

<Answer>
三条规则：①遇到换行符，且下一 token 无法与当前语句拼接成合法语法时，在换行处插入分号；②遇到右大括号 `}` 时，在 `}` 前插入分号；③输入流（文件/程序）结束时，在末尾插入分号。`return\nvalue` 的问题：`return` 后面换行，ASI 规则①检测到换行，而 `return` 本身就是一个完整的语句（return 后可无表达式表示返回 undefined），于是 ASI 在 return 后补了分号，`return` 变成「返回 undefined」，下一行的 `value` 变成独立表达式语句。修复：`return` 与返回值写同一行，或用括号包裹。这个陷阱也适用于 `throw`、`break`、`continue` 后换行。
</Answer>

**问题 2**：`let x = 1\n(x+2).toFixed()` 为什么会报 `TypeError`？如何修复？

<Answer>
因为 ASI 不会在 `1` 和 `(x+2)` 之间补分号——`(x+2)` 这个以 `(` 开头的 token 序列可以和前面的 `1` 拼接成合法语法：`1(x+2)` 被解析成「把 1 当函数调用，参数是 x+2」，于是整行变成 `1(x+2).toFixed()`，即先调用 `1(x+2)`（数字不是函数，TypeError）。ASI 只在「拼接后不合法」时才补分号，而 `1(...)` 语法上合法（函数调用表达式），所以不补。修复方法：①在以 `(`、`[`、`` ` ``、`+`、`-` 开头的行前加分号，即 `;(x+2).toFixed()`；②或在上一行末尾显式写分号 `let x = 1;`。这是无分号风格必须警惕的「行首防御」场景。
</Answer>
</Exercises>
