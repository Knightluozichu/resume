## 直觉引入

你一定踩过这样的坑：`0.1 + 0.2 !== 0.3`，或者 `NaN === NaN` 居然是 `false`。这些不是 bug，而是 JavaScript 类型系统的设计后果。JavaScript 有七种原始类型——number、string、boolean、null、undefined、symbol、bigint，它们按值访问、不可变、存在栈上；此外一切皆对象（引用类型），按引用访问、可变、存在堆上。理解类型系统的关键不是背类型列表，而是弄清三件事：值传递与引用传递的区别、不可变性意味着什么、类型转换何时发生又如何预判。

## 原始类型与引用类型

<Term def="原始类型是按值访问、不可变、存储于栈的数据类型；引用类型（对象）是按引用访问、可变、存储于堆的数据结构。赋值和传参时原始类型复制值的副本，引用类型复制引用地址——这是理解所有「为什么改了那个这个也变了」问题的根源。">值传递与引用传递</Term>是类型系统的核心分界。七种原始类型中，**number** 是 IEEE 754 双精度浮点（整数和浮点数统一为一种类型），**string** 是不可变的 UTF-16 字符序列，**boolean** 只有 `true`/`false`，**null** 表示空值（`typeof null === "object"` 是历史遗留 bug），**undefined** 表示未定义，**symbol** 是唯一不可变的私有属性键，**bigint** 是任意精度整数（`123n`）。

```javascript
// 1. 值传递：原始类型复制副本，互不影响
let a = 1;
let b = a;
b = 2;
console.log(a); // 1，a 不受影响

// 2. 引用传递：对象复制引用地址，指向同一对象
let obj1 = { x: 1 };
let obj2 = obj1;
obj2.x = 2;
console.log(obj1.x); // 2，obj1 和 obj2 指向同一对象

// 3. 字符串不可变：方法返回新串，不改原串
let s = "hello";
s[0] = "H"; // 无效，s 仍是 "hello"
s = s.toUpperCase(); // 返回新串 "HELLO"，赋值后才改变 s

// 4. NaN 陷阱：与任何值（含自身）都不等
NaN === NaN; // false！
Number.isNaN(NaN); // true，用这个判断
isNaN("abc"); // true 但有隐式转换，不推荐

// 5. 浮点精度：0.1+0.2 不等于 0.3
0.1 + 0.2 === 0.3; // false，实际是 0.30000000000000004
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON; // true，用容差比较
```

## 类型转换

JavaScript 是弱类型语言，运算符在操作数类型不匹配时会做类型转换。**显式转换**用 `Number(x)`/`String(x)`/`Boolean(x)` 明确表达意图；**隐式转换**由运算符触发：`+x` 转数字、`x + ""` 转字符串、`!!x` 转布尔、`==` 触发抽象相等比较。工程上的原则是**显式优于隐式**——把转换写在明处，让读代码的人一眼看懂。特别注意 `ToBoolean` 只有 6 个 falsy 值：`false`、`0`、`""`、`null`、`undefined`、`NaN`（外加 `0n`），其余全是 truthy——包括 `"0"`、`[]`、`{}`。

## 常见误区

<Callout type="trap">
**误区：`typeof null === "object"` 是 bug 所以不用管它。** 这确实是历史遗留 bug（null 在底层二进制表示中类型标签恰好是对象标签），但它有实际后果：判断 null 不能用 `typeof`，要用 `x === null`。另一个常被忽视的陷阱是浮点精度——`0.1 + 0.2 !== 0.3` 不是 bug 而是 IEEE 754 双精度的固有特性，所有使用浮点数的语言都有此问题。涉及金额计算时，要么用整数分（乘以 100 后计算），要么用容差比较（`Math.abs(a - b) < Number.EPSILON`），要么用 bigint/decimal 库。把浮点数当精确值做相等比较，迟早出财务 bug。
</Callout>

<Exercises>
**问题 1**：原始类型和引用类型在赋值与传参时有什么本质区别？这段代码输出什么？

<Answer>
假设代码：let a = 1; let b = a; b = 2; let o1 = {x:1}; let o2 = o1; o2.x = 2; 问 a 和 o1.x 分别是多少。原始类型按值传递：`let b = a` 复制了 a 的值 1 给 b，b 改成 2 不影响 a，所以 a 仍是 1。引用类型按引用传递：`let o2 = o1` 复制的是引用地址而非对象本身，o2 和 o1 指向堆中同一个对象，`o2.x = 2` 修改的是这个共享对象，所以 o1.x 变成 2。本质区别：原始类型复制值的副本（互不影响），引用类型复制引用地址（指向同一对象，改一个另一个也变）。这也是为什么函数参数如果是对象，函数内部修改它会影响外部——传的是引用的副本，但指向同一对象。
</Answer>

**问题 2**：为什么 `0.1 + 0.2 !== 0.3`？`NaN === NaN` 为什么是 `false`？工程上如何正确处理这两个问题？

<Answer>
0.1 + 0.2 !== 0.3 是 IEEE 754 双精度浮点的固有特性：0.1 和 0.2 在二进制中是无限循环小数，无法精确表示，存储时已被截断，相加后得到 0.30000000000000004 而非 0.3。这不是 JavaScript 独有，所有 IEEE 754 语言都如此。处理方式：①用容差比较 `Math.abs(a - b) < Number.EPSILON`；②金额用整数分计算后除以 100；③用 bigint 或 decimal 库。NaN === NaN 为 false 是规范设计：NaN 表示「不是一个数字」，两个非数字没有相等的概念（NaN 可能来自不同运算），故规范规定 NaN 与任何值（含自身）都不等。判断 NaN 用 `Number.isNaN(x)`（不隐式转换）而非全局 `isNaN`（会先隐式转数字，`isNaN("abc")` 误判为 true）。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="值传递与引用传递">原始类型（number/string/boolean/null/undefined/symbol/bigint）按值访问，赋值与传参复制值的副本，互不影响；引用类型（对象/数组/函数）按引用访问，赋值与传参复制引用地址，指向堆中同一对象，改一个另一个也变。这是所有「为什么改了那个也变了」问题的根源。</GlossaryItem>
<GlossaryItem term="字符串不可变">string 是不可变的 UTF-16 字符序列，所有字符串方法（toUpperCase/slice/replace）都返回新串而不改原串，s[0]="H" 无效。字符串拼接创建新串，大量拼接用数组 join 或模板字符串更高效。字符串 length 对码点大于 U+FFFF 的字符（如 emoji）返回码元数（2）而非字符数。</GlossaryItem>
<GlossaryItem term="类型转换">弱类型语言在运算符操作数类型不匹配时自动转换。显式：Number(x)/String(x)/Boolean(x) 意图明确；隐式：+x 转数字、x+"" 转字符串、!!x 转布尔、== 抽象比较。ToBoolean 只有 6 个 falsy（false/0/""/null/undefined/NaN 加 0n），其余 truthy。工程原则：显式优于隐式，默认用 ===。</GlossaryItem>
</Glossary>
