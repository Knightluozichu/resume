## 本章定位

<Term def="JavaScript 是一门动态、基于原型且函数是一等值的通用语言；本章用控制台、语言导览和字符频率直方图把语法、对象、模块与运行环境连成第一条完整程序链。">表达式</Term> 是本章的入口观察量。JavaScript 是一门动态、基于原型且函数是一等值的通用语言；本章用控制台、语言导览和字符频率直方图把语法、对象、模块与运行环境连成第一条完整程序链。 这意味着阅读不能停在 API 名称或最终打印值，而要回答：输入何时进入、值或对象怎样变化、控制权在哪里转移、错误如何传播、宿主资源由谁清理。

## 六阶段机制链

### 1. 启动 JavaScript 环境

固定源码、运行环境和输入，在动作发生前记录可见绑定、值类型、对象身份、待处理任务和已打开资源。若起点不稳定，后续比较没有意义。

### 2. 求值表达式与语句

只执行本阶段最小动作，记录它读取了什么、写入了什么，以及控制权交给语言运行时还是浏览器、Node 或工具链。

### 3. 组合对象、数组和函数

检查抽象规则是否被真正满足。不要用最终输出反推过程；对象引用、隐式转换、短路与异步调度都可能产生表面相同的结果。

### 4. 引入类与模块

在边界值、重复输入、迟到结果和错误宿主状态下重放。保存第一个与正常轨迹不同的位置，而不是只保存最后一条异常。

### 5. 构造字符频率直方图

让失败沿规定通道传播，并核对调用者是否能区分可重试、应停止和必须降级的情况。静默吞错不能作为恢复策略。

### 6. 核对输入、状态与输出

修复单一故障后重放完全相同的输入。只有绑定、值、任务、句柄和生成产物都回到可预测状态，本章才可以签发。

## 最小可运行实验

```javascript
const histogram = new Map();
for (const char of "banana") {
  histogram.set(char, (histogram.get(char) ?? 0) + 1);
}
console.log([...histogram.entries()].sort());
```

## 字符频率直方图的端到端拆解

<Term def="字符频率直方图把文本逐字符归一化、计数、排序并输出，是同时检验字符串迭代、Map 状态和数据变换的最小完整程序。">字符频率直方图</Term>不是一个孤立算法题，而是本章语言导览的验收样本。输入阶段先决定是否区分大小写、空白和组合字符；计数阶段每次读取旧值并写回新值；展示阶段再把 Map 转换为条目数组并排序。任一阶段省略，最终柱形图都可能“看起来合理”却无法复现。

以字符串 `"Aáa\u0301"` 为边界样本时，视觉上相近的字符不一定具有相同码点。正确实验应先记录原始码点，再分别执行 NFC 规范化和大小写归一化，比较计数键的数量。若直接从最终柱形图猜测输入，会把词法文本、运行时字符串与展示标签混为一谈。

计数容器也要保存过程证据：首次遇到字符时旧值是 `undefined`，空值合并后写入 1；再次遇到时读取已有计数并递增。若误用 `value || 0`，本例仍可能正确，但它会把合法的 0 与缺失值合并。这里选择空值合并，是为了让“键不存在”成为明确的分支条件。

最后分别保留插入顺序和排序后顺序。Map 保证按插入顺序迭代，而展示层常按字符或频次排序；排序只作用于新建的条目数组，不应暗中改变计数容器。这样就能从一段小程序观察值、对象、函数、迭代和模块化输出五类基础机制。

| 样本 | 注入方式 | 必查证据 | 通过条件 |
