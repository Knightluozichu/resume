## 直觉引入

函数是 JavaScript 抽象的基石——你用函数封装行为、用闭包记住状态、用 this 在方法中引用实例。但这三者也是初学者最容易困惑的地方：为什么 `setTimeout(obj.method, 0)` 里 `this` 不是 `obj` 了？为什么外层函数返回后，内层函数还能访问外层的变量？答案在于两个机制：**this 由调用点决定**（不是定义处），**闭包让函数记住并延续其定义处的词法作用域**。理解了这两点，你就能解释大多数「为什么这段代码的行为和预期不符」的函数相关问题。

## 四种定义与 this 绑定

<Term def="this 绑定四规则是 JavaScript 普通函数确定 this 指向的规则：默认绑定（独立调用，严格模式 this 为 undefined）、隐式绑定（obj.method()，this 为 obj）、显式绑定（call/apply/bind 指定 this）、new 绑定（构造调用，this 为新对象）。优先级：new > bind > apply/call > 隐式 > 默认。规则由调用点决定，与定义处无关。">this 绑定四规则</Term>是函数最核心的机制。四种函数定义形式各有 this 行为：**函数声明**（`function f() {}`，会提升）和**函数表达式**（`const f = function() {}`，不提升变量名）的 this 由调用点按四规则决定；**箭头函数**（`() => {}`）没有自身 this，继承外层词法作用域的 this；**方法简写**（`{ f() {} }`）的 this 指向调用它的对象。

```javascript
// 1. this 四规则
function show() { console.log(this); }
show();            // 默认绑定：严格模式 undefined，非严格 window
const obj = { show };
obj.show();        // 隐式绑定：this → obj
show.call({ x: 1 }); // 显式绑定：this → {x:1}
new show();        // new 绑定：this → 新对象

// 2. 隐式丢失：回调中 this 丢失
const obj2 = { name: "A", greet() { console.log(this.name); } };
setTimeout(obj2.greet, 0); // undefined！回调独立调用，this 丢失

// 3. 修复：bind 或箭头函数
setTimeout(obj2.greet.bind(obj2), 0); // "A"，bind 永久绑定
setTimeout(() => obj2.greet(), 0);    // "A"，箭头包裹保持隐式绑定

// 4. 箭头函数继承外层 this
function Timer() {
  this.count = 0;
  setInterval(() => { this.count++; }, 1000); // 箭头继承 Timer 的 this
  // 若用普通函数，this 会丢失变成 undefined/window
}

// 5. call/apply/bind 区别
fn.call(obj, a, b);     // 立即调用，逐个传参
fn.apply(obj, [a, b]);  // 立即调用，数组传参
const bound = fn.bind(obj, a); // 返回新函数，永久绑定，可预设参数（柯里化）
bound(b); // 调用时再传剩余参数
```

## 闭包：延续作用域

闭包是函数与其定义时所处的词法环境的组合。当外层函数返回内层函数时，内层函数仍持有对外层变量的引用——即使外层函数已执行完毕，其变量也不会被回收。这让函数能「记住」并继续访问定义处的作用域。闭包的用途极广：**私有状态封装**（模块模式）、**函数工厂**（生成配置化函数）、**柯里化**（分步传参）、**回调记住上下文**（事件处理保留状态）。

```javascript
// 闭包：计数器封装私有状态
function createCounter() {
  let count = 0; // count 藏在闭包里，外部拿不到但函数记得住
  return {
    inc: () => ++count,
    get: () => count,
  };
}
const c = createCounter();
c.inc(); c.inc();
console.log(c.get()); // 2，count 存活在闭包中

// 闭包陷阱：循环中 var 共享变量
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3 3 3，var 共享同一 i
}
// 修复 1：let 创建每轮独立作用域
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0 1 2
}
// 修复 2：IIFE 立即执行函数隔离
for (var i = 0; i < 3; i++) {
  ((j) => setTimeout(() => console.log(j), 0))(i); // 0 1 2
}
```

## 常见误区

<Callout type="trap">
**误区：箭头函数只是普通函数的简写，到处用它更简洁。** 箭头函数与普通函数有本质区别：它没有自身 this（继承外层词法 this）、没有 arguments 对象、不能作构造函数（不能用 new）、没有 prototype。这些差异决定了箭头函数适合「需要外层 this」的场景（回调、定时器、事件处理中访问实例），但不适合「需要自身 this」的场景（对象方法、原型方法、构造函数）。把对象方法写成箭头函数 `obj = { greet: () => this }`，this 不指向 obj 而是外层（通常是 undefined 或 window）——这是最常见的箭头函数误用。原则：需要 this 指向调用对象时用普通函数/方法简写，需要继承外层 this 时用箭头函数。
</Callout>

<Exercises>
**问题 1**：`setTimeout(obj.greet, 0)` 中 `this` 为什么丢失？三种修复方法是什么？

<Answer>
obj.greet 作为回调传给 setTimeout 时，传递的是函数本身的引用而非「obj.greet 这个方法」。当 setTimeout 在未来调用它时，调用形式是独立调用（没有 obj. 前缀），落回默认绑定规则：严格模式下 this 是 undefined，非严格模式下是 window。这叫「隐式丢失」——赋值或传参时丢失了对象上下文。三种修复：①用 bind 永久绑定：setTimeout(obj.greet.bind(obj), 0)，返回一个 this 固定为 obj 的新函数；②用箭头包裹保持隐式绑定：setTimeout(() => obj.greet(), 0)，箭头函数里调用 obj.greet() 仍是隐式绑定，this 指向 obj；③用闭包捕获：const self = this; setTimeout(function() &#123; self.greet(); }, 0)（老式写法）。现代代码推荐前两种。
</Answer>

**问题 2**：闭包是什么？为什么循环中 `var` 的 `setTimeout` 会打印相同的值，`let` 不会？

<Answer>
闭包是函数与其定义时词法环境的组合，让函数在外层作用域返回后仍能访问外层变量。循环中 var 的问题：var 是函数作用域，整个循环只有一个 i，每次迭代共享同一个 i。setTimeout 的回调是闭包，捕获的是这个共享的 i 的引用。当回调在循环结束后（i 已变成 3）执行时，读到的都是 3。let 的区别：let 是块作用域，每次循环迭代创建一个独立的 i，回调闭包捕获的是各自迭代轮次的 i（0/1/2），所以打印 0 1 2。本质区别：var 共享一个变量（闭包都引用同一个），let 每轮新建独立变量（闭包各引用各的）。不用 let 也可用 IIFE 立即执行函数手动创建独立作用域隔离每轮的 i。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="this 绑定四规则">普通函数确定 this 的规则：默认绑定（独立调用，严格模式 undefined）、隐式绑定（obj.m()，this→obj）、显式绑定（call/apply/bind）、new 绑定（构造调用，this→新对象）。优先级 new > bind > apply/call > 隐式 > 默认。由调用点决定，与定义处无关。箭头函数例外：无自身 this，继承外层词法 this。</GlossaryItem>
<GlossaryItem term="call/apply/bind">显式指定 this 的三种方法。fn.call(obj, a, b) 立即调用逐个传参；fn.apply(obj, [a,b]) 立即调用数组传参；fn.bind(obj) 返回新函数永久绑定 this（可预设参数实现柯里化）。箭头函数的 this 无法被这三者改变，因为它没有自身 this。</GlossaryItem>
<GlossaryItem term="闭包">函数与其定义时词法环境的组合。外层返回内层函数后，内层仍持有外层变量引用，外层变量不随外层调用结束而销毁。用途：私有状态封装、函数工厂、柯里化、回调记住上下文。注意闭包持有整个作用域，循环中 var 共享变量需用 let 或 IIFE 隔离。</GlossaryItem>
</Glossary>
