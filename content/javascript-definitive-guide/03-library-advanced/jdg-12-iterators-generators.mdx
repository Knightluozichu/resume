<Term def="可迭代协议把数据源与消费方式解耦，生成器把暂停点编码进函数；next、return、throw 和 yield 双向传值共同定义生命周期。">Iterable</Term> 是本章的入口观察量。可迭代协议把数据源与消费方式解耦，生成器把暂停点编码进函数；next、return、throw 和 yield 双向传值共同定义生命周期。 这意味着阅读不能停在 API 名称或最终打印值，而要回答：输入何时进入、值或对象怎样变化、控制权在哪里转移、错误如何传播、宿主资源由谁清理。

## 六阶段机制链

### 1. 取得迭代器

固定源码、运行环境和输入，在动作发生前记录可见绑定、值类型、对象身份、待处理任务和已打开资源。若起点不稳定，后续比较没有意义。

### 2. 请求下一项

只执行本阶段最小动作，记录它读取了什么、写入了什么，以及控制权交给语言运行时还是浏览器、Node 或工具链。

### 3. 执行到 yield 暂停

检查抽象规则是否被真正满足。不要用最终输出反推过程；对象引用、隐式转换、短路与异步调度都可能产生表面相同的结果。

### 4. 向生成器传回值或异常

在边界值、重复输入、迟到结果和错误宿主状态下重放。保存第一个与正常轨迹不同的位置，而不是只保存最后一条异常。

### 5. 关闭迭代器

让失败沿规定通道传播，并核对调用者是否能区分可重试、应停止和必须降级的情况。静默吞错不能作为恢复策略。

### 6. 以 done 和 value 收敛

修复单一故障后重放完全相同的输入。只有绑定、值、任务、句柄和生成产物都回到可预测状态，本章才可以签发。

## 最小可运行实验

```javascript
function* range(start, end) {
  for (let value = start; value <= end; value += 1) yield value;
}
const doubled = [...range(1, 3)].map((n) => n * 2);
console.log(doubled);
```
