## 直觉引入

现代前端应用离不开三件事：从服务器拿数据（网络）、在浏览器存数据（存储）、处理耗时计算不卡 UI（多线程）。Fetch 是 Promise 化的现代网络 API，但它有个反直觉的设计——HTTP 4xx/5xx 错误不会 reject，你需要手动检查 `res.ok`。客户端存储有三兄弟：localStorage（持久）、sessionStorage（会话级）、IndexedDB（大容量异步数据库），选错会导致数据丢失或性能问题。Web Worker 让你在主线程之外开一个线程跑 CPU 密集计算——因为 JavaScript 单线程，加密、图像处理、大数据排序如果不卸载到 Worker，会卡死 UI。

## Fetch API

<Term def="Fetch 是基于 Promise 的现代网络请求 API。关键陷阱：Fetch 只在网络层出错（DNS 解析失败、断网）时才 reject Promise，HTTP 4xx/5xx 不会 reject——需手动检查 res.ok 或 res.status。用 AbortController 实现超时和取消。">Fetch 陷阱</Term>是新手最常踩的坑。`fetch(url, options)` 返回 Promise，`res.ok` 检查状态码是否在 200-299，`res.status` 读取 HTTP 状态码，`res.json()`/`res.text()` 异步读取响应体。Fetch 只在网络层错误时 reject（如断网、CORS 被拒、DNS 失败），HTTP 404/500 不会 reject——因为从 HTTP 角度看请求「成功」返回了响应，只是状态码表示失败。用 `AbortController` 实现超时和取消。

```javascript
// 1. 基本用法 + 手动检查状态
async function getUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) { // 必须手动检查！4xx/5xx 不会自动 reject
    throw new Error(`HTTP ${res.status}`);
  }
  return res.json();
}

// 2. POST 请求
async function createUser(data) {
  const res = await fetch("/api/users", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data),
  });
  return res.json();
}

// 3. 超时 + 取消（AbortController）
async function fetchWithTimeout(url, ms = 5000) {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), ms);
  try {
    const res = await fetch(url, { signal: ctrl.signal });
    return await res.json();
  } catch (e) {
    if (e.name === "AbortError") throw new Error("请求超时或被取消");
    throw e; // 真正的网络错误
  } finally {
    clearTimeout(timer);
  }
}
// 场景：用户快速切换页面时取消未完成的请求
```

## 客户端存储

三种存储方案各有定位：**localStorage** 持久存储（手动才清除，同源共享，同步 API，约 5-10MB）；**sessionStorage** 会话级（标签页关闭即清除，不跨标签页，同步 API）；**IndexedDB** 异步事务型 NoSQL 数据库（容量大数百 MB+，存对象/文件/Blob，异步不阻塞主线程）。选型原则：配置/Token 等小数据用 localStorage，临时会话数据用 sessionStorage，大量结构化数据用 IndexedDB。

```javascript
// localStorage：同步，字符串，约 5-10MB
localStorage.setItem("token", "abc");
const token = localStorage.getItem("token");
localStorage.removeItem("token");
// 存对象需序列化
localStorage.setItem("user", JSON.stringify({ name: "A" }));
const user = JSON.parse(localStorage.getItem("user"));

// IndexedDB：异步，容量大，存对象
const db = await openDB("mydb", 1, {
  upgrade(db) { db.createObjectStore("users", { keyPath: "id" }); },
});
await db.put("users", { id: 1, name: "A", tags: ["a", "b"] }); // 存对象无需序列化
const user = await db.get("users", 1);
const all = await db.getAll("users");
```

## Web Worker

<Term def="Web Worker 是浏览器提供的多线程能力：new Worker('worker.js') 创建独立线程，通过 postMessage/onmessage 与主线程通信（数据结构化克隆）。Worker 不能操作 DOM/window，适合卸载 CPU 密集计算（加密、图像处理、大数据排序）不阻塞主线程 UI。">Web Worker</Term>让 JavaScript 拥有多线程能力。主线程 `new Worker("worker.js")` 创建 Worker，`postMessage(data)` 发送数据，`onmessage` 接收 Worker 返回结果。Worker 在独立全局作用域运行，不能访问 DOM/window/document，通过消息传递通信（数据被结构化克隆，不是共享引用）。`SharedWorker` 可跨标签页共享，`Service Worker` 是离线缓存与推送的底座。

```javascript
// 主线程
const worker = new Worker("heavy-compute.js");
worker.postMessage({ data: largeArray });
worker.onmessage = (e) => {
  console.log("计算结果", e.data);
  worker.terminate(); // 用完终止
};

// worker.js（Worker 线程）
self.onmessage = (e) => {
  const result = heavyCompute(e.data.data); // CPU 密集计算
  self.postMessage(result); // 发回主线程，不阻塞 UI
};
```

## 常见误区

<Callout type="trap">
**误区：Fetch 的 catch 能捕获所有请求错误，4xx/5xx 会进 catch。** 这是 Fetch 最常见的误解。Fetch 只在网络层出错（断网、DNS 失败、CORS 被拒）时才 reject Promise 进 catch；HTTP 404、500 等状态码不会 reject——因为从协议角度请求「成功」返回了响应。所以 `fetch(url).then(...).catch(...)` 中 404 不会进 catch，会进 then，`res` 看起来正常但 `res.ok` 是 false。必须手动检查 `if (!res.ok) throw new Error(res.status)`。另一个陷阱是 localStorage 同步阻塞——它在主线程同步读写，存大数据会卡 UI，大数据应用 IndexedDB。Web Worker 的数据是结构化克隆（复制而非共享），传超大对象有拷贝开销，用 Transferable 对象（如 ArrayBuffer）可转移所有权避免拷贝。
</Callout>

<Exercises>
**问题 1**：为什么 Fetch 的 4xx/5xx 不会进 catch？如何正确处理 HTTP 错误？如何实现超时取消？

<Answer>
Fetch 只在网络层出错时才 reject（断网、DNS 失败、CORS 被拒），HTTP 4xx/5xx 不 reject——因为从 HTTP 协议角度，请求成功发出并收到了响应，只是响应状态码表示失败。Fetch 的 Promise 表示「网络请求是否完成」而非「业务是否成功」。正确处理：在 then 中手动检查 if (!res.ok) throw new Error(`HTTP ${res.status}`)，res.ok 在状态码 200-299 时为 true。或封装一个 wrapper 函数统一检查。实现超时取消用 AbortController：const ctrl = new AbortController(); setTimeout(() => ctrl.abort(), 5000); fetch(url, { signal: ctrl.signal })。abort() 会让 fetch 抛出 AbortError，在 catch 中判断 e.name === "AbortError" 区分超时取消和真正的网络错误。场景：搜索框输入快速变化时取消上一个请求、页面跳转时取消未完成请求。
</Answer>

**问题 2**：localStorage/sessionStorage/IndexedDB 如何选型？Web Worker 解决了什么问题？

<Answer>
三者选型：localStorage——持久存储（手动清除才消失），同源共享，同步 API，约 5-10MB，适合存 Token、用户配置等小数据；sessionStorage——会话级（标签页关闭清除），不跨标签页共享，同步 API，适合存临时会话状态如未提交的表单；IndexedDB——异步事务型 NoSQL 数据库，容量大（数百 MB+），能存对象/文件/Blob 不需序列化，异步不阻塞主线程，适合存大量结构化数据如离线缓存、聊天记录。原则：小而持久用 localStorage，小而临时用 sessionStorage，大而结构化用 IndexedDB。Web Worker 解决 JavaScript 单线程下 CPU 密集计算阻塞 UI 的问题：加密、图像处理、大数据排序等在主线程跑会卡死页面交互。Worker 在独立线程运行这些计算，通过 postMessage 传结果回主线程更新 UI。Worker 不能操作 DOM（只有主线程能），数据通过结构化克隆传递（复制非共享）。SharedWorker 跨标签页共享，Service Worker 做离线缓存。
</Answer>
</Exercises>
