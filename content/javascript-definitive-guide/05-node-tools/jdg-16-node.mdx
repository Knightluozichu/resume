## 本章定位

<Term def="Node 把 JavaScript 接到进程、缓冲区、事件、流、文件、网络、子进程和工作线程；异步 I/O、背压和资源生命周期是服务端正确性的核心。">Buffer</Term> 是本章的入口观察量。Node 把 JavaScript 接到进程、缓冲区、事件、流、文件、网络、子进程和工作线程；异步 I/O、背压和资源生命周期是服务端正确性的核心。 这意味着阅读不能停在 API 名称或最终打印值，而要回答：输入何时进入、值或对象怎样变化、控制权在哪里转移、错误如何传播、宿主资源由谁清理。

## 六阶段机制链

### 1. 启动 Node 进程与模块

固定源码、运行环境和输入，在动作发生前记录可见绑定、值类型、对象身份、待处理任务和已打开资源。若起点不稳定，后续比较没有意义。

### 2. 接收事件或 I/O

只执行本阶段最小动作，记录它读取了什么、写入了什么，以及控制权交给语言运行时还是浏览器、Node 或工具链。

### 3. 在 Buffer 与流中传输数据

检查抽象规则是否被真正满足。不要用最终输出反推过程；对象引用、隐式转换、短路与异步调度都可能产生表面相同的结果。

### 4. 处理背压和文件状态

在边界值、重复输入、迟到结果和错误宿主状态下重放。保存第一个与正常轨迹不同的位置，而不是只保存最后一条异常。

### 5. 调用网络、子进程或工作线程

让失败沿规定通道传播，并核对调用者是否能区分可重试、应停止和必须降级的情况。静默吞错不能作为恢复策略。

### 6. 关闭句柄并报告结果

修复单一故障后重放完全相同的输入。只有绑定、值、任务、句柄和生成产物都回到可预测状态，本章才可以签发。
