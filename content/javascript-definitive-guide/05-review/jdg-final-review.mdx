## 直觉引入

走到这里，你已经爬完了《JavaScript权威指南》的四层知识。单独看每一层都不难，真正考验功力的是把它们串起来——因为真实代码从不只用一层。一个按钮点击的处理函数里 `await fetch` 拿数据、用 `Map` 缓存、用 Proxy 做响应式追踪、用闭包封装状态、用事件委托减少监听器、用 Worker 处理大数据——四层知识在一行代码里交叉。总复习的任务，就是用「运行时旅程」这个枢纽把四层连成一张网，让你面对任意一段代码时，能从「源码字符如何解析、类型如何求值、函数如何封装、数据如何加工、网页如何响应」的视角，精确解释它从输入到输出的完整链路。

## 四层知识图谱

<Term def="运行时旅程是 JavaScript 代码从源码字符到网页响应的完整链路：词法解析（字符→token→语句）→ 类型求值（原始/引用/转换）→ 函数封装（this/闭包/模块）→ 数据加工（数组/集合/元编程）→ 网页响应（DOM/事件/Fetch/Worker）。四层知识在这条链路上各司其职。">运行时旅程</Term>是四层知识的交汇点。**语言核心**回答「字符如何组成程序、数据如何表示」——ASI 决定语句边界、七种原始类型按值访问、类型转换由抽象操作驱动。**函数抽象**回答「行为如何封装、代码如何组织」——this 由调用点绑定、闭包延续作用域、class 是原型链语法糖、ESM 静态分析支持 tree-shaking。**标准库与元编程**回答「数据如何高效加工、语言行为能否改写」——数组方法分纯函数与副作用、Map/Set 提供有序集合、Proxy/Reflect 拦截并转发操作。**Web 平台**回答「代码如何与网页世界交互」——事件流三阶段传播、委托利用冒泡减负、Fetch 是 Promise 化请求、Worker 卸载 CPU 密集计算。

```javascript
// 一段同时动用四层知识的代码：你能解释每一层的作用吗？
import { fetchData } from "./api.js"; // 【函数抽象】ESM 静态 import

class DataManager { // 【函数抽象】class 语法糖，方法在原型上
  #cache = new Map(); // 【标准库】Map 集合 + # 私有字段

  constructor(endpoint) {
    this.endpoint = endpoint; // 【语言核心】字符串原始类型
  }

  async load(id) { // 【函数抽象】async 返回 Promise
    if (this.#cache.has(id)) return this.#cache.get(id); // 【标准库】Map 查询
    const res = await fetch(`${this.endpoint}/${id}`); // 【Web 平台】Fetch 请求
    if (!res.ok) throw new Error(`HTTP ${res.status}`); // 【Web 平台】手动检查状态
    const data = await res.json(); // 【语言核心】对象引用类型
    this.#cache.set(id, data); // 【标准库】Map 存储
    return data;
  }
}

document.addEventListener("click", async (e) => { // 【Web 平台】事件委托在 document
  const item = e.target.closest(".item"); // 【Web 平台】精确匹配
  if (!item) return;
  const mgr = new DataManager("/api"); // 【函数抽象】new 绑定 this
  const data = await mgr.load(item.dataset.id); // 【函数抽象】闭包访问 #cache
  display.textContent = JSON.stringify(data); // 【语言核心】类型转换 + 【Web 平台】DOM 更新
});
// 四层在一组代码里全部参与：词法→类型→函数→标准库→Web
```

## 建立工程判断力

四层交叉的关键洞察：**词法是地基**（ASI 决定语句边界，省分号有时出错）→ **类型是数据的真相**（原始按值、对象按引用、转换有规则）→ **函数是抽象的工具**（this 调用点绑定、闭包延续作用域、模块静态分析）→ **标准库是工具箱**（Map 优于对象当字典、纯函数不改原数组、Proxy 改写默认行为）→ **Web 平台是舞台**（委托减负、Fetch 手动查状态、Worker 卸载计算）。判断力的标志：看到一段代码，能预判它的运行时行为和性能影响——知道闭包何时泄漏、this 何时丢失、展开何时是浅拷贝、Fetch 4xx 何时不进 catch、Worker 何时该用——而不是「跑一下才知道」。

## 常见误区

<Callout type="trap">
**误区：四层知识是独立的，分开学就行。** 真实代码从不分开用。一个 class 里的 async 方法访问 `this.#cache`（Map），同时涉及词法（class 不提升/TDZ）、类型（对象引用）、函数（async 返回 Promise、this 由调用点绑定、# 私有字段）、标准库（Map 集合）、Web 平面（fetch 请求、DOM 更新）。把它们当独立知识点背，遇到组合场景就解释不了。正确的学法是以「运行时旅程」为主线串联：每段代码先问「字符如何解析（ASI/标识符）」「类型如何求值（原始/引用/转换）」「函数如何封装（this/闭包/模块）」「数据如何加工（数组/集合/Proxy）」「网页如何响应（DOM/事件/Fetch/Worker）」——把这五问变成分析任意代码的固定套路，才算真正掌握 JavaScript。
</Callout>

<Exercises>
**问题 1**：用四层知识解释一段 `class { async load() { this.#cache = new Map(); ... await fetch(...) } }` 代码涉及哪些层。

<Answer>
这段代码同时动用四层：①语言核心——class 声明不提升（TDZ，先声明后用）、内部默认严格模式；字符串模板 `${this.endpoint}/${id}` 涉及类型转换；res.json() 返回对象是引用类型。②函数抽象——class 是原型链语法糖，方法 load 在原型上供实例共享；#cache 是私有字段（真私有，不在原型）；async load 返回 Promise，this 由调用点绑定（mgr.load() 时 this 指向 mgr，但若回调中 mgr.load 传参需防 this 丢失）。③标准库与元编程——new Map() 创建有序键值集合，has/get/set 操作 Map（优于对象当字典，任意键有序无原型干扰）。④Web 平台——fetch 发请求，4xx/5xx 不 reject 需手动检查 res.ok；document.addEventListener 事件委托，e.target.closest 精确匹配；textContent 更新 DOM。四层在一组代码里全部参与，分开学无法解释整体行为。
</Answer>

**问题 2**：什么是「运行时旅程」？为什么它是串联全书的主线？

<Answer>
运行时旅程是 JavaScript 代码从源码字符到网页响应的完整链路：词法解析（Unicode 文本→token→语句，ASI 决定边界）→ 类型求值（七种原始类型按值、对象按引用、类型转换由抽象操作驱动）→ 函数封装（四种定义形式、this 调用点绑定、闭包延续作用域、class 语法糖、ESM 静态 import）→ 数据加工（数组纯函数/副作用、Map/Set 集合、Proxy/Reflect 元编程）→ 网页响应（事件流三阶段、委托减负、Fetch Promise 请求、Storage 存储、Worker 多线程）。它是串联全书的主线，因为真实代码的每一次交互都走完这条链路：用户点击→事件监听（Web）→闭包捕获上下文（函数）→async 发请求（Web+函数）→数据处理（标准库）→类型转换（语言核心）→DOM 更新（Web）。以这条链路为主线，十章知识点不再是孤立的 API 列表，而是从「字符到网页」的完整工程能力——这才是《JavaScript 权威指南》作为「权威指南」的价值所在。
</Answer>
