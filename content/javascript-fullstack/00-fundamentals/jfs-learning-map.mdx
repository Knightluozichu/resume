## 直觉引入

把一个全栈应用想象成一家餐厅。前端是前厅——菜单怎么展示、顾客怎么点单、上菜怎么呈现（React 组件与状态）；后端是厨房——订单怎么接、菜怎么做、多份订单怎么排队（Node.js 服务器与框架）；数据库是仓库——食材存哪、怎么取、怎么补货（MongoDB 与数据建模）；工程化是管理制度——卫生怎么检查、流程怎么标准化、分店怎么开（测试与部署）。本书回答的就是这些「从用户点击到数据落盘」的全栈工程问题。

## 五阶段递进

<Term def="JavaScript 全栈应用是以 React 为视图层、Node.js 为运行时、Express/Koa 为 Web 框架、MongoDB 为持久层、Jest/Docker 为工程保障的端到端分层体系。">JavaScript 全栈系统</Term>的学习可以拆成五个递进阶段。**前端基础**包括 React 核心概念与状态管理——它们解决「界面怎么渲染」和「状态怎么流动」，是用户可见层的地基。**后端服务**包括 Node.js 服务器与 Web 框架——它们决定「请求怎么处理」和「路由怎么分发」。**数据层**包括 MongoDB 与 GraphQL API——它们让应用「能存取」和「能查询」。**工程化**包括认证安全与测试部署——它们保障「能信任」和「能上线」。**总复习**串联全部知识点。

```javascript
// 一次「用户提交表单 → 存入数据库 → 返回结果」的全栈旅程
// 1. 前端：React 组件捕获表单提交，状态驱动 UI
function CheckoutForm() {
  const [order, setOrder] = useState(null); // 状态管理（第 2-3 章）
  const handleSubmit = async (e) => {
    e.preventDefault();
    // 2. 后端：fetch 发请求到 Node.js 服务器
    const res = await fetch("/api/orders", { // async/await（第 4-5 章）
      method: "POST",
      headers: { Authorization: `Bearer ${token}` }, // 认证（第 8 章）
      body: JSON.stringify(formData),
    });
    // 3. 数据层：服务器写入 MongoDB，返回持久化结果
    const data = await res.json(); // Mongoose + GraphQL（第 6-7 章）
    setOrder(data);
  };
  return <form onSubmit={handleSubmit}>{/* React 渲染（第 2 章） */}</form>;
}

// 4. 工程化：上述接口被 Jest 测试覆盖、Docker 打包、CI/CD 部署（第 9 章）
// 5. 总复习：从点击到落盘的完整链路复盘（第 10 章）
```

## 常见误区

<Callout type="trap">
**误区：会写前端就等于会全栈。** 前端只是用户可见的冰山一角——组件怎么写、样式怎么调，照着文档抄就能做出页面。真正的全栈难点在端到端：状态如何在前后端同步、请求如何鉴权、数据库如何建模、并发如何处理、部署如何自动化。这些是「前后端协作时」才显现的工程问题，也是全栈面试与生产实战的真正考点。把前端当终点的人，做出的应用能看但不能用；把全栈当核心的人，才能做出可控、可扩展、可上线的完整产品。
</Callout>

<Exercises>
**问题 1**：全书五阶段是什么？为什么是这个顺序？

<Answer>
前端基础（React/状态管理）→ 后端服务（Node.js/Web 框架）→ 数据层（MongoDB/GraphQL）→ 工程化（认证安全/测试部署）→ 总复习。顺序由数据流决定：用户先看到前端，前端发请求到后端，后端读写数据层，工程化保障整条链路可信可上线。先有「能看」，再有「能处理」，然后「能存取」，接着「能保障」，最后「能复盘」。跳过前端直接学后端会脱离用户视角；跳过后端直接学数据库会脱离请求上下文。
</Answer>

**问题 2**：为什么 JavaScript 能用同一种语言同时写前端和后端？

<Answer>
JavaScript 的宿主环境决定了它的能力边界：浏览器提供 DOM API 让 JS 操作页面，Node.js 提供 fs/http 模块让 JS 操作文件系统和网络。两者共享同一套语言核心（ECMAScript 规范——类型、函数、Promise、模块），但运行时 API 不同。这种「同语言、不同运行时」的设计让开发者只需学一套语法，就能在前后端复用逻辑（如表单校验、数据转换），降低了全栈心智成本。代价是前后端的并发模型、模块系统、API 仍有差异，需要理解运行时区别。
</Answer>

<GlossaryItem term="五阶段递进">前端基础（React/状态管理）→ 后端服务（Node.js/Web 框架）→ 数据层（MongoDB/GraphQL）→ 工程化（认证安全/测试部署）→ 总复习。每层解决前一层的遗留问题：前端能渲染但不能处理请求，后端补处理；后端能处理但不持久，数据层补存取；数据层能存取但不可信，工程化补保障。</GlossaryItem>
