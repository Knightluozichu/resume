## 边界记录模板

每次实验都建立一行六列证据：**输入快照、当前阶段、语言状态、宿主资源、首个偏离点、恢复结果**。语言核心章节要展开变量绑定、对象身份和调用栈；浏览器章节要增加节点连接状态、事件监听数量、网络请求与页面地址；Node.js 章节要增加请求流、响应是否结束、文件或数据库连接和事务状态。执行“创建脚本入口”前先写预测，经过“建立变量绑定”后只比较一项受控变化，到“用练习验证边界”时重放同一输入。若最终值相同但对象、任务、监听器、流或连接数量不同，仍判定失败；若异常被捕获但部分状态已经提交，也不能签发。这个模板把 API 记忆转换成可复查的因果链，并让正常、边界、失败和恢复样本可以逐列对照。

## 最小可运行实验

```javascript
const prices = [19, 8, 27, 12];
let total = 0;
for (const price of prices) {
  if (!Number.isFinite(price) || price < 0) continue;
  total += price;
}
console.log({ total, average: total / prices.length });
```

## 四类样本与验收

| 样本 | 注入方式                         | 必查证据                         | 通过条件                   |
| ---- | -------------------------------- | -------------------------------- | -------------------------- |
| 正常 | 合法输入与单次执行               | 值、对象、调用点、任务、宿主资源 | 六阶段按预期完成           |
| 边界 | 空值、极值、重复输入、慢 I/O     | 类型与协议边界、停止条件         | 不发生隐式越界或重复提交   |
| 失败 | 错误参数、拒绝、断流、数据库失败 | 首个偏离点与错误通道             | 明确停止、传播或回滚       |
| 恢复 | 清除故障后重放相同输入           | 清理后的状态与资源数             | 无旧任务、监听器、流和连接 |

本页签发不变量是：**程序先把值绑定到变量，再由表达式产生新值，最后由语句组织执行顺序；作用域、类型转换、优先级和控制流必须在每一步显式可解释。** 单次输出、截图或一次请求成功不能替代值语义、对象身份、控制流、任务顺序和宿主资源的完整轨迹。
