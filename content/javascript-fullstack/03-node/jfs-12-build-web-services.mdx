## 边界记录模板

每次实验都建立一行六列证据：**输入快照、当前阶段、语言状态、宿主资源、首个偏离点、恢复结果**。语言核心章节要展开变量绑定、对象身份和调用栈；浏览器章节要增加节点连接状态、事件监听数量、网络请求与页面地址；Node.js 章节要增加请求流、响应是否结束、文件或数据库连接和事务状态。执行“监听 TCP 端口”前先写预测，经过“选择方法和路径”后只比较一项受控变化，到“结束响应并记录耗时”时重放同一输入。若最终值相同但对象、任务、监听器、流或连接数量不同，仍判定失败；若异常被捕获但部分状态已经提交，也不能签发。这个模板把 API 记忆转换成可复查的因果链，并让正常、边界、失败和恢复样本可以逐列对照。

## 最小可运行实验

```javascript
import { createServer } from "node:http";

const server = createServer((request, response) => {
  if (request.method === "GET" && request.url === "/health") {
    response.writeHead(200, {
      "content-type": "application/json; charset=utf-8",
    });
    response.end(JSON.stringify({ ok: true }));
    return;
  }
  response.writeHead(404, { "content-type": "text/plain; charset=utf-8" });
  response.end("not found");
});

server.listen(3000);
```

## 常见误区与故障注入

  端口”到“结束响应并记录耗时”的过程。**
  相同输出可能来自不同对象别名、任务顺序、DOM 状态、HTTP

## 四类样本与验收

| 样本 | 注入方式                         | 必查证据                         | 通过条件                   |
| ---- | -------------------------------- | -------------------------------- | -------------------------- |
| 正常 | 合法输入与单次执行               | 值、对象、调用点、任务、宿主资源 | 六阶段按预期完成           |
| 边界 | 空值、极值、重复输入、慢 I/O     | 类型与协议边界、停止条件         | 不发生隐式越界或重复提交   |
| 失败 | 错误参数、拒绝、断流、数据库失败 | 首个偏离点与错误通道             | 明确停止、传播或回滚       |
| 恢复 | 清除故障后重放相同输入           | 清理后的状态与资源数             | 无旧任务、监听器、流和连接 |
