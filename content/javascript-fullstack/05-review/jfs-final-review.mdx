## 全栈请求生命周期复盘

<Term def="全栈请求生命周期是用户操作从前端触发、经网络到后端、读写数据层、再返回前端渲染的完整闭环；每个环节都有对应的框架、性能与安全考量，全栈工程师需能在整条链路上定位问题。">全栈请求生命周期</Term>是本书的主线。

```javascript
// 一次购买请求的完整旅程，标注每章知识点
// === 前端（第 2-3 章）===
function BuyButton({ product }) {
  const [state, setState] = useState("idle"); // 本地状态
  const cart = useCartStore();                // 全局状态（第 3 章）
  const handleBuy = async () => {
    setState("loading");
    // === 后端请求（第 4-5 章）===
    const res = await fetch("/api/orders", {
      method: "POST",
      headers: { Authorization: `Bearer ${token}` }, // 认证（第 8 章）
      body: JSON.stringify({ productId: product.id }),
    });
    if (!res.ok) setState("error");          // 错误处理
    // === 数据层（第 6-7 章）===
    const order = await res.json();           // 后端已写 MongoDB + GraphQL 返回
    cart.add(order);
    setState("success");
  };
  return <button onClick={handleBuy}>{/* 虚拟 DOM 渲染（第 2 章） */}</button>;
}

// === 后端（第 4-5 章）=== Node.js + Express
app.post("/api/orders", authMiddleware, async (req, res) => {
  // 事件循环非阻塞处理（第 4 章）
  const order = await Order.create({ ...req.body, userId: req.user.id }); // Mongoose（第 6 章）
  res.json(order); // 响应流式写出
});

// === 工程化（第 8-9 章）=== 上述链路被 Jest 测试、Docker 打包、CI/CD 部署
```

## 全栈架构判断力

| 决策点 | 选项 | 取舍 |
|--------|------|------|
| 状态管理 | useState / Context / Zustand / Redux | 本地够用就不上全局；高频细粒度用 selector 库 |
| Web 框架 | Express / Koa / Fastify | 快速原型 Express；优雅中间件 Koa；高性能 Fastify |
| 数据建模 | 嵌入 / 引用 | 一起读用嵌入；独立共享用引用 |
| API 风格 | REST / GraphQL | 简单固定缓存优先 REST；多端按需 GraphQL |
| 认证 | Session / JWT | 有状态易吊销用 Session；无状态易扩展用 JWT |

## 常见误区

<Callout type="trap">
**误区：全栈就是前后端都会写。** 会写只是入门。真正的全栈判断力在于「整条链路的取舍」：知道前端的某个状态方案会如何影响后端 API 设计；知道数据库的建模方式如何决定前端请求次数；知道认证方案如何影响水平扩展；知道测试分层如何影响迭代速度。能独立完成全链路的人是「全栈工程师」；只会拼凑各层代码的是「全栈搬运工」。区分标志：遇到性能问题，能否从浏览器到数据库逐层定位而非只会说「前端慢」或「后端慢」。
</Callout>

<Exercises>
**问题 1**：用全栈请求生命周期描述一次「用户下单」的完整旅程，标注每章知识点。

<Answer>
①前端：用户点击购买，React 事件触发（第 2 章），useState 更新 loading 状态驱动 UI 重渲染，购物车全局状态用 Zustand/Redux 管理（第 3 章）；②网络：fetch 发 POST 到后端，header 带 JWT Bearer token（第 8 章），async/await 不阻塞主线程；③后端：Node.js 事件循环接收请求（第 4 章），Express/Koa 中间件链先验签 JWT（第 8 章）再进路由（第 5 章）；④数据层：Mongoose 校验并写入 MongoDB（第 6 章），如用 GraphQL 则 Resolver 编排数据 + DataLoader 防 N+1（第 7 章）；⑤响应：后端 JSON 返回，前端 setState 更新 UI；⑥工程化：整条链路被 Jest 单元+集成测试覆盖，Docker 多阶段构建打包，CI/CD 自动部署（第 9 章）。一环断则全链断。
</Answer>

**问题 2**：列表页加载缓慢，作为全栈工程师你会如何逐层排查？

<Answer>
分层定位而非盲猜：①前端——React DevTools Profiler 看是否有无谓重渲染、useEffect 是否死循环、列表是否缺 key 导致全量重渲染（第 2-3 章）；②网络——DevTools Network 看请求耗时、是否 N+1（一个列表页发了几十个请求）、payload 是否过度获取（第 7 章 GraphQL/REST）；③后端——Node 日志看接口响应时间、事件循环是否被 CPU 密集任务阻塞、中间件是否有同步重逻辑（第 4-5 章）；④数据库——MongoDB explain 看查询是否走索引、是否缺索引导致全表扫描、populate 是否 N+1（第 6 章）；⑤部署——服务器 CPU/内存是否打满、Docker 容器是否资源受限（第 9 章）。先量化（哪个环节慢）再优化，避免「感觉前端慢」式盲改。
</Answer>
</Exercises>
