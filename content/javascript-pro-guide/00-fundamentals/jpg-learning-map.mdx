## 直觉引入

把 JavaScript 程序想象成一栋大楼。你先要打地基——数据有哪些类型、变量怎么声明、作用域怎么划分（语言基础）；然后立柱子——对象怎么造、属性怎么定义、原型怎么复用（对象与原型）；接着拉电线——异步操作怎么排队、回调怎么调度（异步模型）；再装门窗——页面怎么操作、浏览器环境怎么用（DOM 与 BOM）；最后做装修——代码怎么拆分打包、模块怎么加载（模块系统）。本书回答的就是这些「从语法到运行时」的 JavaScript 工程问题。

## 五阶段递进

<Term def="JavaScript 运行时是以单线程事件循环为调度核心、通过原始与引用类型组织数据、用原型链实现对象复用、靠 Promise 与事件循环处理异步、经 DOM/BOM 与浏览器交互、以模块系统组织代码的分层体系。">JavaScript 运行时系统</Term>的学习可以拆成五个递进阶段。**语言基础**包括数据类型与变量、作用域与闭包——它们解决「数据怎么存」和「变量在哪可见」，是所有上层逻辑的基底。**对象与原型**包括对象创建、属性特征、原型链——它们决定「数据怎么组织」和「行为怎么复用」。**异步模型**包括 Promise/async 和事件循环——它们让程序「能等待」和「能调度」。**浏览器与模块**包括 DOM/BOM 操作和模块系统——它们连接「代码与世界」和「代码与代码」。**总复习**串联全部知识点。

```javascript
// 一次「点击按钮 → 发请求 → 更新页面」的完整 JS 运行时旅程
btn.addEventListener("click", async () => {
  // 1. 语言基础：箭头函数形成闭包，捕获 btn 与 display
  const format = (d) => JSON.stringify(d, null, 2); // 闭包 + 箭头函数

  // 2. 异步模型：await 暂停函数，事件循环调度回调
  const data = await fetchData(); // Promise + async/await（第 6-7 章）

  // 3. 对象与原型：data 是对象，继承自 Object.prototype
  const text = format(data); // toString / JSON 方法来自原型链（第 4-5 章）

  // 4. 浏览器：DOM 更新触发重排重绘
  display.textContent = text; // DOM API（第 8 章）
});

// 5. 模块系统：fetchData 从别的文件 import 进来（第 9 章）
// import { fetchData } from "./api.js";  // ESM 静态加载
```

## 常见误区

<Callout type="trap">
**误区：会写 JavaScript 语法就等于懂 JavaScript。** 语法只是表层——`let`/`const` 怎么写、函数怎么定义，这些照着文档抄就会。真正的难点在运行时：变量为什么提升、闭包为什么不释放内存、`this` 到底指向谁、Promise 为什么比回调先执行、原型链查找的代价、事件循环的微任务宏任务顺序。这些是「代码跑起来之后」才显现的机制，也是中高级面试与工程实战的真正考点。把语法当终点的人，写出的代码能跑但脆弱；把运行时当核心的人，才能写出可控、可维护、高性能的 JavaScript。
</Callout>

<Exercises>
**问题 1**：全书五阶段是什么？为什么是这个顺序？

<Answer>
语言基础（类型/变量/作用域/闭包）→ 对象与原型（对象/OOP/原型链）→ 异步模型（Promise/事件循环）→ 浏览器与模块（DOM/BOM/ESM）→ 总复习。顺序由依赖关系决定：上层依赖下层。没有类型与作用域就没有变量；没有对象就没有数据组织；没有异步模型就处理不了 I/O；没有 DOM/BOM 就和浏览器无关；没有模块系统代码就无法规模化。先有「能存」，再有「能组织」，然后「能等待」，接着「能交互」，最后「能拆分」。
</Answer>

**问题 2**：为什么 JavaScript 是单线程，却能处理高并发的异步 I/O？

<Answer>
JavaScript 的执行线程是单线程（只有一个调用栈），但它的宿主环境（浏览器/Node）是多线程的。当遇到 setTimeout、fetch 等异步操作时，JS 引擎把实际工作交给浏览器的 Web API 线程处理，自己继续执行同步代码不阻塞。等 Web API 完成后，把回调推入任务队列；当调用栈清空时，事件循环从队列取出回调执行。这种「单线程执行 + 多线程 I/O + 事件循环调度」的模型，让 JS 既避免了多线程同步复杂度，又能高效处理并发 I/O。代价是 CPU 密集任务会阻塞主线程，需要用 Worker 拆分。
</Answer>
