## 机制拆解

### 1. 传参仍是按值

传递原始值会复制标量，传递对象会复制引用值；函数能修改引用指向的对象，却不能通过重新赋参改变调用方绑定。用对象图而非“按引用传递”口号解释，边界会更清晰。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 作用域来自书写位置

函数在定义时捕获外层词法环境，不按调用位置动态查找。with与直接eval会让解析难以静态判断，应避免；块级声明则让临时变量的生命范围更精确。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 垃圾回收不等于没有泄漏

只要监听器、定时器、缓存或闭包仍从根可达，对象就不会被回收。组件销毁时应注销外部订阅、取消任务并清空无界缓存，用堆快照比较保留路径而非只看总内存。

function mutate(record) {
  record.count += 1;
  record = { count: 0 };

const state = { count: 0 };
mutate(state);
