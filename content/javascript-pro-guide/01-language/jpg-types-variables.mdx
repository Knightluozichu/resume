## 直觉引入

把变量想象成贴着标签的盒子。原始类型的盒子里直接装着值本身——你把盒子复制给别人，别人拿到的是一个新盒子装着同样的值，改自己的不影响对方。引用类型的盒子里装的不是对象本身，而是一张写着「对象在仓库哪个货架」的地址条——你把地址条复制给别人，两人找的是同一个货架上的同一件物品，谁改了对方都看得到。这就是「值传递」与「引用传递」（实为按引用的值传递）的本质区别。

## 类型与内存模型

<Term def="原始类型是直接存储在栈中的简单数据段，包括 Undefined、Null、Boolean、Number、String、Symbol、BigInt 七种，复制时拷贝值本身；引用类型是存储在堆中的对象，变量保存的是指向堆内存的地址，复制时拷贝地址而非对象。">原始类型与引用类型</Term>的区分是 JS 类型系统的根基。原始类型共七种，它们不可变（字符串看似可改实则每次操作返回新串）。引用类型只有一种——Object，但数组、函数、日期、正则都是它的衍生。`typeof` 能区分原始类型与函数，但 `typeof null === "object"` 是历史遗留 bug；`instanceof` 沿原型链判断，只能检测引用类型。

```javascript
// 原始类型：复制 = 拷贝值
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 —— a 不受影响

// 引用类型：复制 = 拷贝地址
let obj1 = { count: 1 };
let obj2 = obj1;
obj2.count = 99;
console.log(obj1.count); // 99 —— 同一对象，互相可见

// typeof 的边界
typeof undefined; // "undefined"
typeof null;      // "object"（历史 bug，非 "null"）
typeof function(){}; // "function"
typeof [];        // "object"（数组无法用 typeof 区分）
[] instanceof Array; // true（引用类型用 instanceof）

// Number 的精度陷阱
0.1 + 0.2 === 0.3; // false —— IEEE 754 双精度浮点
(0.1 + 0.2).toFixed(2); // "0.30" —— 用 toFixed 或 BigInt 处理
9007199254740992 + 1 === 9007199254740992; // true —— 超出安全整数
9007199254740993n + 1n; // 9007199254740994n —— BigInt 任意精度
```

## let / const / var 三者差异

`var` 是 ES5 的遗留声明，有函数作用域、变量提升、可重复声明三大缺陷。`let`/`const` 是 ES6 引入的块级作用域声明，存在**暂时性死区（TDZ）**——在声明语句执行前访问会抛 ReferenceError，而非像 var 那样得到 undefined。`const` 声明的是不可重新绑定的绑定（binding），但绑定的对象本身仍可修改内部属性。

```javascript
// var 的问题：提升 + 函数作用域 + 重复声明
console.log(x); // undefined（已提升，非报错）
var x = 1;
var x = 2; // 合法但危险

if (true) {
  var y = 3;
}
console.log(y); // 3 —— var 泄漏到函数/全局

// let/const：块级作用域 + TDZ
// console.log(z); // ReferenceError: Cannot access 'z' before initialization
let z = 1;

if (true) {
  let w = 4;
}
// console.log(w); // ReferenceError —— w 仅在块内可见

// const 冻结绑定不冻结内容
const obj = { x: 1 };
// obj = {}; // TypeError —— 不能重新绑定
obj.x = 2; // 合法 —— 对象内容可改
Object.freeze(obj); // 真正冻结内容（浅冻结）
```

## 常见误区

<Callout type="trap">
**误区：const 声明的对象就不能改了。** `const` 冻结的是「变量到值的绑定」，不是「值本身」。对 `const obj = {x:1}`，你不能写 `obj = {}`（重新绑定），但 `obj.x = 2` 完全合法，因为对象内部属性没被 const 保护。要真正冻结对象内容，需用 `Object.freeze(obj)`，且它是浅冻结——嵌套对象仍可改。工程上默认用 const 表达「这个引用不会重新指向」，需要重新赋值才用 let，var 一律禁用。
</Callout>

<Exercises>
**问题 1**：原始类型和引用类型在赋值和传参时有什么本质区别？

<Answer>
原始类型（Undefined/Null/Boolean/Number/String/Symbol/BigInt）按值赋值：复制时创建一份独立的值副本，修改副本不影响原变量。引用类型（Object 及其衍生）按「引用的值」赋值：变量存的是堆中对象的地址，复制时拷贝的是地址，两个变量指向同一个堆对象，任一方修改属性另一方可见。函数传参同理——传原始类型拷贝值，传对象拷贝地址（所以在函数内改对象属性会影响外部，但重新赋值参数不影响外部）。JS 没有真正的「按引用传递」，只有「按值传递」，只是对象的「值」是地址。
</Answer>

**问题 2**：什么是暂时性死区（TDZ）？它和 var 的提升有什么区别？

<Answer>
暂时性死区（Temporal Dead Zone）指 let/const 声明的变量从作用域开始到声明语句执行之间的区域。在这个区域内访问变量会抛 ReferenceError，而非像 var 那样返回 undefined。var 的提升是把声明提到作用域顶部并初始化为 undefined，所以提升后可访问（值为 undefined）；let/const 也会提升，但不会被初始化，处于 TDZ 中不可访问。TDZ 的价值是强制「先声明后使用」，避免 var 时代「先用后声明得到 undefined」导致的隐蔽 bug。这也意味着 typeof 不再安全——`typeof x`（x 在 TDZ 内）也会报错。
</Answer>

<Glossary>
<GlossaryItem term="原始类型">直接存栈、按值访问的七种简单数据：Undefined、Null、Boolean、Number、String、Symbol、BigInt。复制时拷贝值本身，互不影响；不可变（对字符串的操作返回新串而非原地改）。</GlossaryItem>
<GlossaryItem term="引用类型">存堆、按引用访问的 Object 及衍生（数组、函数、日期、正则等）。变量保存堆地址，复制时拷贝地址，共享同一对象。typeof 只能返回 "object"/"function"，具体类型用 instanceof 或 Array.isArray 判断。</GlossaryItem>
<GlossaryItem term="暂时性死区（TDZ）">let/const 声明的变量在作用域开始到声明语句之间的区域，访问会抛 ReferenceError。与 var 的提升不同——var 提升后初始化为 undefined 可访问，let/const 提升但不初始化不可访问。强制先声明后使用。</GlossaryItem>
<GlossaryItem term="const 绑定">const 声明的是不可重新绑定的绑定（binding），即变量名不能再指向别的值；但若绑定的是对象，对象内部属性仍可修改。需 Object.freeze 才能冻结内容，且为浅冻结。</GlossaryItem>
</Glossary>
