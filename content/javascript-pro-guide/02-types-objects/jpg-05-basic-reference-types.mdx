## 机制拆解

### 1. 时间点与日历表示分开

Date内部是时间戳，但构造和格式化会受时区影响。协议传输应使用明确时区的ISO表示或时间戳，业务日历还要单独处理时区、夏令时和仅日期语义。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 全局正则带lastIndex状态

带g或y标志的RegExp在test与exec之间更新lastIndex，共享实例会让相同输入得到不同结果。迭代匹配时显式管理状态，单次验证可避免全局标志或每次创建实例。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 不要显式创建包装对象

new Boolean(false)是对象，因此在条件中为真；原始字符串调用方法时的自动装箱是短暂规范行为。API应返回原始值，类型检查也要区分typeof与instanceof。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 常见误区与故障注入

<Callout type="trap">
  **误区一：用本地时间字符串跨系统传输日期，部署到不同时区后偏移。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：复用带g标志的正则做验证，lastIndex让奇数次与偶数次结果不同。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **Date**：以自UTC纪元起毫秒数保存时间点并提供本地与UTC视图的内置对象。
- **RegExp**：封装正则模式、标志和匹配状态的内置引用类型。
- **包装对象**：临时或显式把原始值包装成Boolean、Number或String对象的引用类型。
- **Global对象**：规范中承载全局函数、常量和构造器、在宿主中映射为全局对象的抽象。
- **Math**：提供无实例状态的数学常量和数值运算函数的单例内置对象。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
