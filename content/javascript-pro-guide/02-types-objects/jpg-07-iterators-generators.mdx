## 机制拆解

### 1. 协议比循环语法更基础

for-of、扩展运算符和Array.from都先请求Symbol.iterator，再反复调用next。自定义集合只要实现协议即可接入这些消费者，同时必须决定重复迭代是创建新游标还是共享状态。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 生成器是显式暂停状态机

生成器函数调用时不执行正文，第一次next才进入；yield把局部变量和指令位置一起保存。next传值、throw注入异常、return提前结束构成三种恢复通道，适合建模惰性序列和协作流程。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 资源迭代需要return

读取文件、游标或订阅的迭代器若被break提前终止，应通过return释放资源。生成器的finally可承接这一责任；测试要主动提前退出，而不是只验证自然耗尽。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
function* range(end) {
  try {
    for (let i = 0; i < end; i += 1) yield i;
  } finally {
    console.log("closed");
  }
}
for (const value of range(3)) {
  if (value === 1) break;
}
```

## 常见误区与故障注入

## 小结

- **可迭代协议**：对象通过Symbol.iterator返回迭代器、从而可被for-of等语法消费的契约。
- **迭代器协议**：next返回包含value与done结果对象、可选return负责提前清理的契约。
- **生成器**：调用后返回生成器对象、执行可在yield处暂停和恢复的特殊函数。
- **yield**：在生成器中产出值并暂停执行、下次恢复时接收输入的表达式。
- **提前终止**：消费者停止迭代时通过return通知生产者执行清理的协议路径。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
