## 机制拆解

### 1. 属性不只有键和值

访问器属性可计算或验证状态，数据属性的可写、可枚举与可配置标志决定反射行为。Object.defineProperty默认缺失标志为false，批量定义前要明确每项契约。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 继承是对象间委托

构造函数的prototype成为实例原型，属性查找沿链向上。组合继承等旧模式要处理父构造重复调用；现代class extends与super简化写法，但实例方法仍位于原型上。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 私有状态与实例共享要分开

写在构造函数里的函数每个实例一份，原型方法由实例共享；闭包私有变量会改变内存和调试特性。选择封装方式时要同时考虑身份检查、序列化、子类扩展与方法共享。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
class Counter {
  #value = 0;
  increment() {
    this.#value += 1;
    return this.#value;
  }
}
const a = new Counter();
const b = new Counter();
console.assert(a.increment() === 1 && b.increment() === 1);
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：把class当成与原型无关的新对象模型，调试属性查找时失去路径。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：在共享原型上放可变数组，所有实例意外共享内容。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

| 样本 | 输入与环境变化                   | 预期状态       | 通过条件                     |

## 小结

- **属性描述符**：以value/get/set和writable/enumerable/configurable描述对象属性行为的记录。
- **原型**：对象在自身缺少属性时继续查找的另一个对象。
- **构造函数**：配合new创建对象、绑定原型并初始化实例状态的可调用对象。
- **原型链**：由对象的内部原型逐级连接形成的属性委托查找路径。
- **类**：为构造、原型方法、继承和静态成员提供统一语法的严格模式定义。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
