## 机制拆解

### 1. Reflect是正确默认路径

捕获器参数与Reflect同名方法对应，先调用Reflect保持目标默认语义，再叠加日志、验证或绑定。直接用target[prop]容易改变receiver和访问器this，从而破坏继承场景。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 不变式限制虚构能力

不可配置且不可写属性不能被get捕获器报告为另一个值，目标不可扩展时ownKeys不能遗漏或新增键。代理不是任意伪造对象；违反不变式会由引擎抛出TypeError。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 代理模式要控制身份与递归

代理不等于目标对象，严格相等和私有字段访问可能不同。在捕获器内操作代理自身会递归；元数据应放到外部WeakMap，并测试嵌套代理、撤销和错误堆栈。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const target = { count: 0 };
const proxy = new Proxy(target, {
  set(obj, key, value, receiver) {
    if (!Number.isFinite(value)) return false;
    return Reflect.set(obj, key, value, receiver);
  },
});
proxy.count = 2;
console.assert(target.count === 2);
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：捕获器内读取receiver[prop]，立即再次触发同一捕获器形成递归。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：ownKeys隐藏不可配置属性，直到运行时以TypeError失败。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **Proxy**：以目标对象和处理器创建、可拦截对象内部操作的代理对象。
- **捕获器**：处理器上对应get、set、ownKeys等内部操作的拦截方法。
- **Reflect**：提供与代理捕获器一一对应、返回更规则结果的反射方法集合。
- **捕获器不变式**：代理结果必须与目标不可配置属性、可扩展状态等事实保持一致的约束。
- **可撤销代理**：可通过revoke永久切断代理与目标访问能力的代理组合。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
