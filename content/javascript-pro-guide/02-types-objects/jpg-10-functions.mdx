## 机制拆解

### 1. 调用形式决定普通函数this

方法调用、独立调用、call/apply/bind与new有不同绑定规则；箭头函数则捕获外层this。把需要动态接收者的方法写成箭头属性，会改变原型共享和重绑定能力。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 参数是独立初始化作用域

默认参数从左到右求值，可以引用前面参数，但存在自己的暂时性死区。剩余参数是真数组，arguments是类数组且在严格模式不与形参联动；API应优先用显式参数对象表达可选项。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 闭包保留的是环境绑定

循环中使用let会为每次迭代创建绑定，var则共享函数绑定。闭包能实现私有状态和工厂，但也会延长环境中对象可达性；只捕获必要值，并为长期回调设计取消。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

function describe(prefix = "value", ...items) {

const bound = describe.bind(null, "items");

## 小结

- **箭头函数**：没有自身this、arguments、super和new.target、从词法环境捕获这些值的函数表达式。
- **arguments**：普通函数中表示实参数量与值的类数组对象。
- **this绑定**：由调用形式或显式绑定决定普通函数执行时接收者的规则。
- **闭包**：函数连同其定义位置可访问的词法环境形成的组合。
- **尾调用**：函数返回位置直接返回另一个调用结果、理论上可复用调用栈的调用形式。
