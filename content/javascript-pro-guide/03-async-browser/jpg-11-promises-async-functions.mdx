## 机制拆解

### 1. Promise解决控制反转与组合

执行器同步运行并只能落定一次，then处理器总异步调度且返回新Promise。处理器返回值会成为下游成功值，抛出异常则成为失败；忘记return会让链提前以undefined继续。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 聚合器表达失败策略

Promise.all适合全成功，allSettled保留每项结果，race取首次落定，any取首次成功。选择前先定义部分成功、失败后是否取消剩余工作和结果顺序，不能只看哪个API最短。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. await不等于串行或取消

连续await会顺序启动任务，先创建Promise再统一等待才能并发。AbortController、超时Promise和finally资源清理需显式接入；捕获错误后若无法恢复，应重新抛出保留失败语义。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 1000);
try {
  await fetch("/api/data", { signal: controller.signal });
} finally {
  clearTimeout(timeout);
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：then处理器启动异步工作却忘记return，下游过早完成。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：在循环里逐个await独立请求，把可并发任务无意串行化。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **Promise**：表示未来一次成功值或失败原因、状态一旦落定不再改变的对象。
- **微任务**：当前任务结束后、下一任务前清空的高优先级作业队列中的工作。
- **Promise链**：then、catch和finally返回新Promise并传递值或失败的组合流程。
- **async函数**：调用时总返回Promise、允许在函数体内使用await暂停逻辑流程的函数。
- **await**：等待值同化为Promise并在其落定后以微任务恢复async函数的表达式。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
