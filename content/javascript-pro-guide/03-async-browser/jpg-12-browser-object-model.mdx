## 机制拆解

### 1. window有双重身份

全局var可能成为window属性，但let与const不会；窗口关系还包括parent、top、opener和frame。跨源窗口只能执行受限操作，代码不应通过捕获跨源异常来猜测权限。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. URL与历史是应用状态边界

修改location会导航，history.pushState只新增同文档历史且不会自动触发popstate。路由器必须把URL、页面状态和滚动恢复绑定到同一版本，并对直接打开和前进后退保持一致。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 能力检测优于身份字符串

navigator.userAgent可以被简化或伪装，screen尺寸也不等于可用视口。需要剪贴板、分享或网络信息时直接检测目标API、权限与安全上下文，并为拒绝分支设计界面。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const state = { view: "details", id: 7 };
history.pushState(state, "", "/items/7");
window.addEventListener("popstate", (event) => console.log(event.state));
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：用screen宽度决定布局，忽略窗口、缩放和移动端可视视口。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：pushState后只更新URL不更新应用状态，前进后退出现分叉。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **window**：浏览器窗口全局对象，同时承载全局作用域和窗口控制接口。
- **location**：表示当前文档URL各组成部分并可触发导航的对象。
- **navigator**：提供浏览器身份、能力和设备相关信息入口的对象。
- **history**：表示当前标签页会话历史并支持同文档状态导航的对象。
- **视口**：页面当前可布局或可视的窗口区域，其尺寸受浏览器UI与缩放影响。
