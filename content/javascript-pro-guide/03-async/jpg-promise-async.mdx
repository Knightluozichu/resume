## 直觉引入

把 Promise 想象成餐厅的取餐呼叫器。你下单（创建 Promise）后拿到一个呼叫器（Promise 对象），此时状态是「等待中」（pending）——你不知道什么时候好。后厨做好了会按响呼叫器，要么亮绿灯「好了来取」（fulfilled，resolve），要么亮红灯「食材没了取消」（rejected，reject）。关键是一旦亮灯，状态就定了，不会再变——不会先绿灯又变红灯。你可以挂多个回调（then）在呼叫器上，亮灯时它们都会触发。async/await 则是让你写代码时像同步一样「等呼叫器响了再继续」，但底下仍是回调机制。

## Promise 三态与链式调用

<Term def="Promise 是表示异步操作最终完成（或失败）及其结果值的对象。有 pending（等待）、fulfilled（完成）、rejected（拒绝）三态，状态一经改变不可逆。通过 then/catch/finally 注册回调，支持链式调用——每个 then 返回新 Promise，实现串行异步流程编排。">Promise</Term>解决了回调地狱（callback hell）问题。三态不可逆是核心约束：pending → fulfilled 或 pending → rejected，且 fulfilled ↔ rejected 不可互转。链式调用的关键是 then 返回的是**新 Promise**：return 值会作为下一个 then 的参数，return Promise 会等待其落定，throw 会进入 catch。

```javascript
// 基础：三态
const p = new Promise((resolve, reject) => {
  setTimeout(() => resolve("done"), 1000);
});
p.then(v => console.log(v))   // "done"
 .catch(e => console.error(e))
 .finally(() => console.log("cleanup")); // 无论成败都执行

// 链式：then 返回新 Promise
fetch(url)
  .then(r => r.json())        // return Promise，链会等待
  .then(data => data.items)   // return 普通值，立即传下去
  .then(items => render(items))
  .catch(e => console.error("链中任一步抛错都到这里"))
  .finally(() => hideLoading());

// 组合器
Promise.all([p1, p2, p3])      // 全成功才成功，一个失败即失败（短路）
  .then(([a, b, c]) => ...);
Promise.race([p1, p2])         // 第一个落定（无论成败）即返回
Promise.allSettled([p1, p2])   // 等全部落定，返回每个的状态（不短路）
Promise.any([p1, p2])          // 第一个成功即返回，全失败才失败
```

## async/await 语法糖

<Term def="async/await 是基于 Promise 的语法糖。async 函数始终返回 Promise；await 暂停 async 函数执行直到 Promise 落定，期间不阻塞主线程（事件循环继续），落定后以值或抛错恢复。用同步风格写异步代码，错误用 try/catch 捕获。">async/await</Term>让异步代码看起来像同步。`async` 函数自动把返回值包装成 Promise；`await` 暂停当前 async 函数（不阻塞主线程），等 Promise 落定后恢复。错误用 try/catch 捕获，比 .catch() 更直观。但要注意：串行 await 会损失并发性能，需用 Promise.all 并行。

```javascript
// Promise 链写法
function fetchUser() {
  return fetch(url)
    .then(r => r.json())
    .then(data => data)
    .catch(e => { console.error(e); throw e; });
}

// async/await 等价写法（更直观）
async function fetchUser() {
  try {
    const r = await fetch(url);
    const data = await r.json();
    return data;
  } catch (e) {
    console.error(e);
    throw e;
  }
}

// 性能陷阱：串行 await 慢
async function slow() {
  const a = await fetchA(); // 1s
  const b = await fetchB(); // 1s —— 串行，共 2s
}
// 修复：并行
async function fast() {
  const [a, b] = await Promise.all([fetchA(), fetchB()]); // 共 1s
}
```

## 常见误区

<Callout type="trap">
**误区：await 会阻塞主线程，所以异步代码会卡住页面。** `await` 暂停的是**当前 async 函数**的执行，不是主线程。遇到 await 时，函数立即返回（交出控制权），主线程继续执行后续同步代码、处理其他事件。等 Promise 落定后，事件循环把「await 之后的代码」作为微任务排入队列，在当前同步代码和微任务清空后恢复执行。所以 await 期间页面完全可交互。真正阻塞主线程的是同步的 CPU 密集计算（如大循环、同步 JSON.parse 巨型字符串），这些要用 Web Worker 拆分，而非 await。
</Callout>

<Exercises>
**问题 1**：Promise 的三态为什么不可逆？这对工程有什么意义？

<Answer>
Promise 三态 pending → fulfilled/rejected 一经改变不可逆，fulfilled 与 rejected 不可互转。这个约束的意义：① 确定性——注册的回调（then/catch）只会被触发一次，且顺序确定，避免回调被多次调用或状态抖动导致的逻辑混乱；② 可组合——Promise.all/race 等组合器依赖状态的稳定性来正确聚合；③ 可缓存——已落定的 Promise 可安全传递，注册 then 总会拿到确定结果（已是终态不会再变）。不可逆让 Promise 成为可靠的异步值容器，这是它优于回调的根本——回调无法保证只触发一次、无法保证触发顺序。
</Answer>

**问题 2**：下面的串行 await 有什么性能问题？如何修复？

<Answer>
`const a = await fetchA(); const b = await fetchB();` 是串行的——fetchA 完成后才开始 fetchB，总耗时 = A + B。如果两者无依赖关系，这是浪费。修复：用 Promise.all 并行启动：`const [a, b] = await Promise.all([fetchA(), fetchB()])`，fetchA 和 fetchB 同时发出，总耗时 ≈ max(A, B)。注意 Promise.all 立即执行传入的所有 Promise（它们已被调用），然后 await 等待全部完成。原则：无依赖的异步操作应并行（Promise.all），有依赖的才串行 await。这是异步性能优化的核心。
</Answer>
</Exercises>

<GlossaryItem term="Promise 组合器">all（全成才成，一败即败，短路）、race（第一个落定即返回）、allSettled（全等，不短路，返回各状态）、any（第一个成功即返回，全败才败）。用于并行编排多个异步操作。</GlossaryItem>
