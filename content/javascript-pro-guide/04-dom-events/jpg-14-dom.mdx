## 机制拆解

### 1. 节点层级有结构约束

Document、Element、Text和Comment可拥有的父子关系不同，节点只能属于一个ownerDocument且同时只有一个父节点。插入已存在节点会移动它，不会复制；跨文档需要导入或收养。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 批量读写减少布局抖动

反复交替读取布局和写入样式会强制同步计算。先收集数据，再在DocumentFragment中构建，最后一次替换或插入；同时避免innerHTML接收未可信字符串。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 观察器是批处理通知

MutationObserver回调在变更后异步接收记录，多个修改可合并。配置要限定subtree、attributes与attributeFilter，处理完组件生命周期后disconnect，避免观察整个文档造成成本和保留。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const fragment = document.createDocumentFragment();
for (const text of ["A", "B"]) {
  const item = document.createElement("li");
  item.textContent = text;
  fragment.append(item);
}
document.querySelector("ul")?.append(fragment);
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：把插入已有节点误认为复制，原位置节点意外消失。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：观察整个document的所有属性变化，回调自身修改又产生反馈循环。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **Node**：DOM所有节点类型共享的基础接口，定义层级关系与通用操作。
- **Document**：表示整个文档、创建节点并作为节点所有权根的接口。
- **Element**：表示元素节点、承载标签、属性、子节点与查询能力的接口。
- **DocumentFragment**：不进入最终树的轻量节点容器，可批量组织后一次插入。
- **MutationObserver**：异步批量接收DOM结构、属性或文本变化记录的观察接口。
