## 机制拆解

### 1. 样式值分声明与计算

element.style只表示行内声明，getComputedStyle返回级联后的只读值，但读取某些几何属性会触发布局。批量读取再批量写入，单位转换和伪元素也要显式处理。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 遍历器把过滤与导航分开

TreeWalker适合树形移动，NodeIterator适合线性扫描；过滤器返回接受、拒绝或跳过会影响子树行为。遍历期间修改树要用固定策略，避免游标位置难以推断。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. Range边界是节点加偏移

文本节点偏移按字符，元素节点偏移按子节点索引。extractContents会移动片段，cloneContents会复制；用户选择和编辑器操作前后要规范化文本节点并重建合法边界。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const range = document.createRange();
const text = document.querySelector("p")?.firstChild;
if (text) {
  range.setStart(text, 0);
  range.setEnd(text, Math.min(5, text.textContent?.length ?? 0));
  console.log(range.toString());
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：从element.style读取最终颜色，外部样式表生效时得到空值。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：混淆元素与文本节点的Range偏移单位，截取位置错误。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **计算样式**：浏览器级联与布局计算后某元素属性的只读最终值视图。
