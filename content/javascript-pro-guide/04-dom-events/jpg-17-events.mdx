## 机制拆解

### 1. 传播与默认行为是两条轴

stopPropagation阻止继续传播但不取消默认行为，preventDefault取消可取消事件的默认动作但不阻止其他监听器。stopImmediatePropagation还会阻止同目标后续监听器，使用前要明确影响范围。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 委托依赖可验证目标

监听器应从event.target向上用closest查找匹配元素，并确认结果仍在委托容器内。Shadow DOM可能重定向目标，需要composedPath；键盘操作也要与点击提供等价命令。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 监听器本身有生命周期

匿名函数难以remove，重复渲染可能叠加监听。使用稳定函数、once、AbortSignal或组件清理钩子统一注销；高频scroll与pointermove要控制工作量而非盲目节流所有事件。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const controller = new AbortController();
document.querySelector("ul")?.addEventListener(
  "click",
  (event) => {
    const item = event.target.closest?.("li");
    if (item) console.log(item.dataset.id);
  },
  { signal: controller.signal },
);
controller.abort();
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：调用stopPropagation后以为链接不会导航，默认行为仍执行。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：每次渲染重新addEventListener，旧闭包和重复副作用持续累积。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **事件流**：事件从文档向目标捕获、在目标处理并向上冒泡的传播路径。
- **事件处理程序**：注册在目标上、事件到达相应阶段时被调用的函数。
- **默认行为**：浏览器在事件未被取消时执行的导航、提交或编辑等内置动作。
- **事件委托**：在共同祖先监听冒泡事件并根据实际目标处理多个子元素的模式。
- **合成事件**：由脚本构造并分派、isTrusted为false的事件对象。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
