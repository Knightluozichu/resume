## 直觉引入

把模块想象成快递包裹。CommonJS 像「货到付款」——你（require）打电话时快递员才出发，等到货了签收才能继续，同步阻塞；而且你拿到的是包裹里东西的**复印件**，原厂再改设计你手里的不变。ESM 像「订阅目录」——快递公司在出发前（编译期）就先看一遍所有订阅清单（import 静态分析），规划好路线，甚至能发现你订了却没用的东西直接不发货（tree-shaking）；而且你拿到的是**实时链接**，原厂改了你立刻看到。这就是静态 vs 动态、值拷贝 vs 实时绑定的区别。

## ESM 的四大特征

<Term def="ESM（ES Modules）是 JavaScript 官方模块系统，采用静态分析（编译期确定依赖）、异步加载、实时绑定（import 的是引用，导出方改变即同步）、严格模式自动开启。支持 tree-shaking（未用导出可剔除）和动态 import()。浏览器与 Node 原生支持，是现代前端模块化的标准。">ESM</Term>是官方标准。四大特征：① **静态加载**——import 必须在顶层，路径是字符串字面量，编译期即可分析全部依赖（无法用变量拼路径，除非动态 import）；② **实时绑定**——import 的是导出的引用，导出方改变后导入方立即看到新值（这是与 CommonJS 值拷贝的核心区别）；③ **异步执行**——模块按依赖图异步加载执行，支持顶层 await；④ **严格模式**——自动开启，无需 "use strict"，顶层 this 为 undefined。

```javascript
// math.js —— 导出
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export default function multiply(a, b) { return a * b; } // 默认导出

// app.js —— 导入
import multiply, { PI, add } from "./math.js"; // 默认不带{}，命名带{}
import * as math from "./math.js"; // 命名空间导入
console.log(multiply(2, 3), add(PI, 1)); // 6 4.14159

// 实时绑定：导出方改变，导入方同步
// counter.js
export let count = 0;
export function inc() { count++; }
// app.js
import { count, inc } from "./counter.js";
console.log(count); // 0
inc();
console.log(count); // 1 —— 实时绑定，立即看到新值（CommonJS 会仍是 0）

// 动态 import()：运行时加载，返回 Promise
button.addEventListener("click", async () => {
  const { heavyFn } = await import("./heavy.js"); // 按需加载，懒执行
  heavyFn();
});

// import.meta：模块元信息
console.log(import.meta.url); // 当前模块的 URL
```

## CommonJS 的特征

<Term def="CommonJS 是 Node.js 的模块系统，采用运行时同步加载（require 阻塞到模块返回）、值拷贝（导出的值被复制，导出方改变不影响已 require 的副本）、首次加载后缓存。require 可在任意位置用变量拼路径。this 指向 module.exports，循环依赖返回已执行部分。">CommonJS</Term>是 Node 的传统模块系统。`require` 同步阻塞加载，返回 `module.exports` 的**拷贝**。首次 require 后模块被缓存，再次 require 返回缓存。`this` 在模块顶层指向 `module.exports`。循环依赖时，require 会返回对方「已执行到当前行」的部分（可能不完整），这是 CJS 循环依赖坑的根源。

```javascript
// math.cjs
const PI = 3.14159;
function add(a, b) { return a + b; }
module.exports = { PI, add };
// 或 exports.PI = PI; exports.add = add;

// app.cjs
const { PI, add } = require("./math"); // 同步阻塞，返回拷贝
const math = require("./math"); // 整体

// 值拷贝：导出方改变不影响已 require 的副本
// counter.cjs
let count = 0;
function inc() { count++; }
module.exports = { count, inc };
// app.cjs
const { count, inc } = require("./counter");
inc();
console.log(count); // 0 —— 值拷贝，仍是初始值（与 ESM 实时绑定相反）

// 动态路径：require 支持变量
const name = "./plugins/" + config.plugin;
const plugin = require(name); // ESM 的 import 做不到（需动态 import()）
```

## ESM vs CommonJS 关键差异

| 维度 | ESM | CommonJS |
|------|-----|----------|
| 加载时机 | 静态（编译期） | 运行时（同步阻塞） |
| 绑定 | 实时绑定（引用） | 值拷贝 |
| 顶层 this | undefined | module.exports |
| 严格模式 | 自动开启 | 需手动声明 |
| tree-shaking | 支持 | 不支持 |
| 动态路径 | import()（返回 Promise） | require(变量)（同步） |
| 循环依赖 | 处理较好（实时绑定） | 返回不完整部分 |
| 适用 | 浏览器 + Node（现代） | Node 传统 |

## 常见误区

<Callout type="trap">
**误区：ESM 和 CommonJS 可以随便混用。** 两者互操作有严格限制。Node 中 ESM 可以 `import` CommonJS 的默认导出（module.exports 整体作为 default），但无法具名导入 CJS 的属性——`import {x} from "./cjs.cjs"` 可能失败，因为 CJS 是运行时求值，ESM 是静态分析，编译期不知道 CJS 导出了哪些具名。反向 CJS 用 `require` 加载 ESM 更受限——返回的是 namespace 对象且是 Promise 包装，需 `await import()`。工程上应统一用一种（现代项目选 ESM），混用靠构建工具（webpack/esbuild）桥接，并理解默认导出的坑。package.json `"type":"module"` 或 .mjs 扩展名启用 ESM。
</Callout>

<Exercises>
**问题 1**：ESM 的实时绑定和 CommonJS 的值拷贝有什么本质区别？举例说明。

<Answer>
ESM import 的是导出的「引用」——导出方修改后，导入方立即看到新值。CommonJS require 的是导出的「拷贝」——导出后修改不影响已 require 的副本。例：counter 模块 `let count=0; function inc(){count++}`。ESM 中 `import {count, inc}`，调用 inc() 后 count 变 1（实时绑定）。CommonJS 中 `const {count, inc} = require()`，调用 inc() 后 count 仍是 0（拷贝的是初始值）。这导致 ESM 的循环依赖能正确工作（双方实时同步），而 CJS 的循环依赖会拿到不完整的拷贝。实时绑定也使 ESM 的 tree-shaking 更可靠（编译期知道哪些被引用）。
</Answer>

**问题 2**：为什么 ESM 支持 tree-shaking 而 CommonJS 不支持？

<Answer>
tree-shaking 依赖「静态分析」——在编译期就能确定哪些导出被使用、哪些没被使用，从而剔除未用的代码。ESM 的 import 是静态声明：必须在顶层、路径是字面量、具名导入明确指定了用哪些。构建工具（webpack/esbuild/rollup）扫描 import 语句就能建立完整的依赖与使用图，把没被 import 的导出删掉。CommonJS 的 require 是运行时调用：可以写在任意位置、路径可用变量拼接、require 返回整体对象后用哪个属性运行时才知。编译期无法确定哪些导出没用，故无法安全剔除。所以用 ESM 是 tree-shaking 生效的前提，CJS 代码会被整体打包。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="ESM">JavaScript 官方模块系统。静态加载（编译期分析依赖）、实时绑定（引用）、异步执行、自动严格模式、支持 tree-shaking 和动态 import()。浏览器与 Node 原生支持，现代前端标准。</GlossaryItem>
<GlossaryItem term="CommonJS">Node 传统模块系统。运行时同步加载（require 阻塞）、值拷贝（导出改变不影响已 require 副本）、首次缓存、this=module.exports、支持变量路径。无法 tree-shaking。</GlossaryItem>
<GlossaryItem term="实时绑定">ESM 的 import 是对导出的引用，导出方改变后导入方立即看到新值。与 CommonJS 值拷贝相反。使 ESM 循环依赖能正确工作、tree-shaking 更可靠。</GlossaryItem>
<GlossaryItem term="tree-shaking">构建期剔除未使用的导出代码，减小包体积。依赖 ESM 的静态分析（import 必须顶层、具名、字面量路径）。CommonJS 因运行时动态无法 tree-shaking。副作用代码会阻碍 tree-shaking，需标记 sideEffects:false。</GlossaryItem>
<GlossaryItem term="动态 import()">import() 函数返回 Promise，运行时按需加载模块。用于路由懒加载、条件加载、减小首屏包。是 ESM 中替代 CommonJS require(变量) 的动态加载方案。</GlossaryItem>
</Glossary>
