## 机制拆解

### 1. 运动必须乘时间

按帧增加固定距离会在高刷新率设备上更快。使用rAF时间戳计算dt，并对后台恢复后的巨大间隔设上限；复杂模拟可用固定步长累计器，渲染再插值。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. Canvas尺寸有两套单位

CSS尺寸决定布局，width/height属性决定位图分辨率。按devicePixelRatio放大位图并缩放上下文可避免模糊，但要控制最大像素预算和窗口变化后的重建。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 2D上下文是状态机

变换、透明度、合成与裁剪会持续影响后续绘制。局部绘制用save/restore包围，路径在beginPath后重建；离屏画布和脏矩形只在测量证明有效时采用。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 六阶段证据链

可操作链条是：读取帧时间戳 → 计算有界步长 → 更新模拟状态 → 缩放物理画布 → 保存绘制状态 → 提交帧并重调度。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明任务、状态和资源重新收敛。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
let previous = performance.now();
function frame(now) {
  const dt = Math.min((now - previous) / 1000, 0.05);
  previous = now;
  update(dt);
  draw();
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

## 小结

- **requestAnimationFrame**：在浏览器下一次绘制前调度回调并提供高精度时间戳的动画API。
- **时间步长**：相邻动画帧时间戳之差，用于让运动与实际时间而非帧数相关。
- **Canvas**：通过脚本在位图表面即时绘制2D或WebGL图形的元素。
- **绘图状态栈**：保存和恢复变换、样式、裁剪等2D上下文状态的栈。
- **设备像素比**：CSS像素与设备物理像素之间的比例，用于调整画布清晰度。
