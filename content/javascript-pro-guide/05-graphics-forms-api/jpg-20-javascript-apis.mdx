## 机制拆解

### 1. 跨上下文传值有三种成本

结构化克隆复制值，Transferable转移底层所有权，SharedArrayBuffer共享内存并需Atomics同步。选择依据是数据大小、发送后是否仍需使用与竞争模型，不能把共享内存当更快的普通对象。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 文件媒体和流都要释放

Blob URL使用后revoke，媒体播放受用户激活和权限限制，ReadableStream生产者必须尊重desiredSize与取消。资源API成功创建只是生命周期开始，页面隐藏和组件销毁也要清理。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 组件与密码学都有封装边界

Shadow DOM提供样式和节点封装但不等于安全隔离；自定义元素生命周期应幂等。Web Crypto只提供原语，密钥生成、保存、算法参数和随机数协议仍需经过成熟方案设计。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 小结

- **SharedArrayBuffer**：允许多个执行上下文共享同一二进制内存、需隔离安全上下文的缓冲区。
- **结构化克隆**：在窗口或工作者之间复制复杂值并处理循环引用的标准序列化算法。
- **Blob**：表示不可变原始字节数据、可切片并生成临时URL的对象。
- **Web组件**：由自定义元素、Shadow DOM和模板等能力组成的原生组件模型。
- **Web Crypto**：在安全上下文提供随机数、摘要、签名与加密原语的异步API。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
