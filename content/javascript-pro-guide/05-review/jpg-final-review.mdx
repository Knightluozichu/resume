## 直觉引入

前面九章我们分别学了语言基础、对象原型、异步模型、DOM/BOM、模块系统——像学了一堆零件。总复习要做的，是把这些零件装回一台完整的机器，看它们如何在一行真实代码里协同运转。最好的方式是选一个最小但完整场景：用户点击按钮，触发一次网络请求，拿到数据后更新页面。这 4 行代码里，五层知识点全部出现——闭包捕获、原型继承、Promise/await、DOM 更新、ESM 模块。看懂这 4 行，就懂了 JavaScript 运行时。

## 五层协同：一次点击的完整旅程

<Term def="JavaScript 运行时五层协同是指语言基础（类型/作用域/闭包）、对象与原型（对象/OOP/原型链）、异步模型（Promise/事件循环）、DOM/BOM（文档树/浏览器环境）、模块系统（ESM）在一次页面交互中共同作用。每一层都不是孤立的，而是协同支撑代码的存储、组织、调度、交互与拆分。">五层协同</Term>在下面的代码中完整呈现。一个按钮点击事件处理器，用 async 箭头函数（闭包）捕获 DOM 引用，await 一个从 ESM 模块导入的异步函数（Promise + 事件循环），处理返回的对象数据（原型链上的方法），最终更新 DOM 触发渲染。每一行都映射到前面章节的知识点。

```javascript
// ⑤ 模块系统：从 api.js 静态导入（编译期分析，支持 tree-shaking）
import { fetchData } from "./api.js";
import { format } from "./utils.js";

// ④ DOM：事件监听 + 事件委托
document.querySelector("#app").addEventListener("click", async (e) => {
  if (!e.target.matches(".load-btn")) return; // 委托判断

  // ① 语言基础：async 箭头函数形成闭包，捕获 display
  const display = document.querySelector("#result");

  try {
    // ③ 异步模型：await 暂停函数（不阻塞主线程），事件循环调度
    const data = await fetchData("/api/users"); // Promise + 事件循环

    // ② 对象与原型：data 是对象，JSON.stringify 继承自原型链
    const text = format(data); // format 闭包捕获的工具函数

    // ④ DOM：更新触发重排重绘（事件循环渲染阶段）
    display.textContent = text;
  } catch (err) {
    // ③ 异步模型：await 的错误用 try/catch 捕获
    // ② 对象与原型：err 是 Error 实例，message 来自原型
    display.textContent = `错误：${err.message}`;
  }
});
```

## 工程判断力三问

全书学完，真正要内化的是三组判断力：

**1. 数据是值还是引用？** 看到变量赋值或函数传参，立即判断——原始类型（7 种）拷贝值，对象拷贝地址。这决定修改是否影响外部、深拷贝是否必要、React 状态为何要返回新对象。误判导致「改了但不生效」或「不该变却变了」的隐蔽 bug。

**2. 异步用 Promise 还是回调？** 看到异步操作，默认用 Promise/async-await，只有性能关键的事件（如 scroll、高频数据）才用回调 + 节流防抖。Promise 的 then 是微任务，比 setTimeout 先执行；await 后的代码是微任务。误判导致回调地狱、竞态条件、未处理的 rejection。

**3. 瓶颈在 DOM 还是计算？** 看到性能问题，先判断是 DOM 重排重绘（用 rAF、DocumentFragment、transform 优化）还是 CPU 计算（用 Web Worker、防抖、算法优化）。DOM 操作是前端性能头号杀手，但 CPU 密集任务也会阻塞主线程卡帧。误判导致优化方向错误——改了 JS 逻辑但 DOM 仍慢，或反之。

## 常见误区

<Callout type="trap">
**误区：五层知识是独立的，记住每层就行。** 五层是一个有机整体，真正的难点在它们的交叉点。闭包捕获的若是 DOM 引用且不释放，会内存泄漏（①+④）；async 函数里的 this 若不绑定会丢失（①+②）；Promise 链中操作 DOM 若不批处理会布局抖动（③+④）；ESM 的循环依赖遇到实时绑定行为与 CJS 不同（②+⑤）。面试和实战考的恰恰是这些交叉，而非单层知识点。所以总复习的要点不是「再背一遍每层」，而是「在真实代码里识别每层在何处起作用、如何相互影响」。
</Callout>

**问题 1**：用「一次点击 → 发请求 → 更新页面」描述五层知识点如何协同。

<Answer>
① 语言基础：事件处理用箭头函数形成闭包，捕获 display 等 DOM 引用；变量用 const 声明，作用域正确。② 对象与原型：fetch 返回的 Response 对象、data 对象都继承自原型链，调用的 .json()、JSON.stringify 等方法来自原型。③ 异步模型：await fetchData 暂停 async 函数（不阻塞主线程），fetch 的网络 I/O 由浏览器 Web API 处理，回调进入微任务队列，事件循环在同步代码后调度。④ DOM/BOM：addEventListener 监听点击，textContent 更新触发重排重绘（在事件循环渲染阶段），可用事件委托减少监听器。⑤ 模块系统：fetchData/format 通过 ESM import 静态加载，支持 tree-shaking 减小包体积。4 行代码，五层全部参与。
</Answer>

**问题 2**：什么是工程判断力三问？各自解决什么典型问题？

<Answer>
三问：① 数据是值还是引用？——判断赋值/传参后修改是否影响外部。原始类型拷贝值（互不影响），对象拷贝地址（共享同对象）。误判导致「改了不生效」（原始类型期望共享）或「不该变却变了」（对象意外共享）。典型：React 状态必须返回新对象（引用改变才触发渲染）。② 异步用 Promise 还是回调？——默认 Promise/async-await（微任务，优先级高，可链式可组合），只有 scroll 等高频事件才用回调+节流。误判导致回调地狱、竞态、未处理 rejection。③ 瓶颈在 DOM 还是计算？——DOM 问题用 rAF/Fragment/transform（减少重排），计算问题用 Worker/防抖/算法（减少主线程占用）。误判导致优化无效。三问覆盖了前端工程 90% 的常见决策。
</Answer>
