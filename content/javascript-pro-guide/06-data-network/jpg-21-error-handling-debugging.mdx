## 机制拆解

### 1. 只捕获能处理的异常

catch后静默会把失败变成错误成功。边界可以补充操作ID和输入摘要、包装cause后重抛，或展示可恢复反馈；finally只做无条件清理，不应覆盖原返回或异常。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 错误分类指导处置

TypeError等编程错误通常应暴露并修复，用户输入错误应转为字段反馈，网络超时可能重试但需幂等，安全违规应拒绝并限量记录。分类基于责任与恢复策略，不基于消息字符串。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 调试从首个偏离开始

固定版本、输入与时序，用条件断点、日志点、网络面板和性能记录比较正常与失败轨迹。生产源映射要控制访问，结构化日志避免敏感数据，并把最终根因变成自动测试。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 六阶段证据链

可操作链条是：复现固定输入 → 保存原始异常 → 定位首偏离点 → 检查调用与异步链 → 在责任边界恢复 → 记录回归测试。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明任务、状态和资源重新收敛。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
async function load() {
  try {
    return await fetch("/api").then((r) => {
      if (!r.ok) throw new Error(`HTTP ${r.status}`);
      return r.json();
    });
  } catch (cause) {
    throw new Error("load failed", { cause });
  }
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：catch所有异常后只console.log，调用方继续提交错误状态。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：只盯最终报错行，没有比较状态第一次变坏的位置。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化                   | 预期状态       | 通过条件                     |
| ---- | -------------------------------- | -------------- | ---------------------------- |
| 正常 | 合法输入、权限、顺序与版本       | 六阶段完成     | 输出和状态摘要一致           |
| 边界 | 空值、极限容量、重复事件或慢任务 | 达到预算不越界 | 主线程与内存有界             |
| 失败 | 异常、取消、拒权、断网或旧产物   | 首偏离点停止   | 明确传播、回滚或降级         |
| 恢复 | 修复后重放同一输入               | 收敛到正常轨迹 | 无陈旧任务、监听器和资源泄漏 |

本页签发不变量是：**异常不会被静默吞掉；错误保留cause与操作上下文；相同输入能复现并由回归测试覆盖根因。** 单次成功、平均耗时或最终截图不能替代运行时版本、执行轨迹、首偏离点与清理证据。

## 小结

- **Error对象**：承载错误名称、消息、堆栈及可选原因的异常值基类。
- **异常传播**：throw沿调用栈向外寻找最近匹配处理边界的控制流。
- **错误边界**：能够添加上下文、恢复、转换或终止操作的明确捕获位置。
- **断点**：在满足位置或条件时暂停执行、检查当前运行状态的调试器设施。
- **源映射**：把转换或压缩后的代码位置映射回原始源文件位置的数据。
