## 机制拆解

### 1. 解析成功要检查错误节点

DOMParser对XML语法错误通常返回包含parsererror的文档而不是抛异常。调用方要检查根元素和错误节点，并限制输入大小；HTML与XML解析模式对大小写、闭合和错误恢复完全不同。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. XPath按命名空间URI匹配

文档默认命名空间不会自动应用到XPath无前缀名称。提供前缀解析器，把查询前缀映射到URI；不能依赖源文档选用的具体前缀字符串。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 转换输出仍是不可信内容

XSLT生成HTML后直接插入页面可能带来脚本或URL风险。优先转换为受控数据模型，若必须呈现则使用成熟清洗策略；外部实体和网络加载也应在服务端安全边界处理。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const documentXml = new DOMParser().parseFromString(
  '<root><item id="1"/></root>',
  "application/xml",
);
if (documentXml.querySelector("parsererror"))
  throw new SyntaxError("invalid XML");
console.assert(documentXml.documentElement.localName === "root");
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：以为DOMParser遇到坏XML会throw，随后把parsererror当业务文档处理。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">

## 小结

- **XML DOM**：按XML规则解析并以DOM节点树表示文档的模型。
- **DOMParser**：把字符串解析为指定MIME类型文档的浏览器接口。
- **XPath**：用路径表达式在XML节点树中选择节点或计算值的语言。
- **XSLT**：以样式表规则把XML树转换为另一文档或文本的转换语言。
- **命名空间**：以URI而非前缀标识XML元素和属性所属词汇的机制。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
