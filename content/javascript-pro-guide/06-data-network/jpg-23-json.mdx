## 机制拆解

### 1. JSON不是JavaScript对象字面量

键必须双引号，不能有注释、尾逗号、undefined、函数、Symbol或BigInt。JSON.parse不执行代码，应始终替代eval；但语法安全不代表业务模式可信，解析后仍需验证形状和范围。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 序列化会静默改变数据

对象中的undefined和函数被省略，数组中变为null，NaN与Infinity变为null，Date通常通过toJSON变成字符串，循环引用抛错。协议设计应显式定义这些情况而非依赖默认。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. reviver和replacer是边界钩子

reviver后序执行，返回undefined会删除属性；replacer可白名单字段，space只用于可读输出。钩子不应承担完整业务校验，且处理**proto**等键时要避免合并到有原型目标。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
const text = JSON.stringify({ createdAt: new Date(0), value: 3 });
const data = JSON.parse(text, (key, value) =>
  key === "createdAt" ? new Date(value) : value,
);
console.assert(data.createdAt instanceof Date);
```
