## 机制拆解

### 1. Fetch只拒绝网络失败

HTTP 404或500仍会兑现为Response，调用方必须检查ok或status。响应体流通常只能消费一次，clone有缓存成本；超时要用AbortController，重试要限制在幂等操作。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. CORS是读取授权不是服务器防火墙

简单请求也会发送，只是脚本可能无法读响应；预检验证方法和头。凭据模式、允许源和Vary必须匹配，不能在允许凭据时使用通配源，也不能把CORS当认证。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 长连接需要应用层协议

WebSocket提供有序消息但没有业务心跳、重连、去重和背压。协议应包含版本、消息类型、最大尺寸和操作ID；重连后重新认证并恢复订阅，关闭码区分正常、版本和容量原因。

const response = await fetch("/api/items", {

## 常见误区与故障注入

<Callout type="trap">
  **误区一：fetch返回fulfilled就当业务成功，500响应继续解析为正常数据。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：WebSocket断线后无限立即重连，形成客户端同步风暴。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 小结

- **XMLHttpRequest**：以事件和可变状态发起HTTP请求并支持进度通知的传统浏览器接口。
- **Fetch**：以Request、Response、Promise和流模型发起网络请求的现代接口。
- **CORS**：服务器通过响应头授权跨源脚本读取响应的浏览器安全协议。
- **Beacon**：在页面卸载等场景异步排队少量数据、无需等待响应的提交接口。
- **WebSocket**：在一次HTTP升级后建立全双工消息通道的协议与浏览器接口。
