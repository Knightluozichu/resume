## 机制拆解

### 1. 旧模块模式解决全局污染

IIFE通过闭包隐藏私有变量并返回公共API，CommonJS和AMD进一步定义依赖与加载。理解这些模式有助于迁移遗留代码，但新浏览器代码应优先使用原生ES模块。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. ES模块先链接后执行

静态import必须位于顶层，使工具能分析依赖、树摇和循环；导入是只读实时绑定，模块默认严格模式且每个URL通常只实例化一次。循环依赖可链接，但过早读取未初始化绑定仍会失败。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 动态加载是异步边界

import()适合路由或大功能分块，错误包括下载、解析和求值失败。部署必须保证入口与分块版本一致，缓存策略不能让旧入口请求已删除的新哈希；预加载要由测量驱动。

## 最小可运行实验

以下代码用于独立观察本页机制；生产实现还需加入输入验证、兼容策略、权限、取消与清理。

```js
// counter.js
export let count = 0;
export const increment = () => {
  count += 1;
};
// consumer.js
const module = await import("./counter.js");
module.increment();
console.assert(module.count === 1);
```

## 小结

- **模块模式**：用闭包和对象在无原生模块时隐藏状态并暴露公共接口的模式。
- **模块说明符**：import或export from中定位依赖模块的字符串标识。
- **静态依赖**：可在执行前分析、链接并确定导入导出的模块关系。
- **实时绑定**：导入名称持续指向导出模块绑定、而非复制某次值的语义。
- **动态import**：按需异步加载模块并返回模块命名空间Promise的表达式。
