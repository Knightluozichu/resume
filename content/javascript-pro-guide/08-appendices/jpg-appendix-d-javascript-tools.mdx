## 机制拆解

### 1. 工具职责不能互相替代

格式化器统一布局，linter发现规则缺陷，类型检查验证静态契约，测试观察行为。把全部责任压给一个工具会留下盲区，也会制造无法解释的重复规则。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 构建必须可重现

固定Node与包管理器版本，提交锁文件，CI使用冻结安装并验证完整性。转译目标来自浏览器矩阵，打包分块和polyfill由实际需求驱动；同一提交应产生可追踪产物。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 发布证据连接到源码

生产错误通过发布版本和源映射还原，但源映射访问要受控。产物生成SBOM与哈希，先灰度再推广；工具升级单独提交并跑完整测试，避免业务变化与构建变化混在一起。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 六阶段证据链

可操作链条是：锁定运行时依赖 → 格式与静态检查 → 执行分层测试 → 转译目标语法 → 打包压缩映射 → 签名发布与监控。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明任务、状态和资源重新收敛。

## 验收矩阵

| 样本 | 输入与环境变化                   | 预期状态       | 通过条件                     |
| ---- | -------------------------------- | -------------- | ---------------------------- |
| 正常 | 合法输入、权限、顺序与版本       | 六阶段完成     | 输出和状态摘要一致           |
| 边界 | 空值、极限容量、重复事件或慢任务 | 达到预算不越界 | 主线程与内存有界             |
| 失败 | 异常、取消、拒权、断网或旧产物   | 首偏离点停止   | 明确传播、回滚或降级         |

本页签发不变量是：**依赖与工具版本锁定；同一提交构建可重现；测试、产物、源映射和运行错误可追溯到同一发布。** 单次成功、平均耗时或最终截图不能替代运行时版本、执行轨迹、首偏离点与清理证据。

## 小结

- **静态检查**：不执行程序就分析语法、类型或规则并报告潜在缺陷的过程。
- **转译**：把较新语法或语言扩展转换为目标运行时可解析代码的构建步骤。
- **打包器**：解析模块依赖图并生成可部署分块、资源清单和映射的工具。
- **源映射**：连接生成代码位置与原始源码位置、支持调试和错误还原的数据。
- **锁文件**：记录依赖解析出的精确版本与完整性、保证安装可重复的文件。
