## 直觉：先画执行与所有权

JavaScript工具链从编辑、静态检查、测试、转换、打包到监控构成可重现供应链，每一步都需锁版本与保留映射。 真正的难点不是让一次示例得到预期输出，而是让绑定、对象、任务、权限和资源在异常、取消、重复与版本切换后仍可解释。先预测：若只保存最终截图，最可能隐藏哪一种陈旧状态？

## 核心概念与所有权

<Term def="不执行程序就分析语法、类型或规则并报告潜在缺陷的过程。">静态检查</Term>、<Term def="把较新语法或语言扩展转换为目标运行时可解析代码的构建步骤。">转译</Term>、<Term def="解析模块依赖图并生成可部署分块、资源清单和映射的工具。">打包器</Term>、<Term def="连接生成代码位置与原始源码位置、支持调试和错误还原的数据。">源映射</Term>、<Term def="记录依赖解析出的精确版本与完整性、保证安装可重复的文件。">锁文件</Term>。
每个概念都要回答：谁创建输入，状态保存在哪里，哪个任务或版本可修改它，结束后由谁清理。

|   2 | 转译     | 把较新语法或语言扩展转换为目标运行时可解析代码的构建步骤。 |
|   3 | 打包器   | 解析模块依赖图并生成可部署分块、资源清单和映射的工具。     |
|   4 | 源映射   | 连接生成代码位置与原始源码位置、支持调试和错误还原的数据。 |

## 机制拆解

### 1. 工具职责不能互相替代

格式化器统一布局，linter发现规则缺陷，类型检查验证静态契约，测试观察行为。把全部责任压给一个工具会留下盲区，也会制造无法解释的重复规则。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 2. 构建必须可重现

固定Node与包管理器版本，提交锁文件，CI使用冻结安装并验证完整性。转译目标来自浏览器矩阵，打包分块和polyfill由实际需求驱动；同一提交应产生可追踪产物。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

### 3. 发布证据连接到源码

生产错误通过发布版本和源映射还原，但源映射访问要受控。产物生成SBOM与哈希，先灰度再推广；工具升级单独提交并跑完整测试，避免业务变化与构建变化混在一起。

先预测：若省略这一层，哪个绑定、任务、权限或资源会先偏离？

## 六阶段证据链

可操作链条是：锁定运行时依赖 → 格式与静态检查 → 执行分层测试 → 转译目标语法 → 打包压缩映射 → 签名发布与监控。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明任务、状态和资源重新收敛。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：删除锁文件让CI每次获取最新间接依赖，构建结果漂移。**
  必须保存输入、任务顺序、状态摘要与首次拒绝原因，而不是只看最终页面。
</Callout>

<Callout type="trap">
  **误区二：发布压缩代码却没有受控源映射，生产错误无法定位原始行。**
  必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化                   | 预期状态       | 通过条件                     |
| ---- | -------------------------------- | -------------- | ---------------------------- |
| 正常 | 合法输入、权限、顺序与版本       | 六阶段完成     | 输出和状态摘要一致           |
| 边界 | 空值、极限容量、重复事件或慢任务 | 达到预算不越界 | 主线程与内存有界             |
| 失败 | 异常、取消、拒权、断网或旧产物   | 首偏离点停止   | 明确传播、回滚或降级         |
| 恢复 | 修复后重放同一输入               | 收敛到正常轨迹 | 无陈旧任务、监听器和资源泄漏 |

## 小结

- **静态检查**：不执行程序就分析语法、类型或规则并报告潜在缺陷的过程。
- **转译**：把较新语法或语言扩展转换为目标运行时可解析代码的构建步骤。
- **打包器**：解析模块依赖图并生成可部署分块、资源清单和映射的工具。
- **源映射**：连接生成代码位置与原始源码位置、支持调试和错误还原的数据。
- **锁文件**：记录依赖解析出的精确版本与完整性、保证安装可重复的文件。
- 六阶段机制链已经映射到正常、边界、失败与恢复证据。
