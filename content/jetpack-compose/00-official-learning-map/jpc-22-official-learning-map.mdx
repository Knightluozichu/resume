# 《Jetpack Compose从入门到实战》权威学习地图

本页依据王鹏、关振智、曾思淇《Jetpack Compose从入门到实战》独立重构，不复制原文。版本锁定机械工业出版社2022年8月首版、331页、ISBN 9787111711377；得到电子版标注2022年7月发行。全书正式结构是11章、200个章/节/小节节点。

原书处在Compose快速演进的2022年。课程先复现书中的API、行为和项目边界，再把今天的替代方案写入迁移账本；不会用Material 3、类型安全路由或Foundation新API改写原目录。

## 从状态开始

<Term def="以状态为输入描述界面结果，由框架负责把状态变化映射为界面更新">声明式UI</Term>、<Term def="状态向下驱动界面、事件向上请求变更并由唯一所有者归约的流向">单向数据流</Term>、<Term def="Compose在观察状态变化后重新执行受影响组合范围以更新树的过程">重组</Term>、<Term def="可组合调用进入、保留并离开组合树时所经历的所有权阶段">组合生命周期</Term>、<Term def="逐项记录原书API、现代替代、行为差异、测试证据和回退条件的清单">迁移账本</Term>构成本页的核心词汇。Compose不是“自动更新一切”：只有被观察的状态读、稳定身份、正确Effect键和明确所有者共同成立，框架才能把变化限制在可解释范围。每个示例先写状态和事件，再画组合、布局、绘制与外部副作用边界。

本单元主线是以11章197个节点贯通声明式基础、组件、状态、渲染、动画、手势、导航、生态与两个产品实战。交互管线用于逐层选择目录节点；反例实验在正常、状态抖动、错误身份、所有者销毁与版本漂移之间切换；证据门要求结构、状态、生命周期、可访问性和迁移五类证据全部通过。

## 可运行实现切片

下面代码只承担本章最小机制，不隐藏状态所有者和事件入口。真实项目还要补齐空态、错误态、恢复、可访问性与截图测试。

```kotlin
data class LearningEvidence(
    val chapter: Int,
    val reproducedNodes: Set<String>,
    val tests: List<String>,
    val migrationNotes: List<String>
)

check(evidence.reproducedNodes.size == 197)
```

实现后先断言业务结果，再观察组合或交互成本。把版本、设备、字体比例、窗口尺寸、主题和输入样本写进测试记录，才能分辨代码回归与环境差异。

```kotlin
data class ComposeProbe(
    val stateId: String,
    val recompositions: Int,
    val semanticsReady: Boolean,
    val ownerActive: Boolean
)

check(probe.semanticsReady)
check(probe.ownerActive)
```

## 迁移账本与回归合同

迁移不是“能编译”就结束。每一项记录原书API、2022年行为、现代替代、行为差异、验证样本和回退条件。尤其要覆盖状态恢复、手势阈值、返回栈、主题角色与第三方组件退役。

```text
原书节点: 第1章 全新的Android UI框架
原书版本: Compose 2022 首版语境
现代候选: 待依赖矩阵验证
不变量: 状态结果、可访问语义、生命周期所有权
证据: 11章197节点矩阵、版本卡、状态到渲染因果链、Tetris与Chatty交付路线、现代迁移账本
回退: 任一不变量失败即恢复原实现
```

## 本章回顾

回顾时不要从API清单开始，而要从一个状态变化或用户事件开始，依次回答谁拥有状态、哪些调用进入组合、约束如何传递、像素或导航结果怎样产生、外部工作何时取消。再用11章197节点矩阵、版本卡、状态到渲染因果链、Tetris与Chatty交付路线、现代迁移账本复核；任何无法重放的结论都退回实验阶段。

**问题 1**：本页为什么必须按11个目录节点学习？

<Answer>因为第1章 全新的Android UI框架、第2章 了解常用UI组件、第3章 定制UI视图、第4章 状态管理与重组、第5章 Compose组件渲染流程、第6章 让页面动起来：动画等节点共同构成“以11章197个节点贯通声明式基础、组件、状态、渲染、动画、手势、导航、生态与两个产品实战”的完整链路；删去任何正式节点都会让输入、机制或验收证据断裂。</Answer>

**问题 2**：本页最小正确性合同是什么？

<Answer>给定同一状态与事件，界面业务结果、语义、生命周期所有权和恢复行为必须确定；优化或迁移不能改变合同。</Answer>

**问题 3**：哪个反例最能推翻错误实现？

<Answer>让“把全书压缩成布局、状态和导航几页，遗漏渲染流程、手势、第三方库以及两个完整项目”成立并运行所有者销毁、状态恢复或版本漂移场景；若结果重复、错位、泄漏或不可访问，方案即失败。</Answer>

**问题 4**：为什么一次截图或一次流畅运行不是证据？

<Answer>它没有覆盖状态序列、重组边界、语义树、不同窗口与主题、生命周期取消和进程恢复，也不能解释版本差异。</Answer>

**问题 5**：怎样升级Compose而不改写原书？

<Answer>先保存2022年API与行为基线，再一次替换一个依赖或API，用同一状态、事件、截图和恢复测试比较，并填写迁移账本。</Answer>

**问题 6**：独立交接需要哪些产物？

<Answer>需要源码与依赖锁、目录节点映射、状态事件样本、11章197节点矩阵、版本卡、状态到渲染因果链、Tetris与Chatty交付路线、现代迁移账本、失败测试、可访问性结果、版本迁移记录与回退条件。</Answer>
