# 第1章 全新的Android UI框架

本页依据王鹏、关振智、曾思淇《Jetpack Compose从入门到实战》独立重构，不复制原文。版本锁定机械工业出版社2022年8月首版、331页、ISBN 9787111711377；得到电子版标注2022年7月发行。全书正式结构是11章、200个章/节/小节节点。

原书处在Compose快速演进的2022年。课程先复现书中的API、行为和项目边界，再把今天的替代方案写入迁移账本；不会用Material 3、类型安全路由或Foundation新API改写原目录。

## 从状态开始

<Term def="以状态为输入描述界面结果，由框架负责把状态变化映射为界面更新">声明式UI</Term>、<Term def="由Compose编译器参与转换、可进入组合树的带Composable注解函数">Composable</Term>、<Term def="通过内容lambda向调用者开放结构插槽而不是依赖继承扩展组件">Slot API</Term>、<Term def="在受限设计时环境中渲染可组合函数并快速核对状态样本的工具">Preview</Term>、<Term def="Compose树与传统View树相互嵌入并传递状态、事件和生命周期的接缝">互操作边界</Term>构成本页的核心词汇。Compose不是“自动更新一切”：只有被观察的状态读、稳定身份、正确Effect键和明确所有者共同成立，框架才能把变化限制在可解释范围。每个示例先写状态和事件，再画组合、布局、绘制与外部副作用边界。

本单元主线是从声明式UI、Compose API原则与View关系，走到环境部署、首个应用、预览和已有项目接入。交互管线用于逐层选择目录节点；反例实验在正常、状态抖动、错误身份、所有者销毁与版本漂移之间切换；证据门要求结构、状态、生命周期、可访问性和迁移五类证据全部通过。

## 可运行实现切片

下面代码只承担本章最小机制，不隐藏状态所有者和事件入口。真实项目还要补齐空态、错误态、恢复、可访问性与截图测试。

```kotlin
@Composable
fun Greeting(name: String) {
    Text(text = "Hello, $name")
}

@Preview(showBackground = true)
@Composable
fun GreetingPreview() = AppTheme { Greeting("Compose") }
```

实现后先断言业务结果，再观察组合或交互成本。把版本、设备、字体比例、窗口尺寸、主题和输入样本写进测试记录，才能分辨代码回归与环境差异。

data class ComposeProbe(

## 本章回顾

回顾时不要从API清单开始，而要从一个状态变化或用户事件开始，依次回答谁拥有状态、哪些调用进入组合、约束如何传递、像素或导航结果怎样产生、外部工作何时取消。再用状态到UI映射、编译配置、预览与设备结果、版本目录、View与Compose双向边界复核；任何无法重放的结论都退回实验阶段。
