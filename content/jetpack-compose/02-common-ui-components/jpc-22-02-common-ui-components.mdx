## 从状态开始

<Term def="按调用顺序包装节点并依次参与布局、绘制、输入和语义处理的不可变链">Modifier链</Term>、<Term def="只在特定父布局接收者中成立并向父布局传递数据的Modifier">作用域修饰符</Term>、<Term def="协调顶部栏、底部栏、悬浮按钮和内容内边距的页面骨架">Scaffold</Term>、<Term def="仅组合和布局当前需要项目并按滚动状态增量工作的容器">惰性布局</Term>、<Term def="跨插入删除与移动保持列表项目身份和局部状态归属的唯一标识">稳定键</Term>构成本页的核心词汇。Compose不是“自动更新一切”：只有被观察的状态读、稳定身份、正确Effect键和明确所有者共同成立，框架才能把变化限制在可解释范围。每个示例先写状态和事件，再画组合、布局、绘制与外部副作用边界。

本单元主线是沿Modifier顺序与作用域，组合文本、图片、按钮、选择器、对话框、基础布局、Scaffold和惰性列表。交互管线用于逐层选择目录节点；反例实验在正常、状态抖动、错误身份、所有者销毁与版本漂移之间切换；证据门要求结构、状态、生命周期、可访问性和迁移五类证据全部通过。

<Answer>给定同一状态与事件，界面业务结果、语义、生命周期所有权和恢复行为必须确定；优化或迁移不能改变合同。</Answer>

**问题 3**：哪个反例最能推翻错误实现？
<Answer>让“把Modifier当成无序样式集合，或让惰性列表使用位置作为身份导致状态错位”成立并运行所有者销毁、状态恢复或版本漂移场景；若结果重复、错位、泄漏或不可访问，方案即失败。</Answer>

**问题 4**：为什么一次截图或一次流畅运行不是证据？
<Answer>它没有覆盖状态序列、重组边界、语义树、不同窗口与主题、生命周期取消和进程恢复，也不能解释版本差异。</Answer>

**问题 5**：怎样升级Compose而不改写原书？
<Answer>先保存2022年API与行为基线，再一次替换一个依赖或API，用同一状态、事件、截图和恢复测试比较，并填写迁移账本。</Answer>

**问题 6**：独立交接需要哪些产物？
<Answer>需要源码与依赖锁、目录节点映射、状态事件样本、Modifier顺序对照、作用域编译约束、布局边界、列表稳定键、滚动状态与语义树、失败测试、可访问性结果、版本迁移记录与回退条件。</Answer>
