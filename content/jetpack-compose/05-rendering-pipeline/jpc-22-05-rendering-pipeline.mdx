# 第5章 Compose组件渲染流程

本页依据王鹏、关振智、曾思淇《Jetpack Compose从入门到实战》独立重构，不复制原文。版本锁定机械工业出版社2022年8月首版、331页、ISBN 9787111711377；得到电子版标注2022年7月发行。全书正式结构是11章、200个章/节/小节节点。

原书处在Compose快速演进的2022年。课程先复现书中的API、行为和项目边界，再把今天的替代方案写入迁移账本；不会用Material 3、类型安全路由或Foundation新API改写原目录。

## 从状态开始

<Term def="执行可组合函数并维护可复用组、节点和状态观察关系的阶段">组合阶段</Term>、<Term def="父布局传给子项的最小与最大宽高边界">约束</Term>、<Term def="子项在约束下产生尺寸并把可放置结果交还父项的过程">测量</Term>、<Term def="父布局确定已测量子项坐标和层次的过程">放置</Term>、<Term def="按节点与修饰符顺序把内容输出到画布或平台Canvas的阶段">绘制阶段</Term>构成本页的核心词汇。Compose不是“自动更新一切”：只有被观察的状态读、稳定身份、正确Effect键和明确所有者共同成立，框架才能把变化限制在可解释范围。每个示例先写状态和事件，再画组合、布局、绘制与外部副作用边界。

本单元主线是从组合进入测量、布局与绘制，比较Layout Modifier、Layout、Intrinsic、SubcomposeLayout、Canvas和DrawModifier。交互管线用于逐层选择目录节点；反例实验在正常、状态抖动、错误身份、所有者销毁与版本漂移之间切换；证据门要求结构、状态、生命周期、可访问性和迁移五类证据全部通过。

## 可运行实现切片

下面代码只承担本章最小机制，不隐藏状态所有者和事件入口。真实项目还要补齐空态、错误态、恢复、可访问性与截图测试。

```kotlin
@Composable
fun TwoColumn(content: @Composable () -> Unit) {
    Layout(content = content) { measurables, constraints ->
        val width = constraints.maxWidth / 2
        val children = measurables.map { it.measure(constraints.copy(maxWidth = width)) }
        layout(constraints.maxWidth, children.maxOf { it.height }) {
            children.forEachIndexed { i, p -> p.placeRelative((i % 2) * width, 0) }
        }
    }
}
```

实现后先断言业务结果，再观察组合或交互成本。把版本、设备、字体比例、窗口尺寸、主题和输入样本写进测试记录，才能分辨代码回归与环境差异。

## 本章回顾

回顾时不要从API清单开始，而要从一个状态变化或用户事件开始，依次回答谁拥有状态、哪些调用进入组合、约束如何传递、像素或导航结果怎样产生、外部工作何时取消。再用组合树、约束传递、测量次数、放置坐标、绘制层次、固有测量与子组合触发记录复核；任何无法重放的结论都退回实验阶段。

**问题 1**：本页为什么必须按13个目录节点学习？
<Answer>因为第5章 Compose组件渲染流程、5.1 组合、5.2 布局、5.2.1 Layout Modifier、5.2.2 Layout Composable、5.2.3 固有特性测量Intrinsic等节点共同构成“从组合进入测量、布局与绘制，比较Layout Modifier、Layout、Intrinsic、SubcomposeLayout、Canvas和DrawModifier”的完整链路；删去任何正式节点都会让输入、机制或验收证据断裂。</Answer>

**问题 2**：本页最小正确性合同是什么？
<Answer>给定同一状态与事件，界面业务结果、语义、生命周期所有权和恢复行为必须确定；优化或迁移不能改变合同。</Answer>

**问题 3**：哪个反例最能推翻错误实现？

**问题 4**：为什么一次截图或一次流畅运行不是证据？

**问题 5**：怎样升级Compose而不改写原书？
<Answer>先保存2022年API与行为基线，再一次替换一个依赖或API，用同一状态、事件、截图和恢复测试比较，并填写迁移账本。</Answer>
