## 全书知识图谱

<JpcFinalReviewDiagram />

全书以 **UI = f(state)** 为核心心智模型，九个章节覆盖六大领域。每个领域解决一个核心问题，彼此通过 State 和 Modifier 关联。

## 核心概念串联

```kotlin
// 一条主线贯穿全书：@Composable + State 驱动 → 自动重组 → 声明式 UI

// 第1章 基础：@Composable 是一切的起点
@Composable
fun MyApp() {
    // 第5章 主题：MaterialTheme 提供颜色/文字/形状
    MaterialTheme {
        // 第6章 导航：NavHost 管理页面
        NavHost(navController, startDestination = "home") {
            composable("home") {
                HomeScreen()
            }
        }
    }
}

// 第2章 布局 + 第3章 状态：布局组织结构，状态驱动更新
@Composable
fun HomeScreen(viewModel: HomeViewModel = viewModel()) {
    // 第3章 状态：ViewModel 持有状态
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    
    // 第2章 布局：Column 组织结构
    Column(modifier = Modifier.fillMaxSize()) {
        // 第5章 主题：消费主题 Token
        Text("首页", style = MaterialTheme.typography.headlineMedium)
        
        // 第2章 布局：LazyColumn 懒加载列表
        LazyColumn {
            items(uiState.items, key = { it.id }) { item ->
                // 第4章 动画：列表项动画
                AnimatedContent(targetState = item) { animItem ->
                    ItemRow(animItem)
                }
            }
        }
    }
}

// 第7章 互操作 + 第8章 高级：复杂场景
@Composable
fun ItemDetailScreen(url: String) {
    // 第7章 互操作：嵌入 WebView
    AndroidView(factory = { WebView(it) }, update = { it.loadUrl(url) })
    
    // 第8章 高级：手势缩放
    var scale by remember { mutableStateOf(1f) }
    Box(Modifier.pointerInput(Unit) {
        detectTransformGestures { _, _, zoom, _ -> scale *= zoom }
    })
}
```

## 选型决策矩阵

| 场景 | 首选方案 | 理由 |
|------|----------|------|
| 列表展示 | LazyColumn + key | 懒加载，key 保障项状态稳定 |
| 状态持有 | ViewModel + StateFlow | 跨重组存活，生命周期感知 |
| UI 临时状态 | remember + mutableStateOf | 轻量，组合内记忆 |
| 跨配置变更 | rememberSaveable | Bundle 序列化，旋转恢复 |
| 派生计算 | derivedStateOf | 依赖变化才重组，性能优化 |
| 显隐动画 | AnimatedVisibility | 声明式，自动 fade+slide |
| 内容切换 | AnimatedContent | 新旧内容过渡 |
| 单属性动画 | animate*AsState | 一行搞定 |
| 多属性联动 | updateTransition | 同状态驱动多属性 |
| 手势驱动 | Animatable + coroutine | 协程可暂停/取消 |
| 嵌入 WebView | AndroidView | factory+update 模式 |
| 页面导航 | NavHost + NavController | 类型安全路由 |
| 底部导航 | Scaffold + NavigationBar | 联动 NavHost |
| 自定义布局 | Layout + MeasurePolicy | measure+place |
| 懒加载布局 | SubcomposeLayout | 分阶段组合 |
| 手势检测 | pointerInput + detect* | 底层精确控制 |
| 嵌套滚动 | nestedScroll + Connection | 父子协同滚动 |

## 架构最佳实践

```kotlin
// 1. 单向数据流（UDF）
@Composable
fun Screen(viewModel: MyViewModel = viewModel()) {
    // 状态向下：ViewModel → UI
    val state by viewModel.state.collectAsStateWithLifecycle()
    
    // 事件向上：UI → ViewModel
    MyContent(
        data = state.data,
        onItemClick = { viewModel.onItemClick(it) }
    )
}

// 2. 状态提升到合适层级
@Composable
fun FormScreen() {
    var name by rememberSaveable { mutableStateOf("") }  // 提升到 Screen
    var email by rememberSaveable { mutableStateOf("") }
    
    NameField(value = name, onValueChange = { name = it })  // 无状态组件
    EmailField(value = email, onValueChange = { email = it })
    SubmitButton(enabled = name.isNotBlank() && email.isNotBlank())
}

// 3. 重组性能优化
@Composable
fun OptimizedList(items: List<Item>) {
    val hasSelection by remember { derivedStateOf { items.any { it.selected } } }
    
    LazyColumn {
        items(items, key = { it.id }) { item ->
            // key 保障稳定，derivedStateOf 减少重组
            ItemRow(item)
        }
    }
    
    if (hasSelection) {  // 只有 hasSelection 变化才重组
        SelectionBar()
    }
}

// 4. 副作用管理
@Composable
fun DataScreen(url: String) {
    LaunchedEffect(url) {  // url 变化时重新加载
        val data = fetchData(url)
        // 更新状态
    }
    
    DisposableEffect(Unit) {
        val listener = registerListener()
        onDispose { listener.unregister() }  // 离开时清理
    }
}
```

<Callout type="success" title="学习总结">
Compose 的核心是思维方式的转变——从命令式（手动操作 View）到声明式（UI = f(state)）。掌握三件事就能应对 90% 的场景：①用 @Composable 描述 UI，②用 State 驱动更新，③用 Modifier 修饰外观。其余的布局容器、动画 API、导航、互操作都是在这三件事基础上的扩展。
</Callout>

## 关键对比速查

| 概念 | 传统 View | Compose |
|------|-----------|---------|
| UI 描述 | XML + 代码 | @Composable 函数 |
| 状态管理 | 手动同步 | State 自动重组 |
| 布局 | LinearLayout/FrameLayout | Column/Row/Box |
| 列表 | RecyclerView + Adapter | LazyColumn + items() |
| 主题 | styles.xml + theme.xml | MaterialTheme |
| 导航 | Fragment + FragmentManager | NavHost + NavController |
| 动画 | ObjectAnimator/TransitionManager | animate*AsState/AnimatedVisibility |
| 自定义 View | 继承 View/ViewGroup | Layout/Modifier.layout() |
| 事件 | setOnClickListener | Modifier.clickable |
| 状态保存 | onSaveInstanceState | rememberSaveable |

**问题 1**：用全书知识设计一个带动画的购物车列表页面的架构。

<Answer>
架构设计：①状态层——CartViewModel持有MutableStateFlow<CartUiState>，包含items列表、totalPrice、isCheckingOut等状态。ViewModel负责业务逻辑：addToCart/removeItem/updateQuantity/clearCart。②UI层——@Composable fun CartScreen(vm: CartViewModel = viewModel()) { val state by vm.state.collectAsStateWithLifecycle(); CartContent(state, vm::onAction) }。③布局——CartContent用Scaffold(topBar={CartTopBar(totalPrice=state.totalPrice)}, bottomBar={CheckoutBar(enabled=state.items.isNotEmpty(), total=state.totalPrice)}) { padding -> LazyColumn { items(state.items, key={it.id}) { item -> CartItemRow(item, onDelete={vm.removeItem(item.id)}) } } } }。④动画——删除商品时用AnimatedVisibility包裹每一行，exit=shrinkVertically()+fadeOut()实现滑动删除动画。总价变化用animateIntAsState做数字滚动动画。⑤主题——用MaterialTheme.colorScheme.primary做按钮色，MaterialTheme.typography.headlineSmall做总价文字。⑥导航——CheckoutBar的onClick调用navController.navigate("checkout")，CheckoutScreen通过savedStateHandle接收选中的商品列表。⑦互操作——如果商品图片用Glide加载，用AndroidView嵌入ImageView或用Coil-Compose的AsyncImage（推荐原生方案）。⑧性能——items用key=item.id保障列表稳定；用derivedStateOf计算「是否有选中商品」避免不必要重组；价格计算用derivedStateOf。数据流：用户点击删除→onAction(CartAction.Remove(id))→ViewModel更新StateFlow→CartScreen自动重组→LazyColumn diff（key匹配）→AnimatedVisibility播放删除动画。全程单向数据流，UI只负责展示和传递事件。
</Answer>

**问题 2**：总结全书各章的核心知识点和它们之间的关联。

<Answer>
各章核心知识点：①基础——@Composable注解（可组合函数入口）、remember（组合内记忆）、Slot API（组件内容由调用方决定）、Composition生命周期（enter/compose/dispose）、无副作用原则（副作用用LaunchedEffect/DisposableEffect管理）。②布局——Column/Row/Box（三大容器）、Modifier链（顺序敏感，从外到内）、LazyColumn（懒加载列表，key保障稳定）、Constraints（约束传播）、measure→place（测量摆放两阶段）。③状态——mutableStateOf（可观察状态）、重组机制（智能跳过+并行+最小范围）、rememberSaveable（跨配置变更）、ViewModel+StateFlow（跨重组+业务逻辑）、derivedStateOf（派生状态优化）、状态提升（Stateful→Stateless，单向数据流）。④动画——三层API：AnimatedVisibility/AnimatedContent（高层声明式）、animate*AsState/updateTransition（中层状态驱动）、Animatable/AnimationSpec（底层精确控制）、Easing曲线、选型决策树。⑤主题——MaterialTheme三支柱：ColorScheme（颜色角色）、Typography（文字样式）、Shapes（形状）、CompositionLocal（主题传递机制）、深浅色+Dynamic Color。⑥导航——NavHost（导航图）、NavController（路由管理）、类型安全路由（Serializable对象）、嵌套导航图、底部导航联动、深层链接、返回结果（SavedStateHandle）。⑦互操作——AndroidView（Compose中嵌入View，factory+update）、ComposeView（View中嵌入Compose）、生命周期绑定、性能优化（合并ComposeView）、渐进迁移（自底向上）。⑧高级——Layout+MeasurePolicy（自定义布局）、SubcomposeLayout（分阶段组合）、pointerInput+detect*Gestures（手势检测）、draggable/swipeable/nestedScroll（高层手势）、嵌套滚动机制。关联：①@Composable是所有章节的基础——没有@Composable就没有Composable函数。②State驱动是核心——布局(③)、动画(④)、导航(⑥)都依赖State变化触发更新。③Modifier贯穿全书——布局(②)用Modifier组织结构、主题(⑤)用Modifier消费Token、高级(⑧)用Modifier.layout/pointerInput扩展。④单向数据流是架构主线——状态提升(③)、ViewModel(③)、导航传参(⑥)都遵循UDF。⑤性能是交叉主题——derivedStateOf(③)、LazyColumn key(②)、AndroidView优化(⑦)都关注性能。
</Answer>

**问题 3**：在不同场景下如何选择正确的 Compose API？给出决策流程。

<Answer>
决策流程：①布局选择——需要垂直排列→Column；水平排列→Row；层叠→Box；长列表→LazyColumn/LazyRow；流式→自定义FlowLayout(Layout)；需要根据测量结果决定内容→SubcomposeLayout。②状态选择——UI临时态（展开折叠）→remember+mutableStateOf；需旋转恢复→rememberSaveable；业务数据/跨重组→ViewModel+StateFlow；派生计算→derivedStateOf。③动画选择——显隐切换→AnimatedVisibility；内容切换→AnimatedContent/Crossfade；单属性→animate*AsState；多属性联动→updateTransition；无限循环→rememberInfiniteTransition；手势驱动→Animatable+coroutine。④导航选择——简单页面→composable("route")；带参数→类型安全路由composable<Route>；分组→navigation()嵌套图；底部导航→Scaffold+NavigationBar+currentBackStackEntryAsState。⑤互操作选择——Compose中嵌入WebView/Map→AndroidView(factory+update)；XML中嵌入Compose→ComposeView/AbstractComposeView；Fragment级迁移→ComposeView+setViewCompositionStrategy。⑥手势选择——单击→clickable；单击+双击+长按→combinedClickable；拖拽→draggable(简单)/pointerInput+detectDragGestures(自定义)；缩放旋转→pointerInput+detectTransformGestures；锚点滑动→swipeable；嵌套滚动→nestedScroll+NestedScrollConnection。⑦自定义选择——修改单个组件布局→Modifier.layout()；全新布局容器→Layout()+MeasurePolicy；自定义绘制→Modifier.drawBehind()/drawWithContent()。原则：①从高层API开始选——高层更简洁、更声明式、更不易出错。②高层满足不了才降层——如animate*AsState无法满足时才用Animatable。③优先Compose原生方案——能用LazyColumn就不用AndroidView+RecyclerView。④性能考虑——列表用key、频繁变化用derivedStateOf、避免AndroidView在快速滚动列表中。
</Answer>

**问题 4**：对比 Compose 和传统 View 在各维度的差异，分析 Compose 的优势和局限。

<Answer>
各维度对比：①UI描述——View：XML布局+Kotlin代码分离，XML不能写逻辑，代码不能描述结构。Compose：@Composable函数中Kotlin代码直接描述UI结构和逻辑，无XML，类型安全。②状态管理——View：命令式，手动findViewById+setText，状态与UI手动同步，易遗漏。Compose：声明式，State变化自动重组，UI=f(state)，状态与UI自动同步。③布局——View：LinearLayout/FrameLayout/ConstraintLayout，XML声明，层级深。Compose：Column/Row/Box，Kotlin代码，组合式，Modifier链替代属性。④列表——View：RecyclerView+Adapter+ViewHolder，模板代码多。Compose：LazyColumn+items()，几行代码搞定，key自动diff。⑤主题——View：styles.xml+theme.xml，XML配置。Compose：MaterialTheme+CompositionLocal，Kotlin代码，深浅色/动态取色简洁。⑥动画——View：ObjectAnimator/TransitionManager/XML动画，API分散。Compose：animate*AsState等统一API，声明式，自动组合。⑦导航——View：Fragment+FragmentManager+FragmentTransaction，手动管理。Compose：NavHost+NavController，声明式导航图，类型安全路由。⑧自定义——View：继承View/ViewGroup，重写onMeasure/onDraw/onLayout。Compose：Layout()+Modifier.layout()，函数式，组合优于继承。⑨状态保存——View：onSaveInstanceState/onRestoreInstanceState，手动序列化。Compose：rememberSaveable，自动序列化。Compose优势：①声明式——状态自动同步，减少bug。②类型安全——编译期检查，无findViewById运行时错误。③代码复用——组合优于继承，@Composable可任意嵌套复用。④开发效率——预览（@Preview）、无XML、热重载。⑤性能——智能跳过重组、编译期优化。Compose局限：①学习曲线——声明式思维转变需要时间。②互操作开销——AndroidView有额外开销，不适合大量使用。③生态成熟度——部分三方库尚无Compose原生支持。④调试难度——重组机制不直观，性能分析工具不如View成熟。⑤APK体积——Compose运行时增加约2-3MB。⑥初学者易写出不必要的重组——需要理解稳定性、key、derivedStateOf等概念。总体：Compose是Android UI的未来方向，Google全力推进。新项目推荐用Compose，老项目渐进迁移。
</Answer>
