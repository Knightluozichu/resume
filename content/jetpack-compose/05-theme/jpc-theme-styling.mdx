## MaterialTheme 三大支柱

<JpcThemeStylingDiagram />

MaterialTheme 是 Compose 的主题系统入口，通过 CompositionLocal 向子树提供 ColorScheme（颜色）、Typography（文字）、Shapes（形状）三大主题 Token。

```kotlin
// MaterialTheme 包裹根组件
@Composable
fun AppTheme(darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit) {
    val colorScheme = if (darkTheme) darkColorScheme() else lightColorScheme()
    
    MaterialTheme(
        colorScheme = colorScheme,
        typography = Typography,
        shapes = Shapes,
        content = content
    )
}
```

## ColorScheme：颜色系统

```kotlin
// 定义颜色方案
val LightColors = lightColorScheme(
    primary = Color(0xFF6200EE),
    onPrimary = Color.White,
    secondary = Color(0xFF03DAC6),
    onSecondary = Color.Black,
    surface = Color.White,
    onSurface = Color.Black,
    background = Color(0xFFFAFAFA),
    onBackground = Color.Black,
    error = Color(0xFFB00020)
)

val DarkColors = darkColorScheme(
    primary = Color(0xFFBB86FC),
    onPrimary = Color.Black,
    surface = Color(0xFF121212),
    onSurface = Color.White,
    background = Color.Black,
    onBackground = Color.White
)

// 在组件中消费颜色
@Composable
fun ThemedButton(text: String, onClick: () -> Unit) {
    Button(onClick = onClick, colors = ButtonDefaults.buttonColors(
        containerColor = MaterialTheme.colorScheme.primary,      // 主色
        contentColor = MaterialTheme.colorScheme.onPrimary       // 主色上的文字色
    )) {
        Text(text)
    }
}
```

<Callout type="info" title="颜色命名约定">
颜色用「角色名」而非「色值名」：primary（主色）而非 purple。这样换主题时所有组件自动适配。on 前缀表示「在某色之上的前景色」：onPrimary = primary 背景上的文字色。
</Callout>

## Typography：文字系统

```kotlin
// 定义文字样式
val Typography = Typography(
    displayLarge = TextStyle(fontSize = 57.sp, fontWeight = FontWeight.Normal, lineHeight = 64.sp),
    headlineLarge = TextStyle(fontSize = 32.sp, fontWeight = FontWeight.Normal, lineHeight = 40.sp),
    titleLarge = TextStyle(fontSize = 22.sp, fontWeight = FontWeight.Bold, lineHeight = 28.sp),
    bodyLarge = TextStyle(fontSize = 16.sp, fontWeight = FontWeight.Normal, lineHeight = 24.sp),
    labelLarge = TextStyle(fontSize = 14.sp, fontWeight = FontWeight.Medium, lineHeight = 20.sp)
)

// 消费文字样式
@Composable
fun ThemedText() {
    Text("大标题", style = MaterialTheme.typography.headlineLarge)
    Text("正文内容", style = MaterialTheme.typography.bodyLarge)
    Text("按钮", style = MaterialTheme.typography.labelLarge)
}

// 也可以组合覆盖
Text("自定义", style = MaterialTheme.typography.bodyLarge.copy(
    color = MaterialTheme.colorScheme.primary,
    fontWeight = FontWeight.Bold
))
```

## Shapes：形状系统

```kotlin
// 定义形状
val Shapes = Shapes(
    small = RoundedCornerShape(8.dp),    // Button、Chip
    medium = RoundedCornerShape(12.dp),   // Card
    large = RoundedCornerShape(16.dp)     // BottomSheet、Dialog
)

// 消费形状
@Composable
fun ThemedCard() {
    Card(shape = MaterialTheme.shapes.medium) {
        Text("圆角卡片")
    }
}

// 自定义形状
CircleShape                    // 圆形
RoundedCornerShape(16.dp)      // 统一圆角

```

## 深浅色与动态取色

```kotlin
@Composable
fun AppTheme(darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit) {
    // 动态取色（Android 12+ Material You）
    val context = LocalContext.current
    val colorScheme = when {
        Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
            if (darkTheme) dynamicDarkColorScheme(context)
            else dynamicLightColorScheme(context)
        }
        darkTheme -> DarkColors
        else -> LightColors
    }
    
    MaterialTheme(colorScheme = colorScheme, content = content)
}

// 判断当前是否深色模式
@Composable
fun AdaptiveIcon() {
    val isDark = isSystemInDarkTheme()
    Icon(
        painter = if (isDark) painterResource(R.drawable.icon_dark)
                  else painterResource(R.drawable.icon_light),
        contentDescription = null
    )
}
```

## CompositionLocal 原理

```kotlin
// MaterialTheme 本质是通过 CompositionLocal 提供主题
// 等价于：
val LocalColorScheme = staticCompositionLocalOf { lightColorScheme() }
val LocalTypography = staticCompositionLocalOf { Typography() }
val LocalShapes = staticCompositionLocalOf { Shapes() }

// MaterialTheme 内部做了类似这样的事：
@Composable
fun MaterialTheme(colorScheme, typography, shapes, content) {
    CompositionLocalProvider(
        LocalColorScheme provides colorScheme,
        LocalTypography provides typography,
        LocalShapes provides shapes
    ) {
        content()
    }
}

// 子组件通过 MaterialTheme.colorScheme 读取
// 等价于 LocalColorScheme.current
```

<Glossary>

<GlossaryItem term="MaterialTheme">
Compose 的主题系统入口组件。通过 CompositionLocal 向子树提供 ColorScheme、Typography、Shapes 三大主题 Token。子组件通过 MaterialTheme.colorScheme/typography/shapes 读取。
</GlossaryItem>

<GlossaryItem term="ColorScheme">
颜色角色方案，定义 primary/secondary/surface/error 等颜色角色及其 on 变体。lightColorScheme() 和 darkColorScheme() 提供默认值。颜色用角色名（如 primary）而非色值名。
</GlossaryItem>

<GlossaryItem term="CompositionLocal">
Compose 的依赖注入机制。通过 CompositionLocalProvider 提供值，子树通过 LocalXxx.current 读取。MaterialTheme 的颜色/文字/形状都是通过 CompositionLocal 传递的。
</GlossaryItem>

<GlossaryItem term="Dynamic Color">
Android 12+ 的 Material You 动态取色功能。系统从壁纸提取颜色生成 ColorScheme，使 App 颜色与系统主题一致。通过 dynamicLightColorScheme/dynamicDarkColorScheme 获取。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：MaterialTheme 如何通过 CompositionLocal 传递主题？子组件如何消费？

<Answer>
MaterialTheme内部使用CompositionLocalProvider向子树提供三个CompositionLocal：LocalColorScheme、LocalTypography、LocalShapes。当MaterialTheme(colorScheme=..., typography=..., shapes=...)被调用时，它在内部用CompositionLocalProvider将这三个值注入Composition的上下文中。子组件通过MaterialTheme.colorScheme/typography/shapes读取——这三个属性实际上是LocalColorScheme.current/LocalTypography.current/LocalShapes.current的便捷访问器。CompositionLocal的特点：①隐式传递——不需要通过参数逐层传递，子树中任何深度的Composable都能直接读取。②作用域——只有MaterialTheme子树中的Composable才能读到该主题，不同子树可以有不同主题（如一个屏幕用亮色、另一个用暗色）。③响应式——如果colorScheme变化（如深浅色切换），所有读取它的Composable自动重组。消费方式：`MaterialTheme.colorScheme.primary`获取主色，`MaterialTheme.typography.bodyLarge`获取文字样式，`MaterialTheme.shapes.medium`获取形状。也可以用.copy()覆盖部分属性：`MaterialTheme.typography.bodyLarge.copy(color = Color.Red)`。
</Answer>

**问题 2**：颜色用「角色名」而非「色值名」有什么好处？

<Answer>
角色名（如primary/surface/error）vs 色值名（如purple/white/red）的好处：①主题自适应——同一个MaterialTheme.colorScheme.primary在亮色主题下是紫色(#6200EE)、在暗色主题下是浅紫色(#BB86FC)、在动态取色下是从壁纸提取的颜色。用角色名后，组件代码不需要知道当前是什么主题，换主题时所有组件自动适配。如果用色值名，换主题时需要手动修改每个组件的颜色。②语义清晰——primary表示「主色」，onPrimary表示「主色上的前景色」，surface表示「表面色」。开发者看到角色名就知道这个颜色用在什么场景，看到Color(0xFF6200EE)则不知道这个紫色是主色还是次要色。③一致性保障——Material Design规范定义了每个颜色角色的用途（primary用于主要按钮、surface用于卡片背景、error用于错误提示）。用角色名强制开发者遵循规范，避免随意用色导致视觉混乱。④品牌定制——切换品牌色只需修改colorScheme中的primary值，所有使用primary的组件自动更新。如做白标应用时，不同客户只需提供不同的colorScheme。
</Answer>

**问题 3**：如何实现深浅色主题切换和 Android 12 动态取色？

<Answer>
```kotlin @Composable fun AppTheme(darkTheme: Boolean = isSystemInDarkTheme(), dynamicColor: Boolean = true, content: @Composable () -> Unit) { val context = LocalContext.current val colorScheme = when { dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> { if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context) } darkTheme -> DarkColors else -> LightColors } MaterialTheme(colorScheme = colorScheme, typography = AppTypography, shapes = AppShapes, content = content) }```关键点：①isSystemInDarkTheme()——读取系统暗色模式设置，返回Boolean。系统切换暗色模式时自动重组AppTheme，切换colorScheme。②dynamicColor——Android 12+(S)支持Material You动态取色，系统从壁纸提取颜色生成ColorScheme。dynamicLightColorScheme(context)/dynamicDarkColorScheme(context)获取动态方案。③降级策略——低于Android 12或不启用动态取色时，回退到自定义的DarkColors/LightColors。④在Activity中使用——`setContent { AppTheme { AppContent() } }`，AppTheme包裹所有内容。⑤局部主题——可以在某个子树用不同的MaterialTheme覆盖，如某个屏幕强制暗色：`MaterialTheme(colorScheme = darkColorScheme()) { DarkScreen() }`。Typography和Shapes不受深浅色影响，通常不需要切换。
</Answer>

**问题 4**：如何自定义一个非 Material 的主题系统？

<Answer>
自定义主题系统需要三个步骤：①定义主题数据类——`data class AppColors(val primary: Color, val textPrimary: Color, val background: Color, val isDark: Boolean)`。②创建CompositionLocal——`val LocalAppColors = staticCompositionLocalOf { error("AppColors not provided") }`（用error作为默认值，强制必须Provide）。③创建Theme Composable——`@Composable fun AppTheme(darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit) { val colors = if (darkTheme) DarkAppColors else LightAppColors; CompositionLocalProvider(LocalAppColors provides colors) { content() } }`。④消费——`val colors = LocalAppColors.current; Box(Modifier.background(colors.background)) { Text("text", color = colors.textPrimary) }`。与MaterialTheme的区别：①不用MaterialDesign的颜色角色命名，可以自定义任何字段名。②可以包含非视觉属性（如间距、动画时长）——`data class AppTheme(val colors: AppColors, val spacing: Spacing, val motion: Motion)`，然后用多个CompositionLocal分别提供。③staticCompositionLocalOf vs compositionLocalOf——前者值变化时不触发重组（适合不会变的主题），后者会触发重组（适合会动态变化的值）。实际项目通常在MaterialTheme基础上扩展：用MaterialTheme提供Material组件需要的Token，额外用自定义CompositionLocal提供品牌专属Token（如自定义间距、圆角、动画时长）。
</Answer>
