## 从状态开始

<Term def="在Modifier节点上启动可随键重启的挂起式指针事件处理作用域">PointerInput</Term>、<Term def="标记某一位置变化已由处理器使用以协调同一事件链上的竞争者">事件消费</Term>、<Term def="区分轻微抖动与有意拖动所需跨越的系统距离">触摸阈值</Term>、<Term def="父子滚动容器在预滚动、子消费与后滚动阶段分配位移和速度的协议">嵌套滚动</Term>、<Term def="在点击、长按、拖动、多指与父级拦截之间决定唯一有效解释的过程">手势仲裁</Term>构成本页的核心词汇。Compose不是“自动更新一切”：只有被观察的状态读、稳定身份、正确Effect键和明确所有者共同成立，框架才能把变化限制在可解释范围。每个示例先写状态和事件，再画组合、布局、绘制与外部副作用边界。

本单元主线是比较点击、复合点击、拖动、滑动、多点触控、滚动和嵌套滚动，再以PointerInput定制事件并结合动画。交互管线用于逐层选择目录节点；反例实验在正常、状态抖动、错误身份、所有者销毁与版本漂移之间切换；证据门要求结构、状态、生命周期、可访问性和迁移五类证据全部通过。

## 可运行实现切片

下面代码只承担本章最小机制，不隐藏状态所有者和事件入口。真实项目还要补齐空态、错误态、恢复、可访问性与截图测试。

```kotlin
Modifier.pointerInput(Unit) {
    awaitEachGesture {
        val down = awaitFirstDown(requireUnconsumed = false)
        val drag = awaitTouchSlopOrCancellation(down.id) { change, over ->
            change.consume()
        }
        if (drag != null) drag(drag.id) { change -> change.consume() }
    }
}
```

实现后先断言业务结果，再观察组合或交互成本。把版本、设备、字体比例、窗口尺寸、主题和输入样本写进测试记录，才能分辨代码回归与环境差异。

```kotlin
data class ComposeProbe(
    val stateId: String,
    val recompositions: Int,
    val semanticsReady: Boolean,
    val ownerActive: Boolean
)

check(probe.semanticsReady)
check(probe.ownerActive)
```

<Callout type="trap">**本章核心陷阱。** 直接从原始坐标判断手势而忽略事件消费、触摸阈值、取消和可访问性语义。修复必须回到状态所有者、稳定身份、生命周期和可观察结果，而不是继续堆Modifier或Effect。</Callout>

<Callout type="trap">**版本错位。** 原书Swipeable等API按2022年版本保存；现代替代API必须通过行为、阈值和状态恢复对照迁移。</Callout>

## 本章回顾

回顾时不要从API清单开始，而要从一个状态变化或用户事件开始，依次回答谁拥有状态、哪些调用进入组合、约束如何传递、像素或导航结果怎样产生、外部工作何时取消。再用指针序列、消费标记、触摸阈值、速度、取消、父子滚动分配、语义动作与多指轨迹复核；任何无法重放的结论都退回实验阶段。
