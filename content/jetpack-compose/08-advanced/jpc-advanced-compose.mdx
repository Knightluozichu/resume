## 自定义布局与手势

<JpcAdvancedComposeDiagram />

高级 Compose 涵盖两大核心能力：自定义布局（Layout/SubcomposeLayout）和手势处理（pointerInput/draggable/swipeable/nestedScroll）。

## 自定义 Layout

```kotlin
// Layout 组件：自定义测量和摆放逻辑
@Composable
fun FlowLayout(
    modifier: Modifier = Modifier,
    horizontalSpacing: Dp = 8.dp,
    verticalSpacing: Dp = 8.dp,
    content: @Composable () -> Unit
) {
    Layout(modifier = modifier, content = content) { measurables, constraints ->
        val hSpacing = horizontalSpacing.roundToPx()
        val vSpacing = verticalSpacing.roundToPx()
        
        val placeables = measurables.map { it.measure(constraints) }
        
        var width = 0
        var height = 0
        var lineHeight = 0
        var lineWidth = 0
        
        // 先计算所有行
        val rows = mutableListOf<MutableList<Placeable>>()
        var currentRow = mutableListOf<Placeable>()
        
        placeables.forEach { placeable ->
            if (lineWidth + placeable.width > constraints.maxWidth) {
                // 换行
                rows.add(currentRow)
                width = maxOf(width, lineWidth)
                height += lineHeight + vSpacing
                currentRow = mutableListOf()
                lineWidth = 0
                lineHeight = 0
            }
            currentRow.add(placeable)
            lineWidth += placeable.width + hSpacing
            lineHeight = maxOf(lineHeight, placeable.height)
        }
        if (currentRow.isNotEmpty()) {
            rows.add(currentRow)
            width = maxOf(width, lineWidth)
            height += lineHeight
        }
        
        layout(width, height) {
            var y = 0
            rows.forEach { row ->
                var x = 0
                var maxH = 0
                row.forEach { placeable ->
                    placeable.placeRelative(x, y)
                    x += placeable.width + hSpacing
                    maxH = maxOf(maxH, placeable.height)
                }
                y += maxH + vSpacing
            }
        }
    }
}
```

    val vertical = all.roundToPx() * 2
    val placeable = measurable.measure(constraints.offset(-horizontal, -vertical))
    layout(placeable.width + horizontal, placeable.height + vertical) {
        placeable.placeRelative(all.roundToPx(), all.roundToPx())
    }

## SubcomposeLayout

```kotlin
// SubcomposeLayout：分阶段组合
// 先测外层 → 根据结果决定组合内层

@Composable
fun AdaptiveGrid(
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit
) {
    SubcomposeLayout(modifier) { constraints ->
        // 第一阶段：组合一个测量探针
        val probe = subcompose("probe", content).first()
            .measure(constraints)
        
        // 根据探针结果计算列数
        val columns = constraints.maxWidth / probe.width
        
        // 第二阶段：组合实际内容
        val items = subcompose("items", content).map {
            it.measure(constraints.copy(maxWidth = constraints.maxWidth / columns))
        }
        
        // 摆放
        layout(constraints.maxWidth, constraints.maxHeight) {
            items.forEachIndexed { i, placeable ->
                val col = i % columns
                val row = i / columns
                placeable.placeRelative(
                    col * placeable.width,
                    row * placeable.height
                )
            }
        }
    }
}
```

<Callout type="warning" title="SubcomposeLayout 适用场景">
SubcomposeLayout 有额外开销（多次组合），只在以下场景使用：①内容依赖测量结果（如 TabRow 需要知道最大 Tab 宽度）。②懒加载（LazyColumn 只组合可见项）。③条件组合（某些子元素只在特定条件下出现）。简单布局用 Layout() 即可。
</Callout>

## 手势处理

```kotlin
// pointerInput：底层手势检测
@Composable
fun TouchDetector() {
    Box(
        Modifier
            .size(200.dp)
            .background(Color.Blue)
            .pointerInput(Unit) {
                detectTapGestures(
                    onTap = { offset -> /* 单击 */ },
                    onDoubleTap = { offset -> /* 双击 */ },
                    onLongPress = { offset -> /* 长按 */ }
                )
            }
    )
}

// detectDragGestures：拖拽
@Composable
fun Draggable() {
    var offset by remember { mutableStateOf(Offset.Zero) }
    Box(
        Modifier
            .offset { IntOffset(offset.x.toInt(), offset.y.toInt()) }
            .pointerInput(Unit) {
                detectDragGestures { delta ->
                    offset += delta  // 累加偏移
                }
            }
    )
}

// detectTransformGestures：缩放+旋转
@Composable
fun Zoomable() {
    var scale by remember { mutableStateOf(1f) }
    var rotation by remember { mutableStateOf(0f) }
    Box(
        Modifier
            .graphicsLayer(scaleX = scale, scaleY = scale, rotationZ = rotation)
            .pointerInput(Unit) {
                detectTransformGestures { _, pan, zoom, rotationChange ->
                    scale *= zoom
                    rotation += rotationChange
                }
            }
    )
}
```

## 嵌套滚动

```kotlin
// 嵌套滚动连接：子组件滚动事件先传给父组件
val nestedScrollConnection = object : NestedScrollConnection {
    override fun onPreScroll(available: Offset, source: NestedScrollSource): Offset {
        // 子组件滚动前，父组件先消费（如 AppBar 收起）
        return Offset.Zero  // 不消费，传给子
    }
    
    override fun onPostScroll(consumed: Offset, available: Offset, source: NestedScrollSource): Offset {
        // 子组件滚动后，剩余的滚动量传给父组件
        return Offset.Zero  // 不消费
    }
    
    override fun onPreFling(available: Velocity): Velocity {
        // fling 前
        return Velocity.Zero
    }
    
    override fun onPostFling(consumed: Velocity, available: Velocity): Velocity {
        // fling 后
        return Velocity.Zero
    }
}

// 使用
Box(Modifier.nestedScroll(nestedScrollConnection)) {
    LazyColumn { /* 列表内容 */ }
}
```

<Glossary>

<GlossaryItem term="Layout">
自定义布局的核心组件。接收 MeasurePolicy lambda，参数为 measurables（待测量子元素）和 constraints（父约束）。在 lambda 中测量子元素（measure）并摆放（placeRelative）。
</GlossaryItem>

<GlossaryItem term="SubcomposeLayout">
分阶段组合的布局组件。先组合部分内容测量，再根据测量结果决定组合剩余内容。适用于内容依赖测量结果的场景（如 TabRow、LazyColumn）。有额外组合开销。
</GlossaryItem>

<GlossaryItem term="pointerInput">
底层手势检测的 Modifier。在协程中用 detectTapGestures/detectDragGestures/detectTransformGestures 检测手势。key 变化时重新启动检测。
</GlossaryItem>

<GlossaryItem term="NestedScrollConnection">
嵌套滚动连接接口。通过 onPreScroll/onPostScroll/onPreFling/onPostFling 拦截子组件的滚动和 fling 事件，实现父组件与子组件的协同滚动（如 AppBar+列表）。
</GlossaryItem>

</Glossary>

**问题 1**：实现一个自定义 FlowLayout（流式布局），让子元素自动换行。

<Answer>
```kotlin @Composable fun FlowLayout(modifier: Modifier = Modifier, horizontalSpacing: Dp = 8.dp, verticalSpacing: Dp = 8.dp, content: @Composable () -> Unit) { Layout(modifier = modifier, content = content) { measurables, constraints -> val hSp = horizontalSpacing.roundToPx(); val vSp = verticalSpacing.roundToPx(); val placeables = measurables.map { it.measure(constraints) }; var width = 0; var height = 0; var lineWidth = 0; var lineHeight = 0; val rows = mutableListOf<MutableList<Pair<Placeable, Int>>>(); var currentRow = mutableListOf<Pair<Placeable, Int>>(); placeables.forEach { p -> if (lineWidth + p.width > constraints.maxWidth && currentRow.isNotEmpty()) { rows.add(currentRow); width = maxOf(width, lineWidth - hSp); height += lineHeight + vSp; currentRow = mutableListOf(); lineWidth = 0; lineHeight = 0 }; currentRow.add(p to lineWidth); lineWidth += p.width + hSp; lineHeight = maxOf(lineHeight, p.height) }; if (currentRow.isNotEmpty()) { rows.add(currentRow); width = maxOf(width, lineWidth - hSp); height += lineHeight }; layout(width.coerceAtMost(constraints.maxWidth), height.coerceAtMost(constraints.maxHeight)) { var y = 0; rows.forEach { row -> var maxH = 0; row.forEach { (p, x) -> p.placeRelative(x, y); maxH = maxOf(maxH, p.height) }; y += maxH + vSp } } } }```
核心逻辑：①测量所有子元素（measure(constraints)得到Placeable）。②遍历Placeable，累加行宽lineWidth。当lineWidth+下一个元素宽度>maxWidth时换行——保存当前行到rows，重置lineWidth/lineHeight。③记录每个元素在行内的x偏移（用于摆放时定位）。④计算总尺寸——width=最长行的宽度，height=所有行高之和+间距。⑤layout(width,height)返回结果，在lambda中按行按列placeRelative(x,y)摆放每个Placeable。关键点：constraints携带父元素给的可用空间范围（maxWidth/maxHeight），子元素测量时传入相同constraints（流式布局不限制单个子元素宽度，由maxWidth决定换行）。
</Answer>

**问题 2**：SubcomposeLayout 与 Layout 有什么区别？各自适用什么场景？

<Answer>
区别：①组合方式——Layout一次性组合所有子元素（content lambda中的所有@Composable先组合再测量），SubcomposeLayout分阶段组合（可以先组合部分子元素测量，再根据结果决定是否组合其余子元素）。②API——Layout的MeasurePolicy接收measurables（已组合的子元素），SubcomposeLayout的lambda接收constraints，用subcompose(slotId, content)按需组合子元素。③开销——Layout只组合一次，SubcomposeLayout可能组合多次，每次subcompose()都有组合开销。④灵活性——SubcomposeLayout更灵活，可以「先测后组」。Layout适用场景：①标准布局容器（Column/Row/Box都是用Layout实现的）。②所有子元素已知，不需要根据测量结果决定组合什么。③固定结构布局（如FlowLayout、自定义对齐）。④性能优先——只组合一次，开销最小。SubcomposeLayout适用场景：①内容依赖测量结果——如TabRow需要先测量所有Tab的宽度，才知道TabIndicator的位置和宽度。②懒加载——LazyColumn用SubcomposeLayout只组合可见区域的item，不可见的不组合。③条件组合——某些子元素只在特定条件下出现，如 BoxWithConstraints 根据可用空间决定显示一列还是两列。④分阶段测量——先组合「探针」元素获取信息，再组合实际内容。原则：默认用Layout，只有需要「先测后组」或懒加载时才用SubcomposeLayout（因为后者有额外开销）。
</Answer>

**问题 3**：pointerInput 中的手势检测是如何工作的？如何同时处理点击和拖拽？

<Answer>
pointerInput工作原理：①pointerInput(key)是一个Modifier，在协程中运行手势检测。②内部用awaitPointerEventScope挂起函数监听底层PointerEvent（触摸事件），每次有新的触摸事件时恢复协程。③detect*Gestures是一组封装好的检测器，内部用awaitPointerEvent处理事件序列，识别手势模式（tap=down+up无移动，drag=down+move，transform=多指down+move）。④key变化时取消当前协程重新启动检测——key用于控制检测的「作用域」，如pointerInput(Unit)永不重启，pointerInput(id)在id变化时重启。同时处理点击和拖拽的挑战：detectTapGestures和detectDragGestures不能在同一个pointerInput中同时调用（它们各自占用事件流）。解决方案：①方案一——分两个pointerInput：`.pointerInput(Unit){ detectTapGestures(onTap=...) }.pointerInput(Unit){ detectDragGestures{...} }`。但问题：两个检测器都会收到事件，drag可能吞掉tap的事件（onTap需要等待长按超时确认不是drag，而drag立即响应move）。②方案二——自定义手势检测：在awaitPointerEventScope中手动处理事件序列：先awaitFirstDown，然后用withTimeout(waitForUpOrLongPress)等待——如果up了就是tap，如果move超阈值就是drag。③方案三——用awaitEachGesture：```kotlin .pointerInput(Unit) { awaitEachGesture { val down = awaitFirstDown(); var isDrag = false; while(true) { val event = awaitPointerEvent(); val change = event.changes.first(); if(change.positionChanged() && distance(down.position, change.position) > touchSlop) { isDrag = true; // 开始拖拽 }; if(!change.pressed) { if(!isDrag) { /* tap */ }; break } } } }```关键概念：touchSlop（触摸 slop 阈值）——移动距离超过此值才算拖拽，否则视为点击。避免微小移动误判为拖拽。
</Answer>

**问题 4**：嵌套滚动的机制是什么？如何实现一个滚动时收起的 Header？

<Answer>
嵌套滚动机制：①事件传播顺序——子组件（如LazyColumn）滚动时，先问父组件（onPreScroll）「你要先消费多少？」，父组件消费一部分后剩余的给子组件滚动。子组件滚动完后，如果还有剩余滚动量，再问父组件（onPostScroll）「你要消费剩余的吗？」。②fling同理——onPreFling（父先消费速度）→子组件fling→onPostFling（父消费剩余速度）。③消费机制——返回的Offset/Velocity表示父组件消费了多少，剩余的传给子组件。返回Offset.Zero表示不消费。实现收起Header：```kotlin @Composable fun CollapsibleHeader() { var headerHeight by remember { mutableStateOf(200.dp) }; var scrolled by remember { mutableStateOf(0f) }; val connection = object : NestedScrollConnection { override fun onPreScroll(available: Offset, source: NestedScrollSource): Offset { // 子组件滚动前，父组件先消费（收起Header） val delta = available.y; val newScrolled = (scrolled + delta).coerceIn(-headerHeightPx, 0f); val consumed = newScrolled - scrolled; scrolled = newScrolled; return Offset(0f, consumed) // 消费掉的量 }; override fun onPostScroll(consumed: Offset, available: Offset, source: NestedScrollSource): Offset { // 子组件滚动完后，剩余的向上滚动量用于展开Header if (available.y > 0) { val newScrolled = (scrolled + available.y).coerceIn(-headerHeightPx, 0f); val consumed = newScrolled - scrolled; scrolled = newScrolled; return Offset(0f, consumed) }; return Offset.Zero } }; Column(Modifier.nestedScroll(connection)) { Box(Modifier.height(headerHeight).offset { IntOffset(0, scrolled.roundToInt()) }); LazyColumn { items(...) } } }```关键：①onPreScroll——向下滚动(available.y<0)时父组件先消费，收起Header（offset变小）。②onPostScroll——向上滚动且子组件到顶时(available.y>0)，父组件消费剩余量展开Header。③coerceIn限制Header不会过度收起/展开。④返回的consumed量被子组件感知，避免双重滚动。
</Answer>
