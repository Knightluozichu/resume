# 第8章 为Compose添加页面导航

本页依据王鹏、关振智、曾思淇《Jetpack Compose从入门到实战》独立重构，不复制原文。版本锁定机械工业出版社2022年8月首版、331页、ISBN 9787111711377；得到电子版标注2022年7月发行。全书正式结构是11章、200个章/节/小节节点。

原书处在Compose快速演进的2022年。课程先复现书中的API、行为和项目边界，再把今天的替代方案写入迁移账本；不会用Material 3、类型安全路由或Foundation新API改写原目录。

## 从状态开始

<Term def="把导航图与承载当前目的地内容的组合区域连接起来的容器">NavHost</Term>、<Term def="按导航操作保存目的地及其参数、状态和生命周期所有者的栈">返回栈</Term>、<Term def="从外部URI或应用内链接直接解析并进入指定目的地的契约">深链</Term>、<Term def="把一组目的地及其起点封装为可独立管理流程的子图">嵌套导航图</Term>、<Term def="决定ViewModel或依赖实例创建、共享和销毁边界的所有权范围">作用域</Term>构成本页的核心词汇。Compose不是“自动更新一切”：只有被观察的状态读、稳定身份、正确Effect键和明确所有者共同成立，框架才能把变化限制在可解释范围。每个示例先写状态和事件，再画组合、布局、绘制与外部副作用边界。

本单元主线是建立Navigation图、参数、底部导航、嵌套图、深链和ViewModel作用域，并用Hilt提供依赖。交互管线用于逐层选择目录节点；反例实验在正常、状态抖动、错误身份、所有者销毁与版本漂移之间切换；证据门要求结构、状态、生命周期、可访问性和迁移五类证据全部通过。

## 可运行实现切片

下面代码只承担本章最小机制，不隐藏状态所有者和事件入口。真实项目还要补齐空态、错误态、恢复、可访问性与截图测试。

```kotlin
NavHost(navController, startDestination = "home") {
    composable("home") { Home(onOpen = { id -> navController.navigate("detail/$id") }) }
    composable("detail/{id}") { entry ->
        Detail(id = requireNotNull(entry.arguments?.getString("id")))
    }
}
```

实现后先断言业务结果，再观察组合或交互成本。把版本、设备、字体比例、窗口尺寸、主题和输入样本写进测试记录，才能分辨代码回归与环境差异。

```kotlin
data class ComposeProbe(
    val stateId: String,
    val recompositions: Int,
    val semanticsReady: Boolean,
    val ownerActive: Boolean
)

check(probe.semanticsReady)
check(probe.ownerActive)
```

<Callout type="trap">**本章核心陷阱。** 把完整对象塞进路由、在组合重组时重复导航，或让ViewModel与依赖作用域脱离返回栈所有者。修复必须回到状态所有者、稳定身份、生命周期和可观察结果，而不是继续堆Modifier或Effect。</Callout>

<Callout type="trap">**版本错位。** 原书字符串路由与Hilt集成按2022年解释；类型安全路由属于现代迁移层，不替换原目录。</Callout>

<Callout type="warning">示例数据必须是合成数据。聊天账号、头像URL、深链参数、日志和截图不得包含真实令牌、联系人或用户消息。</Callout>

## 本章回顾

回顾时不要从API清单开始，而要从一个状态变化或用户事件开始，依次回答谁拥有状态、哪些调用进入组合、约束如何传递、像素或导航结果怎样产生、外部工作何时取消。再用路由表、返回栈轨迹、参数编码、深链测试、进程恢复、导航图级ViewModel与依赖作用域复核；任何无法重放的结论都退回实验阶段。
