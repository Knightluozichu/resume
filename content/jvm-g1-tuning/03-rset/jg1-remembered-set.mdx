## 直觉引入

RSet像一本「谁引用了我」的反向电话簿。传统电话簿（正向引用）从「我」查「我引用了谁」，RSet从「我」查「谁引用了我」。G1回收某个Region时，需要更新所有指向该Region的引用——如果用正向方式，要扫描全堆才能找到引用者。RSet让G1直接查到「Region B和C引用了我」，只需扫描B和C的特定Card，避免全堆扫描。

## RSet：反向引用索引

```text
问题：G1 以 Region 为单位回收，回收 Region A 时需要知道：
  "哪些其他 Region 引用了 A 中的对象？"
  否则 evacuation 后无法更新引用。

传统方案：全堆扫描 → 堆越大越慢
G1 方案：RSet(A) 记录引用 A 的所有 Region 和 Card

  Region A (被回收)        Region B (引用方)     Region C (引用方)
  ┌──────────────┐         ┌──────────────┐     ┌──────────────┐
  │ Card 0       │         │ Card 1: obj→A │     │ Card 4: obj→A │
  │ Card 1       │ ←────── │ Card 2        │     │ Card 5        │
  │ Card 2       │ ←────── │ Card 3        │     │ Card 6        │
  │ ...          │         │ ...           │     │ ...           │
  ├──────────────┤         └──────────────┘     └──────────────┘
  │ RSet(A):     │
  │  {B: Card 1} │  ← 反向索引：B 的 Card 1 引用了 A
  │  {C: Card 4} │  ← 反向索引：C 的 Card 4 引用了 A
  └──────────────┘
```

<Callout type="insight">
**核心价值**：没有RSet，G1每次回收都要扫描全堆找引用关系（O(堆大小)）。有了RSet，只需扫描目标Region的RSet指向的Card（O(RSet条目数)）。这是G1实现Region级回收的关键基础设施。
</Callout>

## 卡表：RSet的底层实现

```text
卡粒度：512 字节 / Card

堆按 512B 划分为 Card：
  Card 0 (0-511B) | Card 1 (512-1023B) | Card 2 ... | Card N

写操作触发 Write Barrier：
  obj.field = target
  → 判断 obj 和 target 是否在不同 Region
  → 如果是，将 target 所在 Card 标记为 dirty
  → 加入 DCQ（Dirty Card Queue）

RSet 按 Card 精确记录：
  RSet(A) = { RegionB: {Card1}, RegionC: {Card4} }
  回收 A 时只需扫描 B 的 Card 1 和 C 的 Card 4（各 512B）
```

## Write Barrier / DCQ / Refine 流程

```text
完整流程：

  Mutator 线程                GC 线程
  ┌───────────┐              ┌───────────────┐
  │ 写引用操作  │              │               │
  │ obj.f = t  │              │               │
  ├───────────┤              │               │
  │Write Barrier│             │               │
  │判断跨Region │ ──加入──→   │ DCQ 队列       │
  │标记dirty Card│            │ (每线程一个)    │
  └───────────┘              ├───────────────┤
                             │ Refine 线程    │
                             │ 异步消费 DCQ   │
                             │ 更新到 RSet    │
                             └───────────────┘

源码入口：
  G1PostBarrierInlining::post_barrier  → Write Barrier 入口
  DCQ → G1DirtyCardQueueSet            → Refine 线程消费
  OtherRegionsInfo                     → RSet 数据结构管理
```

<Callout type="trap">
**陷阱**：Write Barrier 是每次写操作都执行的，不是只在GC时执行。这意味着G1的写操作比不使用RSet的收集器（如Parallel GC）多几条指令的开销。这是G1相比CMS的主要性能开销之一，也是G1在小堆上不如Parallel的原因。
</Callout>

## PRT 三级退化

```text
RSet 的精度与开销权衡（三级退化）：

  Sparse PRT（细粒度）           Fine PRT（中粒度）          Coarse PRT（粗粒度）
  ┌─────────────────┐          ┌─────────────────┐        ┌─────────────────┐
  │ 每个 Card 单独记录 │          │ Card 位图按 Region│        │ 仅记 Region 级位图│
  │ 扫描精确          │ 退化→    │ 分组              │ 退化→  │ 扫描整个 Region   │
  │ 元数据大          │          │ 中等精度/开销      │        │ 元数据小/扫描放大  │
  └─────────────────┘          └─────────────────┘        └─────────────────┘

退化触发条件：
  引用 Card 数超过阈值 → Sparse 退化为 Fine
  引用 Region 数超过阈值 → Fine 退化为 Coarse

影响：
  Coarse PRT 扫描时需要扫描整个 Region（而非精确 Card）
  → 停顿时间增加 → 这是 G1 大堆 RSet 膨胀的根因之一
```

## RSet 内存占用

```text
估算：
  每个 Region 的 RSet 平均占用 Region 大小的 1%-5%
  极端情况（大量跨 Region 引用）可达 20%

  32GB 堆 × 5% = 1.6GB RSet 内存开销

膨胀场景：
  ① 大量短生命周期跨 Region 引用（数组遍历修改不同 Region）
  ② 大对象被广泛引用（Humongous 跨多 Region）
  ③ 对象关系图高度互联（HashMap/缓存结构）

控制参数：
  -XX:G1RSetUpdatingPauseTimePercent=10  控制Refine线程在GC暂停中更新RSet的时间比例
  -XX:G1ConcRefinementThreads            控制并发Refine线程数（默认=ParallelGCThreads）
  -XX:G1HeapRegionSize                   增大Region减少跨引用频率
```

<Exercises>
**问题 1**：G1的RSet（Remembered Set）是什么？它解决了什么问题？

<Answer>
RSet是G1用于记录「哪些其他Region引用了本Region中的对象」的数据结构，本质是一个反向引用索引。解决的问题：G1以Region为单位回收，回收某个Region时需要知道是否有其他Region引用了本Region的对象——否则evacuation时复制存活对象后，需要更新所有指向它的引用，但如果不扫描全堆就无法知道引用来源。RSet让G1只需扫描目标Region的RSet就能找到所有跨Region引用，避免全堆扫描。例如回收Region A时，RSet(A)记录了Region B和C中有对象引用A中的对象，GC只需扫描B和C中引用A的区域即可更新引用。
</Answer>

**问题 2**：G1的卡表（Card Table）和RSet是什么关系？卡粒度如何影响精度和开销？

<Answer>
卡表是RSet的底层实现机制。RSet记录的是Region级别的引用关系（哪个Region引用本Region），卡表记录的是更细粒度——512字节的Card粒度——具体哪个Card中有跨Region引用。G1的堆被划分为Card（每512字节一个Card），当写操作产生跨Region引用时，Write Barrier将目标Card标记为dirty，并记录到源Region的RSet中。精度与开销的权衡：①细粒度PRT——每个Card单独记录，扫描精确但元数据大；②粗粒度PRT——只记录「哪个Region有引用」不记Card，扫描时需要扫描整个引用Region，元数据小但扫描放大；③三级退化——当引用Card数超过阈值或引用Region数超过阈值时自动降级。
</Answer>

**问题 3**：G1的Write Barrier如何工作？它在RSet维护中起什么作用？

<Answer>
G1使用两种Write Barrier：①SATB Write Barrier——用于并发标记阶段，在引用被覆盖前将旧值存入SATB队列；②RS Write Barrier——用于RSet维护，在写入新引用后，如果引用是跨Region的，将目标Card标记为dirty并加入DCQ。工作流程：G1PostBarrierInlining::post_barrier在每次写引用后执行——判断源对象和目标对象是否在不同Region，如果是则将目标Card加入DCQ。Refine线程异步消费DCQ，将dirty Card更新到对应Region的RSet中。作用：Write Barrier是G1维护RSet的唯一入口，没有它G1无法知道跨Region引用关系。代价：每次写操作都增加额外开销。
</Answer>

**问题 4**：RSet的内存占用如何估算？什么情况下RSet会膨胀？如何控制？

<Answer>
内存占用估算：G1中每个Region的RSet平均占用Region大小的1%-5%，极端情况下可达20%。膨胀场景：①大量短生命周期跨Region引用——如数组遍历修改不同Region的对象；②大对象（Humongous）被广泛引用——一个Humongous对象跨越多Region，每个引用它的Region都要记录RSet；③对象关系图高度互联——如HashMap/缓存结构。控制参数：`-XX:G1RSetUpdatingPauseTimePercent`（控制Refine线程在GC暂停中更新RSet的时间比例，默认10%）；`-XX:G1ConcRefinementThreads`（控制并发Refine线程数）；`-XX:G1HeapRegionSize`增大Region减少跨引用频率。可通过jcmd GC.heap_info查看RSet统计。
</Answer>

<Glossary>
<GlossaryItem term="RSet">Remembered Set——反向引用索引，记录「哪些其他Region的哪些Card引用了本Region的对象」。让G1回收某个Region时只需扫描RSet指向的Card，避免全堆扫描。</GlossaryItem>
<GlossaryItem term="卡表">Card Table——堆按512字节划分为Card，写操作产生跨Region引用时通过Write Barrier将目标Card标记为dirty。RSet按Card粒度精确记录引用位置。</GlossaryItem>
<GlossaryItem term="Write Barrier">每次写引用操作时执行的额外逻辑。G1有两种：SATB Barrier（并发标记用，捕获旧引用）和RS Barrier（RSet维护用，标记dirty Card加入DCQ）。</GlossaryItem>
<GlossaryItem term="PRT三级退化">Sparse（细粒度，每Card单独记录）→Fine（中粒度，Card位图按Region分组）→Coarse（粗粒度，仅Region级位图）。退化降低元数据开销但增加扫描放大。</GlossaryItem>
<GlossaryItem term="DCQ">Dirty Card Queue——Write Barrier将跨Region引用的dirty Card加入DCQ，Refine线程异步消费DCQ更新RSet。</GlossaryItem>
</Glossary>
