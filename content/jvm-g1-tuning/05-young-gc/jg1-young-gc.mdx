## 直觉引入

Young GC像「早市清场」。市场（Eden Region）摆满了摊位（对象），清场时（STW暂停所有线程）先找出还在营业的摊位（存活对象，通过GC Roots和RSet扫描），把它们搬到隔壁临时市场（Survivor Region），然后把原市场整个清空（Eden Region回Free List）。搬运时用推车（PLAB）批量运输提高效率，每个推车在目标市场预占一块空间。

## 触发条件

```text
触发：Eden Region 分配满（_young_list_target_length 达到上限）

流程：
  Mutator 线程请求分配新对象
  → Eden 无可用 Region
  → 触发 Young GC（G1CollectedHeap::do_collection_pause）
  → 所有 Mutator 线程进入安全点（STW）
  → GC 线程接管执行回收
```

## 七步执行流程

```text
源码入口：G1CollectedHeap::do_collection_pause

① 安全点暂停（STW）
   所有 Mutator 线程进入安全点
   G1VMThread 接管执行 GC

② 根扫描（Root Scanning）
   从 GC Roots 出发标记直接引用的新生代对象
   GC Roots = 线程栈 / 静态字段 / JNI 全局引用 / 同步监控器

③ RSet 扫描（Scan RSets）
   扫描各 Old Region 的 RSet 中记录的引用新生代 Region 的 Card
   找到跨代引用（Old → Young）
   ⚠ 这是停顿时间的主要贡献者

④ 更新 RSets（Update RSets）
   处理 DCQ 中积压的 dirty Card
   将新产生的跨 Region 引用更新到对应 RSet
   部分必须在 STW 中完成（并发 Refine 线程来不及的）

⑤ 对象复制 / evacuation
   Eden 和 Survivor 中的存活对象复制到新 Region
   使用 PLAB（G1ParGCAllocBuffer）批量分配
   存活对象 → Survivor（年龄<MaxTenuringThreshold 且有空间）
            → Old（晋升，年龄达阈值或 Survivor 空间不足）

⑥ 引用处理（Reference Processing）
   SoftReference / WeakReference / PhantomReference
   按引用类型和策略决定是否回收

⑦ 重置与统计（Reset & Accounting）
   清空原 Eden Region → Free List
   更新 Eden / Survivor 大小目标（自适应调整）
   记录本次 GC 数据到 G1Analytics
```

<Callout type="insight">
**全程STW**：Young GC的七个阶段全部在STW中执行，没有并发阶段。停顿时间由回收的Region数量和RSet扫描量决定。G1通过控制Eden大小（自适应调整）来间接控制Young GC的停顿时间。
</Callout>

## evacuation 疏散复制

```text
源码：G1ParEvacuateFollowersClosure + G1ScanEvacuatedRegionClosure
      G1ParScanThreadState::copy_to_survivor_space

分配目标空间：
  每个 GC 线程分配一个 PLAB（G1ParGCAllocBuffer）
  在目标 Survivor 或 Old Region 中预分配一段空间
  复制对象时通过指针碰撞（bump-the-pointer）在 PLAB 内分配

复制决策：
  对象年龄 < MaxTenuringThreshold 且 Survivor 有空间
    → 复制到 Survivor Region，年龄 +1
  对象年龄 ≥ MaxTenuringThreshold 或 Survivor 空间不足
    → 晋升到 Old Region

复制过程：
  ① 在目标 Region 的 PLAB 中分配空间
  ② memcpy 复制对象头和对象体
  ③ 更新对象头的 Mark Word（重置 hashcode/锁信息等）
  ④ 在旧对象位置记录 forwarding pointer（指向新地址）
  ⑤ 递归扫描新对象的引用，继续复制（Cheney 算法变体）

前向指针（Forwarding Pointer）：
  防止同一对象被多个 GC 线程重复复制
  第一次复制时用 CAS 设置 forwarding pointer
  后续线程发现已有 forwarding pointer → 直接使用新地址
```

## RSet 扫描——停顿的主要贡献者

```text
源码：G1RemSet::scan_rem_set → G1ScanRSForRegionClosure

流程：
  ① 遍历 CSet 中每个 Region 的 RSet
     RSet 记录了 "哪些其他 Region 的哪些 Card 引用了本 Region"
  ② 对每个引用 Region 的 Card：
     Fine-grained PRT → 精确定位到 Card 中的对象引用
     Coarse PRT → 需扫描整个 Region 的 dirty Card
  ③ 同时处理 DCQ 中积压的 dirty Card（G1RemSet::refine_card）
  ④ 合并 RSet 扫描和 DCQ Refinement 减少重复扫描

为什么是停顿主要贡献者：
  ① RSet 扫描量与跨代引用密度成正比
     老年代有大量对象引用新生代 → RSet 条目多 → 扫描量大
  ② Coarse PRT 放大效应
     某 Region 被大量其他 Region 引用 → 退化为 Coarse → 扫描整个 Region
  ③ DCQ 积压
     并发 Refine 线程来不及处理 → 积压的 dirty Card 必须在 STW 中处理

优化方向：
  控制 RSet 粒度（-XX:G1RSetUpdatingPauseTimePercent）
  减少不必要的跨 Region 引用（合理设置 Region 大小）
```

## Eden/Survivor 自适应调整

```text
源码：G1Policy::record_collection_pause_end
      → G1YoungGenSizePolicy::compute_eden_space

每次 Young GC 后：
  ① 收集数据
     G1Analytics 记录：停顿时间 / 回收 Region 数 / 存活对象量
                       根扫描时间 / RSet 扫描时间

  ② 计算目标 Eden 大小
     上次停顿 << MaxGCPauseMillis → 增加 Eden（减少 GC 频率，提升吞吐）
     上次停顿 ≈ MaxGCPauseMillis → 减少 Eden（降低单次 GC 时间）
     
     _young_list_target_length = 自适应计算的 Eden Region 数

  ③ Survivor 调整
     根据 TargetSurvivorRatio 和存活对象量调整 Survivor Region 数

  ④ 晋升阈值动态化
     Survivor 空间紧张 → 提前晋升到 Old（降低 MaxTenuringThreshold 效果）

关键源码：
  G1Policy::calculate_young_list_desired_min_length  → 最小 Eden Region 数
  G1Policy::calculate_young_list_desired_max_length  → 最大 Eden Region 数（受停顿约束）
```

<Callout type="trap">
**陷阱**：增大Eden不一定让GC更慢。G1的自适应策略会根据历史数据估算——如果存活对象少（大部分对象朝生夕死），Eden增大后单次GC回收更多对象但复制量增加不多，反而减少GC频率提升吞吐。但如果存活对象多（如缓存），Eden增大意味着更多存活对象需要复制，停顿时间反而增加。
</Callout>

<Exercises>
**问题 1**：G1 Young GC的触发条件和执行流程是什么？

<Answer>
触发条件：Eden Region分配满（_young_list_target_length达到上限），应用线程请求分配新对象时Eden无可用空间，触发Young GC。执行流程（源码G1CollectedHeap::do_collection_pause）：①准备阶段——Mutator线程在安全点暂停；②根扫描——从GC Roots出发标记直接引用的新生代对象；③RRS扫描——扫描各Old Region的RSet中记录的引用新生代Region的Card；④更新RSets——处理DCQ中的dirty Card；⑤对象复制——将Eden和Survivor中的存活对象复制到新的Survivor或Old Region；⑥引用处理——处理Soft/Weak/Phantom Reference；⑦重置——清空原Eden Region回Free List，更新Eden/Survivor大小目标。整个Young GC全程STW。
</Answer>

**问题 2**：G1 Young GC源码中evacuation阶段如何实现？对象如何从Eden复制到Survivor/Old？

<Answer>
evacuation阶段源码（G1ParEvacuateFollowersClosure + G1ParScanThreadState::copy_to_survivor_space）：①分配目标空间——为每个GC线程分配G1ParGCAllocBuffer（PLAB），在目标Survivor或Old Region中预分配空间，通过指针碰撞在PLAB内分配；②扫描根——GC线程从GC Roots和RSet出发找到存活对象；③复制决策——对象年龄未达MaxTenuringThreshold且Survivor有空间→复制到Survivor Region；对象年龄达阈值或Survivor空间不足→晋升到Old Region；④对象复制——在目标Region的PLAB中分配空间，memcpy复制对象头和对象体，更新Mark Word；⑤引用更新——将源对象的所有引用者更新为新地址（通过RSet反向定位）；⑥前向指针——旧对象位置记录forwarding pointer指向新地址，防止同一对象被多次复制。
</Answer>

**问题 3**：G1 Young GC中RSet扫描的源码流程是什么？为什么这一步是停顿时间的主要贡献者？

<Answer>
RSet扫描源码流程（G1RemSet::scan_rem_set → G1ScanRSForRegionClosure）：①遍历CSet中每个Region的RSet——RSet记录了哪些其他Region的哪些Card引用了本Region；②对每个引用Region的Card——Fine-grained PRT精确定位到Card中的对象引用，Coarse PRT需扫描整个Region的dirty Card；③更新RSets——同时处理DCQ中积压的dirty Card；④合并处理——将RSet扫描和DCQ Refinement合并为一个阶段减少重复扫描。为什么是停顿主要贡献者：①RSet扫描量与跨代引用密度成正比——老年代有大量对象引用新生代时RSet条目多；②Coarse PRT放大效应——退化为Coarse PRT需扫描整个Region而非精确Card；③DCQ积压——并发Refine线程来不及处理时必须在STW中处理。
</Answer>

**问题 4**：G1 Young GC后Eden/Survivor的大小如何自适应调整？

<Answer>
自适应调整源码（G1Policy::record_collection_pause_end → G1YoungGenSizePolicy::compute_eden_space）：①收集数据——每次Young GC后G1Analytics记录停顿时间、回收Region数、存活对象量、根扫描时间、RSet扫描时间等；②计算目标Eden大小——G1AdaptiveSizePolicy根据历史平均停顿时间与MaxGCPauseMillis的比较调整下次Young GC的目标Eden Region数。如果上次停顿远低于目标→增加Eden（减少GC频率提升吞吐）；如果上次停顿接近或超过目标→减少Eden（降低单次GC时间）；③Survivor调整——根据存活对象量和TargetSurvivorRatio调整Survivor Region数；④晋升阈值动态化——Survivor空间紧张时提前晋升到Old。关键源码：G1Policy::calculate_young_list_desired_min_length和calculate_young_list_desired_max_length。
</Answer>

<Glossary>
<GlossaryItem term="Young GC七步流程">安全点暂停→根扫描→RSet扫描→更新RSets→对象复制(evacuation)→引用处理→重置统计。全程STW，无并发阶段。</GlossaryItem>
<GlossaryItem term="evacuation">疏散复制——Eden/Survivor中存活对象通过PLAB批量复制到新Region。使用Chenney算法变体递归扫描引用，前向指针防止重复复制。</GlossaryItem>
<GlossaryItem term="PLAB">G1ParGCAllocBuffer——每个GC线程在目标Region预分配的一段空间，对象复制时通过指针碰撞在PLAB内分配，减少全局锁竞争。</GlossaryItem>
<GlossaryItem term="G1AdaptiveSizePolicy">根据历史GC数据动态调整Eden/Survivor大小。停顿远低于目标→增大Eden（减频率提吞吐），接近目标→减小Eden（降停顿）。</GlossaryItem>
</Glossary>
