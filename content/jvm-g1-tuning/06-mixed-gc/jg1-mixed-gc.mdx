## 直觉引入

Mixed GC像「深度清运日」。日常清运（Young GC）只清生活垃圾区（Eden+Survivor），深度清运日除了清生活垃圾区，还额外清理一部分积存仓库（Old Region）。清理哪些仓库？先看垃圾清单（并发标记统计的候选列表），按「垃圾多/清运快」排序（回收效率降序），在规定时间内（MaxGCPauseMillis）尽量多清。清不完的留到下次深度清运日，直到清单清完。

## Mixed GC vs Young GC

```text
              Young GC                    Mixed GC
CSet组成      Eden + Survivor              Eden + Survivor + 部分Old
触发时机      Eden 分配满                  并发标记周期完成后的疏散阶段
回收目标      仅新生代                      新生代 + 增量回收老年代
设计目的      日常回收                      用多次短停顿替代一次Full GC
频率          高                           一个并发标记周期内多次（默认8次）
```

## CSet 老年代 Region 选择策略

```text
源码：G1Policy::finalize_collection_set
      G1Policy::finalize_old_collection_set

① 候选列表
   并发标记 Cleanup 阶段根据各 Old Region 存活率排序
   存活率低（垃圾多）的优先
   形成 _collection_set_candidates 列表

② 时间预算计算
   预算 = MaxGCPauseMillis（如 200ms）
        - 新生代 Region 预估回收时间
        - 固定开销（根扫描 / RSets 更新等）
   = 可用于 Old Region 回收的剩余预算

③ 贪心选择
   按候选列表顺序（垃圾多→少）
   逐个估算 Old Region 回收耗时
   源码：G1Analytics::predict_region_copy_time_ms
   加入后总预估时间 ≤ 预算 → 纳入 CSet
   加入后总预估时间 > 预算 → 停止选择

④ 数量上限
   G1MixedGCCountTarget=8（默认）
   每次最多选候选总量的 1/8
   期望分 8 次 Mixed GC 回收完所有候选

⑤ 存活率过滤
   G1MixedGCLiveThresholdPercent=85%（默认）
   存活率 > 85% 的 Old Region 不纳入 CSet
   回收性价比太低（复制存活对象太多）
```

## 三种终止条件

```text
源码：G1Policy::finalize_old_collection_set 中的退出条件

① 时间预算耗尽
   加入下一个 Old Region 后预估总时间 > MaxGCPauseMillis
   → 停止选择
   → 剩余候选保留在 _collection_set_candidates
   → 下一次 Mixed GC 继续从上次位置选择
   → 产生浮动垃圾（下轮回收）

② 候选列表耗尽
   所有候选 Old Region 都已纳入 CSet
   → 本轮 Mixed GC 后老年代清理完毕
   → 并发标记周期结束
   → 等待下一次 IHOP 触发新的并发标记周期

③ 存活率过高
   剩余候选 Old Region 存活率 > G1MixedGCLiveThresholdPercent(85%)
   → 回收性价比太低
   → 终止本轮 Mixed GC
   → 这些 Region 在下一次并发标记周期重新评估
   → 如果存活率降低（更多对象死亡）可能重新纳入候选
```

<Callout type="insight">
**核心理念**：G1不会强制回收所有垃圾Region，而是优先回收性价比高的，保证停顿可控。Mixed GC是「增量回收」——分多次逐步清理老年代，每次只回收一部分，避免一次Full GC的长停顿。浮动垃圾是可接受的代价。
</Callout>

## evacuation 差异

```text
Mixed GC 与 Young GC 共用同一个 evacuation 代码路径
区别仅在 CSet 组成

源码：G1ParEvacuateFollowersClosure
      G1ParScanThreadState::copy_to_survivor_space

对象复制决策（根据来源 Region 类型和年龄）：

  来自 Eden 的对象：
    年龄 < MaxTenuringThreshold 且 Survivor 有空间 → 复制到 Survivor
    否则 → 晋升到 Old Region

  来自 Survivor 的对象：
    年龄 < MaxTenuringThreshold 且 Survivor 有空间 → 复制到 Survivor（年龄+1）
    否则 → 晋升到 Old Region

  来自 Old Region 的对象（Mixed GC 特有）：
    → 直接复制到新 Old Region（不能回 Survivor）
    → 原 Old Region 清空回 Free List

evacuation 差异影响：
  ① CSet 更大 → 复制更多存活对象 → 耗时更长
  ② RSet 扫描量更大 → Old Region 的 RSet 条目更多
  ③ Old Region 存活率高 → 复制量大（大部分对象存活，只有少量垃圾可回收）
```

## Mixed GC 分批回收时间线

```text
并发标记周期完整时间线：

  并发标记 ──→ Mixed GC 1 ──→ Mixed GC 2 ──→ ... ──→ Mixed GC 8 ──→ 周期结束
  (识别候选)    (回收1/8)      (回收1/8)              (回收完)       (等待下次IHOP)

  ↑                                                                ↑
  IHOP 触发                                                     候选清空
  
  正常 Young GC 在 Mixed GC 之间穿插执行（Eden 满就触发）
```

<Callout type="trap">
**陷阱**：Mixed GC次数不是固定的8次。G1MixedGCCountTarget=8只是「期望值」，实际次数取决于：①候选Old Region总量；②每次选择是否因时间预算提前终止；③是否有Old Region存活率超过85%被跳过。可能少于8次（候选少），也可能多于8次（每次因预算选得少）。
</Callout>

<Exercises>
**问题 1**：G1 Mixed GC与Young GC的区别是什么？Mixed GC回收哪些Region？

<Answer>
核心区别：①CSet组成——Young GC的CSet只包含新生代Region（Eden+Survivor），Mixed GC的CSet包含新生代Region+部分老年代Region；②触发时机——Young GC在Eden满时触发，Mixed GC在并发标记周期完成后的疏散阶段触发；③回收目标——Young GC只回收新生代，Mixed GC增量回收老年代。Mixed GC回收的Region：所有Eden Region、所有Survivor Region、以及从CSet候选列表中按回收效率降序选择的部分Old Region（受MaxGCPauseMillis时间预算约束）。Mixed GC的设计目的：用多次短停顿的Mixed GC替代一次长停顿的Full GC，实现老年代的增量回收。
</Answer>

**问题 2**：Mixed GC的CSet中老年代Region的选择策略是什么？源码中如何控制选择数量？

<Answer>
选择策略（源码G1Policy::finalize_collection_set）：①候选列表——并发标记的Cleanup阶段根据各Old Region的存活率排序，存活率低（垃圾多）的优先；②时间预算——Mixed GC的停顿时间预算 = MaxGCPauseMillis - 新生代Region回收预估时间 - 固定开销；③贪心选择——按候选列表顺序，逐个估算Old Region的回收耗时，如果加入后总预估时间不超过时间预算则纳入CSet，否则停止；④数量上限——G1MixedGCCountTarget（默认8）控制期望分几次Mixed GC回收完所有候选Old Region，每次最多选择候选总量的1/target比例；⑤G1MixedGCLiveThresholdPercent（默认85%）——存活率超过此阈值的Old Region不纳入CSet。
</Answer>

**问题 3**：Mixed GC在什么情况下会终止？终止后剩余Old Region如何处理？

<Answer>
Mixed GC终止条件：①时间预算耗尽——加入下一个Old Region后预估总时间超过MaxGCPauseMillis，停止选择（留下浮动垃圾，下轮Mixed GC回收）；②候选列表耗尽——所有候选Old Region都已纳入CSet，本轮Mixed GC后老年代清理完毕，并发标记周期结束；③存活率过高——剩余候选Old Region的存活率超过G1MixedGCLiveThresholdPercent（默认85%），回收性价比太低，终止本轮Mixed GC。终止后剩余Old Region处理：①如果是条件①（时间预算），剩余候选Old Region保留在_collection_set_candidates列表，下一次Mixed GC继续；②如果是条件②（候选耗尽），并发标记周期结束，等待下一次IHOP触发；③如果是条件③（存活率高），这些Region会在下一次并发标记周期重新评估。
</Answer>

**问题 4**：Mixed GC的evacuation阶段与Young GC有何不同？Old Region的存活对象复制到何处？

<Answer>
evacuation差异：①CSet更大——Mixed GC的CSet包含Old Region，evacuation需要复制更多存活对象（Old Region存活率通常远高于Eden），复制耗时更长；②RSet扫描量更大——Old Region的RSet条目更多；③目标Region不同——Young GC中存活对象复制到Survivor或Old Region，Mixed GC中Old Region的存活对象只能复制到新的Old Region（不能再回到Survivor）。源码处理（G1ParEvacuateFollowersClosure）：Mixed GC和Young GC共用同一个evacuation代码路径，区别仅在CSet组成。G1ParScanThreadState::copy_to_survivor_space根据对象来源Region类型和年龄决定目标Region类型——来自Eden/Survivor的对象按年龄判断，来自Old Region的对象（Mixed GC特有）直接复制到新Old Region；evacuation后原Old Region清空回Free List。
</Answer>

<Glossary>
<GlossaryItem term="Mixed GC">G1增量回收老年代的GC，CSet=Eden+Survivor+部分Old Region。在一个并发标记周期内分多次执行（默认8次），用短停顿替代Full GC长停顿。</GlossaryItem>
<GlossaryItem term="CSet老年代选择">从候选Old Region（并发标记选出）中按回收效率（垃圾量/预估耗时）降序贪心选择，受MaxGCPauseMillis时间预算和G1MixedGCCountTarget数量上限约束。</GlossaryItem>
<GlossaryItem term="三种终止条件">①时间预算耗尽（留浮动垃圾下轮回收）②候选列表耗尽（周期结束）③存活率>85%（性价比太低跳过）。</GlossaryItem>
<GlossaryItem term="G1MixedGCLiveThresholdPercent">Old Region存活率上限（默认85%），超过此值的Region不纳入CSet，因为复制存活对象太多回收性价比低。</GlossaryItem>
</Glossary>
