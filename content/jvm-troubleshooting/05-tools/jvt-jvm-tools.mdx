## 直觉引入

把 JVM 诊断工具想象成「医生的检查设备」。jps 是「挂号单」（列出有哪些病人/进程）；jstat 是「心电监护仪」（实时看 GC 和类加载的动态变化）；jmap 是「X光片」（拍堆内存快照，看哪里长了东西）；jstack 是「神经系统检查」（看所有线程在干什么、有没有卡住/死锁）；jcmd 是「万能检查仪」（JDK7+ 统一入口，替代以上所有）。可视化工具里，JConsole 是「便携监护仪」（简单看概览），VisualVM 是「综合检查台」（监控+采样），MAT 是「病理分析仪」（深度分析堆 dump 找泄漏），Arthas 是「微创探针」（生产环境热诊断，不停机）。

## JDK 命令行工具

```text
jps       列 JVM 进程，显示 pid + 主类名
          jps -l 全限定名，-v 显示 JVM 参数

jstat     监控 GC 和类加载统计
          jstat -gc <pid> 1000  每秒打印堆各区域使用量和GC次数
          jstat -gcutil <pid>    显示百分比
          jstat -class <pid>     类加载统计
          观察GC趋势的首选

jmap      堆内存分析
          jmap -heap <pid>              打印堆配置和各代使用
          jmap -histo:live <pid>        存活对象直方图(按类统计实例数和字节数)
          jmap -dump:format=b,file=dump.hprof <pid>  导出堆dump供MAT分析

jstack    线程栈 dump
          jstack <pid>     打印所有线程调用栈和锁状态
          jstack -l <pid>  额外锁信息
          死锁和线程卡住诊断利器

jcmd      JDK7+ 统一命令工具(首选)
          jcmd <pid> help              列出所有命令
          jcmd <pid> GC.heap_dump      替代 jmap dump
          jcmd <pid> Thread.print      替代 jstack
          jcmd <pid> VM.flags          看 JVM 参数
          jcmd <pid> JFR.start         启动飞行记录
```

<Callout type="insight">
**jcmd 是新一代首选**：功能更全且支持动态诊断（如运行时改日志级别、启动 JFR），可替代 jps/jstat/jmap/jstack 的部分功能。
</Callout>

## CPU 热点定位流程

生产环境不停机定位 CPU 热点代码的标准流程：

```text
1. top            找 CPU 高的 Java 进程 pid
2. top -Hp <pid>  找该进程内 CPU 高的线程 tid
3. printf '%x' <tid>  tid 转十六进制(如 0x1a2b)
4. jstack <pid> | grep -A 30 nid=0x1a2b  找该线程调用栈，栈顶=热点

替代方案用 Arthas（无需手动转 nid）：
  thread -n 3              打印 CPU 占用最高的3个线程及其栈
  trace <类> <方法>        看方法内部调用链耗时
  profiler start/stop      生成火焰图，横轴宽的方法是热点
```

<Callout type="trap">
**误区**：生产环境随意 heapdump。heapdump 会触发 STW（全堆暂停），高流量时可能导致服务超时。jstack 影响小但 heapdump 要在低峰期或做好降级准备。
</Callout>

## 四款可视化/在线工具对比

```text
JConsole    JDK自带，JMX实时监控内存/线程/类加载/MBean
            优点：简单开箱即用  缺点：只能监控不能深度分析
            适用：快速看概览

VisualVM    JDK自带(JDK9+单独下载)，监控+dump分析一体
            可看堆直方图/线程dump/CPU内存采样/插件扩展
            适用：中度分析

MAT         Eclipse出品，专攻堆dump深度分析
            Dominator Tree找内存大户/Leak Suspects自动报告泄漏
            Shallow/Retained Heap计算/GC Roots路径追踪
            适用：内存泄漏排查权威工具(不监控实时)

Arthas      阿里开源，运行时热诊断(无需改代码无需重启)
            dashboard实时概览/thread线程分析/jad反编译
            watch方法监控入参返回值/trace调用链耗时
            profiler火焰图/heapdump堆转储
            适用：生产环境在线诊断(不停机)
```

## 工具选择决策

```text
快速看概览         → JConsole / VisualVM
内存泄漏深度分析    → MAT（dump 离线分析）
生产在线热诊断     → Arthas（thread/trace/profiler 不停机）
GC趋势观察         → jstat -gc
死锁/线程卡住      → jstack（连续三次）
堆对象分析         → jmap -histo / jmap -dump
```

<Exercises>
**问题 1**：jps、jstat、jmap、jstack、jcmd 各自的作用是什么？

<Answer>
①jps——列 JVM 进程，显示 pid 和主类名；②jstat——监控 GC 和类加载统计，jstat -gc 每秒打印堆各区域使用量和 GC 次数，是观察 GC 趋势的首选；③jmap——堆内存分析，-heap 打印堆配置，-histo:live 打印存活对象直方图，-dump 导出堆 dump 供 MAT 分析；④jstack——线程栈 dump，打印所有线程调用栈和锁状态，是死锁和线程卡住诊断利器；⑤jcmd——JDK7+ 统一命令工具，可替代上述工具，功能更全且支持动态诊断（JFR.start 启动飞行记录）。
</Answer>

**问题 2**：如何用 jstack 诊断线程问题？什么情况下要连续 dump 三次？

<Answer>
jstack 诊断流程：①jps 找 pid；②jstack <pid> 打印线程栈；③分析输出——线程状态（RUNNABLE/BLOCKED/WAITING）、调用栈、锁信息（waiting on/locked）。死锁 jstack 末尾自动检测打印 Found deadlock。CPU 高先 top -Hp 找线程 tid，printf '%x' 转十六进制，jstack 找 nid=0xtid 的线程看栈顶。连续 dump 三次的场景：①区分瞬时和持续状态——单次可能是瞬时快照，三次都卡在同一位置才是真问题；②死锁确认——三次都在就是稳定死锁；③性能热点确认——三次都在同一方法说明是真热点。命令：for i in 1 2 3; do jstack <pid> > t_$i.txt; sleep 2; done。
</Answer>

**问题 3**：对比 JConsole、VisualVM、MAT、Arthas 四款工具的特点和适用场景。

<Answer>
①JConsole——JDK自带，JMX实时监控，简单开箱即用但只能监控不能深度分析；②VisualVM——JDK自带，监控+dump分析一体，可看堆直方图/线程dump/采样，适合中度分析；③MAT——Eclipse出品，专攻堆dump深度分析，Dominator Tree找内存大户、Leak Suspects自动报告泄漏、Retained Heap计算、GC Roots路径追踪，是内存泄漏排查权威工具；④Arthas——阿里开源，运行时热诊断无需改代码无需重启，thread/trace/watch/profiler功能强大，适用生产环境在线诊断。选择：快速监控JConsole/VisualVM，内存泄漏MAT，生产在线热诊断Arthas。
</Answer>

**问题 4**：生产环境 CPU 飙高，如何在不重启应用的情况下定位到具体是哪段代码导致的？

<Answer>
不停机定位 CPU 热点标准流程：①top 找 CPU 高的 Java 进程 pid；②top -Hp <pid> 找该进程内 CPU 高的线程 tid；③printf '%x' <tid> 转十六进制得 nid；④jstack <pid> | grep -A 30 nid=0xtid 找该线程调用栈，栈顶方法就是热点。若热点不明显连续 jstack 三次取交集。替代方案用 Arthas 更简单：①arthas-boot attach 到目标 JVM；②thread -n 3 打印 CPU 占用最高3个线程及栈；③trace <类> <方法> 看方法内部调用链耗时；④profiler start 生成火焰图，横轴宽的方法是热点。常见根因：死循环/正则回溯（栈顶在业务方法）、GC频繁（栈顶在GC线程，看jstat）、锁竞争自旋（多线程BLOCKED在同一锁）。
</Answer>
