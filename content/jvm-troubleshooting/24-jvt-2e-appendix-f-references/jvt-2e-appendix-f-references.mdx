## 为什么从“调查引用审计台”开始

附录F 参考资料要解决的是把书目、规范、工具手册和调查工件登记为可追溯引用，区分事实来源、案例输入与本地推断。 直觉上，最后出现的异常、最热的方法和最大的对象都只是信号；根因必须解释正常与故障时间线的第一个分叉，并能让原反例在最小修复后稳定转为通过。

先预测：把来源身份从“稳定链接”切换到“版本化一手源”，引用可追溯度和权威误借风险将怎样变化？运行前写下能推翻假设的观察，结果不符时修改假设而不是删除失败样本。

## 官方目录逐项深读

### Appendix F: references

**四级证据 1/1。** Appendix F: references：引用登记来源身份和直接支持的主张，不能用权威链接替代本地因果证据。本节点以“ISBN”为焦点，运行`claim -> source -> version -> local evidence`或等价探针，保存原始输出、时间窗、扰动预算和适用边界。

验证 Appendix F: references 时，先预测它在 登记来源 阶段怎样改变引用可追溯度；随后只调整来源身份或本地验证。若“把目录或工具页面的存在误报为对本地根因的直接证明”没有制造预期首错，就撤回当前假设并检查替代解释。

## 最小调查切片

```yaml
claim: thread-dump-command
source: Oracle JDK 25 jcmd manual
verified_with: jcmd <pid> Thread.print -l
```

附录F 参考资料运行该切片时要固定主机、容器、进程、JDK、应用commit、配置、负载与时间窗；所有日志、JFR、线程转储和堆转储都写入受控目录并登记大小、哈希、权限和删除期限。命令失败或超出扰动预算时立即停止，不把半份工件包装成完整证据。

## 三个必须主动触发的误区

<Callout type="trap" title="信号不等于根因">
  附录F 参考资料中的引用可追溯度只能缩小假设；必须用源码、竞争假设和反例解释为什么该信号出现。
</Callout>

<Callout type="trap" title="调查动作改变现场">
  把目录或工具页面的存在误报为对本地根因的直接证明。保存工具配置和扰动预算，必要时退回低侵入采样，并在未附加工具的运行中确认首错。
</Callout>

<Callout type="trap" title="修复后只看告警消失">
  附录F 参考资料的修复要重放原负载、原故障和正常基线；资源、线程、数据与外部副作用都恢复，才满足引用只支持其直接陈述的事实，本地因果结论仍由运行证据承担。
</Callout>

## 练习、答案与节点验证

<Exercises>

**问题 1：假设与单变量。** 怎样验证来源身份而不让本地验证混入因果结论？

<Answer>
  固定应用commit、JDK、负载、时间窗和本地验证，只把来源身份从“稳定链接”切到“版本化一手源”；保存引用可追溯度、权威误借风险和首个分叉。
</Answer>

**问题 2：逐节点四级证据。** 正式目录节点怎样从出现升级为解释、交互和练习验证？

<Answer>
1. Appendix F: references：用ISBN定位观察点，运行`claim -> source -> version -> local evidence`或同义探针，补齐基线、故障、恢复和复位证据。
</Answer>

**问题 3：恢复闭环。** 注入“把目录或工具页面的存在误报为对本地根因的直接证明”后如何证明根因和修复？

<Answer>
  沿登记来源、核对身份、绑定主张、保存版本、审计引用定位首错，只改变最小因果前提；随后用相同输入重放正常、故障、恢复和复位四条轨迹。只有引用只支持其直接陈述的事实，本地因果结论仍由运行证据承担再次成立，调查才通过。
</Answer>

</Exercises>
