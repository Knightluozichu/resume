## 为什么从“Java故障综合答辩台”开始

《Troubleshooting Java（第2版）》全书总复习要解决的是在一次综合事件中完成假设树、日志、JFR、线程/堆证据、跨服务追踪、修复与恢复交接。 直觉上，最后出现的异常、最热的方法和最大的对象都只是信号；根因必须解释正常与故障时间线的第一个分叉，并能让原反例在最小修复后稳定转为通过。

先预测：把证据层级从“资源与转储”切换到“跨服务与数据”，根因复现率和证据缺口率将怎样变化？运行前写下能推翻假设的观察，结果不符时修改假设而不是删除失败样本。

## 最小调查切片

```bash
jcmd -l
jcmd <pid> JFR.start duration=60s filename=incident.jfr
jcmd <pid> Thread.print -l > threads.txt
```

《Troubleshooting Java（第2版）》全书总复习运行该切片时要固定主机、容器、进程、JDK、应用commit、配置、负载与时间窗；所有日志、JFR、线程转储和堆转储都写入受控目录并登记大小、哈希、权限和删除期限。命令失败或超出扰动预算时立即停止，不把半份工件包装成完整证据。

## 三个必须主动触发的误区

<Callout type="trap" title="信号不等于根因">
  《Troubleshooting Java（第2版）》全书总复习中的根因复现率只能缩小假设；必须用源码、竞争假设和反例解释为什么该信号出现。
</Callout>

<Callout type="trap" title="调查动作改变现场">
  修复后只看告警消失，没有重放原负载、反例和数据对账。保存工具配置和扰动预算，必要时退回低侵入采样，并在未附加工具的运行中确认首错。
</Callout>

<Callout type="trap" title="修复后只看告警消失">
  《Troubleshooting Java（第2版）》全书总复习的修复要重放原负载、原故障和正常基线；资源、线程、数据与外部副作用都恢复，才满足原始症状由最小修复消失且正常基线、资源和数据状态全部恢复。
</Callout>

## 练习、答案与节点验证

<Exercises>

**问题 1：假设与单变量。** 怎样验证证据层级而不让闭环程度混入因果结论？

<Answer>
  固定应用commit、JDK、负载、时间窗和闭环程度，只把证据层级从“资源与转储”切到“跨服务与数据”；保存根因复现率、证据缺口率和首个分叉。
</Answer>

**问题 2：逐节点四级证据。** 正式目录节点怎样从出现升级为解释、交互和练习验证？

<Answer>
1. Freeze the incident baseline：用baseline定位观察点，运行`incident bundle: versions + timeline + raw evidence + replay`或同义探针，补齐基线、故障、恢复和复位证据。
2. Build competing root-cause hypotheses：用logs定位观察点，运行`incident bundle: versions + timeline + raw evidence + replay`或同义探针，补齐基线、故障、恢复和复位证据。
3. Capture low-overhead runtime evidence：用JFR定位观察点，运行`incident bundle: versions + timeline + raw evidence + replay`或同义探针，补齐基线、故障、恢复和复位证据。
4. Escalate to thread or heap artifacts safely：用dump定位观察点，运行`incident bundle: versions + timeline + raw evidence + replay`或同义探针，补齐基线、故障、恢复和复位证据。
5. Correlate services and data side effects：用trace定位观察点，运行`incident bundle: versions + timeline + raw evidence + replay`或同义探针，补齐基线、故障、恢复和复位证据。

</Answer>

**问题 3：恢复闭环。** 注入“修复后只看告警消失，没有重放原负载、反例和数据对账”后如何证明根因和修复？

<Answer>
  沿冻结事件、建立时间线、定位首错、修复反证、恢复交接定位首错，只改变最小因果前提；随后用相同输入重放正常、故障、恢复和复位四条轨迹。只有原始症状由最小修复消失且正常基线、资源和数据状态全部恢复再次成立，调查才通过。
</Answer>
