## 三条核心主线

<Callout type="info" title="三条核心主线">

贯穿全书的三条主线，回答 Kong 的三个核心问题：

1. **主线一 · 代理路由**：`Route → Service → Upstream → Target` — 回答「请求怎么转发」
2. **主线二 · 插件扩展**：`Plugin → Consumer → Credential → ACL` — 回答「横切关注点怎么处理」
3. **主线三 · 部署运维**：`DB/DB-less → Cluster → Hybrid → Mesh` — 回答「怎么部署、怎么扩展」

</Callout>

### 三个交汇点

| 交汇点 | 涉及主线 | 意义 |
|--------|----------|------|
| Route-Service-Plugin | 代理路由 ↔ 插件扩展 | 路由匹配成功后触发插件链执行，是请求处理的枢纽 |
| Consumer-Credential-Plugin | 插件扩展 ↔ 安全流量 | 凭证触发认证插件，认证通过后 ACL 控制访问权限 |
| DB-less-Hybrid-Mesh | 部署运维 ↔ 扩展能力 | 声明式配置 + 控制面数据面分离 + 网格全栈治理 |

## Kong 核心设计哲学

Kong 的四大技术特点：

1. **OpenResty 架构** — Nginx 事件驱动 + LuaJIT 即时编译，单机可达数万 RPS
2. **插件化扩展** — 横切关注点全部通过插件实现，按 priority 排序在 Nginx 生命周期执行
3. **数据模型抽象** — Service/Route/Consumer/Plugin/Upstream 五大核心实体，解耦路由与后端
4. **多模式部署** — DB/DB-less/Hybrid 适配从开发到生产到云原生的全场景

<Glossary>

<GlossaryItem term="OpenResty">
Nginx + LuaJIT + Lua 库的组合，让 Nginx 可以用 Lua 脚本动态处理请求。Kong 底层运行时。
</GlossaryItem>

<GlossaryItem term="Route-Service-Plugin">
Kong 三大核心实体的关系链：Route（入口匹配）→ Service（出口路由）→ Plugin（横切逻辑），是请求处理的基础抽象。
</GlossaryItem>

<GlossaryItem term="DB-less 模式">
不使用数据库，配置通过声明式 YAML 文件加载到内存的部署模式。适合 K8s/GitOps/安全要求高的场景。
</GlossaryItem>

<GlossaryItem term="Hybrid 模式">
控制面（CP）与数据面（DP）分离的部署模式。CP 运行 Admin API + 数据库，DP 运行 Proxy 无 Admin API，适合大规模多地域部署。
</GlossaryItem>

</Glossary>
