## 什么是 API 网关

<KgaApiGatewayIntroDiagram />

API 网关是微服务架构中的 **统一入口层**，位于客户端与后端微服务之间，作为所有外部请求的反向代理和流量管理枢纽。

<Callout type="info" title="没有 API 网关时会怎样">

- 客户端需直接调用多个微服务，地址分散、协议多样
- 认证、限流、日志等逻辑在每个微服务中重复实现
- 后端服务拆分合并时客户端必须跟着改
- 外部 HTTP 请求需转换为内部 gRPC 等协议

API 网关将这些问题集中到一层解决。

</Callout>

## 五大核心职责

### 1. 反向代理与路由

接收所有外部请求，根据 URL 路径、HTTP 方法、Host 头等匹配规则将请求转发到对应的后端微服务。

```
Client → GET /api/v1/users/123
         ↓
    API 网关 (路由匹配 /api/v1/users → 用户服务)
         ↓
    用户服务 http://user-service:8080/users/123
```

### 2. 认证与授权

集中处理身份认证（JWT/OAuth2/Key Auth），验证请求者身份和访问权限，微服务无需各自实现认证逻辑。

### 3. 流量控制

限流（Rate Limiting）防止后端被压垮，熔断（Circuit Breaking）防止级联故障，缓存（Caching）减少后端压力。

### 4. 安全防护

CORS 跨域控制、IP 黑白名单、Bot 检测、TLS 终止，保护后端服务免受恶意攻击。

### 5. 可观测性

统一日志记录、指标采集（Prometheus）、分布式追踪（Zipkin），全链路请求可视化。

## Kong 是什么

Kong 是一个 **开源的、云原生的、高性能 API 网关**，基于 OpenResty（Nginx + LuaJIT）构建。

### 核心特性

| 特性 | 说明 |
|------|------|
| 高性能 | Nginx 事件驱动，单机可达数万 RPS，亚毫秒级延迟 |
| 插件化架构 | 认证/安全/流量/可观测全部以插件提供，Lua 编写，热加载 |
| 多协议 | HTTP/HTTPS、gRPC、WebSocket、TCP、UDP |
| 多平台 | Docker、Kubernetes、VM 裸机 |
| Admin API | RESTful 管理接口，支持 CI/CD 自动化 |
| 生态 | Kong Mesh（Service Mesh）、Kong Enterprise（企业版） |

## Kong vs Nginx

| 维度 | Nginx | Kong |
|------|-------|------|
| 定位 | 通用 Web 服务器/反向代理 | API 网关 |
| 配置 | nginx.conf 文件 | Admin API / 声明式配置 |
| 插件 | 手写 Lua/第三方模块 | 100+ 官方插件，开箱即用 |
| 动态配置 | 修改需 reload | Admin API 动态生效 |
| 管理界面 | 无 | Admin API + Kong Manager |

<Callout type="tip" title="选型建议">

- 需要 API 网关功能（认证/限流/监控/多协议）→ **选 Kong**
- 只需简单反向代理和静态文件 → **选 Nginx**
- Kong 本质是 Nginx 的 API 网关超集——底层就是 Nginx + OpenResty

</Callout>

<Glossary>

<GlossaryItem term="南北向流量">
外部客户端到内部服务的入口流量（从外到内）。API 网关管理南北向流量。
</GlossaryItem>

<GlossaryItem term="横切关注点">
多个微服务都需要但又不属于业务核心的逻辑，如认证、限流、日志、监控。API 网关将这些逻辑集中处理。
</GlossaryItem>

<GlossaryItem term="LuaJIT">
Lua 语言的即时编译器（Just-In-Time），性能接近 C。OpenResty 用 LuaJIT 执行 Lua 脚本处理请求。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 什么是 API 网关？它在微服务架构中解决什么核心问题？

<Answer>

API 网关是微服务架构中的统一入口层，位于客户端与后端微服务之间。核心问题：入口统一（避免客户端直连多个微服务）、横切关注点集中（认证/限流/日志不再重复实现）、解耦（后端变化不影响客户端）、协议转换（外部 HTTP 转内部 gRPC）。

</Answer>

**问题 2：** Kong 与 Nginx 直接做反向代理相比有什么区别？

<Answer>

Kong 在 Nginx+OpenResty 之上封装了 API 网关抽象（Service/Route/Consumer/Plugin），通过 Admin API 管理无需手写 nginx.conf；提供 100+ 官方插件（JWT/限流/CORS 等）开箱即用；支持动态配置（Admin API 增删路由插件无需重启）。选 Kong 当需要 API 网关级别功能时开发效率高 10 倍，选 Nginx 当只需简单代理时更轻量。

</Answer>

</Exercises>
