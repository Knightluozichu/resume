## 部署模式全景

<KgaDeploymentHaDiagram />

Kong 支持三种部署模式 + 两种平台部署方式，适配从开发到生产到云原生的全场景。

## DB 模式 vs DB-less 模式

| 维度 | DB 模式 | DB-less 模式 |
|------|---------|-------------|
| 数据库 | PostgreSQL | 无数据库 |
| 配置方式 | Admin API 动态增删 | 声明式 YAML 文件 |
| 多节点同步 | 共享数据库自动同步 | 需外部同步配置文件 |
| OAuth2/Consumer | 支持（持久化存储） | 不支持需 DB 的插件 |
| Admin API | 可读写 | 只读/禁用 |
| 启动速度 | 需等 DB 连接 | 快（内存加载） |
| 安全性 | Admin API 可动态篡改 | 配置即代码（GitOps） |
| 适用场景 | 动态配置生产环境 | K8s/容器/GitOps/安全要求高 |

<Callout type="tip" title="选型路径">

```
开发/测试 → DB 模式（灵活）
K8s 生产  → DB-less（声明式 + GitOps）
需要 OAuth2/动态 Consumer → DB 模式
大规模多节点 → Hybrid 模式
```

</Callout>

## Docker 部署

### DB-less 模式（最简部署）

```bash
# 创建网络
docker network create kong-net

# 启动 Kong (DB-less)
docker run -d --name kong --network kong-net \
  -e "KONG_DATABASE=off" \
  -e "KONG_PROXY_LISTEN=0.0.0.0:8000,0.0.0.0:8443 ssl" \
  -e "KONG_ADMIN_LISTEN=0.0.0.0:8001" \
  -e "KONG_DECLARATIVE_CONFIG=/kong/kong.yml" \
  -v ./kong.yml:/kong/kong.yml \
  -p 8000:8000 -p 8443:8443 -p 8001:8001 \
  kong:latest

# 声明式配置 kong.yml
# _format_version: "3.0"
# services:
#   - name: example-service
#     url: http://example.com
# routes:
#   - name: example-route
#     paths: ["/"]
```

### DB 模式（PostgreSQL）

```bash
# 1. 启动 PostgreSQL
docker run -d --name kong-db --network kong-net \
  -e "POSTGRES_USER=kong" -e "POSTGRES_DB=kong" -e "POSTGRES_PASSWORD=kong" \
  postgres:13

# 2. 初始化数据库
docker run --rm --network kong-net \
  -e "KONG_DATABASE=postgres" -e "KONG_PG_HOST=kong-db" \
  -e "KONG_PG_USER=kong" -e "KONG_PG_PASSWORD=kong" \
  kong kong migrations bootstrap

# 3. 启动 Kong
docker run -d --name kong --network kong-net \
  -e "KONG_DATABASE=postgres" -e "KONG_PG_HOST=kong-db" \
  -e "KONG_PG_USER=kong" -e "KONG_PG_PASSWORD=kong" \
  -e "KONG_PROXY_LISTEN=0.0.0.0:8000" -e "KONG_ADMIN_LISTEN=0.0.0.0:8001" \
  -p 8000:8000 -p 8001:8001 kong:latest
```

## Kubernetes 部署

### Kong Ingress Controller (KIC)

KIC 是一个 K8s 控制器，将 K8s Ingress/CRD 资源自动转换为 Kong 配置。

```
用户创建 K8s Ingress/CRD → KIC 监听变更 → 翻译为 Kong 声明式配置
→ 通过 Admin API 推送到 Kong Gateway Pod → Kong 执行 Proxy
```

```bash
# Helm 安装 KIC
helm install kong kong/kong -n kong \
  --set ingressController.enabled=true \
  --set ingressController.env.feature_gates=GatewayAlpha=true
```

### K8s 原生 CRD

```yaml
# KongPlugin CRD
apiVersion: configuration.konghq.com/v1
kind: KongPlugin
metadata:
  name: jwt-auth
plugin: jwt
config:
  claims_to_verify: ["exp"]
```

<Callout type="info" title="KIC 优势">

- kubectl 声明式管理（`kubectl apply`）
- GitOps 友好（配置即代码）
- 自动同步（无需手动调 Admin API）
- 与 K8s Service/Ingress 原生集成

</Callout>

## Hybrid 模式

Kong 2.x+ 引入，将节点分为 **Control Plane (CP)** 和 **Data Plane (DP)**。

| 角色 | 职责 | 组件 |
|------|------|------|
| **CP** | 配置管理 | Admin API + PostgreSQL |
| **DP** | 流量代理 | Proxy（无 Admin API） |

```
运维 → CP Admin API → 写入DB → WebSocket推送 → 多个DP
                                                    ↓
                                              DP内存缓存配置
                                              Proxy处理流量
```

### 解决的问题

1. **Admin API 安全** — DP 不暴露 Admin API，无法被篡改
2. **配置一致性** — 所有 DP 从同一 CP 接收配置
3. **数据库隔离** — DP 不连数据库，DB 故障不影响 DP 代理
4. **横向扩展** — DP 无状态，可随意水平扩展
5. **多地域部署** — CP 在中心，DP 在边缘

<Callout type="warning" title="Hybrid 配置">

```bash
# CP 节点
KONG_ROLE=control_plane
KONG_DATABASE=postgres
KONG_CLUSTER_LISTEN=0.0.0.0:8005

# DP 节点
KONG_ROLE=data_plane
KONG_DATABASE=off
KONG_CLUSTER_CP_HOST=cp.example.com
KONG_CLUSTER_TLS_CERT=...
KONG_CLUSTER_TLS_KEY=...
```

</Callout>

## 生产级高可用架构

```
                    ┌─── CP 集群 (3节点, Raft) ───┐
                    │   Admin API + PostgreSQL     │
                    │   (内网, 配置管理)            │
                    └──────────┬───────────────────┘
                               │ WebSocket 推送
                    ┌──────────┼───────────────────┐
                    ↓          ↓                   ↓
              ┌─── DP ───┐ ┌─── DP ───┐      ┌─── DP ───┐
              │  Proxy    │ │  Proxy    │      │  Proxy    │
              │  机房A    │ │  机房A    │      │  机房B    │
              └─────┬─────┘ └─────┬─────┘      └─────┬─────┘
                    ↓             ↓                   ↓
              后端服务池      后端服务池          后端服务池
```

| 层级 | 高可用措施 |
|------|-----------|
| DP 节点 | 无状态，HPA 按 CPU 自动扩缩 Pod |
| Upstream | 多 Target + 健康检查自动故障转移 |
| PostgreSQL | 主从复制 + Patroni 自动切换 |
| CP 集群 | 多 CP 节点 Raft 共识 |
| 跨机房 | DNS 故障切换 |

<Glossary>

<GlossaryItem term="DB-less 模式">
不使用数据库的部署模式。配置通过声明式 YAML 文件加载到内存，Admin API 只读或禁用。适合 K8s/GitOps/安全要求高的场景。
</GlossaryItem>

<GlossaryItem term="Hybrid 模式">
控制面(CP)与数据面(DP)分离的部署模式。CP 运行 Admin API + 数据库，DP 运行 Proxy 无 Admin API。CP 通过 WebSocket 推送配置到 DP。适合大规模多地域部署。
</GlossaryItem>

<GlossaryItem term="KIC (Kong Ingress Controller)">
Kong 的 Kubernetes Ingress Controller。监听 K8s Ingress/CRD 资源变更，翻译为 Kong 声明式配置推送到 Kong Gateway Pod。
</GlossaryItem>

<GlossaryItem term="decK">
Kong 的声明式配置管理工具。用 YAML 文件管理 Kong 配置，支持 diff/sync/backup，适合 GitOps CI/CD 流程。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** Kong 的 DB 模式和 DB-less 模式有什么区别？各自适用于什么场景？

<Answer>

DB模式用PostgreSQL存储配置，Admin API动态增删，多节点共享DB自动同步，支持OAuth2/Consumer持久化。适合需要动态配置的生产环境。DB-less模式无数据库，声明式YAML配置加载到内存，Admin API只读，启动快安全(GitOps)。适合K8s/容器/GitOps/安全要求高。选型：开发用DB模式，K8s生产用DB-less，需OAuth2用DB模式，大规模用Hybrid。

</Answer>

**问题 2：** Kong 的 Hybrid 模式是什么？它如何解决大规模部署中的问题？

<Answer>

Hybrid模式将Kong节点分为CP(控制面)和DP(数据面)。CP运行Admin API+PostgreSQL不处理Proxy流量，DP运行Proxy无Admin API。CP通过WebSocket TLS推送配置到DP。解决的问题：①Admin API安全(DP不暴露) ②配置一致性(所有DP从同一CP接收) ③数据库隔离(DP不连DB, DB故障不影响代理) ④横向扩展(DP无状态) ⑤多地域部署(CP中心,DP边缘)。适合大规模生产环境。

</Answer>

</Exercises>
