## 变量声明与类型系统

Kotlin用`val`和`var`声明变量，这是它与Java最直观的区别：

```kotlin
val x: Int = 42        // val: 不可变引用（类似Java final）
var y = "hello"        // var: 可变引用，类型自动推断为String
val z = 3.14           // 推断为Double
val b: Boolean = true  // 显式指定类型
```

<Callout type="insight">
**核心理念**：Kotlin推荐优先使用`val`。不可变引用让代码更安全——你不用担心变量被意外修改，这在多线程环境下尤其重要。`val`引用不可变，但引用的对象本身可能是可变的（如`val list = mutableListOf(1,2)`，list不能再赋值但可以add元素）。
</Callout>

## 空安全（Null Safety）

Kotlin在类型系统层面区分非空类型和可空类型，这是它消除NPE的核心武器：

```kotlin
var a: String = "hi"      // 非空类型，不能赋值null
var b: String? = null     // 可空类型，加?标记

// 可空类型的成员不能直接访问
// val len = b.length     // 编译错误！

// 安全调用 ?. —— null时返回null而非NPE
val len: Int? = b?.length

// Elvis运算符 ?: —— null时提供默认值
val l: Int = b?.length ?: 0

// 非空断言 !! —— null时抛NPE（不推荐）
val force = b!!.length

// let安全作用域
b?.let { println(it.length) }  // 仅b非空时执行
```

<Callout type="trap">
**误区**：滥用`!!`非空断言。`!!`等于告诉编译器「我确定它不为null」，但如果运行时为null就会NPE，等于放弃了Kotlin的空安全保护。正确做法是用`?.`或`?:`处理null，或在逻辑上确保非空后利用智能转换。
</Callout>

## 控制流：if与when都是表达式

Kotlin中`if`和`when`都是表达式，有返回值：

```kotlin
// if表达式
val result = if (x > 0) "positive" else "negative"

// when表达式（替代Java的switch，但更强大）
val desc = when (x) {
    1 -> "one"
    2, 3 -> "two or three"
    in 4..10 -> "between 4 and 10"
    is Int -> "is Int"     // 类型检查
    else -> "other"
}

// when也可不带参数，作为if-else链的替代
when {
    x > 100 -> "big"
    x > 10 -> "medium"
    else -> "small"
}
```

## 字符串模板与集合

```kotlin
// 字符串模板
val name = "Kotlin"
val age = 10
println("name=$name, age=$age, next=$`{age + 1}`")

// 集合创建
val list = listOf(1, 2, 3)           // 只读List
val mutableList = mutableListOf(1, 2) // 可变List
val map = mapOf("k1" to "v1", "k2" to "v2")

// 遍历
for ((key, value) in map) {
    println("$key = $value")
}
for (i in 0 until list.size) { ... }
for (i in 1..10 step 2) { ... }
```

## 智能转换（Smart Cast）

Kotlin编译器在类型检查后自动进行类型转换，无需手动强转：

```kotlin
fun process(obj: Any): Int {
    if (obj is String) {
        // 编译器自动将obj当作String，无需 (obj as String)
        return obj.length
    }
    return 0
}

// when中的智能转换
when (obj) {
    is String -> println(obj.length)  // obj自动是String
    is Int -> println(obj + 1)       // obj自动是Int
}
```

**问题 1**：Kotlin中`val`和`var`有什么区别？为什么推荐优先使用`val`？

<Answer>
`val`（value）声明不可变引用——一旦赋值不能再指向其他对象，类似Java的final。`var`（variable）声明可变引用——可以多次重新赋值。推荐优先使用`val`的原因：①安全性——不可变引用不会被意外修改，减少并发bug。②可读性——`val`变量只需看初始化就能确定其值，`var`变量需要追踪所有赋值点。③可维护性——不可变性让代码更容易推理和重构。④函数式风格——`val`鼓励声明式编程，减少副作用。注意：`val`引用不可变不等于对象不可变——`val list = mutableListOf(1,2)`中list不能再赋值为其他List，但list可以add/remove元素。若需要真正的不可变对象，用`listOf`而非`mutableListOf`。
</Answer>

**问题 2**：Kotlin的空安全机制包含哪些操作符？各自的使用场景是什么？

<Answer>
Kotlin空安全操作符：①可空类型`?`——`String?`表示变量可为null，非空类型`String`不能赋值null，编译期检查。②安全调用`?.`——`b?.length`在b为null时返回null而不抛NPE，返回类型为`Int?`。适合链式调用：`person?.address?.city?.length`。③Elvis运算符`?:`——`b?.length ?: 0`在左侧为null时返回右侧默认值，将`Int?`收窄为`Int`。适合提供默认值。④非空断言`!!`——`b!!.length`在b为null时抛NPE。不推荐使用，仅在确定非空且需快速失败时用。⑤let安全作用域——`b?.let { process(it) }`仅在b非空时执行块，适合对非空值执行多步操作。⑥智能转换——`if (b != null) return b.length`编译器自动将b当作非空String。核心原则：用`?.`+`?:`处理可空值，避免`!!`，利用智能转换消除冗余检查。
</Answer>

**问题 3**：Kotlin的`when`表达式与Java的`switch`有什么区别？

<Answer>
Kotlin`when`与Java`switch`的区别：①when是表达式——有返回值，可赋值给变量：`val x = when(y) { ... }`；switch是语句，无返回值。②分支匹配更强大——when支持单值（`1 ->`）、多值（`2, 3 ->`）、范围（`in 4..10 ->`）、类型检查（`is String ->`，带智能转换）、条件表达式（`when { x > 0 -> ... }`）；switch只支持常量值匹配。③无需break——when分支自动break，不会贯穿；switch需要显式break否则贯穿。④穷尽性检查——when作为表达式时必须覆盖所有可能（else分支），编译器强制保证；switch无此保证。⑤when可不带参数——用作if-else链的更清晰替代：`when { x > 100 -> "big"; else -> "small" }`。总之when更安全、更强大、更简洁。
</Answer>

**问题 4**：什么是智能转换（Smart Cast）？它如何简化代码？

<Answer>
智能转换是Kotlin编译器在类型检查（`is`）通过后，自动将变量当作目标类型使用，无需手动强转（`as`）。工作原理：编译器在`if (obj is String)`的条件块内，将`obj`的类型从`Any`收窄为`String`，后续可直接调用`obj.length`等String成员。适用场景：①if分支——`if (obj is String) println(obj.length)`。②when分支——`when(obj) { is String -> obj.length; is Int -> obj + 1 }`。③逻辑与——`if (obj is String && obj.length > 5)`。限制：智能转换只对val和局部var有效，对可变类属性无效（因为可能在检查和使用之间被其他线程修改）。智能转换消除了Java中`if (obj instanceof String) { String s = (String) obj; s.length(); }`这种冗余的检查+强转模式，代码更简洁安全。
</Answer>
