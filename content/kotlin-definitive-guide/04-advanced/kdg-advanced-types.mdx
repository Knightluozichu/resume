## 泛型基础

Kotlin泛型与Java泛型类似，在类或函数上声明类型参数：

```kotlin
// 泛型类
class Box<T>(val value: T) {
    fun getValue(): T = value
}

val intBox = Box<Int>(42)
val strBox = Box("hello")  // 类型推断

// 泛型函数
fun <T> identity(x: T): T = x
identity(42)       // 返回Int
identity("hello")  // 返回String

// 泛型约束——上界
fun <T : Comparable<T>> max(a: T, b: T): T =
    if (a > b) a else b  // T实现了Comparable才能用>
```

## 型变：协变与逆变

泛型型变解决的核心问题：`List&lt;Dog&gt;`能否赋值给`List&lt;Animal&gt;`？

```text
协变（out）—— 生产者，只读不写
  Producer<Animal> = Producer<Dog>  ✓ 合法
  Dog是Animal的子类型 → Producer<Dog>是Producer<Animal>的子类型

逆变（in）—— 消费者，只写不读
  Consumer<Dog> = Consumer<Animal>  ✓ 合法
  Dog是Animal的子类型 → Consumer<Animal>是Consumer<Dog>的子类型
```

### 协变 out

```kotlin
// out标记T为协变——只能出现在返回位置（生产者）
interface Producer<out T> {
    fun produce(): T
    // fun consume(item: T)  // 编译错误！out T不能出现在参数位置
}

class DogProducer : Producer<Dog> {
    override fun produce(): Dog = Dog()
}

// Dog是Animal子类 → Producer<Dog>是Producer<Animal>子类
val p: Producer<Animal> = DogProducer()  // 合法！
```

### 逆变 in

```kotlin
// in标记T为逆变——只能出现在参数位置（消费者）
interface Consumer<in T> {
    fun consume(item: T)
    // fun produce(): T  // 编译错误！in T不能出现在返回位置
}

class AnimalConsumer : Consumer<Animal> {
    override fun consume(item: Animal) { println(item) }
}

// Dog是Animal子类 → Consumer<Animal>是Consumer<Dog>子类
val c: Consumer<Dog> = AnimalConsumer()  // 合法！
```

<Callout type="insight">
**PECS原则**：Producer Extends, Consumer Super。如果一个泛型类型只生产T（返回T），用`out T`协变；如果只消费T（接收T参数），用`in T`逆变。既能生产又能消费的不变形（如`Array&lt;T&gt;`可读可写），不能用out/in。Kotlin的`List&lt;out T&gt;`是协变的（只读），`MutableList&lt;T&gt;`是不变的（可读可写）。
</Callout>

## 星投影与上界约束

```kotlin
// 星投影 * —— 类型参数未知，但安全使用
fun printSize(box: Box<*>) {
    val v = box.value  // 类型为Any?
    println(v)
}

// 多类型参数的星投影
interface Map<K, V> {
    fun get(key: K): V
}
fun useMap(map: Map<*, *>) {
    // map.get("key")  // 编译错误，不知道K类型
    val v = map.get(Any())  // 安全，K投影为Any?
}

// 上界约束
fun <T : Number> sum(a: T, b: T): Double = a.toDouble() + b.toDouble()
// T必须是Number或其子类

// 多重约束 where
fun <T> ensureComparable(a: T, b: T): Int where T : Comparable<T>, T : Number {
    return a.compareTo(b)
}
```

## reified：具体化类型参数

普通泛型T在运行时被擦除（类型擦除），无法用`T::class`获取类型。`reified`配合`inline`让T在调用处被替换为实际类型：

```kotlin
// 普通泛型——运行时T被擦除，无法检查
// fun <T> isType(x: Any): Boolean = x is T  // 编译错误！

// reified——inline + reified保留T的类型信息
inline fun <reified T> isType(x: Any): Boolean = x is T

isType<String>("hello")  // true
isType<Int>(42)          // true

// 实际应用：类型安全的JSON解析
inline fun <reified T> Gson.fromJson(json: String): T =
    fromJson(json, T::class.java)

// 实际应用：类型过滤
inline fun <reified T> List<*>.filterType(): List<T> =
    filterIsInstance<T>()

val items: List<Any> = listOf(1, "a", 2, "b", 3)
val numbers: List<Int> = items.filterType<Int>()  // [1, 2, 3]
```

<Callout type="trap">
**误区**：滥用reified。reified只能用于inline函数，且每次调用都会在调用处生成代码，增大字节码体积。只在确实需要运行时类型信息（如类型检查、反射、JSON解析）时使用，普通泛型场景不需要。
</Callout>

<Exercises>
**问题 1**：Kotlin的协变`out`和逆变`in`分别是什么含义？PECS原则如何理解？

<Answer>
协变（out）和逆变（in）是泛型型变的两种形式：①协变out——标记类型参数为`out T`表示T只能出现在返回位置（生产者）。此时`Producer&lt;Dog&gt;`是`Producer&lt;Animal&gt;`的子类型（Dog是Animal子类型时），可以安全赋值。因为只读不写，不会发生类型不安全的写入。②逆变in——标记类型参数为`in T`表示T只能出现在参数位置（消费者）。此时`Consumer&lt;Animal&gt;`是`Consumer&lt;Dog&gt;`的子类型（注意方向反转），可以安全赋值。因为只写不读，传入的任何Dog都能被当作Animal处理。PECS原则（Producer Extends, Consumer Super）= Kotlin的`out`/`in`：如果泛型类型只生产T（返回T），用out协变；如果只消费T（接收T参数），用in逆变。Kotlin标准库中`List&lt;out T&gt;`是协变只读集合，`MutableList&lt;T&gt;`是不变可变集合（既读又写），`Comparator&lt;in T&gt;`是逆变的比较器。不变形（不用out/in）意味着既不能安全地`List&lt;Dog&gt;`赋给`List&lt;Animal&gt;`也不能反向，如Array&lt;T&gt;是不变的因为可读可写。
</Answer>

**问题 2**：什么是星投影`*`？它与Java的通配符`?`有什么关系？

<Answer>
星投影`*`表示类型参数未知但使用安全。`Box<*>`表示「一个Box，但不知道T是什么类型」。使用规则：①对于协变`out T`——`Box<*>`的T投影为`Any?`，可以读取（返回Any?）但不能写入。②对于逆变`in T`——`Box<*>`的T投影为`Nothing`，可以写入（接受Nothing即不可写）但不能读取。③对于不变T——`Box<*>`的读取返回Any?，写入被禁止。应用场景：①当不关心具体类型参数时——`fun printSize(box: Box<*>) = println(box.value)`。②多类型参数的部分投影——`Map<String, *>`表示key是String，value未知。与Java通配符`?`的关系：Kotlin的`*`等价于Java的`?`（无界通配符）。Kotlin的`out T`等价于Java的`? extends T`，`in T`等价于Java的`? super T`。Kotlin在声明端用out/in（declaration-site variance），Java在使用端用`? extends`/`? super`（use-site variance），Kotlin的星投影是使用端的补充手段。
</Answer>

**问题 3**：`reified`具体化类型参数解决了什么问题？为什么必须配合`inline`？

<Answer>
`reified`解决了泛型类型擦除（Type Erasure）的问题。JVM上的泛型在运行时被擦除——`List&lt;Int&gt;`和`List&lt;String&gt;`在运行时都是`List`，无法用`T::class`获取T的类型，也无法用`x is T`做运行时类型检查。`reified`让类型参数T在调用处被实际类型替换，从而保留运行时类型信息。必须配合`inline`的原因：inline函数的体在调用处展开，编译器在展开时知道T的具体类型（如调用`filterType&lt;Int&gt;()`时T=Int），因此可以将T替换为Int。非inline函数编译为独立的方法，T在方法签名中被擦除，无法保留。reified的应用场景：①运行时类型检查——`inline fun &lt;reified T&gt; isType(x: Any) = x is T`。②类型安全的JSON解析——`inline fun &lt;reified T&gt; Gson.fromJson(json: String): T = fromJson(json, T::class.java)`。③类型过滤——`filterIsInstance&lt;T&gt;()`。④启动Activity（Android）——`inline fun &lt;reified T : Activity&gt; Context.startActivity()`。限制：reified函数只能是inline的，增大字节码体积；reified类型参数不能用作普通类的类型参数。
</Answer>

**问题 4**：设计一个类型安全的泛型Repository API，说明你的型变选择。

<Answer>
设计一个类型安全的Repository泛型API：```kotlin
// 数据源接口——协变out，只读生产者
interface DataSource&lt;out T&gt; &#123;
    fun get(id: String): T?
    fun getAll(): List&lt;T&gt;
}

// 数据接收器——逆变in，只写消费者
interface DataSink&lt;in T&gt; &#123;
    fun save(item: T)
    fun saveAll(items: List&lt;T&gt;)
}

// Repository——不变T，既能读又能写
class Repository&lt;T&gt;(
    private val source: DataSource&lt;T&gt;,
    private val sink: DataSink&lt;T&gt;
) &#123;
    fun find(id: String): T? = source.get(id)
    fun list(): List&lt;T&gt; = source.getAll()
    fun save(item: T) = sink.save(item)
}

// 使用——协变让DataSource&lt;User&gt;可以赋给DataSource&lt;Any&gt;
val userSource: DataSource&lt;User&gt; = UserDataSource()
val anySource: DataSource&lt;Any&gt; = userSource  // 合法，out协变

// 逆变让DataSink&lt;Any&gt;可以赋给DataSink&lt;User&gt;
val anySink: DataSink&lt;Any&gt; = AnyDataSink()
val userSink: DataSink&lt;User&gt; = anySink  // 合法，in逆变```型变选择理由：①DataSource只产出T（get返回T），用out协变——DataSource&lt;User&gt;可以安全地当作DataSource&lt;Any&gt;使用，因为读出来的User一定能当Any用。②DataSink只消费T（save接收T），用in逆变——DataSink&lt;Any&gt;可以安全地当作DataSink&lt;User&gt;使用，因为传入的User一定能被Any的sink接受。③Repository既读又写，不变——如果协变，外部可能写入错误类型；如果逆变，读取返回类型不安全。这套设计让类型系统保证读写安全，编译器阻止不安全的赋值。
</Answer>
