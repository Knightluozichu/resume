## 最小可执行切片

下面的Kotlin片段抓住本单元的机制。先预测输出、静态类型和失败位置，再运行；若环境较新，要把编译器差异写进迁移记录。

```kotlin
data class Player(var name: String = "", var health: Int = 100)

val player = Player().apply {
    name = "Madrigal"
}.also { require(it.health in 0..100) }

val label = player.takeIf { it.health > 0 }?.let { it.name }
```

## 四层证明与实验记录

**第一层是编译期证明。** 为“按返回接收者还是闭包结果、参数名是this还是it，选择apply、let、run、with、also与takeIf”写一张类型表：每个输入是否可空、引用是val还是var、函数参数和返回值是什么、类或成员是否可见、泛型参数位于生产端还是消费端。随后保留一个故意不能编译的对照，例如把可空值传给非空参数、修改只读引用、访问私有成员或违反泛型约束。编译器诊断必须与事先写下的预测一致；否则说明读者只是记住了写法，没有掌握静态合同。

**第二层是运行期证明。** 编译通过并不保证业务输入有效。围绕本页的首节点“9. Standard Functions”建立等价类：正常值、空或空白、最小边界、最大边界、非法格式与重复调用。每次执行保存原始输入、标准输出、异常类型和断言结果。若代码通过默认值、catch或隐式转换继续运行，还要回答它是否保留了失败语义，是否让调用者误以为操作成功。

**第三层是所有权与时间证明。** 可变集合、闭包、对象声明、lazy属性、Java平台类型、Activity和协程都会令结果依赖“何时读写、由谁取消”。把创建、读取、修改、释放或取消画成时间线，交换两个相邻动作并重新预测。同步代码检查别名和共享可变状态；Android与异步代码检查主线程、生命周期所有者、状态恢复和迟到结果。这样才能具体检验“为追求链式写法嵌套作用域函数，令接收者与返回值失去可读性”，而不是只在说明文字中提醒。

**第四层是迁移证明。** 先用原书Kotlin 1.2工具链保存基线，再在现代环境只改变一个变量。语言升级关注弃用、推断和标准库行为；JDK升级关注字节码目标；Android升级关注插件、生命周期和平台限制；协程升级关注结构化并发与取消。新方案可以更好，但必须同时保留原始行为、差异、测试、决策和回滚，不能用今天的答案覆盖2018年的目录事实。

实验记录按“假设、固定条件、单一变量、观察、结论、反例、下一步”七栏填写。对本页而言，最终交付不是更多代码行，而是标准函数决策表、等价展开、链路断点、空值实验和副作用审计；另一位读者应能在没有作者口头解释的情况下重建环境、运行正常与失败样例，并指出结论在哪个版本或输入边界失效。
