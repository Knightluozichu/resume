## 选型矩阵：什么场景用什么特性

| 场景 | 推荐特性 | 原因 |
|------|---------|------|
| 变量声明 | `val`优先 | 不可变更安全，减少可变状态 |
| 空值处理 | `?.`+`?:` | 编译期消除NPE，避免`!!` |
| 分支逻辑 | `when`表达式 | 替代switch，有返回值，穷尽检查 |
| 数据建模 | `data class` | 一行生成equals/hashCode/copy |
| 状态建模 | `sealed class`+`when` | 有限状态，编译器保证穷尽 |
| 单例 | `object` | 线程安全，简洁 |
| 静态成员 | `companion object` | 替代Java static |
| 通用容器 | 泛型`&lt;T&gt;` | 类型安全复用 |
| 只读集合 | `List&lt;out T&gt;` | 协变安全，不可变 |
| 异步操作 | `suspend`协程 | 非阻塞，顺序写法替代回调 |
| 并发获取 | `async`+`await` | 并行执行，合并结果 |
| 数据流 | `Flow` | 协程版冷流，背压自然 |
| UI状态 | `StateFlow` | 热流，状态持有 |
| 增强API | 扩展函数 | 不改源码加方法 |
| 声明式配置 | DSL | 类型安全构建器 |
| UI构建 | Compose | 声明式，状态驱动 |
| Java调用 | `@JvmStatic`/`@JvmField` | 互操作友好 |
| 类型检查 | `reified` | 运行时保留泛型类型 |
| 单元测试 | JUnit+MockK | Kotlin原生，mock final类 |
| 协程测试 | `runTest` | 虚拟时间，跳过delay |

<Callout type="insight">
**核心理念**：Kotlin的设计哲学是「简洁、安全、惯用」。简洁——消除Java样板代码（data class/类型推断/字符串模板）。安全——编译期消除错误（空安全/sealed穷尽/智能转换）。惯用——用Kotlin特有的表达方式（扩展函数/协程/DSL）而非直译Java。选型的核心标准：哪个特性让代码更安全、更简洁、更可维护。
</Callout>

## 三大维度交叉复习

```text
维度1：语言核心（表达力）
  基础语法 → 函数 → OOP → 高级类型
  关键链：val/var → Lambda → data class → 泛型out/in

维度2：并发与抽象（控制力）
  协程 → Flow → DSL
  关键链：suspend → async/await → 带接收者Lambda

维度3：工程实践（落地力）
  Android → 测试 → 互操作
  关键链：扩展函数 → Compose → MockK/runTest

交叉点：
  语言核心 × 并发 = suspend函数（语言级协程支持）
  语言核心 × 工程 = 扩展函数（增强Android API）
  并发 × 工程 = viewModelScope（结构化并发落地Android）
  语言核心 × 并发 × 工程 = Compose（DSL+状态+协程构建UI）
```

<Exercises>
**问题 1**：用知识图谱的方式，串联《Kotlin编程权威指南》全书八大核心领域的关系。

<Answer>
全书八大核心领域以Kotlin语言为核心交汇：①基础语法——val/var变量声明、空安全（String?/?.//?:/!!）、when表达式、字符串模板、智能转换。这是Kotlin的地基，所有上层特性都建立在类型系统和空安全之上。②函数与Lambda——高阶函数（函数作为参数/返回值）、Lambda表达式（it/末尾Lambda）、函数类型((Int)->Int)、inline内联函数、集合操作map/filter/reduce。函数式编程能力是Kotlin的核心表达力。③类与对象——主构造函数、open/override继承、data class数据类、sealed class密封类、object单例、companion object伴生对象、属性委托by。OOP建模能力是业务逻辑的基础。④高级类型——泛型类/函数、out协变/in逆变（PECS原则）、星投影*、上界约束T:Comparable、reified具体化。泛型是抽象复用的核心。⑤协程——suspend挂起函数、launch/async构建器、结构化并发coroutineScope、Flow异步流、Dispatcher调度器。协程是并发编程的现代方案。⑥DSL——带接收者的Lambda、@DslMarker作用域控制、infix中缀调用、扩展函数、类型安全构建器。DSL是设计领域语言的能力。⑦Android——扩展函数增强View、Android KTX简化、协程替代回调、Java互操作注解、Jetpack Compose声明式UI。Android是Kotlin的主战场。⑧测试——JUnit单元测试、MockK模拟、runTest协程测试、代码规范、测试金字塔。测试是质量保障。交叉关系：语言核心是所有特性的基础（空安全贯穿所有代码）；函数式→协程（suspend是函数式+并发的交汇）；OOP→高级类型（泛型是OOP的抽象延伸）；协程→DSL（带接收者Lambda是两者的共同机制）；语言核心→Android（扩展函数/空安全改造Android开发）；全书→测试（所有特性都需要测试保障）。
</Answer>

**问题 2**：对比Kotlin与Java在以下场景的差异：空安全、异步编程、数据建模、集合操作。

<Answer>
Kotlin与Java四大场景对比：①空安全——Kotlin在类型系统层面区分非空String和可空String?，编译期消除NPE。?.安全调用、?:Elvis、智能转换。Java只有运行时NPE，靠Optional或手动检查。②异步编程——Kotlin用协程suspend函数，顺序写法无嵌套：`val data = api.fetch()`。launch/async/Flow，结构化并发自动管理生命周期。Java用CompletableFuture/回调/线程池，代码嵌套且需手动管理线程。对比：`suspend fun load() { val a = api.getA(); val b = api.getB(a); }` vs `api.getA().thenCompose(a -> api.getB(a)).thenAccept(b -> ...)`。③数据建模——Kotlin用`data class User(val name: String, val age: Int)`一行生成equals/hashCode/copy/toString/解构。sealed class + when实现穷尽状态匹配。Java需手写或Lombok生成equals/hashCode，enum不能携带不同类型数据，switch不保证穷尽。④集合操作——Kotlin内置函数式操作：`list.map &#123; it*2 }.filter &#123; it>5 }.sortedBy { it }.forEach { }`，链式流畅。List&lt;out T&gt;协变只读，MutableList&lt;T&gt;可变。Java需Stream API：`list.stream().map(x->x*2).filter(x->x>5).sorted().forEach()`，写法冗长，且Stream是一次性消费的。总结：Kotlin在所有场景都更简洁、更安全、更惯用——空安全编译期保证、协程顺序异步、data class一行建模、集合操作链式自然。Java的方案都能用但更冗长、更易错。
</Answer>

**问题 3**：设计一个完整的Kotlin Android项目架构，说明每层用了哪些Kotlin特性。

<Answer>
完整Kotlin Android项目架构（MVVM + Clean Architecture）：①UI层（Compose）——@Composable函数构建声明式UI，StateFlow收集ViewModel状态，remember/mutableStateOf管理本地状态。sealed class UiState(Loading/Success/Error)驱动UI渲染，when穷尽匹配。viewModelScope.launch启动协程。②ViewModel层——class ViewModel用viewModelScope启动协程，suspend函数调用Repository，StateFlow/MutableStateFlow暴露UI状态。sealed class建模状态。@JvmStatic用于Java互操作。③Repository层——泛型Repository&lt;T&gt;抽象数据源，suspend函数提供顺序式API，Flow返回数据流。out/in型变设计安全API。data class建模数据实体。④DataSource层——Retrofit接口定义API（suspend函数），Room DAO用suspend/Flow。扩展函数增强Context/View。withContext(Dispatchers.IO)切换线程。reified实现类型安全的JSON解析。⑤Domain层（UseCase）——data class建模值对象，sealed class建模业务结果，泛型UseCase&lt;Input, Output&gt;。⑥DI层——object单例管理依赖，companion object提供工厂方法。⑦测试层——JUnit单元测试（反引号方法名），MockK模拟Repository（every/coEvery/verify/coVerify），runTest协程测试（虚拟时间），测试金字塔（70%单元/20%集成/10%UI）。⑧互操作——@JvmStatic/@JvmField/@JvmOverloads让Java代码调用友好，平台类型边界处标注可空性。核心设计理念：用Kotlin的类型系统消除bug（空安全/sealed穷尽/val不可变），用协程简化异步（suspend替代回调/结构化并发），用扩展函数和DSL增强API（不改源码加功能），用data class和sealed class简化建模（一行代码+穷尽匹配），用测试保障质量（MockK+runTest）。
</Answer>

**问题 4**：Kotlin的「简洁、安全、惯用」设计哲学分别体现在哪些特性上？

<Answer>
Kotlin「简洁、安全、惯用」设计哲学的体现：①简洁（消除样板代码）——data class一行生成equals/hashCode/copy/toString（替代Java十几行）；类型推断（val x = 42替代int x = 42）；字符串模板（"$name"替代name+"");主构造函数（class Person(val name:String)替代Java字段+构造+getter/setter）；扩展函数（替代工具类）；when表达式（替代switch+break）。②安全（编译期消除错误）——空安全（String?类型系统区分，?./:?/!!处理null，编译期消除NPE）；sealed class穷尽匹配（when表达式编译器强制覆盖所有分支，新增子类报错提醒）；智能转换（is检查后自动类型转换，消除冗余强转）；val不可变优先（减少可变状态的并发bug）；不可变集合（listOf替代mutableListOf，防止意外修改）；泛型型变（out/in让类型关系在编译期安全，避免运行时ClassCastException）。③惯用（用Kotlin特有方式表达）——协程替代回调（suspend顺序写法，非阻塞，结构化并发）；扩展函数替代工具类（String.isEmail()替代EmailValidator.isEmail(str)）；DSL替代配置文件（Gradle Kotlin DSL/Compose UI/HTML DSL，类型安全+IDE补全）；作用域函数（apply配置/let处理null/run执行块/also副作用）；集合函数式操作（map/filter/reduce链式，替代for循环）；带接收者的Lambda（构建嵌套声明式API）。这三者相辅相成：简洁让代码更易读，安全让代码更可靠，惯用让代码更符合语言设计意图。判断Kotlin代码质量的标准：是否用了val而非var？是否用了data class而非POJO？是否用了协程而非回调？是否用了扩展函数而非工具类？如果答案是「否」，说明在直译Java而非用惯用Kotlin。
</Answer>
