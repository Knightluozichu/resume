## 从本章问题开始

附录A 补充挑战练习要解决的不是语法记忆，而是把附加挑战拆成可判定输入、约束、实现、反例与回归测试，并连接Exercism练习。先写出输入和期望结果，再运行最小切片；如果无法解释失败落在编译期、边界层还是运行期，程序即使输出一次正确答案也未通过。

本页不把 val 等同深度不可变，也不把简洁语法等同动态类型。Kotlin 的类型、可空性、求值规则和对象模型共同压缩非法状态；本章不变量是把附加挑战拆成可判定输入、约束、实现、反例与回归测试，并连接Exercism练习的输入、类型边界、求值结果和失败路径都能由独立读者重放。

## 最小可执行切片

```kotlin
fun frame(lines: List<String>): List<String> {
    val width = lines.map { it.length }.max() ?: 0
    val border = "*".repeat(width + 4)
    return listOf(border) +
        lines.map { "* " + it.padEnd(width) + " *" } +
        border
}
```

运行切片时固定 Kotlin/JDK 或 Android 工具链版本、输入数据和命令；保存标准输出、编译诊断及断言。迁移实验必须另建记录，不能静默改写2018年的历史坐标。

<Callout type="trap" title="本章核心陷阱">
  只提交能通过一个样例的代码，没有边界和反例。先缩小到最小反例，明确是类型合同、对象所有权、求值顺序还是平台边界失效，再用同输入验证修复。
</Callout>

<Callout type="trap" title="把当前惯例倒灌进第一版">
  附录A 补充挑战练习保留 Kotlin 1.2/JVM 的历史身份；当前 Kotlin 或 Android 方案只作单独迁移坐标，不能据此改写第一版目录和接口身份。
</Callout>

<Callout type="trap" title="只保留成功输出">
  挑战清单、约束表、失败测试、复杂度说明和复盘记录必须同时包含正常、边界和失败路径；如果故障后不能恢复并复位，本页实践闭环仍未完成。
</Callout>

## 练习、答案与四级证据

<Exercises>

**问题 1：历史与迁移。** 怎样既保留 Kotlin 1.2 的教学身份，又使用当前官方资料核验机制？

<Answer>
  先以[Kotlin 1.2发布说明](https://kotlinlang.org/docs/whatsnew12.html)和目录锁定历史范围，再用[当前技术文档](https://kotlinlang.org/docs/basic-syntax.html)建立单独迁移记录。比较相同输入、结果和不变量；只改变版本坐标，不把当前API伪装成第一版内容。
</Answer>

**问题 2：逐节点验证。** 本页 2 个正式节点怎样从出现升级到可复查证据？

<Answer>
  - **A. More Challenges**：在声明合同阶段保存输入与结果，触发只提交能通过一个样例的代码，没有边界和反例后恢复初态，并由挑战清单、约束表、失败测试、复杂度说明和复盘记录确认语义未漂移。
  - **Leveling Up with Exercism**：在建立输入阶段保存输入与结果，触发只提交能通过一个样例的代码，没有边界和反例后恢复初态，并由挑战清单、约束表、失败测试、复杂度说明和复盘记录确认语义未漂移。
</Answer>

**问题 3：反例闭环。** 遇到只提交能通过一个样例的代码，没有边界和反例时，如何判断修复真正成立？

<Answer>
  保存首个失败诊断，恢复显式输入域、类型或对象边界和求值顺序，再以相同工具链和输入重跑正常、边界、非法三组样例。只有挑战清单、约束表、失败测试、复杂度说明和复盘记录回到基线且把附加挑战拆成可判定输入、约束、实现、反例与回归测试，并连接Exercism练习的输入、类型边界、求值结果和失败路径都能由独立读者重放重新成立，才能通过。
</Answer>
