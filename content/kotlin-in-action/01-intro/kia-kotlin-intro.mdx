## 为什么选择 Kotlin

<KiaKotlinIntroDiagram />

Kotlin 由 JetBrains 于 2011 年开发，2016 年发布 1.0 正式版，2017 年成为 Android 官方语言。它不是 Java 的替代品，而是让 Java 生态更简洁安全的语言。

## 四大设计目标

### 1. 简洁——消除样板代码

```kotlin
// Java 需要数十行代码实现的数据类
// Kotlin 一行搞定
data class User(val name: String, val age: Int)

// 自动生成 equals() / hashCode() / toString() / copy() / componentN()
val user = User("Kotlin", 10)
val copy = user.copy(age = 11)
val (name, age) = user  // 解构声明
```

```kotlin
// 默认参数替代方法重载
// Java 需要写 3 个重载方法
fun greet(name: String = "World", greeting: String = "Hello") =
    "$greeting, $name!"

greet()                          // Hello, World!
greet("Kotlin")                  // Hello, Kotlin!
greet(greeting = "Hi")           // Hi, World!
```

### 2. 安全——编译期消除 NPE

```kotlin
// 类型系统区分非空和可空
var a: String = "hello"    // 非空，不可赋 null
var b: String? = null      // 可空，可持有 null

// 安全调用链
val length: Int? = b?.length       // null 时返回 null
val len: Int = b?.length ?: 0      // Elvis 运算符，null 时返回 0
val safe: Int = b!!.length         // 非空断言，null 时抛 NPE（慎用）

// 智能转换
if (b != null) {
    println(b.length)  // 编译器自动将 b 当作非空 String
}
```

### 3. 互操作——与 Java 100% 兼容

```kotlin
// Kotlin 直接调用 Java 库
import java.util.ArrayList

val list = ArrayList<String>()
list.add("Kotlin")

// Java 调用 Kotlin（需加注解）
// Kotlin 侧
@JvmStatic
fun create(): User = User("Kotlin", 10)

@JvmField
val MAX_SIZE = 100

@JvmOverloads  // 为默认参数生成 Java 重载方法
fun greet(name: String = "World", greeting: String = "Hello") = "$greeting, $name!"
```

<Callout type="info" title="编译流程">
`.kt` 源码 → `kotlinc` 编译器 → `.class` 字节码 → JVM 运行。Kotlin 编译产物是标准 Java 字节码，JVM 不区分来源，这是互操作的基础。
</Callout>

### 4. 工具友好

IntelliJ IDEA 和 Android Studio 对 Kotlin 有一等支持：
- Java → Kotlin 自动转换（Cmd+Shift+Option+K）
- 代码补全、重构、调试体验与 Java 一致
- 编译期错误提示和快速修复

## Java vs Kotlin 核心对比

```kotlin
// 变量声明
// Java:  String x = "hello";
// Kotlin: val x = "hello"  // 类型推断，val 不可变

// switch vs when
// Java:  switch (x) { case 1: ...; break; }
// Kotlin:
val desc = when (x) {
    1 -> "one"
    in 2..10 -> "small"
    else -> "unknown"
}  // when 是表达式有返回值，无需 break

// 空安全
// Java:  if (str != null) { str.length(); }
// Kotlin: str?.length  // 一行搞定

// 数据类
// Java:  数十行 equals/hashCode/toString
// Kotlin: data class User(val name: String, val age: Int)  // 一行
```

## Kotlin 的定位

<Callout type="warning" title="核心理念">
Kotlin 不是「更好的 Java」，而是让 Java 生态更简洁安全。它编译为标准 JVM 字节码，与 Java 无缝互操作，同时提供空安全、协程、DSL 等现代语言特性。
</Callout>

<Glossary>

<GlossaryItem term="NPE（NullPointerException）">
Java 中最常见的运行时异常。Kotlin 通过类型系统在编译期区分非空和可空类型，从根源消除 NPE。
</GlossaryItem>

<GlossaryItem term="平台类型（Platform Type）">
Java 互操作时，Java 返回值在 Kotlin 中表示为 `String!`（平台类型），可能为空也可能非空。需显式处理可空性。
</GlossaryItem>

<GlossaryItem term="@JvmStatic / @JvmField / @JvmOverloads">
Kotlin 供 Java 调用时添加的注解，分别让 companion object 方法变为真正的静态方法、属性暴露为 public 字段、为默认参数生成重载方法。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：Kotlin 的四大设计目标是什么？

<Answer>
简洁（消除样板代码）、安全（编译期消除 NPE）、互操作（与 Java 100% 兼容）、工具友好（IntelliJ 一等支持）。核心理念是让 Java 生态更简洁安全而非替代 Java。
</Answer>

**问题 2**：Kotlin 的编译流程是什么？如何实现与 Java 的互操作？

<Answer>
.kt 源码 → kotlinc 编译器 → .class 字节码 → JVM 运行。Kotlin 编译为标准 Java 字节码，可直接调用 Java 库。Java 调用 Kotlin 需加 @JvmStatic/@JvmField/@JvmOverloads 注解。顶层函数编译为「文件名Kt」类的静态方法。
</Answer>

**问题 3**：为什么说 Kotlin 的空安全比 Java 运行时 null 检查更优越？

<Answer>
Kotlin 在类型系统层面区分 String（非空）和 String?（可空），编译期拦截对可空类型的直接访问，强制用 ?. 或 ?: 处理。Java 的 null 检查是运行时的，忘记检查就 NPE。Kotlin 从根源消除而非事后检测。
</Answer>

**问题 4**：Kotlin 相比 Java 在哪些方面减少了样板代码？

<Answer>
data class 替代手写 equals/hashCode/toString；默认参数替代方法重载；顶层函数+扩展函数替代工具类；智能转换替代 instanceof+强制转换；object 替代双重检查锁单例；属性访问替代 getter/setter。
</Answer>

</Exercises>
