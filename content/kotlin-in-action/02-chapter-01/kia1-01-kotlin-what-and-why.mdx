## 从类型、解析和运行时开始

Kotlin的<Term def="编译器在运行前确定表达式、参数、返回值与成员约束的类型系统">静态类型</Term>不是额外负担，而是重构、自动补全和跨Java边界推理的证据。每个例子先写输入类型、可空性和期望输出，再判断调用在编译期选中了成员、扩展、约定还是函数值；不能从短小语法直接猜测运行语义。

<Term def="把可能为空与保证非空写入类型并要求调用点显式处理的语言合同">空安全</Term>把许多失败前移到编译期，但平台类型、反射、反序列化和非空断言仍可把风险带回运行时。课程要求为每个边界保留null输入、缺失字段、错误类型和Java未标注返回值，不能用一次正常输出证明安全。

<Term def="在不修改既有类的前提下以静态解析方式提供额外函数或属性的声明">扩展声明</Term>服务于调用点可读性，却不会真正向接收者类注入虚方法。<Term def="接收函数作为参数或返回函数，并让行为能够组合的函数">高阶函数</Term>可以消除重复，但还要解释捕获、对象分配、内联和控制流。<Term def="Kotlin与Java在类型、调用约定、集合、异常和字节码层双向协作的能力">Java互操作</Term>贯穿全书，是判断设计是否成立的最终边界。

本单元主线是从目标平台、静态类型、函数式与面向对象、设计哲学和工具链解释Kotlin为何能渐进进入Java工程。先用结构图选中正式节点，再在执行实验中切换Kotlin调用、Java调用、null边界、擦除与反射，最后以证据门确认目录、类型、运行时、互操作和版本均可重放。

## 最小可执行切片

先预测以下代码的静态类型、求值顺序和输出，再运行。样例刻意保留可空输入、集合变换、扩展与Java友好入口，便于把语法表象还原为调用合同。

```kotlin
data class Record(val id: Int, val label: String?)

fun Record.display(): String = label?.trim()?.takeIf { it.isNotEmpty() } ?: "#$id"

fun select(records: List<Record>, predicate: (Record) -> Boolean): List<String> =
    records.asSequence().filter(predicate).map(Record::display).toList()

fun main() {
    val input = listOf(Record(1, " Kotlin "), Record(2, null))
    check(select(input) { it.id > 0 } == listOf("Kotlin", "#2"))
}
```

## 五层机制与反例证明

**类型层。** 为输入、接收者、参数、返回值、类型实参和可空性逐项标注。类型推导可以减少重复，但解释时必须还原推导结果。遇到平台类型，不假定非空；先在Java声明、注解和真实返回值上建立证据，再决定边界校验位置。

**解析层。** 写出成员函数、扩展函数、运算符约定、函数值或反射调用的选择规则。扩展按静态接收者类型解析，默认参数由Kotlin调用点处理，具名参数不能直接照搬到Java；每项结论都要用最小重载或双向调用反例验证。

**运行时层。** 检查闭包捕获、序列惰性、装箱、泛型擦除、内联展开、反射与对象创建。用计数器、字节码、调用顺序和异常类型区分“语法更短”与“执行更少”。性能结论必须有输入规模与测量方法，不能从API名称推断。

**API设计层。** 以调用点为中心比较普通函数、扩展、运算符、带接收者lambda和DSL。先写合法句子与禁止句子，再决定抽象；如果接收者不清、顺序隐蔽、副作用不可见或错误消息恶化，普通API通常更合适。

**互操作与版本层。** 从Java调用同一能力，并检查空值注解、静态入口、函数接口、集合可变性、异常和反射。先保存Kotlin 1.0基线，再一次只改变编译器、标准库、JVM目标、Gradle插件或新版语言特性之一；协程与Flow属于后续版本，不得倒填进本书目录。

围绕“把Kotlin理解成只面向Android的脚本语言，或把简洁误解为放弃静态类型约束”预写推翻条件：编译选择与预测不符、Java调用合同改变、null穿透边界、擦除导致错误转换、求值次数异常、资源未释放或DSL产生歧义中的任一项出现，都表示当前解释不成立。最终交付Hello World产物、字节码目标、平台矩阵、设计取舍表和Java调用记录，使另一位开发者无需口头提示即可重放。

<Callout type="trap">**本单元核心陷阱。** 把Kotlin理解成只面向Android的脚本语言，或把简洁误解为放弃静态类型约束。修复时先还原静态类型、解析位置、运行时代价和Java调用合同，再写能推翻当前解释的测试。</Callout>

<Callout type="trap">**版本混淆。** 本书基线是Kotlin 1.0，第1版没有协程和Flow章节。新版编译器可用于验证迁移，但必须单列差异，不能用第2版知识替换第1版目录。</Callout>
