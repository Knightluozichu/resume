## 类声明与构造函数

<KiaClassesInterfacesDiagram />

```kotlin
// 主构造函数 + 属性声明（一行搞定）
class Person(val name: String, val age: Int)

// 带 init 块的主构造函数
class Person(name: String) {
    val name: String
    val nameLength: Int

    init {
        this.name = name
        this.nameLength = name.length
        println("Person created: $name")
    }
}

// 次构造函数用 constructor
class Person(val name: String) {
    var children: MutableList<Person> = mutableListOf()

    constructor(name: String, parent: Person) : this(name) {
        parent.children.add(this)
    }
}
```

## 继承与接口

```kotlin
// Kotlin 类默认 final（不可继承），需 open 标记
open class Animal(val name: String) {
    // 方法也默认 final，需 open 才能 override
    open fun sound(): String = "some sound"
}

class Dog(name: String) : Animal(name) {
    // override 的方法默认是 open 的，可用 final 禁止再继承
    final override fun sound(): String = "Woof"
}

// 接口——可有默认实现
interface Clickable {
    fun click()                          // 抽象方法
    fun showOff() = println("clickable") // 默认实现
}

class Button : Clickable {
    override fun click() = println("clicked")
    // showOff() 有默认实现，可不重写
}

// 接口方法冲突——需显式指定
interface Focusable {
    fun showOff() = println("focusable")
}

class ImageButton : Clickable, Focusable {
    override fun click() = println("image clicked")
    override fun showOff() {
        super<Clickable>.showOff()  // 显式调用
        super<Focusable>.showOff()
    }
}
```

<Callout type="info" title="类默认 final 的好处">
Kotlin 类默认不可继承，需明确用 open 标记。这防止意外继承导致的「脆弱基类」问题，符合 Effective Java「要么为继承设计并文档化，要么禁止继承」的建议。
</Callout>

## 特殊类

### data class

```kotlin
// 一行替代 Java 数十行样板代码
data class User(val name: String, val age: Int)

// 自动生成：equals() / hashCode() / toString() / copy() / componentN()
val user = User("Kotlin", 10)
val copy = user.copy(age = 11)           // User(name=Kotlin, age=11)
val (name, age) = user                   // 解构声明
println("$name, $age")                    // Kotlin, 10
```

### sealed class

```kotlin
// 限制继承层级——所有子类必须在同一文件/模块
sealed class Result {
    data class Success(val data: String) : Result()
    data class Error(val message: String) : Result()
    object Loading : Result()
}

// when 配合 sealed class 实现编译期穷尽检查
fun handle(result: Result) = when (result) {
    is Result.Success -> println("OK: ${`result.data`}")
    is Result.Error -> println("ERR: ${`result.message`}")
    Result.Loading -> println("Loading...")
    // 无需 else——新增子类时编译器强制处理
}
```

### object 单例

```kotlin
// 替代 Java 双重检查锁单例——饿汉式，线程安全
object Database {
    fun connect() = println("Connected")
    fun disconnect() = println("Disconnected")
}

// 匿名对象——替代 Java 匿名内部类
window.addListener(object : ClickListener {
    override fun onClick() = println("clicked")
})
```

### companion object

```kotlin
// 替代 Java static 成员
class User(val name: String) {
    companion object {
        const val MAX_AGE = 150
        fun create(name: String) = User(name)
    }
}

// 调用
User.MAX_AGE
User.create("Kotlin")

// companion object 是真正的对象——可实现接口、有类型
class User {
    companion object Factory : Creatable<User> {
        override fun create() = User()
    }
}
```

## 委托

```kotlin
// by 委托——复用实现而不写转发代码
interface Logger {
    fun log(msg: String)
}

class ConsoleLogger : Logger {
    override fun log(msg: String) = println(msg)
}

// User 委托 Logger 给 logger 实例
class User(val name: String, logger: Logger) : Logger by logger

val user = User("Kotlin", ConsoleLogger())
user.log("created")  // 委托给 ConsoleLogger
```

<Callout type="warning" title="Kotlin OOP 核心差异">
类默认 final（需 open）、接口可有默认实现、data class 自动生成样板代码、object 替代单例模式、companion object 替代 static、sealed class 实现穷尽检查、by 委托替代继承。
</Callout>

<Glossary>

<GlossaryItem term="data class">
用 `data class` 声明，自动生成 equals/hashCode/toString/copy/componentN 的类。用于数据建模，消除 Java 样板代码。
</GlossaryItem>

<GlossaryItem term="sealed class">
密封类，限制继承层级在同一文件/模块内。配合 when 实现编译期穷尽检查，新增子类时编译器强制处理新分支。
</GlossaryItem>

<GlossaryItem term="object">
单例声明，编译为饿汉单例，线程安全。也可用作匿名对象替代 Java 匿名内部类。
</GlossaryItem>

<GlossaryItem term="companion object">
伴生对象，在类内部声明，通过类名访问。替代 Java 的 static 成员，但它是真正的对象（可实现接口）。
</GlossaryItem>

<GlossaryItem term="by 委托">
用 `by` 关键字将接口实现委托给另一个对象，复用实现而不需写转发代码。替代继承的「组合优于继承」原则。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：data class 解决了什么问题？自动生成哪些方法？

<Answer>
解决 Java 数据类样板代码问题。自动生成 equals/hashCode/toString/copy/componentN（解构声明）。约束：主构造至少一参数，需 val/var，不能 abstract/open/sealed/inner。
</Answer>

**问题 2**：Kotlin 类默认 final 有什么好处？open 的含义？

<Answer>
防止意外继承导致的脆弱基类问题，符合 Effective Java 建议。open 标记允许继承的类/方法。override 的成员默认 open，可用 final 禁止再继承。
</Answer>

**问题 3**：object、companion object、sealed class 分别解决什么问题？

<Answer>
object 替代双重检查锁单例（饿汉线程安全）；companion object 替代 static 成员（是真正对象可实现接口，工厂方法首选）；sealed class 限制继承层级配合 when 实现编译期穷尽检查（状态建模首选）。
</Answer>

**问题 4**：Kotlin 接口与 Java 接口有什么区别？

<Answer>
Kotlin 接口可有默认实现（与 Java 8+ 类似）；不能有构造函数和实例字段但可有 val 属性（子类需实现）；方法冲突用 super<接口名>.方法() 指定；默认 open。用 by 委托复用接口实现。
</Answer>

</Exercises>
