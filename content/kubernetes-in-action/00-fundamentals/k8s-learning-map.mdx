## 四条核心主线

<Callout type="info" title="四条核心主线">

贯穿全书的四条主线，回答 K8s 的四个核心问题：

1. **主线一 · 工作负载**：`Pod → Deployment → ReplicaSet → Job/CronJob` — 回答「应用怎么跑」
2. **主线二 · 网络通信**：`Service → Endpoints → DNS → Ingress` — 回答「服务怎么发现」
3. **主线三 · 存储配置**：`Volume → PV → PVC → StorageClass` — 回答「数据怎么持久化」
4. **主线四 · 调度运维**：`Scheduler → Affinity → RBAC → NetworkPolicy` — 回答「怎么调度和运维」

</Callout>

### 四个交汇点

| 交汇点 | 涉及主线 | 意义 |
|--------|----------|------|
| Pod-Service-Endpoints | 工作负载 ↔ 网络通信 | Pod 由标签被 Service 选中，Endpoints 动态维护端点列表 |
| Pod-Volume-PVC | 工作负载 ↔ 存储配置 | Pod 通过 PVC 挂载 PV，实现数据持久化与配置注入 |
| Deployment-Scheduler-Node | 工作负载 ↔ 调度运维 | Deployment 创建 Pod，Scheduler 按资源/亲和性分配节点 |
| Secret-RBAC-NetworkPolicy | 存储配置 ↔ 调度运维 | Secret 管理敏感数据，RBAC 控制访问，NetworkPolicy 隔离流量 |

## Kubernetes 核心设计哲学

K8s 的四大技术特点：

1. **声明式 API** — 用户声明期望状态（YAML），控制器持续 reconcile 实际状态向期望状态收敛
2. **控制器模式** — 每类资源对应一个控制器（Deployment Controller、ReplicaSet Controller 等），Watch + Reconcile 循环
3. **Pod 最小调度单元** — 容器不直接调度，Pod 内多容器共享网络和存储，是 K8s 的原子单位
4. **分层架构** — 控制面（API Server/etcd/Scheduler/Controller Manager）与数据面（kubelet/kube-proxy/容器运行时）分离

<Glossary>

<GlossaryItem term="声明式 API">
用户通过 YAML/JSON 声明期望状态（如「3 个副本」），K8s 控制器持续监控并将实际状态向期望状态收敛。不同于命令式（「启动一个容器」），声明式天然支持自愈和可重入。
</GlossaryItem>

<GlossaryItem term="Pod">
Kubernetes 最小调度单元，包含一个或多个紧密耦合的容器。同一 Pod 内容器共享网络命名空间（IP/端口）和存储卷，始终调度到同一节点。
</GlossaryItem>

<GlossaryItem term="控制面">
Kubernetes 集群的大脑，包含 API Server（唯一入口）、etcd（状态存储）、Scheduler（调度）、Controller Manager（控制器集合）。负责集群级决策和状态管理。
</GlossaryItem>

<GlossaryItem term="Reconcile 循环">
控制器的核心工作模式：Watch 资源变化 → 对比期望状态与实际状态 → 执行操作消除差异 → 循环往复。保证系统最终一致性。
</GlossaryItem>

</Glossary>
