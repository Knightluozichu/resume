## 核心概念

### LangChain 是什么

LangChain 是**开源的大语言模型应用开发框架**，通过标准化抽象和模块化组合将模型能力转化为完整应用。其核心设计理念：

- **标准化抽象**：Runnable 接口统一所有组件的调用方式
- **模块化组合**：组件可插拔，用管道符自由编排
- **LCEL 表达式**：管道语法原生支持流式/异步/批量
- **生态集成**：数百种模型和工具开箱即用

### 五大核心模块

| 模块 | 职责 | 核心组件 |
|------|------|----------|
| Model I/O | 基础管道 | PromptTemplate / LLM / OutputParser |
| Chains | 流程编排 | LLMChain / SequentialChain / LCEL 管道 |
| Memory | 状态管理 | Buffer / Window / Summary / KG |
| Agents | 自主执行 | Agent / Tools / AgentExecutor |
| Retrieval | 知识增强 | Loaders / Splitters / VectorStore |

### Runnable 统一接口

| 方法 | 模式 | 用途 |
|------|------|------|
| invoke / ainvoke | 同步/异步单次 | 基础调用 |
| stream / astream | 同步/异步流式 | 逐 Token 输出 |
| batch / abatch | 同步/异步批量 | 并行处理 |

<Callout type="info">

LangChain 的核心创新是 Runnable 接口：所有组件实现统一的四种调用模式（invoke/stream/batch 及异步版本），使得任何组件都可以用管道符 | 无缝连接。这种统一性让链的组合自动继承流式、异步、批量和可观测性能力，无需额外开发。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="Runnable 接口">

LangChain 的核心抽象，所有组件都实现该接口。提供 invoke（单次）、stream（流式）、batch（批量）三种调用模式，每种有同步和异步版本。管道符 | 连接的组件自动继承所有调用模式。

</GlossaryItem>

<GlossaryItem term="LCEL (LangChain Expression Language)">

LangChain 表达式语言，用管道符 | 连接 Runnable 组件。相比传统 Chain 类的四大优势：流式原生、异步支持、批量处理、LangSmith 可观测性。是官方推荐的现代写法。

</GlossaryItem>

<GlossaryItem term="五大模块">

LangChain 的核心架构：Model I/O（模型交互）、Chains（流程编排）、Memory（状态管理）、Agents（自主执行）、Retrieval（知识增强）。五者通过 Runnable 接口统一组合。

</GlossaryItem>

<GlossaryItem term="AgentExecutor">

Agent 的执行引擎，管理 ReAct 循环（思考-行动-观察），控制最大迭代次数、错误处理和提前停止策略。是 Agent 从定义到执行的运行时容器。

</GlossaryItem>

<GlossaryItem term="Vector Store">

向量数据库存储模块，将文本嵌入向量存储并支持相似度检索。LangChain 集成 Chroma、FAISS、Milvus、Pinecone 等多种向量数据库，是 RAG 应用的核心基础设施。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

LangChain 的核心设计理念是什么？它通过什么机制实现模块化组合？

<Answer>

核心设计理念四点：标准化抽象——Runnable 接口统一所有组件调用方式。模块化组合——组件可插拔自由编排。LCEL 表达式语言——管道符连接组件，原生支持流式/异步/批量。生态集成——数百种工具和模型集成。模块化组合通过 Runnable 接口实现：所有组件实现统一接口（invoke/stream/batch），用管道符连接时自动传递数据，支持并行、透传、分支等组合模式。

</Answer>

### 问题 2

LangChain 的五大核心模块分别是什么？各自承担什么职责？

<Answer>

五大核心模块：Model I/O 处理与模型的交互，包含提示模板、模型调用、输出解析。Chains 将多个组件按顺序组合执行。Memory 在多轮对话中维护上下文状态。Agents 让 LLM 作为推理引擎自主决策，结合工具和执行循环。Retrieval 加载文档、分块、向量化、存储检索，支撑 RAG 应用。

</Answer>

### 问题 3

Runnable 接口提供了哪些核心方法？这些方法如何统一不同组件的调用模式？

<Answer>

Runnable 接口提供四种调用模式：invoke/ainvoke 单次同步/异步调用。stream/astream 流式同步/异步调用，逐 Token 返回。batch/abatch 批量同步/异步调用，并行处理。统一机制：所有组件都实现 Runnable 接口，用相同方法调用任何组件。管道符连接的每个组件都支持相同调用模式，整条管道自动继承流式/异步/批量能力。

</Answer>

### 问题 4

LCEL 相比传统 Chain 类有哪些优势？为什么推荐使用？

<Answer>

四大优势：流式原生——管道自动支持 stream，传统 Chain 需额外改造。异步支持——原生支持 ainvoke/astream/abatch。批量处理——batch 方法自动并行化。可观测性——与 LangSmith 深度集成，自动记录每步输入输出。推荐原因：LCEL 是官方推荐的新写法，传统 Chain 类已逐渐被标记为遗留。代码更简洁，且自动获得四大能力。

</Answer>

</Exercises>
