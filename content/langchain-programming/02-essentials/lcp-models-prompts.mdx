## 核心概念

### Model I/O 三阶段

Model I/O 是 LangChain 的基础管道，包含三个阶段：

- **Prompts**：将用户输入和变量填充到模板，格式化为模型可理解的提示
- **Models**：通过统一的 invoke 接口调用 LLM 或 ChatModel
- **Output Parsers**：将模型返回的原始文本解析为结构化数据

<LcpModelsPromptsDiagram />

### 模型类型对比

| 类型 | 接口 | 输入 | 输出 | 适用场景 |
|------|------|------|------|----------|
| LLM | predict/invoke | 纯文本 | 纯文本 | 单轮补全/摘要/翻译 |
| ChatModel | predict/invoke | Message 列表 | AIMessage | 多轮对话/角色/Function Call |

### 提示模板类型

| 模板 | 用途 | 创建方法 |
|------|------|----------|
| PromptTemplate | 单轮文本提示 | from_template |
| ChatPromptTemplate | 多角色对话提示 | from_messages |
| FewShotPromptTemplate | 少样本示例提示 | 指定 examples + example_prompt |
| MessagesPlaceholder | 动态消息占位 | 插入历史对话 |

<Callout type="info">

Model I/O 的本质是一条标准化管道：提示模板负责格式化输入，模型负责推理生成，输出解析器负责结构化结果。在 LCEL 中用管道符简洁表示：prompt | model | parser。所有模型通过 Runnable 接口统一，支持同步/异步/流式/批量四种调用模式。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="PromptTemplate">

单轮文本提示模板，用花括号变量标记占位符，format 时填充。通过 from_template 方法快速创建。适合简单的文本补全任务。

</GlossaryItem>

<GlossaryItem term="ChatPromptTemplate">

多角色对话提示模板，支持 SystemMessage/HumanMessage/AIMessage 三种角色。通过 from_messages 方法构建，可用 MessagesPlaceholder 插入动态历史对话。

</GlossaryItem>

<GlossaryItem term="Output Parser">

输出解析器，将模型返回的原始文本解析为结构化数据。StrOutputParser 返回纯字符串，JsonOutputParser 解析 JSON，PydanticOutputParser 解析并验证为 Pydantic 对象。

</GlossaryItem>

<GlossaryItem term="FewShotPromptTemplate">

少样本示例提示模板，提供多个输入-输出对作为示例，引导模型按示例格式和风格生成。适合需要特定输出格式或风格引导的场景。

</GlossaryItem>

<GlossaryItem term="PydanticOutputParser">

基于 Pydantic 的输出解析器，定义 Pydantic 模型声明字段类型和约束，自动生成格式说明注入提示，解析时自动验证类型。相比 JsonOutputParser 增加了类型验证和字段约束。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

Model I/O 的三个阶段是什么？它们如何组成完整的模型调用流程？

<Answer>

三阶段：Prompts 提示模板——将用户输入和变量填充到模板中格式化为提示文本。Models 模型调用——通过统一的 invoke 接口调用 LLM 或 ChatModel。Output Parsers 输出解析——将模型返回的原始文本解析为结构化数据。流程：输入变量到 PromptTemplate 格式化到 Model 调用到 OutputParser 解析到结构化结果。LCEL 中用管道符连接：prompt | model | parser。

</Answer>

### 问题 2

LLM 和 ChatModel 有什么区别？在什么场景下应该选择哪种模型类型？

<Answer>

LLM 输入纯文本返回纯文本，适合单轮补全任务。ChatModel 输入 Message 列表返回 AIMessage，适合多轮对话、角色扮演、Function Calling。现代 LLM 提供商已普遍转向 ChatModel 接口。多轮对话、需要系统提示、需要 Function Calling 时必须用 ChatModel。实际开发中推荐统一使用 ChatModel，功能更完整、兼容性更好。

</Answer>

### 问题 3

PromptTemplate、ChatPromptTemplate 和 FewShotPromptTemplate 各自的用途是什么？

<Answer>

PromptTemplate 用于单轮文本提示，通过 from_template 创建，变量用花括号标记。ChatPromptTemplate 用于多角色对话提示，通过 from_messages 创建，支持 System/Human/AI 三种角色和 MessagesPlaceholder 动态历史。FewShotPromptTemplate 用于少样本示例提示，提供输入-输出对引导格式和风格，适合需要特定输出格式的场景。

</Answer>

### 问题 4

如何使用 PydanticOutputParser 实现结构化输出？它相比 JsonOutputParser 有什么优势？

<Answer>

使用步骤：定义 Pydantic 模型声明字段类型和描述，创建解析器，用 get_format_instructions 注入提示，parse 解析输出并验证。相比 JsonOutputParser 的优势：类型验证（自动验证字段类型）、字段约束（支持 min_length/ge 等）、描述文档（字段描述自动注入提示）、错误处理（清晰错误信息）、嵌套模型（支持复杂结构化数据）。

</Answer>

</Exercises>
