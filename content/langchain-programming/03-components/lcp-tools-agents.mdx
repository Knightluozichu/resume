## 核心概念

### Agent 执行循环

Agent 以 LLM 为推理引擎，通过 ReAct 循环自主完成任务：

- **Thought（思考）**：分析输入和已有观察，推理下一步
- **Action（行动）**：选择工具并构造调用参数
- **Observation（观察）**：执行工具获取结果
- **循环**：反馈观察结果，继续思考直到完成

<LcpToolsAgentsDiagram />

### Agent 类型对比

| 类型 | 机制 | 优点 | 缺点 | 推荐度 |
|------|------|------|------|--------|
| ReAct Agent | 文本解析 Thought/Action | 通用性强 | 解析易错/轮次多 | 一般 |
| OpenAI Functions | Function Calling 原生 | 高效稳定 | 依赖特定模型 | 较高 |
| Tool Calling Agent | bind_tools 统一接口 | 多模型/并行调用 | 需模型支持 | 推荐 |

### 常用工具

| 工具 | 功能 | 使用场景 |
|------|------|----------|
| Search | 搜索引擎查询 | 实时信息获取 |
| Calculator | 数学计算 | 精确数值计算 |
| Python REPL | 代码执行 | 数据分析处理 |
| SQL Database | 数据库查询 | 结构化数据检索 |
| API Request | HTTP 请求 | 外部服务调用 |

<Callout type="info">

Agent 的本质是让 LLM 从"回答者"进化为"行动者"：不再只是生成文本，而是自主选择工具、规划步骤、循环执行。ReAct 循环（思考-行动-观察）是核心执行模式。生产环境推荐 Tool Calling Agent：结构化输出可靠、支持多模型切换、支持并行工具调用，是 LangChain 官方主推的现代写法。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="Agent">

以 LLM 为推理引擎的智能系统，能够自主感知输入、规划决策、选择工具、执行行动。通过 ReAct 循环实现思考-行动-观察的迭代执行，直到完成任务。

</GlossaryItem>

<GlossaryItem term="ReAct">

Reason + Act 的缩写，Agent 的核心执行模式。LLM 交替进行推理（Thought）和行动（Action），每次行动后观察结果（Observation），循环直到完成。通用性强但轮次多。

</GlossaryItem>

<GlossaryItem term="Tool Calling Agent">

新一代统一 Agent 接口，通过 model.bind_tools(tools) 绑定工具，模型直接输出结构化工具调用消息。支持多模型、并行工具调用，是生产环境推荐写法。

</GlossaryItem>

<GlossaryItem term="AgentExecutor">

Agent 的执行引擎，管理 ReAct 循环。控制最大迭代次数（max_iterations）、错误处理（handle_parsing_errors）、提前停止策略（early_stopping_method）和回调支持。

</GlossaryItem>

<GlossaryItem term="@tool 装饰器">

LangChain 自定义工具的快捷方式，装饰 Python 函数使其成为 Tool。函数文档字符串作为工具描述，参数类型注解自动生成 schema。是定义自定义工具最简洁的方式。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

Agent 的 ReAct 执行循环是什么？AgentExecutor 如何控制这个循环？

<Answer>

ReAct 循环：Thought 思考——分析输入和已有观察，推理下一步。Action 行动——选择工具并构造参数。Observation 观察——执行工具获取结果。循环直到任务完成。AgentExecutor 控制机制：max_iterations 限制最大轮次防止无限循环。early_stopping_method 达到上限后让 LLM 生成最终答案。handle_parsing_errors 处理格式错误自动重试。return_intermediate_steps 返回每步记录便于调试。

</Answer>

### 问题 2

如何在 LangChain 中定义和创建自定义工具？Tool 的关键属性是什么？

<Answer>

两种方式：@tool 装饰器——装饰函数，文档字符串作为描述。继承 BaseTool——实现 _run 和 _arun 方法。关键属性：name 工具名称需唯一简洁。description 描述告诉 Agent 何时使用，应包含用途、输入格式、输出格式。args_schema Pydantic 模型定义参数 schema。return_direct 是否直接返回工具输出跳过 LLM 处理。最佳实践：描述清晰具体，参数有明确类型约束，复杂工具拆分为多个简单工具。

</Answer>

### 问题 3

ReAct Agent、OpenAI Functions Agent 和 Tool Calling Agent 有什么区别？生产环境应选哪种？

<Answer>

ReAct Agent 基于文本解析，通用但解析易错、轮次多。OpenAI Functions Agent 利用 Function Calling 原生能力，高效稳定但仅依赖 OpenAI。Tool Calling Agent 新一代统一接口，bind_tools 绑定工具，支持多模型和并行调用。生产环境推荐 Tool Calling Agent：结构化输出可靠无解析错误，支持多模型切换不被供应商锁定，支持并行工具调用效率更高，LangChain 官方主推，与 LangGraph 深度集成。

</Answer>

### 问题 4

设计一个能搜索网页、执行代码和查询数据库的研究助手 Agent，描述其完整实现方案。

<Answer>

完整方案：工具定义——搜索工具 DuckDuckGoSearchRun，代码执行 PythonREPLTool，数据库 SQLDatabaseToolkit。模型 ChatOpenAI(model=gpt-4o, temperature=0)。Agent 用 create_tool_calling_agent 创建，系统提示设定研究助手角色。AgentExecutor 配置 max_iterations=15、handle_parsing_errors=True。添加 ConversationBufferWindowMemory(k=5) 支持多轮。安全措施：PythonREPL 沙箱、SQL 只读、搜索结果限制。调用 agent_executor.invoke 执行，Agent 自主搜索、分析、查询、综合生成报告。

</Answer>

</Exercises>
