## 为什么先冻结依赖、数据流与trace

<Term def="依赖锁定是第2章 LangChain初体验的第1个可执行证据坐标。">依赖锁定</Term>、<Term def="语言模型是第2章 LangChain初体验的第2个可执行证据坐标。">语言模型</Term>、<Term def="提示模板是第2章 LangChain初体验的第3个可执行证据坐标。">提示模板</Term>、<Term def="输出解析是第2章 LangChain初体验的第4个可执行证据坐标。">输出解析</Term>、<Term def="LCEL是第2章 LangChain初体验的第5个可执行证据坐标。">LCEL</Term>、<Term def="安全实践是第2章 LangChain初体验的第6个可执行证据坐标。">安全实践</Term>共同构成本页坐标。从可复现环境开始，把模型、提示、解析器组合成最小LCEL链，再接入观测与服务边界，最后用密钥和输入安全关闭快速入门。

LangChain是快速演进的框架，本书首版记录的是2023至2024年前后的模块和接口。学习时必须分开原书的架构脉络、首版代码形状和后来版本的迁移方式。类名废弃不会让Runnable、schema、检索、工具权限、记忆隔离和事件追踪失效；实现应以端口与契约测试隔离具体版本。

每次运行保存Python版本、依赖锁摘要、代码提交、环境配置名、输入、节点图、模型与工具版本、事件trace、原始错误、输出校验和回退动作。只保存最终回答无法区分模板、模型、检索、记忆、工具或回调中的首个错误，也无法证明升级前后语义相同。

<Callout type="info">**验收命题：** 能在固定依赖与假模型上运行invoke、stream和服务适配，保存trace，并证明密钥、输入与输出不会越过边界。</Callout>

## 数学与执行骨架

$$
output=parse(model(render(input)))
$$

$$
environment=python+packages+config
$$

$$
latency=render+model+parse
$$

$$
safe=secret\land input\land output
$$

公式用于固定比较对象：组合必须说明函数方向，检索必须说明分母，代理必须有预算，事件必须有父子关系。框架生成的图或trace只是观测结果，仍需用输入输出断言和故障样本证明业务语义。

## 三段可运行骨架

```python
def freeze_run(code_version, dependency_lock, config, inputs):
    return {"code": code_version, "lock": dependency_lock, "config": config, "inputs": inputs}
```

```python
def record(trace, node, expected, actual):
    trace.append({"node": node, "expected": expected, "actual": actual, "ok": expected == actual})
    return trace
```

```python
def first_divergence(trace):
    return next((item for item in trace if not item["ok"]), None)
```

代码通过普通Python表达核心合同，可在没有外部模型、LangSmith或LangServe时运行。接入真实LangChain版本时，由薄适配器映射到相应Runnable、模型、检索器或回调API；契约测试不随类名变化，从而可以精确定位迁移差异。

## 固定样例与手算

先用三个节点构造管道：模板节点接收字典并输出消息，模型假对象接收消息并输出固定结构，解析节点验证必需字段。分别调用单次、两项批量和逐块流式接口，聚合后的业务结果应一致；若事件数量或顺序不同，差异必须在trace中可解释。

再取查询向量q=(1,0)、文档向量d1=(0.8,0.6)、d2=(0,1)，余弦相似度分别为0.8和0。检索top-1应返回d1，但这只证明向量邻近，不证明d1支持答案。生成前仍需核对文档ID、嵌入版本、文本范围和引用；空召回必须拒答。

代理实验注册read与write两个工具，普通权限只允许read。模型若选择write，schema可以正确但权限门禁仍应拒绝；工具超时不得被改写成“执行成功”。记忆实验再写入两名用户的同名事实，读取必须按租户隔离，并在过期时间后删除。

最后注入三个故障：依赖版本改变输出字段、检索器返回失效文档ID、回调处理器抛出异常。系统应分别在解析、引用校验和观察端口报告首个分叉；回调失败不篡改已完成的业务结果，解析与引用失败则阻断发布。

## 常见失败与回退

<Callout type="trap">**本章高风险失败：** 复制最新版文档代码到首版环境，未锁依赖就排查逻辑，或把LangServe暴露的链视为自动安全。</Callout>

<Callout type="trap">**框架抽象不是责任转移：** 链能运行不代表schema、来源、权限、记忆隔离和trace通过；中间合同失败必须阻断相应动作。</Callout>

<Callout type="tip">**回退顺序：** 环境锁 → 输入schema → 节点路由 → 模型或检索 → 输出解析 → 工具权限 → 记忆写入 → 回调。首个差异未解释前不比较整段回答。</Callout>

## 本章回顾

从可复现环境开始，把模型、提示、解析器组合成最小LCEL链，再接入观测与服务边界，最后用密钥和输入安全关闭快速入门。 掌握标准不是记住快速变化的API，而是能重建节点、合同、trace、失败和回退。通过标准为：能在固定依赖与假模型上运行invoke、stream和服务适配，保存trace，并证明密钥、输入与输出不会越过边界。
