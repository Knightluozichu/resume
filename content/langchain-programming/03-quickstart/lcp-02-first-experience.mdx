## 为什么第一次体验不从密钥开始

假如终端已经打印出一段流畅的回答，你能判断是模板生效了、模型接通了，还是程序只是返回了预设文本吗？第一次体验应先建立可检查的数据路径，再接入外部服务。

本页先把模型替换为确定性的离线函数，让每一阶段都可复算；最后再说明真实SDK、观测平台与HTTP部署各自增加了什么责任。三个图与程序都不需要密钥，也不宣称发生过在线模型调用。

## 第2章 LangChain初体验

这一章的产物不是“一个能回答问题的聊天框”，而是一条能说明输入、处理阶段、输出和失败位置的最小路径。贯穿输入为 `{"topic": "缓存"}`：模板把主题放入用户消息，离线模型返回JSON文本，解析器再生成字典。依赖图解释它在哪里运行，类型管道解释它怎样变形，运行树解释何时成功或中断。学习完应能把故障定位到阶段，而非笼统地说“LangChain坏了”。

## 2.1 开发环境准备

先把“解释器能运行”“依赖能导入”“请求能到达服务端”分开检查。<Term def="为一个项目单独保存解释器关联和安装包的目录，避免其他项目的包互相干扰">虚拟环境</Term>解决本机包隔离，不保证远端模型、驱动或系统库也一致。记录 `python --version`、`python -m pip --version`，确认pip属于同一解释器；部署机还需记录操作系统、架构与系统依赖。

**先预测：** 只删除provider集成包，`langchain-core`会一并消失吗？在实验一卸载集成包，再切换v1/classic路径和Python版本。观察分支消失与入口阻断的区别；完成后全重置，回到Python 3.11、v1路径和集成包存在的状态。

### 2.1.1 管理工具安装

管理工具负责创建环境、安装/解析依赖并记录结果，框架则提供运行时能力。第一次只使用Python自带的venv与pip，避免同时混用多个包管理器；后续采用uv或其他工具时，也应保留一个明确的环境入口。

```bash
python3 --version
python3 -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell 改用 .venv\Scripts\Activate.ps1
python -m pip --version
```

这些是读者操作指引，不是本站声称已在所有平台执行的日志。下文离线程序**不需要pip安装任何包**。接入真实SDK时才在单独环境选择并锁定 `langchain`、对应provider包及其兼容依赖；不要把没有版本号的安装命令当成可复现环境。

<Term def="记录实际解析出的依赖版本，必要时连同哈希和环境标记固定安装结果的文件">依赖锁</Term>与虚拟环境是两件事：前者描述“应该装什么”，后者承载“本机实际装了什么”。`python -m pip freeze > requirements.snapshot.txt`可记录当前安装版本，但不等于跨平台、含哈希的完整锁；换机仍需重装、检查并运行测试。删除环境重建，比依赖“我机器上以前装过”更可靠。

### 2.1.2 源码安装

源码安装适合阅读实现、验证修复或贡献补丁，不是普通调用SDK的必需步骤。先在官方仓库选择与目标发布版本对应的tag或提交，查看该提交的开发文档与包目录，再在包根执行其支持的安装方式，例如 `python -m pip install -e .`。LangChain是多包仓库，不能假定仓库根就是单一可安装包。

`-e`使导入指向工作区，修改源码可能立刻改变行为；必须记录提交ID、未提交补丁、安装包目录与依赖锁。若 `import langchain` 意外加载了当前目录下同名文件，应先查 `module.__file__`，而不是反复重装。实验一的导入路径图只画选定依赖关系，不伪装为某个历史提交的完整依赖树。

### 2.1.3 其他库安装

`langchain-core`提供消息、提示与Runnable等基础抽象，`langchain`提供当前高层入口，provider集成包负责对接具体模型SDK；LangSmith客户端用于观测，服务层还可能依赖Web框架。它们不是一个“装了LangChain就全部接通”的整体。

将故障按层排查：`ModuleNotFoundError`先查包与解释器；认证失败查密钥和权限；超时查网络与服务端；解析错误查返回内容与解析约束。实验一没有画网络边，因为**包能导入并不意味着网络能调用**。真实接入时记录provider、模型标识、包版本和环境变量名，但不要把变量值写进依赖清单。

<Callout type="trap" title="同名包与导入路径不是同一个概念">
  **现象 →** pip显示已安装，Python仍无法导入旧Chain。 **原因 →**
  解释器错位，或v1命名空间已精简；不是所有旧入口都留在langchain内。 **修法 →**
  先核对pip所属解释器，再按迁移指南判断应迁移接口还是显式采用langchain-classic；不可只改包名而不测行为。
</Callout>

## 2.2 快速开始

把链理解成三个可单独测试的函数：`format_prompt → fake_model → parse`。每个阶段只接收上一阶段的输出。<Term def="规定输入有哪些字段、字段类型及必要校验的规则">输入schema</Term>在本例要求topic为非空字符串；输出则要求answer为字符串。Python类型注解本身不会强制运行时检查，所以程序另写显式校验。

**先预测：** 模型阶段结束后，结果是字典还是装着字符串的消息对象？在实验二逐步执行三次；再全重置、注入坏JSON并重复操作。应看到消息已生成，但最后的字典没有出现，失败点是解析而非环境。

### 2.2.1 语言模型

语言模型接口把模型服务包装成可调用对象。真实聊天模型常接收消息序列并返回 `AIMessage`，其内容可能是文本或结构化内容块，不能无条件把任意模型的 `content` 当成JSON字符串。provider集成解决协议差异，模型选择、采样参数、超时与凭据仍要由应用确定。

本例用 `fake_model` 取代外部服务：固定输入必得固定JSON文本。这样能隔离“模型输出不符合约定”的失败，不能据此判断真实模型质量。当前v1可从标准模型接口开始；需要工具循环与状态管理时再学习 `create_agent` 与LangGraph，而非把每次单模型调用都包装成agent。

### 2.2.2 提示模板

<Term def="把固定指令和本次输入按位置组合成消息或文本的规则">提示模板</Term>将格式约束放在system消息，把本次主题放在user消息。输入 `{"topic":"缓存"}` 不是直接交给模型的句子，必须先完成变量校验和格式化。真实LangChain中的 `ChatPromptTemplate` 通常产出 `ChatPromptValue`，可以转换为消息列表；本例直接使用列表，刻意省去SDK对象层。

模板不是安全沙箱：用户即使在topic里写“忽略所有指令”，也不应因此获得文件或网络权限。字符串插值也不等于执行Python表达式；不要为便利而接受未受信任的模板代码或使用 `eval`。

### 2.2.3 输出解析器

<Term def="把模型返回的内容转换为应用需要的数据形状，并在不合规则时报告错误的步骤">输出解析器</Term>不负责“让模型变聪明”。`json.loads`只能验证JSON语法；`{"answer":7}`语法正确，却不满足本例answer为字符串的约束。因此程序在解析后再检查字段类型。

实验二的坏JSON缺少正确引号，错误在语法解析阶段产生，下游字典必须缺席。真实项目可采用结构化输出能力或更严格的schema校验，但仍需处理拒绝、截断、超时及不合规则的结果，不要把空字典作为静默兜底。

<Callout type="trap" title="模型成功不等于业务成功">
  **现象 →** 已收到AIMessage，应用仍报JSONDecodeError。 **原因 →**
  通信成功只证明收到内容，不能保证其格式或字段合法。 **修法 →**
  分开记录模型run与解析run；验证字段，明确返回错误或有上限的重试，不伪造正常结果。
</Callout>

### 2.2.4 使用LCEL进行组合

<Term def="LangChain Expression Language，用Runnable的组合规则构造可调用的数据处理链">
  LCEL
</Term>
把兼容的Runnable串联起来，常见写法是 `prompt | model |
parser`。`|`表示前者输出交给后者，**不会自动修补类型**；相邻阶段形状不匹配时仍会失败。普通Python函数的
`|`并不能直接组合，本页离线程序用函数调用表达相同的数据流，不冒充SDK的Runnable实现。

Runnable常用入口包括 `invoke`（一个输入得到一个结果）、`batch`（多个输入分别执行，通常按输入顺序收集结果）、`stream`（迭代取得输出片段）。实际并发、异步与异常选项取决于实现；流能否逐步穿过整条链还取决于各阶段是否支持流式转换。完整JSON解析器可能等到末尾才返回，不能仅凭调用了stream就断言全链低延迟。

#### 可复核离线最小程序：先看见类型，再替换模型

依次把以下三段保存到同一个 `quickstart_offline.py`。只用标准库，运行 `python3 quickstart_offline.py`；不需要LangChain、API密钥或联网。本章证据目录保留同名完整程序、独立测试与真实输出。第一段定义输入校验和两条消息，`topic`不合规则直接在模板边界失败。

```python
import json
from dataclasses import dataclass

@dataclass(frozen=True)
class AIMessage:
    content: str

def format_prompt(data: dict) -> list[dict[str, str]]:
    topic = data.get("topic")
    if not isinstance(topic, str) or not topic.strip():
        raise ValueError("topic must be a non-empty string")
    return [
        {"role": "system", "content": "只返回含answer的JSON"},
        {"role": "user", "content": topic},
    ]

def fake_model(messages: list[dict[str, str]], bad=False) -> AIMessage:
    if bad:
        return AIMessage("answer: 缺少JSON引号")
    topic = messages[-1]["content"]
    return AIMessage(json.dumps({"answer": topic + "的解释"},
                                ensure_ascii=False))
```

第二段把AIMessage的字符串内容转换成字典，并组合成一个最小执行入口。解析失败会抛出异常，不能带着无效结果继续运行。本例只保留answer字段，其他字段不会透传。

```python
def parse(message: AIMessage) -> dict[str, str]:
    data = json.loads(message.content)
    if not isinstance(data, dict) or not isinstance(data.get("answer"), str):
        raise ValueError("answer must be a string")
    return {"answer": data["answer"]}

def invoke(data: dict, bad=False) -> dict[str, str]:
    messages = format_prompt(data)
    reply = fake_model(messages, bad=bad)
    return parse(reply)

def stream(data: dict, fail=False):
    text = fake_model(format_prompt(data)).content
    cuts = (0, len(text) // 3, 2 * len(text) // 3, len(text))
    for i in range(3):
        if fail and i == 1:
            raise TimeoutError("offline simulated interruption")
        yield text[cuts[i]:cuts[i + 1]]
```

第三段演示单次、批量、流缓冲以及坏JSON。这里batch是显式列表推导式，**顺序执行**，不是SDK并发测试；stream把字符串分成三块，不等于真实token流。完整缓冲后才调用parse，与实验三的“片段不等于最终结果”一致。

```python
if __name__ == "__main__":
    sample = {"topic": "缓存"}
    print("invoke:", invoke(sample))
    print("batch:", [invoke({"topic": t}) for t in ("缓存", "管道")])
    chunks = list(stream(sample))
    print("stream chunks:", chunks)
    print("stream parsed:", parse(AIMessage("".join(chunks))))
    try:
        invoke(sample, bad=True)
    except json.JSONDecodeError as exc:
        print("failure:", type(exc).__name__)
```

应得到 `invoke: {'answer': '缓存的解释'}`，batch依次返回缓存、管道两个字典；流的三段拼接后等于模型完整JSON文本，最后打印 `failure: JSONDecodeError`。这是离线函数的可复算结果，不是在线SDK执行证明。真实接入的下一步是保持schema测试不变，单独替换模板/模型适配层，再验证凭据、网络、返回内容形状与SDK版本。

### 2.2.5 使用LangSmith进行观测

<Term def="把一次请求内各处理步骤关联起来的运行记录，包含父子关系、输入输出、状态及时间等信息">
  执行trace
</Term>
回答“哪一步先失败”，不是仅保存最后一句回答。一次模板—模型—解析链可以有一个root
run和三个子run，模型输出正常而解析失败时，两个子run的状态不同。LangSmith提供trace采集、查看、调试和评估能力，具体开启方式与环境变量应依[官方文档](https://docs.langchain.com/langsmith/observability)配置。

观测与评估也不同：trace说明这次怎样执行，独立测试集则检查是否满足预期。上线前应验证成功与失败都能关联到请求，确保采样或脱敏不会隐藏关键错误。涉及云端上传时先审查输入、消息和输出是否含个人信息或凭据；仅关闭界面展示不等于未上传。

**先预测：** 把一次调用改为三个输入的batch，应该变成一个更长prompt，还是三个子运行？实验三选择batch并拖动时钟；再选stream，看三个片段到达后才产生完整结果。注入模型中断，观察条宽在第3拍封口，解析阶段缺席；全重置会恢复invoke、时钟0和无故障。

### 2.2.6 使用LangServe提供服务

LangServe在历史教程中用于把Runnable暴露为HTTP接口，常围绕invoke、batch、stream和输入/输出schema构建服务。其职责是传输与接口封装，不是自动完成鉴权、限流、租户隔离和模型质量保证。HTTP传入的JSON还需要验证才能进入模板；内部异常应映射成不泄露堆栈或密钥的错误响应。

2024的“本地链→LangServe端点”应按当时匹配的包版本理解。[LangServe官方仓库](https://github.com/langchain-ai/langserve)本次可访问，并明确建议新项目考虑LangGraph Platform而非LangServe。当前产品名称和部署选项继续演进，应依最新官方部署资料选型；不能称LangServe为v1唯一生产推荐，也不能把LangGraph运行时、LangSmith观测与HTTP服务视作同一个东西。

本章未启动LangServe或Web服务。若把离线invoke包装为服务，至少写下以下接口合同并实际测试：请求体 `{"topic":"缓存"}`；成功返回 `{"answer":"缓存的解释"}`；输入非法与模型/解析失败分开处理；流式接口在中断时发出明确错误/结束信号而不是追加“正常完成”。还需鉴权、限流、超时、日志脱敏、部署环境锁以及回退版本；图中root的失败封口就是服务端不能忽略的状态。

## 2.3 最佳安全实践

从“有什么输入、能触达什么资源、会把什么数据送出去”划定边界。<Term def="只授予完成当前任务必需的权限和资源访问范围">最小权限</Term>意味着教学模型调用不应同时拿到生产数据库写权限；密钥从服务端环境或受控密钥系统读取，不放进浏览器包、Git、提示模板和trace。依赖升级前查官方安全公告，不能以书的出版年份判断今天是否安全。

| 边界          | 典型风险                          | 本章可操作的检查                                 |
| ------------- | --------------------------------- | ------------------------------------------------ |
| 输入→模板     | 未受信任模板、超长输入、缺失topic | 只接受预定义字段与非空字符串，服务层另设长度上限 |
| 模型→解析     | 无效JSON、错误字段、被截断内容    | 先语法后字段校验；失败时不交付业务结果           |
| 运行→观测平台 | 提示、凭据、个人信息外传          | 上传前脱敏/过滤，检查失败run也不含秘密           |
| 调用→服务资源 | 匿名滥用、超时堆积、工具越权      | 鉴权与配额、超时取消、服务端最小权限             |

提示注入不能靠“再写一句不要泄密”根治，权限检查必须在模型之外执行。本例没有工具执行、文件读取或外部网络权限，因此坏JSON只能导致解析失败；将来增加工具时，应新增参数白名单、授权检查和副作用审计。

<Callout type="trap" title="成功截图不能代替安全和失败证据">
  **现象 →** 演示成功，却在日志或浏览器包中发现真实密钥；流中断还显示完成。
  **原因 →** 把可观测性等同于全量上传，把局部片段当成业务结果。 **修法 →**
  撤销泄露密钥、审查上传字段，按root状态结束请求；保存不含秘密的失败trace和可重建环境。
</Callout>

## 小结与练习

- 环境导入、网络调用、结果解析必须分层检查。
- 模型返回消息不等于解析后的业务字典。
- batch增加运行分支；stream片段需要结束语义。
- 解析失败先查内容，发布还需服务、安全与真实集成证据。

**问题 1：重建一次可解释的环境。** 同事安装了最新版langchain，又用2024教程导入旧Chain，报错后直接编辑site-packages。请说明管理工具、源码安装、其他库分别该怎么处理，并在实验一演示“旧入口”与“缺包”不是同一故障。

</Answer>

**问题 2：改代码并独立实现字段校验。** 在fake_model里返回 `{"answer":7}`，预测在哪一阶段失败。再给输出增加 `source: "offline"`，要求解析器只接受这个固定值；为topic为空、坏JSON和正常输入各写一个断言。

<Answer>
  数字answer是合法JSON，json.loads会通过，随后字段检查抛出ValueError；与实验二缺引号触发JSONDecodeError不同。将fake_model的正常JSON对象加入source字段，在parse的字典检查后验证
  `data.get("source") ==
  "offline"`，不符时抛ValueError，并返回含answer与source的字典。正常输入应得到两个字段；空topic在format_prompt抛ValueError；坏JSON仍在json.loads抛JSONDecodeError。最后保留原来的批顺序与流拼接测试，确认修改没有破坏组合。真实LCEL中也要检查相邻Runnable的输入输出，不能期望竖线替你补字段。
</Answer>

**问题 3：从流中断决定服务行为。** 实验三在stream模式注入第3拍中断，再解释：应该上传哪类run状态？客户端能否把第一片当作成功JSON？若要通过LangServe或其他服务层部署，还缺什么？

<Answer>
  应保留关联请求的root与模型失败状态，解析阶段未执行，不能伪造成功run。片段1只是JSON文本的一部分，不满足完整语法，必须结束为错误或按协议告知中断；若重试，要有预算并避免副作用重复。观测前脱敏，不上传密钥；服务端补齐输入校验、鉴权、配额、超时、取消和错误映射。LangSmith负责观测而非替代服务鉴权，LangServe是历史封装方案，不是v1唯一推荐。上线仍缺真实SDK、provider网络、服务端点、真实trace上传及部署回退测试，本章离线成功不能覆盖它们。

## 名词解释

<Glossary>
  <GlossaryItem term="虚拟环境">
    一个项目自己的包目录与解释器关联；让项目之间少互相影响，不隔离远端服务。
  </GlossaryItem>
  <GlossaryItem term="依赖锁">
    记录需要安装的确切依赖结果；与本机已有环境对照才能判断是否重建一致。
  </GlossaryItem>
  <GlossaryItem term="输入schema">
    允许进入程序的字段与类型规则；本例topic必须是非空字符串。
  </GlossaryItem>
  <GlossaryItem term="提示模板">
    固定消息骨架加本次变量，产出交给模型的消息；不是权限控制器。
  </GlossaryItem>
  <GlossaryItem term="输出解析器">
    把模型内容变成应用数据的步骤；格式或字段不合法时应该显式报错。
  </GlossaryItem>
  <GlossaryItem term="LCEL">
    用Runnable组合规则表达数据流的语言；相邻阶段仍必须类型相容。
  </GlossaryItem>
  <GlossaryItem term="执行trace">
    一次请求的运行记录树，可看见哪个步骤成功、哪个失败；不是答案正确性的证明。
  </GlossaryItem>
  <GlossaryItem term="最小权限">
    只开放任务必需的能力；模型能生成文本，不代表它应能执行任意命令。
  </GlossaryItem>
</Glossary>
