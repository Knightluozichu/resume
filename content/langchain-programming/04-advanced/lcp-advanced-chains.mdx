## 核心概念

### LCEL 核心 Runnable 原语

LCEL 提供一组 Runnable 原语，用于构建复杂的链式组合：

- **RunnablePassthrough**：透传输入，assign 方法添加新字段
- **RunnableParallel**：并行执行多个 Runnable，结果按字典合并
- **RunnableLambda**：将普通函数包装为 Runnable
- **RunnableBranch**：条件分支，根据条件选择不同 Runnable
- **RunnableMap**：字典映射，并行调度

### 动态路由模式

| 模式 | 实现 | 适用场景 |
|------|------|----------|
| 条件路由 | RunnableBranch | 规则明确的分支 |
| 语义路由 | LLM 分类 + Lambda 路由 | 需要理解语义的分类 |
| 并行调度 | RunnableParallel | 同时获取多种数据 |

### LCEL 四大优势

| 优势 | 说明 | 价值 |
|------|------|------|
| 流式原生 | stream/astream 自动支持 | 降低首字延迟 |
| 异步支持 | ainvoke/astream/abatch | 高并发场景 |
| 批量处理 | batch 自动并行化 | 提升吞吐量 |
| 可观测性 | LangSmith 自动追踪 | 调试和监控 |

<Callout type="info">

LCEL 的本质是用管道符 | 组合 Runnable 原语，统一同步/异步/流式/批量四种调用模式。路由模式有三种：RunnableBranch 条件分发（规则明确）、Router LLM 语义分发（需理解语义）、RunnableMap 并行调度（同时获取多种数据）。RunnablePassthrough.assign 是多步数据流的关键——在不丢失原始数据的前提下添加新字段。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="RunnablePassthrough">

LCEL 透传原语，不修改输入直接传递。assign 方法在保留原始输入的同时添加新字段，是多步数据流传递的关键工具。在 RAG 链中用于同时传递检索结果和原始问题。

</GlossaryItem>

<GlossaryItem term="RunnableParallel">

LCEL 并行原语，同时执行多个 Runnable，输入相同，结果按字典键合并。用于同时从多个来源获取数据，如并行检索多个知识库或同时获取检索结果和透传原始问题。

</GlossaryItem>

<GlossaryItem term="RunnableBranch">

LCEL 条件分支原语，根据条件函数选择执行不同的 Runnable。按顺序匹配条件，第一个满足的执行其 Runnable，都不匹配则执行 default。用于动态路由，替代传统 RouterChain。

</GlossaryItem>

<GlossaryItem term="RunnableLambda">

LCEL 函数包装原语，将普通 Python 函数包装为 Runnable，使其可以加入管道。用于自定义数据转换逻辑，如格式化检索结果、提取特定字段。

</GlossaryItem>

<GlossaryItem term="Router Chain">

动态路由链，根据输入内容将请求分发到不同的处理链。传统写法用 RouterOutputParser + MultiPromptChain，现代推荐用 RunnableBranch 或 LLM 分类 + RunnableLambda 路由。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

LCEL 的核心 Runnable 原语有哪些？各自的作用是什么？

<Answer>

核心原语：RunnablePassthrough 透传输入不修改数据，assign 方法添加新字段。RunnableParallel 并行执行多个 Runnable，结果按字典键合并。RunnableLambda 将普通函数包装为 Runnable。RunnableBranch 条件分支根据条件选择不同 Runnable。RunnableMap 字典映射并行调度。RunnableSequence 管道序列用 | 连接自动创建。RunnableWithFallbacks 主 Runnable 失败时切换备用。

</Answer>

### 问题 2

如何用 LCEL 实现动态路由？与传统 RouterChain 相比有何优势？

<Answer>

两种方式：RunnableBranch——按条件函数顺序匹配，第一个满足的执行对应 Runnable。自定义 RunnableLambda 路由——先用 LLM 分类，再根据分类结果用 Lambda 选择对应链。与传统 RouterChain 对比的优势：代码更简洁无需定义多个组件。自动流式支持。条件函数可以是任意 Python 逻辑。可与其他 LCEL 组件无缝组合。与 LangSmith 集成自动追踪路由决策。

</Answer>

### 问题 3

RunnablePassthrough.assign 的工作原理是什么？在 RAG 链中如何使用？

<Answer>

工作原理：接收字典输入，在不修改原始键值对的前提下添加新字段。新键的值通过传入的 Runnable 计算得到，输入是完整输入字典。在 RAG 链中使用：chain = (RunnablePassthrough.assign(context=lambda x: retriever(x["question"])) | prompt | model | parser)。作用：检索器只需 question 字段，但模型需要 context 和 question 两个字段。assign 确保两者都传递到下游。每一步都可以 assign 新字段，构建复杂的数据流管道。

</Answer>

### 问题 4

设计一个多知识库路由 RAG 系统：用户问题先分类，再路由到对应知识库检索，最后生成答案。

<Answer>

实现：定义分类链 classify_chain = classify_prompt | model | StrOutputParser()。准备多个检索器 tech/finance/legal/general。定义路由函数根据 category 选择检索器。构建完整链：full_chain = (RunnablePassthrough.assign(category=classify_chain) | RunnablePassthrough.assign(context=lambda x: route_retriever(x).get_relevant_documents(x["question"])) | qa_prompt | model | StrOutputParser())。两个 assign 分别添加 category 和 context，原始 question 始终保留。调用 full_chain.invoke 执行，自动分类路由检索生成。

</Answer>
