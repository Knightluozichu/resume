## 核心概念

### RAG 两阶段流程

RAG（检索增强生成）让模型"开卷考试"，通过检索外部知识减少幻觉：

- **离线索引**：Document Loaders 加载文档 → Text Splitters 分块 → Embeddings 向量化 → Vector Store 存储
- **在线检索**：用户提问向量化 → similarity_search 检索 Top-K → Context 构造 → LLM 生成

### 分块策略参数

| 参数 | 推荐值 | 影响 |
|------|--------|------|
| chunk_size | 500-1000 | 太大稀释相似度，太小语义不完整 |
| chunk_overlap | 50-200 (10%-20%) | 防止边界信息丢失 |
| separators | 段落-行-空格 | 递归保持语义完整性 |

### 关键优化策略

| 策略 | 原理 | 效果 |
|------|------|------|
| 混合检索 | 向量 + BM25 关键词 | 提升召回率 |
| 重排序 | Cross-Encoder 重排 Top-K | 提升精确度 |
| Multi-Query | 多角度查询扩展 | 覆盖更多语义 |
| Parent Document | 检索小块返回大块 | 保持上下文完整 |

<Callout type="info">

RAG 的本质是为模型提供准确的外部知识，让回答有据可依。LCEL 实现 RAG 链的关键是 RunnablePassthrough.assign——在保留原始问题的同时添加检索结果字段，确保两者都传递给模型。生产环境需要从分块策略、检索方法、重排序三个维度优化检索质量。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="RAG (检索增强生成)">

Retrieval Augmented Generation，在生成前检索外部知识增强模型回答。离线索引阶段构建向量知识库，在线检索阶段检索相关文档并构造增强提示。有效减少幻觉，让模型开卷考试。

</GlossaryItem>

<GlossaryItem term="RecursiveCharacterTextSplitter">

递归字符分块器，优先用段落分隔符分割，其次换行符，最后空格。递归方式尽可能保持语义完整性。chunk_size 控制块大小，chunk_overlap 控制重叠防止边界信息丢失。

</GlossaryItem>

<GlossaryItem term="Vector Store">

向量数据库，存储文本嵌入向量并支持相似度检索。LangChain 集成 Chroma、FAISS、Milvus、Pinecone 等。as_retriever 方法将向量库转为 Runnable 检索器，可加入 LCEL 管道。

</GlossaryItem>

<GlossaryItem term="EnsembleRetriever">

集成检索器，融合向量语义检索和 BM25 关键词检索。取长补短——向量覆盖语义相关但用词不同的文档，BM25 覆盖精确关键词匹配。通过 weights 参数调节权重。

</GlossaryItem>

<GlossaryItem term="MultiQueryRetriever">

多查询检索器，用 LLM 从多个角度重写用户问题，每个问题分别检索，合并去重结果。覆盖更多语义维度，提高召回率。适合用户提问表述单一的场景。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

RAG 的完整流程分为哪两个阶段？每个阶段包含哪些步骤？

<Answer>

离线索引阶段：Document Loaders 加载文档，Text Splitters 分块，Embeddings 向量化，Vector Store 存储建立索引。在线检索阶段：用户提问向量化，similarity_search 检索 Top-K，Context 构造将检索片段与问题组装为增强提示，LLM 基于检索内容生成回答。LCEL 实现：chain = retriever | prompt | model | parser，或用 RunnablePassthrough.assign 保留原始问题。

</Answer>

### 问题 2

RecursiveCharacterTextSplitter 的工作原理是什么？chunk_size 和 chunk_overlap 如何影响 RAG 效果？

<Answer>

递归地尝试用分隔符（段落-行-空格）分割文本，优先在语义边界分割。chunk_size 太大（>1000）单个块信息过多检索精度下降，太小（&lt;300）语义不完整。chunk_overlap 重叠确保边界信息不丢失，通常 10%-20%。推荐 chunk_size=500-1000，chunk_overlap=50-200。选择原则：语义完整性优先，兼顾检索精度和 Token 效率。

</Answer>

### 问题 3

如何用 LCEL 实现一个完整的 RAG 链？如何同时传递检索结果和原始问题给模型？

<Answer>

创建检索器 vectorstore.as_retriever(search_kwargs=k)。定义提示模板包含 context 和 question 两个变量。组合链用 RunnablePassthrough.assign 保留原始输入并添加 context 字段：chain = (RunnablePassthrough.assign(context=lambda x: retriever.get_relevant_documents(x["question"])) | prompt | model | parser)。也可用 RunnableParallel 并行获取 context 和透传 question。RunnablePassthrough 的作用是透传原始输入确保不丢失。

</Answer>

### 问题 4

如何优化 RAG 系统的检索质量？描述至少三种高级优化策略及其原理。

<Answer>

三种策略：混合检索——结合向量语义检索和 BM25 关键词检索，用 EnsembleRetriever 融合，向量覆盖语义相关文档，BM25 覆盖精确关键词匹配，提升召回率。重排序——先检索 Top-20 候选再用 Cross-Encoder 重新打分取 Top-5，Bi-Encoder 速度快精度有限，Cross-Encoder 逐一打分精度高，两阶段平衡速度和精度。Multi-Query——用 MultiQueryRetriever 让 LLM 多角度重写问题分别检索合并去重，覆盖更多语义维度提高召回率。额外策略：Parent Document 检索小块返回大块保上下文。

</Answer>

</Exercises>
