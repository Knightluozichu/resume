## 为什么从输入与输出开始

把模型接进应用，就像在工厂里接入一台会根据来料调整加工方式的机器。送入的内容、先后次序和操作要求都会影响成品；只盯最后一句话，找不到出错的工位。

本章把工序拆开：先看机器怎样从多个候选中选择，再检查材料如何装配，最后决定成品能否交给下一步。没有这些检查，漂亮的回答也可能变成错误订单。

## 原书目录与机制解释

### 第3章 模型输入与输出

模型 I/O 不是一次字符串进、字符串出的黑箱调用。应用先构造输入，经模型产生响应，再把响应变成可使用的数据。本章将这三层分开：**输入层能确定地检查变量和角色；生成层带有不确定性；输出层能检查结构，却不能凭结构证明事实正确。** 三个实验依次对应这三层，练习 1—3 回收它们。

### 3.1 大模型原理解释

生成式语言模型在已有上下文基础上给下一个 <Term def="模型读写文本的切分单位，可能是字、词片段或其他编码单元">token</Term> 分配分数，再选择一个继续生成。这个过程逐步重复，后一个位置的条件包含前面已经生成的内容。因此早期选择可能影响后续整段，不是先在某处存好唯一标准答案再取出。

实验一只展示一个位置、三个虚构候选，用 <Term def="归一化成概率之前的候选数值分数">logit</Term> 表示分数。真实词表远大于三个候选，模型还包含复杂的内部计算；图中 A/B/C 不对应真实词表编号。

### 3.1.1 为什么模型输出不可控

这里的“不可控”不等于不能约束，而是不能把一次成功当成每次必然成功。<Term def="缩放候选分数、改变抽样分布集中程度的参数">温度</Term> T 对教学分数的作用可写成：

$$
p_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)},\qquad T>0
$$

这个式子在说：每个分数除以同一个正温度，再转成正数并归一化。减小 T 会放大相对差距，但不改变分数排序。实现时先减最大分数能避免指数溢出，不改变结果。

即使概率不变，不同抽样位置仍可能落进不同区间。实验一固定抽样序列以便复查；它不是随机数质量演示。真实服务还可能受模型更新、并行执行和供应商解码实现影响；不应承诺 T=0 必然逐字复现，也不能用温度代替事实核验。

### 3.1.2 输入对输出的影响

问题、限制、示例和历史消息一起改变条件分布，而不是只改变答案外观。例如“只返回商品编号”限制输出形态，给出两个退款分类示例会倾向该分类方式；但示例中的错误也可能被模仿。相关资料若含恶意指令，不能因为被放入上下文就拥有更高权限。

在实验一选择“误导偏向 B”再降温，B 的条会更长：**更稳定地选中 B 不等于更接近事实。** 这里的分数变化是人工设置的反例，不是测得“示例一定会把概率改变多少”。这对应练习 1。

### 3.2 提示模板组件

<Term def="把固定要求与命名变量组合成模型输入的可复用规则">提示模板</Term>
将不变部分与本次数据分开。它处在模型之前，负责渲染，不负责思考。给定同一模板和变量，应用应该能先查看最终文本或消息，检查遗漏、意外拼接及长度，再决定是否请求模型。实验二的候选区对应示例选择，下面的消息栈对应装配结果。

### 3.2.1 基础提示模板

基础模板的变量是显式输入，例如 `question`。花括号占位不是向模型传递 Python 变量，而是先在本地替换成文本。少一个必填变量应在渲染时失败；若模板里要出现字面 JSON 花括号，需按模板语法转义，不能靠模型猜。

当前 core 示例不调用模型：

```python
from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate.from_template("将问题归类为物流或退款：{question}")
text = prompt.format(question="订单到哪了？")
assert text == "将问题归类为物流或退款：订单到哪了？"
# prompt.format() 缺 question，抛 KeyError，而不是发出请求。
```

实验二切到“缺 question”后没有消息输出；这是一项确定的输入错误，不应算作模型生成失败。

### 3.2.2 自定义提示模板

“自定义”先考虑组合而不是继承：把格式约束预先固定，用 `partial` 绑定不随请求变化的字段，再在调用时传问题。更复杂的定制才需要实现模板类规定的格式化方法及输入类型。不要把用户提交的任意模板代码当可信程序执行。

```python
custom = PromptTemplate.from_template(
    "{format_rule}\n问题：{question}"
).partial(format_rule="只输出分类名，不附解释。")
assert custom.input_variables == ["question"]
assert "订单到哪了？" in custom.format(question="订单到哪了？")
```

这段只是约束文本，不会强制模型遵守格式。实验二“保留角色”和“拼成一个 human”的对照说明：内容相同也不代表输入结构相同。

### 3.2.3 使用FewShotPromptTemplate

<Term def="在本次输入内放少量示例，让模型参照任务模式；不更新权重">
  few-shot
</Term>
是把示例放进上下文，不是微调。`FewShotPromptTemplate` 先用 `example_prompt`
格式化每个样本，再拼上前缀与当前问题。它生成文本，并不会自动给示例加聊天角色。

```python
from langchain_core.prompts import FewShotPromptTemplate

examples = [
    {"question": "订单到哪了？", "label": "物流"},
    {"question": "退款到账了吗？", "label": "退款"},
]
example_prompt = PromptTemplate.from_template("问：{question}\n类：{label}")
few = FewShotPromptTemplate(
    examples=examples,
    example_prompt=example_prompt,
    prefix="仿照示例做分类。",
    suffix="问：{question}\n类：",
    input_variables=["question"],
)
rendered = few.format(question="包裹还没到")
assert rendered.count("问：") == 3
```

若需要实验二那种成对 human/ai 消息，使用聊天消息模板，见 3.3.2。增加示例会占用上下文，不能无限堆；示例答案质量和敏感信息也要检查。

### 3.2.4 示例选择器

<Term def="在候选样本中按明确规则挑选本次要放进输入的示例">示例选择器</Term>
位于模板装配之前。常见规则有长度预算、语义相似和兼顾多样性：相关样本未必足够短，最相近的几个也可能高度重复。真实语义选择通常需要嵌入模型及检索设施；本章不伪造这些调用。

实验二使用可手算的标签匹配：相同业务记 1，否则 0，同分保持原序；取前 k 个。默认物流选 E2，原序取一个却选 E1 寒暄。这不是 embedding，也不是 LangChain 内置类的等价实现。真实预算要用目标模型对应的计数方式，给系统要求、问题、历史、示例与预期输出共同留空间；图上的“格”仅用于长度直觉。

### 3.3 大模型接口

统一接口的价值在于让上层用相似方式传消息、接响应，而不是抹掉供应商差异。当前 v1 可通过 `langchain.chat_models.init_chat_model` 初始化，再安装相应供应商集成包；底层消息、模板等基础类型仍在 `langchain_core`。更换供应商时要重新核对参数、流事件、结构化输出和错误语义。

实验二的消息栈是调用边界，实验三从响应边界开始；中间没有真实网络请求。原书时期的具体初始化代码必须放回它自己的依赖环境，不能仅因类名类似就与当前初始化代码混用。

### 3.3.1 聊天模型

<Term def="接收角色消息序列并返回助手消息的模型抽象">聊天模型</Term>
的输入保留发言者与顺序，通常用 `SystemMessage` 表达应用要求、`HumanMessage`
表达用户输入、`AIMessage` 表达助手响应。`HumanMessage.type` 为
`human`、`AIMessage.type` 为 `ai`；发送给供应商时常映射为
user/assistant，不能把这两组名称误当成互相冲突。

输出的 `AIMessage.content` 可能是字符串，也可能是内容块列表；除了可见文本，还应留意工具调用、使用量和供应商响应元数据。不能对任意响应一概执行字符串 JSON 解析。具体内容块与拒答信息见[官方消息文档](https://docs.langchain.com/oss/python/langchain/messages)。实验三明确使用应用归一化后的预置文本，不宣称供应商原样返回这种封装。

### 3.3.2 聊天模型提示词的构建

<Term def="消息中说明谁在发言的结构字段，不是正文中的前缀文字">消息角色</Term>
不能靠 `system:` 这样的正文前缀创造。`ChatPromptTemplate`
组合角色模板，`FewShotChatMessagePromptTemplate`
则把每个示例变成一对消息。以下沿用上面的 `examples`，不调用模型：

```python
from langchain_core.prompts import (
    ChatPromptTemplate, FewShotChatMessagePromptTemplate,
)

example_chat = ChatPromptTemplate.from_messages([
    ("human", "{question}"), ("ai", "{label}"),
])
few_chat = FewShotChatMessagePromptTemplate(
    example_prompt=example_chat, examples=examples,
)
chat = ChatPromptTemplate.from_messages([
    ("system", "只返回分类名。"), few_chat, ("human", "{question}"),
])
messages = chat.invoke({"question": "包裹还没到"}).to_messages()
assert [m.type for m in messages] == [
    "system", "human", "ai", "human", "ai", "human",
]
```

实验二 k=2 时也是六条消息。消息顺序与角色有意义，但角色本身不是防注入或权限系统；应用仍须限制用户可控制哪些字段，不能把用户输入提升成系统要求。

### 3.3.3 定制大模型接口

已有供应商集成时优先使用它。没有现成集成，才考虑用 <Term def="把统一消息与返回类型转换为某个后端协议的边界代码">模型适配器</Term> 封装后端。当前 `BaseChatModel` 的核心定制点是 `_generate` 与 `_llm_type`，返回 `ChatResult`，其中每个 `ChatGeneration` 包含 `AIMessage`。不能把一个 HTTP 响应字典直接冒充标准助手消息。

下面是**离线假模型**，只回显最后一条输入，用于检查装配链路，不代表大模型推理。它明确处理字符串和停止串；不实现网络、工具调用或真正逐块流式传输。

```python
from langchain_core.language_models.chat_models import BaseChatModel
from langchain_core.messages import AIMessage
from langchain_core.outputs import ChatGeneration, ChatResult

class LocalEcho(BaseChatModel):
    @property
    def _llm_type(self) -> str:
        return "local-echo-demo"

    def _generate(self, messages, stop=None, run_manager=None, **kwargs):
        content = messages[-1].content
        if not isinstance(content, str):
            raise TypeError("此离线样例只接受字符串内容")
        text = "echo:" + content
        cuts = [text.index(s) for s in (stop or []) if s and s in text]
        if cuts:
            text = text[:min(cuts)]
        return ChatResult(generations=[
            ChatGeneration(message=AIMessage(content=text))
        ])

echo = LocalEcho()
assert echo.invoke(messages).content == "echo:包裹还没到"
assert echo.invoke("hello!", stop=["!"]).content == "echo:hello"
```

生产适配还要考虑认证、超时、错误类型、元数据与敏感数据处理；实验三提醒我们不要把“不完整响应”转换成“正常成功”。这项定制没有证明任何供应商兼容性。

### 3.3.4 扩展模型接口

定制是接入后端，扩展则是在现有接口上增加能力。先判断能否通过组合完成，例如“模板 → 模型 → 解析器”；只有后端确实提供增量事件时才实现 `_stream`，有真正异步客户端时才考虑原生异步方法。继承了通用方法不代表拥有原生并行、真实流式或结构化输出能力。

当前模型文档提供 `with_structured_output`，支持程度及方法选择取决于具体模型与集成；上述 `LocalEcho` 没实现工具绑定，不能直接拿它证明此能力。下面是**供应商调用示意，未联网实跑**；`MODEL_ID` 由项目配置，必须自行安装对应集成包、设置密钥并核对模型支持：

```python
import os
from langchain.chat_models import init_chat_model
from pydantic import BaseModel, ConfigDict

class Order(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")
    sku: str
    qty: int

model = init_chat_model(os.environ["MODEL_ID"])
structured = model.with_structured_output(Order, include_raw=True)
# result = structured.invoke("生成 sku=A1、qty=2 的订单")
# 查看 raw、parsed、parsing_error；异常仍需捕获，业务规则另行检查。
```

结构化输出不是“任何模型都能强制正确”，也不等于自动授权。实验三的 qty=99 能通过整数校验，但库存不足，因此停在业务检查。

### 3.4 输出解析器

<Term def="把模型输出转换成应用对象，并在不符合约定时给出失败的组件">
  输出解析器
</Term>
在模型之后。它可以提取字符串、解析 JSON 或验证类型；当前 core 的
`StrOutputParser`、`JsonOutputParser`、`PydanticOutputParser`
分工不同。尤其不要把 JSON 可解析误当成字段类型正确，也不要假设带容错的部分 JSON
解析等于响应已经完整。

先处理 <Term def="模型或服务明确表示不提供所请求内容的响应">拒答</Term> 与 <Term def="因长度上限、连接中断等原因没有得到完整输出">截断</Term>，再处理语法与字段。具体信号随供应商变化；实验三使用应用已归一化的样本，不捏造通用 `finish_reason` 或 `refusal` 字段。流式中间片段可以展示，但在结束状态确认前不要创建业务对象。

以下是**Python 标准库的严格教学解析器**，不冒充某个 LangChain 容错解析器。它只接受完整文本与精确的字段集合；`type(...) is int` 还避免把 Python 的布尔值当整数：

```python
import json

def parse_order(text):
    obj = json.loads(text)  # 不补括号；语法错抛 JSONDecodeError
    if not isinstance(obj, dict) or set(obj) != {"sku", "qty"}:
        raise ValueError("字段集合错误")
    if type(obj["sku"]) is not str or type(obj["qty"]) is not int:
        raise ValueError("字段类型错误")
    if obj["sku"] != "A1" or not 1 <= obj["qty"] <= 5:
        raise ValueError("商品不存在或库存不足")
    return obj

assert parse_order('{"sku":"A1","qty":2}') == {"sku": "A1", "qty": 2}
# parse_order('{"sku":"A1","qty":99}') 会因库存不足被拒绝。
```

真正应用应把拒答/截断的归一化放在这段函数之前，授权、幂等和副作用控制放在它之后。不要无限自动重试：格式修正无法补足无权限、无库存或缺失事实，重试也可能增加费用。实验三的字段树只说明“读到了哪些字段”，并不证明内容可信。

## 常见误区

<Callout type="trap" title="低温就是更聪明或完全可复现">
  温度只调整抽样集中程度，不修正知识和输入。误导上下文的最高分候选仍然最高；实验一可以直接观察。真实服务是否支持
  temperature 及其范围应查具体模型文档。
</Callout>

<Callout type="trap" title="多放示例等于训练了模型">
  few-shot
  只占用本次上下文，不修改权重。示例越多不一定越相关，还可能挤掉问题或输出预算；实验二用
  k 显示成对消息增加，而不是虚构训练进度。
</Callout>

<Callout type="trap" title="字符串里写 system 就有系统权限">
  消息角色属于结构字段，字符串前缀不是角色。保留 system
  消息也不是安全认证；后端授权不能交给提示词决定。
</Callout>

<Callout type="trap" title="能解析就能执行，解析失败就无限重试">
  语法、类型、业务、授权是不同检查。拒答或截断先处理结束状态；库存不足无需再问模型“改到能通过”。结构化输出仍可能失败，不能吞掉原始响应和错误。
</Callout>

**问题 1：同一分数，为什么结果会变？**

重置实验一，保持默认温度 1，连续切换抽样位置，记录前两个结果。再把温度降到 0.2，预测默认分数的最高概率；最后换成“误导偏向 B”。说明为什么这些操作不能证明模型正确率提高。

<Answer>
  默认分数 2/1/0 归一化约为 66.5%/24.5%/9.0%，u=0.18 落在 A，u=0.72 落在
  B。温度降到 0.2 后 A 约占 99.3%，分布更集中而排序不变。误导分数 0/3/1
  在低温下集中于
  B。这里既没有事实标签也没有测评集，不能从集中度推出正确率。分数缺失故障应停止抽样，重置后恢复分数、温度、抽样位置及故障开关。
</Answer>

**问题 2：装配六条消息，并在调用前挡住错误。**

<Answer>
  匹配优先选择 E2，再按同分原序选择 E1；角色为
  system、human、ai、human、ai、human，共六条。原序取一个会选寒暄 E1。缺
  question 在模板渲染阶段阻断，没有模型请求；拼接故障仍有文本，但只剩一个
  human，原 system 和 ai
  不再是角色。这些是输入构造问题，与模型温度无关。真实语义选择需另接嵌入和检索，本实验标签匹配不代表它们的效果。
</Answer>

**问题 3：六种响应应该停在哪里？**

  qty=2

  0。

## 名词解释

<Glossary>
  <GlossaryItem term="token">
    模型使用的编码单位，不保证等于一个字或一个词。图中候选只是教学符号。
  </GlossaryItem>
  <GlossaryItem term="logit">
    归一化之前的候选分数，不是概率，也不是事实可信度。
  </GlossaryItem>
  <GlossaryItem term="温度">
    调节分布集中程度的参数；正温度缩放不改变原分数排序。
  </GlossaryItem>
  <GlossaryItem term="提示模板">
    固定要求和变量的装配规则，在模型调用前渲染。
  </GlossaryItem>
  <GlossaryItem term="few-shot">
    把少量示例放入本次输入供模仿，不更新模型权重。
  </GlossaryItem>
  <GlossaryItem term="示例选择器">
    按长度、相关性或其他规则挑选本次输入使用的示例。
  </GlossaryItem>
  <GlossaryItem term="聊天模型">
    以角色消息为输入、助手消息为输出的模型抽象；具体能力因集成而异。
  </GlossaryItem>
  <GlossaryItem term="消息角色">
    消息结构中的发言者身份；正文前缀文字不能替代它。
  </GlossaryItem>
  <GlossaryItem term="模型适配器">
    把统一接口转换为后端协议并把响应转换回标准类型的边界实现。
  </GlossaryItem>
  <GlossaryItem term="输出解析器">
    把生成内容转换成对象的组件；解析成功不是事实或授权证明。
  </GlossaryItem>
  <GlossaryItem term="拒答">
    模型或服务表示不提供请求内容的结果，不能伪造成正常业务对象。
  </GlossaryItem>
  <GlossaryItem term="截断">
    尚未获得完整响应的情况，例如长度限制或连接中断；先检查完成状态。
  </GlossaryItem>
</Glossary>
