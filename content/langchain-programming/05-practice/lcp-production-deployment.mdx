## 核心概念

### 生产架构总览

生产环境的 LangChain 应用从客户端到 LLM Provider 经过多层：

- **客户端** → **API 网关**（鉴权/限流/路由） → **LangChain 服务**（Chain/Agent） → **LLM Provider**

<LcpProductionDeploymentDiagram />

### 六大优化维度

| 维度 | 方案 | 解决问题 |
|------|------|----------|
| 流式输出 | stream/astream/SSE | 首字延迟 |
| 缓存 | InMemoryCache/RedisCache | 重复请求成本 |
| 异步 | ainvoke/abatch/asyncio | 高并发吞吐 |
| 可观测性 | LangSmith 全链路追踪 | 调试和监控 |
| 容错 | with_fallbacks/重试/超时 | 服务可用性 |
| 安全 | Guardrails/PII脱敏/限流 | 安全防护 |

### 部署方案

| 方案 | 特点 | 适用场景 |
|------|------|----------|
| FastAPI + Uvicorn | REST API / SSE 流式 | 自定义 API 服务 |
| LangServe | 一键部署 Runnable | 快速原型上线 |
| LangGraph Cloud | 托管部署 + 自动扩缩 | 无运维需求 |

<Callout type="info">

生产部署的核心目标：低延迟（流式输出降低首字延迟）、低成本（缓存减少重复调用）、高可用（容错和备用模型保障服务）、可监控（LangSmith 全链路追踪）、安全（输入校验和输出过滤）。生产环境推荐 FastAPI + Redis 缓存 + LangSmith 追踪 + Docker/K8s 容器化 + HPA 自动扩缩的完整方案。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="流式输出 (Streaming)">

逐 Token 返回模型输出而非等待完整响应。LangChain 中用 stream/astream 方法实现。astream_events 提供更细粒度的事件流，包含每步的开始/结束/Token 流。降低首字延迟提升用户体验。

</GlossaryItem>

<GlossaryItem term="LangSmith">

LangChain 官方的可观测性平台，全链路追踪每步输入输出、延迟、Token 消耗和成本。支持性能分析、问题定位和 A/B 测试。LCEL 管道自动与 LangSmith 集成，无需额外开发。

</GlossaryItem>

<GlossaryItem term="with_fallbacks">

LangChain 容错机制，为主模型设置备用模型列表。主模型失败时自动切换到备用模型。配合 tenacity 重试（指数退避）和 timeout 超时控制，保障服务可用性。

</GlossaryItem>

<GlossaryItem term="RedisCache">

基于 Redis 的 LLM 响应缓存，精确缓存以 prompt+model 参数为 key。相同输入直接返回缓存结果，大幅降低 API 调用费用。支持 TTL 自动过期避免脏数据。

</GlossaryItem>

<GlossaryItem term="LangServe">

LangChain 官方部署工具，将 Runnable 一键部署为 REST API。自动生成 OpenAPI 文档和 Playground 调试界面。适合快速原型上线，底层基于 FastAPI。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

LangChain 生产部署的六大优化维度是什么？各自解决什么问题？

<Answer>

六大维度：流式输出用 stream/astream 逐 Token 返回解决首字延迟。缓存用 InMemoryCache/RedisCache 缓存响应解决重复请求成本。异步用 ainvoke/abatch/astream 并发处理解决高并发吞吐。可观测性用 LangSmith 全链路追踪解决调试和监控。容错用 with_fallbacks 备用模型和重试超时解决可用性。安全用输入校验、PII 脱敏、速率限制解决安全防护。

</Answer>

### 问题 2

如何在 LangChain 中实现流式输出？astream_events 和普通 stream 有什么区别？

<Answer>

实现：chain.stream(input) 返回生成器逐 Token 产出。await chain.astream(input) 异步版本。区别：stream 只输出最终结果的 Token 流，无法看到中间步骤。astream_events 产生完整事件流，包括每个 Runnable 的开始/结束、中间步骤的 Token 流、错误事件。astream_events 适合复杂链调试和多步骤 UI 展示，如 Agent 场景中同时展示思考过程和工具调用。前端用 SSE 推送。

</Answer>

### 问题 3

如何配置 LangChain 缓存？语义缓存和精确缓存有什么区别？

<Answer>

配置：set_llm_cache(InMemoryCache()) 或 set_llm_cache(RedisCache(redis_client))。语义缓存用 RedisSemanticCache 配合 Embeddings。区别：精确缓存以 prompt+model 参数为 key，完全匹配才命中，零误差但命中率低。语义缓存用嵌入向量比较相似度，语义相似即命中，命中率高但有误命中风险。生产建议：高一致性场景用精确缓存，高复用场景用语义缓存（设较高阈值如 0.95），配合 TTL 过期。

</Answer>

### 问题 4

设计一个 LangChain 应用的生产部署方案，涵盖 API 服务、流式输出、容错、缓存和监控。

<Answer>

方案：API 服务用 FastAPI 构建 REST API，StreamingResponse 返回 SSE 流。流式用 astream_events 产生事件流 yield 格式化为 SSE。容错用 with_fallbacks 设置备用模型链，配合 tenacity 重试和 30 秒超时。缓存用 Redis 精确缓存高频请求，set_llm_cache(RedisCache)，1 小时 TTL。监控用 LangSmith 追踪全链路，设告警（错误率/P99延迟/日成本）。安全用 API Key 鉴权、速率限制、输入长度限制、敏感词过滤。部署 Docker 容器化、K8s 编排、HPA 自动扩缩、多副本负载均衡。日志结构化 JSON 到 ELK。

</Answer>

</Exercises>
