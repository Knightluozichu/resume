## 练习题

<Exercises>

### 问题 1

用一句话概括 LangChain 编程的全流程，然后展开解释四个层次。

<Answer>

一句话：LangChain 编程是从理解框架架构出发，通过 Model I/O 和 Chains 组装基础管道，用 Memory 维持对话状态，用 Agents 和 RAG 构建智能应用，最后通过流式/缓存/追踪/容错实现生产部署的完整过程。四层：基础层理解架构设计和 Runnable/LCEL 抽象。组件层掌握 Model I/O 三阶段、Chains 组合、Memory 状态管理。应用层通过 Agent、RAG、高级链构建智能应用。工程层通过六大优化维度实现生产部署。四层递进：框架理解定义边界，组件掌握定义能力，智能应用定义场景，生产部署定义可靠。

</Answer>

### 问题 2

LCEL 管道、Memory、Agent 和 RAG 四种技术各自解决什么问题？如何组合使用？

<Answer>

LCEL 管道解决组件编排问题，用管道符连接 Runnable 统一调用模式。Memory 解决上下文丢失问题，多轮对话维护历史状态。Agent 解决自主执行问题，LLM 自主选择工具规划步骤。RAG 解决知识不足问题，检索外部知识减少幻觉。组合：RAG+Memory 检索增强同时记住对话历史。Agent+RAG 将检索器作为 Agent 工具自主决定何时检索。LCEL+所有 LCEL 是底层编排，Memory/RAG/Agent 都通过 LCEL 组合。Agent+Memory Agent 执行多步骤时记住中间结果。

</Answer>

### 问题 3

从框架选择到生产上线，LangChain 应用开发的核心决策链是怎样的？

<Answer>

决策链：模型选择考量能力/成本/延迟/隐私。提示设计先优化提示再考虑增强。链的组合单步用 LCEL 管道，多步用 assign 传递数据流，需要路由用 Branch。记忆策略短对话 Buffer 中等 Window 长对话 SummaryBuffer 生产用 Redis 持久化。知识增强频繁更新用 RAG，分块检索重排序是关键优化。自主执行简单用 Function Calling 复杂用 Tool Calling Agent。生产优化流式降延迟缓存降成本追踪便调试容错保可用。部署 FastAPI 或 LangServe Docker+K8s 容器化 HPA 自动扩缩。

</Answer>

### 问题 4

设计一个企业智能客服系统的完整方案，涵盖 RAG 知识库、多轮记忆、Agent 工具调用和生产部署。

<Answer>

方案：需求 7x24 客服准确回答支持查订单提工单多轮对话。知识库构建 RAG 离线加载产品手册 FAQ 分块向量化存 Chroma。检索增强 RAG 在线向量化检索 Top-10 重排 Top-5 构造增强提示。多轮记忆 ConversationSummaryBufferMemory(max_token_limit=2000) Redis 持久化 session_id 隔离。Agent 工具 knowledge_search RAG 检索、query_order 查订单 API、create_ticket 创建工单、transfer_human 转人工。Agent 用 create_tool_calling_agent 系统提示设定客服角色。生产部署 FastAPI SSE 流式 Redis 缓存 with_fallbacks 备用模型 LangSmith 追踪 API Key 鉴权限流 Docker+K8s。评估 100 测试题人工标注 LLM-Judge A/B 测试。

</Answer>
