```python
def split_document(document_id, text, size=240, overlap=40):
    step = size - overlap
    return [{"id": f"{document_id}:{start}", "text": text[start:start + size]} for start in range(0, len(text), step)]
```

```python
def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    norm_a = sum(x * x for x in a) ** 0.5
    norm_b = sum(y * y for y in b) ** 0.5
    return dot / (norm_a * norm_b)
```

```python
def answer_with_evidence(question, hits, generate):
    if not hits: return {"answer": "证据不足", "citations": []}
    result = generate(question, hits)
    return {"answer": result, "citations": [hit["id"] for hit in hits]}
```

代码通过普通Python表达核心合同，可在没有外部模型、LangSmith或LangServe时运行。接入真实LangChain版本时，由薄适配器映射到相应Runnable、模型、检索器或回调API；契约测试不随类名变化，从而可以精确定位迁移差异。

## 固定样例与手算

先用三个节点构造管道：模板节点接收字典并输出消息，模型假对象接收消息并输出固定结构，解析节点验证必需字段。分别调用单次、两项批量和逐块流式接口，聚合后的业务结果应一致；若事件数量或顺序不同，差异必须在trace中可解释。

再取查询向量q=(1,0)、文档向量d1=(0.8,0.6)、d2=(0,1)，余弦相似度分别为0.8和0。检索top-1应返回d1，但这只证明向量邻近，不证明d1支持答案。生成前仍需核对文档ID、嵌入版本、文本范围和引用；空召回必须拒答。

代理实验注册read与write两个工具，普通权限只允许read。模型若选择write，schema可以正确但权限门禁仍应拒绝；工具超时不得被改写成“执行成功”。记忆实验再写入两名用户的同名事实，读取必须按租户隔离，并在过期时间后删除。

最后注入三个故障：依赖版本改变输出字段、检索器返回失效文档ID、回调处理器抛出异常。系统应分别在解析、引用校验和观察端口报告首个分叉；回调失败不篡改已完成的业务结果，解析与引用失败则阻断发布。

## 独立对照实验

基线在干净环境中运行，冻结依赖锁、假模型、文档集、工具注册表和输入集合。记录每个节点的schema、开始结束事件、耗时、输出摘要与错误类型。相同配置重复三次，确定性节点必须一致；随机模型按结构、事实、安全和费用断言比较，不要求逐字相同。

第二轮每次只改一个因素：升级LangChain但保持适配器外合同，切换模型但保持节点图，修改切块但保持文档与查询，注入工具错误但保持模型选择。首个分叉若早于预期，先修环境或适配器；若晚于预期，说明门禁没有在正确边界生效。

独立复核进程只读取保存的配置和受控样本，不共享会话内存。它重建环境、重放失败案例、相邻边界和正常基线，检查日志脱敏、事件父子关系、幂等与回退次数。三个集合都通过后才关闭问题，不能用一次新的成功运行覆盖原失败证据。

## 版本迁移演练

迁移前先导出旧版本的节点清单、输入输出schema、配置字段、事件类型与冻结样本结果，再在新版本建立逐项映射。若某个类被拆分或移动，只修改适配器；若默认参数、异常类型或流式事件语义变化，则把它记录为行为差异，并为旧新路径各保留一条可运行契约测试。没有映射和测试的接口不得批量替换。

演练使用四类样本：普通成功、结构化输出损坏、模型或工具超时、外部文本注入。旧新版本都必须在相同边界作出等价决定，允许最终措辞不同，但不能改变schema、权限、引用和回退语义。迁移报告写清依赖锁、差异、临时兼容层、删除条件与负责人；回滚需能恢复代码和锁文件，而不依赖已经污染的进程状态。

复核者还要从空目录按说明重建环境，证明锁文件、配置模板、假模型和样本数据足以启动测试。若必须依赖本机缓存、未声明环境变量或在线账户，复现记录应明确判定为不完整。最终产物包含一条最小成功trace和一条预期失败trace，让后来读者能区分框架升级问题与业务逻辑问题，并能重复验证结论。

## 六类工程证据

### 版本与环境合同

保存解释器、依赖锁、代码摘要和配置名称。首版接口与当前接口通过适配器和兼容矩阵连接；未经锁定的环境不进入行为归因。

### Runnable与schema合同

每个节点声明输入输出和错误；invoke、stream与batch在业务语义上可对照。并行、分支和fallback保存实际路由，避免组合语法隐藏执行。

### 检索与来源合同

文档使用稳定ID，切块与嵌入带版本，召回和生成分开评分。回答逐项绑定来源，无召回或证据冲突时显式拒答或转人工。

### 工具与权限合同

工具含schema、权限、超时、幂等和风险等级。代理每步保存选择、参数、原始结果和预算，高风险动作等待外部批准。

### 记忆与隔离合同

记忆区分短期消息、摘要、实体和持久状态，写入有来源、租户和过期时间。读取内容仍是不可信数据，删除可验证。

### 回调与发布合同

trace以稳定ID连接节点、模型和工具事件，日志先脱敏。发布同时满足质量、安全、延迟和成本基线，失败回退到已验证依赖锁。

## 常见失败与回退

<Callout type="trap">**本章高风险失败：** 只评价最终回答，不测检索召回；混用嵌入版本；让模型在无证据或冲突证据时补写结论。</Callout>

<Callout type="trap">**框架抽象不是责任转移：** 链能运行不代表schema、来源、权限、记忆隔离和trace通过；中间合同失败必须阻断相应动作。</Callout>

<Callout type="tip">**回退顺序：** 环境锁 → 输入schema → 节点路由 → 模型或检索 → 输出解析 → 工具权限 → 记忆写入 → 回调。首个差异未解释前不比较整段回答。</Callout>

## 本章回顾

把RAG拆成加载、分块、嵌入、存储、检索和生成，覆盖多文档联合检索及召回、切块、版本和引用挑战。 掌握标准不是记住快速变化的API，而是能重建节点、合同、trace、失败和回退。通过标准为：能从带稳定ID的文档构建索引，计算相似度与召回，保存引用，并用空召回和冲突文档验证拒答。
