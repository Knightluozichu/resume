## 为什么“会回答”还不等于“能办事”

想象一条加工流水线：有人决定下一步加工什么，有人操作机器，还有人检查回执。若把“建议开机”直接当成“已完成加工”，就会漏单、重做，甚至越权开动机器。

本章把建议、执行、回执分开。没有这层分工，最后一句“办好了”既不能证明操作发生过，也不能证明操作被允许。

## 第6章 智能代理设计

贯穿任务是：先读取两项统计，再决定要不要写一张金额 42 的发票，最后把附件统计放回下一轮输入。我们不让一个“万能模型”承担所有职责，而是把系统拆成三种可核查对象：模型输出的候选调用、宿主保存的待处理集合、工具实际留下的结果或副作用。

本章只增加五组概念：代理、工具调用、工具契约、人工批准、多模态消息。实验 1 管“下一步去哪、结果属于谁”；实验 2 管“到底能不能执行”；实验 3 管“消息里究竟装了什么”。三者是同一执行路径的不同截面，不是三道发布审核。

### 6.1 智能代理的概念

<Term def="根据当前消息选择下一步动作，并由宿主执行和反馈的循环系统">
  智能代理
</Term>
不是“一个更长的提示”，而是模型与执行环境组成的循环：读状态 → 提议动作 → 执行 →
收集结果 →
再读状态。固定链预先决定路径；代理允许本轮结果改变下一步路径，因此必须另设边界。

状态至少保存消息、待处理标识、执行记录、剩余预算及停止原因。模型返回普通最终回答且没有待处理调用时可正常结束；它不是工具成功的凭据。工具挂起、返回错误或预算耗尽则是不同停止状态，不能全部写成“任务完成”。看实验 1 的“核对→模型”回边：只有回包完整，下一轮才有可靠观察。

### 6.2 LangChain中的代理

LangChain 提供模型消息、工具描述和代理编排，但权限与业务幂等仍由应用实现。现代 v1 的输入状态通常含 `messages`；模型节点产生调用，工具节点完成执行与反馈。工具返回到消息状态后，模型才有机会修正计划。这解释了为什么只打印最终文本会丢掉关键证据。

实验 1 把调用与回包画在状态机下面：圆角框是候选调用，直角框是结果，交叉线代表**乱序成功**，断线代表**协议不成立**。真正的网络超时、取消信号和并发任务清理由运行时处理；本图的“超时”是明确的确定性事件，不是浏览器等待真实服务。

### 6.2.1 LLM驱动的智能代理

<Term def="模型提出的工具名、参数与唯一标识；它本身并不执行工具">工具调用</Term>
包含工具名、参数和调用标识。LangChain 归一化调用中的字段叫 `id`，对应
`ToolMessage` 的字段叫 `tool_call_id`；某些供应商原始协议叫
`call_id`。本页图上统一写 call_id 指代这层关联，**不是要求 SDK 字段都改名**。

一次输出可能有多个调用。设待处理集合为 `{c1, c2}`，回包先到 `c2` 再到 `c1` 完全合法；依顺序配对则会串结果。只有每个待处理标识恰有一个终态结果，且没有未知或重复结果标识，才可继续。结果内容可以是明确的工具错误，不一定是成功值，但“根本没有回包”不能假造为成功消息。实验 1 的 c9 故障会使 c1 悬空并停止。

### 6.2.2 LangChain中的代理

一次提议到下一轮模型之间，至少维护三项不变量：调用标识不重复；结果集合与待处理集合一一对应；执行前确认本轮未超过预算。下面的教学执行器在整批执行前检查预算，所以只剩 1 次预算却有 2 个调用时，实际执行是 0 次，不会悄悄执行一半。

同一个标识重提是协议错误；**不同标识、相同参数**可能是模型重试。实验 1 的 c1/c3 是同一个纯统计工具，按“工具名+规范化参数”复用缓存，仍分别生成属于 c1、c3 的结果。这个缓存策略不能套到支付等副作用：重复付款可能是两笔合法业务，必须由业务键、持久记录和原子提交判断，不能凭参数相同就吞单。

### 6.2.3 代理的类型

“ReAct”“结构化工具调用”“多模态”不是互斥的软件类名。ReAct 描述根据观察再选动作的过程；结构化调用描述输出格式；多模态描述输入内容。历史文本代理会从格式化文本解析动作，解析失败是额外故障面；现代结构化调用可减少文本解析歧义，但并不能替代参数和权限检查。

一次模型输出两项统计可并行执行，依 ID 汇合；有数据依赖的步骤必须串行。并行不等于共享一份可随意改写的状态。实验 1 故意反转结果到达顺序；无结果样本则在模拟截止事件发生时停下。除此之外还要有轮数、调用次数、时间/费用预算：即使每轮回包都合法，模型也可能永远继续调用。

先预测：把轨迹切换为“重复参数、新 ID”，执行次数应为 1 还是 2？再分别试 c9、重复 ID、无结果和不足预算，推进到最后，比较连线与实际执行计数。每次“完全重置”应回到乱序合法样本、第一帧和暂停状态。

### 6.2.4 自定义代理工具

<Term def="工具的名称、用途、输入结构和执行约束所组成的接口约定">工具契约</Term>
让模型知道能申请什么，也让宿主知道如何拒绝。工具名要稳定、描述要说明何时使用；输入
schema 可以限制金额为整数且在 1—100 内。**schema
合法只说明格式合法**，不说明当前用户可以写发票。身份、scope、资源归属必须来自可信执行上下文，而不是模型生成的参数。

<Term def="在副作用执行前等待可信人员对精确动作和参数作出决定">人工批准</Term>
是执行边界：schema → allowlist 权限 → 挂起审批 → 执行。等待时写入次数必须为
0；拒绝就终止；批准只适用于当前精确参数。把金额 42 改成 43
后沿用旧批准，属于审批绕过。现代 HITL
的编辑决定也不能绕过重新校验；生产环境还需要持久检查点、授权审批人及恢复时重新检查权限。

### 6.3 设计并实现一个多模态代理

<Term def="同一消息用不同类型的内容块携带文字、图像或音频等信息">
  多模态消息
</Term>
不是把“图片路径”塞进一段文字。消息可以包含 text、image、audio
内容块；标准内容块与供应商原生格式还需适配。模型是否支持视觉、音频、文件 URL
或内联数据，必须查具体模型能力，不能因为接口接收了 JSON 就认定读到了附件。

处理路径应是：解析内容块 → 检查附件类型/大小 → 按能力分流 → 本地工具或模型读取 → 把工具结果按调用标识回填。实验 3 用 4×4 灰度数组真实计算暗像素数量，用八个音频样本真实计算峰值；这既不是 OCR，也不是语音转写。原生视觉分支只展示“把 image 块交给模型”的路由，**没有进行视觉推理**。

先预测：改成 ZIP MIME 后，图片统计工具还应收到 i1 吗？切到“音频超限”，应只拒绝音频，不把它当成文本继续处理。切到“有视觉能力”，图片的竖直工具支路改为直送曲线，音频仍走峰值工具。实验的 MIME/大小校验只针对本地 fixture；生产还要检查内容魔数、解码上限、附件访问控制，抓取远程 URL 时防止内网访问与超额下载。

## 完整本地实例：把边界写成断言

以下是**可直接运行的完整 Python 3.10+ 程序**，只用标准库。依次把七段 Python 代码**按出现顺序**粘贴到同一个 `agents_local.py` 文件，然后运行 `python3 agents_local.py`。不需要 API key，不依赖本网站附件。`script` 是预先写好的模型提议，不是真实 LLM；工具只计算数组或写内存列表，不访问互联网。

第一段定义唯一允许的纯工具。先验证名称与严格整数类型，再返回数值；这里不用 `eval`，也不接受任意函数名。后续 `cache` 仅用于这个纯函数。

```python
import json


def key(value):
    return json.dumps(value, sort_keys=True, separators=(",", ":"))


def call(cid, n=3):
    return {"id": cid, "name": "double", "args": {"n": n}}


def pure_tool(c):
    if c["name"] != "double":
        raise ValueError("unknown tool")
    if set(c["args"]) != {"n"} or type(c["args"]["n"]) is not int:
        raise ValueError("schema")
    return 2 * c["args"]["n"]
```

第二段开始循环。`budget` 计算**提议的调用数**，缓存命中也消耗预算，以免无穷重试；`rounds` 是第二道上限。重复 ID 在执行前拦下。这里为了教学简化，全批拒绝，而不是部分调度。

```python
def run(script, fault="", budget=4, rounds=3):
    seen, cache, executed, hits = set(), {}, 0, 0
    def done(reason):
        return reason, executed, hits
    for calls in script[:rounds]:
        if not calls:
            return done("final")
        ids = [c["id"] for c in calls]
        if len(set(ids)) != len(ids) or seen.intersection(ids):
            return done("duplicate_id")
        if len(calls) > budget:
            return done("budget")
        budget -= len(calls)
        seen.update(ids)
        results = []
        for c in calls:
            signature = key([c["name"], c["args"]])
            if signature in cache:
                hits += 1
            else:
                try:
                    cache[signature] = pure_tool(c)
                except ValueError:
                    return done("tool_error")
                executed += 1
            results.append({"tool_call_id": c["id"],
                            "content": cache[signature]})
```

第三段**接在第二段后面，保持下面前两层缩进**。反转列表模拟乱序；`missing` 注入确定性截止事件，`wrong` 注入未知 ID。未完整收齐就不进入下一轮模型。轮数用完即止损，即使尚有调用预算。

```python
        results.reverse()
        if fault == "missing":
            return done("timeout")
        if fault == "wrong":
            results[0]["tool_call_id"] = "c9"
        received = [r["tool_call_id"] for r in results]
        if len(received) != len(set(received)) or set(received) != set(ids):
            return done("protocol")
    return done("round_limit")
```

第四段恢复顶格，创建副作用执行器。`proposal` 是可信宿主保存的精确动作快照，批准令牌在此用字符串模拟，不是安全签名。参数变动、未批准或权限不符都会提前返回，唯一写入点在所有条件之后。`used` 仅防同进程内重复执行；现实系统应使用持久业务幂等键和事务，不宣称这段代码能解决跨进程重复支付。

```python
def write_invoice(c, scope, decision, approval, effects, used):
    args = c["args"]
    amount = args.get("amount")
    if c["name"] != "invoice" or set(args) != {"amount"}:
        return "schema"
    if type(amount) is not int or not 1 <= amount <= 100:
        return "schema"
    if scope != "invoice:write":
        return "forbidden"
    proposal = key(c)
    if decision == "pending":
        return "waiting"
    if decision != "approve" or approval != proposal:
        return "rejected"
    if c["id"] in used:
        return "duplicate"
    used.add(c["id"])
    effects.append({"invoice": "INV-42", "amount": amount})
    return "written"
```

第五段处理自定义本地内容块，**不是供应商 SDK 请求格式**。image 的单位是灰度字节，audio 的单位是 float32 样本（每个 4 字节）；类型和上限先判，后计算。原生分支仅返回待发送 image 块，不会神奇地识别内容。

```python
PIXELS = [0, 0, 255, 255, 0, 255, 0, 255,
          255, 0, 255, 0, 255, 255, 0, 0]
AUDIO = [0, .25, -.5, .75, -1, .5, -.25, 0]


def route(block, native=False):
    kind, data = block["type"], block["data"]
    if kind == "text":
        return {"type": "text", "text": data}
    expected = {"image": "image/x-gray8", "audio": "audio/x-f32"}
    if kind not in expected or block["mime"] != expected[kind]:
        return {"error": "mime"}
    size = len(data) * (4 if kind == "audio" else 1)
    if not data or size > 64:
        return {"error": "size"}
    if kind == "image" and native:
        return {"type": "image", "data": data}
    value = sum(p < 128 for p in data) if kind == "image" else max(map(abs, data))
    return {"tool_call_id": "i1" if kind == "image" else "a1",
            "content": value}
```

第六段验证实验 1、2。被拒绝的写请求不仅有错误字符串，还必须留下**零副作用**；批准后也不能重复消费同一调用。`loop` 使用不同 ID，证明标识合法并不足以保证终止。

```python

assert run(base) == ("final", 2, 0)
assert run(base, "wrong")[0] == "protocol"
assert run(base, "missing")[0] == "timeout"
assert run(base, budget=1) == ("budget", 0, 0)
assert run([[call("c1"), call("c1")]]) == ("duplicate_id", 0, 0)
assert run([[call("c1")], [call("c1")]])[0] == "duplicate_id"
assert run([[call("c1")], [call("c3")], []]) == ("final", 1, 1)
loop = [[call(str(i))] for i in range(4)]
assert run(loop)[0] == "round_limit"
c = {"id": "w1", "name": "invoice", "args": {"amount": 42}}
effects, used = [], set()
for amount, scope, decision, expected in [
    ("42", "invoice:write", "approve", "schema"),
    (42, "invoice:read", "approve", "forbidden"),
    (42, "invoice:write", "pending", "waiting"),
    (42, "invoice:write", "reject", "rejected"),
    (43, "invoice:write", "approve", "rejected"),
]:

    assert write_invoice(changed, scope, decision, key(c), effects, used) == expected
    assert effects == []
assert write_invoice(c, "invoice:write", "approve", key(c), effects, used) == "written"
assert write_invoice(c, "invoice:write", "approve", key(c), effects, used) == "duplicate"
assert len(effects) == 1
```

第七段验证实验 3 的实际计算和拒收，输出唯一的成功行。`8` 是逐个数灰度小于 128 的元素，`1` 是音频绝对值的最大值；不是模型编造的答案。运行不通过时 Python 会在失败的断言处停止。

```python
print("PASS: loop, permission, multimodal; dark=8 peak=1 writes=1")
```

## 容易踩的坑

<Callout type="trap" title="按回包顺序拼结果">

**现象 →** c2 的数值被记在 c1 名下。**原因 →** 并行到达顺序不稳定，却用数组下标配对。**修法 →** 按 tool_call_id 与待处理集合核对；未知、重复或缺失都阻止下一轮。实验 1 的交叉线是成功，不是错误。

</Callout>

<Callout type="trap" title="合法参数加一句安全提示就足够">

**现象 →** 只有读取权限也能写发票。**原因 →** schema 只验证结构，模型提示并不执行授权。**修法 →** 宿主从可信身份取权限，副作用之前阻断；审批绑定精确参数。实验 2 的批准不能打开权限阀门。

</Callout>

<Callout type="trap" title="缓存重试就可以不设终止条件">

**现象 →** 每次都命中缓存，代理却永远不停。**原因 →** 节省工具计算不等于结束模型循环。**修法 →** 每次提议也消耗预算，另设轮数与时间上限；无结果记录超时而非伪造成功。改 run 的 rounds 验证止损。

</Callout>

<Callout type="trap" title="发了文件名就等于模型读到了文件">

**现象 →** 对 ZIP 附件给出“图像识别结果”。**原因 →** 把文本路径或 MIME 声明当作真实内容与能力证明。**修法 →** 校验内容、限制大小并选择支持的模型/工具；实验 3 的拒收支路不会调用统计工具，峰值也不是转写。

</Callout>

## 小结

- 调用标识配对回包，停止原因单独记录。
- 校验、权限和批准都通过后才可写入。
- 内容块与工具结果不同，按能力明确路由。

## 练习与答案

<Exercises>

**问题 1：把 run 的调用预算改成 1，再分别运行 base 与纯缓存重试脚本，会在哪里停？如何证明无限循环被截断？**

<Answer>

base 一次提议两调用，批前预算检查直接返回 `("budget", 0, 0)`。重试脚本第一轮 c1 执行一次，第二轮 c3 即使可命中缓存也因预算不足而不调度。独立实现一个每轮新 ID、同参数的脚本，设置 budget=100、rounds=2，应返回 `round_limit`；不能只检查工具实际执行次数。

</Answer>

**问题 2：批准金额 42 后改成 43，为什么不能继续用同一个 approval？补出副作用为零的断言。**

<Answer>

批准对象是完整提议快照，不是“此工具永远可用”。构造 `changed = {**c, "args": {"amount": 43}}`，传 `approval=key(c)`，应返回 `rejected` 且 effects 仍为空。生产中编辑后的请求要重新验证、授权并审批；审批人与执行器之间还需要可信身份和持久恢复边界。

</Answer>

**问题 3：把第一个灰度 0 改成 255，再把音频复制三份；两条路径分别发生什么？原生图片分支能证明模型识图成功吗？**

<Answer>

暗像素由 8 变 7，i1 结果也应是 7；三份音频为 24 个 float32 样本、96 字节，超出 64 字节限额，返回 size 错误，不能产生 a1 成功结果。原生分支仅封装 image 块，未发出模型请求，不能证明识图成功。

</Answer>

</Exercises>

  <GlossaryItem term="智能代理">
    在建议、执行、反馈之间循环选择下一步的系统，不只是一个聊天模型。见实验 1

  </GlossaryItem>

    含工具名、参数、标识的动作申请；回包必须按标识归位，申请不等于执行。
  </GlossaryItem>
  <GlossaryItem term="工具契约">
    告诉模型怎样申请、告诉宿主怎样验证的一套接口规则；格式合法不等于有权执行。
  </GlossaryItem>
  <GlossaryItem term="人工批准">
    先暂停副作用，等可信人员批准精确动作后再执行；改参数需要重新检查。
  </GlossaryItem>
  <GlossaryItem term="多模态消息">
    以不同内容块携带文字、图像、音频的消息；路径、原始附件与工具统计值不是同一种东西。
  </GlossaryItem>
