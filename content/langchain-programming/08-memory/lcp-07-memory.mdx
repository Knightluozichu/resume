## 为什么不能把所有对话都留下：直觉

工厂流水线的下一道工序需要前面留下的要求，但工位空间有限。把所有记录都搬来，工位会装不下；只留最近两张，又可能把最早写下的禁忌扔掉。

解决办法不是单纯“多记一点”，而是决定留下什么、放在哪里、何时更新，以及要求作废后哪些副本也必须清掉。否则回答看起来连贯，实际上已经忘记关键限制。

### 第7章 记忆组件

记忆不是让模型永久学会新事实，而是应用在下一次调用前补充信息。一次历史 Memory 调用通常是：读取旧信息 → 放入提示 → 执行模型/工具 → 保存新输入输出。缺少最后一步，下一轮就读不到新事实；保存时机错误，又会把失败工具结果当成事实。

本章把五个核心问题拆开：预算窗口、摘要损失、结构化检索、线程持久化、生命周期。实验1检查“送了什么”，实验2检查“怎么存与查”，实验3检查“属于谁、失败后在哪、何时消失”。

### 7.1 构建记忆系统

先给每条信息标注所有者、会话、事件ID、来源和有效期。不要先选一个听起来像“记忆”的类。会话内的 <Term def="一次运行及其后续步骤共享的当前数据，如消息和工具结果">state</Term> 决定本轮可读内容；<Term def="按线程保存和恢复执行状态快照的持久化机制">checkpointer</Term> 保存线程检查点；<Term def="按命名空间和键存应用数据、可跨线程读取的存储">store</Term> 则承载经授权的用户长期偏好。

例如用户A的订单讨论属于 thread A，用户A的语言偏好可放在用户级 store；换线程不应丢偏好，但用户B绝不能读到它。实验3“正常→恢复”表示线程快照；切B后应为空。内存版 saver/store 可用于开发，不能证明进程重启后还在。生产持久化、身份校验与保留策略须另行配置。

### 7.2 记忆组件类型

类名决定的首先是“读取什么形状的信息”，不是持久性。用同一四轮样本比较：不能吃花生（10）、周五出发（14）、改到周六（12）、想吃面条（16）。单位是预置 <Term def="模型分词后的计费或上下文单位，不等于汉字数或轮数">token</Term> 费用，不是真实分词结果。

示例总上限48，固定提示与当前问题8，输出预留8，历史可用预算为 `48 − 8 − 8 = 32`。实际还要计入工具定义、消息封装和检索结果，不能只数聊天正文。实验1的红竖线是历史预算，不是模型总上限。

先预测：最近2轮能否保留花生禁忌？将策略切成“全缓冲”，再将预算从32改到56，哪一项问题被解决、哪一项没有？

### 7.2.1 ConversationBufferMemory

历史全缓冲把已有输入输出逐渐累积，下一次全部读出。常见历史接口 `load_memory_variables` 负责提供记忆字段，`save_context` 负责追加本轮；是否返回字符串或消息由具体配置决定，并非永远是一种格式。

实验1“全缓冲”保留三项事实，但费用 `10 + 14 + 12 + 16 = 52`，大于32。预算调到56后能装下，却没有解决更长会话的增长、过时事实与隐私保留问题。一个 Memory 对象在 Python 堆中活着，不等于磁盘持久化，更不等于按租户隔离。

### 7.2.2 ConversationBufferWindowMemory

窗口只取最近若干轮，而非“最重要的若干条事实”。历史 `k` 是轮窗口的抽象，旧实现通常用成对的人类/AI消息切片；工具消息、多角色或不完整轮次不能机械按 `2*k` 推广，更不是 token 上限。

实验1固定窗口为最近2轮：费用 `12 + 16 = 28`，预算通过，却丢了第1轮禁忌。把预算调到24又会超限：**轮数小并不保证 token 少**。当前消息裁剪应使用适配目标模型的计数，并维护角色、工具调用与工具结果配对；不能截断后留下孤立的工具结果。

### 7.2.3 ConversationEntityMemory

实体记忆先识别“在说谁”，再按实体键更新相关信息，读取时注入实体摘要。所核对的 classic 实现保存的是每实体的模型生成摘要字符串，不是内置的强类型属性表。它适合“用户A/小林的住址=杭州”这样的档案，不适合靠一串同名文本猜身份。抽取可能错，属性更新也必须带来源；历史实体存储实现不保证自动具备生产一致性。

实验2选“实体”，推进到“写入”，属性从上海变成杭州，来源从 A/e1 变 A/e2。开启“丢掉用户隔离键”，同名B的苏州会覆盖A。图中属性表是将摘要内容结构化后的教学表示，抽取是预置的，不是该类原样存储格式；真正接入模型时，还要测别名、否定句、删除请求和同名歧义。

### 7.2.4 ConversationKGMemory

知识图记忆将信息组织为“主体—关系—客体”，例如“小林—现居住—杭州”，而不是只有一个属性值。它能沿关系查询，但需区分“曾居住”和“现居住”，否则搬家后同时出现两条有效住址。

实验2选“知识图”，写入后旧边变虚线，新边连接杭州。虚线表示本页主动失效的关系，**不是历史类自动解决冲突的承诺**。实际关系应带证据与有效时间；历史 `ConversationKGMemory` 的三元组抽取也不是通用图推理引擎。题2要求比较属性覆盖与关系失效。

先预测：同一句“搬到杭州”，会改变一个属性、增加一条边，还是追加一个检索点？再比较三种结构。

### 7.2.5 VectorStoreRetrieverMemory

该历史类把本轮信息转为文档交给向量存储，读取时用当前输入查询相关内容。它不是按最近轮次读出，也不会因为新事实出现就必然覆盖旧文档。应保留所有者、时间、来源和原文引用，先过滤权限，再检索并组织提示。

实验2“向量”把三条文档放在二维平面，以到查询点 `(0.90, 0.65)` 的平方欧氏距离排序。A旧距离为 `0.25² + 0.05² = 0.0650`，A新为 `0.05² + 0.20² = 0.0425`。新点更近，但这只是预置坐标，不是 embedding 模型的实测质量。

### 7.2.6 ConversationSummaryMemory

摘要把历史压成一段短文本，通常会调用语言模型，因此节省的上下文可能以额外调用、延迟和信息损失为代价。递归摘要还会把一次抽取错误带入后续轮次；原始证据被丢弃后，不能从短摘要精确还原。

实验1“摘要”统一计8 token。正常样本保留禁忌与改期；开启故障后变成“爱吃花生，周五出发，喜欢面条”。费用仍是8，但否定词和日期更正都丢了。图中事实槽变叉，说明**费用相同不代表语义等价**。这是对比用的固定坏摘要，不声称某个真实模型必然这样输出。

<Callout type="trap">
  **现象 →** 摘要更短，回答却推荐了花生。 **原因 →**
  压缩删掉否定词；预算指标没检查事实。 **修法 →**
  对禁忌、数字、更正建立独立断言，保留可追溯证据，缺证据时追问而不是猜测。
</Callout>

### 7.2.7 ConversationSummaryBufferMemory

混合策略给较旧信息做摘要，保留新鲜消息尾部。它不是“摘要免费附赠”：历史 token 限制与裁剪方式依具体版本而异，最终提示中摘要和尾部都要计费。摘要里的旧日期还可能与尾部新日期冲突，装配时须明确证据优先级。

实验1“摘要+最近1轮”是本页固定策略，不是逐行复现该类的裁剪算法。费用 `8 + 16 = 24`，比最近2轮28低；但最后一轮只有面条偏好，修复不了坏摘要中的禁忌与日期。将预算调到20会超限，题1据此检验费用和事实两个维度。

### 7.2.8 VectorStoreRetrieverMemory

**目录登记的7.2.5与7.2.8确实同名。本页保留两个坐标，不推测排版原因，也不虚构第二种 API。** 7.2.5解释结构，这里检验同一机制的读取与遗忘边界。

实验2开“丢掉用户隔离键”，B私点距离 `0.01² + 0.03² = 0.0010`，比A新更近，于是 top-1 返回B的私有住址。检索分数再高也不能代替授权。实验3到“源记录删除”后，索引圆仍存在；只有传播并确认后才清空。所核对 classic 源码中的 `VectorStoreRetrieverMemory.clear()` 明确不做清理；其他组件的会话消息删除或摘要重置，也不能作为外部索引已清理的证据。

### 7.3 记忆组件的应用

应用层先决定读写责任，再组合策略。读路径：认证身份 → 选线程与用户空间 → 读取短期/长期数据 → 校验权限与有效期 → 预算装配。写路径：成功事件 → 校验抽取 → 持久化 → 索引更新。来自用户或检索的记忆仍是数据，不能升级为系统指令。

实验3“恢复”与“删除传播”显示两个不同边界：已提交状态能恢复，派生副本未必同时更新。正文代码以数据库事务和独立删除任务模拟它们，既不调用代理，也不把“回答流畅”当作持久化验收。

### 7.3.1 将记忆组件接入代理

历史代理/链通常通过约定的输入输出键加载并保存 Memory，须检查 `memory_key`、`input_key`、`output_key` 与提示占位符匹配；多输出或中间工具步骤不能猜哪个字段是最终答案。一次工具失败不应被存成用户已完成的事实。

现代 v1 的 agent 基于 LangGraph；短期消息属于 state，通过 `checkpointer` 与配置里的 `thread_id` 延续会话，长期信息用 store 按应用定义的 namespace/key 读取。**不是**把旧类放进任意 `memory=` 参数就完成迁移。实验3将B切成同一个线程键会串线；键应由应用认证上下文生成，并校验访问权。

<Callout type="trap">
  **现象 →** 本地第二次调用有历史，上线重启后全部丢失。 **原因 →**
  用进程内对象代替持久化，还把旧 Memory 当作 v1 状态机制。 **修法 →** 分开
  state、checkpointer、store，实测持久后端的重启恢复；实验3“提交前崩溃”只能恢复已提交事件。
</Callout>

### 7.3.2 自定义记忆组件

自定义不是继承名字就够了，至少需定义读取、写入、清理合同。历史 Memory 要按其抽象接口提供变量名和加载/保存/清理行为；现代应用则可定义状态字段、节点与持久后端。两者不能拼成一个未经测试的“通用子类”。

本页离线实现选择 `(owner, thread, event)` 作为主键，使重试同一事件不重复；写入与模拟索引插入同事务提交。实验3“提交前崩溃→恢复→重试”对应回滚、空读、重新提交。生产外部索引不能靠一个本地事务同时提交，通常需要可靠事件投递、幂等消费者和补偿检查。

### 7.3.3 不同记忆组件结合

组合前列清楚每个输出键：近期消息、摘要、实体档案、检索片段分开，不让两个组件都写同一个 `history` 字段。即使历史组合工具能检查键冲突，也不会自动处理“摘要说周五、档案说周六”的语义矛盾。

先根据来源时间选择有效事实，再去重与计费；不应把同一段对话在原文、摘要、检索命中中重复塞入。实验1混合策略用24 token，实验2追加向量可能同时返回旧新地址。题2要求给出明确的冲突处理，而不只是说“多个组件效果更好”。

### 7.4 记忆组件实战

场景是客服偏好记录：A希望后续回答不推荐花生，B不应看到A的会话。实战验收分三部分：提示费用正确；隔离、恢复和重试正确；删除源记录后追踪派生索引。实验1与2是前两种读写策略的对比，实验3把生命周期串起来。

先预测：在“提交前崩溃”模式的恢复步能读到 e1 吗？在“索引删除任务未投递”模式走到最后，源与索引是否都为空？逐步观察节点填充、跨线程红线和墓碑回执，再重置所有控件。

### 7.4.1 方案说明

只记录完成授权的必要事实，不把身份、权限或密钥交给模型决定。按用户建立 <Term def="将不同用户或用途的数据分开的命名空间，仍需应用实施授权">namespace</Term>，会话内再细分 thread。读取过滤过期记录，删除或到期会创建 <Term def="表示某条源信息已失效、用于通知派生副本清理的标记">墓碑</Term>，保留至消费者确认。

实验3的“正常”泳道只允许A读e1；提交前崩溃读空；重复e1仍一个节点；删除后先源空、索引仍在，再传播清空。到期与主动删除可以共用失效传播，但图中演示的是主动删除。真实系统还要处理旧检查点、摘要、缓存、备份保留期和检索竞态；本实验没有证明这些已清理。

### 7.4.2 代码实践

下面是**完整、独立的 Python 标准库程序**，不依赖 LangChain、网络、API key 或附件。将以下五段 Python **按顺序拼到同一个 `memory_lab.py` 文件**。需要 Python 3.10+，运行 `python3 memory_lab.py`。固定样本与图一致；SQLite 是本地契约测试容器，不模拟供应商 SDK。索引虽然放在同一库，删除故意分两次事务，显露传播窗口。约定 event 在同一 owner 下全局唯一，墓碑按 owner/event 使该事件在各线程失效；不是线程本地可重复的编号。

第一段固定费用与事实，并定义可计数的断言。`kept`返回费用和是否保留禁忌，不能用费用代替语义判断。

```python
import sqlite3
import tempfile
from pathlib import Path

COSTS = [10, 14, 12, 16]
checks = 0

def check(condition):
    global checks
    assert condition
    checks += 1

def kept(policy, lossy=False):
    if policy == "buffer":
        return sum(COSTS), True
    if policy == "window":
        return sum(COSTS[-2:]), False
    if policy == "summary":
        return 8, not lossy
    if policy == "hybrid":
        return 8 + COSTS[-1], not lossy
    raise ValueError(policy)
```

第二段建表。源记录按用户、线程、事件区分；索引按用户、事件去重，因此示例要求事件ID在同一用户内跨线程唯一。长期用户偏好若跨线程共享，应另建用户级表，不擅自取消本例的线程过滤。

```python
def connect(path):
    db = sqlite3.connect(path)
    db.executescript("""
        CREATE TABLE IF NOT EXISTS memory(
            owner TEXT, thread TEXT, event TEXT, text TEXT,
            expires INTEGER, PRIMARY KEY(owner, thread, event));
        CREATE TABLE IF NOT EXISTS idx(
            owner TEXT, event TEXT, text TEXT,
            PRIMARY KEY(owner, event));
        CREATE TABLE IF NOT EXISTS tombstone(
            owner TEXT, event TEXT, PRIMARY KEY(owner, event));
    """)
    return db

def write(db, owner, thread, event, text, expires, fail=False):
    with db:
        dead = db.execute("SELECT 1 FROM tombstone WHERE owner=? "
                          "AND event=?", (owner, event)).fetchone()
        if dead:
            return False
        db.execute("INSERT OR IGNORE INTO memory VALUES(?,?,?,?,?)",
                   (owner, thread, event, text, expires))
        db.execute("INSERT OR IGNORE INTO idx VALUES(?,?,?)",
                   (owner, event, text))
        if fail:
            raise RuntimeError("before commit")
    return True
```

第三段实现读取、失效和派生清理。读取按身份和时间过滤；到期后不能读出，但索引要等失效扫描与传播。墓碑阻止旧事件重放复活；本例不处理墓碑自身到期，生产需结合重放保留期。

```python
def read(db, owner, thread, now=0):
    return db.execute("SELECT event,text FROM memory WHERE owner=? "
                      "AND thread=? AND expires>? ORDER BY event",
                      (owner, thread, now)).fetchall()

def forget(db, owner, event):
    with db:
        db.execute("DELETE FROM memory WHERE owner=? AND event=?",
                   (owner, event))
        db.execute("INSERT OR IGNORE INTO tombstone VALUES(?,?)",
                   (owner, event))

def propagate(db):
    with db:
        db.execute("DELETE FROM idx WHERE EXISTS (SELECT 1 FROM "
                   "tombstone t WHERE t.owner=idx.owner "
                   "AND t.event=idx.event)")

def expire(db, now):
    rows = db.execute("SELECT DISTINCT owner,event FROM memory "
                      "WHERE expires<=?", (now,)).fetchall()
    for owner, event in rows:
        forget(db, owner, event)
```

第四段检查费用、隔离、连接重建恢复与失败重试。关闭再打开连接模拟应用重建存储对象，**不是操作系统断电或远程数据库崩溃测试**。异常在提交前注入，事务必须回滚。

```python
check(kept("buffer") == (52, True))
check(kept("window") == (28, False))
check(kept("summary", True) == (8, False))
check(kept("hybrid") == (24, True))
check(kept("window")[0] <= 32 < kept("buffer")[0])
with tempfile.TemporaryDirectory() as tmp:
    path = Path(tmp) / "memory.sqlite"
    db = connect(path)
    write(db, "A", "t1", "e1", "不能吃花生", 100)
    check(read(db, "B", "t1") == [])
    check(read(db, "A", "t2") == [])
    db.close()
    db = connect(path)
    check(read(db, "A", "t1") == [("e1", "不能吃花生")])
    write(db, "A", "t1", "e1", "不能吃花生", 100)
    check(len(read(db, "A", "t1")) == 1)
    try:
        write(db, "A", "t1", "e2", "喜欢面条", 100, fail=True)
    except RuntimeError:
        pass
    check(len(read(db, "A", "t1")) == 1)
    write(db, "A", "t1", "e2", "喜欢面条", 100)
    check(len(read(db, "A", "t1")) == 2)
```

第五段**紧接上段，保留四空格缩进**，继续处于 `with` 临时目录内。先证实删除传播前索引仍在，再确认清理、阻止重放，最后检查到期。预期只打印 `PASS: 20 checks; local simulation only`；断言失败将直接退出，不能把失败吞掉后报通过。

```python
    forget(db, "A", "e1")
    check(read(db, "A", "t1") == [("e2", "喜欢面条")])
    check(db.execute("SELECT COUNT(*) FROM idx WHERE event='e1'")
          .fetchone()[0] == 1)
    propagate(db)
    check(db.execute("SELECT COUNT(*) FROM idx WHERE event='e1'")
          .fetchone()[0] == 0)
    check(write(db, "A", "t1", "e1", "旧事件", 100) is False)
    check(read(db, "A", "t1") == [("e2", "喜欢面条")])
    check(read(db, "A", "t1", now=100) == [])
    check(db.execute("SELECT COUNT(*) FROM idx").fetchone()[0] == 1)
    expire(db, now=100)
    propagate(db)
    check(db.execute("SELECT COUNT(*) FROM memory").fetchone()[0] == 0)
    check(db.execute("SELECT COUNT(*) FROM idx").fetchone()[0] == 0)
    db.close()
print(f"PASS: {checks} checks; local simulation only")
```

程序用固定文本，不执行模型抽取；没有实现聊天角色协议、真实 checkpointer、向量检索、并发写、索引消费者故障恢复或备份擦除。下一步接入 SDK 时，须分别锁版本、替换后端并重复相同行为测试；不能用这20条断言冒充 SDK 已测试。

<Callout type="trap">
  **现象 →** 删除对话后，检索仍命中旧偏好。 **原因 →**
  源、摘要、检查点和外部索引不是一个删除域。 **修法 →**
  标记失效、过滤读取、投递删除、等待回执并复查副本；实验3末步红圈表示任务丢失，不应报告“已彻底删除”。
</Callout>

## 小结

- 费用合格与关键事实保留必须分别验收。
- 结构决定读写，用户与线程键决定隔离。
- 恢复靠已提交状态，删除要核对派生副本。

## 练习与答案

<Exercises>

**问题 1：预算够了，记忆就正确了吗？**

在实验1选混合策略、预算20并开启坏摘要。手算费用、指出两个丢失事实；将预算改到32后，再解释为什么不能直接推荐花生。

<Answer>
  费用8+16=24，比20超4；禁忌与周六更正都在坏摘要中丢失。改到32只修复装配预算，未修复事实。最后一轮只包含面条偏好，不能替代过敏证据。应恢复原始证据或追问，不能把“未提到禁忌”当作“无禁忌”。
</Answer>

**问题 2：搬家事实该怎样更新？**

比较实体、知识图、向量三种写入。若检索同时返回上海与杭州，应如何选？在实验2取消用户过滤，计算B私点为何排第一。

<Answer>
  实体按身份键更新location并保留来源；图将旧现居住边失效后增加杭州有效边；向量通常追加新文档而不自动撤回旧文档。先做用户与有效期过滤，再按来源和有效时间裁决，不能只看相似度。B的平方距离0.0010小于A新0.0425和A旧0.0650，但没有授权仍绝不能返回。
</Answer>

**问题 3：独立实现删除失败重试，并验证完整重置。**

修改正文程序：第一次不调用 `propagate`，先断言过期e2的索引仍有1条；第二次调用两遍清理，断言仍为0。解释为什么这不证明所有历史检查点和备份已清空。最后在实验3选B、注入丢任务、走到末步，再点“重置全部”。

<Answer>
  把到期后的首次propagate移到新增“索引仍有1条”断言之后，再连续调用两次；DELETE在无匹配行时仍安全，说明本地清理幂等。它只检查两张当前表，未枚举旧检查点、缓存、摘要或备份。图的重置应恢复A、正常、首步、空节点与0%进度，且播放停止；不能只把文字改回初始值。
</Answer>

</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="state">
    本次运行携带的数据；消息、工具结果与自定义字段都可在里面，不等于永久知识。
  </GlossaryItem>
  <GlossaryItem term="checkpointer">
    把线程执行状态存成检查点、之后可继续或恢复的机制；耐久性取决于后端。
  </GlossaryItem>
  <GlossaryItem term="store">
    按命名空间和键存应用数据的地方，可供同一用户的多个线程使用。
  </GlossaryItem>
  <GlossaryItem term="token">
    模型处理文本的分词单位；汉字数、轮数都不能直接充当它。
  </GlossaryItem>
  <GlossaryItem term="namespace">
    数据的分区名字；划分用户或用途，但还需要应用检查访问权。
  </GlossaryItem>
  <GlossaryItem term="墓碑">
    “这条信息已失效”的通知标记，帮助其他副本完成清理并防止旧事件复活。
  </GlossaryItem>
</Glossary>
