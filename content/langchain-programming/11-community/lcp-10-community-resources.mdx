## 为什么资源需要一张可追溯的地图

搜索结果像一叠不同年份的地图：图上画了新桥，不代表你脚下的路已经通车。本章解决“找到的建议适不适用于手头项目”，避免照着新地图走进旧路的断口。

判断不靠谁的地图收藏最多，而靠它画的是哪条路、哪一年、有没有可回到现场的坐标。三个实验分别让你拆掉一条来源连线、缩小可选范围、切断一条跨边界的请求。

### 10.2.2 LangServe

LangServe 把 Runnable 暴露成 HTTP 接口。其[官方 README](https://raw.githubusercontent.com/langchain-ai/langserve/main/README.md)本次可读，明确标记 deprecated，并称自2024-11-18起弃用、建议新项目考虑 LangGraph Platform、仅接受社区 bug fix 而不接受新功能。**这是 README 快照中的维护声明**，不是本页独立验证的产品历史；旧服务分析和新项目选择应分开。README 里的旧模板链接可能失效，不因它是官方链接就免查。

  请求拓扑

先回答哪条线跨越在线服务边界。按 README 的端点说明，`POST /invoke`
处理单个输入，`POST /batch`
可在一个HTTP请求中携带多个输入；两条子运行不等于两次HTTP请求。实验三是省略路径前缀与真实报文的示意；实际需在部署端点查

### 10.2.3 LangSmith

[LangSmith 观测文档](https://docs.langchain.com/langsmith/observability)提供执行追踪入口。一个<Term def="一次操作的执行区间，带身份及父子关系；多个区间可组成运行树">span</Term>记录一次操作，根与子区间表达执行层级；它不是传输报文。LangSmith 观测不必承担向用户返回模型结果的角色；图中根区间包住子区间，虚线导出到观测端，实线响应返回客户端。

先预测：关闭 tracing 会不会让 HTTP 响应消失？在实验三推进到“响应”再关闭，导出边和观测树消失，服务执行区间及返回边保留。再开 batch(2)，一个请求下出现两个子区间：本设计假设根加子共三个导出 span。真实 SDK 可能另有模型、检索等更深层区间，不应照抄图中数量。上线前还需验证密钥配置、采样、导出队列错误处理和输入输出脱敏；本文没有验证这些在线行为。

### 10.3.1 生态系统概览

[总览](https://docs.langchain.com/oss/python/langchain/overview)将 LangChain 的高层构建与底层 LangGraph 关系分开；[集成目录](https://docs.langchain.com/oss/python/integrations/providers/overview)定位模型/工具提供方；LangSmith承担观测等产品能力。开源库、集成包与托管产品有不同维护、许可证、账户与数据边界，不能因为名字相近就把权限或服务承诺互相继承。

实验三中客户端、服务和观测端是三个责任域；观测可以服务于 LangChain 以外的应用。图里没有画 LangGraph 托管服务，不能从图推断“迁移LangServe只需改URL”。要迁移部署，还需调查持久化、并发和API语义，而不只是改包名。

### 10.3.2 变化与重构

[官方 v1 迁移指南](https://docs.langchain.com/oss/python/migrate/langchain-v1)说明命名空间精简、旧链等转向 `langchain-classic`，并要求 Python 3.10+。三条轨道必须分列：2024接口仅作为历史阅读范围；classic 是兼容旧功能的独立包/导入路径；现代v1采用当前公开接口。**classic不是“把v1降成2024”**，也不证明行为完全一样。

动手试：实验二选择“保留旧导入”、Python3.10、不注入旧钉子，先观察依赖点仍亮而迁移边断开；再切classic，迁移边接到过渡支路，允许候选也改变。现实中应分别记录依赖变更和应用代码变更，再比较回归输入，避免把两类变化混成一次“升级成功”。

### 10.3.3 发展计划

可以制定**自己的**发展计划：若旧模板仅需维护，先用隔离环境调查classic；若新增agent能力，再按现代接口做小样；若准备暴露公网服务，重新调查维护状态、身份认证和数据治理；若只是排查失败，则先补观测。它们是本页设计建议，不是厂商路线图。

下次复查触发条件也要具体：Python支持范围变化时重算实验二；文档出现新导入时重查实验一的版本边；观测导出改同步时重画实验三的失败传播。没有新资料就保留未知，不把“生态活跃”转换成未来兼容保证。

## 可复算实践：无网络的约束与拓扑诊断

保存下面**两个连续代码块**为同一个 `community_probe.py`，按先后顺序拼接；在全新目录执行 `python3 -I community_probe.py`。只用标准库，建议 Python3.10+；不需安装SDK或联网。`V`仅处理本例中不带预发布/本地标识的整数段版本，真实PEP 440范围还需标准工具与完整解析器。

第一段固定本次可读元数据的两个core范围，故障参数模拟项目额外的 `core<1`。它同时核查解释器范围和导入路线，三者分别报告，不合成质量分数。

```python
CORES = ("0.3.79", "1.4.4", "1.6.10")
def V(value):
    parts = tuple(map(int, value.split(".")))
    return parts + (0,) * (3 - len(parts))

def diagnose(route="modern", python="3.10", old_pin=False):
    lower = "1.4.4" if route == "classic" else "1.6.10"
    core = [v for v in CORES if V(lower) <= V(v) < V("2")
            and (not old_pin or V(v) < V("1"))]
    return {"core": core,
            "python": V("3.10") <= V(python) < V("4"),
            "import": route != "legacy"}

assert V("1.6.10") > V("1.6.9")
assert diagnose()["core"] == ["1.6.10"]
assert diagnose("classic")["core"] == ["1.4.4", "1.6.10"]
assert diagnose(old_pin=True)["core"] == []
assert not diagnose(python="3.9")["python"]
assert not diagnose("legacy")["import"]
print("modern:", diagnose())
print("conflict:", diagnose(python="3.9", old_pin=True))
```

第二段是实验三最后一步的邻接关系计算：batch两个输入仍只有一条HTTP请求边；span身份里的 `root`、`child-0` 表达父子关系。它不模拟真实并发时间、SDK缓存、服务鉴权或网络重试。

```python
def topology(batch=False, tracing=True, blocked=False):
    if blocked:
        return [("client", "boundary")], []
    requests = [("client", "service"), ("service", "client")]
    children = 2 if batch else 1
    spans = [("root", f"child-{i}") for i in range(children)]
    if tracing:
        requests.append(("service", "observer"))
        return requests, ["root"] + [b for _, b in spans]
    return requests, []

edges, spans = topology(batch=True)
assert edges.count(("client", "service")) == 1
assert len(spans) == 3
assert ("service", "client") in topology(tracing=False)[0]
assert ("service", "observer") not in topology(tracing=False)[0]
assert topology(blocked=True) == ([("client", "boundary")], [])
print("batch:", len(edges), "edges,", len(spans), "spans")
print("offline assertions: 11 passed")
```

预期输出如下。`edges=3` 包括请求、响应、观测导出，**不是三个HTTP业务请求**；这里11条 `assert` 只证明这个有限离线程序的结果。

## 小结

- 资源要有版本和来源边，热度不是证据。
- 依赖交集、解释器与导入迁移须分开验证。
- HTTP返回与span导出属于不同路径。

**问题 2：把离线程序默认路线改成 classic，额外保留 core＜1，Python改3.9。手算三个结果，再在实验二复核；为什么仅移除旧钉子还不够？**

<Answer>
  classic要求core至少1.4.4，与core小于1没有交集，因此候选为[]；Python3.9不在≥3.10且小于4范围，故False；classic导入已改接，故import为True。移除旧钉子后候选恢复1.4.4与1.6.10，但解释器仍不满足。即使三项都满足，还没验证完整依赖和应用行为。
</Answer>

**问题 3：在实验三选择batch(2)，播放到响应，关闭tracing，再阻断HTTP，最后重置。应分别保留/删除哪些边？新项目该直接采用LangServe吗？**

<Answer>
  batch仍一条请求边，服务区间内两条子区间。关闭tracing只删除导出边与观测树，执行和响应保留；阻断HTTP则请求停在边界，不进入服务，不产生本图服务内span或成功返回。重置须回到invoke、tracing开启、HTTP恢复、第一步且暂停。README快照标记LangServe弃用，因此新项目应重新调查官方建议的部署方案与需求，而非把旧教程当当前推荐；本文未测试任何在线部署。
</Answer>

## 名词解释

<Glossary>
  <GlossaryItem term="证据谱系">
    让一个说法沿连线回到文档、包和源码材料的关系；缺一条关键边就应保留未知，不是机械权威排名。
  </GlossaryItem>
  <GlossaryItem term="最小复现">
    用尽可能少的程序、输入与环境条件稳定重现同一现象，方便别人独立调查。
  </GlossaryItem>
  <GlossaryItem term="依赖约束">
    包和解释器允许版本范围的声明；组合安装需要同时满足各范围，满足范围仍不保证应用语义正确。
  </GlossaryItem>
  <GlossaryItem term="请求拓扑">
    调用在系统之间怎样去、怎样回的连线；能区分业务响应与辅助观测路径。
  </GlossaryItem>
  <GlossaryItem term="span">
    一次操作的执行区间及身份/父子关系；多个区间组成运行树，不等同于HTTP请求数量。
  </GlossaryItem>
</Glossary>
