## 核心概念

### 推理瓶颈分析

大模型推理面临四大瓶颈：

| 瓶颈 | 原因 | 影响 |
|------|------|------|
| 内存瓶颈 | KV缓存占用大量显存 | 限制并发数 |
| 计算瓶颈 | 自回归逐 token 生成 | 生成速度受限 |
| 延迟瓶颈 | 首字延迟和生成延迟 | 用户体验 |
| 吞吐瓶颈 | 并发处理能力 | 服务成本 |

### 四大核心优化技术

<LlmInferenceDiagram />

1. **KV Cache 缓存**：缓存历史 K/V 矩阵避免重复计算，将每步计算从 O(n^2) 降为 O(n)。PagedAttention 分页管理减少显存碎片。

2. **量化压缩**：将 FP16 权重压缩到 INT8/INT4，减少模型体积和显存占用。GPTQ、AWQ、GGUF 是常见方法。

3. **连续批处理**：动态拼批请求，不同长度序列并行，已完成请求立即返回、新请求立即加入。提升 GPU 利用率从 30% 到 70%+。

4. **投机解码**：小模型快速起草候选 token，大模型并行验证。一次验证多个 token，加速 2-3 倍且不损失精度。

### 部署架构

```
API 网关 → 负载均衡 → 推理引擎(vLLM/TensorRT) → 模型存储 → 监控告警
```

### 关键推理指标

| 指标 | 含义 | 目标 |
|------|------|------|
| TTFT 首字延迟 | 用户等待首字时间 | 越低越好 |
| TPS 生成速度 | 每秒生成 token 数 | 越高越好 |
| 吞吐量 | 并发请求处理能力 | 越高越好 |
| 显存利用率 | GPU 显存使用效率 | 越高越好 |

<Callout type="info">

核心：KV缓存省计算，量化降显存，批处理提吞吐，投机解码加生成——四管齐下让大模型跑得快。推理优化是将大模型从「实验室原型」变成「线上服务」的关键工程，没有推理优化，再强的模型也无法大规模服务用户。

</Callout>

## 术语表

<Glossary>

<GlossaryItem term="KV Cache">

键值缓存。在自回归生成中缓存每层每头的 K 和 V 矩阵，新 token 只需计算自己的 Q 与缓存的 K 做注意力。将每步计算从 O(n^2) 降为 O(n)，是推理加速的核心技术。

</GlossaryItem>

<GlossaryItem term="PagedAttention">

vLLM 提出的 KV Cache 分页管理技术。将 KV Cache 分为固定大小的页，按需分配和回收，减少显存碎片，支持更多并发请求。

</GlossaryItem>

<GlossaryItem term="量化">

将模型权重从高精度（FP16）压缩到低精度（INT8/INT4），减少模型体积和显存占用。INT8 减半显存精度损失极小，INT4 减少 75% 但精度损失较大。

</GlossaryItem>

<GlossaryItem term="连续批处理">

Continuous Batching / Inflight Batching。动态拼批请求，每个 token 生成步都可重新组 batch，已完成请求立即返回、新请求立即加入。将 GPU 利用率从 30% 提升到 70%+。

</GlossaryItem>

<GlossaryItem term="投机解码">

Speculative Decoding。小模型快速生成候选 token，大模型并行验证，接受一致的拒绝不一致的。不损失精度（验证保证分布一致），加速 2-3 倍。

</GlossaryItem>

</Glossary>

## 练习题

<Exercises>

### 问题 1

KV Cache 的原理是什么？它如何加速自回归推理？

<Answer>

原理：自回归生成中每生成新 token 需要计算它与所有历史 token 的注意力。不缓存则每步重新计算所有历史 K/V，计算量随序列长度平方增长。KV Cache 将每层每头 K/V 矩阵缓存，新 token 只需计算自己的 Q 与缓存 K 做注意力。加速效果：①避免重复计算——历史 K/V 只算一次后续复用；②每步计算从 O(n^2) 降为 O(n)；③推理分 Prefill（处理输入，计算密集）和 Decode（逐 token，访存密集）两阶段。PagedAttention 进一步分页管理减少显存碎片。代价是 KV Cache 占显存，长序列时显存压力大。

</Answer>

### 问题 2

模型量化的常见方法有哪些？INT8 和 INT4 量化各有什么优缺点？

<Answer>

常见方法：GPTQ（基于二阶信息后训练量化）、AWQ（根据激活分布保护重要通道）、GGUF（llama.cpp 生态格式支持多种量化级别）、PTQ（不需重训练直接量化）。INT8：显存减少约 50%，精度损失极小（<1%），几乎所有 GPU 支持。优点精度好，缺点压缩比不够大。INT4：显存减少约 75%，精度损失较大（2-5%），部分能力可能下降。优点极大降低成本，缺点需精细校准和误差补偿。选择原则：精度要求高用 INT8，成本敏感用 INT4，实践中常用混合精度（关键层 FP16/INT8，其余 INT4）。

</Answer>

### 问题 3

连续批处理（Continuous Batching）为什么能大幅提升推理吞吐量？

<Answer>

传统静态批处理问题：①不同请求长度不同，必须等最长请求完成才释放整个 batch，短请求 GPU 空闲浪费；②新请求必须等当前 batch 完成才能加入，排队延迟高。连续批处理解决：①请求级动态拼批——不同请求可不同时间加入/离开 batch；②Iteration-level 调度——每步可重新组 batch，已完成请求立即返回，新请求立即加入；③Padding 最小化——只对当前步 token 对齐而非整个序列。效果：GPU 利用率从 30-40% 提升到 70-90%，吞吐量提升 2-10 倍，降低排队延迟。vLLM 和 TGI 内置此技术。

</Answer>

### 问题 4

投机解码（Speculative Decoding）的原理是什么？它如何在不损失精度的前提下加速生成？

<Answer>

原理：①小模型快速生成 k 个候选 token（起草）；②大模型并行验证 k 个 token——一次前向传播即可验证多个 token（注意力可并行计算）；③接受概率分布一致的 token，拒绝不一致的，从拒绝点重新采样。加速原理：①大模型自回归生成是访存密集型（每步只生成 1 token 但要加载全部权重），GPU 利用率低；②投机解码让大模型一次前向验证多 token，将多次串行 Decode 合并为一次并行计算；③小模型虽要生成 k 个 token 但推理极快。不损失精度原因：验证过程保证最终输出与大模型自回归生成的分布完全一致——接受/拒绝逻辑保证采样等价性，只是改变计算顺序。Medusa 头是变体——在大模型上添加多预测头直接并行预测多 token。实际加速 2-3 倍。

</Answer>
