## 第3章 Transformer

一句话里的每个位置都要决定该参考谁。逐个位置往后传信息，路径可能很长；让位置彼此直接交流，又必须防止答案提前泄漏。本章从三个位置的数值计算开始，把“参考谁”变成可检查的权重。

<Term def="以注意力组织位置之间的信息交换，并结合逐位置前馈变换的神经网络架构">
  Transformer
</Term>
的关键不是一张漂亮的连线图，而是连线对应哪次乘法、哪些连接不合法，以及加速后是否仍算同一个问题。以下三个实验分别拆开连接、位置和执行顺序；均为玩具计算，不运行真实模型或训练任务。

本页按原书目录保留本章21个正式坐标，采用 ASCII 编号。书目与目录只界定教学范围，技术解释是独立重写，不能据此归因为作者观点。先修是上一章的词元、条件概率与向量点积；其余主题在五个核心术语周围展开，不要求一次背下所有方法名。

## 3.1 Transformer编码器模块

编码器把整段输入映射成同长度的上下文向量。一次自注意力让每个位置读取其他位置的信息，逐位置前馈网络再变换各自通道；二者不是同一个操作。原论文编码器每层有这两个子层，各有残差连接，采用子层后归一化；今天常见的前归一化是变体，不能倒填为原版。

把词元向量排成行，输入形状为 n×d；线性投影得到 Q、K、V，分别可理解为查询、索引和待取内容。单头中 Q/K 形状是 n×dₖ，V 是 n×dᵥ。注意力矩阵是 n×n，行对应 query，列对应 key，不要把这两个轴互换。

<Term def="把查询与键的点积除以维度平方根，经行softmax后用于加权值向量">
  缩放点积注意力
</Term>
把匹配分数变成一行权重。符号 S 是分数，M 是掩码，A 是权重，O 是输出；n
是位置数，dₖ 是键通道数。

$$
S=\frac{QK^\top}{\sqrt{d_k}},\qquad A=\operatorname{softmax}_{\mathrm{row}}(S+M),\qquad O=AV.
$$

人话说：先比对，再排除不准读的位置，然后分配权重，最后读取内容。除以平方根是在点积方差随维数增长的常见假设下控制量级，不是消除所有训练不稳定性。softmax 每行和为1，但 O 是向量而不是下一词概率。

多头对不同投影分别做以上计算，再拼接并投影回 d 维。原论文 base 配置的8头、512通道、每头64维是具体配置，不是所有 Transformer 的定义。前馈子层原版使用两次线性变换夹 ReLU；残差要求输入输出通道能对齐。[Attention §3.1–3.3](https://arxiv.org/html/1706.03762)是此处的全文依据。

**先预测**：实验默认观察 Q1，因果模式下只允许读取 K1。把 Q 倍数调大，输出会不会变？再改成双向模式，答案为何不同？图中分数矩阵随阶段切到掩码矩阵，右侧始终显示归一化后的预览，便于对照。

下面开始一份完整的标准库 Python 程序。**按正文顺序拼接全部 `python` 块为一个文件运行**；后面的几何和采样继续使用前面的定义，没有省略模型权重或隐藏依赖。第一块定义同实验的三组向量，`dot` 只沿通道求和。

```python
from math import exp, sqrt, cos, sin, isclose
from fractions import Fraction as F

Q = [[1, 0], [0, 1], [1, 1]]
K = [[1, 0], [0, 1], [1, -1]]
V = [[1, 0], [0, 2], [2, 1]]

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def softmax(xs):
    m = max(xs)
    e = [exp(x - m) for x in xs]
    return [x / sum(e) for x in e]
```

第二块计算所有行，保留 S 便于检查。`reverse=True` 是有意反向的故障，不能用作训练掩码。每行至少保留自己，所以没有全为负无穷的非法 softmax 行。

```python
def attention(scale=1, causal=True, reverse=False):
    scores = [[scale * dot(q, k) / sqrt(2) for k in K]
              for q in Q]
    masked = [[s if not causal or (j >= i if reverse else j <= i)
               else -float("inf") for j, s in enumerate(row)]
              for i, row in enumerate(scores)]
    weights = [softmax(row) for row in masked]
    out = [[sum(a * V[j][d] for j, a in enumerate(row))
            for d in range(2)] for row in weights]
    return scores, masked, weights, out

S, M, A, O = attention()
assert all(isclose(sum(row), 1) for row in A)
assert all(A[i][j] == 0 for i in range(3) for j in range(i + 1, 3))
assert O[0] == [1, 0]
assert attention(scale=2)[3][0] == O[0]
bad = attention(reverse=True)
assert bad[2][0][2] > 0 and bad[3][0] != O[0]
assert attention()[3] == O
print("attention", A, O, "fault", bad[3][0])
```

这验证的是掩码和数值管线，没有实现多头投影、归一化、反向传播或一个可训练模型。只有一个合法 key 时，无论分数如何缩放，softmax 权重都是1；有多个合法 key 时，扩大 Q 会改变权重的集中程度。

## 3.2 编码器-解码器架构

原版翻译架构中，编码器双向读完整源句；解码器先对已知目标前缀做自注意力，再以自身状态为 Q、编码器输出为 K/V 做交叉注意力。交叉注意力的矩阵可以是“目标长度×源长度”，不必是方阵，也不应套用目标侧的三角掩码去遮源句。

<Term def="在自回归注意力中屏蔽未来位置，使当前位置只能读取自己及过去">
  因果掩码
</Term>
约束目标侧自注意力。训练时把目标输入右移，再用三角掩码阻断未来，才能并行计算各位置而不泄漏目标。掩码是在
softmax **之前**给非法分数加负无穷；在 softmax
后把权重清零却不重归一化，会破坏权重和。

<Callout type="trap" title="有数值，不代表没有偷看">
  现象：反向掩码仍能得到和为1的权重。原因：归一化只保证概率形状，不知道哪些位置是未来。修法：同时断言每行和为1、所有未来权重为0；在实验一用Q1注入故障再恢复，观察O1首差。
</Callout>

只用编码器、只用解码器、编码器加解码器是不同信息访问方式。不能把“Transformer”直接等同于“所有层都能双向看全文”，也不能把生成任务的因果规则强加给所有编码器。

## 3.3 位置嵌入

如果只有同一套逐位置投影和无掩码自注意力，重排输入位置会相应重排输出，网络没有自动获得绝对次序。<Term def="把位置索引或位置间关系送入网络，让相同内容在不同位置可被区分">位置编码</Term> 补上顺序信息。目录使用“位置嵌入”，本节用“编码”统称固定函数、可学习位置向量和相对关系；它们不全是同一种查表。

### 3.3.1 绝对位置编码

原论文给词元嵌入加上同宽度的正弦/余弦位置向量，并比较可学习的位置嵌入。位置 p 是非负整数，i 是频率对索引，d 是模型宽度，ωᵢ 为该对角频率。

$$
\omega_i=10000^{-2i/d},\qquad PE(p,2i)=\sin(p\omega_i),\quad PE(p,2i+1)=\cos(p\omega_i).
$$

人话说：每两个通道是一对快慢不同的钟。不同频率帮助区分不同尺度的位置；绝对向量会随 p 改变。可学习查表与固定正弦都在“给哪个位置什么表示”层工作，不直接改变注意力的合法连接。

### 3.3.2 相对位置编码

有些方法把位置差作为分数偏置或其他相对变换，目的在于明确建模“相隔多远”。原论文正弦编码的一个几何性质是：在单频二维子空间，共同平移对应旋转。实验为直观把横纵轴写作 (cos, sin)，只是交换了原式两通道的显示顺序。

$$
u_\omega(p)=(\cos\omega p,\sin\omega p),\qquad u_\omega(p)\cdot u_\omega(p+\Delta)=\cos(\omega\Delta).
$$

这里 u 是单位圆向量，Δ 是相对位移。人话说：两根箭头一起转，不改夹角。但把位置向量**加到内容向量后再任意投影**，一般还有内容项与交叉项，不能由这个恒等式断言整个 QK 只依赖 Δ。实验没有伪装成完整相对注意力模型。

**动手试**：到第4步，改变共同平移 s，观察两根箭头同时转动而点积不变。换频率会改变夹角；注入“K位置多1”，会改变实际相对位移，恢复后偏差应归零。

<Llm03TransformerComputeTraceLab />

程序第三块用同一单位圆复算，遍历位置、位移、平移与频率；检验对象是这个二维恒等式，不是训练后的长文本能力。浮点比较用容差，不能对 `cos` 运算强求逐位相等。

```python
def phase(p, omega):
    return [cos(omega * p), sin(omega * p)]

for omega in [0.25, 0.5, 1]:
    for p in range(7):
        for delta in range(1, 5):
            for shift in range(6):
                a = phase(p + shift, omega)
                b = phase(p + delta + shift, omega)
                assert isclose(dot(a, b), cos(omega * delta), abs_tol=1e-12)
reference = dot(phase(1, .5), phase(3, .5))
wrong = dot(phase(1, .5), phase(4, .5))
assert not isclose(reference, wrong)
print("position", reference, "misaligned", wrong)
```

## 3.4 更长的上下文

加长上下文首先改变资源需求。密集自注意力的分数对数随 n² 增长；因果屏蔽去掉约半数连接，但仍是二次量级。自回归解码每个新 query 读已有 n 个 key，若缓存增长，则单步读取量也增长。能分配内存不等于模型能可靠利用很远的证据。

应分开检查：训练见过的长度、位置表示适用范围、注意力内存、跨段状态与任务质量。[Transformer-XL 摘要](https://arxiv.org/abs/1901.02860)明确提出段级循环及新位置编码来跨固定段学习依赖；此处只依据实际取得的摘要介绍方向，没有复现全文实现。滑窗会丢窗口外直接连接；位置外推即使不报错，也需要长距离任务验证。原 Attention §3.5 的外推动机不是所有长度都有效的保证。

## 3.5 外部记忆

外部记忆把一部分信息存到当前注意力窗口之外，再按查询取回。它不同于把所有历史一直放在同一个密集矩阵里，也不同于把知识更新进参数。[Memorizing Transformers 摘要](https://arxiv.org/abs/2203.08913)描述对近期内部键值表示的非可微近邻查找；本文不把这种内部表示检索等同于“任何文档库都可直接读取”。

取回什么由索引、相似度和存储版本决定；漏检、旧内容与错误来源不会因“有外存”自动消失。部署应检查检索命中、权限、更新/失效、额外读取延迟，以及取回信息究竟如何进入网络。本章不模拟近邻索引，也不报告外存带来的准确率提升。

## 3.6 更快、更小的Transformer

优化先要选目标：参数存储、训练总计算、单请求延迟、吞吐、峰值显存不是同一个量。下列子节区分保持数学结果的执行变换、改变连接/容量的架构方法和改变训练方案的方法。实验三只展示推理依赖与概率正确性，不给这些方法排统一速度榜。

### 3.6.1 高效注意力

[FlashAttention 摘要](https://arxiv.org/abs/2205.14135)把分块和减少显存/片上存储读写用于**精确**注意力：不必把整个分数矩阵长期物化，不能据此说所有成对乘法都消失。稀疏注意力则跳过某些连接；低秩、核近似等也可能改变结果。原 Attention 表1中的局部限制注意力降低连接数量，但跨远距离可能需更多层传播。

选型应写清“是否保留同一连接集合和归一化”“误差怎样测”“内核能否利用稀疏”。理论运算量更小不保证具体硬件更快；本页未运行任何 GPU 注意力内核。

### 3.6.2 条件计算

条件计算让不同输入只激活部分模块；例如按词元选择专家前馈层，而不是每个位置都调用全部专家。[Switch Transformer 摘要](https://arxiv.org/abs/2101.03961)支持稀疏激活、路由及通信/训练稳定性问题的范围描述。总参数可以很大，活跃参数较少，但参数仍要存放，路由不均和跨设备通信仍有代价。

它与注意力稀疏化的轴不同：前者常选“哪个计算模块”，后者选“哪些位置互相读”。把专家数量直接当每个词元的计算倍数，或认为稀疏激活必然省掉等比例总显存，都会误判。

### 3.6.3 搜索高效Transformer

架构搜索先定义可变的原语、候选空间、训练预算和评分目标，再选候选；它不是免费寻找“最优 Transformer”。[Primer 摘要](https://arxiv.org/abs/2109.08668)描述在程序原语层搜索，并把主要改动归于平方 ReLU 与 Q/K/V 投影后的逐通道卷积。这里仅介绍摘要明确给出的候选方向，没有复现搜索或采用其性能数字。

搜索成本应与最终模型训练成本分别记账，并在相同数据、质量目标与硬件下比较。只比较最终候选的一次运行，会漏掉候选淘汰成本与特定实现的优势。

### 3.6.4 在单个GPU上一天内训练一个语言模型

这是受限预算的问题，不是“今天任意语言模型都能一天练成”的承诺。[Cramming 摘要](https://arxiv.org/abs/2212.14034)（2022年提交）研究在单个消费级 GPU、一天预算下从零训练**掩码语言模型**，修改流水线并报告接近 BERT 的表现。本文实际访问范围是摘要；没有取得该实验的硬件日志，也未在本机复现。

先固定训练目标、数据、模型规模、时间/能耗预算、基线和质量评价，再讨论配方。不能把摘要的特定受限实验换成“一天训练前沿聊天大模型”，更不能用本页浏览器真实 GPU 渲染证明语言模型训练加速。

## 3.7 推理优化

生成时，同一段历史会被不断读取。<Term def="保存过去位置在各层计算出的键和值，使新增词元无需重算历史投影的缓存">KV缓存</Term> 把过去位置的 K/V 留下来；新 query 仍要读取相关历史。它不缓存所有未来答案，也不是把历史注意力权重原封不动复用。

推理要区分预填充与逐词解码：预填充并行处理提示，解码受新词依赖限制。普通注意力在给定层数 L、KV头数 h、每头宽 dₕ、每元素 b 字节时，单请求 n 个位置的缓存粗算是 `2 × L × n × h × dₕ × b` 字节；2来自K和V，不含权重、临时张量、分页浪费及其他状态。多查询/分组查询会改变KV头数，不能套用查询头数高估或低估。

### 3.7.1 推测解码

“推测解码”（也称投机解码）让较便宜的草稿模型串行提案 γ 个词元，再由目标模型在这些**候选前缀**上批量验证。目标验证可在一批里处理多个位置，不代表只算了一个位置。第一处拒绝之后的提案与临时缓存必须作废，因为它们依赖未被接受的前缀。

本节依据真实取得并补读的 [Leviathan 等，2023 全文 PDF](https://proceedings.mlr.press/v202/leviathan23a/leviathan23a.pdf)，定位为 §2.3、Algorithm 1（纸面第3页）、§3.3–3.4及附录 A.1（第11页）。设 p(x) 是目标分布，q(x) 是同一前缀上的草稿分布，提案 x 来自 q；a(x) 是对这个提案的接受概率，β 是总体接受率。

$$
a(x)=\min\left(1,\frac{p(x)}{q(x)}\right),\quad \beta=\sum_x\min(p(x),q(x)),\quad r(x)=\frac{[p(x)-q(x)]_+}{1-\beta}.
$$

人话说：草稿过多分配的概率质量必须拒绝，然后把质量补给草稿分配不足的词。q(x)=0 的词不会被提案抽到，不需要对该词做接受除法；β=1 时无拒绝，残差分布无需定义。拒绝时从 r 补抽；若 γ 个提案全部接受，再从对应下一前缀的 p 补抽一个。

$$
P(\text{输出}=x)=\min(p(x),q(x))+(1-\beta)r(x)=p(x).
$$

这个恒等式通过加总接受与拒绝两条路径证明**单步边际**。真实自回归模型在每个前缀使用自己的 pᵢ/qᵢ，才能逐步维持目标联合分布；本页实验刻意固定每步 p/q，不能拿它的断言冒充真实模型的逐前缀验证。等分布也不表示同一随机种子下会生成完全相同的序列。

**先预测**：默认 p=(0.5,0.3,0.2)，q=(0.2,0.2,0.6)，草稿首先抽到C。接受概率是1/3，固定验证数0.7会拒绝它。恢复分布 r 应是(0.75,0.25,0)，还是原p？把故障打开，比较边际条形与最终补抽token，再切换“接近目标”走全部接受路径。

<Llm03TransformerEvidenceGateLab />

程序第四块用有理数**枚举**概率质量，而非用随机频率近似正确性。`wrong=True` 保留相同接受率，却错误地直接从 p 重抽；它会系统性偏移边际。β=1 时的分支只为让函数总有返回值，实际上不会使用拒绝分布。

```python
P = [F(1, 2), F(3, 10), F(1, 5)]
POOR = [F(1, 5), F(1, 5), F(3, 5)]
CLOSE = [F(9, 20), F(7, 20), F(1, 5)]

def sampling(p, q, wrong=False):
    accepted = [min(a, b) for a, b in zip(p, q)]
    beta = sum(accepted)
    r = p if wrong or beta == 1 else [
        max(F(0), a - b) / (1 - beta) for a, b in zip(p, q)]
    marginal = [a + (1 - beta) * b for a, b in zip(accepted, r)]
    return beta, r, marginal

for q in [POOR, CLOSE, P, [F(1), F(0), F(0)]]:
    beta, r, marginal = sampling(P, q)
    assert marginal == P and sum(marginal) == 1
assert sampling(P, POOR)[1] == [F(3, 4), F(1, 4), F(0)]
assert sampling(P, POOR, wrong=True)[2] != P
print("marginal", sampling(P, POOR)[2],
      "fault", sampling(P, POOR, wrong=True)[2])
```

第五块按给定均匀数抽样，累积概率到第一次越过 u。演示复用固定数方便逐格核对，不把固定轨迹当随机试验；证明等分布来自上一块完整质量枚举。

```python
def draw(prob, u):
    acc = F(0)
    for i, value in enumerate(prob):
        acc += value
        if u < acc:
            return i
    raise ValueError("probabilities must sum to one and 0<=u<1")

def trace(q, window=3, prefix=2, wrong=False):
    proposals = [draw(q, u) for u in [F(55, 100), F(9, 10), F(1, 10)][:window]]
    uniforms = [F(7, 10), F(9, 10), F(9, 10)]
    n = window
    for i, x in enumerate(proposals):
        if uniforms[i] > min(F(1), P[x] / q[x]):
            n = i
            break
    r = sampling(P, q, wrong)[1] if n < window else P
    extra = draw(r, F(3, 5))
    return proposals, proposals[:n] + [extra], prefix + n
```

最后一块断言拒绝、全部接受和恢复三条路径。有效 KV 数是已有格加接受提案格；补抽的最后一个 token 尚未前向计算，下次迭代才写入自己的 KV。因此有效缓存数不能无条件等于输出长度加已有长度。

```python
proposals, output, valid_kv = trace(POOR)
assert proposals == [2, 2, 0]
assert output == [0] and valid_kv == 2
assert trace(POOR, wrong=True)[1] == [1]
assert trace(POOR)[1] == output
assert trace(CLOSE)[1] == [1, 2, 0, 1]
assert trace(CLOSE)[2] == 5
assert trace(CLOSE, window=1, prefix=6)[2] == 7
print("rejection", proposals, output, valid_kv)
print("all accepted", trace(CLOSE))
print("PASS: attention, geometry, exact marginal, rollback, recovery")
```

<Callout type="trap" title="拒绝后抽p，不会自动等分布">
  现象：草稿被拒后直接抽p，看起来仍在用大模型。原因：接受路径已经拿走min(p,q)的质量，重抽p没有补齐正确缺口。修法：用归一化的正残差r；默认故障输出边际为(0.40,0.32,0.28)，不等于p。greedy相同前缀比较不构成随机采样等分布证明。
</Callout>

### 3.7.2 简化Transformer

减少层、宽度、头或改动前馈结构可以降低参数/计算，但会改变函数与容量，一般需要重新训练、微调或质量回归。去掉解码器交叉注意力还会改变信息来源，不能说只是“无损省掉一层”。与之相对，融合算子、避免临时张量等实现简化的目标是保留数学计算；也仍要检查数值误差。

选择时先定位瓶颈：若受KV读取限制，单纯删一个不占主导的算子不必然改善总体延迟。不能把简化结构与精确投机采样混为一类“输出不变”的技术。

### 3.7.3 修剪

修剪（剪枝）删去部分权重、通道、头或层。非结构化稀疏让许多权重归零，却可能仍以密集矩阵存储和执行；结构化剪枝更容易改变实际张量尺寸，但通常也改变模型函数。零权重比例不等于吞吐提升比例。

本页只给方法定义与部署判断，不复现某一剪枝论文，也不报告压缩率。应检查剪枝后的校准/微调、困难样本、真实内核稀疏支持与端到端计时；“参数少”不是“答案质量没变”的证据。

### 3.7.4 蒸馏

蒸馏用教师的预测等监督信号训练较小的学生。[Hinton 等摘要](https://arxiv.org/abs/1503.02531)讨论把模型集成知识压缩进更易部署的单模型；这里不把学生视为教师的逐点复制，也不使用摘要之外的温度/损失实验细节作论文结论。

学生可独立服务，也可作为投机草稿；两种用法的正确性来源不同。直接用学生会改变输出分布；用学生提案再由教师按精确规则验证，才有前述采样保证。学生的训练成本与推理收益应分别记账。

### 3.7.5 混合精度

混合精度让不同张量或运算使用不同浮点格式，在存储、吞吐和数值范围之间权衡；它不是所有值统一截断。低精度乘法配较高精度累加、保留关键状态的高精度是常见思路；具体内核和格式必须检查，不能仅从“位数减半”推出运行时间减半。

[Mixed Precision Training 摘要](https://arxiv.org/abs/1710.03740)讨论半精度权重/激活/梯度、单精度权重副本与损失缩放；这是训练配方范围，不代表推理一定需要损失缩放。推理应检查溢出、舍入与小概率变化；量化成整数又是另一类表示。本页 Python 使用普通数值和有理数，不模拟低精度硬件。

<Callout type="trap" title="少算、少存、跑得快是三个命题">
  现象：窗口缩短、权重剪零或位数减少后，就写“GPU加速”。原因：没有测量实际内核、读写和调度，且可能改变质量。修法：分别报告理论计算、存储和同条件端到端指标；本页只报告玩具计数与概率误差，没有测得GPU加速。
</Callout>

### 3.7.6 高效扩展Transformer推理

多请求服务需要调度：预填充通常工作量大，解码每步工作量小而反复读权重/KV；把不同请求组合进批次，要在吞吐、首词延迟和逐词延迟之间取舍。请求结束后释放缓存、让新请求加入，是动态批处理要处理的生命周期，不能把实验三的一条序列当成已实现的服务调度器。

[PagedAttention 摘要](https://arxiv.org/abs/2309.06180)把分页思想用于巨大且动态增长/缩减的KV缓存，减少碎片和冗余复制。页表改变物理存储管理，不自动扩大模型的有效上下文，也不等于外部知识检索。多设备切分还涉及通信和同步；前缀共享必须满足模型、token、位置、缓存版本与权限一致。

投机轨迹里的“暂存→验证→截断→提交”是真实算法依赖的模拟：多个候选位置可批验证，拒绝后后缀不可提交。更大 γ 可能摊薄目标串行调用，也可能浪费计算与临时KV；论文§3.3的时间分析有并行资源假设，§3.4明确可能增加总算术量。本文没有把批次数换算成毫秒、GPU倍速或线上吞吐。

## 3.8 小结

沿着三个位置走完计算后，应能把合法连接、位置关系与执行策略分开检查。注意力的数值正确性、生成概率正确性和系统性能需要各自的证据，不能互相替代。

- QK给分数，mask限定合法读取，softmax后才聚合V。
- 同频位置一起旋转保留夹角，不保证任意长度外推。
- KV缓存复用历史投影；拒绝的候选后缀必须回滚。
- 精确投机采样用接受率和残差校正，不靠greedy类比。
- 优化需声明改变什么、保留什么，并另测质量与性能。

<Glossary>
  <GlossaryItem term="Transformer">
    用注意力交换位置信息，再用逐位置前馈变换处理通道的架构；不限于某一种编码器或解码器配置。
  </GlossaryItem>
  <GlossaryItem term="缩放点积注意力">
    QK点积除以维度平方根，行归一化后加权V；分数、概率和输出向量是三种不同对象。
  </GlossaryItem>
  <GlossaryItem term="因果掩码">
    在归一化前阻止读取未来位置；方向写反仍会有数值，但生成任务已泄漏答案。
  </GlossaryItem>
  <GlossaryItem term="位置编码">
    送入绝对位置或相对关系的表示；正弦函数、学习查表、相对偏置不能混为一谈。
  </GlossaryItem>
  <GlossaryItem term="KV缓存">
    保存各层过去位置的键和值；节省重复投影，却仍占内存且需要读历史。
  </GlossaryItem>
