## 为什么“学会预测”不等于“选好一句话”

一条生产线可以根据过去的产品预测下一件，也可以在残缺产品上补齐缺口。两者看见的材料不同，验收位置也不同。若把答案一起送进输入，成绩会很好看，却没有学到原来的任务。

产品完成后，出货规则仍能改变结果：每次取眼前最优，不一定使整批最好；多留一些候选，也不自动保证质量。本章把“学习时允许看什么”和“使用时选什么”拆开计算。

### 第4章 预训练目标和解码策略

这一正式章坐标对应两种不同决策。训练侧的<Term def="规定输入如何构造、哪些位置参与误差，以及要预测什么的学习任务。">预训练目标</Term>决定模型因为什么误差而调整参数；生成侧在参数固定后，把模型给出的条件概率变成一次次词元选择。本页只计算后者的规则及前者的输入／标签关系，不进行梯度更新。

先修是上一章的注意力与因果遮罩，以及[第2章的词元和概率单位](/learn/large-language-models/03-language-tokenization/llm-02-language-modeling-tokenization)。如果两个模型分词方式不同，逐词元概率和损失不能直接当作同一种单位比较；本页统一用字母作固定词表，排除这个混杂因素。

### 4.1 模型架构

架构在这里首先回答“当前位置能从哪里取信息”。编码器通常允许双向读取输入；因果解码器只读取当前及之前的**输入**位置；编码器—解码器先表示源序列，再让目标侧读取源表示及已经给出的目标前缀。它们不是三个固定任务标签：同类架构仍可更换预训练目标。T5论文§3.2及图3专门分开比较架构与目标。

| 信息流        | 允许读取                                 | 不能据此推出                 |
| ------------- | ---------------------------------------- | ---------------------------- |
| 编码器        | 有效输入的左右两侧                       | 每个位置都必须计入损失       |
| 因果解码器    | 当前位置及之前的输入                     | 当前输入就是当前预测标签     |
| 编码器—解码器 | 源序列双向，目标前缀因果，交叉读取源表示 | 可提前读取尚未给出的目标答案 |

实验一把可见性画成0/1矩阵，而不是注意力强弱。1只表示允许读取；真正的注意力权重还要由查询、键等计算。双向并不天然泄漏：只要原词已从输入替换为遮盖标记，读取那个标记不等于读取原答案。

### 4.2 预训练目标

因果语言建模（CLM）用前缀预测下一词。令输入为A、B、C、D、PAD，第0行输入A，预测标签B；第1行输入B，预测C。矩阵可以包含对角线，因为对角线是当前**输入**，不是右移后的标签。这里不预测最后的PAD，所以只监督前三行。实际训练通常还有起止标记；本例省略它们，不能据此推断产品的标记约定。

$$
A^{\mathrm{CLM}}_{ij}=\mathbf{1}[i<4,\ j<4,\ j\le i],\qquad
L=-\frac{\sum_i m_i\log p_i(y_i)}{\sum_i m_i}.
$$

第一个式子规定每行能看到哪列；第二个式子只把监督掩码为1的位置计入平均负对数概率。可见性遮罩与损失掩码控制不同事情，不能用其中一个代替另一个。

遮盖语言建模（MLM）则先破坏输入，只在选中的位置还原原词。实验默认把B替换为M，输入A、M、C、D、PAD；所有有效位置可以双向读取，只有B所在行计损失。故障“泄漏答案”会**恢复输入中的B**，而不是仅打开对角线。BERT原论文§3.1实际选取15%的位置，其中80%替换为[MASK]、10%替换为随机词、10%保持原词；还使用下一句预测目标。BERT的10%保持原词是其任务配方的一部分；本toy则约定该样本必须遮盖，恢复答案才算违反约定，不能据此判定BERT配方有错。实验简化为只遮一个词，绝不冒充完整BERT流程。

**先预测：** CLM打开未来列后，标签概率会怎样变化？MLM恢复原词会不会改变矩阵形状？再切换PAD误计损失，看分母是否改变。

<Llm04PretrainingDecodingContextContractLab />

实验中的概率也是真算的，但生成规则是人为定义的：对每个可见输入，给与它相同的候选词加2分；M不对应任何候选，PAD永不可读；对五个候选分数做softmax。CLM默认前三行的正确答案都未出现，平均损失约2.8319；泄漏后有效行都读到A—D，正确标签概率升至约0.2418。这是暴露答案导致成绩虚高的**构造反例**，不是语言模型能力测量。PAD故障另把第5行的均匀分布损失计入，使CLM分母由3变4。

下面开始完整程序。把本页所有Python块按顺序拼进同一文件，以Python 3运行；只用标准库，每块都是同一程序的连续部分。

```python
import math

TOKENS = ["A", "B", "C", "D", "PAD"]

def softmax(logits, temperature=1.0):
    assert temperature > 0
    top = max(logits)
    weights = [math.exp((z-top)/temperature) for z in logits]
    return [w / sum(weights) for w in weights]

def objective(mode="clm", masked=1, fault="none"):
    inputs = TOKENS.copy()
    if mode == "mlm" and fault != "leak":
        inputs[masked] = "M"
    visible = [[i < 4 and j < 4 and
                (mode == "mlm" or j <= i or fault == "leak")
                for j in range(5)] for i in range(5)]
    mask = [(i < 3 if mode == "clm" else i == masked)
            or (fault == "pad" and i == 4) for i in range(5)]
    target = [min(i+1, 4) if mode == "clm" else i
              for i in range(5)]
    scores = [[sum(2 for j in range(5)
                   if visible[i][j] and inputs[j] == v)
               for v in TOKENS] for i in range(5)]
    probs = [softmax(row) for row in scores]
    loss = -sum(math.log(probs[i][target[i]])
                for i in range(5) if mask[i]) / sum(mask)
    return visible, mask, loss, inputs
```

这一块明确把“输入内容”“读取权限”“监督标签”分开。以下断言检查右移索引、泄漏及PAD，而不是仅检查程序能启动。

```python
baseline = objective()
assert baseline[0][0] == [True, False, False, False, False]
assert baseline[1] == [True, True, True, False, False]
assert objective(fault="leak")[2] < baseline[2]
assert sum(objective(fault="pad")[1]) == 4
mlm = objective("mlm")
leaked = objective("mlm", fault="leak")
assert mlm[3][1] == "M" and leaked[3][1] == "B"
assert mlm[0] == leaked[0]  # 相同权限，不同输入内容
assert leaked[2] < mlm[2]
assert objective() == baseline  # 从相同输入恢复
print("objective loss", round(baseline[2], 4))
```

| -------------------------------- | --------------------------------------------- | ---------------------------------------- |
| BERT（2018预印本／2019会议论文） | 双向编码器；MLM与下一句预测                   | 实验一：原答案从输入移走，选定位置计损失 |

以T5式片段还原作展开：源输入“我 X 北京”，目标“X 爱 Z”；X、Z是区分缺失片段边界的标记，不是普通词。解码器训练时可得到右移目标“起始、X、爱”，依次预测“X、爱、Z”。提供上一步的正确词作为输入叫teacher forcing；把“爱”提前放进预测“爱”的那一行，仍是泄漏。实验一不实现T5的哨兵词或源目标双矩阵，它只演示CLM／MLM的核心区别。

### 4.4 解码策略

有了固定的条件概率，还需要选词规则。训练损失并不规定生成时一定取最大概率，更不保证概率最大的整句最有用。Holtzman等人的核采样论文比较同一模型下不同解码的输出，指出开放式生成中最大化似然可能产生退化文本；这是特定实验支持的经验结论，不是“束搜索在所有任务都更差”的定理。

#### 温度先改分布，截断再改支持集

模型给出的未归一化分数叫logits；本例固定为log(0.4)、log(0.3)、log(0.2)、log(0.1)。生成时的<Term def="在softmax前缩放分数差，控制分布尖锐或平坦程度的正数。">温度</Term>控制各候选之间的相对差距，不修改模型参数。

$$
p_T(v)=\frac{\exp(z_v/T)}{\sum_w\exp(z_w/T)},\quad T>0.
$$

这表示分数先除以正温度，再转成总和为1的概率。实现会先减去最大logit防止溢出；T越低通常越尖锐，但不是把概率直接除以T。T=0不能代入公式，可把唯一最大值情况下的极限与贪心联系起来；并列最大值须另定规则。

top-k只保留概率最高的k个词；<Term def="选择排序后累计概率首次达到阈值的最小前缀，再在其中按归一化概率抽样。">核采样</Term>（top-p）按质量而非数量确定集合。实验先按温度后的概率降序排序，概率并列按词表A、B、C、D的原顺序破同分。这里选择“最小前缀”的确定约定，不把阈值边界上的所有并列词额外加入；其他实现若采用不同并列规则，应明确记录。

$$
n=\min\{r:\sum_{j=1}^{r}p_T(v_{(j)})\ge p\},\qquad
q(v)=\frac{p_T(v)\mathbf{1}[v\in S]}{\sum_{w\in S}p_T(w)}.
$$

先找刚好够阈值的最短候选前缀，再除以留下的概率质量；因此top-p=0.75在本例T=1时保留前三词，质量为0.9，而不是恰好保留0.75。约定0&lt;p≤1，p=1保留全部词；top-k需满足1≤k≤词表大小。

**猜一猜：** 同样的u=0.65，top-k=2与top-p=0.75会落在哪个区间？再把u调至0.95并打开“未重归一化”，看抽样为何落空。温度改变后候选数量也可能变化。

<Llm04PretrainingDecodingComputeTraceLab />

累计分布CDF把q铺成[0,1)上的相邻区间，区间长度就是抽中概率。u必须在[0,1)，选择满足“前一累计值≤u&lt;当前累计值”的词；u=1不应被偷偷归到最后一词。此处固定u是为了对照，不是假称某随机种子生成的随机数序列。基线q=(4/9,3/9,2/9,0)，u=0.65落在B区间；故障下质量只剩0.9，u=0.95没有合法区间。

继续程序，显式实现排序与并列约定；阈值比较使用10⁻¹²的浮点容差，避免本应为0.9的加和因舍入而多留一词。对任何严格正的softmax分布，p=1都保留整个词表；不依赖浮点加和是否恰好等于1。

```python
def truncate(probs, kind="p", threshold=.75, faulty=False):
    order = sorted(range(len(probs)), key=lambda i: (-probs[i], i))
    if kind == "k":
        assert int(threshold) == threshold and 1 <= threshold <= len(probs)
        keep = order[:int(threshold)]
    else:
        assert 0 < threshold <= 1
        keep, mass = [], 0.0
        for i in order:
            keep.append(i)
            mass += probs[i]
            if threshold < 1 and mass >= threshold - 1e-12:
                break
    mass = sum(probs[i] for i in keep)
    return [v / (1 if faulty else mass) if i in keep else 0.0
            for i, v in enumerate(probs)]

def sample(probs, u):
    assert 0 <= u < 1, "u must be in [0,1)"
    cdf = 0.0
    for i, p in enumerate(probs):
        cdf += p
        if u < cdf:
            return i
    return None  # 故障分布可能留下没有覆盖的区间
```

以下不是统计试验，而是确定性边界测试：对照质量守恒、并列、p=1与非法u。正式抽样需要随机数发生器，还要记录其状态；本页不估计生成质量或多样性分数。

```python
p = softmax([math.log(v) for v in [.4, .3, .2, .1]])
q = truncate(p)
assert math.isclose(sum(q), 1)
assert sample(q, .65) == 1
assert sum(v > 0 for v in truncate(p, "k", 2)) == 2
assert truncate(p, threshold=1) == p
assert truncate([.25]*4, threshold=.5) == [.5, .5, 0, 0]
broken = truncate(p, faulty=True)
assert math.isclose(sum(broken), .9)
assert sample(broken, .95) is None
assert sample(truncate(p), .95) == 2
assert max(softmax([math.log(v) for v in p], .5)) > max(p)
try:
    sample(q, 1)
except AssertionError:
    pass
else:
    raise AssertionError("u=1 was not rejected")
print("nucleus", [round(v, 4) for v in q])
```

#### 局部最大与整条路径

<Term def="每一步只取当前条件概率最高的词，不保留其他前缀。">贪心解码</Term>
的优势是决策简单，不用维护多个前缀；代价是第一步丢弃的分支以后无法回来。
<Term def="每一层扩展保留的前缀，再按累计分数只保留指定数量的候选。">
  束搜索
</Term>
用更多候选缓解这个问题，但有限宽度仍可能剪掉真正的全局最优路径。

$$
\log P(y_1,\ldots,y_t\mid x)=\sum_{s=1}^{t}\log P(y_s\mid x,y_{<s}).
$$

整条序列的概率是各步条件概率相乘，取对数后变成逐步相加；不能把各步概率直接相加，也不能只用最后一步的条件概率排序。

**先预测：** 首步A=0.6、B=0.4；下一步A的两个候选概率0.51／0.49，B的两个候选0.9／0.1。贪心会选哪条？束宽2会选哪条？切换宽度后再注入丢弃次优前缀，确认故障发生在第一层，不是最后随意改答案。

<Llm04PretrainingDecodingEvidenceGateLab />

贪心先取A，再选A1，联合概率0.6×0.51=0.306；束宽2先留下A、B，随后B1以0.4×0.9=0.36胜出。图中边粗表示条件概率，叶子下方数字是联合概率，淡化的分支已被剪掉。把P(A)改为0.8，A1的0.408又超过B1的0.18，说明“首步较弱分支更好”只是这一组输入的反例，不是另一条普遍规律。

下面的搜索会在**每层**截断束，而不是先枚举整树再声称完成束搜索。两步之后统一终止，不比较不同长度；所以无需长度归一化。

```python
def search(width=2, root_a=.6, faulty=False):
    transitions = {
        "": [("A", root_a), ("B", 1-root_a)],
        "A": [("A1", .51), ("A2", .49)],
        "B": [("B1", .9), ("B2", .1)],
    }
    beams = [("", 0.0)]
    trace = []
    for depth in range(2):
        candidates = [(token, score + math.log(p))
                      for prefix, score in beams
                      for token, p in transitions[prefix]]
        candidates.sort(key=lambda item: (-item[1], item[0]))
        limit = 1 if faulty and depth == 0 else width
        beams = candidates[:limit]
        trace.append(beams.copy())
    return beams[0][0], math.exp(beams[0][1]), trace
```

最后验证参考、改变、故障和恢复。若改成不等长序列，还须显式加入EOS候选、已完成束保存和停止条件；不能把当前两步程序冒充完整生产解码器。

```python
assert search(1)[0] == "A1"
assert math.isclose(search(1)[1], .306)
assert search(2)[0] == "B1"
assert math.isclose(search(2)[1], .36)
assert search(2, faulty=True)[0] == "A1"
assert len(search(2, faulty=True)[2][0]) == 1
assert search(2, root_a=.8)[0] == "A1"
assert search(2) == search(2, faulty=False)
print("search", search(1)[:2], search(2)[:2])
print("all assertions passed")
```

在真正生成中，短序列往往因乘的因子较少而有较高原始概率；加入长度惩罚会改变搜索目标，不只是加速技巧。EOS必须参与结束决策，达到最大长度也不等于自然完成。翻译等输入约束强的任务常用束搜索；开放式写作可考虑随机采样，但具体温度、截断阈值要依任务评估，不能靠这个四词实验决定。

### 4.5 小结

本节回收的不是某个模型排名，而是三条可检查的区分：读入权限不等于监督位置；单步分布不等于选词规则；局部最优不等于整条路径最优。任何对比若同时改变模型、提示和温度，都不能只把差异归因于预训练目标。

- 用右移标签与两种掩码检查训练任务。
- 先调温度，再截断并归一化，最后用CDF抽样。
- 比较累计路径分数，同时检查第一层剪枝。

## 常见误区与故障定位

每个故障都能定位到具体计算，而不是笼统说“模型坏了”。先核对输入与状态，再判断结果是否支持预期解释。

<Callout type="trap" title="损失变小就是任务学得更好？">
  **现象 →** 打开泄漏后损失下降。**原因 →**
  CLM读到未来答案，或MLM原词被恢复，输入任务已变。**修法 →**
  关闭泄漏并完整重置，逐行核对输入、标签和可见列；不能报告为训练改进。
</Callout>

<Callout type="trap" title="截断后直接沿用原概率？">
  **现象 →** u=0.95找不到词。**原因 →**
  候选质量只有0.9，却当作完整分布使用。**修法 →**
  除以保留质量，检查Σq=1，再在[0,1)内抽样。
</Callout>

<Callout type="trap" title="束宽写2就一定保留了两条？">
  **现象 →** 请求宽2却仍输出A1。**原因 →** 第一层实际只剩A，B1已不可达。**修法
  →** 检查每层实际候选数、累计log分数与停止规则，而不是只读配置值。
</Callout>

## 练习与答案

三题分别检验输入合同、概率计算和搜索取舍。先写预测，再操作或改程序，最后展开答案比对。

<Exercises>

**问题 1**：MLM输入A、M、C、D时，矩阵中的第2行第2列为1是否已经泄漏B？把故障切换为“泄漏答案”，哪项数据真正变了？

<Answer>
  没有。读取M不等于读取B。故障恢复输入中的B，可见性矩阵不变，但证据加和多了B的2分，目标B的概率升高、损失下降。关闭故障后应恢复M和原损失，而不是只把颜色改回去。
</Answer>

**问题 2**：T=1时用top-k=2，写出q和u=0.65的落点。再把实验改为top-p=1、T=2，保留多少个词？u=1是否合法？

<Answer>
  前两词质量0.7，q=(4/7,3/7,0,0)，u=0.65落在B。top-p=1无论正温度是多少都保留全部四词；T=2只改变概率，不减少数量。u=1不在[0,1)，程序应拒绝它，不能强行返回D。
</Answer>

**问题 3**：修改实验的首步概率，求束宽2下A1与B1打平的P(A)；然后分别试0.6、0.65。若用于翻译和开放式故事续写，你会如何选择规则并声明边界？

<Answer>
  令a×0.51=(1-a)×0.9，得a=0.9/1.41≈0.6383。故a=0.6时B1赢，0.65时A1赢；界面步长0.05无法精确取打平值，可改Python参数验证。翻译可把束搜索作为候选方案，故事可把采样作为候选方案，但都必须用各自任务指标和人工检查验证。两步toy没有语言质量证据，不能证明某策略普遍最优。
</Answer>

## 名词解释

以下五个术语对应正文首次高亮；字母词表、右移与softmax等辅助概念已在相应实验旁展开。

<Glossary>
  <GlossaryItem term="预训练目标">
    规定学习时喂入什么、预测什么、在哪些位置扣分；不是生成时的选词菜单。
  </GlossaryItem>
  <GlossaryItem term="温度">
    用正数缩放分数差：低温通常更集中，高温更分散；不改变训练参数。
  </GlossaryItem>
  <GlossaryItem term="核采样">
    保留累计概率刚够阈值的最小前缀，再归一化抽样；保留数量可随分布变化。
  </GlossaryItem>
  <GlossaryItem term="贪心解码">
    每步只取眼前概率最高的词；丢掉的前缀不会再回来。
  </GlossaryItem>
  <GlossaryItem term="束搜索">
    每层扩展候选，再保留有限条累计分数最好的前缀；不是穷举保证。
  </GlossaryItem>
</Glossary>
