## 为什么同一个模型，换几行示范就换了答案

你要把客服留言分成三个类别。换一组例子，结果变了；在输入末尾放一条强烈的负面评论，结果又变了。此时模型文件并未改变。另一位同事换了一个适配器，也得到不同结果。两者都像“学会了任务”，但前者改变**本次推理的条件**，后者改变**持久参数**。分不清这一点，下一步就无法决定该保存提示、重估偏置，还是训练适配器。

本页用三个小计算把它们拆开：示范决定一套手写邻居投票；校准重加权已给出的类别概率；LoRA给线性层加一个低秩更新。它们都能在浏览器与标准库Python中复算，但**没有运行真实LLM，也没有训练或测量任何模型**。先修是上一章的条件概率与softmax，以及矩阵乘法的行列规则。

## 第5章 上下文学习和轻量级微调

本章的总问题不是“哪一种永远更强”，而是“性能变化来自上下文样本、顺序、校准还是参数更新？”令模型为 $p_\theta(y\mid D,x)$：$D$是示范及指令，$x$是本次问题，$\theta$是权重。改$D$是输入侧适应；训练$\theta$的子集或增量是参数侧适应；输出校准则变换概率。这三处改变可以组合，但比较时必须先分开。

### 5.1 上下文学习

<Term def="在推理输入中提供任务描述或示范，以条件化输出；本次使用不通过梯度更新模型权重。">
  上下文学习
</Term>
（ICL）的“学习”不等于在这个请求中执行优化器。[GPT-3论文](https://arxiv.org/pdf/2005.14165)§2区分零样本、单样本和少样本设置；少样本示范被串进上下文，评估时不做梯度更新。计算仍有中间激活和缓存，故“不更新权重”绝不等于“没有状态变化”。

真实任务需要先固定标签文字、输出格式和可用上下文长度。示范太多可能挤走查询或关键信息；更多例子不是免费训练数据。若把真实测试答案直接放进上下文，就变成泄漏，而非泛化。

### 5.1.1 示范样本选择

<Term def="放进提示中的输入—输出实例，用于表达任务规则、标签含义或解题形式；其来源和标签需要独立核验。">
  示范样本
</Term>
至少有四个选择维度：相关性、标签覆盖、难度、长度预算。最近邻可以提高局部相关性，却也会集中同一类，或反复检索同一个错误标签。用完整测试集标签来挑选“最好示范”则越过评估边界。相似度检索是一种选择策略，不是任务正确性的保证。

实验一故意只保留三个候选。A=(0.2,0.2,+1)、B=(0.8,0.3,−1)、C=(0.6,0.8,+1)，默认Q=(0.7,0.4)。这些是人为二维特征，不是实测嵌入。“最近两个”选B、C；“正负各一个”先选最近正例C，再选负例B。后者同时改变槽位次序，所以要用排列控件把次序对齐，才可隔离选择本身。

### 5.1.2 样本排序

固定示范集合后，排列仍可能改变模型输出。[Zhao等人](https://proceedings.mlr.press/v139/zhao21c/zhao21c.pdf)§3–4分析了提示格式、示范集合和排列引发的方差，并讨论近因偏置。下面不是复现GPT-3，而是用显式位置衰减构造一个可手算的顺序敏感系统。对两条示范，位置$i=0,1$，$d_i$为欧氏距离，$y_i\in\{-1,+1\}$：

$$
w_i=\frac{\rho^{1-i}}{0.1+d_i},\qquad
s=\frac{\sum_i w_i y_i}{\sum_i w_i},\qquad
p(+)=\frac{1+s}{2}.
$$

$0.1$防止零距离造成无穷权重；$\rho\in(0,1]$控制前位衰减。这里的$p(+)$是**我们定义的投票概率**，不是LLM输出概率。默认B在前、C在后，约得$p(+)=0.485$；反转后约为0.191。先预测：把$\rho$设为1后，反转还会变吗？再翻转最近的B标签，看“离得近”如何放大错标影响；最后点恢复，并试完整重置。

<Llm05IclLightweightFinetuningContextContractLab />

平面里的虚线表示入选示范，矩形位置槽显示顺序和权重，末端条段显示正票比例。故障把B的负标签改为正标签时，两票都正，$p(+)=1$；这不是系统更自信就更正确的证据。查询移到另一侧后，最近候选会变化，因此故障始终作用于**当下最近的候选**。

下面开始本页完整标准库程序。将三个Python块按顺序拼入同一个文件，以Python 3运行。第一块复现选择和排序；没有模型下载、SDK或网络调用。

```python
import math

DEMOS = [("A", .2, .2, 1), ("B", .8, .3, -1), ("C", .6, .8, 1)]

def vote(query=(.7, .4), policy="nearest", reverse=False,
         rho=.5, fault=False):
    ranked = sorted(
        [(name, math.hypot(x-query[0], y-query[1]), label)
         for name, x, y, label in DEMOS], key=lambda row: row[1])
    nearest = ranked[0][0]
    if policy == "nearest":
        slots = ranked[:2]
    else:
        slots = [next(d for d in ranked if d[2] == label)
                 for label in (1, -1)]
    if reverse:
        slots.reverse()
    weights = [rho**(1-i) / (.1+d) for i, (_, d, _) in enumerate(slots)]
    labels = [-label if fault and name == nearest else label
              for name, _, label in slots]
    score = sum(w*y for w, y in zip(weights, labels)) / sum(weights)
    return (1+score)/2

p_first, p_reverse = vote(), vote(reverse=True)
assert p_first > p_reverse
assert math.isclose(vote(rho=1), vote(rho=1, reverse=True))
assert math.isclose(vote(fault=True), 1)
print("vote", round(p_first, 6), round(p_reverse, 6))
```

### 5.1.3 指令生成

指令描述标签和约束，示范则展示约束如何落在实例上。“为留言分类”不如“只输出退款、物流、其他之一；同时提及两类时按主要诉求分类”可检验。自动生成指令也不能省掉验证：[APE论文](https://arxiv.org/pdf/2211.01910)§3以输入—输出示范生成候选指令，再对候选评分、选择或迭代。这是一个**搜索与验证流程**，不是“模型写的指令天然正确”。

实际应在开发集上选指令，锁定后再测测试集。若同时换指令和示范，实验一的顺序反转结果就不能解释总体收益；指令可能已经改了任务定义。也要区别“用训练数据做指令微调”与“在一次提示中写一句指令”，两者的权重更新边界不同。

### 5.1.4 思维链

<Term def="提示中展示或要求生成从问题到答案的中间推理步骤；可检查这些步骤，但文字轨迹不保证忠实反映内部计算。">
  思维链
</Term>
把示范从“问题→答案”扩成“问题→中间步骤→答案”。[Wei等人](https://arxiv.org/pdf/2201.11903)§2–3在算术等任务中研究这种提示；结果依赖模型规模、任务与示范，不能概括为所有小模型或所有问题都获益。

例如“每箱3件，4箱共多少件？”可以展示“4×3=12”。检查者应独立验证乘法与单位，而不是因为中间文本流畅就接受12。中间步骤可能包含错误再碰巧得到正确答案，也可能只是事后合理化。本页没有把邻居投票的加权明细叫作真实模型的思维链：前者是完全透明的人为计算，后者的可见文字不等于内部机制全貌。

### 5.1.5 递归提示

递归提示把较大问题拆成可复用的子问题，再把子答案带回父问题。与在一次回答中写长思维链不同，它常涉及**多次调用与外部控制**。[Least-to-Most论文](https://arxiv.org/pdf/2205.10625)§2、表1–2给出先分解、再按顺序利用已有答案求解的具体实例；它是这个方向的一个方案，不等同于所有递归提示。

独立设计时还要补上终止条件：子问题必须更小或达到基本情形，设最大深度、调用数和总词元预算。若分解器反复返回原问题，控制器必须拒绝递归；若子答案错误，后面的调用可能放大它。保存子问题图、父子依赖和失败节点，比只保存最终答案更利于排查。

### 5.1.6 为什么ICL有效

“能利用示范”是行为观察，“为什么能利用”是机制问题。任务识别、预训练中已学模式的检索、在前向传播中实施某种学习算法，可能解释不同模型和任务的现象；不能从一次准确率变化就选定唯一解释。GPT-3的无梯度评估支持“推理时无需显式优化器”这一事实，不支持“内部一定执行了与某算法完全相同的学习过程”。

实验一只证明**所定义系统**的顺序敏感性来自$\rho$：置1后敏感性消失；它没有证明Transformer的顺序敏感性也全来自近因权重。解释真实机制需要对模型内部做干预，并在多种输入和模型上验证，学术争议不能被这张图消除。

### 5.1.7 评估

至少冻结基座版本、提示模板、示范集合、顺序、训练预算、数据切分和评估脚本。先在开发集挑选，再在从未用于挑选的测试集报告结果。对ICL，多个示范集合与排列的均值、离散程度及最差情形通常比单一最好排列更有解释力。对微调，增加训练随机种子和数据预算记录。准确率、概率可靠性、延迟与费用是不同指标。

一个可执行的消融表应包括：基座＋固定提示；只换示范；只换排列；只校准；只加适配器；最后才测试组合。组合收益可以报告，但不能把它全部归给LoRA。这里不虚构“我们的准确率提高了多少”：没有真实模型与独立数据，就没有那项测量。

## 5.2 提示语言模型的校准

即便示范不变，模型也可能偏爱某些标签词。<Term def="用同一提示下内容无关输入产生的类别基线，调整有内容输入的类别分数；效果取决于该基线是否代表待校正的偏置。">上下文校准</Term>先测无内容输入（例如N/A）对应的$p_0$，再调整查询概率$p$。Zhao等人§5使用对角变换，分类时比较$p_i/p_{0,i}$的大小。它不是用测试标签拟合后处理，也不保证所有概率置信度都更可靠。

实验二从**给定的三类概率**开始，未调用模型。我们把比值再按和归一化，以便画到概率单纯形中：

$$
u_i=\frac{p_i}{p_{0,i}},\qquad q_i=\frac{u_i}{\sum_j u_j},\qquad p_{0,i}>0.
$$

论文§5式(1)明确为 $\hat q=\operatorname{softmax}(W\hat p+b)$，其中 $W=\operatorname{diag}(p_{cf})^{-1}$、$b=0$；分类决策取 $\arg\max(W\hat p+b)$。本页使用的是**比值和归一化的教学变体**，与其分类argmax一致，但数值置信度不等同于对比值做softmax，不能冒充逐项复现论文概率。三角形的三个顶点是“某一类概率为1”，任意内部点的三个坐标和为1。线段是从$p$到$q$的几何位移，不是模型训练轨迹。

**先预测：** $p=(0.45,0.35,0.20)$、$p_0=(0.6,0.3,0.1)$时，第三类原始概率最低，校准后会不会成为最大？操作后逐项核对：比值为$(0.75,1.1667,2)$，归一化为$(9/47,14/47,24/47)$，即约$(0.1915,0.2979,0.5106)$。再把基线改成均匀，位移应消失。

<Llm05IclLightweightFinetuningComputeTraceLab />

故障把第三个基线概率设为零。此时除法没有定义，组件停止计算、不画$q$。实际系统若遇到浮点下溢，应检查是否可获得更稳定的对数概率和基线估计；不能无说明地加一个任意小数，再宣称校准可靠。即便所有分母为正，很小的估计误差仍可能被放大。

第二块程序复现同一变换，同时实现论文softmax形式作区别检查。二者argmax相同并不意味着置信度相同；只有另用带标签的独立样本画可靠性曲线或算相应校准误差，才能讨论概率质量。

```python
def normalize(values):
    total = sum(values)
    assert total > 0
    return [v/total for v in values]

def contextual_calibration(p, p0):
    assert len(p) == len(p0) and all(v >= 0 for v in p)
    if any(v <= 0 for v in p0):
        raise ValueError("content-free baseline must be strictly positive")
    return normalize([v/b for v, b in zip(p, p0)])

p, p0 = [.45, .35, .20], [.6, .3, .1]
q = contextual_calibration(p, p0)
assert all(math.isclose(a, b) for a, b in zip(q, [9/47, 14/47, 24/47]))
assert all(math.isclose(a, b) for a, b in zip(
    contextual_calibration(p, [1/3]*3), p))
ratios = [a/b for a, b in zip(p, p0)]
softmax_q = normalize([math.exp(v-max(ratios)) for v in ratios])
assert max(range(3), key=q.__getitem__) == max(range(3), key=softmax_q.__getitem__)
assert not math.isclose(q[2], softmax_q[2])
try:
    contextual_calibration(p, [2/3, 1/3, 0])
except ValueError:
    print("calibration rejects zero baseline")
else:
    raise AssertionError("zero baseline was not rejected")
print("calibration", [round(v, 6) for v in q])
```

## 5.3 轻量级微调

当提示预算或稳定性成为瓶颈，可以训练较少的参数来适配任务。“轻量”通常指可训练参数、适配器存储或优化器状态较少，不等于无需反向传播，也不等于模型本体可以不装入内存。下面依正式标题讨论三类思路及组合；由于未读原书正文，不声称这份成员列表就是作者的完整分类。

### 5.3.1 基于添加的方法

在冻结主干外增加可训练模块，例如adapter的瓶颈网络，或可学习的连续前缀。手写自然语言示范是输入文本；连续前缀是经优化得到的向量，两者都叫“提示”却不在同一训练边界。前者无需为该请求训练参数，后者需要训练过程。

[He等人的统一视角论文](https://arxiv.org/pdf/2110.04366)§2–3比较adapter、prefix tuning和LoRA的表示修改位置与形式。新增模块可能增加推理路径或占用上下文／缓存空间，具体代价取决于接入点。对多租户部署，适配器小不代表同时装载许多适配器没有管理成本。

### 5.3.2 基于规范的方法

保留这个正式标题时，先防一个术语坑：不能看见“规范”便自动解释为LayerNorm。本节独立讨论**约束更新范围**这条路线，例如只更新偏置、部分层或所选已有参数；这与向网络添加新模块不同。统一视角论文§2.1将只调偏置等作为相关参数高效方法讨论。若采用正则项约束更新幅度，也应写清目标函数及约束对象，而不是只写“规范后更稳定”。

选参式方法需要交付参数掩码：哪些张量可训练、占总量多少、优化器是否真的排除冻结参数。若冻结范围选错，局部任务可能欠拟合；若把“只调少数参数”说成“完全不改基座”，则与实际存储状态矛盾。

### 5.3.3 基于重新参数化的方法

<Term def="把权重增量写成两个瘦矩阵的乘积，冻结基座而训练低秩因子；常见实现为LoRA。">低秩适配</Term>（LoRA）把$\Delta W$写成$BA$。[原论文](https://arxiv.org/pdf/2106.09685)§4.1给出前向式、$\alpha/r$缩放和可合并性。对$W_0\in\mathbb R^{d\times k}$，$A\in\mathbb R^{r\times k}$、$B\in\mathbb R^{d\times r}$：

$$
h=W_0x+\frac{\alpha}{r}B(Ax),\quad
W=W_0+\frac{\alpha}{r}BA,\quad
N_{\mathrm{train}}=r(k+d).
$$

这里的“秩”限制**更新矩阵**，不是声称基座$W_0$也是低秩。只有$r(k+d)<dk$时这一层的新增可训练参数才少于全量更新。真实训练通常让一个因子初始为零，使初始增量为零；实验三为看清乘法，直接给定非零A、B，**没有执行优化或模拟初始化过程**。

**先预测：** 默认$W_0=I$、$A=[1,-1]$、$B=[1,2]^T$、$x=(2,1)$、$r=1$、$\alpha=2$。$Ax=1$、$BAx=(1,2)$、$\Delta h=(2,4)$，所以$h=(4,5)$。若漏掉缩放，结果应变为$(3,3)$，不是同一个适配器。操作后核对图中合并矩阵的乘积。

<Llm05IclLightweightFinetuningEvidenceGateLab />

把秩改成2时，图中增加A的一行和B的一列；它不是偷偷训练出一组新权重，而是切到另一组明确给定的因子。默认秩1的$BA$两行相关，只能表达受限更新。秩2的示例可为满秩，却需要8个新增参数，而2×2基座只有4个。小矩阵正好反驳“用了LoRA就一定省参数”；在大维度、小秩时才有优势。

第三块程序分别走“分支计算”和“先合并再乘”两条路径，比较每个分量，并检查遗漏缩放的失败与其恰好不可见的边界。

```python
def matvec(matrix, vector):
    return [sum(a*b for a, b in zip(row, vector)) for row in matrix]

def lora(rank=1, alpha=2, x=(2, 1), fault=False):
    A = [[1, -1]] if rank == 1 else [[1, -1], [0, 1]]
    B = [[1], [2]] if rank == 1 else [[1, 0], [2, 1]]
    z = matvec(A, x)
    scale = 1 if fault else alpha/rank
    delta = [scale*v for v in matvec(B, z)]
    h = [a+b for a, b in zip(x, delta)]  # W0 = I
    W = [[(1 if i == j else 0) + scale*sum(
        B[i][t]*A[t][j] for t in range(rank))
        for j in range(2)] for i in range(2)]
    merged_h = matvec(W, x)
    assert all(math.isclose(a, b) for a, b in zip(h, merged_h))
    return h, W

assert lora()[0] == [4, 5]
assert lora(fault=True)[0] == [3, 3]
assert lora(alpha=1)[0] == lora(alpha=1, fault=True)[0]
for r in (1, 2):
    for a in (1, 2):
        for x in ((2, 1), (1, -1)):
            lora(r, a, x)
            lora(r, a, x, fault=True)
assert 1*(2+2) == 2*2  # toy: no parameter saving
assert 8*(4096+4096) < 4096*4096
print("lora", lora()[0], "all assertions passed")
```

### 5.3.4 混合方法

可以将不同位置的adapter、前缀或低秩更新组合，也可组合ICL与参数适配。统一视角论文§4.6的组合方法是一个研究实例，不是组合一定优于单一方法的定理。组合需要同时计算新增参数、上下文预算、激活与缓存开销；可合并的线性分支也不意味着任意非线性adapter都能直接合并。

如需判断LoRA是否带来收益，先保持示范、指令和校准不变，只替换适配器。若新版本同时改了三者，回退时也要逐项复原并重新评估。实验三的合并等价只检查线性代数一致，不检查适配后语言能力，也不等于测得更快的推理吞吐。

## 常见误区与失败诊断

这三种方法的故障落在不同位置：错标污染输入依据；零基线让后处理未定义；遗漏缩放改变有效权重。排查时先找第一个计算分岔，不要只看最终标签。恢复按钮用于保持当前参数、撤销单故障；完整重置还应恢复输入、选择、排列、缩放、游标和暂停状态。

<Callout type="trap" title="近邻示范越多越可信？">
  错标的近邻可能比远处正确示范更有影响。实验一直接翻转最近标签，在权重没变的情况下就能让投票极端化。检索分数不替代标签审计；真实系统还要防止查询或测试答案被混进示范池。
</Callout>

<Callout type="trap" title="选错方案：把校准当成任务学习">
  如果模型根本不懂任务，重新分配类别概率并不会产生缺失的能力。校准要求基线有代表性，且不能用测试标签反复选最有利基线。需要学习新任务时，应先改善示范或训练数据，再独立比较参数适配；不能用一个更好看的概率向量代替测试结果。
</Callout>

<Callout type="trap" title="缩放故障没改变答案，就算实现正确？">
  在α/r=1时，遗漏缩放确实不影响数值；在某个标签决策上，向量改变也可能没有跨过分类阈值。必须用多个α、秩和输入，检查中间向量与合并等价，而不是只跑一个无效故障案例。
</Callout>

## 5.4 小结

输入、后处理与权重是三种不同的状态位置。本章实验给出可逐项复算的最小例，但真实模型的收益仍需要冻结实验条件、报告方差，并在独立测试集上确认。

- ICL改输入条件，参数适配改持久权重。
- 示范的相关性、标签与顺序要分别控制。
- 校准重加权概率，零基线必须拒绝。
- LoRA先降维再升维，节省有尺寸条件。
- 混合方法的收益要靠单因素消融归因。
