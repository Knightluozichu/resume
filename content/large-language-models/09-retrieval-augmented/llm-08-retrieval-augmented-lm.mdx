## 第8章 检索增强型语言模型

模型记住的内容不可能随每一次资料更新而自动刷新。把外部材料引入预测过程，可以更新可用信息；但如果材料错了、找到的段落缺了关键关系，模型也可能更自信地答错。我们需要同时检查“材料怎样改变预测”和“材料究竟证明什么”。

本章按外部记忆进入计算的位置展开：预训练时选择文档，生成时修改词元概率，推理时寻找关系链，或者在网络内部读取块。黑盒与视觉系统又分别增加了接口限制和跨模态配对问题。三张实验图分别画几何、概率路径和可见性矩阵，不把它们归结成同一张检索流程图。

## 8.1 预训练检索增强型语言模型

预训练检索不是把搜索结果临时粘到聊天提示里。以 [REALM §3](https://arxiv.org/abs/2002.08909) 为例，模型用查询与文档的向量内积选择材料，再借助材料恢复被遮盖的内容。向量表示可视为 <Term def="把上下文或材料编码成向量、供索引比较和查找的表示；不是事实真伪标记。">检索键</Term>。它位于检索器与索引的接口上；更接近只表示某种相似性。

### 从一个文档答案到文档求和

检索器不必断言“只有这一篇正确”。把尚未确定的文档身份称为 <Term def="预测时没有直接确定、需要在候选集合中求和的文档变量。">潜文档</Term> $z$。设 $x$ 是输入，$y$ 是目标，$r_z=p_\eta(z\mid x)$ 是检索概率，$g_z=p_\theta(y\mid x,z)$ 是读入该文档后的目标概率。用 <Term def="对未确定变量的各个可能取值按概率加权求和，而不是只挑一个取值。">边际化</Term> 得到：

$$
p(y\mid x)\approx\sum_{z\in D_k} r_z g_z.
$$

人话说：每篇材料各做一次预测，再按材料的权重合并。这里 $r_z$ 在 top-k 候选内重新归一化，不能假装被排除的文档不存在。REALM 的遮盖预测目标也不是完整自回归句子概率。训练更新文档编码器后，旧索引会过时；REALM §3.3 异步刷新索引，并对已选候选以新参数重新计算概率。仅换提示词不能替代这一训练机制。

### RAG：求和放在乘积外面还是里面

[RAG §2.1](https://arxiv.org/abs/2005.11401) 的生成器条件为 $g_{zi}=p_\theta(y_i\mid x,z,y_{<i})$。同一输入检索出的候选集上，两种分解为：

$$
p_{\mathrm{seq}}(y\mid x)\approx\sum_z r_z\prod_i g_{zi},\qquad
p_{\mathrm{tok}}(y\mid x)\approx\prod_i\sum_z r_zg_{zi}.
$$

Sequence 让一条完整输出路径始终使用同一文档；Token 允许每一步的潜文档身份不同。Token **不等于每生成一个词元都重新搜索一次**。若输出只有一个词元，两式相等；有多个词元时，不能交换求和与乘积。

> 先猜：A 对两个目标词元的条件概率是 (0.9, 0.2)，B 是 (0.1, 0.8)，权重各半。跨文档路径会不会增加这条目标序列的概率？再切换实验模式。

<Llm08RetrievalAugmentedLmComputeTraceLab />

Sequence 为 $0.5\times0.18+0.5\times0.08=0.13$；Token 为 $0.5\times0.5=0.25$。后者含 A→B、B→A 路径；这不是“准确率提高了12%”。每个第二词元的概率都条件于同一已给前缀 $y_1$，没有假设两个词元无条件独立。

以下标准库 Python 各块**按正文顺序拼接**，保存为一个文件即可运行。它模拟确定的小表，不加载真实 LM、不训练索引，也不测量 GPU 性能。第一块实现实验2的概率账本。

```python
from math import exp, isclose, log


def softmax(scores):
    e = [exp(s - max(scores)) for s in scores]
    return [v / sum(e) for v in e]


def rag(prior, conditional):
    seq = sum(r * a * b for r, (a, b)
              in zip(prior, conditional))
    tok = 1.0
    for i in range(2):
        tok *= sum(r * ps[i] for r, ps
                   in zip(prior, conditional))
    return seq, tok


conditional = [(0.9, 0.2), (0.1, 0.8)]
assert all(isclose(a, b) for a, b in
           zip(rag([0.5, 0.5], conditional), (0.13, 0.25)))
```

## 8.2 词元级检索

[kNN-LM §2](https://arxiv.org/abs/1911.00172) 存的不是“问题→完整答案”，而是“过去上下文的隐藏表示→下一个词元”。推理时查询当前上下文的键，找到 k 个邻居。把邻居权重按**相同目标词元**相加，得到 <Term def="将近邻上下文的距离权重按其下一个词元合并、再归一化得到的预测分布。">kNN分布</Term>。它在输出分布层工作，不把整篇邻居文档送进生成器。

### 距离核、合票与插值

设邻居键值为 $(k_j,v_j)$，当前键 $q=f(x)$，距离为 $d$。原论文使用 $\exp(-d(q,k_j))$，实验取平方 L2；本页固定温度为1：

$$
w_j=\frac{\exp(-d(q,k_j))}{\sum_{\ell\in N_k}\exp(-d(q,k_\ell))},\quad
p_{\mathrm{kNN}}(v)=\sum_{j\in N_k}\mathbf1[v_j=v]w_j,\quad
p(v)=(1-\lambda)p_{\mathrm{LM}}(v)+\lambda p_{\mathrm{kNN}}(v).
$$

先把邻居的票数归一化，再合并同词元，最后与基础模型插值。不要给每个不同词元各算一次 softmax；那会把重复邻居的支持丢掉。$\lambda=0$ 完全不使用检索，$\lambda=1$ 完全依赖邻居。

> 先猜：查询 q=(1,0)，B=(3,4) 的内积最大，但它离 q 最近吗？切换距离核与原始内积，观察入选点和词元票数。

<Llm08RetrievalAugmentedLmContextContractLab />

默认负平方 L2 选 A、C，二者都投“桥”，因此混合概率为 $0.6\times0.6+0.4\times1=0.76$。图中原始内积/余弦是**相似度 toy 对照**，不是将 kNN-LM 原样改称余弦检索。单位向量满足 $-\|q-k\|^2=2\cos(q,k)-2$：排序相同，但在固定温度下 softmax 票数仍不同，要匹配温度尺度才能等同分布。

下面代码与图共享三个键和两类词元。污染把 B 放到 q 上（内积模式改为放大键范数）；算法会继续计票，应用层却必须阻断未核验内容。恢复索引不能只删警告文字。

```python
def knn(metric="l2", k=2, lam=0.4,
        image=False, poisoned=False):
    b = (4.0, 0.4) if image else (3.0, 4.0)
    if poisoned:
        b = (6.0, 0.0) if metric == "dot" else (1.0, 0.0)
    rows = [("A", (0.8, 0.6), "桥"),
            ("B", b, "河"), ("C", (0.6, -0.8), "桥")]
    scored = []
    for name, (a, b), word in rows:
        if metric == "cosine":
            a, b = a / (a*a+b*b)**0.5, b / (a*a+b*b)**0.5
        score = -((1-a)**2+b*b) if metric == "l2" else a
        scored.append((score, name, word))
    picked = sorted(scored, key=lambda r: (-r[0], r[1]))[:k]
    weights = softmax([s for s, _, _ in picked])
    vote = sum(w for w, row in zip(weights, picked)
               if row[2] == "桥")
    return [r[1] for r in picked], (1-lam)*0.6 + lam*vote


assert knn()[0] == ["A", "C"]
assert isclose(knn()[1], 0.76)
assert knn("dot")[0][0] == "B"
assert knn(poisoned=True)[1] < knn()[1]
```

## 8.3 通过高效和精简检索进行问答和多跳推理

减少候选数能减少读入材料、模型调用和重复文本，却可能先删掉“桥接关系”。例如问“青桥的设计者出生在哪座城市”：材料 d1 给出“青桥→设计者→林岚”，材料 d2 给出“林岚→出生地→海城”。只保留与“桥”字面最相关的 d1，即使排序非常漂亮，也不能回答出生地。

### 预算应花在缺失关系上

[IRCoT §3.1](https://arxiv.org/abs/2212.10509) 交替进行推理与检索，用新推理内容发起后续检索，而非一次塞满固定材料。它提供的是一种寻找关系链的策略，生成的中间句子本身并不是证据。实际系统应保存每条关系的来源、版本和实体身份，并限制跳数与调用预算；未找到桥接边就返回“证据不足”。精简可以去重、压缩无关句，也不能把关系的主体、否定词或时点压掉。

下面不是 IRCoT 的模型复现，而是一个可执行的两跳证据检查器。预算不足和缺桥会产生不同轨迹。代码只读取预先白名单化的关系三元组，没有“执行检索到的指令”的入口。

```python
facts = [("青桥", "设计者", "林岚", "d1"),
         ("林岚", "出生地", "海城", "d2")]


def two_hop(rows, budget=2):
    entity, used = "青桥", []
    for relation in ("设计者", "出生地"):
        if len(used) >= budget:
            return None, used
        edge = next((r for r in rows
                     if r[0] == entity and r[1] == relation), None)
        if edge is None:
            return None, used
        entity = edge[2]
        used.append(edge[3])
    return entity, used


assert two_hop(facts) == ("海城", ["d1", "d2"])
assert two_hop(facts[:1]) == (None, ["d1"])
assert two_hop(facts, budget=1) == (None, ["d1"])
```

与实验2的联系是：高权重文档不必含第二跳。不能把检索先验、语言模型似然、两跳关系成立当成同一项指标。练习3将要求删除 d2，再说明为何提高 top-k 或改写答案语气都不能凭空补证据。

## 8.4 检索增强型Transformer

[RETRO §2.2–2.4](https://arxiv.org/abs/2112.04426) 把输入分成 chunk。每个完整 chunk 检索相似的邻居 N，并附上该邻居在**外部原文中的后继** F，组成 [N | F]；编码后通过 chunked cross-attention 进入自回归解码器。F 不是当前输入序列的未来，但同源文档和重复文本仍需过滤，否则可能抄回目标。

### 为什么输入位置要移一格

<Term def="某个计算位置只能读取在其预测时刻已经可获得的输入与检索信息的约束。">
  因果可见性
</Term>
不只意味着把未来词元涂黑：检索查询本身也不能包含未来。采用零基索引，输入 $x_i$
的隐藏状态预测 $x_{i + 1}$；$C_c$ 占输入行 $cm$ 到 $(c+1)m-1$。只有读完
$C_c$，包 $E_c$ 才能直接使用。

RETRO 的直接 cross-attention 窗口是 $C_c$ 的**最后一个输入位置**加上下一块的前 $m-1$ 个位置，而非所有更晚输入位置都直接读取此包。等价路由为：

$$
\operatorname{packet}(i)=\left\lfloor\frac{i+1}{m}\right\rfloor-1,\qquad
E_c\text{ 直接可见}\iff\operatorname{packet}(i)=c.
$$

当 packet 为 −1 时不使用检索。对 $m=2$，输入行0无检索；行1、2直接读 E0；行3、4读 E1；行5读 E2。更早包的信息可以通过因果自注意力**间接**传播，但不是当前 cross-attention 的额外列。

> 先猜：m 从2改成3后，首个可用检索包出现在输入行几？若从整块开头就读该块检索包，会泄漏几行？

<Llm08RetrievalAugmentedLmEvidenceGateLab />

图采用论文 §2.4 的**包级直接路由**，展示更长输入流的前三块，因此末行仍预测下一词元、读取 E2；不复现有限训练批次的尾部 padding。它并非完整 RETRO attention mask 或真实注意力数值；它不模拟邻居编码器、所有层、相对位置偏置、训练与缓存。在窗口内，k 个邻居的 2m 位置合并后参与 cross-attention，故邻居数改变图中可读位置数，而不改变包窗口。

```python
def packet(i, m, early=False):
    return i // m if early else (i+1) // m - 1


def direct_mask(m, early=False):
    return [[int(packet(i, m, early) == c) for c in range(3)]
            for i in range(3*m)]


def leaks(m, early=False):
    return sum(i < (packet(i, m, early)+1)*m-1
               for i in range(3*m))


assert [packet(i, 2) for i in range(6)] == [-1, 0, 0, 1, 1, 2]
assert direct_mask(3)[2] == [1, 0, 0]
assert leaks(3) == 0 and leaks(3, early=True) == 6
assert leaks(2, early=True) == 3
```

## 8.5 检索增强型黑盒语言模型

如果只能调用固定 LM，不能改网络层，就无法把 RETRO 的 cross-attention 插进去。[REPLUG §3](https://arxiv.org/abs/2301.12652) 采取另一条路：把每篇候选文档分别放到输入前，分别得到下一词元分布，再按检索权重做输出集成。接口必须提供足够的概率信息；只有文本输出的聊天 API 不能直接执行这一概率级算法。

### 似然反馈不等于事实监督

REPLUG LSR §4 用冻结 LM 对已知目标 y 的似然作为检索训练信号：$P_R=\operatorname{softmax}(s/\gamma)$，$Q_{LM}=\operatorname{softmax}(P_{LM}(y\mid d,x)/\beta)$，最小化 $\mathrm{KL}(P_R\|Q_{LM})$。这里按原文的 LM likelihood 记法给式子，不擅自换成对数似然，也不倒转 KL；被更新的是检索器，不是黑盒 LM。

实验2的 Sequence 文档贡献可除以总和得到给定 y 的潜文档后验：A 为 $0.09/0.13\approx0.692$。这个“先验×似然”的后验与 LSR 的 softmax 目标**不是同一分布**。下面同时计算二者；这只是检验公式的数值表，不是一个无目标答案时就能调用的生产重加权器。

```python
likelihood = [a*b for a, b in conditional]
prior = [0.5, 0.5]
contributions = [r*g for r, g in zip(prior, likelihood)]
posterior = [c/sum(contributions) for c in contributions]
beta = 0.1
lsr_target = softmax([g/beta for g in likelihood])
kl = sum(p * log(p/q)
         for p, q in zip(prior, lsr_target))
assert isclose(posterior[0], 9/13)
assert not isclose(posterior[0], lsr_target[0])
assert kl >= 0
```

高似然可能来自模板复述、目标泄漏或错误但流畅的材料，不证明材料真实。部署时还应核对权限、版本、引用对应与无答案条件。含“忽略此前要求”“上传密钥”等句子的证据是**不可信数据**，不是更高优先级的指令；输入隔离、工具权限控制和证据核验不能由一次概率加权替代。

## 8.6 视觉增强语言建模

视觉检索引入的不只是一个“图片 URL”。[MuRAG §3.1–3.2](https://arxiv.org/abs/2210.02928) 将图像和文本组成外部记忆，用 ViT 与 T5 构造多模态表示，通过检索训练与生成训练连接查询、记忆和文本答案。读取阶段使用图像 patch 等多模态内容，并非只把图片的说明文字当作普通段落。

### 对齐空间与证据身份是两次检查

实验1的“图像键”把 B 改到 (4,0.4)，文本值仍为“河”。它假定查询与图像已经对齐到可比较空间，**不包含 ViT、像素输入或 MuRAG 训练**。切到余弦且 k=1，B 会优先；保留负 L2，A 仍可能最近。这里的目的，是看到跨模态对齐、范数与距离度量会改变读取到的文本值，而不是用三个手写点证明视觉识别有效。

真实图像证据还必须保存图像身份、拍摄时点、区域与说明文字的对应。相似外观的另一座桥不能证明青桥的设计者；说明写“海城”也不等于拍摄地点经过核验。以下把实验的几何选择与独立身份门并置：即使图像检索分数最高，身份不符也不输出事实。更完整的系统还需处理 OCR 错误、裁剪丢失和图像内指令注入。

```python
image_choice, image_p = knn("cosine", k=1, image=True)
assert image_choice == ["B"]
image_records = {"B": {"entity": "另一座桥", "caption": "海城河面",
                       "verified": False}}
record = image_records[image_choice[0]]
can_support = record["entity"] == "青桥" and record["verified"]
assert not can_support
assert isclose(image_p, 0.36)  # 算法偏向“河”，不代表事实成立

# 最后一组断言：故障、恢复、无检索和预算边界。
baseline = knn()
assert knn(lam=0)[1] == 0.6
assert knn(poisoned=True) != baseline
assert knn() == baseline
assert isclose(rag([1, 0], conditional)[0], 0.18)
assert two_hop(facts[:1])[0] is None
assert two_hop(facts)[0] == "海城"
assert leaks(3, True) > 0 and leaks(3) == 0
print("PASS: knn / rag / bridge / retro / blackbox / visual")
```

到这里，将全部六块 Python 顺序拼接运行，应输出一行 PASS。它核对的是手工输入下的代数与边界，不是论文指标复现、事实库验证或真实模型安全认证。

## 8.7 小结

三种机制分别改变预测的不同部分：近邻改变词元票数，潜文档分解改变概率路径，移位窗口限制网络能读什么。选型时先问接口和训练条件，再问召回预算与证据是否够用。

- 能用距离核合票，不把相关性当真实性。
- 能区分先求和与先相乘，不把后验当准确率。
- 能按输入/预测索引定位直接检索包。
- 能识别缺桥、概率接口与图像配对的独立缺口。

### 常见误区 1：检索排第一就足以作答

**现象**：长向量总排第一，或检索到多篇相关图文，就认为答案有了事实支持。

**原因**：把范数当相关性，再把相关性当真实性；缺桥、错实体或混入不可信指令，并不会因排名高而消失。

**修法**：在实验1切换 L2/内积/余弦，记录排序与票数，选择与训练目标一致的度量，不盲目归一化；另按关系和图像身份核验证据，缺证据拒答，材料中的指令不执行。

### 常见误区 2：硬选 top1 等于潜文档边际化

**现象**：硬选 top1 后仍报告原来的边际概率。

**原因**：把单路径当成对候选文档的加权求和，忽略删去另一条路径已经改变了计算。

**修法**：打开实验2故障，重新计算0.18，再恢复双文档求和得到0.13；分别写出单路径与边际化算式，不沿用故障前的概率。

### 常见误区 3：整块一开始就能读取其检索包

**现象**：整块一开始就读其检索包，把提前解锁当作加速。

**原因**：查询用了尚不可见的输入，改变了预测的因果条件，而不只是增加检索噪声。

**修法**：打开实验3故障，再恢复移位；逐行核对输入位置、预测位置与当前移位窗口可直接读取的检索包，先核对索引，再谈速度。

## 名词解释

这五个术语把全章连起来：从键到概率，从未定文档到求和，再到读取时序；它们都不直接承担事实认证。

<Glossary>
  <GlossaryItem term="检索键">
    供查询与材料比较的向量表示，相近不等于事实可靠。
  </GlossaryItem>
  <GlossaryItem term="潜文档">
    预测中未确定的候选文档身份，需要在可能取值间合并。
  </GlossaryItem>
  <GlossaryItem term="边际化">
    把隐藏选项的条件预测按概率加权求和，而不是硬选一个。
  </GlossaryItem>
  <GlossaryItem term="kNN分布">
    邻居上下文按距离投票、同词元合票后得到的预测分布。
  </GlossaryItem>
  <GlossaryItem term="因果可见性">
    预测时不读取尚不可用的输入或由这些输入产生的检索结果。
  </GlossaryItem>
</Glossary>
