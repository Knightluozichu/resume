## 第12章 环境影响

同样是训练一个模型，为什么两份碳排放报告能相差很多？原因未必是谁乘错了数：一份可能只算加速器，另一份还包括主机、机房和硬件制造；也可能同样的电量来自不同时间的电网。必须先对齐“算什么”，再比较“多少”。本章把一个环境账本分成三层：**功率随时间累积成电量，电量随时空加权成排放，共享排放按明确分母分摊。**

这里的<Term def="在一段时间内消耗的能量；电力计算通常用千瓦时，不能把瓦数直接叫作电量。">能耗</Term>使用电量单位 kWh。1 kW 的设备运行 1 h 消耗 1 kWh；功率 W 描述消耗的快慢，不是已经消耗的总量。阅读本章只需要加权求和与单位换算，前章模型结构知识不是计算的前提。

<Term def="一次核算明确包含和排除的设备、阶段、时间与共享份额；边界不同，数字不能直接比较。">
  系统边界
</Term>
是账本的第一行。例如“训练任务的设备与主机 IT
电量”不等于“整个数据中心的总用电”，更不等于“模型全生命周期环境影响”。训练试错、最终训练、部署推理、硬件制造、运输与报废是否纳入，必须分别声明。全章的数字均为虚构教学输入，浏览器只做计算模拟，**没有运行模型，也没有测量本机
GPU 能耗**。

### 三层账本的单位

| 层次         | 输入                 | 运算后输出 | 不能省略的边界                     |
| ------------ | -------------------- | ---------- | ---------------------------------- |
| 时间积分     | W、h、设备数量       | kWh        | 主机是否计入、采样是否覆盖全过程   |
| 电网加权     | kWh、gCO₂e/kWh       | kgCO₂e     | 时段、区域、机房开销、排放因子口径 |
| 生命周期分摊 | kgCO₂e、小时、请求数 | gCO₂e/次   | 共享训练与制造份额、同质服务分母   |

CO₂e 是把多种温室气体按所选全球变暖潜势口径换成二氧化碳当量，不只是 CO₂。比较外部报告还要核对其排放因子的年份、温室气体范围及所用时间尺度；单位相同不保证口径相同。

## 12.1 能源消耗和温室气体排放

先把电量算对。一次训练中，设备在计算、等待通信、写检查点时可能有不同功率；峰值乘总时长会抹掉这些阶段。相反，只测一段低功率再外推全程也可能低估。设备数量、每台设备实际功率、持续时间和主机消耗共同决定电量，参数量本身并不是电量计。

### 把时间画成宽度，把功率画成高度

设第 $i$ 段持续 $\Delta t_i$ 小时，有 $n$ 台加速器，每台功率为 $P_i$ W，主机合计为 $H_i$ W。假设每段内部功率恒定，则

$$
E_{\mathrm{IT}}=\frac{1}{1000}\sum_i(nP_i+H_i)\Delta t_i.
$$

每项就是一个矩形的面积，除以 1000 把 Wh 换成 kWh。若功率持续变化，这是分段近似；应报告采样间隔、缺失样本、仪表覆盖和误差。Strubell 等在 2019 年论文 §2 把 GPU、CPU、DRAM 与训练时长结合，并采样功率；这里保留这种分项思想，但**不把其历史平均 PUE 或美国电网因子当作今天所有任务的常数**。[S1]

> 先预测：第二段持续时间是第一段的两倍。如果采样器把后两段都误报成第一段功率，矩形高度会怎样，电量会变高还是变低？然后切换“平稳轨迹”，检查故障是否仍然产生数值差异。

<Llm12EnvironmentalImpactContextContractLab />

默认总功率为 500、900、300 W，持续 0.25、0.50、0.25 h，电量为 0.125 + 0.450 + 0.075 = **0.650 kWh**。只算加速器是 0.550 kWh，漏掉主机则少 0.100 kWh。重复首样本会报告 0.500 kWh；虚线保留正确轨迹，便于定位第二段第一次偏离。平稳轨迹下三个功率相同，这个故障暂时“不露馅”，但采样器仍未正常工作——单一测试通过不代表没有缺陷。

下面开始一份连续 Python 程序；将本章六个 `python` 块按顺序拼接即可用 Python 3 标准库运行。第一块只计算 IT 边界，明确 W 与 h 的输入单位，用 `isclose` 避免浮点直接相等。

```python
from math import isclose

durations_h = (0.25, 0.50, 0.25)
accelerator_w = (200, 400, 100)
devices, host_w = 2, 100

def energy_kwh(power_w, hours):
    assert len(power_w) == len(hours)
    assert all(p >= 0 for p in power_w)
    assert all(h > 0 for h in hours)
    return sum(p * h for p, h in zip(power_w, hours)) / 1000

it_w = tuple(devices * p + host_w for p in accelerator_w)
it_kwh = energy_kwh(it_w, durations_h)
assert isclose(it_kwh, 0.650)
assert isclose(energy_kwh((500, 500, 500), durations_h), 0.500)
print("IT kWh:", round(it_kwh, 3))
```

### 为什么电量相同，排放可以不同

<Term def="每单位电量所归属的温室气体排放量，必须注明区域、时间和平均或边际等核算口径。">
  碳强度
</Term>
把电量转换为排放。例如 500 gCO₂e/kWh 表示每消耗 1 kWh 归属 500
gCO₂e。平均碳强度用于把已有电网排放分配给用电者；边际因子关注新增或减少这部分用电时哪些发电响应，两者不等价。不能只凭平均强度较低，就声称跨区迁移必然带来相同的实际减排。

<Term def="Power Usage Effectiveness，设施总用电与 IT 设备用电的比值；1.2 表示每 1 kWh IT 电量对应 1.2 kWh 设施电量。">
  PUE
</Term>
描述机房电力开销。若 IT 电量为 0.6 kWh、PUE 为 1.2，则设施电量为 0.72 kWh，其中
0.12 kWh 是制冷、供配电等开销。PUE 不替代电网碳强度，也不能自动补全所有未采样的
IT 空闲功率。若墙表已覆盖相同设施总边界，再乘 PUE 会重复计算。[S2, S3]

### 先做测量计划，再谈优化

真实工作中应同步采集时间戳、设备/主机功率、训练阶段、作业共享比例和设施计量范围；由硬件计数器推算的值、插座表测值和标称 TDP 分开列示。TDP 是设计与散热相关指标，不是本次任务的功率记录。低精度、批处理、硬件利用率或更快完成可能改变能耗，但必须同时测功率与时长，且固定任务质量；更高瞬时功率未必消耗更多总电量。

BLOOM 论文 §4.2 在缺少实时功率记录时用了 TDP 代理，§4.3 另讨论空闲和基础设施消耗，§4.1 估计制造排放。[S3] 这些部分的假设和数据可得性不同，不能把它们合称“全都直接实测”。环境影响还包括水资源、材料与电子废物，本章的电碳算例不提供这些维度的结论。

## 12.2 估算训练模型的排放量

训练排放估算不是一个孤立乘法，而是逐时段对齐边界的过程：先取 IT 电量，再补足同一时段的设施开销，最后用该时空单元的排放因子加权。训练结束后，还要另算模型开发试验与服务运行；若报告制造份额，不能把它混进用电因子里又加一次。本节先演算运行排放，再扩展为共享生命周期账本。

### 逐格加权，不能随意换成简单平均

设 IT 电量为 $E_i$ kWh，设施系数为 $u_i$，平均电网碳强度为 $g_{r,i}$ gCO₂e/kWh，区域为 $r$，则

$$
C_{\mathrm{op}}=\frac{1}{1000}\sum_i E_i u_i g_{r,i}\quad\text{kgCO₂e}.
$$

若机房开销跨时段或区域，需要匹配其实际因子；这里假设它与 IT 电量同地同时发生。Patterson 等 §2.3–2.5 将设施效率与能源供应分别讨论，并给出训练电量和排放的简化公式。[S2] 其特定公司的净碳核算不能直接替代本章使用的平均电网口径，也不能把旧年份区域值视为当前数据。

> 先预测：甲区晚段的碳强度较低，移到晚段后 IT 电量是否改变？再将 PUE 从 1.2 改成 1.5。观察“选位置”和“补机房开销”分别改了哪一项，最后注入漏乘故障。

<Llm12EnvironmentalImpactComputeTraceLab />

这个实验使用**独立于实验一的任务**：两个时段分别消耗 0.2 和 0.4 kWh，总计 0.6 kWh。甲区早段为 600、500 g/kWh；按 PUE 1.2 得到 0.24 × 600 / 1000 + 0.48 × 500 / 1000 = **0.384 kgCO₂e**。移到甲区晚段 200、100 后为 **0.096 kgCO₂e**，并不是电量减少了。格子的深浅是强度，下划线表示被任务占用的时段，条带区分 IT 与设施额外用电。

第二块实现同样的时空索引，长度和非负性检查先于乘法。错误路径只漏乘 PUE，其他输入不变，才能定位差异。

```python
intensity = {"A": (600, 500, 200, 100), "B": (300, 250, 250, 300)}
task_it = (0.2, 0.4)

def operational_kg(energy, ci, pue):
    assert len(energy) == len(ci)
    assert pue >= 1 and all(e >= 0 for e in energy)
    assert all(g >= 0 for g in ci)
    return sum(e * pue * g for e, g in zip(energy, ci)) / 1000

early = operational_kg(task_it, intensity["A"][:2], 1.2)
late = operational_kg(task_it, intensity["A"][2:], 1.2)
missing_pue = operational_kg(task_it, intensity["A"][:2], 1)
assert isclose(early, 0.384) and isclose(late, 0.096)
assert isclose(missing_pue, 0.320)
print("early/late kg:", early, late)
```

第三块直接检查简单平均的陷阱。时长或电量不同，必须按电量权重；采用未加权的 550 g/kWh 会把这个任务高估为 0.396 kg。这里没有利用电网调度模型，因而不推断电力系统的因果变化。

```python
facility = tuple(e * 1.2 for e in task_it)
ci = intensity["A"][:2]
weighted_ci = sum(e * g for e, g in zip(facility, ci)) / sum(facility)
unweighted_kg = sum(facility) * (sum(ci) / len(ci)) / 1000
assert isclose(weighted_ci, 533.3333333333334)
assert isclose(unweighted_kg, 0.396)
assert not isclose(unweighted_kg, early)
```

### 把共享训练与制造放入同一本账

<Term def="用来比较环境代价的一份明确服务，例如满足相同质量和长度约束的一次请求；它决定分摊账本的分母。">
  功能单位
</Term>
回答“为了得到什么服务付出代价”。每次请求、每百万输出
token、每个达到质量阈值的完成任务都可作为单位，但不能混用。短回答与长回答、低质量与合格答案的“每次”并不天然可比。

设共享训练排放为 $T$ kgCO₂e，同质请求数为 $Q$，每次运行排放为 $c$ kgCO₂e；硬件制造总额为 $M$ kgCO₂e，服务占用 $h$ 小时，硬件可分摊的总使用寿命为 $L$ 小时。采用按使用时间直线分摊，得到

$$
C_{\mathrm{total}}=T+Qc+M\frac{h}{L},\qquad
C_{\mathrm{per}}=\frac{C_{\mathrm{total}}}{Q}.
$$

这是一种显式分配规则，不是唯一规则。共享设备还需约定占用比例；若寿命按日历年给出，需要利用率等假设才能转成可分摊使用小时。制造排放（embodied emissions）已发生于供应链，不是训练用电排放。BLOOM §4.1 也按时间分摊制造，并说明设备数据代理和未覆盖的基础设施，不能当作精确完整的生命周期清单。[S3]

> 先预测：请求数从一千增为一万，单次分摊会下降，服务总排放一定下降吗？取消制造项是“减排”，还是仅缩小报告边界？注入重复共享账故障，检验“每次 × 次数 = 总账”。

<Llm12EnvironmentalImpactEvidenceGateLab />

默认制造份额是 1000 × 100 / 10000 = 10 kg。加上训练 20 kg、运行 2 kg，总计 **32 kg**，除以一千次是 **32 g/次**。硬件条带按真实比例画出 100 h 小切片，下方明确标记放大倍率，不把 1% 画成半个寿命。故障把 30 kg 的共享项每次都收全额，得到 **30.002 kg/次**，不再能还原 32 kg 总账。

第四块将“是否纳入制造”作为边界参数；不纳入时不能据此宣称制造排放为零。这里 $c$ 已经包含设施和电网换算，不能再乘一次 PUE。

```python
def lifecycle(requests, life_h, include_embodied=True):
    assert requests > 0 and life_h >= 100
    training_kg, use_h, hardware_kg = 20.0, 100, 1000.0
    running_kg = requests * 0.002
    embodied_kg = hardware_kg * use_h / life_h if include_embodied else 0.0
    total_kg = training_kg + running_kg + embodied_kg
    return total_kg, total_kg / requests

total, per = lifecycle(1000, 10000)
assert isclose(total, 32) and isclose(per, 0.032)
assert isclose(per * 1000, total)
wrong_per = 20 + 0.002 + 10
assert isclose(wrong_per, 30.002)
assert not isclose(wrong_per * 1000, total)
```

第五块比较两种常见“变好”。请求更多使共享份额摊薄，但运行排放增加；延长假设寿命降低本服务分配到的制造份额，不代表制造活动已经减少。若延长寿命牺牲运行能效，必须另算，不能只看分母。

```python
more_total, more_per = lifecycle(10000, 10000)
long_total, long_per = lifecycle(1000, 20000)
operational_total, _ = lifecycle(1000, 10000, False)
assert isclose(more_total, 50) and isclose(more_per, 0.005)
assert more_total > total and more_per < per
assert isclose(long_total, 27) and isclose(long_per, 0.027)
assert isclose(operational_total, 22)
print("total kg / g per request:", total, per * 1000)
```

### 不确定性必须随结果交付

报告应说明采样漏点、估计功率、平均碳因子、PUE 适用时段、制造代理和寿命假设。如果假设 IT 电量误差为 ±10%，碳强度误差为 ±20%，并固定 PUE，本例早段排放的保守端点为 0.384 × 0.9 × 0.8 与 0.384 × 1.1 × 1.2。它们是输入范围的乘积包络，**不是统计置信区间**，也没有覆盖未知系统边界。

第六块完成敏感性检查。代码没有调用云 API、读取 GPU，也没有把模拟计时冒充测量。实际报告还要保存仪表、数据源版本和时区，使别人能按相同边界复算。

```python
low = early * 0.9 * 0.8
high = early * 1.1 * 1.2
assert isclose(low, 0.27648) and isclose(high, 0.50688)
assert low <= early <= high
print("assumption envelope kg:", round(low, 5), round(high, 5))
print("all environmental accounting assertions passed")
```

### 误区一：模型参数越多，能耗就按比例越大

**现象：** 用参数数量给两个训练任务排序。**原因：** 忽略训练 token 数、精度、稀疏激活、硬件、利用率与时长。**修法：** 固定质量目标和任务，记录功率轨迹与运行时间，以积分电量比较；不从本章玩具图推断真实 GPU 速度。

### 误区二：低碳电网或低 PUE 就等于零环境代价

**现象：** 选低强度区域后宣称“零排放”，或墙表结果再乘 PUE。**原因：** 混淆电网因子、机房开销与制造边界。**修法：** 分项列出电量、时空因子、设施范围和制造份额；以实验二的故障核对是否漏算或重算。

### 误区三：单次指标下降，服务总排放也必然下降

**现象：** 扩大请求量后只报告更低的 g/次。**原因：** 把共享项摊薄误认为总量减少。**修法：** 同报总量和功能单位值，并核对质量及输出长度；实验三万次请求为 5 g/次，却有 50 kg 总量，高于默认 32 kg。

## 12.3 小结

环境报告的可信度首先来自可复算的边界，而不是小数位数。先拿到功率与时间，再把电量对齐到设施和时空因子，最后明确共享训练与制造的分摊方法；三个层次不可跳接。能耗优化、排放归因降低、生命周期分配变化是三件事，应分别报告。

- 电量是功率的时间积分，不由参数量单独决定。
- PUE 补设施边界，碳强度补时空权重。
- 共享项只计一次，功能单位必须同质。
- 同时报告总量、单次值、假设与未知项。

**问题 2**：把实验二改为乙区早段、PUE 1.5。正确结果与漏乘结果各是多少？若给你的是设施总表读出的 0.30 和 0.60 kWh，还要乘 PUE 吗？

<Answer>
  正确为 (0.2 × 1.5 × 300 + 0.4 × 1.5 × 250) / 1000 = 0.240 kg，漏乘为 0.160
  kg。若 0.30、0.60 已是相同范围的设施电量，直接加权得到 0.240 kg，不再乘
  PUE。改变区域、时段或因子口径必须重新声明；不能将这次归因差值直接叫作边际减排量。
</Answer>

**问题 3**：实验三保持制造纳入、硬件寿命 10000 h，把请求数改为 10000。用“总量—单次—守恒”三项解释变化。再将寿命改成 20000 h，能否据此宣称工厂少排放了 5 kg？

<Answer>
  总账为 20 + 10000 × 0.002 + 10 = 50 kg，单次 0.005 kg = 5 g；5 g × 10000 = 50
  kg，守恒。总量比默认增加 18 kg，单次却下降。寿命 20000 h 时制造份额为 5
  kg，总账 45 kg、单次 4.5 g；这只是本服务分配到的制造份额减少 5
  kg，制造总额假设仍为 1000 kg，不能声称工厂实际少排放。
</Answer>

</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="能耗">
    一段时间消耗的能量；电力账本以 kWh 表示，是功率随时间的累积。
  </GlossaryItem>
  <GlossaryItem term="系统边界">
    账本纳入和排除的设备、阶段、时间与共享份额；比较前必须对齐。
  </GlossaryItem>
  <GlossaryItem term="碳强度">
    每 kWh 所归属的温室气体排放量，附带区域、时段与平均或边际口径。
  </GlossaryItem>
  <GlossaryItem term="PUE">
    设施总电量除以 IT 电量；不能对已含设施开销的电量重复使用。
  </GlossaryItem>
  <GlossaryItem term="功能单位">
    一份明确、同质的服务，用作环境代价的比较和分摊分母。
  </GlossaryItem>
</Glossary>
