## 为什么总复习要重新算一遍

一份回答同时可能“更像人写的”“更受评价者喜欢”“引用更多”“占用更少内存”。这些并不是同一件事。如果只留一个总分，出了问题就不知道该改输入材料、计算方式，还是评价方法。

本页把前面各章接成三次可检查的计算：先看一个输入如何变成输出概率，再比较材料权重与偏好目标，最后看请求如何占用内存。每次只改变一类条件，让结果自己说明差别。

这是**本站综合复习，不是原书新增正式章**。14个主题是前言、12章、参考文献；153是详细目录坐标数，不能拿它当作153项能力已验证。原书为熊涛著中文原创《大语言模型：基础与前沿》，人民邮电出版社/异步图书，2024-04，ISBN 9787115634887。我们只访问了元数据与目录，未读原书正文；260纸本页仅由豆瓣记录支持，馆藏本轮不证明页数。得到83个浅层条目与豆瓣139个编号节、12个章标题及首尾两项交叉核对。以下机制来自独立研究阅读，不冒充作者的整书总结。

## 表示、计算与学习：先找变化发生在哪里

这一组把前言和第1至5章连起来：先决定要验证的主张，再固定输入表示，最后区分预测计算、训练更新和提示条件。实验1只计算一个注意力头；完整模型的更多结构应回到各章展开，而不是在总复习里偷偷省略后称为真实模型。

### 前言

复习起点不是选“最强模型”，而是把问题说清楚：要预测后续文本、检索一条事实、遵循一组偏好，还是把成本限制在预算内？把相同输入交给不同系统时，还要记录词表、模板、上下文和模型版本。练习1固定这些条件后改变掩码，才能把输出变化归因到计算，而非换了输入。

### 第1章 大语言模型：辩论、争议与未来发展方向

[第1章](/learn/large-language-models/02-debates-future/llm-01-debates-future)区分行为表现与解释它的理论。实验1能证明这组手工向量在某个掩码下得到某个概率，不能由此推断理解、意识或全面泛化。可迁移的检查是“变换条件后预测是否仍成立”：例如把合并词元拆开，再重新计算，而不是凭一条顺眼回答下结论。

### 第2章 语言模型和分词

对既定上下文分配后续词元的概率，称为 <Term def="固定已经给出的条件后，各种后续取值获得的概率；总和为1，但不等于事实正确率。">条件分布</Term>。同一字符串 abc 可以被我们的手工词表分成 [ab,c] 或 [a,b,c]。这不是实际 BPE 合并算法，但保留了[第2章](/learn/large-language-models/03-language-tokenization/llm-02-language-modeling-tokenization)的接口问题：分词一变，序列长度、嵌入查表和注意力矩阵形状都变。

跨词表比较困惑度时，分母是词元数，不能把每词元损失直接当成同一尺度。下面从标准库开始；**本页所有 Python 块按顺序拼接，就是一个可独立运行的程序**。无需模型、网络、第三方库或 GPU。

```python
import math


def softmax(xs):
    es = [math.exp(x - max(xs)) for x in xs]
    return [e / sum(es) for e in es]


def kl(p, q):
    return sum(a * math.log(a / b) for a, b in zip(p, q) if a)


emb = {"a": [1, 0], "b": [0, 1], "ab": [1, 1], "c": [1, -1]}
assert math.isclose(sum(softmax([1, 0, 0])), 1)
```

### 第3章 Transformer

[原论文 §3.1、§3.2.1、§3.2.3](https://arxiv.org/abs/1706.03762)给出缩放点积及解码器可见性限制。限制当前位置不能读未来输入的规则称为 <Term def="在预测计算中屏蔽尚未到达的位置，使输出只能依赖允许的输入前缀。">因果掩码</Term>。此处输入位置 i 用已见的 0…i 预测下一词元，因此允许 j≤i；它不等同于把对角线也遮住。

符号：x 为二维嵌入，i 为查询行，j 为键列，a 为注意力权重，h 为加权结果，T 为输出温度。实验取 Q=K=V=X、头宽2，并手工指定输出投影；这不是训练出的 Transformer，缺少位置编码、残差、归一化与前馈网络。

$$
s_{ij}=x_i\cdot x_j/\sqrt{2},\quad
 a_{ij}=\frac{\exp(s_{ij})}{\sum_{t\le i}\exp(s_{it})}\;(j\le i),\quad
 h_i=\sum_{j\le i}a_{ij}x_j.
$$

人话说：先比较向量，再只对允许读取的列分票，最后合成一个向量。输出词表为甲、乙、EOS，概率是 softmax([h₀,h₁,0]/T)，**不是**矩阵里的注意力权重。先预测：在行0打开未来列后，哪些数字会先变？

<LlmOfficialFinalReviewContextContractLab />

代码把掩码放在归一化之前。故障去掉限制后，查询行0也会读取后面的向量。输出温度只作用于最终 logits，不应改变注意力矩阵。

```python
def chain(tokens, row=0, temperature=1, leak=False):
    xs = [emb[t] for t in tokens]
    keys = list(range(len(xs))) if leak else list(range(row + 1))
    scores = [sum(a * b for a, b in zip(xs[row], xs[j])) / math.sqrt(2)
              for j in keys]
    weights = softmax(scores)
    h = [sum(w * xs[j][d] for w, j in zip(weights, keys)) for d in range(2)]
    out = softmax([h[0] / temperature, h[1] / temperature, 0])
    return weights, h, out


base = chain(["ab", "c"])
broken = chain(["ab", "c"], leak=True)
assert base[0] == [1.0] and base[1] == [1.0, 1.0]
assert broken[0][1] > 0 and broken[1] != base[1]
assert chain(["ab", "c"], temperature=2)[0] == base[0]
assert chain(["a", "b", "c"])[1] == [1.0, 0.0]
assert chain(["ab", "c"]) == base  # 撤销故障，完整基线恢复
```

### 第4章 预训练目标和解码策略

[第4章](/learn/large-language-models/05-pretraining-decoding/llm-04-pretraining-decoding)中，因果语言建模以已见前缀预测后续词元；遮盖重建的可见条件不同，不能直接沿用同一个泄漏判断。交叉熵 −log p(目标词元) 是训练目标；温度、top-k 与核采样则改变输出选择。实验1提高 T 会压平输出分布，却不会替模型重新学知识。练习1要求同时读出权重与概率，正是为了不把解码设置误认为训练更新。

### 第5章 上下文学习和轻量级微调

[第5章](/learn/large-language-models/06-icl-finetuning/llm-05-icl-lightweight-finetuning)的示例排序通过输入条件影响预测；参数不变也能改变注意力。低秩适配则通过 ΔW=BA 改变参数：若 W 为4×4、秩1，只需4+4=8个因子参数，而非16个完整增量。实验1改分词是前一种“改变输入接口”的教学近似，不是一次 LoRA 更新；练习1的解释必须说出修改发生在哪一层，不能只写“模型变聪明”。

## 规模与条件计算：少算与少存不是一回事

第6、7章把单层计算扩成训练与部署系统。总参数量、激活参数量、每设备状态、专家负载各有不同分母。实验3随后只算一组固定参数和 KV 存储，不能把它的容量结果外推成训练成本或 MoE 加速比。

### 第6章 训练更大的模型

[第6章](/learn/large-language-models/07-training-scale/llm-06-training-larger-models)的训练预算常用近似 C≈6ND，其中 N 为参数量、D 为训练词元数；系数和适用架构必须声明。这不是推理每词元耗电公式。数据并行复制模型状态，张量并行切分部分矩阵，流水线并行拆层，通信和空泡又引入额外限制。实验3的并发数2表示同设备同时服务两个请求，**不是**把模型拆到两张卡上。

### 第7章 稀疏专家模型

[第7章](/learn/large-language-models/08-sparse-moe/llm-07-sparse-moe)的路由先决定每个词元送往哪些专家，再处理容量冲突。若4个词元全选同一专家而容量为2，top-1并不能保证全部被处理；重路由、丢弃或溢出是不同策略。MoE 可以减少每词元激活的专家计算，但不能据此删去所有未激活专家的驻留权重。练习3要求指出实验3尚未包含专家权重和通信的哪些账目。

下面用最小容量计数让这两种分母可执行：训练计算预算随 D 变化，而路由是否接纳取决于逐专家计数，不由总参数量决定。

```python
train_flops = 6 * 1000 * 2000  # 手工设定N、D，不是实测
assert train_flops == 12_000_000
routes, expert_capacity = [0, 0, 0, 0], 2
loads, accepted = [0, 0], []
for expert in routes:
    admitted = loads[expert] < expert_capacity
    accepted.append(admitted)
    if admitted:
        loads[expert] += 1
assert accepted == [True, True, False, False]
assert loads == [2, 0]
```

## 材料、偏好与风险：不要把目标互相替代

第8至11章改变系统能读到什么、偏向什么，以及我们怎样评价这些改变。实验2有意把检索概率与偏好目标分开：同一个回答可以有较高生成概率，却在给定偏好下得分较低；两者都不能单独证明事实成立。

### 第8章 检索增强型语言模型

检索引入尚未确定的材料身份；这种需要按可能取值求和的变量称为 <Term def="没有直接观测或固定、需要在候选取值上求和的变量；本页指候选文档身份。">潜变量</Term>。按 [RAG §2.1](https://arxiv.org/abs/2005.11401)，给定候选文档后先分别预测，再用检索权重合并。实验2只有单个回答变量，不模拟 RAG-Token 与 RAG-Sequence 的完整序列分解，更不复现 RETRO 的块移位窗口。

设两篇文档对回答 A 的概率为 .9、.2，文档0先验为 α，则 p(A)=.9α+.2(1−α)。α=.5时得到.55；α=.8时得到.76。这只是候选内概率，并非事实支持分数。向量邻居票数、多跳缺桥和黑盒候选重加权的不同接口，应回到[第8章](/learn/large-language-models/09-retrieval-augmented/llm-08-retrieval-augmented-lm)核对。

```python
def rag(alpha):
    return [0.9 * alpha + 0.2 * (1 - alpha),
            0.1 * alpha + 0.8 * (1 - alpha)]


assert math.isclose(rag(0.5)[0], 0.55)
assert math.isclose(rag(0.8)[0], 0.76)
assert math.isclose(sum(rag(0.8)), 1)
```

### 第9章 对齐语言模型与人类偏好

偏好优化与“多取一篇材料”不同。作为偏离惩罚基准的固定分布，称为 <Term def="优化时保持固定、用来计算策略偏移惩罚的基准分布；不等于奖励模型或事实真值。">参考策略</Term>。本页固定它为 [.5,.5]，**不使用上面的 RAG 分布充当参考**。[InstructGPT §3.1、§3.5](https://arxiv.org/abs/2203.02155)分别描述示范、偏好比较、强化学习与 KL 惩罚；下面只求有限两动作问题的精确解，不执行 PPO，也不包含其预训练混合项。

符号：π 为待选策略，r 为手工奖励，β>0 为惩罚系数，πref 为固定参考。我们比较的是：

$$
J(\pi)=\sum_y\pi(y)r(y)-\beta\,\mathrm{KL}(\pi\Vert\pi_{\mathrm{ref}}),\qquad
\pi^*(y)=\frac{\pi_{\mathrm{ref}}(y)e^{r(y)/\beta}}{\sum_v\pi_{\mathrm{ref}}(v)e^{r(v)/\beta}}.
$$

人话说：奖励鼓励偏向，KL 惩罚拉回基准。对归一化约束引入乘子，J 对 π(y) 的导数为 r(y)−β(log(π(y)/πref(y))+1) 再减同一常数，令其为0并归一化便得到右式。默认 r=[0,1]、β=1，因此 π\*(A)=1/(1+e)≈.269；即使检索给 A 的概率是.55，也不会强迫偏好策略选 A。

先预测：提高文档0先验，下面的目标曲线会移动吗？再打开“似然冒充奖励”，观察两个分支中哪个先发生变化。

<LlmOfficialFinalReviewComputeTraceLab />

游标只是扫描五个候选策略，虚线单独标出精确最优值。故障把文档0的回答似然 [.9,.1] 误当成奖励；检索不变，优化问题却已经换了。

```python
ref = [0.5, 0.5]


def optimum(reward, beta=1):
    return softmax([math.log(q) + r / beta for q, r in zip(ref, reward)])


def objective(p, reward, beta=1):
    return sum(a * r for a, r in zip(p, reward)) - beta * kl(p, ref)


star = optimum([0, 1])
assert math.isclose(star[0], 1 / (1 + math.e))
assert objective(star, [0, 1]) > objective(ref, [0, 1])
assert optimum([0.9, 0.1])[0] > 0.5  # 似然冒充奖励的故障
assert optimum([0, 1]) == star       # 恢复独立奖励
assert optimum([0, 1], 2)[0] > star[0]
```

### 第10章 减少偏见和有害性

[第10章](/learn/large-language-models/11-bias-toxicity/llm-10-bias-toxicity)要求先定义测什么：检测器分数、群体错误率、错误拒答、使用场景中的伤害不是同一个量。实验2的奖励是手工偏好，完全没有测这些风险。下面两个群体分别错1/2与1/8，总错误率同为2/10，却掩盖了.5与.125的差距；练习2必须保留分组分母，不能把奖励提高当作公平性结论。

### 第11章 视觉语言模型

视觉前缀、交叉注意力与图文检索把图像表示接入不同位置；“能读图”不是单一开关。图像槽位数取决于编码器分辨率、patch 与压缩设计，实验3的4只是手工输入，不是实际模型的固定规格。与[视觉章](/learn/large-language-models/12-vision-language/llm-11-vision-language-models)相连的可执行检查是配对身份：分数高但图像绑定错误，就不能用标签证明当前图片。这个身份断言是必要条件，不足以判断图片里的全部事实。

```python
groups = [(1, 2), (1, 8)]  # (错误数, 样本数)
rates = [errors / total for errors, total in groups]
assert rates == [0.5, 0.125]
assert sum(e for e, n in groups) / sum(n for e, n in groups) == 0.2


def same_image(query_id, memory_id):
    return query_id == memory_id


assert same_image("image-1", "image-1")
assert not same_image("image-1", "image-2")
```

## 单请求成本：先写内存单位，再谈环境结论

把前面增加的文字材料、视觉槽位和输出长度带入同一个请求，才能讨论它们的系统代价。这一节单独核算存储与能源，不把奖励、模型参数量或词元数量直接换算成碳排放。

### 第12章 环境影响

自回归推理保存既往键和值以避免重复计算，这份随上下文增长的存储称为 <Term def="为后续生成保留先前位置的键和值张量的存储；长度通常随已处理词元增长。">KV缓存</Term>。[PagedAttention §2.1–2.3](https://arxiv.org/abs/2309.06180)区分提示处理、逐步生成与批处理；这里不实现其分页算法，仅按张量元素数记账。

符号：L 为层数，Hkv 为 KV 头数，d 为头宽，b 为每元素字节数，S 为每请求已处理长度，B 为并发请求数，W 为权重、U 为工作区。我们假定所有生成词元都已处理并缓存；这与某些实现“刚采样出的最后一个词元尚未写入缓存”的时刻不同。

$$
M_{\mathrm{KV}}=2LH_{\mathrm{kv}}db\,BS,\qquad
M_{\mathrm{total}}=W+U+M_{\mathrm{KV}}.
$$

乘2是 K 与 V，不是“两次前向”。实验取 L=4、Hkv=2、d=8、b=2，因此每请求每词元256字节。W=4 KiB、U=2 KiB，S=文本8+检索8+图像4+已生成0…8。默认请求生成结束时需7 KiB，加固定6 KiB共13 KiB；16 KiB预算只能容纳一个完整长度请求。

B=2 时，固定6 KiB加两个20词元请求的10 KiB，生成0个词元恰好达到16 KiB预算；每再处理一个生成位置，两请求合计增加0.5 KiB，所以生成1个就到16.5 KiB，生成8个达到20 KiB。先预测：此时漏算 V，会出现什么“报告可装下、实际越界”的差异？

<LlmOfficialFinalReviewEvidenceGateLab />

地址格始终展示实际占用，故障只改报告值。它没有模拟碎片、分页、激活峰值或设备通信；满长容量是内存上界，不能当吞吐量。下面同时复算基线、溢出与故障，保持真实字节数不变。

```python
def memory(generated=0, batch=1, retrieved=8, image=4, omit_v=False):
    per_token = 2 * 4 * 2 * 8 * 2
    kv = per_token * batch * (8 + retrieved + image + generated)
    actual = 6 * 1024 + kv
    reported = 6 * 1024 + kv / (2 if omit_v else 1)
    capacity = (16 * 1024 - 6 * 1024) // (per_token * (8 + retrieved + image + 8))
    return actual / 1024, reported / 1024, capacity


assert memory() == (11, 11, 1)
assert memory(8) == (13, 13, 1)
assert memory(0, 2) == (16, 16, 1)  # 恰好到预算
assert memory(1, 2) == (16.5, 16.5, 1)  # 第一个生成位置即越界
assert memory(8, 2) == (20, 20, 1)
assert memory(8, 2, omit_v=True) == (20, 13, 1)
assert memory() == (11, 11, 1)
```

[Strubell 等 §2](https://arxiv.org/abs/1906.02243)用设备功率、持续时间与 PUE 估算用电，再乘电网排放因子。论文的历史平均值不是今天任意机器的常数。本页自设 P=0.1 kW、t=2秒、PUE=1.2、CI=400 gCO₂e/kWh，**并未测量服务器或根据词元数预测运行时间**。练习3要检查千瓦、秒与克的换算，还要说明未包含硬件制造和完整生命周期。

```python
power_kw, seconds, pue, carbon_g_per_kwh = 0.1, 2, 1.2, 400
energy_kwh = power_kw * seconds / 3600 * pue
carbon_g = energy_kwh * carbon_g_per_kwh
assert math.isclose(energy_kwh, 1 / 15000)
assert math.isclose(carbon_g, 0.02666666666666667)
print("PASS: chain / routing / rag / preference / groups / image / memory / units")
```

程序输出 PASS 仅表示上述输入的断言成立，不是对真实语言模型、整本书或部署系统的认证。总复习的作用是找到应返回哪个正式单元继续检查，而不是替每一章发一个免检结论。

## 常见误区 1：调了温度，模型就学会了

**现象**：输出概率更尖或更平，就说训练能力改变。**原因**：把最终选择设置和参数更新混在一起。**修法**：在实验1固定分词与行号，只调温度，确认注意力权重不变；再放开未来列，定位另一种首差。

## 常见误区 2：相关、受欢迎与无害是同一个分数

**现象**：检索权重或奖励上升，就宣布事实正确且风险更低。**原因**：三个目标使用不同标签、条件与分母。**修法**：用实验2分别改变先验和奖励，再用分组代码报告错误率；不执行材料内的不可信指令。

## 常见误区 3：内存能装下，就等于节能

**现象**：报表少算 V 后容量增加，于是声称省电。**原因**：报表遗漏未减少真实张量，更没有测功率和时间。**修法**：实验3对照实际地址占用，再独立核算能源单位；不从容量推导吞吐或碳排放。

## 小结

- 沿输入、注意力与输出概率定位变化。
- 分开计算检索概率与偏好目标。
- 用真实张量长度复核内存，而非报表。
- 风险与环境结论需要各自的测量条件。
