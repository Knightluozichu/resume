## 为什么目录顺序不等于学习顺序

想做知识库问答，并不意味着要先从零预训练。反过来，想训练模型，却不知道输入如何切成词元、标签如何移位，即使能启动分布式任务，也不知道它在优化什么。

地图的用途是先确定产物，再沿依赖回溯：已有模型的应用可绕过自训练；全参数微调要先核算模型状态；偏好优化还需要可采样的初始策略。下面三个实验分别回答“先学什么”“训练对象变成什么”“预算改变哪条路线”。

本页为自造小样本与解析算式驱动的 **simulation**，不执行真实模型训练，不复现全书工程，也不提供其他章节的完整实现。

## 一、按产物回溯先修知识

<Term def="按任务产物与前置需求连接的有向学习导航。">知识依赖图</Term>
的边表示“后一个任务需要前一个任务的产物”，而不是章节编号大小。我们的默认主路径是：数据规则
→ 模型基础 → 并行资源 → SFT初始策略 → RL对齐 →
应用与评估。它是面向本页训练目标的一条教学路线，不声称所有算法都必须按此顺序实现。

<LslOfficialLearningMapContextContractLab />

实验一初始停在“数据”。选择“训练并对齐”并逐步推进：第3章的清洗、去重、隐私与切分决定输入；第2章的因果模型基础决定移位标签和loss；第4章决定状态放在哪些设备；第5章得到可用于本路线偏好采样的SFT策略；第6章才讨论奖励与策略更新；第7、8章检验用途和风险。评估应贯穿各阶段，图中的末节点只代表最终应用验收。

现在选择“跳过基础”，推进到基础节点：图上的断边与读数会指出 **无法构造移位标签与loss**，不是扣一个抽象分数。恢复后改为“调用已有模型”：路线变成数据 → 基础 → 应用/评估，训练分支变暗；此时“跳过SFT”不会阻断，因为你使用已有模型，不负责重新训练它。这里的“数据”也包括应用输入、检索材料与评测集，不要求先收集预训练语料。

<Callout type="trap">

**现象：** 直接跳到RL，以为奖励高就能绕过模型基础。**原因：** 把书目顺序当作依赖，忽略了策略、标签和采样对象的定义。**修法：** 在实验一注入“跳过基础”，读出断点；补齐输入与loss后再推进。跳过SFT仅是本页所选SFT→RL路线的阻断，不代表所有RL方法都必须使用SFT。

</Callout>

## 二、阶段变化先看训练对象

<Term def="切分器产生的离散ID，不等于一个汉字。">词元</Term>
是切分器映射出的离散ID，不是固定长度汉字。本例自造提示ID为 `[11,12]`，回答为
`[21,22,23,2]`，其中2约定为结束符。这不是某个供应商词表。

<LslOfficialLearningMapComputeTraceLab />

**预训练状态：** 实验二的6个输入词元产生5个移位标签 `[12,21,22,23,2]`。输入位置0用11预测12，位置1用11、12预测21，以此类推。所有5个位置都参与loss；注入错误后，红色回边表示读取了未来标签，违反因果约束。最后一个输入没有本例中的下一个标签，不另补监督位置。

**SFT状态：** 切到第二步，序列仍然有提示和回答，但<Term def="只决定哪些预测位置计入SFT损失，不删去提示上下文。">回答mask</Term>变为 `[0,1,1,1,1]`：预测提示12的位置不计入loss，预测第一个回答21的位置必须计入。它是**损失权重**，不是把提示从注意力上下文删除。正常平均loss除以4；注入错误后除以5、提示12也被训练，目标发生改变。把回答改成2个词元，图上标签缩成3格，正常监督缩成2格。

**奖励建模状态：** 切到第三步，图变为一个提示向两条回答分叉。一个<Term def="同一提示下的两条候选回答及其排序。">偏好对</Term>是同一提示下的chosen/rejected及排序，不再是每个位置一个词元标签。若奖励分数为2和0，则排序损失为 $-\log\sigma(2-0)\approx0.126928$。注入错误把右侧提示换成99、98，比较条件不一致，本页拒绝将它视作合法偏好对。奖励建模只是RLHF的一环，不等于PPO策略更新。

<Callout type="trap">

**现象：** SFT训练时把提示标签也计入loss，或者把提示完全删掉。**原因：** 混淆损失mask与注意力上下文。**修法：** 在实验二第二步检查第一个权重为0、其余回答权重为1；保留提示输入，按有效监督位置归一化。真实模板还要明确分隔符、结束符和padding的权重约定。

</Callout>

## 三、目标与预算改变计算路线

<Term def="设备间状态分担与通信的组织方式。">计算拓扑</Term>
描述设备如何分担状态和通信。实验三用设备环、扇区和显存刻度表达状态分片；推理路线用开链作前向阶段示意。连线不是某种并行库的真实通信跟踪，也不代表带宽或性能测量。

<LslOfficialLearningMapEvidenceGateLab />

统一采用十进制GB、7B即 $N=7\times10^9$ 参数。推理仅估2字节/参数的权重，共14 GB；全参数训练假设混合精度权重2、梯度2、FP32主权重4、Adam两份状态8，共16字节/参数、112 GB。这个假设不适用于所有优化器或量化、LoRA设置。

- **全参数SFT／4卡／100万词元：** 理想均匀分片后每卡28 GB，已超过24 GB，默认就显示OOM；先学第3、2、4章，再进入第5章，而不是盲目加训练步数。
- **改8卡：** 每卡状态降至14 GB，扇区缩至八分之一；“状态能放下”仍不保证训练能运行，还缺激活、临时缓冲等预算。开启“错误复制全部状态”，每卡重回112 GB，这说明普通复制式数据并行不会自动解决模型状态装不下的问题。
- **从零预训练：** 数据路线更长，默认切到1亿词元；相同模型和训练字节假设下，状态不变而算量变100倍。1亿只是算例，绝不是7B充分预训练的数据建议。
- **本地推理：** 仅估权重14 GB，1卡也可容纳权重；学习重点转到第7章推理和第8章评估。KV缓存、上下文长度和延迟仍需单独核算，不能拿权重大小证明服务可运行。

计算量采用稠密模型主导项近似：训练 $F\approx6NT$，前向推理 $F\approx2NT$，忽略注意力二次项等成本。实验中 $T$ 是处理词元总量；训练包含提示输入而不仅是有效loss位置，推理是简化前向工作量而非真实自回归服务测量。默认SFT为42 PFLOP；假设每卡有效60 TFLOP/s、4卡理想线性扩展，纯计算估计为175秒。当前显存方案OOM，所以这**不是已执行训练时长**。8卡的87.5秒同样忽略通信与流水线空泡。

<Callout type="trap">

**现象：** 看到“8卡14 GB”就宣称一定可训，或用更多数据并行副本修复OOM。**原因：** 漏算激活与缓冲，且复制不等于分片。**修法：** 对照实验三的扇区和24 GB刻度，先确认每卡持有的是全量还是份额，再为剩余状态和通信单独做预算；不要把理想时间当吞吐基准。

</Callout>

## 可运行的最小复算

将下面完整代码存为 `map_check.py`，使用 Python 3 标准库运行 `python3 map_check.py`。它复算实验二正常SFT与奖励损失、实验三资源算式；不下载模型、不执行训练。预期三行输出如下代码注释。

```python
from math import exp, log

prompt = [11, 12]
answer = [21, 22, 23, 2]
sequence = prompt + answer
labels = sequence[1:]
mask = [int(i + 1 >= len(prompt)) for i in range(len(labels))]
assert labels == [12, 21, 22, 23, 2]
assert mask == [0, 1, 1, 1, 1]
assert sum(mask) == 4
preference_loss = log(1 + exp(-(2 - 0)))
assert abs(preference_loss - 0.126928011) < 1e-8
n, tokens = 7_000_000_000, 1_000_000
state_gb = 16 * n / 1e9
flops = 6 * n * tokens
assert state_gb / 4 > 24
assert state_gb / 8 == 14
assert flops / (4 * 60e12) == 175
print("labels", labels, "mask", mask)
print(f"preference_loss={preference_loss:.6f}")
print(f"state={state_gb:.0f}GB; 4cards={state_gb/4:.0f}GB/card; compute=175s")
# labels [12, 21, 22, 23, 2] mask [0, 1, 1, 1, 1]
# preference_loss=0.126928
# state=112GB; 4cards=28GB/card; compute=175s
```

## 练习：从失败状态倒推修复

<Exercises>

**问题 1：只调用已有模型时，跳过SFT为什么不阻断？跳过基础又为什么阻断？**

<Answer>

在实验一选择“调用已有模型”，边只连接数据、基础、应用/评估，SFT不在路线中。选择“跳过基础”再推进，输入解释和预测机制的前置缺失；训练路线用“无法构造移位标签与loss”、应用路线用“无法解释词元输入与生成长度边界”作具体阻断。对应用读者，需掌握的是已有模型输入输出及边界，而不是必须亲自训练。这个依赖图是学习检查，不是运行时权限门。

</Answer>

**问题 2：提示2个词元、回答2个词元，正常SFT有几个移位标签与几个有效监督位置？**

<Answer>

在实验二选择2个回答词元、切到SFT：序列为11、12、21、22，标签为12、21、22，共3个；mask为0、1、1，有效监督2个。开启错误后变3个有效位置，提示12被误计。切到奖励建模后则是两条长度2的候选回答组成一个排序约束，不能把它称为同一张标签表。

</Answer>

**问题 3：默认4卡OOM时，把词元总量从100万减半能修复模型状态OOM吗？8卡分片又保证什么？**

<Answer>

不能。按实验三的假设，模型状态112 GB与总处理词元量无关，4卡分片仍为28 GB/卡；减少总量仅改变本算式中的计算量。8卡把状态降至14 GB/卡，只证明该部分预算低于24 GB，不保证加上激活与缓冲后仍能运行。复制全部状态时每卡112 GB，设备数再多也没有分片收益。

</Answer>

</Exercises>

## 小结

- 先定目标产物，再回溯知识依赖；应用路线可绕过自训练，不可绕过输入输出与评估边界。
- 阶段改变监督对象：词元预测 → 回答位置loss → 同提示回答排序；奖励模型还不是RL策略更新。
- 设备数、分片方式和词元量影响不同资源项，显存可行性与理想计算时间是两件事。
