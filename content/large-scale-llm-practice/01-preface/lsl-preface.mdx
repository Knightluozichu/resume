## 为什么一本入门书要同时讲理论与实践

把同一段文本交给系统，你可能要翻译，也可能要摘要。过去常见的工作方式是：先决定任务，再选择专门为这项任务训练或微调的模型。任务一多，需要维护的数据、参数副本、接口和评估程序也随之增多。共享模型则把任务意图放进输入，让同一份参数根据不同指令完成不同工作。改变的不只是聊天窗口，而是**任务与模型之间的组织方式**。

这又带来一个看似矛盾的问题：接口更简单了，为什么入门反而需要更多知识？因为一句回答背后仍有训练目标、数据、数值状态、设备容量和应用约束。提示能够改变模型看到的条件，却不能凭空补齐知识、修正训练标签或增加显存。前言的目的，是让读者理解为什么这些问题必须放在一起学，而不是提前记住整本书的目录。

本页的三个实验都是独立构造的小模型与计算器。它们不调用模型服务、不测真实 GPU，也不复现原书的大规模训练；它们让“共享”“装得下”“学对了”分别成为能观察和计算的命题。

## 前言

### 从一任务一模型到共享模型与任务提示

<Term def="先从大量文本学习语言统计规律的训练阶段。">预训练</Term>
先利用大量文本学习语言中的统计规律，得到可用于多种后续工作的参数初始化。它并不自动指定用户当前要完成哪项任务。在传统预训练—微调范式中，团队常为分类、问答、摘要分别微调并部署模型；共享初始化不等于部署时只维护一个模型。

<Term def="多项任务复用同一份参数，通过输入条件区分目标。">共享模型</Term>
指多项任务复用同一份参数。
<Term def="输入中表达任务、上下文或示例的部分，不等于权重更新。">任务提示</Term>
则是输入中用于表达任务、上下文或示例的部分。例如，同样输入“今天下雨”，加上“翻译成英文”与“判断天气”就有不同目标。可以把两种接口写成：

- 专用模式：先路由到任务 $t$ 的参数 $\theta_t$，再计算 $f_{\theta_t}(x)$。
- 共享模式：用同一份 $\theta$ 计算 $f_\theta(\text{instruction}_t,x)$。

这里的区别是参数归属和条件输入，不是“专用模型没有预训练”，也不是“一个提示词就能训练出新能力”。推理时改变提示通常不更新权重；是否胜过专用系统，仍要按任务、数据和评价标准检验。

第一版前言回顾了预训练模型、少样本提示与对话模型带来的范式变化，并把 2022 年 11 月 ChatGPT 的广泛使用作为重要转折。这个历史背景解释了本书为何出现：许多任务开始共享模型接口，而模型内部的训练与系统知识并没有因此变得可省略。前言也明确指出，当时 ChatGPT 的完整实现细节并未公开；不能把一个产品展示反推成已知的完整训练配方。

**先预测，再操作实验一：**保持三个任务不变，把“共享模型”切到“一任务一模型”。模型实体应由一份变成三份，任务数不变。再切回共享并打开“漏任务提示”：多条红色虚线仍汇入一个模型，但同一内容不再足以区分任务。专用模式的任务路由仍可提供任务身份，所以同一故障在那里不等价于完全丢失任务意图。最后重置，回到三任务、共享参数、提示完整。

<Callout type="trap" title="共享参数不等于共享目标">
  现象：用同一句文本测试翻译与摘要，发现输出相同，便认为模型没有多任务能力。原因：输入只保留内容，丢掉了任务指令；共享接口无法知道你想做什么。修法：显式给出指令或示例，并分别准备任务评价；不要以更换提示冒充权重训练。

### 训练、分布式计算与应用为何互相约束

前言并置这些领域，不是要求每个应用开发者立刻编写 CUDA，而是提醒读者：某一侧的选择，会改变另外两侧可实现的方案。

**训练侧**决定学习什么。预训练主要学习文本的条件概率；<Term def="用输入与理想输出配对的样本继续训练。">有监督微调</Term>用指令与理想回答的配对样本，教模型按任务要求作答。奖励建模学习同一提示下多个回答的偏好排序，强化学习再利用奖励信号调整策略。奖励只是特定数据和偏好定义下的代理目标，不是自动获得的“正确性”。第一版以这四阶段组织主要构建内容；这不是断言所有模型都必须采用完全相同的训练流程。

**系统侧**决定这些状态如何计算和放置。训练不仅保存参数，还要保存反向传播的梯度、优化器状态以及中间激活。参数能装进一张卡，不代表训练能装进这张卡。<Term def="多设备处理不同数据，并合并训练信息；完整复制不降低每卡状态。">数据并行</Term>的完整复制方式会让每张设备都持有一份训练状态；增加设备可以分担数据计算，却不自动把每卡状态除以设备数。<Term def="将参数、梯度或优化器等状态分散存放，通常需额外通信。">状态分片</Term>则把部分状态分布存放，但会引入聚合、通信、同步与调度问题。本页只计算理想全状态分片的静态下界，不模拟这些代价。

**应用侧**决定什么才算完成任务。请求的上下文长度、同时服务的人数、延迟上限、外部工具与知识源、输出质量和安全要求，都可能改变训练数据与系统方案。更长的上下文通常增加激活或推理缓存需求；更多通信可能降低计算利用率。反过来，设备容量与延迟预算又会限制可用模型与上下文。应用评估发现的失误还会反哺数据选择，而不应只靠“把模型再变大”。

例如，面向短摘要的模型要转做长文问答：应用要求更长输入；系统必须重新核算激活和缓存；训练或微调需考虑长上下文样本与目标；评估又要检查答案是否来自文本。这是一组相互制约的工程问题，不是一条只需照着走的课程依赖箭头。

**动手算实验二：**设参数量 $P=7\times10^9$，每参数的 BF16 权重、BF16 梯度、FP32 主参数和 Adam 两个 FP32 状态分别占 $2,2,4,4,4$ 字节。这里明确假设训练方案持有 FP32 主参数；并非每个框架和优化器配置都如此。

$$
M_{\mathrm{state}}=P(2+2+4+4+4)=16P\ \mathrm{bytes}.
$$

<Term def="二进制容量单位，1 GiB 等于 2³⁰ 字节。">GiB</Term>按 $2^{30}$
字节计算，而这里的 B 表示十亿个参数。于是全部训练状态是 112 GB，即约 104.308
GiB。再假定每卡激活固定占 2 GiB：

- 四卡完整复制：每卡约 $104.308+2=106.308$ GiB，放不进 24 GiB。
- 四卡理想全分片：每卡约 $104.308/4+2=28.077$ GiB，仍放不进。
- 八卡理想全分片：每卡约 $104.308/8+2=15.039$ GiB，在这个 toy 假设下小于 24 GiB。

**先预测：**在四卡、24 GiB、理想全分片状态下打开“漏算优化器”，账面会降至约 8.519 GiB，但实际堆栈仍为 28.077 GiB。虚线不是释放了空间，而是被漏记的 FP32 主参数、m、v。再把卡数改为八，观察堆栈缩短；切换完整复制后，加卡不再缩短它。重置会恢复所有五项控件，而不仅是故障按钮。

<Callout type="trap" title="参数字节数不是训练显存">
  现象：7B 的 BF16 权重约 13.039 GiB，于是计划在 24 GiB

  2 GiB 激活只是练习假设，不能当真实配置建议。

### 理论与实践双线：一个公式要对得上一组张量

只知道公式，容易忽略标签方向、维度和精度；只看运行日志，又可能把某个下降的 loss 当作能力改善。理论线告诉我们目标、变量和边界，实践线用输入、张量和结果检查实现是否真的对应这个目标。它们不是两套互不相干的内容：一次错误更新就可以暴露两者之间的脱节。

实验三用只有“猫”和“狗”的词表。固定想要的输出为猫，输入特征 $h=[x]$ 的形状为 $[1]$，权重 $W=[w,0]$ 的形状为 $[1,2]$。矩阵乘法给出 logits $z=hW=[wx,0]$，形状为 $[2]$。<Term def="把实数分数转换为总和为 1 的概率。">Softmax</Term>把这两个实数转成概率：

$$
p_{\text{猫}}=\frac{e^{wx}}{e^{wx}+1},\qquad
p_{\text{狗}}=1-p_{\text{猫}}.
$$

目标为猫时，<Term def="单个正确标签下，是模型分配给该标签概率的负对数。">交叉熵</Term>就是 $L=-\log p_{\text{猫}}=\log(1+e^{-wx})$。对这个标量权重求导，得到<Term def="损失对参数的变化率，决定小步更新的方向。">梯度</Term> $g=(p_{\text{猫}}-1)x$。一次 SGD 更新是 $w'=w-\eta g$。它与实验二的 Adam 内存假设是**两个不同的独立 toy**；本标量更新没有使用 Adam。

初始 $w=0,x=1,\eta=1$ 时，logits 是 $[0,0]$，概率是 $[0.5,0.5]$，$L=\log 2\approx0.693147$，$g=-0.5$。更新得到 $w'=0.5$、logits $[0.5,0]$、$p_{\text{猫}}\approx0.622459$、$L\approx0.474077$。这组数把公式、参数和图中概率条连在了一起。

**先预测实验三：**点击“执行一步更新”，曲线上的点应向右下方移动。如果把训练标签反置成狗，梯度就改成 $p_{\text{猫}}x$；同样的更新会把点推向左上方。注意下图始终画“目标猫”的损失，不能把它与错误狗标签下的训练损失混为一谈。切换 $x=2$ 会同时改变曲线陡峭程度、起点梯度与更新位置；重置恢复 $x=1,\eta=1,w=0$、标签正确。

<LslPrefaceEvidenceGateLab />

<Callout type="trap" title="loss 下降可能是在学错标签">
  现象：训练日志里的狗标签 loss
  下降，但需要输出猫的样本表现更差。原因：优化器按给定标签执行，不会自动知道业务目标；训练损失和应用检验针对的是不同目标。修法：先查样本与标签，再查
  logits、概率、梯度符号和更新方向，最后用独立任务样本检验。不要仅因代码能跑或曲线好看就宣称模型学对了。

### 怎样使用这本书

第一版前言面向希望入门大语言模型研究与应用的读者，也把它定位为高年级本科生与研究生相关课程的补充材料。基础深度学习和自然语言处理知识有助于理解训练目标；系统和并行计算概念有助于理解大规模实现。如果进一步研究训练或推理系统，再深入分布式系统、并行计算与 CUDA，而不是把所有底层知识当成使用模型接口前必须跨越的门槛。

读一节理论时，问“符号对应哪项数据、哪块张量、哪一步更新”；做一个实践时，问“实现优化的到底是什么、设备是否容纳、应用是否成功”。这也解释了为什么书中除了构建阶段，还讨论外部工具、知识源、复杂任务规划与评估。它们提供模型能力进入应用后的检验场景，而不是训练结束后的装饰。

研究发展迅速，第一版选择的是其时代有代表性的工作。保持这种历史语境，比把所有新方法塞进前言更有帮助。本页不替原书建立新目录，不引入第二版章节，也不把独立小实验说成作者原始实验。

## 正文实践：完整 Python 对照三个实验

以下只用 Python 3 标准库。把完整代码保存为 `preface_toy.py`，运行 `python3 preface_toy.py`。它不下载模型、不需要 GPU。先手算结果，再对照输出和三个 SVG；误差按浮点数六位小数理解。

```python
import math

# 实验一：同样三个任务；比较部署参数实体，不估算任务质量。
tasks = ["翻译", "摘要", "问答"]
print("models:", len(tasks), "->", 1)

# 实验二：每参数16字节；全状态理想均分；激活固定每卡2 GiB。
P, GiB = 7 * 10**9, 2**30
state = P * (2 + 2 + 4 + 4 + 4) / GiB
for n in (4, 8):
    replicated = state + 2
    sharded = state / n + 2
    missing_optimizer = P * (2 + 2) / GiB / n + 2
    print(f"{n} cards: replica={replicated:.3f}, "
          f"shard={sharded:.3f}, false_bill={missing_optimizer:.3f} GiB")

# 实验三：每次从w=0重新计算一步，不累积，不使用Adam。
def step(x, rate, wrong_label):
    gradient = (0.5 if wrong_label else -0.5) * x
    w = -rate * gradient
    logits = [w * x, 0.0]
    p_cat = 1 / (1 + math.exp(-logits[0]))
    target_cat_loss = math.log1p(math.exp(-logits[0]))
    return w, logits, p_cat, target_cat_loss

for x in (1, 2):
    for wrong in (False, True):
        w, z, p, loss = step(x, 1, wrong)
        print(f"x={x} wrong={wrong}: w={w:.2f}, z={z}, "
              f"p_cat={p:.6f}, L_cat={loss:.6f}")

assert abs(state - 104.3081283569336) < 1e-9
assert state / 4 + 2 > 24 > state / 8 + 2
assert step(1, 1, False)[3] < math.log(2) < step(1, 1, True)[3]
print("all assertions passed")
```

预期第一行是 `models: 3 -> 1`。四卡行依次是 `106.308`、`28.077`、`8.519`；八卡行是 `106.308`、`15.039`、`5.260`。正确标签下，$x=1$ 的猫概率和损失为 `0.622459` 与 `0.474077`；错误标签下为 `0.377541` 与 `0.974077`。$x=2$ 时两组损失分别为 `0.126928` 和 `2.126928`，最后打印 `all assertions passed`。

这份实践能验证字节单位和标量更新，不足以验证真实模型的任务质量、通信效率或训练稳定性。容量实验中“可容纳”只是静态 toy 下界通过，不能代替真实设备剖析。

## 小结

- 任务提示把意图带入共享模型，但不保证胜过专用模型。
- 训练状态、并行方式与应用预算互相制约，必须一起核算。
- 理论给出目标与梯度，实践用张量和任务样例检验其含义。

<Exercises>

**问题 1：四个任务为什么不一定需要四份模型？漏掉任务提示后，专用与共享模式为什么不完全一样？**

<Answer>
  实验一把任务数改为四。专用模式有四个模型参数实体，共享模式只有一个；四项任务通过不同输入条件使用同一份参数。若完全漏掉任务提示，共享接口可能只收到相同内容，无法区分意图；专用系统仍可由路由到的模型确定任务。因此不能声称两种模式都因缺少自然语言提示而同样失效，也不能据此认定共享必然更准确。
</Answer>

**问题 2：在实验二中把 7B、四卡、24 GiB 改成八卡、16 GiB。完整复制和理想全分片分别怎样？能否据此采购设备？**

<Answer>
  完整复制每卡仍需约 106.308 GiB，远超 16 GiB；理想全分片每卡约 15.039
  GiB，只剩约 0.961 GiB
  余量。按本页假设后者可容纳，但不足以作为采购依据：实际激活随序列和批量变化，通信缓冲、临时张量与碎片还未计入。撤销漏算优化器的故障，确认看到的是完整堆栈，再到真实配置上测量。
</Answer>

**问题 3：修改 Python 调用，把输入改成 x=2、学习率改成 0.5。标签正确和反置时，更新后的 logits、猫概率、目标猫损失各是多少？**

<Answer>
  起点概率仍是 0.5。正确标签的梯度为 −1，更新后 w=0.5，logits=[1,0]，猫概率约
  0.731059，猫损失约 0.313262。标签反置时梯度为
  +1，w=−0.5，logits=[−1,0]，猫概率约 0.268941，猫损失约
  1.313262。实验三选择相同输入与学习率并执行一步即可对照；曲线画的是固定目标猫，不是错误标签所定义的训练目标。
</Answer>

    多设备处理不同数据并合并训练信息；完整复制方式不会自动降低每卡状态大小。
  </GlossaryItem>
  <GlossaryItem term="状态分片">
    把参数、梯度或优化器等状态分散存放，以通信等代价换取每卡内存下降。
  </GlossaryItem>
  <GlossaryItem term="GiB">
    二进制容量单位，1 GiB 等于 2³⁰ 字节；不同于十进制 GB。
  </GlossaryItem>
  <GlossaryItem term="Softmax">
    把一组实数分数归一化为总和为 1 的概率；大的分数对应更高概率。
  </GlossaryItem>
  <GlossaryItem term="交叉熵">
    衡量模型给目标分配概率的损失；单个正确标签时是其概率的负对数。
  </GlossaryItem>
  <GlossaryItem term="梯度">
    损失对参数的变化率；沿负梯度小步更新，目的是降低所定义的损失。
  </GlossaryItem>
</Glossary>
