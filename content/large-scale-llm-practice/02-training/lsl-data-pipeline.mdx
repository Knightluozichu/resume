# 数据处理流水线

## 核心概念

### 数据流水线总览

大模型预训练的数据处理是一条从原始数据到训练就绪 Token 序列的完整流水线。数据质量直接决定模型能力的上限——「Garbage In Garbage Out」是铁律。

### 数据处理主流程

**第一步：数据采集**——从网页（Common Crawl）、书籍、论文、代码等来源收集原始文本。数据来源的多样性决定模型知识覆盖面。

**第二步：质量过滤**——用启发式规则（长度、符号率、重复度）、轻量分类器、困惑度过滤等剔除低质量内容。困惑度过滤用小模型给文本打分，过高（乱码）或过低（重复模板）都剔除。

**第三步：去重清洗**——精确去重（哈希匹配）去除完全相同的文档，模糊去重（MinHash LSH）去除近似重复的文档。去重减少模型记忆、提升泛化能力。

**第四步：分词编码**——用 BPE/SentencePiece 将文本转为 Token 序列。分词器的压缩率和覆盖率影响训练效率和模型能力。

**第五步：数据配比**——按比例混合不同来源数据，平衡知识广度、推理深度和长文本能力。

### BPE 分词算法

BPE（Byte Pair Encoding）是大模型最常用的分词算法：

1. **初始化**：将所有词拆为字符序列，词表为所有字符
2. **统计频率**：统计相邻字符对的共现频率
3. **合并**：将最高频字符对合并为新 Token 加入词表
4. **重复**：重复统计-合并直到达到目标词表大小

BPE 的优势在于平衡覆盖与效率：高频词用单 Token 表示效率高，低频词用子词组合保证覆盖，且无需 UNK（未知词）。词表大小需权衡：大词表（128K）压缩率高但参数多，小词表（32K）参数少但压缩率低。主流模型词表多在 32K-128K 之间。

### MinHash LSH 模糊去重

精确去重只能发现完全相同的文档，MinHash LSH 能发现「改了几个字」的近似重复：

- **MinHash**：对文档做 n-gram 切分，用多个哈希函数生成签名，两个文档签名相同位置相等的概率约等于 Jaccard 相似度
- **LSH（局部敏感哈希）**：将签名分桶，相似度高的文档大概率落入同一桶，只需在同桶内做精确比较

MinHash LSH 将 O(n^2) 的两两比较降为近线性，可处理万亿级 Token 数据。相比精确去重，它能去除更多冗余，更有效减少模型对重复内容的记忆。

### 数据配比策略

预训练数据的配比直接影响模型能力分布：

| 数据来源 | 典型占比 | 贡献能力 |
|----------|----------|----------|
| 网页文本 | 50-67% | 常识、世界知识、语言流畅性 |
| 书籍文献 | 15-20% | 长文本连贯性、深度知识 |
| 代码数据 | 5-10% | 逻辑推理、结构化思维 |
| 学术论文 | 2-5% | 专业知识、推理深度 |
| 对话数据 | 1-3% | 对话能力、指令理解 |

配比确定需考虑 Chinchilla 最优（数据量与参数量的最优比例约 20:1）、消融实验验证、目标场景调整。代码数据虽占比小但对推理能力提升显著，是多步推理的关键。

## 术语表

- **BPE（Byte Pair Encoding）**：基于频率的子词分词算法，平衡覆盖与效率
- **MinHash LSH**：基于局部敏感哈希的模糊去重方法，发现近似重复文档
- **Chinchilla 最优**：给定计算预算下数据量与模型参数量的最优比例（约 20:1）
- **数据配比**：不同来源数据在训练集中的混合比例
- **困惑度过滤**：用小模型给文本打分过滤低质量内容的方法
- **Jaccard 相似度**：两个集合交集与并集的比值，衡量文档相似度
