# 评测与测试

## 学习目标

完成本章学习后，你将能够：

1. 掌握大模型评测的核心维度和关键基准数据集
2. 理解基准测试、人工评估、LLM-as-Judge 三种评估方法的优缺点
3. 识别数据污染问题并掌握检测与缓解方法
4. 设计完整的自动化评测流程

## 核心概念

### 为什么评测很重要

评测是大模型研发的「指南针」——没有可靠的评测就没有可靠的迭代。评测决定了我们能否准确判断模型能力、能否发现模型弱点、能否公平比较不同模型。错误的评测会导致错误的结论和决策。

### 评测维度体系

大模型评测覆盖多个能力维度：

| 维度 | 代表基准 | 评测能力 |
|------|----------|----------|
| 知识能力 | MMLU / C-Eval | 常识与学科知识 |
| 推理能力 | GSM8K / MATH | 数学与逻辑推理 |
| 代码能力 | HumanEval / MBPP | 代码生成与补全 |
| 指令遵循 | IFEval / MT-Bench | 格式与约束遵循 |

- **MMLU**：57 个学科的多选题，衡量广泛学科知识
- **GSM8K**：8500 道小学数学应用题，需多步推理计算
- **HumanEval**：164 道 Python 编程题，跑单元测试验证正确性（pass@k）
- **MT-Bench**：多轮对话评估，衡量开放生成质量

### 三种评估方法

**基准测试**：标准化题库自动评分。优点——可复现、成本低、自动化。缺点——覆盖面有限、易过拟合、数据污染风险。

**人工评估**：人类标注员打分。优点——最接近真实体验、可评估开放生成。缺点——成本高、速度慢、标注者偏差。

**LLM-as-Judge**：用强模型（如 GPT-4）评估目标模型。优点——快速、可大规模。缺点——judge 有偏见（如位置偏好、偏好自己风格）。

实践建议：三者结合——基准测试做快速基线，LLM-as-Judge 做大规模自动评估，人工评估做关键场景验收。

### 数据污染

数据污染是当前大模型评测最严峻的挑战：训练数据中包含评测基准的测试集内容，导致模型「见过答案」而非真正理解。

**影响**：分数虚高、无法公平比较、掩盖真实缺陷。

**检测方法**：
- n-gram 匹配——检查训练数据是否含测试集内容
- 困惑度检测——测试集困惑度异常低可能见过
- 改写测试——改写测试题后分数差距大说明污染

**缓解方法**：训练前数据去污、动态基准（定期更新测试集）、改写评测、程序化生成新题。

### 自动化评测流程

完整的自动化评测流程包含六个环节：

1. **构建测试集**——覆盖多维度，含标准基准和私有题库（防污染）
2. **去污染检查**——n-gram 匹配和困惑度检测
3. **模型推理**——统一 prompt 模板，控制解码参数
4. **自动评分**——选择题精确匹配、代码题单元测试、开放生成 LLM-as-Judge
5. **结果分析**——按维度拆解，bad case 归因
6. **迭代优化**——bad case 驱动数据补充和对齐微调

关键考虑：去污染是底线、评分一致性（多次采样取平均）、prompt 敏感性（固定或平均多 prompt）、统计显著性（分数差在小数点后 1-2 位内可能不显著）。

## 术语表

- **MMLU**：57 学科多选题基准，评测广泛学科知识
- **GSM8K**：小学数学应用题基准，评测数学推理
- **HumanEval**：Python 编程题基准，评测代码生成（pass@k）
- **LLM-as-Judge**：用强模型评估目标模型的自动化评估方法
- **数据污染**：训练数据含测试集内容导致评测虚高
- **pass@k**：生成 k 个样本中至少一个通过测试的比例
- **去污染**：从训练数据中删除测试集内容的方法
