## 为什么更多资料不一定教得更好

同一段文章复制十次，占了十份空间，却没有带来十份新知识。另一方面，删掉所有少见表达，可能恰好丢掉读者最需要的专业材料。

本章解决“选什么、留什么、给模型看几次”的问题。若不分清这三件事，资料越来越多，训练却可能更偏、更容易记住私人信息，考试成绩也可能只是提前看过题目。

## 3.1 数据来源

<Term def="模型读入的离散文本单位，不等于字符、单词或字节">词元</Term>
（token）是预算单位；一个来源有多少文档，不直接决定它贡献多少训练词元。来源台账至少记录
URL
或来源标识、抓取日期、语言、许可依据、文本提取版本和拒绝原因。台账让删除请求可以追溯到原始记录，而不是只剩一个无法定位的训练文件。

将“可用库存”和“采样曝光”分开：实验一库存为网页 40、科学 10、代码 10 个教学词元。权重为 6:3:1 时，60 个预算对应 36、18、6 个曝光；科学材料平均被看 1.8 轮。这里没有质量分，权重是实验者选择，不是模型性能测量。

### 3.1.1 通用数据

网页覆盖面大，但主内容提取容易混入导航、广告及镜像；对话含有轮次和引用关系，清洗时不能把上下文全删掉；书籍提供较长的论述结构，但版权与阅读顺序提取是独立问题。公开可读网页不自动授予训练或再分发权。对 PDF，双栏顺序、页眉和公式错误也不会因文件能打开就消失。

实验一的“网页”是通用来源的缩写，不代表全部通用语料。先预测：把总预算由 60 改到 120，会增加库存，还是只增加重复曝光？推进到“完整预算”再观察。

### 3.1.2 专业数据

多语言文本、科学文本与代码各自补足不同能力。多语言语料需要按语言检查留存率，不能把低资源语言的罕见字符直接当噪声；科学文本需要保住公式及单位；代码要保住缩进、文件边界，并检查仓库许可与生成文件。自然语言、字节和代码文件的统计口径不能混作同一种比例。

实验一调高科学权重会挤占另外两源的曝光，而不会凭空增加训练预算。注入“漏掉代码源”，其预算变成 0；这是一种确定的覆盖缺口，不是已测得某个代码评测分数下降。

## 3.2 数据处理

处理顺序取决于要维护的不变量。一个可审计方案是：提取主内容并规范化 → 质量过滤 → 在统一比较表示上跨来源去重与分组 → 按组切分 → 对输出文本遮蔽 → 切分词元 → 针对保留集及外部评估集再次检查。分组不等于每次都删除整簇；可以保留代表或把全簇放在同一分区。

必须记录原文到规范化文本的映射，避免用新文本的字符位置回写旧文档。去重所用文本与实际发布文本也可以不同，但版本和转换关系必须明确。实验二比较分组的作用，实验三展开遮蔽与切分间的长度变化。

### 3.2.1 低质过滤

启发式过滤使用可解释规则，例如去掉抽取失败的空文档、过高重复行比例、异常符号密度；分类器则学习“更像参考语料”的文本。后者输出的是相似于训练偏好的判断，不是普适的内容价值。困惑度也会把方言、罕见术语和陌生语言判为异常。

实践脚本只拒绝少于四个字母数字的样本；它能剔除 `!!!`，却不能识别造谣或科学错误。每条拒绝都留下原因。真实管线中，某来源的过滤规则过严会使库存缩水；实验一只改采样权重，不模拟过滤率。不能只报告总留存率而忽略语言和领域的损失。

<Callout type="trap" title="误区一：过滤越严格，质量必然越高">
  现象：保留下来的网页很整齐，少数语言却消失了。原因：参考分类器或字符阈值偏向多数语言，把分布差异当作低质。修法：按语言、来源分层抽检拒绝样本，报告留存率及独立下游表现；不能用本页的采样权重充当质量测量。
</Callout>

### 3.2.2 冗余去除

精确去重可以比较规范化内容的哈希；近重复则需要容忍局部编辑。实验二把字符串中相邻两个字符组成的 <Term def="连续的若干字符或词元组成的片段；此处取两个字符并去掉重复项">shingle</Term> 放进集合：A=`abcd`，B=`abce`，C=`bcef`。这与生产中常见的词级五元组不是同一个配置。

<Term def="两个集合交集大小除以并集大小">Jaccard 相似度</Term>为 $J(S,T)=|S\cap
T|/|S\cup T|$。A 与 B 共享 `ab,bc`，并集为 `ab,bc,cd,ce`，所以是 2/4；B 与 C
也是 2/4；A 与 C 仅共享 `bc`，是 1/5。阈值 0.5 时前两对连边，三者进入同一
<Term def="沿相似边可以相互到达的一组文档，不要求组内每一对都有边">连通簇</Term>
；相似度本身并不传递。

MinHash 用较小签名估计集合相似，LSH 用分桶缩小候选比较范围，均不能承诺找全全部近重复。正文脚本对三对穷举，结果精确但开销随文档数近似平方增长，不能照搬到万亿词元。

先预测：把阈值调到 0.6，会剩几个簇？再恢复 0.5，打开分区内去重故障：A/C 在训练集、B 在保留集，跨区边消失；“区内没重复”并不能证明两区之间没有泄漏。

<Lsl03PretrainingDataComputeTraceLab />

<Callout type="trap" title="误区二：簇内每一对都超过阈值，区内去重足够安全">
  现象：A 与 C 仅 0.2，却与 B
  同簇；只查训练分区时报告零条边。原因：连通关系沿路径传播，而分区比较遗漏了
  A–B、B–C。修法：在统一表示上跨来源建候选与簇，按簇分配分区；还要单独对既有外部评估集做污染检查。提高阈值会拆散簇，不等于降低实际泄漏。
</Callout>

### 3.2.3 隐私消除

<Term def="可直接或结合上下文识别个人的信息，例如某些姓名、地址、邮箱组合">
  个人身份信息
</Term>
（PII）可通过规则、实体识别与人工审查发现，再按政策删除记录或遮蔽片段。姓名可能是公共作者署名，也可能是私人医疗记录的一部分；上下文与授权都会影响处置，不能把正则命中与违法性画等号。

实验三仅识别受限 ASCII 邮箱模式。`mail a@b.io eval KEY` 中邮箱占原文 `[5,11)`，替换成七字符 `[EMAIL]` 后占 `[5,12)`。必须先在完整文本上处理，再按新文本切分；若先切为单字符再逐个运行完整邮箱正则，没有任何单字符能匹配整个邮箱。

### 3.2.4 词元切分

<Term def="逐次合并高频相邻符号对，并按学得的合并次序切分文本的方法">BPE</Term>
从小符号表逐步合并，例如 `l o w` 可先合并 `l+o` 再合并
`lo+w`，但顺序来自训练语料，不是任意最长匹配。WordPiece 的训练目标与 BPE
不同；常见教材使用“共现频率/两侧频率乘积”说明其选择偏好，不能当成 Google
未公开训练器的完全复现。Unigram
从较大的候选词表出发，依据概率模型剪枝，并寻找高概率切分。

| 方法               | 词表构造方向            | 对照实验三时须区分                       |
| ------------------ | ----------------------- | ---------------------------------------- |
| BPE                | 频繁相邻对逐步合并      | 保存有序合并规则，不能只保存词表         |
| WordPiece          | 根据训练准则扩展词表    | 常见推断采用带续词标记的最长匹配         |
| Unigram            | 从候选词表删减          | 可能存在多条切分路径，不能只按长度取词   |
| 本页固定教学切分器 | 手写四项词表 + 字符回退 | 只验证 offset 与顺序，不训练上述三种算法 |

<Term def="词元在当前文本中的字符起止位置；这里使用左闭右开区间">offset</Term>
不必是字节位置。此处全部输入为 ASCII，Python 字符下标与浏览器字符下标一致；非
ASCII 的 UTF-8 字节和 JavaScript UTF-16
下标不能直接互换。生产分词器还须冻结规范化规则、词表、特殊标记及版本。教学词表包含
`mail`、`eval`、`KEY` 和可选 `[EMAIL]`，其余字符逐字输出，空格跳过。

推进实验三至第二步：正确顺序输出 4 个词元；逐词元遮蔽故障输出 9 个。关闭故障、把占位符改为字符回退，输出变成 10 个；遮蔽相同但预算与位置映射不同。最后一步检查精确字符串 `eval KEY`：开启检查会丢弃整个样本，输出 0 个；关闭后该评估串仍会进入训练。它不是指令注入探测器，也不识别改写后的考题。

  现象：邮箱消失，但 `eval KEY` 仍在；或旧 offset 把 `eval`
  定位错一位。原因：遮蔽改变长度，且隐私与评估污染是不同检测目标。修法：重建位置映射，分别记录遮蔽和评估剔除原因，并对遗漏模式抽检。此处只匹配一种邮箱和一个精确评估串，不覆盖姓名关联、混淆邮箱、语义近似考题或指令注入。

## 3.3 数据影响分析

“更多、更干净、更多样”不是可以独立最大化的三个指标。固定计算预算下，增加一个来源就减少其他来源的曝光；去重会减少可用数据，却可能提高有效覆盖。要测因果效果，应固定模型、分词器、训练预算及评估集，只改变数据处理或混合策略，并重复实验报告波动。本页只测数据变换，不训练模型，不生成虚构的准确率或损失曲线。

### 3.3.1 数据规模影响

规模应同时报告独立库存、实际训练曝光与模型参数量。实验一将预算从 60 提到 120，库存不变，曝光从 36/18/6 变为 72/36/12。科学材料此时重复 3.6 轮；“读过 120 个”不等于“拥有 120 个不同词元”。

第一版介绍的 Chinchilla 研究在既定训练计算下联合选择模型大小与数据量，其 70B 参数、1.4T 训练词元是历史实验配置，不是任意任务的固定比例法则。长推理服务寿命、不同数据质量和不同训练目标会改变取舍；本页三来源小算例不能验证缩放律。

### 3.3.2 数据质量影响

质量需绑定任务与独立评估：文档抽取完整、重复少、许可可用、事实可靠并非同一轴。过滤后的训练损失下降可能来自材料更简单，也可能来自训练/评估重叠，不能单凭这一个数宣称能力增强。

实验二阈值 0.5 只保留 A 作为三者的教学代表时，C 独有的 `ef` 也会丢失。这显示去重可能误伤新信息，需检查簇大小、代表选择和长文局部重叠；不能将“删除比例最大”定义为最好。第一版也提醒其数据研究很多基于较小模型，不能无条件外推到更大训练。

### 3.3.3 数据多样性影响

多样性包含语言、领域、文体、时间和观点。来源标签不同，不保证内容独立；同一报道可能被几十个站点转载。随机打乱顺序只能减少顺序偏差，不能恢复已经删除的小语种材料，也不能让镜像变成新内容。

实验一保持预算 60，将科学权重由 3 改到 6，最大余数法得到 28/28/4，而非三项都增加。实验二跨源比较提醒我们来源多不等于独立样本多；实验三的统一分词口径则防止把字节多误读成曝光多。实际应按语言、时间和任务切片评估，不用来源数量替代多样性结论。

## 3.4 开源数据集合

以下是第一版成稿语境中的历史数据集合，不是当前下载承诺。单位必须逐项读：GiB/TB 是文本体积，B/T token 是特定切分口径下的词元数，不能直接相加。本页没有下载或重放任何大型语料。

| 集合       | 历史规模与组成                                 | 对应本页哪种机制           | 使用边界                                       |
| ---------- | ---------------------------------------------- | -------------------------- | ---------------------------------------------- |
| Pile       | 论文称约 825 GiB 英文文本，22 个子集           | 库存不等于加权曝光         | 子集分别溯源，不把集合名当统一授权             |
| ROOTS      | 约 1.6 TB，46 种自然语言与 13 种编程语言       | 按语言分层过滤、混合       | 语言覆盖不等于等权；逐来源检查权利与访问条件   |
| RefinedWeb | 构建规模约 5T token，公开提取部分约 600B token | 网页过滤与大规模去重       | 全量构建规模不等于可下载部分；底层网页权利另核 |
| SlimPajama | 从约 1.21T 到名义 627B token                   | 清洗、全局去重及保留集复查 | 书内历史值；维护方数据卡本次未成功访问         |

### 3.4.1 Pile

[Pile 原论文](https://arxiv.org/abs/2101.00027)以多来源英文数据扩展训练分布，包括网页、学术材料、代码、书籍与对话等共 22 个子集。第一版以约 800GB 概述，论文使用约 825 GiB，口径不应伪装成精确相等。[维护方仓库](https://github.com/EleutherAI/the-pile)的构成表还区分原始体积、轮数与有效体积：相同库存可以因重复采样得到不同曝光。

借实验一思考小体积来源的上采样，但不要把 toy 的 6:3:1 认作 Pile 权重。特别是书籍、邮件和转载内容，仓库代码许可并不自动覆盖底层内容；要逐子集审核授权、隐私及再分发条件，历史收录不是使用许可。

### 3.4.2 ROOTS

[ROOTS 原论文](https://arxiv.org/abs/2303.03915)说明其为 BigScience/BLOOM 构建的约 1.6TB 多语言集合；第一版记载 46 种自然语言、13 种编程语言。来源含已有语料、网页与代码，重点不只是体量，也包括协作治理和数据文档。

对照实验一，59 种语言类型不意味着各自获得相同 token 预算；对照实验三，跨语言实体识别不能由 ASCII 邮箱正则替代。模型许可、数据访问约定和每个来源内容许可是三层问题，不能因为 BLOOM 可获取就推断所有 ROOTS 文本可自由再分发。本次未成功读取 HF 数据卡，不宣称核实当前访问条件。

### 3.4.3 RefinedWeb

[RefinedWeb 原论文](https://arxiv.org/abs/2306.01116)讨论从 Common Crawl 建立大规模网页语料，历史全量约 5T token，公开提取部分约 600B。第一版分为文档准备、过滤与去重三个阶段，且提醒阶段统计会从文档数切换到 token；不能把不同分母的阶段百分比机械相乘。

该书介绍的近重复配置包含词级五元组及大规模候选搜索；实验二只是精确字符二元组的三文档算例，不是 RefinedWeb 重放。发布数据集的条款也不能替代网页原作者权利、个人信息处理依据和本地合规审查。本次核对到论文摘要及书内正文，未核实当前 HF 数据卡或下载可用性。

### 3.4.4 SlimPajama

第一版记载 Cerebras 将 RedPajama 的约 1.21T 词元清洗、去重到名义 627B，处理含规范化、短文档过滤、全局去重、交错重排、切分与训练/保留集复查。NFC 是 Unicode 规范化：把规范等价序列化到组合形式，并不等于删除所有非 Unicode 或“特殊”字符。

书中的训练/保留集最终复查使用 SHA256 精确匹配。精确匹配与实验二的近重复不是同一保证，不能因此宣称没有语义污染。[维护方数据卡链接](https://huggingface.co/datasets/cerebras/SlimPajama-627B)本次请求超时，规模依据书内可读正文；未核对当前发布文件数、许可版本、下载状态或吞吐。上游各来源许可依然要单独审查。

## 3.5 实践思考

将下面完整代码保存为 `data_lab.py`，使用 Python 3.10 或更新版本运行 `python3 data_lab.py`。只用标准库，无网络、无 SDK、无外部数据。输入六条手写记录，不是 Pile 等数据集的采样。A/B/C 的字符二元组集合与实验二完全相同；另外三条分别代表抽取失败、受限邮箱和评估样本。

先预测：五条通过低质规则的记录经过按簇保留首条会剩几条？再剔除包含 `eval KEY` 的记录会剩几条？对照输出中的阶段计数和逐步断言，而不是只看“程序执行成功”。

```python
import hashlib
import json
import re
import unicodedata
from fractions import Fraction
from itertools import combinations

RAW = "mail a@b.io eval KEY"
VOCAB = ["[EMAIL]", "mail", "eval", "KEY"]
EMAIL = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}")
BENCHMARK = "eval KEY"


def allocate(total, weights):
    exact = [Fraction(total * w, sum(weights)) for w in weights]
    counts = [int(x) for x in exact]
    order = sorted(range(len(weights)), key=lambda i: (-(exact[i] - counts[i]), i))
    for i in order[:total - sum(counts)]:
        counts[i] += 1
    return counts


def shingles(text):
    text = "".join(text.split())
    return {text[i:i + 2] for i in range(len(text) - 1)}


def jaccard(a, b):
    union = a | b
    return Fraction(len(a & b), len(union)) if union else Fraction(1)


def clusters(texts, threshold):
    parents = list(range(len(texts)))

    def root(i):
        while parents[i] != i:
            i = parents[i]
        return i

    for i, j in combinations(range(len(texts)), 2):
        if jaccard(shingles(texts[i]), shingles(texts[j])) >= threshold:
            parents[root(j)] = root(i)
    groups = {}
    for i in range(len(texts)):
        groups.setdefault(root(i), []).append(i)
    return list(groups.values())


def tokenize(text, atomic=True):
    # Fixed toy vocabulary, NOT BPE training. Offsets refer to this text.
    out, i = [], 0
    while i < len(text):
        if text[i] == " ":
            i += 1
            continue
        token = next((v for v in VOCAB if (atomic or v != "[EMAIL]")
                      and text.startswith(v, i)), text[i])
        out.append((token, i, i + len(token)))
        i += len(token)
    return out


def stream(wrong_order=False, atomic=True, check_eval=True):
    text = RAW if wrong_order else EMAIL.sub("[EMAIL]", RAW)
    tokens = tokenize(text, atomic)
    if wrong_order:
        # Intentionally wrong: regex only sees each token, not the full text.
        tokens = [(EMAIL.sub("[EMAIL]", t), a, b) for t, a, b in tokens]
    return text, tokens, [] if check_eval and BENCHMARK in text else tokens


assert allocate(60, [6, 3, 1]) == [36, 18, 6]
assert allocate(120, [6, 3, 1]) == [72, 36, 12]
assert allocate(60, [6, 6, 1]) == [28, 28, 4]
assert allocate(60, [6, 3, 0]) == [40, 20, 0]
a, b, c = map(shingles, ["abcd", "abce", "bcef"])
assert a == {"ab", "bc", "cd"}
assert [jaccard(a, b), jaccard(b, c), jaccard(a, c)] == [Fraction(1, 2), Fraction(1, 2), Fraction(1, 5)]
assert clusters(["abcd", "abce", "bcef"], Fraction(1, 2)) == [[0, 1, 2]]
assert clusters(["abcd", "abce", "bcef"], Fraction(3, 5)) == [[0], [1], [2]]
safe_text, safe, safe_output = stream()
_, wrong, _ = stream(wrong_order=True, check_eval=False)
_, fallback, _ = stream(atomic=False)
assert [len(safe), len(wrong), len(fallback)] == [4, 9, 10]
assert safe == [("mail", 0, 4), ("[EMAIL]", 5, 12), ("eval", 13, 17), ("KEY", 18, 21)]
assert "".join(t for t, _, _ in wrong) == "maila@b.ioevalKEY"
assert len(safe_output) == 0
assert len(stream(check_eval=False)[2]) == 4
assert unicodedata.normalize("NFC", "e\u0301") == "é"

records = [("A", "abcd"), ("B", "abce"), ("C", "bcef"),
           ("noise", "!!!"), ("private", RAW), ("exam", BENCHMARK)]
normalized = [(key, unicodedata.normalize("NFC", text)) for key, text in records]
filtered = [(key, text) for key, text in normalized if sum(ch.isalnum() for ch in text) >= 4]
groups = clusters([text for _, text in filtered], Fraction(1, 2))
representatives = [filtered[group[0]] for group in groups]
masked = [(key, EMAIL.sub("[EMAIL]", text)) for key, text in representatives]
clean = [(key, text) for key, text in masked if BENCHMARK not in text]
counts = [len(records), len(filtered), len(representatives), len(clean)]
assert counts == [6, 5, 3, 1]
assert [key for key, _ in clean] == ["A"]
assert sum(len(tokenize(text)) for _, text in clean) == 4
assert len([1 for _, text in representatives if EMAIL.search(text)]) == 1
assert len([1 for _, text in masked if BENCHMARK in text]) == 2
report = {
    "sampled": allocate(60, [6, 3, 1]),
    "jaccard": [str(jaccard(a, b)), str(jaccard(b, c)), str(jaccard(a, c))],
    "safe_offsets": safe,
    "tokens_safe_wrong_fallback": [len(safe), len(wrong), len(fallback)],
    "stage_documents": counts,
    "rejected": {"low_alnum": ["noise"], "cluster_nonrepresentatives": ["B", "C"],
                 "benchmark_exact": [key for key, text in masked if BENCHMARK in text]},
    "emitted_tokens": 4,
    "toy_vocab_sha256": hashlib.sha256(json.dumps(VOCAB).encode()).hexdigest(),
}
print(json.dumps(report, ensure_ascii=False, indent=2))
```

预期核心结果：`sampled=[36,18,6]`，`jaccard=["1/2","1/2","1/5"]`，三种切分数 `[4,9,10]`；文档数依次 `[6,5,3,1]`，最终只留 A，输出 4 个字符词元。邮箱遮蔽了 1 条，评估串剔除了 `private` 与 `exam` 两条。`KEY` 的正确 offset 是 `[18,21)`；遮蔽前则是 `[17,20)`。这些数量由本页代码实际运行核对，而非大型预训练效果。

这份脚本没有训练/测试拆分器：它以全局簇保留代表说明去重，实验二另行展示“只比较区内”的故障。真正拆分应把整簇分配到同一分区，留好分配种子，并对外部评估集再检查。此例没有并行、MinHash、存储吞吐测量、完备 PII 识别或语义污染检测，也没有模型训练收益结论。

## 小结

- 库存决定可选材料，权重与预算决定曝光；重复轮数可直接计算。
- 近重复阈值决定边，连通关系决定簇；区内无边不证明跨区无泄漏。
- 遮蔽、切分和评估排除维护不同不变量，必须各自记录位置与拒绝原因。

## 名词解释

<Glossary>
  <GlossaryItem term="词元">
    模型使用的离散文本单位。其数量取决于切分规则，不能用文件字节数直接替代。
  </GlossaryItem>
  <GlossaryItem term="shingle">
    连续字符或词元的短片段。实验二用字符二元组集合，不保留重复次数。
  </GlossaryItem>
  <GlossaryItem term="Jaccard 相似度">
    集合交集除以并集。对本章三个文档可精确穷举，生产系统可能先估计候选。
  </GlossaryItem>
  <GlossaryItem term="连通簇">
    沿边能到达的文档组。簇内任意两点不必直接相似，用于分组切分时可减少跨区泄漏。
  </GlossaryItem>
  <GlossaryItem term="个人身份信息">
    能直接或借上下文识别个人的信息。仅遮蔽一种邮箱格式不等于消除所有身份关联。
  </GlossaryItem>
  <GlossaryItem term="BPE">
    依次合并高频相邻对的子词方法。保存合并规则与词表，才能固定切分行为。
  </GlossaryItem>
  <GlossaryItem term="offset">
    当前文本内词元的起止位置。遮蔽或规范化改变文本时，必须更新映射及下标单位。
  </GlossaryItem>
</Glossary>
