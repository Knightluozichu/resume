# 部署实践与案例分析

## 学习目标

完成本章学习后，你将能够：

1. 掌握 LLM 服务的典型部署架构和各组件职责
2. 理解云 API、私有化、混合部署三种模式的适用场景与成本结构
3. 分析 RAG、Agent、代码助手等典型应用案例的架构
4. 运用量化、批处理、缓存、模型路由等成本优化策略

## 核心概念

### 部署架构

LLM 服务的典型部署架构从客户端到 GPU 包含五个组件：

<LslDeploymentCaseDiagram />

| 组件 | 职责 |
|------|------|
| API 网关 | 鉴权、限流、计费、日志 |
| 负载均衡 | 路由请求到不同推理实例，队列管理 |
| 推理引擎 | vLLM/TGI 等负责模型推理，管理 KV 缓存、批处理、量化 |
| GPU 集群 | 多卡多机部署，张量并行切分大模型 |

设计要点：网关与推理引擎解耦（独立扩缩容）、负载均衡感知推理状态（避免路由到满载实例）、推理引擎内连续批处理（提升 GPU 利用率）、全链路监控（TTFT/TPOT/端到端延迟）。

### 三种部署模式

**云 API 调用**（GPT-4/Claude/通义千问）：适合原型开发、低频调用、无敏感数据。成本按 Token 计费，无固定成本。优点是零运维、即开即用；缺点是数据出域、高频时成本高。

**私有化部署**（开源模型自建）：适合企业高频使用、敏感数据、需定制微调。成本为固定 GPU 月租，高用量时单位成本远低于云 API。优点是数据安全、可深度定制；缺点是运维复杂、GPU 投资大。

**混合部署**：简单请求用小模型自建、复杂请求路由到云 API。成本为自建固定+云 API 按量。优点是灵活、成本可控；缺点是架构复杂。

### 典型应用案例

**RAG 知识助手**：检索增强生成解决知识时效性、幻觉、私有知识、可溯源四大问题。架构：文档分块 -> 嵌入生成 -> 向量数据库 -> 检索 Top-K -> 重排序 -> 拼入 prompt 生成 -> 引用来源。是企业知识库问答的标准方案。

**Agent 工具调用**：通过 Function Calling 让模型调用外部工具（搜索、代码执行、数据库查询），实现多步规划和自动化工作流。是 AI Agent 的核心技术。

**代码助手**：Copilot 式代码补全、代码审查、重构、Bug 定位修复。显著提升研发效率，是 LLM 最成功的商业应用之一。

**客服对话**：多轮对话管理、意图识别路由、人机协作。7x24 智能服务，降低人力成本。

### 成本优化策略

| 策略 | 原理 | 效果 |
|------|------|------|
| 量化降本 | INT8/INT4 减少显存，同卡部署更大模型 | 显存降 50-75% |
| 批处理提效 | 连续批处理提升 GPU 利用率 | 吞吐提升 3-8x |
| 缓存复用 | 前缀缓存共享 prompt KV，语义缓存命中 FAQ | 降 50%+ 推理 |
| 模型路由 | 简单用小模型、复杂用大模型 | 降 50-70% 成本 |

综合策略：量化+连续批处理是基础（所有部署都该做），缓存和路由是进阶（根据场景定制）。

## 术语表

- **API 网关**：负责鉴权、限流、计费的入口组件
- **负载均衡**：将请求路由到不同推理实例的调度组件
- **RAG**：检索增强生成，用检索到的文档约束模型生成
- **Function Calling**：让模型调用外部工具的 Agent 技术
- **前缀缓存**：多请求共享相同 prompt 前缀的 KV 缓存
- **语义缓存**：对语义相同请求返回缓存结果的机制
- **模型路由**：根据请求复杂度路由到不同大小模型的策略
