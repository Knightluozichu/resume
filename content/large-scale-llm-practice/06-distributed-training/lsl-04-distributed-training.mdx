## 直觉：扩建一条生产线

一间工厂来不及完成订单，可以复制整条生产线，让各线处理不同订单；也可以把同一道工序拆给多人；还可以让不同车间接力处理前后工序。这三种扩建方式，搬运的东西并不相同。

如果每条线都保存所有库存清单，车间增加了，单个车间却仍然塞不下。还要决定谁保管哪份清单、何时借来、何时归还。停电后只找回成品而找不回生产进度，也无法可靠续工。

## 第4章 分布式训练

把一次训练更新分给多张卡，必须同时回答三个问题：每张卡拥有哪些样本和状态、一次更新前必须交换什么、故障后从哪一个共同状态续跑。加卡只有在这些关系正确时才可能加速。下面先把“切什么”与“存什么”分开，再用通信和恢复把它们接起来；本章覆盖作者稿物理页 89–133，而不是只覆盖三个策略名称。

## 4.1 分布式训练概述

<Term def="分布式作业中一个进程的编号，不是样本号或模型层号">rank</Term>
是参与计算和通信的进程身份；
<Term def="作业参与进程的总数，不一定等于数据并行副本数">world size</Term>
是身份总数。常见的一卡一进程只是部署约定，不能据此把所有进程都当作独立模型副本。单卡可能受计算速度、状态内存或数据搬运限制；不同限制需要不同拆法。

以同步更新为目标时，分布式结果应与相同全局样本、初始权重、损失归一化和优化器步骤的单机结果相符。浮点求和顺序可以带来小误差，但漏样本、重复除法和错配参数版本是算法错误。扩展效率要比较固定工作量的时间及通信/空闲占比，不能拿更大的批次和更少的更新次数冒充同一任务加速。第一实验逐一展示这些拆分；Python 用可精确复算的小数组建立参考。

## 4.2 分布式训练并行策略

三种策略的分界不是“有几台机器”，而是**切样本、切一个算子，还是切先后依赖的层**。先确定谁拥有完整模型，再确定通信发生在更新边界、层内部还是层之间。以下责任表也是第一实验的读图索引。

| 拆分对象 | 单个参与者计算什么     | 必要交换               | 解决不了什么             |
| -------- | ---------------------- | ---------------------- | ------------------------ |
| 样本     | 完整模型上的一部分样本 | 更新前汇总梯度         | 普通复制不减单卡模型状态 |
| 矩阵     | 同一层的一部分乘积     | 层内归并部分结果或输入 | 慢互联会频繁阻塞算子     |
| 层段     | 同一批样本经过的某段层 | 边界激活及反向梯度     | 填充/排空与不均衡层耗时  |

## 4.2.1 数据并行

<Term def="多个完整模型副本处理不同样本，再合并梯度进行同一步更新">
  数据并行
</Term>
（DP）在每个副本保留完整计算图。所有副本从同一权重出发，前向与反向处理不同数据，随后汇总梯度，各自执行相同优化器更新。它主要提高样本吞吐；普通
DP 不会把单卡的参数、梯度和 Adam 状态自动除以卡数。

设副本 r 有 n_r 个样本，其损失按本地样本平均得到梯度 g_r。全局梯度是先还原各副本的梯度总和，再除以全局样本量：

$$
g=\frac{\sum_r n_r g_r}{\sum_r n_r}.
$$

这个式子在说：本地样本数相等时才可以直接平均各卡均值。不等量尾批、动态样本过滤以及按有效 token 归一化时，要使用对应的真实计数，而不是机械除以进程数。

下面 Python 的八个样本被分成3个和5个，本地均值直接平均为 −42.6667，正确加权值为 −51。交互为便于读图使用等量样本：两卡的梯度2、4平均为3，初始 w=1、学习率0.1，更新后应为0.7。少一份贡献却仍除2，会错误得到0.9。实际训练不应静默丢弃超时 rank，而应中止该次更新并从共同状态恢复。

## 4.2.2 模型并行

单卡放不下模型，或一个大矩阵算得太慢时，需要拆模型本身。<Term def="把同一算子的张量分片交给多个进程协同计算">张量并行</Term>（TP）在层内拆分；<Term def="将连续模型层分成前后依赖的多个阶段">流水线并行</Term>（PP）在层间拆分。二者不是“复制模型再换一批数据”。

TP 的行切分例子：x=[1,2,3,4]，W 的四行依次为 [1,0]、[0,1]、[1,1]、[2,1]。两卡各持两行，部分积分别为[1,2]和[11,7]，求和得到完整 y=[12,9]，**不是取平均**。反向时各分片用对应 W 和输出梯度求本地输入梯度；Python 核验 dy=[2,3] 时 dx=[2,3,5,7]。另一种列切分会输出不同列块，下一算子所需布局可能要求收集，不能把所有 TP 都简化成同一个 All-Reduce。

PP 则将一批样本进一步拆成<Term def="一次送入某个流水线阶段的小批样本，可多次累积后再更新">micro-batch</Term>，让后续小批填入已经空出的前级。第一实验画的是等耗时阶段的**纯前向填充—排空**，M=4 个小批、S个阶段，需 M+S−1 个时隙：

$$
U=\frac{MS}{S(M+S-1)}=\frac{M}{M+S-1}.
$$

这个式子在说：忙格数除以所有格数就是该教学调度的占用率；两阶段为80%，四阶段为57.1%。真实训练还要反向传播、保存激活，并选择全前向后全反向或1F1B等调度；这里的占用率不是训练吞吐，也不是所有流水线方案的统一性能公式。

**预测—操作—解释—重置：**先预测两卡 DP 更新权重，再切 TP 对照[12,9]；切 PP 与四设备，拖到最后观察七列中的气泡。勾选漏贡献，DP/TP 数值偏离，PP 末段只剩3个输出。撤销故障后结果复原；“重置并行实验”应回到 DP、两设备、无故障和第1步。播放/暂停、逐步按钮与进度条都只控制当前实验。

## 4.2.3 混合并行

<Term def="同时沿样本、层段和层内张量等不同维度划分训练作业">混合并行</Term>
把三条轴组合，而不是连续使用三个名称。设 D=2、S=2、T=2，以 rank(d,s,t)=(dS+s)T+t
编号，world size=DST=8。下面固定其余两轴，只改变一轴，才得到正确通信组；Python
会验证每类组恰好覆盖所有进程一次。

| 组  | 示例成员 | 成员关系与责任                                |
| --- | -------- | --------------------------------------------- |
| DP  | [0,4]    | 同层段、同张量片；不同样本，合并对应参数梯度  |
| TP  | [0,1]    | 同副本、同层段；不同张量片，交换层内结果      |
| PP  | [0,2]    | 同副本、同张量片；相邻层段，传递激活/反向梯度 |

若每个 DP 副本每次送 b 个样本，累积 A 次才更新：

$$
B_{global}=b\,A\,D,\qquad world\_size=DST.
$$

这个式子在说：只有 DP 轴增加不同样本，TP 和 PP 轴是在合作处理它们。例如 b=2、A=2、D=2 得到8个样本，不是乘总进程数得到32。优先把频繁层内通信的 TP 放在高速互联域内，再评估 PP 边界传输和跨副本通信，具体仍受层大小、设备容量与拓扑约束。

## 4.2.4 计算设备内存优化

模型占用不是只有权重。以 Φ 个参数、FP16 权重及梯度、FP32 主权重和 Adam 两个 FP32 矩为例：P=2Φ、G=2Φ、O=(4+4+4)Φ，总计16Φ字节。<Term def="沿数据并行组拆分优化器、梯度和参数状态以消除冗余的技术">ZeRO</Term>逐阶段消除复制：阶段1分 O，阶段2再分 G，阶段3再分 P。以下是理想均分的**逐卡常驻模型状态**，不是整机内存，也不包括激活。

$$
M_0=16\Phi,\quad M_1=4\Phi+\frac{12\Phi}{D},\quad M_2=2\Phi+\frac{14\Phi}{D},\quad M_3=\frac{16\Phi}{D}.
$$

这个式子在说：未分片的项仍完整驻留，只有被分片的项除以 DP 度。Φ=十亿、D=4 时依次是16、7、5.5、4 GB（十进制，GB不等于GiB）；不是无条件“节省四分之三”。这是作者稿物理页107的状态账本口径。

阶段3计算某层前，要临时收集该层所需权重；反向后把梯度归约到 owner，更新自己持有的优化器状态，及时释放临时全参。第二实验把所有参数视为一层，因此十亿参数的常驻4 GB加临时1.5 GB得到5.5 GB；真实多层模型只聚合当前所需层，但可能预取/重叠，还需激活、通信缓冲与分配器空间。

<Term def="前向少存中间激活，在反向需要时重算它们以换取显存">激活检查点</Term>
以额外计算减少中间激活；这不是把训练状态保存到磁盘。CPU/NVMe offload
把部分状态移出 GPU，却增加主机内存和搬运开销。混合精度也有边界：BF16
的8位指数与FP32相同，但有效尾数仅7位；FP16指数5位、尾数10位。BF16范围更宽不表示精度等同FP32，数值稳定性与可用硬件都要检查。

**先算再动：**初始阶段3、四副本、1B时读常驻线，下一步看虚线临时段；末步应释放回4 GB。勾选“不释放临时全参”再走末步，当前占用停在5.5 GB；撤销故障立即恢复。改7B、两副本和阶段0/1/2看条段长度，解释哪些项没有除D。“重置显存实验”恢复阶段3、D4、1B、无故障和常驻帧。

## 4.3 分布式训练的集群架构

并行策略描述逻辑分工，集群架构决定这些分工怎样落到实际链路。即使两次作业 rank 编号完全相同，将同一 TP 组从节点内搬到跨机架，也可能改变每层等待时间。另一项选择是参数更新由一个中心服务负责，还是由所有参与者用通信原语共同完成；它与硬件拓扑相关，却不是同一问题。

## 4.3.1 高性能计算集群硬件组成

训练节点包含计算设备、主机CPU/内存、存储和网卡。数据读取先受存储与CPU解码供给限制；设备内/节点内可用专用高速互联，如NVLink/NVSwitch；跨节点则要经过网卡及交换网络。机架内的ToR交换机再连到上层交换机，spine或胖树设计意在提供更多并发路径，但上联超售、拥塞和布线都能成为瓶颈（作者稿物理页110–111）。

把上一节的8进程映射到两台四卡节点时，可以让每个 TP 小组留在节点内。PP 传输的是边界激活，DP 传输对应梯度/状态，各自消息大小和调用频率不同。下面路径表用于定位搬运，而不是声称测出了带宽；宣传中的双向总带宽不能直接代入单条消息耗时。

| 路径层级       | 搬运对象示例          | 首先检查                   |
| -------------- | --------------------- | -------------------------- |
| 存储→主机→设备 | token批次、持久检查点 | 数据供给是否使设备空等     |
| 同节点卡间     | TP部分积、分片权重    | 链路连通性及共享流量       |
| 跨节点/机架    | DP归约、PP边界张量    | 上联拥塞、消息大小、组映射 |

## 4.3.2 参数服务器架构

<Term def="集中接收工作进程梯度、维护并更新参数再分发的服务角色">
  参数服务器
</Term>
（PS）把状态管理集中起来：worker拉取权重版本v，在本地求梯度，再push给服务器；服务器聚合并更新至v+1，worker再pull新权重。同步PS等待所需worker集合完成，慢worker会拖住更新；参数分片可把中心状态分给多个服务器，但每个分片仍有明确更新责任。

异步PS可在梯度到达时更新，减少等待，却可能将基于旧权重算出的梯度应用到新权重上。Python用同一学习率展示两个顺序更新：g(w)=2w，从1开始，第二次重新计算梯度得0.64，若第二份梯度仍基于旧w=1则得0.60。这个差异不是舍入误差。选异步要接受陈旧性对优化的影响，不能宣称它只是同步DP的无损加速版。

## 4.3.3 去中心化架构

去中心化不等于“不通信”。<Term def="一组进程按同一约定协作完成归约或数据分发的通信操作">集合通信</Term>让同组进程共同完成同步，不必用独立参数服务器保存全部模型。All-Reduce(SUM)让每个参与者得到元素和；Reduce-Scatter(SUM)先求和、再将不同结果块交给不同owner；All-Gather把各自持有的块拼回完整结果。两阶段组合与All-Reduce求和语义等价，DP若需要平均还应且只应除D一次。

| 原语                        | 输出归属                              | 不能混淆之处        |
| --------------------------- | ------------------------------------- | ------------------- |
| Broadcast / Scatter         | 根数据复制给所有人 / 根数据分块给各人 | 复制与切分不同      |
| Reduce / Gather             | 根得到元素归约 / 根得到输入拼接       | 求和与拼接不同      |
| All-Reduce / All-Gather     | 所有人得到归约 / 所有人得到拼接       | 不都叫“平均”        |
| Reduce-Scatter / All-to-All | 各人得到一个归约块 / 各人互换指定块   | owner结果与重排不同 |

作者稿物理页112–117介绍这些集体操作及环形思路；环形只是实现方式之一。所有rank须按一致顺序、兼容的计数与数据类型调用同组操作，不能某个rank因为无数据便跳过一次。第三实验的矩阵是**语义状态**，不是消息包网络动画：四卡本地向量的第j列为(r+1)(j+1)，求和为[10,20,30,40]，平均为[2.5,5,7.5,10]。归约分散后只有对角owner格，收集后全行相同，空间结构展示了“拥有分片”和“拥有副本”的差别。

**预测并操作：**走到“owner更新”预测 w=1−0.1g=[0.75,0.5,0.25,0]；走到保存时只留下各owner块。勾选丢失最后检查点分片，恢复列出现缺口且拒绝部分加载；撤销后恢复完整向量。改两rank观察矩阵由4×4变2×2；“重置通信实验”恢复四rank、无故障和本地向量帧。真正文件写入、摘要与下一步一致性由后面的 Python 验证，而非由图形宣称完成。

## 4.4 DeepSpeed实践

DeepSpeed将分布式初始化、模型/优化器包装、混合精度和状态分片组织到训练引擎中。原书先讲API、运行时和算子，再接LLaMA训练流程（物理页117–132）。它不是替模型自动决定数据含义：损失的归一化、采样器的划分、全局批次和正确恢复仍需开发者检查。

可以将执行链读成 `数据批次 → 模型前向/loss → engine.backward → engine.step → 完整检查点`。引擎决定何时积累/同步/更新，具体低精度和ZeRO配置改变状态归属。下面解释这条历史实践链的责任，不提供未经运行验证的“当前安装即成功”命令；Python复现的是其中可隔离的算术和存储不变量。

## 4.4.1 基础概念

分布式启动时，rank区分全局进程，local_rank定位节点内设备，node_rank区分节点，world_size给出总进程数。master地址和端口用于会合发现，不意味着该进程一定是集中更新参数的服务器。启动器配置不一致会在训练前就形成错误进程组，不能靠修改学习率补救。

`deepspeed.initialize`包装模型、优化器和运行配置，返回引擎等对象；训练循环通过引擎反向和步进，由它协调累积与更新，而不是同时再调用一遍裸优化器step。原书在此解释ZeRO和低精度模式；当前支持项须查维护方文档。以 b=2、A=4、D=2为例，有效批次为16；在纯DP时D恰等于world size，但加上TP/PP后这个替换失效。第二实验提供内存账本，第一实验提供并行分工，二者合在一起才足以审查配置。

## 4.4.2 LLaMA分布式训练实践

原书实践（物理页122–132）不是只有启动命令：它从文本批次、分词器与模型处理开始，选择优化器和调度器，再初始化引擎，训练、评估并保存。下表把每个环节输入和失败后果展开；这是历史流程解读，不宣称本站跑过真实模型、依赖包或多机训练。

| 环节              | 需要保持的对应关系                                                      | 常见失败及检查                                                   |
| ----------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 数据与DataLoader  | 样本、token、标签与padding遮罩同批对应；分布式采样器为各DP副本分数据    | 各副本读同一份数据会重复计数；跨epoch应更新采样轮次              |
| tokenizer与模型   | 新增padding token后检查词表及embedding尺寸；padding不应产生有效预测标签 | 尺寸不匹配或把填充位置算入loss                                   |
| 优化器与scheduler | AdamW参数组处理衰减；CPUAdam或FusedAdam的选择需与offload/设备一致       | 主状态位置、学习率步数与引擎不同步                               |
| 引擎与配置        | micro-batch、累积、DP度、低精度及ZeRO阶段共同确定一步                   | 将world size误作DP度；重复step导致多更新                         |
| 训练与评估        | 前向取得loss，engine.backward再engine.step；按有效token汇总验证loss     | 各卡困惑度直接平均不等于全局困惑度；应先聚合总负对数似然再指数化 |
| 保存与恢复        | 模型权重导出和完整训练状态保存分开设计                                  | 导出文件可推理，不代表能精确续训                                 |

def pipe(stages, drop=False):
    completed, trace = {}, []
    for tick in range(4 + stages - 1):
        for s in reversed(range(stages)):
            mb = tick - s
            if not 0 <= mb < 4:
                continue
            if drop and s == stages - 1 and mb == 1:
                continue
            incoming = mb + 1 if s == 0 else completed[s - 1, mb]
            completed[s, mb] = 2 * incoming + s

def memory(stage, degree, params):
    p = 2 * params / (degree if stage == 3 else 1)
    g = 2 * params / (degree if stage >= 2 else 1)
    o = 12 * params / (degree if stage >= 1 else 1)
    return p, g, o


assert [sum(memory(s, 4, 1)) for s in range(4)] == [16, 7, 5.5, 4]

    peak = resident + 2 * 10**9 - p  # one-layer all-gather
    assert peak > resident
    assert peak - (2 * 10**9 - p) == resident  # release

def adam(state, grads):
    out = copy.deepcopy(state)
    out["step"] += 1
    t = out["step"]
    for j, g in enumerate(grads):
        out["m"][j] = 0.9 * out["m"][j] + 0.1 * g
        out["v"][j] = 0.99 * out["v"][j] + 0.01 * g * g
        mhat = out["m"][j] / (1 - 0.9**t)
        vhat = out["v"][j] / (1 - 0.99**t)
        out["w"][j] -= 0.01 * mhat / (math.sqrt(vhat) + 1e-8)
    out["cursor"] += 8
    return out

## 4.5 实践思考

选型先写约束，再决定策略：若模型和状态已经装得下，样本吞吐不足可先用DP；若复制的优化器状态挤占显存，可评估ZeRO及激活重算；单层本身仍过大时再考虑TP；模型层多、节点间互联较慢时可评估PP，但必须检查边界激活和气泡。没有“卡越多越该用同一方案”的规则。

使用混合并行时应固定相同全局样本和更新次数，分别记录常驻/峰值显存、有效token吞吐、通信等待、流水线空闲和检查点恢复时间，再与小规模参考比较数值。当前教学实验只能证明小数组上的计算关系和模拟文件恢复，不能替代这些设备测量。遇到漏rank或缺分片时，先阻止不完整更新，再修复参与集合/文件，最后重新核验；吞吐漂亮不是继续训练的许可。

## 常见误区：把资源数字当成正确性

### 卡数增加，单卡就一定能放下

**现象：**两卡普通DP仍然显存溢出。**原因：**它复制完整模型、梯度和优化器，扩展的是样本计算，不是单卡状态容量。**修正：**用第二实验分清P/G/O，先确定哪一项超预算，再评估ZeRO、激活重算或模型并行，不能把DP卡数直接代入整个显存除法。这是“模型放不下”场景选错DP的反例。

### 求和、平均和拼接都叫同步

**现象：**TP的[12,9]被除2，或DP在求平均后又除D一次。**原因：**层内部分积需要求和，而DP的均值来自样本/有效token归一化；All-Gather只是拼接。**修正：**在每个collective前后写出张量布局、归约算子和计数，用第三实验逐格复算；不等量本地批次用加权合并。

### 能载入权重，就能原地续训

**现象：**恢复后首步loss接近，随后轨迹分叉。**原因：**只存w遗漏Adam矩、随机状态或数据位置；有时还静默跳过缺片。**修正：**要求全分片完整、摘要正确且同一更新步，恢复后比较下一步而非只比较静态w。激活重算并不能替代持久检查点。

## 小结与练习

- DP切样本、TP切算子、PP切层，通信责任不同。
- ZeRO只把已分片的项除D，常驻不等于峰值。
- 完整恢复要重建状态与进度，并复算下一步。

## 名词解释

<Glossary>
  <GlossaryItem term="rank">
    一个训练进程的全局编号；同一编号必须在计算、通信和存档时对应同一身份。
  </GlossaryItem>
  <GlossaryItem term="world size">
    整个作业的进程总数；混合并行时包含协作处理同一份样本的进程。
  </GlossaryItem>
  <GlossaryItem term="数据并行">
    完整模型的多个副本各算不同样本，然后合并梯度执行同一步更新。
  </GlossaryItem>
  <GlossaryItem term="张量并行">
    把同一层的矩阵等张量切开，多进程合做一个算子并归并所需结果。
  </GlossaryItem>
  <GlossaryItem term="流水线并行">
    把前后相接的模型层分给不同阶段，小批样本逐段接力。
  </GlossaryItem>
  <GlossaryItem term="micro-batch">
    一次进入模型或流水线阶段的小批样本；多个小批可以共同组成一次更新。
  </GlossaryItem>
  <GlossaryItem term="混合并行">
    同时沿数据、层段、张量等不同轴切分，分别建立对应进程组。
  </GlossaryItem>
  <GlossaryItem term="ZeRO">
    把原本重复保存的模型训练状态沿DP组分片，用通信临时补齐计算所需部分。
  </GlossaryItem>
  <GlossaryItem term="激活检查点">
    少存前向中间结果，反向时重算；它不负责断电后的持久恢复。
  </GlossaryItem>
  <GlossaryItem term="参数服务器">
    接收工作进程梯度并负责维护、更新和分发参数的服务角色。
  </GlossaryItem>
  <GlossaryItem term="集合通信">
    一组进程共同执行求和、收集或分发，所有成员须遵守一致的调用约定。
  </GlossaryItem>
  <GlossaryItem term="检查点">
    保存足够状态以恢复同一训练步，包括权重、优化器、调度器、随机数和数据进度。
  </GlossaryItem>
</Glossary>
