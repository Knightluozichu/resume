## 为什么不只给机器看更多范例

工厂里，一位熟练工人会做零件，不代表他能按新工单交付。我们需要把“要求是什么、怎样才算合格”成对示范，而不是把仓库里的材料全部再倒进流水线。

如果检验员把工单文字也当作成品验收，或只检查练过的订单，产线看起来会越来越好，换一张新订单却可能失手。本章把示范、调整和验收拆开，让每个环节都能单独查错。

## 第5章 有监督微调

<Term def="在预训练模型上，用输入与期望回答的配对数据继续优化参数。">
  有监督微调
</Term>
（SFT）把通用续写模型进一步引向所需的回答方式。它仍可使用下一个词预测目标，但训练材料变成了带角色和任务意图的样本。改变措辞、训练权重、扩大位置范围是三件不同的事，不能用一个“效果更好”混为一谈。

本页的主线是“要求两个数的和，只回答结果”：先规定输入与回答的边界，再限制可训练参数，最后观察优化对未见数据的影响。全部交互与 Python 都是**教学算术模拟**，不下载模型，不复现真实语言训练、显存、延迟或 DeepSpeed 日志。

## 5.1 提示学习和语境学习

这两种方法先回答“能不能不训练就完成任务”。它们在推理时修改模型看到的输入，通常不执行反向传播。与之相比，SFT 在训练后留下可持久化的参数变化。可把同一任务的实现分成下表三种操作，不能把上下文中临时出现的范例当成模型已经学入权重。

| 操作     | 输入中的变化           | 权重中的变化 | 移除范例后           |
| -------- | ---------------------- | ------------ | -------------------- |
| 人工提示 | 增加任务说明、输出约束 | 无           | 说明不再可见         |
| 语境学习 | 增加若干输入—答案范例  | 无           | 不应假定仍能利用范例 |
| SFT      | 把任务配对送进训练     | 有梯度更新   | 保留训练后的参数     |

### 5.1.1 提示学习

<Term def="把任务改写成语言模型可以续写或填空的文本形式。">提示学习</Term>
包含提示添加、答案搜索和答案映射。例子：“判断情感：今天很顺利。答案是___”，候选输出“好”再映射到标签“正面”。映射是任务设计者定义的规则，不是输出词天然带有标签编号。

同一输入换模板会改变候选答案概率；分类时需固定候选词、分词与多词答案的计分法。手工写提示通常不改模型参数，软提示调优则有可训练向量，不能把所有带“提示”二字的方法都说成零训练。序列实验中的 USER 与 ASST 边界就是输入格式的一部分，而非可随意删去的装饰。

### 5.1.2 语境学习

<Term def="在一次推理的输入中放入任务示例，再续写新样本答案，不更新权重。">
  语境学习
</Term>
（ICL）可用“1+1→2；2+1→3；2+2→”表达。模型依据当前上下文续写，不把这一次调用保存为训练结果。示例选择、顺序、标签词和格式都会影响结果，所以评估需冻结这些设置，并排除把测试答案塞进示例的情况。

动手试：在序列实验里切换长指令，观察角色标记后面的回答位置后移；这仅是上下文改变，不意味着模型增加了一轮训练。若只靠堆示例挤满窗口，连期望回答都被截断，后续训练更无从学习。

## 5.2 高效模型微调

全量微调让大量权重及其梯度、优化器状态参与训练；参数高效方法只开放一小部分自由度。节省的是可训练参数及相关状态，不等于消除了基座前向、反向激活或注意力开销。选择方法时先问“哪些张量允许被优化器更新”，再比较可训练参数数目、精度和任务质量。

### 5.2.1 LoRA

<Term def="冻结基座权重，以两个小矩阵的乘积表示可训练权重增量。">LoRA</Term>
令输入为 k 维、输出为 d 维，旁路秩为 r。符号如下：W₀ 是冻结的 d×k 权重；A 是
r×k；B 是 d×r；ΔW 是 d×k
增量。以下按数学行列索引展示矩阵；图中两列分别是两个基向量的像，不涉及存储布局。

$$
\Delta W=BA,\quad h=W_0x+\frac{\alpha}{r}BAx,\quad \operatorname{rank}(BA)\le r.
$$

这个式子说，输入先被 A 压到 r 个坐标，再由 B 映回输出空间；缩放 α/r 控制旁路幅度。r 限制的是**增量**，W₀ 加上增量后通常仍可满秩。可训练数由 dk 变成 r(d+k)；当 d=k=4096、r=8，分别为 16,777,216 与 65,536。

常用非零随机 A、零 B 初始化，使起点 ΔW=0，但 B 仍有梯度。如果 A、B 都为零，链式法则给两者的梯度也都是零，旁路不能起步。训练完可在兼容精度下合并权重；多个适配器切换、量化合并误差与部署实现仍需另测，不能据此保证端到端零延迟。

猜一猜：r=1 时旋转 B 的方向，增量能从线段变成有面积的图形吗？单步至第二个外积，再切 r=2；最后合并，区分 ΔW 的秩与 W 的秩。开启双零初始化看旁路怎样停住。

### 5.2.2 LoRA的变体

第一版重点讨论 AdaLoRA 与 QLoRA。AdaLoRA 把增量写成带奇异方向的因子形式，在总预算下依重要性分配不同矩阵的秩，而不是每层机械使用相同 r。敏感度的基本近似是参数值乘损失梯度的绝对值，再平滑噪声；它是裁剪依据，不是“重要层”已经被证明拥有某种语义能力。

<Term def="量化保存冻结基座，并通过低秩适配器微调的节省显存方法。">QLoRA</Term>
不把所有训练张量都变成 4 位：冻结基座用 NF4
等方式存储，计算时解量化，适配器和梯度采用更高精度。NF4
利用近似正态权重分布设计码点；双重量化进一步压缩块级缩放系数；分页优化器缓解显存峰值。这三项分工不同。

手算存储边界：64 个权重共享一个 32 位缩放数，仅缩放元数据就增加 32/64=0.5 位/权重；它说明“4 位基座”不等于整个训练只需参数量乘 4 位。二维实验的 r=2 甚至比全量参数更多，提醒我们低秩只在 r 远小于层宽时节省参数。

## 5.3 模型上下文窗口扩展

训练时见过的位置范围，并不自动覆盖更长输入。扩窗至少涉及位置表示、长序列训练样本和注意力内存；只把配置的最大长度改大，可能运行成功但检索细节失败。应把“窗口能容纳多少 token”和“模型能可靠利用多少信息”分开检查，前者可由序列实验直接看到，后者需要长度分桶任务评估。

### 5.3.1 具有外推能力的位置编码

<Term def="在注意力打分中加入与查询键距离成比例的负偏置。">ALiBi</Term>
给不同注意力头不同斜率，让距离越远的键受到越大的惩罚。对因果位置 j≤i，可以用
softmax(sᵢⱼ−mₕ(i−j)) 理解：斜率 mₕ
固定，不是新增一张任意长度的位置嵌入表。它提供偏好近邻的归纳偏置，但不能保证所有远距离任务都正确。

例如查询位置 i=6、斜率 0.25，键在 j=2、5、6 时，logit 偏置依次为 −1、−0.25、0。距离相同，惩罚相同；未来位置还须独立施加因果掩码。第一版该段中文写“Softmax 后”，但式 5.9 把偏置放在 Softmax **内**；本页按该式及 ALiBi 原论文使用归一化前的 logits，避免把概率加成负数。

### 5.3.2 插值法

<Term def="把更长序列的位置坐标压缩回原训练位置范围，再适配模型。">
  位置插值
</Term>
保留 RoPE 结构，却改变旋转角使用的位置索引。原窗口 L、目标窗口 L′ 时，使用
m′=mL/L′。它压缩相对距离，不是把 token
删除或把答案截短；新位置也不必是整数。通常仍需长上下文微调与评测，不能把论文特定实验的训练步数当成所有模型的保证。

| token 原位置 m | L=8、L′=16 时 m′ | 直接外推的坐标 |
| -------------- | ---------------- | -------------- |
| 0              | 0                | 0              |
| 7              | 3.5              | 7              |
| 8              | 4                | 8              |
| 15             | 7.5              | 15             |

先预测：第 15 个坐标压回 7.5 后，原来相隔 8 个位置的内容现在只相隔 4 个位置。范围变安全，不代表细节更可分；需要同时测短任务退化、长文数值/网址检索和粗粒度摘要。后面的 Python 对范围与相对距离做断言，不伪造长文模型准确率。

## 5.4 指令数据构建

一条记录应明确任务要求、可选输入、期望回答以及来源。采集、生成和清洗只得到记录；序列化才把它变成模型吃到的 token。数据量再大，如果角色混淆、模板漏分隔或回答标签全被屏蔽，训练目标也会错。本节实验把这条边界变成可数的格子，而非“数据已准备好”的抽象承诺。

### 5.4.1 手动构建指令

人工写作能控制约束与答案质量，但需要标注规范与复核。例如“只回答数字”对应答案“3”，不能一部分标注写“结果是3”，另一部分输出 JSON。覆盖拒答、多轮、信息不足和不同难度，比堆大量同义改写更有价值。第一版以 LIMA 说明高质量、多样化数据的重要性；这不意味着任意少量样本都能获得同样结果。

可建立一条审阅记录：来源为“本章人工算例”、任务为“两个整数相加”、答案通过独立算术核对、输出风格为“单个数字”。分组划分训练与评估时，将同一问题的改写放进同一组，避免文字不同但答案和模板已被记住。这个记录不是从公开数据集摘取，不涉及把可读性当成许可。

### 5.4.2 自动生成指令

Self-Instruct 的四个关键环节是生成任务指令、判断任务是否为分类、生成输入与输出实例、过滤低质或重复样本，再把合格任务加入池。种子任务会影响后续分布；自举不是自动提供真实性。生成“求和”例子时，必须用独立加法校验答案，不能再请同一个生成器说“我认为正确”就算通过。

一个可操作的过滤对照是：“求 1 与 2 的和→3”通过；“求 1 与 2 的和→4”拒绝；再次生成同样问题的改写则按任务组去重。保存生成模型版本、提示、种子来源、过滤理由和许可约束，才能追溯错误如何进入训练。生成过程中不要把最终测试集用作种子。

### 5.4.3 开源指令数据集

第一版列出传统 NLP 任务指令与通用对话指令两类，举例包括 FLAN、Super-Natural Instructions、Dolly、LIMA、Self-Instruct、Alpaca 和 BELLE。它们的语言、标注来源与任务结构不同，不能仅凭“条数多”排序。选择时查实际版本的数据卡与许可，检查是否包含所用评测、个人信息或模型生成内容，避免把历史表中的规模当成当前下载版本。

<Term def="每个位置是否参与监督损失的目标筛选；忽略值不等于遮住输入。">
  标签掩码
</Term>
是本页额外展开的数据实现细节：回答专用训练把用户内容和 padding 的 label 设为
−100，同时保留它们作为输入。因果模型的位置 t−1 的输出预测位置 t
的标签；不要提前手工移位后又让框架移位一次。attention mask 管输入可见性，label
mask 管损失项，两者不是同一数组。

猜一猜：把长指令限制为八个位置，会剩几个可训练回答？先逐步查看原始序列、截断、标签和分母；再开“用户也计 loss”，观察新增的目标。图用固定词表与空格分词，不冒充任何模型的真实 tokenizer。

## 5.5 DeepSpeed-Chat SFT实践

第一版的这一节属于 2023—2024 年历史代码轨道，只讲 DeepSpeed-Chat 三阶段中的第一阶段：以 prompt 与 chosen 回答训练策略模型。奖励模型、rejected 比较目标与 PPO 不在本阶段执行。本页解释各文件的职责，并用独立算术模拟验证数据和更新逻辑；不声称运行了原书多卡脚本、下载了百川模型或复现其困惑度。

### 5.5.1 代码结构

原书将训练入口放在 `training/step1_supervised_finetuning/main.py`，训练配置在其 `training_scripts`，评估入口包括 `prompt_eval.py`，共享的数据/模型工具在 `training/utils`；交互推理属于 `inference`。理解这层分工，才能知道更换数据适配器不会自动更换评估集，更换模型路径也不会自动适配聊天格式。

| 工件       | 检查的问题                     | 本页可运行替身       |
| ---------- | ------------------------------ | -------------------- |
| 数据适配器 | prompt/chosen 是否拼对         | serialize 与标签断言 |
| 模型构造   | 词表、输出头、特殊符号是否一致 | 固定词表 ID 范围检查 |
| 训练入口   | 优化器到底更新谁               | 两参数梯度轨迹       |
| 评估入口   | 是否真使用留出数据             | 训练/留出双曲线      |

当前仓库目录与依赖可能变化；移植需锁定提交、Python/CUDA/库版本与硬件。本表是职责对照，不是可以直接执行的当前 SDK 教程。

### 5.5.2 数据预处理

历史接口从每条样本取 prompt 与 chosen；SFT 不使用 rejected 构造偏好损失。真正送入训练前，应固定分隔符、结束符、截断侧、padding 侧以及标签策略。**本页选择回答专用损失，并不声称所有历史 DeepSpeed-Chat 版本默认如此**；复现某一提交必须检查其 collator 与 labels 构造。

设 x 是 token 序列、mₜ 表示当前位置是否作为监督目标，pθ 是模型条件概率，则：

$$
\mathcal L=-\frac{\sum_{t=1}^{T-1}m_t\log p_\theta(x_t\mid x_{<t})}{\sum_{t=1}^{T-1}m_t}.
$$

这个式子只平均真正受监督的目标项，不把 padding 长度算进分母。短样本中“3”和 EOS 共两项；若它们的假设预测概率为 0.25、0.5，则均值为 (−ln0.25−ln0.5)/2≈1.0397。若截断让分母为零，应拒绝或重处理该样本，而不是用一个常数分母悄悄继续训练。

### 5.5.3 自定义模型

模型替换必须同步核对 tokenizer、词表大小、输出头、特殊 token、精度和前向返回的 logits/loss。原书展示了 Baichuan-7B 的自定义类接入，并涉及 tokenizer 与配置适配；这说明只改一个模型路径未必够用，不代表那段历史加载代码今天还能不改运行。

小规模检查顺序可以是：先验证 token ID 全在词表内；再用一条样本跑前向看 logits 的序列长度与词表维；接着核对有效 label 数；最后只运行一次反向看梯度落在哪些张量。LoRA 模式应冻结 W₀，优化器仅收 A/B；量化基座也不能误入高精度全量更新。下方 Python 对冻结与双零梯度做算术检查，但不加载任何模型类。

### 5.5.4 模型训练

一次训练更新先前向算损失，再反向算梯度，最后优化器修改允许训练的参数；保存检查点还应保存优化器、调度器、随机状态和数据进度，才能继续同一轨迹。微批梯度累积要区分“处理了多少样本”与“更新了几次参数”，多卡日志中的 loss 也不能不经归约就代表全局平均。

第三个实验用两参数二元逻辑回归展示真正的梯度：z=wₛxₛ+wₙxₙ，p=σ(z)，每个权重的梯度是 (p−y)x。训练集中干扰特征恰好与答案同向，留出集中却反向；更新两个权重可以降低训练损失，同时损害留出损失。它有实际计算的参数差分，不是把一个滑块映射成任意“质量分”。

猜一猜：五次更新后，训练损失和留出损失一定同向变化吗？播放后切换“只更新信号权重”，比较干扰权重条；再开启训练集冒充评估，检查曲线没变但报告为何变漂亮。重置会恢复学习率、更新范围、故障与进度。

### 5.5.5 模型推理

训练后的模型在推理时不需要 optimizer.step；应加载选定检查点及匹配的 tokenizer/适配器，用与训练一致的聊天模板构造前缀，只让模型续写回答。用户输入不能被误当作新一条 assistant 回答。EOS、最大生成长度、采样温度等设置影响结果，需要与权重版本一起记录。

原书以命令行 `chat.py` 示范交互推理；几轮对话正常只是烟雾测试。正式验收至少分开发集选择与最终测试，报告指令遵循、事实性、拒答以及目标任务指标。困惑度是平均 token 预测难度，不是“回答正确率”；也不能把训练中选过最佳检查点的同一集合继续称为最终独立测试。本页逻辑回归的留出损失同样不能转换成真实模型能力结论。

## 5.6 实践思考

第一版提出的开放问题包括：指令微调更像学格式还是注入知识，高质量样本数量与模型规模如何相互影响，输出中中英文符号、JSONL/列表形式怎样改变结果，以及数值计算和长上下文细节能否可靠保持。它们要求拆变量实验，不是从一个训练 loss 推出“模型已经会推理”。

对于求和任务，可分别测试熟悉数字、未见数字位数和不同符号表达。若错误只在较长输入出现，先检查是否截断；若标签正确而未见组合失败，再考虑数据覆盖与能力边界。允许工具的任务应单列工具调用结果，不把外部计算器的正确性写成模型自身算术能力。长窗口还应分开测试“话题记得”与“具体金额/网址记得”。

## 独立可执行 Python：序列、低秩与更新

以下整块保存为 `sft_arithmetic.py`，用 Python 3 标准库直接运行。它完整重建本页的序列化、标签计数、外积、位置映射和梯度下降；含预期失败、拒绝与恢复。为方便独立复制保留单一完整代码块；概率只是指定的教学数值，梯度实验是逻辑回归，不是真实 LLM 训练或历史日志回放。

```python
import json
import math

VOCAB = ["PAD", "BOS", "USER", "ASST", "EOS", "求和", "1", "2", "3",
         "请", "先", "阅读", "规则", "再", "计算", "数字", "并", "只答"]

def serialize(long=False, limit=16, prompt_loss=False):
    prompt = "请 先 阅读 规则 再 计算 数字 1 2 并 只答" if long else "求和 1 2"
    tokens = ["BOS", "USER"] + prompt.split() + ["ASST", "3", "EOS"]
    start = tokens.index("ASST") + 1
    tokens = (tokens + ["PAD"] * limit)[:limit]
    ids = [VOCAB.index(t) for t in tokens]
    labels = [v if t != "PAD" and i > 0 and (prompt_loss or i >= start)
              else -100 for i, (t, v) in enumerate(zip(tokens, ids))]
    # Position i-1 predicts label i: each pair keeps its original target coordinate.
    pairs = [(i-1, label) for i, label in enumerate(labels) if label != -100]
    if not pairs:
        raise ValueError("no supervised target after truncation")
    return tokens, ids, labels, pairs

short = serialize()
assert short[0][:8] == ["BOS", "USER", "求和", "1", "2", "ASST", "3", "EOS"]
assert short[3] == [(5, 8), (6, 4)]
assert short[2][8:] == [-100] * 8
assert len(serialize(prompt_loss=True)[3]) == 7
assert all(0 <= i < len(VOCAB) for i in short[1])
try:
    serialize(long=True, limit=8)
    raise AssertionError("truncated answer was accepted")
except ValueError:
    pass  # Expected rejection; recover by increasing the length, not masking the error.
assert len(serialize(long=True, limit=16)[3]) == 2
nll = -(math.log(.25) + math.log(.5)) / 2
assert abs(nll - 1.0397207708399179) < 1e-12

def matmul(b, a):
    return [[sum(b[i][q] * a[q][j] for q in range(len(a)))
             for j in range(len(a[0]))] for i in range(len(b))]

def det(m):
    return m[0][0]*m[1][1] - m[0][1]*m[1][0]

w0 = [[1., 0.], [0., 1.]]
frozen = [row[:] for row in w0]
a, b = [[1., 0.]], [[1.], [0.]]
delta = matmul(b, a)
assert det(delta) == 0
merged = [[w0[i][j]+delta[i][j] for j in range(2)] for i in range(2)]
assert det(merged) == 2  # The merged matrix need not be rank one.
assert abs(det(matmul([[1., 0.], [0., .6]], w0)) - .6) < 1e-12
assert w0 == frozen
# dL/dDelta=[[-1,0],[0,-1]]; dL/dB=G A^T and dL/dA=B^T G.
g = [[-1., 0.], [0., -1.]]
zero = [[0., 0.], [0., 0.]]
assert matmul(g, zero) == zero and matmul(zero, g) == zero
assert matmul(g, w0) != zero  # Nonzero A permits B to start learning.
assert 8*(4096+4096) == 65536 < 4096*4096
positions = [m*8/16 for m in range(16)]
assert max(positions) < 8 and positions[15] == 7.5
assert positions[12] - positions[4] == 4
assert [-.25*(6-j) for j in [2, 5, 6]] == [-1., -.25, 0.]

train = [((1., 1.), 1), ((-1., -1.), 0)]
heldout = [((1., -2.), 1), ((-1., 2.), 0)]
assert not set(train).intersection(heldout)

def loss(w, data):
    # Stable binary CE: softplus(z) - y*z.
    values = []
    for x, y in data:
        z = sum(a*b for a, b in zip(w, x))
        values.append(max(z, 0) + math.log1p(math.exp(-abs(z))) - y*z)
    return sum(values)/len(values)

def run(rate=.8, freeze=False):
    w, trace = [.4, 0.], []
    for step in range(6):
        trace.append(dict(step=step, w=w[:], train=loss(w, train),
                          heldout=loss(w, heldout)))
        if step == 5:
            break
        grad = [0., 0.]
        for x, y in train:
            p = 1/(1+math.exp(-sum(a*b for a,b in zip(w,x))))
            for j in range(2):
                grad[j] += (p-y)*x[j]/len(train)
        w = [w[j]-rate*grad[j] if j == 0 or not freeze else w[j]
             for j in range(2)]
    return trace

full, restricted = run(), run(freeze=True)
assert full[-1]["train"] < full[0]["train"]
assert full[-1]["heldout"] > full[0]["heldout"]
assert restricted[-1]["heldout"] < restricted[0]["heldout"]
assert restricted[-1]["w"][1] == 0
try:
    evaluation_data = train  # Deliberate leakage fault.
    assert evaluation_data is not train, "training data is not heldout evaluation"
    raise RuntimeError("fault was not detected")
except AssertionError:
    evaluation_data = heldout  # Recovery uses the independent set.
assert loss(full[-1]["w"], evaluation_data) == full[-1]["heldout"]
print(json.dumps(dict(mask_targets=len(short[3]), nll=nll,
                      full=full, restricted=restricted), indent=2))
```

序列部分对应标签格里的 ID 和 −100，矩阵部分对应线段/面积与冻结基座，训练循环对应每个时间线步的真实参数。可以把 `rate` 改为 0.2，比对浏览器的小步长轨迹。最终输出同时保留训练与留出值，防止只复制更好看的一列。

## 常见误区

<Callout type="trap" title="屏蔽 label 就是屏蔽输入？">
  **现象 →** 回答看不到用户要求。**原因 →** 把回答专用标签策略错做成 attention
  遮挡。**修法 →** 用户 token
  仍在输入；只把它们的监督目标置为忽略值，并核对因果移位。
</Callout>

<Callout type="trap" title="两个零矩阵最安全？">
  **现象 →** LoRA 增量一直为零。**原因 →** A、B
  同时为零，两个因子的梯度都为零。**修法 →** 保留非零 A、零 B
  的起点；实验里关闭双零故障，观察第一列重新出现。
</Callout>

<Callout type="trap" title="loss 变小就能发布？">
  **现象 →** 训练数字漂亮，换输入却更差。**原因 →**
  学到训练特有相关性，或用训练集冒充评估。**修法 →**
  固定开发/最终测试划分，检查参数差分、长度桶和泄漏，不以单条演示代替验收。
</Callout>

## 小结

- 回答标签与输入可见性分开，截断后要数有效目标。
- LoRA 的低秩约束作用于增量，合并矩阵未必低秩。
- 梯度下降只优化所给目标，留出评估才揭示迁移失败。
