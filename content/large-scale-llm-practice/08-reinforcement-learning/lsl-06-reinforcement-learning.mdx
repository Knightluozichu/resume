## 为什么只模仿成品还不够

工厂给两件成品排优劣，比为每件成品写一份唯一标准图纸容易。文字回答也一样：同一个问题可能有许多合理写法，只照着一份答案生产，无法直接比较完整回答是否更有用。

但检验员也会看走眼。如果生产线只追逐检验分数，就可能专门生产“容易得高分”的次品。本章既要解释怎样利用比较意见改进回答，也要解释为什么高分不能替代独立验货。

## 第6章 强化学习

本章的核心是把“比较两个完整回答”转成“调整下一次生成的概率”。第一版正文在作者稿物理页 162–187（印刷页 148–173）依次讲反馈流程、奖励模型、近端策略优化、MOSS-RLHF 与实践风险。这里以同一个偏好对和三步回复串联这些内容：先学会评分，再追踪信用分配，最后限制策略更新；不是把奖励上升当作真实性的证明。

## 6.1 基于人类反馈的强化学习

<Term def="先用人的比较意见学评分，再用评分改善生成策略的训练路线">RLHF</Term>
把人类反馈变成可重复使用的训练信号。人不必给每次采样都写标准答案，而是先比较候选回复；训练得到的评分器代替大量在线人工打分，再由策略优化算法改变生成分布。偏好中的有用、真实、无害可能冲突，评分器只是特定数据和标注规则下的代理，不能自动代表所有用户。

### 6.1.1 强化学习概述

生成文本可建模为一个逐步决策过程：状态是提示加已生成前缀，动作是下一 token，状态转移是把 token 拼到前缀后，结束符或长度上限使轨迹停止。若把完成决策所需信息纳入状态，这对应马尔可夫决策过程（MDP）；截断上下文可能丢失信息，所以建模假设要单列。

策略 π 给每个动作一个概率，而非只取最高分。状态价值 V 估计从当前前缀继续生成的期望回报；动作价值 Q 则先指定这一步动作。折扣 γ 调整远期奖励权重。基于价值的方法由价值推导行动，基于策略的方法直接调整行动概率，演员—评论员方法同时学策略和 V；第二个教具把这两类量分开展示。

### 6.1.2 强化学习与有监督学习的区别

有监督微调（SFT）通常在固定的提示—示范答案上最小化 token 负对数似然。它告诉模型“这个前缀之后应接哪个词”；RL 路线则由当前策略采样，反馈可以只在整条回复结束时出现。差别不只是换一种损失，还包括数据随策略改变，以及如何把末尾反馈分摊给前面动作。

SFT 可以用多答案和高质量拒答示范，不能简单说它只允许唯一表述；RL 也不是天然消除幻觉。只有奖励真的惩罚无依据断言、覆盖适当拒答并能泛化，策略优化才可能减少该类错误。第一个教具中“较长但答错”的回复就是长度捷径反例。

### 6.1.3 基于人类反馈的强化学习流程

常见路线是先 SFT，再收集同提示候选偏好训练评分器，然后反复采样、计算回报、优化策略。PPO 版 RLHF 有四个逻辑角色，是否共享底座是实现选择，不应把四个角色误说成四份必然独立的硬件副本。

| 角色   | 输入与输出                   | PPO 阶段是否更新    |
| ------ | ---------------------------- | ------------------- |
| 策略   | 提示、前缀 → 下一 token 分布 | 是                  |
| 奖励   | 提示、完整回复 → 标量分数    | 通常冻结            |
| 评论员 | 每个前缀 → 未来回报估计 V    | 是                  |
| 参考   | 相同前缀 → 固定分布          | 否，通常从 SFT 冻结 |

此外还要保留采样时的“旧策略”对数概率，用于 PPO 新旧比率。参考策略用于约束远离起点，旧策略用于衡量一次更新相对采样分布的变化：两者即使初始相同，也不是同一个概念。

## 6.2 奖励模型

<Term def="根据提示和完整回答输出标量、通过人类偏好比较训练的评分函数">
  奖励模型
</Term>
学的是回答之间的相对排序，不是词元预测，也不是天然校准的质量百分比。末端隐状态接标量头是一种常见实现；训练比较两条回复分数的差，整体分数加同一个常数不会改变偏好概率。下面用二维线性函数代替神经网络，使每次更新可手算。

### 6.2.1 数据收集

每条记录至少需要同一个提示 x、较好回答 y_w、较差回答 y_l、比较准则与来源。若两个回答对应不同提示，分差混入题目难度，便不再是有效的同题偏好。候选最好来自目标策略可能产生的分布，标注要分开记录帮助性、事实性与风险，允许不确定或分歧，而非强造唯一真值。

第一版讨论 Anthropic 的有用性/无害性收集，包含通过敌对对话寻找有害输出的过程。收集时选择更有害内容以继续红队对话，不意味着最终训练标签应该奖励有害回答。使用发布数据时必须核对其 chosen/rejected 语义，不能直接依据界面操作方向推断标签。按提示或对话分组划分训练/验证，避免同一问题的近重复泄漏。

### 6.2.2 模型训练

本节符号：r_w、r_l 为同提示两条回复的分数，d 为分差，σ 为 sigmoid，L_RM 为最小化损失，η 为学习率。配对模型采用 Bradley–Terry 形式：

$$
p_w=\sigma(d),\quad d=r_w-r_l,\quad L_{RM}=-\log\sigma(d)=\log(1+e^{-d}).
$$

这个式子在说：把较好回复分数拉到较差回复之上；并不要求某个绝对分数等于1。

令 r=w·f，教具用 f_w=[1,0] 表示简短正确、f_l=[0,1] 表示冗长错误，初始 w=[0,0]。此时 d=0、p_w=0.5、损失约0.6931。对 w 的梯度是 −(1−σ(d))(f_w−f_l)；以 η=0.5 更新，w 变成 [0.25,−0.25]，d=0.5、损失约0.4741。这是在训练真正的偏好对模型，但只有人工特征，不是语言模型训练。

先预测：翻转标签后，哪一根分数柱会变高？推进三步后比较“真实偏好损失”，再关闭故障或重置。

## 6.3 近端策略优化

<Term def="用新旧动作概率比与符号相关的截断目标，抑制过大有利更新的策略优化方法">
  PPO
</Term>
在已采样轨迹上优化策略，但不允许把某次带噪声的优势无限放大。它通常需要奖励、价值估计、旧对数概率和有效
token mask。下面先解释策略梯度为什么使用优势，再从三步数值构造优势，最后看 clip
对不同符号到底做了什么。

### 6.3.1 策略梯度

本节符号：θ 为策略参数，a_t、s_t 是动作和状态，A_t 是相对当前状态平均水平的优势，J 是最大化的期望目标。忽略与策略参数无关的环境转移导数后，轨迹的对数概率梯度是各步动作对数概率梯度之和：

$$
\nabla_\theta J=\mathbb E\left[\sum_t A_t\nabla_\theta\log\pi_\theta(a_t\mid s_t)\right].
$$

这个式子在说：正优势提高这一步动作概率，负优势降低它；权重不再是所有位置共享的整段总分。

用只依赖状态的基线 V(s_t) 从回报中扣除，不改变理想期望梯度，却能减小估计波动。估计 V 有误差时，实际优势也会有误差。把所有拿到正奖励的 token 都当作好动作，会忽略“本来这一步就能得到更高回报”的情况；因此奖励正不代表优势正。

策略与冻结参考的 <Term def="衡量两个分布差异的期望对数比；单个采样对数比不一定为正">KL 散度</Term> 常用于抑制偏移。记 k_t=log π_roll(a_t|s_t)−log π_ref(a_t|s_t)，β 为惩罚系数，R 为终点评分：

$$
r_t=\mathbf 1[t=T-1]R-\beta k_t.
$$

这个式子在说：每步减去采样对数比的代价，只在最后一步加入完整回答的奖励。这里 k_t 是 KL 的单样本估计项，可能为负；在当前策略分布下求期望才得到非负 KL。β=0 会移除这道约束，但 β 很大也可能让改进几乎停滞。

### 6.3.2 广义优势估计

<Term def="把TD残差沿时间反向加权累积，用lambda调节远期信用的优势估计方法">
  GAE
</Term>
将只看下一步与看完整回报连接起来。本节固定 γ=1，λ 调节残差传播；V_t
为评论员输出，δ_t 为 TD 残差，真正终止时 V_T=0、A_T=0：

$$
\delta_t=r_t+\gamma V_{t+1}-V_t,\qquad A_t=\delta_t+\gamma\lambda A_{t+1}.
$$

这个式子在说：先比较实际一步奖励加预测未来是否超过原预测，再把后面尚未分配的优势反向传回来。对时间上限截断而非真正结束，是否 bootstrap 要按环境语义决定，不能一律当结束符。

设 k=[0.2,−0.1,0.4]、β=0.2、R=1、V=[0.3,0.4,0.2,0]。得到 r=[−0.04,0.02,0.92]，δ=[0.06,−0.18,0.72]。λ=0.8 时，从后向前算：A_2=0.72；A_1=−0.18+0.8×0.72=0.396；A_0=0.06+0.8×0.396=0.3768。λ=0 时只剩 δ；λ=1 时在这里得到回报减 V。较大 λ 通常依赖更长采样回报、方差更大，不是无条件更准确。

猜一猜：若真正结束后仍使用 V_T=0.5，错误会只影响最后一格吗？推进到账本第三步，改变 λ，再重置核对初值。

### 6.3.3 近端策略优化算法

记 ρ_t=π_new(a_t|s_t)/π_old(a_t|s_t)，ε 为裁剪宽度。old 是产生这批轨迹的策略，不是长期冻结参考；A 在本轮策略更新中通常作为固定目标，不对其回传策略梯度。最大化的截断代理目标是：

$$
J_{clip}=\mathbb E_t\left[\min\left(\rho_t A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\right)\right].
$$

这个式子在说：只截掉“沿着当前优势方向改善得过多”的激励，不把不利变化也抹平。训练器若最小化 loss，要取整个目标的负号。

当 A=+1、ρ=1.4、ε=0.2，两分支为1.4和1.2，取1.2；当 A=−1、ρ=1.4，两分支为−1.4和−1.2，必须取−1.4。负优势的截平发生在左侧 ρ 小于0.8。PPO 不是把参数投影到硬约束集合，多个优化步后仍要监控实际 KL 与 ratio 分布。

先预测：切成负优势时平台应该出现在曲线哪一侧？播放到“取较小值”，注入“漏掉min”，再把 ρ 移到1.4观察故障。

#### 与 DPO 的边界：不是给 PPO 换一个名字

直接偏好优化（DPO）是本页补充对比，不是第一版的新增正式节。它在离线偏好对上直接更新语言策略。令 z 为同提示两回复相对参考的序列对数比之差、β_D 为温度系数：

$$
z=\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)},\qquad L_{DPO}=-\log\sigma(\beta_D z).
$$

这个式子在说：让较好回复相对参考的增益，超过较差回复的增益。这里的比率是整段回复对参考的比，不是 PPO 单动作对旧策略的比。若两个比率为1.2和0.8、β_D=0.1，损失约0.6731。

| 路线        | 训练信号                            | 典型角色与采样                          | 限制                         |
| ----------- | ----------------------------------- | --------------------------------------- | ---------------------------- |
| PPO 版 RLHF | rollout 奖励与优势                  | 显式奖励、评论员、旧策略概率、冻结参考  | 需采样和稳定性调试           |
| DPO         | 固定 chosen/rejected 的序列似然比较 | 策略与参考，无显式奖励模型/GAE/PPO clip | 离线覆盖不足与偏好噪声仍存在 |

两者都依赖偏好质量。DPO 的推导与 KL 正则化最优策略关系密切，但不能因此把 β_D 和上面的奖励惩罚 β 当作同一实现参数；不同目标与尺度要分别记录。

## 6.4 MOSS-RLHF实践

第一版在这里介绍复旦团队的 MOSS-RLHF/PPO-Max 历史实现，包含稳定训练所需的奖励、KL、价值与策略损失处理。它是源码阅读对象，而不是本页浏览器教具的后台。本次只运行下文标准库算术和前端计算；没有安装 MOSS-RLHF、下载模型、训练奖励网络或做 PPO 微调，也没有模型效果、GPU 训练耗时或吞吐证据。

### 6.4.1 奖励模型训练

原书物理页177–180附近的实现以 LLaMA 底座增加标量 reward_head，比较 preferred/rejected 奖励，可选加入 chosen 的语言建模损失。复现时要核对取的是哪个有效末 token：历史代码的末位置只有在对应 padding/拼接规则成立时才代表句末。随意把右侧 padding 的隐藏状态送进头部，会让评分依赖填充而不是答案。

配对 batch 的前后两半必须真是对应的 chosen/rejected；loss mask 应只计期望的回复位置。先用几条已知偏好验证分数方向、分差和梯度，再讨论规模。第一个教具用明确的两条特征向量完成同类方向检查，但没有模仿或执行原书 PyTorch 类。

### 6.4.2 PPO微调

原书后续代码逐步组织经验采样、奖励与 logprob、评论员值、GAE、回报，再计算价值损失和策略截断损失，并讨论可选熵项与预训练损失。实施时应保存 rollout 时的旧概率、参考概率、终止标志和回复 mask；不能在每个 minibatch 更新后把 old 概率重算成 new，否则 ratio 总接近1、裁剪失效。

第二个教具对应回报与优势检查，第三个对应策略项检查；它们刻意不覆盖价值裁剪、熵、分布式训练和优化器状态。想运行历史框架仍需固定仓库 commit、依赖、模型/数据授权、设备和训练配置。当前官方文档中的新 API 不能替换成“原书已运行”的证据。

## 6.5 实践思考

奖励投机（Reward Hacking）是策略找到评分器偏爱的捷径，而实际回答质量没有改善。原书讨论奖励迅速升高但输出重复或无意义的风险，并建议综合考察困惑度、输出长度、奖励和人工评估。加大 KL 有时抑制偏移，但不能修好错误标签、数据泄漏或有偏评分器。

应先按提示分离保留集，采用盲化、交换顺序的回答比较，同时记录正确性、帮助性、风险与长度。若使用另一模型作评委，也要报告位置偏差、提示敏感性和人工抽查，不把评委分数当绝对真值。教具的翻标故障展示“优化信号可以朝错方向走”，不是人评结果的替身；真实效能仍需另做实验。

<Callout type="trap" title="奖励分数上涨就发布？">
  **现象 →** 评分上涨，事实核验却变差。**原因 →**
  策略在追逐长度等代理特征。**修法 →** 检查盲评与分布外样例，修数据或奖励；KL
  只能限制偏移。
</Callout>

<Callout type="trap" title="clip之后直接乘优势？">
  **现象 →** 负优势且 ratio 很大时惩罚被截平。**原因 →** 漏掉 min 分支。**修法
  →** 用正负 A、左右两侧 ratio 四个案例测试，最小化时再统一取负号。
</Callout>

<Callout type="trap" title="padding也算进GAE？">
  **现象 →** 改填充长度就改变有效回复的优势。**原因 →** 终止与回复 mask
  错误，或在 padding 上传播未来值。**修法 →**
  明确真正终止位置，屏蔽提示和填充，检查最后有效 token 的递推边界。
</Callout>

## 独立可执行的 Python 算术实验

以下六段按顺序拼成一个 `rlhf_arithmetic.py`，仅用 Python 3 标准库即可运行。它是教学算术模拟，不是 SDK、真实训练日志或 MOSS 复现。每段不足30行；特征、奖励、概率与价值都明示固定。运行会捕获预期失败，再断言恢复与初始输入一致。

第一段定义数值稳定的配对损失和真正的梯度迭代。`flip` 只改变训练标签，评估始终用原偏好，避免把错标签训练得好误报为质量改善。

```python
import math

def pair_train(flip=False, length_weight=0.0):
    w = [0.0, length_weight]
    history = []
    for step in range(4):
        d = w[0] - w[1]
        loss = max(0.0, -d) + math.log1p(math.exp(-abs(d)))
        history.append((d, loss))
        sign = -1 if flip else 1
        g = sign / (1.0 + math.exp(sign * d))
        w = [w[0] + 0.5 * g, w[1] - 0.5 * g]
    return history

normal = pair_train()
assert math.isclose(normal[1][0], 0.5)
assert normal[-1][1] < normal[0][1]
```

第二段注入标签反转。预期失败必须被捕获；若故障不触发，程序反而报错。恢复重新从同一 w 开始，不沿用被污染的权重。

```python
fault = pair_train(flip=True)
try:
    assert fault[-1][1] < fault[0][1], "真实偏好损失没有下降"
except AssertionError as error:
    print("EXPECTED preference failure:", error)
else:
    raise AssertionError("翻标故障未被检出")
recovered = pair_train()
assert recovered == normal
assert fault[-1][0] < 0 < normal[-1][0]
```

第三段执行与账本相同的三步 KL/GAE。`terminal_value` 只能在故障时非零；γ=1、λ=0.8，不做优势归一化，便于逐格核对。

```python
def credit(beta=0.2, lam=0.8, terminal_value=0.0):
    log_ratio = [0.2, -0.1, 0.4]
    value = [0.3, 0.4, 0.2, terminal_value]
    reward = [(1.0 if t == 2 else 0.0) - beta * k
              for t, k in enumerate(log_ratio)]
    delta = [reward[t] + value[t + 1] - value[t]
             for t in range(3)]
    advantage, tail = [0.0] * 3, 0.0
    for t in reversed(range(3)):
        tail = delta[t] + lam * tail
        advantage[t] = tail
    return reward, delta, advantage

reward, delta, advantage = credit()
for actual, expected in zip(advantage, [0.3768, 0.396, 0.72]):
    assert math.isclose(actual, expected, abs_tol=1e-10)
assert reward[1] > 0  # 负采样log比不等于负的期望KL
assert credit(lam=0)[2] == credit(lam=0)[1]
```

第四段检查错误终止值沿时间传播的精确量：最后一格多0.5，前两格分别多 λ×0.5 和 λ²×0.5。修复只还原终止边界。

```python
bad_advantage = credit(terminal_value=0.5)[2]
for t in range(3):
    difference = bad_advantage[t] - advantage[t]
    assert math.isclose(difference, 0.5 * 0.8 ** (2 - t))
try:
    assert bad_advantage == advantage, "终止边界改变了信用分配"
except AssertionError as error:
    print("EXPECTED terminal failure:", error)
else:
    raise AssertionError("终止故障未被检出")
assert credit()[2] == advantage
```

第五段把 PPO 的四个象限列成测试。`clip_only` 正是第三个图里的错误支路，负优势且 ratio 大于上界的案例能揭穿它。

```python
def ppo(ratio, advantage, epsilon=0.2):
    clipped = max(1 - epsilon, min(1 + epsilon, ratio))
    return min(ratio * advantage, clipped * advantage)

for ratio, a, expected in [(1.4, 1, 1.2), (1.4, -1, -1.4),
                           (0.6, 1, 0.6), (0.6, -1, -0.8)]:
    assert math.isclose(ppo(ratio, a), expected)
clip_only = 1.2 * -1
assert clip_only != ppo(1.4, -1)
assert ppo(1.4, -1) == -1.4
```

第六段与 DPO 对照，并验证 KL 的分布期望非负。DPO 中1.2与0.8是两个完整回复对参考的比；此计算不含 rollout、价值网络、GAE 或 PPO ratio 裁剪。

```python
beta_dpo = 0.1
z = math.log(1.2) - math.log(0.8)
dpo_loss = math.log1p(math.exp(-beta_dpo * z))
assert math.isclose(dpo_loss, 0.6730794, abs_tol=1e-6)
p, q = [0.8, 0.2], [0.5, 0.5]
terms = [math.log(a / b) for a, b in zip(p, q)]
assert terms[1] < 0
kl = sum(a * k for a, k in zip(p, terms))
assert kl >= 0
print("RM losses:", [round(x[1], 4) for x in normal])
print("recovered A:", advantage)
print("DPO loss:", round(dpo_loss, 6), "KL:", round(kl, 6))
print("Arithmetic assertions complete; no model was trained.")
```

- 同提示偏好训练相对分差，不校准事实正确率。
- KL 修正、终止值和 GAE 决定信用如何回传。
- PPO 的 min 依赖优势符号；DPO 直接优化偏好对。
- 历史源码阅读与真正框架运行是不同证据。

## 名词解释

<Glossary>
  <GlossaryItem term="RLHF">
    把人的偏好比较转成评分，再借助评分调整生成策略的路线；本章主要分析PPO实现。
  </GlossaryItem>
  <GlossaryItem term="奖励模型">
    为提示与完整回答打标量分的函数，偏好对主要教它谁应排在前面。
  </GlossaryItem>
  <GlossaryItem term="PPO">
    比较新旧动作概率并用双分支目标限制过强激励的策略更新方法；不是参数的硬边界。
  </GlossaryItem>
  <GlossaryItem term="KL 散度">
    两个分布的期望对数比；非负的是分布期望，不是每个采样token的对数比。
  </GlossaryItem>
  <GlossaryItem term="GAE">
    把逐步预测误差反向折扣累加，估计动作比当前平均水平好多少。
  </GlossaryItem>
</Glossary>
