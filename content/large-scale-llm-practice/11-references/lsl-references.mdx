## 为什么链接越多，证据未必越多

把参考文献想成图书馆目录：两张目录卡可以指向同一本书，书的另一页也不会变成另一部作品。技术文章若同时列出论文主页、预印本镜像和书中的编号，链接数会增加，独立研究数却可能没有变化。本页的任务不是收藏更多网址，而是回答：**这条具体主张，凭什么由这个具体版本的来源支持？**

一个可检查的记录至少要留下“主张原句、书内编号、作品身份、版本定位、支持范围”。例如，“LoRA 用低秩增量调整权重”与“LoRA 在所有任务上更快”虽然都含 LoRA，所需证据却不同。前者可回到方法定义；后者还必须指定任务、硬件、基线与测量方法，不能从论文题名推出。

逐页核对得到编号 [1] 至 [279]；末条 [279] 是 C-Eval，随后物理页 298（印刷页 284）开始索引。这里的 279 是书目条目数，不是独立论文数，更不是“所有技术结论均已验证”的计数。不能用目录上的起始页或临时摘录的终止位置推算书目范围。

[电子工业出版社第一版书目](https://phei.com.cn/module/goods/wssd_content.jsp?bookid=63826)记录出版时间为 2024 年 1 月、320 页、ISBN 9787121467059。纸书总页数与作者公开稿不同，本页的页码只承诺可在上述固定 PDF 内复核；前言的 2023 年 9 月署名也不等于出版日期。第二版不属于本页核对范围，下面不借它补第一版的条目或结论。

### 本页采用的事实核对点

- [第一版完整稿](https://intro-llm.github.io/chapter/LLM-TAP.pdf)：书目 [2]（印刷页 261）与 [48]（264）都著录 Attention Is All You Need，只是会议著录格式不同；核对题名、作者和年份后才归并，而非只看编号。
- [Transformer 原始研究](https://arxiv.org/abs/1706.03762)：核对注意力架构；第一版正文印刷页 15–17 解释位置编码和注意力，不把它们变成任意模型的性能保证。
- [LoRA 原始研究](https://arxiv.org/abs/2106.09685)：核对冻结预训练权重、引入低秩可训练增量；第一版正文印刷页 123–124 解释该机制，书目 [148] 在印刷页 272 著录为 ICLR 2022。预印本编号中的 2021 与会议年份 2022 是不同字段，不应抹平。
- [ZeRO 原始研究](https://arxiv.org/abs/1910.02054)：核对消除数据并行训练中模型状态冗余的思路；第一版正文印刷页 92–93 讨论优化器状态、梯度和参数的分片，书目 [139] 在印刷页 272 著录为 SC20、2020 年。
- [The Pile 原始记录](https://arxiv.org/abs/2101.00027)：用于练习保留差异。第一版 [72]（印刷页 266）把该 arXiv 编号与 2020 年并列，而 arXiv 记录的首提交在 2021 年。应分别保留“书内著录年份”与“预印本首提交年份”，注明差异，不能悄悄把一本书的原记录改成另一字段。

## 第一版正式坐标逐项解释

第一版把参考文献作为正文之后的独立资料单元。阅读它的价值是恢复论据的来路，而不是从题名列表重建作者未写出的结论。本节保留正式“参考文献”坐标，并用三种检查把书目变成可追溯的阅读记录；它们是本站的独立教学组织，不声称原书采用了同一套检查程序。

### 参考文献

参考文献条目是某一份文献在这本书中的著录，编号只在该书及其版本内有意义。[148] 不是全球通用的 LoRA 标识，换一本书或换一次排版就可能指向别处。先用编号回到完整条目，再以作者、题名、出版载体和稳定标识确认作品；引用方法定义时还须读到相应正文，而不是把参考文献列表本身当作方法证据。

把“主张 → 书目条目 → 原始作品”的连接记成 <Term id="citation-graph">引文图</Term>，能看出多个入口何时汇合。真实例子是 [2] 和 [48]：它们都指向 Vaswani 等人的同一篇 Transformer 论文。归并不是删除读者使用过的入口，而是保留入口、共享作品节点。如果一个入口缺失作者或稳定标识，只能保留待核对状态，不能为了凑数量当作另一篇独立研究。

<Callout type="trap" title="误区一：三条链接就是三次验证">

同一作品的两个著录再加一个镜像，最多说明有三个访问入口。独立复现还需要另一项研究及其方法和结果。缺失身份的链接也不能自动计为独立研究；未知不是新增证据。

</Callout>

## 实验一：沿引文图识别重复入口

先预测：把 [2] 和 [48] 都接到同一个作品节点，再增加镜像，底部作品数会不会变成三？操作“增加镜像入口”，观察中层节点由两个变为三个、底层仍汇合在 T。镜像节点是教学添加的入口，不是第一版多出了一条书目。按“下一步”观察核对路径，再注入身份连接缺失：末支改为虚线并落到问号，含义是不能确认，而不是确认存在新研究。

## 实验二：标题相同，是否能交换页码

<Term id="version-identity">版本身份</Term>
回答“我读到的究竟是哪份材料”。作品可以有预印本、修订稿和会议版本；同一版次还可能有不同排版的文件。因此记录版次之外，还用完整文件摘要锁定字节内容。摘要相同表示本次比较中的文件内容相同，并不保证内容真实，也不能替代作者或出版来源的核查。

<Term id="locator">定位符</Term>
回答“证据在这份材料的哪里”。页码、节号或段落锚点都是定位符。固定 PDF 的物理页
275 与 276
属于同一文件，但不指向同一段证据；离开文件身份，裸页码没有可移植性。图中摘要仅显示八位以便阅读，实际留档必须保留上面的完整
SHA-256。

先预测：选择“另一页，同一 PDF”，应只出现页码差异，不应把作品判成异版。再选“异版同名（教学夹具）”，观察版次和摘要行同时分开。这个异版是人为构造的比较样本，不是已核对的第二版。注入“仅比较标题”，非标题行变成虚线、连接变淡，模拟错误检查器如何忽略真正的差异。

<LslReferencesComputeTraceLab />

故障会让同名夹具被错误合并；恢复字段比较后，版次与摘要的差异重新参与判断。点击“重置身份实验”会恢复完全相同的定位、完整字段比较和第一步。若只移动页码，应更新定位记录；若文件摘要变化，应重新定位并复核，不能直接沿用旧页码。

<Callout type="trap" title="误区二：年份或哈希能单独替你完成核查">

LoRA 的预印本年份与 ICLR 年份不同，不等于两条记录必然矛盾；必须先问它们分别描述什么。反过来，同名不同文件也不保证内容等价。哈希锁定字节、年份描述事件、页码定位证据，三者不能互相替代。

</Callout>

## 实验三：主张覆盖不是论文排名

<Term id="claim-coverage">主张覆盖</Term>
检查的是“一条已写明范围的主张，是否有对应来源直接支持”，不是给论文打质量分。这里选三条机制性主张：Transformer
的注意力架构、LoRA 的低秩权重增量、ZeRO
的训练状态分片。矩阵的行是主张，列是第一版书目编号；圆圈表示在本次选定机制范围内直接对应，短横线表示该来源不承担这条主张的论证，问号表示所需证据缺失。

先预测：把 [148] 和 [139] 的列交换，是否仍能因为“都与训练有关”保留对角线上的三个正确绑定？操作错配开关，看支持圆圈移到非对角位置，虚线格标出错填的引用槽。此时只有一条引用位置正确，另外两条应交换回来，而不是改写论文结论去迁就编号。

<LslReferencesEvidenceGateLab />

恢复后再把主张扩展为“所有任务更快”，三个对应位置都变成问号。机制描述并不直接支持无限范围的速度保证；这里的 0/3 是三条泛化主张均缺直接证据，**不是证明它们都为假**。重置会清除泛化与错配，回到限定机制、正确绑定和第一步。

把“LoRA 无条件提高任意任务速度”“ZeRO 必然降低任何规模的端到端耗时”“Transformer 在所有比较上获胜”等写入 <Term id="unsupported-conclusions">不支持结论</Term> 清单，并注明缺什么：同一任务、实现、硬件、规模与基线下的测量。它们是本次阅读不能推出的结论，不是对相应论文的否定。这一步让证据空白保持可见，避免用领域相近的论文填满引用槽。

## 用 Python 重做这三项检查

下面是一段完整、独立可执行的 Python 3 标准库模拟；复制整个代码块即可运行，不需下载 PDF、模型或安装 SDK。输入是人工整理的微型教学索引，代码不自动证明论文内容，也不跑训练、推理或延迟基准。`3/3`、`1/3`、`0/3` 只是已声明的引用槽检查算术，不是模型效果、论文质量或通用可信度分数。

<Stepper>
  <Step title="预测">
    先写下双条目归并后的作品数，以及错配两项后的正确引用数。
  </Step>
  <Step title="运行">
    执行代码，确认三项正常断言以及一次有意触发的失败提示。
  </Step>
  <Step title="恢复">
    错误引用复原后应恢复 3/3；再增加一个未知入口，独立作品数仍不可增加。
  </Step>
</Stepper>

```python
from hashlib import sha256

entries = {"[2]": "1706.03762", "[48]": "1706.03762"}
assert len(set(entries.values())) == 1
entries["mirror"] = None  # 未核对入口，不是新作品
assert len({v for v in entries.values() if v is not None}) == 1
pdf = "df024a8babac233ed86227306fad33c38e5c24ed9659ccbd0c552310b27d40c5"
identity = ("LLM-TAP", "第一版", pdf)
other_page = (identity, 276)
assert other_page[0] == identity and other_page[1] != 275
fixture = ("LLM-TAP", "异版夹具", sha256(b"fixture").hexdigest())
assert fixture[0] == identity[0] and fixture != identity
supports = {"[2]": {"架构"}, "[148]": {"低秩增量"}, "[139]": {"状态分片"}}
claims = ["架构", "低秩增量", "状态分片"]
cites = ["[2]", "[148]", "[139]"]
def covered(rows, refs):
    assert len(rows) == len(refs)
    return sum(row in supports.get(ref, set()) for row, ref in zip(rows, refs))
assert covered(claims, cites) == 3
wrong = ["[2]", "[139]", "[148]"]
assert covered(claims, wrong) == 1
try:
    assert covered(claims, wrong) == 3, "错配：低秩增量与状态分片的引用互换"
except AssertionError as error:
    print("预期失败：", error)
else:
    raise RuntimeError("故障未被检出")
wrong[:] = cites  # 恢复引用绑定
assert covered(claims, wrong) == 3
assert covered(["所有任务更快"] * 3, cites) == 0
print("归并 1 篇；限定 3/3；错配 1/3；恢复 3/3；泛化 0/3（缺证）")
```

输出应包含“预期失败”以及最后的五项检查结果。注意 `try` 只包住有意出错的那一条断言，其余断言失败会直接停止，不能用一个宽泛的异常处理把所有错误伪装成成功。修改 `supports` 就能改变结果，因此真实使用时必须把每个集合成员与原文段落一起人工留档；程序检查的是记录内部一致性，不是来源的真实性。

## 小结：留下可以被别人复查的阅读记录

一条可复查记录不是一个孤立链接。它沿引文图找到作品，沿版本身份找到文件，再沿定位符找到支持段落；最后把主张限定在段落实际支持的范围内。[2]/[48] 展示重复著录，[148]/[139] 展示领域接近但机制不同，[72] 展示书内年份和外部记录需要分字段保留。三种情况都不能靠链接计数解决。

下一次写技术说明时，为一句结论填写“原句 → 编号 → 作者与题名 → 版次和完整摘要 → 页码/节号 → 支持点 → 不支持结论”。不能填的格子标为待核对，并写出下一步要查的原始材料或实验，而不是让自动生成的引用编号替你作判断。

## 练习与答案

<Exercises>

1. 第一版 [2]、[48] 加一个相同论文的镜像，能否声称“有三项研究证实 Transformer 架构”？如果镜像无法核实身份，计数又该如何处理？

<Answer>

不能。两个真实书目条目在核对题名、作者和载体后汇合到同一作品，镜像也不增加独立研究。无法核实时应保留一个未知入口，记录待查身份，不把未知算成第二篇研究或一次复现。

</Answer>

2. 同学把第一版 PDF 物理页 286 抄成“纸书第 286 页”，又把 LoRA 的 2021 改成 2022，认为这样统一了引用。哪两类信息被混淆？

<Answer>

物理页是特定 PDF 的定位符，不是纸书页码；该文件物理页 286 对应印刷页 272，不能再推断纸书同页。2021 是预印本记录的年份，2022 是书目 [148] 的 ICLR 年份，应该标注事件类型并各自保留，而不是全局替换。文件摘要和出版来源也必须分别记录。

</Answer>

3. 在 Python 索引中增加“某任务上端到端更快”，但不向任何来源增加支持成员，预测结果；运行后应怎样补证，而不是怎样改代码让它通过？

<Answer>

新增主张不会命中现有机制集合，得到缺证。需先说明某任务、硬件、模型规模、实现、对照基线与测量协议，再查同条件的实验表格或亲自测量，保存可复查定位。没有这些材料时，保留不支持结论；不能直接向集合添字符串冒充完成验证。

</Answer>

</Exercises>
