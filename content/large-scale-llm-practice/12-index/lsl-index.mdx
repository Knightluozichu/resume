## 为什么翻到名字，还没有找到答案

地图上同一个地名可能有几个入口。只记最后一个入口，会漏掉另一侧；拿另一版地图的格号去找，也可能走错位置。本页先解决“到底该翻到哪里”。

走到入口还不等于走完路线。读者通常带着一个问题回来查书，需要从目标处回看前提，再判断那里是否真的回答了问题，而不是把出现过的名字当成答案。

## 第一版正式坐标逐项解释

本页只对应原书的一个正式单元“索引”，位于作者第一版公开稿的印刷 p.284–287、PDF 物理第 298–301 页。它是术语到正文位置的导航，不是新一章算法。下面保留这一正式坐标，其他小节是本站对使用方法的独立教学组织，不冒充原书目录。

## 索引

索引把一个检索词连接到正文的一个或多个位置，是从阅读任务返回书中讨论的入口。使用它时，先保留原词条和所有候选页码，再根据上下文选择落点；翻到页上以后仍需回读定义、公式及适用条件。页码命中只是定位成功，不能据此断言两个术语含义相同或模型结论成立。

<Term def="把检索词指向正文出现位置的查找工具，不保证该位置已经解释完问题">
  索引
</Term>
用词条和页码连接阅读任务与正文。原索引先列英文与缩写，再列中文；同一主题可从英文、中文或缩写进入，也可能指向多个页码。例如
Agent 和“智能体”都有 149、197 两个落点，而“智能代理”落在
197。它们帮助找到不同讨论位置，不构成“这些段落完全等价”的断言。

查找在阅读流程中位于“提出问题”之后、“回读定义或公式”之前。只报一个名字和页码，会丢掉检索词的其他写法，也会丢掉这个页码属于哪份文件。第一幅图保留原始记录，第二幅图解决落页，第三幅图才组织补读顺序；三个环节不互相替代。

## 别名要合并入口，页码不能覆盖

<Term def="从一个词保存到一组正文位置的映射；一词可以对应多页">倒排表</Term>
不是“词 → 唯一整数”的字典。本页用它表示“词 →
页码列表”，教学对象是书籍位置，不是训练数据。原索引里两个英文词条分别写作
`In-context Learning，ICL, 3` 与 `Incontext Learning, ICL,
122`；中文“语境学习”直接列 3、122，“上下文学习”列
122。保留原始拼写后，再建立共同的 ICL
检索入口，才能既容忍拼写差异，又不抹掉出处。

第一页落点是第一章对语境学习的概述；第二个落点是 5.1.2 的展开，正文说明它通过上下文中的例子工作，不需要更新模型参数。这个事实来自 p.122 正文，不是看到 ICL 缩写就能推导出来。若只想确认参数是否更新，应优先回读后一处；若想知道第一章如何介绍这条路线，前一处仍然有用。

<Term def="用当前任务和邻近概念区分同名词条的不同落点，而不改写原始记录">

## 页码坐标必须携带文件身份

<Term def="由载体身份、页码体系和数值共同组成的位置；单独一个整数不是完整引用">
  页码坐标
</Term>
区分印刷页和从 PDF
文件第一页开始计数的物理页。在本次核对的作者稿正文与索引区间，两者相差 14
页。读索引的 122 时，应跳到该 PDF 的物理第 136 页，而不是物理第 122 页。PDF
阅读器若显示页面标签，标签可能正好写 122；那是另一种显示方式，不能再加一次偏移。

$$
p_{\mathrm{physical}} = p_{\mathrm{printed}} + 14
$$

这条式子是在说：对已核对的这份作者稿，从印刷页换成物理页需要越过前面的 14 页；它不是所有版次、扫描件或前置页都适用的定律。符号分别是从 1 起计数的物理页和纸面印出的正文页号。比如印刷 p.3、122、240 分别对应物理第 17、136、254 页；换算后仍须看页眉和小节标题确认目标。

先预测：目标选 240，打开漏加偏移，两个落点会相差多少？再将载体切为 Unmapped，图里的连接是否还应存在？未知映射应停止，而不是用猜出的偏移继续跳。

引用至少保留“第一版作者公开稿、文件身份、印刷 p.240／PDF 物理第 254 页、语言模型评估指标”这几项。文件身份可用 SHA-256；本次核对文件为 `df024a8babac233ed86227306fad33c38e5c24ed9659ccbd0c552310b27d40c5`。文件内容变了，应重新确认映射，不能仅凭同一个下载 URL 继续沿用。

出版社第一版书目列 320 页；作者公开 PDF 共 301 个物理页面。二者分别是纸书元数据与本次可查文件的长度，不是需要强行统一的冲突数字。本页的 +14 只绑定后者，不声称适用于 320 页纸书的全部页面。其他版本在图里只标“未映射”，不编造其页数、日期或偏移。

## 从落点回到知识依赖

<Term def="为回答一个问题先补读必要概念，再返回目标定义的阅读关系；不代表索引证明了因果">
  知识依赖
</Term>
让导航从“在哪一页”推进到“先读什么”。原索引给出 Perplexity／困惑度
p.240、Cross-entropy／交叉熵 p.240、Subword／子词
p.52；它并没有画出这些概念之间的推导箭头。下图的依赖边是本站作者建议的阅读顺序，语义关系需另读正文。

以“两个模型困惑度能否直接比较”为任务，先回读序列概率和词元单位，再看 p.240 对交叉熵的说明以及跨页继续的困惑度关系。p.240 使用以 2 为底的交叉熵；下一页把它联系到困惑度。还需要检查评估文本与切分单位是否一致，并确认交叉熵的对数底与指数还原的底匹配：`PPL = b^H_b`。仅仅更换对数底、再用相同底正确还原，不会改变困惑度；把自然对数交叉熵误用 2 的幂还原则会算错。同页出现两个术语，不意味着任意两份实验输出已可比较。

另一个任务是区分精确率与准确率。索引将 Confusion Matrix 放在 p.237，将 Precision、Recall、Accuracy 放在 p.238；这提示我们先回读预测类别与真实类别构成的计数。精确率的分母是预测为正的样本数，准确率的分母是全部样本数。不能因二者同页就互换，也不能由词条位置推出某个模型评估合格。

先预测：选择 Precision 后，前两个节点应换成什么？打开“把索引当证明”，观察只亮目标、前提空缺的路径。这个快捷跳转可以帮助赶路，却不能替代定义核验。

## 可执行的微型定位器：失败与恢复

下面是 **Python 3 标准库玩具模拟**：只做小型索引的合并、筛选、页码换算和拒绝未核验结论，不做真实模型训练、SDK 调用或延迟回放。把以下四段按顺序保存为同一个 `index_locator.py` 文件即可独立执行；输入是人工录入的几个真实词条，不是整本书的机器抽取结果。

第一段将原始拼写与教学上下文标签分开存储。标签便于选择页码，但不是书上附带的官方语义标注。归一化只覆盖列出的别名；没有匹配时返回空表，不做任意模糊替换。

```python
# index_locator.py -- toy locator, no model/SDK/training replay
RAW = [
    ("In-context Learning", 3, "overview"),
    ("Incontext Learning", 122, "adaptation"),
    ("Agent", 149, "reinforcement"),
    ("Agent", 197, "application"),
]
ALIASES = {
    "icl": "icl", "语境学习": "icl", "上下文学习": "icl",
    "in-context learning": "icl", "incontext learning": "icl",
    "agent": "agent", "智能体": "agent",
}

def normalize(word):
    return ALIASES.get(word.strip().casefold(), word.strip().casefold())

def build(overwrite=False):
    table = {}
    for spelling, page, context in RAW:
        key = normalize(spelling)
        entry = (page, context)
        table[key] = [entry] if overwrite else table.get(key, []) + [entry]
    return table
```

第二段用完整列表查找，再按上下文缩小集合。坐标转换则必须匹配载体；教学中只登记这份作者稿，未知文件不使用默认值兜底。范围检查是最低限度的健全性检查，不足以证明标题也匹配。

```python
def lookup(table, word, context=None):
    entries = table.get(normalize(word), [])
    return sorted({p for p, c in entries if context is None or c == context})

CARRIER = "first-author-pdf-sha256-df024a8b"
OFFSETS = {CARRIER: 14}

def physical_page(printed, carrier=CARRIER):
    if carrier not in OFFSETS:
        raise ValueError("unmapped carrier: refuse navigation")
    result = printed + OFFSETS[carrier]
    assert 1 <= result <= 301
    return result

def expect_failure(name, operation):
    try:
        operation()
    except (AssertionError, ValueError):
        print("expected failure:", name)
    else:
        raise AssertionError("fault was not detected: " + name)
```

第三段先运行正常路径，再单独注入覆盖错误与漏加偏移。测试发现错误后，分别重建完整列表与重新计算坐标，恢复的是同一查询的可用落点，不是模型质量。

```python
correct = build()
assert lookup(correct, "ICL") == [3, 122]
assert lookup(correct, "Incontext Learning", "adaptation") == [122]
assert lookup(correct, "智能体", "reinforcement") == [149]
assert lookup(correct, "unknown") == []
assert [physical_page(p) for p in (3, 122, 240)] == [17, 136, 254]

broken = build(overwrite=True)
def require_both():
    assert lookup(broken, "ICL") == [3, 122]
expect_failure("last-write loses page 3", require_both)
assert lookup(build(), "ICL") == [3, 122]  # reimport full records

def wrong_coordinate():
    assert 122 == physical_page(122)  # omitted offset
expect_failure("printed is not physical", wrong_coordinate)
assert physical_page(122) == 136
expect_failure("edition has no mapping",
               lambda: physical_page(122, "another-edition"))
```

最后把“定位成功”和“正文核验”刻意分开。布尔值只是教学任务的完成标记，不是程序能判断学术真假的神谕；真实核验需要人读正文、公式与适用条件。

```python
def finish_reading(locations, body_checked):
    assert locations, "no location found"
    assert body_checked, "a page hit does not prove a definition"
    return "located; body checked by reader"

expect_failure("index hit is not proof",
               lambda: finish_reading([240], False))
assert finish_reading([240], True) == "located; body checked by reader"
assert lookup(build(), "ICL") == lookup(correct, "ICL")
print("recovery: ICL [3, 122]; printed 122 -> physical 136")
print("all locator assertions completed; no model-quality claim")
```

预期输出包括四条 `expected failure`，随后是恢复落点与完成提示。故障被捕获才能继续；删掉错误检测会让实验失去教学意义。如果索引记录本身录错，程序可能一致地给出错页，所以还要用原 PDF 的页眉、小节标题与正文交叉核验。

## 常见误区与修复

<Callout type="trap" title="找到缩写，反而漏掉第一次讨论">
  现象：查 ICL 只得到 122。原因：把两个英文写法归一化后，用单个整数覆盖了
  p.3。修复：先保留原词条，再合并页码列表；按任务筛选候选，不删除另一条出处。
</Callout>

<Callout type="trap" title="页号看似正确，阅读器却跳错页">
  现象：输入 122 后不在
  5.1.2。原因：把印刷页当成物理页，或对已经显示印刷标签的阅读器又加了一次
  14。修复：先确认阅读器计数方式和文件身份，再用页眉与标题复核；不同文件重新建立映射。
</Callout>

<Callout type="trap" title="索引有这个词，所以模型结论成立">
  现象：引用“困惑度，240”就声称模型更好。原因：位置证据被误用为实验或定义证据。修复：回读正文，核对概率、单位、数据与比较条件；索引只能负责带路，不能批准结论。
</Callout>

## 小结

- 合并别名入口时，保留一词多页和原始拼写。
- 页码必须带文件身份与计数体系，未知版本停止换算。
- 阅读依赖帮助补前提，不能把索引升级为语义证明。

<Exercises>

**问题 1：覆盖后还能靠筛选找回吗？**

在第一幅图选 ICL、A 上下文，走到第三步，再打开故障。预测候选集合，并说明为什么切换到“全部落点”不是完整恢复。你会怎样修改只存一个整数的实现？

<Answer>
  A 需要 p.3，而覆盖实现只剩 p.122，因此候选为空；改成全部只能显示残存的
  122，仍找不回 3。应从原始记录重建“归一化词 →
  页码列表”，保留两条英文拼写及来源；列表去重后应为 [3,
  122]。关闭图中故障相当于重新载入完整记录，不是从丢失数据中推理恢复。
</Answer>

**问题 2：同样的 240，为什么不能直接跳？**

第二幅图选择印刷 240。分别在已核对作者稿、漏加偏移、未知版本三种情况下报告落点与动作。如果同学的阅读器页面标签已经写 240，还应不应该加 14？

<Answer>
  作者稿物理目标是 254；漏加偏移错到物理 240，提前 14
  页；未知版本没有已验证映射，应拒绝跳转并先核查文件。若阅读器按印刷页面标签导航，则直接输入标签
  240，不再次加 14；先确认它使用的是标签还是从第一页起计数的物理页。纸书总页数
  320 本身不提供这个映射。
</Answer>

**问题 3：为指标问题选一条补读路线**

同学想比较两个切词方式不同的模型，却只引用索引的 Perplexity p.240。用第三幅图解释尚缺哪些核对；再切到 Precision，说明为何不能把同页的 Accuracy 当同义词。

<Answer>
  先补序列概率与词元单位，再读 p.240
  的交叉熵及跨页的困惑度关系；不同词元切分或评估文本会破坏直接可比性；交叉熵换底后须用对应的底还原困惑度，页码命中不证明模型更好。分类路线则先核对真实类别与预测类别，再读混淆矩阵；精确率只在预测为正的集合里计算，准确率面向所有样本。两个词都在
  p.238 是位置相邻，不是分母相同。图中箭头只是本站建议的阅读关系。
</Answer>

</Exercises>
