## 实验一：相似关系怎样穿过切分污染评估

<Term def="图中能沿边互相到达的一组节点；用于分组时是一种闭包政策。">
  连通分量
</Term>
把重复候选图划成若干组。边表示已发现的一对相似记录。近重复相似性本身**不具有传递性**：A像B、B像C，不能推出A像C；选择把整条链放到同一侧，是为了避免跨侧相似边的保守切分政策，不是在证明端点语义相同。误连边可能把过多数据并为一组，需要回查边的质量。

这里的记录是A—F，默认边为A—B、B—C、D—E；F独立。逐条切分用A、B、D训练，C、E、F测试；按分量切分用A、B、C训练，D、E、F测试。玩具答题规则是：若测试条目的分量在训练中出现就“记住答对”，否则仅F答对。它刻意放大记忆效应，**不是任何真实模型的预测器**。

猜一猜：把切分单位从“逐条”改成“分量”，表面准确率会升还是降？删除B—C桥接边，是否会改变C的泄漏判定？

<LslOfficialFinalReviewContextContractLab />

操作顺序：先选逐条并走到时间线末端，再删桥接边，最后选分量并注入故障。故障会忽略选定分组退回逐条；关掉故障便恢复。选择分量切分时0/3条目泄漏、准确率1/3；逐条时2/3泄漏、表面3/3，去掉泄漏条目后仅余F，1/1不能冒充同一测试集的改进。删桥接边后逐条为1/3泄漏、表面2/3、独立子集1/2。

这连接了第3章去重和第8章任务评估：去重还可能改变训练权重，防污染则关乎测试独立性，两者不是同一个目标。分组策略在看测试答案前冻结；不能反复换组直到成绩最好。

## 实验二：不给提示计分，不等于不让模型读提示

<Term def="取0或1的目标选择变量；决定哪些位置直接贡献训练损失。">目标掩码</Term>
发生在损失端，而注意力的因果遮罩发生在可见上下文端。回答依然读提示；把提示目标掩掉，不会阻止共享网络通过回答位置获得与提示相关的梯度。

为隔离直接目标的效果，本实验把四个位置建成四个**独立标量**，每个位置只有一个目标 <Term def="概率归一化前的分数；这里是独立二元目标分数，不是网络权重。">logit</Term>。这不表示真实模型有四个互不关联的参数。

符号：$p_i$为第$i$个目标的概率，$m_i$为掩码，$M=\sum_i m_i$为有效目标数，$z_i$为该位置的独立目标分数。固定另一个类别分数为零，则$p_i=\sigma(z_i)$，所以$\partial p_i/\partial z_i=p_i(1-p_i)$。

$$
L_{\mathrm{SFT}}=-\frac{1}{M}\sum_i m_i\log p_i,
\qquad \frac{\partial L_{\mathrm{SFT}}}{\partial z_i}=\frac{m_i(p_i-1)}{M}.
$$

这个式子在说：只给被选中的目标计分，且按被选目标数平均；对数导数中的$1/p_i$与概率导数中的$p_i$约去，得到右侧的直接目标梯度。**这不是共享模型参数的总梯度**。

现在换监督对象：<Term def="把同一提示下偏好回答的奖励推高于另一回答的二元比较损失。">成对偏好损失</Term>使用奖励差$\Delta=r^+-r^-$，不是下一个词元标签。这里的$r^+$、$r^-$指被标为偏好与非偏好的回答奖励。

$$
L_{\mathrm{pair}}=-\log\sigma(\Delta)=\log(1+e^{-\Delta}),
\qquad \frac{\partial L_{\mathrm{pair}}}{\partial\Delta}=-\frac{1}{1+e^{\Delta}}.
$$

这个式子在说：奖励差越朝标注偏好方向增大，损失越小；对$\log(1+e^{-\Delta})$求导便得到右侧。标注颠倒时它仍会推动“错误的偏好”。这是奖励模型常用的成对目标，**不等于DPO目标，也不包含PPO的策略比、裁剪、优势或KL控制**。

猜一猜：把目标从“只计回答”改为“整段”，回答的直接目标梯度会不变吗？把偏好标签颠倒，会不会自动修好目标掩码？

<LslOfficialFinalReviewComputeTraceLab />

四个概率固定为0.2、0.8、0.4、0.6。默认掩码为0、0、1、1，平均损失0.7136、直接梯度0、0、−0.3、−0.2。改成整段后平均损失0.8149、梯度−0.2、−0.05、−0.15、−0.1；回答梯度减半来自分母由2变4，不是“提示变容易”。故障强制误用整段目标。

奖励差+1时损失0.3133，反向标注取−1时为1.3133。两种监督可以分别出错，修一个不会修另一个。这就是从第2章语言建模，经第5章回答标签，到第6章奖励建模时必须逐次核对目标的原因。

## 实验三：块不够时，怎样才算公平的服务比较

<Term def="这里是可分配、持有、释放的固定容量缓存槽；每块为教学容量单位。">
  KV块
</Term>
在推理时存放过去位置的键和值，避免反复计算。第4章讨论的参数、梯度和优化器训练状态与它不是同一种内存。本实验假定每个请求一开始就知道静态块需求，不模拟真实解码逐步增长、分页块表、共享或抢占。

三请求都在t=0到达：A需要3块且运行3拍，B需要2块运行1拍，C需要1块运行1拍。每一拍先接纳能装入空块的请求，再共同运行一拍；完成者在该拍末释放自己的**原物理槽**。下一拍才能复用槽。FIFO遇到装不下的队首就停止接纳；绕过策略允许检查后面的请求。后者可能改善短请求等待，也可能在其他负载下饿死长请求，不是普遍更优。

猜一猜：4块时允许C绕过B，能缩短C的等待；是否也能缩短整组完成时间？预算变5块后变快，还能说是“同资源调度优化”吗？

<LslOfficialFinalReviewEvidenceGateLab />

4块FIFO：t=0至2由A持有0、1、2槽，C被B挡住；t=3再接纳B和C，总共4拍。4块绕过：C在t=0占槽3并在拍末释放，A继续持有前三槽；B等到t=3，总共仍4拍。5块FIFO：t=0接纳A+B，B释放槽3、4，t=1由C复用槽3；3拍完成全部请求。资源变化与策略变化要分开报告。

故障丢掉长请求A，只做B+C，显示2/3完成、1拍、表面2请求/拍；这不是比完整负载3/4请求/拍更好的公平结果。时间线呈现t=0—3，泳道保留t=4的全部结局。**拍不是毫秒，也不是GPU延迟**；这只是隔离分配、等待与分母的离散算术，不是FastServe或vLLM实现。恢复时关掉故障并核对A重新出现和块释放。

## 完整可执行算术：把故障和恢复写成断言

以下各Python块按出现顺序放进同一个文件，用Python 3标准库执行；所有实现都在正文，没有隐藏的省略号、模型下载、训练或SDK。这里为便于逐段解释拆开代码块，拼接后可独立运行。先实现关系闭包；它表达切分政策，不把相似性变成数学等价关系。

闭包按图连通性计算。答题规则固定，逐条与分量切分只改变测试独立性。

```python
from math import exp, log, log1p

def split_score(grouped=True, bridge=True):
    parent = {x: x for x in "ABCDEF"}
    def find(x):
        while parent[x] != x:
            x = parent[x]
        return x
    edges = [("A", "B"), ("D", "E")]
    if bridge:
        edges.append(("B", "C"))
    for a, b in edges:
        parent[find(a)] = find(b)
    train, test = ("ABC", "DEF") if grouped else ("ABD", "CEF")
    seen = {find(x) for x in train}
    leaks = [x for x in test if find(x) in seen]
    correct = [x for x in test if x in leaks or x == "F"]
    clean = [x for x in test if x not in leaks]
    return len(leaks), len(correct), len(test), sum(x == "F" for x in clean), len(clean)
```

四个概率来自相互独立的目标分数。梯度是对这些分数求导，不能用它代替共享网络反向传播。

```python
def objective(answer_only=True, reversed_pair=False):
    p = [0.2, 0.8, 0.4, 0.6]
    mask = [0, 0, 1, 1] if answer_only else [1, 1, 1, 1]
    count = sum(mask)
    loss = -sum(m * log(q) for m, q in zip(mask, p)) / count
    gradient = [m * (q - 1) / count for m, q in zip(mask, p)]
    delta = -1 if reversed_pair else 1
    pair_loss = log1p(exp(-delta))
    pair_grad = -1 / (1 + exp(delta))
    return loss, gradient, pair_loss, pair_grad
```

物理槽在请求运行时保持归属。每拍快照记录接纳后、运行前的状态；完成在拍末发生，下一拍可复用。

```python
def schedule(capacity=4, bypass=False, drop=False):
    waiting = [("A", 3, 3), ("B", 2, 1), ("C", 1, 1)]
    if drop:
        waiting = [r for r in waiting if r[0] != "A"]
    owners, running, done, history = [""] * capacity, [], [], []
    for tick in range(7):
        i = 0
        while i < len(waiting):
            name, blocks, ticks = waiting[i]
            if blocks <= owners.count(""):
                waiting.pop(i)
                running.append([name, ticks])
                for slot in [j for j, x in enumerate(owners) if not x][:blocks]:
                    owners[slot] = name
            elif bypass:
                i += 1
            else:
                break
        history.append((owners[:], [r[0] for r in running], done[:]))
        for request in running:
            request[1] -= 1
            if request[1] == 0:
                done.append(request[0])
                owners = ["" if x == request[0] else x for x in owners]
        running = [r for r in running if r[1] > 0]
    finish = next(t for t, (_, _, d) in enumerate(history) if len(d) == len(done))
    return history, finish, len(done)
```

### 2.1 Transformer结构

Transformer把嵌入、注意力、前馈与残差归一化组合起来。复习重点是注意力在位置之间交换信息、前馈在每个位置变换表示，后文的缓存仅能复用其中适合缓存的键和值。

### 2.1.1 嵌入表示层

嵌入把词元编号映射为向量，位置相关信息用于区分次序。第3章若改词表，编号含义和嵌入表便须配套；仅复用同名模型文件并不保证输入语义一致。

### 2.1.2 注意力层

注意力以查询与键的匹配权重混合值向量；因果遮罩阻止位置读取未来。实验二屏蔽的是训练目标，不是取消提示作为注意力上下文，二者发生在不同的计算位置。

### 2.1.3 前馈层

前馈层对各位置的表示进行非线性变换，其参数随训练更新。它不等于跨词元检索库；第7章外部检索增加输入材料，并没有把检索器变成这一层。

### 2.1.4 残差连接与层归一化

残差提供信息与梯度的旁路，层归一化调整特征尺度。目标掩码为零只消除该位置的直接损失项，不保证提示表示经其他位置反向传播的梯度也为零。

### 2.1.5 编码器和解码器结构

编码器常用双向上下文，解码器的自回归部分使用因果约束。第8章选择似然或生成评估时，必须与模型结构和可见上下文匹配，不能把未来答案提前给模型。

### 2.2 生成式预训练语言模型GPT

GPT用生成式预训练建立逐词元预测能力，再适配下游任务。训练损失衡量给定文本的可预测性；知识问答与安全性仍需额外任务检查，不能从一个loss推导所有能力。

### 2.2.1 无监督预训练

所谓无监督预训练仍有由文本自身构造的预测目标。第3章重复文本会反复贡献相近目标，实验一进一步表明它若跨入测试集合，还会污染对泛化能力的判断。

### 2.2.2 有监督下游任务微调

下游有监督微调把共享表示适配到具体标注任务。第5章的指令微调扩展了任务表达方式，但标签定义、数据切分和测试独立性依然不能省略。

### 2.2.3 基于HuggingFace的预训练语言模型实践

第一版展示基于HuggingFace的模型加载、分词与训练流程。可迁移的是输入与标签对应关系，不是某版函数签名；本页标准库算术不声称复现该SDK或原章训练结果。

### 2.3 大语言模型结构

大语言模型在通用Transformer基础上选择位置编码、归一化和注意力实现。结构选择会同时改变训练成本和推理缓存布局，因此要把第4章与第7章的资源估算分开。

### 2.3.1 LLaMA的模型结构

第一版介绍LLaMA的预归一化、RMSNorm、SwiGLU与旋转位置编码等结构选择。它们解释特定模型的计算，不提供“任意窗口长度都可可靠使用”的保证；窗口扩展另见第5章。

### 2.3.2 注意力机制优化

多查询、分组查询等注意力变体改变键值头共享方式，影响KV大小；高效注意力实现还涉及访存。实验三把块容量抽象出来，不把所有变体的缓存量当成一样。

### 2.4 实践思考

基础章的实践思考应落实到张量轴、遮罩方向与词元目标的可算例子。先在实验二发现哪一项不该产生直接梯度，再谈扩大网络；复杂实现不会自动修正目标错误。

## 第3章 大语言模型预训练数据

数据章把“更多文本”拆成来源、处理、规模、质量和多样性。实验一只模拟其中的重复关联和集合隔离，不自动检测隐私或证明实际语料已经干净。

[返回课程：第3章 大语言模型预训练数据](/learn/large-scale-llm-practice/05-data/lsl-03-pretraining-data)。

### 3.1 数据来源

数据来源决定领域、语言、许可和风险边界。评估集从同一个来源抽样不一定错误，但要进一步排除内容重复与调参使用，不能把域相同误判为样本独立。

### 3.1.1 通用数据

通用数据包括网页、书籍、百科等广覆盖内容。它们可提供广泛表达形式，也容易包含同文转载；实验一中的跨集合边正是在提醒：不同网址并不必然是不同知识样本。

### 3.1.2 专业数据

专业数据增强代码、科研等领域分布，却可能放大领域偏差。第8章的垂直评估应报告真实目标领域，而不是用一份通用总分推断专业任务可用性。

### 3.2 数据处理

低质过滤、去重、隐私处理与分词分别解决不同问题。去掉完全相同文档不等于消除近重复，更不等于消除隐私；本页连通分量切分是独立教学策略，不冒充原书指定算法。

### 3.2.1 低质过滤

分类器与启发式规则可筛低质文本，过滤标准本身也会带来选择偏差。改阈值后应检查被删除的语言与领域，再把剩余数据送往训练和评估，不能只看清洗后体积。

### 3.2.2 冗余去除

冗余可以发生在句子、文档和数据集层面。相似度不传递，但把相似边取连通闭包再整体切分能保守阻断链式跨集联系；实验一的A-B-C展示了收益，也提示误连会合并过多数据。

### 3.2.3 隐私消除

隐私消除识别并处理个人敏感信息。去重不是匿名化，散列标识也不自动去掉正文里的隐私；第8章安全检查应覆盖泄露风险，而不仅是一般答题正确率。

### 3.2.4 词元切分

词元切分把字符串转换为模型实际处理的单位，BPE等子词方法在词表和序列长度之间取舍。计训练量、上下文长度、loss分母或KV预算时都应使用同一分词口径。

### 3.3 数据影响分析

规模、质量、多样性共同影响学习，不能由一个总词元数决定结果。实验一显示数据量没有变时，单改切分关系也能让表面成绩下降，这不是模型退化的证据。

### 3.3.1 数据规模影响

增加有效训练数据可改善统计覆盖，但受计算预算和重复比例约束。复制同一批样本会增加计数而不增加同等独立信息；第4章加速训练不能补偿这一信息缺口。

### 3.3.2 数据质量影响

高质量语料可提高学习效率，但“高质”依任务而定。筛选器偏好某种文体时可能损伤其他分布，因此应与第8章分领域结果一起解释，而不是只宣称过滤越严越好。

### 3.3.3 数据多样性影响

多样性涉及来源、语言与任务的覆盖。混合比例会改变模型学到的分布，评估时要固定或明确报告题型权重；重复网页再多也不能替代欠缺的专业样本。

### 3.4 开源数据集合

Pile、ROOTS、RefinedWeb与SlimPajama代表不同采集与清洗取向。名称不是可互换的数据规格；做跨实验比较必须记录版本、混合比例、处理方式和实际使用子集。

### 3.4.1 Pile

Pile组织多种英文来源以支持语言模型研究。它的多来源性质不意味着每个来源质量或权利状态相同，也不自动排除评测题，因此需要来源级追踪与污染检查。

### 3.4.2 ROOTS

ROOTS强调多语言协作构建和治理。复习时把语言覆盖与各语言采样权重分开：多语种列表存在，并不保证训练时所有语言获得相同有效词元量。

### 3.4.3 RefinedWeb

RefinedWeb展示从网页提取与过滤得到训练语料的路径。网页规模与有效文本质量不是一回事；实验一的相似关系检查只是其后仍需考虑的一类验证。

### 3.4.4 SlimPajama

SlimPajama通过清洗和去重整理多来源语料。压缩语料体积可以减少冗余成本，但“更小”本身不是能力指标，仍需在第8章的固定测试上比较。

### 3.5 实践思考

数据章的实践应同时问删了什么、保留了什么、测试是否受影响。实验一用相同玩具答题规则，只变相似边和切分，正好隔离“模型没变但分数变了”的原因。

## 第4章 分布式训练

分布式章解决训练状态与计算超过单设备能力的问题。它与推理服务共享资源约束，却持有不同状态；优化器分片省下的内存不能直接当成实验三的KV缓存量。

[返回课程：第4章 分布式训练](/learn/large-scale-llm-practice/06-distributed-training/lsl-04-distributed-training)。

### 4.1 分布式训练概述

分布式训练把计算、存储与通信分给多个设备。有效速度受同步与通信拖累，不是设备数的线性倍增；比较时先固定训练目标和有效批量，再计资源消耗。

### 4.2 分布式训练并行策略

并行策略决定哪个维度被分割、何时交换数据。数据、张量、流水线并行的通信对象不同，跨章诊断应先识别交换的是梯度、激活还是参数，不能一概归为网络慢。

### 4.2.1 数据并行

数据并行复制模型、分配不同样本并聚合梯度。局部有效目标数不同时，简单平均各卡均值可能改变全局目标；这与实验二掩码改变loss分母直接相连。

### 4.2.2 模型并行

模型并行把参数或层分给不同设备，需交换激活或局部计算结果。能装下模型不代表通信代价可忽略；推理KV的分片还要与相应注意力计算所在设备一致。

### 4.2.3 混合并行

混合并行组合多种分割方式以利用集群。配置合法需满足维度与设备组关系，最优组合依赖模型和互联；不能把实验三两种队列规则当成混合训练并行策略。

### 4.2.4 计算设备内存优化

重计算以额外计算换激活内存，ZeRO分片优化器状态、梯度或参数。这里讨论训练内存；推理中的KV按请求增长，两类优化不能在显存表中重复抵扣。

### 4.3 分布式训练的集群架构

集群架构决定计算节点如何通过网络交换训练状态。第8章若比较速度，必须报告节点数和互联；否则把更大集群的吞吐称作同资源算法优势会混淆原因。

### 4.3.1 高性能计算集群硬件组成

计算设备、主机内存、存储与网络共同构成集群。显存足够只是必要条件之一，数据供给或互联也可能成为瓶颈；实验三故意只保留一种块预算，不模拟完整集群。

### 4.3.2 参数服务器架构

参数服务器组织工作节点与集中参数服务之间的交换，适合同步或异步变体。它改变状态归属与一致性路径，不是把所有通信都消除了，还可能出现服务侧瓶颈。

### 4.3.3 去中心化架构

去中心化架构可通过集合通信聚合状态，避免单一参数服务器承担全部聚合。通信量、拓扑和同步代价依然存在；不能由“去中心化”推出任意规模都更快。

### 4.4 DeepSpeed实践

第一版用DeepSpeed连接训练代码、并行和内存配置。复习可核对有效批量、精度与ZeRO阶段如何落入配置，但不把历史配置复制到当前依赖后便宣称成功复现。

### 4.4.1 基础概念

有效批量由每卡微批量、数据并行度与梯度累积共同决定。改变其中一项若不校正其他项，会同时改变优化过程与吞吐；相同资源比较也必须说明这个训练口径。

### 4.4.2 LLaMA分布式训练实践

LLaMA分布式实践把模型、数据与启动配置组合起来。启动成功不是正确性结论，还要查标签、损失、同步和检查点；本页没有运行DeepSpeed或训练真实LLaMA。

### 4.5 实践思考

诊断内存不足时先分清参数、优化器、梯度与激活，不应盲目调低所有超参。实验三迁移这种“先定状态对象再定预算”的方法，但其分配对象仅是推理KV块。

## 第5章 有监督微调

SFT将指令及期望回答组织成可训练序列。实验二的掩码问题连接基础章的逐词元概率、数据章的目标构造和强化学习章的不同监督信号，避免把所有loss统称为对齐。

[返回课程：第5章 有监督微调](/learn/large-scale-llm-practice/07-supervised-finetuning/lsl-05-supervised-finetuning)。

### 5.1 提示学习和语境学习

提示学习与语境学习通过输入条件影响输出，不必更新参数。与SFT的区别在于改变发生于输入还是学习过程，因此答题变好不能直接证明发生了参数微调。

### 5.1.1 提示学习

提示可描述任务、约束格式或给出角色信息。改提示也是一次实验变量变化；第8章比较模型时应固定提示，或明确把提示策略作为被评估系统的一部分。

### 5.1.2 语境学习

语境学习通过输入示例展示任务，通常不更新权重。若把测试题及答案当作示例，模型就见到了目标信息；这与实验一切分泄漏不同形式、同样破坏独立检查。

### 5.2 高效模型微调

高效微调减少需要更新或保存的参数，缓解适配成本。它没有取消训练目标、激活或基础权重的存在，显存节省应分项核算，不能仅凭可训练参数比例估计总显存。

### 5.2.1 LoRA

LoRA用低秩矩阵乘积表示权重增量，基础权重可冻结。冻结权重并非停止所有反向传播；梯度仍须经计算路径到达适配器，与目标掩码的零直接梯度也不是一回事。

### 5.2.2 LoRA的变体

LoRA变体改变低秩预算分配或结合量化等方法。参数量、精度与训练稳定性分别受不同选择影响，选型应报告实际适配对象，不可只把名称中的“高效”当成效果证明。

### 5.3 模型上下文窗口扩展

上下文窗口扩展处理位置表示与长序列适应问题。可接收更多词元不等于能利用所有远处信息，而且会提高缓存与计算压力，需连接第7章资源和第8章长上下文评价。

### 5.3.1 具有外推能力的位置编码

外推位置编码希望在超出训练长度时保留有用关系。设计动机不等于无限长度保证，应在超长输入上检验任务质量，而不是仅检查程序是否没有报错。

### 5.3.2 插值法

位置插值把更长序列的位置映射回原来的位置范围，通常需配合适应训练。距离尺度因此改变；扩窗后仍要验证细粒度位置关系，并重新预算服务KV。

### 5.4 指令数据构建

指令数据需说明任务、上下文和回答的边界。这个边界决定哪些词元成为学习目标，实验二正是把预处理差异落实到loss与梯度，而不止比较数据集名称。

### 5.4.1 手动构建指令

人工指令构建需要规范任务与答案质量，标注一致性比数量本身更重要。与第6章成对偏好标注相比，SFT提供的是期望回答文本，不是只给两答案排序。

### 5.4.2 自动生成指令

自动生成指令扩大覆盖，也可能继承生成模型偏差或产生近重复。生成后仍需筛选与隔离；把自动生成测试题和其训练来源分开，应结合实验一的关联分量检查。

### 5.4.3 开源指令数据集

开源指令集降低起步成本，但不同集合的模板、许可和任务分布不同。混合训练之前先统一字段与目标规则，评估时警惕与公开基准的内容重合。

### 5.5 DeepSpeed-Chat SFT实践

DeepSpeed-Chat的SFT实践连接预处理、模型包装、训练和推理。这里可迁移的是顺序与职责：先验证标签，再启动训练，最后独立生成检查；代码接口保留历史语境。

### 5.5.1 代码结构

代码结构把数据处理、模型创建和训练入口分离，便于定位错误。实验二若出现提示梯度，优先检查数据到标签路径，不应先到服务调度器里找原因。

### 5.5.2 数据预处理

预处理把提示与回答拼接、分词并生成标签或掩码。填充与提示位置是否计损失必须显式约定，且移位对齐后检查目标；否则模型会优化与任务不一致的文本位置。

### 5.5.3 自定义模型

自定义模型要使输出、词表和损失接口一致。换骨干并不保证旧包装可直接用，应先验证输出logit的轴和目标索引，再进行多卡训练。

### 5.5.4 模型训练

训练将样本和目标送入前向、反向与优化器更新。观察loss下降只能证明所定义目标改善，不能排除标签错位；实验二即便算得顺利也可能优化错误提示目标。

### 5.5.5 模型推理

推理只提供提示生成回答，不再提供监督答案。若把训练拼接序列原样带答案送入推理，会把“能接续给定答案”误当成“能自行回答”。

### 5.6 实践思考

SFT的实践思考应比较提示策略、目标范围与适配成本。实验二改为整段目标不是数值崩溃，而是换了任务权重；只有在约定仅训回答时，忽略掩码才是实现故障。

## 第6章 强化学习

强化学习章引入偏好与策略优化，超越逐词元模仿。实验二只模拟奖励模型的成对排序，不实现策略采样、价值函数、优势估计或PPO；不要把曲线称作完整RLHF训练。

[返回课程：第6章 强化学习](/learn/large-scale-llm-practice/08-reinforcement-learning/lsl-06-reinforcement-learning)。

### 6.1 基于人类反馈的强化学习

RLHF通常先获得SFT策略，再训练奖励模型并以其反馈优化策略。各阶段可以使用不同数据与模型副本，最后仍需要独立评价，不能用训练奖励直接证明真实用户满意度。

### 6.1.1 强化学习概述

强化学习以交互产生的回报引导策略选择动作。语言生成中可将词元视为动作，但动作间有序依赖；本页四个独立logit故意不具备这种完整环境结构。

### 6.1.2 强化学习与有监督学习的区别

有监督学习给定示范目标，强化学习通过回报评价采取的动作。奖励高不等于每个词都有参考标签，也不保证内容真实；错位奖励可以使策略学会取巧。

### 6.1.3 基于人类反馈的强化学习流程

RLHF流程把演示、偏好排序和策略更新连接起来。诊断时先问数据属于哪一阶段；实验二翻转偏好改变的是期望奖励排序，忽略SFT掩码改变的是词元监督范围。

### 6.2 奖励模型

奖励模型把提示与回答映成标量以拟合偏好排序。标量是代理信号，可能受长度或文风影响；第8章应使用独立标准，不要只报告这个模型自己的高分。

### 6.2.1 数据收集

成对数据需在同一提示下比较回答，并保留标注方向与一致性。把胜者和败者交换会反转监督含义，实验二的负奖励差说明正确程序仍可忠实学习错误标注。

### 6.2.2 模型训练

常见成对损失用胜者与败者奖励差进入sigmoid。它学相对排序而不直接最大化回答的词元概率；这不是DPO的策略比率目标，更不是PPO的裁剪策略目标。

### 6.2.3 开源数据

开源偏好数据的标注方式、语言与安全范围各不相同。训练前要核对胜负字段而非仅读列名；训练集与评价集还要按提示或关联来源隔离。

### 6.3 近端策略优化

PPO通过限制策略变化改善更新稳定性。它需要旧策略概率、优势等对象；实验二只画奖励差损失，缺少这些对象，所以不能从该图声称完成了PPO。

### 6.3.1 策略梯度

策略梯度把采样动作的对数概率梯度与回报或优势结合。高回报动作会增加相应概率，但方差与信用分配仍需处理；它不是对奖励差曲线直接求一次导数就结束。

### 6.3.2 广义优势估计

广义优势估计结合时序差分残差，以折扣和衰减权衡偏差与方差。估计量依赖奖励、价值与终止处理；漏处理结束位置会把不该传播的后续价值带入。

### 6.3.3 近端策略优化算法

PPO用新旧策略概率比与裁剪目标限制更新，常伴随价值与正则项。裁剪不是硬保证所有参数或KL都不变，因此训练后仍需监测策略漂移与任务表现。

### 6.4 MOSS-RLHF实践

MOSS-RLHF实践把奖励模型与PPO分阶段实现。复习时沿样本、奖励、优势、策略更新检查接口，历史工程路径可供理解，但本页没有运行该仓库或复刻其成绩。

### 6.4.1 奖励模型训练

奖励模型训练先将成对回答与偏好方向匹配，再计算排序损失。若偏好反向，损失同样可以下降；这与实验二曲线上移动的红点相连，不能只靠下降日志验收数据。

### 6.4.2 PPO微调

PPO微调使用策略生成样本并结合奖励与约束更新。SFT参考、旧策略和价值估计有不同职责，不能任意共用或遗漏；独立评估要检验奖励取巧与能力退化。

### 6.5 实践思考

强化学习实践应检查奖励是否忠实于用户目标，以及优化后是否产生副作用。即使代理奖励提高，答题、安全或多样性也可能下降；需要连接第8章多维评估。

## 第7章 大语言模型应用

应用章把已训练模型接入提示、检索、工具、模态与服务。外部组件会改变结果与成本，实验三只取服务缓存和接纳部分，不把它当成完整应用性能或端到端质量。

[返回课程：第7章 大语言模型应用](/learn/large-scale-llm-practice/09-applications/lsl-07-llm-applications)。

### 7.1 推理规划

推理规划用提示组织中间过程或子问题。中间步骤有助于结构化任务，但可读解释不是正确性的保证；最终答案及所用外部事实仍需要第8章的方法检查。

### 7.1.1 思维链提示（Chain-of-Thought Prompting）

思维链提示展示或诱导中间推理步骤，可能改善部分复杂任务。链条写得长不代表逻辑无误，评价时不可仅以步骤数量替代结果正确性，也应固定提示设置。

### 7.1.2 由少至多提示（Least-to-Most Prompting）

由少至多提示先分解再逐步求解，并将前面结果用于后续。早期子问题出错会传播，所以要定位首次错误；它不是靠一次更长提示就保证解决所有复杂问题。

### 7.2 综合应用框架

应用框架组织模型、提示、检索与工具的调用。它提供接口组合而非替代模型质量判断；切换框架若同时改变检索和提示，便不能把收益只归因于底层模型。

### 7.2.1 LangChain框架核心模块

第一版LangChain核心模块涉及模型、提示、记忆、索引、链与代理等组织方式。这里的记忆是应用管理的上下文状态，不是实验三的物理KV，也不是模型权重中的知识。

### 7.2.2 知识库问答实践

知识库问答先检索再把相关内容供模型生成。检索来源可提高可追查性，但若库中存有测试答案，成绩仍会受污染；应分开报告检索命中、回答质量和评估数据边界。

### 7.3 智能代理

智能代理围绕目标循环选择行动并利用反馈。工具返回不是天然可信输入，动作还可能产生外部副作用；应把权限、终止与结果验证纳入系统设计。

### 7.3.1 智能代理的组成

代理的规划、记忆与工具能力各有状态和接口。查错要区分模型决定错、工具执行错与记忆取错，而不是把所有失败都归于模型参数量不够。

### 7.3.2 智能代理的应用实例

应用实例展示任务分解与工具交互的组合价值。复用实例应限定允许的动作和环境；一个成功轨迹不证明其他任务安全，也不能用无限重试隐藏失败成本。

### 7.4 多模态大模型

多模态模型将图像等输入与语言处理连接。第8章若检验视觉问答，除语言表达外还需验证对图像事实的依赖；文本流畅不能证明模型真正使用了视觉输入。

### 7.4.1 模型架构

视觉编码器、连接模块和语言骨干可用不同方式组合，决定信息如何对齐。可训练模块选择又连接第5章高效适配，不应把所有多模态结构当成一套相同训练目标。

### 7.4.2 数据收集与训练策略

图文配对数据与分阶段训练常用于建立跨模态对应及指令能力。数据噪声或配对错误会破坏对齐，评估应避免重复图片或近似描述跨入测试。

### 7.4.3 多模态能力示例

多模态示例可展示描述、问答或推理，但示例只是能力片段。需改变图像关键事实并检查回答是否随之变化，才能排除仅靠语言先验猜中的可能。

### 7.5 大语言模型推理优化

自回归推理分提示处理与逐步解码，KV缓存避免重复计算过去的键值。缓存占用随请求增长，实验三简化为静态块需求，用它隔离内存接纳与排队，不模拟逐词元增长。

### 7.5.1 FastServe框架

第一版FastServe将迭代级执行、抢占与键值缓存管理结合，讨论Skip-join多级反馈队列。实验三的FIFO/绕过是较小的教学规则，不是这一真实调度算法或其性能复现。

### 7.5.2 vLLM推理框架实践

vLLM的PagedAttention用块表管理非连续的KV存储，减少浪费并支持共享。实验三展示稳定物理槽分配与释放，但省略真实块表、共享、写时复制与注意力内核，不声称实现vLLM。

### 7.6 实践思考

应用实践要同时固定输入任务与计费资源。若丢弃最难或最长请求，吞吐可能变漂亮；实验三用完成2/3的反例，把未服务请求明确留在比较分母中。

## 第8章 大语言模型评估

评估章把模型能力转成受任务、输入和指标限定的结论。实验一查测试独立性，实验二查目标是否偷换，实验三查负载和资源是否相同；三者不能由一个排行榜分数替代。

[返回课程：第8章 大语言模型评估](/learn/large-scale-llm-practice/10-evaluation/lsl-08-llm-evaluation)。

### 8.1 模型评估概述

评估先确定用途、数据和判断规则，再决定比较对象。离线准确率、人工偏好与在线服务指标回答不同问题，报告时应明确哪一层改善，避免把系统速度写成知识能力。

### 8.2 大语言模型评估体系

评价体系覆盖知识能力、伦理安全和垂直领域。维度之间不保证同步改善；奖励模型偏好和服务吞吐即使都上升，也仍需分别验证事实正确与危险行为。

### 8.2.1 知识与能力

知识与能力测试考察事实、推理等方面，但题型决定可见能力。多选得分不能完整表示开放生成质量，且公开题污染会让实验一中的记忆命中伪装成能力。

### 8.2.2 伦理与安全

伦理与安全涉及偏见、有害内容和隐私等问题。安全评价要覆盖具体风险与攻击情境，不是给模型附一个通用安全标签；第3章的数据隐私处理也不能替代输出检查。

### 8.2.3 垂直领域评估

垂直领域评估需匹配领域知识、术语和真实任务代价。通用知识总分不能保证医疗或法律应用可靠，专业测试还应说明数据时效和需要人工介入的边界。

### 8.3 大语言模型评估方法

指标描述如何计算，方法决定怎样采样和比较。实验一固定答题规则后换独立集合，实验三固定请求集合后换调度，都是先把可比较对象定义清楚再算数字。

### 8.3.1 评估指标

似然、准确率、重合类指标或人工评分各有适用任务。聚合前要说明分母和权重；只在完成请求上统计或把重复题当独立样本，都可能误导结论。

### 8.3.2 评估方法

自动、人工与模型辅助评估都有局限，需考虑提示、位置或裁判偏差。模型评分可提高规模化效率，但应校准并保留人类复核，不把裁判身份当成绝对真值。

### 8.4 大语言模型评估实践

基础模型与SFT/RL模型的输出接口不同，评估配置也应适配。比较时显式记录提示、解码、上下文与样本集合，而不是只看模型名称和总分。

### 8.4.1 基础模型评估

基础模型可通过续写似然或语境示例进行测试，词元化和选项评分规则会影响结果。把候选答案放进上下文打分不同于自由生成，不能把两种设置直接混作同一准确率。

### 8.4.2 SFT/RL模型评估

SFT/RL模型适合额外检查开放回答与多轮交互，书中讨论匿名成对比较等方法。偏好胜率需说明提问分布、匿名与投票规则，不把一次胜出当成普遍优越。

### 8.5 实践思考

评估实践思考要求同任务、同标准，并报告不足。实验三中完成少一个请求的方案即使平均更快也不能直接获胜，实验一清除污染后分数降低反而更接近真实泛化检查。

参考文献把正文主张连到论文与资料。复习时按具体机制回查支持段落与版本；镜像或重复著录不是新增独立研究，参考文献课程页提供了身份与主张范围的核对方法。

## 常见误区：同名对象与错误场景

- **现象 →** A像B且B像C，所以A与C一定重复。**原因 →** 把闭包分组政策误认成相似关系的传递性。**修法 →** 观察实验一删桥接边后的分量变化；保守切分不替代边质量检查。
- **现象 →** 提示不计损失，所以提示无法影响学习。**原因 →** 把直接目标梯度和共享网络反向传播混为一谈。**修法 →** 用实验二定位损失端掩码，同时保留回答的上下文；偏好目标还须单独核对标注。
- **现象 →** 长请求多时总是选绕过，或用丢A的2请求/拍宣布提速。**原因 →** 选错场景且忽略未完成工作。**修法 →** 用实验三核对完整请求集合、等待与资源；必要时加入公平性约束，不能从本例推出通用最优调度。

## 小结与三道迁移练习

- 分组切分保护独立性，不保证分数更高。
- 先核对目标与分母，再解读梯度和奖励。
- 同负载、明资源，吞吐才有可比性。
