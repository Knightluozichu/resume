## 为什么看不见的背面仍然会消耗 GPU

前几章那条流水线已经学会比远近、按镂空模板放行。但一个实心盒子摆在你面前时，它默认仍会把背对你的三角形送去铺色块。即使这些色块最后被深度测试挡住，前面的几何和覆盖工作已经发生。

这一章给流水线加一道**省料**工序：在真正动手铺色块之前，先扫一眼每个面**是朝着你、还是背对着你**，把指定朝向直接扔掉。对相机在外部的封闭盒子，通常可以省掉大量背面片段工作；但顶点处理已经完成，总帧时收益也取决于场景和 GPU。

没有它会怎样？在正常不透明渲染和深度测试下，盒子通常仍能正确显示，只是 GPU 可能做了更多光栅与片段工作。怎么认出「这个面朝你还是背你」？秘密藏在三角形三个顶点投影后的**绕行方向**里。

## 面剔除：背对你的面，干脆不画

这道省料工序就是 <Term def="primitive 在顶点着色、装配与裁剪之后，进入光栅化前按窗口坐标环绕判定 front/back，并按 glCullFace 丢弃指定朝向。它省光栅化和片段工作，不会省已经执行的 vertex shader；只对可安全忽略一侧的表面启用。">面剔除</Term>（face culling）：GPU 按三角形投影后的朝向，把指定一侧的 primitive **在光栅化之前整体丢掉**，不再产生覆盖样本或运行片段着色器。

更精确的顺序是：所有顶点先执行 vertex shader，primitive 装配并经过裁剪，随后根据窗口坐标有向面积判定正背并剔除，保留面才光栅化。被剔面连片段都不生成，所以主要节省光栅与 fragment shader；顶点成本已经发生，不能把剔除宣传成“整个三角形零成本”。

正常深度测试下，封闭不透明立方体开关剔除后的最终图像通常相同：关闭时背面仍被处理，只是最终深度失败。是否安全不只取决于“封闭”，还取决于相机在外部、材质不需要双面效果、几何环绕一致。摄像机进入封闭网格内部时，原本的背面正是要看的内壁，策略必须切换。

## 环绕顺序：顶点绕一圈是逆时针还是顺时针

那 GPU 凭什么一眼认出「这个面朝你还是背你」？靠的是三角形三个顶点的 <Term def="三角形顶点按 v0→v1→v2 投影到窗口坐标后形成的逆时针（CCW）或顺时针（CW）方向。原始索引给出起点，完整变换链可能保持或翻转它；GPU 用最终窗口环绕判定 front/back。">环绕顺序</Term>（winding order）——把三个顶点按定义的先后（`v0 → v1 → v2`）连起来走一圈，这一圈要么是**逆时针**（CCW，counter-clockwise）、要么是**顺时针**（CW，clockwise）。

这个方向完全由你**定义顶点的顺序**决定。同样三个位置的点，你先写左下还是先写右下，绕出来的方向就相反。一般约定建模时所有三角形都按**逆时针**定义顶点。下面这张图把「逆时针」和「顺时针」两种绕法并排画出来：

<WindingOrderDiagram />

记住一个反直觉但关键的事实（也是整章的题眼）：**同一个三角形，从正面看是逆时针、从它背面看就变成顺时针**——就像你正面看墙上一个顺时针画的钟，绕到墙背后透过去看，它就成了逆时针。GPU 利用的正是这一点。

## 正面与背面：投影到屏幕后看到的环绕方向

有了环绕顺序，区分正背面就水到渠成了。一个三角形投影到屏幕后，GPU 看它三个顶点**在窗口坐标中**的环绕方向：方向和 `glFrontFace` 约定一致（默认逆时针），它就是 <Term def="投影到窗口坐标后，顶点环绕与 glFrontFace 约定一致的 polygon。默认约定为 CCW；是否保留还取决于 glCullFace，并不等于它在所有模型里都必然可见。">正面</Term>（front face）；方向相反，它就是 <Term def="投影到窗口坐标后，顶点环绕与 glFrontFace 约定相反的 polygon。默认 glCullFace(GL_BACK) 会剔除它，但室内视角、开放网格和双面材质可能需要保留。">背面</Term>（back face）。

为什么这招管用？正是上一节那个事实：封闭物体上，朝向你的面投影后保持约定的逆时针（正面），而背对你的面是「从背后看」的，环绕自动反转成顺时针（背面）。于是 GPU 不需要任何额外信息，单看屏幕上的环绕方向，就能把朝你的和背你的分得清清楚楚。这个判定过程，下一节单步走一遍就彻底清楚了。

## glCullFace 与 glFrontFace：剔谁、谁算正面

光会判定还不够，你得告诉 GPU **剔哪一面**、以及**哪种环绕算正面**，这是两个独立的开关。先看决定剔掉哪一面的 <Term def="设置面剔除『剔掉哪一面』的函数，原型 glCullFace(mode)：GL_BACK 只剔背面（默认，最常用）、GL_FRONT 只剔正面、GL_FRONT_AND_BACK 正背都剔。它只在面剔除已启用（glEnable(GL_CULL_FACE)）时才生效。">`glCullFace`</Term>，默认是 `GL_BACK`（剔背面，也是绝大多数情况要的）；再看决定哪种环绕算正面的 <Term def="设置哪种窗口坐标环绕算正面的函数：GL_CCW 为逆时针（默认），GL_CW 为顺时针。约定必须匹配完整变换后的最终环绕；镜像变换可能让原本正确的索引翻转。">`glFrontFace`</Term>，默认是 `GL_CCW`（逆时针为正面）。这两件套配上 `glEnable(GL_CULL_FACE)` 这个总开关，就是面剔除的全部 API。

`glCullFace` 可填的值就三个：

| `glCullFace(...)`   | 剔掉哪一面                           |
| ------------------- | ------------------------------------ |
| `GL_BACK`           | 只剔**背面**（**默认**，最常用）     |
| `GL_FRONT`          | 只剔**正面**（反过来，留背面）       |
| `GL_FRONT_AND_BACK` | 正面背面**都剔**（这个面什么都不画） |

划重点：`glFrontFace` 的约定**必须和完整变换后的窗口环绕一致**。顺时针索引沿用默认 `GL_CCW` 会判反；逆时针索引经过镜像变换也可能得到同样结果。GPU 会把本想保留的面当成背面剔掉，物体可能消失或像内外翻。

## 镜像与负缩放：同一份网格也可能突然翻面

环绕不只由原始索引决定，还受完整变换链影响。普通平移、旋转和正尺度保持朝向；在一个轴上使用 `scale.x = -1` 做镜像，会把窗口几何左右翻转，CCW 变 CW。两个负尺度轴又翻转两次、恢复原方向。判断依据是模型变换左上 3×3 的行列式符号：负值表示奇数次镜像、环绕反转。

<CullingTransformParityDiagram />

渲染镜像实例时有三种做法：为该 draw call 临时切换 `glFrontFace(GL_CW)`；预处理一份反转三角形索引的 mesh；或在确实双面时关闭剔除。状态切换要按 draw 分组并在之后恢复。投影矩阵若人为翻转 Y，也会改变最终窗口环绕，因此跨 OpenGL/Vulkan 或离屏坐标约定时应通过一个已知三角形实测，而不是只看模型文件。

面剔除只看**位置投影后的环绕**，不读取顶点法线；法线反了会让光照错，却不会直接改变 culling。片段 shader 可用 `gl_FrontFacing` 区分当前 primitive 的朝向，为真正双面材质选择不同法线或颜色，但前提是该面没有在更早阶段被剔除。

## 单步走一遍：环绕顺序怎么定出正背面

把上面三节串起来，用一个立方体上「朝你的正面」和「背对你的背面」两个三角形，单步走完整套判定。

> 猜一猜：建模时这两个面的顶点**都按同一个逆时针顺序**定义。可它们一个朝你、一个背你。投影到屏幕后，这两个面看到的环绕方向会**一样还是相反**？哪个还是逆时针、哪个会反转成顺时针？先想一想，再单步走下面三步。

## 代码对照：开启面剔除这三行

面剔除的代码短到不能再短——开总开关、（按需）指定剔哪面和哪种环绕算正面，剩下 GPU 全自动干。

```cpp
glCullFace(GL_BACK);    // 剔背面（默认就是 GL_BACK）
glFrontFace(GL_CCW);    // 逆时针环绕算正面（默认就是 GL_CCW）
```

```ts
// 初始化时开一次：默认是关的，不开就不会剔任何面

// 下面两行其实都是默认值，写出来只为表明意图：
gl.cullFace(gl.BACK); // 剔背面（默认就是 BACK）
gl.frontFace(gl.CCW); // 逆时针环绕算正面（默认就是 CCW）
```

  </Tab>
</CodeTabs>

逻辑两端一字对应：`glEnable(GL_CULL_FACE)` 打开总开关；`glCullFace` 选剔哪面、`glFrontFace` 选哪种环绕算正面。默认值适合环绕一致、无镜像的封闭外壳；室内视角、镜像实例和双面材质必须按 draw call 调整。`GL_FRONT` 也常用于只渲染内壁或某些阴影 pass，但它不是所有室内场景的固定答案。注意这里的 API 差异和那个最容易栽的前提：

<Callout type="warn">
  API 差异：桌面是全局函数 + 大写常量 `glEnable(GL_CULL_FACE)`；WebGL2
  是上下文方法 + 上下文常量 `gl.enable(gl.CULL_FACE)`，`gl.cullFace` /
  `gl.frontFace` 同理。更要命的是 **面剔除默认是关的**——不调 `glEnable`
  它一点不起作用、也不报错。还有一条铁律：**`glFrontFace`
  的约定必须和完整变换后的窗口绕向一致**。普通逆时针网格保持默认
  `GL_CCW`；顺时针数据或发生环绕翻转的镜像实例应改用
  `GL_CW`，否则本想保留的面会被当作背面剔掉。
</Callout>

### 镜像实例：按变换奇偶修正正面约定

若同一 mesh 既画普通实例又画镜像实例，应在每次绘制前根据变换奇偶选择正面约定，并在结束后恢复状态。实际引擎可预先把 `mirrored` 存进实例数据，再按该标志分组绘制，避免频繁切换状态。

<CodeTabs>
  <Tab label="C++ / OpenGL 3.3">

```cpp
const bool mirrored = glm::determinant(glm::mat3(model)) < 0.0f;

glFrontFace(mirrored ? GL_CW : GL_CCW);
glCullFace(GL_BACK);
DrawMesh();

// 恢复 pass 约定，避免影响后续 draw call。
glFrontFace(GL_CCW);
```

  </Tab>
  <Tab label="TypeScript / WebGL2">

```ts
// mirrored 在更新实例变换时预先计算。
gl.frontFace(instance.mirrored ? gl.CW : gl.CCW);
gl.cullFace(gl.BACK);
drawMesh(instance);

// 恢复 pass 约定，避免状态泄漏。
gl.frontFace(gl.CCW);
```

  </Tab>
</CodeTabs>

## 怎样证明剔除真的省到了

不要用“最终画面更干净”判断性能，因为正常 opaque 场景开关剔除后本就应当看起来一样。固定相机、分辨率和材质，分别测量关闭与开启剔除时的 GPU 时间；若分析器支持，再比较 submitted primitives、rasterized primitives 和 fragment invocations。

预期是：vertex shader invocations 基本不变，被光栅化的 primitive 与片段调用减少。减少幅度受可见朝向、遮挡、Early-Z、片段着色成本和硬件架构影响，不能把“约一半背面”直接换算成“帧时间快一倍”。对很小、已被 Early-Z 高效拒绝或顶点瓶颈的场景，收益可能很小，应以测量结果决定是否保留状态复杂度。

## 容易踩的坑

<Callout type="trap">
  **现象**：开了面剔除后，物体**整个消失**了，或者看起来像**内外翻**——只剩本该看不见的内壁、朝你的面全没了。**原因**：环绕约定对不上——要么顶点数据其实是**顺时针**定义的，`glFrontFace`
  却还是默认 `GL_CCW`；要么不小心把 `glCullFace` 设成了
  `GL_FRONT`（剔正面）。两种都导致**正面被当背面剔掉**。**修法**：让
  `glFrontFace` 和顶点真实绕向一致（顺时针数据用 `GL_CW`），并确认 `glCullFace`
  是 `GL_BACK`。
</Callout>

<Callout type="trap">
  **现象**：普通实例正常，同一 mesh 做 X 轴负缩放后却消失或内外翻。**原因**：奇数个负尺度轴让变换行列式为负，窗口环绕翻转，但 `glFrontFace` 仍沿用原约定；重算法线不能修复 culling。**修法**：镜像 draw call 切换 `GL_CW`、使用反向索引，或按材质关闭剔除，并在绘制后恢复状态。
</Callout>

<Callout type="trap">
  **现象**：给一片**草**、一张**纸片**、一面**布**（这类只有一层、两面都要看见的网格）开了面剔除，结果它从某些角度看**缺了一半、出现破洞**或干脆消失。**原因**：面剔除假设「背面看不见」，可单面/开放网格**没有把内部裹住**，它的「背面」其实是要给你看的另一面——被剔掉就破了。**修法**：对这类单面或双面要看的物体，**别开面剔除**（`glDisable(GL_CULL_FACE)`），或单独为它们临时关掉、画完再开回来。
</Callout>

<Callout type="trap">
  **现象**：照着教程设了 `glCullFace` /
  `glFrontFace`，可性能一点没省、背面照样在画。**原因**：忘了
  `glEnable(GL_CULL_FACE)` 这个**总开关**——它默认是**关**的，光设 `glCullFace` /
  `glFrontFace` 而不启用，面剔除根本没开工，还不报错。**修法**：初始化时务必
  `glEnable(GL_CULL_FACE)` 开一次；想临时不剔，用 `glDisable(GL_CULL_FACE)` 关。
</Callout>

## 小结

- **面剔除**位于顶点处理之后、光栅化之前：省光栅与片段工作，不省已经执行的 vertex shader
- GPU 按最终窗口坐标的 **CCW / CW 环绕**判定 front/back，不读取法线，也不比较深度
- `glEnable` 开总开关，`glCullFace` 选剔哪侧，`glFrontFace` 定义哪种环绕算正面；每个 pass 都要管理和恢复状态
- 镜像或奇数轴负缩放会翻转环绕，应切换 front-face 或反转索引；室内视角、开放网格和双面材质需要单独策略
- 收益取决于场景、Early-Z 与 shader 成本；用 GPU 时间和 primitive/fragment 计数验证，不能按“背面约一半”推导帧时间

<Exercises>

**问题 1（排错题：物体消失 / 破洞）** 某人做了两件事都翻车了：① 给一个立方体开了面剔除，立方体却**整个消失**了；② 给一片随风摆的**草**（一张单面纸片网格）开了同样的设置，草从背面看**整个没了**。这两个现象分别是什么原因？各自怎么改？

<Answer>

两个翻车原因不同：

① **立方体消失**：这是环绕约定对不上——它的顶点数据其实是**顺时针**定义的，而 `glFrontFace` 还是默认 `GL_CCW`，于是 GPU 把它朝你的**正面全判成了背面剔掉**，只剩本该看不见的内壁，看起来就是「消失 / 内外翻」。修法：把 `glFrontFace(GL_CW)` 改成和顶点真实绕向一致（或反过来调整顶点数据），确保 `glCullFace` 是 `GL_BACK`。

② **草从背面没了**：草是**单面网格**，两面都要看见，但面剔除会把它「背对你」的那一面当背面剔掉——绕到草背后看，正好剔的就是你要看的那面，于是整片草没了。修法：草这类单面 / 双面要看的网格**根本不该开面剔除**，给它单独 `glDisable(GL_CULL_FACE)`，画完再开回来。

关键区别：①是「该开却设错了约定」，②是「这类物体压根不该开」。

</Answer>

**问题 2（问答题）** 有人说「面剔除靠的是比较深度，把更远的面扔掉」。这个说法对吗？面剔除到底是在管线的哪一步、靠什么信息认出该剔的面？它和深度测试是同一回事吗？

<Answer>

不对。面剔除**不比较深度**，靠的是三角形三个顶点投影到屏幕后的**环绕方向**（逆时针还是顺时针）来判正背面，把背面剔掉。它发生在**光栅化之前**（顶点投影完、还没拆成片段时），被剔的面连片段都不生成。

它和**深度测试**是两回事：深度测试按样本比较深度值，逻辑上属于逐片段操作；实现若满足条件可做 Early-Z，在片段着色器前提前拒绝，也可能在片段着色后完成。面剔除则在**光栅化之前**按环绕整面丢弃。两者互不替代：前者解决遮挡，后者利用表面朝向减少后续工作。

</Answer>

**问题 3（改设置 / 观察题）** 在 §5 那个「剔除关 vs 开」对比里，默认是 `glCullFace(GL_BACK)`（剔背面）。如果把它改成 `glCullFace(GL_FRONT)`（改剔正面），对着一个封闭立方体看，画面会变成什么样？这种「剔正面」在什么场景下反而有用？

<Answer>

改成 `glCullFace(GL_FRONT)` 后，朝你的**正面全被剔掉**，留下的是**背对你的背面**——于是你会**透过物体看到它的内壁**，就像把立方体「翻过来从里面看」。对一个普通实心立方体来说这通常是穿帮的。

但「剔正面」在**从物体内部观察**的场景下反而正好有用：比如你要做一个**房间 / 天空盒**，把摄像机放在一个大盒子内部，你想看到的恰恰是盒子的**内壁**（背对盒子外侧、朝向房间内的那些面）。这时剔掉朝外的正面、保留朝内的背面，正好把房间内壁干净地显示出来，又省掉了朝外那些你看不到的面。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="面剔除">
  渲染管线在**光栅化之前**的一道优化工序：GPU
  根据窗口环绕把指定朝向的 polygon **直接丢弃**，不再为它们光栅化、跑片段着色器；已经发生的顶点处理不会被省掉。默认**关闭**，要手动
  `glEnable(GL_CULL_FACE)` 开。详见本章「面剔除」一节。
</GlossaryItem>

<GlossaryItem term="环绕顺序">
  一个三角形的三个顶点，按定义的先后（`v0 → v1 →
  v2`）投影到窗口坐标后，要么是**逆时针**（CCW，counter-clockwise）、要么是**顺时针**（CW，clockwise）。原始索引决定起始绕向，镜像等变换还可能把它翻转；GPU 用最终结果判定正面 / 背面。详见本章「环绕顺序」一节。
</GlossaryItem>

<GlossaryItem term="正面">
  投影到屏幕后，三个顶点的环绕方向和你约定的方向（默认逆时针
  CCW）**一致**的 polygon。默认剔背设置会保留它，但“正面”是环绕分类，不保证它在任意材质和相机位置下必然可见。详见本章「正面与背面」一节。
</GlossaryItem>

<GlossaryItem term="背面">
  投影到窗口坐标后，顶点环绕和 `glFrontFace` 约定**相反**的 polygon。默认 `glCullFace(GL_BACK)` 会丢弃它；室内视角、开放网格和双面材质则可能需要保留。详见本章「正面与背面」一节。
</GlossaryItem>

<GlossaryItem term="glCullFace">
  设置面剔除「**剔掉哪一面**」的函数，原型 `glCullFace(mode)`：`GL_BACK`
  只剔背面（**默认**，最常用）、`GL_FRONT` 只剔正面、`GL_FRONT_AND_BACK`
  正背都剔（这个面就什么都不画了）。它只在面剔除已启用 `glEnable(GL_CULL_FACE)`
  时才生效。详见本章「glCullFace 与 glFrontFace」一节。
</GlossaryItem>

<GlossaryItem term="glFrontFace">
  设置「**哪种环绕方向算正面**」的函数，原型 `glFrontFace(mode)`：`GL_CCW`
  表示逆时针环绕为正面（**默认**）、`GL_CW`
  表示顺时针环绕为正面。它**必须和完整变换后的窗口环绕一致**——原始索引正确但镜像变换未修正时，正面仍会被当背面剔掉。详见本章「glCullFace
  与 glFrontFace」一节。
</GlossaryItem>

</Glossary>
