## 直觉引入

把 Linux 内核想象成一座「超级工厂」。你写的一个用户程序调用 `read(fd, buf, 4096)`，这个请求要经过七道关卡：首先通过「安检口」（系统调用入口，第 4 章）从用户态进入内核态；内核查阅「户籍册」（VFS，第 8 章）找到文件对应的操作函数；先去「缓存仓库」（Page Cache）找数据，如果命中直接返回；如果没命中，要去「仓储区」（块设备）调取；调取过程中要分配「搬运箱」（内存管理，第 7 章）；搬运完毕后设备发出「完成信号」（中断处理，第 5 章）；整个过程要「排队挂号」（同步机制，第 6 章）防止数据竞争；而这一切的调度由「交通指挥」（CFS 调度器，第 3 章）协调。

## 四阶段递进

<Term def="Linux内核是操作系统的核心，运行在CPU最高特权级（Ring 0），管理进程、内存、文件、设备和网络等所有硬件资源，为用户态程序提供统一的系统调用接口。">Linux内核</Term>的学习可以拆成四个递进阶段。**内核基础**包括内核简介和进程管理——它们解决「内核是什么」和「怎么管理进程」。**调度与系统调用**包括 CFS 调度器和系统调用机制——它们解决「怎么分配CPU」和「怎么进入内核」。**中断与同步**包括中断处理和内核同步方法——它们解决「怎么响应硬件」和「怎么保证并发安全」。**内存与VFS**包括内存管理和虚拟文件系统——它们解决「怎么分配内存」和「怎么统一文件接口」。

```text
// 「一次 read() 系统调用」——Linux 内核全程参与的数据流
read(fd, buf, 4096)
  // 1. 系统调用入口（第 4 章）：用户态 -> 内核态
  //    syscall 指令 -> entry_SYSCALL_64 -> sys_read
  //    切换栈、保存寄存器、校验参数

  // 2. 进程管理（第 2 章）：找到进程的文件表
  //    current->files->fdt[fd] -> file 对象
  //    task_struct 记录了进程的所有资源

  // 3. VFS 层（第 8 章）：找到文件操作集
  //    file.f_op->read_iter -> ext4_file_read_iter
  //    经 dentry/inode 路由到具体文件系统

  // 4. Page Cache：先查缓存
  //    命中？copy_to_user -> 返回
  //    未命中？-> 分配页，发起块 I/O

  // 5. 内存分配（第 7 章）：分配缓存页
  //    alloc_pages(GFP_KERNEL, order)
  //    -> Buddy System 从 Zone 分配

  // 6. 中断处理（第 5 章）：设备完成
  //    硬中断 -> ACK + 调度 softirq
  //    softirq -> 标记页完成 -> 唤醒等待进程

  // 7. 同步保护（第 6 章）：保护共享数据
  //    自旋锁保护 per-cpu 计数
  //    RCU 保护 dentry/inode 查找

  // 8. 数据返回（全链路）：
  //    softirq完成 -> 唤醒进程 -> copy_to_user
  //    -> sys_read 返回 -> 用户程序继续
```

## 常见误区

<Callout type="trap">
**误区：会调内核 API 就等于懂内核。** 会写 `kmalloc`、`copy_to_user` 注册个设备只是「会用内核接口」——照着教程抄就能做。真正懂内核的人能解释：为什么 CFS 用红黑树而非优先队列（O(log n) 插入删除且可预测）、为什么自旋锁要关抢占而非仅原子操作（防止单核上持锁进程被调度走导致死锁）、为什么 RCU 读端不加锁也能安全（写端先拷贝再延迟回收旧副本）、为什么 VFS 用函数指针表而非 switch 分发（多态，新增文件系统不需改内核核心代码）。把内核当黑盒的人遇到 panic 只能重启；懂机制的人能用 crash 分析 vmcore、用 eBPF 追踪函数参数、用 ftrace 绘制调用图。区分标志：能否解释「Linux 内核为什么这样设计」而非只是「能编译它」。
</Callout>

<Exercises>
**问题 1**：全书四阶段递进是什么？为什么是这个顺序？

<Answer>
内核基础（简介与进程管理）→ 调度与系统调用（CFS/syscall）→ 中断与同步（中断处理/同步方法）→ 内存与VFS（Buddy/Slab/VFS）。顺序由依赖关系决定：先理解内核整体架构和用户态/内核态分层才能进入内核内部；进程是内核管理的核心对象，所以先讲进程管理和调度；系统调用是用户程序进入内核的唯一合法入口；中断是内核响应硬件的机制；多核并发要求同步保护；内存管理是进程和文件系统的底层支撑；VFS 统一了所有文件系统接口。先「认识内核」，再「管理进程」，然后「进入内核」，接着「响应事件」，再「保证并发安全」，然后「分配内存」，最后「统一文件接口」。
</Answer>

**问题 2**：用「一次 read() 系统调用」描述全书主线。

<Answer>
一次 read() 经过七个内核子系统：①系统调用入口（第4章）——syscall指令进入内核态，保存上下文，校验参数；②进程管理（第2章）——当前进程的 task_struct 记录了打开的文件表，通过 fd 找到 file 对象；③VFS层（第8章）——调用 file.f_op->read_iter，经 VFS 抽象层路由到具体文件系统；④内存分配（第7章）——未命中缓存时 alloc_pages 从 Buddy 分配物理页；⑤中断处理（第5章）——DMA完成后硬中断+softirq标记完成，唤醒等待进程；⑥同步保护（第6章）——全程用自旋锁/RCU保护共享数据。一条数据流，七大子系统全部参与。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Linux内核">运行在CPU最高特权级（Ring 0）的核心软件，管理进程、内存、文件、设备和网络等所有硬件资源，为用户态程序提供统一的系统调用接口。全书从架构分层出发，最终用一次read()串联所有子系统。</GlossaryItem>
<GlossaryItem term="四阶段递进">内核基础 → 调度与系统调用 → 中断与同步 → 内存与VFS。每层解决前一层的遗留问题：架构解决「怎么认识」，调度解决「怎么运行」，系统调用解决「怎么进入」，中断解决「怎么响应」，同步解决「怎么并发」，内存解决「怎么分配」，VFS解决「怎么读写」。</GlossaryItem>
<GlossaryItem term="机制与策略分离">Linux内核的两大设计哲学之一。内核提供通用机制（如CFS调度框架、VFS抽象层），具体策略由用户态或可配置模块决定。这让内核保持通用而可扩展。</GlossaryItem>
<GlossaryItem term="一切皆文件">Linux内核的两大设计哲学之一。VFS将设备、管道、socket、普通文件统一为文件描述符接口，用open/read/write/close操作一切，极大简化了编程模型。</GlossaryItem>
</Glossary>
