## 内核架构

<Term def="单片内核将进程管理、内存管理、文件系统、驱动全部运行在内核态同一地址空间，通过函数直接调用协作，性能高但耦合度大。">单片内核</Term>是 Linux 的核心架构选择。与微内核不同，Linux 将所有子系统（调度、内存、VFS、驱动、网络）都放在内核态同一地址空间运行，函数之间直接调用，没有 IPC 开销。但 Linux 吸收了微内核的模块化思想——通过可加载内核模块（LKM）动态加载和卸载驱动、文件系统，无需重启。

## 用户态与内核态

```text
// CPU 特权级与地址空间分离
用户态（Ring 3）
  - 独立虚拟地址空间（通过页表隔离）
  - 不能执行特权指令（修改页表、关中断、直接I/O）
  - 错误只导致自己崩溃（SIGSEGV）

内核态（Ring 0）
  - 共享全局内核地址空间
  - 可执行所有指令、访问所有硬件
  - 错误导致整个系统崩溃（kernel panic）

// 用户程序需要特权操作时
// 必须通过系统调用请求内核代劳
// 内核校验参数后才执行

// 系统调用是唯一合法入口：
//   syscall 指令 -> CPU切换到Ring 0
//   -> 保存上下文 -> 查sys_call_table
//   -> 执行内核函数 -> sysret返回Ring 3
```

## 内核子系统

Linux 内核由八大子系统构成，它们通过数据结构紧密协作：

```text
// 1. 系统调用接口——用户进入内核的唯一入口
//    open/read/write/fork/mmap/...

// 2. 进程管理——创建、调度、销毁进程
//    task_struct / fork / exit / wait

// 3. 进程调度——分配CPU时间
//    CFS / 红黑树 / vruntime

// 4. 内存管理——分配物理内存、管理虚拟地址
//    Zone / Buddy / Slab / 页表

// 5. 虚拟文件系统（VFS）——统一文件接口
//    superblock / inode / dentry / file

// 6. 中断处理——响应硬件和异常
//    IDT / 上半部 / 下半部（softirq/tasklet/workqueue）

// 7. 内核同步——并发保护
//    自旋锁 / 信号量 / RCU / 原子操作

// 8. 设备驱动——控制硬件设备
//    字符设备 / 块设备 / 网络设备
```

<Callout type="info">
**Linux 两大设计哲学：** ①机制与策略分离——内核提供通用机制（如 CFS 调度框架、VFS 抽象层），具体策略由用户态或可配置模块决定。②一切皆文件——VFS 将设备、管道、socket 统一为文件描述符接口。这两条原则让 Linux 极具可扩展性。
</Callout>

## 版本与编译

```text
// 内核版本号体系
X.Y.Z 格式
  X = 主版本号（如 6）
  Y = 次版本号
  Z = 修订号

mainline（主线）
  - Linus 维护的开发分支
  - 每 2-3 个月发布一个版本
  - 包含所有新特性

stable（稳定版）
  - 基于 mainline 做 bug 修复回溯
  - 只修 bug 不加新特性
  - 版本号追加第四位（如 6.6.1）

longterm（LTS 长期支持版）
  - 选定 stable 版本长期维护（2-6年）
  - 为企业发行版提供安全补丁

// 内核编译流程
make menuconfig    // 配置：从Kconfig树选择功能选项 -> .config
make               // 编译：Makefile + Kbuild 编译源文件 -> vmlinux/bzImage + .ko
make modules_install  // 安装模块到 /lib/modules/
make install          // 安装内核到 /boot/

// 可配置构建的原因：
// Linux 要运行在从嵌入式到超算的广泛硬件上
// Kconfig 系统让用户按需裁剪，减小镜像和内存占用
```

<Exercises>
**问题 1**：单片内核和微内核的核心区别是什么？Linux 如何兼得两者优点？

<Answer>
单片内核将所有子系统运行在内核态同一地址空间，函数直接调用，性能高但耦合度大。微内核只把最基本功能放内核态，其余作为用户态服务进程，模块化好但 IPC 开销大。Linux 选择单片内核以获得高性能，同时通过可加载内核模块（LKM）吸收微内核的模块化思想——动态加载/卸载驱动和文件系统无需重启，既保持直接调用的性能，又获得接近微内核的灵活性。
</Answer>

**问题 2**：为什么用户程序不能直接执行特权指令？系统调用如何解决这个问题？

<Answer>
CPU 硬件提供 Ring 特权级机制：用户态运行在 Ring 3，不能执行特权指令（修改页表、关中断、直接 I/O），MMU 阻止用户态访问内核地址空间。用户程序需要特权操作时，通过 syscall 指令触发 CPU 切换到 Ring 0（内核态），内核保存上下文、校验参数后代为执行，执行完毕通过 sysret 返回 Ring 3。系统调用是用户程序进入内核的唯一合法入口，是安全边界的守护者。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="单片内核">将进程管理、内存管理、文件系统、驱动全部运行在内核态同一地址空间的架构。优点是函数直接调用性能高，缺点是耦合度大。Linux选择此架构并通过LKM获得模块化能力。</GlossaryItem>
<GlossaryItem term="可加载内核模块（LKM）">Linux吸收微内核思想的机制。允许在运行时动态加载/卸载驱动和文件系统模块（.ko文件），无需重启。通过insmod/rmmod管理，兼顾性能与可扩展性。</GlossaryItem>
<GlossaryItem term="Ring特权级">CPU硬件机制。Ring 0为内核态（最高特权），Ring 3为用户态（最低特权）。用户态不能执行特权指令，必须通过系统调用进入内核态。</GlossaryItem>
<GlossaryItem term="Kconfig/Kbuild">Linux内核的配置与构建系统。Kconfig定义可选功能选项树，menuconfig生成.config；Kbuild根据.config编译选中的源文件，实现按需裁剪。</GlossaryItem>
</Glossary>
