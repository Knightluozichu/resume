## 机制、对象与故障模型

从多任务和策略进入CFS调度类、时间记账、进程选择、睡眠唤醒、抢占、实时策略和调度系统调用。

本章核心不变量是：**可运行集合、优先级/权重、CPU亲和与抢占条件明确；唤醒不会丢失，调度延迟与公平性有可比较证据。** 它必须同时约束正常、边界、失败和恢复样本。函数返回成功只是一条证据，还要检查对象引用、上下文限制、锁、状态更新和异步清理。

最小实验：用CPU型与I/O型任务构造固定负载，改变nice、亲和与调度类，采集运行时间和调度延迟。

故障实验：注入唤醒风暴、CPU绑定和高优先级实时线程，观察饥饿、迁移与节流边界。

源码证据表至少包含提交、配置、入口、调用栈、当前上下文、对象/字段、锁、预期状态、实际状态、首错和清理十一列。涉及性能还需保存CPU/NUMA放置、预热、采样窗口和延迟分位；涉及异步回调还需保存注册、进入、注销与排空时刻。

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

**问题 1** 为什么不能只凭最终输出验收第4章 进程调度？

<Answer>

<Answer>
  固定源码提交、.config、工具和输入，先预测CFS与调度器类的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

  撤销设置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>
