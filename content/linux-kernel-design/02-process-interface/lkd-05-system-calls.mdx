## 为什么从这个问题开始

<Term def="系统调用ABI连接区分API与ABI阶段的对象、生存期、执行上下文和首错证据。">系统调用ABI</Term>、<Term def="调用号连接选择调用号阶段的对象、生存期、执行上下文和首错证据。">调用号</Term>、<Term def="入口处理连接进入内核入口阶段的对象、生存期、执行上下文和首错证据。">入口处理</Term>、<Term def="参数验证连接复制并验证参数阶段的对象、生存期、执行上下文和首错证据。">参数验证</Term>、<Term def="用户指针连接执行内核实现阶段的对象、生存期、执行上下文和首错证据。">用户指针</Term>
共同构成本章坐标。区分API、POSIX、C库和系统调用，追踪调用号、陷入处理、参数验证、实现绑定与系统调用上下文。

原书基于Linux 2.6.34，正文先还原书中对象、API和控制路径，再把现代内核差异作为显式迁移检查。CFS、tasklet、BKL、基树、单队列块层、旧回写线程等机制不能被现代实现悄悄替换，也不能不加说明地当作当前代码。

## 常见误区

<Callout type="trap">**误区一：** 把C库函数名与内核系统调用一一等同。</Callout>

<Callout type="trap">
  **误区二：** 先解引用用户指针再检查access/copy结果。
</Callout>

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第5章 系统调用？

<Answer>
  最终输出会隐藏错误上下文、引用泄漏、锁序、缓存和延迟回收。必须同时核对版本、入口、对象、生存期、首个状态分叉和恢复结果。
</Answer>

**问题 2** 如何把“进入内核入口”变成源码证据？

<Answer>
  固定源码提交、.config、工具和输入，先预测系统调用ABI与调用号的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  用户指针、长度、权限和返回值在入口处验证；ABI编号稳定，错误路径不泄漏内核数据或资源。
  撤销设置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
