## 进程的一生

```text
// fork() -> 子进程创建
//   kernel_clone() -> copy_process()
//     分配新 task_struct（dup_task_struct）
//     复制父进程资源（写时复制 COW）
//       copy_mm -> 共享页表，标记只读
//       copy_files -> 共享文件描述符表
//       copy_signal -> 复制信号处理表
//     分配新 PID
//     设置 sched_entity（vruntime = 父进程vruntime）
//     加入调度器运行队列

// exec() -> 加载新程序
//   execve() -> do_execve()
//     读取 ELF 文件头
//     替换 mm_struct（新地址空间）
//     映射代码段/数据段/BSS/堆/栈
//     设置入口点（ELF entry point）
//     从第一条指令重新开始

// exit() -> 进程终止
//   do_exit()
//     释放 mm / files / fs / signal
//     设置 state = TASK_DEAD
//     通知父进程（SIGCHLD）
//     加入僵尸队列（等待 wait() 回收）
```

## 进程与线程

<Term def="task_struct是Linux内核中描述进程/线程的核心数据结构，包含标识、调度、内存、文件、信号等全部信息。">task_struct</Term>统一表示进程和线程——在 Linux 内核中线程就是轻量级进程（LWP），没有专门区分。区别仅在于资源共享程度。

```text
// 进程 vs 线程：区别在于 clone() 的 flags
fork()         -> clone(SIGCHLD)           // 复制所有资源
vfork()        -> clone(CLONE_VM|CLONE_VFORK|SIGCHLD)  // 共享mm
pthread_create -> clone(CLONE_VM|CLONE_FS|CLONE_FILES|CLONE_SIGHAND|...)
                                           // 共享mm/fs/files/signal

// task_struct 中的关键标识
pid  = 线程ID（内核内部标识，每个task_struct唯一）
tgid = 线程组ID = 用户视角的"进程PID"
     = 线程组主线程的 pid

// getpid() 返回 tgid（不是 pid！）
// gettid() 返回 pid（实际线程ID）

// 用户程序视角：
//   进程PID = tgid
//   线程TID = pid
//   同一进程的所有线程 tgid 相同，pid 不同
```

## 写时复制

```text
// COW（Copy-On-Write）工作原理
// fork() 时不立即复制整个地址空间

// 步骤1: fork() 时
//   子进程共享父进程的物理页
//   所有页表项标记为只读（PTE去掉写权限）

// 步骤2: 父或子进程尝试写入某个页
//   -> 触发缺页异常（page fault）
//   -> 内核检查：是COW页？
//   -> 分配新物理页，复制内容
//   -> 修改页表项指向新页，恢复写权限
//   -> 返回用户态重新执行写入指令

// 优势：
//   1. fork() 极快（不拷贝几百MB地址空间）
//   2. 节省物理内存（大部分页父子都不修改）
//   3. fork()+exec() 优化（exec立即替换地址空间，无需复制）
```

<Callout type="trap">
**误区：fork() 会复制父进程的全部内存。** 实际上 fork() 用写时复制（COW）技术，子进程只共享父进程的物理页（标记只读），只有实际写入时才触发缺页异常复制该页。典型场景下 fork() 后立即 exec()，子进程根本不会写入旧地址空间，COW 让这种场景几乎零拷贝开销。
</Callout>

## 状态转换

```text
// 进程状态（task_struct->state）
TASK_RUNNING         0   // 就绪或运行中（等待CPU或正在CPU上跑）
TASK_INTERRUPTIBLE   1   // 可中断睡眠（可被信号唤醒）
TASK_UNINTERRUPTIBLE 2   // 不可中断睡眠（不响应信号，如等待磁盘I/O）
__TASK_STOPPED       4   // 停止（SIGSTOP/SIGTSTP）
EXIT_ZOMBIE         16   // 僵尸（已exit，等待父进程wait回收）
EXIT_DEAD           32   // 死亡（父进程已回收，即将释放）

// 僵尸进程问题：
//   子进程 exit() 后变 EXIT_ZOMBIE
//   task_struct 保留（含退出状态）等父进程 wait()
//   如果父进程不 wait() -> 僵尸进程泄漏
//   父进程退出后 -> 孤儿进程被 init 收养 -> init 自动wait
```

<Exercises>
**问题 1**：Linux 中进程和线程的区别是什么？内核如何表示它们？

<Answer>
在 Linux 内核中进程和线程统一用 task_struct 表示，没有专门区分。区别在于共享程度：进程有独立的地址空间（mm_struct）、文件描述符表、信号处理表；线程（轻量级进程 LWP）共享同一进程的这些资源。fork() 创建新进程时复制所有资源；clone() 创建线程时通过 flags 指定共享 mm、files、signal 等。task_struct 中 pid 是线程 ID，tgid 是进程 ID。用户视角的「进程PID」实际上是 tgid，getpid() 返回 tgid。这种设计简化了调度器——只需处理 task_struct，无需区分进程/线程。
</Answer>

**问题 2**：描述进程从 fork 到 exit 的完整生命周期，包括各阶段的状态转换。

<Answer>
①fork() 创建子进程，初始状态 TASK_RUNNING（就绪）；②调度器选中——运行态执行代码；③等待 I/O 或事件——状态变为 TASK_INTERRUPTIBLE（可中断睡眠）或 TASK_UNINTERRUPTIBLE（不可中断睡眠）；④事件完成——被唤醒回到 TASK_RUNNING（就绪）；⑤exit()——调用 do_exit() 释放资源，状态变为 EXIT_ZOMBIE（僵尸态），保留 task_struct 等待父进程 wait() 回收；⑥父进程 wait()——调用 release_task() 释放剩余资源，task_struct 彻底销毁变为 EXIT_DEAD。中途可能有 TASK_STOPPED（被 SIGSTOP 暂停）。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="task_struct">Linux内核中描述进程/线程的核心数据结构，包含标识(pid/tgid)、调度(state/sched_entity)、内存(mm)、文件(files/fs)、信号(signal)等信息。每个进程/线程一个，用slab分配器缓存。</GlossaryItem>
<GlossaryItem term="写时复制（COW）">fork()时不立即复制地址空间，而是共享父进程物理页标记只读。只有写入时才触发缺页异常复制该页。大幅减少fork()耗时和内存占用。</GlossaryItem>
<GlossaryItem term="僵尸进程">进程exit()后到父进程wait()回收之间的过渡状态(EXIT_ZOMBIE)。task_struct保留含退出状态，等待父进程查询。父进程不wait()会导致僵尸泄漏。</GlossaryItem>
<GlossaryItem term="轻量级进程（LWP）">Linux对线程的内部称呼。线程在内核中与进程一样用task_struct表示，区别仅在于通过clone()的flags共享mm/files/signal等资源。同一进程的所有线程tgid相同。</GlossaryItem>
</Glossary>
