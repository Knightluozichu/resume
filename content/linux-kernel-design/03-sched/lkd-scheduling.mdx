## CFS 核心思想

<Term def="CFS（Completely Fair Scheduler）是Linux默认的进程调度器，通过维护每个进程的虚拟运行时间（vruntime），始终选择vruntime最小的进程运行，实现公平的CPU时间分配。">CFS</Term>的核心原则很简单：**谁跑得最少就让谁跑**。每个进程维护一个虚拟运行时间 vruntime，CFS 始终选择 vruntime 最小的进程运行。

## vruntime 计算

vruntime 是 CFS 公平性的核心。它的计算公式将实际运行时间按权重归一化：

$$\text{vruntime} \mathrel{+}= \Delta\text{exec} \times \frac{\text{NICE\_0\_LOAD}}{\text{weight}}$$

其中 $\Delta\text{exec}$ 是进程本次实际运行的物理时间，$\text{weight}$ 是进程权重（由 nice 值决定），$\text{NICE\_0\_LOAD}$ 是 nice 0 的基准权重（1024）。

```text
// nice值 -> 权重映射表（prio_to_weight[40]，预计算）
nice -5:  weight = 3121   // 优先级高，vruntime增长慢
nice -1:  weight = 1277
nice  0:  weight = 1024   // 基准
nice +1:  weight =  820
nice +5:  weight =  335
nice +10: weight =  110   // 优先级低，vruntime增长快

// 每差1级nice, CPU时间份额差约10%
// 权重比约 1.25倍

// CPU时间份额 = weight / sum(所有可运行进程weight)
// 例: A(nice 0, w=1024) + B(nice -5, w=3121)
//   A获得 1024/(1024+3121) = 25%
//   B获得 3121/(1024+3121) = 75%
```

## 红黑树运行队列

```text
// CFS 用红黑树（rbtree）组织运行队列
// 按vruntime排序，最左节点 = vruntime最小

struct cfs_rq {
  struct rb_root_cached tasks_timeline;  // 红黑树根
  struct sched_entity *curr;             // 当前运行的进程
  u64 min_vruntime;                      // 基准vruntime
  unsigned int nr_running;               // 可运行进程数
};

// 调度操作复杂度：
// pick_next_task:  O(1)   // 取最左节点
// enqueue_task:    O(log n)  // 插入红黑树
// dequeue_task:    O(log n)  // 从红黑树删除

// 为什么选红黑树而非优先队列（堆）？
//   堆: 查找最小O(1), 插入O(log n)
//       但删除任意节点需O(n)扫描定位
//   红黑树: 查找最小O(1), 插入O(log n)
//           删除任意节点O(log n)（通过指针直接定位）
//   进程被信号杀死时需从队列移除 -> 红黑树更优
//   且红黑树最坏情况平衡, 不退化为链表
```

## 上下文切换

```text
// 上下文切换完整过程
schedule()
  -> pick_next_task()       // 调度器选下一个进程
  -> context_switch()
       -> switch_mm()       // 切换地址空间
            // 加载新进程页表基址到 CR3
            // 刷新 TLB（不同地址空间时）
       -> switch_to()       // 切换CPU寄存器和内核栈
            // 保存当前进程寄存器到 thread_struct
            // 加载新进程寄存器从 thread_struct
            // 切换内核栈指针

// 不可避免的性能开销：
//   1. TLB刷新 -> 后续访存变慢（需重新走页表）
//   2. CPU缓存(L1/L2/L3)冷启动 -> 新进程数据不在缓存
//   3. 寄存器/栈恢复开销
//   4. 分支预测器冷启动

// 上下文切换约几微秒，是纯开销
// 调度器应尽量减少不必要的切换
```

<Callout type="trap">
**误区：nice 值越低进程跑得越快。** nice 值不改变 CPU 频率，不加快单条指令执行速度。nice 值只影响 CPU 时间份额的分配比例——nice 值低意味着权重高，vruntime 增长慢，被调度选中的频率更高，在单位时间内获得更多 CPU 时间。低优先级进程不会被饿死，只是获得较少时间份额。
</Callout>

<Exercises>
**问题 1**：CFS 如何用 vruntime 实现公平？写出计算公式并解释。

<Answer>
CFS 维护每个进程的虚拟运行时间 vruntime，始终选择 vruntime 最小的进程运行。计算公式：vruntime += delta_exec * NICE_0_LOAD / weight。delta_exec 是实际运行时间，weight 是进程权重（由 nice 值决定）。nice 值越低权重越大，vruntime 增长越慢，被调度的频率更高。CFS 用红黑树按 vruntime 排序，总是取最左节点（vruntime 最小者）运行。当最小者运行一段时间后 vruntime 增长不再是最小，调度器切换到新的最小者，实现公平轮转。
</Answer>

**问题 2**：CFS 为何选择红黑树而非优先队列（堆）来组织运行队列？

<Answer>
红黑树优势：①查找最小值 O(1)——最左节点即 vruntime 最小者；②插入删除 O(log n)——进程入队（被唤醒）和出队高效；③最坏情况平衡，不退化为链表，操作稳定可预测。对比优先队列（堆）：虽然查找最小 O(1)、插入 O(log n)，但删除任意节点（如进程被信号杀死需从队列移除）需要 O(n) 扫描定位，而红黑树通过指针可直接删除 O(log n)。此外红黑树按 vruntime 排序天然支持「选最小」的调度语义。CFS 选择红黑树是操作复杂度和功能需求的平衡。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="vruntime">虚拟运行时间，CFS调度的核心指标。计算为实际运行时间乘以基准权重除以进程权重。vruntime最小的进程优先运行，实现公平分配CPU时间。</GlossaryItem>
<GlossaryItem term="nice值">进程优先级调整值，范围-20到+19，默认0。nice值越低优先级越高。每差1级nice值CPU时间份额差约10%。CFS将nice值映射为权重（nice 0对应1024）。</GlossaryItem>
<GlossaryItem term="红黑树（rbtree）">CFS用于组织运行队列的自平衡二叉搜索树。按vruntime排序，最左节点为最小值。查找最小O(1)，插入删除O(log n)，最坏情况平衡不退化。</GlossaryItem>
<GlossaryItem term="上下文切换">从一个进程切换到另一个进程执行的过程。包括switch_mm切换地址空间（刷新TLB）和switch_to切换寄存器/栈。开销主要来自TLB冷启动和CPU缓存失效，约几微秒。</GlossaryItem>
</Glossary>
