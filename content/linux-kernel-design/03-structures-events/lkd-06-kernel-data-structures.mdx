## 机制、对象与故障模型

比较内核链表、kfifo、idr映射、红黑树和复杂度，用侵入式结构、所有权和访问模式选择数据结构。

本章核心不变量是：**节点所有者、插入删除协议、遍历并发和销毁顺序明确；复杂度与真实访问模式匹配。** 它必须同时约束正常、边界、失败和恢复样本。函数返回成功只是一条证据，还要检查对象引用、上下文限制、锁、状态更新和异步清理。

最小实验：为同一对象集合分别画链表、FIFO、ID映射和树索引操作，比较查找、顺序与内存局部性。

故障实验：注入重复删除、空队列、ID泄漏和遍历期间修改，检查结构不变量何时首次破坏。

源码证据表至少包含提交、配置、入口、调用栈、当前上下文、对象/字段、锁、预期状态、实际状态、首错和清理十一列。涉及性能还需保存CPU/NUMA放置、预热、采样窗口和延迟分位；涉及异步回调还需保存注册、进入、注销与排空时刻。

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

**问题 1** 为什么不能只凭最终输出验收第6章 内核数据结构？

<Answer>
  最终输出会隐藏错误上下文、引用泄漏、锁序、缓存和延迟回收。必须同时核对版本、入口、对象、生存期、首个状态分叉和恢复结果。
</Answer>

**问题 2** 如何把“初始化所有权”变成源码证据？

<Answer>
  固定源码提交、.config、工具和输入，先预测list_head与kfifo的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  节点所有者、插入删除协议、遍历并发和销毁顺序明确；复杂度与真实访问模式匹配。
  撤销设置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>
