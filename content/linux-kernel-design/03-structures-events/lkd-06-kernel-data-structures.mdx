## 为什么从这个问题开始

<Term def="list_head连接描述访问模式阶段的对象、生存期、执行上下文和首错证据。">list_head</Term>、<Term def="kfifo连接选择结构阶段的对象、生存期、执行上下文和首错证据。">kfifo</Term>、<Term def="idr连接初始化所有权阶段的对象、生存期、执行上下文和首错证据。">idr</Term>、<Term def="红黑树连接插入与查找阶段的对象、生存期、执行上下文和首错证据。">红黑树</Term>、<Term def="复杂度连接并发遍历阶段的对象、生存期、执行上下文和首错证据。">复杂度</Term>
共同构成本章坐标。比较内核链表、kfifo、idr映射、红黑树和复杂度，用侵入式结构、所有权和访问模式选择数据结构。

原书基于Linux 2.6.34，正文先还原书中对象、API和控制路径，再把现代内核差异作为显式迁移检查。CFS、tasklet、BKL、基树、单队列块层、旧回写线程等机制不能被现代实现悄悄替换，也不能不加说明地当作当前代码。

## 常见误区

<Callout type="trap">
  **误区一：** 只按大O选择结构，忽略对象数量、缓存局部性和内核现成API。
</Callout>

<Callout type="trap">
  **误区二：** 删除节点后继续使用container_of得到的宿主对象。
</Callout>

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第6章 内核数据结构？

<Answer>
  最终输出会隐藏错误上下文、引用泄漏、锁序、缓存和延迟回收。必须同时核对版本、入口、对象、生存期、首个状态分叉和恢复结果。
</Answer>

**问题 2** 如何把“初始化所有权”变成源码证据？

<Answer>
  固定源码提交、.config、工具和输入，先预测list_head与kfifo的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  节点所有者、插入删除协议、遍历并发和销毁顺序明确；复杂度与真实访问模式匹配。
  撤销设置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
