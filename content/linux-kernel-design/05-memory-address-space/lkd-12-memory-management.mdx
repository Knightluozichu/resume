## 机制、对象与故障模型

从页和区进入页分配、kmalloc/vmalloc、slab、内核栈、高端内存与每CPU分配，建立分配选择树。

本章核心不变量是：**分配标志与上下文匹配，虚拟连续和物理连续需求明确；失败可处理，释放API与来源一致。** 它必须同时约束正常、边界、失败和恢复样本。函数返回成功只是一条证据，还要检查对象引用、上下文限制、锁、状态更新和异步清理。

最小实验：为小对象、大虚拟缓冲、页数组和每CPU计数分别选择分配器，记录地址、标志与失败路径。

故障实验：注入原子上下文睡眠分配、超大kmalloc、错配释放和栈溢出。

源码证据表至少包含提交、配置、入口、调用栈、当前上下文、对象/字段、锁、预期状态、实际状态、首错和清理十一列。涉及性能还需保存CPU/NUMA放置、预热、采样窗口和延迟分位；涉及异步回调还需保存注册、进入、注销与排空时刻。

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

**问题 1** 为什么不能只凭最终输出验收第12章 内存管理？

  page与GFP标志的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

</Answer>
