## 为什么从这个问题开始

<Term def="struct page连接确定容量连续性阶段的对象、生存期、执行上下文和首错证据。">struct page</Term>、<Term def="GFP标志连接选择内存区阶段的对象、生存期、执行上下文和首错证据。">GFP标志</Term>、<Term def="kmalloc连接设置GFP上下文阶段的对象、生存期、执行上下文和首错证据。">kmalloc</Term>、<Term def="slab连接分配并初始化阶段的对象、生存期、执行上下文和首错证据。">slab</Term>、<Term def="每CPU数据连接观察缓存与映射阶段的对象、生存期、执行上下文和首错证据。">每CPU数据</Term>
共同构成本章坐标。从页和区进入页分配、kmalloc/vmalloc、slab、内核栈、高端内存与每CPU分配，建立分配选择树。

原书基于Linux 2.6.34，正文先还原书中对象、API和控制路径，再把现代内核差异作为显式迁移检查。CFS、tasklet、BKL、基树、单队列块层、旧回写线程等机制不能被现代实现悄悄替换，也不能不加说明地当作当前代码。

## 常见误区

<Callout type="trap">**误区一：** 把虚拟连续误认为物理连续。</Callout>

<Callout type="trap">
  **误区二：** 忽略分配失败，或用与分配来源不匹配的释放函数。
</Callout>

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第12章 内存管理？

<Answer>
  最终输出会隐藏错误上下文、引用泄漏、锁序、缓存和延迟回收。必须同时核对版本、入口、对象、生存期、首个状态分叉和恢复结果。
</Answer>

**问题 2** 如何把“设置GFP上下文”变成源码证据？

<Answer>
  固定源码提交、.config、工具和输入，先预测struct
  page与GFP标志的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  分配标志与上下文匹配，虚拟连续和物理连续需求明确；失败可处理，释放API与来源一致。
  撤销设置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>

- struct page：连接“确定容量连续性”的源码对象与运行证据。
