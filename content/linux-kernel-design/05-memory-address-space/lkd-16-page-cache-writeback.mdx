## 为什么从这个问题开始

<Term def="页高速缓存连接定位缓存映射阶段的对象、生存期、执行上下文和首错证据。">页高速缓存</Term>、<Term def="address_space连接查找缓存页阶段的对象、生存期、执行上下文和首错证据。">address_space</Term>、<Term def="脏页连接标记脏页阶段的对象、生存期、执行上下文和首错证据。">脏页</Term>、<Term def="flusher线程连接触发回写阶段的对象、生存期、执行上下文和首错证据。">flusher线程</Term>、<Term def="回写拥塞连接处理拥塞阶段的对象、生存期、执行上下文和首错证据。">回写拥塞</Term>

原书基于Linux 2.6.34，正文先还原书中对象、API和控制路径，再把现代内核差异作为显式迁移检查。CFS、tasklet、BKL、基树、单队列块层、旧回写线程等机制不能被现代实现悄悄替换，也不能不加说明地当作当前代码。

## 四类样本与验收

| 样本 | 只改变什么               | 必查证据                 | 通过条件   |
| ---- | ------------------------ | ------------------------ | ---------- |
| 基线 | 固定提交、配置与输入     | 对象、上下文、状态和日志 | 与预测一致 |
| 边界 | 容量、亲和、长度或时序   | 第一处饱和或拒绝         | 边界可解释 |
| 失败 | 一个指针、锁序或异步故障 | 首错栈、字段和责任层     | 故障可定位 |
| 恢复 | 撤销设置或恢复快照       | 残留对象与同输入重放     | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第16章 页高速缓存和页回写？

<Answer>
  最终输出会隐藏错误上下文、引用泄漏、锁序、缓存和延迟回收。必须同时核对版本、入口、对象、生存期、首个状态分叉和恢复结果。
</Answer>

**问题 2** 如何把“标记脏页”变成源码证据？

<Answer>
  固定源码提交、.config、工具和输入，先预测页高速缓存与address_space的结构字段、执行上下文和状态转换，只改变一个条件并停在首错。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  缓存页归属和脏状态可追踪；回写、错误和回收不会丢失用户已确认的数据语义。
  撤销设置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
