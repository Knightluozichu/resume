## VFS 抽象层

<Term def="VFS（Virtual File System）是内核中的抽象层，为用户态提供统一的文件操作接口，通过函数指针表将操作路由到底层不同文件系统的具体实现。">VFS</Term>是 Linux「一切皆文件」哲学的基石。它让用户可以用相同的 open/read/write/close 操作 ext4、xfs、nfs、procfs 等完全不同的文件系统，无需知道底层差异。

## 四核心对象

```text
// VFS 四个核心对象及其关系

// 1. superblock —— 已挂载的文件系统实例
struct super_block {
  dev_t s_dev;              // 设备号
  unsigned long s_blocksize; // 块大小
  unsigned long s_maxbytes;  // 最大文件大小
  struct file_system_type *s_type;  // 文件系统类型
  const struct super_operations *s_op;  // 操作函数表
  // ...
};

// 2. inode —— 文件/目录的元数据
struct inode {
  unsigned long i_ino;      // inode号
  umode_t i_mode;           // 文件类型和权限
  loff_t i_size;            // 文件大小
  struct timespec i_atime;  // 访问时间
  struct timespec i_mtime;  // 修改时间
  const struct inode_operations *i_op;  // inode操作
  const struct file_operations *i_fop;  // file操作
  // ... 数据块位置信息 ...
};

// 3. dentry —— 目录项（路径分量到inode的映射）
struct dentry {
  struct dentry *d_parent;    // 父目录项
  struct qstr d_name;         // 名字
  struct inode *d_inode;      // 关联的inode
  struct dentry_operations *d_op;
  // ... 构成目录树 ...
};

// 4. file —— 已打开的文件实例
struct file {
  const struct file_operations *f_op;  // 操作函数表
  struct dentry *f_dentry;    // 关联的dentry
  struct inode *f_inode;      // 关联的inode
  loff_t f_pos;               // 当前偏移量
  unsigned int f_flags;       // 打开模式(O_RDONLY等)
  // ...
};

// 关系链:
// superblock -> inode -> dentry -> file
// 一个inode可以有多个dentry（硬链接）
// 一个inode可以有多个file（多次打开）
```

## 路径查找

```text
// open("/home/user/file.txt") 的路径查找过程

// 1. 从根目录 "/" 的 dentry 开始（绝对路径）
//    或从当前工作目录的 dentry 开始（相对路径）

// 2. 逐级解析路径分量
//    分量1: "home"
//      先查 dentry 缓存(dcache)
//      命中? 直接用
//      未命中? 调用父目录inode的 i_op->lookup()
//              -> 具体文件系统从磁盘读取目录项
//              -> 创建新 dentry 并关联 inode

// 3. 分量2: "user" -> 重复上述过程
// 4. 分量3: "file.txt" -> 得到 dentry + inode

// 5. 创建 file 对象
//    设置 file.f_op = inode->i_fop（操作函数表）
//    分配文件描述符 fd
//    返回 fd 给用户

// 后续 read(fd, buf, n):
//   fd -> file -> file.f_op->read()
//   -> VFS路由到 ext4/xfs/nfs 的具体read实现

// "." -> 当前dentry
// ".." -> 父dentry
// 符号链接 -> 递归解析目标路径
```

## 一切皆文件

<Callout type="info">
**VFS 的多态分发：** VFS 调用 `file.f_op->read()`，实际执行的是 ext4 或 xfs 或驱动注册的具体 read 函数。这是通过函数指针表实现的 C 语言多态。新增文件系统只需实现 superblock/inode/dentry/file 的操作接口并注册，无需修改 VFS 核心代码。这就是「机制与策略分离」。
</Callout>

```text
// 「一切皆文件」的三个例子

// 1. 设备文件 /dev/ttyS0（字符设备）
//    file_operations 由驱动注册:
struct file_operations tty_fops = {
  .read  = tty_read,   // 最终调用硬件读
  .write = tty_write,  // 最终调用硬件写
  .open  = tty_open,
  .release = tty_close,
};
//    用户: read(fd, buf, n) 读串口
//    与读普通文件完全一样的API

// 2. proc文件 /proc/cpuinfo（procfs虚拟文件系统）
//    没有实际磁盘数据，内容运行时动态生成:
struct file_operations proc_cpuinfo_fops = {
  .open  = cpuinfo_open,
  .read  = cpuinfo_read,  // 读取CPU信息格式化输出
};
//    用户: cat /proc/cpuinfo 就像读普通文件

// 3. 套接字 socket
//    通过socket()系统调用创建，内部用file对象表示:
struct file_operations socket_file_ops = {
  .read_iter = sock_read_iter,   // 读网络数据
  .write_iter = sock_write_iter, // 写网络数据
  .poll = sock_poll,             // epoll支持
};
//    用户: read/write/epoll操作网络连接

// 统一API: 设备、内核信息、网络连接
// 都用 open/read/write/close 操作
```

<Exercises>
**问题 1**：VFS 的四个核心对象各自的作用和关系是什么？

<Answer>
①superblock——代表已挂载的文件系统实例，存储块大小、总块数等元信息；②inode——代表文件/目录的元数据（大小、权限、时间戳、数据块位置），每个文件唯一；③dentry——代表路径的一个目录项，是路径名到inode的映射，构成目录树，内核用dcache缓存加速查找；④file——代表一个进程打开的文件实例，包含偏移量和打开模式。关系：superblock→inode→dentry→file。一个inode可有多个dentry（硬链接）和多个file（多次打开）。
</Answer>

**问题 2**：Linux 的「一切皆文件」哲学在 VFS 中是如何实现的？给三个非普通文件的例子。

<Answer>
通过VFS统一接口实现：任何对象只要实现了file_operations和inode_operations接口，就能被当作文件操作。三个例子：①设备文件/dev/ttyS0——字符设备，file_operations由驱动注册，read/write调用硬件操作；②proc文件/proc/cpuinfo——procfs虚拟文件系统，read函数运行时动态生成内容；③套接字socket——内部用file对象表示，有sock_read_iter等操作。VFS让用户态用统一API操作设备、内核信息、网络连接，极大简化编程模型。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="VFS">虚拟文件系统，内核中的抽象层。为用户态提供统一的文件操作接口，通过函数指针表将操作路由到底层不同文件系统的具体实现。</GlossaryItem>
<GlossaryItem term="四个核心对象">superblock(已挂载文件系统实例)、inode(文件元数据)、dentry(目录项/路径映射)、file(已打开文件实例)。通过函数指针表(file_operations/inode_operations)实现多态分发。</GlossaryItem>
<GlossaryItem term="dentry缓存(dcache)">内核缓存dentry的机制。路径查找时先查dcache命中则直接用，避免从磁盘读取目录项。大幅加速重复路径查找。</GlossaryItem>
<GlossaryItem term="一切皆文件">Linux设计哲学。设备文件、proc文件、socket等非普通文件都通过实现file_operations接口，用open/read/write/close统一操作。极大简化编程模型。</GlossaryItem>
</Glossary>
