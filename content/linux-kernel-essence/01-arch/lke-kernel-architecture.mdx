## 内核是什么

<Term def="内核空间（Kernel Space）是操作系统内核运行的虚拟地址空间区域，运行在CPU最高特权级（Ring 0），可执行所有指令、访问所有硬件。用户空间（User Space）是应用程序运行的区域，运行在Ring 3，受特权指令限制，不能直接访问硬件。">用户态/内核态</Term>的分界线是整个操作系统安全的基石。CPU 提供 Ring 0 ~ Ring 3 四个特权级，Linux 只用两级：Ring 0 运行内核，Ring 3 运行用户程序。用户程序想读写文件、分配内存、收发网络包，不能直接操作硬件，必须通过系统调用「请求」内核代劳。

## 两条进入内核的路径

```text
// 路径一：系统调用（同步，由用户程序主动发起）
// 用户程序执行 syscall / int 0x80 指令
//   → CPU 切换到 Ring 0
//   → 跳转到 entry_SYSCALL_64（内核入口）
//   → 保存用户态寄存器到内核栈
//   → 查 syscall_dispatch_table[rax]
//   → 执行 sys_read / sys_write / sys_open ...
//   → 恢复用户态寄存器
//   → sysret / iret 返回 Ring 3

// 路径二：中断与异常（异步或被动）
// 硬件中断（外设 → 中断控制器 → CPU）
//   → 网卡收到包 / 磁盘完成I/O / 定时器到期
//   → CPU 切换到 Ring 0
//   → 跳转到 IDT 中断描述符表对应入口
//   → do_IRQ → 具体中断处理函数
//
// 异常（CPU 执行指令时产生）
//   → 缺页异常（Page Fault）：访问未映射地址
//   → 除零异常：整数除以零
//   → 通用保护异常（GP）：违规访问
//   → do_page_fault / do_divide_error
```

## 内核子系统的职责

| 子系统 | 核心数据结构 | 核心功能 | 对应章节 |
|--------|-------------|---------|---------|
| 进程管理 | `task_struct` | 创建/调度/销毁进程 | 第3章 |
| 内存管理 | `zone` / `page` / `mm_struct` | 物理分配/虚拟映射/页回收 | 第4章 |
| 文件系统 | `super_block` / `inode` / `dentry` | VFS抽象/缓存/读写 | 第5章 |
| 网络协议栈 | `sk_buff` / `sock` | 收发包/路由/过滤 | 第8章 |
| 设备驱动 | `device` / `device_driver` | 字符/块/网络设备 | 第6章 |
| 同步原语 | `spinlock_t` / `mutex` | 并发保护 | 第7章 |

## 系统调用的开销

<Callout type="trap">
**误区：系统调用就是普通函数调用。** 系统调用远比函数调用昂贵。一次函数调用只涉及栈帧切换（几纳秒），一次系统调用涉及：特权级切换（Ring 3→Ring 0）、栈切换（用户栈→内核栈）、寄存器保存恢复、TLB 可能部分失效、分支预测器缓存污染。实测一次 `getpid()` 约 100~200ns，而一次普通函数调用约 1~2ns。这就是为什么 glibc 的 `printf` 要先写入用户态缓冲区，攒够一页再 `write` 系统调用一次性输出——减少跨越用户态/内核态边界的次数。
</Callout>

<Exercises>
**问题 1**：用户态和内核态的根本区别是什么？为什么需要这个分界？

<Answer>
用户态运行在 Ring 3，有自己的独立虚拟地址空间（只能访问用户区），不能执行特权指令（如修改页表、关中断、直接I/O），错误只导致自己崩溃（SIGSEGV）。内核态运行在 Ring 0，共享全局内核地址空间，可执行所有指令、访问所有硬件，错误导致整个系统崩溃（kernel panic）。需要这个分界的根本原因：隔离与保护。如果没有特权级隔离，一个恶意或 buggy 的程序可以直接读取其他进程的内存、篡改文件系统、霸占CPU。硬件提供 Ring 机制，内核利用它构建安全边界——用户程序想做「需要特权」的事，必须通过系统调用请求内核代劳，内核校验参数后才执行。
</Answer>

**问题 2**：系统调用和中断的异同是什么？

<Answer>
相同点：两者都触发 CPU 从 Ring 3 切换到 Ring 0，都保存用户态上下文，都跳转到内核预定义的入口执行。不同点：①发起方不同——系统调用由用户程序主动执行 syscall 指令发起（同步），中断由外设硬件或CPU异常触发（异步或被动）；②入口不同——系统调用经 syscall_dispatch_table 按寄存器 rax 的值分发，中断经 IDT（中断描述符表）按中断号分发；③上下文不同——系统调用在进程上下文中执行（可以睡眠、可以访问当前进程的task_struct），硬件中断在中断上下文中执行（不能睡眠、没有明确的进程归属）；④返回路径不同——系统调用用 sysret/iret 返回，中断用 iret 返回并可能检查是否需要调度。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="用户态/内核态">CPU特权级分界。用户态（Ring 3）运行应用程序，受限访问；内核态（Ring 0）运行内核，完全控制硬件。两者通过系统调用和中断切换。</GlossaryItem>
<GlossaryItem term="系统调用（syscall）">用户程序主动请求内核服务的同步机制。经syscall指令进入Ring 0，按系统调用号分发到具体处理函数（sys_read/sys_write等），完成后返回Ring 3。</GlossaryItem>
<GlossaryItem term="中断上下文">硬件中断处理函数的执行环境，不属于任何进程，不能睡眠、不能持有互斥锁、不能执行可能阻塞的操作。与进程上下文（系统调用执行环境）形成对比。</GlossaryItem>
<GlossaryItem term="IDT（中断描述符表）">CPU硬件结构，一个256项的数组，每项指向一个中断/异常处理入口。CPU收到中断信号后自动查IDT跳转到对应处理函数。</GlossaryItem>
</Glossary>
