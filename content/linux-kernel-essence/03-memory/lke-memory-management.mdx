## 物理内存管理三层结构

<LkeMemoryManagementDiagram />

物理内存从粗到细分三层管理。**Zone 分区**按 DMA 能力将物理内存分为 `ZONE_DMA`（低于 16MB，供老式 ISA DMA）、`ZONE_NORMAL`（16MB~896MB，内核直接映射）、`ZONE_HIGHMEM`（高于 896MB，需动态映射，32 位系统特有）。**Buddy 伙伴系统**在每个 Zone 内按 $2^n$ 页（order 0~10）管理空闲块：分配时找到满足要求的最小块，过大则对半拆分；释放时检查「伙伴块」是否也空闲，是则合并为更大的块。**Slab/Slub** 在 Buddy 之上管理小对象：从 Buddy 拿整页，切成固定大小的对象缓存，频繁分配/释放同一类型对象时直接复用，避免反复初始化。

## Buddy 伙伴系统

```text
// 分配：alloc_pages(gfp_mask, order)
//   order=0 → 1页(4KB), order=1 → 2页, order=10 → 1024页(4MB)
//
//   1. 从 zone->free_area[order].free_list 查找
//   2. 若该 order 无空闲块，从 order+1 拆分
//      例：申请 order=0，但只有 order=2 空闲
//      → 拆成两个 order=1 → 拆一个 order=1 成两个 order=0
//      → 分配一个 order=0，剩余挂在 order=0 和 order=1 链表
//   3. 返回 page 指针

// 释放：__free_pages(page, order)
//   1. 计算伙伴块地址：buddy = page ^ (1 << order)
//      XOR 运算：order=0 时 buddy = page^1（相邻页）
//   2. 检查 buddy 是否在 free_area[order] 中
//   3. 若是，从链表摘除 buddy，合并为 order+1
//   4. 递归检查更高 order 的伙伴
//   5. 最终合并后的块挂在对应 order 链表
```

## 4 级页表翻译

虚拟地址到物理地址的翻译在 x86-64 上经过 4 级页表。48 位虚拟地址拆分为 5 段：

$$\text{VA}_{48} = \underbrace{\text{PGD}(9)}_{\text{47~39}} \cdot \underbrace{\text{PUD}(9)}_{\text{38~30}} \cdot \underbrace{\text{PMD}(9)}_{\text{29~21}} \cdot \underbrace{\text{PTE}(9)}_{\text{20~12}} \cdot \underbrace{\text{Offset}(12)}_{\text{11~0}}$$

每级 9 位索引 $2^9 = 512$ 个表项，最后 12 位是页内偏移（$2^{12} = 4\text{KB}$ 页大小）。翻译过程：

$$\text{CR3} \xrightarrow{\text{+PGD}\times 8} \text{PGD表项} \xrightarrow{\text{+PUD}\times 8} \text{PUD表项} \xrightarrow{\text{+PMD}\times 8} \text{PMD表项} \xrightarrow{\text{+PTE}\times 8} \text{PTE表项} \xrightarrow{\text{+Offset}} \text{物理地址}$$

每次访存需 5 次内存读取（4 次查页表 + 1 次取数据），**TLB**（Translation Lookaside Buffer）缓存虚拟→物理映射，命中率通常 >99%，将实际开销降到接近 1 次访存。

## 缺页异常

```text
// CPU 访问虚拟地址 → 查页表 → PTE 的 Present 位 = 0 → 触发缺页异常
// do_page_fault()
//   → 找到发生缺页的 VMA（虚拟内存区域）
//   → 判断缺页类型：

// 情况1：按需调页（Demand Paging）
//   页面从未被加载到内存
//   → filemap_fault() 从文件读取数据到 Page Cache
//   → 建立 PTE 映射
//   → 重新执行触发缺页的指令

// 情况2：写时复制（Copy-On-Write）
//   fork() 后父子共享页表，PTE 标记只读
//   子进程写入 → 触发缺页
//   → 分配新物理页 → 复制内容 → 新 PTE 可写
//   → 子进程写新页，父进程保留原页

// 情况3：延迟分配（Lazy Allocation）
//   malloc() 只分配虚拟地址空间（VMA），不分配物理页
//   首次写入 → 触发缺页
//   → alloc_pages 分配物理页 → 清零 → 建立 PTE

// 情况4：非法访问
//   访问未映射地址 / 权限不足
//   → 发送 SIGSEGV 段错误 → 进程崩溃
```

<Callout type="trap">
**误区：kmalloc 和 vmalloc 可以互换使用。** 两者有本质区别。`kmalloc` 返回的是**物理连续**的内存，适用于 DMA 操作（硬件需要物理连续地址）和需要物理地址的场景，但大块连续内存可能分配失败（碎片化）。`vmalloc` 返回的是**虚拟连续但物理不连续**的内存，可以分配大块内存（不受碎片影响），但不能用于 DMA，且访问时 TLB miss 开销大。规则：小内存用 `kmalloc`（内部走 Slab），大块仅软件访问用 `vmalloc`，需要 DMA 的用 `alloc_pages` 或 `dma_alloc_coherent`。
</Callout>

<Exercises>
**问题 1**：Buddy 伙伴系统的分配和合并原理是什么？为什么用 XOR 计算伙伴地址？

<Answer>
Buddy系统按2^n页管理空闲块。分配时找满足order的最小块，过大则对半拆分直到目标order。释放时用XOR计算伙伴块地址：buddy = page_addr ^ (1 << (order + PAGE_SHIFT))。XOR的原理是：每个块在其伙伴对中的位置只差order对应的那个bit。例如order=0（1页）的两个伙伴地址是page和page^1（即page+1页或page-1页，取决于page的最低位）。如果page地址的该bit为0，buddy就是page|bit（后一个）；如果为1，buddy就是page&~bit（前一个）。XOR天然处理这两种情况。合并条件：buddy也在free_area[order]的空闲链表中。合并后递归检查更高order的伙伴，直到不能合并为止。这保证了大块空闲内存的最大化——避免外部碎片化。
</Answer>

**问题 2**：描述一次 malloc(4096) 后首次写入触发的缺页异常处理过程。

<Answer>
①用户调用malloc(4096)，glibc的ptmalloc从brk或mmap分配虚拟地址空间，但不分配物理页——只在mm_struct的VMA链表中记录一段[addr, addr+4096)的可读写VMA；②用户程序首次写入该地址，CPU查页表发现PTE不存在（Present=0），触发缺页异常（Page Fault）；③do_page_fault()找到包含该地址的VMA，检查权限合法（VMA有写权限）；④判断为延迟分配（Lazy Allocation）：调用alloc_pages(GFP_KERNEL, 0)从Buddy系统分配一个物理页；⑤调用clear_page()将物理页清零（安全要求，防止读到旧数据）；⑥在PTE中建立虚拟地址到物理页的映射，设置Present=1、RW=1、Dirty=1；⑦异常返回，CPU重新执行触发缺页的写指令，这次成功写入。整个过程对用户程序透明——malloc看似立即返回内存，实际物理页在首次访问时才分配。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Buddy伙伴系统">Linux物理内存管理的核心算法，按2^n页（order 0~10）管理空闲块。分配时拆分大块，释放时用XOR计算伙伴地址并合并相邻空闲块，最大化连续空闲区域。</GlossaryItem>
<GlossaryItem term="Slab/Slub分配器">在Buddy之上管理小对象的分配器。从Buddy拿整页，切成固定大小对象缓存。kmalloc内部走Slab。优势：频繁分配/释放同一类型对象时复用内存，避免反复初始化和碎片化。</GlossaryItem>
<GlossaryItem term="4级页表">x86-64的虚拟地址翻译结构：PGD→PUD→PMD→PTE→Offset，每级9位索引512项，支持48位地址空间（256TB）。TLB缓存翻译结果，避免每次访存都走5次内存。</GlossaryItem>
<GlossaryItem term="缺页异常（Page Fault）">CPU访问的虚拟地址在页表中不存在（PTE Present=0）时触发的异常。内核处理：按需调页（从文件加载）、写时复制（fork后共享页写时复制）、延迟分配（malloc后首次访问时分配物理页）。</GlossaryItem>
</Glossary>
