## 机制、实验与故障模型

以ext4启用与迁移、挂载调优、fio基准和FUSE用户态文件系统串起格式、缓存、持久性与性能证据。

本章核心不变量是：**块设备、文件系统特性、挂载参数和工作负载配置明确；数据迁移可回滚，基准区分缓存命中与真实设备I/O。** 这条不变量同时约束正常、边界、失败和恢复四类样本。通过一次命令不等于机制成立，必须解释配置写入哪一层、内核怎样执行、哪个计数或事件先变化，以及失败后谁负责回收。

最小实验：在一次性磁盘镜像上创建ext4，保存特性和挂载参数，运行固定fio矩阵，再用最小FUSE实现对照用户态往返开销。

故障实验：注入不兼容特性、错误挂载参数、掉电前未同步和缓存污染，检查fsck、内核日志、延迟分位与数据校验和。

建议证据表至少包含时间、主机/命名空间、内核与配置哈希、操作、对象或控制层级、预期、实际、首错、清理九列。性能实验还需记录预热、采样窗口、CPU/NUMA放置、缓存和延迟分位；故障实验还需保存内核日志、栈、转储或追踪原始文件。

## 常见误区

<Callout type="trap">
  **误区一：**
  在真实数据盘直接演练特性转换。文件系统迁移必须先做块级备份、离线一致性检查和可验证回滚。
</Callout>

<Callout type="trap">
  **误区二：**
  只报fio带宽而不保存作业文件、缓存状态和延迟分位。不同队列深度与读写模式的数字不能直接比较。
</Callout>

## 四类样本与验收

| 样本 | 控制方式               | 关键证据                 | 通过条件     |
| ---- | ---------------------- | ------------------------ | ------------ |
| 基线 | 固定版本、配置与负载   | 原始计数、日志、对象关系 | 与预测一致   |
| 边界 | 只改变容量、亲和或时间 | 首个饱和点与延迟分位     | 边界可解释   |
| 失败 | 注入一个错误或故障     | 首错、栈、事件或转储     | 责任层可定位 |
| 恢复 | 撤销配置或恢复快照     | 残留对象与同输入结果     | 回到基线     |

**问题 1** 为什么不能只看最终命令输出验收第3章 文件系统？

<Answer>
  最终输出可能隐藏版本错配、缓存、排队、延迟回收或观察工具开销。必须同时保存配置、对象关系、时间线、首个分叉和恢复结果。
</Answer>

**问题 2** 如何把“迁移并校验ext4”变成可执行证据？

<Answer>
  固定内核、配置、工具和工作负载，先预测ext4与日志模式的状态，只改变一个条件；在第一条计数、日志、栈或延迟分位偏离处停止，并与基线对照。
</Answer>

**问题 3** 本页最小通过条件是什么？

  撤销配置或恢复快照后，相同输入必须重新得到基线结果。
