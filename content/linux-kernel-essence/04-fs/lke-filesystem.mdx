## VFS 虚拟文件系统

<Term def="VFS（Virtual File System）是Linux内核的文件系统抽象层，用super_block/inode/dentry/file四个对象统一描述所有文件系统，使上层用相同的read/write/open/close操作ext4、NFS、proc等不同文件系统。">VFS</Term> 是 Linux 文件系统的核心抽象——上层只需调用 `read`/`write`/`open`/`close`，VFS 自动分发到具体文件系统的实现函数。

## VFS 四大对象

```text
// super_block：文件系统实例的元信息
struct super_block {
  s_dev               // 设备号
  s_blocksize         // 块大小（通常4096）
  s_op                // super_operations（mount/umount/inode分配）
  s_root              // 根目录的 dentry
  s_fs_info           // 文件系统私有数据（ext4_sb_info）
};

// inode：文件的元数据（一个文件一个 inode）
struct inode {
  i_ino               // inode 号
  i_mode              // 文件类型+权限
  i_size              // 文件大小
  i_blocks            // 占用块数
  i_op                // inode_operations（create/lookup/link）
  i_fop               // file_operations（read/write/mmap）
  i_mapping           // address_space（指向Page Cache）
};

// dentry：目录项（路径缓存的节点）
struct dentry {
  d_name              // 文件名
  d_parent            // 父目录的 dentry
  d_inode             // 指向关联的 inode
  d_op                // dentry_operations
  d_subdirs           // 子目录链表
};
// dentry 构成路径树：/home/user/file.txt
// → 根dentry → home → user → file.txt

// file：已打开的文件实例（一个文件可被多次打开）
struct file {
  f_inode             // 指向 inode
  f_op                // file_operations（来自inode.i_fop）
  f_pos               // 当前读写偏移
  f_mode              // 打开模式（读/写）
  f_flags             // 打开标志（O_RDONLY/O_NONBLOCK）
};
// fd → file 的映射在 files_struct 的 fdtable 中
```

## read() 全流程

```text
// 用户调用 read(fd, buf, 4096)
SYSCALL_DEFINE3(read, unsigned int, fd, char __user *, buf, size_t, count)
  → fget(fd)                    // 从fdtable取file
  → file.f_op->read_iter()      // 调用具体文件系统的读函数
    → generic_file_read_iter()
      → page_cache_sync_readahead()  // 预读
      → filemap_get_pages()          // 查Page Cache
        → xarray_lookup(mapping, index)  // 命中？
        → 命中：filemap_copy_to_user() → 返回数据
        → 未命中：filemap_create_folio() → 分配页
          → filemap_read_folio() → submit_bio()
            → 块设备I/O → 等待完成 → 页就绪
          → copy_to_user(buf, page_data, count)
      → 更新 file.f_pos
  → 返回读取的字节数
```

## write() 与脏页写回

```text
// 用户调用 write(fd, buf, 4096)
// 关键：write 不直接写磁盘，先写 Page Cache
generic_file_write_iter()
  → filemap_get_pages()         // 查/分配页
  → copy_from_user(page, buf)   // 从用户空间拷贝到页缓存
  → folio_mark_dirty()          // 标记脏页
  → 返回（数据在内存，未到磁盘）

// 异步写回（flusher 线程 / kworker）
// 触发条件：脏页比例超阈值 / 定时到期 / sync调用
writeback_inodes_sb()
  → writepages()                // 具体文件系统的写回
    → mpage_submit_bio()        // 构造bio
    → submit_bio()              → 块设备I/O → 磁盘
  → 清除脏标记

// fsync(fd) —— 强制同步
// 把该文件的所有脏页立即写回磁盘，等待I/O完成后返回
// 保证掉电后数据不丢失
```

## ext4 磁盘布局

```text
// ext4 物理布局
| 引导块 | 超级块 | 块组描述符 | 块组0 | 块组1 | ... | 块组N |

// 每个块组内部：
| 超级块副本 | 块组描述符 | 块位图 | inode位图 | inode表 | 数据块 |

// ext4 核心特性：
// - Extent（区段）：替代ext3的间接块，用树形结构记录连续物理块
//   ext4_extent { ee_block(逻辑), ee_len(长度), ee_start(物理) }
//   一个extent可映射最多32768个连续块（128MB）
//
// - 延迟分配（Delalloc）：write时不分配物理块
//   只在脏页写回时批量分配，减少碎片
//
// - 日志（JBD2）：记录元数据变更，崩溃后快速恢复
//   模式：journal（数据+元数据）/ ordered（仅元数据，数据先写）
//         writeback（仅元数据，不保证数据顺序）
//
// - 多块分配（mballoc）：一次分配多个连续块，减少锁竞争
```

<Callout type="trap">
**误区：write() 返回后数据已经在磁盘上。** 默认 `write()` 只把数据写到 Page Cache 并标记脏页就返回了——数据在内存中，尚未落盘。如果此时断电，数据丢失。要保证数据持久化，必须调用 `fsync(fd)` 强制将脏页写回磁盘并等待 I/O 完成后才返回。ext4 默认 `ordered` 模式保证元数据一致性（文件系统不会损坏），但不保证数据不丢失——可能元数据已写入但数据块未写入，导致文件内容为空或旧数据。对数据安全要求高的应用必须在关键写入后调用 `fsync`。
</Callout>

<Exercises>
**问题 1**：VFS 的四大对象各负责什么？它们之间的关系是什么？

<Answer>
四大对象：①super_block——描述一个已挂载的文件系统实例，包含设备号、块大小、超级操作表s_op（用于创建/销毁inode、同步文件系统等）；②inode——描述一个文件的元数据，包含inode号、权限、大小、文件操作表i_fop和inode操作表i_op，一个文件对应一个inode；③dentry——描述路径中的一个目录项，将文件名与inode关联，构成路径树（/home/user/file.txt是多级dentry链），同时作为路径查找缓存；④file——描述一个已打开的文件实例，包含偏移量f_pos、打开模式f_flags、指向inode的指针，每次open创建一个file实例。关系：super_block管理一棵dentry树，dentry指向inode，file引用inode。同一个inode（文件）可以被多次open产生多个file实例，每个有独立的读写偏移。
</Answer>

**问题 2**：read() 命中和未命中 Page Cache 的路径有什么不同？

<Answer>
命中路径：①fget(fd)取file；②调用file.f_op->read_iter()→generic_file_read_iter()；③page_cache_sync_readahead()发起预读（异步预读相邻页）；④filemap_get_pages()在address_space的XArray中查找页索引；⑤命中——直接调用copy_to_user()从Page Cache页拷贝数据到用户缓冲区，无需任何I/O，微秒级返回。未命中路径：①~③相同；④filemap_get_pages()在XArray中未找到——分配新物理页（alloc_pages→Buddy）；⑤将页加入Page Cache；⑥调用文件系统的readpage→submit_bio()构造块I/O请求，经I/O调度器下发到块设备驱动；⑦当前进程在页的等待队列上睡眠（wait_on_page_locked）；⑧DMA完成数据读取，硬中断+softirq唤醒等待进程；⑨页就绪，copy_to_user()拷贝数据，返回。未命中路径涉及磁盘I/O，延迟比命中高2~3个数量级。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="VFS（虚拟文件系统）">Linux文件系统的抽象层，用super_block/inode/dentry/file四个对象统一所有文件系统。上层调用统一的read/write/open/close，VFS通过操作函数表分发到具体文件系统的实现。</GlossaryItem>
<GlossaryItem term="Page Cache">以页（4KB）为单位的文件缓存，挂在inode的address_space上，用XArray（原radix tree）索引。read先查缓存，write先写缓存。脏页异步写回磁盘。</GlossaryItem>
<GlossaryItem term="脏页写回">write()只写Page Cache并标记脏页。flusher线程在脏页比例超阈值/定时到期/sync调用时异步写回磁盘。fsync强制同步写回并等待完成。</GlossaryItem>
<GlossaryItem term="ext4 Extent">ext4用extent（区段）替代ext3的间接块映射，一个extent记录一段连续的逻辑块到物理块的映射（最多32768个连续块），大幅减少元数据开销和碎片。</GlossaryItem>
</Glossary>
