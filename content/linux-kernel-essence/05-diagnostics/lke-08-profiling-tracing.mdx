## 机制、实验与故障模型

用perf、ftrace、trace-cmd、动态探针和SystemTap从统计采样进入函数、事件和脚本化追踪，形成假设驱动的性能诊断链。

本章核心不变量是：**先提出可证伪假设，再选择最低开销信号；时间戳、CPU、进程、符号和采样配置完整，关闭探针后性能回到基线。** 这条不变量同时约束正常、边界、失败和恢复四类样本。通过一次命令不等于机制成立，必须解释配置写入哪一层、内核怎样执行、哪个计数或事件先变化，以及失败后谁负责回收。

最小实验：为同一CPU/锁/I/O工作负载依次采集perf stat、perf record、函数图与事件追踪，比较每种工具的回答范围和观察开销。

故障实验：注入过高采样频率、全函数追踪、缺失符号与不稳定探针，观察丢失事件、缓冲覆盖和被测系统扰动。

建议证据表至少包含时间、主机/命名空间、内核与配置哈希、操作、对象或控制层级、预期、实际、首错、清理九列。性能实验还需记录预热、采样窗口、CPU/NUMA放置、缓存和延迟分位；故障实验还需保存内核日志、栈、转储或追踪原始文件。

## 可重放命令骨架

```bash
perf stat -e cycles,instructions,cache-misses -- ./workload
perf record -g -- ./workload
perf report --stdio | head
```

```bash
mount -t tracefs nodev /sys/kernel/tracing 2>/dev/null || true
cat /sys/kernel/tracing/available_tracers
cat /sys/kernel/tracing/available_events | head
```

```bash
trace-cmd record -e sched_switch -e block_rq_complete -- ./workload
trace-cmd report | head -n 40
```

<Callout type="trap">
  **安全边界：**
  涉及内核替换、崩溃、文件系统转换、网络重配、设备直通或电源状态的实验只在可丢弃虚拟机或专用测试机执行。先验证控制台、快照和恢复路径。
</Callout>

## 常见误区

<Callout type="trap">
  **误区一：**
  没有假设就开启所有事件和函数。数据量、丢失事件与探针开销会掩盖原始行为，应从最小信号逐步扩展。
</Callout>

<Callout type="trap">
  **误区二：**
  只保留火焰图或百分比截图。必须保存命令、事件列表、采样频率、符号状态、原始数据和同负载基线。
</Callout>

## 四类样本与验收

| 样本 | 控制方式               | 关键证据                 | 通过条件     |
| ---- | ---------------------- | ------------------------ | ------------ |
| 基线 | 固定版本、配置与负载   | 原始计数、日志、对象关系 | 与预测一致   |
| 边界 | 只改变容量、亲和或时间 | 首个饱和点与延迟分位     | 边界可解释   |
| 失败 | 注入一个错误或故障     | 首错、栈、事件或转储     | 责任层可定位 |
| 恢复 | 撤销配置或恢复快照     | 残留对象与同输入结果     | 回到基线     |

**问题 1** 为什么不能只看最终命令输出验收第8章 概要分析与追踪？

<Answer>
  最终输出可能隐藏版本错配、缓存、排队、延迟回收或观察工具开销。必须同时保存配置、对象关系、时间线、首个分叉和恢复结果。
</Answer>

**问题 2** 如何把“限定函数与事件”变成可执行证据？

<Answer>
  固定内核、配置、工具和工作负载，先预测perf与ftrace的状态，只改变一个条件；在第一条计数、日志、栈或延迟分位偏离处停止，并与基线对照。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  先提出可证伪假设，再选择最低开销信号；时间戳、CPU、进程、符号和采样配置完整，关闭探针后性能回到基线。
  撤销配置或恢复快照后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
