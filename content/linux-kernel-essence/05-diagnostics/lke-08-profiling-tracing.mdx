原书的主要技术语境是Linux 2.6.18到3.0，并包含RHEL 4、Fedora和CentOS实践。正文先还原当时机制，再把cgroup v2、现代perf/tracefs、当前虚拟化与电源接口作为显式迁移检查；历史命令与当前系统行为不能悄悄混为一谈。

## 四类样本与验收

| 样本 | 控制方式               | 关键证据                 | 通过条件     |
| ---- | ---------------------- | ------------------------ | ------------ |
| 基线 | 固定版本、配置与负载   | 原始计数、日志、对象关系 | 与预测一致   |
| 边界 | 只改变容量、亲和或时间 | 首个饱和点与延迟分位     | 边界可解释   |
| 失败 | 注入一个错误或故障     | 首错、栈、事件或转储     | 责任层可定位 |
| 恢复 | 撤销配置或恢复快照     | 残留对象与同输入结果     | 回到基线     |

## 小结

- perf：连接“提出性能假设”的机制前提与证据。
- ftrace：连接“选择计数或采样”的机制前提与证据。
- tracepoint：连接“限定函数与事件”的机制前提与证据。
- kprobe：连接“采集统一时间线”的机制前提与证据。
- SystemTap：连接“关联用户与内核栈”的机制前提与证据。
- 本页13个正式目录坐标全部进入实验链，没有用泛化内核主题替代原书HACK。
