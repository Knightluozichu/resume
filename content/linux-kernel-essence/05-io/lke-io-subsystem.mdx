## 三类设备

Linux 将设备分为三类，每类有不同的注册接口和操作模型。

<LkeIoSubsystemDiagram />

```text
// 字符设备（Char Device）
// 按字节/帧流式访问，无缓冲，实时
// 例：串口、键盘、传感器、GPIO
struct file_operations my_fops = {
  .owner   = THIS_MODULE,
  .open    = my_open,
  .read    = my_read,
  .write   = my_write,
  .release = my_release,
};
// 注册：
cdev_init(&my_cdev, &my_fops);
cdev_add(&my_cdev, devno, 1);  // 加入系统，用户可 open("/dev/mydev")

// 块设备（Block Device）
// 按扇区/块随机访问，经I/O调度
// 例：磁盘、SSD、eMMC
// 注册：
blk_mq_alloc_disk(&my_q, fops);  // 分配请求队列
add_disk(my_gendisk);             // 注册到系统

// 网络设备（Network Device）
// 按包收发，无文件操作，经协议栈
// 例：eth0、wlan0、虚拟网卡
// 注册：
register_netdev(&my_netdev);  // 注册网络设备
// 收包：netif_rx(skb) / napi_schedule()
// 发包：dev_queue_xmit(skb)
```

## 设备模型

<Term def="Linux设备模型用bus_type、device、device_driver三个核心结构描述设备的总线归属、实例和驱动绑定关系。总线负责match匹配，匹配成功后调用driver.probe完成初始化。">设备模型</Term>的核心是 bus-device-driver 三角关系。

```text
// 设备绑定流程
// 1. 总线枚举设备（或设备树/ACPI声明）
bus_for_each_dev(bus, ...)
  → device_register(dev)     // 设备挂到总线

// 2. 驱动注册
driver_register(drv)
  → bus_add_driver(drv)      // 驱动挂到总线

// 3. 匹配（总线负责）
bus_type.match(dev, drv)
  → 比较设备名/ID/compatible字段
  → 匹配成功？

// 4. 探测（初始化设备）
driver.probe(dev)
  → 分配私有数据
  → 映射寄存器（ioremap）
  → 注册中断（request_irq）
  → 注册 cdev / gendisk / netdev
  → 设备就绪

// 5. 移除
driver.remove(dev)
  → 注销 cdev / gendisk / netdev
  → 释放中断、内存
```

## 中断上下半部

```text
// 上半部：硬中断（Top Half）
// 特点：关中断（或同优先级中断）、不能睡眠、必须快速完成
// 职责：ACK中断、读取关键数据、调度下半部
irqreturn_t my_isr(int irq, void *dev_id) {
    // 1. 确认是本设备的中断
    // 2. ACK（清除中断源）
    // 3. 从硬件读取紧急数据到缓冲区
    // 4. 调度下半部
    //    napi_schedule(&napi)     // 网络
    //    tasklet_schedule(&tl)    // tasklet
    //    queue_work(wq, &work)    // workqueue
    return IRQ_HANDLED;
}

// 下半部：延迟处理（Bottom Half）
// 三种机制对比：
// ┌──────────┬──────────┬───────────┬──────────────────┐
// │ 机制     │ 上下文   │ 可睡眠?   │ 适用场景         │
// ├──────────┼──────────┼───────────┼──────────────────┤
// │ softirq  │ 中断上下文│ 否        │ 网络收包、定时器 │
// │ tasklet  │ 中断上下文│ 否        │ 中等复杂度善后   │
// │ workqueue│ 进程上下文│ 是        │ 需要睡眠的操作   │
// └──────────┴──────────┴───────────┴──────────────────┘

// workqueue 示例（可睡眠，最常用）
struct work_struct my_work;
INIT_WORK(&my_work, my_work_func);
queue_work(system_wq, &my_work);

void my_work_func(struct work_struct *work) {
    // 此处可以睡眠、可以持有互斥锁
    // 可以分配可能换出的内存（GFP_KERNEL）
    // 适合：文件I/O、大量数据处理、等待用户事件
}
```

## DMA 与内存一致性

```text
// DMA（Direct Memory Access）：设备直接读写内存，不经CPU
// 场景：网卡收发包、磁盘I/O、声卡传输

// 一致性DMA（Coherent）
// 分配的内存对CPU和设备都可见，无需手动同步
// 适合：小型控制结构、描述符环
buf = dma_alloc_coherent(dev, size, &dma_handle, GFP_KERNEL);
// cpu_addr ← CPU访问的虚拟地址
// dma_handle ← 设备访问的总线地址

// 流式DMA（Streaming）
// 临时映射已有内存，需手动同步
// 适合：大块数据传输（网络包、磁盘块）
dma_handle = dma_map_single(dev, cpu_addr, size, DMA_FROM_DEVICE);
// 设备读取 dma_handle 对应的物理内存
// CPU访问前需同步：
dma_sync_single_for_cpu(dev, dma_handle, size, DMA_FROM_DEVICE);
// 设备访问前需同步：
dma_sync_single_for_device(dev, dma_handle, size, DMA_TO_DEVICE);

// 关键：CPU缓存 vs 设备看到的内存
// CPU有L1/L2/L3缓存，设备直接访问物理内存
// dma_sync_* 确保缓存与内存一致
// IOMMU：提供设备地址隔离（类似页表），用于虚拟化
```

<Callout type="trap">
**误区：中断处理函数可以调用任何内核函数。** 中断处理函数运行在中断上下文，有两个硬约束：①**不能睡眠**——没有进程上下文，调度器无法切换回来，睡眠会导致死锁或 panic。因此不能使用 `mutex`、`kmalloc(GFP_KERNEL)`、`copy_from_user`、任何可能阻塞的 I/O 操作。只能用 `spin_lock_irqsave`（自旋锁）、`kmalloc(GFP_ATOMIC)`（原子分配）。②**必须快速完成**——硬中断会屏蔽同优先级及更低优先级的中断，耗时过长会导致其他设备的中断丢失。正确做法是上半部只做最紧急的 ACK 和数据读取，把耗时操作推迟到下半部（workqueue 可睡眠，softirq/tasklet 不可睡眠但开中断）。
</Callout>

<Exercises>
**问题 1**：字符设备、块设备、网络设备的根本区别是什么？

<Answer>
三者从用户接口、访问模式、缓冲策略三个维度区分：①字符设备——通过/dev下的设备节点访问，file_operations接口（open/read/write/ioctl），按字节或帧流式访问，无缓冲（实时），例：串口、GPIO、传感器；②块设备——通过文件系统间接访问（也可直接open /dev/sda），按扇区/块随机访问，经Page Cache缓冲和I/O调度器合并排序，可寻址，例：磁盘、SSD、eMMC；③网络设备——没有/dev节点，不实现file_operations，通过socket API收发数据包，无缓冲（流式），按包处理，例：eth0、wlan0。注册方式也不同：字符设备用cdev_init/cdev_add，块设备用blk_mq_alloc_disk/add_disk，网络设备用register_netdev。
</Answer>

**问题 2**：硬中断处理函数为什么不能睡眠？如果需要在中断中执行可能阻塞的操作怎么办？

<Answer>
硬中断运行在中断上下文而非进程上下文——不属于任何进程，没有task_struct可用于调度。睡眠机制是当前进程主动让出CPU进入等待队列，调度器选另一个进程运行——但中断上下文中没有「当前进程」可让出，调度器无法将其切换回来，导致系统死锁或panic。此外中断通常关闭了同优先级中断，睡眠期间这些中断被长时间屏蔽，可能导致设备饥饿。如果需要执行可能阻塞的操作（如文件I/O、大量数据处理、等待用户事件），正确做法是：硬中断中只做ACK和读取紧急数据，然后调度下半部——使用workqueue（运行在进程上下文，可以睡眠、可以持有互斥锁、可以分配GFP_KERNEL内存）来执行阻塞操作。如果操作不需要睡眠但较耗时，可用softirq或tasklet（运行在中断上下文但开中断，不能睡眠）。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="字符设备">按字节/帧流式访问的设备，通过file_operations接口（open/read/write）操作，无缓冲。注册用cdev_init/cdev_add。例：串口、GPIO、传感器。</GlossaryItem>
<GlossaryItem term="块设备">按扇区/块随机访问的设备，经I/O调度器和Page Cache缓冲。注册用blk_mq_alloc_disk/add_disk。例：磁盘、SSD、eMMC。</GlossaryItem>
<GlossaryItem term="中断上下半部">硬中断（上半部）在中断上下文执行，关中断、不能睡眠，只做ACK和紧急数据读取。下半部（softirq/tasklet/workqueue）延迟执行耗时操作，workqueue运行在进程上下文可睡眠。</GlossaryItem>
<GlossaryItem term="DMA（直接内存访问）">设备直接读写物理内存不经CPU的技术。一致性DMA（dma_alloc_coherent）无需手动同步；流式DMA（dma_map_single）需dma_sync_*保证CPU缓存与设备看到的内存一致。IOMMU提供设备地址隔离。</GlossaryItem>
</Glossary>
