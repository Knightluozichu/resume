## 协议栈全景

<Term def="sk_buff（socket buffer）是Linux网络栈中数据包的统一载体，包含数据区指针（head/data/tail/end）和各层协议头信息。各层处理时只移动指针加/剥头，不拷贝数据。">sk_buff</Term> 是整个网络栈的灵魂——从应用层到网卡驱动，数据包始终以 sk_buff 形式存在，各层只移动指针加/剥协议头，零拷贝传递。

## 发送路径

```text
// 用户调用 send(sock, buf, len, 0)
// → sock_sendmsg()
//   → inet_sendmsg()  // TCP/UDP
//     → tcp_sendmsg() / udp_sendmsg()

// TCP 发送：
tcp_sendmsg()
  → 等待发送窗口（滑动窗口流量控制）
  → skb = alloc_skb()           // 分配sk_buff
  → copy_from_user(skb->data, buf)  // 用户数据→skb
  → tcp_send_skb()              // 加入发送队列
  → tcp_write_xmit()            // 拥塞控制判断
    → ip_queue_xmit()           // 下沉到IP层
      → ip_route_output()       // 路由查找
      → ip_output()             // 加IP头
        → NF_INET_LOCAL_OUT     // Netfilter钩子
        → ip_finish_output()
          → neigh_output()      // ARP解析（加以太网头）
            → dev_queue_xmit()  // 下沉到链路层
              → qdisc（流量控制）
              → dev_hard_start_xmit()
                → 驱动 ndo_start_xmit()  // 硬件发送
                  → DMA → 网卡
```

## 接收路径与 NAPI

```text
// 网卡收到数据包 → DMA写入预分配的环形缓冲区 → 硬中断

// 硬中断（上半部）：
netdev_irq()
  → 禁用网卡硬中断（关键！）
  → napi_schedule(&napi)        // 调度NAPI轮询
  → 返回（极短）

// softirq（NET_RX_SOFTIRQ）：
net_rx_action()
  → napi_poll()                 // 轮询网卡
    → 循环：从环形缓冲区取包
      → skb = napi_get_skb()    // 构造sk_buff
      → netif_receive_skb(skb)  // 上送协议栈
    → 预算用完或包取空？
      → 取空：重新启用硬中断
      → 用完：留待下次softirq继续

// 协议栈逐层处理：
netif_receive_skb(skb)
  → __netif_receive_skb()
    → eth_type_trans()          // 设置协议号（ETH_P_IP）
    → ip_rcv()                  // IP层
      → NF_INET_PRE_ROUTING     // Netfilter钩子
      → ip_route_input()        // 路由判断：本机/转发
      → ip_local_deliver()      // 本机接收
        → NF_INET_LOCAL_IN
        → tcp_v4_rcv() / udp_rcv()  // 传输层
          → 找到对应socket
          → tcp_v4_do_rcv()
            → 放入socket接收队列
            → 唤醒等待的recv()
```

## NAPI 的核心思想

```text
// 传统方式：每个包一个硬中断 → 高速流量下中断风暴
// NAPI（New API）：中断 + 轮询混合
//
// 第一个包来 → 硬中断 → 关中断 → 开始轮询
// 轮询取包直到：预算用完 或 包取空
//   包取空 → 开中断 → 回到中断模式（等下一个包）
//   预算用完 → 不开中断 → 留到下次softirq继续轮询
//
// 优势：
// 1. 高吞吐时减少中断开销（一次轮询处理多个包）
// 2. 低延迟时第一个包仍有中断通知
// 3. 轮询时关中断防止中断风暴
// 4. 预算（budget，默认300包）防止单个softirq占用太久
```

## Netfilter 与 iptables

```text
// Netfilter 在协议栈路径上的5个钩子点
// （每个钩子可注册多个回调函数）

//         ← NF_INET_PRE_ROUTING（入站，路由前）
//              ↓
//         路由判断：本机 or 转发？
//         ↙              ↘
// 本机：LOCAL_IN         转发：FORWARD
//   ↑                       ↓
//   ↑                  NF_INET_POST_ROUTING（转发出站）
//   ↑                       ↓
// 应用层                    网卡发出
//   ↓
// NF_INET_LOCAL_OUT（本机发出）
//   ↓
// POST_ROUTING → 网卡发出

// iptables 五链对应五个钩子：
// PREROUTING → INPUT → FORWARD → OUTPUT → POSTROUTING
//
// 四表（优先级从高到低）：
// raw（-j NOTRACK，跳过连接跟踪）
// mangle（修改TOS/TTL等字段）
// nat（SNAT/DNAT地址转换）
// filter（-j ACCEPT/DROP，过滤）
//
// conntrack（连接跟踪）：维护每条流的状态
// NEW / ESTABLISHED / RELATED / INVALID
// NAT依赖conntrack判断回程流量
```

<Callout type="trap">
**误区：网络收包和文件读取一样是同步的。** 网络收包是完全异步的。用户调用 `recv()` 时如果socket接收队列没有数据，进程会被挂到等待队列上睡眠（`sk_wait_data`）。数据到达网卡后经 DMA→硬中断→NAPI轮询→协议栈逐层处理→放入socket接收队列→唤醒等待进程——整个过程跨越了中断上下文和进程上下文，从网卡到用户空间的数据拷贝至少经过：DMA到内核内存→协议栈处理→`copy_to_user` 到用户缓冲区。这就是为什么网络延迟远高于内存读取——一次局域网 round-trip 约 50~100us，一次内存读取约 100ns，差三个数量级。
</Callout>

<Exercises>
**问题 1**：sk_buff 的设计为什么能实现零拷贝？各层如何处理协议头？

<Answer>
sk_buff内部有四个关键指针：head（数据区起始）、data（有效数据起始）、tail（有效数据结束）、end（数据区结束）。空间布局：[head ... data ... tail ... end]，data到tail之间是当前层的有效数据。接收时从底层往上「剥头」：每经过一层，data指针后移跳过该层头（如IP层处理后data后移20字节跳过IP头），不需要拷贝或修改数据。发送时从顶层往下「加头」：每经过一层，data指针前移腾出空间写入该层头（如IP层在数据前加20字节IP头），tail指针可能后移追加尾部（如以太网CRC）。整个收发过程中，用户数据在sk_buff的数据区中位置不变，只有data/tail指针在移动——实现了各层间的零拷贝传递。alloc_skb时会预留足够的headroom和tailroom给各层头使用。
</Answer>

**问题 2**：NAPI 相比传统中断驱动收包有什么优势？工作原理是什么？

<Answer>
传统方式每个数据包到达都触发一次硬中断，高速流量下中断风暴导致CPU大部分时间在处理中断而非实际数据。NAPI采用「中断+轮询」混合模式：①网卡收到第一个包触发硬中断，中断处理函数关闭网卡硬中断并调度NAPI轮询（napi_schedule）；②NET_RX_SOFTIRQ软中断中调用napi_poll循环从网卡环形缓冲区取包，每次最多取budget个（默认300）；③包取空则重新开启硬中断，回到中断模式等待下一个包；④预算用完但还有包，则不开中断，留到下次softirq继续轮询。三大优势：①高吞吐时一次轮询处理多个包，中断开销摊薄到每包极低；②低吞吐时第一个包仍有中断通知，延迟不退化；③轮询时关中断防止中断风暴。现代高速网卡（10G/40G/100G）几乎都用NAPI。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="sk_buff">Linux网络栈中数据包的统一载体，通过head/data/tail/end四个指针管理数据区。各层处理时只移动指针加/剥协议头，实现零拷贝传递。</GlossaryItem>
<GlossaryItem term="NAPI">中断+轮询混合收包机制。第一个包触发硬中断后关中断并轮询取包，高吞吐时减少中断开销，低延迟时首个包仍中断通知。现代高速网卡标配。</GlossaryItem>
<GlossaryItem term="Netfilter">Linux内核网络包过滤框架，在协议栈路径上设置5个钩子点（PRE_ROUTING/LOCAL_IN/FORWARD/LOCAL_OUT/POST_ROUTING），iptables/nftables在钩子上注册过滤/NAT规则。</GlossaryItem>
<GlossaryItem term="conntrack（连接跟踪）">Netfilter的连接跟踪模块，维护每条网络流的状态（NEW/ESTABLISHED/RELATED/INVALID），NAT依赖它判断回程流量并还原地址。</GlossaryItem>
</Glossary>
