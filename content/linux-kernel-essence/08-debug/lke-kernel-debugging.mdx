## 工具链全景

内核调试工具分为三大类：**日志与观测**（printk/ftrace/tracepoints）用于了解内核执行了什么；**动态追踪**（kprobes/eBPF/perf）用于深入分析函数参数和性能热点；**崩溃分析**（kdump/crash）用于事后定位 panic。

## printk 与 ftrace

```text
// printk：最基础的内核日志
printk(KERN_ERR "device error at %s:%d\n", __FILE__, __LINE__);
printk(KERN_WARNING "timeout: status=0x%x\n", status);
printk(KERN_DEBUG "debug: ptr=%px\n", ptr);

// 日志级别：
// KERN_EMERG   (0) 系统不可用
// KERN_ALERT   (1) 必须立即处理
// KERN_CRIT    (2) 严重条件
// KERN_ERR     (3) 错误条件
// KERN_WARNING (4) 警告
// KERN_NOTICE  (5) 正常但重要
// KERN_INFO    (6) 信息
// KERN_DEBUG   (7) 调试

// 查看：dmesg / journalctl / /var/log/kern.log

// ftrace：函数追踪（零开销，基于编译器 -pg 插桩）
// 启用：
echo function > /sys/kernel/debug/tracing/current_tracer
echo schedule > /sys/kernel/debug/tracing/set_ftrace_filter
cat /sys/kernel/debug/tracing/trace

// 函数调用图（含调用关系）：
echo function_graph > /sys/kernel/debug/tracing/current_tracer
// 输出示例：
//   schedule() {
//     pick_next_task_fair() {
//       __pick_first_entity();
//     }
//     context_switch() {
//       switch_mm();
//       switch_to();
//     }
//   }
```

## eBPF 与 perf

```text
// eBPF：内核态安全运行沙箱（现代可观测性核心）
// 验证器保证安全：不循环、不越界、不睡眠

// bpftrace 一行命令追踪：
// 追踪所有 openat 系统调用的文件名：
bpftrace -e 'tracepoint:syscalls:sys_enter_openat {
    printf("%s open: %s\n", comm, str(args->filename));
}'

// 追踪内核函数每次调用的耗时：
bpftrace -e 'kprobe:__schedule { @[comm] = count(); }'
// 统计每个进程被调度的次数

// 追踪函数返回值：
bpftrace -e 'kretprobe:kmalloc { @[comm] = sum(retval); }'
// 统计每个进程通过kmalloc分配的总字节数

// eBPF attach 点：
// - kprobe/kretprobe：动态插入任意函数入口/出口
// - tracepoint：内核静态埋点（稳定ABI）
// - perf_event：PMU硬件计数器
// - XDP：网卡收包路径（高速包过滤）

// perf：性能采样分析
// 采样CPU热点：
perf record -F 99 -g -a -- sleep 10
//   -F 99: 采样频率99Hz
//   -g: 记录调用栈
//   -a: 所有CPU
//   sleep 10: 采样10秒

// 查看热点：
perf report
//   按函数排序，显示占比和调用栈

// 基于PMU硬件计数器：
perf stat -e cache-misses,branch-misses ./myapp
//   统计缓存未命中和分支预测失败次数
```

## 崩溃分析

```text
// kdump：内核崩溃时捕获内存转储
// 原理：
// 1. 主内核崩溃 → kexec 快速启动备用内核（无需硬件重启）
// 2. 备用内核访问主内核的物理内存 → 写入 vmcore 文件
// 3. 系统重启后分析 vmcore

// 配置：
//   crashkernel=256M  // 预留256MB给备用内核
//   kdump 服务启用

// crash 工具分析 vmcore：
crash /usr/lib/debug/vmlinux /var/crash/vmcore

// 常用命令：
crash> bt              // 查看崩溃时的调用栈
crash> ps              // 列出所有进程
crash> struct task_struct ffff888012345678  // 查看task_struct内容
crash> rd -a ffff888012345678  // 读取内存
crash> mod -s mydriver  // 加载模块符号
crash> dis my_function  // 反汇编函数

// KASAN：内存错误检测（编译时启用）
// CONFIG_KASAN=y
// 检测：越界访问、Use-After-Free、双重释放
// 运行时自动检测并打印详细报告

// lockdep：锁依赖检测器
// CONFIG_LOCKDEP=y
// 检测：潜在死锁、锁顺序违规
// 运行时自动分析所有加锁序列
```

<Callout type="trap">
**误区：生产环境不能开追踪工具。** 传统工具（ftrace 全函数追踪、kprobe 大量插桩）确实有较高开销，不适合生产长期开启。但 **eBPF 改变了这个范式**——验证器保证安全（不会崩溃系统），JIT 编译保证低开销（纳秒级），可在生产环境实时部署和移除。Netflix、Facebook 等公司在生产环境大规模运行 eBPF 追踪工具（bcc/bpftrace/co-re），用于：网络延迟分析、I/O 性能定位、安全审计、容器监控。典型场景：生产环境突然变慢 → 用 bpftrace 一行命令定位哪个函数耗时增加 → 定位到问题后移除探针 → 无需重启服务。`perf record` 采样模式的开销也可控（1-3%），适合短时性能 profiling。
</Callout>

<Exercises>
**问题 1**：ftrace 和 eBPF 有什么区别？各自适合什么场景？

<Answer>
ftrace是内核内置的追踪框架，基于编译器-pg插桩在函数入口插入调用钩子。优势：零配置（内核自带）、函数追踪和调用图功能强大、开销可预测。劣势：功能相对固定（预定义的tracer）、不能动态采集函数参数和返回值、不能写复杂逻辑。eBPF是可编程的内核沙箱，通过验证器保证安全后JIT编译执行用户编写的程序。优势：可编程（用C子集写任意采集逻辑）、可采集函数参数/返回值/局部变量、attach点丰富（kprobe/tracepoint/perf_event/XDP）、生产环境低开销可长期运行。劣势：需要BTF/符号信息支持、编程门槛较高、验证器限制（栈深度1024、循环受限）。场景选择：快速看函数调用关系用ftrace；采集函数参数/返回值/性能统计/生产环境长期监控用eBPF。
</Answer>

**问题 2**：内核发生 panic 后如何定位原因？描述完整流程。

<Answer>
①前提：系统已配置kdump（预留crashkernel内存、启用kdump服务）；②内核发生panic时，kdump的panic handler被调用，通过kexec快速启动备用内核（不经历BIOS重启，保留物理内存内容）；③备用内核启动后，通过/proc/vmcore读取主内核的物理内存，将其转储为vmcore文件保存到磁盘；④系统正常重启；⑤用crash工具分析vmcore：`crash vmlinux vmcore`；⑥`bt`查看崩溃时CPU的调用栈——定位到崩溃的函数和代码行；⑦`ps`查看所有进程状态，找异常进程；⑧`struct`查看关键数据结构内容（如崩溃进程的task_struct）；⑨`dis`反汇编崩溃函数确认具体指令；⑩结合源码分析根因。辅助工具：KASAN（编译时启用，运行时自动检测内存越界/UAF并打印报告）、lockdep（检测锁死锁）、`dmesg`查看崩溃前的日志线索。如果kdump未配置，只能依赖串口日志/panic时打印的调用栈做有限分析。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="ftrace">内核内置的函数追踪框架，基于编译器-pg插桩。支持函数追踪（function）和调用图（function_graph）模式，零配置使用，适合了解函数调用关系。</GlossaryItem>
<GlossaryItem term="eBPF">可编程的内核安全沙箱，用户编写的程序经验证器检查安全后JIT编译执行。可attach到kprobe/tracepoint/perf_event等点，采集函数参数和性能数据，生产环境低开销。</GlossaryItem>
<GlossaryItem term="perf">基于PMU硬件计数器的性能分析工具。perf record采样CPU热点，perf stat统计硬件事件（cache-miss/branch-miss），perf report排序显示热点函数。</GlossaryItem>
<GlossaryItem term="kdump/crash">内核崩溃转储与分析工具链。kdump在panic时通过kexec启动备用内核转储物理内存为vmcore；crash工具分析vmcore查看调用栈/进程状态/数据结构/反汇编，定位崩溃根因。</GlossaryItem>
</Glossary>
