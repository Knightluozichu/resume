## 直觉起点

学习路线像一座有分岔的工厂：机器没有供电时，检查包装工位没有意义；包装失败，也不能反推供电故障。需要先找到停在哪个环节，再决定补哪一课。

本页帮助你在九个主题间选择下一步。如果只按网页数打勾，很容易把“看过命令”误当成“有证据证明命令在正确环境运行”。

## 四个责任位置：证据不能跨层借用

先在图中找两个包围框。外框是运行虚拟化软件、提供虚拟硬件的 <Term def="承载虚拟化软件与来宾的物理或外层操作系统">宿主</Term>；内框是安装在虚拟机器里的 <Term def="在虚拟硬件上独立启动的操作系统实例">来宾</Term>。在宿主终端敲命令，不会因为另一扇窗口开着 Ubuntu 就自动变成来宾操作。

来宾内也有分工：<Term def="解释命令文本、处理展开并调度内建或外部程序的命令解释器">Shell</Term> 解析输入；<Term def="管理进程、内存和设备，并实施文件访问等系统服务的操作系统核心">内核</Term> 提供系统服务。终端是输入输出界面，不等于 Shell。图里内建 pwd 与外部 cat 走不同路径：前者不必通过 PATH 查找程序，后者需要先找到可执行文件，再请求读取输入文件。

证据也有位置：`uname -r` 报告当前环境的内核版本，不报告发行版的完整软件集合；`/etc/os-release` 描述当前文件系统中的系统标识；`id` 和 `pwd` 记录当前命令身份与目录。把这些输出与虚拟机名称、来宾控制台、时间和操作窗口一起留存，才不容易拿错机器的结果。容器、远程登录、共享内核等环境还需额外标注，不能仅凭一张终端截图排除它们。

## 动手实验：先预测，再走到首个断口

本实验是有限状态教学模型，不会安装系统或执行 Linux 命令。固定普通用户、可读文件内容 ok、无别名/函数/命令缓存；注入的“根文件系统不可用”特指来宾无法进入本实验所需的交互 Shell，并不代表所有真实启动失败都相同。实际系统可能进入救援环境，须看启动日志而非套用图中帧数。

先预测：选择“PATH 缺少程序目录”，外部 cat 与内建 pwd 是否都会失败？点击预测后验证，再切回外部命令并选“文件不可读”。逐步观察：前者停在查找，后者越过查找才停在读取。第二幅图显示建议的学习前置关系；它没有“学完百分比”，也不会把一次模拟结果写成课程通过。

## 九个主题怎样形成学习依赖

学习顺序不必和目录排版完全相同。以下把每章的细分节点归入实际产物：环境先于命令，命令分到身份、软件、网络与脚本，工具链和文本处理最后在项目汇合。这是本站的教学建议，不是出版社提供的依赖图；身份和安全约束始终横跨各分支。

### 路线1：认识系统，先固定实验机器

操作系统概述与嵌入式系统帮助你区分资源管理职责和设备使用场景；Linux 历史、优势与发行版本用于解释“同一内核家族不等于相同工具版本”，不能推导任何发行版在所有场景都更快。虚拟机、Ubuntu 安装、虚拟机工具则分别对应虚拟硬件、来宾系统与集成功能。鼠标可用或共享目录出现，不证明启动磁盘与隔离边界正确。

本章小结应产出一张环境记录：架构、发行版、内核、虚拟磁盘、是否共享目录。对照实验外框和内框，若根文件系统断开就回这里；不要先研究 PATH。当前 Ubuntu 安装文档包含比2021教材更新的界面，本页不把新截图当作原书操作步骤。

### 路线2：使用系统，把一行命令拆为责任链

终端介绍和终端软件解决“从哪里输入”，Shell 概述及命令格式解决“谁解析文字”。用户/系统命令用于询问身份与环境；文件命令处理路径与数据；压缩打包改变数据表示和容器；常用功能命令则扩展观察或操作方式。它们不是一个同质列表：例如归档完成不证明已验证恢复，退出状态也不代替数据核对。

本章小结用图中的两条分支验收：在受控环境判断命令是内建、函数还是外部程序，记录标准输出、标准错误与退出状态。查找失败首先回到命令格式与 PATH；不要因为终端还能输入就宣称全部命令可用。

### 路线3：用户管理，给访问请求补上身份

用户属性、用户与组、配置文件建立身份的表示；用户管理和组管理改变这些记录。磁盘配额则约束特定文件系统上的资源使用，并非文件读写权限的另一种写法。只看空闲磁盘仍可能漏掉配额限制，必须核查挂载、配额启用与具体主体。不要在宿主上为学习而修改用户数据库。

将图切到文件不可读：Shell 和 cat 仍可运行，失败发生在文件访问。先保留当前身份、文件及父目录的模式信息，再在隔离来宾复现；真实权限还可能受 ACL、挂载选项等影响。本章小结要能区分“不能读已有文件”和“不能继续占用空间”，二者证据不同。

### 路线4：软件管理，区分程序路径与包依赖

工具概述先划清包管理与程序执行。dpkg 命令、本地 Deb 包管理和 Deb 制作关注安装包及其元数据；APT 机制、apt-get 与 apt-cache 关注仓库索引、候选版本和依赖关系。包名不一定等于可执行文件名；即使已经装包，PATH 或环境仍可能让命令查找失败。

本章小结保存包版本、来源和依赖诊断，而非只截取“安装完成”。对图中的 PATH 故障，重装软件不是首选证据：先检查查找路径。修改仓库或安装依赖会写系统状态，应留在可回滚来宾；模拟安装计划也不保证真实下载或安装一定成功。

### 路线5：编程环境，让产物逐阶段可观察

编辑器简介、Vim 安装配置、工作模式与按键决定源文件是否按预期保存。GCC 简介、编译流程、选项和版本切换决定源文件经历哪些阶段；典型 C 工具链包括预处理、编译、汇编和链接。GDB 简介、使用及基本命令围绕被调试进程与断点；Make 简介、Makefile 使用及规则把目标、依赖和构建命令联系起来。

本章小结应交付源文件、工具版本、构建命令与诊断输出。图中能找到 cat，只证明这个工具可执行，不能替代 GCC 或 GDB 的证据。Make 报告无需更新也不保证游戏逻辑正确；先检查规则中的依赖是否完整，再进入项目验证。

### 路线6：网络配置，观察不能跳过中间层

IP 地址、子网掩码、网关和 DNS 分别参与接口地址、网段判断、跨网段转发和名字解析。图形界面配置与指令配置是两种入口，要核对实际生效状态；不同 Ubuntu 版本可能使用不同管理后端，不能复制一个文件路径就视为通用答案。

TFTP、NFS、SSH 是不同服务，不要把端口可达当成文件授权或登录成功。本章小结按“地址与路由 → 名字 → 服务与权限”保留证据。交互图没有网络栈：cat 的成功与失败都不证明网络连通。本地俄罗斯方块项目也不天然依赖远程文件服务；联网实验需要独立隔离和授权。

### 路线7：Shell 编程，把成功和失败都变成输入

脚本介绍说明命令可以组合为可重复流程；开头、执行方式、变量、语句、函数与脚本调用决定解释器、数据流与控制流。脚本由 `bash file` 执行和作为可执行文件直接启动，不具有完全相同的前提。变量应考虑引用与空值，函数返回状态也不能和打印内容混为一谈。

猜数字与石头剪刀布是目录给出的两个练习场景，不提供本页可复用的原书代码。可以自行设计固定输入序列，检查分支是否进入预期状态；不要用一次随机“赢了”当作测试。本章小结回收输入、输出及失败传递，图中的127正是不能被后续成功命令掩盖的状态。

### 路线8：正则表达式，先固定匹配规则

起源介绍定位文本检索问题，概念节点区分模式与被匹配文本；符号定义和匹配规则要先说明所用工具及模式方言，再谈文本处理工具。Shell 通配和正则不是同一种语法。以 GNU grep 为例，基本与扩展正则对某些运算符的写法有差异，不能把一个工具的模式无条件搬到另一个工具。

本章小结交付固定文本、模式、选项、匹配行和不匹配行。把观察范围限定在文本层：筛选日志可帮助找到异常，不代表日志不存在的行为就没发生。图中的输出节点只是可供检查的数据，不是自动判定对错的答案库。

### 路线9：项目实战，把工具可用与状态正确分开

开发背景、需求分析、功能设计和软件框架先限定要实现什么；核心技术、案例代码分析与设计逻辑再连接输入、移动、碰撞、消行和结束状态。这些游戏检查点是本站独立提出的验证建议，不声称核对了不可访问的原书案例实现、语言或完整代码。

效果展示应配固定棋盘与固定输入，检查方块不能穿墙、占用格不重叠、消行后格子状态一致，而不只是展示一张能动的画面。本章小结汇合工具链、脚本与文本证据：能启动是环境证据，状态转移正确是逻辑证据。未取得源码和运行记录时，案例内部实现保持未知。

## 安全起步：观察之后再决定是否写入

最小观察记录应包含执行机器、命令、身份、目录、环境、输出与状态。下面是供已准备好的隔离来宾参考的只读例子，本批没有执行它们；宿主不是 Linux 时不要照搬。显式调用 Bash 是为了避免默认 Shell 不同造成解释差异。

```bash
bash --noprofile --norc
uname -r
cat /etc/os-release
id
pwd
type -a pwd cat
printf 'status=%s\n' "$?"
```

前两项分别观察内核版本和系统标识，`id` 与 `pwd` 观察身份和位置，`type` 帮助解释命令查找；最后一行只读取紧前一条 `type` 的退出状态，不是整段脚本的成功证明。新 Bash 仍继承环境变量，也不是安全沙箱。PATH、别名、函数、缓存等必须记录或排除后，才可比较图中简化模型。

需要写入时再创建一次性来宾副本，并先明确虚拟磁盘路径；不在宿主运行提权安装、分区、格式化、用户删除或递归权限修改。禁用不需要的共享目录、剪贴板和外部网络，文件传输先检查目标位置。快照用于回滚某个来宾状态，不等同于独立备份；恢复后也要重新核查共享路径和外部副作用。任何任务若要求绕过权限或访问未授权机器，就停止。

## 容易误判的三种现象

现象背后可能跨越不同责任层。以下反例与实验的故障位置相对应，不要用后一步的“看起来正常”抹掉先一步失败。

<Callout type="trap" title="pwd 成功，所以 PATH 没问题？">
  现象：内建 pwd 有输出，外部 cat
  找不到。原因：两者查找路径不同。修法：核对命令类型和
  PATH；无缓存等简化前提不满足时，还要检查缓存、函数和别名。
</Callout>

<Callout type="trap" title="读文件失败，直接切换 root？">
  现象：程序存在但文件读取失败。原因：身份、文件或目录访问规则可能不同，提权会破坏原始条件。修法：先保留普通用户与对象证据，再在授权隔离环境定位，不在宿主上改权限试错。
</Callout>

<Callout type="trap" title="117个节点都列出来，课程就合格？">
  现象：目录计数正确却无真实操作证据。原因：范围核对、教学内容和运行验收是三个问题。修法：按本章要求收集可观察产物；本页仍为未验收草稿，不把教学模型或源文档抓取当作浏览器、虚拟机或发布证据。
</Callout>

## 小结与练习

路线图的用途是决定下一次需要什么证据，而不是提供通过率。<Term def="只能支持特定环境与责任层结论、不能任意外推的观察范围">证据边界</Term> 决定每个结论最多能走多远：先定位机器，再定位命令路径，最后检查实际产物。

- 九主题117个目录节点与本站11页不是同一个计数。
- Shell 查找失败与内核拒绝文件访问应分别定位。
- 来宾命令输出不能代替宿主、网络和项目证据。

<Exercises>

1. 在实验中选择外部 cat、PATH 故障，预测并验证；再改成内建 pwd。两次首个停止点相同吗？

<Answer>
  不相同。无缓存、函数、别名和处理钩子的模型中，cat 在查找处停止，状态127；pwd
  走内建分支，终态模型值0。这个反例应回查主题2的命令解释，再判断主题4是否真有缺包证据。重置后必须回到外部命令、无故障、首帧、无预测且暂停。
</Answer>

2. 一张终端截图同时显示 ok 与内核版本。能据此宣布 Ubuntu 来宾安装、宿主隔离和 SSH 服务均正确吗？请补出最少证据类别。

<Answer>
  不能。要补执行窗口与机器身份、来宾系统标识、虚拟磁盘与共享配置；若声称 SSH
  正常，还须在授权隔离网络记录路由/解析、服务状态及实际连接身份。终端命令最多支持当前执行环境的局部结论；没有这些记录时，跨机器与网络结论保持未知。
</Answer>
