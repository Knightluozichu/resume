## 直觉引入

你在终端敲下一行 `ls -la /home`，按下回车，屏幕上立刻列出目录内容。这看似瞬间完成的一步，其实经过了三道关卡：Shell 先把你的输入拆成「命令名 `ls`」+「选项 `-la`」+「参数 `/home`」，然后在 PATH 目录里找到 `/usr/bin/ls` 这个可执行文件，最后调内核去读取 `/home` 目录的 inode 并把结果回显到终端。Shell 就是用户与内核之间的「翻译官」——你告诉它你想做什么，它翻译成内核能执行的系统调用。

## 命令结构与 PATH 查找

<Term def="Shell 是命令行解释器（如 Bash/Zsh），负责读取用户输入、拆分命令和参数、在 PATH 中查找可执行文件、调用内核系统调用执行，最后把结果回显到终端。它是用户与内核之间的「命令翻译器」。">Shell</Term> 的命令结构固定为 `command [options] [arguments]`。以 `ls -la /home` 为例：`ls` 是命令名；`-la` 是选项（`-l` 长格式，`-a` 显示隐藏文件，短选项可合并）；`/home` 是参数。短选项用单减号 `-`，长选项用双减号 `--`（如 `ls --all`）。

Shell 如何找到 `ls`？它按顺序搜索 PATH 环境变量列出的目录（如 `/usr/local/bin:/usr/bin:/bin`），找到第一个匹配就执行。找不到则报 `command not found`。

```bash
# 查看命令的完整路径
which ls          # /usr/bin/ls
whereis nginx     # nginx: /usr/sbin/nginx /etc/nginx

# 查看当前 PATH
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

# 自定义脚本执行方式
./script.sh       # 用 ./ 指定当前目录（不在 PATH 中）
cp script.sh /usr/local/bin/  # 放入 PATH 目录后可直接 script.sh 执行
```

## 管道与重定向

管道和重定向是命令行的核心组合能力——它们让简单命令可以串联成强大的数据处理流水线。

```bash
# 管道：命令 → 命令（前一个的 stdout 连到后一个的 stdin）
ls -la | grep '.txt'           # 列出文件并过滤含 .txt 的行
ps aux | sort -k3 -rn | head   # 按CPU排序取前10进程
cat access.log | wc -l          # 统计文件行数

# 重定向：命令 ↔ 文件
ls > files.txt                  # stdout 写入文件（覆盖）
ls >> files.txt                 # stdout 追加到文件
sort < unsorted.txt             # 从文件读入 stdin
command > out.log 2> err.log    # stdout 和 stderr 分别写入不同文件
command > all.log 2>&1          # stderr 合并到 stdout 一起写入
command > /dev/null 2>&1        # 丢弃所有输出（静默执行）

# 进程的三个标准流
# stdin  (fd 0) ← 终端键盘 / 文件 / 管道输入
# stdout (fd 1) → 终端屏幕 / 文件 / 管道输出
# stderr (fd 2) → 终端屏幕 / 文件（错误信息，可独立重定向）
```

## 实战：组合命令排查问题

```bash
# 找出占用磁盘最大的 5 个目录
du -sh /* 2>/dev/null | sort -rh | head -5

# 统计 nginx 访问日志中访问量最高的 10 个 IP
cat /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# 查找并杀掉占用 8080 端口的进程
ss -tlnp | grep 8080    # 找到 PID
kill -9 <PID>            # 终止进程

# 批量重命名 .txt 为 .bak
for f in *.txt; do mv "$f" "${f%.txt}.bak"; done
```

<Callout type="trap">
**误区：管道会传递 stderr。** 管道只传递 stdout。如果一个命令的报错信息经 stderr 输出，管道后面的命令收不到。要捕获错误流需用 `2>&1` 把 stderr 合并到 stdout。例如 `command 2>&1 | grep error` 才能过滤到错误信息。另一个坑：`command | grep error` 中如果 command 失败了，因为管道只看最后一个命令的退出码，grep 成功则整个管道返回成功——生产脚本中应加 `set -o pipefail` 使管道中任一命令失败则整体失败。
</Callout>

<Exercises>
**问题 1**：Shell 如何找到用户输入的命令？PATH 的作用是什么？

<Answer>
用户键入命令后，Shell 按顺序在 PATH 环境变量列出的目录中查找同名的可执行文件。PATH 是冒号分隔的目录列表，如 `/usr/local/bin:/usr/bin:/bin`。Shell 从左到右搜索，找到第一个匹配就执行。找不到则报 `command not found`。用 `which command` 可查看命令完整路径，`echo $PATH` 查看搜索路径。
</Answer>

**问题 2**：管道和重定向的区别是什么？`2>&1` 的含义是什么？

<Answer>
管道 `|` 把前一个命令的 stdout 连到后一个命令的 stdin，用于命令间传递数据。重定向改变数据流向：`>` 写入文件（覆盖），`>>` 追加，`<` 从文件读入。`2>&1` 把 stderr（fd 2）重定向到 stdout（fd 1）当前指向的位置，使错误信息和正常输出合并到一起。常用于 `command > all.log 2>&1` 把所有输出写入同一文件，或 `command 2>&1 | grep error` 让管道也传递错误信息。
</Answer>
</Exercises>
