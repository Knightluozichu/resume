## 核心机制深挖

由终端、Shell和命令格式进入用户/系统、文件、压缩打包及常用功能命令，重点是参数、输入输出和退出状态。 原书以2021年前后的Ubuntu和嵌入式开发辅助环境为对象。命令、包版本、网络配置界面和工具输出会随发行版更新，因此本页保留原书目录身份，并要求实验记录实际Ubuntu版本；现代差异只能作为显式对照，不能悄悄改写原书。

本页不变量是：**当前目录、引用与通配符、标准输入输出错误、返回码和副作用都明确，危险命令先在隔离目录验证。**。它在正常命令、权限拒绝、依赖缺失、网络超时和中断恢复中都必须成立。命令退出为零只是一个样本，不代表执行身份正确、文件树无污染、配置可重建或下一次运行仍然幂等。

最小实验：建立测试目录，完成查找、复制、压缩、管道和重定向任务，并为每步保存命令、输出和文件树差异。 每一步先写预期，再记录命令文本、当前目录、用户与组、标准输出/错误、退出码和前后状态差异。对需要管理员权限的操作，说明为何需要提权以及最小授权范围。

故障实验：注入空通配符、含空格文件名、权限拒绝和管道前段失败，验证引用与pipefail。 删除故障后应从干净快照或明确逆操作恢复，以完全相同的输入重放。若表面结果恢复但包数据库、账户文件、路由、挂载、临时文件或后台进程仍不同，就不能判定通过。

所有破坏性练习都应在可丢弃虚拟机、临时目录或隔离网络中进行。不要在生产主机复制删除、账户、包管理、网络或服务命令；实验安全边界本身也是本章知识的一部分。

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
trap 'printf "failed at line %s\n" "$LINENO" >&2' ERR
workspace="$(mktemp -d)"
trap 'rm -rf "$workspace"' EXIT
printf 'stage=%s workspace=%s\n' "打开终端会话" "$workspace"
```
