## 为什么“看起来一样”还会复制失败

把一份带空格的报告复制到新位置，少写两个引号，结果可能从“一份副本”变成“两次找不到文件”。这一章教你在敲回车前推断结果，而不是失败后反复试同一行。

只盯着屏幕最后有没有出现文件，会错过真正的问题：输入在哪里被拆开，目标位置是否存在，失败是否已经被下一次操作掩盖。先把这三件事分开，才有可靠的排查顺序。

## 第2章 Linux 操作系统的使用

本章把操作拆成一条可观察的责任链：输入窗口传递字符，解释程序整理参数，具体命令读写文件，最后返回状态。后面的模型始终使用同一组两份源文件，让引号、匹配规则和目标目录的变化有可比较的结果；命令速查与归档实验再把这条链用到其他任务。

范围依据是出版社目录中的本章 13 个层级节点，不是原书正文。以下技术解释独立依据 GNU Bash、GNU Coreutils、GNU tar 与 Ubuntu 官方文档重写。示例面向 Ubuntu 中的 Bash 与 GNU 工具；浏览器中的图只计算有限案例，不会在你的电脑上执行命令。

## 2.1 初识终端

<Term def="让用户输入字符并显示程序输出的交互端点；桌面中通常由终端模拟器提供">
  终端
</Term>
不是“一个会复制文件的程序”。你输入字符，终端把字符送给正在前台读取输入的程序，并显示程序写回的内容。把窗口换成另一款软件，不会自动修复文件名引用错误。下表把后续实验的三个责任者放到同一条线上。

| 责任者   | 接收什么                 | 负责什么                     | 不负责什么                   |
| -------- | ------------------------ | ---------------------------- | ---------------------------- |
| 终端软件 | 键盘输入、程序输出字符   | 显示、会话交互、滚动记录     | 不决定 `*.txt` 匹配哪些文件  |
| Bash     | 一行字符、当前目录、环境 | 识别引号、展开路径、启动命令 | 不替 `cp` 保证目标可写       |
| `cp`     | 已整理好的参数与文件路径 | 读取源、写入目标、返回结果   | 不知道输入时哪些引号被移除了 |

### 2.1.1 终端介绍

提示符是程序显示的“可以输入了”的提示，不属于命令本身。示例里只复制代码，不复制书籍中常见的行首 `$`。提示符能被定制，不能凭一个 `#` 或用户名字符串证明当前权限；身份要用命令查询。窗口历史也不是文件备份：看见先前输出，不表示文件还处于当时状态。

先在 Ubuntu 的终端输入下列只读观察命令。`pwd` 显示当前工作目录，`printf` 在这里输出固定文字。预期是一个目录路径和一行 `ready`；目录名因环境而异，不要求相同。对应练习 3 要求区分“屏幕内容”和“程序事实”。

```bash
pwd
printf '%s\n' 'ready'
```

### 2.1.2 终端软件

Ubuntu 桌面可从应用列表搜索 Terminal；官方入门教程也给出常见的 `Ctrl` + `Alt` + `T` 快捷键。不同桌面版本、发行版和按键设置可能不同，服务器安装也可能根本没有桌面窗口。GNOME Terminal 等终端模拟器提供窗口和标签页；Bash 是窗口里可能运行的解释程序，二者可分别替换。

**会话的当前目录独立，底层文件并不因此复制**。下面用两个独立 Bash 会话 A、B 区分这两种状态：`cd` 改的是执行它的 Shell 的当前目录，不是某个文件的存放位置；两个会话若访问同一实际路径，读写的仍是同一文件。关闭含未完成任务的窗口也不能当作可靠的暂停方式。

这是可选的 Ubuntu 实机对照，**网页未执行这些命令**；需要同一台机器、同一用户、同一文件系统视图的两个独立 Bash 会话，而不是连接不同主机的窗口。先预测，再依次输入。只在新建的临时目录写一个固定文本文件，不用 sudo、不删除既有文件。若任一步报错就停止，不继续输入后续段。

**准备 A：** 新建专用目录及子目录，进入专用目录并打印真实路径。下面将打印出的路径记作 P；P 是说明符号，不是要输入的命令或固定路径。

```bash
base=$(mktemp -d /tmp/lop02-session.XXXXXX) &&
  mkdir -- "$base/sub" &&
  cd -- "$base" &&
  pwd -P
```

**准备 B：** 把下一段第一行单引号内的路径，完整替换为 A 刚打印的 P（不要照抄“实际后缀”）。B 的 `base` 是手动赋值，不是从 A 自动同步。此时分别在 A、B 输入 `pwd -P`，都应得到 P。

```bash
base='/tmp/lop02-session.实际后缀'
cd -- "$base" && pwd -P
```

**先预测：** 只让 A 进入 `sub` 后，B 的 `pwd -P` 会变成 P/sub 吗？A 随后写入 P/shared.txt，B 留在 P 是否能读到？请先写下两个路径和文件内容，再按顺序核对；练习 3 的第一问直接回收此区别。

**只在 A 输入：** 第一行记录移动前路径，第二行只移动 A，第三行记录移动后路径，最后写入同一个绝对路径。

```bash
pwd -P
cd -- "$base/sub" &&
  pwd -P &&
  printf '%s\n' 'from-A' > "$base/shared.txt"
```

**然后在 B 输入：** 两次 `pwd -P` 包围读取操作，检查读取同一文件不需要让 B 跟随 A 切换目录。

```bash
pwd -P
cat -- "$base/shared.txt"
pwd -P
```

| 按顺序观察的状态  | A 的 `pwd -P` | B 的 `pwd -P`     | P/shared.txt 与 B 的读取                    |
| ----------------- | ------------- | ----------------- | ------------------------------------------- |
| 两边准备完成      | P             | P                 | 尚未创建文件                                |
| 仅 A 执行 `cd` 后 | P/sub         | P（未改变）       | 尚未创建文件                                |
| A 写入，B 再读取  | P/sub         | P（读取前后相同） | 文件内容为 `from-A` 加换行；B 输出 `from-A` |

表中的路径是**预期状态，不是运行日志**。A 的 `cd` 没有向 B 发出切换目录操作；A 的重定向却实际写入共享文件系统。这里使用 `"$base/shared.txt"` 固定同一路径；如果在 A 改用相对路径 `shared.txt`，会写到 P/sub/shared.txt，B 在 P 读取 `shared.txt` 就不是同一目标。不同主机、容器挂载或权限差异也不能套用“同一路径必可见”。下方主实验只解释单会话参数与复制，不负责模拟 A/B 会话。

这一区别可核对 [Ubuntu Bash 手册的执行环境与 cd 内建命令](https://manpages.ubuntu.com/manpages/noble/en/man1/bash.1.html)：当前工作目录属于 Shell 的执行环境。无需清理或复用此目录；若想从头比较，重新准备一个新目录，并把新 P 再传给 B，不要对旧文件作批量删除。

这里的终端说明与打开方法参照 [Ubuntu 命令行入门](https://ubuntu.com/tutorials/command-line-for-beginners)；实验图中的 `sandbox/` 是模型标签，不是你已经创建的目录。

## 2.2 认识 Shell

<Term def="读取命令文本、按语法展开和组织参数、执行命令并收集结果的解释程序">
  Shell
</Term>
把字符输入变成程序调用。Bash 是一种 Shell；Linux
是操作系统内核，二者不能画等号。Bash
可以交互读取，也可以读取脚本。我们此处只研究简单命令的路径参数，不提前引入完整脚本语言。

在实验里，Shell 位于字符表达式与 `cp` 之间。图上的参数槽来自其处理结果，不是 `cp` 自己重新解析一遍命令文本。此职责依据 [Bash：Shell 是什么](https://www.gnu.org/software/bash/manual/html_node/What-is-a-shell_003f.html) 与 [Shell 的操作步骤](https://www.gnu.org/software/bash/manual/html_node/Shell-Operation.html)。

### 2.2.1 Shell 概述

`cd` 必须改变当前 Shell 的工作目录，所以是内建命令；如果只让一个外部子程序改自己的目录，父 Shell 不会跟着移动。`cp` 通常是外部工具，接收路径后操作文件。`type cd`、`type cp` 可以观察当前 Bash 如何解析这些命令名；输出可能显示内建、路径、函数或别名，不应预先把所有环境都当作同一配置。

```bash
printf '%s\n' "$BASH_VERSION"
type cd
type cp
```

若第一行为空，不要直接套用本章的 Bash 匹配预期，先确认当前解释程序。环境变量 `$SHELL` 通常记录登录 Shell，**不保证就是当前正在解释这行输入的程序**。本章模型假定无别名或函数替换 `cp`；诊断真实机器时，应先做这里的观察。变量与内建命令定义见 [Ubuntu Bash 手册](https://manpages.ubuntu.com/manpages/noble/en/man1/bash.1.html)。

### 2.2.2 Shell 命令格式

常见外形是“命令名、选项、操作数”，但不是所有命令都接受相同选项。GNU `cp -- "report one.txt" out/` 中，`--` 是交给 `cp` 的“选项到此结束”，后两项是源和目标。Shell 移除语法引号后交付的 <Term def="程序收到的有序字符串列表；一个槽位对应一个完整参数，槽内允许空格">参数数组 argv</Term> 为下表所示。命令名计入第 0 项；计数 `argc` 为 4。

| 索引 | 字符串           | 谁解释其用途            |
| ---- | ---------------- | ----------------------- |
| 0    | `cp`             | 程序调用的命令名        |
| 1    | `--`             | GNU `cp` 识别为选项结束 |
| 2    | `report one.txt` | `cp` 查找的一条源路径   |
| 3    | `out/`           | `cp` 使用的目标目录路径 |

双引号能保护这里的空格，但并不是“里面永远不展开”：`$` 等仍有特殊规则；单引号则保留其中字符的字面值，不能直接包含另一个单引号。本例仅用无变量的文件名，避免把引用问题与变量展开混成一件事。参照 [单引号](https://www.gnu.org/software/bash/manual/html_node/Single-Quotes.html)、[双引号](https://www.gnu.org/software/bash/manual/html_node/Double-Quotes.html)。

**先预测：**把源文件名的引号去掉，`cp` 收到几条源路径？再选 `*.txt`：一个匹配出的文件名内部有空格，会不会再次被拆开？请选择预测，逐步推进到最后一帧，再读解释；完整 Reset 可恢复全部条件。

<Lop02UsingLinuxLab />

模型的无匹配案例是 `*.log`。Bash 未启用 `nullglob`、`failglob` 时，它原样进入参数数组；启用 `failglob` 则在展开阶段报错，根本不启动 `cp`。如果启用模型未提供的 `nullglob`，这个词会被删除；只剩目标的 `cp` 仍不构成成功复制。zsh 的默认无匹配行为不同，不能用 macOS 默认 Shell 来“反证”这个 Bash 案例。依据 [Bash 路径名展开](https://www.gnu.org/software/bash/manual/html_node/Filename-Expansion.html)。

## 2.3 Linux 操作系统命令

选择命令前先确定要观察哪个对象：自己的身份、系统信息、目录项还是文件内容。相同的一行字符在不同工作目录中可以访问不同文件；选项拼写正确，也可能因为目标不存在而失败。实验的第 4、5 帧分别显示文件变化和结果，目的是防止把“已经执行”误认为“已经成功”。

<Term def="命令结束后交回 Shell 的数值；0 通常表示成功，非零含义由命令和 Shell 约定">
  退出状态
</Term>
用 `$?`
读取，但它只属于最近结束的命令。要马上保存，再打印或执行其他命令。错误输出与状态是两条证据：无输出的
`cp` 可以成功，输出了一行提示也不证明任务完成。Bash 的命令未找到常用
127，找到却不可执行常用 126；不要把模型里的 1 推广成所有失败。

### 2.3.1 用户与系统相关命令

先查身份，再讨论权限，避免遇错就加 `sudo`。`whoami` 回答当前有效用户名称，`id` 显示用户及组标识，`uname` 查询内核相关信息。它们不负责创建账户，本章也不改用户和组；账户管理留给下一章。下表是不同问题对应的观测，不是几条可以互相替代的命令。

| 问题                         | 只读命令               | 输出不能证明什么                 |
| ---------------------------- | ---------------------- | -------------------------------- |
| 这个进程以谁的有效身份运行？ | `whoami`、`id -u`      | 不单凭用户名证明某目录可写       |
| 它带哪些组身份？             | `id`                   | 不保证组信息在别的旧会话中已更新 |
| 正在运行哪个内核？           | `uname -s`、`uname -r` | 不等于 Ubuntu 发行版本号         |

在 Ubuntu 还可读取 `/etc/os-release` 了解发行版；它与 `uname -r` 回答的对象不同。在练习 3 中，先指出应该查“身份”还是“目标目录”，而不是把系统信息当错误修复指令。命令定义参照 [Coreutils 用户信息](https://www.gnu.org/software/coreutils/manual/coreutils.html#User-information) 与 [系统上下文](https://www.gnu.org/software/coreutils/manual/coreutils.html#System-context)。

### 2.3.2 文件相关命令

<Term def="定位文件或目录的名称序列；相对路径从当前工作目录出发，绝对路径从根目录出发">
  路径
</Term>
是名字，不是内容。`pwd` 定位出发点，`ls` 列出目录项，`mkdir` 创建目录，`cp`
复制，`mv` 移动或改名，`rm`
删除；删除不承诺进入桌面回收站。图中源和副本属于不同目录项，复制成功后源仍存在，不能把
`cp` 看成剪切。

下面是**可选的 Ubuntu/Bash 实机实验**，不是网页模型的执行记录。它只在 `mktemp` 新建的目录中写固定文件，无管理员权限、无网络、无删除。括号把目录改变限制在子 Shell；每次重新运行会生成新的临时目录，不污染已有实验。退出状态在复制后立即保存。

```bash
(
  work=$(mktemp -d) || exit 1
  cd -- "$work" || exit 1
  mkdir -- out || exit 1
  printf '%s\n' A > a.txt || exit 1
  printf '%s\n' R > 'report one.txt' || exit 1
  cp -- 'report one.txt' out/
  rc=$?
  printf 'cp status=%s\n' "$rc"
  ls -1 -- out/
  printf '保留实验目录：%s\n' "$work"
)
```

预期 `cp status=0`，`out/` 中只有 `report one.txt`。若手动把 `cp` 那行改成不带引号的 `report one.txt`，新目录里没有 `report` 或 `one.txt`，GNU `cp` 预期非零且不产生副本。已有目录、权限和磁盘故障可能让真实行为不同；查 [GNU cp 文档](https://www.gnu.org/software/coreutils/manual/coreutils.html#cp-invocation)，不要用模型替代诊断。本章不提供 `rm -rf` 清理命令；确认临时路径后可用文件管理器检查和删除。

### 2.3.3 压缩打包相关指令

归档把多个路径与文件内容组织成一个容器，压缩再对数据编码以减少体积；二者不是同一操作。GNU tar 的 `-c` 创建、`-t` 列目录、`-x` 提取、`-f` 指定归档文件；`-z` 选择 gzip 压缩。后缀 `.tgz` 本身不是内容正确性的证明。先检查归档成员名，再选择提取位置，避免覆盖工作文件。

| 时点                              | 参与的路径              | 结果                      |
| --------------------------------- | ----------------------- | ------------------------- |
| 创建前                            | `data/report one.txt`   | 一份源文件                |
| `tar -czf bundle.tgz -C data ...` | 成员名 `report one.txt` | 包内不必携带 `data/` 前缀 |
| `tar -tzf bundle.tgz`             | 列出成员名              | 不向目录写入成员          |
| `tar -xzf bundle.tgz -C unpack`   | `unpack/report one.txt` | 在指定目录生成副本        |

这里的 `-C` 是 tar 在处理后续路径时改变目录，**不是**让调用它的 Shell 永久换目录。下面只提取自己刚刚创建的归档，且输出目录全新；不要把它无条件套在下载来的不可信包上。路径穿越、链接和覆盖风险需要额外审查，本节不声称提供通用安全解包器。

```bash
(
  work=$(mktemp -d) || exit 1
  cd -- "$work" || exit 1
  mkdir -- data unpack || exit 1
  printf '%s\n' R > 'data/report one.txt' || exit 1
  tar -czf bundle.tgz -C data -- 'report one.txt' || exit 1
  tar -tzf bundle.tgz || exit 1
  tar -xzf bundle.tgz -C unpack || exit 1
  cat -- 'unpack/report one.txt'
  printf '保留归档实验目录：%s\n' "$work"
)
```

预期列出 `report one.txt`，提取后 `cat` 显示 `R`。若 `unpack` 不存在，`-C unpack` 不会代建目录。参照 [GNU tar 创建归档](https://www.gnu.org/software/tar/manual/html_node/create.html) 与 [改变工作目录](https://www.gnu.org/software/tar/manual/html_node/directory.html)，`-z` 等选项另见 [Ubuntu tar 手册](https://manpages.ubuntu.com/manpages/noble/en/man1/tar.1.html)；练习 2 要求你先写出成员路径，再推断提取落点。

### 2.3.4 系统常用功能命令

常用功能不是背诵更多命令名，而是把输入与输出接起来。`cat` 读取文件内容，`wc -l` 统计换行数量，`sort` 排序；`date` 读取时间。计数不等于读者肉眼认为的“行数”：没有末尾换行的一个单词可以让 `wc -l` 输出 0。下面直接产生输入，不依赖网络和已有文件。

```bash
printf 'b\na\n' | LC_ALL=C sort | wc -l
printf 'one' | wc -l
```

第一行预期为 2，第二行为 0；输出周围空白不计入判断。竖线把前一个命令的标准输出交给后一个命令的标准输入；错误输出默认不在这条通道内。`LC_ALL=C` 固定排序规则，避免把语言环境差异误判为排序错误。

Bash 默认管道的退出状态来自最后一个命令，因此最后的计数成功不能证明上游都成功。本章先用逐条保存状态定位错误；后续 Shell 编程再讨论 `pipefail`。命令说明参照 [Coreutils wc](https://www.gnu.org/software/coreutils/manual/coreutils.html#wc-invocation)、[sort](https://www.gnu.org/software/coreutils/manual/coreutils.html#sort-invocation)；管道规则参照 [Bash 管道](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html)。练习 3 用输出与状态分离来检验这个边界。

## 常见误区：先判断是谁的错误

<Callout type="trap" title="文件存在，cp 却说找不到">

**现象 →** `report one.txt` 在源目录里，不带引号复制仍失败。 **原因 →** Bash
按未引用的空白分出两个路径；不是文件被改名。 **修法 →**
用引号保留参数边界，在实验中对照 argv 第 2、3 槽。

</Callout>

<Callout type="trap" title="没有匹配，不等于自动跳过">

**现象 →** `*.log` 没匹配却仍被 `cp` 当作路径。 **原因 →** Bash
的默认无匹配规则保留原词；failglob 会改为提前报错。 **修法 →** 先确认 Shell
与选项，在模型中打开 failglob 看 cp 是否启动。

</Callout>

<Callout type="trap" title="最后一条命令成功，误以为前面也成功">

**现象 →** 复制失败后运行 `ls`，再查 `$?` 却得到 0。 **原因 →** 状态已被 `ls`
的结果替换，管道也有类似遮蔽风险。 **修法 →** 每个关键操作后立即
`rc=$?`，同时核对文件变化。

</Callout>

## 2.4 本章小结

- 终端传递字符，Bash 整理参数，命令操作文件。
- 引号保护参数边界，通配符展开由 Shell 决定。
- 先查身份与路径，再看文件、归档与退出状态。

### **问题 1：修改模型输入并定位失败层**

初始 `out/` 存在，先切换到“去掉引号”，再预测“不会写入”并单步走完。写出完整 argv、源文件数量与新增副本数。再切换 `*.txt`，先预测后重放；最后打开“out/ 不存在”。哪一次是 Shell 错误？用完整 Reset 检查是否恢复初始条件。

<Answer>

去引号时 argv 为 `cp`、`--`、`report`、`one.txt`、`out/`，两条源路径都不存在，副本为 0、预期 cp 状态为 1。`*.txt` 展开成 `a.txt` 与 `report one.txt`，后者虽然有空格仍是一个参数；两个源均复制，状态为 0。目标缺失时 cp 已经启动，但不能向目录写入，预期状态为 1；这三次都不是 Shell 展开错误。只有另选无匹配 `*.log` 且打开 failglob 才由 Shell 中止。Reset 后是“保留空格”、目标存在、failglob 关、预测未选、第 1 帧、暂停；旧时间线取消，副本尚未显示。

</Answer>

### **问题 2：独立设计不会混淆路径的归档检查**

要求把 `data/report one.txt` 放入归档，包内成员名不要带 `data/`，再提取到空目录 `unpack/`。写出创建、列目录与提取三行命令，解释 `-C` 的作用。若 `unpack/` 不存在，应该先改哪个条件？

<Answer>

在本节临时目录的准备步骤之后，三行依次是 `tar -czf bundle.tgz -C data -- 'report one.txt'`、`tar -tzf bundle.tgz`、`tar -xzf bundle.tgz -C unpack`。第一个 `-C` 让后续源路径相对于 data 查找，所以成员名是 `report one.txt`；第二个 `-C` 决定提取根，结果是 `unpack/report one.txt`，不会变成 `unpack/data/report one.txt`。先创建并确认目标是专用空目录，而不是把错误“修成”管理员权限。只对自己创建并检查过的包做本实验。

</Answer>

### **问题 3：会话目录、共享文件与命令证据**

**第一问，先预测两个会话：** 两边已按 2.1.2 准备在 P。只有 A 执行 `cd -- "$base/sub"`，随后向 `"$base/shared.txt"` 写入 `from-A` 加换行。B 不执行 `cd`，依次运行 `pwd -P`、`cat -- "$base/shared.txt"`、`pwd -P`。假定所有命令成功且没有其他写入者，写出 A 的最终目录和 B 的三项输出。若 A 改向相对路径 `shared.txt` 写入，B 在 P 运行 `cat shared.txt` 还能读到这次写入吗？解释“独立”的是哪种状态，“共享”的又是什么。

**第二问，检查证据：** 一位同学在终端执行复制，看到错误，随后用 `uname -r` 和 `ls` 得到输出，便说“系统正常，复制成功”。指出至少三处证据不充分。再预测 `printf 'one' | wc -l` 的计数，说明它为何不能代替复制结果检查。

<Answer>

第一问：A 的最终目录为 P/sub；B 依次输出 P、`from-A`、P（每项都有换行）。A 的 `cd` 只改 A 会话的当前目录；B 的当前目录保持 P，但两个会话通过相同绝对路径访问的是同一个文件，文件不会按终端窗口各复制一份。若 A 改用相对路径，则写入 P/sub/shared.txt；B 的 `cat shared.txt` 仍访问 P/shared.txt，**不是这次写入**。若 P/shared.txt 不存在会报错；若保留了上一步实验文件则读到旧内容，不能因此认定路径相同。

第二问：终端能显示文字只说明交互仍工作；`uname -r` 是内核版本，不是文件权限或发行版本；`ls` 成功的退出状态不能回溯证明 `cp` 成功。应先用 `type cp` 确认命令，必要时用 `id` 查有效身份，再核对当前目录、两端路径与 cp 当时保存的状态。`printf 'one'` 不产生换行，因此 `wc -l` 为 0；管道只统计其收到的数据，既没读取目标副本，也没验证文件内容一致。网页模型没有执行这些真实命令。

</Answer>
