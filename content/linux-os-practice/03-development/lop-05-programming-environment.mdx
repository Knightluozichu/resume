## 核心机制深挖

把Vim编辑模式、GCC编译流程与选项、GDB调试和Makefile规则串成从源文件到可诊断程序的Linux开发闭环。 原书以2021年前后的Ubuntu和嵌入式开发辅助环境为对象。命令、包版本、网络配置界面和工具输出会随发行版更新，因此本页保留原书目录身份，并要求实验记录实际Ubuntu版本；现代差异只能作为显式对照，不能悄悄改写原书。

本页不变量是：**源文件、编译选项、头文件、目标文件、链接库和调试符号可追溯，Make依赖图与真实产物一致。**。它在正常命令、权限拒绝、依赖缺失、网络超时和中断恢复中都必须成立。命令退出为零只是一个样本，不代表执行身份正确、文件树无污染、配置可重建或下一次运行仍然幂等。

最小实验：编写多文件C程序，用-E/-S/-c观察阶段产物，制造崩溃后由GDB回溯，再用Makefile实现增量构建。 每一步先写预期，再记录命令文本、当前目录、用户与组、标准输出/错误、退出码和前后状态差异。对需要管理员权限的操作，说明为何需要提权以及最小授权范围。

故障实验：注入缺头文件、未定义符号、优化后变量消失和错误依赖，区分编译、链接、运行与构建缓存故障。 删除故障后应从干净快照或明确逆操作恢复，以完全相同的输入重放。若表面结果恢复但包数据库、账户文件、路由、挂载、临时文件或后台进程仍不同，就不能判定通过。

所有破坏性练习都应在可丢弃虚拟机、临时目录或隔离网络中进行。不要在生产主机复制删除、账户、包管理、网络或服务命令；实验安全边界本身也是本章知识的一部分。

## 最小可重放骨架

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
trap 'printf "failed at line %s\n" "$LINENO" >&2' ERR
workspace="$(mktemp -d)"
trap 'rm -rf "$workspace"' EXIT
printf 'stage=%s workspace=%s\n' "编辑源文件" "$workspace"
```

```text
baseline: Ubuntu version + package index + user identity + file tree + network state
prediction: command + expected exit code + expected side effects
observation: stdout + stderr + exit code + state diff
recovery: reverse command or clean snapshot + identical input replay
```

```bash
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：命令没有报错就代表任务正确。**
  命令可能以错误用户执行、修改了意外路径、吞掉管道前段失败或留下半配置状态，必须检查退出码和前后状态差异。
</Callout>

<Callout type="trap">
  **误区二：把通用运维主题当成原书章节。**
  官方目录没有独立systemd和防火墙章，却有Vim/GCC/GDB/Make、正则表达式与俄罗斯方块项目；忠实复原不能用自拟主题替换。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                     | 必查证据                 | 通过条件     |
| ---- | ---------------------------- | ------------------------ | ------------ |
| 正常 | 固定快照、身份和输入         | 命令、退出码、状态差异   | 与预测一致   |
| 边界 | 空文件、极限配额、无匹配输入 | 引用、终止和副作用       | 不越界不误删 |

| 恢复 | 逆操作或快照后重放           | 文件、账户、包、网络状态 | 回到基线     |
