## 直觉引入

一台服务器要能被外部访问，就像一栋楼要能通邮——首先楼要有门牌号（MAC 地址，网卡固有的），然后要分配一个街道地址（IP 地址，可配置的），还要知道信件往哪送（路由表，决定数据包的下一跳），最后要能查地址簿（DNS，把域名翻译成 IP）。这四层从底到顶：接口 → IP → 路由 → DNS，就是 Linux 网络配置的核心。

## 网络接口与 IP 地址

<Term def="ip 命令来自 iproute2 包，是现代 Linux 网络配置的标准工具，替代了废弃的 ifconfig。它通过 netlink 接口与内核通信，可操作网络接口、IP 地址、路由表、ARP 表等。">ip 命令</Term> 是网络配置的核心工具：

```bash
# 查看网络接口
ip link show              # 列出所有网卡（eth0/wlan0/lo）
ip -br link show          # 精简格式（接口名+状态+MAC）

# 查看 IP 地址
ip addr show              # 详细查看所有接口的 IP
ip -br addr show          # 精简格式
# eth0   UP    192.168.1.10/24  fe80::a00:27ff:fe4e:66a1/64

# 配置 IP（临时生效，重启丢失）
sudo ip addr add 192.168.1.10/24 dev eth0    # 给 eth0 添加 IP
sudo ip addr del 192.168.1.10/24 dev eth0    # 删除 IP
sudo ip link set eth0 up                      # 启用接口
sudo ip link set eth0 down                    # 禁用接口
```

## 路由表

```bash
# 查看路由表
ip route show
# default via 192.168.1.1 dev eth0        # 默认网关
# 192.168.1.0/24 dev eth0 proto kernel    # 本网段直连

# 路由决策规则：
# 1. 内核收到数据包，查找目标 IP
# 2. 按路由表从具体到通用匹配
# 3. 匹配到本网段→直接交付
# 4. 都不匹配→走默认路由（default via 网关）

# 配置路由（临时）
sudo ip route add default via 192.168.1.1     # 设置默认网关
sudo ip route add 10.0.0.0/8 via 192.168.1.2  # 添加静态路由
sudo ip route del default                     # 删除默认路由

# 查看ARP表（IP→MAC映射）
ip neigh show
```

## netplan 持久化配置

```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  ethernets:
    eth0:
      addresses:
        - 192.168.1.10/24        # 静态IP
      gateway4: 192.168.1.1      # 默认网关
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]  # DNS服务器

# DHCP 自动获取 IP
# /etc/netplan/01-dhcp.yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: true
```

```bash
# 应用 netplan 配置
sudo netplan apply              # 立即生效（永久）
sudo netplan try                # 试应用（120秒后自动回滚，防SSH断连）

# DNS 解析
cat /etc/resolv.conf            # 查看 DNS 服务器
# nameserver 8.8.8.8
# nameserver 1.1.1.1

# 测试 DNS 解析
dig example.com                 # 详细 DNS 查询
nslookup example.com            # 简单 DNS 查询
```

## 连通性排查

```bash
# 检查本地网络
ip addr show                    # IP 配置是否正确
ip route show                   # 路由表是否有默认网关

# 逐层排查
ping 127.0.0.1                  # 测试本机 TCP/IP 协议栈
ping 192.168.1.1                # 测试能否到达网关
ping 8.8.8.8                    # 测试能否到达外网IP
ping example.com                # 测试 DNS 解析+外网连通
curl -I http://example.com      # 测试 HTTP 连通

# 查看端口监听状态
ss -tlnp                        # TCP监听端口（t=tcp, l=listen, n=数字, p=进程）
ss -tlnp | grep 80              # 查看谁在监听 80 端口
```

<Callout type="trap">
**误区：`ip addr add` 配置的 IP 会永久生效。** ip 命令的配置是临时的，重启后丢失。要永久生效必须写入配置文件——Ubuntu 用 netplan（`/etc/netplan/*.yaml`），CentOS 用 NetworkManager 或 `/etc/sysconfig/network-scripts/ifcfg-*`。另一个坑：`netplan apply` 会立即切换网络配置，如果你通过 SSH 连接且新配置有误，会断连锁死自己。用 `netplan try` 可试应用——如果 120 秒内不按回车确认，自动回滚到旧配置。
</Callout>

<Exercises>
**问题 1**：什么是默认网关？路由表如何决定数据包走向？

<Answer>
默认网关是当目标 IP 不在本机任何子网内时数据包的下一跳地址。路由查找规则：从最具体到最通用匹配——先查匹配目标子网的路由（如 192.168.1.0/24），有则直接交付；都不匹配则走默认路由发给网关。`ip route show` 查看路由表，`default via 192.168.1.1` 表示默认网关。
</Answer>

**问题 2**：netplan 相比传统方式有什么优势？如何安全生效？

<Answer>
netplan 用 YAML 声明式描述配置，优势：①声明式清晰可读；②持久化——apply 后永久生效；③统一后端生成 NetworkManager 或 systemd-networkd 配置。传统 `ip addr add` 是临时的。安全生效用 `netplan try`——试应用 120 秒，不确认则自动回滚，防止 SSH 断连锁死。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="ip 命令">来自 iproute2 的现代网络配置工具，替代废弃的 ifconfig。通过 netlink 与内核通信，可操作接口、IP、路由、ARP。配置是临时的，持久化需配合 netplan 或 NetworkManager。</GlossaryItem>
<GlossaryItem term="路由表">内核维护的数据包转发决策表。按从具体到通用匹配目标 IP——匹配本网段直接交付，不匹配走默认网关。`ip route show` 查看。</GlossaryItem>
<GlossaryItem term="netplan">Ubuntu 的网络配置抽象层，用 YAML 声明式描述。`netplan apply` 永久生效，`netplan try` 试应用可自动回滚。配置文件在 /etc/netplan/*.yaml。</GlossaryItem>
</Glossary>
