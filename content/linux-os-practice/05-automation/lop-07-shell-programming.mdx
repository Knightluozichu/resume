## 核心机制深挖

从脚本头和执行方式进入变量、语句、函数、脚本调用，再用猜数字与石头剪刀布验证控制流和输入边界。 原书以2021年前后的Ubuntu和嵌入式开发辅助环境为对象。命令、包版本、网络配置界面和工具输出会随发行版更新，因此本页保留原书目录身份，并要求实验记录实际Ubuntu版本；现代差异只能作为显式对照，不能悄悄改写原书。

本页不变量是：**变量引用安全、输入经过验证、错误状态可传播、临时资源有清理钩子，同一输入能重放。**。它在正常命令、权限拒绝、依赖缺失、网络超时和中断恢复中都必须成立。命令退出为零只是一个样本，不代表执行身份正确、文件树无污染、配置可重建或下一次运行仍然幂等。

最小实验：以固定随机序列实现两个小游戏，记录输入、随机值、分支和退出码，并为边界输入编写自动测试。 每一步先写预期，再记录命令文本、当前目录、用户与组、标准输出/错误、退出码和前后状态差异。对需要管理员权限的操作，说明为何需要提权以及最小授权范围。

故障实验：注入空变量、非数字输入、命令失败和中断信号，检查strict mode与trap清理。 删除故障后应从干净快照或明确逆操作恢复，以完全相同的输入重放。若表面结果恢复但包数据库、账户文件、路由、挂载、临时文件或后台进程仍不同，就不能判定通过。

所有破坏性练习都应在可丢弃虚拟机、临时目录或隔离网络中进行。不要在生产主机复制删除、账户、包管理、网络或服务命令；实验安全边界本身也是本章知识的一部分。

## 最小可重放骨架

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
trap 'printf "failed at line %s\n" "$LINENO" >&2' ERR
workspace="$(mktemp -d)"
trap 'rm -rf "$workspace"' EXIT
printf 'stage=%s workspace=%s\n' "声明解释器" "$workspace"
```

```text
baseline: Ubuntu version + package index + user identity + file tree + network state
prediction: command + expected exit code + expected side effects
observation: stdout + stderr + exit code + state diff
recovery: reverse command or clean snapshot + identical input replay
```

run_case() {
  name="$1"
  shift
  printf 'CASE %s\n' "$name"
  "$@"
  status=$?
  printf 'STATUS %s %s\n' "$name" "$status"
  return "$status"
}

<Callout type="trap">
  **误区一：命令没有报错就代表任务正确。**
  命令可能以错误用户执行、修改了意外路径、吞掉管道前段失败或留下半配置状态，必须检查退出码和前后状态差异。

## 四类样本与验收

| 样本 | 注入方式                     | 必查证据                 | 通过条件     |
| ---- | ---------------------------- | ------------------------ | ------------ |
| 正常 | 固定快照、身份和输入         | 命令、退出码、状态差异   | 与预测一致   |
| 边界 | 空文件、极限配额、无匹配输入 | 引用、终止和副作用       | 不越界不误删 |
| 失败 | 权限拒绝、缺依赖、网络超时   | 首错命令与责任层         | 失败被隔离   |
| 恢复 | 逆操作或快照后重放           | 文件、账户、包、网络状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看最终终端输出验收第7章 Shell 编程？

<Answer>
  输出可能隐藏错误身份、路径、权限、依赖和残留副作用。必须比较退出码、标准错误、状态差异和恢复后的同输入重放。
</Answer>

**问题 2** 如何把“第7章 Shell 编程”变成可执行证据？

<Answer>
  沿“声明解释器、读取校验输入、展开变量、执行分支循环、调用函数脚本、检查状态并清理”固定Ubuntu快照和输入，只改变一个条件，保存首错；恢复后比较身份、文件、包、网络或项目状态。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  变量引用安全、输入经过验证、错误状态可传播、临时资源有清理钩子，同一输入能重放。
  失败路径不得污染后续实验，逆操作明确，同一输入可以重新到达基线。
</Answer>

</Exercises>

## 小结

- shebang：连接“声明解释器”的命令契约。
- Shell变量：连接“读取校验输入”的身份权限。
- 条件与循环：连接“展开变量”的状态变化。
- Shell函数：连接“执行分支循环”的输出证据。
- 脚本调用：连接“调用函数脚本”的失败恢复。
- 本页13个目录坐标全部进入实战链，不以泛化运维主题替代原书内容。
