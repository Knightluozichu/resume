## 为什么脚本会在第 3 行而不是第 17 行失败

把几行命令写进文件再执行，和逐行敲进终端，表面看起来都是“出现结果”。但脚本一旦失败，真正的问题往往不在最后那行输出，而在更早的某个命令已经返回了非零状态、某个变量已经为空、或者某个临时目录已经没清理。

Shell 编程的核心不是背诵语法，而是把一段脚本拆成可观察的链：谁解释这行、谁展开变量、谁在什么条件下分支、失败时停在哪里、退出后留下什么。只有每一点都有证据，才能说脚本“跑通了”。

## 从 shebang 到退出码：脚本的七步链

本章范围依据出版社目录中的第 7 章 13 个层级节点，技术解释独立依据 GNU Bash 手册、GNU Coreutils 与 Ubuntu 官方文档重写。示例面向 Ubuntu 中的 Bash；浏览器中的实验只计算固定教学案例，不会在你的电脑上执行命令。

### shebang 与解释器选择

<Term def="脚本首行以 #! 开头的标记，告诉系统用哪个解释器执行本文件">
  shebang
</Term>
是脚本与系统的第一个契约。`#!/usr/bin/env bash` 表示“在 PATH 里找 bash”，比写死
`/bin/bash` 更适应不同发行版。没有 shebang 时，直接 `./script.sh` 可能用当前
Shell 解释，行为不可预期。

```bash
#!/usr/bin/env bash
printf '%s\n' "script starts"
```

### 执行权限与启动方式

脚本需要可读，直接执行还需要可执行权限。两种常见启动方式不等价：

- `./script.sh`：按 shebang 启动新进程执行。
- `bash script.sh`：明确用 bash 读取，不要求可执行权限，但会忽略 shebang 里指定的其他解释器。

```bash
chmod +x script.sh
./script.sh
bash script.sh
```

<Term def="命令或脚本结束后交回 Shell 的整数；0 通常表示成功，非零含义由命令约定">
  退出状态
</Term>
用 `$?` 读取。它只代表最近一条命令，必须立即保存，否则会被下一条覆盖。

### 变量与变量展开

<Term def="Shell 把 $name 替换为变量值的过程；引号会改变展开时机与边界">
  变量展开
</Term>
是脚本出错的高发区。赋值时 `=`
两侧不能有空格；引用时双引号保留整体但允许展开，单引号保留字面量。

```bash
name="report one.txt"
printf '%s\n' "$name"   # 一个参数：report one.txt
printf '%s\n' $name     # 两个参数：report 与 one.txt
```

未引用变量进入 `rm $name` 这类命令，可能把单个文件名拆成多个路径，造成误删。本章实验用只读模型演示，不在你的机器上执行删除。

### 语句：分支与循环

`if` 判断的是命令的退出状态，不是字符串的“真假”。`while`/`for` 的循环条件也依赖退出状态。`case` 适合多路匹配。

```bash
if [[ -z "$guess" ]]; then
  echo "empty input" >&2
  exit 1
fi

for f in "$workspace"/*.txt; do
  [[ -e "$f" ]] || continue
  printf 'processing %s\n' "$f"
done
```

### 函数与脚本调用

<Term def="把一段命令命名并接收参数；函数内的局部变量用 local 声明，避免污染调用者">
  函数
</Term>
让脚本可分层。调用时像普通命令一样写参数，函数内部用 `$1`、`$2` 接收。

```bash
check_guess() {
  local g=$1
  if (( g == secret )); then echo "命中！"
  elif (( g < secret )); then echo "太小"
  else echo "太大"; fi
}

check_guess "$guess"
```

脚本之间可以嵌套调用：被调用脚本以新进程执行，变量互不干扰；用 `source other.sh` 则是在当前 Shell 执行，会共享变量与当前目录。

### strict mode 与 trap 清理

<Term def="Bash 选项组合 set -euo pipefail，让命令失败、未定义变量和管道错误立即暴露">
  strict mode
</Term>
不是万能保险，但它能把“悄悄失败”变成“立即报错”。配合
<Term def="在信号或退出时执行指定命令；常用于删除临时目录或恢复状态">trap</Term>
，可以在脚本无论成功还是失败退出时都执行清理。

```bash
set -euo pipefail
workspace=$(mktemp -d)
trap 'rm -rf "$workspace"' EXIT
```

`trap` 的清理命令也要用引号保护变量；否则在定义时就展开，可能指向空字符串或错误路径。本章所有删除操作只在可丢弃环境中演示，网页模型不会访问真实文件系统。

### 从目录节点到执行链

本章的 13 个目录节点可以翻译成上面七步链中的具体行为。7.1 Shell 脚本介绍回答的是“为什么把命令写成文件”；7.2 Shell 脚本的基本语法是后续所有脚本的基础。脚本的开头由 shebang 决定；脚本的执行依赖执行权限与启动方式；变量、语句、函数与脚本调用则分别对应变量展开、分支循环、函数封装和脚本间嵌套调用。Shell 编程应用通过猜数字游戏和石头、剪刀、布游戏把分支、函数、随机数与输入校验组合起来。7.4 本章小结再把这些点回收为可检查的目标。

## 代码对照：整块逻辑 vs 函数

下面两段实现同一个猜数字判断。左边把所有逻辑堆在主流程，右边把判断封装成函数。函数不是为了让代码变长，而是让“比较逻辑”可以被单独验证和复用。

<CodeTabs>
<Tab label="主流程">

```bash
#!/usr/bin/env bash
set -euo pipefail
read -r guess
secret=42

if (( guess == secret )); then
  echo "命中！"
elif (( guess < secret )); then
  echo "太小"
else
  echo "太大"
fi
```

</Tab>
<Tab label="函数版">

```bash
#!/usr/bin/env bash
set -euo pipefail
read -r guess
secret=42

check_guess() {
  local g=$1
  if (( g == secret )); then echo "命中！"
  elif (( g < secret )); then echo "太小"
  else echo "太大"; fi
}

check_guess "$guess"
```

</Tab>
</CodeTabs>

函数版多了一层调用，但 `check_guess` 可以在脚本别处复用，也更容易用不同输入单独测试。注意调用时必须加 `"$guess"` 引号，否则函数内部收到的 `$1` 可能被空格拆分。

## 常见误区

<Callout type="trap" title="把 $ 后面的变量名当字符串处理">

**现象 →** `echo $filename` 遇到带空格的文件名时输出被拆成两段。 **原因 →**
变量展开后 Shell 会再次分词；不是 echo 把文件名拆开。 **修法 →**
引用变量 `"$filename"`，在实验中观察 argv 槽位变化。

</Callout>

<Callout type="trap" title="以为 exit 0 就证明前面都成功">

**现象 →** 脚本最后打印成功，但中间某个 `cp` 其实失败了。 **原因 →**
没有 `set -e` 时，单个命令失败不会终止脚本；最后一条命令的成功会掩盖前面的失败。 **修法 →**
关键操作后立即保存 `$?`，或开启 strict mode 并用 `||` 显式处理。

</Callout>

<Callout type="trap" title="trap 里的变量没加引号">

**现象 →** 临时目录有时删不掉。 **原因 →**
`trap 'rm -rf $workspace' EXIT` 中的 `$workspace` 在 trap 定义时就展开，若当时为空，命令会变成 `rm -rf ` 或错误路径。 **修法 →**
用单引号包裹 trap 命令体，让变量在退出时才展开。

</Callout>

<Exercises>

**问题 1：** 修改脚本配置并定位失败层

在实验中选择“空输入”，先开启 strict mode 和输入校验，预测结果并单步走完。再关闭输入校验、保持 strict mode，重新预测并走完。两次失败分别发生在哪一步？stderr 是谁产生的？用完整 Reset 检查是否恢复初始状态。

<Answer>

第一次（校验开）：失败发生在 validate 步；stderr 是校验块自己输出的“输入校验：guess 为空字符串”，退出状态 1；trap 若开启仍会清理 workspace。第二次（校验关）：失败发生在 branch 步；stderr 是 Bash 算术表达式报的操作数错误，`(( < 42 ))` 无法对空值求值；这是运行时错误而非校验失败。完整 Reset 后 strict/校验/函数/trap 全部恢复默认开启，输入恢复“正常”，预测清空，时间线回到第 1 步并暂停。

</Answer>

**问题 2：** 把主流程改成函数并验证参数边界

把下面主流程改写为 `check_guess` 函数，要求函数接收一个参数并在内部用 `local` 声明变量。写出调用语句，并说明如果调用时写成 `check_guess $guess` 且 `guess` 是 `report one.txt`，函数内部 `$1` 会是什么。

```bash
if (( guess == secret )); then echo "命中！"
elif (( guess < secret )); then echo "太小"
else echo "太大"; fi
```

<Answer>

```bash
check_guess() {
  local g=$1
  if (( g == secret )); then echo "命中！"
  elif (( g < secret )); then echo "太小"
  else echo "太大"; fi
}

check_guess "$guess"
```

如果调用写成 `check_guess $guess`，`report one.txt` 会被拆成两个参数：`$1` 是 `report`，`$2` 是 `one.txt`。函数内部 `local g=$1` 只拿到 `report`，比较会失败或报操作数错误。必须用 `"$guess"` 把含空格的字符串作为单个参数传入。

</Answer>

**问题 3：** 设计一个可重放的石头剪刀布脚本

要求：脚本随机选择“石头/剪刀/布”并与用户输入比较；使用函数判断胜负；对非预期输入给出明确错误并退出 1；在退出前清理临时目录。写出脚本骨架（不超过 30 行的核心部分），并说明随机数来源为什么要固定种子或作为外部输入。

<Answer>

```bash
#!/usr/bin/env bash
set -euo pipefail
workspace=$(mktemp -d)
trap 'rm -rf "$workspace"' EXIT

items=(石头 剪刀 布)
# 教学演示：用固定种子让结果可重放
RANDOM=12345
computer=${items[RANDOM % 3]}
read -r user
judge() {
  local a=$1 b=$2
  [[ "$a" == "$b" ]] && { echo 平局; return; }
  case "${a}-${b}" in
    石头-剪刀|剪刀-布|布-石头) echo 你赢 ;;
    *) echo 电脑赢 ;;
  esac
}
[[ " ${items[*]} " =~ " $user " ]] || { echo "请输入：石头、剪刀或布" >&2; exit 1; }
judge "$user" "$computer"
```

固定 `RANDOM=12345` 让每次运行得到相同序列，便于核对胜负逻辑；生产环境可改用 `/dev/urandom` 或命令行传入种子。`trap` 用单引号保证 `$workspace` 在退出时展开；校验失败时 `exit 1` 仍会触发 trap 清理。

</Answer>

</Exercises>

## 小结

- shebang 决定脚本由哪个解释器执行；执行权限与启动方式影响变量环境。
- 变量展开在引号内外行为不同；未引用是脚本边界错误的主要来源。
- `if`/`while`/`for`/`case` 与函数让流程可分层；函数调用要引用实参。
- strict mode 把“悄悄失败”变成“立即报错”；trap 负责无论成败都清理。
- 退出状态只反映最近命令；必须立即保存或配合 `-e`/`pipefail` 使用。
