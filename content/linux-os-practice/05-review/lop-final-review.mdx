## 直觉引入

假设老板给你一台新装的 Ubuntu 服务器说「把它弄上线」。你要做的不是敲一个命令，而是走完一条完整的链路：先 SSH 登录（命令行基础），检查和配置文件权限（文件权限），创建运维用户并禁用 root 登录（用户管理），更新系统并安装服务（包管理），配置网络 IP（网络配置），设置防火墙只开必要端口（防火墙安全），让服务开机自启（systemd 服务），最后写脚本自动备份和监控（Shell 脚本）。八章知识串成一条线——这就是全书的总复习。

## 一台服务器从装好到上线

```bash
# ===== 第1步：命令行基础（第1章）=====
# SSH 登录服务器
ssh deploy@192.168.1.10
# 熟悉终端操作：ls/cd/cp/rm/grep/cat/管道重定向
ls -la /etc/
cat /etc/os-release | grep VERSION

# ===== 第2步：文件权限（第2章）=====
# 检查关键文件权限
ls -l /etc/ssh/sshd_config      # 应为 -rw-r--r-- (644)
ls -l ~/.ssh/                    # 应为 drwx------ (700)
ls -l ~/.ssh/authorized_keys    # 应为 -rw------- (600)
# 修正权限
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

# ===== 第3步：用户管理（第3章）=====
# 创建运维用户（如果还没有）
sudo useradd -m -s /bin/bash ops
sudo usermod -aG sudo ops
# 配置 SSH 密钥
ssh-copy-id ops@192.168.1.10
# 禁用 root 密码登录
sudo vim /etc/ssh/sshd_config
#   PermitRootLogin no
#   PasswordAuthentication no
sudo systemctl restart sshd

# ===== 第4步：包管理（第4章）=====
# 更新系统
sudo apt update && sudo apt upgrade -y
# 安装 Web 服务
sudo apt install nginx -y
# 验证
nginx -v

# ===== 第5步：网络配置（第5章）=====
# 检查网络
ip addr show
ip route show
# 如果需要固定IP
sudo vim /etc/netplan/01-netcfg.yaml
#   ethernets:
#     eth0:
#       addresses: [192.168.1.10/24]
#       gateway4: 192.168.1.1
#       nameservers: [8.8.8.8, 1.1.1.1]
sudo netplan apply

# ===== 第6步：防火墙安全（第6章）=====
# 配置防火墙（默认拒绝！）
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp       # SSH
sudo ufw allow 80/tcp       # HTTP
sudo ufw allow 443/tcp      # HTTPS
sudo ufw enable
sudo ufw status verbose

# ===== 第7步：systemd 服务（第7章）=====
# 启动 nginx 并设开机自启
sudo systemctl enable --now nginx
systemctl status nginx
# 测试
curl -I http://localhost

# ===== 第8步：Shell 脚本（第8章）=====
# 编写自动化备份脚本
cat > /opt/scripts/backup-nginx.sh << 'EOF'
#!/bin/bash
set -euo pipefail
BACKUP_DIR="/backup/$(date +%Y%m%d)"
mkdir -p "$BACKUP_DIR"
tar czf "$BACKUP_DIR/nginx-conf.tar.gz" /etc/nginx/
tar czf "$BACKUP_DIR/nginx-logs.tar.gz" /var/log/nginx/
echo "[$(date)] backup complete: $BACKUP_DIR"
EOF
sudo chmod +x /opt/scripts/backup-nginx.sh
# 设置定时任务（每天凌晨3点备份）
echo '0 3 * * * /opt/scripts/backup-nginx.sh >> /var/log/backup.log 2>&1' | sudo crontab -

# ===== 上线完成 =====
echo "Server is ready!"
```

## 权限系统的三层安全防线

全书从第 2 章到第 3 章构建了 Linux 安全的三层防线：

```text
第一层：文件权限（rwx/UGO/ACL）
  └─ 控制谁能读写执行哪些文件
  └─ 内核比对进程 UID/GID 与文件属主/属组
  └─ chmod 755 / setfacl -m u:alice:rw

第二层：用户管理（UID/组/sudoers）
  └─ 控制系统里有谁、属于哪些组
  └─ useradd 创建用户 / usermod -aG 管理组
  └─ 不同用户通过组获得不同文件访问权限

第三层：sudo 提权（最小权限原则）
  └─ 控制谁能临时获得 root 权限
  └─ 平时普通用户操作，需要时 sudo 提权
  └─ /etc/sudoers 限制可执行的命令
  └─ 日志审计：/var/log/auth.log

三层协作：文件权限做基础隔离 → 用户/组做身份分组 → sudo 做提权审计
```

## 服务故障排查链路

```bash
# 当服务起不来或访问不了时，按此链路排查：

# 1. systemd 层：服务状态
systemctl status nginx           # 状态是 failed 还是 inactive？
journalctl -u nginx -n 50       # 看错误日志
# 常见问题：配置文件语法错、ExecStart 路径错、权限不足

# 2. 文件权限层：配置和目录权限
ls -l /etc/nginx/nginx.conf     # nginx 用户能否读取？
ls -ld /var/www/html            # nginx 用户能否进入？
# 常见问题：配置文件属主不对、webroot 不可读

# 3. 网络层：IP 和路由
ip addr show                    # IP 配置是否正确？
ip route show                   # 有默认网关吗？
ping <client-ip>                # 能否到达客户端？

# 4. 防火墙层：端口是否放行
sudo ufw status                 # 80/443 端口是否 allow？
sudo iptables -L -n             # 规则是否正确？
ss -tlnp | grep 80              # nginx 是否在监听 80？

# 5. 包管理层：软件是否完整
dpkg -l nginx                   # 包是否正确安装？
nginx -t                        # 配置测试
```

<Callout type="trap">
**误区：自动化就是写脚本。** 自动化运维的终极目标不是「写很多脚本」，而是「让系统自运转」——systemd 保证服务持续运行（崩溃自动重启、开机自动启动），Shell 脚本+crontab 处理周期性维护（备份、清理、监控），两者互补。更进一步用 Ansible 做多机批量部署，用 Prometheus+Grafana 做监控告警。但底层都是 Linux 运维基础知识：你得先懂命令行、权限、网络、服务管理，才能写出可靠的自动化方案。先理解手动操作，再自动化——否则脚本里的错误你排查不了。
</Callout>

**问题 1**：用「一台服务器从装好到上线」描述全书主线，列出八个步骤。

<Answer>
①命令行基础——终端操作 ls/cd/grep/管道重定向；②文件权限——rwx/UGO/chmod/setfacl 控制访问；③用户管理——useradd 创建用户、sudo 提权、SSH 密钥；④包管理——apt install nginx 安装服务；⑤网络配置——ip addr/netplan 配置 IP 和网关；⑥防火墙安全——ufw allow 22 放行 SSH、deny 3306 拒绝 MySQL 外网；⑦systemd 服务——systemctl enable nginx 开机自启；⑧Shell 脚本——自动化备份、日志清理、监控。八步串成从裸机到生产级运维的完整链路。
</Answer>

**问题 2**：权限系统的三层安全防线如何协作？服务起不来如何系统排查？

<Answer>
三层防线：①文件权限（rwx/UGO/ACL）控制谁能访问什么文件；②用户管理（UID/组）控制系统里有谁、属于哪些组；③sudo 提权控制谁能临时获得 root 权限，遵循最小权限+审计。协作：文件权限做基础隔离，用户/组做身份分组，sudo 做提权审计。排查链路：systemctl status → journalctl 日志 → 文件权限检查 → 网络配置(ip addr/route) → 防火墙(ufw status) → 端口监听(ss -tlnp)。八章知识形成完整排查链。
</Answer>
