## 核心机制深挖

以俄罗斯方块项目贯通背景、需求、功能设计、软件框架、终端核心技术、代码逻辑与最终效果。 原书以2021年前后的Ubuntu和嵌入式开发辅助环境为对象。命令、包版本、网络配置界面和工具输出会随发行版更新，因此本页保留原书目录身份，并要求实验记录实际Ubuntu版本；现代差异只能作为显式对照，不能悄悄改写原书。

本页不变量是：**方块占用不越界不重叠，旋转和下落可预测，锁定/消行/计分状态转换只发生一次。**。它在正常命令、权限拒绝、依赖缺失、网络超时和中断恢复中都必须成立。命令退出为零只是一个样本，不代表执行身份正确、文件树无污染、配置可重建或下一次运行仍然幂等。

最小实验：用固定方块序列和按键时间线运行一局，保存每拍棋盘哈希、分数和终局结果并重放。 每一步先写预期，再记录命令文本、当前目录、用户与组、标准输出/错误、退出码和前后状态差异。对需要管理员权限的操作，说明为何需要提权以及最小授权范围。

故障实验：注入边界旋转、连续快速输入、满行连消和终端尺寸变化，定位状态机与绘制分叉。 删除故障后应从干净快照或明确逆操作恢复，以完全相同的输入重放。若表面结果恢复但包数据库、账户文件、路由、挂载、临时文件或后台进程仍不同，就不能判定通过。

所有破坏性练习都应在可丢弃虚拟机、临时目录或隔离网络中进行。不要在生产主机复制删除、账户、包管理、网络或服务命令；实验安全边界本身也是本章知识的一部分。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：命令没有报错就代表任务正确。**
  命令可能以错误用户执行、修改了意外路径、吞掉管道前段失败或留下半配置状态，必须检查退出码和前后状态差异。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                     | 必查证据                 | 通过条件     |
| ---- | ---------------------------- | ------------------------ | ------------ |
| 正常 | 固定快照、身份和输入         | 命令、退出码、状态差异   | 与预测一致   |
| 边界 | 空文件、极限配额、无匹配输入 | 引用、终止和副作用       | 不越界不误删 |
| 失败 | 权限拒绝、缺依赖、网络超时   | 首错命令与责任层         | 失败被隔离   |
| 恢复 | 逆操作或快照后重放           | 文件、账户、包、网络状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看最终终端输出验收第9章 项目实战：俄罗斯方块游戏？

<Answer>
  输出可能隐藏错误身份、路径、权限、依赖和残留副作用。必须比较退出码、标准错误、状态差异和恢复后的同输入重放。
</Answer>

**问题 2** 如何把“第9章 项目实战：俄罗斯方块游戏”变成可执行证据？

<Answer>
  沿“冻结需求规则、设计棋盘与方块、解析输入时钟、检测移动旋转、消行计分绘制、重放并验收”固定Ubuntu快照和输入，只改变一个条件，保存首错；恢复后比较身份、文件、包、网络或项目状态。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  方块占用不越界不重叠，旋转和下落可预测，锁定/消行/计分状态转换只发生一次。
  失败路径不得污染后续实验，逆操作明确，同一输入可以重新到达基线。
</Answer>

</Exercises>

## 小结

- 需求分析：连接“冻结需求规则”的命令契约。
- 棋盘模型：连接“设计棋盘与方块”的身份权限。
- 方块旋转：连接“解析输入时钟”的状态变化。
- 游戏循环：连接“检测移动旋转”的输出证据。
- 项目验收：连接“消行计分绘制”的失败恢复。
- 本页12个目录坐标全部进入实战链，不以泛化运维主题替代原书内容。
