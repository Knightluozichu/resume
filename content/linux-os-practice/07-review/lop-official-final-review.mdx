## 核心机制深挖

用可重建Ubuntu实验机和可重放俄罗斯方块项目串联身份、文件、软件包、编译调试、网络服务、Shell与正则证据。 原书以2021年前后的Ubuntu和嵌入式开发辅助环境为对象。命令、包版本、网络配置界面和工具输出会随发行版更新，因此本页保留原书目录身份，并要求实验记录实际Ubuntu版本；现代差异只能作为显式对照，不能悄悄改写原书。

本页不变量是：**所有命令有预期退出码和副作用，配置可恢复，服务端到端可验证，项目在固定输入下得到相同状态轨迹。**。它在正常命令、权限拒绝、依赖缺失、网络超时和中断恢复中都必须成立。命令退出为零只是一个样本，不代表执行身份正确、文件树无污染、配置可重建或下一次运行仍然幂等。

最小实验：从干净快照自动重建全书环境，运行网络与脚本测试，最后重放固定俄罗斯方块输入。 每一步先写预期，再记录命令文本、当前目录、用户与组、标准输出/错误、退出码和前后状态差异。对需要管理员权限的操作，说明为何需要提权以及最小授权范围。

故障实验：删除依赖、撤销权限、破坏DNS并中断脚本，确认诊断能定位首因且恢复不会隐藏残留状态。 删除故障后应从干净快照或明确逆操作恢复，以完全相同的输入重放。若表面结果恢复但包数据库、账户文件、路由、挂载、临时文件或后台进程仍不同，就不能判定通过。

所有破坏性练习都应在可丢弃虚拟机、临时目录或隔离网络中进行。不要在生产主机复制删除、账户、包管理、网络或服务命令；实验安全边界本身也是本章知识的一部分。

## 最小可重放骨架

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
trap 'printf "failed at line %s\n" "$LINENO" >&2' ERR
workspace="$(mktemp -d)"
trap 'rm -rf "$workspace"' EXIT
printf 'stage=%s workspace=%s\n' "恢复干净快照" "$workspace"
```

```text
baseline: Ubuntu version + package index + user identity + file tree + network state
prediction: command + expected exit code + expected side effects
observation: stdout + stderr + exit code + state diff
recovery: reverse command or clean snapshot + identical input replay
```

```bash
run_case() {
  name="$1"
  shift
  printf 'CASE %s\n' "$name"
  "$@"
  status=$?
  printf 'STATUS %s %s\n' "$name" "$status"
  return "$status"
}
```
