## 为什么从这个应用任务开始

把书中的入门程序搬进服务，就像让工厂试制线接正式订单：送出订单、收到第一件半成品、完成整批验收不是一回事。只看“有结果”会把中途失败当成完成。

本章把这条线拆成三件事：读懂收发内容、决定失败后等多久再试、发出前检查容量和费用。每次先预测，再操作，最后说明哪条边界阻止了交付。

### 2.5.1 ChatCompletion端点的输入选项

**公开坐标 9/22。** <Term def="Chat Completions请求中承载角色和内容的消息列表。">messages</Term>：Chat Completions请求中承载角色和内容的消息列表。 角色和内容共同组成对话输入，模型标识另行选择；采样、输出上限和工具参数须逐项核对所选模型支持情况。迁移到 Responses 时按迁移指南构造 input，而不是只更换 URL。实验①会同时改变路径和请求体，避免“旧参数永久通用”的假设。

### 2.5.2 ChatCompletion端点的输出格式

**公开坐标 10/22。** <Term def="将响应按事件陆续交付，而不是一次性返回完整结果。">流式响应</Term>：将响应按事件陆续交付，而不是一次性返回完整结果。 非流式 Chat Completions 文本通常从 choices 中的 message 读取；流式文本使用 delta 增量，不能逐帧按完整 message 解析。Responses 使用带类型的事件，示例关注 response.output_text.delta 与 response.completed。实验①省略其他事件，不把一个事件或网络分块等同于一个 token。

### 2.5.3 从文本补全到函数

**公开坐标 11/22。** 文本补全生成文字；<Term def="模型提出结构化工具请求，应用验证并执行后再回传结果的机制。">函数调用</Term>则产生工具名和参数，应用还要校验模式、用户身份、允许工具、业务策略和幂等条件，再执行并回传结果。参数能解析不是授权，实验①“传输完整”也不自动执行工具；下方对照表列出这个独立分支。

### 2.6 使用其他文本补全模型

**公开坐标 12/22。** <Term def="根据给定文本前缀继续生成内容的接口形态。">文本补全</Term>：根据给定文本前缀继续生成内容的接口形态。 原书另列 Completion，是为了区分“续写 prompt”和“按角色组织 messages”。保留这条历史坐标，不保证旧模型今天仍可调用；迁移测试应保存当时输入输出样本。下表将两种文本解析路径与 Responses 并列。

### 2.6.1 Completion端点的输入选项

**公开坐标 13/22。** 旧 Completion 围绕 <Term def="旧文本补全接口用于续写的输入文本或相应输入结构。">prompt</Term> 构造请求，而不是把 messages 原样搬过去。输出限制与采样参数须按当时端点、模型和 SDK 文档复现；本页不臆造原书参数默认值。对照表与实验①共同说明：请求模式与解析器必须成对迁移。

### 2.6.2 Completion端点的输出格式

**公开坐标 14/22。** 旧文本补全的典型文本路径是 <Term def="补全类接口组织候选结果的列表，不是所有API都共有的响应字段。">choices</Term>[0].text，Chat Completions 非流式文本路径则是 choices[0].message.content；流式分支又不同。Responses 返回 output 项，Python SDK 的 output_text 是便捷取文本属性，不应假定原始 HTTP JSON 必有同名字段。见下方对照表。

### 2.7 考虑因素

**公开坐标 15/22。** <Term def="按凭证、输入、配额、临时限流或服务异常决定下一步处理。">错误分类</Term>：按凭证、输入、配额、临时限流或服务异常决定下一步处理。 要把失败变成可测试类型：401 先修凭证，错误输入先修请求；429 还须区分临时速率限制与配额不足，不能只看数字就重试。临时限流或部分服务异常可以有限重试，并记录尝试次数、等待和终止原因。实验②提供这些分支，不声称覆盖所有错误码。

### 2.7.1 定价和标记限制

**公开坐标 16/22。** <Term def="按分词单位估算输入、输出预留和上下文容量，并独立限制费用。">token 预算</Term>：按分词单位估算输入、输出预留和上下文容量，并独立限制费用。 定价和标记限制关心的是容量与成本，不是真实性判断。输入应包含规则、历史、工具定义和本轮内容；输出预留不是已消费输出。实验③以输入加预留检查窗口，再按虚构单价估算费用；真实模型还需核对最大输出、推理 token、缓存、工具费用及服务端 usage。

### 2.7.2 安全和隐私

**公开坐标 17/22。** <Term def="服务对输入、输出和相关记录的保存范围与时长。">数据保留</Term>：服务对输入、输出和相关记录的保存范围与时长。 调用前限制秘密、个人数据、权限与预算；成功响应仍需遵守数据政策。现行数据控制要按端点、账户配置与适用条件核对，不能把“不用于训练”解释成“完全不存储”，也不能回填成原书当时政策。实验③只检查预算，不代替数据权限或动作授权。

## 从请求到结果：代码与合同对照

以下是接口形态对照，不是对原书代码的逐字复现。**旧 SDK 的类名不等于 HTTP 端点名称**，也不能据此推断现行 Chat Completions 已停用。

| 接口坐标         | 请求主体   | 非流式文本读取                                           | 流式/工具分支                                             |
| ---------------- | ---------- | -------------------------------------------------------- | --------------------------------------------------------- |
| 历史 Completion  | `prompt`   | `choices[0].text`（有文本候选时）                        | 按历史环境复现，不承诺旧模型可用                          |
| Chat Completions | `messages` | `choices[0].message.content`（文本消息时）               | 文本增量读取 `choices[0].delta.content`；工具调用另行处理 |
| Responses        | `input`    | 解析 `output` 项；Python SDK 提供 `output_text` 便捷属性 | 按事件类型处理；工具调用由应用验证执行后回传              |

现行服务端 Python 主路径如下。事先安装并锁定兼容版本的 `openai` 包，配置服务端 `OPENAI_API_KEY` 与账户可用的 `OPENAI_MODEL`。此例不声称特定模型可用，也不包含完整生产异常处理。

```python
import os
from openai import OpenAI

client = OpenAI()  # 从服务端环境读取 OPENAI_API_KEY
response = client.responses.create(
    model=os.environ["OPENAI_MODEL"],
    input="用一句话问好。",
)
print(response.output_text)  # SDK 便捷属性，不是所有接口共有字段
```

创建客户端解决身份与连接配置，`responses.create` 选择接口及其 `input` 模式，最后一行只取文本便捷视图。处理工具、拒绝或未完成状态时还须检查完整响应，不能把空文本当成功。若另加实验②的重试策略，还须核对 SDK 自带重试，避免两层策略叠加；实验仅模拟应用策略。

| 辅助 API                 | 输入 → 输出                 | 验证证据与不可替代的边界                   |
| ------------------------ | --------------------------- | ------------------------------------------ |
| 嵌入                     | 内容 → 数值向量             | 模型、维度、距离、检索评测；相似不等于真实 |
| 内容审核                 | 待审核内容 → 安全类别等判断 | 类别、阈值、人工升级；不是用户授权         |
| 语音识别（原书 Whisper） | 音频 → 转写文本             | 来源、使用权限、抽样听校；转写可能错误     |
| 图像生成（原书 DALL·E）  | 提示等受支持输入 → 图像结果 | 内容复核、使用权限；不是事实照片证明       |

</Callout>

### 实验①：请求合同与流式帧

预测首段文本出现时是否可交付。推进正常路径的 5 个事件，观察“你好”到“你好，世界”的缓冲区；再注入断流，检查已经显示的文本为什么不能当完整结果。切换 Responses / Chat Completions，观察路径、请求体和帧字段一起变化；错配解析器会在第一个文本增量失败。选择“正常”重放，或重置回 Responses、第 0 帧。

## 常见误区

<Callout type="trap" title="HTTP 200 或显示了文本，就算完成？">
  **现象 →** 断流后把“你好”当完整回答。**原因 →**
  把HTTP成功与流结束混在一起。**修法 →**
  在实验①注入断流，保留局部文本为未完成状态，核对完成事件并校验内容后才交付。
</Callout>

<Callout type="trap" title="只看429，就一直重试？">
  **现象 →** 配额不足时不断发送。**原因 →** 未分类错误，也未限制重试次数。**修法
  →**
  在实验②对比临时限流和配额不足；前者退避且有限重试，后者先修配额。含副作用的动作另核对幂等，不能盲目重放。
</Callout>

<Callout type="trap" title="结构和预算通过，就有执行权限？">
  **现象 →** 工具参数能解析或预算通过后立即执行。**原因 →**
  把模式/容量检查当业务授权。**修法 →**
  独立核对用户身份、允许工具、业务策略和人工确认；密钥只放服务端，泄漏后必须撤销或轮换。
</Callout>

<Callout type="trap" title="把现代接口倒填原书？">
  **现象 →** 将Responses字段、当前模型或价格说成原书内容。**原因 →**
  混淆目录坐标、SDK版本与现行接口。**修法 →**
  分开保存历史样本和迁移测试；用现行文档核对当前事实，不声称旧choices结构通用于所有端点。
</Callout>

## 可重放应用协议

| 实验        | 固定输入/基线                                      | 必留证据                                   | 拒绝条件与恢复                                   |
| ----------- | -------------------------------------------------- | ------------------------------------------ | ------------------------------------------------ |
| 请求/流式帧 | 问好任务、Responses、正常、第0帧                   | 端点、请求模式、事件顺序、缓冲区、完成状态 | 解析器错配或断流时拒绝完整交付；修复后重放       |
| 有限重试    | 临时429、基础500ms、无Retry-After下限、无抖动、0次 | 状态码与类别、尝试数、起点、等待、停止原因 | 401/配额型429立即停止；503耗尽后失败；修因再请求 |
| 预算准入    | 历史1024、输出1024、费用上限8                      | 输入2176、预留总量3200、估算费用5.248      | 窗口或费用超限时本地拒绝；缩短历史或调整预算     |

运行记录还应包括环境变量名称（不含密钥值）、接口适配器版本、模型标识、输入输出模式、请求标识、实际用量、数据保留决策和迁移测试。模拟器不替应用生成这些生产证据。各实验独立重置，不保留上一次故障；没有完成状态的文本不能偷偷并入下一次重试结果。

## 小结

- 区分旧SDK、Chat Completions与Responses
- 密钥只在服务端，接口版本与模型快照可追溯
- 请求与响应经模式校验，错误响应不能进入业务流程
- 费用、数据和错误路径受限，成功响应不能绕过治理
- 辅助API（嵌入、审核、语音图像）各自有数据与错误边界

## 练习与答案

<Exercises>

1. **预测—操作—解释：流式故障。** 正常轨迹推进到 HTTP 200 后，能交付吗？注入“首段文本后断流”，再切换“误用另一接口的流式解析器”，分别记录缓冲区、失败位置和恢复方法。为什么不能统一读取 `choices[0].message.content`？

<Answer>
  HTTP 200
  后缓冲区仍为空，不能判定流完成。断流轨迹共4个事件，第3个事件形成“你好”，第4个事件中断，必须保留未完成标记；解析器错配在第3个事件失败，缓冲区为空。非流式Chat
  Completions的message、流式delta与Responses类型化事件不同。选择正确接口和解析器，撤销故障重放正常5个事件，才得到“你好，世界”及传输完成状态；内容验证和工具授权仍是后续步骤。重置回到Responses、正常、第0帧。
</Answer>

2. **计算并复现：退避起点。** 默认临时限流下三次请求何时开始、何时结束？把模拟 Retry-After 调成1000ms后再算。切到401、配额型429、持续503，哪个分支应立即停止？

<Answer>
  默认起点为0、700、1900ms，结束为200、900、2100ms，总等待1500ms。Retry-After=1000ms且不加抖动时，两次等待均为1000ms，起点变成0、1200、2400ms，最终2600ms结束。401与配额型429只尝试一次；持续503最多三次，之后明确失败。抖动样本只为重放，真实应用应分散客户端重试，不能把演示数字当SDK默认行为。图上请求条的起点与等待条长度应同时改变。
</Answer>

3. **恢复预算并检查目录范围。** 注入历史膨胀后，保持输出1024，算出溢出和费用；仅将输出降到256能恢复吗？给出一个真正通过的设置，并说明为何嵌入、审核、Whisper和DALL·E不能复用聊天文本验证。

<Answer>
  输入=640+512+3072=4224，总预留5248，超出4096窗口1152；虚构费用=4.224+3.072=7.296单位，虽低于费用上限8，仍必须拒绝。输出降到256时总量4480，仍超384。历史改为1920、输出1024时总量恰好4096，费用6.144，通过两个预算检查。也可重置至默认3200、费用5.248。预算通过不代表授权或内容真实：嵌入需核对向量与检索评测，审核需核对分类与业务策略，语音转写需听校与来源权限，图像需内容及使用权限复核。逐项对应2.8的原有目录范围，而非把所有结果强转成choices文本。
</Answer>

</Exercises>

<Glossary>
  <GlossaryItem term="接口时代">
    区分书中历史环境与部署时实际使用的接口、SDK和模型版本。
  </GlossaryItem>
  <GlossaryItem term="HTTP 请求">
    客户端按方法、地址、请求头和请求体向服务端发送的一次调用。
  </GlossaryItem>
  <GlossaryItem term="模型标识">
    在请求中选择具体模型的名称，能力与可用性须按当前文档和账户核对。
  </GlossaryItem>
  <GlossaryItem term="Playground">
    用于交互试验模型输入和设置的开发界面。
  </GlossaryItem>
  <GlossaryItem term="Python SDK">
    把HTTP请求封装成Python方法和对象的开发库。
  </GlossaryItem>
  <GlossaryItem term="API 密钥">
    用于证明调用身份的秘密凭证，不能交给浏览器或写进公开日志。
  </GlossaryItem>
  <GlossaryItem term="Hello World">
    以最小输入验证身份、连接和响应解析的入门程序。
  </GlossaryItem>
  <GlossaryItem term="接口适配器">
    把不同接口的输入输出转换成应用内部统一结构的边界层。
  </GlossaryItem>
  <GlossaryItem term="messages">
    Chat Completions请求中承载角色和内容的消息列表。
  </GlossaryItem>
  <GlossaryItem term="流式响应">
    将响应按事件陆续交付，而不是一次性返回完整结果。
  </GlossaryItem>
  <GlossaryItem term="函数调用">
    模型提出结构化工具请求，应用验证并执行后再回传结果的机制。
  </GlossaryItem>
  <GlossaryItem term="文本补全">
    根据给定文本前缀继续生成内容的接口形态。
  </GlossaryItem>
  <GlossaryItem term="prompt">
    旧文本补全接口用于续写的输入文本或相应输入结构。
  </GlossaryItem>
  <GlossaryItem term="choices">
    补全类接口组织候选结果的列表，不是所有API都共有的响应字段。
  </GlossaryItem>
  <GlossaryItem term="错误分类">
    按凭证、输入、配额、临时限流或服务异常决定下一步处理。
  </GlossaryItem>
  <GlossaryItem term="token 预算">
    按分词单位估算输入、输出预留和上下文容量，并独立限制费用。
  </GlossaryItem>
  <GlossaryItem term="数据保留">
    服务对输入、输出和相关记录的保存范围与时长。
  </GlossaryItem>
  <GlossaryItem term="辅助 API">
    分别面向向量、审核、语音或图像等任务的接口，不能共用一种文本解析器。
  </GlossaryItem>
  <GlossaryItem term="嵌入">
    将内容映射成可用于相似度计算的数值向量。
  </GlossaryItem>
  <GlossaryItem term="内容审核">
    对输入或输出进行安全类别判断，供应用策略参考。
  </GlossaryItem>
  <GlossaryItem term="Whisper 和 DALL·E">
    原书目录中的语音识别和图像生成模型名称，分别对应不同输入输出任务。
  </GlossaryItem>
  <GlossaryItem term="迁移回归测试">
    用固定样本核对更换SDK或接口后，应用输入输出和错误处理是否仍符合合同。
  </GlossaryItem>
  <GlossaryItem term="指数退避">
    失败后逐渐拉长再次尝试的等待间隔，并配合次数上限；不是无限循环。
  </GlossaryItem>
  <GlossaryItem term="Retry-After">
    服务端建议等待后再尝试的响应头，实际要解析其格式；本页仅用毫秒模拟。
  </GlossaryItem>
</Glossary>
