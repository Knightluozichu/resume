## 第一组：输入是什么，模型这次能看到多少

### Prompt：给这一次任务的条件

本页的 <Term def="提供给模型的任务指令、示例及相关上下文。">Prompt</Term>（提示）是本次调用的条件，而不是模型的新权重。它可包含任务说明、示例与待处理资料，不只是用户最后输入的那一句。需要它，是因为同一模型可在不同任务条件下产生不同输出。[提示文档](https://developers.openai.com/api/docs/guides/prompt-engineering)给出生成请求的例子。实验一将这部分抽象为输入格，不模拟真实分词。

### Token：序列中的处理单位

一个 <Term def="分词器把文本编码后得到的序列单位，不一定等于一个字或一个词。">Token</Term>（标记）可能对应一个词、词的一部分、标点或字节片段。模型接收的是编码后的有序序列；计费和长度上限也常以 token 计量。不要把“十个汉字”直接当作“十个 token”。[tiktoken 官方说明](https://github.com/openai/tiktoken#what-is-bpe-anyway)介绍文本与 token 序列的转换；实际计数要选对模型对应的分词方式。实验一的 t1、t2 只表示顺序，不是某句话的真实 token ID。

### Context：这一次处理的范围

这里的 <Term def="模型本次调用可利用的输入信息；上下文窗口是该次处理允许的token容量边界。">Context</Term>（上下文）可以包含指令、对话历史、召回资料和工具结果；它不是“模型曾见过的一切”。窗口还要为生成输出留空间，某些模型也计入推理 token。[会话状态文档](https://developers.openai.com/api/docs/guides/conversation-state)说明窗口与输入、输出、推理的关系。实验一用固定 16 格解释预算，**不是任何实际模型的容量**。

### Embedding：用于比较的向量

一个 <Term def="把输入编码成数值向量的表示，常用于检索或比较相关性。">Embedding</Term>（嵌入）把一段输入映射为一组数值，便于检索、聚类或比较相近程度。维度数不是文本的 token 数；向量相近也不证明文本事实正确。[官方嵌入文档](https://developers.openai.com/api/docs/guides/embeddings)描述了整段文本到向量的接口。实验一画的是**整段文本的三维示意向量**，不是生成模型内部逐 token 的隐藏状态，也不是可无损替代 prompt 的“压缩文件”。

### Memory：应用保存与选择的状态

在应用架构中，<Term def="应用在调用之间保存、筛选并在需要时取回的信息，不等于模型自动学习。">Memory</Term>（记忆）可以是历史消息、用户偏好或摘要。框架或服务帮助保存，不等于模型每次都读到了全部内容：选出的信息进入当前请求后仍占用上下文，且可能过期或被错误归属。这里讨论应用机制，不承诺某款产品的个人记忆政策。实验一“召回记忆”增加 4 格，直观展示保存和使用是两个动作。

### 实验一：向量维度不能兑换上下文容量

**猜一猜：把输入从 6 格改成 10 格，再召回 4 格记忆，加上 4 格输出预留，16 格窗口还放得下吗？** 先单步观察序列和向量，再到容量检查。开启“漏算输出预留”，比较账面与真实需求；最后重置，确认回到输入 6、记忆 0、故障关闭、第一步暂停。

红线以下的格不属于窗口。输入与记忆已占 14 格时，只剩 2 格，不能再保证 4 格输出。把同一文本送去计算 embedding，不会自动缩短另一次生成请求。实际系统还须计入消息包装、工具描述等开销，并核对所用模型的输出上限。

## 第二组：用户用什么，程序调用什么，谁在计算

### 产品：面向使用者的整体服务

一个 <Term def="把界面、账号、会话与模型能力组合起来供人使用的应用服务。">产品</Term>可以提供聊天、文件处理或工具入口。ChatGPT 是产品名称，而不是一个固定的模型标识。需要区分这一层，是因为产品界面、编排与可用功能可能变化；看到某个按钮不能推出 API 也有完全相同的入口。实验二左侧表示产品内部路由，虚线只说明可能由产品安排模型，不暴露或猜测真实后端。

### 模型：执行学习所得计算的对象

一个 <Term def="用训练得到的参数把输入映射为预测或输出的计算系统。">模型</Term>有自己的架构和参数；GPT-4 在第一版中是模型系列名称，不能与 ChatGPT 产品画等号。应用调用时通常还需选择具体可用的模型标识与能力范围。实验二的 A/B 是抽象模型，不是对现有型号的承诺；内部节点和线宽只是权重示意，不表示真实网络规模。

### API：请求与响应的约定

一个 <Term def="软件之间约定如何发请求、传参数、接收结果与错误的接口。">API</Term>并非模型本身。请求接口规定消息格式、认证方式和返回结构，模型字段再选择承担计算的对象。历史 SDK 的 `ChatCompletion`、`Completion` 写法不应直接当作现行调用样板；现行 Responses 与 Chat Completions 的差异需按[迁移文档](https://developers.openai.com/api/docs/guides/migrate-to-responses)核对。Responses 是接口名称，不能填成模型名。实验二中换模型改变下游连线，不把接口层变成权重网络。

### 推理：使用权重，不自动写回权重

一次 <Term def="用已有模型参数计算输出的过程，通常不更新这些参数。">推理</Term>会受当前输入影响，但不等于把对话永久训练进模型。会话能引用上一轮内容，可能是应用传回历史或服务保存会话状态，而非权重已改变。实验二选择“推理”后走到第三步，模型高亮、线宽保持原样；这与实验一的应用记忆形成对照。

### Fine-tuning：改变模型参数的训练

与推理不同，<Term def="在已有模型上用特定数据继续训练，以改变其行为的过程。">Fine-tuning</Term>（微调）属于训练，需要数据、训练过程和效果评估。它可能改善格式、风格或特定任务表现，但不保证事实永远正确，也不是查询实时数据库的替代品。实验二切换“微调示意”，第三步改变连线粗细来表示权重变化。

**现行平台限制必须另查。** 本次访问的[监督微调文档](https://developers.openai.com/api/docs/guides/supervised-fine-tuning)已说明 OpenAI 正在收缩该平台，新用户不能访问，存量用户有过渡安排。这里解释稳定的训练概念，不保证任何读者今天都能创建托管微调任务；更不能把这一现行状态倒写成第一版时期的事实。

### 实验二：改入口、换模型、比较是否改权重

**猜一猜：在同一 API 下从 A 换到 B，接口层会消失吗？把推理换成微调，哪组线应该变化？** 选自建应用，单步到第三步，切换模型和操作；再选 ChatGPT 产品，观察 API 参数为何不适用。故障模式把接口名当模型，路径会在协议层断开。重置须恢复自建应用、A、推理、无故障及第一步暂停。

## 第三组：谁能提出动作，谁负责真的执行

### Tool：模型可请求使用的外部能力

一个 <Term def="模型可请求调用的外部函数、服务或能力，其执行责任由宿主系统承担。">Tool</Term>（工具）可以查询资料，也可以修改订单。工具描述让模型知道能力与参数，但描述不授予业务权限。工具可能由平台托管，也可能由开发者应用执行；实验三专门讨论**应用执行的退款函数**，不代表所有工具都在浏览器本地运行。

### Function calling：结构化提议与结果回传

所谓 <Term def="让模型输出函数调用请求，由宿主处理并返回结果的交互机制。">Function calling</Term>（函数调用）通常让模型输出函数名、参数和调用标识，应用执行后再把结果送回模型。[官方工具调用指南](https://developers.openai.com/api/docs/guides/function-calling)把提议、执行与结果回传分为不同步骤。参数符合结构只解决“能否解析”，不解决“是否有权操作”。实验三第一条箭头仅是提议，最后阶段才可能出现实际调用线。

### Plugin：第一版时期的产品集成形态

本书历史语境中的 <Term def="第一版时期通过清单与接口描述把外部能力接入ChatGPT的插件集成方式。">Plugin</Term>（插件）不是所有现代工具的别名。历史 ChatGPT 插件用清单和 OpenAPI 描述暴露服务；官方[旧 quickstart](https://github.com/openai/plugins-quickstart)保留了这种形态，其 README 已注明被 GPTs 替代。[示例清单](https://github.com/openai/plugins-quickstart/blob/main/.well-known/ai-plugin.json)的 `auth.type: none` 只说明这个演示没有认证配置，绝不是生产退款服务可跳过权限检查的依据。

因此，读旧书的“安装插件”时应标记为历史操作，不直接照搬菜单。现行函数工具可以复用“描述能力、接收调用、返回结果”的机制，但不是把旧清单改个文件名就迁移完成。实验三不复现旧产品 UI，只对照这些集成方式都必须面对的执行责任。

### 身份认证：确认是谁

一次 <Term def="校验凭证以确认请求者身份的过程。">身份认证</Term>可以确认哪个用户或服务在请求，例如验证登录会话或服务凭证。但“已登录”只回答是谁，不回答其能否退款某个订单。实验三假定身份已确认，把权限和订单归属留给下一步检查；真实系统应在可信服务端获得身份，不能相信模型自报的用户名。

### 授权：决定能对哪个对象做什么

一次 <Term def="依据身份、资源归属和策略决定是否允许某项操作。">授权</Term>要同时考虑主体、动作和目标对象。拥有退款功能权限，不等于有权退别人的订单；工具返回的文字也不能替应用改变这个规则。实验三要求“账号有退款权限”且“目标属于本人”才连到执行端。模型不能凭一句“用户同意”绕过检查；生产操作还应处理金额、审计、重复请求等条件，本图只保留两个必要条件。[OWASP 对象级授权说明](https://github.com/OWASP/API-Security/blob/master/editions/2023/en/0xa1-broken-object-level-authorization.md)强调：接收对象 ID 的接口应核对当前用户能否对该对象执行该动作，而不只是确认用户已登录。

### 实验三：格式正确仍可能必须拒绝

**猜一猜：已登录且有退款功能权限的用户，请求他人订单时，会出现应用到工具的执行线吗？** 单步到授权，注入“请求他人的订单”，再进到执行阶段；撤销故障并恢复权限后对比结果。重置应恢复有权限、本人订单、第一步以及副作用计数 0。

<LaeGlossaryAuthorizationGateLab />

这是一段可回放的本地模拟，不会真的发请求或退款。正常路径中执行端出现活动条，结果再回到应用与模型；拒绝路径停在应用，不能把“模型已经提出调用”记作“退款已成功”。插件清单、函数描述、登录凭证各司其职，没有一个能单独替代业务授权。

## 常见混淆与修正

1. **现象 →** 用 3 维向量替代 10 个输入 token，宣布窗口不会超限。

   **原因 →** 把两类接口的表示混为一谈，且忽略生成输出。

   **修法 →** 做实验一，按生成请求实际输入与预留输出预算，不按 embedding 维数计数。

2. **现象 →** 说“调用 Responses 模型，聊得越多权重越懂我”。

   **原因 →** 把接口当模型、把会话状态当训练。

   **修法 →** 用实验二定位模型字段；在推理与微调之间比较线宽，再查状态保存位置。

3. **现象 →** 旧插件清单不带认证，便让模型直接退款。

   **原因 →** 把演示配置、结构化参数和业务权限混同。

   **修法 →** 标注历史集成方式；用实验三的他人订单反例验证应用会拒绝，执行次数保持 0。

## 小结

- 序列、向量、记忆和窗口预算是不同对象。
- 产品提供体验，API 约定通信，模型负责计算。
- 推理不等于训练，工具提议不等于授权执行。

## 快速名词索引

<Glossary>
  <GlossaryItem term="Prompt">
    任务给模型的指令、示例和资料；改变本次条件，不等于改权重。见实验一。
  </GlossaryItem>
  <GlossaryItem term="Token">
    文本编码后的处理单位；一个字或一个词不一定刚好占一个。见实验一的有序格。
  </GlossaryItem>
  <GlossaryItem term="Context">
    本次可用的信息范围；窗口容量还须考虑输出及适用的推理开销。见实验一容量格。
  </GlossaryItem>
  <GlossaryItem term="Embedding">
    输入的数值向量表示，常用于相关性比较；维度数不是 token 数。见实验一正负条。
  </GlossaryItem>
  <GlossaryItem term="Memory">
    跨调用保存并按需取回的信息；进入请求的部分仍占上下文。见实验一召回开关。
  </GlossaryItem>
  <GlossaryItem term="产品">
    面向使用者的整体应用服务，如 ChatGPT；不等于某一个模型。见实验二入口层。
  </GlossaryItem>
  <GlossaryItem term="模型">
    用训练所得参数进行计算的系统；具体能力与可用版本需另查。见实验二模型层。
  </GlossaryItem>
  <GlossaryItem term="API">
    程序间交换请求和结果的合同；接口名不等于模型名。见实验二协议层。
  </GlossaryItem>
  <GlossaryItem term="推理">
    用已有参数产生输出，通常不修改参数。见实验二保持原宽的连接。
  </GlossaryItem>
  <GlossaryItem term="Fine-tuning">
    在已有模型上继续训练以调整行为；与保存会话不同。见实验二变宽的连接。
  </GlossaryItem>
  <GlossaryItem term="Tool">
    外部可调用能力；模型能请求它，不代表可以无条件执行。见实验三工具泳道。
  </GlossaryItem>
  <GlossaryItem term="Function calling">
    模型发出函数调用提议、宿主处理并回传结果的机制。见实验三的分段箭头。
  </GlossaryItem>
  <GlossaryItem term="Plugin">
    本页专指第一版时期的 ChatGPT
    插件集成；旧清单和安装操作不是现行通用规范。见实验三的宿主执行边界。
  </GlossaryItem>
  <GlossaryItem term="身份认证">
    确认请求者是谁；不是判断其是否有权操作订单。实验三假定此步骤已完成。
  </GlossaryItem>
  <GlossaryItem term="授权">
    按身份、对象和规则决定可否执行。见实验三的菱形检查及拒绝分支。
  </GlossaryItem>
</Glossary>
