## 直觉引入

Lua 在葡萄牙语中是"月亮"的意思。它不像 Python 那样包罗万象——它小巧、快速、可嵌入。Lua 的设计哲学是"提供机制而非策略"：它只给你最少的构建块（8 种类型、1 种数据结构 table、函数作为一等公民），让你用这些块搭建出任何你需要的结构。

本书以 Roberto Ierusalimschy 的《Lua 程序设计》为蓝本，带你从类型值开始，经过表达式语句、函数闭包协程，最终到达元表与 C API。每一步都体现 Lua"少即是多"的设计哲学。

## 概念讲解

### 四大板块

全书按学习递进分为四个板块：

1. **Lua 基础**（第 1-2 章）：学习地图与类型值。理解 8 种基本类型和 table 这一唯一数据结构。
2. **核心机制**（第 3-4 章）：表达式与语句。运算符体系、变量声明、条件循环——Lua 控制流的特色。
3. **高级特性**（第 5-7 章）：函数、闭包、协程。函数是一等公民，闭包捕获 upvalue，协程实现协作式多任务。
4. **元编程与 C 交互**（第 8-10 章）：元表、C API、总复习。元表实现 OOP 和运算符重载，C API 让 Lua 嵌入 C 程序。

### Lua 的核心定位

<Term def="Lua 是嵌入式脚本语言——核心小巧（约 20000 行 C 代码），设计为嵌入宿主程序中扩展功能，而非独立运行。">

Lua 的核心定位是"嵌入式脚本语言"。它不像 Python 那样自带丰富的标准库——Lua 故意保持小巧，把具体功能留给宿主程序提供。Lua 的价值在于：用极简的语言核心，提供强大的扩展机制（元表、C API），让宿主程序可以用 Lua 脚本化。

</Term>

### 为什么 table 是唯一数据结构

Lua 没有数组、字典、集合、对象——它只有 table。这不是缺陷，而是设计哲学：table 足够通用，可以模拟所有这些结构。数组是 `t[1], t[2], ...`，字典是 `t["key"] = value`，对象是 `t.method = function() end`，模块也是 table。一种结构，无限可能。

<Stepper>

<Step title="第一步：类型值打底">

Lua 有 8 种基本类型：nil、boolean、number、string、function、table、userdata、thread。关键理解：Lua 是动态类型语言——变量没有类型，值有类型。table 是唯一的数据结构，承载一切。nil 表示"缺失"，只有 nil 和 false 为假。

</Step>

<Step title="第二步：表达式语句强骨">

Lua 的运算符有独特之处：`~=` 表示不等于（不是 `!=`），`//` 是向下取整除，`and/or` 返回操作数而非布尔值。变量默认全局——必须用 `local` 声明局部变量。控制结构用 `then/do...end` 作为块标记。没有 `continue`、没有 `switch`、没有 `++`。

</Step>

<Step title="第三步：函数闭包协程拓边界">

函数是一等公民——可以赋值、传递、返回。支持多返回值和可变参数。闭包捕获外层局部变量（upvalue），实现状态封装和迭代器。协程通过 resume/yield 在单线程内协作切换执行权，是 Lua 的协作式多任务机制。

</Step>

<Step title="第四步：元表 C API 收全貌">

元表通过 `__index` 实现继承，元方法重载运算符——这是 Lua OOP 的基础。C API 通过虚拟栈与 Lua 交换数据，让 C 函数注册为 Lua 可调用函数——这是 Lua 嵌入式定位的核心。学完这一步，你就理解了 Lua 的完整能力图谱。

</Step>

</Stepper>

## 代码对照

```lua
-- Lua 学习递进：从值到元编程

-- Layer 1: 类型与值
local s = "hello"        -- string
local n = 3.14           -- number
local t = {1, 2, 3}      -- table（数组）
t.name = "array"         -- table（字典）

-- Layer 2: 表达式与语句
local x = 10 // 3        -- 向下取整除 = 3
if x ~= 0 then           -- ~= 是不等于
    for i = 1, #t do     -- # 是长度运算符
        print(t[i])
    end
end

-- Layer 3: 函数、闭包与协程
local function counter()  -- 函数是一等公民
    local count = 0       -- upvalue
    return function()     -- 闭包
        count = count + 1
        return count
    end
end

local co = coroutine.create(function(a)  -- 协程
    local b = coroutine.yield(a + 1)
    return a + b
end)

-- Layer 4: 元表与 C API
local Point = {x = 0, y = 0}
Point.__index = Point    -- 继承
function Point.new(x, y)
    return setmetatable({x = x, y = y}, Point)
end
function Point.__add(a, b)  -- 运算符重载
    return Point.new(a.x + b.x, a.y + b.y)
end

local p1 = Point.new(1, 2)
local p2 = Point.new(3, 4)
local p3 = p1 + p2       -- 调用 __add
```

## 常见误区

<Callout type="trap">

**误区：用 Python 的思维学 Lua**

Lua 和 Python 看起来都是脚本语言，但设计哲学完全不同。Python 有丰富的标准库和内置数据结构（list、dict、set、tuple），Lua 只有 table。Python 有 class 关键字，Lua 用元表模拟 OOP。Python 有 continue/switch，Lua 没有。用 Python 的思维写 Lua 会处处碰壁。

</Callout>

<Callout type="trap">

**误区：忽视 local，默认全局变量**

Lua 变量默认是全局的——`x = 10` 创建全局变量。必须用 `local x = 10` 声明局部变量。忘记 local 是 Lua 最常见的 bug 来源：全局变量被意外覆盖，性能下降（全局访问比局部慢），代码难以维护。规则：所有变量都用 local 声明，除非确实需要全局。

</Callout>

<Exercises>

**问题 1**：Lua 全书四大板块的顺序是什么？每个板块的核心知识是什么？

<Answer>

四大板块：Lua 基础 → 核心机制 → 高级特性 → 元编程与 C 交互。

1. Lua 基础：8 种基本类型，table 是唯一数据结构，nil 表示缺失
2. 核心机制：运算符体系（~=、//、and/or 短路），local 声明，if-elseif-else/while/repeat/for
3. 高级特性：函数是一等公民（多返回值/可变参数），闭包捕获 upvalue，协程 resume/yield
4. 元编程与 C 交互：元表 __index 实现继承，元方法重载运算符，C API 虚拟栈交换数据

每个板块建立在前一个基础上：表达式操作的是值，语句控制的是表达式，函数封装的是语句，元表扩展的是函数。

</Answer>

**问题 2**：为什么 Lua 只用 table 作为数据结构？这种设计有什么优缺点？

<Answer>

Lua 只用 table 是"提供机制而非策略"设计哲学的体现。table 足够通用——可以模拟数组（`t[1], t[2]`）、字典（`t["key"]`）、对象（`t.method`）、模块。

优点：
1. 语言核心极简——只需要实现一种数据结构
2. 学习成本低——掌握 table 就掌握了所有数据组织方式
3. 灵活性高——同一段代码可以处理数组和字典
4. 元表可以扩展 table 行为——实现 OOP、运算符重载

缺点：
1. 没有类型约束——table 可以同时是数组和字典，编译器无法检查
2. 性能不如专门结构——数组部分和哈希部分混合，可能影响缓存
3. 可读性降低——看到 `t[1]` 不确定是数组还是字典
4. 标准库弱——需要自己实现 set、queue 等结构

</Answer>
