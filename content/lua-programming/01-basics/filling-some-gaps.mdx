## 从Control-flow Graph开始理解Statement，而不是背关键字

Lua控制结构少而正交：local决定name binding与lifetime，condition决定edge是否可走，loop决定edge何时回返，break/return/goto改变出口。真正难点不在写出`end`，而在回答每条edge上哪些locals存在、哪些expressions求值几次、何时停止、退出前谁负责cleanup。

先预测：`if 0 then`是否进入；`local x=x`读取新x还是外层x；`repeat local line=read() until line==nil`能否在condition访问line；numerical for的limit function调用几次；generic iterator返回`false`是否结束；goto能否越过一个local声明跳到label。把binding、truthiness和edge画出来后再执行。

## Local Variables and Blocks

Local declaration从声明之后到当前block结束有效。Block可以是chunk、function body、control structure body，也可用`do ... end`显式创建。意味着`local x = x`右侧initializer仍解析到外层x；新local不会在自身initializer中生效。

Local默认值为nil，多变量声明按multiple-result rules调整。把相关locals放在靠近首次使用处可缩短lifetime，但递归或相互引用需要forward declaration：先`local f`，再赋function。`local f = function() return f() end`在没有外层f时，function body里的f可能解析为global，因为新local尚未覆盖initializer；`local function f()`是为递归处理过的sugar。

Shadowing不是总错，但同名value具有不同unit/ownership时很危险。Closure捕获binding而不是某次打印值；之后给该local重新赋值，closure会观察新值。循环变量每次迭代的closure语义要在目标Lua版本测试，避免从其它语言或更新版Lua推断。

```lua
local x = "outer"

do
  local x = x .. ":inner" -- initializer reads the outer x
  assert(x == "outer:inner")
end

local factorial
factorial = function(n)
  if n == 0 then return 1 end
  return n * factorial(n - 1)
end
assert(factorial(5) == 120)
```


## Control Structures与Truthiness

Lua只有false与nil为falsey；数字0、empty string、empty table都truthy。让C/JavaScript移植代码常出错：`while count do`不会在count变0时停止，`if text then`不会拒绝empty string。

Conditions不要求boolean type，但boundary validation最好先转成domain predicate，例如`count > 0`、`text ~= ""`。`and`与`or`返回operand value而非规范化boolean，并short-circuit；适合guard，但`value or default`会把false也替换掉。需要boolean output时用explicit comparison或`not not value`，但后者仍只表达truthiness。

Control body都是block，inside local在相应`end`后失效。Condition expression可能调用function或metamethod，side effects应明确；不要在同一condition里同时读取、修改与释放资源。

## if then else

`if condition then ... elseif condition then ... else ... end`按顺序求值，进入第一条truthy branch，其余conditions不再执行。`elseif`是单一结构，不需要额外end。Branch order是policy：先放specific case还是general case会改变结果，尤其是range overlap和capability checks。

Guard clause用early return减少nesting，但必须尊重resource ownership。先validate所有纯输入，再acquire resource，或把cleanup集中在一条出口；不要在open handle后散布无法清理的returns。Branch coverage应包含boundary equality、false/nil与0/empty string。

## while

While在每次iteration前测试condition，因此可能执行零次。适合“只要前置条件仍成立就继续”，如iterator之外的state machine或bounded retry。Loop invariant应在首次测试前成立，并由body保持；progress measure必须向termination推进。

Condition读mutable external state时可能永不变化。加入max iterations、deadline或input consumption proof；对numeric counter明确integer overflow和step。Loop body中修改参与condition的多个variables时，集中到尾部，避免一条branch忘记progress。

## repeat

Repeat先执行body，再在尾部测试`until condition`，因此至少一次。与许多语言不同，repeat body中的locals对until condition可见，因为condition属于同一block。适合read-then-validate、prompt-once和attempt-until-valid。

注意until在condition为truthy时停止，和while继续条件方向相反。把`while not done`机械改成`repeat ... until not done`会反转两次。Body中的break仍可提前退出，不求值本轮until；cleanup与result state要覆盖这条edge。

```lua
local attempts = 0
local value

repeat
  attempts = attempts + 1
  local candidate = attempts == 3 and "ready" or ""
  value = candidate
until value ~= "" or attempts >= 5

assert(value == "ready" and attempts == 3)
```

## Numerical for

Numerical form为`for variable = initial, limit, step do ... end`，step省略时为1。Initial、limit与step在loop开始前各求值一次，不会因body修改来源变量而变化。要求动态limit必须改用while才能每轮重新读取。

Loop variable是body local，不应在body内给它赋值；即使语法允许某些操作，也不能依赖修改影响hidden control state。Positive step在value不超过limit时执行，negative step在value不小于limit时执行；step为zero或NaN等异常必须在输入边界拒绝。Bound是inclusive，off-by-one测试要覆盖empty range、single value、reverse range和大整数边界。

Lua 5.3的integer/float subtypes会影响数值for行为与精度；时间戳、ID或超大range不应经float step。若iteration count来自untrusted input，先算上限并拒绝资源耗尽。

## Generic for

Generic form为`for names in expression-list do ... end`。Expression list通常产生iterator function、invariant state与initial control value；loop反复调用iterator(state, control)，把results赋给loop variables，并以第一个result为下一control。当第一个result为nil时结束，false不会结束。

统一了`pairs`、`ipairs`、`io.lines`和custom iterators。Additional results只是本轮variables，不决定termination。Expression list只在进入loop时求值一次。

Pairs不保证order，ipairs按sequence到first nil；选择generic for并不会抹掉underlying iterator contract。Custom iterator必须保证progress、终止与mutation policy；若closure捕获state，要说明并发/重入是否安全。Iterator返回nil作为合法data就与termination冲突，应改用control key加data value。


## break, return, and goto

Break退出最内层loop，控制转到loop后的statement；它不能直接退出两层loop，也不携带result。Return退出当前function并遵循multiple-result adjustment。Goto跳到当前function内可见label `::name::`，可前跳或后跳，但不能跳入某个尚未生效local的scope。

避免“找到结果就跳走”造成handle泄漏。Lua 5.3没有内建continue，常见写法是在iteration尾放label并goto；为避免跳入locals的scope，把本轮locals包在`do ... end`内，再把label放在block之后。

```lua
for index, item in ipairs({ "ok", "", "skip", "done" }) do
  do
    if item == "" or item == "skip" then goto continue end
    print(index, item)
    if item == "done" then break end
  end
  ::continue::
end
```

Goto适合状态机、统一error cleanup或continue-like flow，但过多crossing edges会让lifetime和invariant难审计。优先用small function、guard和structured loop；确需goto时让label邻近、方向明确、无resource acquisition跨越，并测试每条jump edge。


## 本章回顾：每条Edge都要证明Scope与Progress

1. Local从声明完成后开始生效；initializer可读取外层同名binding，do block可缩短lifetime。
2. Lua condition仅把false和nil当falsey，0与empty string仍进入true branch。
3. While可执行零次，repeat至少一次且body locals对until condition可见。
4. Numerical for快照initial/limit/step并使用inclusive bound；dynamic bounds应改用while。
5. Generic for由iterator、state与control驱动，以iterator首个结果为nil终止。
6. Break、return与goto离开不同区域；每条exit都要满足local scope、result和cleanup契约。
