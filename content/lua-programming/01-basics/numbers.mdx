## 为什么Lua 5.3的Number不再等于Double

Lua语言层的type name仍是`number`，但5.3默认实现内部有integer与float两种subtype：通常是signed 64-bit integer和double-precision float。`math.type`可观察subtype，`math.maxinteger`/`math.mininteger`给出整数边界。构建Lua时可选择不同width，因此工程contract不能只写“Lua number一定是64-bit”。

同时带来性能、精度和互操作收益，也引入边界：ID若被迫转float可能丢bit；C API要区分`lua_Integer`与`lua_Number`；JSON decoder是否保留整数需要验证。

先预测：`3`与`3.0`的`type`和`math.type`分别返回什么；`7/2`与`7//2`是什么subtype；最大integer加1会抛错还是wrap；大integer转float再转回能否保持identity；`0.3-0.2==0.1`能否作为money invariant。先写答案，再用目标Lua binary运行。

## Numerals：Decimal、Hexadecimal与Exponent

Integer numeral可写十进制和十六进制，例如`42`、`0x2A`；带decimal point或exponent通常形成float，例如`42.0`、`4.2e1`。Hexadecimal float使用binary exponent标记`p`，例如`0x1.8p1`表示3.0。Lexical form影响初始subtype，但后续operator仍可能转换。

Underscore digit separator不是Lua 5.3 numeral语法；不要从其它语言搬来。Leading sign是unary operator，不属于numeral token，因此precedence会影响`-2^2`。Source中的巨大integer literal若超出integer range可能按float读取或失败，必须用目标runtime和`math.type`验证，不能只看打印出来的十进制文本。

```lua
local samples = { 42, 42.0, 0x2A, 4.2e1, 0x1.8p1 }

for _, value in ipairs(samples) do
  print(value, type(value), math.type(value))
end

assert(math.type(42) == "integer")
assert(math.type(42.0) == "float")
assert(0x1.8p1 == 3.0)
```

## Representation Limits与Exact Integer Boundary

64-bit signed integer范围通常从`-2^63`到`2^63-1`；double有约53 bits significand，所以只保证到`2^53`附近的连续整数精确。决定数据库key、timestamp tick、bit mask和counter是否能经过float通道。

Integer arithmetic overflow按Lua整数语义wrap，不应作为business validation；先检查range或使用domain-specific big integer/decimal library。Float有rounding、infinity与NaN；NaN不等于自身，会破坏table key/equality与sorting assumptions。Lua table numeric keys会归一化exact integral float和integer的等价性，但不可把这推广到所有序列化器或host language。


## Arithmetic Operators与Subtype传播

Lua提供`+ - * / // % ^`和unary minus。两个integer对`+ - * % //`通常走integer arithmetic；若任一operand为float或operator要求float，则转换。`/`总做floating division，`^`产生float。不要通过“打印无小数点”推断subtype，用`math.type`。

Floor division `//`向负无穷取整，不是toward-zero truncation；modulo与它配套。在negative inputs最能区分实现是否正确。Divisor为0、mininteger除-1、float NaN/infinity等边界要单独测试。


```lua
local cases = {
  { 7, 3 }, { -7, 3 }, { 7, -3 }, { -7, -3 },
}

for _, pair in ipairs(cases) do
  local a, b = pair[1], pair[2]
  local q, r = a // b, a % b
  assert(a == q * b + r)
  print(a, b, q, r)
end

assert(-7 // 3 == -3)
assert(-7 % 3 == 2)
```

## Relational Operators与Mixed Comparison

Numbers支持`== ~= < <= > >=`。Integer与float比较时，Lua尽力避免先把large integer粗暴转float后再误判；但application不可依赖不同language/serializer都有同样算法。Exact integer-valued float可与对应integer相等，NaN与任何value包括自身都不相等。

排序comparator必须形成strict weak ordering；NaN、mixed units或string coercion会破坏transitivity。Money、duration和ID先统一domain representation再比较。`0`在Lua仍truthy，numeric zero test必须写`x == 0`，不能写`if not x`。

## The Mathematical Library

`math`提供trigonometry、log/exp、sqrt、absolute、min/max、angles、integer/float helpers等。单位通常是radians，使用degree输入前显式`math.rad`；inverse functions输出同样要标注单位。`math.huge`代表positive infinity，`math.pi`是float approximation。

`math.min`/`math.max`只按numeric ordering选value，不处理missing/NaN policy；empty input或dynamic list需要boundary contract。`math.abs(math.mininteger)`在固定-width integer上是危险case，因为positive counterpart可能不可表示。科学计算应保存tolerance、units和error budget，不用单个epsilon覆盖所有量级。

## Random-number Generator不是Security Boundary

Lua 5.3 `math.random()`可生成unit interval伪随机float，单integer参数给1..upper，两参数给lower..upper；invalid/empty range应失败。`math.randomseed`设置当前process generator state。防止flaky test和伪安全token。

固定seed适合单runtime回归，但algorithm和sequence可能随Lua build/version变化；测试更应inject RNG或assert statistical/property outcomes，不锁死跨版本序列。密码、session token、nonce和key必须使用OS/crypto RNG，`math.random`不提供不可预测性。多thread/state环境还需明确generator是否共享及同步。

## Rounding Functions

`math.floor`向下，`math.ceil`向上，`math.modf`拆integer part与fraction，`math.tointeger`只在value能exact转换为Lua integer时返回integer，否则nil。Toward-zero可用`math.modf`的integer part语义或按sign组合，但要测试negative zero/large value。

Float显示round到若干digits不等于value已round；`string.format`只改变text。Financial rounding还涉及half-up、half-even、currency scale，不等于floor/ceil。若需求是quantization，先以integer minor units或decimal library建模，再定义tie policy。

## Conversions是Input Gate而不是Convenience

`tonumber(text)`解析完整numeric string，失败返回nil；`tonumber(text, base)`按2..36的base解析integer digits。Arithmetic对numeric string的隐式coercion在Lua版本间有差异且隐藏invalid input，boundary应显式parse。`tostring`/`string.format`负责输出，但默认格式不承诺round-trip所有float或稳定schema。

要区分invalid syntax、out of range、fractional、non-finite和unsupported base，而不是都变成0。`math.tointeger`是exact-integral gate，不是rounding。


```lua
local function parse_port(text)
  local value = tonumber(text)
  if value == nil then return nil, "invalid-number" end

  value = math.tointeger(value)
  if value == nil then return nil, "not-an-integer" end
  if value < 1 or value > 65535 then return nil, "out-of-range" end
  return value
end

assert(parse_port("443") == 443)
assert(select(2, parse_port("3.5")) == "not-an-integer")
assert(select(2, parse_port("70000")) == "out-of-range")
```


## Precedence与可读性

从高到低要特别注意：power高于unary，unary高于乘除，乘除高于加减，concatenation、comparison、and、or依次降低；power与concatenation具有right associativity。经典陷阱是`-2^2`解释为`-(2^2)`，不是`(-2)^2`。复杂bitwise precedence将在Bits and Bytes章处理。

不要把precedence知识用于炫技。跨三层operator、混合boolean fallback或有side effect时加parentheses和locals；测试应直接表达业务invariant。Formatter不会证明作者的unit、rounding和overflow意图。

## Lua Before Integers与Version Boundary

Lua 5.2及更早的常见配置用单一double number model，5.3加入integer subtype与bitwise operators。旧code可能依赖float division、numeric coercion、`math.floor`或C API的`lua_Number`；迁移后需要检查serialization、format、table keys、C signatures和overflow。

反向兼容也不能只删除`//`：large integer exactness、`math.type`、min/max、bitwise与pack/unpack都不同。Library若支持多个Lua版本，应有runtime matrix与明确feature adapter，不用版本字符串散落条件分支。

## 本章回顾：先确定Representation，再谈公式

1. Lua 5.3的number含integer与float subtype，build配置和C API width必须记录。
2. Numeral lexical form影响初始subtype；operator决定传播，`/`与`^`产生float语义。
3. Integer width、float exact boundary、overflow与NaN决定ID和比较是否安全。
4. `//`是floor division，`%`与它满足重构等式；negative cases是必测边界。
5. Math、random、rounding和conversion都要有units、range、seed与failure contract。
6. Lua 5.3前后的single/double与dual subtype模型不同，迁移必须覆盖wire和C boundary。
