## 从Table Identity开始，而不是把它拆成数组与字典

Lua table是统一的associative data structure：key可为除nil/NaN外的大多数values，value可为除“存储nil”外的任意value。数组、record、set、object、graph都只是约定。决定API必须说明borrow、share、copy或transfer。

先预测：两个内容相同的table是否相等；`b=a`后修改b会不会影响a；false能否作value；给existing key赋nil后`pairs`是否仍能看见；float key 1.0与integer key 1是否同一entry。不要凭其它语言的array/map规则回答。

```lua
local a = { enabled = false, count = 1 }
local b = a
local c = { enabled = false, count = 1 }

b.count = 2
assert(a.count == 2 and a == b)
assert(a ~= c)

a.enabled = nil
assert(a.enabled == nil) -- key被删除，不是存储了nil
```

## Table Indices与Nil Deletes Entry

Key的type是contract的一部分：`"1"`与`1`不同，exact integral float通常归一到对应integer key，table/function/userdata key按identity。Nil不能作key，NaN也不稳定且被拒绝。Mutable table作key时identity稳定，但内容变化不改变hash identity；序列化后通常无法保持同一key语义。

解释了`if t[k] then`的双重错误：stored false会被误判missing，stored nil根本不可能表示present。Presence check使用`t[k] ~= nil`；若domain需要显式null，存唯一sentinel。


## Table Constructors

Constructor `{}`创建新identity。List fields按1开始依次放置；record sugar `name=value`等价`["name"]=value`；general field `[expression]=value`支持任意key。Mixed constructor可用，但要清楚list index计数与explicit keys独立。

Field expressions按语言规定顺序/多-result规则求值，最后一个list expression可能贡献multiple results。不要在constructor中混入依赖顺序的side effects；先算locals再构造。Duplicate key最终只剩一个mapping，但不应依赖复杂重复写入表达业务merge。

```lua
local host = "db.internal"
local config = {
  host = host,
  port = 5432,
  ["read-only"] = true,
  "primary",
  "analytics",
}

assert(config[1] == "primary")
assert(config.host == "db.internal")
assert(config["read-only"] == true)
```

Constructor是data expression，不是class constructor；metatable另行设置。若接受external key/value生成table，先validate count/key/value，防止prototype-like capability泄漏、memory exhaustion或错误canonicalization。

## Arrays, Lists, and Sequences：Proper Sequence边界

Lua convention用integer keys 1..n且无holes表示sequence。让`#`、`ipairs`和table library有清晰意义。Empty sequence的n为0。

有hole时`#t`只返回某个border，不是元素count；`ipairs`在首个nil停止；后方elements可能存在却被sequence API忽略。Map/mixed table不能用`#`计entries，应在mutation时维护count或遍历计算。Zero-based key 0也不属于标准sequence范围。


## Table Traversal与Order Boundary

`pairs`基于`next`遍历所有entries，顺序unspecified；`ipairs`按1递增到首个nil。防止hash layout、版本或mutation改变snapshot/test结果。

遍历时删除当前existing key通常是常见用法，但添加新keys、rehash或复杂mutation的可见性不应依赖。稳妥做法是先collect keys/snapshot，再mutation。Comparator sorting keys要处理mixed key types；最好在schema中禁止不可比较的混合keys。

Deterministic serialization先validate key domain，收集keys，按explicit comparator排序，再emit。`pairs`输出“这次看起来稳定”不构成兼容保证。

## Safe Navigation不等于False Navigation

访问深层field时可写`zip and zip.company and zip.company.director`，短路避免index nil。的风险是Lua `and`把false也当停止；若false是合法leaf，可接受，但中间node schema必须是table或nil。

重复path expression可能读取metamethod多次并产生side effects；保存local或写pure helper逐段读取。不要用`a and a.b or default`在false leaf上fallback；只对nil做default。第20章学习`__index`后还要考虑lookup可能执行code。


## The Table Library

`table.insert/remove`在proper sequence中移动elements，middle操作O(n)；`table.move`复制contiguous integer range并处理overlap；`table.concat`连接sequence；`table.sort`in-place reorder；`table.pack`用`n`保存含nil的argument count，`table.unpack`按range展开。


```lua
local packed = table.pack("a", nil, "c")
assert(packed.n == 3 and packed[2] == nil)

local values = { 5, 1, 5, 2 }
table.sort(values, function(left, right)
  return left < right
end)
assert(table.concat(values, ",") == "1,2,5,5")

local copy = {}
table.move(values, 1, #values, 1, copy)
assert(copy ~= values and copy[1] == values[1])
```

Sort不保证stable；comparator若读mutable external state或返回`<=`可能违反strict ordering。Unpack大量elements可能超过argument/result limits；boundary限定range。Table library不会自动修复holes或mixed keys。

## Copy、Snapshot与Memory Model

Shallow copy遍历keys并复制values；nested tables仍share identity。Deep copy必须定义cycles、shared subgraphs、metatables、table keys和userdata/functions policy，不存在通用安全答案。Serialization同样需要这些contract，第15章详解。

Lua实现常把integer sequence与hash entries优化为不同内部parts，但不是language-visible layout。Performance需profile，不按“array part一定O(1)”写correctness。Memory pressure还取决于key/value lifetimes、weak tables和GC，后续第23章处理。

## 本章回顾：先声明Shape，再选择API

1. Table有identity，assignment共享mutable state；content相同不代表table相等。
2. Nil key非法，nil value删除entry；present-nil需要sentinel。
3. Constructor支持list、record和general fields，但mixed shape需要明确schema。
4. Proper sequence是1..n无holes；sparse/map不能依赖length或ipairs。
5. Pairs顺序unspecified；deterministic output要collect/sort。
6. Safe navigation按truthiness且可能触发metamethod；table library需要range、owner与comparator law。
