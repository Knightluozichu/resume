## 为什么Bits必须先声明Width

Bitwise code常写成几枚operators，却同时依赖Lua integer width、协议field width、signed/unsigned interpretation和byte order。Lua 5.3通常用signed 64-bit `lua_Integer`，但build可配置不同width；一个8-bit flags field放进Lua integer后，高位仍存在，除非显式mask。

先预测：negative integer右移是否补sign bits；shift count为negative时发生什么；8-bit complement `~value`是否只翻8位；signed -1与unsigned max比较谁更小；`string.pack("I2", 65536)`是截断还是错误；unpack返回几个values；binary mode为何仍不能保证一次read拿满请求长度。先写width与schema，再运行。

<Term def="每次位运算先规定逻辑字段的bit width、允许range和运算后mask，避免Lua整数高位污染较窄协议字段。">fixed-width bit domain</Term>把“整数值”和“n-bit pattern”分开。对8-bit field常用mask `0xFF`；extract前shift/mask，set前验证field value fits，再清除目标bits并写入。

## Bitwise Operators

Lua 5.3提供binary AND `&`、OR `|`、XOR `~`、left shift `<<`、right shift `>>`，以及unary NOT `~`。Operands必须可转换为integer，否则报错；result为integer。Unary NOT翻转整个Lua integer width，不是application field width，之后通常要mask。

<Term def="Lua的左右shift按整数位宽丢弃越界bits并用zero填充，right shift对负数也不是arithmetic sign extension。">logical-shift contract</Term>意味着`x >> 1`不能替代signed floor/truncate division。Negative shift count会向相反方向shift；绝对值达到或超过integer width通常得到zero，仍应在boundary限制count而非依赖极端行为。

Precedence中shifts与bitwise层级和算术不同，复杂field expression加parentheses。XOR与unary NOT都写`~`，由arity/context区分。不要把C的`^`当XOR，Lua里`^`是exponentiation。

```lua
local function replace_field(word, shift, width, field)
  assert(width > 0 and shift >= 0)
  local field_mask = (1 << width) - 1
  assert(field >= 0 and field <= field_mask)
  local shifted_mask = field_mask << shift
  return (word & ~shifted_mask) | (field << shift)
end

local flags = 0
flags = replace_field(flags, 4, 3, 5)
assert(((flags >> 4) & 0x7) == 5)
assert((~0x0F & 0xFF) == 0xF0) -- explicit 8-bit complement
```

`(1 << width)-1`在width等于integer full width时会溢出/shift to zero，generic helper需要特别处理full-width mask。Protocol通常选择1/2/4/8-byte fields并用tested constants，避免dynamic unchecked width。

## Unsigned Integers

Lua integer type本身通常是signed，但bitwise operators操作其bit pattern。最高位为1的pattern打印成decimal可能为negative，却可表示协议中的unsigned value。<Term def="同一lua_Integer bit pattern按signed arithmetic或modulo 2^width的unsigned magnitude解释，比较与格式化必须选择一种视图。">unsigned interpretation</Term>禁止用普通less-than比较full-width unsigned patterns。

`math.ult(a, b)`按unsigned integer比较两个Lua integers，适合full `lua_Integer` width。较窄unsigned field先mask后通常落入non-negative range，可普通比较。输出可使用明确hex更直观；decimal unsigned formatting的portable behavior要按Lua/C library验证。

Unsigned overflow按modulo field width是否允许是protocol decision。Sequence number可能允许wrap并用half-range rule比较，money/count绝不应wrap。Pack unsigned field超range应视为validation error，不依赖silent truncation。

## Packing and Unpacking Binary Data

`string.pack(format, values...)`按format构造binary string；`string.unpack(format, data, position)`返回decoded values，最后额外返回next unread position；`string.packsize(format)`给fixed-size format的byte size，variable-length string formats不能总给constant size。

<Term def="Pack format把endianness、alignment、numeric width/signedness、padding和string framing编码为必须版本化和审计的二进制schema。">binary format string</Term>常用prefix：`<` little endian、`>` big endian、`=` native endian；`!n`控制最大alignment。Integer items包括fixed-size `i[n]`/`I[n]`及native types；float items包括`f`、`d`、`n`。Strings可用`c[n]` fixed bytes、`z` zero-terminated、`s[n]` length-prefixed。

稳定wire/file schema应显式byte order、exact widths且避免native padding。`j/J/T/l/L`等native-size类型会随ABI变化，不适合跨机协议。String encoding另行声明；pack只处理bytes，不验证UTF-8。Zero-terminated string无法表示embedded NUL，length-prefixed/ fixed string则可以。

```lua
local HEADER = ">c4BBI4" -- magic, version, flags, payload length
local encoded = string.pack(HEADER, "LUA1", 1, 0x05, 3) .. "abc"

local magic, version, flags, length, next_pos = string.unpack(HEADER, encoded)
assert(magic == "LUA1" and version == 1 and flags == 0x05)
assert(length == 3 and next_pos == string.packsize(HEADER) + 1)

local payload = string.sub(encoded, next_pos, next_pos + length - 1)
assert(payload == "abc")
```

<Term def="String.unpack最后返回的next position是后续字段唯一可信起点，parser必须证明它单调前进且不越过input end。">unpack cursor invariant</Term>使多个records可顺序decode。Lua string index从1开始；next position指向未消费byte，而不是已消费end。Position和length都按bytes。

## Binary files

Binary file用`"rb"`/`"wb"`避免text newline translation。Lua string可保存任意bytes和NUL；读取n bytes可能少于n或在EOF返回nil/short data，frame parser必须实现exact-read loop并区分clean EOF与truncated frame。Network stream更不能假设一次read等于一个frame。

<Term def="Binary record先以固定可信header声明magic、version、flags与bounded length，再精确读取payload并处理integrity和trailing bytes的边界。">binary frame boundary</Term>要求在allocation/substr前验证length上限与remaining bytes。Magic只防误识别，version选择schema，flags拒绝unknown reserved bits。

```lua
local function read_exact(file, length)
  local chunks, total = {}, 0
  while total < length do
    local chunk = file:read(length - total)
    if chunk == nil or #chunk == 0 then
      return nil, total == 0 and "eof" or "truncated"
    end
    chunks[#chunks + 1] = chunk
    total = total + #chunk
  end
  return table.concat(chunks)
end

local function read_frame(file, max_payload)
  local header_size = string.packsize(">c4BBI4")
  local header, reason = read_exact(file, header_size)
  if not header then return nil, reason end
  local magic, version, flags, length = string.unpack(">c4BBI4", header)
  if magic ~= "LUA1" or version ~= 1 then return nil, "unsupported-header" end
  if (flags & 0xF0) ~= 0 or length > max_payload then return nil, "invalid-range" end
  return read_exact(file, length)
end
```

Frame还可能需要checksum或cryptographic authentication。Checksum发现accidental corruption，不证明sender；MAC/AEAD需要key management和constant-time library，不应手写。Compressed payload要同时限制compressed与decompressed size，防止decompression bomb。

## Schema Evolution与Security

Version必须在解析变长/含义变化前读取。新增optional field可通过length-delimited sections或TLV，但unknown field skip仍需验证length。Reserved bits发送方写0、接收方按policy reject或ignore；没有规则就无法前向兼容。

Binary parser面对untrusted bytes时，所有count乘法、offset加法和allocation都要检查overflow与上限。Lua integer计算可能wrap，验证`length <= remaining`前还要避免构造已overflow的end position。先用subtraction形式比较，或逐段cursor检查。

## 本章回顾：Bit Pattern必须有Width，Byte Stream必须有Schema

1. Lua bitwise operators在lua_Integer全宽运行，较窄field每次extract/update后要mask。
2. Right shift逻辑补零；negative count反向，`~`分别表示binary XOR与unary NOT。
3. Full-width unsigned interpretation使用math.ult等明确操作，不能混入signed comparison。
4. Pack format显式规定endianness、width、alignment与string framing；native ABI格式不适合wire。
5. Unpack返回values加next cursor，parser要验证cursor、remaining bytes和trailing policy。
6. Binary file按exact frame读取，先验证header/length/version，再处理payload与integrity。

<Exercises>

**问题 1：怎样计算8-bit Value的Bitwise NOT？**

<Answer>Lua unary `~value`翻整个lua_Integer width，因此随后mask：`(~value) & 0xFF`。先验证value位于0..255；测试0x00得到0xFF、0x0F得到0xF0、0xFF得到0x00。</Answer>

**问题 2：为什么Binary Schema不应使用Native `j`、`T`或`=`？**

<Answer>这些依赖host integer/size_t width或native byte order/alignment，同一logical record在不同ABI产生不同bytes。Wire/file协议选固定`i[n]/I[n]`、显式`<`/`>`并避免implicit padding，再用known hex fixture跨实现验证。</Answer>

**问题 3：Header宣布1GB Payload时Parser应何时拒绝？**

<Answer>Unpack固定header后、任何payload allocation/read/substr之前，验证length为允许integer、未超max_payload且offset arithmetic不overflow。Stream随后exact-read；短读返回truncated。若压缩，还要限制解压后size。</Answer>
