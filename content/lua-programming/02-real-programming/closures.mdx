## 为什么Closure不是“函数里带一个值”

Closure来自两条Lua基础规则：function是value，name按lexical scope解析。Function body引用外层local时，运行时必须让该binding在外层call返回后仍可访问；得到的function value连同这些upvalues构成closure。捕获的不是一张创建时value snapshot，而是binding，多个closures可能共享并修改它。

先预测：两次调用counter factory得到的函数是否共享count；同一次factory返回getter/setter是否共享value；把module field替换为新function后，旧变量引用会不会自动变化；callback只使用`context.id`却捕获整个context时，context里的large cache能否回收；map callback返回多个values会保留几个。先画identity与reachability，再运行。

<Term def="Function value与其引用的外层lexical bindings共同形成可在原block结束后继续执行的运行时对象。">closure binding object</Term>比“记忆”更精确：closure可以只读，也可完全无状态；关键是code与binding environment，而不是一定有mutable counter。

## Functions as First-Class Values

Function与number、string、table一样可赋变量、存table、作为argument、作为result。`function f(x) ... end`等价于给f赋一个function value；`function t.run(x) ... end`等价于给`t.run`赋值。Anonymous function只是没有在expression内声明name的function literal，赋给变量后同样可调用和比较identity。

<Term def="Function可在不特殊包装的情况下被创建、赋值、存储、传参和返回，并以identity参与程序数据流的性质。">first-class function value</Term>让strategy、callback、iterator和factory成为普通结构。Table field被新function替换，只改变field mapping；之前保存到local或另一个table的旧function仍指向原value，直到所有references释放。

`table.sort(items, comparator)`展示典型higher-order API。Comparator可以匿名定义并捕获sort direction或field name，但必须形成strict ordering且不要在比较中修改items。Callback API需声明调用次数上限、result arity、error传播、是否允许yield和是否长期保存callback。

```lua
local records = {
  { name = "delta", score = 2 },
  { name = "alpha", score = 2 },
  { name = "beta", score = 5 },
}

local field = "score"
table.sort(records, function(left, right)
  if left[field] == right[field] then
    return left.name < right.name
  end
  return left[field] > right[field]
end)
assert(records[1].name == "beta" and records[2].name == "alpha")
```

## Non-Global Functions

非全局function主要有两种：放在table field中形成namespace，或保存在local中。Table namespace适合exported API，local function隐藏implementation并避免global name collision。`local function parse(...) ... end`是递归友好的声明形式，等价于先声明local再赋function，而不是普通`local parse = function...`的完全机械替换。

Mutual recursion需要先声明所有locals，再分别赋function，否则较早的function body可能解析到global或nil。例如先`local parse_expr, parse_atom`，再给两者赋值。<Term def="Function名称被限制在local block或显式module table中，export surface与递归binding都由声明顺序控制的命名策略。">non-global function boundary</Term>让API审计能分清public、private与replaceable hooks。

Local function不是安全边界：若被return、存入public table或作为callback注册，外部仍可调用。反过来，global function也不必然共享state；state取决于upvalues和tables。模块设计应最小化exports，把invariants放在不可直接访问的locals，并为需要测试替换的dependencies显式注入。

## Lexical Scoping

Lexical scoping按source nesting决定name绑定，不按caller stack动态查找。Function在定义处解析free variables；在别处调用时仍访问原来的outer locals。<Term def="Free variable按函数定义处的source block绑定到local或environment，而不随调用者的局部变量改变的名称解析规则。">lexical scope resolution</Term>保证把callback传给陌生caller后语义仍稳定。

Outer function每调用一次会创建一组新的locals，因此两次factory calls通常产生独立bindings。同一次factory若返回多个closures，它们引用同一个local，则共享读写。Upvalue在仍有closure可达时存活；最后一个closure不可达后，binding与其引用对象才有机会被GC回收。

```lua
local function new_cell(initial)
  local value = initial
  local function get() return value end
  local function set(next_value)
    value = next_value
    return value
  end
  return get, set
end

local get_a, set_a = new_cell(10)
local get_b = new_cell(20)
set_a(11)
assert(get_a() == 11 and get_b() == 20)
```

<Term def="同一lexical local被多个closures捕获时，所有closures读取和修改同一个binding，而不同factory activation通常创建不同binding。">shared upvalue ownership</Term>可以实现private state，也会引入隐式coupling。Getter/setter、event handlers和iterator若共享状态，应声明reentrancy、concurrency和reset policy；callback调用callback时可能在同一operation中二次修改upvalue。

## Capture Size、Loop Binding与Lifecycle

Closure只要引用outer table，就可能让整张object graph保持reachable。只需要ID时先`local id=context.id`再捕获id；但若业务必须观察context后续变化，就应捕获shared table并接受lifetime。优化前先profile，不能为了减小capture把live binding误改成snapshot。

循环中创建closures时要依据目标Lua版本和loop form判断binding。Numerical/generic for的loop variables有语言定义的local语义，但while外层counter通常是同一个binding；最清晰的跨版本写法是在iteration body创建`local snapshot = value`并捕获snapshot。测试必须在loop结束后调用所有closures，单在body内调用发现不了共享问题。

Long-lived registry、timer、UI listener或C callback必须有unregister/revoke API。Closure没有自动知道业务生命周期；弱table能改变reachability，但不能替代明确ownership。Captured file handles、coroutines和native userdata尤其要显式release，不依赖GC时机。

## A Taste of Functional Programming

Higher-order programming把行为作为argument：map把每个input变换为output，filter按predicate保留values，fold从seed累计，composition连接stages。<Term def="Higher-order pipeline明确每个stage的输入输出shape、顺序、effects、failure与资源成本，而不是只把callbacks串在一起。">functional transformation contract</Term>防止“函数式”成为隐藏mutation与多次遍历的标签。

Lua table同时可表示sequence/map，functional helper必须声明接受proper sequence还是arbitrary table。Map通常保持1..n cardinality；callback返回nil会在Lua table中制造hole，需选择reject、sentinel或packed result。Filter用truthiness判断时false与nil都不保留，但0和empty string保留。Fold必须给seed与direction；非associative operation改变order就改变结果。

```lua
local function map(values, transform)
  local output = {}
  for index, value in ipairs(values) do
    local result = transform(value, index)
    assert(result ~= nil, "map result must be non-nil")
    output[index] = result
  end
  return output
end

local function compose(first, second)
  return function(value)
    return second(first(value))
  end
end

local normalize = compose(string.lower, function(value) return "@" .. value end)
local result = map({ "Ada", "LUA" }, normalize)
assert(result[1] == "@ada" and result[2] == "@lua")
```

Composition要考虑multiple results：`second(first(x))`让first位于最后argument position，可展开多个results；若second只期望一个，应用括号或先存local显式收缩。Error可直接传播、返回result object或在stage boundary捕获，但整条pipeline只能选一套清晰协议。

## 本章回顾：先画Binding，再谈函数式风格

1. Function是first-class value，assignment、table replacement与callback registration按identity工作。
2. Non-global function通过local或module table控制命名与export，mutual recursion需要forward locals。
3. Lexical scope在定义处解析free variables；closure携带这些bindings跨越outer call lifetime。
4. 不同factory calls创建独立state，同一factory的sibling closures可共享upvalue。
5. Closure会延长captured graph寿命，long-lived callbacks必须有明确unregister和capture-size策略。
6. Map/filter/fold/composition仍需shape、order、nil、error、effect和cost contract。

<Exercises>

**问题 1：为什么Getter和Setter能共享Private Value，而两个Factory实例互不影响？**

<Answer>同一次new_cell activation只创建一个value local，getter/setter都捕获该binding，所以setter写入后getter可见；第二次activation创建另一个binding，closure graph没有连接，因此独立。用两个实例交错调用可验证ownership。</Answer>

**问题 2：怎样避免长期Callback无意保留一个巨大Context？**

<Answer>先确认需要snapshot还是live state。只需immutable字段时提取small locals再创建closure；需要live state时保存最小facade或ID查表。Registry提供unregister，owner结束时删除callback并清空references，用memory profile验证captured graph可回收。</Answer>

**问题 3：Map Callback可能返回Nil时应怎样定义结果？**

<Answer>不能直接写入sequence并继续依赖#或ipairs，因为nil会形成hole。选择一种明确协议：reject nil、用private sentinel、返回table.pack并维护n，或把语义改为filter-map且compact输出。测试nil在首/中/尾位置及order/cardinality。</Answer>

</Exercises>
