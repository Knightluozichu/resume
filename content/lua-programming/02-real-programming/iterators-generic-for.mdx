## 为什么Generic for背后有三个State Values

表面上`for value in values() do`像一个函数，实际generic for在进入时保存iterator function、invariant state和initial control value。每轮调用iterator(state, control)，把首结果更新为next control；首结果nil时结束。Closure iterator可把state藏进upvalues，但protocol本身不要求closure。

先预测：iterator首结果false是否结束；expression list中的factory调用几次；body给loop variable赋值能否改变下一control；同一个closure iterator交给两个loops会独立吗；pairs为何能stateless；按sorted keys遍历时source中途新增key会不会出现；callback-style true iterator如何break。先画owner与control。

把generator syntax还原为普通call protocol。Lua 5.3的核心语义以这三个values理解；更新版语言可能加入close value，不应倒灌到本书baseline。

## Iterators and Closures

Closure iterator factory创建private state并返回next function。每次调用推进position、返回item；结束时首结果nil。防止malformed input或empty match造成infinite loop。

每次factory call创建独立upvalues；同一个iterator function被多个consumers调用则共享并交错state。Stateful iterator通常不可rewind/reentrant，API应命名为new/make并记录single-consumer。若closure捕获file handle，loop提前break不会自动通知iterator cleanup；owner需with-iterator helper、explicit close或更合适的resource protocol。

```lua
local function range(first, last, step)
  step = step or 1
  assert(step ~= 0)
  local current = first - step
  return function()
    current = current + step
    if (step > 0 and current <= last) or (step < 0 and current >= last) then
      return current
    end
    return nil
  end
end

local values = {}
for value in range(1, 5, 2) do values[#values + 1] = value end
assert(table.concat(values, ",") == "1,3,5")
```

Range这里仅返回iterator，generic for把缺少的state/control视为nil并反复调用closure。Untrusted bounds需限制iteration count与integer overflow；`current=current+step`溢出可能让termination失效。


## The Semantics of the Generic for

Generic form的expression list只求值一次，得到iterator、state和control。概念展开如下：保存三元组；循环调用iterator(state, control)；把results赋给fresh loop locals；首结果赋给hidden control；若首结果nil则break；否则执行body。

要求data如果可能nil，改用separate non-nil key/control并把data放后续result。Additional results可以nil，不影响termination。

```lua
local function step(state, control)
  local next_control = control + 1
  if next_control > #state then return nil end
  return next_control, state[next_control]
end

local function values(sequence)
  return step, sequence, 0
end

local seen = {}
for index, value in values({ false, "b", "c" }) do
  seen[index] = value
end
assert(seen[1] == false and seen[3] == "c")
```

若step错误地写`if value then return ... end`，false element会提前停止；正确termination检查index/range或`value ~= nil`。Body中修改index local不改变hidden control，因为下一control来自iterator首结果。


## Stateless Iterators

Stateless iterator不把iteration state存upvalue，全部由invariant state与control提供，因此同一iterator function可服务多个loops。`next(table, key)`返回下一个key/value，key nil从头开始；`pairs`通常提供next、table、nil。Order unspecified且mutation policy有限。

Ipairs-style iterator用sequence作为state、index作为control：next index加一，读取value，value为nil时结束。使reentrancy更清晰，但underlying table mutation仍可能破坏结果。

Iterator function可复用不等于state thread-safe。两个loops遍历同一mutable table时，修改可见性取决于collection contract。需要snapshot就先copy keys/values；需要live view则限制allowed mutations。

## Traversing Tables in Order

Pairs不承诺order。有序遍历先collect keys到sequence，按total comparator排序，再用closure/stateless iterator依次返回key与current value。区分两种语义：只snapshot keys时删除key会返回nil、新key不出现；snapshot key-value pairs则完全稳定但复制更多。

```lua
local function ordered_pairs(source)
  local keys = {}
  for key in pairs(source) do keys[#keys + 1] = key end
  table.sort(keys)
  local index = 0
  return function()
    index = index + 1
    local key = keys[index]
    if key == nil then return nil end
    return key, source[key]
  end
end

local output = {}
for key, value in ordered_pairs({ z = 1, a = 2, m = 3 }) do
  output[#output + 1] = key .. value
end
assert(table.concat(output, ",") == "a2,m3,z1")
```

Mixed key types不能直接`table.sort(keys)`，必须schema禁止或提供type-ranked comparator。Comparator不能读取迭代中变化的external state。Large tables的O(n) memory/O(n log n) cost需预算；若data源已ordered，使用其native iterator。

## True Iterators

原书把由traversal function控制循环、对每个item调用callback的形式称true iterator。Generator把control交给caller的for body；true iterator持有control：`all_words(function(word) ... end)`。可避免每item generator state transfer，但control composition更困难。

Early stop可让callback返回false/tag，或raise专用sentinel再在边界捕获；前者更清晰。Callback error默认传播，traversal必须cleanup resources。Nested traversal与yieldability按runtime测试。若caller需要普通break、多loop clauses和generic algorithms，generator通常更符合Lua习惯。


## Iterator Errors、Resources与Testing

Iterator error发生在for获取next item阶段，body尚未执行本轮。Protected boundary应覆盖整个loop，resource owner在success、iterator error、body error与break都cleanup。不要让iterator用nil吞I/O error；返回control加result，或raise/typed status保持EOF与failure不同。

Property tests比较iterator输出与reference sequence，并断言调用次数最多n+1、首nil后不再产生item。Fuzz empty/single/false/nil data、mutation与deep inputs。

## 本章回顾：Iterator是Progress与Control Ownership协议

1. Closure iterator隐藏state，每个factory实例独立；同一function多consumer会共享消费。
2. Generic for一次求值iterator/state/control，每轮首result更新control，首nil才终止。
3. Stateless iterator从显式state/control计算下一项，next/pairs与ipairs-style是典型例子。
4. Ordered traversal必须collect/sort keys并声明key snapshot还是完整value snapshot。
5. True iterator主动调用callback，early stop、error、cleanup和reentrancy需专门协议。
6. 所有iterator都要证明strict progress、bounded work与resource lifecycle。
