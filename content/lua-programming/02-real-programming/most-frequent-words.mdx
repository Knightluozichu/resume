## 从一条Data Pipeline开始理解词频

Most Frequent Words把前几章连成一个完整程序：`io.lines`流式读取，`string.gmatch`切token，table按word计数，把keys收集成sequence，用`table.sort`按frequency排列，最后输出前k项。每个API都简单，但最终答案由整条pipeline的contract共同决定。

先预测：`Hello, hello_2`用`%w+`得到几个tokens；`pairs(counts)`是否每次给相同order；两个word同为10次时sort comparator只写count greater-than会不会稳定；k大于unique count怎么办；UTF-8中文在byte-oriented pattern下会得到什么；输入包含一亿个不同tokens时程序先耗尽CPU还是memory。先写政策，再写代码。

<Term def="从bytes到word keys的规则集合，明确character model、pattern、case normalization、punctuation、digits、locale与invalid input。">tokenization policy</Term>不是实现细节，而是报表定义。同一文本按`%a+`、`%w+`或Unicode word segmentation会得到不同分母与排名；测试fixture必须连同policy version保存。

## Reading and tokenizing text

`io.lines()`可逐行读取current input，避免一次把全部文件装进string；`io.lines(path)`在正常EOF后关闭自己打开的文件。流式读取限制raw bytes memory，却不能限制frequency table，因为unique vocabulary仍可能随input增长。还需设置最大bytes、lines、line length、tokens和unique words。

Lua pattern classes按bytes和locale工作，不是Unicode word-break algorithm。教学示例可用`%w+`，生产多语言文本应使用Unicode-aware tokenizer、normalization与case folding library。Lowercase应在计数前进行，确保`Lua`与`LUA`是否合并由显式policy决定；locale变化可能改变`%a`与`string.lower`。

```lua
local function words_in(line)
  return coroutine.wrap(function()
    for token in string.gmatch(line, "%w+") do
      coroutine.yield(string.lower(token))
    end
  end)
end

local sample = {}
for word in words_in("Lua, LUA and lua_53") do
  sample[#sample + 1] = word
end
assert(sample[1] == "lua" and sample[2] == "lua")
```

Coroutine不是完成此任务的唯一方式，直接gmatch loop更轻；这里用它把tokenizer封装为iterator。API要声明underscore和digits是否属于word。若需要apostrophe、hyphen或CJK segmentation，pattern会变成product rule，不能用“看起来像词”验收。

## Counting word frequencies with tables

Counts table以normalized word为key、positive integer为value。更新惯用`counts[word] = (counts[word] or 0) + 1`，因为missing key为nil；这要求table只存counts，绝不能把false混入。<Term def="每处理一个token，总频次恰增一，已有key保持正整数，新key使unique count恰增一，所有keys已规范化的计数约束。">frequency-table invariant</Term>可让错误定位到单次update。

同时维护`total`与`unique`，就能检查`sum(counts)==total`且table entry数等于unique。Counter接近`math.maxinteger`时必须拒绝、saturate或切换representation；Lua integer overflow不能成为合法频次。Untrusted input还要限制key length，避免少量超长tokens占满memory。

```lua
local function add_word(state, word)
  assert(type(word) == "string" and word ~= "")
  local previous = state.counts[word]
  if previous == nil then
    assert(state.unique < state.max_unique, "vocabulary-limit")
    state.unique = state.unique + 1
    previous = 0
  end
  assert(previous < math.maxinteger, "counter-overflow")
  state.counts[word] = previous + 1
  state.total = state.total + 1
end

local state = { counts = {}, total = 0, unique = 0, max_unique = 1000 }
for word in string.gmatch("red blue red", "%a+") do add_word(state, word) end
assert(state.total == 3 and state.unique == 2 and state.counts.red == 2)
```

<Term def="输入处理在bytes、lines、tokens、token length、unique keys、counter range与elapsed time上设置可观测上限的资源协议。">streaming input budget</Term>让“逐行读取”真正bounded。超限时应返回partial/failed状态，不把截断结果冒充完整报告；若允许approximation，算法和error bound必须另行标注。

## Collecting keys for ranking

Table按word查count高效，但`table.sort`只排序proper sequence，因此先遍历`pairs(counts)`把keys放进words array。Pairs order unspecified，不过这不应影响最终结果，只要sort comparator为所有不同keys给出complete deterministic order。

收集keys是O(vocabulary)额外memory。数据很大且只需small k时可维护bounded heap，但Lua标准库不带heap；是否值得实现取决于profile。全量sort通常O(v log v)，清晰且适合教学。任何优化都必须保持同一tie policy和top-k cutoff。

## Sorting and reporting the most frequent words

Primary order是count descending。Equal counts若不加secondary key，`table.sort`不保证stable，输入sequence又来自unordered pairs，报告会漂移。<Term def="Comparator先按count降序，再以word或另一个稳定key完全消除equal-count歧义的确定性顺序。">deterministic frequency tie-break</Term>使snapshot、cache和用户分页可复现。

Comparator必须strict：同一个word与自身比较返回false；不能使用greater-or-equal。若word comparison受locale影响，固定byte lexical order或使用versioned collation key。Sort期间counts不可修改，否则comparator可能违反transitivity。

```lua
local function top_words(counts, limit)
  assert(math.type(limit) == "integer" and limit >= 0)
  local words = {}
  for word in pairs(counts) do words[#words + 1] = word end

  table.sort(words, function(left, right)
    local left_count, right_count = counts[left], counts[right]
    if left_count == right_count then return left < right end
    return left_count > right_count
  end)

  local report = {}
  for rank = 1, math.min(limit, #words) do
    local word = words[rank]
    report[rank] = { rank = rank, word = word, count = counts[word] }
  end
  return report
end

local report = top_words({ lua = 3, code = 2, book = 2 }, 10)
assert(report[2].word == "book" and report[3].word == "code")
```

<Term def="Top-k API明确k的type/range、equal-count cutoff、少于k项、output schema与format escaping的报告边界。">top-k reporting boundary</Term>要求data与printing分离。先返回records，再由CLI/JSON/UI formatter处理delimiter、Unicode与alignment；直接`print(word,count)`难以测试escaping和schema。

## End-to-end failure与验证

完整程序还要组合I/O error、tokenizer error、budget exceed、sort allocation和output failure。读取失败时不能继续打印“完整top words”；可返回status加已处理bytes，但report必须标partial。Output写入pipe可能在close时失败，照第7章检查close outcome。

Property tests可生成tokens list，直接构造expected counts，再比较streaming pipeline；所有report counts之和不一定等于total，因为只输出top k，但每个record必须与counts一致、order严格符合comparator。Golden tests则固定policy version、input bytes与完整report。

## 本章回顾：词频答案由Policy与Invariant共同定义

1. Io.lines与gmatch形成stream，但raw input、token count与unique vocabulary都要设预算。
2. Tokenization明确character model、case、punctuation、digits、locale和invalid input。
3. Frequency table每个token恰加一，counts为positive integers，total与unique提供交叉检查。
4. Pairs只用于收集keys，不提供报告order；sort comparator需count descending加完整tie-break。
5. Top-k明确k range、cutoff ties与output schema，并把data generation和formatting分离。
6. 失败或截断结果必须标partial，不能冒充完整统计。

<Exercises>

**问题 1：为什么逐行读取仍可能Memory Exhaustion？**

<Answer>Line streaming只限制当前raw text，counts table仍为每个unique normalized token保存key与counter；攻击者可发送无限不同长词。限制bytes、token length、token count和max unique，超限返回明确失败或使用标注误差的approximate algorithm。</Answer>

**问题 2：怎样保证Equal Count的报告每次相同？**

<Answer>把keys收集进sequence后，用strict comparator：count不同时降序，相同时按固定word byte order升序。不要依赖pairs或stable sort，也不要用greater-or-equal。对全同频输入反复随机插入顺序做property test。</Answer>

**问题 3：Top 10只有7个Unique Words时应该怎样输出？**

<Answer>先验证k为non-negative integer，再迭代到`math.min(k,#words)`，返回7条records；不要补nil items。若产品要求“第10名同频全部包含”，那是另一种include-all-ties contract，需在cutoff处扩展并可能超过k。</Answer>

</Exercises>
