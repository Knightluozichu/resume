## 为什么Coroutine首先是可暂停的Control Flow

Coroutine保留自己的Lua stack和locals，可在`yield`处暂停，再从同一点继续。它不是OS thread：不会抢占、不并行执行CPU code，也不自动等待socket。谁调用resume，谁决定何时运行；coroutine只有主动yield或结束才交回控制。

先预测：create后body是否执行；first resume arguments去哪里；yield values由谁接收；next resume arguments在coroutine里是什么；function正常返回后status；error是否由resume抛出；同一coroutine能否两个owners交错resume；long loop不yield会不会阻塞其它tasks。先画状态与数据箭头。

要求每个task只有一个scheduler owner，避免double resume与资源归属不清。

## Coroutine Basics

`coroutine.create(function)`创建suspended coroutine，不执行body。`coroutine.resume(co,args...)`第一次把args传给function parameters；成功返回true加yielded或final returned values，失败返回false加error object。`coroutine.status`观察suspended/running/normal/dead。

与pcall类似。正常业务首结果false仍是`true,false,...`。Failed/returned coroutine变dead，再resume返回failure。

```lua
local worker = coroutine.create(function(initial)
  local command, value = coroutine.yield("ready", initial * 2)
  assert(command == "add")
  return value + 1, "done"
end)

local ok, state, doubled = coroutine.resume(worker, 5)
assert(ok and state == "ready" and doubled == 10)
assert(coroutine.status(worker) == "suspended")

local finished, result, tag = coroutine.resume(worker, "add", 20)
assert(finished and result == 21 and tag == "done")
assert(coroutine.status(worker) == "dead")
assert(not coroutine.resume(worker))
```

Yield call在next resume时返回其arguments，因此数据是双向的。Error不会自动带完整cross-coroutine traceback；失败时结合`debug.traceback(co,error)`保存诊断，且不要丢弃coroutine identity后再找。


## Who Is the Boss?

Lua coroutines是asymmetric：resume从caller转入coroutine，yield只能回到直接resumer。让producer/consumer可反转：producer每次yield item，consumer决定何时请求下一项。

`coroutine.wrap(fn)`返回普通function，调用时内部resume；yield/return values直接成为wrapper results，error通常传播。它更简洁，但隐藏thread identity/status，scheduler需要取消、trace和inspection时优先create/resume。

Yieldability受C/API boundary影响：不是所有host callbacks允许从其下层yield；Lua C continuation API可显式支持。Library若可能yield必须声明，caller protected/host boundary需测试目标runtime。


## Coroutines as Iterators

Factory创建coroutine，遍历逻辑每发现item就yield；wrapper function每次resume并返回item。比手写state machine直观，但每itemresume有成本。

```lua
local function tree_values(root)
  return coroutine.wrap(function()
    local function visit(node)
      if not node then return end
      visit(node.left)
      coroutine.yield(node.value)
      visit(node.right)
    end
    visit(root)
  end)
end

local tree = { value = 2, left = { value = 1 }, right = { value = 3 } }
local output = {}
for value in tree_values(tree) do output[#output + 1] = value end
assert(table.concat(output, ",") == "1,2,3")
```

Generic for以首nil终止，因此iterator不能yield nil作为item control；用index/tag加data。Loop提前break会遗留suspended coroutine及captured resources，纯memory traversal可由GC处理，file/socket iterator必须显式close/cancel owner。

Recursive traversal仍可能Lua stack overflow；coroutine不消除其内部recursion depth。Untrusted tree用explicit stack与node/depth budget。

## Event-Driven Programming

Coroutine让async workflow写成linear code：task发出I/O request descriptor并yield；event loop注册socket/timer，ready后resume task并传result。把host I/O和业务control分离。

Scheduler必须使用non-blocking APIs；一个blocking DNS/file/socket call会阻塞所有tasks。Fairness要求每次resume做bounded work，ready queue轮转；backpressure限制queued tasks、buffers和outstanding requests。Timeout/cancel是typed resume result，task在finally-style path关闭资源。

```lua
local function await(kind, resource)
  local ok, value = coroutine.yield({ kind = kind, resource = resource })
  if not ok then error(value, 0) end
  return value
end

local task = coroutine.create(function()
  local payload = await("read", "socket-1")
  return #payload
end)

local started, request = coroutine.resume(task)
assert(started and request.kind == "read")
local resumed, length = coroutine.resume(task, true, "hello")
assert(resumed and length == 5 and coroutine.status(task) == "dead")
```

示例只演示request/response；真实dispatcher验证descriptor、保存task到wait set、poll readiness、清理registration并处理resume false。Task error不能让整个event loop退出，除非policy如此；日志保留task trace与operation ID。


## Errors、Cancellation与Structured Lifetime

Scheduler为task建立parent/owner，child tasks在scope结束前完成或cancel，避免detached work持有资源。Cancel不能强杀任意Lua instruction；cooperative task在yield/resume boundary接收cancel，CPU loop需instruction hook/隔离runtime。

Task error状态dead，resume返回error；捕获trace、remove wait registration、close resources、通知parent。Cleanup自身失败附加而不覆盖primary。Coroutine object被GC不等于业务task完成。

## 本章回顾：Coroutine把Stack变成Scheduler管理的State

1. Create只创建suspended task；resume首boolean区分执行成功，后续为yield/return或error。
2. Yield values流向resumer，next resume arguments成为yield results，形成双向协议。
3. Lua coroutine不抢占，resumer掌握调度；wrap简洁但隐藏status和thread identity。
4. Coroutine iterator保存复杂traversal stack，提前break时仍要处理captured resources。
5. Event task yield typed request，scheduler负责non-blocking wait、fairness、timeout、cancel和cleanup。
6. Coroutines提供concurrency而非parallelism，blocking call和CPU loop仍会阻塞。
