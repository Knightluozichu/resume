## 为什么Reflection首先是Capability边界

Lua通常保护函数的局部变量、调用栈和closure状态；`debug`库却能穿过这些边界，读取甚至改写运行中的程序。它适合debugger、profiler、coverage和受控诊断，不是普通业务代码的依赖。代码若必须靠stack level或local index才能工作，重构一个wrapper就可能改变语义。

先预测：`debug.getinfo(1)`里的level 1是谁；同名local在不同frame是否同一slot；修改upvalue会影响几个closures；suspended coroutine能否读取；hook是否归属于thread；删掉`os`和`io`后为何仍未形成安全sandbox。把每个API标成read metadata、read state、write state或control execution。

意味着“方便诊断”和“可交给不可信脚本”是两种相反的设计目标。

## Introspective Facilities

`debug.getinfo([thread,] function-or-level, what)`返回信息table。传function观察静态信息；传stack level观察某个active frame。`what`选择字段，例如`S` source、`l` current line、`n` name、`u` parameter/upvalue信息、`f` function、`L` valid lines；只请求所需字段，避免在高频路径中制造额外table和line集合。

不能作为长期identity。函数名也不是function固有属性，Lua常从调用上下文推断，匿名函数或间接调用可能没有可靠name。

```lua
local function describe(level)
  local info = assert(debug.getinfo(level + 1, "Slnu"))
  return {
    source = info.short_src,
    line = info.currentline,
    name = info.name or "<anonymous>",
    upvalues = info.nups,
  }
end

local function work()
  local frame = describe(1)
  assert(frame.source and frame.line > 0)
  return frame
end

work()
```

`debug.traceback([thread,] message, level)`是面向诊断的stack snapshot；错误发生时尽早保存。Source、line和name来自debug metadata，发布时剥离路径或敏感参数，避免诊断本身泄露host结构。


## Accessing local variables

`debug.getlocal([thread,] level, index)`返回local name和value；没有该slot时返回nil。正索引遍历parameters和locals，负索引可访问相应frame的varargs。`debug.setlocal`按同样坐标写值并返回name。编译器生成或不可命名slot可能显示临时名称，变量超出live range后不会因为源码里出现过就可读取。

不是变量的稳定handle。若先resume coroutine再拿旧level/index写入，目标可能已经改变或消失。

```lua
local function inspect_first_local(level)
  local name, value = debug.getlocal(level + 1, 1)
  if name then return { name = name, value = value } end
  return nil
end

local function calculate(input)
  local doubled = input * 2
  local first = inspect_first_local(1)
  assert(first ~= nil)
  return doubled
end

assert(calculate(4) == 8)
```

Debugger展示locals时要限制深度、数量和string长度；直接递归格式化table会触发巨大图、cycle，甚至调用有副作用的metamethod。诊断器应以raw、bounded、cycle-aware方式编码。

## Accessing non-local variables

Closure把外层local捕获成upvalue。`debug.getupvalue(function, index)`返回name/value，`debug.setupvalue`改写cell；`debug.upvalueid`可判断两个closures是否共享同一cell，`debug.upvaluejoin`能让一个upvalue改为共享另一个cell。

解释了为什么修改一个counter的upvalue会影响共享该cell的closure。`upvaluejoin`是instrumentation级手术，索引随function实现变化，不应作为模块公开协议。

```lua
local function counter()
  local n = 0
  return function(delta)
    n = n + (delta or 1)
    return n
  end
end

local next_value = counter()
local name, value = debug.getupvalue(next_value, 1)
assert(name == "n" and value == 0)
assert(debug.setupvalue(next_value, 1, 10) == "n")
assert(next_value() == 11)
```

热修复若替换upvalue，必须验证name、function source/version和cell sharing，再做原子切换与rollback；仅凭index 1可能改到不同构建中的另一个capture。


## Accessing other coroutines

多个debug API接受可选thread参数，可读取另一个Lua coroutine的stack、info和locals。最可靠的检查点是task已经yield、处于suspended状态且scheduler暂不resume；此时frame不会在采集中途变化。Dead coroutine通常没有可用执行栈，running current coroutine用普通形式即可。

要求scheduler持有唯一owner。不要一边异步展示旧snapshot，一边允许用户按旧level写回新frame。

生产诊断应把thread ID、status、wait reason、top frames和bounded locals复制成普通data，然后立即释放暂停；不要把thread或live values暴露到远程console。`debug.traceback(co)`可补全跨task错误，但需把resumer关系和operation ID另行记录，因为coroutine stacks彼此独立。

## Hooks

`debug.sethook([thread,] hook, mask, count)`为指定thread安装hook；mask包含`c` call、`r` return、`l` line，正count产生instruction-count事件。Hook收到event和可选line。`debug.gethook`读取当前配置；传空参数关闭hook。

必须实测。Line hook通常比低频count sampling昂贵；hook内不做blocking I/O、不遍历对象图、不调用会再次触发复杂路径的代码，也不依赖yield。回调只写预分配buffer或轻量counter，重处理放到安全点。


## Profiles

Profile先回答问题再选机制。Call hook可统计调用次数；call/return配对可估算inclusive time，但tail calls、C functions、errors和coroutine切换需要单独归属。Count/line sampling以较低频率观察当前frame，可近似热点，却不是精确逐函数计时。

基准流程是固定workload和warm-up，先测无hook baseline，再测instrumented run，多次重复并报告分布与observer tax。Wall time包含等待，CPU time未必；coroutine-based server还要按task与operation区分等待时间和running time。Profiler自己的allocation、table lookup和clock call也应进入开销预算。

## Sandboxing

Sandbox从最小capability开始：加载chunk时给出新environment，只放入纯函数和经过包装的domain APIs；不暴露`debug`、`package`、`require`、`io`、`os`、host globals、registry通道或能取回它们的closure。输入输出都做schema、size与authority检查。

Environment隔离不限制CPU、memory、stack、output、open handles或native call。Instruction hook提供Lua bytecode budget，host还需wall-clock cancellation、allocator/memory limit、I/O quota与并发上限。对敌对代码使用独立Lua state，强边界场景放入受OS限制的separate process，以窄IPC交换普通data。


## 本章回顾：Reflection必须由Host拥有

1. Getinfo观察function或frame metadata，stack level只是瞬时坐标。
2. Getlocal/setlocal访问live frame slot；getupvalue/setupvalue访问closure cell，两者都不是稳定业务schema。
3. Scheduler可在暂停resume时采集其他coroutine的bounded snapshot，并保存跨task ownership。
4. Hook提供call、return、line和count事件，但会改变被测程序，必须校准开销和re-entry风险。
5. Profiler要区分running、waiting、tail call、C function与coroutine归属，并报告baseline差异。
6. Sandbox不能只删globals；还要收紧capability、禁用debug、限制资源，并按威胁使用state/process isolation。
