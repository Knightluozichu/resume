## 为什么扩展Application先定义Host Policy

“用Lua扩展应用”意味着host决定何时创建state、加载哪些chunks、暴露哪些functions，以及Lua结果如何进入native domain。配置文件也是可执行代码；即使只想读取width和height，只要开放完整global environment，脚本就可能执行I/O、加载module或无限循环。

先预测：`lua_getglobal`遇到不存在名字会不会不push；读取number后忘记pop会怎样；`lua_getfield`是否触发`__index`；`lua_rawget`需要谁把key放到top；`lua_pcall(L,2,1,0)`前stack从下到上应是什么；返回string pointer在result pop后是否还能保存；generic signature解析到一半失败时如何恢复stack。

先于任何`lua_getglobal`调用。

## The Basics

经典用法让Lua chunk计算配置，再由C读取globals。Load与run仍是两步；只在`lua_pcall`成功后读取。下面helper接受已经创建的state并保持“成功或失败都恢复入口top”。

```c
static int load_config(lua_State *L, const char *path) {
  int base = lua_gettop(L);
  int status = luaL_loadfile(L, path);
  if (status == LUA_OK) status = lua_pcall(L, 0, 0, 0);
  if (status != LUA_OK) {
    const char *message = lua_tostring(L, -1);
    fprintf(stderr, "config: %s\n", message ? message : "unknown error");
  }
  lua_settop(L, base);
  return status == LUA_OK;
}

static int get_global_int(lua_State *L, const char *name, lua_Integer *out) {
  int base = lua_gettop(L), isnum = 0;
  lua_getglobal(L, name);
  lua_Integer value = lua_tointegerx(L, -1, &isnum);
  lua_settop(L, base);
  if (!isnum) return 0;
  *out = value;
  return 1;
}
```

读取API不能用0代表missing，因为0可能是合法配置。Host应区分missing、wrong type、out of range和valid，并在native对象commit前完成全部validation，避免半更新状态。

让多个配置读取可以安全组合。


## Table Manipulation

结构化配置通常放在table。`lua_gettable(L,index)`从top弹出key并push查询结果；table由index定位，先用`lua_absindex`避免push key改变负index。`lua_settable`弹出key和value。普通访问遵守`__index`/`__newindex`，因此可能执行Lua code并raise。

必须按信任边界选择。读取用户对象property可能需要ordinary semantics；解析data-only configuration通常偏向raw access和显式schema。

```c
static int get_window(lua_State *L, lua_Integer *width,
                      lua_Integer *height) {
  int base = lua_gettop(L), ok_width = 0, ok_height = 0;
  lua_getglobal(L, "window");
  if (!lua_istable(L, -1)) {
    lua_settop(L, base);
    return 0;
  }

  lua_getfield(L, -1, "width");
  lua_Integer w = lua_tointegerx(L, -1, &ok_width);
  lua_pop(L, 1);
  lua_getfield(L, -1, "height");
  lua_Integer h = lua_tointegerx(L, -1, &ok_height);
  lua_settop(L, base);
  if (!ok_width || !ok_height || w <= 0 || h <= 0) return 0;
  *width = w; *height = h;
  return 1;
}
```

Table可能有cycles、sparse integer keys和mixed key types；C侧遍历用`lua_next`时，保留table和current key，处理value后pop value但保留key给下一轮。遍历中随意转换key或修改table会破坏迭代契约。

## Some short cuts

`lua_getfield(L,t,"name")`等价于push string key再gettable的常用形式；`lua_geti`处理integer key。对应setter会消费top value。`lua_rawget`/`lua_rawset`使用stack key并绕过metamethod，`lua_rawgeti`/`lua_rawseti`处理integer key。Globals有`lua_getglobal`/`lua_setglobal`。


## Calling Lua Functions

C调用Lua function时，先push callable，再按顺序pusharguments，最后`lua_pcall(L,nargs,nresults,msgh)`。Call会消费function与arguments；成功push约定数量results，失败pusherror object。Function lookup本身也要验证，不能把nil当作callable交给pcall。

```c
static int call_distance(lua_State *L, double x, double y, double *out) {
  int base = lua_gettop(L), isnum = 0;
  lua_getglobal(L, "distance");
  if (!lua_isfunction(L, -1)) { lua_settop(L, base); return 0; }
  lua_pushnumber(L, x);
  lua_pushnumber(L, y);
  if (lua_pcall(L, 2, 1, 0) != LUA_OK) {
    fprintf(stderr, "%s\n", lua_tostring(L, -1));
    lua_settop(L, base);
    return 0;
  }
  double result = lua_tonumberx(L, -1, &isnum);
  lua_settop(L, base);
  if (!isnum) return 0;
  *out = result;
  return 1;
}
```

若要traceback，在call frame下方放message handler并把absolute index传给pcall，之后删除。返回table/string不能在pop后保留裸stack pointer；要么立刻复制成native owner，要么建立registry reference并明确定义release。

可用stack snapshot测试。

## A Generic Call Function

书中的通用思路用signature描述arguments和results，例如分隔符`>`之前是input specifiers，之后是output specifiers。实现必须先验证整个signature和output pointers，再检查stack capacity；随后push function/arguments、pcall、从后半签名逐项checked conversion，最终恢复base。

```c
/* Example contract: "dd>d" means two double inputs, one double output. */
int call_by_signature(lua_State *L, const char *function_name,
                      const char *signature, ...);

/* The helper owns no returned Lua pointers:
   numbers/booleans are copied, strings require caller buffers or references. */
double result = 0.0;
if (!call_by_signature(L, "distance", "dd>d", 3.0, 4.0, &result)) {
  report_script_failure();
}
```

不能边读`va_list`边修改stack后才发现非法specifier，否则难以rollback。Variadic C类型提升、NULL string、整数范围、result count和错误文本都要定义。


## Errors、Reentrancy与Ownership

普通table access和Lua call都可能执行Lua代码，进而error、yield（受调用边界限制）或re-enter host callbacks。Native helper不要持有不允许重入的锁跨越这些调用；host object先进入一致状态，再调用Lua。每个registry reference、buffer和native handle必须有单一owner与release path。

Generic helper适合少量稳定类型；复杂domain API应使用显式typed wrappers，错误更清楚，也能做range/schema validation。Signature不是安全边界，Lua函数仍只能获得policy允许的capabilities。

## 本章回顾：Extension是双向Typed Boundary

1. Host先定义环境、source、budget和conversion policy，再加载可执行配置。
2. Balanced lookup保存base，校验并复制value，所有分支恢复top；配置先transactional验证再commit。
3. Table get/set需追踪key与value的stack效果，并明确ordinary或raw metamethod semantics。
4. 从C调用Lua要构造function+arguments call frame，以pcall得到results或error并验证输出。
5. Stack string pointer不归host长期所有，跨pop生命周期要复制或registry-reference。
6. Generic signature helper是小型FFI，先完整parse，再调用并transactional写outputs。
