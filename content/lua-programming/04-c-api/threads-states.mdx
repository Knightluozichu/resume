## 为什么Threads and States先统一三个名词

Lua API中的thread通常指coroutine：它有独立execution stack，却与同一global state中的其它threads共享globals、registry、heap和GC。`lua_State *`既可指main thread也可指coroutine。独立调用`luaL_newstate`才创建另一套global state。OS thread则是native scheduler实体，三者不能混称。

先预测：两个Lua coroutines改同一global table是否互相可见；只有C pointer指向newthread、却把thread object从stack pop且不root，会不会安全；`lua_xmove`能否把table移到另一个`luaL_newstate`；两个OS workers能否同时进入同一state的不同coroutines；独立states间传function要复制什么；只开base/table/string库是否仍自动允许C module loader。

提供cooperative concurrency而不是memory isolation。

## Multiple Threads

`lua_newthread(L)`创建coroutine并把thread object压到parent stack，返回其`lua_State *`。C pointer不是GC root：若thread object被pop且没有registry/table reference，suspended coroutine可能被回收。Scheduler先`luaL_ref`保存thread，terminal后`luaL_unref`。

还应绑定task ID、owner和cancel state。

```c
typedef struct LuaTask { lua_State *thread; int ref; } LuaTask;

static LuaTask create_task(lua_State *L, const char *function_name) {
  LuaTask task = {0};
  task.thread = lua_newthread(L);       /* thread object is on L */
  task.ref = luaL_ref(L, LUA_REGISTRYINDEX); /* pop and root it */
  lua_getglobal(task.thread, function_name);
  if (!lua_isfunction(task.thread, -1)) {
    lua_settop(task.thread, 0);
    luaL_unref(L, LUA_REGISTRYINDEX, task.ref);
    task.thread = NULL; task.ref = LUA_NOREF;
  }
  return task;
}

static int resume_task(lua_State *owner, LuaTask *task, int nargs) {
  int status = lua_resume(task->thread, owner, nargs); /* Lua 5.3 API */
  if (status == LUA_YIELD) return status;
  /* LUA_OK: results; otherwise error object is on the child stack. */
  lua_settop(task->thread, 0);
  luaL_unref(owner, LUA_REGISTRYINDEX, task->ref);
  task->thread = NULL; task->ref = LUA_NOREF;
  return status;
}
```

生产scheduler在clear前复制results/error/traceback，并区分yield values和final results。Lua 5.4的`lua_resume`签名不同，本书面向Lua 5.3，编译时不能混用header/API。


## lua_xmove、Scheduling与Shared Heap

`lua_xmove(from,to,n)`在共享同一global state的threads之间移动top n values，常用于准备arguments或收集results。它不能跨independent states；目标stack需有capacity。Tables/userdata移动后仍是同一heap object，不是深拷贝。

必须在同一serialized owner上下文执行。一个OS threadresume时，另一个不得同时访问该state、registry或siblings。


## Lua States

每次`luaL_newstate`创建独立global state：不同heap、globals、registry、GC与allocator bookkeeping。两个states之间没有Lua object identity共享，close一个不应触碰另一个。Host可以把每个state绑定到不同OS worker，实现真正并行，但共享native service仍需同步和capability控制。

比coroutine强，但不是自动security sandbox：host暴露的C functions仍可共享process authority。

```c
typedef struct WorkerLua { lua_State *L; size_t memory_limit; } WorkerLua;

static WorkerLua create_worker(size_t memory_limit) {
  WorkerLua worker = {0};
  worker.memory_limit = memory_limit;
  worker.L = lua_newstate(limited_allocator, &worker);
  if (worker.L == NULL) return worker;
  /* Libraries are opened explicitly below, before the worker is published. */
  return worker;
}
```

State pointer和其Lua values不跨worker直接使用。Host shutdown先停止新messages、cancel tasks、在owner thread运行cleanup并`lua_close`，最后销毁queue/native context。

## Message passing between independent states

Independent states不能`lua_xmove`。跨state通信先把允许的Lua value编码成host-owned message，再在receiver构造新的Lua values。拒绝function、thread、full userdata和raw pointer；这些携带state或native identity。

```lua
-- Data-only envelope; each state gets a fresh decoded table.
local message = {
  version = 1,
  kind = "render-job",
  request_id = "job-1042",
  payload = { width = 1280, height = 720, samples = 64 },
}

-- Sender validates and encodes with byte/depth limits.
-- Receiver validates version/kind, then grants only its local capabilities.
```

Serializer处理nil/boolean/integer/number/string和受限tables，定义NaN/Infinity、integer range、duplicate keys、cycles与ordering。Queue必须bounded；full queue阻塞、拒绝或传播backpressure。Message completion/cancel用request ID和generation解决late response。


## Opening libraries on demand

`luaL_openlibs`打开完整标准库，适合trusted通用runtime；worker/sandbox应使用`luaL_requiref`逐个打开。Base、table、string、math、utf8、coroutine、package、io、os、debug各有不同authority。打开package会引入searchers/loaders，还需收紧`package.path/cpath`与C loader。

应进入state configuration version。

```c
static void open_worker_libraries(lua_State *L) {
  luaL_requiref(L, "_G", luaopen_base, 1); lua_pop(L, 1);
  luaL_requiref(L, LUA_TABLIBNAME, luaopen_table, 1); lua_pop(L, 1);
  luaL_requiref(L, LUA_STRLIBNAME, luaopen_string, 1); lua_pop(L, 1);
  luaL_requiref(L, LUA_MATHLIBNAME, luaopen_math, 1); lua_pop(L, 1);
  /* No package/io/os/debug or dynamic C loader for this worker policy. */
}
```

Base library本身也要审计可用functions；host可在open后删除不需要的globals，但更可靠的是构造allowlisted environment。Module按需加载可注册到受控preload table，不必允许filesystem/native搜索。

## Parallelism、Failure与Shutdown

Independent state crash/error应转成message failure，不持有另一个state的stack reference。Per-state memory limit、instruction/wall deadline、queue capacity和native service quota共同防止一个worker拖垮process。真正敌对任务仍需process isolation。

Shutdown顺序先停止accept，等待或cancel inflight messages，owner thread回收coroutines/registry refs/userdata，close state，再释放host queues。反序会产生late callback访问已关闭state。

## 本章回顾：Parallelism来自Isolation而非Coroutine数量

1. Lua thread只有stack/status独立，同一state内globals、registry、heap和GC全部共享。
2. Newthread object必须建立Lua root；C pointer本身不能阻止suspended coroutine被GC。
3. lua_xmove只在同一global state的threads之间搬引用，不能跨independent states。
4. 同一state由单一OS owner串行访问；独立states可分配到不同workers实现parallelism。
5. 跨state只传versioned bounded data messages，receiver重新构造values并授予本地capabilities。
6. Standard libraries按需开放，package/io/os/debug/C loader都属于明确policy，而非默认便利。
