- 掌握区块链的区块头结构与哈希链接机制
- 理解默克尔树在交易摘要与验证中的作用
- 领悟区块链不可篡改的密码学与经济学原理
- 学会 SPV 轻节点的 Merkle 路径验证方法

## 核心概念

### 区块结构

每个区块由区块头和区块体组成。区块头是 80 字节的固定摘要，包含：

- **PrevHash**：前一个区块的哈希，形成链式结构
- **MerkleRoot**：区块内所有交易的默克尔根
- **Nonce**：PoW 随机数
- **难度目标**：当前 PoW 目标值
- **时间戳**：出块时间
- **版本号**：协议版本

区块体包含该区块打包的所有交易。矿工对区块头进行 PoW 哈希竞争。

### 哈希链接

每个区块的 PrevHash 指向前一个区块的哈希，形成一条不可断裂的链。修改任何区块的内容会导致其哈希变化，进而使后续所有区块的 PrevHash 失效。这是区块链不可篡改的结构基础。

### 默克尔树

默克尔树将区块内所有交易两两哈希、逐层向上合并，最终生成一个根哈希（MerkleRoot）存入区块头。它的三大作用：

1. **高效验证**：验证某交易是否在区块中只需 log(n) 个哈希组成的 Merkle 路径
2. **篡改检测**：任何交易被篡改都会导致 MerkleRoot 变化，篡改立即暴露
3. **轻节点支持**：SPV 轻节点只需区块头即可验证交易

### 不可篡改原理

篡改比特币区块链的代价极高：

1. 篡改任意交易 → MerkleRoot 变化
2. → 区块哈希变化
3. → 后续所有区块的 PrevHash 失效
4. → 需重新计算所有后续区块的 PoW
5. → 计算量超过全网算力，实际不可行

链越长、确认数越多，篡改难度越大。这是密码学（哈希链）与经济学（PoW 算力成本）的双重保障。

### SPV 轻节点验证

SPV（简化支付验证）轻节点只下载区块头（约 50MB），不存完整交易。验证流程：

1. 向全节点请求目标交易的 Merkle 路径
2. 用 Merkle 路径重新计算 MerkleRoot，与区块头比对
3. 检查该区块在最长链中且有足够确认数

SPV 以极低存储代价实现交易验证，适合手机钱包等资源受限场景。

|------|------|
| 区块头 | 区块的 80 字节固定摘要 |
| PrevHash | 前一个区块的哈希 |
