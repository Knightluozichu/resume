## 学习目标

- 掌握比特币交易的基本结构（输入、输出、其他字段）
- 理解 UTXO 模型与账户模型的本质区别
- 学会解锁脚本与锁定脚本的配合验证机制
- 区分 P2PKH、P2SH、P2WPKH 三种脚本类型

## 核心概念

### 交易结构

一笔比特币交易由三部分组成：

**输入（Inputs）**：引用前一笔 UTXO，包含 txid（前一笔交易 ID）、vout（输出索引）和解锁脚本（提供签名和公钥证明拥有该 UTXO 的花费权）。

**输出（Outputs）**：创建新的 UTXO，包含锁定脚本（定义花费条件）和金额。每个输出成为一个新的未花费交易输出。

**其他字段**：版本号（协议版本）、锁定时间（延迟生效）、见证数据（SegWit 签名）。

### UTXO 模型

比特币没有账户和余额的概念。资金以「未花费交易输出」（UTXO）的形式存在。每笔交易消费若干 UTXO 作为输入，创建若干新 UTXO 作为输出。

关键规则：
- UTXO 一次性消费，不可部分花费（需找零）
- 输入总额 = 输出总额 + 手续费
- 脚本定义花费条件，而非账户余额

### 脚本系统

比特币使用基于栈的脚本语言定义花费条件：

**锁定脚本（ScriptPubKey）**：附加在输出上，定义花费该 UTXO 的条件。

**解锁脚本（ScriptSig）**：附加在输入上，提供满足条件的证明（签名+公钥）。

验证时将解锁脚本和锁定脚本拼接执行，结果为 TRUE 则交易有效。以 P2PKH 为例，解锁脚本提供签名和公钥，锁定脚本验证公钥哈希匹配后用 OP_CHECKSIG 验证签名。

### 常见脚本类型

- **P2PKH**（支付到公钥哈希）：最常见，1 开头地址，锁定脚本为 OP_DUP OP_HASH160 公钥哈希 OP_EQUALVERIFY OP_CHECKSIG
- **P2SH**（支付到脚本哈希）：支持多签等复杂脚本，3 开头地址，收款方只需提供脚本哈希
- **P2WPKH**（隔离见证公钥哈希）：bc1 开头，见证数据移出脚本，手续费更低

### 手续费机制

手续费 = 输入总额 - 输出总额。矿工优先打包手续费率（sat/byte）高的交易。手续费激励矿工维护网络，也是反垃圾交易的经济学屏障。SegWit 交易将见证数据以折扣方式计入权重，实际降低了手续费。

## 术语表

| 术语 | 含义 |
|------|------|
| UTXO | 未花费交易输出 |
| txid | 交易唯一标识符 |
| 锁定脚本 | 定义 UTXO 花费条件 |
| 解锁脚本 | 提供花费证明 |
| OP_CHECKSIG | 验证签名的脚本操作码 |
| 手续费 | 输入与输出差额，归矿工所有 |
| 见证数据 | 签名数据（SegWit 中独立存储） |
