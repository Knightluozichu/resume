## 核心概念

### 去中心化网络拓扑

比特币网络是一个对等（P2P）网络，没有中央服务器。每个节点既是客户端也是服务器，与相邻节点直接通信。节点通过 addr 消息发现新节点，建立连接后通过 Gossip 协议传播交易和区块。

### 节点类型

比特币网络中有三种节点：

**全节点（Full Node）**：存储完整区块链（约 500GB），独立验证所有交易和区块，不依赖第三方信任。全节点是网络的骨干，维护着完整的账本副本。

**矿工节点（Miner）**：全节点加挖矿功能，收集交易并竞争出块，获得区块奖励和手续费。矿工节点在验证能力上与全节点相同，额外增加了 PoW 计算。

**SPV 轻节点（Light）**：只存区块头（约 50MB），用 Merkle 证明验证交易。手机钱包常用此模式。SPV 在安全性与资源之间做了取舍，牺牲部分安全性换取极低存储。

### Gossip 传播

节点收到新交易或区块后的传播流程：

1. 先验证有效性
2. 向相邻节点发送 inv 消息通告哈希
3. 邻居节点未见过该哈希则回复 getdata 请求完整数据
4. 收到数据后验证并继续向其他邻居通告

这种洪泛式传播确保交易和区块在几秒内扩散到全网。每个节点独立验证，不信任任何来源。

### 关键 P2P 消息

| 消息 | 作用 |
|------|------|
| version | 握手与版本协商 |
| inv | 通告交易或区块哈希 |
| getdata | 请求具体数据内容 |
| tx / block | 传输交易或区块数据 |
| addr | 节点发现，交换已知节点地址 |

### 安全性与信任模型

全节点和 SPV 轻节点在安全模型上有本质区别：

- **全节点**：独立验证一切，安全性最高，但存储和带宽开销大
- **SPV 轻节点**：通过 Merkle 证明验证交易是否在区块中，但无法验证交易合法性（如双花），需信任全节点提供的证明和最长链

SPV 适合移动设备等资源受限场景，是在安全性与实用性之间的合理取舍。
