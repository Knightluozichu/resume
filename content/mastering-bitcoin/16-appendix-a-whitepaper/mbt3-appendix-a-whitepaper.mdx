## 为什么从可验证状态开始

白皮书提出用数字签名、点对点传播和累计PoW解决无需中央铸币机构的双重支付。第三版附录保留原文用于历史坐标，理解时还要结合后续协议实现和勘误，不能把简化描述当当前全部规则。

比特币最容易被界面和术语掩盖：钱包余额是UTXO视图，地址是脚本编码，交易哈希只是候选对象标识，矿工出块也不代表全节点必须接受。要判断实现是否正确，必须追踪前状态、被引用输出、规范序列化、脚本与签名、节点策略、区块承诺、累计工作量和后状态。只保存最终余额或区块高度，会漏掉错误网络、冲突交易、脚本失败、重组与索引视图滞后。

本页先手算最小实例，再运行工具。正常样本证明主路径；边界样本取零值、最大金额、恰好费用、最短证明或时间锁边界；单故障样本只改变网络前缀、字节、签名、outpoint、脚本、target或确认中的一项。三组样本共享源码标签、节点、创世状态和观察点，使首个差异可以归因，而不是靠重复广播或刷新页面碰运气。

每次实验生成机器可读证据：官方印刷标签、软件提交、网络与创世哈希、输入原文、解析对象、验证结果、错误、前后UTXO或链状态和确认区块。独立复核者从空目录重放，若字段缺失、节点未同步或结果绑定到不同哈希，门禁明确失败。涉及密钥的示例只使用公开测试向量、regtest或signet，不把教学代码连接真实资产。

官方标题层级还要转成可检查任务：章标题定义端到端目标，节标题定义机制与对象，小节标题定义算法、字段、异常或部署选择。每个标题至少对应一个输入、一个不变量、一个可观察结果和一个失败样本；多个标题可以共享实验环境，但不能因主题相近而合并掉独立语义。这样既保留原书结构，也让读者能从目录逐项证明掌握程度。

**现象 →** 把白皮书当当前比特币协议的完整规格直接套用。
**原因 →** 白皮书是设计起点，后续 BIP 与实现修正了许多细节。
**修法 →** 以白皮书为历史坐标，共识细节交叉验证 BIP 与 Bitcoin Core。

**现象 →** 以为 SPV 证明了交易就等于交易有效。
**原因 →** SPV 只证明交易被有工作量区块承诺，不独立验证全部规则。
**修法 →** 区分包含证明与规则验证，SPV 还依赖同伴诚实提供数据。你可以亲自试一下：用 SPV 验证一笔被同伴遗漏的交易，观察是否能发现数据缺失。

**现象 →** 把白皮书的 PoW 概率计算当成精确安全保证。
**原因 →** 计算基于独立性等简化假设，真实出块是高方差过程。
**修法 →** 复算时显式标明假设，短期出块用统计区间而非确定值。

## 小结

- 白皮书用签名链、时间戳与 PoW 网络解决双重支付
- 它是设计起点，当前规则需结合实现与勘误交叉验证
- PoW 要求区块头哈希小于 target，难度周期调整速率
- SPV 用区块头链与 Merkle 证明但不验证全部规则
- 通过标准：能从所有权链推导到 PoW 选择与 SPV 证明

def select_chain(chains):
    cumulative = [sum(c) for c in chains]
    best = max(range(len(cumulative)), key=lambda i: cumulative[i])
    return {
        "best_index": best,
        "cumulative_work": cumulative[best],
        "all": cumulative,
    }

chains = [[1, 1, 1], [1, 1, 1, 1], [1, 1]]

assert result["best_index"] == 1
