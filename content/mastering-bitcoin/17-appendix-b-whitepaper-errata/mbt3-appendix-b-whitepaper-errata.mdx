## 为什么从可验证状态开始

勘误不是否定白皮书，而是把概念模型与实际共识、网络和隐私行为对齐。每条修正要标明原主张、隐藏假设、反例、当前规则和验证方法，防止二手表述继续放大误差。

比特币最容易被界面和术语掩盖：钱包余额是UTXO视图，地址是脚本编码，交易哈希只是候选对象标识，矿工出块也不代表全节点必须接受。要判断实现是否正确，必须追踪前状态、被引用输出、规范序列化、脚本与签名、节点策略、区块承诺、累计工作量和后状态。只保存最终余额或区块高度，会漏掉错误网络、冲突交易、脚本失败、重组与索引视图滞后。

本页先手算最小实例，再运行工具。正常样本证明主路径；边界样本取零值、最大金额、恰好费用、最短证明或时间锁边界；单故障样本只改变网络前缀、字节、签名、outpoint、脚本、target或确认中的一项。三组样本共享源码标签、节点、创世状态和观察点，使首个差异可以归因，而不是靠重复广播或刷新页面碰运气。

每次实验生成机器可读证据：官方印刷标签、软件提交、网络与创世哈希、输入原文、解析对象、验证结果、错误、前后UTXO或链状态和确认区块。独立复核者从空目录重放，若字段缺失、节点未同步或结果绑定到不同哈希，门禁明确失败。涉及密钥的示例只使用公开测试向量、regtest或signet，不把教学代码连接真实资产。

官方标题层级还要转成可检查任务：章标题定义端到端目标，节标题定义机制与对象，小节标题定义算法、字段、异常或部署选择。每个标题至少对应一个输入、一个不变量、一个可观察结果和一个失败样本；多个标题可以共享实验环境，但不能因主题相近而合并掉独立语义。这样既保留原书结构，也让读者能从目录逐项证明掌握程度。

## 正常、边界与故障矩阵

| 样本   | 只改变的变量                    | 预期结果               | 必存证据                     |
| ------ | ------------------------------- | ---------------------- | ---------------------------- |
| 正常   | 有效UTXO、脚本、费用与网络      | 状态转移并达到确认条件 | 原始对象、前后状态、区块哈希 |
| 边界   | 零值、最大值、恰好阈值或时间锁  | 按明确规则接受或拒绝   | 边界值、判断分支、资源成本   |
| 单故障 | 网络、字节、签名、引用或PoW一项 | 首个无效规则处拒绝     | 错误、首差、原状态与回退点   |

先写出预期字节、栈、金额或哈希，再运行节点和解析器。若钱包、区块浏览器与本地节点给出不同答案，以固定网络上的原始交易、被花费输出、区块头和本地共识验证为坐标；第三方展示不能覆盖本地可验证事实。

## 容易踩的坑

**现象 →** 把勘误当成否定白皮书，全盘推翻原始模型。
**原因 →** 勘误是对齐概念模型与实际行为，不是否定设计起点。
**修法 →** 每条修正标明原主张、隐藏假设、反例、当前规则与验证方法。

**现象 →** 用新术语简单覆盖历史表述，不说明影响范围。
**原因 →** 缺乏对原假设与实现行为的逐项对照，修正失去可追溯性。
**修法 →** 修正引用当前共识或可复算数据并明确影响范围。你可以亲自试一下：对一条勘误列出原主张与当前规则两列，检验是否每项都能落到证据。

**现象 →** 把白皮书概率计算当成精确结论直接引用。
**原因 →** 原计算隐含独立性等假设，实现行为有偏差。
**修法 →** 复算时拆出假设、公式与实现行为，用反例标明边界。

## 小结

- 勘误不是否定白皮书而是对齐概念模型与实际行为

- 修正引用当前共识或可复算数据并明确影响范围
- 概率计算须拆假设、公式与实现行为再复算
- 通过标准：为七类勘误建原主张-修正-证据-影响表

def make_erratum(original, assumption, counterexample, current_rule):
    entry = {
        "original": original,
        "assumption": assumption,
        "counterexample": counterexample,
        "current_rule": current_rule,
    }
    missing = [k for k, v in entry.items() if not v]
    return {"entry": entry, "pass": not missing, "missing": missing}
