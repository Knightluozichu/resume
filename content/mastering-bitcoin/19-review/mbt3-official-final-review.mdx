## 为什么从可验证状态开始

全书验收不以背诵BIP和命令结束，而以可审计状态轨迹证明：密钥只在受控边界签名，交易满足价值和脚本规则，区块满足PoW与链选择，钱包可恢复，二层参与者可按合同退出。

比特币最容易被界面和术语掩盖：钱包余额是UTXO视图，地址是脚本编码，交易哈希只是候选对象标识，矿工出块也不代表全节点必须接受。要判断实现是否正确，必须追踪前状态、被引用输出、规范序列化、脚本与签名、节点策略、区块承诺、累计工作量和后状态。只保存最终余额或区块高度，会漏掉错误网络、冲突交易、脚本失败、重组与索引视图滞后。

本页先手算最小实例，再运行工具。正常样本证明主路径；边界样本取零值、最大金额、恰好费用、最短证明或时间锁边界；单故障样本只改变网络前缀、字节、签名、outpoint、脚本、target或确认中的一项。三组样本共享源码标签、节点、创世状态和观察点，使首个差异可以归因，而不是靠重复广播或刷新页面碰运气。

每次实验生成机器可读证据：官方印刷标签、软件提交、网络与创世哈希、输入原文、解析对象、验证结果、错误、前后UTXO或链状态和确认区块。独立复核者从空目录重放，若字段缺失、节点未同步或结果绑定到不同哈希，门禁明确失败。涉及密钥的示例只使用公开测试向量、regtest或signet，不把教学代码连接真实资产。

官方标题层级还要转成可检查任务：章标题定义端到端目标，节标题定义机制与对象，小节标题定义算法、字段、异常或部署选择。每个标题至少对应一个输入、一个不变量、一个可观察结果和一个失败样本；多个标题可以共享实验环境，但不能因主题相近而合并掉独立语义。这样既保留原书结构，也让读者能从目录逐项证明掌握程度。

## 核心约束与推导

$$
\sum value(inputs)=\sum value(outputs)+fee
$$

$$
H_i=hash(H_{i-1} \Vert merkle(T_i) \Vert metadata_i)
$$

$$
S_{t+1}=apply(S_t,T_t), \quad valid(T_t,S_t)=1
$$

$$
gate=source \times version \times replay \times boundary \times failureEvidence
$$

前两式对应本页的密码、交易、费用、网络、区块或二层核心不变量。状态转移式要求候选对象先通过当前状态验证，再原子地产生后状态；失败保留原状态。证据门禁使用乘法语义，来源、版本、重放、边界或失败证据任一缺失，整条结论都不能发布。

```typescript
type Evidence = {
  version: string;
  before: string;
  input: string;
  after?: string;
  error?: string;
};

function evidenceGate(run: Evidence) {
  const complete = Boolean(
    run.version && run.before && run.input && (run.after || run.error),
  );
  return { complete, page: "mbt3-official-final-review", run };
}
```

```python
def apply_candidate(state, candidate, verify):
    if not verify(state, candidate):
        return {"accepted": False, "state": state, "reason": "invalid"}
    next_state = state.copy()
    next_state.update(candidate["changes"])
    return {"accepted": True, "state": next_state, "reason": None}
```

```python
def verify_value_conservation(inputs, outputs, fee):
    if len(inputs) != len({item["outpoint"] for item in inputs}):
        return False
    return sum(item["value"] for item in inputs) == sum(outputs) + fee
```

第一段把成功与失败放进同一证据结构；第二段证明拒绝路径不污染原状态；第三段验证本页最小协议对象。生产系统必须使用成熟密码、序列化和节点库，并补充资源限制、并发、持久化、超时、隐私与密钥隔离。

## 正常、边界与故障矩阵

| 样本   | 只改变的变量                    | 预期结果               | 必存证据                     |
| ------ | ------------------------------- | ---------------------- | ---------------------------- |
| 正常   | 有效UTXO、脚本、费用与网络      | 状态转移并达到确认条件 | 原始对象、前后状态、区块哈希 |
| 边界   | 零值、最大值、恰好阈值或时间锁  | 按明确规则接受或拒绝   | 边界值、判断分支、资源成本   |
| 单故障 | 网络、字节、签名、引用或PoW一项 | 首个无效规则处拒绝     | 错误、首差、原状态与回退点   |

先写出预期字节、栈、金额或哈希，再运行节点和解析器。若钱包、区块浏览器与本地节点给出不同答案，以固定网络上的原始交易、被花费输出、区块头和本地共识验证为坐标；第三方展示不能覆盖本地可验证事实。

## 常见失败与回退

<Callout type="trap">
  **把地址当账户、哈希当确认：**
  地址提示锁定脚本，交易哈希标识序列化对象；二者都不证明UTXO未花费、脚本成功或交易已进入累计工作量链。
</Callout>

<Callout type="trap">
  **把策略拒绝当共识无效：**
  尘埃、最低中继费和内存池限制可能只是节点策略。复核必须区分序列化、脚本和区块共识规则与本地中继策略。
</Callout>

<Callout type="tip">
  **回退顺序：** 第三版标签 -> 网络与创世哈希 -> 字节序和序列化 -> UTXO与价值 -> 脚本和签名 -> 节点策略 -> 区块PoW与链选择 -> 钱包或二层视图。首个差异未解释前不比较余额。
</Callout>
