## 学习目标

- 理解以太坊的设计目标：去中心化的图灵完备智能合约平台
- 掌握以太坊四层架构（应用层、合约层、执行层、共识层）
- 区分账户模型、智能合约、状态机三大核心概念
- 对比以太坊与比特币在设计哲学上的差异

## 核心概念

### 从比特币到世界计算机

比特币证明了去中心化数字货币的可行性，但其脚本语言并非图灵完备，无法实现复杂逻辑。以太坊由 Vitalik Buterin 于 2013 年提出、2015 年上线，核心创新是引入图灵完备的智能合约：让区块链不再只是账本，而成为一台「世界计算机」——任何人都可在上面部署不可篡改的程序，实现可编程价值。

### 以太坊四层架构

<MetEthereumOverviewDiagram />

以太坊的架构可归纳为四层：

1. **共识层**：PoS 权益证明，验证者质押 ETH 产出区块，保障去中心化共识
2. **执行层**：EVM 虚拟机处理交易、计量 Gas、驱动状态转换
3. **合约层**：Solidity 编写的智能合约编译为字节码，定义可编程逻辑
4. **应用层**：DApp、DeFi、NFT、DAO 等用户与合约交互的入口

### 三大核心概念

**账户模型**：以太坊采用账户模型而非比特币的 UTXO 模型。账户分为两类——EOA（外部拥有账户，由私钥控制）和 CA（合约账户，由代码控制）。账户状态包含余额与 nonce，整个网络维护一棵全局状态树。

**智能合约**：部署在链上的图灵完备程序，一旦部署不可篡改。合约定义了自动执行的规则，被交易或其他合约调用时执行逻辑、读写存储、发出事件。这是以太坊实现可编程价值的核心。

**状态机**：以太坊本质上是一台状态机。每个区块包含一批交易，交易驱动状态从前一个区块转换到下一个。全局状态用默克尔帕特里夏树（MPT）组织，任何节点都可独立验证状态根，保证一致性。

### 以太坊 vs 比特币

| 维度 | 以太坊 | 比特币 |
|------|--------|--------|
| 账户模型 | 账户模型 | UTXO 模型 |
| 可编程性 | 图灵完备智能合约 | 受限脚本 |
| 共识机制 | PoS 权益证明 | PoW 工作量证明 |
| 核心定位 | 世界计算机 | 价值存储 |
| 状态管理 | 全局状态树 | 未花费输出集合 |

## 术语表

| 术语 | 含义 |
|------|------|
| 世界计算机 | 以太坊的定位，全球共享的可编程计算平台 |
| PoS | 权益证明，按质押量选择验证者 |
| 状态机 | 由交易驱动状态转换的系统模型 |
| MPT | 默克尔帕特里夏树，组织以太坊状态的数据结构 |
| nonce | 账户交易序号，防重放 |
| 图灵完备 | 可实现任意计算逻辑的能力 |
| 不可篡改 | 部署后的合约代码无法修改 |

## 练习题

1. 以太坊的核心设计目标是什么？它如何超越比特币的定位？
2. 描述以太坊四层架构，并说明各层的职责。
3. EOA 与 CA 有什么区别？为什么说合约账户不能主动发起交易？
4. 什么是以太坊的状态机模型？全局状态如何组织？
5. 对比以太坊与比特币在账户模型、可编程性、共识机制上的差异。
