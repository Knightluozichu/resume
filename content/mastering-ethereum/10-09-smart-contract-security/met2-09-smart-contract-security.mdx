## 为什么从可验证状态开始

本页按官方第二版在线目录重建 **Chapter 9. Smart Contract Security**，覆盖该正式单元的 59 个二至五级标题。教学顺序保留原目录的依赖关系，但正文全部独立撰写：每个标题都转成对象、前状态、输入、规则、后状态和失败证据，避免只给术语摘要。

合约安全从资产、权限和不变量建模开始，覆盖重入、delegatecall、未检查返回值、抢跑、拒绝服务、精度、价格操纵、输入验证、签名重放与配置错误。 阅读时把“客户端或网页显示了什么”和“协议能验证什么”分开：钱包、浏览器、RPC与索引器是观察面，规范编码、签名、交易、收据、区块、状态根、证明和最终化检查点才是可复核对象。任何结论都要绑定链ID、客户端版本、区块坐标与原始输入。

实验统一在本地开发链或公开测试网完成，私钥只使用一次性测试向量。先写预期，再运行；先保存原始对象，再看格式化界面。正常样本证明主路径，边界样本选择零值、最大值、恰好阈值或时序边缘，单故障样本只改变链ID、nonce、一个字节、一个签名、一个价格或一个证明条件。

每个外部入口都要明确调用者、可改变状态、资产上限和失败原子性；任何外部调用或价格输入都视为不可信。 若执行失败，证据必须说明首个拒绝规则、错误数据、消耗的资源以及状态是否回滚；若执行成功，还要区分交易池接纳、区块包含、执行状态与PoS最终性，不能把交易哈希当成最终结算。

通过标准是：能为最小金库建立威胁模型，复现一个漏洞、修复并以正常、边界和单故障测试证明不变量。 独立复核者应能从空目录和相同测试向量重建结果；缺失来源、版本、输入、前状态、后状态或失败证据任一项，结论都不能进入下一页。

## 核心约束与推导

$$
S_{t+1}=Apply(S_t, T_t), \quad Valid(T_t,S_t)=1
$$

$$
gasUsed(T) \le gasLimit(T), \quad fee=gasUsed \times effectiveGasPrice
$$

$$
stateRoot_{n}=Commit(accounts,storage,code,balances)
$$

$$
gate=source \times version \times replay \times boundary \times failureEvidence
$$

状态转移只接受针对当前前状态有效的输入；Gas约束把资源消耗纳入确定性执行；状态根把大量账户与存储压缩为区块可承诺对象。证据门禁采用乘法语义，任一因子缺失都不能用其他截图或口头解释补偿。

```typescript
type EthereumEvidence = {
  chainId: number;
  block: string;
  beforeRoot: string;
  inputHash: string;
  afterRoot?: string;
  error?: string;
};

export function evidenceGate(run: EthereumEvidence) {
  return {
    page: "met2-09-smart-contract-security",
    accepted: Boolean(run.afterRoot || run.error),
    immutableInput: run.inputHash,
  };
}
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

contract InvariantProbe {
    uint256 public value;
    event Applied(uint256 beforeValue, uint256 afterValue);

    function apply(uint256 next) external {
        uint256 beforeValue = value;
        require(next >= beforeValue, "non-monotonic");
        value = next;
        emit Applied(beforeValue, next);
    }
}
```

```typescript
function applyCandidate(
  state: bigint,
  next: bigint,
  gasUsed: bigint,
  gasLimit: bigint,
) {
  if (gasUsed > gasLimit)
    return { accepted: false, state, reason: "out-of-gas" };
  if (next < state)
    return { accepted: false, state, reason: "invalid-transition" };
  return { accepted: true, state: next, reason: null };
}
```

第一段把成功与失败放进同一证据合同；第二段给出可观察事件和显式不变量；第三段证明拒绝路径保持原状态。真实系统应使用成熟客户端、ABI、密码与证明库，并补齐并发、重组、超时、持久化、隐私和密钥隔离。

## 正常、边界与故障矩阵

| 样本   | 只改变的变量                            | 预期结果             | 必存证据                   |
| ------ | --------------------------------------- | -------------------- | -------------------------- |
| 正常   | 有效链ID、输入、签名、Gas与前状态       | 接受并得到预期后状态 | 原始交易、收据、前后状态根 |
| 边界   | 零值、最大值、恰好阈值或时序边缘        | 按明确规则接受或拒绝 | 边界值、判断分支、资源成本 |
| 单故障 | 链ID、nonce、签名、价格、证明或数据一项 | 首个无效规则处拒绝   | 错误数据、首差、原状态     |

先预测每个样本的状态根、返回值和错误，再操作滑块；若两个变量同时变化，实验失去归因能力，必须重置。

<Callout type="trap">
  **修复时同时改变多个变量：**
  升级客户端、换网络、改账户又改输入会失去首差。恢复固定基线，只改变一个变量，重放原失败、相邻边界和正常样本。
</Callout>

## 本章回顾

合约安全从资产、权限和不变量建模开始，覆盖重入、delegatecall、未检查返回值、抢跑、拒绝服务、精度、价格操纵、输入验证、签名重放与配置错误。 核心不是记住工具名称，而是能从官方标题定位对象、规则与证据。每个外部入口都要明确调用者、可改变状态、资产上限和失败原子性；任何外部调用或价格输入都视为不可信。 完成后应删除临时密钥和测试状态，保留不含秘密的版本、输入哈希、收据、状态根、错误与复核结论。

<Exercises>

1. 如何为Chapter 9. Smart Contract Security建立最小可重放基线？

<Answer>
  固定官方第二版页面、链ID、客户端版本、账户、区块坐标、前状态和原始输入，先手算预期，再保存解析、验证、执行、收据与状态证据。
</Answer>

2. 如何证明“能为最小金库建立威胁模型，复现一个漏洞、修复并以正常、边界和单故障测试证明不变量。”不是一次偶然成功？

<Answer>
  在同一基线上执行正常、边界和单故障样本，由独立客户端核对原始对象、状态根与拒绝点；三组证据一致才通过。
</Answer>

3. 修复Chapter 9. Smart Contract Security的一个失败后怎样回归？

<Answer>
  先重放原失败，再运行相邻边界和正常基线；按版本、网络、编码、签名、状态、Gas、证明与最终性定位首差，全部不变量通过后才进入下一页。
</Answer>
