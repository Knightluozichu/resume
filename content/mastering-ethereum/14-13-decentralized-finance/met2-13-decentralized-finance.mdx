## 为什么从可验证状态开始

本页按官方第二版在线目录重建 **Chapter 13. Decentralized Finance**，覆盖该正式单元的 18 个二至五级标题。教学顺序保留原目录的依赖关系，但正文全部独立撰写：每个标题都转成对象、前状态、输入、规则、后状态和失败证据，避免只给术语摘要。

DeFi把交换、借贷、稳定资产和质押表示为公开状态机。可组合性放大资本效率，也把价格、流动性、清算、治理和外部协议风险连接起来。 阅读时把“客户端或网页显示了什么”和“协议能验证什么”分开：钱包、浏览器、RPC与索引器是观察面，规范编码、签名、交易、收据、区块、状态根、证明和最终化检查点才是可复核对象。任何结论都要绑定链ID、客户端版本、区块坐标与原始输入。

实验统一在本地开发链或公开测试网完成，私钥只使用一次性测试向量。先写预期，再运行；先保存原始对象，再看格式化界面。正常样本证明主路径，边界样本选择零值、最大值、恰好阈值或时序边缘，单故障样本只改变链ID、nonce、一个字节、一个签名、一个价格或一个证明条件。

资产守恒、定价函数、抵押门限和清算激励必须在费用、精度与极端价格下仍成立；收益不能脱离风险来源解释。 若执行失败，证据必须说明首个拒绝规则、错误数据、消耗的资源以及状态是否回滚；若执行成功，还要区分交易池接纳、区块包含、执行状态与PoS最终性，不能把交易哈希当成最终结算。

通过标准是：能手算一次AMM交换和抵押仓位，验证滑点、费用、健康度与清算边界，并模拟预言机失真。 独立复核者应能从空目录和相同测试向量重建结果；缺失来源、版本、输入、前状态、后状态或失败证据任一项，结论都不能进入下一页。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

contract InvariantProbe {
    uint256 public value;
    event Applied(uint256 beforeValue, uint256 afterValue);

    function apply(uint256 next) external {
        uint256 beforeValue = value;
        require(next >= beforeValue, "non-monotonic");
        value = next;
        emit Applied(beforeValue, next);
    }
}
```

```typescript
function applyCandidate(
  state: bigint,
  next: bigint,
  gasUsed: bigint,
  gasLimit: bigint,
) {
  if (gasUsed > gasLimit)
    return { accepted: false, state, reason: "out-of-gas" };
  if (next < state)
    return { accepted: false, state, reason: "invalid-transition" };
  return { accepted: true, state: next, reason: null };
}
```

第一段把成功与失败放进同一证据合同；第二段给出可观察事件和显式不变量；第三段证明拒绝路径保持原状态。真实系统应使用成熟客户端、ABI、密码与证明库，并补齐并发、重组、超时、持久化、隐私和密钥隔离。

## 正常、边界与故障矩阵

| 样本   | 只改变的变量                            | 预期结果             | 必存证据                   |
| ------ | --------------------------------------- | -------------------- | -------------------------- |
