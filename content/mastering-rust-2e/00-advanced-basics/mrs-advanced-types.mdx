## 直觉引入

想象你在管理一个仓库，所有货物都用「箱子」称呼。你说「搬一箱过来」，结果搬来的是食品箱，但你需要的是药品箱——因为都是「箱子」，没人能提前发现错误。

Rust 的类型系统就是给每个箱子贴上精确标签。Newtype 是给箱子贴上「药品」标签——药品箱和食品箱不再混淆。类型别名是给复杂箱子起个简称——「大号药品箱」简称「大药箱」，方便但不改变本质。Never 类型是「黑洞箱」——东西放进去就出不来了（永不返回）。DST 是「大小不定的箱子」——需要额外标签记录有多大。

## 概念讲解

### Newtype 模式

<Term def="Newtype 是用 struct 包装一个现有类型创建全新类型，编译后与原类型内存布局相同（零成本），但类型系统视为不同类型，实现类型安全隔离。">

```rust
struct Meters(u32);
struct Feet(u32);

fn add_meters(a: Meters, b: Meters) -> Meters {
    Meters(a.0 + b.0)
}
// add_meters(Meters(10), Feet(5)); // 编译错误！类型不匹配
```

没有 Newtype，Meters 和 Feet 都是 u32，混用不会报错——米加英尺得到无意义结果。Newtype 让编译器帮你检查量纲安全。

</Term>

### 类型别名

<Term def="类型别名用 type 关键字创建现有类型的简称，不创建新类型，别名与原类型完全等价，用于简化复杂类型签名。">

```rust
// 简化复杂类型
type Handler = Box<dyn Fn(Event) -> Result<(), Error>>;
type IntMap = std::collections::HashMap<String, i32>;

// 不创建新类型，IntMap 就是 HashMap<String, i32>
fn process(map: IntMap) -> Handler { ... }
```

类型别名是方便，不是安全——`type Id = u64` 后 Id 和 u64 完全等价，不会阻止混用。

</Term>

### Never 类型

<Term def="Never 类型 ! 表示「永不返回」，是类型系统的底类型（bottom type），可强制转为任何类型，用于控制流分析和类型推导。">

```rust
// panic! 返回 !
let x: i32 = match opt {
    Some(v) => v,
    None => panic!("没有值"),  // ! 可转为 i32
};

// loop 返回 !（永不退出）
let y = loop { /* 永不退出 */ };
```

`!` 让编译器知道某些分支不会产生值，因此不需要类型匹配——这是类型推导能正确工作的关键。

</Term>

### DST 胖指针

<Term def="DST（动态大小类型）是编译期大小未知的类型（如 [T]、str、dyn Trait），必须通过胖指针引用——胖指针包含数据指针和元数据（长度或 vtable 指针）。">

```rust
// &[T] = (ptr, len)
let slice: &[i32] = &[1, 2, 3];  // ptr + len=3

// &str = (ptr, len)
let s: &str = "hello";  // ptr + len=5(字节)

// &dyn Trait = (ptr, vtable_ptr)
let obj: &dyn Display = &42;  // ptr + vtable(方法地址表)
```

普通引用是 1 个字宽度（8 字节），胖指针是 2 个字宽度（16 字节）。

</Term>

定义 `struct Meters(u32)` 和 `struct Feet(u32)`，为它们实现加减和转换方法。编译器会阻止 Meters 和 Feet 直接相加——类型不匹配。这就是 Newtype 的价值：用类型系统防止逻辑错误。

</Step>

<Step title="第二步：用类型别名简化签名">

遇到 `Box<dyn Fn(Event) -> Result<(), Box<dyn Error>>>` 这样的复杂类型，用 `type Handler = ...` 起别名。代码可读性大幅提升，但不影响类型安全——别名只是简称。

</Step>

<Step title="第三步：理解 Never 类型的角色">

观察 `panic!()`、`process::exit()`、无限循环都返回 `!`。在 match 表达式中，`!` 分支不需要匹配返回类型，因为永不产生值。这让 `let x = match { Some(v) => v, None => panic!() }` 能正确推导 x 的类型。

</Step>

<Step title="第四步：掌握 DST 胖指针">

理解 &[T]、&str、&dyn Trait 都是胖指针——2 个字宽度。尝试用 `std::mem::size_of` 验证：普通 `&u32` 是 8 字节，`&[u32]` 是 16 字节。DST 让 Rust 支持运行时确定大小的类型同时保持类型安全。

</Step>

## 代码对照

```rust
// === Newtype: 类型安全量纲 ===
struct Meters(u32);
struct Feet(u32);

impl std::ops::Add for Meters {
    type Output = Meters;
    fn add(self, other: Meters) -> Meters {
        Meters(self.0 + other.0)
    }
}

impl Meters {
    fn to_feet(&self) -> Feet {
        Feet((self.0 as f64 * 3.281) as u32)
    }
}

let a = Meters(10);
let b = Meters(20);
let c = a + b;           // Meters(30) — 类型安全
// let d = Meters(10) + Feet(5);  // 编译错误！

// === 类型别名: 简化复杂签名 ===
type Callback = Box<dyn Fn(i32) -> Result<(), String>>;
type IntMap = std::collections::HashMap<String, Vec<i32>>;

fn register(handlers: &mut Vec<Callback>, cb: Callback) {
    handlers.push(cb);
}

// === Never 类型: 控制流 ===
fn find_or_panic<T>(opt: Option<T>, msg: &str) -> T {
    match opt {
        Some(v) => v,
        None => panic!("{}", msg),  // ! 可转为 T
    }
}

// === DST: 胖指针验证 ===
use std::mem::size_of;
fn demo_dst() {
    let n: u32 = 42;
    let r: &u32 = &n;
    let s: &[u32] = &[1, 2, 3];
    let t: &str = "hello";
    let d: &dyn std::fmt::Display = &42;

    println!("&u32:    {} bytes", size_of::<&u32>());    // 8
    println!("&[u32]:  {} bytes", size_of::<&[u32]>());  // 16 (胖指针)
    println!("&str:    {} bytes", size_of::<&str>());    // 16 (胖指针)
    println!("&dyn:    {} bytes", size_of::<&dyn std::fmt::Display>()); // 16
}
```

## 常见误区

<Callout type="trap">

**误区：用类型别名替代 Newtype 图省事**

`type UserId = u64; type OrderId = u64;` 看起来方便，但 UserId 和 OrderId 完全等价——你把 OrderId 传给期望 UserId 的函数，编译器不会报错，运行时才发现 bug。用 Newtype `struct UserId(u64); struct OrderId(u64);` 才能实现类型隔离。别名是方便，Newtype 是安全，不要混淆。

</Callout>

<Callout type="trap">

**误区：认为胖指针和普通指针一样大**

`&u32` 是 8 字节（一个指针），`&[u32]` 是 16 字节（指针 + 长度）。把胖指针当普通指针用会导致内存布局理解错误，特别是在 FFI（与 C 交互）时——C 的指针是 8 字节，Rust 的胖指针是 16 字节，直接传递会出错。必须用 `as_ptr()` 和 `len()` 拆分后传递。

</Callout>

<Exercises>

**问题 1**：Newtype 模式和类型别名的核心区别是什么？各自适合什么场景？

<Answer>

核心区别：Newtype `struct Id(u64)` 创建一个全新的类型，与 u64 不兼容，必须显式转换；类型别名 `type Id = u64` 只是 u64 的另一个名字，Id 和 u64 完全等价，编译器不区分。

Newtype 适合需要类型安全隔离的场景——如 UserId 和 OrderId 都是 u64 但不能混用，Meters 和 Feet 都是 u32 但量纲不同。编译器在类型不匹配时报错，防止逻辑错误。

类型别名适合简化复杂类型签名的场景——如 `type Handler = Box<dyn Fn(Event) -> Result<(), Error>>` 让代码更可读，但不需要类型隔离（Handler 就是那个复杂类型，传别的同样类型不会出错）。

一句话：别名是方便，Newtype 是安全。需要防止类型混用时用 Newtype，只需要简化名字时用别名。

</Answer>

**问题 2**：Rust 的 DST（动态大小类型）是什么？胖指针的结构是怎样的？

<Answer>

DST 是编译期大小未知的类型，包括 [T]（切片）、str（字符串切片）、dyn Trait（trait 对象）。它们不能直接存放在栈上，必须通过胖指针引用。

胖指针是双字宽度的指针（16 字节），包含数据指针和元数据：
1. `&[T]` = (ptr, len)——数据指针 + 元素个数。如 `&[1,2,3]` 的胖指针是 (ptr, 3)。
2. `&str` = (ptr, len)——数据指针 + 字节长度。如 `"hello"` 的胖指针是 (ptr, 5)。
3. `&dyn Trait` = (ptr, vtable_ptr)——数据指针 + 虚表指针。vtable 包含 trait 方法的函数地址。

普通引用 `&u32` 是 8 字节（单指针），胖指针是 16 字节（双字）。DST 让 Rust 支持运行时确定大小的类型，同时保持类型安全——编译器确保你总是通过胖指针访问 DST，不会直接操作裸 DST。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="Newtype 模式">

用 struct 包装现有类型创建全新类型的模式，如 `struct Meters(u32)`。编译后与原类型内存布局相同（零成本），但类型系统视为不同类型，实现类型安全隔离。

</GlossaryItem>

<GlossaryItem term="类型别名">

用 type 关键字创建的现有类型简称，如 `type Id = u64`。不创建新类型，别名与原类型完全等价，用于简化复杂类型签名。

</GlossaryItem>

<GlossaryItem term="Never 类型 (!)">

表示「永不返回」的底类型，可强制转为任何类型。panic!、process::exit、无限循环返回 !。在控制流分析和类型推导中起关键作用，让编译器知道某些分支不会产生值。

</GlossaryItem>

<GlossaryItem term="DST 胖指针">

动态大小类型的引用，双字宽度（16 字节），包含数据指针和元数据。&[T] 的元数据是长度，&dyn Trait 的元数据是 vtable 指针。让 Rust 支持运行时确定大小的类型同时保持类型安全。

</GlossaryItem>
