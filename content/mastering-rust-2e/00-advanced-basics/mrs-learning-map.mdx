## 直觉引入

学 Rust 像盖一座精密建筑。你不是从屋顶开始，而是从地基往上——地基是类型系统（进阶基础），骨架是内存与并发模型（Rust 的核心竞争力），内部装修是元编程能力（宏和 Unsafe），最后接入外部世界（生态与工程）。

每层都建立在前层之上：没有类型系统的深度认知，就无法理解所有权；没有内存模型，就无法安全使用 Unsafe；没有前三者，WebAssembly 和网络编程就是空中楼阁。本书带你从「会写 Rust」到「精通 Rust」，关键是理解每层的设计哲学和层间依赖。

## 概念讲解

### 四大板块

全书按学习递进分为四个板块：

1. **Rust 进阶基础**（第 1-2 章）：学习地图与高级类型。建立类型系统的深度认知——Newtype、类型别名、Never 类型、DST 胖指针。
2. **内存与并发**（第 3-4 章）：内存管理与并发深入。掌握 Rust 的核心竞争力——所有权系统、借用检查、Send/Sync 编译期线程安全。
3. **元编程**（第 5-7 章）：宏深入、Trait 进阶、Unsafe 深入。扩展编译期和底层能力——声明宏/过程宏、关联类型与泛型约束、裸指针与安全边界。
4. **生态与工程**（第 8-10 章）：WebAssembly、网络编程、总复习。落地到实际工程场景——跨平台编译、async 网络、综合实战。

### 设计哲学

<Term def="Rust 的设计哲学是「零成本抽象 + 编译期安全」：在不牺牲运行时性能的前提下，把尽可能多的安全检查推到编译期，让错误在编译时暴露而非运行时崩溃。">

这个哲学贯穿全书：Newtype 零成本（编译后无开销）、所有权零成本（无 GC）、Send/Sync 零成本（编译期线程安全）、宏零成本（编译期展开）。Rust 的核心理念是——如果它能编译通过，它就不会出内存安全或线程安全问题。

</Term>

### 为什么内存与并发是核心

<Term def="Rust 的核心竞争力是所有权系统——在无 GC 的前提下实现内存安全，在无锁的前提下实现编译期线程安全，这是其他语言做不到的。">

C/C++ 手动管理内存，靠程序员纪律保证安全；Java/Go 用 GC 牺牲性能换安全；Rust 用所有权系统在编译期保证安全，运行时零开销。并发方面，C++ 靠运行时检测（TSan），Rust 用 Send/Sync trait 在编译期拒绝数据竞争。这是 Rust 存在的根本理由，也是本书最核心的板块。

</Term>

<Step title="第二步：内存与并发强骨">

这是全书核心。深入理解所有权系统——每个值有唯一所有者，借用规则（一个可变或多个不可变），生命周期标注。然后进入并发——Send/Sync 如何在编译期保证线程安全，Mutex/RwLock/Arc 如何组合使用。这一步把「能编译」提升到「能安全并发」。

## 代码对照

```rust
// Rust 学习递进：从类型系统到工程落地

// === Layer 1: 进阶基础 — Newtype 类型安全 ===
struct Meters(u32);
struct Feet(u32);

impl Meters {
    fn to_feet(&self) -> Feet {
        Feet((self.0 as f64 * 3.281) as u32)
    }
}

// === Layer 2: 内存与并发 — 所有权与线程安全 ===
use std::sync::{Arc, Mutex};
use std::thread;

let data = Arc::new(Mutex::new(vec![1, 2, 3]));
let handles: Vec<_> = (0..3).map(|i| {
    let data = Arc::clone(&data);
    thread::spawn(move || {
        let mut lock = data.lock().unwrap(); // 编译期线程安全
        lock.push(i);
    })
}).collect();
for h in handles { h.join().unwrap(); }

// === Layer 3: 元编程 — 宏与 Trait ===
macro_rules! measure {
    ($val:expr) => { Meters($val) };
}

trait Distance {
    fn in_meters(&self) -> f64;
}
impl Distance for Feet {
    fn in_meters(&self) -> f64 { self.0 as f64 / 3.281 }
}

// === Layer 4: 生态工程 — async 网络 ===
async fn fetch_data(url: &str) -> Result<String, Box<dyn std::error::Error>> {
    // 实际用 reqwest 等异步 HTTP 库
    Ok(format!("Data from {}", url))
}
```

## 常见误区

<Callout type="trap">

**误区：跳过基础直接学并发**

很多人急着想学 async/await 和并发，跳过类型系统和所有权基础。结果写出的代码编译不过却看不懂错误信息——因为不理解生命周期标注，不理解借用规则，不理解 Send/Sync 约束从何而来。Rust 的并发安全建立在所有权系统之上，跳过地基直接盖楼必然崩塌。

</Callout>

<Callout type="trap">

**误区：把 Rust 当 C++ 写**

有 C++ 经验的人容易把 Rust 当「带 borrow checker 的 C++」——大量使用 Unsafe、手动管理指针、绕过类型系统。这完全浪费了 Rust 的核心价值。Rust 的设计哲学是让编译器帮你保证安全，正确的方式是：尽量用 Safe Rust，只在性能关键路径用最小化 Unsafe，充分利用类型系统防止错误。

</Callout>

<Exercises>

**问题 1**：Rust 的设计哲学是什么？它如何体现在四大板块中？

<Answer>

Rust 的设计哲学是「零成本抽象 + 编译期安全」——在不牺牲运行时性能的前提下，把尽可能多的安全检查推到编译期。

体现在四大板块：
1. 进阶基础——Newtype 和类型别名是零成本抽象（编译期消除，运行时无开销），类型系统在编译期防止类型混用错误。
2. 内存与并发——所有权系统是零成本的内存安全（无 GC 开销），Send/Sync 是零成本的线程安全（编译期拒绝数据竞争，无运行时检测）。
3. 元编程——宏在编译期展开无运行时开销，Unsafe 把安全边界显式化集中在可审计代码块中。
4. 生态与工程——async/await 是零成本抽象（状态机编译期生成），WebAssembly 追求零成本跨平台。

核心理念：如果 Rust 代码能编译通过，它就不会有内存安全或线程安全问题。

</Answer>

**问题 2**：为什么内存与并发板块是全书的核心？它解决了其他语言什么做不到的问题？

<Answer>

内存与并发是 Rust 的核心竞争力，解决了「无 GC 的内存安全」和「编译期线程安全」两个其他语言做不到的问题：

1. 内存安全：C/C++ 手动管理内存，靠程序员纪律保证安全，一旦疏忽就内存泄漏或 UAF；Java/Go 用 GC 自动回收，但牺牲运行时性能（STW 停顿、内存开销）；Rust 用所有权系统在编译期保证安全——每个值有唯一所有者，借用规则防止数据竞争，生命周期防止悬垂引用，运行时零 GC 开销。

2. 线程安全：C++ 靠程序员纪律和运行时检测（TSan），数据竞争在运行时才暴露；Rust 用 Send/Sync trait 在编译期标记类型能否跨线程共享，违反规则的代码编译不过——数据竞争在编译期就消灭。

这两个能力是 Rust 存在的根本理由，也是本书最核心、最值得花时间的板块。其他板块（类型系统、元编程、生态）都是建立在这个基础之上的。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="零成本抽象">

Rust 的核心设计原则：抽象机制（如泛型、迭代器、trait）在编译后与手写代码性能完全一致，运行时无额外开销。与 C++ 的「零开销原则」一脉相承，但 Rust 进一步扩展到了内存安全和线程安全领域。

</GlossaryItem>

<GlossaryItem term="所有权系统">

Rust 的内存管理核心：每个值有唯一所有者，值在所有者离开作用域时自动释放，借用规则（一个可变引用或多个不可变引用）防止数据竞争。无需 GC 即可保证内存安全，是 Rust 区别于其他语言的根基。

</GlossaryItem>

<GlossaryItem term="Send/Sync">

Rust 的线程安全标记 trait：Send 表示类型可安全跨线程转移所有权，Sync 表示类型可安全跨线程共享引用。编译器自动推导，违反规则的代码编译不过，实现编译期线程安全。

</GlossaryItem>

<GlossaryItem term="四大板块">

全书按递进分为：Rust 进阶基础（类型系统）、内存与并发（所有权与线程安全）、元编程（宏/Trait/Unsafe）、生态与工程（WebAssembly/网络）。每层建立在前层之上，构成完整能力链。

</GlossaryItem>

</Glossary>
