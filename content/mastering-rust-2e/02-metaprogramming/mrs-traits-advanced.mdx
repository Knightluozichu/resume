## 直觉引入

想象你是个工厂设计师。Trait 是产品规格书——定义了产品必须有什么功能（方法签名），但不关心怎么实现。关联类型是规格书里的「配套零件型号」——一个产品只有一种配套型号（如 Iterator 的 Item）。泛型 trait 是「可适配多种零件」——同一个产品可以配不同零件（如 From<T> 可以从多种类型转换）。

静态分发是「每种规格单独开模具」——编译期为每种类型生成专门代码，调用时直接用，最快但模具多（代码膨胀）。动态分发是「通用模具加可换配件」——运行时通过配件表（vtable）查找方法，一份代码但有一次查表开销。选择取决于性能需求和是否需要异构集合。

## 概念讲解

### 关联类型

<Term def="关联类型 `trait Iterator { type Item; }` 在一个 impl 中只确定一种关联类型，比泛型参数更清晰，不需要在类型签名中重复标注。">

```rust
trait Iterator {
    type Item;  // 关联类型
    fn next(&mut self) -> Option<Self::Item>;
}

impl Iterator for Counter {
    type Item = u32;  // 只有一种 Item
    fn next(&mut self) -> Option<u32> { ... }
}
```

关联类型适合「一个类型实现 trait 时只有一种合理关联」的场景。用泛型参数会让签名变复杂：`Iterator<Item=u32>` 而非 `Iterator`。

</Term>

### 泛型 trait 与约束

<Term def="泛型 trait `trait From<T>` 可以多次 impl 不同 T。trait 约束 `T: Ord + Clone` 限定泛型必须实现哪些 trait，编译期检查。">

```rust
// 泛型 trait：可多次 impl
impl From<u32> for i64 { ... }
impl From<String> for i64 { ... }  // 可以共存

// trait 约束
fn largest<T: PartialOrd>(list: &[T]) -> &T { ... }

// where 子句：复杂约束更清晰
fn process<T, U>(x: T, y: U)
where
    T: Display + Clone,
    U: AsRef<str>,
{ ... }
```

</Term>

### 静态分发 vs 动态分发

<Term def="静态分发（单态化）编译期为每种类型生成代码，零运行时开销但代码膨胀；动态分发（trait 对象 &dyn Trait）运行时通过 vtable 间接调用，一份代码但有开销。">

```rust
// 静态分发：编译期生成具体代码
fn print_static<T: Display>(x: &T) { println!("{}", x); }
// print_static::<i32> 和 print_static::<String> 是两份代码

// 动态分发：trait 对象，运行时 vtable 查找
fn print_dyn(x: &dyn Display) { println!("{}", x); }
// 一份代码，通过 vtable 间接调用
```

</Term>

## 交互Demo

<MrsTraitsAdvancedDiagram />

<Stepper>

<Step title="第一步：用关联类型定义 trait">

定义 `trait Config { type Output; fn build(&self) -> Self::Output; }`。关联类型让 trait 使用者不需要在签名中标注 Output 是什么——impl 时确定。比泛型参数 `trait Config<Output>` 更简洁。

</Step>

<Step title="第二步：用 trait 约束限定泛型">

`fn sort<T: Ord>(mut v: Vec<T>)` 要求 T 实现 Ord（可排序）。多重约束用 +：`T: Ord + Clone + Debug`。复杂约束用 where 子句移到签名后，提升可读性。

</Step>

<Step title="第三步：选择静态或动态分发">

性能敏感用静态分发 `fn func<T: Trait>(x: T)`——编译期单态化零开销。需要异构集合（Vec<Box<dyn Trait>> 存不同类型）或插件系统用动态分发 `fn func(x: &dyn Trait)`——运行时 vtable 查找。

</Step>

<Step title="第四步：检查对象安全">

判断 trait 能否做 dyn：方法不能返回 Self、不能有泛型参数、trait 不要求 Sized。Clone（返回 Self）和 Default（无 &self 返回 Self）不能做 dyn。Display 和 Iterator（关联类型不涉及 Self）可以。

</Step>

</Stepper>

## 代码对照

```rust
use std::fmt::Display;
use std::cmp::PartialOrd;

// === 关联类型 ===
trait Container {
    type Item;  // 关联类型
    fn first(&self) -> Option<&Self::Item>;
    fn last(&self) -> Option<&Self::Item>;
}

impl Container for Vec<i32> {
    type Item = i32;
    fn first(&self) -> Option<&i32> { self.as_slice().first() }
    fn last(&self) -> Option<&i32> { self.as_slice().last() }
}

// === 泛型 trait + 多重约束 ===
trait From<T> {
    fn from(value: T) -> Self;
}

// where 子句
fn merge<T, U>(a: T, b: U) -> String
where
    T: Display,
    U: Display,
{
    format!("{} {}", a, b)
}

// === 静态分发 ===
fn print_all<T: Display>(items: &[T]) {
    for item in items {
        println!("{}", item);
    }
}
// 编译期为 print_all::<i32> 和 print_all::<String> 各生成一份

// === 动态分发（trait 对象）===
fn print_dyn(items: &[Box<dyn Display>]) {
    for item in items {
        println!("{}", item);
    }
}
// 一份代码，运行时 vtable 查找

// 异构集合：存储不同类型
let mixed: Vec<Box<dyn Display>> = vec![
    Box::new(42),
    Box::new("hello"),
    Box::new(3.14),
];
print_dyn(&mixed);  // 动态分发处理不同类型

// === 默认实现 ===
trait Logger {
    fn log(&self, msg: &str);
    // 默认实现：可被覆盖
    fn error(&self, msg: &str) {
        self.log(&format!("[ERROR] {}", msg));
    }
}

struct ConsoleLogger;
impl Logger for ConsoleLogger {
    fn log(&self, msg: &str) { println!("{}", msg); }
    // error 使用默认实现，无需重写
}
```

## 常见误区

<Callout type="trap">

**误区：泛型 trait 和关联类型混用**

有人同时用泛型参数和关联类型 `trait Foo<T> { type Bar; }`，导致 impl 时混乱。原则：如果关联类型在 impl 时只有一种选择就用关联类型（如 Iterator 的 Item）；如果需要多次 impl 不同类型就用泛型参数（如 From<T>）。不要两者混用——增加复杂度但通常没有实际好处。

</Callout>

<Callout type="trap">

**误区：无脑用 trait 对象图灵活**

有人一上来就用 `Box<dyn Trait>`，觉得比泛型灵活。但 trait 对象有运行时开销（vtable 间接调用无法内联），且不是所有 trait 都能做 dyn（对象安全限制）。正确做法：优先泛型（静态分发零开销），只在需要异构集合或运行时多态时才用 trait 对象。

</Callout>

<Exercises>

**问题 1**：关联类型和泛型 trait 的区别是什么？什么时候用哪个？

<Answer>

关联类型 `trait Iterator { type Item; }` 在一个 impl 中只能确定一种 Item——impl Iterator for Vec<T> 的 Item 就是 T，不能有第二个 impl。泛型 trait `trait From<T>` 可以多次 impl——impl From<u32> for i64 和 impl From<String> for i64 可以共存。

用关联类型的场景：一个类型实现 trait 时只有一种合理的关联类型。如 Iterator 的 Item（一个迭代器只产出一种元素类型），Add 的 Output（一种类型加法只有一种结果类型）。优点是签名简洁——用 Iterator 不需要写 Iterator<Item=u32>。

用泛型 trait 的场景：一个类型需要用不同参数多次实现 trait。如 From<T>（i64 可以从 u32、String 等多种类型转换），Into<T>（同上）。

原则：只有一种合理关联用关联类型，需要多次 impl 不同类型用泛型参数。

</Answer>

**问题 2**：静态分发和动态分发各自适合什么场景？如何选择？

<Answer>

静态分发（单态化）：`fn func<T: Trait>(x: T)` 编译期为每种具体类型生成一份代码，调用时直接内联，零运行时开销。代价是代码膨胀（每种类型一份代码）。适合性能敏感路径——高频调用的函数、库的核心 API。

动态分发（trait 对象 `&dyn Trait`）：运行时通过 vtable 间接调用方法，有一次指针解引用开销，无法内联优化。优点是代码不膨胀（一份代码处理所有类型）。适合需要运行时多态的场景——异构集合（Vec<Box<dyn Animal>> 存不同动物类型）、插件系统（运行时加载不同实现）、依赖注入。

选择原则：优先静态分发（性能好），需要异构集合或运行时多态时才用动态分发。注意不是所有 trait 都能做 trait 对象——必须对象安全（方法不返回 Self、无泛型参数、不要求 Sized）。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="关联类型">

trait 中用 `type Item;` 声明的占位类型，在 impl 时确定。一个类型对同一 trait 只能有一种关联类型实现，比泛型参数更简洁，适合一对一关联场景。

</GlossaryItem>

<GlossaryItem term="trait 约束">

限定泛型必须实现哪些 trait 的机制，如 `T: Ord + Clone`。编译期检查，确保泛型代码只使用约束允许的方法。where 子句用于复杂约束提升可读性。

</GlossaryItem>

<GlossaryItem term="静态分发">

编译期为泛型的每种具体类型生成代码（单态化），调用时直接使用，零运行时开销但代码膨胀。Rust 默认的泛型分发方式。

</GlossaryItem>

<GlossaryItem term="动态分发">

通过 trait 对象（&dyn Trait）运行时通过 vtable 间接调用方法，一份代码处理所有类型但有间接调用开销。适合异构集合和运行时多态，需 trait 对象安全。

</GlossaryItem>

</Glossary>
