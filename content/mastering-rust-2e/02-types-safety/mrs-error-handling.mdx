<Term def="问号运算符在失败时通过From转换并提前返回，成功时解包；它简化传播但不会自动增加操作上下文。">问号运算符与提前返回</Term>不是孤立语法。它承接可恢复错误给出的目标，并通过Option 与 Result 组合子进入真实项目。阅读代码时要沿着输入、所有权或状态、动作、结果和证据五个节点追踪，而不是只记函数名。

```rust
use std::{fs, io, path::Path};
fn load(path: &Path) -> Result<String, io::Error> {
    let text = fs::read_to_string(path)?;
    Ok(text.trim().to_owned())
}
```

## 机制一：从类型到行为

Result把成功值和失败值放进类型，调用者必须选择传播、转换或恢复；错误类型应携带可判断上下文，而不是只返回模糊字符串。 map、and_then、ok_or_else等组合子把直线路径与失败路径分开；链条过长时使用显式match可以提高诊断和可读性。 两者协作时，先写出谁拥有数据、谁可以修改、失败由谁处理，再决定具体API。这样可以把编译器诊断还原为契约冲突，而不是把错误信息当成需要逐条消除的噪声。

<Term def="panic表示当前契约已被破坏或程序无法继续，不应用于普通输入、网络超时或文件缺失；库边界尤其应让调用者决定恢复策略。">不可恢复错误</Term>进一步约束运行行为。它说明“类型正确”与“协议正确”是两层证据：前者由编译器帮助证明，后者还需要测试、时间线和边界输入。

## 机制二：失败、资源与边界

问号运算符在失败时通过From转换并提前返回，成功时解包；它简化传播但不会自动增加操作上下文。 panic表示当前契约已被破坏或程序无法继续，不应用于普通输入、网络超时或文件缺失；库边界尤其应让调用者决定恢复策略。 失败实验至少覆盖正常、空值或零长度、上限附近、显式错误和资源中断。涉及线程、网络、数据库、GUI或FFI时，还要加入超时、取消、部分完成与关闭路径。

不要把原书示例的依赖版本直接复制到新项目。先固定Rust edition与最小支持版本，再查询维护中的crate文档和迁移说明；保留原书要讲的架构边界，按当前API重写适配层。

```rust
fn port(text: Option<&str>) -> Result<u16, String> {
    text.ok_or_else(|| "missing port".to_string())?
        .parse().map_err(|_| "invalid port".to_string())
}
```

本章按照官方目录逐项覆盖可恢复错误、Option 与 Result 组合子、问号运算符与提前返回、不可恢复错误、自定义错误与 Error Trait。核心方法是先用类型表达资源与能力，再用运行期协议约束超时、顺序和外部失败，最后用测试、日志或调试记录证明结果可重复。
