## 原书章节骨架

Packt 官方目录把本章组织为程序与内存、分配策略、内存管理陷阱、内存安全三要素、Rust 指针类型。这里保留原书问题顺序，再把2019年前后的案例放到当前Rust工程语境中理解：概念不因crate版本变化而失效，但命令、依赖和框架API必须以当前项目锁定版本的官方文档为准。

官方核心单元核对：程序与内存；内存管理；分配策略；内存管理陷阱；内存安全；内存安全三要素；Rust指针类型。

<Term def="悬垂指针、重复释放、释放后使用、泄漏与数据竞争来自生命周期或别名规则失守；Rust安全子集通过所有权和借用静态排除其中大部分。">内存管理陷阱</Term>不是孤立语法。它承接程序与内存给出的目标，并通过分配策略进入真实项目。阅读代码时要沿着输入、所有权或状态、动作、结果和证据五个节点追踪，而不是只记函数名。

fn first(bytes: &[u8]) -> Option<u8> {
    bytes.first().copied()
}

let owned = Box::new([1_u8, 2, 3]);
assert_eq!(first(&owned[..]), Some(1));
```

## 机制一：从类型到行为

程序通过栈帧、静态区和堆组织不同生命周期的数据；讨论性能前要先回答值在哪里、由谁拥有以及何时释放。 栈分配快速且遵循作用域，堆分配支持动态大小和跨作用域所有权；Box、Rc与Arc表达不同所有权关系，不只是分配便利函数。 两者协作时，先写出谁拥有数据、谁可以修改、失败由谁处理，再决定具体API。这样可以把编译器诊断还原为契约冲突，而不是把错误信息当成需要逐条消除的噪声。

<Term def="访问有效内存、遵守初始化与布局、满足别名和同步规则共同构成安全边界；只证明指针非空远远不够。">内存安全三要素</Term>进一步约束运行行为。它说明“类型正确”与“协议正确”是两层证据：前者由编译器帮助证明，后者还需要测试、时间线和边界输入。

use std::rc::Rc;
let shared = Rc::new(String::from("config"));
let reader = Rc::clone(&shared);
assert_eq!(Rc::strong_count(&reader), 2);
```

## 机制二：失败、资源与边界

悬垂指针、重复释放、释放后使用、泄漏与数据竞争来自生命周期或别名规则失守；Rust安全子集通过所有权和借用静态排除其中大部分。 访问有效内存、遵守初始化与布局、满足别名和同步规则共同构成安全边界；只证明指针非空远远不够。 失败实验至少覆盖正常、空值或零长度、上限附近、显式错误和资源中断。涉及线程、网络、数据库、GUI或FFI时，还要加入超时、取消、部分完成与关闭路径。

不要把原书示例的依赖版本直接复制到新项目。先固定Rust edition与最小支持版本，再查询维护中的crate文档和迁移说明；保留原书要讲的架构边界，按当前API重写适配层。

```rust
use std::cell::RefCell;
let state = RefCell::new(vec![1]);
state.borrow_mut().push(2);
assert_eq!(&*state.borrow(), &[1, 2]);
```

## 机制三：可复现证据

<Term def="引用、Box、Rc、Arc、Cell、RefCell和裸指针各自编码所有权、共享与可变性；选择依据是语义证据，不是为了让借用检查器安静。">Rust 指针类型</Term>负责把本章收束成证据。引用、Box、Rc、Arc、Cell、RefCell和裸指针各自编码所有权、共享与可变性；选择依据是语义证据，不是为了让借用检查器安静。 一次可靠验收要保存输入、工具链、依赖锁定、命令、退出状态、关键输出和失败样本。性能结论还要记录release构建、样本数与环境噪声；并发结论则要记录任务边界、超时和关闭结果。
