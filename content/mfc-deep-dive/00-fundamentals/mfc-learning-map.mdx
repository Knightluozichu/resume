## 直觉引入

把 MFC 想象成一座「房屋中介」。你写的一个程序 `myapp.exe` 想盖一栋楼（窗口程序），但不熟悉施工规范（Win32 API）。中介（MFC）给你一套现成的施工流程：先到「管理处」登记楼型（注册窗口类），它帮你跑手续（第2章 Win32基础）；你只填一张「户型偏好表」（重写 InitInstance），框架照表施工（第8章 模板方法）；楼盖好后，住户的报修单（消息）由「楼长」按楼层逐级派工（第5章 消息路由）；楼里的家具（数据）想换风格，设计师画图（CView）、库房管货（CDocument）分工明确（第4章 文档/视图）；中介还能凭户型档案（CRuntimeClass）现场复制一栋同款楼（第6章 RTTI与动态创建），并把家具装箱入库、拆箱还原（第7章 序列化）；最后中介还接驳「跨小区物流标准」（第9章 COM）。本书回答的就是「MFC 如何用 C++ 把 Win32 模型抽象成可复用框架」的工程原理问题。

## 四阶段递进

<Term def="MFC 是微软对 Win32 API 的 C++ 应用框架封装，以 CObject 为根类，通过虚函数多态、CRuntimeClass 类型链、消息映射表、文档/视图架构等机制，把过程式的 Win32 编程提升为面向对象的框架式开发。">MFC（Microsoft Foundation Classes）</Term>的学习可以拆成四个递进阶段。**基础基石**包括 Win32 窗口程序模型和 C++ 虚函数多态——它们解决「MFC 封装的底层是什么」和「MFC 依赖哪些 C++ 特性」。**MFC框架**包括文档/视图架构和消息路由——它们解决「MFC 程序的骨架长什么样」。**六大技术核心**包括 RTTI/动态创建和持久化/序列化——它们解决「MFC 的硬核机制如何工作」。**高级应用**包括模板方法模式与 COM 接口——它们解决「MFC 体现了哪些设计哲学」并升华到组件化。最后总复习以 CObject 为根串联全部知识点。

```text
// 「一个 MFC 程序从启动到退出」——六大技术全部参与的完整旅程
CMyApp theApp;  // 1. 全局应用对象先于 WinMain 构造（CObject 体系）

WinMain(...)    // MFC 内部的 WinMain，你几乎不碰
  theApp.InitInstance();   // 2. 模板方法钩子（第8章）
    AddDocTemplate(new CSingleDocTemplate(
        IDR_MAINFRAME,
        RUNTIME_CLASS(CMyDoc),     // 3. CRuntimeClass（第6章 RTTI）
        RUNTIME_CLASS(CMainFrame), //    动态创建框架窗口
        RUNTIME_CLASS(CMyView)));  //    动态创建视图
    m_pMainWnd->ShowWindow(SW_SHOW);

  theApp.Run();            // 4. 消息循环骨架 + OnIdle 空闲处理
    // 用户「文件/打开」→ CArchive 读字节流
    //   → 按类名查 CRuntimeClass → CreateObject 重建对象图（第7章 序列化）
    // 用户点菜单 ID_FILE_OPEN → WM_COMMAND
    //   → View::OnCmdMsg → Document → Frame → App 逐级路由（第5章）
    //   → 命中 CMyDoc::OnFileOpen → 数据改动 → UpdateAllViews → OnDraw 重绘（第4章）

  theApp.ExitInstance();   // 5. 退出钩子，清理资源
// 若集成 OLE/ActiveX：CCmdTarget 用接口映射表承载 IUnknown（第9章 COM）
```

## 常见误区

<Callout type="trap">
**误区：会用 AppWizard 生成程序就等于懂 MFC。** 点几下向导出一个带文档/视图的程序、在 OnDraw 里画几行、在 OnFileOpen 里读个文件——这只是「会用 MFC API」，照着 MSDN 抄就行。真正懂 MFC 的人能解释：为什么 CObject 是几乎所有类的根（统一提供 RTTI/序列化/诊断）、为什么用消息映射表而非虚函数处理消息（消息太多会让 vtable 膨胀）、为什么命令消息要逐级路由（让最合适的对象处理）、为什么 CRuntimeClass 要自建而不用标准 RTTI（MFC 早于标准 RTTI，且要支持动态创建）、为什么 CArchive 要先写类名（读时按名动态创建实现自描述持久化）。把 MFC 当黑盒的人遇到「框架没调到我的函数」只能瞎试；懂设计的人能读消息映射、追 OnCmdMsg 路由、理解 CRuntimeClass 链表。区分标志：能否解释「MFC 为什么这样设计」而非只是「能用它」。
</Callout>

<Exercises>
**问题 1**：全书四阶段递进是什么？为什么是这个顺序？

<Answer>
基础基石（Win32基础 + C++机制）→ MFC框架（文档/视图 + 消息路由）→ 六大技术核心（RTTI/动态创建 + 持久化/序列化）→ 高级应用与总复习（模板方法 + COM + 总复习）。顺序由依赖关系决定：MFC 是对 Win32 的 C++ 封装，必须先懂 Win32 窗口程序模型和 C++ 虚函数多态；框架层（文档/视图、消息路由）是 MFC 程序的骨架；核心机制（RTTI、序列化）依赖框架层的 CObject/CCmdTarget 基类；高级应用是设计哲学升华，需先懂机制再看模式；最后总复习以 CObject 为根串联六大技术。先「懂底层」，再「懂架构」，然后「懂机制」，接着「懂设计」，最后「能贯通」。
</Answer>

**问题 2**：用「一个 MFC 程序从启动到退出」描述全书主线，列出六大技术的入场时机。

<Answer>
一个 MFC 程序从 theApp 全局对象构造到退出：①程序初始化（第2/8章）——theApp 全局对象先构造，WinMain 调 theApp.InitInstance()，用户重写填入「加文档模板、显示主窗口」（模板方法）；②文档/视图（第4章）——InitInstance 里 AddDocTemplate 用 CRuntimeClass 动态创建 Doc/View/Frame；③消息映射与路由（第5章）——主窗口 ShowWindow 后进入 CWinApp::Run，命令消息按 View→Document→Frame→App 路由；④RTTI/动态创建（第6章）——框架全程用 CRuntimeClass 识别类型、动态创建对象；⑤序列化（第7章）——「文件/打开」时 CArchive 按类名动态创建对象图恢复状态；⑥COM（第9章）——若集成 OLE/ActiveX，CCmdTarget 用接口映射表承载 IUnknown；⑦退出——ExitInstance 钩子 + 析构。一次运行，六大技术全部参与。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="MFC 六大技术">程序初始化、消息映射、RTTI、动态创建、序列化、文档/视图（COM 为扩展）。六者全部建立在 CObject 根类之上：CRuntimeClass 同时支撑 RTTI/动态创建/序列化，文档模板用 CRuntimeClass 动态创建 Doc/View/Frame，消息映射基类 CCmdTarget 也派生自 CObject。一句话：CObject 是根，CRuntimeClass 是脊柱。</GlossaryItem>
<GlossaryItem term="四阶段递进">基础基石（Win32+C++）→ MFC框架（文档/视图+消息路由）→ 六大技术核心（RTTI+序列化）→ 高级应用与总复习（模板方法+COM+总复习）。每层解决前层的遗留：基础解决「MFC封装的底层是什么」，框架解决「程序骨架长什么样」，核心解决「硬核机制如何工作」，高级解决「体现什么设计哲学」。</GlossaryItem>
<GlossaryItem term="一个 MFC 程序的一生">一个 myapp.exe 从 theApp 构造到 ExitInstance 的完整旅程：全局对象构造 → WinMain 调 InitInstance（加文档模板、显示窗口）→ Run 消息循环（命令路由、序列化读写、视图重绘）→ ExitInstance 清理 → 析构。全书以这条主线串联各章节。</GlossaryItem>
