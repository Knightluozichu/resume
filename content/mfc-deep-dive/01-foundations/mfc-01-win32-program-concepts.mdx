## 核心机制深挖

从WinMain、窗口类、消息循环和窗口函数建立事件驱动模型，再扩展到资源、对话框、Console、进程与线程。 原书绑定Visual C++ 5.0与MFC 4.2。本页保留这个历史技术身份；现代Visual Studio、64位、Unicode、智能指针或新UI框架只可作为明确标注的对照，不能反向改写原书机制。

本页不变量是：**模块实例、窗口对象、消息队列和窗口函数的责任边界清楚；线程只处理属于自身队列与共享状态的工作。**。它必须在正常输入、空输入、创建失败、消息未处理、持久化版本不符和中断恢复中都成立。窗口看起来能显示、命令偶尔能执行或文件能写出，都不足以证明对象图、分派路径和资源生存期正确。

最小实验：为最小Win32程序记录WM_CREATE、WM_PAINT、WM_COMMAND与WM_DESTROY顺序，再加入对话框、OnIdle式空闲处理和工作线程。 运行前记录工具版本、编译选项、链接方式、资源哈希、输入序列和预期调用路径；运行后保存消息日志、对象关系、文件字节或线程退出状态。

故障实验：注入注册失败、GetMessage错误、跨线程更新窗口和漏发PostQuitMessage，定位生命周期断点。 每次只改变一个条件，停在第一处与预测不同的位置。删除故障后从干净构建或明确逆操作恢复，并以完全相同的输入重放；如果最终画面相同但对象、句柄、线程、Archive或资源状态不同，仍判定失败。

机制证据表至少保留六列：框架表面动作、对应的C++对象或宏、下沉到Win32的入口、可观察状态、首个失败信号、恢复操作。对历史代码还要单列“原书行为”和“现代迁移差异”：前者用于解释MFC 4.2为何这样工作，后者只说明在64位、Unicode或新工具链中怎样验证同一不变量。这样既不会把旧API当成今天的最佳实践，也不会因现代封装更方便而跳过原书真正要揭示的内部机制。

```cpp
int WINAPI WinMain(HINSTANCE app, HINSTANCE, LPSTR, int show) {
  RegisterClass(&windowClass);
  HWND window = CreateWindow(className, title, WS_OVERLAPPEDWINDOW, 0, 0, 640, 480, 0, 0, app, 0);
  ShowWindow(window, show);
  MSG msg{}; while (GetMessage(&msg, 0, 0, 0) > 0) { TranslateMessage(&msg); DispatchMessage(&msg); }
  return static_cast<int>(msg.wParam);
}
```

LRESULT CALLBACK WndProc(HWND window, UINT message, WPARAM w, LPARAM l) {
  if (message == WM_DESTROY) { PostQuitMessage(0); return 0; }
  return DefWindowProc(window, message, w, l);
}

| 样本 | 注入方式                   | 必查证据                   | 通过条件     |
