## 核心机制深挖

用封装、继承、this、虚函数、对象生存期、RTTI、动态创建、异常和模板解释MFC宏背后的C++机制。 原书绑定Visual C++ 5.0与MFC 4.2。本页保留这个历史技术身份；现代Visual Studio、64位、Unicode、智能指针或新UI框架只可作为明确标注的对照，不能反向改写原书机制。

本页不变量是：**动态类型、对象所有权、虚调用目标和模板实例来源可解释；切片、悬空对象与跨模块实例化不会被隐藏。**。它必须在正常输入、空输入、创建失败、消息未处理、持久化版本不符和中断恢复中都成立。窗口看起来能显示、命令偶尔能执行或文件能写出，都不足以证明对象图、分派路径和资源生存期正确。

最小实验：构造基类指针、栈/堆/全局/静态对象和模板容器，打印构造析构、type_info与虚调用轨迹。 运行前记录工具版本、编译选项、链接方式、资源哈希、输入序列和预期调用路径；运行后保存消息日志、对象关系、文件字节或线程退出状态。

故障实验：注入对象切片、非虚析构、异常中途退出和模板定义缺失，比较编译期与运行期失败。 每次只改变一个条件，停在第一处与预测不同的位置。删除故障后从干净构建或明确逆操作恢复，并以完全相同的输入重放；如果最终画面相同但对象、句柄、线程、Archive或资源状态不同，仍判定失败。

机制证据表至少保留六列：框架表面动作、对应的C++对象或宏、下沉到Win32的入口、可观察状态、首个失败信号、恢复操作。对历史代码还要单列“原书行为”和“现代迁移差异”：前者用于解释MFC 4.2为何这样工作，后者只说明在64位、Unicode或新工具链中怎样验证同一不变量。这样既不会把旧API当成今天的最佳实践，也不会因现代封装更方便而跳过原书真正要揭示的内部机制。

## 最小可重放骨架

```cpp
struct Base { virtual ~Base() = default; virtual const char* name() const = 0; };
struct Derived final : Base { const char* name() const override { return "Derived"; } };
```

```cpp
void inspect(Base& object) {
  std::cout << object.name() << ' ' << typeid(object).name();
}
```

```cpp
template<class T> class Owner {
 public: explicit Owner(T* value) : value_(value) {}
 ~Owner() { delete value_; }
 private: T* value_;
};
```
