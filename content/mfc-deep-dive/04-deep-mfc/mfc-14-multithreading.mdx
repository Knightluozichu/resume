## 核心机制深挖

从模块、进程、线程、优先级、调度和Context进入Worker/UI Thread、CWinThread、创建、结束与同步。 原书绑定Visual C++ 5.0与MFC 4.2。本页保留这个历史技术身份；现代Visual Studio、64位、Unicode、智能指针或新UI框架只可作为明确标注的对照，不能反向改写原书机制。

本页不变量是：**窗口只由所属UI线程操作；共享数据有明确同步协议，线程对象与句柄生存期覆盖执行期，退出可等待。**。它必须在正常输入、空输入、创建失败、消息未处理、持久化版本不符和中断恢复中都成立。窗口看起来能显示、命令偶尔能执行或文件能写出，都不足以证明对象图、分派路径和资源生存期正确。

最小实验：Worker Thread计算笔画统计并PostMessage给UI线程，UI Thread样例维护独立消息泵，比较两者对象模型。 运行前记录工具版本、编译选项、链接方式、资源哈希、输入序列和预期调用路径；运行后保存消息日志、对象关系、文件字节或线程退出状态。

故障实验：注入跨线程SendMessage死锁、竞争写入、悬空参数和强制终止，检查Context与资源泄漏。 每次只改变一个条件，停在第一处与预测不同的位置。删除故障后从干净构建或明确逆操作恢复，并以完全相同的输入重放；如果最终画面相同但对象、句柄、线程、Archive或资源状态不同，仍判定失败。

机制证据表至少保留六列：框架表面动作、对应的C++对象或宏、下沉到Win32的入口、可观察状态、首个失败信号、恢复操作。对历史代码还要单列“原书行为”和“现代迁移差异”：前者用于解释MFC 4.2为何这样工作，后者只说明在64位、Unicode或新工具链中怎样验证同一不变量。这样既不会把旧API当成今天的最佳实践，也不会因现代封装更方便而跳过原书真正要揭示的内部机制。

## 最小可重放骨架

```cpp
AfxBeginThread(&computeStatistics, new ImmutableInput(snapshot));
```

```cpp
UINT computeStatistics(LPVOID raw) {
  std::unique_ptr<ImmutableInput> input(static_cast<ImmutableInput*>(raw));
  Result result = compute(*input);
  PostMessage(input->target, WM_APP_RESULT, 0, reinterpret_cast<LPARAM>(new Result(result)));
  return 0;
}
```

```text
worker owns computation; UI thread owns HWND
stop request -> wake wait -> join/observe exit -> release handles
```

<Callout type="trap">
  **误区一：AppWizard生成并能编译，就等于理解MFC。**
  生成代码只是一个样本。必须能沿全局Application对象、Document
  Template、运行时类、消息表和Win32回调解释每个关键动作。
</Callout>
