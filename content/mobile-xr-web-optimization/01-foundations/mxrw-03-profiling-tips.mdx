## 问题：怎样证明掌握的是官方单元 3，而不是背下一组技巧？

先预测：若只报告修改后FPS，没有设备、构建、场景、输入、热状态和画面合同，另一位开发者能否证明收益来自这次修改？不能。跨平台优化首先是受控实验，其次才是技巧选择。

跨平台优化从早期、持续、目标设备测量开始。Profiler负责定位帧与模块，Profile Analyzer比较多帧分布；温度和设备规格进入测试上下文，CPU或GPU分流决定下一工具。

## 核心模型与不可变条件

跨平台优化从早期、持续、目标设备测量开始。Profiler负责定位帧与模块，Profile Analyzer比较多帧分布；温度和设备规格进入测试上下文，CPU或GPU分流决定下一工具。

不可变条件是：**基线与候选使用同设备、构建、场景、画质、输入、热状态和帧范围，并同时保存CPU、GPU与长尾帧。** 如果测试上下文、视觉或玩法结果发生变化，就不能把两次数字直接相减。先解释变化，再决定是否建立新基线。

## 从输入到发布的证据链

主链为：**固定设备 → 预热稳态 → Profiler采样 → CPU/GPU分流 → Analyzer比较 → 回归结论**。每个节点保存平台、设备、浏览器或运行时、Unity与包版本、构建提交、场景检查点、预算、实际值和首个异常。后一节点只消费前一节点已验证事实。

## 可执行实现骨架

```csharp
using Unity.Profiling;

static readonly ProfilerMarker TickMarker = new("Gameplay.Tick");

void Update()
{
    using (TickMarker.Auto()) Tick(Time.deltaTime);
}

double FrameBudget(int targetFps) => 1000.0 / targetFps;
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="官方边界或测试上下文丢失">
  在Editor冷启动只测一次平均FPS，然后把结果外推到最低档手机、Web浏览器和XR头显。
  保存错误结论、首个偏离节点和原始数据，再恢复官方边界与相同条件复验。
</Callout>

<Callout type="trap" title="数字变好但结果或维护成本恶化">
  故意降低画质、跳过玩法工作、扩大永久缓存或增加难以维护的平台分支。若主指标改善但视觉、行为、内存、热量或发布可靠性变差，发布门必须拒绝。
</Callout>

## 证据矩阵与签发标准

| 维度       | 正常样本         | 边界样本           | 失败样本         | 签发条件       |
| ---------- | ---------------- | ------------------ | ---------------- | -------------- |
| 平台上下文 | 代表设备固定构建 | 最低规格或长时运行 | 故意改变一项条件 | 差异可解释     |
| 主证据链   | 六节点均记录     | 接近预算输入       | 首个节点注入偏差 | 能定位首因     |
| 性能结果   | 达到预算         | 无长尾越界         | 主动制造回归     | 同输入可复验   |
| 正确性     | 视觉玩法一致     | 生命周期完整       | 降质或转移成本   | 所有门同时通过 |
