## 问题：怎样证明掌握的是官方单元 6，而不是背下一组技巧？

先预测：若只报告修改后FPS，没有设备、构建、场景、输入、热状态和画面合同，另一位开发者能否证明收益来自这次修改？不能。跨平台优化首先是受控实验，其次才是技巧选择。

资产成本在导入时决定。纹理尺寸与压缩、网格属性与多边形、自动导入规则和Addressables分组必须按平台预算治理，运行时优化不能弥补错误源资产。

## 核心模型与不可变条件

资产成本在导入时决定。纹理尺寸与压缩、网格属性与多边形、自动导入规则和Addressables分组必须按平台预算治理，运行时优化不能弥补错误源资产。

不可变条件是：**每个发布资产都有平台格式、最大尺寸、内存估算、依赖与加载释放所有者，并通过自动导入规则复现。** 如果测试上下文、视觉或玩法结果发生变化，就不能把两次数字直接相减。先解释变化，再决定是否建立新基线。

## 从输入到发布的证据链

主链为：**源资产 → 导入规则 → 平台压缩 → 依赖分组 → 运行加载 → 内存签发**。每个节点保存平台、设备、浏览器或运行时、Unity与包版本、构建提交、场景检查点、预算、实际值和首个异常。后一节点只消费前一节点已验证事实。

## 三步复现与分步观察

<Stepper>
  <Step title="1. 冻结平台合同与输入">
    固定设备或浏览器、构建、场景、画质、预热、输入和结果合同，写出唯一假设及反证条件。

    内存签发”保存中间值，在首个越界点停止下钻；一次只修改一个主要因素。
    </Step>
  <Step title="3. 同输入复验并签发">

## 可执行实现骨架

```csharp
sealed class MobileTextureRules : AssetPostprocessor
{
    void OnPreprocessTexture()
    {
        var importer = (TextureImporter)assetImporter;
        importer.isReadable = false;
        importer.mipmapEnabled = !assetPath.Contains("/UI/");
        importer.maxTextureSize = 2048;
    }
}
```

PASS invariant=每个发布资产都有平台格式、最大尺寸、内存估算、依赖与加载释放所有者，并通过自动导入规则复现。
REJECT changed-context | hidden-quality-loss | shifted-cost | missing-failure-replay

## 两个必须主动制造的失败样本

<Callout type="trap" title="官方边界或测试上下文丢失">
  美术源文件更新后恢复默认导入设置，移动包重新使用超大RGBA纹理和Read/Write网格。
  保存错误结论、首个偏离节点和原始数据，再恢复官方边界与相同条件复验。
</Callout>

<Callout type="trap" title="数字变好但结果或维护成本恶化">
  故意降低画质、跳过玩法工作、扩大永久缓存或增加难以维护的平台分支。若主指标改善但视觉、行为、内存、热量或发布可靠性变差，发布门必须拒绝。
</Callout>

| 维度       | 正常样本         | 边界样本           | 失败样本         | 签发条件       |
