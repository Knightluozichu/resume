## 问题：怎样证明掌握的是官方单元 7，而不是背下一组技巧？

先预测：若只报告修改后FPS，没有设备、构建、场景、输入、热状态和画面合同，另一位开发者能否证明收益来自这次修改？不能。跨平台优化首先是受控实验，其次才是技巧选择。

## 核心模型与不可变条件

## 可执行实现骨架

```csharp
sealed class TickRegistry
{
    readonly List<ITickable> active = new(512);
    public void Add(ITickable item) => active.Add(item);
    public void Remove(ITickable item) => active.Remove(item);
    public void Tick(float dt)
    {
        for (int i = 0; i < active.Count; i++) active[i].Tick(dt);
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="官方边界或测试上下文丢失">
  把所有MonoBehaviour
  Update集中到一个管理器却不注销禁用对象，调用次数下降但旧对象仍持续执行。
  保存错误结论、首个偏离节点和原始数据，再恢复官方边界与相同条件复验。
</Callout>

<Callout type="trap" title="数字变好但结果或维护成本恶化">
  故意降低画质、跳过玩法工作、扩大永久缓存或增加难以维护的平台分支。若主指标改善但视觉、行为、内存、热量或发布可靠性变差，发布门必须拒绝。
</Callout>
