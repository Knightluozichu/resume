## 对象工厂要解决什么

面向对象程序常需「根据标识符动态创建对应类型的对象」——读配置文件根据控件名创建控件、根据消息类型创建处理器。但 C++ 没有反射，不能 `new "Button"`，必须有一套「标识符到构造函数」的映射。这就是对象工厂要解决的：把「用类型名动态构造对象」从语言缺失变成库提供。

<McdObjectFactoryDiagram />

对象工厂两个核心操作：Register 把「标识符到创建函数」对存进内部映射表，创建函数是返回基类指针的 lambda 或函数对象；CreateObject 根据标识符查表，调用对应创建函数返回新对象。工厂内部用 `std::map<string, CreatorFunc>` 存映射。启动时 Register 所有类型，运行时 CreateObject 查表构造。

价值是解耦调用方与具体类型——调用方只认基类接口和标识符，新增类型只需 Register 一条，不改正文代码，这是开闭原则的经典实现。

## GenFactory 自动生成

Loki 的 GenFactory 用 typelist 把「一族派生类型」作为模板参数，自动生成能创建族内任意类型的工厂。GenFactory 递归遍历 typelist，为每个类型生成创建函数（`new Derived` 包装成返回基类指针），把类型映射到整数索引，CreateObject 按索引查表调用。

相比手写工厂省了：手写一堆 Register 调用（typelist 自动注册）、手写 switch-case（编译器递归实例化生成分支）、标识符管理（用 typelist 索引无字符串拼写错误）。代价是所有类型必须编译时确定（typelist 是编译时结构），运行时新增类型不支持；标识符是整数索引不如字符串可读；模板膨胀。

## 克隆与抽象工厂的区别

工厂扩展支持克隆（原型模式）：注册原型对象指针和它的 Clone 方法，CreateObject 调用 `prototype->Clone()` 返回深拷贝。原型可预先配置状态，克隆出的对象继承状态。

对象工厂与抽象工厂的区别：对象工厂造「一个类型的多个变体」（1 个基类 N 个派生），用 CreateObject(id) 选类型；抽象工厂造「多个类型的一族变体」（M 个基类 N 个族），用多个 Make 方法各返回不同基类。对象工厂是 1:N，抽象工厂是 M:N。

<Callout type="tip">
<strong>建议 →</strong> 现代 C++ 工厂应返回 `unique_ptr<Base>` 而非裸指针，用 lambda 作 CreatorFunc，配合 DI 容器。Loki 工厂是 C++03 风格返回裸指针，现代改写要包智能指针。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> 忘记 Register 某个类型，运行时 CreateObject 返回空或抛异常。<strong>原因 →</strong> 字符串工厂的映射表是运行时构建的，漏注册编译不报错。<strong>修法 →</strong> 用 GenFactory（typelist 编译时注册）或在启动时加自检断言所有预期类型都已注册。
</Callout>

## 小结与练习

- 对象工厂解决「按标识符动态创建对象」，Register 建表、CreateObject 查表
- GenFactory 用 typelist 自动生成工厂，省手写 Register 与 switch-case
- 支持克隆（原型模式），注册原型对象和 Clone 方法
- 对象工厂 1:N（单基类多派生），抽象工厂 M:N（多基类多族）

## 名词解释

<Glossary>
  <GlossaryItem term="Register">对象工厂的注册操作，把「标识符到创建函数」对存进内部映射表，启动时建立完整映射。</GlossaryItem>
  <GlossaryItem term="CreateObject">对象工厂的创建操作，根据标识符查映射表调用对应创建函数返回新对象的基类指针。</GlossaryItem>
  <GlossaryItem term="GenFactory">Loki 的通用工厂，用 typelist 列出派生类型，递归遍历自动生成「索引到创建函数」映射，省手写注册。</GlossaryItem>
  <GlossaryItem term="原型模式">通过克隆已有原型对象创建新对象，工厂注册原型与 Clone 方法，CreateObject 调用 Clone 返回深拷贝。</GlossaryItem>
</Glossary>
