## SingletonHolder 的设计

经典单例（Meyers 单例）把创建方式、生命周期、线程安全写死成「函数内 static」，灵活度低。Loki 的 SingletonHolder 把这三个维度拆成 Policy 模板参数，让使用者按场景组合。

<McdSingletonDiagram />

三个 Policy 维度：CreationPolicy 决定单例怎么造（`CreateUsingNew` 用 new、`CreateStatic` 用静态局部对象免堆分配、`CreateUsingMalloc` 用 malloc 加 placement new）；LifetimePolicy 决定何时销毁、销毁顺序、死引用处理；ThreadingModel 决定线程安全等级（`SingleThreaded` 无锁、`ObjectLevelLockable` 对象锁）。

```cpp
template<
  typename T,
  template<class> class CreationPolicy = CreateUsingNew,
  template<class> class LifetimePolicy = DefaultLifetime,
  template<class> class ThreadingModel = ObjectLevelLockable
>
class SingletonHolder;
```

## 生命周期与销毁顺序

单例最棘手的是销毁顺序。C++ 全局/静态对象销毁顺序与构造相反，但跨翻译单元的单例依赖编译器看不到，导致「A 依赖 B，B 先销毁，A 析构访问 B 拿到死引用」。

LifetimePolicy 提供几种选择。`DefaultLifetime` 在 atexit 链里销毁。`PhoenixSingleton`（凤凰单例）销毁后若再被访问就重建，像凤凰复活，适合可重建的配置缓存。`SingletonWithLongevity` 让使用者给每个单例一个 longevity 数值，按数值降序销毁，保证被依赖的活到最后，适合依赖关系明确的场景。

## DCLP 的 bug 与现代写法

双重检查锁定（DCLP）是经典单例线程安全写法，但在 C++03 有 bug。`instance = new Singleton;` 分配内存、构造对象、赋指针三步，编译器和 CPU 可能重排成先赋指针再构造。另一线程第一次检查看到非空直接返回，但对象未构造完，未定义行为。根因是 C++03 没有内存模型，锁外读 instance 无同步。

C++11 正确写法是用 Meyers 单例——函数内 static 局部变量，标准保证线程安全初始化：

```cpp
Singleton& Instance() {
  static Singleton inst;   // C++11 起线程安全
  return inst;
}
```

或用 `std::call_once` 手动控制。Loki 的 DCLP 在 C++03 是已知缺陷，现代 C++ 应改用 Meyers 或 call_once。

<Callout type="trap">
<strong>现象 →</strong> 多单例析构时崩溃或读到无效数据。<strong>原因 →</strong> 跨翻译单元单例销毁顺序未定义，A 析构访问已销毁的 B。<strong>修法 →</strong> 用 SingletonWithLongevity 显式排销毁顺序，或改用依赖注入把生命周期交给调用方。现代 C++ 优先依赖注入减少全局单例。
</Callout>

<Callout type="tip">
<strong>建议 →</strong> 单例长期被批评（全局状态、隐藏依赖、难测试）。Loki Policy 化解决生命周期与线程安全，但无法解决「全局状态」本质。现代 C++ 优先依赖注入，实在要单例用 Meyers（C++11 起线程安全）。
</Callout>

## 小结与练习

- SingletonHolder 用三个 Policy 参数化：创建、生命周期、线程模型
- LifetimePolicy 解决销毁顺序与死引用：Phoenix 重建、Longevity 显式排序
- DCLP 在 C++03 有内存模型 bug，C++11 用 Meyers 单例或 call_once
- 单例本质是全局状态，现代 C++ 优先依赖注入

## 名词解释

<Glossary>
  <GlossaryItem term="CreationPolicy">单例创建策略，决定如何构造单例对象，如 CreateUsingNew、CreateStatic（静态局部免堆分配）。</GlossaryItem>
  <GlossaryItem term="LifetimePolicy">单例生命周期策略，决定销毁时机与顺序，如 PhoenixSingleton（销毁后可重建）、SingletonWithLongevity（按 longevity 排序销毁）。</GlossaryItem>
  <GlossaryItem term="DCLP">双重检查锁定模式，先无锁检查再持锁构造的线程安全单例写法，C++03 下因无内存模型有 bug。</GlossaryItem>
  <GlossaryItem term="死引用">单例销毁后其他对象仍持有其引用，访问导致未定义行为，是多单例销毁顺序问题的核心症状。</GlossaryItem>
</Glossary>
