## 直觉引入

把物理内存想象成一栋宿舍楼，每个进程是一个住客。最朴素的方案是「连续分配」——给每个住客分一整层连续的房间。问题是住客人数变了就得搬家（外部碎片），住客东西少了空出半层也浪费（内部碎片）。**分段**是改进版：不再整层分，而是按用途切——代码段、数据段、栈段各分一块连续房间，段内连续、段间不必相邻。但段大小不一，搬来搬去还是碎片。**分页**是终极方案：把宿舍楼切成固定大小的「4KB 标准间」，每个进程的地址空间也切成 4KB 页，用一张「页表」记录「虚拟页 → 物理帧」的映射。页是固定大小，任何空闲帧都能放任何页，外部碎片彻底消除。这就是现代操作系统的内存管理基石。

## 分段与分页

<Term def="虚拟内存是为每个进程提供的独立、连续的虚拟地址空间抽象。它通过 MMU + 页表把虚拟地址翻译成物理地址，使每个进程以为自己独占整台机器的内存，实际物理内存被多进程共享且按需分配。">虚拟内存</Term>的核心是「地址翻译」——程序发出的虚拟地址（VA）经 MMU 翻译成物理地址（PA）。**分段**的翻译是：虚拟地址 = (段号, 段内偏移)，段表记录每段的基址和界限，PA = 段基址 + 偏移。分段的好处是「按逻辑结构切分」（代码、数据、栈各自成段），缺点是段大小可变导致外部碎片严重。**分页**的翻译是：虚拟地址 = (页号, 页内偏移)，页表记录「虚拟页号 → 物理帧号」，PA = 帧号 × 页大小 + 偏移。分页的好处是页固定大小、无外部碎片，缺点是最后一页可能浪费（内部碎片）且页表本身占内存。

```text
// 分页地址翻译全链路（以 32 位、4KB 页为例）

// 虚拟地址 32 位 = 页号(20位) + 偏移(12位)
//   2^12 = 4096 = 4KB 页大小
//   2^20 = 1M 个虚拟页号

// 单级页表的问题：1M 项 × 4字节/项 = 4MB 页表/进程
//   100 个进程 = 400MB 页表，全驻内存太浪费

// 多级页表（x86 二级）：
//   虚拟地址 = 页目录号(10) + 页表号(10) + 偏移(12)
//   页目录 1024 项 × 4B = 4KB（始终驻留）
//   每个页目录项指向一个页表（4KB），按需分配
//   未使用的地址范围对应的页表根本不分配 → 省内存

// TLB（Translation Lookaside Buffer）：页表项的高速缓存
//   MMU 先查 TLB，命中则一步出物理地址（~1 周期）
//   未命中则遍历多级页表（多次访存），称为「page table walk」
//   典型 TLB 命中率 &gt; 99%，是虚拟内存能高效运行的关键
```

## 虚拟内存与按需调页

虚拟内存让进程的地址空间可以远大于物理内存——页表项有个「有效位」（valid bit），为 0 表示该页不在物理内存中（可能在磁盘 swap 区或文件中）。当程序访问一个有效位为 0 的页时，MMU 触发**缺页异常**（page fault），内核接管：①查页表确认该页在磁盘的位置；②找一个空闲物理帧（没有就触发页面置换淘汰一页）；③从磁盘读入该页到物理帧；④更新页表项（帧号 + 有效位 = 1）；⑤重新执行触发缺页的指令。这就是**按需调页**（demand paging）——页不在内存时才按需调入，而非一次性全部载入。好处是进程可以比物理内存大、启动快（只载入首页）、多个进程共享物理帧（如共享库的代码页映射到不同进程的同一虚拟地址）。

## 常见误区

<Callout type="trap">
**误区：虚拟内存就是「用磁盘当内存」，所以访问磁盘上的页和访问内存一样快。** 错。虚拟内存的「快」靠的是局部性原理 + TLB——程序访问的地址高度集中（时间局部性、空间局部性），TLB 缓存了最近翻译的页表项，99% 以上的访存一步命中、和物理内存几乎一样快。一旦缺页，代价是磁盘 I/O（毫秒级，比内存慢 10 万倍）。如果缺页率太高（如工作集大于物理内存导致抖动），CPU 大部分时间在等磁盘，系统直接卡死。虚拟内存的本质是「用少量物理内存 + 磁盘做溢出，靠局部性让大多数访问命中内存」——它是用空间换时间的精心设计，不是「磁盘当内存随便用」。
</Callout>

<Exercises>
**问题 1**：为什么多级页表比单级页表省内存？

<Answer>
单级页表必须为整个地址空间的每一个页都预留一个页表项——32 位系统 4GB 地址空间、4KB 页 = 1M 项 × 4 字节 = 4MB 页表，每个进程都要 4MB，且必须常驻内存。但绝大多数进程只用了地址空间的一小部分（代码+数据+栈可能只有几十 MB），剩下上 GB 的地址空间根本没映射——单级页表里这些项全是无用的「无效」项，白白占 4MB。多级页表按需分配：页目录常驻（4KB），但二级页表只为「实际使用的地址范围」分配。未用的地址范围在页目录里就是「不存在」项，根本不分配对应的二级页表。一个只用 10MB 内存的进程，只需 3 个二级页表（12KB）+ 1 个页目录（4KB）= 16KB，远小于单级的 4MB。代价是多一次访存（page table walk），但 TLB 让这代价几乎不出现。
</Answer>

**问题 2**：缺页处理的完整流程是什么？为什么说按需调页让进程可以「大于物理内存」？

<Answer>
缺页流程：①程序访问虚拟地址，MMU 查页表发现有效位 = 0，触发缺页异常陷入内核；②内核查页表项确认该页在磁盘的位置（swap 区或映射文件）；③在物理内存找一个空闲帧，若无空闲则用页面置换算法（LRU/Clock）淘汰一页腾出帧（若被淘汰页是脏页还需写回磁盘）；④启动磁盘 I/O 把该页从磁盘读入物理帧；⑤I/O 完成后更新页表项（填入帧号、有效位置 1）；⑥恢复进程上下文，重新执行触发缺页的那条指令（这次 MMU 翻译就能成功）。按需调页让进程「大于物理内存」的原理是：进程的地址空间可以远超物理内存，但任一时刻只有「正在使用的工作集」驻留在物理帧中，其余页存在磁盘。只要缺页率低（工作集 &lt; 物理内存），程序照常运行——靠局部性原理，大部分访问命中驻留页，偶尔缺页才去磁盘换入。物理内存只是地址空间的「缓存」。
</Answer>

<Glossary>
<GlossaryItem term="虚拟内存">每个进程拥有的独立、连续的虚拟地址空间抽象。通过 MMU + 页表翻译成物理地址，使进程以为自己独占整台机器内存。核心机制是按需调页——页不在内存时才从磁盘调入。靠局部性 + TLB 让大多数访存一步命中。</GlossaryItem>
<GlossaryItem term="分页">把地址空间切成固定大小的页（如 4KB），物理内存切成同等大小的帧，用页表记录「虚拟页 → 物理帧」映射。固定大小消除外部碎片，任何空闲帧可放任何页。代价是内部碎片（最后一页）和页表占内存。</GlossaryItem>
<GlossaryItem term="TLB">Translation Lookaside Buffer，页表项的高速缓存。MMU 先查 TLB，命中则一步出物理地址；未命中则遍历多级页表（page table walk）。典型命中率 &gt; 99%，是虚拟内存高效运行的关键——没有 TLB，每次访存要多查数次页表。</GlossaryItem>
<GlossaryItem term="缺页">访问有效位为 0 的页时 MMU 触发的异常。内核接管后从磁盘调入该页、更新页表、重新执行指令。代价是磁盘 I/O（毫秒级）。缺页率过高导致抖动——CPU 大部分时间等磁盘，系统卡死。</GlossaryItem>
</Glossary>
