## 直觉引入

把磁盘想象成一台老式点唱机——磁头臂像唱针要在不同磁道（柱面）间移动，每移动一次都要「寻道」（机械臂物理转动）。寻道是毫秒级的机械运动，比磁盘旋转和数据传输慢得多，是磁盘性能的主要瓶颈。磁盘调度的目标就是**最小化寻道距离**。FCFS（先来先服务）就是「按请求顺序移动」——磁头可能从柱面 1 跳到 100 再跳回 5，来回横穿。SSTF（最短寻道优先）就是「每次找最近的请求」——贪心但可能让远端请求饿死。SCAN（电梯算法）就是「磁头沿一个方向扫到底再折返」——像电梯一层层停，公平且高效。C-SCAN（循环扫描）是「只在一个方向服务，到头快速返回」——各请求等待时间更均匀。LOOK 是 SCAN 的变体——「不到物理边界，到最远请求就折返」，不白跑空段。

## 磁盘结构与寻道模型

<Term def="磁盘由多个盘片叠成，每个盘面有磁头，同位置的所有磁道构成一个柱面。访问数据的三步时间是：寻道时间（磁臂移到柱面）+ 旋转延迟（盘片转到扇区）+ 传输时间（读扇区数据）。寻道是机械运动，通常是主要瓶颈。">磁盘</Term>的物理结构决定了性能模型。一个磁盘有若干**盘片**（platter），每面有**磁道**（track），磁道分成**扇区**（sector）。所有盘面同一位置的磁道构成一个**柱面**（cylinder）——磁头臂移动到某柱面后，所有盘面的该磁道同时可达。访问一个扇区的时间 = **寻道时间**（磁臂移到目标柱面，平均 5-10ms）+ **旋转延迟**（盘片转到目标扇区，平均半转，4-6ms）+ **传输时间**（读扇区，微秒级）。寻道是纯机械运动，远比电子传输慢，所以磁盘调度的核心是**让磁头臂少跑路**。

```text
// 磁盘调度五算法（柱面请求队列：98, 183, 37, 122, 14, 124, 65, 67）
// 当前磁头在 53，柱面范围 0-199

// FCFS（先来先服务）：按到达顺序服务
//   53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
//   总寻道距离 = 45+85+146+85+108+110+59+2 = 640
//   优点：公平、无饥饿；缺点：来回横穿，寻道距离大

// SSTF（最短寻道优先）：每次选离当前最近的
//   53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
//   总寻道距离 = 12+2+30+23+84+24+2+59 = 236
//   优点：寻道距离小；缺点：远端请求可能饥饿（持续有近请求来）

// SCAN（电梯算法）：沿一个方向扫到底，再折返
//   向大方向：53 → 65 → 67 → 98 → 122 → 124 → 183 → (199边界)
//   折返：183 → 124 → 122 → 98 → 67 → 65 → 37 → 14
//   优点：寻道高效、无饥饿；缺点：两端请求等待方差大

// C-SCAN（循环扫描）：只向大方向服务，到头快速返回到 0 再扫
//   53 → 65 → 67 → 98 → 122 → 124 → 183 → (199) → (0) → 14 → 37
//   优点：各请求等待时间更均匀（都经历一次单向扫描）
//   缺点：返回段有「空跑」（C-LOOK 改进：只返回到最小请求 14）

// LOOK：SCAN 但不到物理边界，到最远请求即折返
//   向大：53 → ... → 183（最远请求，折返，不跑到 199）
//   向小：183 → ... → 14（最小请求，折返，不跑到 0）
//   现代系统常用 LOOK，避免白跑空段
```

## 算法权衡对比

FCFS 最公平（严格按序）但寻道距离最大——磁头可能反复横穿。SSTF 寻道距离小但会饥饿——若柱面 50 附近源源不断来请求，柱面 180 的请求永远轮不到。SCAN（电梯）是折中——磁头沿一个方向扫过所有请求，到边界折返，既高效又无饥饿，但两端的请求等待方差大（刚扫过的那端要等磁头跑个来回）。C-SCAN 把折返改成「快速返回到起点重扫」，让所有请求的等待时间更均匀（都经历一次单向扫描），代价是返回段有「空跑」（C-LOOK 改进为只返回到最小请求）。现代操作系统多用 **LOOK/C-LOOK** 的变体——既避免白跑到物理边界，又兼顾公平与寻道效率。对 SSD（无机械寻道），这些算法意义减弱——SSD 的随机访问代价低，调度策略更关注磨损均衡（wear leveling）和垃圾回收。

## 常见误区

<Callout type="trap">
**误区：磁盘调度算法对 SSD 同样重要。** 错。FCFS/SSTF/SCAN/C-SCAN 的优化目标是「寻道时间」——磁臂的机械运动，这是机械盘独有的。SSD 没有磁臂，任意逻辑块访问时间几乎相同（几十微秒），不存在「柱面 1 到 100 比到 50 慢」的几何关系。SSD 的调度关注点完全不同：①磨损均衡（wear leveling）——让写入均匀分布到各闪存块，避免某些块先写坏；②垃圾回收——后台合并有效页、擦除无效块；③TRIM——告知 SSD 哪些块已删除可提前擦除。把 SCAN 用在 SSD 上没有意义，反而 SSD 内部的 FTL（闪存转换层）会把逻辑地址映射到物理页，对操作系统隐藏真实位置。调度算法要匹配硬件特性。
</Callout>

<Exercises>
**问题 1**：SSTF 为什么会导致饥饿？SCAN 如何避免？

<Answer>
SSTF 每次选离当前磁头最近的请求，若柱面 50 附近源源不断来新请求，磁头会一直在 50 附近打转，柱面 180 的请求永远「不是最近的」而轮不到——这就是饥饿。SCAN（电梯算法）避免饥饿的机制是「方向锁定」：磁头沿一个方向（如向大柱面）扫过，途中的请求按柱面顺序依次服务，到边界才折返。因为方向是固定的，远端请求（180）一定会被扫到——磁头向大方向扫时必然经过 180，不会因为中途有更近的请求而跳过它（中途请求已按顺序服务）。这就像电梯——向上运行时，10 楼的请求不会让电梯跳过 9 楼，因为方向锁定按楼层顺序停。代价是刚扫过的那端请求要等磁头跑到边界再折返，等待方差大；C-SCAN 用「单向服务 + 快速返回」让等待更均匀。
</Answer>

**问题 2**：磁盘访问的三段时间是什么？为什么寻道是主要瓶颈？

<Answer>
三段时间：①寻道时间——磁臂机械移到目标柱面，平均 5-10ms；②旋转延迟——盘片旋转到目标扇区到磁头下，平均半转，4-6ms（7200rpm）；③传输时间——读扇区数据，微秒级（单扇区 512B/4KB，带宽 100-200MB/s）。寻道是主要瓶颈的原因：它是纯机械运动（磁臂转动），受物理惯性限制，毫秒级且难以再缩短；旋转延迟也是机械的但随转速固定；传输是电子的，微秒级可忽略。寻道时间通常是三段中最大的（5-10ms vs 4-6ms vs 微秒级），所以磁盘调度的核心是最小化寻道距离——FCFS/SSTF/SCAN/C-SCAN 全在优化磁臂的移动路径。这也是为什么顺序读远快于随机读：顺序读只寻道一次（到起始位置），后续扇区靠旋转连续读；随机读每次都要重新寻道。
</Answer>

<GlossaryItem term="磁盘结构">多盘片叠加，每面磁头，同位置磁道构成柱面。访问三段时间：寻道（磁臂移柱面，5-10ms，机械运动）+ 旋转延迟（盘片转半转，4-6ms）+ 传输（微秒级）。寻道是主要瓶颈，磁盘调度核心是最小化寻道距离。</GlossaryItem>
<GlossaryItem term="SCAN（电梯算法）">磁头沿一个方向扫到底再折返，途中请求按柱面顺序服务。高效且无饥饿（方向锁定保证远端必被扫到），缺点是两端等待方差大。C-SCAN 改为单向服务+快速返回让等待更均匀。</GlossaryItem>
<GlossaryItem term="SSTF">最短寻道优先，每次选离当前最近的请求。寻道距离小但会饥饿——近端源源不断来请求则远端永远轮不到。是贪心策略的典型反例（局部最优不等于全局最优）。</GlossaryItem>
<GlossaryItem term="LOOK / C-LOOK">SCAN/C-SCAN 的改进：不跑到物理边界，只到最远/最近请求即折返，避免白跑空段。现代 OS 常用。SSD 无寻道，这些算法对 SSD 意义减弱，SSD 关注磨损均衡和 GC。</GlossaryItem>
