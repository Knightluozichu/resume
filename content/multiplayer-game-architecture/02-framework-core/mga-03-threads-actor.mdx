## 直觉：先找唯一事实

从架构瓶颈和游戏主循环推导进程、线程与Actor的职责，让每个Actor串行拥有状态并通过消息处理跨线程协作。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
void Actor::drain(std::size_t budget) {
    assert(std::this_thread::get_id() == owner_thread_);
    for (std::size_t i = 0; i < budget; ++i) {
        auto message = mailbox_.try_pop();
        if (!message) break;
        apply(*message);
    }
}
```

同时保存阶段轨迹，不能只看最终返回值：

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  Actor暴露内部对象引用给其他线程，表面使用消息模型，实际仍然发生无锁并发写。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  邮箱无限增长且没有公平调度，一个热门Actor拖垮进程内所有其他Actor。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **游戏主循环**：按固定阶段消费输入、更新状态、发送输出并记录耗时的循环。
- **Actor**：串行拥有私有状态并仅通过异步消息交互的并发单元。
- **邮箱**：保存发送给Actor且等待按序消费的有界消息队列。
- **线程亲和**：Actor在一个调度代际中固定由指定执行线程消费的约束。
- **背压**：下游达到容量预算后主动减速、拒绝或降级上游输入的机制。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
