## 直觉：先找唯一事实

把PHP验证接口、第三方库、账号校验、消息过滤和机器人批量登录串成可防重放、可限流、可审计的登录链路。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
LoginResult LoginService::verify(const LoginRequest& request) {
    limiter.consume(request.remote_ip());
    replay_guard.consume(request.nonce());
    Identity identity = php_auth.verify(request.proof());
    return tickets.issue(identity, gate_audience, ttl_30s);
}
```

同时保存阶段轨迹，不能只看最终返回值：

```text
trace_id,stage,request_id,generation,state_version,budget,decision
baseline-01,绘制登录时序,42,7,1,normal,accept
boundary-01,签发并绑定会话,43,7,2,limit,accept
failure-01,机器人批量压测签发,44,6,2,exceeded,reject
```

每个样本从相同夹具开始，只改变一个故障变量：

```text
for sample in [baseline, boundary, failure, recovery]:

  assert_single_owner_and_current_generation()
  assert_bounded_queue_and_memory()
```

## 可复现实验

用机器人并发提交正常、错误密码、重复Nonce、过期票据和超速消息，先预测过滤器的拒绝顺序，再核对每个请求ID的唯一结果。 保存编译版本、配置摘要、协议版本、随机种子、请求序号、首偏离节点、恢复动作和最终决策。平均吞吐只能说明趋势，不能证明关键状态没有重复或丢失。

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  客户端提交账号ID后服务端直接信任，没有让验证接口签名或绑定Nonce，任意账号都可被冒用。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  批量登录只统计成功数，不保存失败阶段和请求ID，无法区分限流、依赖超时与协议错误。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **登录凭据**：用于证明账号控制权且不应以明文长期保存的秘密或证明。
- **会话票据**：登录成功后签发的短期、限受众、可撤销授权。
- **Nonce**：用于保证同一认证请求不能被成功重放的一次性随机值。
- **消息过滤**：按认证阶段、消息类型、尺寸和速率拒绝非法输入的入口策略。
- **测试机器人**：按确定脚本模拟登录、断线和重试并保存证据的自动客户端。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
- 公开目录条目已逐项列出，随书源码与现代补充不会冒充原书分节。
