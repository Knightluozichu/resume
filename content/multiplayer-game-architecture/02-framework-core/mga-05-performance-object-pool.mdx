## 直觉：先找唯一事实

用Visual Studio工具、gprof和valgrind建立证据，再从内存布局与生命周期判断对象池是否真正降低分配成本而未引入复用污染。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
Handle Pool::acquire() {
    Slot& slot = free_.pop();
    ++slot.generation;
    slot.value.reset();
    slot.in_use = true;
    return Handle{slot.index, slot.generation};
}
```

同时保存阶段轨迹，不能只看最终返回值：

```text
trace_id,stage,request_id,generation,state_version,budget,decision
baseline-01,固定性能基线,42,7,1,normal,accept
boundary-01,判断池化对象,43,7,2,limit,accept
failure-01,高水位回收后签发,44,6,2,exceeded,reject
```

每个样本从相同夹具开始，只改变一个故障变量：

```text
for sample in [baseline, boundary, failure, recovery]:
  reset_fixture(seed = 20260716)
  run_same_script(sample)
  assert_single_owner_and_current_generation()
  assert_bounded_queue_and_memory()
  export_first_divergence_and_recovery()
```

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  看到分配函数在热点中就把所有对象池化，却增加锁竞争、缓存抖动和常驻内存。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  归还对象时没有清空订阅、身份和缓冲区，新会话继承上一位玩家的状态。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **基线**：在固定版本、负载和环境下保存的优化前指标与轨迹。
- **热点**：在代表负载中占用显著CPU时间、分配或等待预算的代码路径。
- **内存布局**：字段在缓存行、对象和容器中的组织方式及其访问局部性。
- **对象池**：复用同类对象存储并显式管理获取、重置和归还的结构。
- **代际**：对象每次从池中重新获取时递增、用于拒绝旧引用的版本。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
