## 直觉：先找唯一事实

从最小ECS工程推进到libserver、login、robots、YAML与log4cplus，使实体身份、组件数据、系统行为、配置和日志各有明确边界。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
struct Entity { std::uint32_t index; std::uint32_t generation; };

void MovementSystem::update(World& world, Duration dt) {
    world.each<Position, Velocity>([dt](Entity entity, Position& p, const Velocity& v) {
        p.value += v.value * dt.count();
    });
}
```

同时保存阶段轨迹，不能只看最终返回值：

```text
trace_id,stage,request_id,generation,state_version,budget,decision
baseline-01,建立实体代际,42,7,1,normal,accept
boundary-01,抽取libserver,43,7,2,limit,accept
failure-01,配置日志回归签发,44,6,2,exceeded,reject
```

每个样本从相同夹具开始，只改变一个故障变量：

```text
for sample in [baseline, boundary, failure, recovery]:
  reset_fixture(seed = 20260716)
  run_same_script(sample)
  assert_single_owner_and_current_generation()
  assert_bounded_queue_and_memory()
  export_first_divergence_and_recovery()
```

## 可复现实验

反复创建销毁实体并延迟投递旧消息，先预测无代际句柄的污染位置，再打乱System注册顺序验证依赖检查。 保存编译版本、配置摘要、协议版本、随机种子、请求序号、首偏离节点、恢复动作和最终决策。平均吞吐只能说明趋势，不能证明关键状态没有重复或丢失。

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  Entity只用整数索引，销毁后索引被复用，旧消息错误地修改新实体。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  System依赖通过注册顺序隐式决定，增加一个系统后更新次序改变且没有启动期检查。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

<Mga06EcsFrameworkEvidenceLab />

本页签发不变量是：**实体句柄含代际；组件数据与系统行为分离；系统依赖可拓扑排序；配置校验失败阻止启动。** 任何单次演示、截图或平均指标都不能替代代际、序号、状态摘要和恢复证据。

## 小结

- **Entity**：只承担稳定身份、由索引和代际共同组成的ECS实体句柄。
- **Component**：按数据职责组织且不隐含执行顺序的实体状态片段。
- **System**：查询所需组件并按阶段更新它们的行为单元。
- **YAML配置**：启动时解析、校验并形成不可变运行快照的外部配置。
- **结构化日志**：以固定字段记录事件、实体、请求和决策而非拼接自然语言。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
