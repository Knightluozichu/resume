## 直觉引入

你和朋友微信约饭。你说「我 10 分钟到」，朋友回「好的我也快了」。你们各自根据自己的估计出发（客户端预测），到了之后打电话确认位置（服务器校正）——如果实际路况导致你晚到了 5 分钟，你会告诉朋友「我改到 15 分钟到」（校正后的新预测）。如果你只是看着朋友的朋友圈定位等他（快照插值），你看到的定位不是实时的，而是他几秒前发的，你根据历史位置推算他现在大概在哪。这就是多人在线游戏状态复制的三个核心机制。

## 权威服务器与客户端预测

<Term def="权威服务器模型是指服务器持有游戏状态的唯一权威副本，所有客户端的状态变更必须经服务器确认才生效。">权威服务器模型</Term>是多人在线游戏的标配。客户端想移动角色？发送移动请求给服务器，服务器计算新位置后广播给所有相关客户端。问题在于网络有延迟——如果客户端每次都等服务器确认才移动，玩家会感到明显的「输入延迟」（按了方向键但角色不动）。解决方案是客户端预测。

<Term def="客户端预测是指客户端在发送请求后不等服务器确认，先本地模拟预测结果，待服务器返回权威结果后再做校正。">客户端预测</Term>的核心思路是「乐观执行」。客户端发送移动请求后，立刻在本地按预期方向移动角色。当服务器返回权威位置后，客户端比对预测位置和权威位置：如果一致，什么都不做（预测正确）；如果有偏差，客户端将角色「 snapping」到服务器位置（校正）。好的预测算法能做到 95% 以上的预测命中率，玩家几乎感觉不到校正。

<Term def="快照插值是客户端对远程玩家的状态不做预测，而是缓存服务器广播的状态快照，在两个快照之间做线性插值以获得平滑表现。">快照插值</Term>处理的是「看别人」的问题。对于远程玩家，你收到的是服务器定期广播的位置快照（如每秒 20 次），如果直接用这些离散位置渲染，角色会「一卡一卡」地跳。插值的做法是：始终渲染「稍延迟于当前时间」的位置（如延迟 100ms），在两个快照之间做线性插值，让远程玩家的移动看起来平滑连续。

```go
// 客户端预测 + 服务器校正
type ClientMovement struct {
    pendingInputs []InputSeq // 已发送但未确认的输入序列
    serverPos     Vec3       // 服务器最新确认的位置
    predictedPos  Vec3       // 客户端预测的当前位置
}

func (c *ClientMovement) ApplyInput(input Input) {
    // 1. 客户端预测：立即本地模拟
    c.predictedPos = simulate(c.predictedPos, input)
    c.pendingInputs = append(c.pendingInputs, input.Seq)
    // 2. 发送输入给服务器（不等回复）
    sendToServer(input)
}

func (c *ClientMovement) OnServerReconcile(serverPos Vec3, lastAckSeq int) {
    // 3. 服务器校正：丢弃已确认的输入
    c.pendingInputs = dropAcked(c.pendingInputs, lastAckSeq)
    c.serverPos = serverPos
    // 4. 从服务器位置重新模拟未确认的输入
    c.predictedPos = serverPos
    for _, input := range c.pendingInputs {
        c.predictedPos = simulate(c.predictedPos, input)
    }
    // 5. 如果偏差过大，直接 snap（瞬移）
    if dist(c.predictedPos, serverPos) &gt; SNAP_THRESHOLD {
        c.predictedPos = serverPos
    }
}
```

## 常见误区

<Callout type="trap">
**误区：客户端预测等于让客户端做决定。** 客户端预测只是「乐观渲染」——客户端先按预期走，但最终位置以服务器为准。如果客户端预测错了（比如撞到服务器知道但客户端不知道的墙），服务器校正会把角色拉回正确位置。预测不改变「服务器权威」的本质，只是用「先走后校」的方式掩盖网络延迟。如果让客户端真正做决定，那就是客户端权威——作弊者可以伪造位置。
</Callout>

<Exercises>
**问题 1**：客户端预测和服务器校正的完整流程是什么？

<Answer>
① 客户端采集输入 → ② 本地预测模拟（立即移动）→ ③ 发送输入给服务器 → ④ 服务器权威计算 → ⑤ 服务器返回确认的位置 + 最后确认的输入序号 → ⑥ 客户端丢弃已确认输入 → ⑦ 从服务器位置重新模拟未确认输入 → ⑧ 比对预测位置和校正后位置，偏差小则忽略、偏差大则 snap。整个过程中玩家看到的是预测位置（流畅），服务器返回的是权威位置（正确），两者通过校正机制收敛。
</Answer>

**问题 2**：为什么远程玩家要用插值而不是预测？

<Answer>
本地玩家的输入是已知的，可以准确预测；远程玩家的输入是未知的，你不知道他下一秒会按什么键，无法预测。如果对远程玩家做预测，预测方向经常错误，角色会反复跳变，体验更差。插值的策略是「宁可延迟也不要跳变」——始终渲染 100ms 前的位置，在快照之间平滑过渡。虽然远程玩家看起来比实际位置延迟 100ms，但移动是平滑的，不会突然瞬移。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="权威服务器">持有游戏状态唯一权威副本的服务器，所有状态变更必须经其确认。是反作弊的基石。</GlossaryItem>
<GlossaryItem term="客户端预测">客户端发送请求后不等服务器确认，先本地模拟预期结果，待服务器返回后再校正。用「先走后校」掩盖延迟。</GlossaryItem>
<GlossaryItem term="服务器校正">客户端收到服务器权威位置后，比对预测位置并做调整。偏差小时忽略，偏差大时 snap。</GlossaryItem>
<GlossaryItem term="快照插值">客户端缓存远程玩家的状态快照，在两个快照间做线性插值，以平滑延迟换取消除跳变。</GlossaryItem>
</Glossary>
