## 核心概念与所有权

<Term def="封装连接获取、超时、健康检查和归还的数据库边界。">连接组件</Term>、<Term def="把SQL结构与用户值分别提交给数据库解析的执行方式。">参数化查询</Term>、<Term def="一组写入全部提交或全部回滚的原子边界。">事务</Term>、<Term def="带版本、前置检查和回退策略的表结构演进。">Schema迁移</Term>、<Term def="在数据库字段与Protobuf消息间显式转换类型、缺省值和版本。">数据映射</Term>。
这些概念要同时回答四个问题：谁创建输入，谁拥有可变状态，什么代际拒绝旧结果，失败后谁回滚或补偿。

|   # | 概念       | 工程含义                                                 |
| --: | ---------- | -------------------------------------------------------- |
|   1 | 连接组件   | 封装连接获取、超时、健康检查和归还的数据库边界。         |
|   2 | 参数化查询 | 把SQL结构与用户值分别提交给数据库解析的执行方式。        |
|   3 | 事务       | 一组写入全部提交或全部回滚的原子边界。                   |
|   4 | Schema迁移 | 带版本、前置检查和回退策略的表结构演进。                 |
|   5 | 数据映射   | 在数据库字段与Protobuf消息间显式转换类型、缺省值和版本。 |

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  先查询角色不存在再单独插入，没有唯一约束和事务，两个并发请求创建重复角色。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  直接按字段顺序把SELECT结果写入Protobuf，表结构调整后字段错位却不报错。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **连接组件**：封装连接获取、超时、健康检查和归还的数据库边界。
- **参数化查询**：把SQL结构与用户值分别提交给数据库解析的执行方式。
- **事务**：一组写入全部提交或全部回滚的原子边界。
- **Schema迁移**：带版本、前置检查和回退策略的表结构演进。
- **数据映射**：在数据库字段与Protobuf消息间显式转换类型、缺省值和版本。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
- 公开目录条目已逐项列出，随书源码与现代补充不会冒充原书分节。
