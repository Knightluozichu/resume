## 直觉：先找唯一事实

用SystemManager、allinone工程、线程分类、IAwakeSystem、对象池、主动销毁和时间堆完善ECS生命周期与定时调度。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
void TimerHeap::dispatch(TimePoint now) {
    while (!heap_.empty() && heap_.top().deadline <= now) {
        Timer timer = heap_.pop();
        if (owners_.is_current(timer.owner, timer.generation))
            timer.callback();
    }
}
```

同时保存阶段轨迹，不能只看最终返回值：

```text

failure-01,取消重入后签发,44,6,2,exceeded,reject
```

## 可复现实验

为池化对象安排一万个定时器并在一半到期前销毁，先预测裸指针方案的污染，再验证代际令牌和时间堆复杂度。 保存编译版本、配置摘要、协议版本、随机种子、请求序号、首偏离节点、恢复动作和最终决策。平均吞吐只能说明趋势，不能证明关键状态没有重复或丢失。

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  对象归还池后旧定时器仍持有裸指针，到期时修改已复用给新实体的内存。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  SystemManager关闭顺序与启动顺序相同，上游先释放后下游仍在发送消息。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>
