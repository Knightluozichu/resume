## 直觉：先找唯一事实

在game与space职责之间引入Redis共享短期状态，以性能剖析验证多进程登录协议而不把Redis误当永久事实源。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```text
SET login:{account} {session_generation} NX EX 30
if result != OK: reject_duplicate_login
bind ticket to session_generation
renew only after authenticated heartbeat
delete with compare-and-delete on logout
```

同时保存阶段轨迹，不能只看最终返回值：

```text
trace_id,stage,request_id,generation,state_version,budget,decision
baseline-01,划分game与space,42,7,1,normal,accept
boundary-01,分析共享瓶颈,43,7,2,limit,accept
failure-01,Redis失效后签发,44,6,2,exceeded,reject
```

每个样本从相同夹具开始，只改变一个故障变量：

```text
for sample in [baseline, boundary, failure, recovery]:
  reset_fixture(seed = 20260716)
  run_same_script(sample)
  assert_single_owner_and_current_generation()
  assert_bounded_queue_and_memory()
  export_first_divergence_and_recovery()
```

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  多个进程先GET再SET登录状态，没有原子条件写，两个并发登录都认为自己成功。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  Redis超时后直接放行登录，短暂依赖故障演变为重复会话和状态分叉。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **game进程**：承载玩家业务身份和非空间玩法状态的服务进程。
- **space进程**：拥有地图空间实体、移动和区域交互事实的服务进程。
- **Redis**：用于跨进程共享短期状态、原子键操作和过期数据的内存数据库。
- **TTL**：Redis键自动失效前的剩余生存时间。
- **登录幂等键**：让同一登录意图在重试时只产生一个有效会话的唯一键。
