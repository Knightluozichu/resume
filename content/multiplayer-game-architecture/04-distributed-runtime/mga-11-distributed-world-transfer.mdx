## 直觉：先找唯一事实

把资源配置、World、WorldProxy和跨进程地图跳转组织成准备、冻结、转移、接管、提交的事务，支持客户端进入和连续跨WorldProxy移动。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 最小实现骨架

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
TransferResult Coordinator::move(PlayerId player, WorldId target) {
    Reservation r = target_world.prepare(player);
    Snapshot s = source_world.freeze(player, r.ticket);
    target_world.accept(r.ticket, s);
    source_world.commit_departure(r.ticket);
    return target_world.publish_ready(r.ticket);
}
```

同时保存阶段轨迹，不能只看最终返回值：

```text
trace_id,stage,request_id,generation,state_version,budget,decision
baseline-01,读取并校验地图配置,42,7,1,normal,accept
boundary-01,源World冻结快照,43,7,2,limit,accept
failure-01,客户端重连恢复签发,44,6,2,exceeded,reject
```

每个样本从相同夹具开始，只改变一个故障变量：

```text
for sample in [baseline, boundary, failure, recovery]:
  reset_fixture(seed = 20260716)

  assert_single_owner_and_current_generation()
  assert_bounded_queue_and_memory()

```

## 可复现实验

在准备、冻结、接管和提交四个阶段分别杀死源或目标进程，先预测玩家应落在哪一侧，再重放相同跳转票据。 保存编译版本、配置摘要、协议版本、随机种子、请求序号、首偏离节点、恢复动作和最终决策。平均吞吐只能说明趋势，不能证明关键状态没有重复或丢失。

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或代际被绕过">
  源World先删除玩家再通知目标创建，目标失败后玩家在两个世界都不存在。
  修复后用相同输入重放，并保存首偏离状态与拒绝原因。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  目标先开放输入而源端尚未冻结，两个World同时处理背包或位置更新，状态无法合并。
  必须补充边界、失败和恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件               |
| ---- | ---------------------------- | ---------------- | ---------------------- |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端摘要和状态版本一致 |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无无限队列和第二份事实 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚   |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏   |

## 小结

- **World**：在单个进程内权威拥有一组地图实体和空间规则的运行对象。
- **WorldProxy**：代表远端World并转发定位、准备和跳转消息的本地代理。
- **跳转票据**：绑定玩家、源、目标、状态版本和过期时间的一次性迁移授权。
- **冻结点**：源World停止接受新业务输入并截取一致状态的迁移阶段。
- **双写禁令**：迁移期间任何时刻都只能有一个World权威修改玩家状态的约束。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
- 公开目录条目已逐项列出，随书源码与现代补充不会冒充原书分节。
