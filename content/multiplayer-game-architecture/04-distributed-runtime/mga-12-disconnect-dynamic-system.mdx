## 直觉：先找唯一事实

区分玩家连接断开和进程间链路断开，并以有版本、有依赖、有排空屏障的方式动态新增系统。 真正的难点不是把接口调用成功，而是让每次输入只产生一份事实，旧连接、旧实体、旧进程和旧定时器不能越过代际边界。先预测：如果只保留最终成功截图，本章最可能隐藏哪一种重复执行、状态污染或资源泄漏？

## 六阶段证据链

本章的可操作链条是：分类断线来源 → 保留或回收玩家会话 → 摘除失联进程路由 → 校验新系统依赖 → 排空旧版本并切换 → 重连回滚后签发。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明没有留下第二份事实。

下面的代码是用于复现实验的独立最小骨架，不是原书源码复制；生产实现还要补齐超时、错误分类、指标和资源清理。

```cpp
bool SystemManager::activate(Module next) {
    validate_interface(next);
    ingress.pause();
    barrier.wait_until_drained();
    if (!next.start(snapshot_current_state())) return rollback();
    current.swap(next);
    ingress.resume();
    return true;
}
```

## 小结

- **玩家断线**：客户端传输连接消失但业务会话可能保留等待重连的状态。
- **进程断线**：服务实例间心跳或传输失败并触发路由摘除与恢复的状态。
- **租约**：只有持续续期才有效、超时后自动失效的资源所有权证明。
- **动态系统**：在运行期按明确接口、版本和依赖加入SystemManager的行为模块。
- **排空屏障**：切换版本前停止新输入并等待旧任务和消息完成的阶段门。
