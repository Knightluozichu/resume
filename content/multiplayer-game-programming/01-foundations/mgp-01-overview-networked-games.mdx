## 直觉：先找唯一事实

网络游戏架构不是从套接字开始，而是从共享体验、权威归属和可接受延迟的历史约束开始。 真正的难点不是让一次理想样本跑通，而是让消息身份、世界版本、状态权威和时间预算在丢包、乱序、重复与断线后仍可解释。先预测：如果只保存最终成功画面，本页最可能隐藏哪一种分歧？

## 机制拆解

### 1. 历史不是年表，而是约束来源

从同机、本地网络到互联网，带宽、延迟、参与人数与作弊面不断变化。每次架构演进都在回答同一组问题：谁拥有真相、传什么、多久传一次，以及分歧如何恢复。把产品需求写成这些约束，才能避免先选技术再解释需求。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. Tribes：消息进入游戏逻辑的边界

Starsiege: Tribes 的案例强调网络管理器、事件管理器与对象之间的职责分离。接收线程不能直接任意修改世界；消息要先经过解析、验证和排序，再形成游戏可理解的事件。这个边界使重放、拒绝畸形输入和定位首个分歧成为可能。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. Age of Empires：少传数据但提高确定性成本

确定性锁步只交换玩家命令，能把带宽从世界状态规模降到输入规模，却要求所有节点对相同输入产生完全相同结果。随机数种子、浮点差异、命令帧和迟到策略都会成为协议的一部分；任何未受控差异都会累积成世界分叉。

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```
