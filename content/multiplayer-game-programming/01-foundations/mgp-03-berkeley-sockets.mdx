## 机制拆解

### 1. API差异必须隔离

Windows 的 Winsock 初始化、错误码获取和句柄类型与类Unix平台不同。把这些差异封装在薄适配层中，上层只接触统一的创建、地址转换、发送、接收和关闭契约；否则平台条件分支会渗入协议状态机。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. UDP保留消息边界，TCP只提供字节流

一次UDP接收对应一个数据报，但数据报仍可能丢失、重复或被截断。TCP的send和recv都可能只推进部分字节，一次接收不等于一条消息。长度前缀、最大帧长和累计缓冲区必须由应用协议明确管理。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 非阻塞不是忽略错误

EWOULDBLOCK表示当前没有进展，不等于连接失败；连接重置、不可达和对端关闭则需要不同转换。事件循环应为读写就绪、超时和取消定义单一状态迁移，并保证任何路径都只关闭一次句柄。

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```
