## 直觉引入

UDP 是「无连接」的——你往一个地址发包，不需要先「建立连接」。这就像明信片：写好地址就能寄，不需要和收件人提前打招呼。但游戏需要「会话」概念——服务器需要知道「这个客户端是谁、有没有登录、当前在哪个房间」。如果直接用裸 UDP，任何知道服务器地址的人都能发数据包，服务器分不清这是不是合法玩家。所以我们需要在 UDP 之上自己实现一套「连接」机制：用握手确认双方身份，用状态机跟踪会话生命周期，用保活检测对方是否还在线，用超时清理僵尸连接。

## 连接状态机

<Term def="连接状态机是 UDP 上模拟 TCP 连接语义的机制：通过 Disconnected → Connecting → Connected → Disconnecting 状态转移，跟踪会话的完整生命周期。">连接状态机</Term>是游戏网络连接管理的核心。每个连接对象维护一个状态变量，只有特定状态下的特定操作才被允许。

```cpp
enum class ConnectionState {
    Disconnected,   // 未连接
    Connecting,     // 握手中
    Connected,      // 已连接，正常通信
    Disconnecting,  // 正在断开（发送断连包）
};

class Connection {
    ConnectionState state = ConnectionState::Disconnected;
    uint32_t clientId;      // 会话标识
    Address remoteAddr;     // 对端地址
    float timeoutAccumulator = 0.0f;
    static constexpr float TIMEOUT_SECONDS = 10.0f;

public:
    // 客户端发起连接
    void Connect(const Address& addr) {
        remoteAddr = addr;
        state = ConnectionState::Connecting;
        SendConnectRequest();
    }

    // 每帧更新：检查超时
    void Update(float dt) {
        if (state == ConnectionState::Connected) {
            timeoutAccumulator += dt;
            if (timeoutAccumulator > TIMEOUT_SECONDS) {
                state = ConnectionState::Disconnected;
                // 通知上层：连接超时断开
            }
        }
    }

    // 收到数据包时重置超时计时器
    void OnPacketReceived() {
        timeoutAccumulator = 0.0f;
    }
};
```

## 握手协议

<Term def="握手协议是连接建立时的身份验证过程：客户端发送连接请求，服务器返回挑战码，客户端回应挑战，双方确认身份后进入 Connected 状态。">握手协议</Term>防止伪造和重放攻击。简单做法是「挑战-响应」：服务器生成随机 challenge，客户端必须正确回应才能建立连接。

```cpp
// === 客户端握手流程 ===
// 1. 发送 CONNECT_REQUEST（含自己的 protocolVersion）
// 2. 收到 CONNECT_CHALLENGE（含服务器随机 challenge）
// 3. 发送 CONNECT_RESPONSE（含 challenge 回应 + clientId）
// 4. 收到 CONNECT_ACCEPT → 进入 Connected

// === 服务器握手流程 ===
// 1. 收到 CONNECT_REQUEST → 生成随机 challenge，存入 pendingConnections
// 2. 发送 CONNECT_CHALLENGE
// 3. 收到 CONNECT_RESPONSE → 验证 challenge 回应
// 4. 分配 clientId，发送 CONNECT_ACCEPT → 进入 Connected

struct ConnectRequest {
    uint32_t protocolVersion;  // 协议版本号
    uint32_t challenge;        // 客户端生成的随机数
};

struct ConnectChallenge {
    uint32_t serverChallenge;  // 服务器生成的随机数
    uint32_t clientChallenge;  // 回显客户端的随机数
};

struct ConnectResponse {
    uint32_t serverChallenge;  // 回显服务器的随机数
    uint8_t  clientSalt[16];   // 客户端盐值
};
```

## 保活与超时

UDP 没有内置的连接状态，如果客户端突然断电或拔网线，服务器不会收到任何通知。必须通过**保活**和**超时**机制来检测死连接：

```cpp
// 客户端：定期发送保活心跳（如果没有其他数据发送）
void Connection::SendKeepalive() {
    if (timeSinceLastSend > 1.0f) {  // 1 秒没发数据就发心跳
        Packet pkt(MSG_KEEPALIVE);
        Send(pkt);
    }
}

// 服务器：累计超时时间，超过阈值断开
void Connection::Update(float dt) {
    timeoutAccumulator += dt;
    if (timeoutAccumulator > TIMEOUT_SECONDS) {
        Disconnect("timeout");
    }
}
```

## 常见误区

<Callout type="trap">
**误区：连接建立后就不用管了，UDP 自然会维持。** UDP 是无连接协议，内核不维护任何连接状态。如果客户端拔网线，服务器收不到任何 FIN/RST（那是 TCP 的概念），连接会永远挂着占资源。必须自己实现超时检测：每次收到包重置计时器，超时阈值内没收到任何包就主动断开。阈值通常设 5-10 秒——太短会在网络抖动时误断，太长会让死连接占资源。同时客户端应定期发心跳包，让服务器知道你还活着。
</Callout>

<Exercises>
**问题 1**：为什么 UDP 上需要自己实现连接管理？不能直接发包吗？

<Answer>
UDP 是无连接协议，内核不维护连接状态。直接发包有两个问题：一是安全性——任何知道服务器地址的人都能发伪造数据包，服务器无法区分合法与非法客户端；二是资源管理——没有连接概念就无法跟踪会话生命周期，客户端断线后服务器无法感知，死连接会永远占资源。自己实现连接管理（握手验证身份 + 状态机跟踪生命周期 + 超时清理死连接）可以解决这些问题，在无连接的 UDP 之上建立会话语义。
</Answer>

**问题 2**：描述挑战-响应握手协议的流程，为什么不能只用一个 CONNECT 包？

<Answer>
流程：①客户端生成随机 clientChallenge，发 CONNECT_REQUEST；②服务器生成随机 serverChallenge，回显 clientChallenge，发 CONNECT_CHALLENGE；③客户端验证 clientChallenge 匹配，回显 serverChallenge，发 CONNECT_RESPONSE；④服务器验证 serverChallenge 匹配，分配 clientId，发 CONNECT_ACCEPT。不能只用一个 CONNECT 包的原因：一是防伪造——单包握手无法验证对端身份，攻击者可以伪造源地址发 CONNECT；二是防重放——单包握手可以被录包重放，挑战-响应的随机数让每次握手不可重放；三是防 IP 欺骗——攻击者伪造源 IP 发包时，收不到服务器返回的 challenge，无法完成握手。
</Answer>
</Exercises>

<GlossaryItem term="连接状态机">UDP 上模拟 TCP 连接语义的机制：Disconnected → Connecting → Connected → Disconnecting。每个状态只允许特定操作，防止非法状态下的数据交换。</GlossaryItem>
<GlossaryItem term="握手协议">连接建立时的身份验证过程。挑战-响应式：客户端发请求 → 服务器返挑战 → 客户端回应挑战 → 服务器确认。防止伪造、重放和 IP 欺骗。</GlossaryItem>
<GlossaryItem term="保活心跳">定期发送的小数据包，用于告诉对端「我还在线」。UDP 无内置连接状态，必须靠心跳 + 超时检测死连接。心跳间隔通常 1-5 秒。</GlossaryItem>
<GlossaryItem term="超时断连">累计一段时间未收到对端任何数据包，主动断开连接。阈值通常 5-10 秒，太短误断抖动连接，太长死连接占资源。</GlossaryItem>
</Glossary>
