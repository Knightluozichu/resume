## 直觉引入

大多数家庭网络都有一个路由器，它像一栋公寓的前台——外面的人只知道公寓的地址（公网 IP），不知道哪个房间对应哪个住户（内网设备）。当住户往外寄信时，前台记下「这个房间发出去的信，回信寄到公寓 xxx 号信箱」，然后用自己的地址转发。这就是 NAT。问题是：如果两个人都在各自的公寓里，想互相寄信，但彼此只知道对方的公寓地址（不知道信箱号），信就寄不到。NAT 穿透就是让两个人通过一个共同的中间人（STUN 服务器）交换各自的「公网信箱号」，然后直接互相寄信。

## NAT 的工作原理

<Term def="NAT（Network Address Translation，网络地址转换）是路由器将内网私有 IP 映射到公网 IP 的机制。它维护一张映射表：内网 IP:端口 → 公网 IP:端口，让多台内网设备共享一个公网 IP。">NAT</Term>让 IPv4 地址不够用的问题得到缓解，但也给 P2P 通信带来了障碍。

```
内网设备 192.168.1.100:5000
        ↓ 发包到 203.0.113.1:9999
NAT 路由器（公网 IP 198.51.100.1）
        ↓ 创建映射：192.168.1.100:5000 → 198.51.100.1:30000
        ↓ 用 198.51.100.1:30000 发包到 203.0.113.1:9999
目标服务器
        ↓ 收到来源 198.51.100.1:30000
        ↓ 回包到 198.51.100.1:30000
NAT 路由器
        ↓ 查映射表：30000 → 192.168.1.100:5000
        ↓ 转发给 192.168.1.100:5000
内网设备收到回包 ✓
```

## NAT 的四种类型

| 类型 | 映射规则 | 穿透难度 | 说明 |
|------|---------|---------|------|
| Full Cone | 同一内网端口 → 固定公网端口，任何外部主机可达 | 最易 | 最宽松 |
| Restricted Cone | 同一内网端口 → 固定公网端口，仅限联系过的外部 IP | 中等 | 需先打洞 |
| Port Restricted Cone | 同上，且仅限联系过的外部 IP:端口 | 较难 | 需双向打洞 |
| Symmetric | 不同目标 → 不同公网端口 | 最难 | 通常需 TURN |

<Term def="对称型 NAT（Symmetric NAT）为每个不同的目标地址分配不同的公网端口，使得通过 STUN 获得的映射地址无法被其他对端使用，是 P2P 穿透的最大障碍。">对称型 NAT</Term>是打洞的杀手——因为每个目标的映射端口不同，对端无法通过 STUN 得到的地址直接通信。

## UDP 打洞流程

```cpp
// === 打洞流程（A 和 B 都在 NAT 后面）===

// 1. A 和 B 各自向 STUN 服务器发包，获取自己的公网映射地址
Address addrA = stunServer.GetMyPublicAddress();  // 198.51.100.1:30000
Address addrB = stunServer.GetMyPublicAddress();  // 203.0.113.5:40000

// 2. A 和 B 通过 STUN 服务器交换彼此的公网地址
//    （STUN 服务器充当「介绍人」）
stunServer.Introduce(addrA, addrB);

// 3. A 向 B 的公网地址发包（在 A 的 NAT 上开洞）
SendTo(addrB, "punch");  // B 的 NAT 可能丢弃（未认识 A）

// 4. B 向 A 的公网地址发包（在 B 的 NAT 上开洞）
SendTo(addrA, "punch");  // A 的 NAT 已认识 B（第 3 步开的洞）

// 5. 双方 NAT 都有了对方的映射，P2P 通信建立
//    后续数据包直接 A ↔ B，不经过 STUN
```

## STUN 与 TURN

<Term def="STUN（Session Traversal Utilities for NAT）服务器帮助 NAT 后的客户端发现自己的公网映射地址。TURN（Traversal Using Relays around NAT）服务器在打洞失败时充当中继，转发双方数据。">STUN 与 TURN</Term>是 NAT 穿透的两件武器。STUN 是「介绍人」——帮你发现自己的公网地址并介绍给对端。TURN 是「中继站」——当打洞失败（如对称型 NAT）时，所有数据通过 TURN 服务器转发。

```
打洞成功（大部分场景）：       打洞失败（对称型 NAT）：

  A ←—P2P—→ B                   A ←—→ TURN ←—→ B
  （直连，低延迟）               （中继，延迟翻倍，TURN 服务器吃带宽）
```

## 常见误区

<Callout type="trap">
**误区：有了 STUN 就能穿透所有 NAT。** STUN 只能帮你发现自己的公网映射地址，能不能打洞取决于双方 NAT 类型。如果一方是对称型 NAT（每个目标分配不同端口），对端从 STUN 拿到的地址根本对不上——对端发包到那个端口，NAT 会当成陌生来源丢弃。实际部署中大约 80-85% 的 NAT 可以打洞成功，剩下 15-20% 需要回退到 TURN 中继。这就是为什么生产环境的 NAT 穿透方案总是 STUN + TURN 组合——STUN 优先直连，TURN 兜底中继。
</Callout>

<Exercises>
**问题 1**：解释 NAT 的四种类型，哪种最难穿透？为什么？

<Answer>
四种类型：①Full Cone——同一内网端口映射到固定公网端口，任何外部主机都可达，最易穿透；②Restricted Cone——固定公网端口，但仅限联系过的外部 IP 可达，需先打洞；③Port Restricted Cone——同上且限制到 IP:端口，需双向打洞；④Symmetric NAT——为每个不同目标分配不同公网端口。Symmetric 最难穿透，因为通过 STUN 获取的映射地址只在到 STUN 的方向上有效，其他对端发到该端口的数据会被 NAT 当作陌生来源丢弃，打洞几乎不可能成功，通常需要 TURN 中继。
</Answer>

**问题 2**：描述完整的 UDP 打洞流程，为什么需要 STUN 服务器？

<Answer>
流程：①A 和 B 各自向 STUN 服务器发包，STUN 观察到它们的公网映射地址（IP:端口）并返回；②A 和 B 通过 STUN 服务器交换彼此的公网地址；③A 向 B 的公网地址发包，在 A 的 NAT 上为 B 开洞（B 的 NAT 可能丢弃此包）；④B 向 A 的公网地址发包，在 B 的 NAT 上为 A 开洞（此时 A 的 NAT 已认识 B，包能通过）；⑤双方 NAT 都有了对方映射，P2P 通道建立。需要 STUN 因为：NAT 后的设备不知道自己的公网地址（NAT 做的映射对内网设备透明），必须通过一个公网第三方（STUN）来观察和告知。STUN 同时充当「介绍人」帮双方交换地址。
</Answer>

<Glossary>
<GlossaryItem term="NAT">网络地址转换，路由器将内网私有 IP 映射到公网 IP 的机制。维护映射表让多台内网设备共享一个公网 IP，缓解 IPv4 地址不足，但给 P2P 通信带来障碍。</GlossaryItem>
<GlossaryItem term="UDP 打洞">NAT 穿透技术：两个 NAT 后的对端通过 STUN 服务器交换公网地址，然后互相发包在各自 NAT 上「打洞」，建立 P2P 直连。前提是至少一方不是对称型 NAT。</GlossaryItem>
<GlossaryItem term="STUN 服务器">帮助 NAT 后的客户端发现公网映射地址的公网服务器。充当「介绍人」帮对端交换地址。打洞成功后不再参与数据转发。</GlossaryItem>
<GlossaryItem term="TURN 服务器">打洞失败时的中继兜底方案。所有数据通过 TURN 服务器转发，延迟翻倍且消耗服务器带宽，但保证连通性。生产环境通常 STUN 优先 + TURN 兜底。</GlossaryItem>
</Glossary>
