## 机制拆解

### 1. 从逻辑字段出发，而非复制结构体

结构体包含填充、平台字节序、指针和编译器布局，不能成为线上格式。应逐字段定义类型、范围、是否可缺省和最大长度，并让读取器在消费前验证剩余字节，避免畸形长度触发越界或内存放大。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 引用需要网络身份

本地指针只在一个地址空间有效。对象图跨网络时，要先为可复制对象分配稳定网络ID，再决定引用目标尚未出现、已销毁或重复到达时的处理。解析顺序必须允许延迟绑定，而不能制造悬空对象。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 压缩与可维护性共同签发

位打包、范围量化和上下文编码能省带宽，却会增加版本耦合。每项压缩都应记录误差预算和回退格式；读取旧版本、跳过未知字段、拒绝不支持的必需字段都要由测试覆盖。

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```
