## 直觉：先找唯一事实

客户端—服务器与点对点的差异，本质是权威、信任、可用性和带宽责任如何分配。 真正的难点不是让一次理想样本跑通，而是让消息身份、世界版本、状态权威和时间预算在丢包、乱序、重复与断线后仍可解释。先预测：如果只保存最终成功画面，本页最可能隐藏哪一种分歧？

## 机制拆解

### 1. 拓扑选择要写成责任表

客户端—服务器便于集中裁决和隐藏对手信息，但增加托管成本和服务器往返；点对点降低中心带宽，却扩大作弊面、NAT问题与最慢节点影响。把状态所有者、验证者、失败接管者逐项列出，比一张连接图更能揭示代价。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 客户端—服务器样例验证权威输入

客户端只发送意图和序号，服务器验证速度、冷却和权限后推进世界，再回传带版本的状态。客户端预测只能改善显示，不能成为事实来源；出现差异时必须以服务器基线重放尚未确认输入。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 点对点样例验证一致性与退出

锁步点对点要求每个节点收齐命令或按明确超时策略推进。节点退出时，剩余节点必须就新成员集合、命令帧和随机种子达成同一视图；主机迁移不能只更换地址，还要转移权威状态和防重放信息。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

## 六阶段证据链

可操作链条是：量化玩法约束 → 选择权威位置 → 实现客户端—服务器 → 实现点对点 → 注入主机离开 → 比较证据签发。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明状态与资源重新收敛。

<Stepper>
  <Step title="1. 量化玩法约束与选择权威位置">
    固定协议版本、网络种子、输入序号与状态所有者，运行正常和边界样本。
    </Step>
  <Step title="2. 实现客户端—服务器与实现点对点">
    注入延迟、抖动、丢包、重复或责任节点中断，要求在首偏离点停止。
    </Step>
  <Step title="3. 注入主机离开与比较证据签发">
    清除故障后重放相同输入，核对世界摘要、对象数量、消息债务与资源租约。
    </Step>
</Stepper>

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：只比较连接数量，不比较权威、作弊、NAT、托管成本和故障接管。** 必须保存消息序号、世界版本和首次拒绝原因，而不是只看最终画面。
</Callout>

<Callout type="trap">
  **误区二：主机迁移只切换新地址，没有同步最后确认帧、会话密钥与对象所有权。** 必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 网络与输入变化 | 预期状态 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 合法版本、顺序、身份与容量 | 六阶段完成 | 权威摘要与对象身份一致 |
| 边界 | 临界延迟、抖动、回绕或满载 | 达到预算不越界 | 队列有界且无永久饥饿 |
| 失败 | 丢包、重复、畸形、断线或节点失效 | 首偏离点停止 | 明确拒绝、回滚或接管 |
| 恢复 | 清除故障后重放同一输入 | 收敛到正常轨迹 | 无双权威、幽灵对象和资源泄漏 |

本页签发不变量是：**拓扑中的每份状态有唯一裁决责任；客户端意图经过验证；节点离开后所有参与者收敛到同一成员与世界版本。** 单次演示、平均延迟或最终截图不能替代序号、版本、首偏离点和恢复证据。

## 小结

- **客户端—服务器**：客户端提交输入，由服务器维护或裁决权威世界状态的拓扑。
- **点对点**：参与节点彼此直接交换输入或状态、共同承担模拟责任的拓扑。
- **权威服务器**：对合法输入和最终状态拥有裁决权、客户端不能覆盖其结果的节点。
- **主机迁移**：当前主机离开后选择新主机并转移足够状态以继续会话的过程。
- **信任边界**：输入跨越后必须验证身份、权限、范围和时序，不能直接接受对方事实的边界。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
