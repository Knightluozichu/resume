## 直觉：先找唯一事实

插值、客户端预测、服务器校正和回滚分别解决不同观察者的时间问题，组合时必须保留权威历史和输入序号。 真正的难点不是让一次理想样本跑通，而是让消息身份、世界版本、状态权威和时间预算在丢包、乱序、重复与断线后仍可解释。先预测：如果只保存最终成功画面，本页最可能隐藏哪一种分歧？

## 机制拆解

### 1. 先用哑终端建立延迟基线

等待服务器后再显示本地动作最简单且权威清晰，但输入响应至少承担一个往返时间。这个版本是重要对照组：预测方案必须证明手感改善，同时没有改变服务器裁决和最终状态。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 自身预测与远端插值解决不同问题

本地玩家需要立即响应，所以预测自己的运动；远端对象没有本地输入，通常在稍晚的渲染时间上插值两个已知快照。把两者混用会造成外推爆炸，或让本地输入额外增加插值延迟。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 校正和回滚都依赖有界历史

客户端以服务器确认的输入序号为基线，丢弃已确认输入并重放剩余输入。服务器为命中判定保留带时间戳的历史变换，但回滚窗口必须有上限，并验证客户端时间，防止高延迟或伪造时间获得无限优势。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

## 六阶段证据链

可操作链条是：保存输入序号 → 本地预测自身 → 缓存远端快照 → 插值显示远端 → 权威基线校正 → 历史回滚裁决。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明状态与资源重新收敛。

<Stepper>
  <Step title="1. 保存输入序号与本地预测自身">
    固定协议版本、网络种子、输入序号与状态所有者，运行正常和边界样本。
    </Step>
  <Step title="2. 缓存远端快照与插值显示远端">
    注入延迟、抖动、丢包、重复或责任节点中断，要求在首偏离点停止。
    </Step>
  <Step title="3. 权威基线校正与历史回滚裁决">
    清除故障后重放相同输入，核对世界摘要、对象数量、消息债务与资源租约。
    </Step>
</Stepper>

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：对本地和远端对象统一使用插值缓冲，让自己的操作也平白增加延迟。** 必须保存消息序号、世界版本和首次拒绝原因，而不是只看最终画面。
</Callout>

<Callout type="trap">
  **误区二：服务器无限信任客户端时间并无限回滚，使高延迟或伪造时间戳获得不公平命中。** 必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 网络与输入变化 | 预期状态 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 合法版本、顺序、身份与容量 | 六阶段完成 | 权威摘要与对象身份一致 |
| 边界 | 临界延迟、抖动、回绕或满载 | 达到预算不越界 | 队列有界且无永久饥饿 |
| 失败 | 丢包、重复、畸形、断线或节点失效 | 首偏离点停止 | 明确拒绝、回滚或接管 |
| 恢复 | 清除故障后重放同一输入 | 收敛到正常轨迹 | 无双权威、幽灵对象和资源泄漏 |

本页签发不变量是：**服务器始终裁决事实；输入序号使校正可重放；插值与回滚历史有明确时间窗口和内存上限。** 单次演示、平均延迟或最终截图不能替代序号、版本、首偏离点和恢复证据。

## 小结

- **哑终端客户端**：只显示服务器状态并等待权威结果、不在本地推演输入的客户端模型。
- **客户端插值**：在有意延迟的渲染时间上，用相邻权威快照平滑远端对象。
- **客户端预测**：本地立即应用自己的输入以隐藏到服务器往返延迟的技术。
- **服务器校正**：收到权威状态后回到确认基线并重放未确认本地输入的过程。
- **服务器回滚**：按事件发生时刻查询或重建历史状态，以裁决延迟到达动作的技术。
