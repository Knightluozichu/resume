## 直觉：先找唯一事实

伸缩首先靠减少每个玩家必须看到和必须更新的工作，再考虑分区与实例扩展机器数量。 真正的难点不是让一次理想样本跑通，而是让消息身份、世界版本、状态权威和时间预算在丢包、乱序、重复与断线后仍可解释。先预测：如果只保存最终成功画面，本页最可能隐藏哪一种分歧？

## 机制拆解

### 1. 先改变复杂度，再加机器

若每个玩家都接收所有对象，带宽和序列化成本会随玩家与对象乘积增长。空间网格、视野、队伍和交互规则可先缩小相关集合；只有记录漏发与多发，才能证明裁剪没有破坏玩法。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 优先级与频率共享同一预算

近处敌人、当前目标和高速对象应更频繁，远处静态对象可以降频。调度器要综合重要性、最后发送时间和预计字节数，避免低优先级对象永久饥饿，并在超预算时给出可解释的丢弃顺序。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 分区和实例都引入边界协议

空间分区需要跨区可见、对象移交和双写防护；实例化需要房间分配、容量与销毁生命周期。迁移必须以版本化所有权令牌完成，防止两个服务器同时模拟同一对象或都认为对方负责。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

## 六阶段证据链

可操作链条是：测量每连接成本 → 裁剪对象作用域 → 计算动态相关性 → 分配优先级频率 → 划分世界或实例 → 压测迁移签发。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明状态与资源重新收敛。

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：在全量广播模型上直接增加服务器，保留了玩家数乘对象数的根本成本。** 必须保存消息序号、世界版本和首次拒绝原因，而不是只看最终画面。
</Callout>

<Callout type="trap">
  **误区二：跨分区迁移没有所有权令牌，短暂双写或无人负责造成状态复制与丢失。** 必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 网络与输入变化 | 预期状态 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 合法版本、顺序、身份与容量 | 六阶段完成 | 权威摘要与对象身份一致 |
| 边界 | 临界延迟、抖动、回绕或满载 | 达到预算不越界 | 队列有界且无永久饥饿 |
| 失败 | 丢包、重复、畸形、断线或节点失效 | 首偏离点停止 | 明确拒绝、回滚或接管 |
| 恢复 | 清除故障后重放同一输入 | 收敛到正常轨迹 | 无双权威、幽灵对象和资源泄漏 |

## 小结

- **对象作用域**：某个连接当前有资格接收和维护的一组网络对象。
- **相关性**：根据距离、可见性、队伍或玩法规则判断对象对某连接是否重要。
- **服务器分区**：把世界或模拟责任划分给多个服务器进程并定义跨区转移。
- **实例化**：为一组玩家创建隔离的世界副本以限制共享状态规模。
- **更新优先级**：在带宽与CPU预算内按重要性、陈旧度和变化程度安排复制。
