## 直觉：先找唯一事实

客户端和网络都处于不可信边界；安全依赖最小信息暴露、严格输入验证、服务端裁决和纵深防护。 真正的难点不是让一次理想样本跑通，而是让消息身份、世界版本、状态权威和时间预算在丢包、乱序、重复与断线后仍可解释。先预测：如果只保存最终成功画面，本页最可能隐藏哪一种分歧？

## 机制拆解

### 1. 加密不能隐藏所有信息

传输加密能保护内容，但流量大小、频率和端点仍可能暴露行为模式。更重要的是，已被控制的客户端拥有会话明文。服务器应只发送玩家有权知道的状态，而不是把全部世界加密后交给客户端保密。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 验证是状态相关的

长度与数值范围只是第一层；移动速度要结合上一权威位置和时间，技能要检查冷却、资源和目标可见性，消息还要检查会话、序号与重放窗口。任何失败都应在修改世界前被拒绝并留下限量证据。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 检测与加固形成闭环

客户端反篡改只能提供信号，不能替代服务器裁决。服务端以行为不变量、速率和关联事件生成风险证据；主机再通过最小权限、补丁、网络分段、密钥轮换和容量限制降低被攻破后的影响。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

## 六阶段证据链

可操作链条是：枚举可见资产 → 最小化封包信息 → 验证每个输入 → 权威计算结果 → 关联作弊证据 → 加固监控与响应。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明状态与资源重新收敛。

<Stepper>
  <Step title="1. 枚举可见资产与最小化封包信息">
    固定协议版本、网络种子、输入序号与状态所有者，运行正常和边界样本。
    </Step>
  <Step title="2. 验证每个输入与权威计算结果">
    注入延迟、抖动、丢包、重复或责任节点中断，要求在首偏离点停止。
    </Step>
  <Step title="3. 关联作弊证据与加固监控与响应">
    清除故障后重放相同输入，核对世界摘要、对象数量、消息债务与资源租约。
    </Step>
</Stepper>

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：认为协议未公开或流量已加密就能信任客户端提交的位置、伤害和时间。** 必须保存消息序号、世界版本和首次拒绝原因，而不是只看最终画面。
</Callout>

<Callout type="trap">
  **误区二：检测到异常后只封禁，不保存可解释证据、误报回滚和攻击面修复记录。** 必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 网络与输入变化 | 预期状态 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 合法版本、顺序、身份与容量 | 六阶段完成 | 权威摘要与对象身份一致 |
| 边界 | 临界延迟、抖动、回绕或满载 | 达到预算不越界 | 队列有界且无永久饥饿 |
| 失败 | 丢包、重复、畸形、断线或节点失效 | 首偏离点停止 | 明确拒绝、回滚或接管 |
| 恢复 | 清除故障后重放同一输入 | 收敛到正常轨迹 | 无双权威、幽灵对象和资源泄漏 |

本页签发不变量是：**不可信输入在改变状态前被验证；关键结果由服务端计算；检测证据可解释、限量并能驱动处置。** 单次演示、平均延迟或最终截图不能替代序号、版本、首偏离点和恢复证据。

## 小结

- **封包嗅探**：观察网络流量的内容、时序和元数据以推断协议或敏感状态。
- **输入验证**：在信任边界检查消息身份、长度、范围、权限、时序和状态前置条件。
- **作弊检测**：以客户端信号与服务器行为证据识别不可能或高度异常操作的机制。
- **服务端裁决**：关键游戏结果只由服务器根据合法意图和权威状态计算。
- **纵深防护**：在协议、进程、主机、网络和运营层布置相互独立的限制与检测。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
- 官方目录逐项追踪，现代补充不会冒充原书正式分节。
