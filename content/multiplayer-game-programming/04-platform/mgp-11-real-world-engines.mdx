## 直觉：先找唯一事实

## 机制拆解

### 1. Unreal：角色与所有权决定调用合法性

Actor复制、属性通知和RPC建立在服务器权威及连接所有权之上。标记为复制不等于任何客户端都能修改；要区分服务器、拥有者客户端和模拟代理，并验证创建、休眠、相关性变化与销毁的顺序。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. Unity：具体API会变，网络语义不应漂移

不同Unity网络方案的组件名称和生命周期会演进，但服务器权威、网络身份、生成与销毁、命令方向和快照平滑仍是稳定问题。把这些语义写入适配层测试，避免教程版本与项目包版本不一致时悄然改变行为。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 样例必须验证失败路径

编辑器内双窗口成功只能证明理想路径。应在独立进程和受控网络中测试迟到加入、所有者离开、对象超出相关范围、重复RPC和版本不匹配，并比较两种引擎是否保持相同产品不变量。

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```
