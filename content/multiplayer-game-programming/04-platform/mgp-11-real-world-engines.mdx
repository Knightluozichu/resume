## 直觉：先找唯一事实

引擎网络API封装了复制与RPC，但不会替开发者决定权威、所有权、相关性和失败语义。 真正的难点不是让一次理想样本跑通，而是让消息身份、世界版本、状态权威和时间预算在丢包、乱序、重复与断线后仍可解释。先预测：如果只保存最终成功画面，本页最可能隐藏哪一种分歧？

## 机制拆解

### 1. Unreal：角色与所有权决定调用合法性

Actor复制、属性通知和RPC建立在服务器权威及连接所有权之上。标记为复制不等于任何客户端都能修改；要区分服务器、拥有者客户端和模拟代理，并验证创建、休眠、相关性变化与销毁的顺序。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. Unity：具体API会变，网络语义不应漂移

不同Unity网络方案的组件名称和生命周期会演进，但服务器权威、网络身份、生成与销毁、命令方向和快照平滑仍是稳定问题。把这些语义写入适配层测试，避免教程版本与项目包版本不一致时悄然改变行为。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 样例必须验证失败路径

编辑器内双窗口成功只能证明理想路径。应在独立进程和受控网络中测试迟到加入、所有者离开、对象超出相关范围、重复RPC和版本不匹配，并比较两种引擎是否保持相同产品不变量。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：把属性勾选为复制后就假设权威、所有权和迟到加入都自动正确。** 必须保存消息序号、世界版本和首次拒绝原因，而不是只看最终画面。
</Callout>

<Callout type="trap">
  **误区二：只在编辑器单机多窗口测试，漏掉独立进程、网络故障和引擎版本差异。** 必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 网络与输入变化 | 预期状态 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 合法版本、顺序、身份与容量 | 六阶段完成 | 权威摘要与对象身份一致 |
| 边界 | 临界延迟、抖动、回绕或满载 | 达到预算不越界 | 队列有界且无永久饥饿 |
| 失败 | 丢包、重复、畸形、断线或节点失效 | 首偏离点停止 | 明确拒绝、回滚或接管 |
| 恢复 | 清除故障后重放同一输入 | 收敛到正常轨迹 | 无双权威、幽灵对象和资源泄漏 |

## 小结

- **引擎复制**：由游戏引擎跟踪对象或属性变化并通过内置网络层传播的机制。
- **网络角色**：描述对象在本地是权威、自治代理还是模拟代理的职责标记。
- **引擎RPC**：由引擎生成和路由、但仍受调用方向与所有权约束的远程命令。
- **相关性钩子**：允许游戏按连接决定对象是否复制及以何种频率复制的扩展点。
- **语义适配层**：把产品级网络不变量映射到不同引擎API并保持行为一致的边界。
- 六阶段机制链已经映射到正常、边界、失败和恢复证据。
