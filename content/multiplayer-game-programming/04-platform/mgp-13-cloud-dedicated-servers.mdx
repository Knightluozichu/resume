## 机制拆解

### 1. 托管决策要比较完整成本

自托管提供控制但承担容量、补丁和全球网络运维；云托管提高弹性却引入启动时间、配额和持续成本。决策应以地区峰值并发、每进程容量、目标等待时间和故障预算量化，而不是只比较单台机器价格。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 两级管理器分离主机与进程生命周期

虚拟机管理器维护计算节点池，进程管理器在健康节点上维护可分配比赛进程。进程崩溃不必立刻销毁虚拟机，节点失联则必须使其所有进程退出可分配集合；两个层级通过租约而不是永久记录声明所有权。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 伸缩闭环必须处理慢启动和排空

容量信号经冷却和预测产生扩缩请求，新镜像启动、下载和健康检查都需要提前量。缩容先排空，确认无会话和未上传结果后再终止；重试创建也要用操作ID去重，防止控制面超时制造额外实例。

struct NetworkEvidence {

  return next.objectId == current.objectId &&
