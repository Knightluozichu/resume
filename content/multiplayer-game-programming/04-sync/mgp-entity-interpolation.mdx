## 直觉引入

你在玩射击游戏，看远处的敌人跑动。服务器每 30ms 发一次敌人的位置，但网络有抖动——有时 20ms 到，有时 60ms 到。如果你收到位置就直接把敌人移过去，敌人就会像瞬移一样跳来跳去，根本瞄不准。解决办法是「故意延迟」：不立刻用最新位置，而是把收到的位置存起来，总是渲染「100ms 前」的位置。这样你有足够的历史快照可以在两个位置之间平滑插值，敌人看起来就在匀速滑行。代价是远程敌人比实际位置滞后 100ms，但比跳变好多了——瞄提前量是玩家的基本功。

## 快照缓冲

<Term def="快照缓冲（Snapshot Buffer）是客户端缓存最近收到的远程实体状态快照的环形队列。插值器从缓冲区中取两个相邻快照，按时间戳在它们之间线性插值，保证渲染平滑。">快照缓冲</Term>是实体插值的基础。没有缓冲区，收到快照就渲染会导致跳变；有缓冲区，就能在历史快照间平滑过渡。

```cpp
struct Snapshot {
    float timestamp;        // 服务器时间戳
    std::vector<EntityState> entities;  // 所有实体状态
};

class SnapshotBuffer {
    std::deque<Snapshot> buffer;
    static constexpr size_t MAX_SIZE = 64;

public:
    void Add(const Snapshot& snap) {
        buffer.push_back(snap);
        // 保持时间有序且不超过最大大小
        while (buffer.size() > MAX_SIZE) {
            buffer.pop_front();
        }
    }

    // 取两个相邻快照用于插值
    bool GetSnapshotsForInterpolation(float renderTime,
                                      Snapshot& s1, Snapshot& s2,
                                      float& alpha) {
        // 找到 renderTime 落在哪两个快照之间
        for (size_t i = 0; i < buffer.size() - 1; i++) {
            if (buffer[i].timestamp <= renderTime
                && buffer[i+1].timestamp >= renderTime) {
                s1 = buffer[i];
                s2 = buffer[i+1];
                float range = s2.timestamp - s1.timestamp;
                alpha = range > 0 ? (renderTime - s1.timestamp) / range : 0;
                return true;
            }
        }
        return false;  // 没有合适的快照对
    }
};
```

## 插值延迟

<Term def="插值延迟（Interpolation Delay）是客户端故意将渲染时间设为落后于最新快照一个固定时间（如 100ms），确保始终有两个快照可用于平滑插值。代价是远程实体显示滞后。">插值延迟</Term>是平滑渲染的关键。渲染时间 = 当前时间 - 插值延迟。

```cpp
class EntityInterpolator {
    SnapshotBuffer buffer;
    static constexpr float INTERP_DELAY = 0.1f;  // 100ms 插值延迟

public:
    void OnSnapshot(const Snapshot& snap) {
        buffer.Add(snap);
    }

    void Render(float currentTime) {
        // 渲染时间 = 当前时间 - 插值延迟
        float renderTime = currentTime - INTERP_DELAY;

        Snapshot s1, s2;
        float alpha;
        if (buffer.GetSnapshotsForInterpolation(renderTime, s1, s2, alpha)) {
            // 在 s1 和 s2 之间线性插值
            for (auto& entity : renderEntities) {
                auto* e1 = FindInSnapshot(s1, entity.id);
                auto* e2 = FindInSnapshot(s2, entity.id);
                if (e1 && e2) {
                    entity.position = lerp(e1->position, e2->position, alpha);
                    entity.rotation = slerp(e1->rotation, e2->rotation, alpha);
                }
            }
        }
    }
};
```

```
时间线：
  快照到达: ----[S1]------[S2]------[S3]------[S4]----
  渲染位置:                   ↑ 渲染点（在 S2-S3 之间插值）
                              |←延迟→|
                              100ms 后退

  即使 S3 延迟到达，S2 仍可用来插值，不会跳变
```

## 外推的陷阱

<Term def="外推（Extrapolation）是在没有新快照时，根据最后已知速度预测未来位置。与插值不同，外推是猜测，可能出错（如实体转弯或停止）。">外推</Term>是缓冲区中没有足够快照时的应急方案，但要小心使用：

```cpp
// 插值：在两个已知快照之间，安全
pos = lerp(s1.pos, s2.pos, alpha);  // 一定在 s1 和 s2 之间

// 外推：在最后快照之后，猜测
if (noNewSnapshot) {
    pos = lastSnapshot.pos + lastSnapshot.vel * timeSinceLast;
    // 危险：如果实体转弯了，这个位置是错的
    // 如果太久没新快照，应该冻结或标记为不可信
}
```

## 常见误区

<Callout type="trap">
**误区：插值延迟设得越小越好，这样远程实体越接近真实位置。** 插值延迟设太小会导致缓冲区经常没有两个快照可用——网络抖动时快照到达间隔不均匀，如果延迟 < 最大抖动，就会出现「没有快照可插值」的情况，不得不外推或冻结，反而更卡。典型值是 100ms（约 3 帧 @ 30Hz），这能吸收大部分网络抖动。竞技游戏可以降到 50-70ms 但需要更稳定的网络。插值延迟本质是「用延迟换平滑」——没有延迟会跳变，延迟太大感觉迟钝。100ms 是经验上的最佳平衡点。
</Callout>

<Exercises>
**问题 1**：为什么不直接用最新收到的快照渲染远程实体？快照缓冲解决了什么问题？

<Answer>
直接用最新快照渲染有两个问题：一是跳变——快照每 30ms 到一个，直接把实体移到新位置，实体就每 30ms 瞬移一次，看起来在跳；二是网络抖动——快照到达间隔不均匀（有时 20ms 有时 60ms），直接渲染会让实体忽快忽慢。快照缓冲解决这两个问题：缓存历史快照，在两个相邻快照之间按时间戳线性插值，让实体在两个已知位置之间匀速滑动。渲染时间设为当前时间 - 插值延迟（如 100ms），确保始终有两个快照可插值，吸收网络抖动。代价是远程实体显示滞后 100ms。
</Answer>

**问题 2**：插值和外在推有什么区别？什么时候该用哪个？

<Answer>
插值（Interpolation）：在两个已知快照之间计算中间位置。安全——结果一定在两个已知点之间，不会出错。需要两个快照，所以有插值延迟（渲染时间落后于最新快照）。正常状态下总是用插值。外推（Extrapolation）：在最后已知快照之后，根据速度预测未来位置。无需等待新快照，零延迟。但它是猜测——如果实体转弯、加速或停止，预测位置就是错的，会导致实体「飞出去再弹回来」。只在缓冲区没有足够快照时短暂使用，且超过一定时间（如 200ms）应冻结实体并标记为不可信。原则：优先插值，外推只是应急，不可长期依赖。
</Answer>
</Exercises>

<GlossaryItem term="快照缓冲">客户端缓存的远程实体状态快照队列。插值器从中取两个相邻快照进行插值。典型大小 32-64 个快照，约 1-2 秒历史数据。</GlossaryItem>
<GlossaryItem term="插值延迟">客户端故意将渲染时间设为落后于最新快照的固定时间（如 100ms）。确保始终有两个快照可插值，吸收网络抖动。代价是远程实体显示滞后。</GlossaryItem>
<GlossaryItem term="插值">在两个已知快照之间按时间戳线性（或球面）插值。安全——结果在已知点之间。正常状态下的标准做法。</GlossaryItem>
<GlossaryItem term="外推">根据最后已知速度预测未来位置。零延迟但可能出错（转弯/停止时预测错误）。仅作应急，不可长期依赖。</GlossaryItem>
