## 机制拆解

### 1. 从输入到权威世界

客户端用序号发送意图，套接字层只负责字节交付；服务器在信任边界验证会话、范围和时序，再让权威模拟推进。网络ID把对象生命周期连接到序列化字段、状态更新和RPC。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 2. 从受损网络到可玩画面

延迟、抖动和丢包通过可重放仿真注入。自身用预测改善响应，远端对象用插值平滑，服务器确认触发校正，命中判定在有界权威历史上回滚；这些技术不能改变最终裁决。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

### 3. 从单局到生产平台

相关性、优先级、分区和实例控制每连接成本，安全验证阻止客户端成为事实来源。引擎适配、玩家服务和云端托管共同维持身份、版本、幂等结果和服务器生命周期闭环。

先预测：若省略这一层，哪一个序号、所有权或时间预算会最先失真？

## 六阶段证据链

可操作链条是：采样并编号输入 → 序列化发送意图 → 服务器验证推进 → 复制相关状态 → 客户端预测校正 → 结果入库并回收会话。正常样本证明能力，边界样本证明预算，失败样本证明拒绝，恢复样本证明状态与资源重新收敛。

## 最小实现骨架

以下代码是独立复现实验骨架，不复制原书代码。序号比较必须处理回绕，生产实现还需补齐平台错误、认证、容量与资源清理。

```cpp
struct NetworkEvidence {
  std::uint32_t sequence;
  std::uint32_t worldVersion;
  std::uint64_t objectId;
  double sentAtMs;
  double appliedAtMs;
};

bool accepts(const NetworkEvidence& next, const NetworkEvidence& current) {
  return next.objectId == current.objectId &&
         next.worldVersion >= current.worldVersion;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：逐章知识都能复述，却无法画出一次输入跨越各层的版本、所有权和时间线。** 必须保存消息序号、世界版本和首次拒绝原因，而不是只看最终画面。
</Callout>

<Callout type="trap">
  **误区二：只做正常局演示，没有迟到、重复、丢包、作弊、扩缩和排空后的恢复证据。** 必须加入边界、失败与恢复样本，证明错误没有跨入下一阶段。
</Callout>

## 验收矩阵

| 样本 | 网络与输入变化 | 预期状态 | 通过条件 |

| 正常 | 合法版本、顺序、身份与容量 | 六阶段完成 | 权威摘要与对象身份一致 |
| 边界 | 临界延迟、抖动、回绕或满载 | 达到预算不越界 | 队列有界且无永久饥饿 |
| 失败 | 丢包、重复、畸形、断线或节点失效 | 首偏离点停止 | 明确拒绝、回滚或接管 |
| 恢复 | 清除故障后重放同一输入 | 收敛到正常轨迹 | 无双权威、幽灵对象和资源泄漏 |
