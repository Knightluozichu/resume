## 两条核心主线

### 主线一：SQL语言能力

```
// 从写对到写快的递进路径
// SQL基础（DDL/DML/DQL）
//   └── INSERT/UPDATE/DELETE/SELECT
//   └── WHERE/GROUP BY/HAVING/ORDER BY
// 高级查询
//   └── JOIN（INNER/LEFT/RIGHT/FULL）
//   └── 子查询（标量/行/列/表 · IN/EXISTS）
//   └── 窗口函数（RANK/DENSE_RANK/ROW_NUMBER）
// 索引与优化
//   └── B+Tree索引原理
//   └── EXPLAIN执行计划分析
//   └── 最左前缀/覆盖索引/索引下推
//
// 核心：写对SQL → 理解执行顺序 → 建对索引 → 看懂执行计划
```

### 主线二：数据可靠与运维

```
// 从数据正确到系统可用的递进路径
// 事务与锁
//   └── ACID四大特性
//   └── 隔离级别（RC/RR/Serializable）
//   └── MVCC多版本并发控制
//   └── 锁体系（行锁/间隙锁/Next-Key）
// 安全与备份
//   └── 权限管理（GRANT/REVOKE）
//   └── SQL注入防护
//   └── 备份恢复（mysqldump/xtrabackup/PITR）
//   └── 三大日志（redo/undo/binlog）
// 数据库管理
//   └── 主从复制（异步/半同步/MGR）
//   └── 高可用（MHA/InnoDB Cluster）
//   └── 监控（Buffer Pool/慢查询/连接数）
//
// 核心：数据一致性 → 数据安全 → 系统可用
```

<Callout type="info" title="核心认知">
全书两条主线在"索引+执行计划"与"事务+备份恢复"交汇——索引影响事务的锁范围和执行效率，备份恢复依赖事务日志（redo/undo/binlog）。理解这些交汇点，才能从"会用MySQL"升级到"精通MySQL"。
</Callout>

**问题 1**：全书分为哪几个篇章？各自的核心内容和递进逻辑是什么？

<Answer>
全书分三个篇章：基础篇——MySQL入门基础（安装配置/数据类型/建库建表）、SQL基础（DDL/DML/DQL）、数据库设计（三大范式/ER建模）；进阶篇——高级查询（JOIN/子查询/窗口函数）、索引与优化（B+Tree/EXPLAIN/执行计划）、事务与锁（ACID/MVCC/隔离级别）；高级篇——安全与备份（权限/审计/备份恢复）、数据库管理（主从复制/高可用/监控）、全书复习。递进逻辑：从会用SQL到会设计库，再到会优化和运维。两条主线交汇：SQL语言能力（基础SQL→高级查询→索引优化）和数据可靠运维（事务→安全→管理），在"索引+执行计划"和"事务+备份恢复"处交汇。
</Answer>

**问题 2**：贯穿全书的两条核心主线是什么？它们在哪些章节交汇？

<Answer>
主线一SQL语言能力：SQL基础（DDL/DML/DQL）→ 高级查询（JOIN/子查询/窗口函数）→ 索引与优化（EXPLAIN/执行计划），解决"如何写对且写得快"。主线二数据可靠与运维：事务ACID → 索引优化 → 安全备份 → 数据库管理，解决"如何保证数据安全与系统可用"。两条主线在"索引+执行计划"（性能优化章）与"事务+备份恢复"（安全与运维章）交汇——索引影响事务的锁范围和执行效率，备份恢复依赖事务日志（redo/undo/binlog）。
</Answer>

**问题 3**：为什么学习MySQL要遵循"先用→会设计→会优化→会运维"的顺序？

<Answer>
顺序依据：先用——建立SQL手感，理解数据如何存取；会设计——用范式和ER建模确保数据结构合理，减少后期返工；会优化——在正确设计基础上提升性能；会运维——保障上线后的安全与可用。跳过设计的风险：①表结构不合理导致后期优化事倍功半，索引再好也救不了烂设计；②缺乏范式约束会产生大量数据冗余，占用空间且引发一致性问题；③反范式应是在满足范式前提下的有意为之。设计决定了优化的天花板。
</Answer>

**问题 4**：InnoDB为什么是MySQL的默认存储引擎？它相比MyISAM有哪些核心优势？

<Answer>
InnoDB从MySQL 5.5起成为默认引擎，核心优势：①支持事务（ACID），MyISAM不支持；②行级锁，MyISAM只有表锁，高并发写入InnoDB性能远优；③支持外键约束；④MVCC多版本并发控制，读不阻塞写；⑤崩溃恢复能力强（redo log）；⑥聚簇索引组织数据，主键查询高效。MyISAM仅适合以读为主、无事务需求的场景，现代MySQL应统一用InnoDB。
</Answer>
