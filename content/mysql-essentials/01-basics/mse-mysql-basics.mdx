## MySQL架构与存储引擎

<MseMysqlBasicsDiagram />

MySQL采用客户端/服务器架构。客户端（mysql CLI、Workbench、JDBC等）发送SQL语句，MySQL Server经过连接管理层（认证/线程管理）→ SQL层（解析器→优化器→执行器）→ 存储引擎接口，最终由存储引擎（InnoDB/MyISAM等）读写磁盘数据。

<Callout type="info" title="核心认知">
MySQL的存储引擎是可插拔的——SQL层（Server层）负责解析和优化，存储引擎负责数据的物理存取。InnoDB从5.5起成为默认引擎，支持事务、行锁、MVCC，是OLTP场景的首选。
</Callout>

## 数据类型速查

| 类别 | 类型 | 说明 | 典型场景 |
|------|------|------|----------|
| 整数 | `TINYINT` | 1字节(-128~127) | 状态/布尔 |
| 整数 | `INT` | 4字节(-2^31~2^31-1) | 主键/计数 |
| 整数 | `BIGINT` | 8字节 | 大ID/时间戳 |
| 小数 | `DECIMAL(p,s)` | 精确小数 | 金额（禁用FLOAT/DOUBLE） |
| 字符串 | `CHAR(n)` | 定长n字符 | 手机号/身份证 |
| 字符串 | `VARCHAR(n)` | 变长n字符 | 姓名/邮箱/地址 |
| 文本 | `TEXT` | 长文本(64KB) | 文章内容 |
| 二进制 | `BLOB` | 二进制(64KB) | 图片/文件 |
| 日期 | `DATE` | 日期(YYYY-MM-DD) | 生日 |
| 日期 | `DATETIME` | 日期时间 | 创建时间/更新时间 |
| 时间 | `TIMESTAMP` | 时间戳(1970-2038) | 自动更新时间 |

<Callout type="warning" title="类型选择原则">
能小不大（`TINYINT` > `INT` > `BIGINT`），定长用`CHAR`变长用`VARCHAR`，金额必须用`DECIMAL`（禁用`FLOAT`/`DOUBLE`），大文件存文件系统只存路径。
</Callout>

## DDL建库建表

```
-- 创建数据库
CREATE DATABASE shop CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE shop;

-- 创建用户表
CREATE TABLE users (
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
  username VARCHAR(50) NOT NULL COMMENT '用户名',
  email VARCHAR(100) NOT NULL COMMENT '邮箱',
  phone VARCHAR(20) DEFAULT NULL COMMENT '手机号',
  age TINYINT UNSIGNED DEFAULT 0 COMMENT '年龄',
  balance DECIMAL(10,2) DEFAULT 0.00 COMMENT '余额',
  status TINYINT DEFAULT 1 COMMENT '状态:1正常0禁用',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  UNIQUE KEY uk_username (username),
  UNIQUE KEY uk_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 修改表结构
ALTER TABLE users ADD COLUMN avatar VARCHAR(255) DEFAULT NULL COMMENT '头像URL';
ALTER TABLE users MODIFY COLUMN phone VARCHAR(15) NOT NULL;
ALTER TABLE users DROP COLUMN avatar;
ALTER TABLE users RENAME TO members;

-- 清空表（保留结构，重置AUTO_INCREMENT）
TRUNCATE TABLE users;

-- 删除表（结构+数据）
DROP TABLE users;
```

## 约束体系

| 约束 | 关键字 | 说明 |
|------|--------|------|
| 主键 | `PRIMARY KEY` | 唯一标识+非空，一张表一个 |
| 自增 | `AUTO_INCREMENT` | 主键自动递增（配合INT） |
| 唯一 | `UNIQUE` | 值不重复（允许NULL） |
| 非空 | `NOT NULL` | 不允许NULL |
| 默认 | `DEFAULT` | 未指定时自动填充 |
| 外键 | `FOREIGN KEY` | 引用另一表主键，保证参照完整性 |
| 检查 | `CHECK` | 自定义条件（MySQL 8.0.16+） |

<Glossary>

<GlossaryItem term="存储引擎">
MySQL可插拔的底层数据存取模块。InnoDB（默认，支持事务/行锁/MVCC）、MyISAM（无事务/表锁/全文索引）、Memory（全内存/重启丢失）。现代MySQL应统一使用InnoDB。
</GlossaryItem>

<GlossaryItem term="聚簇索引">
InnoDB的主键索引，叶子节点直接存储完整行数据。数据和主键索引"聚簇"在一起，按主键查询一次IO即可获取整行。一张表只有一个聚簇索引。
</GlossaryItem>

<GlossaryItem term="utf8mb4">
MySQL中真正完整的UTF-8字符集，支持4字节字符（包括emoji表情）。utf8是utf8mb3的别名，只支持3字节，无法存储emoji。MySQL 8.0默认字符集已改为utf8mb4。
</GlossaryItem>

<GlossaryItem term="AUTO_INCREMENT">
自增属性，配合整数主键使用。插入时不指定主键值则自动递增。`INT UNSIGNED`范围0~4294967295，足够大多数场景。分布式环境需考虑雪花算法等方案。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：MySQL的客户端/服务器架构由哪几层组成？SQL语句经过哪些处理阶段？

<Answer>
MySQL架构分四层：①连接管理层——连接池、认证鉴权、线程管理；②SQL层（Server层）——解析器（词法/语法分析）→优化器（生成执行计划）→执行器（调用引擎接口）；③存储引擎接口——可插拔引擎架构；④文件系统——.ibd数据文件、redo/undo日志。SQL处理：客户端发SQL → 连接层认证 → 解析器解析 → 优化器优化 → 执行器调引擎 → 引擎读写磁盘 → 结果返回。
</Answer>

**问题 2**：VARCHAR和CHAR的区别是什么？TEXT和BLOB的区别呢？

<Answer>
CHAR(n)是定长字符串，始终占n字符空间，不足用空格填充，适合长度固定的数据（手机号/身份证）。VARCHAR(n)是变长字符串，占 真实长度+1~2字节，适合长度不固定的数据（姓名/邮箱）。TEXT存储文本字符串（有字符集），BLOB存储二进制数据（无字符集，如图片）。大文件建议存文件系统只存路径。
</Answer>

**问题 3**：MySQL中INT(11)的11代表什么？DECIMAL(10,2)中10和2分别是什么？

<Answer>
INT(11)的11是显示宽度（display width），不是存储长度——INT无论写INT(1)还是INT(11)都占4字节、范围相同。显示宽度仅在ZEROFILL时有效，MySQL 8.0已废弃。DECIMAL(10,2)中10是精度（总位数），2是小数位数——可存-99999999.99到99999999.99。金额必须用DECIMAL（精确小数），禁用FLOAT/DOUBLE（浮点精度丢失）。
</Answer>

**问题 4**：设计一张用户表，包含自增主键、用户名（唯一非空）、邮箱（唯一）、手机号、年龄（默认0）、注册时间（默认当前时间），请写出DDL。

<Answer>
CREATE TABLE users (id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT, username VARCHAR(50) NOT NULL, email VARCHAR(100) NOT NULL, phone VARCHAR(20) DEFAULT NULL, age TINYINT UNSIGNED DEFAULT 0, created_at DATETIME DEFAULT CURRENT_TIMESTAMP, UNIQUE KEY uk_username(username), UNIQUE KEY uk_email(email)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
</Answer>
