## ACID与隔离级别

<MseTransactionsDiagram />

事务是数据库操作的最小逻辑执行单位，具有ACID四大特性。InnoDB通过undo log保证原子性、redo log保证持久性、锁+MVCC保证隔离性，三者共同保证一致性。

## ACID四大特性

| 特性 | 含义 | 实现机制 |
|------|------|----------|
| A 原子性 | 全部成功或全部回滚 | undo log（记录旧值，回滚恢复） |
| C 一致性 | 事务前后数据合法 | A+I+D共同保证（最终目标） |
| I 隔离性 | 并发事务互不干扰 | 锁（写写互斥）+ MVCC（读写不互斥） |
| D 持久性 | 提交后永久保存 | redo log（WAL先写日志再写磁盘） |

## 四个隔离级别

```
-- 查看当前隔离级别
SELECT @@transaction_isolation;  -- MySQL 8.0
-- 默认：REPEATABLE-READ（RR）

-- 设置隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 事务控制
BEGIN;
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  SAVEPOINT sp1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;
  -- 如果出错回滚到保存点
  -- ROLLBACK TO sp1;
COMMIT;  -- 提交（持久化）  /  ROLLBACK;  -- 回滚全部
```

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 性能 |
|----------|------|------------|------|------|
| READ UNCOMMITTED | 有 | 有 | 有 | 最好 |
| READ COMMITTED (RC) | 无 | 有 | 有 | 好 |
| REPEATABLE READ (RR) | 无 | 无 | 无(InnoDB) | 中 |
| SERIALIZABLE | 无 | 无 | 无 | 最差 |

<Callout type="info" title="InnoDB默认RR解决幻读">
InnoDB在RR级别下通过MVCC（快照读）+ Next-Key Lock（当前读）解决幻读。快照读通过Read View看到事务开始时的快照；当前读通过锁住间隙阻止INSERT。
</Callout>

## MVCC多版本并发控制

```
-- MVCC核心：每行隐藏列 + undo版本链 + Read View
--
-- 隐藏列：
--   trx_id = 最后修改该行的事务ID
--   roll_pointer → 指向undo log中该行旧版本
--
-- undo版本链：
--   每次UPDATE/DELETE在undo log记录旧版本
--   通过roll_pointer串联成链表
--
-- Read View（一致性快照）：
--   事务SELECT时生成，包含当前活跃事务ID列表
--   遍历版本链找第一个可见版本
--
-- RC vs RR核心区别：
--   RC：每次SELECT生成新Read View → 看到最新已提交数据
--   RR：第一次SELECT生成后复用 → 整个事务看到一致快照
```

## InnoDB锁体系

| 分类 | 类型 | 说明 |
|------|------|------|
| 粒度 | 行锁 | 锁单行（默认） |
| 粒度 | 间隙锁 Gap Lock | 锁两行间隙，阻止INSERT |
| 粒度 | Next-Key Lock | Record + Gap（RR默认） |
| 模式 | 共享锁 S | 读锁 `SELECT ... LOCK IN SHARE MODE` |
| 模式 | 排他锁 X | 写锁 `SELECT ... FOR UPDATE` / UPDATE / DELETE |
| 表级 | 意向锁 IS/IX | 标记行锁意向，快速判断表锁冲突 |

<Callout type="warning" title="死锁处理">
死锁：两事务互相持有对方需要的锁。InnoDB通过wait-for graph检测环，回滚undo量最小的事务。预防：①按固定顺序访问表和行；②事务尽量短小；③大事务拆小。
</Callout>

<Glossary>

<GlossaryItem term="ACID">
事务四大特性：原子性（全部成功或全部回滚，undo log实现）、一致性（数据始终合法，A+I+D保证）、隔离性（并发互不干扰，锁+MVCC实现）、持久性（提交后永久，redo log实现）。
</GlossaryItem>

<GlossaryItem term="MVCC">
多版本并发控制。每行有隐藏列trx_id和roll_pointer→undo log版本链。事务SELECT时生成Read View一致性快照，遍历版本链找可见版本。实现读不阻塞写、写不阻塞读。RC每次SELECT新Read View，RR复用第一次的。
</GlossaryItem>

<GlossaryItem term="隔离级别">
四个级别从低到高：读未提交（脏读）、读已提交RC（解决脏读）、可重复读RR（解决不可重复读，InnoDB解决幻读）、串行化（全部解决但性能最差）。InnoDB默认RR。
</GlossaryItem>

<GlossaryItem term="Next-Key Lock">
InnoDB在RR级别下的锁策略 = Record Lock（行锁）+ Gap Lock（间隙锁）。锁住行+锁住行之间的间隙，阻止其他事务在范围内INSERT，从而解决幻读。
</GlossaryItem>

<GlossaryItem term="redo log">
InnoDB重做日志，物理日志，记录页的物理修改。WAL机制——先写redo log再写数据页。保证事务提交后即使崩溃也能从redo log恢复已提交数据（持久性D）。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：事务的ACID特性分别是什么？InnoDB如何保证每个特性？

<Answer>
A原子性——全部成功或全部回滚，undo log实现。C一致性——事务前后数据合法，A+I+D共同保证。I隔离性——并发互不干扰，锁+MVCC实现。D持久性——提交后永久保存，redo log的WAL机制实现（先写日志再写磁盘，崩溃后用redo log恢复）。
</Answer>

**问题 2**：四个隔离级别各出现什么并发问题？InnoDB默认哪个？如何解决幻读？

<Answer>
读未提交：脏读+不可重复读+幻读。RC：解决脏读，有不可重复读+幻读。RR：解决脏读+不可重复读，InnoDB额外解决幻读。串行化：全部解决但性能最差。InnoDB默认RR，通过MVCC（快照读Read View）+ Next-Key Lock（当前读锁间隙）解决幻读。
</Answer>

**问题 3**：MVCC的工作原理？RC和RR在MVCC上的核心区别？

<Answer>
MVCC原理：每行有隐藏trx_id和roll_pointer→undo log版本链。SELECT时生成Read View（活跃事务ID列表），遍历版本链找第一个可见版本。RC每次SELECT生成新Read View看到最新已提交数据（不可重复读）；RR第一次SELECT生成后复用，整个事务看一致快照（可重复读）。
</Answer>

**问题 4**：InnoDB的行锁有哪些类型？什么是死锁？如何检测处理？

<Answer>
锁类型：按粒度分行锁/间隙锁Gap Lock/Next-Key Lock(Record+Gap)；按模式分共享锁S(读锁)/排他锁X(写锁)；表级有意向锁IS/IX。死锁是两事务互相持有对方需要的锁。InnoDB用wait-for graph检测环，回滚undo量最小的事务。预防：按固定顺序访问、事务短小、大事务拆小。
</Answer>

</Exercises>
