## 直觉引入

堆快照就像给内存拍一张「X光片」。但单张 X 光片只能看到「现在有什么」，看不出「哪里在病变」——你不知道哪些对象是正常的、哪些是泄漏的。所以真正有效的做法是拍三张片子：第一张是基线（手术前），第二张是操作后（可能产生了病变），第三张是再次操作后（病变在扩大）。把第二张和第三张减去第一张，差值就是「新增的、可能是泄漏的对象」。然后对这些可疑对象，用 Retainers 面板像「追溯血管走向」一样，沿着引用链找到那个「源头病变」（该断的引用）。

## Shallow Size 与 Retained Size

<Term def="Shallow Size 是对象自身占用的内存（不含其引用的其他对象），Retained Size 是对象被回收后能释放的总内存（自身 + 其独占引用的所有对象）。定位泄漏时 Retained Size 才是关键——一个 Shallow Size 很小的对象可能因为独占引用了一个巨大的数组而拥有极大的 Retained Size。">Shallow Size 与 Retained Size</Term>的区别是理解堆快照的核心。一个对象本身的 Shallow Size 可能很小（比如一个 Map 只有几十字节），但如果它独占引用了一个 100MB 的数组，它的 Retained Size 就是 100MB——删掉这个 Map 就能释放 100MB。

```javascript
// 用代码理解 Shallow vs Retained
const cache = new Map();      // Shallow: ~80B, Retained: ~80B（空的）
const hugeArray = new Array(1e6).fill("x"); // Shallow: ~8MB

cache.set("key", hugeArray);  // cache 独占引用 hugeArray
// 现在:
//   cache 的 Shallow: ~80B（Map 结构本身没大多少）
//   cache 的 Retained: ~8MB（删掉 cache，hugeArray 也变成不可达 → 释放 8MB）
//   hugeArray 的 Shallow: ~8MB
//   hugeArray 的 Retained: ~8MB（没有独占引用其他对象）

// 如果 hugeArray 被多处引用:
const otherRef = hugeArray;
//   cache 的 Retained: ~80B（删掉 cache，hugeArray 仍被 otherRef 引用 → 不释放）
//   这就是为什么 Retained Size 依赖「独占引用」
```

## 三快照法工作流

```javascript
// 方法一：用 DevTools Memory 面板手动拍快照
// 1. 启动: node --inspect server.js
// 2. DevTools → Memory → Take heap snapshot（快照1: 基线）
// 3. 执行一次业务操作（如发一个请求）
// 4. Take heap snapshot（快照2: 第一次操作后）
// 5. 手动触发 GC（点 Collect garbage 按钮）
// 6. 再执行一次相同操作
// 7. Take heap snapshot（快照3: 第二次操作后）
// 8. 选快照3 → Comparison → 对比快照2
//    看 "Delta" 列：新增的对象就是泄漏嫌疑

// 方法二：用代码自动拍快照（生产环境/无人值守）
const { writeHeapSnapshot } = require("node:v8");

let snapshotCount = 0;
function takeSnapshot(label) {
  const file = `heap-${label}-${Date.now()}.heapsnapshot`;
  writeHeapSnapshot(file);
  console.log(`快照已保存: ${file}`);
}

// 在内存超过阈值时自动拍快照
setInterval(() => {
  const { heapUsed } = process.memoryUsage();
  if (heapUsed > 500 * 1024 * 1024) { // 超过 500MB
    takeSnapshot(`high-mem-${++snapshotCount}`);
  }
}, 30000);

// 也可以在特定操作前后拍
// takeSnapshot("before-request");
// doRequest();
// takeSnapshot("after-request");
```

```javascript
// Comparison 视图的关键列:
// Constructor: 对象类型（如 Map, Array, Object, String）
// Added: 两次快照间新增的对象数量
// Deleted: 两次快照间被回收的对象数量
// Delta: 净增量（Added - Deleted），正值=可能泄漏
// Alloc. Size: 新增对象占用的内存
// Freed Size: 被回收对象释放的内存
// Size Delta: 净增内存（最关键的指标）

// 典型泄漏在 Comparison 视图中的表现:
// (string)  Delta: +50000   Size Delta: +3.2MB  ← 每次操作多5万个字符串
// (Map)     Delta: +1       Size Delta: +8MB    ← Map 对象只增1个但内存涨8MB
//   → 点开 Map → Retainers → 发现是被全局 cache 引用
```

## 常见误区

<Callout type="trap">
**误区：拍一张快照就能找到泄漏。** 单张快照只展示「当前内存里有什么」，但内存里有几十万个对象，绝大多数是正常的——你无法区分哪些是泄漏的、哪些是正常使用的。必须用三快照法拍至少两张快照做 Comparison，找出两次快照间的「增量」——只有增量才可能是泄漏。更精确的是三快照：基线 → 操作1 → 快照2 → GC → 操作2 → 快照3，对比快照2和快照3的增量，排除一次性缓存。直接看单张快照的 Retained Size 排序找最大的对象，往往会把正常的大缓存（如模块缓存、连接池）误判为泄漏。
</Callout>

<Exercises>
**问题 1**：Shallow Size 和 Retained Size 的区别是什么？为什么定位泄漏要看 Retained Size？

<Answer>
Shallow Size 是对象自身占用的内存，不含其引用的其他对象。比如一个 Map 的 Shallow Size 只有几十字节（Map 结构本身）。Retained Size 是对象被回收后能释放的总内存，等于自身 Shallow Size 加上它独占引用的所有对象的 Shallow Size 之和。「独占引用」是关键——只有该对象引用、没有其他对象也引用的才算。定位泄漏要看 Retained Size 的原因：泄漏的根因往往是一个小对象（如 Map 的 key、闭包变量）独占引用了一个大对象（如大数组、大字符串）。这个小对象 Shallow Size 很小，但 Retained Size 很大——删掉它就能释放大量内存。如果只看 Shallow Size，你会盯着大数组本身，但它可能被多处引用（删掉一个引用不释放），找不到真正的泄漏点。Retained Size 告诉你「删掉这个对象能释放多少内存」，这才是修复泄漏的指引。
</Answer>

**问题 2**：描述三快照法的完整步骤，以及为什么需要三张而不是两张。

<Answer>
三快照法步骤：①拍快照1（基线，启动后稳定状态）；②执行一次业务操作（如发一个请求）；③拍快照2（第一次操作后）；④手动触发 GC（点 Collect garbage，清掉一次性对象）；⑤再执行一次相同的业务操作；⑥拍快照3（第二次操作后）；⑦选快照3 → Comparison → 对比快照2，看 Delta 列。需要三张而不是两张的原因：两张快照（基线 vs 操作后）的增量中混入了「一次性缓存」——有些对象第一次操作时创建是正常的（如模块初始化、JIT 编译缓存），它们不会在第二次操作时继续增长。三快照法通过对比快照2和快照3（两次操作之间的增量），排除了这些一次性增长——如果每次操作的增量都相同，说明是泄漏（每次操作都新增一份不回收的对象）；如果第二次增量显著小于第一次，说明第一次的大头是一次性初始化。第三张快照的作用是「确认泄漏是持续性的而非一次性的」。
</Answer>
</Exercises>

<GlossaryItem term="Shallow Size">对象自身占用的内存大小，不含其引用的其他对象。一个 Map 的 Shallow Size 只有几十字节，即使它引用了 100MB 的数据。仅看 Shallow Size 无法定位泄漏。</GlossaryItem>
<GlossaryItem term="Retained Size">对象被回收后能释放的总内存，等于自身 Shallow Size 加上独占引用对象的 Shallow Size 之和。定位泄漏的关键指标——删掉 Retained Size 最大的对象能释放最多内存。</GlossaryItem>
<GlossaryItem term="三快照法">拍基线快照 → 操作 → 快照2 → GC → 操作 → 快照3 → 对比快照2和快照3的增量。通过两次操作间的增量对比排除一次性缓存，确认泄漏是持续性的。是 Heap Snapshot 定位泄漏的标准工作流。</GlossaryItem>
