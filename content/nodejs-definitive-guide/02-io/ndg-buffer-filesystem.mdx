## 直觉引入

想象你在仓库管理货物。**Buffer** 是仓库里的标准集装箱——每个箱子固定大小（一个字节 0-255），放在仓库外的堆场（V8 堆外内存），不占仓库内部的整理空间（GC 不管它）。你需要搬运大宗货物（二进制文件/网络数据）时，用集装箱打包比零散搬运高效得多。**fs 模块**是仓库的进出库系统——有三种提货方式：同步提货（阻塞式，排队等完才能走人）、异步回调（下个单，好了通知你）、Promise 提货（推荐，下个单用 await 等）。**path 模块**是仓库的地址管理系统——帮你拼接货位编号、解析绝对路径。

## Buffer：二进制数据容器

<Term def="Buffer 是 Node.js 中表示固定长度二进制数据的类，分配在 V8 堆外内存，每个元素是一个字节（0-255），不经过 V8 GC 管理。">Buffer</Term>

```javascript
// 创建 Buffer
const buf1 = Buffer.alloc(8);           // 分配 8 字节并填零（安全）
const buf2 = Buffer.allocUnsafe(8);     // 分配 8 字节不填零（快，可能含旧数据）
const buf3 = Buffer.from("Hello", "utf8"); // 从字符串创建
// buf3 → <Buffer 48 65 6c 6c 6f>

// 读写
buf1.write("Hi", 0, "utf8");             // 从 offset 0 写入
console.log(buf3.toString("utf8"));      // "Hello"
console.log(buf3[0]);                    // 72 (H 的 ASCII)

// 操作
const part = buf3.subarray(0, 3);        // 切片 <Buffer 48 65 6c>
const combined = Buffer.concat([buf1, buf3]); // 拼接

// 编码
Buffer.from("ABCD", "base64");           // Base64 解码
buf3.toString("hex");                    // "48656c6c6f"

// 关键：Buffer 在 V8 堆外，处理大块二进制不增加 GC 压力
// fs.readFile 不指定编码时返回 Buffer（不是字符串）
```

## fs 模块：三种读写方式

```javascript
const fs = require("fs");
const { readFile, writeFile } = require("fs/promises"); // Promise API（推荐）

// ① 同步（阻塞）——仅在启动期用
try {
  const data = fs.readFileSync("config.json", "utf8");
  const config = JSON.parse(data);
} catch (e) { /* ... */ }

// ② 异步回调——传统方式
fs.readFile("data.txt", "utf8", (err, data) => {
  if (err) return console.error(err);
  console.log(data);
});

// ③ Promise（推荐）——async/await
async function loadConfig() {
  const data = await readFile("config.json", "utf8");
  return JSON.parse(data);
}

// 大文件用流式读取（不一次性读入内存）
const { createReadStream, createWriteStream } = fs;
const stream = createReadStream("big.bin", { highWaterMark: 64 * 1024 });
stream.on("data", (chunk) => { /* chunk 是 Buffer */ });

// 注意：底层都走 libuv 线程池（默认 4 线程）
// 可通过 UV_THREADPOOL_SIZE=8 调大（启动前设置）
```

## path 模块与文件描述符

```javascript
const path = require("path");

// 路径拼接与解析
path.join("src", "lib", "util.js");      // "src/lib/util.js"
path.resolve("src", "..", "dist");        // "/cwd/dist"（绝对路径，基于 cwd）
path.extname("file.tar.gz");              // ".gz"
path.basename("/a/b/c.txt", ".txt");      // "c"
path.dirname("/a/b/c.txt");               // "/a/b"

// __dirname（CJS）vs import.meta.url（ESM）
// CJS:
console.log(__dirname);   // 当前模块所在目录的绝对路径
console.log(__filename);  // 当前模块文件的绝对路径

// ESM（没有 __dirname）:
// import { fileURLToPath } from "url";
// const __dirname = path.dirname(fileURLToPath(import.meta.url));

// 文件描述符（fd）：大文件随机读取
const fd = fs.openSync("large.db", "r");
const buf = Buffer.alloc(1024);
// 从位置 4096 读取 1024 字节到 buf 的 offset 0
fs.readSync(fd, buf, 0, 1024, 4096);
fs.closeSync(fd); // 用完必须关闭（fd 是有限系统资源）
```

## 常见误区

<Callout type="trap">
**误区：运行时用 `fs.readFileSync` 读取配置文件没关系，反正只读一次。** 错。同步 API 会阻塞事件循环——文件在磁盘上、网络存储上时，读取可能耗时几十毫秒甚至几秒，期间所有请求无法响应。即使是启动期也建议用异步。运行时绝对禁止同步 API。大文件更不能用 `readFile`（一次性读入内存 OOM），必须用 `createReadStream` 流式读取。fd（文件描述符）是有限资源（默认每进程 1024），用完必须 close，否则 fd 泄漏导致后续 open 失败（EMFILE）。
</Callout>

<Exercises>
**问题 1**：Buffer.alloc 和 allocUnsafe 有何不同？为什么不推荐在生产代码中用 allocUnsafe？

<Answer>
alloc(size) 分配并填零——安全但慢（要清零旧内存）。allocUnsafe(size) 分配但不填零——快但可能含旧数据（内存碎片中的敏感信息），必须手动写入覆盖后才能使用。生产代码不推荐 allocUnsafe 的原因：未初始化的 Buffer 可能包含上一个进程残留的密码、密钥等敏感数据，造成信息泄漏。除非确定会立即填满整个 Buffer（如从网络读到 Buffer 后立刻发送），否则用 alloc。Node.js 内部优化：小 Buffer（<4KB）的 allocUnsafe 会用预分配的内部池，实际上 alloc 和 allocUnsafe 性能差异在大多数场景可忽略。
</Answer>

**问题 2**：如何用文件描述符（fd）实现大文件的随机读取？为什么不直接用 readFile？

<Answer>
大文件随机读取：fs.open 获得 fd，fs.read(fd, buf, offset, length, position, cb) 从指定 position 读取，用完 fs.close(fd)。不用 readFile 因为 readFile 会把整个文件读入内存——10GB 文件占 10GB 内存甚至 OOM。随机读取只取需要的片段，内存恒定（=buffer 大小）。也可用 createReadStream(path, { start, end }) 流式读取片段。fd 是有限系统资源（默认 1024/进程），用完必须 close 否则 fd 泄漏导致 EMFILE。生产用 graceful-fs 限制并发 fd 数。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Buffer">Node.js 中表示固定长度二进制数据的类，分配在 V8 堆外内存（C++ 层），每个元素是一个字节（0-255）。不经过 V8 GC 管理，适合处理大块二进制数据（文件/网络）不给 GC 造成压力。alloc 填零安全，allocUnsafe 不填零快但有信息泄漏风险。</GlossaryItem>
<GlossaryItem term="fs 三种读写方式">同步（阻塞事件循环，仅启动期用）、异步回调（非阻塞但回调地狱）、Promise（fs.promises，推荐 async/await）。三者底层都走 libuv 线程池（默认 4 线程）。大文件用 createReadStream 流式读取而非 readFile 一次性读入内存。</GlossaryItem>
<GlossaryItem term="文件描述符（fd）">操作系统分配给打开文件的整数句柄。fs.open 返回 fd，后续 fs.read/fs.write 用 fd 操作。fd 是有限资源（默认每进程 1024），用完必须 close。大文件随机读取用 fd + position 偏移，内存恒定。fd 泄漏会导致 EMFILE 错误（无法打开新文件）。</GlossaryItem>
</Glossary>
