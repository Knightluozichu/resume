## 直觉引入

想象一条工厂流水线。**Readable** 是原料入口——矿石从传送带送进来；**Writable** 是成品出口——加工好的产品装箱发出。**Duplex** 是双向通道——像电话线，两边同时说话和听话，互不干扰（TCP socket 就是这种）。**Transform** 是中间加工站——原料进去、成品出来，输入和输出之间有个转换关系（比如压缩机：原始数据进去、压缩数据出来）。**pipe** 就是把传送带连起来——原料自动从入口流向出口，但如果出口处理太慢（装箱跟不上），传送带会自动暂停等它跟上——这就是**背压**。

## 四种流类型

<Term def="流（Stream）是 Node.js 处理流式数据的抽象基类——数据不是一次性全部到达，而是分成 chunk 逐步处理，避免大文件一次性读入内存导致 OOM。">流</Term>

```javascript
const { Readable, Writable, Duplex, Transform } = require("stream");
const fs = require("fs");

// Readable：数据源
const readable = fs.createReadStream("big.txt", { highWaterMark: 64 * 1024 });
// Writable：数据目的地
const writable = fs.createWriteStream("copy.txt");
// Duplex：同时可读可写（如 TCP socket）
// const socket = net.connect(3000); // socket.read() + socket.write()
// Transform：写入变换后读出（如压缩）
const { createGzip } = require("zlib");
const gzip = createGzip(); // 写入原始 → 读出压缩

// pipe：把可读流连接到可写流
readable.pipe(gzip).pipe(writable);
// 内部自动处理背压：writable 写不过来时暂停 readable

// pipeline：推荐替代 pipe（自动错误传播 + 清理）
const { pipeline } = require("stream");
pipeline(readable, gzip, writable, (err) => {
  if (err) console.error("管道失败:", err);
  else console.log("复制完成");
});
```

## 背压机制

**背压（Backpressure）** 是流式处理的核心安全机制。当 Readable 生产数据的速度大于 Writable 消费速度时，数据会在内存中堆积。pipe/pipeline 内部自动处理：

```javascript
// pipe 内部的背压逻辑（简化）：
readable.on("data", (chunk) => {
  const ok = writable.write(chunk);
  if (!ok) {
    // Writable 内部缓冲满了，返回 false
    readable.pause();        // 暂停读取
    writable.once("drain", () => {
      readable.resume();     // 缓冲排空后恢复
    });
  }
});

// 为什么推荐 pipeline 而非 pipe：
// 1. pipe 不传播错误——如果 gzip 崩溃，readable 和 writable 不会被销毁 → 内存泄漏
// 2. pipeline 自动销毁所有流并回调错误
// 3. pipeline 支持多个 Transform 串联

// 异步迭代（Node 10+，最简洁的方式）：
async function processStream(readable, writable) {
  for await (const chunk of readable) {
    // 自带背压处理：await 等待 writable 写完
    if (!writable.write(chunk)) {
      await new Promise(resolve => writable.once("drain", resolve));
    }
  }
  writable.end();
}
```

## 流动模式与暂停模式

Readable 流有两种模式：

```javascript
const readable = fs.createReadStream("data.txt");

// 暂停模式（默认）：需要显式 read()
readable.on("readable", () => {
  let chunk;
  while ((chunk = readable.read()) !== null) {
    console.log("读到:", chunk.length, "字节");
  }
});

// 流动模式：data 事件自动推送
readable.on("data", (chunk) => {
  console.log("推送:", chunk.length, "字节");
});
readable.on("end", () => console.log("读完"));

// 切换：添加 data 监听 → 流动；移除 → 暂停
//       pause() / resume() 手动控制
```

## 常见误区

<Callout type="trap">
**误区：`stream.pipe()` 会自动处理所有错误。** 错。pipe 只处理背压，不传播错误——如果源流或目标流出错，另一端不会被自动销毁，导致内存泄漏和句柄泄漏。必须用 `stream.pipeline()` 替代——它会自动销毁所有流并在出错时调用回调。或者手动监听每个流的 error 事件。这是生产环境流处理的头号坑。
</Callout>

<Exercises>
**问题 1**：Node.js 流有哪四种类型？各自的特点和典型应用场景？

<Answer>
①Readable（可读流）：数据源，如 fs.createReadStream、http.IncomingMessage。②Writable（可写流）：数据目的地，如 fs.createWriteStream、http.ServerResponse。③Duplex（双工流）：同时可读可写，读写独立缓冲，如 TCP socket。④Transform（转换流）：Duplex 特例，写入经变换后从读取端输出，如 zlib.createGzip（压缩）、crypto.createCipheriv（加密）。前两者是基础，后两者是组合——Duplex 是两条独立管道，Transform 是中间加了过滤器。
</Answer>

**问题 2**：如何自定义一个 Transform 流实现「读取文件 → 行号前缀 → 写入文件」？

<Answer>
继承 Transform 或 new Transform({ transform })。核心是 _transform(chunk, encoding, callback)：接收 chunk，处理后 this.push() 推送输出，callback() 表示完成。维护行计数器和未完成行缓冲。每次收到 chunk（Buffer）按 \n split 成行，给每行加前缀后 push，最后一行可能不完整需缓存。还需 _flush(callback) 处理残留行。然后 pipeline(readStream, transform, writeStream)。关键点：chunk 边界不等于行边界——一个 chunk 可能在行中间断开，必须用缓冲拼接。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="背压（Backpressure）">当 Readable 生产速度 > Writable 消费速度时，数据在内存堆积的安全机制。pipe/pipeline 内部自动处理：Writable.write() 返回 false 时暂停 Readable，drain 事件后恢复。不处理背压会导致内存无限增长 OOM。异步迭代 for await...of 自带背压。</GlossaryItem>
<GlossaryItem term="pipeline vs pipe">pipeline 是 pipe 的安全替代——自动传播错误并销毁所有流（防止内存泄漏），支持多 Transform 串联，有 Promise 版本。pipe 不传播错误，中间流出错时源/目标流不会被销毁。生产环境流处理应一律用 pipeline。</GlossaryItem>
<GlossaryItem term="流动模式与暂停模式">Readable 的两种运行模式。暂停模式（默认）需显式 read() 拉取，监听 readable 事件。流动模式 data 事件自动推送。添加 data 监听器 → 流动；移除 → 暂停。推荐用 pipe/pipeline 或 for await...of（暂停模式逐块拉取，自带背压），避免手动监听 data 事件。</GlossaryItem>
</Glossary>
