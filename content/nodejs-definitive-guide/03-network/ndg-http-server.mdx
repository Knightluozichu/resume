## 直觉引入

想象一个银行柜台。**http.createServer** 就是开设窗口——每个请求是一个客户。客户递上申请表（**req**），柜员处理完递回回执（**res**）。申请表不是一次性到手的——客户可能从口袋里一张张掏表单（body 以 chunk 流式到达），柜员要等他说「我掏完了」（end 事件）才能开始处理。回执也是一张张递出去的（res.write 分段写），最后说「给完了」（res.end）。关键：只有一个柜员（单线程），但他同时接待多个客户——让一个客户等审批时（异步 I/O），他转头处理另一个客户。但如果某个客户需要柜员手动算账 5 分钟（CPU 密集同步代码），所有其他客户都得等。

## req 与 res 的流式本质

<Term def="IncomingMessage 是 HTTP 请求对象，继承自 Readable 流——请求体以 chunk 流式到达。ServerResponse 是 HTTP 响应对象，继承自 Writable 流——响应体通过 write/end 写出。">req/res 流</Term>

```javascript
const http = require("http");

const server = http.createServer((req, res) => {
  // req: IncomingMessage（可读流）
  console.log(req.method);    // "GET" / "POST"
  console.log(req.url);       // "/api?foo=bar"
  console.log(req.headers);   // { host, cookie, "content-type", ... }

  // res: ServerResponse（可写流）
  res.writeHead(200, { "Content-Type": "application/json" });
  // 或分别设置：
  // res.statusCode = 200;
  // res.setHeader("Content-Type", "application/json");

  res.write(JSON.stringify({ ok: true })); // 分段写
  res.end();  // 必须调用！否则连接挂起（客户端一直等）
});

server.listen(3000, () => console.log("Server on :3000"));
```

## POST body 流式接收

```javascript
// 原生 http 不自动解析 body（不像 Express 的 body-parser）
function readBody(req, limit = 1e6) {
  return new Promise((resolve, reject) => {
    let body = "";
    let size = 0;

    req.on("data", (chunk) => {
      size += chunk.length;
      if (size > limit) {
        reject(new Error("Body too large")); // 防 DoS
        req.destroy(); // 停止接收
        return;
      }
      body += chunk.toString("utf8");
    });

    req.on("end", () => resolve(body));
    req.on("error", reject);
  });
}

server.on("request", async (req, res) => {
  if (req.method === "POST") {
    try {
      const body = await readBody(req, 1e6); // 限制 1MB
      const data = JSON.parse(body);
      res.end(JSON.stringify({ received: data }));
    } catch (e) {
      res.writeHead(400);
      res.end("Bad Request");
    }
  }
});
```

## 路由分发

```javascript
const { URL } = require("url");

const routes = [
  { method: "GET",  pattern: "/api/users",     handler: getUsers },
  { method: "GET",  pattern: "/api/users/:id", handler: getUser },
  { method: "POST", pattern: "/api/users",     handler: createUser },
];

server.on("request", async (req, res) => {
  const { pathname } = new URL(req.url, `http://${req.headers.host}`);
  const route = routes.find(r => r.method === req.method && matchPath(r.pattern, pathname));

  if (!route) {
    res.writeHead(404);
    return res.end("Not Found");
  }

  try {
    await route.handler(req, res);
  } catch (e) {
    res.writeHead(500);
    res.end("Internal Server Error");
  }
});

// 每个 req 独立回调，互不阻塞——一个慢请求不卡住其他请求
// 但 CPU 密集同步代码会阻塞事件循环影响所有请求
```

## 常见误区

<Callout type="trap">
**误区：忘记调用 `res.end()` 没关系，响应会自动结束。** 错。如果不调用 `res.end()`，HTTP 连接会一直保持打开状态——客户端一直等待更多数据，直到超时。这会导致连接泄漏、fd 耗尽。即使响应体为空也必须 `res.end()`。另一个坑：`res.end(data)` 可以同时写入最后一块数据并结束，但 `res.write(data)` 之后必须再调用 `res.end()`。
</Callout>

<Exercises>
**问题 1**：http.createServer 的回调中 req 和 res 分别是什么？它们和流有什么关系？

<Answer>
req 是 IncomingMessage 实例，继承自 Readable 流——HTTP 请求体流式到达，需用 req.on('data') 接收 chunk、req.on('end') 处理完成。res 是 ServerResponse 实例，继承自 Writable 流——响应体通过 res.write() 分段写或 res.end() 一次性结束。关系：req 是「可读的请求」、res 是「可写的响应」——大文件上传/下载可用 pipe 直接连接 req→文件流、文件流→res，实现零内存拷贝的流式传输。
</Answer>

**问题 2**：为什么每个 HTTP 请求互不阻塞？但什么情况下它们会互相影响？

<Answer>
互不阻塞：每个请求的回调在事件循环中独立排队执行，I/O 操作交给 libuv 线程池，主线程只管调度。一个请求等数据库时不阻塞其他请求。互相影响：①CPU 密集同步代码阻塞事件循环——5 秒同步循环让所有请求等 5 秒；②共享资源竞争——全局变量/单例连接池的中间状态；③fd 耗尽——并发太高导致新连接无法 accept（EMFILE）。解决：CPU 密集用 worker_threads；共享资源用锁/队列；fd 限制用 cluster 或调高 ulimit -n。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="IncomingMessage（req）">HTTP 请求对象，继承自 Readable 流。提供 req.method、req.url、req.headers 属性，请求体通过 data/end 事件流式接收。原生 http 模块不自动解析 body——需手动收集 chunk 并限制大小防止 DoS。框架（Express/Koa）的 body-parser 中间件封装了这套逻辑。</GlossaryItem>
<GlossaryItem term="ServerResponse（res）">HTTP 响应对象，继承自 Writable 流。writeHead(statusCode, headers) 设置状态码和头，write(chunk) 分段写响应体，end() 结束响应。必须调用 end() 否则连接挂起。大响应用 pipe 连接可读流实现流式传输（如文件下载 createReadStream().pipe(res)）。</GlossaryItem>
<GlossaryItem term="并发模型">Node.js HTTP 服务器是「单线程 + 事件循环 + 异步 I/O」模型——一个主线程处理所有请求的回调，I/O 交给 libuv 线程池。每个请求互不阻塞（一个等 I/O 时不影响其他），但同步 CPU 代码会阻塞所有请求。这就是为什么 CPU 密集场景需要 worker_threads 或 cluster。</GlossaryItem>
</Glossary>
