## 直觉引入

想象一家餐厅生意太好一个厨师忙不过来。**cluster** 是开分店——每家分店有独立厨房（独立进程/V8/内存），但共享同一个外卖电话号码（端口），总店（主进程）接线后分配给最闲的分店（round-robin）。一家分店厨房着火（崩溃）不影响其他分店。**worker_threads** 是在同一个厨房里加厨师——他们共享厨房设施（进程内存），但各有各的案板（独立 V8/事件循环）。主厨师把重活（揉面/CPU 密集）交给副厨师做，自己做轻活（接单/I/O）。副厨师做完通过传菜窗口（postMessage）把结果递回来。开分店成本高（每店独立租金/内存），加厨师成本低（共享厨房），但厨师间传菜需要排队（序列化开销）。

## cluster：多进程

<Term def="cluster 模块让 Node.js 利用多核 CPU——主进程 fork 多个子进程（Worker），每个有独立 V8/事件循环，通过 round-robin 共享同一端口。">cluster</Term>

```javascript
const cluster = require("cluster");
const http = require("http");
const os = require("os");

if (cluster.isPrimary) {
  // 主进程：按 CPU 核心数 fork Worker
  const numCPUs = os.cpus().length;
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }

  // Worker 崩溃自动重启
  cluster.on("exit", (worker, code) => {
    console.log(`Worker ${worker.process.pid} 退出，重启中...`);
    cluster.fork();
  });

  // 主进程与 Worker 通信（IPC）
  cluster.on("message", (worker, msg) => {
    console.log(`来自 Worker ${worker.id}:`, msg);
  });
} else {
  // Worker 进程：每个独立处理请求
  http.createServer((req, res) => {
    res.writeHead(200);
    res.end(`Worker ${process.pid} 处理了请求`);
  }).listen(3000);

  // Worker 向主进程发消息
  process.send({ status: "ready", pid: process.pid });
}
// PM2 就是基于 cluster 封装的生产级进程管理器
```

## worker_threads：多线程

```javascript
const { Worker, isMainThread, parentPort, workerData } = require("worker_threads");

if (isMainThread) {
  // 主线程：创建 Worker 卸载 CPU 密集任务
  const worker = new Worker("./heavy-task.js", {
    workerData: { input: largeArray },
  });

  worker.on("message", (result) => {
    console.log("Worker 计算完成:", result);
  });

  worker.on("error", (err) => console.error("Worker 出错:", err));
  worker.on("exit", (code) => console.log(`Worker 退出码: ${code}`));
} else {
  // Worker 线程：执行 CPU 密集计算
  const { input } = workerData;
  const result = heavyCompute(input); // 不阻塞主线程事件循环
  parentPort.postMessage(result);
}

// SharedArrayBuffer：零拷贝共享内存（配合 Atomics 保证线程安全）
const shared = new SharedArrayBuffer(1024);
const buffer = new Int32Array(shared);
// 主线程和 Worker 线程可同时读写 buffer
// Atomics.add(buffer, 0, 1); // 原子操作
```

## 常见误区

<Callout type="trap">
**误区：`worker_threads` 可以替代 `cluster`。** 错。它们解决不同问题。cluster 是多进程——每个 Worker 是独立进程，进程隔离保证一个崩溃不影响其他，适合 I/O 密集的 HTTP 服务器水平扩展。worker_threads 是多线程——同进程内独立 V8 实例，适合 CPU 密集计算不阻塞主线程。worker_threads 不能直接共享 HTTP 服务器（同进程内 listen 同端口会冲突）。正确组合：cluster 多进程 + 每个进程内 worker_threads 处理 CPU 密集任务。选择原则：I/O 并发用 cluster，CPU 计算用 worker_threads。
</Callout>

<Exercises>
**问题 1**：cluster 和 worker_threads 的本质区别是什么？各自适合什么场景？

<Answer>
cluster 是多进程——每个 Worker 独立进程、独立 V8、独立内存空间，通过 IPC（消息序列化）通信。worker_threads 是多线程——同进程内独立 V8 和事件循环，但共享进程内存（可通过 SharedArrayBuffer 零拷贝通信）。cluster 适合 I/O 密集水平扩展（HTTP 服务器多核负载），进程隔离保证容错。worker_threads 适合 CPU 密集计算（图像/加密/压缩），不阻塞主线程，比 cluster 轻量。选择：I/O 并发用 cluster，CPU 计算用 worker_threads。可组合使用。
</Answer>

**问题 2**：生产环境如何实现零停机重启（zero-downtime reload）？

<Answer>
基于 cluster + 信号机制：①主进程收到 SIGUSR2（PM2 reload 信号），逐个重启 Worker 而非同时；②对一个 Worker 发 SIGTERM，Worker 收到后 server.close() 停止接受新连接，等待已有连接处理完退出；③主进程监听 exit 事件 fork 新 Worker 替换。关键：server.close() 优雅关闭——停止 listen 且等待连接结束，但长连接（WebSocket）需超时强制断开。逐个替换始终有 N-1 个 Worker 在服务。PM2 reload 命令就是这个原理。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="cluster（多进程）">主进程 fork 多个子进程（Worker），每个有独立 V8/事件循环/内存。所有 Worker 共享同一端口——主进程用 round-robin 分发连接。Worker 崩溃主进程自动重启。适合 I/O 密集水平扩展。代价：每进程独立 V8 内存开销大。PM2 基于此原理。</GlossaryItem>
<GlossaryItem term="worker_threads（多线程）">同进程内创建独立 V8 实例和事件循环的线程。通过 postMessage（序列化）或 SharedArrayBuffer（零拷贝+Atomics 原子操作）通信。适合 CPU 密集计算不阻塞主线程。比 cluster 轻量但 postMessage 有序列化开销。不能直接共享 HTTP 端口。</GlossaryItem>
<GlossaryItem term="零停机重启">cluster 逐个重启 Worker 而非全部同时——对 Worker 发 SIGTERM 后 server.close() 优雅关闭（停止 accept、等待已有连接结束），主进程 fork 新 Worker 替换。始终有 N-1 个 Worker 在服务。PM2 reload 命令基于此原理。K8s 环境可用 readiness probe + 滚动更新。</GlossaryItem>
</Glossary>
