## 直觉引入

全书九章学完，现在把所有知识串起来。想象一个用户在浏览器输入网址访问你的 Node.js 服务器——这「一次 HTTP 请求」会经过全书讲的每一个机制。从服务器启动时加载代码（模块系统），到请求到达时事件循环调度（事件循环），到底层 TCP 连接和 TLS 加密（TCP/TLS），到 HTTP 协议解析（HTTP 服务器），到请求体的二进制数据处理（Buffer/fs），到大响应的流式输出（流与管道），到多核扩展（集群/Worker），到全程监控（性能调试）。理解这条主线，你就理解了 Node.js 运行时的全貌。

## 运行时旅程：一次 HTTP 请求

<Term def="运行时旅程是一次 HTTP 请求从到达服务器到响应完成的完整路径——贯穿模块加载、事件循环、TCP/TLS、HTTP 解析、Buffer/fs、流式输出、集群分发、性能监控八个机制。">运行时旅程</Term>

```javascript
// 一次 HTTP 请求的完整运行时旅程（注释标注全书章节）

// ① 模块系统（第 3 章）：服务器启动时同步加载，缓存在 Module._cache
const http = require("http");
const { readFile } = require("fs/promises");
const { createReadStream } = require("fs");
const { pipeline } = require("stream");

// ⑧ 集群（第 8 章）：cluster 主进程 round-robin 分发到 Worker
// if (cluster.isPrimary) { cluster.fork(); ... } else {
http.createServer(async (req, res) => {

  // ② 事件循环（第 2 章）：req 回调由 poll 阶段触发
  // ③ TCP/TLS（第 7 章）：底层 TCP 连接已建立（HTTPS 经 TLS 加密）
  // ④ HTTP 服务器（第 6 章）：req 是 IncomingMessage 可读流
  const { method, url } = req;
  console.log(`${method} ${url}`);

  if (url === "/api/data") {
    // ⑤ Buffer/fs（第 5 章）：异步读文件不阻塞事件循环
    const data = await readFile("./data.json");

    res.writeHead(200, { "Content-Type": "application/json" });
    // ⑥ 流与管道（第 4 章）：大文件用 pipe 流式输出
    res.end(data);

  } else if (url === "/api/download") {
    // 流式下载：createReadStream → pipe → res（背压自动处理）
    const stream = createReadStream("./large.bin");
    pipeline(stream, res, (err) => {
      if (err) console.error("下载失败:", err);
    });

  } else {
    res.writeHead(404);
    res.end("Not Found");
  }
  // res.end() 必须调用，否则连接挂起

}).listen(3000);
// ⑨ 性能调试（第 9 章）：--inspect + Profiler 全程监控
// node --inspect app.js → Chrome DevTools
// monitorEventLoopDelay() 检测 p99 延迟
// process.memoryUsage() 监控内存趋势
```

## 三大维度对比

| 维度 | CommonJS | ES Modules |
|------|----------|------------|
| 加载 | 同步，运行时求值 | 异步，三阶段（解析→实例化→求值） |
| 值传递 | 值拷贝（导出时快照） | 实时绑定（live binding） |
| 静态分析 | 动态（不支持 tree-shaking） | 静态（支持 tree-shaking） |
| this | module.exports | undefined（严格模式） |
| __dirname | 有 | 无（用 import.meta.url） |
| 顶层 await | 不支持 | 支持 |

## 性能排查思路

```javascript
// 系统化排查：先量后改
// 1. 事件循环延迟（找同步阻塞）
const { monitorEventLoopDelay } = require("perf_hooks");
const h = monitorEventLoopDelay({ resolution: 5 });
h.enable();
// p99 > 10ms = 有同步阻塞 → CPU Profile 找热点

// 2. I/O 瓶颈（查数据库/外部 API/同步 fs）
// --prof 看是否有大量 I/O 等待
// UV_THREADPOOL_SIZE=8 调大 libuv 线程池

// 3. 内存（查泄漏）
// process.memoryUsage() 看 heapUsed 趋势
// Heap Snapshot 对比找泄漏对象

// 4. CPU（查单核打满）
// top/htop 看进程 CPU 是否 100%
// 用 cluster 扩展到多核

// 5. 连接数（查 fd 耗尽）
// lsof -p pid | wc -l
// ulimit -n 调高或用 cluster
```

## 常见误区

<Callout type="trap">
**误区：理解 Node.js 运行时就是背概念。** 错。理解的标志是能在故障时快速定位根因——为什么响应变慢（事件循环延迟 → 同步阻塞 → CPU Profile 找热点）、为什么内存涨（Heap Snapshot → retainer 链找泄漏）、为什么 Worker 崩溃（进程隔离 → cluster 自动重启）、为什么 require 修改不生效（Module._cache 缓存 → 需重启进程）。这些是「代码跑起来后」的运行时判断力，不是 API 知识。把运行时当核心的人才能写出可控、可扩展、可排查的 Node.js 服务。
</Callout>

<Exercises>
**问题 1**：用「一次 HTTP 请求的完整生命周期」串联全书十个知识点。

<Answer>
①模块系统（第3章）：启动时 require/import 加载代码，缓存在 Module._cache；②事件循环（第2章）：请求到达后 poll 阶段接收；③TCP/TLS（第7章）：TCP 三次握手，HTTPS 经 TLS 协商密钥；④HTTP 服务器（第6章）：http 模块解析为 req（可读流）和 res（可写流）；⑤Buffer（第5章）：请求体以 Buffer chunk 流式到达；⑥fs（第5章）：处理逻辑读写文件用 fs.promises 异步 API；⑦流与管道（第4章）：大响应用 createReadStream().pipe(res) 流式传输；⑧集群（第8章）：cluster round-robin 分发到多核 Worker；⑨性能（第9章）：Profiler 监控 CPU/内存，事件循环延迟检测阻塞。一个请求贯穿全部九个机制。
</Answer>

**问题 2**：一个 Node.js HTTP 服务器在高并发下响应变慢，请描述系统化的排查思路。

<Answer>
分层排查：①事件循环延迟——monitorEventLoopDelay 检测 p99，>10ms 有同步阻塞，CPU Profile 找热点（JSON.parse/正则/循环），拆到 worker_threads 或分块 setImmediate。②I/O 瓶颈——数据库慢查询/外部 API 超时/同步 fs。调大 UV_THREADPOOL_SIZE。③内存——process.memoryUsage() 看 heapUsed 是否持续增长（泄漏导致 GC 频繁 STW），Heap Snapshot 找泄漏。④连接数——fd 是否耗尽（lsof），调高 ulimit -n 或 cluster。⑤CPU——单核打满用 cluster 扩展多核。⑥网络——TCP 连接队列溢出调 somaxconn。先量后改：先监控定位瓶颈层再针对性优化。
</Answer>
</Exercises>
