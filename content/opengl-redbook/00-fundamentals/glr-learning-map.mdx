## 直觉起点：本体系以第 9 版为基线

这里核对的是 **OpenGL Programming Guide: The Official Guide to Learning OpenGL, Version 4.5 with SPIR-V, 9th Edition**。官方目录共有 12 章，既包括基础绘制、片段操作、纹理、帧缓冲、光照与阴影，也包括过程纹理、细分着色器、几何着色器、内存模型和计算着色器。

因此，“学完 VAO + GLSL + texture 就等于学完红宝书”是不成立的。OpenGL 4.5 的核心难点不是记住多少函数，而是维护四份合同：对象生命周期、状态归属、阶段接口和内存可见性。

是命令生效的环境，不是窗口本身。

## 一条统一执行模型

### 对象与状态：命令究竟修改谁

传统绑定式 API 先把对象放到 target，再修改“当前绑定对象”；Direct State Access（DSA）则在调用中直接给出对象名。两者最终修改相同类型的对象状态，但 DSA 能减少隐藏依赖。

```cpp
GLuint buffer = 0;
glCreateBuffers(1, &buffer);
glNamedBufferStorage(buffer, bytes, initialData,
                     GL_DYNAMIC_STORAGE_BIT | GL_MAP_WRITE_BIT);

GLuint vao = 0;
glCreateVertexArrays(1, &vao);
glVertexArrayVertexBuffer(vao, 0, buffer, 0, sizeof(Vertex));
glEnableVertexArrayAttrib(vao, 0);
glVertexArrayAttribFormat(vao, 0, 3, GL_FLOAT, GL_FALSE, offsetof(Vertex, pos));
glVertexArrayAttribBinding(vao, 0, 0);
```

这段 DSA 配置把 buffer、binding index、attribute format 三个身份写在调用中。VAO 记录的是“如何取顶点”和元素缓冲绑定；它不拥有 VBO 数据，也不会复制顶点。

### 图形管线：阶段接口必须逐段闭合

顶点进入 vertex shader 后，可以经过 tessellation control/evaluation 和 geometry shader，再进入裁剪、透视除法、viewport、rasterization 与 fragment shader。随后才是 scissor、stencil、depth、blending 等逐片段操作。

必须在每一段闭合。一个简化的屏幕坐标关系是：

$$
\mathbf p_{ndc}=\frac{\mathbf p_{clip}.xyz}{\mathbf p_{clip}.w},
\qquad
x_w=x_0+\frac{w_v}{2}(x_{ndc}+1).
$$

裁剪发生在齐次裁剪空间，不能先除以 $w$ 再用普通三维线段规则替代。背面剔除依据窗口空间绕序；深度测试则比较光栅化产生的样本深度与深度附件。

### 计算与内存：执行完成不等于结果可见

compute shader 不经过图元装配和光栅化。一次 dispatch 产生多个 work group，每组包含多个 invocation；组内可共享 `shared` 内存，组间没有一次 dispatch 内的全局栅栏。

```cpp
glUseProgram(computeProgram);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 0, particleSsbo);
glDispatchCompute(groupCount, 1, 1);

// 下一条绘制把同一存储作为顶点输入，必须声明后续消费者。
glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT |
                GL_VERTEX_ATTRIB_ARRAY_BARRIER_BIT);
glUseProgram(drawProgram);
glBindVertexArray(particleVao);
glDrawArrays(GL_POINTS, 0, particleCount);
```

要按生产者和消费者选择位。CPU 读取还可能需要 fence、映射规则或显式等待，不能用 `glMemoryBarrier` 替代所有同步。

的总调用数由三维组数与 `local_size` 相乘：

$$
N_i=\text{numWorkGroups}_i\times\text{workGroupSize}_i,
\qquad i\in\{x,y,z\}.
$$

## 小结

第 9 版红宝书的完整主线是：在上下文中创建对象与状态，用 shader 和 drawing command 驱动图形阶段，经坐标/图元/片段操作写入纹理或 framebuffer，再用内存模型连接 transform feedback、SSBO、compute 与后续消费者。十二章共享的不是一组函数清单，而是一套可验证的执行与可见性合同。
