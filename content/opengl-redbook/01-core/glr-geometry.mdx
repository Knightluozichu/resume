## 直觉：绘制命令只提供“如何取数和组装”

OpenGL 不知道一个 buffer 里存的是网格。VAO 描述字节如何成为 attribute，draw command 指定索引范围、实例数和图元拓扑；随后 shader 与固定阶段才把输入变成可裁剪、可光栅化图元。

先预测：EBO 已正确上传，但在绑定另一个 VAO 后调用 `glDrawElements` 读到错误索引，最可能是 EBO 内容损坏还是 VAO 记录的 element-buffer binding 不同？先检查后者，因为元素缓冲绑定属于 VAO 状态。

<Term def="由 VAO 中的 attribute format、binding index、buffer、offset、stride 和 divisor 共同定义，把原始字节解释为顶点属性的合同">顶点规格</Term>是官方 Drawing with OpenGL 的中心，而不只是一次 `glVertexAttribPointer`。

## Buffer、VAO 与顶点取数

现代 DSA 把“attribute 使用哪个 binding”与“binding 读取哪个 buffer”分开，便于多个属性共享交错步长，也便于只替换 buffer/offset。

```cpp
glCreateVertexArrays(1, &vao);
glVertexArrayVertexBuffer(vao, 0, vertexBuffer, 0, sizeof(Vertex));
glEnableVertexArrayAttrib(vao, 0);
glVertexArrayAttribFormat(vao, 0, 3, GL_FLOAT, GL_FALSE, offsetof(Vertex, position));
glVertexArrayAttribBinding(vao, 0, 0);
glVertexArrayElementBuffer(vao, indexBuffer);
```

<Term def="保存顶点属性启用、格式到 binding 的映射、binding 的 buffer/offset/stride/divisor 以及元素缓冲绑定的容器对象">VAO</Term>不复制 VBO/EBO 数据。对顶点索引 $v$、实例索引 $i$，divisor 为 $d$ 的实例属性元素近似取自：

$$
k=\begin{cases}v,&d=0\\\lfloor i/d\rfloor,&d>0\end{cases},
\qquad address=base+offset+k\cdot stride.
$$

整数属性应使用 `glVertexArrayAttribIFormat`，double 使用 `LFormat`；错误地用浮点 format 可能产生转换或归一化，而不是按位保留整数。

## 图元与绘制命令

`glDrawArrays` 用隐式连续顶点序号；`glDrawElements` 从 VAO 的元素缓冲读取索引；base vertex 给索引加偏移；instanced 版本增加实例域；indirect 版本从 GPU buffer 读取参数。

```cpp
struct DrawElementsIndirectCommand {
  GLuint count;
  GLuint instanceCount;
  GLuint firstIndex;
  GLint  baseVertex;
  GLuint baseInstance;
};

glBindBuffer(GL_DRAW_INDIRECT_BUFFER, commandBuffer);
glMultiDrawElementsIndirect(GL_TRIANGLES, GL_UNSIGNED_INT,
                            nullptr, drawCount,
                            sizeof(DrawElementsIndirectCommand));
```

<Term def="给定图元模式、顶点或索引范围、实例域及可选基址，触发顶点取数和图元装配的命令">绘制命令</Term>不会自动检查索引是否越过 buffer 存储。primitive restart 可在 strip 中用特殊索引断开图元，但 restart index 必须与索引类型和模式一致。

## 观察、剔除与齐次裁剪

顶点阶段输出 `gl_Position` 的 clip coordinates。规范裁剪体满足：

$$
-w_c\le x_c\le w_c,\quad -w_c\le y_c\le w_c,\quad -w_c\le z_c\le w_c.
$$

因此裁剪应在除以 $w$ 之前处理齐次边界。culling 通常在图元装配后依据窗口空间 winding 排除正/背面；clipping 则会产生新顶点。用户裁剪距离可由 `gl_ClipDistance[]` 输出。

观察矩阵是摄像机世界变换的逆。若摄像机刚体变换为 $C=[R\;t]$，则：

$$
V=C^{-1}=\begin{bmatrix}R^T&-R^Tt\\0&1\end{bmatrix}.
$$

把 view 当作“移动世界”是实现直觉，数学合同仍是坐标系逆变换。

## Transform feedback：在光栅化前捕获

<Term def="在顶点处理最后一个活动阶段之后，把指定 varying 顺序写入缓冲，可选择关闭 rasterization 的捕获机制">Transform feedback</Term>适合验证变换结果、流式几何和某些粒子更新。链接前指定捕获 varying，或使用显式布局；开始捕获时 primitive mode 必须与输出拓扑兼容。

捕获缓冲与输入缓冲重叠可能形成未定义反馈。常用 ping-pong：A 读 B 写，下一轮交换。若后续命令消费结果，还需遵守命令和内存可见性合同。

```cpp
const char* varyings[] = {"tf.position", "tf.velocity"};
glTransformFeedbackVaryings(program, 2, varyings, GL_INTERLEAVED_ATTRIBS);
glLinkProgram(program);

glEnable(GL_RASTERIZER_DISCARD);
glBeginTransformFeedback(GL_POINTS);
glDrawArrays(GL_POINTS, 0, particleCount);
glEndTransformFeedback();
glDisable(GL_RASTERIZER_DISCARD);
```

## Tessellation：patch、TCS 与 TES

输入 `GL_PATCHES` 后，每个 patch 由 `glPatchParameteri(GL_PATCH_VERTICES, n)` 指定控制点数。<Term def="按 patch 执行、读取控制点并输出控制点属性以及 inner/outer tessellation levels 的可选阶段">细分控制着色器</Term>（TCS）决定细分密度；不同 invocation 写各自输出，跨 invocation 依赖需 `barrier()`。

固定细分器根据 level 生成参数域坐标；<Term def="对细分器产生的三角形、四边形或 isoline 参数坐标求值，并写出最终 clip position 的必需阶段">细分求值着色器</Term>（TES）在域内插值或计算曲面。相邻 patch 的共享边必须给出一致 outer level，否则出现裂缝；fractional spacing 只能缓解 level 变化跳动，不能修复不一致边合同。

以三角域重心坐标 $(u,v,w)$ 为例：

$$
u+v+w=1,\qquad P(u,v,w)=uP_0+vP_1+wP_2.
$$

位移贴图应在 TES 中基于一致空间法线/切线求值，并重新评估细分后法线，而不是把低模顶点法线盲目复制到所有新点。

## Geometry shader 与 layered rendering

geometry shader 每次接收一个完整输入图元，可以输出零到多个图元，并用 `EmitVertex`/`EndPrimitive` 控制流。它可写 `gl_Layer` 把图元送往 texture array/cubemap 的不同层，适合一次处理少量层的 shadow/cubemap 任务。

<GlrProgrammableGeometryDiagram />

geometry shader 的放大率和串行化压力可能成为瓶颈。只为复制同一网格应优先 instancing；大规模生成/剔除可考虑 compute + indirect draw；规则曲面细分使用 tessellation。选择依据是输入域、输出拓扑、同步和实测，而不是“阶段越多越高级”。

## 常见误区

<Callout type="trap">
**现象 →** 切换 VAO 后索引绘制异常，却反复重传 EBO。
**原因 →** 忘记 element-buffer binding 是 VAO 状态。
**修法 →** 对实际 draw 绑定的 VAO 查询元素缓冲和 attribute/binding 配置，再验证索引范围。
</Callout>

<Callout type="trap">
**现象 →** 相邻细分 patch 出现裂缝。
**原因 →** 两侧独立计算共享边 outer level，量化或视距输入不同。
**修法 →** 用共享边的规范化 key/函数计算相同 level，并用线框和边 id 可视化验收。
</Callout>

<Callout type="trap">
**现象 →** 为批量复制网格加入 geometry shader 后反而变慢。
**原因 →** 用图元放大阶段承担纯实例复制，增加输出和调度瓶颈。
**修法 →** 先比较 instancing；只有需要逐图元拓扑变换或 layered routing 时才保留 geometry shader。
</Callout>

## 练习

<Exercises>

**问题 1：为什么一个交错 VBO 可以被多个 attribute 正确读取？**

<Answer>
VAO 把每个 attribute 的 format/relative offset 映射到 binding，binding 再保存 buffer、base offset、stride 和 divisor。地址由这两层共同计算，不是 attribute location 直接等于 buffer 槽。
</Answer>

**问题 2：设计 transform feedback 的 ping-pong 粒子验收。**

<Answer>
准备 A/B 两组缓冲，第一帧 A 输入 B 捕获，下一帧交换；开启 rasterizer discard，捕获位置/速度。用 CPU 更新少量粒子作为 oracle，检查计数、首尾值和越界保护，并在转为绘制输入前满足可见性合同。
</Answer>

**问题 3：何时选择 TCS/TES、geometry、instancing 或 compute？**

<Answer>
规则 patch 连续求值用 tessellation；少量逐图元拓扑改变或 layered routing 用 geometry；同网格多对象用 instancing；大规模任意生成、剔除并生成 indirect commands 用 compute。最后以边界正确性和 GPU 时间确认。
</Answer>

</Exercises>

## 小结

几何路径从 VAO 顶点规格和 drawing command 开始，经观察、culling、homogeneous clipping 和可选 transform feedback，再由 tessellation/geometry 改变细节或拓扑。每一层都要明确输入域、输出域和边界；API 能执行不代表索引、共享边或阶段选择正确。
