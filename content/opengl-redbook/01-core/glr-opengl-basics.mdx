## 直觉引入

OpenGL就像驾驶汽车——你不需要知道引擎内部怎么工作，但需要知道方向盘(状态设置)和油门(绘制命令)怎么用。OpenGL是状态机：设置当前着色器、纹理、混合模式等状态，然后发出绘制命令。

## 概念讲解

<Term def="OpenGL状态的集合，包含所有当前设置">OpenGL上下文</Term><Term def="通过设置状态影响后续操作的计算模型">状态机</Term><Term def="移除所有废弃API的现代OpenGL规范">Core Profile</Term><Term def="GLFW创建窗口和上下文，GLAD加载函数指针">GLAD/GLFW</Term>

### OpenGL初始化流程
1. GLFW初始化并创建窗口 2. 设置OpenGL版本(3.3+ Core) 3. 创建上下文 4. GLAD加载函数 5. 设置视口

### 状态机模型
设置状态->绘制->设置新状态->绘制。状态包括着色器、纹理、混合、深度测试等。减少状态切换是性能优化关键。

## 代码对照

```cpp
int main() {
    glfwInit();
    glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);
    glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 3);
    glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);
    GLFWwindow* window = glfwCreateWindow(800, 600, "OpenGL", NULL, NULL);
    glfwMakeContextCurrent(window);
    gladLoadGLLoader((GLADloadproc)glfwGetProcAddress);
    glViewport(0, 0, 800, 600);
    while(!glfwWindowShouldClose(window)) {
        glClearColor(0.2f, 0.3f, 0.3f, 1.0f);
        glClear(GL_COLOR_BUFFER_BIT);
        glfwSwapBuffers(window);
        glfwPollEvents();
    }
    glfwTerminate();
}
```

macOS需要FORWARD_COMPAT标志。渲染循环中先清空再绘制最后交换缓冲。

## 常见误区

<Callout type="trap">
**现象 →** 不检查GLAD加载是否成功。
**原因 →** 默认加载会成功。
**修法 →** gladLoadGLLoader可能失败。应检查返回值，失败时调用OpenGL函数会段错误。
</Callout>

<Callout type="trap">
**现象 →** 在渲染循环中频繁设置相同状态。
**原因 →** 每次绘制前都设置所有状态。
**修法 →** 状态切换有开销。相同状态物体应批量绘制(Sorting by state)。
</Callout>

## 练习

<Exercises>
**问题**：什么是OpenGL上下文？

<Answer>
OpenGL上下文是状态集合，包含当前着色器、纹理、缓冲区等所有OpenGL状态。所有操作在当前上下文中进行。
</Answer>

**问题**：为什么macOS需要FORWARD_COMPAT标志？

<Answer>
macOS的OpenGL实现只支持Core Profile且要求前向兼容。FORWARD_COMPAT移除所有已废弃功能。
</Answer>
</Exercises>
