## 直觉引入

着色器就像GPU上的小程序——顶点着色器是「位置变换器」，片段着色器是「上色器」。它们用GLSL编写，编译链接后运行在GPU上，每帧为每个顶点/片段执行一次。

## 概念讲解

<Term def="OpenGL着色器语言，类C语法，运行在GPU上">GLSL</Term><Term def="逐顶点执行的着色器，负责坐标变换">顶点着色器</Term><Term def="逐片段执行的着色器，计算最终颜色">片段着色器</Term><Term def="全局只读变量，CPU设置后所有顶点/片段共享">Uniform</Term>

### GLSL基础
变量类型：vec3/vec4/mat4/sampler2D。限定符：in(输入)、out(输出)、uniform(全局)。

### 着色器生命周期
编写GLSL->glCreateShader->glCompileShader->glCreateProgram->glAttachShader->glLinkProgram->glUseProgram

### 数据传递
顶点着色器in<-顶点属性，out->片段着色器in。uniform由CPU设置。gl_Position是特殊输出。

## 代码对照

```glsl
// 顶点着色器
#version 330 core
layout(location = 0) in vec3 aPos;
layout(location = 1) in vec3 aColor;
out vec3 vertexColor;
uniform mat4 mvp;
void main() {
    gl_Position = mvp * vec4(aPos, 1.0);
    vertexColor = aColor;
}
// 片段着色器
#version 330 core
in vec3 vertexColor;
out vec4 FragColor;
void main() {
    FragColor = vec4(vertexColor, 1.0);
}
```

layout(location=N)指定顶点属性位置。uniform由CPU通过glUniform设置。out变量自动插值传递到下一阶段。

## 常见误区

<Callout type="trap">
**现象 →** 不检查着色器编译错误。
**原因 →** 编译失败不报异常。
**修法 →** 必须用glGetShaderiv检查GL_COMPILE_STATUS，用glGetShaderInfoLog获取错误信息。
</Callout>

<Callout type="trap">
**现象 →** 在着色器中使用if/else分支。
**原因 →** 逻辑需要条件判断。
**修法 →** GPU是SIMD架构，分支(warp divergence)导致同warp内所有线程执行所有分支。用mix/step/clamp替代。
</Callout>

## 练习

<Exercises>
**问题**：GLSL中in/out/uniform的区别？

<Answer>
in是输入(来自上一阶段)，out是输出(传给下一阶段)，uniform是CPU设置的全局只读常量。顶点着色器out自动插值为片段着色器in。
</Answer>

**问题**：着色器编译链接的完整步骤？

<Answer>
glCreateShader->glShaderSource->glCompileShader->检查错误->glCreateProgram->glAttachShader->glLinkProgram->检查链接->glUseProgram
</Answer>
</Exercises>
