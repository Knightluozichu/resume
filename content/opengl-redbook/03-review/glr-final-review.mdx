## 直觉：整书完成等于合同闭环，不等于 API 都调用过

第 9 版十二章可以收束为五个问题：命令在哪个 context 中解释？shader 阶段怎样连接？图元/片段怎样产生附件样本？资源怎样布局和采样？写入何时对下一消费者可见？

先预测：项目图像正确运行十分钟后才偶发花屏，更应先怀疑固定光照公式还是资源复用/同步？优先检查后者，并用帧序号、segment fence 和 barrier 访问图证明。

<Term def="把对象、状态、阶段接口、资源布局、访问顺序和输出期望写成可检查前置条件与后置条件的渲染设计方式">渲染合同</Term>让调试从猜现象变成定位第一处违约。

## 十二章验收矩阵

1. **Introduction**：记录实际版本/profile、当前 context、DSA 对象标签和 debug output；
2. **Shader Fundamentals**：保存 GLSL/SPIR-V 身份、compile/link/pipeline validate 日志和接口反射；
3. **Drawing**：验证 VAO binding/format、索引范围、primitive、instance 与 indirect command；
4. **Color/Pixels/Fragments**：逐项测试 depth/stencil/blend/mask、MSAA 样本和像素读回；
5. **Viewing/Culling/Clipping/Feedback**：CPU 比较变换、裁剪边界、绕序和 transform feedback；
6. **Textures/Framebuffers**：格式、view/sampler、mip、FBO completeness、MRT 和 resolve；
7. **Light/Shadow**：空间、法线矩阵、分项光照、shadow depth/bias/PCF；
8. **Procedural Texturing**：noise/stripe 的 footprint、限频、bump/normal 语义；
9. **Tessellation**：patch、TCS level、TES 域求值和共享边无裂缝；
10. **Geometry**：geometry shader 输入/输出计数、layered rendering 与替代路径比较；
11. **Memory**：std140/std430 反射、SSBO/atomic、memory barrier、fence 与映射所有权；
12. **Compute**：work group、dispatch 越界、shared 归约和后续 draw 消费。

<Term def="把官方目录每个单元映射到实现位置、可观察中间量、失败注入与通过判据的表格">证据矩阵</Term>防止总复习只重复名词。

## 项目 A：可诊断离屏渲染器

项目 A 绘制带纹理/过程材质、直接光和 shadow map 的实例场景，使用 HDR MRT + depth/stencil + MSAA，最后 resolve、合成透明并读回关键像素。

```cpp
beginDebugGroup("frame");
updatePersistentFrameRing(frameData);
renderShadowMap(scene, light);
renderOpaqueMrt(scene);          // color + normal + object id + depth
renderTransparentPremultiplied(scene);
resolveMsaaAndToneMap();
enqueuePixelProbeReadback();
endDebugGroup();
```

每个 pass 保存 named FBO attachment 表、program/pipeline、VAO、draw count 和 timer query。调试模式可显示 world normal、N·L、shadow coordinate、mip LOD、sample coverage 和 object ID。

对 HDR 颜色 $C$，一个可测的简单 tone-map 是：

$$
C_{mapped}=\frac{C}{1+C},\qquad C_{display}=encode_{sRGB}(C_{mapped}).
$$

参考图必须固定曝光、颜色空间、分辨率和驱动容差；否则截图差异无法归因。

## 项目 B：GPU 驱动粒子与可见性

项目 B 用 compute 更新粒子 SSBO，组内归约产生统计，原子分配可见项，写 indirect command，再以 vertex/geometry 或 instanced path 绘制。可选 transform feedback 路径作为阶段对照。

```cpp
dispatchParticleUpdate(readSsbo, writeSsbo, count);
dispatchVisibilityAndCommands(writeSsbo, indirectBuffer);
glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT |
                GL_COMMAND_BARRIER_BIT |
                GL_VERTEX_ATTRIB_ARRAY_BARRIER_BIT);
drawParticlesIndirect(indirectBuffer);
insertFenceForRingSegment();
swap(readSsbo, writeSsbo);
```

<Term def="为避免同一存储在一轮中既作输入又被覆盖，使用两份资源交替承担只读源和写入目标的所有权模式">Ping-pong 资源</Term>只解决读写重叠，不自动建立 dispatch 到 draw 的可见性。

<GlrCapstoneDiagram />

粒子更新用 CPU 对前 32 项作 oracle；总数、存活数、可见数和 draw instance count 必须满足：

$$
0\le N_{draw}=N_{visible}\le N_{alive}\le N_{capacity}.
$$

压力测试覆盖 count 非 local-size 整倍数、零粒子、满容量、原子溢出保护、GPU 延迟下 ring 回绕与窗口 resize。

## 故障定位顺序

空白帧按环境 → program → draw → fragment ops → attachment/readback 排查；几何错误按 vertex fetch → transform → clip/assemble → tessellation/geometry 排查；偶发旧数据按 producer → barrier → consumer → fence/ownership 排查。

```cpp
struct FrameEvidence {
  uint64_t frameId;
  Hash shaderSet;
  Hash stateSnapshot;
  uint32_t submittedDraws, visibleItems;
  double cpuSubmitMs, gpuFrameMs;
  std::vector<DebugMessage> messages;
  ImageHash referenceOutput;
};
```

<Term def="在同一帧身份下关联状态快照、调试消息、计数器、CPU/GPU 时间和输出哈希的一组诊断记录">帧证据包</Term>使跨帧偶发问题可重放和比较。

## 性能验收不是正确性替代品

先通过数值/图像/同步正确性，再测性能。固定设备、驱动、分辨率、场景和相机，预热后异步采集 CPU submit、各 GPU pass、pipeline statistics；报告中位数、P95 和最坏帧，并标出 query 是否导致等待。

<Term def="在功能与参考输出保持一致的前提下，对目标设备和工作负载规定 CPU/GPU 时间、内存、吞吐及高分位波动上限">性能预算</Term>必须带适用条件。不同算法若输出质量不同，不能只比较毫秒。

## 常见误区

<Callout type="trap">
**现象 →** 十二章都出现过 API 名称，就宣布全书覆盖。
**原因 →** 把关键词存在当成概念、实现和验证完整。
**修法 →** 每章必须在证据矩阵中有实现、观测点、失败注入和通过判据。
</Callout>

<Callout type="trap">
**现象 →** 为了通过参考图，把 barrier 全改成 ALL、每帧 glFinish。
**原因 →** 用全局串行掩盖资源依赖和所有权错误。
**修法 →** 画精确访问图，选择匹配 barrier/fence；同步正确后再检查并行性能。
</Callout>

<Callout type="trap">
**现象 →** 只保存最终截图，偶发问题无法复现。
**原因 →** 缺少帧身份、状态、消息、计数和中间附件。
**修法 →** 建立帧证据包，异常时冻结 ring segment、command buffer 与关键 attachment。
</Callout>

## 练习

<Exercises>

**问题 1：项目 A 如何同时验收第 4、6、7、8 章？**

<Answer>
用 MRT/depth/stencil/MSAA 验收片段操作；纹理 view/sampler/FBO/resolve 验收资源；分项 lighting + shadow depth/bias/PCF 验收光影；带限 noise/bump 在不同距离和斜视下验收过程纹理。
</Answer>

**问题 2：项目 B 出现 visible count 正确但 indirect draw 为零，查什么？**

<Answer>
先检查 command layout/offset/stride 和写入目标，再检查 compute 到 indirect consumer 的 COMMAND barrier、draw buffer binding 与 instanceCount 字段；用读回/调试 SSBO 对同一帧 command 做快照。
</Answer>

**问题 3：什么证据足以宣布本书完成？**

<Answer>
官方十二章均有通过的单元探针；两个综合项目的正常/边界/压力场景通过数值与参考图；无高严重度调试消息和同步复用错误；目标设备性能预算通过；章节与整书评分均达到门槛。
</Answer>

</Exercises>

## 小结

红宝书的最终能力不是记住函数，而是能把一次帧拆成环境、程序、绘制、片段、资源和内存合同，并为每层保留证据。官方十二章只有在单元探针、综合项目、压力回归和性能预算全部闭环时才算掌握。
