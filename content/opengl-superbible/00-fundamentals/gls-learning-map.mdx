## 直觉引入

超级宝书就像一本实践手册——从写第一个三角形程序开始，逐步深入着色器管线、顶点处理、片段着色，再到纹理映射、缓冲管理、几何着色器，最终学习性能优化。每章配完整代码，实践驱动。

全书分四大板块：**基础**(学习地图、第一个程序)、**核心**(着色器管线、顶点处理)、**高级**(片段着色、纹理映射、缓冲对象、几何着色器、性能)、**复习**(总复习)。

## 代码对照

```cpp
// 第一个OpenGL程序核心结构
int main() {
    // 1. 初始化
    glfwInit();
    GLFWwindow* window = glfwCreateWindow(800, 600, "OpenGL", NULL, NULL);
    glfwMakeContextCurrent(window);
    gladLoadGLLoader((GLADloadproc)glfwGetProcAddress);
    // 2. 着色器+VBO/VAO
    GLuint shader = createShader(vertexSrc, fragmentSrc);
    GLuint VAO = createTriangleVAO();
    // 3. 渲染循环
    while(!glfwWindowShouldClose(window)) {
        glClear(GL_COLOR_BUFFER_BIT);
        glUseProgram(shader);
        glBindVertexArray(VAO);
        glDrawArrays(GL_TRIANGLES, 0, 3);
        glfwSwapBuffers(window);
        glfwPollEvents();
    }
}
```

超级宝书从第一个程序出发，逐步深入。每个技术点配完整可运行代码。

## 常见误区

<Callout type="trap">
**现象 →** 只看不练，代码当作阅读材料。
**原因 →** 理解了概念就行。
**修法 →** 图形学是工程学科。每个概念都必须用代码验证。从第一个三角形开始逐步增加功能：变换→纹理→光照→阴影。
</Callout>

<Callout type="trap">
**现象 →** 跳过基础章节直接看高级。
**原因 →** 基础太简单。
**修法 →** 高级章节依赖基础概念(VBO/VAO/着色器)。跳过基础会导致高级章节的代码看不懂。按顺序学习每章实践。
</Callout>

<Exercises>
**问题**：超级宝书和红宝书的学习方式有什么不同？

<Answer>
红宝书更偏API参考(按功能组织)，超级宝书更偏教程实践(按项目递进)。红宝书适合查阅，超级宝书适合系统学习。两者互补。
</Answer>

**问题**：如何用超级宝书做项目驱动学习？

<Answer>
1)跟着第一个程序搭建环境 2)逐步加功能(变换→纹理→光照) 3)每章学完实现一个小demo 4)最后整合成完整渲染器 5)性能章节作为优化进阶。
</Answer>
