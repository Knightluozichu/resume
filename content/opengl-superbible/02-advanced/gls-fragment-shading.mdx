## 为什么片段输出不等于最终像素

光栅化生成的是（fragment），不是已经写入屏幕的 pixel。一个可能接收多个图元的片段；多重采样时，每个像素还有多个。Fragment shader 输出仍要经过逐片段测试、混合、格式转换和写掩码，才可能修改 framebuffer attachment。

<GlsFragmentShadingDiagram />

旧章把顺序固定成“shader → depth → stencil → blend”，又把 blend 结果称为最终屏幕颜色。更准确的模型是：OpenGL 定义各状态的可观察结果；实现只要保持语义，可以提前执行 depth/stencil、并行处理 coverage，或合并多个 sample。离屏 framebuffer 的输出甚至完全不会立即显示。

若像素数为 $P$、每像素 sample 数为 $S$，多重采样 attachment 的样本容量量级为：

$$
N_{samples}=P\times S
$$

但 fragment shader invocation 数不一定等于 $P\times S$，还取决于覆盖、sample shading、early rejection 与 helper invocations。

## Fragment Shader 的输入、输出与调用粒度

可读取插值接口和内建值。`gl_FragCoord` 给出 window x/y、深度 z 和与插值相关的 reciprocal w；`gl_FrontFacing` 区分正反面；点图元提供 `gl_PointCoord`；多重采样可提供 `gl_SampleID`、`gl_SamplePosition` 与 `gl_SampleMaskIn`。

<GlsFragmentInvocationDiagram />

屏幕空间导数 `dFdx`、`dFdy` 在相邻 invocation 组上估计，常用于隐式纹理 LOD 与法线扰动。标量 $f$ 的梯度近似为：

$$
\nabla f\approx\left(\frac{\partial f}{\partial x},
\frac{\partial f}{\partial y}\right)
=\left(\operatorname{dFdx}(f),\operatorname{dFdy}(f)\right)
$$

实现可启动。因此“片段 shader 执行次数就是覆盖像素数”不成立。

Fragment outputs 通过 location 映射到 draw buffer。一个 shader 可输出多个颜色值形成（MRT）；输出类型必须与 attachment 的整数/浮点类别兼容。`discard` 终止当前 invocation 对 framebuffer 的更新，适合硬边 cutout，但并非半透明混合的替代。

```glsl
#version 450 core
layout(location = 0) out vec4 outAlbedo;
layout(location = 1) out vec4 outNormalDepth;

in VS_OUT { vec3 normal; vec2 uv; } fsIn;
uniform sampler2D albedoMap;

void main() {
    vec4 albedo = texture(albedoMap, fsIn.uv);
    if (albedo.a < 0.5) discard; // hard cutout, not translucent blend
    outAlbedo = albedo;
    outNormalDepth = vec4(normalize(fsIn.normal) * 0.5 + 0.5,
                          gl_FragCoord.z);
}
```

官方 `fragcolorfrompos` 直接使用 `gl_FragCoord` 生成颜色；`programinfo` 同时声明浮点和整数 fragment output，展示 output location/type 属于 program interface；`shapedpoints` 用 `gl_PointCoord` 与 `discard` 把方点裁成圆环或其他形状。

## Early Tests、Stencil、Depth 与写掩码

包含 scissor、stencil、depth 等状态。模板测试由比较函数、reference、value mask 和三组操作组成：stencil fail、depth fail、depth pass；深度测试把 source depth 与已有 attachment depth 按 `GL_LESS`、`GL_LEQUAL` 等函数比较。

<GlsPerFragmentTestsDiagram />

深度通过条件可抽象为：

$$
\operatorname{pass}_{depth}=F(z_{src},z_{dst})
$$

即使测试通过，`glDepthMask(GL_FALSE)` 仍可禁止深度写；`glColorMask` 与 stencil write mask 同理。测试“是否通过”和存储“哪些位更新”是两个问题。

可能减少昂贵 shader 工作，但 `discard`、image/SSBO side effects、`gl_FragDepth` 和 sample controls 会影响实现可提前做多少。不能写成“discard 必然禁用 Early-Z”。`layout(early_fragment_tests) in;` 可要求测试在 shader 前发生；此时 shader 写出的 depth 不参与该测试。若只单调增大或减小 depth，可使用 conservative depth layout 帮助实现保留优化。

片段工作量可粗略拆成：

$$
N_{shader}=N_{covered}-N_{earlyRejected}+N_{helpers}+N_{extraSampleShading}
$$

这仍是分析模型，不是精确硬件计数。应结合 samples-passed query、pipeline statistics 和 GPU timer 验证。

## Blend Equation：Straight 与 Premultiplied 不能混用

的一般形式为：

$$
\mathbf C_{out}=E
\left(F_s\mathbf C_s,F_d\mathbf C_d\right)
$$

最常见 straight alpha 使用：

$$
\mathbf C_{out}=\alpha_s\mathbf C_s+(1-\alpha_s)\mathbf C_d
$$

若纹理和 shader 输出已经是，则应使用：

$$
\mathbf C_{out}=\mathbf C_s+(1-\alpha_s)\mathbf C_d
$$

<GlsBlendEquationDiagram />

透明表面通常保持 depth test、关闭 depth write，并按需要排序；straight alpha 的普通 over 操作与顺序有关。加法粒子可用 `ONE, ONE`，某些用途可用 `glBlendFuncSeparate` 或 `glBlendEquationSeparate` 独立处理 alpha。多个 MRT attachment 还能使用 indexed blend state。Integer attachment 不执行普通 floating-point blending，必须选择匹配的写入策略。

官方 `blendmatrix` 遍历 source/destination factors 直接比较结果，`starfield` 使用 additive `ONE, ONE`。这比记住“透明物体固定用一组参数”更能揭示 source、destination 与 equation 的角色。

## Framebuffer、Attachments 与 Off-Screen Rendering

（framebuffer）本身不保存 texel；attachment 才是 texture 或 renderbuffer storage。默认 framebuffer 由窗口系统提供，应用创建的 FBO 支持（off-screen rendering）。

<GlsFramebufferDiagram />

建立 FBO 的证据链是：创建 attachment storage，附加到 attachment points，用 `glDrawBuffers` 建立 fragment output location 到 color attachment 的 routing，检查 framebuffer completeness，设置与目标尺寸匹配的 viewport，然后 clear/render。所有启用 draw buffer 指向的 attachment 必须满足完整性规则，multisample attachment 的 sample count 也要兼容。

```cpp
glCreateFramebuffers(1, &fbo);
glCreateTextures(GL_TEXTURE_2D, 1, &color0);
glTextureStorage2D(color0, 1, GL_RGBA16F, width, height);
glCreateTextures(GL_TEXTURE_2D, 1, &color1);
glTextureStorage2D(color1, 1, GL_RGBA8, width, height);
glCreateTextures(GL_TEXTURE_2D, 1, &depth);
glTextureStorage2D(depth, 1, GL_DEPTH_COMPONENT32F, width, height);

glNamedFramebufferTexture(fbo, GL_COLOR_ATTACHMENT0, color0, 0);
glNamedFramebufferTexture(fbo, GL_COLOR_ATTACHMENT1, color1, 0);
glNamedFramebufferTexture(fbo, GL_DEPTH_ATTACHMENT, depth, 0);
const GLenum draws[] = { GL_COLOR_ATTACHMENT0, GL_COLOR_ATTACHMENT1 };
glNamedFramebufferDrawBuffers(fbo, 2, draws);

if (glCheckNamedFramebufferStatus(fbo, GL_FRAMEBUFFER)
    != GL_FRAMEBUFFER_COMPLETE) {
    throw std::runtime_error("incomplete framebuffer");
}
```

官方 `basicfbo` 创建 RGBA8 color texture 与 DEPTH_COMPONENT32F depth texture，先在 512×512 FBO 中渲染，再把 color texture 用于第二 pass；`deferredshading` 通过两个 color attachments 和 depth attachment 构造 G-buffer。这说明离屏结果只是后续输入，不是“最终像素”。

若颜色格式每 sample 为 $b_c$ 字节、深度模板为 $b_d$ 字节，尺寸 $W\times H$、sample 数 $S$，最低 attachment 容量量级为：

$$
B_{FBO}=W\,H\,S\,(b_c+b_d)
$$

MRT 要把所有颜色 attachment 累加；mip levels 和驱动内部布局还会增加实际占用。

## MSAA、Sample Shading 与 Resolve

（MSAA）主要提高边缘 coverage 精度。它不保证 fragment shader 对每个 sample 都执行，也不会自动解决纹理内部、shader 高频信号或透明边缘的所有 aliasing。

<GlsMultisampleDiagram />

启用并设置最小比例 $q$ 时，$S$ sample 像素的最低 invocation 数近似满足：

$$
N_{min}=\left\lceil qS\right\rceil
$$

使用 sample-qualified inputs、`gl_SampleID` 或 `gl_SamplePosition` 也可能触发 per-sample 行为。官方 `sampleshading` 对比关闭与 `glEnable(GL_SAMPLE_SHADING); glMinSampleShading(1.0)`，展示 coverage sample 与 shader frequency 是两个控制维度。

Multisample color attachment 通常要。对线性颜色的简单平均模型是：

$$
\mathbf C_{resolved}=\frac1S\sum_{i=0}^{S-1}\mathbf C_i
$$

实际 resolve 规则受格式和 API 操作约束，可使用 framebuffer blit 或自定义 shader。Alpha-to-coverage 把 alpha 转成 coverage mask，适合 foliage 边缘，但不是普通透明合成。

## Advanced Formats、Point Sprites 与 Getting at Your Image

Attachment internal format 决定精度、范围、转换和可用操作。Normalized formats 把整数存储映射到归一化数；integer formats 要匹配 `ivec/uvec` outputs 且不使用普通 blend；floating formats 支持 HDR 但增加带宽。sRGB attachment 在启用 `GL_FRAMEBUFFER_SRGB` 时对线性 shader 输出做编码，不能先在 shader 手动编码再重复转换。

<GlsFormatReadbackDiagram />

可用局部坐标构造圆形。以中心 $(0.5,0.5)$ 为例，圆内条件为：

$$
\left\lVert\mathrm{gl\_PointCoord}-\begin{pmatrix}0.5\\0.5\end{pmatrix}\right\rVert^2\le r^2
$$

官方 `shapedpoints` 用这一局部坐标和 `discard` 生成不同点形状。

需要明确 read buffer、format、type 和 `GL_PACK_ALIGNMENT`。若每行原始字节为 $R$、pack alignment 为 $A$，行跨度为：

$$
R_{packed}=\operatorname{alignUp}(R,A)
$$

直接 `glReadPixels` 到 CPU 可能等待此前渲染完成；PBO 允许把传输目的放入 buffer，稍后配合 fence 映射，但不会自动消除等待。官方 `bumpmapping` 的截图路径计算对齐行宽、调用 `glReadPixels(GL_BGR, GL_UNSIGNED_BYTE)` 并写 TGA，正好说明 storage format 与 transfer format 并非同一个参数。

```cpp
glBindFramebuffer(GL_READ_FRAMEBUFFER, sourceFbo);
glReadBuffer(GL_COLOR_ATTACHMENT0);
glPixelStorei(GL_PACK_ALIGNMENT, 1);
glBindBuffer(GL_PIXEL_PACK_BUFFER, readbackPbo);
glReadPixels(0, 0, width, height, GL_RGBA, GL_UNSIGNED_BYTE, nullptr);
GLsync ready = glFenceSync(GL_SYNC_GPU_COMMANDS_COMPLETE, 0);
// 后续帧确认 ready，再映射 PBO；不要立刻 map 迫使同步。
```

## 本章回顾

Fragment Processing and the Framebuffer 包含 fragment shader、per-fragment tests、color output、off-screen rendering、antialiasing、advanced formats、point sprites 与 image readback。Shader output 只是 source；测试、blend、write masks、attachment 格式和 sample 状态共同决定存储结果。可复刻原书的标准，是能从状态推导每个 attachment 的结果，从 sample 设置推导容量与最小调用量，并用 completeness、query、timer 和读回证据闭合整条链。
