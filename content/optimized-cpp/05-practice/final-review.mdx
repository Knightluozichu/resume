## 全书回顾

《C++ 性能优化指南》的核心方法论是测量驱动的闭环优化——先建立基线、定位热点，再针对性优化，最后验证提升且无回归。全书五板块围绕这条主线展开：

## 五板块串联

- **性能思维**：建立「测量→分析→优化→验证」的闭环。90/10 法则——聚焦热点，不在非热点上浪费时间。
- **字符串与算法**：`string_view` 零拷贝、`reserve` 预分配、`move`/RVO 转移所有权；算法选择不只看大 O，还要看常数因子和缓存友好性。
- **内存管理**：栈优先于堆、对象池/arena 批量分配、`unique_ptr` 零开销替代 `shared_ptr`。
- **I/O 与并发**：缓冲减少系统调用、批量增大传输量、异步让 I/O 与计算重叠；锁竞争用细粒度锁，false sharing 用 `alignas(64)` 对齐。
- **优化实践**：benchmark 建基线、perf 定位热点、Valgrind 深挖细节，工具链纳入 CI 防回归。

## 低风险高收益的优化优先级

<Term def="性能优化应从低风险高收益入手：算法与数据结构 → 数据布局与缓存 → 内存分配 → 并发">优化优先级</Term>

1. **测量驱动**（前提）：先建基线和热点定位能力
2. **字符串优化**（低风险高收益）：改传参方式、加 `reserve`、确保 `move`
3. **数据结构与算法选择**（低风险高收益）：`vector` 替代 `list`、选对算法
4. **内存分配优化**（中风险高收益）：对象池、`thread_local` 缓冲、`make_shared`
5. **并发与 I/O**（高风险高收益）：单线程极致后再上多核，分段锁/无锁、异步 I/O

## 从「能跑」到「高性能」的路线图

一个 C++ 项目的性能优化应遵循五阶段路线图：

1. **建立测量基础设施**：集成 google-benchmark、配置 perf/Valgrind、CI 回归检测
2. **低垂果实**：字符串优化、数据结构选择、`unique_ptr` 替代 `shared_ptr`
3. **内存与分配优化**：热路径去 `malloc`、数据布局扁平化、减少临时对象
4. **算法与缓存优化**：选对算法、缓存友好布局、SIMD 向量化
5. **并发与 I/O**：单线程极致后上多核、异步 I/O、零拷贝

<Callout type="tip">
核心原则：每阶段都先剖析再动手。优化到「够用」就停——过度优化的代码可维护性差，边际收益递减。把 benchmark 纳入 CI，防止性能随重构流失。
</Callout>

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> 不测量就上多核优化，8 核只比 1 核快 1.5 倍。 <strong>原因 →</strong> 单线程没吃满就并行，只是「把烂代码跑多份」。锁竞争和 false sharing 进一步拖累。 <strong>修法 →</strong> 先在单线程上榨干性能（字符串、算法、内存），确认单线程瓶颈后再上并发。并发是最后手段，不是第一手段。
</Callout>

## 小结与练习

- 全书主线：测量优先 → 从高频操作到内存分配 → 从 I/O 到并发 → 用工具链固化
- 低风险高收益优先：字符串 → 数据结构 → 内存 → 并发
- 五阶段路线图：测量基础设施 → 低垂果实 → 内存优化 → 算法与缓存 → 并发与 I/O
- 每阶段先剖析再动手，优化到「够用」就停，benchmark 纳入 CI 防回归
