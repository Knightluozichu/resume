## 学习目标

- 掌握5 Whys追问法，通过逐层提问穿透表象到根因

## 核心概念

### 根因分析的价值

问题分析告诉我们「问题是什么」，根因分析则回答「问题为什么发生」。治标不治本是组织问题反复出现的常见原因——头痛医头、脚痛医脚，根因不除，问题不断变种重现。根因分析工具的价值在于：穿透表层现象，找到最深层的驱动因素，从源头解决问题。

### 5 Whys 追问法

5 Whys是最简洁的根因分析工具：对每个问题连续追问「为什么」，每一层的答案成为下一层的问题，通常追问5次即可穿透到根因。

**经典示例：**
1. 为什么设备停机了？——电机过载保护触发
2. 为什么电机过载？——轴承润滑不足
3. 为什么润滑不足？——润滑泵未及时维护
4. 为什么未及时维护？——维护计划缺失
5. 为什么维护计划缺失？——**根因：设备管理制度不完善**

### 鱼骨图（石川图）

鱼骨图从4M维度系统化归因：

| 维度 | 含义 | 典型原因 |
|------|------|----------|
| 人（Man） | 人员因素 | 操作失误、技能不足、态度问题 |
| 机（Machine） | 设备因素 | 设备老化、精度下降、维护不足 |
| 料（Material） | 材料因素 | 材料不合格、批次差异、供应不稳 |
| 法（Method） | 方法因素 | 流程缺陷、标准缺失、方法不当 |

### 帕累托图

帕累托图基于80/20法则：80%的问题由20%的原因造成。通过将原因按频次降序排列并绘制累计折线，可以直观识别「关键少数」——优先解决这些原因，投入产出比最高。

### 故障树分析（FTA）

故障树分析从「顶事件」（系统失效）出发，用逻辑门（与门、或门）逐层分解到「底事件」（基本故障），构建故障传播的逻辑树。它适用于安全关键系统和复杂故障场景。

### 根因分析核心逻辑

**表层现象 → 逐层追问（5 Whys） → 系统归因（鱼骨图） → 量化排序（帕累托） → 逻辑分解（故障树） → 定位根因**

## 术语表

| 术语 | 释义 |
|------|------|
| 5 Whys | 连续追问「为什么」穿透到根因的方法 |
| 鱼骨图 | 从4M维度系统化归因的图示工具 |
| 石川图 | 鱼骨图的别称，以发明者石川馨命名 |
| 帕累托图 | 按频次排序并累计的柱状-折线组合图 |
| 80/20法则 | 少数关键原因造成多数问题的规律 |
| 故障树分析 | 用逻辑门从顶事件分解到底事件的方法 |
| 顶事件 | 故障树分析中需要分析的最终故障 |
| 底事件 | 故障树分析中最基本的不可再分故障 |

## 练习题

1. 用5 Whys追问法分析一个你工作中遇到的质量问题，直到找到根因。
2. 鱼骨图的4M维度分别是什么？请为每个维度举出两个典型原因。
3. 帕累托图的80/20法则对资源分配有什么指导意义？
4. 故障树分析与5 Whys在分析逻辑上有什么本质区别？各适用于什么场景？
