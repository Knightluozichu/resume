## 为什么工具不是答案：流程才决定群体怎样思考

第4章 高级套装：提高执行力的12个工具承担 **用12个高级工具连接变革动力、关键主体、系统结构、风险、共同收益、愿景和战略资源配置。** 本课程不复制原书正文、图示或案例，而把出版社公开目录中的工具命题重构为会议合同、参与轨迹、流程实验、失败样本和行动证据。本页逐项覆盖14个目录节点：第4章 高级套装：提高执行力的12个工具、力场分析：思考动力，掌握执行力、利益相关者分析：找出关键人物，实现计划、决策树：不要说“决定不了”、期望与课题的矩阵图：突破课题繁多的头脑风暴、思维系统图：摆脱恶性循环、要素图：解决项目延迟问题、风险评估表：选择最小风险克服危机、双收益矩阵：找出先后顺序的共同点、时光机法：享受构筑愿景的过程、采访英雄：让对方回想起过去的辉煌，重新振作起来、SWOT法：用SWOT法提高战略意识、PPM：用痛苦与喜悦的原则打破现状、小专栏：在公司中开始引导。

引导者的职责不是用工具表演，也不是在团队犹豫时替大家决定，而是让相关信息安全进入、让分歧被准确看见、让收敛标准透明，并把结论转成责任和反馈。一个工具是否合适取决于会议目的、阶段、人数、权力结构、时间、风险与输出；同一个头脑风暴放在决策阶段会延迟收敛，投票放在问题尚未澄清时会快速选错。

## 四个可手算观察指标

以下公式是课程观察工具，不是原书量表。参与覆盖率检查相关成员是否真正进入讨论：

$$
V = N_{participants\ contributing} / N_{participants\ relevant}
$$

发言平衡用归一化熵避免总时长掩盖一人垄断：

$$
B = -\sum_i p_i \log(p_i) / \log(n)
$$

问题清晰率要求关键主张带有事实、边界或验证方式：

$$
C = N_{claims\ testable} / N_{claims\ material}
$$

行动兑现率只计算有负责人、期限且已回访的承诺：

$$
A = N_{actions\ closed} / N_{actions\ committed}
$$

指标必须结合角色、专业相关性和会议阶段解释。发言完全平均不一定理想，专家在特定阶段可以多讲；匿名输入提高覆盖却可能降低追问深度；行动兑现高如果目标错误也没有价值。数字用于暴露问题，不用于给参与者贴人格标签。

## 把工具选择变成可重放会议协议

本单元主链是“识别变化动力 → 纳入关键主体 → 绘制系统与风险 → 形成共同愿景战略 → 落实责任并跟踪”。会前先冻结目的、决策权、阶段、参与者、保密边界、时间盒和输出；再从49个工具中选择能消除当前流程障碍的最小组合。会中记录发言者、信息卡、分类变更、异议、阶段切换和引导者介入；会后保存结论、负责人、期限、依赖与反馈。

三种阶段必须匹配工具。发散探索需要安全、独立输入和多角度；收敛选择需要标准、边界条件、异议和透明筛选；行动落实需要责任、资源、风险与回访。若会议同时要求三者，引导者应显式分段并提示规则切换，不能一边要求大胆想象一边即时批评。

## 最小可重放实现

第一段把会议与工具选择声明为数据：

```ts
type FacilitationContract = {
  unit: string;
  purpose: string;
  phase: "explore" | "converge" | "execute";
  decisionOwner: string;
  selectedTool: string;
  expectedArtifact: string;
};

const contract: FacilitationContract = {
  unit: "opt-23-chapter-04",
  purpose: "动力阻力形成可复核结果",
  phase: "converge",
  decisionOwner: "会前明确的授权角色",
  selectedTool: "力场分析：思考动力，掌握执行力",
  expectedArtifact: "结论、异议、负责人、期限与反馈日期",
};
```

第二段从发言与行动记录计算覆盖和兑现：

```python
def review_meeting(relevant, speakers, committed, closed):
    voice_coverage = len(set(speakers)) / max(len(set(relevant)), 1)
    action_follow_through = closed / max(committed, 1)
    return {
        "voice_coverage": voice_coverage,
        "action_follow_through": action_follow_through,
    }
```

第三段预注册阶段、扰动与拒绝条件：

```yaml
unit: "opt-23-chapter-04"
chain:
  [
    "识别变化动力",
    "纳入关键主体",
    "绘制系统与风险",
    "形成共同愿景战略",
    "落实责任并跟踪",
  ]
phases: [explore, converge, execute]
vary_one: [safety, balance, structure, ownership]
record: [speaker, artifact, dissent, transition, owner, deadline, follow_up]
reject_when:
  [coerced_disclosure, hidden_decision, no_minority_record, owner_missing]
```

代码只固定记录，不替代引导判断。发言分析要保护隐私，沉默可能来自思考方式、专业相关性或文化，而不一定代表压制；需要结合匿名反馈和访谈解释，不能把单个指标变成员工评价。

## 阶段与工具选择矩阵

| 阶段 | 当前障碍             | 适合工具特征           | 常见误用       | 必要产物   |
| ---- | -------------------- | ---------------------- | -------------- | ---------- |
| 进入 | 陌生、紧张、规则不清 | 低风险破冰、基本规则   | 强迫隐私披露   | 共同规则   |
| 发散 | 信息少、视角窄       | 静默输入、多角度、聚类 | 边发散边批评   | 候选与主题 |
| 澄清 | 问题模糊、因果混乱   | 流程、逻辑树、鱼骨图   | 把假设当根因   | 可验证问题 |
| 收敛 | 候选多、标准冲突     | 矩阵、投票、异议       | 票数替代边界   | 选择与理由 |
| 执行 | 无主、阻力、风险     | 4W1H、力场、风险表     | 会议结束即完成 | 责任与回访 |

工具可以组合，但每增加一个工具都增加解释、切换和时间成本。最小充分组合比“把49个都用上”更专业；熟练掌握少数工具、知道何时不用，优于只会复述全部名称。


## 证据包、伦理边界与独立复核

证据包至少保存版次、目录坐标、会议目的、阶段、决策权、参与者与缺席者、权力关系、工具选择理由、基本规则、时间盒、发言分布、匿名输入、阶段产物、分类变更、少数意见、停车场、行动负责人、期限、依赖、风险、回访和最终结果。涉及个人披露、绩效或冲突时要取得同意并限制传播。

独立复核者先根据会前合同判断工具是否匹配阶段，再从记录重算四项指标；随后更换引导者或降低心理安全，检查结论是否稳健。若只有引导者主观复盘、没有产物与行动反馈，或参与者无法安全表达不同意见，不能宣称工具有效。
