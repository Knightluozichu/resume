## 为什么工具不是答案：流程才决定群体怎样思考

后记承担 **把49个工具转成个人练习路线：选择少数高频工具，跨场景实践、复盘介入效果，再逐步扩展工具箱。** 本课程不复制原书正文、图示或案例，而把出版社公开目录中的工具命题重构为会议合同、参与轨迹、流程实验、失败样本和行动证据。本页逐项覆盖1个目录节点：后记。

引导者的职责不是用工具表演，也不是在团队犹豫时替大家决定，而是让相关信息安全进入、让分歧被准确看见、让收敛标准透明，并把结论转成责任和反馈。一个工具是否合适取决于会议目的、阶段、人数、权力结构、时间、风险与输出；同一个头脑风暴放在决策阶段会延迟收敛，投票放在问题尚未澄清时会快速选错。

## 版次、目录与改编合同

本路径依据森时彦、引导工具箱研究会《引导工具箱：解决组织问题的49个工具（修订本·第2版）》，朱彦泽、夏敏、李猛译，电子工业出版社，2023年4月，ISBN 9787121393174。电子工业出版社官方书页列出导论、入门8个工具、初级13个工具、中级16个工具、高级12个工具、每章小专栏与后记，共59个正式目录节点，其中49个为具名引导工具；课程按6个正式单元完整覆盖，另设学习地图与综合复核，共8页。高校馆藏记录交叉确认2023年修订版与ISBN，出版社当前页面显示后续印次日期，不把印次日期误作新版目录。

目录标题用于定位，课程公式、代码、实验与练习是独立教学重构。破冰、身体活动、个人反馈与关系练习需要自愿、隐私、无障碍和退出选项；涉及组织权力、人员评价或战略资源时，引导流程不能取代合法授权与最终责任。

## 五个核心术语

<Term def="通过流程、提问和适度介入帮助群体自己思考、选择与行动，而非替群体给答案。">引导</Term>、<Term def="暂缓评价并扩大信息、观点或方案空间的讨论阶段。">发散</Term>、<Term def="按预先声明的标准比较、组合和选择，形成明确结论的阶段。">收敛</Term>、<Term def="暂存重要但不属于当前议题的内容，并承诺负责人和回访时间的可见清单。">停车场</Term>、<Term def="对下一步交付、期限、依赖和反馈承担明确责任的单一角色。">行动负责人</Term>。

发散和收敛必须在流程上分开：发散阶段保护数量、差异与边缘信息，收敛阶段才引入目标、边界和证据。停车场维持当前聚焦，但只有回访才建立信任。行动负责人把群体结论连接到现实；如果会议结束只有“大家认为”，没有谁在何时交付什么，引导尚未完成。

## 四个可手算观察指标

以下公式是课程观察工具，不是原书量表。参与覆盖率检查相关成员是否真正进入讨论：

$$
V = N_{participants\ contributing} / N_{participants\ relevant}
$$

发言平衡用归一化熵避免总时长掩盖一人垄断：

$$
B = -\sum_i p_i \log(p_i) / \log(n)
$$

问题清晰率要求关键主张带有事实、边界或验证方式：

$$
C = N_{claims\ testable} / N_{claims\ material}
$$

行动兑现率只计算有负责人、期限且已回访的承诺：

$$
A = N_{actions\ closed} / N_{actions\ committed}
$$

指标必须结合角色、专业相关性和会议阶段解释。发言完全平均不一定理想，专家在特定阶段可以多讲；匿名输入提高覆盖却可能降低追问深度；行动兑现高如果目标错误也没有价值。数字用于暴露问题，不用于给参与者贴人格标签。

## 权威目录坐标与工具机制

### 后记

**目录节点 1/1。** 后记把掌握标准从记住49个工具改为拥有约5个能够在不同场合熟练使用、复盘并调整的工具。引导能力来自实践、反馈和创造新工具，而不是工具数量。

应用“后记”前，先写会议目的、当前阶段、参与者、权力差异、时间盒和预期输出，再沿“选择真实问题 → 挑选少数工具 → 在不同场景实践 → 记录反馈改进 → 形成个人工具组”运行。重点观察五个擅长工具：它是否让更多相关信息进入、让问题结构更清楚，并把结论交给明确的行动负责人。一次只改变一个流程条件，避免把引导效果与议题难度或领导介入混在一起。

本节点至少保存工具使用前基线、参与分布、产物快照、一个拒绝或少数意见、行动项和回访结果。会议气氛热烈不是充分证据；若低权力成员仍沉默、分类掩盖边缘信息、投票替代边界判断，或行动项无人兑现，就必须缩小工具适用范围并调整流程。

## 把工具选择变成可重放会议协议

本单元主链是“选择真实问题 → 挑选少数工具 → 在不同场景实践 → 记录反馈改进 → 形成个人工具组”。会前先冻结目的、决策权、阶段、参与者、保密边界、时间盒和输出；再从49个工具中选择能消除当前流程障碍的最小组合。会中记录发言者、信息卡、分类变更、异议、阶段切换和引导者介入；会后保存结论、负责人、期限、依赖与反馈。

三种阶段必须匹配工具。发散探索需要安全、独立输入和多角度；收敛选择需要标准、边界条件、异议和透明筛选；行动落实需要责任、资源、风险与回访。若会议同时要求三者，引导者应显式分段并提示规则切换，不能一边要求大胆想象一边即时批评。

## 最小可重放实现

第一段把会议与工具选择声明为数据：

```ts
type FacilitationContract = {
  unit: string;
  purpose: string;
  phase: "explore" | "converge" | "execute";
  decisionOwner: string;
  selectedTool: string;
  expectedArtifact: string;
};

const contract: FacilitationContract = {
  unit: "opt-23-afterword",
  purpose: "五个擅长工具形成可复核结果",
  phase: "converge",
  decisionOwner: "会前明确的授权角色",
  selectedTool: "后记",
  expectedArtifact: "结论、异议、负责人、期限与反馈日期",
};
```

第二段从发言与行动记录计算覆盖和兑现：

```python
def review_meeting(relevant, speakers, committed, closed):
    voice_coverage = len(set(speakers)) / max(len(set(relevant)), 1)
    action_follow_through = closed / max(committed, 1)
    return {
        "voice_coverage": voice_coverage,
        "action_follow_through": action_follow_through,
    }
```

第三段预注册阶段、扰动与拒绝条件：

```yaml
unit: "opt-23-afterword"
chain:
  [
    "选择真实问题",
    "挑选少数工具",
    "在不同场景实践",
    "记录反馈改进",
    "形成个人工具组",
  ]
phases: [explore, converge, execute]
vary_one: [safety, balance, structure, ownership]
record: [speaker, artifact, dissent, transition, owner, deadline, follow_up]
reject_when:
  [coerced_disclosure, hidden_decision, no_minority_record, owner_missing]
```

代码只固定记录，不替代引导判断。发言分析要保护隐私，沉默可能来自思考方式、专业相关性或文化，而不一定代表压制；需要结合匿名反馈和访谈解释，不能把单个指标变成员工评价。

## 阶段与工具选择矩阵

| 阶段 | 当前障碍             | 适合工具特征           | 常见误用       | 必要产物   |
| ---- | -------------------- | ---------------------- | -------------- | ---------- |
| 进入 | 陌生、紧张、规则不清 | 低风险破冰、基本规则   | 强迫隐私披露   | 共同规则   |
| 发散 | 信息少、视角窄       | 静默输入、多角度、聚类 | 边发散边批评   | 候选与主题 |
| 澄清 | 问题模糊、因果混乱   | 流程、逻辑树、鱼骨图   | 把假设当根因   | 可验证问题 |
| 收敛 | 候选多、标准冲突     | 矩阵、投票、异议       | 票数替代边界   | 选择与理由 |
| 执行 | 无主、阻力、风险     | 4W1H、力场、风险表     | 会议结束即完成 | 责任与回访 |

工具可以组合，但每增加一个工具都增加解释、切换和时间成本。最小充分组合比“把49个都用上”更专业；熟练掌握少数工具、知道何时不用，优于只会复述全部名称。

<Callout type="trap" title="陷阱：先挑喜欢的工具，再寻找问题">
  应先诊断会议目的、阶段和障碍，再选择最小工具。拿着熟悉模板套所有问题，会让工具制造额外流程而不是帮助思考。
</Callout>

<Callout type="trap" title="陷阱：把热烈、满意或一致当作成果">
  热烈可能由少数人主导，一致可能来自权力压制。必须保存参与分布、少数意见、决策理由和行动回访。
</Callout>

## 证据包、伦理边界与独立复核

证据包至少保存版次、目录坐标、会议目的、阶段、决策权、参与者与缺席者、权力关系、工具选择理由、基本规则、时间盒、发言分布、匿名输入、阶段产物、分类变更、少数意见、停车场、行动负责人、期限、依赖、风险、回访和最终结果。涉及个人披露、绩效或冲突时要取得同意并限制传播。

独立复核者先根据会前合同判断工具是否匹配阶段，再从记录重算四项指标；随后更换引导者或降低心理安全，检查结论是否稳健。若只有引导者主观复盘、没有产物与行动反馈，或参与者无法安全表达不同意见，不能宣称工具有效。

## 本章回顾

后记不是工具名称清单，而是“选择真实问题 → 挑选少数工具 → 在不同场景实践 → 记录反馈改进 → 形成个人工具组”中的群体思考单元。掌握本页意味着能逐项定位1个权威目录节点，解释五个擅长工具、跨场景实践、引导复盘、方法改造、持续成长的适用条件与失败信号，并让参与、产物、异议、责任和回访共同验收引导结果。

<Exercises>

1. 怎样为后记选择最小充分工具？

<Answer>
  先冻结目的、阶段、参与者、权力关系、时间和输出，定位当前唯一主要流程障碍，再选择直接处理该障碍的工具。写出不用它会怎样、使用后产生什么产物，并保留退出和替代方案。
</Answer>

2. 怎样证明工具改善了群体思考而不是只改善气氛？

<Answer>
  比较使用前后的参与覆盖、可验证主张、少数意见保留、收敛理由和行动兑现；保持议题与时长接近。只有气氛评分提高却无信息、决策或行动变化，不支持强结论。
</Answer>

3. 何种失败会迫使你停止或更换工具？

<Answer>
  强迫披露、低权力成员持续沉默、阶段与工具错配、分类删除边缘证据、投票越过边界条件或行动无主，都应停止。恢复安全、澄清授权，再选择更小或异步的流程。
</Answer>

</Exercises>
