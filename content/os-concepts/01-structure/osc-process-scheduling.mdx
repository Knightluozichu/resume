## 直觉引入

把 CPU 想象成一位只有一个窗口的银行柜员，顾客（进程）排队等待服务。**FCFS**（先来先服务）就像普通排队——先到先办，但前面一个办存折的老奶奶可能让后面只取 100 块的年轻人等半小时（convoy effect 护航效应）。**SJF**（最短作业优先）让取 100 块的先办——平均等待最短，但办存折的老奶奶可能等到天黑（饥饿）。**RR**（轮转）给每人 1 分钟，超时排到队尾——公平、响应快，但频繁切换窗口浪费柜员时间。**MLFQ**（多级反馈队列）是终极方案：新顾客先排快速窗口（假设是小额业务），多次超时则降级到慢速窗口——既照顾小额快办，又不饿死大额业务。

## 进程与 PCB

<Term def="进程是程序的一次执行实例，是资源分配和调度的基本单位。内核为每个进程维护 PCB（进程控制块），记录进程标识、处理器状态、调度信息和资源信息——PCB 是进程存在的标志。">进程</Term>与程序的本质区别在于动态性：程序是磁盘上的静态代码，进程是代码在内存中的一次运行实例。一个程序可对应多个进程（如打开多个浏览器窗口）。PCB（进程控制块）是内核为每个进程维护的核心数据结构，包含：①进程标识（PID、UID）；②处理器状态（寄存器现场、PC、栈指针）；③调度信息（状态、优先级、队列指针）；④内存管理信息（页表基址）；⑤I/O 状态（打开文件表）。进程切换 = 保存当前 PCB 现场 + 加载下一个 PCB 现场——这就是上下文切换的开销来源。

## 调度算法对比

```text
// 三种基本调度算法的甘特图（P1=6ms, P2=8ms, P3=7ms，同时到达）

// FCFS（先来先服务）——简单但护航效应
// [P1: 0-6] [P2: 6-14] [P3: 14-21]
// 平均等待时间 = (0+6+14)/3 = 6.67ms
// 问题：长作业 P2 阻塞短作业 P1

// SJF（最短作业优先，非抢占）——理论最优但需预知
// [P1: 0-6] [P3: 6-13] [P2: 13-21]  （按突发时间排序 P1<P3<P2）
// 平均等待时间 = (0+6+13)/3 = 6.33ms
// 问题：长作业 P2 饥饿

// RR（轮转，量子=4ms）——公平但切换多
// P1(0-4) P2(4-8) P3(8-12) P1(12-16) P2(16-20) P3(20-24) P2(24-28) P3(24-27)
// 响应时间最优但上下文切换频繁
```

**FCFS** 简单公平但有 convoy effect（护航效应）：长作业阻塞短作业。**SJF** 理论最优（最小化平均等待时间），但需预知突发时间（不现实），且长作业可能饥饿。**RR** 公平、响应快，但量子太小则切换开销大，量子太大退化为 FCFS。实际系统用**多级反馈队列（MLFQ）**组合三者的优点：新进程进高优先级短量子队列（假设是短作业），多次用完量子后降级（可能是长作业），定期提升所有进程优先级防止饥饿。MLFQ 用观察行为动态判断作业类型，无需预知突发时间。

## 常见误区

<Callout type="trap">
**误区：SJF 是最好的调度算法。** SJF 确实最小化平均等待时间——但「最好」取决于优化目标。如果目标是响应时间（交互式系统），RR 远优于 SJF——RR 让每个进程快速获得首次响应，SJF 让短作业快速完成但长作业连首次响应都等不到。如果目标是公平性，RR 也优于 SJF——SJF 对长作业不公平。更关键的是 SJF 需要预知进程的 CPU 突发时间，这在交互式和分时系统中根本不可能——用户随时可能输入新命令。MLFQ 的精妙在于用「观察行为」代替「预知信息」：多次用完短量子的进程降级为长作业，这才是实际系统的做法。
</Callout>

<Exercises>
**问题 1**：FCFS、SJF 和 RR 三种调度算法的特点和适用场景分别是什么？

<Answer>
FCFS（先来先服务）：按到达顺序执行，非抢占。简单公平，但长作业阻塞短作业（convoy effect），平均等待时间长。适合长作业为主的批处理。SJF（最短作业优先）：选突发时间最短的执行，非抢占。理论最优（最小化平均等待时间），但需预知突发时间（不现实），且长作业可能饥饿。适合可预估作业时间的批处理。RR（轮转）：每个进程执行一个时间量子后强制切换。公平、响应时间短（适合交互式），但量子太小则上下文切换开销大。适合分时交互系统。实际系统用多级反馈队列组合三者优点。
</Answer>

**问题 2**：什么是 convoy effect（护航效应）？它为什么是 FCFS 的致命弱点？

<Answer>
Convoy effect 是 FCFS 调度中的现象：当一个长作业正在 CPU 上执行时，所有短作业都在就绪队列里等它，就像一列慢车后面堵了一串快车。效果是 CPU 利用率和吞吐量急剧下降——短作业本来几毫秒就能完成，却要等长作业几十秒。致命原因：FCFS 不考虑作业长度，纯粹按到达顺序排队。一个 CPU 突发 100ms 的作业排在突发 1ms 的作业前面，后者要白等 100ms。SJF 通过优先短作业解决了这个问题，但引入了长作业饥饿的风险。MLFQ 的解法是动态调整：新进程先给短量子（假设是短作业），多次用完量子后降级（可能是长作业），兼顾短作业响应和长作业公平。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="进程">程序的一次执行实例，是资源分配和调度的基本单位。有独立地址空间和 PCB。与程序的区别：程序是静态代码，进程是动态执行实例。一个程序可对应多个进程。</GlossaryItem>
<GlossaryItem term="PCB">进程控制块——内核为每个进程维护的数据结构，包含进程标识、处理器状态、调度信息和资源信息。进程切换 = 保存当前 PCB + 加载下一个 PCB。PCB 是进程存在的标志。</GlossaryItem>
<GlossaryItem term="FCFS">先来先服务调度。按到达顺序执行，非抢占。简单但护航效应——长作业阻塞短作业。适合批处理。</GlossaryItem>
<GlossaryItem term="SJF">最短作业优先调度。选 CPU 突发时间最短的执行。理论最优（最小化平均等待时间），但需预知突发时间且长作业可能饥饿。</GlossaryItem>
<GlossaryItem term="RR">轮转调度。每进程执行一个量子后切换到下一个。公平且响应快，适合交互式。量子太小则切换开销大，太大退化为 FCFS。</GlossaryItem>
<GlossaryItem term="MLFQ">多级反馈队列。多个优先级队列，高优先级短量子（快响应），用完量子降级（识别长作业），定期提升防饥饿。无需预知突发时间，实际系统最常用。</GlossaryItem>
</Glossary>
