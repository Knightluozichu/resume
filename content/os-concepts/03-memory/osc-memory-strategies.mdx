## 直觉引入

把内存管理想象成管理一个停车场。**连续分配**像给每辆车分配连续的车位——如果一辆大巴（大进程）走了，留下的大空位可能放不进两辆小轿车，但中间的小空位又停不了大巴——这就是**外部碎片**（总空间够但不连续）。而每辆车按 4 米对齐停车，一辆 3.5 米的车占 4 米——浪费 0.5 米，这是**内部碎片**（块内浪费）。**分页**的解法是拆解：把每辆车拆成 4 米的标准段，散停到任何空位——不需要连续，外部碎片消失了（任何空位都能用），但最后一辆车的最后一段可能没满（内部碎片）。**分段**则按车辆的逻辑部分（车头、车厢、车尾）精确分配——无内部碎片但段间产生外部碎片。**段页式**是先分段再分页——兼得两者优点。

## 连续分配与碎片

<Term def="外部碎片是内存总量够用但空闲块太小太分散无法满足大请求的现象。内部碎片是分配的块比请求的大、多余部分浪费在块内的现象。">内存碎片</Term>有两种。**外部碎片**：进程间的间隙太小无法利用——空闲空间总量够但被碎片化切割。**内部碎片**：分配时向上取整（如按 4KB 对齐），分配块大于实际需求，多余部分浪费。连续分配同时产生两种碎片。解决外部碎片的方法是**压缩**（移动进程合并空闲块），但开销大且需要重定位。三种分配策略：**首次适应**（找第一个够大的块，快但低地址碎片多）、**最佳适应**（找最小的够大的块，剩出大块但小碎片极多）、**最差适应**（找最大的块，剩出碎片较大但消耗大块）。实验表明首次适应综合性能最好。

## 分页地址翻译

```text
// 分页地址翻译：虚拟地址 → 物理地址
// 页大小 = 2^k（通常 4KB = 2^12），偏移占 k 位

// 虚拟地址结构
// ┌─────────────┬──────────┐
// │  页号 p     │  偏移 d  │
// │  (高位)     │  (低位)  │
// └─────────────┴──────────┘

// 翻译过程
// 1. 用页号 p 查页表 → 得到帧号 f
// 2. 物理地址 = f × 帧大小 + d（偏移直接拼接）

// 页表项内容
// ┌──────────┬────┬────┬────┬────┐
// │ 帧号 f   │有效│保护│脏位│引用│
// └──────────┴────┴────┴────┴────┘

// TLB 加速
// 无 TLB: 每次访存 = 查页表（1次访存）+ 取数据（1次访存）= 2 倍开销
// 有 TLB: 先查 TLB（1时钟周期），命中则直接得帧号 ≈ 1 倍开销
// TLB 命中率 95%+（局部性原理），EAT ≈ 1.05 倍访存
```

分页消除外部碎片的原因：每个进程的页可以分散在物理内存的任意空闲帧中，不需要连续——物理帧只要有空闲就能用。但分页有内部碎片（最后一页可能没填满）。**TLB**（Translation Lookaside Buffer）是 CPU 内的硬件缓存，存近期用过的页表项。先查 TLB，命中则直接得到帧号（一个时钟周期），未命中才查内存中的页表。TLB 命中率通常 95%+，使平均访存开销接近 1 倍而非 2 倍。

## 常见误区

<Callout type="trap">
**误区：分页完全消除了内存碎片。** 不对。分页消除了外部碎片（页可分散分配，不需要连续空间），但仍有内部碎片——进程最后一页往往没填满。例如进程需 17KB，按 4KB 分页需 5 页 20KB，浪费 3KB。页越大内部碎片越严重——这也是现代系统支持多种页大小（4KB/2MB/1GB 大页）的原因之一：大页减少页表开销但增加内部碎片，需权衡。分段则相反：无内部碎片（段大小精确）但有外部碎片（段间间隙不连续）。段页式结合两者，是现代系统的折中方案。
</Callout>

<Exercises>
**问题 1**：外部碎片和内部碎片的区别是什么？分页为什么能消除外部碎片？

<Answer>
外部碎片：内存总量够用，但空闲块太小太分散，无法满足大请求。内部碎片：分配的块比请求的大，多余部分浪费在块内。分页消除外部碎片的原因：每个进程的页可以分散在物理内存的任意空闲帧中，不需要连续——物理帧只要有空闲就能用，不需要大块连续空间。但分页有内部碎片：最后一页可能没填满。分段消除内部碎片（段大小精确匹配），但产生外部碎片（段间间隙不连续）。
</Answer>

**问题 2**：分页机制中，虚拟地址如何翻译成物理地址？TLB 的作用是什么？

<Answer>
虚拟地址由页号 p 和偏移 d 组成。翻译过程：①用 p 查页表得到帧号 f；②物理地址 = f × 帧大小 + d（偏移直接拼接）。问题：每次访存要先查页表（一次内存访问）再取数据（又一次内存访问），开销翻倍。TLB 是 CPU 内的硬件缓存，存近期用过的页表项。先查 TLB，命中则直接得到帧号（一个时钟周期），未命中才查内存中的页表。TLB 命中率通常 95%+，使平均访存开销接近 1 倍而非 2 倍。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="外部碎片">内存总量够用但空闲块太小太分散，无法满足大请求。连续分配的固有问题，压缩可缓解但开销大。分页可消除。</GlossaryItem>
<GlossaryItem term="内部碎片">分配块大于实际需求，多余部分浪费在块内。分页的固有问题（最后一页未填满），分段可消除。</GlossaryItem>
<GlossaryItem term="TLB">Translation Lookaside Buffer，CPU 内的硬件缓存，存近期用过的页表项。命中率 95%+，将访存开销从 2 倍降到接近 1 倍。多级页表场景下更加重要。</GlossaryItem>
<GlossaryItem term="段页式">先分段（逻辑结构，消除内部碎片），再对每段分页（消除外部碎片）。结合两者优点的折中方案，是现代系统的常见做法。</GlossaryItem>
</Glossary>
