## 直觉引入

把虚拟内存想象成一个图书馆。物理书架（物理内存）只能放 100 本书，但图书馆目录（页表）登记了 10000 本书的位置——其余 9900 本存在地下仓库（磁盘）。读者要看的书如果在书架上（有效位=1），直接拿取（内存访问）；如果不在（缺页），管理员去仓库取书放回书架——但书架满了就得挑一本「最不可能再看」的撤下（页面置换）。**FIFO** 撤下最早入库的（但可能是一本常看的经典）；**LRU** 撤下最久没翻的（基于局部性，通常表现好）；**OPT** 撤下未来最久不看的（理论最优但无法预知）。如果书架太小，读者不停跑仓库（抖动），效率极低——工作集模型确保每人至少有足够的活跃书籍在书架上。

## 请求分页

<Term def="请求分页是虚拟内存的核心机制：进程的页面只在被访问时才从磁盘加载到物理内存（按需调页），而非一次性全部加载。缺页时触发缺页中断，内核从磁盘读入页面。">请求分页</Term>的关键是页表中的有效位（valid bit）：1 表示页面在物理内存中，0 表示不在（在磁盘上）。缺页中断流程：①CPU 访问虚拟地址，查页表发现有效位=0 → 触发缺页中断；②内核找到空闲物理帧（若无则页面置换淘汰一页）；③从磁盘读入该页到物理帧；④更新页表（帧号 + 有效位置 1）；⑤重启被中断的指令。有效访问时间 EAT = $(1-p) \times \text{内存访问} + p \times \text{缺页处理}$，其中 $p$ 是缺页率。只要 $p$ 足够小（如 0.001），EAT 接近纯内存访问——这就是虚拟内存「用磁盘扩充内存」的数学基础。

## 页面置换算法

```text
// 四种页面置换算法对比

// OPT 最佳置换：淘汰未来最久不用的页面
// 优点：理论最优（缺页率最低）
// 缺点：无法实现（不能预知未来访问序列），只作评估基准

// FIFO 先进先出：淘汰最先进入内存的页面
// 优点：简单（队列实现）
// 缺点：愚蠢（最老的不一定最不用）；有 Belady 异常
// Belady 异常：帧数增多反而缺页更多（FIFO 独有）

// LRU 最近最少使用：淘汰最久未访问的页面
// 优点：基于局部性原理，性能接近 OPT
// 缺点：实现开销大（需精确记录每页最后访问时间）
// 硬件实现：计数器法（每页一个计数器）或栈法（维护访问栈）

// Clock 时钟算法：LRU 的近似
// 每页一个引用位，访问时硬件置 1
// 环形扫描：遇到引用位=1 清零跳过，遇到=0 淘汰
// 优点：开销小（只需一个引用位），效果接近 LRU
// 二次机会算法 = Clock 的变体
```

## 工作集与抖动

<Term def="工作集 W(t, Δ) 是进程在过去 Δ 时间窗口内访问的页面集合，代表进程当前的活跃内存足迹。抖动是多道程序度过高导致每个进程帧不够、频繁缺页、CPU 利用率骤降的现象。">工作集</Term>模型的核心思想：只有当进程的全部工作集都在物理内存中时，进程才能高效运行。**抖动**（thrashing）发生在多道程序度过高时——每个进程分到的物理帧不足以容纳其工作集，导致所有进程都在频繁缺页、CPU 利用率骤降。解法：①监控每个进程的工作集大小，确保分配的帧数 ≥ 工作集大小——不够就挂起部分进程（降低多道程序度）；②用页错误频率（PFU）控制——缺页率过高说明帧不够则多给帧，缺页率过低说明帧富裕则回收帧，维持缺页率在合理区间。

## 常见误区

<Callout type="trap">
**误区：增加物理内存帧数一定减少缺页率。** 对 LRU 和 OPT 成立（它们是栈式算法——n 帧的页面集合是 n+1 帧的子集），但对 FIFO 不成立——FIFO 存在 **Belady 异常**：帧数增多反而缺页更多。原因是 FIFO 不满足栈性质——它按进入顺序淘汰，与访问模式无关，增加帧数可能保留了一个将来很早就要用的「老页面」，反而把一个新进入但马上要用的页面淘汰了。这也是为什么实际系统不用纯 FIFO，而是用 Clock（LRU 近似）——Clock 满足栈性质，无 Belady 异常。Belady 异常是理解「为什么不能简单增加内存解决缺页」的关键案例。
</Callout>

<Exercises>
**问题 1**：什么是请求分页（demand paging）？缺页中断的处理流程是什么？

<Answer>
请求分页是虚拟内存的核心机制：进程的页面只在被访问时才从磁盘加载到物理内存（按需调页），而非一次性全部加载。页表中有有效位：1 表示在内存，0 表示不在。缺页中断流程：①CPU 访问虚拟地址，查页表发现有效位=0 → 触发缺页中断；②内核找到空闲物理帧（若无则页面置换淘汰一页）；③从磁盘读入该页到物理帧；④更新页表（帧号 + 有效位置 1）；⑤重启被中断的指令。有效访问时间 EAT = (1-p) × 内存访问 + p × 缺页处理，只要 p 足够小，EAT 接近纯内存访问。
</Answer>

**问题 2**：什么是工作集模型？它如何解决抖动问题？

<Answer>
工作集 W(t, Δ) 是进程在过去 Δ 时间窗口内访问的页面集合——代表进程当前的活跃内存足迹。工作集模型的核心：只有当进程的全部工作集都在物理内存中时才能高效运行。抖动是多道程序度过高时每个进程分到的帧不足以容纳工作集，导致频繁缺页、CPU 利用率骤降。解法：①监控工作集大小，确保分配帧数 ≥ 工作集——不够就挂起部分进程降低多道程序度；②用页错误频率控制——缺页率过高多给帧，过低回收帧。工作集模型把内存分配从「固定帧数」变为「按需供给」，从根本上防止抖动。
</Answer>

<Glossary>
<GlossaryItem term="请求分页">虚拟内存的核心机制。页面只在被访问时才从磁盘加载到内存（按需调页）。缺页时触发缺页中断，内核从磁盘读入。EAT = (1-p) × 内存 + p × 缺页处理，p 足够小时开销接近纯内存访问。</GlossaryItem>
<GlossaryItem term="LRU">最近最少使用页面置换算法。淘汰最久未访问的页面，基于局部性原理性能接近 OPT。但需精确记录访问时间，开销大。Clock 算法是其低成本近似。</GlossaryItem>
<GlossaryItem term="Belady异常">FIFO 独有的现象：增加物理帧数反而缺页更多。原因是 FIFO 不满足栈性质。LRU 和 OPT 满足栈性质，无此异常。</GlossaryItem>
<GlossaryItem term="抖动">多道程序度过高导致每个进程帧不够容纳工作集，频繁缺页、CPU 利用率骤降。解法：降低多道程序度或用页错误频率控制。</GlossaryItem>
<GlossaryItem term="写时复制">COW（Copy-on-Write）。fork() 时父子共享只读页，写时才拷贝。延迟拷贝降低开销，fork-exec 模式下避免无谓复制。</GlossaryItem>
</Glossary>
