## 核心机制深挖

用有界缓冲、读者写者和哲学家就餐检验同步工具，并对照 Windows、Linux、POSIX、Java 与函数式编程方案。 每个目录概念都放回“声明案例不变量 → 选择同步原语 → 枚举线程交错 → 检查安全性 → 检查活性 → 对照系统实现”资源状态机。输入可能是系统调用、地址、字节流、中断、资源请求或远程消息；状态可能位于进程表、页表、设备队列、文件元数据、虚拟机或保护域；输出同时说明返回值、所有权与下一阶段可依赖的承诺。

本页不变量是：**案例资源计数守恒且不会越界；所有允许交错保持数据不变量，系统最终继续前进且不会让某类参与者永久饥饿。**。正常和错误路径都必须保持它。一次成功只证明一个样本可用，不能证明边界安全；所以每项机制进入正常、边界、失败和恢复四条轨迹，并写清谁检测、谁阻塞或重试、谁逆序清理、谁上报。

用最小工作负载沿“声明案例不变量 → 选择同步原语 → 枚举线程交错 → 检查安全性 → 检查活性 → 对照系统实现”记录系统调用、内核对象和资源状态，再注入单一边界并重放。 运行前把预期写成快照，运行后逐字段比较。并发记录同步边，地址记录位宽权限，I/O 记录缓冲区与完成事件，持久化区分提交与落盘，分布式记录丢失、重复和重排。

注入权限、容量、时序或设备故障，在“声明案例不变量”之后的首个偏离点停止，逆序清理并验证同一输入恢复。 删除故障后以相同输入重放，确认返回值、内核对象、外部结果和清理状态一起恢复。只修正末端输出却留下线程、页、设备请求、文件引用、虚拟状态或权限污染，仍不通过。

第10版使用 Linux、Windows 10、多核、NVM、云和容器作为实例。现代版本会改变实现与性能数值，但进程状态、地址翻译、I/O 分层、持久化、虚拟化隔离和保护域仍可验证。现代对照不能覆盖2018英文原版与2023中文出版版的目录身份。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：应用结果正确就代表系统资源正确。**
  中间仍可能有竞争、脏映射、丢中断、半提交元数据、泄漏对象或越权，必须检查首个内核状态变化和清理。
</Callout>

<Callout type="trap">
  **误区二：用几个主题页代替恐龙书第10版。**
  原书有9部分21章，分开讲进程、线程、调度、两章同步、三章文件系统、安全、保护、虚拟机、分布式及两套案例，不能合并丢失。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                     | 必查证据                 | 通过条件     |
| ---- | ---------------------------- | ------------------------ | ------------ |
| 正常 | 固定版本、负载和输入         | 全阶段状态与输出         | 与预测一致   |
| 边界 | 极值、空输入、低容量         | 终止、权限与资源         | 不越界不泄漏 |
| 失败 | 错地址、设备超时、断连或竞争 | 首个错误与责任层         | 失败被隔离   |
| 恢复 | 逆序清理后重放               | 状态、输出、持久化和审计 | 回到受控结果 |

## 练习

<Exercises>

**问题 1** 为什么不能只看最终输出验收第 7 章 同步案例？

<Answer>
  最终输出会隐藏调度、地址映射、设备队列、持久化、所有权和权限。必须先预测，保存首个偏离点，逆序清理后以同一输入重放。
</Answer>

**问题 2** 如何把“第7章 同步案例”变成可执行证据？

<Answer>
  沿“声明案例不变量、选择同步原语、枚举线程交错、检查安全性、检查活性、对照系统实现”登记输入、内核状态、责任接口、边界、失败出口和恢复条件，让四类样本都留下可比较快照。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  案例资源计数守恒且不会越界；所有允许交错保持数据不变量，系统最终继续前进且不会让某类参与者永久饥饿。
  异常路径不污染下一次运行，所有资源有唯一逆序清理路径，恢复轨迹重新到达正常状态。
</Answer>

</Exercises>

## 小结

- 有界缓冲：连接“声明案例不变量”的请求与内核状态。
- 读者写者：连接“选择同步原语”的资源所有权。
- 哲学家就餐：连接“枚举线程交错”的同步或权限边界。
- 内核同步：连接“检查安全性”的失败传播。
- 函数式并发：连接“检查活性”的恢复证据。
