## 直觉引入

把文件系统想象成一个大图书馆。**VFS** 是图书馆的前台——不管书存在哪个书库（ext4/FAT/NFS），读者都用同一套借书流程（open/read/write/close），前台负责把请求转给对应书库。**inode** 是每本书的「馆藏卡」——记录了书的元信息（作者、大小、权限）和「书在第几排第几架」的位置信息（数据块指针）。小书直接记位置（直接指针），中等书需要一层索引（一级间接），大书需要多层索引（二级/三级间接）。**日志**就像图书管理员的操作记录本——先在记录本上写好「我要做什么」，再实际去做，万一中途断了电，恢复时照记录本重做即可——保证「要么全做要么全不做」。**硬链接**是同一本书的多个目录卡（同一 inode），**软链接**是一张写着「请去 XX 架找那本书」的便签条（独立 inode 存路径）。

## VFS 虚拟文件系统

<Term def="VFS（虚拟文件系统）是内核中的抽象层，为应用程序提供统一的文件操作接口（open/read/write/close），屏蔽底层不同文件系统（ext4/FAT/NFS/NTFS）的实现差异，使「一切皆文件」成为可能。">VFS</Term>定义了四个核心对象：①超级块（superblock）——文件系统整体信息；②inode——文件元数据+数据块指针；③目录项（dentry）——目录到文件的映射；④文件对象（file）——打开文件的上下文（读写位置等）。每种文件系统只需实现这些对象的操作函数集。应用程序调 `read(fd, buf, n)` 时，VFS 通过 fd 找到文件对象，调用其 `read` 方法，底层自动分派到 ext4 或 NFS 的实现。VFS 让「一切皆文件」的 Unix 哲学成为可能——设备、网络套接字、管道都可以用同一套 API 操作。

## inode 与数据块指针

```text
// inode 的分级索引设计（以 4KB 块、4 字节指针为例）

// 12 个直接块指针 → 12 × 4KB = 48KB
//    小文件直接存完，一次访盘取数据（最快）

// 1 个一级间接块指针 → 1024 × 4KB = 4MB
//    间接块存 1024 个数据块指针
//    访问需两次读盘：先读间接块，再读数据块

// 1 个二级间接块指针 → 1024² × 4KB = 4GB
//    两层间接索引
//    访问需三次读盘

// 1 个三级间接块指针 → 1024³ × 4KB = 4TB
//    三层间接索引
//    访问需四次读盘

// 设计哲学：分级索引
//    小文件（48KB 以内）：直接指针，一次访盘，极快
//    中等文件（4MB）：一级间接，两次访盘
//    大文件（4GB）：二级间接，三次访盘
//    超大文件（4TB）：三级间接，四次访盘
//    用少量指针覆盖极大范围，同时常见情况（小文件）保持高效
```

## 日志文件系统

传统文件系统崩溃时可能半完成——元数据更新了但数据没写，或目录改了但 inode 没改，导致不一致。**日志文件系统**的解法是「先写日志再写实际数据」：①写日志区（记录事务：begin + 变更数据）；②提交记录（commit 标记）；③写实际位置（数据块、inode、目录项）；④检查点（标记日志事务完成）。崩溃恢复时扫描日志：有 commit 标记的事务重做（redo），没有 commit 的事务丢弃。这保证了「要么全做要么全不做」的原子性。代价是写入开销加倍，所以 ext4 允许选择 journal=ordered（只日志元数据）或 journal=writeback 来权衡安全性和性能。

## 常见误区

<Callout type="trap">
**误区：删除大文件很慢，因为要擦除所有数据。** 恰恰相反——删除大文件通常瞬间完成。因为删除操作只是把 inode 从目录树中解链（清除目录项中的文件名→inode 映射），把 inode 标记为空闲，把数据块标记为空闲——并不擦除实际数据。数据块只是「被标记为可覆写」，将来新文件写入时会覆盖。所以删除 1GB 和删除 1KB 一样快（都是修改几个元数据块）。这也是为什么误删文件可以用数据恢复工具找回——数据还在磁盘上，只是 inode 没了。而复制大文件慢是因为要把每个数据块都读出来写到新位置——N 次磁盘 I/O。删除 = 修改几个元数据，复制 = 读写全部数据块。
</Callout>

<Exercises>
**问题 1**：VFS 的作用是什么？它如何让不同文件系统共用统一 API？

<Answer>
VFS 是内核中的抽象层，为应用程序提供统一的文件操作接口（open/read/write/close），屏蔽底层不同文件系统的实现差异。VFS 定义四个核心对象：超级块（文件系统信息）、inode（文件元数据+块指针）、目录项（目录到文件映射）、文件对象（打开文件上下文）。每种文件系统只需实现这些对象的操作函数集。应用程序调 `read(fd, buf, n)` 时，VFS 通过 fd 找到文件对象，调用其 `read` 方法，底层自动分派到 ext4 或 NFS 的实现。VFS 让「一切皆文件」成为可能。
</Answer>

**问题 2**：inode 的数据块指针结构如何兼顾小文件和大文件？

<Answer>
inode 包含 12 个直接块指针、1 个一级间接、1 个二级间接、1 个三级间接。以 4KB 块、4 字节指针为例：直接指针覆盖 48KB（小文件一次访盘）；一级间接覆盖 4MB（两次访盘）；二级间接覆盖 4GB（三次访盘）；三级间接覆盖 4TB（四次访盘）。这种指数式扩展使小文件极快（直接指针一次访盘），大文件虽慢但能支持到 TB 级。这是「分级索引」设计——用少量指针覆盖极大范围，同时常见情况（小文件）保持高效。
</Answer>

<Glossary>
<GlossaryItem term="VFS">虚拟文件系统。内核中的抽象层，为应用提供统一的文件操作接口，屏蔽底层不同文件系统的差异。定义超级块、inode、目录项、文件对象四大核心对象。让「一切皆文件」成为可能。</GlossaryItem>
<GlossaryItem term="inode">文件元数据结构，包含文件类型、权限、大小、时间戳和数据块指针。分级索引设计（直接/一级/二级/三级间接）兼顾小文件和大文件。硬链接 = 多个目录项指向同一 inode。</GlossaryItem>
<GlossaryItem term="日志文件系统">先写日志再写实际数据的文件系统。崩溃恢复时扫描日志重做已提交事务、丢弃未提交事务。保证「要么全做要么全不做」的原子性。ext4、NTFS、ZFS 都支持日志。</GlossaryItem>
<GlossaryItem term="硬链接">多个目录项指向同一个 inode（同一 inode 号）。删除原文件后硬链接仍可访问数据（inode 引用计数未归零）。不能跨文件系统、不能链接目录。</GlossaryItem>
<GlossaryItem term="软链接">符号链接。一个特殊文件，内容是目标路径字符串。有自己的独立 inode。删除原文件后变悬空链接。可跨文件系统、可链接目录。</GlossaryItem>
</Glossary>
