## 直觉引入

把操作系统想象成一座城市的市政管理系统。**CPU 管理**是交通调度——决定哪些车辆（进程）上路、谁先走（调度算法）、怎么避免撞车（同步）、怎么防止死锁路口（死锁）。**内存管理**是土地分配——每个市民（进程）分到一块地（地址空间），地块可以不连续（分页），可以比实际城市大（虚拟内存），不够住时从郊区（磁盘）调地（按需调页）。**文件系统**是档案馆——文件按目录分类，每份档案有编号（inode），借阅用统一流程（VFS），归档有日志防丢（日志文件系统）。**大容量存储**是仓储物流——货物（数据块）按最优路线配送（磁盘调度），多仓备份防灾害（RAID）。城市运转（boot 到 shutdown）时，这四个系统协作：交通让市民出门 → 土地让市民有家 → 档案馆存数据 → 仓库供物资——形成完整的资源管理闭环。

## 资源管理闭环

<Term def="操作系统的资源管理闭环：CPU 调度让进程运行 → 内存管理让进程隔离运行 → 文件系统让数据持久 → 存储调度让 I/O 高效。四大子系统协作形成「能执行→能隔离→能持久→能高效」的完整链条。">资源管理闭环</Term>包含四大子系统。**CPU 管理**（第 1-4 章）：OS 结构搭建平台，进程调度分配 CPU，线程同步保护并发，死锁防护资源争抢——解决「进程怎么运行」。**内存管理**（第 5-6 章）：连续分配和分页隔离地址空间，虚拟内存用磁盘扩充物理内存——解决「进程怎么隔离存取」。**文件系统**（第 7 章）：VFS 统一接口，inode 组织数据，日志保证一致——解决「数据怎么持久化」。**大容量存储**（第 8 章）：磁盘调度优化寻道，RAID 保障冗余——解决「I/O 怎么高效可靠」。

## 从 boot 到 shutdown

```text
// 操作系统从启动到关机的完整旅程

// BOOT 阶段
// 1. BIOS/UEFI 自检，加载 bootloader（GRUB/systemd-boot）
// 2. bootloader 加载内核映像到内存，跳转内核入口
// 3. 内核初始化：调度器、内存管理、VFS、驱动（OS 结构 第1章）
// 4. 创建 init 进程（PID=1），开始调度执行

// 进程运行阶段
// 5. init fork() 出 shell/服务进程（写时复制 COW 优化）
// 6. shell fork() + exec() 启动 ./a.out
//    - fork: COW 共享页（虚拟内存 第6章）
//    - exec: 按需调页载入新程序（虚拟内存 第6章）
//    - 进程调度器分配 CPU 时间片（进程调度 第2章）

// 7. a.out 运行时
//    - pthread_create 派生线程，互斥锁保护共享数据（线程同步 第3章）
//    - 多线程争锁可能死锁，银行家算法避免（死锁 第4章）
//    - MMU 经页表翻译虚拟地址，TLB 加速（内存策略 第5章）
//    - 缺页中断 → 从磁盘按需调页 → LRU 淘汰旧页（虚拟内存 第6章）

// 8. a.out 读写文件
//    - open() 经 VFS 定位 inode（文件系统 第7章）
//    - read() 通过 inode 数据块指针取数据（文件系统 第7章）
//    - 写操作先记日志保证崩溃一致（文件系统 第7章）
//    - I/O 请求经 SCAN/C-SCAN 调度优化寻道（大容量存储 第8章）
//    - RAID 5 保障数据冗余（大容量存储 第8章）

// SHUTDOWN 阶段
// 9. a.out exit() → 回收 PCB、关闭 fd、释放内存帧
// 10. 系统关机：flush 脏页到磁盘，卸载文件系统
// 11. 内核停止调度器，关闭设备，断电——资源管理闭环完成
```

## 设计哲学

操作系统的设计可以总结为五条核心原则。**①机制与策略分离**：机制是「怎么做」（调度器框架、页表硬件），策略是「做什么」（FCFS vs RR、LRU vs FIFO）。**②局部性原理**：程序访问有时间和空间局部性——TLB 缓存近期页表项，预取相邻页，工作集模型跟踪活跃页面。**③惰性求值**：fork 用写时复制延迟拷贝，虚拟内存按需调页延迟加载——只在真正需要时付出代价。**④层次化设计**：VFS 在文件系统之上，TLB 在页表之上，多级页表在单级页表之上——每层解决一层问题。**⑤一切皆文件**：Unix 把设备、管道、网络抽象为文件——统一接口降低复杂度。

## 常见误区

<Callout type="trap">
**误区：操作系统各章节是独立的知识点。** 恰恰相反——全书是一个环环相扣的资源管理链。进程调度（第 2 章）需要内存管理（第 5 章）为进程提供地址空间；内存管理需要虚拟内存（第 6 章）用磁盘扩充物理内存；虚拟内存缺页需要文件系统（第 7 章）和磁盘 I/O（第 8 章）读入页面；文件系统需要磁盘调度（第 8 章）高效读写。线程同步（第 3 章）和死锁（第 4 章）是进程调度的并发延伸。OS 结构（第 1 章）是所有子系统的容器。把这些看作孤立知识点的人遇到系统问题只会「重启试试」；理解闭环的人能顺着链条定位问题——是调度不公？内存不够？缺页过多？I/O 瓶颈？
</Callout>

<Exercises>
**问题 1**：操作系统的「资源管理闭环」包含哪四个子系统？它们如何协作？

<Answer>
四大子系统：CPU 管理、内存管理、文件系统、大容量存储。协作链条：①CPU 管理创建进程并调度执行（OS 结构 + 进程调度 + 线程同步 + 死锁防护）；②进程运行时访问内存，内存管理负责地址翻译和隔离（分页 + 虚拟内存 + 页面置换）；③内存数据需持久化，文件系统负责把字节组织成文件存到磁盘（VFS + inode + 日志）；④文件系统向磁盘发 I/O 请求，大容量存储负责调度和冗余（磁盘调度 + RAID）。闭环：CPU 调度让进程运行 → 内存管理让进程隔离 → 文件系统让数据持久 → 存储调度让 I/O 高效。
</Answer>

**问题 2**：操作系统如何用「抽象」和「调度」两个手段管理硬件资源？分别举例说明。

<Answer>
抽象：向上隐藏硬件细节，提供简化接口。进程抽象 CPU——程序不用关心寄存器和中断，OS 给「独占 CPU」幻觉。地址空间抽象内存——程序不用关心物理帧位置，MMU 翻译使每进程有独立虚拟内存。文件抽象磁盘——程序不用关心柱面/扇区，open/read/write 操作字节流。调度：向下分配物理资源，按策略共享。CPU 调度——RR/MLFQ 给每进程时间片。页面置换调度——LRU/Clock 决定哪个页被淘汰。磁盘调度——SCAN/C-SCAN 重排 I/O 减少寻道。抽象让程序「以为独占」，调度让资源「实际共享」。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="资源管理闭环">CPU 管理 → 内存管理 → 文件系统 → 大容量存储。四大子系统协作形成「能执行→能隔离→能持久→能高效」的完整链条。每个子系统解决前一层的遗留问题。</GlossaryItem>
<GlossaryItem term="从 boot 到 shutdown">系统从启动到关机的完整旅程：内核初始化 → fork/exec 创建进程 → 线程同步与死锁防护 → 页表翻译与缺页置换 → inode 定位文件 → 磁盘调度读盘 → exit 回收资源 → flush 脏页关机。全书以这条主线串联各章。</GlossaryItem>
<GlossaryItem term="机制与策略分离">OS 设计核心原则。机制是「怎么做」（调度器框架、页表硬件），策略是「做什么」（FCFS vs RR、LRU vs FIFO）。机制通用可复用，策略可替换适应不同场景。</GlossaryItem>
<GlossaryItem term="惰性求值">OS 设计原则。fork 用 COW 延迟拷贝，虚拟内存按需调页延迟加载——只在真正需要时付出代价，避免无谓开销。</GlossaryItem>
<GlossaryItem term="一切皆文件">Unix 哲学。把设备、管道、网络套接字抽象为文件——用统一的 open/read/write/close 接口操作，降低系统复杂度。VFS 是这一哲学的实现基础。</GlossaryItem>
</Glossary>
