## 核心机制深挖

从 I/O 硬件、轮询、中断与 DMA 进入应用接口、内核子系统、请求转换、STREAMS、性能和异步 I/O。 每个目录概念都放回“发起 I/O 调用 → 进入内核子系统 → 配置控制器 DMA → 处理中断完成 → 驱动错误恢复 → 返回应用结果”资源状态机。输入可能是系统调用、地址、字节流、中断、资源请求或远程消息；状态可能位于进程表、页表、设备队列、文件元数据、虚拟机或保护域；输出同时说明返回值、所有权与下一阶段可依赖的承诺。

本页不变量是：**请求、缓冲区、DMA 和完成事件生命周期一致；中断和驱动错误只完成一次，设备无关层保留统一语义。**。正常和错误路径都必须保持它。一次成功只证明一个样本可用，不能证明边界安全；所以每项机制进入正常、边界、失败和恢复四条轨迹，并写清谁检测、谁阻塞或重试、谁逆序清理、谁上报。

用最小工作负载沿“发起 I/O 调用 → 进入内核子系统 → 配置控制器 DMA → 处理中断完成 → 驱动错误恢复 → 返回应用结果”记录系统调用、内核对象和资源状态，再注入单一边界并重放。 运行前把预期写成快照，运行后逐字段比较。并发记录同步边，地址记录位宽权限，I/O 记录缓冲区与完成事件，持久化区分提交与落盘，分布式记录丢失、重复和重排。

注入权限、容量、时序或设备故障，在“发起 I/O 调用”之后的首个偏离点停止，逆序清理并验证同一输入恢复。 删除故障后以相同输入重放，确认返回值、内核对象、外部结果和清理状态一起恢复。只修正末端输出却留下线程、页、设备请求、文件引用、虚拟状态或权限污染，仍不通过。

第10版使用 Linux、Windows 10、多核、NVM、云和容器作为实例。现代版本会改变实现与性能数值，但进程状态、地址翻译、I/O 分层、持久化、虚拟化隔离和保护域仍可验证。现代对照不能覆盖2018英文原版与2023中文出版版的目录身份。

## 状态与失败矩阵

| 对象         | 正常状态               | 边界样本             | 失败证据           | 恢复条件           |
| ------------ | ---------------------- | -------------------- | ------------------ | ------------------ |
| 进程与同步   | 状态转换和同步边明确   | 抢占、竞争、低容量   | 调度与等待图       | 唤醒并回收全部流   |
| 地址与存储   | 映射、权限、元数据有效 | 缺页、空间耗尽、断电 | 页表与日志轨迹     | 重建一致映射或事务 |
| 设备与虚拟化 | 请求和完成一一对应     | 超时、迁移、过量提交 | 控制器与客户机状态 | 清理后相同输入重放 |
| 分布式与安全 | 所有权、身份、协议明确 | 节点失联、越权、重放 | 消息与审计记录     | 恢复隔离和最小权限 |

## 常见误区与故障注入

<Callout type="trap">

  中间仍可能有竞争、脏映射、丢中断、半提交元数据、泄漏对象或越权，必须检查首个内核状态变化和清理。
