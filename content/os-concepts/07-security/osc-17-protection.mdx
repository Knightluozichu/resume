## 核心机制深挖

从保护目标、原则和保护环进入保护域、访问矩阵、ACL、权能、基于语言保护和权利撤销。 每个目录概念都放回“定义保护对象 → 识别访问主体 → 查询访问矩阵 → 执行权利检查 → 传播或限制权利 → 撤销并审计”资源状态机。输入可能是系统调用、地址、字节流、中断、资源请求或远程消息；状态可能位于进程表、页表、设备队列、文件元数据、虚拟机或保护域；输出同时说明返回值、所有权与下一阶段可依赖的承诺。

本页不变量是：**每次对象操作由明确主体、域和权利授权；复制、所有权、控制与撤销语义一致，最小权限贯穿生命周期。**。正常和错误路径都必须保持它。一次成功只证明一个样本可用，不能证明边界安全；所以每项机制进入正常、边界、失败和恢复四条轨迹，并写清谁检测、谁阻塞或重试、谁逆序清理、谁上报。

用最小工作负载沿“定义保护对象 → 识别访问主体 → 查询访问矩阵 → 执行权利检查 → 传播或限制权利 → 撤销并审计”记录系统调用、内核对象和资源状态，再注入单一边界并重放。 运行前把预期写成快照，运行后逐字段比较。并发记录同步边，地址记录位宽权限，I/O 记录缓冲区与完成事件，持久化区分提交与落盘，分布式记录丢失、重复和重排。

注入权限、容量、时序或设备故障，在“定义保护对象”之后的首个偏离点停止，逆序清理并验证同一输入恢复。 删除故障后以相同输入重放，确认返回值、内核对象、外部结果和清理状态一起恢复。只修正末端输出却留下线程、页、设备请求、文件引用、虚拟状态或权限污染，仍不通过。

第10版使用 Linux、Windows 10、多核、NVM、云和容器作为实例。现代版本会改变实现与性能数值，但进程状态、地址翻译、I/O 分层、持久化、虚拟化隔离和保护域仍可验证。现代对照不能覆盖2018英文原版与2023中文出版版的目录身份。
