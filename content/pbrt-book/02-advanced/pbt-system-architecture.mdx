## 直觉引入

想象一座工厂。原材料（场景数据）进入流水线（渲染管线），经过不同车间（光线生成、求交、着色、积分），最终产出成品（像素）。PBRT 就是这座工厂的蓝图——它定义了每个组件的职责、组件之间如何协作、以及如何并行生产。

渲染是计算密集型任务，PBRT 的架构设计直接影响性能。好的架构能让渲染快10倍，差的架构能让理论正确的算法变得不可用。

## 代码对照

```cpp
// PBRT 并行渲染架构
void Render(Scene scene) {
    // 1. 构建 BVH 加速结构
    BVH bvh(scene.primitives);
    
    // 2. 瓦片化并行渲染
    int tileSize = 16;
    std::vector<Tile> tiles = generateTiles(film, tileSize);
    
    ParallelFor(tiles, [&](Tile tile) {
        Sampler sampler(tile.seed);
        for (auto pixel : tile.pixels) {
            for (int s = 0; s < sampler.SPP; s++) {
                CameraSample cs = sampler.GetCameraSample(pixel);
                Ray ray = camera.GenerateRay(cs);
                Spectrum L = integrator.Li(ray, scene, sampler);
                film.AddSample(pixel, L);
            }
        }
    });
    
    // 3. 写入图像
    film.WriteImage();
}
```

## 常见误区

<Callout type="trap">
**误区：认为渲染性能只取决于算法复杂度。**
实际性能受内存访问模式影响巨大。BVH 遍历中缓存未命中可能比三角形求交慢10倍。好的 BVH 构建算法（如 Morton 排序）不仅减少节点数，更优化内存局部性。
</Callout>

<Callout type="trap">
**误区：瓦片越小并行度越高越好。**
瓦片太小会导致每个瓦片的启动开销（采样器初始化、局部缓冲分配）占比增大，且瓦片间负载不均。瓦片太大则并行度不足。通常 16x16 到 64x64 是经验最佳值。
</Callout>

<Exercises>
**问题 1**：BVH 加速结构如何将光线-三角形测试从 O(N) 降到 O(logN)？

<Answer>
BVH 把场景组织成一棵二叉树：每个内部节点存储一个包围所有子节点的轴对齐包围盒(AABB)，叶子节点存储少量三角形。光线追踪时，从根节点开始，先测试光线是否与节点的 AABB 相交——不相交则跳过整个子树。只有到达叶子节点才进行三角形求交。由于每层只访问一个子树（或两个都访问但很快剔除一个），树高 log(N)，平均测试次数 O(logN)。
</Answer>

**问题 2**：为什么 PBRT 使用瓦片化并行渲染？瓦片大小如何影响性能？

<Answer>
瓦片化的优势：1）每个瓦片独立渲染，线程间无需同步（除瓦片分配）；2）瓦片内采样器和缓冲局部化，缓存友好；3）自然支持负载均衡（用无锁队列动态分配瓦片）。瓦片大小的影响：太小→启动开销大、负载不均；太大→并行度不足、内存占用高。通常 16x16~64x64 像素是最佳值，需根据缓存大小和场景复杂度调整。
</Answer>
</Exercises>
