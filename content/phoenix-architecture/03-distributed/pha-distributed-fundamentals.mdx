## CAP 定理

<PhaDistributedFundamentalsDiagram />

### 三要素

| 要素 | 含义 |
|------|------|
| C（Consistency 一致性） | 所有节点同一时刻看到相同数据，读总能返回最新写入值 |
| A（Availability 可用性） | 系统持续可用，每个请求都能在合理时间内收到非错误响应 |
| P（Partition Tolerance 分区容忍） | 网络分区（节点间通信中断）时系统仍能继续工作 |

<Callout type="warning" title="「三选二」是误导">

在分布式系统中，网络分区（P）是**客观存在、不可避免**的——网络总会断、节点总会挂。因此P不是「选择」而是「必须保证」的前提。实际选择是分区发生时在 **C 和 A 之间权衡**：

- **CP**：分区时拒绝写入（牺牲可用性）— ZooKeeper / etcd（宁可不可用，不可数据错）
- **AP**：分区时允许写入（牺牲一致性）— Cassandra / DynamoDB（宁可数据暂时不一致）

CAP不是「三选二」，而是「**分区发生时，C和A二选一**」。

</Callout>

## 分布式八大基本问题

| 问题 | 说明 |
|------|------|
| 网络不可靠 | 消息可能丢失、延迟、乱序 |
| 时钟不同步 | 各节点物理时钟无法完全同步，不能用绝对时间判断事件先后 |
| 消息延迟与乱序 | 发送顺序不等于接收顺序 |
| 节点故障 | crash-stop（崩溃不恢复）/ crash-recovery（崩溃后恢复） |
| 拜占庭故障 | 节点不仅崩溃，还可能发送错误/恶意信息 |
| 状态分歧 | 不同节点对同一数据有不同视图 |
| 部分失败 | 部分节点成功部分失败（单机系统不存在此问题） |
| 三态 | 调用结果：成功 / 失败 / **超时**（不知道对方成功还是失败） |

### 部分失败与三态

```
单机调用：         分布式调用：
  成功 ←─→ 失败      成功 ←─→ 失败
                        ↕
                     超时（第三态）
                  「不知道对方执行了没」
```

<Callout type="info" title="超时是最棘手的状态">

调用方不知道对方是否执行了操作。**重试**可能导致重复执行（需幂等），**不重试**可能导致操作丢失。对策：超时 + 重试 + 幂等 + 补偿事务。

</Callout>

## 逻辑时钟

为什么不能用物理时钟：①各节点NTP同步存在偏差；②时钟可能回拨；③即使完美同步，网络延迟不确定也无法用物理时间确定因果。

**Lamport逻辑时钟规则：**

1. 节点执行本地事件：`C = C + 1`
2. 节点发送消息：附带当前 `C` 值
3. 节点接收消息：`C = max(本地C, 消息C) + 1`

**性质：** 如果事件A因果先于事件B（`A → B`），则 `C(A) < C(B)`。但反过来不成立——`C(A) < C(B)` 不一定意味着因果有序（可能是并发事件）。Lamport时钟给出的是**偏序**。

## BASE 理论

BASE 是 CAP 中 AP 选择的工程实践延伸：

| 字母 | 含义 |
|------|------|
| BA | Basically Available 基本可用 — 故障时损失部分可用性但核心功能可用 |
| S | Soft State 软状态 — 允许存在中间状态 |
| E | Eventually Consistent 最终一致性 — 无新写入时最终所有副本收敛 |

<Glossary>

<GlossaryItem term="CAP定理">
分布式系统在网络分区时，一致性（C）和可用性（A）只能二选一，分区容忍（P）是不可放弃的前提。由Eric Brewer于2000年提出（猜想），2002年由Gilbert和Lynch证明（定理）。
</GlossaryItem>

<GlossaryItem term="部分失败（Partial Failure）">
分布式系统最本质的难点：一个操作涉及多个节点，可能部分成功部分失败。单机系统要么全成功要么全失败（原子性），分布式系统需要决定是回滚已成功的还是重试已失败的。
</GlossaryItem>

<GlossaryItem term="三态（Three States）">
单机调用只有成功/失败两态，分布式调用有第三态：超时——调用方不知道对方是否执行了操作。超时是最难处理的状态，需配合幂等和重试策略。
</GlossaryItem>

<GlossaryItem term="Lamport逻辑时钟">
Leslie Lamport提出的逻辑时钟算法，用「因果关系」而非「物理时间」定义事件顺序。每个节点维护单调递增计数器，通过消息传递时钟值建立事件间的偏序关系。是分布式系统事件排序的理论基础。
</GlossaryItem>

<GlossaryItem term="最终一致性（Eventual Consistency）">
BASE理论的核心：系统保证在没有新的更新操作时，最终所有副本会收敛到一致状态，但不保证任意时刻都一致。收敛时间取决于复制延迟、网络状况、副本数量。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** CAP定理的三要素是什么？为什么说「三选二」是误导？

<Answer>

三要素：C一致性（所有节点同一时刻看到相同数据）、A可用性（每个请求都能在合理时间内收到非错误响应）、P分区容忍（网络分区时系统仍能继续工作）。「三选二」是误导因为P是客观存在不可放弃的前提——分布式系统网络总会断、节点总会挂。实际选择是分区发生时在C和A之间权衡：CP（拒绝写入牺牲可用性，如etcd/ZooKeeper）、AP（允许写入牺牲一致性，如Cassandra/DynamoDB）。CA只在单机或无分区理想情况下成立。

</Answer>

**问题 2：** 什么是「部分失败」和「三态」？它们对系统设计有什么挑战？

<Answer>

部分失败：一个操作涉及多个节点时可能部分成功部分失败，单机系统不存在此问题（要么全成功要么全失败）。三态：分布式调用除了成功/失败还有第三态超时——调用方不知道对方是否执行了操作。挑战：超时时重试可能导致重复执行（需幂等保证），不重试可能导致操作丢失。对策是超时+重试+幂等+补偿事务的组合策略。

</Answer>

</Exercises>
