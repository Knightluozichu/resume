## 负载均衡

请求链路：`客户端 → 负载均衡 → 限流 → 熔断/降级 → 后端服务`

| 策略 | 说明 |
|------|------|
| 轮询 | 依次分发，简单 |
| 加权轮询 | 按服务器性能分配权重 |
| 最少连接 | 分发给当前连接数最少的节点 |
| 一致性哈希 | 相同Key固定路由（会话保持） |
| 随机 / IP哈希 | 随机或按客户端IP路由 |

| 层级 | 实现 |
|------|------|
| 四层（传输层） | LVS / Nginx（基于IP+端口） |
| 七层（应用层） | Nginx / Envoy / API Gateway（基于URL/Header） |

## 限流算法

| 算法 | 原理 | 特点 |
|------|------|------|
| 计数器 | 固定窗口内计数 | 简单但有临界突刺 |
| 滑动窗口 | 细分窗口平滑计数 | 平滑，无突刺 |
| 漏桶 | 恒定速率出水 | 输出匀速，不允许突发 |
| 令牌桶 | 恒定速率放令牌 | 允许突发流量（令牌可积累） |

<Callout type="info" title="漏桶 vs 令牌桶核心区别">

漏桶限制**处理速率**（出水恒定，不允许突发）；令牌桶限制**平均速率**但允许瞬时突发（桶中积累的令牌可瞬间消费）。

</Callout>

**集群限流：** Redis + Lua原子操作（读取计数+判断+递增），或网关层统一限流，或Sentinel Cluster模式（Token Server统一分配令牌）。

## 熔断器三态

```
    错误率超阈值          等待时间到
Closed ──────────> Open ──────────> Half-Open
  ↑                                       │
  │         试探成功                       │
  └───────────────────────────────────────┘
  │         试探失败
  └──────────────────> Open（重置计时）
```

| 状态 | 行为 |
|------|------|
| Closed（关闭） | 正常放行，监控错误率/慢调用 |
| Open（打开） | 快速失败，执行降级逻辑 |
| Half-Open（半开） | 放行少量试探请求，成功→Closed，失败→Open |

实现：Sentinel（阿里主流）/ Resilience4j（轻量）/ Hystrix（已停更）

## 降级

熔断或超时时执行的兜底策略：

| 降级方式 | 示例 |
|----------|------|
| 返回默认值 | 推荐服务不可用→返回默认推荐列表 |
| 返回缓存 | 商品服务不可用→返回缓存数据 |
| 返回兜底 | 支付服务不可用→返回「支付维护中」 |

<Callout type="warning" title="核心链路不降级">

核心链路（下单/支付）不降级，非核心（推荐/评论）优先降级。降级的目标是保核心功能存活，牺牲非核心功能。

</Callout>

## 超时与重试

| 维度 | 建议 |
|------|------|
| 连接超时 | 1s |
| 读超时 | 2-3s |
| 写超时 | 5s |
| 重试策略 | 指数退避 + 抖动 + 最大3次 |
| 重试前提 | 仅对幂等接口重试 |

<Callout type="warning" title="重试风暴 = 雪崩">

不加限制的重试会放大流量（1次失败→3次重试→9次请求），导致雪崩。重试必须配合熔断和限流，且仅对幂等接口重试。

</Callout>

## 幂等性设计

| 方式 | 原理 |
|------|------|
| 唯一ID + 去重表 | 请求携带唯一ID，处理前查重 |
| Token机制 | 先获取令牌，消费后失效 |
| 乐观锁（CAS） | `UPDATE ... WHERE version=X` |
| 状态机 | 只允许合法状态转换 |
| 数据库唯一约束 | 重复插入报错，捕获后返回已有结果 |

## 面向失败设计

<Callout type="info" title="Design for Failure">

**假设一切都会失败：** 网络会断 / 服务会挂 / 依赖会慢 / 数据会丢 / 时钟会偏。

**韧性 =** 限流（控流量）+ 熔断（快失败）+ 降级（保核心）+ 重试（恢临时故障）+ 幂等（安全重试）+ 超时（防资源耗尽）

**目标：** 局部故障不扩散为全局雪崩，系统在降级中继续提供核心服务。

</Callout>

<Glossary>

<GlossaryItem term="令牌桶算法">
限流算法。桶中以恒定速率放入令牌，请求处理前需取一个令牌。桶满则丢弃令牌。特点：允许突发流量（积累的令牌可瞬间消费），但平均速率受控。适合允许短时突发的场景。
</GlossaryItem>

<GlossaryItem term="熔断器（Circuit Breaker）">
灵感来自电路保险丝的韧性模式。监控下游服务错误率，超阈值时「熔断」（快速失败），避免级联故障。三态：Closed（正常）→Open（熔断）→Half-Open（试探恢复）。实现：Sentinel/Resilience4j。
</GlossaryItem>

<GlossaryItem term="幂等性（Idempotency）">
对同一操作执行一次和执行多次效果完全相同。分布式系统中由于超时重试必须保证幂等，否则会导致重复扣款/重复下单。实现：唯一ID去重表、Token机制、乐观锁、状态机。
</GlossaryItem>

<GlossaryItem term="舱壁模式（Bulkhead）">
资源隔离模式。将系统分为多个独立「舱壁」（如独立线程池），一个舱壁故障不影响其他。源自船舶水密舱设计。防止一个慢服务耗尽全局线程池拖垮整个系统。
</GlossaryItem>

<GlossaryItem term="面向失败设计（Design for Failure）">
分布式系统设计哲学。不追求「永不故障」（不可能），而是假设一切都会失败，通过韧性模式（限流/熔断/降级/重试/幂等/超时）让系统在局部故障时降级存活，不让局部故障扩散为全局雪崩。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 熔断器的三个状态是什么？状态转换的条件是什么？

<Answer>

三态：Closed（正常放行，监控错误率）、Open（快速失败执行降级，等待恢复时间）、Half-Open（放行少量试探请求）。转换条件：Closed→Open（错误率超阈值如50%或慢调用比例超阈值）；Open→Half-Open（等待时间到如5秒）；Half-Open→Closed（试探成功）；Half-Open→Open（试探失败，重置计时器）。

</Answer>

**问题 2：** 什么是「面向失败设计」？请设计一个防止级联雪崩的韧性方案。

<Answer>

面向失败设计：假设一切都会失败（网络断/服务挂/依赖慢/数据丢/时钟偏），用韧性模式让系统在降级中存活。防雪崩方案（全链路防护）：①入口限流（令牌桶控总QPS）+降级（保核心）②网关熔断（每服务独立熔断器）+超时（全局3s）③服务间调用超时分级+重试（指数退避+最大3次+仅幂等）+熔断+降级④资源隔离（舱壁模式/线程池隔离）⑤多级缓存（DB不可用返回缓存兜底）⑥MQ削峰⑦监控告警自动扩容。目标：局部故障不扩散为全局雪崩。

</Answer>

</Exercises>
