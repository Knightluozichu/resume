## 学习目标

- 理解四种数据源架构模式的内部结构和职责划分
- 掌握各模式与领域逻辑模式的配合关系
- 建立从表数据入口到数据映射器的解耦递进认知
- 能够根据系统复杂度选择合适的数据源模式

## 核心概念

### 数据源层的作用

数据源层负责将领域对象与数据库（或其他持久化存储）之间进行转换。它的核心目标是**让领域逻辑尽可能不感知数据库的存在**。

### 四种数据源模式

1. **表数据入口（Table Data Gateway）**——一个对象充当整张表的网关，提供 findAll / findById / insert / update / delete 等方法。返回 Record Set 供上层使用。领域逻辑与数据库访问完全分离。

2. **行数据入口（Row Data Gateway）**——每行记录对应一个对象实例，对象只含数据加持久化方法。无业务逻辑，纯粹的数据代理。

3. **活动记录（Active Record）**——行数据入口 + 领域逻辑。对象同时承载数据、行为和持久化。最常见的数据源模式，Rails ActiveRecord 即此模式。

4. **数据映射器（Data Mapper）**——独立的映射器负责持久化，领域对象完全不知道数据库存在。最高解耦，最复杂。Hibernate / TypeORM 的核心思想。

### 解耦程度递进

四种模式按解耦程度递进排列：

**表数据入口 → 行数据入口 → 活动记录 → 数据映射器**

从表级网关到行级代理，从领域逻辑混合到完全分离，领域对象与数据库的耦合度逐渐降低。

### 与领域逻辑模式配合

| 领域逻辑模式 | 配合的数据源模式 | 场景 |
|-------------|-----------------|------|
| 事务脚本 | 表数据入口 | 简单系统 |
| 表模块 | 表数据入口 | 中等复杂度 |
| 活动记录 | 活动记录 | 中等 / 单表逻辑 |
| 领域模型 | 数据映射器 | 复杂 / 领域模型 |

### 选择依据

- 简单 CRUD 系统 → 表数据入口 + 事务脚本
- 中等复杂度、与表结构对齐 → 表数据入口 + 表模块
- 中等复杂度、单表逻辑 → 活动记录
- 复杂领域逻辑 → 数据映射器 + 领域模型

## 术语表

| 术语 | 释义 |
|------|------|
| 表数据入口 | 充当整张表网关的数据源模式 |
| 行数据入口 | 每行记录对应一个对象实例的数据源模式 |
| 活动记录 | 行数据入口加领域逻辑的数据源模式 |
| 数据映射器 | 独立映射器负责持久化的数据源模式 |
| Record Set | 表数据的内存表示 |
| 网关 | 封装外部系统访问的对象 |
| 解耦 | 降低模块间的依赖关系 |
| 持久化 | 将对象状态保存到持久存储 |
