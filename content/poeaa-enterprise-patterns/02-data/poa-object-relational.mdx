## 核心概念

### 对象关系阻抗失配

面向对象的领域模型与关系型数据库之间存在天然的结构差异——对象有继承、聚合、引用，而表只有行、列、外键。ORM（Object-Relational Mapping）的核心任务就是弥合这一失配。

### 映射基础模式

| 模式 | 作用 |
|------|------|
| 标识域 Identity Field | 为对象保存数据库主键，维持对象身份 |
| 外键映射 Foreign Key Mapping | 将对象间引用映射为表间外键 |
| 关联表映射 Association Table Mapping | 多对多关系通过中间关联表实现 |
| 依赖映射 Dependent Mapping | 子对象由父对象负责映射 |
| 嵌入值 Embedded Value | 将小对象映射为所属表的若干列 |
| 序列化大对象 Serialized LOB | 将对象图序列化为大对象存储 |

### 核心 ORM 机制

**元数据映射（Metadata Mapping）**——用元数据描述对象与表的对应关系，映射器基于元数据自动完成 CRUD。是所有 ORM 框架的核心。

**标识映射（Identity Map）**——在一次工作范围内，确保每个数据库行只加载为一个对象实例。防止重复查询产生不一致的对象。

**工作单元（Unit of Work）**——维护一次业务操作中所有被修改的对象变更列表，在 commit 时统一同步到数据库。保证事务一致性。

**延迟加载（Lazy Load）**——对象关联的数据在首次被访问时才从数据库加载。减少不必要的数据传输。

### 三大机制协同

查询时先查标识映射 → 命中则复用，未命中则查询数据库 → 修改对象时工作单元记录变更 → 提交时工作单元统一执行 SQL → 标识映射保证一致性。三者共同保证了「一个事务内一个对象一份变更」的 ORM 基本契约。

### 资源库 Repository

将数据访问抽象为类似集合的接口——add / remove / findByCriteria。是领域层面对持久化的最高抽象。内部封装数据映射器，向上提供面向领域的查询接口。

### 延迟加载的四种方式

1. **虚代理（Lazy Initialization）**——首次访问时加载
2. **值占位符（Value Holder）**——包装实际值
3. **重写（Virtual Proxy）**——子类化实现延迟
4. **查询对象延迟**——真正迭代时才执行 SQL

|------|------|
| 元数据映射 | 用元数据描述对象-表对应关系的机制 |
| 标识映射 | 保证一个事务内同一行只加载为一个对象 |
| 工作单元 | 维护对象变更列表并统一提交的模式 |
| 延迟加载 | 数据在首次访问时才从数据库加载 |
| 资源库 | 将数据访问抽象为集合操作的模式 |

| 外键映射 | 将对象引用映射为表间外键 |
| 关联表映射 | 多对多关系通过中间表实现 |
| 查询对象 | 用对象构建查询条件避免手写 SQL |
| 阻抗失配 | 对象模型与关系模型的结构差异 |
