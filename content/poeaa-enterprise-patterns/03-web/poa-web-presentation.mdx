## 核心概念

### Web 表现层的挑战

Web 表现层需要处理 HTTP 请求的无状态性、URL 路由、输入验证、视图渲染、认证授权等问题。Fowler 提供了一套完整的模式来组织这些职责。

### MVC 模式

MVC（Model-View-Controller）是 Web 表现层最经典的模式：

- **模型（Model）**——领域逻辑和数据状态
- **视图（View）**——渲染输出 HTML
- **控制器（Controller）**——协调输入输出

工作流程：控制器接收请求 → 操作模型 → 选择视图渲染。

### 控制器模式

| 模式 | 特点 | 适用场景 |
|------|------|----------|
| 页面控制器 | 每页一个控制器，处理该页请求 | 页面少、逻辑简单 |
| 前端控制器 | 单一入口处理所有请求 | 中大型应用 |
| 应用控制器 | 根据 URL 映射到处理器 | 需要集中路由 |

### 视图模式

1. **模板视图（Template View）**——在 HTML 中嵌入动态标记，如 JSP / ERB / Razor。
2. **转换视图（Transform View）**——将领域数据逐个转换为 HTML 节点，如 XSLT。
3. **两步视图（Two Step View）**——先生成逻辑屏幕，再转 HTML，支持多主题。

### 辅助模式

- **视图助手（View Helper）**——辅助类处理视图中的逻辑
- **截断过滤器（Intercepting Filter）**——请求前后链式处理认证/日志
- **命令（Command）**——封装请求为对象，支持撤销/队列

### 请求处理流程

完整的请求处理流程：

**前端控制器 → 过滤器链 → 应用控制器 → 模板视图 → HTML 响应**

## 术语表

| 术语 | 释义 |
|------|------|
| MVC | 模型-视图-控制器，分离业务/展示/协调的架构模式 |
| 页面控制器 | 每个页面对应一个控制器的模式 |
| 前端控制器 | 单一入口处理所有请求的模式 |
| 应用控制器 | 集中管理 URL 到处理器映射的模式 |
| 模板视图 | 在 HTML 中嵌入动态标记的视图模式 |
| 转换视图 | 将数据逐个转换为 HTML 的视图模式 |
| 两步视图 | 先生成逻辑屏幕再转 HTML 的视图模式 |
| 视图助手 | 辅助处理视图逻辑的类 |
| 截断过滤器 | 请求前后链式处理的模式 |
| 命令 | 封装请求为对象的模式 |
