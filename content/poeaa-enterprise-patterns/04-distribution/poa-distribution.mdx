## 学习目标

- 理解分布式对象的第一法则及其背后的代价
- 掌握远程外观模式如何最小化远程调用次数
- 理解数据传输对象（DTO）的设计原则和组装逻辑
- 建立在「何时该分布式」和「如何最小化分布式代价」之间的决策能力

## 核心概念

### 分布式对象的第一法则

Fowler 的名言：**分布式对象的第一法则：不要分布式**。

<PoaDistributionDiagram />

### 分布式的四大代价

| 代价 | 说明 |
|------|------|
| 网络延迟 | 远程调用比本地方法调用慢几个数量级 |
| 序列化开销 | 对象需要编解码才能在网络传输 |
| 可靠性降低 | 网络不可靠，需处理超时、重试、部分失败 |
| 部署复杂 | 多节点部署和运维成本高 |

### 远程外观 Remote Facade

领域对象的方法通常是细粒度的（每个方法只做一小件事），直接远程调用会产生大量网络往返。远程外观将多个细粒度操作合并为一次粗粒度远程调用。

**工作原理**：远程外观本身不包含业务逻辑，只是将领域模型的细粒度操作适配为远程友好的粗粒度调用。

### 数据传输对象 DTO

DTO 是在远程调用间传递数据的纯数据容器。

**特征**：
- 无行为，纯数据结构
- 序列化友好（JSON / Protobuf）
- 扁平化对象图，减少嵌套
- 可组装不同领域对象的子集

**远程外观 + DTO = 分布式通信的最小单元**。

### 何时该分布式

分布式不是默认选择，而是在以下需求驱动时才采用：

1. **团队协作需要**——独立团队独立部署
2. **性能瓶颈隔离**——独立扩展热点模块
3. **技术异构**——不同语言/平台协作

### 最佳实践

优先单体 → 必要时拆分 → 用远程外观 + DTO 最小化远程调用。

## 术语表

| 术语 | 释义 |
|------|------|
| 远程外观 | 将细粒度操作聚合为粗粒度远程调用的模式 |
| DTO | 在远程调用间传输数据的纯数据容器 |
| 序列化 | 将对象转换为可传输格式的过程 |
| 分布式代价 | 分布式带来的延迟、开销、复杂度 |
| 粗粒度 API | 每次调用完成更多工作的接口 |
| 细粒度 API | 每次调用只做一小件事的接口 |
| 会话亲和 | 请求需要路由到同一服务实例 |
| 微服务 | 分布式架构的实践形式 |
