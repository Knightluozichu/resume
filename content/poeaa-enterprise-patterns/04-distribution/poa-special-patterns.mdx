## 核心概念

### 特殊模式的定位

除了分层架构、领域逻辑、数据源、Web 表现和分布式等主要模式外，Fowler 还提供了一组处理特殊场景的模式——离线并发、全局查找、动态扩展、测试隔离等。

### 离线并发控制

当用户在离线状态下编辑数据后重新提交，需要离线并发控制：

| 模式 | 机制 | 适用场景 | 优势 |
|------|------|----------|------|
| 乐观离线锁 | 提交时验证版本号 | 冲突概率低 | 不阻塞，高可用 |
| 悲观离线锁 | 编辑前获取独占锁 | 冲突概率高 | 无冲突，强一致 |

配合锁管理策略：
- **粗粒度锁**——锁定一组相关对象，避免死锁
- **隐式锁**——框架自动管理锁的获取和释放

### 注册表模式 Registry

提供一个全局对象查找入口，替代到处传递引用。通过 getPerson(id) / findXxx() 等方法获取对象实例。

**注意事项**：生命周期管理、线程安全、可测试性、避免过度使用。

### 其他特殊模式

| 模式 | 作用 |
|------|------|
| 值列表持有者 | 缓存查询结果集，减少重复 DB 查询 |
| 插件 Plugin | 运行时动态加载实现，配置驱动装配 |
| 服务桩 Service Stub | 外部服务的测试替身，隔离依赖 |
| 记录集 Record Set | 表数据的内存表示，与 UI 绑定 |

### 离线编辑工作流程

完整的离线编辑流程：

**获取数据 + 版本号 → 离线编辑 → 提交验证版本 → 成功/冲突处理 → 完成**
