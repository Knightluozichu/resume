## 为什么 第二部分 模式 值得单独学习

用10个模式族、51个模式形成可检索参考，每个选择都必须包含适用条件、替代方案和代价。 第二部分 模式 的核心不是套用某个框架 API，而是回答：如何保持目录范围、模式族关系与实际架构问题之间的一一对应。在 订单系统架构评审 中，如果无法说清责任、状态和失败由谁承担，即使正常请求能够返回，架构决定也没有完成。

本页以 2024 年中文版公开目录限定 **第二部分 模式** 的范围，并依据 Martin Fowler 的作者图书页和模式目录独立重写。它不复现原书正文、插图或代码；目录只决定“要讲什么”，这里的案例、实验、判断题和答案均为本课程原创。

## 先建立直觉：问题、机制与代价

第二部分 模式 面对的具体压力是“单元覆盖、跨族依赖与可追溯来源”。它采用的机制可以概括为：用10个模式族、51个模式形成可检索参考，每个选择都必须包含适用条件、替代方案和代价。 机制带来的收益必须与新增间接层、同步责任或迁移成本同时记录，否则学习者只会得到一个没有拒绝条件的模式名称。

对 第二部分 模式，优先比较的替代路线是：按真实问题进入模式族，而不是把模式名称当作采购清单。本页的通过条件是“能按问题而非流行框架选择模式，并用基线、临界与受控故障场景验证”；若实验只能显示结果而不能指出 10个模式族 从何处越界，就不能据此选择 第二部分 模式。

## 目录单元到教学证据

### 第二部分 模式

在 **第二部分 模式** 的学习边界里，第二部分 模式 不是待背诵的目录词，而是用来检查“问题识别”是否把责任交给正确对象。对 订单系统架构评审，学习者要记录 10个模式族 的可观察变化，并说明它何时支持或否定 第二部分 模式。

## 专属设计案例：订单系统架构评审

把 订单系统架构评审 切成“问题识别 → 模式族 → 模式机制 → 协作组合 → 取舍验证”五个观察点。第二部分 模式 的设计草案必须写出谁拥有状态、谁作出业务决定、失败怎样传播，以及 10个模式族、51个模式、使用时机、协作模式、失败边界 中哪个指标最先提示当前方案不再适用。

设计记录采用五个可换行字段：单元键为 **poeaa24-part-02-patterns**；模式族为 **book**；裁决是“能按问题而非流行框架选择模式，并用基线、临界与受控故障场景验证”；观测项包括 10个模式族、51个模式、使用时机、协作模式、失败边界；拒绝条件是“10个模式族 超过团队为 第二部分 模式 设定的边界”。

配置不是生产框架语法，而是一张评审卡。对 第二部分 模式 的任何实现都要能把运行证据重新映射到这张卡；如果更换 ORM、Web 框架或部署平台后无法回答同一组问题，说明决定依赖的是工具偶然行为而不是模式语义。

## 选择与拒绝矩阵

| 评审问题 | 选择 第二部分 模式 的证据         | 应拒绝或改用其他方案的信号                       |
| -------- | --------------------------------- | ------------------------------------------------ |
| 责任     | 问题识别 到 取舍验证 的所有者清晰 | 模式族 可以绕过边界直接改写状态                  |
| 变化     | 10个模式族 的变化被局部吸收       | 一次小改动同时触及 51个模式、使用时机、协作模式  |
| 失败     | 故障能在 取舍验证 前被识别并回退  | 只能看到最终错误，无法定位 10个模式族 的首个异常 |
| 替代     | 已与同族候选比较并保留撤回路径    | 因框架内置或团队习惯而跳过问题分析               |

## 本章小结

掌握 第二部分 模式 的标志不是记住定义，而是能在 订单系统架构评审 中解释“问题识别 → 模式族 → 模式机制 → 协作组合 → 取舍验证”的责任链，利用 10个模式族、51个模式、使用时机、协作模式、失败边界 作出可证伪的选择，并在出现“把目录节点当成正文结论”时明确拒绝当前实现。

<Exercises>

1. 为 第二部分 模式 写一条最小设计合同：哪一个输入变化必须引起哪一个可观察结果？

<Answer>
  以 订单系统架构评审 为例，固定 问题识别 的输入和 取舍验证 的期望结果，只改变
  10个模式族；合同必须说明 第二部分 模式
  在何值接受、何值拒绝，以及拒绝后怎样恢复到初始状态。
</Answer>

2. 在什么情况下不应选择 第二部分 模式？

<Answer>
  当“能按问题而非流行框架选择模式，并用基线、临界与受控故障场景验证”无法成立，或
  10个模式族、51个模式
  的主要变化会同时穿透多个责任边界时，应回到同族候选比较。不能因为框架提供同名类或注解就继续使用
  第二部分 模式。
</Answer>

3. 如何证明本页目录节点不是只在文字里出现？

<Answer>
  对 第二部分 模式
  逐项执行责任、取舍和失败实验；每个概念都要连接一个观察点、一条裁决和一次复位记录。若任一概念只有名称而没有
  10个模式族 或 51个模式 的验证证据，本页仍不通过。
</Answer>
