## 为什么 12.8 类表继承 值得单独学习

为继承层次中的每个类建立一张表，通过共享身份连接父类与子类数据。 12.8 类表继承 的核心不是套用某个框架 API，而是回答：如何在对象身份、关联、继承和写回之间保住一致语义，同时控制查询与映射成本。在 订单聚合持久化 中，如果无法说清责任、状态和失败由谁承担，即使正常请求能够返回，架构决定也没有完成。

本页以 2024 年中文版公开目录限定 **12.8 类表继承** 的范围，并依据 Martin Fowler 的作者图书页和模式目录独立重写。它不复现原书正文、插图或代码；目录只决定“要讲什么”，这里的案例、实验、判断题和答案均为本课程原创。

## 先建立直觉：问题、机制与代价

12.8 类表继承 面对的具体压力是“同一身份实例数、查询次数、脏对象集合与关联装载范围”。它采用的机制可以概括为：为继承层次中的每个类建立一张表，通过共享身份连接父类与子类数据。 机制带来的收益必须与新增间接层、同步责任或迁移成本同时记录，否则学习者只会得到一个没有拒绝条件的模式名称。

对 12.8 类表继承，优先比较的替代路线是：根据领域复杂度选择入口、活动记录、映射器、工作单元及结构映射组合。本页的通过条件是“能正确连接多级表并保持身份唯一，同时测量读取联接和写入事务的成本”；若实验只能显示结果而不能指出 标识 从何处越界，就不能据此选择 12.8 类表继承。

## 目录单元到教学证据

### 12.8 类表继承

在 **12.8 类表继承** 的学习边界里，12.8 类表继承 不是待背诵的目录词，而是用来检查“对象图”是否把责任交给正确对象。对 订单聚合持久化，学习者要记录 标识 的可观察变化，并说明它何时支持或否定 12.8 类表继承。

## 专属设计案例：订单聚合持久化

把 订单聚合持久化 切成“对象图 → 身份 → 关联 → 继承 → 关系模式”五个观察点。12.8 类表继承 的设计草案必须写出谁拥有状态、谁作出业务决定、失败怎样传播，以及 标识、外键、聚合边界、值对象、继承策略 中哪个指标最先提示当前方案不再适用。

设计记录采用五个可换行字段：单元键为 **poeaa24-pattern-19-class-table-inheritance**；模式族为 **mapping**；裁决是“能正确连接多级表并保持身份唯一，同时测量读取联接和写入事务的成本”；观测项包括 标识、外键、聚合边界、值对象、继承策略；拒绝条件是“标识 超过团队为 12.8 类表继承 设定的边界”。

配置不是生产框架语法，而是一张评审卡。对 12.8 类表继承 的任何实现都要能把运行证据重新映射到这张卡；如果更换 ORM、Web 框架或部署平台后无法回答同一组问题，说明决定依赖的是工具偶然行为而不是模式语义。

## 选择与拒绝矩阵

| 评审问题 | 选择 12.8 类表继承 的证据        | 应拒绝或改用其他方案的信号                 |
| -------- | -------------------------------- | ------------------------------------------ |
| 责任     | 对象图 到 关系模式 的所有者清晰  | 身份 可以绕过边界直接改写状态              |
| 变化     | 标识 的变化被局部吸收            | 一次小改动同时触及 外键、聚合边界、值对象  |
| 失败     | 故障能在 关系模式 前被识别并回退 | 只能看到最终错误，无法定位 标识 的首个异常 |
| 替代     | 已与同族候选比较并保留撤回路径   | 因框架内置或团队习惯而跳过问题分析         |

  的代价，也无法证明方案可以复位或撤回。

## 本章小结

掌握 12.8 类表继承 的标志不是记住定义，而是能在 订单聚合持久化 中解释“对象图 → 身份 → 关联 → 继承 → 关系模式”的责任链，利用 标识、外键、聚合边界、值对象、继承策略 作出可证伪的选择，并在出现“把数据库行和内存对象的身份生命周期视为天然相同”时明确拒绝当前实现。

<Exercises>

1. 为 12.8 类表继承 写一条最小设计合同：哪一个输入变化必须引起哪一个可观察结果？

<Answer>
  以 订单聚合持久化 为例，固定 对象图 的输入和 关系模式 的期望结果，只改变
  标识；合同必须说明 12.8 类表继承
  在何值接受、何值拒绝，以及拒绝后怎样恢复到初始状态。
</Answer>

2. 在什么情况下不应选择 12.8 类表继承？

<Answer>
  当“能正确连接多级表并保持身份唯一，同时测量读取联接和写入事务的成本”无法成立，或
  标识、外键
  的主要变化会同时穿透多个责任边界时，应回到同族候选比较。不能因为框架提供同名类或注解就继续使用
  12.8 类表继承。
</Answer>

  标识 或 外键 的验证证据，本页仍不通过。
</Answer>
