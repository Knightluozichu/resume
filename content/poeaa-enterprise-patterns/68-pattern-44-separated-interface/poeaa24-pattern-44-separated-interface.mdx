## 为什么这一单元不可压缩

本页依据马丁·福勒《企业应用架构模式》，王怀民、周斌译，机械工业出版社，2024年2月，ISBN 9787111746959，400页的公开完整中文目录，独立重构 **18.4 分离接口**。18.4 分离接口（Separated Interface）不是类名清单，而是对一个反复出现的企业应用问题、作用边界和后果的命名。把接口放在与实现不同的包中，使高层策略可以依赖抽象而不依赖实现部署。课程不复制原书正文、插图、代码或练习答案，而是把目录命题改写为新的架构模型、应用切片、交互实验、失败样本和可重放证据。

2024年中文版目录逐项列出译者序、前言、模式列表、引言及5节、两部分、18章、第1至8章38个叙述小节、第9至18章51个模式和参考文献，共76个正式单元、119个目录节点。Martin Fowler 官方图书页确认本书围绕企业应用的分层、领域逻辑、数据库映射、Web 表示、并发、会话和分布展开；作者官方目录逐项列出51个模式，Pearson 原版目录交叉确认18章。目录坐标决定学习分母，框架流行度不能替代原书结构。

本书出版语境早于今天常见的 ORM、依赖注入容器和 Web 框架。现代框架把工作单元、身份映射、前端控制器或数据传输对象封装成默认机制，却没有消除事务范围、对象身份、调用粒度、部分失败和一致性之间的裁决。学习者必须能在框架失效、默认值变化或边界跨进程时重新推导这些决定。

## 四个可手算模型

远程调用的粗略成本把往返延迟和载荷传输分开：

$$
C_r = n \times l + p / b
$$

其中 $n$ 是远程往返次数，$l$ 是单次延迟，$p$ 是载荷字节数，$b$ 是有效带宽。优化序列化却不减少高延迟往返，通常不会改变主导项。

对象关系映射成本由身份、关联、继承和变更跟踪共同决定：

$$
C_m = i + a + h + t
$$

并发风险不是数据库行数，而是重叠概率、业务事务持续时间和热点竞争的组合：

$$
R_c = o \times d \times q
$$

发布门禁采用乘法含义：内容覆盖、正常样本、边界样本、故障样本和独立复核任何一项为零，整体就不能通过。

$$
G = c 	imes n 	imes e 	imes f 	imes r
$$

这些式子不是生产容量模型，而是迫使设计者公开假设、单位和主导变量。先手算再运行交互实验；若工具结果与预期不同，保存最早出现差异的边界，不要从最终异常反向猜测。

## 原书目录坐标与核心机制

### 18.4 分离接口

英文模式名：**Separated Interface**。把接口放在与实现不同的包中，使高层策略可以依赖抽象而不依赖实现部署。

该模式必须与同族候选比较：18.1 入口（Gateway）、18.2 映射器（Mapper）、18.3 层超类型（Layer Supertype）、18.5 注册表（Registry）、18.6 值对象（Value Object）、18.7 货币（Money）、18.8 特殊情况（Special Case）、18.9 插件（Plugin）、18.10 服务桩（Service Stub）、18.11 记录集（Record Set）。选择时分别记录问题复杂度、对象与数据边界、事务范围、调用粒度和替换成本，不能因为框架内置就跳过裁决。

验收要求：能从高层模块替换一个实现，检查依赖方向，并证明接口包不反向引用实现。

### 问题、语境、机制与后果

任何模式裁决先写问题：哪个变化、失败或复杂度正在伤害系统；再写语境：数据规模、团队边界、事务与部署约束是否成立；然后写机制：责任移到哪里、依赖方向怎样改变、状态由谁拥有；最后写后果：获得什么，同时增加了哪些间接层、同步成本和调试难度。

对18.4 分离接口，最小证据链是“调用者 → 抽象边界 → 适配机制 → 协作者 → 结果”。1. 依赖方向必须有一个可观察指标和一个拒绝阈值；2. 对象语义必须有一个可观察指标和一个拒绝阈值；3. 配置必须有一个可观察指标和一个拒绝阈值；4. 测试隔离必须有一个可观察指标和一个拒绝阈值；5. 表示转换必须有一个可观察指标和一个拒绝阈值。只画静态类图不足以证明事务、加载、远程失败或会话过期行为，因此本页把拓扑、映射和事务证据拆成三个视图。

## 最小实现骨架

第一段代码让应用服务只编排用例、事务与端口，领域规则仍由领域对象承担：

```ts
type Decision = { accepted: boolean; reason: string };

async function executeUseCase(command: Command): Promise<Decision> {
  return unitOfWork.run(async () => {
    const aggregate = await repository.get(command.id);
    const decision = aggregate.apply(command);
    if (!decision.accepted) return decision;
    await repository.save(aggregate);
    return decision;
  });
}
```

第二段显式记录版本，允许离线业务事务在提交点检测冲突：

```sql
UPDATE orders
SET status = :status, version = version + 1
WHERE order_id = :id AND version = :expected_version;
-- affected_rows must equal 1
```

第三段把模式决定写成可审查配置，而不是让框架默认值成为隐含架构：

```yaml
architecture_decision:
  unit: poeaa24-pattern-44-separated-interface
  transaction: one-use-case
  remote_calls_max: 4
  conflict_policy: reject-and-reload
  evidence: [normal, exact-boundary, single-fault]
```

代码骨架故意不绑定具体框架。迁移到 Spring、Jakarta、.NET、Rails 或其他栈时，应逐项映射工作单元、身份范围、异常翻译和请求生命周期；若框架只覆盖机制的一部分，剩余责任必须由应用明确承担。

## 选择矩阵与迁移策略

| 决策轴   | 低复杂度候选         | 高复杂度候选                     | 拒绝信号                       |
| -------- | -------------------- | -------------------------------- | ------------------------------ |
| 领域规则 | 事务脚本或表模块     | 领域模型与服务层协作             | 规则在控制器、SQL和模板间重复  |
| 数据映射 | 活动记录或入口对象   | 数据映射器、工作单元、资源库     | 同一身份出现冲突对象或部分写入 |
| Web 表示 | 页面控制器与模板视图 | 前端控制器、应用控制器、两步视图 | 认证、导航或业务规则散落       |
| 分布     | 保持本地调用         | 远程外观与DTO组成粗粒度边界      | 循环远程调用、内部对象直接越界 |
| 并发会话 | 短系统事务、无状态   | 明确离线锁和权威会话位置         | 静默覆盖、锁失主或会话不可清理 |

迁移顺序从观测开始：先记录当前查询、往返、事务、冲突和错误；再把一个用例放进新边界；随后以双读或影子流量比较语义；最后才删除旧路径。数据库结构、对象模型和远程契约不要同批无证据更换，否则首差无法归因。

<Callout type="trap" title="陷阱：把模式当成必须使用的零件">
  模式描述的是反复出现的问题与取舍，不是架构完成度清单。没有对象关系阻抗时强加数据映射器，或没有远程边界时先造DTO，都会增加间接层而不解决真实问题。
</Callout>

<Callout type="trap" title="陷阱：把框架默认值当成已验证边界">
  ORM 会话、Web
  请求和数据库事务的生命周期并不天然相同。必须用关闭会话后的延迟加载、并发提交、超时重试和部分失败样本验证，不能因为正常演示成功就宣布通过。
</Callout>

## 可重放证据与独立复核

每次实验保存版次、目录坐标、需求、代码哈希、迁移版本、工具版本、输入、初始数据库快照、时钟与单位；随后保存预期链、实际链、查询与远程轨迹、事务结果、首差和回退点。敏感数据只保留结构化摘要和不可逆标识，证据仍要足以重放。

独立复核者不能读取实现者的结论，只接收合同和样本。他先手算四个模型，再运行相同正常、边界和故障输入；双方必须在相同节点接受或拒绝，并能解释差异来自模式假设、框架机制还是环境。若只能复现最终错误却不能定位首差，证据仍不合格。

## 本章回顾

18.4 分离接口的掌握标准是把“调用者 → 抽象边界 → 适配机制 → 协作者 → 结果”变成可观察、可比较、可撤回的架构决定。记住模式名只能帮助检索；真正的能力是从问题和语境出发比较候选，明确机制与后果，再用正常、恰好边界、单故障和独立复核关闭证据链。
