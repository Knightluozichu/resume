## 学习目标

- 掌握 DRY 原则，理解知识唯一性的重要性
- 理解正交性，学会消除不相关事物间的影响
- 掌握可逆性，保持设计决策的灵活
- 学会用曳光弹验证架构，用原型探索未知
- 掌握估算方法，用量化数据支撑决策

## 核心概念

### DRY 原则

DRY（Don't Repeat Yourself）是务实方法的基石：**系统中的每个知识点应当有唯一的、权威的表示**。

<PpApproachDiagram />

重复不仅仅是代码重复，还包括：
- 数据模式的重复
- 测试逻辑的重复
- 构建配置的重复
- 文档与代码的重复

**重复 = 维护灾难的根源**——修改一个知识点需要多处同步，遗漏任何一处就会产生不一致。

### 正交性

正交性是指**消除不相关事物间的影响**。两个组件如果修改其中一个不会影响另一个，则它们是正交的。

评估正交性的方法：
- **自上而下设计**：先定义各层职责，再实现
- **分层架构**：各层只通过定义良好的接口通信
- **测试隔离**：修改一个模块的测试不需要修改其他模块
- **变化局部化**：需求变更只影响一个模块

### 可逆性

如果某个决定可逆，就大胆尝试。保持可逆性的方法：
- 不要锁定架构，选择允许变化的设计
- 用抽象层隔离变化，具体实现可替换
- 用配置驱动决策，运行时可改
- 避免过早优化

**终极工具 = 抽象层 + 配置驱动**

### 曳光弹与原型

| 特性 | 曳光弹 | 原型 |
|------|--------|------|
| 目的 | 验证架构打通链路 | 探索未知验证概念 |
| 代码 | 保留并演进 | 用完即弃 |
| 质量 | 生产级 | 可忽略正确性 |
| 用途 | 全链路集成 | 单点探索 |

曳光弹 = 保留，原型 = 丢弃。

### 估算

估算帮助量化决策：
- **理解量级**：小时 / 天 / 周 / 月
- **基于模型**：用公式或类比估算
- **检查循环**：估算后验证，记录偏差
- **持续校准**：记录估算结果，持续改进

## 术语表

| 术语 | 释义 |
|------|------|
| DRY | Don't Repeat Yourself，知识唯一性原则 |
| 正交性 | 消除不相关事物间的影响 |
| 可逆性 | 决策可被逆转的程度 |
| 曳光弹 | 用最小代码打通全链路验证架构 |
| 原型 | 用完即弃的探索代码 |
| 估算 | 对工作量的量化预测 |

## 练习题

1. 什么是 DRY 原则？为什么它如此重要？
2. 什么是正交性？如何评估代码的正交性？
3. 曳光弹与原型设计有何区别？何时用哪个？
4. 什么是可逆性？如何在设计中保持可逆性？
