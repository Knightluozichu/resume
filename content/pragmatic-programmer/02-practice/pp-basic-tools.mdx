## 学习目标

- 理解纯文本作为通用数据格式的优势
- 掌握 Shell 作为工具组合积木的使用方法
- 学会熟练使用编辑器，达到肌肉记忆
- 掌握版本控制作为项目真相之源的用法
- 理解科学调试方法，避免巧合编程

## 核心概念

### 工具栈分层

工具是手的延伸。务实程序员选好工具、用熟工具、让工具帮你做重复的事。

<PpBasicToolsDiagram />

### 纯文本

纯文本是人类与机器之间的通用接口：

- **人类可读**：无需专门工具即可查看
- **不会过时**：文本格式比任何二进制格式都长寿
- **易于测试**：可用 diff、grep、管道处理
- **版本控制友好**：变更可被精确追踪
- **互操作性好**：所有系统都能读写文本

### Shell

Shell 是工具组合的积木：

- **管道组合**：将多个命令串联，完成复杂任务
- **自动化**：将重复操作脚本化
- **构建/部署**：一条命令完成构建和部署
- **批处理**：批量处理文件和数据

### 编辑器

编辑器应熟练到**肌肉记忆**程度：

- **流式编辑**：连续编辑不需停下来找菜单
- **快捷键**：掌握核心操作的键盘快捷键
- **模板和代码片段**：一键展开重复代码
- **宏**：录制重复操作序列
- **自动补全**：利用 IDE 智能补全

### 版本控制

VCS 不仅仅是代码管理，它是项目的**真相之源**：

| 用途 | 说明 |
|------|------|
| 真相之源 | 代码仓库是项目状态的唯一权威记录 |
| 时间机器 | 可以回到任何历史版本 |
| 分布式协作 | 多人并行开发，通过合并汇聚 |
| 实验沙箱 | 用分支做实验，失败则丢弃 |
| 发布管理 | 用标签标记发布版本 |
| 审计追踪 | 每次变更都有记录 |

### 科学调试

科学调试用科学方法定位 bug：

1. **复现**：稳定复现问题
2. **观察**：收集错误信息、日志、堆栈
3. **假设**：基于观察提出原因假设
4. **实验**：设计最小实验验证假设
5. **修正**：验证通过则修复

**勿用巧合编程**——不要随机修改碰运气。

### 代码生成器

代码生成器分为两类：

- **被动生成**：用向导/模板一次性生成，生成后可自由修改
- **主动生成**：构建时根据模板和元数据自动生成，模板是权威的

**一次编写，多次运行**——DRY 的实践工具。
