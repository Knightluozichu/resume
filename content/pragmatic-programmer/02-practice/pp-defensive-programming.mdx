## 学习目标

- 掌握契约式设计（DBC），用前置/后置条件和不变式定义责任
- 理解「死程序说真话」，学会早崩溃优于带病运行
- 掌握断言式编程，验证不可能发生的事
- 学会正确使用异常处理，区分异常与错误码

## 核心概念

### 防御式编程的理念

防御式编程的核心假设：**一切都会出错**。你的代码会被错误调用、传入非法参数、遇到不可预期的状态。防御式编程的目标是确保即使出错也不会造成更大伤害。

### 契约式设计（DBC）

契约式设计通过「契约」明确模块间的责任边界：

| 要素 | 谁负责 | 说明 |
|------|--------|------|
| 前置条件 | 调用方 | 必须满足的条件（如参数非空） |
| 后置条件 | 被调方 | 必须保证的结果（如返回值范围） |
| 不变式 | 双方 | 调用前后始终成立（如余额非负） |

违反契约 = bug，应立即暴露。

### 死程序说真话

当程序检测到不可能状态时，应**立即崩溃**而非带病运行：

- **早崩溃 = 早发现**：崩溃立即暴露问题
- **优于带病运行**：崩溃的程序好于产生错误结果的程序
- **避免连锁损害**：及时停止防止错误传播

### 断言式编程

断言检查「永远不该发生的事」：

- **应该检查**：编程错误、逻辑不可能、不变式违反
- **不应该检查**：预期错误（用错误码/异常）、副作用、性能关键路径

核心原则：**断言查 bug，不处理错误**。生产环境通常应保留断言。

### 异常处理

异常和错误码适合不同场景：

| 维度 | 异常 | 错误码 |
|------|------|--------|
| 适合 | 意外、不可预期 | 预期、可恢复 |
| 传播 | 自动沿调用栈 | 需手动检查 |
| 性能 | 有运行时开销 | 无开销 |
| 清晰度 | 分离正常与错误路径 | 可能产生大量 if-else |

**在系统边界集中处理异常**，不要让异常散落各处。

## 术语表

| 术语 | 释义 |
|------|------|
| 契约式设计 | 用契约明确模块间责任边界 |
| 前置条件 | 调用方必须满足的条件 |
| 后置条件 | 被调方必须保证的结果 |
| 不变式 | 调用前后始终成立的条件 |
| 死程序说真话 | 检测到不可能状态时立即崩溃 |
| 断言 | 验证永远不该发生的事 |
| 异常 | 用于意外错误的处理机制 |

## 练习题

1. 什么是契约式设计？它包含哪些要素？
2. 「死程序说真话」是什么意思？
3. 断言应该检查什么？不应该检查什么？
4. 异常和错误码分别适合什么场景？如何选择？
