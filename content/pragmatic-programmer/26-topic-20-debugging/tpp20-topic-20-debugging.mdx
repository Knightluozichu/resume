## 本页对象、状态与因果

20 调试不使用变化率、耦合率或置信度等虚构总分。它直接检查“复现 → 数据 → 假设 → 实验 → 回归”中的真实对象；每次操作只改变“失败样本、错误信息、最小复现、首差、回归测试”中的一个条件，并在第一处状态变化停下。

- **复现**：进入时读取“失败样本”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **数据**：进入时读取“错误信息”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **假设**：进入时读取“最小复现”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **实验**：进入时读取“首差”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **回归**：进入时读取“回归测试”，退出前写明对象、状态变化、下游接收者与拒绝条件。

这条链的基线是“复现”收到完整的失败样本，故障样本则只撤掉最小复现。若下游仍显示成功，说明合同或观测点错误；恢复时必须从原始输入重放，不能手工修改最后一个节点。

## 从提示到可失败的因果链

本页主链是 **复现 → 数据 → 假设 → 实验 → 回归**。每条边必须写明传递的是决定、知识、数据、控制、状态还是反馈；每个节点记录所有者、进入条件、退出条件、超时与失败升级路径。只有箭头而没有传递对象与状态变化的图，无法证明因果。

以复现、观测、假设和证伪驱动调试，先制造失败测试，再修首个因果分叉。 为避免把这句话变成口号，先选一个真实对象，记录失败样本、错误信息、最小复现、首差、回归测试的当前值；再执行正常样本、恰好边界和只改变一个条件的故障样本。三类样本共享其余输入，结果差异才能归因给唯一变量。

五节点逐项裁决如下：**复现** 由“失败样本”负责提供第1份证据；**数据** 由“错误信息”负责提供第2份证据；**假设** 由“最小复现”负责提供第3份证据；**实验** 由“首差”负责提供第4份证据；**回归** 由“回归测试”负责提供第5份证据。任一节点缺少输入、输出或责任人，链路就停在该处，不能跳到最终结果宣布成功。

## 决策账本与反例

| 字段 | 必答问题                         | 拒绝条件                   |
| ---- | -------------------------------- | -------------------------- |
| 命题 | 在什么对象和边界下预期什么结果   | 只有提示文字，没有失败条件 |
| 基线 | 版本、输入、状态和单位怎样冻结   | 分母或时间窗口混用         |
| 干预 | 唯一改变了哪个变量               | 同时换工具、改流程和扩范围 |
| 证据 | 首差、结果、输出哈希和回退在哪里 | 只有截图或主观印象         |
| 复核 | 谁能在相同输入下重建结论         | 复核者依赖原作者点击步骤   |

反例不是“我不同意”。反例必须满足同一前提却产生相反结果，或指出前提在目标环境不成立。发现反例后，缩小结论的适用范围、更新模型并重放旧样本；不能删除失败记录来保持提示看似永远正确。

## 正常、边界与单故障矩阵

| 样本   | 只改变的变量                   | 预期                                       | 必存证据                     |
| ------ | ------------------------------ | ------------------------------------------ | ---------------------------- |
| 正常   | 已知输入、稳定依赖、完整证据   | “复现 → 数据 → 假设 → 实验 → 回归”主链闭合 | 基线、逐节点输出、结果哈希   |
| 边界   | 恰好容量、期限、权限或质量阈值 | 明确接受或拒绝，不产生假完成               | 阈值来源、比较算式、原状态   |
| 单故障 | 一个依赖、状态、工具或角色失效 | 在首个异常点暴露并回退                     | 首差、错误上下文、恢复与回归 |

操作前先写预测。若一次同时改架构、换团队流程、升级工具和重写测试，就无法知道结果来自哪里，必须重置基线后重新实验。

## 跨时代与跨团队迁移

20周年版已经重写了大量第一版材料，但任何建议仍有上下文。迁移到云服务、移动端、数据系统或AI辅助开发时，分别记录团队规模、发布频率、数据敏感性、自动化反馈和监管约束。现代工具可以缩短机械反馈，却不能代替对失败样本、错误信息、最小复现、首差、回归测试的语义判断。

例如，工具自动生成测试或重构补丁时，分开保存“工具拒绝的非法样本”“运行期拒绝的边界样本”和“仍需人评审的语义样本”。一个自动检查通过，只证明它声明覆盖的分支；只有风险被消除而非转移，才可调整本页建议的实践权重。

## 最小证据包与独立复核

证据包包含ISBN与目录坐标、需求和代码哈希、工具版本、输入、初始状态、变更触达图、反馈时间、失败日志、输出哈希、用户结果、恢复动作和结论。覆盖率、格式化结果或最终截图只能辅助定位，不能单独证明掌握。

独立复核者只接收冻结输入、验收命题和边界，不接收原作者的操作顺序或期待答案。复核者先预测5个节点，再运行同一数据；结果不一致时比较首个分叉和原始日志，不用职位、熟练度或最终结果投票。

2. 怎样证明“能稳定复现问题，列出可证伪假设，用一次一变量实验定位首差并留下回归测试。”不是一次偶然成功？

<Answer>
  先预测“复现 → 数据 → 假设 → 实验 →
  回归”的状态，再让独立复核者只依据冻结输入与失败样本、错误信息、最小复现、首差、回归测试重建；双方应在同一真实对象发现首差，并保留同一恢复状态。
</Answer>

3. 修复一个失败后怎样回归？

<Answer>
  先重放原失败，再运行相邻边界和正常基线；逐节点检查失败样本、错误信息、最小复现、首差、回归测试，全部通过后才进入下一页。
</Answer>
