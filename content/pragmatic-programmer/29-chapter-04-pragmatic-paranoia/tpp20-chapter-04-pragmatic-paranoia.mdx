## 本页对象、状态与因果

第4章 务实的偏执不使用变化率、耦合率或置信度等虚构总分。它直接检查“契约 → 校验 → 失败隔离 → 资源平衡 → 反馈半径”中的真实对象；每次操作只改变“契约式设计、快速失败、断言、资源所有权、前灯范围”中的一个条件，并在第一处状态变化停下。

- **契约**：进入时读取“契约式设计”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **校验**：进入时读取“快速失败”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **失败隔离**：进入时读取“断言”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **资源平衡**：进入时读取“资源所有权”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **反馈半径**：进入时读取“前灯范围”，退出前写明对象、状态变化、下游接收者与拒绝条件。

这条链的基线是“契约”收到完整的契约式设计，故障样本则只撤掉断言。若下游仍显示成功，说明合同或观测点错误；恢复时必须从原始输入重放，不能手工修改最后一个节点。

## 正式目录逐项讲解

### 第4章 务实的偏执

承认软件不完美，以契约、快速失败、断言、资源所有权和小步反馈限制损害。

### 提示36：你无法写出完美的软件

这一章级提示先于具体Topic建立风险前提，必须通过契约式设计、快速失败、断言、资源所有权、前灯范围验证；它不能被误归入相邻Topic，也不能脱离整章边界单独当成口号。这里的结论不是放弃质量，而是把不可消除的不确定性转成明确的故障边界、恢复责任和回归证据。

### 23 契约式设计

用前置条件、后置条件和不变量定义双方责任，让契约既可读又能在边界处执行。

目录提示：**提示37：通过契约进行设计**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 24 死掉的程序不会说谎

在状态已经不可信时尽早停止并暴露上下文，避免错误继续传播成更难定位的数据损坏。

目录提示：**提示38：尽早崩溃**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 25 断言式编程

用断言表达真正不可能的内部状态，并区分断言、输入校验和可恢复业务错误。

目录提示：**提示39：使用断言去预防不可能的事情**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 26 如何保持资源的平衡

让获取资源的一方承担释放责任，以作用域、所有权和异常路径证明资源始终平衡。

目录提示：**提示40：有始有终**、**提示41：在局部行动**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 27 不要冲出前灯范围

只在可见反馈范围内小步前进，对远期预测保留不确定性，避免以猜测制造不可逆承诺。

目录提示：**提示42：小步前进——由始至终**、**提示43：避免占卜**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

## 从提示到可失败的因果链

本页主链是 **契约 → 校验 → 失败隔离 → 资源平衡 → 反馈半径**。每条边必须写明传递的是决定、知识、数据、控制、状态还是反馈；每个节点记录所有者、进入条件、退出条件、超时与失败升级路径。只有箭头而没有传递对象与状态变化的图，无法证明因果。

承认软件不完美，以契约、快速失败、断言、资源所有权和小步反馈限制损害。 为避免把这句话变成口号，先选一个真实对象，记录契约式设计、快速失败、断言、资源所有权、前灯范围的当前值；再执行正常样本、恰好边界和只改变一个条件的故障样本。三类样本共享其余输入，结果差异才能归因给唯一变量。

五节点逐项裁决如下：**契约** 由“契约式设计”负责提供第1份证据；**校验** 由“快速失败”负责提供第2份证据；**失败隔离** 由“断言”负责提供第3份证据；**资源平衡** 由“资源所有权”负责提供第4份证据；**反馈半径** 由“前灯范围”负责提供第5份证据。任一节点缺少输入、输出或责任人，链路就停在该处，不能跳到最终结果宣布成功。

## 决策账本与反例

| 字段 | 必答问题                         | 拒绝条件                   |
| ---- | -------------------------------- | -------------------------- |
| 命题 | 在什么对象和边界下预期什么结果   | 只有提示文字，没有失败条件 |
| 基线 | 版本、输入、状态和单位怎样冻结   | 分母或时间窗口混用         |
| 干预 | 唯一改变了哪个变量               | 同时换工具、改流程和扩范围 |
| 证据 | 首差、结果、输出哈希和回退在哪里 | 只有截图或主观印象         |
| 复核 | 谁能在相同输入下重建结论         | 复核者依赖原作者点击步骤   |

反例不是“我不同意”。反例必须满足同一前提却产生相反结果，或指出前提在目标环境不成立。发现反例后，缩小结论的适用范围、更新模型并重放旧样本；不能删除失败记录来保持提示看似永远正确。

## 正常、边界与单故障矩阵

| 样本   | 只改变的变量                   | 预期                                                   | 必存证据                     |
| ------ | ------------------------------ | ------------------------------------------------------ | ---------------------------- |
| 正常   | 已知输入、稳定依赖、完整证据   | “契约 → 校验 → 失败隔离 → 资源平衡 → 反馈半径”主链闭合 | 基线、逐节点输出、结果哈希   |
| 边界   | 恰好容量、期限、权限或质量阈值 | 明确接受或拒绝，不产生假完成                           | 阈值来源、比较算式、原状态   |
| 单故障 | 一个依赖、状态、工具或角色失效 | 在首个异常点暴露并回退                                 | 首差、错误上下文、恢复与回归 |

操作前先写预测。若一次同时改架构、换团队流程、升级工具和重写测试，就无法知道结果来自哪里，必须重置基线后重新实验。

## 跨时代与跨团队迁移

20周年版已经重写了大量第一版材料，但任何建议仍有上下文。迁移到云服务、移动端、数据系统或AI辅助开发时，分别记录团队规模、发布频率、数据敏感性、自动化反馈和监管约束。现代工具可以缩短机械反馈，却不能代替对契约式设计、快速失败、断言、资源所有权、前灯范围的语义判断。

例如，工具自动生成测试或重构补丁时，分开保存“工具拒绝的非法样本”“运行期拒绝的边界样本”和“仍需人评审的语义样本”。一个自动检查通过，只证明它声明覆盖的分支；只有风险被消除而非转移，才可调整本页建议的实践权重。

## 最小证据包与独立复核

证据包包含ISBN与目录坐标、需求和代码哈希、工具版本、输入、初始状态、变更触达图、反馈时间、失败日志、输出哈希、用户结果、恢复动作和结论。覆盖率、格式化结果或最终截图只能辅助定位，不能单独证明掌握。

独立复核者只接收冻结输入、验收命题和边界，不接收原作者的操作顺序或期待答案。复核者先预测5个节点，再运行同一数据；结果不一致时比较首个分叉和原始日志，不用职位、熟练度或最终结果投票。

1. 如何为第4章 务实的偏执建立最小可重放基线？

  固定2020年中文第2版目录坐标、需求、代码哈希、工具、输入、初始状态和单位，先画“契约

2. 怎样证明“能说明第4章各Topic如何沿“契约 → 校验 → 失败隔离 → 资源平衡 → 反馈半径”形成依赖，并用一个真实项目样本验证整章而非背诵提示。”不是一次偶然成功？

  反馈半径”的状态，再让独立复核者只依据冻结输入与契约式设计、快速失败、断言、资源所有权、前灯范围重建；双方应在同一真实对象发现首差，并保留同一恢复状态。

</Answer>
