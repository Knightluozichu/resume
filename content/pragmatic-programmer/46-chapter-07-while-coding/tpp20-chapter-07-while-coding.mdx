## 本页对象、状态与因果

第7章 当你编码时不使用变化率、耦合率或置信度等虚构总分。它直接检查“感知阻力 → 显化假设 → 测量复杂度 → 测试重构 → 安全表达”中的真实对象；每次操作只改变“蜥蜴脑、巧合式编程、算法速度、重构、特性测试”中的一个条件，并在第一处状态变化停下。

- **感知阻力**：进入时读取“蜥蜴脑”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **显化假设**：进入时读取“巧合式编程”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **测量复杂度**：进入时读取“算法速度”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **测试重构**：进入时读取“重构”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **安全表达**：进入时读取“特性测试”，退出前写明对象、状态变化、下游接收者与拒绝条件。

这条链的基线是“感知阻力”收到完整的蜥蜴脑，故障样本则只撤掉算法速度。若下游仍显示成功，说明合同或观测点错误；恢复时必须从原始输入重放，不能手工修改最后一个节点。

## 正式目录逐项讲解

### 37 听从蜥蜴脑

把迟疑、烦躁和阻塞当作潜意识发现不一致的信号，暂停并用小实验显化未知。

目录提示：**提示61：倾听你内心的蜥蜴**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 38 巧合式编程

把偶然可运行的代码转成有意图、有假设和有边界的实现，不依赖未说明的环境巧合。

目录提示：**提示62：不要依赖巧合编程**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 39 算法速度

先分析数量级和增长阶，再在目标环境测量常数与数据分布，避免只信公式或只信微基准。

目录提示：**提示63：评估算法的级别**、**提示64：对估算做测试**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 40 重构

在测试保护下持续重构，以小步、行为等价和可回退提交改善设计而不夹带功能变化。

目录提示：**提示65：尽早重构，经常重构**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 41 为编码测试

把测试当成代码的第一个用户和设计反馈源，从端到端切片推动接口、耦合与可观察性改善。

目录提示：**提示66：测试与找 Bug 无关**、**提示67：测试是代码的第一个用户**、**提示68：既非自上而下，也不自下而上，基于端对端构建**、**提示69：为测试做设计**、**提示70：要对软件做测试，否则只能留给用户去做**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 42 基于特性测试

用生成器探索输入空间，用不变量裁决结果，并通过缩减找到最小反例。

目录提示：**提示71：使用基于特性的测试来校验假设**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 43 出门在外注意安全

以最小攻击面、及时补丁、最小权限和输入边界构成持续安全工程，而非上线前一次扫描。

目录提示：**提示72：保持代码简洁，让攻击面最小**、**提示73：尽早打上安全补丁**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

### 44 事物命名

用名称传达领域意图和作用域，并在意图变化时及时重命名，避免陈旧名称传播错误模型。

目录提示：**提示74：好好取名；需要时更名**。这些提示在本课程中作为可失败命题进入实验，不作为脱离边界的口号。

## 从提示到可失败的因果链

本页主链是 **感知阻力 → 显化假设 → 测量复杂度 → 测试重构 → 安全表达**。每条边必须写明传递的是决定、知识、数据、控制、状态还是反馈；每个节点记录所有者、进入条件、退出条件、超时与失败升级路径。只有箭头而没有传递对象与状态变化的图，无法证明因果。

在编码现场结合直觉、因果、复杂度、重构、测试、安全和命名持续校正实现。 为避免把这句话变成口号，先选一个真实对象，记录蜥蜴脑、巧合式编程、算法速度、重构、特性测试的当前值；再执行正常样本、恰好边界和只改变一个条件的故障样本。三类样本共享其余输入，结果差异才能归因给唯一变量。

五节点逐项裁决如下：**感知阻力** 由“蜥蜴脑”负责提供第1份证据；**显化假设** 由“巧合式编程”负责提供第2份证据；**测量复杂度** 由“算法速度”负责提供第3份证据；**测试重构** 由“重构”负责提供第4份证据；**安全表达** 由“特性测试”负责提供第5份证据。任一节点缺少输入、输出或责任人，链路就停在该处，不能跳到最终结果宣布成功。

## 决策账本与反例

| 字段 | 必答问题                         | 拒绝条件                   |
| ---- | -------------------------------- | -------------------------- |
| 命题 | 在什么对象和边界下预期什么结果   | 只有提示文字，没有失败条件 |
| 基线 | 版本、输入、状态和单位怎样冻结   | 分母或时间窗口混用         |
| 干预 | 唯一改变了哪个变量               | 同时换工具、改流程和扩范围 |
| 证据 | 首差、结果、输出哈希和回退在哪里 | 只有截图或主观印象         |
| 复核 | 谁能在相同输入下重建结论         | 复核者依赖原作者点击步骤   |

反例不是“我不同意”。反例必须满足同一前提却产生相反结果，或指出前提在目标环境不成立。发现反例后，缩小结论的适用范围、更新模型并重放旧样本；不能删除失败记录来保持提示看似永远正确。

## 正常、边界与单故障矩阵

| 样本   | 只改变的变量                   | 预期                                                             | 必存证据                     |
| ------ | ------------------------------ | ---------------------------------------------------------------- | ---------------------------- |
| 正常   | 已知输入、稳定依赖、完整证据   | “感知阻力 → 显化假设 → 测量复杂度 → 测试重构 → 安全表达”主链闭合 | 基线、逐节点输出、结果哈希   |
| 边界   | 恰好容量、期限、权限或质量阈值 | 明确接受或拒绝，不产生假完成                                     | 阈值来源、比较算式、原状态   |
| 单故障 | 一个依赖、状态、工具或角色失效 | 在首个异常点暴露并回退                                           | 首差、错误上下文、恢复与回归 |

操作前先写预测。若一次同时改架构、换团队流程、升级工具和重写测试，就无法知道结果来自哪里，必须重置基线后重新实验。

## 跨时代与跨团队迁移

20周年版已经重写了大量第一版材料，但任何建议仍有上下文。迁移到云服务、移动端、数据系统或AI辅助开发时，分别记录团队规模、发布频率、数据敏感性、自动化反馈和监管约束。现代工具可以缩短机械反馈，却不能代替对蜥蜴脑、巧合式编程、算法速度、重构、特性测试的语义判断。

例如，工具自动生成测试或重构补丁时，分开保存“工具拒绝的非法样本”“运行期拒绝的边界样本”和“仍需人评审的语义样本”。一个自动检查通过，只证明它声明覆盖的分支；只有风险被消除而非转移，才可调整本页建议的实践权重。

## 最小证据包与独立复核

证据包包含ISBN与目录坐标、需求和代码哈希、工具版本、输入、初始状态、变更触达图、反馈时间、失败日志、输出哈希、用户结果、恢复动作和结论。覆盖率、格式化结果或最终截图只能辅助定位，不能单独证明掌握。

独立复核者只接收冻结输入、验收命题和边界，不接收原作者的操作顺序或期待答案。复核者先预测5个节点，再运行同一数据；结果不一致时比较首个分叉和原始日志，不用职位、熟练度或最终结果投票。
