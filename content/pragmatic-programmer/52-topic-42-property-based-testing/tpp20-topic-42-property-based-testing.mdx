## 本页对象、状态与因果

42 基于特性测试不使用变化率、耦合率或置信度等虚构总分。它直接检查“生成器 → 前置约束 → 不变量 → 随机运行 → 缩减”中的真实对象；每次操作只改变“特性测试、生成器、不变量、种子、最小反例”中的一个条件，并在第一处状态变化停下。

- **生成器**：进入时读取“特性测试”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **前置约束**：进入时读取“生成器”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **不变量**：进入时读取“不变量”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **随机运行**：进入时读取“种子”，退出前写明对象、状态变化、下游接收者与拒绝条件。
- **缩减**：进入时读取“最小反例”，退出前写明对象、状态变化、下游接收者与拒绝条件。

这条链的基线是“生成器”收到完整的特性测试，故障样本则只撤掉不变量。若下游仍显示成功，说明合同或观测点错误；恢复时必须从原始输入重放，不能手工修改最后一个节点。

## 从提示到可失败的因果链

本页主链是 **生成器 → 前置约束 → 不变量 → 随机运行 → 缩减**。每条边必须写明传递的是决定、知识、数据、控制、状态还是反馈；每个节点记录所有者、进入条件、退出条件、超时与失败升级路径。只有箭头而没有传递对象与状态变化的图，无法证明因果。

用生成器探索输入空间，用不变量裁决结果，并通过缩减找到最小反例。 为避免把这句话变成口号，先选一个真实对象，记录特性测试、生成器、不变量、种子、最小反例的当前值；再执行正常样本、恰好边界和只改变一个条件的故障样本。三类样本共享其余输入，结果差异才能归因给唯一变量。

五节点逐项裁决如下：**生成器** 由“特性测试”负责提供第1份证据；**前置约束** 由“生成器”负责提供第2份证据；**不变量** 由“不变量”负责提供第3份证据；**随机运行** 由“种子”负责提供第4份证据；**缩减** 由“最小反例”负责提供第5份证据。任一节点缺少输入、输出或责任人，链路就停在该处，不能跳到最终结果宣布成功。

## 决策账本与反例

| 字段 | 必答问题                         | 拒绝条件                   |
| ---- | -------------------------------- | -------------------------- |
| 命题 | 在什么对象和边界下预期什么结果   | 只有提示文字，没有失败条件 |
| 基线 | 版本、输入、状态和单位怎样冻结   | 分母或时间窗口混用         |
| 干预 | 唯一改变了哪个变量               | 同时换工具、改流程和扩范围 |
| 证据 | 首差、结果、输出哈希和回退在哪里 | 只有截图或主观印象         |
| 复核 | 谁能在相同输入下重建结论         | 复核者依赖原作者点击步骤   |

反例不是“我不同意”。反例必须满足同一前提却产生相反结果，或指出前提在目标环境不成立。发现反例后，缩小结论的适用范围、更新模型并重放旧样本；不能删除失败记录来保持提示看似永远正确。

## 正常、边界与单故障矩阵

| 样本   | 只改变的变量                   | 预期                                                   | 必存证据                     |
| ------ | ------------------------------ | ------------------------------------------------------ | ---------------------------- |
| 正常   | 已知输入、稳定依赖、完整证据   | “生成器 → 前置约束 → 不变量 → 随机运行 → 缩减”主链闭合 | 基线、逐节点输出、结果哈希   |
| 边界   | 恰好容量、期限、权限或质量阈值 | 明确接受或拒绝，不产生假完成                           | 阈值来源、比较算式、原状态   |
| 单故障 | 一个依赖、状态、工具或角色失效 | 在首个异常点暴露并回退                                 | 首差、错误上下文、恢复与回归 |

操作前先写预测。若一次同时改架构、换团队流程、升级工具和重写测试，就无法知道结果来自哪里，必须重置基线后重新实验。

## 跨时代与跨团队迁移

20周年版已经重写了大量第一版材料，但任何建议仍有上下文。迁移到云服务、移动端、数据系统或AI辅助开发时，分别记录团队规模、发布频率、数据敏感性、自动化反馈和监管约束。现代工具可以缩短机械反馈，却不能代替对特性测试、生成器、不变量、种子、最小反例的语义判断。

例如，工具自动生成测试或重构补丁时，分开保存“工具拒绝的非法样本”“运行期拒绝的边界样本”和“仍需人评审的语义样本”。一个自动检查通过，只证明它声明覆盖的分支；只有风险被消除而非转移，才可调整本页建议的实践权重。

## 最小证据包与独立复核

证据包包含ISBN与目录坐标、需求和代码哈希、工具版本、输入、初始状态、变更触达图、反馈时间、失败日志、输出哈希、用户结果、恢复动作和结论。覆盖率、格式化结果或最终截图只能辅助定位，不能单独证明掌握。

独立复核者只接收冻结输入、验收命题和边界，不接收原作者的操作顺序或期待答案。复核者先预测5个节点，再运行同一数据；结果不一致时比较首个分叉和原始日志，不用职位、熟练度或最终结果投票。

  “DRY”“敏捷”“尽早失败”等词不能直接裁决设计。回到对象、前提、失败条件和目录坐标，把主张改写成可被反例推翻的句子。

## 本章回顾

用生成器探索输入空间，用不变量裁决结果，并通过缩减找到最小反例。 完成“能为一个变换定义至少两个不变量，固定随机种子复现失败，并保存缩减后的最小反例。”后，仍要由独立复核者在相同边界重建输入、主链、首差和回退。一次成功不是普遍结论；能说明何时失败、如何恢复、哪些输入尚未覆盖，才是可迁移的务实知识。

1. 如何为42 基于特性测试建立最小可重放基线？

2. 怎样证明“能为一个变换定义至少两个不变量，固定随机种子复现失败，并保存缩减后的最小反例。”不是一次偶然成功？

<Answer>

  缩减”的状态，再让独立复核者只依据冻结输入与特性测试、生成器、不变量、种子、最小反例重建；双方应在同一真实对象发现首差，并保留同一恢复状态。
</Answer>
