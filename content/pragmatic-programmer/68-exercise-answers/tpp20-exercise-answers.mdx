## 练习的参考答案

本页依据 David Thomas、Andrew Hunt《程序员修炼之道：通向务实的最高境界（第2版·20周年版）》，云风译，电子工业出版社，2020 年 4 月，ISBN 9787121384356 的公开中文目录，独立重构 **练习的参考答案**。正文、代码、图示、实验和练习都是本课程重新设计的教学材料，不复制原书正文、插图、练习答案或代码。

参考答案不是一道题的唯一终点，而是一条可以比较的路径：答题者先说明前提和预测，再与参考路径对照，找到第一个分歧，最后用反例或独立复算检查两条路径的边界。答案相同不代表推理可靠，答案不同也不代表个人一定错误。

## 三个会让答案评估失真的陷阱

<Callout type="trap" title="把参考答案当成评分模板">

- **现象**：答题者只复述结论，为了匹配措辞删掉自己的前提和不确定性。
- **原因**：把教学用的比较路径误当作唯一正确文本，失去了问题边界和推理过程。
- **修法**：先独立作答，再按前提、证据、步骤、边界逐项对照；结论不同但边界更清楚时，保留差异并继续验证。

</Callout>

<Callout type="trap" title="只比较最后结论">

- **现象**：两个答案都写“重构”或“加测试”，却没有说明输入、约束、失败样本和恢复动作。
- **原因**：评估跳过了首个分歧，无法判断差异来自假设、步骤还是观察结果。
- **修法**：把答案拆成可检查节点，找出第一个变化，再只修改一个变量重放。

</Callout>

<Callout type="trap" title="用熟练度替代独立复算">

- **现象**：评审者因为作者资历或表达流畅就接受答案，没有实际运行边界样本。
- **原因**：权威感被当作证据，复核者依赖作者的操作顺序和期待答案。
- **修法**：冻结输入、命题和边界，让另一名成员先预测再复算；无法重建时降低结论等级。

</Callout>

## 五个词把答案变成可比较路径

`<Term def="题目要求、输入、约束、时间窗口和不在范围内的条件；它决定答案比较的共同起点。">题目边界</Term>`防止答题者用不同问题得出不同结论。边界不清时，先补问题而不是急着评分。

`<Term def="在看到参考答案前，对输入、机制、结果和失败条件写出的可检验预期。">独立预测</Term>`把答案评估从事后解释变成可观察的过程。预测错了并不可耻，隐藏预测才无法学习。

`<Term def="从前提到结论的有序步骤，包括每一步的证据、判断和失败回退。">参考路径</Term>`用于比较推理结构，不要求复制原作者的措辞。每一步都应能被另一个人复走。

`<Term def="两条答案第一次产生不同状态、假设或结果的节点；它决定下一轮应只检查什么。">首个分歧</Term>`比最后的结论更有诊断价值。找到首差后，记录两边输入和证据，避免凭印象争论。

`<Term def="由另一名复核者在冻结输入和边界下重新运行题目，检查结论、反例和回退是否成立。">独立复算</Term>`让参考答案接受现实约束。复算失败时，答案应缩小适用范围，而不是修改日志。

五个词组成学习回路：题目边界决定比较对象，独立预测保留原始假设，参考路径提供结构，首个分歧定位问题，独立复算决定接受、修正或暂停。

## 怎样阅读参考答案

先把问题改写成可判定命题：在什么输入、约束和时间窗口内，预期什么结果？然后独立写预测与失败条件。阅读参考答案时只比较一个维度：它是否改变了前提、步骤、证据或边界。

参考答案可以提供一种合理路径，却不能替你证明当前项目中的代码、流程或组织约束。若答案依赖某个工具版本、隐含权限或未说明的数据质量，必须把这些条件补入边界，再决定结论能否迁移。

## 答案比较合同

```ts
type AnswerReview = {
  prompt: string;
  prediction: string;
  referencePath: string[];
  firstDivergence: string;
  counterexample: string;
  replayEvidence: string;
  decision: "accept" | "revise" | "pause";
};

function isReplayable(review: AnswerReview) {
  return (
    review.prompt.length > 0 &&
    review.prediction.length > 0 &&
    review.referencePath.length >= 2 &&
    review.firstDivergence.length > 0 &&
    review.replayEvidence.length > 0 &&
    review.decision !== "pause"
  );
}
```

这个合同要求答案包含题目、预测、至少两步参考路径、首个分歧和复算证据。它不承诺所有问题只有一个答案；它只保证每个决定都有前提、路径和可复核的暂停条件。

## 四步比较流程

<Stepper>

<Step title="1. 冻结题目边界">

记录输入、约束、目标、时间窗口、允许的工具和失败条件。把模糊的“最佳方案”改成可以被反例推翻的命题。

</Step>

<Step title="2. 先写独立预测">

在阅读参考答案前写下前提、预计结果、信心和最可能失败的地方。保留原始预测，不能用事后知识覆盖它。

</Step>

<Step title="3. 对齐参考路径并找首差">

把两条路径拆成节点，逐项比较输入、步骤、证据和边界。记录第一个分歧及其责任变量，只对这个变量做下一轮检查。

</Step>

<Step title="4. 用边界样本独立复算">

让另一名成员在不知道期待答案的情况下重放正常、边界和单一故障样本。根据结果接受路径、修正前提或暂停结论，并保留回退。

</Step>

</Stepper>

## 正常、边界与单一故障证据

<Tpp20ExerciseAnswersEvidenceDiagram />

| 样本     | 只改变的变量                   | 预期判定                         | 必存证据                       |
| -------- | ------------------------------ | -------------------------------- | ------------------------------ |
| 正常     | 题目、前提、步骤和复算环境完整 | 两条路径的差异可解释             | 输入、预测、逐步输出、复算记录 |
| 边界     | 约束或资源恰好越过阈值         | 修改结论边界或暂停，不产生假完成 | 阈值、失败条件、替代解         |
| 单一故障 | 一个步骤、依赖或复核角色失效   | 在首个分歧暴露并回退             | 首差、错误上下文、恢复动作     |

## 最小答案证据包与反例

证据包包含题目版本、输入、独立预测、参考路径、工具版本、运行日志、正常与边界样本、首个分歧、反例、复算者、决定和回退。最终答案截图或与参考答案文字相似，只能辅助定位，不能单独证明推理成立。

反例应满足同一前提却产生不同结果，或指出题目边界在当前环境不成立。发现反例后，先确认首差，再缩小适用范围、修正前提并重放旧样本；不要删除反例来维持分数。

## 练习

<Exercises>

**问题 1：** 你的答案和参考答案结论不同，但你使用了不同的输入假设。如何判断谁更合理？

<Answer>

先冻结题目边界，逐项列出两边的输入、约束和时间窗口；若首个分歧来自假设，就不要直接比较最后结论。补一组能区分假设的正常与边界样本，让独立复核者重放，再决定接受、修正或缩小其中一条路径。

</Answer>

**问题 2：** 参考答案在你的当前工具版本上无法复现，你会如何记录？

<Answer>

保存原题版本、参考路径、工具和依赖版本、输入、失败日志和首个分歧。把版本漂移写成适用边界，不修改旧记录；用当前版本的替代路径重放样本，若仍无法证明就暂停迁移结论。

</Answer>

**问题 3：** 评审者说“答案看起来对”，但没有运行边界样本。你会要求什么？

<Answer>

要求先写验收命题和失败条件，再运行正常、边界和单一故障样本；保存输入、输出、首差、复核人和回退。若没有可重放证据，结论只能标为线索，不能因为表达流畅或作者资历而接受。

</Answer>

</Exercises>

## 本单元回顾

参考答案是比较路径，不是唯一结论。先冻结题目边界，独立写预测，再定位参考路径的首个分歧，最后用边界样本和独立复算验证；能解释前提、反例、失败和回退，才算真正学会一道练习。
