## 为什么这一单元不可压缩

本页依据 David Thomas、Andrew Hunt《程序员修炼之道：通向务实的最高境界（第2版）》，云风译，电子工业出版社，2020年4月，ISBN 9787121384356的公开完整中文目录，独立重构 **译者跋**。记录云风对中文版术语与实践语境的处理，避免把译名、作者概念和读者引申混成同一层。 本课程不复制原书正文、插图、练习答案或代码，而把目录命题转写成新的模型、案例、交互实验、失败样本与复核证据。

中文版目录逐项列出序、新版前言、第一版前言、9章、53个Topic、99条提示、跋、参考文献、练习的参考答案和译者跋，共69个正式单元、168个目录节点。作者官方页面和英文原版目录交叉核对9章53个Topic；英文版另有索引，中文版公开目录以译者跋收束，课程不把英文索引偷加到中文分母。

豆瓣书目登记作者、译者、出版社、2020年4月1日、344页和ISBN；出版社展示页登记2020年3月26日上市。两者是出版/上市日期口径差异，不影响版本识别。书中语言与工具例子有时代边界，责任、反馈、可变更性和用户价值仍需在当前项目重新验证。

## 四个可计算模型

反馈周期必须包含发现、判断、修改与验证，而不是只统计编码时间：

$$
feedbackLatency=detect+decide+change+verify
$$

变更风险同时受触达范围、不确定性、耦合和证据约束：

$$
changeRisk=(reach	imes uncertainty	imes coupling)/(evidence+1)
$$

知识复制越多、变化越频繁，漂移与修复成本越高：

$$
driftCost=copies	imes changeRate	imes repairCost
$$

发布采用乘法门禁，任一关键证据为零都不能用平均分掩盖：

$$
release=intent	imes executableEvidence	imes userValue	imes independentReview
$$

所有变量必须来自同一项目快照。若“变化次数”来自一个月、“缺陷”来自一年、“证据覆盖”来自另一分支，计算结果没有可比意义。公式是强迫读者暴露假设的工具，不是自动裁决人的评分器。

## 三段最小可运行骨架

```typescript
type PragmaticSnapshot = {
  edition: "2020-CN-2e";
  unit: "tpp20-translator-postface";
  baseline: string;
  inputs: readonly string[];
  evidence: readonly string[];

export function changeRisk(
  reach: number,
  uncertainty: number,
  coupling: number,
  evidence: number,
) {
  if ([reach, uncertainty, coupling, evidence].some((value) => value < 0))
    throw new Error("negative metric");
  return (reach * uncertainty * coupling) / (evidence + 1);
}
```

```python
def feedback_gate(detect, decide, change, verify, limit):
    latency = detect + decide + change + verify
    return {"latency": latency, "accepted": latency <= limit,
            "margin": limit - latency}
```

```python
def apply_one_change(baseline, changes, validate):
    if len(changes) != 1:
        return {"accepted": False, "state": baseline, "reason": "not-single-change"}
    candidate = dict(baseline, **changes)
    return ({"accepted": True, "state": candidate, "reason": None}
            if validate(candidate) else
            {"accepted": False, "state": baseline, "reason": "gate-rejected"})
```

第一段固定版次与证据对象，第二段把完整反馈而非编码局部放入预算，第三段保证故障被拒绝时基线不被半更新。运行记录至少保存目录坐标、输入快照、预期、实际、首差、输出哈希和回退状态。

## 正式目录逐项讲解

### 译者跋

记录云风对中文版术语与实践语境的处理，避免把译名、作者概念和读者引申混成同一层。 本页以译者责任、术语映射、语境差异、版本信息、读者复核为五个复核坐标，把标题转成可运行实验。

复核动作：冻结2020年中文第2版目录坐标与项目基线，只改变一个条件；保存预期、实际、首差和回退。结论必须回答“能为一个关键译名列出英文概念、中文选择、上下文含义和可能误读。”，并注明未覆盖的输入。

## 从提示到可失败的因果链

本页主链是 **原文概念 → 译名选择 → 中文语境 → 当前解释 → 术语复核**。每条边必须写明传递的是决定、知识、数据、控制、状态还是反馈；每个节点记录所有者、进入条件、退出条件、超时与失败升级路径。只有箭头而没有传递对象与状态变化的图，无法证明因果。

记录云风对中文版术语与实践语境的处理，避免把译名、作者概念和读者引申混成同一层。 为避免把这句话变成口号，先选一个真实对象，记录译者责任、术语映射、语境差异、版本信息、读者复核的当前值；再执行正常样本、恰好边界和只改变一个条件的故障样本。三类样本共享其余输入，结果差异才能归因给唯一变量。

五节点逐项裁决如下：**原文概念** 由“译者责任”负责提供第1份证据；**译名选择** 由“术语映射”负责提供第2份证据；**中文语境** 由“语境差异”负责提供第3份证据；**当前解释** 由“版本信息”负责提供第4份证据；**术语复核** 由“读者复核”负责提供第5份证据。任一节点缺少输入、输出或责任人，链路就停在该处，不能跳到最终结果宣布成功。

## 决策账本与反例

| 字段 | 必答问题                         | 拒绝条件                   |
| ---- | -------------------------------- | -------------------------- |
| 命题 | 在什么对象和边界下预期什么结果   | 只有提示文字，没有失败条件 |
| 基线 | 版本、输入、状态和单位怎样冻结   | 分母或时间窗口混用         |
| 干预 | 唯一改变了哪个变量               | 同时换工具、改流程和扩范围 |
| 证据 | 首差、结果、输出哈希和回退在哪里 | 只有截图或主观印象         |
| 复核 | 谁能在相同输入下重建结论         | 复核者依赖原作者点击步骤   |

反例不是“我不同意”。反例必须满足同一前提却产生相反结果，或指出前提在目标环境不成立。发现反例后，缩小结论的适用范围、更新模型并重放旧样本；不能删除失败记录来保持提示看似永远正确。

## 正常、边界与单故障矩阵

| 样本   | 只改变的变量                   | 预期                                                           | 必存证据                     |
| ------ | ------------------------------ | -------------------------------------------------------------- | ---------------------------- |
| 正常   | 已知输入、稳定依赖、完整证据   | “原文概念 → 译名选择 → 中文语境 → 当前解释 → 术语复核”主链闭合 | 基线、逐节点输出、结果哈希   |
| 边界   | 恰好容量、期限、权限或质量阈值 | 明确接受或拒绝，不产生假完成                                   | 阈值来源、比较算式、原状态   |
| 单故障 | 一个依赖、状态、工具或角色失效 | 在首个异常点暴露并回退                                         | 首差、错误上下文、恢复与回归 |

操作前先写预测。若一次同时改架构、换团队流程、升级工具和重写测试，就无法知道结果来自哪里，必须重置基线后重新实验。

## 跨时代与跨团队迁移

20周年版已经重写了大量第一版材料，但任何建议仍有上下文。迁移到云服务、移动端、数据系统或AI辅助开发时，分别记录团队规模、发布频率、数据敏感性、自动化反馈和监管约束。现代工具可以缩短机械反馈，却不能代替对译者责任、术语映射、语境差异、版本信息、读者复核的语义判断。

例如，工具自动生成测试或重构补丁时，分开保存“工具拒绝的非法样本”“运行期拒绝的边界样本”和“仍需人评审的语义样本”。一个自动检查通过，只证明它声明覆盖的分支；只有风险被消除而非转移，才可调整本页建议的实践权重。

## 最小证据包与独立复核

证据包包含ISBN与目录坐标、需求和代码哈希、工具版本、输入、初始状态、变更触达图、反馈时间、失败日志、输出哈希、用户结果、恢复动作和结论。覆盖率、格式化结果或最终截图只能辅助定位，不能单独证明掌握。

独立复核者只接收冻结输入、验收命题和边界，不接收原作者的操作顺序或期待答案。复核者先预测5个节点，再运行同一数据；结果不一致时比较首个分叉和原始日志，不用职位、熟练度或最终结果投票。

## 常见失败与回退

<Callout type="trap">
  **把提示当作脱离上下文的口号：**
  “DRY”“敏捷”“尽早失败”等词不能直接裁决设计。回到对象、前提、失败条件和目录坐标，把主张改写成可被反例推翻的句子。
</Callout>

<Callout type="trap">
  **让工具通过代替用户与工程证据：**
  静态检查、生成式工具和流水线只覆盖声明的机制。回到“原文概念 → 译名选择 →
  中文语境 → 当前解释 → 术语复核”主链，补齐运行、边界、用户结果和独立复核。
</Callout>

## 本章回顾

记录云风对中文版术语与实践语境的处理，避免把译名、作者概念和读者引申混成同一层。 完成“能为一个关键译名列出英文概念、中文选择、上下文含义和可能误读。”后，仍要由独立复核者在相同边界重建输入、主链、首差和回退。一次成功不是普遍结论；能说明何时失败、如何恢复、哪些输入尚未覆盖，才是可迁移的务实知识。

1. 如何为译者跋建立最小可重放基线？

2. 怎样证明“能为一个关键译名列出英文概念、中文选择、上下文含义和可能误读。”不是一次偶然成功？

<Answer>
  先手算变更触达、反馈延迟、知识漂移与证据置信度，再让独立复核者只依据输入和验收合同重建；双方必须在相同首差拒绝故障，并保留相同回退状态。
</Answer>

<Answer>
