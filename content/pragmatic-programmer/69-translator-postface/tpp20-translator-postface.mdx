## 译者跋

本页依据 David Thomas、Andrew Hunt《程序员修炼之道：通向务实的最高境界（第2版·20周年版）》，云风译，电子工业出版社，2020 年 4 月，ISBN 9787121384356 的公开中文目录，独立重构 **译者跋**。正文、代码、图示、实验和练习都是本课程重新设计的教学材料，不复制原书正文、插图、练习答案或代码。

译者跋提醒我们：技术概念进入另一种语言后，不只是词语替换，还会带着行业习惯、文化语境、读者经验和时代变化。一个译名可以易读，却可能藏掉原概念的边界；一个保留英文的术语可以精确，却可能让初学者失去入口。可靠的做法是把概念、选择、上下文和复核证据分层保存。

## 三个会让术语判断失真的陷阱

<Callout type="trap" title="把译名当成原概念本身">

- **现象**：团队争论某个中文词“对不对”，却没有列出原概念的动作、边界、反例和责任对象。
- **原因**：把语言表面等同于语义，忽略一个词在不同上下文可能承担不同操作。
- **修法**：先写概念合同，再记录译名如何覆盖它；保留原词、定义或例子来暴露没有覆盖的部分。

</Callout>

<Callout type="trap" title="用本地习惯覆盖上下文">

- **现象**：某个术语在团队里有固定俗称，读者却根据日常含义作出错误的工程判断。
- **原因**：没有记录版本、目标读者、行业语境和术语在句子中的动作。
- **修法**：给术语补上下文例句、反例和适用边界；必要时并列中文译名与英文原词，让复核者检查差异。

</Callout>

<Callout type="trap" title="把读者误读归咎于读者">

- **现象**：读者按字面执行后造成错误，团队只说“你没理解”，却没有修改定义、提示或验收例子。
- **原因**：把沟通结果当作个人能力问题，缺少独立读者复核和误读记录。
- **修法**：收集误读样本，定位首个歧义，改写说明或增加边界；让另一名读者在不知道期待答案时重述概念。

</Callout>

## 五个词把译者责任变成诊断链

`<Term def="术语在原始材料中指向的动作、对象、边界、关系和失败条件，而不是某个字面词。">原文概念</Term>`是翻译的起点。没有概念合同，就无法判断译名保留了什么、丢失了什么。

`<Term def="为原文概念选择的中文表达、英文保留或组合写法，以及选择的理由和取舍。">译名选择</Term>`应该注明可读性、精确性、既有行业用法和潜在误解之间的权衡。

`<Term def="术语进入目标读者的组织、行业、时代和句子后，哪些假设会改变它的理解或使用。">语境差异</Term>`包括团队角色、工具边界、文化含义和版本变化。语境不明时，任何译名都只能算暂定。

`<Term def="读者依据译名、例句或提示形成的错误模型，以及错误模型会触发的动作和后果。">可能误读</Term>`不是语言瑕疵清单，而是可以被样本和复述验证的失败路径。

`<Term def="由另一名读者或领域成员在同一版本和边界下重述、举例并指出反例，检查术语是否可用。">读者复核</Term>`把译者的选择暴露给独立反馈。复核失败时，应该修订说明或缩小承诺，而不是投票决定“听起来更顺”。

五个词组成诊断链：原文概念确定要传递的东西，译名选择公开取舍，语境差异说明适用范围，可能误读提供故障样本，读者复核决定是否需要改写。

## 从概念到可复核术语

### 先写概念合同

不要从字典释义开始。先写术语在工程实践中要求谁做什么、对象状态如何改变、什么情况不适用，以及失败后由谁接住。再选择中文表达，才能比较译名而不是比较审美。

### 保存选择与上下文

记录原词、中文译名、版本、目标读者、例句、反例和选择理由。若一个译名需要保留英文、脚注或相邻术语才能避免误导，应把这种成本写进教学材料，而不是隐藏在译者记忆中。

### 用误读反推解释

请独立读者只读术语和例句，先说出它会如何行动，再比较预期模型。首个歧义可能来自译名，也可能来自原概念没有定义、上下文没有写出或读者拥有不同前提；定位后只修一处，再重放。

## 术语诊断合同

```ts
type TermReview = {
  originalConcept: string;
  chosenTerm: string;
  context: string[];
  likelyMisread: string[];
  readerReplay: string;
  owner: string;
  decision: "keep" | "annotate" | "revise";
};

function isTermReady(review: TermReview) {
  return (
    review.originalConcept.length > 0 &&
    review.chosenTerm.length > 0 &&
    review.context.length > 0 &&
    review.likelyMisread.length > 0 &&
    review.readerReplay.length > 0
  );
}
```

这个合同不声称存在脱离语境的完美译名。它要求选择、边界、误读和读者复核都可见；当一个词必须注释或修订时，记录决定和责任人比维护“译名永远正确”的形象更重要。

## 四步术语复核流程

<Stepper>

<Step title="1. 写出原文概念合同">

记录对象、动作、状态变化、边界、反例和失败责任。不要先争论中文词的顺口程度，先说明要让读者能够做出什么判断。

</Step>

<Step title="2. 记录译名选择与取舍">

列出中文译名、原词、已有行业用法、目标读者和选择理由。明确哪个语义被压缩、哪个语义必须通过例子或注释补回。

</Step>

<Step title="3. 设计误读样本">

让读者根据术语和例句给出行动预测，加入版本、文化和团队边界下的反例。只改变一个条件，定位首个歧义来自词、语境还是概念定义。

</Step>

<Step title="4. 独立复核并决定">

由另一名读者重述概念、举例并指出不适用场景。根据证据保留译名、增加注释或修订表达，并保存复核时间、版本和后续责任人。

</Step>

</Stepper>

## 正常、边界与单一故障证据

<Tpp20TranslatorPostfaceEvidenceDiagram />

| 样本     | 只改变的变量                   | 预期判定                       | 必存证据                   |
| -------- | ------------------------------ | ------------------------------ | -------------------------- |
| 正常     | 概念、译名、语境和复核信息完整 | 读者可复述概念并指出边界       | 原词、译名、例句、复核记录 |
| 边界     | 读者经验、版本或行业语境变化   | 增加注释或缩小承诺，不强行统一 | 误读、边界、选择理由       |
| 单一故障 | 一个译名、例句或复核角色失效   | 在首个歧义暴露并回退           | 首差、错误模型、修订动作   |

语言迁移不是把所有差异抹平。面对云服务、移动端、数据系统或 AI 辅助开发时，分别记录团队规模、责任关系、反馈速度、数据敏感性和监管约束；同一个中文词在不同操作环境中可能需要不同例句和停止条件。

## 最小术语证据包与反例

证据包包含原文概念、原词与版本、中文译名、选择理由、目标读者、上下文例句、反例、可能误读、复核者复述、决定、责任人和修订时间。读者“觉得顺”只能说明表达流畅，不能单独证明概念没有漂移。

反例可以是同一译名让不同读者采取相反动作，也可以是一个版本或行业让原本清晰的解释失效。发现反例后，先记录首个歧义，再补定义、例句或边界并让独立读者重放；不要删除误读样本来维持译名表面稳定。

## 练习

<Exercises>

**问题 1：** 一个中文译名很顺口，但读者把它理解成“任何时候都应该执行”。你会先改词还是先改说明？

<Answer>

先冻结原文概念合同和误读动作，判断首个歧义来自词义、例句还是缺少边界；再只修改一处并让独立读者重述。如果词本身覆盖不了概念，就保留原词或增加注释，而不是用更顺口的表达隐藏限制。

</Answer>

**问题 2：** 同一个术语在老项目和 AI 辅助开发流程中需要不同例句，是否说明有一个译名错了？

<Answer>

不一定。先比较对象、责任关系、反馈速度、工具版本和失败后果，确认是否只是语境差异。保留稳定的概念合同，为不同边界补例句和反例；若中文词让两种环境产生不可接受的相反动作，再记录证据并修订或并列说明。

</Answer>

**问题 3：** 复核者说“我知道这个词”，却无法指出不适用场景。如何收敛？

<Answer>

把“知道”改成可观察任务：复核者先重述概念、给出一个适用例和一个反例，再说明失败时谁负责。若不能指出边界，术语只能标为暂定；补充上下文和故障样本后重新复核。

</Answer>

</Exercises>

## 本单元回顾

译者跋的任务不是宣布某个词永远正确，而是让原文概念、译名取舍、中文语境、可能误读和读者复核彼此可见。把误读当作诊断信号，定位首个歧义并重新验证，才能让术语跨语言、跨团队和跨时代地保持可用。
