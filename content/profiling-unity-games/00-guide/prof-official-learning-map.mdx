## 核心模型与不可变条件

这本93页指南不是工具菜单，而是一条从帧预算、瓶颈分类、内存预算到平台原生证据的闭环。学习顺序必须先问目标和边界，再选观测工具，最后用相同输入证明修改有效。

本单元的不可变条件是：**六个顶层目录区域、每个工具的适用问题、目标设备基线与修改前后对照必须同时保留，不能把全书压缩成一次Profiler截图。** 只要输入条件、观测边界或结果合同有一项改变，就不能把两次测量直接相减。先解释变化来源，再决定是否建立新的基线。

## 从输入到结论的诊断链

## 可执行实现骨架

下面的代码只承担本单元的数据所有权或测量边界。真正项目应把阈值放入版本化配置，并让证据文件引用同一个配置哈希。

```csharp
public readonly record struct ProfilingEvidence(
    string Device, string Build, string Scenario,
    double CpuMs, double GpuMs, long MemoryBytes,
    string FirstBottleneck, bool Reproduced);

public static bool CanShip(ProfilingEvidence e, double frameBudgetMs, long memoryBudget)
    => Math.Max(e.CpuMs, e.GpuMs) <= frameBudgetMs
       && e.MemoryBytes <= memoryBudget
       && e.Reproduced;
```

每次采集都保存结构化元数据，避免报告与原始文件失联：

```json
{
  "chapter": "prof-official-learning-map",
  "officialPages": "全书目录与第7页导言",
  "chain": [
    "目标设备",
    "预算合同",
    "高层采样",
    "瓶颈分流",
    "专项工具",
    "回归证据"
  ],
  "device": "target-low-tier-01",
  "build": "commit-and-unity-version",
  "scenario": "fixed-checkpoint",
  "baseline": "capture-before.data",
  "candidate": "capture-after.data",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

自动门输出必须同时保留通过值和拒绝原因，而不是只给一个绿色图标：

```text
PASS context=device+build+scene+quality+input
PASS chain=目标设备 -> 预算合同 -> 高层采样 -> 瓶颈分流 -> 专项工具 -> 回归证据
PASS invariant=六个顶层目录区域、每个工具的适用问题、目标设备基线与修改前后对照必须同时保留，不能把全书压缩成一次Profiler截图。
REJECT missing-raw-data | changed-context | hidden-quality-loss | unreplayed-failure
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="官方边界或测量上下文丢失">
  只介绍CPU、GPU、Memory三个窗口，却跳过方法论、功耗、Project
  Auditor、自动化测试和原生工具索引。
  先保存错误结论、首个偏离节点和原始数据，再恢复官方目录边界与相同测试条件复验。
</Callout>

<Callout type="trap" title="数字改善但工作被转移或结果改变">
  故意降低画质、跳过玩法工作、扩大永久缓存或把任务推迟到下一帧。若主指标改善但GPU、内存、热量、图像或玩法合同变差，发布门必须拒绝。
</Callout>

## 证据矩阵与签发标准

| 维度   | 正常样本       | 边界样本           | 失败样本           | 签发条件       |
| ------ | -------------- | ------------------ | ------------------ | -------------- |
| 上下文 | 固定设备与构建 | 最低档或长时间运行 | 故意改变一项条件   | 差异可解释     |
| 主链   | 六节点均有记录 | 预算附近输入       | 在首个节点注入偏差 | 能定位首因     |
| 结果   | 达到性能合同   | 无长尾越界         | 主动制造回归       | 同输入可复验   |
| 副作用 | 画面玩法一致   | 生命周期完整       | 降质或转移成本     | 所有门同时通过 |
