## 问题：怎样证明掌握的是官方单元 8，而不是记住几个工具名？

先预测：如果只看到最终帧率或一张截图，不知道设备、构建、场景、输入和采样方式，能否判断修改真的有效？不能。性能结果是测试上下文与程序行为共同产生的，脱离上下文的数字既不能复现，也不能指导下一步。

Memory Profiler快照解释某一稳定点为什么占用这些字节；Unity Profiler时间轴和Allocation Call Stacks解释运行期间哪里持续分配。泄漏判断需要操作前后快照、引用链和可重复生命周期。

## 核心模型与不可变条件

Memory Profiler快照解释某一稳定点为什么占用这些字节；Unity Profiler时间轴和Allocation Call Stacks解释运行期间哪里持续分配。泄漏判断需要操作前后快照、引用链和可重复生命周期。

本单元的不可变条件是：**同一操作循环结束并完成预期卸载后，非缓存对象数量与字节数应回到允许区间；每帧分配必须有调用栈和所有者。** 只要输入条件、观测边界或结果合同有一项改变，就不能把两次测量直接相减。先解释变化来源，再决定是否建立新的基线。

## 从输入到结论的诊断链

主链为：**稳定点A → 执行生命周期 → 稳定点B → Summary分流 → Objects持留链 → 分配栈修复**。每个节点保存构建提交、设备ID、场景检查点、帧号或快照ID、当前预算、实际值和首个异常。下一节点只消费上一节点已验证的事实，不能用“感觉更流畅”跨过中间归因。

### 1. Memory Profiler

Summary先显示总量和类别，帮助判断增长位于Managed、Native、Graphics还是未跟踪区域。它是分诊台，不能替代具体对象和引用链分析。

## 可执行实现骨架

下面的代码只承担本单元的数据所有权或测量边界。真正项目应把阈值放入版本化配置，并让证据文件引用同一个配置哈希。

```csharp
readonly List<Enemy> visible = new(256);

void CollectVisible(ReadOnlySpan<Enemy> candidates)
{
    visible.Clear();
    foreach (var enemy in candidates)
        if (camera.IsVisible(enemy.Bounds)) visible.Add(enemy);
}

// Reuse bounded storage, then verify it does not retain destroyed objects.
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="官方边界或测量上下文丢失">
  只把C#引用置空就认为纹理已释放，或在第一次进入场景与资源尚未预热时比较快照，把合法缓存增长误判成泄漏。
  先保存错误结论、首个偏离节点和原始数据，再恢复官方目录边界与相同测试条件复验。
</Callout>

<Callout type="trap" title="数字改善但工作被转移或结果改变">
  故意降低画质、跳过玩法工作、扩大永久缓存或把任务推迟到下一帧。若主指标改善但GPU、内存、热量、图像或玩法合同变差，发布门必须拒绝。
</Callout>
