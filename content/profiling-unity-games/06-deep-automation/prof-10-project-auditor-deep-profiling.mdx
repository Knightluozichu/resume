## 核心模型与不可变条件

Project Auditor在运行前扫描设置、资源和代码风险，把可静态证明的问题从Profile会话中移除。Domain Reload优化只有在静态状态能可靠复位后才安全，Roslyn分析结果应先清零。

本单元的不可变条件是：**关闭Domain Reload前，所有静态字段、事件和单例都必须在每次进入Play Mode时得到确定复位，并通过连续多次运行与场景重载证明。** 只要输入条件、观测边界或结果合同有一项改变，就不能把两次测量直接相减。先解释变化来源，再决定是否建立新的基线。

## 从输入到结论的诊断链

主链为：**运行审计 → 按类别分流 → 修复高置信问题 → 启用Roslyn → 复位静态状态 → 连续重进验证**。每个节点保存构建提交、设备ID、场景检查点、帧号或快照ID、当前预算、实际值和首个异常。下一节点只消费上一节点已验证的事实，不能用“感觉更流畅”跨过中间归因。

### 1. Project Auditor

Project Auditor能发现项目设置、资源导入、Shader、代码和其他类别中的已知风险。结果是候选问题，不是运行时热点；按严重度、可信度和目标平台筛选。

## Deep Profiling：在已知边界内增加细节

本单元还对应官方目录中的 **Deep profiling**、**When to use deep profiling**、**Using deep profiling**、**Top-to-bottom approach**、**Deep profile only when necessary**、**Deep profiling in automated processes** 与 **Deep profiling on low-spec hardware**。

Deep Profiling会在大量托管函数入口和出口插入标记，给出完整调用树，也会显著增加CPU时间和Profiler内存。调用层级深的代码会承担更多标记开销，因此Deep数据适合回答“宽标记内部调用了什么”，不适合与普通采样直接比较绝对耗时。

顶向下流程先用普通Unity Profiler锁定线程、系统和一个宽标记，再判断Allocation Call Stacks、手工ProfilerMarker或原生采样是否已足够。只有信息仍不足时才短时开启Deep；找到首个可修改调用路径后立即关闭，并在普通目标构建上复验真实收益。

Player构建需要预先打开Deep Profiling Support，自动流程可使用命令行开关，但必须限制场景和帧数。低规格硬件上的环形缓冲区可能被样本填满；可以评估Profiler.maxUsedMemory，也要把新增内存计入设备风险。设备无法承受时，优先使用局部插桩。

```csharp
using Unity.Profiling;

static readonly ProfilerMarker NarrowMarker =
    new("Inventory.RebuildVisibleRows");

void RebuildVisibleRows()
{
    using (NarrowMarker.Auto())
        model.Rebuild(viewport);
}
```

Deep模式的退出证据包括：问题路径、调用树截图或原始数据、局部标记位置、关闭Deep后的普通采样，以及相同输入下的性能和正确性对照。没有普通模式复验，Deep结论不得进入发布门。

## 可执行实现骨架

下面的代码只承担本单元的数据所有权或测量边界。真正项目应把阈值放入版本化配置，并让证据文件引用同一个配置哈希。

```csharp
static class SessionState
{
    public static int Score;
    public static event Action? OnReset;

    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
    static void ResetStatics()
    {
        Score = 0;
        OnReset = null;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="官方边界或测量上下文丢失">
  为了缩短进入Play Mode时间直接关闭Domain
  Reload，导致第二次运行继承旧分数、事件订阅和对象引用，出现只在编辑器复现的幽灵状态。
  先保存错误结论、首个偏离节点和原始数据，再恢复官方目录边界与相同测试条件复验。
</Callout>

<Callout type="trap" title="数字改善但工作被转移或结果改变">
  故意降低画质、跳过玩法工作、扩大永久缓存或把任务推迟到下一帧。若主指标改善但GPU、内存、热量、图像或玩法合同变差，发布门必须拒绝。
</Callout>
