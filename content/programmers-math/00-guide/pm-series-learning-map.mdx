## 从问题开始

先把“会计算”改写成五个可反驳的问题：三册目录处理的对象是什么，数学模型保留了哪些信息，图形直觉执行后哪些量应保持不变，程序实验依赖哪些前提，证据链用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

第一册9章、第二册8章、第三册含第0章在内6章，共23个权威核心单元。 因而第一张检查表记录定义和非例；把现实对象映射为变量、集合、关系和假设，并明确模型有效范围。 第二张检查表记录表示变化；用状态、分布和空间变换图观察结构，再回到公式验证。 第三张检查表记录推导所保持的不变量。用小规模枚举、模拟和数值计算检查推导，不把有限实验冒充证明。 负责指出退化边界，每章保留定义、推导、边界、代码和反例，形成可复查结论。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现三册目录和数学模型的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造程序实验的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“把三册当成术语速查表，跳过推导和假设，只记结论。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。贯穿项目选择“有噪声的服务容量预测”：先定义二进制状态与逻辑告警，再用计数和复杂度估计测试空间；接着建立到达与延迟分布，最后用向量状态和线性更新融合观测。每一步都写出假设与反例。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写三册目录与数学模型的输入域和单位；推导栏逐步说明图形直觉使用的规则；边界栏记录程序实验在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用证据链对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
\text{离散推理}\longrightarrow\text{概率模型}\longrightarrow\text{线性空间}\longrightarrow\text{可验证程序}
$$

学习顺序按依赖组织。逻辑、余数、归纳、计数和递归建立离散推理语言；概率分布以计数和条件化为基础；协方差、PCA与卡尔曼滤波又需要向量和矩阵。站内顺序保留原书卷内章节，同时在跨卷复习中补回这些依赖。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
learning_path = {
    "数学思维": 9,
    "概率统计": 8,
    "线性代数": 6,
}
assert sum(learning_path.values()) == 23
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 边界与失败模式

**程序实验**：用小规模枚举、模拟和数值计算检查推导，不把有限实验冒充证明。

**证据链**：每章保留定义、推导、边界、代码和反例，形成可复查结论。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "三册目录到证据链的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "把三册当成术语速查表，跳过推导和假设，只记结论。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

## 常见误区

<Callout type="trap" title="模型前提被省略">把三册当成术语速查表，跳过推导和假设，只记结论。 修复方式是回到对象、输入域和不变量，写出能推翻当前结论的最小反例。</Callout>

<Callout type="trap" title="数值等于证明">认为代码跑出预期数字就证明公式；程序可能与推导共享同一个错误。 有限样例、模拟和浮点结果只能提供实现证据；普遍结论仍需要推导，统计结论还需要不确定性说明。</Callout>
