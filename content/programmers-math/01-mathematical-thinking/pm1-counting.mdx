### 核心单元索引

1. **加法原理**：互斥方案的数量相加；若方案重叠，必须先消除交集或使用容斥。
2. **乘法原理**：连续选择的分支数相乘，每一步的可选数可以依赖前面的选择。
3. **排列**：选择对象且顺序重要；无放回时后续可选数递减。
4. **组合**：只关心选中集合，不关心内部顺序；可由排列除去k阶乘的重复次序。
5. **计数模型**：先建立对象与一一对应关系，再计算；公式只是模型的压缩结果。

这些单元构成一条依赖链。加法原理负责互斥方案的数量相加；若方案重叠，必须先消除交集或使用容斥。 乘法原理负责连续选择的分支数相乘，每一步的可选数可以依赖前面的选择。 排列负责选择对象且顺序重要；无放回时后续可选数递减。 组合负责只关心选中集合，不关心内部顺序；可由排列除去k阶乘的重复次序。 计数模型负责先建立对象与一一对应关系，再计算；公式只是模型的压缩结果。 如果跳过定义直接套公式，计算可能正确，却无法判断结论何时失效。

## 从问题开始

先把“会计算”改写成五个可反驳的问题：加法原理处理的对象是什么，乘法原理保留了哪些信息，排列执行后哪些量应保持不变，组合依赖哪些前提，计数模型用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

互斥方案的数量相加；若方案重叠，必须先消除交集或使用容斥。 因而第一张检查表记录定义和非例；连续选择的分支数相乘，每一步的可选数可以依赖前面的选择。 第二张检查表记录表示变化；选择对象且顺序重要；无放回时后续可选数递减。 第三张检查表记录推导所保持的不变量。只关心选中集合，不关心内部顺序；可由排列除去k阶乘的重复次序。 负责指出退化边界，先建立对象与一一对应关系，再计算；公式只是模型的压缩结果。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现加法原理和乘法原理的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造组合的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“看到“选k个”就用组合公式，却忽略输出是否区分次序、是否允许重复、是否有约束。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。为三个浏览器、两种身份和四种网络状态设计测试，笛卡尔积有24种。但若访客身份不允许离线写入，部分组合无意义。测试设计应先列约束，再用覆盖目标压缩，而不是盲目宣称全组合或随意挑几个样例。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写加法原理与乘法原理的输入域和单位；推导栏逐步说明排列使用的规则；边界栏记录组合在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用计数模型对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
P(n,k)=\frac{n!}{(n-k)!},\qquad {n\choose k}=\frac{n!}{k!(n-k)!}
$$

从n个对象选k个并排序共有n乘(n减1)直到(n减k加1)种。每个无序集合在排列计数中出现k阶乘次，因为选中对象内部任意排序都指向同一组合。因此除以k阶乘得到组合数。这个商必须建立在一一对应上。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
from math import factorial

def choose(n: int, k: int) -> int:
    if not 0 <= k <= n:
        return 0
    k = min(k, n - k)
    result = 1
    for i in range(1, k + 1):
        result = result * (n - k + i) // i
    return result

assert choose(5, 2) == 10
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 机制与数据流

**加法原理**：互斥方案的数量相加；若方案重叠，必须先消除交集或使用容斥。

**乘法原理**：连续选择的分支数相乘，每一步的可选数可以依赖前面的选择。

**排列**：选择对象且顺序重要；无放回时后续可选数递减。

把数据流写成“输入对象 → 表示 → 变换 → 结果 → 证据”。这样可以定位单位、概率质量、维度或状态在哪一步丢失，也能区分数学模型错误与代码实现错误。


## 边界与失败模式

**组合**：只关心选中集合，不关心内部顺序；可由排列除去k阶乘的重复次序。

**计数模型**：先建立对象与一一对应关系，再计算；公式只是模型的压缩结果。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "加法原理到计数模型的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "看到“选k个”就用组合公式，却忽略输出是否区分次序、是否允许重复、是否有约束。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

```python
evidence = [
    ("加法原理", "definition"),
    ("排列", "derivation"),
    ("计数模型", "boundary-and-counterexample"),
]
assert len({name for name, _ in evidence}) == 3
```

1. 手算一个最小非平凡样例，标注每个符号的语义和单位。
2. 运行程序并与手算结果比较，再加入零、边界、非法和退化输入。
3. 故意删除一个关键假设，记录哪个推导步骤首先失效。
4. 固定环境与随机种子重跑，保存残差、频率或复杂度，而不只保存“通过”。
