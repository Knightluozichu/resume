## 原书章节定位

本页对应权威目录中的“第7章 指数爆炸：识别问题空间”，不是把多本数学书的相近主题拼成一章。原书在这里要解决的中心问题是：指数爆炸描述输入每增加一点，候选空间按固定倍数增长。棋盘、密码、子集和递归搜索都可能迅速越过硬件能力。对数帮助反推可承受输入规模，剪枝、近似、随机化和改变问题是常见应对方式。 阅读时先辨认对象和关系，再看符号如何压缩这些关系，最后检查程序是否保持同一语义。

### 核心单元索引

1. **问题空间**：算法可能检查的候选集合；先估计其大小，才能判断暴力法是否可行。
2. **指数增长**：输入增加1使规模乘常数，长期增长远快于任意固定次数多项式。
3. **对数尺度**：把乘法增长转换为加法，可反推位数、安全强度和最大可处理规模。
4. **剪枝**：利用约束提前排除整片候选空间；有效性依赖不会误删可行解的证明。
5. **复杂度策略**：减少输入、改进算法、接受近似或利用领域结构，而不是只寄希望于更快机器。

这些单元构成一条依赖链。问题空间负责算法可能检查的候选集合；先估计其大小，才能判断暴力法是否可行。 指数增长负责输入增加1使规模乘常数，长期增长远快于任意固定次数多项式。 对数尺度负责把乘法增长转换为加法，可反推位数、安全强度和最大可处理规模。 剪枝负责利用约束提前排除整片候选空间；有效性依赖不会误删可行解的证明。 复杂度策略负责减少输入、改进算法、接受近似或利用领域结构，而不是只寄希望于更快机器。 如果跳过定义直接套公式，计算可能正确，却无法判断结论何时失效。

## 从问题开始

先把“会计算”改写成五个可反驳的问题：问题空间处理的对象是什么，指数增长保留了哪些信息，对数尺度执行后哪些量应保持不变，剪枝依赖哪些前提，复杂度策略用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

算法可能检查的候选集合；先估计其大小，才能判断暴力法是否可行。 因而第一张检查表记录定义和非例；输入增加1使规模乘常数，长期增长远快于任意固定次数多项式。 第二张检查表记录表示变化；把乘法增长转换为加法，可反推位数、安全强度和最大可处理规模。 第三张检查表记录推导所保持的不变量。利用约束提前排除整片候选空间；有效性依赖不会误删可行解的证明。 负责指出退化边界，减少输入、改进算法、接受近似或利用领域结构，而不是只寄希望于更快机器。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现问题空间和指数增长的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造剪枝的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“只看小输入运行很快就断言算法可扩展，没有画增长曲线或估算翻倍后的成本。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。功能开关组合测试有n个二元开关，完全枚举是2的n次方。团队应识别互斥约束、关键交互和风险优先级，用成对覆盖或性质测试压缩；同时保留少量端到端组合验证，不能把压缩后的覆盖误称为穷尽证明。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写问题空间与指数增长的输入域和单位；推导栏逐步说明对数尺度使用的规则；边界栏记录剪枝在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用复杂度策略对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
S(n)=2^n,\qquad n=\log_2 S
$$

n个布尔变量各有两种选择，连续应用乘法原理得到2的n次方种赋值。若每秒检查十亿种，60位空间仍需数十年量级。硬件快一倍只多处理一个二进制位，说明指数问题不能靠常数优化根治。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
def subsets(values):
    result = [[]]
    for value in values:
        result += [subset + [value] for subset in result]
    return result

items = list(range(10))
assert len(subsets(items)) == 2 ** len(items)
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 机制与数据流

**问题空间**：算法可能检查的候选集合；先估计其大小，才能判断暴力法是否可行。

**指数增长**：输入增加1使规模乘常数，长期增长远快于任意固定次数多项式。

**对数尺度**：把乘法增长转换为加法，可反推位数、安全强度和最大可处理规模。

把数据流写成“输入对象 → 表示 → 变换 → 结果 → 证据”。这样可以定位单位、概率质量、维度或状态在哪一步丢失，也能区分数学模型错误与代码实现错误。

## 边界与失败模式

**剪枝**：利用约束提前排除整片候选空间；有效性依赖不会误删可行解的证明。

**复杂度策略**：减少输入、改进算法、接受近似或利用领域结构，而不是只寄希望于更快机器。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "问题空间到复杂度策略的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "只看小输入运行很快就断言算法可扩展，没有画增长曲线或估算翻倍后的成本。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

## 常见误区

<Callout type="trap" title="模型前提被省略">只看小输入运行很快就断言算法可扩展，没有画增长曲线或估算翻倍后的成本。 修复方式是回到对象、输入域和不变量，写出能推翻当前结论的最小反例。</Callout>

<Callout type="trap" title="数值等于证明">把剪枝当启发式随意删除分支，却没有证明被删除区域不含正确答案。 有限样例、模拟和浮点结果只能提供实现证据；普遍结论仍需要推导，统计结论还需要不确定性说明。</Callout>
