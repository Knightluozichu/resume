先不要计算。预测当输入规模、随机机制、基底或数值精度变化时，结论是否仍成立；再写出你依赖的假设。递归定义由基例和缩小规则组成。汉诺塔、阶乘、斐波那契和递归图形展示同一模式：把规模n的问题归约为更小问题，并明确如何组合答案。程序实现还必须分析调用树、栈深和重复子问题。 本章用<Term def="对象通过更小规模的同类对象定义，同时必须给出不再递归的基例。">递归定义</Term>、<Term def="用相邻规模的数值关系描述成本或答案，是从程序结构到数学模型的桥梁。">递推关系</Term>、<Term def="每次调用保存参数、局部状态和返回位置；深度过大可能耗尽栈空间。">调用栈</Term>、<Term def="不同分支计算同一输入时，朴素递归会指数重复，可用记忆化或迭代消除。">重复子问题</Term>、<Term def="沿树、列表或语法结构下降，正确性依赖每一步都进入严格更小的子结构。">结构递归</Term>建立可检查的语言。

## 原书章节定位

本页对应权威目录中的“第6章 递归：用自身定义自身”，不是把多本数学书的相近主题拼成一章。原书在这里要解决的中心问题是：递归定义由基例和缩小规则组成。汉诺塔、阶乘、斐波那契和递归图形展示同一模式：把规模n的问题归约为更小问题，并明确如何组合答案。程序实现还必须分析调用树、栈深和重复子问题。 阅读时先辨认对象和关系，再看符号如何压缩这些关系，最后检查程序是否保持同一语义。

### 核心单元索引

1. **递归定义**：对象通过更小规模的同类对象定义，同时必须给出不再递归的基例。
2. **递推关系**：用相邻规模的数值关系描述成本或答案，是从程序结构到数学模型的桥梁。
3. **调用栈**：每次调用保存参数、局部状态和返回位置；深度过大可能耗尽栈空间。
4. **重复子问题**：不同分支计算同一输入时，朴素递归会指数重复，可用记忆化或迭代消除。
5. **结构递归**：沿树、列表或语法结构下降，正确性依赖每一步都进入严格更小的子结构。

这些单元构成一条依赖链。递归定义负责对象通过更小规模的同类对象定义，同时必须给出不再递归的基例。 递推关系负责用相邻规模的数值关系描述成本或答案，是从程序结构到数学模型的桥梁。 调用栈负责每次调用保存参数、局部状态和返回位置；深度过大可能耗尽栈空间。 重复子问题负责不同分支计算同一输入时，朴素递归会指数重复，可用记忆化或迭代消除。 结构递归负责沿树、列表或语法结构下降，正确性依赖每一步都进入严格更小的子结构。 如果跳过定义直接套公式，计算可能正确，却无法判断结论何时失效。

## 从问题开始

先把“会计算”改写成五个可反驳的问题：递归定义处理的对象是什么，递推关系保留了哪些信息，调用栈执行后哪些量应保持不变，重复子问题依赖哪些前提，结构递归用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

对象通过更小规模的同类对象定义，同时必须给出不再递归的基例。 因而第一张检查表记录定义和非例；用相邻规模的数值关系描述成本或答案，是从程序结构到数学模型的桥梁。 第二张检查表记录表示变化；每次调用保存参数、局部状态和返回位置；深度过大可能耗尽栈空间。 第三张检查表记录推导所保持的不变量。不同分支计算同一输入时，朴素递归会指数重复，可用记忆化或迭代消除。 负责指出退化边界，沿树、列表或语法结构下降，正确性依赖每一步都进入严格更小的子结构。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现递归定义和递推关系的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造重复子问题的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“只有递归调用没有可达基例，或递归参数并未严格变小，程序最终耗尽调用栈。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。遍历目录树是结构递归：文件是基例，目录的结果由子项结果组合。工程实现必须处理符号链接环、权限失败、深度限制和部分结果。数学上的树若被现实链接变成图，就需要已访问集合恢复“规模严格减小”的前提。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写递归定义与递推关系的输入域和单位；推导栏逐步说明调用栈使用的规则；边界栏记录重复子问题在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用结构递归对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
T(n)=2T(n-1)+1,\ T(0)=0\Rightarrow T(n)=2^n-1
$$

汉诺塔先把n减1个盘移到辅助柱，再移动最大盘，最后把n减1个盘移到目标柱，因此次数满足两倍前一规模加1。展开得到2的n次方减1；这也说明递归写法虽短，工作量仍会指数增长。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative")
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

assert fib(20) == 6765
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 机制与数据流

**递归定义**：对象通过更小规模的同类对象定义，同时必须给出不再递归的基例。

**递推关系**：用相邻规模的数值关系描述成本或答案，是从程序结构到数学模型的桥梁。

**调用栈**：每次调用保存参数、局部状态和返回位置；深度过大可能耗尽栈空间。

把数据流写成“输入对象 → 表示 → 变换 → 结果 → 证据”。这样可以定位单位、概率质量、维度或状态在哪一步丢失，也能区分数学模型错误与代码实现错误。

## 边界与失败模式

**重复子问题**：不同分支计算同一输入时，朴素递归会指数重复，可用记忆化或迭代消除。

**结构递归**：沿树、列表或语法结构下降，正确性依赖每一步都进入严格更小的子结构。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "递归定义到结构递归的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "只有递归调用没有可达基例，或递归参数并未严格变小，程序最终耗尽调用栈。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

## 工程案例

遍历目录树是结构递归：文件是基例，目录的结果由子项结果组合。工程实现必须处理符号链接环、权限失败、深度限制和部分结果。数学上的树若被现实链接变成图，就需要已访问集合恢复“规模严格减小”的前提。 案例验收应同时保存输入快照、参数与单位、算法版本、随机种子、退出状态和摘要结果。若只保存最终图或最终数字，后来无法区分数据变化、模型变化和实现变化。

## 常见误区

<Callout type="trap" title="模型前提被省略">只有递归调用没有可达基例，或递归参数并未严格变小，程序最终耗尽调用栈。 修复方式是回到对象、输入域和不变量，写出能推翻当前结论的最小反例。</Callout>

<Callout type="trap" title="数值等于证明">把代码行数短误认为复杂度低；调用树可能指数膨胀，必须分析重复子问题。 有限样例、模拟和浮点结果只能提供实现证据；普遍结论仍需要推导，统计结论还需要不确定性说明。</Callout>
