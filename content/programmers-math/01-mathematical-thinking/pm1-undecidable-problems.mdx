## 原书章节定位

本页对应权威目录中的“第8章 不可解问题：程序能力的边界”，不是把多本数学书的相近主题拼成一章。原书在这里要解决的中心问题是：本章用反证法、可数性、对角论证和停机问题说明：有些问题不是资源不足，而是不存在对所有输入都正确的算法。认识不可判定边界，能防止把静态分析、验证和安全扫描承诺成不可能的万能工具。 阅读时先辨认对象和关系，再看符号如何压缩这些关系，最后检查程序是否保持同一语义。

### 核心单元索引

1. **反证法**：假设结论的否定成立，并推导矛盾；矛盾必须来自假设与已知规则。
2. **可数集合**：能与自然数建立一一对应；有限字符串和程序文本虽无限但可枚举。
3. **对角论证**：构造一个在第n位不同于第n个对象的新对象，证明任何枚举都不完整。
4. **停机问题**：不存在一个程序能对任意程序及输入总是判定其最终是否停止。
5. **半判定**：某些问题找到证据时可以确认，但无证据分支可能永不结束；超时不等于逻辑否定。

这些单元构成一条依赖链。反证法负责假设结论的否定成立，并推导矛盾；矛盾必须来自假设与已知规则。 可数集合负责能与自然数建立一一对应；有限字符串和程序文本虽无限但可枚举。 对角论证负责构造一个在第n位不同于第n个对象的新对象，证明任何枚举都不完整。 停机问题负责不存在一个程序能对任意程序及输入总是判定其最终是否停止。 半判定负责某些问题找到证据时可以确认，但无证据分支可能永不结束；超时不等于逻辑否定。 如果跳过定义直接套公式，计算可能正确，却无法判断结论何时失效。

## 从问题开始

先把“会计算”改写成五个可反驳的问题：反证法处理的对象是什么，可数集合保留了哪些信息，对角论证执行后哪些量应保持不变，停机问题依赖哪些前提，半判定用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

假设结论的否定成立，并推导矛盾；矛盾必须来自假设与已知规则。 因而第一张检查表记录定义和非例；能与自然数建立一一对应；有限字符串和程序文本虽无限但可枚举。 第二张检查表记录表示变化；构造一个在第n位不同于第n个对象的新对象，证明任何枚举都不完整。 第三张检查表记录推导所保持的不变量。不存在一个程序能对任意程序及输入总是判定其最终是否停止。 负责指出退化边界，某些问题找到证据时可以确认，但无证据分支可能永不结束；超时不等于逻辑否定。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现反证法和可数集合的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造停机问题的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“把尚未找到算法等同于已证明不可解；不可判定性需要严格归约或对角证明。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。静态分析器可以对受限语言、有限状态或特定缺陷给出可靠结论，却不能普遍判定任意程序所有运行性质。工程文档必须区分已证明安全、找到反例、分析超时和超出模型四种状态，不能把“未发现问题”写成“没有问题”。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写反证法与可数集合的输入域和单位；推导栏逐步说明对角论证使用的规则；边界栏记录停机问题在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用半判定对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
|\{\text{programs}\}|=\aleph_0,\qquad |\{f:\mathbb N\to\{0,1\}\}|>\aleph_0
$$

假设存在万能停机判定器H。构造程序D：输入程序p，若H判断p以自身为输入会停机，D就无限循环；否则D立即停止。询问D对自身的行为，两种回答都会与D的定义相反，因此H不可能存在。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
from collections.abc import Iterator

def enumerate_binary_strings() -> Iterator[str]:
    yield ""
    width = 1
    while True:
        for value in range(2 ** width):
            yield format(value, f"0{width}b")
        width += 1

stream = enumerate_binary_strings()
assert [next(stream) for _ in range(4)] == ["", "0", "1", "00"]
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 机制与数据流

**反证法**：假设结论的否定成立，并推导矛盾；矛盾必须来自假设与已知规则。

**可数集合**：能与自然数建立一一对应；有限字符串和程序文本虽无限但可枚举。

**对角论证**：构造一个在第n位不同于第n个对象的新对象，证明任何枚举都不完整。

把数据流写成“输入对象 → 表示 → 变换 → 结果 → 证据”。这样可以定位单位、概率质量、维度或状态在哪一步丢失，也能区分数学模型错误与代码实现错误。

## 边界与失败模式

**停机问题**：不存在一个程序能对任意程序及输入总是判定其最终是否停止。

**半判定**：某些问题找到证据时可以确认，但无证据分支可能永不结束；超时不等于逻辑否定。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "反证法到半判定的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "把尚未找到算法等同于已证明不可解；不可判定性需要严格归约或对角证明。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

## 工程案例

静态分析器可以对受限语言、有限状态或特定缺陷给出可靠结论，却不能普遍判定任意程序所有运行性质。工程文档必须区分已证明安全、找到反例、分析超时和超出模型四种状态，不能把“未发现问题”写成“没有问题”。 案例验收应同时保存输入快照、参数与单位、算法版本、随机种子、退出状态和摘要结果。若只保存最终图或最终数字，后来无法区分数据变化、模型变化和实现变化。

## 常见误区

<Callout type="trap" title="模型前提被省略">把尚未找到算法等同于已证明不可解；不可判定性需要严格归约或对角证明。 修复方式是回到对象、输入域和不变量，写出能推翻当前结论的最小反例。</Callout>

<Callout type="trap" title="数值等于证明">把超时当成不停机证明；有限等待只能说明在该预算内没有停止。 有限样例、模拟和浮点结果只能提供实现证据；普遍结论仍需要推导，统计结论还需要不确定性说明。</Callout>
