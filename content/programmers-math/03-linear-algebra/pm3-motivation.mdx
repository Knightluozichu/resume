## 原书章节定位

本页对应权威目录中的“第0章 动机：空间想象与线性近似”，不是把多本数学书的相近主题拼成一章。原书在这里要解决的中心问题是：线性代数的价值不止是解方程。向量把对象放进空间，矩阵表达映射，局部线性化让复杂非线性问题可计算。动机章要求读者先看见几何和程序中的用途，再进入符号推导。 阅读时先辨认对象和关系，再看符号如何压缩这些关系，最后检查程序是否保持同一语义。

### 核心单元索引

1. **空间想象**：把多个数视为一个点或方向，关系、距离和变换因而可视化。
2. **向量表示**：按固定顺序收集特征；每一维的语义、单位和基底必须明确。
3. **线性映射**：保持加法与数乘的变换，可由矩阵统一表示并组合。
4. **线性近似**：在局部用切线或雅可比矩阵逼近非线性函数，误差随步长增大。
5. **数值证据**：图形直觉、代数等式和程序计算相互检查，尤其关注尺度与舍入。

这些单元构成一条依赖链。空间想象负责把多个数视为一个点或方向，关系、距离和变换因而可视化。 向量表示负责按固定顺序收集特征；每一维的语义、单位和基底必须明确。 线性映射负责保持加法与数乘的变换，可由矩阵统一表示并组合。 线性近似负责在局部用切线或雅可比矩阵逼近非线性函数，误差随步长增大。 数值证据负责图形直觉、代数等式和程序计算相互检查，尤其关注尺度与舍入。 如果跳过定义直接套公式，计算可能正确，却无法判断结论何时失效。

## 从问题开始

先把“会计算”改写成五个可反驳的问题：空间想象处理的对象是什么，向量表示保留了哪些信息，线性映射执行后哪些量应保持不变，线性近似依赖哪些前提，数值证据用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

把多个数视为一个点或方向，关系、距离和变换因而可视化。 因而第一张检查表记录定义和非例；按固定顺序收集特征；每一维的语义、单位和基底必须明确。 第二张检查表记录表示变化；保持加法与数乘的变换，可由矩阵统一表示并组合。 第三张检查表记录推导所保持的不变量。在局部用切线或雅可比矩阵逼近非线性函数，误差随步长增大。 负责指出退化边界，图形直觉、代数等式和程序计算相互检查，尤其关注尺度与舍入。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现空间想象和向量表示的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造线性近似的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“把向量只看成数字列表，忽略维度语义、单位和基底，导致合法运算产生无意义结果。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。相机标定把三维点通过投影映射到像素。完整模型非线性，但在当前参数附近可以用雅可比预测微小参数调整如何改变重投影误差。迭代优化每步都依赖局部近似，步长过大会离开可信邻域。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写空间想象与向量表示的输入域和单位；推导栏逐步说明线性映射使用的规则；边界栏记录线性近似在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用数值证据对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
f(x+\Delta x)\approx f(x)+J_f(x)\Delta x
$$

一元函数在点x附近的增量可由导数乘步长近似；多元函数把导数推广为雅可比矩阵。这个矩阵把输入微小变化映射到输出变化，是优化、控制、图形变换和机器学习反向传播的共同局部模型。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
def derivative(f, x, h=1e-6):
    return (f(x + h) - f(x - h)) / (2 * h)

f = lambda x: x * x
linear = f(3.0) + derivative(f, 3.0) * 0.01
assert abs(linear - f(3.01)) < 1e-3
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 机制与数据流

**空间想象**：把多个数视为一个点或方向，关系、距离和变换因而可视化。

**向量表示**：按固定顺序收集特征；每一维的语义、单位和基底必须明确。

**线性映射**：保持加法与数乘的变换，可由矩阵统一表示并组合。

把数据流写成“输入对象 → 表示 → 变换 → 结果 → 证据”。这样可以定位单位、概率质量、维度或状态在哪一步丢失，也能区分数学模型错误与代码实现错误。

## 边界与失败模式

**线性近似**：在局部用切线或雅可比矩阵逼近非线性函数，误差随步长增大。

**数值证据**：图形直觉、代数等式和程序计算相互检查，尤其关注尺度与舍入。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "空间想象到数值证据的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "把向量只看成数字列表，忽略维度语义、单位和基底，导致合法运算产生无意义结果。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

## 常见误区

<Callout type="trap" title="模型前提被省略">把向量只看成数字列表，忽略维度语义、单位和基底，导致合法运算产生无意义结果。 修复方式是回到对象、输入域和不变量，写出能推翻当前结论的最小反例。</Callout>

<Callout type="trap" title="数值等于证明">把局部线性近似外推到远处，不估计截断误差或调整步长。 有限样例、模拟和浮点结果只能提供实现证据；普遍结论仍需要推导，统计结论还需要不确定性说明。</Callout>
