## 原书章节定位

本页对应权威目录中的“《程序员的数学》三册总复习”，不是把多本数学书的相近主题拼成一章。原书在这里要解决的中心问题是：总复习不再按卷隔离知识，而是检验能否从现实问题选择离散、概率或线性模型，推导结论，识别适用边界，并用程序与反例建立证据。23章的验收标准是能迁移，而不是能复述。 阅读时先辨认对象和关系，再看符号如何压缩这些关系，最后检查程序是否保持同一语义。

### 核心单元索引

1. **离散推理链**：位权、逻辑、模运算、归纳和递归共同描述有限程序如何处理无限规模。
2. **状态空间**：计数与指数增长决定穷举边界，不可判定性说明算法能力还有原则极限。
3. **概率推断**：联合、条件、分布、估计和随机过程把不确定性变成可计算模型。
4. **线性系统**：向量、矩阵、秩、分解和特征值解释表示、求解与长期行为。
5. **综合验收**：结论必须附输入域、单位、随机机制、数值误差和可重放证据。

这些单元构成一条依赖链。离散推理链负责位权、逻辑、模运算、归纳和递归共同描述有限程序如何处理无限规模。 状态空间负责计数与指数增长决定穷举边界，不可判定性说明算法能力还有原则极限。 概率推断负责联合、条件、分布、估计和随机过程把不确定性变成可计算模型。 线性系统负责向量、矩阵、秩、分解和特征值解释表示、求解与长期行为。 综合验收负责结论必须附输入域、单位、随机机制、数值误差和可重放证据。 如果跳过定义直接套公式，计算可能正确，却无法判断结论何时失效。

## 从问题开始

先把“会计算”改写成五个可反驳的问题：离散推理链处理的对象是什么，状态空间保留了哪些信息，概率推断执行后哪些量应保持不变，线性系统依赖哪些前提，综合验收用什么观测验收？回答时必须给出对象集合、输入域、单位或概率机制。若这些信息缺失，同一个符号可能在相邻步骤中悄悄换义，后面的精确计算也无法挽救模型。

位权、逻辑、模运算、归纳和递归共同描述有限程序如何处理无限规模。 因而第一张检查表记录定义和非例；计数与指数增长决定穷举边界，不可判定性说明算法能力还有原则极限。 第二张检查表记录表示变化；联合、条件、分布、估计和随机过程把不确定性变成可计算模型。 第三张检查表记录推导所保持的不变量。向量、矩阵、秩、分解和特征值解释表示、求解与长期行为。 负责指出退化边界，结论必须附输入域、单位、随机机制、数值误差和可重放证据。 则把数学结论翻译成可观察证据。五张表共同回答“为什么这一步可以做”，而不只回答“怎么算”。

$$
\mathcal M:X\longrightarrow Y,\qquad x\mapsto y
$$

这里的映射符号不是说所有章节都线性，而是要求明确输入集合X、输出集合Y和模型M。离散章节的M可以是逻辑规则或递归，概率章节可以是分布或条件化，线性代数章节则常由矩阵实现。模型改变时，旧结论必须重新验收。

## 反例推演

从正常样例开始：选择一个能同时出现离散推理链和状态空间的最小输入，手算中间状态；随后把规模减到零或一，检查定义是否仍有意义；再制造线性系统的退化情形，观察结果是不存在、不唯一、偏差增大还是数值不稳定。最后使用“跨章综合时混用不同总体、基底或单位，公式单独正确但组合后失去语义。”作为反例方向，指出最先失效的定义或等式。

反例不是为了否定整章，而是标记结论的边界。一个合格说明要写成“在条件A、B、C下得到结论Q；删除B时，输入x产生现象R，因此Q不能外推”。只说“这个例子不工作”不足以区分模型错误、实现错误与资源耗尽。综合题：为带噪传感器的环形事件缓冲设计异常检测。模运算管理槽位，逻辑定义告警，归纳证明索引不越界，概率分布描述噪声，协方差识别联合异常，LU或特征方法求模型。最终用故障注入和固定种子重放。

$$
\varepsilon=\operatorname{distance}(y_{observed},y_{predicted})
$$

距离的含义随章节变化：精确离散结果可用相等或不变量，概率模拟可用频率误差与区间，数值线性代数可用残差范数和相对误差。先定义误差，再运行实验；不能看到输出以后才挑一个对自己有利的指标。

## 验收证书

验收证书包含五栏。定义栏写离散推理链与状态空间的输入域和单位；推导栏逐步说明概率推断使用的规则；边界栏记录线性系统在零值、极值和退化输入下的状态；实现栏保存算法版本、依赖和随机种子；结论栏用综合验收对应的误差或反例决定通过。任何一栏缺失，都只能称为演示，不能称为可复核结论。

$$
\operatorname{accept}=\bigl(\text{assumptions hold}\bigr)\land\bigl(\varepsilon\le\tau\bigr)\land\bigl(\text{counterexamples explained}\bigr)
$$

阈值tau必须在看结果前定义，并与业务或数值预算关联。精确问题的阈值可以是零，浮点问题应按尺度使用相对容差，统计问题应报告区间与功效而不是硬凑单点。验收结论还要注明未覆盖范围，使下一位读者知道哪里需要重新建模。

## 可核查推导

$$
\text{定义}\to\text{推导}\to\text{算法}\to\text{边界实验}\to\text{反例}
$$

一个完整解答先声明样本空间或向量空间，再写变量和不变量；随后选择证明、估计或数值分解；最后检查复杂度、统计误差、条件数与不可判定边界。不同数学工具负责不同不确定性，不能用单一分数掩盖模型缺口。 推导中的每个等号都应能说明用了定义、代数恒等式还是额外假设。若某一步只在有限、独立、满秩或可导等条件下成立，就把条件写在该步旁边，而不是藏在结论之后。

```python
evidence = {
    "definition": True,
    "derivation": True,
    "boundary_cases": 5,
    "counterexample": True,
    "reproducible_seed": 20260715,
}
assert all([evidence["definition"], evidence["derivation"], evidence["counterexample"]])
```

上面的程序是推导的一个有限投影。它能发现实现错误，却不能单独证明对所有输入成立。验收时至少用手算小例、随机样例和故意破坏假设的反例三路比较。

## 机制与数据流

**离散推理链**：位权、逻辑、模运算、归纳和递归共同描述有限程序如何处理无限规模。

**状态空间**：计数与指数增长决定穷举边界，不可判定性说明算法能力还有原则极限。

**概率推断**：联合、条件、分布、估计和随机过程把不确定性变成可计算模型。

把数据流写成“输入对象 → 表示 → 变换 → 结果 → 证据”。这样可以定位单位、概率质量、维度或状态在哪一步丢失，也能区分数学模型错误与代码实现错误。

## 边界与失败模式

**线性系统**：向量、矩阵、秩、分解和特征值解释表示、求解与长期行为。

**综合验收**：结论必须附输入域、单位、随机机制、数值误差和可重放证据。

边界测试不只包括零、空集合和单元素。离散问题要检查规模翻倍与溢出，概率问题要检查归一化、相关性和尾部，线性代数问题要检查维度、秩、条件数与浮点残差。只有失败状态也能被解释，模型才可用于工程决策。

```python
experiment = {
    "claim": "离散推理链到综合验收的关系",
    "normal_case": "满足本章全部假设",
    "boundary_case": "零规模、退化分布或近奇异输入",
    "counterexample": "跨章综合时混用不同总体、基底或单位，公式单独正确但组合后失去语义。",
}
assert set(experiment) == {"claim", "normal_case", "boundary_case", "counterexample"}
```

## 工程案例

综合题：为带噪传感器的环形事件缓冲设计异常检测。模运算管理槽位，逻辑定义告警，归纳证明索引不越界，概率分布描述噪声，协方差识别联合异常，LU或特征方法求模型。最终用故障注入和固定种子重放。 案例验收应同时保存输入快照、参数与单位、算法版本、随机种子、退出状态和摘要结果。若只保存最终图或最终数字，后来无法区分数据变化、模型变化和实现变化。

1. 手算一个最小非平凡样例，标注每个符号的语义和单位。
2. 运行程序并与手算结果比较，再加入零、边界、非法和退化输入。
3. 故意删除一个关键假设，记录哪个推导步骤首先失效。
4. 固定环境与随机种子重跑，保存残差、频率或复杂度，而不只保存“通过”。

## 常见误区

<Callout type="trap" title="模型前提被省略">跨章综合时混用不同总体、基底或单位，公式单独正确但组合后失去语义。 修复方式是回到对象、输入域和不变量，写出能推翻当前结论的最小反例。</Callout>

<Callout type="trap" title="数值等于证明">只报一个最终数字，不给区间、残差、复杂度和失败状态。 有限样例、模拟和浮点结果只能提供实现证据；普遍结论仍需要推导，统计结论还需要不确定性说明。</Callout>
