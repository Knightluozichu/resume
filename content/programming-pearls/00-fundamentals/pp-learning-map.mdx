## 直觉引入

想象你是侦探。新手侦探拿到案子就冲去抓嫌疑人，老侦探先花半天理清案情。编程珠玑的核心思想就是先想清楚再写代码：Bentley 用一个个真实案例展示，很多看似需要复杂算法的问题，换个角度思考就豁然开朗。全书精神：对问题的深刻理解往往比精妙的算法更重要。

全书分四大板块，呈思维方法→算法优化→程序设计→专题文章的递进关系。Bentley 的特色是用专栏文章的形式，每章一个独立故事，从真实问题出发引出深刻的编程思想。

### 学习路径

先学问题分析方法（正确定义问题、二分思维），再学算法优化（位图、二分搜索），然后学程序设计原则（代码调优、粗略估算），最后读专题文章。

## 代码对照

```java
// 同一问题：在有序数组中查找元素
// 错误的看起来对的二分搜索
int buggySearch(int[] a, int key) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;  // BUG: 溢出
        if (a[mid] < key) lo = mid;  // BUG: 不收缩
        else if (a[mid] > key) hi = mid;
        else return mid;
        // 可能死循环
    }
    return -1;
}

// 正确的二分搜索
int correctSearch(int[] a, int key) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;  // 防溢出
        if (a[mid] < key) lo = mid + 1;  // 收缩
        else if (a[mid] > key) hi = mid - 1;
        else return mid;
    }
    return -1;
}
// Bentley 发现 90% 的程序员写不出正确的二分搜索
```

## 常见误区

<Callout type="trap">
**误区：认为编程珠玑是算法书。**
编程珠玑的核心不是算法而是思维方法。它教你如何定义问题、如何估算、如何验证正确性。算法只是载体。
</Callout>

<Callout type="trap">
**误区：跳过问题定义直接写代码。**
全书第一章就讲正确定义问题。很多 bug 不是代码错误而是问题定义错误。
</Callout>

<Exercises>
**问题 1**：全书四大板块是什么？它们之间是什么关系？

<Answer>
基础思维、算法优化、程序设计、专题文章。呈递进关系：基础思维提供方法论，算法优化用经典案例展示正确性优先，程序设计从算法到工程的桥梁，专题文章收束思想。
</Answer>

**问题 2**：为什么 Bentley 说90%的程序员写不出正确的二分搜索？

<Answer>
二分搜索看似简单但边界条件极易出错：mid溢出、lo/hi不收缩导致死循环、终止条件选择。简单算法的正确性验证比复杂度分析更重要。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="问题定义">编程第一步，明确输入、输出、约束和正确性条件。好的定义已解决一半问题。</GlossaryItem>
<GlossaryItem term="二分搜索">有序集合中每次折半查找，O(log n)。看似简单但边界极易出错。</GlossaryItem>
<GlossaryItem term="位向量">用位运算压缩数据，每个 bit 表示一个布尔值。空间效率极高。</GlossaryItem>
<GlossaryItem term="粗略估算">信封背面计算，用数量级估算快速判断方案可行性。</GlossaryItem>
</Glossary>
