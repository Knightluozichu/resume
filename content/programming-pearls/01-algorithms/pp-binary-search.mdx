## 直觉引入

Bentley 给专业程序员布置了一个任务：写二分搜索。结果是——90%的人写错了。二分搜索只有几行代码，但边界条件（mid 计算、lo/hi 更新、终止条件）极易出错。这一章的教训：简单不等于容易，正确性验证比写代码更重要。

## 概念讲解

### 二分搜索的正确实现

<PpBinarySearchDiagram />

<Term def="二分搜索在有序数组中每次折半查找，正确实现需要精确处理mid计算、lo/hi收缩和终止条件">二分搜索</Term>

正确实现的三个要点：1）mid = lo + (hi-lo)/2 防止溢出（而非 (lo+hi)/2）；2）lo = mid+1 和 hi = mid-1 必须收缩（而非 lo=mid），否则可能死循环；3）终止条件 lo &lt;= hi（包含等号），确保最后检查 mid==key。

### 循环不变式

循环不变式是证明算法正确性的工具：在每次循环开始时，如果 key 存在则一定在 [lo, hi] 范围内。初始化时为真（key 在 [0, n-1]），保持时（每次缩小范围但 key 若存在仍在范围内），终止时（lo>hi 说明 key 不存在）。

<Stepper>
<Step title="lo/hi收缩">lo=mid+1 和 hi=mid-1 必须加减1。如果用 lo=mid，当 lo和hi 相邻时 mid=lo，lo 永远不前进，死循环。</Step>
<Step title="终止条件">while(lo&lt;=hi) 包含等号。当 lo==hi 时还需检查 a[lo]==key。如果用 lo&lt;hi 则漏掉最后一个元素。</Step>
</Stepper>

## 代码对照

```java
// 正确的二分搜索
int binarySearch(int[] a, int key) {
    int lo = 0, hi = a.length - 1;
    while (lo &lt;= hi) {  // 包含等号
        int mid = lo + (hi - lo) / 2;  // 防溢出
        if (a[mid] &lt; key) lo = mid + 1;  // 收缩
        else if (a[mid] > key) hi = mid - 1;  // 收缩
        else return mid;
    }
    return -1;
}

// 变体：lower_bound（第一个 >= key 的位置）
int lowerBound(int[] a, int key) {
    int lo = 0, hi = a.length;
    while (lo &lt; hi) {  // 注意：hi 初始化为 length，用 &lt;
        int mid = lo + (hi - lo) / 2;
        if (a[mid] &lt; key) lo = mid + 1;
        else hi = mid;  // 不收缩，hi=mid
    }
    return lo;
}

// 变体：upper_bound（第一个 > key 的位置）
int upperBound(int[] a, int key) {
    int lo = 0, hi = a.length;
    while (lo &lt; hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] &lt;= key) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```

## 常见误区

<Callout type="trap">
**误区：用 (lo+hi)/2 计算 mid。**
当数组很大时 lo+hi 可能溢出 int 范围（>2^31-1），产生负数导致数组越界。这是 Java 标准库在 2006 年才修复的 bug。用 lo+(hi-lo)/2 安全。
</Callout>

<Callout type="trap">
**误区：二分搜索很简单所以不会出错。**
Bentley 的实验证明 90% 的程序员写不对。简单算法的正确性验证反而更难，因为你不会仔细测试「看起来对」的代码。
</Callout>

<Exercises>
**问题 1**：用循环不变式证明二分搜索的正确性。

<Answer>
不变式：key 若存在则一定在 [lo,hi] 范围内。初始化为真。保持：若 a[mid]&lt;key 则 key 在 mid 右侧，lo=mid+1 后 key 仍在 [lo,hi]；类似处理 &gt;。终止：lo&gt;hi 说明范围空，key 不存在。
</Answer>

**问题 2**：lower_bound 和 binarySearch 的 lo/hi 更新有什么不同？为什么？

<Answer>
binarySearch 用 lo=mid+1/hi=mid-1（精确匹配，可跳过 mid）。lower_bound 用 hi=mid（找第一个>=key，a[mid]>=key 时 mid 可能是答案不能跳过）。终止条件也不同：前者 lo&lt;=hi，后者 lo&lt;hi。
</Answer>
</Exercises>
