## 从“一千行程序其实只在做一件事”开始

Column 3描述一种常见失败：程序包含hundreds of cases，概念上却只是：

```c
if (k ==   1) c001++;
if (k ==   2) c002++;
// ... hundreds of repeated branches ...
if (k == 500) c500++;
```

先预测：若category从500扩到1000，是继续复制branches，还是把category number直接当data address？

Data Structures Program（）的核心原则是：**不要用program text手工编码本可由data表达的规律。**


## 3.1 A Survey Program：500个变量变成一个数组

Survey Program读取value 1到500，并统计frequency。用array：

```c
enum { MIN_ANSWER = 1, MAX_ANSWER = 500 };
uint64_t count[MAX_ANSWER + 1] = {0};

while (read_answer(&k)) {
    if (k < MIN_ANSWER || k > MAX_ANSWER) fail("answer out of range");
    count[k] += 1;
}
```

数组（）让input value k同时成为category和address。


处理前t个responses后，invariant：

$$
\operatorname{count}[v]
=
\left|\{i\mid0\le i<t,\ x_i=v\}\right|
$$

Initialization时all counts zero；读到valid k只增加对应bucket；termination时every response恰好贡献once。

Code length从O(number of categories) special branches降为O(1) generic loop；data size仍是O(domain)，这是正确的成本归属。


## 3.2 Generalizing can be simpler

为fixed 500 cases写500个names看似“具体”，实际更难review和change。把problem推广为n categories后，one indexed rule反而更短：

$$
T(m)=\Theta(m+n),\qquad S(n)=\Theta(n)
$$

其中m是responses，n是category count。General version明确了domain和cost，也自然支持different n。

这是一种Inventor's paradox：solving a more general indexed problem can be easier than enumerating a specific large case。前提是variation真的由one key统一；若each category有different semantics，应使用records或strategy table，而不是硬塞进numeric array。

## 3.3 Form-Letter Programming：内容是data，布局是template

Form-Letter Programming（）把：

- repeated prose and layout放进template；
- title、author、city、year等变化放进record；
- placeholder substitution放进one renderer。


Data可表示为name-value pairs：

```text
%title Programming Pearls
%author Jon Bentley
%city Reading, Massachusetts
%year 1999
```

Template：

```text
%title
%author
%city, %year
```


旧做法为every letter copy source，再改four literals；布局change必须编辑all copies。Data-driven version只改one template，new record不需要new branch。

Renderer contract：

- Every required placeholder must resolve exactly once。
- Unknown fields按policy reject或ignore。
- Escaping取决于output target，HTML、SQL和plain text不可共享同一种escape。
- Optional fields用explicit condition，不靠空字符串偶然排版。
- Template与record schema要versioned。

## 3.4 An Array of Examples

数组实例（Array of Examples）不只用于survey counters：

- Month index到days lookup。
- Character code到frequency。
- State enum到handler function。
- Product id到price。
- Polynomial degree到coefficient。
- Matrix row/column到cell。
- Finite-state machine的state/event到next state。


共同结构是：key来自small dense integer domain，same operation适用于all elements。

若key sparse，例如customer IDs横跨64-bit universe，direct array浪费space；若需要ordered range query，用balanced tree；若只需equality lookup，用hash table；若relation是graph，用adjacency structure。


数据结构不是按“熟悉程度”选择，而是按domain density、operations、ordering、mutation、locality和resource budget选择。

## 3.5 Lookup tables replace logic

Repeated conditionals常可转table：

```ts
const rules = [
  { min: 0,   label: "standard",  discount: 0 },
  { min: 100, label: "preferred", discount: 10 },
  { min: 500, label: "premium",   discount: 15 },
];

const selected = [...rules].reverse().find(rule => amount >= rule.min);
```


Table-driven program（）带来：

- Rules可排序、validate、diff与test。
- New case通常是new row。
- Same table可驱动UI、validation和execution。
- Domain experts可能直接维护data。

代价是schema、ordering semantics与conflict resolution必须清楚。Two overlapping rules谁优先不能靠array order暗示而不记录。

## 3.6 Structuring Data：从names到relationships

Structuring Data的标准不断提高：

1. Meaningful variable names。
2. Arrays把indexed peers成组。
3. Records把one entity的heterogeneous fields绑定。
4. Pointers/references表达relationships。
5. Functions封装insert、search、delete等operations。
6. Modules隐藏representation。
7. Object-oriented classes发布abstraction并封装state/invariants。

### Parallel arrays的问题

`names[i]`、`scores[i]`、`active[i]`依靠index i维持entity relationship。Insert、delete或sort时漏改one array，就发生silent drift。


Record：

```ts
type Student = {
  name: string;
  score: number;
  active: boolean;
};
```

把related fields作为one value移动，使relationship structural而不是conventional。Column强调的不是“永远不要parallel arrays”；columnar analytics可能因cache/vectorization刻意采用structure-of-arrays，但它需要封装joint operations和length invariant。

## 3.7 Abstract Data Type与representation hiding

抽象数据类型（，ADT）让clients依赖：

```ts
interface SetADT<Key> {
  insert(key: Key): void;
  contains(key: Key): boolean;
  size(): number;
}
```

而非依赖sorted array indexes、hash buckets或tree nodes。


Representation change只要保持observable contract，不应修改clients。若client读取`set.buckets`或假设iteration order，abstraction已leak。

David Parnas的module principle可表述为：按likely-to-change design decisions切分modules，不只按execution steps切分。Data representation往往是应隐藏的decision。

## 3.8 Invariants follow relationships

每种structure都带proof obligations：

- Array：0 ≤ index &lt; length。
- Record：required fields present，field-level constraints。
- Sorted array：keys nondecreasing。
- Hash table：each key位于其hash bucket/probe chain，load factor在policy内。
- Tree：reachability、acyclic ownership、ordering或balance。
- Graph：edge endpoint valid，directed/undirected symmetry按contract。
- Parallel arrays：all lengths equal且same index same entity。

若invariant无法一句话写清，representation可能不适合，或abstraction boundary太大。


## 3.9 Cost belongs to structure and workload

Data structure选择不能只用Big-O headline。需计算：

$$
\text{total bytes}
=
\text{payload}
+\text{metadata}
+\text{unused capacity}
+\text{allocator overhead}
+\text{alignment}
$$


同样1000个8-byte values：

- Contiguous array接近8 KB，cache-friendly。
- Linked nodes可能每node另有two pointers、alignment与allocator metadata。
- Hash table需spare buckets维持load factor。

Workload matrix应列operations与frequency：

$$
C
=
\sum_{op} \operatorname{frequency}(op)\cdot\operatorname{cost}(op)
$$

Read-heavy immutable table、write-heavy cache、ordered range index和graph traversal需要不同structures。Benchmark要使用representative key distribution和size。

## 3.10 Powerful Tools for Specialized Data

Specialized Data Structures（）把更多programming effort移入成熟工具。


### Hypertext

Documents是nodes，cross-references是links；navigation、backlinks和search由system提供。若problem本质是connected knowledge，不应手写screens和jump tables。

### Spreadsheets

Cells形成grid，formulas形成dependency graph。Budget、forecast和tabular scenario可由data与formulas表示，automatic recomputation替代manual update code。

### Databases

Relations、keys、indexes、queries和transactions构成persistent shared data model。Filtering、joining、aggregation、concurrency和durability不应在每个application从零实现。

### UI properties

Visual control可由name-value properties表示：position、size、visibility、multiline、binding。Designer或runtime assignment改变data，generic UI engine完成render与event wiring。

这些tools不是免编程：schema、constraints、security、versioning和performance仍要设计。但它们把common operations变成tested primitives。

## 3.11 Glue languages and composition

Shell、Tcl、Visual Basic以及现代workflow tools常用于连接specialized objects。Glue program应保持thin：

- Parse and validate boundaries。
- Invoke tools through stable interfaces。
- Convert representations explicitly。
- Preserve errors and observability。
- Avoid reimplementing tool internals。

若80%的logic塞入stringly typed glue，应该升级为typed module或service；若只为join/filter写thousands lines，应该回到database query。

## 3.12 Failure modes


- Dense array用于huge sparse IDs导致allocation爆炸。
- Hash table被误用于required ordered output，后续依赖accidental order。
- Parallel arrays在delete后length或index drift。
- Template未escape untrusted value，产生injection。
- Generic table rules重叠却无priority。
- ADT暴露mutable internal references，client绕过checks。
- Spreadsheet cell references隐含business logic，无tests或version control。
- Database schema缺foreign keys，application code无法独自维持integrity。


## 3.13 Principles

Column 3的principles可以汇总为：

1. **Don't write a big program when a little one will do.**
2. Repetition often signals missing data structure。
3. Use arrays wheninteger index is the natural key。
4. Put changing facts inrecords and tables，stable logic in generic operations。
5. Preserve relationships structurally，not by naming conventions。
6. Hide representation behind ADT/module boundaries。
7. Choose structure from workload and measured costs。
8. Use specialized tools whose data model already matches the problem。
9. Treat invariants、schema and failure policy as part of representation。

## 3.14 Independent certificate


验收一个data-structure rewrite：

- **Equivalence**：Old and new versions produce same valid outputs。
- **Domain**：All indexes/keys validated。
- **Relationships**：Insert/delete/sort preserve entity links。
- **Operations**：ADT behavior independent of representation。
- **Cost**：Memory and operation frequency match budget。
- **Migration**：Serialized data version and rollback defined。
- **Mutations**：Bad index、duplicate key、parallel drift、stale cache、unknown field均被捕获。

## 3.15 逐步运行路线


## 小结

- Data Structures Programs用representation替代重复special-case control flow。
- A Survey Program把500个branches变成one indexed counter array。
- Form-Letter Programming分离template、name-value records与renderer。
- Array of Examples展示dense integer indexing在counts、lookup和dispatch中的普适性。
- Table-Driven Program让variations成为rows，generic interpreter保持稳定。
- Structuring Data从arrays推进到records、modules、ADT和encapsulated classes。
- Records保护field relationships；parallel arrays需要额外joint invariant。
- Abstract Data Type隐藏representation，使clients不受migration影响。
- Powerful Tools for Specialized Data提供hypertext、spreadsheet、database和UI property models。
- Structure cost由payload、metadata、capacity、locality和workload共同决定。
- 简短代码必须由明确domain、relationships、schema与certificate支撑。
