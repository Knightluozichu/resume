## 从“二十行代码为什么仍值得证明”开始

Binary search已有两千多年思想史，程序却直到电子计算时代仍频繁写错。困难不在“每次折半”这个口号，而在每个细节必须彼此一致：区间是closed还是half-open，`high`初值是`n - 1`还是`n`，循环条件是否含等号，更新是否越过`mid`，未找到返回什么，duplicates允许返回哪一个位置。

先预测：在`[1, 3, 5, 7]`中寻找7时，若代码使用closed interval，却把循环写成`low < high`，最后一个候选是否一定会被检查？再预测空数组、单元素失败、目标落在两元素之间时，同一程序会怎样结束。


Program Verification（）不是在代码写完后附加一篇数学作文。本栏的核心方法是：先写contract，再寻找能从precondition走向postcondition的invariant，最后让代码直接实现证明中的状态变化。

## 4.1 The Challenge of Binary Search

给定nondecreasing array $a[0\ldots n-1]$和target $t$，最朴素的exact-search contract是：

$$
\operatorname{sorted}(a)
\Longrightarrow
\begin{cases}
a[r]=t, & r\ge 0,\\
\forall i\in[0,n),\ a[i]\ne t, & r=-1.
\end{cases}
$$

Specification（）必须先回答四件事：

1. **Precondition**：array按nondecreasing order排序，`n`与storage一致。
2. **Success**：若返回nonnegative index $r$，则$r$在bounds内且$a[r]=t$。
3. **Failure**：返回`-1`当且仅当target不存在。
4. **Duplicates**：本版允许返回任意一个equal occurrence；first或last occurrence属于另一个contract。


若输入未排序，binary search不是“偶尔变慢”，而是推理前提失效。若caller需要insertion point，返回`-1`也不够；应改写postcondition并实现`lower_bound`。Correctness只对**声明过的contract**有意义。


## 4.2 Writing the Program

先选择closed candidate interval $[low,high]$。它表示：如果target存在，至少一个possible occurrence仍在这个区间中。

```cpp
#include <cstddef>
#include <span>

int binary_search_exact(std::span<const int> a, int target) {
    std::ptrdiff_t low = 0;
    std::ptrdiff_t high = static_cast<std::ptrdiff_t>(a.size()) - 1;

    while (low <= high) {
        const std::ptrdiff_t mid = low + (high - low) / 2;
        if (a[mid] < target) {
            low = mid + 1;
        } else if (a[mid] > target) {
            high = mid - 1;
        } else {
            return static_cast<int>(mid);
        }
    }
    return -1;
}
```

这段程序的每个符号都来自representation decision：

- `low = 0`与`high = n - 1`建立full closed interval。
- `low <= high`表示one remaining candidate仍须检查。
- `mid`位于active interval内。
- 若`a[mid]`较小，sortedness证明index不大于`mid`的位置都不可能命中，因此new `low`是`mid + 1`。
- 对称地，较大分支把`high`设为`mid - 1`。
- Equality直接满足success postcondition。
- 循环结束时`low > high`，candidate interval empty，满足absence postcondition。


### Midpoint不是纯代数问题

数学上：

$$
\frac{low+high}{2}=low+\frac{high-low}{2}.
$$

bounded integer machine上，`low + high`可能先overflow；右式只在valid bounds下计算nonnegative difference，风险更小。Signed overflow在C++中甚至是undefined behavior，不只是得到一个负数。


这也说明formal reasoning必须包含machine model。若证明假设unbounded integers，而implementation使用fixed-width signed integers，证明与程序之间仍有gap。

## 4.3 Understanding the Program：找出loop invariant

Loop Invariant（）不是泛泛的“数组有序”。本程序需要的核心命题是：

$$
I(low,high):
\bigl(\exists i\in[0,n),\ a[i]=t\bigr)
\Longrightarrow
\bigl(\exists j\in[low,high],\ a[j]=t\bigr).
$$

换句话说，如果target存在，active interval从未丢掉all occurrences。它允许duplicates，也不承诺保留first occurrence；这与“任一命中”的contract完全一致。


### Initialization

循环前`low = 0`、`high = n - 1`。Every valid array index都位于initial interval，因此target若存在，至少一个occurrence在其中。空数组时`high = -1`，loop不执行；absence postcondition直接成立。

### Maintenance

设invariant在iteration入口成立，且`mid`位于active interval。

- 若$a[mid] < t$，因array sorted，对所有$i\le mid$都有$a[i]\le a[mid] < t$。Discard $[low,mid]$不会丢掉target，故`low = mid + 1`保持invariant。
- 若$a[mid] > t$，对所有$i\ge mid$都有$a[i]\ge a[mid] > t$。Discard $[mid,high]$安全，故`high = mid - 1`保持invariant。
- 若$a[mid]=t$，返回`mid`，success postcondition成立。

### Termination

只证明invariant，得到的是Partial Correctness（）。还需证明loop会终止。

定义nonnegative loop variant：

$$
V=high-low+1.
$$

每个non-returning branch都排除`mid`，new interval size严格小于old size：

$$
0\le V_{k+1}<V_k.
$$

Nonnegative integer不可能无限strictly decrease，因此loop必然结束。Termination与partial correctness合并，得到Total Correctness（）。


## 4.4 Boundary choices必须形成一个整体

Closed interval方案不是唯一正确方案。Half-open interval $[low,high)$同样可证，但它需要`high = n`、loop condition `low < high`和不同的updates。错误通常来自把两套conventions各拿一半。


常见mutations及其证伪：

| Mutation | Minimal state | Failure |
|---|---|---|
| `high = n` with closed interval | empty或last boundary | 可能读取`a[n]` |
| `while (low < high)` | `low == high` | 最后一个candidate未检查 |
| `low = mid` | two candidates, target right | interval可能不缩小 |
| `high = mid` | two candidates, target left | interval可能不缩小 |
| return `low` on failure | target absent between values | 把insertion point误报为exact match |

Counterexample（）越小，越容易定位是哪条proof obligation断裂。


## 4.5 Duplicates改变的是specification

Exact search遇到equal `a[mid]`立即return，只保证某个occurrence。若需要first occurrence，success condition必须改成：

$$
a[r]=t\quad\land\quad(r=0\ \lor\ a[r-1]<t).
$$

对应实现不在equality时立即结束，而把right boundary继续左移：

```cpp
int first_occurrence(std::span<const int> a, int target) {
    std::ptrdiff_t low = 0;
    std::ptrdiff_t high = static_cast<std::ptrdiff_t>(a.size());
    while (low < high) {
        const std::ptrdiff_t mid = low + (high - low) / 2;
        if (a[mid] < target) low = mid + 1;
        else high = mid;
    }
    if (low == static_cast<std::ptrdiff_t>(a.size()) || a[low] != target) return -1;
    return static_cast<int>(low);
}
```

这里采用half-open interval，invariant更接近“answer若存在，则first valid position位于`[low, high]` boundary search space”。不要把这段的`high = mid`复制回前面的closed exact-search；相同语句在不同contract与interval representation中有不同意义。

## 4.6 Complexity从variant直接读出

每次iteration把candidate count至多减半。对$n > 0$：

$$
C(n)\le \lfloor\log_2 n\rfloor+1,
\qquad
T(n)=\Theta(\log n),
\qquad
S(n)=\Theta(1).
$$

Big-O不是correctness proof。一个non-terminating mutation不能因为“设计意图是logarithmic”而获得$O(\log n)$；先证明variant严格下降，才有资格计算iteration bound。

## 4.7 Principles

Column 4可提炼为一套可复用程序书写原则：

1. **Understand the problem before writing code.** 把valid input、success、failure和ambiguity写成contract。
2. **Choose a representation that makes the proof local.** Interval convention应让candidate meaning一句话可说清。
3. **Derive code from invariants.** Branch不是经验模板，而是由sortedness证明可discard的region。
4. **Prove progress separately from preservation.** Invariant负责不丢正确答案，variant负责一定结束。
5. **Keep specification and implementation at the same machine model.** Bounds、overflow、types和memory safety都属于正确性。
6. **Use counterexamples and tests to attack assumptions.** Proof、static analysis、tests与runtime checks覆盖不同failure classes。
7. **Treat changed semantics as a new problem.** Any occurrence、first occurrence、last occurrence与insertion point需要不同postconditions。

## 4.8 The Roles of Program Verification

Verification的价值不只是一张“已证明”证书。


### Design

寻找invariant会迫使作者先决定state representation。若很难说明active interval的含义，通常代码的bound convention也尚未统一。Proof activity在运行前就能排除整类off-by-one choices。

### Documentation

高价值comment应写“为什么discard这一侧安全”，而不是把`low = mid + 1`翻译成自然语言。Contract与invariant让reviewer不必模拟all executions，也让API callers知道sortedness和duplicate policy。

### Testing

证明揭示应测试的boundaries：empty、singleton success/failure、first、last、absent below/above/between、duplicates以及near-limit indexes。Mutation testing可故意删除`+1`、改loop relation或改initial high，确认suite能杀死这些bugs。

```ts
const cases = [
  { a: [],                 t: 4, want: -1 },
  { a: [4],                t: 4, want: 0 },
  { a: [4],                t: 3, want: -1 },
  { a: [1, 3, 5, 7],       t: 1, want: 0 },
  { a: [1, 3, 5, 7],       t: 7, want: 3 },
  { a: [1, 3, 5, 7],       t: 4, want: -1 },
  { a: [1, 3, 3, 3, 5],    t: 3, wantAny: [1, 2, 3] },
];
```

Property oracle可与linear search比较：若binary search返回$r\ge0$，检查bounds与equality；若返回`-1`，linear scan也必须找不到。不要让test重复implementation的同一错误逻辑。

### Maintenance

一次看似微小的semantic change，例如“返回任一duplicate”改为“返回first duplicate”，会改变invariant、equality branch和tests。Maintenance时应重新检查受影响proof chain，而不是只新增一个flag。

### Proof不会替代现实系统测试

证明只覆盖model中的assumptions。它通常不会自动证明caller传入memory有效、array在search期间未被concurrently mutated、comparator满足strict weak ordering、compiler与hardware无故障、resource limits合理。Tests、sanitizers、static analysis、fuzzing和production observability仍不可缺少。


## 4.9 Correctness certificate

一份可审计certificate应把claim绑定到exact code revision：

- **Contract**：sorted input、interval bounds、duplicate和failure semantics明确。
- **Initialization**：initial state建立invariant。
- **Maintenance**：每个branch使用sortedness并保持candidate claim。
- **Progress**：variant nonnegative且strictly decreases。
- **Termination**：empty interval或successful return导出postcondition。
- **Machine safety**：midpoint、index type、empty array与casts无overflow/out-of-bounds。
- **Counterexamples**：boundary suite与mutations覆盖各proof obligation。
- **Scope**：concurrency、memory validity和environment assumptions显式记录。


## 4.10 逐步运行路线


## 小结

- Binary search的难点是contract、interval convention、loop condition与updates必须一致。
- Specification先固定sortedness、success、failure和duplicate semantics。
- Closed interval invariant保证target若存在，至少一个occurrence仍在active interval。
- Initialization、maintenance和termination把global claim拆为local proof obligations。
- Loop variant $high-low+1$严格下降，补足partial correctness所缺的termination。
- Safe midpoint避免`low + high`在bounded integer arithmetic中的overflow。
- Any occurrence、first occurrence和insertion point是不同contracts，不能混用updates。
- Minimal counterexamples比large random examples更快暴露off-by-one与non-progress。
- Verification参与design、documentation、testing和maintenance，但不替代现实machine与integration tests。
- Correctness certificate必须绑定exact implementation、machine assumptions与boundary evidence。
