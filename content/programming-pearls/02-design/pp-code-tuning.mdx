## 直觉引入

想象你的车跑得不够快。换发动机（换算法）最根本但成本高。代码调优更像调校发动机——不换零件（不换算法），而是调整点火时间（缓存热点数据）、减轻车重（减少不必要操作）、优化进气（循环展开）。效果有限但成本低，适合在算法已最优时进一步榨取性能。

## 概念讲解

### 代码调优

<PpCodeTuningDiagram />

<Term def="代码调优是在不改变算法的前提下，通过微观优化提升性能的工程实践">
代码调优
</Term>

代码调优不改变复杂度，而是优化常数因子。常见技巧：1）缓存频繁计算的结果；2）循环展开减少分支开销；3）强度削减（加法替代乘法）；4）预处理常量；5）减少函数调用。关键是先profile找到瓶颈再针对性调优。

### 调优的代价

代价：可读性下降、维护成本上升、可移植性下降、可能引入bug。因此只在确实需要时调优，且调优前后必须benchmark验证。

## 交互Demo

<Stepper>
<Step title="缓存">缓存频繁计算的值避免重复计算。如循环长度缓存到局部变量。</Step>
<Step title="循环优化">循环展开减少分支判断，强度削减（加法替代乘法），不变操作移出循环。</Step>
<Step title="减少开销">内联小函数，用数组替代对象减少间接访问，位运算替代算术。</Step>
</Stepper>

## 代码对照

```java
// 1. 缓存
// 调优前
for (int i = 0; i < a.length; i++)
    sum += a[i] * expensiveCompute(i);
// 调优后
int n = a.length;  // 缓存长度
for (int i = 0; i < n; i++)
    sum += a[i] * cache[i];  // 预计算缓存

// 2. 循环展开
// 调优前
for (int i = 0; i < n; i++) a[i] = 0;
// 调优后（4路展开）
int limit = n - 3;
for (int i = 0; i < limit; i += 4) {
    a[i]=0; a[i+1]=0; a[i+2]=0; a[i+3]=0;
}
for (int i = limit; i < n; i++) a[i] = 0;

// 3. 强度削减：乘法→加法
// 调优前: a[i] = i * 4;
// 调优后
for (int i = 0, v = 0; i < n; i++, v += 4) a[i] = v;

// 4. 减少函数调用
// 调优前: for (int x : a) max = Math.max(max, x);
// 调优后
for (int x : a) if (x > max) max = x;
```

## 常见误区

<Callout type="trap">
**误区：不profile就盲目调优。**
90%运行时间花在10%代码上。不profile就调优可能浪费时间甚至让代码更慢。
</Callout>

<Callout type="trap">
**误区：调优后不benchmark。**
有些调优在现代CPU上可能无效甚至有害。必须benchmark验证确实提升。
</Callout>

<Exercises>
**问题 1**：代码调优和算法优化的区别？

<Answer>
算法优化改变复杂度（O(n^2)→O(n log n)），效果大成本高。代码调优不改变算法只优化常数因子，效果有限成本低。先算法优化再代码调优。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="代码调优">不改变算法的微观优化，优化常数因子。</GlossaryItem>
<GlossaryItem term="循环展开">减少循环次数，每次处理多个元素，减少分支开销。</GlossaryItem>
<GlossaryItem term="强度削减">用更快运算替代较慢运算（加法替代乘法）。</GlossaryItem>
<GlossaryItem term="profile">性能分析工具，定位热点代码。调优前必须先profile。</GlossaryItem>
</Glossary>
