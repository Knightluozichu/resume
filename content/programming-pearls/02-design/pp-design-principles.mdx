## 直觉引入

想象盖房子。你不能只关注砖头好不好（代码质量），还要看地基稳不稳（架构设计）、布局合理不合理（模块设计）。Bentley 的设计哲学：先保证正确（房子不倒），再追求简洁（布局合理），最后优化效率（材料节省）。顺序不能颠倒——倒着来会盖出又快又省但会塌的房子。

## 概念讲解

### 设计哲学

<PpDesignPrinciplesDiagram />

<Term def="Bentley的设计哲学是正确性优先、简洁性次之、效率第三，顺序不可颠倒">
设计哲学
</Term>

正确性优先：代码必须正确，所有优化在正确性面前都是次要的。简洁性次之：简洁代码更易理解和维护。效率第三：在正确和简洁的基础上优化，不过早优化。

### 问题分解层次

系统设计确定整体架构和数据流。模块设计定义接口和职责。代码设计选择数据结构和算法。每层都有设计决策，高层决策影响更大。

## 代码对照

```java
// 求最大子数组和的三种方案

// 方案1：暴力 O(n^3) — 正确但慢
int maxSubSum1(int[] a) {
    int max = 0;
    for (int i = 0; i < a.length; i++)
        for (int j = i; j < a.length; j++) {
            int sum = 0;
            for (int k = i; k <= j; k++) sum += a[k];
            max = Math.max(max, sum);
        }
    return max;
}

// 方案2：优化 O(n^2) — 复用前面的和
int maxSubSum2(int[] a) {
    int max = 0;
    for (int i = 0; i < a.length; i++) {
        int sum = 0;
        for (int j = i; j < a.length; j++) {
            sum += a[j];
            max = Math.max(max, sum);
        }
    }
    return max;
}

// 方案3：Kadane O(n) — 最优
int maxSubSum3(int[] a) {
    int max = 0, sum = 0;
    for (int x : a) {
        sum = Math.max(sum + x, 0);
        max = Math.max(max, sum);
    }
    return max;
}
```

## 常见误区

<Callout type="trap">
**误区：过早优化代码。**
Knuth: 过早优化是万恶之源。先用最简单正确方式实现，再profile找瓶颈，只优化热点。
</Callout>

<Callout type="trap">
**误区：追求clever trick而非清晰。**
聪明代码往往难维护。先写清晰代码，不够快再优化。简洁比聪明更重要。
</Callout>

**问题 1**：Bentley设计哲学三个优先级？为什么顺序不能颠倒？

<Answer>
正确性优先、简洁性次之、效率第三。不正确则无意义；不简洁则难维护验证；在正确简洁基础上优化才有意义。
