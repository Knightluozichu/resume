## 从“这段代码看起来能更快”开始

Code review中常见一句话：“把这里改成位运算/宏/手工展开，肯定更快。”Column 9要求把“肯定”拆成六份evidence：这真是hot spot吗？为什么贵？改法等价吗？Compiler已经做了吗？Representative input上更快吗？End-to-end值得增加complexity吗？

先预测：一个program有70%时间在allocator中，把allocator局部加速4倍，whole program会加速4倍、2倍，还是不到2.2倍？拖动hot fraction与local speedup，先看upper bound，再决定是否值得改。


Code Tuning（）不是性能工作的第一步。它适合已有correct program、higher design levels已合理、latency或cost确实重要，而且profile显示少数hot spots支配运行时间的场景。

若fraction $p$可加速$s$倍，overall speedup受Amdahl relation约束：

$$
S_{\mathrm{overall}}
=
\frac{1}{(1-p)+p/s}.
$$

当$p=0.7,s=4$时，overall约2.11倍。优化后hot spot占比下降，next bottleneck也会移动，所以每轮change后都要重新profile。

## 9.1 A Typical Story

Chris Van Wyk与Bentley讨论code tuning后，花几小时把一个3,000-line graphics program的runtime减半。Complex pictures原先可能处理10 minutes；第一步不是读所有code，而是对ten typical pictures做profile。

结果约70%时间落在general memory allocator `malloc`。Program通过one wrapper访问allocator，因此可先在wrapper加入accounting，不必修改allocator source。计数显示most popular record type分配约68,000次，runner-up约2,000次，skew超过30:1。


Van Wyk为common fixed-size record维护free linked list：

```cpp
Node* free_nodes = nullptr;

Node* allocate_node() {
    if (free_nodes != nullptr) {
        Node* result = free_nodes;
        free_nodes = free_nodes->next;
        return result;
    }
    return static_cast<Node*>(std::malloc(sizeof(Node)));
}

void release_node(Node* node) {
    node->next = free_nodes;
    free_nodes = node;
}
```

Common request由list pop/push完成，uncommon sizes仍走general allocator。总runtime降到原来的45%，allocator此时约占30%；fragmentation也改善。这个修改只增加约20 lines，没有改变user-visible behavior，也没有把whole allocator重写成special-purpose system。

Hot Spot（）不是“code看起来复杂”的地方，而是representative execution明确付费的地方。

这个story的可迁移路径：

1. **Profile representative work**：先定位cost。
2. **Instrument through an abstraction point**：在allocator wrapper计数。
3. **Exploit common case**：只为34:1的record type开fast path。
4. **Preserve fallback**：其他sizes仍correct。
5. **Measure end-to-end**：45%是whole-program result，不是microbenchmark。
6. **Re-profile**：确认bottleneck移动且memory没有恶化。


## 9.2 A First Aid Sampler

First Aid Sampler把four composite problems当作diagnosis exercise。每个solution都不是万能rule，而是“已知precondition + specific cost model + measurement”的组合。

### Integer Remainders：用代数恒等式降强度

Juggling rotation一类inner loop可能反复计算：

```cpp
i = (i + step) % n;
```

若invariant保证$0\le i\lt n$、$0\le step\lt n$，则$0\le i+step\lt2n$，最多subtract once：

```cpp
i += step;
if (i >= n) {
    i -= n;
}
```


Strength Reduction（）在某些machines给约2倍，在另一些machines没有差别。Modern compiler可能已识别constant modulus；branch misprediction也可能抵消division savings。Source transformation必须由disassembly或benchmark验证。

若`step`可能大于等于$n$，one subtraction不再等价；应保留`%`、先normalize step，或使用loop，但后两者也要重新计算cost。性能改动不能偷改input domain。

### Functions, Macros and Inline Code：文本替换不是函数

把tiny `max` function换为macro曾接近2倍，但手工inline没有进一步收益。这说明procedure-call overhead可能重要，也说明compiler与context决定结果。

危险在于classic C macro：

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))

float arrmax(int n) {
    if (n == 1) return x[0];
    return MAX(x[n - 1], arrmax(n - 1));
}
```

当recursive result赢得comparison时，`arrmax(n - 1)`会在condition和selected branch各执行一次。对adversarial ordering，recurrence接近：

$$
C(n)=2C(n-1)+O(1)=\Theta(2^n).
$$


原书报告：Function version对$n=10{,}000$只需few milliseconds；macro version在特定input下，$n=21$约6 seconds、$n=28$约12 seconds。数字依platform变化，但semantic hazard不变。Modern C++应优先`inline`/`constexpr` function，让arguments exactly once。


### Sequential Search：combine tests，再考虑unrolling

Straightforward loop每iteration检查bounds和value：

```cpp
for (std::size_t i = 0; i < n; ++i) {
    if (x[i] == target) return i;
}
return n;
```

Sentinel（）把two exit conditions合并：

```cpp
const T saved = x[n];
x[n] = target;
std::size_t i = 0;
while (x[i] != target) {
    ++i;
}
x[n] = saved;
return i;
```


原书在其environment中，sentinel约再快5%；Loop Unrolling追加约56% speedup。Unrolling可减少index updates和branches，增加instruction-level parallelism：

```cpp
while (x[i] != target &&
       x[i + 1] != target &&
       x[i + 2] != target &&
       x[i + 3] != target) {
    i += 4;
}
```


但现代compiler可能自动unroll/vectorize；manual version还引入tail handling、code size、instruction-cache pressure与out-of-bounds risk。Loop Transformations（code motion、combining tests、unrolling、fusion与branch removal）必须基于actual generated code与target workload。

Sentinel也有contract cost：需要one writable extra slot，multithreaded shared array上temporary mutation可能造成data race。若这些preconditions不成立，不能使用。

### Computing Spherical Distances：augment data and exploit monotonicity

Margaret Wright需要在5,000 points的globe set中，为20,000 query points寻找angular nearest neighbor。Naive all-pairs本身有$10^8$ pairs，每pair再用含约ten sine/cosine operations的formula，large maps需要hours。

Andrew Appel建议保留simple array，却为stored latitude/longitude预计算unit Cartesian coordinates：

$$
(x,y,z)
=
(\cos\phi\cos\lambda,\cos\phi\sin\lambda,\sin\phi).
$$

对同一sphere上的unit vectors $a,b$：

$$
\lVert a-b\rVert^2
=
2-2(a\cdot b).
$$

Angular distance在目标range内与dot product/chord distance单调对应，所以nearest ordering相同；inner loop只需multiplications/additions，甚至不必求square root。改动约dozens of lines，runtime由hours降到less than half a minute，而不必实现hundreds of lines的fancy spatial structure。


这里同时使用Data Structure Augmentation（预存$x,y,z$）与Algebraic Identity（用chord/dot ranking替代angle）。如果需要输出exact angular distance，只对winner最后计算one `acos`，不要对every candidate计算。

## 9.3 Major Surgery — Binary Search

Column 4的clean binary search已经是$O(\log n)$，看似没有fat。Column 9进一步要求：sorted array可能有duplicates，要返回target的first occurrence；fixed workload中$n=1000$。

先用fictitious boundary values建立lower-bound invariant：

$$
x[l]\lt t
\quad\land\quad
x[u]\ge t
\quad\land\quad
-1\le l\lt u\le n.
$$

```cpp
int first_equal(std::span<const int> x, int target) {
    int lower = -1;
    int upper = static_cast<int>(x.size());
    while (lower + 1 != upper) {
        const int middle = lower + (upper - lower) / 2;
        if (x[middle] < target) lower = middle;
        else upper = middle;
    }
    return upper < static_cast<int>(x.size()) && x[upper] == target
        ? upper
        : -1;
}
```

每iteration只比较one array element与target。Termination时$l+1=u$；若target存在，其first occurrence只能是$u$。


### Change the range representation

Major Surgery Binary Search（）把range表示为lower bound $l$与power-of-two increment $i$，使$l+i=u$。

因为1,000不是power of two，先取largest lower power $512$。Initial test让range成为`[-1, 511]`或`[488, 1000]`，随后$i$依次取256、128、64、32、16、8、4、2、1：

```cpp
int lower = -1;
if (x[511] < target) lower = 1000 - 512;

if (x[lower + 256] < target) lower += 256;
if (x[lower + 128] < target) lower += 128;
if (x[lower +  64] < target) lower +=  64;
if (x[lower +  32] < target) lower +=  32;
if (x[lower +  16] < target) lower +=  16;
if (x[lower +   8] < target) lower +=   8;
if (x[lower +   4] < target) lower +=   4;
if (x[lower +   2] < target) lower +=   2;
if (x[lower +   1] < target) lower +=   1;
```

Loop control、increment division与assignments全部消失。Correctness并非magic：在每个`if`前后都保持$x[l]\lt t$且$x[l+i]\ge t$，只把$i$减半。

### A benchmark that was too good

历史测量跨four machines、five languages和multiple optimization levels，runtime reduction从38%到factor 5不等。第二版current machine上，初次结果从350 ns降至125 ns，apparent reduction 64%。

这个结果是biased：Scaffolding按`x[0]`,`x[1]`顺序搜索，给memory access与branch prediction过于友好的pattern。把same targets随机化后：

$$
\text{reduction}
=
\frac{418-266}{418}
\approx
36\%.
$$


36%仍是real improvement，但claim、适用范围与维护成本完全不同。若production queries确实ordered，应把它写成workload fact并保留；否则randomized order更接近general claim。

Fixed-size unrolled code只适合extremely stable contract。Array size变化、duplicates policy、different comparator或compiler/hardware都可能让它失效。通常应优先standard library lower bound；只有profile证明这one function值得时，才保留specialized implementation与clean reference side by side。

## 9.4 Principles

### Tune rarely

Efficiency只是correctness、functionality、security、maintainability与delivery中的one property。Premature Optimization会在还不知道hot spot前制造complexity。只有performance matters且higher-level alternatives不够时才进入local tuning。

### Profiling and Measurement

Profiling and Measurement（）包含：

- Profile wall time、CPU、allocations、cache misses、I/O或tail latency，选择与problem一致的metric。
- 覆盖representative distributions，不只测happy path。
- Warm up runtime与data；固定compiler flags、frequency policy和machine state。
- 多次运行，报告median、spread与raw samples。
- One patch只改变one hypothesis，保留baseline。
- Compare outputs、side effects、numeric tolerance与resource limits。
- 先看end-to-end，再用microbenchmark解释。

### Check other design levels first

若algorithm仍是$O(n^2)$且input已增长100倍，loop unrolling不是答案。依次检查problem definition、system structure、algorithm/data structure、code tuning、system software和hardware。Local tuning适合small but dominant costs；large factor通常来自higher level。

### Speedups can be slowdowns

原书总结：

- `%`换`if`有时2倍，有时no difference。
- Function换macro有时约2倍，有时因multiple evaluation慢10,000倍。
- Sentinel在一个environment约5%，在另一个可能被compiler等价优化。
- Inline和unroll会放大code并伤害instruction cache。
- Cache若没有locality会增加time与space。

因此optimization不是source-code property，而是program、compiler、hardware与workload的joint result。

### Rules are hypotheses, not guarantees

Appendix 4把27条rules分为：

| Category | Representative ideas |
|---|---|
| Space-for-Time | augmentation、precomputed results、caching、lazy evaluation |
| Time-for-Space | packing、overlaying、interpreters |
| Loop Rules | code motion、combine tests、unroll、fusion、remove branches |
| Logic Rules | algebraic identities、short circuit、reorder tests、lookup tables |
| Procedure Rules | collapse hierarchy、common cases、recursion transformations |
| Expression Rules | compile-time initialization、strength reduction、common subexpressions、word parallelism |

每条rule只是生成experiment的prompt。Compiler、cache hierarchy、vector units与branch predictor会改变结果；correctness proof和measurement拥有final vote。

## 9.5 Tuning certificate


Retain一个tuning patch前，记录：

- **User goal**：要改善哪个latency/cost/SLO。
- **Profile**：Hot spot占比与representative inputs。
- **Cost model**：Expensive operation为何dominant。
- **Hypothesis**：One specific transformation预计改变什么。
- **Equivalence**：Preconditions、invariants、oracle与edge cases。
- **Measurement**：Baseline/variant、raw data、variance与environment。
- **End-to-end effect**：不是只写local nanoseconds。
- **Tradeoffs**：Code size、memory、accuracy、portability与maintenance。
- **Rollback**：何种regression自动恢复clean implementation。

## 9.6 逐步运行路线


## 小结

- Code Tuning只在higher design levels合理、performance matters且profile指向hot spot时使用。
- Van Wyk从约70% allocator cost与68,000:2,000 allocation skew推导common-record free list。
- 约20 lines修改使whole graphics program降到原runtime的45%，同时减少fragmentation。
- First Aid Sampler覆盖remainder strength reduction、function/macro、sentinel/unroll与spherical-distance augmentation。
- Algebraic replacement必须有range invariant；macro可能因multiple evaluation把linear recursion变成exponential。
- Sentinel用guard合并bounds与value tests，但要求writable extra slot和safe mutation。
- Loop Transformations交换branches、parallelism、code size与tail complexity，不能只看source lines。
- Spherical nearest neighbor用precomputed Cartesian coordinates和monotonic identity消除repeated trigonometry。
- Major Surgery Binary Search以lower-bound invariant、power-of-two increment与ten-level unrolling调优fixed 1,000-element case。
- Ordered benchmark造成64% apparent reduction；randomized representative queries将可信结果修正为36%。
- Profiling and Measurement、correctness proof、end-to-end effect与maintenance tradeoff共同决定是否保留patch。
