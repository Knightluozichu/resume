## 从“直接调用库函数”开始

如何把records排成order？Column 11的第一答案不是手写算法，而是use a library sort function。Library通常已经处理了types、comparators、adversarial cases、portability与多年调优。只有当existing sort难以接入、不能表达required order，或measurement证明它不满足constraint时，才进入本栏的手写路径。

先预测：面对10,000个almost-sorted records，应先写Quicksort、Insertion Sort，还是先测system library？改变data shape与constraint，观察first candidate如何变化。


Sorting（）的完整postcondition至少包含：

1. Ordered：相邻records不违反comparator。
2. Permutation：output与input拥有相同multiset，既不丢也不复制。
3. Stability若required：equal keys保持original relative order。
4. Resource envelope：time、extra memory与stack depth满足target workload。

只检查“看起来有序”会漏掉duplicate loss；只看big-O会漏掉comparator calls、cache、function-call overhead与bad recursion depth。

## 11.1 Insertion Sort

Insertion Sort（）像card player整理手牌。对array `x[n]`，开始时`x[0..0]`已排序；每轮把`x[i]`插入`x[0..i]`，于是boundary向右推进。

原书用四行状态表示过程：

```text
3 | 1 4 2
1 3 | 4 2
1 3 4 | 2
1 2 3 4 |
```


第一版最接近definition：

```cpp
void isort1(int x[], int n) {
    for (int i = 1; i < n; ++i) {
        // invariant: x[0..i-1] is sorted
        for (int j = i; j > 0 && x[j - 1] > x[j]; --j) {
            swap(x[j - 1], x[j]);
        }
    }
}
```

Correctness来自two-level invariant。Outer loop开始时prefix sorted；inner loop把new value越过所有larger predecessors，且不改变其他records的relative order。结束时`x[0..i]` sorted。Outer loop终止后整个array sorted。

原书接着做两次局部调优。`isort2`把inner-loop swap function展开；`isort3`发现被插入的`t`在每次swap中不变，于是保存一次、只右移larger records：

```cpp
void isort3(int x[], int n) {
    for (int i = 1; i < n; ++i) {
        int t = x[i];
        int j = i;
        while (j > 0 && x[j - 1] > t) {
            x[j] = x[j - 1];
            --j;
        }
        x[j] = t;
    }
}
```

若input有$I$个inversions，shift count与$I$同阶：

$$
T(n,I)=\Theta(n+I).
$$

Random permutation的expected inversions约$n(n-1)/4$，所以average与worst case均为$\Theta(n^2)$；almost-sorted data若$I=O(n)$，同一program近似linear。这正是11.3最后cleanup pass成立的原因。


原书400 MHz Pentium II上的models分别约为$11.9n^2$、$3.8n^2$、$3.2n^2$ nanoseconds。`isort3`排1,000 integers只需few milliseconds，10,000约one third second，但million integers接近one hour。Absolute times早已过时，仍有效的是：algorithmic quadratic wall不会被小常数消除；对small或nearly sorted input，simple tight loop却很有竞争力。


## 11.2 A Simple Quicksort

Simple Quicksort（）来自C. A. R. Hoare 1962年的Quicksort。原书从八个integers开始：

```text
55 41 59 26 53 58 97 93
```

以55为pivot完成partition后，可得到：

```text
41 26 53 | 55 | 59 58 97 93
```

只要独立sort左右两侧，whole array就sorted。一次linear partition为许多records建立了global relation；相比之下，Insertion Sort一次sift只让one more prefix element到位。

### Lomuto partition invariant

Partition（）采用Nico Lomuto的one-way scan。令pivot为`x[l]`，scan `i`从`l+1`到`u`，boundary `m`保持：

```text
x[l+1..m]   <  x[l]
x[m+1..i-1] >= x[l]
x[i..u]        unknown
```


完整的`qsort1`很短，但每一行都承担proof obligation：

```cpp
void qsort1(int x[], int l, int u) {
    if (l >= u) return;

    int m = l;
    for (int i = l + 1; i <= u; ++i) {
        if (x[i] < x[l]) {
            swap(x[++m], x[i]);
        }
    }

    swap(x[l], x[m]);
    // x[l..m-1] < x[m] <= x[m+1..u]
    qsort1(x, l, m - 1);
    qsort1(x, m + 1, u);
}
```

Final pivot swap不能省。若保留pivot在`x[l]`却递归`(l,m)`，pivot为strict maximum时subproblem不缩小，会infinite recursion。交换后pivot固定在final position `m`，two recursive ranges都strictly smaller，因此同时证明partial correctness与termination。

### Average and worst shape

若每层pivot都接近middle：

$$
T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n).
$$

若每层pivot都是minimum或maximum：

$$
T(n)=T(n-1)+\Theta(n)=\Theta(n^2),
$$

stack depth也从expected $O(\log n)$恶化为$O(n)$。`qsort1`总选first element，因此already sorted input直接触发worst shape；大量equal keys也会全部落在同一侧。


## 11.3 Better Quicksorts

Better Quicksorts（）不是一次神奇替换，而是四层可独立验证的改进。

### Improvement 1：sentinel Lomuto

原书Problem 2给出Bob Sedgewick的reverse scan。`x[l]`既是pivot也作sentinel，inner scan不再单独检查lower bound，loop结束时pivot已随最后一次swap进入boundary：

```cpp
void qsort2(int x[], int l, int u) {
    if (l >= u) return;
    int i = u + 1;
    int m = u + 1;
    do {
        do { --i; } while (x[i] < x[l]);
        swap(x[--m], x[i]);
    } while (i > l);
    qsort2(x, l, m - 1);
    qsort2(x, m + 1, u);
}
```

Sentinel optimization必须和its invariant一起移动；只删除bound check而没有guaranteed stopper会读出array。原书measurement从`qsort1`约$60n\log_2n$降到`qsort2`约$56n\log_2n$ nanoseconds，属于small constant improvement。

### Improvement 2：two-way partition

One-way scan遇到all-equal values会形成`0`与`n-1`的split。Two-way partition让`i`从left、`j`从right扫描，交换misplaced pair；equal values会被两边共同消费：

```cpp
void qsort3(int x[], int l, int u) {
    if (l >= u) return;
    int t = x[l];
    int i = l;
    int j = u + 1;

    for (;;) {
        do { ++i; } while (i <= u && x[i] < t);
        do { --j; } while (x[j] > t);
        if (i > j) break;
        swap(x[i], x[j]);
    }

    swap(x[l], x[j]);
    qsort3(x, l, j - 1);
    qsort3(x, j + 1, u);
}
```


Two-way code更快且驯服all-equal degeneration，但boundary details明显更delicate。Tests必须覆盖empty、one element、two equal、all equal、sorted、reverse sorted、pivot duplicate与alternating values。若duplicate concentration极高，原书Problem 11的fat pivot把array分成`less / equal / greater`三区，直接跳过equal middle region。

### Improvement 3：random pivot

所有前述versions若always choose first record，仍会被sorted input击中。进入partition前执行：

```cpp
swap(x[l], x[randint(l, u)]);
```

Random Pivot（）把expected bound建立在random-number call上，而不是建立在data distribution上。对任何fixed input，expected runtime为$\Theta(n\log n)$。`randint`必须覆盖closed range `[l,u]`且绝不out of bounds；偏差或overflow会破坏performance argument甚至memory safety。

对distinct keys，standard randomized analysis给出expected comparisons：

$$
\mathbb{E}[C_n]
=2(n+1)H_n-4n
\sim 2n\ln n.
$$


Randomization不是worst-case guarantee。若system要求deterministic latency，可以采用introspective fallback、Heapsort或显式depth limit；Column 14会给出worst-case $O(n\log n)$的Heapsort。

### Improvement 4：small subarrays and one cleanup pass

Quicksort在tiny ranges上支付recursion、random generator与partition setup。Sedgewick的做法是在range size小于Cutoff时直接return，不逐个用Insertion Sort处理每个range；整个Quicksort结束后，array由globally ordered small clumps组成，再运行one `isort3` cleanup。

Cutoff（）在原书system上near 50，但不是portable constant：

```cpp
void qsort4(int x[], int l, int u, int cutoff) {
    if (u - l < cutoff) return;

    swap(x[l], x[randint(l, u)]);
    int t = x[l];
    int i = l;
    int j = u + 1;

    for (;;) {
        do { ++i; } while (i <= u && x[i] < t);
        do { --j; } while (x[j] > t);
        if (i > j) break;
        int temp = x[i]; x[i] = x[j]; x[j] = temp;
    }
    swap(x[l], x[j]);
    qsort4(x, l, j - 1, cutoff);
    qsort4(x, j + 1, u, cutoff);
}

qsort4(x, 0, n - 1, measured_cutoff);
isort3(x, n);
```


`qsort4`还只inline inner-loop swap，因为other swaps不在hot loop，展开收益negligible。每个change都应单独benchmark，避免把randomization、partition scheme与compiler effects混成一个unexplained result。

### 原书benchmark ladder

原书对random integers报告如下models：

| Program | Lines of C | Nanoseconds |
|---|---:|---:|
| C library `qsort` | 3 | $137n\log_2n$ |
| Quicksort 1 | 9 | $60n\log_2n$ |
| Quicksort 2 | 9 | $56n\log_2n$ |
| Quicksort 3 | 14 | $44n\log_2n$ |
| Quicksort 4 + isort3 | 15 + 5 | $36n\log_2n$ |
| C++ library `sort` | 1 | $30n\log_2n$ |


在该machine上sort one million random integers约0.6 seconds for C++ `sort`到2.7 seconds for C `qsort`。C `qsort`的flexible interface对每次comparison做function call；C++ template `sort(x,x+n)`可inline comparator并且code最短。这里最重要的sorting principle是：home-made versions展示derivation与measurement，但fastest measured result仍来自library。


## 11.4 Principles

Sorting Principles（）可整理为六条。

### Use a library when it meets the contract

System library同时节省programmer time与maintenance risk。先写comparator、stability、memory与latency requirement，再建立library baseline。只有evidence显示gap，才维护custom sort。

### Match algorithm to scale and shape

Insertion Sort适合small/nearly sorted data；large general input需要$n\log n$ family。External files、small integer universe、stable records或expensive keys还可能指向merge、radix、key indexing或decorate-sort-undecorate，而不是本栏Quicksort。

### Derive code from invariants

`m`,`i`,`j`不是pointer choreography。它们代表已经classified regions。每次comparison/swap都必须preserve region predicate，并使unknown region shrinking。Final pivot placement同时建立postcondition与termination measure。

### Separate algorithm changes from code tuning

从$n^2$到$n\log n$是dominant speedup；inline swap、sentinel与cutoff是在正确algorithm之后取得constant factors。先profile与benchmark，再修改hot operation。

### Treat the comparator and stability as part of correctness

Comparator若不满足strict weak ordering，可让sort result undefined或inconsistent。Stability（）不是美学属性，而是multi-key pipelines常依赖的contract。


### Measure distributions, not one random array

Benchmark matrix至少覆盖sizes、random、sorted、reverse、organ-pipe、all-equal、few-unique、nearly sorted与real traces；记录median、tail、comparisons、moves、allocations与max stack。每个candidate必须先通过same correctness oracle。

## 11.5 Problems

原书Problems把本栏扩展为design space，而不是让读者只复写code：

- Minimum/maximum/mean无需full sort；median可用selection；mode则依赖domain与representation。Sorting可能被overused，也可能是canonicalization的恰当primitive。
- Experiment选择cutoff，应做parameter sweep、warmup、multiple seeds、multiple shapes与confidence interval，不应把one machine的50写成universal truth。
- Worst-case stack可通过“递归smaller partition、loop处理larger partition”限制为$O(\log n)$。
- Fat pivot适合duplicate-heavy data；Quickselect只递归包含rank `k`的一侧，expected linear time。
- Sort-selection guide还需考虑space、programmer time、generality、stability、input properties与Column 1的special integer constraints。


Production oracle可写成：

```cpp
bool valid_sort(const vector<Record>& before,
                const vector<Record>& after,
                Comparator less) {
    if (before.size() != after.size()) return false;
    for (size_t i = 1; i < after.size(); ++i) {
        if (less(after[i], after[i - 1])) return false;
    }
    return multiset_fingerprint(before) == multiset_fingerprint(after);
}
```

Fingerprint只适合fast test pass；release-critical tests应使用independent reference sort或exact multiset to avoid collision masking。

## 11.6 Further Reading

原书把Donald Knuth的*The Art of Computer Programming, Volume 3: Sorting and Searching*作为definitive detailed reference：mathematical analysis、important algorithms、variations与exercises。第二版于1998更新；MIX assembly显老，但implementation principles仍有效。

Robert Sedgewick的第三版*Algorithms*提供更modern treatment，Parts 1–4覆盖Fundamentals、Data Structures、Sorting与Searching，并分别有C、C++和Java editions。Further reading的目的不是收集更多algorithm names，而是学习如何把proof、machine model与industrial implementation放在一起。

## 小结

- Sorting首先是ordered permutation contract；stability、memory、stack与comparator同样属于correctness。
- Library sort是默认起点，custom code需要constraint或measurement证明。
- Insertion Sort维护sorted prefix，work与inversions相关；small或nearly sorted input上很有效。
- 原书三版Insertion Sort通过inline swap与shift saved value把constant model从$11.9n^2$降到$3.2n^2$ nanoseconds。
- Simple Quicksort用Lomuto partition维护lower/scanned/unknown regions，final pivot swap保证postcondition和termination。
- Balanced partitions给$\Theta(n\log n)$，extreme pivots给$\Theta(n^2)$与linear stack。
- Better Quicksorts依次采用sentinel、two-way partition、random pivot、cutoff、one final insertion pass与hot-loop inline swap。
- Random pivot保证任意fixed input上的expected $n\log n$，不提供deterministic worst-case guarantee。
- 原书benchmark中C++ library `sort`约$30n\log_2n$ nanoseconds，快于hand-made与C `qsort` candidates。
- Sorting principles要求先换algorithm，再调hot code，并用target distributions而非one friendly case测量。
- Adversarial suite至少覆盖sorted、reverse、all equal、few unique、nearly sorted与boundary sizes。
- Release certificate要同时证明ordered、permutation、stability requirement、stack bound与target performance。
