## 直觉引入

想象一个城市。你看到的街道、建筑、车辆，背后有一整套基础设施在运转：供水管网、电力系统、垃圾回收车队。你平时不会注意到它们，但一旦出了问题（停水、断电、垃圾堆积），整座城市就瘫痪了。

Python 的内部机制就是这座城市的「基础设施」：对象模型是建筑结构，内存管理是供水供电，字节码虚拟机是交通规则。你平时写 `a = 1` 时不会关心底层，但当遇到内存泄漏、性能瓶颈、神秘 bug 时，理解这些机制就是你的「工程师执照」。

## 概念讲解

### 一切皆对象

<PyaPythonInternalsDiagram />

<Term def="在 Python 中，所有数据（数字、字符串、函数、类、模块）都是对象，每个对象有唯一的身份（id）、类型（type）和值（value）">
一切皆对象
</Term>

Python 与 C/Java 的根本区别：在 Python 中，**类也是对象**，`int` 本身是一个类型对象，`def` 创建的函数也是一个 function 对象。这意味着你可以在运行时检查、传递、修改任何东西。

```python
# 函数是对象
def greet(): pass
print(type(greet))   # <class 'function'>

# 类也是对象
print(type(int))     # <class 'type'>
print(type(str))     # <class 'type'>

# type 自己也是对象，且是自己的类型
print(type(type))    # <class 'type'>
```

### 内存管理

<Stepper>
<Step title="引用计数（主要机制）">
每个对象维护一个引用计数器。`a = obj` 时计数 +1，`del a` 或变量离开作用域时 -1。计数归零时对象立即回收。优点：即时、确定性强。缺点：无法处理循环引用。
</Step>
<Step title="分代垃圾回收（辅助机制）">
解决循环引用问题。将对象分为三代（0/1/2），新对象在 0 代，存活越久越往老代移。GC 定期扫描各代，用可达性分析检测循环引用组并回收。可通过 `gc` 模块手动触发或调参。
</Step>
<Step title="内存池（pymalloc）">
CPython 维护私有内存池，小对象（≤512B）用 arena/pool/block 三级分配器管理，减少 malloc/free 系统调用开销。大对象直接走系统分配器。
</Step>
</Stepper>

### CPython 执行流程

Python 是解释型语言，但并非逐行解释。实际流程是：

1. **编译**：源代码 → AST → 字节码（`.pyc` 缓存）
2. **执行**：字节码由虚拟机（eval loop）逐条执行

`dis` 模块可以反汇编字节码，是理解性能和调试的利器：

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
#  2           0 LOAD_FAST                0 (a)
#              2 LOAD_FAST                1 (b)
#              4 BINARY_ADD
#              6 RETURN_VALUE
```

## 代码对照

```python
import sys, gc, dis

# 1. 引用计数观察
a = [1, 2, 3]
print(sys.getrefcount(a))  # 2（a 本身 + getrefcount 参数引用）

b = a
print(sys.getrefcount(a))  # 3（增加了 b 的引用）

del b
print(sys.getrefcount(a))  # 2

# 2. 循环引用：引用计数无法回收
class Node:
    def __init__(self):
        self.ref = None

n1 = Node()
n2 = Node()
n1.ref = n2  # n1 -> n2
n2.ref = n1  # n2 -> n1（循环引用）
del n1, n2   # 引用计数不为 0，但对象已不可达
gc.collect() # 分代 GC 回收循环引用

# 3. 内省工具
class MyClass:
    """示例类"""
    def method(self): pass

print(dir(MyClass))           # 列出所有属性
import inspect
print(inspect.getsource(MyClass.method))  # 获取源码
```

## 常见误区

<Callout type="trap">
**误区：认为 Python 有真正的私有属性。**
Python 的 `__var` 只是名称改写（name mangling），变成 `_ClassName__var`，并非真正的访问控制。`_var` 约定为「内部使用」但语言层面不阻止访问。设计 API 时应靠文档约定而非语法限制。
</Callout>

<Callout type="trap">
**误区：认为 del 语句会立即释放内存。**
`del a` 只减少引用计数。如果还有其他引用指向同一对象，对象不会被回收。即使引用计数归零、对象被回收，内存也未必归还操作系统——CPython 的内存池会缓存内存供后续分配复用。要观察真实内存释放需用 `tracemalloc`。
</Callout>

<Exercises>
**问题 1**：为什么 Python 需要分代垃圾回收？仅靠引用计数不够吗？

<Answer>
引用计数无法处理循环引用。当两个对象互相引用时（A.ref = B, B.ref = A），即使外部删除了对 A 和 B 的引用，两者的引用计数仍为 1（互相指向），永远不会归零，导致内存泄漏。分代 GC 通过可达性分析（从根对象出发遍历）检测不可达的循环引用组并回收它们。所以引用计数处理一般情况（即时回收），分代 GC 处理循环引用（定期扫描）。
</Answer>

**问题 2**：`type`、`object`、`int` 三者是什么关系？

<Answer>
`object` 是所有类的基类（顶层父类）。`type` 是所有类的元类（类型的类型）。`int` 是一个具体的类型对象。关系链：`int` 的类型是 `type`（`type(int) is type`），`int` 继承自 `object`（`int.__bases__ == (object,)`）。而 `type` 本身也是对象，它的类型是自身（`type(type) is type`），且继承自 `object`（`type.__bases__ == (object,)`）。这构成了 Python 对象模型的核心：`type` 创建类型，`object` 提供基础行为。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="引用计数">
每个对象维护一个计数器，记录被引用的次数。引用增加时 +1，减少时 -1，归零时立即回收。CPython 内存管理的主要机制。
</GlossaryItem>
<GlossaryItem term="分代垃圾回收">
将对象按存活时间分代（0/1/2），定期扫描回收不可达对象（特别是循环引用）的辅助 GC 机制。新对象在年轻代，存活越久越往老代移。
</GlossaryItem>
<GlossaryItem term="字节码">
CPython 将源码编译成的中间指令序列，存储在 .pyc 文件中，由虚拟机的 eval loop 逐条执行。可用 dis 模块反汇编查看。
</GlossaryItem>
<GlossaryItem term="内省">
程序在运行时检查自身结构的能力。Python 通过 type()、dir()、id()、inspect 模块等提供内省支持，是元编程和调试的基础。
</GlossaryItem>
</Glossary>
