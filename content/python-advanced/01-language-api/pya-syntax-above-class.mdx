## 原书骨架与现代迁移

官方章节围绕内置类型子类化、super与MRO、描述符与property、slots与对象布局、元编程展开。原书出版于Python 2.5与早期敏捷工具生态，本章保留它解释“为什么”的结构；命令和安全默认按当前Python、标准库与PyPA维护文档迁移，不把EasyInstall、distutils安装命令、旧CI或旧项目平台直接当成新项目默认。

<Term def="描述符把属性读取、写入和删除委托给类属性对象，property是常用封装；数据描述符、实例字典与非数据描述符有确定查找优先级。">描述符与property</Term>承接前两项，把局部语法或工具放回应用数据流。阅读时沿输入、协议、状态、输出和证据追踪，避免只背API名称。

```python
class Named:
    def __init_subclass__(cls, *, label, **kwargs):
        super().__init_subclass__(**kwargs)
        cls.label = label

class Job(Named, label="job"):
    pass
```

## 机制一：责任与数据流

直接继承list或dict时部分C级操作可能绕过重写方法；先确认需要的是名义子类型、协议实现还是组合包装，避免只为复用存储而继承。 super沿方法解析顺序继续协作调用，不等同于固定父类；多重继承中的每个实现要使用兼容签名并继续链条，才能保持菱形结构只执行一次。 先写出公共行为和失败类型，再选择语法或工具。这样即使实现从原书工具迁到当前生态，调用者仍能依据相同契约判断结果。

<Term def="slots声明固定属性槽并可减少实例字典开销，但会影响弱引用、继承和动态属性；只有测量大量实例后才应为内存使用它。">slots与对象布局</Term>提醒我们：抽象不能消除成本，只会改变成本出现的位置。包装、生成器、构建系统、CI或缓存都必须说明资源、顺序和异常传播。

```python
class Positive:
    def __set_name__(self, owner, name): self.name = name
    def __get__(self, obj, owner=None): return obj.__dict__[self.name]
    def __set__(self, obj, value):
        if value <= 0: raise ValueError("positive value required")
        obj.__dict__[self.name] = value
```

## 机制二：失败与边界

描述符把属性读取、写入和删除委托给类属性对象，property是常用封装；数据描述符、实例字典与非数据描述符有确定查找优先级。 slots声明固定属性槽并可减少实例字典开销，但会影响弱引用、继承和动态属性；只有测量大量实例后才应为内存使用它。 边界实验至少包含正常、空输入、上限附近、依赖失败和重复执行。涉及网络、并发或外部制品时，再加入超时、取消、部分完成与摘要校验。

历史工具不等于无价值。正确迁移是先提取声明式配置、隔离、持续反馈和可回滚发布等不变量，再用维护中的接口重写；错误做法是机械替换命令却保留隐式环境和不可追踪副作用。

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass
assert D.__mro__ == (D, B, C, A, object)
```

## 机制三：证据闭环

<Term def="原书通过new和metaclass展示类创建钩子；现代代码优先类装饰器或init_subclass，只有必须控制类对象创建时才引入元类。">元编程</Term>负责收束验收。原书通过new和metaclass展示类创建钩子；现代代码优先类装饰器或init_subclass，只有必须控制类对象创建时才引入元类。 保存解释器、依赖锁定、输入、命令、退出状态、关键输出和制品摘要，才能让另一台干净机器重放同一结论。

## 实战验收清单

1. 在隔离环境运行三段示例，记录解释器实现、版本和依赖来源。
2. 为核心行为增加正常、空输入、失败和重复执行测试，先看到失败再修改实现。
3. 清理缓存和临时文件后重跑，证明结果不依赖工作区残留。
4. 对历史命令写出当前替代路径，并说明保留的架构不变量与不再采用的安全默认。

## 迁移决策题

设想团队正在维护一个已经运行多年的Python服务：它仍依赖本章对应的历史工具，但业务不能停机。先不要直接重写。第一步列出内置类型子类化承担的真实输入和输出，再用super与MRO识别构建或运行时依赖；第二步把描述符与property放进隔离实验，证明当前行为与失败类型；第三步用slots与对象布局设计兼容层，让旧入口和新入口在同一组契约测试下运行；最后以元编程保存制品摘要、性能或行为差异与回滚条件。只有新路径在正常、边界和故障输入上都达到既定条件，才逐步切换流量或调用者。这样迁移的是可验证契约，而不是把一个旧命令盲目替换为一个新命令。
