## 直觉引入

想象一家餐厅只有一个服务员（单线程）。如果每次点菜都要等厨房做完才能接待下一桌，效率极低。但如果服务员点完单就去找下一桌（发起 IO 后不等待），厨房做好后通知服务员上菜（IO 完成回调），一个服务员就能同时服务很多桌。asyncio 就是这个服务员——事件循环是服务员，协程是桌上的订单，await 就是等厨房的时候先去忙别的。

## 概念讲解

### 事件循环

<PyaAsyncioDiagram />

<Term def="事件循环是 asyncio 的核心调度器，在单线程中轮询就绪的 IO 事件并恢复对应的协程">
事件循环
</Term>

事件循环维护一个就绪队列和定时器。它不断检查哪些 IO 操作完成了（用 epoll/kqueue/select），然后恢复等待这些 IO 的协程。协程在 await 处让出控制权，事件循环调度其他就绪协程。这是协作式并发——协程主动让出（await），而非被抢占。

### 协程与 Task

async def 定义协程函数，调用返回协程对象（不执行）。await 挂起协程等待 awaitable 完成。create_task 将协程包装为 Task 并立即调度。gather 并发运行多个 Task 并收集结果。

## 代码对照

```python
import asyncio

# 1. 基础协程
async def hello():
    await asyncio.sleep(1)
    return 'hello'

# 2. 并发请求
async def fetch_all(urls):
    tasks = [asyncio.create_task(fetch(u)) for u in urls]
    return await asyncio.gather(*tasks)

# 3. 超时控制
async def fetch_with_timeout(url, timeout=5):
    try:
        async with asyncio.timeout(timeout):
            return await fetch(url)
    except asyncio.TimeoutError:
        return None

# 4. 信号量限制并发
async def limited_fetch(urls, max_concurrent=10):
    sem = asyncio.Semaphore(max_concurrent)
    async def guarded(url):
        async with sem:
            return await fetch(url)
    return await asyncio.gather(*[guarded(u) for u in urls])
```

## 常见误区

<Callout type="trap">
**误区：以为 asyncio 能加速 CPU 密集型任务。**
asyncio 是 IO 并发，不是 CPU 并行。事件循环在单线程中运行，CPU 密集任务不 await 会阻塞整个事件循环。CPU 密集场景用 multiprocessing。
</Callout>

<Callout type="trap">
**误区：在协程中用 time.sleep() 代替 asyncio.sleep()。**
time.sleep() 是阻塞调用，会卡住整个事件循环。必须用 await asyncio.sleep() 让出控制权。
</Callout>

<Exercises>
**问题 1**：为什么说 asyncio 是协作式并发而非并行？

<Answer>
asyncio 在单线程中运行，协程在 await 处主动让出，同一时刻只有一个协程在执行。并行需要多核同时执行。
</Answer>

**问题 2**：用 gather 并发请求 10 个 URL，如果某个失败怎么办？

<Answer>
gather 默认在任一 Task 抛异常时取消所有 Task。用 return_exceptions=True 让异常作为结果返回，或在协程内部 try/except。
</Answer>
</Exercises>
