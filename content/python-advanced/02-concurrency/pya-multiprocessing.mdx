## 直觉引入

想象一个厨房。GIL 就像只有一把菜刀——所有厨师（线程）只能轮流用，同时只有一个人在切菜。你可以雇很多厨师（多线程），但切菜速度不会变快。multiprocessing 的做法是开多个厨房（进程），每个厨房有自己的菜刀，真正同时切菜。代价是厨房之间共享食材（内存）需要额外搬运（IPC）。

## 概念讲解

### GIL与多进程

<PyaMultiprocessingDiagram />

<Term def="GIL（全局解释器锁）保证同一时刻只有一个线程执行 Python 字节码，multiprocessing 通过创建独立进程绕过此限制">
GIL
</Term>

CPython 的 GIL 是实现层面的选择（简化引用计数线程安全），而非语言规范。它导致多线程无法并行执行 CPU 密集的 Python 代码。multiprocessing 创建独立进程，每个进程有自己的 GIL 和内存空间，真正并行。代价是进程创建和 IPC 的开销远大于线程。

### 进程池

Pool 管理一组工作进程，自动分配任务。pool.map(func, iterable) 并行映射，类似 map 但并行。pool.starmap 处理多参数。apply_async 异步提交单个任务。进程数通常设为 os.cpu_count()。

## 代码对照

```python
import multiprocessing as mp
import os

# 1. 基础多进程
if __name__ == '__main__':
    p = mp.Process(target=print, args=('hello',))
    p.start(); p.join()

# 2. 进程池：并行计算
def square(x): return x * x

if __name__ == '__main__':
    with mp.Pool(os.cpu_count()) as pool:
        results = pool.map(square, range(1000))

# 3. 进程间通信：Queue
def producer(q):
    for i in range(10): q.put(i)
    q.put(None)

if __name__ == '__main__':
    q = mp.Queue()
    p1 = mp.Process(target=producer, args=(q,))
    p1.start(); p1.join()

# 4. 共享内存
from multiprocessing import shared_memory
shm = shared_memory.SharedMemory(create=True, size=1000)
```

## 常见误区

<Callout type="trap">
**误区：多进程一定比多线程快。**
多进程有进程创建、内存复制、IPC 序列化的开销。轻量任务可能比单线程还慢。只有任务计算量大且可并行时才划算。
</Callout>

<Callout type="trap">
**误区：在 Jupyter 中直接运行多进程代码。**
multiprocessing 在 macOS 用 spawn 方式启动，需在 if __name__ == '__main__' 保护下运行。Jupyter 中经常导致挂起。
</Callout>

<Exercises>
**问题 1**：什么时候用 threading，什么时候用 multiprocessing？

<Answer>
IO 密集用 threading 或 asyncio——GIL 在 IO 等待时释放。CPU 密集用 multiprocessing——绕过 GIL 真正并行。
</Answer>

**问题 2**：进程池 map 和 apply_async 各适合什么场景？

<Answer>
map 适合相同函数应用到大量独立数据。apply_async 适合不同函数或少量任务，异步提交返回 AsyncResult。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="GIL">全局解释器锁，CPython 保证同一时刻只有一个线程执行字节码。是 multiprocessing 存在的根本原因。</GlossaryItem>
<GlossaryItem term="进程池">预创建一组工作进程，复用避免频繁创建销毁。Pool.map/apply_async 自动分配任务和收集结果。</GlossaryItem>
<GlossaryItem term="IPC">进程间通信，包括 Queue、Pipe、SharedMemory。因进程内存隔离，数据必须通过 IPC 传递。</GlossaryItem>
<GlossaryItem term="spawn">multiprocessing 启动方式，重新 import 模块创建子进程。Windows/macOS 默认。</GlossaryItem>
</Glossary>
