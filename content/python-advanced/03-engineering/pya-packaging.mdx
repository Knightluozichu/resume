## 直觉引入

想象你做了一道好菜（写了个好模块），但只在自己厨房能吃（只在本地能跑）。打包分发就是把菜做成预制菜放到超市（PyPI）——别人买回家按说明加热就能吃（pip install 即可用）。关键在于标准化：包结构、依赖声明、构建流程都要遵循约定，别人才用得起来。

## 概念讲解

### 项目结构

<PyaPackagingDiagram />

<Term def="pyproject.toml 是 Python 项目的标准配置文件，定义构建系统、项目元数据和工具配置">
pyproject.toml
</Term>

现代 Python 项目推荐 src 布局：src/mypackage/ 放源码，tests/ 放测试，pyproject.toml 放配置。src 布局强制安装后测试（避免直接 import 本地目录），更贴近用户真实体验。pyproject.toml 替代了 setup.py/setup.cfg，声明式配置更清晰。

### 构建与发布

python -m build 生成 sdist（.tar.gz 源码包）和 wheel（.whl 预编译包）。wheel 优先因为安装快。twine upload 上传到 PyPI。版本号用语义化版本：MAJOR.MINOR.PATCH。

## 交互Demo

<Stepper>

## 代码对照

```python
# pyproject.toml
[build-system]
requires = ["setuptools>=68.0", "wheel"]
build-backend = "setuptools.backends._legacy:_Backend"

[project]
name = "mypackage"
version = "1.2.3"
requires-python = ">=3.10"
dependencies = ["requests>=2.28", "click>=8.0"]

[project.optional-dependencies]
dev = ["pytest>=7.0", "ruff", "mypy"]

[project.scripts]
mycli = "mypackage.cli:main"

# 项目结构:
# myproject/
#   pyproject.toml
#   src/mypackage/__init__.py
#   tests/test_core.py

# 构建与发布:
# python -m build          # 生成 sdist + wheel
# twine check dist/*       # 检查包元数据
# twine upload dist/*      # 上传到 PyPI

# 语义化版本号:
# 1.0.0 -> 1.0.1 (bug修复)
# 1.0.0 -> 1.1.0 (新功能)
# 1.0.0 -> 2.0.0 (不兼容变更)
```

## 常见误区

<Callout type="trap">
**误区：把源码直接放在项目根目录而非 src/ 下。**
非 src 布局有导入陷阱：pytest 可能直接 import 本地源码而非安装版本，导致测试通过但安装后失败。
</Callout>

<Callout type="trap">
**误区：在 setup.py 中写复杂构建逻辑。**
现代 Python 打包推荐用 pyproject.toml 声明式配置。setup.py 只在需要自定义 C 扩展编译时才保留。
</Callout>

<Exercises>
**问题 1**：pyproject.toml 和 setup.py 的区别？

<Answer>
pyproject.toml 是声明式配置（TOML格式），清晰可读、工具无关。setup.py 是命令式（Python代码），灵活但易出错。现代工具都支持 pyproject.toml。
</Answer>

**问题 2**：语义化版本号怎么选？什么时候升 major？

<Answer>
PATCH：bug 修复。MINOR：新功能向后兼容。MAJOR：不兼容变更。0.x.x 阶段任何变更都允许不兼容。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="pyproject.toml">Python 项目标准配置文件（PEP 518/621），声明构建系统、项目元数据、依赖。</GlossaryItem>
<GlossaryItem term="wheel">Python 预编译包格式（.whl），安装时不需编译，速度快。</GlossaryItem>
<GlossaryItem term="PyPI">Python Package Index，Python 官方包仓库。twine upload 上传包。</GlossaryItem>
<GlossaryItem term="语义化版本">版本号 MAJOR.MINOR.PATCH。不兼容变更升 major，兼容新功能升 minor，修复升 patch。</GlossaryItem>
</Glossary>
