## 直觉引入

想象盖大楼不搭脚手架。你能盖，但很危险——没法检查高处质量，出了问题难以定位。测试就是代码的脚手架：它让你在修改时有安全网，在重构时有验证手段，在交付时有质量保证。没有测试的代码是黑盒，改一行不知道崩了哪里。有测试的代码是白盒，改一行立刻知道影响范围。

## 概念讲解

### pytest核心

<PyaTestingDiagram />

<Term def="pytest 是 Python 最流行的测试框架，支持 fixture 依赖注入、参数化测试、丰富的断言和插件生态">
pytest
</Term>

pytest 用 assert 语句断言（失败时自动显示详细对比），fixture 管理测试前置/后置（替代 setUp/tearDown），@pytest.mark.parametrize 实现数据驱动测试，conftest.py 共享 fixture。pytest 自动发现 test_ 开头的文件和函数。

### 测试金字塔

测试金字塔：底层大量单元测试（快、隔离、多），中层适量集成测试（验证模块协作），顶层少量端到端测试（验证完整流程）。倒金字塔（大量 E2E 少量单元）是反模式——慢、脆、难定位。

## 交互Demo

<Stepper>
<Step title="单元测试">测试单个函数/类，隔离所有外部依赖（用 mock 替换数据库、网络）。执行快（毫秒级），数量多。</Step>
<Step title="集成测试">测试模块间协作，如服务+数据库的真实交互。执行较慢（秒级），验证接口契约和数据流。</Step>
<Step title="端到端测试">测试完整业务流程。执行慢（分钟级），数量少，验证关键路径正确性。</Step>
</Stepper>

## 代码对照

```python
import pytest
from unittest.mock import Mock, patch

# 1. 基础测试
def test_add():
    assert add(1, 2) == 3
    assert add(-1, 1) == 0

# 2. fixture：依赖注入
@pytest.fixture
def db_session():
    session = create_session()
    yield session  # yield 前是 setup，后是 teardown
    session.close()

# 3. 参数化测试
@pytest.mark.parametrize('input,expected', [
    ([1, 2, 3], 6),
    ([], 0),
    ([-1, 1], 0),
])
def test_sum(input, expected):
    assert sum(input) == expected

# 4. mock 隔离外部依赖
def test_fetch_user():
    mock_api = Mock()
    mock_api.get_user.return_value = {'id': 1, 'name': 'Alice'}
    with patch('myapp.api_client', mock_api):
        user = get_user(1)
        assert user['name'] == 'Alice'

# 5. 异常测试
def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)
```

## 常见误区

<Callout type="trap">
**误区：测试覆盖率越高越好。**
100% 覆盖率不等于没有 bug。覆盖率只衡量代码被执行过，不衡量逻辑被正确验证。80% 的好测试远胜 100% 的烂测试。
</Callout>

<Callout type="trap">
**误区：为了测试而修改生产代码。**
测试应验证生产行为而非实现细节。如果重构（不改行为）导致测试失败，说明测试过度耦合实现。
</Callout>

<Exercises>
**问题 1**：什么是 TDD？红-绿-重构循环是什么？

<Answer>
TDD：先写测试（红——失败），再写最少代码使测试通过（绿），然后重构优化。循环保证每行代码都有测试覆盖。
</Answer>

**问题 2**：如何测试一个调用了外部 API 的函数？

<Answer>
用 mock 替换 API 调用，设置 return_value 为预设响应。测试函数逻辑不测试 API 本身。验证 mock 被正确调用。
</Answer>
</Exercises>
