## 为什么学习地图必须保留第三版20章

《Python Crash Course, Third Edition》不是“变量、函数、类、项目”八个概览主题。官方20章先用11章建立environment、data、control、abstraction、I/O与tests，再用Alien Invasion、data visualization和Learning Log三组项目分别训练实时状态、外部数据与多用户Web release。合并章节会丢掉Lists的两章差异、Dictionaries、User Input、三章游戏状态、三章数据来源和三章Django演进。

先预测：写Pygame continuous movement失败应回第7章while还是第9章class；API response shape漂移应回第10章exceptions还是第17章normalization；Django用户能编辑他人Entry应回第19章authorization而不是第20章CSS。地图的价值是给出最小回退点，不只是列目录。

### 阶段一：第1–4章，environment、values与lists

1. **Getting Started** 建立Python interpreter、VS Code、terminal、Hello World与Troubleshooting证据。
2. **Variables and Simple Data Types** 处理variable binding、strings、f-strings、removeprefix/removesuffix、numbers、constants与comments。
3. **Introducing Lists** 建立index、append/insert/pop/remove、sort/sorted/reverse/len与IndexError模型。
4. **Working with Lists** 处理for loop、range、comprehension、slice、copy、tuple和PEP 8。

<Term def="第1–4章建立的interpreter、binding、type、index、mutation、copy/alias与iteration模型。">value and collection foundation</Term>

阶段验收不是背method names，而是能解释name指向哪个object、mutation影响哪些aliases、slice产生何种copy、loop body在何种indentation执行，并用最小program复现environment问题。

```python
numbers = [1, 2, 3]
alias = numbers
copy = numbers[:]
alias.append(4)

assert numbers == [1, 2, 3, 4]
assert copy == [1, 2, 3]
assert alias is numbers and copy is not numbers
```

### 阶段二：第5–11章，program contracts与verification

5. **if Statements** 训练conditional tests、membership、branch order与list conditions。
6. **Dictionaries** 训练key-value CRUD、get、iteration views与nested shape。
7. **User Input and while Loops** 把raw input经过parse/validate进入state machine，并证明termination。
8. **Functions** 建立argument binding、return、list ownership、`*args`、`**kwargs`与module imports。
9. **Classes** 建立instance state、methods、inheritance、composition和dependency boundary。
10. **Files and Exceptions** 处理Path、read/write、specific exceptions、text analysis、JSON schema与refactoring。
11. **Testing Your Code** 用pytest、assert、regression tests与fixtures提供behavior evidence。

<Term def="由condition、state transition、function signature、class invariant、I/O failure和test oracle共同形成的程序行为边界。">program contract chain</Term>

这七章把“能执行语句”提升为“能说明输入、状态、输出与failure”。第12章开始的每个project都依赖这些contract：event loop是state machine，Sprite是class，settings/file/API是boundary，regression test保护修改。

```python
def normalize_record(raw: dict[str, object]) -> dict[str, object]:
    if "name" not in raw:
        raise ValueError("missing name")
    return {"name": str(raw["name"]).strip(), "active": bool(raw.get("active", True))}

def test_missing_name_is_rejected() -> None:
    with pytest.raises(ValueError, match="missing name"):
        normalize_record({})
```

### 阶段三：第12–14章，Alien Invasion realtime system

12. **A Ship That Fires Bullets** 建立Pygame event loop、Clock.tick、Settings、Ship continuous movement与Bullet Group lifecycle。
13. **Aliens!** 建立fleet rows、edge detection、groupcollide、ship hit、repopulate和game_active。
14. **Scoring** 建立Play restart transaction、speedup scale、score/high score、level和ship lives HUD。

<Term def="输入事件、逐帧更新、Sprite Groups、collision transition、render与restart共同维持的实时游戏状态闭环。">realtime state loop</Term>

三章不能压成“做一个游戏”。第12章证明单对象和bullet lifecycle，第13章引入集合关系与life state，第14章把difficulty、reward和cached HUD纳入一致性。遇到窗口冻结先查event drain，fleet跳跃查edge transition次数，score过期查HUD refresh。

```python
while running:
    check_events()
    if stats.game_active:
        ship.update()
        bullets.update()
        aliens.update()
        resolve_collisions()
    draw_frame()
    clock.tick(60)
```

### 阶段四：第15–17章，data generation、files与APIs

15. **Generating Data** 使用Matplotlib line/scatter、RandomWalk、Die distribution、Plotly与savefig/write_html。
16. **Downloading Data** 读取CSV headers/weather series和GeoJSON earthquake features，处理missing records与geospatial encoding。
17. **Working with APIs** 处理requests、status code、JSON response、rate limits、GitHub repositories、Hacker News和API tests。

<Term def="data经过generate/read/request、parse、schema validate、normalize、visual encode与artifact export的可审计链路。">data evidence pipeline</Term>

三章的差异在source boundary：generated data可控制seed，CSV/GeoJSON需验证文件schema，API还增加transport/status/rate-limit。它们共同要求图前验证、图后artifact evidence，不能用“看起来合理”替代count/range/shape守恒。

### 阶段五：第18–20章，Learning Log Web release

18. **Getting Started with Django** 从virtual environment、project/app到Topic/Entry models、migrations、admin、shell、URLs、views与template inheritance。
19. **User Accounts** 加入ModelForm、POST/CSRF、login/logout/register、login_required、owner ForeignKey和authorization。
20. **Styling and Deploying an App** 使用django-bootstrap5、responsive navigation/forms/cards，并通过Platform.sh、requirements、Gunicorn、production settings、YAML、migrate、collectstatic、logs和custom error pages完成release。

<Term def="Django model、migration、request、template、session、owner authorization、static与deployment gates组成的Web交付路径。">web release path</Term>

Web项目不能只验收首页。至少用anonymous、owner与other user三类identity跑register/login/create/edit/logout和direct-id security matrix，再在DEBUG=False下验证static、migration、Gunicorn与logs。

```bash
mkdir -p evidence/ch19
python manage.py test learning_logs.tests.test_authorization \
  | tee evidence/ch19/authorization.txt
python manage.py makemigrations --check \
  | tee evidence/ch19/migration-check.txt
```

## 两种合理路线与共同终点

**首次学习路线**按1–20顺序，避免project code成为无法解释的模板。**复习路线**可先选一个项目做diagnostic：若Pygame state失控回第5–9章，data schema失败回第6/10章，Django owner漏洞回第9/11/19章。无论路线，最终都要逐章填满五项evidence gate。

<Callout type="trap" title="把20章合并为8个主题更便于导航">
合并会删除Dictionaries、User Input、三章游戏状态、三种data source和Django的model/auth/deploy演进。导航可以分组，但正文入口必须逐章保留。
</Callout>

<Callout type="trap" title="项目能运行就说明前置章节已掌握">
happy path运行不证明alias、termination、error、authorization或deployment边界。每章要能解释failure、实现练习并留下对应证据。
</Callout>

## 本章回顾：20章是一条可回退、可验收的能力链

1. 第1–4章建立interpreter、values、collections与iteration。
2. 第5–11章建立control、function/class、I/O和test contracts。
3. 第12–14章完成Alien Invasion realtime state loop。
4. 第15–17章完成generated/file/API data evidence pipeline。
5. 第18–20章完成Django model、auth、style与production release。

<Exercises>

**问题 1：为什么官方20章不能被“基础、函数、类、游戏、数据、Web”六页替代？**

<Answer>分组可用于导航，但每章有独立contract：Lists分引入与working，Dictionaries和User Input不能消失；Alien Invasion分别建立ship/bullet、fleet/collision和score/restart；data分generated、file与API boundaries；Django分model/request、auth/owner和style/deploy。合并会让故障没有最小回退点，也无法逐章验收目录、练习和review。</Answer>

**问题 2：一个API图表为空，应沿哪些章节回退检查？**

<Answer>先在第17章区分transport、status、JSON、schema与valid empty，再检查normalization和rate limit；文件/exception处理回第10章，dictionary nested shape回第6章，visual encoding与artifact回第15章。修复producer后重新验证record count、sort、labels和export，而不是只让Plotly不报错。</Answer>

**问题 3：每章何时可以推进到下一章？**

<Answer>官方outline已覆盖，能独立解释state/failure，练习或mini-project已实现，review问题能在无提示下回答，并留下对应test/build/artifact evidence。项目章还需验证failure path：Pygame cleanup/collision、data schema/count、Django owner/security/release gates；页面阅读和100分报告本身不等于掌握。</Answer>

</Exercises>
