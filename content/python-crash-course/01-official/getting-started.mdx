## 为什么第一章先建立可观察的执行环境

初学者看到“程序没有运行”，常把写代码的软件、运行代码的软件和代码本身混为一谈。先分清“在哪里写、用什么跑、跑的是哪个文件、在哪里看结果”，之后每个错误才有明确检查点。

第三版以 Python 3.11 和 VS Code 为教学环境，本章的首个程序也可用较新的 Python 3 运行。目标不是依赖某个按钮，而是换一个启动入口仍能找到同一文件、得到同一结果。先预测：文件在编辑器能运行、终端却报错，代码本身是否一定有问题？

<Term def="由editor、terminal、Python executable、working directory和项目文件共同组成的可复现运行上下文。">programming environment</Term>

## 尚未安装：先分清三个需要准备的东西

<Term def="真正读取并执行源代码的Python可执行文件；命令名、VS Code选择项和虚拟环境最终都必须解析到它。">Python interpreter</Term> 是实际运行 `.py` 文件的软件；VS Code 是编辑器；Microsoft 的 Python 扩展把两者连接起来。**安装编辑器或扩展，不等于安装 Python。** 本章只用 Python 自带功能，不需要安装第三方包。

### 先准备 Python：按自己的系统走一条分支

若已有可用 Python，直接进入下节验证，不必为了“从零”重装。若 `py` / `python3` 找不到，先按下表完成安装，再关闭旧终端并打开新终端检查。下载只从 [Python 官方入口](https://www.python.org/downloads/)进入，选适合系统及处理器的稳定 Python 3，不选预览版。

| 系统 | 未安装时的官方路径 | 权限与安全边界 |
| --- | --- | --- |
| Windows | 按 [Windows 使用文档](https://docs.python.org/3/using/windows.html)从 python.org 或 Microsoft Store 安装 Python Install Manager，再按引导安装一个稳定 Python 3。新终端用 `py --version` 验证。旧版安装器与旧 `py` 启动器的界面可能不同，不照抄旧教程的勾选项。 | 优先当前用户可用的安装方式。若学校/公司禁用商店或安装，找管理员，不修改组织策略；也不要盲改命令别名或系统搜索路径。 |
| macOS | 从官网下载 macOS 安装包，按 [macOS 使用文档](https://docs.python.org/3/using/mac.html)运行安装器；若文档要求，完成随包提供的证书安装步骤。新终端用 `python3 --version`。 | 官方安装器需要管理员授权，没有权限就请管理员处理。不要删除或替换 Apple 管理的 `/usr/bin/python3`，它可能被开发工具使用。 |
| Linux | 先试 `python3 --version`；多数发行版已提供 Python。没有时，按 [Unix 使用文档](https://docs.python.org/3/using/unix.html)及**本发行版**软件管理说明安装 Python 3 软件包，再验证。 | 包名和命令随发行版不同，不把 Ubuntu 命令照搬到 Fedora。系统级安装可能需要管理员；不要覆盖 `/usr/bin/python3`，不要用 `sudo pip` 改系统环境。 |

例如，**仅在 Ubuntu 且已获得管理员授权时**，[Ubuntu 官方说明](https://documentation.ubuntu.com/ubuntu-for-developers/howto/python-setup/)推荐用 `sudo apt install python3-full` 获取包含标准库的运行环境；确认软件包清单后再同意安装，完成后重跑 `python3 --version`。这是操作系统的软件包管理，不是 `sudo pip`；其他发行版不要照搬。

“命令不存在”也可能是安装后旧终端尚未刷新，不等于一定缺软件。若命令打开商店、选错版本或提示权限错误，保留原提示，读相应官方排错页；不要反复卸载，也不要以管理员身份运行整套编辑器来掩盖文件权限问题。

### 再准备 VS Code 与 Python 扩展

从 [VS Code 官方下载页](https://code.visualstudio.com/download)选择对应系统和架构。Windows 可选无需管理员权限的 [User setup](https://code.visualstudio.com/docs/setup/windows)；macOS 按[官方安装说明](https://code.visualstudio.com/docs/setup/mac)打开下载的 `.dmg`，将应用拖入 Applications，遇到授权要求请管理员处理；Linux 按[官方安装说明](https://code.visualstudio.com/docs/setup/linux)选择发行版支持的包。被设备管理策略阻止时停止并求助，不绕过权限限制。

打开 VS Code 左侧 Extensions，搜索 `ms-python.python`，核对名称 **Python**、发布者 **Microsoft** 后安装并启用（[官方扩展页](https://marketplace.visualstudio.com/items?itemName=ms-python.python)）。本章不要求另装 Code Runner。已有 Python 的读者也要验证实际解释器，不能仅看扩展的安装状态。

## 选择解释器：版本号只是第一份证据

<Stepper>
  <Step title="选择操作系统并查看启动命令">
    先按上表判断本机应使用 `py` 还是 `python3`，预测版本输出，再在终端执行下方探针并记录路径。到本页“编程环境四层”实验点击“步进 trace”，观察“启动·PATH”由终端而非编辑器负责；实验不会替你安装软件。
  </Step>
  <Step title="确认命令映射到哪个 executable">
    Windows常用`py`，macOS/Linux常用`python3`；不要只相信命令名，要同时读取版本与`sys.executable`。
  </Step>
  <Step title="让 VS Code 与终端使用同一路径">
    编辑器状态栏选择的interpreter若和终端不同，依赖、版本和运行结果都可能分叉。
  </Step>
</Stepper>

下面只执行自己系统的两行，记录版本及实际可执行文件路径；它们不安装包、不修改配置。Windows 的安装管理器若提示尚无运行时，先完成安装引导，再重跑验证，不把下载提示当成成功输出。

```bash
# Windows PowerShell
py --version
py -c "import sys; print(sys.executable); print(sys.version)"

# macOS / Linux
python3 --version
python3 -c "import sys; print(sys.executable); print(sys.version)"
```

若终端显示多个Python version，不要先卸载任何版本。先记录每条命令对应的路径，再选定本书项目使用的一条。后续安装包也必须用同一解释器调用`-m pip`，否则容易出现“安装成功但import失败”。

### 让编辑器选中已验证的解释器

1. 在自己的用户目录中创建可写文件夹 `python-crash-course`，在 VS Code 选择 **File → Open Folder** 打开它。不要使用系统安装目录，也不要对来历不明的下载项目直接授予信任。
2. Windows/Linux 按 `Ctrl+Shift+P`，macOS 按 `Cmd+Shift+P`，执行 **Python: Select Interpreter**，选中上面 `sys.executable` 对应路径。列表没有时，用 **Enter interpreter path** 指定已验证的可执行文件；不要随便选择一个版本号相似的项目。
3. 关闭旧的集成终端，用 **Terminal → New Terminal** 新建一个。解释器选择会影响扩展的运行入口，但不保证电脑上每个终端的 `py` / `python3` 都随之改变。下节仍要比较两个入口的探针输出。

操作依据为 [VS Code Python 入门](https://code.visualstudio.com/docs/python/python-tutorial)及[环境选择说明](https://code.visualstudio.com/docs/python/environments)。本章先跑无依赖脚本；后续项目的隔离环境与包安装，仍要遵守“记录并使用同一解释器”的原则。

## Hello World Program：追踪文件到输出

在刚打开的文件夹中点 New File，命名为 `hello_world.py`，输入下面代码，再用 `Ctrl+S`（macOS 为 `Cmd+S`）保存。右下角语言模式应为 Python；文件必须真的以 `.py` 结尾，不能是隐藏扩展名后的 `hello_world.py.txt`。

<CodeTabs>
  <Tab label="源代码 hello_world.py">

```python
message = "Hello Python world!"
print(message)
```

  </Tab>
  <Tab label="终端运行 + 输出">

```bash
# macOS / Linux：终端已位于文件所在文件夹
python3 hello_world.py
# Windows PowerShell 则执行：py hello_world.py
# 预期输出：Hello Python world!
```

  </Tab>
</CodeTabs>

源代码与运行命令是同一份证据的两面：前者证明写了什么，后者证明实际执行了哪份文件。先用文件右上角 **Run Python File in Terminal** 运行，再在终端手动执行对应命令；不要把 Debug、Run Code 或交互窗口当成同一入口。预期均为一行 `Hello Python world!`，而不是把命令打进文件或 Python 的 `>>>` 提示符里。

  </Step>
  <Step title="比较编辑器运行与终端运行">

  </Step>
  <Step title="故意制造一个语法错误">

<Term def="终端解析并启动Python executable的命令；它还携带脚本路径、参数和当前working directory。">python command</Term> 指启动解释器的终端命令。先确认终端当前目录就是保存文件的文件夹；若另开了终端，下面的路径必须替换为自己的真实绝对目录，不能原样复制占位路径。

Windows PowerShell 示例（只运行这一组，`$LASTEXITCODE` 紧接 Python 命令读取）：

```powershell
Set-Location "C:\Users\你的用户名\python-crash-course"
py hello_world.py
$LASTEXITCODE
```

macOS / Linux 示例（`pwd` 应显示保存脚本的文件夹）：

```bash
cd "$HOME/python-crash-course"
pwd
python3 hello_world.py
echo $?
```

最后一行应为 `0`，前面的程序输出应为 `Hello Python world!`。若文件夹不在用户目录，改用实际路径并保留引号。若需要固定 `sys.executable` 的绝对路径，PowerShell 的带引号可执行路径前要加 `&`，如 `& "C:\实际路径\python.exe" hello_world.py`；macOS/Linux 则直接用 `"/实际路径/python3" hello_world.py`。这两个绝对路径只是写法示意，不是安装位置承诺。

运行不是“点一下按钮”，而是一次可验证协议：输入是解释器路径、源文件路径和环境；输出是exit code、stdout与stderr。成功时exit code为0并出现预期文本；失败时保留完整traceback，不能只截取最后一句。

<Term def="从保存源文件、选择解释器、解析语法到执行并写出stdout/stderr的连续因果链。">execution trace</Term>

## Troubleshooting：按层定位而不是反复重装

<Stepper>
  <Step title="选择一个可观察故障">
    先预测“找不到命令”和“打不开文件”哪一个发生得更早。回到上方实验，保持“注入故障”关闭，依次点 `command not found` 和 `can't open file`，观察落点从“启动·PATH”移到“读取文件”，再按下文方法排查本机对应层。
  </Step>
  <Step title="读取第一条失败证据">
    shell找不到命令是PATH/安装层，can't open file是路径层，SyntaxError是source层；不同层不能使用同一个修复动作。
  </Step>
  <Step title="做最小修复并重跑原命令">
    修复后必须用完全相同的输入复现成功，记录executable、working directory、exit code和stdout。
  </Step>
</Stepper>

### 1. syntax highlighting 不出现

先确认文件已保存为`.py`，VS Code右下角语言模式为Python，并已启用Python扩展。syntax highlighting只是编辑器识别文件的证据，不证明Python已经安装，也不证明当前代码可执行。

### 2. `command not found`

这条错误发生在解释器启动之前。检查官方安装是否完成、关闭并重开终端、尝试系统对应的`py`或`python3`。不要通过创建一个名字相同但目标未知的alias掩盖问题。

### 3. `can't open file`

解释器已经启动，但脚本路径不存在。检查working directory、拼写、大小写和扩展名。用当前目录列表证明文件位置，或直接传入绝对路径。

### 4. `SyntaxError`

解释器找到了文件，但无法解析语法。traceback会指出文件和行号，caret通常指向检测到异常的位置，而根因可能在前一个未闭合引号或括号。修复一个最小错误后立即重跑。

<Term def="根据错误发生在shell、path、parser还是runtime层，保留原始证据并验证最小修复的过程。">layered troubleshooting</Term>

下面探针脚本打印四项证据，证明编辑器和终端是否解析到同一解释器：

<CodeTabs>
  <Tab label="环境探针 environment_probe.py">

```python
# 保存为 environment_probe.py，证明编辑器和终端是否使用同一解释器。
from pathlib import Path
import sys

print(f"executable={sys.executable}")
print(f"version={sys.version.split()[0]}")
print(f"cwd={Path.cwd()}")
print(f"script={Path(__file__).resolve()}")
```

  </Tab>
  <Tab label="运行后输出示例">

```bash
$ python3 environment_probe.py
executable=/usr/local/bin/python3
version=3.11.5
cwd=/Users/reader/python-crash-course
script=/Users/reader/python-crash-course/environment_probe.py
# exit code: 0
```

  </Tab>
</CodeTabs>

两份输出对比：executable 与 script 必须一致，cwd 可不同但需能解释相对路径影响。

### 把一次成功运行整理成最小证据包

一条“在我机器上能跑”的口头结论无法帮助下一次排错。最小证据包至少包含四项：原始启动命令、`sys.executable`与完整版本、源文件绝对路径、进程的exit code和stdout/stderr。它们共同回答“用什么、从哪里、运行哪个文件、结果是什么”。如果只保留截图，命令参数、路径和错误文本往往无法检索；如果只保留源代码，又无法证明实际执行的是哪份文件。

环境证据还要区分稳定信息与临时信息。Python版本、解释器路径和项目根目录应在同一学习阶段保持稳定；working directory可以随启动入口变化，因此代码若依赖相对路径，必须明确它相对的是进程cwd而不是脚本所在目录。后续第10章会用`pathlib`显式处理文件路径，这里先养成打印cwd和script path的习惯，避免把路径错误误判为文件内容错误。

阅读traceback时从最后一行取得异常类型和消息，再向上找到第一个属于自己项目的文件与行号；第三方库内部帧提供调用背景，但初学阶段通常不是第一处修改点。`SyntaxError`的caret表示parser发现无法继续的位置，未必就是根因字符；运行期`NameError`、`TypeError`则表示语法已经通过，程序执行到具体表达式才失败。这个时间顺序能迅速缩小检查范围。

修复完成后不要换一条更容易成功的命令。应保留相同解释器、相同working directory和相同脚本路径重跑原输入，再比较错误前后的exit code与输出；只有这样才能把“同时发生的其他变化”排除出因果链。若编辑器运行成功但终端仍失败，分别打印两端的executable和cwd，先解释差异，再决定统一解释器还是调整启动目录。

这份证据包也是后续章节的共同底座：安装pytest、Pygame或Django时，需要证明包安装到了同一interpreter；运行项目测试时，需要知道测试发现从哪个目录开始；部署Django时，也要区分本地editor配置与生产进程环境。第一章建立的不是一次Hello World，而是一套可持续复现的运行协议。

### 卡住时怎样求助：先缩小，再脱敏

先按错误发生层查对应的 Python / VS Code 官方文档，用错误类型和关键句搜索，而不是直接上传整个项目。仍不清楚时，把代码缩成一个无第三方依赖的文件，只保留导致错误的几行；输入改为虚构数据，并用原启动方式确认仍出现同类错误。

向老师、设备管理员或 [Python 官方帮助入口](https://www.python.org/about/help/)指向的 Python Help 社区求助时，给出：系统与终端类型、Python 版本、**预期与实际结果**、最小代码、启动命令、相关完整错误栈、已尝试的单一修复。安装权限问题交给管理员；代码问题附可复制文本，别只发“不能运行”的截图。

发出前只保留必要证据：把用户名、个人目录或内网地址统一换成占位值，保留路径层级、空格和扩展名等诊断特征；删除密码、令牌、真实业务数据。不要发送 `.env`、全部环境变量、凭据文件或整个用户目录。公开文本中的路径占位符应标明“已脱敏”；在本地以等价虚构路径重测，确认没有把原故障一起删掉。若令牌已泄露，应撤销或轮换，而不只是遮住截图。

<Callout type="trap" title="VS Code 显示 Python 语法高亮，所以环境已经正确">
语法高亮只说明editor识别了文件类型。必须实际运行version probe，并比较VS Code与终端的`sys.executable`；否则两个入口可能使用不同Python或不同依赖集合。
</Callout>

<Callout type="trap" title="运行失败就重装 Python">
重装会改变更多状态，却不一定修复脚本路径或语法错误。先按command、path、parser、runtime分层，保存原始命令和完整stderr，再针对根因做最小变更。
</Callout>

<Callout type="trap" title="修复后换一条更容易成功的命令">
**现象 →** `python3 hello_world.py` 报错后，改用编辑器按钮跑通就认为问题解决。
**原因 →** 换命令改变了 interpreter、working directory 等输入变量，无法证明原故障已修；"同时发生的其他变化"混入因果链。
**修法 →** 保留相同解释器、相同 cwd、相同脚本路径重跑原命令，比较前后 exit code 与 stdout；只有原输入复现成功才算闭环。
</Callout>

## 本章回顾：留下可重复的第一份证据

- 编程环境由 editor、terminal、interpreter、program 四层组成，各层职责不混
- 启动命令可不同，但必须确认 Python version 与 executable 路径
- `hello_world.py` 经保存→启动→读取→解析→执行，stdout 是最后证据
- 排错先辨失败层（shell/path/parser/runtime），再最小修复并用原命令回归
- 能从终端独立运行脚本并留下证据包，而非只依赖编辑器按钮

**问题 1：从 `py` / `python3` 不可用开始，完成启动与求助检查表，并独立实现 `environment_probe()`。怎样证明两个入口一致？**

先选自己的系统，逐项留下证据，不必也不应为了做题安装三套系统。探针函数无输入，返回 `executable`、`version`、`cwd`、`script` 四项字典；被导入时不应打印。

<Answer>

- [ ] 已从官方文档确定安装方式和权限；已有可用解释器就跳过重装，受限设备已咨询管理员。
- [ ] 新终端能输出版本与 `sys.executable`；VS Code 已启用 Microsoft Python 扩展并选择此解释器。
- [ ] 已在可写目录保存 `hello_world.py`，扩展名/语言模式正确；按钮与终端都输出预期一行，终端退出码为 0。
- [ ] 两入口运行探针，`executable` 和 `script` 一致；`cwd` 即使不同，也能说明相对路径会指向哪里。不一致就改解释器选择或启动路径，再重跑原入口。
- [ ] 若仍失败，已查官方排错说明并准备最小复现，附预期/实际、版本、命令、相关完整错误；用户名路径已一致脱敏，无令牌或私人数据，虚构输入仍可复现。

用 `sys` 与 `pathlib.Path` 收集四项，组装成字典返回；脚本被导入时不自动打印，只在直接运行时输出：

```python
from pathlib import Path
import sys

def environment_probe() -> dict:
    return {
        "executable": sys.executable,
        "version": sys.version.split()[0],
        "cwd": str(Path.cwd()),
        "script": str(Path(__file__).resolve()),
    }

if __name__ == "__main__":
    for k, v in environment_probe().items():
        print(f"{k}={v}")
```

关键：函数返回结构化证据而非直接 print，便于测试断言；`__name__` 守卫让脚本可被导入而不副作用。
</Answer>
