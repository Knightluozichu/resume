## 直觉引入

你往笔记本上写东西，写完要合上本子——不然风一吹纸就飞了。文件操作也是一样：打开文件、读写内容、关闭文件。忘记关闭文件会导致数据丢失或资源泄漏。Python 的 `with` 语句就像自动合上的笔记本——用完自动关闭，即使中间出错也不漏。

异常处理就像开车系安全带。正常行驶时安全带不影响你，但出事故时它保护你。`try-except` 结构让程序在出错时优雅处理——而不是直接崩溃。你不可能预见所有错误，但可以在关键位置做好防护。

## 概念讲解

### 文件读写

<Term def="文件操作三步：open() 打开文件获取文件对象，read()/write() 读写内容，close() 关闭文件。with 语句自动管理关闭。">

```python
# 传统方式（需要手动关闭）
f = open("data.txt", "r")    # 打开文件
content = f.read()           # 读取全部内容
f.close()                    # 必须关闭！

# with 语句（推荐——自动关闭）
with open("data.txt", "r") as f:
    content = f.read()       # 读取全部
    # 离开 with 块时自动 close()

# 逐行读取（适合大文件）
with open("data.txt", "r") as f:
    for line in f:           # 逐行迭代
        print(line.strip())  # strip() 去除换行符

# 写入文件
with open("output.txt", "w") as f:   # "w" 覆盖写
    f.write("Hello, World!\n")

with open("output.txt", "a") as f:   # "a" 追加写
    f.write("Another line\n")
```

文件模式：`r` 只读（默认）、`w` 覆盖写、`a` 追加写、`r+` 读写。加 `b` 表示二进制模式（如 `rb` 读图片）。

</Term>

### 异常处理

<Term def="try-except-else-finally 是 Python 异常处理结构：try 放可能出错的代码，except 捕获异常，else 在无异常时执行，finally 无论是否异常都执行。">

```python
try:
    number = int(input("输入数字: "))
    result = 10 / number
except ValueError:
    print("输入不是有效数字！")
except ZeroDivisionError:
    print("不能除以零！")
except Exception as e:       # 捕获其他所有异常
    print(f"未知错误: {e}")
else:
    print(f"结果: {result}")  # 无异常时执行
finally:
    print("程序结束")          # 无论是否异常都执行
```

异常捕获顺序：从具体到一般。先 `except ValueError`，再 `except ZeroDivisionError`，最后 `except Exception`。如果先捕获 `Exception`，后面的具体异常永远不会执行。

</Term>

### JSON 序列化

```python
import json

# 写入 JSON
data = {"name": "Alice", "scores": [90, 85, 88]}
with open("data.json", "w") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

# 读取 JSON
with open("data.json", "r") as f:
    loaded = json.load(f)
    print(loaded["name"])    # Alice
```

### 自定义异常

```python
class InvalidScoreError(Exception):
    """自定义异常：无效分数"""
    def __init__(self, score, message="分数必须在 0-100 之间"):
        self.score = score
        self.message = message
        super().__init__(self.message)

def set_score(score):
    if not 0 <= score <= 100:
        raise InvalidScoreError(score)  # 抛出自定义异常
    return score

try:
    set_score(150)
except InvalidScoreError as e:
    print(f"错误: {e} (输入值: {e.score})")
```

<Step title="第一步：用 with 安全操作文件">

with 语句在进入时调用文件的 `__enter__`，在离开时（无论正常退出还是异常）调用 `__exit__`（即 close()）。这保证了文件一定会被关闭，即使 read/write 过程中抛出异常。with 是上下文管理器协议的语法糖——推荐所有文件操作都用 with。

</Step>

<Step title="第二步：结构化异常处理">

try 块放可能出错的代码。except 按从具体到一般的顺序捕获异常——先捕获 ValueError，再捕获 Exception。else 在 try 无异常时执行（适合放依赖 try 成功的后续逻辑）。finally 无论是否异常都执行（适合放清理逻辑，如关闭连接）。

</Step>

<Step title="第三步：JSON 持久化">

json.dump() 将 Python 对象（字典、列表等）序列化为 JSON 文本写入文件。json.load() 反向读取。注意 ensure_ascii=False 参数让中文字符正常写入。JSON 只支持基本类型（str/int/float/bool/list/dict/None），自定义类需要手动转换。

</Step>

</Stepper>

## 代码对照

```python
# 综合示例：学生成绩管理系统（文件 + 异常）

import json

class ScoreManager:
    def __init__(self, filename="scores.json"):
        self.filename = filename
        self.scores = {}
        self._load()

    def _load(self):
        """从文件加载成绩"""
        try:
            with open(self.filename, "r") as f:
                self.scores = json.load(f)
        except FileNotFoundError:
            # 文件不存在时初始化空字典
            self.scores = {}
        except json.JSONDecodeError as e:
            # JSON 格式错误
            print(f"数据文件损坏: {e}")
            self.scores = {}

    def _save(self):
        """保存成绩到文件"""
        with open(self.filename, "w") as f:
            json.dump(self.scores, f,
                      ensure_ascii=False, indent=2)

    def add(self, name, score):
        """添加成绩（带验证）"""
        if not isinstance(score, (int, float)):
            raise TypeError("分数必须是数字")
        if not 0 <= score <= 100:
            raise ValueError(f"无效分数: {score}")
        self.scores[name] = score
        self._save()  # 每次修改后自动保存

    def average(self):
        """计算平均分"""
        if not self.scores:
            return 0
        return sum(self.scores.values()) / len(self.scores)

# 使用
try:
    manager = ScoreManager()
    manager.add("Alice", 90)
    manager.add("Bob", 85)
    print(f"平均分: {manager.average():.1f}")
except (TypeError, ValueError) as e:
    print(f"输入错误: {e}")
except Exception as e:
    print(f"系统错误: {e}")
finally:
    print("操作完成")
```

## 常见误区

<Callout type="trap">

**误区：裸 except 捕获所有异常**

`except:` 会捕获所有异常，包括 KeyboardInterrupt（Ctrl+C）和 SystemExit——这会让程序无法正常中断。应该用 `except Exception:` 或捕获具体异常类型。裸 except 还会隐藏真正的 bug，让调试变得困难。

</Callout>

<Callout type="trap">

**误区：open 后忘记 close**

`f = open("file.txt"); content = f.read()` 如果后续代码抛出异常，`f.close()` 不会执行，文件可能损坏或资源泄漏。用 with 语句可以彻底避免这个问题——离开 with 块时自动关闭，即使出错也不漏。

</Callout>

<Exercises>

**问题 1**：以下代码有什么问题？如何修复？

```python
f = open("data.txt", "r")
content = f.read()
result = process(content)  # 可能抛出异常
f.close()
```

<Answer>

问题：如果 `process(content)` 抛出异常，`f.close()` 不会执行，文件不会被关闭，可能导致资源泄漏或数据丢失。

修复方法——使用 with 语句：

```python
with open("data.txt", "r") as f:
    content = f.read()
    result = process(content)  # 即使异常，with 也会自动关闭文件
```

with 语句在离开代码块时（无论是正常退出还是异常退出）自动调用 `f.close()`。这是 Python 管理资源的推荐方式。

</Answer>

**问题 2**：解释 try-except-else-finally 中各块的作用和执行顺序。

<Answer>

- **try**：放可能抛出异常的代码
- **except**：捕获并处理特定异常。可以有多个 except，从具体到一般匹配
- **else**：try 块没有抛出任何异常时执行。适合放依赖 try 成功的后续逻辑——把更多代码放进 else 而非 try，可以避免意外捕获不该捕获的异常
- **finally**：无论是否抛出异常都会执行。适合放清理逻辑（关闭文件、释放锁、关闭连接）

执行顺序：
- 无异常：try → else → finally
- 有异常被捕获：try（异常处中断）→ except → finally
- 有异常未捕获：try（异常处中断）→ finally → 异常继续向上传播

finally 总是最后执行，即使 try/except 中有 return 语句，finally 也会在 return 之前执行。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="with 语句">

上下文管理器的语法糖。进入 with 块时调用 `__enter__`，离开时（无论正常退出还是异常）调用 `__exit__`。文件操作中 `__exit__` 自动调用 close()，保证资源释放。

</GlossaryItem>

<GlossaryItem term="try-except-else-finally">

异常处理结构。try 放可能出错的代码，except 捕获特定异常，else 在无异常时执行，finally 无论是否异常都执行。except 从具体到一般捕获，避免裸 except。

</GlossaryItem>

<GlossaryItem term="JSON 序列化">

json.dump() 将 Python 对象转为 JSON 文本写入文件，json.load() 反向读取。支持 str/int/float/bool/list/dict/None。ensure_ascii=False 让中文正常写入。

</GlossaryItem>

<GlossaryItem term="自定义异常">

继承 Exception 类创建自定义异常，可以携带额外信息。`raise CustomError(data)` 抛出，`except CustomError as e` 捕获后通过 `e.data` 访问附加信息。自定义异常让错误处理更有语义。

</GlossaryItem>
