## 直觉引入

你做了一把椅子。怎么确认它能坐人？你可以直接坐上去试试——但如果它在你朋友坐的时候断了呢？更好的方法是定义测试标准：能承受 100 公斤、四条腿平稳、高度 45 厘米。每次改设计后都跑一遍这些标准——这就是测试。

测试代码就是给程序写"验收标准"。你写了一个函数 `add(a, b)`，怎么确认它返回正确结果？`assert add(2, 3) == 5`。以后修改 add 函数时，运行测试就能立刻知道是否引入了 bug。没有测试的代码像没系安全带的飙车——能跑但出事就是大事。

## 概念讲解

### 测试函数命名约定

<Term def="测试函数必须以 test_ 开头，测试框架自动发现并运行。函数名描述被测行为，如 test_add_positive_numbers。">

```python
# 被测函数
def add(a, b):
    return a + b

# 测试函数
def test_add_positive_numbers():
    """测试两个正数相加"""
    result = add(2, 3)
    assert result == 5

def test_add_negative_numbers():
    """测试负数相加"""
    result = add(-1, -1)
    assert result == -2
```

</Term>

### unittest 框架

```python
import unittest

class TestStringMethods(unittest.TestCase):

    def test_upper(self):
        self.assertEqual("hello".upper(), "HELLO")

    def test_isupper(self):
        self.assertTrue("HELLO".isupper())
        self.assertFalse("Hello".isupper())

    def test_split(self):
        s = "hello world"
        self.assertEqual(s.split(), ["hello", "world"])
        # 验证异常
        with self.assertRaises(TypeError):
            s.split(2)  # split 不接受整数参数

# 运行测试
if __name__ == "__main__":
    unittest.main()
```

常用断言方法：
- `assertEqual(a, b)` — a == b
- `assertNotEqual(a, b)` — a != b
- `assertTrue(x)` / `assertFalse(x)`
- `assertIn(item, container)` — item in container
- `assertRaises(Exception)` — 期望抛出异常
- `assertAlmostEqual(a, b)` — 浮点数近似相等

### pytest 风格

pytest 更简洁，不需要继承 TestCase：

```python
# pytest 风格（更简洁）
def test_add():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0

# 参数化测试
import pytest

@pytest.mark.parametrize("a, b, expected", [
    (1, 2, 3),
    (-1, 1, 0),
    (0, 0, 0),
    (100, 200, 300),
])
def test_add_many(a, b, expected):
    assert add(a, b) == expected

# 测试异常
def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(10, 0)
```

### setUp 与 tearDown

```python
class TestDatabase(unittest.TestCase):
    def setUp(self):        # 每个测试前执行
        self.db = create_test_db()

    def tearDown(self):     # 每个测试后执行
        self.db.close()

    def test_insert(self):
        self.db.insert("Alice")
        self.assertEqual(self.db.count(), 1)
```

### 测试覆盖率

覆盖率衡量测试执行了被测代码的多少行：

```bash
# 安装 pytest-cov
pip install pytest-cov

# 运行并生成覆盖率报告
pytest --cov=myapp --cov-report=term-missing

# 输出示例：
# Name           Stmts   Miss  Cover   Missing
# myapp/utils.py    20      3    85%   15, 22-23
```

<Step title="第一步：编写测试函数">

测试函数以 `test_` 开头，让框架自动发现。函数名描述被测行为。函数体执行被测代码，用 assert 验证结果。一个好的测试只测一个行为——如果测试失败，立刻知道是哪个功能出了问题。

</Step>

<Step title="第二步：运行测试与修复">

运行 `pytest` 或 `python -m unittest` 执行所有测试。测试失败时，框架显示失败的测试名、期望值和实际值。根据失败信息定位 bug，修复代码后重新运行测试——直到全部通过。

</Step>

<Step title="第三步：提升覆盖率与质量">

覆盖率衡量测试执行了多少行代码。用 `pytest --cov` 生成报告，关注 Missing 列——未覆盖的行需要补充测试。但 100% 覆盖率不等于没有 bug——还要测试边界条件、异常路径和集成场景。

</Step>

## 代码对照

```python
# 被测模块: survey.py
class AnonymousSurvey:
    """匿名调查问卷"""

    def __init__(self, question):
        self.question = question
        self.responses = []

    def show_question(self):
        return self.question

    def store_response(self, response):
        if not isinstance(response, str):
            raise TypeError("回应必须是字符串")
        if not response.strip():
            raise ValueError("回应不能为空")
        self.responses.append(response)

    def show_results(self):
        return f"调查结果: {self.responses}"


# 测试模块: test_survey.py
import pytest
from survey import AnonymousSurvey

def test_store_single_response():
    """测试存储单个回应"""
    survey = AnonymousSurvey("你喜欢的语言？")
    survey.store_response("Python")
    assert "Python" in survey.responses

def test_store_multiple_responses():
    """测试存储多个回应"""
    survey = AnonymousSurvey("你喜欢的语言？")
    responses = ["Python", "Java", "Go"]
    for r in responses:
        survey.store_response(r)
    assert len(survey.responses) == 3
    assert "Go" in survey.responses

def test_store_empty_response_raises():
    """测试空回应抛出异常"""
    survey = AnonymousSurvey("问题")
    with pytest.raises(ValueError):
        survey.store_response("")

def test_store_non_string_raises():
    """测试非字符串回应抛出异常"""
    survey = AnonymousSurvey("问题")
    with pytest.raises(TypeError):
        survey.store_response(123)

# 参数化：一次测多个场景
@pytest.mark.parametrize("response", ["Python", "Java", "C++"])
def test_various_responses(response):
    survey = AnonymousSurvey("问题")
    survey.store_response(response)
    assert response in survey.responses
```

## 常见误区

<Callout type="trap">

**误区：测试只测正常路径**

只测 `add(2, 3) == 5` 不够——还要测边界条件和异常路径。`add(-1, 1)`、`add(0, 0)`、`divide(10, 0)` 抛异常。bug 往往藏在边界情况中。好的测试覆盖正常路径、边界条件和异常路径三类场景。

</Callout>

<Callout type="trap">

**误区：追求 100% 覆盖率而忽略测试质量**

覆盖率只衡量"执行了多少行"，不衡量"测了多少行为"。100% 覆盖率也可能漏掉关键逻辑——比如覆盖了 if 语句但没有验证两个分支的结果。测试质量比覆盖率数字更重要：好的测试名描述行为、断言验证有意义的结果、每个测试只测一件事。

</Callout>

<Exercises>

**问题 1**：为什么测试函数要以 test_ 开头？如果不用这个前缀会怎样？

<Answer>

测试函数以 `test_` 开头是测试框架（unittest、pytest）的命名约定。框架在运行时自动扫描所有以 `test_` 开头的函数并执行它们。

如果不用 `test_` 前缀，测试框架不会将其识别为测试函数，不会自动运行。这意味着：
1. 运行 `pytest` 或 `python -m unittest` 时该函数不会被执行
2. 测试实际上没有运行——你可能以为测试通过了，但实际上它从未执行
3. 代码中的 bug 不会被检测到

这就是为什么命名约定在测试中至关重要——它不只是风格问题，而是框架发现和运行测试的机制。

</Answer>

**问题 2**：以下代码有一个测试 bug，找出来并修复。

```python
def is_even(n):
    return n % 2 == 0

def test_is_even():
    assert is_even(2) == True
    assert is_even(3) == False
    assert is_even(0) == True
    print("所有测试通过！")
```

<Answer>

问题：`print("所有测试通过！")` 是误导性的。assert 失败时会抛出 AssertionError，程序中断，不会执行到 print。但如果所有 assert 通过，print 才执行——这看起来没问题。

真正的测试 bug 是：`assert is_even(2) == True` 这种写法不够 Pythonic，虽然功能正确。更重要的是，这个测试缺少边界条件——没有测试负数和奇数。应该补充：

```python
def test_is_even():
    assert is_even(2) == True
    assert is_even(3) == False
    assert is_even(0) == True
    assert is_even(-2) == True    # 负偶数
    assert is_even(-3) == False   # 负奇数
```

同时，应该删掉 `print("所有测试通过！")`——测试框架会报告通过/失败状态，不需要手动 print。手动 print 会让初学者误以为"看到这行就表示测试通过了"，但如果 assert 从未执行（比如函数名没写对），print 也不会执行，反而掩盖了问题。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="单元测试">

对程序中最小可测试单元（通常是函数或方法）进行验证。每个测试函数只测一个行为，使用 assert 断言验证结果。unittest 是 Python 标准库，pytest 是第三方框架（更简洁）。

</GlossaryItem>

<GlossaryItem term="test_ 命名约定">

测试函数必须以 `test_` 开头，测试框架自动发现并运行。测试类以 `Test` 开头（pytest）。命名约定不是可选的——没有它框架不会识别和运行测试。

</GlossaryItem>

<GlossaryItem term="断言（assert）">

验证代码行为是否符合预期。unittest 提供 assertEqual/assertTrue/assertRaises 等方法。pytest 直接用 Python 内置 assert 语句。断言失败时抛出 AssertionError，测试框架报告失败。

</GlossaryItem>

<GlossaryItem term="测试覆盖率">

衡量测试执行了被测代码的多少行。用 `pytest --cov` 生成报告。覆盖率帮助发现未测试的代码路径，但 100% 覆盖率不等于无 bug——还需测试边界条件和异常路径。

</GlossaryItem>

</Glossary>
