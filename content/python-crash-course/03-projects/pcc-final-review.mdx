## 为什么总复习必须以三个完整项目验收20章

单章100分证明页面结构与核心知识齐全，不证明学习者能在真实系统中迁移。第三版的设计正是先用1–11章建立programming primitives，再用三个项目改变约束：游戏按frame处理持续状态，data pipeline面对不可信source，Web app面对并发requests、users和production environment。总复习要比较三者共同contract与不同failure。

先预测：Pygame bullet leak、API valid-empty与Django IDOR分别属于syntax、state、data还是identity问题；哪些tests可以共用，哪些evidence必须项目专属。预测后用三套交互图建立诊断与验收矩阵。

<Term def="从environment、values、control、function/class、I/O到test oracle逐层消费并约束行为的基础contract集合。">program contract stack</Term>

## Part I：第1–11章如何成为共同底座

第1章确认interpreter与execution path；第2–4章定义values、strings、numbers、lists、slices、tuples与iteration；第5–7章把conditions、dictionaries、input和while组成state transitions；第8–9章用functions/classes封装ownership和invariants；第10章把files、exceptions与JSON变成external boundary；第11章用pytest与fixtures固定regression contract。

这些知识不是在项目开始时“学完就丢”。Ship.update读取第7章式state，Bullet/Alien是第9章objects；CSV/API使用第6章nested shape与第10章exception boundary；Django Model/View是class/function contracts，authorization tests依赖第11章isolation。

```python
def execute_boundary(raw_input, parser, operation):
    normalized = raw_input.strip()                  # ch2
    value = parser(normalized)                      # ch7/8
    try:
        return operation(value)                     # ch8/9
    except (ValueError, OSError) as error:          # ch10
        return {"ok": False, "reason": type(error).__name__}
```

这个skeleton可以是terminal input、CSV field、API parameter或Django form field。不同framework改变adapter，不改变“normalize → parse/validate → operation → specific failure”的基础链。

### Alien Invasion：realtime state machine

第12章建立event/update/draw/tick和Ship/Bullet lifecycle，第13章加入fleet edge、collision、life与game_active，第14章加入restart、difficulty、score/high score、level与ships HUD。关键不是Sprite API，而是每帧transition的唯一owner。

游戏invariants包括：window每帧drain events；Ship始终在screen；active bullets不超过limit且越界最终清零；edge一帧最多drop一次；collision删除数与score一致；一次ship hit只减一条life；inactive不更新world但继续event/draw；restart清空上一局动态状态。

```python
snapshot = {
    "frame": frame_number,
    "ship_x": ship.rect.x,
    "bullets": len(bullets),
    "aliens": len(aliens),
    "lives": stats.ships_left,
    "score": stats.score,
    "active": stats.game_active,
}
```

保存collision前后snapshot比录屏更能定位重复transition。视觉用于观察，state trace用于证明。

### Data Visualization：source到artifact的lineage

第15章控制generated data与random seed，第16章处理CSV/GeoJSON files，第17章处理HTTP transport/status/rate-limit。三章共用parse、schema validation、normalization与visual encoding，但source trust逐步降低。

<Term def="从source identity到raw、accepted/skipped records、transform、visual encoding和export artifact的可追溯记录。">data lineage</Term>

data invariants包括：x/y或dates/highs/lows对齐；dice frequency总和等于rolls；CSV accepted+skipped=raw；GeoJSON lon/lat顺序与range正确；API先过status/decode/schema；normalized records是typed；chart labels、units与axis不误导；PNG/HTML存在并记录source/seed/version。

```python
report = {
    "source": source_identity,
    "raw": raw_count,
    "accepted": len(records),
    "skipped": skipped_by_reason,
    "range": {"min": min(values), "max": max(values)},
    "artifact": str(output_path),
}
assert report["accepted"] + sum(skipped_by_reason.values()) == raw_count
```

空chart必须区分valid empty与invalid response。前者是data result，后者是contract failure；把两者都变成空list会制造虚假成功。

### Learning Log：identity、persistence与release

第18章建立project/app、Topic/Entry、migration与URL-view-template链；第19章加入forms、CSRF、session、owner与authorization；第20章加入Bootstrap、production config、static、Gunicorn、Platform YAML与logs。Web state跨database和users，错误会影响他人，因此security与release evidence是必须项。

<Term def="在authentication之后按request.user、object owner与action限制query和write的安全边界。">identity and ownership boundary</Term>

Web invariants包括：migration graph与database一致；invalid form不写data；valid POST采用redirect；owner由server设置；anonymous重定向login；other user对list/detail/edit均不可见且POST不改变record；DEBUG=False、secret/hosts正确；collectstatic、Gunicorn、health与custom errors通过。

```python
def test_cross_user_update_is_impossible(client, alice, bob_entry):
    client.force_login(alice)
    before = bob_entry.text
    response = client.post(edit_url(bob_entry.id), {"text": "overwrite"})
    assert response.status_code == 404
    bob_entry.refresh_from_db()
    assert bob_entry.text == before
```

template隐藏edit link不是authorization。URL可被直接构造，真正边界必须在query中scope owner，并用第二用户fixtures验证database未变。

跨章问题经常有两个根因层：基础语义与项目协调。例如bullet leak的直接问题是第12章cleanup，长期无界growth也需第7章termination思维；Django Entry越权直接属于第19章owner scope，但第6章nested relationship和第11章two-user fixture决定能否正确复现。

## Failure Taxonomy：不要把所有错误都叫“代码有bug”

**Environment failure**：interpreter/package/settings/secret/host错误。**Syntax/type failure**：parse、index、argument binding和field type。**State failure**：loop不终止、transition重复、cache/HUD过期。**Boundary failure**：file missing、JSON/schema drift、HTTP status/rate limit。**Identity failure**：CSRF、anonymous、wrong owner。**Release failure**：dependency、migration、static、process或health gate。

分类决定证据：environment打印executable/config names；state保存before/event/after；data保存counts/path；identity使用user-object-action matrix；release按commit与stage读取logs。没有分类就容易修错层，例如用CSS隐藏security问题、用retry掩盖schema drift。

<Term def="与commit关联的build、test、migration、static、process、health、log和rollback结果集合。">release evidence</Term>

## Capstone：用一个系统串联20章

可选capstone是“学习数据工作台”：CLI导入JSON/CSV学习记录，class/domain rules验证并用pytest保护；Plotly输出进度图；Django提供Topic/Entry forms、accounts与owner隔离；deployment通过production gates。Pygame部分可作为独立实时练习，不必硬塞进Web app，但其state transition method用于设计import job和UI flows。

capstone最小结构：

1. **Domain**：Topic/Entry values、functions/classes与invariants。
2. **Adapters**：CLI/file/API/forms分别parse和normalize，不把raw data直接交domain。
3. **Persistence**：JSON prototype或Django ORM，明确migration/schema。
4. **Presentation**：Plotly artifact与responsive templates各有labels/empty/error states。
5. **Verification**：unit、boundary、two-user security、artifact与release evidence。

## 20章复习矩阵

第1–4章回答“值在哪里、怎样变化”；第5–7章回答“哪条branch、loop何时结束”；第8–9章回答“谁拥有行为与state”；第10–11章回答“boundary如何失败、如何证明修复”。第12–14章回答“每帧如何保持实时一致”；第15–17章回答“data如何可信地变成图”；第18–20章回答“request、user、database与release如何安全协作”。

复习时不要逐页机械重读。先选一个failure scenario，写出producer、input shape、owner、transition、consumer和evidence，再回对应章节补缺。能迁移这个分析框架，才说明20章形成了体系。

<Callout type="trap" title="三个项目都能启动，所以全书已经掌握">
启动只覆盖最窄happy path。必须验证Pygame lifecycle/collision、data schema/count、Django owner/release，以及每个failure的可重复证据。
</Callout>

<Callout type="trap" title="遇到项目问题只重读项目章节">
项目消费第1–11章contracts。alias、loop termination、argument binding、exception或test isolation缺口会在project放大；应从症状回退到最小基础章并重验consumer。
</Callout>

## 本章回顾：掌握意味着能解释、实现、复现和交付

1. 第1–11章构成三个项目共同的program contract stack。
2. Alien Invasion用state transition evidence证明实时loop与object lifecycle。
3. Data项目用data lineage证明source到artifact没有静默丢失或误导。
4. Learning Log用identity boundary与release evidence证明多用户和production安全。
5. 总验收必须覆盖normal、boundary、failure、security与operations，并绑定同一revision。

<Exercises>

**问题 1：比较三个项目的state lifetime与最重要evidence。**

<Answer>Alien Invasion state跨frames，重点是event/update/draw顺序、Group counts、collision与restart snapshots；Data state跨records和artifacts，重点是source identity、accepted/skipped守恒、range/seed/schema与PNG/HTML；Learning Log state跨requests/session/database/release，重点是migrations、form/CSRF、two-user owner matrix、static/Gunicorn/health/logs。三者都要tests，但不能用同一种截图替代专属证据。</Answer>

**问题 2：API返回200但图为空，如何按producer-to-consumer链调试？**

<Answer>保存request/status/headers，确认JSON decode；验证top-level与items schema，区分valid empty；逐item normalize并报告accepted/skipped，检查数值sort和chart inputs；最后检查labels/axis/export。若exception policy有问题回第10章，nested dict回第6章，encoding回第15章。修复producer后重跑所有下游，不只绕过Plotly错误。</Answer>

**问题 3：一个capstone何时达到可交付，而不只是“能演示”？**

<Answer>同一commit下有自动behavior tests、boundary/failure scenarios、identity/ownership security matrix、chart/build/runtime artifacts和operations evidence；clean environment可build，schema migration与static成功，process/health/logs正常，并有rollback路径。正常演示、invalid source、wrong owner和deployment failure都有明确outcome与恢复策略。</Answer>

</Exercises>
