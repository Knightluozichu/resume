## 直觉引入

电影每秒播放 24 帧画面，你看到的是连续动作。游戏也是一样——每秒绘制 60 帧画面，每帧之间快速更新对象位置，人眼就感觉物体在平滑移动。每一帧做三件事：检查玩家按了什么键（事件处理），更新所有对象的位置和状态（状态更新），把所有对象画到屏幕上（屏幕绘制）。这就是游戏循环。

本书的"外星人入侵"项目就是这个循环的完整实践——用类管理飞船和外星人，用循环处理移动和射击，用碰撞检测判定击中。这是全书知识的综合应用：变量列表存储子弹，条件循环控制游戏逻辑，类封装游戏对象，异常处理保证健壮性。

### 游戏循环

<Term def="游戏循环是游戏程序的核心结构：每帧执行事件处理（检测输入）、状态更新（移动物体）、屏幕绘制（渲染画面）三步，循环往复直到游戏结束。">

    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE:
                fire_bullet()

    # 2. 状态更新
    ship.update()           # 更新飞船位置
    aliens.update()         # 移动外星人
    bullets.update()        # 移动子弹
    check_collisions()      # 碰撞检测

    # 3. 屏幕绘制
    screen.fill((0, 0, 0))  # 清屏（黑色背景）
    ship.blitme()           # 绘制飞船
    aliens.draw(screen)     # 绘制所有外星人
    bullets.draw(screen)    # 绘制所有子弹
    pygame.display.flip()   # 翻转缓冲区，显示画面

    clock.tick(60)          # 控制帧率为 60 FPS

### Pygame Sprite 精灵系统

```python
from pygame.sprite import Sprite

class Ship(Sprite):
    """飞船精灵"""

    def __init__(self, screen):
        super().__init__()
        self.screen = screen
        self.image = pygame.image.load("ship.bmp")
        self.rect = self.image.get_rect()
        self.rect.midbottom = screen.get_rect().midbottom
        self.moving_right = False
        self.moving_left = False

    def update(self):
        """每帧更新位置"""
        if self.moving_right:
            self.rect.x += 5
        if self.moving_left:
            self.rect.x -= 5

    def blitme(self):
        """绘制飞船"""
        self.screen.blit(self.image, self.rect)
```

## 常见误区

<Callout type="trap">

**误区：忘记 clock.tick(60) 控制帧率**

没有 `clock.tick(60)`，游戏循环会以 CPU 最快速度运行——在高速电脑上飞船一帧就飞出屏幕，在慢速电脑上卡顿。tick(60) 将帧率限制为 60 FPS，保证所有电脑上游戏速度一致。这是游戏循环不可或缺的一步。

</Callout>

<Callout type="trap">

**误区：把所有逻辑塞进主循环**

游戏循环应该只做协调——事件分发、更新调用、绘制调用。具体逻辑放在各自的类中：飞船移动逻辑在 Ship.update()，碰撞检测在独立函数，游戏统计在 GameStats 类。如果主循环超过 100 行，就该重构——把逻辑提取到类或函数中。

</Callout>

**问题 1**：游戏循环的三步是什么？为什么顺序不能颠倒？

<Answer>

游戏循环三步：
1. **事件处理**：检测玩家输入（键盘、鼠标）和系统事件（退出）
2. **状态更新**：根据输入和游戏规则更新所有对象的位置和状态
3. **屏幕绘制**：清空屏幕，绘制所有对象，翻转缓冲区显示画面

顺序不能颠倒的原因：
- 事件处理必须在最前面——先知道玩家做了什么，才能更新状态
- 状态更新在绘制之前——先更新位置，再画到屏幕上。如果先画再更新，画面比状态滞后一帧
- 绘制在最后——只在状态确定后才渲染，保证画面反映最新状态

另外，事件处理和状态更新之间不应有绘制——否则画面会闪烁。

</Answer>

<Glossary>

<GlossaryItem term="游戏循环（Game Loop）">

游戏程序的核心结构，每帧执行三步：事件处理（检测输入）、状态更新（移动物体）、屏幕绘制（渲染画面）。循环往复直到游戏结束。clock.tick(60) 控制帧率保证速度一致。

</GlossaryItem>

<GlossaryItem term="Sprite（精灵）">

Pygame 中游戏对象的基础类。继承 Sprite 后可加入 Group 统一管理。包含 image（图像）和 rect（矩形位置）两个核心属性。update() 定义每帧行为，blitme() 定义绘制方式。

</GlossaryItem>

<GlossaryItem term="碰撞检测">

检测两个游戏对象是否重叠。groupcollide() 检测两组精灵的碰撞，返回碰撞字典。spritecollideany() 检测单个精灵是否与组中任何精灵碰撞。碰撞结果用于更新分数、删除对象、判定游戏结束。

</GlossaryItem>

<GlossaryItem term="帧率（FPS）">

每秒绘制的画面帧数。clock.tick(60) 将帧率限制为 60 FPS。帧率决定了游戏流畅度——越高越流畅，但 CPU 消耗也越大。限制帧率保证游戏在不同性能的电脑上速度一致。

</GlossaryItem>

</Glossary>
