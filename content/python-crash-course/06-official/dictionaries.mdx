## 为什么需要按名字取资料

给游戏角色保存颜色、分数和速度时，如果只记住“第二项是分数”，插入一个新项目就可能让后面的读取全部错位。我们需要让每份资料带上名字，不必靠位置猜含义。

这一章先做一份角色资料，再做多人资料。目标不是把所有读取都写得“不报错”，而是分清：哪些资料必须有，哪些允许暂时没有。

## 1. 字典：键指向值，而不是位置指向值

Python 的 <Term def="把唯一的键关联到值的可修改容器，按键而非位置查找。">字典</Term>（dict）用大括号创建，冒号左边是键，右边是值。键回答“查哪项”，值回答“这项是什么”。同一个键只能有一条绑定，值却可以重复；`len(d)` 数的是绑定条数。空字典写成 `{}`。

```python
alien = {}
alien["color"] = "green"
alien["points"] = 5
alien["points"] = 10
print(alien["points"], len(alien))  # 10 2
print("green" in alien)           # False：in 默认检查键
print("color" in alien)           # True
```

前两次赋值新增绑定，第三次找到已有键并替换值，不会保留两个 points。字典里的整数键 `0` 也只是一个键，并非“第一项”：`{0: "zero"}[0]` 能读取，是因为真的有键 0。

### 删除与重新插入

`del d[key]` 删除绑定；`d.pop(key)` 还会返回删掉的值，适合“领取积分后移除积分项”。两者在键缺失时默认都抛 `KeyError`；`pop(key, default)` 可指定缺失时返回什么。

```python
alien = {"color": "green", "points": 5}
alien["x"] = 0
alien["points"] = 10
removed = alien.pop("color")
alien["color"] = "yellow"
print(removed)      # green
print(list(alien))  # ['points', 'x', 'color']
del alien["x"]
print(alien)        # {'points': 10, 'color': 'yellow'}
```

Python **3.7 起**保证字典保留插入顺序。更新已有键不移动位置；删除后重新插入会放到末尾。插入顺序不等于字母顺序，更不等于按分数排名。这个保证也不意味着字典支持用位置切片。[事实依据：dict](https://docs.python.org/3/library/stdtypes.html#mapping-types-dict)。

## 2. 什么可以当键，值会不会被复制

键必须 <Term def="对象的哈希值在其生命周期内不变；比较相等的对象必须有相同哈希值。">可哈希</Term>。可以把哈希理解为查找时使用的编号，但相同编号不一定是同一键，还需要相等比较。字符串、整数通常可用；列表和字典不可用。元组只有在**所有元素都可哈希**时才可用，并非加一层圆括号就安全。

```python
locations = {("row", 0): "origin"}
print(locations[("row", 0)])  # origin
try:
    invalid = {("row", []): "bad"}
except TypeError:
    print("元组含列表，不能作键")
```

这里不深入哈希算法，只需要遵守键的契约。此外，“键唯一”以相等关系为准，不是以书写形式为准：`1`、`1.0` 与 `True` 比较相等，作为键会指向同一个条目；不要用它们表示三种身份。[定义依据：hashable](https://docs.python.org/3/glossary.html#term-hashable)。

值不要求可哈希。把列表赋给字典项时，保存的是对那个对象的引用，不是复制一份列表。下例的两条路径汇合到同一个列表，修改对象后，两边都能看到；重新给一个键赋值则只改那条绑定。

```python
shared = ["python"]
choices = {"ada": shared, "grace": shared}
choices["ada"].append("c")
print(choices["grace"])  # ['python', 'c']
choices["ada"] = ["rust"]
print(choices["grace"])  # ['python', 'c']：未跟着换绑
```

## 3. 缺失、None 和默认值是三回事

读取之前先决定 <Term def="键不存在时，是报错、返回默认值，还是显式创建绑定的规则。">缺失策略</Term>：必填的分数可用 `alien["points"]`，让 `KeyError` 暴露错误；允许省略的速度可用 `alien.get("speed", "medium")`。get 只读，缺失时返回默认值，不创建绑定；`None` 是能被正常保存的值，不等于“没有这个键”。

```python
profile = {"name": "Ada", "city": None}
print(profile.get("timezone", "UTC"))  # UTC
print("timezone" in profile)          # False：没写入
print(profile.get("city", "unknown")) # None：键已存在
print("city" in profile)              # True
print(profile.get("missing"))        # None：省略默认值
```

因此只检查 `get(...) is None` 不能区分缺失与已存 None。初学时优先先问 `key in d`，再读取。需要一次读取区分两种情况时，可以用一个专用标记对象，通常叫“哨兵”；`is` 判断是否正是那个对象，不是比较文本内容。

```python
profile = {"city": None}
missing = object()
for key in ("city", "timezone"):
    value = profile.get(key, missing)
    if value is missing:
        print(key, "缺失")
    else:
        print(key, value)
# city None
# timezone 缺失
```

实验最后四步正好展示了“无绑定 → 默认返回 → 方括号报错 → 写入 None → 返回 None”。模拟器为了让你比较结果会允许异常后继续；普通 Python 脚本若不捕获异常，会在方括号读取那行停止，不会自动运行后面的赋值。

## 4. 遍历：先决定一次循环需要什么

`keys()`、`values()`、`items()` 返回 <Term def="随着原字典的绑定变化而反映当前内容的可遍历对象，不是独立复制。">字典视图</Term>。直接 `for key in d` 等价于遍历键；只要值用 values；同时要名字和内容用 items，每次得到一个 `(key, value)` 二元组，可以分给两个循环变量。

```python
languages = {"grace": "cobol", "ada": "python", "lin": "python"}
for name, language in languages.items():
    print(f"{name}: {language}")
print(list(languages.keys()))    # ['grace', 'ada', 'lin']
print(list(languages.values()))  # ['cobol', 'python', 'python']
print(sorted(languages))         # ['ada', 'grace', 'lin']
print(list(languages))           # ['grace', 'ada', 'lin']：原顺序没变
print(sorted(set(languages.values())))  # ['cobol', 'python']
```

values 保留重复值。`set(...)` 去重却不保证展示顺序；需要稳定输出时再排序。`sorted(d)` 返回新列表，默认排序的是键，不是值，而且要求元素可以相互比较。本章统一使用字符串键，混合数字和字符串不能直接如此排序。对应到实验，切换视图只改变输出单位，不应修改字典本身。

### 动态视图不等于固定快照

保存视图后再更新字典，读取视图能看到更新；用 `list(...)` 保存当时的条目，则不会自动新增、删除或替换条目。实验“视图与快照”的上下两部分分别表达这两种关系。

```python
scores = {"ada": 5}
view = scores.items()
snapshot = list(scores.items())
scores["ada"] = 10
scores["grace"] = 8
print(list(view))  # [('ada', 10), ('grace', 8)]
print(snapshot)    # [('ada', 5)]
```

这里的值是整数，所以快照输出不变；若值是列表，快照仍可能引用同一列表，不能把它当作嵌套对象的深复制。也不要边遍历动态视图边增删键：官方文档说明这可能抛 `RuntimeError`，或无法遍历全部条目。安全删除可遍历独立的键列表，见练习 2。[事实依据：Dictionary view objects](https://docs.python.org/3/library/stdtypes.html#dictionary-view-objects)。

## 5. 嵌套：每个括号只走一层

把列表与字典互相容纳，构成 <Term def="容器里面再放容器的层次关系；访问时必须按每层的类型取值。">嵌套结构</Term>。选择依据是查找问题：按第几个展示，用列表装字典；一个名字对应多项内容，用字典装列表；按唯一名字直接找到资料，用字典装字典。

```python
people = [{"name": "Ada"}, {"name": "Grace"}]
places = {"ada": ["London", "Paris"]}
users = {"ada": {"city": "London"}, "grace": {"city": "NYC"}}
print(people[0]["name"])      # Ada：位置 → 字段
print(places["ada"][1])      # Paris：姓名 → 位置
print(users["ada"]["city"]) # London：姓名 → 字段
for name, cities in places.items():
    for city in cities:
        print(name, city)
# ada London
# ada Paris
```

外层一次循环取出“一人的城市列表”，内层才逐个城市打印。同理，`users["ada"]` 得到的是整份内层字典，第二次 `['city']` 才取到文字。先在实验中选形态、预测每层类型，再单步进入结构；打开错误路径会真的停止在不存在的键，或在列表上触发索引类型错误，而不是改动原有数据。

按位置访问列表时可能有 `IndexError`，按键访问字典时可能有 `KeyError`，索引类型不对可能有 `TypeError`。这些不是同一种“缺失”。如果数据允许没有某个城市，应在那一层制定缺失策略，而不是用一个大范围异常捕获把全部错误藏起来。

## 常见误区

<Callout type="trap" title="get 返回了列表，就等于字典存了列表？">
  **现象 →** `d.get("tags", []).append("new")` 后，d 仍无 tags。 **原因 →**
  缺失时只返回临时列表，get 不写入。 **修法 →** 先用成员测试确认是否缺失，再显式
  `d["tags"] = []`；之后才追加。实验的缺失读取也不会新增行。
</Callout>

<Callout type="trap" title="字典有序，所以修改或排序会自动重排？">
  **现象 →** 改 points 后它还在原位置。 **原因 →** 插入顺序不是数值排名，sorted
  返回新列表。 **修法 →**
  展示时显式选择排序规则；只有删除再插入才把已有键放到末尾。
</Callout>

<Callout type="trap" title="删除已处理的项，不会影响下一轮？">
  **现象 →** `for key in d` 中删键可能报 RuntimeError。 **原因 →**
  迭代器正在访问被改变的键集合。 **修法 →** 遍历 `list(d)`
  的键快照再删，不依赖“这次碰巧没报错”。
</Callout>

<Callout type="trap" title="不同键的值一定互不影响？">
  **现象 →** 给 ada 的列表追加，grace 也变化。 **原因 →**
  两个键引用同一个列表；赋值不自动复制。 **修法 →**
  需要独立列表时分别创建。上面的共享引用代码可复现这一差别。
</Callout>

## 小结

- 新增、更新、删除改变绑定；重插改变顺序。
- 视图跟随字典，快照与排序列表不自动更新。
- 按层读取嵌套容器；None 不代表键缺失。

**问题 1：修改实验代码，回收缺失策略**

沿用实验初始样本，先取走 points，再写回 0。请在运行前预测键顺序；随后补全“读缺失 speed 不写入字典”的代码，并断言 city 存为 None 时不会采用默认值。

```python
alien = {"color": "green", "points": 5}
earned = alien.pop("points")
alien["points"] = 0
speed = alien.get("speed", "medium")
alien["city"] = None
assert earned == 5 and speed == "medium"
```

**问题 2：安全删除并解释视图**

独立实现：从 `{"ada": 0, "grace": 8, "lin": 0}` 中删除零分者。删除前保存 items 视图和条目快照；目标是最终只剩 grace，但快照仍保留三人。请说明为何不能直接遍历 d 删除。

<Answer>

```python
scores = {"ada": 0, "grace": 8, "lin": 0}
view = scores.items()
snapshot = list(scores.items())
for name in list(scores):
    if scores[name] == 0:
        del scores[name]
assert list(view) == [("grace", 8)]
assert snapshot == [("ada", 0), ("grace", 8), ("lin", 0)]
assert sorted(scores) == ["grace"]
```

循环输入是删除前复制出的键列表，不随 scores 缩小。items 视图仍跟随 scores，条目快照保留旧绑定。若只要分数而不要名字，values 可以遍历，但无法单靠分数知道该删除哪个键。

</Answer>

**问题 3：独立实现城市查询**

目标访问图为 `users → "ada" → dict → "city" → "London"`（实验的字典装字典形态）。实现 `city_of(users, name)`：用户或 city 键缺失返回 `"unknown"`；city 存在但为 None 时保留 None。约定外层与每份用户资料都是字典，不负责修复类型错误。用正常、缺用户、缺字段、空值四种样本验收。

<Answer>

```python
def city_of(users, name):
    if name not in users:
        return "unknown"
    return users[name].get("city", "unknown")

users = {"ada": {"city": "London"}, "grace": {}, "lin": {"city": None}}
assert city_of(users, "ada") == "London"
assert city_of(users, "missing") == "unknown"
assert city_of(users, "grace") == "unknown"
assert city_of(users, "lin") is None
```

外层先判断用户存在，内层再采用字段默认值。写成 `value or "unknown"` 会把 None、空字符串等有效保存值也覆盖，违反题目约定；“缺失策略”不能替代逐层的数据含义。

</Answer>
