## 直觉：从“做一次”到“继续接收，直到结束”

想象工厂收件处：来一件就登记一件，空单退回，收到收工通知才停。若只能登记一次，第二件就没人处理；若只知道重复登记却没有停下来的办法，收工通知也会被当成普通货物。

程序也需要区分“收到什么”“这一件做不做”“接下来是否还要收”。本章要把这三件事拆开，让你既能连续处理，也能说清每次为什么继续或结束。

## 五个概念：输入怎样变成可推进的工作

### 1. 输入转换：拿到的是文字，不是你眼中的数字

这里的<Term def="把输入得到的字符串变成计算所需的类型；转换不等于检查业务规则。">输入转换</Term>发生在读取之后、计算之前。`input(prompt)`先显示提示，再读取一行，返回字符串；末尾换行被去掉，但空格不会自动去掉。直接按回车得到 `""`，不是数字零。[官方 input 文档](https://docs.python.org/3/library/functions.html#input)还说明：输入流结束会抛出 `EOFError`，并不会自动返回 `"quit"`。

下面是完整小程序，键入 `7` 后依次输出 `str`、`77`、`14`。提示文本也说明了输入格式。实验的“输入”场景用带引号的小格表示同一件事：数字外观仍是文字。

```python
prompt = "请输入一个整数（例如 7）："
raw = input(prompt)
print(type(raw).__name__)
print(raw + raw)
number = int(raw)
print(number + number)
```

`int("7")` 得到整数 7，`int(" 7 ")` 也可以；`int("7.5")` 和 `int("")` 会抛出 `ValueError`，不是自动变成 7 或 0。`strip()`只去掉首尾空白，不会把任意文字变成数字。这里接受前后空白；密码等有空格含义的数据不能照搬这个决定。

### 2. 取模运算符（Modulo Operator）：用余数分流

整数的<Term def="用 % 取得整数除法的余数；右侧不能为零。">取模（modulo）</Term>运算能判断是否整除：`n % 2 == 0`表示偶数。例如 7 件物品每 2 件一组，可分成 3 组，还剩 1 件，因此 `7 % 2`是 1；6 件恰好分成 3 组，余数为 0。实验把这个余数判断画成分流菱形：余数为零就走左侧返回路径，否则才进入输出区。

下面不需要键盘输入，可以直接运行；余数一列依次是 `0、1、0、1`。本章只用整数和正除数 2，不把浮点余数混进奇偶判断。

```python
for number in [0, 1, 2, 7]:
    print(number, number % 2, number % 2 == 0)
```

### 3. while 循环：每一轮都要重新过门

所谓<Term def="先检查条件，为真才执行循环体；执行后回到条件再次检查。">while 循环</Term>不是“把一段代码复制很多次”，而是重复检查同一条件。条件可能一开始就为假，因此循环体允许执行零次。需要知道次数时可以用 `for`；不知道用户何时结束、却知道继续条件时，`while`更直接。

到实验中把上限改成 0：执行点从检查处直接走向退出，输出区保持空。上限为 3 时，`n`从 0 前进到 3；**在进入本轮前检查 `n < 3`，进入后才增加 `n`**，所以本轮输出可以包含 3，并不矛盾。[while 的官方定义](https://docs.python.org/3/reference/compound_stmts.html#the-while-statement)正是这种“先检查、后执行”。

### 4. 循环控制：结束本轮与结束整个循环不同

这里把改变后续执行路线的做法称为<Term def="通过条件、标志、break或continue决定继续本轮、开始下一轮或离开循环。">循环控制</Term>。`continue`跳过本轮余下代码，回到条件检查；`break`直接离开最近一层循环，不再检查其条件。实验中，左侧回路与右上退出节点因此是两条不同路径。[官方 break](https://docs.python.org/3/reference/simple_stmts.html#the-break-statement)与[continue](https://docs.python.org/3/reference/simple_stmts.html#the-continue-statement)定义可对照核查。

`"quit"`只是约定的退出值，不是 Python 的特殊单词。若多个分支都可能要求停止，可以用 `active`这样的布尔变量作标志（flag）；但赋值 `active = False`不会立即跳出本轮，剩余代码仍会执行，下一轮才重新检查。下面刻意用 `else`避免把退出值也打印出来。

```python
active = True
while active:
    message = input("登记内容，quit 结束：").strip()
    if message == "quit":
        active = False
    else:
        print("已登记：", message)
print("收工")
```

### 5. 终止依据：说明什么状态会变，而不是盼着它停止

一个<Term def="解释循环何时能够离开：有限工作持续减少，或用户触发可到达的退出路径。">终止依据</Term>要同时看条件与更新。实验的正常计数每轮先做 `n += 1`，所以距离上限越来越近；错误版的偶数分支跳过更新，下一轮看见原样的 `n=0`，再执行同一个跳过动作。

交互程序则不同：用户若始终不输入 `quit`，程序可以一直等待或工作，不能声称“必定结束”。它的保证是：**退出输入一旦被读取，就能到达退出语句**。等待键盘输入不是忙着执行的无限循环。遇到演示里的错误计数，在普通终端通常可用 `Ctrl+C`中断。

## 实验：沿返回路径找出被跳过的更新

先预测：把计数上限从 3 调到 6，循环体输出会变成什么？再把更新移到 `continue`后面，输出会变多、变少，还是无法结束？

<PccUserInputWhileLab />

按这个顺序动手，不必一次看完全部帧：

1. **正常计数**：上限 3，单步到 `n=2`，看左回路亮起；再继续到条件为假。记录输出 `1、3`，并区分三次执行循环体与两次输出。
2. **故障计数**：同样上限 3，两次走过左回路，状态尺仍在 0。虚线更新节点没有执行；轨迹被演示器截断，不是 Python 发现错误后自动停止。
3. **输入退出**：依次消费 `"2"`、`""`、`"quit"`。空行触发 `continue`，但下一轮会读取新的一行；`quit`触发 `break`，第四格 `"4"`仍未读取。
4. **反例核验**：把故障版上限改成 0，竟然也能退出，因为循环体根本没执行。因此“某一次正常结束”不足以证明更新位置正确。

解释图时，要同时指出“回到了哪一行”和“状态有没有改变”。可以拖动进度回看，或点击“重置全部”清空预测、恢复默认场景。

## 可运行代码：从轨迹到自己的程序

下面各代码块都是可单独运行的 Python 3 程序，无第三方依赖。复制到文件后用 `python3 文件名.py`运行；交互程序按给定次序逐行输入。浏览器实验是有限执行模型，不替代真正的 Python 运行。

### 计数：先保证推进，再决定这一轮是否输出

这是实验正常场景的完整代码。改动 `limit`即可重复图中的边界测试；上限 6 时输出 `1、3、5`，最后再输出 `结束`。

```python
n = 0
limit = 3
while n < limit:
    n += 1
    if n % 2 == 0:
        continue
    print(n)
print("结束")
```

`n=0`提供起点，`n < limit`决定是否进入，`n += 1`保证进展。偶数分支只取消本次输出，不取消已经发生的增加。缩进结束后的最后一行不属于循环体。**不要直接运行无限版本**：先在实验故障场景看轨迹；排错时可单步调试，避免让终端反复空转。

### 输入：每次重新读取，再检查退出与跳过

这段与实验输入场景一致。依次输入 `2`、空行、`quit`，输出只有 `2`和最后的`结束`；不需要再输入第四行。若把 `input()`移到循环外，空行分支也会不断检查旧输入。

```python
while True:
    raw = input("值或 quit: ").strip()
    if raw == "quit":
        break
    if raw == "":
        continue
    print(raw)
print("结束")
```

若需要整数，转换应放在退出检查之后，否则 `int("quit")`会先失败。下面增加一个局部的错误恢复段：`try`尝试转换，`except ValueError`只处理“这段文字不能转成整数”，然后重新读取。异常的完整机制留到第 10 章；此处不捕获所有错误，也不把失败伪装成数字零。

```python
while True:
    raw = input("0～20 的整数，quit 结束：").strip()
    if raw == "quit":
        break
    try:
        number = int(raw)
    except ValueError:
        print("请输入整数文字")
        continue
    if not 0 <= number <= 20:
        print("超出范围")
        continue
    print("偶数" if number % 2 == 0 else "奇数")
```

依次输入 `7.5、-1、8、quit`，预期反馈是“请输入整数文字、超出范围、偶数”，随后退出。转换成功仅说明得到整数，不说明范围合格；两条失败路径都回到新的 `input()`，因此不会困在旧值上。

### 列表间搬运（Moving Items Between Lists）：每轮减少一件待办

集合不需要用户发出结束信号：`while pending`在列表非空时继续。`pop()`拿走末项并返回它，`append()`把拿出的项放到另一个列表；一次拿出对应一次放入，**每轮结束时**两个列表的元素总数保持不变。这里的“搬运”是从待办列表删除，再把同一个值加入完成列表，不是复制后仍留在原处。

```python
pending = ["A", "B", "C"]
finished = []
while pending:
    item = pending.pop()
    finished.append(item)
    print(pending, finished)
assert finished == ["C", "B", "A"]
```

不要假定原有顺序被保留。下面是程序实际打印的三轮状态，待办长度从 3 降到 0，所以能够结束。若必须按 A、B、C 处理，小列表示例可改为 `pop(0)`；大规模队列再考虑更合适的容器。

| 完成轮数 | pending           | finished          |
| -------- | ----------------- | ----------------- |
| 0        | `['A', 'B', 'C']` | `[]`              |
| 1        | `['A', 'B']`      | `['C']`           |
| 2        | `['A']`           | `['C', 'B']`      |
| 3        | `[]`              | `['C', 'B', 'A']` |

“总数不变”要选对观察时刻。第一轮 `pop()`刚执行后，`pending`有 2 项、`finished`有 0 项，另 1 项由 `item`暂存；执行 `append()`后，两个列表才重新合计 3 项。若在两句之间插入 `continue`，待办仍会减少，循环仍能结束，但取出的项没有进入完成列表。**能够终止不等于搬运完整**，这也是为什么上面的断言要检查最终内容，而不只是检查待办为空。

### 删除所有匹配项（remove all instances）：先确认目标仍存在

`remove(value)`一次只删除第一个相等项。要删除所有 `"作废"`，每次先检查还在不在，再删一个；每轮匹配项数量减少 1，从 2 到 1 到 0。用 `for`一边沿原列表前进一边删除，可能跳过移动到当前位置的相邻项。

```python
records = ["保留", "作废", "作废", "归档"]
while "作废" in records:
    records.remove("作废")
print(records)
assert records == ["保留", "归档"]
```

[官方列表方法说明](https://docs.python.org/3/tutorial/datastructures.html#more-on-lists)还规定：找不到目标时 `remove()`会抛出 `ValueError`；空列表 `pop()`会抛出 `IndexError`。前面的成员检查和非空检查不是装饰，而是操作的前提。这里列表很小，重点是正确性，不把逐项查找删除当作大数据最优方案。

### 问卷字典：何时写入，重复名字怎么办

用用户输入填充字典（Filling a Dictionary with User Input）时，问卷每次读取姓名和选项，再写入字典。约定姓名唯一且不能为空；重复姓名保留最新答案。这是明确的规则选择，不是字典帮你保留了两份记录。[官方字典文档](https://docs.python.org/3/tutorial/datastructures.html#dictionaries)说明：已有键再次赋值会替换旧值。

```python
answers = {}
polling = True
while polling:
    name = input("姓名，quit 结束：").strip()
    if name == "quit":
        polling = False
    elif name == "":
        print("姓名不能为空")
    else:
        choice = input("想去哪里？").strip()
        if choice == "":
            print("选项不能为空，本次未记录")
            continue
        answers[name] = choice
print(answers)
```

输入 `小林、海边、小林、山里、quit`，最终只有 `{'小林': '山里'}`。逐次检查下面的状态：循环执行了三轮，但只提交了两次答案，而且字典中只有一个姓名。

| 本轮读取       | 本轮动作               | 轮末字典           |
| -------------- | ---------------------- | ------------------ |
| `小林`、`海边` | 新增姓名，写入答案     | `{'小林': '海边'}` |
| `小林`、`山里` | 同一个键，替换旧答案   | `{'小林': '山里'}` |
| `quit`         | 标志设为假，不询问选项 | `{'小林': '山里'}` |

`polling=False`之后本轮没有其他工作，下一次检查时退出；空选项的 `continue`回到姓名读取，不写入半条记录。循环轮数、成功写入次数和不同姓名数是三个不同的量，不能用字典长度判断已经问过几次。

## 常见误区：观察现象，再修正路径

<Callout type="trap" title="把键入的 8 当成整数 8">
  **现象 →** `raw + raw`得到 `88`而非 16。 **原因 →**
  `input()`返回字符串，字符串加法是拼接。 **修法 →** 先检查退出值，再用
  `int()`转换；失败时重新提示，成功后再检查范围。
</Callout>

<Callout type="trap" title="continue 只是跳过 print，不会影响更新">
  **现象 →** 实验故障版永远停在 `n=0`。 **原因 →** 更新也在
  `continue`之后，本轮余下代码全部被跳过。 **修法 →**
  把必要推进放到跳过之前；单步核对下轮状态确实改变。
</Callout>

<Callout type="trap" title="标志设成 False，后面的语句就不执行了">
  **现象 →** 输入退出值后仍被打印或记录。 **原因 →** 改标志只是赋值，下一次到
  while 才检查。 **修法 →** 用 `else`隔开后续工作；若需立刻离开当前循环，用
  `break`。
</Callout>

<Callout type="trap" title="一次 remove 能删光所有匹配项">
  **现象 →** 相邻的两个“作废”只少了一个。 **原因 →**
  `remove()`只删第一个；遍历原列表时删除还可能漏项。 **修法 →** 小列表用 `while
  目标 in 列表`逐次删除，每次都检查是否仍存在。
</Callout>

## 小结

- 输入先得字符串，转成整数后才能做奇偶计算。
- 跳过、退出、集合更新都要有明确的执行位置。
- 判断能否结束，要检查每条返回路径是否推进状态。

**问题 2 · 改实验对应代码。** 把计数程序改成“只输出 1～6 中的偶数”，且始终能够结束。要求只改分流条件，不移动更新行。写出预期输出，并解释为什么不会卡住。

**小分问：** 待办列表为 `["A", "作废", "作废", "B"]`，先预测反复 `pop()` 再 `append()` 的完整结果。然后独立改为按原顺序搬运，搬完再删除全部 `"作废"`，目标为 `["A", "B"]`。必须检查源列表清空、相邻重复项全删，并测试空列表输入。

<Answer>

```python
n = 0
while n < 6:
    n += 1
    if n % 2 != 0:
        continue
    print(n)
```

输出 `2、4、6`。改成“余数不为零则跳过”，就过滤了奇数。必要推进仍在 `continue`之前，所有六轮都会增加 `n`；若连更新一起挪到最后，则不能用同样的理由保证退出。可先在实验中定位更新，再复制代码到 Python 修改。

小分问中，默认 `pop()` 从末尾取，结果是 `["B", "作废", "作废", "A"]`，不是原顺序。小列表改用 `pop(0)` 从开头取；删除阶段用成员检查控制 `while`，避免边遍历边删除跳过第二个相邻的 `"作废"`。

```python
pending = ["A", "作废", "作废", "B"]
finished = []
while pending:
    finished.append(pending.pop())
assert pending == []
assert finished == ["B", "作废", "作废", "A"]

for original, expected in (
    (["A", "作废", "作废", "B"], ["A", "B"]),
    ([], []),
    (["作废", "作废"], []),
):
    pending, finished = original.copy(), []
    while pending:
        finished.append(pending.pop(0))
    assert pending == [] and finished == original
    while "作废" in finished:
        finished.remove("作废")
    assert finished == expected
    assert "作废" not in finished
```

空列表让两个 `while` 都执行零轮，不会对空列表调用 `pop()`；全作废列表则验证结果确实可以为空。只断言源列表清空，抓不住搬运漏项或顺序颠倒，所以搬运后先检查完整内容，再检查删除后的结果。

</Answer>

**问题 3 · 独立实现。** 写一个队伍问卷：空姓名跳过，`quit`退出，重复姓名拒绝覆盖；合法的新姓名才询问队伍。按次序输入 `阿宁、蓝队、阿宁、quit`，目标字典为 `{'阿宁': '蓝队'}`，重复姓名处不得再询问队伍。

<Answer>

```python
teams = {}
while True:
    name = input("姓名，quit 结束：").strip()
    if name == "quit":
        break
    if name == "":
        continue
    if name in teams:
        print("姓名已登记")
        continue
    team = input("队伍：").strip()
    if team == "":
        print("队伍不能为空")
        continue
    teams[name] = team
print(teams)
```

先检查退出，再检查空值和重复，最后询问队伍并写入。两个姓名相关的 `continue`都跳过了队伍读取，下一轮重新问姓名。另测试第一行就是 `quit`，应输出空字典；第一行空白时不应出现队伍提示。若用户永不输入退出值，问卷不会被保证自动结束。

</Answer>
