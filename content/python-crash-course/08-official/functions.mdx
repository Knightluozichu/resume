## 先把一段加工步骤封装起来

一条生产线反复处理不同批次时，不该每换一批就重写整段操作。我们希望给这段操作起一个名字，让后来的人交入材料、取走结果，而不用逐行追踪内部步骤。

不过，“交进去”和“拿回来”必须说清楚：次序错了会不会加工错？原材料会不会被改掉？屏幕显示“完成”，是否真的交出了成品？没有这些约定，减少重复反而会隐藏错误。

## 1. 调用接口：Defining a Function 与 Passing Arguments

### 定义不是调用

用 `def` 定义一个<Term def="把一段可重复执行的操作命名、接收输入并可返回结果的对象。">函数（function）</Term>。执行定义会创建函数对象并绑定名字，但不会执行函数体。第一次真正调用时，缩进内的代码才运行。函数体首行的<Term def="写在函数体开头的字符串，用来说明用途和调用约定，可通过 help 查看。">文档字符串（docstring）</Term>应说明目的，而不是复述每行代码。

```python
def greet_user(username):
    """Return a greeting; reject an empty name."""
    normalized = username.strip()
    if not normalized:
        raise ValueError("username must not be empty")
    return f"Hello, {normalized.title()}!"


message = greet_user("  ada  ")
assert message == "Hello, Ada!"
print(message)
```

定义中的 `username` 是<Term def="函数定义里接收输入的名字；实参则是调用时传入的实际值或对象。">形参与实参（parameter / argument）</Term>中的形参；调用中的 `"  ada  "` 是实参。上例的 `normalized` 是函数内部的局部名字，不会自动变成调用方的变量。实验 A 会把这些局部绑定画在调用帧里。

### 先绑定，再执行函数体

函数的<Term def="参数顺序、名字、默认值及调用限制共同形成的输入约定。">签名（signature）</Term>决定输入如何匹配。<Term def="按位置、关键字名称和默认值，把调用输入匹配到形参的过程。">参数绑定（argument binding）</Term>不是类型转换，也不会自动复制列表。

```python
def describe_pet(pet_name, animal_type="dog"):
    """Return one sentence describing a pet."""
    return f"{pet_name.title()} is a {animal_type}."


assert describe_pet("milo") == "Milo is a dog."
assert describe_pet("milo", "cat") == "Milo is a cat."
assert describe_pet(animal_type="cat", pet_name="milo") == "Milo is a cat."
```

位置实参按顺序匹配，关键字实参按名字匹配；因此倒序写两个关键字不影响结果。普通调用先写位置实参，再写关键字实参。普通位置参数中，有默认值的参数应排在必填参数后面。默认值只在对应输入**省略**时使用：显式传 `None` 不会自动改用 `"dog"`。

| 调用（沿用上面定义）                    | 函数体之前发生什么                   |
| --------------------------------------- | ------------------------------------ |
| `describe_pet("milo", pet_name="luna")` | 同一参数收到两次值，抛 `TypeError`   |
| `describe_pet(animal_type="cat")`       | 缺少必填 `pet_name`，抛 `TypeError`  |
| `describe_pet("milo", species="cat")`   | 未声明 `species`，抛 `TypeError`     |
| `describe_pet("milo", None)`            | 正常绑定，结果为 `"Milo is a None."` |

绑定失败时函数体不执行，但调用表达式中的实参表达式已经可能被求值；不要误读为“整个调用过程绝无副作用”。错误消息的具体措辞随 Python 版本而异，这里依赖的是异常种类与失败原因。

## 2. 返回通道：Return Values 与可选输入

### `return` 交付对象，`print` 只显示文字

函数的<Term def="函数结束后交给调用方、可赋值或继续计算的对象。">返回值（return value）</Term>由 `return` 给出，执行到它就立即离开当前函数；写 `return` 而不带表达式，或者走到函数末尾，都返回 `None`。`print` 写入屏幕输出通道，它本身也返回 `None`。因此“显示了结果”不等于“调用方收到了那个字符串”，正如实验 A 的两条通道。

```python
def show_name(name):
    print(name.title())


def format_name(name):
    return name.title()


shown = show_name("ada")  # 屏幕显示 Ada
saved = format_name("ada")
assert shown is None
assert saved == "Ada"
```

### 可选参数与返回字典

可选参数允许调用时省略，不表示返回值一定可有可无。下面用 `None` 表示“不提供年龄”，而 `0` 是有效年龄；不能用 `if age:` 混淆两者。返回字典让调用方继续取字段，而不是解析打印出来的文字。

```python
def build_person(first, last, age=None):
    """Return names and an age only when one is supplied."""
    person = {"first": first.title(), "last": last.title()}
    if age is not None:
        person["age"] = age
    return person


assert build_person("jimi", "hendrix")["first"] == "Jimi"
assert "age" not in build_person("jimi", "hendrix")
assert build_person("baby", "lee", age=0)["age"] == 0
```

这个接口约定 `first`、`last` 必有，`age` 可能缺省；不是要求所有返回字典键完全相同，而是要求变化有明确约定。若添加 `age: int | None = None` 这样的类型标注，它帮助阅读和静态检查，不会自动执行运行时类型校验。

### 在 `while` 中调用，不把交互塞进加工函数

将读入、退出判断放在调用方，`build_person` 只构造结果，便于测试。下面用有限数据代替键盘输入，可直接运行；改成命令行程序时，可把 `next(entries)` 换成 `input("First (q to quit): ")`。

```python
# 先执行上面的 build_person 定义。
entries = iter(["ada", "q"])
people = []
while True:
    first = next(entries)
    if first == "q":
        break
    people.append(build_person(first, "lovelace"))
assert people == [{"first": "Ada", "last": "Lovelace"}]
```

## 3. 对象身份：默认值与 Passing a List

### 默认值何时创建？

默认表达式在执行 `def` 时求值一次，不是在每次调用时求值。对于字符串、数字、`None` 等不可变对象，共用默认对象通常没有问题；对于<Term def="可以在不更换对象身份的情况下改变内部内容的对象，例如列表与字典。">可变对象（mutable object）</Term>，修改会被所有引用它的地方看到。

```python
def add_bad(item, items=[]):
    items.append(item)
    return items


a = add_bad("A")
b = add_bad("B")
assert a is b
assert a == ["A", "B"]  # a 不是第一次返回时的历史快照


def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items


x = add_item("A")
y = add_item("B")
assert x == ["A"] and y == ["B"]
assert x is not y
```

实验 B 的 `L0` 就是坏版本共用的列表；修复版本则为两次省略输入的调用分别创建 `L1`、`L2`。如果调用方显式传入同一个列表，修复版本仍会修改并返回它；`None` 修复的只是**默认对象共享**，不是禁止一切修改。

### 原地修改与重新绑定不同

将列表传入函数时，局部参数和调用方名字引用同一个对象。对参数执行 `append` 或 `pop` 会修改共享列表；执行 `items = []` 只是让局部名字转向另一对象，不会重新赋值调用方的名字。用 `is` 比较身份，用 `==` 比较内容。

```python
def edit(items):
    items.append("first")  # 修改原对象
    items = []             # 只重新绑定局部名字
    items.append("local")
    return items


source = []
result = edit(source)
assert source == ["first"]
assert result == ["local"]
assert result is not source
```

### 修改列表与防止修改

函数应说明是否消耗输入、是否保留顺序。下例的 `pop()` 会清空传入列表并倒序处理；换成外层切片后，原列表的槽位得到保留。也可以不用修改输入，直接创建新结果：

```python
def print_models(unprinted, completed):
    """Consume unprinted in reverse order into completed."""
    while unprinted:
        completed.append(unprinted.pop())


def render_models(models):
    """Return new labels in input order without changing models."""
    return [f"printed:{model}" for model in models]


models = ["case", "gear"]
completed = []
print_models(models[:], completed)
assert models == ["case", "gear"]
assert completed == ["gear", "case"]
assert render_models(models) == ["printed:case", "printed:gear"]
```

这里的<Term def="只新建外层容器、保留对内部元素对象引用的复制方式。">浅拷贝（shallow copy）</Term>足以隔离外层 `pop`，却不能隔离内部字典的修改。实验 B 的 `source[:]` 有新列表，却仍指向同一个 `D0`：

```python
source = [{"done": False}]
copy = source[:]
copy.append("A")
copy[0]["done"] = True
assert len(source) == 1
assert source is not copy
assert source[0] is copy[0]
assert source[0]["done"] is True
```

需要隔离到哪一层，取决于函数改到哪一层。对本章这种只有布尔字段的记录，可以逐条 `dict.copy()`；任意深度的嵌套结构不能靠再切一次片解决。

## 4. 可变参数：Arbitrary Number of Arguments

签名中的<Term def="用 *args 收集额外位置实参为元组，用 **kwargs 收集额外关键字实参为字典的机制。">可变参数（variadic arguments）</Term>适合数量不固定的输入。名字 `args`、`kwargs` 是惯例，真正起作用的是星号。位置实参先满足普通参数，其余才进入 `*toppings`；没有剩余时得到空元组。`**options` 接收未被显式参数消耗的关键字。

```python
def make_pizza(size, *toppings, **options):
    """Build an order; only crust is accepted as an extra option."""
    unknown = set(options) - {"crust"}
    if unknown:
        raise TypeError(f"unknown pizza options: {sorted(unknown)}")
    return {
        "size": size,
        "toppings": toppings,
        "crust": options.get("crust", "thin"),
    }


order = make_pizza(12, "mushroom", "onion", crust="thick")
assert order["toppings"] == ("mushroom", "onion")
assert make_pizza(12)["toppings"] == ()
# 调用处的 * 和 ** 是解包，方向与定义时相反。
parts = ["mushroom", "onion"]
settings = {"crust": "thick"}
assert make_pizza(12, *parts, **settings) == order
```

实参流向是 `12 → size`，两种配料 `→ toppings 元组`，`crust → options 字典`。在定义里收集，在调用里展开，是相反方向的操作；`*parts` 不是把整个列表作为一个配料传入。

若接口只允许固定的 `crust`，更清晰的签名是 `def make_pizza(size, *toppings, crust="thin"):`。`*toppings` 后的普通参数只能按关键字传入。固定业务字段优先显式声明，否则 `crsut` 这类拼写错误会被 `**options` 悄悄收下；本例通过允许名单拒绝它。

## 5. 模块边界：Storing Functions in Modules

### 两个文件建立名字来源

本章用含有 Python 定义的 `.py` 文件作为<Term def="具有自己的名字空间、可供其他代码导入的代码单元；本章使用 .py 文件模块。">模块（module）</Term>。<Term def="名字与其引用对象之间的对应关系；不同模块可以各自拥有同名函数。">名字空间（namespace）</Term>让 `pizza.make_pizza` 与别处的同名函数不冲突。保存下面两个文件到同一目录，然后运行 `python app.py`。

```python
# pizza.py
def make_pizza(size, *toppings):
    """Return an order without printing or modifying inputs."""
    return {"size": size, "toppings": toppings}


if __name__ == "__main__":
    print(make_pizza(12, "mushroom"))
```

```python
# app.py
import pizza
from pizza import make_pizza
from pizza import make_pizza as bake
import pizza as p

expected = {"size": 12, "toppings": ("mushroom",)}
assert pizza.make_pizza(12, "mushroom") == expected
assert make_pizza(12, "mushroom") == expected
assert bake(12, "mushroom") == expected
assert p.make_pizza(12, "mushroom") == expected
assert p is pizza
assert bake is pizza.make_pizza
print(expected)
```

`import pizza → pizza → make_pizza` 保留来源；`from pizza import make_pizza → make_pizza` 把函数名字直接引入当前模块。<Term def="用 as 给同一个导入对象另取的本地名字，并非复制对象。">别名（alias）</Term>分别可以用于函数 `bake` 和模块 `p`，上面的身份断言就是证据。

### 顶层执行、入口保护与星号导入

通常在同一解释器进程中，第一次导入执行模块顶层语句，后续导入复用缓存；不应理解为跨进程只执行一次。显式重新加载等情况不在本例范围内。直接执行 `python pizza.py` 时，`__name__` 为 `"__main__"`；被 `app.py` 导入时，它为 `"pizza"`。入口保护仅阻止缩进在它里面的演示代码，不阻止其他顶层语句执行。

`from pizza import *` 会把公开名字引入当前名字空间：若定义 `__all__` 则遵从它，否则通常排除以下划线开头的名字。它容易遮盖已有名字、隐藏来源，故避免作为常规写法。下划线是约定，不是禁止访问的安全屏障。

### Styling Functions：风格让调用约定看得见

函数与参数使用 `lowercase_with_underscores`；顶层函数之间空两行；四空格缩进。文档字符串说明返回、是否修改输入及失败约定。普通默认值和调用关键字的 `=` 两侧不加空格；**带类型标注且有默认值的形参则应加空格**：

```python
def repeat_label(text: str, count: int = 1) -> str:
    """Return repeated text without printing."""
    return text * count


assert repeat_label("go", count=2) == "gogo"
```

对照 `count: int = 1` 与调用中的 `count=2`，不要把“等号两侧永不留空格”当作风格规则。函数拆分应围绕可以命名、测试和复用的行为，不是机械地每两行提取一个函数。

## 常见误区：用反例修正直觉

<Callout type="trap" title="误区一：关键字只是注释，仍按书写顺序传入">
  倒序关键字调用仍正确，因为按名字绑定。相反，位置参数已经占用 `pet_name` 后又写
  `pet_name=...` 会在函数体执行前报错。观察实验 A
  的交叉线与执行次数，不要只看屏幕是否有文字。
</Callout>

<Callout type="trap" title="误区二：print 过结果，赋值就会得到它">
  `shown = show_name("ada")` 显示 Ada，却把 `None` 赋给
  `shown`。需要组合结果时返回它，再由外层决定是否打印；实验 A
  可以直接比较两个通道。
</Callout>

<Callout type="trap" title="误区三：默认列表每次都会新建，返回值也是快照">
  `items=[]` 在定义时创建一次；第一次返回的 `a` 与第二次返回的 `b`
  都引用它，所以后来追加 B 后，a 也能看到 B。用 `None`
  和连续两次调用的身份断言验证修复，而不只测试一次。
</Callout>

<Callout type="trap" title="误区四：传入 items[:] 就能完全防止修改原数据">
  浅拷贝只隔离外层槽位，内部字典仍共享。先声明函数是否修改输入、修改到哪一层，再决定只复制外层、逐项重建，还是保持只读；不要把可变对象传参误写成“自动复制”。
</Callout>

## 小结

- 绑定先于函数体；关键字按名匹配。
- `return` 交付对象；仅打印会隐式返回 `None`。
- 共享默认值与浅拷贝都要检查对象身份。
- 星号在定义时收集，在调用时展开。
- 模块与别名组织来源，不复制函数。

**问题 2 · 独立实现列表隔离。** 实验 B 的浅拷贝仍改动 `source[0]`。实现 `mark_copy(records)`，输入是只含字符串和布尔字段的字典列表，返回全部标为已完成的新记录；输入与返回记录都不能互相改动。另写一个使用 `None` 默认值的追加函数，证明连续省略输入时互不影响。目标对象图为 `source → L0 → D0(False)`，`result → L1 → D1(True)`，没有共用字典的连线。

<Answer>

```python
def mark_copy(records):
    result = []
    for record in records:
        copied = record.copy()
        copied["done"] = True
        result.append(copied)
    return result


def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items


source = [{"name": "case", "done": False}]
result = mark_copy(source)
assert source == [{"name": "case", "done": False}]
assert result == [{"name": "case", "done": True}]
assert result is not source and result[0] is not source[0]
result[0]["name"] = "gear"
assert source[0]["name"] == "case"
assert mark_copy([]) == []
a, b = add_item("A"), add_item("B")
assert a == ["A"] and b == ["B"] and a is not b
```

逐条 `copy()` 对题设的扁平记录足够；若字段是嵌套列表，此答案不再保证内部隔离。`add_item` 仍允许显式传入列表并修改它，这是不同的接口约定。

</Answer>
