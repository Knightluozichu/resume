## 为什么要把记录和操作放在一起

工厂里两辆车使用相同的生产图纸，但出厂后各有自己的里程和维修记录。给甲车登记一次保养，不应该把乙车的记录一起改掉。

若每次都分开保存车名、里程和更新规则，很容易把规则用到错误的车上。本章把这些记录和操作放在一起，同时看清哪些东西各车独有，哪些东西确实共用。

## 1. 创建和使用类：一次调用究竟作用于谁

### 图纸与实际对象

用来定义一类对象的数据和行为的代码叫 <Term def="描述一类对象具有哪些数据和行为的定义。">类</Term>（class）。调用类得到一个 <Term def="由类创建的具体对象，拥有自己的身份和状态。">实例</Term>（instance）。创建两次 `Car("A")`，即使名字相等，也不是同一辆车。实验里的两个圆圈表示两个对象，不是两个变量。

Python 创建实例后调用 <Term def="新实例创建之后执行的初始化方法，不负责返回新对象。">初始化方法</Term> `__init__` 初始化数据；它不是普通的“返回新车”函数，不应返回非 `None` 的值。下方完整的 `Car` 定义可保存为 `car.py`，在任何使用它的代码之前执行。

### 属性、方法和接收者

对象上以名字访问的数据叫 <Term def="通过对象点号访问的命名数据，例如每辆车自己的里程。">属性</Term>。`self.odometer = 0` 每初始化一次就给当前车设置默认里程；`self.services = []` 每次创建新的列表。不要把“每次都是零”和“所有车共用一份记录”混为一谈。

定义在类中、通过实例调用的函数称为 <Term def="通过实例调用时，自动接收该实例的函数行为。">方法</Term>。普通实例方法的首个参数按约定写作 <Term def="普通实例方法的第一个参数，指向这次调用的接收对象。">self</Term>，不是 Python 关键字。在后面的引用图第 3、4 步，调用路线会分别落到 A、B，仪表随之改变。

```python
# car.py
class Car:
    """A car with nondecreasing recorded mileage."""

    kind = "road vehicle"

    def __init__(self, name):
        self.name = name
        self.odometer = 0
        self.services = []

    def update_odometer(self, mileage):
        if mileage < self.odometer:
            raise ValueError("mileage cannot go backwards")
        self.odometer = mileage

    def increment_odometer(self, distance):
        if distance < 0:
            raise ValueError("distance must be nonnegative")
        self.update_odometer(self.odometer + distance)

    def fill_gas_tank(self):
        return "gas tank filled"
```

这里先检查再赋值，所以拒绝更新不会留下半改的里程；`increment_odometer` 把增量转换成总里程，再复用更新规则。示例假设输入是普通非负整数，未实现字符串、浮点特殊值等完整输入校验。

通过 `a.update_odometer` 取出方法时，Python 会记住接收对象，这叫 <Term def="把类中的函数和本次接收实例配成可调用的方法对象。">方法绑定</Term>。对这里的普通方法，`a.update_odometer(40)` 相当于 `Car.update_odometer(a, 40)`。取出方法暂存起来也不会丢失接收者。

```python
# 在 Car 定义之后执行
a, b = Car("A"), Car("B")
alias = a
update = alias.update_odometer
assert update.__self__ is a
update(40)
b.increment_odometer(20)
assert alias is a and a is not b
assert (a.odometer, b.odometer) == (40, 20)
```

`alias = a` 只增加一个指向 A 的名字，没有运行 `Car(...)`。这种指向关系叫 <Term def="名字或属性指向某个对象的关系；赋值不意味着复制对象。">引用</Term>。`is` 检查是不是同一个对象；值相同不是身份相同。

## 2. 修改属性：独立状态与共享状态

### 直接赋值、更新总值、增加差量

修改属性有三种常见写法。直接赋值简单，却绕过你写在方法里的检查；更新方法接收新总值；递增方法接收差量。Python 不会因为类里存在更新方法，就禁止别人直接给属性赋值。

```python
# 接着上一段执行：A=40，B=20
b.odometer = 30                 # 直接写总值
b.update_odometer(50)           # 检查后写总值
b.increment_odometer(5)         # 在原值上加5
assert b.odometer == 55
for invalid in (54, -1):
    before = b.odometer
    try:
        b.update_odometer(invalid)
    except ValueError:
        pass
    else:
        raise AssertionError("rollback was accepted")
    assert b.odometer == before
b.update_odometer(55)           # 相等合法；没有倒退
assert a.odometer == 40
```

图中最后一步拒绝把 A 从 40 改回 10：指针不回退，并出现拒绝标记。这不是 Python 自动提供的保护，而是 `if` 和 `raise` 实现的规则。

### 为什么两辆不同的车也可能共用列表

定义在类体里的数据是 <Term def="定义在类对象上的属性；实例没有同名属性时可以从类中查到它。">类属性</Term>。`Car.kind` 适合表达共同分类。列表若放在类体里，则也只有一份；新建两个实例不会自动复制这份列表。看下面的错误模式，再在实验中对比指向列表的连线。

```python
class SharedCar:
    services = []              # 错误：每辆车的维修记录不应共用

x, y = SharedCar(), SharedCar()
x.services.append("check")
assert x is not y
assert x.services is y.services
assert y.services == ["check"]
x.services = ["private"]       # 在x上建立同名属性，不是改类属性
assert x.services == ["private"]
assert y.services == SharedCar.services == ["check"]
```

对这里的普通数据属性，读取先找实例上的同名属性，没有才找类；`append` 修改已经找到的列表，而 `x.services = ...` 给实例设置同名属性。修复本例应在 `__init__` 中使用 `self.services = []`，不要在类体或可变默认参数里共用列表。

## 3. 继承：沿用父类能力，但不要漏掉初始化

当电动车仍应具备汽车的里程操作时，可以使用 <Term def="子类沿用并扩展父类行为的关系，表示一种更具体的同类对象。">继承</Term>。`ElectricCar(Car)` 声明电动车是汽车的一种；子类没定义的普通方法可沿父类查找。它不是把父类对象塞进子类对象，里程仍在同一辆电动车实例上。

子类定义自己的 `__init__` 后，不会自动再执行父类的版本。用 <Term def="按方法查找顺序从当前类之后继续查找实现的代理。">super()</Term> 调用下一份初始化实现。本章单继承情形中就是 `Car.__init__`，传入的仍是同一个 `self`。不要把它泛化成“永远直接找父类”，多继承的查找顺序更复杂。

子类也能提供同名方法来 <Term def="子类提供同名方法，使普通实例调用采用子类的行为。">重写</Term> 父类行为。电动车的加油操作返回“不需要油箱”，而普通车保持原行为。下面同一段代码同时展示继承调用与电池持有关系。

## 4. 组合：电池是车的部件，不是一种车

将另一个实例保存在属性中叫 <Term def="让对象持有另一个对象并使用其能力，表示拥有部件的关系。">组合</Term>。`ElectricCar` 继承 `Car`，却通过 `self.battery` 持有 `Battery`；读取容量要经过 `ev.battery.capacity_kwh`。电池的容量归电池对象，汽车的里程归汽车对象。两者都可以独立修改，不必塞进庞大的车辆类。

```python
# electric_car.py（与car.py放在同一目录）
from car import Car


class Battery:
    """An independently replaceable battery."""

    def __init__(self, capacity_kwh=60):
        self.capacity_kwh = capacity_kwh

    def describe(self):
        return f"{self.capacity_kwh} kWh"


class ElectricCar(Car):
    """A car that owns a battery instead of using a gas tank."""

    def __init__(self, name):
        super().__init__(name)
        self.battery = Battery()

    def fill_gas_tank(self):
        return "no gas tank"
```

按调用关系读代码：`ElectricCar("E")` → 子类初始化 → `super().__init__` 设置同一实例的名字和里程 → `Battery()` 创建第二个对象 → `self.battery` 指向它。`fill_gas_tank` 的普通调用命中子类版本；里程更新则沿用父类版本。以断言验证比仅看类名更可靠：

```python
# 在前述定义可用后执行
ev, other_ev = ElectricCar("E"), ElectricCar("F")
ev.increment_odometer(12)
ev.battery.capacity_kwh = 80
assert isinstance(ev, Car)
assert ev.odometer == 12
assert other_ev.odometer == 0
assert other_ev.battery.capacity_kwh == 60
assert ev.battery is not other_ev.battery
assert ev.fill_gas_tank() == "no gas tank"
assert Car("G").fill_gas_tank() == "gas tank filled"
```

## 5. 导入类、使用标准库与编码风格

### 把定义与使用分开

一个可导入的 Python 文件是 <Term def="可由import加载的Python代码单元；本章用.py文件组织类定义。">模块</Term>。先保存前面的 `car.py` 和 `electric_car.py`，再在同一目录创建 `main.py`，从该目录运行 `python3 main.py`。不要把测试过程散落在类定义文件的顶层，否则首次导入时也会执行它们。

下列程序覆盖导入单个类、同模块多个类、整个模块以及别名；它们是展示语法的对照，实际项目只选清楚一致的一种，不必重复导入。

```python
# main.py
from car import Car
from electric_car import Battery, ElectricCar
import electric_car
from electric_car import ElectricCar as EV

fleet = [Car("A"), ElectricCar("E"), EV("F")]
spare = Battery(80)
other = electric_car.ElectricCar("G")
assert isinstance(fleet[1], Car)
assert isinstance(other.battery, Battery)
assert spare.describe() == "80 kWh"
assert fleet[1].fill_gas_tank() == "no gas tank"
print([car.name for car in fleet])  # ['A', 'E', 'F']
```

`import electric_car` 绑定模块名，之后写 `electric_car.ElectricCar`；`from ... import ...` 直接绑定类名；`as EV` 只是换一个本地名字，不会生成新类。不要用 `from ... import *`，它隐藏名称来源并可能覆盖已有名字。当前依赖方向是 `main.py` → `electric_car.py` → `car.py`，不要让 `car.py` 反过来导入 `main.py`。

### 标准库 random 也是现成能力

随 Python 安装提供的模块构成 <Term def="随Python提供的模块集合，不必为这些模块另装第三方包。">标准库</Term>。例如 `random` 提供 `randint` 和 `choice`，也提供能拥有独立随机状态的 `Random` 类。本章使用后者，避免修改整个模块共用的随机状态。

```python
from random import Random

rng = Random(9)
roll = rng.randint(1, 6)          # 包含1与6两个端点
picked = rng.choice(["A", "B"])  # 序列必须非空
assert 1 <= roll <= 6
assert picked in {"A", "B"}
replay = Random(9)
assert (roll, picked) == (
    replay.randint(1, 6), replay.choice(["A", "B"])
)
```

相同种子、相同版本和相同调用顺序便于重现实验；不要把某个随机输出硬编码成跨版本承诺。`choice([])` 会报错，`random` 也不应用来生成密码或安全令牌。本段体现“导入已有能力，再创建并使用对象”，而非每次都自己重写类。

### 风格让对象关系容易读

按 PEP 8，类名采用 `ElectricCar` 这样的 CapWords，方法、属性和模块用 `update_odometer`、`capacity_kwh`、`electric_car.py` 这样的下划线命名。实例方法首参数写 `self`；模块级类之间通常空两行，类内方法之间空一行，简短文档字符串说明职责。前面的三个文件就是对照，不要命名为 `random.py` 遮住标准库。

## 常见误区：观察现象，定位原因

<Callout type="trap" title="两个名字不是两辆车">

**现象 →** 改 `alias.odometer`，`a.odometer` 也变了。<br />
**原因 →** `alias = a` 只增加引用，二者指向同一对象。<br />
**修法 →** 需要独立车就再次调用 `Car(...)`；实验中看名字连线是否汇合。

</Callout>

<Callout type="trap" title="不同实例仍可能共享维修记录">

**现象 →** 给 A 追加记录，B 的记录也增加。<br />
**原因 →** 类体中的 `services = []` 只创建一个列表。<br />
**修法 →** 在 `__init__` 中写 `self.services = []`；打开实验错误模式看两条列表引用汇合。

</Callout>

<Callout type="trap" title="有检查方法不代表属性不可直接改">

**现象 →** `a.odometer = -1` 依然能成功。<br />
**原因 →** 直接赋值没有调用 `update_odometer` 的检查。<br />
**修法 →** 约定更新入口，并测试倒退、相等、增长与负增量；不要宣称普通公开属性已强制受保护。

</Callout>

<Callout type="trap" title="子类初始化不会自动叠加">

**现象 →** 电动车更新里程时报属性不存在。<br />
**原因 →** 子类写了自己的 `__init__`，却漏调父类初始化。<br />
**修法 →** 本例先 `super().__init__(name)` 再创建电池；不要让电池继承汽车来补里程。

</Callout>

## 小结

- 名字引用对象，普通方法绑定本次接收实例。
- 每实例初始化列表，方法检查通过后再更新里程。
- 电动车继承汽车、组合电池；模块组织这些定义。

**问题 3：独立实现可换电池的配送车。** 目标状态是两辆车里程各为 10 和 0；只把第一辆的电池从 60 换成 80 kWh，第二辆仍为 60，第一辆里程不清零。将新类保存为 `delivery_car.py`，通过导入实现，不复制汽车的方法。

**小分问：代码审查。** 有人把下面的类存成 `random.py`，紧贴上一模块级类，类内新增方法也不留空行。逐项指出应改的名字与间隔：哪些只是风格问题，哪一项可能让同目录新进程中的 `import random` 导入错误模块？

```python
class delivery_car(ElectricCar):
    def ReplaceBattery(self, battery): self.battery = battery
```

<Answer>

继承保留里程行为，组合允许替换电池。这里只接受一个已经构造好的电池，调用者决定是否共用它。

```python
# delivery_car.py
from electric_car import ElectricCar


class DeliveryCar(ElectricCar):
    """An electric car with a replaceable battery."""

    def replace_battery(self, battery):
        self.battery = battery
```

在同一目录运行以下测试。若给两辆车传同一块电池，它们会共享电池；此处显式创建新电池验证独立状态。

```python
from delivery_car import DeliveryCar
from electric_car import Battery

first, second = DeliveryCar("D1"), DeliveryCar("D2")
first.increment_odometer(10)
first.replace_battery(Battery(80))
assert (first.odometer, second.odometer) == (10, 0)
assert first.battery.capacity_kwh == 80
assert second.battery.capacity_kwh == 60
assert first.battery is not second.battery
assert first.fill_gas_tank() == "no gas tank"
```

小分问的修正就是上面的 `DeliveryCar.replace_battery`：`delivery_car` 是合法标识符，但类应采用 CapWords，改为 `DeliveryCar`；`ReplaceBattery` 改为下划线命名 `replace_battery`，调用处也要同步改名。方法体另起缩进行；两个模块级类之间通常留两行空行，类内两个方法之间留一行。这些改善可读性，不应误判成 Python 一定无法解析。

文件名应为 `delivery_car.py`，不能因为 `random.py` 也是小写就判合格。在该目录运行新脚本时，本地同名模块可能先于标准库被找到；若它只定义配送车，`random.Random` 就不存在。用新进程运行下列探针：错误文件名下先看到本地路径，再得到 `AttributeError`；改名后重新启动进程，路径应指向标准库，断言通过。仅在旧进程里再 `import` 一次可能仍用缓存，不能作为修复证据。

```python
import random

print(random.__file__)
rng = random.Random(9)
assert 1 <= rng.randint(1, 6) <= 6
```
