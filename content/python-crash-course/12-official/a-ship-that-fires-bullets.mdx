## 先做一艘能动、能停的飞船

先把屏幕想成一张小地图：飞船从底部中央出发，只能左右移动；子弹沿直线向上飞。我们暂时不放敌人，只检验移动、停止、发射和退出。

如果一开始就铺满敌人、分数和爆炸效果，飞船不动时便很难找到原因。本章每加一种行为就观察一次画面，让问题留在最小范围内。

## 五个机制：把一次按键变成可见的一帧

### 1. 游戏循环：每轮都交付一幅完整画面

Pygame 是 Python 的游戏与多媒体库。它提供窗口、输入和绘图能力，却不会替你决定先移动还是先画。

<Term def="反复读取输入、更新对象并展示画面的程序循环，一轮通常对应一帧。">游戏循环</Term>
负责这个顺序：读取事件 → 更新飞船 → 更新并清理子弹 → 清背景并绘制对象 → 展示画面
→ 限制循环速度。

`pygame.display.set_mode()` 创建窗口和屏幕绘图表面（`Surface`）；`fill()` 清除上一帧，`blit()` 把飞船表面贴到屏幕，`display.flip()` 展示本帧。漏掉清背景会留下拖影，漏掉展示则可能一直看不到更新。下方实验中虚线残影是刻意的教学标记，不是运行项目的实际拖影。

`Clock.tick(60)` 每轮调用一次，用等待来限制最高帧率，**不保证每秒恰好 60 帧**，也不自动移动对象。本例速度是每帧 2.5 像素：接近 60 帧/秒时约为 150 像素/秒，只有 30 帧/秒时约为 75。按秒计速需要再用经过时间相乘，不在本章暗中混入。实验用手动帧数替代等待，因果关系相同，但不是实际帧率测量器。

### 2. 游戏窗口与用户输入（Game Window and User Input）：消息必须持续取走

<Term def="保存窗口关闭、按键按下和松开等消息，等待程序读取的有容量限制的队列。">事件队列</Term>
是操作系统与游戏之间的收件箱。`pygame.event.get()` 取走待处理消息；`QUIT`
代表关闭请求，`KEYDOWN` 和 `KEYUP` 分别代表按下与松开。

每帧都要处理队列。Pygame 官方文档说明队列有容量上限，满时新消息会被丢弃，长期不处理也可能让系统把程序视为无响应。在事件处理函数里再写一个“按住期间一直循环”的内循环，会阻断后续松键和关闭消息。

实验底部轨迹把“事件”与“位移”分开：只点“右键”时箭头点亮，飞船不动；推进一帧后位置才变。这正是在区分消息处理和画面更新。

窗口接收输入，但屏幕图像不会直接接收“右移命令”。一次按键动作（keypress）先成为消息，消息中的 `type` 表示发生了什么，`key` 才表示哪一个键。比如 `KEYDOWN` 是“按下”，不是“右键”；右键由 `K_RIGHT` 指定。只有键盘事件分支才读取 `event.key`，因为关闭事件不承诺有这个属性。

| 对象或阶段 | Python 中的对应 | 能改变什么，不能代替什么 |
| --- | --- | --- |
| 游戏窗口及屏幕绘图表面 | `display.set_mode()` 返回的 `screen` | 提供显示目标，不维护飞船方向 |
| 事件处理循环（event loop） | `_check_events()` 内的 `for event in pygame.event.get()` | 消费消息并修改标志，不执行持续位移 |
| 飞船更新 | `Ship.update()` | 读取标志和速度，计算下一帧坐标 |
| 画面展示 | `_draw()` 最后的 `display.flip()` | 提交已画好的画面，不读取按键或更新坐标 |

事件处理循环是游戏循环中的一个阶段，不是另一个永不退出的循环。**若同一帧更新前已经读到了右键按下和松开，最终标志为假，该帧不会移动**；这不是丢消息，而是本例按最终输入状态更新的结果。后面的“输入阶段观测”会真实投递这两个事件验证它，并检查绘制不会偷偷移动飞船。


### 3. 移动标志：按下开始，松开停止

<Term def="记录某个方向是否仍处于按住状态的布尔值，每帧更新时都读取它。">移动标志</Term>
把一次按键消息变成持续行为。按下右键设 `right = True`，松开设回
`False`；更新时计算 `int(right) -
int(left)`，再乘每帧速度。两边都按住时相互抵消，这是本例明确选择的规则。

若把位移写在 `KEYDOWN` 分支里，飞船可能只跳一步，或依赖系统重复按键，速度就不再由游戏控制。正确方案把“修改方向标志”留在事件阶段，把“修改位置”放进每帧更新阶段。失去窗口焦点也清空标志，避免切走窗口时漏收松键而一直滑行。实验提供相同的安全停止，以及只针对松键的故障开关。

### 4. 矩形边界：精确积累，整数绘制

<Term def="Pygame 的 Rect 用整数坐标描述对象的位置和尺寸，可据此摆放对象与约束屏幕边界。">矩形边界</Term>
不是飞船的美术轮廓，而是包住它的框。坐标原点在窗口左上方，向右是 x 增大，向下是
y 增大。`rect.midbottom` 指底边中点，用它可将飞船放在底部中央。

`Rect` 只存整数。若每帧把 0.25 像素直接加回整数框，小数就无法累积。因此另存 `self.x = float(self.rect.x)`，每帧先更新浮点数，再显式 `int(self.x)` 写回矩形。以实验的 2.5 为例，位置 147 → 149.5 → 152，而画出的左边缘为 147 → 149 → 152。

宽 330、飞船宽 36，所以左边缘合法范围为 0 到 294。先把浮点位置限制在此范围，再同步矩形；若只限制矩形，隐藏的浮点位置仍可能跑到屏幕外，反向时要等很久才回来。实验里的细线与虚框对应这两份位置。

### 5. 精灵组：发射、更新和离场是一条链

<Term def="Group 保存多个 Sprite 游戏对象，可批量更新和绘制，并在对象离场时将其移除。">精灵组</Term>
用于管理子弹。每颗子弹是一个
`Sprite`，保存图像、矩形及浮点纵坐标；`Group.update()` 逐个调用它们的
`update()`，`Group.draw()` 使用它们的 `image` 和 `rect` 绘制。

按空格时先检查活动数量是否小于 3，再从飞船顶部生成子弹。向上飞要减小 y。清理条件是 `rect.bottom <= 0`，不是 `rect.top <= 0`：顶端刚出界时尾部仍可见。遍历 `group.copy()` 再 `kill()` 可避免边遍历原组边修改它；`kill()` 把精灵从所属组移除，不等于强行销毁所有 Python 引用。

实验的三格槽代表当前组中的对象数，不是总发射次数。同一位置连续发射的子弹可能重叠，看数量应同时看槽位。若从不清理，即使子弹看不见也会占满三格，无法再次发射。

## 先预测，再在空间中逐帧验证

1. **先预测**：重置后按右键，位置会立刻改变吗？推进两帧，读数应为 149.5、152。松开右键再推进，位置不变。
2. **试一试边界**：重置后锁定右键，连续推进三次 20 帧。位置停在 294，而不是越过右边。换成左键推进一帧，应立即回到 291.5。
3. **观察子弹变化**：重置后连发四次，只有三颗被接纳。推进两次 20 帧后全部清理，第五次发射就能成功。
4. **制造一个真错误**：开启“忽略松键”，按右键、推进、松开、再推进，飞船仍移动。点击“释放方向”安全停止；“完整重置”还会恢复故障开关、帧数、位置、对象和计数。

### A. 设置类（Settings Class）：把调节项收在一起

`Settings` 只保存参数，不处理输入或画图。窗口、飞船和子弹都从这里读取速度与尺寸，避免多个文件各写一份数值。这里用一个文件展示完整项目，类的职责仍然独立。

设置类回答“应该多快、多大、允许几颗”，不回答“当前在哪里、正在按哪个键”。`AlienInvasion` 创建一个设置对象，并把同一对象交给飞船；所以更改 `game.settings.ship_speed` 后，下一次 `Ship.update()` 就会读到新值。位置 `x` 和方向 `right` 则属于飞船，不能塞进所有对象共用的设置里。

作者配套的设置类在 `__init__()` 中给实例赋值；本例把不可变的数字和颜色元组写成类默认值来缩短代码。两者不应混淆：`game.settings.ship_speed = 0.25` 给这个实例增加同名属性，并不把 `Settings.ship_speed` 的默认值也改掉。后面的责任观测会同时检查当前设置与新建设置，验证这一区别。


```python
import pygame


class Settings:
    width, height = 330, 360
    fps = 60
    background = (24, 29, 38)
    ship_color = (104, 195, 220)
    bullet_color = (238, 226, 178)
    ship_speed = 2.5
    bullet_speed = 8.0
    bullets_allowed = 3
```

### B. 飞船类（Ship Class）：自己生成资产并持有状态

`Surface((36, 28), pygame.SRCALPHA)` 创建透明图像，随后在其中画出飞船，不需要任何下载资源。矩形底边中点放在距窗口底部 18 像素的位置，于是顶部为 314。`self.x` 是计算位置，`rect.x` 是显示位置。

飞船类把外观 `image`、摆放位置 `rect`、计算位置 `x` 和移动标志收在同一个对象里。传入 `game` 是为了取得现成的屏幕与设置引用，**不是再创建一个窗口**。`image.get_rect()` 返回与图像同尺寸的新矩形，初始左上角为 `(0, 0)`；接着设置 `midbottom` 才将它移到屏幕底部。这里不能误用整个屏幕的矩形，否则宽度会变成 330，飞船将没有横向移动空间。

持续移动（continuous movement）的职责也分两层：游戏类解释按键消息，飞船类在每次更新中执行位移。`Ship.draw()` 只读取已确定的位置。实验中方向箭头对应移动标志，细线对应 `x`，虚框对应 `rect`；观察“按下点亮箭头、推进才移动轮廓”，就是在观察这两个类的交接，而不是两处都计算一次位移。


```python
class Ship:
    def __init__(self, game):
        self.screen = game.screen
        self.settings = game.settings
        self.image = pygame.Surface((36, 28), pygame.SRCALPHA)
        points = [(18, 0), (34, 24), (24, 20),
                  (18, 27), (12, 20), (2, 24)]
        pygame.draw.polygon(self.image, self.settings.ship_color, points)
        self.rect = self.image.get_rect()
        self.rect.midbottom = (self.settings.width // 2,
                               self.settings.height - 18)
        self.x = float(self.rect.x)
        self.left = False
        self.right = False
```

若以后替换为位图，才需要提供真实图片文件，并用 `Path(__file__).resolve().parent / "images" / "ship.bmp"` 构造路径，而不是依赖启动时所在目录。加载成功后也要重新取得图像矩形，边界上限应继续使用实际图像宽度。

### C. 飞船更新与绘制：追加在 Ship 类中

这段保留四个空格的类内缩进。先从两个方向标志得到位移，再限制浮点位置，最后同步整数框。`draw()` 只展示，不偷偷改变坐标，才方便逐帧验证。

```python
    def update(self):
        direction = int(self.right) - int(self.left)
        self.x += direction * self.settings.ship_speed
        max_x = self.settings.width - self.rect.width
        self.x = max(0.0, min(max_x, self.x))
        self.rect.x = int(self.x)

    def draw(self):
        self.screen.blit(self.image, self.rect)
```

### D. 子弹类：只管自己的位置

子弹继承 `pygame.sprite.Sprite`，先初始化父类，才能参与组管理。子弹图像为 4×10 像素，底边与飞船顶边相接；`update()` 只负责向上移动。是否允许生成、何时离组，交给拥有子弹组的游戏对象。

```python
class Bullet(pygame.sprite.Sprite):
    def __init__(self, game):
        super().__init__()
        self.speed = game.settings.bullet_speed
        self.image = pygame.Surface((4, 10))
        self.image.fill(game.settings.bullet_color)
        self.rect = self.image.get_rect()
        self.rect.midbottom = game.ship.rect.midtop
        self.y = float(self.rect.y)

    def update(self):
        self.y -= self.speed
        self.rect.y = int(self.y)
```

### E. 游戏类：持有对象并协调循环

游戏对象创建窗口、计时器、飞船和组。`run_game()` 不塞入各对象的细节，只安排阶段。收到退出请求后直接结束循环；`finally` 保证循环中出错或退出时释放 Pygame 资源。

```python
class AlienInvasion:
    def __init__(self):
        pygame.init()
        self.settings = Settings()
        size = (self.settings.width, self.settings.height)
        self.screen = pygame.display.set_mode(size)
        pygame.display.set_caption("Ship and Bullets")
        self.clock = pygame.time.Clock()
        self.ship = Ship(self)
        self.bullets = pygame.sprite.Group()
        self.running = True

    def run_game(self):
        try:
            while self.running:
                self._check_events()
                if not self.running:
                    break
                self.ship.update()
                self._update_bullets()
                self._draw()
                self.clock.tick(self.settings.fps)
        finally:
            pygame.quit()
```

### F. 输入处理：追加在 AlienInvasion 类中

本例不启用按键重复；空格一次按下发射一次，不实现按住连射。左右键按下和松开都会走方向分支，而发射只响应按下。窗口失焦时将两个标志清空；关闭按钮和 Esc 都能退出。

```python
    def _check_events(self):
        for event in pygame.event.get():
            if event.type == pygame.QUIT:
                self.running = False
            elif event.type == pygame.WINDOWFOCUSLOST:
                self.ship.left = self.ship.right = False
            elif event.type in (pygame.KEYDOWN, pygame.KEYUP):
                down = event.type == pygame.KEYDOWN
                if event.key == pygame.K_LEFT:
                    self.ship.left = down
                elif event.key == pygame.K_RIGHT:
                    self.ship.right = down
                elif down and event.key == pygame.K_SPACE:
                    self._fire_bullet()
                elif down and event.key == pygame.K_ESCAPE:
                    self.running = False
```

### G. 子弹和画面：继续追加在 AlienInvasion 类中

`_fire_bullet()` 在添加前检查容量。更新后遍历组的副本并清理；若一颗子弹本帧才离场，同一帧较早到达的发射请求仍可能被拒绝——因为事件处理发生在清理之前。下一次按下空格才能使用释放的名额。

```python
    def _fire_bullet(self):
        if len(self.bullets) < self.settings.bullets_allowed:
            self.bullets.add(Bullet(self))

    def _update_bullets(self):
        self.bullets.update()
        for bullet in self.bullets.copy():
            if bullet.rect.bottom <= 0:
                bullet.kill()

    def _draw(self):
        self.screen.fill(self.settings.background)
        self.ship.draw()
        self.bullets.draw(self.screen)
        pygame.display.flip()
```

绘制时飞船先于子弹，保证子弹覆盖在飞船前方。本例没有碰撞判定，所以组仅用于批量更新、绘制和移除，而不是用来推断“命中”。

### 责任观测：共享设置引用，不等于所有参数都会自动生效

先预测：创建子弹后再修改设置中的子弹速度，旧子弹会跟着变速吗？本例飞船每帧读取 `self.settings.ship_speed`，但子弹在构造时把速度复制到 `self.speed`，因此**新设置影响旧飞船，却只影响新建子弹**。同理，修改窗口宽度的配置值不会自动重建显示表面；动态改窗口还必须重新创建窗口、重新对齐位置与边界，不能只改一个数字。

完成 A–H 后，将下段单独保存为同目录的 `probe_ownership.py`，不要追加到游戏文件。运行 `python probe_ownership.py`。它使用真实对象检查职责，输出应为 `147.25 147 2.5`、`8.0 3.0`、`(330, 360) 400`；最后一个结果说明配置值和已创建窗口不是同一个状态。

```python
import pygame
from alien_invasion import AlienInvasion, Bullet, Settings

game = AlienInvasion()
try:
    assert game.ship.settings is game.settings
    assert game.ship.screen is game.screen
    assert game.ship.rect.size == (36, 28)
    game.settings.ship_speed = 0.25
    game.ship.right = True
    game.ship.update()
    assert (game.ship.x, game.ship.rect.x) == (147.25, 147)
    assert Settings().ship_speed == Settings.ship_speed == 2.5
    print(game.ship.x, game.ship.rect.x, Settings().ship_speed)
    old_bullet = Bullet(game)
    game.settings.bullet_speed = 3.0
    new_bullet = Bullet(game)
    assert (old_bullet.speed, new_bullet.speed) == (8.0, 3.0)
    print(old_bullet.speed, new_bullet.speed)
    game.settings.width = 400
    assert game.screen.get_size() == (330, 360)
    print(game.screen.get_size(), game.settings.width)
finally:
    pygame.quit()
```

该观测故意制造“配置宽度与真实窗口不一致”后立即退出，不继续执行移动；正常项目应在创建窗口前确定尺寸。若希望已经发出的子弹也响应调速，应让子弹保留设置引用并在 `update()` 中读取速度。这是行为设计上的修改，不是 Pygame 会自动完成的工作。

### 输入阶段观测：一个事件批次不一定产生一次移动

将下面代码另存为 `probe_input.py`，运行 `python probe_input.py`。预期输出为 `False 147.0 147`。这里在实验开始时清空窗口启动消息，以隔离合成事件；**不要把清空队列复制进正常游戏循环**，否则可能丢掉真实的退出和松键消息。

```python
import pygame
from alien_invasion import AlienInvasion

game = AlienInvasion()
try:
    pygame.event.clear()
    before = (game.ship.x, game.ship.rect.topleft)
    down = pygame.event.Event(pygame.KEYDOWN, key=pygame.K_RIGHT)
    up = pygame.event.Event(pygame.KEYUP, key=pygame.K_RIGHT)
    assert down.type == pygame.KEYDOWN and down.key == pygame.K_RIGHT
    pygame.event.post(down)
    pygame.event.post(up)
    game._check_events()
    assert not game.ship.right
    assert not pygame.event.peek([pygame.KEYDOWN, pygame.KEYUP])
    game.ship.update()
    assert (game.ship.x, game.ship.rect.topleft) == before
    game._draw()
    assert (game.ship.x, game.ship.rect.topleft) == before
    print(game.ship.right, game.ship.x, game.ship.rect.x)
finally:
    pygame.quit()
```

这个例子验证了输入阶段确实消费消息，更新阶段只看到最终为假的方向标志，绘制阶段不更改位置。若想在浏览器实验中对照，重置后依次按下、松开右键，期间不推进，最后再单步：箭头先亮后灭，飞船仍在 147。若要捕捉再短的点击也移动一下，那是另一种输入设计，需要另存“本帧曾按下”的信息，不能假称当前标志方案已经支持。


## 四种真实错误与定位方法

<Callout type="trap" title="松开了，飞船仍在移动">

**现象 →** 松键后继续漂移。

**原因 →** `KEYUP` 没清空方向标志，或失焦时漏收事件。

**修法 →** 在松键和失焦时清理标志；用实验“忽略松键”开关复现，再比较正确模式。

</Callout>

<Callout type="trap" title="调慢后不动，撞墙后反向迟钝">

**现象 →** 速度设 0.25 后无法积累位移，或撞墙后要等很久才返回。

**原因 →** 只在整数框里累加，或只限制框而未限制浮点位置。

**修法 →** 先更新并钳制浮点位置，再执行 `rect.x = int(self.x)`。

</Callout>

<Callout type="trap" title="只开三枪，以后永远不能再发射">

**现象 →** 屏幕没有子弹，组里却仍有三颗。

**原因 →** 离场后未移除；不可见不等于不存在。

**修法 →** 每帧更新后遍历组副本，以 `bottom <= 0` 清理；不要用顶端出界作为完全离场条件。

</Callout>

<Callout type="trap" title="窗口无响应，或关闭请求无效">

**现象 →** 窗口出现了，但系统提示无响应。

**原因 →** 主循环未处理事件，或事件分支中的内循环阻塞了后续消息。

**修法 →** 每帧取事件，把持续移动改成标志；确认代码能走到绘制和帧率限制阶段。

</Callout>

## 小结与练习

- 输入、更新、清理、绘制每帧各司其职。
- 持续移动靠标志，松键和失焦都应停止。
- 浮点积累，整数绘制；子弹离场才释放名额。

**问题 2：** 修改运行项目中的 `ship_speed = 0.25`，并把浏览器组件的 `SHIP_WORLD.shipSpeed` 同样改为 0.25。预测从 x=147 开始连续右移四帧的结果。再把更新错误地写成 `self.rect.x = int(self.rect.x + 0.25)`，为何失败？若只给 `game.settings.ship_speed` 赋值而不修改类默认值，现有飞船和新建的 `Settings()` 分别会读到什么？

</Answer>
