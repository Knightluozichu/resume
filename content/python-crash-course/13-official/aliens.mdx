## 先把队伍排好，再让整队行动

在一张平面地图上安排许多敌人，不只是多画几个角色。间距要一致，边缘的角色走不动时，其他角色也要一起转向，否则整队很快散开。

我们还要判断谁击中了谁，以及什么时候重新开局。如果每个角色都独立扣生命，一次撞击可能结束整场游戏。本章把“单个角色的位置”和“整场游戏的决定”分开管理。

## 五个概念，组成一条更新链

### 1. 外星人对象：形状和位置分开

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center [&_a]:justify-center"><Term def="继承 pygame.sprite.Sprite 的游戏对象，可被组统一更新、绘制和移除。">精灵</Term></span>不是一张图片本身。Pygame 的组绘制需要对象提供 `image` 和 `rect`；`Alien`
类负责生成自己的外观与位置，舰队的共同方向则由外层维护。

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center [&_a]:justify-center"><Term def="用整数坐标记录左、上、宽、高的轴对齐区域；右边和下边不包含在区域内。">矩形</Term></span>对应 `pygame.Rect`。`rect.x` 是左边，`rect.right = rect.x +
rect.width`，纵坐标向下增加。它参与碰撞，与画出来的眼睛、透明角落不是一回事。下方实验的蓝框就是实际检测区域，不是装饰边框。

### 2. 舰队布局：每只外星人占一个固定槽位

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center [&_a]:justify-center"><Term def="按行列坐标排列多个精灵，并让它们共享水平移动和下降规则的队形。">舰队布局</Term></span>先决定容量，再创建对象。本章固定外星人宽 24、高 18，飞船高
16；左右各留一个外星人宽度，每个槽位含一个物体和一个同宽空隙。

本章选择**完整槽位法**，并非逐字复现作者第三版的 `while` 循环。即使尾部还能挤下半个槽位，也不再放置外星人。这样容量公式与创建循环严格一致。

- 横向可用空间：`W - 2 × 24`；列数为 `max(0, (W - 48) // 48)`。
- 纵向预留三个外星人高度和一个飞船高度；行数为 `max(0, (H - 54 - 16) // 36)`。
- 第 `c` 列、第 `r` 行的左上角：`x = 24 + 48 × c`，`y = 18 + 36 × r`，下标从 0 开始。

窗口为 320×300 时，横向 272÷48 取整为 5，纵向 230÷36 取整为 6，共 30 只。最后一只位于 `(216, 198)`，右下角 `(240, 216)`，不占据飞船顶边 `y=272`。实验调到宽 272 时只剩 4 列；增加窗口宽度不一定立即增加列数，必须够一个完整槽位。

### 3. 碰边是整队决策，不是每只各自换向

先问“是否有外星人的左边不大于 0，或右边不小于 W”，得到一个布尔值。如果有，所有外星人下降 18，共享方向乘以 −1；随后整队水平移动 `2 × direction`。同一帧最多下降一次。

实验的“两只同时碰右边”中，两只的 `x=296`，右边都为 320。正常结果是 `x=294`，两只的纵坐标从 18、54 变为 36、72。错误模式却下降两次、翻转两次，得到 `x=298`、右边 322，队形越界。

这里用小整数步长且初始坐标对齐；真实游戏若速度大于离边距离，单纯“先检查当前位置，再移动”可能越界。需要预判下一位置或限制统一位移，不能对每只分别夹紧，否则会挤坏队形。本例不声称解决任意高速移动。

### 4. 子弹命中：先明确矩形和删除语义

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center [&_a]:justify-center"><Term def="两个矩形在横向和纵向都有正长度重叠；仅共享一条边不算命中。">矩形碰撞</Term></span>用于调用 `pygame.sprite.groupcollide(bullets, aliens, True,
True)`，默认检查 `rect`。两个 `True`
让命中的子弹和目标执行
`kill()`，从其所属的所有组移除；没有命中的子弹不在返回字典中。

实验中目标的纵区间是 `[90, 108)`。子弹移动后顶边为 108，只贴边，不命中；顶边为 107，则重叠 1 像素。这符合官方的半开边界，不是按中心点或透明像素检测。

Pygame 2.6.1 的 `groupcollide` 按第一组的遍历顺序处理子弹，立即从第二组移除命中目标。样本中 B1 先入组并消灭 A1，B2 就不能再命中 A1。**不能先算全部碰撞对，再统一删除**，那会错误地移除 B2。一弹同时重叠多个尚存目标时，则会移除这些目标。

命中后若舰队为空，先清除剩余子弹，再创建新舰队。本章还将方向恢复为向右；同一帧随后会移动新舰队。实验“命中最后一只”可看到补队阶段首个坐标为 `(24,18)`，下一阶段变为 `(26,18)`。

### 5. 生命状态：碰船与触底共用一次出口

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center [&_a]:justify-center"><Term def="由当前可用生命数和 game_active 共同决定能否继续更新的游戏状态。">生命状态</Term></span>把多个危险条件收敛到一个决定。先用 `pygame.sprite.spritecollideany(ship, aliens)` 检查飞船矩形：返回一个碰撞对象或 `None`，它本身不删除对象。再检查是否有 `alien.rect.bottom >= H`。把两项用 `or` 合并后，最多调用一次失去生命处理。

本章 `lives=3` **包含当前正在用的飞船**，所以三次受击依次为 2、1、0；到 0 当次就令 `game_active=False`。这不是照抄作者配套的备用飞船判断约定。仍有生命时清弹、重建舰队、飞船居中；没有生命时停止位置更新，但仍处理退出、重开和绘图事件。

实验下方的状态图用 3→2→1→0 表达实际转移。“飞船被撞”和“外星人触底”走同一条边；最后一条生命样本可验证结束后不能继续模拟下一帧。

### 1. 定义战场和共享状态

窗口尺寸与实验一致。方向只存一份；`lives` 是当前生命，不是额外备用数量。组负责管理对象成员。

```python
import pygame

W, H = 320, 300
AW, AH, SH = 24, 18, 16
BG, BLUE, WHITE = (20, 25, 35), (90, 170, 235), (235, 240, 245)
pygame.init()
screen = pygame.display.set_mode((W, H))
clock = pygame.time.Clock()
aliens = pygame.sprite.Group()
bullets = pygame.sprite.Group()
state = dict(direction=1, lives=3, game_active=True, wave=1)
```

### 2. 构造外星人、飞船和子弹

`Surface` 在内存中产生实心图形，不加载资源文件。外星人只保存位置，不自己翻转整队方向。飞船和子弹用相同的精灵属性约定，但尺寸不同。

```python
class Alien(pygame.sprite.Sprite):
    def __init__(self, x, y):
        super().__init__()
        self.image = pygame.Surface((AW, AH))
        self.image.fill(BLUE)
        self.rect = self.image.get_rect(topleft=(x, y))


def block(x, y, width, height):
    obj = pygame.sprite.Sprite()
    obj.image = pygame.Surface((width, height))
    obj.image.fill(WHITE)
    obj.rect = obj.image.get_rect(topleft=(x, y))
    return obj


ship = block(W // 2 - 16, H - 28, 32, SH)
```

### 3. 按公式创建舰队与完整重开

当尺寸太小，不能创建有效队伍时，明确报错而不是每帧不断补空队。这里只允许固定窗口，不处理运行中缩放。每次补队和重生都恢复统一方向。

```python
def create_fleet():
    columns = max(0, (W - 2 * AW) // (2 * AW))
    rows = max(0, (H - 3 * AH - SH) // (2 * AH))
    if columns == 0 or rows == 0:
        raise ValueError("窗口不足以容纳一个完整槽位")
    aliens.empty()
    for row in range(rows):
        for column in range(columns):
            aliens.add(Alien(AW + 2 * AW * column,
                             AH + 2 * AH * row))
    state["direction"] = 1


def restart():
    state.update(lives=3, game_active=True, wave=1)
    bullets.empty()
    ship.rect.midbottom = (W // 2, H - 12)
    create_fleet()
```

### 4. 移动子弹、命中和补队

迭代副本时删除出界子弹，避免改动正在遍历的集合。碰撞调用中的两个布尔值缺一不可：只删目标会保留穿透子弹，只删子弹会让外星人不消失。清完最后一只后，剩余子弹也必须清掉。

```python
def update_bullets():
    for bullet in bullets.sprites():
        bullet.rect.y -= 8
        if bullet.rect.bottom <= 0:
            bullet.kill()
    pygame.sprite.groupcollide(bullets, aliens, True, True)
    if not aliens:
        bullets.empty()
        create_fleet()
        state["wave"] += 1
```

### 5. 整队碰边只执行一次

`any(...)` 在首次真值处结束检查。先统一决定，再统一移动；这与在每个对象循环里改变共享方向不是同一回事。

```python
def move_fleet():
    at_edge = any(a.rect.left <= 0 or a.rect.right >= W
                  for a in aliens)
    if at_edge:
        state["direction"] *= -1
        for alien in aliens:
            alien.rect.y += 18
    for alien in aliens:
        alien.rect.x += 2 * state["direction"]
```

### 6. 危险检查与生命结算

一帧顺序与实验严格一致：子弹先检测，舰队后移动，最后检查飞船和底线。若目标在本帧子弹阶段被消灭，它就不会再撞船；这是规则，不是视觉显示的先后错觉。本例不阻塞等待半秒，以免暂停期间停止处理窗口事件。

```python
def lose_life():
    state["lives"] -= 1
    bullets.empty()
    aliens.empty()
    state["game_active"] = state["lives"] > 0
    if state["game_active"]:
        ship.rect.midbottom = (W // 2, H - 12)
        create_fleet()


def tick():
    if not state["game_active"]:
        return
    update_bullets()
    move_fleet()
    ship_hit = pygame.sprite.spritecollideany(ship, aliens) is not None
    bottom_hit = any(a.rect.bottom >= H for a in aliens)
    if ship_hit or bottom_hit:
        lose_life()
```

### 7. 处理键盘输入

方向键移动，空格发射，R 完整重开，Esc 退出。结束后仍处理事件，但不再移动和开火。子弹在按下空格时产生，以飞船当前的矩形位置为准。

```python
def handle_events():
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            return False
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_ESCAPE:
                return False
            if event.key == pygame.K_r:
                restart()
            if (event.key == pygame.K_SPACE and state["game_active"]
                    and len(bullets) < 3):
                bullets.add(block(ship.rect.centerx - 2,
                                  ship.rect.top - 8, 4, 8))
    return True
```

### 8. 主循环：更新停止，绘图仍继续

生命和波次直接显示在窗口标题里。当前阶段没有计分、音效或关卡升级；它们不是验证本章队形和碰撞所必需的部分。`tick(60)` 限制最高帧率，步长仍按帧计算；卡顿时不会自动按时间补偿距离。

```python
restart()
running = True
while running:
    running = handle_events()
    if not running:
        break
    if state["game_active"]:
        keys = pygame.key.get_pressed()
        ship.rect.x += 4 * (int(keys[pygame.K_RIGHT])
                            - int(keys[pygame.K_LEFT]))
        ship.rect.clamp_ip(screen.get_rect())
        tick()
    screen.fill(BG)
    aliens.draw(screen)
    bullets.draw(screen)
    screen.blit(ship.image, ship.rect)
    status = "RUN" if state["game_active"] else "GAME OVER - R"
    pygame.display.set_caption(
        f"Lives {state['lives']} | Wave {state['wave']} | {status}")
    pygame.display.flip()
    clock.tick(60)
pygame.quit()
```

首次运行应见 5 列×6 行蓝色外星人、底部白色飞船和标题 `Lives 3`。左右键控制飞船；空格射中目标后双方消失。清空一波后波次增加，失败到 0 时画面仍响应 R 和 Esc。

要精确复现边界，不必靠手速：在第 8 段的 `restart()` 后、`running = True` 前临时插入 `aliens.empty()`，再插入 `aliens.add(Alien(W - AW, 18), Alien(W - AW, 54))`。第一帧应统一下降一次。碰撞样本则换为 `aliens.add(Alien(96, 90), Alien(24, 18))`，并插入 `bullets.add(block(108, 116, 4, 8))`；首帧仅贴边，把 116 改成 115 才命中。验证后删掉这几行，R 也能恢复完整布局。

## 常见误区

<Callout type="trap">
  **现象 →** 同时到边缘的外星人越多，下降越快。 **原因 →**
  在每只外星人的检测分支里调用整队下降。 **修法 →** 聚合成一次
  `any`，或在第一次处理后 `break`；用实验的双目标错误模式比较。
</Callout>

<Callout type="trap">
  **现象 →** 明明边缘碰到了，子弹却没消失。 **原因 →**
  将接触误当成有面积重叠，或以为默认检测透明像素。 **修法 →** 输出双方 `rect`
  的区间；贴边返回假。需要像素遮罩时才另用 `collide_mask`，不能悄悄更换规则。
</Callout>

<Callout type="trap">
  **现象 →** 两颗子弹同时消失，Python 实际却留下第二颗。 **原因 →**
  教学模拟先收集全部命中对，忽略了 `groupcollide(..., True, True)` 的即时删除。
  **修法 →** 每颗子弹只检查仍存活的目标；固定组插入顺序验证。
</Callout>

<Callout type="trap">
  **现象 →** 飞船碰撞且有外星人触底时，一帧丢两条生命。 **原因 →**
  两条独立分支都执行了失去生命函数。 **修法 →**
  合并为一个危险条件；减生命后立即计算是否结束，避免 0 生命还重生一次。
</Callout>

## 小结与练习

- 按完整槽位推导行列，再从行列生成坐标。
- 整队共享方向，一帧只下降一次。
- 严格矩形重叠才命中，删除顺序影响第二颗子弹。
- 清队后先清弹补队，危险合并后只扣一次生命。
- 生命归零停止更新，事件与绘图仍运行。

<Glossary>
  <GlossaryItem term="精灵">
    可加入 Pygame
    组的游戏对象。图像用于画出来，矩形用于定位；组可以批量绘制，kill
    会把对象从其所属组移除。
  </GlossaryItem>
  <GlossaryItem term="矩形">
    左、上、宽、高组成的整数区域。右边等于左边加宽，下边等于上边加高；右、下边界不包含在检测面积里。
  </GlossaryItem>
  <GlossaryItem term="舰队布局">
    用行列和固定间距排出的队形。个体保存位置，整队共用方向与下降决定。
  </GlossaryItem>
  <GlossaryItem term="矩形碰撞">
    横向、纵向都存在正长度重叠才算命中。默认 groupcollide 和 spritecollideany
    用的就是精灵矩形，不是画面中不透明像素。
  </GlossaryItem>
  <GlossaryItem term="生命状态">
    本章用 lives 表示包含当前飞船的剩余次数，用 game_active
    决定是否更新。每次危险最多扣一次，到零当次结束。
  </GlossaryItem>
