## 游戏结束以后，还能公平地再来一局吗？

想象在一张地图上反复安排挑战：第一轮通过以后，下一轮走得更快；失败了则从起点再来。没有清楚的开始和结束规则，玩家点一次按钮，可能还带着上一轮的速度和障碍。

屏幕上的数字也必须有来由：消灭了多少敌人、剩几次机会、是否刷新纪录，都要从实际发生的事情计算出来，而不是为了“看起来在变化”不断加数。本章让挑战过程和显示结果对得上。

## 五组机制，把一次事件接到整局状态

### 1. Play：画出来，不等于能够点击

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:items-center"><Term def="判断输入点是否落在按钮矩形内；对应 hit testing。">命中测试</Term></span>先问“点在哪”，再问“现在能不能开始”。`Button`
保存矩形并绘制文字，游戏控制器才决定是否接受开始请求。条件必须是
`button.rect.collidepoint(pos) and not active`，否则隐藏的 Play
区域仍可能在游戏中触发重开。

Pygame 矩形的右边、下边不包含在区域内。实验按钮范围是横向 `[90, 250)`、纵向 `[244, 300)`：中心点通过，`(250, 272)` 不通过。这不是减去一个随意的容差，而是与矩形碰撞规则一致的边界定义。

看下方“首次开始 / 边界命中”：点按战场会移动十字标记；键盘可以聚焦“测试 Play 中心”或“测试右边界”按钮按 Enter。最后一步才提交结果。浏览器将指针坐标逆变换到 SVG 坐标，不能直接拿屏幕像素和 `viewBox` 数字比较。

### 2. 开始与重开：一次提交整套新局状态

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:items-center"><Term def="一次事件处理结束前完成所有相关状态更新，不让渲染读到半新半旧的一局；对应 atomic reset。">原子重置</Term></span>在这里是单线程事件逻辑，不是数据库事务，也不表示 Python
多条赋值具有线程安全保证。新局需要一起重置分数、关卡、生命、速度、敌人分值、方向、子弹、舰队、飞船位置和按键状态，最后才打开
`active`。任一字段遗漏，都可能让上一局偷偷影响下一局。

最高分是例外：它属于本次程序运行，不属于某一局。因此应初始化在 `reset_stats()` 外面；每次得分后取历史最高值。重开不清高分，但关闭程序后没有任何文件写入，下一次启动仍为 0。

实验“高难度结束后重开”把旧局设为第3关、速度1.21、每只112分，留下旧子弹和偏离中心的飞船。正常提交一次性恢复；故障开关故意漏掉难度初始化。实验的“完整重置”则模拟重新加载整个教具，会连高分和故障一起清除。

### 3. 升级：改变速度，也改变下一关的分值

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:items-center"><Term def="随关卡推进调整移动速度和奖励等参数；对应 dynamic difficulty。">动态难度</Term></span>在作者配套代码中分为不变设置和可变设置。清空舰队后，飞船、子弹、外星人的速度各乘
`1.1`；每只外星人的分值执行 `int(points *
1.5)`。下降距离、子弹数量上限不随之改变，不能把所有设置都乘一个数。

从50分开始，分值依次是50、75、112、168；112来自 `int(75 * 1.5)`，不是四舍五入成113，也不能总用初始50乘倍率后只在最后取整。初始外星人速度1.0，第三关变成1.21；下方横线直接表示相同时长内的位移，长度随倍率改变。

必须先按旧关分值处理最后一次命中，再清弹、补队、加速、增加关卡。实验“命中最后一只并升级”从得分950、每只75开始，结果是1025分，第3关的新敌人才值112分。空队检查只能补一次，补队后队伍已非空。

### 4. 得分：数外星人，不是数子弹键

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:items-center"><Term def="groupcollide 返回的字典：键是发生碰撞的第一组对象，值是它碰到的第二组对象列表；对应 collision mapping。">碰撞映射</Term></span>连接几何事件和分数。`groupcollide(bullets, aliens, True, True)` 返回“子弹 →
外星人列表”，同时移除命中的两组成员。得分增量应为 `points * sum(len(targets) for
targets in hits.values())`；`len(hits)` 只数命中的子弹。

实验“一弹命中两只”用加宽的诊断子弹跨过两个相邻矩形，并不是正常游戏默认弹宽。正常结算移除两只，加150分；错误模式仍移除两只，却只加75分。图上减少的对象数量直接揭穿错误，不靠自造的正确率或评分。

同一只外星人不会因为两颗子弹都靠近而自然算两次：本例使用删除参数，先处理的命中会把目标移出组。若改用不删除的碰撞查询，就必须另外去重。不要把这种实现顺序推广为所有碰撞系统都必然如此。

### 5. 显示：四种读数，来自同一个真实状态

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:items-center"><Term def="将游戏状态绘制为当前得分、最高分、关卡和生命提示的显示对象；对应 scoreboard。">记分板</Term></span>只负责读取，不应自行决定加分。作者的 `Scoreboard`
将文字预先渲染为图像，在分数、最高分、关卡、生命改变时重新准备对应图像；当前分数在右上、最高分在上方中央、关卡在分数下面，生命用飞船图标表示。

原例只在显示时用 `round(score, -1)` 取到十位并加千位分隔符，内部仍保存精确整数。例如75显示80；Python 的取整遇到正中间取偶数，85也显示80，不宜称为通常意义的“四舍五入”。本文程序和实验直接显示精确值，以便核对每一次命中；程序每帧重新渲染文字，避免缓存失效干扰本章重点。

生命的边界也要声明：作者 `_ship_hit()` 先检查 `ships_left > 0` 再减1，所以变成0时仍重生，下一次受击才结束。本文明确采用“图标数包含当前飞船，3→2→1→0立即结束”，不是声称与原代码完全相同。看实验“最后一条生命被撞”，图标消失、活动关闭、Play出现，分数和最高分保留。

## 实验：先预测，再看对象与读数同时改变

猜一猜：把旧局速度提高到1.21后只清零分数，下一局真的回到第一关了吗？再预测：一颗子弹击中两只，字典长度是1还是2？

按下面顺序验证，不需要快速点击：

1. 首次开始，测试右边界，拖到最后一步：仍等待；改点中心，再走到最后一步：完整开局。
2. 选择重开样本，先开故障再提交：关卡回到1但速度仍1.21。关故障重放，对照速度、分值、飞船、子弹和高分。
3. 选择一弹两只：第一步有两个相交目标，检测后都消失；正常加150，故障只加75。
4. 选择最后一只：先出现1025分，再看到新舰队与第3关。选择最后生命：零生命时停止。
5. 从正常开局结果点“保留结果再点 Play”：活动中即使点击中心也被拒绝。最后点“完整重置实验”，所有状态回到最初。

这是一条可倒放的事件记录，不是完整动作游戏。阶段2/3为了讲解展示结算顺序；新局重置始终只在最后一步一次提交。关闭动画偏好时仍可单步，界面不依赖自动播放。

### A. 数据与界面对象

`Session` 只包含一局的数据，不含最高分。测试模式在初始化 Pygame 前启用无窗口驱动；普通运行仍打开真实窗口。颜色仅是本地游戏的绘制参数。

```python

WIDTH, HEIGHT = 640, 480
BG, FG, ACCENT = (20, 25, 34), (238, 242, 246), (95, 194, 179)

@dataclass

    score: int = 0
    level: int = 1
    lives: int = 3
    speed: float = 1.0
    points: int = 50
    direction: int = 1
```

`Box` 用纯色表面充当精灵，给组提供 `image` 和 `rect`；浮点位置避免小速度被整数截掉。`Button` 只保存矩形、绘制文字，不修改游戏状态。

```python
class Box(pygame.sprite.Sprite):
    def __init__(self, rect, color):
        super().__init__()
        self.rect = pygame.Rect(rect)
        self.image = pygame.Surface(self.rect.size)
        self.image.fill(color)
        self.x, self.y = float(self.rect.x), float(self.rect.y)

class Button:
    def __init__(self):
        self.rect = pygame.Rect(200, 212, 240, 56)
        self.font = pygame.font.Font(None, 36)

    def draw(self, screen):
        pygame.draw.rect(screen, ACCENT, self.rect, border_radius=8)
        image = self.font.render("Play / Enter", True, BG)
        screen.blit(image, image.get_rect(center=self.rect.center))
```

`Scoreboard` 同时读四类状态，图标数直接等于当前生命数。这里每帧重新渲染精确分数；正式项目可以像作者代码一样缓存文字，但改变数值时必须刷新缓存。

```python
class Scoreboard:
    def __init__(self):
        self.font = pygame.font.Font(None, 28)

    def draw(self, game):
        screen, s = game.screen, game.session
        def text(value, x, y, anchor="topleft"):
            image = self.font.render(value, True, FG)
            rect = image.get_rect(**{anchor: (x, y)})
            screen.blit(image, rect)
        text(f"High {game.high:,}", WIDTH // 2, 12, "midtop")
        text(f"Score {s.score:,}", WIDTH - 12, 12, "topright")
        text(f"Level {s.level}", WIDTH - 12, 42, "topright")
        text(f"x{s.speed:.2f} | {s.points} pts", 12, 72)
        for i in range(s.lives):
            x = 16 + i * 26
            pygame.draw.polygon(screen, ACCENT,
                                [(x, 34), (x + 9, 18), (x + 18, 34)])
```

### B. 新局提交与事件结算

控制器保留跨局的 `high` 和本局的 `session`。第一帧就有舰队和按钮，但 `active=False`，不会在玩家准备前移动。`new_fleet()` 每次先清空旧队，防止两队叠加。

```python
class Game:
    def __init__(self):
        pygame.init()
        self.screen = pygame.display.set_mode((WIDTH, HEIGHT))
        pygame.display.set_caption("Scoring - arrows, Space, Enter, Q")
        self.clock = pygame.time.Clock()
        self.button, self.board = Button(), Scoreboard()
        self.high, self.active = 0, False
        self.session = Session()
        self.ship = Box((302, 430, 36, 24), FG)
        self.bullets, self.aliens = pygame.sprite.Group(), pygame.sprite.Group()
        self.held = set()
        self.new_fleet()

    def new_fleet(self):
        self.aliens.empty()
        for row in range(2):
            for col in range(4):
                self.aliens.add(Box((100 + col * 100, 120 + row * 52,
                                     28, 22), ACCENT))
```

开始函数返回是否接受点击。只有条件成立才换掉整份 `Session`，清空按键和旧弹、重建队伍并居中；最后启用更新、隐藏鼠标。没有在这些赋值之间绘制半重置状态。射击也要检查活动门禁。

```python
    def start(self, pos):
        if self.active or not self.button.rect.collidepoint(pos):
            return False
        # One event handler, no update/draw before the whole reset finishes.
        self.session = Session()
        self.held.clear()
        self.bullets.empty()
        self.new_fleet()
        self.center_ship()
        self.active = True
        pygame.mouse.set_visible(False)
        return True

    def center_ship(self):
        self.ship.rect.midbottom = (WIDTH // 2, HEIGHT - 26)
        self.ship.x = float(self.ship.rect.x)

    def fire(self):
        if self.active and len(self.bullets) < 3:
            x, y = self.ship.rect.midtop
            self.bullets.add(Box((x - 2, y - 12, 4, 12), FG))
```

碰撞先移除对象，后按命中目标数和旧关分值加分，再检查最高分。舰队清空才升级、清弹和补队。受击最多扣一次生命；减到0立即结束，分数与难度不在受击时归零。

```python
    def resolve_hits(self):
        if not self.active:
            return 0
        hits = pygame.sprite.groupcollide(self.bullets, self.aliens, True, True)
        count = sum(len(targets) for targets in hits.values())
        self.session.score += count * self.session.points
        self.high = max(self.high, self.session.score)
        if not self.aliens:
            self.bullets.empty()
            self.session.level += 1
            self.session.speed *= 1.1
            self.session.points = int(self.session.points * 1.5)
            self.new_fleet()
        return count

    def lose_life(self):
        if not self.active:
            return
        self.session.lives -= 1
        self.bullets.empty()
        self.held.clear()
        if self.session.lives == 0:
            self.active = False
            pygame.mouse.set_visible(True)
        else:
            self.new_fleet()
            self.center_ship()
```

### C. 更新、输入、绘制

更新以秒为单位接收 `dt`，乘60转换为参考帧数，再乘难度倍率。因此基础速度1.5/2.5/1.0仍可与作者设置对照，但本文增加了时间归一化与50ms上限。碰边聚合后只换向一次；撞船或触底共用一次扣生命。

```python
    def update(self, dt):
        if not self.active:
            return
        s = self.session
        scale = min(dt, 0.05) * 60 * s.speed
        axis = int(pygame.K_RIGHT in self.held) - int(pygame.K_LEFT in self.held)
        self.ship.x = max(0, min(WIDTH - 36, self.ship.x + axis * 1.5 * scale))
        self.ship.rect.x = round(self.ship.x)
        for bullet in self.bullets.copy():
            bullet.y -= 2.5 * scale
            bullet.rect.y = round(bullet.y)
            if bullet.rect.bottom <= 0:
                bullet.kill()
        self.resolve_hits()
        if any(a.rect.left <= 0 or a.rect.right >= WIDTH for a in self.aliens):
            s.direction *= -1
            for alien in self.aliens:
                alien.rect.y += 10
        for alien in self.aliens:
            alien.x += s.direction * scale
            alien.rect.x = round(alien.x)
        hit = pygame.sprite.spritecollideany(self.ship, self.aliens)
        bottom = any(a.rect.bottom >= HEIGHT for a in self.aliens)
        if hit or bottom:
            self.lose_life()
```

Enter走与点击相同的 `start()`，不能绕开活动检查。鼠标用事件位置而非稍后查询的新位置；触摸位置从0到1换算为窗口坐标。失焦清空按键，避免返回窗口后飞船继续跑。

```python
    def event(self, event):
        if event.type == pygame.QUIT:
            return False
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_q:
                return False
            if event.key == pygame.K_RETURN:
                self.start(self.button.rect.center)
            elif event.key == pygame.K_SPACE:
                self.fire()
            elif self.active and event.key in (pygame.K_LEFT, pygame.K_RIGHT):
                self.held.add(event.key)
        elif event.type == pygame.KEYUP:
            self.held.discard(event.key)
        elif event.type == pygame.MOUSEBUTTONDOWN and event.button == 1:
            self.start(event.pos)
        elif event.type == pygame.FINGERDOWN:
            self.start((int(event.x * WIDTH), int(event.y * HEIGHT)))
        elif event.type == pygame.WINDOWFOCUSLOST:
            self.held.clear()
        return True
```

绘制顺序是战场、飞船、四类读数，最后按活动状态决定是否画 Play。绘制本身不加分、不扣生命。即使等待开始，也继续处理退出和绘制，不能把整个循环都塞进活动条件。

```python
    def draw(self):
        self.screen.fill(BG)
        self.aliens.draw(self.screen)
        self.bullets.draw(self.screen)
        self.screen.blit(self.ship.image, self.ship.rect)
        self.board.draw(self)
        if not self.active:
            self.button.draw(self.screen)
        pygame.display.flip()

    def run(self):
        running = True
        while running:
            dt = self.clock.tick(60) / 1000
            for event in pygame.event.get():
                if not self.event(event):
                    running = False
            if running:
                self.update(dt)
                self.draw()
        pygame.quit()
```

### E. 故意失败一次，再修回来

将 `count = sum(len(targets) for targets in hits.values())` 临时改成 `count = len(hits)`，再运行同一测试，应该在 `assert game.resolve_hits() == 2` 处失败：只有一个字典键，但确实删除了两个目标。本次已用单独的故障副本实际运行并得到该 `AssertionError`；恢复目标数求和后，原测试重新通过。不要把故障版本留在游戏中。

另一个边界可以手算并断言：把一局末尾分值设成75，消灭最后一只应先加75，下一关分值才变112。只改一行的执行顺序就可能多给37分。窗口卡顿时本例会限制单次时间步；它仍是离散矩形检测，极高速度可能跨过目标，不宣称实现连续碰撞检测。

## 常见误区：显示错了，先检查数据的来路

<Callout type="trap">

**现象 →** 重开后显示第1关，敌人却仍像第3关一样快。<br />
**原因 →** 只重置统计数据，没重置动态速度和分值。<br />
**修法 →** 让 `start()` 建立完整新局；实验开故障可直接看到速度线未缩短。

</Callout>

<Callout type="trap">

**现象 →** 一弹击落两只，只收到一只的分数。<br />
**原因 →** `len(hits)` 数的是发生碰撞的子弹键。<br />
**修法 →** 对各目标列表长度求和；同时保留真实删除，避免重复计分。

</Callout>

<Callout type="trap">

**现象 →** 内部已经加分，界面还是旧数字；或者每次重开最高分消失。<br />
**原因 →** 缓存文字未重新渲染，或把最高分塞进本局重置。<br />
**修法 →** 更新对应记分板图像；最高分放在重置函数外，磁盘持久化则是另外的功能。

</Callout>

<Callout type="trap">

**现象 →** 生命图标已空，玩家仍能继续一条命。<br />
**原因 →** 混用了“备用飞船数”和“包含当前飞船的剩余生命数”。<br />
**修法 →** 明确约定再写终止条件；本文减到0就停止，不把作者的先检查再扣减误说成同一语义。

</Callout>

## 小结与练习

- 按钮命中与活动门禁必须同时成立。
- 新局完整重置；最高分属于本次程序运行。
- 先按旧分值计分，再清弹补队和升级。
- 记分板展示状态，不替游戏逻辑作决定。
