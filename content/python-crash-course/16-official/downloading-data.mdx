## 直觉：先验货，再把记录放到图上

像一条工厂流水线，外面送来的原料不能直接装箱。一天的两个温度如果拿错配对，图上仍能出现漂亮色带，但它讲的已不是那天的天气。

本章把“下载后就画”拆成检查、整理、绘制三个环节。先用小样本看清每一次丢弃和排序，再换成自己的文件；这样发生错误时，能找到坏的是哪条记录，而不只是盯着图猜。

## 1. CSV File Format：列的位置不是列的含义

<Term def="用分隔符组织记录的文本格式；带引号的字段可包含逗号甚至换行，必须由解析器处理。">CSV（Comma-Separated Values）</Term> 看起来像逗号分开的表格，但不能用 `split(',')` 替代 `csv.reader`。作者公开的天气文件里，站名 `"SITKA AIRPORT, AK US"` 自带逗号；手动切开就会让后面的日期和温度全部错位。读真实文件使用 `open(path, encoding="utf-8-sig", newline="")`，让解析器处理换行，并兼容文件开头的编码标记。

<Term def="标明各列名称的首行；先核对必需字段，再建立名称到位置的索引。">表头（Header）</Term> 是解释每一列的依据。先用 `enumerate(header)` 打印索引，再用 `header.index("DATE")` 等取位置。列重排不应改变图；缺少列名、重复列名应停止处理整个文件，而不是悄悄猜一个位置。实验的“列重排”和“错误表头”正好区分这两种情况。

## 2. Extracting and Reading Data：把一整条记录检查完

日期由 `datetime.strptime(text, "%Y-%m-%d")` 转换；本例还检查转回字符串是否一致，拒绝宽松格式和不存在的日期。温度用 `float()`，随后检查有限性：`float("NaN")` 不会报错，但不能当作正常观测。真实天气文件也可能使用整数；应按数据说明决定是否允许小数，不能任意截断。

本章选择**成对删除**：当天任一温度缺失，就不给这一天画高低温；不拿 0 补缺值。列数不符、温度非数字、高温小于低温、同站同日重复都报告记录位置。只有全部通过，才保存一个 `(日期, 高温, 低温)` 整体，避免三个独立列表长短一致、实际却日期错配。下方表格能逐行核对。

## 3. Plotting Weather Data：排序、缺日和阴影是三件事

<Term def="按时间键组织的观测序列；绘图前排序，并明确缺失时刻该如何显示。">时间序列（Time Series）</Term> 需要真正的日期坐标。本例原始顺序是 1、3、2、4 日；关闭排序时，折线会先向右、再折回左侧。正常排序后的最高温为 `[8, 9, 10, 7]`，最低温为 `[2, 1, 4, 0]`，单位均为摄氏度，逐日温差为 `[6, 8, 6, 7]`。

`fill_between(dates, highs, lows, alpha=0.18)` 的阴影表示同一天两条边界之间的温度范围，不表示置信度。两条边界必须共享同一日期轴且高温不低于低温。删掉 2 日后，直接把 1 日连到 3 日会暗示跨缺日连续。本章先补齐日历，把缺日填成 `NaN`，令曲线和阴影留下断口；实验也只连接相邻的完整日期。若研究允许跨日连线，应显式说明那是插值假设，不是已有观测。

## 4. Downloading Your Own Data：文件之外也要保存单位

从 [NOAA Climate Data Online](https://www.ncei.noaa.gov/cdo-web/search) 开始，按以下步骤取得自己的天气数据，而不是只改一个文件名：

1. 选择日汇总数据 **Daily Summaries**、日期区间和地点；在搜索结果中选定一个站点，记下站点 ID，避免把附近多个站的同日记录混在一起。
2. 按页面提供的下载或订单流程选择 CSV，包含 `DATE`、`TMAX`、`TMIN`；选择公制或英制并保存选择记录。不同下载服务流程会变化，不能假定都有一个永久直链。
3. 保存原始文件、站点名称、起止日期、下载时间、原始 URL、单位说明；先打印表头及前三条记录，再调用本章解析函数。检查过滤前后条数、首末日期和异常原因。
4. 若站点改变或使用另一种 NOAA 产品，重新看字段说明。服务导出的摄氏度、华氏度与原始产品中的缩放整数不能混用；例如某些原始日数据的温度按十分之一摄氏度存储，不能一律除以 10。

[作者公开的 Sitka CSV](https://raw.githubusercontent.com/ehmatthes/pcc_3e/main/chapter_16/the_csv_file_format/weather_data/sitka_weather_2021_simple.csv) 可用来练习文件读取：其前六列是 `STATION, NAME, DATE, TAVG, TMAX, TMIN`，2021-01-01 的高低温原始数值是 `44, 40`。本次获取的快照有 364 条有效记录；补齐全年日历后，2021-04-23 没有记录。这说明“每一行都有值”也不等于“每一天都有观测”。这是另一份文件，**不是本章的 8、2 摄氏度教学样本**；应结合来源说明标注单位后绘制。若转换华氏度，使用 `(F - 32) * 5 / 9`，不能只改轴上的 °C。

网络超时、403、站点改版或收到 HTML 错误页都不等于“空天气”。下载失败时保留错误信息，不覆盖已有原始文件。本章下面的代码不发网络请求，全部样本内置；因此不需要先下载上述 CSV，也不依赖未提供的 `weather_data/` 文件。换真实文件时，只替换 `parse_weather` 的输入文本，保留后续检查逻辑。

## 5. Mapping Global Datasets：一个点从哪里来

<Term def="以JSON对象表达地理要素的格式；本章读取FeatureCollection中的Point要素及其属性。">GeoJSON（地理 JSON）</Term> 顶层的 `features` 是要素列表。每个要素里，`properties` 保存观测属性，`geometry` 保存几何形状；不能把地点名称当坐标，也不能假定所有几何形状都是点。[USGS 文档](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) 给出的地震点坐标顺序是 `[longitude, latitude, depth]`，即**经度、纬度、深度**；经纬度用度，深度用千米，二维地图不把深度当纬度。

`properties.mag` 是 <Term def="描述地震大小的对数量；本章用正震级控制圆点面积，但面积不代表释放的能量。">震级（Magnitude）</Term>，可为缺值，也可能为零或负值。零和负值不必然是错误，但不能直接拿负数当圆点大小。本例明确只显示正震级，并单独报告这种策略排除；`null`、非有限数、错误几何或越界坐标则视为坏记录。实验的“追加缺值”会显示三点仍在，但新增四条都有诊断。

### Plotly Map：位置、大小和悬浮分别指定

`px.scatter_geo` 用 `lon`、`lat` 决定位置，`size="mag"` 编码圆面积，`size_max=22` 限制最大符号尺寸，`hover_name="place"` 给出地点；`hover_data` 明确列出经度、纬度和震级。震级是对数量，不能把两倍面积解释为两倍能量。过滤后要固定大小标尺，否则剩下的小震也可能被自动放大成最大圆。

实验把全世界的经纬范围线性映射到一个 2∶1 矩形，是**等距圆柱投影的简化坐标图**，省略海岸线；它不是等面积图，高纬地区会被拉宽。经纬交换后，阿拉斯加和日本的“纬度”越界被拒绝，智利示意点却会落到 `(-32, -72)` 并通过范围检查。只有核对字段顺序和已知位置，才能发现这个仍在合法范围内的错误。

### 7.2 原子地接收一条记录

按列名取得索引；把错误表头作为文件级错误返回，把其他异常作为记录级诊断保存。这里的“记录 2”含表头计数；字段内有换行时，它不等于文本文件的物理行号。重复日期策略是保留第一个通过验证的记录，拒绝后续重复；多站数据必须先选站，不能直接套用这个规则。

```python
def parse_weather(text):
    reader = csv.reader(io.StringIO(text, newline=""))
    header = next(reader, [])
    required = ["DATE", "TMAX", "TMIN"]
    if len(set(header)) != len(header) or any(k not in header for k in required):
        return [], ["表头错误：需要唯一的 DATE、TMAX、TMIN"]
    di, hi, li = [header.index(k) for k in required]
    accepted, errors, seen = [], [], set()
    for number, row in enumerate(reader, 2):
        try:
            if len(row) != len(header):
                raise ValueError("列数不符")
            date = datetime.strptime(row[di], "%Y-%m-%d").date()
            if date.isoformat() != row[di]:
                raise ValueError("日期格式不规范")
            if not row[hi].strip() or not row[li].strip():
                raise ValueError("温度缺失")
            high, low = float(row[hi]), float(row[li])
            if not all(math.isfinite(n) for n in (high, low)):
                raise ValueError("温度不是有限数")
            if high < low or date in seen:
                raise ValueError("高低颠倒或同站同日重复")
        except ValueError as error:
            errors.append(f"记录 {number}：{error}")
            continue
        accepted.append((date, high, low))
        seen.add(date)
    return sorted(accepted), errors
```

### 7.3 先补齐日历，再绘制温差带

`daily_series` 保证三个数组同长、同索引指向同一天。缺日的两项都是 `NaN`，而不是被分别删除。一个日期仍能画点；没有完整记录时显示说明，不调用 `min()` 猜日期范围。

```python
def daily_series(records):
    if not records:
        return [], [], []
    lookup = {d: (h, l) for d, h, l in records}
    first, last = min(lookup), max(lookup)
    dates = [first + timedelta(days=i) for i in range((last - first).days + 1)]
    pairs = [lookup.get(d, (math.nan, math.nan)) for d in dates]
    return dates, [p[0] for p in pairs], [p[1] for p in pairs]


def save_weather(records, name):
    dates, highs, lows = daily_series(records)
    fig, ax = plt.subplots(figsize=(7, 3.5))
    if dates:
        ax.plot(dates, highs, "o-", label="High")
        ax.plot(dates, lows, "o--", label="Low")
        ax.fill_between(dates, highs, lows, alpha=0.18)
        ax.legend()
        fig.autofmt_xdate()
    else:
        ax.text(0.5, 0.5, "No complete records", ha="center", transform=ax.transAxes)
    ax.set(xlabel="Date", ylabel="Temperature (C)", title=name)
    fig.tight_layout()
    fig.savefig(OUT / f"weather-{name}.png", dpi=150)
    plt.close(fig)
```

### 7.4 内置 GeoJSON：位置与属性分开

这三个点只用于教学，不是实际地震报告。日本示意点坐标是 `[140, 36, 20]`；第三项深度不参与二维位置。变体与实验一致，交换前两项可制造确定的坐标错误。

```python
def feature(identifier, place, mag, coordinates):
    return {"type": "Feature", "id": identifier,
            "properties": {"place": place, "mag": mag},
            "geometry": {"type": "Point", "coordinates": coordinates}}


QUAKES = [
    feature("a", "阿拉斯加示意", 4.2, [-150, 60, 10]),
    feature("j", "日本示意", 5.5, [140, 36, 20]),
    feature("c", "智利示意", 3.1, [-72, -32, 15]),
]
QUAKE_CASES = {
    "normal": QUAKES,
    "swapped": [feature(f["id"], f["properties"]["place"], f["properties"]["mag"],
        [f["geometry"]["coordinates"][1], f["geometry"]["coordinates"][0],
         f["geometry"]["coordinates"][2]]) for f in QUAKES],
    "missing": QUAKES + [feature("null", "缺震级", None, [10, 20, 0]),
        {"type": "Feature", "properties": {"mag": 2}, "geometry": None},
        feature("zero", "零震级", 0, [10, 20, 0]),
        feature("negative", "负震级", -0.5, [10, 20, 0])],
    "empty": [],
}
```

解析前先确认顶层是 `FeatureCollection`。JSON 解码成功仅说明语法有效，不说明里面一定有正确地理要素。`type(n) in (int, float)` 刻意排除布尔值，避免把 `true` 当作震级 1。

```python
def as_object(value):
    return value if isinstance(value, dict) else {}


def parse_quakes(document, minimum=0):
    doc = as_object(document)
    if doc.get("type") != "FeatureCollection" or not isinstance(doc.get("features"), list):
        return [], ["需要 FeatureCollection 和 features 列表"], 0
    accepted, errors, filtered = [], [], 0
    for number, raw in enumerate(doc["features"], 1):
        f = as_object(raw)
        p, g = as_object(f.get("properties")), as_object(f.get("geometry"))
        c, mag = g.get("coordinates"), p.get("mag")
        if f.get("type") != "Feature" or g.get("type") != "Point" or not isinstance(c, list) or len(c) < 2:
            errors.append(f"要素 {number}：不是有效 Point"); continue
        lon, lat = c[:2]
        if not all(type(n) in (int, float) and math.isfinite(n) for n in (lon, lat, mag)):
            errors.append(f"要素 {number}：坐标或震级缺失／非有限数"); continue
        if abs(lon) > 180 or abs(lat) > 90:
            errors.append(f"要素 {number}：经纬范围错误"); continue
        if mag <= 0:
            errors.append(f"要素 {number}：震级有效但本图只画正震级"); continue
        if mag < minimum:
            filtered += 1; continue
        accepted.append(dict(id=str(f.get("id", number)), place=p.get("place")
            if isinstance(p.get("place"), str) else "未命名", lon=lon, lat=lat, mag=mag))
    return accepted, errors, filtered
```

### 7.5 输出地图与真正离线的坐标版本

下面生成两种 HTML。`include_plotlyjs=True` 把 Plotly JavaScript 嵌入文件，避免从 CDN 加载脚本；但 **`scatter_geo` 的世界底图还可能请求外部 TopoJSON**。所以 `earthquakes-map.html` 导出成功不等于断网地图渲染成功。离线请打开同样数据的 `earthquakes-offline.html`：它只用普通二维散点坐标轴，无海岸线、无地理底图请求，与本章 SVG 的范围简化一致。两者都明确列出悬浮信息。

大小标尺固定为基准样本的最大震级 5.5，避免过滤时重新缩放。本例半径随震级平方根增长，面积随正震级增长；换真实数据时应从未过滤的完整有效集合计算一次基准，而不是每次过滤后重算。

```python
def save_quakes(records, name):
    if not records:
        empty = go.Figure()
        empty.add_annotation(text="No matching earthquakes", showarrow=False)
        empty.write_html(OUT / f"earthquakes-{name}-empty.html", include_plotlyjs=True)
        return
    options = dict(size="mag", size_max=22, hover_name="place",
                   hover_data={"lon": True, "lat": True, "mag": True, "id": False})
    geo = px.scatter_geo(records, lon="lon", lat="lat",
                         projection="equirectangular", **options)
    geo.update_geos(showcoastlines=True, showcountries=False)
    offline = px.scatter(records, x="lon", y="lat", **options)
    offline.update_xaxes(range=[-180, 180], title="Longitude (degrees)")
    offline.update_yaxes(range=[-90, 90], title="Latitude (degrees)",
                         scaleanchor="x", scaleratio=1)
    for fig, kind in ((geo, "map"), (offline, "offline")):
        fig.update_traces(marker_sizemode="area", marker_sizeref=5.5 / 22**2)
        fig.update_layout(title=f"Teaching points: {name} ({kind})")
        path = OUT / (f"earthquakes-{kind}.html" if name == "normal"
                      else f"earthquakes-{name}-{kind}.html")
        fig.write_html(path, include_plotlyjs=True, full_html=True)
```

### 7.6 执行、导出与核对

这里实际遍历每一种故障；诊断另存为 UTF-8 JSON，可追溯被丢弃的记录。GeoJSON 先序列化再用 `json.loads` 读取，演示文本到对象的边界。无任何预先存在的 CSV 或 JSON 文件依赖。

```python
if __name__ == "__main__":
    report = {}
    for name, text in WEATHER_CASES.items():
        records, errors = parse_weather(text)
        save_weather(records, name)
        report[f"weather-{name}"] = {"accepted": len(records), "errors": errors}
    for name, features in QUAKE_CASES.items():
        text = json.dumps({"type": "FeatureCollection", "features": features})
        document = json.loads(text)
        records, errors, filtered = parse_quakes(document)
        save_quakes(records, name)
        report[f"quakes-{name}"] = {"accepted": len(records), "errors": errors,
                                    "filtered": filtered}
    doc = {"type": "FeatureCollection", "features": QUAKES}
    at_four, _, count = parse_quakes(doc, minimum=4)
    at_six, _, _ = parse_quakes(doc, minimum=6)
    save_quakes(at_four, "threshold-4")
    save_quakes(at_six, "threshold-6")
    assert len(at_four) == 2 and count == 1 and not at_six
    normal, _ = parse_weather(WEATHER)
    reordered, _ = parse_weather(WEATHER_CASES["reordered"])
    assert normal == reordered
    missing, _ = parse_weather(WEATHER_CASES["missing"])
    dates, highs, lows = daily_series(missing)
    assert len(dates) == 4 and math.isnan(highs[1]) and math.isnan(lows[1])
    (OUT / "diagnostics.json").write_text(json.dumps(report, ensure_ascii=False,

    print({name: item["accepted"] for name, item in report.items()})
```

## 8. 常见误区

<Callout type="trap" title="列换了，图还在，但数读错了">

**现象 →** 换一个站点文件后温度异常，或日期解析失败。<br />
**原因 →** 写死列号，或用逗号切开带引号的站名。<br />
**修法 →** 用 `csv.reader`，打印表头，按列名建索引；实验的“列重排”应不改变图，“错误表头”必须停下。

</Callout>

<Callout type="trap" title="阴影跨过没有观测的那一天">

**现象 →** 缺一天仍画出连续色带，或高低温并非同日。<br />
**原因 →** 分别过滤两个列表，或删掉日期后直接连接剩余点。<br />
**修法 →** 整条接收、按日期排序、补齐日历为 `NaN`；用缺值情景核对断口，不把 0 当缺失。

</Callout>

<Callout type="trap" title="经纬没越界，就一定是正确位置？">

**现象 →** 智利示意点跑向南极附近，却不报错。<br />
**原因 →** 把经纬交换；两数都可能落在合法范围。<br />
**修法 →** 按 USGS 的经度、纬度、深度顺序提取，并核对已知地点；实验中合法但错误的点是 `(-32, -72)`。

</Callout>

<Callout type="trap" title="HTML 已导出，断网却没有世界底图">

**现象 →** 文件存在、脚本也内嵌，地图仍无法完整显示。<br />
**原因 →** 地理底图还可能加载外部 TopoJSON。<br />
**修法 →** 区分文件导出与浏览器渲染；断网使用本章无底图的坐标版本，不能宣称未验证的在线地图通过。

</Callout>

## 9. 小结与练习

- 按列名解析，整条检查，再按日期对齐绘图。
- 记录来源、站点与单位；缺值和网络失败分开处理。
- 经纬合法不代表顺序正确；大小与悬浮信息也要核对。

<Exercises>

**问题 1：** 列顺序改成 `TMIN,DATE,TMAX` 后，第一行是 `2,2021-01-01,8`。三个索引分别是什么？结果应是什么？再给数据加一条 `2021-01-05,NaN,2`，为什么仅捕获 `ValueError` 不够？

<Answer>

`DATE` 索引为 1，`TMAX` 为 2，`TMIN` 为 0；得到 1 日高温 8、低温 2、温差 6，与原文件相同。`float("NaN")` 转换成功，不触发 `ValueError`；需要 `math.isfinite()` 拒绝。新增坏记录只增加一条诊断，不应改变已有四天的曲线。

</Answer>

**问题 2：** 独立修改 `save_weather`：增加一条“日温差”折线，并让 2 日缺测时仍有断口。用缺值情景验证，目标点为 1 日 6、3 日 6、4 日 7，不能在 2 日补 0。若换成两个站点的数据，还需要先做什么？

<Answer>

在 `daily_series` 得到数组后计算 `ranges = [h - l for h, l in zip(highs, lows)]`，再画 `ax.plot(dates, ranges, "s:", label="Daily range")`，放在 `ax.legend()` 前。`NaN - NaN` 仍是 `NaN`，所以目标曲线在 2 日断开。两个站应先按 `STATION` 分组并分别解析，或明确只选一个站；用“站点＋日期”识别重复，不可把两站同日当坏记录删掉。单位统一后再比较。

</Answer>

**问题 3：** 把阈值设为 4.0，再设为 6.0，分别显示几个点？将智利坐标 `[-72, -32, 15]` 前两项交换会怎样？如果只成功写出 `earthquakes-map.html`，能否声称断网地图验证通过？

<Answer>

4.0 留下两点，6.0 没有点，应显示空结果而不是崩溃。交换后变成经度 −32、纬度 −72，范围仍合法，但地点错误，深度 15 不受影响。写出地图 HTML 只证明 Python 导出步骤成功；还没有证明浏览器能取得底图。离线应使用 `earthquakes-offline.html` 或本章 SVG 坐标图；完整世界底图需另行验证资源加载与实际渲染。

</Answer>

</Exercises>
