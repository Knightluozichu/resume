## 为什么不能拿到一份数据就立刻画图

一条生产线上，收货、验货、整理和展示是不同工序。货没送到，与送来了一箱不合规格的东西，解决方式并不相同。把两者都记成“数量为零”，最后做出的统计会误导人。

本章把网上取得的数据也这样处理：每一关检查自己的条件，只把合格且含义明确的数值交给图表。没有这几道检查，网页临时故障可能变成一张看起来正常、实际上全错的图。

## 1. 请求与响应：四层检查不能颠倒

<Term def="程序之间按约定交换请求和数据的入口；英文 Application Programming Interface，简称 API。">应用程序编程接口</Term> 让我们直接请求结构化数据，而不必从网页排版里找数字。这里的 `requests.get()` 发出公开、只读的 GET 请求；GitHub 请求搜索仓库，HN 请求榜单与故事详情。请求参数 `params` 由 Requests 编码，不手工拼接含空格的查询字符串。

<Term def="等待连接建立或读取数据时允许的等待时长；Requests 中不等于整个下载的总时间上限。">超时</Term>（timeout）必须显式给出。`timeout=(3.05, 10)` 分别限制连接等待和读取等待；读取超时不是“整个下载只能持续 10 秒”。DNS、断网等异常也可能发生在没有收到任何响应时。实验上半部的返回箭头此时消失，不能补一个虚构的 500。

<Term def="HTTP 响应中表示请求结果的数字，例如成功 200、禁止访问 403、请求过多 429。">HTTP 状态码</Term> 到达后，先判断是否是端点约定的成功状态。`raise_for_status()` 可检查一般 HTTP 错误；本章手工分支，是为了先读取限流头并保留错误分类。500 的正文即使是一份有效 JSON，也仍是 HTTP 失败。

<Term def="JavaScript Object Notation，一种文本数据交换格式；解码后可得到字典、列表、字符串、数字或 None 等值。">JSON</Term> 解码发生在 HTTP 检查之后。`response.json()` 可能因 HTML 错误页或空正文抛出异常；反过来，成功解码为列表也不保证符合仓库端点要求的字典结构。最后一关检查根对象、列表字段、每条记录和数值类型，这就是本章的 shape 检查。第五节实验中的三个错误模式分别在不同关口截断图形。

| 检查层 | 示例 | 处理结果 |
| --- | --- | --- |
| 传输 | Timeout、ConnectionError | 没有可用响应；记录 timeout/network |
| HTTP | 403、429、500 | 检查限流信号；否则记录 http |
| 解码 | 200 + HTML | 记录 json，不解析字段 |
| 结构 | 200 + `{"items": {}}` | 记录 shape，不绘制错误数据 |

## 2. 限流：状态码只是线索，不是全部解释

<Term def="服务端对一定时间内请求量或负载施加的限制；英文 rate limit。">速率限制</Term> 保护公开服务。GitHub 的主要限额耗尽时可能返回 **403 或 429**，常带 `x-ratelimit-remaining: 0`；次级限制也可能使用这两种状态。普通 403 还可能表示访问被拒绝，不能一律等待配额恢复。

本章把 429，或带 remaining=0／明确 rate limit 正文的 403 归为限流。`x-ratelimit-reset` 是恢复时间的 Unix **绝对秒数**；`Retry-After` 在所引用 GitHub 说明里表示至少再等多少秒。二者不是同一个量：固定 `now=1000`、`reset=1180` 时，要等 180 秒，而非 1180 秒。实验会画出这段等待区间。

代码取已知等待要求的最大值，并设置 60 秒保守下限；缺失或损坏的头不能当作立即重试许可。这个等待值是“最早可尝试的提示”，不是成功保证；次级限制可能还要更久。为了请求预算可控，本例**不自动休眠、不重试**，由调用者决定稍后运行。HN 聚合中遇到限流会停止余下详情请求。

## 3. GitHub 仓库：先规范化，再比较长度

<Term def="将来源字段整理为一致的本地字段和类型，并显式处理缺失、重复和非法记录；英文 response normalization。">响应规范化</Term> 把 `full_name`、`stargazers_count`、`description` 转为 `name`、`stars`、`description`。用完整仓库名区分同名项目。缺少说明文字可变成空字符串；缺少 stars 却不能变成 0，因为“未知”和“确实零颗星”不同。

本章丢弃名字或 stars 非法的仓库，并记录原因；Python 中 `bool` 是 `int` 子类，因此用 `type(value) is int` 排除 `True`。保留真实零值。按 stars 降序、name 升序打破平局，使测试结果稳定。字段格中的问号、剔除标记与最终缺少的柱是一一对应的。

搜索使用 `q=language:python`、`sort=stars`、`order=desc`、`per_page=3`。这只是当前第一页的三个公开结果，不能把 `len(items)` 当作全站总量；`total_count` 也不等于已下载数量。本章不翻页。若 `incomplete_results=true`，服务可能只给了部分搜索结果，即使 HTTP 200 也标记 partial。Stars 表示受关注程度，不等于代码质量。

<Term def="Plotly 的高层绘图接口；用一行记录对应一根条形，px.bar 不会替你修复或排序原始数据。">Plotly Express</Term> 接收已经规范化的记录。条形长度表示 stars，分类顺序要显式固定，并把最大的放在上方。空结果同样是正常边界；为 pandas 表显式声明列名，可以避免空列表被误判为另一种绘图输入。第六节将断言图形的数据数组，而不是只判断“没抛异常”。

## 4. HN：榜单编号不是故事详情

Hacker News 的 `topstories.json` 返回编号列表，还可能包含 job。先取前三个不同编号，再逐个读取 `/item/{id}.json`，成功后才能按讨论量排序。这个顺序不是“全站评论最多的前三条”，只是榜单头部样本里的本地排名。实验的 HN 模式对应详情聚合后的字段格。

<Term def="HN 故事或投票的 descendants 字段所给出的总评论数；不是直接子节点列表 kids 的长度。">评论总数</Term> 来自 `descendants`。`kids` 是直接子节点编号，嵌套回复不能靠 `len(kids)` 算齐。我们只处理 story：跳过 job、deleted、dead；为可能不可用的 `null` 详情提供防御分支。注意 deleted 是标志位，不能声称“被删除的记录一定返回 null”。

<Term def="一次采集里有些记录成功、另一些失败或字段未知，保留成功记录并公开缺口；英文 partial result。">部分结果</Term> 不应该被伪装成完整榜单。详情断网时记录问题并继续；限流时停止。评论数缺失的合法故事仍保留，值为 `None`，排序时放在已知值之后，实验中不画成零长柱。顶层编号列表结构错误则整轮失败，没有可以安全请求的编号。

### 6.1 导入、错误类型和等待时间

错误对象携带分类、状态码与等待提示，调用者不必从一段字符串里猜失败层级。

```python
import math
import time
import requests

GITHUB = 'https://api.github.com/search/repositories'
HN = 'https://hacker-news.firebaseio.com/v0'
```

`ApiError` 是本章统一的错误出口；只有收到响应时才有 status。

```python
class ApiError(Exception):
    def __init__(self, kind, detail, status=None, wait=None):
        super().__init__(detail)
        self.kind, self.status, self.wait = kind, status, wait
```

数值检查允许 0，但排除负数、字符串、浮点数和布尔值，避免把 `True` 画成 1。

```python
def nonnegative(value):
    return type(value) is int and value >= 0
```

头字段来自外部，先解析有限的非负数字；NaN、无限大和缺失值都视为未知。

```python
def header_seconds(value):
    try:
        number = float(value)
        return number if math.isfinite(number) and number >= 0 else None
    except (TypeError, ValueError):
        return None
```

等待计算接受注入的当前时刻。取最大值遵守所有已知下限，60 秒是本例保守策略，不是协议保证。

```python
def rate_wait(headers, now):
    retry = header_seconds(headers.get('retry-after'))
    reset = header_seconds(headers.get('x-ratelimit-reset'))
    waits = [60]  # 保守下限；不自动重试
    if retry is not None:
        waits.append(math.ceil(retry))
    if reset is not None:
        waits.append(max(0, math.ceil(reset - now)))
    return max(waits)
```

### 6.2 唯一接触网络的边界

只在取得响应之后检查头与正文。错误 HTTP 不调用 `.json()`；200 解码成功后返回原始值，字段契约交给各端点处理。`get` 和 `now` 都能替换，离线测试既能复现断网，也能固定恢复时间。

```python
def fetch_json(url, *, get=requests.get, now=time.time, params=None):
    try:
        response = get(url, params=params, timeout=(3.05, 10),
                       headers={'Accept': 'application/json',
                                'User-Agent': 'pcc-public-api-lab'})
    except requests.Timeout as exc:
        raise ApiError('timeout', str(exc)) from exc
    except requests.RequestException as exc:
        raise ApiError('network', str(exc)) from exc
    headers = {k.lower(): v for k, v in response.headers.items()}
    status = response.status_code
    limited = status == 429 or (status == 403 and (
        headers.get('x-ratelimit-remaining') == '0'
        or 'rate limit' in response.text.lower()))
    if limited:
        raise ApiError('rate_limit', '稍后再试', status,
                       rate_wait(headers, now()))
    if status != 200:  # 本章两个端点均约定成功响应为 200
        raise ApiError('http', f'HTTP {status}', status)
    try:
        return response.json()
    except ValueError as exc:
        raise ApiError('json', '正文不是可解码的 JSON', status) from exc
```

### 6.3 规范化仓库并稳定排序

根结构不符合约定时失败；单条坏记录则收集 issues、保留其余数据。`partial` 同时反映服务声明的不完整与本地发现的缺口。缺少 description 不影响数值可比性。

```python
def normalize_repos(payload):
    if not isinstance(payload, dict) or not isinstance(payload.get('items'), list):
        raise ApiError('shape', '预期对象及 items 列表')
    incomplete = payload.get('incomplete_results', False)
    if type(incomplete) is not bool:
        raise ApiError('shape', 'incomplete_results 必须是布尔值')
    rows, issues, seen = [], [], set()
    for index, item in enumerate(payload['items']):
        if not isinstance(item, dict):
            issues.append(f'items[{index}]: 非对象'); continue
        name, stars = item.get('full_name'), item.get('stargazers_count')
        if not isinstance(name, str) or not name.strip() or not nonnegative(stars):
            issues.append(f'items[{index}]: 名称或 stars 缺失/非法'); continue
        if name in seen:
            issues.append(f'{name}: 重复'); continue
        seen.add(name)
        description = item.get('description')
        rows.append({'name': name, 'stars': stars,
                     'description': description if isinstance(description, str) else ''})
    rows.sort(key=lambda row: (-row['stars'], row['name']))
    return {'rows': rows, 'issues': issues, 'partial': incomplete or bool(issues)}
```

端点包装只负责参数与流程衔接。默认 requests.get 会联网；测试传入替代函数就不会联网。

```python
def github_repos(*, get=requests.get, now=time.time):
    payload = fetch_json(GITHUB, get=get, now=now, params={
        'q': 'language:python', 'sort': 'stars', 'order': 'desc', 'per_page': 3})
    return normalize_repos(payload)
```

### 6.4 把 HN 详情整理成故事记录

返回 `(row, issue)`：完全不可用时没有 row；评论未知时可以同时有 row 和 issue。链接指向 HN 讨论页，不依赖可缺失的外链 url；标题仅作为文字数据，不当作可信 HTML 插入网页。

```python
def normalize_story(item, expected_id):
    if item is None:
        return None, f'{expected_id}: null，当前不可用'
    if not isinstance(item, dict) or item.get('id') != expected_id:
        return None, f'{expected_id}: item 结构/编号错误'
    if item.get('deleted') or item.get('dead') or item.get('type') != 'story':
        return None, f'{expected_id}: 删除、dead 或不是 story'
    title = item.get('title')
    if not isinstance(title, str) or not title.strip():
        return None, f'{expected_id}: 缺少标题'
    comments = item.get('descendants')
    issue = None
    if not nonnegative(comments):
        comments, issue = None, f'{expected_id}: 评论总数未知'
    return {'id': expected_id, 'title': title, 'comments': comments,
            'url': f'https://news.ycombinator.com/item?id={expected_id}'}, issue
```

榜单先严格检查，去重后限制最多三个详情请求。单项普通失败继续、限流停止；已经成功的故事不会因后一项失败而丢失。最终把未知评论排到末尾；本例 partial 只描述已选样本的异常，不把“没采集全部榜单”藏起来。

```python
def hn_stories(*, get=requests.get, now=time.time, limit=3):
    if type(limit) is not int or not 0 <= limit <= 3:
        raise ValueError('教学请求预算 limit 为 0..3')
    ids = fetch_json(f'{HN}/topstories.json', get=get, now=now)
    if not isinstance(ids, list) or any(type(i) is not int or i <= 0 for i in ids):
        raise ApiError('shape', 'topstories 必须是正整数编号列表')
    rows, issues = [], []
    selected = list(dict.fromkeys(ids))[:limit]
    for item_id in selected:
        try:
            item = fetch_json(f'{HN}/item/{item_id}.json', get=get, now=now)
            row, issue = normalize_story(item, item_id)
            if row is not None:
                rows.append(row)
            if issue:
                issues.append(issue)
        except ApiError as exc:
            issues.append(f'{item_id}: {exc.kind}; wait={exc.wait}')
            if exc.kind == 'rate_limit':
                break  # 停止余下请求，保留已取得的结果
    rows.sort(key=lambda r: (r['comments'] is None,
                            -(r['comments'] or 0), r['id']))
    return {'rows': rows, 'issues': issues, 'partial': bool(issues)}
```

### 6.5 用同一份排序数据生成条形图

显式列结构可处理空集。`categoryarray` 保存排序，`autorange="reversed"` 让第一条显示在上方。这个函数只构造图，不自动打开浏览器。

```python
def repo_figure(report):
    import plotly.express as px
    import pandas as pd
    rows = report['rows']
    names = [row['name'] for row in rows]
    table = pd.DataFrame(rows, columns=['name', 'stars', 'description'])
    figure = px.bar(table, x='stars', y='name',
                    orientation='h', labels={'stars': 'Stars', 'name': 'Repository'},
                    title='当前样本（部分结果）' if report['partial'] else '当前样本')
    figure.update_yaxes(categoryorder='array', categoryarray=names,
                        autorange='reversed')
    return figure
```

## 7. 离线测试：注入响应，而不是赌网络稳定

<Term def="替换网络和时间依赖，用固定输入检验处理代码；英文 offline test。">离线测试</Term> 的重点不是把期望打印出来，而是让失败能由断言检出。`Reply` 模拟响应，`fake_get` 记录调用参数并只返回预先声明的数据；漏配 URL 会直接报错，绝不退回真实网络。

创建 `test_api_lab.py`，按顺序放入下列块。这些测试导入的正是上一节代码，不是另写一份“看起来类似”的实现。

```python
import pytest

from api_lab import (ApiError, GITHUB, HN, fetch_json, github_repos,
                     hn_stories, normalize_repos, normalize_story, repo_figure)
```

先导入依赖。响应替身能返回固定 JSON，也能在解码时抛错；它不是远程服务。

```python
class Reply:
    def __init__(self, body=None, status=200, headers=None, text=''):
        self.body, self.status_code = body, status
        self.headers, self.text = headers or {}, text

    def json(self):
        if isinstance(self.body, Exception):
            raise self.body
        return self.body
```

按 URL 路由到响应或网络异常，记录调用次数、超时和搜索参数，以验证没有隐蔽重试。

```python
def fake_get(replies):
    calls = []
    def get(url, **kwargs):
        calls.append((url, kwargs))
        result = replies[url]
        if isinstance(result, Exception):
            raise result
        return result
    get.calls = calls
    return get
```

这组用例区分五种错误。特别让 HTTP 500 搭配无法解码的正文，验证 HTTP 分支先于 JSON 分支。

```python
@pytest.mark.parametrize('reply,kind', [
    (requests.Timeout('slow'), 'timeout'),
    (requests.ConnectionError('offline'), 'network'),
    (Reply(status=500, body=ValueError()), 'http'),
    (Reply(status=403, text='Forbidden'), 'http'),
    (Reply(body=ValueError('html')), 'json'),
])
def test_error_layers(reply, kind):
    with pytest.raises(ApiError) as caught:
        fetch_json('public', get=fake_get({'public': reply}))
    assert caught.value.kind == kind
```

固定 now=1000，验证 403/429 分类、绝对 reset、相对等待、坏头和过去时间。每次只发出一次注入调用。

```python
@pytest.mark.parametrize('status,headers,text,wait', [
    (403, {'X-RateLimit-Remaining': '0', 'X-RateLimit-Reset': '1180'}, '', 180),
    (429, {'Retry-After': '90'}, '', 90),
    (403, {}, 'secondary rate limit', 60),
    (429, {'Retry-After': 'NaN', 'X-RateLimit-Reset': 'bad'}, '', 60),
    (429, {'X-RateLimit-Reset': '900'}, '', 60),
])
def test_limits(status, headers, text, wait):
    get = fake_get({'public': Reply(status=status, headers=headers, text=text)})
    with pytest.raises(ApiError) as caught:
        fetch_json('public', get=get, now=lambda: 1000)
    assert (caught.value.kind, caught.value.wait) == ('rate_limit', wait)
    assert len(get.calls) == 1  # 没有偷偷重试
```

顶层 JSON 解析成功不代表形状正确；错误根节点和错误 incomplete_results 类型都必须拒绝。

```python
@pytest.mark.parametrize('payload', [None, [], {}, {'items': {}},
                                        {'items': [], 'incomplete_results': 'true'}])
def test_shape(payload):
    with pytest.raises(ApiError, match='items|incomplete_results') as caught:
        normalize_repos(payload)
    assert caught.value.kind == 'shape'
```

排名用同星数检查名称打破平局；缺失 stars、非对象、布尔值和重复记录各记一条问题。继续检查 Plotly 的数值与类别顺序，防止图形上下颠倒。

```python
def test_repos_and_plot():
    payload = {'items': [
        {'full_name': 'lab/b', 'stargazers_count': 4, 'description': None},
        {'full_name': 'lab/a', 'stargazers_count': 4},
        {'full_name': 'lab/zero', 'stargazers_count': 0},
        {'full_name': 'lab/missing'}, None,
        {'full_name': 'lab/bool', 'stargazers_count': True},
        {'full_name': 'lab/a', 'stargazers_count': 4},
    ], 'incomplete_results': True}
    get = fake_get({GITHUB: Reply(payload)})
    report = github_repos(get=get)
    assert [r['name'] for r in report['rows']] == ['lab/a', 'lab/b', 'lab/zero']
    assert report['rows'][1]['description'] == ''
    assert report['partial'] and len(report['issues']) == 4
    assert get.calls[0][1]['timeout'] == (3.05, 10)
    assert get.calls[0][1]['params']['per_page'] == 3
    fig = repo_figure(report)
    assert list(fig.data[0].x) == [4, 4, 0]
    assert fig.layout.yaxis.autorange == 'reversed'
    assert list(fig.layout.yaxis.categoryarray) == ['lab/a', 'lab/b', 'lab/zero']
```

模拟榜单重复编号、null 详情与未知评论。18 来自 descendants，不是 kids 中的一个直接子节点。最多四次注入调用：一份榜单加三份详情。

```python
def test_hn_partial():
    get = fake_get({f'{HN}/topstories.json': Reply([1, 1, 2, 3, 4]),
        f'{HN}/item/1.json': Reply({'id': 1, 'type': 'story', 'title': 'A',
                                  'descendants': 18, 'kids': [9]}),
        f'{HN}/item/2.json': Reply(None),
        f'{HN}/item/3.json': Reply({'id': 3, 'type': 'story', 'title': 'C'})})
    report = hn_stories(get=get)
    assert [r['comments'] for r in report['rows']] == [18, None]
    assert report['partial'] and len(report['issues']) == 2
    assert len(get.calls) == 4  # 一个榜单、三个详情；重复 id 不重复请求
```

无记录、结构错误、删除、dead、job 和空标题都不会进入故事排名。

第一条成功、第二条限流：成功记录仍保留，不请求第三条。真实零评论不能被误判为缺失。

```python
def test_hn_failure_keeps_success_and_stops_on_limit():
    get = fake_get({f'{HN}/topstories.json': Reply([1, 2, 3]),
        f'{HN}/item/1.json': Reply({'id': 1, 'type': 'story', 'title': 'A',
```

不把字符串、布尔值或负数转换成请求编号；根列表不合格时立即停止。

空仓库列表不是解析失败。检查图中实际条目为零，不绑定 Plotly 内部是否保留一条空 trace。

非限流的单项网络失败不会阻断其余请求。最终按评论数 42、18 排序，而不是按榜单编号排序，也不是按 kids 长度排序。

```python
def test_hn_item_network_failure_continues():
    get = fake_get({f'{HN}/topstories.json': Reply([1, 2, 3]),
        f'{HN}/item/1.json': requests.ConnectionError('offline'),
        f'{HN}/item/2.json': Reply({'id': 2, 'type': 'story', 'title': 'B',
                                  'descendants': 18, 'kids': [7]}),
        f'{HN}/item/3.json': Reply({'id': 3, 'type': 'story', 'title': 'C',
                                  'descendants': 42, 'kids': []})})
    report = hn_stories(get=get)
    assert [r['comments'] for r in report['rows']] == [42, 18]
    assert report['partial'] and 'network' in report['issues'][0]
    assert len(get.calls) == 4
```

缺失、布尔值、负值、字符串评论数都保留为未知，避免错误类型偷偷变成零。

```python
from api_lab import ApiError, github_repos

try:
    report = github_repos()
except ApiError as exc:
    print({'error': exc.kind, 'status': exc.status, 'wait': exc.wait})
else:
    print(report)
```

线上结果只证明“某个时间点可以访问”，不证明下次一定成功。公开端点、代理和网关也可能拒绝请求；若收到 403，就保存 403，不为了凑成功次数反复请求。本文的稳定正确性依据是上述离线测试。

## 容易踩的坑

<Callout type="trap" title="200 就等于可以读 items？">
现象：访问 items 时崩溃。原因：状态、JSON 语法和字段结构是三道不同的门。修法：先检查 HTTP，再解码，再检查根结构；在实验中依次切换 JSON 和 shape 错误，观察字段格都没有伪造记录。
</Callout>

<Callout type="trap" title="把所有 403 都当成限流">
现象：无休止地等待后重发。原因：403 也能表达普通拒绝访问。修法：结合 remaining、错误正文和 Retry-After/reset；本例只给等待提示，不自动重试，更不使用私有凭证绕过限制。
</Callout>

<Callout type="trap" title="用 0 填满所有缺失字段">
现象：不可用故事和零评论故事看起来一样。原因：把未知数值当作测量值。修法：保留 None、问题清单和 partial；删除记录剔除，未知评论单列，已知零值正常保留。
</Callout>

<Callout type="trap" title="图表能显示就说明排名正确">
现象：最大仓库出现在最下方，或评论数只是一级回复数。原因：图表类别顺序与业务排序脱节，或误用 len(kids)。修法：明确 categoryarray 与 reversed，并断言 descendants 和图数据，而不是只检查函数无异常。
</Callout>

## 小结

- 传输、HTTP、JSON、结构分别验证。
- 限流结合状态、头和正文，不盲目重试。
- 未知不是零；部分结果必须公开缺口。
- 图表只比较当前样本中的合格记录。
- 固定响应和时钟让失败能够稳定重现。

<Glossary>
  <GlossaryItem term="应用程序编程接口">Application Programming Interface（API）：程序按约定请求数据的入口；本章只使用公开 GET 端点。</GlossaryItem>
  <GlossaryItem term="超时">Timeout：连接或读取等待的上限；Requests 的读取超时不是下载全程总时限。</GlossaryItem>
  <GlossaryItem term="HTTP 状态码">HTTP status code：响应结果数字；200 成功不保证 JSON 或字段结构正确，403 也不只代表限流。</GlossaryItem>
  <GlossaryItem term="JSON">JavaScript Object Notation：文本数据交换格式，不是 Python 字典的同义词；解码可得到多种值，包括 None。</GlossaryItem>
  <GlossaryItem term="速率限制">Rate limit：服务端限制请求频率或负载的机制；reset 是绝对时间，GitHub 文档中的 Retry-After 是等待秒数。</GlossaryItem>
  <GlossaryItem term="响应规范化">Response normalization：把外部字段变为一致的内部记录，显式处理非法、重复和未知值，再交给排序和图表。</GlossaryItem>
  <GlossaryItem term="Plotly Express">Plotly 高层绘图接口，通常导入为 px；px.bar 把已经整理好的记录画成条形。</GlossaryItem>
  <GlossaryItem term="评论总数">Total comment count：HN 的 descendants 值，包含嵌套讨论；不等于 kids 直接子节点数量。</GlossaryItem>
  <GlossaryItem term="部分结果">Partial result：有些数据成功、有些失败或未知的结果；需要同时呈现成功记录与缺口说明。</GlossaryItem>
  <GlossaryItem term="离线测试">Offline test：用固定响应和时间替代网络依赖的自动检查；不等于对实时服务可用性的承诺。</GlossaryItem>
</Glossary>
