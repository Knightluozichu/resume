## 页面做出来，为什么还不能交付？

一条生产线既要把产品做对，也要把产品完整地送到使用者手里。笔记能保存，只证明内部工序可用；手机上按钮挤成一团、公开页面暴露内部错误，都是交付失败。

本章把外观和交付分开检查：先让页面在不同宽度下好用，再确认换一台机器仍能得到同样结果。我们只在本机验证，不创建收费资源，也不把“检查通过”说成已经上线。

## 五个边界，连接八组知识点

### 1. 外观边界：模板继承，不是复制每一页

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center"><Term def="页面根据可用宽度改变列数或导航展开方式，而不是只把全部内容等比例缩小。">响应式布局</Term></span>
由浏览器应用样式规则。Bootstrap 5 提供导航、栅格、按钮和卡片；`django-bootstrap5` 则把 Django 表单对象转换为相应标记，不负责身份认证、数据库或发布。

公共 `base.html` 放页面标题、viewport、导航和资源引用；子模板只填 `content`。本例 `col-12 col-md-6` 在 768 CSS 像素开始并排，`navbar-expand-lg` 在 992 像素开始横排。下图可分别越过两个断点，观察“内容已经两列、菜单仍折叠”的中间区间。

窄屏导航的展开需要 Bootstrap 的 JavaScript bundle，只有 CSS 不够。`bootstrap_css` 与 `bootstrap_javascript` 默认生成外部资源链接：模板渲染成功不等于浏览器已成功下载它们。本地 `app.css` 则由另一条静态路径提供，两者不能混为一谈。

### 2. 表单边界：装饰输入，不跳过服务端验证

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center"><Term def="已经带上用户提交内容的 Django 表单；验证失败时同时保留输入与错误。">绑定表单</Term></span>
应以 `EntryForm(request.POST)` 构造，再由 `is_valid()` 判断。失败时重新渲染同一个对象，`bootstrap_form` 才能显示错误；若换成空表单，读者的输入和错误都会丢失。

第19章的边界必须继续存在：登录才能读主题；按 `owner=request.user` 过滤主题；保存条目前先验证主题所有权。隐藏按钮仅改变外观，不能阻止直接发来的 POST。本章没有把 `owner` 或 `topic` 放进可编辑字段。

条目用 `.card` 表达标题和正文；表单用标签、错误文本和按钮表达操作。图中两者是独立区域，宽度变化只改变排列，不改变访问权限。退出使用带 CSRF 令牌的 POST 表单，而不是 Django 5.2 不再接受的 GET 退出链接。

### 3. 运行边界：代码能导入，还要配置能成立

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center"><Term def="Python Web 服务器调用应用的标准接口；Gunicorn 通过该接口把请求交给 Django。">WSGI</Term></span>
不是数据库，也不是静态资源目录。启动目标 `learning_log.wsgi:application` 表示模块和其中的应用对象。Gunicorn 缺包、模块名拼错或配置导入失败，都会使 worker 无法启动；此时甚至还没有 Django 错误页。

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center"><Term def="进程启动时从代码外部注入的配置值；密钥、主机名与运行模式不应写死在仓库里。">环境变量</Term></span>
把同一份代码和不同环境分开。`SECRET_KEY` 必须足够随机且保密；`DEBUG=False` 隐藏调试详情；`ALLOWED_HOSTS` 接受主机名而非 URL，不是用户权限表，也不是 CORS 设置。缺少密钥应立即报错，不能悄悄退回公开的示例密钥。

图中“缺密钥”截断 WSGI，“陌生 Host”截断动态请求，“忘记 migrate”直到数据库层才失败。Bootstrap 与这些错误无关。静态中间件可能提前返回文件，所以 Django 的 Host 校验不能代替边缘服务器的主机限制。

### 4. 静态边界：找到源文件，不等于用户取得到

<span className="[&_button]:min-h-11 [&_button]:min-w-11 [&_a]:inline-flex [&_a]:min-h-11 [&_a]:min-w-11 [&_a]:items-center"><Term def="把各应用的静态源文件汇入发布目录的构建动作；Django 命令是 collectstatic。">静态收集</Term></span>
读取应用的 `static/` 等源目录，输出到 `STATIC_ROOT`；`STATIC_URL` 只是浏览器请求前缀，不是磁盘路径。样式源文件能在开发模式下找到，不意味着关闭调试以后仍有人提供它。

本例选择 WhiteNoise：紧跟 `SecurityMiddleware`，从已收集目录提供 CSS，并使用带内容哈希的文件名。它适合本例的静态资源，不负责用户上传文件、备份或数据库持久化。图中 CSS 命中直接回浏览器；HTML 才继续进入视图与数据库。文件丢失时先错在静态交付链，而不是主题查询。

图中的 CSS 丢失故障假设哈希清单仍在，只缺发布文件。若连 `staticfiles.json` 都没生成，Manifest 存储可能在模板生成 CSS 地址时抛出“缺少清单条目”的异常，导致 **HTML 500**。所以静态配置错误不一定只表现为 CSS 404，必须读日志确认。

### 5. 发布边界：代码版本、数据版本和平台约定

依赖清单回答“装什么”，迁移文件回答“数据库应长什么样”，部署配置回答“何时执行什么”。Git 记录代码、迁移和经审查的配置，不应记录密钥、本机数据库或收集产物。`migrate` 使用已提交的迁移；不要在发布时临时 `makemigrations`。

一次发布要按阶段找日志：安装失败看构建日志；密钥缺失看启动日志；缺表看迁移和运行日志；静态 404 看文件路径与收集记录。`collectstatic` 不创建数据库表，`migrate` 也不会生成 CSS。下面的 YAML 对照与沙盒命令分别验证这些职责，不能用“平台显示绿色”替代检查。

### 2. 配置：从启动入口就拒绝缺密钥

完整替换 `learning_log/settings.py` 为第一段，再把后两段按顺序追加到**同一文件**。`os.environ.get()` 只读取进程环境，不会自动加载 `.env`。本例默认关闭调试；只有显式 `DJANGO_DEBUG=1` 才打开，发布环境不要设置它。

```python title="learning_log/settings.py"
import os
from pathlib import Path
from django.core.exceptions import ImproperlyConfigured

BASE_DIR = Path(__file__).resolve().parent.parent
SECRET_KEY = os.environ.get("DJANGO_SECRET_KEY", "")
if len(SECRET_KEY) < 50:
    raise ImproperlyConfigured("DJANGO_SECRET_KEY must be at least 50 chars")
DEBUG = os.environ.get("DJANGO_DEBUG", "0") == "1"
ALLOWED_HOSTS = [h.strip() for h in os.environ.get(
    "DJANGO_ALLOWED_HOSTS", "localhost,127.0.0.1"
).split(",") if h.strip()]
INSTALLED_APPS = [
    "django.contrib.auth", "django.contrib.contenttypes",
    "django.contrib.sessions", "django.contrib.messages",
    "django.contrib.staticfiles", "django_bootstrap5",
    "learning_logs", "accounts",
]
ROOT_URLCONF = "learning_log.urls"
WSGI_APPLICATION = "learning_log.wsgi.application"
DATABASES = {"default": {
    "ENGINE": "django.db.backends.sqlite3",
    "NAME": BASE_DIR / "db.sqlite3",
```

### 3. 数据与视图：美化不能绕开所有权

模型沿用共同项目的命名。这里不依赖 `__str__` 显示标签，模板明确使用 `topic.text`；两种模型都带创建时间，条目按新到旧排序。

```python title="learning_logs/models.py"
from django.conf import settings
from django.db import models

class Topic(models.Model):
    owner = models.ForeignKey(settings.AUTH_USER_MODEL,
                              on_delete=models.CASCADE)
    text = models.CharField(max_length=200)
    date_added = models.DateTimeField(auto_now_add=True)

class Entry(models.Model):
    topic = models.ForeignKey(Topic, on_delete=models.CASCADE,
                              related_name="entries")
    text = models.TextField()
    date_added = models.DateTimeField(auto_now_add=True)

    class Meta:
        ordering = ["-date_added", "-pk"]
```

表单只开放条目正文；关联哪个主题，由服务端从经过授权的查询结果决定。

```python title="learning_logs/forms.py"
from django import forms
from .models import Entry

class EntryForm(forms.ModelForm):
    class Meta:
        model = Entry
        fields = ["text"]
        labels = {"text": "条目内容"}
        widgets = {"text": forms.Textarea(attrs={"rows": 3})}
```

主题页同时显示已有条目和新增表单。`request.POST or None` 在空 POST 时会错误地得到未绑定表单，因此这里显式判断请求方法。成功后重定向，避免刷新页面重复提交。

```python title="learning_logs/views.py"
from django.contrib.auth.decorators import login_required
from django.shortcuts import get_object_or_404, redirect, render
from .forms import EntryForm
from .models import Topic

@login_required
def index(request):
    topics = Topic.objects.filter(owner=request.user).order_by("pk")
    return render(request, "learning_logs/index.html", {"topics": topics})

@login_required
def topic(request, pk):
    selected = get_object_or_404(Topic, pk=pk, owner=request.user)
    form = EntryForm(request.POST if request.method == "POST" else None)
    if request.method == "POST" and form.is_valid():
        entry = form.save(commit=False)
        entry.topic = selected
        entry.save()
        return redirect("learning_logs:topic", pk=pk)
    return render(request, "learning_logs/topic.html", {
        "topic": selected, "form": form,
    })
```

### 8. Git 微实验：保存、比较，再安全恢复

这段支持附录 D 的本地版本管理范围，不是远程部署。Git 把**工作区**（正在编辑的文件）、**暂存区**（下次准备提交的内容）和**提交快照**（本地历史）分开：`add` 选择内容进入暂存区，`commit` 把暂存区保存成快照，`log` 查看历史。`git diff` 比较工作区与暂存区，`git diff --cached` 比较暂存区与当前提交；刚创建但尚未跟踪的文件不会出现在普通 `diff` 中，要先用 `status` 发现它们。

<Callout type="warning" title="只在一次性的临时仓库练习">

恢复会覆盖指定文件的未暂存修改；未提交且没有备份的内容可能永久丢失。先读差异、复制文件到仓库外，再明确恢复对象，不使用 `reset --hard`、`clean -fd` 或对整个目录盲目恢复。下面不操作 Learning Log 工程或本站仓库，不连接远程，也不需要真实密钥。

</Callout>

在 macOS/Linux 的 Bash 或 Zsh 中按顺序运行四段，保持同一个终端会话，需要 Git 2.23 或以上（`restore` 从该版本提供）。第一段创建唯一临时目录；每个 Git 操作都用 `-C` 明确目标，`${git_repo:?}` 在变量丢失时直接报错，避免落到当前项目。若任何命令失败，先停止排错，不跳到下一段。不要把路径变量改成已有项目。

```bash
# git-lab-1：准备；只写临时目录。
git --version
git_lab=$(mktemp -d "${TMPDIR:-/tmp}/pcc-git.XXXXXX") || exit 1
git_repo="$git_lab/repo"
mkdir "$git_repo" "$git_lab/backup" "$git_lab/no-hooks"
git -C "${git_repo:?}" -c init.templateDir= init
cat > "$git_repo/.gitignore" <<'IGNORE'
.env
.env.*
*.sqlite3
*.db
*.pem
*.key
.venv/
IGNORE
printf 'release=local-check\n' > "$git_repo/release-note.txt"
printf 'DEMO_ONLY=not-a-secret\n' > "$git_repo/.env"
printf 'fake database, not SQLite\n' > "$git_repo/db.sqlite3"
git -C "${git_repo:?}" status --short
git -C "${git_repo:?}" check-ignore .env db.sqlite3
```

预期 `status --short` 只有 `?? .gitignore` 和 `?? release-note.txt`；`??` 表示未跟踪。`check-ignore` 应列出两个模拟文件。真实 `.env`、数据库和密钥**不能入版本**；`.gitignore` 只影响未跟踪文件，不会把已经入库的秘密从历史中抹去，也不是秘密扫描器。若真实密钥已经泄漏，应先撤销／轮换，再处理历史与访问范围，不能只补一条忽略规则。

```bash
# git-lab-2：只暂存点名的两个教学文件。
git -C "${git_repo:?}" add -- .gitignore release-note.txt
git -C "${git_repo:?}" status --short
git -C "${git_repo:?}" diff --cached --stat
git -C "${git_repo:?}" -c user.name='Local Git Learner' \
  -c user.email='learner@example.invalid' \
  -c commit.gpgSign=false -c core.hooksPath="$git_lab/no-hooks" \
  commit -m 'Save local release note'
git -C "${git_repo:?}" log -1 --oneline
git -C "${git_repo:?}" status --short
```

暂存后应看到两个 `A `（左列表示暂存区的新增）；提交后 `log` 出现一条带短哈希的记录，最后的状态输出为空。提交身份只是虚构标签，`-c` 仅对本条命令生效，不改全局配置；空模板、空钩子目录与禁用签名让这个小仓库不执行自定义提交脚本。这里的 `commit` 只保存本地快照，绝不意味着已经上传或发布。

```bash
# git-lab-3：制造一处未暂存修改，先观察，再在仓库外备份。
printf 'release=broken-css-path\n' > "${git_repo:?}/release-note.txt"
git -C "${git_repo:?}" status --short
git -C "${git_repo:?}" diff -- release-note.txt
git -C "${git_repo:?}" diff --cached -- release-note.txt
cp "$git_repo/release-note.txt" "$git_lab/backup/release-note.before-restore.txt"
git -C "${git_repo:?}" diff -- release-note.txt > "$git_lab/backup/change.patch"
cat "$git_lab/backup/release-note.before-restore.txt"
```

此时状态是 ` M release-note.txt`（右列表示工作区修改）；普通差异应有 `-release=local-check` 与 `+release=broken-css-path`，而暂存差异为空。仓库外副本应含 `release=broken-css-path`，补丁记录这次文本变化。**确认这两份备份存在且内容正确后**，再执行恢复。备份目录和小仓库都在临时路径，系统清理后可能消失；真实工程需另做持久且安全的备份。

```bash
# git-lab-4：仅恢复这个文件；不要改成整个目录。
test -s "${git_lab:?}/backup/change.patch" &&
  cmp -s "${git_repo:?}/release-note.txt" "$git_lab/backup/release-note.before-restore.txt" &&
  git -C "${git_repo:?}" restore -- release-note.txt
cat "$git_repo/release-note.txt"
git -C "${git_repo:?}" diff --exit-code -- release-note.txt
git -C "${git_repo:?}" status --short
```

前三行用 `&&` 串联：只有补丁非空、`cmp -s` 确认副本与当前文件逐字一致，才允许恢复；否则保留原文件，回到备份步骤检查，不删掉保护条件。

预期文件恢复为 `release=local-check`，差异命令退出码为 0，状态输出为空，仓库外副本仍保留错误版本。这里 `restore -- 文件` 默认从**暂存区**恢复工作区；本例提交后没有再次 `add`，暂存区恰好与当前提交 `HEAD` 一致。若你已暂存新内容，它不会替你回到旧提交；应先分别检查两个 `diff`，不要靠重复恢复来碰运气。

这个实验仅恢复一个文本文件，不切换版本、不撤销提交、更不操作数据库。实际交付要记录提交哈希和迁移状态：**回退代码不回退数据库**，旧代码未必兼容新表结构。数据库恢复须另外审核迁移、备份及恢复方案；静态产物也要与代码版本匹配。下一节的检查和后文排错表验证的是这些边界，不是让 Git 包办发布。

```python title="learning_logs/tests.py（追加3）"
        self.assertEqual(self.client.get("/", HTTP_HOST="evil.invalid").status_code, 400)

        self.assertNotEqual(url, "/static/learning_logs/app.css")
        with self.assertNumQueries(0):
            response = self.client.get(url)
        self.assertEqual(response.status_code, 200)
        body = b"".join(response.streaming_content)
```

## 常见误区：按最先出错的边界找原因

<Callout type="trap" title="首页 200，但没有样式">

**现象 →** 页面内容存在，按钮没有 Bootstrap 外观。

**原因 →** HTML、外部 Bootstrap 资源和本地 CSS 是不同请求。

**修法 →** 分别检查资源 URL；对本地文件核对 collectstatic 与 STATIC_ROOT，不能只重跑数据库迁移。用图的静态故障分支定位。

</Callout>

<Callout type="trap" title="设置 DEBUG=False 后全站 400">

**现象 →** 正常路由也收到 Bad Request。

**原因 →** Host 未在 ALLOWED_HOSTS，或把带协议的整段网址当成主机名。

**修法 →** 在环境中列出准确主机名并查 DisallowedHost；不要用星号绕过检查，CSRF 的可信来源又是另一项设置。

</Callout>

<Callout type="trap" title="错误页面写好了，仍看见堆栈">

**现象 →** 请求显示调试详情，或测试直接抛异常。

**原因 →** DEBUG 仍开启，或测试客户端默认重新抛出异常。

**修法 →** 用独立进程核对调试开关；测试 500 时关闭异常重抛，并断言正文没有敏感标记、日志确有记录。

</Callout>

<Callout type="trap" title="推送了代码，就以为数据库也被上传">

**现象 →** 应用能启动，查主题却报缺表，或者远程没有本地笔记。

**原因 →** Git 不传递数据库状态；迁移只管理结构，不搬运用户数据。

**修法 →** 应用既有迁移，另行设计数据迁移与备份。本章只验证沙盒数据库，不执行真实推送。

</Callout>

## 小结与练习

- 两个断点分别控制内容列数与导航展开。
- 表单样式与卡片不能替代认证、验证和所有权检查。
- 环境、迁移、静态和进程必须分别验收。
- 历史平台配置不是当前可执行部署承诺。
- 200、400、404、500 与启动失败指向不同边界。
