## 直觉引入

学运维自动化像盖供水系统。你得先会拧水龙头（运维基础：Python 环境与标准库），再会改自家水管（系统管理：文件与进程），然后把水接到整栋楼（网络自动化：远程批量操作），最后装上水表和报警阀（高级运维：监控告警与配置管理）。只会拧龙头的人，永远管不了一栋楼。

本书以 Python 自动化运维为蓝本，带你从「能跑脚本」跨越到「批量、可重复、可监控」的工程化运维。全书按「基础 → 系统 → 网络 → 高阶」四步推进，每一步都建立在前一步的基础上。

没有运维基础，你不知道脚本该放哪个环境跑；没有系统管理，你操控不了本机文件进程；没有网络自动化，你只能一台台手动操作；没有高级运维，你的系统出事了才知道、改配置全靠手。

## 概念讲解

### 四大板块

全书按学习递进分为四个板块：

1. **运维基础**（第 1-2 章）：学习地图与运维基础。建立 Python 在运维中的角色认知，掌握环境管理（虚拟环境、依赖）与常用标准库（os/sys/subprocess 入门）。
2. **系统管理**（第 3-4 章）：文件操作与进程管理。用 pathlib 操控文件、用 subprocess/psutil 管理进程，这是单机运维最频繁的操作。
3. **网络自动化**（第 5-7 章）：网络自动化、SSH·paramiko、网页抓取。从单机走向多机，实现批量远程执行与数据采集。
4. **高级运维**（第 8-10 章）：监控告警、配置管理、总复习。构建可观测、可重复的运维闭环。

### 为什么按这个顺序学

<Term def="学习递进链：基础筑底、系统练手、网络成网、高阶闭环，每步把「能跑脚本」提升到「批量、可重复、可监控」。">

按这个顺序学的核心价值在于建立**递进能力链**。基础筑底——没有环境管理和标准库认知，脚本无处安放。系统练手——文件和进程是单机运维的原子操作，也是远程操作的结果处理基础。网络成网——从单机推到多机，批量与远程依赖前两步的能力。高阶闭环——监控告警和配置管理把零散脚本组织成可观测、可重复的体系。

</Term>

### 学习路径建议

**推荐路径**：学习地图 → 运维基础 → 文件操作 → 进程管理 → 网络自动化 → SSH·paramiko → 网页抓取 → 监控告警 → 配置管理 → 总复习。

前两个板块必须按顺序学，系统管理是网络自动化的单机地基。网络自动化三章可在系统管理基础上灵活推进。高级运维放最后，因为监控和配置管理要把前面所有能力串成闭环。

## 代码对照

```python
# 运维递进：从环境管理到监控闭环

# Layer 1: 运维基础——环境与标准库
import os, sys, subprocess
print(sys.executable)            # 当前 Python 解释器，确认环境
print(os.getcwd())               # 当前工作目录

# Layer 2: 系统管理——文件与进程
from pathlib import Path
for f in Path("/var/log").glob("*.log"):    # pathlib 批量遍历
    print(f.name, f.stat().st_size)

import psutil
for p in psutil.process_iter(['pid', 'name', 'cpu_percent']):
    if p.info['cpu_percent'] and p.info['cpu_percent'] > 50:
        print(f"高 CPU: {p.info}")          # 找出吃 CPU 的进程

# Layer 3: 网络自动化——批量远程
# (示意) paramiko 批量 SSH 执行同一命令
# for host in hosts:
#     ssh.exec_command("uptime")

# Layer 4: 高阶闭环——监控告警
def check_disk(threshold=0.9):
    for part in psutil.disk_partitions():
        usage = psutil.disk_usage(part.mountpoint).percent / 100
        if usage > threshold:
            alert(f"{part.mountpoint} 磁盘使用 {usage:.0%}")  # 超阈值告警

def alert(msg):
    print(f"[ALERT] {msg}")      # 实际可接邮件/钉钉/飞书

check_disk()
```

从确认环境、遍历日志、找高 CPU 进程，到批量 SSH、磁盘告警——每一步都建立在前一步的基础上。

## 常见误区

<Callout type="trap">

**误区：跳过系统管理直接学网络自动化**

很多人急着学批量 SSH、跳过文件操作和进程管理。结果能在远程跑一句命令，却处理不好返回的输出、管不好远程服务、看不懂系统指标——因为没建立单机运维的原子能力。系统管理是网络自动化的地基。

</Callout>

<Callout type="trap">

**误区：把运维脚本写成「一次性命令拼盘」**

不抽象函数、不处理错误、不记日志，脚本能跑就丢。规模一上来就顾不过来、出问题没法复盘。运维自动化的核心是「可重复、可监控」，从第一个脚本起就要有函数化、日志、返回码意识。

</Callout>

<Exercises>

**问题 1**：本书四大板块的顺序是什么？为什么按这个顺序学习？

<Answer>

四大板块顺序：运维基础 → 系统管理 → 网络自动化 → 高级运维。按这个顺序学习是因为建立了递进能力链：1. 基础筑底——没有环境管理和标准库认知，脚本无处安放；2. 系统练手——文件和进程是单机运维的原子操作，也是远程操作结果的处理基础；3. 网络成网——从单机推到多机依赖前两步能力；4. 高阶闭环——监控和配置管理要把前面所有能力串成闭环。跳过任何一层，上层能力就会悬空。

</Answer>

**问题 2**：为什么说运维自动化的核心是「用代码替代手工，让运维变工程」？从可重复性和可监控性说明。

<Answer>

手工运维依赖人，每次做法可能不同、出问题难复盘、规模一大顾不过来。用代码替代手工的两个核心价值：1. 可重复性——脚本是「操作的可执行文档」，每次运行一致、可版本化、可审查，批量操作 100 台和 1 台一样可靠；2. 可监控性——代码化运维天然可观测，执行有日志、返回码、可接入告警，手工的「我执行完了」无法度量。「让运维变工程」意味着运维从「救火手艺」变成有设计、有版本、有度量的工程实践。

</Answer>
