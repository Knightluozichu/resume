## 从一次运维变更开始

先预测：脚本在一台测试机成功，是否就能安全用于批量生产？不能。还要说明目标、权限、超时、部分失败、证据和回滚。必须落进可观察的执行链。


## 核心模型与责任

业务服务监控必须从可观察信号回到用户体验：配置是否漂移、目录是否完整、通知是否送达、HTTP是否在预算内返回正确内容。每个探针都要给出时间、目标和判定依据。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

difflib文件内容差异适合生成统一diff和HTML报告。比较前先固定编码、换行和敏感字段处理；差异报告用于解释变化，是否允许变化仍由发布清单或策略决定。
```python
from difflib import unified_diff
before = open('nginx.old', encoding='utf-8').readlines()
after = open('nginx.new', encoding='utf-8').readlines()
print(''.join(unified_diff(before, after, fromfile='old', tofile='new')))
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

filecmp文件与目录差异可快速找出只存在一侧、不同和异常文件。默认浅比较可能只看stat信息，关键校验应计算内容摘要并防止符号链接越过预期目录。

```python
from pathlib import Path
from hashlib import sha256
def digest(path: Path) -> str:
    return sha256(path.read_bytes()).hexdigest()
assert digest(Path('source.conf')) == digest(Path('backup.conf'))
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

smtplib邮件通知由消息构造、TLS、认证、收件人和发送结果组成。告警内容应含事件ID与恢复链接，凭据来自密钥存储；发送失败进入重试队列，不能阻塞主采集循环。
Web服务质量探测同时检查DNS、连接、TLS、状态码、时延和业务断言。成功状态码不代表页面正确，重定向和证书错误也不能被静默忽略；超时必须覆盖连接与读取阶段。
```python
import requests
response = requests.get('https://example.com/health', timeout=(2, 4))
response.raise_for_status()
assert response.json()['status'] == 'ok'
print(response.elapsed.total_seconds())
```
