## 从一次运维变更开始

先预测：脚本在一台测试机成功，是否就能安全用于批量生产？不能。还要说明目标、权限、超时、部分失败、证据和回滚。必须落进可观察的执行链。


## 核心模型与责任

定制业务质量报表把原始监控转换为可审计结论。报表必须标明数据窗口、时区、缺失值和聚合规则，图表只是证据入口，原始数据与生成版本仍需可追溯。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

XlsxWriter流量周报可生成工作表、公式和图表，但公式引用、单位和日期格式要由测试验证。写入时使用常量内存模式处理大数据，关闭workbook前检查异常。
```python
import xlsxwriter
book = xlsxwriter.Workbook('traffic.xlsx')
sheet = book.add_worksheet('weekly')
sheet.write_row(0, 0, ['day', 'bytes'])
sheet.write_row(1, 0, ['Mon', 1024])
chart = book.add_chart({'type': 'line'})
chart.add_series({'values': '=weekly!$B$2:$B$2'})
sheet.insert_chart('D2', chart)
book.close()
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

rrdtool网卡流量图体现固定步长、数据源类型、heartbeat和归档策略。COUNTER适合累计字节，GAUGE适合瞬时值；更新间隔超过heartbeat会产生unknown而不是虚构插值。

```python
import rrdtool
rrdtool.create('net.rrd', '--step', '60', 'DS:bytes:COUNTER:120:0:U', 'RRA:AVERAGE:0.5:1:1440')
rrdtool.update('net.rrd', 'N:1048576')
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

动态路由轨迹图把每跳地址、自治域或位置映射为路径。ICMP可能被过滤，星号不等于链路中断；图中要保留采样时间、目标和未响应跳，不能用地理连线冒充真实物理线路。
TCP探测与可视化证据应关联连接时延、端口、失败阶段与路由变化。一次traceroute和一次成功连接只能说明当时路径，趋势判断需要重复采样及一致时钟。
```python
import socket, time
started = time.monotonic()
with socket.create_connection(('example.com', 443), timeout=3):
    latency = time.monotonic() - started
print({'target': 'example.com:443', 'seconds': latency})
```
