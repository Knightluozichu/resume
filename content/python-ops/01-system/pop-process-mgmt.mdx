## 直觉引入

管进程像管一群员工。`subprocess.run` 是「派一个任务，等他干完拿结果回来」——简单任务用它。`subprocess.Popen` 是「派一个任务，他不阻塞你，你可以随时看他干到哪、给他塞新指令」——长任务、流式输出用它。

`psutil` 则是「办公室监控屏」——CPU、内存、磁盘、网络、进程谁在忙，一目了然。运维排查「机器为什么卡」「谁在吃 CPU」，全靠它。

这两个库一个管「跑命令」、一个管「看状态」，是单机运维的核心工具。用错（shell=True 注入、Popen 管长驻服务），轻则脚本崩、重则安全漏洞或服务不可靠。

## 概念讲解

### subprocess：启动子进程

<Term def="subprocess.run 同步阻塞拿结果；Popen 异步可交互管道。默认 shell=False 传列表参数，避免命令注入。">

`subprocess.run` 是同步阻塞封装，等子进程跑完返回 `CompletedProcess`（含 stdout/stderr/returncode），适合一次性调用。`subprocess.Popen` 是异步底层类，创建子进程后立即返回，父进程可继续，通过 `.communicate()`/`.poll()`/管道与子进程交互，适合流式输出、长进程、并行多进程。

</Term>

### shell=False 的安全基线

`shell=True` 让参数经 shell 解析，有**命令注入**风险：`run(f"ping {host}", shell=True)` 中 host 含 `; rm -rf /` 就会执行删除。默认 `shell=False` 传列表 `run(['ping', host])`，每个参数独立 argv 不经 shell，注入字符只是普通字符串。运维脚本默认 shell=False 是安全基线。

### psutil：监控指标

psutil 跨平台（Linux/macOS/Windows）读取五大维度：`cpu_percent()`、`virtual_memory()`、`disk_usage()`、`net_io_counters()`、`process_iter()`。是监控告警的数据源、排查「谁在吃资源」的标准工具。

### 长驻服务交给专业工具

Popen 管长驻服务有局限（无自动重启、无开机自启、无依赖编排）。生产环境用 systemd（Linux 标准）、supervisord（跨平台）、Kubernetes（云原生）。Python 脚本负责生成配置、调用 systemctl、轮询健康检查，而非自己造进程管理器。

## 代码对照

```python
import subprocess
import psutil

# 1. run 同步调用（默认 shell=False，安全）
r = subprocess.run(['df', '-h'], capture_output=True, text=True, check=True)
print(r.stdout[:80])
print(r.returncode)              # 0

# 2. Popen 异步流式读输出
proc = subprocess.Popen(['tail', '-f', 'app.log'],
                        stdout=subprocess.PIPE, text=True)
for line in proc.stdout:         # 流式逐行读
    if 'ERROR' in line:
        print(line.strip())
    if some_stop_condition:
        proc.terminate()         # 主动停止
        break

# 3. psutil 排查高 CPU 进程
# 预热 cpu_percent（首次返回 0）
for p in psutil.process_iter(['pid', 'name', 'cpu_percent']):
    pass
import time; time.sleep(0.5)
for p in psutil.process_iter(['pid', 'name', 'cpu_percent']):
    cpu = p.info['cpu_percent']
    if cpu is not None and cpu > 50:
        print(f"PID={p.info['pid']} {p.info['name']} CPU={cpu:.1f}%")

# 4. psutil 系统指标
print(f"CPU 总占用: {psutil.cpu_percent(interval=1)}%")
mem = psutil.virtual_memory()
print(f"内存: {mem.percent}% ({mem.used//1024//1024}MB/{mem.total//1024//1024}MB)")
print(f"磁盘 /: {psutil.disk_usage('/').percent}%")

# 5. 管理子进程（终止）
p = subprocess.Popen(['sleep', '300'])
p.terminate()                    # 优雅终止（SIGTERM）
p.wait(timeout=5)                # 等退出，超时抛 TimeoutExpired
```

`cpu_percent` 首次调用返回 0，需两次采样间隔才有意义——生产中先预热再读。`terminate()` 发 SIGTERM 优雅退出，`kill()` 发 SIGKILL 强杀。

## 常见误区

<Callout type="trap">

**误区：用 `shell=True` 拼字符串命令**

`run(f"ping {host}", shell=True)` 中 host 含 `; rm -rf /` 会命令注入。默认 shell=False 传列表 `run(['ping', host])`，参数独立 argv 不经 shell。运维脚本默认 shell=False 是安全基线，只有需要管道/通配符且输入可信时才用 shell=True。

</Callout>

<Callout type="trap">

**误区：用 Popen 管生产长驻服务**

Popen 管长驻服务无自动重启、无开机自启、无依赖编排、日志管理弱。生产环境用 systemd（Linux 标准，支持 cgroups 资源限制、journald 日志）、supervisord（跨平台）、Kubernetes（云原生）。Python 脚本负责生成 unit 配置、调用 systemctl，而非自己 reimplement 进程管理器。

</Callout>

<Exercises>

**问题 1**：`subprocess.run` 和 `Popen` 的核心区别是什么？各适合什么场景？

<Answer>

run 是同步阻塞封装，等子进程跑完返回 CompletedProcess（含 stdout/stderr/returncode），适合一次性调用拿结果。Popen 是异步底层类，创建子进程后立即返回，父进程可继续，通过 communicate/poll/管道与子进程交互，适合流式读取输出（如 tail -f）、与子进程交互、并行启动多进程、长时间运行的后台进程。现代运维优先 run（更安全简洁），需要异步/管道/交互时才下沉到 Popen。

</Answer>

**问题 2**：为什么不要用 `shell=True`？正确做法是什么？

<Answer>

shell=True 让参数经 shell 解析（/bin/sh -c），有命令注入风险：若命令含用户输入，攻击者可用 `;`、`$()`、反引号注入任意命令，如 `run(f"ping {host}", shell=True)` 中 host 传入 `; rm -rf /` 会执行删除。即使无恶意输入，shell 也会因空格、特殊字符误解析。正确做法：传列表参数、shell=False（默认）：`run(['ping', host])`，每个参数作为独立 argv 不经 shell，注入字符只是普通字符串。只有确实需要 shell 管道/通配符/变量展开且输入可信时才 shell=True 并严格校验输入。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="subprocess.run">

同步阻塞的子进程调用封装，等命令跑完返回 CompletedProcess。配合 capture_output/text/check 一次性拿结果，适合简单任务。

</GlossaryItem>

<GlossaryItem term="Popen">

异步底层子进程类，创建后立即返回，可读写管道、流式输出、与子进程交互。适合长进程、流式输出、并行多进程。

</GlossaryItem>

<GlossaryItem term="命令注入">

shell=True 时参数经 shell 解析，攻击者可用 `;`、`$()` 等注入任意命令。防御：默认 shell=False 传列表参数，参数独立 argv 不经 shell。

</GlossaryItem>

<GlossaryItem term="psutil">

跨平台系统指标库，读取 CPU/内存/磁盘/网络/进程五大维度。是监控告警的数据源、排查「谁在吃资源」的标准工具。

</GlossaryItem>

</Glossary>
