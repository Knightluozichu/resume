## 核心模型与责任

Ansible集中化管理以无代理SSH连接和模块返回为基础。控制节点生成任务计划，目标节点执行幂等模块；changed、failed和diff共同说明本次收敛发生了什么。 <Term def="YAML与Inventory分别描述任务数据和资产分组。变量优先级很复杂，关键配置应限制定义位置；密钥使用Vault或外部密钥系统，库存中的主机身份需可审计。">YAML与Inventory</Term>

本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

YAML与Inventory分别描述任务数据和资产分组。变量优先级很复杂，关键配置应限制定义位置；密钥使用Vault或外部密钥系统，库存中的主机身份需可审计。 <Term def="模块与目标匹配决定影响范围。先用list-hosts或check模式验证pattern，对破坏性任务使用limit和serial；shell模块只有在专用模块无法表达时使用，并显式给出changed_when。">模块与目标匹配</Term>

```python
all:
  children:
    web:
      hosts:
        app01.example:
        app02.example:
      vars:
        ansible_user: deploy
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

模块与目标匹配决定影响范围。先用list-hosts或check模式验证pattern，对破坏性任务使用limit和serial；shell模块只有在专用模块无法表达时使用，并显式给出changed_when。 <Term def="playbook、角色与包含把任务、handler、模板和默认变量组织成可复用单元。角色接口是变量契约，不应依赖调用目录里的隐式全局变量；handler只在变化时触发。">playbook、角色与包含</Term>

<PopAnsibleBoundaryLab />

```python
- name: Install and start nginx
  hosts: web
  serial: 1
  become: true
  tasks:
    - ansible.builtin.package:
        name: nginx
        state: present
    - ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

playbook、角色与包含把任务、handler、模板和默认变量组织成可复用单元。角色接口是变量契约，不应依赖调用目录里的隐式全局变量；handler只在变化时触发。 <Term def="Facts、变量、条件与循环驱动跨系统差异。Facts可能过期或昂贵，条件引用前先设默认值；循环任务保持标签明确，失败结果应能定位具体item。">Facts、变量、条件与循环</Term>

Facts、变量、条件与循环驱动跨系统差异。Facts可能过期或昂贵，条件引用前先设默认值；循环任务保持标签明确，失败结果应能定位具体item。 <Term def="验证集中化管理平台Ansible详解的授权、结果和失败路径。">集中化管理平台Ansible详解验收边界</Term>

```python
- name: Render site configuration
  ansible.builtin.template:
    src: site.conf.j2
    dest: /etc/nginx/conf.d/site.conf
    validate: 'nginx -t -c %s'
  notify: Reload nginx
```

## 实战验证清单

在隔离环境执行三段代码：先只读采集，再模拟一台目标超时，最后验证失败不会改变未授权对象。记录命令或API参数、开始结束时间、目标清单、返回码、标准错误、制品摘要和回滚结果。涉及网络扫描、远程命令或配置发布时，必须使用经过批准的测试资产。

## 常见误区

<Callout type="trap" title="只要Ansible集中化管理能运行就可以批量">
单机成功没有证明目标选择、并发预算、部分失败和回滚。扩大范围前必须完成预览、限流、逐主机结果与停止条件。
</Callout>

<Callout type="trap" title="原书工具API可以原样用于今天的生产">
原书出版于2014年，部分工具和安全默认已经变化。应保留架构思想，依据当前官方文档迁移API、主机密钥、TLS、权限和依赖版本。
</Callout>
