## 核心模型与责任

Python大数据应用章节用Web日志展示分布式批处理。先定义输入格式、键和值，再把可独立并行的map与需要聚合的reduce分开；坏行和编码错误进入单独计数。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

Hadoop部署包括JDK、HDFS、YARN、节点角色和配置一致性。自动化先校验主机名、时间、磁盘和权限，再格式化NameNode；格式化是破坏性步骤，不可放进重复运行脚本。
```python
# mapper.py
import sys
for line in sys.stdin:
    try:
        fields = line.rstrip().split()
        status, size = fields[8], int(fields[9])
        print(f'{status}\t{size}')
    except (IndexError, ValueError):
        print('bad_line\t1', file=sys.stderr)
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

原生Python MapReduce通过stdin读取、stdout输出制表符分隔键值。日志只写stderr，mapper与reducer保持流式和确定性；组合器只能用于满足结合律与交换律的聚合。

```python
# reducer.py
import sys
from itertools import groupby
for key, rows in groupby((line.rstrip().split('\t', 1) for line in sys.stdin), key=lambda row: row[0]):
    print(key, sum(int(value) for _, value in rows), sep='\t')
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

mrjob框架把step、协议、运行器和配置封装起来，可在本地先验证再提交Hadoop。输入输出协议要显式，任务参数与代码版本写进作业元数据。
Web日志多维统计包括流量、状态码、分钟请求、来源IP和文件访问。维度组合会膨胀键空间，隐私字段应脱敏，迟到数据和时区规则要在报表中说明。
```python
from mrjob.job import MRJob
class StatusBytes(MRJob):
    def mapper(self, _, line):
        fields = line.split()
        yield fields[8], int(fields[9])
    def reducer(self, status, sizes):
        yield status, sum(sizes)
```
