## 核心模型与责任

Fabric批量运维把SSH命令封装成可组合任务。原书基于Fabric 1的fabfile与env，现代Fabric使用Connection和task；迁移时要逐项验证角色、网关、sudo和失败传播。 <Term def="fab参数与fabfile定义任务入口、主机和参数。任务函数保持幂等，把配置与密钥从源码移出，并让每台主机返回结构化结果；命令字符串只拼接经过引用的值。">fab参数与fabfile</Term>

本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

fab参数与fabfile定义任务入口、主机和参数。任务函数保持幂等，把配置与密钥从源码移出，并让每台主机返回结构化结果；命令字符串只拼接经过引用的值。 <Term def="环境、角色与网关把目标分组及跳板拓扑显式化。角色不能代替资产清单，动态主机需来自受信库存；并行发布限制批次，避免错误同时扩散到全部节点。">环境、角色与网关</Term>

```python
from fabric import task
@task
def uptime(c):
    result = c.run('uptime', hide=True, warn=True)
    if result.failed:
        raise RuntimeError(result.stderr)
    print(result.stdout.strip())
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

环境、角色与网关把目标分组及跳板拓扑显式化。角色不能代替资产清单，动态主机需来自受信库存；并行发布限制批次，避免错误同时扩散到全部节点。 <Term def="文件打包上传与校验应生成版本化归档和SHA-256摘要，上传到临时目录，校验后解压到新版本目录。失败时旧版本软链接保持不变。">文件打包上传与校验</Term>

<PopFabricBoundaryLab />

```python
from fabric import Connection
connection = Connection(host='app01', user='deploy', gateway='jump.example')
connection.put('release.tar.gz', remote='/tmp/release.tar.gz.part')
connection.run('sha256sum /tmp/release.tar.gz.part')
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

文件打包上传与校验应生成版本化归档和SHA-256摘要，上传到临时目录，校验后解压到新版本目录。失败时旧版本软链接保持不变。 <Term def="LNMP部署与代码发布要分开基础设施和应用发布。安装包、模板、健康检查、切换与回滚形成事务式流程；Fabric负责编排，不应把不可恢复数据库迁移隐藏在普通发布任务中。">LNMP部署与代码发布</Term>

LNMP部署与代码发布要分开基础设施和应用发布。安装包、模板、健康检查、切换与回滚形成事务式流程；Fabric负责编排，不应把不可恢复数据库迁移隐藏在普通发布任务中。 <Term def="验证系统批量运维管理器Fabric详解的授权、结果和失败路径。">系统批量运维管理器Fabric详解验收边界</Term>

```python
@task
def release(c, version):
    target = f'/srv/app/releases/{version}'
    c.run(f'mkdir -p {target}')
    c.run(f'tar -xzf /tmp/{version}.tar.gz -C {target}')
    c.run(f'ln -sfn {target} /srv/app/current')
    c.run('curl --fail http://127.0.0.1/health')
```
