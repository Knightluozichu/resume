## 核心模型与责任

pexpect批量运维适合只能通过交互终端驱动的遗留程序。优先选择有结构化API的工具；必须使用终端时，把提示符、超时、EOF和错误分支写成显式状态机。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

spawn、run与pxssh覆盖长会话、一次命令和SSH封装。spawn的before与after表示匹配前后数据，编码必须明确；run适合简单命令，pxssh仍需严格主机密钥策略。
```python
import pexpect
child = pexpect.spawn('passwd demo', encoding='utf-8', timeout=5)
child.expect('New password:')
child.sendline(secret)
child.expect('Retype new password:')
child.sendline(secret)
child.expect(pexpect.EOF)
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

expect交互状态机一次匹配多个候选提示并根据返回索引转移。提示符可能本地化、含颜色或随版本变化，应优先使用稳定正则并为未知输出保留失败分支。

```python
patterns = [r'Password:', r'Permission denied', pexpect.TIMEOUT, pexpect.EOF]
index = child.expect(patterns)
if index == 0: child.sendline(secret)
elif index == 1: raise PermissionError(child.before)
else: raise TimeoutError('unexpected terminal state')
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

自动化FTP操作在原书中展示用户名、密码和命令交互；现代生产应改用SFTP或HTTPS，凭据通过安全输入注入。若维护FTP遗留系统，禁止明文跨不可信网络。
远程打包下载需要在远端检查命令退出、归档大小和摘要，再下载到临时文件并原子改名。无论成功失败都关闭会话并清理临时文件，避免半成品被后续任务误用。
