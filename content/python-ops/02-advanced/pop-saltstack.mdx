## 核心模型与责任

SaltStack集中化管理由master、minion、事件总线和状态系统组成。接受minion key前核对身份，目标表达式先预览；返回数据要关联job ID、minion和函数。 <Term def="远程执行与模块适合即时查询和操作，命令模块不是默认选择。执行范围、超时和批次要受控，长期配置转成state，避免临时命令成为无人记录的真实状态。">远程执行与模块</Term>

本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

远程执行与模块适合即时查询和操作，命令模块不是默认选择。执行范围、超时和批次要受控，长期配置转成state，避免临时命令成为无人记录的真实状态。 <Term def="grains静态事实描述操作系统、CPU和自定义标签，适合目标匹配但不存秘密。自定义grain来源需可信，变更后刷新并验证，不能让节点自行声明高权限角色。">grains静态事实</Term>

```python
# 先预览目标，再执行只读函数
salt -C 'G@roles:web and E@app0[1-2]' test.version --out=json
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

grains静态事实描述操作系统、CPU和自定义标签，适合目标匹配但不存秘密。自定义grain来源需可信，变更后刷新并验证，不能让节点自行声明高权限角色。 <Term def="pillar安全数据由master按目标编译后发送给minion，适合分层配置与秘密。仍要最小化暴露、加密后端和审计读取；pillar.get使用明确默认值避免缺失键产生错误配置。">pillar安全数据</Term>

<PopSaltstackBoundaryLab />

```python
# top.sls
base:
  'G@roles:web':
    - match: compound
    - nginx
# pillar.get('service:port', 8080) 提供显式默认值
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

pillar安全数据由master按目标编译后发送给minion，适合分层配置与秘密。仍要最小化暴露、加密后端和审计读取；pillar.get使用明确默认值避免缺失键产生错误配置。 <Term def="state声明式配置通过SLS和requisite表达资源及依赖。先test模式查看变化，文件使用模板和校验，服务只在配置变化后watch重载，失败保持旧配置。">state声明式配置</Term>

state声明式配置通过SLS和requisite表达资源及依赖。先test模式查看变化，文件使用模板和校验，服务只在配置变化后watch重载，失败保持旧配置。 <Term def="验证集中化管理平台Saltstack详解的授权、结果和失败路径。">集中化管理平台Saltstack详解验收边界</Term>

```python
/etc/nginx/conf.d/site.conf:
  file.managed:
    - source: salt://nginx/site.conf.j2
    - template: jinja
    - check_cmd: nginx -t -c
nginx:
  service.running:
    - watch:
      - file: /etc/nginx/conf.d/site.conf
```
