## 核心模型与责任

paramiko批量运维直接实现SSH协议，适合命令与文件传输。连接、认证、执行、读取退出码和关闭资源必须完整；stdout有内容不代表命令成功，stderr和exit_status同样是契约。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

SSHClient与SFTPClient分别管理命令会话和文件操作，底层共享Transport。客户端应设置连接、认证和banner超时，用上下文或finally关闭SFTP、channel、transport与client。
```python
import paramiko
client = paramiko.SSHClient()
client.load_system_host_keys()
client.set_missing_host_key_policy(paramiko.RejectPolicy())
client.connect(host, username=user, key_filename=key, timeout=5)
stdin, stdout, stderr = client.exec_command('uptime', timeout=10)
status = stdout.channel.recv_exit_status()
client.close()
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

密钥认证与主机指纹是信任边界。加载经过审批的known_hosts并使用RejectPolicy，首次指纹通过独立通道核验；AutoAddPolicy会把中间人风险变成永久信任。

```python
with paramiko.SSHClient() as bastion:
    bastion.load_system_host_keys()
    bastion.connect(jump_host, username=jump_user, key_filename=key)
    channel = bastion.get_transport().open_channel('direct-tcpip', (target, 22), ('127.0.0.1', 0))
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

堡垒机远程命令通过direct-tcpip channel把第二段SSH隧道建立在第一段Transport上。每一跳分别验证主机密钥和身份，并记录目标、跳板与退出码。
堡垒机远程文件上传先传到临时名，校验大小与摘要后再远端原子替换。并发批量任务使用有界worker、逐主机结果和失败重试，不能因一台失败掩盖整体状态。
```python
with client.open_sftp() as sftp:
    remote_tmp = '/etc/app.conf.part'
    sftp.put('app.conf', remote_tmp, confirm=True)
    assert sftp.stat(remote_tmp).st_size == Path('app.conf').stat().st_size
    sftp.rename(remote_tmp, '/etc/app.conf')
```
