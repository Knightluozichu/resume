## 核心模型与责任

Func统一网络控制器是原书时代的证书化远程执行框架，学习价值在控制器、minion、模块和结果聚合模型。项目已属历史技术，生产选型应评估Ansible、Salt或现代编排平台。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

目标主机选择与模块把主机pattern映射到远程方法。任何批量入口都要先返回匹配清单、限制并发并逐主机报告；网络分区时不能把未返回节点记成成功。
```python
# 历史Func调用模型的最小抽象
controller = Controller(trusted_inventory)
targets = controller.preview('web-*')
assert targets
result = controller.call(targets, module='command', args=['uptime'], timeout=10)
```

运行前固定测试目标与时间窗，运行后保存结构化结果、耗时和异常类型。不要把打印了几行输出当成成功，也不要让示例凭据进入源码。

## 机制二：状态、网络与批量

自定义Func模块在minion端公开方法和版本。输入执行前验证，命令使用参数列表，返回结构化字典；模块以最小用户运行并通过签名包发布。

```python
class DiskModule:
    version = '1.0'
    def usage(self, mountpoint='/'):
        if mountpoint not in {'/', '/data'}:
            raise ValueError('mountpoint not allowed')
        return {'mountpoint': mountpoint, 'percent': read_usage(mountpoint)}
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

非Python API接口让其他语言通过XML-RPC等方式调用控制器。远程接口必须认证授权、限流和版本化，序列化边界拒绝任意对象，错误码与部分失败可机器解析。
Func Facts采集主机事实供查询和决策。事实要带采集时间与schema版本，敏感字段最小化；动态健康信息不应伪装成长期事实，过期缓存必须可识别。
```python
def normalize(results, expected_hosts):
    normalized = {host: {'status': 'missing'} for host in expected_hosts}
    for host, payload in results.items():
        normalized[host] = {'status': 'ok', 'payload': payload}
    return normalized
```
