## 直觉引入

想象你是个快递调度员。每天要给 200 个站点打电话确认状态——如果每次都重新拨号、自我介绍、挂断，效率极低。聪明的做法是保持一条线路不断开，连续问完所有站点；遇到占线就等几秒重拨，而不是傻等。

网络自动化就是这个思路。requests 库是你打电话的工具，Session 是保持的那条线路，timeout 是没人接就挂断重拨的耐心上限，重试机制是占线后自动再拨。把这些组合起来，你就能稳定地批量和几百台设备「通话」。

## 概念讲解

### requests 基础

<Term def="requests 是 Python 最流行的 HTTP 客户端库，封装了 urllib3 连接池，提供简洁的 API 发起 HTTP 请求并处理响应。">

requests 把复杂的 HTTP 协议简化成几个方法：`get` 获取资源、`post` 提交数据、`put`/`delete` 修改删除。响应对象 `resp` 携带状态码、响应头和响应体，用 `resp.json()` 直接解析 JSON，`resp.text` 取文本，`resp.raise_for_status()` 在 4xx/5xx 时抛异常。

</Term>

### 会话复用

<Term def="requests.Session 维护一个连接池，在同一会话内的多次请求复用 TCP 连接，避免重复握手，同时自动保持 Cookie。">

每次 `requests.get()` 都是新连接——DNS 解析、TCP 握手、TLS 协商全套重来。用 `Session` 后，同域名的后续请求复用已建立的连接，延迟可降低 50% 以上。Session 还自动管理 Cookie，适合需要登录态的接口。

</Term>

### 健壮性三要点

<Term def="生产环境请求必须具备的三项保障：超时控制防止挂死、重试机制应对瞬时故障、会话复用提升性能。">

- **超时**：`timeout=(连接超时, 读取超时)`，不设则无限阻塞
- **重试**：捕获异常后重试，配合指数退避（1s→2s→4s）避免雪崩
- **会话**：Session 复用连接池，减少握手开销

</Term>

<Step title="第一步：基础请求与异常处理">

用 `requests.get()` 发起请求，用 `try-except` 捕获网络异常。设置 `timeout` 防止挂死，用 `raise_for_status()` 把 HTTP 错误转为异常。这是最基础的可控请求模式。

</Step>

<Step title="第二步：引入 Session 复用连接">

把单次请求升级为 `Session` 模式——创建一次 session，后续所有请求都走 `session.get()`。连接池自动复用 TCP 连接，Cookie 自动保持。批量调用时性能显著提升。

</Step>

<Step title="第三步：加入重试与指数退避">

在 Session 基础上包装重试逻辑：捕获 `RequestException` 后重试，每次失败后 `time.sleep(2 ** attempt)` 等待更久。用 `HTTPAdapter` 配置底层重试次数，双重保障。

</Step>

<Step title="第四步：批量并发与限流">

用 `ThreadPoolExecutor` 控制并发数，配合信号量限流。单机失败捕获不阻塞，结果分批落盘。这是生产级批量 API 调用的完整模式。

</Step>

## 代码对照

```python
import requests
import time
from requests.adapters import HTTPAdapter
from concurrent.futures import ThreadPoolExecutor, as_completed

# === Level 1: 基础请求 ===
try:
    resp = requests.get("https://api.example.com/status", timeout=5)
    resp.raise_for_status()
    data = resp.json()
except requests.RequestException as e:
    print(f"请求失败: {e}")

# === Level 2: Session 复用 ===
session = requests.Session()
session.mount("https://", HTTPAdapter(max_retries=3))
session.headers.update({"User-Agent": "OpsBot/1.0"})

for host in ["server1", "server2", "server3"]:
    r = session.get(f"https://{host}/api/health", timeout=5)
    print(host, r.status_code)  # 复用连接，更快

# === Level 3: 重试 + 指数退避 ===
def fetch_with_retry(url, retries=3, timeout=5):
    for attempt in range(retries):
        try:
            resp = session.get(url, timeout=timeout)
            resp.raise_for_status()
            return resp.json()
        except requests.RequestException:
            if attempt == retries - 1:
                raise
            time.sleep(2 ** attempt)  # 1s -> 2s -> 4s

# === Level 4: 并发批量 ===
def check_host(host):
    try:
        return host, fetch_with_retry(f"https://{host}/api/health")
    except Exception as e:
        return host, {"error": str(e)}

hosts = [f"node{i}" for i in range(200)]
with ThreadPoolExecutor(max_workers=20) as pool:
    futures = [pool.submit(check_host, h) for h in hosts]
    for f in as_completed(futures):
        host, result = f.result()
        print(host, result)
```

## 常见误区

<Callout type="trap">

**误区：不设 timeout 图省事**

很多人写 `requests.get(url)` 不加 timeout，本地测试没问题，上生产后某台服务器卡死，整个脚本挂住几小时无人察觉。timeout 不是可选项——没有它，一个慢节点就能拖垮整个批量任务。养成习惯：每次请求必带 timeout。

</Callout>

<Callout type="trap">

**误区：重试无退避，打爆服务器**

捕获异常后立即重试，看似合理，但如果 200 个线程同时遇到 503 同时重试，瞬间流量翻倍，把本就过载的服务器彻底打崩。必须加指数退避——每次失败后等待更久，给服务器喘息时间。重试不是越快越好，而是越稳越好。

</Callout>

<Exercises>

**问题 1**：为什么 `requests.Session` 比多次 `requests.get()` 更快？连接复用的原理是什么？

<Answer>

`requests.get()` 每次都创建新连接，完整经历 DNS 解析、TCP 三次握手、TLS 协商，开销大。`Session` 内部维护连接池（由 urllib3 实现），对同一域名的后续请求复用已建立的 TCP 连接，跳过握手和 TLS 协商，延迟可降低 50% 以上。此外 Session 自动管理 Cookie，省去手动传递的麻烦。批量调用同一组服务器时，Session 的性能优势非常明显。

</Answer>

**问题 2**：在生产环境批量调用 200 台设备 API 时，需要考虑哪些健壮性措施？请列出至少四点。

<Answer>

1. **超时控制**：设置连接超时（如 3s）和读取超时（如 10s），防止慢节点挂死整个任务。
2. **重试机制**：捕获异常后重试，配合指数退避（1s→2s→4s）避免雪崩。
3. **会话复用**：用 Session 复用连接池，减少握手开销。
4. **并发控制**：用线程池控制并发数（如 20），避免本机资源耗尽。
5. **限流**：用信号量或令牌桶控制 QPS，防止打爆目标服务器。
6. **容错隔离**：单机失败捕获异常不阻塞其余，结果标记成功/失败/超时。
7. **分批落盘**：结果分批写入，支持断点续跑。

</Answer>

</Exercises>

<Glossary>

<GlossaryItem term="requests">

Python 最流行的 HTTP 客户端库，封装 urllib3 连接池，提供 get/post/put/delete 等简洁 API，自动处理编码、重定向、Cookie，是运维网络自动化的基础工具。

</GlossaryItem>

<GlossaryItem term="Session">

requests.Session 维护连接池和 Cookie，在同一会话内复用 TCP 连接避免重复握手，批量调用时性能显著优于独立请求，是生产环境的标配。

</GlossaryItem>

<GlossaryItem term="指数退避">

重试策略：每次失败后等待时间按指数增长（1s→2s→4s→8s），避免大量客户端同时重试造成雪崩效应，是分布式系统容错的基本模式。

</GlossaryItem>

<GlossaryItem term="HTTPAdapter">

requests 的连接适配器，可配置 max_retries（最大重试次数）和 pool_connections（连接池大小），挂载到 Session 上实现底层重试和连接管理。

</GlossaryItem>

</Glossary>
