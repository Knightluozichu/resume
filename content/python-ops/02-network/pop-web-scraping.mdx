## 直觉引入

想象你在图书馆抄目录。你不是把整本书搬走，而是：找到书架（请求页面）、翻开目录页（解析 HTML）、抄下书名和编号（提取字段）、记到笔记本上（存储数据）。每一步专注一件事，互不干扰。

网页抓取就是这个流程的自动化。requests 负责把页面「搬过来」，BeautifulSoup 负责把 HTML「翻成结构」，select 负责把目标字段「抄下来」，最后写入文件「存起来」。但你是图书馆的客人，不能乱翻、不能喧哗、不能把书架搬空——这就是礼貌爬虫的原则。

## 概念讲解

### 四阶段管道

<Term def="爬虫四阶段管道：请求（获取 HTML）→ 解析（构建 DOM 树）→ 清洗（提取目标字段）→ 存储（写入结构化文件）。四阶段解耦，各司其职。">

```python
# 请求
resp = requests.get(url, timeout=10, headers={"User-Agent": "..."})
# 解析
soup = BeautifulSoup(resp.text, "html.parser")
# 清洗
items = soup.select("div.news-item")
# 存储
with open("news.csv", "w") as f:
    ...
```

</Term>

### BeautifulSoup 解析

<Term def="BeautifulSoup 将 HTML 解析为可遍历的 DOM 树，提供 find/find_all（按标签属性查找）和 select/select_one（CSS 选择器查找）两套 API。">

`select` 用 CSS 选择器语法，灵活强大：`div.news-item h3.title a` 表示「news-item 下 title 下的 a 标签」。`select_one` 返回首个匹配或 None。`get_text(strip=True)` 提取文本去空白，`get('href', '')` 取属性带默认值。

</Term>

### 礼貌爬虫三要点

<Term def="礼貌爬虫三要点：遵守 robots.txt 尊重禁止路径、控制请求频率避免压垮服务器、伪装真实 UA 并留联系方式。">

- **robots.txt**：用 `urllib.robotparser` 解析，尊重 Disallow 规则
- **频率控制**：`time.sleep(1~2)` 限制每秒请求数
- **UA 标识**：用真实浏览器 UA，可留邮箱方便联系

高频请求等同于 DoS 攻击，会导致 IP 被封甚至法律风险。

</Term>

<Step title="第一步：请求与编码处理">

用 `requests.get()` 获取页面，设置 timeout 和 UA。关键细节：用 `resp.apparent_encoding` 自动检测真实编码（chardet 库），修正中文乱码——很多页面声明的 charset 与实际不符。

</Step>

<Step title="第二步：解析与提取">

用 `BeautifulSoup(resp.text, 'html.parser')` 解析。用 `select()` 按 CSS 选择器提取目标节点列表，`select_one()` 取单节点。返回 None 时跳过，避免 AttributeError。

</Step>

<Step title="第三步：清洗与容错">

对每个提取的节点用 `get_text(strip=True)` 去空白，`get('href', '')` 取属性带默认值。缺失字段给 'N/A' 而非报错，保证单条脏数据不中断整批。

</Step>

<Step title="第四步：存储与增量">

清洗后的数据写入 CSV/JSON。大规模采集时加增量逻辑：记录已抓 URL，下次只抓新增；用 hashlib 去重；断点续爬记录进度，中断后可恢复。

</Step>

</Stepper>

## 代码对照

```python
import requests
import time
import csv
from bs4 import BeautifulSoup
from urllib.robotparser import RobotFileParser

# === Level 1: 礼貌检查 robots.txt ===
rp = RobotFileParser()
rp.set_url("https://example.com/robots.txt")
rp.read()
if not rp.can_fetch("OpsBot/1.0", "https://example.com/news"):
    print("robots.txt 禁止抓取，跳过")
    exit()

# === Level 2: 请求 + 编码处理 ===
def fetch_page(url, timeout=10):
    headers = {"User-Agent": "Mozilla/5.0 (OpsBot/1.0)"}
    resp = requests.get(url, timeout=timeout, headers=headers)
    resp.encoding = resp.apparent_encoding  # 修正中文乱码
    return resp.text

# === Level 3: 解析 + 清洗 ===
def parse_news(html):
    soup = BeautifulSoup(html, "html.parser")
    results = []
    for item in soup.select("div.news-item"):
        title_tag = item.select_one("h3.title a")
        time_tag = item.select_one("span.date")
        if not title_tag:  # 缺失标题则跳过
            continue
        results.append({
            "title": title_tag.get_text(strip=True),
            "link": title_tag.get("href", ""),
            "time": time_tag.get_text(strip=True) if time_tag else "N/A"
        })
    return results

# === Level 4: 完整管道 + 频率控制 ===
def scrape_all(base_url, pages=10):
    all_news = []
    for page in range(1, pages + 1):
        url = f"{base_url}?page={page}"
        try:
            html = fetch_page(url)
            news = parse_news(html)
            all_news.extend(news)
            print(f"第 {page} 页: 抓取 {len(news)} 条")
        except Exception as e:
            print(f"第 {page} 页失败: {e}")
        time.sleep(2)  # 礼貌延时

    # 存储到 CSV
    with open("news.csv", "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=["title", "link", "time"])
        writer.writeheader()
        writer.writerows(all_news)
    return all_news
```

## 常见误区

<Callout type="trap">

**误区：不控制频率，疯狂请求**

有人写爬虫不加 sleep，一秒发几十个请求，把人家小服务器直接打宕机。这不仅不道德，还可能导致 IP 被永久封禁，甚至面临法律风险。频率控制是爬虫的基本礼仪——加 1-2 秒延时，既保护目标也保护自己。

</Callout>

<Callout type="trap">

**误区：忽略编码导致乱码**

直接用 `resp.text` 取内容，遇到 GBK 编码的中文页面就全乱码。原因是 requests 按 HTTP 头声明的 charset 解码，但很多页面声明错误。解决：用 `resp.apparent_encoding`（chardet 检测真实编码）覆盖 `resp.encoding`，再取 text。这一行代码能解决 90% 的中文乱码问题。

</Callout>

<Exercises>

**问题 1**：requests + BeautifulSoup 爬虫的四阶段管道是什么？为什么要分阶段而不是一个函数搞定？

<Answer>

四阶段：请求（requests 获取 HTML）→ 解析（BeautifulSoup 构建 DOM 树）→ 清洗（select 提取字段去噪）→ 存储（写入 CSV/JSON）。

分阶段的原因是解耦：1) 每阶段职责单一，便于独立测试和调试——请求失败不影响解析逻辑；2) 可替换实现——解析器可从 html.parser 换成 lxml，存储可从 CSV 换成数据库，互不影响；3) 可复用——同一解析逻辑可用于不同来源的 HTML；4) 容错隔离——单阶段失败不会污染其他阶段的数据。一个函数搞定的结果是任何小改动都要重测整个流程，维护成本极高。

</Answer>

**问题 2**：面对动态加载（JS 渲染）的网页，有哪几种技术方案？如何选择？

<Answer>

三种方案：1) **接口直抓**——分析浏览器 Network 面板，找到返回数据的 XHR/API 接口，直接用 requests 抓 JSON。最快最轻量，但需逆向分析接口参数。2) **requests + BeautifulSoup**——只能抓静态 HTML，对 JS 渲染内容无效，适合传统服务端渲染页面。3) **无头浏览器**（Playwright/Selenium）——启动真实浏览器渲染 JS 后抓取，最通用但最慢，资源消耗大。

选择原则：优先尝试接口直抓（快且稳），其次静态 HTML 抓取，最后才用无头浏览器（慢且重）。判断依据是数据是否在初始 HTML 中——在源码里能看到就用 BeautifulSoup，看不到就找接口或上无头浏览器。反爬严重的场景还需配合代理池、UA 轮换、Cookie 维持。

</Answer>

<Glossary>

<GlossaryItem term="BeautifulSoup">

Python HTML/XML 解析库，将 HTML 转为可遍历的 DOM 树，提供 find/find_all（按标签属性）和 select/select_one（CSS 选择器）两套 API，是爬虫数据提取的核心工具。

</GlossaryItem>

<GlossaryItem term="robots.txt">

网站根目录下的协议文件，声明允许/禁止爬虫抓取的路径。礼貌爬虫应先解析 robots.txt 并遵守其规则，违反可能构成侵权或被法律追责。

</GlossaryItem>

<GlossaryItem term="CSS 选择器">

定位 DOM 节点的语法，如 `div.news-item h3.title a` 表示「news-item 类的 div 下 title 类的 h3 下的 a 标签」。BeautifulSoup 的 select 方法支持完整 CSS 选择器语法。

</GlossaryItem>

<GlossaryItem term="apparent_encoding">

requests 响应对象的属性，由 chardet 库检测 HTML 内容的真实编码。当页面声明的 charset 与实际不符时，用 `resp.encoding = resp.apparent_encoding` 可修正中文乱码。

</GlossaryItem>

</Glossary>
