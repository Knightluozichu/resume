## 直觉引入

学完九章，你掌握了各种工具——pathlib 管文件、subprocess 管进程、requests 管网络、Paramiko 管 SSH、psutil 管监控。但工具零散，怎么串起来？

想象你在盖一栋楼。砖瓦水泥是工具（各种库），但你不能只会搬砖——你得知道这栋楼的结构：地基（运维基础）、骨架（系统管理）、管道网络（网络自动化）、智能系统（高级运维）。总复习就是带你从直升机上俯瞰整栋楼，看清每一层的位置和关系，知道自己站在哪里、还能往哪走。

## 概念讲解

### 四大板块递进

<Term def="全书四大板块构成递进能力链：运维基础（思维+标准库）→ 系统管理（本地自动化）→ 网络自动化（远程操作）→ 高级运维（可观测+可管理）。每层建立在前层之上。">

1. **运维基础**：建立 Python 工程化思维，认知标准库/三方库/工程化三层能力栈
2. **系统管理**：本地自动化能力——pathlib 管文件，subprocess 管进程
3. **网络自动化**：远程操作能力——requests 调 API，Paramiko 跑 SSH，BeautifulSoup 抓数据
4. **高级运维**：可观测+可管理——psutil 监控告警，YAML+Jinja2 配置管理

</Term>

### 四核心素质

<Term def="自动化运维的四核心素质：批量（同时处理多节点）、健壮（超时重试异常隔离）、安全（密钥认证最小权限）、可观测（监控日志告警）。四者构成能力闭环。">

- **批量**：ThreadPoolExecutor 并发，而非逐台手动
- **健壮**：timeout + 重试 + 异常隔离，一崩全崩不行
- **安全**：密钥认证 + RejectPolicy + 最小权限
- **可观测**：psutil 监控 + 日志记录 + 告警通知

缺一批量无效率，缺健壮不可用，缺安全引风险，缺可观测成黑箱。

</Term>

### 综合实战能力

<Term def="综合实战是把四大板块的工具组合使用：用 Paramiko 远程执行巡检命令，用 psutil 监控资源，用 requests 检查 API，用 pathlib 整理报告——一个脚本覆盖全维度。">

真正的运维自动化不是单个工具的使用，而是多个工具的组合。一个综合巡检脚本可能同时用到 SSH（远程连接）、subprocess（本地命令）、requests（API 检查）、psutil（资源监控），结果聚合后写入报告——这就是综合实战。

</Term>

## 代码对照

```python
# === 综合巡检脚本：串联全书四大板块 ===
import psutil              # 高级运维：监控
import requests            # 网络自动化：HTTP
import paramiko            # 网络自动化：SSH
from pathlib import Path   # 系统管理：文件
from concurrent.futures import ThreadPoolExecutor
from datetime import datetime

def full_inspect(host, key_path):
    """四维度综合巡检"""
    report = {"host": host, "time": datetime.now().isoformat()}
    client = paramiko.SSHClient()
    client.set_missing_host_key_policy(paramiko.RejectPolicy())
    try:
        client.connect(host, username="ops",
                       key_filename=key_path, timeout=10)

        # 维度1: 文件检查 — 磁盘空间
        _, stdout, _ = client.exec_command("df -h /", timeout=10)
        report["disk"] = stdout.read().decode()

        # 维度2: 进程状态 — 关键服务存活
        _, stdout, _ = client.exec_command(
            "systemctl is-active nginx", timeout=10)
        report["nginx"] = stdout.read().decode().strip()

        # 维度3: 网络连通性 — API 健康检查
        _, stdout, _ = client.exec_command(
            'curl -s -o /dev/null -w "%{http_code}" '
            'http://localhost:8080/health', timeout=10)
        report["api_status"] = stdout.read().decode().strip()

        # 维度4: 资源监控 — CPU/内存
        _, stdout, _ = client.exec_command(
            "top -bn1 | head -5", timeout=10)
        report["resources"] = stdout.read().decode()

        report["status"] = "ok"
    except Exception as e:
        report["status"] = "fail"
        report["error"] = str(e)
    finally:
        client.close()
    return report

# 批量执行（批量素质）
hosts = [f"node{i}" for i in range(100)]
with ThreadPoolExecutor(max_workers=20) as pool:
    reports = list(pool.map(
        lambda h: full_inspect(h, "~/.ssh/id_ed25519"), hosts))

# 结果汇总写入报告文件（文件操作）
report_path = Path("reports") / f"inspect_{datetime.now():%Y%m%d}.txt"
report_path.parent.mkdir(exist_ok=True)
with report_path.open("w") as f:
    ok = [r for r in reports if r["status"] == "ok"]
    fail = [r for r in reports if r["status"] == "fail"]
    f.write(f"巡检完成: {len(ok)} 正常, {len(fail)} 异常\n\n")
    for r in fail:
        f.write(f"[异常] {r['host']}: {r.get('error', '未知')}\n")
```

## 常见误区

<Callout type="trap">

**误区：学了工具等于会运维**

很多人学完 pathlib、subprocess、requests、paramiko 就觉得自己会自动化运维了。但工具只是砖瓦——真正的运维能力是把工具组合成系统：知道什么场景用什么工具，知道怎么让脚本健壮（超时重试）、安全（密钥认证）、可观测（监控告警）。工具可以速查文档，但系统思维需要反复实践。总复习的价值就是帮你从「会用工具」升级到「能建系统」。

</Callout>

<Callout type="trap">

**误区：一上来就搭大平台**

有人学完就急着搭 Ansible/Prometheus/Kubernetes 全家桶，结果啃不动、用不起来、团队抵触。正确路径是分阶段：先用 Python 脚本解决最痛的重复工作（批量巡检、日志收集），让团队尝到甜头；再引入配置管理工具体系化；最后才上监控平台和编排系统。先解决痛点建立信心，再逐步升级——不要一上来就大而全。

</Callout>

<Exercises>

**问题 1**：自动化运维的四核心素质是什么？为什么缺一不可？

<Answer>

四核心素质：
1. **批量**——能同时处理成百上千台节点（ThreadPoolExecutor 并发），而非逐台手动。缺则效率低，自动化无意义。
2. **健壮**——超时重试、异常隔离、幂等执行，不会因个别故障崩溃。缺则一崩全崩，不可用。
3. **安全**——密钥认证、host key 验证、最小权限，不引入安全风险。缺则自动化变成自动化攻击入口。
4. **可观测**——监控指标、日志记录、告警通知，知道发生了什么。缺则故障黑箱，无法排障。

四者构成能力闭环：批量解决效率，健壮保障可用，安全控制风险，可观测提供反馈。任何一个缺失，运维体系都不完整——批量但不可观测是「瞎跑」，安全但低效是「纸上谈兵」。

</Answer>

**问题 2**：如何为一家公司分阶段搭建自动化运维体系？

<Answer>

分三阶段推进：

**阶段一（1-2月）基础自动化**：先用 Python 脚本解决最痛的重复工作——批量 SSH 巡检（Paramiko）、日志集中收集、基础监控（psutil+告警脚本）。目标是把人肉操作降到最低，建立自动化文化，让团队尝到甜头。

**阶段二（3-4月）体系化**：引入配置管理（YAML+Jinja2 或 Ansible）实现配置版本化和幂等分发；搭建监控系统（Prometheus+Grafana）替代脚本监控，支持指标存储和可视化；建立 CI/CD 管道自动化部署。

**阶段三（5-6月）智能化**：引入告警智能聚合和根因分析减少告警疲劳；对接工单系统实现自动派单；建设运维知识库和 SOP 文档化。

核心原则：先解决最痛问题建立信心，再体系化建设，最后智能化提升。不要一上来就上大而全的平台——先让团队感受到自动化的价值，再逐步推进。

</Answer>

<GlossaryItem term="四核心素质">

自动化运维的四项必备能力：批量（同时处理多节点）、健壮（超时重试异常隔离）、安全（密钥认证最小权限）、可观测（监控日志告警）。四者构成完整能力闭环。

</GlossaryItem>

<GlossaryItem term="能力递进链">

全书四大板块的依赖关系：运维基础（思维+标准库）是地基，系统管理（文件+进程）是骨架，网络自动化（HTTP+SSH+爬虫）是血脉，高级运维（监控+配置管理）是大脑。每层建立在前层之上。

</GlossaryItem>

<GlossaryItem term="综合巡检">

把多维度检查（文件/进程/网络/资源）组合到一个脚本中的运维模式。典型实现用 Paramiko 远程执行命令，覆盖磁盘空间、服务存活、API 健康检查、CPU/内存监控，结果聚合后生成报告。

</GlossaryItem>

<GlossaryItem term="分阶段建设">

搭建运维体系的推进策略：先基础自动化（脚本解决痛点）→ 再体系化（配置管理+监控平台）→ 最后智能化（告警聚合+自动派单）。核心是先建立信心再逐步升级。

</GlossaryItem>
