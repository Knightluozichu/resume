## 核心模型与责任

分布式质量监控平台把各地区探针、调度、时间序列存储和报表组合起来。探针位置本身是维度，同一目标必须从多个地点采样，才能区分用户侧、区域和服务端故障。
本章按照原书核心模块建立最小实验，再用现代Python和安全默认重写边界。工具版本可以变化，但目标选择、输入验证、结果聚合和审计证据不能消失。

## 机制一：采集或控制入口

监控平台架构包含任务定义、采集器租约、结果上报、聚合、告警和查询。调度器避免重复租约，采集器带心跳，部分离线不会让整个平台停止。

## 机制二：状态、网络与批量

监控数据库模型区分Target、Probe、Check、Sample和Incident。原始样本按时间分区，聚合值保留算法版本；缺失样本是未知而不是零。

```python
def availability(samples):
    known = [sample for sample in samples if sample.error_code != 'NO_DATA']
    if not known: return None
    return sum(sample.success for sample in known) / len(known)
```

批量任务要先预览匹配目标，再限制并发并逐目标汇总。成功、失败、超时和未返回是不同状态；只展示总成功率会掩盖关键主机失败。

## 机制三：证据与恢复

数据采集角色与rrdtool作业把探针结果按固定step更新并生成归档。时间戳单调、重复点有策略，采集延迟与服务时延分开保存，图表标出unknown区间。
Django业务报表按服务、地区和窗口展示可用率、分位延迟和错误分布。可用率分母排除经批准维护但保留原始事件，报表可下钻到样本和告警时间线。

def percentile(values, fraction):
    ordered = sorted(values)
    if not ordered: return None
    index = min(len(ordered) - 1, math.ceil(fraction * len(ordered)) - 1)
    return ordered[index]
