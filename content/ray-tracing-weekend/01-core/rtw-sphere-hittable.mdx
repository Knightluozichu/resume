## 直觉引入

场景里不会只有一个球。要支持任意多个物体，得先抽象出一个共同接口：「给一条射线，告诉我你被击中了吗？击中点在哪、法线朝哪」。这就是可命中对象（hittable）。

每种几何体（球、平面、三角形）各自实现这个接口，场景用一个列表把它们装起来。射线来了，列表挨个问每个物体「你最近被击中在哪」，记下全局最近的那个交点——这就是这一像素真正看到的东西。

## 概念讲解

<Term def="记录射线与物体相交结果的数据结构">命中记录</Term>（hit_record）包含：交点 $\mathbf{p}$、交点处法线 $\mathbf{n}$、参数 $t$、以及是否正面命中 `front_face`。<Term def="可被射线命中的几何体统一接口">可命中对象</Term>（hittable）提供 `hit(ray, t_min, t_max, rec)` 方法。

### 法线方向判定
射线可能从球外射入，也可能从球内射出（如折射后再相交）。几何上的外法线始终由球心指向交点；写进 `hit_record` 的法线则约定为始终迎向入射射线：

$$
\text{front\_face} = (\mathbf{d}\cdot\mathbf{n}_{out} < 0),\quad \mathbf{n} = \text{front\_face}\ ?\ \mathbf{n}_{out}\ :\ -\mathbf{n}_{out}
$$

这两个概念不能混为一谈。<Term def="几何外法线：由物体局部几何决定、从球心指向表面的单位向量。它不因观察者或入射射线位置而改变。">几何外法线</Term>用于判断光线是从外侧还是内侧命中；`rec.normal` 则是给散射代码的统一输入，满足 `dot(r.direction(), rec.normal) <= 0`。因此光线在球内向外射出时，`front_face=false`，记录里的法线会朝球内，但几何外法线仍朝球外。

$$
\mathbf{n}_{out}=\frac{\mathbf{p}-\mathbf{C}}{r},\qquad
\mathbf{d}\cdot\mathbf{n}\le0
$$

### 严格区间不是多余的 if

<Term def="严格命中区间：只接受严格位于 (t_min,t_max) 内的根。端点不算命中，因此从表面刚发出的新射线不会立即再次命中同一位置。">严格命中区间</Term>把“根存在”转换为“这条射线当前允许看到它”。原书的 `interval::surrounds(root)` 使用开区间，而不是 `contains` 的闭区间：如果根恰好等于 `t_min`，多半是前一次命中点因浮点误差又被命中，应排除；如果根等于当前最近距离 `t_max`，保持先前记录可让列表遍历更稳定。

$$
t\in(t_{min},t_{max})\quad\Longrightarrow\quad
\text{该根可以写入 hit\_record}
$$

`hit_record` 也应当具有“只在成功时写入”的语义。球体先算出局部 `root`，确认它在区间内，再同时写入 `t`、`p`、法线和材质指针。若求交失败却留下上一次的字段，调用者很容易把旧材质或旧法线误当成这次命中。

### 列表为何能作为正确但朴素的场景

<Term def="最近命中不变量：遍历过程中 closest 始终是当前已检查物体中最小的合法 t；每次调用子对象时将它作为新的 t_max，遍历结束后 rec 就是最先可见表面。">最近命中不变量</Term>使 `hittable_list` 成为正确的基线实现。它的代价是每条射线都测试所有物体，随着随机球数量增长会变慢；但在引入 BVH 之前，这段小而清晰的循环正好用来验证每个物体是否遵守相同的 `hit` 契约。

### 取最近交点
射线可能与球有两个交点，取 $t\in[t_{min},t_{max}]$ 内最小的正根，并不断收紧 $t_{max}$ 为当前最近距离，使后续物体只可能贡献更近的交点。

## 代码对照

C++ 抽象接口、球体命中与列表：

```cpp
struct hit_record {
  point3 p;
  vec3   normal;
  double t;
  bool   front_face;
  shared_ptr<material> mat_ptr;   // 后面材质章会用到
};

class hittable {
  public:
    virtual ~hittable() = default;
    virtual bool hit(const ray& r, interval ray_t, hit_record& rec) const = 0;
};

// 球的命中：取区间内最近正根，并确定朝外法线
bool sphere::hit(const ray& r, interval ray_t, hit_record& rec) const {
  vec3 oc = r.origin() - center;
  auto a = r.direction().length_squared();
  auto h = dot(oc, r.direction());
  auto c = oc.length_squared() - radius*radius;
  auto disc = h*h - a*c;
  if (disc < 0) return false;
  auto sqrtd = sqrt(disc);
  auto root = (-h - sqrtd) / a;            // 近根
  if (!ray_t.surrounds(root)) {            // 不在区间内试远根
    root = (-h + sqrtd) / a;
    if (!ray_t.surrounds(root)) return false;
  }
  rec.t = root;
  rec.p = r.at(rec.t);
  vec3 outward_normal = (rec.p - center) / radius;
  rec.set_face_normal(r, outward_normal);  // 按射线方向翻转法线
  return true;
}

// 列表：遍历并收紧 t_max
bool hittable_list::hit(const ray& r, interval ray_t, hit_record& rec) const {
  hit_record temp_rec; bool hit_anything = false;
  auto closest = ray_t.max;
  for (const auto& obj : objects)
    if (obj->hit(r, interval(ray_t.min, closest), temp_rec)) {
      hit_anything = true; closest = temp_rec.t; rec = temp_rec;
    }
  return hit_anything;
}
```

`set_face_normal` 内部用点积判定正反面并翻转法线，使材质无需关心射线来自内还是外。

```cpp
void hit_record::set_face_normal(const ray& r, const vec3& outward_normal) {
  front_face = dot(r.direction(), outward_normal) < 0;
  normal = front_face ? outward_normal : -outward_normal;
}

// 调用方可始终假定 normal 迎向入射射线。
// 材质通过 front_face 决定折射率比，例如外部->玻璃与玻璃->空气。
```

这段函数刻意不修改 `outward_normal`。同一份球体几何可以被不同射线从内外两侧命中，而 `front_face` 将“这一次射线的位置关系”保留为独立信息；玻璃材质需要它选择正确的介质折射率比。

## 常见误区

<Callout type="trap">
**现象 →** 玻璃球内部折射后再次相交时法线朝错方向，折射计算出错。
**原因 →** 球的几何外法线始终朝球外，但折射公式需要法线朝射线来源侧。
**修法 →** 用 set_face_normal 按入射方向翻转：射线从外进内时法线朝外，从内出外时法线朝内，并记 front_face 供材质判断介质。
</Callout>

<Callout type="trap">
**现象 →** 列表没收紧 t_max，结果渲染了「最远」而非「最近」的交点，出现穿透。
**原因 →** 遍历时每个物体都在原始 [t_min,t_max] 区间求交，后命中的远物体覆盖了近物体。
**修法 →** 每次命中把 closest 更新为当前 t，后续物体只在此更小区间内求交，保证留下全局最近交点。
</Callout>

## 练习

<Exercises>
**问题 1**：hit_record 里 front_face 是怎么判定的？为什么要把记录法线翻转成始终朝射线来源侧？

<Answer>
front_face = (射线方向 · 几何外法线 < 0)，即射线迎着外法线射入为正面命中。写入记录的法线会被翻转为始终朝射线来源侧，并不总是朝几何外侧；这样材质的散射/折射公式始终可假定法线迎向入射光，而 `front_face` 保留了内外信息供折射率判断。
</Answer>

**问题 2**：hittable_list 如何保证返回的是最近交点而非任意一个？

<Answer>
维护一个 closest 变量初始化为 t_max，遍历每个物体时用 [t_min, closest] 作为求交区间；一旦命中就把 closest 更新为该交点的 t。这样后续物体只能在比当前更近的位置命中，遍历结束 rec 里留下的就是全局最近交点。
</Answer>

**问题 3**：一条射线在 t=0.00001 命中刚离开的表面，在 t=2.0 命中另一只球。若 `t_min=0.001`、`t_max=infinity`，应保留哪个命中？为什么这个选择对反射与折射很重要？

<Answer>
应排除 t=0.00001 并保留 t=2.0。前者通常是浮点误差导致的新射线立即命中自己的出发面，若接受它，反射或折射会在同一点反复递归，形成黑斑、噪点或错误自阴影。严格的 t_min 把下一次有效求交推到离开表面之后。
</Answer>
</Exercises>

## 小结

- `outward_normal` 描述球体几何；`rec.normal` 描述当前入射射线可直接使用的方向，两者职责不同。
- `front_face` 是折射等材质判断内外介质的可靠标志，不能只从法线长度或位置猜测。
- 根必须位于严格命中区间才可写入记录，避免 `t≈0` 的自相交。
- 列表每次收紧 `t_max` 维护最近命中不变量；这是所有后续加速结构都必须保持的语义。

<GlossaryItem term="可命中对象">hittable，提供 hit(ray, t区间, rec) 接口的几何体抽象，球、列表等都实现它。</GlossaryItem>
