## 从一个会失败的图像实验开始

The vec3 Class要回答的不是“这个名词是什么”，而是：在固定输入下，如何验证“用一个三分量类型统一表达方向、点与线性色彩”，并让一个反例可重复地推翻错误实现？先写下预期像素、几何或估计量，再运行基线；只要长度、点积、叉积方向和分量运算的单元样本无法指出差异来自哪一步，图像看起来正确也不能通过。

本页的不变量是：The vec3 Class的输入、公式中间量、输出与恢复结果可用同一基线复算。反例“对零长度向量归一化，或把color误当作point3参与几何平移”只改变一个条件，因而正常、故障与恢复三次运行应能用同一输入直接比较。

## 原书单元与独立机制解释

### The vec3 Class

vec3 提供加减、点积、叉积和归一化；point3 与 color 是语义别名，帮助读者区分位置和辐射颜色，却不会产生新的运行时类型。验收重点是每个运算的几何含义，而不是运算符重载本身。

本单元的正式坐标是vec3、point3、color。验证The vec3 Class时，先制造“对零长度向量归一化，或把color误当作point3参与几何平移”，再检查长度、点积、叉积方向和分量运算的单元样本能否把错误定位到用一个三分量类型统一表达方向、点与线性色彩的首个分叉。

$$
\widehat{v}=\frac{v}{\sqrt{v\cdot v}}
$$

## 最小可重现实验

```cpp
double length_squared(const vec3& v) { return dot(v, v); }
vec3 unit_vector(const vec3& v) {
  if (length_squared(v) == 0) throw std::domain_error("zero vector");
  return v / std::sqrt(length_squared(v));
}
```

运行The vec3 Class时固定随机种子、输入几何、坐标约定和数值精度；记录编译命令或算法版本、输出摘要与失败条件。实验输出若依赖隐藏全局状态，必须先消除该依赖再比较。

<Callout type="trap" title="本页核心误区">
  对零长度向量归一化，或把color误当作point3参与几何平移。这个错误会破坏“The vec3 Class的输入、公式中间量、输出与恢复结果可用同一基线复算”，应先由长度、点积、叉积方向和分量运算的单元样本定位，再讨论性能或视觉风格。
</Callout>

<Callout type="trap" title="不要把别的图形API模板套进来">
  The vec3 Class只解释用一个三分量类型统一表达方向、点与线性色彩。若原始资料讨论纯C++路径追踪、OpenGL时代图形学或光传输积分，就不能用VkBuffer、Fence与Semaphore替代相应的几何、光栅化或蒙特卡洛机制。
</Callout>

**问题 1：公式与边界。** 怎样用一个数值样本证明 $\widehat{v}=\frac{v}{\sqrt{v\cdot v}}$ 中的量没有混用空间、单位或概率密度？

<Answer>
  先写出每个量的定义域与单位，选择能手算的输入，分别计算中间量和最终结果；再只扰动一个量。若长度、点积、叉积方向和分量运算的单元样本的变化方向与公式不一致，应拒绝实现而不是调整截图。
