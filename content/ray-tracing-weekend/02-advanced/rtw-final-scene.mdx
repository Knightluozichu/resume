## 直觉引入

前面九章攒齐了所有零件：射线、求交、相机、漫反射、金属、玻璃、景深。最终场景就是把它们组装起来——一片大地、三个主角球（哑光、金属、玻璃），再撒一把随机大小、随机材质的小球。就像把学到的调料全用上做一道大菜。

随机生成让画面充满细节又不重复，而三种材质的混合让反射、折射、漫反射同时出现，互相映照——这才是检验光线追踪是否正确的最好测试图。

## 概念讲解

### 场景构成
- **地面**：一个极大的漫反射球（半径 1000），充当大地。
- **三个主角**：中央哑光球、左侧金属球、右侧玻璃球，分别展示三种材质。
- **随机小球**：用循环在地面网格上随机生成上百个小球，材质按概率分配（多数漫反射、少数金属/玻璃）。

### 材质分配策略
：用一个随机数决定每个小球是漫反射（80%）、金属（15%）还是玻璃（5%），并随机颜色，避免人工排列的呆板感。

### 渲染参数
- `samples_per_pixel`：每像素采样数，越高越平滑越慢。
- `max_depth`：递归深度，决定反射能弹几次，太浅玻璃和镜面发暗。
- `image_width`/`aspect`：分辨率与宽高比。

### 随机场景首先是回归测试，不是装饰

的价值不只是“球很多”。同一个场景同时包含漫反射、模糊金属、清晰金属和玻璃，可让法线方向、折射率比、背景采样和递归深度在一张图中一起接受检验。若每次运行都完全改变随机序列，画面差异可能来自场景变化而非代码修改，无法判断修复是否真的有效。

因此开发阶段应提供显式随机种子：先用固定种子生成基准 PPM，修改求交或材质后仍用同一粒子布局重渲；只有想探索不同构图时才换种子。并不会消除路径采样噪点，但它把“场景随机性”和“每像素路径随机性”分开，方便定位问题。

### 主角排除区是几何约束

随机小球的中心不是任意可取。应至少覆盖小球半径、主角半径与可见空隙。示例的 `0.9` 是为半径 0.2 的小球避开右侧主角而选的视觉间隔；如果你改大随机球半径或移动主角，阈值也必须一起改。仅检查中心距离大于零不足以防相交。

场景还应避免把小球直接生成在巨大地面球内部。小球中心 y=0.2、半径=0.2 使它刚好与 y=0 的平面相切；这正是用半径 1000 的“地面球”近似平面的好处：局部看似平坦，却仍使用同一套球体求交与法线代码。

### 渲染预算的三个乘数

可先用一个粗略上界预估，而不必等到风扇转起来才发现设置过大：

$$
\mathrm{work}\approx W\times H\times\mathrm{samples\_per\_pixel}
\times\mathrm{average\_bounces}\times\mathrm{objects\_tested}
$$

`max_depth` 是平均弹跳次数的上界而非保证值，许多路径会更早射向天空或被材质吸收。没有 BVH 的列表场景中，`objects_tested` 会随随机小球数量近似线性增长；所以把分辨率、样本数和物体数同时翻倍，耗时远不止两倍。调试时应先使用低分辨率、少样本、固定种子验证逻辑，再单独提高一个维度观察质量收益。

## 代码对照

C++ 最终场景生成：

```cpp
hittable_list world;

// 地面（极大漫反射球）
auto ground = make_shared<lambertian>(color(0.5, 0.5, 0.5));
world.add(make_shared<sphere>(point3(0,-1000,0), 1000, ground));

// 三个主角
auto mat1 = make_shared<lambertian>(color(0.1,0.2,0.5));    // 哑光蓝
auto mat2 = make_shared<dielectric>(1.5);                    // 玻璃
auto mat3 = make_shared<metal>(color(0.8,0.6,0.2), 0.0);     // 金属
world.add(make_shared<sphere>(point3(0, 1, 0), 1.0, mat2));
world.add(make_shared<sphere>(point3(-4, 1, 0), 1.0, mat1));
world.add(make_shared<sphere>(point3( 4, 1, 0), 1.0, mat3));

// 随机小球：按概率分配材质
for (int a = -11; a < 11; a++) {
  for (int b = -11; b < 11; b++) {
    auto choose_mat = random_double();
    point3 center(a + 0.9*random_double(), 0.2, b + 0.9*random_double());
    if ((center - point3(4,0.2,0)).length() > 0.9) {        // 避开主角
      shared_ptr<material> sphere_mat;
      if (choose_mat < 0.8) {                                // 80% 漫反射
        auto albedo = color::random() * color::random();
        sphere_mat = make_shared<lambertian>(albedo);
      } else if (choose_mat < 0.95) {                        // 15% 金属
        auto albedo = color::random(0.5, 1);
        sphere_mat = make_shared<metal>(albedo, random_double(0,0.5));
      } else {                                               // 5% 玻璃
        sphere_mat = make_shared<dielectric>(1.5);
      }
      world.add(make_shared<sphere>(center, 0.2, sphere_mat));
    }
  }
}

// 相机与渲染参数：构造器顺序为 focus_dist 后 aperture。
camera cam(20, 16.0/9.0, /*focus_dist*/ 10.0, /*aperture*/ 0.1);
cam.render(world, /*samples*/ 500, /*max_depth*/ 50);
```

`choose_mat` 的概率分段让多数小球是哑光、少数反光/折射，画面既丰富又有视觉重点。

将随机种子与预算集中成配置，能让“修复前后是否相同场景”成为可验证条件：

```cpp
struct render_settings {
  int image_width = 400;
  int samples_per_pixel = 100;
  int max_depth = 25;
  uint64_t scene_seed = 20260711;
};

const render_settings settings{};
random_engine rng(settings.scene_seed);  // 场景生成只读取此 rng
auto world = random_scene(rng);
camera cam(20, 16.0 / 9.0, 10.0, 0.1);
cam.render(world, settings.samples_per_pixel, settings.max_depth);
```

这份配置适合第一次验收：图像小、样本数有限、场景固定。确认玻璃、金属和地面都正确后，再把样本数提高到 500 或更高；不要在首轮就同时提高分辨率和深度，否则任何错误都会被漫长渲染时间掩盖。

```cpp
bool overlaps_hero(const point3& center, double small_radius,
                   const point3& hero_center, double hero_radius) {
  const auto required_gap = small_radius + hero_radius + 0.05;
  return (center - hero_center).length() < required_gap;
}

// 将三个主角都放入检查列表，而不是只排除其中一个。
if (!overlaps_any_hero(center, 0.2, hero_spheres)) {
  world.add(make_shared<sphere>(center, 0.2, sphere_mat));
}
```

把布局约束提取为函数，也会让场景修改更安全：新增或移动主角时，排除规则不会继续偷偷使用旧的中心与阈值。

## 小结

- 随机球场景应以固定种子作为回归输入，而不是每次运行的不可控装饰。
- 主角排除半径必须随球体半径和主角位置共同维护，避免布局相交污染求交测试。
- 样本数压低随机噪点，递归深度保留反射与折射链，场景数量决定每次路径的求交成本。
- 首轮使用小预算验证几何和材质，再逐项提高分辨率、样本和深度，才能定位质量与性能变化的来源。
