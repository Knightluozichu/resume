## 从一个会失败的图像实验开始

Surface Normals and Multiple Objects × Moving Camera Code Into Its Own Class要回答的不是“这个名词是什么”，而是：在固定输入下，如何验证“把交点几何、朝向和多对象最近命中统一成查询合同，并把相机初始化、射线生成、颜色求值与图像写出收拢为稳定接口”，并让一个反例可重复地推翻错误实现？先写下预期像素、几何或估计量，再运行基线；只要front_face、单位法线、对象身份和最近命中距离、公开参数、initialize派生量、首末像素射线和重构前后PPM哈希无法指出差异来自哪一步，图像看起来正确也不能通过。

本页的不变量是：Surface Normals and Multiple Objects的输入、公式中间量、输出与恢复结果可用同一基线复算，且Moving Camera Code Into Its Own Class的输入、公式中间量、输出与恢复结果可用同一基线复算。反例“不根据入射方向翻转法线，或遍历对象时没有收紧t上界；重构时改变像素坐标或初始化顺序，导致相同场景输出发生漂移”只改变一个条件，因而正常、故障与恢复三次运行应能用同一输入直接比较。

## 原书单元与独立机制解释

### Surface Normals and Multiple Objects

法线从球心指向交点，hit_record 保存t、位置、法线与正反面，hittable_list 逐对象缩短允许上界以保留最近命中。这样材质只消费稳定的命中记录，不再重复求交细节。

本单元的正式坐标是法线、hit_record、hittable_list。验证Surface Normals and Multiple Objects时，先制造“不根据入射方向翻转法线，或遍历对象时没有收紧t上界”，再检查front_face、单位法线、对象身份和最近命中距离能否把错误定位到把交点几何、朝向和多对象最近命中统一成查询合同的首个分叉。

$$
n=\frac{P-C}{r},\qquad t_{\max}\leftarrow t_{\mathrm{closest}}
$$

### Moving Camera Code Into Its Own Class

Moving Camera Code Into Its Own Class把分散在main中的视口计算、get_ray、ray_color与render循环迁入camera类。重构前后图像必须一致；initialize集中派生参数，render只负责按像素调度并写出结果。

本单元的正式坐标是camera class、initialize、render。验证Moving Camera Code Into Its Own Class时，先制造“重构时改变像素坐标或初始化顺序，导致相同场景输出发生漂移”，再检查公开参数、initialize派生量、首末像素射线和重构前后PPM哈希能否把错误定位到把相机初始化、射线生成、颜色求值与图像写出收拢为稳定接口的首个分叉。

$$
R=write(color(get\_ray(pixel)))
$$

if (object.hit(r, interval(t_min, closest), rec)) {

  rec.set_face_normal(r, outward_normal);
  nearest = rec;
}

<Callout type="trap" title="不要把别的图形API模板套进来">
