## 直觉引入

把整本书浓缩成一句话：从相机发射射线，撞到物体后让材质决定往哪散射，递归若干层再平均——就是一张真实感图片。复习就是把这条链上每个环节的「为什么」和「怎么算」重新捋一遍，找出自己卡住的节点。

这一章不再教新东西，而是把九章的知识点连成网，并训练「看到 bug 就能定位到链上哪一环」的诊断能力。

## 概念讲解

### 全书数据流
相机 `get_ray` 产出射线 → `world.hit` 求交得 `hit_record` → `mat_ptr->scatter` 算衰减与散射方向 → `ray_color` 递归 → 多次采样平均 → `write_color` 伽马校正输出。

### 三类材质对照
| 材质 | 散射方向 | attenuation | 关键点 |
|------|----------|-------------|--------|
| 漫反射 | N + 随机单位向量 | albedo | 余弦加权，需伽马校正 |
| 金属 | reflect(d,N) + fuzz | 金属色 | 校验方向朝外 |
| 电介质 | Snell 折射 / 全内反射 | ≈白 | front_face 决定 ratio |

### 常见 bug 速查
- **全黑**：max_depth=0 或散射返回 false。
- **偏暗**：漏伽马校正。
- **穿透/选远点**：列表没收紧 t_max。
- **玻璃发黑**：depth 太小或漏判全内反射。
- **画面拉歪**：宽高比算反。

### 把渲染器拆成五个可观测契约

<Term def="路径状态：一条递归光线路径在任意时刻携带的射线、剩余深度、当前吞吐量和随机样本。调试时必须能回答它来自哪个像素、命中了什么、下一跳去了哪里。">路径状态</Term>是从“图像异常”走向“某一行代码”的桥梁。不要在最终 4K 图上直接猜：选一个固定像素、固定样本序号，打印该路径经过的 `ray`、root、`front_face`、attenuation 和 depth；将它与上一章可预期的几何关系逐项对照。

1. **输出契约**：PPM 头、像素遍历顺序与 `write_color` 的 [0,1] 到字节映射正确。先用红绿渐变验证它，任何复杂场景之前都应通过。
2. **相机契约**：同一 `(i,j)` 在固定随机数下产生确定的射线；宽高比、`lookfrom/lookat/vup` 与 focus_dist 共同决定它经过的方向。
3. **几何契约**：命中根在严格 `(t_min,t_max)` 区间内，`rec.normal` 永远迎向入射射线，`front_face` 仍保留真实内外侧。
4. **材质契约**：`scatter=true` 时同时写入 attenuation 和 scattered；金属方向朝表面外，玻璃先检查全内反射再按 Schlick 选择路径。
5. **统计契约**：同一场景种子下，样本平均在增加 samples_per_pixel 时应只减少噪点；平均完成后才做伽马变换。

<Term def="图像不变量：在固定种子、固定相机和固定渲染参数下，每次运行都应保持不变的可观测性质，例如渐变方向、法线颜色、最近命中和统计均值。它们比主观地看“像不像”更适合做回归测试。">图像不变量</Term>比一张“看起来对”的最终图更可靠。例如，把 `ray_color` 临时替换为法线颜色后，球的右侧应偏红、上侧偏绿，若不是则先修命中和法线；把所有材质临时替换为吸收材质后，球应遮住天空而不是透出背景；这些小实验能把问题限制在一个契约内。

### 先做受控渲染，再提高预算

<Term def="受控渲染：固定场景种子、相机、低分辨率、少量样本和有限递归深度的调试渲染。它牺牲最终画质以换取快速、可比较的输出，是定位渲染错误的第一步。">受控渲染</Term>推荐配置是 64×36、每像素 4 到 16 样本、固定场景种子。此时不要追求平滑阴影，而要验证同一像素在代码修改前后为何改变。确认所有不变量后，再按顺序增加分辨率、样本数、场景密度和 max_depth；一次只改变一个旋钮，才能区分性能回退与画质收益。

<Term def="首个失效边界：沿 get_ray、hit、scatter、ray_color、write_color 的顺序检查时，第一个不满足接口契约的位置。修复它比继续检查后续结果更有效，因为下游异常通常只是上游错误的传播。">首个失效边界</Term>是排错优先级：若根已经不在区间内，就无需讨论玻璃的 Schlick；若线性颜色已经为零，就无需先改伽马；若法线颜色图反向，先不要提高 samples_per_pixel。这个顺序能避免在末端调参掩盖上游逻辑错误。

## 代码对照

全书最小可运行骨架（伪代码）：

```cpp
int main() {
  hittable_list world = build_final_scene();          // 第9章场景
  camera cam(20, 16.0/9.0, /*focus_dist*/10.0, /*aperture*/0.1); // 相机与景深

  for (int j = h-1; j >= 0; --j)
    for (int i = 0; i < w; ++i) {
      color c(0,0,0);
      for (int s = 0; s < samples; ++s) {             // 第6章采样
        auto u = (i + random_double()) / (w-1);
        auto v = (j + random_double()) / (h-1);
        c += ray_color(cam.get_ray(u,v), world, max_depth); // 第2、4、5、7章
      }
      write_color(std::cout, c, samples);             // 第6章伽马校正
    }
}

color ray_color(const ray& r, const hittable& world, int depth) {
  hit_record rec;
  if (depth <= 0) return color(0,0,0);                // 递归上限
  if (world.hit(r, interval(0.001, inf), rec)) {      // 第4章求交
    ray sc; color att;
    if (rec.mat_ptr->scatter(r, rec, att, sc))        // 第5、6、7章材质
      return att * ray_color(sc, world, depth-1);
    return color(0,0,0);
  }
  return background(r);                               // 第2章背景
}
```

每个函数对应特定章节，bug 出现时可直接跳到对应章节核对。

先把最终路径追踪器缩小为可观察的一条路径。这个调试函数不替代正式渲染，只在固定像素或固定种子上打印契约关键值：

```cpp
color debug_ray_color(const ray& r, const hittable& world, int depth) {
  hit_record rec;
  if (depth <= 0) return color(0, 0, 0);
  if (!world.hit(r, interval(0.001, infinity), rec)) return background(r);

  assert(dot(r.direction(), rec.normal) <= 0.0);
  assert(rec.t > 0.001);
  std::clog << "t=" << rec.t
            << " front=" << rec.front_face
            << " normal=" << rec.normal << '\n';

  ray scattered;
  color attenuation;
  if (!rec.mat_ptr->scatter(r, rec, attenuation, scattered)) return color(0, 0, 0);
  return attenuation * debug_ray_color(scattered, world, depth - 1);
}
```

当玻璃异常时，先只跟踪穿过玻璃中心的一条相机射线：检查第一次命中 `front_face=true`、离开时为 false，检查 ratio 是否从 `1/ir` 切换到 `ir`。当金属出现黑斑时，检查 `dot(scattered.direction(), rec.normal)` 是否被 fuzz 推到非正。输出这些值比把样本数加到 1000 更快定位根因。

```cpp
// 三个快速的图像级回归开关：每次只启用一个。
enum class debug_view { beauty, normals, depth, material_id };

color visualize_hit(const hit_record& rec, debug_view view) {
  if (view == debug_view::normals)
    return 0.5 * color(rec.normal.x() + 1, rec.normal.y() + 1, rec.normal.z() + 1);
  if (view == debug_view::depth)
    return color(rec.t / 10.0, rec.t / 10.0, rec.t / 10.0);
  return material_color(rec.mat_ptr); // 给每种材质固定调试色
}
```

法线图验证方向与 front_face，深度图验证最近根，材质 ID 图验证 `hit_record` 是否写入正确的指针。只有这三张中间图都满足预期时，beauty 图里的噪点、反射和景深才值得继续调。

## 常见误区

<Callout type="trap">
**现象 →** 复习时只记公式，没建立「数据流」全局观，遇到 bug 无从下手。
**原因 →** 把各章当孤立知识点，没串成 get_ray→hit→scatter→ray_color→write_color 的链。
**修法 →** 用一张数据流图把十章串起来，每个 bug 先定位到链上哪一环，再回到对应公式核对。
</Callout>

<Callout type="trap">
**现象 →** 三种材质散射方向搞混，写金属时用了漫反射的随机方向。
**原因 →** 没有对照表区分 reflect(d,N)+fuzz、N+随机向量、Snell 折射三者的本质差异。
**修法 →** 记住金属=镜面反射+模糊、漫反射=法线+随机、电介质=折射/全内反射，每类对应一个公式，写代码前先归类。
</Callout>

## 练习

<Exercises>
**问题 1**：把全书十二个核心单元串成一条数据流，并说明每个环节对应哪一章。

<Answer>
相机 get_ray 产射线（第3、8章）→ world.hit 求交得 hit_record（第2、4章）→ mat_ptr->scatter 算衰减与散射方向（第5、6、7章）→ ray_color 递归（第5章，深度上限防溢出）→ 多次采样平均（第6章）→ write_color 伽马校正输出（第6章）。第1章是全局地图，第9章是场景组装，第10章是串讲诊断。
</Answer>

**问题 2**：渲染出「玻璃球发黑、其余正常」，请给出诊断思路与可能的根因。

<Answer>
先定位数据流：只有玻璃（电介质）出问题，说明 get_ray、hit、采样、伽马都正常，问题在 scatter 或递归深度。可能根因：(1) max_depth 太小，光线进玻璃后没折射出来就被截断成黑——调大 depth；(2) 漏判全内反射，refract 产生非法向量——补 cannot_refract 判定走 reflect；(3) front_face 搞反导致 ratio 错误，折射方向失真。逐一核对电介质 scatter 代码即可定位。
</Answer>

**问题 3**：同一场景在 16 样本时有颗粒噪点，在 256 样本时噪点降低但整张图仍比预期暗。该先调 samples_per_pixel、max_depth 还是 gamma？请给出最短的验证顺序。

<Answer>
先固定种子并输出线性平均值与伽马后的像素值：若线性平均值合理而写出的图暗，先检查 gamma 和字节映射；若线性平均值本身已经很低，再检查 attenuation、背景和递归深度。因为从 16 到 256 样本已降低颗粒噪点，仍然整体偏暗通常是系统偏差而不是方差。max_depth 只在反射或玻璃特定区域发黑时再提高；不能先盲目加样本掩盖显示或能量错误。
</Answer>
</Exercises>

## 小结

- 全书十二单元最终收敛为一条路径链：输出与向量 → 相机 → 命中记录 → 材质散射 → 统计平均与显示。
- 先固定种子和低预算，再从输出、相机、几何、材质、统计五个契约检查不变量。
- 法线、深度和材质 ID 图把 beauty 图的复杂现象拆成可验证的中间状态。
- 排错应停在首个失效边界；下游颜色、噪点或模糊往往只是上游契约破坏的结果。
