## 直觉引入

碰撞检测的核心矛盾：你要判断 N 个物体之间谁碰了谁，暴力两两检测是 $O(n^2)$，物体一多帧率就崩。解决办法是分两步走——先粗筛，用廉价的包围体快速排除绝大多数不可能碰撞的对，得到一小批「候选对」；再精算，对候选对做精确的几何检测。全书围绕这条管线展开。

## 五阶段递进

<Term def="碰撞检测是判断两个或多个物体在空间中是否相交的计算过程，是物理模拟、角色控制、触发器等游戏系统的基石。">碰撞检测</Term>的学习可以拆成五个递进阶段。**基础层**包括学习地图和碰撞检测类型——建立离散与连续的区分认知。**粗粒度层**（Broad Phase）包括 Sweep and Prune 和空间分割——用排序或分桶把 $O(n^2)$ 降到 $O(n \log n)$。**细粒度层**（Narrow Phase）包括 GJK 和 SAT——对候选对做精确凸体检测。**优化层**包括连续碰撞检测和优化策略——处理高速穿透并榨干硬件性能。**总复习**把管线串成整体。

```cpp
// 碰撞检测管线的核心结构
struct CollisionPipeline {
    BroadPhase broad;     // 粗筛：输出候选对列表
    NarrowPhase narrow;   // 精算：对候选对精确检测
    // 一帧的流程
    void Step(float dt) {
        auto pairs = broad.GeneratePairs(bodies);  // O(n log n)
        auto contacts = narrow.Detect(pairs);       // 只检测候选对
        Resolve(contacts);                          // 交给物理引擎
    }
};
```

## 常见误区

<Callout type="trap">
**误区：跳过粗粒度直接做精确检测。** 1000 个物体两两检测要 50 万次，其中 99% 根本不可能碰。粗粒度用包围体的区间重叠或空间分桶，一次比较就能排除一对。跳过它，无论细粒度算法多快，总量都扛不住。
</Callout>

<Exercises>
**问题 1**：碰撞检测为什么要分 Broad Phase 和 Narrow Phase 两阶段？

<Answer>
直接对 N 个物体两两精确检测是 $O(n^2)$，1000 个物体就要 50 万次。Broad Phase 用廉价的包围体（AABB/球）快速排除不可能相交的对，只把真正可能碰的「候选对」交给 Narrow Phase。这样精确但昂贵的检测只跑在少量候选对上。两阶段把总复杂度从 $O(n^2)$ 降到接近 $O(n \log n)$，是实时性的关键。
</Answer>

**问题 2**：全书五阶段是什么？为什么是这个顺序？

<Answer>
基础（类型认知）→ 粗粒度（Broad Phase）→ 细粒度（Narrow Phase）→ 优化（CCD + 性能）→ 总复习。顺序由管线依赖决定：先理解离散与连续的区别，才知道该用什么检测；粗筛产出候选对，精算才能消费；精确检测跑通后才谈优化提速；最后用管线视角串联。跳过任何一层都会在后续遇到「为什么这样设计」的困惑。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Broad Phase">粗粒度阶段，用包围体快速排除不可能碰撞的物体对，输出候选对列表，复杂度目标 $O(n \log n)$。</GlossaryItem>
<GlossaryItem term="Narrow Phase">细粒度阶段，对候选对做精确几何检测（GJK/SAT），确认是否真正相交并求接触信息。</GlossaryItem>
<GlossaryItem term="候选对">Broad Phase 输出的「可能碰撞的物体对」，数量远小于全部两两组合，是两阶段管线的衔接点。</GlossaryItem>
</Glossary>
