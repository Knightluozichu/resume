## 为什么要用包围体

精确检测两个复杂多边形是否相交很贵——要遍历所有边。但如果先用一个简单的形状把物体「包住」，先检测包围体是否相交，不相交就直接跳过，就能省掉绝大部分精确检测。包围体的设计核心是权衡：**包裹得越紧（紧密性高），误判越少；但形状越复杂，检测越贵**。

## 四种包围体

<Term def="轴对齐包围盒 AABB 是边始终平行于坐标轴的矩形/长方体，只用 min/max 两个点表示，相交检测最快。">AABB</Term>是最常用的包围体。它的相交检测只需 3 条轴各比较一次区间是否重叠——每条轴判断 $\max(A_{min}, B_{min}) \leq \min(A_{max}, B_{max})$。**包围球**最简单，只需球心+半径（4 个 float），两球相交只比较球心距离与半径和，且旋转完全不影响（球旋转不变）。**OBB**（有向包围盒）的盒子能跟随物体旋转，紧密性最好，但两 OBB 相交需用 SAT 检测 15 条轴。**k-DOP** 用 k 个固定法向的半空间交集表示，比 AABB 紧密但比 OBB 便宜。

```cpp
// AABB 相交检测：3 轴区间重叠法
bool intersectAABB(const AABB& a, const AABB& b) {
    // 三条轴都重叠才相交，任一轴分离即不相交
    if (a.max.x < b.min.x || b.max.x < a.min.x) return false;
    if (a.max.y < b.min.y || b.max.y < a.min.y) return false;
    if (a.max.z < b.min.z || b.max.z < a.min.z) return false;
    return true;  // 三轴全重叠
}

// 包围球相交：一次距离比较
bool intersectSphere(const Sphere& a, const Sphere& b) {
    float r = a.r + b.r;
    return distanceSquared(a.center, b.center) <= r * r;
}
```

## 旋转更新的代价

物体旋转时，AABB 需要重新计算（把旋转后的 8 个顶点投影取 min/max），开销不小；包围球完全不需要更新（旋转不变），这是它的巨大优势；OBB 只需乘一个旋转矩阵即可更新，代价低且保持紧密性。这就是为什么旋转频繁的物体常用 OBB 而非 AABB。

<Callout type="trap">
**误区：包围体越紧越好。** 紧密性高确实减少误判，但检测成本也上升。Broad Phase 每帧对所有物体跑包围体相交，如果用 OBB（15 轴 SAT），1000 个物体就是 50 万次 15 轴检测。实际中 Broad Phase 几乎都用 AABB 或球——便宜到能批量跑，误判留给 Narrow Phase 精确处理。
</Callout>

<Exercises>
**问题 1**：为什么 Broad Phase 通常用 AABB 而不用 OBB？

<Answer>
Broad Phase 要对全部物体两两检测，数量巨大。AABB 相交只需 3 次区间比较（极快），且可以用 SIMD 批量处理 4 组。OBB 相交要检测 15 条轴（SAT），慢 5 倍以上。Broad Phase 的目标是「快速排除不可能碰的对」，少量误判（AABB 比物体大）可以交给 Narrow Phase 处理。用 OBB 的紧密性在 Broad Phase 是浪费——速度比精度重要。
</Answer>

**问题 2**：物体旋转时，AABB 和包围球哪个更新成本更低？为什么？

<Answer>
包围球更低——实际上为零。球具有旋转不变性：无论物体怎么转，包围球的球心和半径都不变，不需要任何更新。AABB 旋转后必须重算：把旋转后的 8 个顶点投影到 3 条轴取 min/max，涉及 8 次矩阵乘法和 48 次比较。这也是包围球在动态场景中仍有价值的原因——尽管紧密性差，但零更新成本。
</Answer>
</Exercises>

<GlossaryItem term="OBB">有向包围盒，盒子方向跟随物体旋转，紧密性高但两 OBB 相交需 SAT 检测 15 条轴。</GlossaryItem>
