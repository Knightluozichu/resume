## 直觉：实时约束不等于固定 16.6 ms

实时渲染是在给定交互、刷新率、设备和质量目标下持续生成可接受图像。60 Hz 的一帧间隔约 16.67 ms，但应用还要给模拟、输入、合成器和显示留预算；VR 可能要求更高刷新率与更严 motion-to-photon latency。

先预测：一个离线算法被压到 10 ms，是否自动成为可用实时算法？不一定。还要检查最坏/P95 波动、内存、延迟、时序稳定和交互质量。

不是单一平均 FPS。


## 官方 26 章的五层体系

### 1. 管线与硬件

Introduction、The Graphics Rendering Pipeline、The Graphics Processing Unit、Graphics Hardware 建立应用阶段、几何/光栅、GPU 执行和硬件带宽。接口变化不改变吞吐、延迟、占用率和 producer-consumer 数据流。

### 2. 表示与几何

Transforms、Polygonal Techniques、Curves and Curved Surfaces、Beyond Polygons、Intersection Test Methods、Collision Detection 回答对象如何表示、变换、求交和维持时空接触。

### 3. 外观与图像

Shading Basics、Texturing、Light and Color、Physically Based Shading、Local Illumination、Image-Space Effects、Volumetric and Translucency Rendering、Non-Photorealistic Rendering 覆盖采样、颜色、BRDF、局部光、屏幕空间、介质和风格化。

### 4. 可见性与光传输

Shadows、Global Illumination、Real-Time Ray Tracing 从直接可见性、间接传输扩展到 BVH、混合光栅/光追和降噪。

### 5. 系统、交互与未来

Pipeline Optimization、Acceleration Algorithms、Efficient Shading、Virtual and Augmented Reality、The Future 把特性装入真实帧循环，处理负载均衡、LOD/空间结构、tiled/clustered、预测/畸变和研究趋势。

比“顶点到像素”更完整。

## 正确性与实时性的双门槛

对固定工作量，帧预算关系可写成：

$$
T_{frame}\ge\max(T_{CPU},T_{GPU},T_{present}),
$$

但同步点会让阶段相加而非完全重叠。平均帧时间不足以描述 hitch，至少记录 median、P95/P99 和最坏帧。

图像技术要有 reference image/数值误差；几何查询要有 brute-force oracle；碰撞要检查漏检和 penetration；VR/AR 要测 motion-to-photon、预测误差和畸变；性能优化要做控制变量。

```cpp
for (Scenario s : validationSuite) {
  runCorrectnessOracle(s);
  captureIntermediateBuffers(s);
  measureCpuGpuMemoryLatency(s);
  recordPercentilesAndFailureBoundary(s);
}
```
