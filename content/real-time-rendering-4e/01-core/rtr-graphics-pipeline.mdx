## 直觉引入

想象一条汽车流水线。原材料（顶点数据）进厂后，先经冲压车间（顶点着色器）成型，再进焊接车间（光栅化）把零件拼成半成品，最后进喷漆车间（片段着色器）上色出厂。每个车间都有固定工序，但冲压和喷漆的参数可以自定义（可编程），而焊接的工序是固定的（固定功能）。

渲染管线就是这条流水线。理解它，就理解了3D数据如何变成屏幕上的像素。

## 概念讲解

### 管线三阶段

<RtrGraphicsPipelineDiagram />

<Term def="渲染管线是从3D场景数据到2D图像的处理流水线">渲染管线</Term>分三个大阶段：应用阶段（CPU端）、几何阶段（GPU顶点处理）、光栅化阶段（GPU片段处理）。

关键区分：<Term def="可编程阶段是开发者可以编写着色器代码控制其行为的管线阶段">可编程阶段</Term>包括顶点着色器和片段着色器；<Term def="固定功能阶段是只能配置参数但不能编程的管线阶段">固定功能阶段</Term>包括光栅化、深度测试、混合等。

## 代码对照

```glsl
// 顶点着色器：把顶点从模型空间变换到裁剪空间
#version 330 core
layout(location = 0) in vec3 aPos;
uniform mat4 model;
uniform mat4 view;
uniform mat4 projection;

void main() {
    gl_Position = projection * view * model * vec4(aPos, 1.0);
}

// 片段着色器：计算每个像素的最终颜色
#version 330 core
out vec4 FragColor;
uniform vec3 objectColor;

void main() {
    FragColor = vec4(objectColor, 1.0);
}
```

## 常见误区

<Callout type="trap">
**误区：认为管线每个阶段都可以编程。**
光栅化、深度测试、混合是固定功能阶段，只能配置参数。试图在光栅化阶段插入自定义代码是不可能的——硬件电路决定了它的行为。
</Callout>

<Callout type="trap">
**误区：混淆片段和像素。**
片段是潜在像素——它包含了位置、深度、颜色等信息，但不一定最终出现在屏幕上。只有通过深度测试和混合后，片段才写入帧缓冲成为像素。
</Callout>

<Exercises>
**问题 1**：渲染管线分哪三个大阶段？各阶段在CPU还是GPU上执行？

<Answer>
应用阶段在CPU上执行（提交Draw Call、设置状态）；几何阶段在GPU上执行（顶点着色器变换坐标）；光栅化阶段在GPU上执行（光栅化生成片段、片段着色器计算颜色、输出合并写入帧缓冲）。
</Answer>

**问题 2**：为什么光栅化是固定功能而不是可编程的？

<Answer>
光栅化的核心任务是把三角形覆盖的像素找出来，这是一个确定性的数学过程（判断像素中心是否在三角形内），不需要灵活编程。用固定硬件电路实现比可编程单元效率高得多，节省GPU资源给真正需要编程的着色器阶段。
</Answer>
</Exercises>
