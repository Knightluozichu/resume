## 直觉：一帧是证据链，不是功能清单

先预测：某场景 GPU 只有 8 ms 就一定满足 60 FPS 吗？white-furnace 通过就一定没有 specular aliasing 吗？单帧截图正确就一定适合 VR 吗？每个答案都是否定的，因为实时渲染同时受数值、表示、可见性、采样、历史、队列和显示约束。

总复习的目标不是背“管线→变换→着色”，而是能从输入场景追踪到显示像素，并对每个近似提供 reference、边界场景和成本证据。


## 官方 26 章五层能力矩阵

### 第一层：帧、管线与硬件

1. **Introduction**：定义实时目标、应用、质量与 latency；
2. **The Graphics Rendering Pipeline**：application、geometry、raster、pixel/output 与 present；
3. **The Graphics Processing Unit**：SIMT、occupancy、divergence、memory hierarchy；
23. **Graphics Hardware**：front end、shader/texture/raster/output、bandwidth 与显示。

这一层回答“工作在哪里执行、如何重叠、由什么资源限制”。稳态近似：

$$
T_{frame}\approx\max(T_{CPU},T_{GPU},T_{present})+T_{serialized}.
$$

### 第二层：空间与几何表示

4. **Transforms**：model/view/projection、clip/NDC、normal matrix、quaternion；
16. **Polygonal Techniques**：topology、normal/tangent seam、simplification、LOD；
17. **Curves and Curved Surfaces**：Bézier、B-spline/NURBS、subdivision、tessellation。

这一层回答“对象是什么形状、在哪个空间、如何离散”。验收包括解析点、法线垂直性、winding/seam、屏幕误差与 crack-free edge。

### 第三层：外观、光色与采样

5. **Shading Basics**：shading frequency、perspective interpolation、normal/derivative；
6. **Texturing**：mapping、footprint、mip、anisotropy、compression/virtualization；
8. **Light and Color**：radiance/irradiance、photometry、linear RGB、display transform；
9. **Physically Based Shading**：BRDF、GGX D/F/G、Fresnel、energy 与 material workflow；
10. **Local Illumination**：light types、visibility、area/environment sampling；
12. **Image-Space Effects**：depth/normal/motion/history、post 与 temporal reconstruction；
13. **Beyond Polygons**：particle/billboard、implicit/SDF、voxel、hair/curve primitive；
14. **Volumetric and Translucency Rendering**：extinction、transmittance、in-scattering、alpha/subsurface；
15. **Non-Photorealistic Rendering**：ramp、contour、stroke、style 与 temporal coherence。

这一层回答“信号代表什么、怎样响应光、如何被有限样本重建”。核心 transport：

$$
L_o=L_e+\int_{\Omega^+}f_rL_iV(\mathbf n\cdot\mathbf l)d\omega.
$$

### 第四层：可见性与全局传输

7. **Shadows**：light-space depth、bias、PCF/PCSS、moment、CSM 与 hybrid；
11. **Global Illumination**：lightmap/probe、screen-space、voxel/SDF、dynamic GI；
26. **Real-Time Ray Tracing**：BLAS/TLAS、traversal/intersection、sampling、reuse 与 denoise。

这一层回答“光路是否被挡、间接能量从哪里来、缺失样本怎样估计”。Monte Carlo 样本均值：

$$
\hat L=\frac{1}{N}\sum_i\frac{f(X_i)}{p(X_i)},
\qquad \sigma_{\hat L}\propto 1/\sqrt N.
$$

因此实时低样本必须同时设计 sampling、PDF、history validation、spatial filter 与 fallback，不能只报“开启光追”。

### 第五层：查询、效率与交互系统

18. **Pipeline Optimization**：timeline、控制变量实验、P95/P99 与 frame pacing；
19. **Acceleration Algorithms**：BVH/grid/hierarchy、build/refit、候选漏斗；
20. **Efficient Shading**：early-Z、forward+/deferred、GPU-driven、VRS/upscale；
21. **Virtual and Augmented Reality**：pose、stereo、reprojection、foveation、motion-to-photon；
22. **Intersection Test Methods**：AABB/triangle、边界约定、watertight 与退化输入；
24. **The Future**：ray/neural/virtualized data 的 reference、power、platform 与 fallback；
25. **Collision Detection**：broad/narrow phase、GJK/SAT、contact、CCD/TOI。

这一层回答“怎样少做但不漏、怎样在运动和显示期限前给出稳健结果”。它不是最后再做的优化层，而是每个特性从第一天就要携带的系统约束。

## 四类跨章故障树


要求先分症状：

- **正确性**：黑屏、坐标错、裂缝、漏物体、错误碰撞 → transform/clip、topology、resource state、culling、intersection；
- **光能与外观**：过曝、漏光、材质跨场景失真 → color space、units、BRDF、visibility、GI/history；
- **空间/时域采样**：闪烁、拖影、moire、阴影游泳 → footprint、LOD、motion、disocclusion、filter/bias；
- **系统与交互**：hitch、P99、输入延迟、XR 不适 → CPU/GPU/present timeline、stream/build、queue、reprojection。

先看最早错误中间量，不要从最终 tone-mapped 截图猜原因。每个 debug view 必须标注空间、范围、单位和是否经过历史。

## 从零搭建：按垂直切片交付

原页的“先全功能、最后优化”会积累不可测系统。更稳健的是每个切片同时交付功能、证据与预算：

1. **可信三角形切片**：resource/command、MVP、clip/depth、present；附解析顶点与 CPU/GPU/present 时间线；
2. **可信材质切片**：linear color、normal/tangent、texture footprint、BRDF；附 white-furnace 与 material spheres；
3. **可信可见性切片**：culling、depth、shadow、intersection；附 raw bounds/depth/bias 和 reference；
4. **可信光传输切片**：direct、IBL/GI/ray、history；附分层 radiance、variance、confidence；
5. **可信交互切片**：streaming、animation/collision、XR/latency、fallback；附轨迹、P95/P99、设备矩阵。

避免等到功能堆完才发现空间、颜色或同步约定不兼容。

```ts
type FeatureGate = {
  correctness: { analyticCases: string[]; referenceErrorMax: number };
  temporal: { cameraPaths: string[]; flickerMax: number; lagFramesMax: number };
  performance: { cpuP95Ms: number; gpuP95Ms: number; memoryMiB: number };
  platforms: { required: string[]; fallback: string };
};

function acceptFeature(result: GateResult, gate: FeatureGate) {
  return passesCorrectness(result, gate.correctness) &&
         passesTemporal(result, gate.temporal) &&
         passesBudget(result, gate.performance) &&
         passesFallback(result, gate.platforms);
}
```

## 统一验收矩阵


可以是解析解、高分辨率 raster、高样本 path trace、CPU double precision 或人工标注 contact。reference 也有假设，必须与被测量的空间、曝光、材质和时间对齐。

每个章节能力至少要回答：

- input/schema 是否明确，非法输入如何处理；
- 中间量是否可视化，能否从 consumer 追到 producer；
- analytic/reference 与误差度量是什么；
- 动态、遮挡暴露、尺度、退化输入是否覆盖；
- CPU/GPU/present、memory、stream/build 与功耗预算是多少；
- feature 缺失或超预算时如何降级。

## 小结

Real-Time Rendering 4e 的 26 章构成五层系统：帧与硬件、空间与几何、外观与采样、可见性与传输、查询与交互。真正掌握它意味着能画出 producer-consumer 链、解释每个近似、用 reference 和故障注入定位问题，并在分位数、延迟、内存和 fallback 约束下交付。
