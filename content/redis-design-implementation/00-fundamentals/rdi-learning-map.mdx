## 四条核心主线

### 主线一：数据结构

```
// Redis 底层数据结构怎么设计的递进路径
// SDS 简单动态字符串
//   └── len + free + buf[] → O(1) 取长度 · 二进制安全
//   └── 空间预分配 + 惰性释放
// 链表 adlist
//   └── 双端 · 无环 · O(1) 头尾增删
// 字典 dict
//   └── 哈希表 + 链地址法 · 渐进式 rehash
// 跳跃表 skiplist
//   └── 多层链表 · O(logN) 查找 · 概率层数
// intset / ziplist
//   └── 小数据专用 · 节约内存
//
// 核心：选最合适的结构 → 内存效率 + 操作复杂度
```

### 主线二：对象系统

```
// Redis 对象系统怎么桥接底层和用户的递进路径
// 5种对象类型
//   └── string / list / hash / set / zset
// 多编码
//   └── 同一类型可对应多种底层数据结构
//   └── 编码转换由阈值触发（对用户透明）
// 内存管理
//   └── 引用计数 + 对象共享 + LRU/LFU
// 命令多态
//   └── 同一命令根据对象类型执行不同实现
//
// 核心：底层结构决定编码 → 编码决定性能特征
```

### 主线三：数据库机制

```
// Redis 单机数据库怎么跑的递进路径
// 键空间
//   └── redisDb.dict → 所有键值对
//   └── expires 字典 → 过期管理
// 过期删除
//   └── 惰性删除 + 定期删除 + 淘汰策略
// 持久化
//   └── RDB（快照） vs AOF（追加） vs 混合
// 事件驱动
//   └── 文件事件（I/O多路复用）+ 时间事件（serverCron）
// 事务与Lua
//   └── MULTI/EXEC + WATCH 乐观锁 + Lua 原子脚本
// 发布订阅
//   └── PUBLISH/SUBSCRIBE + 模式订阅
//
// 核心：单线程事件驱动 → 无锁 + 纯内存 = 高性能
```

### 主线四：分布式高可用

```
// Redis 多机怎么协作的递进路径
// 主从复制
//   └── SYNC（全量）→ PSYNC（部分重同步）
//   └── 复制偏移量 + 积压缓冲区
// Sentinel 哨兵
//   └── 监控 + 自动故障转移 + 通知
//   └── SDOWN → ODOWN → Leader 选举 → 选新主
// Cluster 集群
//   └── 16384 槽位分片 · CRC16(key) mod 16384
//   └── Gossip 协议 · MOVED/ASK 重定向
//
// 核心：复制是基础 → 哨兵保高可用 → 集群做水平扩展
```

<Callout type="info" title="核心认知">
全书四条主线在「对象编码」（底层数据结构决定对象编码方式）与「持久化+复制」（单机持久化机制是复制的数据传输基础）与「事件驱动+分布式」（事件循环是所有Redis进程的运行模型，包括哨兵和集群节点）处交汇。理解这些交汇点，才能从"会用Redis"升级到"理解Redis设计与实现"。
</Callout>

<GlossaryItem term="Redis核心设计哲学">
Redis的核心设计哲学是"用最合适的底层数据结构，在内存中实现最高效的KV存储"。具体体现为：纯内存操作（微秒级延迟）、单线程事件驱动（无锁无竞态）、I/O多路复用（单核10万+QPS）、多编码自适应（小数据节约内存/大数据保证性能）、fork+ COW（持久化和复制的无锁快照）。
</GlossaryItem>

<Exercises>

**问题 1**：全书分为哪四个部分？各自的核心内容和递进逻辑是什么？

<Answer>
全书分四个部分：第一部分「数据结构底座」——SDS简单动态字符串（len/free/buf[]，O(1)取长度，二进制安全，空间预分配）、双端链表adlist（O(1)头尾增删，多态）、字典dict（MurmurHash2哈希，链地址法，渐进式rehash）、跳跃表skiplist（多层链表，O(logN)查找，概率层数）、整数集合intset（有序无重复，升级不降级）、压缩列表ziplist（连续内存，节约内存，级联更新）；第二部分「对象系统与编码」——5种对象类型（string/list/hash/set/zset）、多编码（同一类型对应多种底层数据结构）、编码转换（阈值触发，对用户透明）、引用计数/对象共享/LRU-LFU淘汰；第三部分「数据库实现」——键空间（redisDb.dict）、过期删除（惰性+定期）、持久化（RDB快照/AOF追加/混合）、事件驱动（文件事件+时间事件）、事务（MULTI/EXEC/WATCH）、发布订阅；第四部分「分布式与高可用」——主从复制（SYNC/PSYNC）、Sentinel哨兵（监控+故障转移）、Cluster集群（16384槽位分片）。递进逻辑：从数据怎么存到用户怎么用到单机怎么跑到多机怎么协作。
</Answer>

**问题 2**：贯穿全书的四条核心主线是什么？它们在哪些章节交汇？

<Answer>
主线一「数据结构」：SDS → 链表 → 字典 → 跳跃表 → intset/ziplist，回答「数据怎么存」。主线二「对象系统」：5种类型 → 多编码 → 编码转换 → 命令多态，回答「用户怎么用」。主线三「数据库机制」：键空间 → 持久化 → 事件 → 事务 → 发布订阅，回答「单机怎么跑」。主线四「分布式高可用」：复制 → 哨兵 → 集群，回答「多机怎么协作」。四条主线在「对象编码」（底层数据结构决定对象编码方式）与「持久化+复制」（单机持久化机制是复制的数据传输基础）与「事件驱动+分布式」（事件循环是所有Redis进程的运行模型）处交汇。
</Answer>

**问题 3**：为什么学习Redis设计与实现要遵循"数据结构 → 对象系统 → 数据库实现 → 分布式高可用"的顺序？

<Answer>
顺序依据：数据结构——理解SDS、字典、跳跃表等底层实现，是理解Redis一切性能特征的基础；对象系统——5种类型和编码转换将底层结构桥接到用户侧，需要先理解数据结构才能理解编码选择；数据库实现——键空间、持久化、事件驱动是单机运行的核心机制，需要先理解对象系统才能理解键值存储；分布式高可用——复制、哨兵、集群建立在单机机制基础上，持久化是复制的数据传输基础，事件驱动是所有进程的运行模型。跳过基础的风险：①不懂数据结构无法理解编码转换；②不懂对象系统无法理解键空间；③不懂持久化无法理解复制；④不懂事件驱动无法理解哨兵和集群的运行模型。
</Answer>

**问题 4**：Redis的核心设计哲学是什么？它如何通过技术选择实现高性能？

<Answer>
核心设计哲学：用最合适的底层数据结构，在内存中实现最高效的KV存储。通过以下技术选择实现高性能：①纯内存操作——所有数据在内存中，读写微秒级延迟；②单线程事件驱动——命令执行单线程，无锁无竞态，避免上下文切换；③I/O多路复用——epoll/kqueue/select监听套接字，单核处理大量并发连接；④多编码自适应——小数据用ziplist/intset节约内存（指针开销大于数据本身），大数据用hashtable/skiplist保证O(1)/O(logN)操作复杂度；⑤fork+ COW——持久化和复制通过fork子进程+写时复制实现无锁快照。这些设计使Redis单核即可达到10万+ QPS。
</Answer>
