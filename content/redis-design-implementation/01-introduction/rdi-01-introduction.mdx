## 三个必须主动触发的误区

### 误区 1
**现象 →** 数据量超过物理内存
**原因 →** 内存数据库溢出换页
**修法 →** 按内存容量规划数据，配 maxmemory 策略

### 误区 2
**现象 →** 任意场景都上 Redis
**原因 →** 复杂查询与强一致不适用
**修法 →** 关系查询用 SQL 库，Redis 做高速层

### 误区 3
**现象 →** 以为单线程等于单核限制
**原因 →** 瓶颈常在网络而非 CPU
**修法 →** 先压测网络吞吐再谈 CPU 扩展

## 小结

- Redis 是内存数据结构服务器
- 五种对象类型覆盖主流缓存场景
- 单线程模型简化并发与一致性
- 功能从缓存扩展到消息与计算
- 版本差异要在实验前确认

## 练习、答案与节点验证

<Exercises>

**问题 1：** Redis 为什么能在单线程下保持高吞吐？

<Answer>
内存操作本身是微秒级，瓶颈在网络与锁；单线程消除锁竞争与上下文切换，配合多路复用 I/O 达到十万级 QPS。
</Answer>

**问题 2：** 什么时候不该用 Redis？

<Answer>
数据量超内存且无法接受丢失窗口、需要强一致事务、复杂关系查询三类场景，应选持久型数据库或专用系统。
</Answer>

**问题 3：** 为一个会话存储场景选择 Redis 数据结构并说明理由。（独立实现）

<Answer>
选哈希存用户字段，字段级读写省带宽；设 TTL 自动过期；说明为何不用字符串 JSON（更新需整体读写）。
</Answer>

</Exercises>
