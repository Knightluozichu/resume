## 为什么从“SDS字节与扩容轨迹台”开始

第2章 简单动态字符串的核心任务是从sdshdr的len、free和buf理解常数时间取长、二进制安全、空间预分配与惰性释放。命令返回值只暴露外层合同；实现解释还必须连接内存结构、写入与读取路径、事件顺序以及失败后的旧状态回收。SDS字节与扩容轨迹台把这些关系放进同一条可复位轨迹。

先写预测：当写入长度由“跨预留空间”进入“含零字节”时，哪个可观察状态最先变化？再规定什么结果会推翻当前解释。交互中的分数只表达透明因果方向，不冒充真实Redis测量。

<Callout type="trap" title="命令表象不等于实现">
  第2章 简单动态字符串不能从一次redis-cli结果反推全部控制流；必须在sds.c定位结构、写入路径和读取路径，并保存能推翻解释的边界输入。
</Callout>

<Callout type="trap" title="版本倒灌">
  Redis 4.0以后新增或替换的结构与功能不能倒灌到3.0。新版资料只作差异说明，正式验收仍以本章源码文件与作者目录为准。
</Callout>

<Callout type="trap" title="恢复不等于进程在线">
  注入按C字符串的strlen和终止零推断SDS长度，截断二进制载荷后，要用同一命令序列核对结构、回复、文件或偏移以及最终键值；只有“字符串长度、终止字节和可用空间始终一致，扩容不会溢出，二进制数据不被截断”恢复才算通过。
