## 三个必须主动触发的误区

### 误区 1
**现象 →** 混入超大整数
**原因 →** 全集合升级内存翻倍
**修法 →** 按值域分集合存储

### 误区 2
**现象 →** 对 intset 做大量随机删除
**原因 →** 数组搬移成本高
**修法 →** 考虑换哈希编码或批量重建

### 误区 3
**现象 →** 以为整数集合有序就全能
**原因 →** 只支持整数类型
**修法 →** 非整数元素自动换编码

## 小结

- 整数集合是有序无重复紧凑数组
- 类型升级机制节省内存
- 插入触发升级保证有序
- 只存整数且元素不多时使用
- 升级之后不会降级

## 练习、答案与节点验证

<Exercises>

**问题 1：** 整数集合的升级机制如何工作？

<Answer>
新元素超出当前编码范围时，按新元素类型统一升级整个集合并保持有序，如 int16 全转 int32。
</Answer>

**问题 2：** 为什么升级后不允许降级？

<Answer>
避免反复升降级的抖动成本；降级收益小，而升级是单次操作，规则简化实现。
</Answer>

**问题 3：** 判断：集合 {1,2,65536} 应使用什么编码，内存占用如何估算？（独立实现）

<Answer>
65536 超 int16 触发升级到 int32，3 元素 ×4 字节加头部，总约 20 字节。
</Answer>

</Exercises>
