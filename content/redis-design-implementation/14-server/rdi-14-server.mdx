# 第14章 服务器

本课程对应黄健宏著《Redis设计与实现》正式出版新版（常称第2版），机械工业出版社2014年6月出版，388页，ISBN 9787111464747。作者以Redis 2.9 unstable分支，也就是Redis 3.0源码为基线，重写旧版并补齐复制、Sentinel、集群、排序和位操作等内容。

## 从一条命令的完整路径开始

先预测：客户端发出命令后，Redis 3.0会读取哪些结构、改变哪些字段、在何处分配或释放内存、何时写持久化缓冲、何时传播给副本、何时回复？再预测键数量和命令率增加十倍后的P99与故障终点。不要先看运行结果再拼源码故事。

本页主问题是“从读取协议、查找命令、预备执行、调用函数到回复客户端，串联serverCron与初始化”。最终交付不是命令摘要，而是命令执行时序、serverCron职责表、启动阶段日志与失败注入，由另一位工程师按Redis 3.0基线复跑并证明：**命令查找、权限与状态检查先于执行，统计和传播围绕同一调用，初始化失败不留下半可用服务**。

## 源码机制：结构、状态与所有权

结构层先写字段不变量。Redis用C结构体和指针表达对象、字典、客户端、服务器与集群状态；图中每条边都要说明谁创建、谁修改、谁释放。只列字段名不足以解释实现，必须给出命令前后快照和结构间引用。

函数层再写控制流。把命令入口、核心操作、后台周期任务与清理路径分开；正常返回、错误返回和异步完成不是同一边界。围绕“从读取协议、查找命令、预备执行、调用函数到回复客户端，串联serverCron与初始化”记录关键分支、循环上界、复杂度与可能阻塞事件循环的操作。

状态层检查跨阶段一致性。字典迁移、AOF重写、RDB子进程、复制重同步、Sentinel选举和迁槽都同时保留新旧状态；需要标出切换条件、双写或增量缓冲、失败恢复与旧状态回收，避免只描述最终形态。

版本层限制结论。书中结构和阈值对应Redis 3.0，后续版本可能替换底层编码或增加命令；课程引用新版本时只作为差异说明，不能覆盖本页的正式实现和验收分母。

## 运行机制：事件循环、内存与I/O

Redis主事件循环依次处理已就绪文件事件和到期时间事件。单线程减少共享状态锁，不等于所有操作无停顿；大键、慢命令、fork页表复制、写时复制和同步I/O都可能放大尾延迟。实验同时看命令率、对象大小和后台活动。

内存证据至少包含键数、值大小、对象类型与编码、allocator统计和碎片；文件证据包含RDB/AOF大小、校验、fsync策略和恢复时间；网络证据包含客户端输出缓冲、复制偏移、积压缓冲与断线重连。只有这些证据和业务对账共同支持“命令查找、权限与状态检查先于执行，统计和传播围绕同一调用，初始化失败不留下半可用服务”。

## 独立证据与生产交接

目录证据保存作者官网24章与本页小节映射；源码证据保存结构字段、关键函数、调用顺序和版本提交；运行证据保存配置、键分布、对象编码、命令脚本、INFO、延迟与资源；故障证据保存注入点、最后确认命令、恢复动作和对账。

性能判断必须保留分位数和背景任务。平均吞吐会隐藏事件循环排队、输出缓冲、大键、渐进rehash、过期扫描、fork和fsync尖峰。任何优化若改变持久性、复制确认、对象语义或恢复能力，都不是等价比较。

恢复判断必须从用户数据结束。RDB/AOF能载入、从节点重新连接、Sentinel完成切换或槽迁移完成都只是阶段；还要按操作ID、键数量、值、TTL和业务约束核对，并验证旧主或旧槽不再接受错误写入。
