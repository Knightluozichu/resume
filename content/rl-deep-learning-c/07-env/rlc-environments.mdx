## 环境搭建：RL的实验场

强化学习算法需要环境来训练和测试。本章用C语言实现两个经典RL环境——GridWorld（离散）和CartPole（连续），并设计统一接口使不同算法能在相同环境上公平对比。

## 统一环境接口

设计统一接口使算法与环境解耦——换环境只需改Env实现，算法代码不变：

```c
typedef struct {
    double state[STATE_DIM];  // 新状态
    double reward;            // 奖励
    int done;                 // 是否终止
} EnvStep;

typedef struct {
    int state_dim;
    int action_dim;
    void* internal;           // 环境内部状态
} Env;

// 重置环境到初始状态
void env_reset(Env* e);

// 执行动作，返回转移结果
EnvStep env_step(Env* e, int action);
```

<Callout type="info">

**统一接口的价值**：Q-Learning、DQN、Policy Gradient都只需调用 `env_reset` 和 `env_step`，无需知道环境内部逻辑。同一接口下可公平比较不同算法。新环境只需实现接口即可接入。

</Callout>

## GridWorld环境

GridWorld是最简单的RL测试环境：一个网格，智能体从起点S走到目标G，避开陷阱H。

### 环境定义

- **状态**：网格位置 `(row, col)`，编码为整数 `s = row * n_cols + col`
- **动作**：&#123;上(0), 下(1), 左(2), 右(3)&#125; 共4个离散动作
- **转移**：移动到相邻格子，碰墙留原地
- **奖励**：到G给+1，到H给-1，普通移动给-0.01（鼓励快速到达）
- **终止**：到达G或H

### C语言实现

```c
typedef struct {
    int row, col;
} GridWorld;

static const int dr[] = {-1, 1, 0, 0};  // 上 下 左 右
static const int dc[] = {0, 0, -1, 1};

void gridworld_reset(Env* e) {
    GridWorld* gw = (GridWorld*)e->internal;
    gw->row = 2;  // 起点S
    gw->col = 0;
}

EnvStep gridworld_step(Env* e, int action) {
    GridWorld* gw = (GridWorld*)e->internal;
    EnvStep step;
    step.done = 0;
    
    int new_row = gw->row + dr[action];
    int new_col = gw->col + dc[action];
    
    // 边界检查
    if (new_row >= 0 && new_row < 3 && new_col >= 0 && new_col < 4) {
        gw->row = new_row;
        gw->col = new_col;
    }
    
    // 奖励和终止
    if (gw->row == 0 && gw->col == 3) {        // 目标G
        step.reward = 1.0;
        step.done = 1;
    } else if (gw->row == 1 && gw->col == 1) { // 陷阱H
        step.reward = -1.0;
        step.done = 1;
    } else {
        step.reward = -0.01;  // 鼓励快速到达
    }
    
    step.state[0] = (double)(gw->row * 4 + gw->col);  // 状态编码
    return step;
}
```

<Callout type="tip">

**GridWorld是Q-Learning的理想测试环境**：状态空间小且离散（12个状态完全用Q表存储），问题清晰（最短路径），可可视化（网格直接打印），含关键挑战（陷阱需避开、延迟奖励）。

</Callout>

## CartPole环境

CartPole是经典的连续状态RL环境：控制小车左右移动使杆保持平衡。

### 环境定义

- **状态**：4维连续向量 `[x, ẋ, θ, θ̇]`（位置、速度、角度、角速度）
- **动作**：&#123;左推(0), 右推(1)&#125; 共2个离散动作
- **奖励**：每存活一步+1
- **终止**：杆角度超过±12°，或小车位置超出±2.4

### 物理模拟

```c
void cartpole_step(Env* e, int action) {
    CartPole* cp = (CartPole*)e->internal;
    
    double force = (action == 1) ? 10.0 : -10.0;
    double cos_theta = cos(cp->theta);
    double sin_theta = sin(cp->theta);
    double temp = (force + cp->polemass_length * cp->theta_dot * cp->theta_dot * sin_theta) / cp->total_mass;
    double thetaacc = (cp->gravity * sin_theta - cos_theta * temp) / 
                      (cp->length * (4.0/3.0 - cp->masscart * cos_theta * cos_theta / cp->total_mass));
    double xacc = temp - cp->polemass_length * thetaacc * cos_theta / cp->total_mass;
    
    // 欧拉法积分
    cp->x += cp->tau * cp->x_dot;
    cp->x_dot += cp->tau * xacc;
    cp->theta += cp->tau * cp->theta_dot;
    cp->theta_dot += cp->tau * thetaacc;
}
```

<Callout type="warning">

**为什么CartPole需要DQN？** 状态 `[x, ẋ, θ, θ̇]` 是连续的，有无穷多个值，Q表无法存储。若强行离散化（每维分10桶），状态数 `10^4=10000`，且精度损失大。DQN用神经网络 `Q(s,a;θ)` 近似连续状态到Q值的映射，只需存储网络参数。

</Callout>

## 奖励函数设计

| 类型 | 说明 | 优缺点 |
|------|------|--------|
| 稀疏奖励 | 只在目标达成时给奖励（GridWorld到G给+1） | 目标明确但学习困难（信号少） |
| 密集奖励 | 每步都给反馈（CartPole每步+1） | 信号丰富但可能误导 |
| 奖励塑形 | 在稀疏基础上加中间奖励 `r'=r+γΦ(s')-Φ(s)` | 需谨慎设计防止reward hacking |

## 统一训练循环

```c
// 适用于所有算法和环境的统一循环
for (int ep = 0; ep < MAX_EPISODES; ep++) {
    env_reset(&env);
    double state[STATE_DIM];
    get_state(&env, state);
    int done = 0;
    double total_reward = 0.0;
    
    while (!done) {
        // 算法选动作（Q-Learning/DQN/PG各不同）
        int action = agent_act(state);
        
        // 环境执行
        EnvStep step = env_step(&env, action);
        
        // 算法学习
        agent_learn(state, action, step.reward, step.state, step.done);
        
        memcpy(state, step.state, sizeof(double) * STATE_DIM);
        done = step.done;
        total_reward += step.reward;
    }
    
    printf("Episode %d, Reward: %.2f\n", ep, total_reward);
}
```

<Glossary>

<GlossaryItem term="GridWorld">
经典离散RL环境，网格中从起点到目标的最短路径问题。状态用网格位置编码（整数索引），动作4个方向，到达目标给正奖励陷阱给负奖励。因状态空间小且离散，是Q-Learning的理想测试环境。本书用C语言实现。
</GlossaryItem>

<GlossaryItem term="CartPole">
经典连续状态RL环境，控制小车使杆保持平衡。状态4维连续向量 `[x, ẋ, θ, θ̇]`，动作2个离散（左推/右推），每步+1奖励。因状态连续无法用Q表，是DQN的经典入门环境。C语言用欧拉法积分运动方程。
</GlossaryItem>

<GlossaryItem term="稀疏奖励（Sparse Reward）">
只在目标达成时给奖励，其余为0或小负值。优点：目标明确不误导。缺点：智能体随机探索难碰到奖励，大状态空间训练极慢。GridWorld只在到达G给+1是典型稀疏奖励。
</GlossaryItem>

<GlossaryItem term="奖励塑形（Reward Shaping）">
在稀疏奖励基础上加人工中间奖励 `r'=r+γΦ(s')-Φ(s)`（势函数法），理论保证不改变最优策略。作用：加速学习。风险：设计不当导致reward hacking（智能体钻空子获取高奖励但未完成任务）。
</GlossaryItem>

</Glossary>

### 问题 1

在C语言中如何设计一个统一的RL环境接口？为什么需要统一接口？

<Answer>

统一接口：`typedef struct { double state[STATE_DIM]; double reward; int done; } EnvStep;` 配合 `void env_reset(Env* e); EnvStep env_step(Env* e, int action);`。reset重置到初始状态，step接收动作返回新状态、奖励、是否终止。需要统一接口原因：①算法解耦——Q-Learning/DQN/PG只需调reset和step，换环境不改算法。②公平对比——同一接口比较不同算法。③可扩展——新环境实现接口即可接入。C语言用void* internal实现多态。
</Answer>

### 问题 2

GridWorld环境的C语言实现中，状态、动作、奖励如何定义？为什么它是Q-Learning的理想测试环境？

<Answer>

GridWorld定义：状态是网格位置 `(row,col)` 编码为整数 `s=row*n_cols+col`（4×3网格12个状态）；动作4个方向 &#123;上下左右&#125;；转移移动到相邻格碰墙留原地；奖励到G给+1到H给-1普通-0.01；到G或H终止。是Q-Learning理想测试环境原因：①状态空间小且离散——12个状态完全用 `double q[12][4]` 存储。②问题清晰有明确最优解。③可可视化——网格打印到终端。④含关键挑战——陷阱需避开、延迟奖励测试信用分配。⑤快速迭代——数千episode几秒。
</Answer>

### 问题 3

CartPole环境的状态、动作、奖励是什么？为什么它需要DQN而非Q-Learning？

<Answer>

CartPole：状态4维连续 `[x, ẋ, θ, θ̇]`（位置/速度/角度/角速度）；动作2个离散 &#123;左推/右推&#125;；奖励每步+1；终止——杆角度超±12°或小车位置超±2.4。需要DQN原因：状态连续有无穷多值，Q表无法枚举存储。强行离散化每维10桶状态数 `10^4=10000`，精度损失大且维度灾难。DQN用NN `Q(s,a;θ)` 近似连续状态到Q值映射，只需存网络参数（几百个浮点数）。C语言用欧拉法积分运动方程做物理模拟。
</Answer>

### 问题 4

在RL实验中，如何设计奖励函数？稀疏奖励和密集奖励各有什么优缺点？

<Answer>

设计原则：①目标对齐——奖励引导智能体达成真正目标，避免reward hacking。稀疏奖励：只在目标达成给奖励。优点目标明确不误导，缺点学习困难（信号少大空间不收敛）。密集奖励：每步给反馈。优点信号丰富收敛快，缺点可能引入偏差（如「距离目标」做奖励可能学到原地打转）。奖励塑形：稀疏+中间奖励 `r'=r+γΦ(s')-Φ(s)`（势函数法保证不改变最优策略）。实践：先稀疏验证环境正确性，不收敛再逐步加密集/塑形，监控奖励曲线和行为防止reward hacking。
</Answer>
