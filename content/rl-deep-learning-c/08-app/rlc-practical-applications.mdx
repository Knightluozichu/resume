## 方法选型：如何选择合适的RL算法

学完全书后面对新RL任务，如何选择算法？本章对比四种核心方法，给出选型决策树和工程实践指南。

<RlcPracticalApplicationsDiagram />

## 四种方法对比

| 方法 | 类型 | 状态空间 | 动作空间 | 优点 | 缺点 |
|------|------|---------|---------|------|------|
| Q-Learning | 基于价值 | 离散小 | 离散 | 简单稳定 | 不适用大空间 |
| DQN | 基于价值 | 连续/高维 | 离散 | 处理大状态空间 | 训练不稳定 |
| Policy Gradient | 基于策略 | 连续/高维 | 连续/离散 | 连续动作友好 | 方差大收敛慢 |
| Actor-Critic | 混合 | 连续/高维 | 连续/离散 | 方差小收敛快 | 实现复杂 |

## 选型决策树

```text
状态空间离散且小?
├── 是 → Q-Learning (Q表)
└── 否 → 动作空间连续?
    ├── 否 → DQN (NN近似Q)
    └── 是 → Policy Gradient / Actor-Critic
```

<Callout type="info">

**选型核心依据**：①状态空间——离散小用Q表，连续/高维用NN。②动作空间——离散用DQN，连续用PG/AC。③样本成本——免费仿真器可on-policy（PG），昂贵真实环境需off-policy（DQN+经验回放）。④任务复杂度——简单任务Q-Learning够用，复杂任务需Actor-Critic/PPO。

</Callout>

## C语言工程实践

### 内存管理

```c
// 用固定大小数组替代动态分配
#define MAX_STATES 1000
#define MAX_ACTIONS 10
#define MAX_LAYERS 5
#define MAX_NEURONS 128
#define BUFFER_SIZE 10000

// Q表：固定二维数组
double q_table[MAX_STATES][MAX_ACTIONS];

// 神经网络：固定三维数组
double W[MAX_LAYERS][MAX_NEURONS][MAX_NEURONS];

// 经验回放：环形缓冲区
typedef struct {
    double states[BUFFER_SIZE][STATE_DIM];
    int actions[BUFFER_SIZE];
    int idx;
    int size;
} ReplayBuffer;
```

<Callout type="tip">

**固定大小数组优先**：教学和嵌入式场景用编译时常量定义数组大小，避免malloc/free的开销和内存泄漏。虽然浪费空间但现代内存充足可接受，且缓存友好、访问快。

</Callout>

### 数值稳定性

```c
// 梯度裁剪
void clip_gradient(double* grad, int n, double max_norm) {
    double norm = 0.0;
    for (int i = 0; i < n; i++) norm += grad[i] * grad[i];
    norm = sqrt(norm);
    if (norm > max_norm) {
        double scale = max_norm / norm;
        for (int i = 0; i < n; i++) grad[i] *= scale;
    }
}

// 学习率衰减
double lr = lr0 / (1.0 + decay * epoch);

// 安全sigmoid（防溢出）
double sigmoid_safe(double x) {
    if (x >= 0.0) return 1.0 / (1.0 + exp(-x));
    double e = exp(x); return e / (1.0 + e);
}
```

## 评估与监控

### 核心指标

| 指标 | 说明 | C语言实现 |
|------|------|-----------|
| 平均回报 | 每100episode的平均累积奖励 | `total_reward / 100` |
| 收敛速度 | 达到目标回报的episode数 | 计数器 |
| 稳定性 | 收敛后回报的标准差 | 滑动窗口方差 |
| Q值监控 | DQN中max Q是否异常膨胀 | 打印 `max(Q)` |

### 学习曲线分析

```c
// 每100 episode打印日志
if (ep % 100 == 0) {
    printf("Episode %d, AvgReward: %.2f, Epsilon: %.3f, MaxQ: %.2f\n",
           ep, avg_reward, epsilon, max_q_value);
    fprintf(log_file, "%d %.2f %.3f %.2f\n", ep, avg_reward, epsilon, max_q_value);
}
```

<Callout type="warning">

**常见问题诊断**：①曲线长期不涨——探索不足或奖励稀疏，增大ε或加奖励塑形。②剧烈震荡——学习率过大，降低α/lr。③先涨后降——Q值发散或过拟合，检查梯度是否爆炸。④Q值膨胀——DQN过估计，用Double DQN。

</Callout>

## C语言 vs Python框架

| 维度 | C语言从零实现 | Python框架(PyTorch) |
|------|-------------|-------------------|
| 自动微分 | 手动推导+实现 | 自动 |
| GPU加速 | 需手写CUDA | 一行`.cuda()` |
| 生态 | 无 | 丰富(优化器/层/数据加载) |
| 理解深度 | 强制理解每步计算 | 可能成调包侠 |
| 内存控制 | 固定数组无GC | 有GC停顿 |
| 适用场景 | 学习/嵌入式 | 研究/生产 |

<Callout type="info">

**何时用哪种**：学习阶段（本书目标）用C语言打地基建立底层直觉；研究/生产阶段用Python框架快速迭代和规模化部署。理想路径是先C后Python——「知其然且知其所以然」。

</Callout>

<Glossary>

<GlossaryItem term="方法选型（Algorithm Selection）">
根据任务特性选择RL算法的过程。核心依据：状态空间（离散/连续）、动作空间（离散/连续）、样本成本、任务复杂度。决策树：状态离散小→Q-Learning；状态连续+动作离散→DQN；动作连续→PG/Actor-Critic。
</GlossaryItem>

<GlossaryItem term="学习曲线（Learning Curve）">
以episode为横轴、平均回报为纵轴的曲线，反映训练进展。理想曲线平滑上升后收敛。曲线形状诊断：长期不涨=探索不足/奖励稀疏；剧烈震荡=学习率过大；先涨后降=Q值发散/过拟合。
</GlossaryItem>

<GlossaryItem term="梯度裁剪（Gradient Clipping）">
防止梯度爆炸的技术，当梯度范数超阈值时按比例缩放。C语言实现：算范数→判断→缩放。在RNN和RL训练中常用，DQN和PG都建议使用。
</GlossaryItem>

<GlossaryItem term="reward hacking">
智能体找到奖励函数的漏洞获取高奖励但未完成真正任务的现象。如用「距离目标」做奖励可能学到原地打转。防止：谨慎设计奖励、监控实际行为、用稀疏奖励验证。
</GlossaryItem>

</Glossary>

### 问题 1

Q-Learning、DQN、Policy Gradient、Actor-Critic四种方法分别适合什么场景？

<Answer>

①Q-Learning——状态离散小且动作离散（GridWorld）。②DQN——状态连续/高维但动作离散（CartPole/Atari）。③Policy Gradient——动作连续（机器人控制）。④Actor-Critic——需兼顾连续动作和训练稳定性的复杂任务。选型决策树：状态离散小→Q-Learning；状态连续+动作离散→DQN；动作连续→PG（简单）或Actor-Critic（复杂）。
</Answer>

### 问题 2

在C语言实现RL算法时，内存管理有哪些关键注意事项？

<Answer>

①固定大小数组优先——用 `#define` 定义 `MAX_STATES/MAX_NEURONS/BUFFER_SIZE`，避免malloc/free。②环形缓冲区实现经验回放——`idx=(idx+1)%BUFFER_SIZE`循环覆盖。③神经网络用静态三维数组——`double W[MAX_LAYERS][MAX_NEURONS][MAX_NEURONS]`，缓存友好。④状态存储用一维数组——`states[idx*STATE_DIM]`索引更可控。⑤避免碎片化——预分配固定数组。⑥统一用double——float精度可能不足。⑦显式初始化——memset或循环置零。
</Answer>

### 问题 3

如何评估一个RL算法的训练效果？需要监控哪些指标？

<Answer>

核心指标：①平均回报——每100episode平均累积奖励，应单调上升收敛。注意评估时关闭探索（ε=0）。②收敛速度——达目标回报的episode数。③稳定性——收敛后回报标准差。④Q值/策略熵监控——DQN防Q值膨胀，PG防策略熵过早坍缩。⑤行为可视化——打印轨迹判断策略合理性。⑥泛化能力——未见状态上测试。学习曲线诊断：不涨=探索不足/奖励稀疏；震荡=学习率过大；先涨后降=Q值发散。C语言用fprintf输出日志后期画图。
</Answer>

### 问题 4

用C语言从零实现RL/DL相比用Python框架，在工程和教育上各有什么优劣？

<Answer>

工程优势(Python)：自动微分、GPU加速、生态丰富、调试工具。工程优势(C)：无依赖适合嵌入式、内存可控无GC停顿、性能透明。教育优势(C)：①强制理解底层——手动实现矩阵乘法/梯度/Q表更新无黑盒。②暴露数值问题——溢出/梯度消失firsthand体验。③建立直觉——「NN就是矩阵乘法+激活函数」「反向传播就是链式法则循环」。④可迁移——理解C实现后用PyTorch每个API都知道底层做什么。何时用：学习阶段用C打地基，研究生产用Python快速迭代规模化。理想路径先C后Python。
</Answer>
