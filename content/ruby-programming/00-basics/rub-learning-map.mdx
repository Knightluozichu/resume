## 直觉引入

如果把学 Ruby 比作学做一道菜，那这本《Ruby 基础教程》就是一份精心编排的食谱。你不会一开始就学分子料理（元编程），而是先认识食材（对象与变量），再学基本刀工（字符串与控制流），然后掌握烹饪技法（类与模块），最后才能自由创新（元编程与实战）。

Ruby 的设计者松本行弘（Matz）有一个核心理念：**让程序员快乐**。Ruby 的语法优雅、表达力强，追求"最小惊讶原则"——代码读起来应该像自然语言一样流畅。

## 概念讲解

### 四大板块

<Term def="Ruby 基础教程全书分为四大板块：Ruby基础、核心语法、类与模块、元编程与实战，按递进关系组织。">

全书十章分为四大板块，每个板块建立在前一个板块的基础上：

1. **Ruby 基础**（第1-2章）：对象模型与变量——一切皆对象是 Ruby 的地基
2. **核心语法**（第3-4章）：字符串与控制流——操作数据和流程控制的基本工具
3. **类与模块**（第5-7章）：类、模块与块——OOP 抽象与代码复用的核心机制
4. **元编程与实战**（第8-10章）：元编程与 Gems——运行时操控代码与生态管理

</Term>

### Ruby 的设计哲学

<Term def="Ruby 追求程序员快乐，核心原则包括：一切皆对象、块是灵魂、最小惊讶原则、多种方式做同一件事。">

Ruby 有几个区别于其他语言的核心设计：

- **一切皆对象**：`5.class` 返回 `Integer`，没有基本类型和对象类型的割裂
- **块是灵魂**：块（Block）让 Ruby 的迭代器如此优雅——`[1,2,3].each { |x| puts x }`
- **最小惊讶原则**：API 设计应让用户感到"自然"，方法名和行为应一致
- **表达力优先**：Ruby 允许多种写法，选择最可读的那种

</Term>

<Stepper>
<Step title="第一板块：Ruby 基础">
理解"一切皆对象"——数字、字符串、类本身都是对象。掌握四种变量（局部/实例/类/全局）的作用域。这是后续所有知识的基石：不理解对象模型，就无法理解类和元编程。
</Step>
<Step title="第二板块：核心语法">
学习字符串操作（可变、插值、冻结）和 Symbol 的区别。掌握条件分支（if/unless/case-when）和迭代器（each/times/map）。记住：Ruby 中只有 `nil` 和 `false` 为假，`0` 和 `""` 都是真。
</Step>
<Step title="第三板块：类与模块">
类是 OOP 的核心——`initialize` 构造、`attr_accessor` 生成属性、`<` 继承。模块解决 Ruby 单继承限制——通过 Mixin 实现多重继承。块、Proc、Lambda 是 Ruby 的函数式编程工具。
</Step>
<Step title="第四板块：元编程与实战">
元编程让 Ruby 的代码在运行时动态生成和修改——Rails 的优雅正源于此。`method_missing` 捕获未定义方法、`define_method` 动态定义方法、`send` 运行时调用。Gems 和 Bundler 管理 Ruby 的包依赖。
</Step>
</Stepper>

## 代码对照

```ruby
# Ruby 的"一切皆对象"在一行代码中体现
5.class          # => Integer
5.class.class    # => Class
5.class.superclass  # => Object

# 块——Ruby 的灵魂
[1, 2, 3].each { |x| puts x }          # 大括号块
[1, 2, 3].each do |x|                   # do-end 块
  puts x
end

# 模块 Mixin——解决单继承限制
module Walkable
  def walk; "#{self.class} walks"; end
end

class Dog
  include Walkable  # Dog 现在有 walk 方法
end

Dog.new.walk  # => "Dog walks"
```

## 常见误区

<Callout type="trap">
**误区：把 Ruby 当 Python 学**
Ruby 和 Python 看起来相似，但核心哲学不同。Python 追求"只有一种正确方式"，Ruby 追求"多种方式做同一件事"。Python 有基本类型和对象类型的区分，Ruby 一切皆对象。Python 的 lambda 只能一行，Ruby 的块可以多行。学 Ruby 要理解它的设计哲学，而非套用 Python 的思维。
</Callout>

<Callout type="trap">
**误区：跳过基础直接学 Rails**
Rails 大量使用元编程——`has_many`、`validates`、`before_action` 背后都是 `define_method` 和 `method_missing`。不理解 Ruby 的类、模块和块，Rails 的代码就像天书。先掌握 Ruby 基础，再学 Rails，才能理解 Rails 的魔法。
</Callout>

<Exercises>
**问题 1**：Ruby 全书四大板块的顺序是什么？为什么要按这个顺序学习？

<Answer>
四大板块：Ruby 基础（对象模型与变量）→ 核心语法（字符串与控制流）→ 类与模块（OOP 与 Mixin）→ 元编程与实战（动态方法与 Gems）。

按这个顺序学习是因为建立了递进的能力链：对象模型是理解一切的基础（一切皆对象），核心语法是操作对象的工具，类与模块是组织代码的抽象机制，元编程是运行时操控代码的高级能力。每一层都建立在前一层之上——不理解对象模型就无法理解类，不理解类就无法理解 Mixin，不理解模块就无法理解元编程中的 include/extend。
</Answer>

**问题 2**：Ruby 的"一切皆对象"与 Python 有什么本质区别？

<Answer>
Python 区分基本类型和对象类型——`int`、`float` 在 Python 中是基本类型（虽然 Python 3 做了统一，但历史包袱仍在），方法不是一等公民。

Ruby 从设计之初就坚持一切皆对象：`5` 是 `Integer` 的实例，`Integer` 是 `Class` 的实例，`Class` 的父类是 `Object`，`Object` 的父类是 `BasicObject`。方法可以通过 `method(:name)` 获取为 `Method` 对象。这种纯粹的对象模型让元编程更加一致和强大——所有类型都走同一套方法查找机制。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="一切皆对象">
Ruby 的核心设计原则——数字、字符串、类、模块本身都是对象。`5.class` 返回 `Integer`，`String.class` 返回 `Class`。这让 Ruby 的类型系统高度统一，元编程更一致。
</GlossaryItem>
<GlossaryItem term="块（Block）">
Ruby 的灵魂特性——一段可以传递给方法的代码。`{ |x| puts x }` 或 `do |x| puts x end`。通过 `yield` 调用，是迭代器和高阶函数的基础。
</GlossaryItem>
<GlossaryItem term="模块（Module）">
Ruby 的双重角色：命名空间组织代码 + Mixin 实现多重继承。模块不能实例化，但可以通过 `include`/`prepend`/`extend` 混入类中。
</GlossaryItem>
<GlossaryItem term="最小惊讶原则">
Matz 的设计理念——API 行为应符合用户的直觉预期。方法名应自解释，相同模式应有一致行为。这让 Ruby 代码读起来像自然语言。
</GlossaryItem>
</Glossary>
