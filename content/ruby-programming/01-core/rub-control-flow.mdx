## 直觉引入

控制流就像交通信号灯——它决定代码往哪个方向走。Ruby 的信号灯设计得很人性化：`if` 正向判断，`unless` 反向判断（"除非"），`case-when` 多路分支。而且 Ruby 的条件可以放在语句后面——`puts "hi" if greeting` 读起来像英语句子。

Ruby 的循环更倾向于"块迭代"——不写 `for i = 0; i < n; i++`，而是写 `n.times { |i| ... }`。这是 Ruby 的惯用法：让代码描述"做什么"而非"怎么做"。

## 概念讲解

### 条件分支

<Term def="Ruby 条件分支有三种：if/elsif/else（正向）、unless（反向）、case-when（多路匹配）。所有条件都是表达式，有返回值。">

```ruby
# if/elsif/else
result = if x > 0
  "正"
elsif x < 0
  "负"
else
  "零"
end

# unless = if 的反面
puts "不是零" unless x == 0

# 后缀形式（单行）
puts "成年人" if age >= 18

# 三目运算符
status = x > 0 ? "正" : "非正"
```

Ruby 的 `if` 是表达式——它返回最后求值表达式的结果，可以直接赋值。这让 Ruby 比 C/Java 的条件语句更灵活。

</Term>

### case-when 与 === 匹配

<Term def="case-when 使用 === 运算符匹配，比 switch 更强大——支持 Range、Class、Proc 等模式匹配。">

```ruby
case x
when 1..10      # Range === x：x 在 1..10 范围内
  "小"
when 11..100
  "中"
when String     # Class === x：x 是 String 的实例
  "字符串"
when ->(n) { n.is_a?(Integer) && n > 100 }  # Proc === x
  "大数"
else
  "其他"
end
```

`===` 的行为因左操作数类型而异：
- Range：`(1..10) === 5` → 是否包含
- Class：`String === "hi"` → 是否是实例
- Regexp：`/\d+/ === "123"` → 是否匹配
- Proc：`lambda === x` → 调用并返回布尔值

</Term>

### 循环与迭代

<Term def="Ruby 循环分两类：整数迭代（times/upto/downto）和集合迭代（each/map/select）。while/until/loop 较少使用——块迭代是惯用法。">

```ruby
# 整数迭代
5.times { |i| puts i }         # 0 1 2 3 4
1.upto(5) { |i| puts i }       # 1 2 3 4 5
5.downto(1) { |i| puts i }     # 5 4 3 2 1

# 集合迭代（最常用）
[1, 2, 3].each { |x| puts x }  # 1 2 3
[1, 2, 3].map { |x| x * 2 }   # [2, 4, 6]（返回新数组）
[1, 2, 3].select(&:even?)      # [2]（筛选）
{a: 1, b: 2}.each { |k, v| puts "#{k}=#{v}" }

# while/until（较少使用）
while x > 0 do x -= 1 end
until x == 0 do x -= 1 end     # while 的反面

# loop（无限循环，需 break）
loop do
  break if done
end
```

Ruby 倾向用 `each`/`map`/`select` 等块迭代替代 `while` 循环——更声明式、更安全、更符合 Ruby 风格。

</Term>

<Step title="选择条件结构">
单条件用 `if`/`unless`，多条件用 `case-when`。`unless` 用于"除非...否则不..."的语义——`raise_error unless valid`。后缀形式适合单行简单条件——`puts x if x`。`case-when` 用 `===` 匹配，支持 Range 和 Class，比 switch 强大得多。
</Step>
<Step title="选择循环结构">
优先用块迭代（each/map/select），而非 while/until。`n.times` 替代 `for i in 0...n`。`each_with_index` 替代手动计数。`map` 替代"遍历+push"模式。`select`/`reject` 替代"遍历+条件+push"。这样代码更声明式、更少 bug。
</Step>
<Step title="理解 === 与 == 的区别">
`==` 是值相等（`"a" == "a"` → true），`===` 是模式匹配（`String === "a"` → true）。`case-when` 隐式用 `===`，所以 `when String` 匹配字符串实例，`when 1..10` 匹配范围内数字。理解 `===` 是理解 case-when 的关键。
</Step>
</Stepper>

## 代码对照

```ruby
# === 条件分支 ===
score = 85

# if/elsif/else 作为表达式
grade = if score >= 90
  "A"
elsif score >= 80
  "B"
elsif score >= 70
  "C"
else
  "F"
end
puts grade  # => B

# case-when 多路匹配
case score
when 90..100 then "A"
when 80..89  then "B"
when 70..79  then "C"
else "F"
end

# unless（if 的反面）
puts "及格" unless score < 60

# === 循环迭代 ===
# 块迭代（惯用法）
numbers = [1, 2, 3, 4, 5]

# each：遍历（返回原数组）
sum = 0
numbers.each { |n| sum += n }
puts sum  # => 15

# map：变换（返回新数组）
doubled = numbers.map { |n| n * 2 }
puts doubled.inspect  # => [2, 4, 6, 8, 10]

# select：筛选
evens = numbers.select(&:even?)
puts evens.inspect  # => [2, 4]

# each_with_index
numbers.each_with_index do |n, i|
  puts "索引#{i}: #{n}"
end

# reduce：聚合
total = numbers.reduce(0) { |acc, n| acc + n }
puts total  # => 15

# Hash 迭代
hash = { name: "Alice", age: 30 }
hash.each { |key, value| puts "#{key}: #{value}" }
```

## 常见误区

<Callout type="trap">
**误区：用 for 循环替代 each**
Ruby 有 `for x in array` 语法，但它不创建新作用域——循环变量 `x` 会泄漏到外部。`array.each { |x| ... }` 用块，块变量在块外不可访问。Ruby 社区几乎不用 `for`，始终用 `each`。这不是风格问题，是作用域安全问题。
</Callout>

<Callout type="trap">
**误区：不理解 === 和 == 的区别**
`==` 是值相等判断（`5 == 5` → true）。`===` 是模式匹配，行为因左操作数类型而异：`Range#===` 检查包含，`Class#===` 检查类型，`Regexp#===` 检查匹配。`case-when` 隐式用 `===`，所以 `when Integer` 不是检查相等，而是 `Integer === x`（x 是否是 Integer 实例）。混淆两者会导致 case 逻辑错误。
</Callout>

<Exercises>
**问题 1**：以下 case-when 的输出是什么？解释 === 的作用。

```ruby
case "hello"
when String then puts "字符串"
when "hello" then puts "精确匹配"
when /ll/    then puts "正则匹配"
end
```

<Answer>
输出：`字符串`

`case-when` 从上到下匹配，找到第一个匹配就停止。`when String` 检查 `String === "hello"`——`Class#===` 检查右操作数是否是左操作数的实例。`"hello"` 是 `String` 的实例，所以匹配成功。

如果调整顺序：
```ruby
case "hello"
when "hello" then puts "精确匹配"  # "hello" === "hello" → true（先匹配）
when String  then puts "字符串"     # 不会执行
when /ll/    then puts "正则匹配"   # 不会执行
end
```
输出：`精确匹配`

关键：`===` 的行为取决于左操作数类型。`String === "hello"` 是类型检查，`"hello" === "hello"` 是值相等，`/ll/ === "hello"` 是正则匹配。case-when 按 === 语义匹配，从上到下短路。
</Answer>

**问题 2**：用 Ruby 惯用法重写以下 C 风格代码。

```c
// C 风格
int sum = 0;
for (int i = 0; i < 10; i++) {
    if (i % 2 == 0) {
        sum += i * i;
    }
}
```

<Answer>
Ruby 惯用法重写：

```ruby
# 最 Ruby 风格：链式块迭代
sum = (0...10).select(&:even?).map { |n| n * n }.sum

# 或者更简洁
sum = (0...10).step(2).map { |n| n * n }.sum

# 逐步分解
numbers = (0...10)              # Range: 0,1,2,...,9
evens = numbers.select(&:even?) # [0, 2, 4, 6, 8]
squares = evens.map { |n| n ** 2 }  # [0, 4, 16, 36, 64]
sum = squares.sum               # 120
```

关键变化：
1. `for` 循环 → `select`/`map`/`sum` 链式调用
2. `if (i % 2 == 0)` → `select(&:even?)`（声明式筛选）
3. `sum += i * i` → `map { |n| n ** 2 }.sum`（变换后聚合）
4. 整个逻辑一行表达，读起来像描述需求而非实现步骤

Ruby 风格核心：用块迭代描述"做什么"，让代码更声明式。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="case-when">
Ruby 的多路分支，使用 === 匹配。比 C/Java 的 switch 强大——支持 Range、Class、Regexp、Proc 等模式。从上到下短路匹配。
</GlossaryItem>
<GlossaryItem term="=== 运算符">
模式匹配运算符，行为因左操作数类型而异。Range 检查包含、Class 检查实例、Regexp 检查匹配。case-when 隐式使用。
</GlossaryItem>
<GlossaryItem term="块迭代">
Ruby 的惯用循环方式——each/map/select 等方法接收块，避免手动维护循环变量。比 while/for 更声明式、更安全。
</GlossaryItem>
<GlossaryItem term="后缀条件">
条件可放在语句之后——`puts x if x > 0`。适合单行简单条件，读起来像自然语言。`unless` 是反向后缀——`raise unless valid`。
</GlossaryItem>
</Glossary>
