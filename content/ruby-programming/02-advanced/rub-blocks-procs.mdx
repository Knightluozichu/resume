## 直觉引入

块就像你给方法的一张"便签"——上面写了"用这个方式处理每个元素"。方法 `each` 不知道也不关心你做什么，它只管遍历，然后通过 `yield` 把每个元素交给你便签上的代码处理。

块不是对象——你不能把它存进变量。但如果你需要存储或传递，可以用 `Proc.new` 把块变成对象。Lambda 是 Proc 的"严格版"——它像真正的函数：检查参数个数、`return` 只退出自身。

## 概念讲解

### 块（Block）

<Term def="块是附加在方法调用后的匿名代码段，用 {...} 或 do...end 表示。通过 yield 调用，不是对象。">

```ruby
# 大括号块（单行习惯用 {}）
[1, 2, 3].each { |x| puts x }

# do-end 块（多行习惯用 do...end）
[1, 2, 3].each do |x|
  result = x * x
  puts "#{x}^2 = #{result}"
end

# yield 调用块
def with_timer
  start = Time.now
  yield          # 执行传入的块
  puts "耗时: #{Time.now - start}s"
end

with_timer { sleep(1); puts "做事中" }
# => 做事中
# => 耗时: 1.0s
```

块不是对象——不能 `b = { puts "hi" }`。这是块与 Proc 的核心区别。

</Term>

### Proc 与 Lambda

<Term def="Proc 是对象化的块，可存入变量、作为参数传递。Lambda 是 Proc 的子类，检查参数个数且 return 只退出自身。">

```ruby
# Proc：块的对象形式
proc1 = Proc.new { |x| puts x * 2 }
proc1.call(5)     # => 10
proc1.(5)         # => 10（语法糖）
proc1[5]          # => 10（语法糖）

# Lambda：严格的 Proc
lam1 = lambda { |x| puts x * 2 }
lam2 = ->(x) { puts x * 2 }  # 箭头语法（Stabby Lambda）

lam1.call(5)      # => 10
```

Proc 和 Lambda 的两大差异：

1. **参数检查**：Lambda 严格检查参数个数，Proc 忽略多余/缺少的参数
2. **return 行为**：Lambda 的 return 只退出自身，Proc 的 return 退出定义它的方法

```ruby
# 参数检查差异
proc = Proc.new { |a, b| [a, b] }
proc.call(1)         # => [1, nil]（不报错，缺的补 nil）
proc.call(1, 2, 3)   # => [1, 2]（不报错，多余的丢弃）

lam = lambda { |a, b| [a, b] }
lam.call(1)          # => ArgumentError（参数数量错误）
lam.call(1, 2, 3)    # => ArgumentError
```

</Term>

### &block 与 &:method

<Term def="&block 将块捕获为 Proc 对象，&:method 是方法名转块的语法糖。& 是"转块"运算符。">

```ruby
# &block 捕获块
def compute(&block)
  block.call  # 块已转为 Proc 对象
end

compute { puts "Hi" }  # => Hi

# &:method 语法糖
[1, 2, 3].map { |x| x.to_s }  # 等价于
[1, 2, 3].map(&:to_s)         # => ["1", "2", "3"]

# &:upcase 等价于 { |s| s.upcase }
["hi", "hello"].map(&:upcase)  # => ["HI", "HELLO"]
```

`&:to_s` 的原理：`:to_s` 是 Symbol，`&` 调用 Symbol#to_proc 把它转成 `{ |obj| obj.to_s }`。

</Term>

<Stepper>
<Step title="块与 yield">
块是 Ruby 最自然的迭代机制。方法内用 `yield` 调用块，`yield(arg)` 传参给块。`block_given?` 检查是否传了块。块不是对象——不能存储，只能随方法调用使用。这是"最小惊讶"的体现——你不需要定义函数对象，直接写块就行。
</Step>
<Step title="Proc 对象化">
需要存储或传递块时，用 `Proc.new { }` 或 `&block` 捕获为 Proc 对象。Proc 是"松散"的——不检查参数，return 退出外层方法。适合"行内逻辑"的场景——回调、自定义排序。
</Step>
<Step title="Lambda 严格函数">
Lambda 是 Proc 的严格版——检查参数、return 只退出自身。行为更像"真正的函数"。适合需要严格契约的场景——高阶函数、闭包。`->(x) { x * 2 }` 是简洁的箭头语法。
</Step>
</Stepper>

## 代码对照

```ruby
# === yield 与块 ===
def repeat(n)
  n.times { yield }  # 调用块 n 次
end

repeat(3) { puts "Hello" }
# => Hello
# => Hello
# => Hello

# 带参数的 yield
def map_result(array)
  result = []
  array.each { |x| result << yield(x) }
  result
end

puts map_result([1, 2, 3]) { |x| x * 10 }.inspect
# => [10, 20, 30]

# block_given? 检查
def safe_yield
  if block_given?
    yield
  else
    "no block"
  end
end

puts safe_yield { "有块" }  # => 有块
puts safe_yield             # => no block

# === &block 捕获 ===
def store_block(&block)
  @callback = block  # 存储块为 Proc 对象
end

def run_callback(arg)
  @callback.call(arg) if @callback
end

store_block { |x| puts "回调: #{x}" }
run_callback("test")  # => 回调: test

# === &:method 语法糖 ===
names = ["alice", "bob", "charlie"]

# 完整写法
upcase_names = names.map { |n| n.upcase }

# 语法糖（Symbol#to_proc）
upcase_names = names.map(&:upcase)  # => ["ALICE", "BOB", "CHARLIE"]

# 链式调用
puts names.map(&:upcase).map(&:length).inspect
# => [5, 3, 7]

# === Proc vs Lambda return ===
def proc_return
  p = Proc.new { return 1 }
  p.call
  return 2  # 不会执行——Proc 的 return 退出了方法
end

def lambda_return
  l = lambda { return 1 }
  l.call       # return 只退出 lambda
  return 2     # 会执行
end

puts proc_return    # => 1
puts lambda_return  # => 2
```

## 常见误区

<Callout type="trap">
**误区：混淆 Proc 和 Lambda 的 return 行为**
Proc 的 `return` 退出**定义它的方法**（不是 Proc 本身）——如果方法已经返回，会抛 `LocalJumpError`。Lambda 的 `return` 只退出 Lambda 自身。这导致：在方法内用 Proc 时 `return` 提前退出方法，而 Lambda 不会。记住：Lambda 行为更像"独立函数"，Proc 行为更像"内联代码"。
</Callout>

<Callout type="trap">
**误区：不理解 `&:method` 的工作原理**
`array.map(&:upcase)` 不是魔法——`&` 对 Symbol 调用 `to_proc`，生成 `{ |obj| obj.upcase }`。这意味着 `&:method` 只能调用无参方法（如 `to_s`、`upcase`、`strip`）。需要参数时不能用它——`map(&:+(1))` 是不合法的。理解原理后就不会滥用。
</Callout>

<Exercises>
**问题 1**：以下代码输出什么？解释 Proc 和 Lambda 在 return 上的差异。

```ruby
def test_proc
  p = Proc.new { return "from proc" }
  p.call
  "from method"
end

def test_lambda
  l = lambda { return "from lambda" }
  l.call
  "from method"
end

puts test_proc
puts test_lambda
```

<Answer>
输出：
```
from proc
from method
```

解释：
- **Proc 的 return**：退出定义 Proc 的方法。`test_proc` 中 `p.call` 执行 Proc，`return "from proc"` 直接退出 `test_proc` 方法。后面的 `"from method"` 永远不执行。
- **Lambda 的 return**：只退出 Lambda 自身。`l.call` 执行 Lambda，`return "from lambda"` 只退出 Lambda。`test_lambda` 继续执行，返回 `"from method"`。

核心差异：Proc 的行为像"内联代码"——return 影响外层方法。Lambda 的行为像"独立函数"——return 只影响自身。选择建议：需要严格函数语义用 Lambda，需要与外层方法紧密耦合用 Proc。
</Answer>

**问题 2**：实现一个 `with_file` 方法，打开文件、执行块、确保关闭文件（类似 File.open 的块形式）。

<Answer>
```ruby
def with_file(filename, mode = "r")
  file = File.open(filename, mode)
  begin
    yield(file)          # 把文件对象传给块
  ensure
    file.close            # 确保关闭
  end
end

# 使用
with_file("data.txt") do |f|
  content = f.read
  puts content
end  # 文件自动关闭，即使块中抛异常

# 原理分析：
# 1. 方法打开文件，创建 File 对象
# 2. yield(file) 将文件传给块使用
# 3. ensure 保证无论块是否抛异常，文件都被关闭
# 4. 块返回值成为方法返回值（如果块正常执行）

# 对比 File.open 的块形式（标准库就是这么做的）
File.open("data.txt") do |f|
  puts f.read
end  # File.open 内部用 ensure 关闭文件

# 更通用的资源管理模式
def with_resource(resource)
  begin
    resource.open
    yield(resource)
  ensure
    resource.close
  end
end

# 这是"块作为资源管理工具"的经典模式——RAII 的 Ruby 版本
```

关键点：
1. `yield(file)` 把资源传给块——块负责使用资源
2. `ensure` 保证资源释放——无论正常返回还是异常
3. 这是 Ruby 的惯用法——File.open、DB 连接、锁都用这种模式
4. 块让资源管理的"获取-使用-释放"模式变得优雅
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="块（Block）">
Ruby 的核心特性——附加在方法调用后的匿名代码段。`{ |x| ... }` 或 `do |x| ... end`。通过 yield 调用，不是对象。是迭代器和资源管理的基石。
</GlossaryItem>
<GlossaryItem term="Proc">
对象化的块——可以存入变量、作为参数传递、在方法间复用。不检查参数个数，return 退出定义它的方法。用 `Proc.new { }` 或 `&block` 创建。
</GlossaryItem>
<GlossaryItem term="Lambda">
Proc 的严格版——检查参数个数，return 只退出自身。行为更像独立函数。`lambda { |x| ... }` 或 `->(x) { ... }` 创建。适合高阶函数和闭包。
</GlossaryItem>
<GlossaryItem term="&:method 语法糖">
`array.map(&:upcase)` 的简写。`&` 对 Symbol 调用 `to_proc`，生成 `{ |obj| obj.upcase }`。只能用于无参方法调用。
</GlossaryItem>
</Glossary>
