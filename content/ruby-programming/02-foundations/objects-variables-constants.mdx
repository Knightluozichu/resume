## 从“变量装着值”这个误解开始

在Ruby里，变量更像贴在对象引用上的名字，而不是内嵌对象的盒子。执行`copy = original`不会自动复制String、Array或自定义对象；两个名字可能指向同一object，任何原地修改都能从两边观察到。是理解参数传递、容器元素与缓存副作用的起点。

先预测：`a = "ruby"; b = a; b.upcase!`之后`a`是什么？它也看到`"RUBY"`；若写`b = b.upcase`，则b改指向新String，a仍指向原对象。前者是mutation，后者包含新对象与rebinding。

## 对象

对象具有identity、可观察state和class，并通过method响应消息。`object_id`可辅助一次进程内的identity实验，`equal?`判断是否同一对象；`==`由class定义value equality；`eql?`与`hash`共同影响Hash key。要求调用者根据用途选方法。

```ruby
first = "ruby"
same = first
equal_value = "ruby"

p first.equal?(same)        # true
p first.equal?(equal_value) # false
p first == equal_value      # true
p first.eql?(equal_value)   # true for these Strings
```

`freeze`阻止某些对象的后续修改，但不是递归deep freeze：冻结Array不会自动冻结内部String。把可变对象当Hash key后再改变参与`hash`/`eql?`的state，会让lookup失效；key应使用稳定immutable value，或在修改后谨慎`rehash`。对象边界不只看能否调用方法，还要看谁拥有mutation权。

## 类

Class描述实例如何构造以及method lookup从何开始。`value.class`返回Class对象，`Class`本身也是class；`is_a?`沿ancestor chain判断实例是否属于某class/module，通常比精确比较`value.class == Expected`更支持subclass与mixin。

```ruby
class Counter
  def initialize(start)
    @value = start
  end

  def increment
    @value += 1
  end
end

counter = Counter.new(10)
p counter.increment
p Counter.ancestors
```

Ruby方法调用依赖行为而非必须先通过class检查。若对象只需响应`each`或`write`，直接依赖这个protocol并在边界测试；过度使用`is_a?`常把开放的message model收窄成硬编码type switch。第8章会展开继承、module、mixin和duck typing。


## 变量：名字前缀说明owner

Ruby没有变量类型声明，但变量类别通过名字形态决定。比“前缀记忆表”更重要。

局部变量如`total`由lexical scope决定；parser看到赋值后才把名字识别为local，否则无receiver调用`total`可能被解析为method call。Instance variable如`@total`属于某个object，未初始化读取通常得到nil。Class variable如`@@total`在inheritance hierarchy共享，容易让一个subclass影响另一个。Global variable如`$total`全进程可见，是隐藏依赖。

### 局部变量、实例变量、类变量与全局变量

局部变量适合一次method/block activation内的中间状态；instance variable保存object长期state，应只通过维持不变量的方法修改。Class variable应谨慎使用：如果目标是“每个class自己拥有一个值”，更常用class object的instance variable `@count`，避免ancestor共享规则。Global state优先封装进显式object并注入调用者。

```ruby
class Sequence
  @created = 0

  class << self
    attr_reader :created

    def build
      @created += 1
      new(@created)
    end
  end

  def initialize(number)
    @number = number
  end
end
```

这里`Sequence`作为object拥有`@created`，每个instance拥有自己的`@number`。相同拼写的instance variable附着在不同receiver上，不共享。并发访问`@created += 1`仍需要同步；选择class-instance variable只解决owner，不自动保证atomicity。


## 常量

以大写字母开头的名字通常是constant，按lexical nesting与ancestor规则解析。Constant assignment后重新赋值会warning，但Ruby并不因此冻结引用对象：`OPTIONS = []`后仍可`OPTIONS << :fast`。要求需要immutable data时显式freeze并处理nested对象。

Constant适合class/module、不会改变的configuration schema和真正固定值；runtime可变配置不应伪装成constant。Namespace使用module/class嵌套，引用外层constant时明确`Outer::NAME`。Autoload与framework loader可能增加解析规则，核心Ruby实验先用普通require固定来源。

## 保留字

`class`、`module`、`def`、`if`、`unless`、`case`、`while`、`do`、`end`、`begin`、`rescue`、`ensure`、`yield`、`self`、`nil`、`true`和`false`等是parser保留字，不能作为普通local/method定义名称。保留字与内置method不同：`puts`可被重新定义或以receiver限定，`if`属于grammar。

Dynamic Hash key或外部字段可包含`"class"`，但转成keyword、method或constant前必须有mapping。代码生成器要先处理keyword collision，不能只做字符替换。静态syntax check能发现grammar冲突，却不能证明生成的API语义合理。


## 多重赋值

多重赋值先求值右侧，再把结果分配给左侧目标，因此可安全交换变量。解释了swap、解构和方法多返回值。

```ruby
left = "L"
right = "R"
left, right = right, left

head, *middle, tail = [10, 20, 30, 40]
p left: left, right: right
p head: head, middle: middle, tail: tail
```

左侧位置多于值时用nil补齐；值多于无splat的目标时多余值被丢弃。这个便利会掩盖input shape变化，外部data应先检查length/schema，再解构。Splat总是收集Array；只有一个目标但希望拆开Array时，需要逗号或splat表达解构意图。

### 交换变量的值

`a, b = b, a`不会让第二个assignment读到已修改的a，因为右侧在分配前完成。若右侧method有side effect，仍按从左到右求值；不要把复杂I/O和状态修改藏进一个看似简单的swap表达式。

### 获取数组的元素

`first, second = values`取前两项；`first, *rest`保留剩余项；`first, = values`只取第一项；nested pattern可拆嵌套Array。解构返回的是元素引用，不是deep copy，修改nested mutable元素仍可能影响原数组。


## 本章回顾：先找对象，再找名字owner

1. Assignment复制reference；mutation、rebinding与copy是不同操作，identity/value/hash equality也不同。
2. Class规定实例构造与method lookup，但Ruby接口常依赖可响应的行为而非精确class。
3. Local、instance、class和global变量扩大不同scope；优先选择最窄owner并显式注入共享依赖。
4. Constant约束名称绑定意图，不自动冻结对象；保留字属于grammar而非普通内置method。
5. Multiple assignment先求值右侧再分配，便于swap与destructure，也可能静默补nil或丢多余值。
