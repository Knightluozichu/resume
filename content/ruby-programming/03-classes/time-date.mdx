## 从“时间就是一个Time对象”开始拆分

时间需求至少分instant、elapsed duration、calendar date、local civil time与timezone rules。<Term def="时间值声明它表示instant、duration、calendar date还是local civil fields，以及采用哪个clock/zone。">temporal type contract</Term>避免一个Time同时承担所有语义。

先预测：测代码耗时用`Time.now`是否可靠？系统clock可NTP调整或人工回拨，差值可能跳变；elapsed measurement使用monotonic clock。Wall time保留给timestamp与用户日历。

## Time类与Date类

Time表示带offset/zone解释的instant与civil fields；Date标准库表示calendar date而无time-of-day。DateTime也存在，但现代实践常用Time+Date及timezone library；本书语义按Ruby 2.3 API验证。

<Term def="Date只有年月日，Time包含instant/time-of-day/offset；互转时必须补充或丢弃信息。">Time Date information boundary</Term>说明转换不可能完全中性。

```ruby
require "date"

instant = Time.now
date = Date.today

p instant: instant, date: date
p utc: instant.utc
```

System default timezone依部署环境变化，测试不要依赖机器local zone。业务若需IANA zone/DST历史，使用成熟timezone library并固定tzdata version；numeric offset不等于完整zone rules。

## 获取时间

`Time.now`获取wall clock，`Time.utc`/`Time.local`从civil fields构造，`Time.at`从epoch seconds构造。<Term def="Clock source可注入，生产选择wall或monotonic，测试使用fixed/fake clock。">clock injection boundary</Term>让expiration和scheduler可测。

```ruby
class Expiry
  def initialize(clock)
    @clock = clock
  end

  def expired?(deadline)
    @clock.call >= deadline
  end
end

fixed = -> { Time.utc(2026, 7, 14, 12, 0, 0) }
p Expiry.new(fixed).expired?(Time.utc(2026, 7, 14, 11, 0, 0))
```

Deadline若用于进程内timeout，使用monotonic numeric deadline；业务token expiry跨进程则用UTC instant并接受wall clock skew policy。

## 计算时间

Time-Time得到seconds数值，Time+seconds得到新Time。Elapsed duration使用`Process.clock_gettime(Process::CLOCK_MONOTONIC)`，不可转calendar。<Term def="Duration arithmetic使用明确seconds unit与monotonic source，不混入calendar day/month。">elapsed time contract</Term>。

```ruby
started = Process.clock_gettime(Process::CLOCK_MONOTONIC)
perform_work
elapsed = Process.clock_gettime(Process::CLOCK_MONOTONIC) - started
puts format("%.3fs", elapsed)
```

Timeout budget递减同一monotonic deadline，nested calls传remaining time，避免每层重新给完整timeout。Wall timestamps相减可用于历史approximate interval，但DST/clock adjustment语义需说明。

## 时间的格式与本地时间

`strftime`按pattern格式化；pattern必须包含业务所需zone offset与precision。<Term def="时间文本声明pattern、locale、timezone/offset、fraction precision与缺失字段默认。">time format contract</Term>不使用locale-dependent默认to_s作为machine protocol。

```ruby
instant = Time.utc(2026, 7, 14, 12, 34, 56)
p instant.strftime("%Y-%m-%dT%H:%M:%SZ")
p instant.getlocal("+08:00").strftime("%Y-%m-%d %H:%M:%S %:z")
```

Ruby 2.3对`%:z`等directive支持需验证。UTC用Z/offset；local display需要user timezone而非server timezone。Offset `+08:00`不包含DST/history，长期schedule使用IANA zone。

## 从字符串中获取时间

`Time.parse`灵活但会推断缺失fields，machine input优先`Time.strptime(text, pattern)`或ISO parser。<Term def="Parse只接受完整声明的grammar，拒绝ambiguous、trailing text与非法calendar fields。">strict temporal parsing</Term>。

```ruby
require "time"

text = "2026-07-14T12:34:56+08:00"
parsed = Time.iso8601(text)
p parsed.utc
```

Input若无offset，是local civil time而非唯一instant；API必须要求zone或由明确user context解释。DST overlap同一local time可能对应两个instants，gap可能不存在；timezone library提供disambiguation policy。

## 获取日期

`Date.today`依local zone，`Date.new(year, month, day)`显式构造，`Date.parse/strptime/iso8601`解析。<Term def="Business date使用哪一timezone决定today，并以Gregorian calendar/有效年月日验证。">calendar date contract</Term>不能让server zone决定用户“今天”。

```ruby
require "date"

date = Date.new(2026, 7, 14)
p date
p date.leap?
p date.wday
```

账单/航班日期通常是local calendar date，存Date/ISO date，不先转midnight UTC造成偏移。

## 计算日期

Date+Integer按calendar days移动，Date-Date得Rational days；`>>`/`<<`移动months。<Term def="Calendar arithmetic按日/月/年规则并明确month-end、leap day与business-day policy。">calendar arithmetic contract</Term>不同于加86400 seconds。

```ruby
date = Date.new(2024, 1, 31)
p next_day: date + 1
p next_month: date >> 1
p previous_month: date << 1
```

Month shift的end-of-month clamping按API验证；“每月最后一天”与“同日号，不存在则某政策”需独立domain object。Business days还要holiday calendar/version，不能只跳周末。

## 日期的格式与从字符串中获取日期

Date#strftime格式化，Date.strptime按pattern严格解析，Date.iso8601适合`YYYY-MM-DD`。<Term def="Date text只包含calendar fields，不暗示time-of-day或timezone。">date serialization boundary</Term>让API避免混淆。

Flexible Date.parse可能接受不完整/多格式；import先按schema尝试有限formats并记录选择，不随locale。Round-trip测试leap day、month-end、invalid 2023-02-29与leading zeros。

## Time与Date的互相转换

Time#to_date丢time-of-day/offset context（先在哪个zone取date很重要）；Date#to_time或构造Time必须选择time与zone。<Term def="Time到Date先选zone后截取，Date到Time必须补time-of-day和zone。">temporal conversion contract</Term>禁止隐式server defaults。

```ruby
require "date"

instant = Time.utc(2026, 7, 14, 23, 30)
shanghai_like = instant.getlocal("+08:00")
p utc_date: instant.to_date
p local_date: shanghai_like.to_date
```

同一instant在不同zone可能不同date。Date转instant用于“当天开始”时，DST使day length非86400秒；timezone library按zone rules计算start/end。

## 本章回顾：Instant、Duration与Calendar不可混用

1. Time/Date承载不同信息，clock/zone必须显式；测试注入fixed/monotonic source。
2. Elapsed measurement用monotonic，UTC instant用于storage，user zone用于display/calendar。
3. Format/parse固定pattern、offset、precision与strictness，epoch明确seconds/millis。
4. Date arithmetic按calendar day/month并处理leap/month-end/business calendar，不用固定秒数替代。
5. Time↔Date转换会丢失或补充time/zone，必须由业务policy决定。

<Exercises>

**问题 1：怎样测试“30分钟后过期”而不sleep？**

<Answer>把clock注入对象，业务expiry用fixed wall/UTC instants；进程timeout用fake monotonic numeric clock。推进fake值断言边界前/等于/后，另测clock skew policy。</Answer>

**问题 2：为什么无offset时间文本不能直接转唯一Time？**

<Answer>它只给local civil fields，缺timezone；不同zone对应不同instant，DST overlap甚至同zone有两个候选。要求offset/zone，或由明确user context与gap/overlap policy解释。</Answer>

**问题 3：如何表达“下个月最后一天”？**

<Answer>使用Date calendar operations构造下月并求其末日，明确month-end policy；不要加30天或固定seconds。测试1月31日、2月闰/平年、12月跨年和business calendar调整。</Answer>
