## 为什么总复习从故障模型而不是目录背诵开始

完成23章后，最有价值的能力不是顺序背出`Array`后面是`String`，而是看到现象就知道画哪张图。三个数组元素一起变化属于对象状态；块里的`return`提前离开方法属于控制分派；UTF-8字符串与Windows-31J字节混用属于数据解释；导入中断留下半个数据库属于资源边界。官方目录保证覆盖，故障模型把覆盖转化为诊断方法。

先预测再分类：`Hash.new([])`导致不同key共享数组是哪类；`rescue Exception`吞掉终止信号是哪类；`String#length`与`bytesize`判断协议长度错误是哪类；`File.open`后回调抛错却没关闭handle是哪类；正则按逗号切CSV为何同时违反数据与边界契约。分类不是贴标签，而是决定收集什么证据、回查哪章、最小复现应保留哪些行为。

### 第一部分：最小程序与对象消息

Ruby表达式几乎都围绕接收者发送消息。字面量创建对象，变量保存引用，方法返回最后一个表达式；数组、散列、正则和时间对象在第2章先提供直觉，第3章把它们放入实际命令。终局验收需要同时说明stdout/stderr、exit status、输入编码和运行目录，不能把IDE中的一次输出当作程序契约。

```ruby
def run(argv, stdout: $stdout, stderr: $stderr)
  path = argv.fetch(0)
  stdout.puts File.basename(path)
  0
rescue KeyError => error
  stderr.puts "usage: ruby tool.rb PATH (#{error.message})"
  64
end

exit(run(ARGV)) if $PROGRAM_NAME == __FILE__
```

这里依次出现参数、方法、File类、依赖注入、特定异常与状态码。测试不要启动真实进程也可以传`StringIO`，但最终仍要做一次进程级验收，确认通道与exit status一致。

### 第二部分：作用域、分派、块与异常

第4-11章可以用一条调用链串联：局部变量引用一个receiver；条件决定是否调用；循环或迭代器重复调用；方法按参数契约执行；类与模块决定方法查找；运算符转成方法；块交给被调用者控制；异常沿栈传播并由`rescue`/`ensure`收口。

<Term def="记录receiver、class/ancestors、method、arguments、block、result、exception与ensure的完整调用证据。">dispatch trace</Term>比“Ruby是动态语言”更具体。

```ruby
class Batch
  def initialize(items)
    @items = items
  end

  def each_valid
    return enum_for(__method__) unless block_given?

    @items.each_with_index do |item, index|
      yield item
    rescue StandardError => error
      warn "index=#{index} #{error.class}: #{error.message}"
    end
  end
end
```

要验证空集合、块缺失、块异常、外部可变状态和重复枚举。`rescue`范围过大时会把哪个操作的错误归到当前item，也需要明确；清理资源应放在真正拥有资源的frame中。

<Callout type="trap" title="把所有错误都rescue StandardError后继续，程序就更健壮">
恢复需要明确不变量。若一个item失败后全局状态已部分改变，继续会扩大污染；若无法恢复，应补充上下文后重新抛出或终止transaction。捕获异常不是完成错误处理。
</Callout>

### 第三部分：核心类的表示与语义

第12-21章围绕“同一个值如何被表示、转换和拥有”。Numeric有整数/浮点与范围；Array有顺序、索引、共享元素；String有字符、字节、编码和可变性；Hash有key equality、default与顺序；Regexp有pattern grammar、match state和回溯风险；IO/File/Dir有open/read/write/close；Encoding定义decode/encode错误；Time/Date定义日历、时区与区间；Proc把块对象化并带来参数与`return`差异。

<Term def="同时说明type、identity、shape、range、bytes、encoding、ordering和aliasing，并用独立断言验证转换前后。">representation proof</Term>是核心类复习的共同格式。

```ruby
raw = File.binread("records.txt")
decoded = raw.encode("UTF-8", "Windows-31J", invalid: :raise, undef: :raise)

rows = decoded.each_line.filter_map.with_index(1) do |line, number|
  fields = line.chomp.split("\t", -1)
  raise "line #{number}: expected 3 fields" unless fields.length == 3
  fields.freeze
end
```

示例仅适用于真正的TSV，不适用于CSV；若源格式允许quoted newline，应换`CSV`parser。`each_line`是stream边界，`encode`是否一次加载全文件是memory边界，`freeze`只冻结外层数组还是字段字符串也要验证。正是这些问题把API调用升级为表示证明。

### 第四部分：工具的来源、事务与查询契约

第22章要求文本处理具有input grammar、encoding、streaming、deterministic output和error status；第23章把source provenance、CSV schema、normalization、SQLite schema/index、prepared insert、transaction、validation、atomic activation与parameterized query连接起来。数据库文件只是某个source version的派生索引，raw数据和构建报告才是重建依据。

<Term def="候选数据集在独立位置完整构建并通过行数、完整性、样本查询和版本检查后，才原子替换live版本。">candidate activation contract</Term>阻止读者看到半完成状态。

```ruby
database.transaction do
  statement = database.prepare(<<~SQL)
    INSERT INTO postal_codes(postal_code, prefecture, city, locality)
    VALUES (?, ?, ?, ?)
  SQL

  begin
    records.each { |record| statement.execute(*record.values_at(:code, :prefecture, :city, :locality)) }
  ensure
    statement.close
  end
end
```

还要固定gem/schema版本，验证duplicate distribution和index plan，在candidate关闭并flush后activate。查询参数绑定只能保护values，表名和排序字段必须allowlist；空结果是正常业务状态，数据库损坏才是系统错误。

### 对象状态：Identity、Alias与Method Lookup

Ruby变量是标签，赋值不会自动复制对象。`Array.new(3, [])`和`Hash.new([])`都可能制造意外共享；`dup`与`clone`也只做浅复制且冻结/单例方法语义不同。对象故障先打印`class`、`object_id`、关键字段与`ancestors`，再缩小到哪次状态转移破坏不变量。

### 控制分派：Return、Yield与Exception

方法、块、Proc和lambda的参数/return不同；`break`、`next`、`redo`改变迭代；异常同时携带class、message、cause与backtrace。<Term def="列出caller、receiver、running frame、block、normal result、exception与下一owner的控制账本。">control-transfer ledger</Term>用于区分业务`false`、正常`nil`和执行失败。

### 数据解释：Bytes、Encoding、Pattern与Time

字符串的`length`按字符语义，`bytesize`按字节；`force_encoding`只改标签，不验证或转码；`encode`才做转换。正则处理模式，CSV处理结构；Time对象的offset与时区数据库不是一回事。每次转换都保存original，明确normalization version并测试不可表示字符。

### 资源边界：IO、Callback与Transaction

Block-form `File.open`、`Dir.chdir`、transaction和prepared statement都是owner工具。资源清理覆盖success、error、cancel和shutdown；`ensure`必须幂等且不能遮蔽原异常。Proc回调可能晚到，需用generation/token判断目标是否仍有效。SQLite candidate只有验证后才能activate，旧版本保留到rollback窗口结束。

<Callout type="trap" title="Ruby有垃圾回收，所以文件和数据库资源最终会自动释放">
GC只管理Ruby对象可达性，不保证及时关闭稀缺OS/数据库资源，也不保证transaction语义。文件、statement、connection和temporary candidate必须有显式owner与终止路径。
</Callout>

<Exercises>

**问题 1：Hash不同key意外共享同一个Array，属于哪类故障，如何证明？**

<Answer>主类是对象状态/alias。构造两个不存在的key，分别取得默认值并比较`object_id`；向其中一个追加后断言另一个也变化。修复为`Hash.new { |hash, key| hash[key] = [] }`，再断言不同key的对象ID不同且重复访问同一key稳定。</Answer>

**问题 2：CSV导入中回调抛错后出现半张live表，怎样按四模型修复？**

<Answer>控制上让异常传播到拥有transaction的frame；资源上在candidate数据库内事务导入并ensure关闭statement/connection；数据上保留row locator和原始字段；对象上避免跨row共享可变buffer。失败时rollback且不activate，断言live version/hash/rows/query不变。</Answer>

**问题 3：一个完整Ruby数据工具需要哪些验收项？**

<Answer>输入有参数、来源、版本、checksum、encoding和size限制；转换有CSV schema、original/canonical和rejected rows；持久化有schema/index/prepared transaction/integrity/activation；查询有grammar、limit、stable order、empty/error status和dataset provenance。测试正常、坏编码、重复、中断、验证失败、数据库忙、重复运行、回滚与shutdown。</Answer>

</Exercises>
