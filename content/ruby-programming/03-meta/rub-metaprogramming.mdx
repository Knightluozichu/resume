## 直觉引入

元编程就像"写代码的代码"——普通编程是写代码让计算机执行，元编程是写代码让代码自己生成代码。

想象你有一个数据表 `users`，有 `name`、`email`、`age` 字段。在 Java 中你需要手写 `findByName`、`findByEmail`、`findByAge` 三个方法。在 Ruby on Rails 中，你只需要写 `find_by` 一次——`method_missing` 会在运行时拦截 `find_by_name` 调用，自动解析方法名，生成查询。这就是元编程的威力。

## 概念讲解

### Open Class（打开类）

<Term def="Open Class 允许在任何地方重新打开已存在的类（包括内置类），添加或修改方法。Ruby 没有类的"封闭"概念。">

```ruby
# 重新打开 String 类，添加方法
class String
  def shout
    upcase + "!!!"
  end
end

puts "hello".shout  # => HELLO!!!

# 这就是"猴子补丁"（Monkey Patching）
# 甚至可以覆盖内置方法（危险！）
class String
  def length
    42  # 不要这么做！
  end
end
```

Open Class 是 Ruby 最强大的特性之一，也是最危险的——你可以修改任何类，包括 `String`、`Integer` 等内置类。Rails 大量使用 Open Class 扩展内置类（如 `ActiveSupport` 给 `Time` 加了 `1.day.ago`）。

</Term>

### define_method 动态定义

<Term def="define_method 在运行时动态创建方法，避免重复编写相似的样板代码。">

```ruby
class Product
  ATTRIBUTES = [:name, :price, :stock]

  ATTRIBUTES.each do |attr|
    define_method(attr) do
      instance_variable_get("@#{attr}")
    end

    define_method("#{attr}=") do |value|
      instance_variable_set("@#{attr}", value)
    end
  end
end

p = Product.new
p.name = "Widget"
p.price = 9.99
puts p.name   # => Widget
puts p.price  # => 9.99
```

这就是 `attr_accessor` 的简化实现——用 `define_method` 批量生成 getter/setter。

</Term>

### method_missing 幽灵方法

<Term def="method_missing 在调用不存在的方法时触发，可以动态处理未知方法。Rails ActiveRecord 的 find_by_name 等方法由此实现。">

```ruby
class DynamicFinder
  def initialize(data)
    @data = data
  end

  def method_missing(name, *args)
    # 匹配 find_by_xxx 模式
    if name.to_s =~ /^find_by_(.+)$/
      field = $1.to_sym
      @data.find { |item| item[field] == args[0] }
    else
      super  # 不匹配则交给父类处理
    end
  end

  # 重要：覆盖 method_missing 时应同时覆盖 respond_to_missing?
  def respond_to_missing?(name, include_private = false)
    name.to_s.start_with?("find_by_") || super
  end
end

finder = DynamicFinder.new([
  { name: "Alice", age: 30 },
  { name: "Bob", age: 25 }
])

puts finder.find_by_name("Alice")  # => {name: "Alice", age: 30}
puts finder.find_by_age(25)        # => {name: "Bob", age: 25}
```

</Term>

### send 动态调用

<Term def="send 在运行时动态调用方法——方法名可以是变量。public_send 不调用 private 方法。">

```ruby
class Calculator
  def add(a, b); a + b; end
  def sub(a, b); a - b; end

  private
  def secret; "hidden"; end
end

calc = Calculator.new

# send 动态调用
method_name = :add
puts calc.send(method_name, 3, 5)  # => 8

# send 可以调用 private 方法（慎用！）
puts calc.send(:secret)  # => hidden

# public_send 不调用 private（更安全）
calc.public_send(:secret)  # => NoMethodError
```

</Term>

<Stepper>
<Step title="Open Class 扩展类">
`class String` 重新打开 String 类，可以添加新方法或覆盖现有方法。这是 Ruby 的设计——类永不"封闭"。优点：灵活（给内置类加方法）；缺点：危险（可能破坏别人的代码）。使用原则：谨慎修改内置类，优先用模块。
</Step>
<Step title="define_method 批量生成">
当多个方法逻辑相似、只是名字不同时，用 `define_method` 循环生成。避免手写大量样板代码。`attr_accessor` 本身就是用 define_method 实现的。适合：属性访问器、委托方法、API 端点生成。
</Step>
<Step title="method_missing 动态分发">
`method_missing` 拦截未定义的方法调用，根据方法名动态处理。Rails 的 `find_by_name`、`User.has_many :posts` 都基于此。注意：必须同时覆盖 `respond_to_missing?`，否则 `respond_to?` 不认识幽灵方法。
</Step>
</Stepper>

## 代码对照

```ruby
# === Open Class: 扩展内置类 ===
class Integer
  def minutes
    self * 60  # 5.minutes => 300
  end

  def hours
    self * 3600  # 2.hours => 7200
  end

  def ago
    Time.now - self  # 1.day.ago（需要 day 方法）
  end
end

puts 5.minutes      # => 300
puts 1.hours        # => 3600

# === define_method: 批量生成属性 ===
class Configuration
  SETTINGS = [:host, :port, :database, :username, :password]

  SETTINGS.each do |setting|
    define_method(setting) do
      instance_variable_get("@#{setting}")
    end

    define_method("#{setting}=") do |value|
      instance_variable_set("@#{setting}", value)
    end
  end

  def initialize
    @host = "localhost"
    @port = 5432
  end
end

config = Configuration.new
puts config.host        # => localhost
config.database = "myapp"
puts config.database    # => myapp

# === method_missing: 动态方法分发 ===
class DataRecord
  def initialize(attributes = {})
    @attributes = attributes
  end

  def method_missing(name, *args)
    name_str = name.to_s

    if name_str.end_with?("=")
      # setter: name=(value)
      key = name_str.chomp("=").to_sym
      @attributes[key] = args[0]
    elsif @attributes.key?(name)
      # getter: name
      @attributes[name]
    else
      super
    end
  end

  def respond_to_missing?(name, include_private = false)
    name_str = name.to_s
    name_str.end_with?("=") || @attributes.key?(name) || super
  end
end

user = DataRecord.new(name: "Alice", email: "alice@example.com")
puts user.name    # => Alice
user.age = 30     # 动态设置
puts user.age     # => 30

# === send: 运行时方法调用 ===
class Service
  def process_payment; "处理支付"; end
  def send_email; "发送邮件"; end
  def generate_report; "生成报告"; end

  def dispatch(action)
    method_name = action.to_sym
    if respond_to?(method_name)
      send(method_name)
    else
      "未知操作: #{action}"
    end
  end
end

service = Service.new
puts service.dispatch("process_payment")  # => 处理支付
puts service.dispatch("send_email")       # => 发送邮件
puts service.dispatch("unknown")          # => 未知操作: unknown
```

## 常见误区

<Callout type="trap">
**误区：覆盖 method_missing 但忘记 respond_to_missing?**
`method_missing` 处理幽灵方法，但 `respond_to?` 默认不知道这些方法存在。`finder.respond_to?(:find_by_name)` 返回 `false`，即使方法能正常调用。这会导致依赖 `respond_to?` 的代码（如 `method(:name)` 或序列化器）出错。必须同时覆盖 `respond_to_missing?`，让 `respond_to?` 也认识幽灵方法。
</Callout>

<Callout type="trap">
**误区：过度使用元编程导致代码不可读**
元编程很强大，但代价是可读性和调试难度。`method_missing` 中的逻辑在调用栈中不可见——出错时堆栈跟踪指向 `method_missing`，而非实际方法。`define_method` 生成的方法在代码中搜不到。原则：能用普通方法定义就用普通方法，只有当方法逻辑真的重复且模式化时才用元编程。Rails 的 `find_by` 是合理的——100 个字段不值得手写 100 个方法。
</Callout>

**问题 1**：用 `method_missing` 实现一个类似 Rails ActiveRecord 的 `find_by_<field>` 动态查找器。

<Answer>
```ruby
class RecordCollection
  def initialize(records)
    @records = records
  end

  def method_missing(name, *args)
    name_str = name.to_s

    if name_str =~ /^find_by_(.+)$/
      field = $1.to_sym
      @records.find { |r| r[field] == args[0] }
    elsif name_str =~ /^find_all_by_(.+)$/
      field = $1.to_sym
      @records.select { |r| r[field] == args[0] }
    elsif name_str =~ /^find_by_(.+)_and_(.+)$/
      field1, field2 = $1.to_sym, $2.to_sym
      @records.find { |r| r[field1] == args[0] && r[field2] == args[1] }
    else
      super
    end
  end

  def respond_to_missing?(name, include_private = false)
    name.to_s =~ /^find_(all_)?by_.+/ || super
  end
end

users = RecordCollection.new([
  { name: "Alice", age: 30, city: "NYC" },
  { name: "Bob", age: 25, city: "LA" },
  { name: "Alice", age: 28, city: "SF" }
])

puts users.find_by_name("Alice")          # => {name: "Alice", age: 30, ...}
puts users.find_all_by_name("Alice").size  # => 2
puts users.find_by_name_and_age("Alice", 28)  # => {name: "Alice", age: 28, ...}
puts users.respond_to?(:find_by_name)     # => true

# 关键点：
# 1. 正则 /^find_by_(.+)$/ 提取字段名
# 2. $1 是正则的第一个捕获组（字段名）
# 3. find_all_by_ 和 find_by_x_and_y 扩展模式
# 4. respond_to_missing? 让 respond_to? 认识这些方法
# 5. super 处理不匹配的情况——交给父类的 method_missing
```

这就是 Rails ActiveRecord 的核心原理——`User.find_by_email("test@example.com")` 背后就是 method_missing 解析方法名，生成 SQL 查询。
</Answer>

**问题 2**：解释 `attr_accessor :name` 的实现原理。用 `define_method` 实现一个简化版。

<Answer>
`attr_accessor :name` 在底层调用 `Module#define_method` 生成两个方法：

```ruby
# Ruby 源码中的简化版 attr_accessor
class Module
  def my_attr_accessor(*names)
    names.each do |name|
      # 生成 getter
      define_method(name) do
        instance_variable_get("@#{name}")
      end

      # 生成 setter
      define_method("#{name}=") do |value|
        instance_variable_set("@#{name}", value)
      end
    end
  end
end

# 测试
class Person
  my_attr_accessor :name, :age
end

p = Person.new
p.name = "Alice"
p.age = 30
puts p.name  # => Alice
puts p.age   # => 30

# 原理解析：
# 1. my_attr_accessor 接收 Symbol 数组
# 2. 对每个 name，用 define_method 生成两个方法
# 3. getter：读取 @"#{name}" 实例变量
# 4. setter：设置 @"#{name}" 实例变量
# 5. define_method 的块用闭包捕获 name 的值
# 6. instance_variable_get/set 按字符串名访问实例变量

# attr_reader 和 attr_writer 类似：
def my_attr_reader(*names)
  names.each do |name|
    define_method(name) do
      instance_variable_get("@#{name}")
    end
  end
end

def my_attr_writer(*names)
  names.each do |name|
    define_method("#{name}=") do |value|
      instance_variable_set("@#{name}", value)
    end
  end
end
```

这就是 Ruby 元编程的精髓——语言的基础设施本身就是用元编程构建的。`attr_accessor` 不是关键字，而是 Module 的方法——用 `define_method` 动态生成方法。理解了这一点，你就能理解 Rails 的 `has_many`、`belongs_to` 等宏方法的实现原理。
</Answer>

<GlossaryItem term="Open Class">

</GlossaryItem>

</GlossaryItem>
<GlossaryItem term="send">
运行时动态调用方法——方法名可以是变量或 Symbol。public_send 不调用 private 方法，更安全。
</GlossaryItem>
