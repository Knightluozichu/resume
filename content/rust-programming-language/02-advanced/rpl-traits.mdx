## 直觉引入

trait 就像一份「能力合同」——定义了某种能力需要哪些方法。类型通过实现这些方法来「签署合同」。与 Java 不同，Rust 不需要声明 implements——拥有方法就自动满足。trait 让你既能用泛型获得零开销多态（静态分发），也能用 trait object 获得运行时多态（动态分发）。

## 概念讲解

### trait 定义与实现

<Term def="trait 定义方法签名，类型通过 impl Trait for Type 实现。可有关联类型、默认方法。孤儿规则限制实现位置。">trait 定义方法签名，类型通过 `impl Trait for Type` 实现： ```rust trait Summary { fn summarize(&self) -> String; // 默认方法 fn default_method(&self) { println!("default"); } } struct Article { title: String } impl Summary for Article { fn summarize(&self) -> String { self.title.clone() } } ``` 孤儿规则（Orphan Rule）：只有当 trait 或类型至少一个在当前 crate 中定义时才能 impl。防止不同 crate 对同一 (Type, Trait) 组合实现冲突。为外部类型实现外部 trait 需用 newtype 模式包装。</Term>

### 静态分发 vs 动态分发

<Term def="静态分发：泛型+bound 编译期单态化，零开销但代码体积大。动态分发：&amp;dyn Trait 通过 vtable 运行时查找，体积小但有间接跳转。">**静态分发**（泛型 + trait bound）： ```rust fn print<T: Display>(x: T) { println!("{}", x); } ``` 编译器为每种具体类型生成一份代码（单态化 monomorphization）。调用时直接跳转到具体方法，零运行时开销，但代码体积增大。 **动态分发**（trait object）： ```rust fn print(x: &dyn Display) { println!("{}", x); } let v: Vec<Box&lt;dyn Display>> = vec![Box::new(1), Box::new("hi")]; ``` 通过 vtable（虚函数表）在运行时查找方法。有一次间接跳转开销，代码体积小。适合需要将不同类型存入同一集合的场景。 选择：性能关键路径用泛型，需要异构集合或跨 ABI 用 dyn。</Term>

## 代码对照

```rust
// trait 定义与实现
trait Animal {
    fn name(&self) -> String;
    fn sound(&self) -> String;
    // 默认方法
    fn info(&self) -> String {
        format!("{} says {}", self.name(), self.sound())
    }
}

struct Dog { name: String }
struct Cat { name: String }

impl Animal for Dog {
    fn name(&self) -> String { self.name.clone() }
    fn sound(&self) -> String { "Woof".to_string() }
}

impl Animal for Cat {
    fn name(&self) -> String { self.name.clone() }
    fn sound(&self) -> String { "Meow".to_string() }
}

// 静态分发（泛型单态化）
fn print_info<T: Animal>(animal: &T) {
    println!("{}", animal.info());
}

// 动态分发（trait object）
fn print_dyn(animal: &dyn Animal) {
    println!("{}", animal.info());
}

fn main() {
    let dog = Dog { name: "Rex".into() };
    let cat = Cat { name: "Whiskers".into() };
    
    print_info(&dog);  // 编译期生成 Dog 版本
    print_info(&cat);  // 编译期生成 Cat 版本
    
    // 异构集合需要 dyn
    let animals: Vec<Box&lt;dyn Animal>> = vec![
        Box::new(dog), Box::new(cat)
    ];
    for a in &animals { print_dyn(a.as_ref()); }
}
```

## 常见误区

<Callout type="trap">
**误区：dyn Trait 和泛型性能差不多**
静态分发（泛型）零开销——编译器生成具体类型代码，直接调用。动态分发（dyn）有 vtable 查找的间接跳转开销。在热路径上差异可能显著。性能关键用泛型，需要运行时多态（异构集合）才用 dyn。
</Callout>

<Callout type="trap">
**误区：可以为任何类型实现任何 trait**
孤儿规则限制：只有 trait 或类型至少一个在当前 crate 中定义时才能 impl。不能为外部类型实现外部 trait（如 impl Display for Vec&lt;i32&gt;）。需要用 newtype 模式：struct MyVec(Vec&lt;i32&gt;); impl Display for MyVec {}。
</Callout>

<Exercises>
**问题 1**：静态分发和动态分发有什么区别？何时选择哪种？

<Answer>
静态分发：泛型+bound 编译期单态化生成独立代码，零运行时开销但代码体积大。动态分发：&amp;dyn Trait 通过 vtable 运行时查找有一次间接跳转开销代码体积小。选择：性能关键路径用泛型（静态），需异构集合(Vec&lt;Box&lt;dyn&gt;&gt;)或跨 ABI 用 dyn（动态）。
</Answer>

**问题 2**：如何为外部类型（如 Vec&lt;i32&gt;）实现自己的 trait？

<Answer>
直接 impl MyTrait for Vec&lt;i32&gt; 合法（Vec 外部但 MyTrait 自己）。但不能为外部类型实现外部 trait（如 impl Display for Vec&lt;i32&gt; 不合法因都是外部的）。需用 newtype 模式：struct MyVec(Vec&lt;i32&gt;); impl Display for MyVec &#123;&#125;——包装一层自己的类型绕过孤儿规则。
</Answer>

</Exercises>
