## 直觉引入

Rust 的 async 就像一本「烹饪食谱」——你写下步骤（async fn），编译器把它变成一台自动烹饪机（状态机 Future）。但食谱本身不会自己做饭——你需要一个厨师（runtime）来执行它。与 Go 的 goroutine 不同，Rust 的 async 是惰性的——创建 Future 不会执行任何代码，必须有人 poll 它才会推进。

## 概念讲解

### Future 与 poll

<Term def="Future trait 的 poll 方法尝试推进执行：返回 Ready(结果) 或 Pending(需等待)。Pending 时通过 Waker 注册通知。Future 是惰性的需 runtime 轮询。">
Future trait：
```rust
trait Future {
    fn poll(self: Pin<&mut Self>, cx: &mut Context) -> Poll<Output>;
}
```

`poll` 尝试推进 Future 的执行：
- `Ready(result)`：完成，返回结果
- `Pending`：未完成，需等待。通过 `cx.waker()` 注册一个 Waker，当条件满足时 `Waker.wake()` 通知 runtime 重新 poll

**Future 是惰性的**——创建 async fn 返回的 Future 不会执行任何代码，必须有人调用 poll 推进。Runtime（如 tokio）维护任务队列和 IO 事件循环，不断 poll 就绪的 Future。

与 Go goroutine 的核心区别：Rust async 是**协作式**（需 await 让出控制权），Go goroutine 是**抢占式**（runtime 自动调度）。
</Term>

### async fn 与状态机

<Term def="async fn 编译为实现 Future 的状态机。每个 await 点是状态机的暂停/恢复点。状态机保存跨 await 的局部变量。">
`async fn foo() { let a = step1().await; let b = step2(a).await; b }` 编译为状态机：
```rust
enum FooFut {
    Start,
    AwaitingStep1(Step1Fut),
    AwaitingStep2(Step2Fut, A), // 保存跨 await 的变量 a
    Done,
}
```

poll 时根据当前状态推进：
1. Start → 创建 Step1Fut，进入 AwaitingStep1
2. AwaitingStep1 → poll Step1Fut，Ready 时取出 a，创建 Step2Fut，进入 AwaitingStep2
3. AwaitingStep2 → poll Step2Fut，Ready 时返回 Ready(b)

每个 `.await` 对应一个状态转换点。状态机保存所有跨 await 点的局部变量——这就是 async fn 不需要独立栈的原因（所有状态在状态机结构体中）。
</Term>

## 代码对照

```rust
use tokio::net::TcpListener;
use std::time::Duration;

#[tokio::main]  // 启动 tokio runtime
async fn main() {
    // 并发运行多个任务
    tokio::join!(server_task(), timer_task());
}

// TCP 服务器：每连接一个 async task
async fn server_task() {
    let listener = TcpListener::bind("127.0.0.1:8080").await.unwrap();
    loop {
        let (mut socket, _) = listener.accept().await.unwrap();
        // spawn 为每个连接创建独立 task（轻量，不占线程）
        tokio::spawn(async move {
            handle_connection(&mut socket).await;
        });
    }
}

// 定时任务：非阻塞等待
async fn timer_task() {
    let mut interval = tokio::time::interval(Duration::from_secs(60));
    loop {
        interval.tick().await;  // 非阻塞等待
        cleanup().await;
    }
}

async fn handle_connection(socket: &mut TcpStream) {
    // 所有 IO 都是 .await（非阻塞）
    let mut buf = [0; 1024];
    let n = socket.read(&mut buf).await.unwrap();
    socket.write_all(&buf[..n]).await.unwrap();
}

async fn cleanup() { /* 清理逻辑 */ }
```

## 常见误区

<Callout type="trap">
**误区：async fn 创建后会自动执行**
async fn 是惰性的——调用 `async_fn()` 返回一个 Future，但不会执行任何代码。必须有人 poll 它（通常是 runtime 通过 spawn 或 await）。如果创建 Future 但不 spawn 也不 await，里面的代码永远不会执行。这是 Rust async 与 Go goroutine 的关键区别。
</Callout>

<Callout type="trap">
**误区：async Rust 不需要 runtime**
Rust 没有内置 async runtime——标准库只提供 Future trait，不提供执行器。必须选择第三方 runtime（如 tokio、async-std）。`#[tokio::main]` 宏会自动启动 runtime。如果不使用 runtime，async 代码不会执行。
</Callout>

<Exercises>
**问题 1**：Rust async/await 与 Go goroutine 有什么本质区别？

<Answer>
Rust async 是编译期状态机转换——async fn 编译为实现 Future 的状态机，await 是暂停/恢复点。Future 惰性需 runtime 轮询。零运行时开销栈空间小。Go goroutine 是运行时调度的轻量线程——有独立栈（2KB 可增长），go 创建后自动调度。核心：Rust 协作式（需 await 让出），Go 抢占式（runtime 调度）。
</Answer>

**问题 2**：为什么 Future 需要 runtime 才能执行？

<Answer>
Future 是惰性的——创建 async fn 返回的 Future 不会执行任何代码。poll 尝试推进执行，Pending 时通过 Waker 注册通知。但 Future 自己不会调用自己的 poll——需要 runtime 维护任务队列和 IO 事件循环不断 poll 就绪的 Future，Waker 唤醒时重新调度。没有 runtime，async 代码永远不会执行。
</Answer>

</Exercises>
