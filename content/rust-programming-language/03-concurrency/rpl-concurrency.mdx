## 直觉引入

Rust 的并发安全就像「编译期安检」——你在编译时就要通过所有权系统的检查，证明你的代码没有数据竞争。通不过编译就不能运行。这意味着 Rust 程序一旦编译通过，大部分数据竞争就已经被消除了——这是其他语言做不到的。

## 概念讲解

### Send 与 Sync

<Term def="Send: 类型可安全在线程间转移所有权。Sync: 类型可安全被多线程共享引用（&T 是 Send）。大部分类型自动实现。">
Rust 用两个标记 trait 保证线程安全：

- **Send**：类型可以安全地在线程间转移所有权（move 到另一个线程）
- **Sync**：类型可以安全地被多个线程同时共享引用（&T 是 Send 的）

大部分类型自动实现 Send/Sync（如果所有字段都是 Send/Sync）。例外：
- `Rc<T>` 不是 Send（引用计数非原子操作）
- `Arc<T>` 是 Send（原子引用计数）
- `Mutex<T>` 是 Send + Sync（内部加锁保护）
- `Cell<T>`/`RefCell<T>` 是 Send 但不是 Sync（内部可变性非线程安全）

编译器在编译期验证——如果类型不 Send，编译错误阻止 move 到其他线程。
</Term>

### Arc<Mutex<T>>

<Term def="Arc 提供共享所有权（原子引用计数），Mutex 提供安全可变（互斥锁）。两者组合实现线程安全的共享可变状态。">
`Arc<Mutex<T>>` 是 Rust 中线程安全的共享可变状态的标准模式：

- **Arc<T>**（Atomic Reference Counted）：原子引用计数，多个线程共享同一数据的所有权。最后一个 Arc drop 时释放数据。提供 &T 访问（只读）。
- **Mutex<T>**：互斥锁，提供对内部数据的独占访问。`lock()` 返回 `MutexGuard<T>`（RAII 守卫），持有守卫期间可修改数据，守卫 drop 时自动解锁。

两层包装的原因：
- Arc 让多个线程持有「共享所有权」（数据不被提前释放）
- Mutex 让多个线程能「安全修改」共享数据（一次只一个线程进入）
- `Arc<Mutex<T>>` = 共享所有权 + 安全可变 = 线程安全的共享可变状态
</Term>

## 代码对照

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // Arc<Mutex<T>>: 线程安全的共享可变状态
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter); // 原子引用计数+1
        let handle = thread::spawn(move || {
            let mut num = counter.lock().unwrap(); // 加锁
            *num += 1; // 修改共享数据
            // num (MutexGuard) drop 时自动解锁
        });
        handles.push(handle);
    }

    for handle in handles { handle.join().unwrap(); }

    println!("Result: {}", *counter.lock().unwrap()); // 10
}

// Rc<T> 不是 Send，不能跨线程
// let rc = std::rc::Rc::new(0);
// thread::spawn(move || { *rc; }); // 编译错误: Rc 不是 Send
```

## 常见误区

<Callout type="trap">
**误区：Mutex 和 Arc 总是必须一起用**
Mutex 可以单独用在单线程场景（替代 RefCell 提供内部可变性）。Arc 也可以单独用（共享只读数据 Arc<T>）。只有需要跨线程共享可变状态时才需要 Arc<Mutex<T>>。只读共享用 Arc<T> 即可，单线程可变用 RefCell<T>。
</Callout>

<Callout type="trap">
**误区：Rust 不会死锁**
Rust 消除了数据竞争（编译期保证），但不能消除死锁。如果两个线程以不同顺序获取多个锁，仍会死锁。避免策略：固定锁顺序、缩短锁作用域、用 try_lock、用 channel 替代锁（消息传递模型）。parking_lot::Mutex 有死锁检测。
</Callout>

<Exercises>
**问题 1**：Send 和 Sync 分别表示什么？Rc<T> 为什么不是 Send？

<Answer>
Send: 类型可安全在线程间转移所有权。Sync: 类型可安全被多线程共享引用。Rc<T> 不是 Send 因为引用计数是非原子操作——多线程同时 clone/drop 会导致计数错误。Arc<T> 用原子操作所以是 Send。
</Answer>

**问题 2**：为什么需要 Arc<Mutex<T>> 两层包装？

<Answer>
Arc 提供共享所有权（多线程共享数据不被提前释放），Mutex 提供安全可变（一次只一个线程修改）。单独 Arc 只能共享 &T 不可变，单独 Mutex 不能跨线程共享所有权。Arc<Mutex<T>> = 共享所有权+安全可变 = 线程安全共享可变状态。
</Answer>

</Exercises>
