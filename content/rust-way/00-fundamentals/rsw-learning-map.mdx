## 直觉引入

如果把学 Rust 比作盖一栋摩天大楼，那所有权就是地基。你不会先装修顶层（async 运行时），而是先打地基（所有权与借用），再立承重柱（类型系统与生命周期），接着装安防系统（错误处理与 unsafe 边界），最后才能封顶装修（宏与异步工程）。

Rust 的设计者有一个执念：**把运行时错误前移到编译期**。C/C++ 把内存安全的责任全交给程序员，运行时崩溃是家常便饭；Go 用 GC 换来了安全却牺牲了精细控制；Rust 选择了第三条路——用所有权模型在编译期证明内存安全与线程安全，运行期零额外开销。

## 概念讲解

### 四大板块

<Term def="Rust 编程之道全书分为四大板块：Rust基石、类型系统、错误与安全、高级工程，按递进关系组织。">

全书十章分为四大板块，每个板块建立在前一个板块的基础上：

1. **Rust 基石**（第1-2章）：所有权与借用——这是 Rust 区别于所有语言的灵魂
2. **类型系统**（第3-4章）：Trait、泛型与生命周期——抽象复用与引用安全
3. **错误与安全**（第5-7章）：错误处理、unsafe、并发——可恢复错误与无畏并发
4. **高级工程**（第8-10章）：async 运行时、宏、总复习——生产级工程能力

</Term>

### Rust 的设计哲学

<Term def="Rust 追求安全与性能的统一，核心原则包括：所有权保证内存安全、零成本抽象、编译期错误前移、无畏并发。">

Rust 有几个区别于其他语言的核心设计：

- **所有权是地基**：每个值有唯一所有者，离开作用域自动释放——无需 GC
- **零成本抽象**：高层抽象（迭代器、泛型、async）编译后与手写底层代码一样快
- **编译期安全**：借用检查器在编译期消除数据竞争与悬垂引用，而非运行时崩溃
- **无畏并发**：Send/Sync 标记 trait 让编译器阻止错误的数据共享

</Term>

<Stepper>
<Step title="第一板块：Rust 基石">
理解所有权三原则：每个值有唯一所有者、值随所有者离开而释放、赋值或传参默认是移动（move）。借用规则：任意数量不可变引用 & 或唯一可变引用 &mut，二者互斥。这是后续所有知识的基石——不理解所有权，就无法理解生命周期和并发。
</Step>
<Step title="第二板块：类型系统">
Trait 定义行为契约，泛型实现类型无关复用。泛型 + trait bound 在编译期单态化，零运行时开销。生命周期 'a 是编译期标注，确保引用绝不悬垂。这两者共同构成 Rust 的类型安全骨架。
</Step>
<Step title="第三板块：错误与安全">
Result<T,E> 处理可恢复错误，panic! 处理不可恢复错误，? 操作符让错误优雅传播。unsafe 块解锁裸指针等能力，但须用 safe API 封装不变式。Send/Sync 在编译期守护线程安全，实现「无畏并发」。
</Step>
<Step title="第四板块：高级工程">
async fn 编译成 Future 状态机，由执行器通过 poll/Waker 调度，以极低开销承载海量并发。宏（macro_rules! 与过程宏）在编译期生成代码，消除样板。总复习串联全书知识图谱。
</Step>
</Stepper>

## 代码对照

```rust
// 所有权：move 语义
let s1 = String::from("hello");
let s2 = s1;          // s1 的所有权移动给 s2
// println!("{}", s1); // 编译错误：s1 已被移动

// 借用：不可变与可变互斥
let mut data = vec![1, 2, 3];
let r1 = &data;       // 不可变借用
let r2 = &data;       // 多个不可变借用可以共存
// let r3 = &mut data; // 编译错误：已有不可变借用时不能可变借用
println!("{} {}", r1, r2);

// 错误处理：Result + ?
fn read_and_parse() -> Result<i32, Box<dyn std::error::Error>> {
    let s = std::fs::read_to_string("num.txt")?; // ? 自动传播 Err
    let n: i32 = s.trim().parse()?;
    Ok(n)
}
```

## 常见误区

<Callout type="trap">
**误区：把 Rust 当「带 GC 的现代 C++」学**
Rust 的所有权模型是全新的范式，不是 C++ 的 RAII 加点语法糖。C++ 允许多个指针指向同一资源，靠程序员自律避免问题；Rust 在编译期就禁止这种共享。学 Rust 要从「与借用检查器对话」开始，而不是套用 C++ 的指针思维——否则你会觉得编译器处处跟你作对。
</Callout>

<Callout type="trap">
**误区：跳过所有权直接写项目**
所有权是 Rust 的地基，跳过它直接写项目会遇到大量「为什么编译器不让我这么做」的困惑。不理解借用规则，就无法理解为什么不能在循环中持有可变引用；不理解生命周期，就无法理解为什么函数不能返回局部变量的引用。先打牢所有权基础，后续的类型系统和并发才能顺理成章。
</Callout>

<Exercises>
**问题 1**：Rust 全书四大板块的顺序是什么？为什么要按这个顺序学习？

<Answer>
四大板块：Rust 基石（所有权与借用）→ 类型系统（Trait、泛型与生命周期）→ 错误与安全（错误处理、unsafe、并发）→ 高级工程（async、宏、总复习）。

按这个顺序学习是因为建立了递进的能力链：所有权是理解一切的基础（内存如何分配释放），类型系统是抽象复用的骨架（trait bound + 生命周期），错误与安全是工程稳健的保障（Result + 无畏并发），高级工程是生产级能力（海量并发 + 代码生成）。每一层都建立在前一层之上——不理解所有权就无法理解生命周期，不理解生命周期就无法理解并发中的引用安全。
</Answer>

**问题 2**：Rust 的「零成本抽象」是什么意思？举例说明。

<Answer>
零成本抽象指的是：你使用的高层抽象，编译后的机器码与手写底层代码一样高效，不为「不使用的功能」付代价。

例如迭代器：`vec.iter().map(|x| x * 2).filter(|x| x > 5).sum()` 这串链式调用看似有很多中间步骤，但编译器会优化成与手写 for 循环一样的单次遍历，没有中间集合分配。再如泛型：`fn max<T: Ord>(a: T, b: T)` 在编译期为每个具体类型生成特化代码（单态化），运行时是直接调用，没有虚表跳转——与手写 `max_i32`、`max_f64` 完全一样快。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="所有权（Ownership）">
Rust 的核心机制：每个值有唯一所有者，所有者离开作用域时值被自动释放。赋值和传参默认是移动语义，转移所有权而非复制。这是 Rust 无需 GC 即可保证内存安全的根基。
</GlossaryItem>
<GlossaryItem term="借用检查器（Borrow Checker）">
编译器组件，在编译期验证引用规则：任意数量不可变引用 & 或唯一可变引用 &mut，二者互斥。它在零运行时开销下消除了数据竞争与悬垂引用。
</GlossaryItem>
<GlossaryItem term="零成本抽象（Zero-cost Abstraction）">
Rust 的设计原则：高层抽象编译后与手写底层代码一样高效。不为你不使用的功能付代价，使用的高层功能也不比手写更慢。迭代器、泛型、async 都遵循此原则。
</GlossaryItem>
<GlossaryItem term="无畏并发（Fearless Concurrency）">
Rust 的并发理念：Send/Sync 标记 trait 让编译器在编译期阻止数据竞争。你可以放心地重构并发代码，因为编译器会拒绝所有不安全的共享——并发错误不再是运行时定时炸弹。
</GlossaryItem>
</Glossary>
