## 从分号改变结果开始

Rust是一门表达式导向语言。字面量、运算、块、`if`、`match`和循环控制都可产生值；`let`绑定和以分号结尾的表达式通常作为语句使用。<Term def="求值后产生一个确定类型和值，可被外层上下文继续使用的语法单元。">value-producing expression</Term>解释了函数体最后一行为何不写`return`，也解释了多写一个分号为何把结果变成unit。

```rust
fn classify(n: i32) -> &'static str {
    if n < 0 { "negative" } else if n == 0 { "zero" } else { "positive" }
}

assert_eq!(classify(7), "positive");
```

`if`两个结果分支必须类型兼容，因为整个表达式只有一个静态类型。发散表达式如`panic!`的never type可与其他分支汇合，但不代表panic是普通返回值。

## 变量绑定、可变性与作用域

`let name = value`建立名字到值的绑定；默认不可变，`let mut`只允许通过该绑定修改，并不会让所有嵌套引用自动可变。Shadowing建立新绑定，可以改变类型；赋值修改现有位置，不能改变其类型。<Term def="名字在词法作用域内关联一个值、所有权责任和可变许可的关系。">variable binding contract</Term>要求区分绑定不可变、值内部可变和引用独占这三层。

```rust
let raw = "42";
let raw: u32 = raw.parse().expect("valid number");
let mut total = raw;
total += 1;
assert_eq!(total, 43);
```

## 函数、闭包与参数传递

函数签名必须明确参数和返回类型。传入非Copy值通常move，传入引用是borrow；闭包还会从环境按共享借用、独占借用或move捕获。第6章会深入Fn族，本章先记录调用前后哪些绑定仍可用。<Term def="一次函数或闭包调用对参数值执行复制、移动、共享借用或独占借用的约定。">call ownership contract</Term>比“按值传递”更精确。

## 流程控制与模式匹配

`if`适合布尔条件，`loop`可通过`break value`产生值，`while`表达条件循环，`for`消费`IntoIterator`。`match`必须穷尽枚举状态，并能在pattern中解构、绑定、忽略和加guard。<Term def="用形状匹配同时决定控制分支、字段绑定与所有权动作的机制。">exhaustive pattern dispatch</Term>让新增枚举variant时，遗漏处理变成编译错误。

```rust
enum Command { Add(i32), Reset, Quit }

fn apply(total: &mut i32, command: Command) -> bool {
    match command {
        Command::Add(value) => { *total += value; true }
        Command::Reset => { *total = 0; true }
        Command::Quit => false,
    }
}
```

## 基础类型与复合类型

整数类型区分位宽和符号，浮点数有近似误差，`bool`表达真假，`char`是Unicode scalar value。Tuple把不同类型固定组合，array保存固定数量同型元素，slice是带长度的借用视图。类型大小、对齐和溢出行为与target及profile有关；不要把`usize`假设成永远64位。

<Term def="一个类型在内存中的size、alignment、字段或元素关系以及metadata组成。">type representation shape</Term>是选择拷贝、借用和FFI布局的基础。默认Rust结构布局没有稳定ABI承诺，第4章再展开。

## 集合类型与字符串

`Vec<T>`、`String`和`HashMap<K,V>`在栈上保存handle，在堆上管理动态缓冲。`len`是已初始化元素数量，`capacity`是无需重新分配可容纳数量。扩容可能移动buffer，因此不能在持有元素引用时继续push。String保证UTF-8，不能用整数直接索引“第几个字符”；第8章会处理bytes、char和grapheme边界。

## 智能指针与共享模型

`Box<T>`提供独占堆owner，`Rc<T>`提供单线程共享owner，`Arc<T>`用原子计数支持跨线程共享owner。`Cell`和`RefCell`提供内部可变性，`Mutex`把共享修改与线程同步结合。<Term def="由指针类型明确资源owner数量、释放方式、可变性和线程边界的设计。">smart pointer ownership model</Term>提醒我们共享所有权不自动允许共享修改。

## 泛型、Trait与错误处理预览

泛型把类型参数化，Trait描述所需行为，bound让函数体只能调用已声明能力；编译器通常单态化具体实例。`Option<T>`表示可缺失，`Result<T,E>`表示可恢复失败，`?`在保留错误类型转换规则的前提下提前返回。第3章深入类型系统，第9章建立健壮错误边界。

<Callout type="trap" title="mut表示这个对象从任何地方都能修改">
`mut`修饰绑定；共享引用仍不能通过它修改普通数据。`RefCell`等内部可变性把检查移到运行期，也仍受借用规则约束。
</Callout>

<Callout type="trap" title="match只是更长的switch">
match还执行穷尽性检查、结构解构、绑定和所有权动作。忽略这些差异容易在pattern中意外move字段，或用通配符掩盖新增variant。
</Callout>

## 本章回顾

Rust用表达式统一求值，用绑定承载owner和可变许可，用pattern统一控制与解构。基础、复合、集合和智能指针类型拥有不同表示与owner模型；泛型Trait和Result则把复用与失败写进签名。后续章节会逐层放大这些精要。

按官方目录复核，本章的语言精要已经依次覆盖语句与表达式、变量绑定、函数与闭包、流程控制与模式匹配、基础类型与复合类型、集合类型与智能指针，以及泛型、Trait与错误处理；这些不是互不相干的语法点，而是同一条“值怎样产生、绑定、流动并失败”的执行链。

<Exercises>
**问题 1：块尾表达式加分号后为何可能编译失败？**
<Answer>分号把值丢弃，块结果变成unit。若函数或外层表达式期待其他类型，分支和返回类型不再匹配。</Answer>

**问题 2：`for item in values`与`for item in &values`有何区别？**
<Answer>前者通常调用owned IntoIterator并消费集合，item获得元素；后者借用集合，item通常是元素引用，循环后values仍可用。具体行为由IntoIterator实现决定。</Answer>

**问题 3：怎样在Box、Rc和Arc之间选择？**
<Answer>先问owner数量和线程边界：单owner选Box或直接内联；单线程多owner选Rc；跨线程多owner选Arc。需要修改时再选择Cell/RefCell或锁，不能把共享owner误当共享可变。</Answer>
</Exercises>
