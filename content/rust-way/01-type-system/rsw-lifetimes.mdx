## 直觉引入

生命周期像是一张「保质期标签」。超市里的牛奶有保质期——你不能在过期后喝它。Rust 里的每个引用也有保质期：它指向的数据必须在这段保质期内有效，否则引用就「过期」变成悬垂指针。

编译器的借用检查器就是「质检员」，它检查每个引用的保质期是否覆盖了它的使用范围。生命周期标注 `'a` 就是给引用贴保质期标签，让质检员能对比「引用活多久」和「数据活多久」。

关键认知：生命周期不改变任何运行时行为——它纯粹是编译期标注，帮助编译器验证引用安全。一旦编译通过，生命周期信息就被擦除，运行时无任何开销。

## 概念讲解

### 生命周期标注的必要性

<Term def="生命周期 'a 是编译期标注，描述引用的有效范围。当函数有多个引用参数和返回引用时，编译器需要标注来确定返回引用的寿命与哪个参数绑定。">

考虑 `fn longest(x: &str, y: &str) -> &str`——返回的引用到底跟 x 还是 y 同寿？编译器无法判断，因为 x 和 y 的寿命可能不同。如果返回的引用比实际数据活得久，就是悬垂引用。

显式标注 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str` 告诉编译器：返回引用的寿命等于 x 和 y 寿命的交集（取较短者）。这保证返回的引用不会比任一输入活得更久。

</Term>

### 生命周期省略规则

<Term def="三条省略规则让常见场景无需显式标注：每个引用参数独立 'a；单输入引用时输出取同 'a；方法中 &self 的 'a 赋给输出。三条都套不上时编译器要求显式标注。">

1. **规则 1**：每个引用参数获得独立的生命周期 `<'a, 'b>`
2. **规则 2**：若只有一个输入生命周期参数，输出赋同寿
3. **规则 3**：若有 `&self`/`&mut self`，输出的生命周期取 self 的

三条规则都套不上时，编译器报错要求显式标注。大多数情况规则 2、3 已覆盖。

</Term>

### 结构体中的生命周期

<Term def="结构体持有引用时必须标注生命周期，确保结构体不会比它引用的数据活得更久。这是「数据所有权的时序约束」。">

```rust
struct Excerpt<'a> {
    part: &'a str, // part 引用的数据必须比 Excerpt 活得久
}
```

结构体持有引用而非拥有数据，是一种「借用型结构体」。它轻量但受限——不能比被引用的数据长寿。如果需要独立拥有数据，应改用 `String` 而非 `&str`。

</Term>

<Step title="步骤1：识别需要标注的场景">
当一个函数返回引用，且有多个引用参数时，编译器无法确定返回引用跟谁同寿——这时需要显式 `'a`。单引用参数或方法大多由省略规则覆盖。
</Step>
<Step title="步骤2：理解 'a 是「交集」约束">
`fn f<'a>(x: &'a T, y: &'a T) -> &'a T` 中，'a 取 x 和 y 寿命的交集。这意味着返回引用在 x 或 y 任一过期前都有效。这是保守的最小公倍数——保证绝不悬垂。
</Step>
<Step title="步骤3：用 'static 表示全程有效">
`'static` 是最长的生命周期，表示数据在程序整个运行期有效。字符串字面量是 `&'static str`（编译进二进制）。谨慎使用 `'static` 约束——它可能隐藏本应短寿的引用问题。
</Step>
</Stepper>

## 代码对照

```rust
// 显式标注：返回引用与两个输入同寿（取交集）
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
let s1 = String::from("long string");
let s2 = String::from("hi");
let result = longest(s1.as_str(), s2.as_str());
println!("最长: {}", result);

// 省略规则覆盖：单输入，输出自动同寿
fn first_word(s: &str) -> &str {
    // 无需标注 'a，规则 2 自动补
    &s[..s.find(' ').unwrap_or(s.len())]
}

// 结构体持有引用：必须标注
struct Parser<'a> {
    text: &'a str,
}
impl<'a> Parser<'a> {
    fn peek(&self) -> &str { // 规则 3：输出取 self 的 'a
        &self.text[..1]
    }
}

// 'static 生命周期
let literal: &'static str = "我活在程序全程";
```

## 常见误区

<Callout type="trap">
**误区：以为生命周期标注会改变运行时行为**
生命周期 `'a` 纯粹是编译期标注，编译通过后就被擦除，运行时零开销。它只是告诉借用检查器「这些引用的寿命关系」，帮助编译器验证安全性。标注 `'a` 不会让代码变慢或分配内存。
</Callout>

<Callout type="trap">
**误区：结构体过度使用引用导致生命周期传染**
当结构体持有 `&'a str`，所有使用该结构体的函数和结构体都要带上 `'a`，造成「生命周期病毒式传播」。如果数据本应由结构体拥有，用 `String` 而非 `&str`。只在确有性能需求且数据寿命明确时才用引用持有。
</Callout>

<Exercises>
**问题 1**：以下函数为什么需要显式生命周期标注？省略规则为何不适用？

```rust
fn longest(x: &str, y: &str) -> &str { ... }
```

<Answer>
因为这个函数有两个引用参数 `x` 和 `y`，且返回引用。编译器需要知道返回的引用跟 x 还是 y 同寿，才能验证返回引用不悬垂。

省略规则不适用：规则 1 给 x 和 y 各分配独立的 `'a`、`'b`；规则 2 要求「只有一个输入生命周期」才把输出赋同寿——这里有多个输入，不满足；规则 3 要求有 `&self`，这里没有。三条规则都套不上，编译器报错要求显式标注 `<'a>`。

标注为 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str` 后，'a 表示「x 和 y 寿命的交集」，返回引用在这个交集内有效，保证不悬垂。
</Answer>

**问题 2**：什么时候应该用 `'static` 约束？它有什么风险？

<Answer>
`'static` 表示引用在程序整个运行期有效，如字符串字面量（编译进二进制段）。合理使用场景：全局配置、错误消息等确实全程有效的数据。

风险：过度使用 `'static` 约束会让函数只能接受 `'static` 数据，排斥了短寿引用。例如 `fn cache(data: &'static str)` 只能传字面量，不能传运行时构造的 String 的引用。这限制了函数的通用性。

更糟的是，开发者可能为了满足 `'static` 约束而用 `Box::leak` 故意泄漏内存把短寿数据变成 'static——这是内存泄漏的常见源头。正确做法是让生命周期参数化 `<'a>`，让调用方决定寿命。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="生命周期（Lifetime）">
编译期标注，描述引用的有效范围。用 `'a` 表示。它不改变运行时行为，纯粹帮助借用检查器验证引用不悬垂。编译通过后生命周期信息被擦除。
</GlossaryItem>
<GlossaryItem term="悬垂引用（Dangling Reference）">
引用指向已被释放的内存。Rust 的借用检查器通过生命周期标注在编译期阻止悬垂引用——返回引用的寿命不能超过它指向的数据。
</GlossaryItem>
<GlossaryItem term="'static 生命周期">
最长的生命周期，表示数据在程序整个运行期有效。字符串字面量是 `&'static str`。谨慎用作约束——它会排斥所有短寿引用，限制函数通用性。
</GlossaryItem>
<GlossaryItem term="生命周期省略规则">
编译器自动补全生命周期的三条规则：参数各自独立 'a；单输入输出同寿；方法输出取 self 寿命。三条都套不上时要求显式标注。
</GlossaryItem>
</Glossary>
