## 直觉引入

Trait 像是一份「能力合同」。你定义一个 `Summary` trait 表示「能摘要」，任何类型只要签了这份合同（实现了 `summarize` 方法），就能被「需要能摘要的东西」的函数接受。这和 Java 的接口、Go 的接口思路类似，但 Rust 的 trait 更强大——它支持默认方法、关联类型、运行时多态与编译期单态化。

泛型则是「填空题模板」：`fn max<T: Ord>(a: T, b: T)` 中的 `T` 是空格，编译器根据你传入的具体类型填上。关键是 `T: Ord` 这个约束——它要求填入的类型必须「可排序」，这就是 trait bound。

## 概念讲解

### Trait 定义与实现

<Term def="Trait 定义一组方法签名（行为契约），类型通过 impl 为自己实现这些方法。Trait 可有默认方法实现，也可作为参数类型与返回类型。">

```rust
trait Summary {
    fn summarize(&self) -> String;
    // 默认方法：实现者可不重写
    fn preview(&self) -> String {
        format!("{}...", &self.summarize()[..10])
    }
}

struct NewsArticle { title: String, content: String }
impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}: {}", self.title, self.content)
    }
}
```

Trait 实现有「孤儿规则」：只能为「本 crate 定义的类型」或「本 crate 定义的 trait」配对实现，防止第三方类型与第三方 trait 冲突。

</Term>

### 泛型与 trait bound

<Term def="泛型用占位符 T 表示「任意类型」，trait bound 限定 T 必须实现的 trait，编译期为每个具体类型单态化生成特化代码。">

泛型让一份代码服务多种类型，trait bound 保证类型安全：

```rust
// 泛型函数 + trait bound
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in &list[1..] {
        if item > max { max = item; }
    }
    max
}
```

`T: PartialOrd` 是约束。多个约束用 `+` 连接：`T: PartialOrd + Debug`。`where` 子句让复杂约束更可读。

</Term>

### 静态分发 vs 动态分发

<Term def="静态分发（单态化）：编译期为每个具体类型生成代码副本，调用零开销。动态分发（trait 对象 &dyn T）：运行时通过虚表查函数地址，一次间接跳转。">

- **泛型 `<T: Trait>`**：静态分发，编译期单态化，零运行时开销，但二进制体积增大
- **trait 对象 `&dyn Trait`**：动态分发，运行时虚表跳转，体积小，可存异构集合，但有少量开销

选择原则：性能敏感且类型有限→泛型；需要运行时异构（如插件系统）→trait 对象。

</Term>

## 代码对照

```rust
// 泛型 + trait bound：静态分发
fn print_summary<T: Summary>(item: &T) {
    println!("{}", item.summarize());
}
let article = NewsArticle { /* ... */ };
print_summary(&article); // 编译期生成 print_summary::<NewsArticle>

// trait 对象：动态分发
fn print_dyn(item: &dyn Summary) {
    println!("{}", item.summarize());
}
// 异构集合：只能用 trait 对象
let items: Vec<Box<dyn Summary>> = vec![
    Box::new(NewsArticle { /* ... */ }),
    Box::new(Tweet { /* ... */ }),
];
for item in &items {
    println!("{}", item.summarize()); // 运行时虚表分发
}

// trait bound + where 子句
fn merge<T, U>(a: T, b: U) -> String
where
    T: Summary,
    U: Summary,
{
    format!("{} | {}", a.summarize(), b.summarize())
}
```

## 常见误区

<Callout type="trap">
**误区：过度使用 trait 对象导致性能损失**
初学者觉得 `Box<dyn Trait>` 方便（不用写泛型），到处使用。但每次方法调用都要虚表跳转，且无法内联优化。性能敏感路径应优先用泛型单态化，让编译器内联。只在确实需要运行时多态（异构集合、插件）时才用 trait 对象。
</Callout>

<Callout type="trap">
**误区：违反孤儿规则导致编译失败**
你不能为 `Vec<T>`（标准库类型）实现自己定义的 `MyTrait`，因为两者都不在你 crate 中——这是孤儿规则。解决：用 newtype 模式 `struct MyVec(Vec<i32>);` 包装，然后为 MyVec 实现 MyTrait。
</Callout>

<Exercises>
**问题 1**：静态分发和动态分发各有什么优缺点？什么时候用哪个？

<Answer>
**静态分发（泛型单态化）**：编译期为每个具体类型生成代码副本，调用直达函数地址，可内联优化，零运行时开销。缺点是二进制体积随类型数增长（代码膨胀），且类型必须在编译期已知。

**动态分发（trait 对象 &dyn T）**：运行时通过虚表查函数地址，一次间接跳转。优点是体积小、可存异构集合、支持运行时决定类型。缺点是无法内联，每次调用有虚表开销，且 trait 对象要求对象安全（方法不能返回 Self、不能有泛型参数）。

选择：性能敏感且类型有限→泛型；需要运行时异构（插件、配置驱动策略）→trait 对象。库的公共 API 常用泛型（给调用方最大性能），应用层灵活处可用 trait 对象。
</Answer>

**问题 2**：什么是孤儿规则？为什么需要它？

<Answer>
孤儿规则（Orphan Rule）：只有当类型或 trait 至少有一个在当前 crate 定义时，才能为该类型实现该 trait。即不能为「别人的类型」实现「别人的 trait」。

需要它的原因：防止冲突。假设 crate A 和 crate B 都为 `Vec<T>` 实现了 `Display`（都在标准库外），当你的程序同时依赖 A 和 B 时，编译器不知道该用哪个实现。孤儿规则保证了 trait 实现的唯一性——实现必须定义在「类型或 trait 的所有者」crate 中。

绕过方法：newtype 模式。`struct MyVec(Vec<i32>);` 创建新类型，MyVec 在你 crate 中，可以为它实现任何 trait。Deref trait 还能让 MyVec 自动获得 Vec 的方法。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Trait">
Rust 的行为契约：定义一组方法签名，类型通过 `impl Trait for Type` 实现。支持默认方法、关联类型、泛型参数。相当于 Java 接口与 Haskell typeclass 的结合。
</GlossaryItem>
<GlossaryItem term="Trait Bound">
泛型类型参数的约束：`T: Trait` 要求 T 必须实现 Trait。多个约束用 `+` 连接，复杂约束用 `where` 子句。它让泛型函数能安全调用 trait 方法。
</GlossaryItem>
<GlossaryItem term="单态化（Monomorphization）">
编译期为泛型的每个具体类型实例生成专用代码的过程。`fn f<T>(x: T)` 调用 `f(1i32)` 和 `f(1.0f64)` 会生成 `f_i32` 和 `f_f64` 两个函数。这是静态分发的实现机制，零运行时开销。
</GlossaryItem>
<GlossaryItem term="Trait 对象（&dyn Trait）">
运行时多态的 trait 实例，由数据指针 + 虚表指针组成。虚表记录方法的函数地址。通过它可在集合中存放不同具体类型，代价是每次调用的间接跳转。要求 trait 是对象安全的。
</GlossaryItem>
</Glossary>
