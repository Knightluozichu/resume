## 从一段行为是否携带环境开始

函数、闭包和迭代器都能封装计算，但表示与owner不同。命名函数项不捕获环境，函数指针保存代码地址；闭包是编译器生成的匿名类型，字段保存捕获值；迭代器则保存“下一步计算到哪里”的状态。<Term def="同时描述代码入口、捕获环境、调用方式、分派和所有权动作的可调用值模型。">callable value model</Term>让高阶API不再只是“把函数传进去”。

先预测：闭包读取外部String但不修改时通常可实现Fn；若把String move出闭包，至少只能按FnOnce调用。

## 函数与高阶函数

函数签名定义参数、返回、泛型和ABI；函数项是零大小的具体类型，可转换为`fn`指针。高阶函数接收或返回可调用值。<Term def="把行为作为参数或结果，使算法与策略解耦的函数。">higher-order function contract</Term>必须声明调用次数、是否并发、是否允许修改环境以及返回值寿命。

```rust
fn apply_twice<T>(mut value: T, mut operation: impl FnMut(T) -> T) -> T {
    value = operation(value);
    operation(value)
}

assert_eq!(apply_twice(3, |n| n + 2), 7);
```

## 闭包实现与捕获所有权

闭包按需要以共享引用、独占引用或move捕获环境。`move`强制闭包取得捕获表达式的值，但Copy值仍复制；它不自动使闭包满足`'static`，捕获值内部仍可能带短引用。<Term def="编译器根据闭包体对外部值的读取、修改或消费，选择字段和捕获方式的规则。">closure capture contract</Term>决定闭包是否能离开当前scope、发送到线程或重复调用。

```rust
let prefix = String::from("id-");
let render = move |number: u32| format!("{prefix}{number}");
assert_eq!(render(7), "id-7");
assert_eq!(render(8), "id-8");
```

## Fn、FnMut与FnOnce

所有闭包至少实现FnOnce，因为调用可能消费self；不移出捕获值的闭包还可实现FnMut；不修改捕获环境的闭包还可实现Fn。<Term def="由调用是否消费闭包、独占修改环境或只读环境形成的三层调用能力。">Fn family capability</Term>是包含关系，不是三种互斥语法。

## 闭包作为参数、返回值与HRTB

参数常用`impl Fn...`或泛型以静态分派；异构存储使用`Box<dyn Fn...>`。返回`impl Fn`隐藏一个具体闭包类型。若回调必须接受任意足够短的借用，可使用`for<'a>`高阶生命周期约束。<Term def="要求一个Trait关系对所有满足条件的生命周期都成立，而不是只对某个固定生命周期成立。">higher-ranked lifetime bound</Term>常见于接受临时引用的回调边界。

## Iterator与IntoIterator

Iterator核心是关联类型Item和`next`；IntoIterator把集合、共享引用或独占引用转换为iterator。`for`循环会调用IntoIterator，因此`for x in values`、`&values`与`&mut values`表达消费、只读借用和独占借用三种owner动作。<Term def="从输入容器的所有权形式决定迭代器类型和Item所有权的协议。">iteration ownership protocol</Term>是阅读循环的第一步。

```rust
struct Countdown(u8);

impl Iterator for Countdown {
    type Item = u8;
    fn next(&mut self) -> Option<Self::Item> {
        if self.0 == 0 { None } else { self.0 -= 1; Some(self.0 + 1) }
    }
}

assert_eq!(Countdown(3).collect::<Vec<_>>(), vec![3, 2, 1]);
```

## 适配器、消费者与惰性

`map`、`filter`、`take`等适配器返回新的iterator并保持惰性；`collect`、`fold`、`sum`、`find`等消费者驱动`next`。<Term def="只有消费者请求下一项时才执行上游计算，并可按短路条件提前停止的管线。">lazy iterator pipeline</Term>允许融合多步计算，不表示所有链都无分配或自动并行。

<Exercises>
**问题 1：API为何优先要求Fn而不是FnOnce？**
<Answer>若API需要重复调用，Fn保证不会消费或独占修改环境；但应使用满足需求的最弱约束。只调用一次的API要求Fn会无谓拒绝合法闭包。</Answer>

**问题 2：`values.into_iter()`可能产生什么Item？**
<Answer>由receiver类型的IntoIterator实现决定。owned集合常产生owned Item，`&collection`产生共享引用，`&mut collection`产生独占引用；不能脱离具体类型和edition猜测。</Answer>

**问题 3：怎样验证迭代器短路？**
<Answer>在上游记录调用次数，组合`take`、`find`或`any`，断言consumer只请求必要项；同时测试空输入、无限iterator和上游副作用。</Answer>
</Exercises>
