## 从“谁负责释放”开始

所有权系统把值的释放责任、可用绑定和引用许可组合成编译期状态机。每个非Copy值有一个逻辑owner；move转移责任，Drop在owner离开scope时运行。<Term def="一个值当前由谁负责释放、哪些绑定仍有效以及允许何种访问的完整状态。">ownership state machine</Term>比“变量不能用两次”更接近真实规则。

先预测：把String传给按值参数后，调用者还能否使用？不能，除非函数返回它、参数改为引用或调用者显式clone。

```rust
fn length(text: &str) -> usize { text.len() }

let text = String::from("ownership");
assert_eq!(length(&text), 9);
assert_eq!(text.len(), 9);
```

## 绑定、作用域与移动

绑定是名字与值的词法关系，scope决定绑定可见和自动清理位置。Copy类型赋值产生独立副本；非Copy类型赋值通常move。<Term def="把值的后续使用权和最终清理责任从一个位置转移到另一个位置的操作。">move responsibility transfer</Term>不会调用用户可见复制，也不会让旧位置保持“空对象”。

## 借用：共享读取与独占修改

`&T`共享借用允许多个reader，`&mut T`独占借用允许一个writer，二者有效期重叠时互斥。<Term def="在不取得最终释放责任的前提下，临时获得受约束访问许可。">borrow access permit</Term>防止迭代器引用在Vec扩容后继续使用，也让数据竞争在safe代码中难以表达。

```rust
fn append_tag(values: &mut Vec<String>, tag: &str) {
    for value in values {
        value.push_str(tag);
    }
}

let mut values = vec!["a".to_owned(), "b".to_owned()];
append_tag(&mut values, "!");
```

## 生命周期参数、省略与约束

生命周期标注描述多个引用有效区间的关系，不延长数据寿命，也不在运行期计时。输入引用各有参数；单输入引用可决定输出；方法中self引用常决定输出，这些省略规则只隐藏常见关系。<Term def="声明输出引用、输入引用与类型参数之间有效区间关系的静态约束。">lifetime relation bound</Term>在多个候选输入、结构体持引用和返回闭包时需要显式表达。

```rust
fn longest<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() { left } else { right }
}
```

Trait object省略生命周期有独立默认规则；公开API应在关系不明显时显式写出。`'static`引用意味着数据可活到程序结束，`T: 'static`则表示T不含短寿命借用，不等于T值永不释放。

## Rc与Weak：单线程共享所有权

Rc强计数大于零时保持值，clone只增加计数；Weak不拥有值，upgrade返回Option。树和图通常用强边表达owner，用弱边表达父指针、缓存观察者或回链。<Term def="用强引用表示资源owner、用弱引用表示不延长资源寿命的观察关系。">strong weak ownership graph</Term>能主动避免引用环。

## Cell、RefCell与内部可变性

Cell适合Copy值替换或take，不提供内部引用；RefCell把共享/独占借用检查移到运行期，违规会panic。<Term def="允许通过共享引用修改内部状态，同时用类型特定机制维持互斥规则。">interior mutability boundary</Term>适合单线程缓存、测试记录器和图结构，不是逃避所有权设计的通用开关。

## Cow、NLL与并发安全

Cow可持有borrowed或owned数据，只读路径不复制，`to_mut`在需要写时克隆。NLL根据引用最后使用位置结束借用，而非机械等到花括号；它放宽合法程序，却不改变一写多读规则。跨线程共享通常从Rc/RefCell切换到Arc/Mutex等Send与Sync组合，编译器检查类型能否安全移动或共享。

<Callout type="trap" title="编译不过就clone">
clone可能隐藏owner不清、制造大对象复制或让多个状态分叉。先决定谁应拥有值、借用需持续多久；只有语义上需要独立副本时才clone。
</Callout>

<Callout type="trap" title="RefCell绕过了借用规则">
RefCell仍执行共享与独占互斥，只是运行时检查并在违规时panic。它也不是Sync，不能直接解决跨线程共享修改。
</Callout>

## 本章回顾

本章覆盖所有权系统中的绑定、作用域与生命周期，借用，生命周期参数、省略与约束，Rc与Weak，Cell与RefCell，Cow，并发安全与NLL。所有工具都围绕两件事：最终谁释放，以及当前谁被许可访问。

<Exercises>
**问题 1：`T: 'static`是否表示T值活到程序结束？**
<Answer>不是。它表示T不包含受更短生命周期约束的借用；owned String可满足该bound，却仍会在owner离开scope时释放。</Answer>

**问题 2：为什么Rc不能直接用于跨线程共享？**
<Answer>Rc计数更新不是原子的，类型不实现Send/Sync。跨线程共享owner通常使用Arc，并按修改需求组合不可变数据、Mutex、RwLock或原子类型。</Answer>

**问题 3：Cow适合什么场景？**
<Answer>输入大多只读、少数路径需要修改时，先借用避免复制，写入时获得owned副本。调用者必须接受结果可能borrowed或owned，并明确其生命周期。</Answer>
</Exercises>
