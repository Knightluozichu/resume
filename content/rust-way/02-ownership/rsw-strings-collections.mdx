## 从“第几个字符”究竟是什么开始

字符串问题至少有四层：原始bytes、编码后的Unicode scalar、组合后的grapheme cluster和用户界面的字形。Rust `String`与`str`保证UTF-8，`char`表示Unicode scalar value，不等于用户看到的完整字符。解释了Rust为何不允许直接`text[0]`。

先预测：`"中".len()`返回3，因为len以UTF-8 bytes计；`chars().count()`返回1，但某些emoji的grapheme数量仍需专门Unicode分段库。


## 字符编码、char与String分类

`Vec<u8>`可保存任意bytes，`String`保存owned UTF-8，`&str`借用UTF-8片段，`char`是四字节Rust值。通常由`String::from_utf8`返回Result；`from_utf8_lossy`会替换非法序列，应由业务明确是否允许信息损失。

```rust
let bytes = vec![0xE4, 0xB8, 0xAD];
let text = String::from_utf8(bytes).expect("valid UTF-8");
assert_eq!(text, "中");
assert_eq!(text.len(), 3);
assert_eq!(text.chars().count(), 1);
```

## 字符串处理与遍历

按bytes遍历适合协议和ASCII边界，按chars遍历适合Unicode scalar逻辑，按lines或split处理分隔结构。必须在算法入口固定，否则offset和长度会混用。

## 修改、拼接与容量

`push`追加char，`push_str`追加str，`insert`和`replace_range`要求byte index位于UTF-8边界。String像Vec一样有length和capacity，扩容可能移动buffer。要求持有slice时不能再修改可能扩容的owner。

```rust
let mut message = String::with_capacity(16);
message.push_str("rust");
message.push('道');
assert_eq!(message, "rust道");
assert!(message.capacity() >= message.len());
```

## 查找、切片与转换

`find`返回匹配起始byte offset，`contains`只回答存在，`strip_prefix`表达协议前缀；切片区间必须落在字符边界。数字解析用`parse`返回Result，格式化产生新String。禁止把byte offset直接显示为“第几个字符”。


## Vec：连续存储、长度与扩容

Vec保存连续同型元素，提供O(1)索引和摊销push。`reserve`至少预留额外容量，`shrink_to_fit`只是请求缩容；remove中间元素需要移动后续值，swap_remove不保序但更快。是unsafe指针和缓存设计的关键。

```rust
let mut values = Vec::with_capacity(2);
values.extend([3, 1, 2]);
values.sort_unstable();
assert_eq!(values, [1, 2, 3]);
```

## 映射与集合：Hash还是有序树

HashMap与HashSet要求Hash和Eq一致，适合平均常数查找；BTreeMap与BTreeSet要求Ord，提供排序遍历和范围查询。Key进入集合后不得改变影响Hash、Eq或Ord的状态，否则查找结构与逻辑值不一致。需要稳定输出时显式排序或用BTree，不应依赖Hash迭代顺序。
