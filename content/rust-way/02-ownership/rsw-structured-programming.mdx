## 从非法状态能否被表示开始

结构化编程在Rust中不等于把C++类翻译为struct。它先用类型表达状态：结构体表示字段共同存在的product type，枚举表示variant互斥的sum type，impl维护构造与方法不变量，Trait表达跨类型行为。<Term def="由数据形状、有效状态、公开操作和owner关系共同组成的类型设计。">state-oriented data model</Term>应让“连接既未建立又已关闭”这类矛盾状态无法构造。

先预测：三个bool表示连接状态有八种组合，而只需要三种状态时，枚举更能让编译器检查穷尽性。

```rust
enum Connection {
    Disconnected,
    Connected { peer: String },
    Closed { reason: String },
}
```

## 面向对象风格：数据、行为与封装

私有字段配受检构造器维护不变量，`&self`查询，`&mut self`更新，按值`self`执行状态消费。Rust没有类继承，通常用组合复用数据与实现，用Trait实现接口多态。<Term def="用私有表示、impl方法和Trait行为边界组织对象，而不依赖类继承层次。">object-style encapsulation</Term>把owner动作写进receiver类型。

```rust
struct Counter { value: u64, limit: u64 }

impl Counter {
    fn new(limit: u64) -> Self { Self { value: 0, limit } }
    fn increment(&mut self) -> bool {
        if self.value == self.limit { false } else { self.value += 1; true }
    }
}
```

## 结构体、枚举与Trait object

结构体适合所有字段同时有效；枚举适合状态携带不同payload；泛型适合同一实现对多类型静态分派；Trait object适合运行期异构集合。<Term def="根据状态闭合性、实现集合是否开放以及分派时机选择结构、枚举、泛型或Trait object。">representation dispatch choice</Term>避免用`Option`字段堆出大量无效组合。

## 析构顺序与部分移动

同一scope的局部owner通常按声明逆序析构；结构体字段按声明顺序析构；实现Drop后先调用`drop`方法，再自动清理字段。编译器用drop flag处理条件初始化和部分移动。<Term def="owner离开有效范围时，Drop实现与其仍初始化字段按规则执行的清理序列。">deterministic drop order</Term>可用于RAII，但正确性不应依赖隐蔽的跨对象时序。

```rust
struct Trace(&'static str);
impl Drop for Trace {
    fn drop(&mut self) { println!("drop {}", self.0); }
}

let _first = Trace("first");
let _second = Trace("second");
```

## Builder模式：从草稿到有效对象

Builder累积可选参数，在`build`统一验证必填项和跨字段关系，再产生不可变有效对象。<Term def="允许暂时不完整配置存在，但只在统一构建边界输出满足全部不变量的对象。">validated builder boundary</Term>适合参数多、默认值多或构造可能失败的类型；简单两参数对象直接构造更清楚。

## Visitor模式：稳定结构上的多种操作

Visitor把遍历结构与操作分离。对封闭enum，`match`函数通常更直接且新增variant会触发穷尽错误；对稳定数据结构、频繁新增操作或跨节点双重分派，Visitor才更有价值。Trait object visitor会增加间接调用与生命周期设计，不能为了模式名称牺牲类型清晰度。

## RAII模式：Guard就是许可

锁guard、文件owner和事务guard把“资源已获取”编码成值；guard析构释放。<Term def="一个值的存在代表资源许可有效，其析构代表许可结束的类型化协议。">RAII guard protocol</Term>让提前返回仍清理资源。若需要commit/rollback，显式状态字段与consume式`commit(self)`比在Drop中执行可能失败的业务操作更可靠。

<Callout type="trap" title="Rust面向对象就是struct加impl">
若所有字段公开、非法组合可随意构造，impl只是语法分组。真正封装要限定构造和更新路径，并让receiver所有权表达状态迁移。
</Callout>

<Callout type="trap" title="Drop里可以完成任何关键业务操作">
Drop不能返回错误，panic期间再次panic可能中止进程，进程异常退出也不保证执行。关键提交应显式调用并处理Result，Drop只做不失败或尽力清理。
</Callout>

## 本章回顾

本章覆盖结构化编程、面向对象风格、结构体与枚举、析构顺序、建造者模式、访问者模式和RAII模式。设计顺序应是有效状态、owner、变化方向和失败路径，模式只是这些约束的结果。

<Exercises>
**问题 1：何时enum优于多个Option字段？**
<Answer>字段组合互斥且每种状态携带不同数据时，enum只允许合法variant并强制穷尽处理；多个Option会产生大量无意义组合和重复运行期检查。</Answer>

**问题 2：字段Drop顺序为何值得记录？**
<Answer>资源间若有依赖，顺序影响清理；Rust字段按声明顺序drop。但更稳妥的设计是把依赖封装进一个owner或显式关闭，避免正确性依赖不明显顺序。</Answer>

**问题 3：Builder的build应验证什么？**
<Answer>验证必填项、范围、字段间关系和资源获取结果；失败返回类型化Error，成功后输出字段私有且持续满足不变量的对象。</Answer>
</Exercises>
