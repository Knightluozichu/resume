## 从非法状态能否被表示开始

结构化编程在Rust中不等于把C++类翻译为struct。它先用类型表达状态：结构体表示字段共同存在的product type，枚举表示variant互斥的sum type，impl维护构造与方法不变量，Trait表达跨类型行为。应让“连接既未建立又已关闭”这类矛盾状态无法构造。

先预测：三个bool表示连接状态有八种组合，而只需要三种状态时，枚举更能让编译器检查穷尽性。

```rust
enum Connection {
    Disconnected,
    Connected { peer: String },
    Closed { reason: String },
}
```


## 面向对象风格：数据、行为与封装

私有字段配受检构造器维护不变量，`&self`查询，`&mut self`更新，按值`self`执行状态消费。Rust没有类继承，通常用组合复用数据与实现，用Trait实现接口多态。把owner动作写进receiver类型。

```rust
struct Counter { value: u64, limit: u64 }

impl Counter {
    fn new(limit: u64) -> Self { Self { value: 0, limit } }
    fn increment(&mut self) -> bool {
        if self.value == self.limit { false } else { self.value += 1; true }
    }
}
```

## 结构体、枚举与Trait object

结构体适合所有字段同时有效；枚举适合状态携带不同payload；泛型适合同一实现对多类型静态分派；Trait object适合运行期异构集合。避免用`Option`字段堆出大量无效组合。

## 析构顺序与部分移动

同一scope的局部owner通常按声明逆序析构；结构体字段按声明顺序析构；实现Drop后先调用`drop`方法，再自动清理字段。编译器用drop flag处理条件初始化和部分移动。可用于RAII，但正确性不应依赖隐蔽的跨对象时序。

```rust
struct Trace(&'static str);
impl Drop for Trace {
    fn drop(&mut self) { println!("drop {}", self.0); }
}

let _first = Trace("first");
let _second = Trace("second");
```


## Builder模式：从草稿到有效对象

Builder累积可选参数，在`build`统一验证必填项和跨字段关系，再产生不可变有效对象。适合参数多、默认值多或构造可能失败的类型；简单两参数对象直接构造更清楚。

## Visitor模式：稳定结构上的多种操作

Visitor把遍历结构与操作分离。对封闭enum，`match`函数通常更直接且新增variant会触发穷尽错误；对稳定数据结构、频繁新增操作或跨节点双重分派，Visitor才更有价值。Trait object visitor会增加间接调用与生命周期设计，不能为了模式名称牺牲类型清晰度。

## RAII模式：Guard就是许可

锁guard、文件owner和事务guard把“资源已获取”编码成值；guard析构释放。让提前返回仍清理资源。若需要commit/rollback，显式状态字段与consume式`commit(self)`比在Drop中执行可能失败的业务操作更可靠。


## 本章回顾

本章覆盖结构化编程、面向对象风格、结构体与枚举、析构顺序、建造者模式、访问者模式和RAII模式。设计顺序应是有效状态、owner、变化方向和失败路径，模式只是这些约束的结果。
