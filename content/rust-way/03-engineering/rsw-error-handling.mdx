## 从“这个失败能否被设计掉”开始

健壮程序不是给每行代码包一层catch，而是缩小无效状态空间。若端口必须非零，就在构造边界验证并产生`NonZeroU16`；若状态互斥，用enum代替多个bool；若字段必须同时有效，保持私有并提供受检构造器。使后续函数只处理已证明数据。

先预测：`Option<u16>`无法区分缺失与非法文本；解析边界应先返回Result，再按业务决定是否把缺失表示为Option。


## Option：表达缺失而非失败原因

Option适合“有或没有”且None不需要详细原因，例如查找未命中。组合子`map`、`and_then`、`filter`和`ok_or_else`可逐步转换；`unwrap`只应在测试、示例或已由附近不变量证明Some时使用。不应承担权限拒绝、解析错误和I/O失败等多个原因。

```rust
fn extension(path: &str) -> Option<&str> {
    path.rsplit_once('.').map(|(_, ext)| ext).filter(|ext| !ext.is_empty())
}

assert_eq!(extension("report.csv"), Some("csv"));
assert_eq!(extension("README"), None);
```

## Result与问号传播

Result用Ok和Err构成穷尽失败通道。`?`在Err时提前返回，并通过From完成兼容错误转换；它不等于忽略错误。应该让调用者能匹配需要恢复的类别，同时保留诊断来源。

```rust
use std::{fs, num::ParseIntError};

fn read_limit(path: &str) -> Result<u64, Box<dyn std::error::Error>> {
    let raw = fs::read_to_string(path)?;
    let value: u64 = raw.trim().parse::<u64>()?;
    Ok(value)
}
```

应用顶层可以用通用错误聚合，公共库更适合稳定enum。路径、记录号和操作名应在最接近边界的位置补充，不能只留下“invalid input”。

## Panic：不变量破坏与不可恢复路径

panic适合程序缺陷、内部不变量被破坏或当前API无法合理继续的状态。Unwind会执行多数Drop，abort直接终止；FFI边界不能让unwind随意跨越未知ABI。要求库对普通外部输入返回Result，而不是panic。


## 错误上下文与来源链

同一个`io::Error`只有在附加“读取哪个路径、执行什么操作”后才可定位。错误wrapper应实现`source`或使用透明包装保留底层类型；Display面向用户，Debug和source chain面向诊断。不能被一次`map_err(|_| "failed")`截断。

```rust
#[derive(Debug)]
enum ConfigError {
    MissingField(&'static str),
    InvalidPort(ParseIntError),
}
```

## 第三方库错误的翻译边界

直接暴露依赖错误会把依赖版本变成公共API；全部转String又丢失结构。边界层应把需要稳定处理的类别映射为领域variant，对不需匹配的底层来源保留source。还应避免把token、密码或完整敏感输入写进上下文。


## 失败注入与状态原子性

测试不能只断言happy path。应注入不存在文件、权限拒绝、非法UTF-8、解析溢出、写到一半失败和依赖超时；同时断言旧状态未被部分修改、临时文件被清理、错误链含路径和source。先构造新状态并验证，最后一次交换提交，比边读边改共享状态更稳健。


## 本章回顾

本章覆盖构建健壮的程序、消除失败、Option、Result、panic和第三方库错误。顺序是先让无效状态不可构造，再选择失败通道，补充上下文和来源链，最后通过失败注入验证资源清理与状态原子性。
