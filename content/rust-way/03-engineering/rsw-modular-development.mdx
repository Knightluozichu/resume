## 从“文件夹不是模块边界”开始

模块化开发同时有构建边界与语言边界。Cargo package由manifest描述，可包含library与binary等target；crate是一次编译和命名空间单元；workspace协调多个package；module则组织crate内部路径和可见性。避免把目录、编译单元和发布单元混为一谈。

先预测：把源码移动到子目录不会自动改变公开API，但修改`mod`声明和`pub use`会改变名称路径。


## Cargo package、crate与target

`Cargo.toml`定义package元数据、依赖、feature、profile和target。一个package最多有一个library crate，可有多个binary、example、test和bench target；每个target产生crate。还应包含license、repository、edition与minimum supported Rust version等维护信息。

```toml
[package]
name = "csv-domain"
version = "0.1.0"
edition = "2024"

[dependencies]
csv = "1"
serde = { version = "1", features = ["derive"] }
```

## 依赖、feature、lockfile与自定义构建

Cargo通过语义版本和registry/source解析依赖图；feature应是加法式能力，避免同名feature在关闭时改变不相关语义。库通常发布兼容范围，应用提交Cargo.lock获得可重复解析。不能覆盖native compiler、环境变量或build script外部工具，后者也需记录。

`build.rs`在编译前生成代码、探测native库或输出link指令；它是构建程序，不应偷偷下载不可校验内容。生成文件写入OUT_DIR，并通过明确输入触发rerun。

## Workspace：共享而不混同发布

Workspace共享lockfile和target目录，可统一lint与profile，同时每个member仍有独立package版本与发布策略。适合把domain、CLI、server和binding拆开，不能用循环依赖连接它们。

```toml
[workspace]
resolver = "3"
members = ["crates/domain", "crates/cli"]

[workspace.dependencies]
serde = { version = "1", features = ["derive"] }
```

## 模块系统、路径与use

`mod`建立模块树，`crate`、`self`和`super`确定路径起点，`use`只把名称引入scope。文件布局是模块树的载体，不是API设计本身。应让内部移动文件时，稳定入口仍可通过`pub use`保持。

## 可见性与私有性

Item默认私有，`pub`公开，`pub(crate)`、`pub(super)`和`pub(in path)`限制范围。字段私有使构造器可以维护不变量；sealed trait可限制外部实现。不是“全部pub方便调用”。


## 完整CSV功能包

CSV不是按逗号split：quoted field可含逗号和换行，escape与编码也有协议。Library层接受Reader并返回领域记录或类型化Error；CLI层负责路径、stdout、stderr和exit status。应保留row/field坐标并避免部分输出伪装成功。

```rust
use serde::Deserialize;

#[derive(Debug, Deserialize)]
struct Record { id: u64, name: String }

fn read_records(input: impl std::io::Read) -> csv::Result<Vec<Record>> {
    csv::Reader::from_reader(input).deserialize().collect()
}
```
