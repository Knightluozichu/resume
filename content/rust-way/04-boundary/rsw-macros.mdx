## 从“程序能否观察自己的类型”开始

Rust没有任意枚举字段和方法的完整运行期反射。它提供`TypeId`比较`'static`类型，`Any`对类型擦除值做受检向下转型，更多结构信息通常通过Trait、泛型或编译期代码生成表达。是刻意受限的，不应替代正常类型设计。

先预测：`downcast_ref`失败会返回None，而不是把错误类型引用强制解释为目标类型；这使失败仍在safe边界内。

```rust
use std::any::Any;

fn as_text(value: &dyn Any) -> Option<&str> {
    value.downcast_ref::<String>().map(String::as_str)
}

assert_eq!(as_text(&String::from("meta")), Some("meta"));
assert_eq!(as_text(&42_u32), None);
```


## 类型检查、向下转型与生命周期

`Any`通常要求`'static`具体类型，因此包含短借用的值不能随意放入长期类型擦除容器。必须保留失败分支和借用寿命。若实现集合在编译期已知，enum或泛型通常更清楚；若只需要行为，dyn Trait优于反复downcast。

## 宏的起源与token模型

宏解决重复语法、样板实现和领域语言表达。它接收token tree或TokenStream并生成新token，生成物会回到编译管线继续解析和检查。意味着宏不能读取运行期变量值，只能生成访问这些值的代码。

## 声明宏：模式与替换

`macro_rules!`用matcher捕获表达式、类型、标识符和重复序列，再在transcriber中展开。宏卫生性减少局部名字意外捕获，但路径、导出和edition边界仍需设计。适合少量结构化重复，不适合复杂语义分析。

```rust
macro_rules! string_vec {
    ($($value:expr),* $(,)?) => {
        vec![$($value.to_string()),*]
    };
}

assert_eq!(string_vec!["a", 2], vec!["a", "2"]);
```

## 过程宏：derive、属性与函数式

过程宏是独立proc-macro crate导出的编译期函数。Derive接收struct或enum item并附加impl；attribute接收属性参数和item；function-like接收调用内token并可生成任意合法语法。应使用完整限定路径、保留span并返回精确compile error。

```rust
// proc-macro crate中的轮廓
#[proc_macro_derive(Describe)]
pub fn derive_describe(input: proc_macro::TokenStream) -> proc_macro::TokenStream {
    let ast = syn::parse_macro_input!(input as syn::DeriveInput);
    expand_describe(ast).unwrap_or_else(syn::Error::into_compile_error).into()
}
```


## 宏的编译过程与调试

编译器先解析足够语法定位宏，执行展开，再进行名称解析、类型检查、借用检查、MIR与codegen。帮助定位“宏接受了输入但生成代码类型不对”。调试时检查展开结果、最小输入、span和compile-fail测试，不要只盯宏实现。


## 编译器插件与稳定替代

早期编译器插件直接依赖内部API，难以跨版本维护。稳定需求优先用声明宏、过程宏、build.rs、Cargo子命令或lint工具；只有编译器开发场景才绑定nightly内部。把升级成本和信任边界写进工程决策。
