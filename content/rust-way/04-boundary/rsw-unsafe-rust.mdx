## 从unsafe究竟允许什么开始

unsafe不会关闭类型检查、借用检查和生命周期检查；它只允许解引用裸指针、调用unsafe函数、访问或修改可变static、实现unsafe Trait、读取union字段等少数能力。必须比“我知道这里没问题”具体到非空、对齐、初始化、范围、别名、寿命和释放。

先预测：创建裸指针通常是safe，解引用才unsafe；指针存在本身不承诺目标仍有效。


## 裸指针、static与union

裸指针可为空、悬垂、不对齐或指向未初始化内存；地址运算还需保持在允许对象范围。可变static是全局共享状态，读写可能数据竞争。Union字段共享存储，读取非活动或不合法表示可能产生未定义行为。应紧邻unsafe块记录来源与保持方式。

```rust
fn first_or_none(values: &[u32]) -> Option<u32> {
    if values.is_empty() { return None; }
    let pointer = values.as_ptr();
    // SAFETY: 非空slice保证pointer有效、对齐且指向已初始化u32。
    Some(unsafe { *pointer })
}

assert_eq!(first_or_none(&[7, 8]), Some(7));
```

## 安全抽象：调用者不能制造UB

安全函数内部可使用unsafe，但必须对所有safe输入维持不变量。入口验证长度与关系，unsafe内核尽量局部，出口重新建立初始化和owner。不仅测试当前实现，还要审计公开方法之间的组合。


## 子类型、型变与无界生命周期

引用生命周期存在子类型关系，容器对类型参数可能协变、逆变或不变；可变引用对目标类型通常需要不变以防写入破坏。由裸指针凭空构造引用可能让编译器推断过长、近似无界的生命周期。影响unsafe容器是否能安全暴露引用。

```rust
use std::marker::PhantomData;
use std::ptr::NonNull;

struct View<'a, T> {
    pointer: NonNull<T>,
    marker: PhantomData<&'a T>,
}
```

PhantomData告诉dropck、auto trait与型变分析这个类型在语义上持有何种T或引用；它不是占位装饰。

## dropck、NonNull与析构安全

Drop实现运行时，类型参数指向的数据必须仍满足析构访问需要。NonNull表达非空协变指针并支持空指针优化，但不证明对齐、初始化或唯一访问。与字段声明、PhantomData和析构体读取行为共同决定。

## Panic安全与部分初始化

unsafe集合在扩容、clone元素或用户回调panic时，必须避免重复drop、读取未初始化值和长度撒谎。常通过先写入MaybeUninit、最后更新len，以及guard在unwind时清理已初始化前缀实现。

```rust
use std::mem::MaybeUninit;

let mut slot = MaybeUninit::<String>::uninit();
slot.write(String::from("ready"));
// SAFETY: 上一行已经完整初始化slot，且只取出一次。
let value = unsafe { slot.assume_init() };
assert_eq!(value, "ready");
```

## 内存分配与安全原则

Allocator返回的地址需满足size与alignment，deallocate必须使用兼容layout和allocator；零大小类型、溢出和realloc失败都有边界。要求先证明算术不溢出，再调用低层API。

## FFI、C/C++与动态语言

FFI必须固定ABI、`repr(C)`布局、整数宽度、字符串编码、null、数组length、错误返回、线程、回调和释放函数。Rust panic不能随意穿越C边界，C++异常也不能穿越未知Rust帧。通常由很薄的unsafe binding层转换为safe领域类型。

## WebAssembly与线性内存

WebAssembly边界常传offset与length或借助绑定生成器。Host可能让线性内存增长并改变视图，字符串需明确UTF-8，handle需防重复释放。动态语言GC对象不能被Rust裸借用跨越未知回调；应使用runtime提供的root或handle机制。


## 本章回顾

本章覆盖超越安全边界：unsafe语法、static、union与裸指针，安全抽象，子类型、型变与无界生命周期，dropck、NonNull与panic安全，内存分配与安全原则，FFI与C/C++，以及动态语言与WebAssembly。Unsafe的产物应是更小、更清楚、更可审计的安全API。
