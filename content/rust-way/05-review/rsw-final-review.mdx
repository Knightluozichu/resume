## 从一个故障应该回到哪一章开始

总复习不是重复语法，而是建立跨章索引。编译器报告move后使用，应回第5章；Vec引用失效先回第8章，再追第4章布局与第5章借用；异步死锁回第11章同步谓词；过程宏生成错误回第12章展开管线；FFI崩溃回第13章ABI与owner协议。让13章成为诊断坐标。

先预测：一个“偶发错误结果”不一定是线程竞争，也可能是HashMap不稳定顺序、第9章错误被String吞掉，或第13章外部buffer寿命错误。

## 第一层：值、类型与内存表示

第1章给出安全、零成本与实用主义，第2章建立表达式和类型地图，第3章用泛型Trait约束能力，第4章解释栈、堆、layout、RAII与泄漏。是阅读性能、FFI和unsafe代码的共同起点。

```rust
use std::mem::{align_of, size_of};

fn describe<T>(_: &T) -> (usize, usize) {
    (size_of::<T>(), align_of::<T>())
}

assert_eq!(describe(&7_u32).0, 4);
```

## 第二层：所有权、调用与数据抽象

第5章决定释放责任与借用，第6章决定闭包环境和Iterator的Item owner，第7章用结构与模式封装状态，第8章处理UTF-8和集合重定位。要求高层API仍能回答谁拥有、谁可改、引用何时结束。

```rust
fn normalize(values: &mut [String]) {
    values.iter_mut().for_each(|value| value.make_ascii_lowercase());
}

let mut values = vec![String::from("RUST")];
normalize(&mut values);
assert_eq!(values[0], "rust");
```

## 第三层：失败、模块、并发与安全边界

第9章让失败进入Option、Result或panic边界，第10章固定crate和可见性，第11章证明线程、原子、channel和Future，第12章审计生成代码，第13章承担编译器无法证明的内存与互操作条件。是生产系统是否可维护的核心。

## 故障逆向诊断

先分阶段：parse/展开、类型借用、链接、运行、并发活性、外部协议。再还原最小输入和toolchain，画值与线程关系，追错误source，最后找到首个失效约束。禁止一开始就clone、加锁或包unsafe掩盖诊断。


## 综合项目：可取消CSV处理服务

同步核心定义私有有效Record和领域Error；CSV adapter读取、验证并保留row坐标；worker层用bounded channel提供背压；取消flag或channel关闭停止接收；结果先写临时文件，flush成功后替换；若有C库加速解析，只在很薄的binding层用unsafe。让每层可以独立测试。

```rust
use std::sync::mpsc::sync_channel;

let (jobs_tx, jobs_rx) = sync_channel::<String>(8);
jobs_tx.send("row-1".into())?;
drop(jobs_tx);
let collected: Vec<_> = jobs_rx.into_iter().collect();
assert_eq!(collected, ["row-1"]);
# Ok::<(), Box<dyn std::error::Error>>(())
```


## 全书验收矩阵

正确性验证正常、空值、极端值与错误值；内存验证owner、Drop、泄漏和峰值；类型验证公开bound与非法状态；并发验证锁顺序、背压、关闭、取消和panic；模块验证clean build、lockfile和最小pub；宏验证展开与compile-fail；unsafe验证SAFETY注释、Miri或sanitizer、FFI对端布局与失败注入。防止“编译通过”成为唯一标准。


## 本章回顾

13章形成三层：语言、类型和内存定义值；所有权、闭包、结构和集合定义安全抽象；错误、模块、并发、宏和unsafe定义系统边界。真正掌握表现为能从故障逆向找到首个不变量，并用综合项目的多维证据证明修复没有转移风险。
