## 直觉引入

光照就像打手电筒照物体——环境光是房间里本来就有的微光，漫反射是物体表面把光均匀散开（像墙），镜面反射是光滑表面把光聚成一个小亮点（像镜面）。Phong 模型就是把这三种光加起来。Blinn-Phong 是它的改进版，用更省的方法算高光。

## 概念讲解

### Phong 三分量
- Ambient（环境光）：ka * ambientColor，模拟间接照明
- Diffuse（漫反射）：kd * max(dot(N, L), 0)，粗糙表面散射
- Specular（镜面反射）：ks * pow(max(dot(R, V), 0), shininess)，光滑表面高光

### Blinn-Phong 改进
用半角向量 H = normalize(L + V) 替代反射向量 R。spec = pow(max(dot(N, H), 0), shininess)。省去了昂贵的 reflect 计算，高光更柔和自然。

### 法线归一化
光照计算依赖法线方向（点积），法线长度不为 1 时结果不正确。插值后法线长度会变化，必须在像素着色器中重新 normalize。

计算环境光（常量）、漫反射（N·L 点积）、镜面反射（R·V 点积的幂次），三者相加得到最终光照颜色。
</Step>
<Step title="第二步：Blinn-Phong 改进">
用半角向量 H = normalize(L + V) 替代 reflect 计算。spec = pow(dot(N, H), shininess)。更高效且高光更自然。
</Step>
<Step title="第三步：多光源支持">
将光源数据打包到数组或 StructuredBuffer，在像素着色器中循环遍历，逐光源计算 Diffuse + Specular 并累加。
</Step>
</Stepper>

## 代码对照

```hlsl
// Blinn-Phong 光照着色器
float4 PSMain(VSOutput input) : SV_TARGET {
    float3 N = normalize(input.Normal);     // 必须归一化
    float3 L = normalize(LightDir);
    float3 V = normalize(ViewPos - input.WorldPos);
    float3 H = normalize(L + V);            // 半角向量

    float4 texColor = DiffuseTexture.Sample(Sampler, input.TexCoord);

    // Ambient
    float3 ambient = 0.1 * texColor.rgb;
    // Diffuse
    float diff = max(dot(N, L), 0.0);
    float3 diffuse = diff * texColor.rgb * LightColor;
    // Specular (Blinn-Phong)
    float spec = pow(max(dot(N, H), 0.0), 32.0);
    float3 specular = spec * LightColor;

    return float4(ambient + diffuse + specular, 1.0);
}

// 多光源循环
float4 PSMainMultiLight(VSOutput input) : SV_TARGET {
    float3 N = normalize(input.Normal);
    float3 V = normalize(ViewPos - input.WorldPos);
    float3 result = 0.1; // ambient

    for (int i = 0; i < LightCount; i++) {
        float3 L = normalize(Lights[i].Position - input.WorldPos);
        float3 H = normalize(L + V);
        float diff = max(dot(N, L), 0.0);
        float spec = pow(max(dot(N, H), 0.0), 32.0);
        result += (diff + spec) * Lights[i].Color;
    }
    return float4(result, 1.0);
}
```

Blinn-Phong 用 H 向量省去了 reflect，多光源用循环遍历光源数组累加。

## 常见误区

<Callout type="trap">
**现象 →** 光照效果过亮或过暗，高光位置不对。
**原因 →** 法线没有归一化。
**修法 →** 法线经过矩阵变换和光栅化插值后长度会变化。必须在像素着色器中用 normalize(input.Normal) 重新归一化。光照计算依赖法线方向，长度不正确会导致点积结果错误。
</Callout>

<Callout type="trap">
**现象 →** 多光源场景帧率急剧下降。
**原因 →** 前向渲染中每个像素都要遍历所有光源。
**修法 →** 前向渲染光源数量受限。多光源场景应考虑延迟渲染（先渲染 G-Buffer 再逐光源计算）。或对光源做剔除，只计算影响范围内的像素。
</Callout>

## 练习

<Exercises>
**问题**：Blinn-Phong 相比 Phong 的改进是什么？

<Answer>
Blinn-Phong 用半角向量 H（光线方向与视线方向的中间向量）与法线的点积替代反射向量 R 与视线的点积。避免了昂贵的 reflect 计算，且高光更柔和自然，性能更好。
</Answer>

**问题**：为什么法线必须归一化后才能用于光照计算？

<Answer>
光照计算依赖法线方向（点积），法线长度不为 1 时点积结果不正确。插值后法线长度可能变化，必须在像素着色器中重新 normalize。法线错误会导致光照强度异常。
</Answer>
</Exercises>
