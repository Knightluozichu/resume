## 直觉引入

想象一个橡皮泥人偶。顶点着色器就是你的双手——你可以拉伸它的四肢（变形动画），扭曲它的身体（漩涡效果），或者让它像旗帜一样飘动（风力模拟）。每个顶点就是一个关节点，你在 GPU 上同时操控成千上万个关节点，让静态模型「活」起来。

关键洞察：顶点着色器的核心能力是**在 GPU 上并行变换顶点位置**。这不仅仅是 MVP 变换——你可以用数学函数驱动顶点位置，实现无需骨骼动画的程序化运动，性能远超 CPU 端逐顶点计算。

## 代码对照

```hlsl
// 顶点着色器：旗帜飘动效果
struct VSInput {
    float4 position : POSITION;
    float3 normal   : NORMAL;
    float2 uv       : TEXCOORD0;
};

struct VSOutput {
    float4 position : SV_POSITION;
    float3 normal   : NORMAL;
    float2 uv       : TEXCOORD0;
};

cbuffer Constants : register(b0) {
    float4x4 worldViewProj;
    float time;
    float waveAmplitude;
    float waveFrequency;
    float waveSpeed;
};

VSOutput main(VSInput input) {
    VSOutput output;
    
    // 旗帜波浪变形：沿X轴传播
    float wave = sin(input.position.x * waveFrequency + time * waveSpeed);
    float3 deformedPos = input.position.xyz;
    deformedPos.z += wave * waveAmplitude * input.uv.x; // 越远离旗杆变形越大
    
    output.position = mul(worldViewProj, float4(deformedPos, 1.0));
    output.normal = input.normal; // 简化：实际需重算法线
    output.uv = input.uv;
    return output;
}
```

## 常见误区

<Callout type="trap">
**误区：变形后不更新法线。**
顶点变形后，原始法线已经不再匹配新的几何形状。如果直接使用原法线做光照计算，变形区域会出现光照错误——暗处变亮、高光位置不对。必须根据变形函数的偏导数重新计算法线，或者用相邻顶点差分近似法线。
</Callout>

<Callout type="trap">
**误区：在顶点着色器中做复杂光照。**
顶点着色器输出的值会被光栅化插值，光照在顶点着色器中计算会导致 Gouraud 着色——低多边形模型上出现明显的多边形边界。高质量光照应该在像素着色器中做（Phong 着色），顶点着色器只负责传递法线和位置数据。
</Callout>

## 练习

<Exercises>
**问题 1**：顶点着色器中的 attribute、uniform、varying 三种变量有什么区别？

<Answer>
attribute 是逐顶点属性，每个顶点有独立的值（如 position、normal、uv），来自顶点缓冲区。uniform 是全局统一变量，所有顶点共享相同的值（如变换矩阵、时间参数），在整个绘制调用中不变。varying 是顶点着色器输出给像素着色器的变量，会被光栅化器在三角形内部线性插值，使像素着色器获得平滑过渡的数据（如插值后的法线、UV坐标）。简单记忆：attribute=输入逐顶点数据，uniform=全局参数，varying=顶点到像素的插值传递。
</Answer>

**问题 2**：为什么顶点变形后必须重新计算法线？如何实现？

<Answer>
法线决定光照方向，而变形改变了几何形状，原法线不再垂直于变形后的表面。用原法线做光照会导致高光和阴影位置错误。重算法线的方法：1) 解析法——对变形函数求偏导，用偏导数的叉积得到新法线（如变形函数 f(x,y,z)，偏导 fx/fy/fz 的叉积归一化即为法线）；2) 数值法——对每个顶点，用相邻顶点的差分近似切线向量，叉积得到法线。解析法精确但需要知道变形函数的数学表达式，数值法通用但有额外计算开销。
</Answer>
</Exercises>
