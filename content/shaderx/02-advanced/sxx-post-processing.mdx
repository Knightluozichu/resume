## 直觉引入

想象你拍了一张照片，然后在修图软件里加滤镜——调亮、模糊背景、加光晕。后处理就是 GPU 的「修图软件」：先把整个场景渲染到一张纹理上，再用全屏着色器对这张纹理做各种效果处理。区别是 GPU 每帧都在实时「修图」，60次/秒。

关键洞察：后处理的核心模式是**渲染到纹理 → 全屏着色器采样**。所有后处理效果（模糊、辉光、景深）都是对已渲染的场景纹理做像素级操作。这意味着性能开销与屏幕分辨率成正比，优化重点是减少纹理采样和 Pass 数量。

<Stepper>
<Step title="第一步：理解渲染到纹理">后处理的前提是 Render Target 切换：先渲染场景到一张离屏纹理（而不是直接到屏幕），然后用全屏四边形（Quad）采样这张纹理做后处理。每个后处理效果可以是一趟单独的 Pass，Pass 之间通过纹理串联。</Step>
<Step title="第二步：高斯模糊优化">
二维高斯模糊的朴素实现是 N×N 次采样（如 9×9 = 81 次）。利用高斯函数的可分离性，拆成水平 N 次和垂直 N 次两趟（9+9 = 18 次），性能提升约 4.5 倍。这是后处理优化的经典案例。
<SxxPostProcessingDiagram />
</Step>
<Step title="第三步：Bloom 流程">Bloom 是多趟后处理的组合：1) 亮度提取（阈值过滤出亮区）；2) 降采样（缩小分辨率提高模糊效率）；3) 高斯模糊（多级模糊形成渐变光晕）；4) 叠加回原图。每一步都是独立的 Pass。</Step>

## 代码对照

```hlsl
// 分离卷积高斯模糊（水平 Pass）
Texture2D inputTexture : register(t0);
SamplerState pointClamp : register(s0);

cbuffer BlurCB : register(b0) {
    float2 texelSize; // 1/width, 1/height
    float blurStrength;
};

static const float weights[5] = { 0.227027, 0.1945946, 0.1216216, 0.054054, 0.016216 };
static const int offsets[5] = { 0, 1, 2, 3, 4 };

float4 main(float4 position : SV_POSITION, float2 uv : TEXCOORD0) : SV_TARGET {
    float4 color = inputTexture.Sample(pointClamp, uv) * weights[0];
    
    [unroll] for (int i = 1; i < 5; i++) {
        float2 offset = float2(texelSize.x * offsets[i] * blurStrength, 0.0);
        color += inputTexture.Sample(pointClamp, uv + offset) * weights[i];
        color += inputTexture.Sample(pointClamp, uv - offset) * weights[i];
    }
    
    return color;
    // 垂直 Pass 只需把 offset 的 x 改成 y
}

// Bloom 亮度提取
float4 BloomExtract(float4 hdrColor, float threshold) {
    float brightness = dot(hdrColor.rgb, float3(0.2126, 0.7152, 0.0722));
    float3 contribution = hdrColor.rgb * max(brightness - threshold, 0.0) / max(brightness, 0.00001);
    return float4(contribution, 1.0);
}
```

## 常见误区

<Callout type="trap">
**误区：后处理用普通双线性采样就够了。**
后处理涉及多趟纹理读写，采样质量直接影响最终效果。模糊应该用线性采样（双线性插值可以合并相邻采样点，减少采样次数），但亮度提取和最终合成应该用点采样（避免不必要的模糊）。更重要的是 Render Target 格式：HDR 效果必须用 float16/float32 格式存储中间结果，用 R8G8B8 会丢失高光信息导致 Bloom 不正确。
</Callout>

<Callout type="trap">
**误区：Bloom 模糊越多越好。**
过度模糊的 Bloom 会让画面「雾蒙蒙」，细节丢失。正确做法是使用多级降采样（Mip Chain）：每级分辨率减半，在小分辨率上做大范围模糊（几乎免费），然后逐级叠加回高分辨率。这样既获得大范围光晕扩散，又保留亮区中心的锐利感。通常 4-6 级降采样即可，盲目增加模糊 Pass 只会浪费性能。
</Callout>

## 练习

<Exercises>
**问题 1**：高斯模糊的分离卷积优化原理是什么？性能提升多少？

<Answer>
二维高斯核是可分离的——一个 2D 高斯核可以分解为两个 1D 高斯核的乘积（行向量 × 列向量）。因此 N×N 的二维卷积可以拆成水平 1D 卷积和垂直 1D 卷积两趟。采样次数从 N×N 降为 2N。以 9×9 核为例：朴素法 81 次采样，分离法 9+9=18 次采样，性能提升约 4.5 倍。数学上 G(x,y) = G(x) × G(y)，两趟 1D 卷积的结果与一趟 2D 卷积完全等价。这是图像处理和后处理中最经典的优化技巧。
</Answer>

**问题 2**：Bloom 辉光效果的完整流程是什么？为什么需要降采样？

<Answer>
Bloom 完整流程：1) 亮度提取——用阈值过滤场景纹理，只保留亮区（如 LDR 中的 >1.0 区域需要 HDR 纹理支持）；2) 降采样——将亮度图缩小到 1/2、1/4、1/8 等多级分辨率；3) 逐级模糊——在每个降采样级别上做高斯模糊，小分辨率上少量采样就能覆盖大范围区域；4) 逐级叠加——将各级模糊结果从最小级别逐级上采样叠加回原分辨率；5) 合成——将叠加后的 Bloom 纹理加到原始场景上。降采样的原因：在原分辨率上做大范围高斯模糊需要很大的核（如 64x64），极其昂贵；降采样后 8x8 核在小分辨率图上等效覆盖原分辨率的大范围，性能提升数十倍。
</Answer>
