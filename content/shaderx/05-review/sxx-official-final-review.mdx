## 逐篇证据公式

$$
mapped = sum(themeArticleCount) = 329
$$

$$
identityError = missingSource + duplicateOwnership
$$

$$
reproductionError = norm(reference - modern)
$$

$$
releaseGate = identityOk * coverageOk * teachingOk * runtimeOk
$$

任一乘项为零都不能发布。分数高不能抵消来源缺失，截图漂亮不能抵消数值错误，微基准快不能抵消完整帧回退。

## 随机抽检协议

```text
pick article -> verify volume and source -> locate unique theme
read model -> run reference -> run modern path -> compare evidence
inject boundary -> reproduce failure -> apply fix -> replay same case
```

抽检既要覆盖早期shader model，也要覆盖后期DirectX 10、移动GPU、引擎和GPGPU文章。每个主题至少抽一篇，重点检查页面是否真正解释该篇的输入、变换、限制和现代对应。

### 身份抽检

先从授权PDF或官方目录抄录卷名与篇名，再反查清单ID、主题页和复习题。标题中的版本号、连字符或大小写可以规范化展示，但不能把两篇不同文章合并。对ShaderX 2必须同时抽到入门册和技巧册；对ShaderX 7要确认重复列出的细分文章只占一个唯一键，而两篇共用6.7编号的AO文章仍各自存在。身份抽检的输出是可追溯记录，不是“搜索到了相似标题”。

### 算法抽检

对抽中文章写一个最小输入，列出原篇可观察输出和一条不可省略的关系。几何类检查空间与共享边，图像类检查采样核与颜色域，光照类检查能量和可见性，计算类检查同步与收敛。现代实现若使用硬件光追、compute或现成API替代旧多pass路径，必须用参考结果证明解决的是同一个问题，并明确质量、性能或适用域发生的变化。

### 工程抽检

在目标设备记录编译目标、资源格式、分辨率、场景、驱动、帧阶段和统计窗口。先捕获正常输入，再注入边界与失败输入；修复后使用同一配置重放。性能结论同时报告CPU提交、GPU时间、带宽或显存和画质误差，移动路径还要报告持续负载与热稳定。只有证据可以由第三方复跑，文章复现才算通过。

```hlsl
float4 AcceptanceProbe(float4 referenceValue, float4 modernValue) : SV_Target {
    return abs(referenceValue - modernValue);
}
```
