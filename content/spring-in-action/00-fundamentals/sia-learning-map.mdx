## 直觉引入

把 Spring 想象成「建造一座可伸缩的软件工厂」。你要先学会「让零件自己组装」（核心IoC——控制反转/依赖注入），再学会「按图纸批量装配零件」（Bean装配——自动装配/Java配置/组件扫描）；需要统一处理「质检、日志、安保」等横切事务时用「流水线旁路」（AOP——切面/通知/织入），把零件送上「传送带」需要「调度中枢」（Spring MVC——DispatcherServlet 控制请求流转）；零件要「入库存储」用「标准化仓库」（数据访问——Spring Data JPA/Repository），工厂要「门禁安保」用「安检通道」（Spring Security——过滤链/认证/授权）；用「预制件+自动装配」让「建厂提速」（Spring Boot——自动配置/起步依赖），最后工厂做大要「分布式连锁经营」（Spring Cloud——服务注册/网关/熔断/配置中心）。

## 四阶段递进

<Term def="Spring 的核心理念是控制反转（IoC）——把对象创建和依赖管理的权力从业务代码「反转」给容器，让开发者聚焦业务逻辑而非装配细节。">核心理念</Term>贯穿全书。全书可以拆成四个递进阶段。**核心与装配**解决「对象怎么来」和「对象怎么连」——IoC 容器管理 Bean 生命周期、依赖注入实现松耦合、自动装配/Java配置/组件扫描完成 Bean 装配。**Web与切面**解决「请求怎么流转」和「横切关注点怎么分离」——AOP 把日志/事务/安全从业务代码剥离、Spring MVC 用 DispatcherServlet 调度 HTTP 请求到控制器。**数据与安全**解决「数据怎么持久化」和「访问怎么控制」——Spring Data JPA 只写接口就生成查询、Spring Security 用过滤链做认证授权。**云原生**解决「配置怎么自动化」和「服务怎么治理」——Spring Boot 约定优于配置一键启动、Spring Cloud 解决微服务注册/网关/熔断/配置。

```java
// 「一个电商订单系统」——Spring 全书知识点全程参与的数据流

// 1. 核心IoC（第1章）：容器管理对象，注入依赖
//    @Service public class OrderService {
//        private final OrderRepo repo;       // 容器注入，不自己 new
//        public OrderService(OrderRepo repo) { this.repo = repo; }
//    }

// 2. Bean装配（第2章）：自动装配 + 组件扫描
//    @SpringBootApplication  // = @Configuration + @ComponentScan + @EnableAutoConfiguration
//    public class App { public static void main(String[] args) { SpringApplication.run(App.class, args); } }

// 3. AOP（第3章）：事务管理是切面的典型应用
//    @Transactional  // 声明式事务，AOP 织入开启/提交/回滚逻辑
//    public Order createOrder(Order o) { ... }

// 4. MVC（第4章）：RESTful 端点
//    @RestController @RequestMapping("/orders")
//    public class OrderController {
//        @PostMapping public Order create(@RequestBody Order o) { return service.create(o); }
//    }

// 5. 数据访问（第5章）：只写接口
//    public interface OrderRepo extends JpaRepository<Order, Long> {
//        List<Order> findByUserId(Long userId);  // 方法名派生查询
//    }

// 6. 安全（第6章）：认证授权
//    @PreAuthorize("hasRole('USER')")
//    public Order createOrder(Order o) { ... }

// 7. Boot（第7章）：自动配置 + 起步依赖
//    <dependency>spring-boot-starter-web</dependency>  // 一个依赖搞定MVC+Tomcat+Jackson

// 8. Cloud（第8章）：微服务治理
//    @FeignClient(name = "user-service")  // 声明式调用远程服务
//    public interface UserClient { @GetMapping("/users/{id}") User get(@PathVariable Long id); }
```

## 常见误区

<Callout type="trap">
**误区：会用 Spring 注解就等于懂 Spring。** 能写出 `@Autowired`、`@RestController` 只是「会用注解」——照着文档抄就能做。真正懂 Spring 的人能解释：为什么控制反转能实现松耦合（对象不再自己 new 依赖，而是由容器注入，依赖可替换）、为什么构造器注入优于字段注入（不可变、可在编译期暴露循环依赖、便于单元测试）、为什么 AOP 用运行时代理而非编译期织入（Spring 选择 JDK 动态代理或 CGLIB，非侵入式）、为什么 Spring Data JPA 只写接口就能查询（运行时动态代理根据方法名生成 JPQL）、为什么 Spring Boot 能自动配置（@ConditionalOnClass 根据类路径条件化装配 Bean）。把 Spring 当黑盒的人遇到 Bean 注入失败只会删注解重试；懂 Spring 的人知道检查组件扫描路径、作用域、条件装配。区分标志：能否解释「Spring 为什么这样设计」而非只是「能跑起来」。
</Callout>

<Exercises>
**问题 1**：全书四阶段递进是什么？为什么是这个顺序？

<Answer>
核心与装配 → Web与切面 → 数据与安全 → 云原生 → 全书复习。顺序由依赖关系决定：先掌握对象怎么创建和装配（IoC 和 Bean 装配是所有 Spring 应用的地基），再学习请求怎么流转和横切关注点怎么分离（MVC 和 AOP 在容器之上处理 Web 和切面）；然后掌握数据怎么持久化和访问怎么控制（数据访问和安全是生产级应用的标配），最后解决配置自动化和服务治理（Boot 和 Cloud 是云原生时代的工程化保障）。先「组装对象」，再「处理请求」，然后「持久化与安全」，最后「云原生」。
</Answer>

**问题 2**：用「一个电商订单系统」描述全书主线。

<Answer>
一个电商订单系统经过全书多个知识点：①核心IoC（第1章）——OrderService 由容器管理，依赖通过构造器注入，不自己 new；②Bean装配（第2章）——@SpringBootApplication 启动组件扫描，@Service/@Repository/@Controller 自动注册为 Bean；③AOP（第3章）——@Transactional 声明式事务，AOP 织入开启/提交/回滚逻辑，业务方法不写事务代码；④MVC（第4章）——OrderController 用 @PostMapping 接收请求，DispatcherServlet 调度到控制器返回 JSON；⑤数据访问（第5章）——OrderRepo extends JpaRepository，findByUserId 方法名派生查询零 SQL；⑥安全（第6章）——@PreAuthorize("hasRole('USER')") 控制只有登录用户能下单，BCrypt 哈希存储密码；⑦Boot（第7章）——spring-boot-starter-web 一个依赖搞定 MVC+Tomcat，application.yml 外部化配置；⑧Cloud（第8章）——@FeignClient 声明式调用 user-service，熔断器防止级联故障。一个系统，全书知识点全部参与。
</Answer>

<Glossary>
<GlossaryItem term="核心理念">Spring 的核心是控制反转（IoC）——把对象创建和依赖管理的权力从业务代码「反转」给容器。开发者只声明需要什么（@Autowired），容器负责创建和注入，实现松耦合。</GlossaryItem>
<GlossaryItem term="四阶段递进">核心与装配 → Web与切面 → 数据与安全 → 云原生 → 全书复习。每层解决前一层的遗留问题：IoC 解决「对象怎么来」，AOP/MVC 解决「请求和切面怎么处理」，数据/安全解决「持久化和访问控制」，Boot/Cloud 解决「工程化和分布式治理」。</GlossaryItem>
<GlossaryItem term="容器">Spring IoC 容器（ApplicationContext），负责实例化、配置、装配 Bean，并管理其完整生命周期。是整个 Spring 框架的核心——所有功能都建立在容器之上。</GlossaryItem>
<GlossaryItem term="Spring生态">以 Spring 框架为核心的技术体系：Spring Framework（核心）、Spring Boot（自动配置）、Spring Security（安全）、Spring Data（数据访问）、Spring Cloud（微服务）等子项目协同覆盖企业级开发全场景。</GlossaryItem>
</Glossary>
