## 控制反转：谁掌管对象

<Term def="控制反转（IoC）是把对象创建和依赖查找的权力从业务代码「反转」给容器——对象不再自己 new 依赖，而是被动接收容器注入的依赖。">控制反转</Term>是 Spring 的地基。传统方式中，对象自己创建依赖（`new`），导致紧耦合——换个实现就要改源码。IoC 把这个权力交给容器：你只声明「我需要 B」，容器负责创建 B 并注入。

<SiaSpringCoreDiagram />

```java
// 传统方式：紧耦合——改依赖 = 改源码
public class OrderService {
    private MysqlOrderRepo repo = new MysqlOrderRepo();  // 写死实现
    // 换成 PostgreSQL？必须改这行代码
}

// IoC方式：松耦合——容器注入，可替换
public class OrderService {
    private final OrderRepo repo;  // 依赖接口，不关心实现
    public OrderService(OrderRepo repo) {  // 容器注入
        this.repo = repo;
    }
    // 测试时注入 mock，生产注入真实实现，源码不动
}
```

## Bean 生命周期

容器对 Bean 的管理分四阶段。理解生命周期才能用好 `@PostConstruct`、`BeanPostProcessor` 等扩展点。

```java
// 1. 实例化：容器通过反射调用构造器创建对象
//    OrderService obj = OrderService.class.getDeclaredConstructor().newInstance();

// 2. 属性填充：容器注入依赖和配置值
public class OrderService {
    @Autowired
    private OrderRepo repo;        // 容器在此阶段注入
    @Value("${order.timeout:30}")
    private int timeout;           // 注入配置值
}

// 3. 初始化：自定义初始化逻辑
public class OrderService {
    @PostConstruct                  // 属性填充后、Bean 就绪前调用
    public void init() {
        // 加载缓存、校验配置、建立连接
    }
    // BeanPostProcessor 的 postProcessBeforeInitialization / postProcessAfterInitialization 也在此阶段
}

// 4. 销毁：容器关闭时回调
public class OrderService {
    @PreDestroy                     // 容器关闭前调用
    public void cleanup() {
        // 释放资源、关闭连接
    }
}
```

## 三种注入方式

<Callout type="trap">
**误区：字段注入最简洁所以最好用。** 字段注入（`@Autowired private B b;`）看似简洁，实则危害大：①无法声明 final——对象不不可变，线程安全隐患；②脱离容器无法测试——单元测试必须用反射或 Spring 容器才能注入 mock，违反可测试性；③隐藏依赖——不看源码不知道依赖什么。构造器注入才是推荐方式：强制声明依赖、保证不可变、脱离容器也能 new。Spring 4.3+ 单构造器的 Bean 自动注入，连 @Autowired 都不用写。
</Callout>

```java
// 1. 构造器注入（推荐）——不可变、可测试、循环依赖早暴露
@Service
public class OrderService {
    private final OrderRepo repo;     // final: 初始化后不可变
    private final UserClient client;
    // 单构造器自动注入，不需要 @Autowired
    public OrderService(OrderRepo repo, UserClient client) {
        this.repo = repo;
        this.client = client;
    }
}
// 单元测试：new OrderService(mockRepo, mockClient)  // 无需容器

// 2. Setter注入——可选依赖、可重新注入
@Service
public class ReportService {
    private EmailSender sender;       // 非 final
    @Autowired(required = false)      // 可选：没有也能跑
    public void setSender(EmailSender sender) { this.sender = sender; }
}

// 3. 字段注入（不推荐）——简洁但不不可变、难测试
@Service
public class OrderService {
    @Autowired                        // 看似简洁
    private OrderRepo repo;           // 非 final，脱离容器无法注入
}
```

## 循环依赖

构造器注入会暴露循环依赖（A 依赖 B，B 依赖 A），Spring 默认报错——这是优点而非缺点，因为它强迫你重新设计。Spring 通过「三级缓存」支持单例 setter 注入的循环依赖，但构造器注入的循环依赖无法解决。

```java
// 循环依赖：A 构造时需要 B，B 构造时需要 A——死锁
@Service
public class A {
    public A(B b) { }  // 构造A需要先构造B
}
@Service
public class B {
    public B(A a) { }  // 构造B需要先构造A——死循环
}
// Spring 启动报错：Requested bean is currently in creation
// 解决：重构设计，或其中一方改用 setter 注入（不推荐掩盖设计问题）
```

<Exercises>
**问题 1**：控制反转（IoC）和依赖注入（DI）是什么关系？IoC 解决了什么问题？

<Answer>
IoC 是思想，DI 是实现。IoC（控制反转）指把对象创建和依赖查找的控制权从业务代码「反转」给容器——对象不再主动 new 依赖，而是被动等待容器注入。DI（依赖注入）是 IoC 的具体实现方式：容器通过构造器、setter 或字段把依赖「注入」到对象中。IoC 解决的核心问题是紧耦合：传统方式中对象自己 new 依赖，换实现就要改源码；IoC 让对象只依赖接口，由容器注入具体实现，实现了「面向接口编程」的松耦合——生产注入真实实现，测试注入 mock，源码不动。
</Answer>

**问题 2**：为什么构造器注入优于字段注入？至少说出三点。

<Answer>
三点优势：①不可变性——构造器注入可以声明 `final` 字段，对象初始化后依赖不可变，线程安全且防止意外修改；②可测试性——脱离 Spring 容器也能用 `new OrderService(mockRepo, mockClient)` 构造对象进行单元测试，不需要反射或启动容器；③依赖显式——构造器参数列表明确声明了所有必需依赖，不看字段注解就知道这个类依赖什么。此外，构造器注入还能在启动时暴露循环依赖（A 依赖 B、B 依赖 A 会直接报错），强迫开发者重新设计，而非用 setter 注入掩盖问题。Spring 4.3+ 单构造器 Bean 自动注入，连 @Autowired 都不用写，简洁性不输字段注入。
</Answer>

**问题 3**：Bean 生命周期的四个阶段是什么？每个阶段容器做什么？

<Answer>
四阶段：①实例化——容器通过反射调用构造器创建 Bean 对象（此时只是空对象，依赖未注入）；②属性填充——容器根据 @Autowired/@Value 注入依赖和配置值（此时依赖可用）；③初始化——依次调用 @PostConstruct、BeanPostProcessor 的前后处理、InitializingBean.afterPropertiesSet、自定义 init-method（此时 Bean 完全就绪，可做缓存加载等初始化）；④销毁——容器关闭时依次调用 @PreDestroy、DisposableBean.destroy、自定义 destroy-method（释放资源、关闭连接）。关键扩展点：BeanPostProcessor 在初始化前后介入，Spring AOP 的代理对象就是在此阶段替换原始 Bean 的。
</Answer>
</Exercises>

<GlossaryItem term="控制反转IoC">把对象创建和依赖管理的控制权从业务代码「反转」给容器。对象不再主动 new 依赖，而是被动接收容器注入，实现松耦合。IoC 是思想，DI（依赖注入）是其实现。</GlossaryItem>
<GlossaryItem term="依赖注入DI">容器通过构造器、setter 或字段把依赖对象注入到目标对象。三种方式中构造器注入最推荐：保证不可变、可测试、依赖显式。</GlossaryItem>
<GlossaryItem term="ApplicationContext">Spring IoC 容器的核心接口，负责实例化、配置、装配 Bean 并管理其完整生命周期。它是 BeanFactory 的超集，增加了事件发布、国际化、资源加载等企业级功能。</GlossaryItem>
<GlossaryItem term="Bean生命周期">Bean 从创建到销毁的四阶段：实例化（反射创建）→ 属性填充（注入依赖）→ 初始化（@PostConstruct 等回调）→ 销毁（@PreDestroy 等回调）。BeanPostProcessor 在初始化前后介入，是 AOP 代理的入口。</GlossaryItem>
