## 横切关注点

<Term def="横切关注点是跨越多个模块的功能（日志、事务、安全、缓存），如果不抽成切面就会散布在每个业务方法里，导致代码纠缠、难以维护。">横切关注点</Term>是 AOP 要解决的问题。没有 AOP 时，日志、事务、安全这些代码会复制粘贴到每个业务方法，改一处要改几十处。

<SiaAopDiagram />

```java
// 无AOP：日志、事务纠缠在业务代码里
public class OrderService {
    public Order create(Order o) {
        Logger.info("开始创建订单");           // 日志纠缠
        Transaction.begin();                   // 事务纠缠
        try {
            // ... 业务逻辑（真正的核心只有这几行）
            Order saved = repo.save(o);
            Transaction.commit();
            Logger.info("创建订单成功");
            return saved;
        } catch (Exception e) {
            Transaction.rollback();            // 事务纠缠
            Logger.error("创建订单失败", e);    // 日志纠缠
            throw e;
        }
    }
    // 每个方法都重复这套样板——改日志格式要改几十处
}

// 有AOP：业务方法只写业务
@Transactional    // 声明式事务（AOP织入 begin/commit/rollback）
public Order create(Order o) {
    return repo.save(o);   // 只有业务逻辑
}
```

## 核心概念

```java
// 切面：封装横切关注点的类
@Aspect
@Component
public class LoggingAspect {

    // 切点：定义「在哪些方法上」生效（execution 表达式）
    @Pointcut("execution(* com.app.service.*.*(..))")
    public void serviceMethods() {}   // 切点签名方法，方法体为空

    // 通知 + 切点：定义「做什么」+「在哪做」
    @Before("serviceMethods()")       // 在切点方法执行前
    public void logBefore(JoinPoint jp) {
        log.info("调用: {}", jp.getSignature());
    }

    @Around("serviceMethods()")       // 环绕：可控制是否执行目标
    public Object time(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = pjp.proceed();  // 执行目标方法
        log.info("耗时: {}ms", System.currentTimeMillis() - start);
        return result;
    }

    @AfterReturning(pointcut = "serviceMethods()", returning = "ret")
    public void logReturn(Object ret) {     // 拿到返回值
        log.info("返回: {}", ret);
    }

    @AfterThrowing(pointcut = "serviceMethods()", throwing = "ex")
    public void logThrow(Exception ex) {    // 拿到异常
        log.error("异常: {}", ex.getMessage());
    }
}
```

## 五种通知时序

```java
@Aspect
public class OrderAspect {
    // @Before：目标方法前执行——做参数校验、权限检查
    @Before("execution(* OrderService.create(..)) && args(order)")
    public void validate(Order order) {
        if (order.getAmount() <= 0) throw new IllegalArgumentException();
    }

    // @After：目标方法后执行（无论成功失败）——类似 finally，做资源清理
    @After("execution(* OrderService.create(..))")
    public void cleanup() { /* 清理线程上下文 */ }

    // @AfterReturning：正常返回后执行——可拿到返回值做后处理
    @AfterReturning(pointcut = "execution(* OrderService.create(..))", returning = "result")
    public void afterReturn(Order result) { /* 发通知 */ }

    // @AfterThrowing：抛异常后执行——可拿到异常做告警
    @AfterThrowing(pointcut = "execution(* OrderService.create(..))", throwing = "ex")
    public void alert(Exception ex) { /* 发告警 */ }

    // @Around：环绕——最强大，可控制是否执行、修改参数、修改返回值、吞异常
    @Around("execution(* OrderService.create(..))")
    public Object around(ProceedingJoinPoint pjp) throws Throwable {
        // 前置逻辑
        Object result = pjp.proceed();      // 执行目标（可传新参数 pjp.proceed(newArgs)）
        // 后置逻辑
        return modifiedResult;               // 可修改返回值
        // 也可 try-catch 吞掉异常
    }
}
```

## 织入与代理

<Callout type="trap">
**误区：Spring AOP 是编译期织入。** Spring AOP 用运行时代理——容器在初始化阶段（BeanPostProcessor）为目标 Bean 创建代理对象，调用方拿到的是代理而非原始对象。两种代理：JDK 动态代理（目标类实现接口时，基于接口生成代理）和 CGLIB（目标类无接口时，生成子类代理）。Spring 默认有接口用 JDK 代理。这带来一个限制：类内部方法自调用（this.xxx()）不经过代理，AOP 失效——因为 this 指向原始对象而非代理。解决：注入自身代理或用 AopContext.currentProxy()。
</Callout>

```java
// 代理失效场景：内部调用不经过代理
@Service
public class OrderService {
    @Transactional
    public void methodA() {
        // 业务
        this.methodB();   // 自调用：this 是原始对象，不是代理 → @Transactional 失效！
    }
    @Transactional
    public void methodB() { /* 不会在新事务里 */ }
}

// 解决一：注入自身代理
@Service
public class OrderService {
    @Autowired
    private OrderService self;   // 注入的是代理对象
    public void methodA() {
        self.methodB();           // 经过代理 → @Transactional 生效
    }
}

// 解决二：AopContext（需开启 exposeProxy=true）
public void methodA() {
    ((OrderService) AopContext.currentProxy()).methodB();
}
```

## 声明式事务

事务管理是 AOP 最典型的应用——`@Transactional` 让事务逻辑从业务代码剥离。

```java
@Service
public class OrderService {
    @Transactional   // AOP 织入：开启事务 → 执行业务 → 提交/回滚
    public Order create(Order o) {
        repo.save(o);
        inventoryService.deduct(o.getItemId());  // 同一事务内
        return o;   // 正常返回 → 提交；抛 RuntimeException → 回滚
    }

    @Transactional(rollbackFor = Exception.class)  // 受检异常也回滚（默认只回滚 RuntimeException）
    public void update(Order o) throws IOException { ... }

    @Transactional(propagation = Propagation.REQUIRES_NEW)  // 新开事务（挂起当前）
    public void audit(Order o) { ... }

    @Transactional(readOnly = true)   // 只读事务（优化）
    public Order find(Long id) { return repo.findById(id); }
}
```

<Exercises>
**问题 1**：AOP 的五个核心概念是什么？它们如何协作？

<Answer>
五个概念：①切面（Aspect）——封装横切关注点的类，用 @Aspect 标注；②切点（Pointcut）——定义「在哪些方法上生效」，用 execution 表达式匹配，如 `execution(* com.app.service.*.*(..))`；③通知（Advice）——定义「做什么」及「何时做」，五种类型（@Before/@After/@Around/@AfterReturning/@AfterThrowing）；④连接点（JoinPoint）——程序执行中可织入的一个点，Spring 仅支持方法级连接点（方法执行的那一刻）；⑤织入（Weaving）——把切面应用到目标对象创建代理的过程，Spring 用运行时代理。协作关系：切面 = 切点 + 通知，切点定位「在哪」，通知定义「做什么」，织入在运行时通过代理把通知插入到切点匹配的方法调用前后。
</Answer>

**问题 2**：@Around 通知为什么最强大？它和 @Before/@After 有什么区别？

<Answer>
@Around 最强大因为它完全包裹目标方法，可以控制：①是否执行目标——调用 pjp.proceed() 才执行，不调用则跳过；②修改参数——pjp.proceed(newArgs) 传入新参数；③修改返回值——proceed() 后可替换返回结果；④吞掉异常——try-catch 后不重抛，调用方感知不到异常；⑤前后都做逻辑——兼具 @Before 和 @After 的能力。区别：@Before/@After 只能在固定的时机做副作用，无法控制目标执行、无法改参数和返回值；@Around 等价于「手写代理方法」。代价是 @Around 最复杂，容易写错（忘记 proceed() 会导致目标不执行）。实践中简单的日志/计时用 @Around，只读前置检查用 @Before，后置清理用 @After，只有需要控制执行流程时才用 @Around。
</Answer>

**问题 3**：为什么 Spring AOP 的内部方法自调用会失效？怎么解决？

<Answer>
原因：Spring AOP 用运行时代理织入。容器为 Bean 创建代理对象，外部调用经过代理（代理执行通知 → 调用目标方法）；但方法内部用 `this.xxx()` 调用，this 指向原始对象而非代理，所以不经过代理，AOP（包括 @Transactional）失效。解决方式：①注入自身代理——`@Autowired private OrderService self;` 然后用 `self.methodB()`（self 是代理对象）；②AopContext.currentProxy()——`((OrderService) AopContext.currentProxy()).methodB()`，需开启 `@EnableAspectJAutoProxy(exposeProxy=true)`；③重构设计——把要自调用的方法拆到另一个 Bean（推荐，避免自调用本身就是更好的设计）。根本建议：AOP 失效往往说明设计有问题，优先重构而非用 hack 绕过。
</Answer>
</Exercises>

<GlossaryItem term="AOP">面向切面编程，把横切关注点（日志/事务/安全/缓存）从业务代码剥离到切面中。Spring AOP 用运行时代理实现织入，仅支持方法级连接点。</GlossaryItem>
<GlossaryItem term="切面Aspect">封装横切关注点的类，用 @Aspect 标注。由切点（在哪做）+ 通知（做什么）组成。声明式事务 @Transactional 就是一个切面的声明式表达。</GlossaryItem>
<GlossaryItem term="通知Advice">定义「做什么」及「何时做」。五种：@Before（前）、@After（后，无论成败）、@Around（环绕，最强大）、@AfterReturning（正常返回后）、@AfterThrowing（异常后）。</GlossaryItem>
<GlossaryItem term="声明式事务">@Transactional 注解实现的事务管理——AOP 在方法周围织入开启事务/提交/回滚逻辑，业务方法不写事务代码。默认只回滚 RuntimeException，rollbackFor 可扩展。</GlossaryItem>
