## 为什么从“MVC表单绑定与校验台”开始

第2章 开发Web应用不是starter、注解或API清单，而是一条从“request → binding → validation → controller → template”到业务结果的可执行合同。MVC表单绑定与校验台把框架决策和领域结果放在同一时间线，先预测第一处变化，再运行、反证、恢复和复位。

第2章 开发Web应用的单变量实验固定提交、JDK、依赖、输入和外部服务，只改变输入样本或渲染路径；面板中的方向性数字用于比较条件，不冒充真实压测、生产SLA或安全证明。

## 三个必须主动触发的误区

<Callout type="trap" title="框架外观不等于业务证明">第2章 开发Web应用即使能够启动、返回200或创建Repository，也可能存在错误状态、重复副作用、越权、阻塞或不可恢复失败；必须沿“request → binding → validation → controller → template”逐段保存证据。</Callout>

<Callout type="trap" title="章专属失败样本">第2章 开发Web应用主动触发“把实体直接当表单命令、忽略BindingResult顺序，或让模板缓存掩盖开发期变更”，并进一步注入“校验失败仍进入领域写入，或错误消息没有回到对应字段”；若BindingResult、响应状态与写入计数没有变化，先修复观测和边界，不得用最终页面或平均分掩盖。</Callout>

<Callout type="trap" title="迁移编译通过不等于迁移完成">第2章 开发Web应用升级后仍需重放身份、配置、数据、消息、响应式终止、管理暴露和关闭流程中的适用合同；只有原反例继续被拒绝，迁移结论才成立。</Callout>
