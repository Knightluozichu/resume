## 请求处理流程

<Term def="DispatcherServlet 是 Spring MVC 的前端控制器（Front Controller），所有请求先到它，由它调度 HandlerMapping 找控制器、HandlerAdapter 执行控制器、ViewResolver 解析视图。">DispatcherServlet</Term>是整个 MVC 的中枢。

<SiaSpringMvcDiagram />

```text
// 一次 GET /orders/123 的完整旅程

// 1. 客户端 → DispatcherServlet（前端控制器接收所有请求）
// 2. DispatcherServlet → HandlerMapping（查映射：哪个方法处理 /orders/123 GET）
//    HandlerMapping 返回：OrderController.getOrder(123) + 拦截器链
// 3. DispatcherServlet → HandlerAdapter（适配执行控制器方法）
// 4. HandlerAdapter → OrderController.getOrder(123)
//    - @PathVariable Long id 绑定 123
//    - 调用 service.find(123) 返回 Order
// 5. 控制器返回 ResponseEntity<Order>（或 ModelAndView）
// 6. @ResponseBody → HttpMessageConverter（Jackson）将 Order 序列化为 JSON
// 7. DispatcherServlet 写回响应 → 客户端收到 JSON
```

## 控制器与注解

```java
// @RestController = @Controller + @ResponseBody（每个方法返回值直接写响应体）
@RestController
@RequestMapping("/orders")
public class OrderController {

    private final OrderService service;
    public OrderController(OrderService service) { this.service = service; }

    // GET /orders?page=0&size=10
    @GetMapping
    public Page<Order> list(@RequestParam(defaultValue = "0") int page,
                            @RequestParam(defaultValue = "10") int size) {
        return service.list(page, size);
    }

    // GET /orders/123
    @GetMapping("/{id}")
    public Order get(@PathVariable Long id) {
        return service.find(id);   // 找不到抛 ResponseStatusException
    }

    // POST /orders  （@RequestBody 反序列化 JSON → 对象）
    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)   // 返回 201
    public Order create(@Valid @RequestBody OrderDto dto) {
        return service.create(dto);        // @Valid 触发校验
    }

    // PUT /orders/123
    @PutMapping("/{id}")
    public Order update(@PathVariable Long id, @RequestBody OrderDto dto) {
        return service.update(id, dto);
    }

    // DELETE /orders/123
    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)   // 返回 204
    public void delete(@PathVariable Long id) {
        service.delete(id);
    }
}
```

## RESTful 设计

<Callout type="trap">
**误区：把所有操作都用 POST。** 把 GET 查询、PUT 更新、DELETE 删除全塞进 POST /orderAction?action=xxx 是反 RESTful 的。问题：①无法利用 HTTP 语义——GET 应幂等可缓存，DELETE 应幂等，混用 POST 丢失这些保证；②缓存失效——GET 可被 CDN/浏览器缓存，POST 不能；③安全审计困难——日志里看不出操作类型。正确做法：用 HTTP 方法表达操作语义，用 URL 表达资源，用状态码表达结果。GET 查询、POST 新建、PUT 整体更新、PATCH 部分更新、DELETE 删除。
</Callout>

```java
// RESTful：HTTP方法语义化 + 资源名复数 + 状态码

// 查询列表    GET    /orders          → 200 + JSON数组
// 查询单个    GET    /orders/{id}     → 200 + JSON / 404
// 新建        POST   /orders          → 201 + 新建资源 / 400 校验失败
// 整体替换    PUT    /orders/{id}     → 200 / 404
// 部分更新    PATCH  /orders/{id}     → 200 / 404
// 删除        DELETE /orders/{id}     → 204 / 404

// 嵌套资源：GET /orders/{id}/items    → 某订单的明细列表
// 状态码：200 OK / 201 Created / 204 No Content / 400 Bad Request / 404 Not Found / 409 Conflict

// 用 ResponseStatusException 抛状态码
@GetMapping("/{id}")
public Order get(@PathVariable Long id) {
    return service.find(id)
        .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "订单不存在"));
}
```

## 全局异常处理

```java
// @ControllerAdvice：全局异常处理，集中管理所有控制器的异常→响应映射
@RestControllerAdvice   // = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {

    @ExceptionHandler(OrderNotFoundException.class)
    public ResponseEntity<ErrorResult> handleNotFound(OrderNotFoundException ex) {
        return ResponseEntity.status(404).body(new ErrorResult("NOT_FOUND", ex.getMessage()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResult handleValidation(MethodArgumentNotValidException ex) {
        String msg = ex.getBindingResult().getFieldErrors().stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return new ErrorResult("VALIDATION_FAILED", msg);
    }

    @ExceptionHandler(Exception.class)   // 兜底
    public ResponseEntity<ErrorResult> handleAll(Exception ex) {
        log.error("未处理异常", ex);
        return ResponseEntity.status(500).body(new ErrorResult("INTERNAL_ERROR", "服务器错误"));
    }
}

// 统一错误响应格式
public record ErrorResult(String code, String message) {}
```

<Exercises>
**问题 1**：描述 DispatcherServlet 处理一次请求的完整流程。

<Answer>
①客户端发送 HTTP 请求到达 DispatcherServlet（前端控制器，拦截所有请求）；②DispatcherServlet 调用 HandlerMapping 查找处理该请求的控制器方法及拦截器链（根据 URL + HTTP 方法匹配 @RequestMapping）；③DispatcherServlet 调用 HandlerAdapter 适配执行控制器方法（处理参数绑定、@Valid 校验、@ResponseBody 序列化等）；④HandlerAdapter 反射调用控制器方法，@RequestParam/@PathVariable/@RequestBody 完成参数绑定；⑤控制器方法执行业务逻辑返回结果（对象/ResponseEntity/ModelAndView）；⑥若方法有 @ResponseBody，HttpMessageConverter（如 Jackson）将返回值序列化为 JSON/XML 写入响应体；⑦若无 @ResponseBody，ViewResolver 将视图名解析为模板渲染 HTML；⑧DispatcherServlet 将响应写回客户端。整个流程中拦截器在 HandlerMapping 前后介入。
</Answer>

**问题 2**：@RestController 和 @Controller 有什么区别？什么时候用哪个？

<Answer>
@Controller 标记类为控制器，方法返回值默认被 ViewResolver 解析为视图名（渲染 HTML 模板）。@RestController = @Controller + @ResponseBody，每个方法的返回值直接通过 HttpMessageConverter 序列化为 JSON/XML 写入响应体，不经过视图解析。用法：写 RESTful API（返回 JSON）用 @RestController；写传统 MVC（返回 HTML 页面）用 @Controller。混合场景：@Controller 类中，需要返回 JSON 的方法单独加 @ResponseBody。注意：@RestController 的方法返回 String 时，这个 String 是 JSON 文本而非视图名。
</Answer>

**问题 3**：如何设计一个 RESTful 的订单 API？列出端点和状态码。

<Answer>
资源名用复数（/orders），HTTP 方法表达操作：GET /orders（列表，200）、GET /orders/&#123;id&#125;（单个，200 或 404）、POST /orders（新建，201 或 400 校验失败）、PUT /orders/&#123;id&#125;（整体更新，200 或 404）、PATCH /orders/&#123;id&#125;（部分更新，200 或 404）、DELETE /orders/&#123;id&#125;（删除，204 或 404）。嵌套资源：GET /orders/&#123;id&#125;/items（订单明细列表）。状态码：200 OK（成功）、201 Created（新建成功）、204 No Content（删除成功）、400 Bad Request（参数校验失败）、404 Not Found（资源不存在）、409 Conflict（并发冲突）、500 Internal Server Error（服务器异常）。关键原则：URL 表达资源、HTTP 方法表达操作、状态码表达结果、GET 幂等可缓存、POST 不幂等。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="DispatcherServlet">Spring MVC 的前端控制器，接收所有 HTTP 请求并调度 HandlerMapping/HandlerAdapter/ViewResolver 完成请求处理。是 MVC 模式的「中枢」。</GlossaryItem>
<GlossaryItem term="@RestController">@Controller + @ResponseBody 的组合，方法返回值由 HttpMessageConverter（如 Jackson）直接序列化为 JSON 写入响应体，用于构建 RESTful API。</GlossaryItem>
<GlossaryItem term="RESTful">用 HTTP 方法（GET/POST/PUT/PATCH/DELETE）表达操作语义、URL 表达资源、状态码表达结果的设计风格。资源名用复数，GET 幂等可缓存。</GlossaryItem>
<GlossaryItem term="@ControllerAdvice">全局异常处理机制，@ExceptionHandler 集中把异常映射为 HTTP 响应。@RestControllerAdvice 额外加 @ResponseBody。避免每个控制器重复写 try-catch。</GlossaryItem>
</Glossary>
