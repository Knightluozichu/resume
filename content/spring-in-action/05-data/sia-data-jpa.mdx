## Repository 接口

<Term def="Spring Data JPA 让你只定义 Repository 接口（继承 JpaRepository），运行时动态代理自动生成实现——方法名派生查询、分页排序、CRUD 全部开箱即用。">Repository</Term>是 Spring Data JPA 的核心抽象。

<SiaDataJpaDiagram />

```java
// 你只写接口，Spring 运行时生成实现类
public interface OrderRepository extends JpaRepository<Order, Long> {

    // 方法名派生查询——零 SQL
    List<Order> findByUserId(Long userId);

    List<Order> findByStatusAndAmountGreaterThan(OrderStatus status, BigDecimal amount);

    List<Order> findByCreatedAtBetween(LocalDateTime start, LocalDateTime end);

    List<Order> findTop10ByOrderByCreatedAtDesc();   // 最近10条

    // 分页排序——传 Pageable，返回 Page
    Page<Order> findByStatus(OrderStatus status, Pageable pageable);

    // 自定义查询
    @Query("SELECT o FROM Order o WHERE o.user.id = :uid")
    List<Order> findByUser(@Param("uid") Long userId);

    // 原生 SQL
    @Query(value = "SELECT * FROM orders WHERE amount > :amt", nativeQuery = true)
    List<Order> findExpensive(@Param("amt") BigDecimal amount);

    // 修改操作
    @Modifying
    @Query("UPDATE Order o SET o.status = :status WHERE o.id = :id")
    int updateStatus(@Param("id") Long id, @Param("status") OrderStatus status);
}
```

## 实体映射

```java
@Entity
@Table(name = "orders")          // 表名（order 是 SQL 保留字，故用 orders）
public class Order {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "order_no", nullable = false, unique = true, length = 32)
    private String orderNo;

    @Column(precision = 10, scale = 2)
    private BigDecimal amount;    // 精度2位小数

    @Enumerated(EnumType.STRING)  // 枚举存字符串（而非默认的 ordinal）
    private OrderStatus status;

    @CreationTimestamp
    private LocalDateTime createdAt;

    // 多对一：多个订单属于一个用户
    @ManyToOne(fetch = FetchType.LAZY)   // 懒加载（避免 N+1 陷阱要配合 JOIN FETCH）
    @JoinColumn(name = "user_id")
    private User user;

    // 一对多：一个订单有多个明细
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    // 等价构造器 + getter/setter 省略
}
```

## 方法名派生查询

方法名按规则命名，Spring 自动解析为 JPQL。关键词：findBy/readBy/queryBy、And/Or、Between/In/Like/IsNull/True、OrderBy、Top/First、Distinct。

```java
public interface UserRepository extends JpaRepository<User, Long> {

    // 基本字段
    User findByEmail(String email);                          // WHERE email = ?

    // 组合条件
    List<User> findByAgeGreaterThanAndStatus(int age, Status s);
    // WHERE age > ? AND status = ?

    // 范围
    List<User> findByCreatedAtBetween(LocalDateTime a, LocalDateTime b);
    // WHERE created_at BETWEEN ? AND ?

    // 集合
    List<User> findByIdIn(List<Long> ids);                   // WHERE id IN (?)

    // 排序 + 分页
    List<User> findByStatusOrderByCreatedAtDesc(Status s);
    Page<User> findByStatus(Status s, Pageable pageable);

    // 去重 + Top
    List<User> findDistinctByDepartmentNotNull();
    List<User> findTop5ByOrderByScoreDesc();                 // 分数最高的5个

    // 子字符串
    List<User> findByNameContaining(String keyword);         // LIKE %keyword%
    List<User> findByNameStartingWith(String prefix);        // LIKE keyword%
}
```

## 持久化上下文与 N+1

<Callout type="trap">
**误区：JPA 懒加载随便用，关联实体自动加载。** 懒加载（FetchType.LAZY）关联实体只有在真正访问属性时才查数据库。但循环访问关联会导致 N+1 查询——查 1 次主表 + N 次关联表（每行触发一次关联查询）。例如查 100 个订单再访问 `order.getUser().getName()`，产生 101 次 SQL。解决：用 @EntityGraph 或 JOIN FETCH 一次性查出关联。另一个坑：懒加载在 Session 关闭后访问抛 LazyInitializationException——事务边界外访问代理失效。解决：在事务内取数据，或改用 DTO 投影。
</Callout>

```java
// N+1 陷阱
List<Order> orders = orderRepo.findAll();   // 1次SQL查所有订单
for (Order o : orders) {
    System.out.println(o.getUser().getName());  // 每次访问触发1次SQL查user → 100次SQL！
}
// 总计：1 + 100 = 101次查询

// 解决一：JOIN FETCH（JPQL 联表查询）
@Query("SELECT o FROM Order o JOIN FETCH o.user")
List<Order> findAllWithUser();   // 1次SQL联表搞定

// 解决二：@EntityGraph
@EntityGraph(attributePaths = {"user"})
@Query("SELECT o FROM Order o")
List<Order> findAllWithUser();

// 解决三：DTO 投影（只取需要的字段，避免加载整个实体）
interface OrderSummary {
    Long getId();
    String getUserName();
    BigDecimal getAmount();
}
@Query("SELECT o.id AS id, o.user.name AS userName, o.amount AS amount FROM Order o")
List<OrderSummary> findSummaries();
```

## 实体状态

```java
// JPA 实体四种状态
// 1. 新建 new：new 出来，未持久化，不在持久化上下文
Order o = new Order();   // 新建态

// 2. 持久 managed：被 EntityManager 管理，事务提交自动同步到数据库
orderRepo.save(o);       // 持久态：之后修改 o，提交时自动 UPDATE（脏检查）

// 3. 游离 detached：曾经持久化但脱离了 EntityManager
Order found = orderRepo.findById(1L).orElseThrow();
// tx.commit() 后 found 变游离态——再修改不会自动同步

// 4. 删除 removed：标记删除，提交时执行 DELETE
orderRepo.delete(found);

// 脏检查：持久态对象的修改自动同步
Order o = orderRepo.findById(1L).orElseThrow();
o.setStatus(OrderStatus.SHIPPED);   // 不需要调用 save！
// 事务提交时，JPA 对比快照发现 status 变了 → 自动 UPDATE
```

<Exercises>
**问题 1**：Spring Data JPA 为什么只写接口就能实现查询？

<Answer>
Spring Data JPA 在运行时为 Repository 接口生成动态代理实现类。机制：①接口继承 JpaRepository，自动获得 save/findById/findAll/delete 等 CRUD 方法（基类 SimpleJpaRepository 已实现）；②自定义方法按命名约定解析——Spring 解析方法名（如 findByEmailAndAge）拆分成关键字（findBy、Email、And、Age），据此动态构造 JPQL（WHERE email = ? AND age = ?）并生成查询；③@Query 注解的方法直接用提供的 JPQL/原生 SQL；④分页排序通过 Pageable 参数自动拼接 LIMIT/OFFSET/ORDER BY。整个过程在应用启动时由 RepositoryFactorySupport 扫描接口、生成代理、注册为 Bean。开发者只定义契约（接口），实现由框架生成——这就是「Repository 模式」的极致。
</Answer>

**问题 2**：什么是 N+1 查询问题？如何解决？

<Answer>
N+1 问题：查询 N 条主实体（1 次 SQL），再逐条访问其懒加载关联实体（N 次 SQL），共 N+1 次查询。例如查 100 个订单再循环访问 `order.getUser().getName()`，产生 1 + 100 = 101 次 SQL，严重拖慢性能。三种解法：①JOIN FETCH——在 JPQL 中 `JOIN FETCH o.user` 一次性联表查出关联，1 次 SQL 搞定；②@EntityGraph——`@EntityGraph(attributePaths={"user"})` 声明关联预加载，框架自动生成 JOIN；③DTO 投影——只 SELECT 需要的字段构造 DTO，避免加载整个关联实体。根本建议：列表查询场景优先 DTO 投影（只取必要字段），详情查询用 JOIN FETCH。同时警惕懒加载在事务外访问会抛 LazyInitializationException。
</Answer>

**问题 3**：JPA 实体的四种状态是什么？脏检查如何工作？

<Answer>
四种状态：①新建（new/transient）——new 创建未持久化，不在持久化上下文；②持久（managed/persistent）——被 EntityManager 管理，处于事务中，修改自动同步数据库；③游离（detached）——曾持久化但脱离了 EntityManager（事务提交后），修改不自动同步；④删除（removed）——标记为删除，提交时执行 DELETE。脏检查（dirty checking）：持久态对象被加载时 JPA 保存一份快照（snapshot）；事务提交时，JPA 逐个对比当前值与快照，发现变化就自动生成 UPDATE——所以持久态对象修改后不需要显式调用 save()。注意：游离态对象修改后不会自动同步，需要 merge() 重新关联；save() 对新建实体执行 INSERT，对游离实体执行 merge+UPDATE。
</Answer>
