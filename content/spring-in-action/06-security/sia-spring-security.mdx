## 过滤链架构

<Term def="Spring Security 用一条过滤器链（FilterChain）拦截所有请求，每个过滤器负责一个安全关注点（认证、CSRF、CORS、授权），最终放行或拒绝。">过滤链</Term>是 Spring Security 的骨架。请求进入控制器前，必须穿过这条链。

<SiaSpringSecurityDiagram />

```text
// 请求穿过安全过滤链
// 请求 → SecurityContextPersistenceFilter（恢复会话中的认证信息）
//      → UsernamePasswordAuthenticationFilter（处理表单登录认证）
//      → BasicAuthenticationFilter（处理HTTP Basic认证）
//      → ...（其他过滤器：CSRF、CORS、异常翻译）
//      → FilterSecurityInterceptor（授权检查：当前用户有权访问该URL吗？）
//      → 控制器（授权通过才到达）

// 关键：认证失败由 AuthenticationEntryPoint 处理（返回401）
//       授权失败由 AccessDeniedHandler 处理（返回403）
```

## 认证：你是谁

```java
// 配置认证：用户名密码从数据库加载
@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/public/**", "/login").permitAll()   // 公开端点
                .requestMatchers("/admin/**").hasRole("ADMIN")         // 需ADMIN角色
                .anyRequest().authenticated()                          // 其余需登录
            )
            .formLogin(form -> form
                .loginPage("/login")           // 自定义登录页
                .defaultSuccessUrl("/home")
                .permitAll()
            )
            .logout(logout -> logout
                .logoutUrl("/logout")
                .logoutSuccessUrl("/login")
            )
            .csrf(csrf -> csrf.disable());     // REST API 可关 CSRF（用 Token 替代）
        return http.build();
    }

    // 密码编码器：必须用 BCrypt，绝不能明文
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();   // 自适应哈希 + 盐
    }
}

// UserDetailsService：从数据库加载用户
@Service
public class UserDetailsServiceImpl implements UserDetailsService {
    @Autowired private UserRepository userRepo;

    @Override
    public UserDetails loadUserByUsername(String username) {
        User user = userRepo.findByEmail(username)
            .orElseThrow(() -> new UsernameNotFoundException(username));
        return org.springframework.security.core.userdetails.User
            .withUsername(user.getEmail())
            .password(user.getPasswordHash())   // 已 BCrypt 哈希
            .roles(user.getRoles().toArray(String[]::new))
            .build();
    }
}
```

## 授权：你能做什么

```java
// URL级授权（配置类）
.requestMatchers("/api/admin/**").hasRole("ADMIN")
.requestMatchers("/api/user/**").hasAnyRole("USER", "ADMIN")
.requestMatchers("/api/**").authenticated()

// 方法级授权（注解，更细粒度）
@Service
public class OrderService {

    @PreAuthorize("hasRole('USER')")   // 调用前检查
    public Order create(Order o) { ... }

    @PreAuthorize("hasRole('ADMIN') or #o.userId == authentication.principal.id")
    // 只有管理员或订单本人能删除（SpEL表达式访问参数和认证主体）
    public void delete(Order o) { ... }

    @PostAuthorize("returnObject.userId == authentication.principal.id")
    // 调用后检查：返回的订单必须属于当前用户
    public Order find(Long id) { ... }

    @PreAuthorize("hasAuthority('order:read')")   // 基于权限而非角色
    public List<Order> list() { ... }
}
// 启用方法级安全：@EnableMethodSecurity
```

## 密码编码

<Callout type="trap">
**误区：用 MD5 或 SHA 加盐存密码就够了。** MD5/SHA 是哈希算法不是密码算法——它们设计目的是快，而「快」对密码存储是致命的：GPU 每秒能算几十亿次 MD5，加盐也挡不住暴力破解。密码存储必须用「慢哈希」：BCrypt（Spring 默认）、Argon2、PBKDF2。BCrypt 的强度因子让每次哈希都慢（几十到几百毫秒），暴力破解成本高到不可行；且每次哈希自动生成不同盐，同一密码两次哈希结果不同。生产环境绝不能用明文、MD5、SHA 存密码——必须 BCrypt 起步。
</Callout>

```java
// 密码存储演进
// 明文存储      → 泄露即裸奔（绝对禁止）
// MD5/SHA       → 彩虹表+GPU暴力破解（已不安全）
// MD5+盐        → 仍可暴力破解（盐防彩虹表，防不了暴力）
// BCrypt（推荐）→ 自适应慢哈希 + 内置盐，GPU暴力成本极高
// Argon2        → 内存难哈希，抗GPU/ASIC（最强但较新）

// 注册：哈希后存储
public void register(String email, String rawPassword) {
    String hash = encoder.encode(rawPassword);   // BCrypt 自动加盐
    userRepo.save(new User(email, hash));         // 存哈希，绝不存明文
}

// 登录：比对哈希
public boolean login(String email, String rawPassword) {
    User user = userRepo.findByEmail(email).orElseThrow();
    return encoder.matches(rawPassword, user.getPasswordHash());
    // matches 内部从哈希提取盐重新计算比对，不存明文
}

// 平滑迁移旧系统：DelegatingPasswordEncoder
// 旧密码 {md5}xxx 新密码 {bcrypt}xxx，编码器根据前缀选择算法，登录时自动升级到 bcrypt
```

<Exercises>
**问题 1**：认证（Authentication）和授权（Authorization）的区别是什么？

<Answer>
认证回答「你是谁」——验证用户身份，通常通过用户名密码、Token、证书等凭证。认证成功后，用户身份（Principal）和权限（Authorities）存入 SecurityContext。授权回答「你能做什么」——验证已认证用户是否有权执行某操作或访问某资源。授权依赖认证的结果（先认证再授权）。Spring Security 中：认证由 AuthenticationManager → AuthenticationProvider → UserDetailsService 完成；授权由 FilterSecurityInterceptor（URL级）或 @PreAuthorize/@PostAuthorize（方法级）完成。认证失败返回 401 Unauthorized，授权失败返回 403 Forbidden——注意 401 是「未认证」，403 是「已认证但无权限」。
</Answer>

**问题 2**：为什么密码必须用 BCrypt 而不能用 MD5？

<Answer>
MD5/SHA 是通用哈希算法，设计目标是「快」——而快对密码存储是致命的：现代 GPU 每秒能计算几十亿次 MD5，即使加盐（防彩虹表）也挡不住暴力穷举破解。BCrypt 是专为密码存储设计的「慢哈希」：①自适应成本因子——可调强度（默认10），每次哈希耗时几十到几百毫秒，让暴力破解成本高到不可行；②内置盐——每次哈希自动生成随机盐并嵌入结果，同一密码两次哈希结果不同，防彩虹表；③抗GPU——BCrypt 的 key expansion 算法对内存敏感，比 MD5 更难用 GPU 并行加速。Spring Security 默认用 BCryptPasswordEncoder。更强可选 Argon2（内存难哈希，抗 ASIC）。绝不能明文或 MD5 存密码。
</Answer>

**问题 3**：@PreAuthorize 和 @PostAuthorize 有什么区别？举例说明。

<Answer>
@PreAuthorize 在方法执行前检查权限——不满足直接抛 AccessDeniedException，方法不执行。适合做「调用门禁」：如 `@PreAuthorize("hasRole('ADMIN')")` 保证只有管理员能调用。@PostAuthorize 在方法执行后检查——方法已执行，检查不满足则抛异常丢弃返回值。适合做「结果过滤」：如 `@PreAuthorize("hasRole('ADMIN') or #o.userId == authentication.principal.id")` 在删除前检查，而 `@PostAuthorize("returnObject.userId == authentication.principal.id")` 在查询后检查返回的订单是否属于当前用户——防止越权访问他人数据。@PostAuthorize 的代价是方法已执行（可能有副作用），所以查询用 @PostAuthorize 合适，有副作用的写操作应该用 @PreAuthorize 在执行前拦截。两者都用 SpEL 表达式，可访问 #参数名、authentication.principal、returnObject。
</Answer>

<GlossaryItem term="认证Authentication">验证「你是谁」——通过用户名密码/Token 确认用户身份。成功后存入 SecurityContext。失败返回 401。</GlossaryItem>
<GlossaryItem term="授权Authorization">验证「你能做什么」——检查已认证用户是否有权访问资源。URL级用 authorizeHttpRequests，方法级用 @PreAuthorize/@PostAuthorize。失败返回 403。</GlossaryItem>
<GlossaryItem term="BCrypt">专为密码存储设计的慢哈希算法——自适应成本因子（慢即安全）、内置随机盐（防彩虹表）、抗 GPU 并行。Spring Security 默认密码编码器。绝不用 MD5 存密码。</GlossaryItem>
