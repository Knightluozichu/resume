## 为什么从“OAuth2授权码与资源服务器台”开始

第8章 保护REST API不是starter、注解或API清单，而是一条从“client → authorization server → token → resource server”到业务结果的可执行合同。OAuth2授权码与资源服务器台把框架决策和领域结果放在同一时间线，先预测第一处变化，再运行、反证、恢复和复位。

第8章 保护REST API的单变量实验固定提交、JDK、依赖、输入和外部服务，只改变令牌状态或授权范围；面板中的方向性数字用于比较条件，不冒充真实压测、生产SLA或安全证明。

## 三个必须主动触发的误区

<Callout type="trap" title="框架外观不等于业务证明">第8章 保护REST API即使能够启动、返回200或创建Repository，也可能存在错误状态、重复副作用、越权、阻塞或不可恢复失败；必须沿“client → authorization server → token → resource server”逐段保存证据。</Callout>

<Callout type="trap" title="章专属失败样本">第8章 保护REST API主动触发“把OAuth2当登录协议、在资源服务器信任任意签名令牌，或把客户端秘密暴露给公共客户端”，并进一步注入“只验证JWT签名，却忽略issuer、audience、过期时间与scope”；若令牌声明、授权决策与401/403差异没有变化，先修复观测和边界，不得用最终页面或平均分掩盖。</Callout>

<Callout type="trap" title="迁移编译通过不等于迁移完成">第8章 保护REST API升级后仍需重放身份、配置、数据、消息、响应式终止、管理暴露和关闭流程中的适用合同；只有原反例继续被拒绝，迁移结论才成立。</Callout>
