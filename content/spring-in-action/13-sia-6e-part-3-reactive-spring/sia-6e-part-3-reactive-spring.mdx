## 为什么从“背压与取消路径台”开始

Part 3 响应式Spring不是starter、注解或API清单，而是一条从“publisher → operators → subscriber → resource”到业务结果的可执行合同。背压与取消路径台把框架决策和领域结果放在同一时间线，先预测第一处变化，再运行、反证、恢复和复位。

Part 3 响应式Spring的单变量实验固定提交、JDK、依赖、输入和外部服务，只改变需求信号或终止方式；面板中的方向性数字用于比较条件，不冒充真实压测、生产SLA或安全证明。

## 官方目录逐项深读

### Part 3. Reactive Spring

**四级证据 1/1。** Part 3 响应式Spring中的Part 3. Reactive Spring：写出0..1或0..N基数、需求、线程、错误、取消和资源释放，不用异步外观掩盖阻塞调用。在Part 3 响应式Spring中固定终止方式为“错误”，只把需求信号从“零”切到“持续”，用request(n)、线程名与取消清理找到第一项因果变化；该节点的练习断言是“需求量受控传播，错误与取消都会释放连接和订阅资源”。

## 三个必须主动触发的误区

<Callout type="trap" title="框架外观不等于业务证明">Part 3 响应式Spring即使能够启动、返回200或创建Repository，也可能存在错误状态、重复副作用、越权、阻塞或不可恢复失败；必须沿“publisher → operators → subscriber → resource”逐段保存证据。</Callout>

<Callout type="trap" title="章专属失败样本">Part 3 响应式Spring主动触发“只把返回类型改成Mono或Flux，却在驱动、业务处理或观测环节继续阻塞”，并进一步注入“把异步包装误当非阻塞，阻塞调用占满事件循环”；若request(n)、线程名与取消清理没有变化，先修复观测和边界，不得用最终页面或平均分掩盖。</Callout>

<Callout type="trap" title="迁移编译通过不等于迁移完成">Part 3 响应式Spring升级后仍需重放身份、配置、数据、消息、响应式终止、管理暴露和关闭流程中的适用合同；只有原反例继续被拒绝，迁移结论才成立。</Callout>
