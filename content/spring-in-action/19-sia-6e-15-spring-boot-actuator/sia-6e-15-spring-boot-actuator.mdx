## 为什么从“Actuator端点与指标台”开始

第15章 Spring Boot Actuator不是starter、注解或API清单，而是一条从“application state → endpoint/metric → secured exposure”到业务结果的可执行合同。Actuator端点与指标台把框架决策和领域结果放在同一时间线，先预测第一处变化，再运行、反证、恢复和复位。

第15章 Spring Boot Actuator的单变量实验固定提交、JDK、依赖、输入和外部服务，只改变端点暴露或调用身份；面板中的方向性数字用于比较条件，不冒充真实压测、生产SLA或安全证明。

## 三个必须主动触发的误区

<Callout type="trap" title="框架外观不等于业务证明">第15章 Spring Boot Actuator即使能够启动、返回200或创建Repository，也可能存在错误状态、重复副作用、越权、阻塞或不可恢复失败；必须沿“application state → endpoint/metric → secured exposure”逐段保存证据。</Callout>

<Callout type="trap" title="章专属失败样本">第15章 Spring Boot Actuator主动触发“无差别暴露env与heapdump、把依赖存活当业务健康，或注册高基数指标”，并进一步注入“暴露env或heapdump等敏感端点，或用高基数用户ID作为指标标签”；若端点清单、tag基数与授权结果没有变化，先修复观测和边界，不得用最终页面或平均分掩盖。</Callout>

<Callout type="trap" title="迁移编译通过不等于迁移完成">第15章 Spring Boot Actuator升级后仍需重放身份、配置、数据、消息、响应式终止、管理暴露和关闭流程中的适用合同；只有原反例继续被拒绝，迁移结论才成立。</Callout>
