## 知识体系全景

<SqtLearningMapDiagram />

《SQL必知必会》以"从会查到会写复杂查询"为主线，系统讲解SQL语言的核心概念和实用技巧。全书分基础篇、进阶篇、高级篇三个篇章，覆盖从单表查询到多表关联、从简单过滤到窗口函数的完整链路。

## 两条核心主线

### 主线一：数据检索能力

```
// 从查得到到查得准的递进路径
// 基础查询
//   └── SELECT / FROM / WHERE
//   └── DISTINCT / LIMIT
// 过滤与排序
//   └── AND / OR / IN / LIKE
//   └── ORDER BY ASC / DESC
// 聚合与分组
//   └── COUNT / SUM / AVG / MAX / MIN
//   └── GROUP BY / HAVING
// 多表关联
//   └── INNER / LEFT / RIGHT JOIN
//   └── 子查询 / UNION
// 高级查询
//   └── 窗口函数 / CTE / 视图
//
// 核心：查什么 → 怎么过滤 → 怎么排序 → 怎么算 → 怎么连
```

### 主线二：数据处理思维

```
// 从行级到组级到表级的思维跃迁
// 行级思维
//   └── 单行过滤（WHERE）
//   └── 行级计算（函数/计算字段）
// 组级思维
//   └── 分组聚合（GROUP BY）
//   └── 组级过滤（HAVING）
// 表级思维
//   └── 多表关联（JOIN）
//   └── 结果组合（UNION）
// 窗口思维
//   └── 跨行计算（窗口函数）
//   └── 分步拆解（CTE）
//
// 核心：单行 → 分组 → 多表 → 窗口（思维跃迁）
```

<Callout type="info" title="核心认知">
全书两条主线在"聚合+窗口函数"与"联结+子查询"处交汇——聚合函数可以嵌入子查询，窗口函数可以在联结结果上运算。理解这些交汇点，才能从"会写SQL"升级到"会写高效SQL"。
</Callout>

<GlossaryItem term="三篇递进">
全书分基础篇（学习地图/SQL基础/数据过滤）、进阶篇（排序/函数/聚合）、高级篇（联结/子查询/高级SQL/复习）三个篇章。基础篇解决"会查"，进阶篇解决"会算"，高级篇解决"会连"，从入门到复杂查询层层递进。
</GlossaryItem>

<GlossaryItem term="两条主线">
主线一数据检索能力：从SELECT到WHERE到ORDER BY到聚合到联结到子查询到窗口函数，解决"如何查到想要的数据"。主线二数据处理思维：从行级到组级到表级到窗口级，解决"如何用正确的思维方式组织查询"。两条主线在"聚合+窗口函数"与"联结+子查询"处交汇。
</GlossaryItem>

<GlossaryItem term="SELECT执行顺序">
SQL语句的书写顺序与执行顺序不同。书写顺序：`SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`。执行顺序：`FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT`。理解执行顺序是写对SQL的关键。
</GlossaryItem>

<GlossaryItem term="从会查到会写复杂查询">
学习路径：①会查基本数据（SELECT/WHERE）→ ②会排序和计算（ORDER BY/函数）→ ③会汇总统计（聚合/分组）→ ④会多表关联（JOIN/子查询）→ ⑤会写复杂查询（窗口/CTE/视图）。每一步都是下一步的前提。
</GlossaryItem>

<Exercises>

**问题 1**：全书分为哪几个篇章？各自的核心内容和递进逻辑是什么？

<Answer>
全书分三个篇章：基础篇——学习地图（知识体系）、SQL基础与SELECT（数据库概念/SELECT/FROM/WHERE）、数据过滤（WHERE/比较/集合/模式匹配）；进阶篇——排序与计算字段（ORDER BY/计算字段/别名）、函数与数据处理（文本/数值/日期/转换）、聚合与分组（COUNT/SUM/AVG/GROUP BY/HAVING）；高级篇——联结查询（INNER/LEFT/RIGHT JOIN）、子查询与组合查询（标量/列/表子查询/UNION）、高级SQL（窗口函数/CTE/视图）、全书复习。递进逻辑：从会查到会算到会连到会写复杂查询。
</Answer>

**问题 2**：贯穿全书的两条核心主线是什么？它们在哪些章节交汇？

<Answer>
主线一数据检索能力：SELECT → WHERE → ORDER BY → 函数 → 聚合 → 联结 → 子查询 → 窗口函数，解决"如何查到想要的数据"。主线二数据处理思维：行级（WHERE）→ 组级（GROUP BY）→ 表级（JOIN）→ 窗口级（窗口函数），解决"如何用正确思维组织查询"。两条主线在"聚合+窗口函数"（聚合章与高级SQL章）与"联结+子查询"（联结章与子查询章）交汇——聚合函数可嵌入子查询，窗口函数可在联结结果上运算。
</Answer>

**问题 3**：为什么学习SQL要遵循"会查→会算→会连→会写复杂查询"的顺序？

<Answer>
顺序依据：会查——建立SQL基本手感，理解数据如何检索；会算——掌握排序、函数和聚合，在查询基础上做计算；会连——理解多表关系，掌握JOIN和子查询；会写复杂查询——综合运用窗口函数、CTE和视图解决实际问题。跳过基础的风险：①不理解WHERE和执行顺序，写出的查询结果不对；②不掌握聚合和分组，无法做多表统计；③不理解JOIN，无法处理关系型数据。每一步都是下一步的前提。
</Answer>

**问题 4**：SQL语句的书写顺序和执行顺序有什么区别？为什么这个区别很重要？

<Answer>
书写顺序：`SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`。执行顺序：`FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT`。区别的核心在于SELECT在执行时排在WHERE和GROUP BY之后。重要性：①理解了执行顺序才能正确使用别名——WHERE中不能用SELECT定义的别名，因为WHERE先执行；②理解了执行顺序才能正确写聚合查询——HAVING在GROUP BY之后执行所以可以用聚合函数，WHERE不行；③理解了执行顺序才能排查查询逻辑错误。
</Answer>
