## WHERE子句：数据过滤体系

<SqtFilteringDataDiagram />

WHERE是SQL中最重要的子句之一，它决定了"从所有行中选出哪些行"。WHERE在FROM之后、GROUP BY之前执行，只能使用表中的原始列。

## 比较运算符

```
-- 等于 / 不等于
SELECT prod_name, prod_price FROM products WHERE prod_price = 9.49;
SELECT prod_name, prod_price FROM products WHERE prod_price != 9.49;
SELECT prod_name, prod_price FROM products WHERE prod_price <> 9.49;  -- 同 !=

-- 大小比较
SELECT prod_name, prod_price FROM products WHERE prod_price < 10;
SELECT prod_name, prod_price FROM products WHERE prod_price >= 10;

-- 范围查询（BETWEEN 包含边界）
SELECT prod_name, prod_price FROM products WHERE prod_price BETWEEN 5 AND 10;

-- 空值检查（必须用 IS NULL，不能用 = NULL）
SELECT cust_name FROM customers WHERE cust_email IS NULL;
SELECT cust_name FROM customers WHERE cust_email IS NOT NULL;
```

## 集合运算符 IN

```
-- IN：匹配列表中的任意值（等价于多个OR，但更简洁）
SELECT prod_name, vend_id FROM products
WHERE vend_id IN ('DLL01', 'BRS01', 'FNG01');

-- 等价的OR写法（更啰嗦）
SELECT prod_name, vend_id FROM products
WHERE vend_id = 'DLL01' OR vend_id = 'BRS01' OR vend_id = 'FNG01';

-- NOT IN：不在列表中
SELECT prod_name, vend_id FROM products
WHERE vend_id NOT IN ('DLL01', 'BRS01');
```

<Callout type="warning" title="NOT IN 与 NULL 的陷阱">
`NOT IN` 列表中如果包含NULL，会导致整个查询返回空结果！因为 `x NOT IN (a, NULL)` 等价于 `x != a AND x != NULL`，而 `x != NULL` 的结果是UNKNOWN（不是TRUE），所以整个条件永远不为TRUE。使用NOT IN前务必确保列表中无NULL，或改用NOT EXISTS。
</Callout>

## 模式匹配 LIKE

```
-- % 匹配任意数量字符（包括零个）
SELECT prod_name FROM products WHERE prod_name LIKE 'Fish%';    -- 以Fish开头
SELECT prod_name FROM products WHERE prod_name LIKE '%bean%';   -- 包含bean
SELECT prod_name FROM products WHERE prod_name LIKE '%bag';     -- 以bag结尾

-- _ 匹配单个字符
SELECT prod_name FROM products WHERE prod_name LIKE '__ inch teddy bear';  -- 两个字符+空格+inch...

-- NOT LIKE
SELECT prod_name FROM products WHERE prod_name NOT LIKE '%bean%';
```

<Callout type="info" title="通配符使用建议">
①`%`放在开头（如 `LIKE '%abc'`）会导致全表扫描，无法使用索引；②通配符搜索比普通搜索慢，能不用就不用；③注意大小写——某些数据库LIKE区分大小写（MySQL默认不区分）；④如需正则表达式，MySQL支持 `REGEXP` 运算符。
</Callout>

## 逻辑运算符 AND / OR / NOT

```
-- AND：两个条件都满足
SELECT prod_name, prod_price FROM products
WHERE vend_id = 'DLL01' AND prod_price <= 4;

-- OR：满足任一条件
SELECT prod_name, prod_price FROM products
WHERE vend_id = 'DLL01' OR vend_id = 'BRS01';

-- AND 与 OR 混合（注意优先级！）
-- AND 优先级高于 OR，以下两种写法含义不同：
-- 写法1（不加括号，AND先执行）
SELECT prod_name FROM products
WHERE vend_id = 'DLL01' OR vend_id = 'BRS01' AND prod_price >= 10;
-- 等价于：vend_id = 'DLL01' OR (vend_id = 'BRS01' AND prod_price >= 10)

-- 写法2（加括号，明确意图）
SELECT prod_name FROM products
WHERE (vend_id = 'DLL01' OR vend_id = 'BRS01') AND prod_price >= 10;
-- 等价于：(vend_id = 'DLL01' OR vend_id = 'BRS01') AND prod_price >= 10

-- NOT：取反
SELECT prod_name FROM products
WHERE NOT vend_id = 'DLL01' ORDER BY prod_name;
-- 等价于 vend_id != 'DLL01'
```

<Callout type="success" title="最佳实践">
在AND和OR混合使用时，**始终用括号明确优先级**。即使你记得AND优先级更高，加括号也能让SQL更可读，避免歧义和潜在错误。
</Callout>

## NULL的特殊行为

```
-- NULL 不等于任何值，包括它自己
-- 以下查询不会返回 cust_email 为 NULL 的行
SELECT * FROM customers WHERE cust_email != 'test@test.com';  -- NULL行被排除！

-- 正确做法：用 IS NULL / IS NOT NULL
SELECT * FROM customers WHERE cust_email IS NULL;
SELECT * FROM customers WHERE cust_email IS NOT NULL;

-- NULL 参与运算的结果也是 NULL
SELECT 100 + NULL;  -- 结果是 NULL，不是 100
```

<Glossary>

<GlossaryItem term="WHERE">
SQL中用于行级过滤的子句，在FROM之后、GROUP BY之前执行。WHERE只能使用表中的原始列，不能使用SELECT中定义的别名和聚合函数。
</GlossaryItem>

<GlossaryItem term="IN">
集合运算符，用于匹配一组值中的任意一个。`WHERE col IN (v1, v2, v3)` 等价于 `col = v1 OR col = v2 OR col = v3`，但语法更简洁，且与子查询配合使用时更直观。
</GlossaryItem>

<GlossaryItem term="LIKE">
模式匹配运算符，配合通配符使用。`%` 匹配任意数量字符，`_` 匹配单个字符。左通配（`LIKE '%abc'`）会导致全表扫描。MySQL还支持REGEXP进行正则匹配。
</GlossaryItem>

<GlossaryItem term="NULL">
SQL中的特殊值，表示"未知"或"不存在"。NULL不等于任何值（包括它自己），与任何值比较结果为UNKNOWN。必须用IS NULL/IS NOT NULL检测。NULL参与运算结果仍为NULL。NOT IN列表中含NULL会导致查询返回空结果。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：WHERE子句在SELECT执行流程中的位置是什么？为什么WHERE中不能使用SELECT定义的列别名？

<Answer>
WHERE在执行流程中的位置：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。WHERE在FROM之后、SELECT之前执行。不能使用SELECT别名的原因：别名是在SELECT阶段（即WHERE之后）才定义的，WHERE执行时别名还不存在。例如 `SELECT price * 1.1 AS new_price FROM products WHERE new_price > 10` 是错误的，应改为 `WHERE price * 1.1 > 10`。但ORDER BY可以使用别名，因为ORDER BY在SELECT之后执行。
</Answer>

**问题 2**：`NOT IN` 列表中包含NULL会导致什么问题？如何避免？

<Answer>
`NOT IN` 列表中包含NULL会导致整个查询返回空结果。原因：`x NOT IN (a, NULL)` 等价于 `x != a AND x != NULL`，而 `x != NULL` 的结果是UNKNOWN（三值逻辑中UNKNOWN不为TRUE），所以整个AND条件永远不为TRUE，所有行都被排除。避免方法：①使用前确保列表中无NULL值；②改用 `NOT EXISTS` 子查询；③使用 `COALESCE` 将NULL替换为不可能的值。例如 `WHERE col NOT IN (SELECT val FROM t WHERE val IS NOT NULL)`。
</Answer>

**问题 3**：AND和OR的优先级关系是什么？混合使用时应该怎么处理？

<Answer>
AND的优先级高于OR。例如 `WHERE a OR b AND c` 等价于 `WHERE a OR (b AND c)`，而不是 `(a OR b) AND c`。混合使用时的最佳实践是**始终用括号明确优先级**，即使你记得优先级规则，加括号也能：①让SQL更可读，他人无需回忆优先级规则就能理解查询意图；②避免因优先级理解错误导致的逻辑bug；③让查询意图一目了然。
</Answer>

**问题 4**：LIKE通配符 `%` 和 `_` 分别是什么含义？使用时有什么注意事项？

<Answer>
`%` 匹配任意数量字符（包括零个字符），`_` 匹配恰好一个字符。注意事项：①左通配（`LIKE '%abc'`）会导致全表扫描，无法使用索引，应尽量避免；②通配符搜索比普通搜索慢，能用 `=` 或 `IN` 就不要用LIKE；③某些数据库LIKE区分大小写（MySQL默认不区分，但受排序规则影响）；④需要匹配字面量的 `%` 或 `_` 时，需使用ESCAPE子句转义；⑤MySQL支持 `REGEXP` 做更强大的正则匹配。
</Answer>

</Exercises>
