## 全书知识图谱

<SqtFinalReviewDiagram />

全书围绕SQL数据查询，从"会查基本数据"到"会算会排"到"会汇总统计"到"会多表关联"到"会写复杂查询"层层递进。两大主线在"聚合+窗口函数"与"联结+子查询"处交汇。

## 五层能力体系

### 第一层：基础查询

```
// 核心：查什么数据
// SELECT 列 FROM 表
//   └── 指定列：SELECT col1, col2
//   └── 全部列：SELECT *
//   └── 去重：SELECT DISTINCT
//   └── 限制：LIMIT n OFFSET m
// WHERE 条件
//   └── 比较运算：= != < > <= >=
//   └── 范围：BETWEEN...AND
//   └── 集合：IN / NOT IN
//   └── 模式：LIKE '%pattern%'
//   └── 空值：IS NULL / IS NOT NULL
//   └── 逻辑：AND / OR / NOT（用括号明确优先级）
```

### 第二层：数据处理

```
// 核心：怎么排序和计算
// ORDER BY
//   └── ASC升序（默认）/ DESC降序
//   └── 多列排序（DESC只修饰相邻列）
//   └── 可用SELECT别名（最后执行）
// 计算字段
//   └── 拼接：CONCAT(a, b)
//   └── 算术：+ - * /（注意整数除法）
//   └── 别名：AS 别名名
// 函数
//   └── 文本：UPPER / LOWER / SUBSTRING / TRIM
//   └── 数值：ROUND / CEIL / FLOOR / ABS / MOD
//   └── 日期：NOW / YEAR / DATEDIFF / DATE_ADD
//   └── 转换：CAST / COALESCE / CASE WHEN
```

### 第三层：聚合分组

```
// 核心：怎么汇总统计
// 聚合函数：COUNT / SUM / AVG / MAX / MIN
//   └── COUNT(*) 含NULL，COUNT(列) 不含NULL
//   └── 除COUNT(*)外都忽略NULL
// GROUP BY 分组
//   └── SELECT非聚合列必须在GROUP BY中
//   └── 可多列分组
// HAVING 组级过滤
//   └── 可用聚合函数（WHERE不行）
//   └── WHERE过滤行，HAVING过滤组
```

### 第四层：多表关联

```
// 核心：怎么查多表
// JOIN
//   └── INNER JOIN：两表匹配的行（交集）
//   └── LEFT JOIN：左表全部，右表无匹配填NULL
//   └── RIGHT JOIN：右表全部，左表无匹配填NULL
//   └── 自联结：同一张表当两份用
// 子查询
//   └── 标量子查询：单行单列（比较运算）
//   └── 列子查询：单列多行（IN / NOT IN）
//   └── 行子查询：单行多列（多列比较）
//   └── 表子查询：多行多列（FROM派生表）
//   └── EXISTS：存在性检查（不受NULL影响）
// UNION
//   └── UNION去重 / UNION ALL不去重
//   └── 列数相同，类型兼容
```

### 第五层：高级特性

```
// 核心：怎么写复杂查询
// 窗口函数（保留明细+聚合）
//   └── RANK / DENSE_RANK / ROW_NUMBER（排名）
//   └── LAG / LEAD（前后行引用）
//   └── SUM / AVG OVER（累计/移动聚合）
//   └── PARTITION BY 分组 + ORDER BY 排序
// CTE（分步拆解）
//   └── WITH 名称 AS (子查询) 主查询
//   └── 可读性好、可复用、可递归
// 视图（持久化复用）
//   └── CREATE VIEW 名称 AS SELECT ...
//   └── 虚拟表，不存数据，简化接口
```

## SELECT执行顺序（全书核心记忆点）

<Callout type="success" title="永远记住这个顺序">
`FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT`

关键推论：①WHERE不能用SELECT别名（WHERE先执行）；②HAVING能用聚合函数而WHERE不行；③ORDER BY能用SELECT别名（最后执行）；④计算字段在SELECT阶段生成；⑤窗口函数在SELECT阶段执行。
</Callout>

## 常见查询模式

```
-- 模式1：过滤+排序（最基础）
SELECT col1, col2 FROM table WHERE condition ORDER BY col1 DESC;

-- 模式2：分组统计
SELECT dim, COUNT(*) AS cnt, AVG(metric) AS avg_val
FROM table WHERE condition GROUP BY dim HAVING cnt > 5 ORDER BY avg_val DESC;

-- 模式3：多表关联
SELECT a.col, b.col
FROM tableA a
INNER JOIN tableB b ON a.id = b.a_id
WHERE a.status = 'active' ORDER BY a.col;

-- 模式4：子查询过滤
SELECT * FROM products
WHERE prod_id IN (SELECT prod_id FROM orderitems WHERE quantity > 100);

-- 模式5：排名+过滤
SELECT * FROM (
  SELECT *, RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rk
  FROM employees
) t WHERE rk <= 3;

-- 模式6：CTE分步拆解
WITH summary AS (
  SELECT dept, AVG(salary) AS avg_sal FROM employees GROUP BY dept
)
SELECT e.name, s.avg_sal FROM employees e
JOIN summary s ON e.dept = s.dept WHERE e.salary > s.avg_sal;
```

<Glossary>

<GlossaryItem term="五层能力体系">
全书SQL能力分为五层：①基础查询（SELECT/WHERE）——查什么；②数据处理（ORDER BY/函数/计算字段）——怎么排序和算；③聚合分组（COUNT/SUM/GROUP BY/HAVING）——怎么汇总统计；④多表关联（JOIN/子查询/UNION）——怎么查多表；⑤高级特性（窗口函数/CTE/视图）——怎么写复杂查询。每层建立在前一层之上。
</GlossaryItem>

<GlossaryItem term="SELECT执行顺序">
SQL核心记忆点：FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。书写顺序和执行顺序不同，理解这个区别是写对SQL的关键。它决定了别名在哪里可用、聚合函数在哪里可用、计算字段在何时生成。
</GlossaryItem>

<GlossaryItem term="两条主线交汇">
主线一数据检索能力（SELECT→WHERE→ORDER BY→函数→聚合→联结→子查询→窗口）与主线二数据处理思维（行级→组级→表级→窗口级）在"聚合+窗口函数"和"联结+子查询"处交汇。窗口函数可以在联结结果上运算，聚合函数可以嵌入子查询。理解交汇点才能写高效复杂SQL。
</GlossaryItem>

<GlossaryItem term="常见查询模式">
六种核心查询模式：①过滤+排序；②分组统计（WHERE→GROUP BY→HAVING）；③多表关联（JOIN+ON+WHERE）；④子查询过滤（IN/EXISTS）；⑤排名+过滤（窗口函数+外层WHERE）；⑥CTE分步拆解（WITH+JOIN）。掌握这六种模式可以覆盖80%的日常SQL需求。
</GlossaryItem>

**问题 1**：全书SQL能力分为哪五层？每层的核心问题和关键概念是什么？

<Answer>
五层能力体系：①基础查询——核心问题"查什么数据"，关键概念SELECT/FROM/WHERE/DISTINCT/LIMIT、比较/集合/模式匹配/逻辑运算/NULL；②数据处理——核心问题"怎么排序和算"，关键概念ORDER BY ASC/DESC、计算字段/拼接/算术/别名、文本/数值/日期/转换函数；③聚合分组——核心问题"怎么汇总统计"，关键概念COUNT/SUM/AVG/MAX/MIN、GROUP BY、HAVING、WHERE vs HAVING；④多表关联——核心问题"怎么查多表"，关键概念INNER/LEFT/RIGHT JOIN、自联结、标量/列/行/表子查询、EXISTS、UNION/UNION ALL；⑤高级特性——核心问题"怎么写复杂查询"，关键概念窗口函数/RANK/LAG/LEAD、CTE/WITH、视图/CREATE VIEW。
</Answer>

**问题 2**：SELECT的完整执行顺序是什么？给出3个由执行顺序决定的关键规则。

<Answer>
执行顺序：`FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT`。三个关键规则：①WHERE中不能使用SELECT定义的列别名——因为WHERE在SELECT之前执行，别名还未定义。应直接用表达式 `WHERE price*1.1 > 10` 而非 `WHERE new_price > 10`；②HAVING可以使用聚合函数而WHERE不行——因为HAVING在GROUP BY之后执行，此时分组已完成可以用聚合函数。WHERE在分组前执行，还没有分组结果；③ORDER BY可以使用SELECT定义的列别名——因为ORDER BY在SELECT之后执行，别名已经定义。这些规则的根本原因是理解"SQL是声明式语言，你写的是要什么，数据库按自己的执行顺序处理"。
</Answer>

**问题 3**：编写一个复杂SQL：查询2024年每个部门薪资排名前3的员工姓名、薪资和排名。

<Answer>
```sql
SELECT * FROM (
  SELECT name, dept, salary,
    RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS dept_rank
  FROM employees
  WHERE YEAR(hire_date) <= 2024
) ranked
WHERE dept_rank <= 3
ORDER BY dept, dept_rank;
```
分析：①WHERE先过滤出2024年及之前入职的员工；②窗口函数RANK()按dept分组、salary降序排名——PARTITION BY dept实现分组，ORDER BY salary DESC实现组内排序；③外层查询过滤dept_rank <= 3取前三名；④ORDER BY最终排序输出。这个查询综合运用了WHERE过滤、窗口函数排名、子查询（派生表）过滤三个层级的知识，体现了五层能力的综合运用。
</Answer>

**问题 4**：什么是"从行级到组级到表级到窗口级的思维跃迁"？为什么这个思维跃迁对写SQL很重要？

<Answer>
思维跃迁四阶段：①行级思维——WHERE过滤单行、函数处理单行数据、计算字段做行内计算。关注点："这一行应该怎样"；②组级思维——GROUP BY将行分组、聚合函数将多行汇总为一行、HAVING过滤组。关注点："这一组应该怎样"，理解了"多行变一行"；③表级思维——JOIN将多张表的行关联、子查询嵌套查询、UNION合并结果。关注点："多张表的数据如何组合"，理解了"多表变一表"；④窗口级思维——窗口函数在不减少行数的前提下做跨行计算、CTE分步拆解。关注点："行与行之间的关系"，理解了"保留明细同时做聚合"。重要性：每一次思维跃迁都打开了新的查询能力维度。不理解组级思维就写不了统计报表，不理解表级思维就处理不了关系型数据，不理解窗口级思维就做不了排名/累计/对比分析。
</Answer>
