## 子查询与组合查询

<SqtSubqueriesDiagram />

子查询是嵌套在另一个查询中的查询，用于实现"查询的查询"。UNION则用于将多个独立查询的结果合并为一个结果集。

## 子查询的四种返回类型

### 标量子查询（单行单列）

```
-- 用在比较运算符右边
-- 查询价格高于平均价格的产品
SELECT prod_name, prod_price
FROM products
WHERE prod_price > (SELECT AVG(prod_price) FROM products);

-- 查询订单总金额最大的订单号
SELECT order_num, SUM(quantity * item_price) AS total
FROM orderitems
GROUP BY order_num
HAVING SUM(quantity * item_price) = (
    SELECT MAX(total) FROM (
        SELECT SUM(quantity * item_price) AS total
        FROM orderitems GROUP BY order_num
    ) AS t
);
```

### 列子查询（单列多行）

```
-- 配合 IN 使用：返回多个值
-- 查询下过订单的客户
SELECT cust_name FROM customers
WHERE cust_id IN (SELECT DISTINCT cust_id FROM orders);

-- 配合 NOT IN：不在列表中的
-- 查询没下过订单的客户
SELECT cust_name FROM customers
WHERE cust_id NOT IN (SELECT DISTINCT cust_id FROM orders);
-- 注意：子查询结果中不能有NULL，否则NOT IN返回空！
```

### 行子查询（单行多列）

```
-- 多列同时比较
SELECT * FROM employees
WHERE (dept_id, salary) = (
    SELECT dept_id, MAX(salary) FROM employees WHERE dept_id = 3
);
```

### 表子查询（多行多列）

```
-- 用在FROM子句中（派生表）
-- 先聚合再筛选
SELECT dept_avg.dept_id, dept_avg.avg_sal
FROM (
    SELECT dept_id, AVG(salary) AS avg_sal
    FROM employees
    GROUP BY dept_id
) AS dept_avg
WHERE dept_avg.avg_sal > 8000;
-- 注意：派生表必须有别名（AS t）
```

## 子查询的使用位置

```
-- ① WHERE 子句（最常见）
SELECT * FROM products
WHERE vend_id IN (SELECT vend_id FROM vendors WHERE vend_country = 'USA');

-- ② SELECT 子句（标量子查询，作为计算列）
SELECT prod_name,
  (SELECT COUNT(*) FROM orderitems WHERE orderitems.prod_id = products.prod_id) AS order_count
FROM products;
-- 相关子查询：子查询引用了外层查询的列

-- ③ FROM 子句（派生表/表子查询）
SELECT t.dept, t.cnt FROM (
    SELECT dept, COUNT(*) AS cnt FROM employees GROUP BY dept
) AS t WHERE t.cnt > 5;

-- ④ HAVING 子句（组级条件）
SELECT dept, AVG(salary) AS avg_sal
FROM employees
GROUP BY dept
HAVING AVG(salary) > (SELECT AVG(salary) FROM employees);
-- 部门平均薪资高于全公司平均的部门
```

## EXISTS 相关子查询

```
-- EXISTS：判断子查询是否返回行（返回TRUE/FALSE）
-- 查询下过订单的客户名
SELECT cust_name FROM customers c
WHERE EXISTS (
    SELECT 1 FROM orders o
    WHERE o.cust_id = c.cust_id
);

-- NOT EXISTS：没有返回行
-- 查询没下过订单的客户名
SELECT cust_name FROM customers c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o
    WHERE o.cust_id = c.cust_id
);
```

<Callout type="success" title="EXISTS vs IN">
EXISTS和IN经常可以互换，但有区别：①EXISTS找到第一个匹配行就返回TRUE（短路），IN需要收集所有结果再比较；②对于大表，EXISTS通常更快（尤其是外表小、子查询表大的情况）；③NOT EXISTS不受NULL影响，比NOT IN更安全；④EXISTS是相关子查询（引用外层列），IN可以是非相关子查询。
</Callout>

## UNION 组合查询

```
-- UNION：合并多个SELECT结果，自动去重
SELECT cust_name, cust_contact FROM customers WHERE cust_state = 'IL'
UNION
SELECT cust_name, cust_contact FROM customers WHERE cust_state = 'IN'
ORDER BY cust_name;
-- 等价于 WHERE cust_state IN ('IL', 'IN')

-- UNION ALL：合并不去重（性能更好）
SELECT 'customer' AS type, cust_name AS name FROM customers WHERE cust_state = 'IL'
UNION ALL
SELECT 'supplier' AS type, vend_name AS name FROM vendors WHERE vend_state = 'IN'
ORDER BY name;

-- UNION 的典型场景：合并不同表的结构化数据
SELECT prod_id, prod_name, 'product' AS source FROM products
UNION
SELECT vend_id, vend_name, 'vendor' AS source FROM vendors;
```

<Callout type="warning" title="UNION 规则">
①每个SELECT必须返回相同数量的列；②对应列的类型需要兼容（不必完全相同）；③结果列名取自第一个SELECT；④ORDER BY只能出现在最后一条SELECT之后（对整个结果排序）；⑤UNION自动去重（消耗性能），如果确认无重复用UNION ALL更快。
</Callout>

<Glossary>

<GlossaryItem term="子查询">
嵌套在另一个查询中的查询。按返回类型分四种：标量子查询（单行单列，用于比较）、列子查询（单列多行，配合IN）、行子查询（单行多列，多列比较）、表子查询（多行多列，用作FROM派生表）。
</GlossaryItem>

<GlossaryItem term="相关子查询">
子查询中引用了外层查询列的子查询。如 `SELECT ... WHERE EXISTS (SELECT 1 FROM t WHERE t.id = outer.id)`。相关子查询对外层每一行都执行一次子查询。EXISTS通常是相关子查询。非相关子查询只执行一次。
</GlossaryItem>

<GlossaryItem term="EXISTS">
判断子查询是否返回行的运算符，返回TRUE/FALSE。EXISTS找到第一个匹配行就返回（短路），通常比IN更快。NOT EXISTS不受NULL影响，比NOT IN更安全。常用于"存在性检查"场景。
</GlossaryItem>

<GlossaryItem term="UNION">
将多个SELECT结果合并为一个结果集的运算符。UNION自动去重，UNION ALL不去重（性能更好）。要求各SELECT列数相同、列类型兼容、列名取自第一个SELECT。ORDER BY只能出现在最后。典型场景：合并不同表的结构相似数据。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：子查询有哪四种返回类型？分别适合在SQL的什么位置使用？

<Answer>
四种返回类型：①标量子查询（单行单列）——用在比较运算符右边（WHERE/HAVING），如 `WHERE price > (SELECT AVG(price) FROM t)`；②列子查询（单列多行）——配合IN/NOT IN使用，如 `WHERE id IN (SELECT id FROM t)`；③行子查询（单行多列）——多列同时比较，如 `WHERE (a, b) = (SELECT x, y FROM t)`；④表子查询（多行多列）——用在FROM子句中作为派生表，如 `FROM (SELECT ... GROUP BY ...) AS t`，必须给派生表起别名。
</Answer>

**问题 2**：EXISTS和IN在什么场景下可以互换？各自有什么优势？

<Answer>
EXISTS和IN在"判断某值是否在子查询结果中"的场景下可以互换，如 `WHERE id IN (SELECT id FROM t)` 等价于 `WHERE EXISTS (SELECT 1 FROM t WHERE t.id = outer.id)`。EXISTS优势：①找到第一个匹配就返回（短路），大表通常更快；②NOT EXISTS不受NULL影响，比NOT IN更安全；③适合相关子查询。IN优势：①语义更直观；②非相关子查询只执行一次，小结果集更快；③语法更简洁。选择原则：外表小子查询表大用EXISTS，外表大子查询表小用IN，NOT场景统一用NOT EXISTS。
</Answer>

**问题 3**：UNION和UNION ALL有什么区别？什么时候应该用哪个？

<Answer>
UNION自动去重（对结果做DISTINCT），UNION ALL不去重。区别：①性能——UNION ALL更快，因为不需要去重排序；②结果——如果两个SELECT有重复行，UNION只保留一行，UNION ALL全部保留。使用场景：①确定无重复或不需要去重时用UNION ALL（性能优先）；②需要去重时用UNION。最佳实践：默认用UNION ALL，只有明确需要去重时才用UNION。因为去重操作需要排序和比较，代价较大，如果数据本身无重复就白白浪费性能。
</Answer>

**问题 4**：UNION组合查询有哪些规则？ORDER BY应该放在哪里？

<Answer>
UNION规则：①每个SELECT必须返回相同数量的列——列数不匹配会报错；②对应列的类型需要兼容——不必完全相同但需要可隐式转换；③结果列名取自第一个SELECT——后续SELECT的列名被忽略；④不允许对单个SELECT使用ORDER BY——只能在整个UNION结果最后使用一次ORDER BY，对合并后的全部结果排序。ORDER BY应放在最后一条SELECT之后，它作用于整个UNION结果。例如 `SELECT ... UNION SELECT ... ORDER BY name` 中的ORDER BY对两段查询的合并结果排序。
</Answer>
