## 高级SQL：窗口函数 / CTE / 视图

<SqtAdvancedSqlDiagram />

窗口函数、CTE和视图是现代SQL的三大高级特性，分别解决"跨行计算"、"复杂查询拆解"和"查询复用"三个不同维度的问题。

## 窗口函数（Window Functions）

窗口函数在不减少行数的前提下，对一组相关行（"窗口"）进行计算。这是SQL中"既保留明细又做聚合"的唯一方式。

### 排序类窗口函数

```
-- RANK：并列名次跳号（1, 1, 3, 4）
-- DENSE_RANK：并列名次不跳号（1, 1, 2, 3）
-- ROW_NUMBER：连续编号不并列（1, 2, 3, 4）

SELECT name, dept, salary,
  RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rank_num,
  DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS dense_rank,
  ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS row_num
FROM employees;
-- PARTITION BY 分组（类似GROUP BY但不合并行）
-- ORDER BY 决定组内排序

-- 查询每个部门薪资前3名
SELECT * FROM (
  SELECT name, dept, salary,
    RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rk
  FROM employees
) t
WHERE rk <= 3;
```

### 偏移类窗口函数

```
-- LAG：取前N行的值
-- LEAD：取后N行的值

SELECT name, salary,
  LAG(salary, 1) OVER (ORDER BY salary) AS prev_salary,
  LEAD(salary, 1) OVER (ORDER BY salary) AS next_salary,
  salary - LAG(salary, 1) OVER (ORDER BY salary) AS diff
FROM employees;
-- 查看每个人的薪资与前一个人的差值

-- 计算月度环比增长
SELECT month, revenue,
  LAG(revenue, 1) OVER (ORDER BY month) AS prev_month,
  ROUND((revenue - LAG(revenue, 1) OVER (ORDER BY month))
    / LAG(revenue, 1) OVER (ORDER BY month) * 100, 2) AS growth_pct
FROM monthly_sales;
```

### 聚合类窗口函数

```
-- 累计求和 / 移动平均
SELECT date, sales,
  SUM(sales) OVER (ORDER BY date) AS cumulative_sales,  -- 累计总和
  AVG(sales) OVER (ORDER BY date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg  -- 3日移动平均
FROM daily_sales;

-- 每行占总和的百分比
SELECT name, salary,
  salary / SUM(salary) OVER () * 100 AS pct_of_total
FROM employees;
-- OVER() 空括号 = 对全部行做聚合
```

<Callout type="info" title="窗口函数 vs GROUP BY">
GROUP BY将多行合并为一行（聚合后行数减少），窗口函数在保留每一行的同时进行聚合计算（行数不变）。当你需要"既看到明细行又看到聚合值"时（如排名、累计、前后对比），用窗口函数。
</Callout>

## CTE（公用表表达式）

```
-- 基本语法：WITH 名称 AS (子查询) 主查询
WITH dept_stats AS (
    SELECT dept_id, AVG(salary) AS avg_sal, COUNT(*) AS emp_count
    FROM employees
    GROUP BY dept_id
)
SELECT e.name, e.salary, d.avg_sal, d.emp_count,
  CASE WHEN e.salary > d.avg_sal THEN '高于平均' ELSE '低于平均' END AS level
FROM employees AS e
JOIN dept_stats AS d ON e.dept_id = d.dept_id
ORDER BY d.dept_id, e.salary DESC;

-- 多个CTE（分步拆解复杂逻辑）
WITH
high_value_orders AS (
    SELECT order_num, SUM(quantity * item_price) AS total
    FROM orderitems
    GROUP BY order_num
    HAVING SUM(quantity * item_price) > 1000
),
customer_totals AS (
    SELECT o.cust_id, COUNT(*) AS order_count, SUM(h.total) AS total_spent
    FROM high_value_orders h
    JOIN orders o ON h.order_num = o.order_num
    GROUP BY o.cust_id
)
SELECT c.cust_name, ct.order_count, ct.total_spent
FROM customer_totals ct
JOIN customers c ON ct.cust_id = c.cust_id
ORDER BY ct.total_spent DESC;
```

<Callout type="success" title="CTE 的核心优势">
①可读性——给子查询起名字，逻辑分步，像写文章一样写SQL；②可复用——同一CTE可在主查询中多次引用，不用重复写；③可递归——递归CTE可以处理树形/图结构数据（如组织架构）；④临时性——CTE只在当前查询有效，不像视图那样持久化。
</Callout>

## 视图（VIEW）

```
-- 创建视图（虚拟表）
CREATE VIEW product_summary AS
SELECT
    p.prod_id,
    p.prod_name,
    p.prod_price,
    v.vend_name,
    (SELECT COUNT(*) FROM orderitems oi WHERE oi.prod_id = p.prod_id) AS order_count
FROM products p
JOIN vendors v ON p.vend_id = v.vend_id;

-- 使用视图（像表一样查询）
SELECT * FROM product_summary WHERE order_count > 10 ORDER BY prod_price DESC;

-- 视图简化复杂查询
CREATE VIEW customer_orders AS
SELECT c.cust_id, c.cust_name, o.order_num, o.order_date,
       SUM(oi.quantity * oi.item_price) AS total_amount
FROM customers c
JOIN orders o ON c.cust_id = o.cust_id
JOIN orderitems oi ON o.order_num = oi.order_num
GROUP BY c.cust_id, c.cust_name, o.order_num, o.order_date;

-- 查询就变得非常简洁
SELECT * FROM customer_orders WHERE total_amount > 500;
```

<Callout type="warning" title="视图的限制">
①视图不存储数据，每次查询都动态执行底层SQL；②复杂视图可能性能较差——视图嵌套视图时尤其注意；③并非所有视图都可更新（含JOIN、聚合、DISTINCT的视图通常不可更新）；④视图是持久化的数据库对象，需要CREATE权限。
</Callout>

## 三者对比与选择

| 特性 | 窗口函数 | CTE | 视图 |
|------|----------|-----|------|
| 作用 | 跨行计算 | 分步拆解 | 查询复用 |
| 持久性 | 临时 | 临时 | 持久化 |
| 场景 | 排名/累计/前后行 | 复杂查询拆分 | 简化接口/权限控制 |
| 可读性 | 中 | 高 | 高（复用后简单） |
| 性能 | 好 | 好 | 取决于底层查询 |

<Glossary>

<GlossaryItem term="窗口函数">
在不减少行数的前提下对一组相关行（"窗口"）进行计算的函数。语法：`函数名() OVER (PARTITION BY 分组列 ORDER BY 排序列)`。分为排序类（RANK/DENSE_RANK/ROW_NUMBER）、偏移类（LAG/LEAD）、聚合类（SUM/AVG/COUNT OVER）。与GROUP BY的区别：窗口函数保留明细行，GROUP BY合并行。
</GlossaryItem>

<GlossaryItem term="CTE（公用表表达式）">
用WITH子句定义的临时命名查询结果，只在当前SQL语句中有效。语法：`WITH 名称 AS (子查询) 主查询`。优势：可读性好（给子查询命名）、可复用（同一CTE可多次引用）、可递归（处理树形结构）。CTE是临时性的，不像视图那样持久化。
</GlossaryItem>

<GlossaryItem term="视图（VIEW）">
基于SQL查询创建的虚拟表，不实际存储数据，每次查询时动态执行底层SQL。语法：`CREATE VIEW 视图名 AS SELECT ...`。用途：简化复杂查询的复用、提供数据安全（隐藏底层表只暴露视图）、统一数据接口。限制：含JOIN/聚合/DISTINCT的视图通常不可更新。
</GlossaryItem>

<GlossaryItem term="PARTITION BY">
窗口函数中用于分组的子句，类似GROUP BY但不合并行。`OVER (PARTITION BY dept)` 表示按dept分组，在每个组内独立计算窗口函数。配合ORDER BY使用时实现组内排序计算（如每个部门内的薪资排名）。OVER()空括号表示对全部行做计算。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1**：窗口函数和GROUP BY有什么本质区别？什么时候应该用窗口函数？

<Answer>
本质区别：GROUP BY将多行合并为一行（行数减少），窗口函数在保留每一行的同时进行聚合计算（行数不变）。用窗口函数的场景：①排名——每个部门内按薪资排名（RANK/DENSE_RANK/ROW_NUMBER）；②累计计算——累计求和/移动平均；③前后行对比——查看前一行/后一行的值（LAG/LEAD）；④占比计算——每行占总和的百分比。核心判断：需要"既看到明细行又看到聚合值"时用窗口函数，只需要汇总值时用GROUP BY。
</Answer>

**问题 2**：RANK、DENSE_RANK和ROW_NUMBER有什么区别？给出具体例子。

<Answer>
假设有3个薪资为10000的行和1个薪资为8000的行（按薪资降序排）：①RANK——并列名次跳号，3个10000并列第1名，8000是第4名（1, 1, 1, 4）；②DENSE_RANK——并列名次不跳号，3个10000并列第1名，8000是第2名（1, 1, 1, 2）；③ROW_NUMBER——不并列，连续编号（1, 2, 3, 4），即使值相同也给不同编号。选择：需要真实排名（允许跳号）用RANK，需要紧凑排名用DENSE_RANK，需要唯一编号用ROW_NUMBER。
</Answer>

**问题 3**：CTE的核心优势是什么？与子查询和视图相比有什么不同？

<Answer>
CTE核心优势：①可读性——给子查询起名字，逻辑分步，像写文章一样写SQL；②可复用——同一CTE可在主查询中多次引用；③可递归——递归CTE可处理树形/图结构数据。与子查询相比：CTE可读性更好、可被多次引用（子查询只能用一次）。与视图相比：CTE是临时的（只在当前查询有效），视图是持久化的（存储在数据库中）；CTE不需要CREATE权限，视图需要。选择依据：复杂查询一次性使用用CTE，需要反复复用的查询逻辑用视图。
</Answer>

**问题 4**：视图是什么？它有哪些用途和限制？

<Answer>
视图是基于SQL查询创建的虚拟表，不实际存储数据，每次查询时动态执行底层SQL。用途：①简化复杂查询——将多表JOIN和子查询封装为视图，使用者只需 `SELECT * FROM 视图名`；②数据安全——只暴露视图给用户，隐藏底层表结构和敏感列；③统一接口——为应用提供稳定的数据访问层，底层表结构变化时只需改视图。限制：①不存储数据，每次查询都执行底层SQL，复杂视图可能性能差；②含JOIN、聚合、DISTINCT、子查询的视图通常不可更新（不能INSERT/UPDATE/DELETE）；③视图嵌套视图时性能和可维护性会下降；④需要CREATE VIEW权限。
</Answer>
