## 1.1 Algorithms（算法）

需要五类信息：可有零个或多个输入；至少一个输出；每一步具有；经过有限步结束；每一步在所选计算模型中可有效完成。它们共同把“想法”变成可检验对象。

Euclid最大公因数算法是这一契约的标准样本。对正整数$m,n$，反复执行

$$
(m,n)\leftarrow(n,m\bmod n)
$$

直到第二个分量为零，返回第一个分量。正确性的核心是

$$
\gcd(m,n)=\gcd(n,m\bmod n),
$$

因为$m=qn+r$，任意同时整除$m,n$的整数也整除$r$，反向同理。是第二个分量$n$：非零余数严格小于除数，所以它形成递减非负整数列。


```cpp
unsigned gcd(unsigned m, unsigned n) {
    while (n != 0) {
        const unsigned remainder = m % n;
        m = n;
        n = remainder;
    }
    return m;
}
```

代码只是算法的一种表达。实现还要决定零输入、整数宽度和余数约定；测试则要检查返回值同时整除两个输入，并且任何共同因子都不大于它。把“若输入为正整数”遗漏掉，会让规范和实现对`gcd(0,0)`产生未说明分歧。

## 1.2 Mathematical Preliminaries（数学预备）

### 归纳、数与离散求和

算法在第$k$步成立的性质，常通过数学归纳建立。证明结构包括基础情形、归纳假设和从$k$到$k+1$的推导。它与循环不变量紧密对应：初始化证明基础情形，循环体证明保持性，终止条件把不变量转成后置条件。


例如三角和满足

$$
\sum_{k=1}^{n}k=\frac{n(n+1)}{2}.
$$

基础$n=1$成立；假设$n-1$成立，则加上第$n$项得到$(n-1)n/2+n=n(n+1)/2$。这不仅证明公式，也给出三角双循环的精确操作数。


数学预备还包括幂与对数、整数函数、初等数论、排列与阶乘、二项式系数、调和数、Fibonacci数和生成函数。它们不是彼此独立的公式表：排列计数描述状态空间，调和和出现在平均成本，生成函数把序列递推转成代数对象，数论支撑取模与后续随机数分析。

### 渐近表示不是精确计时

若存在常数$c,n_0$使所有$n\ge n_0$满足$0\le f(n)\le c g(n)$，则$f(n)=O(g(n))$。它陈述渐近上界，不等同于精确成本，也不表示每个输入都达到该上界。相应的$\Omega$给下界，$\Theta$给同阶上下界。


实验中的$40n$与$n^2$在$n=40$附近交叉。大规模趋势支持线性算法，小输入则可能由常数决定。工程结论应同时报告精确计数模型、渐近类、输入分布和实际测量，而不是只挑一个最顺眼的符号。


## 1.3 Analysis of an Algorithm（算法分析）

算法分析要先选基本操作。比较模型统计比较次数，RAM模型给常数时间字操作，外存模型统计块传输，TAOCP还使用明确机器上的指令或内存引用。设第$i$类操作执行$m_i$次、单位成本$c_i$，则

$$
T=\sum_i c_i m_i.
$$


把$c_i$与$m_i$分开有两个好处：同一执行轨迹可套用不同机器假设；不同算法也能在同一成本向量下公平比较。若只记录墙钟时间，缓存状态、编译优化和系统噪声会掩盖算法差异；若只记操作数，又可能把一次缓存未命中与一次寄存器加法视为同价。

Euclid算法的余数次数与输入结构有关，最坏族由相邻Fibonacci数形成；三角循环的操作数则由闭式精确决定。分析过程应区分最坏、平均和摊还含义，并写明随机变量来自输入分布还是算法内部随机性。

```ts
type Cost = { remainder: number; compare: number; assign: number };

function gcdWithCost(a: number, b: number) {
  const cost: Cost = { remainder: 0, compare: 0, assign: 0 };
  while (++cost.compare && b !== 0) {
    const r = a % b;
    cost.remainder += 1;
    [a, b] = [b, r];
    cost.assign += 2;
  }
  return { gcd: a, cost };
}
```

## 1.3 MIX and Assembly Language（MIX与汇编语言）

### MIX字与字段

MIX是为算法讲解设计的抽象机器。典型MIX字由一个符号和5个字节组成，每字节通常按6位解释，因此数值幅度提供30位。字段操作可只装入或存储一个字的部分字节，这让表示布局和指令成本直接可见。


不能简单等同于现代32位补码整数。它保留正零和负零的符号语义，字节宽度与字段选择也属于指令定义。移植算法时，应保留算法不变量，同时重新审计依赖符号表示、溢出和字节范围的步骤。

### 指令字段与执行状态

一条MIX指令在一个字中编码地址、索引寄存器、字段规范与操作码。机器状态包含内存、累加器A、扩展寄存器X、索引寄存器、跳转寄存器和条件状态。地址计算、字段抽取和寄存器副作用共同定义一步。


```text
        LDA   VALUE
        ADD   INCREMENT
        STA   VALUE
VALUE   CON   41
INCREMENT CON 1
```

这段伪汇编的抽象结论是`VALUE`增加一，但机器级分析还会数装入、加法、存储和地址访问。高级语言实现若把值保留在寄存器、合并存储或向量化，成本模型会改变；正确性目标不变，性能证据必须更新。


## 1.4 Fundamental Programming Techniques（基本编程技术）

### 子程序：调用与返回是一份协议


把重复算法封装为可调用单元。机器层面必须说明参数放在哪里、哪些寄存器由谁保存、返回地址如何记录、结果放在哪里。递归调用把一份静态返回位置扩展为多个动态帧，因此栈并不是语法装饰，而是控制链接的表示。

### 协程：对称转移与两个继续点


不同于普通子程序的调用者主导结构。生产者产生一个值后暂停，消费者处理后再恢复生产者；双方都需要保存继续点。今日生成器、迭代器、用户态调度和异步状态机都能从这一模型理解，但具体线程安全与异常传播仍由运行时约定决定。

### 解释程序：数据也可以是操作


解释程序读取编码指令，按操作码分派，并更新客体状态。实验的栈机把`PUSH`、`ADD`、`MUL`作为数据读取；正确性需分别描述客体程序计数器、值栈与宿主循环。若分派器越界或栈下溢，应返回明确错误，不能把宿主异常误当客体语义。

### 输入输出：算法边界包括设备


逐记录处理与逐块传输可能有相同的CPU操作数，却有不同I/O次数。若100条记录每块装8条，需要13次设备传输；扩大缓冲区减少传输，却增加内存占用与延迟。外部排序和文件搜索将在后续卷把块成本提升为主要模型。
