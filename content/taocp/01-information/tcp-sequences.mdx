## 从“结果有序”为何仍可能排序错误开始

先预测：输入记录`[(2,A),(1,B),(2,C),(1,D)]`按第一列升序后得到`[(1,D),(1,B),(2,C),(2,A)]`，键已经有序，它是否一定正确？如果接口承诺稳定排序，答案是否定的，因为相等键的原始顺序被破坏。若实现还丢掉一个`2`并复制一个`1`，输出仍可能有序，却不再是输入的排列。

Volume 3 Chapter 5 · Sorting（排序）把验收拆成四件事：键满足目标顺序；输出与输入是同一多重集；相等键在承诺稳定时保持相对顺序；代价模型与数据所在层级相符。内存数组关注比较、移动和缓存，磁盘文件则首先关注顺序I/O、运行段数量与归并趟数。


## 排列的组合性质

把排列的结构与算法成本连接起来。对排列 $a_1,\ldots,a_n$，逆序数定义为：

$$
I(a)=\left|\{(i,j):1\le i\lt j\le n,\ a_i>a_j\}\right|.
$$

相邻交换每次恰好改变一个逆序，因此把排列排成升序至少需要 $I(a)$ 次相邻交换，冒泡与插入移动可以据此精确计数。任意一次换位都会翻转排列奇偶性；这在分析置换循环、排序网络和原地变换时提供廉价不变量。


combinatorial properties of permutations（排列的组合性质）还包括循环分解、上升段、下降段和记录值。自然归并会利用现成有序段，快速排序的划分质量受键排列影响，而置换选择生成的外排运行段长度也可视为输入顺序的统计性质。算法分析不能只假设“随机数组”，还要说明随机的是排列、键分布还是重复键的位置。

### 稳定性是记录语义，不是键语义

允许按次关键字先排、再按主关键字排，从而组合出多字段顺序。稳定性必须作用于记录身份；如果测试只比较键数组，就无法发现相等键被交换。装饰键加原始位置能把任意比较排序变成稳定结果，但会增加空间和比较负担。


## 内部排序：数据能够驻留主存

internal sorting（内部排序）的算法选择由输入规模、初始有序度、重复键、记录移动成本、额外空间与最坏情况保障共同决定。没有单个算法在所有维度上占优。小数组常用插入排序；通用库常把快速划分、堆排序保障和插入收尾组合；需要稳定性时常选归并；整数键范围较小时可选分布方法。

### 插入排序与局部有序度

的循环不变量是前缀已排序且仍包含原前缀的全部记录。移动次数等于被新键跨过的逆序数，所以近乎有序输入成本接近线性。若记录很大，可排序指针或索引，避免反复移动整条记录。


```python
def insertion_sort(records, key):
    for i in range(1, len(records)):
        item = records[i]
        j = i - 1
        while j >= 0 and key(records[j]) > key(item):
            records[j + 1] = records[j]
            j -= 1
        records[j + 1] = item
```

相等时不移动是稳定性的关键。如果循环条件写成“大于等于”，输出仍有序，却会反转部分相等记录。二分查找可以减少定位比较，但元素移动仍可能是平方级，因此它不改变数组插入排序的渐近移动量。

### Shellsort：用间隔序列消除远距离逆序

Shellsort 对每个间隔 $h$ 执行若干条交错子序列的插入排序，最终以 $h=1$ 收尾。早期大间隔让元素一次跨越较远距离，缓解普通插入排序只能逐格移动的问题。间隔序列决定最坏界和实践常数，不能把任意“每次减半”都当作等价选择。


Shellsort 原地且代码短，但通常不稳定。分析时要区分比较次数和移动次数，并固定间隔族；只报告某个随机数据集上的平均时间无法支持跨实现结论。

## 交换、选择与归并

### 快速排序：划分不变量与重复键

是快速排序的核心。二路划分对大量重复键可能产生无效递归，三路划分把小于、等于和大于枢轴的记录分开。随机枢轴或取样只能降低坏划分概率；若 API 需要确定的最坏界，还需递归深度监控并切换算法。


$$
T(n)=T(k)+T(n-k-1)+\Theta(n).
$$

当 $k$ 接近一半时递归深度为对数级；当 $k$ 连续为零或 $n-1$ 时比较量成为平方级。实现证书应记录最大递归深度、划分后区间边界以及等值区间，而不是只检查最后输出。

### 堆排序：明确最坏界的选择排序

最大堆满足父键不小于子键。自底向上建堆从最后一个内部节点开始下沉，虽然单次下沉可达树高，但多数节点靠近叶子，总成本为线性。随后反复把根最大值与末尾交换，并在缩短的堆中恢复不变量，得到 $O(n\log n)$ 最坏时间和常数额外空间。


堆排序通常不稳定，缓存局部性也弱于顺序归并或良好划分的快速排序。它的优势是原地和可预测上界，因此适合作为 introsort 在递归过深时的后备，而不是自动成为所有内存排序的首选。

### 归并排序：稳定地合并有序段

把两个有序段线性合成一个有序段。相等键时先取左段记录即可保持稳定。数组版本常需线性辅助空间，链表版本则可重连节点；自底向上的迭代归并还能避免递归栈。


```ts
function merge(left: Item[], right: Item[]) {
  const output: Item[] = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    if (left[i].key <= right[j].key) output.push(left[i++]);
    else output.push(right[j++]);
  }
  return output.concat(left.slice(i), right.slice(j));
}
```

自然归并先识别输入中的现成单调段，可以让部分有序数据少做几趟。验证归并时要检查每个输入游标只前进不后退、输出长度等于已消费记录数，以及输出尾部不大于所有未消费头部。

## 分布排序：绕开纯比较模型

包括计数排序、桶方法和基数排序。计数排序的时间为 $O(n+K)$，其中 $K$ 是键宇宙大小；当 $K$ 远大于记录数时，清零计数表本身就不可接受。稳定基数排序要求每一位的内部分配保持稳定，否则较低位已建立的顺序会被破坏。


比较排序的 $\Omega(n\log n)$ 下界不约束这些方法，因为它们使用了键结构和随机访问桶这一额外信息。声称“线性排序”时必须同时写出键模型、空间 $K$、位数和分配成本。

## 最优排序：比较决策树与固定网络

optimum sorting（最优排序）先问清“优化什么”：最坏比较次数、平均比较次数、并行深度、交换次数，还是代码规模。对互异键的确定性比较排序，每个输入排列必须到达不同叶子，二叉比较树高度因此至少为：

$$
C_n\ge\left\lceil\log_2(n!)\right\rceil=n\log_2n-(\log_2e)n+O(\log n).
$$


下界只是不可突破的门槛，不说明某个通用算法对小 $n$ 达到精确最优。为固定规模寻找最少比较程序，需要构造或排除具体决策树；平均最优还依赖输入概率。

### 排序网络与零一原则

排序网络由位置固定的比较交换器组成，调度与数据无关，适合并行硬件和无分支执行。零一原则说明：若一个比较器网络能排序所有零一输入，它就能排序任意全序输入。于是验证规模从无限键域降为 $2^n$ 个二进制向量。


网络的比较器总数衡量工作量，层数衡量并行深度，两者的最优结构可能不同。实验只展示四路网络；不能据此把一个小规模最优网络外推为任意规模最优算法。

## 外部排序：优化顺序I/O与归并趟数

external sorting（外部排序）面对的数据超过主存，随机访问代价远高于比较。典型流程先生成尽可能长的有序运行段，再执行多路归并。成本主要由完整读写数据的趟数决定，CPU 上省几个比较通常不如减少一趟磁盘传输重要。

若初始运行段数为 $R$、每次最多归并 $k$ 路，忽略不满组与最终输出策略时，归并趟数和近似传输量为：

$$
p=\left\lceil\log_k R\right\rceil,\qquad \text{I/O bytes}\approx 2Np,
$$

其中 $N$ 是数据总字节数；系数二来自每趟完整读取和写回。这个模型解释了为何更长初始段和更高有效路数能直接减少传输，但实际还需计入首轮写段、最终消费以及缓冲约束。

### 置换选择生成初始运行段

置换选择在内存中维护候选最小记录。输出最小值后读入新记录；若新键不小于刚输出的键，就进入当前运行段，否则冻结到下一段。对随机输入，平均运行段长度常接近内存容量的两倍，但降序输入会退化到接近内存容量。


冻结标记必须与记录同行，运行段切换时再解冻。证书要检查每段内部有序、所有输入恰好出现一次，并报告运行段长度分布；只看段数会隐藏丢记录问题。

### 多路归并与设备调度

多路归并同时维护每个运行段的当前头部，用最小堆或 loser tree 在 $O(\log k)$ 选择下一个记录。增加路数可减少归并趟数，却需要更多输入缓冲并增加每次选择工作。实际系统还要考虑块大小、预读、双缓冲、文件句柄和存储设备并发。


历史磁带算法中的平衡归并、多相归并、级联归并和反向读带，都在设备数量、倒带与空运行段之间权衡。现代磁盘或对象存储介质不同，但“让传输顺序化、减少全量读写趟数”的原则仍然成立。


## 检验矩阵与失败复现

排序测试至少包含空输入、单记录、全相等、已升序、已降序、重复键交错、极端键值和大记录。性质测试可把候选结果与可信参考排序比较，但仍应单独核验稳定身份和多重集频数。快速排序记录深度，插入排序核对逆序移动量，堆排序检查每次缩堆后的堆不变量，外排则模拟短读、空段和非均匀运行段。
