## 从“每个数字出现一样多”为什么仍不随机开始

先预测：序列`010101...`中零和一各占一半，频数完美，却能被下一位必翻转的规则完全预测。Volume 2 Chapter 3 · Random Numbers（随机数）把“边际均匀”“相邻独立”“高维结构”“不可简单预测”分开检验，不把一张直方图当作随机性的证明。

<Term def="用有限内部状态和确定转移规则产生可复现数列，并试图满足指定统计模型的算法。">伪随机数生成器</Term>的输出由初始种子完全决定。可复现是实验优势，不是质量缺陷；真正问题是状态转移是否有足够周期、输出映射是否引入偏差、目标应用所观察的维度是否暴露规律。

## 3.1 Generating Uniform Random Numbers（生成均匀随机数）

### 线性同余方法

线性同余生成器用

$$
X_{n+1}=(aX_n+c)\bmod m,
\qquad
U_n=X_n/m.
$$

状态$X_n$位于有限集合$\{0,\ldots,m-1\}$，故序列必然进入循环。$a$是乘数、$c$是增量、$m$是模数，$X_0$是种子。

<TcpLcgLab />

<Term def="从某状态再次出现开始，到该状态下一次出现之间的输出长度。">周期</Term>不超过$m$。混合同余生成器达到全周期$m$时，参数需满足Hull–Dobell条件：$c$与$m$互素；$a-1$能被$m$的每个素因子整除；若$m$是4的倍数，$a-1$也是4的倍数。

<TcpPeriodLab />

全周期只保证一维状态枚举完整，不保证相邻二元组或更高维元组填满空间。LCG点$(U_n,U_{n+1},\ldots,U_{n+d-1})$落在有限组平行超平面上；参数差时，这种<Term def="线性同余输出在高维空间只落于有限平行格点或超平面上的结构缺陷。">格点结构</Term>非常明显。

<TcpLatticeLab />

```ts
function lcg(seed: number, a: number, c: number, m: number) {
  let state = seed;
  return () => {
    state = (a * state + c) % m;
    return state / m;
  };
}
```

在JavaScript中，大参数乘法可能超出安全整数精度；实现应使用BigInt、受控32位运算或经过验证的分解。代码表达式与数学递推必须处于同一模环。

### Statistical Tests（统计检验）

统计检验从“输出符合某个随机模型”的零假设出发，选择统计量并计算其在零假设下的尾部程度。它能在显著水平下拒绝模型，不能证明生成器“随机”。

频数检验把$N$个样本分入$k$个等概率桶，期望值$E=N/k$，Pearson统计量为

$$
\chi^2=\sum_{i=1}^{k}\frac{(O_i-E)^2}{E}.
$$

<TcpFrequencyTestLab />

样本量太小时期望计数不足，近似分布不可靠；样本极大时微小且应用无关偏差也可能显著。因此应同时报告统计量、自由度、样本量和效应大小，不只报告“通过”。

串行检验把$(U_i,U_{i+\ell})$分入二维桶，检查转移而非单点。一个发生器可能每个一维桶完全均匀，却只走固定少数二元转移。

<TcpSerialTestLab />

游程检验先按阈值把样本变为二值，统计连续相同类别的段数。频数固定时，过少游程意味着聚集，过多游程意味着交替。

<TcpRunsTestLab />

<Term def="把连续输出视为高维点并评估其所在平行超平面间距的线性同余结构检验。">谱检验</Term>直接针对格点几何。测试组合应覆盖应用会使用的维数、位段与采样方式；只检验高位不能说明低位可用于洗牌索引。

<Callout type="trap" title="常见误区：p值大就证明生成器正确">

大p值只表示当前统计量没有发现足够反例。坏生成器可能逃过某个检验，优秀生成器也可能按既定显著水平偶然失败。必须在看结果前规定检验族、样本量和失败策略，避免反复换检验直到“通过”。

</Callout>

## 3.2 Other Types of Random Quantities（其他随机量）

### 数值分布与逆变换

若$U$在$[0,1)$均匀，目标累积分布$F$连续单调，则

$$
X=F^{-1}(U)
$$

服从目标分布。指数分布率参数$\lambda$对应$X=-\ln(1-U)/\lambda$。

<TcpDistributionLab />

数值实现需声明端点：若发生器可能返回1，对数会发散；若返回0，某些分布得到无穷或边界值。使用`log1p(-u)`能改善$u$接近零时的精度。

### 拒绝采样

当逆函数难算时，可从易采样proposal产生候选，并按接受规则保留。单位正方形中的点若落在四分之一圆内就接受，其接受率趋近$\pi/4$。

<TcpRejectionLab />

期望每个接受样本的proposal数是$1/p$。低接受率不仅慢，还可能放大分支与随机数消耗；proposal必须覆盖目标支持集，接受概率也要有正确上界。

### Random Sampling and Shuffling（随机采样与洗牌）

Fisher–Yates从尾部$i=n-1$开始，在$0$到$i$中均匀选$j$并交换。第一个固定到尾部的元素有$n$种等概率选择，剩余递归为$n-1$项均匀排列，因此每个排列概率

$$
\frac1n\cdot\frac1{n-1}\cdots\frac11=\frac1{n!}.
$$

<TcpShuffleLab />

```python
def shuffle(a, random_index):
    for i in range(len(a) - 1, 0, -1):
        j = random_index(i + 1)  # 0 <= j <= i, uniform
        a[i], a[j] = a[j], a[i]
```

常见错误是每轮都在完整$0$到$n-1$中交换；不同排列会由不同数量的交换路径产生，结果不均匀。`random_index(bound)`若通过`word % bound`实现，也要处理模偏差。

未知长度流中保留$k$个均匀样本，reservoir sampling先收前$k$项；第$i$项到来时以$k/i$概率接纳，并均匀替换一个槽。归纳可得处理$i$项后，每个历史元素留在reservoir的概率都是$k/i$。

<TcpReservoirLab />

## 3.3 What Is a Random Sequence?（什么是随机序列）

有限序列总能由“逐字打印它”的程序生成，所以随机性不能只看是否存在确定描述。实践中使用统计模型：某类观察者在预定检验与资源范围内不能区分输出与目标分布。密码用途还要求即使知道算法和过去输出，也难以预测未来输出；普通模拟PRNG未必满足。

<Term def="在给定统计模型、检验族和资源范围内，输出未表现出可利用偏差或依赖的经验性质。">统计随机性</Term>依赖用途。Monte Carlo积分关心估计偏差和方差，洗牌关心排列均匀，模拟关心相关结构，安全token关心预测阻力。一个发生器没有脱离用途的单一“随机分数”。

```ts
type RandomRun = {
  algorithm: string;
  version: string;
  parameters: Record<string, string>;
  seed: string;
  sampleCount: number;
  tests: Array<{ name: string; statistic: number; threshold: number }>;
};
```

<Callout type="trap" title="常见误区：同一个种子不能复现才更随机">

科学计算需要精确重放，种子和算法版本应进入结果元数据。不可复现通常意味着隐藏了熵源、并发顺序或库版本，不代表统计质量更好。生产安全系统可以从系统熵播种，但诊断仍应记录允许记录的版本与上下文。

</Callout>

## 检验矩阵与失败复现

检验计划应从下游消费方式反推。若输出按单个浮点数使用，检查边际分布与端点；若两两组成坐标，加入二维串行与格点检查；若连续取数构造矩阵，检验相应维度的线性结构；若只取低若干位作桶索引，必须直接检验那些位，不能拿完整字高位的结果替代。样本选择、跳步、分流和并行拆分都会形成新的输出过程，原发生器证书不能自动继承。

同一批样本跑很多检验时，偶然小p值的机会随检验数增加。工程门禁应预先规定单项阈值、整体错误率处理、哪些失败允许用独立种子复核，以及复核后如何升级。不能在失败后删除“看起来重复”的检验，也不能持续增加样本直到p值跨过阈值。一个可诊断失败记录至少包含算法与版本、全部参数、种子、样本切片规则、检验实现版本、统计量和阈值。

随机算法本身还需与发生器质量分层。若Monte Carlo估计偏离参考值，先用已知良好流替换发生器，再固定流比较算法；若偏差仍在，问题位于采样变换或估计器。反之，用同一算法替换多个发生器可以定位状态转移或输出映射。这样的交叉实验把“结果不对”拆成可复现假设，而不是把一切归因于运气。
