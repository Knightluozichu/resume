## 从“找到一个”究竟返回什么开始

先预测：有序数组`[2,5,5,5,9]`查询键`5`，接口应该返回任意一个、最左一个、最右一个，还是三个记录的范围？如果键不存在，返回`-1`、插入位置还是最接近键？搜索（searching）的第一步不是选数据结构，而是固定查询语义。

Volume 3 Chapter 6 · Searching 按官方结构展开 sequential searching（顺序搜索）、searching by comparison of keys（按键比较搜索）、digital searching（数字搜索）、hashing（散列）和 retrieval on secondary keys（次关键字检索）。这些方法的区别不只是复杂度：它们要求不同的键模型、维护不同索引不变量，并支持不同的精确、范围、前缀和组合查询。

## 顺序搜索：最弱前提与基线成本

<Term def="顺序搜索按存储顺序逐条比较记录，直到找到满足条件的记录或耗尽输入">顺序搜索</Term>不要求数据有序、不要求随机访问，也无需额外索引，因此是流式输入和小表的可靠基线。若目标位置在零基索引 $i$，成功搜索需比较 $i+1$ 次；失败搜索必须查看全部 $n$ 条记录。

<TcpSequentialSearchLab />

在目标等可能位于任意位置且保证存在时，平均比较次数为：

$$
E[C]=\frac{1+2+\cdots+n}{n}=\frac{n+1}{2}.
$$

哨兵技巧把目标临时放在末端，循环内只比较键，结束后再判断命中的是原记录还是哨兵。它减少的是边界分支，不改变线性增长，也必须在并发或只读数据上谨慎使用。自组织表可把近期命中项前移，以非均匀查询分布换取更低平均成本。

```ts
function sequentialFind<T>(items: T[], target: T) {
  for (let index = 0; index < items.length; index += 1) {
    if (items[index] === target) return index;
  }
  return -1;
}
```

## 按键比较搜索：从有序表到多路树

searching by comparison of keys（按键比较搜索）只通过“小于、等于、大于”获取信息。它可支持范围查询与有序遍历，但最坏比较数受决策树限制。数据静态时，有序数组紧凑且缓存友好；更新频繁时，搜索树把顺序关系分布在节点链接中。

### 二分搜索与半开区间

<Term def="二分搜索在有序随机访问序列中比较中点，并用比较结果排除一半候选区间">二分搜索</Term>最容易出错的不是复杂度，而是边界语义。寻找第一个不小于目标的位置时，用半开区间`[low, high)`，保持答案始终落在该区间：

$$
0\le low\le answer\le high\le n.
$$

<TcpBinarySearchLab />

循环结束时`low == high`，它既可能指向第一个相等键，也可能是合法插入点，甚至等于数组长度。这个定义自然处理空数组、重复键和缺失键；再单独比较该位置是否等于目标，即可得到精确查询。

```python
def lower_bound(values, target):
    low, high = 0, len(values)
    while low < high:
        middle = low + (high - low) // 2
        if values[middle] < target:
            low = middle + 1
        else:
            high = middle
    return low
```

### 二叉搜索树与平衡条件

<Term def="二叉搜索树使每个节点左子树键较小、右子树键较大，查询沿一条根到叶路径进行">二叉搜索树</Term>的查询成本为树高。随机插入常有对数平均高度，但已排序插入可退化成链；因此“树搜索是 $O(\log n)$”只有在平衡条件成立时才正确。

<TcpBstSearchLab />

AVL、红黑树等结构用高度或颜色约束限制最长路径。旋转只改变局部父子关系，必须同时保持中序键序、修复元数据并正确连接原父节点。删除比插入更容易暴露遗漏，因为高度亏损可能向根传播。

<TcpBalancedTreeLab />

$$
h_{\mathrm{balanced}}=\Theta(\log n),\qquad h_{\mathrm{unbalanced}}\le n-1.
$$

验证树索引要递归检查键范围、父子链接、节点计数和平衡元数据，而不能只对若干键做成功查询；同一个结构错误可能暂时不影响现有查询路径。

### 多路搜索树与块访问

<Term def="多路搜索树在一个节点保存多个分隔键和多个子指针，使每次块读取排除更大的键区间">多路搜索树</Term>把节点尺寸匹配存储块。B树的所有叶处于同一深度，节点保持规定占用率；分裂与合并维持这些约束。高扇出使十亿记录只需少量随机块读取，这比把二叉树的底数藏在大O符号后更有解释力。

<TcpBTreeFanoutLab />

B+树通常把完整记录或记录指针集中在叶层，并链接叶节点以支持范围扫描；内部节点只承担导航。精确查询、范围查询和顺序扫描因此共享同一个索引，但缓存、页分裂和写放大也成为设计成本。

## 数字搜索：按键位而非整键比较

digital searching（数字搜索）一次检查键的一个字符、比特或数字。成本更接近键长 $L$，而不是记录数的对数；当键很长、共享前缀多或需要前缀查询时，这种模型尤其重要。

### Trie 与前缀子树

<Term def="trie按键的连续数字建立路径，终止标记区分完整键与仅作为前缀的节点">trie</Term>查询`car`时依次沿`c-a-r`边前进，耗时与键长相关。某个前缀节点之下的全部终止键就是前缀查询结果。代价是大量稀疏子指针；可用紧凑边表、双数组或按节点度选择表示。

<TcpTrieLab />

删除键时不能盲目删路径，因为节点可能仍服务于更长键；只有没有孩子且不是其他键终点的后缀节点才能回收。空串、一个键是另一个键的前缀、字符编码和大小写规范都属于索引契约。

### 压缩数字树与判别位

Patricia 类压缩树把只有一个孩子的长链折叠成带标签边，并在分支记录首个不同位。查询必须确认压缩标签完整匹配，而不是只走到叶就宣布成功。压缩降低节点数和指针跳转，却增加边标签比较与更新复杂度。

<TcpPatriciaLab />

数字树的顺序由数字编码决定。若整数直接按补码比特从最高位搜索，负数区间的编码顺序与数值顺序可能不同；需要先做可序化编码变换。

## 散列：平均常数并非无条件保证

<Term def="散列用哈希函数把键映射到有限槽位，并通过冲突处理在同槽键之间继续区分">散列</Term>适合等值查询。正确性要求相等键得到相等哈希值；性能还要求输入分布下的桶较均匀。装载因子 $\alpha=n/m$ 把记录数 $n$ 与槽位数 $m$ 联系起来，但单看平均装载不能发现攻击性碰撞或低位模式。

### 链地址法

链地址法让每个桶保存零个或多个记录。均匀散列假设下，平均查询工作约为常数加桶链长度，即 $\Theta(1+\alpha)$。装载因子可以超过一，删除简单，但节点分配和指针追踪损害局部性。

<TcpChainingLab />

$$
E[C_{\mathrm{chain}}]=\Theta(1+\alpha),\qquad \alpha=\frac{n}{m}.
$$

### 开放寻址与探测序列

<Term def="开放寻址把所有记录保存在主槽数组中，冲突时按确定探测序列寻找下一个候选槽">开放寻址</Term>要求装载因子小于一。线性探测有连续簇，平方探测可能只覆盖部分槽，双重散列需要步长与表长互素。删除不能简单清空槽，否则会截断后续键的查询路径；应使用墓碑或后移重整策略。

<TcpOpenAddressLab />

```ts
function probe(key: number, attempt: number, size: number) {
  const step = 1 + (key % (size - 1));
  return (key % size + attempt * step) % size;
}
```

扩容必须重新散列所有活记录，因为槽位由新表长决定。基准应同时报告成功与失败查询、不同装载因子、碰撞键和删除后状态；只测连续整数键可能恰好迎合某个差哈希函数。

## 次关键字检索：从唯一主键到集合运算

retrieval on secondary keys（次关键字检索）面对非唯一属性，例如“团队=compiler”“级别=senior”。索引项不能只存一个记录地址，而要存记录标识集合或 posting list。AND 查询做交集，OR 查询做并集，NOT 查询则依赖全集或补集表示。

<Term def="倒排表从属性值映射到包含该值的有序记录标识列表，使多条件查询转化为集合运算">倒排表</Term>按记录标识排序后，两表交集可用双指针在线性时间完成；长短极不平衡时，可在长表中跳跃或二分。位图索引用位并行完成交并，适合基数较低且记录编号稳定的属性。

<TcpSecondaryKeyLab />

<TcpInvertedIndexLab />

$$
T_{\cap}=O(|P_1|+|P_2|),\qquad P_{A\land B}=P_A\cap P_B.
$$

查询优化器还要决定交集顺序：先处理最短、选择性最高的 posting list，通常能快速缩小候选集。最终回表读取完整记录可能成为随机I/O瓶颈，因此覆盖索引与批量回表会改变最优计划。

<Stepper>
  <Step title="第一步：声明查询语义与键模型">
    写清精确、下界、范围或前缀查询，说明重复键返回一个还是全部，以及键比较、字符编码和空值规则。
    <TcpBinarySearchLab />
  </Step>
  <Step title="第二步：检查索引结构不变量">
    有序表检查单调性，树检查键范围与平衡，trie检查终止标记，哈希检查每个键沿其探测路径可达，倒排表检查标识有序且不重复。
    <TcpOpenAddressLab />
  </Step>
  <Step title="第三步：用失败键与层级成本验收">
    同时测试存在、缺失、重复、冲突和范围边界；按真实介质记录比较、探测、指针跳转或随机块读取，而非只写渐近符号。
    <TcpSearchCertificateLab />
  </Step>
</Stepper>

## 检验矩阵与失败复现

搜索实现应覆盖空表、单元素、首尾命中、缺失键、重复键、全冲突键、装载阈值、树旋转后的全部旧键、一个词是另一词前缀以及空 posting list。属性测试可把结果与线性扫描 oracle 比较；结构测试则在每次随机插入删除后检查索引不变量。二者缺一不可：错误索引可能碰巧回答当前查询，正确结果也可能来自已经退化的结构。

<TcpSearchCertificateLab />

<Callout type="trap">
**误区：哈希查询写成平均 $O(1)$ 就完成了分析。** 这个结论依赖哈希分布、装载控制和冲突策略；敌对键、差哈希或墓碑堆积都能显著拉长探测。必须报告装载因子和实际探测分布。
</Callout>

<Callout type="trap">
**误区：树结构只要还能找到现有键就正确。** 键范围、平衡元数据、叶深和占用率可能已破坏，只是测试键尚未经过故障分支。更新后必须遍历检查完整结构不变量。
</Callout>

## 练习

<Exercises>

**问题 1**：在有序数组`[2,5,8,12,16]`中求键`10`的 lower bound，给出半开区间变化。

<Answer>
初始`[0,5)`，中点二对应键八，小于十，故变为`[3,5)`；中点四对应十六，不小于十，变为`[3,4)`；中点三对应十二，不小于十，变为`[3,3)`。答案索引三，是十应插入的位置，但不是精确命中。
</Answer>

**问题 2**：为什么高度失衡的二叉搜索树不能保证对数查询？

<Answer>
查询只沿一条根到叶路径，成本由树高而非节点总数直接决定。若按升序插入普通二叉搜索树，每个节点只有右孩子，高度为 $n-1$，一次失败查询可能访问全部节点。平衡约束才把高度限制为 $\Theta(\log n)$。
</Answer>

**问题 3**：开放寻址表删除键时为什么不能直接把槽清空？

<Answer>
后插入的碰撞键可能越过该槽存放。查询这些键时会沿相同探测序列前进；若遇到“从未使用”的空槽就提前判定缺失，清空会截断路径。墓碑标记表示这里已删除但查询仍需继续。
</Answer>

**问题 4**：posting list `A=[1,2,4,7,9]`与`B=[2,3,7,8]`的AND结果是什么，双指针最多推进多少次？

<Answer>
交集为`[2,7]`。双指针每次至少推进一个列表位置，因此推进总次数不超过两表长度之和九，时间为 $O(|A|+|B|)$，额外工作与未命中标识数量同阶。
</Answer>

</Exercises>

## 小结

Chapter 6 不是“二分、B树、哈希谁最快”的排行榜。顺序搜索提供最弱前提基线；比较搜索从有序表扩展到平衡和多路树；数字搜索用键位与前缀组织路径；散列用空间和分布换取等值查询；次关键字检索把查询变成 posting list 集合运算。每种方法都必须同时声明查询语义、键模型、结构不变量和真实层级成本，才能形成可复核搜索设计。

<Glossary>
  <GlossaryItem term="顺序搜索">按存储顺序逐条比较，直至命中或耗尽输入的无索引基线。</GlossaryItem>
  <GlossaryItem term="二分搜索">在有序随机访问序列中反复排除一半候选区间的比较搜索。</GlossaryItem>
  <GlossaryItem term="二叉搜索树">左子树键较小、右子树键较大的链接搜索结构，成本取决于树高。</GlossaryItem>
  <GlossaryItem term="多路搜索树">每节点保存多个分隔键与子指针、以高扇出减少块访问层数的树。</GlossaryItem>
  <GlossaryItem term="trie">按键的字符或比特逐层导航，并以终止标记区分完整键的数字树。</GlossaryItem>
  <GlossaryItem term="散列">用哈希函数映射槽位，并通过链或探测序列解决冲突的等值检索方法。</GlossaryItem>
  <GlossaryItem term="开放寻址">把全部记录放在槽数组内，冲突时继续探测其他槽的散列表方案。</GlossaryItem>
  <GlossaryItem term="倒排表">从属性值或词项映射到有序记录标识集合的次关键字索引。</GlossaryItem>
</Glossary>
