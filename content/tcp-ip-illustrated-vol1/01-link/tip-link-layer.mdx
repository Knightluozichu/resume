## 以太网 II 帧结构

以太网 II 帧是局域网中最常用的链路层封装格式：

| 字段 | 大小 | 作用 |
|------|------|------|
| 前导码 | 8 字节 | 时钟同步（网卡层处理，不显示） |
| 目的 MAC | 6 字节 | 接收方硬件地址 |
| 源 MAC | 6 字节 | 发送方硬件地址 |
| Type | 2 字节 | 上层协议标识 |
| 数据 Payload | 46-1500 字节 | 上层协议数据（MTU=1500） |
| FCS | 4 字节 | 帧校验序列（网卡校验，不显示） |

### Type 字段常见值

```text
0x0800 = IPv4    ← 上层是 IP 协议
0x0806 = ARP     ← 地址解析协议
0x86DD = IPv6    ← IPv6 协议
0x8100 = 802.1Q  ← VLAN 标签
```

## ARP 地址解析

ARP 将 IP 地址解析为 MAC 地址，使 IP 包能在以太网上传输：

```text
1. 主机 A 查 ARP 缓存，无目标 IP 的 MAC
2. 广播 ARP Request: 谁是 192.168.1.1?
   （目标 MAC = FF:FF:FF:FF:FF:FF）
3. 目标主机单播 ARP Reply: 我的 MAC 是 00:50:56:xx:xx:xx
4. 主机 A 缓存 IP-MAC 映射（TTL 约 20 分钟），后续直接使用
```

<Callout type="warning" title="ARP 欺骗原理">

ARP 无认证机制：任何主机都可发送伪造 ARP Reply，将自己的 MAC 与网关 IP 绑定，劫持局域网流量。检测方法：①监控 ARP 响应的源 MAC 是否与预期网关一致 ②同一 IP 对应多个 MAC 说明被欺骗 ③大量 gratuitous ARP（免费 ARP）可能是欺骗信号。

</Callout>

## MTU 与 IP 分片

### MTU 与分片机制

```text
以太网 MTU = 1500 字节（Payload 最大值）

当 IP 包 > MTU 时，路由器分片：
  - DF=1（禁止分片）→ 路由器返回 ICMP 错误（PMTUD 用）
  - DF=0（允许分片）→ 路由器将包拆分

分片标识：
  - Identification：同一原包的分片值相同
  - MF（More Fragments）：1=后面还有分片，0=最后一片
  - Fragment Offset：当前分片在原包中的偏移（单位 8 字节）

目的主机负责重组分片（按 Identification + Offset）
```

### 分片示例

```text
原 IP 包：4000 字节（含 20B IP 头），MTU=1500

分片1: Offset=0,    MF=1, 数据=1480B（总1500B）
分片2: Offset=1480,  MF=1, 数据=1480B（总1500B）
分片3: Offset=2960,  MF=0, 数据=520B （总540B）
```

## MAC 地址与 IP 地址对比

| 特性 | MAC 地址 | IP 地址 |
|------|---------|---------|
| 层级 | 链路层（硬件） | 网络层（逻辑） |
| 长度 | 48 位 | 32 位（IPv4） |
| 结构 | OUI(24b) + 设备(24b) | 网络位 + 主机位 |
| 分配 | 网卡出厂固化 | 动态/静态配置 |
| 有效范围 | 局域网内 | 全局可路由 |
| 变化 | 不随网络变化 | 随网络变化 |

<Glossary>

<GlossaryItem term="以太网 II 帧（Ethernet II Frame）">
以太网 II 帧是局域网最常用的链路层帧格式：前导码（8B，时钟同步）+ 目的MAC（6B）+ 源MAC（6B）+ Type（2B，标识上层协议）+ Payload（46-1500B）+ FCS（4B，校验）。Type 字段值：0x0800=IPv4、0x0806=ARP、0x86DD=IPv6。Payload 最大 1500B 即 MTU。前导码和 FCS 在网卡层处理，上层软件通常不可见。
</GlossaryItem>

<GlossaryItem term="ARP（Address Resolution Protocol）">
ARP 地址解析协议将 IP 地址解析为 MAC 地址。流程：①查 ARP 缓存表 ②无匹配则广播 ARP Request（目标MAC=FF:FF:FF:FF:FF:FF）③目标主机单播回复 ARP Reply ④缓存 IP-MAC 映射（TTL约20分钟）。ARP 只在局域网内有效——跨网段时解析的是网关 MAC。ARP 无认证机制，易受 ARP 欺骗攻击。
</GlossaryItem>

<GlossaryItem term="MTU（Maximum Transmission Unit）">
MTU 是链路层一次能承载的最大 Payload 长度，以太网 MTU=1500 字节。当 IP 包超过 MTU 且 DF=0 时路由器分片传输：每个分片有相同 Identification，MF=1 标记非最后一片，Fragment Offset 标记偏移。DF=1 禁止分片，包过大时路由器返回 ICMP Type 3 Code 4 差错（PMTUD 利用此机制发现路径 MTU）。
</GlossaryItem>

<GlossaryItem term="MAC 地址（Media Access Control Address）">
MAC 地址是 48 位硬件地址，格式如 00:1a:2b:3c:4d:5e。前 24 位是厂商 OUI（组织唯一标识符，可查厂商），后 24 位是设备唯一标识。MAC 固化在网卡中，是链路层地址，只在局域网内有效。与 IP 地址的区别：MAC 是物理地址不随网络变化，IP 是逻辑地址随网络变化；MAC 用于局域网内寻址，IP 用于跨网段路由。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 以太网 II 帧的结构是什么？Type 字段的作用是什么？

<Answer>

以太网 II 帧结构：前导码（8B，同步）+ 目的MAC（6B）+ 源MAC（6B）+ Type（2B）+ 数据（46-1500B）+ FCS（4B，校验）。Type 字段标识上层协议：0x0800=IPv4、0x0806=ARP、0x86DD=IPv6、0x8100=802.1Q VLAN。接收方据 Type 判断将 Payload 交给哪个上层协议处理。

</Answer>

**问题 2：** 什么是 MTU？IP 分片机制如何工作？DF 和 MF 标志的作用是什么？

<Answer>

MTU 是链路层一次能承载的最大数据量，以太网 MTU=1500 字节。当 IP 包超过 MTU 时路由器分片：每个分片有相同 Identification，MF=1 标记非最后一片，Fragment Offset 标记当前片在原包中的位置。DF=1 禁止分片，包过大时路由器返回 ICMP 错误（用于 PMTUD）。目的主机负责重组分片。

</Answer>
