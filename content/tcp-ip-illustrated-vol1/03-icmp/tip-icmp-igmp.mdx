## ICMP 报文类型

ICMP（Internet Control Message Protocol）封装在 IP 包中（Protocol=1），用于差错报告和网络诊断。

### 查询类报文

| Type | 名称 | 用途 |
|------|------|------|
| 8 | Echo Request | ping 请求 |
| 0 | Echo Reply | ping 应答 |

### 差错报告类报文

| Type | 名称 | 用途 |
|------|------|------|
| 3 | Destination Unreachable | 目的不可达 |
| 5 | Redirect | 路由重定向 |
| 11 | Time Exceeded | 超时（TTL=0） |
| 12 | Parameter Problem | 参数问题 |

### ICMP 报文结构

```text
Type(1B) + Code(1B) + Checksum(2B) + 数据(变长)

Type 3 的 Code 值：
  Code 0 = 网络不可达
  Code 1 = 主机不可达
  Code 3 = 端口不可达
  Code 4 = 需要分片但 DF 置位（PMTUD 用）
```

<Callout type="warning" title="ICMP 差错报告的规则">

ICMP 差错报告不会对以下报文生成：①ICMP 差错报文本身（防止无限循环）②广播/组播包 ③非 IP 首部的分片包（非第一片）④特殊地址（如 0.0.0.0）的包。差错报文包含原始 IP 包头部+前 8 字节数据，让源端定位是哪个连接出了问题。

</Callout>

## ping 与 traceroute

### ping 工作流程

```text
1. 源主机发 ICMP Echo Request (Type 8)
2. 目的主机收 到后回 ICMP Echo Reply (Type 0)
3. 源主机根据往返时间(RTT)和是否收到应答判断连通性
```

### traceroute 原理

```text
1. 源端发 TTL=1 的 UDP/ICMP 包
   → 第一跳路由器 TTL减为0 → 丢弃，返回 ICMP Type 11（超时）
   → 源端记录第一跳地址和 RTT

2. 源端发 TTL=2 的包
   → 第二跳路由器返回 ICMP Type 11
   → 记录第二跳

3. 依此递增 TTL，直到包到达目的主机
   → 目的主机返回 ICMP Port Unreachable (Type 3 Code 3) 或 Echo Reply
   → traceroute 结束
```

## IGMP 组播管理

IGMP（Internet Group Management Protocol）封装在 IP 包中（Protocol=2），用于主机与组播路由器之间管理组成员关系。

### 组播地址

```text
D 类地址：224.0.0.0 ~ 239.255.255.255

特殊地址：
  224.0.0.1  = 所有主机组
  224.0.0.2  = 所有路由器组
  224.0.0.22 = IGMP v3 报告地址
```

### IGMP v2 报文类型

| 类型值 | 名称 | 用途 |
|--------|------|------|
| 0x11 | Membership Query | 路由器查询组成员 |
| 0x16 | v2 Membership Report | 主机加入组 |
| 0x17 | Leave Group | 主机离开组 |

### 组播加入与离开流程

```text
加入：主机发送 Membership Report(0x16) 到组播地址
查询：路由器周期性发送 Query(0x11) 检查成员是否还在
离开：主机发送 Leave Group(0x17)，路由器确认后停止转发
```

## Path MTU Discovery

```text
PMTUD 原理：
1. 源端发送 DF=1（禁止分片）的 IP 包
2. 若某路由器发现包 > 下一跳 MTU 且 DF=1
   → 丢弃包，返回 ICMP Type 3 Code 4（需分片但DF置位）
   → ICMP 报文中包含下一跳 MTU 值
3. 源端降低包大小重发
4. 重复直到包能不分片通过 → 得到路径 MTU

效果：源端发送的包始终无需分片即可到达目的
```

<Glossary>

<GlossaryItem term="ICMP（Internet Control Message Protocol）">
ICMP 是 Internet 控制报文协议，封装在 IP 包中（Protocol=1），用于差错报告和网络诊断。报文结构：Type(1B)+Code(1B)+Checksum(2B)+数据。查询类：Type 8=Echo Request、Type 0=Echo Reply（ping 用）。差错类：Type 3=目的不可达、Type 5=路由重定向、Type 11=超时（TTL=0，traceroute 用）、Type 12=参数问题。差错报告包含原始 IP 包头+前 8 字节数据，不会对 ICMP 差错报文本身、广播包生成差错。
</GlossaryItem>

<GlossaryItem term="traceroute">
traceroute 利用 ICMP Time Exceeded（Type 11）探测网络路径。原理：源端发送递增 TTL（1,2,3...）的探测包，每跳路由器 TTL 减为 0 时丢弃包并返回 ICMP 超时报文，源端据此记录每跳地址和 RTT。直到包到达目的主机，返回 ICMP Port Unreachable（Type 3 Code 3）或 Echo Reply，traceroute 结束。每跳通常探测 3 次以统计 RTT 波动。
</GlossaryItem>

<GlossaryItem term="IGMP（Internet Group Management Protocol）">
IGMP 是 Internet 组管理协议，封装在 IP 包中（Protocol=2），用于主机与相邻组播路由器之间管理组播组成员关系。v2 报文类型：0x11=成员查询（路由器周期性发送）、0x16=加入报告（主机加入组）、0x17=离开组。组播地址范围 224.0.0.0~239.255.255.255（D 类）。路由器根据 IGMP 维护组成员表，决定向哪些接口转发组播流量。
</GlossaryItem>

<GlossaryItem term="Path MTU Discovery（PMTUD）">
路径 MTU 发现机制，用于发现源到目的之间路径上的最小 MTU，避免分片。原理：源端设 DF=1 发送 IP 包，若路由器发现包超过下一跳 MTU 且 DF 置位，则丢弃包并返回 ICMP Type 3 Code 4（Fragmentation Needed and DF Set）差错报文，报文中含下一跳 MTU。源端据此降低包大小重发，直到成功通过。最终源端发送的包始终无需分片即可到达目的，提高传输效率。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** ICMP 的主要报文类型有哪些？ping 和 traceroute 分别用了哪些 ICMP 报文？

<Answer>

ICMP 查询类：Type 8=Echo Request、Type 0=Echo Reply。差错类：Type 3=目的不可达、Type 5=路由重定向、Type 11=超时、Type 12=参数问题。ping 用 Echo Request（Type 8）和 Echo Reply（Type 0）。traceroute 发递增 TTL 的包，利用中间路由器返回的 Time Exceeded（Type 11）推断路径，目的主机返回 Port Unreachable（Type 3 Code 3）。

</Answer>

**问题 2：** 什么是 Path MTU Discovery（PMTUD）？它如何利用 ICMP 工作？

<Answer>

PMTUD 用于发现源到目的之间路径上最小的 MTU，避免分片。源端发送 DF=1（禁止分片）的 IP 包，若某路由器发现包超过下一跳 MTU 且 DF=1，则丢弃包并返回 ICMP Type 3 Code 4 差错报文（含下一跳 MTU 值）。源端据此降低包大小重发，直到成功通过。这样源端发送的包始终能在不分片的情况下到达目的。

</Answer>

</Exercises>
