## RTT 估计与 RTO 计算

TCP 通过测量往返时间（RTT）来动态调整重传超时（RTO）。

### RTT 平滑计算

```text
SRTT = (1 - α) × SRTT + α × R        （α = 1/8）
RTTVAR = (1 - β) × RTTVAR + β × |SRTT - R|   （β = 1/4）

RTO = SRTT + max(G, 4 × RTTVAR)

其中：
  R     = 本次测量的 RTT
  SRTT  = 平滑 RTT（指数加权移动平均）
  RTTVAR = RTT 方差（衡量 RTT 波动）
  G     = 系统时钟粒度
```

<Callout type="info" title="为什么用指数加权移动平均">

RTT 受网络拥塞、路由变化等因素影响波动较大。单次测量不代表整体趋势，简单平均又反应太慢。指数加权移动平均（EWMA）给予近期测量更大权重（α=1/8），既能跟踪 RTT 变化趋势，又能平滑噪声。RTO = SRTT + 4×RTTVAR 在 RTT 波动大时自动增大 RTO（减少不必要的重传），在 RTT 稳定时缩小 RTO（提高响应速度）。

</Callout>

## Karn 算法

### 重传歧义问题

```text
场景：发送方发出包 A，超时后重传包 A'
收到 ACK 时，无法判断：
  - 是对原始包 A 的确认（RTT = 现在 - 发送A的时间）
  - 还是对重传包 A' 的确认（RTT = 现在 - 发送A'的时间）

如果判断错误，RTT 估计会偏差很大
```

### Karn 算法的解决方案

```text
规则1：重传的包不参与 RTT 测量
       → 只测量未重传的包的 RTT
规则2：重传时 RTO 指数退避（加倍）
       → 每次重传 RTO = 2 × RTO
       → 直到成功传输后恢复正常 RTO
```

## 超时重传与快速重传

### 超时重传

```text
触发条件：RTO 定时器超时，已发数据未收到 ACK
动作：
  1. 重传未确认的包
  2. ssthresh = cwnd / 2
  3. cwnd = 1（回到慢启动）
  4. RTO 指数退避
含义：认为网络严重拥塞，激进减速
```

### 快速重传

```text
触发条件：收到 3 个重复 ACK
原理：后面的包到了但某个包丢了
      → 接收方不断回 ACK 请求丢失的包
动作：
  1. 立即重传丢失的包（不等超时）
  2. ssthresh = cwnd / 2
  3. cwnd = ssthresh（快恢复，不回到1）
含义：只有个别包丢失，网络轻度拥塞
优势：比重传定时器响应更快，吞吐影响更小
```

## TCP 拥塞控制

### 四个阶段

```text
阶段1：慢启动（Slow Start）
  cwnd 从 1 开始
  每收到一个 ACK → cwnd += 1（指数增长）
  到达 ssthresh → 转拥塞避免

阶段2：拥塞避免（Congestion Avoidance）
  cwnd 每个 RTT += 1（线性增长）
  持续增长直到丢包

阶段3：快重传（Fast Retransmit）
  3 个重复 ACK → 立即重传丢失包
  ssthresh = cwnd / 2

阶段4：快恢复（Fast Recovery）
  cwnd = ssthresh（不从 1 开始）
  继续拥塞避免线性增长

注：如果是超时丢包（非重复ACK），则 ssthresh = cwnd/2，cwnd = 1，回到慢启动
```

### cwnd 变化示意

```text
cwnd
  ↑                        /\        ← 快恢复后线性增长
  │                       /  \      /
  │          线性增长     /    \    /
  │         /           /      \  /
  │        /           /  快恢复\/
  │   指数/           /         
  │   /  /           /          
  │  /  /           /           
  │ /  /           /            
  │/  /           /             
  +--+------------+--------------→ RTT
     慢启动    拥塞避免         
     (指数)     (线性)          
```

## TCP 定时器

| 定时器 | 作用 |
|--------|------|
| 重传定时器 | 已发数据未收到 ACK → 超时重传 |
| 坚持定时器 | Window=0 后周期性探测窗口更新 |
| 保活定时器 | 连接空闲超时探测对端是否存活 |
| 2MSL 定时器 | TIME_WAIT 等待 2×MSL 确保报文消亡 |

<Glossary>

<GlossaryItem term="RTT（Round-Trip Time）">
RTT 往返时间是数据包从发出到收到确认的时间。TCP 用指数加权移动平均平滑 RTT：SRTT = (1-α)·SRTT + α·R（α=1/8），RTTVAR = (1-β)·RTTVAR + β·|SRTT-R|（β=1/4）。RTO = SRTT + max(G, 4·RTTVAR)。SRTT 跟踪 RTT 趋势，RTTVAR 衡量波动。RTT 波动大时 RTO 自动增大（减少不必要重传），稳定时缩小（提高响应速度）。
</GlossaryItem>

<GlossaryItem term="Karn 算法（Karn's Algorithm）">
Karn 算法解决 TCP 重传歧义问题：当一个包被重传后，收到 ACK 时无法判断是对原始包还是重传包的确认。规则：①重传的包不参与 RTT 测量 ②重传时 RTO 指数退避（每次加倍），直到成功传输后恢复正常。这样避免了错误 RTT 样本污染估计，同时在网络持续拥塞时通过退避减轻压力。
</GlossaryItem>

<GlossaryItem term="快速重传（Fast Retransmit）">
快速重传是 TCP 收到 3 个重复 ACK 时不等超时就立即重传丢失包的机制。原理：后面的包到了但某个包丢了，接收方不断回 ACK 请求丢失的包，发送方收到 3 个重复 ACK 即判断丢包。触发后 ssthresh=cwnd/2，cwnd=ssthresh（快恢复，不回到 1）。相比超时重传，快速重传响应更快、对吞吐影响更小，认为网络只是轻度拥塞。
</GlossaryItem>

<GlossaryItem term="TCP 拥塞控制（Congestion Control）">
TCP 拥塞控制通过调节拥塞窗口（cwnd）感知网络承载能力。四个阶段：①慢启动——cwnd 从 1 指数增长到 ssthresh ②拥塞避免——cwnd 每个 RTT 线性加 1 ③快重传——3 个重复 ACK 触发重传，ssthresh=cwnd/2 ④快恢复——cwnd=ssthresh 继续线性增长。超时丢包时 cwnd 归 1 回到慢启动，重复 ACK 丢包时 cwnd 减半走快恢复。核心思想：探测可用带宽，遇拥塞退避。
</GlossaryItem>

</Glossary>

**问题 1：** TCP 如何估计 RTT 并计算 RTO？Karn 算法解决什么问题？

<Answer>

RTT 估计：SRTT = (1-α)·SRTT + α·R（α=1/8），RTTVAR = (1-β)·RTTVAR + β·|SRTT-R|（β=1/4），RTO = SRTT + max(G, 4·RTTVAR)。Karn 算法解决重传歧义问题：重传的包不参与 RTT 测量；重传时 RTO 指数退避（加倍），直到成功传输后恢复。

</Answer>

**问题 2：** TCP 超时重传和快速重传的区别是什么？

<Answer>

超时重传：RTO 超时未收到 ACK 则重传，认为网络严重拥塞，ssthresh=cwnd/2，cwnd=1（慢启动）。快速重传：收到 3 个重复 ACK 立即重传丢失包，认为网络轻度拥塞，ssthresh=cwnd/2，cwnd=ssthresh（快恢复，不回到 1）。快速重传响应更快，对吞吐影响更小。

</Answer>
