## DNS 域名解析

### DNS 工作流程

```text
1. 用户输入 www.example.com
2. 浏览器查本地 DNS 缓存 → 无
3. 查系统 DNS 缓存 → 无
4. 向本地 DNS 服务器发送查询（UDP 端口 53）

递归查询（客户端 → 本地DNS）：
  本地 DNS 负责完成全部解析

迭代查询（本地DNS → 各级服务器）：
  本地DNS → 根服务器：返回 TLD(.com) 服务器地址
  本地DNS → TLD服务器：返回权威服务器地址
  本地DNS → 权威服务器：返回 www.example.com 的 IP

5. 本地 DNS 将 IP 返回给客户端
6. 客户端缓存并访问
```

### DNS 记录类型

| 类型 | 名称 | 用途 |
|------|------|------|
| A | IPv4 地址 | 域名 → IPv4 |
| AAAA | IPv6 地址 | 域名 → IPv6 |
| CNAME | 别名 | 域名 → 域名 |
| MX | 邮件交换 | 域名 → 邮件服务器 |
| NS | 名称服务器 | 域名 → DNS 服务器 |
| TXT | 文本 | 自定义文本（SPF 等） |
| PTR | 指针 | IP → 域名（反向解析） |
| SOA | 起始授权 | 区域管理信息 |

## HTTP 请求响应

### HTTP 请求格式

```text
GET /index.html HTTP/1.1        ← 请求行：方法 路径 版本
Host: www.example.com           ← 请求头
User-Agent: Mozilla/5.0
Accept: text/html
                                ← 空行（头与体分隔）
（请求体，GET 通常无）
```

### HTTP 响应格式

```text
HTTP/1.1 200 OK                 ← 状态行：版本 状态码 短语
Content-Type: text/html         ← 响应头
Content-Length: 1024
                                ← 空行
<html>...</html>               ← 响应体
```

### 状态码分类

| 范围 | 含义 | 示例 |
|------|------|------|
| 2xx | 成功 | 200 OK |
| 3xx | 重定向 | 301 永久重定向、304 Not Modified |
| 4xx | 客户端错误 | 404 Not Found、403 Forbidden |
| 5xx | 服务端错误 | 500 Internal Server Error |

<Callout type="info" title="HTTP 是无状态协议">

HTTP 每个请求独立，服务器不记录之前请求的状态。维持会话的方法：①Cookie——服务器通过 Set-Cookie 头下发，客户端后续请求携带 ②Session——服务器端存储会话状态，通过 Cookie 中的 Session ID 关联。HTTP/1.1 支持持久连接（Keep-Alive）复用 TCP 连接，减少握手开销。

</Callout>

## SMTP 邮件传输

### 邮件系统组件

```text
MUA（邮件客户端）→ MTA（邮件传输代理）→ MTA → MDA（邮件投递代理）→ MUA

协议：
  MUA → MTA：SMTP（发送邮件，端口 25/587）
  MTA → MTA：SMTP（服务器间转发）
  MDA → MUA：POP3（端口 110）或 IMAP（端口 143）
```

### SMTP 命令交互

```text
客户端                              服务器
  |  HELO client.com               |
  |  --------------------------→   |  250 OK
  |  MAIL FROM: <a@client.com>     |
  |  --------------------------→   |  250 OK
  |  RCPT TO: <b@server.com>       |
  |  --------------------------→   |  250 OK
  |  DATA                          |
  |  --------------------------→   |  354 Start input
  |  Subject: Hello                |
  |  This is the body.             |
  |  .                             |  ← 单独一个点表示结束
  |  --------------------------→   |  250 OK
  |  QUIT                          |
  |  --------------------------→   |  221 Bye
```

## FTP 文件传输

### 双连接机制

```text
控制连接（端口 21）：
  传输命令（USER/PASS/LIST/RETR/STOR/QUIT）
  全程保持连接

数据连接（端口 20 或随机）：
  传输文件数据和目录列表
  每次传输建立，传完关闭
```

### 主动模式 vs 被动模式

```text
主动模式（PORT）：
  客户端告诉服务器：我在 IP:端口 等你
  服务器从端口 20 主动连接客户端
  问题：客户端在 NAT/防火墙后时，服务器无法连入

被动模式（PASV）：
  客户端发 PASV 命令
  服务器回复：我在 IP:随机端口 等你
  客户端主动连接服务器
  优势：解决客户端在 NAT 后的问题（现代主流模式）
```

## 应用层协议对比

| 协议 | 端口 | 传输层 | 用途 |
|------|------|--------|------|
| DNS | 53 | UDP/TCP | 域名解析 |
| HTTP | 80/443 | TCP | 网页传输 |
| SMTP | 25/587 | TCP | 邮件发送 |
| POP3 | 110 | TCP | 邮件接收 |
| IMAP | 143 | TCP | 邮件接收 |
| FTP | 20/21 | TCP | 文件传输 |
| SNMP | 161/162 | UDP | 网络管理 |
| DHCP | 67/68 | UDP | IP 分配 |

<Glossary>

<GlossaryItem term="DNS（Domain Name System）">
DNS 域名系统将人类可读的域名解析为 IP 地址。端口 53（UDP 为主，大响应用 TCP）。查询方式：客户端→本地DNS 是递归查询（本地 DNS 完成全部解析）；本地DNS→根/TLD/权威 是迭代查询（逐级返回下一级地址）。记录类型：A(IPv4)、AAAA(IPv6)、CNAME(别名)、MX(邮件)、NS(名称服务器)、TXT(文本)、PTR(反向)、SOA(授权)。DNS 缓存分多层（浏览器/系统/本地DNS/各级服务器），减少查询延迟。
</GlossaryItem>

<GlossaryItem term="HTTP（HyperText Transfer Protocol）">
HTTP 超文本传输协议是 Web 的核心协议，端口 80（HTTP）/443（HTTPS over TLS），基于 TCP。请求格式：请求行（方法+路径+版本）+ 请求头 + 空行 + 请求体。方法：GET/POST/PUT/DELETE/HEAD/OPTIONS。响应格式：状态行（版本+状态码+短语）+ 响应头 + 空行 + 响应体。状态码：2xx成功、3xx重定向、4xx客户端错误、5xx服务端错误。HTTP 是无状态协议，通过 Cookie/Session 维持会话。HTTP/1.1 支持持久连接（Keep-Alive）。
</GlossaryItem>

<GlossaryItem term="SMTP（Simple Mail Transfer Protocol）">
SMTP 简单邮件传输协议用于发送邮件，端口 25/587，基于 TCP 可靠传输。邮件系统：MUA(客户端)→MTA(传输代理)→MTA→MDA(投递代理)→MUA(客户端接收)。SMTP 命令：HELO/EHLO(问候)、MAIL FROM(发件人)、RCPT TO(收件人)、DATA(正文)、QUIT。命令式协议，文本行交互，响应码 220(就绪)/250(OK)/550(邮箱不存在)。MIME 扩展支持附件、HTML、多媒体内容。接收邮件用 POP3（端口110）或 IMAP（端口143）。
</GlossaryItem>

<GlossaryItem term="FTP（File Transfer Protocol）">
FTP 文件传输协议使用双连接：控制连接（端口21，传命令，全程保持）+ 数据连接（传文件，按需建立）。命令：USER/PASS(认证)、LIST(列目录)、RETR(下载)、STOR(上传)、QUIT。两种数据连接模式：主动模式(PORT)——服务器从端口20连客户端，客户端在 NAT 后时无法使用；被动模式(PASV)——客户端连服务器随机端口，解决 NAT 问题，是现代主流模式。FTP 基于 TCP，命令和数据分开传输是其独特设计。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** DNS 的递归查询和迭代查询有什么区别？

<Answer>

递归查询：客户端向本地 DNS 服务器发出查询后，本地 DNS 负责完成全部解析过程（代替客户端依次查询根→TLD→权威），最终返回结果。客户端只需一次请求。迭代查询：DNS 服务器收到查询后如果不知道答案就返回「下一步该问谁」，由请求方自己继续查询。实际中：客户端→本地DNS 是递归查询；本地DNS→根/TLD/权威 是迭代查询。

</Answer>

**问题 2：** FTP 的主动模式和被动模式有什么区别？为什么需要两种模式？

<Answer>

FTP 使用双连接：控制连接（端口21）+ 数据连接。主动模式（PORT）：客户端告诉服务器自己在哪个端口等待，服务器从端口 20 主动连接客户端。问题：客户端在 NAT/防火墙后时服务器无法连入。被动模式（PASV）：客户端发 PASV，服务器回复自己等待的随机端口，客户端主动连接服务器。被动模式解决了客户端在 NAT 后的问题，是现代主流模式。

</Answer>
