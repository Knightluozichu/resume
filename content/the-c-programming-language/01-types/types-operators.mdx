## 数据的基本表示

程序的本质是处理数据。C 语言用「类型」来规定数据在内存中占多少空间、怎么解读二进制位。基本类型只有四种：`char`（字符/小整数）、`int`（整数）、`float`（单精度浮点）、`double`（双精度浮点）。这四种类型是 C 语言的原子——所有更复杂的数据表示都是它们的组合。

<KrcTypesMemoryDiagram />

C 标准唯一定义的绝对大小是 `sizeof(char) == 1`。其余类型的大小依平台而定——但在 64 位 Linux/macOS 上，int 几乎总是 4 字节，double 总是 8 字节。用 `sizeof` 运算符可以确认当前平台的实际大小，它是编译期常量，没有运行时开销。

<Term def="规定变量在内存中起始地址必须是某个数的整数倍的编译器行为，目的是让 CPU 高效访问数据。">内存对齐</Term>是理解类型大小的关键。CPU 访问对齐的数据比未对齐的数据快得多（某些架构上未对齐访问直接崩溃）。所以编译器会在结构体成员之间自动插入 padding 字节，让每个成员落在自身对齐边界的整数倍地址上。

## 运算符与表达式

C 的运算符种类繁多，但核心规则只有一条：<Term def="多个运算符出现在同一表达式中时，决定哪个运算符先执行的规则。">运算符优先级</Term>决定结合顺序。`*` 比 `+` 优先级高，所以 `a + b * c` 等价于 `a + (b * c)`。但 K&R 的建议是：不要背优先级表，拿不准就加括号——括号零成本，但可读性提升巨大。

表达式求值中最容易出问题的是<Term def="运算过程中操作数类型不一致时，编译器自动把较窄的类型转换为较宽类型的规则。">隐式类型转换</Term>。当两个不同类型的操作数参与运算时，C 会自动把较窄的类型提升为较宽的类型。`int + float` 会把 int 提升为 float 再运算。这个规则在大多数情况下是合理的，但在有符号和无符号混合时会制造陷阱。

整数除法是另一个高频陷阱：`7 / 2` 的结果是 `3`（截断小数），不是 `3.5`。两个操作数都是整数时，C 执行整数除法。要得到浮点结果，至少一个操作数必须是浮点类型：`7 / 2.0` 或 `(float)7 / 2`。

## 核心概念

自增自减运算符的前缀和后缀区别是 C 的经典考点。`a++` 是后缀：表达式的值是 a 自增前的旧值，然后 a 加 1。`++a` 是前缀：a 先加 1，表达式的值是自增后的新值。两者最终都让 a 加 1，区别只在「表达式的值」——这在赋值和传参时有实际影响：`b = a++` 让 b 得到旧值，`b = ++a` 让 b 得到新值。

K&R 最精妙的运算符设计是<Term def="对整数二进制位逐位进行与/或/异或/取反操作的运算符：&、|、^、~。">位运算符</Term>。`&`（按位与）、`|`（按位或）、`^`（按位异或）、`~`（取反）、`<<`（左移）、`>>`（右移）。这些运算符让 C 能直接操作硬件寄存器的每一位——这是系统编程的核心需求，也是 C 贴近硬件的体现。

<Callout type="tip">
<strong>建议 →</strong> 写位运算时总是用无符号类型（`unsigned`）。有符号整数的右移行为是实现定义的（有些平台补符号位，有些补 0），用无符号类型可以保证逻辑右移，行为可预测。
</Callout>

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> `int i = -1; unsigned u = 10; if (i < u) printf("yes");` 不输出 yes。<strong>原因 →</strong> 有符号与无符号比较时，C 的隐式转换规则是把有符号转为无符号。-1 被转成 unsigned 后变成 4294967295（2^32 - 1），远大于 10，所以 `i < u` 为假。<strong>修法 →</strong> 避免有符号和无符号直接比较。如果必须比较，先显式转换：`if ((unsigned)i < u)` 或 `if (i < 0 || i < (int)u)`。
</Callout>

## 小结与练习

- C 基本类型只有四种（char/int/float/double），sizeof 是确认实际大小的唯一可靠手段
- 运算符优先级拿不准就加括号；整数除法截断小数，需浮点操作数才走浮点除法
- 隐式类型转换在算术运算中自动发生；有符号与无符号混合比较是最经典的 C 陷阱
- 位运算符让 C 能直接操作二进制位，是系统编程的基础工具

<Exercises>
  <Answer question="`int i = 7; float f = i / 2;` 的 f 是多少？为什么？如何修正为 3.5？">f = 3.0。因为 i 和 2 都是 int，执行整数除法 7/2=3（截断），再隐式转 float。修正：`float f = i / 2.0;`（让除数为 double，触发浮点除法）或 `float f = (float)i / 2;`（显式转换被除数）。</Answer>
  <Answer question="`a[i]++` 和 `++a[i]` 执行后，a[i] 的值和表达式本身的值分别是什么？">两者执行后 a[i] 都加 1。区别在表达式值：`a[i]++`（后缀）返回自增前的旧值，`++a[i]`（前缀）返回自增后的新值。如果 a[i]=5，则 `a[i]++` 的值是 5，`++a[i]` 的值是 6。</Answer>
</Exercises>

## 名词解释

<Glossary>
  <GlossaryItem term="内存对齐">规定变量在内存中起始地址必须是某个数（通常等于类型大小）的整数倍的编译器行为。目的是让 CPU 高效访问数据。编译器会在结构体成员间自动插入 padding 满足对齐要求。</GlossaryItem>
  <GlossaryItem term="运算符优先级">多个运算符出现在同一表达式中时，决定哪个运算符先执行的规则。如乘法优先于加法。K&R 建议拿不准就加括号，不靠记忆优先级表。</GlossaryItem>
  <GlossaryItem term="隐式类型转换">运算过程中操作数类型不一致时，编译器自动把较窄类型转换为较宽类型的规则。如 int + float 时 int 自动提升为 float。有符号与无符号混合时，有符号转为无符号——这是常见陷阱来源。</GlossaryItem>
  <GlossaryItem term="位运算符">对整数二进制位逐位操作的运算符：&amp;（与）、|（或）、^（异或）、~（取反）、&lt;&lt;（左移）、&gt;&gt;（右移）。让 C 能直接操作硬件寄存器每一位，是系统编程的核心工具。</GlossaryItem>
</Glossary>
