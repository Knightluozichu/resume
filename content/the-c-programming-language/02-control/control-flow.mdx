## 程序的执行路径

如果没有控制流，程序就是从上到下逐行执行——这只能写计算器，写不了任何有用的逻辑。控制流让程序有了「根据条件做不同事」和「重复做某件事」的能力。C 语言提供了三种控制结构：条件分支（if-else、switch）、循环（while、for、do-while）和跳转（break、continue、goto、return）。

## 核心概念

<Term def="在 switch 语句中，匹配某个 case 后若不写 break，会继续执行后续所有 case 的语句，直到遇到 break 或 switch 结束。">fall-through（穿透）</Term>是 switch 最需要注意的特性。匹配一个 case 后，程序从该 case 开始执行，不会在下一个 case 处停下来判断——它会一路执行下去。这有时是故意的（多个 case 共享同一段代码），但更多时候是忘了写 break 导致的 bug。

while 和 do-while 的核心区别在于判断时机：<Term def="先检查条件再执行循环体的循环结构，循环体可能一次都不执行。">while</Term>是「先判断后执行」，条件一开始就为假，循环体一次都不跑。<Term def="先执行循环体再检查条件的循环结构，循环体至少执行一次。">do-while</Term>是「先执行后判断」，循环体至少跑一次。当你需要「至少执行一次」时（比如菜单先显示再询问是否继续），do-while 是最自然的选择。

for 循环是 while 的语法糖，但它把初始化、条件、更新三部分集中在头部，让循环结构一目了然。执行顺序是：初始化 → 判断条件 → 执行循环体 → 更新 → 回到判断。for 循环的三个部分都可以省略——省略条件意味着永真（死循环），省略初始化和更新则退化为 while。

break 和 continue 控制循环的中途退出。break 立即跳出当前循环（或 switch），continue 跳过当前循环体剩余部分直接进入下一次迭代。在嵌套循环中，break 只跳出最内层——要跳出多层需要标志变量或 goto。

<Callout type="tip">
<strong>建议 →</strong> for 循环适合「已知次数」的迭代（遍历数组），while 适合「未知次数但有条件」的循环（读到文件末尾），do-while 适合「至少一次」的场景。选对循环结构能让代码意图更清晰。
</Callout>

## 常见误区

<Callout type="trap">
<strong>现象 →</strong> switch 语句忘了写 break，程序执行了不该执行的 case 分支。<strong>原因 →</strong> C 的 switch 默认 fall-through——匹配一个 case 后会继续执行后续所有 case 的语句，不会在 case 边界自动停止。<strong>修法 →</strong> 每个 case 的末尾都写 break（除非故意利用 fall-through）。如果故意 fall-through，加注释说明 `/* fall through */`，让代码审查者知道这不是遗漏。
</Callout>

<Callout type="trap">
<strong>现象 →</strong> `if (a = 0)` 写成了赋值而不是比较，条件永远为假。<strong>原因 →</strong> `=` 是赋值，`==` 是比较。`a = 0` 把 a 赋为 0，整个表达式的值也是 0（假），所以 if 体永远不执行。<strong>修法 →</strong> 把常量写在左边：`if (0 == a)`。如果误写成 `if (0 = a)` 编译器会报错（不能给常量赋值）。这种写法叫 Yoda 条件，虽然怪但能防 bug。
</Callout>

## 小结与练习

- if-else 是二分支，switch 是多路分支；switch 需 break 防 fall-through
- while 先判断后执行（可能 0 次），do-while 先执行后判断（至少 1 次），for 是 while 的语法糖
- break 跳出当前循环/switch，continue 跳过当前迭代；嵌套循环中 break 只跳出最内层
- `=` 是赋值、`==` 是比较，混淆是最常见的 C bug 之一

  <Answer question="switch 语句中忘记写 break 会发生什么？如何避免？">会发生 fall-through（穿透）：匹配某个 case 后，从该 case 开始执行，不加判断地继续执行后续所有 case 的语句，直到遇到 break 或 switch 结束。避免方法：每个 case 末尾写 break；故意 fall-through 时加注释 `/* fall through */` 说明。</Answer>

## 名词解释

<Glossary>
  <GlossaryItem term="fall-through">switch 语句中，匹配某个 case 后若不写 break，会继续执行后续所有 case 语句的现象。可被故意利用（多个 case 共享代码），但更常见是遗漏 break 导致的 bug。</GlossaryItem>
  <GlossaryItem term="while 循环">先检查条件再执行循环体的循环结构。条件一开始为假则循环体一次都不执行。适合「未知次数但有终止条件」的场景，如读到文件末尾。</GlossaryItem>
  <GlossaryItem term="do-while 循环">先执行循环体再检查条件的循环结构。循环体至少执行一次。适合「至少需要执行一次」的场景，如菜单显示后询问是否继续。</GlossaryItem>
  <GlossaryItem term="break / continue">break 立即终止当前循环或 switch，跳到结构之后继续执行。continue 跳过当前循环体剩余部分，直接进入下一次循环条件判断。在嵌套循环中 break 只跳出最内层。</GlossaryItem>
</Glossary>
