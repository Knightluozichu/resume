## 从第一章的可运行反馈环开始

K&R 的第一章 A Tutorial Introduction 不是缩小版参考手册，而是

<Term def="从最小可运行程序出发，通过编译、运行和观察逐步引入变量、控制流、函数、数组与作用域的学习过程。">入门</Term>
路线。每加入一个语法点，就用可观察结果验证；后续七章再把第一章略过的类型规则、生命周期和系统边界展开。

最小 hosted C 程序把源文件、编译器、链接器、运行时和宿主环境连起来。标准入口之一是

<Term def="hosted C 程序的标准入口函数形式之一；int main(void) 不接收命令行参数，返回状态交给宿主环境。">main 函数</Term>。
`printf` 的声明来自头文件，字符串中的 `\n`
是一个换行转义字符，而不是两个普通字符。

```c
#include <stdio.h>

int main(void)
{
    if (printf("hello, world\n") < 0)
        return 1;
    return 0;
}
```

返回 0 表示成功，非零表示失败；宿主如何显示状态属于环境约定。`printf` 可能失败，所以最终程序不能把“调用过输出函数”等同于“输出成功”。这个小例子已经包含声明、函数调用、字符串、返回值和错误策略。

## 变量与算术表达式：先确定计算域

原书用华氏温度与摄氏温度表引入

<Term def="给值命名并按运算符组合计算的基础机制；结果受操作数类型、整数提升、转换和溢出规则约束。">变量与算术表达式</Term>。
公式相同不代表 C
表达式结果相同：整数除法截断，浮点运算按浮点类型执行，格式化输出还要匹配实参类型。

```c
#include <stdio.h>

#define LOWER 0
#define UPPER 300
#define STEP  20

int main(void)
{
    int fahrenheit;
    double celsius;

    for (fahrenheit = LOWER; fahrenheit <= UPPER; fahrenheit += STEP) {
        celsius = (5.0 / 9.0) * (fahrenheit - 32);
        printf("%3d %6.1f\n", fahrenheit, celsius);
    }
    return 0;
}
```

这里用 `5.0 / 9.0` 明确浮点计算；若写 `5 / 9`，整数结果为 0，之后再转 `double` 已无法恢复。循环头清楚写出初值、继续条件和步进。声明放在块开头，使示例保持在 ANSI C90 边界；现代 C 虽允许声明与语句交错，计算类型规则并未因此改变。

`LOWER`、`UPPER` 和 `STEP` 是

<Term def="用宏或枚举为程序参数命名的常量概念，使公式表达意图并集中修改；预处理宏本身没有 C 类型。">符号常量</Term>。
宏替换不做类型检查，也没有作用域对象；简单整数集合可考虑枚举，需要地址或明确类型时可用适当对象。不要把“全大写”当成语言规则，它只是常见命名约定。

## for 语句：用不变量解释循环

`for` 语句适合把初始化、继续条件和推进放在一起，但正确性来自

<Term def="每次循环体开始前都成立，并在一次迭代后仍被保持的事实；结合退出条件可证明范围和结果。">循环不变量</Term>。
温度表中，不变量包括 `fahrenheit` 始终位于当前待输出刻度并按 `STEP`
推进；还要确认加法不会在到达上界前溢出。对不可信上界，不能只凭“每次增加”就断言终止。

数组循环常用 `0 <= index && index < count` 作为范围不变量。修改循环条件或步进时要同时检查空数组、单元素、最大边界和溢出。`break`、`continue` 或函数返回会改变控制流证明，应明确它们离开时哪些资源已取得、哪些结果仍有效。

> 先预测：把整数温度公式改为 `celsius = 5 / 9 * (fahrenheit - 32)` 会得到什么？`5 / 9` 在整数域先截断为 0，所以所有结果为 0；赋给浮点变量不会让之前的计算重做。

## 字符输入输出：EOF 不是字符

<Term def="以 getchar 和 putchar 等接口逐个读取或写出字符的标准 I/O 模式；读取结果用 int 同时表示 unsigned char 值与 EOF。">字符输入输出</Term>
把流循环压缩成一个清晰协议：先调用读取函数，检查返回值，再处理字符。`EOF`
是负的整数常量，用来表示没有字符可返回；它不是文件中存储的一枚特殊字节。

```c
#include <stdio.h>

int main(void)
{
    int character;

    while ((character = getchar()) != EOF)
        if (putchar(character) == EOF)
            return 1;
    if (ferror(stdin))
        return 1;
    return 0;
}
```

必须用 `int` 保存 `getchar` 结果；先缩窄到 `char` 可能把一个合法字节与 `EOF` 混淆。循环结束后检查 `ferror(stdin)`，因为 `EOF` 返回既可能表示正常文件尾，也可能表示读取错误。赋值外的括号不是装饰：`!=` 的优先级高于赋值，去掉会把比较结果 0/1 赋给变量。

## 数组、函数与值传递

字符计数程序用数组把“每个数字出现次数”映射为十个槽位。数组下标必须先证明处于范围；从字符 `'0'` 到 `'9'` 的连续性由 C 字符集规则保证，因此 `character - '0'` 可得 0 到 9。

```c
#include <stddef.h>
#include <stdio.h>

int print_counts(const unsigned long counts[], size_t count)
{
    size_t index;

    for (index = 0; index < count; ++index)
        if (printf("%lu: %lu\n", (unsigned long)index, counts[index]) < 0)
            return 0;
    return 1;
}

int main(void)
{
    unsigned long digits[10] = { 0 };
    int character;

    while ((character = getchar()) != EOF)
        if (character >= '0' && character <= '9')
            ++digits[character - '0'];
    if (ferror(stdin))
        return 1;
    return print_counts(digits, sizeof digits / sizeof digits[0]) ? 0 : 1;
}
```

C 的

<Term def="函数形参接收实参值的副本；传入指针时复制的是地址值，函数可通过副本访问所指对象，但不能改变调用者指针变量本身。">值传递</Term>
适用于所有普通参数。数组形参会调整为指针，所以 `print_counts`
内部无法从形参恢复数组元素数，必须另传
`count`。这并不是“数组按引用传递”；调用者数组未被复制，但形参仍是一个指针值副本。

## 字符数组与完整记录

<Term def="元素为 char 的数组；只有在可达范围内存在结尾空字符时，才满足 C 字符串协议。">字符数组</Term>
可以保存文本，也可以只保存原始字符。K&R
的最长行示例把输入、长度计算和最大值更新拆成函数，揭示了容量契约：读入函数必须知道数组上限，返回长度要说明是否包含换行，以及长行是截断、分段还是失败。

```c
#include <stdio.h>

enum LineResult {
    LINE_END = 0,
    LINE_COMPLETE = 1,
    LINE_TOO_LONG = 2,
    LINE_ERROR = -1
};

int read_line(char line[], int capacity, int *length)
{
    int character;
    int used = 0;
    int too_long = 0;

    while ((character = getchar()) != EOF && character != '\n') {
        if (used + 1 < capacity)
            line[used++] = (char)character;
        else
            too_long = 1;
    }
    line[used] = '\0';
    *length = used;
    if (character == '\n')
        return too_long ? LINE_TOO_LONG : LINE_COMPLETE;
    if (ferror(stdin))
        return LINE_ERROR;
    if (used != 0 || too_long)
        return too_long ? LINE_TOO_LONG : LINE_COMPLETE;
    return LINE_END;
}
```

接口前置条件是 `capacity > 0` 且两个指针有效。容量耗尽后，函数继续消费到换行或文件尾，因此不会把同一逻辑行误当成下一条；`LINE_TOO_LONG` 告诉调用者缓冲内容只是前缀。末行没有换行但含字符时仍返回完整记录，只有文件尾且本次未读字符才返回 `LINE_END`。字符数组容量永远包括结尾空字符位置，拷贝和拼接也要先检查目标剩余空间。

<Callout type="trap">
  **现象**：`read_line`
  返回了一个以空字符结尾的数组，调用者就认定输入记录完整。**原因**：字符串终止只证明缓冲区可安全按字符串读取，不证明已经消费换行或文件尾。**修法**：让结果同时携带长度和完成状态，超长时选择继续消费、动态扩容或拒绝，并测试恰好填满边界。
</Callout>

## 外部变量与作用域：声明不等于定义

<Term def="在函数外定义、具有静态存储期的对象；可通过外部链接跨翻译单元共享，也可用 static 限制为当前翻译单元内部。">外部变量</Term>
帮助第一章把多个函数共享的状态连起来，但也扩大隐藏依赖。一个具有外部链接的对象只能有一个定义，其他翻译单元通过
`extern` 声明引用；头文件通常放声明，某个 `.c` 文件放定义。

<Term def="标识符在源程序中可见的区域规则，包括块作用域、函数作用域、函数原型作用域和文件作用域；它不等同于对象生命周期或链接属性。">作用域</Term>
只回答名字在哪里可见。存储期回答对象存在多久，链接回答不同声明是否指同一实体。块内
`static` 对象具有静态存储期，却只有块作用域；文件作用域 `static`
名字具有内部链接，不会暴露给其他翻译单元。

```c
/* counter.h */
extern unsigned long error_count;
void note_error(void);

/* counter.c */
unsigned long error_count = 0;
static unsigned long call_count = 0;

void note_error(void)
{
    ++call_count;
    ++error_count;
}
```

全局可变状态让测试、并发和重用更难；优先把状态放进结构体并显式传入。确需跨文件共享时，通过函数维护不变量，并把不应公开的名字设为内部链接。头文件保护、兼容函数原型和单一定义共同构成模块边界。

读一个表达式时先问值域与求值规则；读一个循环时问不变量和退出条件；读函数时问前置条件、返回状态和修改范围；读指针时问对象、边界、对齐与生命周期；读结构体时问整体不变量和资源复制；读 I/O 时问外部格式、部分进度和提交失败。

<Term def="让代码只依赖目标标准或平台明确承诺的行为，并把实现定义、未指定和平台扩展隔离在有文档与测试的模块内。">可移植边界</Term>
要求把 ISO C、具体 C 版本、POSIX 和编译器扩展分开。K&R 第二版以 ANSI C

## 综合练习：文本统计器的资源所有权

一个可靠的小项目可以读取文件，统计行数、字符数和最长行，再输出报告。先写状态结构和接口：打开失败不产生统计；每次读取只在成功后更新；超长行按分片或拒绝策略处理；输出和关闭失败向调用者传播。

<Term def="明确每个动态对象、流或描述符由哪个模块负责最终释放，以及借用者可使用到何时的协议。">资源所有权</Term>
可用单一清理出口表达，但 `goto cleanup`
不是自动安全：只有已经成功取得的资源才能释放，错误码要在清理前保存，关闭失败还可能升级最终结果。

```c
#include <stdio.h>

int count_file(const char *path)
{
    FILE *stream = NULL;
    char buffer[256];
    unsigned long chunks = 0;
    int result = 0;

    stream = fopen(path, "r");
    if (stream == NULL)
        goto cleanup;
    while (fgets(buffer, sizeof buffer, stream) != NULL)
        ++chunks;
    if (ferror(stream))
        goto cleanup;
    if (printf("chunks=%lu\n", chunks) < 0)
        goto cleanup;
    result = 1;

cleanup:
    if (stream != NULL && fclose(stream) == EOF)
        result = 0;
    return result;
}
```

这里统计的是缓冲片段，不一定是逻辑行，名字刻意叫 `chunks`。若需求是行数，必须识别换行和无末尾换行；这体现“变量名、接口和实现必须讲同一个协议”。更完整版本还会把输出流传入，避免库函数硬编码 `stdout`，并返回可诊断的错误类别。

## 验证不是只运行一次

编译器警告可以发现缺失原型、格式不匹配、可疑转换和未使用结果；单元测试检查纯函数，集成测试模拟文件尾、长行、短写与关闭失败；AddressSanitizer、UndefinedBehaviorSanitizer 等实现工具可扩大动态观测。它们只覆盖被执行路径，不能证明所有输入都安全。

<KrVerificationLoopMap />

先预测结果与失败状态，再运行测试。对边界代码，既检查返回值，也检查输出内容、流状态和资源是否释放。对平台代码，在支持矩阵上实际编译运行；对实现定义行为，用编译器文档和静态断言锁定目标，而不是从一次实验外推所有系统。

<Callout type="trap">
  **现象**：程序通过普通样例和动态检测，就被认定“没有未定义行为”。**原因**：动态工具只观察实际路径，优化级别、输入和平台变化可能暴露新问题。**修法**：先用标准与接口契约排除非法操作，再用警告、边界测试、故障注入和动态工具提供互补证据。
</Callout>

## 小结

- 第一章从 `main` 和 hello world 建立反馈，再用温度表、`for`、符号常量、字符 I/O、数组与函数逐步扩展
- 变量与表达式必须先确定计算类型；循环由不变量、范围和退出条件证明，而不是靠样例直觉
- `getchar` 返回 `int` 以容纳所有字符值和 `EOF`；数组形参调整为指针，元素数必须另传
- 字符数组以空字符满足字符串协议，但仍要另行判断记录是否完整；外部变量、作用域、存储期和链接是不同维度
- 全书可以按表示、控制、接口、内存、数据模型和系统边界六层检查契约
- 小型 C 项目也要明确资源所有权、部分 I/O、错误传播和关闭结果，并用多层证据验证

<Exercises>

**问题 1** 从华氏温度表解释 `5 / 9` 与 `5.0 / 9.0` 的差异，并为 `for` 循环写出一个范围不变量和一个终止风险。

<Answer>

两个整数相除在整数域计算，`5 / 9` 截断为 0，之后转换为浮点也仍是 0；至少一个操作数为浮点时，`5.0 / 9.0` 得到浮点比例。循环不变量可写为：每次循环体开始时，`fahrenheit` 是从 `LOWER` 按 `STEP` 推进得到且尚未超过 `UPPER` 的当前刻度。若步长为零、方向与条件不一致，或有符号加法在越过上界前溢出，循环可能不终止或先产生未定义行为。

</Answer>

**问题 2** 设计一个读取任意长度逻辑行的接口，说明 `EOF`、末行无换行、缓冲分片、分配失败和空字符终止如何分别表达。

<Answer>

接口应返回独立状态，例如完整行、正常结束、读取错误、分配失败和超出策略上限，并通过输出参数给出缓冲与长度。每次 `fgets` 或字符读取成功后累积，看到换行完成一行；文件尾前已有字符时仍返回最后一行，同时标记无换行；文件尾且无字符才是结束。每次扩容先检查尺寸溢出，分配失败保留或释放旧缓冲按文档处理。成功文本始终额外保留一字节写空字符，长度不包含该终止符。

</Answer>

**问题 3** 对“打开输入、生成统计、写输出”的程序列出六层契约中各一项检查，并说明动态检测为何不能替代它们。

<Answer>

表示层检查计数类型与溢出；控制层检查读取循环只在成功后更新且会终止；接口层检查函数返回值、容量与修改范围；内存层检查缓冲边界和生命周期；数据模型层检查统计结构不变量；系统边界检查打开、部分读取、输出和关闭失败。动态检测只能观察本次构建和输入走过的路径，无法覆盖所有错误分支、平台差异或未触发的未定义行为，因此必须与标准推理、编译警告、边界测试和故障注入结合。

</Answer>

</Exercises>

</GlossaryItem>

<GlossaryItem term="循环不变量">
  每次迭代前成立且被循环体保持的事实，与退出条件一起用于证明范围、结果和终止。
</GlossaryItem>

<GlossaryItem term="字符输入输出">
  逐字符读取和写出的流协议，读取结果使用 `int` 区分全部 `unsigned char` 值与
  `EOF`。
</GlossaryItem>

<GlossaryItem term="值传递">
  函数形参取得实参值副本；指针参数复制地址值，数组形参则调整为指针并需要独立长度契约。
</GlossaryItem>

<GlossaryItem term="字符数组">
  由 `char` 元素组成的数组，只有在边界内含结尾空字符时才是 C 字符串。
</GlossaryItem>

<GlossaryItem term="外部变量">
  函数外定义的静态存储期对象，可具有外部链接或以 `static` 限制为翻译单元内部。
</GlossaryItem>

<GlossaryItem term="作用域">
  标识符在源程序中可见的区域规则，不等于对象存储期，也不等于跨翻译单元链接属性。
</GlossaryItem>

<GlossaryItem term="可移植边界">
  只依赖目标标准或平台承诺，并把实现定义行为和扩展隔离在有文档、有测试的适配模块内。
</GlossaryItem>

<GlossaryItem term="资源所有权">
  规定对象或 I/O
  资源由谁最终释放、借用持续多久以及失败路径怎样移交或回滚的协议。
</GlossaryItem>

</Glossary>
