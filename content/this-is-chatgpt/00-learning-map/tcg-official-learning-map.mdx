## 实验一：可交换的先修顺序，不可丢失的依赖

把“必须先能解释A，才开始B”写成有向边A→B，得到一张本站教学用的<Term def="用有向边表示某任务必须在另一任务之前完成的图；本页无环。">先修图</Term>。节点P、N、E、T、A、G依次代表概率、网络、嵌入、训练、注意、生成。这里的边是练习假设，不是语言模型的实际运行依赖，也不表示作者只允许这一种阅读顺序。

边集合为P→N、N→T、N→A、E→A、T→G、A→G。每轮只能从<Term def="尚未处理且所有前驱都已完成的节点集合。">零入度前沿</Term>取一个节点，再删除它的出边。前沿可能同时有多个节点，所以优先级只解决“都可学时先选谁”，不能让缺少先修的节点提前合法。

先预测：即使把训练T排在优先级第一，默认规则会不会真的先取T？动手单步到结束，记录每次前沿；再只注入“漏掉N→T”。观察训练为何在第一步就被错误地放行，以及红虚线指向的依赖缺项。

<TcgOfficialLearningMapContextContractLab />

默认前沿是P、E；按训练优先规则依次得到P,E,N,T,A,G，所有边都顺向。故障图却把T放到起点，得到T,P,E,N,A,G。**规划器只能保证自己看见的边**；用未删边的真实图复核，N→T就是反例。改成“表征优先”后，即使漏边，E,P,N,A,T,G仍合法：一次成功路线不能证明边表完整。

下面的Python独立执行同一有限消元过程，不读取组件，也不查询模型。候选列表按优先级排列；`all`检查的是当前规划器所用的边。

```python
edges = [("P", "N"), ("N", "T"), ("N", "A"),
         ("E", "A"), ("T", "G"), ("A", "G")]
priority = ["T", "P", "E", "N", "A", "G"]
def topo(priority, fault=False):
    seen = []
    used = [e for e in edges if not (fault and e == ("N", "T"))]
    while len(seen) < len(priority):
        ready = [n for n in priority if n not in seen and
                 all(b != n or a in seen for a, b in used)]
        assert ready, "This teaching graph must stay acyclic"
        seen.append(ready[0])
    return "".join(seen)
assert topo(priority) == "PENTAG"
assert topo(priority, True) == "TPENAG"
assert topo(list("EPNATG"), True) == "EPNATG"
print("orders", topo(priority), topo(priority, True))
```

恢复时点击“全部重置”，优先级应回到训练优先，故障关闭，进度归零且暂停。完整模型没有环；若以后给图增加环，零入度算法可能提前无候选，应报告不可排而不是硬拼一条路线。

## 实验二：关键路径下界，为什么不是实际结束时刻

把每个任务的耗时写在区间上，一条依赖链上耗时之和最大的链称为<Term def="在任务依赖图中总耗时最长的链，给出不受资源争用影响的完工下界。">关键路径</Term>。但同一个人不能同时做两件事；可同时运行的任务上限是<Term def="本页中同时执行的任务数上限；每个任务占用一个名额且不被中断。">并行容量</Term>。这两种约束不是同一个东西。

这里另设五任务：R阅读耗时2，V向量耗时3，F前向耗时f，B反向耗时2，C对照耗时1。只有R完成后V和F才能开始；B等待V与F都结束，C再等待B。时间单位是任意教学单位，不是读者预计用时，更不是训练吞吐或硬件基准。

对f≥3，最长链R→F→B→C的长度为5+f；f=3时另一分支同样长。若容量为1，全部工作不能重叠，最短时间是2+3+f+2+1=8+f；容量至少2，两个分支可并行，才达到5+max(3,f)。默认f=4时二者分别为12和9。

先预测：只把并行容量从1改成2，哪些条形的起点会左移？随后回到容量1再注入“忽略并行名额”，观察占用阶梯越过容量线的区间，而不是只看结束数字变小。

<TcgOfficialLearningMapComputeTraceLab />

默认排程为R[0,2)、V[2,5)、F[5,9)、B[9,11)、C[11,12)。两人排程把F移到[2,6)，B移到[6,8)，C移到[8,9)。故障在容量1时仍画后一种排程，但[2,5)内并行占用为2，因此9不是可行结果。容量已为2或3时，该故障不产生违例；本图只有两个可并行分支，第三个名额不会继续缩短时间。

下面的数值不舍入，全部是整数。总工作量给出容量1的精确答案；对这张特定的分叉汇合图，两个名额足以达到关键路径下界。不能把这个闭式结果套给任意资源受限任务图。

```python
def calendar(workers, f, fault=False):
    forward_start = 2 if workers >= 2 or fault else 5
    tasks = [(0, 2), (2, 5), (forward_start, forward_start + f)]
    join = max(b for a, b in tasks)
    tasks += [(join, join + 2), (join + 2, join + 3)]
    finish = join + 3
    occupancy = [sum(a <= t < b for a, b in tasks)
                 for t in range(finish)]
    bad = [t for t, n in enumerate(occupancy) if n > workers]
    return finish, bad
assert calendar(1, 4) == (12, [])
assert calendar(2, 4) == (9, [])
assert calendar(1, 4, True) == (9, [2, 3, 4])
assert calendar(3, 6) == (11, [])
print("finish", calendar(1, 4), calendar(2, 4))
```

## 实验三：最少实验，不等于足以区分所有错误

在遇到一个错误回答时，“多做几个例子”未必比有针对性地选实验有效。这里给出四个**预设假设**：H0无错、H1切词错、H2因果遮罩错、H3单位错。每个实验返回0或1，仅代表下表规定的响应。我们没有运行真实模型，也没有断言现实故障一定产生这些响应。

| 实验            | H0  | H1  | H2  | H3  | 成本 |
| --------------- | --- | --- | --- | --- | ---- |
| a：联合探针甲   | 0   | 1   | 1   | 0   | 3    |
| b：联合探针乙   | 0   | 0   | 1   | 1   | 3    |
| c：切词定向探针 | 0   | 1   | 0   | 0   | 1    |
| d：遮罩定向探针 | 0   | 0   | 1   | 0   | 1    |

一个实验若让两个假设产生不同响应，就将这一对分开。四个假设共有6对；选择的实验必须让每一对至少被分开一次。所选实验按a,b,c,d顺序组成的响应串叫<Term def="一个假设在选定实验上产生的有序响应串；签名相同意味着这些实验仍无法区分它们。">诊断签名</Term>。例如选择a,b时，四个签名为00、10、11、01，互不相同。

先预测：“实验数最少”和“成本最少”是否会选同一集合？再只让优化器漏检H0/H3这一对，看低成本集合留下哪条未断开的歧义线。

<TcgOfficialLearningMapEvidenceGateLab />

完整检查6对时，最少实验是a,b，共2个、成本6；成本最少却是b,c,d，共3个、成本5，签名000、010、101、100。故障仅漏检H0/H3，两个目标都会选择c,d，成本2；H0和H3都返回00，因此“没发现单位故障”与“真的无错”仍混在一起。把候选范围改成仅H0–H2后，c,d本来就足够：诊断保证总是相对于纳入的候选集。

穷举只有16个子集，足够给出确定性最优解。先构造候选及区分约束，平局时固定按位掩码顺序选择，以免把偶然次序混进比较。

```python
from itertools import combinations
responses = [(0, 1, 1, 0), (0, 0, 1, 1),
             (0, 1, 0, 0), (0, 0, 1, 0)]
costs = [3, 3, 1, 1]
def choose(objective="fewest", count=4, fault=False):
    pairs = list(combinations(range(count), 2))
    checked = [p for p in pairs if not (fault and p == (0, 3))]
    feasible = []
    for mask in range(16):
        tests = [i for i in range(4) if mask & (1 << i)]
        if all(any(responses[t][a] != responses[t][b] for t in tests)
               for a, b in checked):
            cost = sum(costs[t] for t in tests)
            rank = (len(tests), cost) if objective == "fewest" else (cost, len(tests))
            feasible.append((rank, mask, tests, cost))
    _, _, tests, cost = min(feasible)
    sig = ["".join(str(responses[t][h]) for t in tests)
           for h in range(count)]
    return "".join("abcd"[t] for t in tests), cost, sig
```

这些断言同时检查最优集合、成本和签名碰撞。后两组循环覆盖所有控件组合与“第三名额无收益”“候选范围缩小后故障无效”的边界；运行时不访问网络、不训练模型。

```python
assert choose() == ("ab", 6, ["00", "10", "11", "01"])
assert choose("cost") == ("bcd", 5, ["000", "010", "101", "100"])
assert choose(fault=True) == ("cd", 2, ["00", "10", "01", "00"])
for workers in (1, 2, 3):
    for f in (3, 4, 6):
        expected = 8 + f if workers == 1 else 5 + max(3, f)
        assert calendar(workers, f) == (expected, [])
for goal in ("fewest", "cost"):
    assert choose(goal, 3) == choose(goal, 3, True)
print("diagnosis", choose(), choose("cost"), choose(fault=True))
```

## 三种路线判断，不能互相代替

先修消元回答“能否现在开始”，排程回答“在给定资源内何时结束”，诊断集合回答“这些观察能否区分候选解释”。三者都需要明确输入，但它们的输出不是同一种学习得分；将任何一个压成“完成率”会丢失关键反例。

<Callout type="trap">
  **现象 →** 漏边的规划仍给出一条看似合法的路线。 **原因 →**
  规划器只检查自己看见的边；目录顺序也不等于严格先修。 **修法 →**
  用独立的原始边表复核，并换取出优先级寻找潜伏反例。
</Callout>

<Callout type="trap">
  **现象 →** 单人排程看上去也只要9。 **原因 →**
  只算关键路径，却把同一人同时安排到两个分支。 **修法 →**
  在每个区间检查占用是否超过容量；默认单人可行结果是12。
</Callout>

<Callout type="trap">
  **现象 →** c,d分出了H1和H2，却把H0与H3混在一起。 **原因 →**
  求解时漏检了一个候选对；实际系统还可能有未列出的故障。 **修法 →**
  检查完整候选表的每一对，再明确结论只限于该有限表。
</Callout>

<Exercises>

**问题 1** 默认优先级中T排第一，为什么正常序列却从P开始？注入漏N→T后首个错误是什么？

<Answer>

T还有前驱N，不能仅凭优先级进入前沿。起始零入度节点只有P、E，故先取P。删N→T后T也成了零入度候选，立即被取出；用原图检查，第一步T缺少N。表征优先下没有暴露错误只是该路线恰好先走N，不证明漏边安全。

</Answer>

**问题 2** 修改正文Python调用，把`calendar(workers, 4)`中的F耗时参数改成6，并为容量1、2、3各写一条断言；结束时间应是多少？为什么不能用“工作量除容量”直接给出答案？

<Answer>

可分别断言`calendar(1, 6) == (14, [])`、`calendar(2, 6) == (11, [])`和`calendar(3, 6) == (11, [])`。总工作量为14，容量1需14；关键路径为2+6+2+1=11，容量2或3均需11。14/2=7只是不考虑依赖的工作量下界，低于关键路径11；第三个名额也不能让汇合后的B越过尚未结束的F。

</Answer>

**问题 3** 成本最少为什么选b,c,d而不是a,b？只选c,d时，哪一对假设仍不可区分？

<Answer>

b,c,d的成本是3+1+1=5，低于a,b的6，且四个签名000、010、101、100都不同。c,d虽只花2，但H0和H3都是00。错误地漏检这一对会让优化器把未完成的诊断当作完成。最少实验数和最少成本是两个不同目标。

</Answer>
