## 从一句没写完的话开始

输入一句没写完的话，屏幕接出一点；把新增部分留在句尾，再接一点。整段文章看起来像一次完成，实际可以由许多次很小的选择组成。

问题在于：每次新增的到底是什么？上一次选了不同的内容，下一次还能照搬原来的选择表吗？不分清这两件事，就容易把“文字很顺”误当成“整段答案已经预先想好”。

## What Is ChatGPT Doing ... and Why Does It Work? / ChatGPT在做什么，为什么有效？

## It's Just Adding One Word at a Time / 一次只添加一个词

标题中的“词”是直觉入口，不能当成严格计量单位。实际模型处理的离散片段称为 <Term def="词表中用一个编号表示的离散片段；可能是整词、词的一部分或字节片段">token</Term>。一次新增一个编号，解码后却可能只得到一个单词的一部分；有的字节片段单独还不是完整字符。

### 先把“新增一个”放到字节坐标上

字符、字节、词不是三种说法而已。`猫 eats` 有 6 个 Unicode 码点，UTF-8 编码占 8 个字节；英语字母段只有 `eats` 一段。汉字如何构成中文词，需要另一个分词问题，不能靠空格或英语正则回答。实验 1 的“字符”专指码点，不涵盖由多个码点组成的可见字形。

实验沿字节从左到右，在**手工词表**中取能匹配的最长片段；没有匹配就退回一个字节。碎片词表让“猫”的三个字节各占一个 token，`eats` 切成 `eat` 和 `s`；较长片段词表则可以把“猫”放进一个 token，并把空格与 `eats` 合成另一片段。相同文本不变，token 数却从 6 变成 2。

这不是 BPE 算法、真实模型词表或真实 tokenizer。它只隔离一个可检查事实：**编号边界不必和字符边界、单词边界重合**。合并所有 token 的字节再解码，可以还原原文；若错误地要求每个 token 都能单独按 UTF-8 解码，字节兜底片段就会被拒绝。

下面的 Python 程序只用标准库。把本页所有 `python` 代码块按出现顺序拼入同一个文件即可执行，变量会在后续代码块继续使用。第一段先生成真正的 UTF-8 字节跨度，而不是按显示宽度猜位置。

```python
import math
import re

LEXICONS = {
    "pieces": ["re", "play", "ing", " ", "eat", "s", "!"],
    "coarse": ["猫", " eats", "replaying", "!"],
}

def segment(text, mode):
    raw = text.encode("utf-8")
    vocab = sorted((s.encode() for s in LEXICONS[mode]),
                   key=len, reverse=True)
    spans, start = [], 0
    while start < len(raw):
        token = next((v for v in vocab if raw.startswith(v, start)),
                     raw[start:start + 1])
        end = start + len(token)
        spans.append((start, end, token))
        start = end
    return spans
```

`start/end` 是半开字节区间，不是字符下标。下一段检验拼接可逆，并亲自执行那个错误解码步骤；`UnicodeDecodeError` 才是故障证据，而不是把正常输出换成一条红色说明。

```python
text = "猫 eats"
pieces = segment(text, "pieces")
coarse = segment(text, "coarse")
assert (len(text), len(text.encode()), len(pieces), len(coarse)) == (6, 8, 6, 2)
assert re.findall(r"[A-Za-z]+", text) == ["eats"]
assert b"".join(t for _, _, t in pieces).decode() == text
try:
    pieces[0][2].decode("utf-8", errors="strict")
except UnicodeDecodeError:
    pass
else:
    raise AssertionError("故障应在第一个字节片段暴露")
assert all(t.decode() for _, _, t in coarse)
assert len(segment("replaying!", "pieces")) == 4
assert len(segment("replaying!", "coarse")) == 2
assert segment("", "pieces") == []
print("字节跨度:", [(a, b) for a, b, _ in pieces])
```

### 新增内容以后，下一步的条件变了

对固定前缀给所有候选分配非负、总和为 1 的数，称为 <Term def="在给定已有前缀后，各个下一片段出现的概率列表">条件分布</Term>。这里的“条件”不能省略：`上下文+A` 和 `上下文+B` 是不同输入，下一步概率允许不同。

把每次选中的 token 追加到前缀，再用这个新前缀求下一步分布，就是 <Term def="把已经生成的片段作为后续输入，逐步生成下一个片段的方式">自回归生成</Term>。追加不是修改模型参数；这里只改变下一次计算看到的输入。实验 2 用固定表模拟这件事，不训练模型，也不从语料计数估计概率。

符号中，$c$ 是已有上下文，$a$ 是第一步选择，$x$ 是第二步选择。两步路径的概率为：

$$
P(a,x\mid c)=P(a\mid c)\,P(x\mid c,a).
$$

这个式子在说：先走到第一条边，再在已经到达的分支上走第二条边，整条路径的概率是两条条件概率相乘。

上下文 A 的根上，A 比 B 更大：0.6 对 0.4。走 A 后，`x/停` 是 0.51/0.49；走 B 后却是 0.99/0.01。因此每步取最大（贪心）会选 `A→x`，概率为 0.306；另一条 `B→x` 的概率却为 0.396。**局部最大不推出联合最大**，这是数值反例，不是关于所有文章质量的定理。

“停”表示结束标记 EOS，选到就停止。图中的 `x` 只是第二个普通 token；实验只展开两步，并未提供 `x` 之后的分布。全树的四叶比较用于离线验证，不意味着贪心在第一步偷看了第二步。

猜一猜：第一步指定 B 后，第二步还该使用 A 的 0.51/0.49 吗？故障开关只让第二步照抄根表；即使四个叶子加起来仍是 1，为什么计算已经错了？

<TcgMain01OneWordAtATimeComputeTraceLab />

代码把每个条件表分开存储，再枚举四条两步路径。注意 `children[first]` 这一行依赖已经追加的 token；故障恰好破坏这处依赖，而不是更换上下文或同时更换多个概率。

```python
TREES = {
    "A": ([0.6, 0.4], [[0.51, 0.49], [0.99, 0.01]]),
    "B": ([0.2, 0.8], [[0.9, 0.1], [0.25, 0.75]]),
}

def paths(context, fault=False):
    root, children = TREES[context]
    if fault:
        children = [root, root]
    return [root[i] * children[i][j]
            for i in range(2) for j in range(2)]

reference = paths("A")
assert all(math.isclose(a, b) for a, b in
           zip(reference, [0.306, 0.294, 0.396, 0.004]))
assert math.isclose(sum(reference), 1)
assert reference.index(max(reference)) == 2
assert reference[0] < reference[2]
assert math.isclose(paths("A", fault=True)[0], 0.36)
assert paths("A") == reference  # 撤销故障，恢复同一输入
assert paths("B") != reference
print("两步路径 Ax/A停/Bx/B停:", reference)
```

### 同一张表，还要决定怎样选择

分布不变，也可以采用不同选择规则。贪心直接拿最大项，不使用随机数；随机采样让候选按指定概率获得机会。<Term def="在采样前调节候选概率集中程度的正数；零温度通常另行约定为取最大项">温度</Term>改变的是分布形状，不是文本中事实的可信度，更不是模型的“理解深度”。

令 $p_i$ 为原始候选概率，$T$ 为温度，$q_i$ 为变换后的概率。对 $T>0$：

$$
q_i=\frac{p_i^{1/T}}{\sum_j p_j^{1/T}}.
$$

这个式子在说：先把每项做同一个幂变换，再除以总和；大概率项与小概率项的相对差距随温度变化。若原概率来自某组原始分数的指数归一化，这与先把分数除以温度再归一化相同；不需要在本节引入训练过程。

$T=1$ 保持原分布；$T<1$ 让非并列的高概率项更占优势；$T>1$ 让正概率项更接近。原概率为零的项仍为零，不能靠升温“发明”新候选。$T=0$ 不能代入除法，本页另设为取最大项，并列最大取第一个编号；这是一条明确的演示约定。

将 `[0.6,0.3,0.1]` 的温度设为 0.5，先平方得到 `[0.36,0.09,0.01]`，总和 0.46，再除以总和得到约 `[0.782609,0.195652,0.021739]`。若漏掉最后一步，它们只是总长 0.46 的区间，不是覆盖单位区间的概率。

最后用 <Term def="将概率按顺序累加成区间，再用一个零到一之间的数定位候选的离散采样法">逆 CDF 采样</Term>完成一次选择。设 $u$ 是落在 $[0,1)$ 的抽样数，$F_k=\sum_{i=0}^{k}q_i$ 且 $F_{-1}=0$，选择满足下式的编号 $k$：

$$
F_{k-1}\le u<F_k.
$$

这个式子在说：候选占有自己的左闭右开区间，抽样数落到哪一段就选哪项。恰好等于分界点时归右侧；显示时的小数舍入不应反过来改变内部边界。实验固定 $u$ 是为了复算，真实随机采样还需给出随机数来源。

猜一猜：保持默认 $p$、$T=0.5$、$u=0.60$，漏掉归一化会发生什么？再只把 T 改成 1，为什么同一个故障开关会暂时没有影响？

下面实现温度变换。正常路径用对数后减去最大值，避免非常小的温度使所有幂都下溢成零；零概率保留为负无穷再转回零。输入不是合法分布或温度为负时直接拒绝。

```python
def temper(p, temperature):
    if (not p or any(not math.isfinite(v) or v < 0 for v in p)
            or not math.isclose(sum(p), 1, abs_tol=1e-12)):
        raise ValueError("需要总和为1的非负概率")
    if not math.isfinite(temperature) or temperature < 0:
        raise ValueError("温度必须有限且非负")
    if temperature == 0:
        winner = p.index(max(p))
        return [float(i == winner) for i in range(len(p))]
    if temperature == 1:
        return list(p)
    logs = [math.log(v) / temperature if v else -math.inf for v in p]
    peak = max(logs)
    weights = [math.exp(v - peak) for v in logs]
    total = sum(weights)
    return [v / total for v in weights]
```

采样函数检查总和与随机数范围。故障演示可以显式关闭总和检查，观察空洞；生产实现不应为了“总能输出”而悄悄把空洞归给最后一项。末尾的浮点保护只适用于已通过总和检查、累计舍入导致的微小缺口。

```python
def sample(q, u, validate=True):
    if not 0 <= u < 1:
        raise ValueError("u必须在[0,1)")
    if not q or any(not math.isfinite(v) or v < 0 for v in q):
        raise ValueError("无效权重")
    normalized = math.isclose(sum(q), 1, rel_tol=0, abs_tol=1e-12)
    if validate and not normalized:
        raise ValueError("未归一化")
    edge = 0.0
    for i, probability in enumerate(q):
        edge += probability
        if u < edge:
            return i
    if validate and normalized:
        return max(i for i, v in enumerate(q) if v > 0)
    return None

p = [0.6, 0.3, 0.1]
q = temper(p, 0.5)
assert all(math.isclose(a, b) for a, b in zip(q, [36/46, 9/46, 1/46]))
assert sample(q, 0.60) == 0
assert sample([v*v for v in p], 0.60, validate=False) is None
assert sample(temper(p, 1), 0.60) == 1
print("温度0.5:", q, "u=0.60选择", "ABC"[sample(q, 0.60)])
```

最后的断言刻意覆盖默认演示以外的边界：零温度、并列最大、零概率、很小的正温度、精确区间分界点，以及非法输入。它们验证算法约定，不证明真实模型的输出质量。

```python
assert temper([0.5, 0.5, 0], 0) == [1, 0, 0]
assert temper([0.6, 0.4, 0], 2)[2] == 0
assert temper(p, 0.001)[0] > 0.999
assert sample([0.5, 0.5], 0.5) == 1
assert sample([0, 1], 0) == 1
assert sample(q, math.nextafter(1, 0)) == 2

for bad_p, bad_t in [([0, 0], 1), ([-0.1, 1.1], 1), (p, -1)]:
    try:
        temper(bad_p, bad_t)
    except ValueError:
        pass
    else:
        raise AssertionError("非法参数未被拒绝")
for bad_u in [-0.1, 1.0]:
    try:
        sample(q, bad_u)
    except ValueError:
        pass
    else:
        raise AssertionError("非法抽样数未被拒绝")
print("全部边界断言通过；没有加载或运行真实语言模型。")
```

## 三个需要分开的判断

下面三个误区分别破坏了表示、条件依赖和选择规则，不能靠“最终句子读起来正常”来排除。先在实验中找到首个偏差，再判断它是否足以支持自己的解释。

### 一个 token 就是一个完整单词

**现象 →** 以空格数估算 token 数，或认为每个 token 都能独立显示。

**原因 →** 混淆字节、码点、英语单词与词表编号的边界。

**修法 →** 在实验 1 保持文本不变切换词表；再检查拼接后解码，而非强制逐 token 解码。

### 每一步选最大，整段概率就最大

**现象 →** 把 `A→x=0.306` 当成树中最大路径。

**原因 →** 只比较首条边，忽略选定前缀会改变后续条件分布。

**修法 →** 在实验 2 手算 `B→x=0.396`，再撤销“照抄根分布”故障确认恢复。

### 温度越大越懂，0.8 永远最好

**现象 →** 把不同措辞当成更可靠的事实，或将一个参数值当通用最优。

**原因 →** 混淆概率形状、抽样结果和任务质量；作者首节的 0.8 是历史示例观察。

**修法 →** 用实验 3 固定分布与抽样数只变温度，再单独评估任务事实；本页不声称哪种温度改善所有任务。

## 小结与练习

本页把一次新增拆成了“确定片段边界、根据新前缀重算、按规则选择”三个可复算问题。接下来的概率章讨论概率从哪里来；这里的数字均为手工给定，不能拿它们作为训练结果。

- 字节、字符、词与 token 边界不必重合。
- 新前缀决定下一步条件表，局部最大不保证联合最大。
- 温度改变区间；抽样数定位区间，不能漏掉归一化。

  [0,0.46)，0.60 落在空洞。T=1 时恢复原分布，0.60 恰在 B 的左端，所以选
  B；u=0.95 落在 C。C
  被抽中只说明选择规则，不证明内容的正确性，示意数据也不包含可核查的语义事实。
</Answer>
