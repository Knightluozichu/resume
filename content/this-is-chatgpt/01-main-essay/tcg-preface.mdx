## 直觉：看到同一输出，不等于辨认了机制

假设两台机器都给出“甲走”。第一台只存了“甲走、乙停”两条记录；第二台保存两个独立词槽，主语可选甲或乙，动作可选走或停。单看这次输出无法分辨机器。查询“甲停”才把它们分开：第一台没有这条记录，第二台可以组合出来。这不是说神经网络只做词槽组合，而是说明观察样本不足时，机制可以有多种解释。

这里的<Term def="两个集合中的每个元素分别配对，得到全部有序组合">笛卡尔积</Term>把独立选择写成清楚的计算：主语集合为 $S$，动作集合为 $V$，输出集合是 $S\times V$。两槽各有 $m$ 个词，组合有 $m^2$ 种；只记同索引配对则有 $m$ 条。一个未存过的组合仍可能严格来自既定规则，“新串”不自动意味着新规则、新事实或理解。

### 实验一：配对记忆与词槽组合织线

**先预测：**各槽从两个词增加到三个词，查表记录与独立组合分别增加多少？如果错误地要求两个词槽必须取相同索引，会先失去哪一种查询？

<TcgPrefaceContextContractLab />

**操作：**默认查询“甲停”。逐步看实线记忆配对、交叉织线及全部组合，再把每槽词数改为 3。最后打开“误绑两个槽”，观察交叉连接变为虚线、输出圆减少。切换为“已存：甲走”可看到同一个故障为何没有影响这次查询；完整重置应回到两词、交叉查询、故障关闭、第一帧且暂停。

**解释：**默认表内 2 条、规则 4 种，查询“甲停”只有规则可产出。三词时是 3 与 9，故障把 9 压回 3，却仍保留甲走、乙停、丙等。这一因果差别来自槽之间的约束，不是“更聪明”的分数。有限人工规则会组合，并不能推出真实模型训练必然找到该规则，更不能推出组合句为真。

下面的 Python 只使用标准库。各代码块按正文顺序拼接就是一份完整程序；这里先定义两个槽和有限二进制字母表，后面两实验继续使用它们。

```python
from itertools import product

subjects = ("甲", "乙", "丙")
verbs = ("走", "停", "等")
def slot_outputs(m, tied=False):
    assert 1 <= m <= 3
    return {subjects[i] + verbs[j]
            for i in range(m) for j in range(m)
            if not tied or i == j}

def words(n):
    assert 0 <= n <= 5
    return ["".join(chars) for chars in product("ab", repeat=n)]

assert len(slot_outputs(2)) == 4
assert len(slot_outputs(3)) == 9
assert len(slot_outputs(3, tied=True)) == 3
assert "甲停" in slot_outputs(2)
assert "甲停" not in slot_outputs(2, tied=True)
assert slot_outputs(1) == {"甲走"}
assert words(0) == [""]
```

## 能生成，还要说明满足哪一条规则

词槽实验只约定如何拼接，没有约定何为合法。现在把字母表收窄到 a、b，给出两条明确要求：字符串不得含相邻的 bb，并可额外要求最后一个字符为 a。这样的玩具语言足够小，可以既生成又完整检查；它不等于人类语言的意义、事实和语用。把规则说得有限而明确，才能把“看起来合适”换成可复算的问题。

一个<Term def="由有限状态、输入字母和确定转移构成的逐步计算装置">有限自动机</Term>只需记住 A、B、X 三种状态。A 表示尚未违规且上一位不是 b（也包括初态），B 表示尚未违规且上一位是 b，X 表示已经读到 bb。X 是吸收拒绝态：后面再来 a 也不能抹掉曾经出现的 bb。允许任意末位时接受 A、B；末位必须为 a 时只接受非空串的 A。

### 实验二：状态前沿与独立扫描

**先预测：**四位串共有 16 个。若不含 bb 且以 a 结尾，究竟有几个？把“B 读 b 进入 X”误写成“B 读 b 留在 B”，末尾再来一个 a 能否蒙混过关？

<TcgPrefaceComputeTraceLab />

**操作：**默认长度 4、末位 a。逐帧读取字符数量，计数行一直保留此前结果；最后一步用另一种算法扫描全部字符串。切换长度 3、5 会改变前沿的行数，取消末位限制会把终态 B 也纳入接受。打开“错放行 bb”后，查看机器计数、独立扫描和首个误收串。短长度在读完后只保留终态，不多读字符。

**解释：**设读入 $t$ 位的前沿是 $(A_t,B_t,X_t)$，初态为 $(1,0,0)$。每条路径读 a、b 各延伸一次，正常转移为

$$
A_{t+1}=A_t+B_t,\qquad B_{t+1}=A_t,\qquad X_{t+1}=2X_t+B_t.
$$

因此四步依次得到 $(1,1,0)$、$(2,1,1)$、$(3,2,3)$、$(5,3,8)$，每行之和都为 $2^t$。末位 a 接受 5 个：aaaa、aaba、abaa、baaa、baba。故障下四步得到 $(8,8,0)$，错误接受 8 个；按字典序的首个误收串是 abba。总数仍是 16，所以只检查“计数守恒”发现不了规则失效。

```python
def frontier(n, faulty=False):
    assert 0 <= n <= 5
    rows = [(1, 0, 0)]
    for _ in range(n):
        a, b, x = rows[-1]
        rows.append((a + b, a + (b if faulty else 0),
                     2 * x + (0 if faulty else b)))
    return rows

def valid(s, end_a=True):
    return "bb" not in s and (not end_a or s.endswith("a"))

def accepted(n, end_a=True, faulty=False):
    a, b, _ = frontier(n, faulty)[-1]
    if n == 0 and end_a:
        return 0  # 空串没有末位，不能说“末位是a”
    return a if end_a else a + b

assert frontier(4)[-1] == (5, 3, 8)
assert frontier(4, True)[-1] == (8, 8, 0)
assert accepted(4) == 5
assert accepted(4, faulty=True) == 8
assert next(s for s in words(4)
            if s.endswith("a") and not valid(s)) == "abba"
```

上面的独立扫描直接找子串 bb，不借用状态转移表。它与自动机犯错的方式不同，这才有机会抓住“实现和测试一起写错”的问题。下面同时核对每一种长度、末位选择及空串边界；守恒是必要检查，不是充分检查。

```python
for n in range(6):
    for end_a in (False, True):
        oracle = sum(valid(s, end_a) for s in words(n))
        assert accepted(n, end_a) == oracle
    for t, row in enumerate(frontier(n)):
        assert sum(row) == 2 ** t
assert [accepted(n) for n in (3, 4, 5)] == [3, 5, 8]
assert [accepted(n, False) for n in (3, 4, 5)] == [5, 8, 13]
assert accepted(0, False) == 1
assert accepted(0, True) == 0
assert not valid("bba") and valid("baba")
```

## 解释必须允许一个输出把它推翻

规则执行正确，只是解释的一个层次。另一个层次是：我们想说的结论是否超出了已经检查的输入。考虑命题“对每个长度为 $n$ 的 a/b 字符串，某操作做两次就回到原串”。把主张中的“每个”、长度和操作都固定，才能说出什么算失败；否则“多数时候看起来不错”很容易替换掉原命题。

这里的<Term def="对字符串位置做一一对应的重排，不增删字符">置换</Term>让差别变得可见。反转把位置 $j$ 的来源变为 $n-1-j$，两次后回到 $j$。左循环移一位则让输出位置 $j$ 取自输入 $(j+1)\bmod n$，两次取自 $(j+2)\bmod n$。位置没有回原处时，重复字符仍可能让表面字符串相同。

### 实验三：两次置换的接线与反例

**先预测：**三位串 aab 左移两次会变成什么？如果只试 aaa 和 bbb，会不会错误接受“全部输入都能恢复”？把操作改成反转，反例是否还存在？

<TcgPrefaceEvidenceGateLab />

**操作：**默认三位、左循环移一位，逐步追踪圆内字符与旁边原位置编号。打开“只测全同串”，主接线变为 aaa 的通过轨迹，而独立穷举仍保留 aab 的失败位置；故障不是篡改全域计算，而是缩小测试集。再把长度改为 2 或把操作改成反转，观察接线及全域结果一起变化。

**解释：**默认轨迹是 aab → aba → baa，位置 0、2 的字符不同，8 个输入中只有 aaa、bbb 两个满足命题。长度 2 左移两次确实恢复全部 4 个输入；长度 4 则仅有 aaaa、abab、baba、bbbb 四个满足，共 4/16。反转两次对这三个有限域全部成立。一个<Term def="满足命题前提但使其结论失败的具体输入">反例</Term>足以否定全称命题，但没有在少量样本中发现反例，不等于证明它不存在。

```python
def transform(s, operation="rotate"):
    assert operation in ("rotate", "reverse")
    return s[::-1] if operation == "reverse" else s[1:] + s[:1]

def twice(s, operation="rotate"):
    return transform(transform(s, operation), operation)

assert ["aab", transform("aab"), twice("aab")] == ["aab", "aba", "baa"]
for n, expected in ((2, 4), (3, 2), (4, 4)):
    domain = words(n)
    assert sum(twice(s) == s for s in domain) == expected
    assert all(twice(s, "reverse") == s for s in domain)
assert next(s for s in words(4) if twice(s) != s) == "aaab"
assert all(twice(s) == s for s in ("aaa", "bbb"))
assert twice("aab") != "aab"
assert twice("") == "" and twice("a") == "a"
print("PASS: slots 4/9; automaton 5 vs faulty 8; rotate 2/8")
```

这是一种<Term def="枚举事先固定的全部有限输入并逐一检查">有限穷举</Term>，不是对任意长度的自动证明，更不是对语言模型理解能力的证明。反转两次的普遍结论还可用位置公式推导；左移的反例则提醒我们，把测试域说清楚，比给解释贴“已经验证”的标签重要。

## 三个误区：输出、规则与检验不能互相替代

三个实验各有一种容易漏看的失败：样本碰巧命中、总数守恒却规则错误、测试集偏到全同字符串。它们需要不同的修法，不能用同一句“多看几个例子”解决。

<Callout type="trap" title="误区一：生成了新串，就是发现了新规则">
  **现象：**“甲停”没存过，于是把它当成理解或推理的证据。**原因：**独立词槽原本就允许四种组合，未出现过的表记录不等于未定义的规则。**修法：**分别列出存储项、组合规则与查询；用交叉配对区分机制，并承认仅凭这一小例无法识别真实模型内部实现。
</Callout>

<Callout type="trap" title="误区二：所有路径加起来正确，语法就正确">
  **现象：**故障自动机仍有 16
  条四位路径，于是认为没有丢失或错误。**原因：**守恒只限制总量，错误地把拒绝路径转为接受路径也不破坏总量。**修法：**保留拒绝态的含义，用独立子串扫描找
  abba；不能让同一张错误转移表同时担任答案和裁判。
</Callout>

<Callout type="trap" title="误区三：两条全同串通过，就能说全部成立">
  **现象：**aaa 与 bbb
  左移两次都不变，便宣布操作具有二次恢复性。**原因：**重复字符掩盖了位置变化，测试集没有覆盖能暴露变化的输入。**修法：**在固定有限域内找最小反例
  aab，同时区分“字符串偶然相同”与“位置置换回到恒等”。长度变更之后重新说明结论范围。
</Callout>
