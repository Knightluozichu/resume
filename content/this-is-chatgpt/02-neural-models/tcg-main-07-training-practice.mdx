## 为什么“这次跑通了”还不够

同一条生产线，换了原料、调了机器，又只展示最好的一件成品，就无法知道改善来自哪里。训练也一样：一次成功只是一个结果，还不是可迁移的做法。

本章把三个容易误判的环节分开检查：起点是否让信号难以传递，继续加工是否真的改善新样本，以及换一批起点后结论是否还成立。每次只改一个条件，才有办法解释失败与恢复。

## The Practice and Lore of Neural Net Training / 神经网络训练的实践与经验

作者这一节强调，能写出训练步骤，不等于能预先推算出合适的网络、数据量和训练时间。经验有用，但必须说明它依赖的条件。本站把这一点展开成三个有限计算实验：它们不是作者给出的实验，也不复现真实 ChatGPT 的训练。

### 结构与数据：先冻结什么，再讨论调参

延续上一章的权重更新知识，先把网络结构和数据来源固定。直接从输入学到输出，能减少人工设计中间表示的步骤；但并不意味着结构不重要。图像的局部连接、序列对先前位置的依赖，都在限制“哪些信息可以相遇”。中间层变窄可能迫使信息压缩，也可能丢掉任务必需的信息，不能一概称为改进。

下表把作者讨论的实践选择落到可对照的操作；它不是三种万能训练配方。实验一只取“逐层传递”这一条，实验二固定两组数据，避免把每个变化都归因于权重更新。

| 选择                       | 保持不变的对照               | 应检查的后果                                         |
| -------------------------- | ---------------------------- | ---------------------------------------------------- |
| 改层数或中间宽度           | 同一数据、评估和预算口径     | 信号是否传得过去；参数量和计算量是否变化             |
| 人工标签改为已有注释作代理 | 同一任务与独立评估数据       | 注释是否真的对应目标；不能默认网页说明都准确         |
| 重复遍历同一批样本         | 不把重复样本算作新增独立数据 | 训练更好是否伴随新样本表现变差，见实验二             |
| 对图像做保持标签的变化     | 任务标签含义不变             | 变化是否破坏标签；例如翻转带方向语义的目标就未必安全 |
| 沿用已有网络的表示再训练   | 明确哪些权重固定、哪些更新   | 节省数据的同时是否带入不适用的表示                   |

作者还用文本补全说明：可以从文本本身构造输入与目标，不必为每一段另请人标注。原文将它放在“unsupervised learning”语境中；更精确地说，这类目标是从数据自身构造的监督信号，不表示训练没有目标，也不保证文本中的事实正确。

### 初始化尺度：局部平坦如何变成逐层衰减

<Term def="开始更新之前，权重数值相对于输入大小的量级。">初始化尺度</Term>
决定信号一开始落在函数的什么位置。本实验不是随机大网络：输入固定为
0.5，每层只有一个数，所有层权重都设为同一个正数 s，偏置为零。改变
s，是一个受控的起点对比，不是最优初始化算法。

<Term def="输入继续增大时，激活函数的输出已经接近边界，局部变化率很小。">
  激活饱和
</Term>
可以在 tanh
曲线两端直接看到。实验一同时画出当前点的切线，以及累计导数随层数的变化。大权重能放大输入，却也可能把输出推向平坦区；小权重则可能在每一层直接把变化压小。

记 a 为各层输出，z 为进入 tanh 前的数，d 为局部导数，J 为当前输出对最初输入的导数。递推是：

$$
z_l=s a_{l-1},\quad a_l=\tanh(z_l),\quad d_l=1-a_l^2,\quad J_l=J_{l-1}s d_l,\qquad a_0=0.5,\ J_0=1.
$$

这个式子说：先做前向计算，再把每一层的“权重乘局部斜率”连乘；局部斜率本身不是完整梯度。这里没有定义损失，J 是输出对输入的敏感度，不是某个权重的损失梯度。

> 猜一猜：把 s 从 1 改为 4，三层的累计导数一定更大吗？先看第一层切线，再推进到第三层。

<TcgMain07TrainingPracticeContextContractLab />

s=4 时，第一层 z=2，输出约 0.964028，局部导数约 0.070651；第三层 J 只有约 0.0000109172。s=1 的第三层 J 约为 0.533912。故障只把反向使用的 d 错写成 1，前向输出保持不变，却会把 s=4 的三层 J 误报为 64。撤销故障即可恢复，不能把这次变化归因于数据或网络结构。

  不是所有网络的通用最佳尺度。
</Callout>

### 验证集：下降的训练曲线没有回答新样本问题

<Term def="不参与权重更新、用来比较设置或选择检查点的数据。">验证集</Term>
负责问另一个问题：学到的关系能否转移到未用于更新的样本？本实验有意让训练与验证不同。两者都取
x 为 −1 和 +1；训练标签为 1+n x，验证标签都为 1。模型预测为 w+v x，因此 v
对训练有帮助，对干净验证却有害。

这里不是声称验证集通常都比训练集干净，而是人为设置一个可推导的反例。真实项目若两组分布不同，需要解释差别是否符合部署环境。验证数据一旦用于选择，就不能又冒充最终未接触过的测试数据。

两点平均平方误差分别为 E_train=(w−1)²+(v−n)²，E_val=(w−1)²+v²。用训练误差的一半作为更新目标，固定步长 1/4，从 w=v=0 开始。令 q=(3/4)^t，有：

$$
w_t=1-q,\quad v_t=n(1-q),\quad E_{\mathrm{train}}=(1+n^2)q^2,\quad E_{\mathrm{val}}=q^2+n^2(1-q)^2.
$$

这个式子说：训练中两项都在接近各自的目标，而验证第二项却随 v 的增长而增加；所以“还在下降”必须说明是在看哪一组误差。

### 早停：停止时刻与恢复哪一份权重是两件事

<Term def="当验证表现连续若干次未改善时停止更新，并按事先约定恢复检查点。">
  早停
</Term>
需要写清检查频率、改善定义和耐心次数。本实验每轮检查一次，严格变小才算改善；连续
p 次未改善就停。停止后恢复验证误差最低的已观察轮次，不是自动恢复最后一轮。

> 猜一猜：n=1、耐心为 2 时，第 3 轮验证略变差，应立刻停，还是等到第 4 轮？停止以后应拿哪一份权重交付？

<TcgMain07TrainingPracticeComputeTraceLab />

n=1 时，第 2 轮验证误差为 0.5078125，第 3 轮为 0.51220703125，第 4 轮为 0.567413330078125。耐心 2 因而在第 4 轮耗尽，但应恢复第 2 轮。故障只改“恢复点的选择依据”为训练误差；停止时刻与全部曲线不变，恢复却变为第 4 轮，验证误差随之上升。

当 n=0.5 时，10 轮预算内最佳验证点改为第 6 轮，因此答案不是固定的“永远第 2 轮”。若预算用尽仍未触发耐心，也要把“预算结束”和“检测到恶化”分开记录。这个小程序能够完整保存每轮两项误差，不能据此预测大型网络多久收敛。

### 配对实验：同一起点比较，与挑最好一次不同

<Term def="比较两个方案时，在每一对运行中使用相同的随机条件，再汇总各对差异。">
  配对实验
</Term>
能减少起点差异对比较的干扰。实验三固定六个种子，每个种子生成两个初始权重；同一行的
A 和 B 从相同权重开始，训练数据与更新公式相同，仅预算不同：A 固定 2 轮，B 选 4
或 8 轮。

为让 Python 和页面逐项一致，使用明确的 32 位整数递推：状态更新为 (1664525×state+1013904223) 对 2³² 取余，再除以 2³² 得到 u；连续取两个 u，把权重设为 h(2u−1)。这只是可重复输入生成器，不是真实训练框架的随机实现，也不假定六个种子代表全部可能运行。

> 猜一猜：同一批六次运行，B 的均值比 A 差，能否仅靠把 B 换成“最好一次”，让报告宣称 B 更好？推进到 6/6 后再注入故障。

<TcgMain07TrainingPracticeEvidenceGateLab />

默认 h=0.6、B=8 时，A 的六次均值约 0.808119273269，B 约 0.851668077518。平均差 B−A=+0.043548804249，正数表示 B 较差。只把 B 的汇总改成最低值 0.779394938986，而 A 仍保留均值，报告差就变成 −0.028724334282。图上没有任何一次运行变好，移动的是报告的汇总点。

当 h=1 时，B 的全配对均值也可能更好；“更长预算总会更差”同样不成立。配对不保证方案获胜，更不自动构成统计显著性证明。应保留全部配对、同一口径的均值和预算，而不是用最好一次抵消失败运行。

## 用标准库复算三个实验

下面各 Python 块按顺序拼接就是完整程序，只需 Python 3 标准库。第一部分计算有限标量链，第二部分真正执行两参数更新，第三部分重复固定种子比较。没有调用模型库、下载权重或测量 GPU。浮点结果用容差断言，不按显示时的六位小数继续计算。

### 前向输出与导数分开保存

从链式法则直接写出第一实验；`fault` 只影响累计导数，不能顺手改掉前向输出。保存真值可以检查两个路径何时分岔。

```python
from math import tanh, isclose, isfinite


def activation_trace(scale, depth, fault=False):
    a, jacobian, exact = 0.5, 1.0, 1.0
    rows = []
    for layer in range(1, depth + 1):
        z = scale * a
        a = tanh(z)
        derivative = 1 - a * a
        exact *= scale * derivative
        jacobian *= scale * (1 if fault else derivative)
        rows.append((layer, z, a, derivative, jacobian, exact))
    return rows


ref = activation_trace(4, 3)
bad = activation_trace(4, 3, True)
assert isclose(ref[-1][4], 1.0917207107599922e-5)
assert bad[-1][4] == 64
assert [r[2] for r in ref] == [r[2] for r in bad]
assert activation_trace(4, 3) == ref
assert activation_trace(0.2, 5)[-1][4] < 0.001
print("chain", ref[-1][4], bad[-1][4])
```

预期打印约 `chain 1.0917207107599922e-05 64.0`。小尺度五层的导数小于 0.001，也给出“不饱和仍可逐层衰减”的边界，而不是把所有小导数都叫作饱和。

### 执行权重更新，同时记录两组误差

两点 x=±1 的平均消去了交叉项，因此更新式可以写成两个标量。每行先记录误差，再更新；第 0 行是尚未更新的初始状态，第 10 行是十次更新后。

```python
def learning_trace(noise, epochs=10, w=0.0, v=0.0):
    rows = []
    for epoch in range(epochs + 1):
        train = (w - 1)**2 + (v - noise)**2
        validation = (w - 1)**2 + v**2
        rows.append(dict(epoch=epoch, w=w, v=v,
                         train=train, validation=validation))
        w += 0.25 * (1 - w)
        v += 0.25 * (noise - v)
    return rows


curve = learning_trace(1)
assert curve[2]["validation"] == 0.5078125
assert curve[3]["validation"] == 0.51220703125
assert curve[4]["validation"] == 0.567413330078125
assert all(a["train"] > b["train"]
           for a, b in zip(curve, curve[1:]))
```

下一块把“验证决定何时停”和“停止后恢复哪个点”分开写。故障只能替换后一项的指标；这样才能认定观察到的退步来自选错检查点。

```python
def checkpoint(rows, patience, fault=False):
    best, stop = 0, len(rows) - 1
    for i in range(1, len(rows)):
        if rows[i]["validation"] < rows[best]["validation"]:
            best = i
        if i - best >= patience:
            stop = i
            break
    metric = "train" if fault else "validation"
    restored = min(range(stop + 1), key=lambda i: rows[i][metric])
    return best, stop, restored


assert checkpoint(curve, 2) == (2, 4, 2)
assert checkpoint(curve, 2, True) == (2, 4, 4)
assert checkpoint(curve, 2) == (2, 4, 2)
assert checkpoint(learning_trace(0.5), 2) == (6, 8, 6)
print("checkpoints", checkpoint(curve, 2), checkpoint(curve, 2, True))
```

预期 `checkpoints (2, 4, 2) (2, 4, 4)`，三个位置依次为验证最佳、停止、恢复。`min` 在并列时选择最早一个；这与逐轮只接受严格改善的规则相容。

### 固定种子逐对比较，不隐藏任何一对

这里生成全部六对真实的有限更新结果，不从预先写好的成绩表取数。A 与 B 共享每对初始权重；只有更新次数不同。

```python
SEEDS = [11, 29, 47, 83, 101, 137]


def seeded_pairs(amplitude, budget):
    pairs = []
    for seed in SEEDS:
        first = (1664525 * seed + 1013904223) % 2**32
        second = (1664525 * first + 1013904223) % 2**32
        w = amplitude * (2 * first / 2**32 - 1)
        v = amplitude * (2 * second / 2**32 - 1)
        rows = learning_trace(1, budget, w, v)
        pairs.append(dict(seed=seed, w=w, v=v,
                          a=rows[2]["validation"],
                          b=rows[budget]["validation"]))
    return pairs


def paired_report(pairs, fault=False):
    a = sum(r["a"] for r in pairs) / len(pairs)
    b = sum(r["b"] for r in pairs) / len(pairs)
    best_b = min(r["b"] for r in pairs)
    reported = (best_b if fault else b) - a
    return a, b, best_b, b - a, reported
```

最后断言结论翻转，并枚举界面全部离散参数，检查有限值、反向故障不改变前向结果、检查点不越过停止轮次。枚举是这些有限输入的检查，不是所有真实网络的证明。

```python
pairs = seeded_pairs(0.6, 8)
a, b, best_b, delta, reported = paired_report(pairs)
assert isclose(a, 0.80811927326865)
assert isclose(b, 0.8516680775178833)
assert isclose(best_b, 0.7793949389861643)
assert delta > 0 > paired_report(pairs, True)[4]
assert paired_report(pairs)[4] == reported
for scale in (0.2, 1, 4):
    for depth in (1, 3, 5):
        for fault in (False, True):
            rows = activation_trace(scale, depth, fault)
            assert all(isfinite(x) for r in rows for x in r)
for noise in (0.5, 1, 1.5):
    for patience in (1, 2, 3):
        for fault in (False, True):
            best, stop, restored = checkpoint(
                learning_trace(noise), patience, fault)
            assert best <= stop and restored <= stop
for amplitude in (0.2, 0.6, 1):
    for budget in (4, 8):
        for fault in (False, True):
            assert all(isfinite(x) for x in
                       paired_report(seeded_pairs(amplitude, budget), fault))
print("paired", a, b, delta, paired_report(pairs, True)[4])
```

预期最后一行约 `paired 0.808119273269 0.851668077518 0.043548804249 -0.028724334282`。页面时间线逐对揭示时，前几步的均值只用已揭示的运行，必须到 6/6 才与这里的六对结果一致。

## 把经验写成可交接的记录

三个实验分别控制导数计算、恢复规则和汇总口径，避免把几个故障揉在一起。真正训练还需冻结损失定义、步长、每次更新用的样本数量及数据顺序；改变它们会改变估计误差与计算成本，不能只保留最后一条下降曲线。

| 记录项     | 最小可交付内容                                 | 本页如何落实                                          |
| ---------- | ---------------------------------------------- | ----------------------------------------------------- |
| 输入与版本 | 数据划分、标签含义、网络结构、初始权重生成规则 | 两点数据、标量链与明确整数递推                        |
| 比较条件   | 只改变的因素、更新公式、预算与停止规则         | s 或层数；n 或耐心；h 或 B 预算逐项单改               |
| 中间结果   | 所有检查点、失败运行与恢复值                   | 每层导数、双曲线与全部六对                            |
| 资源口径   | 权重规模、样本数、更新次数、运行环境           | 标量链 L 次前向；每 seed 的 A 用 2 轮，B 用 4 或 8 轮 |

作者说明训练大量使用数值数组计算，GPU 适合这类工作；本文没有测量任何 GPU 加速比。更多轮数通常意味着更多计算，但耗时还受硬件、批量和数据读取影响。原文关于未来低精度、计算与存储组织、网络改写的讨论包含作者展望，不能当作今天所有训练系统的已验证实现。本页也不把训练误差平台自动解释为“结构必须更换”：数据、目标、更新设置或数值问题都需要分别排查。

## 三个需要分开诊断的误区

以下现象可能同时出现，但原因和修复动作不同。诊断时先固定其他条件，再让一个错误在图和计算中留下可复算的差异。

### 权重大，反向信号就一定大

现象：s=4 的三层输出接近 1，却把累计导数想成 64。原因：只连乘权重，漏了每层平坦的斜率。修法：同时保留 a、d、J，撤销实验一的导数故障；再试小尺度，区分饱和与直接连乘衰减。

### 最后一轮训练最好，就应交付最后一轮

现象：第 4 轮训练误差比第 2 轮低，于是交付第 4 轮。原因：用训练指标替换了原本承诺的验证恢复规则。修法：将“何时停”和“恢复谁”各存一个索引；默认实验恢复第 2 轮，最终测试数据仍留作独立评估。

### 种子固定且可重跑，挑最好一次就公平

现象：B 最好一次优于 A 均值，报告因此宣布 B 胜出。原因：可重跑不等于同口径，B 被选择性筛选。修法：展示全部配对，并对 A/B 都用同一汇总规则；撤销实验三故障后，默认六对结论恢复为 B 均值较差。

## 小结与练习

训练经验要能说明条件、失败与边界：逐层看导数，分开看训练与验证，再用同一批起点比较两个方案。一个漂亮结果不能替代这三种记录。

## 名词解释

五个术语对应三个检查环节：起点与导数、停止与恢复、重复比较。它们不是关于当前 ChatGPT 内部设置的产品规格。

<Glossary>
  <GlossaryItem term="初始化尺度">
    权重在开始更新前相对于输入大小的量级，影响信号落在激活曲线的哪个区域。
  </GlossaryItem>
  <GlossaryItem term="激活饱和">
    激活输出接近边界、局部变化率很小的状态；不同于所有原因造成的累计导数变小。
  </GlossaryItem>
  <GlossaryItem term="验证集">
    不用于更新权重、用于比较设置或选择检查点的数据；选择后不能再称为未接触过的最终测试。
  </GlossaryItem>
  <GlossaryItem term="早停">
    按约定频率检查验证表现，在持续未改善时停止，并按约定恢复检查点。
  </GlossaryItem>
  <GlossaryItem term="配对实验">
    两个方案在每一对运行中共享随机条件，再按一致口径汇总差异的比较方式。
  </GlossaryItem>
</Glossary>
