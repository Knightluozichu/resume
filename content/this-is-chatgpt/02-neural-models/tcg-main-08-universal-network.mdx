## 先问：是在猜结果，还是已经做完？

工厂里，一个工人能认出许多成品，不代表他能只看几张照片就造出所有新产品。给他更大的工作台，也不等于已经完成下一批订单。

本节要拆开这两种误判：把“有地方放下做法”当成“已经找到了做法”，以及把“说出了结果”当成“已经完成全部步骤”。不分清它们，就会把一次漂亮演示误当成任何任务的保证。

## "Surely a Network That's Big Enough Can Do Anything!" / “足够大的网络当然什么都能做！”

作者这一节的主线不是一个通用逼近定理，而是追问：擅长从经验中提取规律的系统，能否替代需要实际执行的计算？Wolfram先承认大网络可能擅长许多人类能直接完成的思考，再把讨论转向形式计算、不可约性和工具。我们先拆清四种不同的要求，再用三种有限算例检验其中的错误跳步。

### 四种要求不能互相顶替

<Term def="在规定的输入域和误差要求下，存在一组参数能实现所需输入输出关系">
  可表示性
</Term>
是一个“存在”的要求。它在网络设计阶段回答有没有合适的表达形式；不负责告诉你样本来自哪里，也不负责让优化器找到那组参数。实验一直接写出参数，所以没有训练成功率可报告。

<Term def="在指定数据、算法和资源条件下找到满足目标的模型的能力">可学习性</Term>
关注怎样找到参数。上一节讨论的初始化、损失和更新过程属于这一层。已知一组好权重存在，不说明有限数据和有限轮更新会找到它；不同任务也不能共享一个无条件成功保证。

<Term def="模型在未用于构造或训练的输入上仍满足要求的表现">泛化</Term>
在参数确定后接受检查。它要求把样本上的吻合与新输入上的表现分开。实验二故意让所有观测值相同，却在点与点之间藏入波峰，显示“没有观察到”与“不存在”完全不同。

<Term def="一次运行允许实际消耗的轮数、局部操作数等资源上限">执行预算</Term>
最后约束这一次是否真的算完。一个规则即使完全已知，也可能仍需多轮调用。实验三把“有表示”“知道规则”和“执行到了目标轮次”分别画出来，不把中途状态冒充最终答案。

### 作者的不可约性论述和工具位置

<Term def="某些过程的远期行为不能普遍依靠省略实际计算步骤来可靠取得的性质">
  计算不可约性
</Term>
是作者论述的核心。作者把学习描述为利用规律压缩经验，并主张：当过程无法被这样的规律充分压缩时，可学习性与计算能力之间会出现张力。记住很多已有例子、发现局部捷径，都不足以保证下一个未见状态不会出乎预期。这是作者关于计算的一般论述，不能由本页几个小例子独立证明。

作者提出把细胞自动机、图灵机一类小型计算装置接入可训练系统，作为执行工具。这不等于“只要模型很大，就会自动学会装置的所有远期行为”。工具的作用是按明确规则继续运算，并交回可核对的结果；网络负责选择、组织或使用它。实验三的“工具”只多执行确定规则，不调用真实模型或在线服务。

作者还提醒：写文章曾被误认为计算机很难完成；看到它被完成，并不意味着所有原来需要漫长执行的问题也突然有了捷径。这里不应反向推成“神经网络不能做数学”：特定任务可以有结构、短解、记忆或混合求解流程；需要逐个明确算法与资源条件。

原公开长文说“当时的ChatGPT”生成每个token的网络是前馈的，并由此讨论非平凡控制流的限制。应区分一次固定网络调用，与反复生成token、保留外部状态、循环调用工具的整个系统。有限轮算法可以展开为更深的前馈电路；固定深度也不能无条件代表任意多轮执行。本页不核实或宣称当前ChatGPT内部架构、推理预算或工具能力。

## 实验一：把“存在参数”真的写出来

这项补充用来纠正一个常见的旁支误推：通用逼近类结论即使成立，也只是带有函数类、输入域和误差条件的表达结论，不能代替作者对可学习性和计算的追问。先做一个无需训练、可以逐个检查权重的例子，就能看见哪些保证确实存在。

### 从直线斜率构造平方曲线

本节符号如下；后续算例沿用 $x$ 表示输入位置，不沿用此处的误差保证。

| 符号             | 含义                               |
| ---------------- | ---------------------------------- |
| $f(x)=x^2$       | 在 $[0,1]$ 上需要逼近的目标        |
| $n$、$i$         | 等长区间段数、折点编号             |
| $s_n(x)$         | 连结相邻折点的直线插值             |
| $R(z)=\max(0,z)$ | 负输入输出零、正输入原样输出的ReLU |
| $e_n$            | 整个闭区间的最大绝对误差           |

第 $i$ 段连接 $i/n$ 与 $(i+1)/n$，斜率是两端函数值之差除以长度，得到 $(2i+1)/n$。第一段斜率为 $1/n$，每过一个折点增加 $2/n$。因此只需在每个折点加一个向右生效的铰链：

$$
s_n(x)=\frac{x}{n}+\sum_{i=1}^{n-1}\frac{2}{n}R\!\left(x-\frac{i}{n}\right).
$$

这个式子在说：先画第一条直线，然后到达每个折点时只改变斜率，不让函数跳跃。这里用了 $n-1$ 个ReLU铰链和一条仿射直连，不能把这个数当成任意网络结构的最少宽度。

在任一小段的端点记为 $a,b$ 时，直线插值减去平方恰好为 $(x-a)(b-x)$。两端是零，中点最大；段长是 $1/n$，所以：

$$
e_n=\max_{x\in[0,1]}|s_n(x)-x^2|=\frac{1}{4n^2}.
$$

这个式子在说：段数翻倍，这个特定构造的最大误差变为四分之一。它只约束 $[0,1]$；不是所有目标的统一速率，也不是训练自动达到的误差。

猜一猜：把段数从4调到8，折点之间的空隙和最大误差会怎样变化？再把检查位置改为1.25，是否还能沿用这个误差界？

先保存下面的Python为一个文件，后续代码块按阅读顺序追加到同一文件。只用标准库、没有下载、随机数或训练；每块都不超过30行。第一块与图中的公式完全同义。

```python
from math import sin, pi, isclose

def spline(x, n, fault=False):
    assert n >= 2
    y = x / n
    if not fault:
        y += sum(2 / n * max(0, x - i / n)
                 for i in range(1, n))
    return y

for n in (2, 4, 8):
    knots = [i / n for i in range(n + 1)]
    mids = [(i + 0.5) / n for i in range(n)]
    assert all(isclose(spline(x, n), x*x, abs_tol=1e-12)
               for x in knots)
    error = max(abs(spline(x, n) - x*x) for x in mids)
    assert isclose(error, 1 / (4*n*n), abs_tol=1e-12)
assert spline(0.5, 4) == 0.25
assert spline(0.5, 4, fault=True) == 0.125
assert spline(1.25, 4) == 1.4375
assert abs(spline(1.25, 4) - 1.25**2) > 1 / 64
print("spline: n=4 bound=0.015625; outside error=0.125")
```

正常四段构造的误差界是0.015625；删除全部铰链后只剩 $x/4$，在0.5处就错0.125，在1处错0.75。故障改变的是构造，不是假装优化器刚刚训练失败。区间外1.25处输出1.4375、目标1.5625，误差0.125，直接反驳把区间内误差界搬到域外。

## 实验二：点上全对，不等于观察充分

现在不再拥有目标函数的全部信息，只拥有采样值。为了让歧义可见，图中的黑线展示我们事先选定的真目标，但插值器只能使用采样圆点。黑线属于出题者与检查者的信息，不能偷偷当作构造器的额外样本。

### 高频目标与采样间的盲点

记 $k$ 为 $[0,1]$ 内正弦的周期数，$m$ 为等距采样间隔数，观测点为 $x_j=j/m$，共 $m+1$ 点。构造器只把相邻观察值连成直线。在 $k=4,m=4$ 时，所有观察值在精确数学上都是零；它们既符合零函数，也符合四周期的正弦波。

在浮点计算中这些值有约 $10^{-15}$ 的舍入残差，所以断言必须使用容差，不写成每个sin严格等于零。点 $x=1/16$ 没有进入观察集，它的目标值却是1；连线预测约为0。增加网络宽度本身不能从同一组零值中唯一识别目标，除非另加先验、数据或结构约束。

猜一猜：保持四周期目标，把采样间隔从4改为16，哪些波峰开始被观察到？如果只用原来的采样点验收，故障会把怎样的曲线判成“通过”？

<TcgMain08UniversalNetworkComputeTraceLab />

追加函数与验收代码。独立检查使用257点，包含1/16；它会与观察集共享少数端点，但包含未用于构造的点，且没有反馈给插值器。我们报告的是这张有限网格上的最大残差，不是连续区间误差上界。

```python
def wave(x, k):
    return sin(2*pi*k*x)

def interpolate(x, k, m):
    assert 0 <= x <= 1 and m >= 1
    i = min(m - 1, int(x*m))
    q = x*m - i
    return (1-q)*wave(i/m, k) + q*wave((i+1)/m, k)

def diagnostic(k, m, fault=False):
    intervals = m if fault else 256
    return max(abs(wave(i/intervals, k)
                   - interpolate(i/intervals, k, m))
               for i in range(intervals + 1))

assert max(abs(wave(i/4, 4)) for i in range(5)) < 1e-12
assert isclose(wave(1/16, 4), 1.0, abs_tol=1e-12)
assert abs(interpolate(1/16, 4, 4)) < 1e-12
assert isclose(diagnostic(4, 4), 1.0, abs_tol=1e-12)
assert diagnostic(4, 4, fault=True) < 1e-12
assert 0.20 < diagnostic(4, 16) < 0.22
assert diagnostic(4, 16) <= 0.25 < diagnostic(4, 4)
print("sampling: k=4 m=4 fails; m=16 passes threshold 0.25")
```

故障没有动目标和插值器，只把验收集合缩回原样本，因而梳齿残差图塌为零、阈值0.25验收从拒绝变成通过。撤销故障恢复独立检查。$m=16$ 的通过也仅针对这张网格和这个阈值；实验不提供真实训练的样本复杂度、成功概率或所有频率的充分条件。

## 实验三：知道更新规则，仍要对执行负责

这项实验回到作者的正式核心。记住若干状态、能表达某个有限输入输出映射，与确实执行完目标轮数不是一回事。我们不给未知答案填上“看起来合理”的位，而是明确保留“未计算”；然后让一个单故障把中途结果冒充最终结果。

### 每轮一层的局部规则与依赖锥

使用31个二值格，位置0到30；窗口外永远取零，所有格同时更新。规则110的八个输出，按邻居三位从111倒序到000，依次为0、1、1、0、1、1、1、0。不要把本页有限零边界实例，与无限空间中特殊初态下的通用计算结论混为一谈。

本节另记 $L,C,R$ 为上一行的左、中、右三位，$q$ 为邻域编号，$T$ 为目标轮数，$B$ 为允许执行的轮数。

$$
q=4L+2C+R,\qquad C_{\mathrm{next}}=(110\gg q)\mathbin{\&}1.
$$

这个式子在说：先把三位邻域当成0至7的编号，再读取整数110的对应二进制位。右移和按位与只是这张八项规则表的编码，不是学出的参数。

目标中心在下一轮最多依赖上一行的三个位置；向上再追一轮，可能依赖的范围又左右各扩一格，形成图中的锥形。阴影表示可能的依赖范围，并不说明其中每一格都一定改变最终位。虚线空格表示尚未执行，不能读成数值零。

猜一猜：默认双点种子下，只执行2轮，却要第6轮中心位，会怎样？点击故障把第2轮当答案，再让“工具：继续计算”执行满6轮，红框和核对结果会如何变化？

<TcgMain08UniversalNetworkEvidenceGateLab />

下面代码追加完整的同步更新。列表推导先读旧行，再整体替换；若原地从左到右覆盖，就变成另一套非同步规则。每轮计算31个格，计31次局部规则求值；这是本实现的操作量，不是所有算法的最优下界。

```python
def evolve(seed, rounds):
    assert seed in ("pair", "single") and 0 <= rounds <= 8
    active = (14, 16) if seed == "pair" else (15,)
    row = [int(i in active) for i in range(31)]
    rows = [row]
    for _ in range(rounds):
        def bit(i):
            return row[i] if 0 <= i < 31 else 0
        row = [(110 >> (4*bit(i-1) + 2*bit(i) + bit(i+1))) & 1
               for i in range(31)]
        rows.append(row)
    return rows

def execute(seed, target, budget, fault=False):
    assert target in (4, 6, 8) and budget in (2, 4, 8)
    done = min(target, budget)
    rows = evolve(seed, done)
    answer = rows[-1][15] if done == target or fault else None
    return answer, rows, 31*done

rule = [(110 >> q) & 1 for q in range(7, -1, -1)]
assert rule == [0, 1, 1, 0, 1, 1, 1, 0]
assert [r[15] for r in evolve("pair", 8)] == [0,1,0,1,1,0,1,1,0]
```

默认参考输出是“未知”，不是错位0。故障输出0，第6轮离线核对为1。离线核对另执行186次求值，不能因为界面展示了它，就说预算62次的执行器已经算到第6轮。“继续计算”只提高预算至4或8并撤销故障；实际仍在目标轮数停止，不多算无用轮次。

```python
answer, prefix, cost = execute("pair", 6, 2)
assert answer is None and cost == 62 and len(prefix) == 3
wrong, same_prefix, same_cost = execute("pair", 6, 2, fault=True)
truth = evolve("pair", 6)[-1][15]  # oracle另计186次求值
assert same_prefix == prefix and same_cost == cost
assert wrong == 0 and truth == 1 and wrong != truth
recovered, full, full_cost = execute("pair", 6, 8)
assert recovered == truth and len(full) == 7 and full_cost == 186
assert execute("pair", 6, 2)[0] is None  # 重放恢复未知合同
# 同位不是算完的证据：单点种子截断恰巧与目标都为1。
assert execute("single", 6, 2)[0] is None
assert execute("single", 6, 2, fault=True)[0] == 1
assert evolve("single", 6)[-1][15] == 1
print("rule110: unknown -> faulty 0 (truth 1) -> tool 1; cost 62 -> 186")
```

### 这个反例没有证明什么

六轮更新当然能被展开成一个有限前馈计算图：每层复制规则，每层读上一层。它说明一个已知有限程序可以被表示，不说明固定深度能无条件处理任意轮数，也不说明通过有限样本训练必然得到这套展开。

反过来，画出六层依赖锥也不能证明不存在更快算法。有限输入可以直接制表；有些规则、初态或查询有解析解。要证明一般无捷径，需要明确问题族、输入长度、允许算法和复杂度论证，本页没有进行这种证明。作者的一般主张、短例子的计算结果、现代系统的实际能力，应始终分层陈述。

## 复算范围与实现对照

把本页全部五个Python块按顺序拼接即可运行，输出四行说明，每个断言都有具体预期。下面最后一块遍历全部离散种子/轮数/预算，检查未知状态和完整执行的合同；这仍是有限穷举，不升级为全体算法的结论。

```python
print("finite sweeps passed; no training/current-model claim")
```

界面的TypeScript使用相同公式，但以独立数值检查脚本对照Python，不把截图当作数学证明。第一图的播放移动检查区间，第二图依次强调观察点、连线与未见残差，第三图逐行揭开实际已执行状态。完整重置会恢复各自初始参数、故障关闭、时间线首步与暂停；参数或故障变化也会先暂停回到首步。偏好减少动态效果时保留手动步进，隐藏自动播放。以上是实现合同，真实设备的交互验收由主审另行完成。

## 常见误区

这些误区分别对应不同的失败层次。修正时应只改错误前提，不用一个更大的模型名称替代核对。

### 误区一：通用逼近就是训练保证

<Callout type="trap" title="把存在权重当成找到了权重">

**现象 →** 四段公式逼近很好，于是认为训练同规模网络必定达到它。

**原因 →** 直接指定权重跳过了数据和优化，未提供可学习性证据。

**修法 →** 先说明存在性，再独立给训练协议；本页没有后者，不报告训练成功率。

</Callout>

### 误区二：观测误差零就是没有盲点

<Callout type="trap" title="复用原样本掩盖波峰">

**现象 →** 四个间隔的正弦样本都为零，就把零线当作完整目标。

**原因 →** 高频变化落在观察点之间，验收又复用了这些点。

**修法 →** 撤销实验二故障，检查未见位置；同时保留检查网格有限的边界。

</Callout>

### 误区三：画了依赖锥就证明所有计算不可约

<Callout type="trap" title="局部规则的执行图不是复杂度下界">

**现象 →** 六轮图有六层，就断言任何系统都必须执行六轮，且当前模型永远做不到。

**原因 →** 将本算法轨迹当成所有可能算法的证明，又将2023年描述当成当前产品事实。

**修法 →** 报告实际执行成本，不宣称最优下界；当前系统须另查一手实现和测评。

</Callout>

## 小结与练习

四个目标现在各有一个可核对的出口，不需要把作者的哲学性概括伪装成实验定理。

- 四段显式插值误差界为1/64，仅在指定区间内成立。
- 原样本全吻合仍可漏掉幅值为1的未见波峰。
- 第2轮位不能冒充第6轮；工具继续执行才恢复答案。
- 作者的不可约性论述不等于当前产品能力证明。

## 名词解释

这些词对应四种不同的证据责任。遇到新系统时，先问正在讨论哪一层，再问该层的输入、算法和预算是什么。

<Glossary>
  <GlossaryItem term="可表示性">
    在规定的输入域和误差要求下，存在一组参数能实现所需输入输出关系；实验一直接给参数。
  </GlossaryItem>
  <GlossaryItem term="可学习性">
    在指定数据、算法和资源条件下找到满足目标的模型的能力；本页没有运行训练。
  </GlossaryItem>
  <GlossaryItem term="泛化">
    模型在未用于构造或训练的输入上仍满足要求的表现；实验二用未见波峰反驳样本外推。
  </GlossaryItem>
  <GlossaryItem term="执行预算">
    一次运行允许实际消耗的轮数、局部操作数等资源上限；实验三用未知保护尚未执行的查询。
  </GlossaryItem>
  <GlossaryItem term="计算不可约性">
    某些过程的远期行为不能普遍依靠省略实际计算步骤来可靠取得的性质；本页有限实例不证明一般不可约性。
  </GlossaryItem>
</Glossary>
