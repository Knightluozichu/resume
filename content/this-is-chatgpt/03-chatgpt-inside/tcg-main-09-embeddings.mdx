## 为什么不能只给词编号

把“猫”“狗”“鸟”编成1、2、3，程序就能识别它们；但把编号换成31、7、80，文本并未改变，数值间距却完全变了。编号适合区分身份，不适合直接表达关系。

像给地点选地图坐标一样，我们希望若干可比较的数能支撑检索、分类或预测。关键不在“有一串数”，而在这串数由什么数据、任务和比较规则决定。没有这些约定，“离得近”只是图上印象。

## The Concept of Embeddings / 嵌入的概念

<Term def="把对象映射为数值向量，使下游任务能够用这些坐标进行计算的表示">
  嵌入
</Term>
把离散对象接到数值计算上。它不是词典中的唯一意义，也不保证相近对象在任何任务中都相似。本正式坐标先追问坐标如何产生，再检验比较规则，最后检查画成二维时丢掉了什么；下列三实验分别回答这三个问题。

作者公开文章本节从文本环境和手写数字分类任务解释表示的用途：可以借助一个明确的任务，取得网络中间层的一组数，而不必先人工写出“相似”的全部规则。这里的教学重点是**任务约束表示**，不是把作者的“意义空间”比喻升级为语义真值。我们使用原创小语料和符号向量，不读取任何已训练模型参数。

### 从文档环境得到一行坐标

<Term def="在同一文档内，围绕目标位置按给定距离收集上下文的规则">共现窗口</Term>
给出一种可追溯的起点。下面的词已按空格切好；这只是方便手算的离散单位，不代表实际ChatGPT把汉字或词按此规则处理。每行是独立文档，不能把上下两行的末尾和开头接成邻居。

| 文档 | 已切分的序列 |
| ---- | ------------ |
| 1    | 猫 追 球     |
| 2    | 猫 睡 垫     |
| 3    | 狗 追 球     |
| 4    | 狗 追 车     |
| 5    | 鸟 飞 天     |
| 6    | 鸟 睡 枝     |

固定目标行为“猫、狗、鸟”，上下文列为“追、睡、球”。符号 $r$ 是窗口半径，$C_{ij}$ 是目标 $i$ 与上下文 $j$ 的有向配对次数，$v_i$ 是矩阵第 $i$ 行，$P$ 是公开指定的二维映射。只计这三列，所以行和也不是该目标的全部环境频次。

$$
C_{ij}=\sum_d\sum_{p:w_{d,p}=i}\sum_{q:w_{d,q}=j}
\mathbf{1}\{1\leq |p-q|\leq r\},\qquad v_i=(C_{i,追},C_{i,睡},C_{i,球}).
$$

人话说：同一文档内，目标和上下文之间相距不超过 $r$ 且不是同一位置，就加一次。半径2时，“猫 追 球”贡献一次猫—追、一次猫—球；两条狗文档合计狗—追两次。完整矩阵按上表行列顺序为 `[[1,1,1],[2,0,1],[0,1,0]]`。

这三维计数行已经可比较，但只是一个原始统计表示。GloVe原论文§3以词—上下文共现统计建立学习目标，并非把原始计数行直接当作最终低维向量。本实验不优化它的损失，也不是GloVe复现。真实表示还取决于样本选择、加权和训练目标；原始频次中大量出现不等于重要或正确。

### 坐标在语言模型中的位置

在常见token输入表中，token身份用来选取某行数值向量，再交给后续网络处理。编号只负责索引，坐标才参与计算；给token重编号并同步重排表，不应改变表示。经过上下文处理后，同一token位置的中间表示还会随周围文本改变，不能把“固定输入表的一行”和“整段文本的表示”混为一谈。

作者本节也明确区分词和token，并从字词扩展到文本序列的表示。本章只解释这个接口，下一章才进入内部计算；不把本文计数法说成当前ChatGPT的真实嵌入算法，不把作者2023年的具体规模叙述当作当前产品规格。

## 从公式到三个可检算实验

以下使用同一套检查顺序：写下预测，改变一个规则，查看几何和数值，最后完整重置。符号 $q$ 是查询，$v$ 是候选，$\|v\|$ 是长度；实验三的 $A,B,C,D,E,F$ 是原创符号，不承载自然语言词义。所有分数都是计算示例，不是效果基准或运行速度测量。

| 符号           | 本章含义                              |
| -------------- | ------------------------------------- |
| $r,C_{ij},v_i$ | 窗口半径、目标—上下文计数、矩阵的一行 |
| $P$            | 公开指定的降维映射                    |
| $q,v$          | 同维查询与候选向量                    |
| $\|v\|,\hat v$ | 向量长度、单位化后的方向              |
| $A,B,C,T$      | 构造偏移的源点与搬运后的目标          |
| $t,z$          | 偏移倍数、候选E的第三坐标             |
| $d^2$          | 给定维数上的平方欧氏距离              |

计数矩阵在正文以**行列表**显示：外层是目标行，内层按“追、睡、球”的列顺序；这不是图形API的列主序内存数组。每个可视化的投影与距离都明确写出，不靠存储顺序猜含义。

### 实验一：共现矩阵到二维箭头

<Term def="把较高维向量映射到较低维坐标的操作，通常不能从结果唯一恢复原向量">
  降维投影
</Term>
让计数行能画在平面上，但必须公开映射。这里可选 $P(a,b,c)=(a,b)$ 或
$P(a,b,c)=(a,b+c)$：前者丢掉“球”，后者把“球”并入第二轴；两者都不是自动发现的语义方向，也不是PCA。

先预测：处理全部六条文档、半径2、选猫行，把第二种投影打开，箭头如何改变？再注入跨文档故障，检查计数变化，而不是只看警告。

<TcgMain09EmbeddingsContextContractLab />

正常猫行为 `(1,1,1)`，箭头从 `(1,1)` 变成 `(1,2)`。故障把文档拼成一个序列，半径2时猫行为 `(2,1,2)`：例如第一条“球”与下一条“猫”制造额外猫—球配对。故障首个分岔在**计数输入边界**，不是投影器。恢复规则后回到原矩阵；完整重置另会恢复半径2、猫行、第一种投影、第1步和暂停状态。第1步只处理前两条文档，全部矩阵请到第2步读取。

下面开始一份连续Python程序。依次拼接本章所有Python块即可用Python3标准库执行；输入范围有限，不下载模型。第一段把文档边界保留为列表的列表。

```python
from math import sqrt, isclose
from fractions import Fraction as F

DOCS = [s.split() for s in [
    "猫 追 球", "猫 睡 垫", "狗 追 球",
    "狗 追 车", "鸟 飞 天", "鸟 睡 枝",
]]
ROWS, COLS = ["猫", "狗", "鸟"], ["追", "睡", "球"]
def count(radius=2, merge=False, n=6):
    docs = DOCS[:n]
    streams = [sum(docs, [])] if merge else docs
    out = [[0 for _ in COLS] for _ in ROWS]
    for tokens in streams:
        for p, word in enumerate(tokens):
            if word not in ROWS:
                continue
            for q, context in enumerate(tokens):
                if context in COLS and 0 < abs(p-q) <= radius:
                    out[ROWS.index(word)][COLS.index(context)] += 1
    return out
```

第二段复算边界故障和两种投影。半径1时猫—球本应为0，拼接文档却令它变1，说明小窗口也不能代替文档边界。

```python
def project(v, fold=False):
    a, b, c = v
    return (a, b+c if fold else b)

normal = [[1, 1, 1], [2, 0, 1], [0, 1, 0]]
assert count() == normal
assert count(1) == [[1, 1, 0], [2, 0, 0], [0, 1, 0]]
assert count(merge=True) == [[2, 1, 2], [3, 1, 2], [1, 1, 0]]
assert count(1, True)[0] == [1, 1, 1]
assert project(normal[0]) == (1, 1)
assert project(normal[0], True) == (1, 2)
assert project(count(merge=True)[0], True) == (2, 3)
print("counts:", normal)
```

### 实验二：点积与余弦会选中不同候选

<Term def="两个同维向量对应分量乘积之和，既受方向也受模长影响">点积</Term>
把候选沿查询方向的分量汇成一个分数。
<Term def="非零向量的点积除以双方模长，衡量方向接近程度的分数">余弦相似度</Term>
则先消去双方的长度。它们不是好坏之分，而是不同问题：有时长度有用，有时只想比较方向。

$$
q\cdot v=\sum_j q_jv_j,\quad
\|v\|=\sqrt{\sum_jv_j^2},\quad
\cos(q,v)=\frac{q\cdot v}{\|q\|\|v\|}=\hat q\cdot\hat v.
$$

帽号表示单位化向量。对于非零 $q,v$，投影长度是 $\hat q\cdot v$，点积分数还要乘 $\|q\|$；余弦使用 $\hat q\cdot\hat v$。只有单边单位化时仍受另一边长度影响，不能改名叫余弦。

先预测：$q=(1,0)$，$U=(1,1)$，$V=(0.4,0)$，$W=(0,1)$。点积近邻是谁，余弦近邻又是谁？换模式时看候选端点是否移到单位圆上，而不只是读排名。

<TcgMain09EmbeddingsComputeTraceLab />

点积为 `U=1,V=0.4,W=0`，余弦为 `V=1,U≈0.7071,W=0`。把V长度改成2，真实余弦不变，点积却变2。漏除候选模长的故障会让“余弦”在这里也变2，甚至超出合法范围；首个分岔是**单位化**。若当前选择点积，这项故障无作用；不应据此宣称故障总会换冠军。查询改成 `(1,1)` 时也会改变投影方向。完整重置恢复 `(1,0)`、0.4、余弦、无故障、第1步暂停。

第三段实现单位化。这里不加一个极小数掩盖零除，因为零向量没有方向，余弦没有定义；这与把结果硬塞成0是不同契约。

```python
def dot(a, b):
    assert len(a) == len(b)
    return sum(x*y for x, y in zip(a, b))
def unit(v):
    length = sqrt(dot(v, v))
    if length == 0:
        raise ValueError("zero vector has no cosine direction")
    return tuple(x/length for x in v)
def score(q, v, metric="cos", fault=False):
    if metric == "dot":
        return dot(q, v)
    return dot(unit(q), v if fault else unit(v))
def ranking(q=(1, 0), scale=0.4, metric="cos", fault=False):
    candidates = {"U": (1, 1), "V": (scale, 0), "W": (0, 1)}
    scores = {k: score(q, v, metric, fault)
              for k, v in candidates.items()}
    return sorted(scores, key=lambda k: (-scores[k], k)), scores
```

第四段检验排序、正比例缩放不变性及零向量异常。同分仅为复现而按名称排序，不表示第二名在任务中更差。

```python
assert ranking(metric="dot")[0] == ["U", "V", "W"]
assert ranking()[0] == ["V", "U", "W"]
assert isclose(ranking()[1]["U"], 1/sqrt(2))
assert ranking(scale=2)[1]["V"] == 1
assert ranking(scale=2, fault=True)[1]["V"] == 2
assert ranking(fault=True)[0] == ["U", "V", "W"]
assert ranking(metric="dot", fault=True) == ranking(metric="dot")
try:
    unit((0, 0))
except ValueError:
    pass
else:
    raise AssertionError("zero direction must be rejected")
print("neighbors:", ranking()[0], ranking(metric="dot")[0])
```

### 实验三：偏移可搬运，距离却会丢失

向量的加减允许把一个关系形式搬到另一处，但“运算成立”和“自然语言关系成立”是两件事。GloVe论文§4.1的类比评估使用 $b-a+c$ 和余弦去候选词表中找答案；那是明确评估协议，不是普遍语义定律。本实验改用**平方欧氏距离**，专门隔离投影丢失第三维的问题，不能把结果当作论文类比精度。

令 $A=(0,0,0),B=(1,0,1),C=(0,1,0)$，先计算偏移 $B-A$，再搬运到C，目标为T。候选仅包含 $D=(1.2,1,1),E=(1,1,z),F=(1.6,1,1)$；源点A/B/C不参与近邻，避免自匹配。$t$ 为偏移倍数，$z$ 是E的深度。

$$
T=C+t(B-A)=(t,1,t),\qquad
d^2(T,v)=\sum_{j=1}^{3}(T_j-v_j)^2.
$$

人话说：偏移倍数同时改变T的第一和第三坐标。上图平行四边形只画第一、第二坐标；下方坐标尺保留第三坐标，让被隐藏的差距有可见证据。

先预测：默认 $t=1,z=4$ 时T与E在上图重合，完整三维近邻是否一定为E？再注入只看xy的故障，检查哪个距离项先消失。

<TcgMain09EmbeddingsEvidenceGateLab />

默认T为 `(1,1,1)`，完整平方距离 `D=0.04,E=9,F=0.36`，所以选D。二维距离丢掉z差异后成为 `D=0.04,E=0,F=0.36`，改选E。故障首个分岔是**距离求和的维数**，不是偏移计算。下尺中E仍在z=4，而T在z=1。改E的深度只改下尺和三维分数，不改上图位置，这是刻意构造的信息丢失证据。

若 $t=2,z=4$，T变为 `(2,1,2)`，完整距离 `D=1.64,E=5,F=1.16`，两种规则都选F；投影不是每次都错，只是不能保证保真。完整重置恢复 $t=1,z=4$、完整三维、第1步暂停。不能用一个恰巧没换冠军的输入，证明投影总可替代原空间。

第五段用有理数精确构造默认反例，避免0.04的浮点尾数干扰断言。`projected=True`恰好把第三项从距离和中删除。

```python
def analogy(t=1, z=F(4), projected=False):
    target = (F(t), F(1), F(t))
    candidates = {"D": (F("1.2"), F(1), F(1)),
                  "E": (F(1), F(1), F(z)),
                  "F": (F("1.6"), F(1), F(1))}
    dims = 2 if projected else 3
    distances = {k: sum((target[j]-v[j])**2 for j in range(dims))
                 for k, v in candidates.items()}
    nearest = min(distances, key=lambda k: (distances[k], k))
    return target, distances, nearest

assert analogy()[0] == (1, 1, 1)
assert analogy()[1] == {"D": F("0.04"), "E": F(9), "F": F("0.36")}
assert analogy()[2] == "D"
assert analogy(projected=True)[2] == "E"
assert analogy(projected=True)[1]["E"] == 0
assert analogy(2)[1] == {"D": F("1.64"), "E": F(5), "F": F("1.16")}
assert analogy(2)[2] == analogy(2, projected=True)[2] == "F"
assert analogy(z=F("1.4"))[1]["E"] == F("0.16")
print("analogy:", analogy()[2], analogy(projected=True)[2])
```

最后一段把“投影丢掉的信息”写成恒等式。二维距离小于等于三维距离，不意味着近邻排序保持；删掉不同候选的不同z差，会重排差值。

```python
for t in (1, 2):
    for z in (F(4), F("1.4")):
        full, flat = analogy(t, z)[1], analogy(t, z, True)[1]
        for name, depth in (("D", F(1)), ("E", z), ("F", F(1))):
            assert full[name] - flat[name] == (F(t)-depth)**2
print("all assertions passed")
```

预期依次输出 `counts: [[1, 1, 1], [2, 0, 1], [0, 1, 0]]`、`neighbors: ['V', 'U', 'W'] ['U', 'V', 'W']`、`analogy: D E` 和 `all assertions passed`。这些断言只检验公开输入下的算术，不是学得表示质量证明。

## 常见误区：从图像印象退回计算契约

三实验中最容易出错的不是加法，而是悄悄更换输入或度量。下列每个误区都可对应一个可计算的首个分岔点。

### 把“出现得相近”当成“意义相同”

现象：猫和鸟的某列都为1，就断言两者可互换。原因：有限语料和有限列只保留局部环境；相同计数不包含所有用途。修法：声明文档、窗口和候选列，再用明确下游任务验证；本章只证明计数怎么来，不证明语义等价。

### 把大点积分数直接叫作高余弦

现象：把V放大，声称方向更接近查询。原因：点积仍含模长，单边归一化也没有消掉候选长度。修法：复算双方长度，用实验二的s=2反例检查范围；零向量应显式拒绝，不能靠极小分母造一个方向。

### 把二维重合当成高维最近或因果关系

现象：上图E盖住T，就断言它是原空间近邻，甚至解释为对象之间的因果关系。原因：xy投影删除了z，几何相似本身也不是干预证据。修法：检查原空间分数、投影规则和候选集合，用实验三的第三维尺定位丢失项；类比偏移成立仍不保证事实关系成立。

## 小结与练习

坐标的来源、比较的规则、图形遗漏的维度，是三个独立问题。先保留文档边界取得一行计数，再明确用点积还是余弦，最后用原空间验证二维印象。任何一步换约定，都应重新计算，而不是给同一张图换一个更强的解释。

**问题 2**：在实验二将查询改为 `(1,1)`、s设为2。点积与余弦各选谁？漏除候选模长为何可能产生大于1的“余弦”？

<Answer>

点积U与V同为2，W为1；按名称确定性展示U在前。真实余弦U为1，V与W均为 $1/\sqrt2$，因此U最高。漏除候选长度时U与V都为 $\sqrt2$，不是合法余弦；问题出在单位化分母，不在显示保留几位小数。

</Answer>

**问题 3**：用最后两段Python检查 $t=2,z=1.4$ 时完整和投影各选谁。若结论相同，能否说降维从不改变近邻？请给出本章中的反例。

<Answer>

完整距离D=1.64、E=1.36、F=1.16；投影距离D=0.64、E=1、F=0.16，两者都选F。这只是该输入的结果。$t=1,z=4$ 时完整选D、投影选E，就是反例；原空间距离减投影距离等于每个候选的z差平方，不同候选删掉的量不同。

</Answer>

  </GlossaryItem>
  <GlossaryItem term="共现窗口">

  </GlossaryItem>

  </GlossaryItem>

    非零向量的点积除以双方模长，比较方向而不保留长度。

    把高维向量变为较低维坐标的映射，通常丢失信息，未必保持近邻。
