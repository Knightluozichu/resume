## 一段话顺畅，还缺哪几道检查

同一句话可以读着顺、说得通，却把地点、时间或数量说错。本章要把这些判断拆开；否则我们会把第一眼的顺畅，当成后面每一步都可靠的保证。

设想工厂里检查一件成品：外形合格，不代表内部配件配对，更不代表它经过了所有负载测试。文字也需要不同的检查。本页让三道检查分别出错，看看一种成功究竟担保了多少。

## What Really Lets ChatGPT Work? / 真正让ChatGPT工作的是什么？

这个正式目录单元追问的不是“再列一次模型结构”，而是：为什么从大量语言样本中学习，竟能得到那么丰富的表达能力？作者将这理解为语言与思考包含可被学习的规律，并由此提出寻找更显式“语言定律”的研究设想。这里的“我认为”“暗示”很重要：它是科学解释的提议，不是已经证明所有思想都简单的定理。

本页把可重复出现的组织方式称为 <Term def="在许多表达中反复出现、让某些组合比随意组合更常见的模式。">统计规律</Term>。它既包括相邻词的搭配，也可能涉及长距离关系。规律减少了可行表达的范围，因而有助于学习；这不等于模型在生成时逐条查语料，更不能推出常见的说法一定为真。

作者在该节依次讨论语法、括号序列、意义和简单逻辑。下面三个本站实验沿着这条问题链展开，但全部是手写的有限规则或枚举程序：没有训练神经网络，也没有测量任何当前 ChatGPT 产品。

## 实验一：句子的树，为什么不能压成最近邻

语言的 <Term def="词语怎样按结构组合成句子的规则，不负责保证句中事实为真。">句法</Term> 约束表达的形式。我们只选取一个极小的英语片段：主语中心是 key 或 keys，后面可以插入 near the boxes 等短语，最后从 fits 与 fit 中选择一个动词。这里的单复数规则是手工给定的，不是完整英语语法。

### 中心名词与插入短语属于不同层级

在 “The key near the boxes fits” 中，key 是主语中心，boxes 位于插入的短语中。动词随 key 而不是随距离最近的 boxes 变化。树图将这个差异画为不同分支；从中心名词连到动词的弧线，表达一个不能只靠相邻位置替代的依存关系。

符号 `sg` 表示单数，`pl` 表示复数。设主语数为 `s`，规则只有两步：`s=sg` 允许 fits，`s=pl` 允许 fit。两个候选中始终只允许一个，所以候选集合从大小二缩到一。没有给两个分支分配概率，也没有把这种规则说成模型内部真实使用的解析器。

### 先预测：多加一个插入短语会怎样

默认主语为单数、插入一个复数名词短语。先预测：把短语数量改为二，正确动词会改变吗？再开启“最近名词控制动词”，推进到末步。观察树上的控制弧线和末端选中分支，而不只看一句成品文字。

<TcgMain13WhatLetsItWorkContextContractLab />

正确路径仍选 fits，故障路径选 fit。唯一改变的是控制名词的选取方式，不是词表或主语。将短语数量改为零，故障会失去影响：最近名词恰好就是主语中心。这是重要的反例边界；只用没有干扰词的测试，发现不了错误规则。

### 用有限程序复算两条分支

以下各段 Python 按顺序放进同一个文件运行，仅用标准库，既不下载模型，也不联网。第一段让正确规则与故障规则共享输入，以便直接比较。

```python
def agreement(subject, phrases, fault=False):
    nearest = ("pl" if subject == "sg" else "sg") if phrases else subject
    controller = nearest if fault else subject
    expected = "fits" if subject == "sg" else "fit"
    selected = "fits" if controller == "sg" else "fit"
    return selected, selected == expected

assert agreement("sg", 1) == ("fits", True)
assert agreement("sg", 1, True) == ("fit", False)
assert agreement("pl", 2) == ("fit", True)
assert agreement("sg", 0, True) == ("fits", True)
print("grammar:", agreement("sg", 1), agreement("sg", 1, True))
```

预期输出包含 `('fits', True)` 与 `('fit', False)`。这段程序只检验本页定义的依存关系；某句话通过它，不意味着句子有日常意义，更不意味着它描述了真实的钥匙或盒子。

## 实验二：事实约束必须作用于完整世界

把句子写对之后，仍需追问它是否与给定事实相容。我们把满足所有给定条件的一份完整安排称为 <Term def="在指定的小范围内，同时满足所有前提的一份完整情况；不等于现实本身。">一致世界</Term>。这样做不是为生成流畅文字打分，而是将“哪些情况还没有被排除”明确列出。

### 先固定世界，再判断一句话

设虚构对象 A、B、C 分别占据位置一、二、三，每个位置恰好一个对象。只有六种排列：ABC、ACB、BAC、BCA、CAB、CBA。符号 A&lt;B 表示 A 排在 B 前，与大小、重要性或真实城市知识无关。

固定第一条前提 A&lt;B，六个世界只剩 ABC、ACB、CAB。再给 C&lt;B，只剩 ACB、CAB。查询 A&lt;C 在 ACB 中真、在 CAB 中假。给定事实还不足以确定它；“能找到一个支持例子”与“已经得到必然结论”不是一回事。

### 从一个例子到所有例子，差了一个判断

当一句话在每个一致世界都真，才说前提 <Term def="只要前提成立，结论就不能为假；需要检查所有符合前提的情况。">蕴含</Term> 该句。在非空世界集上，本页把结果分为必真、必假和未确定；若前提相互冲突，另列为“前提矛盾”，不借空集合的形式性质宣称现实事实已被证明。

图中行是对象，列是位置，格子数字是“多少个完整世界将该对象放在该位置”。默认最终矩阵为 `[[1,1,0],[0,0,2],[1,1,0]]`。每格底部短条的长度按该格计数除以当前世界总数缩放，便于比较位置支持的集中程度，不是给现实世界赋概率。这些是计数，不是模型置信度；也不能把各格独立抽取后拼成世界，否则可能让 A、C 同占一个位置。下方保留每个完整排列，正是为了保住这种相关性。

### 先预测：一个支持世界能不能替代全部

默认条件下，查询真、假的世界各有一个。先预测：若只看列表第一个 ACB，会误报什么？推进到最后一步再开启故障。然后把第二前提改为 B&lt;C：此时只剩 ABC，“必真”才有充分依据。最后试 B&lt;A，检查矛盾是否被独立报告。

<TcgMain13WhatLetsItWorkComputeTraceLab />

故障只替换判断所用的范围：从所有世界变成第一个可行世界。它没有修改前提，却把未确定报成必真。撤销故障会恢复全部世界判断。这里没有真实外部事实库；若输入前提来自现实，还必须另外核实来源、对象与时间，形式推理本身不能保证输入可靠。

### 枚举比流畅断言更容易核对

下面程序完整列出六个世界，直接计算查询真值，而不是把一句“看起来合理”的结论写死。`undetermined` 表示未确定，不是真或假中的任意猜测。

```python
from itertools import permutations

worlds = ["".join(p) for p in permutations("ABC")]
def before(world, relation):
    return world.index(relation[0]) < world.index(relation[2])

def facts(second, query="A<C"):
    valid = [w for w in worlds if before(w, "A<B") and before(w, second)]
    truth = sum(before(w, query) for w in valid)
    status = ("inconsistent" if not valid else "entailed" if truth == len(valid)
              else "refuted" if truth == 0 else "undetermined")
    matrix = [[sum(w[pos] == item for w in valid) for pos in range(3)]
              for item in "ABC"]
    return valid, truth, status, matrix

v, t, status, matrix = facts("C<B")
assert (v, t, status) == (["ACB", "CAB"], 1, "undetermined")
assert matrix == [[1, 1, 0], [0, 0, 2], [1, 1, 0]]
assert before(v[0], "A<C") and not all(before(w, "A<C") for w in v)
assert facts("B<C")[:3] == (["ABC"], 1, "entailed")
assert facts("B<A")[:3] == ([], 0, "inconsistent")
print("facts:", v, t, status, matrix)
```

行列计数能展示约束如何收紧，但真正的判断仍由完整排列给出。将查询反向为 C&lt;A，默认仍是一个真、一个假；“未确定”并不随着叙述方向改变。也不要把一比一直接解释为现实事件各有二分之一概率：我们并没有提供世界的概率分布。

## 实验三：一个需要保存远程状态的反例

作者在本节介绍了训练小型网络生成括号序列的实验，并讨论长度增加后的失败。这里不复现那些训练结果，而设计一个已知全部规则的错误程序，精确指出它丢了什么。检验一个明确的程序，比从一段失败输出推断所有神经网络的能力上限更稳妥。

### 保存尚未配对的左括号

本实验使用 <Term def="后放入的项目先取出的容器；此处保存还没找到右括号的左括号位置。">栈</Term>：读左括号就放入位置，读右括号就取出最近位置；没有可取项目却读到右括号，称为欠栈。接受条件必须同时满足：过程中没有欠栈，结束时栈为空。只检查末尾数量为零不够。

符号 `d` 是嵌套深度，`K` 是故障程序的容量。输入固定为 `d` 个左括号接 `d` 个右括号；精确程序总能完成配对。故障程序只改一条规则：满 `K` 格后丢弃新的左括号。这样做会损失远处的状态，后来即使遇到正确的右括号，也无法恢复被丢的位置。

### 先预测：第三个左括号去了哪里

默认 `d=3,K=2`。先写出精确深度轨迹 `0,1,2,3,2,1,0`，再预测错误程序的轨迹。开启故障并单步走完：第三个字符时两个栈首次分岔，第六个字符发生欠栈。图顶端虚线画出全程参考配对，实线是本次真正执行的配对；它们不是网络预测概率。

<TcgMain13WhatLetsItWorkEvidenceGateLab />

故障深度为 `0,1,2,2,1,0,0`，最后也是零，但欠栈标记必须保留，所以拒绝。将 `K` 改为三，或把 `d` 降为二，故障路径又会通过。可见短样本上的成功没有证明程序能处理任意深度；同样，一个有限程序的失败也不能直接证明当前所有语言模型都不可能实现配对。

### 逐字符实现，而不是只给末端结论

下面保存每一步深度以及首个欠栈位置，和图中的程序使用相同的“满时丢弃”规则。图额外保存左括号位置以画匹配弧线；判断接受所需的深度和错误标记在这里完整保留。

```python
def bracket_trace(depth, capacity=None):
    text = "(" * depth + ")" * depth
    stack, sizes, underflow, lost = [], [0], 0, 0
    for index, char in enumerate(text, 1):
        if char == "(":
            if capacity is not None and len(stack) == capacity:
                lost += 1
            else:
                stack.append(index)
        elif stack:
            stack.pop()
        elif not underflow:
            underflow = index
        sizes.append(len(stack))
    return sizes, underflow, lost, not stack and not underflow

exact = bracket_trace(3)
bad = bracket_trace(3, 2)
assert exact == ([0, 1, 2, 3, 2, 1, 0], 0, 0, True)
assert bad == ([0, 1, 2, 2, 1, 0, 0], 6, 1, False)
assert next(i for i, (a, b) in enumerate(zip(exact[0], bad[0])) if a != b) == 3
assert bracket_trace(2, 2)[3] is True
print("stack:", exact, bad)
```

对于这一族输入，若 `d>K`，首先在字符 `K+1` 丢状态，首次欠栈在字符 `d+K+1`；如果 `d<=K` 就不会溢出。这个结论来自该程序的具体规则，不能挪作真实模型推理深度的测量。

### 让边界也进入自动检查

把深度一至六、容量一至四的二十四个组合全部跑完，可以避免只挑一个醒目反例。下面是前一段程序的有限穷举，不是性能基准或模型评测。

```python
for d in range(1, 7):
    for k in range(1, 5):
        sizes, underflow, lost, accepted = bracket_trace(d, k)
        assert accepted == (d <= k)
        assert lost == max(0, d - k)
        assert underflow == (d + k + 1 if d > k else 0)
        assert sizes[-1] == 0
print("boundary cases:", 24, "passed")
```

预期最后输出 `boundary cases: 24 passed`。提高容量可以修复本范围内的失败；若想接受无界深度，就不能再用固定容量的丢弃规则。现实系统还可以通过分步输出、外部记忆或工具改变计算过程，因此不要把“单次局部预测”与“整个系统可执行的过程”混为一谈。

## 三个结果，三种不能越过的边界

三个实验不是给模型发一张通用合格证，而是分别排除不同的错误推断。树上的约束说明为什么学习表达不必穷举一切词串；排列中的反例说明为什么流畅不能保证必真；栈的状态损失说明为什么短程成功不能保证长程执行。

### 作者的解释与本站的证据应分开

作者提出寻找隐含语言规律的方向，并以简单逻辑等例子说明语言约束不止句法。他对于意义的一般理论仍保留探索语气。本页的规则、世界和栈都由我们显式给定，能提供精确检查，却没有从模型权重中“发现语言定律”。三个成功演示也不能证明人类语言的全部复杂性已经被解释。

### 不把有限反例升级成普遍定理

这里没有证明计算不可约性，也没有推出“神经网络不能计算”。错误栈失败是因为我们指定了容量与丢弃规则；精确栈则成功。真正评估模型，需要固定版本、输入、推理设置与工具权限，再保存中间状态和结果。2023 年文章提及的网络规模、括号实验表现以及约 1750 亿权重的表述，均不是对当前产品的已核实规格。

## 容易混淆的三件事

检查时先问“这里究竟由什么规则保证”，能避免把一类成功借给另一类任务。

## 小结与练习

回到开头的三道检查：每个目标都有一个能当场复算的结果，而不是一句“语言模型很强或很弱”的总评。

- 主语中心控制动词；插入短语不改变中心的数。
- 前提下必真需要所有一致世界支持，且前提本身仍需核实。
- 三层、两格时第三字符丢状态，第六字符欠栈。

## 名词解释

本章的五个术语对应不同的检验对象：统计规律帮助预测常见表达，句法检查主语与动词的形式约束；一致世界列出满足前提的完整安排，蕴含要求结论在这些安排中全部成立；栈则保存远处尚未配对的左括号位置。分清这些检验，才能解释为什么句法正确不等于事实为真、给定前提内的蕴含不等于现实核验，而有限状态实验中的成功也不证明模型能完成任意长度的计算。
