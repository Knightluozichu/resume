## 为什么“句子顺”还不够

“我用望远镜看见男子”和“我看见带望远镜的男子”可能来自同一串英文词。只检查词放得对不对，不能替我们决定望远镜跟着谁。若系统过早选定一种读法，后续计算即使毫无差错，也可能回答错问题。

另一个问题更直接：2米加30厘米可以计算，2米加30秒却不能靠删去单位变成32。我们需要把句子的连接方式、允许的组合规则和真正执行的计算分开检查，而不是把一段流畅文字直接当作结论。

## Semantic Grammar and the Power of Computational Language / 语义语法与计算语言的力量

本节把“能拼成句子”拆成三个需要分别回答的问题：词语怎样连接，连接后的结构允许怎样解释，以及选定解释后能执行什么计算。它们逐层增加条件，却都不能代替对现实的观察；下面先从同一句话的两种连接方式出发，再说明执行规则为何仍有边界。

### 从连接规则到解释条件

<Term def="规定词或短语怎样组成更大结构的规则；同一词序可能对应多棵树。">
  句法
</Term>
检查结构怎么搭。实验一把英文简化为 `I saw man with telescope`，省略冠词，只讨论
`with telescope`
接在哪个节点。它接在观察事件上，或接在男子上，都是下面玩具规则允许的结构。

<Term def="在给定概念分类与世界假设下，进一步限制哪些组合可解释的规则。">
  语义语法
</Term>
还要说明这些结构指什么、哪些概念可以组合。本章**人为约定**：事件附着表示观察者使用望远镜，实体附着表示男子携带望远镜；给定场景再指定谁拥有它。这不是对所有英语用法的定义，也不是系统从句子里证明了场景。规则处于“解释句子”之后、“执行计算”之前。

精确的执行规则也不自动让任意输入语法没有歧义：必须先指定如何解析、绑定或消歧，再对选定结构求值。实验一保留两棵树，正是为了不把这两件事混为一谈。

作者在2023年原文开头用“my strong suspicion”提出：有意义的语言或许比我们以往认为的更有简单结构。这是研究假说与展望，不是已经证明的普遍定律。本章用可完全检查的小系统展示问题，既不复现 ChatGPT，也不复现 Wolfram Language 的解析器。

### 结构、可计算性与事实是不同检查

<Term def="对某种项允许参加哪些运算的分类；本章用长度和时间的指数表示量的维度。">
  类型约束
</Term>
让系统拒绝不合规则的组合。实验二中，长度加时间会失败；长度除以时间却得到速度。检查的位置不是生成词语时的流畅度，而是执行运算前的输入条件。

<Term def="由操作名及其参数组成的结构；参数可以是数、符号或更小的项。">
  符号项
</Term>
保留了可操作的内部结构，如 `Mul(Add(2,3),4)`。实验三的
<Term def="按明确规则把一个可计算子项替换为结果的单步操作。">归约</Term>先把
`Add(2,3)` 换成 `5`，再得到 `20`；没有为 `Blue` 定义数值规则，就停在原项。

停滞只表示本玩具规则无法继续，不代表该符号在日常语言里没有意义。反过来，算出数值也只说明所选形式规则执行成功。一个关于虚构物体的尺寸计算可以类型正确，但物体是否存在还需独立事实。作者也明确区分“通过语义语法”与“在现实中已经实现”。

## 三个可检算的结构

下面用三种不同结构把上述区别变成可检查的操作：树的父边保存候选读法，单位指数与量值标尺分开检查能否运算和怎样换算，表达式带则记录每次替换有没有真正发生。每个实验都先给出有限规则，再改参数、注入故障并恢复，比较结构变化与数值结果是否一致。

### 实验一：只移动一条父边，读法就变了

使用如下有限规则，`N` 只接受 `I`、`man`、`telescope`，`V` 只接受 `saw`，`P` 只接受 `with`：

```text
S  → N VP
VP → V NP | V NP PP
NP → N | N PP
PP → P N
```

`VP → V NP PP` 产生事件附着；`VP → V NP` 配合 `NP → N PP` 产生实体附着。整句恰有两棵树，不是两个不同词序。若场景约束为“男子拥有望远镜”，只有实体附着相容。**候选数2、相容数1**是本规则与解释约定的计数，不是概率、理解质量或自然语言歧义总数。

先预测：把拥有者从观察者改成男子，候选数和相容数哪个会变？先保持事件附着，单步看父边出现；再改为实体附着，比较 PP 父边从 VP 移到 NP。把拥有者设成男子，然后打开“删除 NP 附着”故障：语法本来允许2棵，保留只剩1棵，场景相容从1降到0。恢复规则后应回到2和1。若场景为观察者，故障仍丢一棵树，但相容数保持1，这是不能省略的无影响边界。

### 实验二：换算数值不等于统一维度

写一个量为 `(v,s,d)`：`v` 是输入数字，`s` 是换到基准单位的比例，`d=(L,T)` 是长度、时间的指数。米与厘米均为 `(1,0)`，秒为 `(0,1)`；厘米的比例为 `0.01`，米、秒为 `1`。本例只处理这些线性单位，没有温度等带偏移的换算。

加法必须先检查 `d₁=d₂`，通过后才用换算后的数相加；除法则让指数逐项相减：

$$
\operatorname{Add}((v_1,s_1,d_1),(v_2,s_2,d_2))
=(v_1s_1+v_2s_2,d_1),\qquad d_1=d_2
$$

这个式子在说：只有维度相同时，才能把两个换到基准单位的数相加，并保留原维度。

$$
\operatorname{Divide}((v_1,s_1,d_1),(v_2,s_2,d_2))
=\left(\frac{v_1s_1}{v_2s_2},d_1-d_2\right),\qquad v_2s_2\ne0
$$

这个式子在说：除法让量值相除、长度和时间的指数分别相减，且分母不能为零。

因此 `2m+30cm = 2.3m`；`2m+30s` 拒绝；`2m/30s = (1/15)m/s`，维度为 `(1,-1)`。图中标尺段表示换算后的量值，格点表示维度，两者不能混读。厘米换成米会改量值段，但不会改维度位置；切到秒会移动维度点。

先预测：厘米改为米，量值段与维度点会分别怎样变化？依次改右项单位、加／除运算，再注入“剥掉单位”故障：两输入维度都被压到原点，加法给出无量纲32。它不是修好了 `m+s`，而是把原问题丢掉了。恢复规则后，`Add/s` 必须重新拒绝。完整重置才恢复 `Add/cm` 的默认2.3m。

### 实验三：项缩短，才能看见计算实际发生

本玩具只定义“两个数相加”和“两个数相乘”。先加模式为 `(2+a)×4`，先乘模式为 `2×a+4`，后一项按乘法优先连接。`a=3` 时，归约分别是：

```text
(2+3)×4  →  5×4  →  20
2×3+4    →  6+4  →  10
```

同样的数字与操作因结构不同产生20和10。把 `a` 改成 `Blue`，输入仍由合法原子和操作组成，但没有数值规则可用；后两帧保持同一项，收缩次数为0。这里没有调用自然语言模型，也没有把字符串交给 `eval`。

先预测：未定义符号会使带子继续缩短，还是停在原处？故障把 `Blue` 偷换成0，先加模式错误得到8，先乘模式错误得到4。**我们拒绝的是无依据的数值解释，不是蓝色这个概念。** 恢复后应重新停滞；若 `a=3`，该故障不改变20或10。进度条显示当前项，淡行预告完整轨迹，单步高亮逐次推进；完整重置还会停掉播放。

## 用标准库复现：先保留结构，再执行规则

把下面代码块按顺序拼成一个 `.py` 文件，用 Python 3 执行。程序只穷举五个词的有限组合，固定执行至多两次归约，不联网、不训练模型、不测速度。首先列出词类与产生式；`parse` 对每个子串枚举所有非空切分，返回树而非只返回一个“正确”标志。

```python
from functools import lru_cache
from itertools import combinations, product
from fractions import Fraction as F

words = "I saw man with telescope".split()
lexicon = {"N": {"I", "man", "telescope"},
           "V": {"saw"}, "P": {"with"}}
grammar = {"S": [("N", "VP")],
           "VP": [("V", "NP"), ("V", "NP", "PP")],
           "NP": [("N",), ("N", "PP")], "PP": [("P", "N")]}

@lru_cache(None)
def parse(symbol, lo, hi):
    if symbol in lexicon:
        return ((symbol, words[lo]),) if (
            hi - lo == 1 and words[lo] in lexicon[symbol]) else ()
    trees = []
    for rhs in grammar[symbol]:
        for cuts in combinations(range(lo + 1, hi), len(rhs) - 1):
            bounds = (lo, *cuts, hi)
            choices = [parse(s, bounds[i], bounds[i + 1])
                       for i, s in enumerate(rhs)]
            trees.extend((symbol, *children)
                         for children in product(*choices))
    return tuple(trees)
```

接着查找 PP 的直接父节点，把两种结构与本章人为解释对应。故障只是删除 NP 读法，不能把这种实现选择说成语言规律。

```python
def pp_parent(tree):
    for child in tree[1:]:
        if not isinstance(child, tuple):
            continue
        if child[0] == "PP":
            return tree[0]
        found = pp_parent(child)
        if found:
            return found
    return None

trees = parse("S", 0, len(words))
readings = {pp_parent(t) for t in trees}
assert len(trees) == 2 and readings == {"VP", "NP"}
def compatible(owner, prune=False):
    retained = readings - ({"NP"} if prune else set())
    required = "VP" if owner == "observer" else "NP"
    return len(retained), int(required in retained)
assert compatible("man") == (2, 1)
assert compatible("man", True) == (1, 0)
assert compatible("observer", True) == (1, 1)
print("parse: 2 trees; man-compatible 1 -> 0 under pruning")
```

单位值用 `Fraction` 精确计算，避免把显示小数的舍入当作约束条件。先把单位转换为比例和指数；只有加法要求指数相等。抛出异常是预期拒绝，不是让程序静默返回32。

```python
units = {"m": (F(1), (1, 0)), "cm": (F(1, 100), (1, 0)),
         "s": (F(1), (0, 1))}
def quantity(op, unit, erase=False):
    scale, right_dim = units[unit]
    left_dim = (1, 0)
    if erase:
        scale, left_dim, right_dim = F(1), (0, 0), (0, 0)
    right = 30 * scale
    if op == "add":
        if left_dim != right_dim:
            raise ValueError("dimension mismatch")
        return F(2) + right, left_dim
    assert op == "divide" and right != 0
    return F(2) / right, tuple(a - b for a, b in
                              zip(left_dim, right_dim))

assert quantity("add", "cm") == (F(23, 10), (1, 0))
assert quantity("divide", "s") == (F(1, 15), (1, -1))
assert quantity("divide", "cm") == (F(20, 3), (0, 0))
try:
    quantity("add", "s")
except ValueError as exc:
    assert str(exc) == "dimension mismatch"
else:
    raise AssertionError("m+s must be rejected")
assert quantity("add", "s", True) == (F(32), (0, 0))
print("units: 23/10 m; m+s rejected; division 1/15 m/s")
```

最后用元组保存符号项。`step` 只处理白名单内的操作：若两个参数已是数，就计算；否则先尝试左子项，再尝试右子项。故障只在数值规则入口把 `Blue` 当0，因此也能定位第一次错误发生在哪里。

```python
def numeric(x, coerce):
    return isinstance(x, int) or (coerce and x == "Blue")

def step(term, coerce=False):
    if not isinstance(term, tuple):
        return term
    op, left, right = term
    assert op in {"+", "*"}
    if numeric(left, coerce) and numeric(right, coerce):
        a = 0 if left == "Blue" else left
        b = 0 if right == "Blue" else right
        return a + b if op == "+" else a * b
    new_left = step(left, coerce)
    if new_left != left:
        return op, new_left, right
    new_right = step(right, coerce)
    return op, left, new_right

def trace(group, atom, coerce=False):
    term = ("*", ("+", 2, atom), 4) if group == "sum-first" else (
        "+", ("*", 2, atom), 4)
    rows = [term]
    for _ in range(2):
        term = step(term, coerce)
        rows.append(term)
    return rows
```

这组断言同时覆盖正常、停滞、错误强制转换和故障无影响边界。停滞检查比较结构是否保持，而非把“不是数字”一概报成解析失败。

```python
for group, normal, wrong in [("sum-first", 20, 8),
                              ("product-first", 10, 4)]:
    rows = trace(group, 3)
    assert isinstance(rows[0], tuple) and rows[2] == normal
    blocked = trace(group, "Blue")
    assert blocked[0] == blocked[1] == blocked[2]
    assert trace(group, "Blue", True)[2] == wrong
    assert trace(group, 3, True)[2] == normal
print("reduce: 20/10; Blue stuck; faulty values 8/4")
```

预期恰好输出三行：`parse: 2 trees; man-compatible 1 -> 0 under pruning`、`units: 23/10 m; m+s rejected; division 1/15 m/s`、`reduce: 20/10; Blue stuck; faulty values 8/4`。所有例子都来自这里明示的规则，不是实际模型向量、训练结果或产品性能。

## 常见误区

这三类错误会发生在不同位置：候选还没交给解释规则就被误删，单位在运算前被丢弃，或计算结果被越界当作现实证据。排查时应找到最先丢失的信息，而不是只看最后有没有得到一个数；下面分别对照实验中的现象、原因和修法。

### 把首个读法当成唯一读法

<Callout type="trap" title="候选生成失败">

**现象 →** 场景说男子带望远镜，解析结果却找不到相容候选。

**原因 →** 实验一的贪心故障删除了合法 NP 附着，候选生成已丢信息。

**修法 →** 保留两棵树后再应用场景约束；不要用后续计算正确掩盖前段误删。

</Callout>

### 把去单位当成换单位

<Callout type="trap" title="单位信息丢失">

**现象 →** 实验二让米加秒，得到看似漂亮的32。

**原因 →** 故障删除了量的类型与换算比例，把两个原本不同的问题混成无量纲算术。

**修法 →** 先检查指数；兼容时才换算比例。不兼容则拒绝，不能“补一个默认单位”。

</Callout>

### 把可求值当成现实为真

<Callout type="trap" title="执行与事实分离">

**现象 →** 表达式算出20，就声称句中实体和关系已获证实。

**原因 →** 实验三只保证按定义归约，没有观察世界；作者的未来展望也不是现有通用事实检查器。

**修法 →** 分别说明输入解释、运算规则与外部事实依据；保持未定义符号，不偷换为0。

</Callout>

## 小结与练习

完成三个实验后，应能沿着“保留读法—检查组合—执行替换”的顺序解释一个结果，并指出哪一步仍没有提供世界事实。下面先压缩回顾各结构的作用，再用无影响边界、单位扩展和未定义符号检查这些区别能否迁移到新输入。

- 移动 PP 父边能换读法，误删候选会失去解释。
- 单位指数控制能否运算；比例控制换算数值。
- 归约可检查执行，但不能单独证明世界事实。

## 名词解释

下面五个词对应本章三个实验中不同的检查对象：句法处理连接结构，语义语法处理给定假设下的解释，类型约束限制可组合的输入，符号项保存计算对象，归约记录实际替换。阅读时可用这些区别定位失败发生在哪一层，不要把它们统称为“理解正确”。
