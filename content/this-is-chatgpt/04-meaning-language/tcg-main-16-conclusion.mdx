## 直觉：运行方式与成功范围是两个问题

看见机器连续写出像样的句子，很容易把“它怎样写出来”与“它为什么能做好这件事”当成同一问。只会描述每一步运算，解释不了新题的成败；只展示一篇好文章，也还没有说明运算。

本章把两问接起来：先追踪一条续写，再改变它所依赖的材料，最后拿没有用于挑选规则的新题检查结果。这样才能看到解释链在哪一段成立，哪一段仍缺答案。

## So ... What Is ChatGPT Doing, and Why Does It Work? / 所以，ChatGPT究竟在做什么，为什么有效？

本节按作者2023年结论的原坐标回收两条解释线：网络怎样接续文本，以及这种运算为何能在某些任务上成功。前者可以追踪输入与输出，后者还需要数据条件和独立任务结果；下文把两者分开检验，不把当年的前向网络描述当成现代ChatGPT全部系统能力的规格。

### 结论中的两层回答

作者在2023年结尾先给出操作层回答：用大量人类文本训练神经网络，再把提示与已经写出的内容送入网络，继续生成。这衔接了前文的输入表示、网络计算和训练，而不是说系统从原文仓库按索引拼句子。学习到的参数会影响候选排序；生成时每多一个词元，下一次计算所见的内容也变了。实验一保留“反复条件化”，不重新展示前章的注意力矩阵。

另一层回答更开放：大量简单计算单元为什么能形成连贯、有用的语言行为？作者将表现与语言中可利用的结构联系起来，并提出进一步寻找语义规律的研究方向。这里应区分可复算的运算、实际任务表现和对语言本质的推测。实验二检验数据依赖，实验三检验新题表现；它们都不能证明作者更强的语言或思维假说。

### “每次前向计算”不等于整个系统只算一次

原段把一次生成所用网络描述为没有内部循环的前向运算。这是当时讨论的范围，不是说整段生成没有重复：外层必须不断更新上下文并再次调用。对工具的调用、程序执行与现代产品内部策略也不能由这句历史概述排除。前文章节出现的175B或温度0.8，同样不是当前ChatGPT规格或普适最优设置。

作者承认“听来合理”可能既不全局一致，也不符合正确计算。因此“为什么有效”必须加宾语：在哪种输入、哪类任务、什么评判下有效？接下来的手工系统把这些条件缩小到可以穷举的程度，代价是不能把其成功率外推到语言模型、脑或意识。

## 实验一：固定条件表也不会只有一条续写

先把续写缩成三步、两个符号：条件表决定每个分叉的概率，抽样带决定这次沿哪条分支走。比较不同路径及其概率乘积，能检验“规则固定”是否意味着“输出唯一”，却不涉及句子是否真实或有用。

### 预测：规则不变，路径可以变

这里的<Term def="给定已经出现的内容后，对下一候选分配总和为1的概率">条件分布</Term>只含A、B两个符号。起始时A的概率为0.6；上一步为A时取q，为B时取1−q。它是人为设定的规则，不是从真实文本训练出来的模型。

在点击前先预测：同一条件表是否只能得到一种三词元串？

每步读取一个固定数u：u小于A的概率就选A，否则选B。固定抽样带让反例可重放，不代表真实系统使用这三枚数。在q=0.75、u=(0.2,0.8,0.4)时，先选A，再选B，最后选B。路径的<Term def="将每一步在实际前缀下选中词元的概率相乘得到的序列概率">联合似然</Term>是：

$$
P(ABB)=P(A)P(B\mid A)P(B\mid AB)=0.6\times0.25\times0.75=0.1125.
$$

这个式子在说：先写A、接着在A后写B、再在AB后写B，三步各自的条件概率相乘，才得到整条ABB路径的概率；它不是答案正确的概率。

### 操作：改变抽样带，再冻结上下文

先单步到最后，检查ABB与0.112500。只切换抽样带为(0.8,0.2,0.8)，会得到BAB与0.025000；表并没有变。再换回默认带，把q改为0.9，得到AAA与0.486000。这些不是“更聪明”的排列，只是不同条件与不同选择。

打开冻结上下文故障后，每步错误地沿用起始0.6。默认带生成ABA，概率0.144000；首个概率分岔在第二步，而不是最后显示字符串时。树的边宽表示到达子节点的联合质量，红色路径标出当前已走前缀，下方折线检查乘积逐步缩小。

<TcgMain16ConclusionContextContractLab />

### 解释：一条文本不能唯一反推模型

八条叶路径的概率和为1；单条输出只是其中一条。看到相同文本，不能断言内部概率相同；看到不同文本，也不能断言规则已经更新。完整重置应把q、抽样带、故障、帧和播放状态一起复原。高似然也不是事实支持：这里连“事实标签”都没有，只有符号路径。

## 实验二：材料与输入共同决定续写偏向

接着分别干预材料来源与输入条件，观察同一候选的概率怎样移动。这里用有限计数表隔离两种变化，再故意抹去行名作为反例；比较的是续写偏向，不是材料可信度或事实正确率。

### 预测：同一个“是”没有脱离上下文的固定概率

实验用两份各20条的有限语料，计数顺序均为[是,否]。A中草稿行为[9,1]，核验行为[2,8]；B中分别为[3,7]和[8,2]。“核验”只是行名，不保证任何内容经过真实核验。

定义混合比例m，逐格计数为(1−m)A+mB，再给每个候选加1，避免零计数。每行原计数和为10，所以草稿行的概率为：

$$
P_m(是\mid 草稿)=\frac{(1-m)9+m3+1}{12}.
$$

这个式子在说：先按混合比例合成草稿行“是”的计数，再加1并除以平滑后的总数12，得到该上下文下选择“是”的概率。

从m=0的10/12移到m=1的4/12，就是这里可测的<Term def="数据来源或输入条件改变，使原来的概率或表现不再保持不变">分布迁移</Term>。气泡面积跟计数走，位移线连接A的基线概率与当前概率，不是“数据可信度”的评分。

### 操作：一次只改一个条件

默认m=0，草稿行P(是)=0.833333；不换语料，只把输入切到核验行，就变为0.250000。再设m=1，两行分别为0.333333和0.750000。混合到m=0.5时则是7/12和6/12。参数修改会暂停播放，当前帧仍可手动前后检查。

故障先给原来的四格各加1，再忽略行名，把两行合并。m=0时两种上下文都变为(9+2+2)/24=13/24。注意分子中的2是两行各自保留的一份平滑计数；不是对合并表重新只加1。条件差异被抹平，是计算上的信息丢失，不是发现了更稳健的世界规律。

### 解释：查表是隔离变量，不是真实ChatGPT实现

真实模型用训练更新参数，并通过输入表示与网络计算产生分布，不是按这两行字面匹配。这个替代系统只让“材料改变”与“输入改变”可分别计算。它不测现实语料规模、神经网络的泛化或当前产品数据。

作者结论中“从已积累的语言统计中续出连贯线索”解释了为何数据相关性重要，却不能使高频说法自动成为真命题。索引污染、恶意指令或错误语料也不能因进入输入便获得可信地位；概率变化需要另行接受事实检验。

## 实验三：有限执行记录与新题表现要同时保留

最后用四位二进制数的奇偶任务，把“执行了哪些步骤”与“在哪些题上答对”并排记录。手写程序的读取位数可调，十六道题可穷举；这个边界明确的小例子用于检查评估分母，而不是模拟语言模型的实际能力。

### 预测：结束了的运算也可能系统性答错

把全部四位二进制串作为16道小题，目标是其中1的个数模2。程序从状态s=0出发，只读取前b位，每读一位就执行s←(s+bit) mod 2。这里的<Term def="明确限制本次程序可读取和更新的步数，而非机器速度或智能程度">计算预算</Term>就是b，取1到4；后面的虚线位置不读取，状态保持不变。

把末两位都是00的四题用于选择规则，另十二题作为<Term def="不参与选择这条规则、随后才用来核对输出的一组固定题目">留出集</Term>。这不涉及神经网络训练。b=2在训练四题上全对，因为忽略的位恰好都是0；在独立十二题上只对四题，因为末两位仅在11时相加不改变奇偶。

### 操作：先看单题状态，再看全部枚举

默认追踪0001：预算2读完前两位后停在0，但完整目标为1。逐步执行能说明错误从何而来；点阵再显示这是哪些题上的共同问题，而非只挑一个难例。将b改为4，0001的最后一位使状态变1，独立结果变为12/12。

评估污染故障不改变程序，不增加预算，也不修正任何预测；它只是拿原四道训练题冒充留出。b=2时reported会显示4/4，而actual独立结果仍是4/12。界面同时保留两组分母，不能用“100%”遮住换题行为。恢复后，reported与actual重新指向同一组十二题。

<TcgMain16ConclusionEvidenceGateLab />

### 解释：“简单元素能做事”不是任意能力证明

这个任务的状态更新极简单；成功来自读取了完成目标所需的位，而不是给程序取了一个拟人的名字。16题穷举可以完整检验此任务，却不能说明开放语言任务也有同样简洁的判据。预算4的正确答案，更不能证明其理解、思考或意识。

这把原文的“简单计算元件可以组合出意外表现”变成了一个谨慎的研究姿态：记录具体运算，测量具体任务，然后问哪些数据结构与训练过程支持外推。前向计算细节能解释输出怎样产生，但能力分布仍须实际评估；一个有限玩具的失败也不能证明语言模型必然失败或无法借助工具解决。

## 可执行对照：从路径到反事实再到留出

以下三段按顺序保存为同一个Python文件即可运行，仅用标准库；不会联网、训练模型或测硬件性能。它们与图中常量相同，断言比输出格式更重要。

### 路径乘积与概率守恒

```python
from math import isclose, isfinite

def thread(q=.75, tape=(.2, .8, .4), fault=False):
    prefix, joint, trace = "", 1., []
    for u in tape:
        p = .6 if not prefix or fault else q if prefix[-1] == "A" else 1-q
        token = "A" if u < p else "B"
        joint *= p if token == "A" else 1-p
        prefix += token
        trace.append((prefix, p, joint))
    return prefix, joint, trace

def leaves(q, prefix="", joint=1.):
    if len(prefix) == 3:
        return [joint]
    p = .6 if not prefix else q if prefix[-1] == "A" else 1-q
    return leaves(q, prefix+"A", joint*p) + leaves(q, prefix+"B", joint*(1-p))

assert thread()[0] == "ABB" and isclose(thread()[1], .1125)
assert isclose(thread(tape=(.8, .2, .8))[1], .025)
assert thread(.9)[0] == "AAA" and isclose(thread(.9)[1], .486)
assert thread(fault=True)[0] == "ABA"
for q in [.6, .75, .9]:
    assert isclose(sum(leaves(q)), 1.)
    assert all(isfinite(v) and v > 0 for v in leaves(q))
print("paths", thread()[0], round(thread()[1], 6), thread(fault=True)[0])
```

预期：`paths ABB 0.1125 ABA`。这里的乘积是按实际前缀计算，不是三个固定边缘概率的乘积。

### 混合后再条件化

```python
A, B = [[9, 1], [2, 8]], [[3, 7], [8, 2]]

def shift(m, fault=False):
    counts = [[(1-m)*A[i][j]+m*B[i][j] for j in range(2)] for i in range(2)]
    pooled = (counts[0][0]+counts[1][0]+2)/24
    p = [pooled if fault else (row[0]+1)/12 for row in counts]
    return counts, p

assert isclose(shift(0)[1][0], 10/12)
assert isclose(shift(0)[1][1], 3/12)
assert shift(1)[1] == [4/12, 9/12]
assert shift(.5)[1] == [7/12, 6/12]
assert shift(0, True)[1] == [13/24, 13/24]
for m in [0, .25, .5, .75, 1]:
    for fault in [False, True]:
        counts, p = shift(m, fault)
        assert all(isclose(sum(row), 10) for row in counts)
        assert all(isfinite(v) and 0 <= v <= 1 for v in p)
print("shift", [round(p, 6) for p in shift(0)[1]])
```

预期：`shift [0.833333, 0.25]`。池化故障仍保留每个原格的平滑量，因此不能另用一个不同分母来“修正”结果。

### 逐例输出与被偷换的评估集

```python
TASKS = [format(n, "04b") for n in range(16)]

def parity(bits, budget):
    states = [0]
    for i, bit in enumerate(bits):
        states.append((states[-1]+int(bit)) % 2 if i < budget else states[-1])
    target = sum(map(int, bits)) % 2
    return states, target

def evaluate(budget, fault=False):
    train = [s for s in TASKS if s.endswith("00")]
    heldout = [s for s in TASKS if not s.endswith("00")]
    correct = lambda s: parity(s, budget)[0][-1] == parity(s, budget)[1]
    reported = train if fault else heldout
    return (sum(map(correct, train)), sum(map(correct, heldout)),
            sum(map(correct, reported)), len(reported))

assert parity("0001", 2) == ([0, 0, 0, 0, 0], 1)
assert parity("0001", 4) == ([0, 0, 0, 0, 1], 1)
assert evaluate(2) == (4, 4, 4, 12)
assert evaluate(2, True) == (4, 4, 4, 4)
assert evaluate(4) == (4, 12, 12, 12)
for budget in range(1, 5):
    for bits in TASKS:
        states, target = parity(bits, budget)
        assert all(isfinite(v) and v in [0, 1] for v in states+[target])
print("heldout", evaluate(2), "contaminated", evaluate(2, True))
```

预期：`heldout (4, 4, 4, 12) contaminated (4, 4, 4, 4)`。前两项始终是真实训练／独立结果；后两项是reported的分子／分母。污染不改变预测，只改变报表取了哪组题。

## 常见误区

下面三种错误分别把路径概率当作理解、把出现频率当作事实、把训练结果当作新题表现。纠正它们时，应回到相应实验中检查概率、来源条件或逐题输出，而不是只换一个更好看的总分。

### 误区一：能背出下一词元计算，就解释了全部能力

<Callout type="trap" title="似然不是正确性">
**现象 →** 用树上一条高概率路径证明模型“懂了”。

**原因 →** 把如何选择输出与对任务目标是否正确混为一谈。

**修法 →** 树上只报告概率；另用实验三明确列出的目标与新题统计成败。

</Callout>

### 误区二：常见说法就是可靠知识

<Callout type="trap" title="频率不是事实核验">
**现象 →** 混合语料后“是”的概率升高，便认为命题更真。

**原因 →** 实验二的计数没有事实标签，行名也不提供可信核验。

**修法 →** 分别检查材料来源与外部事实；不能让频率、检索相关性或输入中的指令替代支持。

</Callout>

### 误区三：四例全对，足以宣布通用成功

<Callout type="trap" title="训练结果不是独立结果">
**现象 →** 污染故障给出4/4，独立十二题的失败却被略去。

**原因 →** 评估重用了挑选规则的题，分母与目标任务不再相同。

**修法 →** 同时列出reported与actual及逐例输出；撤销污染后重算，而不是把小例推成智力或意识结论。

</Callout>

## 小结与练习

检验本章是否读懂，需要能沿着同一条解释链完成三件事：算出一条路径的概率，定位改变分布的条件，并为新题结果保留正确分母。下面先归纳对应关系，再用具体改参题检查能否自行复算。

- 同一条件规则可以产生多条路径，概率不等于事实。
- 材料与输入分别改变续写分布，不能混同来源。
- 执行轨迹说明怎么算，新题结果限定成功范围。

**问题 1：计算与局部改写**

默认抽样带、q=0.9时为什么得到AAA？若将Python的起始概率从0.6改成0.5，其余条件不变，路径与联合似然分别是什么？

**问题 2：分开语料与上下文**

m=0.5时，两种上下文下P(是)分别是多少？打开池化故障后又是多少？为什么不能说故障提高了回答可靠性？

<Answer>
  草稿混合计数[6,4]，平滑后7/12；核验[5,5]，平滑后6/12。合并是(6+5+2)/24=13/24，两行都相同。没有任何真实命题的真假标签；概率居中只是丢掉上下文的结果，不是可靠性测量。
</Answer>

**问题 3：预算与留出分母**

把b从2改到3为何独立结果仍是4/12？打开污染后reported又是多少？这能否证明增加计算没有用？

<Answer>
  b=2对末两位11的四题正确；b=3改为对末位0、但非训练集的四题正确，题目身份变了，数量碰巧相同。训练四题仍全对，所以污染后reported为4/4。b=4则独立12/12；不能仅凭两个预算下相同的总数否认计算作用，更不能外推到语言模型。应查看点阵与逐例轨迹。
</Answer>

</Exercises>
