## 先别把书尾的名字当作保证

书尾列了许多名字和学习入口，我们该感谢谁、接着读什么，与“哪句话已被证实”是不同的问题。若把它们混在一起，一段转述就可能借别人的名字取得并不存在的保证。

本页把这几类关系拆开。先追到被引用的材料，再判断它回答哪一个问题，最后检查手中的副本与允许的用途。三个小实验都使用固定假数据，不测试今天的网站是否在线。

## Thanks / 致谢

作者2023年公开长文的这一节，回顾了自己长期关注神经网络、与许多人交流的经历，并特别感谢两位帮助完成文章的人。这告诉读者写作与交流的背景，不是把每个被提名者列为合著者，也没有逐条说明谁独立验证了哪个技术论断。

### 把关系种类保留在引用路径里

<Term def="从一个论断出发，按指定关系逐步找到所用材料的有向路线。">
  引用路径
</Term>
不只是名字列表。它要保存“谁指向谁”和“为什么指向”：引用一份论文、感谢一个人、推荐一个课程，并不能互换。实验一把这些关系画成不同的边，避免只数链接数量。

本例的<Term def="在某个论断的追查中，被转述或引用的那份最初材料；其原始性相对具体问题而言。">原始来源</Term>是 P 或 Q，不表示它们对所有问题都有最终权威。固定图有五个节点：论断 C 引用转述 R，R 引用原文 P；C 另有一条致谢边到 A，A 提供外链到材料 Q。这里 C、R、A、P、Q 全是教学代号，不对应真实被致谢的人。

### 一个缺失快照怎样改变可达集合

设允许最多追两跳。初始集合只有 C；第一跳沿引用边得到 R，第二跳在 P 的快照已保存时得到 P。所以结果是 C、R、P。若 P 未保存，我们仍知道 R 声称引用了它，但不能冒充已经读过 P；本例的“可检查材料集合”只剩 C、R。

致谢与外链边仍显示在图里，却不参与这次引用计算。故障把它们一起接通，就能绕到 Q。Q 的材料即使存在，也不是通过给定引用关系支持 C。**可达性是在检查材料链条，不是在自动证明论断为真。**不同任务也可以合法追踪推荐关系，但应更换明确的关系合同，不能暗改边的含义。

> 猜一猜：将“原文 P 快照”改成“未保存”，再打开故障，计入的原始材料会是谁？先用下一步检查两跳，再完整重置；P 应恢复、故障应关闭、光标应回入口。

### 问题不同，需要的材料也不同

<Term def="一份材料实际能够回答的具体问题、时间和对象范围，而非它看起来有多权威。">
  论断范围
</Term>
决定我们该把链接放在哪一格。作者原文可以核对“作者2023年写了什么”；出版社书目可以核对某版的出版信息。二者都不能单独回答“这段材料可以复制吗”或“当前产品规格是什么”。后两问需要适用的权利条款、当前且针对该产品的技术记录。

实验二给出一个**人为简化的范围合同**：四种来源分别只支持一行，组成对角线。现实来源可以覆盖多行，仍需逐条阅读，不能机械照搬这张矩阵。选择“文章＋书目”时，历史观点与出版信息各有一格；切到“许可＋当前”，并不会凭空出现新证据。

### 二值矩阵不等于可信度评分

本例中，行表示四类问题，列表示四种来源。设 $M_{ij}=1$ 表示第 $j$ 份记录的范围符合第 $i$ 个问题，$S$ 为选中列集合；某行被覆盖的条件是存在 $j\in S$ 使 $M_{ij}=1$。这里的“1”只表示范围符合，**不是正确率、信任值或法律裁决**。

选择前两列，待核对后两行时，实际覆盖为0。故障则把“已选列”误当成每一行都可填，错误声称覆盖2行，并引入4个不成立的对应格。对角圆点、未选虚框和红色斜线分别呈现真合同、缺材料与错误推广；不能把红格平均成一个貌似精确的风险分。

> 猜一猜：“文章＋书目”不变，只将待核对论断换成“许可＋当前”，哪些行会空下来？打开“有链接就算支持”，解释4个红色斜线格。全选四种来源后，真实覆盖才恢复为2行；完整重置应回到前两列、前两行。

## 链接以外：副本身份与允许用途

补充资源的链接只是入口，保存下来的文件还需要单独核对。实验三把请求固定为“复制 v1”：即使 v2 下载完整、并且另有复制授权，也不能替代指定的 v1；即使版次正确，末尾多出的一个空格仍会改变副本。下面将收到的字节、请求的版次与允许的动作拆成三个独立条件，不把公开可读当作复用许可。

### 字节相同，版本相同，许可相同，是三件事

<Term def="对确定字节计算出的摘要；用于核对副本是否改变，不自带作者、内容真伪或许可信息。">
  字节指纹
</Term>
可以检查下载结果与一份可信记录是否一致。本页用
SHA-256，但只检查四个固定ASCII副本：以 `abc`、`abd`
为基底，以及分别追加一个空格的两个副本。末尾空格也是一个字节；即使肉眼没注意到，摘要仍会变化。指纹相同的判断依赖记录本身可信；这里不把摘要当作来源身份认证。

<Term def="把手中副本连接到明确版次、期望字节与变更关系的记录，而不是只保存一个网址。">
  版本溯源
</Term>
还要回答“这是否是我请求的那一版”。实验三固定请求 v1；候选 v2
是正规的修订版，即使与它自己的记录完全一致，也不是 v1。图上的谱系把 v1 的 `abc`
连到 v2 的 `abd`，逐字节条再核对候选是否发生传输变动。

许可单独作为动作集合处理。本例默认记录只允许 `read`；有一份**合成的明确授权**时才加入 `copy`。请求的动作是 `copy`，所以读得到不等于复制得到允许。该两动作集合不刻画真实世界的合理使用、法定例外或完整合同；没有额外记录，只能说此证据不足，不能据此断言法律绝对禁止。

### 在同一记录上执行三个独立检查

令 $B$ 为收到字节与候选记录摘要相符，$V$ 为候选版次等于请求的 v1，$A$ 为请求动作在该合成许可集合中。本例可复用标记为

$$
E=B\land V\land A.
$$

这就是说：三项都成立才标记本次请求满足这个小合同；一个“网址还在”的布尔值不能代替三项记录。

候选 v2、字节不变、另有复制授权时，三项分别为真、假、真，结果仍是假。故障以入口存在直接输出真；图中红线显示旁路，原来的字节、版次与授权并没有被它修复。把 v1 加上末尾空格，则首先失败的是字节检查；完整重置恢复 v1、原样、仅阅读和入口帧，不会保留上次的授权。

> 猜一猜：改成 v2 并添加复制授权，指纹完全一致还差哪一项？再改回 v1、追加空格，看字节条哪里多了32。关闭故障与完整重置后，三个条件和光标都应恢复默认。

## 用标准库重算，不访问网络

以下四块按顺序拼接即可执行。它们只处理有限合成图、集合和字节，不查询当前网页，不计算真实书籍指纹，不爬课程，也不训练模型。每块均有预期断言。

### 第一步：按边类型追查材料

有向边携带关系标签。目标未保存时不加入可检查集合；循环次数就是最多追几跳，不会无限遍历。

```python
edges = [("C", "R", "cite"), ("R", "P", "cite"),
         ("C", "A", "thanks"), ("A", "Q", "link")]

def reachable(depth=2, saved=True, fault=False):
    reached = {"C": 0}
    for hop in range(1, depth + 1):
        for source, target, kind in edges:
            if (reached.get(source) == hop - 1
                    and (kind == "cite" or fault)
                    and (target != "P" or saved)):
                reached[target] = hop
    return reached

assert set(reachable()) == {"C", "R", "P"}
assert set(reachable(saved=False)) == {"C", "R"}
assert set(reachable(saved=False, fault=True)) == {"C", "R", "A", "Q"}
assert set(reachable(depth=1)) == {"C", "R"}
```

### 第二步：把“范围符合”写成显式对应

只计算待核对的两行。`invalid`数的是错误单元，不是风险；一个来源可能被错误地分配给两个不相干问题。

```python
def incidence(source_count=2, group=0, fault=False):
    rows = [0, 1] if group == 0 else [2, 3]
    selected = range(source_count)
    matrix = [[int(row == col) for col in range(4)]
              for row in range(4)]
    actual = sum(any(matrix[r][c] for c in selected) for r in rows)
    reported = len(rows) if fault else actual
    invalid = sum(not matrix[r][c] for r in rows for c in selected)
    return actual, reported, invalid if fault else 0

assert incidence() == (2, 2, 0)
assert incidence(group=1) == (0, 0, 0)
assert incidence(group=1, fault=True) == (0, 2, 4)
assert incidence(source_count=4, group=1) == (2, 2, 0)
```

### 第三步：摘要不携带版次与授权

`expected`是每个候选自己的记录；`version_match`是另一个检查。即便 v2 的字节正确，也不能代替请求的 v1。

```python
from hashlib import sha256

def provenance(edition=1, extra_byte=False, grant=False, fault=False):
    expected = b"abc" if edition == 1 else b"abd"
    received = expected + (b" " if extra_byte else b"")
    integrity = sha256(expected).digest() == sha256(received).digest()
    version_match = edition == 1
    allowed = {"read", "copy"} if grant else {"read"}
    permitted = {"copy"} <= allowed
    actual = integrity and version_match and permitted
    return integrity, version_match, permitted, actual, fault or actual

assert sha256(b"abc").hexdigest().startswith("ba7816bf8f01")
assert provenance() == (True, True, False, False, False)
assert provenance(2, grant=True) == (True, False, True, False, False)
assert provenance(2, grant=True, fault=True)[-2:] == (False, True)
assert provenance(extra_byte=True, grant=True)[:2] == (False, True)
assert provenance(grant=True)[-2:] == (True, True)
```

### 第四步：穷举有限输入并检查恢复

恢复的目标是完整默认状态，而不是“把最后一条报错藏起来”。下面把各参数的枚举走一遍；真实界面的播放时钟仍需浏览器单独验证，Python不声称覆盖计时器。

```python
from itertools import product

for depth, saved in product([1, 2], [False, True]):
    assert set(reachable(depth, saved)) <= set(reachable(depth, saved, True))
for count, group in product([1, 2, 4], [0, 1]):
    actual, reported, invalid = incidence(count, group, True)
    assert 0 <= actual <= reported <= 2 and invalid >= 0
for edition, dirty, grant, fault in product([1, 2], [0, 1], [0, 1], [0, 1]):
    b, v, a, actual, reported = provenance(edition, dirty, grant, fault)
    assert actual == (b and v and a)
    assert reported == (bool(fault) or actual)
assert reachable() == {"C": 0, "R": 1, "P": 2}
assert incidence() == (2, 2, 0)
assert provenance() == (True, True, False, False, False)
print("PASS: citation paths, incidence, byte/version/rights fixtures")
```

## 容易混淆的三种“有”

前面三个实验分别暴露了不同的替代错误：致谢名字被当作引用核验、选中链接被当作适用材料、可访问入口被当作副本与授权记录。排查时要指出究竟是哪一种关系被偷换，而不是只说“来源不可靠”；下面按现象、原因和修法逐一对应到引用图、范围矩阵与副本检查。

### 有名字，不等于有技术背书

**现象**：因为专家出现在致谢名单，就把某句话写成“专家已验证”。**原因**：把交流、协助与逐条复核混成一种关系。**修法**：保留边类型；找不到对应的核验记录，就只陈述作者实际写下的致谢。

### 有链接，不等于问题已有答案

**现象**：文章与书目两条链接被拿去证明转载许可和当前规格。**原因**：忽略了论断范围。**修法**：在实验二切换待核对行，先留下空格，再找明确适用的条款或带版本的技术资料。

### 有副本，不等于有复用依据

**现象**：地址没变，于是旧指纹、旧版次、旧许可都不再检查。**原因**：地址是入口，不是完整内容身份或授权记录。**修法**：分别核对字节记录、请求版次与动作；实验三用额外空格显示首个字节分岔，不能靠入口旁路恢复。

## 小结与练习

用三个实验的默认状态作起点：引用图能追到已保存的 P，文章与书目覆盖前两类问题，v1 的字节和版次相符却没有额外复制授权。下面的练习要求分别改变这些条件，解释故障为什么只制造误报，以及完整重置究竟恢复哪些记录。

- 致谢说明交流与协助，不自动建立核验关系。
- 推荐入口要读到具体内容后才分配给具体问题。
- 指纹、版次和许可分别记录，不能互相替代。

## 名词解释

下列五个词分别标记材料的连接方式、被追查的起点材料、适用问题和副本身份记录。复述实验结果时，要区分“能追到”“能回答”与“副本对应哪一版”，不要把其中任意一项当作真实性或许可的总保证。

<Glossary>
  <GlossaryItem term="引用路径">
    从论断沿明确关系追到所用材料的路线；致谢与外链不能悄悄当成引用。
  </GlossaryItem>
  <GlossaryItem term="原始来源">
    相对于一个问题，被转述的最初材料；原始不意味着对所有问题都权威。
  </GlossaryItem>
  <GlossaryItem term="论断范围">
    材料能回答哪些具体问题、对象和时间；范围符合不等于自动判真。
  </GlossaryItem>
  <GlossaryItem term="字节指纹">
    确定字节的摘要，用于副本一致性核对，不说明许可或内容正确性。
  </GlossaryItem>
  <GlossaryItem term="版本溯源">
    将副本连到明确版次、期望字节及变更关系的记录，不只是一个网址。
