## 一个距离数字为什么值得追问

一段回答可以同时具备地名、单位、推算口吻，却没有执行过所需的算法。反过来，计算出了一个数字，也不能跳过“它算的是哪一种距离”。两座城市之间有穿过地球内部的直线、球面最短弧、椭球测地线和实际航线；它们不能仅靠同一个“距离”词互相替代。

本页先固定一个足够小的任务：**给定两点经纬度及球半径，计算球面最短弧长**。随后故意损坏角度、中间精度和回答单位，观察错误在哪个数值结构上发生。这里不调用在线模型或 Wolfram|Alpha；能复算的是本站的有限算例，不是2023年截图的重放，也不是当前产品能力测试。

## A Basic Example / 一个基本示例

这个正式目录坐标来自 Stephen Wolfram 2023年1月9日文章的同名节。实际可读文字用 Chicago 与 Tokyo 的距离讨论一件事：语言上很有说服力的结果不保证计算正确；作者认为，结构化知识和明确的计算算法可以补充语言生成。这是一个历史示例的论证方向，不是“所有神经网络永远算不了距离”的定理。

### 原文支持什么，不支持什么

本轮完整阅读了继承存档 `wa-article.txt` 第61–73行：该节讨论把问题交给 Wolfram|Alpha、将其结果补充给 ChatGPT，以及将自然语言转成精确计算语言的思路。作者也提醒当时的输出带有随机性，复试未必相同。本页不据此保证自动纠错成功，更不推定今天的 ChatGPT 接口、内部架构或工具覆盖范围。

原始问答、计算式和部分输出在图片中，抽取文本没有这些数值。**本轮没有读取那些图片，不补写它们的距离或函数表达式。** 以下输入和图形是本站独立重建：Chicago 取 `(41.8781°, −87.6298°)`，Tokyo 取 `(35.6762°, 139.6503°)`，`R=6371 km`。这些坐标仅是自行选定的城市附近输入，不宣称是原图、机场或权威市中心坐标。

### 从角度到距离的最小模型

<Term def="球面与过球心的平面相交得到的圆；非对跖两点之间的较短大圆弧给出球面最短距离。">
  大圆
</Term>
让这个模型具有可检算的几何结构。若两点对应单位向量 $u,v$，夹角为

$$
c=\operatorname{atan2}(\|u\times v\|,u\cdot v),\qquad d=Rc.
$$

<Term def="用弧长除以半径定义的无量纲角度；180度等于π弧度，三角函数在此按弧度接收输入。">
  弧度
</Term>
不是输出末尾可随意替换的标签。纬度 $\varphi$、经度 $\lambda$
在进入三角函数前要乘 $\pi/180$：

$$
u(\varphi,\lambda)=(\cos\varphi\cos\lambda,\cos\varphi\sin\lambda,\sin\varphi).
$$

本页坐标得到 $c\approx1.591807546965$，球弧约 `10141.405882 km`；直弦 $2R\sin(c/2)$ 约 `9104.110735 km`。不是两条算法算出了互相矛盾的答案，而是它们回答了不同几何问题。同点时两者为零；对跖点的最短弧长为 $\pi R$，但可走的半个大圆不唯一。球面模型忽略地形和椭球扁率，也不描述航空交通约束。

## 三个数值结构实验

三个视图分别检查空间几何、非线性中间量和答案允许范围。它们没有共享的“可信度分数”：图一改变中心角与球弧，图二改变半弦曲线上的位置及微小余量，图三改变距离带与舍入单元的包含关系。每个实验都支持单步、拖动、播放和完整重置；改参数或故障开关会回到首帧并暂停。

先逐步显示“夹角与弦”和“最短球弧”，比较虚线弦与彩色弧。90°的参考值是 $\pi R/2$，不是 $\sqrt2R$；前者是球弧，后者是直弦。换半径时两种长度同比例变化，夹角不变。图画的是**所选大圆平面的截面**，不是世界地图，也不是把经纬度投在平面上后连直线。

开启“度数直接传给三角函数”，端点向量先错，夹角和弧长随后一起错；灰色虚弧仍保存正确角度的对照。完整重置恢复本页城市输入、6371 km、无故障及暂停首帧。再选同一点：错误转换对两端相同地发生，距离仍为0；这个无影响边界并不能替错误规则辩护。

### 实验二：看见对跖附近丢失的余量

<Term def="a=sin²(Δφ/2)+cosφ₁cosφ₂sin²(Δλ/2)，在球面上等于归一化半弦长的平方。">
  haversine量
</Term>
把两点关系压成 $a\in[0,1]$，然后反算角度：

$$
a=\sin^2\frac{\Delta\varphi}{2}+\cos\varphi_1\cos\varphi_2\sin^2\frac{\Delta\lambda}{2},\quad
c=2\operatorname{atan2}(\sqrt a,\sqrt{1-a}).
$$

这里固定赤道两点，让经差 $\theta\in[0,\pi]$，所以 $a=\sin^2(\theta/2)$。先预测：179.999°的 $a$ 只保留6位小数，会把两点变得更近还是恰好对跖？再比较90°与179.999999°，哪一个主要问题来自人为提前舍入，哪一个即使不开故障也可能在 binary64 中丢余量？

<div data-visual-kind="haversine-complement-conditioning">
  <TcgWa02BasicExampleComputeTraceLab />
</div>

下方对数刻度把 $1-a$ 放大，0单独列在右端，不能在对数轴上假装有有限位置。空心标记用此赤道特例的 $\cos^2(\theta/2)$ 独立算余量；实心三角是实际从 $1-a$ 相减得到的量。计算阶段逐步揭示 $a$ 和反算误差。默认179.999°时，提前舍入令 $a\to1$，算成整半圈，距离约多 `111.194927 m`。

<Term def="描述输入微小误差如何被输出放大的敏感程度；需说明所用误差尺度，不等于结果可信度评分。">条件数</Term>提醒我们不能只数输出小数位。本例在 $0<a<1$ 时有 $dc/da=1/\sqrt{a(1-a)}$，越靠端点，固定绝对 $a$ 误差可能放大得越明显。它不表示所有小距离都算不好：haversine 对小距离的相对表现通常优于从接近1的余弦相减，本页也保留极近输入供比较。

179.999999°在本算例的 binary64 中可能已经得到 $a=1$；关闭人为故障也不能补回这次舍入前的余量。界面用赤道向量对照 $\operatorname{atan2}(|\sin\theta|,\cos\theta)$ 检查距离差；这是另一条计算路径，不是任意输入上无限精度的真值机。将 $a$ 夹到 `[0,1]` 只防止开方越域，不能恢复信息。在90°附近，故障前后的距离在浮点容差内一致；两点精确对跖时半圈长度也正确。

### 实验三：区间能否支持一个确定的舍入值

现在不再改变坐标，改成一个明确的教学假设：`R∈[6370,6372] km`。这不是测量置信区间，也不意味着地球处处有这样一个半径。因为 $c\ge0$ 且固定，$d=cR$ 单调，距离必在 $[cR_{min},cR_{max}]$ 中。若改用英里，本页按精确因子 `1 mi = 1.609344 km` 除两个端点；不是把 km 三个字母换成 mi。

<Term def="在指定舍入规则下被映射到同一个显示值的输入区间；本页正数half-up、间隔q时为[n−q/2,n+q/2)。">
  舍入单元
</Term>
给“确定到某一位”一个可检查条件。令 $q=10^{-p}$，候选值为中点按正数 half-up
舍入后的 $n$。只有整个允许区间落入 $[n-q/2,n+q/2)$，才可说所有允许输入都舍入成
$n$。下端包含、上端不包含来自本页选定的半入规则，不能默认成 Python 内置 `round`
的偶数舍入。

先预测：把半径范围从 `±1` 收窄到 `±0.01 km`，是否可能让整条距离带落入同一舍入单元？把回答改为 mi 后，省略除法会在图中向哪边越界？

<div data-visual-kind="distance-interval-rounding-cells">
  <TcgWa02BasicExampleEvidenceGateLab />
</div>

默认 km、0位小数得到允许区间约 `[10139.814074,10142.997689] km`。中点虽然能显示为10141，但整带不在 `[10140.5,10141.5)`，不能把10141称作所有允许输入共同的舍入结果。向外包络则为 `[10139,10143] km`：下端向下、上端向上，因此不会把允许距离排除。**包络本身不等于所有可能舍入标签的集合**，它回答的是“怎样用有限小数仍覆盖原区间”。

把半径改为 `±0.01`，区间约 `[10141.389964,10141.421800] km`，这时整带确实舍入为10141。改 mi、范围恢复 `±1`，允许区间约 `[6300.588360,6302.566567] mi`，向外包络为 `[6300,6303] mi`。最后开启故障：候选仍拿公里中点10141，却标为mi；箭头表示它跑到细尺范围之外，而不是细尺裁切漏画。km时因比例为1，这个故障无影响。恢复必须撤销故障，而不是把细尺挪到错误结果附近。

## 用标准库复算同一套假设

下面代码按顺序合并为一个 Python 文件即可有限执行。它不联网、不请求模型、不执行 Wolfram Language；数组中的坐标就是本站自建输入。第一段通过单位向量的点积和叉积构造中心角，避免把球面路径问题变成平面经纬度欧氏距离。

```python
from math import sin, cos, atan2, sqrt, radians, pi, floor, ceil, isclose

CITY = (41.8781, -87.6298, 35.6762, 139.6503)
def vector(lat, lon, degrees=True):
    p, l = (radians(lat), radians(lon)) if degrees else (lat, lon)
    return (cos(p)*cos(l), cos(p)*sin(l), sin(p))

def central(coords, degrees=True):
    p, l, q, m = coords
    u, v = vector(p, l, degrees), vector(q, m, degrees)
    dot = sum(x*y for x, y in zip(u, v))
    w = (u[1]*v[2]-u[2]*v[1], u[2]*v[0]-u[0]*v[2],
         u[0]*v[1]-u[1]*v[0])
    return atan2(sqrt(sum(x*x for x in w)), dot)

c = central(CITY)
d = 6371*c
assert isclose(d, 10141.4058817116, abs_tol=1e-8)
assert isclose(central((0, 0, 0, 90)), pi/2, abs_tol=1e-15)
```

下面比较弧与弦，并检验错误的度数规则；两个相同的错向量仍然夹角为零，说明“某个边界没失败”远不足以验证规则。预期第一行输出城市球面距离，而不是截图中的原始答案。

```python
chord = 2*6371*sin(c/2)
assert isclose(chord, 9104.1107346584, abs_tol=1e-8)
assert chord < d
assert not isclose(central(CITY, False), c, abs_tol=0.01)
assert central((41.8781, -87.6298, 41.8781, -87.6298), False) == 0
assert isclose(7000*c/d, 7000/6371, abs_tol=1e-15)
print(f"sphere: {d:.6f} km; chord {chord:.6f} km")
```

第三段专门保留实际浮点中间量。故障只提前舍入 $a$，没有同时改坐标或半径；`max/min` 是定义域保护，不是修复数值精度。对照直接使用已知赤道角，因此它的来源与先算 $a$ 再反算不同。

```python
def haversine(theta_deg, fault=False):
    theta = radians(theta_deg)
    raw = sin(theta/2)**2
    a = floor(raw*1e6+0.5)/1e6 if fault else raw
    a = min(1.0, max(0.0, a))
    recovered = 2*atan2(sqrt(a), sqrt(1-a))
    reference = atan2(abs(sin(theta)), cos(theta))
    return a, 6371*recovered, 6371000*abs(recovered-reference)

assert haversine(179.999, True)[0] == 1
assert isclose(haversine(179.999, True)[2], 111.1949266457,
               abs_tol=1e-6)
assert haversine(179.999, False)[2] < 0.001
assert haversine(90, True)[2] < 1e-6
assert haversine(180, True)[2] == 0
assert haversine(0.000001, True)[1] == 0
print(f"haversine: early-round error {haversine(179.999, True)[2]:.6f} m")
```

第四段先传播区间，再检查包含关系。`floor/ceil` 作用于端点以取得向外包络；中点舍入只用于提出候选，不能取代区间。故障省略单位换算，而参考端点始终正确，便于独立比较。

```python
def answer(spread=1, unit="km", places=0, fault=False):
    km_low, km_high = (6371-spread)*c, (6371+spread)*c
    factor = 1.609344 if unit == "mi" else 1
    low, high = km_low/factor, km_high/factor
    q = 10**(-places)
    middle = (km_low+km_high)/2 if fault else (low+high)/2
    n = floor(middle/q+0.5)*q
    single = low >= n-q/2 and high < n+q/2
    return (low, high, floor(low/q)*q, ceil(high/q)*q, n, single)

lo, hi, out_lo, out_hi, n, single = answer()
assert isclose(lo, 10139.8140741646, abs_tol=1e-8)
assert isclose(hi, 10142.9976892586, abs_tol=1e-8)
assert (out_lo, out_hi, n, single) == (10139, 10143, 10141, False)
assert answer(0.01)[-1] is True
assert answer(1, "mi")[2:4] == (6300, 6303)
assert answer(1, "mi", fault=True)[4] == 10141
assert answer(1, "mi", fault=True)[-1] is False
assert answer(1, "km", fault=True) == answer()
print("answer: [10139, 10143] km; [6300, 6303] mi; narrow band shares a cell")
```

预期输出恰好三行：`sphere: 10141.405882 km; chord 9104.110735 km`、`haversine: early-round error 111.194927 m`、`answer: [10139, 10143] km; [6300, 6303] mi; narrow band shares a cell`。代码验证本页定义的球面模型；不能用这些 assert 证明城市坐标权威、椭球误差已覆盖、航程正确或任何在线模型已经执行过这些步骤。

## 常见误区

这三个误区分别把角度约定、中间数值信息和回答精度弄混。排查时先找到首次改变的量；输出越长、数字位数越多，都不能绕过输入约定与误差传播。

### 计算器有返回值就表示角度正确

<Callout type="trap">
  **现象 →** 故障模式仍给出一个有限距离。 **原因 →**
  度数被当成弧度，函数合法执行却算了另一些方向。 **修法 →**
  在构造向量前统一乘π/180，用赤道90°和同点两个边界分别检查。
</Callout>

### clamp和多印小数能救回对跖精度

<Callout type="trap">
  **现象 →** a变成1后，显示更多位仍得到半圈。 **原因 →** 余量在中间步骤已丢失。
  **修法 →** 避免提前舍入，改用适合输入的独立计算路径；夹紧只保护定义域。
</Callout>

### 中点四舍五入就是区间的唯一答案

<Callout type="trap">
  **现象 →** 明明距离带跨越多个单元，却断言一个数确定到个位。 **原因 →**
  把方便展示的中点当成所有允许输入的共同值。 **修法 →**
  检查整带包含关系，或用向外包络并说明假设；换单位要同时变两个端点。
</Callout>

## 小结与练习

本章的目标不是记住两座城市间一个数字，而是能把一个距离回答拆成几何对象、数值计算和允许表述三层。下面三个任务分别检查路径选择、精度损失和区间覆盖是否真正闭环。

- 球弧是Rc，穿球直弦是另一种距离。
- 中间量丢失的信息不能靠末尾小数补回。
- 区间与单位传播决定能否给出确定舍入值。
