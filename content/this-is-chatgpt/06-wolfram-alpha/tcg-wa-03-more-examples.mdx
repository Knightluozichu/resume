## 直觉：答案写得顺，不等于事情算得对

这章要解决的不是怎样让回答更像文章，而是怎样找到能直接检查的结果。一个式子写得简短、一份名单排列整齐、一段数字附了出处，都可能掩盖不同错误。

如果只看最后一句话，我们很难知道哪一步出了问题。下面把三类问题分别拆开：先保留不能代入的位置，再跟踪每项移动，最后看清究竟拿什么除以什么。

## 实验一：约分保留一个不能填上的洞

把长式子变短之前，先确认它在哪些位置有意义。实验用本站自造的二次分式展示：分子分母出现同一个因子时，可以在允许的位置约去它，却不能顺带扩大原函数能接收的输入范围。

### 从分解到代值

<Term def="两个多项式相除形成的表达式，分母不能为零">有理式</Term>
不只是印在纸上的符号，它还规定哪些输入允许参与运算。这个允许输入的集合叫
<Term def="使原表达式有意义的全部输入组成的集合">定义域</Term>
。实验一的空心圆正是被排除的输入，而不是没有画好的线。

本节符号如下：

- x：要代入的数。
- a：分母中的被排除根，可取1、2、3。
- d：非零分母倍数，可取1、2。
- F：原分式对应的函数。

$$
F(x)=\frac{x^2-a^2}{d(x-a)}
=\frac{(x-a)(x+a)}{d(x-a)}
=\frac{x+a}{d},\qquad x\ne a.
$$

这个式子在说：先把平方差拆成两个因子，只在x不等于a时消去公共因子，剩下的短式仍必须带着原来的限制。

a=2、d=1时，x=3的原式是5/1=5，短式也是5。可是在x=2，原式是0/0，不能取值；短式单独计算会得到4。后者是另一个扩大了输入范围的函数在该点的值，不能反过来填补原式。代一个合法值相等只是一例，不能证明定义域也相同。

### 先预测，再推进图

猜一猜：把a从2改到3，空心洞会移到哪里？若同时把d改为2，洞的纵坐标又是多少？先看因子条带，再推进到“代值检查”；选择x=a+1与x=a比较，最后打开“丢弃x≠a”故障。

<TcgWa03MoreExamplesContextContractLab />

图中斜线划掉的是公共**因子**，不是隔着加减号消掉单项。a=3、d=2时，洞在(3,3)，x=4的实际值为7/2；故障只丢了输入限制，所以合法位置未必暴露它，必须主动选洞。完全重置恢复a=2、d=1、x=a、故障关闭以及暂停的第一帧。

## 实验二：比较规则决定名单怎么移动

这里不判断名字是否可信，而是把每个项目的身份和用于排名的数分开。四条线穿过不同层的位置，能指出哪次比较让某项提前，也能确认相同数值的两个项目有没有被无故交换。

### 数字相等时仍有先后身份

<Term def="排序时真正参与比较的数值字段，而不是项目名称或数字的文字拼写">
  数值键
</Term>
在本例中是10、2、2、30；A、B、C、D只是原有身份。将10和2转为文字后，逐字符比较会先比较“1”和“2”，于是“10”排在“2”前面。这不是数值大小的结论。

<Term def="键相等的项目在输出中保持输入时的相对顺序">稳定排序</Term>
还要求B:2在C:2前面。图先分别排AB和CD，再比较两个子列的开头，每次取出该方向应先出的一个。两端同键时取左，因为左子列原先就在右子列前；这条规则在降序时也不变。

### 预测第一次分叉

猜一猜：默认输入升序归并时，第一个输出会是A还是B？先走到“二元归并”，再逐个输出。对照故障后，第一层局部排序已经从BA变成AB，最后的错误不是到末尾才突然发生。

<TcgWa03MoreExamplesComputeTraceLab />

数值升序为B:2、C:2、A:10、D:30；词典序故障为A:10、B:2、C:2、D:30。同键的B、C在两种结果中仍稳定，但稳定不意味着比较规则正确。改成A:3、B:12、C:3、D:1时，数值升序为DACB，文字升序为DBAC；可以用这个第二反例排除“只修补10和2就够了”。

## 实验三：同一份数据也能除出不同的答案

有了真实输入仍不能跳过计算口径。本例特意冻结自造年份与地区快照，让读者看清每个人属于哪个分母；数据来源是否真实与这个算术问题是两道独立检查，算术正确不替虚构资料背书。

### 人数占比不是地区比例的平均

<Term def="合并分组比例时，用各组原来的总体数量决定其贡献，而非让每组各占一票">
  加权分母
</Term>
在图中是一百个格子：每格十人。2022年北部100人中20人发生某事件，南部900人中90人发生；粗分区线显示北部只占总体十分之一，不该在合计时突然占一半权重。

本节符号如下：

- E：纳入地区的事件人数合计。
- N：同年同地区集合的总体人数合计。
- r：事件人数占总体人数的比例。

$$
r=\frac{E}{N}=\frac{20+90}{100+900}=\frac{110}{1000}=11\%.
$$

这个式子在说：先分别相加事件人数和总体人数，再相除，不能把人口差九倍的两个地区当作同样大。

北部20%、南部10%的等权平均是15%，回答的是“两个地区比例的平均”，而不是“全部人中事件所占比例”。两种问题都可以定义，但不能改了问题还沿用原来的结果名称。2023快照改为北60/200、南80/800，合计140/1000=14%，等权地区平均则是20%。

### 换年与筛选要同时移动分子分母

猜一猜：只纳入北部时，故障是否还会显错？切换年份观察填色数与分区线，再推进到比率轴，比较空心圆的真实结果与菱形报告值。然后只选北部，解释故障为何暂时被掩盖。

<TcgWa03MoreExamplesEvidenceGateLab />

单地区时没有组间权重差异，两种算式碰巧相同，不能据此宣布故障不存在。恢复两地区后，报告与真实结果再次分开。这里的事件只是有限计数标签，图没有测语言模型质量，也未调用外部API；如果上游交来的是别年数据、错单位或夹带指令的材料，应先隔离并核实，不能让外部文字改写计算规则。

## Python对照：三段顺序拼成一个可运行文件

下面只用Python标准库，对应三个实验的精确计算。把三段依次保存到同一个文件运行；第一段引入的Fraction会被第三段复用。代码没有联网、模型训练或真实Wolfram调用，所有断言都在已声明的有限输入上成立。

### 有理式用精确分数保留未定义状态

`None`专门表示原式不能取值，不能用零替代它。循环同时检查a、d与三种探针位置，合法点的恒等来自因式分解；洞上的断言则检查输入范围没有被短式偷换。

```python
from fractions import Fraction as F


def rational(a, d, x, drop_domain=False):
    if x == a and not drop_domain:
        return None
    return F(x + a, d)


for a in (1, 2, 3):
    for d in (1, 2):
        for x in (a, a + 1, 0):
            exact = None if x == a else F(x*x-a*a, d*(x-a))
            assert rational(a, d, x) == exact
        assert rational(a, d, a) is None
        assert rational(a, d, a, True) == F(2*a, d)
assert rational(3, 2, 4) == F(7, 2)
print("rational:", rational(2, 1, 2), rational(2, 1, 2, True))
```

预期第一行输出`rational: None 4`。若把a改为3且d改为2，洞仍未定义，故障报告3；这不是计算精度造成的误差。

### 两路归并只比较队首，遇到相等先取左

`key`只读取数值或故障字符串，元组第一项的身份不参与比较。`<=`决定相等时取左；输出后只移动被取子列的游标，所以可以逐步对照图中的曲线。

```python
def merge(left, right, lexical=False):
    out, i, j = [], 0, 0
    key = lambda row: str(row[1]) if lexical else row[1]
    while i < len(left) and j < len(right):
        if key(left[i]) <= key(right[j]):
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]


def sort4(values, lexical=False):
    rows = list(zip("ABCD", values))
    left = merge(rows[:1], rows[1:2], lexical)
    right = merge(rows[2:3], rows[3:], lexical)
    return merge(left, right, lexical)


ids = lambda rows: "".join(row[0] for row in rows)
assert ids(sort4([10, 2, 2, 30])) == "BCAD"
assert ids(sort4([10, 2, 2, 30], True)) == "ABCD"
assert ids(sort4([3, 12, 3, 1])) == "DACB"
assert ids(sort4([3, 12, 3, 1], True)) == "DBAC"
print("merge:", ids(sort4([10, 2, 2, 30])))
```

预期第二行输出`merge: BCAD`。这里实现升序；练习要求独立加上降序，不能只把最终列表倒过来，否则同键的B、C会反转，失去稳定性。

### 固定快照先选行，再合计人数

每行依次是地区、事件人数、总体人数。函数先确定筛选集合，再以精确分数分别计算人数占比和地区等权平均；第二个结果用于反例，不冒充第一个问题的答案。

```python
snapshots = {
    2022: [("北", 20, 100), ("南", 90, 900)],
    2023: [("北", 60, 200), ("南", 80, 800)],
}


def aggregate(year, region=None):
    rows = [r for r in snapshots[year] if region in (None, r[0])]
    events = sum(e for _, e, n in rows)
    population = sum(n for _, e, n in rows)
    actual = F(events, population)
    equal_region = sum(F(e, n) for _, e, n in rows) / len(rows)
    return events, population, actual, equal_region


assert aggregate(2022) == (110, 1000, F(11, 100), F(3, 20))
assert aggregate(2023) == (140, 1000, F(7, 50), F(1, 5))
assert aggregate(2022, "北")[2:] == (F(1, 5), F(1, 5))
assert aggregate(2023, "南")[2:] == (F(1, 10), F(1, 10))
print("snapshot:", *aggregate(2022))
```

预期第三行输出`snapshot: 110 1000 11/100 3/20`。图上的11%与15%只是这两个分数的百分比显示，底层没有把展示舍入值再送回计算。

## 常见误区

三个故障分别改变了输入范围、比较类型和统计问题。检查时应找出最早被换掉的那一项，而不是给整份回答一个模糊的好坏标签。

<Callout type="trap" title="约分后处处相等">
**现象 →** 把洞补成4，声称两个函数完全相同。

**原因 →** 约掉公共因子时连同原来分母不能为零的限制一起丢了。

**修法 →** 同时记录短式和x≠a；用x=a检验，而不只测试合法点。

</Callout>

<Callout type="trap" title="稳定就代表排对了">
**现象 →** B、C顺序未变，便接受把10排在2前面的名单。

**原因 →** 稳定性只限制同键相对顺序，不能保证比较的是数字。

**修法 →** 先检查键的类型，再用第二组输入定位第一次比较分歧。

</Callout>

<Callout type="trap" title="有出处就不用核算口径">
**现象 →** 引用数据后直接把20%与10%平均，报告总体15%。

**原因 →** 来源核实与分母核算是两项工作；这里把人数问题换成地区问题。

**修法 →** 冻结年份和地区，分别相加人数；来源未核实的数据不得当作真实事实。

</Callout>

## 小结与练习

下面三题分别回收输入限制、排序轨迹和分母核算。请先写出预测，再改参数或代码，最后用断言检查；一张图通过不替另外两种问题提供保证。

- 约分缩短表达式，不会自动扩大定义域。
- 数值比较和同键稳定性必须分别检查。
- 合计人数占比要保留同年同范围的分母。

<Exercises>

**问题 1：代值反例与定义域**

a=3、d=2时，x=0、x=3、x=4的原式分别是多少？为什么删除限制的故障在两个合法点不显错？

<Answer>
  分别为3/2、未定义、7/2。短式在合法点与原式相等，故障只扩大了输入范围，所以需要x=3这个反例；那里错误报告3。函数是否相同既比较值，也比较允许的输入。
</Answer>

**问题 2：独立实现稳定降序**

给Python的merge和sort4加`descending`参数，默认输入的稳定降序应是什么？能否先升序再反转？词典序降序又会怎样？

<Answer>
  在merge的队首比较处按方向使用`>=`或`<=`，相等时仍取左；sort4的三次merge都传入同一方向。数值稳定降序为DABC，即30、10、2、2。先升序再反转得到DACB，会把B和C倒置。文字降序为DBCA，即“30”、“2”、“2”、“10”；可以在图中切方向与故障复核。
</Answer>

**问题 3：重新核算与故障掩盖**

2023年全部地区的真实占比、错误报告分别是多少？只取北部又分别是多少？如果把北部人数200误录为100而事件人数仍60，真实占比应怎样变化？

<Answer>
  全部地区为140/1000=14%，错误等权报告(30%+10%)/2=20%；只取北部两者均30%，错误被单组掩盖。若改成60/100和80/800，按这份错误输入合计为140/900=7/45，约15.5556%。算术可以完全正确但资料有误，因此要另查快照来源，不能凭工具结果反证原数据可信。
</Answer>

</Exercises>
