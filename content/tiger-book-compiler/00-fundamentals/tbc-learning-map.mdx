## 这本书讲什么

《现代编译器实现》（Modern Compiler Implementation in ML/C/Java，Andrew Appel 著）是编译器领域的经典工程教材，因封面有虎而得名「虎书」。它围绕一门小型函数式语言 **Tiger**，端到端实现一个完整可运行的编译器——从词法分析到寄存器分配，每一阶段都有可落地的算法与数据结构，强调**工程实现**而非纯理论推导。

虎书覆盖的核心能力：

- 词法分析：源码字符流 → Token 序列（ML-Lex 表驱动 DFA）
- 语法分析：Token → 抽象语法树（AST）（ML-Yacc LALR(1) 移进归约）
- 语义分析：AST → 带类型结果（双环境 + 类型规则）
- 活动记录：Frame 抽象管理调用栈（escape / static link）
- 翻译到 IR：带类型 AST → Tree IR（Ex / Nx / Cx 三形式）
- 规范化：Tree IR → 线性规范 IR（消除 ESEQ / 基本块 / trace）
- 指令选择：规范 IR → 机器指令（Maximal Munch 树覆盖）
- 寄存器分配：虚拟寄存器 TEMP → 物理寄存器（干涉图着色）

## 以 Tree IR 为枢纽的分阶段架构

虎书采用**分阶段架构**，每段职责分明，通过 Tree IR 解耦前后端：

| 阶段 | 模块 | 输入 → 输出 | 章节 |
|------|------|------------|------|
| 前端 | 词法 + 语法 + 语义类型 | Tiger 源码 → Token → AST → 带类型结果 | ch1, ch2, ch3 |
| IR 层 | 栈帧 + 翻译 + 规范化 | 带类型结果 → Tree IR → 规范化 IR | ch4, ch5, ch6 |
| 后端 | 指令选择 + 寄存器分配 | 规范化 IR → 机器指令 → 目标代码 | ch7, ch8 |

<Callout type="info">

**关键洞察**：Tree IR 是前后端之间的契约。前端只关心 Tiger 语言，后端只关心目标机器，两者通过 Tree IR 解耦独立演进。Frame 抽象进一步把「变量存哪」这一与机器强相关的决策平台无关化，贯穿前后端。这是 GCC、LLVM 等工业级编译器的标准架构思想。

</Callout>

## 虎书与龙书的差异

| 对比维度 | 虎书（现代编译器实现） | 龙书（编译原理） |
|---------|----------------------|----------------|
| 侧重 | 工程实现 | 理论奠基 |
| 组织方式 | 围绕 Tiger 语言端到端实现 | 按理论主题系统讲解 |
| 中间表示 | Tree IR（树形，可树覆盖） | 三地址码 |
| 栈帧 | Frame 抽象 + static link | 活动记录 + 访问链 |
| 指令选择 | Maximal Munch 树覆盖 | 基本块 + 窥孔 |
| 寄存器分配 | Chaitin-Briggs 图着色 | 图着色 |
| 适合场景 | 工程实践 / 动手实现 | 编译原理教学 / 理论根基 |

<Callout type="tip">

虎书的核心价值在于**做出来**：围绕 Tiger 语言把一个完整编译器从零搭起来，每个概念都对应具体实现——ML-Lex、ML-Yacc、Frame、Tree IR、Maximal Munch、图着色，环环相扣。与偏理论的龙书互补：龙书讲清楚「为什么」，虎书带读者「动手做」。

</Callout>

## 六个核心概念预览

| 概念 | 一句话解释 | 详细章节 |
|------|-----------|---------|
| Tree IR | 介于 AST 和机器指令的树形中间表示 | ch5 |
| Frame 抽象 | 平台无关的栈帧接口，管理 escape 与 static link | ch4 |
| escape 变量 | 被嵌套函数引用、需在栈帧分配的变量 | ch4 |
| Ex / Nx / Cx | 翻译 IR 的三种形式（表达式 / 语句 / 条件） | ch5 |
| Maximal Munch | 贪心选最大指令模板覆盖 IR 树的指令选择算法 | ch7 |
| 干涉图 | 同时活跃的 TEMP 之间连边，用于图着色 | ch8 |

<Glossary>

<GlossaryItem term="Tree IR">
虎书的核心中间表示，一组树形节点（CONST/TEMP/BINOP/MEM/CALL/MOVE/JUMP 等），是前端与后端的契约接口，规范化后适合用 Maximal Munch 做树覆盖指令选择。
</GlossaryItem>

<GlossaryItem term="Frame 抽象">
平台无关的栈帧接口（newFrame/formals/allocLocal），前端只关心 escape 判定与 static link，具体栈帧布局交给后端按目标机器实现。
</GlossaryItem>

<GlossaryItem term="escape 变量">
生命周期超出定义函数体的变量（被嵌套函数引用或取地址），必须在栈帧中分配以获得稳定地址，不能放进寄存器。
</GlossaryItem>

<GlossaryItem term="Maximal Munch">
指令选择算法，从 IR 树根自顶向下贪心选最大指令模板覆盖子树，实现简单高效，虽未必最优但工程上足够好。
</GlossaryItem>

<GlossaryItem term="干涉图">
寄存器分配的核心数据结构，节点是 TEMP（虚拟寄存器），同时活跃的 TEMP 之间连边（干涉），寄存器分配等价于该图的 K 着色。
</GlossaryItem>

</Glossary>

### 问题 1

虎书（现代编译器实现，Appel 著）的整体目标是什么？编译器的核心阶段有哪些？

<Answer>

整体目标是围绕 Tiger 语言端到端实现一个完整编译器，从源代码到目标代码全程可落地。核心阶段：①词法分析——源码→Token ②语法分析——Token→AST ③语义分析与类型检查——AST→带类型结果（exp, ty）④活动记录与栈帧——Frame 抽象管理调用栈 ⑤翻译到中间表示——AST→Tree IR ⑥规范化与基本块——IR→线性规范化 IR ⑦指令选择——IR→机器指令 ⑧寄存器分配——TEMP→机器寄存器。各阶段通过 Tree IR 解耦前后端。

</Answer>

### 问题 2

虎书 10 章的学习路径是什么？前端、IR 层、后端各覆盖哪些章节？

<Answer>

路径：ch0 学习地图 → ch1 词法分析 → ch2 语法分析 → ch3 语义分析与类型 → ch4 活动记录与栈帧 → ch5 翻译到中间表示 → ch6 规范化与基本块 → ch7 指令选择 → ch8 寄存器分配与图着色 → ch9 全书复习。前端覆盖 ch1-ch3（词法→语法→语义类型），IR 层覆盖 ch4-ch6（栈帧→翻译 IR→规范化，Tree IR 在此生成并规范化），后端覆盖 ch7-ch8（指令选择→寄存器分配），ch9 是端到端整合。

</Answer>

### 问题 3

虎书为什么以 Tree IR 作为前后端的解耦枢纽？它带来什么好处？

<Answer>

Tree IR 是介于带类型 AST 和目标机器指令之间的树形中间表示。前端把 Tiger 源码翻译成 Tree IR（关注源语言），后端从 Tree IR 生成目标代码（关注目标机器），两者通过 Tree IR 解耦。好处：①前端不必关心目标机器，后端不必关心源语言 ②支持多语言×多平台复用，M 个前端 + N 个后端避免 M×N 组合爆炸 ③IR 层优化（如规范化、基本块）只写一次即覆盖所有组合 ④Tree IR 设计成树形，便于后端用 Maximal Munch 树覆盖做指令选择。

</Answer>

### 问题 4

虎书与龙书在内容侧重上有何异同？

<Answer>

相同点：都覆盖编译器完整流程（词法→语法→语义→IR→代码生成），都以分阶段架构为核心，都通过中间表示解耦前后端。不同点：虎书更偏工程实现——围绕 Tiger 语言端到端实现一个可运行的编译器，强调 Frame 抽象、Tree IR、Maximal Munch、图着色寄存器分配等可落地的算法与数据结构，采用函数式风格。龙书更偏理论奠基——系统讲解形式语言理论、自动机理论、语法制导翻译的形式化定义、类型系统的数学基础、数据流分析框架。虎书是「做出来」，龙书是「讲清楚为什么」。

</Answer>
