## 词法分析的任务

词法分析（Lexical Analysis）是编译器的第一个阶段。它读入 Tiger 源程序的字符流，按词法规则将其分割成有意义的**词素**（lexeme），并为每个词素生成一个 **Token**。

Token 的结构为 `<token-type, lexeme, attribute>`：

- **token-type**：词法类别（如关键字 `LET`、标识符 `ID`、整数 `INT`）
- **lexeme**：原始字符串（如 `let`、`count`、`42`）
- **attribute**：附加信息（如标识符在符号表中的指针）

例如 Tiger 源码 `let x := 1 in x + 2 end` 经词法分析输出 `LET`、`ID(x)`、`ASSIGN`、`INT(1)`、`IN`、`ID(x)`、`PLUS`、`INT(2)`、`END` 等 Token。

## 正则表达式与有限自动机

Tiger 的词法规则用**正则表达式**描述。正则表达式到可执行扫描器的转换经过一条标准链路：

```text
正则表达式 ──Thompson构造──→ NFA ──子集构造──→ DFA ──Hopcroft──→ 最小化DFA
```

### NFA 与 DFA

| 特性 | NFA（非确定有限自动机） | DFA（确定有限自动机） |
|------|----------------------|---------------------|
| 转移 | 同一输入可到多个状态 | 唯一转移 |
| ε 转移 | 允许 | 不允许 |
| 运行 | 需跟踪多个可能状态 | 只跟踪一个状态 |
| 状态数 | 少 | 可能指数膨胀 |
| 实现 | 回溯 / 模拟 | 表驱动 O(1) 查表 |

<Callout type="info">

**子集构造法**将 NFA 转为 DFA：DFA 的每个状态对应 NFA 的一个状态子集（ε 闭包）。最坏情况 DFA 状态数为 2 的 n 次方（n 为 NFA 状态数），但实际中通常远少于此。

</Callout>

## 最长匹配与优先级

词法分析器处理歧义的两条核心规则：

### 最长匹配（Maximal Munch）

扫描器贪心地读入尽可能多的字符，直到不再匹配任何模式。例如输入 `<=` 应识别为一个 `LE` 运算符，而非 `<` 和 `=` 两个 Token。

### 优先级规则

当多个模式都能匹配同一 lexeme 时，按声明顺序选择第一个。例如关键字 `if` 同时匹配标识符模式 `[a-zA-Z]+` 和关键字模式 `if`，优先级规则保证识别为关键字。

```text
// ML-Lex 规则示例
if      => (Tokens.IF);      // 先声明，优先级高
[a-z]+  => (Tokens.ID);      // 后声明，作为回退
```

## Tiger 的词法特色

Tiger 语言有几个值得注意的词法规则：

- **嵌套注释**：`/* ... /* ... */ ... */` 允许注释嵌套，扫描器需用计数器跟踪嵌套深度，而非遇到第一个 `*/` 就结束
- **字符串转义**：字符串字面量 `"..."` 支持转义序列（如 `\n`、`\t`、`\"`），需在动作代码中处理
- **标识符**：`[a-zA-Z][a-zA-Z0-9_]*`，关键字优先于标识符

## ML-Lex 工具链

ML-Lex 接受三段式输入，自动生成扫描器代码：

```text
声明段（正则定义）  ──┐
规则段（模式+动作）  ──┼── ML-Lex ──→ 扫描器代码（状态转移表 + 驱动循环）
代码段（辅助函数）   ──┘
```

**工作原理**：ML-Lex 将每条规则的正则转为 NFA，合并为一个 NFA（新开始状态通过 ε 转移连到各规则），再转为 DFA 并最小化，最终生成一个状态转移表和一个驱动循环。驱动循环查表转移状态，到达接受状态时记录匹配规则和 lexeme 长度，执行最长匹配后运行对应动作代码。

<Callout type="tip">

ML-Lex 生成的扫描器是**表驱动**的：只需「当前状态 + 当前字符」查表即可决定动作，无需回溯，O(1) 转移。这是工业级词法分析器的标准实现方式。Tiger 编译器把扫描器作为独立模块，语法分析器通过 `yylex()` 拉取下一个 Token。

</Callout>

<Glossary>

<GlossaryItem term="Token">
词法分析的输出单元，结构为 `<token-type, lexeme, attribute>`，包含词法类别、原始字符串和附加属性。
</GlossaryItem>

<GlossaryItem term="NFA（非确定有限自动机）">
允许 ε 转移和同一输入到多状态转移的自动机，由 Thompson 构造法从正则表达式生成，结构直观但运行需跟踪多状态。
</GlossaryItem>

<GlossaryItem term="DFA（确定有限自动机）">
每个 (状态, 输入) 对只有唯一转移的自动机，由子集构造法从 NFA 转换而来，适合表驱动实现，查表 O(1) 转移。
</GlossaryItem>

<GlossaryItem term="最长匹配">
词法分析器贪心读入尽可能多字符的原则，确保 `<=` 被识别为一个 Token 而非 `<` 和 `=`。
</GlossaryItem>

<GlossaryItem term="嵌套注释">
Tiger 允许 `/* ... /* ... */ ... */` 注释嵌套，扫描器需用计数器跟踪深度，而非遇到首个 `*/` 即结束。
</GlossaryItem>

</Glossary>

### 问题 1

词法分析的任务是什么？Token 的结构是怎样的？

<Answer>

词法分析是编译器的第一个阶段，读入源程序字符流，按词法规则分割成有意义的词素（lexeme），并为每个词素生成一个 Token。Token 结构为 `<token-type, lexeme, attribute>`：token-type 是词法类别（如关键字 LET、标识符 ID、整数 INT），lexeme 是原始字符串，attribute 是附加信息（如标识符在符号表中的指针）。例如 Tiger 源码 `let x := 1` 经词法分析输出 LET、ID(x)、ASSIGN、INT(1) 等 Token。

</Answer>

### 问题 2

正则表达式如何转换为有限自动机？NFA 和 DFA 的区别是什么？

<Answer>

转换链：正则表达式 → Thompson 构造法 → NFA → 子集构造法 → DFA → Hopcroft 算法 → 最小化 DFA。NFA（非确定有限自动机）允许 ε 转移和同一输入转移到多个状态，结构直观但运行时需跟踪多个可能状态。DFA（确定有限自动机）对每个 (状态, 输入) 只有唯一转移，无 ε 转移，运行时只需跟踪一个状态，查表 O(1) 转移。DFA 更适合实现扫描器，但状态数可能指数膨胀，最小化后可达最简。

</Answer>

### 问题 3

词法分析器如何处理歧义？最长匹配和优先级规则如何工作？

<Answer>

两条核心规则：①最长匹配（Maximal Munch）——扫描器贪心地读入尽可能多的字符，直到不再匹配任何模式。例如输入 `<=` 应识别为一个 LE 运算符，而非 `<` 和 `=` 两个 Token。②优先级规则——当多个模式都能匹配同一 lexeme 时，按声明顺序选择第一个。例如关键字 `if` 同时匹配标识符模式 `[a-zA-Z]+` 和关键字模式 `if`，优先级规则保证识别为关键字而非标识符。ML-Lex 中先声明的规则优先级更高。

</Answer>

### 问题 4

ML-Lex 工具的工作原理是什么？它如何从正则规范生成可执行的词法分析器？

<Answer>

ML-Lex 接受三段式输入：声明段（正则定义）+ 规则段（模式+动作）+ 代码段（辅助函数）。工作原理：①将每条规则的正则表达式用 Thompson 构造法转为 NFA ②将所有 NFA 合并为一个 NFA——新起始状态经 ε 转移连到各规则的起始态 ③用子集构造法转为 DFA ④最小化 DFA ⑤生成代码：一个状态转移表 + 一个驱动循环。驱动循环查表转移状态，到达接受态时记录匹配的规则和 lexeme 长度，继续尝试最长匹配，最终执行对应规则的动作代码。Tiger 还要求支持嵌套注释。

</Answer>
