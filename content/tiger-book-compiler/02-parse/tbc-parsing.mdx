## 上下文无关文法

语法分析（Syntax Analysis）的核心是**上下文无关文法**（Context-Free Grammar, CFG）。CFG 是 Chomsky 2 型文法，用四元组 `G = (V, T, P, S)` 描述：

- `V`：非终结符集合（语法变量，如 `E`、`T`、`F`）
- `T`：终结符集合（Token，如 `id`、`+`、`*`）
- `P`：产生式集合（形如 `A → α`）
- `S`：开始符号（推导的起点）

经典的表达式文法：

```text
E → E + T | T
T → T * F | F
F → ( E ) | id
```

## 推导与归约

**推导**（Derivation）：从开始符号出发，反复用产生式右部替换非终结符。最左推导（自顶向下）每次替换最左非终结符，最右推导（自底向上）每次替换最右非终结符。

**归约**（Reduction）是推导的逆过程：从输入串出发，用产生式左部替换右部，直到归约到开始符号。

## 自顶向下 vs 自底向上

### 自顶向下：递归下降

从开始符号推导到输入串，方向是「树根→叶子」。

- **递归下降**：每个非终结符对应一个递归函数
- **预测分析**：用 FIRST/FOLLOW 集决定用哪条产生式
- 需先**消除左递归**和**提取公共左因子**，否则会无限递归或回溯

### 自底向上：LR 分析

从输入串归约到开始符号，方向是「叶子→树根」。

- **移进-归约**（Shift-Reduce）：将输入移进栈顶，栈顶匹配某产生式右部（句柄）时归约
- **项目集族**：LR 分析器的状态集合
- **ACTION-GOTO 表**：驱动移进/归约/接受/报错

<Callout type="info">

**LR 比递归下降表达力更强**：LR 从输入端归约，自然处理左递归文法；递归下降遇到左递归会无限循环，需改写文法。ML-Yacc 生成的 LALR(1) 分析器是 Tiger 语法分析的主流选择。

</Callout>

## 移进-归约的工作机制

LR 分析器维护一个**状态栈**和**符号栈**，根据 ACTION 表决定动作：

| 动作 | 含义 |
|------|------|
| Shift（移进） | 把当前 Token 和新状态压栈 |
| Reduce（归约） | 栈顶匹配某产生式右部，弹出后压入左部 |
| Accept（接受） | 归约到开始符号且输入耗尽，分析成功 |
| Error（报错） | 调用错误恢复 |

以文法 `E → E + E | INT` 分析 `INT + INT`：先移进 `INT`，归约为 `E`；移进 `+`；移进 `INT`，归约为 `E`；栈顶 `E + E` 归约为 `E`，接受。

## LR 分析器家族

LR 分析器按 lookahead 精度递进：

| 分析器 | lookahead | 特点 | 状态数 |
|-------|-----------|------|--------|
| LR(0) | 无 | 冲突最多，表达力最弱 | 少 |
| SLR(1) | 用 FOLLOW 集 | 用 FOLLOW 集消解冲突 | 少 |
| LALR(1) | 合并同心集 | 状态少且 lookahead 精确，ML-Yacc 默认 | 中 |
| LR(1) | 精确 | 表达力最强，状态可能爆炸 | 多 |

递进关系：`LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ LR(1)`，表达力递增，状态数递增。

<Callout type="tip">

**LALR(1) 是工业主流**：它在状态数（与 SLR 相同）和 lookahead 精度之间取得平衡，是 ML-Yacc 的默认选择。合并同心集可能引入归约-归约冲突，但实际文法中很少发生。

</Callout>

## 冲突处理与错误恢复

### 移进-归约冲突

在某状态下，既可移进下一个 Token 又可归约栈顶句柄。典型例子是 if-then-else 的悬空 else，解决：默认优先移进，使 else 关联最近的 if。

### 归约-归约冲突

可用两个不同产生式归约栈顶，通常因文法歧义导致，解决：优先选择先声明的产生式。

### 错误恢复（error 伪终结符）

虎书用 `error` 伪终结符做语法错误恢复：在文法中预设 `error` 规则（如 `exp → error`）。分析器遇到错误时，丢弃输入 Token 直到能移进 `error`，然后从错误状态继续分析，避免一错百错地报告大量级联错误。这比遇到第一个错误就停止更友好。

## 抽象文法

虎书区分**具体文法**（含括号、分隔符等无语义节点）和**抽象文法**（只保留语义节点）。ML-Yacc 在归约时执行语义动作，把具体文法节点转成抽象语法树（AST）节点，丢弃括号等无语义信息。AST 是后续语义分析和翻译的输入。

### 问题 1

上下文无关文法（CFG）的四元组是什么？什么是推导和归约？

<Answer>

CFG 四元组 G = (V, T, P, S)：V 是非终结符集合（语法变量），T 是终结符集合（Token），P 是产生式集合（形如 A → α），S 是开始符号。推导（Derivation）：从开始符号出发，反复用产生式右部替换非终结符，直到全部变为终结符。最左推导每次替换最左非终结符（自顶向下），最右推导每次替换最右非终结符（自底向上）。归约（Reduction）是推导的逆过程：从输入串出发，用产生式左部替换右部，直到归约到开始符号。

</Answer>

### 问题 2

递归下降和 LR 分析的核心区别是什么？移进-归约是如何工作的？

<Answer>

递归下降（自顶向下）：从开始符号出发，通过最左推导生成输入串，方向是「树根→叶子」。每个非终结符对应一个递归函数，用预测分析决定产生式，需处理左递归与公共前缀。LR 分析（自底向上）：从输入串出发，通过最右归约的逆过程归约到开始符号，方向是「叶子→树根」。移进-归约工作方式：将输入 Token 移进栈顶，当栈顶匹配某产生式右部（句柄）时归约为左部，重复直到栈中只剩开始符号且输入耗尽（接受）。LR 比 LL 表达力更强，能处理左递归。

</Answer>

### 问题 3

LR 分析器家族（LR(0)、SLR(1)、LALR(1)、LR(1)）的递进关系是什么？ML-Yacc 默认用哪个？

<Answer>

LR(0)：不考虑 lookahead，项目集只看圆点位置，冲突最多，表达力最弱。SLR(1)：在 LR(0) 基础上用 FOLLOW 集消解冲突——只有当 lookahead 在归约项的 FOLLOW 集中才归约。LALR(1)：合并同心项目集（LR(1) 项目去掉 lookahead 后相同的集合合并），状态数与 SLR 相同但 lookahead 更精确。LR(1)（规范 LR）：每个项目携带精确 lookahead，表达力最强但状态数可能爆炸。递进关系：LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ LR(1)。ML-Yacc 默认用 LALR(1)，在状态数和 lookahead 精度之间取得平衡，是工业主流。

</Answer>

### 问题 4

什么是移进-归约冲突和归约-归约冲突？虎书如何做语法错误恢复？

<Answer>

移进-归约冲突：在某状态下，既可移进下一个 Token 又可归约栈顶句柄，无法确定动作。常见于 if-then-else 悬空 else，默认优先移进使 else 关联最近 if。归约-归约冲突：可用两个不同产生式归约栈顶，通常因文法歧义导致，优先选择先声明的产生式。错误恢复：虎书使用 error 伪终结符——在文法中预设 error 规则（如 exp → error），分析器遇到错误时丢弃输入直到能移进 error，然后从错误状态继续分析，避免一错百错地报告大量级联错误。

</Answer>
