## 语义分析的任务

语义分析（Semantic Analysis）接收语法分析产生的 AST，绑定标识符的声明信息并做**类型检查**，输出带类型的结果。词法和语法只能保证程序「形式上合法」，但无法判断语义是否正确——例如变量是否已声明、函数参数类型是否匹配、运算符操作数类型是否合法，这些都靠语义分析。

虎书的语义分析器（`transVar` / `transExp` / `transDec`）递归遍历 AST，查询环境应用类型规则，类型错误时报错。

## 双环境

虎书用两个**环境**（Symbol → 绑定）记录声明信息：

### 类型环境 tenv

记录 `type` 声明，Symbol 映射到类型：

- `int → INT`
- `string → STRING`
- `type rec = {name: string, age: int}` → rec 绑定到对应 record 类型
- `type intList = int array` → intList 绑定到对应 array 类型

### 值环境 venv

记录 `var` 和 `function` 声明，Symbol 映射到值绑定：

- `x → Var(int)`：变量 x 是 int 类型
- `print → Func(string → unit)`：函数 print 接受 string 返回 unit
- `greet → Func(unit → void)`：函数 greet 接受 unit

<Callout type="info">

**作用域管理**：进入 `let ... in ... end` 时把新绑定压入环境，`end` 时弹出。环境用栈式作用域管理——内层声明遮蔽外层同名声明，离开作用域自动恢复。Symbol 是唯一标识符（字符串），环境是 Symbol 到绑定的映射。

</Callout>

## Tiger 类型系统

Tiger 的类型分为基本类型和复合类型：

| 类型 | 说明 |
|------|------|
| int | 整数 |
| string | 字符串 |
| unit | 无值（相当于 void），如无返回值的函数体 |
| record | 记录，`{字段: 类型}` |
| array | 数组，同类型序列 |
| nil | record 的零值（空记录） |

### 名字相等 vs 结构相等

Tiger 的 record 和 array 类型按**声明唯一性**判断相等（名字相等）——每个 `type` 声明产生一个唯一的类型对象。即使两个 record 字段结构完全相同（如都是 `{x:int}`），只要来自不同声明就不相等。这与结构相等（按字段结构判断）不同，是 Tiger 的设计选择。

### nil 子类型

`nil` 是所有 record 类型的子类型，可用于任何需要 record 值的位置作为「空记录」。例如 `type rec = {x:int}; var r: rec := nil` 合法。但 `nil` 不能用于需要 int 或 array 的位置，只针对 record。

<Callout type="tip">

**为什么需要 nil 子类型？** 因为 record 类型用名字相等，每个声明唯一，无法预定义一个通用的「空值」与所有 record 类型都相等。引入 nil 作为特殊子类型——它不是某个具体 record 类型，但可匹配任何 record 类型，解决「record 的空值」问题。

</Callout>

## 一遍做语义检查与翻译

虎书的语义分析器对每个表达式返回二元组 `(exp, ty)`：

- **exp**：该表达式翻译成的 IR 片段（Tree IR 表达式）
- **ty**：推导出的类型

同时返回两者，是因为虎书把**语义分析和翻译到 IR 合并在一个递归遍历中完成**——类型检查的同时生成 IR 片段，避免对 AST 做两次遍历。`ty` 用于上层做类型一致性检查（如 if-then-else 两臂类型必须相同、while 条件必须为 int），`exp` 则积累成完整的 Tree IR。

### 类型检查规则示例

| 表达式 | 规则 |
|--------|------|
| `a + b` | a、b 必须 int，结果 int |
| `a := b` | a、b 类型相同 |
| `if e1 then e2 else e3` | e1 须 int，e2、e3 类型相同 |
| `while e1 do e2` | e1 须 int，e2 须 unit |
| `f(a)` | a 类型匹配 f 的形参类型，结果是 f 的返回类型 |
| `r.field` | r 须 record，field 须存在 |

## 语义错误的种类

- **未声明变量**：venv 中查不到 Symbol
- **类型不匹配**：如把 string 赋给 int 变量
- **字段不存在**：访问 record 没有的字段
- **参数数量/类型错误**：调用函数时形参不匹配
- **break 越界**：`break` 出现在循环外

### 问题 1

语义分析的任务是什么？双环境（tenv / venv）如何工作？

<Answer>

语义分析接收 AST，绑定标识符的声明信息并做类型检查，输出带类型的结果。虎书用双环境：类型环境 tenv（Symbol → 类型绑定，记录 type 声明，如 int、string、自定义 record/array 类型）和值环境 venv（Symbol → 值绑定，记录变量 Var 和函数 Func 的类型签名）。进入 let 作用域时把新绑定压入环境，end 时弹出。语义分析器（transVar/transExp/transDec）递归遍历 AST，查环境应用类型规则，类型错误时报错。

</Answer>

### 问题 2

Tiger 的类型系统有哪些类型？记录类型和数组类型如何判断相等？

<Answer>

Tiger 类型包括：基本类型 int（整数）、string（字符串）、unit（无值，相当于 void）；复合类型 record（记录，{字段: 类型}）和 array（同类型序列）；以及 nil（record 的零值）。记录类型和数组类型按声明唯一性判断相等——每个 record/array 类型声明产生一个唯一的类型对象，即使两个 record 字段结构完全相同（如都是 {x:int}）也不相等。这是结构相等 vs 名字相等的区别，Tiger 用名字相等（唯一性引用相等）。

</Answer>

### 问题 3

nil 子类型规则是什么？为什么需要它？

<Answer>

nil 是所有 record 类型的子类型（nil ⊑ 任意 record 类型），可用于任何需要 record 值的位置作为「空记录」。需要它的原因：record 类型用名字相等，每个声明唯一，无法预定义一个通用的「空值」与所有 record 类型都相等。所以引入 nil 作为特殊的子类型——它不是某个具体 record 类型，但可以匹配任何 record 类型。例如 type rec = {x:int}; var r: rec := nil 合法。注意 nil 不能用于需要 int 或 array 的位置，只针对 record。

</Answer>

### 问题 4

类型检查器返回的 (exp, ty) 表示什么？为什么要同时返回 exp 和 ty？

<Answer>

类型检查器对每个表达式返回二元组 (exp, ty)：exp 是该表达式翻译成的 IR 片段（Tree IR 表达式），ty 是推导出的类型。同时返回两者是因为虎书把语义分析和翻译到 IR 合并在一个递归遍历中完成——类型检查的同时生成 IR 片段，避免对 AST 做两次遍历。ty 用于上层做类型一致性检查（如 if-then-else 两臂类型必须相同、while 条件必须为 int），exp 则积累成完整的 Tree IR。这种「一遍做语义检查+翻译」是虎书的设计特色。

</Answer>
