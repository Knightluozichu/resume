## 活动记录与 Frame 抽象

**活动记录**（activation record）是函数调用时在栈上分配的数据帧，存放本次调用的局部数据——参数、返回地址、局部变量、临时变量等。每次函数调用压入一个新栈帧，返回时弹出。

虎书用 **Frame 抽象**封装栈帧，使前端只关心 escape 判定与 static link，具体栈帧布局交给后端按目标机器实现。Frame 接口提供：

- `newFrame(name, formals)`：创建栈帧，formals 标记每个参数是否 escape
- `name`：返回函数名
- `formals`：返回参数访问方式（frame pointer 偏移或寄存器）
- `allocLocal(everyLocal)`：分配一个局部变量，返回访问方式

`allocLocal(true)` 分配到栈（escape 变量，有地址），`allocLocal(false)` 可进寄存器（非 escape 变量）。

## escape 变量

**escape 变量**是指其生命周期超出定义它的函数体的变量——被嵌套函数引用、被取地址、或在循环/条件外仍需访问的变量。

### 什么算 escape？

- 变量被嵌套函数引用 → escape
- 变量被取地址（`` `&x` ``）→ escape
- 变量在循环/条件外被引用 → escape

### escape 与分配

| 变量类型 | 分配位置 | 原因 |
|---------|---------|------|
| escape 变量 | 栈帧（有稳定地址） | 可被嵌套函数通过 static link 访问，不能放进寄存器 |
| 非 escape 变量 | 可进寄存器 | 生命周期局限在本函数内，无需稳定地址，访存更快 |

<Callout type="info">

**escape 判定在语义分析时完成**：递归检查变量使用，若被内层嵌套函数引用则标记 escape。判定结果传给 `allocLocal`，决定变量存栈还是可进寄存器。这是虎书把「变量存哪」抽象化的关键——前端判定 escape，后端按机器特性决定具体布局。

</Callout>

## 静态链（static link）

Tiger 支持嵌套函数定义——内层函数能访问外层函数的局部变量。但运行时调用栈是**动态**的（调用者不一定是词法外层），所以需要 **static link** 记录词法外层关系。

### static link 如何工作

每次进入函数时，在栈帧中压入 static link——指向该函数**词法外层函数**的栈帧。访问外层变量 `x` 时：

1. 从当前栈帧的 static link 找到外层函数栈帧
2. 按 `x` 在该栈帧的偏移读取

**嵌套层次 = 跨越的 static link 数**：访问外 1 层变量跟 1 次 static link，外 n 层跟 n 次。

### 为什么需要 static link

```text
function outer() =
  let var x := 1
      function inner() = x + 1   /* inner 访问 outer 的 x */
  in inner() end
```

`inner` 调用时，调用栈上是 `outer` 的栈帧，但 `inner` 词法外层是 `outer`。`inner` 通过自己的 static link 找到 `outer` 的栈帧，再按 `x` 的偏移读取。static link 是访问非局部变量的标准技术。

<Callout type="tip">

**static link 本身是 escape 变量**：它要在栈帧中分配（被嵌套函数通过它访问），所以 `newFrame` 会自动为每个函数的 static link 分配栈空间。进入函数时，调用者负责把正确的 static link（指向词法外层栈帧）传入。

</Callout>

## 栈帧内部结构

栈帧从高地址到低地址通常包含：

| 区域 | 用途 |
|------|------|
| 传入参数区 | 超出寄存器传参数量的参数存这里 |
| 返回地址 + static link | 记录返回点和词法外层栈帧（escape） |
| 保存的寄存器 | 被调用者需保存的寄存器 |
| 局部变量 | escape 变量在此分配（有地址） |
| 临时变量 | 非 escape 变量和中间结果（可进寄存器，溢出时存此） |

访问方式通过 frame pointer（`fp`）的偏移定位。Frame 抽象把这些细节隐藏，前端只用 `allocLocal` 拿到访问方式，不关心具体偏移。

## Frame 抽象贯穿前后端

Frame 不只是前端概念，它贯穿整个编译流程：

- **语义分析**：判定哪些变量 escape → `allocLocal(true)`
- **翻译 IR**：通过 Frame 拿到变量访问方式（`fp` 偏移）生成 MEM 节点
- **static link**：作为 escape 变量存栈帧，支持嵌套函数访问外层
- **寄存器分配溢出**：溢出的 TEMP 也用 Frame 的栈空间存

<Callout type="info">

Frame 抽象解决的核心问题：把「变量存哪」这一与机器强相关的决策抽象化，前端写一次即可适配多平台，后端按机器特性实现具体布局。这是平台无关编译器的标准设计。

</Callout>

### 问题 1

什么是活动记录（栈帧）？Frame 抽象提供了哪些接口？

<Answer>

活动记录（activation record）是函数调用时在栈上分配的数据帧，存放本次调用的局部数据。虎书用 Frame 抽象封装它，使前端只关心 escape 判定与 static link，具体栈帧布局交给后端实现。Frame 接口提供：newFrame(name, formals)——创建栈帧（formals 带每个参数是否 escape 的标记）；name——返回函数名；formals——返回参数访问方式（frame pointer 偏移或寄存器）；allocLocal(everyLocal)——分配一个局部变量，返回访问方式。Frame 是平台无关抽象，不同目标机器有不同实现。

</Answer>

### 问题 2

什么是 escape 变量？如何判定？escape 与非 escape 变量在分配上有何区别？

<Answer>

escape 变量是指其生命周期超出定义它的函数体的变量——被嵌套函数引用、被取地址（&amp;x）、或在循环/条件外仍需访问的变量。判定方式：在语义分析时递归检查变量使用，若被内层嵌套函数引用则标记 escape。区别：escape 变量必须在栈帧中分配（有稳定内存地址，可被嵌套函数通过 static link 访问），不能放进寄存器；非 escape 变量可留在寄存器中（更快，无需访存）。allocLocal(true) 分配到栈，allocLocal(false) 可进寄存器。

</Answer>

### 问题 3

静态链（static link）如何工作？为什么需要它？嵌套层次如何决定访问路径？

<Answer>

静态链解决嵌套函数访问外层函数局部变量的问题。每次进入函数时，在栈帧中压入 static link——指向该函数词法外层函数的栈帧。访问外层变量 x 时：①从当前栈帧的 static link 找到外层函数栈帧 ②按 x 在该栈帧的偏移读取。嵌套层次 = 跨越的 static link 数：访问外 1 层变量跟 1 次 static link，外 n 层跟 n 次。需要它的原因：Tiger 支持嵌套函数定义，内层函数能访问外层变量，但运行时调用栈是动态的（调用者不一定是词法外层），所以用 static link 记录词法外层关系，这是访问非局部变量的标准技术。

</Answer>

### 问题 4

栈帧内部包含哪些区域？各区域的用途是什么？

栈帧从高地址到低地址通常包含：①传入参数区——超出寄存器传参数量的参数存这里 ②返回地址 + static link（escape）——记录返回点和词法外层栈帧 ③保存的寄存器——被调用者需保存的寄存器 ④局部变量——escape 变量在此分配（有地址） ⑤临时变量——非 escape 变量和中间结果（可进寄存器，溢出时存此）。访问方式通过 frame pointer（fp）的偏移定位。Frame 抽象把这些细节隐藏，前端只用 allocLocal 拿到访问方式，不关心具体偏移。
