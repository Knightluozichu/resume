## Tree IR 概述

翻译到中间表示把带类型 AST 转换为 **Tree IR**——一组树形中间表示节点。Tree IR 是前后端的契约：前端翻译成它，后端从它生成目标代码。设计成树形是为了便于后端用 Maximal Munch 做树覆盖指令选择。

Tree IR 分为**表达式节点**（求值为值）和**语句节点**（无返回值）两类。

## Tree IR 节点

### 表达式节点

| 节点 | 含义 |
|------|------|
| `CONST(i)` | 常量 i |
| `NAME(label)` | 跳转标签名 |
| `TEMP(t)` | 临时变量/寄存器 |
| `BINOP(op, e1, e2)` | 二元运算 |
| `MEM(e)` | 内存读/写目标（地址 e） |
| `CALL(f, args)` | 函数调用 |
| `ESEQ(stmt, e)` | 先执行 stmt，再把 e 作为值 |

### 语句节点

| 节点 | 含义 |
|------|------|
| `MOVE(dst, src)` | 赋值（dst := src） |
| `EXP(e)` | 丢弃表达式值（仅副作用） |
| `JUMP(exp, labels)` | 跳转 |
| `CJUMP(op, e1, e2, t, f)` | 条件跳转（e1 op e2 为真跳 t，假跳 f） |
| `SEQ(s1, s2)` | 语句序列 |
| `LABEL(name)` | 标记跳转目标 |

## Ex / Nx / Cx 三形式

虎书的翻译器把每个表达式翻译成三种形式之一，用统一接口表示：

- **Ex**（表达式）：求值为一个值，直接是一棵 Tree 表达式树，如 `BINOP(PLUS, a, b)`
- **Nx**（语句）：无返回值，仅副作用，如 `MOVE(MEM(x), v)`
- **Cx**（条件）：根据真假跳转到不同标签，用一个接收真/假标签的函数表示，适合布尔表达式

三种形式可互相转换（`unEx` / `unNx` / `unCx`）：

$$\text{unEx}(\text{Cx}) = \text{ESEQ}(\text{SEQ}(\text{MOVE}(t, 1), \text{SEQ}(\text{CJUMP}(op, e_1, e_2, T, F), \text{SEQ}(\text{LABEL}(F), \text{MOVE}(t, 0))))), t)$$

即把 Cx 转成 Ex 时，生成一个临时变量 `t`，先置 1，条件假则跳到 F 置 0，最终取 `t` 的值。

<Callout type="info">

**Cx 的核心价值**：布尔表达式不必实际求值为 0/1 存入临时变量，而是直接用跳转控制流。这让短路求值（`&`、`|`）和 if/while 条件能高效翻译——条件成立跳真分支，不成立跳假分支，无需多余的求值与存储。

</Callout>

## ESEQ 节点

`ESEQ(stmt, e)` 表示「先执行 `stmt`，再把 `e` 作为值」，允许在表达式内部嵌入副作用。

### 为什么翻译阶段会产生 ESEQ

有些表达式（如带副作用的函数调用、短路逻辑）在递归翻译时自然地把语句和表达式混合，用 ESEQ 表达最直接。例如函数调用结果参与运算时，`CALL` 的副作用和返回值用 `ESEQ` 组合。

### 为什么需要规范化消除 ESEQ

ESEQ 让表达式树不再「纯净」——表达式内部夹杂语句，导致求值顺序复杂、子树互相影响，不利于指令选择（树覆盖）和寄存器分配。所以规范化阶段要消除 ESEQ：把内部 `stmt` 提升到上层 `SEQ`，把表达式树重写成不含 ESEQ 的规范形式。

<Callout type="tip">

ESEQ 是翻译阶段为简洁而引入的「临时复杂度」，规范化阶段负责把它消化掉。这种「先引入后消除」的设计让翻译器写得简单（自然用 ESEQ 组合），而把复杂性集中在规范化一个阶段处理。

</Callout>

## 控制流翻译

### if-then-else

生成真/假/结束标签，用 Cx 形式翻译条件：

$$\text{if } e_1 \text{ then } e_2 \text{ else } e_3 \Rightarrow \text{CJUMP}(\ldots, T, F); \text{LABEL}(T); e_2; \text{JUMP}(END); \text{LABEL}(F); e_3; \text{LABEL}(END)$$

条件为真跳 `T` 执行 `e2`，假跳 `F` 执行 `e3`，两分支都跳到 `END` 汇合。要求 `e2`、`e3` 类型相同。

### while 循环

生成测试/体/结束标签：

$$\text{while } e_1 \text{ do } e_2 \Rightarrow \text{LABEL}(TEST); \text{CJUMP}(\ldots, BODY, END); \text{LABEL}(BODY); e_2; \text{JUMP}(TEST); \text{LABEL}(END)$$

条件 `e1` 须为 int，体 `e2` 须为 unit。`break` 跳到 `END`。

### 短路求值

`&`（AND）和 `|`（OR）用 Cx 串联实现短路：

- `a & b`：`a` 为假短路跳假，否则求 `b`
- `a | b`：`a` 为真短路跳真，否则求 `b`

都用 Cx 形式（接收真/假标签）串联，避免把布尔值实际存入临时变量，直到真正需要值时才用 `unEx` 转换。

## 一遍翻译的设计

虎书把语义分析和翻译到 IR 合并在一个递归遍历中：`transExp` 返回 `(exp, ty)`，`exp` 是 Tree IR 片段，`ty` 是类型。类型检查的同时积累 IR，避免对 AST 做两次遍历。这种「一遍做两件事」是虎书的设计特色。

<Glossary>

<GlossaryItem term="Tree IR">
虎书的核心中间表示，一组树形节点（CONST/TEMP/BINOP/MEM/CALL/MOVE/JUMP 等），是前后端契约，规范化后适合 Maximal Munch 树覆盖。
</GlossaryItem>

<GlossaryItem term="Ex / Nx / Cx">
翻译 IR 的三种形式：Ex 求值为值（表达式树），Nx 无返回值（语句），Cx 根据真假跳转（条件）。三者可通过 unEx/unNx/unCx 互相转换。
</GlossaryItem>

<GlossaryItem term="ESEQ">
Tree IR 表达式节点，表示「先执行语句再求值」，翻译阶段为简洁引入，规范化阶段消除它以纯净表达式树。
</GlossaryItem>

<GlossaryItem term="CJUMP">
Tree IR 条件跳转语句，CJUMP(op, e1, e2, t, f)：e1 op e2 为真跳 t，假跳 f。是控制流翻译的核心。
</GlossaryItem>

<GlossaryItem term="短路求值">
&amp;（AND）和 |（OR）用 Cx 形式串联，左操作数满足条件即短路跳转，不求右操作数，避免多余求值与存储。
</GlossaryItem>

</Glossary>

<Exercises>

### 问题 1

Tree IR 有哪些表达式节点和语句节点？

<Answer>

表达式节点（求值为值）：CONST(i) 常量、NAME(label) 跳转标签名、TEMP(t) 临时变量/寄存器、BINOP(op, e1, e2) 二元运算、MEM(e) 内存读/写目标、CALL(f, args) 函数调用、ESEQ(stmt, e) 先执行语句再求值。语句节点（无返回值）：MOVE(dst, src) 赋值、EXP(e) 丢弃表达式值、JUMP(exp, labels) 跳转、CJUMP(op, e1, e2, t, f) 条件跳转、SEQ(s1, s2) 语句序列、LABEL(name) 标记跳转目标。表达式树和语句树共同构成 Tree IR。

</Answer>

### 问题 2

Ex / Nx / Cx 三种翻译形式分别是什么？它们之间如何转换？

<Answer>

Ex（表达式）：求值为一个值，直接是一棵 Tree 表达式树，如 BINOP(PLUS, a, b)。Nx（语句）：无返回值，仅副作用，如 MOVE(MEM(x), v)。Cx（条件）：根据真假跳转到不同标签，用一个接收真/假标签的函数表示，适合布尔表达式。转换：unEx 把任意形式转成求值表达式——Cx 转 Ex 时生成 CJUMP 把结果存入临时变量；unNx 转成无值语句——Ex 转 Nx 包一层 EXP 丢弃值；unCx 转成条件形式——Ex 转 Cx 时与零比较生成 CJUMP。三种形式让 if/while/短路逻辑能高效翻译。

</Answer>

### 问题 3

ESEQ 节点的作用是什么？为什么翻译阶段会产生它，又为什么需要后续规范化来消除？

<Answer>

ESEQ(stmt, e) 表示「先执行 stmt，再把 e 作为值」，允许在表达式内部嵌入副作用。翻译阶段会产生它，是因为有些表达式（如带副作用的函数调用、短路逻辑）在递归翻译时自然地把语句和表达式混合在一起，用 ESEQ 表达最直接。但 ESEQ 让表达式树不再「纯净」——表达式内部夹杂语句，导致求值顺序复杂、子树可能互相影响，不利于后续指令选择（树覆盖）和寄存器分配。所以规范化阶段要消除 ESEQ：把内部 stmt 提升到上层 SEQ，把表达式树重写成不含 ESEQ 的规范形式，让指令选择能干净地做树覆盖。

</Answer>

### 问题 4

控制流结构（if / while / 短路 & |）如何用 Tree IR 翻译？

<Answer>

if-then-else：生成真/假标签和结束标签，用 Cx 形式翻译条件——条件为真跳到 then，假跳到 else，两分支结束后都跳到结束标签。while：生成测试标签、体标签、结束标签，测试条件为假则跳结束，为真则执行体再跳回测试。短路求值：&（AND）左操作数为假则短路跳假，否则求右操作数；|（OR）左操作数为真则短路跳真，否则求右操作数。这些都用 Cx 形式（接收真/假标签）串联，避免把布尔值实际存入临时变量，直到真正需要值时才用 unEx 转换。这是 Cx 形式的核心价值。

</Answer>
