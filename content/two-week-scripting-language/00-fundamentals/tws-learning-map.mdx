## 这本书讲什么

《两周自制脚本语言》带你从零开始，用 Java 在两周内实现一门完整的脚本语言 **Stone**。Stone 支持：

- 变量赋值与算术运算
- `if` / `while` 控制流
- 函数定义与闭包
- 类定义与继承
- 数组与哈希表

这不是玩具——它覆盖了编译原理的**完整前端+后端链路**，是理解「代码如何变成行为」的最佳入门路径。

## 解释器四层流水线

Stone 解释器的核心是一条流水线，源码经四层处理后得到执行结果：

| 层次 | 模块 | 输入 → 输出 | 章节 |
|------|------|------------|------|
| 前端 | 词法分析（Lexer） | 源码文本 → Token 序列 | ch1 |
| 前端 | 语法分析（Parser） | Token 序列 → AST | ch2 |
| 中端 | 抽象语法树（AST） | AST 节点树 + 访问者模式 | ch3 |
| 后端 | 求值执行（Evaluator） | AST 遍历 + 环境查找 → 结果 | ch4 |

<Callout type="info">

**关键洞察**：AST 是前端与后端的桥梁。前端负责「读懂代码结构」，后端负责「执行代码逻辑」，两者通过 AST 解耦。

</Callout>

## 为什么选树遍历解释器

Stone 采用**树遍历解释器**（tree-walking interpreter），而非字节码虚拟机：

| 对比维度 | 树遍历解释器 | 字节码虚拟机 |
|---------|------------|------------|
| 实现复杂度 | 低（直接遍历 AST） | 高（需编译+VM 两层） |
| 执行性能 | 较慢 | 较快 |
| 教学适用性 | 强（结构清晰） | 弱（细节多） |
| 适合场景 | 入门教学 | 生产级语言 |

<Callout type="tip">

本书目标是**理解原理**而非性能优化。树遍历让源码到结果的完整路径一目了然。

</Callout>

## 四个核心概念预览

| 概念 | 一句话解释 | 详细章节 |
|------|-----------|---------|
| Token | 源码分割后的最小语义单元 | ch1 |
| AST | 反映语法结构的树形数据 | ch3 |
| 环境（Environment） | 变量名到值的绑定容器 | ch4 |
| 闭包 | 函数 + 定义时的环境 | ch5 |

### 问题 1

Stone 语言用什么语言实现？整体目标是什么？

<Answer>

用 Java 实现。整体目标是两周内从零开始自制一个脚本语言解释器，涵盖词法分析、语法分析、抽象语法树、求值执行、函数闭包、类继承、数组哈希等完整功能，理解编译原理的核心概念。

</Answer>

### 问题 2

Stone 解释器的四层流水线是什么？各层之间如何衔接？

<Answer>

四层流水线：①前端词法分析（Lexer，源码 → Token 序列）②前端语法分析（Parser，Token → AST）③中端抽象语法树（AST 节点 + 访问者模式）④后端求值执行（树遍历解释器 + 环境）。衔接方式：Lexer 输出 Token 流给 Parser，Parser 输出 AST 给 Evaluator，Evaluator 遍历 AST 执行计算。AST 是前端与后端之间的数据桥梁。

</Answer>

### 问题 3

全书 10 章的学习路径是什么？各章之间的依赖关系是什么？

<Answer>

路径：ch0 学习地图 → ch1 词法分析器 → ch2 语法分析器 → ch3 抽象语法树 → ch4 求值器 → ch5 函数与闭包 → ch6 类型与错误处理 → ch7 类与继承 → ch8 数组与哈希表 → ch9 全书复习。依赖：ch1 是全部基础，ch2 依赖 ch1（Token），ch3 依赖 ch2（Parser 输出），ch4 依赖 ch3（遍历 AST），ch5-ch8 是在 ch4 基础上的语言特性扩展。

</Answer>

### 问题 4

为什么选择树遍历解释器而非字节码虚拟机？

<Answer>

树遍历解释器直接在 AST 上递归求值，无需中间字节码编译步骤，实现简单、结构清晰，适合教学。Stone 作为入门级脚本语言，重点在于理解编译原理核心概念，非性能优化。树遍历方式让初学者能直观看到源码到执行结果的完整流程。字节码虚拟机引入额外复杂性，不适合两周入门目标。

</Answer>
