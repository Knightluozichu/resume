## 词法分析器的作用

词法分析器（Lexer）是解释器的**第一道工序**：将源代码字符串分割成 Token 序列。

```text
源码文本                        Token 序列
"even = 0"        ──Lexer──→    IDENT("even")  EQ("=")  INT("0")
```

## Token 的四种类型

Stone 的 Token 分为四类，每类用一条正则表达式匹配：

| Token 类型 | 正则规则 | 示例 |
|-----------|---------|------|
| 标识符 Identifier | `[A-Za-z_][A-Za-z0-9_]*` | `even`, `x`, `_val` |
| 整数字面量 Integer | `[0-9]+` | `0`, `42`, `100` |
| 字符串字面量 String | `"(\\\\\"|\\\\\\\\|\\\\n|[^"])*"` | `"hello"`, `"a\nb"` |
| 运算符 Operator | `==|<=|>=|&&|\|\||\p{Punct}` | `+`, `==`, `<=` |

<Callout type="warning">

**多字符运算符必须放在单字符标点之前**。如果 `\p{Punct}`（匹配单个标点）写在 `==` 前面，遇到 `==` 时会先匹配到第一个 `=`，导致 `==` 被拆成两个 `=` Token。

</Callout>

## Lexer 的核心正则

Stone Lexer 用一条组合正则同时匹配所有 Token 类型：

```java
private Pattern tokenPattern = Pattern.compile(
    "\\s*((//.*)|([0-9]+)|" +
    "(\"(\\\\\"|\\\\\\\\|\\\\n|[^\"])*\")|" +
    "[A-Za-z_][A-Za-z0-9_]*|" +
    "==|<=|>=|&&|\\|\\||\\p{Punct})?"
);
```

正则的分组结构：

| 分组 | 匹配内容 | 处理方式 |
|------|---------|---------|
| `\s*` | 前导空白 | 跳过 |
| `(//.*)` | 行注释 | 跳过 |
| `([0-9]+)` | 整数字面量 | 生成 INT Token |
| `("...")`  | 字符串字面量 | 生成 STRING Token |
| `[A-Za-z_]...` | 标识符 | 生成 IDENT Token |
| `==|<=|...` | 运算符 | 生成 OPERATOR Token |

## 逐行扫描流程

```text
┌─────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 读取下一行  │ ──→ │ Pattern.match│ ──→ │ 识别Token类型│ ──→ │ 生成Token入列│
└─────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

1. **读取下一行**源码文本
2. **Pattern.match** 用正则从行首开始匹配
3. **识别 Token 类型**——根据匹配到的正则分组判断
4. **生成 Token 对象**——携带文本和行号，加入队列
5. 匹配到注释或空白时，**跳过不生成 Token**
6. 重复直到行尾，再读下一行

## Token 对象结构

```java
public class Token {
    private int line;     // 行号，用于错误定位
    private String text;  // Token 的文本内容

    public boolean isIdentifier() { ... }
    public boolean isNumber() { ... }
    public boolean isString() { ... }
    public int getLineNumber() { return line; }
    public String getText() { return text; }
}
```

<Callout type="info">

每个 Token 都携带 **line 行号**。当后续语法分析或运行时发生错误时，通过行号精确定位到源代码中的出错位置。

</Callout>

## 注释与空白处理

```text
// 这是一行注释，Lexer 匹配到 //.* 后跳过
   x = 1  // 前导空白 \s* 也被跳过
```

- **行注释** `//`：正则 `(//.*)` 匹配 `//` 后到行尾的所有内容
- **空白**：正则 `\s*` 匹配空格、制表符等
- 两者匹配后**不生成 Token**，直接跳过继续匹配下一个

<GlossaryItem term="Token（单词/记号）">
词法分析器输出的最小语义单元，包含文本内容和行号信息。是源码被结构化后的基本构件。
</GlossaryItem>

<GlossaryItem term="词法分析（Lexical Analysis）">
将源代码字符串按正则规则分割成 Token 序列的过程，也称扫描（Scanning）。
</GlossaryItem>

<GlossaryItem term="最长匹配原则">
正则引擎在多个规则都能匹配时，优先选择匹配字符最多的规则。多字符运算符 `==` 必须写在单字符 `=` 之前才能被正确识别。
</GlossaryItem>

<GlossaryItem term="\p{Punct}">
Java 正则中匹配标点符号的字符类，包括 `!`, `+`, `-`, `*`, `/`, `=`, `<`, `>` 等所有 ASCII 标点。
</GlossaryItem>

### 问题 1

词法分析器的作用是什么？输入和输出分别是什么？

<Answer>

词法分析器的作用是将源代码字符串分割成 Token 序列。输入是 Stone 源代码文本（逐行读取），输出是 Token 对象列表。每个 Token 包含文本内容和行号信息。Lexer 是解释器的前端第一步，为后续的语法分析器提供结构化的输入。

</Answer>

### 问题 2

Stone 的 Token 有哪些类型？各自的正则匹配规则是什么？

<Answer>

四种 Token 类型：①标识符（Identifier）—— `[A-Za-z_][A-Za-z0-9_]*`，匹配变量名和关键字 ②整数字面量（Integer）—— `[0-9]+` ③字符串字面量（String）—— `"(\\"|\\\\|\\n|[^"])*"`，支持转义 ④运算符（Operator）—— `==|<=|>=|&&|\|\||\p{Punct}`，包含多字符运算符和单字符标点。此外正则还匹配行注释 `//.*` 和前导空白 `\s*`，这两种匹配结果不生成 Token。

</Answer>

### 问题 3

Lexer 是如何处理注释和空白的？为什么每个 Token 要携带行号？

<Answer>

Lexer 的正则表达式中包含注释组 `(//.*)` 和空白组 `\s*`。每次匹配后检查匹配到的组：如果是注释或空白（空字符串），则跳过不生成 Token，继续匹配下一个。行号的作用是错误定位——当后续语法分析或运行时发生错误时，可以通过 Token 携带的行号精确定位到源代码中的出错位置，给用户清晰的错误提示。这是编译器前端的基本设计。

</Answer>

### 问题 4

多字符运算符（如 `==`、`<=`、`&&`）在正则中为什么要放在单字符标点之前？

<Answer>

正则表达式按从左到右的顺序尝试匹配。如果 `\p{Punct}`（匹配单个标点符号）放在 `==`、`<=` 等多字符运算符之前，那么遇到 `==` 时会先匹配到第一个 `=`，将其作为单独的 Token 返回，第二个 `=` 再单独匹配，导致 `==` 被拆成两个 `=` Token。把多字符运算符放在前面，正则引擎会优先匹配更长的模式，确保 `==` 被正确识别为一个 Token。这是词法分析中「最长匹配」原则的体现。

</Answer>
