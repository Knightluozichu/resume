## AST 的作用

抽象语法树（AST）是解释器架构的**核心数据结构**——前端（词法+语法分析）的输出，后端（求值器）的输入。

```text
Token 序列  ──Parser──→  AST 节点树  ──Evaluator──→  执行结果
                         (前端输出)    (后端输入)
```

## AST 节点层次

所有 AST 节点继承自抽象基类 `ASTNode`，分为两大分支：

```text
ASTNode（抽象基类）
  ├── ASTList（列表容器，持有多个子节点）
  │     ├── 表达式节点：BinaryExpr, PrimaryExpr, NegativeExpr ...
  │     └── 语句节点：IfStmnt, WhileStmnt, BlockStmnt ...
  └── ASTLeaf（叶子节点，持有一个 Token）
        ├── NumberLiteral（整数字面量）
        ├── StringLiteral（字符串字面量）
        └── Name（变量引用）
```

### ASTList vs ASTLeaf

| 类 | 持有内容 | 子节点 | 示例 |
|----|---------|--------|------|
| ASTList | 子节点列表 | 多个 | BinaryExpr, IfStmnt |
| ASTLeaf | 单个 Token | 无 | NumberLiteral, Name |

## 表达式节点 vs 语句节点

| 类别 | 特点 | 节点类型 |
|------|------|---------|
| 表达式节点 | 有返回值 | NumberLiteral, StringLiteral, Name, BinaryExpr, PrimaryExpr, NegativeExpr |
| 语句节点 | 无返回值（返回 null） | IfStmnt, WhileStmnt, BlockStmnt, NullStmnt |

<Callout type="info">

表达式节点求值后返回计算值（Integer/String/Object），语句节点求值后执行副作用（如变量赋值）并返回 null。

</Callout>

## AST 示例：`(3 + 4) * 5`

```text
        BinaryExpr(*)
         /        \
   BinaryExpr(+)   Number(5)
    /      \
Number(3) Number(4)
```

- 根节点 `BinaryExpr(*)` 持有三个子节点：左操作数、运算符 Token、右操作数
- 左子树 `BinaryExpr(+)` 反映了括号的优先级——先于 `*` 被求值
- 叶子节点 `NumberLiteral` 继承自 `ASTLeaf`，持有一个 INT Token

## 访问者模式

AST 使用**访问者模式**（Visitor Pattern）实现节点遍历，核心是**双重分派**：

### 双重分派机制

```java
// ① ASTNode 子类的 accept 方法（第一次分派）
class BinaryExpr extends ASTList {
    public Object accept(Visitor v) {
        return v.visit(this);  // this 的动态类型 = BinaryExpr
    }
}

// ② Visitor 接口的重载方法（第二次分派）
interface Visitor {
    Object visit(NumberLiteral n);  // 处理整数节点
    Object visit(BinaryExpr b);     // 处理二元运算节点
    Object visit(IfStmnt i);        // 处理 if 语句
    // ... 每种节点一个重载
}
```

<Callout type="warning">

**为什么需要双重分派？** Java 是单分派语言——`v.visit(node)` 只根据 v 的类型选择方法，不根据 node 的运行时类型选择重载。通过在 `accept` 中调用 `v.visit(this)`，`this` 的编译时类型已确定为具体子类，编译器能选择正确的重载方法。

</Callout>

### 访问者的优势

| 优势 | 说明 |
|------|------|
| 解耦节点与操作 | 新增操作只需新增 Visitor，无需修改节点类 |
| 集中处理逻辑 | 同类操作（如求值）集中在同一 Visitor 中 |
| 类型安全 | 编译器检查每种节点是否都有对应处理 |

<Glossary>

<GlossaryItem term="ASTNode">
所有 AST 节点的抽象基类，定义统一的接口（如 location、toString、accept），是前端与后端的接口。
</GlossaryItem>

<GlossaryItem term="ASTList / ASTLeaf">
ASTList 是列表容器节点，持有多个子节点（如 BinaryExpr 持有左操作数、运算符、右操作数）；ASTLeaf 是叶子节点，持有一个 Token（如 NumberLiteral）。
</GlossaryItem>

<GlossaryItem term="访问者模式（Visitor Pattern）">
一种设计模式，将数据结构与操作解耦。在 AST 中用于实现节点遍历——每种节点类型对应一个 visit 重载方法。
</GlossaryItem>

<GlossaryItem term="双重分派（Double Dispatch）">
通过两次方法调用（accept 调用 visit，visit 根据 this 类型选择重载）实现根据两个对象的运行时类型选择方法。弥补 Java 单分派的不足。
</GlossaryItem>

</Glossary>

<Exercises>

### 问题 1

抽象语法树的作用是什么？Stone 中 AST 的两个基本类是什么？

<Answer>

AST 的作用是将以线性序列组织的 Token 转化为反映语法结构的树形数据结构，是前端与后端之间的数据桥梁。Stone 中 AST 的两个基本类：ASTList（列表容器，持有多个子节点）和 ASTLeaf（叶子节点，持有一个 Token）。所有 AST 节点都继承自抽象基类 ASTNode，ASTNode 提供统一的接口（如 location、toString、accept）。

</Answer>

### 问题 2

Stone 的 AST 节点分为哪两大类？各包含哪些具体节点类型？

<Answer>

两大类：①表达式节点（Expression）—— 有返回值，包括 NumberLiteral、StringLiteral、Name、BinaryExpr、PrimaryExpr、NegativeExpr ②语句节点（Statement）—— 无返回值（返回 null），包括 IfStmnt、WhileStmnt、BlockStmnt、NullStmnt。表达式节点和语句节点都继承自 ASTList。

</Answer>

### 问题 3

访问者模式在 AST 中如何实现双重分派？为什么需要双重分派？

<Answer>

双重分派实现：①ASTNode 子类实现 accept(Visitor v) 方法，方法体内调用 v.visit(this)——这是第一次分派（根据 this 的运行时类型选择正确的 accept）②Visitor 接口为每种 AST 节点类型定义重载的 visit 方法，v.visit(this) 时编译器根据 this 的静态类型选择重载——但由于在 accept 中 this 的动态类型已确定，所以能调用正确的 visit 重载——这是第二次分派。需要双重分派是因为 Java 是单分派语言（只根据接收者类型分派，不根据参数类型分派），单次调用 v.visit(node) 无法根据 node 的实际类型选择重载。

</Answer>

### 问题 4

表达式 `(3 + 4) * 5` 的 AST 结构是什么样的？

<Answer>

AST 结构：根节点 BinaryExpr(运算符 `*`)，左子树 BinaryExpr(运算符 `+`)，右子树 NumberLiteral(5)。左子树 BinaryExpr(+) 的左子树是 NumberLiteral(3)，右子树是 NumberLiteral(4)。树形结构反映了运算优先级：括号内的 `3 + 4` 被组织为 `*` 的左子树，先于 `*` 被求值。BinaryExpr 节点持有三个子节点：左操作数、运算符 Token、右操作数。

</Answer>
