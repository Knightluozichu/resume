## 函数定义与调用

```text
定义: def add(x, y) { x + y }
调用: add(3, 4)   →  返回 7
```

<TwsFunctionsDiagram />

## Function 对象

函数定义时创建一个 **Function 对象**，包含三个核心信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| parameters | List`<String>` | 形参名列表 |
| body | BlockStmnt | 函数体 AST |
| env | Environment | **定义时的环境**（闭包关键） |

<Callout type="info">

Function 对象持有的 `env` 是**定义时的环境**，不是调用时的环境。这是实现闭包的关键。

</Callout>

## 函数调用过程

```text
调用 add(3, 4):

步骤 1: 创建新环境 E_new
        E_new: { }
步骤 2: E_new.outer = function.env  ← 指向定义环境，不是调用环境
步骤 3: 绑定参数到 E_new
        E_new: { x=3, y=4 }
步骤 4: 在 E_new 中求值函数体 { x + y }
        → env.get("x")=3, env.get("y")=4 → 3+4=7
步骤 5: 返回 7
```

### 环境链示意

```text
  E_new (调用环境): { x=3, y=4 }
       ↓ outer
  function.env (定义环境): { add=Function, ... }
       ↓ outer
  全局环境: { ... }
```

<Callout type="warning">

**关键**：新环境的 outer 指向**定义环境**而非调用环境。这保证了函数内部能访问定义时可见的变量，但不能访问调用者的局部变量——这是**词法作用域**的核心。

</Callout>

## 闭包：函数 + 环境

闭包 = 函数体 + 定义时的环境引用。Function 对象持有 env 引用，即使定义环境的外层调用已返回，环境仍被函数对象引用而存活。

### counter 示例

```text
def counter(n) {
    def inc() { n = n + 1; n }
    inc
}

c = counter(0)
c()  // → 1
c()  // → 2
```

### 闭包执行过程

```text
1. counter(0) 创建环境 E1: { n=0, outer=全局 }
2. inc 的 Function 对象捕获 E1 作为 env
3. 返回 inc，E1 被 inc 引用而存活

4. 第一次 c():
   创建 E2: { outer=E1 }
   执行 n = n + 1:
     get(n) → E2 没有 → E1 找到 n=0
     put(n) → 写入 E1: n=1
   返回 n → 1

5. 第二次 c():
   创建 E3: { outer=E1 }
   执行 n = n + 1:
     get(n) → E3 没有 → E1 找到 n=1
     put(n) → 写入 E1: n=2
   返回 n → 2
```

<Callout type="tip">

闭包让 `inc` 「记住」了 E1 中的 `n`。每次调用都修改同一个 E1 中的 n，实现状态持久化。

</Callout>

## 引用 vs 值拷贝

Function 对象的 env 字段存储的是 Environment 对象的**引用**（Java 引用语义），而非变量值的快照拷贝。

| 方式 | 行为 | counter 结果 |
|------|------|-------------|
| 引用（Stone 采用） | 闭包内修改写入原环境 | c()→1, c()→2 |
| 值拷贝 | 闭包只看到定义时的快照 | c()→1, c()→1 |

引用方式让多个闭包可以**共享同一外层变量**，实现状态共享。

<Glossary>

<GlossaryItem term="Function 对象">
Stone 中表示函数的运行时对象，包含参数列表（parameters）、函数体 AST（body）和定义时的环境引用（env）三要素。
</GlossaryItem>

<GlossaryItem term="闭包（Closure）">
函数体 + 定义时的环境引用。闭包让函数「记住」定义时可见的变量，即使定义环境的外层调用已返回，环境仍被函数对象引用而存活。
</GlossaryItem>

<GlossaryItem term="词法作用域（Lexical Scope）">
变量的可见性由代码书写位置决定。函数调用时新环境的 outer 指向定义环境而非调用环境，保证函数只能访问定义时可见的变量。
</GlossaryItem>

<GlossaryItem term="环境捕获">
Function 对象持有定义时环境的引用，使环境在定义环境的外层调用返回后仍能存活。这是闭包能访问外层变量的底层机制。
</GlossaryItem>

</Glossary>

<Exercises>

### 问题 1

Stone 中如何定义和调用函数？Function 对象包含哪些信息？

<Answer>

定义函数用 def 语句：`def add(x, y) { x + y }`。调用函数用 `add(3, 4)` 语法。Function 对象包含三个核心信息：①parameters（参数列表）②body（函数体 AST）③env（定义时的环境引用）。函数定义时创建 Function 对象并绑定到函数名变量，调用时利用这些信息创建新环境并执行函数体。

</Answer>

### 问题 2

函数调用的完整过程是什么？新环境的 outer 指向哪里？

<Answer>

函数调用过程：①创建新的 Environment 对象 ②将新环境的 outer 指向函数定义时捕获的 env（不是调用者的环境，而是定义环境）③将实参值绑定到形参名，写入新环境 ④在新环境中递归求值函数体 ⑤返回函数体最后一条语句的求值结果。关键：outer 指向定义环境而非调用环境，这保证了函数内部能访问定义时可见的变量，但不能访问调用者局部变量——这是词法作用域的核心。

</Answer>

### 问题 3

什么是闭包？以 counter 示例说明闭包如何让内层函数修改外层变量。

<Answer>

闭包 = 函数体 + 定义时的环境引用。Function 对象持有定义时的 env，即使定义环境的外层调用已返回，环境仍被函数对象引用而存活。以 counter 为例：调用 counter(0) 创建环境 E1(n=0)，inc 的 Function 对象捕获 E1 作为 env。之后调用 c() 时创建新环境 E2(outer=E1)，执行 `n = n + 1`——get(n) 沿 E2→E1 找到 n=0，put(n) 写入 E1 使 n=1。第二次调用 c() 时 n 已是 1，返回 2。闭包让 inc「记住」了 E1 中的 n。

</Answer>

### 问题 4

为什么说闭包捕获的是环境引用而非值的拷贝？这有什么实际意义？

<Answer>

Function 对象的 env 字段存储的是 Environment 对象的引用（Java 引用语义），而非变量值的快照拷贝。这意味着闭包内对变量的修改（put 操作）会直接写入被引用的环境，影响同一环境中所有共享该变量的闭包。实际意义：①多个闭包可以共享同一外层变量，实现状态共享（如 counter 示例中 inc 每次调用都修改同一个 n）②闭包能感知外层变量的后续修改。如果是值拷贝，则闭包只能看到定义时的快照，无法实现状态共享和修改。

</Answer>
