## 直觉引入

会用 Unity 做出能跑的游戏，和能主导一个商业级 Unity 项目，中间隔着一整条能力链。普通开发者关心「功能怎么实现」，主程关心「架构怎么扛住需求膨胀、性能怎么扛住机型碎片、团队怎么扛住版本迭代」。

这本书把「进阶主程」拆成十章：先用架构和设计模式搭骨架，再用内存与渲染优化补肌肉，接着用 UI 框架和网络同步打通系统级能力，最后用热更新和 CI/CD 完成工程化闭环。每章解决一个主程必答问题。

## 概念讲解

全书分四个阶段：**架构**（设计原则与模式）、**性能**（内存与渲染）、**系统**（UI 与网络）、**工程**（热更新与 CI/CD）。

<Term def="将项目按职责分层，控制依赖方向，避免循环引用">架构设计</Term>是主程的第一职责。<Term def="管理托管堆与原生内存，消除 GC 卡顿">内存管理</Term>决定帧率稳定性。<Term def="在带宽受限网络下保持多端一致性">网络同步</Term>是联机游戏的命脉。<Term def="不重新发版即可修复 Bug 和推送内容">热更新</Term>是线上运营的基础设施。

### 阶段依赖
- 架构 → 性能：先有清晰结构，才能定位和优化瓶颈
- 性能 → 系统：性能基线稳定后，才能叠加 UI 和网络复杂度
- 系统 → 工程：系统成型后，才需要热更新和持续集成支撑迭代

### 学习节奏建议
- 第 1 章通读全图，建立主程能力全局观
- 第 2-5 章是架构与性能，决定项目上限
- 第 6-9 章是系统与工程，决定项目下限
- 第 10 章串联全书，做综合架构评审

## 代码对照

```csharp
// Unity C#: 主程核心能力路径概览
// 1. 架构: 分层 + 依赖注入
public class EnemySpawner {
    private readonly IEnemyFactory _factory; // 注入，不 new
    public EnemySpawner(IEnemyFactory factory) => _factory = factory;
}

// 2. 性能: 对象池消除 GC
var enemy = _pool.Get();
enemy.Activate();
// ... 使用 ...
_pool.Release(enemy); // 回收，不 Destroy

// 3. 渲染: SRP Batcher + GPU Instancing
GraphicsSettings.useScriptableRenderPipelineBatching = true;

// 4. 网络: 状态同步插值
transform.position = Vector3.Lerp(transform.position, _targetPos, Time.deltaTime * 10f);

// 5. 热更新: xLua 加载补丁
LuaEnv lua = new LuaEnv();
lua.DoString("require 'hotfix_patch'");

// 6. CI/CD: 命令行构建
BuildPipeline.BuildPlayer(scenes, outPath, BuildTarget.Android, BuildOptions.None);
```

## 常见误区

<Callout type="trap">
**现象 →** 功能写得很溜，但一接手中型项目就手忙脚乱。
**原因 →** 只学了「怎么用 Unity」，没学「怎么管 Unity 项目」。把功能点当成了能力，缺架构和工程视角。
**修法 →** 先建主程全局观：架构→性能→系统→工程。按这四阶段补能力，每阶段解决一类主程必答问题。
</Callout>
<Callout type="trap">
**现象 →** 项目越做越慢，加个功能要改十几个脚本。
**原因 →** 没有架构分层，模块间循环依赖，牵一发动全身。
**修法 →** 回到第 2 章架构设计：分层 + 模块化 + 依赖注入。先理清依赖方向，再重构热点模块。
</Callout>

## 练习

<Exercises>
**问题**：全书四个阶段分别解决什么问题？如果团队只有一人补能力，应优先哪个阶段？

<Answer>
架构（设计原则与模式）解决代码可维护性；性能（内存与渲染）解决运行稳定性；系统（UI 与网络）解决功能复杂度；工程（热更新与 CI/CD）解决迭代安全性。一人优先补架构——架构决定代码能否长期演进，是其余一切的地基。
</Answer>

**问题**：主程和普通开发者的核心区别是什么？用全书章节举例。

<Answer>
普通开发者关心「功能怎么做」，主程关心「项目怎么扛」。例如：普通开发者用 new 创建敌人，主程用对象池管生命周期（第 4 章）；普通开发者把逻辑写在 MonoBehaviour，主程分层到 Service/Domain（第 2 章）；普通开发者手动出包，主程搭 CI/CD 流水线（第 9 章）。主程价值在跨系统决策，不在单点功能。
</Answer>
</Exercises>
