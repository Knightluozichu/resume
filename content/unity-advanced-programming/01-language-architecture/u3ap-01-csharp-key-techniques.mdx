## 可复现实验

对相同数据分别使用预分配 List、逐步扩容 List 和装箱接口，固定运行次数并记录容量、分配与耗时；再用临界浮点值验证相等判断和排序顺序。

最小实现只暴露本章关键状态，不把因果藏进通用框架。

```csharp
using System;
using System.Collections.Generic;

static bool NearlyEqual(float a, float b, float epsilon)
{
    return Math.Abs(a - b) <= epsilon * Math.Max(1f, Math.Max(Math.Abs(a), Math.Abs(b)));
}

var values = new List<int>(capacity: 4096);
```

统一证据契约把结构、版本和故障计划放在同一结果中。

```ts
type LeadProgramEvidence = {
  chapter: "u3ap-01-csharp-key-techniques";
  runtimeVersion: string;
  sample: "baseline" | "boundary" | "failure";
  stages: readonly string[];
  firstDeviation: string | null;
  decision: "pass" | "rejected";
};

function canRelease(run: LeadProgramEvidence): boolean {
  return run.stages.length === 6 &&
    (run.sample !== "failure" || run.decision === "rejected");
}
```

证据日志至少保留下列字段，并与捕获文件使用同一运行编号。

```text
stage,name,sample,input,observation,result
1,声明数据规模,baseline,planned,observed,pass
2,读取源码路径,baseline,planned,observed,pass
3,建立成本模型,baseline,planned,observed,pass
4,构造边界输入,baseline,planned,observed,pass
5,采集分配耗时,baseline,planned,observed,pass
6,签发语言约束,baseline,planned,observed,pass
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部结论没有运行证据">
  只背复杂度结论，不检查 Unity 运行时版本、容量变化、哈希冲突和 GC 分配，微基准与真实热路径完全脱节。必须保存故障版本和首个偏离节点，再用相同输入验证修复。
</Callout>

<Callout type="trap" title="指标改善但系统边界退化">
  故意让一个平均指标变好，同时删除版本、长尾、内存、协议、画质或交接证据。只要“相同数据规模和运行时配置下，性能结论可复现，且所有浮点边界与集合容量变化都有明确证据。”不成立，即使演示成功也必须拒绝。
</Callout>

**问题 1** 第1章覆盖哪些原连载主题？选择三个写出因果链。

<Answer>
  本页覆盖 List 底层源码剖析、Dictionary 底层源码剖析、浮点数的精度问题、委托、事件、装箱、拆箱、排序算法、搜索算法。合格答案要沿“声明数据规模 → 读取源码路径 → 建立成本模型 → 构造边界输入 → 采集分配耗时 → 签发语言约束”写清上游输入、中间状态和下游证据，不能只复述标题。
</Answer>

**问题 2** 怎样制造“只背复杂度结论，不检查 Unity 运行时版本、容量变化、哈希冲突和 GC 分配，微基准与真实热路径完全脱节。”并证明修复有效？

<Answer>
  固定运行时版本、平台、数据规模和输入，只注入该故障；保存首个偏离节点。修复后用相同条件复测正常、边界和失败组，并确认门禁从拒绝恢复为通过。
</Answer>

**问题 3** 为什么“相同数据规模和运行时配置下，性能结论可复现，且所有浮点边界与集合容量变化都有明确证据。”是第1章的签发不变量？

<Answer>
  因为主程交付的是可演进系统，不是一次演示。缺少该不变量时，局部指标可能改善，却会把成本转移到其他模块、平台、团队或线上故障。
</Answer>
