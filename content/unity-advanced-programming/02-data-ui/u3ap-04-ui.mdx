## 可复现实验

建立静态背景、滚动列表和频繁更新计数器三层 UI，先预测一次文本变化会重建哪些 Canvas，再调整拆分边界并比较批次、布局和长尾帧。

最小实现只暴露本章关键状态，不把因果藏进通用框架。

```csharp
public interface IViewState<in T>
{
    void Render(T state);
}

public sealed class InventoryPresenter
{
    public event Action<int>? ItemSelected;
    public void Select(int id) => ItemSelected?.Invoke(id);
}
```

统一证据契约把结构、版本和故障计划放在同一结果中。

```ts
type LeadProgramEvidence = {
  chapter: "u3ap-04-ui";
  runtimeVersion: string;
  sample: "baseline" | "boundary" | "failure";
  stages: readonly string[];
  firstDeviation: string | null;
  decision: "pass" | "rejected";
};

function canRelease(run: LeadProgramEvidence): boolean {
  return run.stages.length === 6 &&
    (run.sample !== "failure" || run.decision === "rejected");
}
```

证据日志至少保留下列字段，并与捕获文件使用同一运行编号。

```text
stage,name,sample,input,observation,result
1,选择 UI 栈,baseline,planned,observed,pass
2,追踪输入,baseline,planned,observed,pass
3,更新页面状态,baseline,planned,observed,pass
4,触发重建,baseline,planned,observed,pass
5,采集批次帧时,baseline,planned,observed,pass
6,验证页面生命周期,baseline,planned,observed,pass
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部结论没有运行证据">
  每个按钮直接访问全局业务单例，所有元素放在同一个 Canvas，任何小更新都触发整页重建。必须保存故障版本和首个偏离节点，再用相同输入验证修复。
</Callout>

<Callout type="trap" title="指标改善但系统边界退化">
  故意让一个平均指标变好，同时删除版本、长尾、内存、协议、画质或交接证据。只要“一次输入只产生一个业务命令，页面退出后无残留订阅，动态更新只影响声明的 Canvas 边界。”不成立，即使演示成功也必须拒绝。
</Callout>

**问题 1** 第4章覆盖哪些原连载主题？选择三个写出因果链。

<Answer>
  本页覆盖 NGUI 和 UGUI 比较、UGUI 原理及组件使用、UGUI 输入与事件模块、UGUI 核心源码、UI 框架架构、UI 优化一、UI 优化二、UI 优化三。合格答案要沿“选择 UI 栈 → 追踪输入 → 更新页面状态 → 触发重建 → 采集批次帧时 → 验证页面生命周期”写清上游输入、中间状态和下游证据，不能只复述标题。
</Answer>

**问题 2** 怎样制造“每个按钮直接访问全局业务单例，所有元素放在同一个 Canvas，任何小更新都触发整页重建。”并证明修复有效？

<Answer>
  固定运行时版本、平台、数据规模和输入，只注入该故障；保存首个偏离节点。修复后用相同条件复测正常、边界和失败组，并确认门禁从拒绝恢复为通过。
</Answer>

**问题 3** 为什么“一次输入只产生一个业务命令，页面退出后无残留订阅，动态更新只影响声明的 Canvas 边界。”是第4章的签发不变量？

<Answer>
