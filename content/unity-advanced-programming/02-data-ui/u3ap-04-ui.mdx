## 为什么从这个问题开始

第4章 UI围绕“NGUI和早期uGUI的历史问题怎样迁移到Unity 6.3的uGUI、UI Toolkit与可测生命周期？”建立贯穿任务：在同一Player、分辨率和交互脚本下比较页面创建、事件路由、重建与关闭清理。第4章 UI先冻结来源、版本和Player环境，再记录真实对象与透明预算，最后用单故障和同输入恢复验收；只有守住“输入只路由一次，页面状态可恢复，关闭后无回调和资源残留，目标Player预算满足”并交付UI系统选择记录、事件路径、页面状态机、重建捕获、订阅与释放清单，旧文章标题或一次顺利运行才可能升级为可复核证据。

## 最小可重现实验协议

1. 第4章 UI先冻结Unity编辑器、包版本、脚本后端、渲染管线、平台、Player构建、设备、系统、图形API、分辨率、质量级别、输入数据和预期结果。
2. 第4章 UI在目标Player上运行参考路径，保存UI系统选择记录、事件路径、页面状态机、重建捕获、订阅与释放清单；基线状态或帧捕获不稳定时先停止，不用平均值和综合分掩盖波动。
3. 第4章 UI保持其余条件不变，只注入“重复订阅事件、把所有元素放在同一重建边界或用Editor帧率签发优化”，记录首个状态、资源、协议、渲染或路径分岔以及停止条件。
4. 第4章 UI撤销唯一故障，清理句柄、订阅、缓存、连接和场景状态，以同一输入重放；不能恢复“输入只路由一次，页面状态可恢复，关闭后无回调和资源残留，目标Player预算满足”就拒绝发布。
