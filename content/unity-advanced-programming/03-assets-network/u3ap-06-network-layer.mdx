## 可复现实验

用同一移动命令经过 TCP 流和 UDP 数据报传输，固定种子注入延迟、丢包、乱序和重复。先预测客户端状态，再检查协议解析与服务器校正轨迹。

最小实现只暴露本章关键状态，不把因果藏进通用框架。

```csharp
public readonly record struct PacketHeader(
    ushort Version, ushort Type, uint Sequence, int PayloadLength);

static bool IsValid(PacketHeader h, int available)
{
    return h.Version == 1 && h.PayloadLength >= 0 && h.PayloadLength <= available;
}
```

统一证据契约把结构、版本和故障计划放在同一结果中。

```ts
type LeadProgramEvidence = {
  chapter: "u3ap-06-network-layer";
  runtimeVersion: string;
  sample: "baseline" | "boundary" | "failure";
  stages: readonly string[];
  firstDeviation: string | null;
  decision: "pass" | "rejected";
};

function canRelease(run: LeadProgramEvidence): boolean {
  return run.stages.length === 6 &&
    (run.sample !== "failure" || run.decision === "rejected");
}
```

证据日志至少保留下列字段，并与捕获文件使用同一运行编号。

```text
stage,name,sample,input,observation,result
1,声明消息语义,baseline,planned,observed,pass
2,选择传输,baseline,planned,observed,pass
3,编码协议帧,baseline,planned,observed,pass
4,注入网络故障,baseline,planned,observed,pass
5,重建权威状态,baseline,planned,observed,pass
6,统计延迟一致性,baseline,planned,observed,pass
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部结论没有运行证据">
  假设一次 Receive 就是一条完整消息，或把 UDP 当成更快的 TCP，没有序号、确认、重放保护和超时策略。必须保存故障版本和首个偏离节点，再用相同输入验证修复。
</Callout>

<Callout type="trap" title="指标改善但系统边界退化">
  故意让一个平均指标变好，同时删除版本、长尾、内存、协议、画质或交接证据。只要“相同命令序列和故障计划能重放出相同协议轨迹，非法帧被拒绝，最终状态收敛到声明的权威。”不成立，即使演示成功也必须拒绝。
</Callout>

**问题 1** 第6章覆盖哪些原连载主题？选择三个写出因果链。

<Answer>
  本页覆盖 TCP 还是 UDP、实现 TCP、实现 UDP、封装 HTTP、数据协议原理、网络同步解决方案。合格答案要沿“声明消息语义 → 选择传输 → 编码协议帧 → 注入网络故障 → 重建权威状态 → 统计延迟一致性”写清上游输入、中间状态和下游证据，不能只复述标题。
</Answer>

**问题 2** 怎样制造“假设一次 Receive 就是一条完整消息，或把 UDP 当成更快的 TCP，没有序号、确认、重放保护和超时策略。”并证明修复有效？

<Answer>
  固定运行时版本、平台、数据规模和输入，只注入该故障；保存首个偏离节点。修复后用相同条件复测正常、边界和失败组，并确认门禁从拒绝恢复为通过。
</Answer>

**问题 3** 为什么“相同命令序列和故障计划能重放出相同协议轨迹，非法帧被拒绝，最终状态收敛到声明的权威。”是第6章的签发不变量？

<Answer>
  因为主程交付的是可演进系统，不是一次演示。缺少该不变量时，局部指标可能改善，却会把成本转移到其他模块、平台、团队或线上故障。
</Answer>
