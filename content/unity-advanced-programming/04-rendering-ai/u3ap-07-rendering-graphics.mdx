## 可复现实验

构建包含重复网格、透明物体、MSAA 和 Projector 的固定场景，在同一设备比较无批处理、实例化与 SRP Batcher。先预测瓶颈，再保存 Frame Debugger 与 GPU 捕获。

最小实现只暴露本章关键状态，不把因果藏进通用框架。

```csharp
public readonly record struct RenderBudget(
    float CpuMs, float GpuMs, int DrawCalls, long MemoryBytes);

static bool Pass(RenderBudget value, RenderBudget limit)
{
    return value.CpuMs <= limit.CpuMs && value.GpuMs <= limit.GpuMs
        && value.DrawCalls <= limit.DrawCalls && value.MemoryBytes <= limit.MemoryBytes;
}
```

统一证据契约把结构、版本和故障计划放在同一结果中。

```ts
type LeadProgramEvidence = {
  chapter: "u3ap-07-rendering-graphics";
  runtimeVersion: string;
  sample: "baseline" | "boundary" | "failure";
  stages: readonly string[];
  firstDeviation: string | null;
  decision: "pass" | "rejected";
};

function canRelease(run: LeadProgramEvidence): boolean {
  return run.stages.length === 6 &&
    (run.sample !== "failure" || run.decision === "rejected");
}
```

证据日志至少保留下列字段，并与捕获文件使用同一运行编号。

```text
stage,name,sample,input,observation,result
1,锁定画面场景,baseline,planned,observed,pass
2,捕获管线阶段,baseline,planned,observed,pass
3,定位限制端,baseline,planned,observed,pass
4,修改一种策略,baseline,planned,observed,pass
5,复测变体画质,baseline,planned,observed,pass
6,签发设备预算,baseline,planned,observed,pass
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部结论没有运行证据">
  只统计 Draw Call，启用所有合批和 Shader 关键字，结果 CPU 指标变好但显存、变体、透明排序或 GPU 长尾恶化。必须保存故障版本和首个偏离节点，再用相同输入验证修复。
</Callout>

<Callout type="trap" title="指标改善但系统边界退化">
  故意让一个平均指标变好，同时删除版本、长尾、内存、协议、画质或交接证据。只要“同一设备、相机路径和画质设置下，优化后的 CPU、GPU、显存、变体与截图门同时通过。”不成立，即使演示成功也必须拒绝。
</Callout>
