## 核心模型与技术边界

AI 章节依次比较有限状态机、行为树和非典型方案。结构选择取决于行为数量、并发性、可中断性和调试要求；主程要让感知、决策和动作可回放，而不是用随机表现掩盖不可解释状态。

连载写作年代与今天的 Unity、.NET 后端和渲染管线存在差异。复现时保留作者要解释的机制，同时记录旧 API、当前替代路径、运行时版本和验证结果。没有版本映射的“更新版结论”不能覆盖原文章，也不能把今天的默认行为倒推成当年的事实。

## 可复现实验

用状态机和行为树各实现巡逻、发现、追逐、失去目标和返回。固定感知时间线，先预测状态或节点轨迹，再注入目标消失与高优先级中断。

最小实现只暴露本章关键状态，不把因果藏进通用框架。

```csharp
public interface IBehaviourNode
{
    NodeStatus Tick(in WorldFacts facts);
}

public enum NodeStatus { Running, Success, Failure }
public readonly record struct WorldFacts(bool SeesTarget, float Distance);
```

统一证据契约把结构、版本和故障计划放在同一结果中。

```ts
type LeadProgramEvidence = {
  chapter: "u3ap-08-ai";
  runtimeVersion: string;
  sample: "baseline" | "boundary" | "failure";
  stages: readonly string[];
  firstDeviation: string | null;
  decision: "pass" | "rejected";
};

function canRelease(run: LeadProgramEvidence): boolean {
  return run.stages.length === 6 &&
    (run.sample !== "failure" || run.decision === "rejected");
}
```

证据日志至少保留下列字段，并与捕获文件使用同一运行编号。

```text
stage,name,sample,input,observation,result
1,固定感知,baseline,planned,observed,pass
2,运行决策,baseline,planned,observed,pass
3,选择动作,baseline,planned,observed,pass
4,处理中断,baseline,planned,observed,pass
5,记录轨迹,baseline,planned,observed,pass
6,复验行为目标,baseline,planned,observed,pass
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部结论没有运行证据">
  感知、决策和动作都在 Update 中直接修改共享字段，行为偶尔正确却无法解释是谁覆盖了命令。必须保存故障版本和首个偏离节点，再用相同输入验证修复。
</Callout>

<Callout type="trap" title="指标改善但系统边界退化">
  故意让一个平均指标变好，同时删除版本、长尾、内存、协议、画质或交接证据。只要“固定感知时间线能复现相同决策与动作轨迹，中断后系统回到声明的合法状态。”不成立，即使演示成功也必须拒绝。
</Callout>

## 练习

<Exercises>

**问题 1** 第8章覆盖哪些原连载主题？选择三个写出因果链。

<Answer>
  本页覆盖 状态机构架机器人行为、行为树构建 AI、非典型性 AI、感知输入、决策轨迹、动作仲裁。合格答案要沿“固定感知 → 运行决策 → 选择动作 → 处理中断 → 记录轨迹 → 复验行为目标”写清上游输入、中间状态和下游证据，不能只复述标题。
</Answer>

**问题 2** 怎样制造“感知、决策和动作都在 Update 中直接修改共享字段，行为偶尔正确却无法解释是谁覆盖了命令。”并证明修复有效？

<Answer>
  固定运行时版本、平台、数据规模和输入，只注入该故障；保存首个偏离节点。修复后用相同条件复测正常、边界和失败组，并确认门禁从拒绝恢复为通过。
</Answer>

**问题 3** 为什么“固定感知时间线能复现相同决策与动作轨迹，中断后系统回到声明的合法状态。”是第8章的签发不变量？

<Answer>
  因为主程交付的是可演进系统，不是一次演示。缺少该不变量时，局部指标可能改善，却会把成本转移到其他模块、平台、团队或线上故障。
</Answer>

</Exercises>
