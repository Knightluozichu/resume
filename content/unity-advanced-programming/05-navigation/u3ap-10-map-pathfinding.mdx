## 可复现实验

建立窄门、斜坡、动态障碍和不可达岛四类地图，固定代理半径与启发函数。先预测路径，再比较网格构建、搜索节点数、路径长度和失败原因。

最小实现只暴露本章关键状态，不把因果藏进通用框架。

```csharp
public readonly record struct PathRequest(int Start, int Goal, int MapVersion);

static float Priority(float cost, float heuristic) => cost + heuristic;

// 开放集按 Priority 排序；只有得到更低 cost 时才更新父节点。
```

统一证据契约把结构、版本和故障计划放在同一结果中。

```ts
type LeadProgramEvidence = {
  chapter: "u3ap-10-map-pathfinding";
  runtimeVersion: string;
  sample: "baseline" | "boundary" | "failure";
  stages: readonly string[];
  firstDeviation: string | null;
  decision: "pass" | "rejected";
};

function canRelease(run: LeadProgramEvidence): boolean {
  return run.stages.length === 6 &&
    (run.sample !== "failure" || run.decision === "rejected");
}
```

证据日志至少保留下列字段，并与捕获文件使用同一运行编号。

```text
stage,name,sample,input,observation,result
1,生成地图数据,baseline,planned,observed,pass
2,构建导航,baseline,planned,observed,pass
3,提交起终点,baseline,planned,observed,pass
4,运行 A*,baseline,planned,observed,pass
5,平滑与避障,baseline,planned,observed,pass
6,编辑器回归,baseline,planned,observed,pass
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部结论没有运行证据">
  只在空旷地图验证 A*，地图编辑器允许非法连接，角色半径和动态障碍没有进入导航数据。必须保存故障版本和首个偏离节点，再用相同输入验证修复。
</Callout>

<Callout type="trap" title="指标改善但系统边界退化">
  故意让一个平均指标变好，同时删除版本、长尾、内存、协议、画质或交接证据。只要“相同地图版本、代理参数和起终点得到相同路径或明确失败原因，编辑器在导出前拒绝非法拓扑。”不成立，即使演示成功也必须拒绝。
</Callout>

<Exercises>

**问题 1** 第10章覆盖哪些原连载主题？选择三个写出因果链。

<Answer>
  本页覆盖 A* 算法及优化、寻路网格的构建、地图编辑器、地图的制作与优化、动态障碍、路径验收。合格答案要沿“生成地图数据 → 构建导航 → 提交起终点 → 运行 A* → 平滑与避障 → 编辑器回归”写清上游输入、中间状态和下游证据，不能只复述标题。
</Answer>

**问题 2** 怎样制造“只在空旷地图验证 A*，地图编辑器允许非法连接，角色半径和动态障碍没有进入导航数据。”并证明修复有效？

<Answer>
  固定运行时版本、平台、数据规模和输入，只注入该故障；保存首个偏离节点。修复后用相同条件复测正常、边界和失败组，并确认门禁从拒绝恢复为通过。
</Answer>

**问题 3** 为什么“相同地图版本、代理参数和起终点得到相同路径或明确失败原因，编辑器在导出前拒绝非法拓扑。”是第10章的签发不变量？

<Answer>
  因为主程交付的是可演进系统，不是一次演示。缺少该不变量时，局部指标可能改善，却会把成本转移到其他模块、平台、团队或线上故障。
</Answer>
