## 直觉引入

游戏角色怎么动起来的？简单说三步：美术做动作数据（AnimationClip），控制器决定什么时候播什么动作（Animator Controller），执行器驱动骨骼播放（Animator）。进阶加上 IK（脚贴地面）、Timeline（过场动画）、动画事件（关键帧触发逻辑）、程序化动画（代码驱动骨骼）。全书从基础到进阶，逐步构建完整的动画系统认知。

## 概念讲解

### 全书结构

<UanLearningMapDiagram />

<Term def="AnimationClip是Unity的动画数据资产，存储骨骼关键帧、曲线和事件，是动画系统的数据基础">AnimationClip</Term>是动画数据。

<Term def="Animator Controller是管理动画状态和转换的资产，用状态机控制AnimationClip的播放、混合和切换">Animator Controller</Term>是动画逻辑。

<Term def="Animator是挂载在GameObject上的组件，执行Animator Controller的指令，驱动骨骼播放动画">Animator</Term>是动画执行器。

<Term def="Blend Tree是Animator中混合多个AnimationClip的节点，按参数(如速度/方向)平滑混合动画">Blend Tree</Term>是动画混合器。

全书分四大板块：动画基础（Clip/原理）→ Animator 核心（控制器/状态机/混合树）→ 进阶技术（IK/Timeline/事件）→ 程序化与总结（程序化动画/复习）。

## 交互Demo

<Stepper>
<Step title="第一步：动画基础">AnimationClip 存储关键帧数据——每一帧记录骨骼的位置/旋转/缩放。播放时在关键帧间插值生成平滑动画。理解关键帧、曲线、采样率是动画基础。</Step>
<Step title="第二步：Animator 核心">
Animator Controller 管理状态机——每个 State 绑定一个 AnimationClip，Transition 定义状态间的切换条件（参数变化/时间/退出条件）。Blend Tree 按参数混合多个 Clip（如速度0~1 混合 Idle~Run）。
<UanLearningMapDiagram />
</Step>
<Step title="第三步：进阶与程序化">IK 系统做脚部贴合地面和手部抓取，Timeline 做过场动画编排，Animation Event 在动画关键帧触发逻辑（音效/特效/伤害），程序化动画用代码实时驱动骨骼（布娃娃/呼吸/注视）。</Step>
</Stepper>

## 代码对照

```csharp
// Animator 参数控制
Animator animator;
void Update() {
    float speed = _rb.velocity.magnitude;
    animator.SetFloat("Speed", speed); // 驱动 Blend Tree

    if (Input.GetButtonDown("Jump")) {
        animator.SetTrigger("Jump"); // 触发跳跃状态
    }
}

// 动画事件
public void OnAttackHit() {
    // 在攻击动画的关键帧调用
    Collider[] enemies = Physics.OverlapSphere(attackPos, radius);
    foreach (var e in enemies) e.GetComponent<Health>()?.TakeDamage(damage);
}

// IK 脚部贴合
void OnAnimatorIK(int layerIndex) {
    animator.SetIKPosition(AvatarIKGoal.LeftFoot, leftFootTarget.position);
    animator.SetIKPositionWeight(AvatarIKGoal.LeftFoot, 1f);
}
```

## 常见误区

<Callout type="trap">
**误区：认为动画只是美术的事，程序员不需要学。**
程序化动画、IK、动画事件、Blend Tree 参数控制都是程序员的工作。美术做基础动作数据，程序员搭建状态机、设置转换条件、编写动画事件回调、实现 IK 和程序化动画。不理解动画系统的程序员无法做出流畅的角色行为——如根据速度混合走/跑、攻击关键帧触发伤害、脚部贴合斜坡。
</Callout>

<Callout type="trap">
**误区：所有动画都用关键帧制作，不考虑程序化补充。**
纯关键帧动画是静态的——脚部穿地、头部不看向目标、角色无呼吸微动。现代游戏用「关键帧为主+程序化为辅」：主体动作用关键帧，细节用 IK（脚贴地面）、代码（头部注视/呼吸微动）、物理（布娃娃）补充。不学程序化动画就只能做出僵硬的角色。
</Callout>

<Exercises>
**问题 1**：全书四大板块是什么？它们之间是什么关系？

<Answer>
动画基础、Animator 核心、进阶技术、程序化与总结。呈递进关系：动画基础是数据理解（AnimationClip/关键帧），Animator 核心是逻辑控制（状态机/混合树），进阶技术是能力扩展（IK/Timeline/事件），程序化与总结是高级应用（代码驱动骨骼/综合复习）。每一层建立在前一层之上。
</Answer>

**问题 2**：AnimationClip、Animator Controller、Animator 三者是什么关系？

<Answer>
AnimationClip 是数据——存储骨骼关键帧、曲线和事件，由美术制作。Animator Controller 是逻辑——管理状态和转换，定义什么时候播什么 Clip、怎么混合和切换。Animator 是执行——挂载在 GameObject 上，执行 Controller 的指令，驱动骨骼播放 Clip。三者协作：Controller 引用 Clip，Animator 执行 Controller，最终骨骼按 Clip 数据运动。
</Answer>
</Exercises>
