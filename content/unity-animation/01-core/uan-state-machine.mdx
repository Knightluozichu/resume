## 直觉引入

状态机像菜单导航。主菜单（主状态机）有 Idle/Run/Attack/Death 选项。Attack 选项点进去有子菜单（子状态机）——Attack1/Attack2/Attack3 连击序列。Any State 像「紧急退出」按钮——不管在哪个菜单，按了直接跳到 Death/Hurt。

## 概念讲解

### 状态机结构

<UanStateMachineDiagram />

<Term def="Any State是特殊状态节点，可从任意状态转到目标状态，适合全局触发(受击/死亡)，简化连线">Any State</Term>简化全局触发。

<Term def="子状态机(Sub-State Machine)将一组相关状态封装为节点，双击展开内部状态，有Entry/Exit管理进出">子状态机</Term>封装复杂逻辑。

<Term def="Interruption Source控制转换是否可被其他转换中断，让动作响应更灵活(如攻击中被受击打断)">Interruption Source</Term>控制中断。

<Term def="Entry/Exit是子状态机的进出节点，Entry接收外部转入，Exit转回父状态机">Entry/Exit</Term>管理进出。

## 交互Demo

<Stepper>
<Step title="第一步：Any State">Any State 可以转到任意状态——从 Idle/Run/Attack/Jump 任何状态直接转到 Hurt（受击）或 Death（死亡）。不用 Any State 就需要从每个状态各画一条线到 Hurt/Death，连线爆炸。Any State + Trigger 参数让全局触发简洁。</Step>
<Step title="第二步：子状态机">
复杂状态组（如连击 Attack1→Attack2→Attack3）封装为子状态机。主状态机只看到一个 Attack 节点，双击展开内部三个状态。子状态机有 Entry（进入）和 Exit（退出），从主状态机转入 Entry，从 Exit 转回主状态机。
<UanStateMachineDiagram />
</Step>
<Step title="第三步：Interruption Source">默认转换开始后不可中断——必须等 Duration 完成。设置 Interruption Source 允许转换被其他转换打断。如 Attack1→Attack2 转换期间可以被 OnHit 打断转入 Hurt。让动作响应更灵活，避免动作锁定。</Step>
</Stepper>

## 代码对照

```csharp
// 连击系统代码
private int _comboCount = 0;
private float _comboTimer = 0f;
private const float COMBO_WINDOW = 0.3f;

void Update() {
    if (Input.GetButtonDown("Fire1")) {
        _comboCount = Mathf.Min(_comboCount + 1, 3);
        _animator.SetInteger("ComboCount", _comboCount);
        _animator.SetTrigger("Attack");
        _comboTimer = COMBO_WINDOW; // 重置窗口期
    }

    // 超时回到 Idle
    if (_comboTimer > 0) {
        _comboTimer -= Time.deltaTime;
        if (_comboTimer <= 0) {
            _comboCount = 0;
            _animator.SetInteger("ComboCount", 0);
            _animator.SetBool("ComboTimeout", true);
        }
    }

    // 检查攻击动画是否播完
    var state = _animator.GetCurrentAnimatorStateInfo(0);
    if (state.IsName("Attack") && state.normalizedTime >= 0.9f) {
        _animator.SetBool("ComboTimeout", false);
    }
}

// Any State 触发
void TakeDamage() {
    _animator.SetTrigger("Hit"); // 从任何状态转到 Hurt
}
```

## 常见误区

<Callout type="trap">
**误区：从每个状态单独画线到 Hurt/Death，导致状态机连线爆炸。**
如果有 10 个状态都需要转到 Hurt 和 Death，就需要 20 条线——状态机图不可读。正确做法：用 Any State 作为来源，只需要 Any State→Hurt 和 Any State→Death 两条线。无论角色在什么状态，SetTrigger("Hit") 都能触发转到 Hurt。Any State 是状态机简洁的关键工具。
</Callout>

<Callout type="trap">
**误区：把所有状态都放在主状态机中，不使用子状态机。**
一个主状态机有 20+ 个状态和 50+ 条转换线——无法维护。正确做法：将相关状态组封装为子状态机——攻击组（Attack1/2/3）、移动组（Walk/Run/Sprint）、交互组（Pickup/Talk/Open）。主状态机只看到 5~6 个节点，双击展开子状态机查看内部。模块化让复杂状态机可读可维护。
</Callout>

<Exercises>
**问题 1**：Any State 和子状态机分别解决什么问题？

<Answer>
Any State 解决全局触发的连线问题——从任意状态转到目标状态只需一条线，不用从每个状态各画一条。适合受击/死亡等需要从任何动画即时触发的动作。子状态机解决复杂状态组的封装问题——将相关状态（如连击 Attack1/2/3）封装为一个节点，主状态机只看到简洁的节点，双击展开内部状态。适合复杂逻辑模块化。两者配合：主状态机简洁 + Any State 简化触发 + 子状态机封装细节。
</Answer>

**问题 2**：设计一个连击系统，Attack1→Attack2→Attack3，每次有 0.3 秒窗口期。

<Answer>
1)创建子状态机 Attack，内含 Attack1/Attack2/Attack3；2)转换条件：ComboCount==1 转Attack2，ComboCount==2 转Attack3；3)每个 Attack→Exit 设 ComboTimeout 条件；4)代码：点击攻击键时 ComboCount++，SetTrigger("Attack")，重置计时器；5)超时：0.3 秒无输入设 ComboTimeout=true 且 ComboCount=0；6)检查 normalizedTime>=0.9 确保攻击动画播完才允许连击。子状态机的 Exit 转回主状态机 Idle。
</Answer>
</Exercises>

<GlossaryItem term="Any State">特殊状态节点，可从任意状态转到目标，简化全局触发。</GlossaryItem>
<GlossaryItem term="子状态机">将相关状态封装为节点，有 Entry/Exit 管理进出。</GlossaryItem>
<GlossaryItem term="Interruption Source">控制转换是否可被其他转换中断的机制。</GlossaryItem>
