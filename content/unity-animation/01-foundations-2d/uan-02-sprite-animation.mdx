## 问题：为什么图片都导入成功，动画仍可能倒序、跳帧或比例错误

先预测：walk_1、walk_2、walk_10 按文件名字典序自动排列，会得到 1、10、2 还是 1、2、10？很可能是前者。第二章把动画问题前移到资产管线：Texture Type、Sprite Mode、切片矩形、Pivot、Pixels Per Unit、帧命名、采样率和 Wrap Mode 共同决定最终结果。播放错误不一定来自 Animator。

## 源像素到有序时间帧

Sprite 动画先把纹理切成具名矩形，再把 Sprite 引用按时间写入 SpriteRenderer 的 sprite 属性。Pixels Per Unit 决定世界尺度，Pivot 决定每帧对齐，命名和选中顺序决定帧序列，Clip sample rate 决定每秒推进多少采样，Loop Time 决定末尾行为。任何环节漂移都会表现为缩放跳动、脚底滑动、帧顺序错误或意外重复。

## 关键对象与数据流

从一张 4x2 图集开始，固定每格尺寸与底部中心 Pivot，切出八帧并使用零填充名称 walk_01 到 walk_08。按序创建 Clip，计算 duration = frameCount / sampleRate，再分别故意把采样率翻倍、开启不应存在的循环、打乱两帧。诊断时检查导入元数据、Clip 曲线关键帧时间与 Wrap 设置，而不是只看播放画面。

排查时从最早可控输入开始，逐段检查导入设置、中间状态和最终像素。最终画面正确但链路不符合预测，也不能立即签发，因为它可能依赖未记录的帧率、缓存、随机种子或编辑器状态。

## Sprite 跳动通常在播放前已经发生

图集切片得到的不只是矩形，还包含名称、Pivot、Border 和源纹理坐标。若每帧透明边界不同而使用自动中心 Pivot，角色脚底会左右或上下跳；若 Pixels Per Unit 不一致，帧切换会改变世界尺寸；若过滤模式和压缩改变像素边缘，像素画会出现模糊或色边。诊断先在 Sprite Editor 对比切片元数据，再看 Clip 引用和时间，最后才看 Animator。

帧顺序不能依赖未经约束的字典序。walk_1、walk_10、walk_2 会按文本排序成一、十、二；零填充名称或显式序列才能保持稳定。Clip 的持续时间由关键帧时间和采样率共同决定，八帧在每秒八帧下约一秒，在每秒十六帧下约半秒。循环还要检查最后一帧是否与第一帧重复，否则边界会多停一个采样或出现节奏突变。

## 从资产到像素的检查顺序

- 原纹理尺寸、alpha、颜色空间、压缩和平台覆盖设置是否符合目标画面。
- Sprite Mode、切片网格、名称、Pivot 与 Pixels Per Unit 是否跨帧一致。
- AnimationClip 对象引用曲线是否按预期顺序和时间指向每个 Sprite。
- Wrap Mode 或 Loop Time、Animator 速度和全局 timeScale 是否共同改变节奏。
- SpriteRenderer 排序层、材质和对象缩放是否在播放时额外改变结果。

建立八帧标准样本后，分别注入不同 Pivot、错误 PPU、乱序名称、双倍采样率和错误循环。每次只改一项，保存导入元数据、Clip 曲线截图和关键时间点像素。现代 Sprite Atlas 打包方式可以变化，但单帧身份、序列顺序、时间采样和对齐契约仍是可迁移不变量。

图集重新打包还可能改变纹理页位置，但 Sprite 引用应通过资产身份而不是手写 UV 保持稳定。验收在启用旋转打包、紧密网格和平台压缩后重建图集，比较 Renderer 引用、批次、边缘采样与动画顺序。若业务代码依赖切片在源纹理中的固定坐标，应把这种额外契约显式记录，否则一次正常的打包优化就会破坏运行结果。

同时在目标设备验证内存、批次与首帧加载，确保打包收益没有以画质或启动抖动为代价。

## 正常、边界与失败样本

每章至少保存一个正常样本、一个极端边界和一个故意破坏配置。正常样本证明主路径，边界样本说明适用范围，失败样本证明诊断方法真的能抓到错误。


## 从 Unity 5 到现代 Unity

现代 Unity 仍使用 Sprite Editor、AnimationClip 和 SpriteRenderer，但 Sprite Atlas 工作流、2D 包与导入面板位置已变化。原书的故障分类仍适用。现代项目还应验证平台纹理压缩、Pixel Perfect Camera 与 Addressables 打包；这些是交付补充，不替代本章的导入、帧率、循环和顺序。

迁移记录采用五列：原书载体、稳定不变量、现代实现、不可等价处、目标平台证据。允许替换工具和 API，不允许抹去原始问题或倒写历史。

## 验收证据

验收包含原图与切片元数据、八帧名称列表、计算得到的 Clip 时长、三个关键时刻截图，以及过快、误循环、错序三个失败样本。重新导入后 GUID 与帧引用应保持稳定，脚底基准偏差需量化。

## 小结

- Sprite 动画从导入和切片开始，不是从 Animator 开始
- PPU 与 Pivot 分别约束尺度和逐帧对齐
- 帧数与采样率共同决定播放时长
- 速度、循环和顺序问题都能落到具体资产配置
