## 问题：为什么一个镜头飞越和一群萤火粒子属于同一章

先预测：场景中的相机、门和灯能否写进同一个 Clip，并在 2.5 秒触发一次函数？可以。第三章把 Unity 内建动画创作分成两类：Animation 窗口记录任意可动画属性与事件，Particle System 按发射和生命周期规则生成大量短命实例。二者都要求设计时间、属性、作用对象和可观察结束条件。

## 确定性曲线与统计性粒子

AnimationClip 对指定对象属性保存确定性曲线，同一时间应得到同一值；Animation Event 在曲线时间轴上派发函数。粒子系统则从 Shape 采样出生位置，按 Rate 生成粒子，通过 Start Lifetime、Speed、Color over Lifetime、Velocity 和 Renderer 描述群体统计。镜头路径关注单对象连续性，粒子关注分布、峰值存活数和透明消失。

## 关键对象与数据流

先在 0、2、5 秒记录相机位置与旋转，使用曲线保证飞越构图连续；再给门和灯添加属性轨，证明一个 Clip 能协同多个绑定对象。于 2.5 秒插入事件并记录调用计数。粒子部分固定随机种子、发射率和寿命，预测稳态存活数约为 rate x lifetime，再调整 Shape、Velocity、Renderer 和透明曲线观察分布。

排查时从最早可控输入开始，逐段检查导入设置、中间状态和最终像素。最终画面正确但链路不符合预测，也不能立即签发，因为它可能依赖未记录的帧率、缓存、随机种子或编辑器状态。

## 确定性曲线与统计性粒子要用不同证据

镜头飞越和多对象 Clip 在固定时间点应得到可重复 Transform 或属性值，因此可以抽取零秒、中点和终点做数值断言。多个对象写入同一 Clip 时，曲线路径绑定到层级和组件属性；重命名或移动对象可能让绑定失效。Animation Event 还依赖目标组件和方法签名，循环 Clip 会在每次经过事件时间时再次触发。验收要记录对象路径、事件时刻、循环次数和实际调用计数。

粒子系统不要求每个粒子位置完全相同，但应满足可预测统计。稳态最大存活数大致由每秒发射率与生命周期决定，Burst、随机范围和空间模拟会改变瞬时分布。以固定随机种子或足够样本记录出生数、峰值存活数、速度范围、颜色阶段和死亡时间，比截取一张“看起来像萤火虫”的画面更有诊断价值。

## 粒子模块排查顺序

- Main 定义持续时间、循环、起始生命周期、速度、尺寸和模拟空间。
- Shape 与 Emission 决定从哪里、以何种速率或 Burst 产生粒子。
- Velocity over Lifetime 与 Force 等模块决定出生后的运动，不要与起始速度混淆。
- Color over Lifetime 和 Size over Lifetime 使用归一化寿命，梯度端点必须可观察。
- Renderer 决定 billboard、材质、排序和拖尾，粒子存在不代表一定能被相机看见。

压力样本把发射率提高十倍并延长生命周期，验证峰值数量、过度绘制和 CPU/GPU 成本；失败样本关闭 Renderer、把颜色 alpha 设为零或使用错误模拟空间，确认诊断能区分“没有生成”和“生成但不可见”。现代 Particle System 面板布局变化不应改变这条生产链。

## 正常、边界与失败样本

每章至少保存一个正常样本、一个极端边界和一个故意破坏配置。正常样本证明主路径，边界样本说明适用范围，失败样本证明诊断方法真的能抓到错误。


## 从 Unity 5 到现代 Unity

Animation 窗口、Clip 曲线和 Animation Event 仍存在；粒子系统模块名称与布局已现代化。原书的 Particle Renderer 等旧面板表述应映射到当前 Renderer、Emission、Shape、Velocity over Lifetime 与 Color over Lifetime 模块。VFX Graph 可处理更大 GPU 效果，但不是本章粒子实验的替代。

## 验收证据

验收保存相机三时刻截图、曲线切线、多个对象绑定表、事件调用次数，以及粒子固定种子下的发射率、寿命、理论与实际峰值、渲染材质和透明结束帧。关闭某一模块后应能预测最先变化的指标。

证据包同时记录场景路径、代码版本、资产 GUID、参数、复现步骤、预期和实际结果。交给另一位读者后不需要猜测隐藏状态即可重放，才算掌握而不只是看过。

## 小结

- Animation 窗口可记录镜头和多个对象的任意可动画属性
- Animation Event 把时间轴与函数调用连接起来
- 粒子效果由出生分布、生命过程和渲染共同决定
- 发射率与寿命可用于估算存活数量和性能上界
