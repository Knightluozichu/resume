## 问题：为什么动画在原模型上正确，重定向后仍可能滑步或偏移

先预测：同一段走路 Clip 重定向到腿长不同的角色，脚底是否必然完全贴地？不必然。第五章把角色动画拆成几何、骨架、蒙皮、Avatar 映射、Clip 和根运动。重定向只解决骨骼语义映射，不自动修复步幅、根高度、朝向、循环接缝或碰撞控制。

## 模型空间到角色语义空间

绑定角色由 Mesh、Bone hierarchy 和 Skin weights 构成，AnimationClip 改变骨骼局部变换。Humanoid Avatar 把具体骨骼映射到统一人体语义，使一个 Clip 可重定向到兼容角色。Root Motion 从根节点曲线提取世界位移与旋转；关闭时通常由代码或导航移动。偏移可能来自模型轴向、根节点层级、Bake Into Pose、Based Upon 选项、首尾帧或目标体型。

## 关键对象与数据流

先记录 FBX 轴向、比例、骨架根与骨骼映射，验证 Avatar 为有效绿色状态。将同一 Idle、Walk、Turn Clip 分别应用到源角色和目标角色，比较脚接触、髋高和朝向。再开关 Apply Root Motion，记录一周期世界位移与脚滑距离；通过 Root Transform Rotation/Position 的 Bake Into Pose 和 Based Upon 选项逐项修正。

排查时从最早可控输入开始，逐段检查导入设置、中间状态和最终像素。最终画面正确但链路不符合预测，也不能立即签发，因为它可能依赖未记录的帧率、缓存、随机种子或编辑器状态。

## 重定向成功依赖骨架语义而不只是骨骼名字

蒙皮网格保存顶点到骨骼的权重，Rig 定义骨骼层级，Avatar 把具体骨骼映射到人形语义，Humanoid Clip 则可通过这层语义重定向到另一角色。模型导入为 Humanoid 并出现绿色勾选，只说明映射基本有效，还要检查 T Pose、左右骨、手指、上下身比例和肌肉限制。错误映射可能在待机时不明显，却在转身、抬臂或大步运动中出现扭曲。

根运动决定角色世界位移来自动画根轨迹还是游戏代码。Apply Root Motion 开启后，Animator 可以把 Clip 的根位移写到对象；关闭后，脚本或控制器必须提供位移。两者同时写入会双倍移动，两者都不写则原地踏步。Root Transform Rotation、Position Y 和 Position XZ 的 Bake Into Pose 与 Based Upon 选项还决定哪些分量进入姿态、哪些留给 GameObject。

## 重定向验收样本

- 使用一段前进、转身和抬手都明显的标准 Clip，避免待机掩盖错误。
- 源角色与目标角色分别保存 Avatar 映射、身高、朝向和骨骼比例。
- 在根运动开关两种模式下记录对象位移、动画根位移和脚底滑动距离。
- 故意交换骨骼、破坏 T Pose 或改变模型尺度，确认失败信号可定位。
- 修正 motion offset 后重放同一时间点，比较骨盆、双脚和朝向而非只看整体。

现代 Unity 的导入面板名称可能调整，但 Avatar、重定向、根轨迹与对象移动的责任边界不变。证据包要包含模型导入设置、Avatar 配置、Clip 根曲线、控制器位移代码和关键帧姿态截图，使另一位读者能区分资产问题与运行时移动问题。

不同身材角色重定向时，手脚接触点和步幅不会天然完全一致。验证不能只看骨骼是否移动，还要测量脚掌在支撑相位的世界位移、骨盆高度、转向角和目标速度。若必须用 Avatar Mask、脚部 IK 或速度缩放修正，应分别保存修正前后数据，并说明它修复的是表现偏差而非错误骨骼映射。角色缩放也要在模型导入阶段统一，避免运行时非均匀缩放把姿态问题复杂化。

切换不同目标角色时重播同一时间点，并用叠影或骨骼 Gizmo 对齐关键关节，能把比例差异与映射错误分开。

这些测量值应随模型和 Clip 版本保存，资源更新后自动重跑对照。

## 正常、边界与失败样本

每章至少保存一个正常样本、一个极端边界和一个故意破坏配置。正常样本证明主路径，边界样本说明适用范围，失败样本证明诊断方法真的能抓到错误。

## 从 Unity 5 到现代 Unity

Humanoid Avatar、重定向和 Root Motion 仍是现代 Unity 核心。模型导入器界面和选项文字可能变化，但轴向、比例、映射、根曲线和代码所有权不变量仍然适用。Animation Rigging 可增加运行时约束，不能替代基础 Avatar 与根运动验收。

迁移记录采用五列：原书载体、稳定不变量、现代实现、不可等价处、目标平台证据。允许替换工具和 API，不允许抹去原始问题或倒写历史。

## 验收证据

验收包含 FBX/Avatar 配置、骨骼映射截图、两个角色在同一 Clip 的关键姿态、脚滑与地面误差、根运动开关对照、一周期世界位移和修复前后循环接缝。代码与动画只能有一个明确的平移所有者。

证据包同时记录场景路径、代码版本、资产 GUID、参数、复现步骤、预期和实际结果。交给另一位读者后不需要猜测隐藏状态即可重放，才算掌握而不只是看过。

## 小结

- 角色动画资产由网格、骨架、权重、Clip 与 Avatar 共同构成
- Avatar 提供人体语义映射，使动画可跨兼容角色重定向
- 根运动决定动画位移如何进入世界 Transform
- 有效映射不等于无脚滑，偏移仍需量化与修复

<Exercises>

**问题 1** 为什么重定向需要 Avatar？

<Answer>
  它把不同模型的具体骨骼名和层级映射到统一人体语义，Clip 才能跨角色应用。
</Answer>

**问题 2** 角色移动翻倍最先检查什么？

<Answer>
  检查 Apply Root Motion 与代码或 CharacterController 位移是否同时写入世界位置。
</Answer>

**问题 3** 怎样量化脚滑？

<Answer>
  在脚应接触地面的区间记录脚骨世界位置相对地面的水平位移和高度误差。
</Answer>
