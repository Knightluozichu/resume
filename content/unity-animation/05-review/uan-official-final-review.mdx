## 问题：怎样证明掌握的是七章动画系统，而不是会点几个 Inspector 选项

先预测：最终场景画面正常，是否就能签发？不能。综合验收需要从固定输入追到导入资产、时间参数、AnimationClip、Animator 图、Avatar、根运动、Blend Tree 权重、Blend Shape、IK 和视频解码，并保留正常、边界和失败样本。只有另一个读者可以按证据包复现结论，才算掌握。

## 七章动画验收矩阵

验收矩阵横轴是七章，纵轴是输入资产、时间来源、求值器、输出属性、正常样本、边界样本、失败样本、现代迁移与性能证据。每格必须指向具体文件、参数或截图。例如 Sprite 错序指向对象引用关键帧，门不动指向参数与转换，脚滑指向根运动和目标体型，手不到目标指向 IK 可达性，黑屏指向 VideoPlayer Prepare 与解码。

## 关键对象与数据流

综合场景先让相机按曲线飞越精灵和萤火粒子，玩家按按钮打开门，导入角色通过 Avatar 重定向并以 Blend Tree 移动，靠近把手时 IK 接管手部，表情由 Blend Shape 驱动，墙面屏幕通过 VideoPlayer 播放片段。自动记录每阶段开始、结束、参数、状态和误差；随后逐项注入错序帧、缺参数、双重位移、不可达 IK 和未准备视频。

排查时从最早可控输入开始，逐段检查导入设置、中间状态和最终像素。最终画面正确但链路不符合预测，也不能立即签发，因为它可能依赖未记录的帧率、缓存、随机种子或编辑器状态。

## 用故障注入验证七章之间的连接

综合场景固定一个媒体展厅：Sprite 指示灯按序播放，相机沿 Clip 飞越，粒子提供环境效果，按钮驱动门状态图，重定向角色通过 Blend Tree 接近门，根运动决定实际位移，手部 IK 对准把手，面部 Blend Shape 变化，墙面视频同步播放。每条链记录资产身份、时间来源、当前状态、关键参数、输出属性和性能摘要，任何最终画面都能回到中间证据。

第一组故障把 Sprite 帧改成字典乱序，验证资产检查先于 Animator；第二组把门参数名拼错，验证状态图日志能区分输入与转换；第三组同时开启代码位移和根运动，验证脚滑与双倍位移来自责任重叠；第四组把 IK 目标移到不可达位置，验证末端误差和回退；第五组换成目标平台不支持的视频编码，验证 Prepare 错误不会被误判为材质问题。

## 签发层次

- **目录层**：7/7 原章唯一映射，导读和总复习不增加覆盖分母。
- **页面层**：每页有独有交互图、三步实验、陷阱、练习、题库和迁移边界。
- **连接层**：时间、资产、状态、骨骼、权重、约束和媒体之间有明确责任链。
- **运行层**：正常、边界和失败输入均能在固定时间点复现并解释。
- **交付层**：干净检出、目标平台、性能捕获和证据索引共同通过。

现代迁移一次只替换一个载体，例如 MovieTexture 到 VideoPlayer、旧粒子面板到当前模块、旧输入到新输入系统。每次使用同一资产和时间脚本比较可见结果与中间状态，记录不能完全等价的格式、平台和时钟差异。最后盲测只提供症状，由读者选择首个观测点；若能用最少变量变化定位并保留失败样本，才说明掌握的是动画系统而非 Inspector 记忆。

最终证据索引把每个结论连接到提交、场景、资产 GUID、导入设置、Animator Controller、参数快照、关键时间截图、Profiler 捕获和失败样本。另一台机器从干净检出打开工程后，应能按索引重放相同输入并得到相同判断；若依赖原作者 Library 缓存、未提交模型或手工 Inspector 状态，就不能签发。这样书籍评分才代表可交付知识，而不是当前编辑器会话中的偶然成功。

签发者还要抽查一条未预告故障，确认读者能独立选择证据而不是背诵预设答案，并把新案例补回回归矩阵。

抽查过程与结论同样纳入版本化证据索引。

## 正常、边界与失败样本

每章至少保存一个正常样本、一个极端边界和一个故意破坏配置。正常样本证明主路径，边界样本说明适用范围，失败样本证明诊断方法真的能抓到错误。

<Callout type="trap">
  **因果陷阱**：只保存最终录屏会隐藏导入设置、状态参数和求值中间值，无法证明正确画面不是偶然。
</Callout>

<Callout type="trap">
  **版本陷阱**：把现代 Timeline 或 Animation Rigging
  的成功案例当作原章覆盖，会让目录得分和真实复刻脱节。
</Callout>

## 从 Unity 5 到现代 Unity

最终迁移账本至少覆盖旧 Mecanim 称呼、Legacy Animation 示例、粒子模块名称、MovieTexture 与 OGV。当前 Animator、Particle System、VideoPlayer、Input System 或 Animation Rigging 的使用必须标记为替代或补充。若平台解码、根运动或约束行为不可等价，需要保留差异而不是宣称完全一致。

迁移记录采用五列：原书载体、稳定不变量、现代实现、不可等价处、目标平台证据。允许替换工具和 API，不允许抹去原始问题或倒写历史。

## 验收证据

签发要求 7/7 原章覆盖、9/9 页面不低于 90 分、54 道题 ID 和文本唯一、导航分组顺序准确、定向与全库 MDX 零错误。场景证据还包括资产版本、关键参数、时间线日志、误差表、截图、性能数据和至少五个失败样本。

证据包同时记录场景路径、代码版本、资产 GUID、参数、复现步骤、预期和实际结果。交给另一位读者后不需要猜测隐藏状态即可重放，才算掌握而不只是看过。

## 小结

- 最终验收同时检查目录、知识、实验、迁移和工程集成
- 七章分别覆盖时间、精灵、原生工具、状态图、角色资产、混合和高级表现
- 每个正确结论都要有中间状态与失败样本支撑
- 现代功能可以补充，但不能替代原书章节身份

**问题 1** 综合场景为什么要故意制造失败？

<Answer>
  失败样本证明观测和断言真的能区分错误配置，避免只有成功录屏却无法定位回归。

**问题 2** 根运动问题应保存哪些证据？

<Answer>
  Apply Root Motion、Clip 根设置、代码位移所有者、一周期世界位移和脚滑误差。
</Answer>

**问题 3** 怎样处理 MovieTexture 与 VideoPlayer 不等价？

<Answer>
  保留原书的视频纹理问题，记录
  API、格式和平台差异，并用现代管线重新验证首帧、音频和循环。
</Answer>
