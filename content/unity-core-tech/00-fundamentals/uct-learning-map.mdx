## 直觉引入

Unity 是一个「全家桶」引擎——场景管理、资源管线、渲染管线、物理引擎、音频系统、导航、内存管理、构建部署，每个子系统都能独立成书。但实际开发中这些系统紧密耦合：资源没压缩导致内存爆炸，DrawCall 过多卡死渲染，物理在 Update 里算导致抖动。

这本书把 Unity 核心技术拆成十章，从场景架构开始，到资源导入、渲染配置、物理交互、音频管理、导航 AI、内存优化，最后到构建发布。每章解决一个核心问题，章与章之间环环相扣。

## 概念讲解

全书分四个阶段：**基础**（场景与资源）、**核心**（渲染与物理与音频）、**进阶**（导航与内存）、**收尾**（构建与综合）。

<Term def="Unity 中组织游戏对象层级的核心容器">场景</Term>是一切的容器。<Term def="从资源导入到 GPU 渲染的完整数据流">渲染管线</Term>决定画面效果与性能。<Term def="模拟真实物理行为的引擎子系统">物理引擎</Term>处理碰撞与运动。<Term def="将 C# 代码编译为原生机器码并打包到目标平台">构建部署</Term>是上线的最后一步。

### 阶段依赖
- 基础 → 核心：有了场景和资源，才能渲染和模拟物理
- 核心 → 进阶：渲染和物理跑通后，才需要导航和内存优化
- 进阶 → 收尾：优化完成后，才能构建发布

### 学习节奏建议
- 第 1 章通读全图，建立全局观
- 第 2-6 章是核心子系统，逐个掌握
- 第 7-9 章是优化与发布，项目后期最关键
- 第 10 章串联全书，做综合项目

## 常见误区

<Callout type="trap">
**现象 →** 学了一堆 Unity 功能，但做项目时不知道从哪开始。
**原因 →** 没有全局观，把功能点当成了知识点而非工具链。
**修法 →** 先建全局观：场景→资源→渲染→物理→音频→导航→内存→构建。做项目时按这个顺序推进，每步解决一个核心问题。
</Callout>
<Callout type="trap">
**现象 →** 项目做到后期帧率暴跌，不知道是哪个子系统的问题。
**原因 →** 没有用 Profiler 系统性分析，盲目优化。
**修法 →** 用 Profiler CPU 模块定位瓶颈类型：GC 卡顿→内存管理章，DrawCall 过多→渲染管线章，物理计算重→物理引擎章。按章节知识逐项排除。
</Callout>

## 练习

<Exercises>
**问题**：全书四个阶段分别解决什么问题？如果只能保留一个阶段来让项目跑起来，你保留哪个？

<Answer>
基础（场景与资源）解决内容在哪、怎么加载；核心（渲染物理音频）解决看得见、有交互；进阶（导航内存）解决 AI 寻路和性能；收尾（构建）解决怎么发布。若只要项目跑起来，必须保留基础——没有场景和资源就没有游戏，其余都是锦上添花。
</Answer>

**问题**：Unity 的子系统之间如何协作？举一个跨三个子系统的例子。

<Answer>
射击游戏的开枪：物理引擎（Raycast 射线检测命中）→音频系统（播放枪声）→渲染管线（枪口闪光特效）。一个操作涉及三个子系统。再比如敌人 AI：导航（NavMeshAgent 寻路）→物理（碰撞检测）→内存（对象池管理敌人）。理解子系统协作是 Unity 核心能力。
</Answer>
</Exercises>

<GlossaryItem term="场景">Unity 中组织 GameObject 层级的核心容器，通过 SceneManager 加载和卸载，支持 Additive 多场景叠加。</GlossaryItem>
<GlossaryItem term="渲染管线">从 3D 数据到 2D 屏幕像素的完整处理流程，Unity 有 Built-in、URP、HDRP 三种管线。</GlossaryItem>
<GlossaryItem term="物理引擎">Unity 内置的 PhysX 引擎，模拟刚体运动、碰撞检测、关节约束等物理行为，在 FixedUpdate 中运行。</GlossaryItem>
<GlossaryItem term="构建部署">通过 BuildPipeline API 将项目编译为目标平台可执行文件，涉及 IL2CPP、Stripping、签名等步骤。</GlossaryItem>
</Glossary>
