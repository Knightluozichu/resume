## 直觉引入

Unity 项目里有成千上万的资源——模型、纹理、音频、动画。这些资源从磁盘文件变成引擎对象的过程就是资源管线。导入时可以设置压缩格式、LOD、Mipmap 等参数，配错了要么包体爆炸要么画质糊。

资源加载方式从旧到新经历了三代：Resources（全打进包）→ AssetBundle（手动打包分组）→ Addressables（自动分组+按需加载+远程更新）。Addressables 是当前推荐方案——一个地址加载资源，不用关心资源在哪。

## 概念讲解

<Term def="Unity 将磁盘文件导入为引擎对象的流水线，支持自定义导入设置">资源管线</Term>处理一切资源。

<Term def="Unity 的现代资源管理系统，用地址加载资源，支持按需加载和远程更新">Addressables</Term>是资源加载的未来。

<Term def="移动端推荐的纹理压缩格式，压缩比高且质量好">ASTC</Term>是移动端纹理压缩的首选。

### 资源加载方式对比
| 方式 | 优点 | 缺点 |
|---|---|---|
| Resources | 简单 | 全打进包，无法按需 |
| AssetBundle | 可分组 | 手动管理，容易出错 |
| Addressables | 自动分组 | 学习成本 |

<Term def="将多个纹理合并为一张大图减少 DrawCall">图集</Term>是 2D 游戏必备优化。

</Step>

## 代码对照

```csharp
// Unity C#: Addressables 资源加载
using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;

public class AssetLoader : MonoBehaviour
{
    private AsyncOperationHandle<GameObject> enemyHandle;

    async void SpawnEnemy(string address)
    {
        // 异步加载资源
        enemyHandle = Addressables.LoadAssetAsync<GameObject>(address);
        await enemyHandle.Task;

        if (enemyHandle.Status == AsyncOperationStatus.Succeeded)
        {
            Instantiate(enemyHandle.Result, transform);
        }
    }

    // 加载并实例化（一步到位）
    async void SpawnEnemyOneStep(string address, Vector3 pos)
    {
        var handle = Addressables.InstantiateAsync(address, pos, Quaternion.identity);
        await handle.Task;
        // handle.Result 就是实例化后的 GameObject
    }

    void OnDestroy()
    {
        // 释放资源（引用计数减 1）
        if (enemyHandle.IsValid())
            Addressables.Release(enemyHandle);

        // 释放实例
        // Addressables.ReleaseInstance(gameObject);
    }
}
```

## 常见误区

<Callout type="trap">
**现象 →** 用 Resources.Load 加载资源，包体越来越大。
**原因 →** Resources 文件夹的资源全部打进包，无法按需加载，即使没用到也在包里。
**修法 →** 迁移到 Addressables：把资源从 Resources 移出，标记为 Addressable，用地址加载。Addressables 支持按需加载和远程更新，大幅减小包体。
</Callout>
<Callout type="trap">
**现象 →** 移动端纹理内存占用过大，频繁 OOM 闪退。
**原因 →** 纹理用了未压缩格式或 RGBA32，一张 2048 纹理就 16MB。
**修法 →** 在纹理导入设置中选 ASTC 压缩格式（移动端推荐 6x6 或 8x8）。2048 纹理从 16MB 降到 1.4MB。用 Player Settings 的 Texture Compression 强制压缩。
</Callout>

## 练习

<Exercises>
**问题**：为什么不要用 Resources 文件夹加载资源？

<Answer>
Resources 文件夹的所有资源在构建时全部打进包，不管是否用到。这导致包体增大、启动时加载 Resources 目录的序列化文件慢、无法按需加载和远程更新。Addressables 解决了所有问题：按需加载、自动分组、远程更新、引用计数自动管理。Unity 官方也建议弃用 Resources。
</Answer>

**问题**：Addressables 的引用计数是什么？为什么重要？

<Answer>
Addressables 给每个资源维护引用计数。LoadAssetAsync 时计数+1，Release 时计数-1。计数归零时自动释放资源。重要性：防止内存泄漏（忘了 Release）和频繁加载（多次 Load 只加载一次）。如果 3 个地方加载同一资源，Release 3 次才真正释放。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Addressables">Unity 的现代资源管理系统，用地址而非路径加载资源，支持按需加载、引用计数和远程更新。</GlossaryItem>
<GlossaryItem term="ASTC">自适应可伸缩纹理压缩，移动端推荐的纹理压缩格式，压缩比高且质量好。</GlossaryItem>
<GlossaryItem term="AssetBundle">Unity 的资源打包格式，将资源分组打包为独立文件，可按需加载。Addressables 底层基于 AssetBundle。</GlossaryItem>
<GlossaryItem term="引用计数">Addressables 为每个资源维护的加载计数，归零时自动释放，防止内存泄漏和重复加载。</GlossaryItem>
</Glossary>
