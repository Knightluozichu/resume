## 直觉引入

让 NPC 自动走到目标点，不需要手写寻路算法。Unity 的 NavMesh 系统把场景的可行走区域烘焙成一张导航网格，NPC 上的 NavMeshAgent 组件在这个网格上用 A* 算法自动找路。

NavMesh 的核心思想是降维：3D 空间有无数条路，但在地面上可行走的区域是有限的。把可行走区域压缩成 2D 多边形网格，A* 算法在这个小得多的网格上搜索路径，效率比直接在 3D 空间高数百倍。

## 概念讲解

<Term def="标记场景中可行走区域的导航网格，通过烘焙生成">NavMesh</Term>是寻路的地图。

<Term def="挂在角色上在 NavMesh 上自动寻路移动的组件">NavMeshAgent</Term>是寻路的执行者。

<Term def="在图上找最短路径的经典算法，NavMesh 内部使用">A*</Term>是寻路的大脑。

### NavMesh 工作流
1. 标记 Static→Navigation Static
2. 烘焙（Bake）生成 NavMesh
3. 角色挂 NavMeshAgent
4. SetDestination 设置目标

### 关键参数
- **Agent Radius**：角色半径，影响通道宽度
- **Slope**：最大可行走坡度
- **Step Height**：最大台阶高度

<Term def="运行时动态阻挡 NavMesh 的障碍物组件">NavMeshObstacle</Term>实现动态障碍。

</Step>
<Step title="第三步：加动态障碍">
给移动的箱子挂 NavMeshObstacle 组件，勾选 Carve。箱子移动时实时切割 NavMesh，NPC 自动绕开。不勾 Carve 只做避让不更新路径。
</Step>
</Stepper>

## 代码对照

```csharp
// Unity C#: 敌人 AI 寻路系统
using UnityEngine;
using UnityEngine.AI;

[RequireComponent(typeof(NavMeshAgent))]
public class EnemyAI : MonoBehaviour
{
    private NavMeshAgent agent;
    public Transform player;
    public float detectRange = 10f;
    public float attackRange = 2f;
    public Transform[] patrolPoints;

    private int patrolIndex = 0;
    private enum State { Patrol, Chase, Attack }
    private State state = State.Patrol;

    void Start() => agent = GetComponent<NavMeshAgent>();

    void Update()
    {
        float distToPlayer = Vector3.Distance(
            transform.position, player.position);

        // 状态机
        switch (state)
        {
            case State.Patrol:
                Patrol();
                if (distToPlayer < detectRange)
                    state = State.Chase;
                break;

            case State.Chase:
                agent.SetDestination(player.position);
                if (distToPlayer < attackRange)
                    state = State.Attack;
                else if (distToPlayer > detectRange * 1.5f)
                    state = State.Patrol;
                break;

            case State.Attack:
                agent.SetDestination(transform.position); // 停下
                // 攻击逻辑...
                if (distToPlayer > attackRange)
                    state = State.Chase;
                break;
        }
    }

    void Patrol()
    {
        if (patrolPoints.Length == 0) return;

        agent.SetDestination(patrolPoints[patrolIndex].position);

        // 到达巡逻点，切换下一个
        if (!agent.pathPending && agent.remainingDistance < 0.5f)
        {
            patrolIndex = (patrolIndex + 1) % patrolPoints.Length;
        }
    }

    // 检查路径是否有效（目标可达）
    bool CanReach(Vector3 target)
    {
        NavMeshPath path = new NavMeshPath();
        agent.CalculatePath(target, path);
        return path.status == NavMeshPathStatus.PathComplete;
    }
}
```

## 常见误区

<Callout type="trap">
**现象 →** NPC 在角落卡住或走不出窄通道。
**原因 →** Agent Radius 太大，通道宽度不够两个 Agent 通过。或者 NavMesh 没覆盖到通道。
**修法 →** 检查 NavMesh 烘焙是否覆盖通道（蓝色区域）。减小 Agent Radius 或加宽通道。设 Stopping Distance 0.5-1.0 防止 NPC 在目标点原地转圈抖动。
</Callout>
<Callout type="trap">
**现象 →** NPC 寻路到目标点后原地转圈抖动。
**原因 →** NPC 到达目标点后没有停止，NavMeshAgent 还在微调位置。Stopping Distance 设为 0 导致精确到位时反复调整。
**修法 →** 设 agent.stoppingDistance = 0.5f 或更大。到达后手动 agent.isStopped = true。或者检查 agent.remainingDistance < stoppingDistance 时停止。
</Callout>

## 练习

<Exercises>
**问题**：为什么 A* 寻路需要 NavMesh 而不能直接在 3D 空间寻路？

<Answer>
3D 空间每体素做 A* 计算量爆炸——100x100x10 有 10 万节点。NavMesh 把可行走区域压缩成 2D 多边形网格，节点从万级降到百级，A* 搜索效率提升数百倍。NavMesh 本质是 3D 到 2D 的降维压缩：把可行走的表面提取为多边形，NPC 在多边形上寻路而非在 3D 体素中寻路。
</Answer>

**问题**：NavMeshObstacle 的 Carve 选项有什么作用？什么时候需要开启？

<Answer>
Carve 让障碍物实时切割 NavMesh，NPC 寻路时绕开。不勾选只做碰撞避让不更新 NavMesh，NPC 可能卡住。移动的门/箱子等动态障碍需勾选 Carve。但 Carve 有性能开销（重新烘焙局部 NavMesh），静态障碍用 Navigation Static 烘焙更好。大量动态障碍考虑用避让而非 Carve。
</Answer>
</Exercises>
