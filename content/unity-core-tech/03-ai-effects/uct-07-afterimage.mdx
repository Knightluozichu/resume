## 把动态角色转换成轻量视觉快照

蒙皮角色的当前姿态存在骨骼矩阵与蒙皮计算中，SkinnedMeshRenderer.BakeMesh 可把这一帧的变形结果写入普通 Mesh。快照对象使用 MeshFilter 与 MeshRenderer，不再需要 Animator 和骨架；位置、旋转、缩放必须与烘焙空间约定一致。

残影材质通常使用透明混合或加色，并以年龄驱动颜色和 alpha。每个快照若访问 material 会产生实例；可以在池对象上预建材质，或用 MaterialPropertyBlock 写入每实例颜色，避免污染 sharedMaterial 和制造分配。

采样间隔决定运动轨迹密度，生命周期决定屏幕上同时存在数量。最大活跃数近似为生命周期除以采样间隔，需要把 Mesh 容量、快照对象和属性块一起池化；动画快但帧率低时按时间采样比按帧采样稳定。

透明排序、深度写入和后处理会影响轮廓。应在固定相机、背景和动作下比较 ZWrite、渲染队列和混合模式，并在目标移动设备记录 CPU 烘焙时间、顶点数、Overdraw 与内存分配。

## 关键对象与数据流

触发器按时间请求残影，快照池提供空闲 Mesh 与 Renderer，烘焙器写入当前蒙皮网格并复制世界变换，衰减器根据年龄写颜色和透明度，生命周期结束后清空引用并回池。输出是视觉轨迹以及活跃数、烘焙耗时和分配指标。

每次实验只改变一个输入，先保存版本、参数与预期，再比较输出、日志、内存或帧时间。最终结果偶然正确但中间契约不符合预测，仍不能签发，因为隐藏缓存、默认值或执行顺序可能掩盖根因。

## 正常、边界与故障注入

正常样本证明主路径，边界样本说明适用范围，故障样本证明诊断检查确实会在最早契约处拒绝。三类样本必须使用同一观测方式，避免只为成功路径保留证据。

<Callout type="trap">
  **因果陷阱**：复制完整角色会连同
  Animator、脚本和骨架一起运行，效果数量一高就放大 CPU 与内存成本。
</Callout>

<Callout type="trap">
  **边界陷阱**：每次修改 renderer.material
  会创建材质实例，最终看似只有几张残影却积累大量材质。
</Callout>

## 从原书版本迁移到当前 Unity

BakeMesh 与 MaterialPropertyBlock 的核心方案仍可用；SRP 下需要为 URP 或 HDRP 编写兼容透明 Shader，并重新验证深度、阴影和批处理。

VFX Graph 或 GPU 顶点缓存可把大量快照移到 GPU，但会改变资产与调试方式；迁移前后应以同一动作、相机和设备比较视觉与成本。

迁移账本使用五列：原书载体、稳定不变量、当前实现、不可等价处、重放证据。允许 API、插件和渲染管线变化，不允许用新名词删除原章问题或把编辑器成功当成目标平台成功。

## 小结

- 残影只需保存某时刻的可渲染姿态
- 按时间采样比按帧采样稳定
- 属性块避免材质实例化
- 对象池必须同时覆盖对象和动态 Mesh
