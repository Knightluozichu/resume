## 问题：为什么阴影贴图分辨率翻倍，锯齿可能改善，但设备发热和帧时间会明显恶化？

先预测：实时阴影只有一张黑色贴图吗？不是。它要求从光源视角生成遮挡深度，再在接收表面比较当前片元与记录深度，并处理偏移、过滤、裁剪范围和透明度。原书把原理、实现与透明材质处理分开，说明阴影是完整渲染路径而非单个开关。

## 从光源深度到移动端可承受的遮挡证据

Shadow Map 的第一遍从光源视角写深度，第二遍把世界位置变换到光源裁剪空间并比较深度。分辨率、投影视锥和过滤决定有效 texel 密度；范围过大时同样尺寸贴图会把精度浪费在不可见区域。

Bias 抵消自阴影痤疮，但过大造成 Peter Panning；法线偏移对斜面更有效，却可能让细薄几何漂浮。正确调试应显示光源深度、接收坐标和比较值，而不是只拖动滑杆直到看起来顺眼。

移动端预算同时受额外 DrawCall、顶点变换、深度纹理带宽和采样次数影响。小范围角色可用单光阴影、Blob Shadow 或投影纹理，静态环境可烘焙；方案选择由运动遮挡需求和设备基线决定。

透明材质通常不自动把 alpha 作为阴影轮廓。Cutout 可在 ShadowCaster 使用相同 alpha clip，半透明阴影需要额外近似或排序策略。主 Pass 与 ShadowCaster 的 UV、阈值和动画不一致会产生轮廓错位。

## 关键对象与数据流

光源相机裁剪遮挡物并生成深度纹理，接收 Shader 把世界位置投影到该纹理并做带偏移过滤比较，透明材质的 ShadowCaster 复用主材质 alpha 规则。输出是阴影颜色以及深度图、采样坐标、过绘制和 GPU 时间证据。

每次实验只改变一个输入，先保存版本、参数与预期，再比较输出、日志、内存或帧时间。最终结果偶然正确但中间契约不符合预测，仍不能签发，因为隐藏缓存、默认值或执行顺序可能掩盖根因。

## 从原书版本迁移到当前 Unity

书中可能基于 Built-in 管线和自定义投影，现代 URP 提供主光阴影、级联和 Renderer Feature；迁移要保留两遍深度比较原理与移动预算证据。

不同移动 GPU、图形 API 和精度会改变深度伪影，编辑器画面不能代表真机；至少选择低中高三档设备建立可接受阈值。

## 小结

- 实时阴影由光源深度生成和接收比较两遍组成
- 视锥利用率与偏移比单纯分辨率更关键
- 透明物体需要一致的 ShadowCaster 轮廓规则
- 移动端要用真机预算选择阴影方案
