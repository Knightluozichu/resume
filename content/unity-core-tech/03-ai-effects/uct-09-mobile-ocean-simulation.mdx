## 一套波参数驱动视觉、法线和浮力

海水网格提供采样点，顶点密度决定几何波能表达的最高频率。移动端常围绕相机使用有限网格或分环 LOD，把大尺度位移放在顶点，小尺度细节交给法线贴图，避免远处同样高密度。

多个正弦波或 Gerstner 波由方向、波长、幅度、速度和陡度叠加。Gerstner 同时产生水平与垂直位移，陡度过大时会自交。每一分量要使用一致时间和相位，随机参数应固定种子以便回放。

法线可以由波函数偏导推导，也可结合滚动法线纹理。反射、折射、Fresnel、深度颜色和泡沫都增加采样与带宽；移动方案应按设备档位裁剪特性，而不是把桌面水面直接降分辨率。

浮力点查询同一波函数的高度与法线，施加浮力、阻尼和转矩。若 GPU Shader 与 CPU 浮力各写一套近似，参数或时间稍有差异就会穿水；应共享参数并用可对照的简化函数。

风控制波方向与能量，UI 只是修改统一参数集。案例应保存参数快照、设备档位、相机和天气种子，使同一海况可重现，并记录网格顶点数、Shader 变体、GPU 时间和浮力误差。

## 关键对象与数据流

风和海况生成统一 WaveSet，网格系统按相机提供顶点，GPU 用 WaveSet 位移并计算法线与着色，CPU 浮力系统在若干点查询同一时间和参数，UI 修改的也是这份数据。输出是画面、刚体运动和参数快照三条可对照证据。

每次实验只改变一个输入，先保存版本、参数与预期，再比较输出、日志、内存或帧时间。最终结果偶然正确但中间契约不符合预测，仍不能签发，因为隐藏缓存、默认值或执行顺序可能掩盖根因。

## 正常、边界与故障注入

正常样本证明主路径，边界样本说明适用范围，故障样本证明诊断检查确实会在最早契约处拒绝。三类样本必须使用同一观测方式，避免只为成功路径保留证据。

<Callout type="trap">
  **因果陷阱**：GPU 与 CPU 各维护一套波参数或时间，会让水面视觉与浮力长期漂移。
</Callout>

<Callout type="trap">
  **边界陷阱**：为远近海面使用同样网格密度和 Shader
  特性，会把移动端预算浪费在不可见细节。
</Callout>

## 从原书版本迁移到当前 Unity

Built-in、URP 与自定义 SRP 的抓屏、深度和反射接口不同，但统一波模型、网格 LOD、浮力查询与参数快照是稳定核心。

现代设备可用 Compute Shader 或 FFT 海面，但原书移动案例的目标是受控成本；只有真机证据证明收益时才升级模型。

迁移账本使用五列：原书载体、稳定不变量、当前实现、不可等价处、重放证据。允许 API、插件和渲染管线变化，不允许用新名词删除原章问题或把编辑器成功当成目标平台成功。

## 小结

- 网格密度决定可表达波频率
- 视觉和浮力必须共享波参数与时间

- 案例必须连同海况参数一起保存
