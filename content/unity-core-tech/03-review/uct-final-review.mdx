## 直觉引入

这本书从场景管理开始，经过资源管线、渲染管线、物理引擎、音频系统、导航、内存管理、构建部署，把 Unity 的核心技术走了一遍。现在串起来：做一个包含战斗系统的小型 3D 游戏。

这个综合练习会暴露你之前忽略的细节：资源没压缩、DrawCall 没批处理、物理在 Update 里算、GC 每帧几十 KB。每一章的知识都将在项目中得到验证——你会在实践中理解为什么那些优化建议不是废话。

## 概念讲解

全书知识压缩成一条技术路径：<Term def="从项目创建到发布的完整技术流程">技术路径</Term>。

### 完整路径
1. **场景管理**：多场景架构（主场景 + UI 场景 Additive）
2. **资源管线**：Addressables 按需加载、ASTC 压缩
3. **渲染管线**：URP + GPU Instancing + SRP Batcher
4. **物理引擎**：FixedUpdate + Raycast 射击判定
5. **音频系统**：AudioMixer 分轨 + 对象池播放
6. **导航**：NavMesh 烘焙 + Agent 追击
7. **内存管理**：对象池 + GC 零分配
8. **构建部署**：IL2CPP + Stripping + CI/CD

### 性能优化检查表
- Profiler GC Alloc = 0（每帧）
- DrawCall < 100（移动端）
- 纹理全部 ASTC 压缩
- 物理在 FixedUpdate
- 对象池覆盖高频创建对象
- IL2CPP + Stripping

## 代码对照

```csharp
// Unity C#: 综合性能检查脚本
#if UNITY_EDITOR
using UnityEditor;
using UnityEngine;
using UnityEngine.Profiling;

public class PerformanceChecker : EditorWindow
{
    [MenuItem("Tools/Performance Check")]
    static void Check()
    {
        Debug.Log("=== 性能检查报告 ===");

        // 1. DrawCall 检查
        int drawCalls = UnityStats.drawCalls;
        Debug.Log("DrawCall: " + drawCalls +
            (drawCalls < 100 ? " OK" : " WARNING: 超过100"));

        // 2. 纹理内存
        long texMemory = UnityStats.usedTextureMemorySize;
        Debug.Log("纹理内存: " + (texMemory / 1024 / 1024) + "MB");

        // 3. 网格数
        int meshCount = UnityStats.meshes;
        Debug.Log("网格数: " + meshCount);

        // 4. 检查 IL2CPP
        var backend = PlayerSettings.GetScriptingBackend(
            BuildTargetGroup.Android);
        Debug.Log("脚本后端: " + backend +
            (backend == ScriptingImplementation.IL2CPP ? " OK" : " WARNING"));

        // 5. 检查 Stripping
        Debug.Log("代码裁剪: " + PlayerSettings.stripEngineCode);

        Debug.Log("=== 检查完成 ===");
    }
}
#endif
```

## 常见误区

<Callout type="trap">
**现象 →** 项目做到后期帧率掉到 20fps，不知道瓶颈在哪。
**原因 →** 没有用 Profiler 系统性分析。可能是 GC 卡顿、DrawCall 过多、Overdraw 严重、或物理计算太重。
**修法 →** 用 Profiler CPU 模块定位是渲染、物理还是 GC。用 Frame Debugger 分析 DrawCall。逐项排除：先治 GC（对象池），再治 DrawCall（批处理），最后治 Overdraw（减少透明体）。
</Callout>
<Callout type="trap">
**现象 →** 构建后包体 500MB，应用商店拒绝。
**原因 →** 纹理未压缩、音频未编码、代码未裁剪、资源未按需加载。
**修法 →** 纹理全部 ASTC 压缩，音频用 Vorbis，开启 High Stripping，资源用 Addressables 按需加载而非全部打进包。用 Build Report 分析各资源占用。
</Callout>

## 练习

<Exercises>
**问题**：一个 Unity 项目从零到发布的完整技术路径是什么？

<Answer>
1）场景架构设计（多场景 Additive）；2）资源管理（Addressables + ASTC）；3）渲染配置（URP + 批处理）；4）物理交互（FixedUpdate + Raycast）；5）音频管理（AudioMixer + 对象池）；6）导航 AI（NavMesh + Agent）；7）内存优化（对象池 + 零 GC）；8）构建配置（IL2CPP + Stripping）；9）真机测试 + CI/CD 自动化构建发布。
</Answer>

**问题**：全书哪一章的知识在实际项目中影响最大？为什么？

<Answer>
内存管理影响最大。GC 卡顿是最常见的性能杀手——即使场景管理、渲染、物理都做得好，每帧几十 KB 的 GC Alloc 积累到阈值就会卡顿。对象池和零 GC 分配是感觉流畅和感觉卡顿的分水岭。而且 GC 问题往往在项目后期才暴露，返工成本高。
</Answer>
</Exercises>
