## 直觉引入

想象一个邮局。前台收信员（IO 线程）只管收信，不拆信——他的速度极快，每秒处理上千封信。信件按邮编分拣到不同格子里（消息队列），然后投递员（逻辑线程）从格子里取信，按地址送到对应的人手里（Handler）。如果收信员自己拆信、读信、回信，前台早就排长队了。

## 为什么 IO 线程不处理业务

<Term def="IO 线程与逻辑线程分离是游戏服务器的标准架构——IO 线程只负责收发字节，逻辑线程只负责处理消息，两者通过消息队列解耦。">IO 与逻辑分离</Term>有三个核心原因：

1. **防止 IO 阻塞**：业务逻辑可能有数据库查询、复杂计算，如果 IO 线程直接处理，会阻塞 epoll_wait，其他连接全部卡住
2. **线程安全**：逻辑线程单线程串行执行，所有状态修改不需要锁
3. **职责分离**：IO 只管「搬字节」，逻辑只管「跑业务」，各自优化互不影响

## 路由表设计

路由表本质是 `MsgId → Handler` 的哈希映射：

```cpp
// Handler 函数签名
using HandlerFunc = std::function<void(Session*, const char*, int)>;

// 全局路由表
class MessageRouter {
    std::unordered_map<uint16_t, HandlerFunc> m_handlers;

public:
    // 注册：服务启动时调用
    void register_handler(uint16_t msg_id, HandlerFunc handler) {
        m_handlers[msg_id] = std::move(handler);
    }

    // 分发：逻辑线程调用
    void dispatch(Session* session, uint16_t msg_id, const char* data, int len) {
        auto it = m_handlers.find(msg_id);
        if (it != m_handlers.end()) {
            it->second(session, data, len);  // 调用 Handler
        } else {
            LOG_WARN("unknown msg_id=%d from session=%d", msg_id, session->id);
            // 统计未知消息次数，超阈值则断开
            session->inc_unknown_msg_count();
            if (session->unknown_msg_count() > 10) {
                session->kick("too many unknown messages");
            }
        }
    }
};
```

## Handler 注册宏

```cpp
// 用宏自动注册，避免手动维护注册代码
#define REGISTER_HANDLER(msg_id, msg_type, handler_class, handler_func) \
    static bool _reg_##msg_type = []() {                                \
        g_router.register_handler(msg_id,                               \
            [](Session* s, const char* data, int len) {                 \
                msg_type msg;                                           \
                if (!msg.ParseFromArray(data, len)) {                   \
                    LOG_ERROR("parse failed: msg_id=%d", msg_id);       \
                    return;                                             \
                }                                                       \
                handler_class::instance().handler_func(s, msg);         \
            });                                                         \
        return true;                                                    \
    }();

// 使用：在 .cpp 文件中
REGISTER_HANDLER(MSG_CAST_SKILL_REQ, CastSkillReq, CombatHandler, on_cast_skill)
REGISTER_HANDLER(MSG_MATCH_REQ, MatchReq, RoomHandler, on_match)
```

<Callout type="info">
宏在 main() 之前执行（静态变量初始化），自动将 Handler 注册到路由表。启动后路由表只读，查询无锁。
</Callout>

## 无锁消息队列

```cpp
// 单生产者单消费者无锁环形队列（SPSC）
template<typename T, size_t Capacity>
class SpscQueue {
    static_assert((Capacity & (Capacity - 1)) == 0, "Capacity must be power of 2");

    alignas(64) std::atomic<size_t> m_write_pos{0};
    alignas(64) std::atomic<size_t> m_read_pos{0};
    T m_data[Capacity];

public:
    // 生产者（IO 线程）调用
    bool push(const T& item) {
        size_t wp = m_write_pos.load(std::memory_order_relaxed);
        size_t rp = m_read_pos.load(std::memory_order_acquire);
        if (wp - rp >= Capacity) return false;  // 满

        m_data[wp & (Capacity - 1)] = item;
        m_write_pos.store(wp + 1, std::memory_order_release);
        return true;
    }

    // 消费者（逻辑线程）调用
    bool pop(T& item) {
        size_t rp = m_read_pos.load(std::memory_order_relaxed);
        size_t wp = m_write_pos.load(std::memory_order_acquire);
        if (rp == wp) return false;  // 空

        item = m_data[rp & (Capacity - 1)];
        m_read_pos.store(rp + 1, std::memory_order_release);
        return true;
    }
};
```

<Callout type="warning">
`alignas(64)` 防止 false sharing——读写指针在不同 CPU 缓存行上，避免缓存失效导致的性能下降。这是无锁编程的关键细节。
</Callout>

## 完整分发流程

```cpp
// IO 线程：收包 → 推入队列
void io_thread_loop() {
    while (running) {
        int n = epoll_wait(epfd, events, MAX, 100);
        for (int i = 0; i < n; i++) {
            recv_to_ringbuf(events[i].data.fd);
            while (auto pkt = ringbuf.try_pop()) {
                // 推入消息队列
                g_msg_queue.push({session, pkt->msg_id, pkt->body, pkt->len});
            }
        }
    }
}

// 逻辑线程：取消息 → 查路由 → 调 Handler
void logic_thread_loop() {
    while (running) {
        Message msg;
        if (!g_msg_queue.pop(msg)) {
            std::this_thread::sleep_for(std::chrono::microseconds(100));
            continue;
        }
        g_router.dispatch(msg.session, msg.msg_id, msg.data, msg.len);
    }
}
```

<Glossary>
<GlossaryItem term="路由表">MsgId 到 Handler 函数的哈希映射，服务启动时注册，运行时只读查询。</GlossaryItem>
<GlossaryItem term="SPSC 队列">单生产者单消费者无锁队列，用原子操作和内存序实现，适用于 IO 线程→逻辑线程的通信。</GlossaryItem>
<GlossaryItem term="false sharing">多线程修改同一缓存行上的不同变量导致缓存频繁失效，用 alignas(64) 对齐到缓存行可避免。</GlossaryItem>
<GlossaryItem term="内存序">原子操作的可见性约束——acquire 保证后续读不被重排到前面，release 保证前面写不被重排到后面。</GlossaryItem>
</Glossary>

<Answer>
1. 防止 IO 阻塞（业务逻辑慢会卡住事件循环）、线程安全（逻辑单线程不需要锁）、职责分离（IO 搬字节，逻辑跑业务）。消息队列是解耦的缓冲。
2. 路由表是 MsgId→Handler 的哈希映射。启动时用宏注册，运行时查表调用。表是只读的，查询无锁。
3. 用原子操作读写指针，生产者只写 write_pos，消费者只写 read_pos。注意 alignas(64) 防 false sharing，容量 2 的幂用位运算取模，内存序用 acquire/release。
4. 记录警告日志并丢弃，统计未知消息次数超阈值则断开连接（可能是攻击或版本不一致）。必须严格按长度前缀拆包，不能盲目反序列化未知消息体。
</Answer>
