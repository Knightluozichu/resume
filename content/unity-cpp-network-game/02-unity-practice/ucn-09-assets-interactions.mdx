## 最小实现骨架

下面的代码不是原书代码复制，而是用于复现实验的最小骨架。它只表达本章关键所有权，生产实现还要加入错误分类、超时、指标和清理。

```csharp
async Task<GameObject> SpawnAsync(AssetId id)
{
    ManifestEntry entry = manifest.Require(id);
    foreach (AssetId dependency in entry.Dependencies)
        await bundles.AcquireAsync(dependency);
    AssetBundle bundle = await bundles.AcquireAsync(entry.Bundle);
    return Object.Instantiate(bundle.LoadAsset<GameObject>(entry.AssetName));
}
```

状态轨迹必须与代码同时存在：

```text
trace_id,stage,input_version,state_version,owner,budget,decision
baseline-01,规范资源身份,1,1,primary,normal,accept
boundary-01,集成车辆飞行器,1,2,primary,limit,accept
failure-01,卸载恢复后签发,0,2,primary,exceeded,reject
```

验收驱动器每次只改变一个变量，避免同时改变版本、负载和时序后无法定位因果：

```text
for sample in [baseline, boundary, failure]:
  reset_fixture(seed = 20260716)
  run_same_input(sample)
  assert_single_owner()
  assert_bounded_budget()
  export_first_divergence_and_recovery()
```

## 可复现实验

构建两版含共享材质的车辆Bundle，先预测热切换时哪条依赖最易失效，再执行加载、实例化、交互、卸载和回滚并比较清单。 每次运行保存客户端版本、服务端版本、协议或资源摘要、随机种子、样本类型、首偏离节点、恢复动作和最终决策。平均值只能说明趋势，不能证明单次关键状态没有重复或丢失。

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或顺序被绕过">
  按显示名称加载AssetBundle资产，没有稳定ID和清单版本，同名资源在不同包中返回错误对象。
  用同一输入重放修复，保存首偏离状态和拒绝原因；只修到最终画面相同仍不算通过。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  只卸载Bundle句柄，不跟踪实例和依赖引用计数，重复进出场景后内存持续增长或材质变粉。
  必须补充边界和失败样本，证明错误在跨越下一层之前已经停止并留下可恢复证据。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件                 |
| ---- | ---------------------------- | ---------------- | ------------------------ |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端或资源摘要一致       |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无第二份事实，无无限队列 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚     |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏     |

<Ucn09AssetsInteractionsEvidenceLab />

本页签发不变量是：**资源ID稳定；依赖先于主体加载；引用计数不为负；交互由服务器或权威状态确认；卸载后实例不可再访问。**。它必须由轨迹、版本、序号和恢复复测共同证明，不能被一次演示、截图或平均指标替代。
