## 直觉：从问题而不是组件开始

让网关验证授权、绑定连接身份、限制流量并把客户端消息路由到内部服务，同时保持客户端C#与服务器C++协议一致。 本章真正要解决的不是“把API调用出来”，而是让输入经过一条有所有权、有顺序、有预算的状态链，最终产生可解释的输出。先预测：如果只保留最后一张成功截图，最可能漏掉哪一种旧代际、重复执行、资源泄漏或跨线程错误？

## 最小实现骨架

下面的代码不是原书代码复制，而是用于复现实验的最小骨架。它只表达本章关键所有权，生产实现还要加入错误分类、超时、指标和清理。

```cpp
void GateSession::route(const Envelope& envelope) {
    if (!identity_) throw Unauthorized{};
    limiter_.consume(envelope.ByteSizeLong());
    Route route = routes_.require(envelope.message_id());
    envelope.clear_untrusted_player_id();
    route.forward(identity_->player_id(), envelope);
}
```

状态轨迹必须与代码同时存在：

```text
trace_id,stage,input_version,state_version,owner,budget,decision
baseline-01,启动网关框架,1,1,primary,normal,accept
boundary-01,绑定连接身份,1,2,primary,limit,accept
failure-01,进入大厅后签发,0,2,primary,exceeded,reject
```

验收驱动器每次只改变一个变量，避免同时改变版本、负载和时序后无法定位因果：

```text
for sample in [baseline, boundary, failure]:
  reset_fixture(seed = 20260716)
  run_same_input(sample)
  assert_single_owner()
  assert_bounded_budget()
  export_first_divergence_and_recovery()
```

## 可复现实验

让客户端篡改player_id、重复使用票据并以突发速率发送合法消息，先预测认证、路由和限流分别在哪一层拒绝。 每次运行保存客户端版本、服务端版本、协议或资源摘要、随机种子、样本类型、首偏离节点、恢复动作和最终决策。平均值只能说明趋势，不能证明单次关键状态没有重复或丢失。

## 两个必须主动制造的失败

<Callout type="trap" title="所有权或顺序被绕过">
  网关只在首次连接验证票据，后续内部路由信任客户端自带player_id，攻击者可替换身份。
  用同一输入重放修复，保存首偏离状态和拒绝原因；只修到最终画面相同仍不算通过。
</Callout>

<Callout type="trap" title="正常样本掩盖边界错误">
  客户端和服务端分别手工维护消息号，新增协议后编号漂移，合法消息被路由到错误处理器。
  必须补充边界和失败样本，证明错误在跨越下一层之前已经停止并留下可恢复证据。
</Callout>

## 验收矩阵

| 样本 | 输入变化                     | 预期状态         | 通过条件                 |
| ---- | ---------------------------- | ---------------- | ------------------------ |
| 正常 | 合法版本、身份和容量         | 六阶段顺序完成   | 双端或资源摘要一致       |
| 边界 | 临界时序、容量、重复或切换   | 达到预算但不越界 | 无第二份事实，无无限队列 |
| 失败 | 畸形、旧代际、断线或依赖失效 | 在首偏离点停止   | 明确拒绝、补偿或回滚     |
| 恢复 | 修复后重放同一输入           | 收敛到正常轨迹   | 无幽灵状态和资源泄漏     |

<Ucn18GateServerEvidenceLab />

本页签发不变量是：**身份来自已验证连接而非消息体；消息号由单一协议源生成；未认证连接不能路由；每连接队列和速率有上限。**。它必须由轨迹、版本、序号和恢复复测共同证明，不能被一次演示、截图或平均指标替代。
