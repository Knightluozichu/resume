## 直觉引入

匹配系统像一个智能调度员。你说「我要打 5v5」，他记下你的水平和模式（MMR + 模式），放到一个等待池里。先找水平差不多的（±50 分），10 秒没找到就放宽到 ±100 分，30 秒放宽到 ±200 分。凑齐 10 个人后，他给你分配一个空的房间（房间服），告诉你「去这个地址打」。房间有自己的生命周期：等加入→准备→游戏中→结算→销毁。

## MMR 匹配

<Term def="MMR（Matchmaking Rating）是衡量玩家水平的数值，匹配系统根据 MMR 将水平相近的玩家分到同一对局，搜索窗口随等待时间逐步扩大。">MMR 匹配</Term>的核心是搜索窗口的动态扩大：

```cpp
class Matchmaker {
    struct MatchRequest {
        uint64_t player_id;
        int32_t mmr;
        GameMode mode;
        int64_t queue_time;  // 入队时间
    };

    std::vector<MatchRequest> m_queue;

    // 匹配循环（每秒执行）
    void tick() {
        int64_t now = get_time_ms();

        for (auto& req : m_queue) {
            int wait_sec = (now - req.queue_time) / 1000;

            // 搜索窗口随时间扩大
            int mmr_range;
            if (wait_sec < 10) mmr_range = 50;
            else if (wait_sec < 30) mmr_range = 100;
            else if (wait_sec < 60) mmr_range = 200;
            else mmr_range = 9999;  // 全量匹配

            // 找同模式、MMR 范围内的玩家
            auto team = find_team(req, mmr_range, 5);  // 5 人一队
            if (team.size() == 5) {
                auto enemy = find_enemy_team(req, mmr_range, 5);
                if (enemy.size() == 5) {
                    create_room(team, enemy);  // 创建房间
                    remove_from_queue(team);
                    remove_from_queue(enemy);
                }
            }
        }
    }
};
```

<Callout type="info">
搜索窗口扩大的本质是「质量换时间」——等得越久越愿意接受水平差距大的对手。竞技模式慢扩大保质量，休闲模式快扩大保速度。
</Callout>

## 房间状态机

```cpp
enum class RoomState {
    WAITING,      // 等待玩家加入
    READY,        // 准备阶段（选英雄/加载）
    PLAYING,      // 游戏进行中
    SETTLEMENT,   // 结算中
    DESTROYED     // 已销毁
};

class Room {
    RoomState m_state = RoomState::WAITING;
    std::vector<Player*> m_players;
    int64_t m_state_enter_time;

    void change_state(RoomState new_state) {
        LOG_INFO("room %d: %s -> %s", m_id,
                 state_name(m_state), state_name(new_state));
        m_state = new_state;
        m_state_enter_time = get_time_ms();
        on_state_changed(new_state);
    }

    void tick() {
        int64_t now = get_time_ms();
        switch (m_state) {
            case RoomState::WAITING:
                if (m_players.size() == max_players) {
                    change_state(RoomState::READY);
                }
                break;

            case RoomState::READY:
                if (all_ready() || now - m_state_enter_time > 60000) {
                    change_state(RoomState::PLAYING);
                }
                break;

            case RoomState::PLAYING:
                if (check_game_over() || now - m_state_enter_time > 1800000) {
                    change_state(RoomState::SETTLEMENT);
                }
                // 定期快照（崩溃恢复用）
                if (now % 5000 == 0) save_snapshot();
                break;

            case RoomState::SETTLEMENT:
                if (all_acknowledged() || now - m_state_enter_time > 30000) {
                    change_state(RoomState::DESTROYED);
                }
                break;

            case RoomState::DESTROYED:
                cleanup();  // 清理资源、上报数据
                break;
        }
    }
};
```

## 大厅-房间服分离

```
┌──────────────┐    分配房间     ┌──────────────┐
│  大厅服务器   │ ──────────────→ │  房间服 A     │
│  匹配/社交    │                 │  房间 1-100   │
│  商店/背包    │  ←── 结果上报 ── │              │
└──────────────┘                 └──────────────┘
       │                         ┌──────────────┐
       │  分配房间                │  房间服 B     │
       └────────────────────────→ │  房间 101-200│
                                 └──────────────┘
```

```cpp
// 大厅服：匹配成功后分配房间服
void LobbyServer::on_match_success(const Team& team1, const Team& team2) {
    // 找负载最低的房间服
    auto* room_server = find_least_loaded_room_server();
    if (!room_server) {
        // 动态启动新房间服
        room_server = start_new_room_server();
    }

    // 创建房间
    uint32_t room_id = room_server->create_room(team1, team2);

    // 通知玩家连接房间服
    for (auto* player : team1 + team2) {
        RoomEnterNotify notify;
        notify.set_room_id(room_id);
        notify.set_server_addr(room_server->addr());
        send_packet(player, MSG_ROOM_ENTER, notify);
    }
}

// 玩家直连房间服（不经过大厅）
void on_room_enter(const RoomEnterNotify& notify) {
    // 断开大厅连接，连接房间服
    lobby_conn->disconnect();
    room_conn->connect(notify.server_addr());
    room_conn->send(MSG_ROOM_ENTER_REQ, notify.room_id());
}
```

## 崩溃恢复

```cpp
// 房间服定期快照到 Redis
void Room::save_snapshot() {
    RoomSnapshot snap;
    snap.set_room_id(m_id);
    snap.set_state(m_state);
    snap.set_game_time(get_game_time());
    for (auto* p : m_players) {
        snap.add_players(p->serialize());
    }
    // 存入 Redis（TTL 10 分钟）
    redis_setex("room_snapshot:" + std::to_string(m_id), 600,
                snap.SerializeAsString());
}

// 大厅检测房间服崩溃 → 启动新房间服 → 加载快照
void LobbyServer::on_room_server_crash(RoomServer* dead) {
    LOG_ERROR("room server %s crashed, recovering...", dead->addr());

    // 启动新房间服
    auto* new_server = start_new_room_server();

    // 恢复该房间服上的所有房间
    for (uint32_t room_id : dead->room_ids()) {
        auto snap_data = redis_get("room_snapshot:" + std::to_string(room_id));
        if (snap_data) {
            RoomSnapshot snap;
            snap.ParseFromString(*snap_data);
            new_server->restore_room(snap);
            // 通知玩家连接新房间服
            notify_players_reconnect(snap);
        }
    }
}
```

<Callout type="warning">
快照间隔越短丢失越少但 Redis 压力越大。5 秒快照 + 关键事件（击杀/得分）即时快照是常见折衷。恢复期间游戏暂停 5-10 秒，恢复后从快照时间点继续。
</Callout>

<Glossary>
<GlossaryItem term="MMR">Matchmaking Rating，衡量玩家水平的数值，匹配系统据此将水平相近的玩家分到同一对局。</GlossaryItem>
<GlossaryItem term="搜索窗口">匹配时允许的 MMR 差值范围，随等待时间从 ±50 扩大到全量。</GlossaryItem>
<GlossaryItem term="房间服">运行具体对局逻辑的服务器进程，玩家直连不经过大厅，崩溃只影响本房间玩家。</GlossaryItem>
<GlossaryItem term="快照恢复">定期将对局状态序列化到 Redis，房间服崩溃后新进程加载快照恢复对局。</GlossaryItem>
</Glossary>

<Exercises>
1. MMR 匹配的搜索窗口为什么要随时间扩大？不扩大会怎样？
2. 大厅服务器和房间服务器为什么要分离？不能一个服务器搞定吗？
3. 描述一个房间从创建到销毁的完整生命周期。
4. 房间服在对局中途崩溃，如何实现无缝恢复？
</Exercises>

<Answer>
1. 高段位玩家匹配池小，窗口不变可能等 10 分钟匹配不到人。扩大是「质量换时间」的折衷——等越久越接受水平差距大的对手。不扩大导致高段位流失率高。
2. ① 职责不同（大厅全局逻辑 vs 房间对局逻辑）；② 资源隔离（房间服崩溃不影响大厅和其他房间）；③ 弹性扩容（高峰期动态增减房间服）；④ 减少延迟（玩家直连房间服不经大厅转发）。
3. WAITING（等加入）→ READY（准备/选英雄）→ PLAYING（对局）→ SETTLEMENT（结算/发奖励）→ DESTROYED（清理资源）。每个状态有超时机制防卡死。
4. ① 定期快照存 Redis（5 秒 + 关键事件即时）；② 大厅心跳检测崩溃；③ 启动新房间服加载快照；④ 通知玩家连接新地址；⑤ 发送快照恢复状态，游戏从快照时间点继续。恢复期间暂停 5-10 秒。
</Answer>
