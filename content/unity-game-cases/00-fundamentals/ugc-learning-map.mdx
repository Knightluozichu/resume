## 直觉引入

做游戏最大的误区是「我要做一个什么都能做的游戏」。现实是：每种游戏类型有自己的技术栈和设计模式。2D 平台跳跃需要精确的物理碰撞和关卡设计；3D 动作游戏需要连招系统和摄像机控制；RPG 需要背包系统和对话系统；FPS 需要射线检测和 AI。

这本书用 8 种游戏类型作为案例：2D 平台、3D 动作、RPG、FPS、策略、益智、赛车，最后是游戏打磨与发布。每种类型从核心玩法出发，拆解系统设计和技术实现，让你理解「为什么这个类型用这个技术方案」。

## 概念讲解

全书分四个阶段：**入门**（2D/3D 基础）、**进阶**（RPG/FPS）、**拓展**（策略/益智/赛车）、**收尾**（打磨发布）。

<Term def="游戏的核心交互循环，玩家反复执行的最小行为单元">核心玩法</Term>决定一切技术选型。<Term def="2D 游戏中角色移动和碰撞检测的物理系统">平台物理</Term>是 2D 游戏的基础。<Term def="3D 动作游戏中连续攻击的招式系统">连招系统</Term>是动作游戏的灵魂。<Term def="FPS 游戏中用射线检测命中而非物理子弹的射击方式">Raycast 射击</Term>是 FPS 的核心。

<Stepper>
<Step title="第一步：定类型">
先确定要做什么类型的游戏。不同类型的技术栈差异巨大：2D 用 Tilemap+Sprite，3D 用 Mesh+Animation，FPS 用 Raycast+Controller。选错技术栈后期无法回头。
</Step>
<Step title="第二步：做原型">
用最简单的方式实现核心玩法循环。2D 平台：能跑能跳。3D 动作：能打怪。RPG：能拾取装备。先跑通核心循环再加内容。
</Step>
<Step title="第三步：打磨发布">
加音效、特效、UI、关卡。用对象池和批处理优化性能。构建到目标平台测试。这个阶段占整个项目时间的 50%。
</Step>
</Stepper>

## 代码对照

```csharp
// Unity C#: 游戏类型核心代码模式对比
// 2D 平台: Tilemap + Rigidbody2D
public class PlatformerPlayer : MonoBehaviour {
    private Rigidbody2D rb;
    void FixedUpdate() {
        rb.velocity = new Vector2(Input.GetAxis("Horizontal") * speed,
            rb.velocity.y);
        if (Input.GetKeyDown(KeyCode.Space) && IsGrounded())
            rb.AddForce(Vector2.up * jumpForce, ForceMode2D.Impulse);
    }
}

// 3D 动作: Animator + Combo
public class ActionPlayer : MonoBehaviour {
    private Animator anim;
    private int comboCount = 0;
    void Update() {
        if (Input.GetMouseButtonDown(0)) {
            comboCount = (comboCount + 1) % 3;
            anim.SetTrigger("Attack" + comboCount);
        }
    }
}

// FPS: Raycast 射击
public class FPSShooter : MonoBehaviour {
    void Update() {
        if (Input.GetMouseButtonDown(0)) {
            Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);
            if (Physics.Raycast(ray, out var hit, 100f))
                hit.collider.SendMessage("TakeDamage", 10);
        }
    }
}
```

## 常见误区

<Callout type="trap">
**现象 →** 想做一个包含所有类型的游戏，结果什么都做不好。
**原因 →** 没有聚焦核心玩法，试图把平台跳跃、RPG、FPS 全塞进一个游戏。
**修法 →** 先确定一个核心玩法，做到极致。成功的游戏都是一种类型做到最好：超级马里奥只有平台跳跃，暗黑破坏神只有 ARPG。类型可以混搭但必须有主次。
</Callout>
<Callout type="trap">
**现象 →** 技术选型错误，项目后期推倒重来。
**原因 →** 2D 游戏用了 3D 物理，或者 FPS 用了物理子弹而非 Raycast。
**修法 →** 每种类型有成熟的技术方案。2D 用 Rigidbody2D+Tilemap，3D 动作用 Animator 状态机，FPS 用 Raycast。开始前研究同类游戏的技术方案，选对技术栈。
</Callout>

## 练习

<Exercises>
**问题**：为什么做游戏要先定类型再定技术？

<Answer>
不同游戏类型的技术栈差异巨大。2D 平台用 Tilemap+Rigidbody2D，3D 动作用 Animator+Mesh，FPS 用 Raycast+CharacterController。如果先写代码再定类型，大概率技术栈不匹配，后期推倒重来。定类型等于定技术方向，是项目的第一个决策点。
</Answer>

**问题**：全书 8 种游戏类型的核心玩法分别是什么？

<Answer>
2D 平台：跳跃+关卡；3D 动作：连招+战斗；RPG：成长+装备；FPS：射击+AI；策略：资源+指挥；益智：规则+消除；赛车：速度+赛道。每种玩法决定技术方案：平台要精确物理，动作要动画状态机，RPG 要数据驱动，FPS 要 Raycast。
</Answer>
</Exercises>
