## 直觉引入

RPG 的核心是「成长」——角色通过装备、技能、属性变强。这背后是大量的数据：100 种武器、50 种防具、200 种消耗品。如果把这些数据硬编码在脚本里，修改需要改代码重新编译。ScriptableObject 让数据独立于代码——在 Inspector 中编辑，运行时加载，策划不改代码就能调数值。

背包系统是 RPG 的 UI 核心：拖拽移动、堆叠、使用、丢弃。对话系统则让 NPC 活起来——分支选择、条件判断、任务触发。

## 概念讲解

<Term def="Unity 的数据资产类型，将数据与代码分离，在 Inspector 中编辑">ScriptableObject</Term>是 RPG 数据的基础。

<Term def="管理玩家持有物品的系统，支持添加/删除/堆叠/使用">背包系统</Term>是 RPG 的 UI 核心。

<Term def="NPC 对话的分支选择系统，支持条件和任务触发">对话系统</Term>让 NPC 有故事。

### ScriptableObject vs MonoBehaviour
| | ScriptableObject | MonoBehaviour |
|---|---|---|
| 存储 | 资产文件 | 场景对象 |
| 内存 | 一份共享 | 每个实例一份 |
| 编辑 | Inspector | 运行时 |
| 适用 | 数据定义 | 行为逻辑 |

<Term def="RPG 中角色变强的机制，包括升级、装备、技能">成长系统</Term>是 RPG 的核心循环。

## 代码对照

```csharp
// Unity C#: RPG 物品与背包系统
using UnityEngine;
using System.Collections.Generic;

// 物品数据 (ScriptableObject)
[CreateAssetMenu(fileName = "New Item", menuName = "RPG/Item")]
public class ItemData : ScriptableObject
{
    public string itemName;
    public Sprite icon;
    public ItemCategory category;
    public int maxStack = 99;
    public bool consumable = true;

    [Header("属性加成")]
    public int attack;
    public int defense;
    public int health;

    public virtual void Use(GameObject target)
    {
        if (consumable)
        {
            // 使用消耗品
            var stats = target.GetComponent<CharacterStats>();
            if (stats != null)
            {
                stats.health += health;
                stats.attack += attack;
                stats.defense += defense;
            }
        }
    }
}

public enum ItemCategory { Weapon, Armor, Consumable, Material }

// 背包系统
public class Inventory : MonoBehaviour
{
    public int maxSlots = 30;
    private List<InventorySlot> slots = new List<InventorySlot>();

    // 添加物品
    public bool AddItem(ItemData item, int count = 1)
    {
        // 先尝试堆叠
        var existing = slots.Find(s => s.item == item && s.count < item.maxStack);
        if (existing != null)
        {
            existing.count += count;
            return true;
        }

        // 再尝试放空槽
        if (slots.Count < maxSlots)
        {
            slots.Add(new InventorySlot { item = item, count = count });
            return true;
        }
        return false; // 背包满了
    }

    // 删除物品
    public void RemoveItem(ItemData item, int count = 1)
    {
        var slot = slots.Find(s => s.item == item);
        if (slot != null)
        {
            slot.count -= count;
            if (slot.count <= 0)
                slots.Remove(slot);
        }
    }
}

public class InventorySlot
{
    public ItemData item;
    public int count;
}

// 角色属性
public class CharacterStats : MonoBehaviour
{
    public int health = 100;
    public int attack = 10;
    public int defense = 5;
    public int level = 1;
    public int exp = 0;

    public void GainExp(int amount)
    {
        exp += amount;
        if (exp >= level * 100)
        {
            level++;
            exp = 0;
            health += 20;
            attack += 5;
            defense += 3;
        }
    }
}
```

## 常见误区

<Callout type="trap">
**现象 →** 修改物品数值要改代码重新编译，策划无法独立调数值。
**原因 →** 物品数据硬编码在脚本类中，不是 ScriptableObject。
**修法 →** 把物品数据定义为 ScriptableObject，在 Inspector 中编辑数值。策划创建和修改物品资产不需要改代码。运行时只加载一份，内存效率高。
</Callout>
<Callout type="trap">
**现象 →** 背包 UI 拖拽不跟手，拖到格子外物品消失。
**原因 →** 拖拽逻辑写在 Update 里用鼠标位置判断，不够精确。没有处理拖拽失败的情况。
**修法 →** 用 EventSystem 的 IDragHandler/IDropHandler/IDragEndHandler 接口。OnDrag 跟随鼠标，OnDrop 判断目标格子交换物品，OnEndDrag 无效目标时回原位。
</Callout>

## 练习

<Exercises>
**问题**：为什么 RPG 用 ScriptableObject 而非直接写类？

<Answer>
ScriptableObject 把数据存为资产文件，三个优势：1）数据与代码分离，策划在 Inspector 编辑数值不需改代码；2）内存中只有一份实例，100 把剑共享一个 ScriptableObject 而非 100 个 MonoBehaviour；3）可以动态加载和保存，支持 mod 和 DLC。直接写类则数据在代码里，修改需编译，每个实例独立占内存。
</Answer>

**问题**：背包系统的堆叠和拖拽怎么实现？

<Answer>
堆叠：相同 ItemData 的物品 count+1，不超过 maxStack。超过则放新格子。拖拽：实现 IDragHandler/IDropHandler 接口。OnDrag 物品图标跟随鼠标。OnDrop 检查目标格子——空格子直接放入，有相同物品则堆叠，有不同物品则交换。OnEndDrag 无效目标时回原位。
</Answer>
</Exercises>
