## 直觉引入

这本书用 8 种游戏类型作为案例——2D 平台、3D 动作、RPG、FPS、策略、益智、赛车，加上打磨发布。每种类型有独特的技术栈和设计模式。现在串起来：如果你要做一个新游戏，应该怎么选类型、怎么定技术、怎么做到发布。

核心思路是「先定类型再定技术」。2D 平台用 Tilemap+Rigidbody2D，3D 动作用 Animator 状态机，RPG 用 ScriptableObject，FPS 用 Raycast，策略用网格+A*，益智用状态机+规则引擎，赛车用 WheelCollider。选错技术栈后期无法回头。

### 完整游戏开发流程
1. **定类型**：确定核心玩法和游戏类型
2. **定技术**：根据类型选技术栈
3. **做原型**：最快实现核心玩法循环
4. **做内容**：加关卡/敌人/装备
5. **打磨**：性能优化+UX 反馈
6. **发布**：构建+真机测试+商店

### 技术选型速查
| 类型 | 核心技术 | 关键系统 |
|---|---|---|
| 2D 平台 | Tilemap+Rigidbody2D | Coyote Time |
| 3D 动作 | Animator 状态机 | 连招+Cinemachine |
| RPG | ScriptableObject | 背包+对话 |
| FPS | Raycast | AI+CharacterController |
| 策略 | 网格+A* | 框选+寻路 |
| 益智 | 状态机+协程 | 匹配+连锁 |
| 赛车 | WheelCollider | 赛道+Waypoint |

## 常见误区

<Callout type="trap">
**现象 →** 做了 3 个月还不知道游戏好不好玩。
**原因 →** 先做内容再做核心玩法，没有先验证核心循环是否有趣。
**修法 →** 先做原型：1 周内实现核心玩法循环（能跑能跳/能打怪/能射击），找朋友试玩。不好玩就换方向，好笑再投入做内容。原型阶段省下的 3 个月比后面改设计省的多。
</Callout>
<Callout type="trap">
**现象 →** 项目后期发现技术栈不对，推倒重来。
**原因 →** 开始时没研究同类游戏的技术方案，选错了技术栈。
**修法 →** 开始前研究同类成功游戏的技术方案：2D 平台用 Tilemap，3D 动作用 Animator，FPS 用 Raycast。每种类型有成熟方案，不要自己发明轮子。技术栈一旦选定后期很难换。
</Callout>

<Exercises>
**问题**：从想法到发布的完整游戏开发流程是什么？

<Answer>
1）定类型：确定核心玩法和游戏类型（2D 平台/3D 动作/RPG/FPS 等）；2）定技术：根据类型选技术栈（Tilemap/Animator/Raycast 等）；3）做原型：1 周内实现核心玩法循环，验证好玩；4）做内容：加关卡/敌人/装备/音效/特效；5）打磨：性能优化（对象池+批处理）+UX 反馈（震屏+缓动）；6）发布：IL2CPP 构建+真机测试+提交商店。打磨和发布占 50% 时间。
</Answer>

**问题**：全书 8 种游戏类型的技术选型有什么规律？

<Answer>
规律是「核心玩法决定技术方案」。2D 平台需要精确物理→Tilemap+Rigidbody2D+Coyote Time。3D 动作需要流畅连招→Animator 状态机+取消窗口+Cinemachine。RPG 需要数据驱动→ScriptableObject+背包+对话。FPS 需要即时射击→Raycast+CharacterController+AI 状态机。策略需要网格寻路→Grid+A*+框选。益智需要规则流程→状态机+协程+连锁。赛车需要车辆物理→WheelCollider+赛道+Waypoint。
</Answer>
