## 直觉引入

你开车时看仪表盘，速度指针必须实时跟车速走，不能卡顿更不能跳变。这就是 HMI——人和机器之间的信息桥梁。它不是炫技的画布，而是严肃的信息传达工具。

如果仪表盘像游戏 UI 那样偶尔掉帧或延迟，司机可能误判速度导致事故。HMI 的核心矛盾是：信息要快，但不能乱；界面要美，但不能误导。

## 概念讲解

### 什么是 HMI

<UhmHmiBasicsDiagram />

<Term def="人机交互界面，强调实时数据展示与可靠操作响应">HMI</Term> 的全称是 Human-Machine Interface，泛指所有让人操作和监视机器的界面。车载仪表盘、工业控制面板、医疗设备屏幕都是 HMI。

<Term def="界面更新的最大可接受延迟，超过则视为不可用">实时性约束</Term>是 HMI 最重要的特征。车载 HMI 要求数据从产生到显示的延迟不超过 100ms，工业 HMI 的操作响应要求在 50ms 以内。

HMI 与游戏 UI 的核心区别在于：游戏 UI 追求视觉体验，HMI 追求信息传达效率与操作可靠性。HMI 的每个像素都有明确的含义，每次刷新都有数据来源。

        rpmText.text = $"{rpm:F0}";
    }

## 常见误区

<Callout type="trap">
**现象：用 Update 每帧刷新所有 UI 元素。**
原因：HMI 数据更新频率远低于渲染帧率，每帧刷新全部 UI 会浪费性能并可能造成闪烁。修法：使用数据变化检测（脏标记或事件驱动），仅在数据真正变化时更新对应 UI 元素。
</Callout>

<Callout type="trap">
**现象：UI 布局不考虑信息层级，所有元素同等大小。**
原因：HMI 的核心是信息传达，关键信息（如车速、警告）必须比次要信息（如时间、温度）更醒目。修法：建立三级信息层级——紧急（红色大字）、重要（高对比度）、辅助（小字低对比度），按层级分配视觉权重。
</Callout>

<Exercises>
**问题 1**：HMI 的三大约束是什么？为什么它们比视觉效果更重要？

<Answer>
实时性（数据延迟低于阈值）、安全性（界面不能崩溃或显示错误数据）、确定性（相同输入产生相同输出）。这三者比视觉效果重要是因为 HMI 面向安全关键场景——仪表盘卡顿可能导致司机误判速度，控制面板显示错误可能导致工业事故。视觉效果服务于信息传达，而不是反过来。
</Answer>

**问题 2**：为什么不建议在 Update 中每帧刷新所有 UI？

<Answer>
HMI 数据更新频率通常在 10-50Hz，而渲染帧率在 60-120Hz。每帧刷新所有 UI 会造成大量无效操作——数据没变也刷新，浪费 CPU 和 GPU 资源。正确做法是使用脏标记或事件驱动机制，仅在数据源变化时更新对应 UI 元素。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="HMI">人机交互界面（Human-Machine Interface），连接用户与机器系统的可视化操作层，强调实时性和可靠性。</GlossaryItem>
<GlossaryItem term="实时性约束">界面更新的最大可接受延迟，车载 HMI 通常要求不超过 100ms，工业 HMI 要求 50ms 以内。</GlossaryItem>
<GlossaryItem term="脏标记">一种优化策略，仅当数据被标记为「脏」（已变化）时才触发 UI 更新，避免无效刷新。</GlossaryItem>
<GlossaryItem term="信息层级">HMI 中按重要性划分的视觉优先级体系，通常分为紧急、重要、辅助三级，确保关键信息最先被用户注意到。</GlossaryItem>
</Glossary>
