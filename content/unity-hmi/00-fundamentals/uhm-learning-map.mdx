## 直觉引入

想象你在造一辆智能汽车的仪表盘。先学仪表盘是什么（HMI 基础），再学怎么布局按钮和文字（UI 框架），然后学怎么让数据实时更新到屏幕上（数据绑定），接着学怎么让界面动起来（动画），最后学怎么让界面响应触摸和旋钮（输入处理）。

全书核心线索是：先理解「界面是什么」，再学「怎么搭界面」，然后学「怎么驱动界面」，最后学「怎么优化和发布界面」。

## 概念讲解

### 全书结构

<UhmLearningMapDiagram />

<Term def="人机交互界面，连接用户与机器系统的可视化操作层">HMI</Term>（Human-Machine Interface）的核心任务：采集数据 → 绑定到 UI → 渲染显示 → 响应交互 → 持续更新。

全书分四大板块：基础入门（HMI 概念/UI 框架）→ 核心技能（数据绑定/动画/输入）→ 高级实践（性能/部署/高级 HMI）→ 总复习。呈「概念→实现→优化→发布」的递进关系。

    [SerializeField] private Text speedText;

    public float Speed

        set { _speed = value; speedText.text = $"{value:F0} km/h"; }
    }

## 常见误区

<Callout type="trap">
**现象：把 HMI 当普通游戏 UI 做。**
原因：HMI 面向工业/车载场景，有实时性、安全性、确定性约束，不能用游戏 UI 的随意刷新策略。修法：从第一章就建立 HMI 与游戏 UI 的边界认知，数据刷新频率和渲染策略要按 HMI 标准设计。
</Callout>

<Callout type="trap">
**现象：跳过数据绑定直接学动画。**
原因：数据绑定是 HMI 的核心——没有数据驱动，动画只是空壳。修法：严格按学习路径走，先掌握数据绑定再学动画，理解「数据变化触发动画」的因果关系。
</Callout>

<Exercises>
**问题 1**：全书四大板块是什么？它们之间是什么关系？

<Answer>
基础入门、核心技能、高级实践、总复习。呈递进关系：基础入门提供 HMI 概念和 UI 框架认知，核心技能建立数据驱动和交互能力，高级实践实现性能优化和部署上线，总复习串联全部知识点。
</Answer>

**问题 2**：为什么说「UI 是门面，数据是灵魂，性能是底线」？

<Answer>
UI 是用户直接看到和操作的界面层，是 HMI 的外在表现。数据是驱动 UI 变化的核心——仪表盘的数值、状态指示灯的变化都来自底层数据源。性能是 HMI 可用性的底线——车载 HMI 要求稳定帧率，工业 HMI 要求低延迟响应，性能不达标可能导致安全事故。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="HMI">人机交互界面（Human-Machine Interface），连接用户与机器系统的可视化操作层，常见于车载仪表盘、工业控制面板等场景。</GlossaryItem>
<GlossaryItem term="数据绑定">将数据源的值自动同步到 UI 显示的机制，数据变化时 UI 自动更新，无需手动刷新。</GlossaryItem>
<GlossaryItem term="UI 框架">Unity 提供的构建用户界面的工具集，包括 Canvas、Text、Image、Button 等组件和布局系统。</GlossaryItem>
<GlossaryItem term="渲染管线">从场景数据到屏幕像素的处理流程，HMI 中通常需要定制渲染策略以满足性能和视觉要求。</GlossaryItem>
</Glossary>
