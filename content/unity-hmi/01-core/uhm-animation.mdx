## 直觉引入

仪表盘指针从 0 转到 120，不是瞬间跳过去的——那样用户会以为数据错误。它需要一个平滑的过渡，让用户感知到「速度在上升」。这就是 HMI 动画：不是炫技，而是让数据变化变得可感知。

HMI 动画的核心原则是「快而准」：过渡要够快（100-300ms），不能让用户等；要够准（缓动曲线合理），不能让用户误读数据。

## 概念讲解

### Tween 与 Animator

<UhmAnimationDiagram />

<Term def="通过代码插值属性值实现的轻量动画，适合简单的位移/缩放/透明度过渡">Tween 动画</Term>不需要 Animator 组件，直接用代码控制。HMI 中 90% 的动画用 Tween 实现。

<Term def="基于状态机和动画层的动画系统，适合复杂的角色动画和多状态切换">Animator</Term> 适合复杂的多状态动画，但在 HMI 中通常过重。简单的界面过渡用 Tween 更高效。

### 缓动曲线

<Term def="控制动画速度随时间变化的数学函数，决定动画的节奏感">缓动曲线</Term>是动画的灵魂。HMI 常用三种：Ease Out（快进慢出，适合出现）、Ease In（慢进快出，适合消失）、Ease In Out（慢进慢出，适合状态切换）。

## 代码对照

```csharp
// HMI 动画核心：数据驱动的 Tween 过渡
public class HmiAnimator : MonoBehaviour
{
    [SerializeField] private RectTransform needle;
    private float _currentAngle = 0f;
    
    // 数据变化时自动触发动画
    public void SetSpeed(float targetSpeed)
    {
        float targetAngle = Mathf.Lerp(0f, 270f, targetSpeed / 240f);
        // Tween：100ms Ease Out 过渡
        StopAllCoroutines();
        StartCoroutine(TweenAngle(_currentAngle, targetAngle, 0.15f));
    }
    
    IEnumerator TweenAngle(float from, float to, float duration)
    {
        float t = 0;
        while (t < duration)
        {
            t += Time.deltaTime;
            float eased = 1f - Mathf.Pow(1f - t / duration, 3f); // Ease Out Cubic
            _currentAngle = Mathf.Lerp(from, to, eased);
            needle.rotation = Quaternion.Euler(0, 0, -_currentAngle);
            yield return null;
        }
    }
}
```

## 常见误区

<Callout type="trap">
**现象：动画时长超过 500ms。**
原因：HMI 动画不是电影特效，用户需要快速读取信息。过长动画会让用户等待，违反实时性约束。修法：界面过渡控制在 100-300ms，数据指示器控制在 50-150ms。超过 300ms 的动画只在非关键信息上使用。
</Callout>

<Callout type="trap">
**现象：用 Animator 做简单的界面过渡。**
原因：Animator 有状态机开销和初始化成本，对简单过渡来说过重。修法：简单透明度/位移/缩放过渡用 Tween 代码实现，只有复杂多状态切换才用 Animator。HMI 的原则是「够用就好，不过度设计」。
</Callout>

<Exercises>
**问题 1**：Tween 动画和 Animator 动画在 HMI 中如何选择？

<Answer>
Tween 适合简单属性过渡（位移、旋转、缩放、透明度），无需 Animator 组件，代码直接控制，轻量高效。Animator 适合复杂的多状态动画和动画层混合。HMI 中 90% 的动画是简单过渡，用 Tween；只有需要状态机管理复杂动画流时才用 Animator。选择原则是「够用就好，不过度设计」。
</Answer>

**问题 2**：HMI 动画为什么不能太长？推荐时长是多少？

<Answer>
HMI 的核心是信息传达，动画太长会让用户等待，违反实时性约束。用户看仪表盘是为了读数据，不是看动画。推荐时长：界面过渡 100-300ms，数据指示器 50-150ms。超过 300ms 的动画只用于非关键信息（如页面切换），关键数据指示器的动画必须快速完成，确保用户能及时读取最新值。
</Answer>
</Exercises>
