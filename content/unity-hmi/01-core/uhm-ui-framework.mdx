## 直觉引入

搭 HMI 界面就像搭积木。Canvas 是桌面，所有积木都放在上面。RectTransform 是每块积木的尺寸和位置说明书。布局组件（Layout Group）是让你把积木自动排列整齐的规则。

没有布局系统，你得手动算每个按钮的坐标。界面一改，全部重来。有了布局系统，加一个按钮，其他按钮自动让位。

## 概念讲解

### Canvas 与渲染模式

<UhmUiFrameworkDiagram />

<Term def="Unity UI 的根容器，所有 UI 元素必须挂在 Canvas 下才能渲染">Canvas</Term> 有三种渲染模式：Screen Space Overlay（覆盖在画面最上层）、Screen Space Camera（由特定摄像机渲染）、World Space（存在于 3D 世界中）。

<Term def="UGUI 专用的变换组件，用锚点和轴心点控制 UI 元素的位置和缩放">RectTransform</Term> 是 Transform 的子类，增加了宽高、锚点和轴心点。锚点决定了 UI 元素在父容器缩放时的对齐方式。

### 布局组件

HMI 界面通常用三种布局组件：`HorizontalLayoutGroup`（水平排列）、`VerticalLayoutGroup`（垂直排列）、`GridLayoutGroup`（网格排列）。它们自动计算子元素位置，无需手动设坐标。

## 代码对照

```csharp
// 动态创建 HMI 布局
public class HmiLayoutBuilder : MonoBehaviour
{
    [SerializeField] private Canvas canvas;
    
    void BuildDashboard()
    {
        // 创建垂直布局容器
        var panel = new GameObject("DashboardPanel");
        panel.transform.SetParent(canvas.transform, false);
        var vlg = panel.AddComponent<VerticalLayoutGroup>();
        vlg.spacing = 8;
        vlg.padding = new RectOffset(20, 20, 20, 20);
        
        // 添加自适应大小
        var fitter = panel.AddComponent<ContentSizeFitter>();
        fitter.verticalFit = ContentSizeFitter.FitMode.PreferredSize;
    }
}
```

## 常见误区

<Callout type="trap">
**现象：所有 UI 元素都用固定坐标定位。**
原因：固定坐标在不同分辨率下会错位。修法：使用锚点和布局组件，让 UI 元素根据父容器自动定位和缩放。HMI 通常需要适配多种屏幕规格，固定坐标是维护噩梦。
</Callout>

<Callout type="trap">
**现象：Canvas 嵌套层级过深，超过 10 层。**
原因：每多一层 Canvas 重建成本指数增长。修法：将频繁更新的 UI 元素放在独立子 Canvas 中，减少主 Canvas 的重建范围。HMI 界面应控制在 3-5 层以内。
</Callout>

<Exercises>
**问题 1**：Canvas 的三种渲染模式是什么？HMI 通常用哪种？

<Answer>
Screen Space Overlay（UI 覆盖在画面最上层，不受摄像机影响）、Screen Space Camera（由指定摄像机渲染，可加后处理）、World Space（UI 存在于 3D 世界中，可被遮挡）。HMI 通常用 Screen Space Camera，因为需要精确控制渲染层级和后处理效果。
</Answer>

**问题 2**：为什么要把频繁更新的 UI 元素放在独立子 Canvas 中？

<Answer>
Canvas 重建时，会重新计算所有子元素的网格和顶点。如果所有 UI 都在一个 Canvas 下，一个数值变化会导致整个界面重建。把频繁更新的元素（如实时数值显示）拆到独立子 Canvas，重建范围被限制在子 Canvas 内，主 Canvas 不受影响，大幅降低性能开销。
</Answer>
</Exercises>
