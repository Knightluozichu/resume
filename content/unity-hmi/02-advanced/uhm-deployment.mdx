## 直觉引入

把 HMI 应用发布到车载屏幕上，不像发手机 App 那样简单。车规级系统有严格的安全认证、启动时间要求和长期运行稳定性约束。你的界面不仅要在屏幕上跑起来，还要在点火后 2 秒内就显示。

HMI 部署的核心矛盾是：功能要全，但启动要快；界面要美，但资源要小；运行要稳，但还要支持远程更新。

## 概念讲解

### 部署流程

<UhmDeploymentDiagram />

<Term def="将 Unity 工程构建为目标平台可执行包的过程，包括资源压缩、脚本编译和平台适配">构建发布</Term>是 HMI 开发的最后一公里。车载平台通常用 Android Automotive 或嵌入式 Linux，工业平台用 Windows IoT 或定制 Linux。

<Term def="远程空中下载更新，HMI 通过网络下载新版本固件并安装">OTA</Term>（Over-The-Air）是现代 HMI 的必备能力。车辆出厂后功能迭代和 Bug 修复都依赖 OTA，不能每次都回 4S 店刷固件。

### 平台适配要点

HMI 多平台适配的三个维度：分辨率适配（CanvasScaler）、输入适配（Input System 映射）、性能适配（Quality Settings 按平台分级）。

## 代码对照

```csharp
// HMI 构建后处理：按平台配置
#if UNITY_ANDROID
// 车载 Android：锁定横屏、禁止休眠
Screen.orientation = ScreenOrientation.LandscapeLeft;
Screen.sleepTimeout = SleepTimeout.NeverSleep;
#elif UNITY_LINUX
// 嵌入式 Linux：设置窗口全屏
Screen.fullScreen = true;
Screen.fullScreenMode = FullScreenMode.ExclusiveFullScreen;
#endif

// 启动优化：首屏预加载
public class BootManager : MonoBehaviour
{
    async void Start()
    {
        // 先显示首屏（2 秒内）
        await ShowFirstScreen();
        // 后台加载其他资源
        await Addressables.LoadAssetsAsync<Object>("dashboard");
    }
}
```

## 常见误区

<Callout type="trap">
**现象：所有资源都打进包体，启动时全量加载。**
原因：HMI 要求冷启动 2 秒内显示界面，全量加载会导致启动超时。修法：用 Addressables 按需加载，首屏只加载必需资源，其他界面后台预加载或延迟加载。包体也需控制大小，车载存储空间有限。
</Callout>

<Callout type="trap">
**现象：没有 OTA 机制，Bug 修复需要回厂刷固件。**
原因：现代 HMI 必须支持远程更新，否则维护成本极高。修法：集成 OTA 框架，实现版本检查、差分下载、校验安装和回滚。OTA 包必须数字签名防篡改，安装失败必须自动回滚到旧版本。
</Callout>

<Exercises>
**问题 1**：HMI 部署与普通 App 部署的核心区别是什么？

<Answer>
HMI 部署面向车规级/工业级平台，有严格约束：冷启动 2 秒内显示界面、长期 7x24 小时稳定运行、通过安全认证（如 ISO 26262）、支持 OTA 远程更新且能回滚。普通 App 部署面向消费级平台，启动时间容忍度高、不需要安全认证、通过应用商店更新。HMI 还需适配嵌入式硬件（有限 CPU/内存/存储）。
</Answer>

**问题 2**：HMI 为什么需要 OTA？OTA 的关键要求是什么？

<Answer>
车辆出厂后功能迭代和 Bug 修复都依赖 OTA，不能每次回 4S 店刷固件。关键要求：版本检查（知道何时该更新）、差分下载（只下变化部分省流量）、数字签名（防篡改）、校验安装（确保包完整）、自动回滚（安装失败恢复旧版）。OTA 过程中 HMI 必须保持可用状态，不能在行驶中突然黑屏更新。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="构建发布">将 Unity 工程构建为目标平台可执行包的过程，包括资源压缩、脚本编译（IL2CPP）和平台适配。</GlossaryItem>
<GlossaryItem term="OTA">Over-The-Air 远程空中下载更新，HMI 通过网络下载新版本固件并安装，支持版本检查、差分下载和回滚。</GlossaryItem>
<GlossaryItem term="Addressables">Unity 的按需资源加载系统，首屏只加载必需资源，其他后台预加载，控制启动时间和包体大小。</GlossaryItem>
<GlossaryItem term="IL2CPP">Unity 的脚本后端，将 C# 编译为 C++ 再编译为原生代码，提高性能和安全性，HMI 通常用 IL2CPP 而非 Mono。</GlossaryItem>
</Glossary>
