## 直觉引入

回顾全书，我们像造一辆智能汽车的仪表盘一样，从零开始搭建了一个完整的 HMI 系统。先理解什么是 HMI，再搭 UI 骨架，然后接数据、做动画、处理输入，最后优化性能、部署上线、探索高级技术。

全书的灵魂是那句话：UI 是门面，数据是灵魂，性能是底线。每个章节都在围绕这三个核心展开。

## 概念讲解

### 知识脉络回顾

<UhmFinalReviewDiagram />

<Term def="HMI 开发的三层闭环：表现层（UI）、驱动层（数据）、保障层（性能）">核心三角</Term>贯穿全书。UI 框架和动画构建表现层，数据绑定和输入处理构建驱动层，性能优化和部署构建保障层。

### 关键决策点

HMI 开发中的关键决策：Canvas 渲染模式选 Camera（精确控制）；数据绑定用脏标记（减少无效刷新）；动画用 Tween 而非 Animator（轻量高效）；输入用新 Input System（多设备支持）；性能看 1% Low FPS（稳定性优先）；部署用 Addressables（按需加载）。

## 代码对照

```csharp
// HMI 全链路示例：从数据到显示的完整路径
public class HmiFullStack : MonoBehaviour
{
    // 1. 数据层：可观察属性 + 脏标记
    private bool _speedDirty = false;
    private float _speed;
    public float Speed
    {
        get => _speed;
        set { _speed = value; _speedDirty = true; } // 标记脏
    }
    
    [SerializeField] private Text speedText;
    [SerializeField] private RectTransform needle;
    
    // 2. 帧末批量更新（减少无效刷新）
    void LateUpdate()
    {
        if (_speedDirty)
        {
            // 3. 数据绑定 + 动画过渡
            speedText.text = $"{_speed:F0} km/h";
            float angle = Mathf.Lerp(0f, 270f, _speed / 240f);
            needle.rotation = Quaternion.Euler(0, 0, -angle);
            _speedDirty = false;
        }
    }
}
```

## 常见误区

<Callout type="trap">
**现象：学完各章但不能串联，实际做项目时不知从何下手。**
原因：各章是独立知识点，缺乏项目级串联。修法：用「一个仪表盘的诞生」做主线项目：先搭 UI（第2章），再接数据（第4章），加动画（第5章），处理输入（第6章），优化性能（第7章），最后部署（第8章）。
</Callout>

<Callout type="trap">
**现象：只关注技术实现，忽视 HMI 的安全约束。**
原因：HMI 是安全关键系统，技术实现再好也必须满足安全标准。修法：每个功能都要问三个问题——掉帧时会怎样？数据错误时会怎样？界面崩溃时会怎样？有安全风险的功能必须有兜底机制（如默认值、降级显示）。
</Callout>

<Exercises>
**问题 1**：描述一个 HMI 项目从零到上线的完整流程。

<Answer>
1. 需求分析：确定目标平台（车载/工业）、屏幕规格、输入方式、安全等级。2. UI 搭建：Canvas + 布局组件搭建界面骨架，配置 CanvasScaler 适配分辨率。3. 数据对接：实现数据绑定机制（可观察属性+脏标记），对接数据源（总线/传感器）。4. 动画过渡：为关键数据变化添加 Tween 过渡动画（100-300ms）。5. 输入处理：集成 Input System，映射逻辑动作，添加防抖。6. 性能优化：Profiler 定位瓶颈，合并 DrawCall，控制 GC。7. 平台测试：在目标硬件上测试启动时间、帧率、内存。8. 部署上线：配置 IL2CPP + Addressables，集成 OTA。
</Answer>

**问题 2**：HMI 开发的核心三角是什么？三者如何协作？

<Answer>
核心三角：表现层（UI 是门面）——Canvas/布局/动画，决定用户看到什么；驱动层（数据是灵魂）——数据绑定/输入处理，决定 UI 怎么变；保障层（性能是底线）——优化/部署，决定系统能不能稳定跑。三者协作：数据驱动 UI 更新（驱动层→表现层），性能保障两者可靠运行（保障层→表现层+驱动层）。任何一层出问题都会影响整体——UI 崩溃用户看不到数据，数据错误 UI 显示错误信息，性能不达标导致掉帧卡顿。
</Answer>
</Exercises>
