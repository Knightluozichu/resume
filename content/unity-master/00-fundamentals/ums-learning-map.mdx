## 直觉引入

学完 Unity 基础（场景、脚本、物理、UI）之后，很多人卡在「会用但做不好」的阶段：编辑器只会默认窗口，脚本写得啰嗦，渲染管线一知半解，性能问题束手无策。这本书要解决的就是从「会用」到「精通」的跨越。

全书十章覆盖五大维度：**编辑器精通**（自定义窗口与 Inspector）、**脚本进阶**（泛型委托与编辑器扩展）、**渲染深入**（SRP 管线与性能剖析）、**生产工程**（资源管理与团队协作）、**综合实战**。每一章都是实战导向，代码可直接落地。

## 概念讲解

全书分五个阶段：**编辑器**（第 2-3 章）、**脚本**（第 4-5 章）、**渲染**（第 6-7 章）、**生产**（第 8-9 章）、**收尾**（第 10 章）。

<Term def="通过 EditorWindow、PropertyDrawer 等 API 定制 Unity 编辑器界面与工作流">编辑器精通</Term>是达人的第一标志。<Term def="使用泛型约束、委托事件、扩展方法等 C# 高级特性提升代码复用性">高级脚本</Term>让代码更优雅。<Term def="掌握 URP/HDRP 可编程渲染管线的自定义 Renderer Feature">SRP 精通</Term>是渲染进阶核心。<Term def="用 Addressables 管理资源加载与卸载，配合 Git 做团队协作">生产工程</Term>保障项目可维护。

### 阶段依赖
- 编辑器 → 脚本：定制编辑器后才知道需要哪些脚本辅助工具
- 脚本 → 渲染：高级脚本能力是编写自定义渲染代码的基础
- 渲染 → 生产：渲染管线配置完成后，才需要批量资源管理和性能验证
- 生产 → 收尾：工程化能力就绪后，综合实战串联全书

## 常见误区

<Callout type="trap">
**现象 →** 学了很多 Unity 功能，但做项目效率依然低下。
**原因 →** 只会用默认编辑器界面，不会定制工具链。
**修法 →** 先学编辑器精通章：自定义窗口、Inspector 定制、快捷键。把重复操作自动化，效率提升立竿见影。
</Callout>
<Callout type="trap">
**现象 →** 项目画面效果差，但不知道是管线配置问题还是 Shader 问题。
**原因 →** 不了解 SRP 架构，无法区分管线层和材质层的问题。
**修法 →** 学完 SRP 精通章，理解 URP 渲染流程，再用 FrameDebugger 逐 DrawCall 排查，定位是管线配置还是 Shader 代码。
</Callout>

## 练习

<Exercises>
**问题**：全书五个阶段分别解决什么问题？如果项目已经能跑但效率低，该从哪个阶段切入？

<Answer>
编辑器（工具定制）、脚本（代码质量）、渲染（画面与性能）、生产（工程化）、收尾（综合）。项目能跑但效率低，优先切入编辑器阶段——自定义工具把重复操作自动化，投入产出比最高。
</Answer>

**问题**：为什么说编辑器定制是 Unity 达人的第一标志？

<Answer>
因为会定制编辑器意味着理解了 Unity 的扩展架构（EditorWindow、PropertyDrawer、MenuItem），能把团队工作流固化成工具。普通开发者用 Unity 给的工具，达人为团队造工具。这种能力差异在日常效率上体现为十倍以上的差距。
</Answer>
</Exercises>

<GlossaryItem term="编辑器精通">通过 EditorWindow、PropertyDrawer、Gizmo 等 API 定制 Unity 编辑器界面与工作流，把重复操作自动化。</GlossaryItem>
<GlossaryItem term="SRP">Scriptable Render Pipeline，Unity 的可编程渲染管线架构，包含 URP（通用）和 HDRP（高清）两套内置管线。</GlossaryItem>
<GlossaryItem term="Addressables">Unity 的资源管理系统，通过异步加载、引用计数和分组打包解决资源加载与内存管理问题。</GlossaryItem>
<GlossaryItem term="Profiler">Unity 内置的性能分析工具，按 CPU/GPU/内存/渲染等模块逐帧分析性能瓶颈。</GlossaryItem>
</Glossary>
