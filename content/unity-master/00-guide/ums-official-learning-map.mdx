### 为什么原来的高级主题结构错误

旧页面把 EditorWindow、SRP、Addressables、Profiler 和团队协作当作原书章节，但 ISBN 9787515354781 的正式目录完全不同。原书从零基础环境和第一个自然场景开始，逐步解释 GameObject、建模材质、脚本、动画、GUI、构建、外设、playMaker 和优化。纠正目录是内容保真的前提。

### 12个官方单元怎样递进

序章回答需要哪些技能；第一、二章建立场景和对象模型；第三、四章接入资产和规则；第五、六章补动画、导航、GUI 与音频；第七章把项目输出到平台；第八、九章连接设备与可视化脚本；第十章讨论画质预算；附录治理外部工具和资产。

### 历史 API 如何处理

原版 2015 年出版，包含 Web Player、UnityScript、旧 IMGUI、iTween、Movie Texture 和早期设备 SDK。学习页不会悄悄删除这些主题，而是先解释它们在原书中的问题，再给出 WebGL、C#、uGUI、VideoPlayer、OpenXR 等现代映射，并明确哪些只是概念等价而非 API 一比一替换。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

从一个可交互小岛出发，为每个官方单元写一条可观察证据；若某项无法落到场景、代码、构建或性能记录，就回到对应章节补齐。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-official-learning-map";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
public static class ReadingGate
{
    public static bool Complete(int mappedUnits, int totalUnits)
    {
        return mappedUnits == totalUnits && totalUnits == 12;
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```
