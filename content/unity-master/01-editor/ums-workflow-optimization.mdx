## 直觉引入

衡量一个开发者效率的最好指标是：做同一件事，第二次比第一次快多少。Unity 默认的操作流程有很多「多余点击」——每次新建场景要手动加 Camera、Light、EventSystem；每次导入贴图要手动改 Texture Type、Max Size、Compression。这些重复劳动日积月累，吞噬大量时间。

工作流优化的核心思路：**凡重复三次以上的操作，就值得自动化**。快捷键解决「点太多次」，模板解决「每次从零开始」，自动化脚本解决「手动改参数」。

## 概念讲解

三条优化路径：<Term def="通过 MenuItem 快捷键参数或快捷键管理器绑定键盘操作">快捷键定制</Term>减少点击次数；<Term def="用 Package Manager 模板或 ProjectTemplate 预设项目初始结构">项目模板</Term>统一团队起点；<Term def="用 AssetPostprocessor 在资源导入时自动设置参数">导入自动化</Term>消除手动配置。

### 自动化的投入产出判断
- **高频操作**（每次新建脚本、导入贴图）→ 必须自动化
- **中频操作**（每周构建打包、数据表导入）→ 值得自动化
- **低频操作**（项目初始化、平台迁移）→ 写成文档即可，不值得写脚本

## 代码对照

```csharp
// 1. 快捷键: 一键对齐到地面
public static class AlignTools {
    [MenuItem("Tools/Align to Ground %#a")] // Ctrl+Shift+A
    static void AlignToGround() {
        foreach (var go in Selection.gameObjects) {
            Undo.RecordObject(go.transform, "Align");
            if (Physics.Raycast(go.transform.position + Vector3.up * 10, Vector3.down, out var hit, 20))
                go.transform.position = hit.point;
        }
    }
}

// 2. 项目模板: ProjectTemplate.json
// 放在 Packages/com.mycompany.template/TemplateProject/
// 新建项目时出现在模板列表里

// 3. 导入自动化: 贴图导入自动配置
public class TextureImportSettings : AssetPostprocessor {
    void OnPreprocessTexture() {
        var importer = (TextureImporter)assetImporter;
        // UI 贴图: 文件名含 _ui
        if (assetPath.Contains("_ui")) {
            importer.textureType = TextureImporterType.Sprite;
            importer.spriteImportMode = SpriteImportMode.Single;
            importer.maxTextureSize = 2048;
            importer.textureCompression = TextureImporterCompression.Compressed;
        }
        // 法线贴图: 文件名含 _nml
        if (assetPath.Contains("_nml")) {
            importer.textureType = TextureImporterType.NormalMap;
            importer.maxTextureSize = 1024;
        }
        importer.crunchedCompression = true;
        importer.SaveAndReimport();
    }
}

// 4. 自动构建管线
public static class BuildAutomation {
    [MenuItem("Build/Android Release")]
    static void BuildAndroid() {
        var scenes = EditorBuildSettings.scenes
            .Where(s => s.enabled).Select(s => s.path).ToArray();
        BuildPipeline.BuildPlayer(scenes, "Builds/Android",
            BuildTarget.Android, BuildOptions.None);
    }
}
```

## 常见误区

<Callout type="trap">
**现象 →** 写了一堆自动化脚本，但团队成员不用，还是手动操作。
**原因 →** 自动化脚本没有菜单入口，或者入口埋太深，团队不知道怎么调用。
**修法 →** 每个 EditorScript 必须挂 `[MenuItem]`，路径放在 Tools/ 下统一管理。团队培训时演示一遍入口位置。快捷键用 `%` (Ctrl) `#` (Shift) `&` (Alt) 组合，避免与 Unity 默认冲突。
</Callout>
<Callout type="trap">
**现象 →** AssetPostprocessor 把所有贴图都压成 256x256，导致角色贴图糊了。
**原因 →** 自动化规则写得太粗暴，没有按文件名或路径区分处理。
**修法 →** 用 assetPath 做条件分支：UI 贴图 2048、角色 1024、道具 512、法线图 1024。规则写在团队文档里，文件名约定（_ui、_char、_prop）和导入参数一一对应。
</Callout>

## 练习

<Exercises>
**问题**：哪些操作值得自动化？给出判断标准。

<Answer>
判断标准是频率 x 耗时。高频操作（每次新建脚本、导入贴图，每天发生多次）必须自动化；中频操作（每周构建打包）值得自动化；低频操作（项目初始化）写成文档即可。具体阈值：一周内重复三次以上且每次超过 30 秒的操作，就值得写脚本。
</Answer>

**问题**：AssetPostprocessor 的 OnPreprocessTexture 和 OnPostprocessTexture 有什么区别？

<Answer>
OnPreprocessTexture 在导入开始前调用，此时可以修改导入设置（Texture Type、Compression、Max Size），修改后按新设置导入，只导入一次。OnPostprocessTexture 在导入完成后调用，此时贴图已生成，可以拿到 Texture2D 对象做像素级处理（如生成缩略图、修改像素）。导入参数配置用 Pre，像素处理用 Post。
</Answer>
</Exercises>
