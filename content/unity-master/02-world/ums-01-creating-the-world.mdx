## 核心知识与现代 Unity 对照

### 光、天空与空间基准

没有光时材质信息无法被读取，没有地面时对象缺少尺度参照，没有天空时远景边界会暴露。先用一盏方向光、一个 Skybox 和简单地形建立视觉基准，再调整山谷、水面与雾。每次只改一个因素，才能判断亮度变化来自灯、材质还是环境光。

### 从静态布景到运行世界

“让物体动起来”和放置动物引入运行时。对象复制不能只看数量，还要检查 Transform、碰撞体、动画和脚本状态是否独立。Play 模式中的修改通常不会保存，因此实验前记录编辑状态，运行中只观察，退出后再根据证据修改资源。

### 从 Web Player 到 WebGL

原书的“发布到 Web”对应当年的 Web Player；现代 Unity 应使用 WebGL 构建。迁移时要重新检查浏览器输入、压缩格式、内存预算、跨域资源和移动浏览器限制。章节目标仍是相同的：证明内容能离开编辑器，在真实交付环境中启动和交互。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

按光、地形、天空、运动、植被、水和动物的顺序搭建小岛场景，每一步保存截图和帧时间，最后制作 WebGL 构建并比较编辑器与浏览器结果。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-01-creating-the-world";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;

public sealed class IslandMover : MonoBehaviour
{
    [SerializeField] private float speed = 2f;
    private void Update()
    {
        transform.Rotate(Vector3.up, speed * Time.deltaTime * 30f);
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“同时替换灯光、材质和后处理，画面变暗后无法定位首个变化来源”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“每个创造步骤都能单独回放，Play
  模式与 WebGL 中的核心对象、运动和输入保持一致”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
