## 核心知识与现代 Unity 对照

### 事件、状态与控制流

Start、Update 和碰撞回调不是随意命名的函数，而是引擎调度契约。变量必须有稳定类型和所有权，if、switch、for 与 foreach 只是根据状态选择转换。Debug.Log 应输出对象、帧和关键输入，Invoke 与 Coroutine 要记录取消条件，避免延迟逻辑在对象失效后继续执行。

### 引用对象而不是猜名字

原书展示按名称寻找 GameObject 和子对象，但生产代码优先使用序列化引用、GetComponent、Tag 或明确注册表。字符串查找容易被重命名破坏，也隐藏依赖。Transform 的位置、旋转和缩放还要区分局部与世界空间，父子层级会改变结果。

### 物理、输入与实例化

直接改 Transform 和用 Rigidbody.AddForce 属于不同运动模型，不能在同一动态刚体上混用而不说明。输入产生意图，FixedUpdate 提交物理动作，碰撞回调记录结果。Raycast 要保留起点、方向、距离和 LayerMask；Instantiate 要管理数量、生命周期和对象池边界。

### 跨场景状态与现代化边界

DontDestroyOnLoad 只解决对象不销毁，不解决重复实例和状态版本；PlayerPrefs 适合少量用户设置，不适合复杂存档。原书的 UnityScript 已移除，iTween 也应被明确标为历史工具；复刻时用 C#、Animator、Tween 库或自定义插值实现同一行为，并保存迁移前后的时间曲线。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

```csharp
using System.Collections;
using UnityEngine;

public sealed class TrafficLight : MonoBehaviour
{
    private enum Signal { Red, Green, Amber }
    private Signal current;

    private IEnumerator Cycle()
    {
        foreach (Signal signal in System.Enum.GetValues(typeof(Signal)))
        {
            current = signal;
            Debug.Log($"signal={current}");
            yield return new WaitForSeconds(1f);
        }
    }
}
```
