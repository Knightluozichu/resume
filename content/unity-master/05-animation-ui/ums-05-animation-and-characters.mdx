## 核心知识与现代 Unity 对照

### 动画资产与状态控制分离

Clip 只描述随时间变化的姿势或属性，Animator Controller 决定何时播放、怎样过渡。把攻击伤害直接等同于某个动画帧会让逻辑依赖美术长度；更稳妥的做法是用事件发出语义信号，并由规则层检查目标和当前状态。

### 混合树与参数证据

待机、走和跑适合按速度参数放入一维 Blend Tree。验收时记录输入速度、Animator 参数、当前状态和根运动位移，检查阈值附近是否抖动。动画看起来平滑不等于角色速度正确，视觉位移与物理或导航速度必须一致。

### 导航不是播放走路动画

NavMeshAgent 计算路径和期望速度，Animator 根据该速度表现动作。门需要改变可通行性，可能使用 NavMeshObstacle、链接或重新构建局部表面。测试应覆盖门开、门关、目标不可达和路径中途变化，不能只验证一次成功到达。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

给同一角色配置待机、走、跑 Blend Tree 和 NavMeshAgent，在迷宫中加入可开关门；记录速度参数、当前动画、剩余距离和门状态，复现不可达与重规划。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-05-animation-and-characters";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;
using UnityEngine.AI;

public sealed class LocomotionBridge : MonoBehaviour
{
    [SerializeField] private NavMeshAgent agent = null!;
    [SerializeField] private Animator animator = null!;
    private void Update()
    {
        animator.SetFloat("Speed", agent.velocity.magnitude);
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“只根据键盘输入切动画，不读取角色真实速度，导致撞墙时仍播放奔跑且脚底滑动”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“动作参数来自可观察运动状态，门改变导航可达性时角色能停止或重规划且不会穿越关闭边界”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
