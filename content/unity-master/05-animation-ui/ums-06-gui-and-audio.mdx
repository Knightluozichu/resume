## 核心知识与现代 Unity 对照

### 旧式 IMGUI 与保留边界

原书的 GUI.Button 和 GUI.Label 属于立即模式 GUI，适合编辑器工具或简单调试，但运行时产品界面通常使用 uGUI 或 UI Toolkit。复刻时要理解立即模式每帧声明界面的思路，同时把正式 HUD 映射到 Canvas 组件，不能把历史 API 当成现代推荐。

### 布局、锚点与输入焦点

固定像素宽度只在单一分辨率成立；Anchor、Pivot、Canvas Scaler 和布局组件共同决定缩放。ESC 隐藏 Canvas 时还要处理 EventSystem 选中对象、鼠标锁定和游戏暂停。地图或第二相机叠加应明确 Render Texture、Camera Stack 或独立 Canvas 的层级。

### 声音是可测试的反馈通道

按钮音、环境音和音乐应进入不同 Mixer Group，通过参数或 Snapshot 控制。滑动条通常转换为对数分贝，而不是把线性零直接传给音量。淡入淡出要记录持续时间、起止值和中断策略，确保快速切换界面时不会叠加多个协程。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

制作含 HUD、地图、设置面板和主音量滑动条的 Canvas，在三种宽高比下检查锚点；用 ESC 开关设置页，并记录输入焦点、暂停状态和 Audio Mixer 参数。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-06-gui-and-audio";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;
using UnityEngine.Audio;

public sealed class VolumeBinding : MonoBehaviour
{
    [SerializeField] private AudioMixer mixer = null!;
    public void SetMaster(float normalized)
    {
        float decibels = Mathf.Log10(Mathf.Max(normalized, 0.0001f)) * 20f;
        mixer.SetFloat("MasterVolume", decibels);
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“只把 Canvas 设为不可见，却没有释放 EventSystem
  焦点或恢复时间缩放，关闭菜单后角色仍不能输入”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“界面在目标宽高比内无重叠，显示状态、输入焦点、暂停状态和音频参数始终同步”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
