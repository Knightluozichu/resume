## 直觉引入

前九章分别学了编辑器定制、脚本进阶、渲染管线、性能分析、资源管理和团队协作。但真实项目不是孤立使用这些技能——你要同时用 EditorWindow 给策划做工具、用 Addressables 管资源、用 Profiler 查性能、用 Git 协作。

总复习的目标是把这五章的知识串成一条线：从一个需求出发，走完「工具开发 → 脚本实现 → 渲染配置 → 性能验证 → 资源上线」的完整流程。

## 概念讲解

全书五大维度形成一条<Term def="从需求到上线的完整技术流程：工具→脚本→渲染→性能→工程">达人工作链</Term>。

### 全书知识依赖图
- **编辑器**（第 2-3 章）→ 为团队造工具，提升效率
- **脚本**（第 4-5 章）→ 用泛型/委托/扩展写高质量代码，用编辑器扩展做自动化
- **渲染**（第 6-7 章）→ 用 SRP 定制管线，用 Profiler 验证渲染性能
- **生产**（第 8-9 章）→ 用 Addressables 管资源，用 Git 做协作，代码规范保障质量
- **收尾**（第 10 章）→ 串联以上，完成项目级实战

### 综合实战场景
一个塔防游戏需要：技能编辑器（EditorWindow + ScriptableObject）、事件系统（泛型 + 委托）、URP 描边效果（RendererFeature）、Profiler 零 GC 验证、Addressables 分包热更、Git 团队协作。

## 代码对照

```csharp
// === 综合实战: 塔防游戏核心架构 ===

// 1. 工具层: 关卡数据编辑器 (第2章 EditorWindow + ScriptableObject)
[CreateAssetMenu(menuName = "TD/Level")]
public class LevelData : ScriptableObject {
    public List<WaveData> waves;
    public List<Vector3> pathPoints;
}

// 2. 脚本层: 泛型对象池 + 事件总线 (第4章)
public class BulletPool : ObjectPool<Bullet> { } // 泛型池
public struct EnemyKilledEvent : IGameEvent { public int Reward; } // 事件
// 击杀时: EventBus.Publish(new EnemyKilledEvent { Reward = 10 });
// UI订阅: EventBus.Subscribe<EnemyKilledEvent>(e => UpdateGold(e.Reward));

// 3. 渲染层: URP 描边 (第6章)
// OutlineFeature + OutlinePass, 注入 AfterRenderingOpaques
// 塔选中时启用描边 RendererFeature

// 4. 性能层: 零 GC 验证 (第7章)
public class Tower : MonoBehaviour {
    readonly Collider[] _hits = new Collider[32]; // 预分配, 零GC
    void FixedUpdate() {
        Profiler.BeginSample("Tower.Detect");
        int count = Physics.OverlapSphereNonAlloc(
            transform.position, _range, _hits, _enemyLayer);
        for (int i = 0; i < count; i++)
            _hits[i].GetComponent<Enemy>().TakeDamage(_dps * Time.fixedDeltaTime);
        Profiler.EndSample();
    }
}

// 5. 工程层: Addressables 关卡加载 (第8章)
public class LevelManager : MonoBehaviour {
    async Task LoadLevel(string address) {
        var handle = Addressables.LoadAssetAsync<LevelData>(address);
        var levelData = await handle.Task;
        var sceneHandle = Addressables.LoadSceneAsync(
            $"Levels/Level{levelData.levelId}", LoadSceneMode.Additive);
        await sceneHandle.Task;
    }
}

// 6. 工程层: Git 协作 (第9章)
// .gitignore: Library/ Temp/ Build/ → 排除
// .gitattributes: *.fbx *.png → LFS; *.unity *.prefab → UnityYAMLMerge
// .editorconfig: 命名规范 + Roslyn Analyzer 强制
// PR 流程: feature/tower-defense → Review → merge to main
```

## 常见误区

<Callout type="trap">
**现象 →** 学了全书但做项目时还是不知道怎么组合使用。
**原因 →** 把每章当独立知识点学，没有串成工作链。
**修法 →** 用「需求→工具→脚本→渲染→性能→工程」的流程框架串联。每个需求先问：需要什么工具？什么脚本架构？渲染效果怎么实现？性能怎么验证？资源怎么管理？团队怎么协作？六步走完就是完整工作链。
</Callout>
<Callout type="trap">
**现象 →** 项目后期性能崩盘，回头优化发现要改架构。
**原因 →** 前期没有用 Profiler 持续验证，等问题积累到架构层面才暴露。
**修法 →** 从项目第一天起，每完成一个功能就用 Profiler 录一段。设定性能预算（如移动端 30FPS、CPU 16ms/帧、零 GC.Alloc），超标立即修。持续 Profiling 是达人的习惯，不是后期才做的事。
</Callout>

## 练习

<Exercises>
**问题**：全书五大维度如何串联成一条完整的工作链？举例说明。

<Answer>
工作链：需求 → 工具（EditorWindow 做编辑器）→ 脚本（泛型+事件系统实现逻辑）→ 渲染（URP 定制效果）→ 性能（Profiler 验证零GC）→ 工程（Addressables 分包 + Git 协作）。例：塔防技能系统：先做技能数据编辑器（工具），再写事件系统通知击杀（脚本），配 URP 描边显示范围（渲染），Profiler 验证子弹池零 GC（性能），Addressables 分包关卡（工程）。六步串成完整链。
</Answer>

**问题**：如果你只能保留全书的一章来提升项目质量，选哪章？为什么？

<Answer>
选性能分析精要（第 7 章）。因为性能问题是项目后期的最大杀手，且其他章的知识最终都要通过性能验证来确认效果。编辑器再好、脚本再优雅、渲染再漂亮，如果帧率不到 30FPS，产品就是失败的。Profiler 思维（先测量再优化）是所有其他技能的「质量保证」——没有性能验证，所有优化都是盲目的。
</Answer>
</Exercises>
