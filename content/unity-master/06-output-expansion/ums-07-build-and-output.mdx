## 核心知识与现代 Unity 对照

### 平台切换是依赖变更

切换 Build Target 或现代 Build Profile 会触发资源重新导入，并改变图形 API、压缩格式和可用插件。构建前固定 Unity 版本、平台模块、场景列表、包标识和脚本后端。Quality 不是简单高低档，而是帧率、阴影、纹理和后处理预算的成组策略。

### 输入语义跨平台保持一致

鼠标点击只有一个指针，触摸可能同时出现多个接触点并经历 Began、Moved、Ended。平台适配应先定义“选择、拖动、缩放”等语义，再映射鼠标、触摸或手柄。条件编译只隔离平台 API，不能复制整套游戏规则形成分叉。

### 移动构建与发布证据

iOS 构建通常输出 Xcode 工程并依赖证书和 Provisioning Profile；Android 依赖 SDK、包名、目标 API、脚本后端和 Keystore。密钥不能进入仓库。验收必须包含真机安装、冷启动、权限、横竖屏、暂停恢复和升级路径，而不只是 Build Succeeded。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

为桌面、WebGL 和 Android 建立三套构建配置，共用同一“选择与拖动”输入语义；保存构建参数、产物哈希、真机或浏览器日志和平台差异清单。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-07-build-and-output";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;

public static class PlatformCapability
{
    public static bool SupportsTouch()
    {
#if UNITY_IOS || UNITY_ANDROID
        return true;
#else
        return Input.touchSupported;
#endif
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“为了快速适配平台复制整个控制脚本，之后只修复其中一份，导致不同平台规则逐渐分叉”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“平台分支只封装设备能力，核心规则和输入语义共用；签名、包标识和构建配置可审计且密钥不入库”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
