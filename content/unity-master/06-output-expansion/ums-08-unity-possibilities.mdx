## 核心知识与现代 Unity 对照

### 编辑器扩展先解决生产问题

Editor Script 应围绕可重复且易错的任务，例如批量校验资源、生成配置或可视化传感器数据。它不能引用到运行时程序集，也不能把人工确认完全删除。工具输出要带版本、输入资产和变更摘要，确保自动化结果可审查。

### 从厂商 SDK 到开放能力

原书列出的 Oculus Rift、Leap Motion 和 Vuforia 是当时代表性入口。现代项目可用 OpenXR、XR Hands、AR Foundation 或受维护插件，但应保持头部姿态、手势、图像目标等语义层稳定。设备替换时只更换适配器，不重写玩法。

### 物理设备必须处理不可靠性

Arduino 串口数据会有延迟、噪声、断连和非法值；追踪设备也可能失去目标。每个输入都要记录时间戳、范围和有效性，并设计最后有效值、超时归零或切换模拟输入的策略。只有理想连接下能运行的 Demo 不能签发。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

定义统一 PoseOrValue 输入接口，用鼠标模拟器和一个真实或录制设备数据源驱动同一对象；注入断连、漂移和超范围值，观察回退状态。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
public sealed class EvidenceStamp : MonoBehaviour

    [SerializeField] private string unit = "ums-08-unity-possibilities";

        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;

public interface ISpatialInput
{
    bool TryGetPose(out Pose pose, out double timestamp);
}

public sealed class SpatialConsumer : MonoBehaviour
{
    public void Apply(ISpatialInput input)
    {
        if (input.TryGetPose(out Pose pose, out _))
            transform.SetPositionAndRotation(pose.position, pose.rotation);
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```
