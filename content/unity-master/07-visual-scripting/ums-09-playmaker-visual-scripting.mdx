## 核心知识与现代 Unity 对照

### 状态和事件必须具有业务语义

Idle、Moving、Alert 等状态应对应稳定行为阶段，Click、Arrived、Timeout 等事件说明发生了什么。若状态只叫 State1，迁移只靠匿名布尔值，图虽然可见却不可读。进入、每帧和退出 Action 要区分，避免副作用重复执行。

### 变量与脚本通信是接口

FSM Variable 应声明类型、默认值和所有者；脚本向 FSM 发送事件，FSM 向脚本调用明确方法。不要让双方通过对象名称和全局变量相互猜测。现代 Unity Visual Scripting 可以复现相同思想，但迁移时要保留状态、事件和副作用的对照表。

### 可视化不自动等于简单

iTween 移动、组件修改和条件分支很容易堆成长链。图超过单屏、出现大量跨图事件或同一状态承担多个职责时，应拆分层级状态机或把纯计算移回 C#。模板只提取稳定结构，过早模板化会把错误复制到所有实例。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

用 playMaker 或 Unity Visual Scripting 制作门的 Closed、Opening、Open、Closing 四状态，脚本只发送 Use 与 Lock 事件；保存状态轨迹并注入连续点击和动画中断。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-09-playmaker-visual-scripting";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;

public sealed class DoorEventBridge : MonoBehaviour
{
    public event System.Action? UseRequested;
    public void RequestUse()
    {
        Debug.Log($"event=Use sender={name}");
        UseRequested?.Invoke();
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“多个 FSM
  通过全局字符串事件互相调用，事件重名后触发错误对象且无法追踪发送者”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“任一副作用都能追溯到状态、事件和条件，脚本通信接口有类型与发送者，模板实例无隐藏覆盖”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
