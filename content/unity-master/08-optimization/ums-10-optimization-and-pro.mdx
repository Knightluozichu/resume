## 核心知识与现代 Unity 对照

### 版本差异不是优化方案

原书区分 Personal 与 Professional 的功能；现代 Unity 授权和功能边界已变化，应以当前许可条款和包文档为准。无论版本如何，优化都要先定义目标设备、帧预算和画质底线，再在真机构建中测量。编辑器帧率不能代表发布性能。

### 减少不可见或不必要的工作

LOD 降低远处几何成本，Occlusion Culling 跳过遮挡物体，Lightmapping 把静态光计算转移到离线，Light Probe 为动态对象提供近似间接光。每项技术都有内存、烘焙时间、跳变或错误剔除成本，不能全部开启后只看平均帧率。

### 后处理与纹理是带宽决策

旧 Image Effect 在现代管线中通常映射到 Volume 和 Renderer Feature；Projector 可能映射到 Decal Projector。Render Texture 的分辨率、格式、MSAA 和更新频率直接影响带宽。Movie Texture 已由 VideoPlayer 等方案取代，但核心问题仍是解码、上传和显示同步。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 可复现实验

在目标设备录制基线，然后分别启用 LOD、遮挡剔除、烘焙光和降分辨率 Render Texture；每次只改一项，记录 CPU、GPU、内存、绘制调用和画质差异。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-10-optimization-and-pro";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;
using Unity.Profiling;

public sealed class FrameBudgetProbe : MonoBehaviour
{
    private readonly ProfilerRecorder mainThread =
        ProfilerRecorder.StartNew(ProfilerCategory.Internal, "Main Thread", 30);

    private void OnDestroy() => mainThread.Dispose();
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“在编辑器中看到平均帧率上升就签发，却没有检查真机 GPU、峰值内存和 LOD
  跳变”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“每个优化结论都对应同设备同场景的前后证据，性能改善不能越过画质、正确性和内存门槛”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
