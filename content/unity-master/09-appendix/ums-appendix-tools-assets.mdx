## 核心知识与现代 Unity 对照

### 工具链由数据契约连接

Painter 负责在模型上绘制材质，Designer 用节点生成可复用材质，B2M 从图像估计材质通道，Toolbag 用于快速展示和烘焙。导出到 Unity 前要固定金属度或镜面工作流、法线格式、色彩空间、通道打包和单位，否则工具里正确的资产会在引擎中失真。

### 推荐 Asset 也要进入供应链治理

每个插件和资产都应记录来源、版本、许可证、支持的 Unity 版本、运行时依赖和替代方案。只从可信来源导入，先在隔离项目检查脚本、Shader 和设置变更，再进入主项目。停止维护的资产要评估迁移成本，不能成为不可替换的核心。

### 缓动曲线必须可中断

iTween 的 easeType 决定运动节奏，但真实交互还要处理重复触发、反向、暂停和目标销毁。现代可用 AnimationCurve、Animator 或维护中的 Tween 库。验收时采样归一化时间和位置，确认起点、终点、单调性与时长不受帧率影响。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

## 三阶段操作证据链

<Stepper>
  <Step title="1. 建立基线并固定输入">

    → 工具输入”，保存首个可观察变化。
    </Step>
  <Step title="2. 注入边界和失败样本">

    Unity导入”记录首个偏离，不能只保留最终截图。
    </Step>

  </Step>

## 可复现实验

选一个材质或动画 Asset，建立来源卡片；导入隔离项目，记录通道、色彩空间、许可证和依赖，再用三条 easing 曲线运行同一位移并测试中断。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-appendix-tools-assets";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
using UnityEngine;

public sealed class CurveMover : MonoBehaviour
{
    [SerializeField] private AnimationCurve easing = AnimationCurve.EaseInOut(0, 0, 1, 1);
    public Vector3 Evaluate(Vector3 from, Vector3 to, float normalizedTime)
    {
        return Vector3.LerpUnclamped(from, to, easing.Evaluate(normalizedTime));
    }
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="单变量故障">
  故意制造“直接导入整包 Asset，覆盖项目设置和 Shader
  依赖，却没有记录来源、版本或许可证”。保存故障前输入、首个偏离节点、实际状态和拒绝原因；修复后必须用完全相同输入复验。
</Callout>

<Callout type="trap" title="结果看似正确但证据断裂">
  故意只保留最终画面或最终数值，删除环境、平台、版本或中间状态。即使结果看似正常，只要“每个外部工具输出和第三方资产都有可追踪契约，移除或升级后能明确影响范围并复验”无法证明，签发门也必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本       | 边界样本     | 失败样本       | 通过条件         |
| ---- | -------------- | ------------ | -------------- | ---------------- |
| 输入 | 固定版本与对象 | 只改一个阈值 | 注入明确故障   | 三组输入可重放   |
| 状态 | 逐步记录节点   | 检查临界切换 | 定位首个偏离   | 中间状态完整     |
| 结果 | 满足核心目标   | 无越界或卡死 | 被阶段门拒绝   | 修复后同输入通过 |
| 交付 | 编辑器基线     | 目标环境差异 | 构建或设备失败 | 真实目标环境复验 |
