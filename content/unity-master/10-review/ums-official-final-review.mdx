## 核心知识与现代 Unity 对照

### 世界与资产门

场景必须有可读光照、地形或空间边界、天空和动态对象；每个行为能定位到组件。模型、材质、UV、声音和动画都有来源与导入设置，Prefab 实例覆盖可解释。只靠 Asset Store 拼装而无法说明资产职责，不通过这一门。

### 规则与反馈门

输入通过明确接口改变状态，物理与 Transform 不冲突，协程和持久化有生命周期。Animator 参数来自真实运动，GUI 显示状态并正确管理焦点，Audio Mixer 参数可复验。连续点击、目标不可达和界面中断等边界样本必须被处理。

### 平台与性能门

项目要在目标设备或浏览器运行，构建配置、签名和产物可追踪。至少选择一种设备能力或可视化状态机扩展，并注入断连或事件错误。最后在真机构建中记录 CPU、GPU、内存与画质对照，证明优化没有转移问题。

在复刻时，最容易犯的错误是只追求最终画面或最终数值。正确的证据链必须同时保存环境、输入、首个状态变化、中间状态、失败原因和最终产物。版本差异可以改变按钮位置或 API 名称，却不能改变本单元要解决的对象关系和验收问题。

先用一个小型组件记录实验身份。它不替代截图和运行日志，但能把环境与对象写进同一条证据。

```csharp
using UnityEngine;

public sealed class EvidenceStamp : MonoBehaviour
{
    [SerializeField] private string unit = "ums-official-final-review";
    [SerializeField] private string variant = "baseline";

    private void Start()
    {
        Debug.Log($"unit={unit}; variant={variant}; unity={Application.unityVersion}; frame={Time.frameCount}");
    }
}
```

本单元的最小实现如下。运行前先预测输出，运行后记录实际状态和首个差异。

```csharp
public sealed record AcceptanceResult(
    bool World,
    bool Assets,
    bool Rules,
    bool Feedback,
    bool Build,
    bool Performance)
{
    public bool Passed => World && Assets && Rules && Feedback && Build && Performance;
}
```

最后用签发函数拒绝缺少关键证据的结果。不要为了“绿灯”把条件删掉。

```csharp
public static class UnitGate
{
    public static bool CanShip(bool baseline, bool boundary, bool failureReplay, bool targetBuild)
    {
        return baseline && boundary && failureReplay && targetBuild;
    }
}
```
