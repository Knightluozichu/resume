## 直觉引入

把 Unity MMO 开发想象成建造一座虚拟城市。你先要修路架桥——让客户端和服务器能通信（网络客户端架构）；然后制定交通规则——决定数据怎么同步（状态同步 vs 帧同步）；接着盖楼住人——角色怎么创建、怎么穿装备（角色系统）；再设计战斗系统——技能怎么放、伤害怎么算（战斗系统）；城市大了要分区管理——场景怎么流式加载、谁能看到谁（场景流式加载、AOI）；最后还要让城市高效运转、不出乱子——性能优化、部署运维。本书回答的就是这些「从客户端到服务器」的 MMO 实战问题。

## 五阶段递进

<Term def="Unity MMO 是以 Unity 引擎为客户端、以权威服务器为核心的网络多人在线游戏，强调服务器权威、状态同步和大世界流式加载。">Unity MMO</Term>的开发可以拆成五个递进阶段。**客户端网络层**包括 Protobuf 序列化和连接管理——它们解决「客户端怎么和服务器通信」和「消息怎么封包解包」，是所有上层玩法的基础。**玩法系统层**包括角色系统和战斗系统——它们决定「角色怎么创建、穿装备」和「技能怎么放、伤害怎么算」。**世界管理层**包括场景流式加载和 AOI——它们让大世界「加载不卡」和「万人同服不崩」。**生产运维层**包括性能优化和部署运维——它们让游戏「跑得快」和「不停服更新」。

```csharp
// Unity MMO 的核心脉络：一条玩家操作的旅程
public void OnPlayerCastSkill(int skillId, int targetId) {
    // 1. 网络层：构造 Protobuf 消息并封包
    var req = new CastSkillReq { SkillId = skillId, TargetId = targetId };
    byte[] data = ProtobufCodec.Encode(req);          // 序列化
    network.Send(PacketCodec.Wrap(data));              // 长度前缀封包 + TCP 发送

    // 2. 客户端预测：不等服务器回包，先播放起手动画
    animator.Play("Skill_Cast");

    // 3. 服务器校验 + 执行（在服务器端）
    //    → AOI 系统确定广播范围
    //    → 广播 DamageNotify 给视野内所有客户端

    // 4. 客户端收到回包：校正位置、播放命中特效
    network.OnMessage<DamageNotify>(notify => {
        SpawnHitEffect(notify.TargetId, notify.Damage);
    });
}
```

## 常见误区

<Callout type="trap">
**误区：先学玩法系统再学网络基础。** MMO 的所有玩法都建立在网络通信之上——不理解 Protobuf 序列化就理解不了消息怎么打包；不理解状态同步就理解不了为什么伤害要服务器算；不理解 AOI 就理解不了为什么万人同服不会崩。地基没打牢，学角色系统只会停留在「画个角色跑起来」的层面，遇到延迟、同步、反作弊无从下手。
</Callout>

<Exercises>
**问题 1**：全书五阶段是什么？为什么是这个顺序？

<Answer>
客户端网络（Protobuf/同步）→ 玩法系统（角色/战斗）→ 世界管理（场景/AOI）→ 生产运维（优化/部署）→ 总复习。顺序由依赖关系决定：上层依赖下层。没有网络通信就没有联网玩法；没有角色系统就没有战斗对象；没有场景和 AOI 就支撑不了大世界；没有优化和部署就上不了线。先有「能通信」，再有「能玩」，然后能「扛得住」，最后能「上线运营」。
</Answer>

**问题 2**：为什么说「服务器权威」是 MMO 的基石？

<Answer>
MMO 中所有关键逻辑（位置、伤害、经济）必须由服务器计算，客户端的输入只是「请求」而非「指令」。如果不这样，客户端可以伪造数据（给自己加 HP、瞬移、秒杀），作弊无法防范。服务器权威确保了游戏状态的正确性和公平性，是反作弊的第一道防线，也是后续所有同步策略的前提。
</Answer>
</Exercises>
