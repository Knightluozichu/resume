## 从通用客户端网络模块的核心问题开始

通用客户端网络模块的价值不是隐藏所有细节，而是让连接状态、协议边界和线程交接只有一个实现。它必须把 Socket 回调与 Unity 主线程隔离，同时让调用者看到连接、关闭和错误事件。

  延迟会怎样变化，并写出一个能推翻预测的观察结果。
</Callout>

### 外部 API 小而状态清晰

Connect、Send、Close、AddListener 和 Update 足以表达生命周期；内部 Socket、缓冲区和队列不应被业务代码直接访问。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### 事件分两类

连接事件描述 ConnectSucc、ConnectFail、Close，消息事件按协议名分发。两类监听表分开可避免协议与传输错误相互伪装。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### isClosing 防止重复关闭

关闭期间先停止新发送，等待队列排空或达到超时，再释放 Socket。回调和调用方都必须观察同一个关闭状态。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### Update 是主线程交接点

网络回调只把事件和消息写入线程安全队列，Unity Update 再分发给场景对象，避免后台线程访问引擎 API。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### JSON 与 Protobuf 共享帧契约

序列化格式可以替换，但协议名、正文长度、最大帧和版本协商必须稳定；不能把编码器选择散落在业务层。

## 可复现实验

建立一个会重复点击连接、发送和关闭按钮的 Unity 测试场景。先预测快速双击 Connect 会发生什么，再注入连接中再次连接、发送中关闭、后台回调晚到、PONG 丢失和未知协议；记录状态机与主线程事件顺序。

### 最小状态机

```csharp
public enum EvidenceStage {
  "冻结外部接口",
  "实现连接事件",
  "封装协议与帧",
  "串行发送完整数据",
  "主线程消费接收",
  "心跳与关闭后签发"
}

public sealed record TraceEvent(
    string TraceId,
    EvidenceStage Stage,
    long Sequence,
    string State,
    string Decision);
```

## 两个必须主动制造的失败

<Callout type="trap" title="局部假设越过边界">
  为了方便，把 Socket
  暴露给所有业务脚本；每个面板各自连接、关闭和解析，最终同一账号同时存在多个竞争连接。
  保存故障输入、首偏离状态和拒绝原因，再用相同输入复测修复。
</Callout>

<Callout type="trap" title="最终画面掩盖过程错误">
  在 ReceiveCallback 中直接更新 UI，编辑器中偶尔可用便上线；设备上回调线程触碰
  Unity 对象导致随机崩溃。 即使最终 UI
  看起来正常，只要关键版本、一次性结果或队列预算没有证据，阶段门仍必须拒绝。
</Callout>

## 练习

<Exercises>

**问题 1** 为什么连接事件与消息事件要分开？

<Answer>
  连接事件描述传输生命周期，消息事件描述业务协议。分开后连接失败不会伪装成某条业务响应，也便于统一重连与错误提示。
</Answer>

**问题 2** Update 在网络模块中承担什么职责？

<Answer>
  它是后台网络回调与 Unity 主线程之间的消费边界，按预算分发队列中的事件和消息。
</Answer>

**问题 3** 从 JSON 切换到 Protobuf 时哪些契约不应变化？

<Answer>
  消息帧边界、协议标识、最大长度、版本协商、错误分类和分发语义都应保持稳定。
</Answer>

</Exercises>

## 小结

- **外部 API 小而状态清晰**：Connect、Send、Close、AddListener 和 Update 足以表达生命周期；内部 Socket、缓冲区和队列不应被业务代码直接访问。
- **事件分两类**：连接事件描述 ConnectSucc、ConnectFail、Close，消息事件按协议名分发。两类监听表分开可避免协议与传输错误相互伪装。
- **isClosing 防止重复关闭**：关闭期间先停止新发送，等待队列排空或达到超时，再释放 Socket。回调和调用方都必须观察同一个关闭状态。
- **Update 是主线程交接点**：网络回调只把事件和消息写入线程安全队列，Unity Update 再分发给场景对象，避免后台线程访问引擎 API。
- **JSON 与 Protobuf 共享帧契约**：序列化格式可以替换，但协议名、正文长度、最大帧和版本协商必须稳定；不能把编码器选择散落在业务层。
