## 从通用服务端框架的核心问题开始

通用服务端框架要把底层连接、协议解码、玩家会话和持久化分成可验证边界。Select 解决的是多个连接的等待，不解决身份、SQL 注入、重复登录或断线保存；这些必须由上层状态机和数据库契约完成。

### 模块按所有权分层

网络层拥有 ClientState 和字节，协议层拥有解码，玩家层拥有会话，数据库层拥有持久记录。跨层只能传明确对象。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### Select 循环要有时间预算

每轮处理监听、客户端消息和 Timer，再进入下一次等待。单个客户端的大消息不能无限占用循环。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### 心跳绑定 ClientState

lastPingTime 属于连接，不属于账号；认证前也能超时清理。收到 Ping 只更新时间并回应，不能顺带信任客户端时间。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### PlayerData 与 Player 分离

PlayerData 是可持久化数据，Player 包含连接和运行时状态。断线时保存数据并从 PlayerManager 原子移除。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### SQL 参数化是最低边界

账号存在、注册、校验和更新都使用参数化查询及唯一约束。先拼字符串再转义不能覆盖所有编码和语法边界。

## 两个必须主动制造的失败

<Callout type="trap" title="局部假设越过边界">
  只在应用层先查账号不存在再插入，没有数据库唯一约束；两个并发注册都通过检查并写入重复账号。
  保存故障输入、首偏离状态和拒绝原因，再用相同输入复测修复。
</Callout>

<Callout type="trap" title="最终画面掩盖过程错误">
  断线先删除 Player 再异步保存
  PlayerData，保存失败后已无运行时副本，玩家数据静默回退。 即使最终 UI
  看起来正常，只要关键版本、一次性结果或队列预算没有证据，阶段门仍必须拒绝。
</Callout>

## 练习

<Exercises>

**问题 1** ClientState 与 Player 为什么不能是同一个对象？

<Answer>
  连接在认证前就存在，也可能重连；Player
  表达已认证业务身份。分离后网络清理不必伪造账号，重连也能重新绑定。
</Answer>

**问题 2** 防 SQL 注入为什么不能只靠替换引号？

<Answer>
  不同编码、转义规则和语法位置会绕过字符串替换。参数化查询让数据库分别解析 SQL
  结构与值。
</Answer>

**问题 3** 如何防止并发重复注册？

<Answer>
  数据库账号列设置唯一约束，并把冲突映射为确定业务错误；应用预检查只用于友好提示，不能作为最终互斥。
</Answer>

</Exercises>

## 小结

- **模块按所有权分层**：网络层拥有 ClientState 和字节，协议层拥有解码，玩家层拥有会话，数据库层拥有持久记录。跨层只能传明确对象。

- **PlayerData 与 Player 分离**：PlayerData 是可持久化数据，Player 包含连接和运行时状态。断线时保存数据并从 PlayerManager 原子移除。
- **SQL 参数化是最低边界**：账号存在、注册、校验和更新都使用参数化查询及唯一约束。先拼字符串再转义不能覆盖所有编码和语法边界。
