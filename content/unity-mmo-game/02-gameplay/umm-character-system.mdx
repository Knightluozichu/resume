## 直觉引入

想象你在 RPG 游戏里创建角色。先选性别和职业（外观系统的角色创建），然后捏脸调参数（MorphTarget 驱动），进游戏后穿装备改变外观（换装系统），装备还加了属性（装备加成进入属性管线），战斗中吃了 Buff 又变强了（Buff 修饰）。这三个子系统——外观、属性、装备——像三个齿轮咬合在一起，穿一件装备会同时触发外观变化和属性重算。

## 三大子系统

<Term def="CharacterEntity 是 MMO 角色的根节点，承载外观、属性、装备三大子系统，是网络同步的基本单位。">CharacterEntity</Term>作为角色根节点，向下组织三大子系统。**外观系统**负责角色创建（捏脸/选职业）、Prefab 实例化和换装（SkinnedMeshRenderer + 共享骨骼）。**属性系统**管理基础属性、装备加成和 Buff 修饰，通过计算管线输出最终属性。**装备系统**管理装备槽位、穿戴校验和套装效果，任何变更触发属性管线重算。

## 属性计算管线

属性计算是角色系统的核心——任何属性变更都要走完整管线，保证最终值正确：

```csharp
// 属性计算管线：base → equip → buff
public class CharacterStats {
    // 基础属性（来自等级 + 职业配置表）
    public int BaseHP { get; set; }
    public int BaseATK { get; set; }
    public int BaseDEF { get; set; }

    // 装备加成（遍历已穿戴装备累加）
    public int EquipHP { get; set; }
    public int EquipATK { get; set; }

    // Buff 修饰（百分比 + 固定值）
    public float BuffHPPercent { get; set; }  // 如 +20%
    public int BuffHPFlat { get; set; }        // 如 +500

    // 最终值（每次装备/Buff 变化时重算）
    public int FinalHP =>
        (int)((BaseHP + EquipHP) * (1 + BuffHPPercent)) + BuffHPFlat;
    public int FinalATK => BaseATK + EquipATK;  // 简化版

    // 装备变化时触发重算
    public void OnEquipChanged() {
        RecalcEquipBonus();
        // 通知 UI 刷新、广播给 AOI 范围内的其他玩家
    }
}
```

## 换装系统

换装系统通过 SkinnedMeshRenderer + 共享骨骼实现。所有装备部件共用同一套骨骼，换装时替换 Mesh 而非整个角色：

```csharp
// 换装核心：替换 SkinnedMeshRenderer 的 sharedMesh 和 bones
public void EquipPart(EquipmentData data) {
    // 1. 加载装备部件 Prefab（从 AssetBundle）
    GameObject partPrefab = Addressables.LoadAsset<GameObject>(data.AssetPath);

    // 2. 获取部件的 SkinnedMeshRenderer
    var partSMR = partPrefab.GetComponent<SkinnedMeshRenderer>();

    // 3. 绑定到角色的骨骼——关键：bones 数组要映射到角色骨骼
    Transform[] characterBones = characterAnimator.GetBoneTransforms();
    SkinnedMeshRenderer targetSMR = GetSlotSMR(data.SlotType);
    targetSMR.sharedMesh = partSMR.sharedMesh;
    targetSMR.materials = partSMR.materials;
    targetSMR.bones = MapBones(partSMR.bones, characterBones);  // 骨骼名匹配

    // 4. 触发属性重算
    stats.OnEquipChanged();
}
```

## 捏脸数据同步

捏脸数据是一组参数化数值，不是模型文件，同步成本极低：

```csharp
// 捏脸参数（几十个 float，不是 MB 级模型文件）
message CharacterAppearance {
    int32 face_type = 1;       // 脸型
    float eye_size = 2;        // 眼睛大小 0-1
    float eye_angle = 3;       // 眼角角度
    float nose_height = 4;     // 鼻梁高度
    float mouth_size = 5;      // 嘴巴大小
    // ... 总共约 30-50 个参数
}
// 同步成本：约 200 字节，远小于一个模型文件（MB 级）

// 客户端收到后用参数驱动 BlendShape 重建面部
public void ApplyAppearance(CharacterAppearance app) {
    skinnedMeshRenderer.SetBlendShapeWeight(EyeSizeIndex, app.EyeSize * 100f);
    skinnedMeshRenderer.SetBlendShapeWeight(NoseHeightIndex, app.NoseHeight * 100f);
    // ...
}
```

## 常见误区

<Callout type="trap">
**误区：装备穿戴在客户端校验就够了。** 如果客户端校验，玩家可以穿未拥有的装备、穿不兼容职业的装备、同时穿多个同槽位装备。服务器校验确保物品在背包中、类型与槽位匹配、职业和等级限制满足。校验通过后服务器更新状态、重算属性、广播给 AOI 范围内玩家。客户端只做表现层播放。
</Callout>

<Exercises>
**问题 1**：属性计算管线的三层结构是什么？

<Answer>
① 基础属性——来自角色等级和职业配置表（baseHP、baseATK）；② 装备加成——遍历已穿戴装备累加其属性词条；③ Buff/Debuff 修饰——按百分比或固定值修正。最终值 = (base + equip) * (1 + buffPercent) + buffFlat。任何一层变化都触发管线重算。
</Answer>

**问题 2**：捏脸数据如何在网络中高效同步？

<Answer>
捏脸数据是参数化数值（如眼睛大小 0.3、鼻子高度 0.7），不是模型文件。创建时客户端把全部参数序列化为 Protobuf 消息（约 200 字节）上传服务器存库。其他玩家需要看到该角色时，服务器下发参数，客户端用参数驱动 BlendShape 重建面部。只传几十个 float，不传模型文件，带宽极小。
</Answer>
</Exercises>
