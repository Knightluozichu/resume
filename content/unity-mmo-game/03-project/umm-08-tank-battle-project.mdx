## 两个必须主动制造的失败

<Callout type="trap" title="局部假设越过边界">
  把炮塔和炮管旋转都写到车身
  Transform，单机看似能瞄准，网络同步一个角度后整个坦克抖动。
  保存故障输入、首偏离状态和拒绝原因，再用相同输入复测修复。
</Callout>

<Callout type="trap" title="最终画面掩盖过程错误">
  碰撞回调直接根据客户端炮弹携带的 damage
  扣血，没有校验攻击者和炮弹生命周期；重复碰撞可多次结算。 即使最终 UI
  看起来正常，只要关键版本、一次性结果或队列预算没有证据，阶段门仍必须拒绝。
</Callout>

## 验收矩阵

| 维度 | 正常样本     | 边界样本               | 失败样本           | 通过条件               |
| ---- | ------------ | ---------------------- | ------------------ | ---------------------- |
| 输入 | 固定合法流程 | 时序、容量或重复临界值 | 畸形、断线或旧代际 | 分类清晰且可重放       |
| 状态 | 单调推进     | 达到预算但不越界       | 在首偏离点停止     | 单一所有者、无隐式写入 |
| 输出 | 双端证据一致 | 退化可解释             | 拒绝、补偿或回滚   | 不产生第二份事实       |
| 恢复 | 下一流程正常 | 压力下降后收敛         | 同输入修复后通过   | 无幽灵状态和重复结果   |

本页签发不变量是：**模型轴和缩放统一；一次炮弹只结算一次命中；视觉特效不能修改生命值；缺失资源产生可诊断失败。** 任何截图、单次演示或平均值都不能替代它。

## 练习

<Exercises>

**问题 1** 为什么要先整理坦克模型层级？

<Answer>
  车身、炮塔、炮管和发射点有不同旋转与位置职责；层级错误会让本地控制和网络同步同时出错。
</Answer>

**问题 2** 资源管理器怎样帮助网络游戏？

<Answer>
  协议只引用受控资源标识，加载、缓存和缺失处理集中在一处，避免远端输入成为任意资源路径。
</Answer>

**问题 3** 炮弹命中为什么要幂等？

<Answer>
  物理回调可能重复或跨帧触发，网络消息也可能重放；同一炮弹标识只能产生一次伤害结果。
</Answer>

</Exercises>
