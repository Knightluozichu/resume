## 从UI界面模块的核心问题开始

网络游戏 UI 不是一组按钮，而是连接与账号状态的可视化投影。面板必须由统一管理器控制层级和生命周期，协议监听要随打开与关闭成对注册，避免隐藏面板继续消费消息。

### BasePanel 定义生命周期

Init 绑定部件，OnShow 注册协议，OnClose 解除监听并释放临时状态。子面板只实现差异，不自行管理全局层级。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### PanelManager 拥有打开实例

面板名称映射到预设与类，管理器按 Panel、Tip 等层级挂载，并保证重复打开策略一致。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### 按钮提交的是状态转换

登录按钮在未连接时先连接，连接中禁用重复提交，收到响应后才转到大厅。UI 不能先假设成功。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

### 协议监听必须成对

OnShow 添加 MsgLogin 或 MsgRegister，OnClose 删除同一委托。协议名写错或遗漏删除都会产生重复回调。

验证时固定客户端版本、服务端版本、协议版本和输入脚本，先保存正常轨迹，再只改变一个边界条件。最终画面相同不代表过程正确；还要比较消息序号、状态版本、队列水位、拒绝原因和恢复动作。

## 小结

- **BasePanel 定义生命周期**：Init 绑定部件，OnShow 注册协议，OnClose 解除监听并释放临时状态。子面板只实现差异，不自行管理全局层级。
- **PanelManager 拥有打开实例**：面板名称映射到预设与类，管理器按 Panel、Tip 等层级挂载，并保证重复打开策略一致。
- **按钮提交的是状态转换**：登录按钮在未连接时先连接，连接中禁用重复提交，收到响应后才转到大厅。UI 不能先假设成功。
- **协议监听必须成对**：OnShow 添加 MsgLogin 或 MsgRegister，OnClose 删除同一委托。协议名写错或遗漏删除都会产生重复回调。
- **GameMain 只负责编排入口**：初始化网络和面板系统、读取非敏感用户名缓存、打开登录面板。密码和令牌不能明文持久化在本地偏好。
- 已用正常、边界和失败样本验证“同名面板实例数量符合策略；关闭面板无残留监听；一次按钮操作最多产生一个在途请求；UI 只投影已确认状态。”。
