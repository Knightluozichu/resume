## 直觉引入

想象你在谷歌地图上浏览。地图不会一次性加载整个地球的卫星图——那会撑爆你的手机内存。它只加载你当前视野范围内的地图块，你拖动地图时新区域加载、旧区域卸载。MMO 的场景流式加载一模一样：把大世界切成网格块，只加载玩家周围九宫格内的块，玩家走远后自动卸载。这样用有限的内存就能支撑无限大的世界。

## 九宫格分块

<Term def="九宫格分块是把大世界切成固定大小的方格，玩家所在格及周围 8 格（共 9 格）始终在内存中，玩家移动时动态加载新格、卸载旧格。">九宫格分块</Term>是场景流式加载的基础策略。每个网格块对应一个 Unity Scene 文件，包含该区域的地形、建筑、植被等静态内容：

```csharp
// 网格管理器：跟踪玩家所在的网格坐标
public class GridManager : MonoBehaviour {
    public float gridSize = 100f;  // 每格 100x100 米
    private Vector2Int currentGrid;
    private HashSet<Vector2Int> loadedGrids = new();

    void Update() {
        Vector2Int newGrid = WorldToGrid(transform.position);
        if (newGrid != currentGrid) {
            OnGridChanged(currentGrid, newGrid);
            currentGrid = newGrid;
        }
    }

    void OnGridChanged(Vector2Int oldGrid, Vector2Int newGrid) {
        var newGrids = GetNineGrids(newGrid);
        var oldGrids = GetNineGrids(oldGrid);

        // 加载新进入的网格块
        foreach (var g in newGrids.Except(oldGrids))
            StartCoroutine(LoadGridAsync(g));

        // 卸载离开的网格块
        foreach (var g in oldGrids.Except(newGrids))
            StartCoroutine(UnloadGridAsync(g));
    }

    Vector2Int WorldToGrid(Vector3 pos) =>
        new((int)(pos.x / gridSize), (int)(pos.z / gridSize));
}
```

## Additive 加载

Unity 的 `SceneManager.LoadSceneAsync` 配合 `LoadSceneMode.Additive` 可以把新场景叠加到当前场景之上，不销毁已有场景：

```csharp
// 异步加载网格块（Additive 模式）
IEnumerator LoadGridAsync(Vector2Int grid) {
    string sceneName = $"Block_{grid.x}_{grid.y}";
    var op = SceneManager.LoadSceneAsync(sceneName, LoadSceneMode.Additive);
    op.allowSceneActivation = false;  // 先加载到 90%，不立即激活

    while (op.progress < 0.9f)
        yield return null;

    // 在帧间隙激活，减少卡顿
    op.allowSceneActivation = true;
    loadedGrids.Add(grid);
}

// 卸载网格块
IEnumerator UnloadGridAsync(Vector2Int grid) {
    string sceneName = $"Block_{grid.x}_{grid.y}";
    var op = SceneManager.UnloadSceneAsync(sceneName);
    yield return op;
    loadedGrids.Remove(grid);
    // 触发资源卸载
    Resources.UnloadUnusedAssets();
}
```

## SubScene 与物理隔离

普通 Additive 场景的物理和光照在所有叠加场景间共享，可能导致跨场景的光照泄漏或物理碰撞混乱。<Term def="SubScene 是 Unity 2020.1+ 引入的场景分割机制，允许每个子场景有独立的物理场景和光照设置，加载/卸载时自动隔离。">SubScene</Term>可以解决这个问题：

```csharp

// 两个相邻网格块的碰撞体不会互相干扰
// 远处地形的碰撞体也不会参与本地物理计算
```

## Addressables 资源管理

<Term def="Addressables 是 Unity 的资源管理系统，支持按需加载、依赖管理、远程更新和引用计数，是 MMO 流式加载的资源基础设施。">Addressables</Term>在流式加载中负责按需加载资源、管理依赖链、控制内存：

```csharp
// 用 Addressables 按需加载场景块的资源
public async Task LoadGridAssets(Vector2Int grid) {
    string label = $"block_{grid.x}_{grid.y}";
    // Addressables 自动处理依赖链：场景 → 材质 → 贴图
    var handle = Addressables.LoadAssetsAsync<GameObject>(label, prefab => {
        // 实例化预制体
        Instantiate(prefab);
    });
    await handle.Task;
    // handle 的引用计数管理资源生命周期
    // 卸载时调用 Addressables.Release(handle) 自动释放
}
```

## 常见误区

<Callout type="trap">
**误区：网格块越小越好，加载更精细。** 网格块太小会导致玩家移动时频繁触发加载/卸载，每次加载都有 IO 开销和内存碎片。网格块太大则一次加载耗时久，可能卡帧。经验值：网格大小取 50-200 米，配合九宫格策略，保证玩家在单格内移动时不需要触发加载。同时用迟滞区间避免边界抖动。
</Callout>

<Exercises>
**问题 1**：为什么 MMO 不能一次性加载整个世界？

<Answer>
MMO 世界可能达数十平方公里，所有地形、建筑、植被的资源（网格、贴图、材质）加起来可能几 GB 甚至几十 GB，远超设备可用内存（移动端可能只有 1-2GB）。流式加载让任意时刻只有玩家周围九宫格在内存中（约几百 MB），用有限的内存支撑无限大的世界。
</Answer>

**问题 2**：SubScene 和普通 Additive 场景有什么区别？

<Answer>
普通 Additive 场景的物理和光照在所有叠加场景间共享，可能导致跨场景光照泄漏或物理碰撞混乱。SubScene 允许每个子场景有独立的物理场景和光照设置，加载/卸载时自动隔离。相邻网格块的物理系统独立运作，远处地形碰撞体不干扰本地逻辑，同时支持按需烘焙光照。
</Answer>
