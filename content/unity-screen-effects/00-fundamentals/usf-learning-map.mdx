## 直觉引入

屏幕特效就像照片的后期处理——先把场景拍下来（渲染到纹理），再用各种滤镜处理（全屏着色器）。模糊让画面柔和，景深让远处虚化，辉光让亮的东西发光，调色改变整体氛围。本书从最基础的 OnRenderImage 出发，逐步构建电影级后处理管线。

### 学习主线
从屏幕特效基础原理出发，利用深度纹理实现特效，掌握后处理栈架构，实现图像效果和光照特效，色彩校正与调色，辉光泛光效果，最后高级屏幕特效综合实战。

### 屏幕特效 vs 普通 Shader
普通 Shader 处理 3D 几何体的顶点和像素，屏幕特效处理全屏 2D 图像。屏幕特效将场景渲染到纹理后，用全屏着色器对每个像素做后处理。

## 代码对照

```csharp
// 屏幕特效基础 — OnRenderImage
[ExecuteAlways]
public class ScreenEffectBase : MonoBehaviour {
    public Material effectMaterial;

    void OnRenderImage(RenderTexture src, RenderTexture dest) {
        if (effectMaterial != null) {
            // src → Shader 处理 → dest
            Graphics.Blit(src, dest, effectMaterial);
        } else {
            Graphics.Blit(src, dest);
        }
    }
}
```

```hlsl
// 屏幕特效 Shader — 全屏处理
sampler2D _MainTex;

fixed4 frag(v2f_img i) : SV_Target {
    // 采样源纹理
    fixed4 col = tex2D(_MainTex, i.uv);
    // 简单反色效果
    return 1.0 - col;
}
```

OnRenderImage 接收 src（场景渲染结果），经材质的 Shader 处理后输出到 dest（屏幕）。每个屏幕特效都是一个全屏着色器。

## 常见误区

<Callout type="trap">
**现象 →** 把屏幕特效写在普通物体 Shader 中。
**原因 →** 不理解屏幕特效是全屏 2D 处理。
**修法 →** 屏幕特效必须通过 OnRenderImage 或后处理栈执行，处理的是全屏 RenderTexture 而非 3D 几何体。需要 C# 脚本驱动，不能直接挂在物体材质上。
</Callout>

<Callout type="trap">
**现象 →** 每个效果都用单独的 OnRenderImage，性能很差。
**原因 →** 每个 Blit 都是一次全屏绘制调用。
**修法 →** 合并多个效果到一个 Shader 的多个 Pass。使用 RenderTexture 池化避免频繁创建销毁。降分辨率处理再上采样。优先使用后处理栈或 URP RenderFeature 统一管理。
</Callout>

**问题**：屏幕特效和普通 Shader 的核心区别是什么？

<Answer>
普通 Shader 处理 3D 几何体的顶点和像素，屏幕特效处理全屏 2D 图像。屏幕特效将场景渲染到纹理后，用全屏着色器对每个像素做后处理（模糊、调色、辉光等），不需要几何体数据。

</Answer>
