## 第一版权威目录定位

本页一一对应Kenny Lammers《Unity Shaders and Effects Cookbook》第一版中译本《Unity着色器和屏幕特效开发秘笈》第6章 透明度。书目确认机械工业出版社2014年出版、晏伟译、ISBN 9787111480563；正式目录确认全书11章。原书基于早期Unity内置渲染管线，现代Unity项目应复用原理并单独映射API。

### 原章核心配方

1. Alpha参数透明
2. 透明裁剪
3. 渲染队列与深度排序
4. GUI与透明度

### 五个核心对象

1. **Alpha混合**：按源Alpha把透明表面颜色与背景组合。
2. **Alpha裁剪**：按阈值完全保留或丢弃片元的硬边透明。
3. **渲染队列**：控制不透明、裁剪和透明对象执行大类顺序。
4. **深度排序**：为透明表面安排远近绘制顺序以近似正确合成。
5. **GUI透明**：在界面纹理与字体上保留Alpha和混合语义的处理。

## 数据流与公式

比较Alpha混合与Alpha裁剪，显式配置Queue、RenderType、Blend和ZWrite。构造交叉透明面、树叶边缘与GUI案例，展示透明排序不是片元函数能单独解决的问题。 先画出材质属性、纹理、Surface或顶点函数、生成Pass、脚本回调、RenderTexture和固定状态的生产者到消费者链，再把本章对象放到对应阶段。

$$
Co=alpha*Cs+(1-alpha)*Cd
$$

$$
clip(alpha-cutoff)
$$

$$
transparentOrder=backToFront
$$

$$
depthWrite=false for common alpha blend
$$

公式中的方向、颜色、UV、时间与深度必须标注空间、范围和单位。Surface输出或全屏片元输出只是候选结果，最终仍受Pass选择、深度、混合、目标格式和颜色空间影响。

## 最小实现

```shaderlab
Tags { "Queue"="Transparent" } Blend SrcAlpha OneMinusSrcAlpha ZWrite Off
```

实现顺序固定为常量输出、输入可视化、核心公式、材质或脚本绑定和固定状态。先确认Shader支持、实际Pass与源目标正确，再解释画面变化。

## 边界、精度与性能

测试零向量、退化UV、镜像UV、负缩放、透明交叉、纯黑纯白、HDR颜色、不同宽高比、多效果串联和高过度绘制。性能实验固定目标设备、分辨率、VSync与场景，先判断CPU还是GPU受限，再定位具体Draw、采样与Shader阶段。

```text
unity: exact editor and player version
pipeline: Built-in and named rendering path
resources: mesh, texture import, material and target format
state: queue, depth, cull, blend and pass order
evidence: image diff, frame debugger, GPU capture, CPU/GPU ms
failure: smallest replayable counterexample
```

1. 用常量颜色或原样Blit确认材质、脚本、Pass和目标可执行。
2. 可视化UV、法线、深度、遮罩、单个光照项或中间纹理。
3. 打开本章效果，保存基线、候选和参数。
4. 构造边界与失败输入，用帧调试和GPU捕获解释差异。

## 验收证书

证书包含源码版本、Unity与图形API、脚本绑定、资源哈希、Pass状态、源图和中间图、GPU事件、CPU/GPU帧时间与失败反例。开启Alpha输出却仍在Geometry队列写深度，透明对象前后关系随相机变化错误。 修复后必须用同一输入重放，并指出变化发生在哪个阶段。

## 常见误区

<Callout type="trap" title="配方没有执行证据">开启Alpha输出却仍在Geometry队列写深度，透明对象前后关系随相机变化错误。</Callout>

<Callout type="trap" title="只看最终画面">画面相似不证明实际Pass、空间、纹理、混合和性能等价。必须保存中间调试视图、固定状态和帧捕获。</Callout>

## 本章回顾

本页覆盖Alpha混合、Alpha裁剪、渲染队列、深度排序、GUI透明。掌握标准是能画出数据流，写出最小实现，说明材质与脚本契约，再用正确性、边界、精度和性能证据复现结论。
