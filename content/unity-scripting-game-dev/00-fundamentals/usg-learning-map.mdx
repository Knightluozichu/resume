## 直觉引入

做 Unity 游戏像盖一栋楼。C# 语法是砖瓦（变量、类、控制流），Unity API 是施工工具（Transform 移动、Input 输入、Time 计时），组件模式是楼的结构（GameObject 当楼层，Component 当房间），游戏循环是楼的运转（每帧更新电梯、水电），协程与事件是楼的智能系统（定时任务、广播通知），数据持久化是楼的仓库（存档、配置），优化与发布是验收交付（性能达标、上架商店）。

## 代码对照

```csharp
// Unity 脚本的基本结构
public class PlayerController : MonoBehaviour {
    [SerializeField] private float speed = 5f; // Inspector 可编辑
    private Rigidbody _rb; // 缓存引用

    void Awake() { _rb = GetComponent<Rigidbody>(); } // 初始化
    void Start() { /* 第一帧前调用 */ }

    void Update() {
        // 每帧逻辑：输入驱动移动，乘 deltaTime 保证帧率无关
        float h = Input.GetAxis("Horizontal");
        transform.Translate(Vector3.right * h * speed * Time.deltaTime);
    }

    // 协程：跨帧异步
    IEnumerator DelayedSpawn() {
        yield return new WaitForSeconds(2f);
        Instantiate(enemyPrefab, transform.position, Quaternion.identity);
    }
}
```

## 常见误区

<Callout type="trap">
**误区：跳过 C# 基础直接学 Unity。**
Unity 脚本就是 C# 代码——不掌握变量类型、类、继承、泛型、委托，写出来的脚本是「能跑但看不懂」的拼凑。正确做法：先花一两天过一遍 C# 语法基础（值类型/引用类型、类/继承、访问修饰符），再进入 Unity API，这样每个 API 调用都能理解背后的语言机制。
</Callout>

<Callout type="trap">
**误区：把所有功能写在一个脚本里（God Class）。**
一个脚本里写移动、攻击、背包、UI、存档——这是典型的 God Class 反模式。应该拆分为 PlayerMovement、PlayerCombat、Inventory 等组件，通过 GetComponent 和事件系统通信。职责单一、组合优于继承是 Unity 脚本设计的核心原则。
</Callout>

**问题 2**：为什么 Unity 脚本要继承 MonoBehaviour？

<Answer>
因为 Unity 的组件系统基于 MonoBehaviour。只有继承 MonoBehaviour 的类才能挂载到 GameObject 上，参与 Unity 的生命周期回调（Awake/Start/Update）、序列化系统（Inspector 显示字段）和事件系统（OnCollisionEnter 等）。MonoBehaviour 是 Unity 引擎与 C# 代码的桥梁——它让普通 C# 类变成 Unity 组件，可以被引擎识别、序列化、调度。如果不需要挂载到 GameObject，可以用普通 C# 类做纯逻辑或 ScriptableObject 做数据容器。
</Answer>
