## 直觉引入

C# 是 Unity 的官方脚本语言。写 Unity 脚本就是写 C# 类——但不是普通 C# 类，而是继承 MonoBehaviour 的特殊类。普通 C# 类用 `new` 创建，MonoBehaviour 用 `AddComponent` 挂载。普通类的字段靠构造函数初始化，Unity 脚本的字段可以靠 Inspector 序列化。理解这层「C# 语言基础 + Unity 扩展」的关系，才能写出结构清晰、可维护的游戏脚本。

<Term def="[SerializeField] 是 Unity 特性，让 private 字段也能在 Inspector 显示和编辑，兼顾封装性与可配置性">SerializeField</Term>是 Unity 脚本的特色。

<Term def="访问修饰符控制成员可见性：public 全局可见，private 仅类内，protected 类及子类，internal 程序集内">访问修饰符</Term>决定字段能否被 Inspector 序列化。

Unity 规则：public 字段自动序列化（Inspector 可见），private 字段默认不可见，加 `[SerializeField]` 后可见。推荐用 `[SerializeField] private` 而非 public——既能在 Inspector 编辑，又保持封装。

## 代码对照

```csharp
// C# 基础：值类型 vs 引用类型
public class Example : MonoBehaviour {
    // 值类型：赋值拷贝
    private int hp = 100;
    private Vector3 pos = Vector3.zero;

    // 引用类型：赋值共享引用
    private string name = "Player";
    private int[] scores = new int[] { 10, 20, 30 };

    // Unity 序列化字段
    [SerializeField] private float speed = 5f;   // Inspector 可见，代码内私有
    public int maxHp = 100;                       // Inspector 可见，代码内公开
    private int currentHp;                        // Inspector 不可见

    // 类继承
    public class Enemy : MonoBehaviour {
        [SerializeField] protected int damage = 10; // 子类可访问

        public virtual void Attack() { Debug.Log("攻击"); }
    }

    public class Boss : Enemy {
        public override void Attack() { Debug.Log("Boss 重击"); }
    }
}
```

## 常见误区

<Callout type="trap">
**误区：在 Unity 脚本中使用 `new` 实例化 MonoBehaviour。**
MonoBehaviour 只能通过 `AddComponent` 或挂载到 GameObject 上创建，不能用 `new PlayerController()`。Unity 内部需要管理组件的生命周期，`new` 出来的对象脱离了引擎管理，生命周期回调不会触发。正确做法：`gameObject.AddComponent<PlayerController>()`，或在 Inspector 直接挂载。
</Callout>

<Callout type="trap">
**误区：所有字段都用 public 方便 Inspector 编辑。**
public 暴露了内部实现，其他脚本可以直接修改，破坏封装性。一旦字段名变化，所有引用都要改。正确做法：用 `[SerializeField] private` 让字段在 Inspector 可编辑但代码内私有，需要外部访问时用属性（property）封装。
</Callout>

<Exercises>
**问题 1**：值类型和引用类型在赋值时有什么区别？这对 Unity 脚本有什么影响？

<Answer>
值类型（int/float/struct/Vector3）赋值时拷贝数据——修改副本不影响原值。引用类型（class/string/数组）赋值时拷贝引用——两个变量指向同一个对象，修改任一都能影响对方。在 Unity 中：`Vector3 a = b; a.x = 1;` 不影响 b（值类型拷贝）；`Transform t = otherTransform; t.position = ...;` 会影响原对象（引用共享）。理解这点能避免「改了副本却以为改了原值」的 bug。
</Answer>

**问题 2**：为什么推荐用 `[SerializeField] private` 而非 `public` 暴露字段？

<Answer>
public 字段虽然在 Inspector 可编辑，但破坏封装——其他脚本可直接读写，字段一旦改名所有引用都要改，且无法加入校验逻辑。`[SerializeField] private` 让字段在 Inspector 可编辑（满足配置需求），但代码内是私有的（外部不能直接访问），兼顾了可配置性与封装性。需要外部访问时用属性（property）封装，可在 getter/setter 加入校验。这是 Unity 脚本设计的最佳实践。
</Answer>
</Exercises>
