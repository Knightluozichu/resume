## 直觉引入

游戏数据有三种「仓库」。PlayerPrefs 是「抽屉」——放钥匙、硬币等小东西（音量、最高分），随手存取但不放贵重物品。JSON 文件是「保险箱」——放复杂存档（背包、任务进度、角色状态），上锁可迁移。ScriptableObject 是「设计图纸」——放配置数据（武器参数、敌人属性），设计师在 Inspector 编辑，运行时多对象共享。选对仓库，数据管理才能既安全又高效。

### 三种持久化方案

## 代码对照

```csharp
// 1. PlayerPrefs：轻量设置
public class Settings : MonoBehaviour {
    public void SaveVolume(float vol) {
        PlayerPrefs.SetFloat("Volume", vol);
        PlayerPrefs.Save(); // 立即写入
    }

    public float LoadVolume() {
        return PlayerPrefs.GetFloat("Volume", 0.8f); // 默认0.8
    }
}

// 2. JSON 存档
[Serializable]
public class GameSave {
    public int level;
    public float playerHp;
    public Vector3 playerPos;
    public List<string> inventory;
}

public class SaveSystem : MonoBehaviour {
    private string SavePath => Application.persistentDataPath + "/save.json";

    public void Save(GameSave data) {
        string json = JsonUtility.ToJson(data, true); // true=美化格式
        File.WriteAllText(SavePath, json);
    }

    public GameSave Load() {
        if (!File.Exists(SavePath)) return null;
        string json = File.ReadAllText(SavePath);
        return JsonUtility.FromJson<GameSave>(json);
    }
}

// 3. ScriptableObject：配置数据
[CreateAssetMenu(fileName = "Weapon", menuName = "Config/Weapon")]
public class WeaponConfig : ScriptableObject {
    public string weaponName;
    public int damage;
    public float fireRate;
    public GameObject prefab;
}

public class Weapon : MonoBehaviour {
    [SerializeField] private WeaponConfig config; // 引用配置资产

    void Fire() {
        Debug.Log($"{config.weaponName} 造成 {config.damage} 伤害");
    }
}
```

## 常见误区

<Callout type="trap">
**误区：用 PlayerPrefs 存储游戏存档（背包、任务进度）。**
PlayerPrefs 只支持 int/float/string 三种基本类型，不支持数组、列表、嵌套对象。强行用多个 key 拆分存储会导致数据碎片化、难以维护、容易出错。正确做法：复杂存档用 JSON 文件——定义一个 `[Serializable]` 存档类，用 JsonUtility 序列化为 JSON，写入 persistentDataPath。PlayerPrefs 只存轻量设置（音量、最高分、语言选择）。
</Callout>

<Callout type="trap">
**误区：ScriptableObject 运行时修改的数据在重启后丢失。**
ScriptableObject 是资产文件，在构建后的游戏中是只读的——运行时修改的字段值在游戏退出后不会保存。如果需要运行时持久化配置数据（如玩家解锁的武器），仍需配合 JSON 文件保存。ScriptableObject 的定位是「设计师编辑的配置」而非「玩家运行时数据」。正确做法：ScriptableObject 存静态配置（武器基础参数），JSON 存动态数据（玩家解锁状态）。
</Callout>

<Exercises>
**问题 1**：三种持久化方案分别适合什么场景？

<Answer>
PlayerPrefs 适合轻量设置数据（音量、最高分、语言选择）——键值对、简单类型、容量小。JSON 文件适合游戏存档（背包、任务进度、角色状态）——支持复杂嵌套对象、可跨平台持久化、写入 persistentDataPath。ScriptableObject 适合配置数据（武器参数、角色属性、关卡配置）——设计师在 Inspector 编辑、多对象共享、数据与逻辑分离。选择原则：轻量用 PlayerPrefs，存档用 JSON，配置用 ScriptableObject。
</Answer>

**问题 2**：如何实现一个跨平台的存档系统？

<Answer>
1)定义 `[Serializable]` 存档类，包含所有需要保存的字段（关卡、血量、位置、背包）。2)用 `JsonUtility.ToJson(data, true)` 序列化为 JSON 字符串。3)用 `File.WriteAllText(Application.persistentDataPath + "/save.json", json)` 写入文件——persistentDataPath 是 Unity 提供的跨平台可写路径（Windows 在 AppData，Android 在外部存储，iOS 在沙盒）。4)读取用 `File.ReadAllText` + `JsonUtility.FromJson`，文件不存在时返回默认值。5)处理版本迁移——存档加 version 字段，升级时做数据迁移。
</Answer>
</Exercises>
