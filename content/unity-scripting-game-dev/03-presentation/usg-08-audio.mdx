## 核心模型与行为不变量

AudioSource产生声音，唯一有效AudioListener定义接收位置，音频管理器按音乐和音效路由事件。短音效池化，长音乐交叉淡化，空间声音必须设置距离和衰减。

先写功能切片：输入来自哪里，哪个对象拥有状态，在哪个Unity回调更新，调用哪个引擎系统，输出由谁消费，失败时第一条信号是什么。脚本、Inspector引用和场景对象都必须能回到同一个切片编号。

场景切换后只有一个侦听器，重复事件可限流，音乐切换连续且用户音量设置始终生效。 这条不变量要在正常、边界和失败三组输入下成立。最终画面正确但中间所有权、时序或资源生命周期错误，仍不能签发。

## 从输入到结果的数据链

本章主链是：游戏事件 → 音频路由 → 剪辑选择 → 空间参数 → 混合播放 → 结束回收。每个节点保存切片ID、帧号、对象ID和状态版本。表现系统只能呈现玩法事实，资源与数据系统必须通过租约或快照管理生命周期。

```csharp
public void PlaySfx(AudioCue cue, Vector3 position)
{
    if (!limiter.TryAcquire(cue.Id)) return;
    AudioSource source = pool.Get();
    cue.Configure(source, position, settings.SfxVolume);
    source.Play();
}
```

旧输入API、Text、AssetBundle或LitJSON可以迁移到Input System、TextMeshPro、Addressables或System.Text.Json，但迁移账本必须写明原书问题、替代实现、保留不变量和对照证据。

## 两个必须主动制造的失败样本

<Callout type="trap" title="目录或案例漂移">
  多个摄像机都启用AudioListener，或每次命中创建新AudioSource不回收，造成警告、削波和分配尖峰。
  这种实现即使运行正常，也没有覆盖第8章的原书边界。先恢复目录与命名实例，再讨论扩展。
</Callout>

<Callout type="trap" title="结果正确、时序错误">
  故意在低帧率、重复触发、对象禁用和场景卸载时回放。若出现重复结算、旧协程继续运行、事件未退订或资源提前释放，说明状态所有权仍不合格。
</Callout>
