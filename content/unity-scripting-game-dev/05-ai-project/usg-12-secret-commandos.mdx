## 核心模型与行为不变量

综合实例把前11章汇入潜行闭环：主角移动、动画、武器挂点和抛物线指示提供行动；敌人巡逻、视觉、追击和攻击提供压力；关卡裁决统一成功失败。

先写功能切片：输入来自哪里，哪个对象拥有状态，在哪个Unity回调更新，调用哪个引擎系统，输出由谁消费，失败时第一条信号是什么。脚本、Inspector引用和场景对象都必须能回到同一个切片编号。

主角、敌人和关卡各有单一状态权威，武器切换不丢挂点，抛物线与真实投掷使用同一物理参数。 这条不变量要在正常、边界和失败三组输入下成立。最终画面正确但中间所有权、时序或资源生命周期错误，仍不能签发。

## 从输入到结果的数据链

本章主链是：潜行目标 → 主角控制 → 武器道具 → 敌人感知FSM → 关卡交互 → 成功失败。每个节点保存切片ID、帧号、对象ID和状态版本。表现系统只能呈现玩法事实，资源与数据系统必须通过租约或快照管理生命周期。

```csharp
Vector3 SampleTrajectory(Vector3 origin, Vector3 velocity, float t)
{
    return origin + velocity * t + 0.5f * Physics.gravity * t * t;
}

void ResolveMission(MissionEvent e) => missionState.Apply(e);
```

旧输入API、Text、AssetBundle或LitJSON可以迁移到Input System、TextMeshPro、Addressables或System.Text.Json，但迁移账本必须写明原书问题、替代实现、保留不变量和对照证据。

## 两个必须主动制造的失败样本

<Callout type="trap" title="目录或案例漂移">
  预览轨迹与实际投掷使用不同重力，或敌人脚本同时决定玩家死亡和关卡结束，造成结果竞态。
  这种实现即使运行正常，也没有覆盖第12章的原书边界。先恢复目录与命名实例，再讨论扩展。
</Callout>

<Callout type="trap" title="结果正确、时序错误">
  故意在低帧率、重复触发、对象禁用和场景卸载时回放。若出现重复结算、旧协程继续运行、事件未退订或资源提前释放，说明状态所有权仍不合格。
</Callout>

## 当前Unity迁移表

| 原书对象            | 当前实现                           | 必须保留的证据                 |
| ------------------- | ---------------------------------- | ------------------------------ |
| 旧输入、UI或资源API | 当前官方包或兼容层                 | 原案例输入、状态和结果对照     |
| MonoBehaviour回调   | 明确时钟与状态所有者的组件         | Awake到Destroy的顺序日志       |
| 场景公开引用        | SerializeField、稳定ID或运行时注入 | 缺失引用检查和场景重载回放     |
| 手工创建销毁        | 仅在证据支持时使用对象池或租约     | 创建、复位、唯一释放和峰值数据 |

现代迁移不能把原书内容改写为通用最佳实践清单。每章首先复现其具体系统和实例，再补充版本差异、性能风险和可测试接口。
