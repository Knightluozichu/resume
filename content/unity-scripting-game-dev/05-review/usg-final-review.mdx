## 直觉引入

全书像一条流水线：C# 语法是原料，Unity API 是工具，组件架构是组装线，游戏循环是传送带，协程与事件是自动化控制，数据持久化是成品仓库，优化是质检，构建发布是出货。每个环节缺一不可——没有 C# 基础写不出脚本，没有组件架构代码混乱，没有游戏循环游戏不动，没有数据持久化进度丢失，没有优化卡顿掉帧，没有构建发布玩家玩不到。总复习就是把这条流水线在脑中连成一张图。

## 代码对照

```csharp
// 全书知识综合：一个完整的敌人系统
public class Enemy : MonoBehaviour {
    [SerializeField] private EnemyConfig config; // ScriptableObject 配置
    [SerializeField] private GameObject deathEffect;
    private Rigidbody _rb;
    private int _hp;

    // 事件系统：解耦通知
    public static event Action<Enemy> OnEnemyKilled;

    void Awake() {
        _rb = GetComponent<Rigidbody>(); // 缓存引用
        _hp = config.maxHp;
    }

    void OnEnable() {
        // 事件订阅生命周期与启用状态一致
        Player.OnPlayerAttack += HandlePlayerAttack;
        StartCoroutine(BehaviorRoutine()); // 协程：AI 行为
    }

    void OnDisable() {
        Player.OnPlayerAttack -= HandlePlayerAttack;
        StopAllCoroutines();
    }

    void FixedUpdate() {
        // 物理：固定步长移动
        _rb.MovePosition(transform.position + transform.forward * config.speed * Time.fixedDeltaTime);
    }

    // 协程：跨帧 AI 序列
    IEnumerator BehaviorRoutine() {
        while (true) {
            yield return new WaitForSeconds(config.thinkInterval);
            // AI 决策...
        }
    }

    public void TakeDamage(int damage) {
        _hp -= damage;
        if (_hp <= 0) Die();
    }

    void Die() {
        OnEnemyKilled?.Invoke(this); // 事件：通知计分板/任务系统
        if (deathEffect) {
            var effect = ObjectPool.Get(deathEffect); // 对象池：复用特效
            effect.transform.position = transform.position;
        }
        ObjectPool.Return(gameObject); // 对象池：回收而非销毁
    }
}
```

## 常见误区

<Callout type="trap">
**误区：学完就忘，没有形成知识网络。**
孤立记忆每个 API 容易遗忘——知识要用「问题链」串联：为什么用 MonoBehaviour？→ 因为要挂载到 GameObject → 为什么用组件？→ 组合优于继承 → 组件怎么通信？→ GetComponent 和事件 → 事件订阅放哪？→ OnEnable/OnDisable → 为什么？→ 生命周期一致性。用「为什么」串联知识点，形成因果链，比死记硬背牢固十倍。
</Callout>

<Callout type="trap">
**误区：只看不动手，学完做不出游戏。**
看书能理解概念，但只有动手写才能形成肌肉记忆。正确做法：每学一个章节就做一个微型练习——学完 C# 基础写一个简单移动脚本，学完组件模式拆分一个 God Class，学完协程写一个定时生成系统，学完数据持久化做存档功能，学完优化用 Profiler 分析自己的代码。最后综合做一个完整的小游戏（打砖块/太空射击），把所有知识用一遍。
</Callout>

<Exercises>
**问题 1**：全书五大板块之间是什么关系？请用一条主线串联。

<Answer>
五大板块呈递进依赖关系，主线是「从语言到产品」：1)基础入门提供语言基础（C# 语法）和工具（Unity API），没有它们写不出脚本；2)游戏逻辑提供架构骨架（组件模式）和运转机制（游戏循环），没有它们代码混乱且游戏不动；3)进阶机制提供高级工具（协程做异步、事件做通信、持久化做存档），没有它们游戏缺乏深度；4)项目实战提供工程能力（优化保证流畅、构建发布送达玩家），没有它们游戏无法交付；5)总复习串联检查。每一层建立在前一层之上，缺一不可。
</Answer>

**问题 2**：学完全书后，如何独立完成一个 Unity 游戏的脚本开发？

<Answer>
1)规划架构：用组件模式拆分功能（Player/Enemy/UI/Manager），每个组件职责单一。2)实现基础：写 MonoBehaviour 脚本，用四大 API 做交互，Update 处理输入，FixedUpdate 处理物理。3)加异步与通信：用协程做延迟序列（生成/爆炸），用事件系统解耦组件（击杀通知计分）。4)做存档：用 JSON 存游戏进度到 persistentDataPath，用 ScriptableObject 存配置数据，PlayerPrefs 存设置。5)优化：用对象池复用对象，缓存 GetComponent，用 Profiler 定位瓶颈。6)发布：Build Settings 选平台，Player Settings 配置，过检查清单，真机测试，构建上架。
</Answer>
