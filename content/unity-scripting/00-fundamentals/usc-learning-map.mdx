## 直觉引入

写 Unity 脚本就像给机器人编程。MonoBehaviour 是机器人的「操作系统」——提供开机（Awake）、启动（Start）、每帧思考（Update）等生命周期。组件系统是机器人的「身体结构」——每个零件是一个组件，组合起来形成完整功能。核心机制（物理/协程/ScriptableObject）是「肌肉和神经」——让机器人能动、能等、能记。进阶编程是「大脑」——设计模式和架构让机器人聪明高效。

### 全书结构

<UscLearningMapDiagram />

<Term def="MonoBehaviour是Unity所有脚本的基类，提供生命周期方法、协程支持、序列化和Inspector集成">MonoBehaviour</Term>是脚本的入口。

<Term def="协程(Coroutine)是Unity的异步编程机制，用迭代器实现跨帧延迟执行，适合动画序列、延迟操作、异步加载">协程</Term>是异步的利器。

<Term def="ScriptableObject是Unity的数据容器资产，用于存储配置数据，实现数据与逻辑分离，可在多对象间共享">ScriptableObject</Term>是数据的容器。

全书分四大板块：脚本基础（MonoBehaviour/C#）→ 组件系统（架构/生命周期/输入）→ 核心机制（物理/协程/数据）→ 进阶编程（模式/架构/复习）。

## 代码对照

```csharp
// Unity 脚本的基本结构
public class PlayerController : MonoBehaviour {
    [SerializeField] private float speed = 5f; // Inspector 可编辑

    void Awake() { /* 初始化，早于 Start */ }
    void Start() { /* 第一帧前调用 */ }
    void Update() { /* 每帧调用 */ }

    // 组件间通信
    void OnCollisionEnter(Collision other) {
        var enemy = other.GetComponent<Enemy>();
        if (enemy != null) enemy.TakeDamage(10);
    }

    // 协程
    IEnumerator DelayedAction() {
        yield return new WaitForSeconds(2f);
        Debug.Log("2秒后执行");
    }
}
```

## 常见误区

<Callout type="trap">
**误区：在构造函数中初始化字段或访问其他组件。**
Unity 的 MonoBehaviour 构造函数由 Unity 内部调用，此时对象可能未完全初始化。在构造函数中访问 transform、GetComponent 等会报错。正确做法：在 Awake 中初始化（此时对象已创建但场景未完全加载），在 Start 中获取其他组件引用（此时所有对象已 Awake）。
</Callout>

<Callout type="trap">
**误区：把所有游戏逻辑写在一个脚本里（God Class）。**
一个 PlayerController 脚本里写移动、攻击、背包、UI、存档——这是典型的 God Class 反模式。应该拆分为 PlayerMovement（移动）、PlayerCombat（战斗）、Inventory（背包）等组件，通过 GetComponent 互相通信。职责单一、组合优于继承是 Unity 脚本设计的核心原则。
</Callout>

<Exercises>
**问题 1**：全书四大板块是什么？它们之间是什么关系？

<Answer>
脚本基础、组件系统、核心机制、进阶编程。呈递进关系：脚本基础是入门（掌握 MonoBehaviour 和 C# 语法），组件系统是架构理解（生命周期、组件协作、输入处理），核心机制是工具掌握（物理、协程、数据资产），进阶编程是架构升华（设计模式、SOLID 原则）。每一层建立在前一层之上。
</Answer>

**问题 2**：为什么 Unity 脚本必须继承 MonoBehaviour？

<Answer>
因为 Unity 的组件系统基于 MonoBehaviour。只有继承 MonoBehaviour 的类才能挂载到 GameObject 上，参与 Unity 的生命周期回调（Awake/Start/Update）、序列化系统（Inspector 显示字段）和事件系统（OnCollisionEnter 等）。MonoBehaviour 是 Unity 引擎与 C# 代码的桥梁——它让普通 C# 类变成 Unity 组件，可以被引擎识别、序列化、调度。如果不需要挂载到 GameObject，可以用普通 C# 类做纯逻辑或 ScriptableObject 做数据容器。
</Answer>
</Exercises>
