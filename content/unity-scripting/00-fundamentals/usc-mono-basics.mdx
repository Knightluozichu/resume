## 直觉引入

MonoBehaviour 的生命周期像人的一生。Awake 是出生（对象创建），Start 是入学（第一帧前），Update 是每天工作（每帧），LateUpdate 是下班后总结（Update 后），OnDisable 是休假（暂时禁用），OnDestroy 是退休（对象销毁）。理解这些方法的调用时机和顺序，是写好 Unity 脚本的基础。

### 生命周期方法

<Term def="Start在对象启用后第一帧Update之前调用，用于获取其他组件引用和执行依赖初始化">Start</Term>是依赖初始化。

## 代码对照

```csharp
public class Player : MonoBehaviour {
    [Header("移动")]
    [SerializeField] private float speed = 5f;      // Inspector可编辑
    [SerializeField] [Range(0, 100)] private int hp = 100;

    private Rigidbody _rb; // 缓存引用

    void Awake() {
        _rb = GetComponent<Rigidbody>(); // 自身组件引用
    }

    void Start() {
        // 其他对象的引用在此获取
        var manager = FindObjectOfType<GameManager>();
    }

    void Update() {
        float h = Input.GetAxis("Horizontal");
        // 输入和逻辑
    }

    void FixedUpdate() {
        _rb.AddForce(Vector3.forward * speed); // 物理力
    }

    void LateUpdate() {
        // 相机跟随（确保角色已移动）
    }

    void OnDisable() {
        // 清理：停止协程、取消事件订阅
    }
}
```

## 常见误区

<Callout type="trap">
**误区：在构造函数中初始化字段或访问 Unity API。**
Unity 的 MonoBehaviour 构造函数由 Unity 内部调用（反序列化时），此时 transform、GetComponent 等 API 可能不可用。在构造函数中访问这些 API 会报 NullReferenceException 或「can only be called from the main thread」错误。正确做法：所有 Unity API 操作放在 Awake 中。构造函数只做纯 C# 字段赋值。
</Callout>

<Callout type="trap">
**误区：在 Update 中做物理操作（如 transform.position 直接移动）。**
Update 帧率波动，直接修改 transform 会导致物理碰撞检测不稳定（穿透）。物理操作应该放 FixedUpdate（固定时间步），用 Rigidbody.AddForce 或 Rigidbody.MovePosition。如果必须在 Update 中移动，用 Rigidbody.MovePosition 在 FixedUpdate 中插值。Time.deltaTime 在 Update 中用，Time.fixedDeltaTime 在 FixedUpdate 中用。
</Callout>

<Exercises>
**问题 1**：Awake 和 Start 有什么区别？分别在什么时候调用？

<Answer>
Awake 在对象创建时调用（Instantiate 后立即），无论脚本是否启用。Start 在对象启用后第一帧 Update 之前调用。区别：Awake 用于初始化自身状态和缓存自身组件引用，Start 用于获取其他对象的引用（此时所有 Awake 已完成）。如果脚本初始禁用（enabled=false），Awake 仍调用但 Start 不调用——直到启用时才调用。OnEnable 在 Awake 之后、Start 之前调用，每次启用都会触发。
</Answer>

**问题 2**：为什么推荐用 [SerializeField] private 替代 public 字段？

<Answer>
1)封装性：private 字段不能被其他脚本直接修改，防止外部意外破坏内部状态。2)Inspector 可编辑：[SerializeField] 让 private 字段在 Inspector 显示，保留编辑能力。3)API 清晰：public 意味着「对外接口」，数据字段不应该是接口——外部需要访问时用 public 属性（get/set）。4)重构友好：private 字段重命名不影响其他脚本，public 字段重命名可能破坏引用。原则：数据用 [SerializeField] private，行为用 public 方法。
</Answer>
</Exercises>
