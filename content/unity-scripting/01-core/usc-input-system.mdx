## 直觉引入

玩家用手柄还是键鼠？触屏还是 VR 手柄？一个好的游戏应该支持多种输入设备。Unity 有两套输入系统：旧的 Input Manager（简单直接，Input.GetAxis 一行搞定）和新的 Input System（功能强大，支持多设备统一和事件驱动）。理解两者的区别和选型，是游戏输入设计的基础。

## 概念讲解

### 输入系统对比

<UscInputSystemDiagram />

<Term def="旧输入系统(Input Manager)是Unity内置的输入系统，用Input类的静态方法(GetAxis/GetKey)轮询输入，简单但不支持多设备统一">旧输入系统</Term>简单但有限。

<Term def="新输入系统(Input System Package)是Unity的Package，基于InputAction和事件驱动，支持多设备统一、运行时重绑定、VR/AR设备">新输入系统</Term>强大且面向未来。

<Term def="InputAction是新输入系统的核心概念，封装一个操作(如Move/Jump)及其绑定的输入设备，支持事件回调和轮询">InputAction</Term>是新系统的核心。

<Term def="GetAxis返回平滑插值(-1~1)，GetAxisRaw返回离散值(-1/0/1)，前者有惯性后者即时响应">GetAxis</Term>与 GetAxisRaw。

## 交互Demo

<Stepper>
<Step title="第一步：旧输入系统">Input.GetAxis("Horizontal") 返回 -1~1 的平滑值（松开按键逐渐回 0）。Input.GetKeyDown(KeyCode.Space) 返回按下这一帧的布尔值。简单直接，适合快速原型。缺点：配置在 ProjectSettings 中不可热重载，多设备支持差。</Step>
<Step title="第二步：新输入系统">
创建 InputActionAsset 定义 Actions（Move/Jump/Interact），为每个 Action 绑定设备输入。代码中用事件回调：action.performed += ctx => { }。支持键鼠/手柄/触摸统一处理，运行时重绑定（玩家自定义按键）。
<UscInputSystemDiagram />
</Step>
<Step title="第三步：选型策略">快速原型用旧输入系统（一行代码搞定），正式项目用新输入系统（多设备、事件驱动、可重绑定）。新输入系统是 Unity 的未来方向，旧系统已停止更新。两者不能同时激活（Project Settings → Active Input Handling 切换）。</Step>
</Stepper>

## 代码对照

```csharp
// === 旧输入系统 ===
void Update() {
    float h = Input.GetAxis("Horizontal");     // 平滑：-1~1
    float raw = Input.GetAxisRaw("Horizontal"); // 离散：-1/0/1
    if (Input.GetKeyDown(KeyCode.Space)) Jump();
    if (Input.GetMouseButton(0)) Shoot();
}

// === 新输入系统 ===
[SerializeField] private InputActionAsset actions;
private InputAction _moveAction;

void OnEnable() {
    _moveAction = actions.FindAction("Move");
    _moveAction.performed += OnMove;
    _moveAction.Enable();
}
void OnDisable() {
    _moveAction.performed -= OnMove;
    _moveAction.Disable();
}
void OnMove(InputAction.CallbackContext ctx) {
    Vector2 dir = ctx.ReadValue<Vector2>(); // 事件驱动
}
// 也可以轮询：Vector2 dir = _moveAction.ReadValue<Vector2>();
```

## 常见误区

<Callout type="trap">
**误区：在新输入系统中仍然用 Input.GetKeyDown 检测按键。**
新输入系统激活后，旧的 Input 类不再工作（Input.GetKey 返回 false）。必须通过 InputAction 检测输入：创建 Action 绑定按键，用 action.performed 事件或 action.ReadValue 轮询。混用两套系统会导致输入丢失。Project Settings → Active Input Handling 必须选择一套。
</Callout>

<Callout type="trap">
**误区：用 GetAxis 做精确的网格移动（如俄罗斯方块）。**
GetAxis 有平滑插值——松开按键后值逐渐回 0，会导致角色「滑行」超出网格。应该用 GetAxisRaw（离散 -1/0/1）或 GetKeyDown/GetKeyUp（按下/松开事件），确保按键与移动精确对应。GetAxis 适合需要惯性的场景（赛车方向盘、摄像机旋转），GetAxisRaw 适合需要精确控制的场景（网格移动、即时转向）。
</Callout>

<Exercises>
**问题 1**：旧输入系统和新输入系统的主要区别是什么？

<Answer>
旧输入系统：内置，用 Input 静态方法轮询，配置在 ProjectSettings 中不可热重载，多设备支持差，已停止更新。新输入系统：需安装 Package，基于 InputAction 和事件驱动，支持多设备统一（键鼠/手柄/触摸/VR）、运行时重绑定（玩家自定义按键）、可视化编辑 InputActionAsset。新输入系统是未来方向，旧系统适合快速原型。
</Answer>

**问题 2**：如何用新输入系统实现一个支持键鼠和手柄的移动方案？

<Answer>
1)创建 InputActionAsset，定义 Move Action；2)为 Move 绑定两套控制方案：键鼠（WASD/方向键 → Vector2 Composite）和手柄（左摇杆 → Stick Binding）；3)代码中：action.performed += ctx => { moveDir = ctx.ReadValue&lt;Vector2&gt;(); }；4)PlayerInput 组件自动检测当前设备并切换控制方案；5)UI 导航用 InputSystemUIInputModule 支持手柄方向键。关键：不硬编码 KeyCode，通过 Action 间接引用，绑定可配置可切换。
</Answer>
</Exercises>
