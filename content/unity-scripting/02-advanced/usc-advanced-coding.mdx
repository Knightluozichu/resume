## 直觉引入

设计模式是前人总结的「最佳实践」。单例像公司的 CEO——全局唯一，所有人都能找到他。对象池像共享单车——用完放回，不造新车。状态机像红绿灯——按规则在红/黄/绿间切换。观察者像订阅公众号——发布者发文章，订阅者自动收到。模式是工具，不是目标——先有问题再选模式。

## 代码对照

```csharp
// 单例模式
public class GameManager : MonoBehaviour {
    public static GameManager Instance { get; private set; }
    void Awake() {
        if (Instance != null) { Destroy(gameObject); return; }
        Instance = this;
        DontDestroyOnLoad(gameObject);
    }
}

// 对象池
public class ObjectPool<T> where T : Component {
    private readonly Queue<T> _pool = new();
    private readonly T _prefab;

    public ObjectPool(T prefab, int initialSize) {
        _prefab = prefab;
        for (int i = 0; i &lt; initialSize; i++) _pool.Enqueue(Create());
    }
    public T Get() { var obj = _pool.Count > 0 ? _pool.Dequeue() : Create(); obj.gameObject.SetActive(true); return obj; }
    public void Release(T obj) { obj.gameObject.SetActive(false); _pool.Enqueue(obj); }
    private T Create() => Object.Instantiate(_prefab);
}

// 状态机
interface IState { void Enter(); void Update(); void Exit(); }
class PatrolState : IState { /* 巡逻逻辑 */ }

// 观察者
public class Health : MonoBehaviour {
    public event Action<int> OnDamaged;
    public void TakeDamage(int dmg) { OnDamaged?.Invoke(dmg); }
}
```

## 常见误区

<Callout type="trap">
**误区：滥用单例模式，把所有管理器都做成单例。**
单例是全局状态——所有依赖它的代码都硬编码引用 Instance，导致紧耦合、难以测试、难以扩展。只把真正的全局唯一管理器（GameManager/AudioManager）做成单例。能用依赖注入（构造函数传参）或事件系统替代的，不要用单例。一个项目中超过 5 个单例就是坏味道。
</Callout>

<Callout type="trap">
**误区：在状态机中用大量的 if-else / switch-case 切换状态。**
`if (state == State.Patrol) { ... } else if (state == State.Chase) { ... }` 是状态机的反模式——状态多时代码膨胀，新增状态需修改所有 switch。正确做法：每个状态是独立类（实现 IState 接口），Enter/Update/Exit 方法。切换时 currentState.Exit()→currentState = newState→currentState.Enter()。新增状态只需新建类，不改其他状态代码（开闭原则）。
</Callout>

<Exercises>
**问题 1**：对象池模式如何实现？有什么优势？

<Answer>
实现：预创建 N 个对象放入 Queue，Get 时出队 SetActive(true)，Release 时 SetActive(false) 入队，不 Destroy。取出时重置状态（位置/速度/血量）。优势：1)避免频繁 Instantiate/Destroy 的 GC 开销和内存碎片；2)避免运行时创建对象的卡顿；3)内存占用稳定可控。适合子弹/粒子/敌人/UI 列表项等高频创建销毁的对象。注意：对象池大小要合理（太小频繁扩容，太大浪费内存），用 OnEnable/OnDisable 管理重置逻辑。
</Answer>

**问题 2**：用状态机设计敌人 AI，包含巡逻/追击/攻击/逃跑四个状态。

<Answer>
1)定义接口 interface IEnemyState &#123; void Enter(Enemy e); void Update(Enemy e); void Exit(Enemy e); &#125;；2)实现四类：PatrolState（巡逻到随机点）、ChaseState（追击玩家）、AttackState（范围内攻击）、FleeState（血量&lt;30%逃跑）；3)转换条件：Patrol→Chase（发现玩家&lt;5m）、Chase→Attack（距离&lt;2m）、Attack→Chase（距离&gt;3m）、Any→Flee（hp&lt;30%）、Flee→Patrol（脱离危险10m）；4)Enemy 持有 currentState，Update 调 currentState.Update(this)。切换时 currentState.Exit()→currentState=newState→currentState.Enter()。优势：每状态逻辑独立，新增状态不改其他，条件清晰。复杂 AI 用层次状态机（HSM）嵌套。
</Answer>
</Exercises>
