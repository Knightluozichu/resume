## 直觉引入

想象一把剑的属性（攻击力 50、耐久度 100、售价 200 金币）。如果 10 把相同的剑各存一份，浪费内存。ScriptableObject 把属性存为一个 .asset 文件——所有引用这把剑的对象共享同一份数据。改一处，全部生效。这就是数据资产化：数据独立于代码，可在 Inspector 编辑，运行时共享。

## 概念讲解

### 数据架构

## 交互Demo

<Stepper>
<Step title="第一步：创建 SO">定义类继承 ScriptableObject，加 [CreateAssetMenu] 特性。字段用 public 或 [SerializeField] 暴露到 Inspector。右键 Project → Create → 菜单名 生成 .asset 文件，在 Inspector 编辑数据。</Step>
<Step title="第二步：使用 SO">
在 MonoBehaviour 中用 [SerializeField] 引用 SO。运行时访问 SO 的字段。多个 MonoBehaviour 引用同一 SO 时共享数据——内存只存一份。改 SO 的值，所有引用者立即生效。
<UscScriptableObjectsDiagram />
</Step>
<Step title="第三步：注意事项">编辑器模式：运行时改 SO 值会持久化（下次运行仍是新值）。构建后：运行时改 SO 值不持久化（重启恢复原始值）。运行时需要修改的数据应复制到普通 C# 对象，不直接改 SO。SO 适合配置数据，不适合每实例不同的运行时状态。</Step>
</Stepper>

## 代码对照

```csharp
// 定义 ScriptableObject
[CreateAssetMenu(menuName = "Items/Weapon")]
public class WeaponData : ScriptableObject {
    public string weaponName;
    public int damage = 10;
    public float attackRange = 2f;
    public Sprite icon;
    public GameObject prefab;
}

// 使用 ScriptableObject
public class Weapon : MonoBehaviour {
    [SerializeField] private WeaponData data; // Inspector 拖拽引用

    public void Attack() {
        Debug.Log($"{data.weaponName} 造成 {data.damage} 伤害");
    }
}

// SO 事件系统（解耦通信）
[CreateAssetMenu(menuName = "Events/GameEvent")]
public class GameEvent : ScriptableObject {
    public UnityEvent<object> onRaised;
    public void Raise(object data = null) => onRaised?.Invoke(data);
}

// 监听者
public class GameEventListener : MonoBehaviour {
    [SerializeField] private GameEvent gameEvent;
    public UnityEvent<object> response;

    void OnEnable() => gameEvent.onRaised.AddListener(OnEventRaised);
    void OnDisable() => gameEvent.onRaised.RemoveListener(OnEventRaised);
    void OnEventRaised(object data) => response?.Invoke(data);
}
```

## 常见误区

<Callout type="trap">
**误区：用 ScriptableObject 存储每实例不同的运行时状态。**
ScriptableObject 是共享数据——多个引用同一 SO 的对象看到的是同一份数据。如果用 SO 存储敌人的当前血量，所有引用该 SO 的敌人血量会同步变化。SO 只适合存配置数据（所有同类敌人共享的「最大血量=100」），不适合存运行时状态（每个敌人独立的「当前血量」）。运行时状态应存在 MonoBehaviour 实例字段中。
</Callout>

<Callout type="trap">
**误区：在构建后的游戏中运行时修改 SO 值，期望下次启动保持修改。**
编辑器模式：运行时改 SO 值会持久化到 .asset 文件（测试时意外修改配置的常见原因）。构建后：SO 在内存中的修改不会写回 .asset 文件，每次启动从原始 .asset 加载。如果需要运行时持久化数据（如存档），应该用 JSON 序列化到 Application.persistentDataPath，不要依赖 SO 的持久化。
</Callout>

<Exercises>
**问题 1**：ScriptableObject 和 MonoBehaviour 有什么区别？

<Answer>
1)ScriptableObject 不挂载到 GameObject，是独立 .asset 资产；MonoBehaviour 挂载到 GameObject 上。2)多个引用同一 SO 的对象共享同一数据（内存一份）；MonoBehaviour 每实例独立数据。3)SO 适合配置数据（武器参数/角色属性/关卡设置），MonoBehaviour 适合运行时行为（移动/战斗/AI）。4)SO 无生命周期方法（无 Update/Awake），但有 OnEnable/OnDisable。5)SO 可用 CreateAssetMenu 在 Project 中创建，MonoBehaviour 通过 AddComponent 挂载。
</Answer>

**问题 2**：如何用 ScriptableObject 设计事件系统实现模块解耦？

<Answer>
1)定义事件 SO：public class GameEvent : ScriptableObject &#123; public UnityEvent onRaised; public void Raise() &#123; onRaised?.Invoke(); }}，加 CreateAssetMenu；2)在 Project 中创建 .asset（如 PlayerDeathEvent）；3)发布者：[SerializeField] GameEvent onPlayerDied; 调用 onPlayerDied.Raise()；4)监听者：[SerializeField] GameEvent onPlayerDied; OnEnable 中 onPlayerDied.onRaised.AddListener(HandleDeath)，OnDisable 中 RemoveListener。优势：发布者和监听者互不知道对方，通过 SO 资产间接通信，完全解耦。场景切换不丢失引用（SO 是资产不在场景中）。
</Answer>
</Exercises>
