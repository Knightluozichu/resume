## 问题：为什么一个能修改对象的 EditorWindow 仍可能破坏场景和 Prefab 数据

先预测：批量重命名 500 个对象后按 Cmd+Z 无法恢复，是 UI 按钮问题还是工具没有进入 Unity 序列化与 Undo 管线？编辑器扩展不是普通运行时代码加一个窗口。它要尊重 Selection、Undo、SerializedObject、Prefab、dirty state 和 AssetDatabase，才能让自动化结果可撤销、可保存、可复查。

## 选择、验证、变更、撤销与持久化

编辑器工具先读取 Selection 或资产输入，预览即将发生的变更，验证命名冲突和目标类型；执行时通过 Undo 记录对象，用 SerializedProperty 改序列化数据，处理 Prefab override 与 dirty 标记，最后保存资产并输出报告。Attribute 描述元数据，Reflection 发现目标，CustomEditor 或 PropertyDrawer 呈现和编辑。运行时代码与 Editor 程序集必须隔离。

## 关键对象与数据流

批量重命名从选中对象产生预览表，验证重复名后按一个 Undo group 修改；属性工具用 Attribute 标记成员，Reflection 或 SerializedProperty 发现并呈现；颜色混合和本地化工具使用同样输入-预览-提交链。每次操作都记录目标 GUID、旧值、新值与结果，重开项目和撤销后验证持久化。

排查时从最早可控输入开始，逐段检查中间状态和最终消费者。最终结果正确但中间链不符合预测，也不能立即签发，因为它可能依赖未记录的缓存、时序或 Editor 状态。

## 编辑器工具是一笔可撤销的数据事务

批量重命名不能只遍历 Selection 后修改 name。工具应先收集稳定目标集，预览旧名与新名，检测同级冲突和非法字符，再用 Undo.RecordObjects 记录事务，执行修改并标记需要保存的对象。用户撤销后，名称、引用和场景脏状态应一起恢复。若操作跨越资产数据库，还要区分场景对象、Prefab 实例与项目资产，不能把它们当成同一种写入。

Attribute 只附加元数据，Reflection 负责读取元数据，SerializedObject 与 SerializedProperty 才与 Unity 的序列化、Prefab override、多对象编辑和 Undo 协作。直接用 FieldInfo.SetValue 修改字段可能在当前 Inspector 看起来成功，却绕过序列化管线。属性暴露实验要比较直接反射写入与 SerializedProperty 写入，重新加载场景并检查数据是否持久化。

## 工具发布前的最小矩阵

- 空选择、单对象、多对象、嵌套 Prefab 和只读资产分别运行一次。
- 冲突时先阻止写入并展示完整预览，不允许改到一半才失败。
- 连续执行、撤销、重做，再关闭重开项目确认结果和脏标记一致。
- 本地化键检查重复、缺失、回退语言、占位符和目标字体，而不只翻译字符串。
- Editor 代码放在 Editor 程序集边界，Player 构建不得引用 UnityEditor 命名空间。

颜色混合工具还要声明颜色空间与 alpha 规则，否则相同数值在 Gamma 和 Linear 项目中可能得到不同观感。现代 UI Toolkit 可以替换 IMGUI 窗口表现，却不改变预览、验证、Undo、序列化和构建隔离这些事务要求。签发证据应包含操作前后快照、Undo 重放、项目重载和 Player 编译结果。

工具面对域重载和脚本重编译时也必须保持可预测。窗口中的临时选择、预览缓存和未提交编辑不能依赖静态字段永久存在；需要恢复的数据应通过序列化窗口状态或可重建查询获得，操作中的资产修改则必须在重载前形成完整事务。验收可以在预览后触发脚本编译、切换布局并重新打开窗口，确认不会自动执行旧操作，也不会丢失已经提交且可撤销的结果。这一边界能区分真正的生产工具与只在一次 Editor 会话中可用的演示脚本。

## 从 2015 年到现代 Unity

现代 Unity 可用 UI Toolkit 构建 EditorWindow，也有新的 Localization package，但原章的批量操作、Attribute/Reflection、属性暴露和本地化问题仍成立。IMGUI 与 UI Toolkit 只是呈现载体；Undo、SerializedObject、AssetDatabase、程序集隔离和可重放变更才是稳定契约。

迁移记录采用五列：原书载体、稳定不变量、现代实现、不可等价处、目标平台证据。允许替换工具和 API，不允许抹去原始问题或倒写历史。

## 验收证据

验收包含 100 个对象批量重命名、冲突预览、一次撤销/重做、Prefab 实例、多对象属性编辑、颜色边界和三语言缺失键报告。关闭重开项目后结果保持，Player 构建依赖图中不出现 UnityEditor。

证据包同时记录场景路径、代码版本、参数、复现步骤、预期和实际结果。交给另一位读者后不需要猜测隐藏状态即可重放，才算掌握而不只是读完。

## 小结

- 编辑器自动化必须先预览验证，再可撤销地提交
- SerializedProperty 是持久化、多对象和 Prefab 语义的重要入口
- Attribute 描述意图，Reflection 发现目标，UI 只是呈现层
- 现代 UI Toolkit 不改变 Undo、资产和程序集边界

<Exercises>

**问题 1** 批量重命名为何要预览冲突？

<Answer>避免产生重复、空名或破坏约定，并让用户在变更前确认完整影响。</Answer>

**问题 2** SerializedProperty 比直接字段赋值多了什么？

<Answer>Undo、多对象编辑、Prefab override 和 Unity 序列化管线集成。</Answer>

**问题 3** 如何防止 Editor 代码进入构建？

<Answer>
  放入 Editor 文件夹或 Editor-only asmdef，并用构建与依赖检查验证。
</Answer>
