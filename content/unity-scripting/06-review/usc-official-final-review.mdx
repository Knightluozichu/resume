## 问题：怎样证明读者掌握的是高级脚本系统而不是十组 API 摘要

先预测：一个 NPC 能巡逻、相机能显示、存档能写入，是否足以签发全书？还要证明事件没有重复、路径失败可诊断、材质没有泄漏、编辑器操作可撤销、干净检出可重建、旧存档可迁移。综合验收把十章放进同一可重放场景，并要求每个症状能沿生产者到消费者链定位。

## 从源码提交到运行结果再回到证据

Git 检出脚本和资源身份，C# 编译产生组件类型，场景实例进入世界，事件与 AI 更新状态，集合和文本提供配置，相机与图形资源生成画面，Profiler 与调试工具记录行为，编辑器工具维护资产，存档把状态带到下一次运行。失败可以沿相反方向回溯：像素到相机、状态到事件、决策到感知、资源到 GUID、存档到 schema。

## 关键对象与数据流

综合样例由版本化文本配置生成 NPC，FSM 驱动 NavMesh 与事件，相机显示程序网格目标，编辑器工具批量生成巡逻点与本地化键，存档保存状态。测试矩阵固定仓库提交、场景、随机种子和输入轨迹，遍历帧率、相机模式、路径失败、事件泄漏、资源缺失和存档损坏，并保存统一日志。

排查时从最早可控输入开始，逐段检查中间状态和最终消费者。最终结果正确但中间链不符合预测，也不能立即签发，因为它可能依赖未记录的缓存、时序或 Editor 状态。

## 用一条故障链验收跨章连接

综合场景从版本化文本读取 NPC 配置，创建组件实例并通过事件进入有限状态机，NavMesh 执行移动，相机显示程序网格目标，编辑器工具维护巡逻点和本地化键，最终把状态写入存档。验收先固定提交、Unity 版本、场景、随机种子、输入轨迹和目标平台，再记录每个阶段的身份与摘要。这样最终像素错误可以倒推到相机、材质、状态、事件、配置或资源 GUID。

第一条故障注入删除一个 .meta：干净检出后引用失效，证明 Git 交付门能发现资源身份问题。第二条让事件重复订阅：NPC 每次感知触发两次转换，监听者计数和状态时间线应定位生命周期错误。第三条让导航目标不可达：感知仍成立但 pathStatus 失败，状态机进入恢复而非静默停住。第四条在写存档中断进程：下次加载使用有效备份且不覆盖损坏样本。

## 全书签发的四层证据

- **目录层**：10/10 原章唯一映射，导读和总复习不计入原章覆盖率。
- **章节层**：每页目标、核心解释、独有交互图、三步实验、陷阱、练习和题库均能独立重放。
- **连接层**：配置、实例、事件、AI、相机、资源和存档之间有明确生产者与消费者。
- **交付层**：干净检出、目标构建、故障注入、恢复和现代迁移矩阵全部通过。

现代迁移采用单变量顺序：先替换 IDE，再替换导航包、渲染接入、编辑器 UI 或资源寻址，每次都重放同一输入并比较中间状态。若一次同时升级多个子系统，即使最终画面相同，也无法证明哪项迁移保持了原书行为。签发报告必须列出未等价处、平台限制和仍需保留的旧项目证据，而不是把“使用新 API”误写成掌握原章。

最后进行一次盲测：由出题者只提供最终症状和固定复现输入，不说明故障所在章节。读者先画出可能的生产者到消费者链，再选择最早可观察信号，每次只改变一个变量并记录被排除的假设。评分不仅看是否修好，还看是否保留失败样本、是否引入静默降级、是否能在干净检出和目标设备上复现。盲测能揭示读者是否真正建立跨章模型，也能检验本站章节之间的导航和术语是否足以支持独立排障。

证据索引按提交、场景、输入、日志、截图、性能捕获和存档样本建立关联，使任一结论都能回到原始运行记录，而不是只剩最终评分。

## 正常、边界与失败样本

每章至少保存一个正常样本、一个极端边界和一个故意破坏配置。正常样本证明主路径，边界样本说明适用范围，失败样本证明诊断方法真的能抓到错误。

<Callout type="trap">
  **因果陷阱**：十个页面分数通过不代表跨章接口正确；综合场景必须验证事件、状态、资源和存档连接处。
</Callout>

<Callout type="trap">
  **版本陷阱**：一次同时替换 IDE、输入、渲染、AI
  和资源系统会失去归因，现代迁移必须逐项进行。
</Callout>

## 从 2015 年到现代 Unity

综合迁移按载体逐项替换：MonoDevelop 到 Rider/Visual Studio，UnityScript 到 C#，旧 NavMesh 到 AI Navigation，Built-in 后处理到 SRP，手工 Bundle 到 Addressables。每次先跑旧问题基线，再改变一个载体，复查行为、性能和失败边界；不等价项保持双轨说明。

迁移记录采用五列：原书载体、稳定不变量、现代实现、不可等价处、目标平台证据。允许替换工具和 API，不允许抹去原始问题或倒写历史。

## 验收证据

签发包包含英文与中文身份、10 单元覆盖表、12 页导航、72 道题、专属交互图、干净检出、目标场景、事件与 AI 时间线、相机和资源截图、编辑器 Undo、存档恢复及现代迁移矩阵。任一原章缺失或页面低于 90 都保持未完成。

证据包同时记录场景路径、代码版本、参数、复现步骤、预期和实际结果。交给另一位读者后不需要猜测隐藏状态即可重放，才算掌握而不只是读完。

## 小结

- 十章共同覆盖语言、观测、世界、事件、表现、数据、决策、工具、资源与交付
- 综合样例必须能从症状反向定位到明确生产者
- 干净检出、确定输入与失败重放让结论可由他人验证
- 现代替换一次只改变一个载体，并保留不等价边界

</Answer>
