## 直觉引入

想象你在写一份菜谱。ShaderLab就是Unity Shader的「菜谱格式」——它不是写GPU代码的语言，而是描述Shader结构的框架。Properties是「食材清单」（声明可调参数），SubShader是「做法步骤」（实际渲染逻辑），Pass是「每一步操作」（一次渲染通道）。

真正在GPU上运行的代码（Cg/HLSL）写在Pass内部的CGPROGRAM块中。ShaderLab像是包裹GPU代码的「信封」，提供参数声明、多平台回退、渲染状态控制等管理功能。

## 代码对照

```hlsl
Shader "Custom/MyShader" {
    // 1. Properties: 可调参数
    Properties {
        _Color ("Main Color", Color) = (1,1,1,1)
        _MainTex ("Texture", 2D) = "white" {}
        _Gloss ("Gloss", Range(0,1)) = 0.5
    }
    // 2. SubShader: 实现版本
    SubShader {
        Tags { "Queue"="Geometry" "RenderType"="Opaque" }
        LOD 100
        // 3. Pass: 渲染通道
        Pass {
            Tags { "LightMode"="ForwardBase" }
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            // GPU代码...
            ENDCG
        }
    }
    // 4. Fallback: 备选
    FallBack "Diffuse"
}
```

## 常见误区

<Callout type="trap">
**误区：认为ShaderLab就是Shader代码。**
每个Pass都是一次完整的渲染提交，多Pass=多Draw Call。能用单Pass完成的尽量单Pass（如用Blend组合而非多Pass叠加）。
</Callout>

<Callout type="trap">
**误区：滥用多Pass。**
每个Pass都是一次完整的渲染通道——GPU需要重新执行整个管线。多Pass渲染开销与Pass数成正比。能用单Pass完成的效果（如用混合模式组合）就不要用多Pass。必要时可用GrabPass（屏幕抓取）等特殊Pass，但要注意性能。
</Callout>

<Exercises>
**问题 1**：ShaderLab的基本结构是什么？各部分的职责是什么？

<Answer>
Tags控制Shader/SubShader/Pass的渲染行为。常见Tag：1)Queue控制渲染顺序（Background/Geometry/Transparent/Overlay）；2)RenderType用于相机替换渲染（Opaque/Transparent）；3)LightMode指定Pass在哪个光照阶段执行（ForwardBase/ForwardAdd/ShadowCaster）；4)IgnoreProjector是否忽略投影器。Tags决定「什么时候渲染」「怎么渲染」。
</Answer>

**问题 2**：Tags的作用是什么？常见的Tag有哪些？

<Answer>
Tags是键值对，控制渲染行为。常见：Queue控制渲染顺序(Geometry=2000, Transparent=3000, Overlay=4000)；RenderType用于相机ReplacementShader(如渲染深度纹理时区分Opaque/Transparent)；LightMode指定Pass何时执行(ForwardBase=主光, ForwardAdd=附加光, ShadowCaster=生成阴影)；IgnoreProjector忽略投影。Tags决定Shader的渲染时机和方式。
</Answer>
</Exercises>
