## 直觉引入

想象一个工厂的两道工序。第一道（顶点着色器）接收原材料（顶点数据），加工后传递给第二道。第二道（片元着色器）接收半成品（插值后的数据），产出成品（像素颜色）。两道工序之间需要「传送带」传递中间数据——这就是v2f结构体。

写顶点/片元Shader就是定义这个「传送带」上有什么数据，以及每道工序怎么处理这些数据。

## 代码对照

```hlsl
// 完整顶点/片元着色器
struct appdata {
    float4 vertex : POSITION;    // 顶点位置
    float2 uv : TEXCOORD0;       // 纹理坐标
    float3 normal : NORMAL;       // 法线
};

struct v2f {
    float4 pos : SV_POSITION;    // 裁剪空间位置(必须)
    float2 uv : TEXCOORD0;       // 插值UV
    float3 worldNormal : TEXCOORD1; // 世界空间法线
};

v2f vert(appdata v) {
    v2f o;
    o.pos = UnityObjectToClipPos(v.vertex);
    o.uv = v.uv;
    o.worldNormal = UnityObjectToWorldNormal(v.normal);
    return o;
}

fixed4 frag(v2f i) : SV_Target {
    fixed4 col = tex2D(_MainTex, i.uv);
    float3 N = normalize(i.worldNormal);
    float3 L = normalize(_WorldSpaceLightPos0.xyz);
    float diff = max(0, dot(N, L));
    col.rgb *= diff * _LightColor0.rgb;
    return col;
}
```

## 常见误区

<Callout type="trap">
**误区：忘记SV_POSITION语义。**
法线经光栅化插值后长度会变化，需在片元着色器中重新normalize。否则光照计算结果不正确。
</Callout>

<Callout type="trap">
**误区：在片元着色器中使用未归一化的法线。**
法线从顶点传递到片元经过插值，插值后向量长度改变（不再是单位向量）。在片元着色器中用法线做光照计算(dot(N,L))前必须normalize(N)。忘记normalize会导致光照不均匀——某些区域偏亮或偏暗。
</Callout>

<Exercises>
**问题 1**：appdata和v2f结构体分别是什么？它们如何传递数据？

<Answer>
语义绑定是用POSITION/TEXCOORD0/NORMAL/SV_POSITION等标记告诉GPU每个变量的用途。需要它是因为：1)GPU需要知道哪些变量是顶点位置(SV_POSITION用于光栅化)；2)从顶点缓冲到appdata的映射(POSITION对应顶点位置属性)；3)从顶点到片元的插值标记(TEXCOORD0/TEXCOORD1标识可插值变量)。没有语义，GPU不知道如何路由数据。
</Answer>

**问题 2**：语义绑定(Semantic)是什么？为什么需要它？

<Answer>
语义绑定用POSITION/TEXCOORD0/NORMAL/SV_POSITION等标记变量用途。需要因为：1)GPU需知道哪个变量是裁剪空间位置(SV_POSITION用于光栅化)；2)顶点缓冲到appdata的映射(POSITION对应mesh顶点)；3)标记可插值变量(TEXCOORD0等)。SV_POSITION是强制语义，没有它GPU无法光栅化。TEXCOORD0/1/2...是通用插值语义，可传任意插值数据。
</Answer>
</Exercises>
