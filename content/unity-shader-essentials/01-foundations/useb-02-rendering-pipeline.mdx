### 核心对象

1. **渲染流水线**：把场景数据依次转换为屏幕片元并写入帧缓冲的一组逻辑与硬件阶段。
2. **Draw Call**：CPU提交一次绘制状态、资源和图元范围给图形API的命令。
3. **顶点着色器**：对单个顶点执行坐标变换并输出后续阶段插值属性的可编程阶段。
4. **光栅化**：把裁剪后的图元覆盖关系离散为片元并插值顶点属性的过程。
5. **逐片元操作**：在写颜色前执行深度、模板、混合等测试和更新的阶段。

## 数据流与公式

任何Shader效果都先写清五项契约：输入属性来自哪里，当前值位于哪个坐标或色彩空间，可编程阶段输出什么，ShaderLab状态如何合并结果，以及目标平台和Unity版本是什么。

$$
p_{clip}=M_{VP}M_Mp_{object}
$$

$$
p_{ndc}=p_{clip}/w_{clip}
$$

$$
C_{dst}'=F_sC_s+F_dC_d
$$

$$
T_{submit}=N_{draw}\,t_{draw}
$$

应用阶段准备网格、材质与状态并提交Draw Call；GPU几何阶段把顶点变换到裁剪空间，裁剪和屏幕映射后建立三角形；光栅化生成片元，片元着色器计算候选颜色，逐片元阶段决定它能否写入目标。把逻辑流水线与具体API实现分开，才能解释固定管线、HLSL、GLSL和Cg的关系。 公式不是孤立记忆项；每个向量都标注空间，每个颜色都标注线性或sRGB，每个深度都标注设备、NDC或观察距离，每个纹理通道都标注数据语义。

## 最小Shader实现

```hlsl
v2f vert(appdata v) {
    v2f o;
    o.pos = UnityObjectToClipPos(v.vertex);
    o.uv = v.uv;
    return o;
}
```

实现顺序固定为常量颜色、输入可视化、核心公式、材质参数和优化。每新增一个步骤都保留开关，这样画面异常时可以二分定位。编译成功只证明语法和部分类型成立，不证明空间、状态或色彩处理正确。

## Unity侧设置与渲染状态

```csharp
var material = renderer.sharedMaterial;
material.SetFloat("_DebugMode", debugMode);
material.EnableKeyword(debugMode > 0 ? "DEBUG_VIEW" : "BASELINE_VIEW");
Debug.Assert(material.shader.isSupported);
```

材质、相机和光源属于实验输入，不能只保存Shader文件。用Frame Debugger检查实际选择的SubShader和Pass、关键字变体、渲染队列、RenderTarget、深度写入和混合；用Profiler或GPU捕获确认成本来自提交、顶点、片元还是带宽。

## 边界与平台差异

测试零向量、负缩放、非统一缩放、UV边界、透明物体交叉、近远裁剪面、HDR亮度、不同纹理导入设置和移动精度。原书以Unity 5时代内置管线为语境；迁移到当前Unity、URP或HDRP时，应把概念映射和API替换单独记录，不能把新管线行为倒写成原书内容。

```text
scene: fixed reference scene
unity: exact editor version
pipeline: built-in or named SRP
platform: graphics API and GPU
evidence: image diff + frame events + timings
```

## 验收证书

验收包至少包含Shader与脚本、材质参数、测试场景、参考图和候选图、Frame Debugger事件、编译关键字、目标平台、帧时间与反例。把片元着色器输出当最终屏幕颜色，忽略深度、模板、混合和颜色空间转换。 修复后必须重放同一输入，确认画面和性能变化都能由证据解释。

## 常见误区

<Callout type="trap" title="只看最终截图">把片元着色器输出当最终屏幕颜色，忽略深度、模板、混合和颜色空间转换。</Callout>

<Callout type="trap" title="忽略版本与状态">同一段HLSL在不同Unity版本、渲染管线、关键字和纹理导入设置下可能走不同Pass或解释不同数据。修复时把版本、平台、状态和资源设置纳入实验输入。</Callout>

## 本章回顾

本页覆盖渲染流水线、Draw Call、顶点着色器、光栅化、逐片元操作。掌握标准是能从视觉目标画出数据流，写出最小实现，逐阶段可视化中间值，再用渲染状态、边界样例和性能数据完成复现。
