### 核心对象

1. **后处理**：在场景渲染完成后以屏幕纹理为输入执行的全屏图像处理。
2. **卷积核**：按邻域固定权重组合像素以提取或平滑特征的小矩阵。
3. **高斯模糊**：用高斯权重低通滤波，并可拆成水平和垂直两次卷积。
4. **Bloom**：提取高亮、模糊后加回原图以模拟亮区扩散的效果。
5. **运动模糊**：按历史颜色、速度或深度重建位移方向累积样本的效果。

## 数据流与公式

任何Shader效果都先写清五项契约：输入属性来自哪里，当前值位于哪个坐标或色彩空间，可编程阶段输出什么，ShaderLab状态如何合并结果，以及目标平台和Unity版本是什么。

$$
I'(x,y)=\sum_{i,j}K_{ij}I(x+i,y+j)
$$

$$
G(x)=\frac{1}{\sqrt{2\pi}\sigma}e^{-x^2/(2\sigma^2)}
$$

$$
Bloom=Scene+Blur(max(Scene-threshold,0))
$$

$$
C_t=(1-\alpha)C_t+\alpha C_{t-1}
$$

全屏Pass先明确输入纹理、像素尺寸和颜色空间。卷积边缘算子对邻域梯度敏感，高斯核可分离以把二维采样成本降为两个一维Pass。Bloom必须在合适动态范围中提取高亮，简单历史混合的运动模糊会产生拖影，不能与速度缓冲方案混淆。 公式不是孤立记忆项；每个向量都标注空间，每个颜色都标注线性或sRGB，每个深度都标注设备、NDC或观察距离，每个纹理通道都标注数据语义。

## 最小Shader实现

```hlsl
float3 bright = max(tex2D(_MainTex, i.uv).rgb - _Threshold, 0.0);
float3 blurred = SampleGaussian(i.uv, _MainTex_TexelSize.xy);
return float4(bright + blurred, 1.0);
```

实现顺序固定为常量颜色、输入可视化、核心公式、材质参数和优化。每新增一个步骤都保留开关，这样画面异常时可以二分定位。编译成功只证明语法和部分类型成立，不证明空间、状态或色彩处理正确。

## Unity侧设置与渲染状态

```csharp
var material = renderer.sharedMaterial;
material.SetFloat("_DebugMode", debugMode);
material.EnableKeyword(debugMode > 0 ? "DEBUG_VIEW" : "BASELINE_VIEW");
Debug.Assert(material.shader.isSupported);
```

材质、相机和光源属于实验输入，不能只保存Shader文件。用Frame Debugger检查实际选择的SubShader和Pass、关键字变体、渲染队列、RenderTarget、深度写入和混合；用Profiler或GPU捕获确认成本来自提交、顶点、片元还是带宽。

## 边界与平台差异

测试零向量、负缩放、非统一缩放、UV边界、透明物体交叉、近远裁剪面、HDR亮度、不同纹理导入设置和移动精度。原书以Unity 5时代内置管线为语境；迁移到当前Unity、URP或HDRP时，应把概念映射和API替换单独记录，不能把新管线行为倒写成原书内容。

```text
scene: fixed reference scene
unity: exact editor version
pipeline: built-in or named SRP
platform: graphics API and GPU
evidence: image diff + frame events + timings
```

## 验收证书

验收包至少包含Shader与脚本、材质参数、测试场景、参考图和候选图、Frame Debugger事件、编译关键字、目标平台、帧时间与反例。在LDR且伽马空间直接提取高亮，阈值与能量关系失真并导致Bloom脏灰。 修复后必须重放同一输入，确认画面和性能变化都能由证据解释。

## 常见误区

<Callout type="trap" title="只看最终截图">在LDR且伽马空间直接提取高亮，阈值与能量关系失真并导致Bloom脏灰。</Callout>

<Callout type="trap" title="忽略版本与状态">同一段HLSL在不同Unity版本、渲染管线、关键字和纹理导入设置下可能走不同Pass或解释不同数据。修复时把版本、平台、状态和资源设置纳入实验输入。</Callout>
