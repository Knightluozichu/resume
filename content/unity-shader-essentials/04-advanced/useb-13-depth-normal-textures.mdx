### 核心对象

1. **深度纹理**：保存相机可见表面深度或硬件深度编码的屏幕纹理。
2. **深度法线纹理**：在屏幕空间联合编码观察空间法线和深度的纹理。
3. **线性深度**：与观察距离成线性关系、便于物理距离计算的深度值。
4. **世界坐标重建**：由屏幕坐标、深度和逆视投影矩阵恢复片元世界位置。
5. **深度边缘**：相邻像素深度或法线差异超过阈值时识别出的几何轮廓。

## 数据流与公式

任何Shader效果都先写清五项契约：输入属性来自哪里，当前值位于哪个坐标或色彩空间，可编程阶段输出什么，ShaderLab状态如何合并结果，以及目标平台和Unity版本是什么。

$$
p_{clip}=(2uv-1,z,1)
$$

$$
p_w=M_{VP}^{-1}p_{clip}
$$

$$
p_w=p_w/p_w.w
$$

$$
edge=step(\tau_d,|d_i-d_j|)+step(\tau_n,1-n_i\cdot n_j)
$$

硬件深度通常非线性且平台方向可能不同，必须用Unity宏或投影参数解码。世界位置重建从NDC坐标和深度形成裁剪位置，再乘逆视投影矩阵并做齐次除法。深度法线边缘比纯颜色边缘更贴近几何，但阈值随距离和分辨率变化。 公式不是孤立记忆项；每个向量都标注空间，每个颜色都标注线性或sRGB，每个深度都标注设备、NDC或观察距离，每个纹理通道都标注数据语义。

## 最小Shader实现

```hlsl
float rawDepth = SAMPLE_DEPTH_TEXTURE(_CameraDepthTexture, i.uv);
float linearDepth = LinearEyeDepth(rawDepth);
float4 world = mul(_InverseVP, float4(i.ndc, rawDepth, 1));
world.xyz /= world.w;
```

实现顺序固定为常量颜色、输入可视化、核心公式、材质参数和优化。每新增一个步骤都保留开关，这样画面异常时可以二分定位。编译成功只证明语法和部分类型成立，不证明空间、状态或色彩处理正确。

## Unity侧设置与渲染状态

```csharp
var material = renderer.sharedMaterial;
material.SetFloat("_DebugMode", debugMode);
material.EnableKeyword(debugMode > 0 ? "DEBUG_VIEW" : "BASELINE_VIEW");
Debug.Assert(material.shader.isSupported);
```

材质、相机和光源属于实验输入，不能只保存Shader文件。用Frame Debugger检查实际选择的SubShader和Pass、关键字变体、渲染队列、RenderTarget、深度写入和混合；用Profiler或GPU捕获确认成本来自提交、顶点、片元还是带宽。

## 边界与平台差异

测试零向量、负缩放、非统一缩放、UV边界、透明物体交叉、近远裁剪面、HDR亮度、不同纹理导入设置和移动精度。原书以Unity 5时代内置管线为语境；迁移到当前Unity、URP或HDRP时，应把概念映射和API替换单独记录，不能把新管线行为倒写成原书内容。

```text
scene: fixed reference scene
unity: exact editor version
pipeline: built-in or named SRP
platform: graphics API and GPU
evidence: image diff + frame events + timings
```

1. 建立只有一个网格、一个相机和一个主光的参考场景，保存Unity版本与平台。
2. 输出UV、法线、深度或光照项等中间值，确认数据空间和范围。
3. 启用本章核心效果，用Frame Debugger逐Pass检查输入、状态和目标。
4. 构造边界与失败场景，比较参考图、像素差异、Draw Call和GPU时间。

## 验收证书

验收包至少包含Shader与脚本、材质参数、测试场景、参考图和候选图、Frame Debugger事件、编译关键字、目标平台、帧时间与反例。把设备深度直接当世界距离，近处和远处雾密度及运动向量都严重失真。 修复后必须重放同一输入，确认画面和性能变化都能由证据解释。
