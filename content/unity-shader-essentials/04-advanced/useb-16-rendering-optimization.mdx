## 从效果开始

先预测画面、Draw Call和中间缓冲会如何变化，再调整一个参数观察变化。优化先测量：CPU Render Thread高说明提交或状态切换问题，GPU阶段再区分顶点、片元和带宽。批处理要求材质与状态兼容，透明和大量覆盖会放大片元成本；纹理压缩、分辨率和mipmap影响带宽。Shader LOD和变体应按目标硬件设预算，而不是盲目降低精度。 本页用<Term def="限制帧时间的CPU提交、顶点、片元、带宽或同步阶段。">性能瓶颈</Term>、<Term def="合并兼容对象的绘制提交以减少CPU Draw Call开销。">批处理</Term>、<Term def="同一屏幕像素被多个片元重复着色但大部分结果最终被覆盖。">过度绘制</Term>、<Term def="按屏幕贡献或硬件能力切换几何、Shader或分辨率复杂度。">LOD</Term>、<Term def="逐Draw Call检查渲染顺序、状态、目标和结果的Unity工具。">帧调试器</Term>串联视觉目标、GPU数据流、渲染状态和验收证据。

### 核心对象

1. **性能瓶颈**：限制帧时间的CPU提交、顶点、片元、带宽或同步阶段。
2. **批处理**：合并兼容对象的绘制提交以减少CPU Draw Call开销。
3. **过度绘制**：同一屏幕像素被多个片元重复着色但大部分结果最终被覆盖。
4. **LOD**：按屏幕贡献或硬件能力切换几何、Shader或分辨率复杂度。
5. **帧调试器**：逐Draw Call检查渲染顺序、状态、目标和结果的Unity工具。

## 数据流与公式

任何Shader效果都先写清五项契约：输入属性来自哪里，当前值位于哪个坐标或色彩空间，可编程阶段输出什么，ShaderLab状态如何合并结果，以及目标平台和Unity版本是什么。

$$
T_{frame}=\max(T_{cpu},T_{gpu})
$$

$$
T_{gpu}=T_v+T_f+T_b
$$

$$
overdraw=\frac{shaded\ fragments}{screen\ pixels}
$$

$$
FPS=1000/T_{frame}
$$

优化先测量：CPU Render Thread高说明提交或状态切换问题，GPU阶段再区分顶点、片元和带宽。批处理要求材质与状态兼容，透明和大量覆盖会放大片元成本；纹理压缩、分辨率和mipmap影响带宽。Shader LOD和变体应按目标硬件设预算，而不是盲目降低精度。 公式不是孤立记忆项；每个向量都标注空间，每个颜色都标注线性或sRGB，每个深度都标注设备、NDC或观察距离，每个纹理通道都标注数据语义。

## 最小Shader实现

```hlsl
// 先用Profiler与Frame Debugger定位瓶颈
#pragma multi_compile __ QUALITY_LOW QUALITY_HIGH
#if defined(QUALITY_LOW)
  #define SAMPLE_COUNT 4
#else
  #define SAMPLE_COUNT 12
#endif
```

实现顺序固定为常量颜色、输入可视化、核心公式、材质参数和优化。每新增一个步骤都保留开关，这样画面异常时可以二分定位。编译成功只证明语法和部分类型成立，不证明空间、状态或色彩处理正确。

## Unity侧设置与渲染状态

```csharp
var material = renderer.sharedMaterial;
material.SetFloat("_DebugMode", debugMode);
material.EnableKeyword(debugMode > 0 ? "DEBUG_VIEW" : "BASELINE_VIEW");
Debug.Assert(material.shader.isSupported);
```

材质、相机和光源属于实验输入，不能只保存Shader文件。用Frame Debugger检查实际选择的SubShader和Pass、关键字变体、渲染队列、RenderTarget、深度写入和混合；用Profiler或GPU捕获确认成本来自提交、顶点、片元还是带宽。

## 边界与平台差异

测试零向量、负缩放、非统一缩放、UV边界、透明物体交叉、近远裁剪面、HDR亮度、不同纹理导入设置和移动精度。原书以Unity 5时代内置管线为语境；迁移到当前Unity、URP或HDRP时，应把概念映射和API替换单独记录，不能把新管线行为倒写成原书内容。

```text
scene: fixed reference scene
unity: exact editor version
pipeline: built-in or named SRP
platform: graphics API and GPU
evidence: image diff + frame events + timings
```

## 验收证书

验收包至少包含Shader与脚本、材质参数、测试场景、参考图和候选图、Frame Debugger事件、编译关键字、目标平台、帧时间与反例。看到Draw Call多就强制批处理，却增加顶点变换、材质限制和不可见几何，帧时间反而上升。 修复后必须重放同一输入，确认画面和性能变化都能由证据解释。
