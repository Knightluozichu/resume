### 五个核心对象

1. **ShaderLab**：Unity用来组织属性、SubShader、Pass和回退策略的声明框架。
2. **SubShader**：面向一组硬件能力和渲染条件的完整实现候选。
3. **Pass**：一次具体绘制及其程序、标签和固定状态。
4. **Fallback**：当前实现不可用时指定的回退Shader。
5. **Properties**：暴露给材质面板和脚本的持久化参数接口。

## 数据流与公式

按Shader、Properties、SubShader、Pass和Fallback的层次阅读文件，解释Unity如何选择实现并把属性映射为uniform。固定管线、可编程Shader和Surface Shader是书中历史环境的三种形态，不能与现代URP/HDRP混为一谈。 先画出应用脚本、材质属性、SubShader选择、Pass执行、顶点阶段、光栅化、片元阶段和固定状态的生产者到消费者链，再把本章对象放到对应位置。

$$
Shader=Properties+SubShaders+Fallback
$$

$$
SubShader=Tags+LOD+Passes
$$

$$
Pass=program+state+LightMode
$$

$$
propertyightarrow materialightarrow uniform
$$

公式中的位置、方向、深度、颜色和时间必须标注空间、范围与单位。片元函数输出只是候选颜色，最终结果仍经过裁剪、深度、模板、混合、目标格式与颜色编码。

## 最小实现

```shaderlab
Shader "Book/Structure" { Properties { _Color("Color",Color)=(1,1,1,1) } SubShader { Tags { "RenderType"="Opaque" } Pass {} } Fallback "Diffuse" }
```

实现顺序固定为常量输出、输入可视化、核心公式、应用侧绑定和固定状态。先确认材质没有变粉、实际SubShader和Pass正确，再判断画面差异是否来自程序计算。

## 脚本与材质契约

```csharp
var material = renderer.sharedMaterial;
material.SetFloat("_DebugMode", debugMode);
material.SetTexture("_MainTex", sourceTexture);
Debug.Assert(material.shader.isSupported);
```

脚本侧保存Unity版本、渲染路径、相机、灯光、网格布局、材质关键字、纹理导入设置和RenderTexture格式。Shader侧列出Properties、uniform、Tags、LightMode与固定状态，二者缺一都不能复现实验。
