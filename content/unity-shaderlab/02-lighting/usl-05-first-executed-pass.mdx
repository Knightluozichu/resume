本页一一对应郭浩瑜《Unity 3D ShaderLab开发实战详解》第一版第5章 第一个被执行的Pass。书目记录确认人民邮电出版社2014年出版、ISBN 9787115338907；完整目录确认全书5篇33章。本书基于当时Unity内置渲染管线，涉及固定管线、Cg、VertexLit和Surface Shader时保留历史语境，现代Unity项目需另做版本映射。

### 五个核心对象

1. **渲染路径**：Unity按相机与平台选择的一组照明和Pass执行策略。
2. **LightMode**：声明Pass在某条渲染路径中扮演角色的标签。
3. **首个Pass**：在当前SubShader和路径下满足条件并实际被调度的绘制。
4. **Frame Debugger**：逐Draw查看Pass、目标和状态的帧级调试工具。
5. **Pass证书**：记录材质、SubShader、Pass名、LightMode与Draw顺序的证据。

公式中的位置、方向、深度、颜色和时间必须标注空间、范围与单位。片元函数输出只是候选颜色，最终结果仍经过裁剪、深度、模板、混合、目标格式与颜色编码。

## 最小实现

```shaderlab
Pass { Name "BASE" Tags { "LightMode"="ForwardBase" } Color (1,0,0,1) }
```

实现顺序固定为常量输出、输入可视化、核心公式、应用侧绑定和固定状态。先确认材质没有变粉、实际SubShader和Pass正确，再判断画面差异是否来自程序计算。

## 脚本与材质契约

```csharp
var material = renderer.sharedMaterial;
material.SetFloat("_DebugMode", debugMode);
material.SetTexture("_MainTex", sourceTexture);
Debug.Assert(material.shader.isSupported);
```

脚本侧保存Unity版本、渲染路径、相机、灯光、网格布局、材质关键字、纹理导入设置和RenderTexture格式。Shader侧列出Properties、uniform、Tags、LightMode与固定状态，二者缺一都不能复现实验。

## 验收证书

证书包含源码版本、Unity与图形API、脚本绑定、资源哈希、关键字、Pass状态、参考图、GPU事件、CPU/GPU帧时间与失败反例。看到文件中的第一个Pass就认定它最先执行，没有检查渲染路径、标签和替换渲染。 修复后必须用同一输入重放，并指出变化发生在哪个阶段。

## 常见误区

<Callout type="trap" title="把语法当成执行链">看到文件中的第一个Pass就认定它最先执行，没有检查渲染路径、标签和替换渲染。</Callout>

<Callout type="trap" title="只看最终画面">画面相似不证明实际SubShader、Pass、空间、深度、混合和性能等价。必须保存中间视图、固定状态和帧捕获。</Callout>
