## 直觉引入

想象你在做一个游戏。玩家看到的不是代码，而是界面——血条、背包、设置菜单。这些界面怎么做？Unity 提供了两套系统：UGUI（基于 GameObject，像搭积木）和 UI Toolkit（基于 Web 技术，像写网页）。

全书从认识 UI 系统出发，经过 UGUI 核心组件、布局与交互，到动画、UI Toolkit、响应式设计，最终落到性能优化。呈「认知→基础→进阶→优化」的递进结构。

## 常见误区

<Callout type="trap">
**误区：认为 UGUI 已经过时，应该直接学 UI Toolkit。**
UGUI 仍然是 Unity 游戏 UI 的主流方案，尤其在运行时 HUD、粒子特效、3D UI 场景中优势明显。UI Toolkit 目前主要面向编辑器扩展和复杂面板。两者并存互补，不存在谁替代谁。新手应先掌握 UGUI 再学 UI Toolkit。
</Callout>

<Callout type="trap">
**误区：觉得 UI 开发不需要学性能优化。**
UI 是游戏中 Draw Call 的大户——一个未优化的背包界面可能产生上百个 Draw Call，直接拖垮帧率。图集合并、合批打断点控制、Overdraw 削减是 UI 性能的三大杠杆，不学优化就无法支撑中大型项目。
</Callout>

<Exercises>
**问题 1**：全书四大板块是什么？它们之间是什么关系？

<Answer>
UI系统认知、UGUI核心、进阶技术、优化与总结。呈递进关系：系统认知是概念基础，UGUI核心是日常开发主力，进阶技术扩展能力边界，优化总结保障项目落地。每一层都建立在前一层之上。
</Answer>

**问题 2**：为什么 Unity 同时维护 UGUI 和 UI Toolkit 两套 UI 系统？

<Answer>
因为两者解决不同场景的问题。UGUI 基于 GameObject，适合运行时游戏 UI——需要实时更新、粒子特效、3D 空间 UI，与游戏对象系统深度集成。UI Toolkit 基于 Web 技术栈，适合编辑器工具和复杂数据面板——需要灵活布局、样式复用、快速迭代。Unity 同时维护两套系统是为了覆盖不同需求，而非技术债。
</Answer>
</Exercises>
