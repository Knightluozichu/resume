## 直觉引入

想象一个餐厅。顾客点单（输入层），服务员传递订单（事件层），厨房做菜上桌（渲染层）。Unity UI 也是三层结构：InputModule 采集玩家输入，EventSystem 路由事件到目标元素，Canvas 把元素画到屏幕上。理解这三层的职责分工，是设计任何 UI 系统的基础。

## 概念讲解

### 三层架构

<UidUiSystemDiagram />

<Term def="Canvas是UGUI的渲染根节点，负责将所有子级UI元素绘制到屏幕上，有三种渲染模式">Canvas</Term>是渲染的起点。

<Term def="EventSystem是Unity UI的事件中枢，管理输入模块、射线检测和事件派发，每个场景只需一个">EventSystem</Term>是事件的调度器。

<Term def="InputModule是EventSystem的输入采集组件，将物理输入(键鼠/触摸/手柄)转化为UI事件">InputModule</Term>是输入的翻译器。

<Term def="GraphicRaycaster是Canvas上的射线检测组件，对Canvas下所有RaycastTarget元素做命中测试">GraphicRaycaster</Term>负责找到玩家点击了哪个 UI 元素。

## 交互Demo

<Stepper>
<Step title="第一步：Canvas 渲染层">Canvas 是所有 UI 元素的根节点。ScreenSpace-Overlay 模式下 UI 直接画在屏幕上，不需要相机；ScreenSpace-Camera 模式下 UI 可以有透视和后处理；WorldSpace 模式下 UI 作为 3D 物体存在于场景中。</Step>
<Step title="第二步：EventSystem 事件层">
EventSystem 每帧调用 InputModule 采集输入，然后通过 GraphicRaycaster 做射线检测找到目标元素，最后用 ExecuteEvents 将事件派发给目标元素上所有实现了对应接口（如 IPointerClickHandler）的组件。
<UidUiSystemDiagram />
</Step>
<Step title="第三步：InputModule 输入层">InputModule 将物理输入转化为 UI 事件。StandaloneInputModule 处理键鼠，TouchInputModule 处理触摸。新输入系统下用 InputSystemUIInputModule 可以统一处理所有设备。</Step>
</Stepper>

## 代码对照

```csharp
// Canvas 渲染模式
canvas.renderMode = RenderMode.ScreenSpaceOverlay;  // 屏幕覆盖
// canvas.renderMode = RenderMode.ScreenSpaceCamera;  // 屏幕相机
// canvas.renderMode = RenderMode.WorldSpace;          // 世界空间

// EventSystem 事件接口实现
public class MyButton : MonoBehaviour, IPointerClickHandler {
    public void OnPointerClick(PointerEventData eventData) {
        Debug.Log("被点击了！");
    }
}

// 关闭不需要的射线检测
image.raycastTarget = false; // 纯装饰元素关闭，提升性能
```

## 常见误区

<Callout type="trap">
**误区：每个 Canvas 都需要单独挂一个 EventSystem。**
EventSystem 是场景级的单例，整个场景只需要一个。它管理所有 Canvas 的输入事件。如果场景中有多个 EventSystem，Unity 会报警告，且只有一个生效。新建 Canvas 时 Unity 会自动添加 EventSystem，需手动删除重复的。
</Callout>

<Callout type="trap">
**误区：认为所有 Image 和 Text 都需要开启 RaycastTarget。**
RaycastTarget 默认开启，但大多数纯展示性元素（背景图、标签文字）不需要接收点击。每帧的射线检测会遍历所有 RaycastTarget=true 的元素，UI 元素多时开销显著。应养成习惯：创建纯展示元素后立即关闭 RaycastTarget。
</Callout>

<Exercises>
**问题 1**：Canvas 的三种 Render Mode 分别用于什么场景？

<Answer>
ScreenSpace-Overlay：UI 画在屏幕最上层，不受相机影响，适合 HUD（血条、计分）。ScreenSpace-Camera：UI 画在指定相机视野内，可以有透视效果和后处理，适合需要特效的主菜单。WorldSpace：UI 作为 3D 物体存在于场景中，会被其他物体遮挡，适合游戏内告示牌、NPC 对话框。
</Answer>

**问题 2**：EventSystem 的事件路由流程是怎样的？

<Answer>
1)InputModule 每帧采集输入（鼠标位置/点击）；2)GraphicRaycaster 从 Canvas 顶层向下做射线检测，找到第一个 RaycastTarget=true 的命中元素；3)ExecuteEvents 将事件（如 PointerClick）派发给命中元素上所有实现了对应接口（IPointerClickHandler）的组件；4)事件可以冒泡——如果目标元素没有处理，EventSystem 会向上查找父级是否实现了对应接口。
</Answer>
</Exercises>
