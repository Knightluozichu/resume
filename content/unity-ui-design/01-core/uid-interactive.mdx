## 直觉引入

想象一个物理按钮。没碰它是正常色，手指靠近变高亮色，按下去变按下色，不可用时变灰色。Unity 的 Selectable 基类模拟了这个过程——四种状态、三种过渡方式（颜色/精灵/动画）。所有交互组件（Button/Toggle/Slider）都继承自 Selectable，再加上各自的事件接口。

<Step title="第二步：事件接口">
所有交互通过事件接口实现，而非 Update 轮询。IPointerClickHandler 处理点击（Button/Toggle），IDragHandler 处理拖拽（Slider/ScrollRect），IScrollHandler 处理滚轮。事件由 EventSystem 派发，自动支持鼠标和触摸。

</Step>

## 代码对照

```csharp
// Button 点击事件
button.onClick.AddListener(() => Debug.Log("点击"));

// Toggle 值变化

    Debug.Log($"开关: {isOn}");
});

// Slider 值变化
slider.onValueChanged.AddListener(value => {
    volume = value; // 0~1
});

public class DraggableItem : MonoBehaviour, IBeginDragHandler, IDragHandler, IEndDragHandler {

    public void OnDrag(PointerEventData e) { transform.position = e.position; }
    public void OnEndDrag(PointerEventData e) { /* 提交 */ }
}
```

## 常见误区

<Callout type="trap">
**误区：在 Update 中用 Input.GetMouseButton 检测 UI 按钮按下。**
UGUI 有完整的事件系统，应该用 IPointerDownHandler/IPointerUpHandler/IPointerClickHandler 接口。在 Update 中轮询鼠标会绕过事件系统——无法区分 UI 点击和 3D 世界点击，不支持手柄导航，且每帧执行浪费性能。正确做法是实现事件接口，由 EventSystem 自动派发。
</Callout>

<Callout type="trap">
**误区：Slider 的 onValueChanged 在初始化时不触发，不需要处理。**
onValueChanged 在代码中修改 slider.value 时也会触发，包括初始化赋值。如果在回调中有依赖其他未初始化组件的逻辑，会报 NullReferenceException。解决方案：用标志位区分初始化和用户操作，或在 Awake 中先注册事件再设置初始值。
</Callout>

<Exercises>
**问题 1**：Selectable 的四种状态和三种过渡模式分别是什么？

<Answer>
四种状态：Normal（正常/默认）、Highlighted（高亮/鼠标悬停或被选中）、Pressed（按下）、Disabled（禁用/interactable=false）。三种过渡模式：ColorTint（颜色渐变，通过修改 Graphic 的颜色实现）、SpriteSwap（精灵替换，切换 Image 的 sprite）、Animation（动画，通过 Animator 播放对应状态的动画片段）。
</Answer>

**问题 2**：ScrollRect 的工作原理是什么？Viewport 和 Content 的关系？

<Answer>
ScrollRect 通过 RectMask2D 裁剪 Viewport 区域，只显示 Content 中位于 Viewport 内的部分。Content 是实际内容容器，包含所有列表项。滚动时移动 Content 的 RectTransform.anchoredPosition，改变可见区域。normalizedPosition（0~1）表示滚动进度。Viewport 的大小固定（等于 ScrollRect 大小），Content 的大小由内容决定。Horizontal/Vertical Scrollbar 是可选的视觉控件，绑定后自动同步滚动位置。
</Answer>
