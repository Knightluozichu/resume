## 直觉引入

想象一排书架。书架的隔板按书的高度排列（LayoutGroup），每本书有一个最小厚度和期望厚度（LayoutElement），书架本身可以根据书的总厚度伸缩（ContentSizeFitter）。三个组件协作，就能自动排列任意数量、任意大小的 UI 元素——不用手动算坐标。

## 概念讲解

### 布局三件套

<UidLayoutSystemDiagram />

<Term def="LayoutGroup是自动排列子元素的组件，有Horizontal/Vertical/Grid三种，读取子元素的LayoutElement属性决定排列">LayoutGroup</Term>是排列的指挥官。

<Term def="LayoutElement提供minWidth/preferredWidth/flexibleWidth等尺寸约束属性，告诉LayoutGroup自己需要多大空间">LayoutElement</Term>是尺寸的声明书。

<Term def="ContentSizeFitter根据自身的LayoutElement属性自动调整RectTransform尺寸，实现内容驱动的大小自适应">ContentSizeFitter</Term>是大小的调节器。

## 交互Demo

<Stepper>
<Step title="第一步：LayoutGroup 排列">在父物体上挂 VerticalLayoutGroup，子元素会自动从上到下排列。设置 spacing 控制间距，childAlignment 控制对齐方式，padding 控制内边距。三种变体：Horizontal（水平）、Vertical（垂直）、Grid（网格）。</Step>
<Step title="第二步：LayoutElement 约束">
在子元素上挂 LayoutElement，设置 preferredWidth/preferredHeight 声明期望尺寸。LayoutGroup 会优先分配 preferred 值。如果子元素有 minWidth，在空间不足时不会被压缩低于此值。
<UidLayoutSystemDiagram />
</Step>
<Step title="第三步：ContentSizeFitter 自适应">在需要内容驱动大小的元素上挂 ContentSizeFitter，设置 Horizontal/Vertical Fit 为 Preferred，元素的 RectTransform 尺寸会自动跟随 LayoutElement 的 preferred 值。常用于文字框自适应、动态列表项。</Step>
</Stepper>

## 代码对照

```csharp
// VerticalLayoutGroup 自动排列
var vlg = content.AddComponent<VerticalLayoutGroup>();
vlg.spacing = 10f;
vlg.padding = new RectOffset(20, 20, 20, 20);
vlg.childAlignment = TextAnchor.UpperCenter;
vlg.childControlHeight = true;
vlg.childForceExpandHeight = false;

// LayoutElement 尺寸约束
var le = item.AddComponent<LayoutElement>();
le.preferredHeight = 80f;
le.minHeight = 60f;

// ContentSizeFitter 自适应
var csf = content.AddComponent<ContentSizeFitter>();
csf.verticalFit = ContentSizeFitter.FitMode.PreferredSize;

// 手动重建布局（添加新元素后）
LayoutRebuilder.ForceRebuildLayoutImmediate(contentRect);
```

## 常见误区

<Callout type="trap">
**误区：ContentSizeFitter 和 LayoutGroup 嵌套使用时不触发重建。**
ContentSizeFitter 修改自身尺寸会影响 LayoutGroup 的排列，但布局重建不是立即的。添加/删除子元素后需要调用 LayoutRebuilder.ForceRebuildLayoutImmediate 手动触发，否则会出现一帧的布局错位。在 ScrollRect 动态列表中尤其常见。
</Callout>

<Callout type="trap">
**误区：在 LayoutGroup 子元素上同时用 ContentSizeFitter 和手动设置 sizeDelta。**
ContentSizeFitter 会覆盖 sizeDelta。如果同时手动设置 sizeDelta 和挂 ContentSizeFitter，每帧 ContentSizeFitter 都会重置尺寸，导致手动设置无效。应该用 LayoutElement.preferredWidth/Height 替代手动 sizeDelta，让布局系统统一管理尺寸。
</Callout>

<Exercises>
**问题 1**：LayoutElement 的 minWidth、preferredWidth、flexibleWidth 有什么区别？

<Answer>
minWidth 是最小尺寸——布局系统不会把元素压缩到低于此值。preferredWidth 是期望尺寸——布局系统在有空间时优先分配此值。flexibleWidth 是弹性权重——剩余空间（满足所有 min 和 preferred 之后的多余空间）按 flexibleWidth 比例分配。分配优先级：先满足所有 minWidth，再分配 preferredWidth，最后按 flexibleWidth 分剩余空间。
</Answer>

**问题 2**：设计一个背包列表，每项高度根据物品描述长度变化，如何实现？

<Answer>
1)ScrollRect 的 Content 挂 VerticalLayoutGroup（childControlHeight=true, childForceExpandHeight=false）；2)每个列表项挂 LayoutElement，preferredHeight 根据描述行数动态计算；3)列表项挂 ContentSizeFitter（VerticalFit=Preferred）确保高度跟随内容；4)添加/删除项后调用 LayoutRebuilder.ForceRebuildLayoutImmediate 触发重建；5)大量数据用对象池复用，只重建可见区域。关键：ContentSizeFitter 在列表项层级，VerticalLayoutGroup 在父级，不要同层混用。
</Answer>
</Exercises>
