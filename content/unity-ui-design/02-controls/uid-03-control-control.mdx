## 问题：为什么把控件拖进 Canvas 并不等于真正理解它的状态与数据流

## 核心模型：从对象到可观察结果

Graphic 类控件先生成可渲染顶点：Text 依据字体与字符串生成字形网格，Image 依据 Sprite border 和 type 生成简单、九宫格、平铺或填充几何，RawImage 直接映射 Texture 与 uvRect。Selectable 再叠加 Normal、Highlighted、Pressed、Selected、Disabled 状态，并用颜色、Sprite Swap 或 Animation 驱动目标 Graphic。视觉与交互是组合关系，不是继承名称自动保证。

## 关键对象与生产者到消费者链

一次菜单操作从 EventSystem 当前选中对象开始，Navigation 根据方向寻找下一个 Selectable，Move/Submit/Cancel 事件改变状态并触发 UnityEvent。ToggleGroup 维护互斥选择，Slider 把指针位置映射到规范化值，ScrollRect 把拖动与惯性转换为 content anchoredPosition，Mask/RectMask2D 决定可见区。任何一环配置错误都可能表现为按钮不亮、手柄迷路、滚动穿透或内容越界。

为了避免“改完好像对了”，先写下生产者、变换规则、消费者与可观测量。每个对象都必须能在层级、Inspector、事件日志、坐标记录或渲染结果中找到证据；没有观测点的解释不能进入结论。

## 失败边界与常见误判

<Callout type="trap">
  **边界一**：使用 Sliced Image 却未设置 Sprite border，会得到和 Simple
  类似的拉伸结果；问题不在布局，而在资源元数据。
</Callout>

<Callout type="trap">
  **边界二**：Automatic Navigation
  在不规则布局中可能选错目标。发布前必须用真实手柄走遍边界，并对关键菜单改用
  Explicit。
</Callout>

失败样本要保留输入、层级、关键参数和日志。只保存一张错误截图，会丢掉父矩形、相机、输入模块、射线排序或版本差异这些真正决定行为的条件。

## 从 Unity 4.6/5 到现代 Unity

现代项目通常用 TextMeshProUGUI 替代旧 Text，并可用 SpriteAtlas、Input System 与 RectMask2D 改善资源和输入。Selectable 与 UnityEvent 的核心行为仍适用。UI Toolkit 的 Button、ScrollView 和 USS 状态选择器使用另一套树与事件传播；可以比较能力，但不能把它们混进本章原始控件清单。

迁移报告采用四列：原书对象、稳定不变量、现代载体、已知差异。若现代载体改变事件模型、坐标空间或序列化方式，就应判为“功能近似，需要重新验收”，不能写成无差别替换。

## 验收证据包

验收场景是一套可用鼠标、触摸、键盘和手柄操作的设置菜单，包含九宫格面板、Filled 血条、RawImage 预览、按钮、ToggleGroup、Slider 和滚动列表。保存每个 Selectable 的状态转换、当前选中对象、事件参数、scroll normalizedPosition、mask 边界和渲染输出。

验收还要包含正常、边界和失败三类样本。正常样本证明主路径，边界样本证明约束，失败样本证明诊断方法确实能抓到错误。三者使用同一场景与记录格式，下一版本才能直接回归。

## 小结

- Graphic 决定视觉网格，Selectable 决定交互状态与导航
- Image 类型要与 Sprite border、填充目标和纹理来源匹配
- Toggle、Slider、ScrollRect 都是输入到状态再到事件的映射器
- 控件验收必须覆盖鼠标、触摸、键盘和手柄路径

<Exercises>

**问题 1** Filled Image 与 Slider 的职责有什么不同？

<Answer>
  Filled Image 只根据 fillAmount 改变视觉填充；Slider
  还处理输入、范围、方向、handle 和 value changed 事件，常用 Slider 驱动 Filled
  Image。
</Answer>

**问题 2** 为什么 RawImage 不适合替代所有 Image？

<Answer>
  RawImage 直接引用 Texture，缺少 Sprite border、atlas 和 Image type
  语义，容易增加纹理切换；它更适合 RenderTexture 或动态纹理。
</Answer>

**问题 3** 怎样验收一个可访问的手柄菜单？

<Answer>
  记录每个方向的显式或自动邻居，验证 disabled
  项跳过、默认焦点、循环边界、Submit/Cancel 和视觉选中状态，并用事件日志重放。
</Answer>
