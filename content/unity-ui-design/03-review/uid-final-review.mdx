## 常见误区

<Callout type="trap">
**误区：学完全书后还是习惯在 Update 中轮询输入。**
全书反复强调：UGUI 有完整的事件系统，应该用 IPointerClickHandler 等接口被动接收事件。在 Update 中用 Input.GetMouseButton 检测 UI 点击是最大的反模式——绕过事件系统、不支持手柄、每帧执行浪费性能。养成习惯：看到 UI 交互需求，第一反应是「用哪个事件接口」。
</Callout>

<Callout type="trap">
**误区：性能优化只关注 Draw Call，忽略 Canvas 重建。**
Draw Call 是 GPU 开销，Canvas 重建是 CPU 开销。在元素多的 UI（如 100 项背包）中，Canvas 重建的 CPU 开销往往比 Draw Call 更大。静态动态分 Canvas、按需更新（脏标记）、对象池虚拟化是减少 CPU 开销的三大手段。优化时两者都要关注——用 Frame Debugger 查 Draw Call，用 Profiler 查 Canvas.BuildBatch 的 CPU 开销。
</Callout>

<Exercises>
**问题 1**：全书四条核心原则是什么？

<Answer>
1)事件驱动：用事件接口（IPointerClickHandler 等）被动接收输入，不在 Update 中轮询。2)布局优先：用 LayoutGroup/LayoutElement/ContentSizeFitter 自动布局，不手动计算坐标。3)动画用 DOTween：链式 API 一行完成，Sequence 编排复杂动画，Animator 仅用于复杂状态机。4)性能三步法：先查 Draw Call（合批），再查图集（合并），最后查 Overdraw（削减），静态动态分 Canvas。
</Answer>

**问题 2**：综合全书知识，如何设计一个 MMO 游戏的 UI 架构？

<Answer>
分层架构：1)Canvas 分层——Static（背景）/Dynamic（HUD）/Popup（弹窗）/Tooltip（提示），各层独立 Canvas 避免重建扩散；2)组件选型——HUD 用 UGUI（实时更新分独立 Canvas），背包/技能树用 UGUI+LayoutGroup+对象池虚拟化，编辑器工具用 UI Toolkit；3)动画——DOTween 统一管理，Sequence 编排弹窗进出；4)性能——Sprite Atlas 按模块拆分，RaycastTarget 纯装饰全关，Draw Call 控制在 100 以内；5)响应式——Scale With Screen Size + Match + Safe Area 适配。
</Answer>
