## 核心模型：从对象到可观察结果

Overlay Canvas 直接在屏幕空间末端合成，不需要渲染相机；Screen Space Camera 把 Canvas 放在指定相机前方平面，受 planeDistance、相机 viewport 和排序影响；World Space Canvas 是普通场景几何，尺寸、朝向、深度和遮挡都进入世界坐标。Render Camera 决定视觉投影，Event Camera 则让 GraphicRaycaster 把屏幕指针转换成 UI 平面射线，二者可能同一台但职责不同。

## 关键对象与生产者到消费者链

世界目标血条通常先用 Camera.WorldToScreenPoint 得到屏幕点，再由 RectTransformUtility.ScreenPointToLocalPointInRectangle 转换到 Canvas 本地坐标。若使用 World Space Canvas，则可以直接跟随目标位置并朝向相机，但要处理世界尺度、像素密度、遮挡和近远裁剪。还要检查目标在相机后方、离开 viewport、被遮挡或死亡时的显示规则，坐标正确只是第一层。

为了避免“改完好像对了”，先写下生产者、变换规则、消费者与可观测量。每个对象都必须能在层级、Inspector、事件日志、坐标记录或渲染结果中找到证据；没有观测点的解释不能进入结论。

## 失败边界与常见误判

<Callout type="trap">
  **边界一**：WorldToScreenPoint 的 z 为负时目标在相机背后，x/y
  仍可能落在屏幕范围；只检查二维坐标会让标记反向出现。
</Callout>

<Callout type="trap">
  **边界二**：视觉相机正确不代表事件相机正确。多相机或 World Space 场景中，错误
  worldCamera 会造成可见但点击偏移。
</Callout>

失败样本要保留输入、层级、关键参数和日志。只保存一张错误截图，会丢掉父矩形、相机、输入模块、射线排序或版本差异这些真正决定行为的条件。

## 从 Unity 4.6/5 到现代 Unity

现代 Unity 在 URP/HDRP、Camera Stack、XR 多眼和动态分辨率下增加了更多相机边界，但三种 Canvas 模式和视觉/事件相机分工仍适用。迁移时要在实际渲染管线与目标平台测排序、后处理、XR 眼纹理和 Input System 指针；不能用编辑器 Scene View 的可见性代替 Game Camera 证据。

迁移报告采用四列：原书对象、稳定不变量、现代载体、已知差异。若现代载体改变事件模型、坐标空间或序列化方式，就应判为“功能近似，需要重新验收”，不能写成无差别替换。

## 验收证据包

验收场景同时包含 Overlay HUD、Camera 模式菜单和 World Space 终端。记录目标 world position、WorldToScreenPoint 结果、Canvas local point、相机 viewport、planeDistance、sorting、eventCamera、raycast hit 与遮挡结果。移动相机、切换宽高比和把目标放到相机背后，确认失败规则可重放。

验收还要包含正常、边界和失败三类样本。正常样本证明主路径，边界样本证明约束，失败样本证明诊断方法确实能抓到错误。三者使用同一场景与记录格式，下一版本才能直接回归。

## 小结

- 三种 Canvas 模式决定 UI 位于屏幕链还是世界链
- Render Camera 负责视觉，Event Camera 负责输入坐标解释
- 世界跟随 UI 需要处理两段坐标转换和相机背面边界
- 世界空间 UI 还要验收尺度、朝向、深度、遮挡与命中

<Exercises>

**问题 1** Overlay Canvas 做世界跟随标记时，转换函数的 camera 参数通常是什么？

<Answer>
  将屏幕点转换到 Overlay Canvas 本地坐标时通常传
  null；世界点到屏幕点仍使用渲染世界的相机。具体要按 RectTransformUtility API 与
  Canvas 模式验证。
</Answer>

**问题 2** Screen Space Camera 和 World Space 的主要选择依据是什么？

<Answer>
  前者适合保持屏幕布局但需要相机排序或后处理关系的
  UI；后者适合真正存在于场景中的面板，需要深度、尺度、朝向和遮挡。
</Answer>

**问题 3** 如何证明 Event Camera 配置正确？

<Answer>
  在 Canvas 四角和中心发射 PointerEventData，记录 RaycastResult 的目标与
  worldPosition，再切换相机 viewport、位置和分辨率，命中应与视觉元素一致。
</Answer>
