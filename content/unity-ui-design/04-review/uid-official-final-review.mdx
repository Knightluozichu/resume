## 问题：怎样证明学完的是一套完整系统，而不是记住一组 Inspector 选项

先预测：一个菜单在 1080p 鼠标操作下通过，能否说明它在手柄、竖屏、World Space 和遮挡场景也正确？不能。全书最终验收要把第 1 章的架构动机、第 2 章的布局与事件入口、第 3 章的控件状态、第 4 章的响应式约束、第 5 章的相机空间、第 6 章的事件执行和附录场景串成同一个可重放项目。

## 原书边界：全书总复习

综合验收不新增原文章。它逐一引用 6 章和附录的正式范围，检查每个单元是否有独立页面、专属实验、失败样本和现代迁移说明。UI Toolkit、Safe Area、TextMeshPro、Input System 与现代包源码只进入迁移矩阵，不能被用来补足缺失的原书小节。

- **Chapter 1**：从 IMGUI 到保留式 uGUI、编辑器、Canvas 与 UnityEvent
- **Chapter 2**：RectTransform、布局组件、缩放、Mask、Raycasting 与 Input Module
- **Chapter 3**：Text/Image/RawImage、Selectable、Toggle、Slider、ScrollRect、Navigation
- **Chapter 4**：锚点、拉伸与三种 CanvasScaler 模式
- **Chapter 5**：三种 Canvas 模式、Render/Event Camera 与空间 UI
- **Chapter 6**：EventSystem loop、RaycastAll、ExecuteEvents、自定义事件与源码
- **Appendix**：可重复的 3D 场景输入与第 5 章夹具

这些小节按出版社目录保持唯一归属；本站的实验、现代迁移与复习只是教学增强，不改变原章身份，也不拿一个现代主题重复补多个原始单元。

## 核心模型：从对象到可观察结果

综合项目采用双链验收。视觉链为数据状态到控件属性、布局约束、RectTransform 几何、Canvas/Camera 投影和最终像素；输入链为设备、Input Module、PointerEventData、Raycaster、EventSystem、ExecuteEvents、Selectable/自定义处理器和业务状态。两条链在控件状态与最终几何处相交，任一处版本迁移都要证明输入输出不变量。

## 关键对象与生产者到消费者链

项目包含主菜单、设置面板、滚动列表、HUD 世界跟随血条和 World Space 终端。场景夹具提供固定目标路径；布局矩阵覆盖宽高比、DPI 和方向；输入矩阵覆盖鼠标、触摸、键盘与手柄；事件日志覆盖 raycast 和 selected；现代矩阵分别替换 TextMeshPro、Input System 或包版本。每次只替换一个载体。

为了避免“改完好像对了”，先写下生产者、变换规则、消费者与可观测量。每个对象都必须能在层级、Inspector、事件日志、坐标记录或渲染结果中找到证据；没有观测点的解释不能进入结论。

## 失败边界与常见误判


失败样本要保留输入、层级、关键参数和日志。只保存一张错误截图，会丢掉父矩形、相机、输入模块、射线排序或版本差异这些真正决定行为的条件。

## 从 Unity 4.6/5 到现代 Unity

现代化不是把所有页面改名为 UI Toolkit。先标记稳定不变量：父子矩形约束、Canvas 空间、视觉与事件相机、事件数据和消费者契约；再逐项选择 TextMeshPro、Input System、Safe Area、URP/XR 或 UI Toolkit。若改用 UI Toolkit，应另建功能等价实验并承认它不再是原书 uGUI 实现，而不是抹去差异。

迁移报告采用四列：原书对象、稳定不变量、现代载体、已知差异。若现代载体改变事件模型、坐标空间或序列化方式，就应判为“功能近似，需要重新验收”，不能写成无差别替换。

## 验收证据包

最终证据包包含版本身份、7/7 目录映射、项目层级、关键 Inspector 表、输入与布局测试矩阵、事件时间线、坐标日志、失败重放、现代迁移差异和复习题结果。综合得分只有在所有原章页面达到门槛、目录覆盖至少 90%、MDX 和类型检查通过后才签发。

验收还要包含正常、边界和失败三类样本。正常样本证明主路径，边界样本证明约束，失败样本证明诊断方法确实能抓到错误。三者使用同一场景与记录格式，下一版本才能直接回归。

## 综合测试矩阵与签发规则

测试矩阵至少包含三组分辨率、横竖两种方向、鼠标与手柄两种输入、Overlay/Camera/World 三种 Canvas 模式。每个组合执行打开菜单、切换选项、拖动 Slider、滚动列表、返回默认焦点、跟随世界目标与点击世界面板七个动作。输出统一记录最终矩形、当前选中对象、首个 raycast 命中、业务状态、Canvas 模式和相机。组合很多时先用等价类覆盖，再为历史失败增加回归样本。

签发分三层。忠实度层要求 7/7 原始单元、正式小节命中和版本来源；教学层要求每页有模型、专属交互图、三步实验、陷阱、练习与术语；工程层要求 MDX、类型、题库、导航和运行时索引通过。现代迁移另附矩阵，不得提高原始覆盖率。任一章节低于 90、事件链无日志或场景夹具不可复原时，整书保持未完成。

最终复述应能从任一症状选择链路：位置错误先查父矩形、锚、布局与 Scaler；视觉正确但点不到先查 Event Camera、Raycaster 与阻挡；手柄迷路查 selected 和 Navigation；世界标记漂移查 world-screen-local 三段坐标；重复事件查输入模块与 ExecuteEvents；升级后失效则比较原书载体和现代包版本。能够这样定位，才说明知识已经形成体系。

签发记录还应列出每个原始单元的唯一页面、题目数量、专属图模块和最近一次通过时间，并保存一条主动失败的链接或场景。这样下一轮维护者可以快速判断是目录漂移、教学退化、代码编译还是运行行为回归，不会把“文件还在”误当成“知识仍然完整”。

复核者还要随机抽取一个症状，从日志反向定位到责任对象并说明排除过程。只有答案可被另一人重复验证，综合验收才真正闭环。

## 小结

- 6 章与附录共同构成完整原书边界，导读和复习不占原章
- 视觉链与输入链是串联布局、相机、控件和事件的两条主线
- 综合项目必须在多分辨率、多输入和多 Canvas 模式下复测
- 现代迁移要逐项证明功能等价，并保留差异和失败样本
