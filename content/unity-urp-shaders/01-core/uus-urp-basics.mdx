## 直觉引入

想象一个工厂流水线。SRP Core 是工厂主管——决定整体流程；Renderer 是车间主任——组织具体工序；Render Pass 是工位——执行单个工序；Shader 是工人的技能——决定产品质量。URP 就是这个「渲染工厂」，每一帧都按固定流程把 3D 场景加工成 2D 图像。

## 概念讲解

### URP 架构层级

<UusUrpBasicsDiagram />

<Term def="SRP（Scriptable Render Pipeline）是 Unity 的可编程渲染管线框架，允许用 C# 脚本控制渲染流程">SRP</Term> 是 URP 的底层框架。URP 在 SRP 之上提供了开箱即用的跨平台渲染方案。

核心层级：
- <Term def="URP Asset 是管线配置资产，控制渲染质量、阴影、后处理等全局参数">URP Asset</Term>：全局渲染配置（质量等级、MSAA、阴影、后处理）
- <Term def="Renderer Data 定义渲染器的 Pass 组成和 Feature 列表">Renderer Data</Term>：渲染器数据，定义 Pass 列表和 Feature
- <Term def="Render Pass 是管线中的单步渲染操作，如渲染不透明物体、渲染阴影等">Render Pass</Term>：单个渲染步骤
- Shader：着色器，定义物体表面着色逻辑

## 代码对照

```csharp
// URP 渲染调度核心（简化伪码）
// ScriptableRenderer.Render() 每帧调用
public virtual void Render(ScriptableRenderContext context, ref RenderingData renderingData) {
    // 按 m_RenderPasses 列表顺序执行
    foreach (var pass in m_RenderPasses) {
        pass.Execute(context, ref renderingData);
    }
}

// 自定义 Renderer Feature 注册 Pass
public class OutlineFeature : ScriptableRendererFeature {
    public override void Create() {
        m_OutlinePass = new OutlinePass(renderPassEvent);
    }
    public override void AddRenderPasses(ScriptableRenderer renderer, ref RenderingData data) {
        renderer.EnqueuePass(m_OutlinePass); // 注入管线
    }
}
```

## 常见误区

<Callout type="trap">
**误区：混淆 URP Asset 和 Renderer Data 的职责。**
URP Asset 控制全局渲染参数（质量/MSAA/HDR），Renderer Data 控制渲染器的 Pass 组成和 Feature 列表。改阴影质量在 URP Asset，加描边效果在 Renderer Data。两者职责不同，混改会导致配置混乱。
</Callout>

<Callout type="trap">
**误区：忽视 SRP Batch 的启用条件。**
SRP Batch 要求 Shader 兼容（使用 CBUFFER、不使用 MaterialPropertyBlock）、关键词组合一致。不满足条件时自动回退到普通绘制，SRP Batcher 不会生效。需在 Frame Debugger 中确认是否真正合批。
</Callout>

<Exercises>
**问题 1**：URP 的核心架构层级是什么？各层职责是什么？

<Answer>
SRP Core（管线调度核心，每帧调用 Render()）→ Renderer（渲染器，组织 Pass 列表和 Feature）→ Render Pass（渲染通道，执行单步渲染如不透明/阴影/后处理）→ Shader（着色器，定义物体表面着色逻辑）。URP Asset 控制全局参数，Renderer Data 定义 Pass 组成，Feature 可扩展注入自定义 Pass。
</Answer>

**问题 2**：SRP Batch 的条件是什么？为什么有时不生效？

<Answer>
SRP Batch 的条件：1) Shader 兼容（使用 CBUFFER_START/END 包裹属性，符合 URP 规范）；2) 相同 Shader 且相同关键词组合（multi_compile/shader_feature 变体一致）；3) 不使用 MaterialPropertyBlock（会破坏 CBUFFER 兼容性）；4) SRP Batcher 在 URP Asset 中启用。不满足任一条件时回退到普通绘制，可在 Frame Debugger 中查看 SetPass Call 是否被合并来确认是否生效。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="SRP">Scriptable Render Pipeline，Unity 的可编程渲染管线框架，允许用 C# 脚本控制渲染流程。</GlossaryItem>
<GlossaryItem term="Renderer Data">URP 渲染器数据资产，定义渲染器的 Render Pass 组成和 Renderer Feature 列表。</GlossaryItem>
<GlossaryItem term="SRP Batch">URP 合批机制，将相同 Shader 的绘制调用合并，减少 CPU 端 SetPassCall 开销。</GlossaryItem>
<GlossaryItem term="Renderer Feature">可插拔的渲染特性，通过 Create() 创建 Pass 并注入管线，扩展 URP 渲染能力。</GlossaryItem>
</Glossary>
