## 直觉引入

想象你在拼乐高。每个积木块是一个节点——颜色块、数学运算块、纹理采样块。你把它们用线连起来，数据从一个块流向另一个块，最后拼到主输出块上。Shader Graph 就是「乐高版着色器编辑器」——不用写代码，拖拽连线就能生成 Shader。

## 概念讲解

### 节点工作流

<UusUrpShaderGraphDiagram />

<Term def="Shader Graph 是 Unity 的可视化着色器编辑器，通过节点连线生成 HLSL 代码">Shader Graph</Term> 的核心流程：输入节点（Property / Texture）→ 处理节点（Math / Sub Graph）→ 输出节点（Vertex / Fragment）。

关键概念：
- <Term def="Property 是 Shader Graph 的外部参数，对应 ShaderLab 的 Properties，可在材质面板调节">Property</Term>：外部参数（Color / Float / Vector / Texture）
- <Term def="Sub Graph 是可复用的节点子图，类似函数，可跨多个 Shader Graph 调用">Sub Graph</Term>：可复用子图
- <Term def="Master Node 是 Shader Graph 的输出节点，决定 Vertex 和 Fragment 的最终输出">Master Node</Term>：主输出节点

## 代码对照

```hlsl
// Shader Graph 生成的 HLSL（简化）
// 等价于：BaseColor = Texture.Sample(uv) * TintColor;

// 属性定义（对应 Blackboard Property）
CBUFFER_START(UnityPerMaterial)
    float4 _BaseColor;
    float4 _BaseMap_TexelSize;
    float _Smoothness;
CBUFFER_END

// 纹理声明
TEXTURE2D(_BaseMap); SAMPLER(sampler_BaseMap);

// Fragment 函数（对应主节点 Fragment 输出）
half4 frag(Varyings IN) : SV_Target {
    // Sample Texture 2D 节点
    half4 texColor = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, IN.uv);
    // Multiply 节点：texColor * _BaseColor
    half3 baseColor = texColor.rgb * _BaseColor.rgb;
    // 输出到 BaseColor 端口
    return half4(baseColor, 1.0);
}
```

## 常见误区

<Callout type="trap">
**误区：过度依赖 Shader Graph 忽略性能。**
Shader Graph 生成的 HLSL 代码可能不如手写精简——多余节点会产生无用计算，分支逻辑可能生成过多变体。复杂效果应手写 HLSL 或用 Sub Graph 优化节点结构，并用 Frame Debugger 检查实际开销。
</Callout>

<Callout type="trap">
**误区：忽视端口类型匹配。**
Shader Graph 的端口有类型（Vector1/2/3/4），类型不匹配时自动转换可能丢失数据。例如把 Vector4 连到 Vector3 端口会丢弃 w 分量。应显式使用 Split/Combine 节点控制分量，避免隐式转换。
</Callout>

<Exercises>
**问题 1**：Shader Graph 的节点工作流是什么？三个关键概念是什么？

<Answer>
工作流：输入节点（Property / Texture）→ 处理节点（Multiply / Lerp / Sample Texture 等数学与纹理节点）→ 主节点（Vertex / Fragment 输出）。三个关键概念：Property（外部参数，对应材质面板可调属性）、Sub Graph（可复用子图，类似函数封装）、Master Node（主输出节点，决定顶点和像素的最终输出值）。
</Answer>

**问题 2**：什么时候该用 Shader Graph，什么时候该手写 HLSL？

<Answer>
用 Shader Graph：快速原型开发、简单到中等复杂度效果（颜色混合、纹理变换、简单光照修改）、团队中非程序员参与 Shader 制作。手写 HLSL：性能敏感的 Shader（需要精确控制指令数和寄存器）、复杂循环/分支逻辑、自定义 Render Pass 的着色器、需要深度优化变体数量的场景。最佳实践：Shader Graph 做原型，验证效果后手写 HLSL 优化。
</Answer>
</Exercises>
