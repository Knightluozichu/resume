### 五个核心符号

1. **RenderPipeline标签**：让SubShader只在UniversalPipeline中成为候选的标签。
2. **LightMode**：把Pass角色与URP运行时绘制阶段匹配的标签。
3. **UniversalMaterialType**：为Lit、SimpleLit等材质类型提供延迟路径标识。
4. **Render State**：Blend、ZWrite、Cull、Stencil等GPU固定状态。
5. **Pass证书**：记录Pass名、LightMode、关键字、include和目标缓冲的证据。

## 生产者到消费者链

逐Pass读取Lit.shader，建立UniversalForward、UniversalGBuffer、ShadowCaster、DepthOnly、DepthNormals、Meta和MotionVectors之间的角色表。Shader文件顺序不等于每帧执行顺序，必须与Renderer事件和Frame Debugger互证。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
selectedPass=f(renderer,LightMode,material)
$$

$$
state=shaderProperties+passCommands
$$

$$
draw=object*selectedPasses
$$

$$
proof=LightMode+target+event
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
Tags { "RenderPipeline"="UniversalPipeline" "LightMode"="UniversalForward" }
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。

## 验收证书

证书包含提交、文件、符号、调用和include链、材质与关键字、Renderer配置、Pass事件、目标缓冲、GPU计时与失败反例。自定义Pass只有名称没有受支持的LightMode，Shader能编译却从不被URP调度。 修复后必须重放同一配置，并指出静态源码和运行时事件各发生了什么变化。
