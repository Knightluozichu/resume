## 直觉引入

想象你拍了张照片，然后用修图软件调色：先加滤镜（Bloom），再调亮度对比度（Color Adjustments），最后做色调映射让 HDR 效果适配屏幕（Tone Mapping）。URP 后处理栈就是这个「修图流水线」——一帧画面渲染完后，经过一系列全屏处理，输出最终图像。

## 概念讲解

### 后处理链与 Volume 系统

<UusUrpPostProcessingDiagram />

<Term def="Volume 是 URP 后处理的空间权重容器，Global Volume 全局生效，Local Volume 在区域内插值混合">Volume</Term> 系统通过 Volume Profile → Volume Component → Override 管理后处理参数。

后处理链执行顺序：场景渲染（Camera Color RT）→ Bloom → Color Adjustments → Tone Mapping → 输出。

- <Term def="Bloom 是泛光效果，提取亮区并模糊扩散，模拟相机过曝溢光">Bloom</Term>：亮区提取 + 高斯模糊 + 叠加
- <Term def="Tone Mapping 是色调映射，将 HDR（>1.0）颜色压缩到 LDR（0~1）屏幕可显示范围">Tone Mapping</Term>：ACES / Neutral / 可定制曲线
- <Term def="注入点（Injection Point）是后处理 Pass 插入管线的位置，如 BeforeRenderingPostProcessing 和 AfterRendering">注入点</Term>：控制后处理在管线中的执行时机

## 代码对照

```csharp
// URP 后处理 Volume 系统（C# 侧）
// Volume 挂载在 GameObject 上，含 VolumeProfile
[RequireComponent(typeof(Volume))]
public class DynamicExposure : MonoBehaviour {
    Volume m_Volume;
    ColorAdjustments m_Adjustments;

    void Start() {
        m_Volume = GetComponent<Volume>();
        // 从 Profile 获取 Volume Component
        if (m_Volume.profile.TryGet(out m_Adjustments)) {
            m_Adjustments.postExposure.value = 0.5f; // 曝光补偿
        }
    }
}

// 自定义后处理 Renderer Feature（简化）
public class CustomEffectFeature : ScriptableRendererFeature {
    class CustomEffectPass : ScriptableRenderPass {
        public override void OnCameraSetup(CommandBuffer cmd, ref RenderingData data) {
            // 分配临时 RT
            var desc = data.cameraData.cameraTargetDescriptor;
            cmd.GetTemporaryRT(m_TempRT, desc);
        }
        public override void Execute(ScriptableRenderContext ctx, ref RenderingData data) {
            // Blit：source → 自定义材质 → target
            Blit(cmd, cameraColorTarget, m_TempRT, m_Material);
            Blit(cmd, m_TempRT, cameraColorTarget);
        }
    }
}
```

## 常见误区

<Callout type="trap">
**误区：后处理效果越多越好。**
每个后处理效果至少一次全屏 Blit（读+写一个 RT），4K 分辨率下一次 Blit 约 8MB 带宽。叠加 Bloom + DoF + Motion Blur + 调色 + 色调映射 = 5+ 次 Blit，移动端会严重掉帧。应只保留关键效果，移动端用简化版本。
</Callout>

<Callout type="trap">
**误区：在 Tone Mapping 前做调色导致颜色失真。**
Tone Mapping 将 HDR 压缩到 LDR，在 Tone Mapping 前的 Color Adjustments 操作的是 HDR 颜色（可能 >1.0）。如果在 Tone Mapping 后做调色，颜色已被压缩，调色空间不正确。正确顺序：Bloom → Color Adjustments（HDR 空间）→ Tone Mapping（HDR→LDR）→ Vignette/Grain（LDR 空间）。
</Callout>

<Exercises>
**问题 1**：URP 后处理链的执行顺序是什么？为什么 Tone Mapping 在最后？

<Answer>
执行顺序：场景渲染 → Bloom → Color Adjustments → Tone Mapping → Vignette/Grain → 输出。Tone Mapping 在最后（Vignette/Grain 等纯装饰效果除外）因为：1) Bloom 和 Color Adjustments 需要在 HDR 空间（>1.0）操作，才能正确处理过曝区域；2) Tone Mapping 将 HDR 压缩到 LDR（0~1），是不可逆的压缩；3) 在 Tone Mapping 后做 HDR 操作会丢失信息。因此所有 HDR 操作必须在 Tone Mapping 前，LDR 装饰效果在其后。
</Answer>

**问题 2**：Volume 系统的 Global 和 Local Volume 如何混合？

<Answer>
Global Volume 全局生效，权重始终为 1。Local Volume 在 3D 空间中定义一个碰撞体区域，摄像机进入区域时权重从 0 渐变到 1（按 Blend Distance 参数），离开时渐变回 0。多个 Volume 按优先级（Priority）排序，高优先级的 Volume Component 覆盖低优先级的同名 Component。最终参数是所有活跃 Volume 的加权混合结果，实现平滑的区域过渡效果。
</Answer>
</Exercises>
