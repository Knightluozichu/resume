## 直觉引入

想象你用手电筒照一个物体，物体在墙上投下影子。URP 阴影系统就是模拟这个过程：从光源视角「拍一张深度照片」（Shadow Map），然后在渲染物体时比较物体深度和这张深度照片，判断是否在阴影中。级联阴影就像用不同放大倍数拍照——近处用高倍看清细节，远处用低倍覆盖范围。

## 代码对照

```hlsl
// URP 阴影采样（简化）
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Shadows.hlsl"

half4 frag(Varyings IN) : SV_Target {
    // 1. 计算阴影坐标（变换到光源空间）
    float4 shadowCoord = TransformWorldToShadowCoord(IN.positionWS);

    // 2. 采样 Shadow Map（内部含 PCF + Bias）
    // GetMainLightShadow 返回 0~1 的阴影衰减值
    half shadowAttenuation = MainLightRealtimeShadow(shadowCoord);

    // 3. 应用到光照
    Light mainLight = GetMainLight(shadowCoord);
    half3 diffuse = LightingLambert(mainLight.color, mainLight.direction, normalWS);
    half3 finalColor = diffuse * shadowAttenuation * albedo;
    return half4(finalColor, 1.0);
}

// Shadow Bias 原理
// Depth Bias: 沿光线方向偏移采样位置，减少自阴影
// Normal Bias: 沿法线方向收缩物体，减少斜面自阴影
// 两者过大 → Peter Panning（阴影脱离物体底部）
// 两者过小 → Shadow Acne（条纹状自阴影）
```

## 常见误区

<Callout type="trap">
**误区：级联数越多越好。**
每增加一级 Cascade 就多渲染一次 Shadow Map（额外的 Draw Call 和带宽）。4 级 CSM 的阴影渲染开销是 1 级的 4 倍。移动端通常用 2 级，PC 端用 4 级。应根据场景大小和平台性能选择级联数。
</Callout>

<Callout type="trap">
**误区：Bias 调到没 Acne 就行。**
Bias 过大会导致 Peter Panning——阴影脱离物体底部，物体看起来「漂浮」。正确做法：先用较小 Bias 消除大部分 Acne，再用 Normal Bias 微调斜面问题。在阴影质量面板中实时预览 Acne 和 Peter Panning 的平衡点。
</Callout>

<Exercises>
**问题 1**：Shadow Map 的工作原理是什么？CSM 解决什么问题？

<Answer>
Shadow Map 从光源视角渲染场景深度到纹理。渲染物体时，将像素位置变换到光源空间，采样 Shadow Map 的深度值与当前深度比较——如果 Shadow Map 中的深度更近，说明该像素被遮挡（在阴影中）。CSM（级联阴影）解决大场景阴影精度问题：将视锥体分为多级（最多 4 级），近处用高分辨率 Shadow Map 保证精度，远处用低分辨率覆盖范围，平衡精度与性能。
</Answer>

**问题 2**：Shadow Acne 和 Peter Panning 分别是什么？如何平衡？

<Answer>
Shadow Acne 是阴影表面的条纹状自阴影伪影——由于 Shadow Map 分辨率有限，斜面上的像素在深度比较时产生精度误差，导致部分像素误判为在阴影中。Peter Panning 是阴影脱离物体底部的现象——Bias 过大导致阴影偏移过多，物体看起来「漂浮」。平衡方法：先用较小 Depth Bias 消除大部分 Acne，再用 Normal Bias 沿法线收缩物体解决斜面 Acne，最后检查物体底部是否有 Peter Panning。两者互为权衡，需在预览中找到平衡点。
</Answer>
</Exercises>
