### 五个核心符号

1. **Lit Properties**：BaseMap、Metallic、Specular、Smoothness、Normal、Occlusion和Emission接口。
2. **UnityPerMaterial**：SRP Batcher要求稳定布局的逐材质常量缓冲。
3. **SampleMetallicSpecGloss**：按工作流和纹理通道构造金属度或镜面数据的函数。
4. **InitializeStandardLitSurfaceData**：把纹理与属性归并为SurfaceData的入口。
5. **SurfaceData**：跨Forward与GBuffer传递材质语义的标准结构。

## 生产者到消费者链

从Properties到UnityPerMaterial，再到LitInput的采样函数和SurfaceData逐字段追踪。金属/镜面工作流、Smoothness通道、Alpha、法线、遮蔽、Emission与ClearCoat都要记录来源和关键字。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
SurfaceData=f(properties,textures,uv,keywords)
$$

$$
smoothness=sample(channel)*scalar
$$

$$
normalTS=decode(normalMap)
$$

$$
batcher=stable(UnityPerMaterialLayout)
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
InitializeStandardLitSurfaceData(input.uv,surfaceData);
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
