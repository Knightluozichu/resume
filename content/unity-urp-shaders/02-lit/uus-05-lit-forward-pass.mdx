### 五个核心符号

1. **Attributes**：顶点位置、法线、切线、UV和光照贴图坐标输入。
2. **Varyings**：Forward顶点阶段传向片元阶段的插值合同。
3. **InputData**：世界位置、法线、视线、阴影坐标、GI和屏幕UV的光照输入。
4. **UniversalFragmentPBR**：合成GI、主光、附加光和材质BRDF的URP片元入口。
5. **Fog与Alpha**：光照结束后执行雾、透明和输出Alpha处理的尾段。

## 生产者到消费者链

从LitPassVertex构造Varyings，再看InitializeInputData与UniversalFragmentPBR。逐项关闭GI、主光、附加光、SSAO、Decal、Fog和Debug Display，确认关键词如何改变路径。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
vertex=TransformObjectToHClip(positionOS)
$$

$$
inputData=f(varyings,textures)
$$

$$
color=GI+mainLight+sum(additionalLights)+emission
$$

$$
output=MixFog(color)+alpha
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
half4 color=UniversalFragmentPBR(inputData,surfaceData);
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
