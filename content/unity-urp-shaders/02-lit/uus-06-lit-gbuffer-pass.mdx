### 五个核心符号

1. **FragmentOutput**：保存GBuffer多个MRT目标的延迟输出结构。
2. **BRDF编码**：把材质BRDF、法线、烘焙GI和标志压入GBuffer。
3. **MaterialFlags**：区分Lit、SimpleLit、ReceiveShadowsOff等材质行为的位标志。
4. **StencilDeferred**：按模板和光体积读取GBuffer执行延迟光照的路径。
5. **MRT带宽**：同一片元写多个渲染目标造成的显存流量。

## 生产者到消费者链

追踪LitGBufferPassFragment到BRDFDataToGbuffer，再从StencilDeferred解码。核对Forward Only回退、渲染层、阴影遮罩、法线编码和混合光照，记录每个MRT通道语义。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
gbuffer=encode(BRDFData,normal,GI,flags)
$$

$$
lighting=decode(gbuffer)+lights
$$

$$
bandwidth=pixels*sum(targetBytes)
$$

$$
deferredPass=stencilClass+lightVolume
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
FragmentOutput output=BRDFDataToGbuffer(brdfData,inputData,...) ;
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
