### 五个核心符号

1. **DepthOnly**：为深度预Pass或相机深度纹理写入深度。
2. **DepthNormals**：同时输出深度和世界法线供SSAO等屏幕效果使用。
3. **ShadowCaster**：从光源视角写入阴影图并处理偏差与Alpha裁剪。
4. **Meta Pass**：为光照烘焙提取Albedo和Emission。
5. **MotionVectors**：用当前与前一帧裁剪位置生成速度向量。

## 生产者到消费者链

把Lit主材质的Alpha裁剪、顶点变形和双面法线同步到五类辅助Pass。每类Pass都构造故障案例：深度轮廓不一致、阴影错位、烘焙颜色错误或运动拖影。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
depth=clipPosition.z/clipPosition.w
$$

$$
normalBuffer=encode(normalWS)
$$

$$
velocity=currentNDC-previousNDC
$$

$$
meta=albedo+emission
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
Name "ShadowCaster" Tags { "LightMode"="ShadowCaster" }
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event

```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
