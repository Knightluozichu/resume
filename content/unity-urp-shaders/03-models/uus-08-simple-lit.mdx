### 五个核心符号

1. **SimpleLit**：以Blinn-Phong式高光替代完整PBR的轻量受光材质。
2. **SpecularSource**：在无高光、颜色高光与纹理高光之间选择的材质模式。
3. **BlinnPhong**：SimpleLit直接光照中使用的半角向量镜面模型。
4. **SimpleLit GBuffer**：在延迟路径编码轻量材质标志和高光参数的实现。
5. **成本证书**：对比Lit与SimpleLit变体、采样、ALU和画质的记录。

## 生产者到消费者链

对照Lit和SimpleLit的Properties、Input、Forward和GBuffer文件，定位省去的PBR字段与保留的阴影/GI功能。用同一场景在目标设备比较，不凭名称推断更快。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
simple=diffuse+BlinnPhongSpecular
$$

$$
cost=f(samples,ALU,lights,variants)
$$

$$
qualityDelta=imageDiff(Lit,SimpleLit)
$$

$$
choice=budget+artDirection
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
half4 color=UniversalFragmentBlinnPhong(inputData,surfaceData);
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。

## 边界、兼容与性能

测试Forward与Deferred、主光与附加光、Lightmap与Probe、透明与Alpha Clip、XR单通道实例、动态分辨率、DOTS实例、不同图形API和移动Tile GPU。固定Unity版本、平台、分辨率、VSync和场景后再比较CPU/GPU时间。

```text
baseline: official commit 275a7f9ad933
candidate: exact local diff
correctness: image and buffer diff
compatibility: renderer modes, APIs, XR and platforms
performance: variants, SetPass, samples, bandwidth, CPU/GPU ms
failure: smallest replayable configuration
```

1. 在固定提交打开必读文件，定位入口、include、结构和核心函数。
2. 画出生产者到消费者链，并标注关键字与LightMode。
3. 用最小材质和场景触发目标变体，保存中间缓冲。
4. 构造失败配置，用源码差异和GPU事件解释原因。

## 验收证书

证书包含提交、文件、符号、调用和include链、材质与关键字、Renderer配置、Pass事件、目标缓冲、GPU计时与失败反例。直接把所有Lit材质换成SimpleLit，没有验证金属、反射与光滑度语义差异。 修复后必须重放同一配置，并指出静态源码和运行时事件各发生了什么变化。

## 常见误区

<Callout type="trap" title="源码版本没有固定">直接把所有Lit材质换成SimpleLit，没有验证金属、反射与光滑度语义差异。</Callout>

<Callout type="trap" title="静态代码等于运行时">函数被include不代表当前关键字和LightMode会执行它。必须用变体日志、Frame Debugger和GPU捕获互证。</Callout>
