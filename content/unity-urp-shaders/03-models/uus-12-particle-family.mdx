### 五个核心符号

1. **粒子顶点流**：位置、颜色、UV、动画帧、中心和自定义数据组成的输入。
2. **软粒子**：根据场景深度与粒子深度差淡化交界的技术。
3. **相机淡出**：按视距或近裁剪距离调节粒子Alpha的机制。
4. **Flipbook Blending**：在相邻精灵帧间插值减少动画跳变的采样。
5. **粒子实例化**：用实例数据批量驱动多个粒子网格的路径。

## 生产者到消费者链

对照三种粒子Shader的输入与Forward/GBuffer实现，追踪Soft Particles、Camera Fading、Flipbook、Distortion和Instancing关键字。透明粒子成本必须结合过度绘制评估。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
alpha*=softFade(sceneDepth-particleDepth)
$$

$$
frame=lerp(sampleA,sampleB,blend)
$$

$$
cost=fragments*samples*overdraw
$$

$$
variantCount=product(features)
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Particles.hlsl"
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
