### 五个核心符号

1. **Splat Control**：用控制贴图RGBA混合多层地形材质的权重。
2. **Terrain Add Pass**：超过单Pass层数后追加混合更多地形层的Pass。
3. **BasemapGen**：为远距离地形生成低成本合成底图的Shader。
4. **Terrain Detail**：处理细节网格和草纹理的专用材质路径。
5. **Waving Grass**：按风参数顶点变形并维护深度法线一致性的植被Shader。

## 生产者到消费者链

从TerrainLit的控制图采样进入Add Pass与Basemap生成，再读Detail和WavingGrass。验证层权重、法线混合、远近LOD、ShadowCaster与DepthNormals中的风动一致性。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
albedo=sum(weight_i*layer_i)
$$

$$
sumWeights=1
$$

$$
farTerrain=generatedBasemap
$$

$$
grassPosition=base+wind(time,vertexData)
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
half4 splatControl=SplatmapMix(...);
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。

## 边界、兼容与性能

测试Forward与Deferred、主光与附加光、Lightmap与Probe、透明与Alpha Clip、XR单通道实例、动态分辨率、DOTS实例、不同图形API和移动Tile GPU。固定Unity版本、平台、分辨率、VSync和场景后再比较CPU/GPU时间。

candidate: exact local diff

performance: variants, SetPass, samples, bandwidth, CPU/GPU ms

证书包含提交、文件、符号、调用和include链、材质与关键字、Renderer配置、Pass事件、目标缓冲、GPU计时与失败反例。只改主Terrain Pass的风动或Alpha裁剪，DepthNormals与阴影仍使用另一套轮廓。 修复后必须重放同一配置，并指出静态源码和运行时事件各发生了什么变化。
