### 五个核心符号

1. **SpeedTree Geometry**：区分枝干、叶片、Frond和Billboard的几何类型。
2. **风动画**：按树实例、顶点权重和时间驱动的分层形变。
3. **Billboard**：远距离以朝向相机的平面替代完整树几何。
4. **Cross Fade**：在树LOD间用抖动或Alpha完成平滑过渡。
5. **版本族**：SpeedTree 7、8、9资产格式与Shader实现的兼容边界。

## 生产者到消费者链

对照SpeedTree7、8和9入口及Utility函数，追踪风动到Forward、Shadow、DepthNormals与MotionVectors。重点验证Billboard切换、LOD Cross Fade和前一帧位置。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
position=base+wind(instance,weights,time)
$$

$$
lod=f(screenSize)
$$

$$
fade=dither(lodTransition)
$$

$$
velocity=currentWindPosition-previousWindPosition
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
