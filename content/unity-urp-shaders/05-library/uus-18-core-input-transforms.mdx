### 五个核心符号

1. **Core.hlsl**：聚合SRP Core与URP常用定义、纹理宏和变换函数的入口。
2. **UnityInput**：声明相机、矩阵、时间、屏幕与全局渲染常量。
3. **VertexPositionInputs**：一次计算OS、WS、VS、CS与NDC位置的结构。
4. **VertexNormalInputs**：处理法线、切线和副切线到世界空间的结构。
5. **相机相对位置**：在大世界或平台配置下正确获取世界空间相机位置的函数契约。

## 生产者到消费者链

顺着Core include链找到UnityInput和ShaderVariablesFunctions，逐字段验证GetVertexPositionInputs与GetVertexNormalInputs。不要复制内置管线UnityCG.cginc写法到URP。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
positionWS=TransformObjectToWorld(positionOS)
$$

$$
positionCS=TransformWorldToHClip(positionWS)
$$

$$
normalWS=TransformObjectToWorldNormal(normalOS)
$$

$$
screenUV=positionNDC.xy/positionNDC.w
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
VertexPositionInputs p=GetVertexPositionInputs(input.positionOS.xyz);
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
