### 五个核心符号

1. **GetMainLight**：读取主光方向、颜色、距离衰减和阴影衰减的入口。
2. **GetAdditionalLight**：按索引读取影响当前对象或集群的附加光。
3. **Cluster Light Loop**：在Forward+中按屏幕集群遍历灯光的路径。
4. **GlobalIllumination**：组合Lightmap、Probe、反射探针和遮蔽的间接光。
5. **Light Cookie**：按光源空间采样Cookie纹理调制光照的模块。

## 生产者到消费者链

从GetMainLight和附加光循环进入LightingPhysicallyBased，再接GlobalIllumination与Cookie。对照Forward与Forward+关键字，记录灯索引来源和循环范围。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
direct=sum(BRDF*light*attenuation)
$$

$$
indirect=bakedGI+environmentReflection
$$

$$
final=direct+indirect+emission
$$

$$
lightLoop=f(rendererMode,cluster,objectList)
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
for(uint i=0;i<GetAdditionalLightsCount();i++) GetAdditionalLight(i,positionWS);
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。
