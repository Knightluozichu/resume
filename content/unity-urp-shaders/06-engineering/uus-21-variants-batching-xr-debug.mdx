### 五个核心符号

1. **Shader变体**：由multi_compile、shader_feature、平台和Renderer配置产生的编译版本。
2. **SRP Batcher**：按兼容常量布局持续驻留材质数据并减少CPU状态绑定的机制。
3. **DOTS Instancing**：从实体实例数据读取覆盖材质属性的Shader路径。
4. **XR宏**：支持单通道实例化、纹理数组、双眼索引和运动向量的宏合同。
5. **Debug Display**：用替换Shader和调试关键字可视化材质、光照、层与缓冲的系统。

## 生产者到消费者链

把正确性和工程成本放在同一验收：统计变体，检查UnityPerMaterial布局，测试DOTS实例属性、双眼纹理与运动向量，并用DebugReplacement和Frame Debugger解释每个Draw。 阅读顺序固定为资源入口、ShaderLab Properties与Pass、HLSL输入结构、核心函数、共享库、运行时Renderer选择。每个箭头都写明文件、符号、参数、关键字和目标缓冲。

$$
variants=product(keywordOptions)*platforms
$$

$$
cpuCost=f(SetPass,constantUploads)
$$

$$
instanceValue=DOTSOverride or materialDefault
$$

$$
proof=buildLog+frameCapture+XRBothEyes
$$

公式中的位置、方向、深度、颜色和索引必须标注空间、范围与来源。源码中能找到函数不证明它在当前变体执行，必须继续核对pragma、关键字、LightMode和Renderer配置。

## 最小源码探针

```hlsl
CBUFFER_START(UnityPerMaterial) float4 _BaseColor; CBUFFER_END
```

探针顺序是常量输出、输入结构可视化、核心函数分项、固定状态和目标缓冲。先确认实际Shader变体和Pass，再解释颜色或性能差异。

## 运行时互证

```text
source: commit + package path + symbol
material: shader + keywords + UnityPerMaterial layout
renderer: renderer asset + rendering path + pass event
frame: draw + LightMode + target + attachments
evidence: Frame Debugger + GPU capture + variant log
```

用Frame Debugger确认实际Pass和关键字，用GPU捕获确认RenderState、资源绑定、MRT与时序，用构建日志确认变体是否保留。修改包源码时还要记录嵌入包与上游提交的差异。

## 边界、兼容与性能

测试Forward与Deferred、主光与附加光、Lightmap与Probe、透明与Alpha Clip、XR单通道实例、动态分辨率、DOTS实例、不同图形API和移动Tile GPU。固定Unity版本、平台、分辨率、VSync和场景后再比较CPU/GPU时间。

```text
baseline: official commit 275a7f9ad933
candidate: exact local diff
correctness: image and buffer diff
compatibility: renderer modes, APIs, XR and platforms
performance: variants, SetPass, samples, bandwidth, CPU/GPU ms
failure: smallest replayable configuration
```

## 验收证书

证书包含提交、文件、符号、调用和include链、材质与关键字、Renderer配置、Pass事件、目标缓冲、GPU计时与失败反例。用MaterialPropertyBlock或不一致CBUFFER布局测试SRP Batcher，却把普通实例化与SRP Batcher混为同一种合批。 修复后必须重放同一配置，并指出静态源码和运行时事件各发生了什么变化。
