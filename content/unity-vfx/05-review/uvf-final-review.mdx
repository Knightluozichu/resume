## 直觉引入

全书从粒子系统出发，经过 Shader 特效、后处理、动画/物理驱动，最终汇聚到 UI 特效与战斗特效综合。回头看，每一层都是下一层的基础——没有粒子就没有素材，没有 Shader 就没有质感，没有驱动就没有节奏，没有综合就没有打击感。

总复习的目标不是记住每个技术点，而是建立「全链路」视野：从美术制作粒子素材，到 Shader 赋予质感，到后处理统一氛围，到动画/物理驱动触发，到 UI/战斗综合表现，每一步都不可或缺。

## 概念讲解

### 四大技术支柱

<Term def="模拟离散视觉元素的核心系统">粒子系统</Term>——素材层。
<Term def="控制表面渲染效果的 GPU 程序">Shader 特效</Term>——质感层。
<Term def="通过动画事件和物理碰撞触发特效">驱动系统</Term>——节奏层。
<Term def="将所有技术组合为完整玩家体验">综合应用</Term>——表现层。

### 技术协作链路

```
粒子系统 → Shader 特效 → 后处理 → 动画/物理驱动 → UI/战斗综合
  素材       质感         氛围       节奏           体验
```

### 工程化基础设施

| 设施 | 作用 |
|---|---|
| VfxManager | 统一管理特效播放/停止/查询 |
| 对象池 | 复用特效实例，消除 GC |
| ScriptableObject 配置表 | 数据与逻辑分离 |
| 事件系统 | 特效与游戏逻辑解耦 |
| LOD 系统 | 远距离降级优化 |

粒子预制体库（火/冰/雷/爆炸/烟雾）+ Shader 模板（溶解/发光/扭曲）+ 后处理 Volume 配置。建立项目的「特效素材库」，后续所有特效都从这里组合。
</Step>
<Step title="第三步：做战斗综合">
打击感系统（顿帧+震屏+音效统一管理）+ 连击系统（倍率曲线驱动）+ 动画事件框架（帧精确触发）。Profiler 验证每个特效的 CPU/GPU 开销，移动端建立特效预算表。
</Step>

## 代码对照

```csharp
using UnityEngine;
using System.Collections.Generic;

// 特效管理器：统一入口 + 对象池
public class VfxManager : MonoBehaviour
{
    public static VfxManager Instance;

    // 对象池：预制体 → 队列
    private Dictionary<GameObject, Queue<GameObject>> pools = new();

    // 播放特效（统一入口）
    public GameObject Play(GameObject prefab, Vector3 pos,
        Quaternion rot, float duration = -1)
    {
        var obj = GetFromPool(prefab);
        obj.transform.SetPositionAndRotation(pos, rot);
        obj.SetActive(true);
        obj.GetComponent<ParticleSystem>()?.Play();

        // 自动回收
        if (duration > 0)
            StartCoroutine(ReleaseAfter(prefab, obj, duration));

        return obj;
    }

    GameObject GetFromPool(GameObject prefab)
    {
        if (!pools.ContainsKey(prefab))
            pools[prefab] = new Queue<GameObject>();

        var queue = pools[prefab];
        if (queue.Count > 0)
            return queue.Dequeue();

        return Instantiate(prefab);
    }

    void ReturnToPool(GameObject prefab, GameObject obj)
    {
        obj.SetActive(false);
        pools[prefab].Enqueue(obj);
    }

    IEnumerator ReleaseAfter(GameObject prefab,
        GameObject obj, float delay)
    {
        yield return new WaitForSeconds(delay);
        ReturnToPool(prefab, obj);
    }

    // 停止某类特效
    public void StopAll(GameObject prefab)
    {
        if (!pools.ContainsKey(prefab)) return;
        foreach (var obj in pools[prefab])
        {
            var ps = obj.GetComponent<ParticleSystem>();
            if (ps) ps.Stop(true,
                ParticleSystemStopBehavior.StopEmitting);
        }
    }
}
```

## 常见误区

<Callout type="trap">
**现象 →** 项目后期特效越来越多，帧率越来越低，不知道哪里该优化。
**原因 →** 没有在前期建立特效预算表和 Profiler 基线，盲目添加特效。
**修法 →** 1）建立特效预算表——每个场景最大同时存在粒子数限制（如移动端5000）；2）Profiler 验证每个特效的 CPU（模拟耗时）和 GPU（Overdraw）开销；3）分级策略——近距离全特效，中距离减半，远距离只留关键特效；4）定期做回归测试——新增特效后跑 Profiler 对比基线，帧率下降超过5%就审查。
</Callout>

## 练习

<Exercises>
**问题**：如果让你为一个新项目搭建特效系统，你会如何规划技术路线和开发流程？

<Answer>
1）前期规划：确定目标平台（PC/移动端）决定技术上限，确定美术风格决定 Shader 方向。2）基础搭建：VfxManager+对象池框架、ScriptableObject 配置表、特效命名规范和目录结构。3）核心特效制作：粒子预制体库、Shader 模板（溶解/发光/扭曲）、后处理 Volume 配置。4）驱动层：AnimationEvent 框架、物理碰撞特效自动生成。5）战斗综合：打击感系统（顿帧+震屏+音效）、连击系统。6）优化：Profiler 验证、移动端特效预算表、LOD 分级。关键原则：先搭框架再填内容，先保证性能再追求效果，所有特效走数据驱动。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="VfxManager">统一管理特效播放、停止、查询的管理器，所有特效调用走此入口，配合对象池消除 GC。</GlossaryItem>
<GlossaryItem term="特效预算表">每个场景允许的最大特效资源消耗（粒子数、DrawCall、GPU 带宽），用于控制性能不超标。</GlossaryItem>
<GlossaryItem term="视觉优先">先确定想要的视觉效果，再选技术实现的开发原则。效果不够用「视觉欺骗」补偿（如贴图动画替代实时模拟）。</GlossaryItem>
<GlossaryItem term="特效 LOD">根据距离分级降低特效质量的策略，近处全特效、中处减半、远处只留关键元素，控制性能开销。</GlossaryItem>
</Glossary>
