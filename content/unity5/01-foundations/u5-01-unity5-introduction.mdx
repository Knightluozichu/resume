## 核心模型与不可变条件

从引擎定位、版本优势、安装许可和编辑器界面建立后续 TPS 项目的统一工作环境。 主链为：**引擎定位 → 版本能力 → 安装许可 → 项目创建 → 编辑器视图 → 可运行场景**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**所有界面和安装步骤都必须落到可复现项目、明确 Unity 版本与可验证的场景编辑结果。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-01-unity5-introduction",
  "bookPages": "1-34",
  "chain": ["引擎定位","版本能力","安装许可","项目创建","编辑器视图","可运行场景"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=引擎定位 -> 版本能力 -> 安装许可 -> 项目创建 -> 编辑器视图 -> 可运行场景
PASS invariant=所有界面和安装步骤都必须落到可复现项目、明确 Unity 版本与可验证的场景编辑结果。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  只背窗口名称和快捷键，却无法新建、保存、运行项目，也说不清场景、游戏和项目视图各自的数据边界。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
