## 问题：怎样证明掌握的是原书项目，而不是背过一组 Unity API？

## 核心模型与不可变条件

先确定 TPS 的交付顺序，再创建项目、配置脚本环境、组织 Project 视图并导入角色与商店资源。 主链为：**游戏范围 → 开发顺序 → 新建项目 → IDE配置 → 资源组织 → 角色导入**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**导入资源必须保留目录、依赖、许可证和版本信息，项目结构必须让后续场景与脚本引用稳定。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-02-project-preparation",
  "bookPages": "35-48",
  "chain": ["游戏范围","开发顺序","新建项目","IDE配置","资源组织","角色导入"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=游戏范围 -> 开发顺序 -> 新建项目 -> IDE配置 -> 资源组织 -> 角色导入
PASS invariant=导入资源必须保留目录、依赖、许可证和版本信息，项目结构必须让后续场景与脚本引用稳定。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```
