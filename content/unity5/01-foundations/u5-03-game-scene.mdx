## 核心模型与不可变条件

用模型、纹理、材质、Standard Shader、光源和天空盒构成 TPS 场景的几何与视觉基线。 主链为：**3D模型 → 纹理导入 → 材质 → PBR通道 → 光照 → 天空盒**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**场景外观必须由可追溯模型、材质参数、光源和天空配置共同决定，不能依赖丢失引用或编辑器临时状态。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-03-game-scene",
  "bookPages": "49-76",
  "chain": ["3D模型","纹理导入","材质","PBR通道","光照","天空盒"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=3D模型 -> 纹理导入 -> 材质 -> PBR通道 -> 光照 -> 天空盒
PASS invariant=场景外观必须由可追溯模型、材质参数、光源和天空配置共同决定，不能依赖丢失引用或编辑器临时状态。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  把纹理直接当材质、把法线图按颜色图导入，或用环境曝光掩盖缺失光源，导致目标机外观完全不同。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
