## 核心模型与不可变条件

围绕 Rigidbody、Collider、碰撞事件、Tag、发射逻辑、轨迹、粒子、爆炸、音频和枪口火焰完成武器反馈。 主链为：**输入发射 → 子弹生成 → 刚体运动 → 碰撞感知 → 伤害结算 → 视听反馈**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**子弹命中、伤害、生命周期和视听效果必须由同一次发射事件关联，不能因帧率或对象复用重复结算。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-05-projectile-effects",
  "bookPages": "119-170",
  "chain": ["输入发射","子弹生成","刚体运动","碰撞感知","伤害结算","视听反馈"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=输入发射 -> 子弹生成 -> 刚体运动 -> 碰撞感知 -> 伤害结算 -> 视听反馈
PASS invariant=子弹命中、伤害、生命周期和视听效果必须由同一次发射事件关联，不能因帧率或对象复用重复结算。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  只播放爆炸特效却没有唯一命中结算，或高速子弹穿过 Collider 后仍生成声音与粒子，造成证据与玩法脱节。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
