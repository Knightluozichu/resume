## 核心模型与不可变条件

用 Mecanim、NavMesh、AI 状态、攻击受击、血迹、层碰撞、事件和死亡处理构成完整敌人生命周期。 主链为：**模型与Avatar → Animator → NavMesh追击 → AI决策 → 战斗反馈 → 死亡清理**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**敌人的导航、动画、攻击、受击与死亡状态必须单向可解释，任何事件只能在合法状态结算一次。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-06-enemy-character",
  "bookPages": "171-235",
  "chain": ["模型与Avatar","Animator","NavMesh追击","AI决策","战斗反馈","死亡清理"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=模型与Avatar -> Animator -> NavMesh追击 -> AI决策 -> 战斗反馈 -> 死亡清理
PASS invariant=敌人的导航、动画、攻击、受击与死亡状态必须单向可解释，任何事件只能在合法状态结算一次。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  动画事件、碰撞和 AI Update 同时触发伤害，敌人死亡后仍寻路攻击，或对象销毁前留下未解绑事件。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
