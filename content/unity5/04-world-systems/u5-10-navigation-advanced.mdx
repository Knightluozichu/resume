## 核心模型与不可变条件

用动态障碍、Off-Mesh Link 和自定义链接补足烘焙 NavMesh 无法表达的运行时通行关系。 主链为：**烘焙NavMesh → 动态障碍 → 链接端点 → 代理进入 → 特殊移动 → 重新落网**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**导航链接必须保持入口出口、方向、代价、动画和失败恢复一致，动态障碍不能让代理永久卡死。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-10-navigation-advanced",
  "bookPages": "329-336",
  "chain": ["烘焙NavMesh","动态障碍","链接端点","代理进入","特殊移动","重新落网"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=烘焙NavMesh -> 动态障碍 -> 链接端点 -> 代理进入 -> 特殊移动 -> 重新落网
PASS invariant=导航链接必须保持入口出口、方向、代价、动画和失败恢复一致，动态障碍不能让代理永久卡死。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```
