## 核心模型与不可变条件

为静态几何准备 Lightmap UV 并烘焙光照，再用 Light Probe Group 为动态角色提供间接光采样。 主链为：**Lightmap UV → 静态标记 → 光照设置 → 烘焙贴图 → Light Probe → 动态对象采样**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**烘焙输出必须对应当前场景几何、静态标记、UV、光源和质量设置，动态对象的探针采样应连续。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

  "normal": true,

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  修改墙体或光源后继续使用旧烘焙数据，或把探针全放在地面，角色上半身出现明显错误光照。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
