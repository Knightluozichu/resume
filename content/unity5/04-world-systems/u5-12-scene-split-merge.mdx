## 核心模型与不可变条件

按所有权和加载边界拆分大型场景，再通过 Additive 加载、共享坐标和依赖合同组合运行世界。 主链为：**世界边界 → 场景分离 → 共享依赖 → Additive加载 → 初始化 → 反向卸载**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**拆分前后对象 GUID、世界坐标、光照、导航、事件、初始化顺序和卸载责任必须一致。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-12-scene-split-merge",
  "bookPages": "353-360",
  "chain": ["世界边界","场景分离","共享依赖","Additive加载","初始化","反向卸载"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=世界边界 -> 场景分离 -> 共享依赖 -> Additive加载 -> 初始化 -> 反向卸载
PASS invariant=拆分前后对象 GUID、世界坐标、光照、导航、事件、初始化顺序和卸载责任必须一致。
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  把共同依赖复制进多个场景，合并后出现重复管理器、灯光、EventSystem 或跨场景引用丢失。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
