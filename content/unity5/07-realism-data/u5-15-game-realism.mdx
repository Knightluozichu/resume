## 核心模型与不可变条件

用 Ragdoll 处理角色死亡后的物理反馈，用 ScreenPointToRay、Touch 和 Unity Remote 4 完成触屏移动。 主链为：**动画姿态 → 布娃娃切换 → 碰撞受力 → 触点采样 → 屏幕射线 → 角色移动**。每一节点只消费前一节点已经验证的对象、状态或事件，不能从最终表现反推中间过程一定正确。

本页不可变条件是：**动画到布娃娃的切换必须保持姿态和碰撞一致，触屏输入必须基于触点阶段、相机射线与目标平面稳定解释。** 任何“看起来能跑”的结果都必须经过重复加载、异常输入和边界时序检验。

## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-15-game-realism",
  "bookPages": "559-582",
  "chain": ["动画姿态","布娃娃切换","碰撞受力","触点采样","屏幕射线","角色移动"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=动画姿态 -> 布娃娃切换 -> 碰撞受力 -> 触点采样 -> 屏幕射线 -> 角色移动
PASS invariant=动画到布娃娃的切换必须保持姿态和碰撞一致，触屏输入必须基于触点阶段、相机射线与目标平面稳定解释。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  同时启用 Animator 和布娃娃刚体导致骨骼争夺，或把屏幕像素直接当世界坐标导致不同设备移动方向错误。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
