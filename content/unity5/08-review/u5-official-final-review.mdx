## 可执行实现骨架

脚本边界显式保存状态，避免展示层直接决定玩法结果：

```csharp
using UnityEngine;

public sealed class ChapterController : MonoBehaviour
{
    [SerializeField] GameObject target;
    bool completed;

    public void ExecuteOnce()
    {
        if (completed || target == null) return;
        completed = true;
        ApplyChapterResult(target);
    }
}
```

测试记录必须能回到具体对象与事件：

```json
{
  "chapter": "u5-official-final-review",
  "bookPages": "1-586",
  "chain": ["冻结项目版本","运行单机TPS","注入战斗失败","验证网络重连","核对排名数据","完整签发"],
  "unity": "5.x-pinned",
  "scene": "fixed-tps-checkpoint",
  "normal": true,
  "boundary": true,
  "failureReplay": true
}
```

签发输出同时保留通过值与拒绝原因：

```text
PASS context=version+scene+prefab+input
PASS chain=冻结项目版本 -> 运行单机TPS -> 注入战斗失败 -> 验证网络重连 -> 核对排名数据 -> 完整签发
PASS invariant=每一章都要保留正常、边界与失败样本，历史网络 API 只能作为原书复现，不能冒充当前生产推荐。
REJECT duplicate-event | stale-object | changed-scene | missing-cleanup
```

## 两个必须主动制造的失败样本

<Callout type="trap" title="项目主链在中间节点断裂">
  单章示例都能运行，却无法组合成完整场景；网络、对象池和事件在重载或重连后产生重复对象和错误状态。 保存错误状态、事件顺序和首个偏离对象，再恢复相同场景与输入复验。
</Callout>

<Callout type="trap" title="历史 API 被误当成现代生产方案">
  原书内置网络、旧输入或旧动画接口可以用于理解目录，但迁移时必须标注已废弃边界、替代方案和行为差异；不能把示例能运行当成现代上线依据。
</Callout>
