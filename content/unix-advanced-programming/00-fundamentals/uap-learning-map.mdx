## 直觉引入

把 UNIX 系统编程想象成一个「邮局系统」。你写的一封信（数据）要经过多道工序：首先你要在窗口排队领取一个「信箱号」（文件描述符，第2章）；写信时你要知道收信人的「地址信息」（文件与目录，第3章）；邮局内部有多个「分拣员」（进程，第5章）同时工作；分拣员之间用「对讲机」（信号，第6章）和「传送带」（IPC，第7章）协调；一个分拣员可以长出「多只手」（线程，第8章）同时处理多封信；当信件量暴增时，需要「智能分拣系统」（epoll高级I/O，第9章）同时监控上千个信箱。

## 六阶段递进

<Term def="一切皆文件是UNIX的核心设计哲学——将普通文件、设备、管道、套接字统一为文件描述符接口，用open/read/write/close操作一切。">一切皆文件</Term>是贯穿全书的主线。全书可以拆成六个递进阶段。**文件I/O基础**解决「怎么读写」——open/read/write/close和文件描述符。**文件与目录及进程环境**解决「怎么管理」——stat获取文件属性、目录遍历、进程内存布局与启动。**进程控制与信号**解决「怎么创建进程」和「怎么响应异步」——fork/exec/wait和信号处理。**进程间通信与线程**解决「怎么协作」和「怎么并发」——管道/共享内存/互斥锁/条件变量。**高级I/O**解决「怎么做高性能并发」——select/poll/epoll和非阻塞I/O。

```text
// 「一次Web服务器并发请求」——UNIX系统编程全程参与的数据流

// 1. 文件I/O（第2章）：创建监听socket
//    socket() -> 返回 listen_fd
//    accept(listen_fd) -> 返回 conn_fd（新连接）
//    read(conn_fd, buf, 4096) -> 读取HTTP请求
//    write(conn_fd, response, n) -> 发送HTTP响应

// 2. 文件与目录（第3章）：获取静态文件信息
//    stat("/var/www/index.html", &st)
//    -> st.st_size 获取文件大小
//    -> st.st_mode 检查文件类型和权限

// 3. 进程环境（第4章）：读取环境配置
//    getenv("DOCUMENT_ROOT") -> 获取网站根目录
//    getenv("SERVER_PORT") -> 获取监听端口

// 4. 进程控制（第5章）：fork处理并发
//    fork() -> 子进程处理单个请求
//    父进程继续 accept() 等待新连接
//    waitpid(-1, &status, WNOHANG) -> 回收僵尸子进程

// 5. 信号（第6章）：处理异步事件
//    SIGCHLD -> 子进程退出通知 -> 回收僵尸
//    SIGPIPE -> 客户端断连 -> 忽略或关闭fd
//    SIGTERM -> 优雅关闭 -> 停止accept, 等待处理完成

// 6. IPC（第7章）：多进程共享数据
//    pipe(fd) -> 父子进程通信
//    mmap(MAP_SHARED) -> 共享内存存储连接计数

// 7. 线程（第8章）：多线程并发
//    pthread_create -> 工作线程处理请求
//    pthread_mutex_lock -> 保护共享连接队列
//    pthread_cond_signal -> 通知工作线程有新请求

// 8. 高级I/O（第9章）：epoll高并发
//    epoll_create() -> 创建epoll实例
//    epoll_ctl(EPOLL_CTL_ADD, fd) -> 注册连接
//    epoll_wait(events, MAX, -1) -> 等待就绪事件
//    非阻塞read/write处理就绪连接
```

## 常见误区

<Callout type="trap">
**误区：会用系统调用就等于懂UNIX编程。** 会写 `open`、`fork`、`pthread_create` 只是「会用API」——照着man page抄就能做。真正懂UNIX编程的人能解释：为什么fork用COW而非完全复制（避免无用拷贝）、为什么SIGKILL不可被捕获（系统需要强制手段）、为什么epoll比select快（内核维护就绪表O(1)vs O(n)遍历）、为什么管道用fd而非路径名（效率+统一接口）。把UNIX当黑盒的人遇到EAGAIN只能查文档；懂机制的人知道这是非阻塞I/O的正常返回，知道如何配合epoll使用。区分标志：能否解释「UNIX为什么这样设计」而非只是「能编译它」。
</Callout>

<Exercises>
**问题 1**：全书六阶段递进是什么？为什么是这个顺序？

<Answer>
文件I/O → 文件与目录及进程环境 → 进程控制与信号 → 进程间通信与线程 → 高级I/O → 全书复习。顺序由依赖关系决定：先掌握文件描述符和基本I/O操作（这是UNIX「一切皆文件」的基础），再理解文件属性和进程的内存布局与启动流程；进程是UNIX编程核心对象，需先掌握fork/exec/wait创建与控制；信号是进程间异步通信的基础机制；IPC和线程解决多任务协作与并发；高级I/O解决高并发场景的性能问题。先「会读写文件」，再「管理进程」，然后「处理异步事件」，接着「进程间协作」，再「多线程并发」，最后「高性能I/O」。
</Answer>

**问题 2**：用「一次Web服务器并发请求」描述全书主线。

<Answer>
一次Web请求经过全书多个知识点：①文件I/O（第2章）——socket()创建fd，accept()返回新fd，read/write收发数据；②文件与目录（第3章）——stat()获取请求文件大小和权限；③进程环境（第4章）——getenv读取配置环境变量；④进程控制（第5章）——fork()创建子进程处理请求，waitpid回收僵尸；⑤信号（第6章）——SIGCHLD回收子进程，SIGPIPE处理客户端断连；⑥IPC（第7章）——共享内存存储连接计数；⑦线程（第8章）——pthread_create创建工作线程，互斥锁保护共享数据；⑧高级I/O（第9章）——epoll单线程管理数万连接。一条数据流，全书知识点全部参与。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="一切皆文件">UNIX核心设计哲学。将普通文件、目录、设备、管道、套接字统一为文件描述符接口，用open/read/write/close操作一切。使API统一、工具可组合、I/O多路转接通用。是APUE全书基础。</GlossaryItem>
<GlossaryItem term="六阶段递进">文件I/O → 文件与目录及进程环境 → 进程控制与信号 → IPC与线程 → 高级I/O → 全书复习。每层解决前一层的遗留问题：I/O解决「怎么读写」，进程环境解决「怎么运行」，进程控制解决「怎么创建」，信号解决「怎么响应异步」，IPC解决「怎么通信」，线程解决「怎么并发」，高级I/O解决「怎么高性能」。</GlossaryItem>
<GlossaryItem term="文件描述符">非负整数，是进程已打开文件的索引。fd 0/1/2默认分配给stdin/stdout/stderr。fork后子进程继承父进程的fd表，共享file对象。是「一切皆文件」的实现基础。</GlossaryItem>
<GlossaryItem term="系统调用与库函数">系统调用是内核提供的接口（open/read/write），在内核态执行；库函数是C库提供的封装（fopen/fread/fwrite），在用户态执行，底层调用系统调用。标准I/O库在用户空间有缓冲，不带缓冲I/O每次都是系统调用。</GlossaryItem>
</Glossary>
