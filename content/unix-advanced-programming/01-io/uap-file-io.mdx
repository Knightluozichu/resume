## 函数签名与返回值

```c
// open —— 打开或创建文件
int open(const char *path, int oflag, ... /* mode_t mode */);
// 返回: 成功返回最小可用fd, 出错返回-1
// oflag: O_RDONLY | O_WRONLY | O_RDWR (三选一)
//        | O_CREAT(不存在则创建)
//        | O_TRUNC(截断为0)
//        | O_APPEND(追加写)
//        | O_NONBLOCK(非阻塞)
//        | O_CLOEXEC(exec时自动关闭)

// read —— 从fd读数据
ssize_t read(int fd, void *buf, size_t nbytes);
// 返回: >0 读取字节数; 0 已到EOF; -1 出错

// write —— 向fd写数据
ssize_t write(int fd, const void *buf, size_t nbytes);
// 返回: >0 写入字节数(可能<nbytes); -1 出错

// lseek —— 设置文件偏移量
off_t lseek(int fd, off_t offset, int whence);
// whence: SEEK_SET(从头) | SEEK_CUR(当前位置) | SEEK_END(从尾)
// 返回: 新的文件偏移量; -1 出错
// 可用lseek(fd, 0, SEEK_CUR)获取当前偏移量

// close —— 关闭fd, 释放资源
int close(int fd);
// 返回: 0成功; -1出错
// close可能延迟写入(dirty page由内核异步刷盘)
```

## 文件共享模型

```text
// 进程A fork 出进程B, 共享同一文件
// 三级间接寻址:

进程A的fd表          file对象(共享)        inode(共享)
  fd 3 ──────────>  f_pos = 100    ────>  i_size = 4096
                    f_mode = RDONLY        i_blocks = 8
                    f_count = 2            i_fop = ...
                      │
进程B的fd表            │
  fd 3 ──────────────┘  (指向同一个file对象)

// 关键: f_pos(偏移量)是共享的!
// 进程A read 100字节后 f_pos = 200
// 进程B read 会从 200 开始读(不是100)

// 如果两个进程各自open同一文件:
进程A的fd表          file对象A             inode(共享)
  fd 3 ──────────>  f_pos = 100    ────>  i_size = 4096
                                        i_fop = ...

进程B的fd表          file对象B             inode(共享)
  fd 3 ──────────>  f_pos = 0      ────>  (同一个inode)
                    f_count = 1

// 关键: 各自有独立的f_pos!
// 两个进程的读写位置互不影响
```

## dup与重定向

```c
// dup —— 复制fd, 返回最小可用fd
int newfd = dup(oldfd);
// oldfd=3, 最小可用fd=4 → newfd=4
// newfd和oldfd指向同一个file对象, 共享f_pos

// dup2 —— 复制fd到指定fd
int dup2(int oldfd, int newfd);
// dup2(3, 1) → fd 1(stdout)现在指向fd 3的文件
// 标准输出重定向! printf的输出会写到fd 3的文件

// shell重定向原理: ls > file.txt
// 1. fork子进程
// 2. 子进程: open("file.txt", O_WRONLY) → fd=3
// 3. 子进程: dup2(3, 1) → stdout指向file.txt
// 4. 子进程: close(3) → 不需要了
// 5. 子进程: exec("ls") → ls的printf写到file.txt

// fcntl也能复制fd:
// fcntl(oldfd, F_DUPFD, 0) 等价于 dup(oldfd)
// fcntl(oldfd, F_DUPFD_CLOEXEC, 0) 带CLOEXEC的复制
```

<Callout type="info">
**不带缓冲的I/O：** APUE第3章的read/write每次调用都是一次系统调用，用户空间无额外缓冲。而标准I/O库（fread/fwrite）在用户空间有缓冲区，缓冲满或fflush时才调用write系统调用。标准I/O底层最终调用不带缓冲I/O。选择原则：需要精确控制I/O时机用不带缓冲，追求吞吐量用标准I/O。
</Callout>

<Exercises>
**问题 1**：read返回0和返回-1分别意味着什么？

<Answer>
read返回0表示已到文件末尾（EOF），不是错误——这是循环读取的终止条件。read返回-1表示出错，具体错误码在errno中：EAGAIN表示非阻塞模式下无数据可读（不是真正的错误），EINTR表示被信号中断（可重试），EBADF表示fd无效。正确处理模式：循环read直到返回0（EOF），返回-1时检查errno决定是重试（EINTR）还是真正的错误。
</Answer>

**问题 2**：fork后父子进程共享file对象意味着什么？有什么实际用途和陷阱？

<Answer>
fork后子进程继承父进程的fd表副本，fd指向同一个file对象——共享文件偏移量（f_pos）和状态标志。实际用途：①shell重定向——父进程open后fork，子进程继承fd实现重定向；②管道——pipe创建fd后fork，父子通过共享fd通信。陷阱：①偏移量共享——父子同时写同一fd会数据交错，需要同步；②引用计数——close只是减f_count，所有引用关闭才真正释放；③close-on-exec——不设FD_CLOEXEC的话exec后fd仍打开。正确做法：fork后父子各关不需要的fd端。
</Answer>

<Glossary>
<GlossaryItem term="文件描述符">非负整数，是进程已打开文件的索引。fd 0/1/2预留给stdin/stdout/stderr。POSIX保证每次open分配最小可用fd。</GlossaryItem>
<GlossaryItem term="file对象">内核中表示「一个进程打开的一个文件」的结构。包含f_pos（偏移量）、f_mode（模式）、f_op（操作集）、f_count（引用计数）。fork后父子共享同一个file对象。</GlossaryItem>
<GlossaryItem term="不带缓冲的I/O">APUE第3章的open/read/write/close。每个调用都是一次系统调用，用户空间无额外缓冲。与标准I/O（fread/fwrite有用户缓冲）相对。</GlossaryItem>
<GlossaryItem term="dup2重定向">dup2(oldfd, newfd)将newfd指向oldfd的file对象。shell重定向的原理：fork后子进程dup2(file_fd, 1)将stdout指向文件，再exec命令。</GlossaryItem>
</Glossary>
