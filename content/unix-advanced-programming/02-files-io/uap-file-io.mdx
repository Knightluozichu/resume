## 机制、所有权与失败模型

沿open/read/write/lseek/close追踪描述符表、打开文件表项、文件偏移、共享与原子操作。

本页核心不变量是：**成功字节数、部分读写、EINTR、偏移共享和持久化语义都显式处理；每个描述符恰好关闭一次。** 它必须同时约束正常、边界、故障和恢复样本。接口返回成功只是证据之一，还要检查短计数、EINTR/EAGAIN、对象继承、并发时序、缓冲与异步清理。

实验台账至少包含平台与版本、编译宏、入口参数、对象所有者、描述符或ID、预期返回、实际返回、errno、首个状态分叉、原始轨迹和清理结果十一列。性能样本还需固定预热、CPU放置、输入规模、采样窗口与分位数；信号/线程样本必须记录掩码、取消状态和处理上下文。

验证时只改变一个长度、容量、时序、权限、信号或失败点，并在进入“打开对象”前停住第一条返回值、errno、系统调用轨迹、对象计数或状态分叉。最后关闭描述符、回收进程/线程、删除命名对象并恢复终端或信号掩码；同输入重放回到基线，结论才成立。

## 常见误区

<Callout type="trap">
  **误区一：**
  只检查最终输出，不检查短计数、errno、对象继承、信号掩码和并发时序。
</Callout>

<Callout type="trap">
  **误区二：**
  把Linux当前行为当成POSIX保证，或在失败路径遗漏描述符、线程、IPC名字和终端属性的清理。
</Callout>

## 四类样本与验收

| 样本 | 只改变什么                 | 必查证据                  | 通过条件   |
| ---- | -------------------------- | ------------------------- | ---------- |
| 基线 | 平台、宏与固定输入         | 返回值、errno、对象与轨迹 | 与预测一致 |
| 边界 | 长度、容量、权限或时序     | 短计数、拒绝或阻塞点      | 边界可解释 |
| 故障 | 一个信号、断开或失败注入   | 首错与责任层              | 故障可定位 |
| 恢复 | 关闭、回收、删除与属性还原 | 残留对象和同输入重放      | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第3章 文件I/O？

<Answer>
  最终输出会隐藏部分读写、EINTR、描述符泄漏、进程/线程未回收、缓冲和竞态。必须同时核对标准边界、接口合同、对象生存期、首个状态分叉和恢复结果。
</Answer>

**问题 2** 如何把“移动偏移”变成运行证据？

<Answer>
  固定平台、功能测试宏、工具和输入，先预测文件描述符与打开文件描述的返回值、errno、所有权和状态，只改变一个条件并停在首错。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  成功字节数、部分读写、EINTR、偏移共享和持久化语义都显式处理；每个描述符恰好关闭一次。
  关闭全部对象并恢复属性后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
