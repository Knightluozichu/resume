## 内存段详解

```text
// 进程虚拟地址空间 (高地址 → 低地址)

高地址
┌───────────────────┐
│ 命令行参数 argv    │  argv[0]..argv[argc-1], NULL
├───────────────────┤
│ 环境变量 environ   │  PATH=/bin  HOME=/home  ...
├───────────────────┤ ← 栈底(高地址)
│ 栈 Stack          │  局部变量/函数帧/返回地址
│    ↓ 向下增长      │  malloc不会分配这里
│                   │
│    ↑ 空闲空间      │  栈和堆之间的可扩展区域
│                   │
│ 堆 Heap           │  malloc/calloc/realloc分配
│    ↑ 向上增长      │  brk/sbrk系统调用扩展
├───────────────────┤
│ BSS段             │  未初始化的全局/静态变量
│                   │  内核自动清零
├───────────────────┤
│ 数据段 Data       │  已初始化的全局/静态变量
│                   │  如: int g = 42;
├───────────────────┤
│ 正文段 Text       │  CPU执行的机器指令
│                   │  只读, 可共享(多进程共享一份)
└───────────────────┘ ← 低地址

// 验证: size a.out 命令显示各段大小
// text  data  bss  dec  hex  filename
// 1234   567   89  1890 762  a.out
```

## 启动流程

```c
// 从 execve 到 main 的完整启动链

// 1. execve(path, argv, envp)
//    内核加载ELF到内存, 设置各段, 压入argv/envp到栈
//    设置入口地址为 _start (ELF header中的e_entry)

// 2. _start (汇编, C运行时入口)
//    - 清零寄存器
//    - 设置栈指针
//    - 调用 __libc_start_main

// 3. __libc_start_main
//    - 设置 environ 指针 (指向栈上的环境变量)
//    - 注册 atexit 退出处理 (包括stdio的flush)
//    - 初始化线程局部存储(TLS)
//    - 调用 .init 段的构造函数 (如有)
//    - 调用 main(argc, argv, envp)

// 4. main 返回后:
//    __libc_start_main 调用 exit(main_return_value)

// 5. exit(status)
//    - 逆序调用 atexit 注册的函数
//    - flush 所有标准I/O流 (fclose所有FILE*)
//    - 删除 tmpfile 创建的临时文件
//    - 调用 _exit(status)

// 6. _exit(status) — 系统调用
//    - 关闭所有打开的fd (内核自动)
//    - 释放内存 (内核自动)
//    - 向父进程发送 SIGCHLD
//    - 保存退出状态供父进程 waitpid 获取
```

## 环境变量操作

```c
// 环境变量存储在进程内存高地址, 以 environ 指针数组访问
extern char **environ;  // 每个元素指向 "NAME=value" 字符串

// getenv —— 查找环境变量
char *val = getenv("HOME");  // 返回 "/home/user"
// 注意: 返回的是指向environ中的指针, 不要free!

// setenv —— 设置环境变量 (安全, 内部拷贝字符串)
int ret = setenv("MYVAR", "hello", 1);
// 第4参数 overwrite: 0=不覆盖已有, 1=覆盖

// putenv —— 设置环境变量 (不拷贝, 直接用传入的字符串)
int ret = putenv("MYVAR=hello");
// 危险: 后续修改这个字符串会影响环境变量!
// 字符串成为environ的一部分

// unsetenv —— 删除环境变量
int ret = unsetenv("MYVAR");

// 环境变量在fork时被子进程继承
// execve可以指定新的环境变量(envp参数)
// exec系列函数默认继承当前环境
```

<Callout type="info">
**exit与_exit的区别：** exit是C库函数，执行清理（atexit函数逆序调用、flush标准I/O流、删除临时文件）后调用_exit。_exit是系统调用，直接进入内核终止进程。main函数return等价于调用exit。在信号处理函数中不应调用exit（stdio可能不一致），应调用_exit。vfork的子进程也必须用_exit退出（不能用exit，因为共享父进程地址空间，exit的flush会破坏父进程的stdio状态）。
</Callout>

<Exercises>
**问题 1**：C程序内存布局分为哪几个段？BSS和Data段有什么区别？

<Answer>
从高到低：命令行参数和环境变量 → 栈（向下增长）→ 堆（向上增长）→ BSS段 → 数据段 → 正文段。BSS段存放未显式初始化的全局/静态变量，内核加载时自动清零；Data段存放已赋初值的全局/静态变量。例如 `int g;` 在BSS段（初值0），`int g = 42;` 在Data段。正文段存放CPU执行的机器指令，通常只读且可被多个进程共享。
</Answer>

**问题 2**：从execve到main之间发生了什么？为什么说main不是程序第一个执行的函数？

<Answer>
execve由内核加载ELF到内存，设置各段并压入argv/envp到栈，入口设为_start。_start是C运行时的汇编入口，设置栈和寄存器后调用__libc_start_main。__libc_start_main执行初始化：设置environ指针、注册atexit退出处理、初始化TLS、调用构造函数，最后才调用main。main返回后__libc_start_main调用exit，exit执行清理后调用_exit进入内核。C运行时在main之前做了大量初始化工作（stdio、TLS、atexit注册等），所以main不是第一个执行的函数。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="进程内存布局">从高到低：argv/environ → 栈 → 堆 → BSS → Data → Text。栈向下增长存局部变量，堆向上增长存malloc分配，BSS存未初始化全局变量（自动清零），Data存已初始化全局变量，Text存机器指令（只读共享）。</GlossaryItem>
<GlossaryItem term="exit vs _exit">exit是C库函数，执行atexit清理+flush stdio+删除临时文件后调用_exit。_exit是系统调用，直接进入内核终止进程。信号handler中用_exit，vfork子进程也用_exit。</GlossaryItem>
<GlossaryItem term="atexit">注册在exit时自动调用的清理函数，最多32个，按注册逆序执行。用于资源释放（关闭文件、释放全局资源）。main返回后也会触发atexit函数。</GlossaryItem>
<GlossaryItem term="环境变量">存储在进程内存高地址区域，以environ指针数组访问。getenv查找、setenv安全设置（拷贝）、putenv不安全设置（不拷贝）、unsetenv删除。fork时继承。</GlossaryItem>
</Glossary>
