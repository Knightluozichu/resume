## 一次Web请求的完整旅程

```text
// === 服务器启动阶段 ===

// 第2章 文件I/O: 创建监听socket
int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
// socket()返回fd — 「一切皆文件」的体现
bind(listen_fd, (struct sockaddr*)&addr, sizeof(addr));
listen(listen_fd, 128);

// 第9章 高级I/O: 用epoll管理连接
int epfd = epoll_create1(0);
struct epoll_event ev = { .events = EPOLLIN, .data.fd = listen_fd };
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);

// === 接受连接阶段 ===

// 第9章: epoll_wait等待事件
struct epoll_event events[64];
int nready = epoll_wait(epfd, events, 64, -1);

for (int i = 0; i < nready; i++) {
  if (events[i].data.fd == listen_fd) {
    // 第2章: accept返回新连接fd
    int conn_fd = accept(listen_fd, NULL, NULL);
    // 第9章: 注册新连接到epoll, 非阻塞+ET
    set_nonblock(conn_fd);
    ev.events = EPOLLIN | EPOLLET;
    ev.data.fd = conn_fd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, conn_fd, &ev);
  } else {
    // 第2章: 读取HTTP请求
    int conn_fd = events[i].data.fd;
    char buf[4096];

    // 第9章: ET模式循环读取
    while (1) {
      ssize_t n = read(conn_fd, buf, sizeof(buf));
      if (n > 0) {
        // 处理请求数据
      } else if (n == 0) {
        close(conn_fd);  // 客户端关闭
        break;
      } else if (errno == EAGAIN) {
        break;  // 数据读完
      }
    }

    // === 请求处理阶段 ===

    // 第3章: 解析请求, 获取文件信息
    struct stat st;
    if (stat(filename, &st) == 0 && S_ISREG(st.st_mode)) {
      // 第4章: 读取环境配置
      char *root = getenv("DOCUMENT_ROOT");

      // 第9章: 零拷贝发送文件
      int file_fd = open(filename, O_RDONLY);
      sendfile(conn_fd, file_fd, NULL, st.st_size);
      close(file_fd);
    }
  }
}
```

## 并发模型对比

```text
// 模型1: 多进程fork + 阻塞I/O (经典Apache模式)
// 优势: 编程简单, 进程隔离强, 利用多核
// 劣势: 每连接一个进程, 资源消耗大, 切换开销重
// 适用: 连接数少, 计算密集

while (1) {
  int conn_fd = accept(listen_fd, NULL, NULL);
  pid_t pid = fork();
  if (pid == 0) {           // 子进程
    close(listen_fd);       // 不需要监听fd
    handle_request(conn_fd); // 阻塞I/O处理
    close(conn_fd);
    _exit(0);
  }
  close(conn_fd);           // 父进程不需要连接fd
  // 第6章: SIGCHLD回收僵尸
  // signal(SIGCHLD, handler) → waitpid(WNOHANG)
}

// 模型2: 单线程epoll + 非阻塞I/O (Nginx模式)
// 优势: 单线程管理数万连接, 无锁无同步, 内存效率高
// 劣势: 编程复杂(异步事件驱动), 不能利用多核
// 适用: 高并发, I/O密集

// 主循环:
while (1) {
  int n = epoll_wait(epfd, events, MAX_EVENTS, -1);
  for (int i = 0; i < n; i++) {
    if (events[i].data.fd == listen_fd) {
      // accept新连接, 注册到epoll
    } else {
      // 读/写已就绪的连接
      // 非阻塞I/O + 状态机
    }
  }
}

// 模型3: 多线程 + 阻塞I/O (线程池模式)
// 优势: 比进程轻量, 利用多核, 编程相对简单
// 劣势: 线程同步复杂, 大量线程调度开销
// 适用: 中等并发, 混合计算+I/O

// 主线程: accept → 放入任务队列
// 工作线程: 从队列取任务 → 阻塞I/O处理
// 第8章: 互斥锁保护队列, 条件变量通知工作线程
```

## 资源管理原则

```text
// UNIX编程中的资源泄漏防护清单:

// 1. 文件描述符 (第2章)
//    - 每个open必须有对应close
//    - fork后关闭不需要的fd端
//    - open时设O_CLOEXEC, 防止exec后泄漏
//    - atexit注册close函数

// 2. 子进程 (第5章)
//    - 每个fork的子进程必须有wait/waitpid回收
//    - 注册SIGCHLD handler用WNOHANG循环回收
//    - 或signal(SIGCHLD, SIG_IGN)自动回收

// 3. 信号处理 (第6章)
//    - handler中只调用异步信号安全函数
//    - 保存/恢复errno
//    - 用volatile sig_atomic_t标志
//    - sigaction的oact保存旧handler

// 4. IPC资源 (第7章)
//    - 共享内存: shmdt解除映射, shmctl删除
//    - 信号量: semctl删除
//    - 消息队列: msgctl删除
//    - mmap: munmap解除映射

// 5. 线程 (第8章)
//    - 每个pthread_create必须有join或detach
//    - 互斥锁: 成对lock/unlock, 用try/finally保证
//    - 条件变量: 用while检查条件

// 6. 内存
//    - 每个malloc必须有free
//    - realloc后用新指针, 检查返回值
//    - 考虑用valgrind检查泄漏

// 核心原则: 每个获取的资源都必须有对应的释放路径
```

<Callout type="info">
**UNIX编程的核心智慧：** 「一切皆文件」统一了I/O接口；「fork+exec」分离了进程创建和程序加载；「信号」提供了异步通知机制；「文件描述符+epoll」实现了高性能事件驱动。这些设计让UNIX编程模型既简洁又强大——理解这些设计哲学比记住API更重要。
</Callout>

<Exercises>
**问题 1**：对比「多进程fork+阻塞I/O」和「单线程epoll+非阻塞I/O」两种服务器模型。

<Answer>
多进程fork+阻塞I/O：优势——编程简单（同步代码）、进程隔离强、利用多核。劣势——进程创建开销大、每连接一个进程资源消耗多、IPC需系统调用、上下文切换重。适用于连接少计算密集场景。单线程epoll+非阻塞I/O：优势——单线程管理数万连接（无进程开销）、O(1)事件通知、无锁无同步、内存效率高。劣势——编程复杂（异步事件驱动）、不能利用多核（需多进程+epoll）、长计算阻塞所有连接、调试困难。适用于高并发I/O密集场景（Nginx、Redis）。实际中常混合使用：多进程+每进程epoll（Nginx worker模式）。
</Answer>

**问题 2**：用「一次Web请求的完整周期」串联全书知识点。

<Answer>
完整周期：①文件I/O（第2章）——socket()创建fd，accept()返回新fd，read/write收发数据；②文件与目录（第3章）——stat()获取请求文件大小和权限；③进程环境（第4章）——getenv读取配置；④进程控制（第5章）——fork()创建子进程，waitpid回收僵尸；⑤信号（第6章）——SIGCHLD回收子进程，SIGPIPE处理断连；⑥IPC（第7章）——共享内存存储连接计数；⑦线程（第8章）——pthread_create工作线程，互斥锁保护共享数据；⑧高级I/O（第9章）——epoll管理数万连接，sendfile零拷贝发送文件。一次请求，全书十大知识点全部参与。
</Answer>

<Glossary>
<GlossaryItem term="一切皆文件">UNIX核心哲学。文件、设备、管道、套接字统一为fd接口，用open/read/write/close操作一切。使API统一、工具可组合、epoll可通用监听任何fd。</GlossaryItem>
<GlossaryItem term="fork+exec分离">fork创建进程副本，exec替换程序代码。分离设计让shell可以先重定向（fork后dup2）再加载命令（exec），灵活性极高。</GlossaryItem>
<GlossaryItem term="epoll高并发">O(1)就绪通知，内核维护就绪链表，只返回就绪fd。单线程管理数万连接。配合非阻塞I/O和ET边缘触发实现最高性能。Nginx/Redis的核心技术。</GlossaryItem>
<GlossaryItem term="资源管理">UNIX编程核心原则：每个获取的资源（fd、进程、信号、IPC、线程、内存）都必须有对应释放路径。O_CLOEXEC防fd泄漏、SIGCHLD回收僵尸、atexit注册清理、munmap解除映射、join/detach回收线程。</GlossaryItem>
</Glossary>
