## 信号生命周期

## 信号产生

```c
// 信号的三种产生来源:

// 1. 硬件异常 (内核检测, 自动产生信号)
//    除零错误     → SIGFPE (8)
//    非法内存访问 → SIGSEGV (11)
//    总线错误     → SIGBUS (7)
//    栈溢出       → SIGSEGV

// 2. 软件条件 (内核检测条件, 产生信号)
//    alarm定时器到期 → SIGALRM (14)
//    向已关闭的管道写 → SIGPIPE (13)
//    子进程状态变化   → SIGCHLD (17)

// 3. kill/sigqueue (进程主动发送)
#include <signal.h>
kill(pid, SIGTERM);      // 给指定进程发信号
raise(SIGTERM);          // 给自己发信号
sigqueue(pid, sig, &val); // 带数据的信号(实时信号)

// 常用信号编号:
// SIGHUP(1)   挂起        SIGINT(2)   Ctrl+C
// SIGQUIT(3)  Ctrl+\      SIGILL(4)   非法指令
// SIGKILL(9)  强制终止    SIGSEGV(11) 段错误
// SIGPIPE(13) 管道断裂    SIGALRM(14) 定时器
// SIGTERM(15) 优雅终止    SIGCHLD(17) 子进程状态变化
// SIGSTOP(19) 暂停        SIGCONT(18) 继续
```

## 信号处理与sigaction

```c
// 信号的三种处理方式:
//   SIG_DFL  → 默认动作(大多数是终止进程)
//   SIG_IGN  → 忽略信号
//   handler  → 捕获信号, 调用自定义函数

// sigaction —— 推荐的信号注册方式
struct sigaction sa;
sa.sa_handler = my_handler;     // 处理函数
sigemptyset(&sa.sa_mask);       // handler执行期间额外屏蔽的信号集
sa.sa_flags = SA_RESTART;       // 被中断的系统调用自动重启
// sa_flags 其他选项:
//   SA_RESTART   — 被信号中断的系统调用自动重启
//   SA_NOCLDSTOP — SIGCHLD不在子进程暂停/恢复时产生
//   SA_NOCLDWAIT — 子进程不变僵尸
//   SA_SIGINFO   — 使用三参数handler(可获取发送者信息)

sigaction(SIGINT, &sa, NULL);   // 注册SIGINT处理

// 为什么用sigaction而非signal?
// signal的行为在不同UNIX上不一致:
//   - 有的系统handler触发后自动重置为SIG_DFL
//   - 有的系统被中断的系统调用不自动重启
// sigaction行为明确可控, 可移植性好
```

## 信号屏蔽与未决

```c
// 信号屏蔽字 (signal mask) —— 被屏蔽的信号不立即递送
sigset_t mask, oldmask;

sigemptyset(&mask);
sigaddset(&mask, SIGINT);    // 添加SIGINT到屏蔽集
sigaddset(&mask, SIGQUIT);   // 添加SIGQUIT

// 修改进程屏蔽字
sigprocmask(SIG_BLOCK, &mask, &oldmask);    // 添加屏蔽
// SIG_BLOCK   — 添加到当前屏蔽字
// SIG_UNBLOCK — 从当前屏蔽字移除
// SIG_SETMASK — 直接设置屏蔽字

// 被屏蔽的信号产生时:
//   → 标记为pending(未决), 留在pending位图中
//   → 不丢失(同种传统信号多次产生只计一次)
//   → 解除屏蔽后递送

// 查询未决信号
sigset_t pending;
sigpending(&pending);
if (sigismember(&pending, SIGINT)) {
    // SIGINT已产生但被屏蔽, 待递送
}

// 解除屏蔽, 信号被递送
sigprocmask(SIG_SETMASK, &oldmask, NULL);

// SIGKILL和SIGSTOP不能被屏蔽、不能被忽略、不能被捕获!
// 这是系统的「最后手段」
```

<Callout type="trap">
**误区：在信号处理函数中可以调用任何函数。** 错误！信号handler中只能调用异步信号安全（async-signal-safe）函数。printf/malloc/free/fopen等都是不安全的——它们使用全局状态（stdio缓冲区、堆链表），如果主程序正在使用时被信号中断，handler再次调用会导致状态不一致或死锁。安全做法：①handler中只调用write/_exit/waitpid等安全函数；②handler只设置volatile sig_atomic_t标志，主程序检查后处理；③用sigqueue+sigwait同步接收信号（不在handler中处理）。
</Callout>

## 不可靠信号与可靠信号

```text
// 不可靠信号 (信号 1-31, 传统UNIX信号)
//   - 不排队: 同种信号多次产生只递送一次
//   - 可能丢失: pending位图是位图不是队列
//   - 信号处理后可能重置为SIG_DFL (用signal时)
//   - 示例: SIGINT, SIGTERM, SIGCHLD, SIGKILL

// 可靠信号 (SIGRTMIN ~ SIGRTMAX, 实时信号)
//   - 排队: sigqueue每次都递送, 不丢失
//   - 顺序: 编号小的先递送, 同级FIFO
//   - 示例: Linux上 SIGRTMIN=34, SIGRTMAX=64

// 选择原则:
//   - 简单通知用传统信号 (足够且兼容性好)
//   - 需要可靠传递数据用实时信号+sigqueue
//   - SIGKILL(9)和SIGSTOP(19)总是不可屏蔽/不可捕获
```

<Exercises>
**问题 1**：信号的三种处理方式是什么？SIGKILL为什么不能被捕获？

<Answer>
三种处理方式：①默认动作（SIG_DFL）——大多数终止进程；②忽略（SIG_IGN）——不做任何处理；③捕获——注册自定义handler。SIGKILL不能被捕获或忽略的原因：系统需要一种「强制」手段来终止失控的进程，如果允许被捕获，恶意进程可以永远不被杀死（handler中可以再次注册自己）。SIGKILL（9）是kill命令的最后一道防线（kill -9），SIGSTOP同理——保证系统总能暂停或终止进程。这两个信号总是执行默认动作。
</Answer>

**问题 2**：什么是信号屏蔽字和未决信号？信号在什么时机被递送？

<Answer>
信号屏蔽字：进程维护的被屏蔽信号集，被屏蔽的信号在递送时被阻塞。未决信号：已产生但尚未递送的信号，记录在pending位图中。递送时机：信号在进程从内核态返回用户态之前被检查——内核检查 pending & ~mask（未决且未屏蔽的信号），如果有就递送。同种传统信号（1-31）在pending期间多次产生只计一次（位图不是队列），这就是不可靠信号可能丢失的原因。sigprocmask修改屏蔽字，sigpending查询未决信号。SIGKILL和SIGSTOP不被屏蔽。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="信号">软件中断，内核或进程向目标进程发送的异步通知。三种处理：默认动作、忽略、捕获。SIGKILL和SIGSTOP不可被忽略或捕获。</GlossaryItem>
<GlossaryItem term="sigaction">推荐的信号注册函数。比signal更可控：可设置屏蔽字（sa_mask）、SA_RESTART自动重启、SA_SIGINFO获取发送者信息。行为可预测、可移植。</GlossaryItem>
<GlossaryItem term="信号屏蔽字">被屏蔽的信号集，用sigprocmask修改。被屏蔽的信号不立即递送而是标记为pending。SIGKILL/SIGSTOP不被屏蔽。</GlossaryItem>
<GlossaryItem term="异步信号安全">可在信号handler中安全调用的函数（约70个，如write/_exit/waitpid）。printf/malloc/fopen不安全（使用全局状态）。正确做法：handler中只设标志或用安全函数。</GlossaryItem>
</Glossary>
