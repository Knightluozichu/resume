## 管道与FIFO

```c
// 管道 (pipe) —— 半双工, 需有亲缘关系
int fd[2];
pipe(fd);      // fd[0]=读端, fd[1]=写端

pid_t pid = fork();
if (pid == 0) {
    // 子进程: 写
    close(fd[0]);           // 关闭不需要的读端
    write(fd[1], "hello", 5);
    close(fd[1]);
    _exit(0);
} else {
    // 父进程: 读
    close(fd[1]);           // 关闭不需要的写端
    char buf[100];
    int n = read(fd[0], buf, sizeof(buf));
    buf[n] = '\0';
    printf("收到: %s\n", buf);
    close(fd[0]);
    waitpid(pid, NULL, 0);
}

// FIFO (命名管道) —— 可用于无亲缘关系的进程
mkfifo("/tmp/myfifo", 0644);
// 进程A: open("/tmp/myfifo", O_WRONLY) → 写
// 进程B: open("/tmp/myfifo", O_RDONLY) → 读
// 注意: open默认阻塞, 直到另一端也打开

// shell管道的原理: ls | grep | sort
// shell对每个|: pipe(fd) → fork → 子进程dup2 → exec
```

## System V IPC

```c
// 1. 消息队列 —— 有格式的消息, 可按type接收
int msgid = msgget(IPC_PRIVATE, 0644 | IPC_CREAT);

struct my_msg {
    long mtype;       // 消息类型 (>0)
    char mtext[100];  // 消息数据
};

struct my_msg msg = { .mtype = 1, .mtext = "hello" };
msgsnd(msgid, &msg, sizeof(msg.mtext), 0);  // 发送

struct my_msg recv;
msgrcv(msgid, &recv, sizeof(recv.mtext), 1, 0);  // 接收type=1
// 第四参数: 0=任意type, >0=指定type, <0=type<=|值|的最小

msgctl(msgid, IPC_RMID, NULL);  // 删除消息队列

// 2. 共享内存 —— 最快IPC, 无内核拷贝
int shmid = shmget(IPC_PRIVATE, 4096, 0644 | IPC_CREAT);
char *addr = shmat(shmid, NULL, 0);  // 映射到进程地址空间
// 进程A: addr写入数据 → 进程B: 从addr读 (直接可见)
// 必须配合信号量/互斥锁同步!
shmdt(addr);                    // 解除映射
shmctl(shmid, IPC_RMID, NULL);  // 删除共享内存

// 3. 信号量 —— 用于同步, 非数据传输
int semid = semget(IPC_PRIVATE, 1, 0644 | IPC_CREAT);
// P操作 (wait): sem_op = -1
// V操作 (post): sem_op = +1
struct sembuf sop = { .sem_num = 0, .sem_op = -1, .sem_flg = 0 };
semop(semid, &sop, 1);  // P操作
// ... 临界区 ...
sop.sem_op = 1;
semop(semid, &sop, 1);  // V操作
```

## mmap存储映射

```c
// mmap —— 文件映射到内存, 读写内存即读写文件

// 用法1: 文件映射 (高效文件I/O + IPC)
int fd = open("data.txt", O_RDWR);
char *addr = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                  MAP_SHARED, fd, 0);
close(fd);  // 映射后可以close fd
// 现在 addr[0..4095] 就是文件内容
addr[0] = 'X';  // 修改内存 = 修改文件 (MAP_SHARED时)
msync(addr, 4096, MS_SYNC);  // 同步到磁盘
munmap(addr, 4096);  // 解除映射

// 用法2: 匿名映射 (父子进程共享内存)
char *shared = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                    MAP_SHARED | MAP_ANONYMOUS, -1, 0);
// fork后子进程继承映射, MAP_SHARED区域修改互相可见

// MAP_SHARED vs MAP_PRIVATE:
// MAP_SHARED: 修改写入文件/被其他进程可见 (IPC)
// MAP_PRIVATE: 写时复制, 修改私有, 不影响文件 (独立副本)
```

<Callout type="info">
**IPC选择原则：** ①亲缘进程间通信 → 管道（简单高效）；②格式化消息 → 消息队列（可按type选择性接收）；③大数据量高频通信 → 共享内存+信号量（无内核拷贝最快）；④跨主机通信 → 套接字（AF_INET）；⑤文件高效读写 → mmap存储映射。现代编程中，套接字（本地socket）和mmap越来越常用，System V IPC（消息队列/信号量/共享内存）因API复杂和内核持久性问题逐渐被替代。
</Callout>

<Exercises>
**问题 1**：管道有什么限制？FIFO解决了什么问题？

<Answer>
管道的限制：①半双工——数据只能单向流动，需双向要两个管道；②必须有亲缘关系——pipe只能在fork后父子进程间使用（通过继承fd通信）；③无名字——没有路径名，不能被不相关进程打开。FIFO（命名管道）解决了无亲缘关系进程间通信：mkfifo(path, mode)创建文件系统中可见的特殊文件，任何有权限的进程都可以open(path)使用。FIFO语义与pipe相同（半双工、内核缓冲、先进先出），但通过路径名解除了亲缘关系限制。
</Answer>

**问题 2**：共享内存为什么是最快的IPC？它的同步问题如何解决？

<Answer>
共享内存最快的原因：所有IPC中只有共享内存省去了内核拷贝。管道/消息队列/套接字都需要数据从用户空间→内核→用户空间两次拷贝。共享内存让多个进程映射同一物理内存到各自虚拟地址空间，一个写入另一个立即可见，零内核拷贝。同步问题：共享内存本身无同步机制——并发读写会读到不一致数据。解决：①信号量——P/V操作保护临界区；②pthread互斥锁——设PTHREAD_PROCESS_SHARED属性，放在共享内存中；③记录锁（fcntl）。典型模式：shmget→shmat→信号量同步→shmdt→shmctl删除。
</Answer>

<Glossary>
<GlossaryItem term="管道(pipe)">半双工IPC，pipe(fd)创建读端和写端，需fork后亲缘进程间使用。shell管道的原理。限制：半双工、需亲缘关系、无名字。</GlossaryItem>
<GlossaryItem term="共享内存">最快IPC，多个进程映射同一物理内存，零内核拷贝。需配合信号量/互斥锁同步。shmget/shmat/shmdt/shmctl。</GlossaryItem>
<GlossaryItem term="信号量">用于同步而非数据传输的IPC。P操作（wait减1）、V操作（post加1）。保护共享内存的临界区。semget/semop/semctl。</GlossaryItem>
<GlossaryItem term="mmap">存储映射I/O。文件映射：文件映射到内存直接读写。匿名映射：分配内存或父子共享内存。MAP_SHARED共享修改，MAP_PRIVATE写时复制。</GlossaryItem>
</Glossary>
