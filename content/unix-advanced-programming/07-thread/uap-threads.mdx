## 线程控制

```c
#include <pthread.h>

// 创建线程
pthread_t tid;
int ret = pthread_create(&tid, NULL, thread_func, arg);
// 参数: tid(输出), attr(线程属性, NULL=默认),
//       start_routine(线程函数), arg(参数)
// 线程函数签名: void* func(void* arg)

// 线程函数示例
void* worker(void* arg) {
    int id = *(int*)arg;
    // ... 执行工作 ...
    return (void*)(long)id;  // 返回值, 供pthread_join获取
}

// 等待线程结束 (阻塞)
void* retval;
pthread_join(tid, &retval);  // 等待tid线程结束, 获取返回值

// 分离线程 (自动回收, 不可join)
pthread_detach(tid);
// 分离后的线程结束时自动释放资源, 不能再join

// 线程退出
pthread_exit((void*)42);  // 退出并返回值
// main中调用pthread_exit会等待所有线程结束

// 获取自身线程ID
pthread_t self = pthread_self();
```

## 互斥锁

```c
// 互斥锁 —— 保护临界区, 同一时刻仅一个线程持有
pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;

// 静态初始化 (如上) 或动态初始化:
pthread_mutex_init(&mtx, NULL);

// 加锁/解锁
pthread_mutex_lock(&mtx);    // 阻塞直到获取锁
// ... 临界区: 操作共享数据 ...
pthread_mutex_unlock(&mtx);

// 非阻塞加锁
if (pthread_mutex_trylock(&mtx) == 0) {
    // 获取锁成功
    // ... 临界区 ...
    pthread_mutex_unlock(&mtx);
} else {
    // 锁被占用, 做其他事
}

// 超时加锁
struct timespec ts;
clock_gettime(CLOCK_REALTIME, &ts);
ts.tv_sec += 5;  // 5秒超时
if (pthread_mutex_timedlock(&mtx, &ts) == 0) {
    // 在5秒内获取锁
    pthread_mutex_unlock(&mtx);
} else {
    // 超时
}

// 锁类型 (attr设置):
// PTHREAD_MUTEX_NORMAL     — 不检测死锁
// PTHREAD_MUTEX_ERRORCHECK — 返回错误而非死锁
// PTHREAD_MUTEX_RECURSIVE  — 允许同线程多次lock(计数)

pthread_mutex_destroy(&mtx);  // 销毁
```

## 读写锁与条件变量

```c
// 读写锁 —— 读共享, 写独占. 适合读多写少场景
pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

// 读锁 (多个线程可同时持有)
pthread_rwlock_rdlock(&rwlock);
// ... 只读共享数据 ...
pthread_rwlock_unlock(&rwlock);

// 写锁 (独占, 禁止任何读和写)
pthread_rwlock_wrlock(&rwlock);
// ... 修改共享数据 ...
pthread_rwlock_unlock(&rwlock);

// 条件变量 —— 等待条件成立, 与互斥锁配合
pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

// 等待方 (消费者):
pthread_mutex_lock(&mtx);
while (!condition) {           // 必须用while! (防虚假唤醒)
    pthread_cond_wait(&cond, &mtx);
    // 原子操作: 释放mtx + 阻塞 + 被唤醒后重获mtx
}
// 条件成立, 处理数据
pthread_mutex_unlock(&mtx);

// 通知方 (生产者):
pthread_mutex_lock(&mtx);
// ... 修改共享数据, 使condition成立 ...
pthread_cond_signal(&cond);    // 唤醒一个等待线程
// pthread_cond_broadcast(&cond); // 唤醒所有等待线程
pthread_mutex_unlock(&mtx);

// 为什么用while而非if?
// 1. 虚假唤醒: POSIX允许cond_wait在没有signal时返回
// 2. 多线程唤醒: broadcast唤醒多个, 第一个处理后条件
//    可能不再成立, 后续线程必须重新检查
```

<Callout type="trap">
**误区：线程安全和可重入是一回事。** 不是。线程安全：多线程并发调用时能正确执行（用锁或TLS实现）。可重入：被中断后再次调用也能正确执行（不能有任何共享状态）。可重入一定线程安全，但线程安全不一定可重入——用锁实现的线程安全在信号handler中可能死锁。例如：strtok不是线程安全的（用静态变量），strtok_r是线程安全且可重入的（用调用者传入的buffer）。errno用__thread（TLS）实现线程安全，但在信号handler中调用设置errno的函数仍需小心。
</Callout>

<Exercises>
**问题 1**：线程和进程的核心区别是什么？线程间共享什么、各自独有什么？

<Answer>
进程是资源分配单位，线程是CPU调度单位。同一进程的线程共享地址空间，创建切换开销远小于进程。线程间共享：代码段/数据段/堆、文件描述符表、信号处理函数、当前工作目录、全局变量。线程各自独有：栈、寄存器（含PC和SP）、线程ID、errno、信号屏蔽字、线程局部存储（TLS）。共享的优势：通信只需读写共享变量无需IPC。共享的风险：需同步机制保护共享数据一致性。
</Answer>

**问题 2**：条件变量为什么要和互斥锁配合？为什么wait返回后要用while检查条件？

<Answer>
配合互斥锁的原因：检查条件需访问共享数据，必须用锁保护。cond_wait的原子操作：释放锁→阻塞→唤醒后重获锁。如果不配合锁，检查条件和等待之间有竞态——条件恰好在检查后成立并发出signal，但线程还没进入wait，signal就丢失了。用while而非if的原因：①虚假唤醒——POSIX允许cond_wait在没有signal时返回；②多线程唤醒——broadcast唤醒多个线程，第一个获取锁处理后条件可能不再成立，后续线程必须重新检查。模式：while (!condition) pthread_cond_wait(&cond, &mtx)。
</Answer>

<Glossary>
<GlossaryItem term="线程">进程内执行单元，CPU调度基本单位。共享地址空间，创建切换开销小。共享代码/数据/堆/fd表，独有栈/寄存器/线程ID/errno。</GlossaryItem>
<GlossaryItem term="互斥锁">同一时刻仅一个线程持有进入临界区。pthread_mutex_lock/unlock。适合写多场景。注意死锁：lock两次（非RECURSIVE）、忘记unlock、锁排序不对。</GlossaryItem>
<GlossaryItem term="读写锁">读共享（多线程可同时读）、写独占。适合读多写少场景。可能写饥饿（读者持续不断）。用while检查条件防虚假唤醒。</GlossaryItem>
<GlossaryItem term="条件变量">等待条件成立的通知机制，与互斥锁配合。wait原子释放锁+阻塞+重获锁。用while检查条件防虚假唤醒和多线程唤醒竞态。</GlossaryItem>
</Glossary>
