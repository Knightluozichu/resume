## 阻塞与非阻塞

```c
// 阻塞I/O (默认): 数据未就绪时进程挂起
// open时默认阻塞, read无数据时阻塞等待

// 非阻塞I/O: 数据未就绪时立即返回EAGAIN
// 设置方式1: open时加O_NONBLOCK
int fd = open("/dev/tty", O_RDONLY | O_NONBLOCK);

// 设置方式2: fcntl修改已打开的fd
int flags = fcntl(fd, F_GETFL);
flags |= O_NONBLOCK;
fcntl(fd, F_SETFL, flags);

// 非阻塞read的行为:
ssize_t n = read(fd, buf, sizeof(buf));
if (n == -1 && errno == EAGAIN) {
    // 无数据可读, 不是错误, 稍后重试
} else if (n == -1 && errno == EINTR) {
    // 被信号中断, 重试
} else if (n == 0) {
    // EOF
} else {
    // 读到n字节
}

// 非阻塞I/O单独使用的问题: 轮询浪费CPU
// 解决: 配合select/poll/epoll, 只在fd就绪时才read
```

## select / poll / epoll

```c
// === select === (跨平台, 但有fd数量限制和O(n)遍历)
fd_set rset;
FD_ZERO(&rset);
FD_SET(fd1, &rset);
FD_SET(fd2, &rset);
int maxfd = (fd1 > fd2 ? fd1 : fd2) + 1;

struct timeval tv = { .tv_sec = 5, .tv_usec = 0 };  // 5秒超时
int n = select(maxfd, &rset, NULL, NULL, &tv);
// 返回就绪fd数目, 0=超时, -1=出错

if (FD_ISSET(fd1, &rset)) {  // 逐个检查
    read(fd1, buf, sizeof(buf));
}

// select缺点:
//   1. FD_SETSIZE限制(通常1024)
//   2. 每次需重建fd_set
//   3. O(n)遍历检查所有fd

// === poll === (无fd数量限制, 但仍O(n)遍历)
struct pollfd fds[2];
fds[0].fd = fd1; fds[0].events = POLLIN;
fds[1].fd = fd2; fds[1].events = POLLIN;

int n = poll(fds, 2, 5000);  // 5000ms超时
for (int i = 0; i < 2; i++) {
    if (fds[i].revents & POLLIN) {
        read(fds[i].fd, buf, sizeof(buf));
    }
}

// === epoll === (Linux特有, O(1)就绪通知)
int epfd = epoll_create1(0);  // 创建epoll实例

struct epoll_event ev;
ev.events = EPOLLIN | EPOLLET;  // 读事件 + 边缘触发
ev.data.fd = fd1;
epoll_ctl(epfd, EPOLL_CTL_ADD, fd1, &ev);  // 注册fd1

// 等待就绪事件
struct epoll_event events[64];
int n = epoll_wait(epfd, events, 64, -1);  // -1=永久等待
// n = 就绪fd数目, 只返回就绪的!
for (int i = 0; i < n; i++) {
    int fd = events[i].data.fd;
    // 这个fd一定就绪, 直接read
    read(fd, buf, sizeof(buf));
}

// epoll优势:
//   1. O(1)就绪检查(内核维护就绪链表)
//   2. fd注册一次即可(不需每次重新注册)
//   3. 无fd数量限制(支持百万连接)
//   4. 只返回就绪fd(不需遍历全部)
```

## LT 与 ET 触发模式

```c
// LT (水平触发, 默认): 有数据就一直通知
// 只要fd缓冲区非空, 每次epoll_wait都通知
// 可以不一次读完, 下次继续通知
// 编程简单, 不易遗漏

// ET (边缘触发, EPOLLET): 状态变化时通知一次
// 从无数据变为有数据时通知一次, 之后不再通知
// 必须一次性读完(循环read直到EAGAIN)
// fd必须设为非阻塞(否则最后一次read会阻塞)

// ET模式的标准读取模式:
ev.events = EPOLLIN | EPOLLET;  // 必须加EPOLLET
epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);
// fd必须已设为O_NONBLOCK!

// 事件处理:
if (events[i].events & EPOLLIN) {
    while (1) {
        ssize_t n = read(fd, buf, sizeof(buf));
        if (n > 0) {
            // 处理数据
        } else if (n == 0) {
            // 对端关闭
            break;
        } else if (errno == EAGAIN || errno == EWOULDBLOCK) {
            // 数据已读完, 这是正常退出
            break;
        } else if (errno == EINTR) {
            // 被信号中断, 重试
            continue;
        } else {
            // 真正的错误
            break;
        }
    }
}
```

## 散射聚集I/O与零拷贝

```c
// readv —— 一次调用读取到多个不连续缓冲区
struct iovec iov[2];
iov[0].iov_base = header;   iov[0].iov_len = 64;
iov[1].iov_base = body;     iov[1].iov_len = 1024;
ssize_t n = readv(fd, iov, 2);  // 一次读取填满两个缓冲区

// writev —— 一次调用写入多个不连续缓冲区
struct iovec iov[2];
iov[0].iov_base = resp_header; iov[0].iov_len = 128;
iov[1].iov_base = resp_body;   iov[1].iov_len = 4096;
ssize_t n = writev(fd, iov, 2);  // 一次写入(原子性!)

// 优势: 减少系统调用次数, writev保证原子性
// 用途: HTTP响应(头+体在不同缓冲区)一次写出

// sendfile —— 零拷贝, 内核直接从文件到socket
int file_fd = open("large.dat", O_RDONLY);
off_t offset = 0;
ssize_t n = sendfile(socket_fd, file_fd, &offset, file_size);
// 数据全程在内核空间: 文件→内核缓冲→socket缓冲→网卡
// 跳过了用户空间的两次拷贝!

// 对比传统read+write:
// 传统: 文件→内核缓冲→用户缓冲(read)→内核缓冲(write)→socket (4次拷贝)
// sendfile: 文件→内核缓冲→socket (2次拷贝, 减少2次用户空间拷贝)
```

<Callout type="info">
**epoll性能优势的本质：** select/poll每次调用都要把全部fd拷贝到内核并遍历检查（O(n)），而epoll在epoll_ctl时就把fd注册到内核的红黑树中，内核只把就绪fd加入就绪链表，epoll_wait只返回就绪fd（O(1)）。当fd数量大但活跃fd少时（如万连接百活跃），epoll优势极大。这也是Nginx、Redis等高性能服务器选择epoll的原因。
</Callout>

<Exercises>
**问题 1**：select、poll、epoll的核心区别是什么？

<Answer>
select：①fd_set位图有FD_SETSIZE限制（通常1024）；②每次调用需重建fd_set并全部拷贝到内核；③返回后O(n)遍历检查FD_ISSET。poll：①用pollfd数组无数量限制；②每次仍需拷贝全部结构到内核；③返回后仍O(n)遍历检查revents。epoll：①epoll_ctl注册fd到内核红黑树（一次注册即可）；②内核维护就绪链表，epoll_wait只返回就绪fd；③O(1)就绪检查，只拷贝就绪fd到用户空间。核心差异：epoll在内核维护就绪表，不扫描全部fd，当fd多但活跃少时优势极大。
</Answer>

**问题 2**：epoll的ET模式为什么要求fd必须非阻塞？ET的标准读取模式是什么？

<Answer>
ET只在状态变化时通知一次，必须一次性读完所有数据（循环read直到EAGAIN），否则剩余数据永远不会被通知。如果是阻塞fd，最后一次read（缓冲区已空）会阻塞整个线程，导致无法处理其他fd。非阻塞fd在缓冲区空时read返回EAGAIN，循环正常退出。ET标准读取模式：while(1) &#123; n = read(fd, buf, sizeof(buf)); if (n > 0) 处理; else if (n==0) 对端关闭; else if (errno==EAGAIN) 读完退出; else if (errno==EINTR) 重试; else 出错; &#125;。LT模式（默认）有数据就持续通知，可以不一次读完，编程更简单。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="非阻塞I/O">O_NONBLOCK标志使read/write在数据未就绪时返回EAGAIN而非阻塞。单独使用需轮询浪费CPU，配合epoll实现高效事件驱动。</GlossaryItem>
<GlossaryItem term="epoll">Linux特有的I/O多路转接。epoll_create创建实例，epoll_ctl注册fd到内核红黑树，epoll_wait只返回就绪fd。O(1)就绪检查，支持百万连接。</GlossaryItem>
<GlossaryItem term="LT与ET">LT（水平触发）：有数据就一直通知，可不一次读完。ET（边缘触发）：状态变化通知一次，必须一次读完到EAGAIN，fd必须非阻塞。ET效率更高但编程复杂。</GlossaryItem>
<GlossaryItem term="零拷贝(sendfile)">sendfile(out_fd, in_fd)在内核中直接从文件拷贝到socket，跳过用户空间。减少2次拷贝和2次系统调用。Web服务器发送静态文件的标准优化。</GlossaryItem>
</Glossary>
