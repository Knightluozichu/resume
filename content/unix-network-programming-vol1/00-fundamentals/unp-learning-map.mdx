### 服务端 API 生命周期

```text
服务端                          客户端
  |                               |
  | socket() 创建套接字            | socket() 创建套接字
  | bind() 绑定地址端口            |
  | listen() 进入监听              |
  | accept() 等待连接  ←—————————— connect() 发起连接
  |          (三次握手)            |
  | read() ←——————————————— write()
  | write() ———————————————→ read()  数据交互
  | close()                       | close()
  |          (四次挥手)            |
```

<Callout type="info" title="为什么从套接字 API 开始学">

网络编程的本质是进程间通信，而套接字是 UNIX 提供的网络通信接口。理解 `socket/bind/listen/accept/connect` 这组 API 原语，是理解一切网络服务架构的基础。TCP/UDP 编程、I/O 复用、守护进程等高级主题都是在这组原语上的组合与扩展。

</Callout>

## TCP 与 UDP 编程模型对比

| 对比维度 | TCP | UDP |
|---------|-----|-----|
| 连接 | 面向连接（connect/accept） | 无连接 |
| 数据函数 | read/write | recvfrom/sendto |
| 可靠性 | 可靠（ACK/重传） | 不可靠（尽力交付） |
| 边界 | 字节流（无边界） | 数据报（保留边界） |
| 服务端流程 | socket→bind→listen→accept | socket→bind→recvfrom |
| 客户端流程 | socket→connect | socket→sendto |

<Glossary>

<GlossaryItem term="套接字（Socket）">
套接字是 UNIX 网络编程的核心抽象——一个文件描述符，代表一个网络通信端点。通过 socket() 创建，通过 bind/listen/accept/connect 建立通信关系，通过 read/write 或 recvfrom/sendto 收发数据。套接字屏蔽了底层协议细节，提供统一的 API 接口：AF_INET（IPv4）、AF_INET6（IPv6）、AF_LOCAL（Unix域）等地址族，SOCK_STREAM（TCP字节流）、SOCK_DGRAM（UDP数据报）等套接字类型。套接字编程是 UNP 卷1 的全部基础。
</GlossaryItem>

<GlossaryItem term="字节序（Byte Order）">
字节序是多字节数据在内存中的排列方式。主机字节序是 CPU 的本地序（x86 小端，ARM 可配置），网络字节序规定为大端序。端口号和 IP 地址在网络传输时必须用网络字节序。转换函数：htons/htonl（主机序→网络序）用于填入地址结构前，ntohs/ntohl（网络序→主机序）用于从结构取出后。不转换会导致端口/IP 解释错误，连接失败。
</GlossaryItem>

<GlossaryItem term="协议无关编程（Protocol-Independent Programming）">
协议无关编程是指代码不绑定特定协议族（IPv4 或 IPv6），同一代码同时支持两者。核心方法：用 getaddrinfo 替代硬编码 sockaddr_in，getaddrinfo 返回 addrinfo 链表，每个节点包含自适应的 sockaddr 结构（可能 IPv4 或 IPv6），遍历链表逐个 socket+connect 尝试。这样代码无需修改即可在不同协议环境运行，符合 IPv6 普及趋势。地址转换用 inet_pton/inet_ntop 替代旧函数。
</GlossaryItem>

<GlossaryItem term="I/O 复用（I/O Multiplexing）">
I/O 复用是让单线程同时管理多个文件描述符的技术。通过 select/poll/epoll 将多个 fd 注册给内核，阻塞等待任一 fd 就绪，就绪后处理该 fd 的 I/O。这样单线程可以服务大量客户端连接，避免了每连接一个线程的开销。epoll 是 Linux 上的高效实现，通过内核回调机制实现 O(1) 就绪检测，支持大量并发连接，是现代网络服务器的核心技术。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** UNP 卷1 的四层知识体系是什么？各层之间是什么依赖关系？

<Answer>

四层：①套接字基础（socket/bind/listen/accept API 原语和地址结构）②套接字编程（TCP 字节流和 UDP 数据报的客户端-服务端模型）③高级编程（I/O 复用、套接字选项、IPv6 协议无关）④生产级编程（守护进程、IPC、高级 I/O）。依赖关系自底向上：基础 API 是一切的前提，TCP/UDP 编程依赖 API 原语，高级编程扩展 TCP/UDP 的能力（多连接、选项控制、协议无关），生产级编程将前面所有能力组合成可运行的后台服务。

</Answer>

**问题 2：** TCP 和 UDP 在编程模型上的主要区别是什么？

<Answer>

TCP 面向连接：服务端需 listen+accept，客户端需 connect，用 read/write 传输字节流，保证可靠有序交付但无消息边界。UDP 无连接：服务端只需 bind 后直接 recvfrom，客户端用 sendto 发送数据报，用 recvfrom/sendto 收发，保留消息边界但不保证可靠交付。TCP 适合文件传输等需要可靠性的场景，UDP 适合 DNS/视频等需要低延迟或容忍丢失的场景。

</Answer>
