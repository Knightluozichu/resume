## TCP 服务端实现

### echo 服务端代码

```c
int listenfd = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in servaddr;
servaddr.sin_family      = AF_INET;
servaddr.sin_port        = htons(8080);
servaddr.sin_addr.s_addr = htonl(INADDR_ANY);

bind(listenfd, (struct sockaddr *)&servaddr, sizeof(servaddr));
listen(listenfd, 10);

while (1) {
    int connfd = accept(listenfd, NULL, NULL);
    // 循环读取并回显
    char buf[1024];
    ssize_t n;
    while ((n = read(connfd, buf, sizeof(buf))) > 0) {
        write(connfd, buf, n);  // 回显
    }
    close(connfd);  // n==0，对端关闭
}
```

### 服务端流程要点

```text
1. socket() → 创建监听套接字
2. bind()   → 绑定 0.0.0.0:8080
3. listen() → 进入 LISTEN 状态
4. accept() → 阻塞等待，返回已连接套接字
5. read()   → 读取客户端数据
6. write()  → 回显数据
7. close()  → 客户端关闭后关闭连接
```

## TCP 客户端实现

### echo 客户端代码

```c
int sockfd = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in servaddr;
servaddr.sin_family = AF_INET;
servaddr.sin_port   = htons(8080);
inet_pton(AF_INET, "127.0.0.1", &servaddr.sin_addr);

connect(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr));
// 三次握手在此完成

char sendline[1024], recvline[1024];
while (fgets(sendline, sizeof(sendline), stdin) != NULL) {
    write(sockfd, sendline, strlen(sendline));
    int n = read(sockfd, recvline, sizeof(recvline));
    if (n == 0) {
        // 服务端关闭
        break;
    }
    recvline[n] = '\0';
    fputs(recvline, stdout);
}
close(sockfd);
```

<Callout type="info" title="connect 与三次握手">

connect() 发起 TCP 三次握手：发送 SYN → 等待 SYN+ACK → 回复 ACK。connect 返回时连接已建立（ESTABLISHED），可以立即 read/write。如果服务端未启动，connect 返回 -1，errno=ECONNREFUSED。connect 默认阻塞，也可设非阻塞实现超时控制。

</Callout>

## read 返回值处理

### 三种返回值

```text
read() 返回值：
  > 0  → 读取了 n 字节数据，正常处理
  = 0  → 对端关闭连接（收到 FIN），应 close
  < 0  → 出错，检查 errno：
         EINTR  → 被信号中断，应重试
         ECONNRESET → 对端 RST，连接重置
         其他   → 真正错误
```

### 正确的错误处理模式

```c
ssize_t n;
while ((n = read(connfd, buf, sizeof(buf))) > 0) {
    write(connfd, buf, n);
}
if (n == 0) {
    // 对端正常关闭
    close(connfd);
} else if (n < 0) {
    if (errno == EINTR) {
        // 被信号中断，重试
    } else {
        perror("read error");
        close(connfd);
    }
}
```

## TCP 字节流与消息分帧

### 字节流的本质

```text
发送方 write("AB") + write("CD")
        可能合并为一个 TCP 段 → "ABCD"

接收方 read() 可能返回：
  "ABCD"     （一次读完）
  "AB" + "CD"（分两次读）
  "ABC" + "D"（拆分不同）

→ read 返回的字节数不等于 write 的字节数
→ 应用层必须自己实现消息边界
```

### 三种分帧方法

| 方法 | 原理 | 示例 |
|------|------|------|
| 定长消息 | 每条消息固定长度 | 每次读 100 字节 |
| 长度前缀 | 先读长度，再读数据 | HTTP Content-Length |
| 分隔符 | 用特殊字符标记边界 | HTTP `\r\n\r\n` |

```c
// 长度前缀分帧示例
uint32_t len;
read(connfd, &len, 4);    // 先读 4 字节长度
len = ntohl(len);          // 转为主机序
read(connfd, buf, len);    // 再读 len 字节数据
```

<Glossary>

<GlossaryItem term="TCP 字节流（Byte Stream）">
TCP 是面向字节流的协议——不保留消息边界。发送方多次 write 的数据可能被合并为一个 TCP 段传输，一次 write 的数据也可能被拆分为多个段。接收方 read 返回的字节数不一定等于发送方 write 的字节数。这意味着应用层必须自己实现消息分帧：定长消息、长度前缀或分隔符。这是 TCP 编程的核心难点之一，与 UDP 数据报保留边界形成对比。
</GlossaryItem>

<GlossaryItem term="已连接套接字（Connected Socket）">
accept() 返回的新套接字描述符，代表服务端与某个客户端的已建立连接。监听套接字只负责接受连接（accept），已连接套接字负责实际数据传输（read/write）。一个服务端进程通常有一个监听套接字和多个已连接套接字（每个客户端一个）。close() 关闭已连接套接字会触发四次挥手，释放该连接的资源。
</GlossaryItem>

<GlossaryItem term="SIGPIPE 信号">
当向一个已关闭连接（对端已 close）的套接字 write 时，内核会发送 SIGPIPE 信号，默认行为是终止进程。网络服务端必须忽略 SIGPIPE（signal(SIGPIPE, SIG_IGN)）或捕获它，否则一个客户端关闭连接就可能导致整个服务端崩溃。忽略后 write 会返回 -1，errno=EPIPE，应用可据此处理。
</GlossaryItem>

<GlossaryItem term="消息分帧（Message Framing）">
由于 TCP 字节流无边界，应用层必须自己定义消息边界，称为消息分帧。三种方法：①定长消息——每条消息固定长度，简单但浪费带宽 ②长度前缀——消息头包含消息体长度，灵活高效（HTTP Content-Length）③分隔符——用特殊字节序列标记边界（HTTP 的 \r\n\r\n）。选择取决于应用场景：二进制协议常用长度前缀，文本协议常用分隔符。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** TCP echo 服务端的完整工作流程是什么？accept 返回的套接字和监听套接字有什么区别？

<Answer>

流程：socket → bind → listen → accept → read/write 循环 → close。accept 返回的套接字是已连接套接字，代表与某个客户端的已建立连接，用于实际数据传输（read/write）。监听套接字只负责接受连接（accept），不参与数据传输。一个服务端有一个监听套接字和多个已连接套接字（每个客户端一个）。accept 从已完成连接队列取出连接，返回新的已连接套接字 fd。

</Answer>

**问题 2：** TCP 是字节流协议，这对编程有什么影响？如何处理粘包问题？

<Answer>

TCP 字节流无消息边界——一次 write 可能被拆分，多次 write 可能被合并，read 返回的字节数不一定等于 write 的字节数。处理粘包的方法：①定长消息（每条消息固定长度）②长度前缀（先读长度再读数据，如 HTTP Content-Length）③分隔符（如 HTTP 的 \r\n\r\n）。应用层必须自己实现消息分帧，TCP 本身不提供边界标记。

</Answer>

</Exercises>
