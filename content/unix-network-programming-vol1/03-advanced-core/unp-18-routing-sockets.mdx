## 协议、对象与故障模型

第18章 路由套接字围绕数据链路套接字地址结构、读和写、sysctl操作、get_ifi_info函数、接口名字和索引函数建立从套接字接口到分组、内核状态与清理结果的证据链。

本页核心不变量是：**控制消息长度、版本、序号与地址对齐正确，内核返回记录边界可验证，查询不破坏系统配置。** 它同时约束正常、边界、故障和恢复样本。应用函数返回成功只是一条证据，还要检查地址长度、字节序、短计数、EINTR/EAGAIN、套接字状态、内核队列、分组顺序与异步清理。

实验台账至少包含内核/库版本、命名空间、接口与路由、地址端口、入口参数、描述符所有者、预期状态、实际返回与errno、首个分组分叉、内核队列和清理结果十一列。性能样本还固定并发度、连接复用、预热、输入规模、采样窗口和延迟分位；抓包必须记录过滤器、snaplen与时间基准。

  只看应用最终文本，不检查短读写、errno、套接字状态、内核队列与线上分组是否一致。

## 四类样本与验收

| 样本 | 只改变什么                 | 必查证据              | 通过条件   |
| ---- | -------------------------- | --------------------- | ---------- |
| 基线 | 固定网络、地址与输入       | API、状态、队列与分组 | 与预测一致 |
| 边界 | 缓冲、MTU、并发或时序      | 首个阻塞、截断或拒绝  | 边界可解释 |

**问题 1** 为什么不能只凭最终输出验收第18章 路由套接字？

<Answer>
  最终输出会隐藏短读写、errno、地址错误、队列积压、重传、分组重排和描述符泄漏。必须同时核对接口合同、套接字生存期、内核状态、首个分组分叉和恢复结果。
</Answer>

**问题 2** 如何把“发送查询”变成网络证据？

<Answer>
  固定内核、命名空间、接口、路由、地址端口和输入，预测数据链路套接字地址结构与读和写的返回值、状态和分组，只改变一个条件并停在首错或首包分叉。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  控制消息长度、版本、序号与地址对齐正确，内核返回记录边界可验证，查询不破坏系统配置。
  关闭端点并恢复网络设置后，相同输入必须重新得到基线结果。
</Answer>
