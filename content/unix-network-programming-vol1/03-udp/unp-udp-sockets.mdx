## UDP 服务端实现

### echo 服务端代码

```c
int sockfd = socket(AF_INET, SOCK_DGRAM, 0);  // UDP

struct sockaddr_in servaddr, cliaddr;
servaddr.sin_family      = AF_INET;
servaddr.sin_port        = htons(8080);
servaddr.sin_addr.s_addr = htonl(INADDR_ANY);

bind(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr));

// 不需要 listen 和 accept！
char buf[1024];
socklen_t len;
ssize_t n;
while (1) {
    len = sizeof(cliaddr);
    n = recvfrom(sockfd, buf, sizeof(buf), 0,
                 (struct sockaddr *)&cliaddr, &len);
    sendto(sockfd, buf, n, 0,
           (struct sockaddr *)&cliaddr, len);  // 回送
}
```

### 服务端流程要点

```text
1. socket(SOCK_DGRAM) → 创建数据报套接字
2. bind()             → 绑定地址
3. recvfrom()         → 等待并接收数据报（同时获得发送方地址）
4. sendto()           → 向发送方回送数据报
5. 循环 3-4
→ 不需要 listen / accept
```

## UDP 客户端实现

### echo 客户端代码

```c
int sockfd = socket(AF_INET, SOCK_DGRAM, 0);

struct sockaddr_in servaddr;
servaddr.sin_family = AF_INET;
servaddr.sin_port   = htons(8080);
inet_pton(AF_INET, "127.0.0.1", &servaddr.sin_addr);

// 不需要 connect！
char sendline[1024], recvline[1024];
socklen_t len;
while (fgets(sendline, sizeof(sendline), stdin) != NULL) {
    sendto(sockfd, sendline, strlen(sendline), 0,
           (struct sockaddr *)&servaddr, sizeof(servaddr));

    int n = recvfrom(sockfd, recvline, sizeof(recvline), 0,
                     NULL, NULL);  // 不关心回送地址
    recvline[n] = '\0';
    fputs(recvline, stdout);
}
```

<Callout type="info" title="recvfrom 的地址参数">

recvfrom 的第五个参数 `from` 是输出参数，返回时填入发送方地址。服务端正是通过它知道是谁发来的数据报，然后用这个地址作为 sendto 的目标回送。客户端通常不关心回送地址（因为知道是服务端回的），可以传 NULL。

</Callout>

## UDP 数据报特性

### 消息边界保留

```text
发送方：
  sendto("ABC")  → 数据报1
  sendto("DEFG") → 数据报2

接收方：
  recvfrom() → "ABC"  （完整收到数据报1，3字节）
  recvfrom() → "DEFG" （完整收到数据报2，4字节）

→ 不会出现 "ABCDE" + "FG" 的拆分/合并
→ recvfrom 返回值 = 数据报实际大小
```

### 与 TCP 字节流的对比

| 特性 | TCP 字节流 | UDP 数据报 |
|------|-----------|-----------|
| 边界 | 无边界 | 保留边界 |
| read/write | 返回任意字节数 | 返回完整数据报 |
| 可靠性 | 保证可靠有序 | 不保证 |
| 分帧 | 应用层自己实现 | 天然有边界 |

## 已连接 UDP 套接字

### connect 对 UDP 的效果

```text
UDP connect 不发起三次握手（UDP 无连接）
效果：内核将该套接字「绑定」到指定对端地址

好处：
  ① 只能与该对端通信，其他源的数据报被丢弃
  ② 可以用 read/write 代替 recvfrom/sendto
  ③ 异步错误（ICMP端口不可达）能通过 read 报告
     → 不 connect 的 UDP 收不到异步错误！
```

### 已连接 UDP 示例

```c
int sockfd = socket(AF_INET, SOCK_DGRAM, 0);

struct sockaddr_in servaddr;
servaddr.sin_family = AF_INET;
servaddr.sin_port   = htons(8080);
inet_pton(AF_INET, "127.0.0.1", &servaddr.sin_addr);

connect(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr));
// 不发起握手，只是绑定对端地址

write(sockfd, "hello", 5);   // 可以用 write 代替 sendto
read(sockfd, buf, sizeof(buf)); // 可以用 read 代替 recvfrom
```

<Glossary>

<GlossaryItem term="数据报（Datagram）">
UDP 的传输单元，保留消息边界。发送方一次 sendto 的数据，接收方一次 recvfrom 完整收到——不会拆分或合并。recvfrom 的返回值就是数据报的实际字节数。这与 TCP 字节流形成本质区别：TCP 无边界需要应用层分帧，UDP 天然有边界。代价是 UDP 不保证可靠交付、不保证顺序、不保证不重复。每个数据报独立传输，适合 DNS 查询、视频流等场景。
</GlossaryItem>

<GlossaryItem term="recvfrom / sendto">
UDP 的核心收发函数。recvfrom(fd, buf, len, flags, from, fromlen) 接收数据报并获取发送方地址。sendto(fd, buf, len, flags, to, tolen) 向指定地址发送数据报。from 是输出参数（返回发送方地址），to 是输入参数（指定目标地址）。已连接 UDP 套接字可用 read/write 替代。recvfrom 在无数据报时阻塞（默认），非阻塞模式返回 EWOULDBLOCK。
</GlossaryItem>

<GlossaryItem term="已连接 UDP 套接字（Connected UDP Socket）">
对 UDP 套接字调用 connect 的效果：不发起三次握手（UDP 无连接），内核只将该套接字绑定到指定对端地址。好处：①只能与该对端通信 ②可用 read/write 替代 recvfrom/sendto ③能收到异步错误（如 ICMP 端口不可达）——未 connect 的 UDP 收不到异步错误，因为内核不知道该把错误报给谁。适合只与单个服务端通信的 UDP 客户端。
</GlossaryItem>

<GlossaryItem term="UDP 的不可靠性">
UDP 不保证可靠交付：数据报可能丢失、重复、乱序。原因：UDP 无连接，发送后不确认、不重传。网络拥塞时路由器丢弃 UDP 包，发送方和接收方都不知道。应用如果需要可靠性，必须自己实现：序号检测丢失、超时重传、ACK 确认。或者选择 TCP。UDP 适合容忍丢失的场景（视频流、DNS）或应用层自行保证可靠性的场景（QUIC）。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** UDP 服务端编程的基本流程是什么？与 TCP 服务端有什么主要区别？

<Answer>

UDP 服务端流程：socket(SOCK_DGRAM) → bind() → recvfrom()/sendto() 循环 → close()。与 TCP 的主要区别：①不需要 listen() 和 accept()——UDP 无连接，直接 recvfrom 接收数据报 ②用 recvfrom/sendto 而非 read/write ③recvfrom 返回时同时获得对端地址，sendto 需要指定目标地址 ④一个套接字处理所有客户端，不需要维护已连接套接字。

</Answer>

**问题 2：** UDP 客户端可以用 connect 函数吗？如果可以，效果是什么？

<Answer>

可以。UDP 的 connect 不发起三次握手（UDP 无连接），效果是内核将该套接字绑定到指定对端地址。好处：①只能与该对端通信，其他源的数据报被内核丢弃 ②可以用 read/write 代替 recvfrom/sendto ③异步错误（如 ICMP 端口不可达）能通过 read 返回报告给应用——不用 connect 则收不到异步错误。这叫已连接 UDP 套接字。

</Answer>

</Exercises>
