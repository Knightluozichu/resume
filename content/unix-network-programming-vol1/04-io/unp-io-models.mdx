## 五种 I/O 模型对比

## I/O 操作的两个阶段

```text
任何 I/O 操作都分两个阶段：

阶段1：等待数据就绪
  → 数据从网络到达内核接收缓冲区
阶段2：数据拷贝
  → 数据从内核缓冲区拷贝到用户缓冲区

五种模型的区别在于这两个阶段谁来阻塞：
  阻塞I/O：     阶段1阻塞 + 阶段2阻塞
  非阻塞I/O：   阶段1轮询   + 阶段2阻塞
  I/O复用：     select阻塞  + 阶段2阻塞
  信号驱动I/O：  信号通知    + 阶段2阻塞
  异步I/O：     都不阻塞（内核全做完）
```

## 五种模型详解

### 1. 阻塞式 I/O（默认）

```text
应用调用 recvfrom()
  → 阻塞等待数据就绪（阶段1）
  → 数据就绪，内核拷贝到用户缓冲（阶段2）
  → 返回

全程阻塞，无法同时处理其他连接
```

### 2. 非阻塞式 I/O

```text
应用调用 recvfrom()
  → 立即返回 EWOULDBLOCK（无数据）
  → 循环轮询检查
  → 数据就绪 → 拷贝 → 返回

CPU 空转轮询，效率低
```

### 3. I/O 复用（select/poll/epoll）

```text
应用调用 select() 阻塞等待多个 fd
  → 任一 fd 数据就绪 → select 返回
  → 调用 recvfrom() 拷贝数据 → 返回

单线程管理多连接，核心模型
```

### 4. 信号驱动式 I/O（SIGIO）

```text
应用注册 SIGIO 信号处理
  → 主线程不阻塞
  → 数据就绪 → 内核发 SIGIO
  → 信号处理中调 recvfrom() 拷贝 → 返回

异步通知，但拷贝阶段仍阻塞
```

### 5. 异步 I/O（aio_read）

```text
应用调用 aio_read() 立即返回
  → 内核完成全部工作（等待+拷贝）
  → 数据已在用户缓冲 → 信号通知

真正的异步：两阶段都不阻塞
```

<Callout type="info" title="前四种 vs 异步 I/O">

前四种 I/O 模型（阻塞、非阻塞、I/O 复用、信号驱动）在「数据拷贝」阶段都是阻塞的——应用自己调 recvfrom 拷贝数据。只有异步 I/O（aio_read）连拷贝都由内核完成，应用被通知时数据已就绪。因此前四种本质上都是「同步 I/O」，只有第五种是真正的「异步 I/O」。

</Callout>

## select / poll / epoll

### select 工作流程

```c
fd_set rset;
FD_ZERO(&rset);

while (1) {
    FD_SET(listenfd, &rset);  // 每次都要重新设置
    for (int i = 0; i < nconn; i++)
        FD_SET(connfds[i], &rset);

    int nready = select(maxfd + 1, &rset, NULL, NULL, NULL);
    // 阻塞等待任一 fd 就绪

    if (FD_ISSET(listenfd, &rset)) {
        // 监听套接字就绪 → accept 新连接
        int connfd = accept(listenfd, NULL, NULL);
        connfds[nconn++] = connfd;
    }
    for (int i = 0; i < nconn; i++) {
        if (FD_ISSET(connfds[i], &rset)) {
            // 已连接套接字就绪 → read 数据
            int n = read(connfds[i], buf, sizeof(buf));
            if (n == 0) close(connfds[i]);  // 对端关闭
        }
    }
}
```

### 三者对比

| 特性 | select | poll | epoll |
|------|--------|------|-------|
| fd 上限 | FD_SETSIZE(1024) | 无限制 | 无限制 |
| fd 传递 | 每次全量拷贝 | 每次全量拷贝 | 内核维护，无需拷贝 |
| 就绪检测 | O(n) 遍历全部 | O(n) 遍历全部 | O(1) 回调直接返回 |
| 触发方式 | 水平触发(LT) | 水平触发(LT) | LT + 边沿触发(ET) |
| 适用场景 | 连接少、跨平台 | 连接中等 | 大量并发连接 |

### epoll 的优势

```text
select/poll 的问题：
  ① 每次调用都要全量拷贝 fd 集合到内核
  ② 返回后要 O(n) 遍历全部 fd 检查哪些就绪
  ③ 大量连接但只有少数活跃时，大部分遍历是浪费

epoll 的解决：
  ① 内核维护兴趣列表，epoll_ctl 增删改只需一次
  ② 就绪的 fd 通过回调直接加入就绪列表
  ③ epoll_wait 只返回就绪的 fd，O(1) 效率
  ④ 支持 ET 边沿触发，进一步减少调用次数
```

## 水平触发（LT）与边沿触发（ET）

### 触发方式区别

```text
水平触发（LT）：
  只要 fd 有数据可读 → 持续通知
  → 编程简单（没读完下次还会通知）
  → select/poll/epoll 默认

边沿触发（ET）：
  仅在状态变化时通知一次 → 必须一次性读完
  → 编程复杂（必须循环 read 到 EAGAIN）
  → 只有 epoll 支持

ET 模式正确处理：
  while ((n = read(fd, buf, sizeof(buf))) > 0) {
      process(buf, n);
  }
  // n == -1 && errno == EAGAIN → 读完了，正常
  // n == -1 && errno == EINTR  → 被信号中断，重试
```

<Glossary>

<GlossaryItem term="I/O 复用（I/O Multiplexing）">
让单线程同时管理多个文件描述符的技术。通过 select/poll/epoll 将多个 fd 注册给内核，阻塞等待任一 fd 就绪，就绪后处理该 fd。这样单线程可以服务大量客户端连接。核心价值：避免了「一个连接一个线程」的开销，在高并发场景下性能远优于多线程模型。epoll 是 Linux 上的高效实现，Nginx、Redis 等高性能服务器都基于 epoll。
</GlossaryItem>

<GlossaryItem term="select 的局限性">
select 的三个主要局限：①fd 数量受 FD_SETSIZE 限制（默认 1024），无法支持大量连接 ②每次调用需将全部 fd 集合从用户空间拷贝到内核空间 ③返回后需 O(n) 遍历全部 fd 检查哪些就绪——大量连接但少数活跃时，大部分遍历是浪费。这些局限催生了 poll（去掉 fd 数量限制但仍有 O(n) 遍历）和 epoll（内核回调机制实现 O(1) 就绪检测）。
</GlossaryItem>

<GlossaryItem term="epoll">
Linux 特有的高效 I/O 复用机制。优势：①fd 无上限 ②内核维护兴趣列表（epoll_ctl 增删改），epoll_wait 无需全量拷贝 ③就绪检测 O(1)——通过内核回调将就绪 fd 直接加入就绪列表，epoll_wait 只返回就绪的 fd ④支持边沿触发（ET）模式。epoll 适合大量并发连接但只有少数活跃的场景（如 Web 服务器），是现代高性能网络服务器的核心技术。
</GlossaryItem>

<GlossaryItem term="边沿触发（ET）与水平触发（LT）">
LT（水平触发）：只要 fd 有数据可读就持续通知，编程简单但可能通知多次。ET（边沿触发）：仅在状态变化（新数据到达）时通知一次，必须一次性读完所有数据（循环 read 到 EAGAIN），编程复杂但效率更高——减少了 epoll_wait 的返回次数和系统调用次数。ET 必须搭配非阻塞 I/O 使用，且 read/write 要循环到 EAGAIN。只有 epoll 支持 ET，select/poll 只有 LT。
</GlossaryItem>

</Glossary>

**问题 1：** 五种 I/O 模型分别是什么？它们的核心区别在哪里？

<Answer>

五种 I/O 模型：①阻塞式 I/O（recvfrom 全程阻塞）②非阻塞式 I/O（轮询返回 EWOULDBLOCK）③I/O 复用（select/poll/epoll 阻塞等待多个 fd）④信号驱动式 I/O（SIGIO 通知就绪）⑤异步 I/O（aio_read，内核完成全部工作后通知）。核心区别在于「等待数据就绪」和「数据拷贝」两个阶段谁来阻塞：前四种在拷贝阶段都阻塞（同步 I/O），只有异步 I/O 两阶段都不阻塞。

</Answer>

**问题 2：** epoll 相比 select 有哪些优势？水平触发和边沿触发有什么区别？

<Answer>

epoll 优势：①fd 无上限限制（select 受 FD_SETSIZE 1024 限制）②内核维护兴趣列表，无需每次全量拷贝③就绪检测 O(1) 通过回调直接返回就绪 fd，不遍历全部④支持 ET 模式。LT（水平触发）：只要 fd 有数据就持续通知，编程简单。ET（边沿触发）：仅在状态变化时通知一次，必须一次性读完所有数据（循环 read 到 EAGAIN），编程复杂但效率更高，减少 epoll_wait 调用次数。

</Answer>
