## 常见误区

<Callout type="trap">
  **误区一：**
  只看应用最终文本，不检查短读写、errno、套接字状态、内核队列与线上分组是否一致。
</Callout>

<Callout type="trap">
  **误区二：**
  在“第28章 原始套接字”中，把TCP当消息协议、把UDP当可靠流，或把Linux专有行为当成跨UNIX与协议标准保证，都会直接判错。
</Callout>

## 四类样本与验收

| 样本 | 只改变什么                 | 必查证据              | 通过条件   |
| ---- | -------------------------- | --------------------- | ---------- |
| 基线 | 固定网络、地址与输入       | API、状态、队列与分组 | 与预测一致 |
| 边界 | 缓冲、MTU、并发或时序      | 首个阻塞、截断或拒绝  | 边界可解释 |
| 故障 | 丢包、复位、信号或路径故障 | errno、首包与责任层   | 故障可定位 |
| 恢复 | 关闭、回收、撤销网络设置   | 残留端点与同输入重放  | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第28章 原始套接字？

<Answer>
  “第28章 原始套接字”的“第28章 原始套接字”的最终输出会隐藏短读写、errno、地址错误、队列积压、重传、分组重排和描述符泄漏。必须同时核对接口合同、套接字生存期、内核状态、首个分组分叉和恢复结果。
</Answer>

**问题 2** 如何把“计算长度校验”变成网络证据？

<Answer>
  固定内核、命名空间、接口、路由、地址端口和输入，预测原始套接字创建与原始套接字输出的返回值、状态和分组，只改变一个条件并停在首错或首包分叉。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  首部长度、字节序、校验和与链路类型一致，捕获过滤边界明确，实验只使用最小网络权限。
  关闭端点并恢复网络设置后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
