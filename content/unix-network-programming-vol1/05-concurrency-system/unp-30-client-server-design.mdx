验证只改变一个延迟、丢包、重排、缓冲水位、地址、信号或并发度，并在进入“分派连接”前停住第一条返回值、errno、套接字状态、队列计数或分组分叉。最后关闭端点、回收进程线程、撤销流量规则与网络配置；同输入重放回到基线，结论才成立。

## 常见误区

<Callout type="trap">
  **误区一：**
  只看应用最终文本，不检查短读写、errno、套接字状态、内核队列与线上分组是否一致。
</Callout>

<Callout type="trap">
  **误区二：**
  把TCP当消息协议、把UDP当可靠流，或把Linux专有行为当成跨UNIX与协议标准保证。
</Callout>

## 四类样本与验收

| 样本 | 只改变什么                 | 必查证据              | 通过条件   |
| ---- | -------------------------- | --------------------- | ---------- |
| 基线 | 固定网络、地址与输入       | API、状态、队列与分组 | 与预测一致 |
| 边界 | 缓冲、MTU、并发或时序      | 首个阻塞、截断或拒绝  | 边界可解释 |
| 故障 | 丢包、复位、信号或路径故障 | errno、首包与责任层   | 故障可定位 |
| 恢复 | 关闭、回收、撤销网络设置   | 残留端点与同输入重放  | 回到基线   |

## 练习

<Exercises>

**问题 1** 为什么不能只凭最终输出验收第30章 客户/服务器程序设计范式？

<Answer>
  最终输出会隐藏短读写、errno、地址错误、队列积压、重传、分组重排和描述符泄漏。必须同时核对接口合同、套接字生存期、内核状态、首个分组分叉和恢复结果。
</Answer>

**问题 2** 如何把“分派连接”变成网络证据？

<Answer>
  固定内核、命名空间、接口、路由、地址端口和输入，预测TCP客户程序设计范式与TCP测试用客户程序的返回值、状态和分组，只改变一个条件并停在首错或首包分叉。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  连接所有权唯一，锁序和条件谓词明确，过载有界，停机后进程、线程和描述符全部归零。
  关闭端点并恢复网络设置后，相同输入必须重新得到基线结果。
</Answer>

</Exercises>
