## 高并发服务端设计

### 技术组合方案

```text
目标：高并发 TCP echo 服务端

技术选型：
  ① socket/bind/listen/accept  → 基础服务端框架
  ② epoll + 非阻塞I/O          → 单线程管理大量连接
  ③ ET 边沿触发                → 最大化效率
  ④ SO_REUSEADDR               → 允许快速重启
  ⑤ TCP_NODELAY                → 降低回显延迟（小包场景）
  ⑥ daemon_init                → 脱离终端后台运行

架构：
  主线程循环：
    epoll_wait() → 等待所有 fd 就绪
    → 监听套接字就绪 → accept 新连接 + 加入 epoll
    → 已连接套接字就绪 → read → write 回显
    → read 返回 0 → close 连接 + 从 epoll 移除
```

### epoll 服务端核心代码

```c
int epfd = epoll_create1(0);

// 添加监听套接字
struct epoll_event ev;
ev.events  = EPOLLIN | EPOLLET;  // ET 模式
ev.data.fd = listenfd;
epoll_ctl(epfd, EPOLL_CTL_ADD, listenfd, &ev);

while (1) {
    struct epoll_event events[1024];
    int nready = epoll_wait(epfd, events, 1024, -1);

    for (int i = 0; i < nready; i++) {
        int fd = events[i].data.fd;

        if (fd == listenfd) {
            // 新连接（ET 模式需循环 accept）
            while (1) {
                int connfd = accept(listenfd, NULL, NULL);
                if (connfd < 0) break;
                set_nonblocking(connfd);
                ev.events  = EPOLLIN | EPOLLET;
                ev.data.fd = connfd;
                epoll_ctl(epfd, EPOLL_CTL_ADD, connfd, &ev);
            }
        } else {
            // 数据到达（ET 模式需循环 read 到 EAGAIN）
            while (1) {
                int n = read(fd, buf, sizeof(buf));
                if (n > 0) {
                    write(fd, buf, n);  // 回显
                } else if (n == 0) {
                    close(fd);
                    epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
                    break;
                } else if (errno == EAGAIN) {
                    break;  // 读完了
                }
            }
        }
    }
}
```

## TCP vs UDP 编程模型差异

### 对应用设计的影响

| 维度 | TCP | UDP | 影响 |
|------|-----|-----|------|
| 编程模型 | connect/accept | 无连接 | TCP 需维护连接状态 |
| 可靠性 | 保证 | 不保证 | UDP 需自己实现可靠性 |
| 边界 | 无边界 | 有边界 | TCP 需消息分帧 |
| 场景 | 文件传输 | DNS/视频 | 选择决定协议 |

```text
选择 TCP 的场景：
  → 需要可靠传输（文件、支付、数据库）
  → 需要顺序保证（指令流）
  → 可以容忍延迟

选择 UDP 的场景：
  → 需要低延迟（视频、游戏、DNS）
  → 容忍丢失（实时流）
  → 需要多播/广播（只能用 UDP）
  → 应用层自行保证可靠性（QUIC）
```

## 协议无关编程完整方案

### 完整代码框架

```c
// 客户端协议无关连接
struct addrinfo hints, *res;
memset(&hints, 0, sizeof(hints));
hints.ai_family   = AF_UNSPEC;    // 不指定协议
hints.ai_socktype = SOCK_STREAM;

getaddrinfo(host, port, &hints, &res);

int sockfd = -1;
for (struct addrinfo *p = res; p != NULL; p = p->ai_next) {
    sockfd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
    if (sockfd < 0) continue;

    if (connect(sockfd, p->ai_addr, p->ai_addrlen) == 0)
        break;  // 成功

    close(sockfd);
    sockfd = -1;
}
freeaddrinfo(res);

if (sockfd < 0) {
    perror("connect failed");
    exit(1);
}
// sockfd 已就绪，read/write 通信
```
