## 守护进程化

### daemon_init 七步

```c
void daemon_init() {
    // 1. fork()，父进程退出
    pid_t pid = fork();
    if (pid > 0) exit(0);

    // 2. setsid()，创建新会话，脱离控制终端
    setsid();

    // 3. 再次 fork()，确保不会重新获取终端
    pid = fork();
    if (pid > 0) exit(0);

    // 4. chdir("/")，切换到根目录
    chdir("/");

    // 5. umask(0)，清除文件创建掩码
    umask(0);

    // 6. close 所有从 shell 继承的文件描述符
    for (int i = 0; i < 64; i++) close(i);

    // 7. 重定向 stdin/stdout/stderr 到 /dev/null
    open("/dev/null", O_RDONLY);  // fd 0 = stdin
    open("/dev/null", O_WRONLY);  // fd 1 = stdout
    open("/dev/null", O_WRONLY);  // fd 2 = stderr
}
```

<Callout type="info" title="为什么 fork 两次">

第一次 fork + setsid 使进程成为新会话组长，脱离控制终端。但会话组长仍可能通过 open 获取新的控制终端。第二次 fork 使进程不再是会话组长，无法重新关联终端，确保彻底脱离终端控制。

</Callout>

## 四种 IPC 机制

### 1. 管道（Pipe）与 FIFO

```c
// 管道：父子进程间单向通信
int fd[2];
pipe(fd);          // fd[0]读端, fd[1]写端

if (fork() == 0) {
    // 子进程
    close(fd[1]);  // 关闭写端
    read(fd[0], buf, sizeof(buf));
} else {
    // 父进程
    close(fd[0]);  // 关闭读端
    write(fd[1], "hello", 5);
}

// FIFO：命名管道，任意进程可用
mkfifo("/tmp/myfifo", 0666);
int fd = open("/tmp/myfifo", O_WRONLY);
write(fd, "hello", 5);
```

### 2. 消息队列与信号

```c
// 信号：异步通知
void handler(int sig) {
    // 处理 SIGCHLD / SIGTERM 等
}
signal(SIGCHLD, handler);  // 子进程退出时通知

// Posix 消息队列
mqd_t mqd = mq_open("/myqueue", O_CREAT | O_RDWR, 0666, NULL);
mq_send(mqd, "hello", 5, 0);
mq_receive(mqd, buf, sizeof(buf), NULL);
```

### 3. 共享内存与信号量

```c
// 共享内存：最快的 IPC（零拷贝）
int fd = shm_open("/myshm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);
char *ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

// 信号量：保护共享内存的并发访问
sem_t *sem = sem_open("/mysem", O_CREAT, 0666, 1);

sem_wait(sem);    // P 操作（加锁）
ptr[0] = 'A';     // 安全写共享内存
sem_post(sem);    // V 操作（解锁）
```

### 4. Unix 域套接字

```c
// 本地进程间双向通信，地址为文件路径
int sockfd = socket(AF_LOCAL, SOCK_STREAM, 0);

struct sockaddr_un addr;
addr.sun_family = AF_LOCAL;
strcpy(addr.sun_path, "/tmp/unixsock");

// 服务端
bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));
listen(sockfd, 5);
int connfd = accept(sockfd, NULL, NULL);

// 客户端
connect(sockfd, (struct sockaddr *)&addr, sizeof(addr));
```

## IPC 机制对比

| 机制 | 特点 | 优势 | 适用场景 |
|------|------|------|---------|
| 管道 | 半双工、字节流、亲缘进程 | 简单 | 父子进程 |
| FIFO | 半双工、字节流、任意进程 | 路径关联 | 无亲缘进程 |
| 共享内存 | 零拷贝、需同步 | 最快 | 大数据量 |
| Unix域套接字 | 全双工、可靠、可传fd | 功能全 | 本地服务通信 |

<Glossary>

<GlossaryItem term="守护进程（Daemon）">
守护进程是以后台方式运行的长期服务进程，脱离控制终端，不依赖用户登录会话。守护进程化的核心步骤：fork+setsid 脱离终端、再次 fork 防止重新获取终端、chdir(/) 不占用目录、umask(0) 清除掩码、close 所有终端 fd、重定向 stdin/stdout/stderr 到 /dev/null。网络服务端通常以守护进程方式运行，确保不受终端关闭影响。
</GlossaryItem>

<GlossaryItem term="共享内存（Shared Memory）">
最快的 IPC 机制，因为零拷贝——多个进程将同一块物理内存映射到各自虚拟地址空间，直接读写同一块内存，无需内核中转。管道/消息队列每次通信都要经过内核拷贝。注意：共享内存本身不提供同步机制，必须配合信号量或互斥锁保护并发访问，否则有竞态条件。典型用法：shm_open + mmap 映射，sem_open 创建信号量同步。
</GlossaryItem>

<GlossaryItem term="Unix 域套接字（AF_LOCAL）">
本地进程间通信的套接字，地址为文件系统路径名。与网络套接字区别：不经过网络协议栈（无 IP/TCP 头），只在本地通信，更快更可靠。独特能力：可以通过辅助数据（SCM_RIGHTS）在进程间传递文件描述符——内核在接收进程中创建新 fd 指向同一文件表项。这是 Unix 域套接字独有的能力，适用于本地服务通信、权限委托等场景。
</GlossaryItem>

<GlossaryItem term="管道（Pipe）与 FIFO（命名管道）">
管道由 pipe() 创建，半双工（单向），只能在有亲缘关系的进程间使用（父子进程），fd 通过 fork 继承传递。FIFO 由 mkfifo(path) 创建，存在于文件系统中，任意进程可 open(path) 使用。两者都是字节流，read 空时阻塞，write 到断端（读端已关闭）时触发 SIGPIPE。管道适用于父子进程简单通信，FIFO 适用于无亲缘关系进程。
</GlossaryItem>

</Glossary>

**问题 1：** 守护进程化的核心步骤是什么？为什么要 fork 两次？

<Answer>

核心步骤：①fork() 父进程退出 ②setsid() 创建新会话 ③fork() 再次退出父进程 ④chdir(/) ⑤umask(0) ⑥close 所有终端 fd ⑦重定向 stdin/stdout/stderr 到 /dev/null。fork 两次的原因：第一次 fork+setsid 使进程成为新会话组长脱离控制终端，但会话组长仍可能重新获取终端；第二次 fork 使进程不再是会话组长，无法重新关联终端，确保彻底脱离终端。

</Answer>
