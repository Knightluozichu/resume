## 为什么只记结论不足以掌握网络安全

学习“网络安全”时，第一步不是记住结论，而是冻结输入、上下文、版本和成功标准。只有这些条件明确，网络安全的含义才不会随着样例变化。正文已有的概念说明要与结构图、运行轨迹和失败样本互相印证，不能只凭最终输出看似正确就宣布完成。

结构分析从车载攻击面开始：列出参与者、职责、连接方向、生命周期和所有权，再沿正常路径追踪数据或控制流。每一条边都要说明为什么存在、谁创建、谁消费、谁负责清理；如果边界被跨越，必须能在证据中找到第一处异常。

机制验证要把三道防线写成可以执行的条件。正常样本证明主路径，恰好边界样本验证等号和空值，单故障样本只破坏一个假设。三类样本使用同一份观察指标，避免因为测试口径变化而把偶然结果误认成规律。

成本分析同时记录时间、空间、延迟、耦合、可维护性和不可逆操作。入侵检测不是一句“可能失败”，而是可复现输入、预期停点、实际轨迹、错误分类与清理步骤。任何自动重试都要有次数、预算和幂等边界。

方案比较不能只列优点。需要给出直接实现、当前方案和至少一个替代方案，逐项比较复杂度、扩展点、故障隔离和团队认知成本。当问题规模很小或变化轴稳定时，更简单的实现往往更好；模式与框架必须由真实变化压力证明。

实现阶段把大结论拆成可检查的中间产物：配置快照、结构清单、状态转移、输入输出样本、日志摘要和测试结果。每个产物带来源与生成命令，下一阶段只消费已通过门禁的版本，避免旧缓存或隐式默认值污染结论。

解释结果时必须区分相关性与因果性、接口承诺与实现细节、设计意图与运行事实。对“小结与练习”的判断要由独立证据支持，并明确适用范围；一旦输入分布、版本、硬件或组织边界改变，就重新运行最小实验。

复盘从首个分叉开始，而不是从最后一个报错倒推。先比较冻结输入，再比较第一份结构化中间产物，随后检查状态、约束和副作用。这样可以把复杂系统的排错范围收缩到一个阶段，避免在多个层次同时修改造成新的不确定性。

迁移到真实项目时，先选择一个最小但有代表性的切片，保存改造前基线，再逐步引入“网络安全”中的机制。每一步只改变一个变量并保留回滚点；性能、正确性、安全性和可理解性至少各有一项可量化指标。

最终验收要求读者能脱离页面重新画出结构、口述关键链路、实现最小版本、构造一个反例并解释失败位置。若只能复述名词而不能预测中间状态，说明知识仍停留在识记层，需要回到图示和实验重新验证。

## 可复现的最小实现

先把决策记录写成机器可读结构：

```json
{
  "unit": "网络安全",
  "inputFrozen": true,
  "scenario": "normal | boundary | single-fault",
  "firstDivergence": null,
  "cleanupRequired": true
}
```

再用同一条执行链处理三类样本：

```ts
type Evidence = { stage: string; expected: string; actual: string };

function verify(sample: unknown, expected: readonly Evidence[]) {
  const trace = runFromCleanState(sample);
  return expected.find((item, index) => trace[index]?.actual !== item.expected);
}
```

最后保存回归门禁，禁止失败样本静默通过：

```text
normal      -> complete, invariant preserved
boundary    -> complete or explicit rejection
singleFault -> stop at first divergence, no stale output
```

用统一评分解释实验结果：

$$
Q = C_{correct} + C_{trace} + C_{recover} - R_{residual}
$$

$$
C_{coverage} = \frac{N_{verified}}{N_{official}}
$$

$$
R_{residual} = P(failure) \times I(impact)
$$

$$
Accept = (C_{coverage} \ge 0.90) \land (R_{residual} \le R_{budget})
$$

## 术语表


## 网络安全

功能安全防「自己出错」，网络安全防「被人攻击」。智能汽车联网后，攻击面从物理接触扩展到远程——一辆车可能被千里之外的黑客接管。车载网络安全用纵深防御把攻击层层拦截。

## 车载攻击面

是防御的起点。OTA
升级通道是远程入口——若升级验证被绕过，攻击者可刷入恶意固件。OBD
诊断口是物理入口——维修时直连总线，可注入报文。车机 WiFi
与蓝牙是近场入口——可被中间人或欺骗。T-Box（车载联网单元）是远程通信入口——连蜂窝网络，若被攻破可直达车内总线。

这些入口的共同威胁是「以点破面」：攻破一个弱入口后，若车内网络没分段隔离，攻击者可横向移动到刹车、转向等关键 ECU。所以防御第一原则是纵深与隔离——入口要硬，内部要分。

## 三道防线

（Secure Onboard Communication）护报文安全。传统 CAN 报文无认证，谁都能发。SecOC
给每条关键报文附加
MAC（消息认证码）与计数器：发送方用密钥签名，接收方验签才执行；计数器防重放——旧报文重发计数器对不上即拒收。代价是增加总线负载与
ECU 算力开销，所以只用于安全关键报文。

护固件完整。从 bootloader 起逐级验证下一级镜像的签名：bootloader
验内核、内核验驱动与应用，任一级验签失败即拒绝启动。信任根是烧在芯片里不可改的根公钥。安全启动保证车上跑的软件是
OEM 签名的正版，防刷恶意固件。

（Hardware Security Module）护密钥。密钥不能存在普通内存里被随便读取，而要锁进
HSM 这个独立安全芯片——私钥永不出 HSM，签名与解密在 HSM 内完成。HSM 是 SecOC
签名与安全启动验签的信任根载体，被攻破软件也拿不到密钥。

## 入侵检测

是最后一道纵深防线。前三道防「未授权的访问与篡改」，但零日漏洞或内部被攻破时仍可能漏过。IDS（入侵检测系统）监测车内总线流量——异常高频报文、未知
ID、不合规周期——发现可疑行为告警；IPS（入侵防御系统）进一步主动阻断，如切断被攻破
ECU 的总线通信。

IDS/IPS 的价值是「假定防线已被突破」的兜底：即使攻击者绕过了认证与签名，异常行为模式仍会被检测。它是纵深防御的最后一层，把「防不住」变成「至少能发现」。


## 小结与练习

- 车载攻击面：OTA（远程固件）、OBD（物理总线）、WiFi/蓝牙（近场）、T-Box（远程通信）
- SecOC 给报文加签名与计数器防伪造重放；安全启动逐级验签防篡改固件；HSM 隔离密钥防窃取
- IDS/IPS 监测异常报文与行为，是「假定防线已被突破」的兜底纵深防线
- 纵深防御六层：入口加固→内部分隔→报文认证→启动验签→密钥隔离→异常检测
