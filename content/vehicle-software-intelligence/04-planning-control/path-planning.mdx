## 为什么只记结论不足以掌握路径规划

学习“路径规划”时，第一步不是记住结论，而是冻结输入、上下文、版本和成功标准。只有这些条件明确，路径规划的含义才不会随着样例变化。正文已有的概念说明要与结构图、运行轨迹和失败样本互相印证，不能只凭最终输出看似正确就宣布完成。

结构分析从全局规划开始：列出参与者、职责、连接方向、生命周期和所有权，再沿正常路径追踪数据或控制流。每一条边都要说明为什么存在、谁创建、谁消费、谁负责清理；如果边界被跨越，必须能在证据中找到第一处异常。

机制验证要把局部规划写成可以执行的条件。正常样本证明主路径，恰好边界样本验证等号和空值，单故障样本只破坏一个假设。三类样本使用同一份观察指标，避免因为测试口径变化而把偶然结果误认成规律。

成本分析同时记录时间、空间、延迟、耦合、可维护性和不可逆操作。行为预测与轨迹优化不是一句“可能失败”，而是可复现输入、预期停点、实际轨迹、错误分类与清理步骤。任何自动重试都要有次数、预算和幂等边界。

方案比较不能只列优点。需要给出直接实现、当前方案和至少一个替代方案，逐项比较复杂度、扩展点、故障隔离和团队认知成本。当问题规模很小或变化轴稳定时，更简单的实现往往更好；模式与框架必须由真实变化压力证明。

实现阶段把大结论拆成可检查的中间产物：配置快照、结构清单、状态转移、输入输出样本、日志摘要和测试结果。每个产物带来源与生成命令，下一阶段只消费已通过门禁的版本，避免旧缓存或隐式默认值污染结论。

解释结果时必须区分相关性与因果性、接口承诺与实现细节、设计意图与运行事实。对“小结与练习”的判断要由独立证据支持，并明确适用范围；一旦输入分布、版本、硬件或组织边界改变，就重新运行最小实验。

复盘从首个分叉开始，而不是从最后一个报错倒推。先比较冻结输入，再比较第一份结构化中间产物，随后检查状态、约束和副作用。这样可以把复杂系统的排错范围收缩到一个阶段，避免在多个层次同时修改造成新的不确定性。

迁移到真实项目时，先选择一个最小但有代表性的切片，保存改造前基线，再逐步引入“路径规划”中的机制。每一步只改变一个变量并保留回滚点；性能、正确性、安全性和可理解性至少各有一项可量化指标。

最终验收要求读者能脱离页面重新画出结构、口述关键链路、实现最小版本、构造一个反例并解释失败位置。若只能复述名词而不能预测中间状态，说明知识仍停留在识记层，需要回到图示和实验重新验证。

## 可复现的最小实现

先把决策记录写成机器可读结构：

```json
{
  "unit": "路径规划",
  "inputFrozen": true,
  "scenario": "normal | boundary | single-fault",
  "firstDivergence": null,
  "cleanupRequired": true
}
```

再用同一条执行链处理三类样本：

```ts
type Evidence = { stage: string; expected: string; actual: string };

function verify(sample: unknown, expected: readonly Evidence[]) {
  const trace = runFromCleanState(sample);
  return expected.find((item, index) => trace[index]?.actual !== item.expected);
}
```

最后保存回归门禁，禁止失败样本静默通过：

```text
normal      -> complete, invariant preserved
boundary    -> complete or explicit rejection
singleFault -> stop at first divergence, no stale output
```

用统一评分解释实验结果：

$$
Q = C_{correct} + C_{trace} + C_{recover} - R_{residual}
$$

$$
C_{coverage} = \frac{N_{verified}}{N_{official}}
$$

$$
R_{residual} = P(failure) \times I(impact)
$$

$$
Accept = (C_{coverage} \ge 0.90) \land (R_{residual} \le R_{budget})
$$

## 术语表


## 路径规划

规划是感知与控制之间的桥梁——感知告诉车世界长什么样，规划决定车接下来怎么走，控制再把规划变成方向盘与踏板。规划分两层：全局规划找「从哪到哪」的路线，局部规划生成「此刻怎么走」的轨迹。

## 全局规划

在地图路网上找一条从起点到终点的路线，类似导航。它把道路抽象成图（节点是路口、边是道路段、权重是距离或时间），用图搜索算法求最短路径。Dijkstra
算法从起点逐步扩展到所有节点、保证全局最短但慢；A*
加启发函数（如到终点的直线距离）引导搜索方向、更快收敛到目标。全局规划的输出是一条道路级路线，不关心此刻周围有什么障碍。

全局规划只在出发时或偏离路线时算一次，对实时性要求低，追求全局最优。

## 局部规划

在全局路线的框架内，结合实时感知的障碍物，生成未来几秒内可执行的轨迹（位置、速度、时间）。它要同时满足安全（不撞障碍、不出车道）、舒适（加速度与急动度有界）、合规（遵守限速与让行）、可达（符合车辆动力学约束）。

局部规划常用。它以道路中心线为基准，用纵向位移 s（沿道路走了多远）与横向偏移 L（离中心线多远）描述位置。好处是把「沿路走」与「换道」解耦：纵向规划管速度（跟车、加速、减速），横向规划管换道与避让，两者分别优化再合并，比笛卡尔坐标直观得多。

## 行为预测与轨迹优化

规划不是只管自己，还要预测别人。估计周围车辆与行人的未来轨迹——前车会不会变道、行人会不会横穿。预测给规划一个「动态世界」，让规划提前应对而非被动反应。预测不准是多数规划事故的根源：若预测前车不会变道而它变了，规划来不及避让。

把候选轨迹变成最优轨迹。它在 Frenet
空间采样多条候选轨迹（不同纵向速度曲线与横向换道曲线），用代价函数评估每条（碰撞代价、偏离全局路线代价、舒适度代价、合规代价），选代价最低的输出给控制。代价函数的权重调校是工程核心：太偏安全会让车过于保守被频繁加塞，太偏舒适会冒险贴近障碍。


## 小结与练习

- 全局规划在路网图上用 A\*/Dijkstra 找路线，道路级、低频、求全局最优
- 局部规划结合实时障碍生成短时轨迹，用 Frenet 坐标系解耦纵横向，高频、求安全舒适
- 行为预测给规划动态世界，预测时域与不确定性裕度决定规划是预判还是救火
- 轨迹优化用代价函数评估候选，安全是硬约束、急动度衡量舒适度
