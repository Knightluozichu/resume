## 直觉引入

把 Vue.js 想象成一座工厂。原料是「数据」，产品是「页面上的 DOM」。要让原料自动变成产品，你需要一条流水线：第一段是「感知」——数据一变，系统能察觉到（响应式系统）；第二段是「加工」——把数据描述的虚拟结构变成真实 DOM（渲染器）；第三段是「组织」——把界面拆成可复用的积木块（组件模型）；第四段是「优化」——把模板翻译成高效的渲染代码（编译器）；第五段是「调度」——处理缓存、传送、异步等特殊渲染需求（内置组件）。本书回答的就是这些「从能感知到能调度」的 Vue 源码设计问题。

## 五层递进

<Term def="Vue 的设计是以响应式系统为数据驱动引擎、用渲染器把虚拟节点转为平台节点、用组件封装可复用结构、用编译器把模板编译为渲染函数、用内置组件处理缓存与异步等特殊渲染的分层体系。">Vue 设计体系</Term>的学习可以拆成五个递进层次。**响应式系统**包括 Proxy 拦截与副作用调度——它们解决「数据变了谁能知道」和「变化后做什么」，是所有上层逻辑的地基。**渲染器**包括挂载、卸载、patch 与 Diff 算法——它们决定「虚拟结构怎么变成真实节点」和「更新时怎么最小化操作」。**组件模型**包括 setup、Props、emit、slots——它们让界面「能抽象」和「能复用」。**编译器**包括 Parse、Transform、Generate——它们把模板编译成渲染函数并做编译期优化。**内置组件**包括 KeepAlive、Teleport、Suspense——它们处理缓存、传送、异步等渲染器无法直接覆盖的特殊场景。

```javascript
// 一次「数据变化 → 触发更新 → 编译优化 → Diff → DOM 更新」的 Vue 运行时链路
import { ref, effect } from "vue";

const count = ref(0); // 1. 响应式层：ref 创建响应式数据（第 2 章响应式设计）

// 2. 副作用层：effect 注册副作用，count 变时通过 scheduler 决定做什么（第 3 章）
effect(() => {
  console.log("count 是", count.value); // track 登记 effect
});

// 3. 渲染层：组件 render() 产出 VNode，patch 挂载/更新 DOM（第 4-5 章）
// 4. 组件层：setup 提供状态，props/emit 通信（第 6-7 章）
// 5. 编译层：模板经编译器生成 render，含 patchFlag 优化（第 8 章）
// 6. 内置组件：KeepAlive 缓存、Teleport 传送、Suspense 协调（第 9 章）
```

## 常见误区

<Callout type="trap">
**误区：会用 Vue 就等于懂 Vue 的设计。** 调 API、搭模板、写 setup 只是表层——照文档抄就会。真正理解 Vue 在于搞懂设计动机：为什么用 Proxy 而不是 Object.defineProperty；为什么渲染器要与平台解耦；为什么 Diff 要分双端和快速两种；为什么编译器要在 Transform 阶段注入 patchFlag；为什么 KeepAlive 卸载时不断 DOM 而是移到隐藏容器。这些是「源码层面」的问题，也是区分「使用者」与「实现者」的标志。把 API 当终点的人，遇到框架升级只会重学语法；把设计当核心的人，能举一反三理解任何响应式框架。
</Callout>

<Exercises>
**问题 1**：全书五层递进是什么？为什么是这个顺序？

<Answer>
响应式系统（Proxy/track/trigger）→ 渲染器（挂载/卸载/patch/Diff）→ 组件模型（setup/Props/emit）→ 编译器（Parse/Transform/Generate）→ 内置组件（KeepAlive/Teleport/Suspense）→ 总复习。顺序由依赖关系决定：没有响应式就没有「数据变则通知」的机制；没有响应式通知就没有需要渲染器去更新的视图；没有渲染器就没有组件可挂载的载体；没有组件就没有编译器要编译的模板（组件的 template）；没有前面四层，内置组件的特殊调度就无从附着。先「能感知」，再「能渲染」，然后「能抽象」，接着「能编译」，最后「能调度」。
</Answer>

**问题 2（实现题）**：用「一次数据变化到视图更新」的链路，说明全书十章各自扮演什么角色。

<Answer>
count.value++：①响应式设计——ref 的 set 拦截触发 trigger，从 targetMap 取出依赖该数据的 effect（第 2 章）；②副作用调度——scheduler 决定 effect 何时重跑，computed 标脏、watch 执行回调（第 3 章）；③渲染器架构——组件的 render effect 重跑产出新 VNode，patch 比对新旧 VNode（第 4 章）；④Diff 算法——子节点用快速 Diff 预处理头尾，未知序列用 LIS 最小化移动（第 5 章）；⑤组件模型——若 count 在子组件，props 变触发子组件重渲染（第 6 章）；⑥异步组件——若子组件是异步加载的，defineAsyncComponent 管理加载状态（第 7 章）；⑦编译器——模板经编译生成 render，patchFlag 标记动态节点跳过静态比对（第 8 章）；⑧内置组件——若子组件被 KeepAlive 包裹，切走时缓存不卸载（第 9 章）。学习地图（第 1 章）给方向，总复习（第 10 章）串闭环。
</Answer>

<GlossaryItem term="Vue 设计体系">以响应式系统为数据驱动引擎、用渲染器把虚拟节点转为平台节点、用组件封装可复用结构、用编译器把模板编译为渲染函数、用内置组件处理缓存与异步等特殊渲染的分层体系。所有 Vue 运行时能力建立在这五层之上。</GlossaryItem>
<GlossaryItem term="五层递进">响应式系统 → 渲染器 → 组件模型 → 编译器 → 内置组件。每层解决前一层的遗留问题：响应式层能感知但无视觉，渲染器补视觉；渲染器能渲染但不可复用，组件补抽象；组件能抽象但手写 render 繁琐，编译器补模板；编译器能编译但缓存/异步/传送无法直接表达，内置组件补特殊调度。</GlossaryItem>
<GlossaryItem term="运行时链路">一次数据变化从触发到视图更新的完整路径：响应式 trigger（第 2 章）→ scheduler 调度（第 3 章）→ render 产出 VNode + patch（第 4 章）→ Diff 子节点（第 5 章）→ 组件 props 更新（第 6-7 章）→ 编译优化跳过静态（第 8 章）→ 内置组件特殊处理（第 9 章）。全书以这条链路串联各章节。</GlossaryItem>
