## 机制拆解

### 1. 建立机制边界

依赖桶使用WeakMap按target保存Map，再按key保存Set；读取时把activeEffect加入集合，并反向记录到effect.deps。每次执行前cleanup旧集合，才能让条件分支切换后不再响应已离开的依赖。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 2. 处理关键算法

嵌套组件会嵌套执行effect，单个activeEffect变量不足，必须用栈恢复父effect。trigger复制待执行集合，跳过当前activeEffect避免同步自触发；scheduler把执行交给微任务队列并去重。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

computed使用lazy effect和dirty标记，依赖变化只标脏并触发读取者；watch遍历来源或执行getter，保存旧值，并通过失效回调阻止过期异步结果提交。立即执行和flush时机都属于可观察契约。

function effect(fn, options = {}) {
  const run = () => {
    cleanup(run);
    activeStack.push(run);
    fn();
    activeStack.pop();
  };
  run.deps = [];
  run.scheduler = options.scheduler;
  run();
  return run;
}

## 小结

- **副作用函数**：执行时会读取响应式状态并产生外部可观察结果的函数。
- **响应式数据**：读取可被追踪、写入可触发相关副作用重新执行的数据。
- **依赖桶**：按目标对象和属性键保存其关联副作用集合的数据结构。
- **effect栈**：保存嵌套副作用执行上下文、确保依赖归属正确的栈。
- **调度器**：接管副作用触发后的执行时机、顺序和去重策略的函数。
