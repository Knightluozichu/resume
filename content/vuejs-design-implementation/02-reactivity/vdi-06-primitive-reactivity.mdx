## 机制拆解

### 1. 建立机制边界

ref把原始值放在value属性上并使用响应式对象，从而让读取和写入经过track与trigger。标记ref身份不能只靠形状猜测，应使用不可枚举内部标记或受控API。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 2. 处理关键算法

直接解构响应式对象得到普通值，后续读取不再经过代理。toRef返回getter/setter形式的ref并继续指向原属性，toRefs批量映射，解决的是连接丢失而不是复制数据。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

proxyRefs读取时自动返回ref.value，写入普通值时写回旧ref.value，写入新ref时替换引用。脱ref只发生在明确边界，否则数组、集合和嵌套对象会出现难以预测的身份变化。

## 最小可运行实验

```js
function toRef(object, key) {
  return {
    get value() {
      return object[key];
    },
    set value(v) {
      object[key] = v;
    },
  };
}
const count = toRef(state, "count");
```

## 小结

- **ref**：用带value属性的对象承载原始值并参与响应追踪的容器。
- **toRef**：把响应式对象某个属性映射为保持双向联系的ref。
- **toRefs**：把响应式对象的各个可枚举属性批量转换为对应ref。
- **自动脱ref**：在特定读取上下文中自动返回ref的value、减少显式访问的行为。
- **响应丢失**：解构或复制属性后，读取不再经过原代理而失去追踪关系的现象。
