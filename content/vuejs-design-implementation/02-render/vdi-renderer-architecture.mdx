## 直觉引入

响应式系统只负责「数据变了通知谁」，但通知之后「怎么把数据变成页面上的东西」是渲染器的职责。渲染器的输入是 VNode（虚拟节点），输出是真实节点（DOM/Canvas/字符串）。它做三件事：mount（把 VNode 变成真实节点挂到容器上）、unmount（把真实节点从容器移除）、patch（比对新旧 VNode，只更新差异部分）。巧妙之处在于：渲染器把「怎么创建节点」「怎么插入节点」这些平台相关操作抽成 options 参数注入，换个 options 就能渲染到任意目标。

## 渲染器三大操作

<Term def="渲染器是把 VNode 转为平台节点的系统，核心由 mount（挂载）、unmount（卸载）、patch（更新）三大操作组成，通过 createRenderer(options) 注入平台操作实现跨平台。">渲染器</Term>的入口是 `render(vnode, container)`。若 container 为空且 vnode 存在 → mount；若 vnode 为空且 container 有内容 → unmount；若新旧 vnode 都存在 → patch。mount 的流程：根据 vnode.type 调 `options.createElement` 创建节点 → `options.patchProps` 设置属性 → 递归 mount 子节点 → `options.insert` 插入容器。patch 的流程：若新旧类型不同 → unmount 旧的 + mount 新的；若同类型元素 → 复用 el + patchProps 更属性 + patch 子节点；若同类型组件 → 更新 props 触发重渲染。

```javascript
// 渲染器核心设计（简化）
function createRenderer(options) {
  const { createElement, insert, remove, patchProps } = options;

  function mount(vnode, container) {
    const el = vnode.el = createElement(vnode.type); // 创建
    if (typeof vnode.children === "string") {
      el.textContent = vnode.children; // 文本子节点
    } else if (Array.isArray(vnode.children)) {
      vnode.children.forEach((c) => mount(c, el)); // 递归挂载
    }
    if (vnode.props) {
      for (const key in vnode.props) patchProps(el, key, null, vnode.props[key]);
    }
    insert(el, container); // 插入容器
  }

  function patch(n1, n2, container) {
    if (n1.type !== n2.type) { unmount(n1); mount(n2, container); return; }
    const el = n2.el = n1.el; // 复用真实节点
    patchProps(el, /* diff props */);
    patchChildren(n1, n2, el); // Diff 子节点（下一章详解）
  }

  function render(vnode, container) {
    const prev = container._vnode;
    if (vnode) {
      if (prev) patch(prev, vnode, container);
      else mount(vnode, container);
    } else if (prev) unmount(prev);
    container._vnode = vnode;
  }
  return { render };
}
```

## 自定义渲染器：平台解耦

`createRenderer` 的设计精髓在于把平台操作抽成 options。浏览器渲染器注入 `document.createElement`、`parent.appendChild` 等；要渲染到 Canvas，注入 `ctx.fillRect`、`ctx.drawImage` 等；要渲染到字符串（SSR），注入字符串拼接逻辑。渲染器核心逻辑（mount/unmount/patch/Diff）完全复用，只换 options。

```javascript
// 浏览器渲染器
const browserRenderer = createRenderer({
  createElement: (tag) => document.createElement(tag),
  insert: (el, parent) => parent.appendChild(el),
  remove: (el) => el.parentNode.removeChild(el),
  patchProps: (el, key, oldVal, newVal) => { if (newVal == null) el.removeAttribute(key); else el.setAttribute(key, newVal); },
});

// 自定义渲染器：渲染到 Canvas（示意）
const canvasRenderer = createRenderer({
  createElement: (type) => ({ type, children: [] }),
  insert: (el, parent) => { parent.children.push(el); /* 调用 ctx 绘制 */ },
  // ...
});
```

## 常见误区

<Callout type="trap">
**误区：渲染器就是操作 DOM。** 浏览器渲染器确实操作 DOM，但渲染器本身的设计是与平台无关的——平台操作被抽成 options 注入。`createRenderer(options)` 返回的 render 函数，核心逻辑（VNode 树遍历、patch 比对、Diff 算法）不依赖任何具体平台。把渲染器等同于 DOM 操作，就无法理解 Vue 怎么做 SSR（渲染到字符串）和自定义渲染器（渲染到 Canvas）。
</Callout>

<Callout type="trap">
**误区：patch 时同类型元素会创建新的 DOM 节点。** 恰恰相反——patch 同类型元素时复用旧的真实节点 `n2.el = n1.el`，只更新属性和子节点。创建新 DOM 节点发生在类型不同（unmount 旧 + mount 新）或首次 mount 时。复用是 patch 高效的关键，避免了销毁重建的开销。
</Callout>

<Exercises>
**问题 1**：渲染器的 mount、unmount、patch 各自做什么？render 函数如何在这三者间分发？

<Answer>
mount 把 VNode 转为真实节点并插入容器（创建节点 → 设属性 → 递归挂子节点 → 插入）。unmount 把真实节点从容器移除。patch 比对新旧 VNode 更新差异（类型不同则 unmount+mount；同类型元素复用 el 更新属性和子节点；同类型组件更新 props 重渲染）。render(vnode, container) 的分发逻辑：若 container 已有旧 vnode（prev）且新 vnode 存在 → patch；若无 prev 且新 vnode 存在 → mount；若新 vnode 为空且有 prev → unmount。
</Answer>

**问题 2（实现题）**：为什么说 createRenderer 实现了平台解耦？给一个渲染到字符串的 options 雏形。

<Answer>
createRenderer 把所有平台相关操作（createElement/insert/remove/patchProps）抽成 options 参数注入，渲染器核心逻辑（mount/unmount/patch/Diff）只调用 options 接口，不直接调用 document.* 或 ctx.*。换 options 就换渲染目标，核心复用。渲染到字符串的 options 雏形：
```javascript
const stringRenderer = createRenderer({
  createElement: (tag) => ({ tag, attrs: {}, children: [] }),
  insert: (el, parent) => { parent.children.push(el); },
  remove: (el) => { /* 从 parent.children 移除 */ },
  patchProps: (el, key, oldVal, newVal) => { el.attrs[key] = newVal; },
});
// 最后序列化：serialize(vnode) → '<div class="x">hello</div>'
```
渲染器核心的 mount/patch 逻辑不变，只是「节点」从 DOM 元素变成了普通对象，最后序列化成字符串。
</Answer>
</Exercises>
