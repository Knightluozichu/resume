## 直觉引入

当应用变大，把所有组件打包在一起会让首屏加载很慢。异步组件解决「按需加载」：用到时才去请求组件代码。但加载是异步的——加载中显示什么？加载失败显示什么？超时怎么办？`defineAsyncComponent` 用一个状态机管理这些。更进一步，如果一个页面有多个异步组件，你希望「全部加载完再一起显示」而不是「一个一个跳出来」——`Suspense` 就是协调多个异步子树的指挥家。

## defineAsyncComponent 状态机

<Term def="异步组件是用 defineAsyncComponent 包装一个返回 Promise 的 loader 函数，内部用 pending/resolved/rejected 状态机管理加载过程，支持 loading/error 组件、延迟、超时、重试的机制。">异步组件</Term>返回一个包装组件。首次渲染时调用 loader() 发起加载，状态为 pending（渲染 loadingComponent）；loader 的 Promise resolve 后状态切 resolved（缓存真实组件并渲染）；reject 切 rejected（渲染 errorComponent）。配置项：`delay` 控制 loading 显示前的延迟（避免加载太快时 loading 闪烁）；`timeout` 超时自动切 rejected；`errorComponent`/`loadingComponent` 自定义占位；`onError` 支持重试。

```javascript
// 异步组件使用
const AsyncComp = defineAsyncComponent({
  loader: () => import("./HeavyComp.vue"), // 返回 Promise
  loadingComponent: Loading,   // 加载中显示
  errorComponent: Error,       // 加载失败显示
  delay: 200,                   // 200ms 内加载完不显示 loading（防闪烁）
  timeout: 3000,                // 3s 超时切 rejected
});

// 路由懒加载本质就是异步组件
const routes = [
  { path: "/detail", component: () => import("./Detail.vue") },
];
```

## Suspense：协调多异步子树

<Term def="Suspense 是协调多个异步子树挂载时机的内置组件，子树的 async setup 返回 Promise 时挂起并显示 fallback，全部 resolve 后统一提交 DOM。">Suspense</Term>包裹异步子组件。当子树的 setup 是 async（返回 Promise），Suspense 把子树挂起（不提交 DOM），收集所有异步依赖；全部 resolve 后才统一提交 DOM 显示 #default 内容；任一 reject 触发 onError。挂起期间显示 #fallback 插槽。

```vue
<!-- Suspense 协调 -->
<Suspense>
  <template #default>
    <UserProfile />  <!-- async setup: 异步获取用户数据 -->
    <UserPosts />    <!-- async setup: 异步获取文章列表 -->
  </template>
  <template #fallback>
    <Loading />  <!-- 两个都加载完之前显示 -->
  </template>
</Suspense>
```

## 异步组件 vs Suspense

异步组件解决「单个组件按需加载 + 加载状态管理」；Suspense 解决「多个异步子树统一协调」。两者可组合：Suspense 内放异步组件，统一管理加载态。路由懒加载的本质就是异步组件——`() => import()` 返回 Promise，路由匹配后等 Promise resolve 再渲染。

## 常见误区

<Callout type="trap">
**误区：异步组件加载完就一直缓存，不会再加载。** 默认 resolved 后缓存真实组件，下次渲染直接用缓存不再调 loader。但如果用 Suspense 包裹且子树重新挂载，或手动修改加载逻辑，可能重新加载。另外 onError 重试时会重新调 loader。理解「缓存 resolved 结果」是默认行为，但不是绝对的。
</Callout>

<Callout type="trap">
**误区：Suspense 内所有异步必须同时完成。** Suspense 的协调是「收集所有异步依赖，全部 resolve 后提交」。如果某个子组件的 async setup 永远不 resolve，整个 Suspense 会一直显示 fallback。实际开发中要给异步操作加超时和错误处理，避免永远挂起。
</Callout>

<Exercises>
**问题 1**：defineAsyncComponent 的状态机有哪几个状态？delay 和 timeout 各解决什么问题？

<Answer>
三个状态：pending（加载中，渲染 loadingComponent）、resolved（加载成功，缓存并渲染真实组件）、rejected（加载失败，渲染 errorComponent）。delay 解决「加载太快时 loading 闪烁」——设置 delay 后，loadingComponent 在 delay 毫秒后才显示，若在这之前已 resolved 则不显示 loading。timeout 解决「加载卡死」——超过 timeout 毫秒自动切 rejected 显示 errorComponent，避免用户无限等待。两者互补：delay 防快闪，timeout 防卡死。
</Answer>

**问题 2（实现题）**：为什么说路由懒加载本质就是异步组件？说明原理。

<Answer>
路由懒加载写法 `component: () => import('./Detail.vue')`，`() => import()` 返回一个 Promise，resolve 后得到组件定义。这正好符合 defineAsyncComponent 的 loader 签名。路由内部用 defineAsyncComponent 包装这个 loader：匹配路由时触发 loader 加载组件代码（Webpack/Vite 会把 Detail.vue 单独打成一个 chunk），pending 时路由视图可显示 loading，resolved 后渲染组件。所以路由懒加载 = 异步组件 + 动态 import 实现代码分割。好处：首屏不加载详情页代码，按需请求减小首屏体积。
</Answer>
