## 机制拆解

### 1. 建立机制边界

createRenderer接收createElement、setElementText、insert等宿主操作，render把新VNode与容器.\_vnode比较。传入null时卸载旧树，完成状态与宿主节点的对称生命周期。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 2. 处理关键算法

patch根据VNode type区分字符串元素、Text、Comment、Fragment和组件，再决定mount或patch。把平台API写死在核心里会阻止非DOM渲染，也让测试必须依赖浏览器。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

组件render放入effect，首次执行挂载子树，后续状态变化生成新子树并patch。scheduler把多次同步写入合并为一个任务，渲染器不应自行订阅每个状态。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

## 最小可运行实验

```js
function render(vnode, container) {
  if (vnode) patch(container._vnode || null, vnode, container);
  else if (container._vnode) unmount(container._vnode);
  container._vnode = vnode;
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：渲染器核心直接调用document，所谓自定义渲染器只换了容器参数。**
  必须保存输入、执行轨迹和首偏离点，而不是只比较最终结果。
</Callout>

<Callout type="trap">
  **误区二：容器不保存旧VNode，每次render都重新挂载并留下旧节点。**
  必须加入失败与恢复样本，并检查依赖、节点、任务和状态是否清理。
</Callout>

## 小结

- **渲染器**：把虚拟节点映射到宿主平台元素并负责挂载、更新和卸载的模块。
- **宿主操作**：创建元素、设置文本、插入、删除和设置属性等平台相关能力。
- **VNode**：描述元素、组件、文本或片段类型、属性和子节点的虚拟节点。
- **响应系统**：追踪状态读取、触发相关副作用并控制更新执行的模块。
- **自定义渲染器**：通过注入宿主操作把同一渲染核心适配到DOM之外平台的渲染器。
- 官方目录、最小实现、故障注入与恢复证据已经放进同一验收链。
