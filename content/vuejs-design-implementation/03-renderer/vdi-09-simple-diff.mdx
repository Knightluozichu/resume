## 机制拆解

### 1. 建立机制边界

key只在同层兄弟之间表达身份。找到相同key且类型兼容的旧VNode后先patch复用DOM；没有key或重复key会退化查找并让组件状态绑定错误实体。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 2. 处理关键算法

按新顺序遍历时维护lastIndex。如果匹配旧节点索引小于lastIndex，它需要移动；否则更新lastIndex。移动时以新序列前一个节点的下一个兄弟作为锚点插入。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

新节点无匹配时按同样锚点挂载。完成新序列后再遍历旧序列，key在新序列不存在的节点需要卸载。这个算法清楚但O(n²)，为后续Diff优化提供基线。

## 最小可运行实验

```js
let lastIndex = 0;
for (const newVNode of newChildren) {
  const oldIndex = oldChildren.findIndex((v) => v.key === newVNode.key);
  if (oldIndex >= 0) lastIndex = Math.max(lastIndex, oldIndex);
}
```
