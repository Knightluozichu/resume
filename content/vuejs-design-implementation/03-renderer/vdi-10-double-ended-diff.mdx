## 机制拆解

### 1. 建立机制边界

维护oldStart、oldEnd、newStart、newEnd四个索引。头头和尾尾匹配只patch推进；旧头与新尾匹配把旧头移到旧尾后；旧尾与新头匹配把旧尾移到旧头前。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 2. 处理关键算法

四种都不匹配时，在旧中段查找newStart.key。找到则patch并移动到旧头前，把旧位置设undefined形成空洞；找不到说明是新节点，直接在旧头锚点前挂载。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

循环结束后，如果旧区间耗尽，把剩余新节点插到newEnd后一个节点对应锚点前；如果新区间耗尽，卸载剩余非空旧节点。边界索引决定新增顺序。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

## 最小可运行实验

```js
while (oldStart <= oldEnd && newStart <= newEnd) {
  if (!oldChildren[oldStart]) oldStart++;
  else if (same(oldChildren[oldStart], newChildren[newStart])) { patch(...); oldStart++; newStart++; }
  else handleCrossOrFallback();
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：移动后不把旧数组位置标空，后续再次处理同一VNode并重复操作DOM。**
  必须保存输入、执行轨迹和首偏离点，而不是只比较最终结果。
</Callout>

<Callout type="trap">
  **误区二：旧区间先耗尽时一律append，忽略剩余新节点应插入的锚点。**
  必须加入失败与恢复样本，并检查依赖、节点、任务和状态是否清理。
</Callout>
