## 机制拆解

### 1. 建立机制边界

先从左、右两端patch相同节点，常见追加和删除可直接结束。剩余中段若一侧耗尽，只需按锚点挂载或卸载另一侧区间。

### 2. 处理关键算法

复杂中段为新节点建立key到索引映射，source初始化-1。遍历旧节点时找到新索引、patch并写入旧位置；newIndex小于maxNewIndexSoFar说明相对顺序逆转，需要移动。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

对source求最长递增子序列，它代表可保持原DOM相对顺序的节点。逆序遍历新中段：-1项挂载，不在LIS中的项移动，LIS项保持；逆序保证右侧锚点已经存在。

const source = new Array(toBePatched).fill(-1);
for (let oldIndex = start; oldIndex <= oldEnd; oldIndex++) {
  const newIndex = keyToNewIndex.get(oldChildren[oldIndex].key);
  if (newIndex !== undefined) source[newIndex - newStart] = oldIndex;
}

## 常见误区与故障注入

<Callout type="trap">
  **误区一：source记录新索引而不是旧索引，LIS结果无法表示旧DOM相对顺序。**
  必须保存输入、执行轨迹和首偏离点，而不是只比较最终结果。
</Callout>

<Callout type="trap">
  **误区二：正序执行移动，目标右侧锚点尚未就位导致最终顺序错误。**
  必须加入失败与恢复样本，并检查依赖、节点、任务和状态是否清理。
</Callout>

## 小结

- **快速Diff**：先处理公共前后缀，再用索引映射和最长递增子序列最小化移动的算法。
- **前置节点**：新旧子序列从左侧开始连续相同、可直接更新的公共节点。
- **后置节点**：新旧子序列从右侧开始连续相同、可直接更新的公共节点。
- **source数组**：记录新中段节点在旧中段对应位置、用于判断新增与移动的数组。
- **最长递增子序列**：source中保持相对顺序的最长索引序列，对应无需移动的节点。
