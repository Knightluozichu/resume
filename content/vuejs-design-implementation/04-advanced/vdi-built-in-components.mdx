## 直觉引入

普通组件的挂载/卸载由渲染器统一处理，但有些场景渲染器的默认行为不够用：①切走的组件不想销毁（想保留状态和滚动位置）——KeepAlive；②弹窗要渲染到 body 下避免被父级 overflow 裁剪——Teleport；③多个异步组件要一起加载完再显示——Suspense。这三大内置组件本质上是渲染器在 patch 阶段识别出的特殊 VNode 类型，走各自的专属处理分支。

## KeepAlive：缓存组件实例

<Term def="KeepAlive 是缓存组件实例的内置组件，切走时不断开 DOM 而是移到隐藏容器缓存，切回时移回原位复用实例，用 LRU 策略限制缓存数量。">KeepAlive</Term>包裹动态组件。普通组件切走时 unmount 销毁实例和 DOM；KeepAlive 切走时把组件的 DOM 移到一个隐藏的存储容器（不销毁），实例状态保留；切回时把 DOM 从隐藏容器移回原位，复用实例（不重新 setup）。配置：`include`/`exclude` 按组件名过滤缓存；`max` 限制最大缓存数，超出用 LRU（最近最少使用）淘汰最久未访问的。生命周期：`onActivated`（从缓存激活时触发）、`onDeactivated`（移入缓存时触发）。

```vue
<!-- KeepAlive 缓存 Tab 切换的组件 -->
<KeepAlive :include="['TabA', 'TabB']" :max="5">
  <component :is="currentTab" />
</KeepAlive>
<!-- 切走 currentTab 时不销毁，保留 TabA 的输入框值、滚动位置 -->
```

## Teleport：跨容器传送

<Term def="Teleport 是把子树渲染到 to 属性指定容器的内置组件，子树的逻辑归属（props/slots）不变，但真实 DOM 插入到别处。">Teleport</Term>接收 `to` 属性指定目标容器。子树 VNode 正常 patch（走渲染器逻辑），但插入操作改到 `to` 指定的容器。这样弹窗、通知的 DOM 可以脱离父组件的层级，避免被父级的 `overflow: hidden` 裁剪或 `z-index` 嵌套问题。`disabled` 属性为 true 时禁用传送，回退到就近渲染。逻辑上子树仍属于 Teleport 组件（props、事件、响应式不变），只是视觉位置分离。

```vue
<!-- 弹窗传送到 body，避免被父级 overflow 裁剪 -->
<Teleport to="body">
  <Modal v-if="show" @close="show = false" />
</Teleport>
```

## Suspense：协调异步子树

（与第 7 章呼应）<Term def="Suspense 在内置组件层面协调异步子树，子树 async setup 返回 Promise 时挂起显示 fallback，全部 resolve 后提交。">Suspense</Term>作为内置组件，在 patch 阶段识别子树的异步 setup。若返回 Promise，把子树挂起（不提交 DOM），显示 #fallback；收集所有异步依赖，全部 resolve 后统一提交 #default；任一 reject 触发 onError。这让「数据获取与渲染」可声明式编排，无需手动管理加载状态。

## 内置组件的本质

内置组件在渲染器中是一类特殊 VNode——`type` 为 `KeepAlive`/`Teleport`/`Suspense` 等符号。patch 阶段判断 VNode 类型，走专属分支处理，而非普通元素或组件的默认逻辑。这是渲染器用「类型分发」实现的可扩展设计。

## 常见误区

<Callout type="trap">
**误区：KeepAlive 切走的组件还在 DOM 树里。** KeepAlive 切走时把 DOM 移到一个隐藏的存储容器（不在可视区域），不是留在原位。切回时再从隐藏容器移回原位。所以切走期间 DOM 存在但不可见、不占布局。理解这点才能排查「切走后还在影响布局」的 bug——实际上不该影响，若影响说明缓存逻辑有误。
</Callout>

<Callout type="trap">
**误区：Teleport 后子组件的事件和 props 会断开。** Teleport 只改变真实 DOM 的插入位置，子树 VNode 的逻辑关系（props、emit、slots、响应式依赖）完全不变。父组件给 Teleport 内子组件传的 props、监听的事件都正常工作。只是视觉上 DOM 跑到了别处。把 Teleport 理解成「DOM 的物理位置移动，逻辑关系不变」就对了。
</Callout>

<Exercises>
**问题 1**：KeepAlive 缓存组件实例时，切走和切回分别做了什么？LRU 在这里起什么作用？

<Answer>
切走时：不 unmount 销毁，而是把组件的真实 DOM 从原位移到一个隐藏的存储容器（缓存），实例状态（setup 返回的响应式数据、子组件状态、滚动位置等）保留，触发 onDeactivated。切回时：把 DOM 从隐藏容器移回原位，复用缓存的实例（不重新执行 setup），触发 onActivated。LRU（最近最少使用）在缓存数超过 max 时淘汰最久未访问的组件实例——把它的 DOM 从隐藏容器移除并真正 unmount。这样在有限内存下保留最可能再次访问的组件，淘汰冷数据。
</Answer>

**问题 2（实现题）**：Teleport 解决了什么问题？为什么用 Teleport 而不是直接把弹窗组件放在 body 下？

<Answer>
Teleport 解决「弹窗/通知的 DOM 需要脱离父组件层级」的问题——避免被父级的 overflow:hidden 裁剪、避免 z-index 嵌套层级不够被遮挡、避免父级 transform 影响弹窗定位（transform 会创建新的包含块导致 fixed 失效）。为什么不直接把弹窗组件放 body 下：因为弹窗的显示逻辑（v-if/v-show）、数据来源、事件处理都归属在当前组件里，直接放 body 下会导致逻辑与视图分离、props/emit 难以传递。Teleport 让「逻辑归属不变（props/事件/响应式都在当前组件上下文）+ 视觉位置分离（DOM 插到 body）」同时满足。写 `<Teleport to="body"><Modal /></Teleport>`，Modal 的 props 和事件都正常工作，只是 DOM 跑到了 body 下。
</Answer>
</Exercises>
