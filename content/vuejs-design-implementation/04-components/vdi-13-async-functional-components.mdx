## 机制拆解

### 1. 建立机制边界

defineAsyncComponent返回包装组件，setup启动loader并维护loaded、loading和error。延迟计时器避免闪烁，超时产生明确错误；组件卸载后必须停止计时器并拒绝提交晚到结果。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 2. 处理关键算法

onError接收retry和fail，让调用方根据错误类型与尝试次数决定下一步。每次retry返回同一结果链并递增次数，旧尝试不能在新尝试后覆盖状态。

先预测：如果省略这一层，依赖、节点身份、任务顺序或请求状态会在哪里首次偏离？

### 3. 签发失败与恢复

渲染优先级通常是已加载组件、Error组件、Loading组件、占位。函数式组件可规范化为只有render的组件选项，但仍要声明props并参与父子VNode更新。

## 最小可运行实验

```js
function load() {
  return loader().catch(
    (error) =>
      new Promise((resolve, reject) => {
        onError(() => resolve(load()), reject, retries++);
      }),
  );
}
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：加载成功后未清除延迟或超时计时器，稍后又把已成功界面切成错误状态。**
  必须保存输入、执行轨迹和首偏离点，而不是只比较最终结果。
</Callout>

<Callout type="trap">
  **误区二：重试只再次调用loader却不返回Promise，包装组件永远等待第一次失败结果。**
  必须加入失败与恢复样本，并检查依赖、节点、任务和状态是否清理。
</Callout>

## 小结

- **异步组件**：把组件加载过程包装成具有加载、错误、超时和重试状态的组件。
- **Loading组件**：异步加载超过延迟阈值后展示的等待反馈组件。
- **Error组件**：异步组件最终加载失败时展示并接收错误信息的替代组件。
- **重试机制**：根据错误、次数和策略重新启动异步加载并收敛到单一结果的机制。
- **函数式组件**：主要依据props产出VNode、没有普通有状态实例的轻量组件。
