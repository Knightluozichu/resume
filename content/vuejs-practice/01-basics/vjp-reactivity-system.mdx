## 直觉引入

命令式编程里，你改了数据后要手动去改 DOM：`document.querySelector('#count').textContent = count`。数据和视图的对应关系靠人脑维护，一旦漏改就出 bug。Vue 的响应式换了个思路：你只管声明数据与视图的关系，数据一变，框架自动找到依赖这块数据的视图并更新。怎么做到的？答案是在数据的读写上「装监控」——读数据时记下「谁在用我」，写数据时通知「用过我的人重新跑」。这就是 Proxy 拦截 + 依赖收集。

## Proxy 拦截与 track/trigger

<Term def="响应式系统是通过 Proxy 代理对象、在 get 时 track 收集依赖、在 set 时 trigger 派发 effect 重新执行，从而让数据变化自动反映到视图的机制。">响应式系统</Term>的核心是 `reactive(obj)` 返回一个 Proxy 代理。读取属性触发 `get` 拦截，执行 `track`：把当前正在运行的 effect（如组件的 render 函数）记录到「属性 → 依赖集合」的映射 `targetMap` 里。写入属性触发 `set` 拦截，执行 `trigger`：从 `targetMap` 查出该属性的所有 effect，加入调度队列，在微任务里去重合并后统一执行，effect 重新运行读取最新数据生成新 VNode，再 patch 更新 DOM。

```javascript
import { reactive, effect } from "vue";

const state = reactive({ count: 0 }); // Proxy 代理

// effect 注册一个副作用：内部读取 state.count 会触发 track 收集这个 effect
effect(() => {
  console.log("count 是", state.count); // 首次执行：track 登记
});

state.count = 1; // set 拦截 → trigger → 上面 effect 重新执行 → 打印 "count 是 1"
```

## ref 与 reactive

原始类型（number/string/boolean）无法被 Proxy 代理（Proxy 只能代理对象），所以 Vue 用 `ref` 包裹一个 `{ value: T }` 对象，对 `.value` 做 get/set 拦截。`reactive` 直接代理整个对象，访问属性自动触发拦截，但解构会丢失响应式。

```javascript
import { ref, reactive } from "vue";

// ref：原始类型必须用，访问修改走 .value
const count = ref(0);
count.value++; // 触发 set → trigger

// reactive：对象/数组直接代理，无需 .value
const state = reactive({ list: [] });
state.list.push(1); // 触发响应

// 陷阱：解构 reactive 丢失响应式
const { list } = state; // list 不再响应式！应改用 toRefs 或保持 state.list
```

## 常见误区

<Callout type="trap">
**误区一：解构 reactive 对象后仍保持响应式。** `const { count } = reactiveState` 之后，`count` 是一个普通值，改它不会触发更新。解构把代理属性「拆」成了原始值，脱离了 Proxy。解决：用 `toRefs(reactiveState)` 把每个属性转成 ref 再解构，或始终通过 `reactiveState.count` 访问。
</Callout>

<Callout type="trap">
**误区二：整体替换 reactive 对象能保持响应式。** `let state = reactive({ count: 0 }); state = reactive({ count: 1 })` 看似换了内容，但原 Proxy 代理的是旧对象，模板绑定的也是旧代理，视图不更新。正确做法用 `ref`：`state.value = newObj` 会触发响应；或用 `Object.assign(state, newObj)` 逐属性写入仍走 set 拦截。
</Callout>

<Callout type="trap">
**误区三：ref 在 JS 里不用 .value 也能触发响应。** 漏写 `.value` 直接改了 ref 变量本身（而非它包裹的值），没有触发 set 拦截，视图不更新。模板里 Vue 编译器会自动解包所以不用写 `.value`，但 setup 的 JS 代码必须显式写。把「模板自动解包」当成「处处自动」是常见踩坑点。
</Callout>

<Exercises>
**问题 1**：简述 Vue 3 响应式的 track/trigger 机制。

<Answer>
读取属性时（get 拦截）执行 track：把当前 effect 记录到「对象 → 属性 → Dep(Set&lt;effect&gt;)」的 targetMap 里。写入属性时（set 拦截）执行 trigger：从 targetMap 查出该属性的所有 effect，加入调度队列，微任务里去重合并后执行，effect 重跑生成新 VNode 并 patch 更新 DOM。核心：读时登记「谁用了这个数据」，写时通知「用过的人重新跑」。
</Answer>

**问题 2（实现题）**：写一个 `useCounter` Hook，暴露 `count`、`double`（两倍）、`increment`，并说明每一步如何触发响应式。

<Answer>
```javascript
import { ref, computed } from "vue";

export function useCounter(initial = 0) {
  const count = ref(initial); // ref 包裹，.value 走 get/set 拦截
  const double = computed(() => count.value * 2); // 读取 count.value 触发 track，count 变时重算
  function increment() {
    count.value++; // 触发 set → trigger → 依赖 count 的 effect（含 double 与模板）重跑
  }
  return { count, double, increment };
}
```
`count` 是 ref，模板里自动解包直接用 `{{ count }}`；`double` 是 computed，依赖 `count.value`，count 变时重新计算；`increment` 改 `count.value` 触发 trigger，所有依赖 count 的 effect（double 的计算、组件 render）重新执行。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="Proxy 代理">Vue 3 用 Proxy 包裹对象，拦截属性的 get（读取）和 set（写入）操作，从而在读写时插入 track/trigger 逻辑。相比 Vue 2 的 Object.defineProperty，Proxy 能监听属性新增/删除和数组索引修改。</GlossaryItem>
<GlossaryItem term="track/trigger">track 在 get 时执行，把当前 effect 登记到 targetMap（属性 → 依赖集合）；trigger 在 set 时执行，从 targetMap 取出该属性的 effect 调度执行。二者构成「读时收集、写时派发」的依赖管理。</GlossaryItem>
<GlossaryItem term="ref vs reactive">ref 用 { value } 对象包裹任意类型（含原始类型），访问修改走 .value；reactive 用 Proxy 代理对象/数组，属性访问自动拦截但解构丢响应式。原始类型必须用 ref，对象两者皆可。</GlossaryItem>
</Glossary>
