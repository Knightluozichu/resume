## 直觉引入

你写的是 `<div>{{ msg }}</div>` 这样的模板字符串，但浏览器只认识 JavaScript。中间发生了什么？Vue 把模板当成一门「声明式 DSL」：编译期把它解析成抽象语法树（AST），做静态提升和指令变换，最终生成一个等价的 `render` 函数。运行时执行 render 读取响应式数据产出虚拟节点（VNode），数据变化时重新执行 render 得到新 VNode，与旧 VNode 比对（patch）后最小化更新 DOM。指令不是字符串替换，而是被翻译成了 JavaScript 逻辑。

## 编译流程

<Term def="模板编译是 Vue 在构建时或首次挂载时，把模板字符串解析成 AST、经变换生成渲染函数的过程；运行时执行渲染函数产出 VNode 并 patch 到 DOM。">模板编译</Term>分三步：①`parse` 把模板字符串解析成 AST（节点含 Element/Interpolation/Directive）；②`transform` 做静态提升（把不变部分提到 render 外复用）、指令转译（v-if → 三元、v-for → renderList、@click → 事件注册）、给动态节点打 PatchFlag；③`generate` 生成 render 函数代码。运行期执行 render 触发 track 收集依赖，数据变时 trigger 重跑 render，新 VNode 与旧 VNode 按 PatchFlag 只 diff 动态部分。

```javascript
// 模板：
//   <div v-if="show">{{ msg }}</div>
//
// 编译后等价的 render 函数（简化）：
function render(_ctx) {
  return _ctx.show
    ? _createVNode("div", null, _toDisplayString(_ctx.msg), 1 /* PatchFlag: 文本动态 */)
    : null; // v-if 被翻译成三元表达式
}
```

## 核心指令对照

```javascript
// v-if vs v-show
// v-if：条件为 false 不渲染到 DOM，切换时销毁/重建组件
// v-show：始终在 DOM，靠 display:none 切换，切换开销小

// v-for 必须加稳定 key（用数据 id，别用 index）
//   <li v-for="item in list" :key="item.id">{{ item.name }}</li>

// v-model 本质是 :value 绑定 + @input 监听
//   <input v-model="text" />
//   等价于 <input :value="text" @input="text = $event.target.value" />

// :class 支持对象/数组语法，编译期用 normalizeClass 规范化
//   <div :class="{ active: isActive, 'text-danger': hasError }"></div>
```

## 常见误区

<Callout type="trap">
**误区一：v-if 和 v-for 可以随意混用。** 同一元素同时用 v-if 和 v-for 时，Vue 3 中 v-if 优先级高于 v-for，但此时 v-if 无法访问 v-for 的循环变量，逻辑会出错。应把 v-for 移到外层 `<template>` 包裹，或用 computed 先过滤数据再循环，让条件与循环各司其职。
</Callout>

<Callout type="trap">
**误区二：v-for 用 index 作 key 没问题。** 当列表顺序变化（头部插入、删除中间项、拖拽排序），index 仍是 0,1,2... 但对应数据变了，diff 误判「同一个节点」复用 DOM，导致表单状态串项、过渡动画错乱、子组件状态不重置。正确做法用数据本身的稳定唯一 id 作 key，只有纯展示且永不变序的列表用 index 才安全。
</Callout>

<Callout type="trap">
**误区三：把模板当字符串模板引擎。** 以为 `{{ msg }}` 是运行时字面替换。实际上模板在编译期就生成了 render 函数，插值是 render 里读取响应式数据的表达式，指令是编译期翻译的 JS 逻辑，能享受 Tree-shaking、静态提升、PatchFlag 优化。理解这点就不会把模板当「字符串拼接」，而是「编译到 render 的声明式 DSL」。
</Callout>

<Exercises>
**问题 1**：v-if 和 v-show 的区别？各自适用场景？

<Answer>
v-if 是真条件渲染：false 时元素不进 DOM，切换时销毁/重建子组件（触发 unmount/mount，重置状态）。v-show 是显示控制：元素始终在 DOM，靠 display:none 切换，切换开销小但不卸载组件。频繁切换用 v-show 避免反复销毁重建；条件少变化或初始可能为 false 且内容重时用 v-if 按需渲染更省。
</Answer>

**问题 2（实现题）**：写一个列表渲染，要求用 id 作 key，并用 v-if 控制空状态提示。说明 key 如何影响 diff。

<Answer>
```html
<ul v-if="list.length">
  <li v-for="item in list" :key="item.id">{{ item.name }}</li>
</ul>
<p v-else>暂无数据</p>
```
diff 比对新旧 VNode 列表时按 key 判断节点身份：相同 key 复用 DOM 只更新变化属性，不同 key 才销毁重建。用 id 作 key 时，列表顺序变化（如删除中间项）后，每个 id 仍对应原数据，diff 准确复用对应 DOM、只移除被删项，不会串状态。若用 index 作 key，删除中间项后 index 0,1,2 仍连续但数据错位，diff 误判复用导致状态错乱。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="AST 抽象语法树">模板经 parse 解析成的树形结构，节点类型含 Element（元素）、Interpolation（插值）、Directive（指令）等，是 transform 与 generate 的中间表示。</GlossaryItem>
<GlossaryItem term="PatchFlag">transform 阶段给动态节点打的标记，记录该节点哪些部分是动态的（如文本、class、props）。patch 时只 diff 标记的部分，跳过静态内容，加速更新。</GlossaryItem>
<GlossaryItem term="指令编译">指令在编译期被翻译成等价 JS：v-if → 三元表达式、v-for → renderList、v-model → value 绑定 + input 监听、@click → 事件注册。指令不是运行时字符串替换，而是编译期确定的 JS 逻辑。</GlossaryItem>
</Glossary>
