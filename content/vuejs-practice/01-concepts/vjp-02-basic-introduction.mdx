## 机制拆解

### 1. 实例是状态所有者

new Vue接收选项并建立根实例。data中的字段成为视图可读取的状态，methods提供命令，生命周期钩子承接外部资源。不要把所有全局变量挂到实例上；每个状态都应有明确创建者和销毁者。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. Vue 2响应式的数据链

Vue 2主要通过Object.defineProperty为已有属性安装getter和setter。渲染期间的读取触发getter并收集依赖，写入触发setter并通知观察者。新增对象属性和直接按索引写数组是边界，需要Vue.set或替换引用。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 生命周期用于资源对称

created适合准备纯数据，mounted后才能依赖真实DOM，beforeDestroy或destroyed用于移除监听器、定时器和第三方实例。生命周期不是任意业务代码的分类箱，而是外部资源与组件寿命对齐的契约。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
const vm = new Vue({
  el: "#app",
  data: { count: 0 },
  mounted() {
    console.log("mounted", this.$el.textContent);
  },
  beforeDestroy() {
    clearInterval(this.timer);
  },
});
```

证据记录必须同时保存目录坐标、运行时和状态摘要：

```yaml

runtime: Vue 2.x + pinned toolchain
input_fixture: fixed
first_divergence: null
cleanup_complete: true
```

故障脚本保持一次只改变一个变量：

```text

assert -> one_state_owner && stable_output && no_stale_task && no_resource_leak
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：在Vue
  2中直接给已观察对象添加新属性，然后把视图不更新误判为渲染故障。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：在created里读取真实DOM，或在销毁阶段遗漏窗口监听器和定时器。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

<Vjp02BasicIntroductionEvidenceLab />

本页签发不变量是：**同一输入下依赖收集和更新路径可观察，新增属性使用兼容写法，实例销毁后没有残留监听器、定时器或第三方资源。** 单次成功、平均耗时或最终截图不能代替运行时版本、事件轨迹、首偏离点和清理证据。
