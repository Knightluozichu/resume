## 机制拆解

### 1. 数据、属性与方法的所有权

props由父组件拥有，子组件只能提出更新；data由当前实例拥有；methods表示命令。把prop复制进data会制造两个事实来源，除非明确建立一次性初始化或编辑草稿边界。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. computed和watch按问题选择

computed回答由哪些状态可以纯粹推导当前值，并利用缓存避免重复计算；watch回答状态变化后要执行什么副作用，例如请求、持久化或第三方同步。用watch回写另一个状态常常意味着派生关系应改为computed。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 渲染与复用需要可追踪来源

el、template和render存在优先级，最终都生成虚拟节点。过滤器适合简单展示转换，自定义指令只处理DOM细节，组件承担可组合界面。混入合并规则隐蔽，使用时要记录冲突、钩子顺序和迁移出口。

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
new Vue({
  props: { price: Number, quantity: Number },
  computed: {
    total() {
      return this.price * this.quantity;
    },
  },
  watch: {
    total(value) {
      analytics.record("total", value);
    },
  },
});
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：用watch维护本可由computed推导的重复状态，更新顺序变化后两份值不一致。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：大量混入注入同名字段和生命周期钩子，组件无法说明某个方法来自哪里。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |

## 小结

- **计算属性**：根据响应式依赖派生值并按依赖缓存结果的实例属性。
- **侦听属性**：在指定响应式值变化时执行异步操作或外部副作用的观察配置。
- **渲染函数**：直接创建虚拟节点树、表达模板难以描述的动态结构的函数。
- **自定义指令**：在元素生命周期上封装底层DOM行为的可复用扩展。
- **混入**：把一组选项合并到多个组件中的复用机制，存在命名冲突和来源隐蔽成本。
- 本页已经把官方目录、机制链、最小实现、故障注入和恢复证据放在同一条验收路径上。
