## 直觉引入

用户点一个链接到页面真正渲染出来，中间要过几道「关卡」：这个页面要不要登录？有没有权限？数据要不要预取？这些判断都在导航守卫里。守卫是一条有序的链路，每道关卡都能放行、中断或重定向。理解守卫的执行顺序，才能把鉴权、埋点、数据预取放到正确的位置，而不是乱塞导致逻辑错乱或死循环。

## 守卫执行顺序

<Term def="导航守卫是 Vue Router 在一次导航过程中按固定顺序执行的钩子链，每道守卫可放行、中断或重定向，用于鉴权、数据预取与副作用处理。">导航守卫</Term>的完整链路：①`router.beforeEach` 全局前置（鉴权）；②`beforeEnter` 路由独享（路由级权限/预取）；③组件内 `beforeRouteEnter`（进入前，组件未创建无 this）/`beforeRouteUpdate`（路由参数变化复用同组件）；④`router.beforeResolve` 全局解析（所有守卫与异步组件加载完成后）；⑤导航确认、DOM 更新；⑥`router.afterEach` 全局后置（无 next，不可改导航，用于埋点/改标题）。

## next 与 return

Vue Router 4 推荐用 return 值替代 next 回调：`return true`/无 return 放行；`return false` 取消；`return '/login'` 或 `return { path }` 重定向；`return new Error()` 抛错。原则要么全用 return 要么全用 next，不混用。

```javascript
// Vue Router 4 风格：用 return 控制
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isLogin()) {
    return { path: "/login", query: { redirect: to.fullPath } }; // 重定向带原路径
  }
  // 无 return（undefined）即放行
});
```

## 鉴权重定向模式

```javascript
router.beforeEach((to) => {
  const token = localStorage.getItem("token");
  if (to.meta.requiresAuth && !token) {
    return { path: "/login", query: { redirect: to.fullPath } }; // 带原目标
  }
  if (to.path === "/login" && token) {
    return "/"; // 已登录别再进登录页
  }
});

// 登录页成功后回跳
async function login() {
  const { token } = await api.login(form);
  localStorage.setItem("token", token);
  const redirect = route.query.redirect || "/";
  router.push(redirect); // 回原页或首页
}
```

## 常见误区

<Callout type="trap">
**误区一：把数据获取塞进守卫导致职责混乱。** 守卫适合鉴权与重定向，把复杂的数据预取也放守卫会让导航变慢、守卫臃肿。数据预取更适合放组件 setup（配合 Suspense）或 onMounted。守卫应专注「能不能进」，组件负责「进来后拿什么数据」，职责分离更清晰。
</Callout>

<Callout type="trap">
**误区二：beforeRouteEnter 里用 this 访问组件。** beforeRouteEnter 在组件创建前执行，此时实例不存在、this 为 undefined。要用 this 需在 next 回调里：`next(vm => { vm.xxx })`，该回调在组件挂载后执行。这是唯一支持 next 传回调的守卫。其他组件内守卫（beforeRouteUpdate/beforeRouteLeave）执行时组件已存在有 this。
</Callout>

<Callout type="trap">
**误区三：鉴权重定向忘了带原路径导致登录后回不到原页。** 重定向到 /login 时若不把 to.fullPath 存进 query，登录成功后不知道原目标是哪，只能跳首页体验差。应 `return { path: "/login", query: { redirect: to.fullPath } }`，登录后读 `route.query.redirect` 回跳。还要注意白名单（如 /login 自身）不鉴权，避免死循环。
</Callout>

<Exercises>
**问题 1**：列出 Vue Router 守卫的执行顺序。

<Answer>
①router.beforeEach 全局前置；②beforeEnter 路由独享；③组件内 beforeRouteEnter/beforeRouteUpdate；④router.beforeResolve 全局解析；⑤导航确认 DOM 更新；⑥router.afterEach 全局后置。前四道可中断（next(false)/return false）或重定向，afterEach 不可改导航用于副作用。
</Answer>

**问题 2（实现题）**：实现一个全局前置守卫，要求：需要登录的路由（meta.requiresAuth）未登录时跳 /login 并带回跳路径；已登录访问 /login 跳首页。

<Answer>
```javascript
router.beforeEach((to) => {
  const token = localStorage.getItem("token");
  if (to.meta.requiresAuth && !token) {
    return { path: "/login", query: { redirect: to.fullPath } }; // 带原路径回跳
  }
  if (to.path === "/login" && token) {
    return "/"; // 已登录别进登录页
  }
  // 其余放行
});
```
关键点：用 to.meta.requiresAuth 标记需鉴权路由；to.fullPath 保留完整路径含 query/hash 便于精确回跳；/login 自身不标 requiresAuth 避免死循环；登录页登录成功后读 route.query.redirect 执行 router.push(redirect || "/") 回原页。用 return 控制而非 next 回调（Vue Router 4 风格），全守卫统一风格不混用。
</Answer>
</Exercises>

<GlossaryItem term="beforeRouteEnter">组件内进入守卫，在导航确认前、组件未创建时执行，故无 this。是唯一支持 next(vm => ...) 回调的守卫，回调在组件挂载后执行可访问实例。</GlossaryItem>
<GlossaryItem term="鉴权重定向模式">beforeEach 检查登录态，未登录重定向 /login 并把 to.fullPath 存入 query.redirect，登录成功后读 redirect 回跳原页。需白名单 /login 不鉴权避免死循环。</GlossaryItem>
