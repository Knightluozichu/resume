## 机制拆解

### 1. CSS优先处理布局

流式网格和媒体查询能在不读取布局的情况下响应视口，通常比JS监听resize更稳定。只有需要业务测量或第三方组件协调时才使用JS布局，并通过节流和ResizeObserver控制频率。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. 页面和轮播都依赖身份

页面切换要让URL或明确状态成为事实来源，Swiper每一项要有稳定标识。自动播放、可见性变化和用户操作会竞争当前索引，组件应定义优先级，并在离开页面后暂停和释放监听器。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 多语种从配置键驱动

不要把中文散落在模板里再逐句替换。组件绑定语义键，语言包提供值，当前语言决定解析结果。还要验证长文本、缺失键、日期数字格式和从右到左等布局差异，避免只翻译文案。

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
const messages = {
  zh: { hero: { title: "可靠的数字产品" } },
  en: { hero: { title: "Reliable digital products" } },
};

function t(locale, key) {
  return key
    .split(".")
    .reduce((node, part) => node && node[part], messages[locale]);
}
```

证据记录必须同时保存目录坐标、运行时和状态摘要：

```yaml

runtime: Vue 2.x + pinned toolchain
input_fixture: fixed
first_divergence: null
cleanup_complete: true
```

故障脚本保持一次只改变一个变量：

```text

observe -> stop_at_first_divergence
recover -> clear_fault_and_replay
assert -> one_state_owner && stable_output && no_stale_task && no_resource_leak
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：所有断点都用resize事件和像素测量驱动，造成布局抖动并重复实现CSS能力。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：语言切换只替换正文，导航、图片替代文本、日期和SEO元数据仍固定为中文。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

## 小结

- **响应式设计**：用流式尺寸、弹性媒体和断点规则适配不同显示空间的设计方法。
