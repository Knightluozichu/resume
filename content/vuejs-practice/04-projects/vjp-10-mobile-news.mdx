## 机制拆解

### 1. 首屏只承担必要初始化

首屏不能用固定延时掩盖未知启动过程。应用应并行准备必要配置与会话，达到最小可用条件就进入首页；失败时提供重试或离线入口，并记录是哪项依赖阻止启动。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. 列表和详情共享身份而非副本

首页保存频道、分页游标和新闻摘要，详情根据新闻ID读取缓存并刷新完整内容。返回列表时恢复滚动和筛选状态；内容更新应按版本合并，避免旧请求覆盖新频道。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 搜索是可取消的版本流程

每次查询分配递增版本或AbortController，新输入到来时取消旧请求。响应只有在版本仍匹配当前查询时才能提交。空查询、零结果、断网和快速退格都是正常状态，不应复用上次结果冒充新结果。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
let searchVersion = 0;

async function searchNews(query) {
  const version = ++searchVersion;
  const result = await api.search(query);
  if (version !== searchVersion) return;
  store.commit("setSearchResult", { query, result });
}
```

证据记录必须同时保存目录坐标、运行时和状态摘要：

```yaml
book: Vue.js从入门到项目实战
page: vjp-10-mobile-news
sample: normal | boundary | failure | recovery
runtime: Vue 2.x + pinned toolchain
input_fixture: fixed
first_divergence: null
cleanup_complete: true
```

故障脚本保持一次只改变一个变量：

```text
baseline -> run_same_input
inject -> stale-state | duplicate-event | denied-resource | broken-build
observe -> stop_at_first_divergence
recover -> clear_fault_and_replay
assert -> one_state_owner && stable_output && no_stale_task && no_resource_leak
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：首屏使用固定三秒定时器，初始化早已完成仍阻塞，失败时又直接进入空首页。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：快速输入多个关键词时，较慢的旧请求最后返回并覆盖当前搜索结果。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

## 小结

- **应用首屏**：应用启动后在主要内容可用前承担品牌、初始化和过渡反馈的界面。
