## 机制拆解

### 1. 三棵树分开当前、待提交和历史

工作区是正在编辑的内容，暂存区是下一次提交的候选快照，HEAD指向当前提交。git diff和git diff --staged分别比较不同边界，提交前应同时检查，避免把生成物或无关修改带入。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. 分支是引用不是目录副本

创建分支只新增一个提交引用，切换分支会让工作区与目标快照对齐。合并先寻找共同祖先，再组合双方变化；冲突解决后要运行测试并检查最终差异，而不是机械选择某一方。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 远端同步先理解历史关系

fetch只更新远端跟踪引用，pull通常等于fetch后再合并或变基，push要求远端能接受当前引用更新。公开历史上的提交不要随意改写；需要纠错时优先追加可审计提交。

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

本页签发不变量是：**每次提交范围单一且差异已审查，分支关系可解释，冲突结果通过验证，远端历史没有意外改写或敏感文件。** 单次成功、平均耗时或最终截图不能代替运行时版本、事件轨迹、首偏离点和清理证据。
