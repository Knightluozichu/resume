## 核心概念与所有权

<Term def="当前检出的文件内容，可包含尚未暂存的修改。">工作区</Term>、<Term def="记录下一次提交准备包含的文件快照。">暂存区</Term>、<Term def="指向一棵目录树、父提交和元数据的不可变历史对象。">提交</Term>、<Term def="指向某个提交并随新提交移动的命名引用。">分支</Term>、<Term def="两个历史对同一区域做出无法自动组合的修改，需要人工决定结果。">合并冲突</Term>。
这些概念不是孤立名词：每一个都要回答“输入由谁创建、状态保存在哪里、哪个事件可以修改、失败如何传播、离开页面后由谁清理”。

|   # | 概念     | 工程含义                                                     |
| --: | -------- | ------------------------------------------------------------ |
|   1 | 工作区   | 当前检出的文件内容，可包含尚未暂存的修改。                   |
|   2 | 暂存区   | 记录下一次提交准备包含的文件快照。                           |
|   3 | 提交     | 指向一棵目录树、父提交和元数据的不可变历史对象。             |
|   4 | 分支     | 指向某个提交并随新提交移动的命名引用。                       |
|   5 | 合并冲突 | 两个历史对同一区域做出无法自动组合的修改，需要人工决定结果。 |

## 机制拆解

### 1. 三棵树分开当前、待提交和历史

工作区是正在编辑的内容，暂存区是下一次提交的候选快照，HEAD指向当前提交。git diff和git diff --staged分别比较不同边界，提交前应同时检查，避免把生成物或无关修改带入。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. 分支是引用不是目录副本

创建分支只新增一个提交引用，切换分支会让工作区与目标快照对齐。合并先寻找共同祖先，再组合双方变化；冲突解决后要运行测试并检查最终差异，而不是机械选择某一方。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 远端同步先理解历史关系

fetch只更新远端跟踪引用，pull通常等于fetch后再合并或变基，push要求远端能接受当前引用更新。公开历史上的提交不要随意改写；需要纠错时优先追加可审计提交。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
git status --short
git diff
git add path/to/file
git diff --staged
git commit -m "feat: describe one coherent change"
```

证据记录必须同时保存目录坐标、运行时和状态摘要：

```yaml
book: Vue.js从入门到项目实战
page: vjp-appendix-a-git
sample: normal | boundary | failure | recovery
runtime: Vue 2.x + pinned toolchain
input_fixture: fixed
first_divergence: null
cleanup_complete: true
```

故障脚本保持一次只改变一个变量：

```text
baseline -> run_same_input
inject -> stale-state | duplicate-event | denied-resource | broken-build
observe -> stop_at_first_divergence
recover -> clear_fault_and_replay
assert -> one_state_owner && stable_output && no_stale_task && no_resource_leak
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：直接git
  add全部文件并提交，没有检查暂存差异，混入缓存、密钥或无关改动。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：遇到冲突只选择ours或theirs，不理解两侧意图也不运行合并后的验证。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

本页签发不变量是：**每次提交范围单一且差异已审查，分支关系可解释，冲突结果通过验证，远端历史没有意外改写或敏感文件。** 单次成功、平均耗时或最终截图不能代替运行时版本、事件轨迹、首偏离点和清理证据。

## 小结

- **工作区**：当前检出的文件内容，可包含尚未暂存的修改。
- **暂存区**：记录下一次提交准备包含的文件快照。
- **提交**：指向一棵目录树、父提交和元数据的不可变历史对象。
- **分支**：指向某个提交并随新提交移动的命名引用。
- **合并冲突**：两个历史对同一区域做出无法自动组合的修改，需要人工决定结果。
