## 直觉：先画状态、身份与交付链

掌握package.json、语义版本、锁文件、依赖类别与npm脚本的可复现契约。 npm项目的可复现性来自清单、锁文件、受控注册源和确定脚本，而不是某台机器上偶然存在的node_modules。 真正掌握本页，不是让一次演示碰巧得到正确截图，而是能解释输入从哪里来、谁拥有可变状态、哪次事件触发更新、失败后如何停止，以及组件和外部资源何时释放。先预测：只看最终页面，最容易遗漏哪条陈旧请求、重复事件或错误身份？

## 机制拆解

### 1. 清单表达意图，锁文件表达解析结果

package.json中的版本范围允许兼容升级，package-lock.json记录当前完整依赖树。团队和CI应提交锁文件，并使用npm ci按锁文件进行干净安装；只复制node_modules无法审计来源和平台差异。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. 依赖类别决定消费者责任

dependencies随应用运行或包消费而需要，devDependencies服务于本项目构建与测试，peerDependencies声明宿主必须提供的兼容能力。分类错误会让生产缺包或库重复打包。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 脚本是统一入口

dev、test、lint和build等脚本把工具参数放回版本控制，让本地与CI调用同一入口。脚本中引用的二进制从项目依赖解析，不依赖全局安装；安装脚本则应审查网络和执行权限。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
npm ci
npm run lint
npm test
npm run build
npm audit --omit=dev
```

证据记录必须同时保存目录坐标、运行时和状态摘要：

```yaml
book: Vue.js从入门到项目实战
page: vjp-appendix-b-npm
sample: normal | boundary | failure | recovery
runtime: Vue 2.x + pinned toolchain
input_fixture: fixed
first_divergence: null
cleanup_complete: true
```

故障脚本保持一次只改变一个变量：

```text
baseline -> run_same_input
inject -> stale-state | duplicate-event | denied-resource | broken-build
observe -> stop_at_first_divergence
recover -> clear_fault_and_replay
assert -> one_state_owner && stable_output && no_stale_task && no_resource_leak
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：删除锁文件后使用宽松版本安装，再把本机成功当作可复现构建。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：依赖全局安装的CLI，导致开发者和CI使用不同版本与默认配置。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

<VjpAppendixBNpmEvidenceLab />

本页签发不变量是：**干净环境按锁文件得到同一依赖图，运行时与开发依赖分类清楚，所有质量命令经项目脚本执行，来源和完整性可审计。** 单次成功、平均耗时或最终截图不能代替运行时版本、事件轨迹、首偏离点和清理证据。

## 小结

- **package.json**：声明包元数据、依赖、脚本和运行约束的项目清单。
- **语义版本**：用主版本、次版本和修订号表达兼容性承诺的版本规则。
- **锁文件**：记录解析后的精确依赖版本与完整性信息的可提交文件。
- **开发依赖**：只在开发、测试或构建阶段需要而不属于运行时接口的依赖。
- **npm脚本**：在项目清单中命名、可由一致环境调用的命令入口。
- 本页已经把官方目录、机制链、最小实现、故障注入和恢复证据放在同一条验收路径上。
- 原书Vue 2技术语境与现代迁移说明保持清晰边界。
