## 核心概念与所有权

<Term def="构建开始遍历模块依赖图的一个或多个起点。">入口</Term>、<Term def="把匹配资源转换成webpack可纳入模块图内容的函数链。">loader</Term>、<Term def="订阅构建生命周期并处理产物、环境和跨模块任务的扩展。">plugin</Term>、<Term def="构建过程中形成、最终可对应一个或多个输出文件的代码块。">chunk</Term>、<Term def="由资源内容计算并用于文件名、支持长期缓存失效的摘要。">内容哈希</Term>。
这些概念不是孤立名词：每一个都要回答“输入由谁创建、状态保存在哪里、哪个事件可以修改、失败如何传播、离开页面后由谁清理”。

|   # | 概念     | 工程含义                                               |
| --: | -------- | ------------------------------------------------------ |
|   1 | 入口     | 构建开始遍历模块依赖图的一个或多个起点。               |
|   2 | loader   | 把匹配资源转换成webpack可纳入模块图内容的函数链。      |
|   3 | plugin   | 订阅构建生命周期并处理产物、环境和跨模块任务的扩展。   |
|   4 | chunk    | 构建过程中形成、最终可对应一个或多个输出文件的代码块。 |
|   5 | 内容哈希 | 由资源内容计算并用于文件名、支持长期缓存失效的摘要。   |

## 机制拆解

### 1. 模块图决定产物

webpack从entry解析import和require，形成模块依赖图。loader负责把样式、图片或新语法转成模块，解析失败应沿导入链定位。把任意文件复制到输出目录并不等于它进入模块图。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. plugin处理构建级任务

定义环境变量、抽取CSS、生成HTML和压缩产物都需要跨模块或生命周期能力，适合plugin。配置要区分开发和生产：开发强调增量反馈，生产强调确定优化、内容哈希和可观测构建报告。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 代码分割必须验证加载边界

动态import可以形成异步chunk，公共依赖可由优化策略抽取。分包不是越细越好，要同时测首屏请求、缓存复用和失败恢复；部署时HTML与旧新哈希资源要有兼容窗口。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
module.exports = {
  entry: "./src/main.js",
  output: { filename: "[name].[contenthash].js", clean: true },
  module: { rules: [{ test: /\.css$/, use: ["style-loader", "css-loader"] }] },
  optimization: { splitChunks: { chunks: "all" } },
};
```

证据记录必须同时保存目录坐标、运行时和状态摘要：

```yaml
book: Vue.js从入门到项目实战
page: vjp-appendix-c-webpack
sample: normal | boundary | failure | recovery
runtime: Vue 2.x + pinned toolchain
input_fixture: fixed
first_divergence: null
cleanup_complete: true
```

故障脚本保持一次只改变一个变量：

```text
baseline -> run_same_input
inject -> stale-state | duplicate-event | denied-resource | broken-build
observe -> stop_at_first_divergence
recover -> clear_fault_and_replay
assert -> one_state_owner && stable_output && no_stale_task && no_resource_leak
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：只看构建成功，不检查模块图和产物体积，重复依赖悄然进入多个chunk。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：发布时立即删除旧哈希资源，仍缓存旧HTML的用户打开页面后异步chunk全部404。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 验收矩阵

| 样本 | 输入与环境变化               | 预期状态       | 通过条件               |
| ---- | ---------------------------- | -------------- | ---------------------- |
| 正常 | 合法数据、稳定身份、固定版本 | 完成主链       | 输出与状态摘要一致     |
| 边界 | 空值、极限数量、快速重复事件 | 有界退化       | 不越界、不重复、不阻塞 |
| 失败 | 请求拒绝、旧缓存、资源缺失   | 首偏离点停止   | 错误显式传播或降级     |
| 恢复 | 清除故障后重放同一输入       | 收敛到正常轨迹 | 无陈旧任务和资源泄漏   |

## 小结

- **入口**：构建开始遍历模块依赖图的一个或多个起点。
- **loader**：把匹配资源转换成webpack可纳入模块图内容的函数链。
- **plugin**：订阅构建生命周期并处理产物、环境和跨模块任务的扩展。
- **chunk**：构建过程中形成、最终可对应一个或多个输出文件的代码块。
- **内容哈希**：由资源内容计算并用于文件名、支持长期缓存失效的摘要。
