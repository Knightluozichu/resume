## 机制拆解

### 1. 闭包捕获绑定而非瞬时文本

函数返回后，只要内部函数仍引用外层绑定，词法环境就保持可达。循环中var共享同一绑定，延迟回调可能都看到最终值；let为每次迭代建立独立绑定。判断行为要画绑定，不要只看变量名字。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 2. 复制引用不会复制对象

把对象赋给另一个变量、传入函数或放入数组，只复制对象引用。函数内修改对象属性会被调用方观察，重新给参数赋值则只改变局部绑定。需要隔离状态时要明确浅拷贝与深层嵌套的边界。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

### 3. 可达图决定释放

闭包、事件监听器和定时器都可能延长对象寿命。垃圾回收只清理不可达对象，不会判断业务上是否已无用。组件销毁时应取消异步工作并解除外部引用，让词法环境和对象图真正断开。

先预测：若省略这一层，状态、组件身份、异步任务或构建产物会在哪里首次偏离？

## 最小可运行实验

下面的最小实现聚焦本页核心。先在独立页面运行，再加入空输入、快速重复操作和销毁重建；不要直接把演示代码当成完整生产方案。

```js
function createCounter() {
  let count = 0;
  return {
    next() {
      count += 1;
      return count;
    },
    read() {
      return count;
    },
  };
}

const counter = createCounter();
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：认为函数调用结束后所有局部变量都会释放，忽略返回回调仍持有词法环境。**
  最终截图可能仍正确，但状态轨迹、资源数量或下一次交互已经偏离；必须保存首次偏离前后的输入与事件。
</Callout>

<Callout type="trap">
  **误区二：用展开运算符复制顶层对象后修改嵌套对象，误以为原对象不会受影响。**
  用正常样本无法暴露这一问题，要增加边界、失败和恢复样本，并在销毁后检查残留任务。
</Callout>

## 小结

- **闭包**：函数及其创建时可访问词法环境组合形成的可调用对象。
- **词法环境**：按源代码嵌套关系保存标识符绑定和外部引用的运行结构。
- **对象引用**：指向对象身份的值，复制引用不会复制对象本身。
- **可达性**：对象能否从根对象沿引用链被访问到的内存判定。
- **共享修改**：多个引用指向同一对象时，通过任一引用修改可被其他持有者观察的现象。
- 本页已经把官方目录、机制链、最小实现、故障注入和恢复证据放在同一条验收路径上。
