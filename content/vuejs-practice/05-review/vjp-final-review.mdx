## 直觉引入

前面九章是分散的零件，总复习要把它们拼成一台能运转的机器。最好的串联方式不是逐章复述，而是跟着一次真实的用户操作走一遍：用户点击按钮，数据怎么变、视图怎么更新、组件怎么协作、状态怎么共享、页面怎么跳转、首屏怎么渲染、最后怎么打包上线。每一章都在这条旅程里扮演一个角色，没有孤立的知识点。

## 实战：电商详情页的十章协作

一个电商详情页需求，各章如何协作：①响应式系统管理商品数据，加购触发更新（第 2 章）；②模板用 v-if 控制缺货、v-for 渲染规格、插值显示价格（第 3 章）；③拆成 ProductInfo/SkuSelector/Reviews 子组件，props/emit/slot 协作（第 4 章）；④加购与规格选择抽成 useCart/useSku 复用（第 5 章）；⑤购物车数量与登录态放 Pinia 共享（第 6 章）；⑥beforeEach 校验登录才能加购（第 7 章）；⑦详情页 SSR 首屏直出利 SEO（第 8 章）；⑧路由懒加载分包、哈希缓存、上 CDN（第 9 章）。

## 常见误区

<Callout type="trap">
**误区一：「数据变了视图没动」直接 $forceUpdate 兜底。** 这是治标不治本。真正原因可能是：数据没走响应式（改了原始对象）、ref 忘 .value、reactive 被整体替换、解构丢响应式、依赖未在 render 期收集。应用 DevTools 查状态 → 检查数据来源是否响应式 → 确认修改方式 → 用 watch 验证是否触发，找到根因而非盲目强制更新。
</Callout>

<Callout type="trap">
**误区二：把各章知识当孤岛学。** 响应式、模板、组件、状态、路由、SSR、构建不是独立考点，而是一条链：响应式数据驱动模板渲染，渲染发生在组件内，组件间靠状态共享，页面间靠路由导航，首屏靠 SSR，交付靠构建。理解它们如何协作，才能在真实项目里把知识用起来，而非只会答单点面试题。
</Callout>

<Callout type="trap">
**误区三：能跑就等于用好 Vue。** 「能用」是照文档搭出能运行的组件；「用好」是在多个方案间做权衡：何时 ref 何时 reactive、组件边界怎么划、状态归属局部还是全局、守卫放鉴权还是组件内、渲染模式按需选型、分包粒度平衡首屏与交互。判断力来自对每章原理的深入理解，而非 API 记忆。
</Callout>

**问题 2（实现题）**：电商详情页要实现「未登录点加购跳登录页，登录后回详情页继续」，说明涉及哪几章知识及如何协作。

<Answer>
涉及第 2、4、6、7 章。①第 2 章响应式：点击触发加购逻辑；②第 4 章组件：加购按钮在 ProductCard 子组件内，emit('add') 冒泡到父；③第 6 章状态：登录态（token）存 Pinia user store，全局可读；④第 7 章路由守卫：点加购时先检查 user store 的 token，未登录则 `router.push({ path: "/login", query: { redirect: route.fullPath } })` 跳登录页并带详情页路径；登录页登录成功后存 token 到 store，再读 route.query.redirect 执行 router.push(redirect) 回到详情页继续加购流程。四章协作完成「鉴权 + 回跳」体验。
</Answer>
