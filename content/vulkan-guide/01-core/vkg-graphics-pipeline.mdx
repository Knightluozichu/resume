## Pipeline 是接口合同，不是八站流水线

图形阶段常画成“vertex input → vertex shader → rasterization → fragment shader → blending”，这有助于理解数据流，却不能理解 Vulkan pipeline 对象的真正职责。现代 GPU 可能并行、融合或延迟执行阶段；应用真正提交的是一份兼容合同：shader 的输入输出、资源布局、附件格式/采样数，以及哪些状态固定在 pipeline、哪些由 command buffer 动态给出。

通常不可在创建后修改，但被声明为 dynamic 的状态不存储具体值。绑定 pipeline 后还必须在 draw 前设置所需动态状态。创建和绑定成本都依实现而异，不能仅凭“预编译对象”断言绑定一定可以忽略。


## Shader 模块与接口反射

Vulkan shader module 消费 SPIR-V。源码可以来自 GLSL、HLSL、Slang 等前端；构建系统应固定编译器版本、target environment、entry point 和优化/debug 配置，并把编译诊断当内容资产保存。

`VkPipelineShaderStageCreateInfo`指定 stage、module、entry point 和 specialization constants。创建 pipeline 后，若不再用于其他创建操作，shader module 可以销毁；pipeline 保留所需实现状态。

```cpp
VkShaderModule createShaderModule(VkDevice device, std::span<const uint32_t> words) {
  VkShaderModuleCreateInfo info{
    .sType = VK_STRUCTURE_TYPE_SHADER_MODULE_CREATE_INFO,
    .codeSize = words.size_bytes(),
    .pCode = words.data(),
  };
  VkShaderModule module = VK_NULL_HANDLE;
  VK_CHECK(vkCreateShaderModule(device, &info, nullptr, &module));
  return module;
}

VkPipelineShaderStageCreateInfo stages[] = {
  {
    .sType = VK_STRUCTURE_TYPE_PIPELINE_SHADER_STAGE_CREATE_INFO,
    .stage = VK_SHADER_STAGE_VERTEX_BIT,
    .module = vertexModule,
    .pName = "main",
  },
  {
    .sType = VK_STRUCTURE_TYPE_PIPELINE_SHADER_STAGE_CREATE_INFO,
    .stage = VK_SHADER_STAGE_FRAGMENT_BIT,
    .module = fragmentModule,
    .pName = "main",
  },
};
```

构建时至少验证：vertex output location/type 与 fragment input 匹配；descriptor set/binding/type/count 与 set layout 匹配；push constant offset/size/stages 在 layout 范围内；fragment outputs 与 color attachment 位置一致。仅“SPIR-V 能创建 module”不证明 stage interfaces 兼容。

## Pipeline layout 是资源 ABI

描述 descriptor sets 和 push constants，不描述 vertex buffer，也不拥有 descriptor set。多个 pipeline 可以共享兼容 layout；切换 pipeline 时，已绑定 descriptor sets 是否仍兼容取决于规范定义的 set layout 兼容前缀和 push constant ranges，而不是句柄是否相同。

```cpp
VkDescriptorSetLayout setLayouts[] = {frameSetLayout, materialSetLayout};
VkPushConstantRange objectRange{
  .stageFlags = VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT,
  .offset = 0,
  .size = sizeof(ObjectPushConstants),
};
VkPipelineLayoutCreateInfo layoutInfo{
  .sType = VK_STRUCTURE_TYPE_PIPELINE_LAYOUT_CREATE_INFO,
  .setLayoutCount = 2,
  .pSetLayouts = setLayouts,
  .pushConstantRangeCount = 1,
  .pPushConstantRanges = &objectRange,
};
VK_CHECK(vkCreatePipelineLayout(device, &layoutInfo, nullptr, &pipelineLayout));
```

push constant size受 `maxPushConstantsSize`限制，stage visibility 应覆盖实际读取阶段；重叠 ranges 还要满足规范约束。把所有资源都塞进 set 0 会让 layout 演进和绑定复用困难，通常按更新频率和所有权拆为 frame/view、material、object 等集合。

## Dynamic rendering 的附件合同

减少 render pass/framebuffer 对象，但不删除格式、采样数、load/store、layout 和同步合同。

创建 pipeline 时通过 `VkPipelineRenderingCreateInfo`声明 color/depth/stencil formats；`VkGraphicsPipelineCreateInfo::renderPass`设为 null。录制时 `VkRenderingAttachmentInfo`中的 imageView、layout、load/store 与 clear value 必须与这些声明及实际资源兼容。

```cpp
VkFormat colorFormat = swapchainFormat;
VkPipelineRenderingCreateInfo renderingInfo{
  .sType = VK_STRUCTURE_TYPE_PIPELINE_RENDERING_CREATE_INFO,
  .colorAttachmentCount = 1,
  .pColorAttachmentFormats = &colorFormat,
  .depthAttachmentFormat = depthFormat,
  .stencilAttachmentFormat = hasStencil(depthFormat) ? depthFormat : VK_FORMAT_UNDEFINED,
};

VkGraphicsPipelineCreateInfo pipelineInfo{
  .sType = VK_STRUCTURE_TYPE_GRAPHICS_PIPELINE_CREATE_INFO,
  .pNext = &renderingInfo,
  .stageCount = 2,
  .pStages = stages,
  .pVertexInputState = &vertexInput,
  .pInputAssemblyState = &inputAssembly,
  .pViewportState = &viewportState,
  .pRasterizationState = &rasterization,
  .pMultisampleState = &multisample,
  .pDepthStencilState = &depthStencil,
  .pColorBlendState = &colorBlend,
  .pDynamicState = &dynamicState,
  .layout = pipelineLayout,
  .renderPass = VK_NULL_HANDLE,
  .subpass = 0,
};
VK_CHECK(vkCreateGraphicsPipelines(
    device, pipelineCache, 1, &pipelineInfo, nullptr, &pipeline));
```

若 swapchain 重建改变 color format，或 MSAA/depth format 改变，附件合同相关 pipeline 需要重建。若只有 extent 改变且 viewport/scissor 为动态状态，则通常可复用同一 pipeline。

## 固定功能仍是可验证状态

基础 graphics pipeline 还要定义：

- vertex input bindings/attributes 与 input assembly topology；
- viewport count、scissor count；
- rasterization discard、polygon mode、cull mode、front face、depth bias；
- sample count、sample mask 和 alpha-to-coverage；
- depth test/write/compare 与 stencil operations；
- 每个 color attachment 的 blend enable、factors、ops 与 write mask。

非 fill polygon mode、wide lines 等状态需要对应 feature。depth attachment 未提供时，不应创建或启用依赖它的状态假设。color blend attachment count 和 dynamic rendering colorAttachmentCount 必须一致；每个 attachment 的写掩码也应显式设置，否则“绘制成功但无颜色”很难定位。

frontFace 与坐标约定相关。通过负 viewport height 翻转 Y、在 shader 翻转 Y，或改变投影矩阵都会影响 winding；剔除错误应从完整坐标链验证，而不是机械切换 CLOCKWISE。

## 动态状态把组合转成录制责任

可减少 pipeline 组合，但不是免费灵活性。核心 viewport/scissor 常设为动态；更多 cull mode、front face、depth test 等动态能力依赖 Vulkan 版本或扩展 feature，必须查询并启用。


```cpp
VkDynamicState dynamicStates[] = {
  VK_DYNAMIC_STATE_VIEWPORT,
  VK_DYNAMIC_STATE_SCISSOR,
};
VkPipelineDynamicStateCreateInfo dynamicInfo{
  .sType = VK_STRUCTURE_TYPE_PIPELINE_DYNAMIC_STATE_CREATE_INFO,
  .dynamicStateCount = std::size(dynamicStates),
  .pDynamicStates = dynamicStates,
};

vkCmdBindPipeline(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, pipeline);
vkCmdSetViewport(cmd, 0, 1, &viewport);
vkCmdSetScissor(cmd, 0, 1, &scissor);
vkCmdBindDescriptorSets(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS,
    pipelineLayout, 0, descriptorSets.size(), descriptorSets.data(),
    dynamicOffsets.size(), dynamicOffsets.data());
vkCmdDrawIndexed(cmd, indexCount, instanceCount, 0, 0, 0);
```

动态状态通常在 command buffer 中持续到被新值覆盖，但切换到需要不同动态状态集合的 pipeline 后，必须按规范保证 draw 前所有 required dynamic state 都已有效设置。渲染器可在 command encoder 层跟踪 dirty state，避免遗漏和无意义重复命令。

## Pipeline cache 不是通用二进制

可以降低部分重复创建成本，但命中、内容和收益均由实现决定。缓存数据有设备/驱动兼容身份，包括 vendorID、deviceID 与 pipelineCacheUUID；不能把 A 机器文件直接当 B 机器通用缓存。

持久化流程应：创建时校验缓存头与当前设备身份；不兼容就丢弃；运行结束或稳定节点通过 `vkGetPipelineCacheData`导出；写入使用临时文件加原子替换；驱动更新后允许自然失效。多个线程或多个 cache 的合并也要遵守外部同步要求。

首次创建仍可能发生昂贵编译。应用应预热关键 pipeline、后台创建非关键变体，并使用 pipeline creation feedback 或 executable properties 等可用工具测量，而不是把加载卡顿都归因于“没用 cache”。支持 `VK_EXT_pipeline_creation_cache_control`时还可请求在需要编译时失败，从而把实时路径中的意外编译暴露出来。

## 本章检查清单

- shader locations、descriptor bindings、push constants 与 pipeline layout 在创建前已反射验证；
- dynamic rendering formats/sample count 与实际 attachments、swapchain generation 一致；
- 所有 declared dynamic state 在 draw 前都有有效 vkCmdSet*，扩展状态对应 feature 已启用；
- pipeline cache 按设备/驱动身份校验，创建时长和缓存收益有可观测证据。
