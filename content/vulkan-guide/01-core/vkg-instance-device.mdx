## 直觉引入

想象你要在一家大型工厂里开一条生产线。首先你得在工厂管理处「注册」你的公司（VkInstance），拿到入场许可。然后你实地考察工厂里的多条产线（物理设备），看哪条产线的设备能力（队列族）能满足你的生产需求。最后，你跟工厂签合同「租用」那条产线（VkDevice），正式开始生产。

Vulkan 的实例—设备体系就是这套逻辑：先建立与 Vulkan 运行时的连接，再选择 GPU 硬件，最后创建逻辑设备开始实际工作。

## 概念讲解

### VkInstance：与 Vulkan 运行时的连接

<Term def="VkInstance 是应用程序与 Vulkan 运行时之间的连接句柄，创建时需声明应用信息和启用的扩展/层。">VkInstance</Term> 是一切 Vulkan 操作的起点。创建实例时需要填充 `VkApplicationInfo`（应用名称、版本、API 版本）和 `VkInstanceCreateInfo`（启用的层与扩展）。

```c
VkApplicationInfo appInfo = {
    .sType = VK_STRUCTURE_TYPE_APPLICATION_INFO,
    .pApplicationName = "MyRenderer",
    .applicationVersion = VK_MAKE_VERSION(1, 0, 0),
    .apiVersion = VK_API_VERSION_1_3,
};

VkInstanceCreateInfo createInfo = {
    .sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO,
    .pApplicationInfo = &appInfo,
    .enabledLayerCount = 0,
    .enabledExtensionCount = instanceExtensionCount,
    .ppEnabledExtensionNames = instanceExtensions,
};

VkInstance instance;
vkCreateInstance(&createInfo, NULL, &instance);
```

### 物理设备枚举

创建实例后，需要查找系统中支持 Vulkan 的 GPU：

```c
uint32_t deviceCount = 0;
vkEnumeratePhysicalDevices(instance, &deviceCount, NULL);
VkPhysicalDevice* devices = malloc(deviceCount * sizeof(VkPhysicalDevice));
vkEnumeratePhysicalDevices(instance, &deviceCount, devices);
```

每个 <Term def="VkPhysicalDevice 代表系统中一个实际的 Vulkan 兼容 GPU，是不可修改的查询句柄。">VkPhysicalDevice</Term> 都可以查询 `VkPhysicalDeviceProperties`（名称、类型、驱动版本）和 `VkPhysicalDeviceFeatures`（几何着色器、tessellation 等能力）。

### 队列族选择

Vulkan 的命令通过队列提交执行，而队列属于特定的 <Term def="队列族是一组支持相同操作类型的命令队列集合，不同族可能支持图形、计算、传输等不同能力。">队列族（Queue Family）</Term>。选择设备时必须找到支持所需操作的队列族：

```c
uint32_t queueFamilyCount = 0;
vkGetPhysicalDeviceQueueFamilyProperties(device, &queueFamilyCount, NULL);
VkQueueFamilyProperties* queueFamilies = malloc(queueFamilyCount * sizeof(VkQueueFamilyProperties));
vkGetPhysicalDeviceQueueFamilyProperties(device, &queueFamilyCount, queueFamilies);

// 查找支持图形操作的队列族
int graphicsFamily = -1;
for (uint32_t i = 0; i < queueFamilyCount; i++) {
    if (queueFamilies[i].queueFlags & VK_QUEUE_GRAPHICS_BIT) {
        graphicsFamily = i;
        break;
    }
}
```

### 逻辑设备创建

选定物理设备和队列族后，创建 <Term def="VkDevice 是逻辑设备句柄，代表应用程序对物理设备的租用，创建时指定启用的扩展、特性和队列。">VkDevice</Term>（逻辑设备）：

```c
float queuePriority = 1.0f;
VkDeviceQueueCreateInfo queueCreateInfo = {
    .sType = VK_STRUCTURE_TYPE_DEVICE_QUEUE_CREATE_INFO,
    .queueFamilyIndex = graphicsFamily,
    .queueCount = 1,
    .pQueuePriorities = &queuePriority,
};

VkDeviceCreateInfo deviceCreateInfo = {
    .sType = VK_STRUCTURE_TYPE_DEVICE_CREATE_INFO,
    .pQueueCreateInfos = &queueCreateInfo,
    .queueCreateInfoCount = 1,
    .enabledExtensionCount = deviceExtensionCount,
    .ppEnabledExtensionNames = deviceExtensions,
    .pEnabledFeatures = &deviceFeatures,
};

VkDevice device;
vkCreateDevice(physicalDevice, &deviceCreateInfo, NULL, &device);
```

<Stepper>
  <Step title="创建实例">
    填充 `VkApplicationInfo` 和 `VkInstanceCreateInfo`，调用 `vkCreateInstance`。这一步建立与 Vulkan 运行时的连接，声明你需要的扩展（如 `VK_KHR_surface`）。
  </Step>
  <Step title="选择物理设备与队列族">
    调用 `vkEnumeratePhysicalDevices` 枚举所有 GPU，查询每个设备的属性和队列族。找到支持 `VK_QUEUE_GRAPHICS_BIT` 的队列族，并检查设备是否支持你需要的扩展（如 `VK_KHR_swapchain`）。
  </Step>
  <Step title="创建逻辑设备">
    填充 `VkDeviceQueueCreateInfo`（指定队列族和优先级）和 `VkDeviceCreateInfo`（启用扩展和特性），调用 `vkCreateDevice`。之后通过 `vkGetDeviceQueue` 获取队列句柄，开始提交命令。
  </Step>
</Stepper>

## 代码对照

完整实例与设备初始化流程：

```c
// 1. 创建实例
VkInstance instance;
VkResult result = vkCreateInstance(&createInfo, NULL, &instance);
if (result != VK_SUCCESS) { /* 错误处理 */ }

// 2. 枚举物理设备
uint32_t deviceCount = 0;
vkEnumeratePhysicalDevices(instance, &deviceCount, NULL);
VkPhysicalDevice physicalDevice;
vkEnumeratePhysicalDevices(instance, &deviceCount, &physicalDevice);

// 3. 查询设备属性
VkPhysicalDeviceProperties props;
vkGetPhysicalDeviceProperties(physicalDevice, &props);
printf("GPU: %s\n", props.deviceName);

// 4. 选择队列族
uint32_t queueFamilyIndex = findGraphicsQueueFamily(physicalDevice);

// 5. 创建逻辑设备
VkDevice device;
vkCreateDevice(physicalDevice, &deviceCreateInfo, NULL, &device);

// 6. 获取队列
VkQueue graphicsQueue;
vkGetDeviceQueue(device, queueFamilyIndex, 0, &graphicsQueue);
```

## 常见误区

<Callout type="trap">
以为 `vkEnumeratePhysicalDevices` 第一次调用传 NULL 是 bug。实际上这是 Vulkan 的标准两步调用模式：第一次获取数量，第二次填充数组。几乎所有枚举 API 都遵循这个模式。
</Callout>

<Callout type="trap">
忽略了设备扩展检查。即使物理设备支持图形队列族，也不一定支持 `VK_KHR_swapchain`（交换链）。在创建逻辑设备前必须用 `vkEnumerateDeviceExtensionProperties` 检查。
</Callout>

## 练习

<Exercises>
1. 为什么在创建 `VkInstance` 时启用扩展，而在创建 `VkDevice` 时还要再次启用扩展？两者有何区别？
   <Answer>
   实例级扩展（如 `VK_KHR_surface`）是跨设备的全局功能，与 Vulkan 运行时相关；设备级扩展（如 `VK_KHR_swapchain`）与特定 GPU 硬件能力相关。两者作用域不同：实例扩展影响整个应用，设备扩展只影响对应逻辑设备。
   </Answer>

2. 某系统有两块 GPU，一块是集显（VK_PHYSICAL_DEVICE_TYPE_INTEGRATED_GPU），一块是独显（VK_PHYSICAL_DEVICE_TYPE_DISCRETE_GPU）。如何选择最佳设备？
   <Answer>
   遍历所有物理设备，查询 `VkPhysicalDeviceProperties`，优先选择 `deviceType == VK_PHYSICAL_DEVICE_TYPE_DISCRETE_GPU` 的设备（性能更强）。同时检查该设备是否支持所需队列族和扩展，最后可参考 `limits` 和 `memory` 属性做进一步筛选。
   </Answer>
</Exercises>

<Glossary>
  <GlossaryItem term="VkInstance">
    应用与 Vulkan 运行时的连接句柄，创建时声明应用信息与实例级扩展/层。是所有 Vulkan 操作的根。
  </GlossaryItem>
  <GlossaryItem term="VkPhysicalDevice">
    代表系统中一个实际的 Vulkan 兼容 GPU，是不可变的查询句柄，用于获取设备属性、特性和队列族信息。
  </GlossaryItem>
  <GlossaryItem term="队列族 (Queue Family)">
    一组支持相同操作类型的命令队列集合。不同队列族可能支持图形、计算、传输等不同能力，选择合适的队列族是设备初始化的关键。
  </GlossaryItem>
  <GlossaryItem term="VkDevice">
    逻辑设备句柄，代表应用对物理设备的租用。创建时指定队列配置、启用的扩展和特性，之后所有资源创建和命令提交都通过它进行。
  </GlossaryItem>
</Glossary>
