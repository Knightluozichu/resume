## 初始化的目标不是拿到一个句柄

可靠初始化应产出一份**可复现设备合同**：应用最终选中了哪块 physical device、为什么它合格、启用了哪些 feature/extension、每种 queue 来自哪个 family、surface 使用哪些 format 与 present mode，以及兼容路径为何被选中。

`vkEnumeratePhysicalDevices` 返回顺序不是性能排名，也不是稳定设备标识。直接取第一块设备、看到 discrete GPU 就加分，或只查 `VK_QUEUE_GRAPHICS_BIT`，都可能把故障推迟到 swapchain、pipeline 或 submit 阶段。正确流程先做资格判定，再在全部合格候选间做偏好排序。

## Loader 与实例版本协商

<Term def="Vulkan loader 创建的应用级句柄，用来枚举物理设备并承载实例扩展、validation 和 debug messenger">VkInstance</Term>不是 GPU context，也不绑定某一块显卡。它描述应用与 loader 的实例级合同。Vulkan 1.1 及以上 loader 可通过 `vkEnumerateInstanceVersion` 报告支持的最高实例版本；若入口不存在，应回退为 Vulkan 1.0。

`VkApplicationInfo::apiVersion` 表示应用打算使用的 Vulkan API 版本，不能高于 loader 支持范围。它也不能替代 physical device 的 `apiVersion` 或任何可选 feature 查询。

```cpp
uint32_t loaderVersion = VK_API_VERSION_1_0;
if (vkEnumerateInstanceVersion != nullptr) {
  VK_CHECK(vkEnumerateInstanceVersion(&loaderVersion));
}

const uint32_t requested = VK_API_VERSION_1_4;
const uint32_t instanceVersion = std::min(loaderVersion, requested);

VkApplicationInfo app{
  .sType = VK_STRUCTURE_TYPE_APPLICATION_INFO,
  .pApplicationName = "remuse-renderer",
  .applicationVersion = VK_MAKE_API_VERSION(0, 1, 0, 0),
  .pEngineName = "remuse",
  .engineVersion = VK_MAKE_API_VERSION(0, 1, 0, 0),
  .apiVersion = instanceVersion,
};

auto instanceExtensions = window.requiredInstanceExtensions();
appendIfAvailable(instanceExtensions, VK_EXT_DEBUG_UTILS_EXTENSION_NAME);

VkInstanceCreateInfo info{
  .sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO,
  .pApplicationInfo = &app,
  .enabledLayerCount = validationLayers.size(),
  .ppEnabledLayerNames = validationLayers.data(),
  .enabledExtensionCount = instanceExtensions.size(),
  .ppEnabledExtensionNames = instanceExtensions.data(),
};
VK_CHECK(vkCreateInstance(&info, nullptr, &instance));
```

窗口库返回的平台 surface 扩展不能凭经验硬编码。macOS 上的 portability 实现还可能要求 `VK_KHR_portability_enumeration` 和 `VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR`；是否加入必须来自实例扩展枚举结果。

## 稳健枚举与快照一致性

<Term def="由 instance 枚举得到、代表一个 Vulkan 实现设备并用于查询属性能力的不可销毁句柄">VkPhysicalDevice</Term>由实现管理，应用不创建也不销毁。常见 Vulkan 枚举 API 先查询数量再填数组；两次调用之间集合可能变化，因此第二次可能返回 `VK_INCOMPLETE`。封装枚举器应重试，而不是假设第一次 count 永远精确。

```cpp
std::vector<VkPhysicalDevice> enumeratePhysicalDevices(VkInstance instance) {
  for (;;) {
    uint32_t count = 0;
    VK_CHECK(vkEnumeratePhysicalDevices(instance, &count, nullptr));
    std::vector<VkPhysicalDevice> devices(count);
    VkResult result = vkEnumeratePhysicalDevices(instance, &count, devices.data());
    if (result == VK_SUCCESS) {
      devices.resize(count);
      return devices;
    }
    if (result != VK_INCOMPLETE) throw VulkanError(result);
  }
}
```

空列表应产生明确错误：“未发现 Vulkan physical device”，并附 loader 版本与实例扩展，而不是继续访问 `devices[0]`。

## 资格门与偏好门

设备选择分为两层：

1. **资格门**检查所有 required 条件：最低 API 版本、feature、device extension、queue family、surface present support、surface format/present mode、目标 image/buffer format feature、limits 和必要 memory type；
2. **偏好门**只在合格设备间比较：离散/集成类型、显存预算、专用 compute/transfer queue、可选扩展、功耗策略或用户显式选择。

“独显优先”只是可能的 preference。笔记本节能模式、统一内存、外接显示器连接关系或 compute-only 任务都可能让集显更合适。应用也可能向用户展示所有合格设备，而不是替用户决定。

```cpp
struct Candidate {
  VkPhysicalDevice device;
  DeviceSnapshot snapshot;
  int preferenceScore;
};

std::optional<Candidate> qualify(VkPhysicalDevice device, VkSurfaceKHR surface) {
  DeviceSnapshot s = queryDeviceSnapshot(device, surface);

  if (s.apiVersion < VK_API_VERSION_1_3) return std::nullopt;
  if (!s.features.dynamicRendering || !s.features.synchronization2 ||
      !s.features.timelineSemaphore) return std::nullopt;
  if (!s.extensions.contains(VK_KHR_SWAPCHAIN_EXTENSION_NAME)) return std::nullopt;
  if (!s.queues.graphics || !s.queues.present) return std::nullopt;
  if (s.surfaceFormats.empty() || s.presentModes.empty()) return std::nullopt;
  if (!supportsRequiredDepthFormat(s)) return std::nullopt;

  int score = 0;
  if (s.properties.deviceType == VK_PHYSICAL_DEVICE_TYPE_DISCRETE_GPU) score += 100;
  if (s.queues.dedicatedTransfer) score += 10;
  score += optionalFeatureScore(s);
  return Candidate{device, std::move(s), score};
}
```

DeviceSnapshot 应保存形成决策所需的查询结果，避免资格检查和 device 创建分别使用不同假设。设备名称可用于日志，不能当稳定唯一标识；需要持久选择时应考虑 device UUID、LUID 或 PCI bus 信息，并处理驱动更新和设备缺失。

## Properties2 与 Features2 链

`vkGetPhysicalDeviceProperties2` 和 `vkGetPhysicalDeviceFeatures2` 通过 pNext 链一次收集核心及扩展结构。<Term def="以 sType 标识结构类型、通过 pNext 链接扩展结构的 Vulkan 可扩展结构协议">pNext 链</Term>允许 API 演进而不破坏旧结构布局，但每个结构只能在规范允许的链中出现，并且不能重复同一种 sType。

查询链承载实现写回的 available 值；启用链承载应用选择的 enabled 值。把查询结构原样拿去创建设备，可能无意启用大量未测试 feature。更稳妥的做法是构造独立启用链，并对每个 true 字段保留代码层需求来源。

```cpp
VkPhysicalDeviceVulkan13Features available13{
  .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_VULKAN_1_3_FEATURES,
};
VkPhysicalDeviceVulkan12Features available12{
  .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_VULKAN_1_2_FEATURES,
  .pNext = &available13,
};
VkPhysicalDeviceFeatures2 available{
  .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_FEATURES_2,
  .pNext = &available12,
};
vkGetPhysicalDeviceFeatures2(physicalDevice, &available);

VkPhysicalDeviceVulkan13Features enabled13{
  .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_VULKAN_1_3_FEATURES,
  .synchronization2 = VK_TRUE,
  .dynamicRendering = VK_TRUE,
};
VkPhysicalDeviceVulkan12Features enabled12{
  .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_VULKAN_1_2_FEATURES,
  .pNext = &enabled13,
  .timelineSemaphore = VK_TRUE,
};
VkPhysicalDeviceFeatures2 enabled{
  .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_FEATURES_2,
  .pNext = &enabled12,
};
```

将 `enabled` 接到 `VkDeviceCreateInfo::pNext` 时，旧字段 `pEnabledFeatures` 必须为 null。若应用支持 Vulkan 1.2 + 扩展兼容路径，还要按设备 API 版本选择核心 feature 结构或扩展 feature 结构，不能在不允许的版本链中混用。

## Queue family 与逻辑设备创建

<Term def="具有相同 queue capabilities 的队列集合；应用在设备创建时按 family 请求队列数量和优先级">Queue family</Term>可支持 graphics、compute、transfer 等 flags；present 支持则需要针对目标 surface 查询。graphics 与 present 可能同族，也可能分族。

设备创建时，每个 family 最多出现一个 `VkDeviceQueueCreateInfo`。若 graphics/present 恰好是同一 index，重复提交两个 create info 属于错误。请求 queueCount 不能超过 `VkQueueFamilyProperties::queueCount`，每个优先级必须在 0 到 1 之间。

```cpp
std::set<uint32_t> uniqueFamilies = {
  queues.graphicsFamily,
  queues.presentFamily,
};
float priority = 1.0f;
std::vector<VkDeviceQueueCreateInfo> queueInfos;
for (uint32_t family : uniqueFamilies) {
  queueInfos.push_back({
    .sType = VK_STRUCTURE_TYPE_DEVICE_QUEUE_CREATE_INFO,
    .queueFamilyIndex = family,
    .queueCount = 1,
    .pQueuePriorities = &priority,
  });
}

const char* deviceExtensions[] = {VK_KHR_SWAPCHAIN_EXTENSION_NAME};
VkDeviceCreateInfo deviceInfo{
  .sType = VK_STRUCTURE_TYPE_DEVICE_CREATE_INFO,
  .pNext = &enabled,
  .queueCreateInfoCount = static_cast<uint32_t>(queueInfos.size()),
  .pQueueCreateInfos = queueInfos.data(),
  .enabledExtensionCount = 1,
  .ppEnabledExtensionNames = deviceExtensions,
  .pEnabledFeatures = nullptr,
};
VK_CHECK(vkCreateDevice(physicalDevice, &deviceInfo, nullptr, &device));
vkGetDeviceQueue(device, queues.graphicsFamily, 0, &graphicsQueue);
vkGetDeviceQueue(device, queues.presentFamily, 0, &presentQueue);
```

`VkDevice`是所有 device-level 资源和 queue 的生命周期根。销毁时先确保相关 GPU 工作完成，再销毁 pipeline、descriptor、image/buffer、command pool、swapchain 和同步对象，最后 `vkDestroyDevice`。`vkDeviceWaitIdle` 适合受控 shutdown 或简单重建边界，不应成为每帧流程。

## 多 GPU 与 device group

Vulkan 不会把枚举到的两块 GPU 自动合成更快的逻辑设备。普通 `vkCreateDevice` 选择一个 physical device。若要显式使用 device group，需要枚举 `vkEnumeratePhysicalDeviceGroups`，确认设备组能力，并为资源绑定、命令执行 mask 与呈现行为设计专门路径。很多系统上的两块 GPU 不属于可用 device group。

因此默认渲染器应把多 GPU 当“多个候选”，而不是“一份任务自动并行”。跨适配器复制、显示连接、内存可见性和同步成本通常决定 device group 是否值得。

## 常见误区

<Callout type="trap">
**现象 →** 在某些双显卡机器上总选到不连显示器的独显，创建 swapchain 后失败。
**原因 →** 只按 deviceType 排名，未把目标 surface 的 present support 与 format/present mode 放入资格门。
**修法 →** 先淘汰不满足完整 WSI 条件的设备，再在合格候选中考虑独显偏好。
</Callout>

<Callout type="trap">
**现象 →** vkCreateDevice 报 queue family index 重复或创建参数无效。
**原因 →** graphics 与 present 为同一 family，却生成了两个 VkDeviceQueueCreateInfo。
**修法 →** 对 family indices 去重，每个 family 只生成一个 create info；需要多个 queue 时增加该项 queueCount。
</Callout>

<Callout type="trap">
**现象 →** feature 查询为 true，device 创建也成功，但使用时 validation 报 feature 未启用。
**原因 →** available 查询链没有转化为独立 enabled 链，或漏接到 VkDeviceCreateInfo::pNext。
**修法 →** 对每条渲染路径维护最小启用集合，并在启动日志输出 available/enabled 差异。
</Callout>

## 练习

<Exercises>

1. **选择策略：** 独显满足所有功能但功耗高，集显也满足且连接目标显示器。怎样避免把“最佳设备”写死？

<Answer>
先用同一 required 资格门确认两者都能运行，再把性能、功耗、显存预算、显示连接和用户选择写成可配置 preference。桌面高性能配置可偏向独显，电池配置可偏向集显，并允许命令行或设置覆盖。deviceType 只影响排序，不能跳过 surface、feature、format 和 limit 检查。
</Answer>

2. **Feature 链：** 查询到 timelineSemaphore、dynamicRendering 和 synchronization2 均为 true。创建设备时最少要做什么？

<Answer>
构造独立启用结构：VkPhysicalDeviceVulkan12Features 启用 timelineSemaphore，链接 VkPhysicalDeviceVulkan13Features 启用 dynamicRendering 与 synchronization2，再由 VkPhysicalDeviceFeatures2 承载该链并接到 VkDeviceCreateInfo::pNext；同时把 pEnabledFeatures 设为 null。若设备版本低于核心版本，则需按规范改用对应扩展结构和扩展名路径。
</Answer>

3. **队列审计：** graphicsFamily=3、presentFamily=3、transferFamily=7，各请求一个 queue。应生成几个 queue create info？

<Answer>
生成两个：family 3 一个、family 7 一个。graphics 与 present 共用 family 3，不能重复 create info；创建后可以分别调用 vkGetDeviceQueue(device, 3, 0, ...) 获得同一个 queue handle 用于 graphics/present，family 7 的 index 0 用于 transfer。若希望 family 3 内使用两个不同 queue，必须检查 queueCount 至少为 2，并在同一个 create info 中请求 2。
</Answer>

</Exercises>

## 本章检查清单

- 实例版本取 loader 与应用请求的交集，实例扩展来自枚举和窗口平台需求；
- 设备资格门包含 feature、extension、queue、surface、format、limit 与 memory 条件；
- 查询链与启用链分离，device create 只启用已验证且路径需要的能力；
- queue family create infos 已去重，设备选择和淘汰原因可从日志复现。
