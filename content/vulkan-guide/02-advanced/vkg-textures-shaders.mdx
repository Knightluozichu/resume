## 创建 VkImage 还没有分配存储

<Term def="描述图像类型、format、extent、mips、layers、samples、tiling 和 usage 的资源对象；创建后仍需绑定满足 requirements 的 device memory">VkImage</Term>创建成功只建立资源描述。应用还要查询 size、alignment 和 memoryTypeBits，选择兼容 memory type，分配或从大块 allocation 子分配，再用 `vkBindImageMemory2`绑定。

为每张纹理单独 `vkAllocateMemory`容易触及 allocation count 限制并造成碎片。生产渲染器通常使用经过验证的 Vulkan Memory Allocator，或实现按 memory type、usage 和生命周期分池的 allocator；无论哪种都必须遵守 requirements alignment、memoryTypeBits 和 dedicated allocation 要求。

```cpp
VkImageCreateInfo imageInfo{
  .sType = VK_STRUCTURE_TYPE_IMAGE_CREATE_INFO,
  .imageType = VK_IMAGE_TYPE_2D,
  .format = textureFormat,
  .extent = {width, height, 1},
  .mipLevels = mipCount,
  .arrayLayers = arrayLayers,
  .samples = VK_SAMPLE_COUNT_1_BIT,
  .tiling = VK_IMAGE_TILING_OPTIMAL,
  .usage = VK_IMAGE_USAGE_TRANSFER_DST_BIT |
           VK_IMAGE_USAGE_TRANSFER_SRC_BIT |
           VK_IMAGE_USAGE_SAMPLED_BIT,
  .sharingMode = VK_SHARING_MODE_EXCLUSIVE,
  .initialLayout = VK_IMAGE_LAYOUT_UNDEFINED,
};
VK_CHECK(vkCreateImage(device, &imageInfo, nullptr, &image));

VkMemoryRequirements2 requirements{
  .sType = VK_STRUCTURE_TYPE_MEMORY_REQUIREMENTS_2,
};
VkImageMemoryRequirementsInfo2 query{
  .sType = VK_STRUCTURE_TYPE_IMAGE_MEMORY_REQUIREMENTS_INFO_2,
  .image = image,
};
vkGetImageMemoryRequirements2(device, &query, &requirements);
Allocation allocation = allocator.allocateImage(requirements, memoryPolicy);
VK_CHECK(vkBindImageMemory(device, image, allocation.memory, allocation.offset));
```

Optimal tiling 通常适合 GPU 采样和渲染，但 host 不能按紧密 RGBA 数组直接写。上传一般通过 host-visible staging buffer 再 copy 到 device-local image。

## Format 是数据语义

颜色纹理常用 `R8G8B8A8_SRGB`，因为采样时需要把 sRGB 编码转换到线性空间；法线、金属度、粗糙度、深度或任意数据纹理通常使用 UNORM/SFLOAT 等非 sRGB format。把数据纹理标成 sRGB 会在采样时错误变换数值。

创建前用 format properties 检查目标 tiling 下是否支持 sampled image、transfer、linear filtering、color/depth attachment 等真实用途。Blit 生成 mipmap 还需要相应 src/dst 与 filter feature；不支持时应离线生成、用 compute path，或选择兼容 format，而不是盲调 vkCmdBlitImage。

压缩纹理还受 block extent 和 copy offset/row length 对齐约束。Image decoder 输出的 channel order、row stride 和 alpha 语义也必须转成 Vulkan format 合同，不能只按字节数相同就 copy。

## Staging 与 host 可见性

Host-visible memory 若不是 HOST_COHERENT，CPU 写入后必须按 `nonCoherentAtomSize`对齐 range 并 `vkFlushMappedMemoryRanges`，再让 transfer queue 读取。反方向 GPU 写回供 CPU 读时则需等待 GPU 完成并 invalidate non-coherent range。

<VkgTexturesShadersDiagram />

上传命令的依赖链是：host write/flush → transfer read staging → transfer write image → shader sample。Host flush 不是 GPU pipeline barrier；queue submission 和 barrier 仍需建立 device 侧执行与内存可见性。

```cpp
flushIfNonCoherent(stagingAllocation, 0, uploadBytes);

VkImageMemoryBarrier2 toTransfer{
  .sType = VK_STRUCTURE_TYPE_IMAGE_MEMORY_BARRIER_2,
  .srcStageMask = VK_PIPELINE_STAGE_2_NONE,
  .srcAccessMask = VK_ACCESS_2_NONE,
  .dstStageMask = VK_PIPELINE_STAGE_2_COPY_BIT,
  .dstAccessMask = VK_ACCESS_2_TRANSFER_WRITE_BIT,
  .oldLayout = VK_IMAGE_LAYOUT_UNDEFINED,
  .newLayout = VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
  .image = image,
  .subresourceRange = fullMipLayerRange,
};
pipelineBarrier(cmd, toTransfer);

VkBufferImageCopy region{
  .bufferOffset = stagingOffset,
  .imageSubresource = {
    .aspectMask = VK_IMAGE_ASPECT_COLOR_BIT,
    .mipLevel = 0,
    .baseArrayLayer = 0,
    .layerCount = arrayLayers,
  },
  .imageExtent = {width, height, 1},
};
vkCmdCopyBufferToImage(cmd, stagingBuffer, image,
    VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL, 1, &region);
```

若 transfer 与 graphics 使用不同 queue families 且 image 为 EXCLUSIVE sharing，还要做 release/acquire ownership transfer，并用 semaphore 连接 submissions。只把 src/dstQueueFamilyIndex 写进一个随意 barrier 不能完整建立跨队列接力。

## 每个 mip/layer 有独立状态

<Term def="由 aspect、mip level 和 array layer 定位的 image 状态与访问最小跟踪单位">Image subresource</Term>意味着“一张 image 当前是 SHADER_READ_ONLY”常常过于粗糙。生成 mip 时，level 0 可能是 TRANSFER_SRC，level 1 是 TRANSFER_DST，已完成 levels 又可能转成 shader read。

一个典型 blit 循环对第 i-1 层执行 TRANSFER_DST → TRANSFER_SRC，blit 到第 i 层，再把第 i-1 层转到 SHADER_READ_ONLY；循环结束后单独转换最后一层。Barrier 的 subresourceRange 必须只覆盖目标 mip/layer，不能提前把尚未写入的 levels 宣布为可采样。

```cpp
for (uint32_t mip = 1; mip < mipCount; ++mip) {
  transitionMip(cmd, image, mip - 1,
      VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
      VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL,
      VK_PIPELINE_STAGE_2_COPY_BIT, VK_ACCESS_2_TRANSFER_WRITE_BIT,
      VK_PIPELINE_STAGE_2_BLIT_BIT, VK_ACCESS_2_TRANSFER_READ_BIT);

  blitMip(cmd, image, mip - 1, mip, mipExtent(mip - 1), mipExtent(mip));

  transitionMip(cmd, image, mip - 1,
      VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL,
      VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL,
      VK_PIPELINE_STAGE_2_BLIT_BIT, VK_ACCESS_2_TRANSFER_READ_BIT,
      consumingShaderStages, VK_ACCESS_2_SHADER_SAMPLED_READ_BIT);
}
transitionMip(cmd, image, mipCount - 1,
    VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
    VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL,
    VK_PIPELINE_STAGE_2_BLIT_BIT, VK_ACCESS_2_TRANSFER_WRITE_BIT,
    consumingShaderStages, VK_ACCESS_2_SHADER_SAMPLED_READ_BIT);
```

若所有 mip 离线提供，则可一次 copy 多个 VkBufferImageCopy，再用覆盖全范围的 transfer-write → shader-read barrier。状态跟踪粒度应与真实更新粒度匹配。

## Image view 是解释窗口

<Term def="为 VkImage 选择 view type、format、component mapping 与 aspect/mip/layer subresource range 的访问对象">VkImageView</Term>是 descriptor 和 attachment 实际引用的对象。一个 cubemap image 可有 cube view 和逐 face 2D views；一个 mip chain 可有全范围 sampled view 和单 mip attachment views。

Format reinterpretation 不是任意的：image 创建 flags、format compatibility class、aspect 和设备 feature 都会限制 view format。Depth/stencil image 的 aspect 选择也必须与用途匹配。

View 不拥有 image 或 memory。执行中的 descriptor 或 framebuffer 仍引用 view 时，image/view/memory 都必须保持有效；销毁顺序通常是 descriptor 使用完成 → view → image → allocation。

## Sampler 是独立采样状态

`VkSampler`定义 min/mag filter、mipmap mode、address modes、LOD bias/range、compare 和 anisotropy。它不执行 layout transition，也不限定 view format。

各向异性需要 `samplerAnisotropy` feature；maxAnisotropy 要钳制到 `VkPhysicalDeviceLimits::maxSamplerAnisotropy`，不能硬编码 16。Sampler 的 maxLod 若错误设为 0，即使 image 有完整 mip chain 也只会采样 level 0。

```cpp
VkSamplerCreateInfo samplerInfo{
  .sType = VK_STRUCTURE_TYPE_SAMPLER_CREATE_INFO,
  .magFilter = VK_FILTER_LINEAR,
  .minFilter = VK_FILTER_LINEAR,
  .mipmapMode = VK_SAMPLER_MIPMAP_MODE_LINEAR,
  .addressModeU = VK_SAMPLER_ADDRESS_MODE_REPEAT,
  .addressModeV = VK_SAMPLER_ADDRESS_MODE_REPEAT,
  .addressModeW = VK_SAMPLER_ADDRESS_MODE_REPEAT,
  .anisotropyEnable = anisotropySupported ? VK_TRUE : VK_FALSE,
  .maxAnisotropy = anisotropySupported
      ? std::min(requestedAnisotropy, limits.maxSamplerAnisotropy)
      : 1.0f,
  .minLod = 0.0f,
  .maxLod = static_cast<float>(mipCount - 1),
};
VK_CHECK(vkCreateSampler(device, &samplerInfo, nullptr, &sampler));
```

Sampler 可以在兼容纹理间共享。Immutable sampler 可固化进 descriptor set layout，减少 descriptor 内容，但会把 sampler 生命周期和布局设计绑定起来。

## Descriptor 与 shader ABI

<Term def="按 pipeline layout 中的 set/binding/type/count 把 buffer、image view 和 sampler 等资源连接到 shader 的绑定集合">Descriptor set</Term>从 descriptor pool 分配，必须符合 descriptor set layout。Pool 同时受 maxSets 和各 descriptor type 数量约束；只增加 maxSets 不能解决 combined image sampler 配额不足。

`VkDescriptorImageInfo::imageLayout`声明 descriptor 被使用时 image 处于的 layout，不会转换 image。更新 descriptor 后，实际 draw/dispatch 前必须用 barrier 把对应 subresource 转入匹配 layout并建立 shader read 可见性。

默认 descriptor set 在 pending command buffer 使用期间不能随意更新或释放。Per-frame sets、资源 generation，或经过 feature/flags 设计的 update-after-bind 路径可解决生命周期；不能只因为 `vkUpdateDescriptorSets`是 host 调用就认为 GPU 看不到竞争。

<VkgTextureContractDiagram />

Shader 源码应显式写 set 与 binding，构建时编译到目标 Vulkan environment，并反射验证 descriptor type/count、stage visibility、locations 和 push constants：

```glsl
layout(set = 1, binding = 0) uniform sampler2D baseColorTexture;

layout(push_constant) uniform DrawConstants {
    mat4 model;
    uint materialIndex;
} draw;

layout(location = 0) in vec2 uv;
layout(location = 0) out vec4 outColor;

void main() {
    outColor = texture(baseColorTexture, uv);
}
```

Push constants 的最低保证是 128 bytes，但实际可用上限由 `maxPushConstantsSize`查询。Range 的 offset/size/stageFlags 必须与 shader 和 pipeline layout 一致。它适合小而频繁的数据，不应把“一个 MVP 一定适合”写死；渲染器要根据布局、设备 limit 和 draw 模型选择 push constant、dynamic uniform buffer 或 storage buffer。

## 常见误区

<Callout type="trap">
**现象 →** 纹理在部分离散 GPU 上全黑，但集显正常。
**原因 →** staging memory 非 HOST_COHERENT，CPU 写完未 flush；统一内存设备恰好掩盖了错误。
**修法 →** 检查 memory properties，按 nonCoherentAtomSize 对齐并 flush host writes；再保留 transfer 和 shader barriers。
</Callout>

<Callout type="trap">
**现象 →** mip 0 正常，远处纹理随机或 validation 报部分 subresource layout 错误。
**原因 →** 只上传 mip 0，却把整张 image 的 descriptor/layout 当成完整 mip chain，或 barrier range 覆盖错误。
**修法 →** 为每 mip 生成/上传有效内容并独立跟踪状态；view 的 levelCount 和 sampler maxLod 不超过已发布范围。
</Callout>

<Callout type="trap">
**现象 →** descriptor 写了 SHADER_READ_ONLY_OPTIMAL，采样时仍报 image 实际处于 TRANSFER_DST。
**原因 →** 把 descriptor imageLayout 字段误当成 layout transition。
**修法 →** 在使用前录制 transfer-write → shader-read barrier 和真实 layout transition；descriptor 字段仅声明预期状态。
</Callout>

## 练习

<Exercises>

1. **内存链：** vkCreateImage 成功后为何仍不能 copy？列出到可上传前的最小步骤。

<Answer>
VkImage 尚未绑定存储。需查询 VkMemoryRequirements2，选择满足 memoryTypeBits 且符合策略的 memory type，按 size/alignment 分配或子分配 VkDeviceMemory，再 vkBindImageMemory/2。之后还要把目标 subresource 从 UNDEFINED barrier 到 TRANSFER_DST_OPTIMAL，staging 写入若 non-coherent 需 flush，才可 copy。
</Answer>

2. **Mip 状态：** 4 层 mip，刚 copy 完 level 0，准备逐级 blit。为何不能一次把 0..3 全部转到 SHADER_READ_ONLY？

<Answer>
Levels 1..3 尚未被写入，level 0 还要作为 TRANSFER_SRC，后续 level 也会在 TRANSFER_DST/TRANSFER_SRC 间变化。提前转成 shader-read 会与 blit 的真实访问和 layout 冲突。应逐层转换生产者 mip，blit 后将已完成的上一层发布为 shader-read，最后单独发布末层。
</Answer>

3. **采样器与 descriptor：** 设备不支持 anisotropy，纹理有 6 mips，descriptor 写 SHADER_READ_ONLY。怎样创建并证明可采样？

<Answer>
Sampler 将 anisotropyEnable 设 false、maxAnisotropy=1，minLod=0、maxLod=5，并选择支持的 filter/mipmap mode。Image view 覆盖 6 个有效 mips；descriptor 的 set/binding/type 与 shader/layout 匹配。上传完成后用 barrier 把六层实际转到 SHADER_READ_ONLY 并建立 consuming shader stage 的 sampled-read 可见性；descriptor 字段本身不执行转换。
</Answer>

</Exercises>

## 本章检查清单

- VkImage requirements、memoryTypeBits、alignment 和 allocation 生命周期完整，未逐资源滥用 allocation；
- host non-coherent flush、copy、mip/layer barrier 与跨 queue ownership 有完成证据；
- format/sRGB、view range、sampler feature/limits 与 descriptor imageLayout 均符合真实用途；
- SPIR-V reflection 与 pipeline layout ABI 匹配，descriptor/push constant 更新遵守 pending 生命周期。
