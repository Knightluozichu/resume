## 从一个可推翻的运行假设开始

“连接硬件设备”先固定一个问题：如何证明从物理设备能力筛选逻辑设备特性与队列合同？先写下预期对象、状态或像素，再运行正常基线；若设备属性、features链、queue family位、扩展和创建参数不能指出第一个分叉，最终画面看起来正确也不能通过。

本页不变量是：连接硬件设备的输入、状态、输出与恢复结果可用同一证据包重放。故障模式“查询到feature却未在device creation启用，或假设queue family索引固定”每次只改变一个条件，正常、故障、恢复三次运行必须共享输入与版本。

## 正式单元与机制解释

### Instance, Physical and Logical Devices, Features, and Queues

在“连接硬件设备”的“Instance, Physical and Logical Devices, Features, and Queues”检查中，VkPhysicalDevice描述硬件、限制、格式和queue family；VkDevice只启用明确请求的feature与extension。在“连接硬件设备”的“Instance, Physical and Logical Devices, Features, and Queues”检查中，队列由family能力和创建数量决定，图形、计算与传输职责可能共享也可能分离。

在“连接硬件设备”本页，正式坐标是vkinstance、vkphysicaldevice、vkdevice、queue family、feature、extension。在“连接硬件设备”的反例核对中，反事实为“查询到feature却未在device creation启用，或假设queue family索引固定”；应从设备属性、features链、queue family位、扩展和创建参数找到第一个分叉。

$$
Device=select(Properties,Features,Queues)
$$

## 最小可重现实验

```cpp
for (VkPhysicalDevice gpu : enumeratePhysicalDevices(instance)) {
  Candidate c = inspect(gpu);
  if (c.features && c.extensions && c.queues) choose(c);
}
```

运行“连接硬件设备”时记录API/规范版本、设备或浏览器能力、固定输入、关键中间状态与输出摘要。不得用一次漂亮截图替代对象合同、验证消息、时间戳或像素差异。

<Callout type="trap" title="本页核心误区">

</Callout>
