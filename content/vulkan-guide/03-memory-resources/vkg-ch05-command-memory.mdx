## 从一个可推翻的运行假设开始

“指令缓存与内存管理”先固定一个问题：如何证明把buffer/image需求匹配到内存类型、绑定、传输与所有权；按线程所有权录制command buffer并构造可复用提交？先写下预期对象、状态或像素，再运行正常基线；若requirements、memory type、绑定偏移、copy范围、layout和owner family、pool线程归属、buffer状态、submit批次、等待/信号值和fence不能指出第一个分叉，最终画面看起来正确也不能通过。

本页不变量是：指令缓存与内存管理的输入、状态、输出与恢复结果可用同一证据包重放。故障模式“只按属性标志挑内存却忽略memoryTypeBits，或跨队列使用未转移所有权；多个线程并发重置同一command pool，或执行仍处pending状态的buffer”每次只改变一个条件，正常、故障、恢复三次运行必须共享输入与版本。

## 正式单元与机制解释

### Memory Allocation, Buffers, Images, Transfers, and Ownership

在“指令缓存与内存管理”的“Memory Allocation, Buffers, Images, Transfers, and Ownership”检查中，VkBuffer和VkImage先声明用途，再查询memory requirements并绑定满足memoryTypeBits的分配。在“指令缓存与内存管理”的“Memory Allocation, Buffers, Images, Transfers, and Ownership”检查中，staging路径把host写入与device-local消费分开；跨queue family使用还需明确ownership transfer。

在“指令缓存与内存管理”本页，正式坐标是memory allocation、vkbuffer、vkimage、staging、memory type、queue family ownership。在“指令缓存与内存管理”的反例核对中，反事实为“只按属性标志挑内存却忽略memoryTypeBits，或跨队列使用未转移所有权”；应从requirements、memory type、绑定偏移、copy范围、layout和owner family找到第一个分叉。

$$
typeBits\land properties\ne 0
$$

### Command Pools, Command Buffers, Queue Submission, and Threading

在“指令缓存与内存管理”的“Command Pools, Command Buffers, Queue Submission, and Threading”检查中，command pool管理同一queue family的command buffer分配与重置；外部同步要求同一pool不能被多个线程无保护并发访问。在“指令缓存与内存管理”的“Command Pools, Command Buffers, Queue Submission, and Threading”检查中，record只编码命令，queue submission才建立执行批次，secondary buffer适合明确继承边界的并行录制。

在“指令缓存与内存管理”本页，正式坐标是command pool、command buffer、record、vkqueuesubmit、secondary command buffer、thread。在“指令缓存与内存管理”的反例核对中，反事实为“多个线程并发重置同一command pool，或执行仍处pending状态的buffer”；应从pool线程归属、buffer状态、submit批次、等待/信号值和fence找到第一个分叉。

$$
Submit=Waits+CommandBuffers+Signals
$$

## 最小可重现实验

```cpp
ThreadContext& t = contexts[workerId];
VkCommandBuffer cmd = t.begin(queueFamily);
vkCmdCopyBuffer(cmd, staging, deviceLocal, 1, &region);
t.endAndEnqueue(cmd);
```

运行“指令缓存与内存管理”时记录API/规范版本、设备或浏览器能力、固定输入、关键中间状态与输出摘要。不得用一次漂亮截图替代对象合同、验证消息、时间戳或像素差异。

<Callout type="trap" title="本页核心误区">
  只按属性标志挑内存却忽略memoryTypeBits，或跨队列使用未转移所有权；多个线程并发重置同一command pool，或执行仍处pending状态的buffer。它会破坏“指令缓存与内存管理的输入、状态、输出与恢复结果可用同一证据包重放”，应先由requirements、memory type、绑定偏移、copy范围、layout和owner family、pool线程归属、buffer状态、submit批次、等待/信号值和fence定位。
</Callout>
