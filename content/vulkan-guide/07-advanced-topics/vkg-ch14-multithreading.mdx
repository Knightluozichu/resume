## 从一个可推翻的运行假设开始

## 正式单元与机制解释

### Command Pools, Command Buffers, Queue Submission, and Threading

在“多线程Vulkan应用程序”的“Command Pools, Command Buffers, Queue Submission, and Threading”检查中，command pool管理同一queue family的command buffer分配与重置；外部同步要求同一pool不能被多个线程无保护并发访问。在“多线程Vulkan应用程序”的“Command Pools, Command Buffers, Queue Submission, and Threading”检查中，record只编码命令，queue submission才建立执行批次，secondary buffer适合明确继承边界的并行录制。

在“多线程Vulkan应用程序”本页，正式坐标是command pool、command buffer、record、vkqueuesubmit、secondary command buffer、thread。在“多线程Vulkan应用程序”的反例核对中，反事实为“多个线程并发重置同一command pool，或执行仍处pending状态的buffer”；应从pool线程归属、buffer状态、submit批次、等待/信号值和fence找到第一个分叉。

$$
Submit=Waits+CommandBuffers+Signals
$$

## 最小可重现实验

```cpp
parallel_for(workers, [&](uint32_t id) {
  VkCommandBuffer secondary = threadPools[id].beginSecondary(inheritance);
  recordChunk(secondary, chunks[id]);
  ready[id] = threadPools[id].end(secondary);
});
```

运行“多线程Vulkan应用程序”时记录API/规范版本、设备或浏览器能力、固定输入、关键中间状态与输出摘要。不得用一次漂亮截图替代对象合同、验证消息、时间戳或像素差异。

<Callout type="trap" title="本页核心误区">
