## 直觉引入

把 Windows 想象成一座「大楼管理处」。你写的一个程序 `myapp.exe` 双击运行后，它的一生要经过五道关卡：管理处先给它一张「门禁卡」（句柄 HANDLE），让它知道怎么调用大楼的各种设施（Win32 API，第 2 章）；它要在前台接收各种「通知单」（消息循环，第 3 章），知道用户按了什么键、点了什么按钮；它要在大楼里开一间「办公室」（窗口管理，第 4 章），并在墙上贴海报（GDI 绘图，第 5 章）；它要查阅大楼的「档案柜」（注册表，第 6 章）并雇佣「清洁工」（服务与线程，第 7 章）；它要存取「仓库」（文件 I/O，第 8 章）和打电话给其他大楼（网络编程，第 9 章）；最后用一个程序从 `WinMain` 到 `WM_DESTROY` 的完整旅程串起全部知识点（总复习，第 10 章）。本书回答的就是这些「Windows 程序怎么与系统交互」的工程原理问题。

## 五阶段递进

<Term def="Win32 API 是微软为 Windows 操作系统提供的核心 C 语言编程接口，封装在 user32.dll、kernel32.dll、gdi32.dll 三大子系统中，涵盖窗口管理、系统服务和图形设备三大领域，是所有 Windows 桌面程序的底层基石。">Win32 API</Term>的学习可以拆成五个递进阶段。**API基础与消息循环**包括句柄体系、函数调用范式和消息驱动模型——它们解决「怎么调用系统」和「怎么响应事件」。**窗口管理与GDI绘图**包括窗口类注册、窗口生命周期和图形设备接口——它们解决「怎么创建界面」和「怎么绘制图形」。**系统机制**包括注册表、服务和进程线程——它们解决「怎么配置系统」和「怎么并发执行」。**高级I/O**包括文件I/O和网络编程——它们解决「怎么持久化数据」和「怎么跨机通信」。**总复习**用一个窗口程序从启动到退出的完整旅程串联全部知识点。

```text
// 「一个窗口程序从启动到退出」——Windows 全程参与的生命周期
int WINAPI WinMain(hInstance, hPrevInstance, lpCmdLine, nCmdShow)
  // 1. API基础（第 2 章）：获取实例句柄，初始化网络子系统
  //    GetModuleHandle(NULL) → hInstance
  //    WSAStartup() 初始化 Winsock

  // 2. 注册窗口类（第 4 章）：定义窗口模板
  //    WNDCLASSEX { lpfnWndProc = MyWindowProc, lpszClassName = "MyApp" }
  //    RegisterClassEx(&wc)

  // 3. 创建窗口（第 4 章）：实例化窗口
  //    CreateWindowEx(0, "MyApp", "我的应用", WS_OVERLAPPEDWINDOW, ...)
  //    ShowWindow(hwnd, nCmdShow) → 触发 WM_PAINT

  // 4. 消息循环（第 3 章）：分发消息
  //    while (GetMessage(&msg, NULL, 0, 0)) {
  //        TranslateMessage(&msg);  // 按键 → 字符
  //        DispatchMessage(&msg);   // 分发到 WindowProc
  //    }

  // 5. GDI 绘制（第 5 章）：WM_PAINT 中绘制
  //    BeginPaint(hwnd, &ps) → hdc
  //    SelectObject(hdc, hPen) → 选入画笔
  //    Rectangle(hdc, 10, 10, 200, 100) → 绘制矩形
  //    TextOut(hdc, 10, 120, L"Hello", 5) → 绘制文本
  //    EndPaint(hwnd, &ps)

  // 6. 注册表（第 6 章）：读取配置
  //    RegOpenKeyEx(HKEY_CURRENT_USER, L"Software\\MyApp", ...)
  //    RegQueryValueEx(hKey, L"Setting", ...) → 读取配置值

  // 7. 进程线程（第 7 章）：后台处理
  //    CreateThread(NULL, 0, WorkerThread, params, 0, &tid)
  //    WaitForSingleObject(hThread, INFINITE) → 等待完成

  // 8. 文件 I/O（第 8 章）：读写数据
  //    CreateFile(L"data.bin", GENERIC_READ, ...)
  //    ReadFile(hFile, buf, size, &bytesRead, &overlapped)

  // 9. 网络编程（第 9 章）：跨机通信
  //    socket(AF_INET, SOCK_STREAM, 0)
  //    connect(sock, &serverAddr, sizeof(addr))
  //    send(sock, buf, len, 0) / recv(sock, buf, len, 0)

  // 10. 退出：WM_DESTROY → PostQuitMessage(0)
  //     closesocket / WSACleanup / CloseHandle / DestroyWindow
  //     GetMessage 收到 WM_QUIT 返回 FALSE → 循环结束 → 进程退出
```

## 常见误区

<Callout type="trap">
**误区：会调 Win32 API 就等于懂 Windows 编程。** 会写 `CreateWindow`、`MessageBox` 弹个框只是「会用 Windows API」——照着 MSDN 抄就能做。真正懂 Windows 编程的人能解释：为什么句柄是不透明类型而非直接指针（内核对象封装与安全隔离）、为什么消息循环用 `GetMessage` 阻塞而非忙等待（节省 CPU）、为什么 GDI 要设备上下文而非直接画（设备无关性）、为什么跨线程 `SendMessage` 可能死锁（同步等待对方处理）、为什么 IOCP 用少量线程处理海量连接（减少线程切换）。把 Windows 当黑盒的人遇到窗口卡死只能重启；懂机制的人能读懂消息队列、用 Spy++ 追踪消息、理解同步对象状态、排查句柄泄漏。区分标志：能否解释「Windows 为什么这样设计」而非只是「能调用它」。
</Callout>

<Exercises>
**问题 1**：全书五阶段递进是什么？为什么是这个顺序？

<Answer>
API基础与消息循环（Win32 API + 消息循环）→ 窗口管理与GDI绘图（窗口管理 + GDI渲染）→ 系统机制（注册表与服务 + 进程与线程）→ 高级I/O（文件I/O + 网络编程）→ 总复习。顺序由依赖关系决定：先掌握 API 调用范式和消息驱动模型才有「能调用、能响应」的基础；窗口是 Windows 程序的载体，有了窗口才能在其上绘制图形文本；窗口程序需要读取配置（注册表）和后台处理（服务/线程），于是进入系统机制；程序要持久化数据和跨机器通信，于是需要文件 I/O 和网络编程；最后总复习用一个窗口程序的一生串联全链路。先「能调用」，再「能创建」，然后「能配置并发」，接着「能存储通信」，最后「能贯通」。
</Answer>

**问题 2**：用「一个窗口程序的一生」描述全书主线。

<Answer>
一个窗口程序从 `WinMain` 启动到退出：①API基础（第2章）——`WinMain` 入口，获取实例句柄；②注册窗口类（第4章）——填充 `WNDCLASSEX`，`RegisterClassEx` 注册；③创建窗口（第4章）——`CreateWindowEx` 创建，`ShowWindow` 显示；④消息循环（第3章）——`GetMessage`/`TranslateMessage`/`DispatchMessage`；⑤GDI绘制（第5章）——`WM_PAINT` 中 `BeginPaint` 获取 DC，`TextOut`/`Rectangle` 绘制；⑥系统配置（第6章）——`RegOpenKey`/`RegQueryValue` 读取注册表；⑦并发处理（第7章）——`CreateThread` 后台线程，`WaitForSingleObject` 同步；⑧文件与网络（第8-9章）——`CreateFile` 读写文件，`socket`/`connect`/`send`/`recv` 网络通信；⑨退出——`WM_DESTROY` → `PostQuitMessage` → 资源回收。一次运行，九个机制全部参与。
</Answer>
</Exercises>

<GlossaryItem term="五阶段递进">API基础与消息循环 → 窗口管理与GDI绘图 → 系统机制 → 高级I/O → 总复习。每层解决前一层的遗留问题：API解决「怎么调用」，消息循环解决「怎么响应」，窗口解决「怎么创建界面」，GDI解决「怎么绘制」，注册表解决「怎么配置」，线程解决「怎么并发」，文件I/O解决「怎么存储」，网络解决「怎么通信」。</GlossaryItem>
