## 直觉引入

想象你在一家公司的前台工作。外面的人（用户输入、系统事件、其他程序）不断把信件（消息）塞进你的信箱（消息队列）。你不断做三件事：打开信箱取一封信（`GetMessage`）、看看是不是外文信需要翻译（`TranslateMessage`）、把信交给对应部门处理（`DispatchMessage`）。部门（窗口过程）看完信决定怎么处理，处理完继续等你送下一封。这就是 Windows 消息驱动的核心——程序不是「主动做事情」，而是「被动响应消息」。

## 消息驱动三步曲

<Term def="窗口过程（WindowProc）是窗口类注册时指定的回调函数，所有发往该类窗口的消息都由它处理。通过 switch(message) 分支不同消息类型，未处理的消息交给 DefWindowProc 做默认处理。">窗口过程</Term>是消息驱动的核心。消息循环三步曲：

```c
// 消息循环：Windows GUI 程序的心脏
MSG msg;
while (GetMessage(&msg, NULL, 0, 0)) {  // ① 取出消息（阻塞直到有消息）
    TranslateMessage(&msg);               // ② 翻译按键消息为字符消息
    DispatchMessage(&msg);                // ③ 分发到窗口过程
}
// GetMessage 返回 FALSE（收到 WM_QUIT）时退出循环

// 窗口过程：消息的最终处理者
LRESULT CALLBACK WindowProc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam) {
    switch (msg) {
        case WM_CREATE:
            // 窗口创建时初始化
            return 0;

        case WM_PAINT: {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hwnd, &ps);
            // 绘制内容...
            EndPaint(hwnd, &ps);
            return 0;
        }

        case WM_LBUTTONDOWN:
            // 鼠标左键点击：wParam = 按键状态, lParam = 坐标
            {
                int x = LOWORD(lParam);
                int y = HIWORD(lParam);
                // 处理点击...
            }
            return 0;

        case WM_DESTROY:
            PostQuitMessage(0);  // 发送 WM_QUIT 终止消息循环
            return 0;

        default:
            return DefWindowProc(hwnd, msg, wParam, lParam);  // 默认处理
    }
}
```

## PostMessage 与 SendMessage

`PostMessage` 和 `SendMessage` 的本质区别决定了 Windows 程序的并发行为：

```c
// PostMessage：异步，放入队列后立即返回
PostMessage(hwnd, WM_USER+100, 0, 0);
// 不等待处理结果，调用线程继续执行
// 适合：通知另一个线程做某事、跨线程通信

// SendMessage：同步，直接调用窗口过程并等待返回
LRESULT result = SendMessage(hwnd, WM_USER+200, 0, 0);
// 阻塞直到目标窗口过程返回
// 适合：需要立即获取处理结果

// 跨线程 SendMessage 的安全替代：
// 1. SendNotifyMessage —— 不等返回结果（类似异步 SendMessage）
SendNotifyMessage(hwnd, WM_USER+300, 0, 0);

// 2. SendMessageTimeout —— 带超时，避免永久阻塞
DWORD result;
SendMessageTimeout(hwnd, WM_USER+400, 0, 0,
                   SMTO_ABORTIFHUNG, 5000, &result);  // 5秒超时
```

消息队列分为系统队列和线程队列。硬件事件（键盘/鼠标）先进系统队列，`win32k.sys` 转换为 `WM_*` 消息后放入目标线程的消息队列。`WM_PAINT` 和 `WM_TIMER` 是低优先级合成消息，只有队列为空时才生成，避免频繁重绘。

<Callout type="trap">
**误区：在窗口过程中做耗时操作没关系，用户会等。** 窗口过程运行在 UI 线程的消息循环中。如果在 `WM_LBUTTONDOWN` 中执行耗时操作（如网络请求、大文件读取），消息循环被阻塞——窗口无法响应任何消息（重绘、移动、点击），表现为「窗口卡死/无响应」。正确做法：耗时操作放到工作线程（`CreateThread` 或线程池），完成后用 `PostMessage` 通知 UI 线程更新界面。绝不在窗口过程中阻塞超过 100ms。
</Callout>

<Exercises>
**问题 1**：消息循环三步曲是什么？每一步做什么？

<Answer>
①`GetMessage`——从线程消息队列取出消息，阻塞直到有消息（返回 TRUE），收到 WM_QUIT 返回 FALSE 退出循环；②`TranslateMessage`——将虚拟键消息（WM_KEYDOWN/WM_KEYUP）翻译为字符消息（WM_CHAR），不产生字符的按键不做任何事；③`DispatchMessage`——将消息分发给目标窗口的窗口过程处理。三步循环直到 WM_QUIT。窗口过程通过 switch(message) 分支处理，未处理的交给 DefWindowProc。
</Answer>

**问题 2**：PostMessage 和 SendMessage 的本质区别是什么？

<Answer>
`PostMessage` 将消息放入目标窗口所在线程的消息队列后立即返回（异步），不等待处理结果——适合「发后不管」和跨线程通信。`SendMessage` 直接调用目标窗口的窗口过程并等待返回结果（同步）——适合需要立即获取结果的场景。跨线程时 `PostMessage` 安全（消息排队），`SendMessage` 会阻塞调用线程等待目标线程处理，可能死锁。同一线程内 `SendMessage` 就是直接函数调用，不经过队列。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="消息驱动模型">Windows GUI 程序的核心编程范式：程序不主动执行逻辑，而是被动响应系统发来的消息。消息来源包括用户输入（键盘/鼠标）、系统事件（窗口创建/绘制）、应用程序自发（PostMessage/SendMessage）。程序核心结构是「初始化+消息循环+窗口过程回调」三段式。</GlossaryItem>
<GlossaryItem term="消息队列">每个 GUI 线程拥有一个消息队列，存储待处理的消息。消息按 FIFO 顺序处理。WM_PAINT 和 WM_TIMER 是低优先级合成消息，只有队列为空时才生成。GetMessage 从队列取消息（阻塞），PeekMessage 取消息但不阻塞。</GlossaryItem>
<GlossaryItem term="窗口过程（WindowProc）">窗口类注册时通过 WNDCLASSEX.lpfnWndProc 指定的回调函数。所有发往该类窗口的消息都由它处理。通过 switch(message) 分支不同消息类型，返回 LRESULT。未处理的消息交给 DefWindowProc 做默认处理（如窗口移动、最小化等系统行为）。</GlossaryItem>
</Glossary>
