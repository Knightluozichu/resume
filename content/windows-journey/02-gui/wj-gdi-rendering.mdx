## 直觉引入

你在白纸上画画，需要三样东西：画笔（决定线条颜色粗细）、画刷（决定填充颜色）、纸（画在哪里）。在 GDI 里，纸就是**设备上下文（DC）**，画笔和画刷就是 **GDI 对象**。你不用关心纸是屏幕还是打印机——DC 帮你把同样的绘制操作映射到不同设备上。这就是 GDI 的核心哲学：**设备无关性**——一套代码，到处可画。

## DC 与 GDI 对象

<Term def="设备上下文（Device Context，DC）是 GDI 的核心数据结构，定义了图形输出的目标设备和绘制属性（画笔、画刷、字体、映射模式、裁剪区域）。HDC 是 DC 的句柄。通过 DC 实现设备无关性——同一套 GDI 函数可在屏幕、打印机、位图上输出。">设备上下文（DC）</Term>是 GDI 绘制的入口。GDI 对象的创建→使用→销毁有严格流程：

```c
// WM_PAINT 中的标准绘制流程
case WM_PAINT: {
    PAINTSTRUCT ps;
    HDC hdc = BeginPaint(hwnd, &ps);  // ① 获取 DC

    // ② 创建 GDI 对象
    HPEN hPen = CreatePen(PS_SOLID, 2, RGB(255, 0, 0));      // 红色实线画笔
    HBRUSH hBrush = CreateSolidBrush(RGB(0, 0, 255));        // 蓝色实心画刷

    // ③ 选入 DC（保存旧对象）
    HPEN hOldPen = (HPEN)SelectObject(hdc, hPen);
    HBRUSH hOldBrush = (HBRUSH)SelectObject(hdc, hBrush);

    // ④ 绘制
    Rectangle(hdc, 10, 10, 200, 100);   // 带边框和填充的矩形
    MoveToEx(hdc, 10, 10, NULL);        // 移动画笔位置
    LineTo(hdc, 200, 100);              // 画直线
    TextOutW(hdc, 10, 120, L"Hello GDI", 8);  // 绘制文本

    // ⑤ 恢复旧对象
    SelectObject(hdc, hOldPen);
    SelectObject(hdc, hOldBrush);

    // ⑥ 销毁新对象
    DeleteObject(hPen);
    DeleteObject(hBrush);

    EndPaint(hwnd, &ps);  // ⑦ 释放 DC
    return 0;
}
```

GDI 对象六大家族：`HPEN`（画笔）、`HBRUSH`（画刷）、`HFONT`（字体）、`HBITMAP`（位图）、`HRGN`（区域）、`HPALETTE`（调色板）。创建后必须 `SelectObject` 选入 DC 才生效，使用完毕必须恢复旧对象后 `DeleteObject` 销毁。

## 双缓冲与映射模式

直接在窗口 DC 上绘制会产生闪烁——每一步绘制立即显示，背景填充和图形绘制之间的时间差被肉眼看到。双缓冲技术在内存中完成全部绘制后一次性拷贝到屏幕：

```c
// 双缓冲：消除闪烁
case WM_PAINT: {
    PAINTSTRUCT ps;
    HDC hdc = BeginPaint(hwnd, &ps);
    RECT rc; GetClientRect(hwnd, &rc);
    int w = rc.right - rc.left, h = rc.bottom - rc.top;

    // 1. 创建内存 DC 和兼容位图
    HDC memDC = CreateCompatibleDC(hdc);
    HBITMAP memBmp = CreateCompatibleBitmap(hdc, w, h);
    HBITMAP oldBmp = (HBITMAP)SelectObject(memDC, memBmp);

    // 2. 在内存 DC 上绘制（不可见）
    FillRect(memDC, &rc, (HBRUSH)GetStockObject(WHITE_BRUSH));
    Rectangle(memDC, 10, 10, 200, 100);
    TextOutW(memDC, 10, 120, L"双缓冲", 3);

    // 3. 一次性拷贝到屏幕（无闪烁）
    BitBlt(hdc, 0, 0, w, h, memDC, 0, 0, SRCCOPY);

    // 4. 清理
    SelectObject(memDC, oldBmp);
    DeleteObject(memBmp);
    DeleteDC(memDC);

    EndPaint(hwnd, &ps);
    return 0;
}
```

<Callout type="trap">
**误区：创建 GDI 对象后不选入 DC 也能用。** GDI 对象创建后只是存在于内存中，必须通过 `SelectObject(hdc, hObj)` 选入 DC 才对后续绘制生效。选入时返回 DC 中之前的旧对象——必须保存旧对象并在绘制完毕后选回，否则旧对象（可能是系统默认对象）会泄漏。更严重的是：正在被 DC 使用的对象不能 `DeleteObject`——必须先选回旧对象再删除。GDI 对象有进程上限（约 10000 个），泄漏会导致绘制失败。
</Callout>

<Exercises>
**问题 1**：什么是设备上下文（DC）？为什么 GDI 绘制必须通过 DC？

<Answer>
DC 是定义图形输出目标设备和绘制属性的数据结构（含画笔、画刷、字体、映射模式、裁剪区域等）。HDC 是其句柄。必须通过 DC 的原因：①设备无关性——同一套 GDI 函数（Rectangle、TextOut）由 DC 映射到不同物理设备（屏幕、打印机、位图）；②属性封装——绘制属性绑定在 DC 上，简化 API；③状态管理——DC 维护当前绘制状态，连续操作共享属性。获取方式：GetDC（客户区）、BeginPaint（WM_PAINT）、CreateCompatibleDC（内存DC）。用完必须 ReleaseDC 或 EndPaint 释放。
</Answer>

**问题 2**：双缓冲如何解决闪烁问题？

<Answer>
闪烁原因：直接在窗口 DC 上绘制时每一步立即显示，背景填充和图形绘制的时间差造成肉眼可见闪烁。双缓冲原理：创建内存 DC（CreateCompatibleDC）和兼容位图（CreateCompatibleBitmap），在内存 DC 上完成全部绘制（不可见），然后用 BitBlt 一次性拷贝到窗口 DC——整个画面同时更新，无中间闪烁。核心是「先在后台画完，再一次性显示」。双缓冲是 GDI 流畅动画的标配。
</Answer>
</Exercises>
