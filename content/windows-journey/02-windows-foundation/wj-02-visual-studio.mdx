## 核心机制深挖

把Visual Studio 2010、VC++、项目/解决方案、MSDN、Visual Assist X和文件类型组织成可复现工具链，而不是只记安装截图。 原书处于Visual Studio 2010、Windows桌面、GDI、DirectX 9固定功能管线与当时DirectX SDK的技术环境。本页保留这套历史API的目录身份，同时把今天仍成立的窗口生命周期、资源所有权、坐标流水线、状态隔离和可重放实验单独标明，不能用现代接口名称覆盖原书。

本页不变量是：**源码、头文件、库、运行时和构建配置有明确来源，同一提交在固定环境可重复构建。**。它必须在初始化、逐帧更新、绘制、错误返回和销毁路径同时成立。成功显示一帧只是样本，不代表窗口过程、COM引用、GDI对象、缓存边界、渲染状态或输入焦点都正确。

最小实验：从空解决方案创建Win32程序，记录预处理、编译、链接、加载四阶段产物与诊断。 运行前固定编译器、SDK、资源、窗口尺寸、随机种子与输入序列，运行后保存每个阶段的返回码、对象数量、关键矩阵或状态、帧截图摘要和销毁结果。

故障实验：分别移除头文件路径、库目录和运行时DLL，比较编译期、链接期和加载期故障。 删除故障后必须以完全相同的输入重放；若画面恢复但句柄数、资源引用、渲染状态或游戏状态仍与基线不同，就不能判定通过。

现代实现可以用新版Visual Studio、Direct3D 11/12或其他图形API重做同一实验，但对照表必须清楚写出设备创建、资源绑定、着色阶段和呈现模型的差异。迁移的目标是验证机制，不是伪称2013年原书已经讲授后来接口。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：画面看起来正确就代表程序正确。**
  历史图形API允许很多状态悄悄跨帧保留，窗口消息、GDI对象、COM引用和输入焦点也可能已经失配，必须检查首个状态分叉与销毁后的对象数量。
</Callout>

<Callout type="trap">
  **误区二：把现代DirectX知识倒灌进原书目录。**
  本书讲授的是2013年前后的Windows、GDI和DirectX
  9主线；现代对照可以补充，但不能改写版本身份或跳过原书的固定功能管线与示例结构。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                           | 必查证据               | 通过条件     |
| ---- | ---------------------------------- | ---------------------- | ------------ |
| 正常 | 固定工具链、资源和输入             | 六阶段状态与帧结果     | 与预测一致   |
| 边界 | 空资源、极小窗口、最大对象数       | 边界检查与终止条件     | 不越界不忙等 |
| 失败 | 坏句柄、缺资源、设备丢失、状态泄漏 | 首个错误与责任层       | 错误被隔离   |
| 恢复 | 逆序清理后同输入重放               | 对象数、状态哈希与画面 | 回到基线     |
