## 核心机制深挖

以API/SDK、WinMain、句柄、消息队列、窗口创建四步曲、两种消息循环和窗口过程构成Windows程序最小闭环。 原书处于Visual Studio 2010、Windows桌面、GDI、DirectX 9固定功能管线与当时DirectX SDK的技术环境。本页保留这套历史API的目录身份，同时把今天仍成立的窗口生命周期、资源所有权、坐标流水线、状态隔离和可重放实验单独标明，不能用现代接口名称覆盖原书。

本页不变量是：**每个窗口消息都有确定接收者和默认处理出口，创建、显示、泵送、销毁顺序完整且不忙等。**。它必须在初始化、逐帧更新、绘制、错误返回和销毁路径同时成立。成功显示一帧只是样本，不代表窗口过程、COM引用、GDI对象、缓存边界、渲染状态或输入焦点都正确。

最小实验：实现两个等价窗口，分别用GetMessage与PeekMessage循环，记录空闲CPU、输入延迟和WM_DESTROY退出链。 运行前固定编译器、SDK、资源、窗口尺寸、随机种子与输入序列，运行后保存每个阶段的返回码、对象数量、关键矩阵或状态、帧截图摘要和销毁结果。

故障实验：注入未分派消息、遗漏DefWindowProc、错误句柄和退出消息，定位窗口卡死或泄漏的首因。 删除故障后必须以完全相同的输入重放；若画面恢复但句柄数、资源引用、渲染状态或游戏状态仍与基线不同，就不能判定通过。

现代实现可以用新版Visual Studio、Direct3D 11/12或其他图形API重做同一实验，但对照表必须清楚写出设备创建、资源绑定、着色阶段和呈现模型的差异。迁移的目标是验证机制，不是伪称2013年原书已经讲授后来接口。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：画面看起来正确就代表程序正确。**
  历史图形API允许很多状态悄悄跨帧保留，窗口消息、GDI对象、COM引用和输入焦点也可能已经失配，必须检查首个状态分叉与销毁后的对象数量。
</Callout>

<Callout type="trap">
  **误区二：把现代DirectX知识倒灌进原书目录。**
  本书讲授的是2013年前后的Windows、GDI和DirectX
  9主线；现代对照可以补充，但不能改写版本身份或跳过原书的固定功能管线与示例结构。
</Callout>

**问题 2** 如何把“第3章 启程——Windows编程基础”变成可执行证据？

<Answer>
  沿“进入WinMain、注册窗口类、创建显示窗口、泵送消息、执行窗口过程、销毁并退出”固定环境，只改变一个条件，保存首个分叉；删除故障后用同一输入重放并比较资源数和结果。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  每个窗口消息都有确定接收者和默认处理出口，创建、显示、泵送、销毁顺序完整且不忙等。
  异常路径不得污染下一帧或下一次运行，资源有唯一清理责任，恢复轨迹重新到达基线。
</Answer>
