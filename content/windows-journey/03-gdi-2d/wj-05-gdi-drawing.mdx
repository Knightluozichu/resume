```text
freeze -> 创建后备 DC -> 清理背景 -> 绘制精灵 -> 完成合成 -> 一次发布
fault -> 源 DC 与目标 DC 尺寸或 ROP 顺序错误
evidence -> 缓冲代际、BitBlt 次数、透明像素和帧差分
reset -> replay identical input
```

真实程序还要固定编译器、SDK、窗口尺寸、资源、随机种子、时间步和输入记录；否则历史实现与现代迁移不能公平比较。

<Callout type="trap" title="把历史 API 当成当前默认方案">
  本章保留 GDI 双缓冲 的教学身份，但新项目必须核对平台支持并解释为何选择 现代离屏表面 或其他方案。
</Callout>

<Callout type="trap" title="只看最终画面">
  第5章 遮羞的艺术——Windows游戏绘图技巧必须说明创建后备 DC、清理背景、绘制精灵、完成合成、一次发布的先后关系；最终像素相同不代表消息、资源、矩阵或状态安全。
</Callout>

<Callout type="trap" title="失败后继续运行">
  注入“源 DC 与目标 DC 尺寸或 ROP 顺序错误”后应停在第一个因果分叉；若缓冲代际、BitBlt 次数、透明像素和帧差分无法解释并复位，当前实现失败。
</Callout>
