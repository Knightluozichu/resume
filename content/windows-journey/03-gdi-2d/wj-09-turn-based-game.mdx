## 核心机制深挖

以《勇者斗恶龙》项目整合角色、技能、敌方AI、资源初始化、窗口过程、动作逻辑、特效和最终发布。 原书处于Visual Studio 2010、Windows桌面、GDI、DirectX 9固定功能管线与当时DirectX SDK的技术环境。本页保留这套历史API的目录身份，同时把今天仍成立的窗口生命周期、资源所有权、坐标流水线、状态隔离和可重放实验单独标明，不能用现代接口名称覆盖原书。

本页不变量是：**每回合输入只结算一次，生命/法力/冷却满足边界，渲染读取已提交状态而不暗改规则。**。它必须在初始化、逐帧更新、绘制、错误返回和销毁路径同时成立。成功显示一帧只是样本，不代表窗口过程、COM引用、GDI对象、缓存边界、渲染状态或输入焦点都正确。

最小实验：用固定种子运行百场战斗，保存每回合动作、数值变化和胜负，重放并比较状态哈希。 运行前固定编译器、SDK、资源、窗口尺寸、随机种子与输入序列，运行后保存每个阶段的返回码、对象数量、关键矩阵或状态、帧截图摘要和销毁结果。

故障实验：注入重复点击、法力不足、死亡后行动和AI无合法动作，验证状态机拒绝非法转移。 删除故障后必须以完全相同的输入重放；若画面恢复但句柄数、资源引用、渲染状态或游戏状态仍与基线不同，就不能判定通过。

现代实现可以用新版Visual Studio、Direct3D 11/12或其他图形API重做同一实验，但对照表必须清楚写出设备创建、资源绑定、着色阶段和呈现模型的差异。迁移的目标是验证机制，不是伪称2013年原书已经讲授后来接口。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：画面看起来正确就代表程序正确。**
  历史图形API允许很多状态悄悄跨帧保留，窗口消息、GDI对象、COM引用和输入焦点也可能已经失配，必须检查首个状态分叉与销毁后的对象数量。
</Callout>

<Callout type="trap">
  **误区二：把现代DirectX知识倒灌进原书目录。**
  本书讲授的是2013年前后的Windows、GDI和DirectX
  9主线；现代对照可以补充，但不能改写版本身份或跳过原书的固定功能管线与示例结构。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                           | 必查证据               | 通过条件     |
| ---- | ---------------------------------- | ---------------------- | ------------ |
| 正常 | 固定工具链、资源和输入             | 六阶段状态与帧结果     | 与预测一致   |
| 边界 | 空资源、极小窗口、最大对象数       | 边界检查与终止条件     | 不越界不忙等 |
| 失败 | 坏句柄、缺资源、设备丢失、状态泄漏 | 首个错误与责任层       | 错误被隔离   |
| 恢复 | 逆序清理后同输入重放               | 对象数、状态哈希与画面 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只用最终画面验收第9章 梦的初现——开发回合制游戏《勇者斗恶龙》？

<Answer>
  最终画面会隐藏消息丢失、对象泄漏、状态串扰和不可重放更新。必须比较六阶段返回码、所有权、状态快照、帧结果与逆序清理。
</Answer>

**问题 2** 如何把“第9章 梦的初现——开发回合制游戏《勇者斗恶龙》”变成可执行证据？

<Answer>
  沿“定义角色数据、解析玩家行动、选择敌方策略、结算技能效果、绘制战斗反馈、保存可重放轨迹”固定环境，只改变一个条件，保存首个分叉；删除故障后用同一输入重放并比较资源数和结果。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  每回合输入只结算一次，生命/法力/冷却满足边界，渲染读取已提交状态而不暗改规则。
  异常路径不得污染下一帧或下一次运行，资源有唯一清理责任，恢复轨迹重新到达基线。
</Answer>

</Exercises>
