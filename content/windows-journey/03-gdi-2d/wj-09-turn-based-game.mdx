## 问题先于 API

场景切换、战斗和资源加载混在消息处理分支中会产生非法状态。本章先保存问题、初态和输入，再讨论 API；通过条件是“一次只存在一个主状态，存档重载后得到相同地图和回合进度”，不是画面偶然出现一次。

原书处于 Visual Studio 2010、Win32/GDI、DirectX 9 与固定功能管线语境。现代 API 只作迁移对照：GDI 回合项目和分层状态项目名称可以不同，但必须消费相同输入并守住同一不变量。

## 可重放实现或计算骨架

```text
freeze -> 加载地图 -> 等待动作 -> 解析回合 -> 结算战斗 -> 保存恢复
fault -> 战斗退出时残留输入或资源引用进入地图状态
evidence -> 状态转换日志、地图坐标、回合序号和存档哈希
reset -> replay identical input
```

真实程序还要固定编译器、SDK、窗口尺寸、资源、随机种子、时间步和输入记录；否则历史实现与现代迁移不能公平比较。
