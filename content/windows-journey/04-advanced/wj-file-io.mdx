## 直觉引入

文件 I/O 就像去仓库存取货物。同步 I/O 是「亲自去仓库取货」——你叫一辆卡车（`ReadFile`），等卡车开到仓库装好货开回来，你才能做下一件事。异步 I/O 是「委托快递公司」——你下单（`ReadFile` + `OVERLAPPED`）后立即去做别的事，快递公司在后台送货，送到后给你发通知。完成端口（IOCP）是「快递公司 + 多个快递员」——你有一队快递员（线程池）在快递站（完成端口）等通知，货物一到就有人处理，不需要你亲自等。

## 同步与异步 I/O

<Term def="异步 I/O（Overlapped I/O）是 Windows 的高效 I/O 模式：传入 OVERLAPPED 结构并使用 FILE_FLAG_OVERLAPPED 打开文件，ReadFile/WriteFile 立即返回，操作在后台进行，完成后通过事件、APC 回调或完成端口通知。线程不阻塞在单个 I/O 上。">异步 I/O</Term>的核心在于线程不阻塞等待：

```c
// 同步 I/O：阻塞直到完成
HANDLE hFile = CreateFileW(L"data.bin", GENERIC_READ, FILE_SHARE_READ,
    NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
char buf[4096];
DWORD bytesRead;
ReadFile(hFile, buf, sizeof(buf), &bytesRead, NULL);  // 阻塞直到读完
// 线程在这里等着，什么都做不了
CloseHandle(hFile);

// 异步 I/O（Overlapped）：立即返回，后台完成
HANDLE hFile = CreateFileW(L"data.bin", GENERIC_READ, FILE_SHARE_READ,
    NULL, OPEN_EXISTING, FILE_FLAG_OVERLAPPED, NULL);  // 注意标志

OVERLAPPED ov = {};
ov.Offset = 0;  // 文件起始位置（异步I/O不用文件指针）
ov.hEvent = CreateEventW(NULL, TRUE, FALSE, NULL);  // 完成通知事件

char buf[4096];
DWORD bytesRead;
BOOL result = ReadFile(hFile, buf, sizeof(buf), &bytesRead, &ov);
if (!result && GetLastError() == ERROR_IO_PENDING) {
    // I/O 正在进行，线程可以做其他事...
    // 等待完成（也可以用 IOCP 或 APC）
    WaitForSingleObject(ov.hEvent, INFINITE);
    GetOverlappedResult(hFile, &ov, &bytesRead, FALSE);  // 获取实际读取量
}
CloseHandle(ov.hEvent);
CloseHandle(hFile);
```

## IOCP 完成端口

<Term def="完成端口（I/O Completion Port，IOCP）是 Windows 最高效的异步 I/O 模型。创建完成端口对象，关联多个文件/套接字句柄；I/O 完成后通知投递到端口的完成队列；线程池通过 GetQueuedCompletionStatus 取通知处理。内核自动负载均衡，限制并发线程数。">IOCP</Term>是高并发服务器的核心：

```c
// IOCP 高并发模型
HANDLE hIOCP = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);

// 将文件句柄关联到完成端口
CreateIoCompletionPort(hFile, hIOCP, (ULONG_PTR)sessionData, 0);
// sessionData 是完成键（CompletionKey），用于标识这个 I/O 属于哪个会话

// 工作线程：循环处理完成通知
DWORD WINAPI WorkerThread(LPVOID param) {
    HANDLE hIOCP = (HANDLE)param;
    DWORD bytesTransferred;
    ULONG_PTR completionKey;
    OVERLAPPED* pOv;
    while (true) {
        BOOL ok = GetQueuedCompletionStatus(hIOCP, &bytesTransferred,
                                            &completionKey, &pOv, INFINITE);
        if (!ok) continue;

        SessionData* session = (SessionData*)completionKey;
        if (bytesTransferred == 0) {
            // 连接关闭
            closesocket(session->sock);
            delete session;
            continue;
        }

        // 处理已完成的 I/O 数据
        // ... 业务逻辑 ...

        // 投递下一个异步读
        // WSARecv(session->sock, ...);
    }
    return 0;
}

// 创建 N+1 个工作线程（N = CPU 核数）
SYSTEM_INFO si;
GetSystemInfo(&si);
for (int i = 0; i < si.dwNumberOfProcessors + 1; i++) {
    CreateThread(NULL, 0, WorkerThread, hIOCP, 0, NULL);
}
```

## 内存映射文件

```c
// 内存映射文件：像访问内存一样读写文件
HANDLE hFile = CreateFileW(L"large.dat", GENERIC_READ | GENERIC_WRITE,
    FILE_SHARE_READ, NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

HANDLE hMapping = CreateFileMappingW(hFile, NULL, PAGE_READWRITE, 0, 0, NULL);

// 映射到进程地址空间
LPVOID pData = MapViewOfFile(hMapping, FILE_MAP_ALL_ACCESS, 0, 0, 0);

// 直接通过指针访问文件内容（零拷贝）
int* values = (int*)pData;
values[0] = 42;  // 直接写入文件（内核按需分页写回）

UnmapViewOfFile(pData);
CloseHandle(hMapping);
CloseHandle(hFile);
```

<Callout type="tip">
**最佳实践：高并发服务器用 IOCP，大文件处理用内存映射。** IOCP 的核心优势是少量线程管理海量并发 I/O——线程不阻塞在单个 I/O 上，完成通知由内核自动负载均衡分发给空闲线程。并发度由 `CreateIoCompletionPort` 的 `NumberOfConcurrentThreads` 参数控制（通常设为 CPU 核数）。内存映射文件适合处理大文件——内核按需分页加载，只有实际访问的页面才从磁盘读取，避免了 ReadFile 的用户态↔内核态数据拷贝（零拷贝）。
</Callout>

<Exercises>
**问题 1**：同步 I/O 和异步 I/O 的区别是什么？OVERLAPPED 结构的作用？

<Answer>
同步 I/O：ReadFile/WriteFile 阻塞调用线程直到完成——简单但低效。异步 I/O（Overlapped）：用 FILE_FLAG_OVERLAPPED 打开文件，传入 OVERLAPPED 结构，函数立即返回，操作后台进行。OVERLAPPED 包含 Offset/OffsetHigh（文件位置，异步I/O不用文件指针）和 hEvent（完成通知事件）。完成通知方式：①轮询 GetOverlappedResult；②等待 hEvent 事件；③APC 回调（ReadFileEx + alertable wait）；④IOCP 完成端口。核心优势：少量线程管理海量并发 I/O。
</Answer>

**问题 2**：什么是完成端口（IOCP）？为什么它是高并发服务器的核心？

<Answer>
IOCP 是 Windows 最高效的异步 I/O 模型。核心：创建完成端口对象，关联多个文件/套接字句柄；I/O 完成后通知投递到端口完成队列；线程池通过 GetQueuedCompletionStatus 取通知处理。高效原因：①线程不阻塞在 I/O 上——一个线程可发起数百个异步 I/O；②线程池自动负载均衡——内核将完成通知分发给空闲线程；③并发度控制——NumberOfConcurrentThreads 限制同时运行线程数，防止过多线程导致调度开销。典型模式：N+1 个工作线程（N=CPU核数）循环取完成通知处理。
</Answer>

<Glossary>
<GlossaryItem term="异步 I/O（Overlapped）">Windows 高效 I/O 模式。用 FILE_FLAG_OVERLAPPED 打开文件，传入 OVERLAPPED 结构，ReadFile/WriteFile 立即返回，操作后台进行。OVERLAPPED 含 Offset（文件位置）和 hEvent（完成事件）。完成通知：轮询/事件/APC/IOCP。优势：线程不阻塞在单个 I/O 上，少量线程管理海量并发 I/O。</GlossaryItem>
<GlossaryItem term="IOCP（完成端口）">Windows 最高效的异步 I/O 模型。创建完成端口，关联文件/套接字句柄；I/O 完成后通知投递到完成队列；线程池通过 GetQueuedCompletionStatus 取通知处理。内核自动负载均衡，NumberOfConcurrentThreads 限制并发线程数。是 Windows 高并发网络服务器（如 IIS）的标配。</GlossaryItem>
<GlossaryItem term="内存映射文件">将文件直接映射到进程虚拟地址空间的技术。CreateFileMapping + MapViewOfFile 后通过指针访问即等于读写文件。优势：①零拷贝（内核直接管理页面缓存，无用户态↔内核态拷贝）；②按需分页（只有访问的页面才从磁盘加载）；③进程间共享内存（多进程映射同一文件实现最快 IPC）。适合大文件处理和数据库引擎。</GlossaryItem>
</Glossary>
