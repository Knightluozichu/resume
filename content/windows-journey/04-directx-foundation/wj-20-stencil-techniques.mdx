20.6 章节小憩 进入“执行比较”阶段时，先标出输入、状态拥有者和可见输出，再解释第一遍按条件写模板，后续遍用引用值和比较函数限制颜色写入。2013 年的 API 名称作为历史坐标保留；迁移到现代工具时只替换实现，不能改变本章问题与证据口径。

验证 20.6 章节小憩 时固定其余条件，记录模板值、引用值、掩码、比较结果、每遍颜色写入，随后注入“未清模板或写掩码/读掩码混淆导致遮罩跨帧残留”并执行复位。该节点由此同时具备出现、解释、专属实验和练习验证四级证据。

## 可重放实现或计算骨架

```text
freeze -> 清除模板 -> 写入遮罩 -> 执行比较 -> 应用操作 -> 受限绘制
fault -> 未清模板或写掩码/读掩码混淆导致遮罩跨帧残留
evidence -> 模板值、引用值、掩码、比较结果、每遍颜色写入
reset -> replay identical input
```

真实程序还要固定编译器、SDK、窗口尺寸、资源、随机种子、时间步和输入记录；否则历史实现与现代迁移不能公平比较。

<Callout type="trap" title="把历史 API 当成当前默认方案">
  本章保留 D3D9 模板状态 的教学身份，但新项目必须核对平台支持并解释为何选择 现代模板附件 或其他方案。
</Callout>

<Callout type="trap" title="只看最终画面">
  第20章 虚实结合的光影——模板技术必须说明清除模板、写入遮罩、执行比较、应用操作、受限绘制的先后关系；最终像素相同不代表消息、资源、矩阵或状态安全。
</Callout>

<Callout type="trap" title="失败后继续运行">
  注入“未清模板或写掩码/读掩码混淆导致遮罩跨帧残留”后应停在第一个因果分叉；若模板值、引用值、掩码、比较结果、每遍颜色写入无法解释并复位，当前实现失败。
</Callout>
