```text
freeze -> 定义帧合同 -> 划分子系统 -> 注入依赖 -> 运行调度 -> 逆序销毁

evidence -> 依赖图、帧时序、资源图、替身测试和模块替换记录
reset -> replay identical input
```

真实程序还要固定编译器、SDK、窗口尺寸、资源、随机种子、时间步和输入记录；否则历史实现与现代迁移不能公平比较。

<Callout type="trap" title="把历史 API 当成当前默认方案">
  本章保留 教学引擎雏形 的教学身份，但新项目必须核对平台支持并解释为何选择 可替换子系统 或其他方案。
</Callout>

<Callout type="trap" title="只看最终画面">
  第26章 站在巨人肩膀上——游戏引擎技术导论必须说明定义帧合同、划分子系统、注入依赖、运行调度、逆序销毁的先后关系；最终像素相同不代表消息、资源、矩阵或状态安全。
</Callout>

<Callout type="trap" title="失败后继续运行">
  注入“渲染系统反向控制游戏规则或全局单例决定销毁顺序”后应停在第一个因果分叉；若依赖图、帧时序、资源图、替身测试和模块替换记录无法解释并复位，当前实现失败。
</Callout>
