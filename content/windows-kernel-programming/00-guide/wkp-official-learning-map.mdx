## 常见误区与故障注入

<Callout type="trap">
  **误区一：驱动加载成功就说明内核代码正确。**
  很多错误只在缓冲边界、并发回调、错误IRQL或卸载时出现。必须启用定向Verifier并验证完成、引用、池和锁序。
</Callout>

<Callout type="trap">
  **误区二：把这本书改写成WDM/WDF或硬件驱动通论。**
  正式目录的主线是软件内核驱动、系统通知、小过滤器和设备过滤；PnP、MDL和WDF只能在相关机制处作对照，不能冒充原章节。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据                 | 通过条件     |
| ---- | -------------------------- | ------------------------ | ------------ |
| 基线 | 固定快照、sys/PDB和输入    | 状态码、IRQL、对象与日志 | 与预测一致   |
| 边界 | 空缓冲、短输出、断开客户端 | 长度、Information、引用  | 不越界不泄漏 |
| 失败 | 错IRQL、竞态、Verifier规则 | 首错栈和责任层           | 故障可定位   |
| 恢复 | 清理或快照后同输入重放     | 模块、服务、池、回调状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看用户模式输出验收《Windows内核编程》权威学习地图？

<Answer>
  输出可能隐藏错误IRQL、重复完成、悬空回调、池泄漏和卸载竞态。必须同时检查NTSTATUS/Information、内核序号日志、对象引用、Verifier和恢复重放。
</Answer>

**问题 2** 如何把“Introduction读者与样例”变成可执行证据？

<Answer>
  沿“核对版本目录、建立隔离环境、完成基础驱动、追踪IRP机制、实现系统通知、交付过滤项目”固定虚拟机、WDK、sys/PDB和输入，预测调用线程、IRQL、对象与状态码，只改变一个条件并保存首错；恢复后比较IRP、回调、池或过滤上下文。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  11章185个核心目录层级都有唯一教学归属；软件内核驱动主线不会被硬件驱动、PnP或WDF通论替换。
  失败路径不得污染下一轮，卸载与清理明确，相同输入和事件序列能够重新到达基线。
</Answer>

</Exercises>
