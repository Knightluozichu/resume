## 直觉引入

把 IRP 想象成一张「多层工单簿」。用户程序提交一个读写请求，I/O 管理器（前台）把请求写在工单簿的封面上（IRP 头部：状态码、传输字节数），然后为设备栈的每一层各撕一页（I/O 栈位置：功能码、参数）。工单簿从顶楼向下传，每一层读完自己那页后翻到下一页（`IoCallDriver` 自动下移栈指针）。某一层处理完了就在封面上盖章（`IoCompleteRequest` 设置 IoStatus），然后工单簿从底楼向上回收，每一层在回收时可以检查盖章结果（完成例程）。如果用户中途反悔要取消，前台会在工单簿上画个叉（Cancel 标志），各层需要检查叉号并丢弃工单。

## IRP 结构与栈位置

<Term def="IRP（I/O Request Packet）是 Windows 内核中表示一个 I/O 请求的结构体，由头部和 I/O 栈位置数组组成，沿设备栈逐层传递，是内核 I/O 的统一货币。">IRP</Term>由两部分组成。**IRP 头部**包含 `IoStatus`（Status 状态码 + Information 传输字节数）、Cancel 标志、关联线程、MdlAddress 等，由 I/O 管理器维护。**I/O 栈位置数组**（`IO_STACK_LOCATION`）每个设备栈层对应一个，包含 `MajorFunction`（主功能码如 `IRP_MJ_READ`）、`MinorFunction`（次功能码如 `IRP_MN_START_DEVICE`）、`Parameters`（联合体，不同功能码有不同含义）。

```text
// IRP 的核心操作模式
// 1. 获取当前栈位置（每个派遣函数的第一步）
PIO_STACK_LOCATION stack = IoGetCurrentIrpStackLocation(Irp);
ULONG length = stack->Parameters.Read.Length;

// 2. 向下传递（过滤驱动不处理时）
IoSkipCurrentIrpStackLocation(Irp);  // 跳过当前层
IoCallDriver(ext->LowerDevice, Irp);  // 交给下层

// 3. 同步完成（立即处理完毕）
Irp->IoStatus.Status = STATUS_SUCCESS;
Irp->IoStatus.Information = bytesRead;
IoCompleteRequest(Irp, IO_NO_INCREMENT);
return STATUS_SUCCESS;

// 4. 异步处理（需稍后完成）
IoMarkIrpPending(Irp);  // 标记挂起
// ... 保存 Irp 到队列，后续在 DPC 中完成 ...
return STATUS_PENDING;

// 5. 注册完成例程（向下传递时监控结果）
IoCopyCurrentIrpStackLocationToNext(Irp);
IoSetCompletionRoutine(Irp, MyCompletion, context, TRUE, TRUE, TRUE);
IoCallDriver(ext->LowerDevice, Irp);
```

## 完成例程与取消机制

**完成例程**通过 `IoSetCompletionRoutine` 注册，当 `IoCompleteRequest` 时自底向上调用。返回 `STATUS_SUCCESS` 表示接受完成继续向上传递，返回 `STATUS_MORE_PROCESSING_REQUIRED` 表示拦截完成不继续向上（通常配合自行创建的 IRP 使用）。**取消机制**由 `IoCancelIrp` 设置 Cancel 标志并调用驱动的 `CancelRoutine`。实现可取消 I/O 的关键：IRP 必须先加入可搜索队列再注册 CancelRoutine；持有队列锁时检查 Cancel 标志；CancelRoutine 和正常完成路径都必须用自旋锁保护队列操作。

## 常见误区

<Callout type="trap">
**误区：返回 STATUS_PENDING 就不用 IoMarkIrpPending。** `STATUS_PENDING` 只是告诉 I/O 管理器「请求未完成」，但如果不调用 `IoMarkIrpPending`，I/O 管理器不会知道这个 IRP 需要后续完成——当别的代码最终调用 `IoCompleteRequest` 时，I/O 管理器可能认为 IRP 已被放弃而引发崩溃。规则：**只要返回 STATUS_PENDING，就必须先调用 IoMarkIrpPending**。另一个误区是向下传递 IRP 后还在本层访问它——`IoCallDriver` 后 IRP 的所有权已转移给下层，本层不能再访问（除非注册了完成例程并在其中访问）。
</Callout>

<Exercises>
**问题 1**：描述 IRP 从创建到完成的完整生命周期。

<Answer>
四阶段：①创建——I/O 管理器根据用户请求 IoCreateIrp 分配 IRP，填充头部和栈位置，关联用户缓冲区；②派发——IoCallDriver 将 IRP 交给驱动，查找 MajorFunction 派遣函数并调用，栈指针下移一层；③处理——驱动可同步完成（IoCompleteRequest 返回状态）、异步处理（IoMarkIrpPending + STATUS_PENDING）、或向下传递（IoCallDriver + IoSetCompletionRoutine）；④完成——IoCompleteRequest 设置 IoStatus，沿栈向上调用各层 CompletionRoutine，最终 I/O 管理器释放 IRP 并唤醒用户线程。
</Answer>

**问题 2**：IRP 取消机制如何工作？实现可取消 I/O 需要注意什么？

<Answer>
用户 CancelIo 或超时，I/O 管理器调用 IoCancelIrp 设置 Cancel 标志，若注册了 CancelRoutine 则调用它。注意：①IRP 先加入队列再注册 CancelRoutine（否则找不到）；②持队列锁时检查 Cancel 标志；③CancelRoutine 和正常完成路径都用自旋锁保护；④IoSetCancelRoutine(NULL) 返回值判断 CancelRoutine 是否已被调用。取消是内核中最易出竞态的场景之一。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="IRP">I/O Request Packet，内核 I/O 请求的统一表示。由头部（IoStatus/Cancel/线程）和 I/O 栈位置数组组成，沿设备栈逐层传递。每层通过 IoGetCurrentIrpStackLocation 读参数，IoCallDriver 下移栈指针。</GlossaryItem>
<GlossaryItem term="I/O 栈位置">IO_STACK_LOCATION，IRP 中每个设备栈层对应的参数空间。含 MajorFunction（主功能码）、MinorFunction（次功能码）、Parameters（联合体）。IoCallDriver 自动下移栈指针，IoSkipCurrentIrpStackLocation 跳过当前层。</GlossaryItem>
<GlossaryItem term="完成例程">IoSetCompletionRoutine 注册的回调，当 IoCompleteRequest 时自底向上调用。返回 STATUS_SUCCESS 继续向上，STATUS_MORE_PROCESSING_REQUIRED 拦截完成。用于过滤监控、资源释放、拆分请求后续处理。</GlossaryItem>
<GlossaryItem term="IoMarkIrpPending">标记 IRP 为挂起状态。只要返回 STATUS_PENDING 就必须先调用此函数，告诉 I/O 管理器该 IRP 将被后续完成。不调用会导致 IRP 完成时崩溃。</GlossaryItem>
</Glossary>
