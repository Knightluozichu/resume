## 为什么从这个问题开始

第5章 调试围绕“WinDbg、符号、宿主—目标、转储与可重复症状怎样定位首个内核分岔？”建立贯穿任务。先冻结出版轨、目标build、驱动包和对象身份，再以小输入观察状态与调用链，最后用唯一故障和同输入恢复验收；只有守住“每份转储和轨迹都绑定目标build、驱动摘要、符号、输入与唯一故障”并交付宿主/目标清单、符号验证、转储、调用栈、首错假设与恢复报告，目录术语、DDI名字或一次成功加载才可能升级为机制证据。
