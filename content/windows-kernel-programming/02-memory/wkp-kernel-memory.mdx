## 直觉引入

把内核内存想象成两座「仓库」。**非分页池**是「常驻冷库」——东西放在这里永远不会搬走，任何时刻任何人（任何 IRQL）都能直接取用，但仓库空间有限且昂贵。**分页池**是「临时仓库」——东西放在这里可能被搬到远处（换出到磁盘），只有在低优先级时段（PASSIVE_LEVEL）才能安全去取，如果高优先级时去取会发现东西不在（缺页蓝屏），但仓库空间大且便宜。驱动的任务是根据「什么时候要访问这块内存」来选仓库：中断处理（高 IRQL）要用的放冷库，普通请求处理（低 IRQL）要用的放临时仓库。

## 两种内存池

<Term def="非分页池（NonPaged Pool）是 Windows 内核中物理页被永久锁定的内存区域，任何 IRQL 均可安全访问，用于 DPC/ISR 中访问的数据和自旋锁保护的共享数据。">非分页池</Term>的物理页永不换出，DISPATCH_LEVEL 和 DIRQL 均可安全访问。分配函数为 `ExAllocatePool2(POOL_FLAG_NON_PAGED, Size, Tag)`，用于 ISR/DPC 数据、自旋锁保护的全局链表、DMA 缓冲区、设备扩展等。<Term def="分页池（Paged Pool）是 Windows 内核中数据可换出到磁盘的内存区域，仅在 PASSIVE_LEVEL 和 APC_LEVEL 可安全访问。">分页池</Term>可换出，仅低 IRQL 可访问，分配函数为 `ExAllocatePool2(POOL_FLAG_PAGED, Size, Tag)`，用于低频访问的大块数据、注册表缓存等。

```text
// 内核内存分配与释放规范
// 1. 新 API（推荐）：ExAllocatePool2
PVOID buf = ExAllocatePool2(POOL_FLAG_NON_PAGED, 4096, 'myTag');
if (!buf) return STATUS_INSUFFICIENT_RESOURCES;
// ... 使用 buf ...
ExFreePool(buf);  // 必须配对释放

// 2. 旧 API（已废弃）：ExAllocatePoolWithTag
// 危险：不保证零初始化，可能导致内核数据泄漏（CVE）
PVOID old = ExAllocatePoolWithTag(NonPagedPool, 4096, 'myTag');
// ExFreePoolWithTag(old, 'myTag');  // Tag 必须匹配

// 3. IRQL 决定池选型
// DPC/ISR 中：必须用非分页池（高 IRQL 不能缺页）
// PASSIVE_LEVEL 中：可用分页池（节省物理内存）

// 4. 池标签规范
// - 4 字节标识，标记内存归属驱动
// - 分配和释放必须匹配
// - Driver Verifier 用 Tag 追踪泄漏
// - 禁止用 'None' / 'Ddk ' 等通用标签
```

## 池标签与调试

池标签是 4 字节标识符，在分配时指定，标记内存归属。Driver Verifier 的 Pool Tracking 按标签统计分配/释放，`!poolused` 命令列出各标签的未释放字节数，快速定位泄漏。`!pool <地址>` 查看某地址所属标签，帮助判断是哪个驱动分配的。标签通常用驱动名的 4 个字符，同一驱动的不同用途用不同标签（如 `'rbuf'` 接收、`'sbuf'` 发送）。

## 常见误区

<Callout type="trap">
**误区：在 DPC 中分配分页池。** DPC 运行在 DISPATCH_LEVEL，分页池的数据可能已被换出。访问换出页需要缺页处理，而缺页需要 APC_LEVEL（等待 I/O），当前 IRQL 高于 APC_LEVEL 无法降级，导致蓝屏（IRQL_NOT_LESS_OR_EQUAL）。规则：**代码路径的最高 IRQL 决定内存选型**——DPC/ISR 中只能用非分页池，PASSIVE_LEVEL 才能用分页池。Driver Verifier 的 Force IRQL Checking 会强制在每次提升 IRQL 时检查是否访问了分页数据。
</Callout>

<Exercises>
**问题 1**：非分页池和分页池的区别是什么？如何选择？

<Answer>
非分页池：物理页永久锁定不换出，任何 IRQL 可访问。用于 DPC/ISR 数据、自旋锁保护的共享数据、DMA 缓冲区。分页池：可换出，仅 PASSIVE_LEVEL/APC_LEVEL 可访问。用于低频大块数据。选择原则：代码路径的最高 IRQL 决定选型——高 IRQL 用非分页池，低 IRQL 可用分页池节省物理内存。
</Answer>

**问题 2**：在高 IRQL 下访问分页内存会怎样？如何排查？

<Answer>
分页内存可能已换出，缺页处理需 APC_LEVEL 但当前 IRQL 更高无法降级，导致蓝屏（IRQL_NOT_LESS_OR_EQUAL）。排查：①!analyze -v 确认 IRQL 和地址；②!pte 查看页表项是否 Valid；③检查调用栈定位高 IRQL 访问分页数据的函数；④Driver Verifier 开 Force IRQL Checking。避免：DPC/ISR 只访问非分页池，持自旋锁时不访问分页内存。
</Answer>
</Exercises>

<Glossary>
<GlossaryItem term="非分页池（NonPaged Pool）">物理页永久锁定不换出的内核内存区域，任何 IRQL 均可安全访问。用于 DPC/ISR 数据、自旋锁保护的全局数据、DMA 缓冲区、设备扩展。分配：ExAllocatePool2(POOL_FLAG_NON_PAGED, ...)。代价是占用物理内存无法回收。</GlossaryItem>
<GlossaryItem term="分页池（Paged Pool）">数据可换出到磁盘的内核内存区域，仅 PASSIVE_LEVEL/APC_LEVEL 可安全访问。用于低频大块数据、注册表缓存。分配：ExAllocatePool2(POOL_FLAG_PAGED, ...)。优势是可换出减轻物理内存压力。</GlossaryItem>
<GlossaryItem term="ExAllocatePool2">Windows 10 2004 引入的新内存分配 API，默认零初始化（消除信息泄漏）、返回 NULL 而非蓝屏、统一标志位。替代了因安全隐患（不初始化导致内核数据泄漏）被废弃的 ExAllocatePoolWithTag。</GlossaryItem>
<GlossaryItem term="池标签（Pool Tag）">4 字节内存标识符，在分配时指定，标记内存归属驱动。Driver Verifier 用 Tag 追踪分配/释放，!poolused 查看泄漏，!pool 查看地址归属。分配和释放必须匹配，禁止用通用标签。</GlossaryItem>
</Glossary>
