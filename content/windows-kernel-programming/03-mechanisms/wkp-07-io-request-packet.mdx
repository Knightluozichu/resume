## 直觉起点

<Term def="IRP连接接收IRP阶段的IRQL、对象、请求和恢复证据。">IRP</Term>、<Term def="I/O栈位置连接读取栈位置阶段的IRQL、对象、请求和恢复证据。">I/O栈位置</Term>、<Term def="IoCompleteRequest连接验证长度方法阶段的IRQL、对象、请求和恢复证据。">IoCompleteRequest</Term>、<Term def="缓冲/直接I/O连接访问系统缓冲阶段的IRQL、对象、请求和恢复证据。">缓冲/直接I/O</Term>、<Term def="Zero驱动连接设置完成状态阶段的IRQL、对象、请求和恢复证据。">Zero驱动</Term>
共同构成本页坐标。从设备节点、IRP与I/O栈位置、分发和完成进入用户缓冲访问、缓冲/直接I/O，并以Zero驱动贯通读写。

内核编程必须同时画三张图：调用图说明用户请求、系统回调或I/O如何进入驱动；对象图说明DriverObject、DeviceObject、IRP、回调Cookie、上下文和池块由谁拥有；时间图说明注册、并发回调、注销、排空和卸载的先后。少一张图，表面可用的驱动也可能在压力或卸载时蓝屏。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：驱动加载成功就说明内核代码正确。**
  很多错误只在缓冲边界、并发回调、错误IRQL或卸载时出现。必须启用定向Verifier并验证完成、引用、池和锁序。
</Callout>

<Callout type="trap">
  **误区二：把这本书改写成WDM/WDF或硬件驱动通论。**
  正式目录的主线是软件内核驱动、系统通知、小过滤器和设备过滤；PnP、MDL和WDF只能在相关机制处作对照，不能冒充原章节。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据                 | 通过条件     |
| ---- | -------------------------- | ------------------------ | ------------ |
| 基线 | 固定快照、sys/PDB和输入    | 状态码、IRQL、对象与日志 | 与预测一致   |
| 边界 | 空缓冲、短输出、断开客户端 | 长度、Information、引用  | 不越界不泄漏 |
| 失败 | 错IRQL、竞态、Verifier规则 | 首错栈和责任层           | 故障可定位   |
| 恢复 | 清理或快照后同输入重放     | 模块、服务、池、回调状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看用户模式输出验收第7章 I/O请求包？

<Answer>
  输出可能隐藏错误IRQL、重复完成、悬空回调、池泄漏和卸载竞态。必须同时检查NTSTATUS/Information、内核序号日志、对象引用、Verifier和恢复重放。
</Answer>

**问题 2** 如何把“第7章 I/O请求包”变成可执行证据？

<Answer>
  沿“接收IRP、读取栈位置、验证长度方法、访问系统缓冲、设置完成状态、由客户端核对结果”固定虚拟机、WDK、sys/PDB和输入，预测调用线程、IRQL、对象与状态码，只改变一个条件并保存首错；恢复后比较IRP、回调、池或过滤上下文。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  每个IRP只完成一次，IoStatus与Information准确，缓冲访问方式匹配设备标志和IOCTL
  Method，挂起路径保有资源。
  失败路径不得污染下一轮，卸载与清理明确，相同输入和事件序列能够重新到达基线。
</Answer>

</Exercises>
