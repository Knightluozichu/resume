## 核心机制深挖

从设备节点、IRP与I/O栈位置、分发和完成进入用户缓冲访问、缓冲/直接I/O，并以Zero驱动贯通读写。 本书讨论的是Windows软件内核驱动：进程、线程、映像、对象、注册表、文件系统和过滤机制，而不是硬件PnP/WDF通论。正文保留2019原版与2021中文版的技术身份；新WDK API只能作为显式迁移对照。

本页不变量是：**每个IRP只完成一次，IoStatus与Information准确，缓冲访问方式匹配设备标志和IOCTL Method，挂起路径保有资源。**。它必须在正常请求、零长度、无效句柄、缓冲不足、错误IRQL、并发注销和中途卸载中都成立。NTSTATUS成功只是一个观察点，不能证明Information、对象引用、池Tag、锁序和完成次数都正确。

最小实验：实现Zero驱动的Read/Write路径，对缓冲I/O、直接I/O和DeviceIoControl四种Method建立矩阵测试。 每次运行前记录Windows构建、WDK、架构、签名模式、sys/PDB哈希、Driver Verifier配置和虚拟机快照；运行后保存客户端输出、内核序号日志、WinDbg命令及资源差异。

故障实验：注入重复完成、Information错误、MDL为空、METHOD_NEITHER未探测和取消竞态，检查首个分叉。 每轮只改变一个条件并停在第一处偏离。恢复必须使用明确卸载/清理步骤或虚拟机快照，再以相同客户端输入、事件顺序和Verifier配置重放。

证据表至少包含阶段、调用线程、当前IRQL、对象/缓冲所有者、预期与实际NTSTATUS、首错、清理动作七列。涉及回调时还要记录注册Cookie、进入计数、注销时刻和排空条件；涉及IRP时记录Major/Minor、栈位置、缓冲方法、Status/Information和完成次数；涉及过滤器时记录实例、文件对象、名称引用和上下文生存期。

所有实验只在可丢弃虚拟机和测试签名环境运行。先配置内核调试与恢复快照，再加载故意有错的驱动；不要在日常主机、生产终端或含重要数据的系统测试蓝屏、过滤、进程保护或文件备份代码。

## 最小可重放骨架

```cpp
NTSTATUS Complete(PIRP irp, NTSTATUS status, ULONG_PTR information) {
  irp->IoStatus.Status = status; irp->IoStatus.Information = information;
  IoCompleteRequest(irp, IO_NO_INCREMENT); return status;
}
```

```cpp
auto stack = IoGetCurrentIrpStackLocation(irp);
auto buffer = static_cast<std::byte*>(irp->AssociatedIrp.SystemBuffer);
return Complete(irp, STATUS_SUCCESS, stack->Parameters.Read.Length);
```

```text
METHOD_BUFFERED -> SystemBuffer
METHOD_IN_DIRECT/OUT_DIRECT -> SystemBuffer + MDL
METHOD_NEITHER -> user pointers, probe/capture carefully
```

## 常见误区与故障注入

<Callout type="trap">
  **误区一：驱动加载成功就说明内核代码正确。**
  很多错误只在缓冲边界、并发回调、错误IRQL或卸载时出现。必须启用定向Verifier并验证完成、引用、池和锁序。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据                 | 通过条件     |
| ---- | -------------------------- | ------------------------ | ------------ |
| 基线 | 固定快照、sys/PDB和输入    | 状态码、IRQL、对象与日志 | 与预测一致   |
| 边界 | 空缓冲、短输出、断开客户端 | 长度、Information、引用  | 不越界不泄漏 |
| 失败 | 错IRQL、竞态、Verifier规则 | 首错栈和责任层           | 故障可定位   |
| 恢复 | 清理或快照后同输入重放     | 模块、服务、池、回调状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看用户模式输出验收第7章 I/O请求包？

<Answer>
  输出可能隐藏错误IRQL、重复完成、悬空回调、池泄漏和卸载竞态。必须同时检查NTSTATUS/Information、内核序号日志、对象引用、Verifier和恢复重放。
</Answer>

**问题 2** 如何把“第7章 I/O请求包”变成可执行证据？

<Answer>
  沿“接收IRP、读取栈位置、验证长度方法、访问系统缓冲、设置完成状态、由客户端核对结果”固定虚拟机、WDK、sys/PDB和输入，预测调用线程、IRQL、对象与状态码，只改变一个条件并保存首错；恢复后比较IRP、回调、池或过滤上下文。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  每个IRP只完成一次，IoStatus与Information准确，缓冲访问方式匹配设备标志和IOCTL
  Method，挂起路径保有资源。
  失败路径不得污染下一轮，卸载与清理明确，相同输入和事件序列能够重新到达基线。
</Answer>

</Exercises>

## 小结

- IRP：连接“接收IRP”的内核契约与证据。
- I/O栈位置：连接“读取栈位置”的内核契约与证据。
- IoCompleteRequest：连接“验证长度方法”的内核契约与证据。
- 缓冲/直接I/O：连接“访问系统缓冲”的内核契约与证据。
- Zero驱动：连接“设置完成状态”的内核契约与证据。
