## 直觉起点

<Term def="进程通知连接注册通知回调阶段的IRQL、对象、请求和恢复证据。">进程通知</Term>、<Term def="线程通知连接捕获创建退出阶段的IRQL、对象、请求和恢复证据。">线程通知</Term>、<Term def="映像加载通知连接复制稳定字段阶段的IRQL、对象、请求和恢复证据。">映像加载通知</Term>、<Term def="事件队列连接写入有界队列阶段的IRQL、对象、请求和恢复证据。">事件队列</Term>、<Term def="用户模式客户端连接客户端读取阶段的IRQL、对象、请求和恢复证据。">用户模式客户端</Term>
共同构成本页坐标。实现进程创建/退出、线程和映像加载通知，把内核事件安全排队并提供给用户模式客户端消费。

内核编程必须同时画三张图：调用图说明用户请求、系统回调或I/O如何进入驱动；对象图说明DriverObject、DeviceObject、IRP、回调Cookie、上下文和池块由谁拥有；时间图说明注册、并发回调、注销、排空和卸载的先后。少一张图，表面可用的驱动也可能在压力或卸载时蓝屏。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：驱动加载成功就说明内核代码正确。**
  很多错误只在缓冲边界、并发回调、错误IRQL或卸载时出现。必须启用定向Verifier并验证完成、引用、池和锁序。
</Callout>

<Callout type="trap">
  **误区二：把这本书改写成WDM/WDF或硬件驱动通论。**
  正式目录的主线是软件内核驱动、系统通知、小过滤器和设备过滤；PnP、MDL和WDF只能在相关机制处作对照，不能冒充原章节。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据                 | 通过条件     |
| ---- | -------------------------- | ------------------------ | ------------ |
| 基线 | 固定快照、sys/PDB和输入    | 状态码、IRQL、对象与日志 | 与预测一致   |
| 边界 | 空缓冲、短输出、断开客户端 | 长度、Information、引用  | 不越界不泄漏 |
| 失败 | 错IRQL、竞态、Verifier规则 | 首错栈和责任层           | 故障可定位   |
| 恢复 | 清理或快照后同输入重放     | 模块、服务、池、回调状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看用户模式输出验收第8章 进程和线程通知？

<Answer>
  输出可能隐藏错误IRQL、重复完成、悬空回调、池泄漏和卸载竞态。必须同时检查NTSTATUS/Information、内核序号日志、对象引用、Verifier和恢复重放。
</Answer>

**问题 2** 如何把“第8章 进程和线程通知”变成可执行证据？

<Answer>
  沿“注册通知回调、捕获创建退出、复制稳定字段、写入有界队列、客户端读取、注销并排空”固定虚拟机、WDK、sys/PDB和输入，预测调用线程、IRQL、对象与状态码，只改变一个条件并保存首错；恢复后比较IRP、回调、池或过滤上下文。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  回调路径非阻塞且有界，记录拥有所需字符串和标识副本，卸载先注销回调再排空队列。
  失败路径不得污染下一轮，卸载与清理明确，相同输入和事件序列能够重新到达基线。
</Answer>

</Exercises>
