## 直觉起点

本章的核心问题是：对象与注册表前后回调怎样限制访问、关联上下文并在卸载前可靠注销？

、、、、共同构成本页坐标。用对象操作前后回调构建进程保护驱动，再实现注册表前后通知、策略管理、客户端控制和性能约束。

内核编程必须同时画三张图：调用图说明用户请求、系统回调或I/O如何进入驱动；对象图说明DriverObject、DeviceObject、IRP、回调Cookie、上下文和池块由谁拥有；时间图说明注册、并发回调、注销、排空和卸载的先后。少一张图，表面可用的驱动也可能在压力或卸载时蓝屏。

**问题 1：实验设计**

请围绕以下问题设计一个可重现实验：对象与注册表前后回调怎样限制访问、关联上下文并在卸载前可靠注销？

<Answer>
  实验必须满足不变量：只收窄声明的访问且每个注册句柄、上下文和回调引用都反向释放。需要交付的证据包括：操作类/访问掩码矩阵、前后关联键、注册表通知轨迹与注销记录。先冻结完整build、架构、工具链、驱动包、签名、符号和输入；再注入唯一故障"把保护示例扩展为任意内核能力、忽略访问控制、注册句柄泄漏或前后回调错配"；记录首个分岔与竞争性解释；停止新请求并反向清理后以同输入重新验收不变量。无法恢复则标记失败或未知。
</Answer>

**问题 2：故障识别与避免**

如果在实验中观察到"把保护示例扩展为任意内核能力、忽略访问控制、注册句柄泄漏或前后回调错配"，如何定位根因？如何避免？

<Answer>
  定位方法：在操作类/访问掩码矩阵、前后关联键、注册表通知轨迹与注销记录中检查是否违反不变量"只收窄声明的访问且每个注册句柄、上下文和回调引用都反向释放"。具体而言，比较故障轨迹与签名参考基线的首个分岔，记录NTSTATUS、IRQL和调用链差异。避免方法：确保对象通知、进程保护、注册表前后通知、性能与用户态客户的全部约束在每条执行路径上成立；不以一次成功加载或最终蓝屏替代完整调用链证据；安全卸载或恢复快照后以同输入重放验证恢复。
</Answer>
