## 核心机制深挖

用对象操作前后回调构建进程保护驱动，再实现注册表前后通知、策略管理、客户端控制和性能约束。 本书讨论的是Windows软件内核驱动：进程、线程、映像、对象、注册表、文件系统和过滤机制，而不是硬件PnP/WDF通论。正文保留2019原版与2021中文版的技术身份；新WDK API只能作为显式迁移对照。

本页不变量是：**保护策略快照并发安全，前回调只削减允许权限，后回调不伪造结果；注册表回调尊重通知类别和递归边界。**。它必须在正常请求、零长度、无效句柄、缓冲不足、错误IRQL、并发注销和中途卸载中都成立。NTSTATUS成功只是一个观察点，不能证明Information、对象引用、池Tag、锁序和完成次数都正确。

最小实验：保护一个测试进程免受终止句柄，再监视指定注册表路径，比较允许、削权、拒绝和回调注销。 每次运行前记录Windows构建、WDK、架构、签名模式、sys/PDB哈希、Driver Verifier配置和虚拟机快照；运行后保存客户端输出、内核序号日志、WinDbg命令及资源差异。

故障实验：注入递归注册表操作、锁内回调、策略对象悬空和错误Altitude，检查死锁与漏保护。 每轮只改变一个条件并停在第一处偏离。恢复必须使用明确卸载/清理步骤或虚拟机快照，再以相同客户端输入、事件顺序和Verifier配置重放。

证据表至少包含阶段、调用线程、当前IRQL、对象/缓冲所有者、预期与实际NTSTATUS、首错、清理动作七列。涉及回调时还要记录注册Cookie、进入计数、注销时刻和排空条件；涉及IRP时记录Major/Minor、栈位置、缓冲方法、Status/Information和完成次数；涉及过滤器时记录实例、文件对象、名称引用和上下文生存期。

所有实验只在可丢弃虚拟机和测试签名环境运行。先配置内核调试与恢复快照，再加载故意有错的驱动；不要在日常主机、生产终端或含重要数据的系统测试蓝屏、过滤、进程保护或文件备份代码。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：驱动加载成功就说明内核代码正确。**
  很多错误只在缓冲边界、并发回调、错误IRQL或卸载时出现。必须启用定向Verifier并验证完成、引用、池和锁序。
</Callout>

<Callout type="trap">
  **误区二：把这本书改写成WDM/WDF或硬件驱动通论。**
  正式目录的主线是软件内核驱动、系统通知、小过滤器和设备过滤；PnP、MDL和WDF只能在相关机制处作对照，不能冒充原章节。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据                 | 通过条件     |
| ---- | -------------------------- | ------------------------ | ------------ |
| 基线 | 固定快照、sys/PDB和输入    | 状态码、IRQL、对象与日志 | 与预测一致   |
| 边界 | 空缓冲、短输出、断开客户端 | 长度、Information、引用  | 不越界不泄漏 |
| 失败 | 错IRQL、竞态、Verifier规则 | 首错栈和责任层           | 故障可定位   |
| 恢复 | 清理或快照后同输入重放     | 模块、服务、池、回调状态 | 回到基线     |

## 练习

<Exercises>

**问题 1** 为什么不能只看用户模式输出验收第9章 对象和注册表通知？

<Answer>
  输出可能隐藏错误IRQL、重复完成、悬空回调、池泄漏和卸载竞态。必须同时检查NTSTATUS/Information、内核序号日志、对象引用、Verifier和恢复重放。
</Answer>

**问题 2** 如何把“第9章 对象和注册表通知”变成可执行证据？

<Answer>
  沿“注册对象回调、管理保护集合、过滤句柄权限、注册表前后观察、客户端更新策略、注销并等待回调”固定虚拟机、WDK、sys/PDB和输入，预测调用线程、IRQL、对象与状态码，只改变一个条件并保存首错；恢复后比较IRP、回调、池或过滤上下文。
</Answer>

**问题 3** 本页最小通过条件是什么？

<Answer>
  保护策略快照并发安全，前回调只削减允许权限，后回调不伪造结果；注册表回调尊重通知类别和递归边界。
  失败路径不得污染下一轮，卸载与清理明确，相同输入和事件序列能够重新到达基线。
</Answer>

</Exercises>
