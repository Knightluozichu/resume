## 核心机制深挖

从小过滤器加载、Altitude、INF和操作回调进入删除保护、文件名、上下文、文件备份以及通信端口客户端。 本书讨论的是Windows软件内核驱动：进程、线程、映像、对象、注册表、文件系统和过滤机制，而不是硬件PnP/WDF通论。正文保留2019原版与2021中文版的技术身份；新WDK API只能作为显式迁移对照。

本页不变量是：**前后回调配对，上下文与文件对象生存期一致，名称查询引用成对释放，备份顺序不会递归过滤自身。**。它必须在正常请求、零长度、无效句柄、缓冲不足、错误IRQL、并发注销和中途卸载中都成立。NTSTATUS成功只是一个观察点，不能证明Information、对象引用、池Tag、锁序和完成次数都正确。

最小实验：逐步实现删除保护和文件备份小过滤器，保存创建、写、清理、恢复与端口通信的时序证据。 每次运行前记录Windows构建、WDK、架构、签名模式、sys/PDB哈希、Driver Verifier配置和虚拟机快照；运行后保存客户端输出、内核序号日志、WinDbg命令及资源差异。

故障实验：注入名称引用泄漏、自递归备份、上下文竞态、错误回调状态和端口断开，使用Verifier与日志验收。 每轮只改变一个条件并停在第一处偏离。恢复必须使用明确卸载/清理步骤或虚拟机快照，再以相同客户端输入、事件顺序和Verifier配置重放。

证据表至少包含阶段、调用线程、当前IRQL、对象/缓冲所有者、预期与实际NTSTATUS、首错、清理动作七列。涉及回调时还要记录注册Cookie、进入计数、注销时刻和排空条件；涉及IRP时记录Major/Minor、栈位置、缓冲方法、Status/Information和完成次数；涉及过滤器时记录实例、文件对象、名称引用和上下文生存期。

所有实验只在可丢弃虚拟机和测试签名环境运行。先配置内核调试与恢复快照，再加载故意有错的驱动；不要在日常主机、生产终端或含重要数据的系统测试蓝屏、过滤、进程保护或文件备份代码。

## 常见误区与故障注入

<Callout type="trap">
  **误区一：驱动加载成功就说明内核代码正确。**
  很多错误只在缓冲边界、并发回调、错误IRQL或卸载时出现。必须启用定向Verifier并验证完成、引用、池和锁序。
</Callout>

<Callout type="trap">
  **误区二：把这本书改写成WDM/WDF或硬件驱动通论。**
  正式目录的主线是软件内核驱动、系统通知、小过滤器和设备过滤；PnP、MDL和WDF只能在相关机制处作对照，不能冒充原章节。
</Callout>

## 四类样本与验收

| 样本 | 注入方式                   | 必查证据                 | 通过条件     |
| ---- | -------------------------- | ------------------------ | ------------ |
| 基线 | 固定快照、sys/PDB和输入    | 状态码、IRQL、对象与日志 | 与预测一致   |
| 边界 | 空缓冲、短输出、断开客户端 | 长度、Information、引用  | 不越界不泄漏 |
| 失败 | 错IRQL、竞态、Verifier规则 | 首错栈和责任层           | 故障可定位   |
| 恢复 | 清理或快照后同输入重放     | 模块、服务、池、回调状态 | 回到基线     |
