## 直觉起点

本章的核心问题是：Minifilter的高度、注册、实例、pre/post、文件名、context、I/O、通信端口与卸载怎样闭环？

内核编程必须同时画三张图：调用图说明用户请求、系统回调或I/O如何进入驱动；对象图说明DriverObject、DeviceObject、IRP、回调Cookie、上下文和池块由谁拥有；时间图说明注册、并发回调、注销、排空和卸载的先后。少一张图，表面可用的驱动也可能在压力或卸载时蓝屏。

**问题 1：实验设计**

请围绕以下问题设计一个可重现实验：Minifilter的高度、注册、实例、pre/post、文件名、context、I/O、通信端口与卸载怎样闭环？

<Answer>
  实验必须满足不变量：过滤次序合法且callback data、名称、context、端口、实例和filter引用全部归零。需要交付的证据包括：高度/加载组身份、操作回调轨迹、名称/context引用、端口消息与Filter Verifier结果。先冻结完整build、架构、工具链、驱动包、签名、符号和输入；再注入唯一故障"伪造高度、名称或context引用泄漏、pre/post返回错误、通信端口或实例未关闭"；记录首个分岔与竞争性解释；停止新请求并反向清理后以同输入重新验收不变量。无法恢复则标记失败或未知。
</Answer>

**问题 2：故障识别与避免**

如果在实验中观察到"伪造高度、名称或context引用泄漏、pre/post返回错误、通信端口或实例未关闭"，如何定位根因？如何避免？

<Answer>
  定位方法：在高度/加载组身份、操作回调轨迹、名称/context引用、端口消息与Filter Verifier结果中检查是否违反不变量"过滤次序合法且callback data、名称、context、端口、实例和filter引用全部归零"。具体而言，比较故障轨迹与签名参考基线的首个分岔，记录NTSTATUS、IRQL和调用链差异。避免方法：确保Minifilter装卸、初始化、高度、I/O、删除保护、文件名、context、备份、通信与调试的全部约束在每条执行路径上成立；不以一次成功加载或最终蓝屏替代完整调用链证据；安全卸载或恢复快照后以同输入重放验证恢复。
</Answer>
