## 为什么从这个问题开始

第11章 其他主题围绕“签名、Verifier、Native API、过滤器、设备监视与内核库怎样迁移到受支持且最小权限的当前实践？”建立贯穿任务。先冻结出版轨、目标build、驱动包和对象身份，再以小输入观察状态与调用链，最后用唯一故障和同输入恢复验收；只有守住“只有必要内核功能、受支持模型、最小权限、隔离验证、恢复与发布签名全部成立”并交付必要性决策、驱动包/签名/HVCI验证、Verifier设置与reset、过滤设备生命周期，目录术语、DDI名字或一次成功加载才可能升级为机制证据。

## 来源合同、版本差异与安全边界

第11章 其他主题登记的19项差异是：第1章：Thread Stacks；第2章：Exercises；第5章：Tutorial: User mode debugging basics；第6章：Using DPC with a Timer；第6章：Critical Regions and Guarded Regions；第6章：The Spin Lock；第7章：IRP Flow；第7章：Viewing IRP Information；第7章：Completing a Request；第8章：The User Mode Client；第8章：Exercises；第9章：Desktop Objects；第9章：Exercises；第10章：Pipes and Mailslots；第10章：Direct Access Volume (DAX or DAS)；第10章：Context Types；第10章：Managing Contexts；第10章：Exercises；第11章：Example Driver Verifier Sessions。它们可能来自译本底稿、修订时点或目录裁剪；没有出版社正文证据就保持“来源差异”，不补成中文版坐标，也不把作者页面的后续更新倒写给译者。

第11章 其他主题把三条轨道分开：中文版/作者一版解释成书范围；[作者二版](https://leanpub.com/windowskernelprogrammingsecondedition/)及[MIT示例仓库](https://github.com/zodiacon/windowskernelprogrammingbook2e)只做迁移参考；当前平台轨以Microsoft Learn和目标系统公开DDI核对。第11章 其他主题的实验必须记录完整Windows build、架构、SDK、WDK、Visual Studio、驱动模型、签名、VBS/HVCI、驱动包摘要和符号，不能只写Windows 11或latest。

第11章 其他主题涉及内核代码、驱动部署、回调、用户缓冲区、Minifilter、Verifier和故障调试。第11章 其他主题页面只给实验协议；执行仅允许在可丢弃VM或专用测试机，并预备快照、备份、宿主内核调试、崩溃转储、超时、恢复启动和Verifier reset。生产设备、日常主机和无法承受蓝屏或数据损坏的对象不在实验范围内。
