## 直觉引入

把全书知识想象成一场「接力赛」。发令枪响是驱动加载（DriverEntry，第 2 章），第一棒选手（驱动基础）拿到工作证注册能处理哪些任务。第二棒（设备枚举）接到 PnP 管理器的通知，把设备挂上设备栈。第三棒（I/O 请求）接过用户程序的 ReadFile，封装成 IRP 在设备栈中传递。第四棒（内存分配）为数据找仓库，按 IRQL 选非分页池或分页池。第五棒（MDL 直接 I/O）用零拷贝通道搬运大块数据。第六棒（中断处理）在硬件中断时先灭火（ISR）再善后（DPC）。第七棒（同步保护）用自旋锁保护共享数据。第八棒（电源管理）在系统休眠时保存上下文断电。最后一棒（卸载）在设备移除时释放全部资源。九棒选手在一条生命周期线上完成接力——这就是全书主线。

## 九大知识点串联

<Term def="一个驱动从加载到卸载的全生命周期是贯穿全书的主线——九大内核机制在一次生命周期中全部参与，从 DriverEntry 到 DriverUnload 串联驱动基础、IRP、内存、MDL、中断、同步、PnP、电源和框架选型。">一个驱动的一生</Term>是复习全书的核心方法。驱动加载（第 2 章）注册回调 → 设备枚举（第 2/8 章）创建设备加入设备栈 → I/O 请求（第 3 章）创建 IRP 派发完成 → 内存分配（第 4 章）按 IRQL 选池 → MDL 直接 I/O（第 5 章）零拷贝映射 → 中断处理（第 6 章）ISR 灭火 DPC 善后 → 同步保护（第 7 章）自旋锁保护共享数据 → 电源管理（第 8 章）D0/D3 状态转换 → 卸载（第 9-10 章）释放全部资源。

```text
// 一个驱动从加载到卸载——全书知识点串联
// ① 驱动加载（第 2 章）
DriverEntry → WdfDriverCreate / 注册 EvtDeviceAdd

// ② 设备枚举（第 2/8 章）
EvtDeviceAdd → WdfDeviceCreate → 加入设备栈
IRP_MN_START_DEVICE → EvtDevicePrepareHardware
  → IoConnectInterruptEx 连接 ISR（第 6 章）
  → MmMapIoSpace 映射寄存器

// ③ I/O 请求处理（第 3 章）
用户 ReadFile → I/O 管理器创建 IRP
→ IoCallDriver 沿设备栈派发
→ DispatchRead / EvtIoRead 处理
→ IoCompleteRequest 完成

// ④ 内存分配（第 4 章）
ExAllocatePool2(POOL_FLAG_NON_PAGED, Size, Tag)
// DPC/ISR 中必须用非分页池（IRQL 约束）

// ⑤ MDL 直接 I/O（第 5 章）
PVOID kAddr = MmGetSystemAddressForMdlSafe(Irp->MdlAddress, ...);
// 零拷贝访问用户缓冲区

// ⑥ 中断处理（第 6 章）
硬件中断 → ISR(DIRQL): ACK + 禁中断 + IoRequestDpc
→ DPC(DISPATCH_LEVEL): 处理数据 + 完成IRP + 启中断

// ⑦ 同步保护（第 7 章）
KeAcquireSpinLock → 保护共享链表 → KeReleaseSpinLock
// DPC 与用户读取并发访问时必须同步

// ⑧ 电源管理（第 8 章）
IRP_MN_SET_POWER(D3) → 保存上下文断电
IRP_MN_SET_POWER(D0) → 恢复上下文上电

// ⑨ 卸载（第 9-10 章）
IRP_MN_REMOVE_DEVICE → EvtDeviceReleaseHardware
→ WDF 自动删除对象树 / DriverUnload 释放全局资源
```

## IRQL 贯穿全书

IRQL 是内核编程的「红绿灯」，统一约束三大主题。**内存分配**：IRQL >= DISPATCH_LEVEL 只能用非分页池（分页池缺页蓝屏），DPC/ISR 数据必须在非分页池。**同步原语**：自旋锁提升至 DISPATCH_LEVEL 自旋（适合高 IRQL 极短临界区），FastMutex 在 APC_LEVEL 阻塞（适合 PASSIVE_LEVEL 较长临界区），`KeWaitForSingleObject` 非零超时需 PASSIVE_LEVEL。**中断处理**：ISR 在 DIRQL（不能获取锁/分配内存/调用大多数 API），DPC 在 DISPATCH_LEVEL（可获取自旋锁但不能阻塞）。

## 常见误区

<Callout type="trap">
**误区：学完各章节就等于掌握了内核编程。** 各章节是「知识点」，但内核编程是「系统工程」——九大机制在一次 I/O 请求中协同工作。一个 `IRP_MJ_READ` 从用户态到硬件的完整路径涉及：I/O 管理器创建 IRP → MDL 锁定物理页 → 沿设备栈派发 → DMA 散列-聚集 → ISR/DPC 中断处理 → 自旋锁同步 → IoCompleteRequest 完成。任何一环出错都蓝屏。五类常见蓝屏：①IRQL 违规（高 IRQL 访问分页内存/调用阻塞 API）；②内存泄漏/双重释放；③IRP 完成错误（完成未拥有的 IRP/双重完成/取消竞态）；④竞态死锁；⑤PnP/电源状态错误。系统性预防：Driver Verifier 全开 + SDV 静态分析 + 代码 Review + 压力测试。
</Callout>

<Exercises>
**问题 1**：用一个驱动从加载到卸载串联全书九大知识点。

<Answer>
①驱动加载（第2章）DriverEntry 注册回调；②设备枚举（第2/8章）AddDevice 创建设备加入设备栈，START_DEVICE 分配资源；③I/O请求（第3章）ReadFile 创建 IRP，IoCallDriver 派发，IoCompleteRequest 完成；④内存分配（第4章）ExAllocatePool2 分配非分页池；⑤MDL直接I/O（第5章）MmGetSystemAddressForMdlSafe 零拷贝；⑥中断处理（第6章）ISR 灭火 + DPC 善后；⑦同步保护（第7章）KeAcquireSpinLock 保护共享数据；⑧电源管理（第8章）SET_POWER 切换 D0/D3；⑨卸载（第9-10章）REMOVE_DEVICE 释放全部资源。九大机制在一次生命周期中全部参与。
</Answer>

**问题 2**：驱动开发中最容易导致蓝屏的五类错误是什么？

<Answer>
①IRQL 违规——高 IRQL 访问分页内存/调用阻塞 API/持自旋锁分页。预防：Driver Verifier 开 Force IRQL Checking。②内存泄漏/双重释放——分配未释放/释放后使用/Tag 不匹配。预防：Pool Tracking 追踪，WDF 自动管理。③IRP 完成错误——完成未拥有 IRP/双重完成/PENDING 未标记/取消竞态。预防：遵循 IRP 所有权规则。④竞态死锁——锁序不一致/持锁阻塞。预防：统一锁序，Deadlock Detection。⑤PnP/电源状态错误——Stopped 状态处理 I/O/START_DEVICE 前访问硬件。预防：严格状态机处理。系统性预防：Driver Verifier 全开 + SDV + Review + 压力测试。
</Answer>
