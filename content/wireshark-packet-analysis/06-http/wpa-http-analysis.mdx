## HTTP 报文结构

### 请求报文

```text
GET /api/users?id=1 HTTP/1.1        ← 请求行：方法 URI 版本
Host: api.example.com                ← 请求头
User-Agent: Mozilla/5.0
Accept: application/json
Authorization: Bearer abc123
                                     ← 空行（CRLF）
[请求体 - GET 通常为空]              ← 请求体
```

### 响应报文

```text
HTTP/1.1 200 OK                      ← 状态行：版本 状态码 短语
Content-Type: application/json       ← 响应头
Content-Length: 127
Cache-Control: max-age=3600
Set-Cookie: session=xyz
                                     ← 空行
{"id":1,"name":"test"}               ← 响应体
```

## Wireshark HTTP 分析流程

### 1. 过滤 HTTP 请求

```text
http.request                          ← 所有 HTTP 请求
http.request.method == "POST"         ← POST 请求
http.request.method == "GET"          ← GET 请求
http.host contains "google"           ← Host 含 google
http.request.uri contains "login"     ← URI 含 login
```

### 2. 过滤 HTTP 响应

```text
http.response                         ← 所有 HTTP 响应
http.response.code == 200             ← 200 OK
http.response.code == 404             ← 404 Not Found
http.response.code >= 400             ← 4xx/5xx 错误
http.content_type contains "json"     ← JSON 格式响应
http.content_type contains "html"     ← HTML 格式响应
```

### 3. 跟踪 HTTP 流

```text
Analyze → Follow → HTTP Stream
  → 显示完整的请求+响应对话
  → 客户端发送内容为红色，服务器响应为蓝色
  → 可看到完整的 HTTP 头和体内容
  → 适合分析完整的一次 HTTP 交互
```

### 4. 时间分析

```text
http.time > 2                         ← 响应时间超过 2 秒的慢请求
frame.time_delta > 1                  ← 相邻包间隔超过 1 秒
```

<Callout type="info" title="HTTP vs HTTPS 在 Wireshark 中的区别">

HTTP（端口 80）是明文协议，Wireshark 直接解码出请求和响应内容。HTTPS（端口 443）= HTTP over TLS，Wireshark 默认只能看到 TLS 握手和加密数据（显示为「Application Data」），需要导入 TLS 密钥才能解密。

</Callout>

## HTTPS 解密

### SSLKEYLOGFILE 方法

```text
步骤 1：设置环境变量
  export SSLKEYLOGFILE=~/.sslkeylog.log
  （Windows: 系统环境变量 SSLKEYLOGFILE）

步骤 2：浏览器自动写入密钥
  Chrome / Firefox 支持，每次 TLS 连接的密钥写入该文件

步骤 3：Wireshark 导入密钥
  Preferences → Protocols → TLS → (Pre)-Master-Secret log filename
  → 选择 ~/.sslkeylog.log

步骤 4：解密后查看
  → TLS 包详情展开后可看到解密的 HTTP 明文
  → 也可用 http 过滤器直接过滤
```

### TLS 握手分析

```text
tls.handshake.type == 1     ← Client Hello（客户端发起）
tls.handshake.type == 2     ← Server Hello（服务器回应）
tls.handshake.type == 11    ← Certificate（服务器证书）
tls.handshake.type == 16    ← New Session Ticket
```

## HTTP 性能诊断

| 指标 | 过滤器 | 含义 |
|------|--------|------|
| 响应时间 | `http.time > 2` | 请求到响应的时间差 |
| TCP 握手时间 | SYN→SYN+ACK 间隔 | 网络延迟 |
| TLS 握手时间 | Client Hello→Finished | TLS 协商开销 |
| 重传频率 | `tcp.analysis.retransmission` | 网络稳定性 |
| 请求大小 | Content-Length | 上行数据量 |
| 响应大小 | Content-Length | 下行数据量 |

```text
Statistics → HTTP → Packet Counter：按方法/状态码统计
Statistics → HTTP → Request/Response Sequences：请求时序图
```

<Glossary>

<GlossaryItem term="HTTP 流跟踪（Follow HTTP Stream）">
Wireshark 的 Follow HTTP Stream 功能（Analyze → Follow → HTTP Stream）将一个完整 HTTP 对话的请求和响应按时间顺序拼接显示。客户端发送的数据标为红色，服务器响应标为蓝色。可以查看完整的 HTTP 请求头、请求体、响应头和响应体——不受包分割影响。适合分析完整的 HTTP 交互过程。也可 Follow TCP Stream 查看更底层的完整 TCP 流内容。导出时可保存为原始数据文件。
</GlossaryItem>

<GlossaryItem term="HTTPS 解密（TLS Decryption）">
HTTPS = HTTP over TLS/SSL，流量在传输层加密，Wireshark 默认只能看到 TLS 握手和加密的 Application Data。解密方法：利用浏览器的 SSLKEYLOGFILE 功能——设置环境变量 SSLKEYLOGFILE 指向一个文件，Chrome/Firefox 会把每个 TLS 连接的密钥写入该文件。然后在 Wireshark Preferences → Protocols → TLS 中设置 (Pre)-Master-Secret log filename 指向该文件。Wireshark 用密钥解密 TLS 流量后，可看到 HTTP 明文。注意：只能解密有密钥文件的会话，无法解密他人的 HTTPS 流量。
</GlossaryItem>

<GlossaryItem term="http.time 字段">
http.time 是 Wireshark 计算的 HTTP 请求到响应的时间差——从 HTTP 请求包到对应 HTTP 响应包的间隔时间。是诊断 HTTP 性能问题的核心指标。`http.time > 2` 过滤出响应时间超过 2 秒的慢请求。http.time 包括：网络延迟（TCP/TLS 已建立时）+ 服务器处理时间 + 响应传输时间。如果 TCP 握手也慢，需同时检查 SYN→SYN+ACK 间隔（网络延迟）和 TLS 握手时间。
</GlossaryItem>

<GlossaryItem term="TLS 握手（TLS Handshake）">
TLS 握手是建立加密通信的过程：①Client Hello——客户端发送支持的 TLS 版本/加密套件/随机数 ②Server Hello——服务器选择 TLS 版本/加密套件/随机数 ③Certificate——服务器发送证书 ④Key Exchange——双方交换密钥材料 ⑤Finished——握手完成，后续用对称加密通信。Wireshark 中用 `tls.handshake.type` 过滤各阶段。TLS 1.2 需 2-RTT 握手，TLS 1.3 优化到 1-RTT 甚至 0-RTT。TLS 握手时间是 HTTPS 比 HTTP 慢的主要原因之一。
</GlossaryItem>

</Glossary>

<Exercises>

**问题 1：** 如何在 Wireshark 中跟踪完整的 HTTP 对话？如何过滤特定方法的请求和特定状态码的响应？

<Answer>

跟踪 HTTP 对话：Analyze → Follow → HTTP Stream，显示完整的请求+响应文本，客户端发送为红色，服务器响应为蓝色。过滤请求方法：`http.request.method == "POST"` 只看 POST，`http.request.method == "GET"` 只看 GET。过滤状态码：`http.response.code == 404` 只看 404，`http.response.code >= 400` 看所有 4xx/5xx 错误。其他常用：`http.request`（所有请求）、`http.response`（所有响应）、`http.host contains "google"`（特定 Host）、`http.time > 2`（慢请求）。

</Answer>

**问题 2：** HTTPS 流量在 Wireshark 中默认显示为什么？如何解密 HTTPS 流量查看 HTTP 明文？

<Answer>

HTTPS 在 Wireshark 中默认显示为 TLS 握手和加密的 Application Data——无法直接看到 HTTP 请求和响应的明文内容。解密方法：①设置环境变量 SSLKEYLOGFILE 指向一个文件路径（如 `export SSLKEYLOGFILE=~/.sslkeylog.log`）②Chrome/Firefox 浏览器会自动把每个 TLS 连接的密钥写入该文件 ③在 Wireshark → Preferences → Protocols → TLS 中设置 (Pre)-Master-Secret log filename 指向该密钥文件 ④Wireshark 用密钥解密后可看到 TLS 内的 HTTP 明文。注意只能解密有密钥文件的会话。

</Answer>
