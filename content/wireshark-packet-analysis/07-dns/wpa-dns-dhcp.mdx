## DNS 域名解析

### DNS 记录类型

| 类型 | 全称 | 作用 |
|------|------|------|
| A | Address | 域名 → IPv4 地址 |
| AAAA | IPv6 Address | 域名 → IPv6 地址 |
| CNAME | Canonical Name | 别名记录（域名→域名） |
| MX | Mail Exchange | 邮件服务器 |
| TXT | Text | 文本记录（SPF/验证） |
| NS | Name Server | 名称服务器 |
| PTR | Pointer | 反向解析（IP→域名） |

### DNS 查询流程

```text
Client                    Local DNS               Root/TLD/Auth
  |                          |                         |
  | -- Query: example.com -> |                         |
  |    （递归查询）           |                         |
  |                          | -- 迭代查询各级服务器 -> |
  |                          | <- 返回各级 NS/IP ------ |
  | <- Response: 93.x.x.x -- |                         |
  |                          |                         |
```

<Callout type="info" title="递归查询 vs 迭代查询">

**递归查询**：客户端 → Local DNS 服务器，客户端只发一次请求，Local DNS 负责返回最终结果。**迭代查询**：Local DNS → Root → TLD → 权威服务器，每级只返回下一步该问谁，Local DNS 逐级追问。客户端只用递归查询，DNS 服务器之间用迭代查询。

</Callout>

### Wireshark DNS 过滤器

```text
dns                                  ← 所有 DNS 流量
dns.qry.name == "example.com"        ← 特定域名查询
dns.qry.name contains "google"       ← 域名含 google
dns.flags.response == 0              ← 只看查询包
dns.flags.response == 1              ← 只看响应包
dns.qry.type == 1                    ← A 记录查询
dns.qry.type == 28                   ← AAAA 记录查询
dns.flags.rcode != 0                 ← DNS 错误响应（如 NXDOMAIN）
```

## DHCP 动态地址分配

### DORA 四步流程

DHCP 使用 UDP 协议，客户端端口 68，服务器端口 67：

```text
D - Discover（广播发现）
  Client → 255.255.255.255:67
  "谁是 DHCP 服务器？"（源 IP 0.0.0.0）

O - Offer（提供租约）
  Server → Client
  "我可以给你 10.0.0.50"（含掩码/网关/DNS/租期）

R - Request（请求租约）
  Client → 255.255.255.255:67
  "我要 10.0.0.50"（通知所有服务器）

A - Acknowledge（确认租约）
  Server → Client
  "确认，租期 24h"
```

### Wireshark DHCP 过滤器

```text
bootp                                ← 所有 DHCP 流量（基于 BOOTP）
bootp.option.type == 53              ← DHCP 消息类型选项
bootp.type == 1                      ← Discover / Request（客户端→服务器）
bootp.type == 2                      ← Offer / ACK（服务器→客户端）
bootp.option.value == 01             ← Discover
bootp.option.value == 02             ← Offer
bootp.option.value == 03             ← Request
bootp.option.value == 05             ← ACK
```

<Callout type="warning" title="Wireshark 中 DHCP 的协议名是 bootp">

DHCP 基于 BOOTP 协议扩展，Wireshark 中过滤 DHCP 流量用 `bootp` 而非 `dhcp`。DHCP 消息类型（Discover/Offer/Request/ACK）通过 Option 53 区分。

</Callout>

## 协议异常检测

### DNS 异常

| 异常 | 特征 | 检测方法 |
|------|------|---------|
| DNS 劫持 | 响应 IP 与预期不符 | 检查响应来源和 IP |
| DNS 隧道 | 超长查询名、高频 TXT | `dns.txt && frame.len > 200` |
| NXDOMAIN 泛滥 | 大量域名不存在响应 | `dns.flags.rcode == 3` |
| DNS 缓存中毒 | 响应 TTL 异常大 | 检查 TTL 值 |

### DHCP 异常

| 异常 | 特征 | 检测方法 |
|------|------|---------|
| DHCP 饥饿 | 大量 Discover 不同 MAC | `bootp.type == 1` 统计源 MAC |
| DHCP 欺骗 | 非授权服务器发 Offer | 检查 Offer 包源 IP |

```text
DNS 隧道检测：
  - 超长 DNS 查询名（编码数据藏在子域名中）
  - 高频 DNS 查询到同一域名
  - 大量 TXT 记录查询
  - 查询域名看起来像随机字符串
  过滤器：dns.txt && frame.len > 200

DHCP 饥饿检测：
  - 短时间内大量 Discover 来自不同 MAC
  - 这些 MAC 在网络中无其他正常通信
  过滤器：bootp.option.value == 01
```

<Glossary>

<GlossaryItem term="DNS 递归查询与迭代查询">
DNS 递归查询：客户端向 Local DNS 服务器发送查询，Local DNS 负责完成全部解析过程并返回最终结果给客户端。客户端只需发送一次请求。DNS 迭代查询：Local DNS 向根服务器查询，根服务器返回 TLD 服务器地址（而非最终答案），Local DNS 再向 TLD 查询，TLD 返回权威服务器地址，Local DNS 向权威服务器查询获得最终 IP。每级服务器只返回「下一步该问谁」，Local DNS 逐级追问。客户端只用递归查询，DNS 服务器之间用迭代查询。
</GlossaryItem>

<GlossaryItem term="DHCP DORA 流程">
DHCP 动态分配 IP 的四步流程：①Discover——客户端广播发现 DHCP 服务器（源 IP 0.0.0.0，目的 255.255.255.255）②Offer——DHCP 服务器回应可用的 IP 地址及配置（掩码/网关/DNS/租期）③Request——客户端广播请求选定某个 Offer（同时通知未选中的服务器回收 IP）④Acknowledge——服务器确认租约。全部使用 UDP（客户端 68，服务器 67）。租约到期前客户端需续约（Request → ACK），否则 IP 被回收。
</GlossaryItem>

<GlossaryItem term="DNS 隧道（DNS Tunneling）">
DNS 隧道是利用 DNS 协议（端口 53，通常不被防火墙拦截）传输非 DNS 数据的隐蔽通信技术。原理：将数据编码到 DNS 查询的子域名中（如 base32 编码的数据.example.com），通过 TXT 记录返回响应数据。Wireshark 检测特征：①超长 DNS 查询名（正常域名通常不超过 30 字符）②高频 DNS 查询到同一域名 ③大量 TXT 记录查询且记录长度异常 ④查询域名看起来像随机字符串。常用于恶意软件 C2 通信和数据窃取。过滤器：`dns.txt && frame.len > 200`。
</GlossaryItem>

<GlossaryItem term="DHCP 欺骗（DHCP Spoofing）">
DHCP 欺骗是攻击者部署非法 DHCP 服务器，抢先回复客户端的 Discover 请求，分配恶意的网关 IP 和 DNS 地址，从而劫持受害者的网络流量。攻击者可借此实施中间人攻击、DNS 劫持等。Wireshark 检测：查看 Offer 包（bootp.type == 2）的源 IP，确认是否为网络中授权的 DHCP 服务器；非授权 IP 发送 DHCP Offer 即为欺骗。防御：在交换机上配置 DHCP Snooping，只允许信任端口发送 DHCP 响应。
</GlossaryItem>

</Glossary>

**问题 1：** DNS 的递归查询和迭代查询有什么区别？常见的 DNS 记录类型有哪些？

<Answer>

递归查询：客户端 → Local DNS 服务器，客户端只发一次请求，Local DNS 负责返回最终结果（代为完成全部解析）。迭代查询：Local DNS → Root → TLD → 权威服务器，每级只返回下一步该问谁，Local DNS 逐级追问。客户端只用递归查询，DNS 服务器之间用迭代查询。常见记录类型：A（IPv4 地址）、AAAA（IPv6 地址）、CNAME（别名）、MX（邮件交换）、TXT（文本）、NS（名称服务器）、PTR（反向解析 IP→域名）。

</Answer>

**问题 2：** DHCP 的 DORA 四步流程是什么？DHCP 饥饿攻击在 Wireshark 中有什么特征？

<Answer>

DORA 流程：①Discover——客户端广播「谁是 DHCP 服务器？」（源 IP 0.0.0.0，目的 255.255.255.255，UDP 67/68）②Offer——DHCP 服务器回应「我可以给你 10.0.0.50」含掩码/网关/DNS/租期 ③Request——客户端广播「我要 10.0.0.50」通知所有服务器 ④Acknowledge——服务器确认「租期 24h」。DHCP 饥饿攻击特征：短时间内大量 Discover 请求来自不同 MAC 地址（伪造 MAC），目的是耗尽 IP 地址池。Wireshark 检测：用 `bootp.option.value == 01` 过滤 Discover 包，统计源 MAC 数量异常多，且这些 MAC 在网络中无其他正常通信。

</Answer>
