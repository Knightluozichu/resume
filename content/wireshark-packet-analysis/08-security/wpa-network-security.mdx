## 端口扫描检测

### SYN 扫描特征

```text
特征：单个源 IP 短时间内向同一目标的多个不同端口发 SYN
  开放端口 → 回 SYN+ACK
  关闭端口 → 回 RST

检测过滤器：
  tcp.flags.syn==1 && tcp.flags.ack==0

区分扫描 vs 正常：
  扫描 = 一个源 IP → 多个目标端口（一对多端口）
  正常 = 一个源 IP → 少数固定端口（一对一）
```

### 全连接扫描

```text
完成三次握手后立即 FIN，被服务器日志记录
  → 比半开 SYN 扫描更隐蔽但更容易被发现
  → Wireshark 中表现为大量短生命周期的 TCP 连接
```

## DDoS 洪泛检测

### SYN Flood

```text
特征：大量源 IP（通常伪造）向同一目标端口发海量 SYN
  从不完成三次握手（无 ACK）
  目标半连接队列被耗尽，无法接受新连接

检测：tcp.flags.syn==1 && tcp.flags.ack==0
  → 统计目标 IP 的 SYN 速率
  → 正常连接 SYN:ACK ≈ 1:1，Flood 时 SYN 远多于 ACK
```

### UDP Flood

```text
特征：大量 UDP 包到随机端口，触发 ICMP 不可达
  → 目标忙于处理 ICMP 响应而瘫痪

检测：udp && icmp.type == 3
```

### HTTP Flood

```text
特征：高频 HTTP 请求耗尽 Web 服务器连接池
  → 可能是 GET Flood（大量 GET 请求）或 POST Flood
  → 通常使用僵尸网络，源 IP 分散

检测：http.request 统计频率
  → Statistics → HTTP → Packet Counter
```

## 入侵行为检测

### 暴力破解

```text
SSH 暴力破解：
  短时间内大量 SSH 连接尝试
  伴随大量 RST（登录失败后被服务器断开）
  过滤器：ssh && tcp.flags.reset==1

FTP 暴力破解：
  大量 530 Login incorrect 响应
  过滤器：ftp.response.code == 530
```

### SQL 注入

```text
特征：HTTP 请求 URI 或表单中含注入字符串
  ' OR 1=1 --
  UNION SELECT
  xp_cmdshell

检测过滤器：
  http.request.uri contains "UNION"
  http.request.uri contains "SELECT"
  http.request.uri contains "'"
  http.request.uri matches "(?i)union.*select"
```

## 恶意软件通信

### C2（命令与控制）回连

```text
典型特征：
  1. 信标行为——定期向固定 IP/域名发心跳包（如每 60 秒）
  2. DNS 信标——定期查询固定域名
  3. 非常规端口——使用 4444/1337 等非标准端口
  4. 加密流量——C2 通信通常加密（TLS/Application Data）

检测方法：
  Statistics → Endpoints：找高频通信的陌生 IP
  Statistics → IO Graphs：查看流量是否有周期性脉冲
  dns 过滤器：查看 DNS 查询模式
```

### DNS 隧道

```text
特征：
  - 超长 DNS 查询名（编码数据藏在子域名中）
  - 高频 DNS 查询到同一域名
  - 大量 TXT 记录查询
  - 查询域名看起来像随机字符串

检测过滤器：
  dns.txt && frame.len > 200
  dns.qry.name matches "^[a-zA-Z0-9]{30,}"
```

## 统计分析方法

| 工具 | 作用 | 异常发现 |
|------|------|---------|
| Endpoints | 按 IP 统计发包量 | 异常高发包=可疑 |
| Conversations | 端到端会话统计 | 异常通信对 |
| IO Graphs | 流量趋势图 | 突增/突降=异常事件 |
| Protocol Hierarchy | 协议分布 | 非预期协议出现 |

## 常见告警规则

```text
同一源 IP 连接 100+ 端口         → 端口扫描
1 秒内 SYN 包 > 1000             → SYN Flood
DNS 查询频率 > 50/秒             → DNS 异常
非标准端口外联通信                → 可疑 C2
HTTP 4xx/5xx 激增                → 暴力破解或扫描
```

## 异常处置流程

```text
1. 确认范围：用过滤器定位异常源/目的 IP、时间窗口、协议类型
2. 提取特征：记录 IP/端口/包大小/频率模式，生成 IoC 指标
3. 阻断隔离：防火墙封禁 IP、ACL 限制端口、关闭非授权服务
4. 报告归档：导出 pcap + 分析报告，保存证据链供后续取证
```

<Glossary>

<GlossaryItem term="SYN 扫描（SYN Scan）">
SYN 扫描（半开扫描）是端口扫描技术：扫描者向目标端口发 SYN 包，开放端口回 SYN+ACK（扫描者回 RST 不完成连接），关闭端口回 RST。优势是不完成三次握手，不会在应用层日志留痕。Wireshark 检测：单源 IP 短时间内向多端口发 SYN（`tcp.flags.syn==1 && tcp.flags.ack==0`），每端口通常只发一个 SYN。区分扫描与正常连接：扫描是「一对多端口」，正常是「一对少端口」。Statistics → Endpoints 查看某 IP 的连接端口分布。
</GlossaryItem>

<GlossaryItem term="SYN Flood（SYN 洪泛）">
SYN Flood 是 DDoS 攻击：攻击者用伪造源 IP 向目标大量发 SYN 包，但不完成三次握手（不回 ACK），目标的半连接队列（SYN 队列）被占满，无法接受新的合法连接。Wireshark 特征：短时间内海量 SYN 包（`tcp.flags.syn==1 && tcp.flags.ack==0`）指向同一目标端口，源 IP 分散（伪造），SYN:ACK 比例严重失衡（正常≈1:1，攻击时 SYN 远多）。防御：SYN Cookie、SYN 代理、限速。与 SYN 扫描的区别：扫描是一对多端口（探测），Flood 是多对一端口（瘫痪）。
</GlossaryItem>

<GlossaryItem term="C2 通信（Command and Control）">
C2（命令与控制）是恶意软件与攻击者控制服务器之间的通信。典型特征：①信标行为——受害主机定期向固定 IP/域名发送心跳包，间隔规律（如每 60 秒）②非常规端口——使用 4444/1337 等非标准端口 ③加密通信——通常 TLS 加密，Wireshark 中显示为 Application Data ④流量模式异常——正常主机不会持续与陌生 IP 通信。检测方法：Statistics → Endpoints 找高频陌生 IP；IO Graphs 查看周期性脉冲流量；DNS 查询模式分析。常配合 DNS 隧道或域名生成算法（DGA）隐藏 C2 服务器地址。
</GlossaryItem>

<GlossaryItem term="IoC（Indicator of Compromise）">
IoC（入侵指标）是标识安全威胁的特征数据，包括：恶意 IP 地址、恶意域名、文件哈希、URL、注册表键值、互斥体名等。在 Wireshark 中提取 IoC：记录攻击源 IP、目标端口、通信频率、包大小模式、DNS 查询域名等。IoC 用于：①威胁情报共享 ②防火墙/IPS 规则配置 ③后续事件取证 ④威胁狩猎（在历史流量中搜索同类攻击）。处置流程：确认范围 → 提取 IoC → 阻断隔离 → 报告归档。
</GlossaryItem>

</Glossary>

**问题 1：** SYN 端口扫描和 SYN Flood DDoS 在 Wireshark 中的特征分别是什么？如何区分？

<Answer>

SYN 端口扫描特征：单个源 IP 短时间内向同一目标 IP 的多个不同端口发送 SYN 包，开放端口回 SYN+ACK，关闭端口回 RST，每端口通常只发一个 SYN。过滤器 `tcp.flags.syn==1 && tcp.flags.ack==0`。SYN Flood 特征：大量源 IP（伪造）向同一目标端口（如 80/443）发海量 SYN，从不完成三次握手，半连接队列耗尽。区分：扫描是「一个源IP→多个目标端口」目的在于探测；Flood 是「多个源IP→一个目标端口」目的在于瘫痪服务。分析时查看源 IP 数量和目标端口分布——扫描源 IP 少端口多，Flood 源 IP 多端口少。

</Answer>

**问题 2：** 恶意软件 C2 通信在 Wireshark 中有哪些典型特征？如何检测 DNS 隧道？

<Answer>

C2 通信典型特征：①信标行为——受害主机定期（如每 60 秒）向固定 IP/域名发心跳包，间隔规律 ②DNS 信标——定期查询固定域名 ③非常规端口——使用 4444/1337 等非标准端口 ④加密流量——通常 TLS 加密显示为 Application Data ⑤流量模式异常——正常主机不会持续与陌生 IP 通信。检测方法：Statistics → Endpoints 找高频陌生 IP；IO Graphs 查看周期性脉冲流量。DNS 隧道检测：①超长 DNS 查询名（编码数据藏在子域名中，正常域名通常不超 30 字符）②高频 DNS 查询到同一域名 ③大量 TXT 记录查询 ④查询域名像随机字符串。过滤器：`dns.txt && frame.len > 200`。

</Answer>
