## 常见误区与故障注入

<Callout type="trap" title="陷阱：目录标题数量足够就等于完成了学习地图">
  目录条目只能证明覆盖范围，不能证明作用域、调用点、任务顺序或版本边界已经解释。
  修法是为每个关键节点保留 evidence trace，并用正常与边界样本重放首个偏离点。
</Callout>

<Callout type="trap" title="陷阱：现代运行时行为可以直接改写一版历史目录">
  当前 JavaScript 能力与一版作者目录属于不同时间边界，混写会让迁移建议冒充原书事实。
  修法是用 version ledger 分栏记录历史快照、现代差异和适用条件。
</Callout>

故障注入的目标不是制造分数，而是让绑定、版本、队列和清理状态出现可观察的 first divergence；恢复样本必须使用相同输入重放，并确认 learning sign-off 前不存在 stale work。

| 样本 | 注入方式                           | 必查证据               | 通过条件                 |

| 正常 | 规范输入与单次执行                 | 绑定、值、调用点、队列 | 六阶段按预期完成         |

| 恢复 | 修复后重放完全相同输入             | 清理后的状态与任务数   | 无旧绑定、旧任务和旧资源 |

## 版本与原书边界

站内示例优先使用今天可运行且语义稳定的写法，但目录清单、章节归属和历史判断仍以作者一版仓库为准。对已经撤回、替代或标准化后发生变化的能力，本页要求同时写出原书快照和当前状态。

2. **问题 2：失败样本发现旧绑定后，直接切换到恢复样本。** 说明重放前必须检查什么。
