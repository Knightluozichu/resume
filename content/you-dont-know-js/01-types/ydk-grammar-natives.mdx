## 直觉引入

你写过 `"hello".length` 或 `"hello".toUpperCase()` 吗？字符串是原始值，按理说没有属性和方法——那这些调用为什么能工作？答案是引擎在背后做了一次「装箱」：访问原始值的属性时，临时用 `new String(...)` 包一层对象，读取属性后立即销毁。这就是包装类型。类似地，`String`、`Number`、`Boolean` 这些原生构造器有两种身份——用 `new` 调用产生包装对象，不用 `new` 当函数调用则是显式类型转换。混用这两者会踩坑：`new String("a") === "a"` 是 `false`，因为左边是对象、右边是原始值。

## 原生构造器的两类用途

<Term def="原生构造器是语言内置的函数对象，兼具两种调用方式：用 new 调用创建对象实例（如 new Array()），不用 new 当函数调用则做显式类型转换（如 String(123)）。原始值没有属性方法，引擎临时装箱成包装对象供访问后立即销毁。">原生构造器</Term>的用法要分清。**推荐 new 的**：`Object`、`Array`、`Function`、`RegExp`、`Date`、`Error`、`Map`、`Set`——它们创建的就是对象，没有原始值形态。**可当函数做显式转换的**：`String(123)` 得 `"123"`、`Number("9")` 得 `9`、`Boolean(0)` 得 `false`——这是显式转换的安全写法，比 `123 + ""` / `+"9"` / `!!0` 更可读。**应避免 new 的**：`new String("a")`、`new Number(1)`、`new Boolean(false)`——它们产生包装对象，`typeof` 是 `"object"`，与原始值比较会出错。`Symbol`、`null`、`undefined` 没有对应的包装构造器。

```javascript
// 包装对象的「幽灵赋值」
let s = "hi";
s.x = 1;            // 装箱成 String 对象，赋值成功……
console.log(s.x);   // undefined —— 临时对象已被销毁，赋值丢了

// new 与函数调用的区别
typeof "a";            // "string"
typeof new String("a"); // "object"
new String("a") === "a"; // false（对象 ≠ 原始值）
String(123);            // "123"（显式转换，推荐）

// 运算符优先级：&& 高于 ||，都高于 ?:
a && b || c;   // 等价 (a && b) || c
a || b && c;   // 等价 a || (b && c)
// 别背优先级表，用括号表达意图
```

## 运算符优先级与 ASI

运算符优先级决定「先算谁」。最易错的是 `&&` 高于 `||`（两者都高于 `?:`），所以 `a && b || c` 是 `(a && b) || c`。记忆优先级表负担大且易错，工程上更稳妥的做法是**用括号显式表达结合意图**——括号是给读代码的人看的，不是给引擎看的。另一个语法陷阱是**自动分号插入（ASI）**：`return` 后换行会被补分号导致返回 `undefined`；行首以 `[` 或 `(` 开头可能与上一行合并。ASI 的规则复杂且偶有反直觉，建议**显式写分号**，不依赖 ASI 的「方便」。

## 常见误区

<Callout type="trap">
**误区：`new String("a")` 和 `"a"` 是一回事。** 它们天差地别。`"a"` 是原始字符串，轻量、按值比较；`new String("a")` 是包装对象，是引用类型，`typeof` 是 `"object"`，且两个独立的 `new String("a")` 用 `==` 比较是 `false`（对象比较看引用是否相同）。包装对象存在的意义只是让原始值能临时调用方法，日常代码绝不应该手动 `new` 一个包装类型——用字面量 `"a"` / `1` / `false`，需要转换时用 `String(x)` / `Number(x)` / `Boolean(x)`。
</Callout>

<Exercises>
**问题 1**：为什么 `let s = "hi"; s.x = 1; console.log(s.x)` 得到 `undefined`？

<Answer>
s 是原始字符串，没有属性。第二行 `s.x = 1` 访问 s 的属性时，引擎临时用 new String("hi") 装箱成一个包装对象，在包装对象上设置 x = 1，但这个包装对象是临时的，语句执行完立即被销毁——x 赋到了一个即将丢弃的对象上。第三行再次访问 s.x 时，又新建了一个全新的包装对象（没有 x 属性），所以得到 undefined。这就是「幽灵赋值」：写得到、读不到。原始值的属性访问永远是只读的临时装箱，赋值无法持久化。
</Answer>

**问题 2**：`new String("a") === "a"` 为什么是 `false`？工程上应如何避免这个坑？

<Answer>
`===` 类型不同直接返回 false。左侧 `new String("a")` 是包装对象，typeof 是 "object"；右侧 `"a"` 是原始字符串，typeof 是 "string"。类型不同（object ≠ string），所以 === 直接判 false，根本不比值。更隐蔽的是 `new String("a") == new String("a")` 也是 false——对象用 == 比较看引用是否相同，两个独立的对象引用不同。避免方法：永远用字面量 "a" / 1 / false 而非 new 包装类型；需要类型转换用 String(x)/Number(x)/Boolean(x)（无 new 的函数调用）；判断原始值用 typeof；判断对象用 instanceof 或 Array.isArray。记住「原始值用字面量，对象用 new，转换用函数」三类分清。
</Answer>
</Exercises>
