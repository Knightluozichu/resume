## 核心概念与状态所有权

<Term def="按照运行时调用栈而不是源码嵌套关系寻找名称的作用域规则；它是本章的对照模型。">动态作用域</Term>

<Term def="按照函数写在哪里决定名称归属的绑定规则，JavaScript 的普通变量采用这种规则。">词法绑定</Term>

<Term def="记录当前函数调用关系的运行时栈，动态查找会沿它向调用者方向检查。">调用栈</Term>

<Term def="当前函数由谁调用以及该调用帧中有哪些同名绑定的运行时环境。">调用者环境</Term>

<Term def="从当前环境开始，按指定规则逐层寻找名称直到找到绑定或确认不存在的过程。">动态查找</Term>

<Term def="由调用表达式和接收者决定的特殊上下文，不等同于普通变量的词法或动态查找。">this</Term>

## 常见误区与故障注入

<Callout type="trap" title="陷阱：JavaScript 会沿调用栈寻找未声明的变量">
  现象：caller 里有同名 value，就预测 read() 会读取 caller.value。原因：JavaScript 的标识符按函数定义位置的词法环境解析，不按运行时调用者改写。修法：同时画 definition chain 和 call stack，再比较两条路径。
</Callout>

<Callout type="trap" title="陷阱：this 就是动态作用域下的普通变量">
  现象：把 this 的变化解释成 value 一样的名称查找。原因：this 通常由调用表达式的接收者或调用方式决定，不等于沿调用栈查找自由变量。修法：分别记录 identifier binding 与 call-site receiver，再重放方法调用和脱离调用。
</Callout>

故障注入只改变一个条件：调用者环境、函数定义位置或调用表达式的接收者。若同时改变变量名和调用路径，就无法判断偏离来自词法规则、动态对照模型还是 this 绑定。

## 练习

<Exercises>

1. **问题 1：修改 `read` 与 `caller` 示例，让 caller 和全局都声明 `value`。** 分别写出 JavaScript 词法规则与假设动态规则下的结果，并画出两条查找路径。

<Answer question="为什么 JavaScript 的 read() 仍然返回 global？">
  read 的函数体定义在全局环境中，value 的词法绑定在定义时就确定为 global。caller 只是运行时调用者，不能把 caller.value 注入 read 的词法环境；只有在假设动态作用域的对照模型里，调用栈才会让 caller.value 获胜。
</Answer>

2. **问题 2：把 `caller` 改成另一个调用者，并在两个调用者中放入不同的 value。** 记录动态模型的最近绑定、词法模型的定义绑定和第一个分歧点。

<Answer question="更换调用者为什么能改变动态模型却不能改变词法模型？">
  动态查找从当前调用栈向调用者环境移动，更换调用者就更换了候选绑定；词法查找沿 read 的定义环境移动，调用者只改变路径而不改变定义位置，所以仍读取同一份 global 绑定。
</Answer>

3. **问题 3：把 `read` 改成对象方法，再分别用 `obj.read()` 和脱离对象的 `const run = obj.read; run()` 调用。** 说明变量 value 与 `this` 应分别记录什么证据。

<Answer question="为什么 this 不能直接当作动态作用域？">
  value 仍按函数定义位置解析；this 则由调用表达式是否带有 obj 接收者、严格模式等调用条件决定。前一次调用有 obj，后一次调用可能失去接收者；两条证据属于不同机制，不能用 this 的变化证明变量沿调用栈查找。
</Answer>

</Exercises>
