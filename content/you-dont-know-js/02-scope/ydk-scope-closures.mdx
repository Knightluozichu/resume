## 直觉引入

作用域回答「变量在哪可见」。JavaScript 用的是**词法作用域**——作用域的边界在编写代码时由代码结构（函数/块的位置）画好，和运行时在哪里调用无关。你可以把它想象成一组嵌套的气泡：全局气泡里套着函数气泡，函数气泡里套着内部函数气泡。查找变量时由内向外逐层找，命中即止；内层同名变量会遮蔽外层。闭包则建立在这之上：当一个函数被传到别处执行时，它会「带走」自己定义处的气泡——哪怕那个气泡的外层函数早已返回，闭包仍能继续访问其中的变量。

## 词法作用域与欺骗词法

<Term def="词法作用域是由代码书写时函数和块的位置决定的作用域模型，编译阶段就确定边界，与运行时调用位置无关；查找变量时由内向外逐层进行，内层同名变量遮蔽外层。">词法作用域</Term>是 JavaScript 作用域的根基。引擎查找变量时从最内层作用域开始，逐层向外，找到就停。有两类机制可以「欺骗」词法作用域：`eval` 在运行期执行字符串，可以改写当前作用域（声明新变量），破坏引擎的静态优化；`with` 用对象创建临时作用域。两者都会让引擎无法在编译期确定变量来源，性能差且易出错，严格模式禁用了 `with`，`eval` 也有独立作用域限制。结论是：**别用它们欺骗词法作用域**。

```javascript
// 词法作用域：由书写位置决定，与调用处无关
var a = 2;
function foo() {
  var b = 3;
  function bar() {
    var c = 4;
    return a + b + c; // c 自身、b 外层、a 全局，由内向外查
  }
  return bar;
}
var baz = foo();
baz(); // 9 —— bar 在 foo 内定义，记住的是 foo 的作用域，不是调用处 baz 的作用域

// 闭包：模块模式（IIFE + 返回公开 API，私有成员藏在闭包里）
var Counter = (function () {
  var count = 0; // 私有，外部拿不到
  return {
    inc: function () { return ++count; }, // 闭包延续对 count 的访问
    get: function () { return count; },
  };
})();
Counter.inc(); // 1
Counter.count; // undefined —— count 不暴露
```

## 闭包的本质

闭包不是「函数返回另一个函数」这个形式，而是「函数记住并继续访问其词法作用域」这个机制。`makeCounter` 返回的函数之所以能一直累加 `count`，是因为它持有对 `count` 所在作用域的引用——哪怕 `makeCounter` 早已执行完返回，`count` 也不会被回收。闭包的经典应用：模块模式（私有成员封装）、`once`（保证函数只执行一次）、循环中捕获每轮的 `i`（用 IIFE 或 `let`）。循环 + 闭包是最经典的坑：`for (var i...)` 的回调共享同一个 `i`，最终都拿到循环结束值；用 `let` 或 IIFE 才能为每轮捕获独立的 `i`。

## 常见误区

<Callout type="trap">
**误区：闭包 = 函数返回一个函数。** 形式不是本质。即使不返回任何函数，只要内部函数在外部函数之外被调用并访问了外部变量，闭包就存在。闭包的真正定义是「函数与其词法作用域的组合」——函数记住了自己定义处的变量环境，并在被调用时继续访问它。判断闭包是否存在，不看代码长什么样，而看「函数是否在自己定义的作用域之外执行，且访问了该作用域的变量」。模块模式之所以能封装私有成员，正是依赖闭包：私有的 `count` 只能通过返回的公开方法访问，外部无法直接触碰。
</Callout>

<Exercises>
**问题 1**：词法作用域和动态作用域的区别是什么？JavaScript 是哪种？

<Answer>
词法作用域的作用域边界在编写代码时由函数/块的位置确定，编译阶段就固定，与运行时在哪里调用无关——查找变量时从定义处由内向外逐层找。动态作用域的作用域边界在运行时由调用栈决定，函数在哪里被调用就找哪里的变量。JavaScript 是词法作用域（绝大多数语言都是）。区别体现在：词法作用域下，baz = foo() 后在任意位置调用 baz()，bar 内的 a 总是指向 foo 定义处的全局 a，而非调用 baz 的位置附近的 a。this 的绑定机制有点像动态作用域（由调用点决定），但作用域本身是词法的，两者别混淆。
</Answer>

**问题 2**：为什么 `for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0)` 打印三个 3？如何修复？

<Answer>
var 声明的 i 是函数级作用域，整个循环共用一个 i。setTimeout 的回调是闭包，捕获的是同一个 i 的引用。循环结束时 i 已经是 3，三个回调在宏任务队列里依次执行时读到的都是 3。修复有两种：①把 var 改成 let——let 是块级作用域，每轮循环创建一个独立的 i 绑定，每个闭包捕获各自的 i，打印 0 1 2；②用 IIFE 在每轮捕获当时的 i 值：setTimeout((function(j){ return () => console.log(j); })(i), 0)，把 i 作为参数传进 IIFE，j 是独立的副本。本质都是为每轮循环创建独立的作用域/绑定，让闭包捕获到不同的值。
</Answer>

<Glossary>
<GlossaryItem term="词法作用域">由代码书写时函数和块的位置决定的作用域模型，编译阶段确定边界，与运行时调用位置无关。查找变量由内向外逐层进行，内层同名变量遮蔽外层。eval/with 可在运行期欺骗词法作用域但代价大，严格模式禁用 with。</GlossaryItem>
<GlossaryItem term="闭包">函数与其词法作用域的组合。函数记住自己定义处的变量环境，即使在该作用域之外被调用（甚至定义处的外层函数已返回），仍能继续访问其中的变量。本质是「函数记住并延续其词法作用域」，非「函数返回函数」的形式。应用：模块模式、once、循环捕获 i。</GlossaryItem>
<GlossaryItem term="模块模式">用 IIFE 包裹私有状态，返回公开 API 的对象，私有成员通过闭包封装、外部无法直接访问。是 ES6 模块出现前实现封装的标准手法，闭包让私有变量只对公开方法可见。</GlossaryItem>
</Glossary>
