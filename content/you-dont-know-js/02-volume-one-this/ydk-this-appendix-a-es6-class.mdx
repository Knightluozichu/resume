## 核心概念与状态所有权

<Term def="class 是声明构造器与原型方法的语法形式；它改变书写方式，不会把方法复制到每个实例。">class 语法</Term> 先提供类定义；真正的实例状态仍由构造器调用时的 `this` 持有。

<Term def="constructor 是用 new 创建实例时运行的初始化方法；它把属于当前实例的字段写到 this 上。">constructor</Term> 负责把输入转成实例自己的状态。

<Term def="extends 建立子类原型与父类原型之间的链接，使缺失的方法可以向父级查找。">extends</Term> 表达的是可观察的原型关系，而不是把父类源码拷贝进子类。

<Term def="super 在子类方法中定位父级实现，同时仍以当前实例作为接收者执行它。">super</Term> 让父级行为可以复用，但不会把当前 `this` 换成父级对象。

<Term def="原型链接是对象查找自身属性失败后继续向上查找的关系；它决定共享方法从哪里被找到。">原型链接</Term> 连接 `child`、`Child.prototype` 与 `Parent.prototype`。

<Term def="方法描述符是属性的 value、writable、configurable、enumerable 等元数据；class 方法默认位于原型上且不可枚举。">方法描述符</Term> 把“方法没有复制到实例”变成可以检查的证据。

这些概念要一起回答五个问题：输入由谁创建，绑定或状态保存在哪里，哪一步读取或修改它，失败怎样传播，结束后由谁清理。只有五项同时可观察，机制解释才算闭环。

| 观察量 | 本页判定方式 |
| --- | --- |
| class 语法 | 比较类定义与实例自身属性，确认方法没有被复制 |
| constructor | 记录 `new Child()` 产生的接收者与实例字段 |
| extends | 用 `Object.getPrototypeOf` 检查两层原型关系 |
| super | 跟踪父级方法查找与当前实例的 `this` |
| 方法描述符 | 读取 prototype 方法的 `enumerable` 等属性 |

## 常见误区与故障注入

<Callout type="trap" title="陷阱：class 方法会复制到每个实例">

现象：为每个 `child` 想象一份独立的 `speak` 函数。

原因：把类声明的视觉结构误当成对象内存布局；方法实际通常在 `Child.prototype` 上共享。

修复：同时运行 `Object.hasOwn(child, "speak")` 与 `Object.hasOwn(Child.prototype, "speak")`，比较状态归属和行为来源。

</Callout>

<Callout type="trap" title="陷阱：super 就是把父方法复制到子方法里">

现象：认为 `super.speak()` 会把 `this` 换成 `Parent.prototype`。

原因：忽略了父级方法的查找位置与当前调用接收者是两件事。

修复：让父方法读取 `this.name`，再用 `new Child()` 调用，确认父级实现读取的仍是 child 的状态。

</Callout>

<Callout type="trap" title="陷阱：class 构造器可以像普通函数一样调用">

现象：直接运行 `Child()`，期待得到一个没有原型链接的对象。

原因：class 构造器有强制的 `new` 调用约束，缺少实例接收者时会在入口处失败。

修复：把调用改为 `new Child()`，再比较实例状态、原型链接和方法查找路径。

</Callout>

<Callout type="info" title="观察法：先看 own property，再看 prototype">

现象：只打印 `child.speak()` 的返回值，无法分辨方法从哪里来。

原因：属性查找把实例自身属性和原型上的共享行为合并成了一个最终结果。

修复：依次读取 `Object.keys(child)`、`Object.getPrototypeOf(child)` 和方法描述符，把状态、关系、元数据分栏记录。

</Callout>

## 机制拆解

### 1. 声明类与原型方法

声明 `class Parent` 时，方法定义进入 `Parent.prototype` 的方法槽；声明本身不会为未来每个实例复制一份函数。`class` 语法收紧了构造器调用和方法定义的边界，但它仍然要依赖对象属性查找来执行行为。

先写证据：`Object.hasOwn(Parent.prototype, "speak")` 应为真，而 `Object.keys(Parent.prototype)` 通常看不到 `speak`，因为 class 方法默认不可枚举。这个差异正是语法外观与属性描述符之间的连接点。

### 2. 用 new 创建实例

`new Child()` 做两件关键的事：创建新的实例接收者，并把它的原型设置为 `Child.prototype`，随后进入构造器流程。实例自己的数据应写到 `this`，共享行为则留在原型链上。

如果把 `Child()` 当普通函数调用，class 构造器会直接抛出 `TypeError`。这不是“少了一个可选参数”，而是实例创建契约没有成立；应在故障样本中把停止点记录为构造器入口。

### 3. constructor 初始化状态

`constructor(name) { this.name = name; }` 中的 `this` 是新建的 child。因而 `Object.keys(child)` 可以看到 `name`，但通常看不到 `speak`。这让状态所有权和行为来源保持分离：每个实例有自己的数据，多个实例共享同一个方法实现。

验证时不要只比较输出。创建两个不同名字的实例，分别读取 `name`，再比较 `childA.speak === childB.speak`；前者应不同，后者应相同，才能同时证明实例状态独立、方法行为共享。

### 4. extends 建立两层原型关系

`class Child extends Parent` 会建立 `Child.prototype → Parent.prototype` 的方法查找链。`Object.getPrototypeOf(child) === Child.prototype`，而 `Object.getPrototypeOf(Child.prototype) === Parent.prototype`，这两条断言比“Child 继承 Parent”这句口号更可验收。

当 child 自身没有 `speak` 时，查找先检查 `Child.prototype`，再进入 `Parent.prototype`。若链条被错误替换，结果可能仍然偶尔正确，却会在 `super`、内省或多层继承时暴露首个偏离点。

### 5. super 解析父级方法

子类覆盖 `speak` 时，`super.speak()` 定位的是父级实现；真正执行函数时，接收者仍是当前 child。因此父级方法可以读取 `this.name`，返回与 child 状态相关的结果。

把它简化成普通的“复制 + 调用”会漏掉两个证据：父级方法来自哪里，以及它为谁执行。实验应同时记录 `Parent.prototype.speak` 的来源和 `new Child("Ada").speak()` 的接收者。

### 6. 检查语法糖之外的运行时链接

最后用内省把推理钉住：`Object.getOwnPropertyNames(Child.prototype)` 可以看到 `constructor` 与方法名，而 `Object.getOwnPropertyDescriptor(Child.prototype, "speak")` 可以读取 `enumerable: false` 等元数据。实例只承担自己的字段，不承担一份重复的方法。

这条证据链覆盖正常、边界、失败与恢复：正常样本证明查找路径，边界样本证明多个实例的状态隔离，失败样本证明缺少 `new` 时明确停止，恢复样本则在修正调用后重新创建干净实例。

## 最小可运行实验

下面的片段只保留本章最小机制。运行前先预测每一行的绑定、类型与输出，再修改一个条件观察首个偏离点：

```js
class Parent {
  speak() {
    return this.name;
  }
}

class Child extends Parent {
  constructor(name) {
    super();
    this.name = name;
  }

  speak() {
    return super.speak() + ":child";
  }
}

const child = new Child("Ada");
console.log(child.speak());
console.log(Object.getPrototypeOf(child) === Child.prototype);
console.log(Object.getOwnPropertyDescriptor(Child.prototype, "speak"));
```

预期结果是 `Ada:child`、第一条原型断言为 `true`，并且 `speak` 的描述符显示 `enumerable: false`。如果把 `new Child("Ada")` 改成 `Child("Ada")`，故障应在构造器入口停止，而不是生成一个“半成品实例”。

   <Answer>

   在 `constructor(name)` 中写入 `this.name = name`，然后比较 `first.name !== second.name` 与 `first.speak === second.speak`。前者说明状态属于实例，后者说明方法沿原型共享。

   </Answer>

2. 使用 `Object.keys`、`Object.getOwnPropertyNames` 和 `Object.getOwnPropertyDescriptor` 检查 `Child.prototype.speak`。哪一项证据能解释方法为什么没有出现在实例的键列表中？

   <Answer>

   `Object.keys(child)` 只列出实例自身的可枚举状态字段；`Object.getOwnPropertyNames(Child.prototype)` 能看到 `speak`，而其描述符的 `enumerable` 为 `false`。因此方法在原型上共享，并非复制到每个 child。

   </Answer>

3. 分别运行 `new Child("Ada").speak()`、`Child("Ada")`，再让父级 `speak` 读取 `this.name`。记录正常输出、故障类型和 `super` 调用时的接收者。

   <Answer>

   正常调用应返回 `Ada:child`；直接调用 class 构造器会得到 `TypeError`，因为缺少 `new`。`super.speak()` 找到父级实现，但父级函数仍以当前 child 为 `this`，所以能够读取 `Ada`。

   </Answer>

</Exercises>

## 小结

- **class 语法**：提供更整洁的声明外壳，不等于复制实例方法。
- **constructor**：在 `new` 流程中把状态写入当前实例。
- **extends**：建立子类与父类原型之间的可观察链接。
- **super**：定位父级实现，同时保留当前实例作为接收者。
- **原型链接**：决定属性查找如何从 child 向两个 prototype 继续。
- **方法描述符**：用 `enumerable` 等元数据证明方法的存放与枚举行为。

理解 class 的关键不是背诵语法，而是能沿着实例、原型、父级方法和描述符逐步复演一次运行时过程。
