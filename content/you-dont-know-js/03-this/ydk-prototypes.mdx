## 直觉引入

JavaScript 没有 Java/C++ 那种「类」，它的对象复用靠的是**原型链**：每个对象都有一个内部属性 `[[Prototype]]`，指向另一个对象（它的原型）。访问一个属性时，如果自身没有，就沿 `[[Prototype]]` 一路向上找，直到找到或到达链顶 `null`。这套机制本质是「对象直接关联对象」的**行为委托**，而非「类继承类」。ES6 的 `class` 关键字只是这套原型机制的语法糖——写法像类，底层仍是原型链。理解这一点，才能解释为什么「修改一个实例的原型会影响所有实例」「为什么 `instanceof` 其实是在查原型链」。

## [[Prototype]] 与属性查找

<Term def="[[Prototype]] 是每个对象内部的链接，指向其原型对象。访问属性时若自身没有，沿 [[Prototype]] 逐层向上查找，直到命中或到达链顶 null（Object.prototype.__proto__）。这套对象间的链接构成原型链，本质是行为委托而非传统类继承。">[[Prototype]]</Term>是原型链的基石。读取属性沿链向上找，找不到返回 `undefined`（不报错）；写入属性则直接写在当前对象上，会遮蔽原型链上同名属性（不会修改原型）。`__proto__`（已 deprecated）是访问 `[[Prototype]]` 的历史遗留方式，现代代码用 `Object.getPrototypeOf(obj)` 读取、`Object.create(proto)` 创建指定原型的对象。原型链的终点是 `Object.prototype.__proto__ === null`——查找到这里停止。直接改 `__proto__` 或 `Foo.prototype` 会让所有已存在实例的查找路径变化，非常危险且影响性能（破坏引擎的隐藏类优化）。

```javascript
// 原型链委托
const Foo = { greet() { return "hi"; } };
const obj = Object.create(Foo); // obj.__proto__ === Foo
obj.greet();        // "hi" —— 自身没有，沿链在 Foo 找到
obj.toString();     // 来自 Object.prototype，继续向上链
Object.getPrototypeOf(obj) === Foo; // true

// 属性遮蔽（写不修改原型）
obj.greet = function () { return "yo"; }; // 写在自身，遮蔽 Foo.greet
Foo.greet;          // 仍是原方法，未被改

// 寄生组合继承（最优，ES6 class extends 的底层）
function Animal(name) { this.name = name; }
Animal.prototype.speak = function () { return this.name; };
function Dog(name) { Animal.call(this, name); } // 1. 借构造函数（实例属性）
Dog.prototype = Object.create(Animal.prototype); // 2. 复制原型（方法委托）
Dog.prototype.constructor = Dog; // 3. 修正 constructor
// ES6 等价写法
class Dog2 extends Animal { constructor(name) { super(name); } }
```

## 继承方式演进与行为委托

原型链继承（`Sub.prototype = new Super()`）有两个致命缺陷：引用类型的属性被所有实例共享（改一个全变）、无法向父构造函数传参。组合继承（构造函数 `call` + 原型链）解决了共享问题但调用了两次父构造函数（一次在 `call`、一次在 `new Super()`），有冗余。**寄生组合继承**是最优解：用 `Object.create(Super.prototype)` 复制原型（只复制方法、不调父构造函数）+ 构造函数 `call` 借实例属性，只调一次父构造函数——这正是 ES6 `class extends` 的底层实现。YDKJS 提倡的「行为委托」心智更进一步：与其模拟类的继承层级，不如直接设计对象间的委托关系（`Object.create` 关联对象），代码更扁平、更符合 JS 的真实机制。

## 常见误区

<Callout type="trap">
**误区：JavaScript 的 class 就是真正的类。** 它只是原型机制的语法糖。`class Foo {}` 编译后仍是函数 + `Foo.prototype`，`extends` 底层是寄生组合继承（`Object.create` + `super` 调用），`instanceof` 检查的是原型链上是否出现某构造函数的 `prototype`。心智上把 class 当类用没问题，但遇到「为什么改了原型所有实例都变」「为什么实例没有 own 属性却能调方法」「super 到底调的谁」这些问题，必须回到原型链委托的真相才能解释。YDKJS 的核心观点：JS 没有类，只有对象间的委托链；理解行为委托比套用类继承心智更接近语言本质。
</Callout>

<Exercises>
**问题 1**：读取属性和写入属性在原型链上的行为有何不同？为什么？

<Answer>
读取属性沿原型链向上查找：自身没有就找 __proto__（即 [[Prototype]]），逐层向上直到命中或到达 Object.prototype.__proto__ = null，找不到返回 undefined（不报错）。写入属性则不查原型链，直接在当前对象上创建/修改 own 属性——若原型链上有同名属性，会在当前对象新建一个遮蔽它，不会修改原型上的原属性。这样设计的原因：原型是共享的，若写入也沿链查找修改，一个实例改属性会影响所有实例，破坏封装。读写不对称保证实例能自定义属性而不污染共享原型。若确实要改原型属性，需显式 Foo.prototype.x = ... 而非 obj.x = ...。
</Answer>

**问题 2**：原型链继承有什么缺陷？寄生组合继承如何解决？为什么说它是 class extends 的底层？

<Answer>
原型链继承 Sub.prototype = new Super() 有两个缺陷：①父类的引用类型属性（如数组）挂在 Super.prototype 上被所有实例共享，一个实例 push 会影响全部；②无法向父构造函数传参（new Super() 时没有实例参数）。组合继承（构造函数 call + 原型链）解决共享但调了两次父构造函数（call 一次、new Super() 一次），实例属性冗余。寄生组合继承：Dog.prototype = Object.create(Animal.prototype) 只复制原型（方法委托，不调父构造函数、不产生实例属性）+ 构造函数 Animal.call(this, name) 借实例属性（只调一次）。它消除了共享、可传参、只调一次父构造函数，是最优解。ES6 class extends 编译后正是这套：super(name) 对应 Animal.call，extends 对应 Object.create(Animal.prototype) 并修正 constructor，所以说是 class extends 的底层。
</Answer>
</Exercises>
