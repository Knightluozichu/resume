## 直觉引入

`this` 是 JavaScript 里最被误解的关键字之一。很多人以为 `this` 指向「函数自己」或「定义它的对象」，都不对。**`this` 是在函数调用时绑定的，由调用点（call-site，即函数被调用的那行代码）决定指向谁。** 同一个函数，用不同方式调用，`this` 就不同。判断 `this` 要看四条规则，按优先级从高到低：new 绑定 > 显式绑定 > 隐式绑定 > 默认绑定。还有个例外——箭头函数不适用这四规则，它继承定义处外层的 `this`。

## 四规则与优先级

<Term def="this 绑定由调用点（函数被调用的那行代码）决定，按四规则优先级判断：new 绑定（构造调用指向新对象）> 显式绑定（call/apply/bind 指定对象）> 隐式绑定（对象方法指向该对象）> 默认绑定（独立调用指向全局或 undefined）。箭头函数是例外，继承词法 this。">this 绑定四规则</Term>是判断 `this` 的核心工具。**默认绑定**（最低优先级）：独立函数调用 `foo()`，非严格模式 `this` 指向全局对象，严格模式是 `undefined`。**隐式绑定**：对象方法调用 `obj.foo()`，`this` 指向调用处的 `obj`；但引用赋值或传回调会让 `this` 丢失（`var f = obj.foo; f()` 落回默认绑定）。**显式绑定**：`foo.call(obj)` / `apply(obj, args)` / `bind(obj)`，`this` 指定到 `obj`；`bind` 是硬绑定，返回的新函数 `this` 不可再改。**new 绑定**（最高优先级）：`new Foo()` 创建新对象，`this` 指向它。判断时从调用点出发，按优先级匹配。

```javascript
// 四规则示例
function foo() { console.log(this.a); }
var a = "全局"; // （非严格模式）

foo();             // 默认绑定：全局 → "全局"
var obj = { a: "obj", foo };
obj.foo();         // 隐式绑定：this → obj → "obj"

// 隐式丢失：引用赋值或回调，this 丢了
var f = obj.foo;
f();               // 默认绑定 → "全局"（不是 obj！）
setTimeout(obj.foo, 0); // 同理，回调里 this 丢失

// 显式绑定
foo.call({ a: "call" });  // "call"
var bound = foo.bind({ a: "bind" });
bound();           // "bind"（硬绑定，call/apply 改不了）

// new 绑定（最高优先级）
function Bar(a) { this.a = a; }
var b = new Bar("new"); // this → 新对象
console.log(b.a);  // "new"

// 箭头函数例外：继承词法 this，四规则都改不了
function Timer() {
  this.seconds = 0;
  setInterval(() => this.seconds++, 1000); // 箭头继承 Timer 的 this
}
```

## 隐式丢失与箭头函数

隐式绑定最容易在两个场景丢失：①把方法赋给变量再调用（`var f = obj.foo; f()`）；②把方法作为回调传递（`setTimeout(obj.foo, 0)`、`arr.map(obj.foo)`）。丢失的根因是调用点变成了独立调用，落回默认绑定。修复方法：用 `bind` 硬绑定（`setTimeout(obj.foo.bind(obj), 0)`）、用箭头函数包裹（`setTimeout(() => obj.foo(), 0)`）、或直接在方法内用箭头函数捕获 `this`。箭头函数没有自己的 `this`，它继承定义处外层词法作用域的 `this`，且 `call`/`apply`/`bind` 都改不了——这让它在回调里保留外层 `this` 非常方便，但不适合需要动态 `this` 的对象方法或原型方法。

## 常见误区

<Callout type="trap">
**误区：`this` 指向函数自己或定义它的对象。** 都错。`this` 在调用时绑定，由调用点决定，和函数定义在哪、定义在哪个对象里都无关。同一个函数 `foo`，`obj.foo()` 时 `this` 是 `obj`，`foo()` 时 `this` 是全局（或 undefined），`foo.call(x)` 时 `this` 是 `x`，`new foo()` 时 `this` 是新对象。判断 `this` 的正确方法是找到调用点（函数被调用的那行），按 new > 显式 > 隐式 > 默认的优先级匹配。另一个相关误区：箭头函数的 `this` 不是「指向定义它的对象」，而是「继承定义处外层词法作用域的 this」，且无法被 call/apply/bind 改变。
</Callout>

<Exercises>
**问题 1**：`var f = obj.foo; f()` 为什么 `this` 不再指向 `obj`？如何修复？

<Answer>
this 由调用点决定。obj.foo() 的调用点是 obj.foo，属于隐式绑定，this 指向 obj。但 var f = obj.foo 只是把函数引用赋给 f，调用点变成 f()，是独立调用，属于默认绑定，this 指向全局（非严格）或 undefined（严格）。this 是否绑定看「调用时 this 在点号左边是谁」，f() 调用点没有点号左边的对象，所以丢失。修复三种：①硬绑定 var f = obj.foo.bind(obj) 后 f() 的 this 恒为 obj；②箭头包裹 setTimeout(() => obj.foo(), 0) 在箭头里显式以 obj 调用；③在方法内部用箭头函数捕获 this。回调场景（setTimeout、map、事件监听）同理，传递方法引用都会丢 this。
</Answer>

**问题 2**：箭头函数的 `this` 和普通函数有何不同？什么场景该用、什么场景不该用？

<Answer>
普通函数有自己的 this，由调用点按四规则绑定，可被 call/apply/bind 改变。箭头函数没有自己的 this，继承定义处外层词法作用域的 this，且 call/apply/bind 无法改变它。该用的场景：回调里需要保留外层 this，如定时器、事件处理、Promise 链中访问外层对象——箭头函数省去 bind/self = this 的样板。不该用的场景：①对象方法，因为对象字面量不创建作用域，箭头方法里的 this 是外层（通常是全局/undefined）而非对象本身；②原型方法，同理 this 不会指向实例；③需要动态 this 的函数（如可被 call 复用的工具函数）。判断准则：需要「调用点决定 this」用普通函数，需要「固定外层 this」用箭头。
</Answer>
</Exercises>
