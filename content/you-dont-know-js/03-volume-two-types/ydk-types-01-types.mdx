## 直觉：先预测，再运行

JavaScript 的类型属于值而非变量；`typeof` 能区分多数内建类型，却对 `null` 和函数保留历史特例，并且未声明标识符与值为 `undefined` 是两种状态。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：typeof null 的结果就是 null 的类型">

现象：看到 `typeof null` 返回 `object`，就把 `null` 当成普通对象处理。

原因：这是 JavaScript 保留下来的历史分类结果；`typeof` 的标签不等于所有场景下的完整类型判定。

修复：需要判断空值时直接使用 `value === null`，需要判断对象时再排除 `null`。

</Callout>

<Callout type="trap" title="陷阱：undefined 值和未声明标识符是同一件事">

现象：把 `let declared;` 与不存在的 `missingName` 都记成“变量值为 undefined”。

原因：前者有一个已经登记的绑定，只是当前值为 `undefined`；后者根本没有可读取的绑定。

修复：用 `typeof missingName` 做安全探测，但对已声明变量仍要按普通值读取和追踪其绑定。

</Callout>

<Callout type="trap" title="陷阱：typeof 能完成所有类型检测">

现象：用 `typeof value === "object"` 判断数组，用 `typeof value === "number"` 判断有效数字。

原因：`typeof` 只提供粗粒度标签，数组、`null`、`NaN` 等边界会共享或误导标签。

修复：数组用 `Array.isArray`，NaN 用 `Number.isNaN`，空值用显式比较；让检测 API 与问题一一对应。

</Callout>

<Callout type="info" title="观察法：把值、绑定和分类结果分栏">

现象：只记录最终的字符串输出，无法解释变量改绑或未声明探测为何不同。

原因：值的类型、绑定是否存在、`typeof` 返回的标签属于三个不同观察面。

修复：每个样本同时记录表达式、绑定状态、值、标签和可靠断言，再注入一个边界条件重放。

</Callout>

## 核心概念与状态所有权

<Term def="类型描述的是当前值的运行时类别；变量本身可以先后绑定到不同类型的值。">值的类型</Term> 属于值，而不是变量名称的永久属性。

<Term def="typeof 是一个快速分类运算符，返回表示运行时类别的字符串，但它对 null、函数和未声明标识符有特殊规则。">typeof</Term> 适合做第一层分流，不应被当成所有类型问题的终点。

<Term def="undefined 是一个真实的 JavaScript 值，已声明但没有初始化的绑定可以保存它。">undefined 值</Term> 说明绑定存在，只是当前没有更具体的值。

<Term def="未声明标识符是从未登记进当前可访问环境的名称；直接读取通常抛出 ReferenceError。">未声明标识符</Term> 与保存 `undefined` 的已声明绑定必须分开追踪。

<Term def="内建类型是语言运行时直接提供的值类别，例如 string、number、boolean、object、symbol、bigint、function 和 undefined。">内建类型</Term> 是 `typeof` 分类和专用检测 API 的共同背景。

<Term def="类型检测是针对一个具体问题选择观察方式的过程；typeof、显式比较和专用 API 各自承担不同边界。">可靠类型检测</Term> 要先写清楚要判断的是标签、空值、容器还是数值有效性。

这些概念要一起回答五个问题：输入由谁创建，绑定是否存在，状态保存在哪里，哪一步读取或分类它，失败怎样传播，结束后由谁清理。只有把值与绑定分开，`typeof` 的历史行为才不会变成猜谜。

| 观察量 | 本页判定方式 |
| --- | --- |
| 值的类型 | 用数字、字符串、函数、数组和 `null` 样本比较运行时类别 |
| typeof | 记录返回标签，并标出它只是粗分类还是可直接验收 |
| undefined 值 | 创建已声明但未赋值的绑定，验证值存在且可读取 |
| 未声明标识符 | 用安全探测和直接读取对照，定位 `ReferenceError` 边界 |
| 内建类型 | 对照 `typeof` 的标签与专用 API 的精确判断 |
| 可靠类型检测 | 为 null、数组和 NaN 选择显式比较或专用函数 |

## 机制拆解

### 1. 表达式产生一个值

表达式先产生值，变量绑定只是保存这个值的可访问位置。`let item = 42` 里，`42` 是值，`item` 是绑定；随后执行 `item = "ready"`，改变的是绑定指向的值，不是把变量永久改造成某一种类型。

先记录两个证据：当前值是什么，以及它由哪个绑定保存。把 `typeof item` 放在第二步观察，是为了避免把变量名直接当成类型来源。

### 2. 值携带运行时类型

数字、字符串、布尔值、对象、函数、symbol、bigint 和 `undefined` 都是值的不同运行时类别。变量可以在不同时间保存不同类别的值，因此同一个绑定在重放样本时可能得到不同的 `typeof` 标签。

这也是“动态类型”的准确含义：类型检查发生在值被观察时，而不是声明变量时一次性签发一个不可改变的标签。要解释行为，应记录改绑前后的值和标签，而不是只说“这个变量是数字”。

### 3. typeof 执行分类

对普通值，`typeof` 返回 `"string"`、`"number"`、`"boolean"`、`"object"`、`"function"`、`"symbol"`、`"bigint"` 或 `"undefined"` 等字符串。函数被单独标为 `"function"`，这是语言运算符提供的便捷分类。

`typeof` 的优势是安全、快速、适合初筛；限制是它会合并不同结构，尤其把数组和 `null` 放在 `"object"` 这一标签下。验收时要把“标签正确”与“业务判定足够精确”分成两列。

### 4. 识别 null 历史特例

`typeof null` 返回 `"object"`，但 `null` 并不是一个可继续读取属性的普通对象。历史结果无法通过换一种拼写修复，只能在需要判断空值时使用 `value === null`，在需要判断非空对象时使用 `value !== null && typeof value === "object"`。

边界样本应把 `null` 与 `{}`、`[]` 放在一起比较：它们的 `typeof` 标签相同，但语义和后续可用操作不同。这正是“先分类、再按问题确认”的必要性。

### 5. 区分未声明与未赋值

`let declared;` 创建了一个已经登记的绑定，读取它得到 `undefined`。`missingName` 如果从未声明，则直接读取会抛出 `ReferenceError`；但 `typeof missingName` 为了兼容探测环境能力，会返回 `"undefined"` 而不抛错。

两者的共同字符串结果不能抹平不同的状态：前者有绑定、有值、可被后续赋值；后者没有绑定，不能当成可写变量使用。故障样本应在“直接读取”处停止，并记录错误类型。

### 6. 按用途选择可靠检测

把检测函数当成问题的答案表：要知道是不是函数，可以用 `typeof value === "function"`；要知道是不是数组，用 `Array.isArray(value)`；要知道一个数字是不是 NaN，用 `Number.isNaN(value)`；要判断空值，用 `value === null`。

可靠检测不是堆更多 API，而是先写验收问题。若问题是“有没有绑定”，先区分安全探测和直接读取；若问题是“是不是对象”，还要决定是否排除 `null`；若问题是“是不是数组”，就不要停在 `typeof === "object"`。

## 目录主题逐项讲解

### Chapter 1: Types

**Chapter 1: Types** 提出总问题：值的类型、变量绑定和检测标签分别由谁拥有。先用普通值走完主路径，再用 `null`、`undefined` 和未声明标识符制造偏离点。

### A Type By Any Other Name...

**A Type By Any Other Name...** 强调名称、绑定和值不是同一层东西。变量名可以保持不变，所绑定的值和 `typeof` 结果却可以随赋值改变。

### Built-in Types

**Built-in Types** 提供运行时直接可观察的类别背景。学习时不要只背标签，要把标签和对象结构、可调用性、空值语义及专用检测 API 对照起来。

### Values as Types

**Values as Types** 把结论落回值模型：类型跟着值走，检测动作必须针对当前值和当前绑定状态。每个边界样本都应保留表达式、值、标签和最终断言。

## 最小可运行实验

下面的片段只保留本章最小机制。运行前先预测每一行的绑定状态、值、标签与断言，再修改一个条件观察首个偏离点：

```js
let declared;
const empty = null;
const task = () => 1;

console.log(typeof declared, declared === undefined);
console.log(typeof empty, empty === null);
console.log(typeof task, typeof task === "function");
console.log(typeof missingName);
console.log(Array.isArray([]), Number.isNaN(NaN));
```

预期结果依次体现：已声明但未赋值的值、`null` 的历史标签、函数的特殊标签、未声明探测的安全结果，以及两个专用检测 API。若把最后一行改为直接读取 `missingName`，故障应明确为 `ReferenceError`。

## 练习

<Exercises>

1. 写一段代码，让同一个变量先保存数字、再保存字符串；记录两次 `typeof`，并说明类型变化发生在值还是变量上。

   <Answer>

   先执行 `let sample = 42; console.log(typeof sample);`，再执行 `sample = "ready"; console.log(typeof sample);`。输出从 `number` 变为 `string`，说明变量绑定换了值，类型跟着当前值走。

   </Answer>

2. 比较 `typeof null`、`null === null`、`typeof []` 和 `Array.isArray([])`。哪几个结果说明 `typeof` 只是粗分类？

   <Answer>

   `typeof null` 和 `typeof []` 都是 `object`，但 `null === null` 为真，`Array.isArray([])` 也为真。前者是历史标签，后者是针对具体语义的可靠断言；因此不能用 `typeof value === "object"` 单独完成两种判断。

   </Answer>

3. 分别测试已声明但未赋值的变量、`typeof missingName` 和直接读取 `missingName`。记录绑定状态、返回值或错误，并说明为什么不能把三者合并成一个 undefined 状态。

   <Answer>

   `let declared;` 有绑定，读取值为 `undefined`；`typeof missingName` 没有绑定但安全返回字符串 `"undefined"`；直接读取 `missingName` 会抛出 `ReferenceError`。三个样本的共同词面不能覆盖绑定存在性和错误传播差异。

   </Answer>

</Exercises>

## 小结

- **值的类型**：类型属于当前值，变量可以重新绑定到另一类值。
- **typeof**：安全的快速分类器，但不是所有边界问题的最终答案。
- **undefined 值**：已声明绑定可以保存的真实值。
- **未声明标识符**：没有可读取绑定的名称，直接读取会失败。
- **内建类型**：运行时直接提供的类别背景，包含函数与对象等特殊观察结果。
- **可靠类型检测**：让显式比较或专用 API 与具体问题匹配。

理解本章的关键不是背出一串标签，而是能在每次检测中同时说明值是什么、绑定是否存在、`typeof` 返回什么，以及为什么这个断言足够或不够精确。
