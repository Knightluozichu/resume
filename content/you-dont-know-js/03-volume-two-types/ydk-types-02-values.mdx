## 常见误区与故障注入

<Callout type="trap" title="陷阱：数组 length 就是实际元素数量">

现象：`const a = []; a[2] = "x"` 之后，把 `a.length === 3` 解释成三个元素都存在。

原因：数组的 length 记录最高索引加一；中间索引可能是空槽，而不是显式保存的 `undefined`。

修复：同时检查 `a.length`、`0 in a`、`2 in a` 和 `Object.keys(a)`，把容量与槽位存在性分开记录。

</Callout>

<Callout type="trap" title="陷阱：字符串长度就是用户看到的字符数">

现象：看到一个表情符号，就认为它占一个 `length` 单位并能用一次索引完整读取。

原因：JavaScript 字符串按 UTF-16 code unit 计数；一个 Unicode code point 可能由两个 code unit 组成。

修复：需要用户感知字符时使用 `Array.from` 或按 code point 遍历，并记录 `length` 与 code point 数量的差异。

</Callout>

<Callout type="trap" title="陷阱：所有数字都可以用普通相等比较">

现象：用 `0.1 + 0.2 === 0.3` 判断浮点计算无误，或用 `NaN === NaN` 判断 NaN 身份。

原因：二进制浮点表示会留下近似误差；NaN 不等于自身，正零和负零在普通相等中又会被合并。

修复：近似计算声明容差，NaN 使用 `Number.isNaN`，正负零使用 `Object.is`，不要用显示字符串替代断言。

</Callout>

<Callout type="trap" title="陷阱：对象赋值会复制一个独立对象">

现象：执行 `const b = a` 后修改 `b.items`，却认为 `a.items` 不会变化。

原因：对象赋值复制的是引用身份，两个绑定指向同一个对象；原始值才是在赋值时复制当前值。

修复：先比较 `a === b`，再记录一次受控 mutation；需要隔离时显式复制结构并重新检查嵌套引用。

</Callout>

## 核心概念与状态所有权

<Term def="数组中从零到 length 之间不一定每个索引都有属性；空槽与显式保存 undefined 的元素是不同状态。">稀疏数组</Term> 把容量、索引存在性和迭代行为拆成三份证据。

<Term def="字符串由 UTF-16 code unit 序列构成；length 和索引遵循 code unit 语义，不直接等于用户感知字符数量。">字符串不可变性</Term> 还意味着每次拼接或切片都要观察新值，而不是修改原字符串。

<Term def="Number 以二进制浮点方式表示大多数数字；十进制小数运算可能产生近似误差，需要容差比较。">浮点精度</Term> 要求把计算值和可接受误差一起写入验收条件。

<Term def="NaN 表示不是一个可用数字的结果；它不等于自身，应使用 Number.isNaN 做精确判断。">NaN</Term> 是特殊值，不是一个普通的数字字面量比较结果。

<Term def="值与引用描述赋值之后保存了什么：原始值通常复制值，对象通常复制引用身份；后者会产生可观察的别名。">值与引用</Term> 决定一次 mutation 是否会被多个绑定同时看到。

<Term def="专用 API 是针对具体边界提供的检测工具，例如 Array.isArray、Array.from、Number.isNaN 和 Object.is。">专用边界 API</Term> 让断言对象与问题精确匹配，而不是停在粗略的显示结果。

这些概念要一起回答五个问题：值由谁创建，容量或身份保存在哪里，哪一步读取或修改它，边界怎样传播，结束后由谁清理。只有同时保留表面结果与内部证据，值的语义才不会被一个数字或字符串掩盖。

| 观察量 | 本页判定方式 |
| --- | --- |
| 稀疏数组 | 比较 `length`、`in` 和实际键集合，确认空槽是否存在 |
| 字符串不可变性 | 比较原字符串、新字符串、code unit 与 code point |
| 浮点精度 | 记录计算结果、误差和声明的容差 |
| NaN | 用 `Number.isNaN` 验证，而不是用相等运算符猜测 |
| 值与引用 | 比较身份，再注入一次 mutation 观察别名传播 |
| 专用边界 API | 让每个 API 只负责一个明确的边界问题 |

## 机制拆解

### 1. 确定值的实际类型

确定一个值是什么，不能只看变量名称。数组是对象，但数组还拥有索引属性和 length 规则；字符串是不可变原始值；数字包含有限数、Infinity、NaN、正零和负零等不同语义区域。

因此第一步要把值的表面表示和可观察结构分开：打印数组不能证明所有槽位都存在，打印一个小数也不能证明它与数学实数完全相等。后续每个断言都应标明自己观察的是长度、身份、精度还是特殊值。

### 2. 区分容器与原始值

数组是容器，可以拥有空槽并在索引处保存元素；字符串虽然可以按索引读取，却不能原地修改字符。`text[0] = "x"` 不会改变原字符串，任何变更都应理解为创建了新的字符串值。

Unicode 样本尤其适合暴露容器直觉的漏洞：`"😀".length` 是两个 UTF-16 code unit，但 `Array.from("😀").length` 是一个 code point。要做用户感知字符处理，必须声明采用哪种单位。

### 3. 检查数字特殊值

浮点精度不是“打印时保留几位”的问题。`0.1 + 0.2` 的内部结果可能略偏离 `0.3`，可靠的近似比较应计算差值并与业务容差比较。`Number.EPSILON` 可以作为尺度参考，但工程验收仍要根据数值范围选择容差。

特殊数字值还包括 NaN、Infinity 和正负零。NaN 不等于自身，所以 `value === NaN` 永远不能作为有效检测；`Object.is(-0, 0)` 为假，说明正负零的身份差异需要单独记录。

### 4. 判断复制的是值还是引用

原始值赋值时，新的绑定得到当前值的副本；对象赋值时，新的绑定得到同一个对象的引用。`const a = { items: [] }; const b = a;` 之后，`a === b` 为真，`b.items.push(1)` 也会让 `a.items` 看到变化。

不要把“引用共享”理解成对象被复制了两份。真正共享的是身份；如果需要隔离，应明确采用浅复制或深复制，并继续检查嵌套对象是否仍然共享。

### 5. 执行变更并观察别名

一次受控 mutation 是判断身份关系的实验：先记录 `a === b`、`a.items.length` 和 `b.items.length`，只通过一个绑定修改，再记录三者。若两个绑定都变化，说明它们指向同一对象或共享了嵌套引用。

对原始值则采用重新赋值对照：`let first = 1; let second = first; second = 2` 不会改变 `first`。这两个实验必须使用同样的记录格式，否则容易把“不能改变原字符串”和“对象别名可变”混成一句泛泛的值语义。

### 6. 用专用 API 验证边界

专用 API 把含糊的表面结果变成明确断言：用 `Array.isArray` 确认数组，用 `Array.from` 按可迭代元素观察 Unicode，用 `Number.isNaN` 判断 NaN，用 `Object.is` 检查正负零或身份，用 `in` 检查数组槽位是否存在。

选择 API 前先写问题。若问题是“有几个索引属性”，看 `in` 或键集合；若问题是“有几个用户感知字符”，按 code point 遍历；若问题是“两个绑定是否共享对象”，比较 `===` 并观察 mutation。每个检测都要配一个边界反例。

## 目录主题逐项讲解

### Chapter 2: Values

**Chapter 2: Values** 把学习重点从“变量叫什么”转到“值的结构、身份和边界如何运行”。先建立正常的值样本，再让稀疏槽位、特殊数字和别名共享暴露首个偏离点。

### Arrays

**Arrays** 不只是连续元素列表；length、索引属性、空槽和迭代方式共同决定它的行为。观察数组时同时记录容量和属性存在性。

### Strings

**Strings** 是不可变的 UTF-16 code unit 序列。字符串的视觉字符、code point、code unit 和 length 必须在问题需要时分别命名。

### Numbers

**Numbers** 采用浮点表示，精度误差、Infinity 和正负零都属于值语义的一部分。比较数字时要把容差或特殊值断言写进验收表。

### Special Values

**Special Values** 让 NaN、Infinity、正零和负零成为显式样本。它们不能只靠普通相等和格式化输出判断。

### Value vs Reference

**Value vs Reference** 解释赋值后的身份关系：原始值复制当前值，对象保存可共享的引用。一次受控 mutation 能把别名传播变成直接证据。

## 六阶段证据链

本页的可执行链条是：确定值的实际类型 → 区分容器与原始值 → 检查数字特殊值 → 判断复制的是值还是引用 → 执行变更并观察别名 → 用专用 API 验证边界。正常样本证明主路径，边界样本证明槽位、编码、精度与特殊值差异，失败样本定位错误断言，恢复样本证明修正 API 或复制策略后没有旧身份污染。

## 最小可运行实验

下面的片段只保留本章最小机制。运行前先预测每一行的长度、身份、精度与输出，再修改一个条件观察首个偏离点：

```js
const sparse = [];
sparse[2] = "x";

const text = "😀";
const objectA = { items: [] };
const objectB = objectA;

console.log(sparse.length, 0 in sparse, 2 in sparse);
console.log(text.length, Array.from(text).length);
console.log(0.1 + 0.2 === 0.3, Number.isNaN(NaN), Object.is(-0, 0));
objectB.items.push("shared");
console.log(objectA === objectB, objectA.items.length);
```

预期结果同时展示容量与槽位、code unit 与 code point、浮点和特殊值边界，以及对象引用共享。把 `objectB` 改成 `{ items: [] }` 后重放，身份和 mutation 传播应出现可解释的差异。

## 四类样本与验收

| 样本 | 注入方式 | 必查证据 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 连续数组、普通字符串和有限数字 | 长度、值、计算结果 | 表面结果与基础 API 一致 |
| 边界 | 空槽、Unicode 表情、NaN、正负零 | 槽位、编码、特殊身份 | 使用专用 API 得到精确断言 |
| 失败 | 用普通相等或显示字符串替代边界检测 | 首个错误判断 | 明确指出误判来源，不传播错误结论 |
| 恢复 | 改用容差、Object.is 或显式复制后重放 | 新身份与新状态 | 旧别名、旧精度假设没有污染下一轮 |

本页签发不变量是：**值的表面相似不保证语义相同；槽位、编码、精度、特殊值和引用身份必须使用对应证据验证。** 最终输出不能替代长度、属性存在性、误差、身份和 mutation 轨迹。

## 练习

<Exercises>

1. 创建一个稀疏数组 `a`，只写入索引 2。使用 `length`、`in` 和 `Object.keys` 证明它不是一个包含三个实际元素的连续数组。

   <Answer>

   执行 `const a = []; a[2] = "x"` 后，`a.length` 为 3，`0 in a` 为假，`2 in a` 为真，`Object.keys(a)` 只有 `"2"`。length 是最高索引加一，不代表每个槽位都有属性。

   </Answer>

2. 比较 `"😀".length`、`Array.from("😀").length` 和 `"😀".codePointAt(0)`。说明为什么字符串的 length 不等于用户感知字符数量。

   <Answer>

   `"😀".length` 为 2，因为它由两个 UTF-16 code unit 组成；`Array.from("😀").length` 为 1，按 code point 计数；`codePointAt(0)` 返回完整的 Unicode code point。选择哪个结果取决于问题是处理存储单位还是用户感知字符。

   </Answer>

3. 构造一个浮点近似、一个 NaN、一个负零和一对对象别名，分别用容差、`Number.isNaN`、`Object.is` 和 `===` 验收，再注入一次 mutation。

   <Answer>

   用 `Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON` 做近似比较；用 `Number.isNaN(NaN)` 判断 NaN；用 `Object.is(-0, 0)` 观察正负零差异；用 `const b = a; a === b` 证明对象身份共享，再通过 `b.items.push(1)` 检查别名传播。

   </Answer>

## 小结

- **稀疏数组**：length 记录容量边界，不能替代槽位存在性。
- **字符串不可变性**：字符串值不能原地改写，且 length 按 UTF-16 code unit 计数。
- **浮点精度**：十进制运算可能是近似结果，验收要声明容差。
- **NaN**：不等于自身，使用 `Number.isNaN` 做检测。
- **值与引用**：原始值复制值，对象赋值共享引用身份。
- **专用边界 API**：让 `in`、`Array.from`、`Object.is` 等工具回答明确问题。

理解本章的关键不是背诵异常清单，而是能在每次操作中说明值的结构、边界、身份和适用的检测证据。
