## 直觉：先预测，再运行

String、Number、Boolean 等原生函数既可转换值也可作为构造器创建包装对象；属性访问会临时装箱，`valueOf` 与显式转换负责拆箱，二者不应混为同一类型。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：String 和 new String 只是两种写法">

现象：把 `String("42")` 与 `new String("42")` 都当成返回同一种字符串值的函数调用。

原因：普通调用执行转换，`new` 调用执行构造器并留下包装对象；两者的 `typeof`、身份和比较行为不同。

修复：分别记录 `typeof result`、`result instanceof String`、`result.valueOf()` 和 `result === "42"`。

</Callout>

<Callout type="trap" title="陷阱：原始值调用方法说明它已经变成对象">

现象：看到 `"hello".toUpperCase()` 能运行，就认为字符串变量已经保存了一个 String 包装对象。

原因：属性访问会提供短暂的装箱语义，让原型方法可以被找到和执行；这不等于持久改变原始值的身份。

修复：比较原字符串是否被修改，并用 `Object.getPrototypeOf` 检查真正被保存的值，不要从一次方法调用推断长期对象身份。

</Callout>

<Callout type="trap" title="陷阱：valueOf 和显式转换可以互相替代">

现象：把 `boxed.valueOf()`、`String(boxed)` 和 `Number(boxed)` 当成无条件相同的拆箱动作。

原因：valueOf 按包装对象的原生值返回结果，显式转换还会执行目标类型的转换规则，输入和目标类型不同就会得到不同语义。

修复：先写清楚目标是取回原始值还是转换成某种类型，再选择 valueOf、String、Number 或 Boolean，并记录异常边界。

</Callout>

<Callout type="info" title="观察法：先记录调用方式，再记录结果">

现象：只记录最后的字符串或数字，无法解释为什么某个值拥有身份、方法或不同的比较结果。

原因：原生函数的普通调用、属性访问和 new 构造器分别改变了转换、装箱和身份轨迹。

修复：每个样本同时记录调用形式、返回值、typeof、prototype、valueOf 和是否保留对象身份。

</Callout>

## 核心概念与状态所有权

<Term def="String、Number、Boolean 等由语言提供的函数；不带 new 时通常执行类型转换，带 new 时可能创建对应的包装对象。">原生函数</Term> 既有转换入口，也有构造器入口，不能只看函数名字推断路径。

<Term def="运行时用于描述值的内部分类信息；它帮助区分原始值、函数和包装对象，但不是业务代码应直接依赖的私有字段。">内部分类</Term> 是观察运行时形状的线索，不等于把所有对象都归为同一类型。

<Term def="原始值访问属性或方法时，运行时提供短暂对象语义以完成属性查找和调用；这个临时对象通常不会被用户变量保存。">装箱</Term> 解释了为什么原始字符串可以调用原型方法。

<Term def="从包装对象或可转换输入中取回原始值的过程；valueOf 和显式 String、Number、Boolean 调用可能参与其中。">拆箱</Term> 要结合目标类型和对象的转换协议解释。

<Term def="由 new String、new Number 或 new Boolean 创建的对象，拥有身份和原型关系，不能当成对应原始值的透明替代品。">包装对象</Term> 通常只在确实需要对象身份或属性时才应被保留。

<Term def="包装对象提供的取原始值方法；它通常返回对象内部保存的 primitive，但不负责替代所有目标类型转换规则。">valueOf 拆箱</Term> 是观察包装对象内部原始值的一个明确检查点。

这些概念要一起回答五个问题：输入由谁创建，调用是否带 `new`，值和身份保存在哪里，哪一步触发方法查找或转换，结束后由谁清理包装对象。只有把转换、临时装箱和持久构造分开，原生函数的行为才可复演。

| 观察量 | 本页判定方式 |
| --- | --- |
| 原生函数 | 对照普通调用和 `new` 调用的返回形状 |
| 内部分类 | 记录原始值、包装对象与方法来源的差异 |
| 装箱 | 观察原始值访问属性时的临时方法查找 |
| 拆箱 | 比较 `valueOf`、显式转换与原始值结果 |
| 包装对象 | 检查身份、prototype 和 `instanceof`，避免误当原始值 |
| valueOf 拆箱 | 明确它取回什么值，以及是否还需要目标类型转换 |

## 机制拆解

### 1. 取得原始值

原生函数不带 `new` 时，优先把它理解成转换器：`String(42)` 返回原始字符串，`Number("3.14")` 返回原始数字，`Boolean(0)` 返回原始布尔值。这条路径通常不会留下一个需要维护的包装对象。

验收时记录返回值、`typeof` 和身份比较。普通转换的重点是“得到哪一种 primitive”，而不是“创建了哪个构造器实例”。

### 2. 属性访问触发临时装箱

`"hello".toUpperCase()` 可以运行，是因为原始字符串在属性访问期间获得了短暂的对象语义，运行时得以查找 `String.prototype` 上的方法。方法执行结束后，用户变量仍保存原始字符串，不能据此推断它变成了包装对象。

同样的模式也适用于数字和布尔值的原型方法。临时装箱是解释属性访问的机制，不是一个应该长期保存并到处传递的对象。

### 3. 在原型上解析方法

临时对象需要找到 `toUpperCase`、`toFixed` 或其他方法时，会沿对应的原型关系查找。方法的来源是 `String.prototype`、`Number.prototype` 或 `Boolean.prototype`，不是每个原始值内部都复制了一份函数。

把方法来源记录下来，可以区分“原始值支持某个操作”和“变量保存一个包装对象”。这两个结论可能产生相同输出，却有不同的身份、属性和维护边界。

### 4. 以原始值作为接收者执行

原型方法执行时仍然要处理当前接收者。比如 `"hello".toUpperCase()` 读取的是当前字符串值；执行返回新字符串，不会原地修改原字符串。对数字原型方法也要记录输入值、结果值与是否产生新 primitive。

这个步骤提醒我们：方法来源和接收者不是一回事。方法可以在 prototype 上共享，而每次调用仍然针对当前原始值执行。

### 5. 需要时通过 valueOf 拆箱

`new String("hello").valueOf()` 返回原始字符串；`new Number(3).valueOf()` 返回原始数字。`valueOf` 是观察包装对象内部 primitive 的直接入口，但它不意味着所有转换都已完成。

如果目标是字符串、数字或布尔值，显式调用对应的 `String`、`Number` 或 `Boolean` 还会执行目标类型规则。先决定目标，再选择拆箱方式，才能避免把取值、转换和异常传播混在一起。

### 6. 避免长期保存包装对象

`new String("hello")` 创建的是有身份的对象：它有自己的 prototype，可以被 `===` 比较为不同于原始字符串的对象。长期保存这类包装对象会让相等判断、序列化、属性修改和团队认知成本变高。

除非确实需要对象身份或对象属性，否则优先保存原始值。若必须接收包装对象，先用 `valueOf` 或明确的显式转换取得目标 primitive，再在边界处验证结果。

## 目录主题逐项讲解

### Chapter 3: Natives

**Chapter 3: Natives** 的主线是同一个名字对应两条不同调用路径：普通调用负责转换，`new` 负责构造。先把调用方式写在样本旁，再追踪返回值和身份。

### Internal [[Class]]

**Internal [[Class]]** 提醒我们观察运行时分类和内部形状，但不要把历史内部术语当成业务代码可直接读取的属性。现代代码应使用公开 API 验收可观察行为。

### Boxing Wrappers

**Boxing Wrappers** 解释原始值为何能访问原型方法。临时装箱支持一次属性访问，不代表变量持久保存包装对象。

### Unboxing

**Unboxing** 把包装对象的内部 primitive 重新带回比较、计算或传递流程。`valueOf` 是一个观察点，显式转换则可能继续改变目标类型。

### Natives as Constructors

**Natives as Constructors** 强调 `new String`、`new Number` 和 `new Boolean` 会保留对象身份。构造器路径只有在确实需要对象语义时才值得承担。

## 六阶段证据链

本页的可执行链条是：取得原始值 → 属性访问触发临时装箱 → 在原型上解析方法 → 以原始值作为接收者执行 → 需要时通过 `valueOf` 拆箱 → 避免长期保存包装对象。正常样本证明转换主路径，边界样本证明原始值与包装对象的身份差异，失败样本定位错误的构造器或转换输入，恢复样本证明改用明确 primitive 后没有旧 wrapper 污染。

## 最小可运行实验

下面的片段只保留本章最小机制。运行前先预测调用方式、返回类型、方法来源和身份，再修改一个条件观察首个偏离点：

```js
const primitive = "hello";
const converted = String(42);
const boxed = new String(primitive);

console.log(typeof primitive, primitive.toUpperCase());
console.log(typeof converted, converted === "42");
console.log(typeof boxed, boxed instanceof String, boxed.valueOf());
console.log(boxed === primitive, boxed.valueOf() === primitive);
```

预期结果是：原始字符串可调用原型方法，普通 `String` 调用返回 primitive，`new String` 返回对象，包装对象与原始字符串身份不同但 `valueOf()` 可以取回相同文本。

| 样本 | 注入方式 | 必查证据 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | `String(42)`、`Number("3.14")` | 调用方式、返回值、typeof | 普通调用返回目标 primitive |
| 边界 | `"hello".toUpperCase()` 与 `new String("hello")` | 临时装箱、prototype、身份 | 能区分临时方法访问与持久 wrapper |
| 失败 | 错把 wrapper 当 primitive 或对错误输入做 Number 转换 | 首个错误断言与异常/NaN | 明确记录失败，不继续传播假身份 |

本页签发不变量是：**普通原生函数调用负责转换，属性访问可以临时装箱，`new` 才留下包装对象；拆箱和目标类型转换必须分别记录。** 最终输出不能替代调用方式、方法来源、接收者和对象身份的完整轨迹。

## 练习

<Exercises>

1. 比较 `String("42")` 与 `new String("42")` 的 `typeof`、`instanceof String`、`valueOf()` 和相等行为，写出两条调用路径的差异。

   <Answer>

   `String("42")` 返回原始字符串，`typeof` 为 `string`，不是 `String` 实例；`new String("42")` 返回对象，`typeof` 为 `object`，`instanceof String` 为真，但 `valueOf()` 返回原始字符串。包装对象与原始字符串不是同一身份，不能只看最终文本判断相同。

   </Answer>

2. 让一个原始字符串调用 `toUpperCase`，再检查原字符串是否改变，并指出方法来自哪个原型。为什么这不证明变量保存了包装对象？

   <Answer>

   `const text = "hello"; const result = text.toUpperCase();` 得到新字符串 `"HELLO"`，原 `text` 仍为 `"hello"`。方法来自 `String.prototype`；属性访问提供的是临时装箱语义，变量本身仍保存原始字符串。

   </Answer>

3. 创建 `new Number("3.14")` 和 `new Boolean(0)`，分别用 `valueOf`、显式转换和 `===` 检查它们。记录什么时候得到 primitive，什么时候仍保留 wrapper identity。

   <Answer>

   `numberBox.valueOf()` 得到数字 primitive，`Number(numberBox)` 也得到数字；`booleanBox.valueOf()` 得到布尔 primitive，`Boolean(booleanBox)` 则遵循对象真值规则。原对象与这些 primitive 的 `===` 不会因为文本或数值相同而变成同一身份。

   </Answer>

</Exercises>

## 小结

- **原生函数**：不带 `new` 时通常执行转换，带 `new` 时可能创建包装对象。
- **内部分类**：帮助观察原始值与包装对象的运行时形状，但不应当作私有字段依赖。
- **装箱**：原始值访问属性时获得的短暂对象语义。
- **拆箱**：从包装对象或转换输入取得目标 primitive 的过程。
- **包装对象**：有身份和 prototype 的 String、Number、Boolean 对象。
- **valueOf 拆箱**：读取包装对象内部 primitive 的明确检查点。

理解本章的关键不是记住“所有东西都是对象”，而是能说明一次调用到底是转换、临时装箱还是持久构造，并能在边界处验证返回值和身份。
