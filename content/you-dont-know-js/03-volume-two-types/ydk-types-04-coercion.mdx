## 直觉：先预测，再运行

强制类型转换由 ToPrimitive、ToString、ToNumber、ToBoolean 等抽象操作组成；显式与隐式转换共享这些规则，宽松相等比较类型转换后的值而非简单忽略类型。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：强制转换就是把类型标签换一下">

现象：看到 `1 + "2"` 得到 `"12"`，就认为 JavaScript 只是把数字标签改成字符串。

原因：转换是由运算符和抽象操作共同决定的过程，可能先取原始值，再选择 ToString 或 ToNumber，最后才执行运算。

修复：把运算符、操作数原始类型、中间 primitive、目标抽象操作和最终结果分栏记录。

</Callout>

<Callout type="trap" title="陷阱：宽松相等只是忽略类型，严格相等只是更严格的宽松相等">

现象：把 `"42" == 42` 当成“忽略类型”，再把 `===` 理解成同一套规则的更高门槛。

原因：`==` 可能递归触发类型转换，而 `===` 不进行这类隐式转换；两者回答的是不同的验收问题。

修复：同时记录两侧值、转换路径和比较运算符，先问“是否允许转换”，再选择相等形式。

</Callout>

<Callout type="trap" title="陷阱：对象参与运算时一定直接变成字符串">

现象：看到对象与字符串或数字运算，就跳过 valueOf、toString 和 ToPrimitive 的顺序。

原因：对象需要先提供原始值，最终走字符串还是数字路径取决于运算符、hint 和返回值。

修复：给对象加入可观测的 valueOf/toString，记录哪一个先被调用，再重放显式 String、Number 和隐式运算。

</Callout>

<Callout type="info" title="观察法：显式样本先行，隐式样本后验">

现象：一上来只研究复杂的 `==` 或加法，结果记住了几个反例却无法迁移。

原因：没有先建立 ToString、ToNumber、ToBoolean 的单步基线，隐式规则就没有可对照的中间证据。

修复：先分别运行显式转换，再把同样的值放入运算符和比较中，对照转换前后状态解释差异。

</Callout>

## 核心概念与状态所有权

<Term def="把对象或其他值转换为原始值的抽象步骤；对象通常通过 valueOf 或 toString 提供 primitive。">ToPrimitive</Term> 是许多后续转换的入口，而不是最终目标类型本身。

<Term def="把输入转换成字符串的抽象规则；它会处理 undefined、null、布尔值、数字、字符串和对象的原始值。">ToString</Term> 解释字符串拼接和显式 String 调用的共同部分。

<Term def="把输入转换成数字的抽象规则；空白字符串、布尔值、null 和无法解析的文本会落到不同结果。">ToNumber</Term> 是数值运算、显式 Number 和一元加号的重要证据。

<Term def="把输入转换成布尔值的抽象规则；对象通常为真，零、空字符串、null、undefined 和 NaN 等值会落到假分支。">ToBoolean</Term> 决定条件位置和显式 Boolean 调用的结果。

<Term def="允许不同类型操作数在比较前按规则转换的相等算法；它可能递归应用 ToPrimitive、ToString 或 ToNumber。">抽象相等</Term> 对应 `==`，不是“什么都不检查”。

<Term def="把值放入具体运算符或比较中时实际发生的转换过程；显式写在代码里，隐式由运算符触发，但二者可以共享抽象规则。">隐式转换轨迹</Term> 要通过操作数和中间值而不是结果猜测。

这些概念要一起回答五个问题：运算符是什么，操作数的原始类型是什么，对象是否先提供 primitive，目标抽象操作是什么，最终运算和比较如何消费结果。只记录末尾布尔值，会丢掉最重要的转换路径。

| 观察量 | 本页判定方式 |
| --- | --- |
| ToPrimitive | 给对象注入可观测 valueOf/toString，记录原始值来源 |
| ToString | 对数字、布尔值、null 和对象执行显式字符串转换 |
| ToNumber | 对文本、空白、布尔值和 null 执行显式数字转换 |
| ToBoolean | 对零、空字符串、对象和 NaN 验证条件结果 |
| 抽象相等 | 比较 `==` 与 `===` 的转换差异和中间值 |
| 隐式转换轨迹 | 将运算符、操作数、目标类型、结果按顺序保存 |

## 机制拆解

### 1. 读取运算符与操作数类型

转换分析从运算符开始。`+` 既可以做数值加法，也可以做字符串拼接；`==` 与 `===` 的算法不同；关系比较还要看双方是否都是字符串。相同的值放进不同运算符，转换路径可能完全不同。

因此先写一张操作数表：左值、右值、运算符、当前类型和是否为对象。不要一看到结果是字符串就跳过操作数读取；结果只是最后一个证据点。

### 2. 必要时把对象转为原始值

对象不能直接作为数值或字符串参与大多数抽象运算，需要先通过 ToPrimitive 找到 primitive。这个过程可能调用 `valueOf` 或 `toString`，并且对象自定义这些方法时，调用顺序本身就是可观察证据。

用一个带日志的对象重放 `obj + 1`、`String(obj)` 和 `Number(obj)`，你会看到同一个对象在不同 hint 或目标类型下可能提供不同原始值。不要把“对象最终显示成什么”当成 ToPrimitive 的完整解释。

### 3. 按抽象操作转换目标类型

ToString、ToNumber 和 ToBoolean 是不同的目标规则。`Number("42")` 与 `Boolean("42")` 都显式写出意图，但结果分别是数字 42 和布尔真；空字符串、空白字符串、null、undefined 和 NaN 还会揭示边界差异。

先独立验证目标转换，再把值放进隐式运算。这样当 `1 + "2"` 走字符串路径时，可以指出它与 `Number("2")` 的结果不同，而不是把所有规则归结为“JavaScript 很奇怪”。

### 4. 执行数值、字符串或布尔运算

显式转换适合把意图固定在代码中：`String(value)`、`Number(value)`、`Boolean(value)` 和 `+value` 都可以作为单步样本。隐式转换发生在运算符内部，仍然要回到相同的抽象规则理解。

例如 `1 + "2"` 的结果是字符串拼接，而 `1 - "2"` 会尝试走数值路径。用同一组操作数换运算符，正好可以证明运算符是转换路径的一部分。

### 5. 对宽松相等递归应用规则

`"42" == 42` 为真，不是因为比较器无视类型，而是算法允许一侧转换后继续比较。`"42" === 42` 为假，因为严格相等要求类型和值都符合，不进行这类隐式转换。

宽松相等遇到对象、null、undefined、NaN 或布尔值时还有更多边界。验收时不要只收集 true/false；至少保留两侧原始值、是否触发转换、转换后的值和运算符。

### 6. 保留转换前后证据

转换轨迹是一个时间序列：原始操作数 → ToPrimitive → 目标转换 → 运算或比较 → 最终值。显式样本可以逐步拆开，隐式样本则要用可观测对象方法或对照运算验证猜测。

恢复样本应在同一输入上换成显式转换或严格相等，再重放一次。若结论改变，要说明是转换意图改变，而不是把第一次结果当成稳定类型事实。

## 目录主题逐项讲解

### Chapter 4: Coercion

**Chapter 4: Coercion** 的主线是把“类型变化”还原成抽象操作链。先建立显式转换基线，再把同一组值放入运算符、相等和关系比较中。

### Converting Values

**Converting Values** 关注把一个值有意转换到目标表示。记录输入、目标类型、结果和异常边界，比背诵一张真假表更可靠。

### Abstract Value Operations

**Abstract Value Operations** 把 ToPrimitive、ToString、ToNumber、ToBoolean 视作可追踪的规则节点。它们不是魔法词，而是解释中间值的坐标。

### Explicit Coercion

**Explicit Coercion** 把意图写在 `String`、`Number`、`Boolean` 或一元运算中，适合建立单步可验收的转换样本。

### Implicit Coercion

**Implicit Coercion** 由运算符和比较器触发。隐式不等于不可解释；只要保留运算符和中间值，它仍然能还原为抽象规则。

### Loose Equals vs Strict Equals

**Loose Equals vs Strict Equals** 不是“宽松版本与严格版本”的简单强弱关系。`==` 允许特定转换，`===` 不允许这类转换，选择应由问题的契约决定。

### Abstract Relational Comparison

**Abstract Relational Comparison** 处理小于、大于等关系运算。双方都是字符串时可能按字典序比较，至少一侧走数字路径时则要记录转换后的数值。

## 七阶段证据链

本页的可执行链条是：读取运算符与操作数类型 → 必要时把对象转为原始值 → 按抽象操作转换目标类型 → 执行数值、字符串或布尔运算 → 对宽松相等递归应用规则 → 保留转换前后证据。关系比较作为横向复核，要求同样记录操作数、目标路径和最终布尔值。

## 最小可运行实验

下面的片段只保留本章最小机制。运行前先预测每一行的运算符、操作数类型、中间转换和输出，再修改一个条件观察首个偏离点：

```js
const objectValue = {
  valueOf() {
    return 2;
  },
  toString() {
    return "object-value";
  },
};

console.log(String(42), Number("42"), Boolean(""));
console.log(1 + "2", 1 - "2");
console.log("42" == 42, "42" === 42);
console.log(objectValue + 1, String(objectValue));
console.log("2" < "10", 2 < 10);
```

预期结果应同时体现显式转换、加法与减法的路径差异、宽松与严格相等的差异、对象 ToPrimitive 以及字符串关系比较。若只保留最后的 true/false，就无法解释每行为何不同。

## 四类样本与验收

| 样本 | 注入方式 | 必查证据 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 显式 String、Number、Boolean 转换 | 输入、目标类型、结果 | 每条显式规则独立可解释 |
| 边界 | 对象 valueOf、字符串加法、空值与 NaN | ToPrimitive、目标转换和运算符 | 中间值与边界结果完整记录 |
| 失败 | 把 `==` 当成忽略类型，或把字符串关系比较当数字比较 | 首个错误路径 | 明确指出误判的抽象操作 |
| 恢复 | 改用显式转换、`===` 或显式数字比较后重放 | 新路径与结果 | 意图清晰，旧的隐式假设不再污染 |

本页签发不变量是：**显式和隐式转换共享抽象规则；宽松相等允许特定转换，严格相等不进行这类转换；关系比较也必须保留中间值。** 最终结果不能替代运算符、操作数、目标类型和转换顺序。

## 练习

<Exercises>

1. 分别计算 `Number("42")`、`String(42)`、`Boolean(0)` 和 `+"3.5"`，为每个结果写出目标抽象操作与返回类型。

   <Answer>

   `Number("42")` 和 `+"3.5"` 走 ToNumber，分别返回数字 42 和 3.5；`String(42)` 走 ToString，返回字符串 `"42"`；`Boolean(0)` 走 ToBoolean，返回假。每个样本都把目标类型写在语法中，便于独立验收。

   </Answer>

2. 为对象实现 `valueOf` 返回 2、`toString` 返回 `"object-value"`，比较 `object + 1`、`String(object)` 和 `Number(object)`。记录每种表达式的 ToPrimitive 与目标转换路径。

   <Answer>

   `object + 1` 会先要求对象提供 primitive，结果可能走数值或字符串相关路径，必须通过日志确认；`String(object)` 目标是 ToString，`Number(object)` 目标是 ToNumber。答案的关键不是背一个固定顺序，而是记录实际调用的 valueOf/toString 和最终目标类型。

   </Answer>

3. 对照 `"42" == 42`、`"42" === 42`、`"2" < "10"` 和 `2 < 10`。说明哪几行允许转换，以及为什么关系比较的两个结果可以不同。

   <Answer>

   `==` 允许按规则把不同类型的操作数转换后比较，`===` 不做这类隐式转换；因此前两行的结果不同。两个字符串进行关系比较时可能按字典序判断，数字操作数则走数值比较，所以 `"2" < "10"` 与 `2 < 10` 不必相同。

   </Answer>

</Exercises>

## 小结

- **ToPrimitive**：对象参与转换时取得 primitive 的入口。
- **ToString**：把值按字符串规则转换，显式 String 和字符串路径会用到它。
- **ToNumber**：把值按数字规则转换，Number、减法和数值比较会用到它。
- **ToBoolean**：把值按真假规则转换，条件和显式 Boolean 会用到它。
- **抽象相等**：`==` 允许特定的递归转换，`===` 不做这类转换。
- **隐式转换轨迹**：把运算符触发的幕后步骤按顺序记录下来。

理解强制类型转换的关键不是避免所有隐式行为，而是知道什么运算符触发什么抽象操作，并把中间值写成可复核证据。
