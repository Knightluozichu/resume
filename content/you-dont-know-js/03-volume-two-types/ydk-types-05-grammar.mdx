## 直觉：先预测，再运行

语法不是排版规则。**表达式**产生值，**语句**组织控制流；解析器先确定结构，运行时才按结构产生结果。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：运算符按书写顺序从左到右执行">

现象：看到 `1 + 2 * 3`，就先做加法，再把结果乘以 3。

原因：解析器按照优先级与结合性建立结构，求值顺序受表达式树支配，而不是只看字符出现顺序。

修复：先画出 `1 + (2 * 3)`，再用 `(1 + 2) * 3` 做对照，把分组证据和最终值同时记录。

</Callout>

<Callout type="trap" title="陷阱：每一次换行都会自动插入分号">

现象：把换行当成无条件的语句终止，或认为 `return` 下一行的对象字面量一定会被返回。

原因：ASI 只在特定语法无法继续、到达受限产生式或文件结尾等条件下发挥作用；缩进不是语法规则。

修复：把 `return\n{ value: 1 }` 与 `return { value: 1 }` 并排运行，记录语句边界和完成值。

</Callout>

<Callout type="trap" title="陷阱：finally 只是清理，不会改变 return 或 throw">

现象：认为 `try` 中已经 `return 1`，所以 `finally` 只能打印日志，结果忽略了它可以再次 `return` 或 `throw`。

原因：`finally` 执行后会消费并可能覆盖先前的完成记录；新的 return、throw 或异常会成为外层看到的结果。

修复：分别测试 finally 正常结束、再次 return 和再次 throw，比较外层收到的完成类型与值。

</Callout>

<Callout type="trap" title="陷阱：switch 命中 case 后必然只执行一个分支">

现象：只找到匹配的 `case` 就停止推理，没有检查 `break` 或后续语句是否贯穿。

原因：switch 的匹配负责找到入口，break 才负责离开 switch；缺少 break 时控制流可以继续执行后续 case。

修复：为同一输入分别加入和移除 `break`，记录每个 case 的进入、执行和退出原因。

</Callout>

## 核心概念与状态所有权

<Term def="可以嵌套并产生值的语法结构，例如字面量、调用、成员访问和运算组合。">表达式</Term> 的所有权在语法树节点：节点保存操作数与运算符，求值后把值交给外层节点。

<Term def="改变控制流或声明绑定的语法结构，例如 if、return、throw、switch 和块。">语句</Term> 的所有权在执行上下文：上下文消费语句并产生正常、return、throw、break 或 continue 等完成类型。

<Term def="决定表达式树如何分组的规则；高优先级运算通常先成为低优先级运算的子节点，同级运算再由结合性决定方向。">运算符优先级</Term> 负责把字符序列变成可解释的结构，而不是直接替代求值。

<Term def="解析器在特定语法边界隐式补入分号的规则；它受受限产生式、无法继续解析和文件结束等条件限制。">自动分号插入</Term> 只能通过语法边界验证，不能用换行数量推断。

<Term def="语句执行结束时携带的完成类型、值和目标的记录；return、throw、break 与正常完成会沿控制流以不同方式传播。">完成记录</Term> 是解释 return、异常传播和 switch 退出的共同证据。

<Term def="finally 执行后对 try 或 catch 既有完成记录形成的最终覆盖结果；finally 内新的 return 或 throw 可以替换先前结果。">finally 完成值</Term> 由外层最终观察，不能只看 try 块里的 return。

这些概念要一起回答五个问题：输入由谁解析，结构如何分组，哪条语句产生完成记录，哪个边界改变传播，最后由谁消费结果。只记录最后的数字或字符串，会丢掉语法和控制流的所有权关系。

| 观察量 | 本页判定方式 |
| --- | --- |
| 表达式 | 对 `1 + 2 * 3` 画出树并说明每个子表达式的值 |
| 语句 | 对 `return`、`throw`、`break` 标出完成类型与消费方 |
| 运算符优先级 | 对加法、乘法和括号比较两棵不同表达式树 |
| 自动分号插入 | 对 return 后换行样本标出语句边界和返回值 |
| 完成记录 | 记录正常、return、throw、break 的传播路径 |
| finally 完成值 | 比较 finally 正常结束、return、throw 三种覆盖结果 |

## 机制拆解

### 1. Chapter 5: Grammar

**Chapter 5: Grammar** 的主线是把源码从字符序列还原为语法结构，再解释结构如何产生完成记录。解析阶段先识别表达式、语句、块和控制流入口；运行阶段才消费这些节点。

第一条证据是结构而不是输出。`1 + 2 * 3` 的树应体现乘法成为加法右侧子树；`(1 + 2) * 3` 则把加法整体提升。两者都能运行，却不是同一语法。

### 2. Statements & Expressions

**Statements & Expressions** 的区别在于结果的消费方式。表达式可以把值交给调用、赋值或更大的表达式；语句则可以建立块、跳转、返回或抛出完成记录。

把 `const value = 1 + 2` 和 `return 1 + 2` 并排观察：右侧 `1 + 2` 都是表达式，但声明与 return 是不同语句，前者把值绑定到环境，后者把完成记录交给函数调用者。

### 3. Operator Precedence

**Operator Precedence** 决定表达式树的分组，结合性处理同一优先级的重复运算。优先级不是“更早打印结果”的口号，而是确定哪个节点先成为哪个节点的子节点。

用 `1 + 2 * 3`、`(1 + 2) * 3` 与 `10 - 3 - 2` 做三次对照：前两次验证括号改变树，第三次验证同级减法的结合方向。答案应包含树形分组和求值路径，而不只是 7、9、5 三个数字。

### 4. Automatic Semicolons

**Automatic Semicolons** 只在语法需要边界时介入。`return`、`break`、`continue` 等受限位置尤其值得做边界实验，因为换行可能让下一行不再属于同一语句。

比较下面两段：

```js
function explicitReturn() {
  return { value: 1 };
}

function restrictedReturn() {
  return
  { value: 1 };
}
```

第一段把对象字面量作为 return 表达式；第二段在 `return` 后换行，函数先完成返回，后面的块不再成为返回表达式。缩进相同并不代表语法结构相同。

### 5. Errors

**Errors** 不是普通字符串值。解析错误会阻止程序形成可执行结构，运行时 throw 则产生异常完成记录；try/catch/finally 决定记录是否被捕获、替换或继续传播。

故障注入时分开记录“解析阶段无法继续”和“运行阶段主动 throw”。前者没有可消费的函数体，后者已有执行上下文但改变了完成类型。把两者都称作“报错”会掩盖恢复边界。

### 6. Function Arguments

**Function Arguments** 在函数调用入口建立参数绑定。位置参数、默认参数与剩余参数都属于入口规则；函数体中的 `arguments` 则是另一种观察调用输入的方式，不能用一个数组输出替代所有绑定关系。

用 `function f(a = 1, ...rest) { return [a, rest]; }` 分别调用 `f()`、`f(0)` 和 `f(1, 2, 3)`。记录 `a` 的默认值是否触发、rest 收集了什么，以及返回完成记录由谁消费。

### 7. try..finally

**try..finally** 的关键是完成记录的传播与覆盖。try 正常结束时 finally 仍会执行；try 中的 return、throw 或 break 也必须先经过 finally。若 finally 自己产生新的 return 或 throw，外层通常只看到新记录。

```js
function finalValue() {
  try {
    return "try";
  } finally {
    return "finally";
  }
}
```

这个函数返回 `"finally"`，因为 finally 的 return 覆盖了 try 的 return。工程代码通常让 finally 做清理而不再次 return，这样更容易保留原始错误或返回值。

### 8. switch

**switch** 先计算判别式并匹配 case，再从匹配位置开始执行语句列表。`break` 负责离开 switch；没有 break 时，控制流可能贯穿到后续 case，直到遇到 break 或 switch 结束。

因此测试 switch 至少要有命中、未命中、命中后 break 和命中后贯穿四种样本。每种样本记录 case 匹配、实际执行的语句和退出原因，不能只记录最后一个字符串。

## 七阶段证据链

本页的可执行链条是：解析源码 → 建立表达式树 → 在受限产生式处理换行 → 执行语句并产生完成记录 → 建立函数参数绑定 → 进入 finally 处理既有记录 → 由 switch 或外层控制流消费结果。正常样本证明主路径，边界样本证明语法容量，失败样本定位停止点，恢复样本证明旧完成记录没有污染下一次执行。

## 最小可运行实验

下面的片段只保留本章最小机制。运行前先预测每一行的语法结构、参数绑定、完成类型与输出，再修改一个条件观察首个偏离点：

```js
function inspect(input = "ok", ...rest) {
  try {
    switch (input) {
      case "ok":
        return 1 + rest.length * 2;
      default:
        throw new Error("unknown input");
    }
  } finally {
    console.log("cleanup", input);
  }
}

console.log(inspect("ok", "extra"));
```

预期轨迹是：参数入口绑定 `input` 与 `rest`；switch 命中 `case "ok"`；表达式按优先级计算 `1 + (rest.length * 2)`；return 形成完成记录；finally 打印清理信息后，原 return 继续传播。若把 finally 改成 `return 0`，就能观察覆盖结果。

## 四类样本与验收

| 样本 | 注入方式 | 必查证据 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 带括号的表达式、显式 return、带 break 的 switch | 语法树、完成类型、退出原因 | 结构与主路径都能解释 |
| 边界 | return 后换行、无 break、默认参数与空 rest | 语句边界、贯穿路径、参数绑定 | 不把缩进或空数组当成规则 |
| 失败 | 解析不完整、运行时 throw、finally 再次 throw | 首个停止点与异常完成 | 明确区分解析失败和运行时传播 |
| 恢复 | 修复括号、补上 break、移除 finally 中的 return 后重放 | 新树、新完成记录、旧状态清理 | 原错误不污染下一次执行 |

本页签发不变量是：**表达式产生值、语句组织控制流；优先级与结合性决定分组；ASI 只在受限边界发挥作用；finally 可以覆盖先前的 return 或 throw；switch 的 break 决定是否退出。** 最终输出、单次截图或一个错误消息都不能替代语法树与完成记录的完整轨迹。

## 练习

<Exercises>

1. 分别画出 `1 + 2 * 3`、`(1 + 2) * 3` 和 `10 - 3 - 2` 的表达式树，并写出每一步求值顺序。

   <Answer>

   第一段分组为 `1 + (2 * 3)`，先得到 6，再得到 7；第二段分组为 `(1 + 2) * 3`，先得到 3，再得到 9；第三段按左结合分组为 `(10 - 3) - 2`，结果是 5。括号和结合性都改变了结构证据，不能只比较最终数字。

   </Answer>

2. 比较 `return { value: 1 }` 与 `return` 后换行再写对象块的行为；再为一个 `switch` 样本分别加入和移除 `break`，记录语句边界与执行路径。

   <Answer>

   同一行的 return 把对象字面量作为表达式返回；return 后换行会在受限位置结束 return，函数先返回 undefined，下一行的花括号不再属于返回表达式。switch 命中后有 break 会退出，没有 break 则继续执行后续 case，直到新的 break 或 switch 结束。

   </Answer>

3. 解释下面函数为什么返回 `"finally"`，并把 finally 中的 return 改为日志语句，比较两次调用者观察到的完成值。

   ```js
   function result() {
     try {
       return "try";
     } finally {
       return "finally";
     }
   }
   ```

   <Answer>

   try 先产生 return 完成记录，但 finally 一定执行；finally 又产生 return，因此新的完成记录覆盖旧记录，调用者得到 `"finally"`。如果 finally 只打印日志而正常结束，try 的 return 才会继续传播，调用者得到 `"try"`。

   </Answer>

</Exercises>

## 小结

- **表达式与语句**：前者提供值，后者组织控制流并产生完成记录。
- **运算符优先级**：先决定表达式树分组，再谈求值顺序与结果。
- **自动分号插入**：只在特定语法边界介入，换行和缩进不是充分证据。
- **函数参数**：调用入口建立位置、默认与 rest 绑定，函数体消费这些绑定。
- **try..finally**：finally 总会执行，其中新的 return 或 throw 可以覆盖先前记录。
- **switch**：case 负责匹配入口，break 负责退出，缺失 break 会形成贯穿。

理解语法的关键不是背诵“哪一行会报错”，而是把源码、语法树、完成记录和控制流写成可复核的证据链。
