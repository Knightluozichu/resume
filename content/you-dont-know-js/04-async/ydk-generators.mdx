## 直觉引入

普通函数一旦调用就一口气执行到 `return` 或末尾，中间停不下来。**生成器**（`function*`）打破了这条规则：它可以在 `yield` 处暂停、把值产出去，等下一次 `next()` 调用时从暂停处恢复继续。这让生成器能「按需生产」一个序列——惰性求值，用一次算一次，省内存。更妙的是，生成器天然满足**迭代器协议**：每次 `next()` 返回 value/done 结果对象，所以生成器对象可以直接被 `for...of`、展开语法 `...`、解构消费。生成器还能双向通信——`next(v)` 把 `v` 注入回生成器作为上一个 `yield` 的返回值。这套「暂停恢复 + 双向通信」正是 `async/await` 的机制原型。

## 生成器与迭代器协议

<Term def="迭代器协议要求对象实现 next() 方法，返回 value/done 结果。生成器（function*）是创建迭代器的便捷语法，yield 暂停并产出值，next(v) 恢复执行并把 v 注入为上一个 yield 的返回值。可迭代协议要求对象实现 [Symbol.iterator]() 返回迭代器，for...of/展开/解构都消费它。">迭代器协议</Term>是生成器的基础。生成器函数 `function* gen()` 调用后不立即执行，而是返回一个迭代器对象；首次 `next()` 启动执行到第一个 `yield` 暂停，返回 value 为产出值、done 为 false 的结果；再次 `next(v)` 从暂停处恢复，`v` 成为该 `yield` 表达式的返回值，继续到下一个 `yield`；遇到 `return` 或结束返回 value 为返回值、done 为 true 的结果。生成器对象同时满足可迭代协议（它的 `[Symbol.iterator]` 返回自身），所以能被 `for...of` 直接遍历。数组、字符串、Map、Set、arguments 都是可迭代对象——它们的 `[Symbol.iterator]` 返回迭代器。

```javascript
// 生成器：暂停恢复 + 双向通信
function* dialog() {
  const name = yield "你叫什么？"; // next("Tom") 的 "Tom" 成为 yield 返回值
  return `你好，${name}`;
}
const it = dialog();
it.next();        // { value: "你叫什么？", done: false }
it.next("Tom");   // { value: "你好，Tom", done: true }

// 惰性序列：无限自然数，按需取
function* naturals() { let n = 1; while (true) yield n++; }
const nums = naturals();
nums.next().value; // 1
nums.next().value; // 2 —— 不主动算就永远停在 n=2，省内存

// for...of 消费可迭代对象（底层调 [Symbol.iterator]）
for (const x of [1, 2, 3]) console.log(x);   // 数组可迭代
for (const ch of "hi") console.log(ch);      // 字符串可迭代
const [a, b] = new Set([1, 2]);              // Set 可迭代，解构
const arr = [...function* () { yield 1; yield 2; }()]; // 生成器可迭代
```

## 生成器驱动的异步

生成器最深刻的应用是驱动异步：让生成器 `yield` 一个 Promise，外部运行器等它 resolve 后把结果 `next(result)` 回灌进生成器，这样就能用「同步顺序」的写法表达异步流程——这是 `async/await` 的前身。`await x` 在机制上等价于「`yield` 一个 Promise + 运行器自动等其 resolve 并回灌结果」。理解这一点，就能明白 `await` 为何是「让出主线程」而非「阻塞」：生成器在 `yield` 时挂起返回控制权，Promise resolve 后运行器把回调（恢复生成器）推入微任务队列，主线程从未被卡住。

## 常见误区

<Callout type="trap">
**误区：生成器只是个语法糖，用普通函数也能实现。** 形式上能模拟，但生成器的「暂停恢复」是语言级能力，普通函数无法在中间暂停把控制权交还调用者再恢复。普通函数调用是「调用→执行→返回」一气呵成，栈帧在返回时销毁；生成器在 yield 时冻结整个执行上下文（局部变量、执行位置），next 时恢复，这种「可中断的执行状态」普通函数做不到。这也是为什么生成器能实现无限序列（惰性求值）、能驱动异步（yield Promise 暂停等待）——这些都需要「暂停时保留状态」的能力。理解生成器的暂停恢复，才能理解 await 的让出主线程和协程式并发。
</Callout>

<Exercises>
**问题 1**：生成器的 `next(v)` 中 `v` 起什么作用？value/done 各代表什么？

<Answer>
next(v) 的 v 是「注入」回生成器的值，它成为上一个 yield 表达式的返回值，实现双向通信。流程：首次 next() 启动生成器执行到第一个 yield 暂停，返回 value 为 yield 产出的值、done 为 false 的结果；第二次 next(v) 从暂停处恢复，v 作为第一个 yield 的返回值赋给左侧变量，继续执行到第二个 yield 暂停，返回新的 value/done 结果；遇到 return 或函数结束时，value 是 return 的值或 undefined，done 为 true。value 是本次产出/返回的值，done 表示生成器是否已结束。注意首次 next() 传参无意义（没有上一个 yield 接收），要传初始值通常用生成器函数参数。
</Answer>

**问题 2**：`for...of`、展开语法 `...`、解构 `[a,b] = x` 底层如何工作？生成器为何能被它们消费？

<Answer>
它们底层都消费可迭代协议：调用对象的 [Symbol.iterator]() 方法获取迭代器，然后反复调用迭代器的 next() 直到 done 为 true。for...of 每轮把 value 赋给循环变量；展开语法把每个 value 收集进新数组；解构按位置取前几个 value。生成器能被消费是因为它同时满足两个协议：①迭代器协议——生成器对象有 next() 方法，返回 &#123;value, done&#125;；②可迭代协议——生成器对象的 [Symbol.iterator]() 返回自身。所以生成器对象天然是可迭代对象，能被 for...of/展开/解构直接消费。这也意味着生成器是一次性的：遍历完后 done 为 true，不能重复遍历，需重新调用生成器函数创建新迭代器。
</Answer>
