## 直觉：先预测，再运行

asynquence 可以看成一套把异步合作写成“可组合序列”的历史工具：普通步骤按顺序接力，多个分支可以并行，gate 可以等待若干完成信号，失败可以沿统一通道传播。它的价值不在一个特殊的库名，而在于把时序、完成和错误边界写成可观察的契约。

这套抽象不能被简单地当成现代 Promise 的无条件替代。阅读附录时，要同时追踪每个操作的状态所有权、回调或结果的消费位置、重复完成的处理、分支清理和与原生能力的桥接方式。只要这些边界没有被保留，表面相同的链式写法就可能表达不同语义。

先预测：顺序步骤怎样传值，两个分支何时释放 gate，某一分支拒绝后谁消费错误，桥接到 Promise 后是否仍然只完成一次。记录预期后再切换样本，比较第一个偏离点。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：序列只是把回调换成点号调用">

现象：看到链式 API 就只关心最后的值，忽略每一步何时启动、谁拥有状态和错误在哪里结束。

原因：组合库的核心是完成协议与顺序契约；表面链条可能隐藏异步启动、一次完成和清理边界。

修复：给每一步记录输入、输出、启动时机、错误消费者和结束状态，再与原生 Promise 链逐项对照。

</Callout>

<Callout type="trap" title="陷阱：gate 会自动取消剩余分支并保证资源清理">

现象：一个并行分支失败后，直接认为其他分支已经停止，或把 gate 释放当成所有任务都已经回收。

原因：gate 通常只表达“收集若干完成信号”的条件；取消、超时、Worker 终止和文件关闭需要额外协议。

修复：为每个分支保存请求 id 和清理函数，分别验证成功、拒绝、超时、重复 signal 与迟到结果。

</Callout>

<Callout type="trap" title="陷阱：任意 then 链都能无损替代历史组合算子">

现象：把 asynquence 的顺序、并行或 gate 代码机械改成 `then`，却没有检查结果顺序、错误恢复和重复完成语义。

原因：Promise 能表达许多相同流程，但聚合、取消、进度、门闩计数和回调适配仍需应用层约定；库的便利 API 可能包含额外策略。

修复：先列出原算子的输入输出契约，再用 Promise、`all`、`allSettled` 或显式 gate 重建，并为每个差异补测试。

</Callout>

<Callout type="trap" title="陷阱：失败处理只要打印日志就完成了错误契约">

现象：某个分支拒绝后打印错误，但主序列仍继续提交旧值，或 gate 永远等待未发送的完成信号。

原因：日志不是错误消费者；失败必须决定序列停止、恢复、降级或取消哪些分支，并解除所有等待状态。

修复：为错误建立唯一边界，记录拒绝原因、已完成分支、待处理分支和最终状态，确认没有迟到结果继续写入。

</Callout>

## 核心概念与状态所有权

<Term def="把异步步骤、完成状态、错误传播和组合操作包装在一起的历史 JavaScript 库；其价值在于协议，而不是库名本身。">asynquence</Term> 的创建者负责签发序列状态，消费者负责订阅或推进后续步骤。

<Term def="一组按顺序接力的异步步骤；前一步的完成值成为后一步的输入，失败则进入约定的错误边界。">序列</Term> 保存顺序与当前状态，不能把最后输出当成完整的执行轨迹。

<Term def="等待多个独立信号达到计数或条件后释放后续步骤的汇合机制；它不自动提供取消和资源回收。">gate</Term> 的所有权在计数与释放规则，必须防止重复 signal、漏 signal 和迟到 signal。

<Term def="接收拒绝、异常、超时或取消结果并决定停止、恢复、降级或继续的明确控制流边界。">错误通道</Term> 不是日志；它必须拥有最终状态与清理动作。

<Term def="把顺序、并行、汇合、恢复或桥接规则组合成新异步流程的函数或 API；每个算子都应有输入、输出和失败契约。">组合算子</Term> 需要说明是否启动工作、是否保证一次完成、是否保留顺序以及如何取消。

<Term def="把历史库的完成、错误和清理契约映射到原生 Promise、生成器执行器或其他现代接口的适配层。">桥接适配器</Term> 不能只转换类型，还要验证时序、身份、取消和错误传播是否相同。

这些概念要一起回答五个问题：状态由谁创建，步骤何时启动，分支如何汇合，失败由谁消费，结束后哪些任务被清理。只看链式语法或最终字符串，无法判断 gate 是否泄漏等待，也无法判断桥接是否重复完成。

| 观察量 | 本页判定方式 |
| --- | --- |
| asynquence | 记录库对象、版本和组合算子对状态的所有权 |
| 序列 | 对比顺序步骤的启动、输入、输出和完成状态 |
| gate | 注入重复、缺失与迟到 signal，检查是否只释放一次 |
| 错误通道 | 追踪拒绝来源、恢复决定和最终清理动作 |
| 组合算子 | 为每个算子写出输入、输出、时序和取消契约 |
| 桥接适配器 | 对照 Promise 或生成器执行器的完成、错误与身份边界 |

## 机制拆解

### 1. Appendix A: asynquence Library

**Appendix A: asynquence Library** 的重点是理解一套历史组合库如何把异步流程的状态、顺序、并行和错误写成可复用协议。它不是现代项目中必须安装的推荐，而是观察抽象如何回应回调嵌套、错误传播和并发汇合问题的材料。

阅读这类库时，先找到创建序列、追加步骤、分支汇合和错误处理的入口，再把每个入口映射到现代 Promise、生成器 runner 或显式状态机。这样既能保留历史设计的意图，也能识别哪些便利 API 依赖当时的运行时和工具链。

### 2. 创建异步序列

创建序列时要确定谁持有 pending、fulfilled 和 rejected 状态。调用者得到的序列对象不应因为多个消费者而重复启动同一项工作；如果库允许重复订阅，也要说明是共享结果还是重新执行。

最小状态记录至少包括序列 id、输入、启动时间、当前步骤、完成值或错误、待清理任务。状态记录让你能分辨“还没有开始”“正在等待”“已经完成”和“已经取消”，而不是把它们都叫作异步。

### 3. 追加顺序步骤

顺序组合把前一步的完成值交给下一步。若步骤返回普通值、异步序列或错误，下一步的状态转换应有明确规则；特别要防止一个回调同时调用成功和失败，导致后续步骤收到两次输入。

顺序不等于同步。每一步可以在未来恢复，但逻辑上的依赖顺序仍然固定。测试时要分别覆盖成功链、空值链、步骤抛错、恢复后继续以及完成后的迟到回调。

### 4. 用 gate 并行分支

gate 适合表达“若干独立任务都完成后再继续”。它可以由计数器、键集合或显式分支注册表实现，但必须先登记所有分支再允许释放，避免某个快速分支在其他分支还没有注册时提前打开 gate。

并行还需要清理契约：一个分支失败时，其他分支是否取消，已经完成的结果是否保留，超时后谁关闭资源。gate 只负责条件，不应冒充完整的取消控制器。

### 5. 聚合与统一错误

聚合结果时保留分支 id，不能只按到达顺序写入数组。迟到结果可能来自旧请求，错误也可能先于其他成功值到达；聚合器要有一次决策边界，决定是全成才继续、收集部分结果，还是首错停止。

错误通道应把原因、步骤、已完成分支和清理结果传给最终消费者。恢复值要与原始错误分开记录，否则后续步骤看似成功，却无法解释失败是否被处理、替换或吞没。

### 6. 与 Promise 和生成器桥接

现代桥接可以用 Promise 表达顺序，用 `Promise.all` 或 `allSettled` 表达聚合，用生成器 runner 表达逐步恢复，但每种映射都要验证语义。Promise 不自动提供 gate 的取消、进度或资源权；生成器也不自动等待被 yield 的异步值。

桥接适配器的验收清单包括：是否只完成一次，错误是否到达同一边界，结果顺序是否保持，取消或超时是否清理底层工作，旧回调是否会在新请求中写入。若这些问题没有答案，桥接只是换了表面 API。

## 六阶段证据链

本页的可执行链条是：创建异步序列 → 追加顺序步骤 → 用 gate 并行分支 → 聚合分支结果 → 统一进入错误通道 → 与原生 Promise 组合对照。正常样本证明主路径，边界样本证明分支数、重复 signal 和迟到回调，失败样本定位拒绝、超时或错误消费者，恢复样本证明旧任务已清理且桥接没有重复恢复。

## 最小可运行实验

下面用原生 Promise 写出与附录历史组合相同的最小观察面：顺序步骤、并行聚合和错误边界。运行前先预测每一步的状态，再替换一个分支为拒绝：

```js
function task(label, value) {
  return Promise.resolve({ label, value });
}

const sequence = task("first", 2)
  .then(({ value }) =>
    Promise.all([task("left", value + 1), task("right", value + 2)]),
  )
  .then((branches) => branches.map(({ label, value }) => `${label}:${value}`))
  .catch((error) => [`recovered:${error.message}`]);

sequence.then(console.log);
```

这个例子保留了可观察结果，却没有自动解决取消、超时、进度和资源清理。要模拟 gate，必须明确分支注册和释放条件；要桥接历史库，还要把原算子的完成、错误和顺序契约写成测试，而不是只比较最终数组。

## 四类样本与验收

| 样本 | 注入方式 | 必查证据 | 通过条件 |
| --- | --- | --- | --- |
| 正常 | 两个顺序步骤、两个分支、明确聚合 | 序列 id、分支 id、顺序、完成状态 | 只完成一次且结果可解释 |
| 边界 | 空分支、重复 signal、分支提前完成、迟到结果 | gate 计数、注册表、请求身份、顺序 | 不提前释放、不重复聚合、不写旧请求 |
| 失败 | 分支拒绝、步骤抛错、超时或桥接类型错误 | 错误来源、消费者、已完成分支、清理 | 错误明确停止或恢复，gate 不永久等待 |
| 恢复 | 重建序列并重放相同输入 | 新序列 id、任务数、资源和最终状态 | 无旧回调、旧分支和旧错误污染 |

本页签发不变量是：**asynquence 的价值在组合契约；序列按协议接力，gate 只释放一次，分支聚合保留身份，错误拥有明确消费者，桥接 Promise 或生成器时必须保留顺序、一次完成、取消与清理边界。**

## 版本与原书边界

本单元以一版原书附录的历史库语境为结构基线。正文使用现代可运行的 Promise 对照独立重构组合机制；不把历史库 API 伪装成当前标准，也不把现代 Promise 的能力反推为当年的实现细节。

原书附录关注 asynquence 如何组织顺序、并行、gate、错误与生成器流程。本文保留这些问题边界，并补充现代桥接、取消、超时和资源清理的验收要求；这些补充属于今天的工程重构，不冒充历史库的完整 API 文档。

## 练习

<Exercises>

1. 用原生 Promise 重建一个两步顺序链：第一步产生输入，第二步失败后恢复为可识别的对象；写出每一步的序列状态。

   <Answer>

   第一段可以返回 `Promise.resolve({ step: 1, value: 2 })`，第二段检查输入后 `throw new Error("broken")`，最后接 `catch((error) => ({ recovered: true, message: error.message }))`。状态依次是 pending、fulfilled、rejected、fulfilled；恢复对象必须与原始错误分开保存，不能把 catch 当成没有失败。

   </Answer>

2. 实现一个 gate，等待两个分支各 signal 一次后释放；再测试重复 signal、缺失 signal 和其中一个分支拒绝的行为。

   <Answer>

   先登记两个分支 id，使用 `Set` 记录已经 signal 的 id；只有两个 id 都出现且 gate 尚未释放时才 resolve。重复 id 不增加计数，缺失 signal 不能自动成功；拒绝分支要走 reject 或统一错误通道，并执行其他分支的取消与清理。测试应断言 gate 只释放一次，且拒绝后不会被迟到 signal 改写。

   </Answer>

3. 将一个历史组合算子桥接到 Promise 或生成器 runner，并列出不能只靠类型转换验证的语义。

   <Answer>

   顺序算子可映射为 `then` 链，并行聚合可映射为 `Promise.all` 或 `allSettled`，逐步恢复可映射为生成器 runner；但必须逐项验证完成只发生一次、分支结果顺序、错误消费者、取消与超时、迟到回调和资源清理。若原算子允许部分成功或有 gate 计数，直接使用 `Promise.all` 可能改变失败和聚合契约。

   </Answer>

</Exercises>

## 小结

- asynquence 是理解历史异步组合契约的材料，不是现代项目中必须无条件采用的库。
- 序列负责顺序接力，gate 负责明确的汇合条件，分支聚合必须保留身份与完成边界。
- 错误通道要决定停止、恢复、取消和清理，日志不能替代错误消费者。
- Promise 和生成器可以承载相同意图，但桥接必须验证一次完成、顺序、取消和资源语义。
- 最终验收要覆盖正常、边界、失败和恢复样本，防止旧回调污染新序列。
