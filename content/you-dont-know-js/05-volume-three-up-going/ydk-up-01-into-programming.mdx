## 直觉：先预测，再运行

编程不是把自然语言逐句翻译成语法，而是把目标变成一组可执行的步骤：读取输入，使用值和变量表示状态，用表达式计算中间结果，再用分支、循环和函数组织重复工作。程序的意义来自这些步骤之间的关系，不只来自最后打印出来的字符串。

初学者常把“没有报错”当成“做对了”。实际上，类型转换可能悄悄改变值，条件可能漏掉边界，循环可能少处理一次，函数可能把输入和外部状态混在一起。可靠的学习循环是先预测绑定和输出，再运行，定位第一个不同之处，修改一个假设后重放。

先预测：给定价格数组和税率，哪些值会被保存，哪一个表达式先求值，分支何时命中，循环何时结束，函数最终返回什么。记录预期后切换样本，比较第一个语义偏离点。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：代码没有抛错就说明结果正确">

现象：程序顺利打印一个数字，就跳过输入检查、边界样本和中间变量验证。

原因：JavaScript 允许许多合法但不符合目标的值流动；隐式转换、空值和错误分支可能让错误结果看起来很正常。

修复：为输入、类型、关键中间值和最终结果写断言，至少重放正常、空值、边界和错误四类样本。

</Callout>

<Callout type="trap" title="陷阱：变量名就是变量的全部语义">

现象：看到 `total`、`items` 或 `result` 这些名字，就假设它们在所有块和函数中都指向同一个值。

原因：变量绑定受作用域、声明方式、赋值时机和遮蔽影响；名字相同不代表绑定身份相同。

修复：在每个关键步骤记录绑定位置、当前值和生命周期，避免用名称替代作用域与状态证据。

</Callout>

<Callout type="trap" title="陷阱：循环和函数只是减少重复输入，不需要契约">

现象：循环里随意修改外部变量，函数依赖隐含全局状态，却只用一个正常输入测试。

原因：重复控制和封装会扩大状态边界；缺少初始化、结束条件、输入输出约定时，错误会在多次迭代后才出现。

修复：明确循环不变量、推进与结束条件，为函数写输入、返回值、副作用和错误契约，并测试空集合与极限数量。

</Callout>

<Callout type="trap" title="陷阱：注释或复制代码可以替代动手验证">

现象：只读注释或照抄示例，能描述语法，却无法预测修改一个值后哪条路径会改变。

原因：语义模型必须经过运行、观察和反例检验；注释记录意图，但不会证明实际绑定、类型和执行顺序。

修复：先写预测，再改动一个输入或运算符，观察首个偏离点，最后把稳定发现写成可运行测试。

</Callout>

## 核心概念与状态所有权

<Term def="一个接受输入并通过值、表达式、控制流和函数产生可观察结果的可执行过程。">程序</Term> 的所有权在执行状态：要知道当前绑定、路径、值和下一步动作，才能解释结果。

<Term def="保存一个值的命名绑定；变量的身份由作用域和声明位置决定，当前值则由赋值与执行顺序决定。">变量</Term> 是状态观察的入口，不是只由名称决定的文本标签。

<Term def="根据当前值计算新值的代码片段；它可以包含字面量、变量、运算符和函数调用，并遵循明确的求值规则。">表达式</Term> 的结果需要结合类型、操作数和求值顺序来预测。

<Term def="决定下一步执行哪条路径的结构，包括条件、循环和函数调用；控制流把局部值连接成完整过程。">控制流</Term> 要有分支覆盖、循环结束条件和错误路径，不能只测试一条主路。

<Term def="把输入、局部绑定、返回值和副作用封装成可复用单元的声明；函数边界应明确输入输出与生命周期。">函数</Term> 可以减少重复，但也会引入参数、局部作用域和调用契约。

<Term def="用输入、预期、运行结果和断言重复检查程序契约的实践；它把一次观察变成可以回放的证据。">练习</Term> 不只是抄写代码，而是主动修改、制造边界并验证语义。

这些概念要一起回答五个问题：输入由谁提供，绑定保存在哪里，值如何变化，控制流为何选择某条路径，结束后结果如何被测试。只看最后输出，无法判断类型转换、变量遮蔽、漏迭代或隐藏副作用。

| 观察量 | 本页判定方式 |
| --- | --- |
| 程序 | 记录输入、步骤、状态变化、输出和结束条件 |
| 变量 | 区分绑定身份、作用域、赋值时机和当前值 |
| 表达式 | 逐项预测操作数、类型、运算符和中间结果 |
| 控制流 | 覆盖条件路径、循环不变量、函数调用和错误出口 |
| 函数 | 验证参数、局部状态、返回值、副作用和重复调用 |
| 练习 | 用正常、边界、失败和恢复样本重放契约 |

## 机制拆解

### 1. Chapter 1: Into Programming

**Chapter 1: Into Programming** 建立的是程序语义模型：输入进入执行过程，值被绑定和转换，表达式计算中间结果，控制流选择路径，函数封装可重复步骤，最后用实践检验预测。每一步都应留下可观察证据。

初学时可以把代码看成一张状态转移图。节点是绑定和值，边是赋值、运算、分支、迭代或调用；当输出不符合预期，沿图寻找首个状态分叉，比从最后一行倒猜更可靠。

### 2. Code

**Code** 是给运行时执行的具体指令集合，不等于注释、变量名或格式。阅读代码时先标出输入来源、每次赋值、函数调用和输出，再预测运行顺序。

```js
const prices = [10, 20];
const tax = 0.1;
const total = prices[0] + prices[1];
console.log(total * (1 + tax));
```

这段代码的证据不是“看起来像算总价”，而是数组值、加法结果、税率和最终乘法都可以被单独观察。改动一个输入后，要确认哪一个绑定先变化。

### 3. Try It Yourself

**Try It Yourself** 把阅读变成实验：先复制最小样本，写下每一步预期，再只改一个值、运算符或条件，运行后比较预测与结果。一次只改变一个因素，才能判断偏离来自哪个假设。

可以从空数组、负数、字符串数字和大输入开始做边界实验。每个实验记录输入、预期类型、实际值、首个偏离点和修复后的回放结果，这些记录比一次成功运行更有学习价值。

### 4. Operators

**Operators** 连接操作数并产生值。加法、比较、逻辑运算、赋值和条件运算符不只是符号替换；操作数类型、短路规则、优先级和求值顺序都会改变结果。

```js
const label = "items: " + 2;
const allowed = label.length > 0 && 2 >= 1;
```

预测运算符时先写出每个操作数的类型，再写中间结果，最后写整体结果。遇到隐式转换时不要只记“某个例子会这样”，应把转换边界纳入测试。

### 5. Values & Types

**Values & Types** 要求区分“值是什么”和“它如何被使用”。数字、字符串、布尔值、`null`、`undefined`、对象和数组拥有不同的运算、比较、复制与属性行为。

类型不是装饰信息：它影响加法是数值相加还是字符串拼接，也影响空值检查、真假判断和函数参数契约。运行前记录类型，运行后用明确断言确认没有靠偶然转换得到结果。

### 6. Code Comments

**Code Comments** 适合记录为什么这样做、输入假设、边界和暂时的风险，不应把注释当成运行时事实。注释描述意图，代码和测试证明实际行为；两者冲突时应修正过期注释或实现。

好注释能帮助下一位读者找到契约，例如“这里假设数组已经按时间排序”。但如果这个假设重要，就还应在代码中验证，或在测试中提供未排序输入，不能只依靠阅读者自觉。

### 7. Variables

**Variables** 是绑定而不是盒子的简单比喻。声明位置决定作用域，赋值时机决定当前值，块和函数可以创建同名但不同身份的绑定；调试时要记录绑定路径而不是只看名称。

```js
let total = 1;
{
  const total = 2;
  console.log(total); // 2
}
console.log(total); // 1
```

这个例子中两个 `total` 的文字相同，绑定身份却不同。把变量放进明确的局部作用域，减少隐含共享状态，通常比依靠命名约定更容易验证。

### 8. Blocks

**Blocks** 用花括号建立语句范围和块级作用域。它们可以让条件和循环中的临时变量不泄漏到外部，也能把一组相关动作组织成更清晰的控制流单元。

块本身不会自动创建业务契约；仍然要检查初始化、执行顺序、异常出口和离开块后的状态。尤其要区分块内声明与外部同名绑定，避免把遮蔽误认为赋值。

### 9. Conditionals

**Conditionals** 通过条件选择执行路径。一个可靠的分支要说明条件的值域、真路径、假路径、嵌套优先级和未覆盖输入的默认行为。

```js
function classify(total) {
  if (total < 0) return "invalid";
  if (total === 0) return "empty";
  return "ready";
}
```

测试这段函数至少要覆盖负数、零和正数。若新规则增加了上限或空值，还要补充相邻边界，确保分支变化没有让旧路径悄悄失效。

### 10. Loops

**Loops** 把同一类操作应用到多个值。循环的正确性依赖初始化、循环不变量、推进动作和结束条件；缺少任何一个都可能导致漏项、重复或永不结束。

```js
function sum(values) {
  let total = 0;
  for (const value of values) total += value;
  return total;
}
```

空数组、一个元素、多个元素和包含边界值的数组能帮助验证循环。对每次迭代记录累计值与剩余输入，通常能很快发现更新顺序或结束条件的问题。

### 11. Functions

**Functions** 用参数、局部绑定和返回值封装过程。好的函数契约写清楚接受什么、返回什么、是否修改外部状态、错误如何表达以及重复调用是否安全。

```js
function totalWithTax(prices, rate) {
  const subtotal = prices.reduce((total, price) => total + price, 0);
  return subtotal * (1 + rate);
}
```

这个函数仍需测试空数组、负税率、非数字输入和重复调用。把输入验证和计算边界显式写出，能减少函数调用者对隐含状态的猜测。

### 12. Practice

**Practice** 是把预测、运行、观察和修改循环起来的工程训练。每次练习都应从一个最小样本开始，增加一个边界或故障，记录首个偏离点，再把稳定发现固化成断言或测试。

练习的目标不是写更多代码，而是建立迁移能力：看到新 API 时仍能问输入是什么、值在哪里、路径怎么选、循环何时结束、函数如何返回、失败谁处理。可重放的记录让这种能力不依赖记忆某个例子的输出。

## 最小可运行实验

下面的片段同时展示值、运算符、条件、循环和函数。运行前先预测空数组、普通数组和异常输入的行为：

```js
function totalWithTax(prices, rate) {
  let subtotal = 0;
  for (const price of prices) {
    if (typeof price !== "number") throw new TypeError("price");
    subtotal += price;
  }
  return subtotal * (1 + rate);
}

console.log(totalWithTax([10, 20], 0.1));
```

这个实验的契约是：输入是数字数组，循环累加 subtotal，条件拒绝非数字，函数返回含税数字。把一个元素替换成字符串，程序应在首个非法值处停止；修复输入后重放同一数组，结果应稳定。

## 练习

<Exercises>

1. 修改 `totalWithTax`，让它接受一个空数组并返回 0，同时拒绝字符串价格；为每种输入写出预期类型和输出。

   <Answer>

   用 `let subtotal = 0` 作为空数组的单位值，循环不会执行时直接返回 `0 * (1 + rate)`。每次迭代先断言 `typeof price === "number"`，不满足就抛出 `TypeError`。测试应覆盖空数组、一个数字、多个数字和一个字符串，并检查错误发生在非法输入而不是最后计算。

   </Answer>

2. 为一个分支函数补齐边界测试，说明为什么只测试 true 路径不能证明条件正确。

   <Answer>

   如果函数按 `total < 0`、`total === 0` 和其他值分类，就分别测试负数、零、正数；若加入上限，则再测试上限前、等于上限和超过上限。条件正确性来自路径覆盖和返回契约，而不是某一次 true 分支打印了预期字符串。

   </Answer>

3. 把一段带隐式外部变量的计算改成纯函数，并写出如何通过重放证明它没有旧状态污染。

   <Answer>

   将外部变量改为参数，把累计值放在函数局部变量中，只通过 `return` 输出结果。例如 `sum(values)` 每次调用都从 `total = 0` 开始。用相同输入连续调用两次、交替调用不同输入，再比较返回值；如果结果只由参数决定且调用顺序不影响输出，就有证据说明没有共享旧状态。

   </Answer>

</Exercises>

## 小结

- 编程从输入和目标开始，用值、表达式、变量与控制流构造可观察过程。
- 运算符和类型影响中间结果；变量绑定由作用域和执行顺序决定。
- 条件要覆盖路径，循环要有不变量和结束条件，函数要有输入输出和副作用契约。
- 注释记录意图，运行和测试证明行为；实践通过预测、修改和重放建立语义模型。
- 正常、边界、失败与恢复样本共同构成可迁移的编程证据。

<GlossaryItem term="程序">接受输入并通过值、表达式、控制流和函数产生可观察结果的执行过程。</GlossaryItem>
<GlossaryItem term="变量">由作用域和声明位置确定身份、由赋值与执行顺序确定当前值的命名绑定。</GlossaryItem>
<GlossaryItem term="表达式">根据操作数、运算符和函数调用计算新值的代码片段。</GlossaryItem>
<GlossaryItem term="控制流">通过条件、循环和函数调用决定程序下一步执行路径的结构。</GlossaryItem>
<GlossaryItem term="函数">封装参数、局部绑定、返回值和副作用的可复用执行单元。</GlossaryItem>
<GlossaryItem term="练习">通过预测、运行、观察、修改和断言重复检查程序契约的实践。</GlossaryItem>

</Glossary>
