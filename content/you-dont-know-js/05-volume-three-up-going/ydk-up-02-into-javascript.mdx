## 直觉：先预测，再运行

JavaScript 的难点不在于把一行代码读成中文，而在于追踪值怎样经过类型语义、变量绑定、条件路径和函数调用，最后在一个具体的调用点上确定 `this`，或沿原型链找到属性。只看最后的输出，会把转换、查找和绑定过程藏起来。

一个更可靠的学习循环是：先写下每个操作数的类型、每个名称的绑定、函数值的去向和调用形式；再运行一个正常样本；随后只改变一个边界条件，定位第一个不同之处。错误发生在转换、分支、调用点还是原型查找，决定了修复方式。

先预测：给定一个对象方法、一个被单独保存的函数和一个原型上的方法，哪一次调用会改变 `this`，哪一个属性会沿原型链命中，严格模式会在哪一步把隐式行为变成错误？记录预期后切换样本，比较首个偏离点。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：值相同就代表类型和语义相同">

现象：把数字、数字字符串、空值和布尔值放进同一个比较或加法中，只检查最终显示的文本。

原因：JavaScript 会在部分运算中进行隐式转换；转换可能让结果看似合理，却改变比较、属性访问或函数参数的含义。

修复：在每个边界记录 `typeof`、原始值、转换规则和目标契约，分别测试严格比较、显式转换与意外输入。

</Callout>

<Callout type="trap" title="陷阱：严格模式只是格式偏好">

现象：把 `"use strict"` 当成 lint 配置，认为开启或关闭不会影响运行时。

原因：严格模式会改变未声明赋值、某些 `this` 默认值和一部分静默失败行为；它是执行语义的一部分。

修复：在普通函数、未声明赋值和只读属性等样本中分别对照运行，记录错误出现的位置和类型。

</Callout>

<Callout type="trap" title="陷阱：this 由函数名字或定义位置决定">

现象：函数一旦写在对象里，就假设以后无论怎样传递都拥有同一个 `this`。

原因：普通函数的 `this` 主要由调用形式决定；取出方法、显式绑定、构造调用和箭头函数的规则并不相同。

修复：把同一个函数分别作为方法、普通函数和显式绑定调用，逐次记录调用点与接收者。

</Callout>

<Callout type="trap" title="陷阱：原型继承就是把属性复制一份">

现象：修改原型方法后，认为已有对象应该保留创建时的旧副本，或认为所有旧写法都等于现代写法。

原因：原型是运行时查找和委托关系；旧语法、新语法与宿主 API 也属于不同层级，不能用一个“兼容”结论抹平差异。

修复：分别观察自有属性、原型属性、方法修改后的读取结果，再把语言能力和宿主能力分栏验证。

</Callout>

## 核心概念与状态所有权

<Term def="在运行时可被保存、传递、比较或作为表达式结果使用的实体；值的类型决定许多操作和转换规则。">值与类型</Term> 是所有后续解释的入口：先问当前值是什么、类型是什么，再问它会被怎样使用。

<Term def="由作用域、声明位置和执行环境共同确定的名称到值的关系；赋值会更新绑定的当前值，但不会改变绑定身份。">变量绑定</Term> 不等于一个可随意搬动的盒子。相同名字在不同块或函数中可能指向不同绑定。

<Term def="对执行语义施加更严格约束的模式；它把部分原本静默或隐式的行为改成明确错误，并改变部分函数调用的默认语义。">严格模式</Term> 是运行时契约，不只是代码风格。

<Term def="可以像其他数据一样保存、传递、返回和组合的函数实体；函数值仍携带其定义时的词法环境。">函数值</Term> 让回调、闭包和高阶函数成为同一套值语义的不同用法。

<Term def="普通函数执行时由调用形式确定的接收者绑定；方法调用、普通调用、显式绑定和构造调用会产生不同结果。">this 绑定</Term> 要从调用点倒推，不能从函数名字或定义位置单独推断。

<Term def="对象在查找缺失的自有属性时沿 [[Prototype]] 关系继续查找的过程；找到的是共享行为或数据的来源，而不是自动复制。">原型查找</Term> 将对象的自有状态与共享行为分开。

这些概念共同回答五个问题：输入值由谁创建，名称绑定保存在哪里，当前函数由哪个调用点触发，属性查找会走到哪里，失败由语言层还是宿主层处理。每一次实验都应至少保留正常、边界、失败和恢复四类证据。

## 机制拆解

### 1. Chapter 2: Into JavaScript

**Chapter 2: Into JavaScript** 的主线不是语法清单，而是运行时模型：值进入表达式，名称解析到变量绑定，条件决定路径，函数值携带词法环境，调用形式决定 `this`，属性读取在必要时沿原型链继续。最后还要把语言本身与旧新语法、宿主能力分开。

```js
const base = { label: "base" };
const child = Object.create(base);
child.read = function read() {
  return `${this.label}:${typeof this.read}`;
};

console.log(child.read());
```

这段代码至少有三条可观察路径：`child` 的自有 `read`，`base` 提供的 `label`，以及方法调用为 `read` 建立的 `this`。不要把“打印出 base:function”当成全部解释；还要说明值、绑定和查找顺序。

### 2. Values & Types

**Values & Types** 要求把“值”和“值的类型语义”分开。数字、字符串、布尔值、`null`、`undefined`、对象和数组不是同一类操作数；加法可能做数值相加，也可能触发字符串拼接，比较则可能选择严格或宽松规则。

```js
const number = 1;
const text = "2";
console.log(number + text);       // "12"
console.log(number + Number(text)); // 3
console.log(number === text);     // false
```

学习重点不是背下某个转换表，而是在接口边界明确契约：接收数字就拒绝数字字符串，或先显式转换并测试失败分支。`null`、`undefined`、空字符串和零也要分别验证，不能只用“空”这个词概括。

### 3. Variables

**Variables** 是名称到值的绑定。`let` 和 `const` 产生块级绑定，`var` 的历史行为与函数作用域、提升和重复声明有关；同名并不代表同一身份，内层绑定可以遮蔽外层绑定。

```js
let status = "outer";
{
  const status = "inner";
  console.log(status); // inner
}
console.log(status); // outer
```

读代码时先圈出作用域，再标记声明和赋值发生的时间。一个稳定的工程习惯是缩小共享状态，把可变值留在明确的生命周期内；这比依靠变量名暗示所有权更容易测试和重放。

### 4. Conditionals

**Conditionals** 消费一个条件值并选择路径。真假判断、短路求值、严格比较和默认分支都可能影响后续代码；可靠的条件要写出输入值域、命中路径、未命中行为和相邻边界。

```js
function classify(value) {
  if (value === null) return "missing";
  if (typeof value !== "number") return "invalid";
  if (value >= 0) return "ready";
  return "negative";
}
```

测试不应只覆盖 `true` 路径。`null`、数字字符串、零、负数和正数分别代表不同证据；若改变判断顺序，必须重跑所有相邻边界，确认没有让更具体的情况被宽泛条件抢先消费。

### 5. Strict Mode

**Strict Mode** 让某些隐式行为变成更早、更明确的错误。它会拒绝未声明赋值，也会改变普通函数在没有有效接收者时的 `this` 默认值；严格模式下的错误暴露了原本会被静默吞掉的契约问题。

```js
"use strict";

function assign() {
  undeclared = 1;
}

try {
  assign();
} catch (error) {
  console.log(error instanceof ReferenceError);
}
```

严格模式不会替你证明业务逻辑正确。它只是把一部分边界收紧，仍然需要检查类型、分支、错误处理和资源清理；比较默认模式和严格模式时，记录差异发生在什么阶段。

### 6. Functions As Values

**Functions As Values** 意味着函数可以被赋给变量、放进数组、作为参数传递或作为返回值交给下一层。函数值还会保留定义时的词法环境，因此闭包既是值传递，也是状态封装。

```js
function makeCounter() {
  let count = 0;
  return function next() {
    count += 1;
    return count;
  };
}

const next = makeCounter();
console.log(next(), next()); // 1 2
```

这里被传回的是 `next` 这个函数值，`count` 不是全局变量，却能被后续调用读取和更新。验证函数值时要区分“传的是哪一个函数”“它携带什么环境”“调用几次后内部状态怎样”，并测试重复调用与独立实例之间是否互相污染。

### 7. this Keyword

**this Keyword** 对普通函数来说主要由调用点决定，而不是由函数定义位置或名字决定。`obj.read()` 是隐式方法调用，`read()` 是普通调用，`read.call(other)` 是显式调用；构造调用与箭头函数又有各自的规则。

```js
"use strict";
const first = { name: "first", read() { return this.name; } };
const read = first.read;
const second = { name: "second" };

console.log(first.read());       // first
console.log(read.call(second));  // second
console.log(read());             // TypeError when this is undefined
```

把方法取出并不改变函数值本身，却改变了调用形式。分析 `this` 时先写出“谁在点号左侧、是否显式绑定、是否构造调用、是否是箭头函数”，再预测接收者；不要用词法作用域的规则替代调用点规则。

### 8. Prototypes

**Prototypes** 提供对象属性查找的委托路径。对象先检查自己的属性，如果没有命中，再沿 `[[Prototype]]` 查找；找到的共享方法仍然以实际接收者作为 `this`，而不是把方法复制给每一个对象。

```js
const speaker = {
  say() {
    return this.name;
  },
};
const alice = Object.create(speaker);
alice.name = "Alice";

console.log(alice.say());
console.log(Object.hasOwn(alice, "say")); // false
```

第二行证明 `say` 来自原型查找，不是 `alice` 的自有副本。修改 `speaker.say` 后再次读取 `alice.say`，可以观察委托关系；如果在 `alice` 上创建同名自有属性，查找则会在第一层停止。

### 9. Old & New

**Old & New** 不是把旧代码简单判成错误，而是把历史兼容性和现代语义分层。`var`、回调、构造函数和手动原型操作可能仍在真实项目中出现；`let`、`const`、类语法、Promise 和模块则提供了不同的作用域、异步和组织边界。

```js
var legacy = "function scoped";
{
  let modern = "block scoped";
  console.log(legacy, modern);
}
```

迁移时不要只替换关键字。应先写出原代码的绑定、调用、错误和兼容约束，再逐项验证新写法是否改变了提升、作用域、`this`、原型或异步时序。保留旧语法的理由也应是明确的运行环境约束，而不是“以前大家都这么写”。

### 10. Non-JavaScript

**Non-JavaScript** 指语言运行时之外的边界：浏览器 DOM、网络、文件系统、计时器、JSON、WebAssembly 或 Node.js API 都由宿主提供。JavaScript 代码可以调用这些能力，但 API 的可用性、权限、时序和错误模型不属于纯语言语义。

```js
const payload = JSON.parse('{"ok":true}');
const message = payload.ok ? "ready" : "blocked";
console.log(message);
```

`JSON.parse` 是宿主或标准库边界上的能力，输入格式错误时会抛错；而条件表达式本身属于语言层。调试时把“语言值如何流动”和“宿主何时回应”分栏，才能知道问题应在类型契约、权限、网络时序还是环境版本中修复。

## 最小可运行实验

下面的片段把值、函数值、`this`、原型和严格模式放进一个小样本。运行前先预测每次调用的接收者和每个属性的来源：

```js
"use strict";

const base = {
  describe() {
    return `${this.name}:${this.kind}`;
  },
};

const child = Object.create(base);
child.name = "child";
child.kind = "runtime";

const describe = child.describe;
console.log(child.describe());
console.log(describe.call(child));
console.log(Object.hasOwn(child, "describe"));
```

实验契约是：`describe` 来自原型，`child.describe()` 以 `child` 为接收者，单独保存后需显式绑定才可复用，原型方法不是 `child` 的自有副本。将 `child.kind` 改成数字、删除 `name` 或去掉显式绑定，分别记录值、类型、查找和 `this` 的首个偏离点。

<Exercises>

1. 修改最小实验，让 `describe` 分别以方法调用、普通调用和 `call` 显式绑定运行；为每次调用写出 `this` 的预期值和失败原因。

   <Answer>

   `child.describe()` 的调用点把 `child` 作为接收者；把方法保存到 `describe` 后直接调用，在严格模式下 `this` 为 `undefined`，访问 `name` 会失败；`describe.call(child)` 重新显式提供接收者，因此能得到稳定结果。关键不是函数定义在哪里，而是每次执行使用了哪一种调用形式。

   </Answer>

2. 为 `Values & Types` 样本补齐数字、数字字符串、`null` 和 `undefined` 的测试，说明为什么应优先显式转换或拒绝输入。

   <Answer>

   先记录每个样本的原始值与 `typeof`，再决定接口契约。若接口只接受数字，就用 `typeof value === "number"` 并拒绝其余输入；若允许文本，就在边界处调用 `Number`，检查结果是否为有效数字。这样可以把转换放在一个可测试的地方，而不是让加法或比较隐式决定业务含义。

   </Answer>

3. 证明原型方法不是复制到实例：修改原型方法、在实例上添加同名属性，再分别观察查找结果。

   <Answer>

   先用 `Object.hasOwn(child, "describe")` 确认实例没有自有方法，再修改 `base.describe` 并重新调用，实例会读取到新的原型方法。随后在 `child.describe` 上写入一个新函数，查找会在实例层停止，原型版本不再被使用。三次观察共同证明属性查找是动态委托，而不是创建实例时复制一份。

   </Answer>

</Exercises>

## 小结

- 值与类型决定表达式、比较和参数边界；变量是受作用域管理的绑定，不是单纯的命名盒子。
- 函数是可以传递和返回的值；它保留词法环境，但普通函数的 `this` 仍由调用点决定。
- 严格模式把部分隐式行为变成明确错误；条件、错误和恢复都要用边界样本验证。
- 原型查找沿委托链寻找共享行为，不等于把属性复制到每个对象。
- 旧新语法和非 JavaScript 宿主能力需要单独披露版本、权限、时序和错误边界。
