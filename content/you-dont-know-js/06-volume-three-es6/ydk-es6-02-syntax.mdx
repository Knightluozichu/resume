## 直觉：先预测，再运行

ES6 语法的价值不只是让代码更短，而是把过去依赖约定的边界写得更清楚：`let` 和 `const` 标出块级绑定，解构标出数据形状，默认参数标出缺省规则，展开和 `for..of` 暴露迭代协议，箭头函数固定词法 `this`，Symbol 则提供不与字符串冲突的身份。

简写也会隐藏新的问题。解构可能在 `null` 处失败，默认值只对 `undefined` 生效，展开依赖可迭代对象，箭头函数没有自己的 `this`，Unicode 的字符数和码点数可能不同，Symbol 键还不会出现在普通字符串键枚举中。

先预测：给定一个带默认值的解构、一个自定义迭代器、一个模板字符串和一个 Symbol 键，哪些绑定会产生，哪一步会读取迭代器，哪种枚举能看见该键？记录预期后只改一个边界，比较第一个偏离点。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：默认值会替换所有空值">

现象：把参数或解构默认值当成“只要没有可用值就启用”，因此把 `null`、`false` 和 `0` 都替换掉。

原因：默认参数和解构默认值针对的是 `undefined`；其他值仍然是调用者明确提供的输入。

修复：分别测试缺失、显式 `undefined`、`null`、`false` 和 `0`，把实际契约写成可断言的输入表。

</Callout>

<Callout type="trap" title="陷阱：展开语法可以复制任何对象">

现象：看到 `...value` 就认为数组、普通对象和自定义对象都能得到同一种复制结果。

原因：数组展开和 `for..of` 消费可迭代协议；对象展开读取可枚举自有属性，两个协议并不相同。

修复：先确认输入的迭代器或属性集合，再分别测试顺序、浅复制、缺失键和副作用。

</Callout>

<Callout type="trap" title="陷阱：箭头函数只是更短的普通函数">

现象：把普通函数改成箭头函数后仍期待它拥有自己的 `this`、`arguments` 或构造能力。

原因：箭头函数使用定义位置的词法 `this`，没有自己的 `arguments`，也不能作为构造函数调用。

修复：对方法回调、事件处理和构造调用分别比较接收者、参数来源和失败类型。

</Callout>

<Callout type="trap" title="陷阱：Unicode 字符和 Symbol 都只是字符串细节">

现象：用 `length` 推断用户看到的字符数，或用字符串枚举查找 Symbol 属性。

原因：Unicode 字符可能由多个 UTF-16 代码单元组成；Symbol 是独立的属性键身份，不会自动出现在字符串键列表中。

修复：按码点、组合字符和展示需求选择处理方式，并用 `Object.getOwnPropertySymbols` 单独检查 Symbol 键。

</Callout>

## 核心概念与状态所有权

<Term def="由 let 和 const 创建、受花括号边界约束的词法绑定；声明会经历初始化时机和暂时性死区，const 绑定不能重新赋值。">块级声明</Term> 让局部状态的可见范围与生命周期更容易审计。

<Term def="把数组元素或可迭代值收集为剩余参数或把序列展开到新位置的语法；其行为依赖迭代协议和读取顺序。">展开与剩余</Term> 既能表达输入收集，也能表达序列拆分，不能把两者当成深复制。

<Term def="在参数或解构绑定得到 undefined 时提供替代表达式的规则；显式 null、false 和 0 不会触发默认值。">默认参数</Term> 是一条精确的缺省契约。

<Term def="按对象属性或可迭代位置创建多个局部绑定的语法；读取来源、缺失属性和默认值触发条件共同决定结果。">解构</Term> 把数据形状写进声明，但不会自动验证业务类型。

<Term def="使用反引号和插值表达式构造字符串的语法；插值会执行求值，标签模板还可以接管分段与值的处理。">模板字面量</Term> 是可观察的求值过程，不只是字符串拼接的别名。

<Term def="可作为对象属性键且不与字符串冲突的原始身份；Symbol 属性需要专门的反射方式查找，不等于公开或加密。">Symbol</Term> 适合表达协议入口和元数据键。

这些概念共同回答五个问题：绑定在哪里建立，输入形状如何读取，迭代器何时消费，函数上下文从哪里来，文本与键身份如何保持。每次实验都要保留正常、边界、失败和恢复四类样本。

## 机制拆解

### 1. Chapter 2: Syntax

**Chapter 2: Syntax** 的主线是让代码结构更接近运行时契约：声明告诉你绑定边界，解构告诉你输入形状，迭代语法告诉你数据如何被消费，箭头函数告诉你上下文从哪里来，Unicode 和 Symbol 则把文本与身份边界显式化。

读一段新语法时，不要先问“旧写法怎么改成新写法”，而要先问它创建了哪些绑定、读取了哪些值、触发了哪个协议、在哪个顺序执行。改写之后重跑正常和失败样本，才能知道语法变化是否保留了原契约。

### 2. Block-Scoped Declarations

**Block-Scoped Declarations** 用 `let` 和 `const` 创建块级词法绑定。与函数作用域的 `var` 不同，块级声明不会自动泄漏到外层；声明到初始化之间还有暂时性死区，过早读取会失败。

```js
let status = "outer";
{
  const status = "inner";
  console.log(status);
}
console.log(status);
```

这里的两个 `status` 是不同绑定。`const` 约束的是绑定不能重新赋值，不代表对象内部不可变；真正的边界应通过作用域、初始化和对象状态分别验证。

### 3. Spread / Rest

**Spread / Rest** 在数组、参数和对象场景中有相似的三个点，但协议不同。数组展开和剩余参数读取可迭代值，对象展开读取可枚举自有属性；它们通常只做浅层复制。

```js
function collect(first, ...rest) {
  return [first, ...rest];
}

console.log(collect("a", "b", "c"));
console.log({ ...{ id: 1 }, active: true });
```

`rest` 收集剩余参数，`spread` 把序列放回新数组；对象展开的属性规则则不同。对自定义对象做实验时，先检查是否有 `Symbol.iterator`，否则不要从 `...value` 的外观推断它必然可展开。

### 4. Default Parameter Values

**Default Parameter Values** 只在对应参数的值为 `undefined` 时计算默认表达式。默认表达式在调用时求值，可以引用之前的参数，但后续参数和函数体变量有不同的可见性规则。

```js
function greet(name = "guest") {
  return `hello ${name}`;
}

console.log(greet());
console.log(greet(undefined));
console.log(greet(null));
```

前两次使用默认值，第三次把 `null` 作为真实输入。默认参数适合表达缺失值的契约，不适合模糊地清洗所有“看起来为空”的数据；若业务要求拒绝 `null`，应显式写验证。

### 5. Destructuring

**Destructuring** 按属性名或迭代位置创建绑定。对象解构读取属性，数组解构消费迭代器；缺失属性可以触发默认值，`null` 或 `undefined` 作为整体来源则可能在解构开始处失败。

```js
const payload = { id: 7, tags: ["js", "es6"] };
const {
  id,
  tags: [firstTag],
  label = "untitled",
} = payload;

console.log(id, firstTag, label);
```

嵌套解构很方便，但也要让错误边界可读。先验证来源是对象，再读取深层属性；把复杂解构拆成两步，往往能更清楚地定位缺失数据、默认值和类型不符的位置。

### 6. Object Literal Extensions

**Object Literal Extensions** 包括简写属性、简写方法、计算属性名和对象展开等能力。它们减少重复文字，却没有改变属性枚举、原型、访问器或方法调用的基本规则。

```js
const label = "ready";
const key = "status";
const record = {
  label,
  [key]: true,
  describe() {
    return `${this.label}:${this.status}`;
  },
};

console.log(record.describe());
```

计算属性名在对象创建时求值，简写方法仍然有方法调用的 `this` 语义。不要把“写法更短”当成“运行时没有顺序”；先记录键表达式、属性创建和调用点。

### 7. Template Literals

**Template Literals** 用反引号表示字符串，并在 `${...}` 中执行表达式。插值会读取绑定、调用函数并把结果转成字符串；标签模板还可以接收静态片段和原始值，改变最终输出方式。

```js
const name = "Ada";
const count = 2;
const message = `${name} has ${count} messages`;
console.log(message);
```

模板字符串并不会自动转义 HTML，也不会自动做本地化或安全编码。把用户输入放入模板时，仍要根据输出上下文选择转义；若使用标签模板，则要测试标签函数的参数顺序和异常路径。

### 8. Arrow Functions

**Arrow Functions** 没有自己的 `this`、`arguments` 或构造能力；它从定义位置的词法环境读取 `this`。这使它适合回调和保持外层上下文，但不适合需要动态接收者的对象方法。

```js
const context = {
  value: 3,
  read() {
    return [1].map(() => this.value);
  },
};

console.log(context.read());
```

箭头函数保留 `read` 的 `this`，而普通函数回调可能需要显式绑定。把方法改写成箭头函数前，要先写出原代码的调用点、构造需求和 `arguments` 依赖，不能只依据行数减少做迁移判断。

### 9. for..of Loops

**for..of Loops** 按可迭代协议读取值，而不是像 `for..in` 那样枚举属性键。数组、字符串、Set 和 Map 有不同的迭代值；普通对象没有默认迭代器，直接使用会失败。

```js
const values = new Set(["a", "b"]);
for (const value of values) {
  console.log(value);
}
```

循环会调用迭代器并逐步取得结果，因此生成器、资源释放和提前 `break` 都可能影响行为。测试时至少比较空集合、单值、重复值、不可迭代对象和提前退出，记录迭代器实际签发的值。

### 10. Regular Expression Extensions

**Regular Expression Extensions** 扩展了正则表达式的 Unicode、粘滞匹配和分组能力，但每个标志位都改变了解析或匹配边界。正则仍然是有状态的求值工具，不应只凭一个成功样本判断。

```js
const pattern = /\p{Letter}+/u;
console.log(pattern.test("café"));
```

Unicode 模式让正则可以按更完整的字符类别匹配，但目标引擎、标志和输入编码仍要验证。对于用户输入，测试组合字符、不同脚本、空字符串和超长文本，并注意正则回溯造成的性能边界。

### 11. Number Literal Extensions

**Number Literal Extensions** 提供二进制、八进制、十六进制和数字分隔符等更清晰的字面量写法。它们改变的是源码表示，不会让 Number 获得无限精度；大整数边界仍需使用合适的类型。

```js
const binary = 0b1010;
const hex = 0xff;
const readable = 1_000_000;
console.log(binary, hex, readable);
```

读数字时区分字面量进制、运行时 Number 值和字符串解析规则。对金额、时间戳或大整数，先写精度契约，再决定使用 Number、BigInt 或字符串，并测试转译器和目标引擎是否支持源代码写法。

### 12. Unicode

**Unicode** 处理字符、码点、UTF-16 代码单元和规范化之间的差异。`length` 统计的是代码单元数量，不一定等于用户感知的字符数；组合字符还可能需要按字素簇处理。

```js
const text = "A😀";
console.log(text.length);
console.log([...text].length);
console.log([...text].map((char) => char.codePointAt(0)));
```

展开字符串会使用迭代协议按码点读取，但这仍不等于完整的用户感知字符。输入校验、截断、排序和展示要分别说明单位；不要用一个 `length` 结论覆盖所有文本需求。

### 13. Symbols

**Symbols** 是可作为属性键的原始身份，每次调用 `Symbol()` 都得到不同值。Symbol 属性不会出现在 `Object.keys` 或普通字符串枚举中，但可以通过专门的反射 API 发现，也可能参与语言协议。

```js
const internal = Symbol("internal");
const record = { name: "Ada", [internal]: 42 };

console.log(Object.keys(record));
console.log(Object.getOwnPropertySymbols(record).length);
```

Symbol 不是加密和真正隐私；持有该 Symbol 的代码仍能访问属性。它适合防止协议键与用户字符串冲突，使用时要记录身份来源、可发现性和序列化行为。

## 最小可运行实验

下面的片段把块级声明、解构、默认值、展开、迭代、模板、箭头函数、Unicode 和 Symbol 放进一个小样本。运行前先预测每个绑定和协议边界：

```js
const metadata = Symbol("metadata");
const source = { id: 7, tags: ["js", "es6"], [metadata]: "internal" };
const {
  id,
  tags: [first, ...rest],
  label = "untitled",
} = source;

const summary = (value = label) => `${id}:${value}:${[first, ...rest].join(",")}`;
for (const tag of source.tags) console.log(tag);
console.log(summary(), Object.getOwnPropertySymbols(source).length);
```

| 恢复 | 修复输入或改用正确协议后重放 | 新绑定、迭代器、文本和键集合 | 无旧状态、旧迭代器或旧键污染 |

## 练习

<Exercises>

1. 修改最小实验，分别传入缺失的 `label`、`undefined`、`null`、`false` 和 `0`，说明哪几次会触发默认值。

   <Answer>

   缺失和显式 `undefined` 会触发默认值；`null`、`false` 和 `0` 都是调用者明确提供的值，不会触发默认值。测试应记录原始输入、绑定结果和最终模板文本，避免把“空”作为一个不精确的类别。

   </Answer>

2. 创建一个自定义可迭代对象，让 `for..of` 和数组展开都能读取它；再删除迭代器，说明两个使用点的失败边界。

   <Answer>

   在对象上实现 `[Symbol.iterator]`，让它返回具有 `next()` 的迭代器；`for..of` 和数组展开都会通过这个协议取得值。删除或破坏该方法后，两个使用点都会在尝试消费迭代器时失败。对象展开是另一条属性枚举规则，不能用它证明对象可迭代。

   </Answer>

3. 为一个包含 Unicode 文本和 Symbol 元数据的对象写验收表，分别比较 `length`、码点遍历、`Object.keys` 和 Symbol 反射结果。

   <Answer>

   `length` 记录 UTF-16 代码单元数量，展开字符串更接近码点数量，但仍不一定等于用户感知的字素簇数量；`Object.keys` 只列字符串键；`Object.getOwnPropertySymbols` 才能列出自有 Symbol 键。验收表应把这四种观察量分栏，不能用其中一个数字替代文本和身份契约。

   </Answer>

</Exercises>

## 小结

- 块级声明改变绑定边界；解构和默认参数把数据形状与缺失值契约写得更明确。
- 展开、剩余和 `for..of` 依赖不同的读取协议；对象展开不等于数组迭代，也不等于深复制。
- 对象字面量、模板和箭头函数减少样板，但求值顺序、插值副作用和词法 `this` 仍需验证。
- 正则、数字字面量和 Unicode 需要分别处理解析、精度、码点与展示边界。
- Symbol 提供不冲突的属性身份，但不是加密；可发现性、反射和序列化仍是公开契约的一部分。
