## 直觉：先预测，再运行

代码组织不是把所有代码塞进 class，也不是把文件拆成模块就算完成。迭代器规定消费者如何取得下一项，生成器规定生产者何时暂停，模块规定依赖如何通过静态绑定连接，class 则提供构造和实例方法的声明式表面；它们分别管理序列、时间、依赖和对象行为。

这些机制可以组合，却不能互相替代。生成器产生的是可被迭代器消费的对象，模块导出的是绑定而不是复制的值，class 的方法通常仍位于原型上。调试时先画出协议和所有权，再看语法表面，才能知道状态停在哪里、依赖从哪里来、方法由谁复用。

先预测：一个生成器交给 `for..of`，模块导出一个可变绑定，class 实例调用一个方法时，哪一层负责生产、哪一层负责读取、哪一层负责共享方法？记录预期后切换边界样本，比较首个偏离点。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：可迭代对象和迭代器是同一个东西">

现象：只要对象能被 `for..of` 使用，就假设它本身就是带有当前游标的迭代器。

原因：可迭代对象通过 `Symbol.iterator` 提供迭代器；迭代器通过 `next()` 保存消费进度，两个角色可以是同一对象，也可以分开。

修复：分别记录入口、迭代器实例、每次 `next()` 的结果和结束后的状态，测试重复调用是否重新开始。

</Callout>

<Callout type="trap" title="陷阱：生成器只是返回数组的快捷写法">

现象：调用生成器就期待全部值立即产生，忽略 `yield` 暂停、恢复、传值和提前结束。

原因：生成器返回的是可暂停的迭代器；生产发生在每次 `next()`，并由执行帧保存局部状态。

修复：逐次调用 `next()`，记录 `value` 与 `done`，再注入 `return()`、`throw()` 或提前停止观察清理路径。

</Callout>

<Callout type="trap" title="陷阱：模块导入是导出值的复制品">

现象：导出绑定更新后，认为导入方仍持有旧值，或把循环依赖当成普通对象复制。

原因：ES 模块暴露的是静态、活的绑定；模块作用域、初始化顺序和循环依赖会影响可读取的时机。

修复：用最小模块样本观察导出绑定更新、导入读取和初始化失败，区分绑定关系与对象快照。

</Callout>

<Callout type="trap" title="陷阱：class 语法等于经典类继承且方法复制到实例">

现象：看到 `class` 就认为实例拥有独立方法，或认为它绕开了原型和 `this` 调用规则。

原因：class 是原型对象模型的声明式表面；实例方法通常共享在 prototype 上，构造调用仍会建立接收者。

修复：用 `Object.hasOwn`、`Object.getPrototypeOf` 和方法调用分别检查自有属性、原型来源和 `this`。

</Callout>

## 核心概念与状态所有权

<Term def="由可迭代入口和 next() 结果组成的消费协议；每次读取都签发 value 与 done，并可能持有独立的消费进度。">迭代协议</Term> 让生产者和消费者可以解耦。

<Term def="能够暂停和恢复执行的函数；yield 产生一个迭代结果并保存局部状态，后续 next、return 或 throw 决定如何继续。">生成器</Term> 把按需生产写成可观察的状态机。

<Term def="拥有自己的模块作用域并通过 export 暴露绑定、通过 import 建立依赖的代码单元；模块边界同时影响初始化和加载错误。">ES 模块</Term> 将文件结构变成可分析的依赖边界。

<Term def="由导入方在模块初始化前建立的依赖关系；导入通常指向导出绑定本身，而不是把当时的值复制一份。">静态绑定</Term> 让工具能分析依赖，也让循环初始化需要明确处理。

<Term def="组织构造器、实例方法、静态方法和继承表面的语法；它依然建立在原型和构造调用等 JavaScript 机制之上。">class</Term> 是声明式组织方式，不是完全不同的对象模型。

<Term def="对象属性缺失时继续查找共享行为的链接关系；class 方法、手动委托和内建对象都可以通过原型链复用行为。">原型委托</Term> 负责共享，而不是复制每个方法。

这些概念共同回答五个问题：谁生产数据，谁消费数据，依赖何时建立，状态由谁持有，实例方法从哪里查找。每个组织实验都应保留正常、边界、失败和恢复四类样本。

| --- | --- |
| 迭代协议 | 检查 Symbol.iterator、next、value、done 和进度所有权 |
| 生成器 | 逐次记录 yield、恢复、传值、return 和 throw |
| ES 模块 | 区分模块作用域、导出表、初始化顺序和加载错误 |
| 静态绑定 | 观察导入方读取的是活绑定还是独立快照 |

## 机制拆解

### 1. Chapter 3: Organization

**Chapter 3: Organization** 讨论的是把代码的生产、消费、依赖和行为边界写清楚。迭代器和生成器处理序列，模块处理依赖，class 处理对象构造和方法组织；它们的共同点是把隐含状态变成可观察协议。

一个可靠的组织模型要能回答：下一项由谁签发，暂停后谁保存局部状态，导出绑定何时初始化，导入方何时可读，实例方法是否共享，以及错误和资源由谁清理。表面语法越短，越需要用实验把这些问题展开。

### 2. Iterators

**Iterators** 是消费者和数据源之间的协议。可迭代对象通过 `Symbol.iterator` 提供迭代器，迭代器通过 `next()` 返回 `{ value, done }`；`for..of`、数组展开和生成器都可以消费这一协议。

```js
const sequence = {
  values: ["a", "b"],
  [Symbol.iterator]() {
    let index = 0;
    return {
      next: () => ({
        value: this.values[index++],
        done: index > this.values.length,
      }),
    };
  },
};

console.log([...sequence]);
```

这里每次调用 `sequence[Symbol.iterator]()` 都可以创建独立游标。若让对象自身同时充当迭代器，则重复消费可能从旧位置继续；组织数据时要明确迭代器是否可重置、是否共享、提前结束时如何释放资源。

### 3. Generators

**Generators** 用 `function*` 和 `yield` 把生产逻辑拆成多个可恢复阶段。调用生成器函数不会立即执行函数体，而是返回迭代器；每次 `next(input)` 才恢复到下一个 yield，并把输入送回暂停点。

```js
function* ids() {
  const prefix = yield "ready";
  yield `${prefix}-1`;
  return `${prefix}-done`;
}

const run = ids();
console.log(run.next());
console.log(run.next("item"));
console.log(run.next());
```

生成器的局部绑定和执行位置是状态所有权。`return()` 会结束它，`throw()` 会把错误注入暂停点；如果生成器包着文件、锁或网络资源，还需要在 `finally` 中验证清理，而不是只检查最后一个值。

### 4. Modules

**Modules** 提供模块作用域、显式导出和显式导入。模块代码只在自己的作用域中解析名称，导出表定义边界，加载器则负责解析依赖、初始化和错误传播；这与把多个脚本拼接到全局作用域不同。

```js
// counter.js
let count = 0;
export function next() {
  count += 1;
  return count;
}
```

模块内部的 `count` 不应该被外部直接修改。导出的函数可以暴露受控操作，模块系统因此同时提供封装和可分析的依赖图；测试时要覆盖缺失导出、路径错误、循环依赖和初始化异常。

### 5. Static Imports and Live Bindings

静态导入在模块解析和初始化阶段建立依赖。**Modules** 通过 `export` 提供绑定，**静态绑定** 让导入方读取导出方的同一关系，而不是把当前值复制到一个无关变量中；导出方更新绑定后，导入方在合法时机读取到更新。

```js
// state.js
export let status = "idle";
export function activate() {
  status = "active";
}

// view.js
import { status, activate } from "./state.js";
console.log(status);
activate();
console.log(status);
```

示例中的绑定更新并不意味着所有循环依赖都安全。模块的初始化顺序、暂时不可用的导出和顶层副作用仍然可能造成失败；依赖图要记录边、初始化时机和每个模块的副作用。

### 6. Classes

**Classes** 用构造器、实例方法、静态方法和 `extends` 提供更熟悉的组织表面，但实例方法通常定义在 `prototype` 上。`new` 调用构造器并建立接收者，方法调用的 `this` 仍然取决于调用形式。

```js
class Record {
  constructor(id) {
    this.id = id;
  }

  describe() {
    return `record:${this.id}`;
  }
}

const record = new Record(7);
console.log(record.describe());
console.log(Object.hasOwn(record, "describe"));
```

最后一行通常是 `false`，因为 `describe` 来自 `Record.prototype`。class 让构造和方法组织更清楚，却没有消除原型委托、属性覆盖和方法取出后的 `this` 边界；迁移时要把这些运行时事实保留下来。

### 7. 组织机制的组合边界

把机制组合起来时，先按层写契约，再让下一层消费：生成器产生迭代器，`for..of` 消费迭代器；模块导出生成器，另一个模块导入并调用；class 可以把消费过程封装为实例方法，但方法仍通过原型共享。

```js
class Batch {
  constructor(values) {
    this.values = values;
  }

  *items() {
    yield* this.values;
  }
}

for (const item of new Batch([1, 2])) {
  console.log(item);
}
```

这段代码有多个可观察边界：`new Batch` 创建实例，`items` 来自原型，生成器持有迭代状态，`yield*` 委托给数组的迭代器，循环消费 `{ value, done }`。任何一层的错误都要能单独定位。

## 六阶段证据链

本页的可执行链条是：实现迭代入口 → 用生成器按需生产 → 用模块导出边界 → 由导入方建立静态绑定 → 用 class 组织实例方法 → 回到底层协议和原型委托。正常样本证明主路径，边界样本证明重复消费、提前结束和循环依赖，失败样本定位协议或初始化停止点，恢复样本证明旧迭代器、旧绑定和旧实例状态没有污染下一次执行。

| 阶段 | 输入 | 关键状态 | 输出 |
| --- | --- | --- | --- |
| 迭代入口 | 可迭代对象、游标 | Symbol.iterator、next、done | 可消费序列 |
| 生成器生产 | 函数体、yield、输入 | 暂停帧、局部绑定、完成状态 | 按需迭代器 |
| 模块导出 | 模块作用域、函数、值 | 导出表、初始化、副作用 | 公开绑定 |
| 静态导入 | 依赖图、导入名 | 活绑定、解析顺序、循环边 | 可读取依赖 |
| class 实例 | 构造参数、方法 | 自有属性、构造状态、原型 | 实例行为 |
| 底层协议 | 实例、原型、迭代器 | 查找终点、接收者、清理 | 可解释组织模型 |

## 最小可运行实验

下面的片段把生成器、`for..of`、class 和原型方法放进一个小样本。运行前先预测生产、消费和方法查找的顺序：

```js
class Batch {
  constructor(values) {
    this.values = values;
  }

  *items() {
    yield* this.values;
  }
}

const batch = new Batch(["a", "b"]);
for (const value of batch.items()) console.log(value);
console.log(Object.hasOwn(batch, "items"));
```

实验契约是：构造器把数组保存为实例状态，`items` 从原型查找，生成器逐项暂停，`yield*` 委托给数组迭代器，循环消费迭代结果。把 `values` 改成不可迭代对象、把方法取出后调用，或重复消费同一个迭代器，分别记录首个偏离点。

## 四类样本与验收

| 样本 | 注入方式 | 必查证据 | 通过条件 |

| 正常 | 可迭代数组、完整生成器、合法模块和 class 实例 | next、yield、绑定、原型 | 六阶段按预期完成 |

## 练习

<Exercises>

1. 为一个自定义可迭代对象实现 `Symbol.iterator`，让它每次返回独立迭代器；再证明重复 `for..of` 不会共享游标。

   <Answer>

   `Symbol.iterator` 每次调用都应创建新的 `index` 和 `next()` 闭包。先分别把同一个对象交给两个循环，交错推进或在第一个循环提前退出，再比较第二个循环是否从第一项开始；如果第二个循环从旧位置继续，说明迭代器状态错误地放在了可迭代对象本身。

   </Answer>

2. 逐次调用一个生成器的 `next()`、`return()` 和 `throw()`，记录 `value`、`done` 和 finally 清理顺序。

   <Answer>

   第一次 `next()` 执行到第一个 `yield` 并返回 `done: false`；后续 `next(input)` 把输入送回暂停点。`return()` 会让生成器完成并触发 finally，`throw(error)` 会在暂停点抛出错误，同样应经过 finally。验收要检查完成后再次 `next()` 的稳定结果，以及资源是否只清理一次。

   </Answer>

3. 创建一个 class 实例并检查方法来源，再把方法取出调用；说明为什么 class 没有消除原型和 `this` 边界。

   <Answer>

   用 `Object.hasOwn(instance, "method")` 和 `Object.getPrototypeOf(instance)` 证明方法来自 prototype。直接调用 `instance.method()` 会提供实例接收者；把方法保存后再调用则改变调用形式，可能得到 undefined 或错误。class 只是把构造和原型方法写成声明式语法，底层查找与 this 规则仍然存在。

   </Answer>

</Exercises>

## 小结

- 迭代器提供 `next()`、`value` 和 `done` 协议；可迭代对象与迭代器可以是不同角色。
- 生成器把生产逻辑变成可暂停状态机；yield、恢复、return、throw 和清理都应可观察。
- ES 模块通过模块作用域和导出表组织依赖；静态导入连接的是活绑定，不是无关快照。
- class 组织构造器和实例方法，但实例方法通常仍在原型上，方法取出后仍受 `this` 调用规则影响。
- 代码组织的质量来自协议和所有权清晰，而不是文件数量或语法表面是否现代。

<GlossaryItem term="ES 模块">拥有模块作用域并通过 export 和 import 组织依赖的代码单元。</GlossaryItem>
<GlossaryItem term="静态绑定">由导入方连接到导出方、可被依赖分析并保持活跃关系的模块绑定。</GlossaryItem>
<GlossaryItem term="class">组织构造器、实例方法和继承表面的声明式语法，底层仍使用原型机制。</GlossaryItem>
<GlossaryItem term="原型委托">对象查找缺失属性时沿原型链寻找共享行为的链接关系。</GlossaryItem>
