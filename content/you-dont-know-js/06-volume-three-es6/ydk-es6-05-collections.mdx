## 直觉：先问“谁拥有这条记录”

集合解决的不是“把很多值放在一起”这么简单。TypedArrays 规定一段缓冲区怎样被解释，Maps 规定键如何找到值，Sets 规定重复值怎样消失，WeakMaps 与 WeakSets 则规定对象失去外部引用后不应被集合继续挽留。选错集合，通常不是一行 API 写错，而是数据所有权和生命周期被悄悄改写。

先预测：把两个外形相同但身份不同的对象放进 Map，把重复数字放进 Set，再把同一对象放入 WeakMap 和 WeakSet；哪些查询会命中，哪些内容能被枚举，哪些内容能被 JSON 序列化？写下预测后切换交互样本，观察首个偏离点。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：集合只是数组的另一种写法">

现象：先把所有数据塞进数组，遇到查找、去重或元数据绑定时再用循环补救。

原因：数组表达位置序列，不自动表达键身份、唯一性、字节宽度或对象生命周期；补丁会把真正的不变量藏在调用者代码里。

修复：先写出读取契约，再选择集合；用正常、重复、错误身份和生命周期结束四类样本验证不变量。

</Callout>

<Callout type="trap" title="陷阱：对象键按内容相等">

现象：`map.get({ id: 1 })` 期待取回之前用 `{ id: 1 }` 存入的值。

原因：普通对象作为 Map 键按引用身份比较；两个对象即使字段相同，也不是同一个键。

修复：保存并复用同一个键对象，或在边界处明确生成稳定的原始键；测试 get、has 和 delete 的身份条件。

</Callout>

<Callout type="trap" title="陷阱：弱集合可以像强集合一样枚举">

现象：尝试遍历 WeakMap 或 WeakSet，或者把它们直接转换为 JSON 快照。

原因：弱集合不提供成员枚举，避免快照本身成为对象存活的强引用；可达性也可能随运行时回收而变化。

修复：用已知对象调用 get、has、set 或 delete；需要报告时维护独立的、明确拥有生命周期的索引。

</Callout>

<Callout type="trap" title="陷阱：视图边界和缓冲区边界是一回事">

现象：修改一个 TypedArray 后，假定所有视图都以同一元素类型、偏移和长度读取。

原因：多个视图可以共享 ArrayBuffer，但 byteOffset、length 和元素类型各自决定解释窗口；越界读写不是“自动扩容”。

修复：记录 buffer、byteOffset、length 和 BYTES_PER_ELEMENT，先对照字节图再断言读写结果。

</Callout>

## 核心概念与状态所有权

<Term def="把数据组织方式与读取契约绑定的设计判断：先确定字节形状、键身份、唯一性或对象生命周期，再选择集合。">集合选择</Term> 决定调用者需要维护多少额外不变量。

<Term def="由 ArrayBuffer、元素类型、字节偏移和长度共同决定的一段二进制读取窗口。">二进制视图</Term> 让同一块内存可以被不同类型的 TypedArray 解释。

<Term def="把一个键和一个值关联起来的 Map 记录；对象键按引用身份查找，而不是按字段内容猜测。">键值关联</Term> 适合缓存、索引和对象元数据。

<Term def="只保留一个成员的 Set 集合规则；重复加入不会产生第二个成员，并且迭代遵循插入顺序。">唯一性</Term> 把去重从调用者循环提升为集合契约。

<Term def="集合只通过对象键或成员资格访问，不提供枚举，并且不应凭自身引用阻止对象被回收的关系。">弱可达性</Term> 是 WeakMaps 和 WeakSets 的生命周期边界。

<Term def="把集合内容转换为日志、网络载荷或持久化快照的过程；弱集合不能直接提供完整枚举，因此必须另建强索引。">集合快照</Term> 需要明确谁拥有快照以及何时失效。

这六个概念可以压缩成一张责任表：TypedArrays 负责“如何解释字节”，Maps 负责“怎样找到值”，Sets 负责“哪些值算重复”，弱集合负责“对象是否仍可达”，快照负责“怎样向外部系统报告”。每次实验都要记录输入身份、读取方式、输出边界和清理责任。

| 观察量 | 要记录的证据 | 不应偷换成 |
| --- | --- | --- |
| 二进制视图 | buffer、offset、length、元素类型 | 普通数组的数字列表 |
| 键值关联 | 键的身份、has/get/delete 结果 | 对象字段的相似度 |
| 唯一性 | 首次加入顺序、重复加入结果 | 排序后的偶然顺序 |
| 弱可达性 | 已知对象的 has/get 与外部所有权 | 可枚举的成员清单 |
| 集合快照 | 快照创建者、时间点和失效条件 | 弱集合的实时内容 |

## 机制拆解

### 1. Chapter 5: Collections

**Chapter 5: Collections** 的主线是“选择正确的观察契约”。如果问题关心的是固定字节布局，使用 TypedArrays；如果关心键和值的关系，使用 Maps；如果关心是否已经出现，使用 Sets；如果元数据不应延长对象生命周期，才考虑 WeakMaps 或 WeakSets。

先把每个候选集合写成四元组：输入是什么、成员怎样比较、能否枚举、谁负责清理。四元组中任何一项没有答案，集合选择就还没有完成。交互时间线把这些问题按步骤展开，避免只凭 API 名称做决定。

### 2. TypedArrays

**TypedArrays** 是访问 ArrayBuffer 的类型化窗口，而不是一组“更快的数字”。`Uint8Array` 每个元素占一个字节，`Uint16Array` 的元素宽度不同；同一缓冲区上改变视图类型、偏移或长度，就可能得到完全不同的读取解释。

```js
const buffer = new ArrayBuffer(4);
const bytes = new Uint8Array(buffer);
const words = new Uint16Array(buffer);

bytes[0] = 1;
bytes[1] = 2;
console.log(bytes.byteOffset, bytes.length, words.length);
```

验证 TypedArrays 时不要只打印数组内容。把 `buffer`、`byteOffset`、`length` 和 `BYTES_PER_ELEMENT` 一起记录；如果数据来自网络或文件，还要明确字节序和截断策略。固定长度视图不会替调用者完成容量检查。

### 3. Maps

**Maps** 用键和值表达关联，键可以是对象、函数或原始值。Map 的关键不是“查找更方便”，而是把键的身份规则写入数据结构：保存时的键和查询时的键必须是同一个身份，除非键本身是稳定的原始值。

```js
const owner = { id: 7 };
const metadata = new Map([[owner, { dirty: false }]]);

console.log(metadata.get(owner));
console.log(metadata.get({ id: 7 }));
```

第二次查询得到 `undefined` 并非 Map 丢数据，而是查询对象不是原来的键。`size`、`has`、`get`、`set` 和 `delete` 应该在边界测试中一起出现，分别证明记录数量、身份命中、读取、更新和清除的契约。

### 4. WeakMaps

**WeakMaps** 适合保存“对象作为所有者时才有意义”的私有状态。它们不能枚举，键必须是对象；外部代码仍持有对象时，可以通过同一对象读取或删除状态，但不能从 WeakMap 反推出所有对象。

```js
const privateState = new WeakMap();
const widget = {};

privateState.set(widget, { mounted: true });
console.log(privateState.get(widget));
privateState.delete(widget);
```

弱引用不是立即回收的通知，也不是资源清理回调。若状态关联了事件监听器、文件句柄或网络连接，必须由拥有这些资源的生命周期显式关闭；不能把垃圾回收当作业务层 finally。

### 5. Sets

**Sets** 表达成员资格和唯一性。重复 `add` 不会追加第二个成员，迭代顺序则保留首次加入的顺序；这让 Set 很适合去重、访问记录和能力集合，但不适合表达“每个键对应一个值”的关系。

```js
const seen = new Set(["cache", "cache", "network"]);
seen.add("cache");

console.log([...seen]);
console.log(seen.has("network"));
```

测试 Set 时同时验证 `size`、迭代结果和 `has`。如果业务需要把一次出现的来源、时间或计数也保存下来，就要把 Set 与 Map 的职责分开，不要把附加字段藏在数组索引里。

### 6. WeakSets

**WeakSets** 只表达对象成员资格，不提供枚举和关联值。它适合标记“这个对象已经通过校验”或“这个对象已经被处理”，但不能用于生成成员报告，也不能把原始值直接加入其中。

```js
const visited = new WeakSet();
const node = {};

visited.add(node);
console.log(visited.has(node));
visited.delete(node);
```

WeakSet 的 `has` 需要一个已知对象；如果产品需要展示所有已处理对象，就要由业务层维护一个明确的强索引，并规定索引何时删除。这样可以把“弱集合的生命周期语义”和“报告系统的可枚举需求”分开。

## 从比较规则走到生命周期

集合 API 的相似外形容易掩盖不同的所有权。下面四段实验分别固定一种问题：

1. **形状**：TypedArrays 只解释自己覆盖的字节窗口；改变 offset 或类型就改变读取语义。
2. **关联**：Maps 通过键身份找到值；稳定的原始键和可复用的对象键都比临时对象可靠。
3. **成员资格**：Sets 只保留唯一成员；需要值之外的信息时，另建 Map 保存元数据。
4. **可达性**：WeakMaps 与 WeakSets 不提供枚举；业务清理不能依赖“也许已经回收”。

把这四类问题写入测试名称，代码审查时就能看到集合选择是否与数据契约一致。

## 序列化与快照边界

`JSON.stringify` 适合有明确字段的对象和数组，却不会自动把 Map、Set、WeakMap 或 WeakSet 变成业务想要的快照。强集合可以通过展开或自定义转换表达成员；弱集合没有完整枚举协议，任何快照都必须来自另外维护的强索引或已知对象集合。

```js
const ids = new Set(["a", "b"]);
const labels = new Map([["a", "alpha"]]);

const snapshot = {
  ids: [...ids],
  labels: Object.fromEntries(labels),
};
console.log(JSON.stringify(snapshot));
```

快照是某个时间点的副本，不是集合本身。写入缓存或网络前要记录快照创建时间、来源和失效条件；读取时不能把旧快照误认为实时成员资格。

## 最小可运行实验

下面的片段把本章四种核心选择放在同一条可回放轨迹中。运行前先预测日志，再只改一个变量：

```js
const buffer = new ArrayBuffer(2);
const bytes = new Uint8Array(buffer);
const key = { id: 1 };
const map = new Map([[key, "metadata"]]);
const set = new Set(["ready", "ready"]);
const weakMap = new WeakMap([[key, { active: true }]]);
const weakSet = new WeakSet([key]);

bytes[0] = 9;
console.log(bytes.length, map.get(key), [...set], weakMap.has(key), weakSet.has(key));
```

## 练习

<Exercises>

1. 给一个共享 ArrayBuffer 建立 `Uint8Array` 和 `Uint16Array` 两个视图，记录同一字节写入后两者的读取差异，并说明 offset、length 和字节序如何影响结论。

   <Answer>

   先打印两个视图的 `byteOffset`、`length` 和 `BYTES_PER_ELEMENT`，再写入两个字节。`Uint8Array` 按单字节读取，`Uint16Array` 把两个字节组合成一个元素，具体数值还受运行时字节序影响。答案的重点不是背一个十进制数字，而是证明两个视图拥有不同的解释窗口。

   </Answer>

2. 用 Map 保存对象元数据，用 Set 记录已经处理过的对象 ID；故意用一个字段相同的新对象查询 Map，并比较两种结构的测试结果。

   <Answer>

   Map 的对象键按引用身份比较，新对象不会命中旧记录；如果需要按 ID 查找，应使用稳定的原始 ID 作为键，或复用原对象。Set 只表达 ID 是否出现，重复 `add` 不增加成员；若还要保存元数据，应由 Map 承担关联职责。

   </Answer>

3. 设计一个 WeakMap 私有状态和一个 WeakSet 访问标记，并写出独立的资源清理与报告索引；解释为什么不能遍历弱集合来完成这两件事。

   <Answer>

   WeakMap 保存对象对应的状态，WeakSet 保存已访问成员资格；二者只能对已知对象调用 `get`、`has` 或 `delete`，不能生成完整成员列表。需要报告时维护一个有明确删除时机的强索引；计时器、监听器或连接则由显式生命周期关闭，不能等待垃圾回收替代清理。

   </Answer>

</Exercises>

## 小结

- **TypedArrays**：用固定的字节宽度、偏移和长度解释 ArrayBuffer。
- **Maps**：用键身份连接任意值与元数据，查询前必须确认键仍是同一身份。
- **Sets**：把唯一性和插入顺序作为成员资格契约，而不是数组循环的副作用。
- **WeakMaps**：把对象私有状态放进不可枚举的弱引用边界，但不负责业务资源清理。
- **WeakSets**：只记录对象成员资格，报告需求要由独立强索引承担。
- **Chapter 5: Collections** 的核心判断是“数据需要哪一种比较规则和所有权”，不是“哪一个 API 看起来最短”。
