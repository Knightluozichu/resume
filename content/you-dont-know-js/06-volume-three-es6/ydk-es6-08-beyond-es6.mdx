## 直觉：先区分“当时的未来”和“今天的现在”

技术书里的 future 不是永久标签。作者在 2015 年记录的候选能力，有的成为标准，有的改名或换了语义，有的被撤回，还有的只在特定引擎或工具链中存在。阅读本章时，最重要的动作不是背下预测，而是给每项能力附上时间、状态、现代写法和验证方法。

## 常见误区与故障注入

<Callout type="trap" title="陷阱：原书说 future 就代表今天还在提案阶段">

现象：看到 ES6 之后的章节就把 async、展开和 includes 当成实验特性，或者继续使用早期提案的旧语法。

原因：书籍保存的是一个时间点的知识快照；规范演进会把候选能力标准化、重命名、拆分或撤回。

修复：给每项能力记录原书日期、当前规范状态、目标引擎和迁移说明；代码示例以最终语法为准。

</Callout>

<Callout type="trap" title="陷阱：对象展开等于深复制">

现象：展开配置对象后修改嵌套字段，期待源对象完全不受影响。

原因：对象展开复制的是第一层可枚举自有属性，嵌套对象仍然是共享引用；它解决的是组合语法，不是通用持久化复制。

修复：分别断言第一层值、嵌套身份、访问器和属性顺序；需要深复制时选择明确的领域策略。

</Callout>

<Callout type="trap" title="陷阱：includes 和 indexOf 在所有值上等价">

现象：用 indexOf 判断数组是否包含 NaN，或把 includes 的布尔结果和索引位置混用。

原因：includes 使用 SameValueZero，可以识别 NaN；indexOf 返回位置且对 NaN 有不同表现，两者输出契约不同。

修复：用 NaN、-0、对象引用和缺失值做对照，先确定需要成员资格还是位置，再选 API。

</Callout>

<Callout type="trap" title="陷阱：撤回提案可以用 polyfill 原样补回来">

现象：为 Object.observe(..) 或 SIMD 写一个同名包装，就声称获得了原提案的性能和通知语义。

原因：撤回方案的协议、调度、性能和生命周期并不会因为名字相同而复活；替代工具通常只覆盖原问题的一部分。

修复：先写业务需求，再选择 Proxy、显式状态更新、TypedArrays、WebAssembly 或普通批处理，并记录差异与降级。

</Callout>

<Term def="从规范或引擎路线中退出、不能再按原协议直接依赖的设计；它仍可作为技术演进案例。">撤回提案</Term> 需要现代替代，而不是伪造同名实现。

## 机制拆解

### 1. Chapter 8: Beyond ES6

**Chapter 8: Beyond ES6** 应被当成一次状态审计，而不是未来愿望清单。原书的价值在于保存当时的提问；现代学习的任务则是把每个提问重新放进规范、实现和项目约束中回答。

交互时间线把这件事拆成六步：快照提供历史坐标，状态查询提供当前坐标，分类决定推荐，最终语法用于实现，替代方案承接撤回需求，目标验证负责发现环境差异。

### 2. async functions

**async functions** 已进入语言标准。async 函数总是返回 Promise，函数体中的 await 表达等待和错误传播边界；它让控制流更容易阅读，却没有消除微任务、取消、超时和资源清理。

```js
async function loadPair(fetchFirst, fetchSecond) {
  const first = await fetchFirst();
  const second = await fetchSecond(first);
  return { first, second };
}
```

验证时要同时观察 fulfilled、rejected 和 finally 路径。若两个请求可以并行，顺序 await 还可能改变性能；最终语法解决表达问题，不自动解决调度决策。

### 3. Object.observe(..)

**Object.observe(..)** 是原书记录过的撤回方向，今天不应作为现行对象变化通知 API。它的历史意义在于提醒我们：语言级观察机制涉及批处理、调度、可观察范围和生命周期，不能只把“变化事件”四个字搬到一个新函数名上。

```js
const state = { ready: false };
state.ready = true;
console.log(state.ready);
```

如果业务需要响应状态变化，应根据边界选择显式状态更新、框架响应式系统、Proxy 观察入口或事件总线，并写出批处理、取消、异常和性能差异。不要为撤回提案制作一个看似兼容、实际语义不同的空壳。

### 4. Exponentiation Operator

**Exponentiation Operator** 用 `**` 表达幂运算，进入标准后不再需要把它当成实验语法。它仍然有优先级、结合性、负数括号和 BigInt 类型边界，最终语法并不等于没有测试成本。

```js
console.log(2 ** 3);
console.log(-2 ** 2);
console.log((-2) ** 2);
```

在实际代码中，负底数通常需要括号以表达意图；还要避免把 Number 和 BigInt 混在同一运算中。回归表应保存输入类型、括号结构和溢出策略，而不是只保存一个结果数字。

### 5. Object Properties and ...

**Object Properties and ...** 记录了对象属性展开等语法方向。今天的对象展开可用于组合浅层配置、过滤属性和构造新对象，但它不会递归复制，也不会自动保留所有描述符、原型和私有状态。

```js
const defaults = { theme: "light", nested: { cache: true } };
const current = { ...defaults, theme: "dark" };

console.log(current.theme, current.nested === defaults.nested);
```

展开顺序决定后面的属性覆盖前面的属性；嵌套引用的身份则提醒我们它是浅复制。需要隔离状态时，应该按领域结构显式复制，而不是把三个点当成深度保证。

### 6. Array#includes(..)

**Array#includes(..)** 已进入标准，适合表达“数组是否包含这个值”的成员资格判断。它返回布尔值，并使用 SameValueZero，因此 `[NaN].includes(NaN)` 为 true；这与返回索引的 indexOf 是不同契约。

```js
console.log([NaN].includes(NaN));
console.log(["a", "b"].includes("b"));
console.log(["a", "b"].indexOf("b"));
```

用 includes 时仍要考虑起始位置、对象引用和稀疏数组边界。需要位置时使用 indexOf，需要复杂谓词时使用 some 或 find；API 选择应该由问题的输出契约决定。

### 7. SIMD

**SIMD** 是原书记录过的向量化方向，SIMD.js 方案后来撤回，不能把它当作今天跨环境可依赖的 JavaScript API。它所表达的“让相同操作批量处理数据”的需求仍然存在，但承接方式可能是 TypedArrays、WebAssembly、GPU API 或引擎自动向量化。

```js
const values = new Float32Array([1, 2, 3, 4]);
const doubled = values.map((value) => value * 2);
console.log(doubled);
```

替代方案要根据数据规模、内存布局、调用边界和部署环境选择。普通批处理更容易维护，WebAssembly 或专用硬件可能带来额外构建和调试成本；二者都不应被简化成“SIMD 已经存在”。

## 最小可运行实验

下面的实验把已标准化能力、撤回能力的现代处理和目标验证放在一起。运行前先预测每一项的状态：

```js
async function read() {
  return await Promise.resolve({ value: 2 ** 3 });
}

const source = { nested: { ready: true } };
const copy = { ...source };
const members = [NaN, 2];

console.log(copy.nested === source.nested);
console.log(members.includes(NaN));
read().then(console.log);
```

1. 为 async functions 写成功、拒绝和 finally 三条回归路径，记录它们返回的 Promise 状态以及两个 await 的执行顺序。

   <Answer>

   async 函数的成功分支返回 fulfilled Promise，未处理错误返回 rejected Promise；finally 无论哪条路径都应执行。两个顺序 await 会让第二步等待第一步的结果，若业务允许并行则应显式使用 Promise.all，并记录这不是语法自动优化。

   </Answer>

2. 比较 `2 ** 3`、负数底数和对象展开的嵌套身份，写出最终标准语法仍需保留的边界断言。

   <Answer>

   指数运算要用括号表达负底数意图，并区分 Number 与 BigInt；对象展开只复制第一层，嵌套对象与源对象仍可能是同一引用。断言应覆盖优先级、输入类型、覆盖顺序和嵌套身份，而不是只检查一个正数结果。

   </Answer>

3. 为 Object.observe(..) 和 SIMD 选择现代替代，比较 Array#includes(..) 与 indexOf 的输出契约，并写一个目标引擎 Feature Testing 记录。

   <Answer>

   Object.observe(..) 可按需求改用显式状态更新、响应式系统或 Proxy；SIMD 的批量计算需求可由 TypedArrays、WebAssembly 或其他平台能力承接。includes 返回成员资格布尔值且能识别 NaN，indexOf 返回索引并有不同的 NaN 行为。记录目标引擎、版本、能力探测、降级路径和复查时间，才能让迁移结论可追溯。

## 小结

- **async functions** 已标准化，但仍然有 Promise、错误、调度和清理边界。
- **Exponentiation Operator** 与 **Object Properties and ...** 使用最终语法，却仍需测试优先级、类型、浅复制和属性顺序。
- **Array#includes(..)** 的成员资格语义与 indexOf 不同，尤其是 NaN 和返回值契约。
- **Object.observe(..)** 与 **SIMD** 说明提案可能撤回；现代替代必须写出目标、差异和成本。
- **Chapter 8: Beyond ES6** 的学习方法是追踪状态，不是把历史预测当成永久 API。
