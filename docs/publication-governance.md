# 书籍发布治理

生产环境采用整书白名单，章节的 `draft` 字段和历史整改状态都不能单独触发上架。

## 三份记录的职责

- `quality/fidelity-manifests.json`：记录原版目录、可访问来源、改写模式和核心知识单元。
- `quality/publication-ledger.json`：由当前质量规则重算，记录逐章分数、维度、硬阻断与内容哈希；这是发布资格证据。
- `quality/publication-policy.json`：经整书审批后进入的生产白名单；这是运行时唯一可见性开关。

`quality/remediation-ledger.json` 是历史整改台账，不再具有发布权限。

## 不可绕过的顺序

1. `pnpm quality:audit -- --check --book <slug>`：修到整书所有章节通过。
2. `pnpm quality:audit -- --update-ledger`：使用当前规则全库重算发布台账。
3. `pnpm quality:invariants`：确认台账库存、内容哈希、来源证据和状态不矛盾。
4. `pnpm quality:approve-book -- --book <slug>`：把合格整书加入生产白名单。
5. 提交内容、发布台账和白名单，再执行 `./deploy.sh --book <slug>`。

硬阻断包括但不限于：质量 v2 未审、分数或维度不达标、视觉证据缺失、目录单元未覆盖、日文假名正文残留、章内/跨章/跨书模板复制、来源权限与声明不一致，以及 `manualBypass`。

任何脚本都不得把 `manualBypass` 章节变成 `passed` 或 `published`。旧的 `force-pass-book.mjs` 只保留为失败即停的兼容入口。

## 多维整改顺序

1. **来源与边界**：先确认版本、目录分母、授权范围和可复现来源；只有目录时必须独立改写。
2. **知识与语言**：正式概念要有不少于一个可复核解释，正文主语言保持中文，原文术语只在必要的来源说明中出现。
3. **重复与失真**：章内、跨章和跨书长句复制均为硬阻断；标题替换式组件不能充当章节专属视觉。
4. **教学与练习**：学习目标、直觉、反例、总结、答案和实践模式必须形成闭环，不能靠正文长度补分。
5. **视觉与 UX**：章节视觉需同时表达责任/数据关系和失败轨迹；桌面、移动、交互变化、重置和控制台错误都由真实浏览器验收。
6. **工程与发布**：MDX、组件注册、源锚点、构建后链接、生产构建与内容哈希全部通过后，才执行整书审批。
