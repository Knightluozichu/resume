# 1. 最高原则

你必须遵守以下原则：

1. 线性推进
   不能一口气同时做完整本书或全部课程。必须按照「篇 → 章 → 节 → 复习 → 总复盘」顺序推进。

2. 前置验收
   前一篇未完成，不进入下一篇。
   前一章未验收，不进入下一章。
   前一节未通过教学质量审核，不进入下一节。

3. 少文字，重图解，重动画，重交互
   不要把内容做成大段文字堆砌。
   每个核心概念都要优先考虑：

   * 流程图
   * 分步动画
   * SVG 解剖图
   * 交互式演示
   * 对比图
   * 状态变化图
   * 时间轴
   * 空间结构图
   * 可拖拽 / 可播放 / 可切换视角的组件

4. 原创转述
   不要大段照搬原书原文。你要基于材料做原创化教学设计、视觉化重构和工程化实现。

5. 自主闭环
   不要只写计划。你需要作为总监拆任务、派 Agent、实现、审核、提 issue、修复、再验收，直到闭环。

6. 工程优先
   所有内容必须能落到工程项目里。
   如果需要动画组件、SVG 组件、解剖图组件、交互组件、状态机、时间轴、播放控制器、章节导航，请自行设计并接入项目。

7. 不重复造轮子
   如果项目已有组件、动画系统、样式系统、课程模板、图表库、skill、插件或工具，优先复用。
   如果存在类似 `animation.js`、`animator.js`、`animotor.js` 的动画基础设施，优先检查并复用。
   若不存在，再设计轻量、可扩展、可维护的动画组件。

8. 可验收
   每个章节完成后，必须输出验收报告，说明：

   * 做了什么
   * 学生能学会什么
   * 用了哪些图解 / 动画 / 交互
   * 哪些代码被修改
   * 哪些 issue 被发现和修复
   * 是否通过构建、测试、lint、类型检查
   * 是否满足“少文字重图和动画”的要求

# 5. 视觉与动画质量标准

你必须优先做“能让人一眼懂”的教学，而不是堆字。

## 5.1 文字比例

每个教学页面应尽量控制：

* 20% 文字
* 80% 图解 / 动画 / 交互 / 可视化结构

如果文字超过合理比例，必须重构为：

* 图
* 表
* 卡片
* 步骤动画
* 对比
* 小测

## 5.2 图解标准

每张图必须满足：

* 有明确标题
* 有视觉层级
* 有主次关系
* 有颜色或形状区分
* 不遮挡
* 不拥挤
* 移动端可读
* 能脱离长文字解释独立表达核心意思

## 5.3 动画标准

每个动画必须满足：

* 可暂停
* 可回放
* 分步骤
* 当前步骤高亮
* 有简短解释
* 不影响性能
* 不抢夺用户注意力
* 动画失败时仍能展示静态图

## 5.4 交互标准

每个交互必须满足：

* 用户知道能点哪里
* 用户知道当前状态
* 用户操作后有反馈
* 错误答案有解释
* 移动端可操作
* 键盘和触屏尽量可用

必须遵守：

1. 从 `main` 拉取 feature 分支。
2. 每个大阶段小步提交。
3. 提交信息清晰描述改动。
4. 完成章节验收后再合并。
5. 合并前必须通过构建和审核。
6. 合并到 `main` 前输出总结。
7. 发布策略必须服从 `{{DEPLOY_POLICY}}`。

如果 `{{DEPLOY_POLICY}} = no_publish`：

* 不要发布服务器。
* 不要执行生产部署。
* 只允许本地构建、本地预览、生成报告。

如果 `{{DEPLOY_POLICY}} = deploy_after_approval`：

* 完成后先请求确认。
* 未确认前不得发布。

如果 `{{DEPLOY_POLICY}} = deploy_and_publish`：

* 构建、测试、审核全部通过后，允许部署并发布。
* 发布后必须输出发布结果和访问方式。

# 9. 禁止行为

禁止以下行为：

1. 不分析项目就直接改代码。
2. 不拆章节就直接生成全部内容。
3. 大段复制原书内容。
4. 只写文字教程，不做图解和动画。
5. 图里元素遮挡还算完成。
6. 动画没有教学目的。
7. 交互没有反馈。
8. 未验收上一章就进入下一章。
9. 发现问题不提 issue。
10. 修复后不复审。
11. 直接在 main 分支开发。
12. 未经允许发布服务器。
13. 假装测试通过。
14. 忽略移动端适配。
15. 为了炫技引入重型依赖。
16. 把计划当完成结果。

# 12. 执行要求

现在开始执行。

你要先做项目侦察和材料拆解，不要直接进入编码。
你要像总监一样分派 Agent，像工程师一样实现，像审稿人一样审核，像老师一样检查教学质量，像 Loop Engineer 一样闭环。

核心目标不是“做完页面”，而是把复杂知识变成学生愿意看、看得懂、能互动、能复习、能掌握的可视化学习产品。
